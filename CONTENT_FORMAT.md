# Формат урока (CONTENT_FORMAT.md)

Спецификация для авторов и ИИ-агентов: как должен быть устроен файл урока,
чтобы сервер (`internal/content`) корректно его разобрал, а фронтенд
(`LessonView.vue` + `Quiz.vue`) отрендерил.

> Кратко: обычный markdown с YAML-фронтматтером в начале; тело делится на
> секции заголовками `## `; в конце обязательны `## Квиз` (3–5 вопросов в
> fenced-блоке `` ```quiz `` с 0-базовым индексом правильного ответа) и
> `## Где пригодится`.

---

## 1. Где лежит урок и как называется файл

```
content/<category>/<slug>.md
```

- `<category>` — одна из 12 ветвей: `web`, `crypto`, `pwn`, `reversing`,
  `forensics`, `osint`, `stego`, `network`, `cloud`, `mobile`, `hardware`,
  `misc`.
- `<slug>` — короткий уникальный идентификатор в kebab-case
  (`web-sqli`, `rsa-attacks`, `heap-uaf`). Имя файла совпадает со `slug`.
- Расширение: `.md` (также принимается `.markdown`).
- Файлы и каталоги, чьё имя начинается с `.` или `_`, **игнорируются**
  загрузчиком. Поэтому скелет [`content/_template.md`](content/_template.md)
  не попадает в дерево — его можно держать рядом с уроками.

Ветвление дерева задаётся **не каталогами**, а полем `parent` во
фронтматтере: каталог = категория (цвет ветви), `parent` = урок-родитель.

---

## 2. Фронтматтер

Начинается с первой строки файла, обрамлён `---` сверху и снизу. Разбирается
упрощённым YAML-парсером (`parseSimpleYAML`), поэтому поддерживаются только
простые конструкции: `ключ: значение`, inline-списки `[a, b, c]` и
блочные списки (`- элемент` на новой строке). Вложенные словари не
поддерживаются.

```yaml
---
id: web-sqli
title: "SQL-инъекции: от обнаружения до эксплуатации"
category: web
parent: web-http-basics
difficulty: medium
order: 4
tags: [sqli, database, injection, owasp]
prerequisites: [web-http-basics, web-architecture]
useful_for:
  - "CTF Web категория"
  - "Bug bounty"
  - "Пентест веб-приложений"
estimated_minutes: 40
summary: "Как находить и эксплуатировать SQL-инъекции: boolean, union, time-based, обход фильтров."
---
```

### Поля

| Поле                | Тип              | Обязательно | По умолчанию        | Описание |
|---------------------|------------------|:-----------:|---------------------|----------|
| `id`                | string           | **да**      | имя файла без `.md` | Уникальный идентификатор урока и slug в URL (`/lesson/<id>`). Должен совпадать с именем файла. |
| `title`             | string           | **да**      | = `id`              | Заголовок на графе и странице урока. |
| `category`          | string           | **да**      | первый каталог под `content/` | Slug ветви (см. список выше). |
| `parent`            | string           | нет         | `""` (корень ветви) | `id` урока-родителя. Пустое значение → узел становится корнем ветви. |
| `difficulty`        | enum             | **да**      | `medium`            | `beginner` \| `easy` \| `medium` \| `hard` \| `expert`. Недопустимое значение → `medium`. |
| `order`             | int              | **да**      | `0`                 | Порядок среди соседей (меньше = выше/левее). |
| `tags`              | list[string]     | нет         | `[]`                | Метки для поиска и навигации. |
| `prerequisites`     | list[string]     | нет         | `[]`                | `id` уроков, которые стоит пройти раньше. |
| `useful_for`        | list[string]     | нет         | `[]`                | Где навык пригодится (CTF, bug bounty, работа). |
| `estimated_minutes` | int              | нет         | авто                | Оценка времени. Если 0/пусто — считается автоматически: `слов / 180 + 2`. |
| `summary`           | string           | нет         | `""`                | Одна строка для карточки и поиска. |
| `author`            | string           | нет         | `""`                | Автор (опционально). |

Примечания:

- Строки можно брать в кавычки (`"..."` или `'...'`) — парсер их снимет.
  Если в тексте есть `:` — **обязательно** заключайте значение в кавычки.
- Пустой `parent:` (без значения) трактуется как «корень» — это нормально.
- `prerequisites` ссылается на `id` (не на имя файла, хотя обычно они совпадают).

## 3. Тело и разбиение на секции

Тело — обычный markdown (GFM: таблицы, списки, код в ``` ```). На фронтенде
он рендерится через `marked` и санитизируется `DOMPurify`, код подсвечивается
`highlight.js`.

**Разбиение на секции происходит по строкам, начинающимся ровно с `## `**
(два решётки + пробел). Каждая такая строка открывает новую секцию; текст до
первого `## ` становится секцией «Введение».

- `#`, `###`, `####` **не** являются границами секций — используйте `##`
  для смысловых блоков и `###` внутри них.
- Секция — единица отслеживания прогресса: пока секция видна, копится время;
  когда накоплено `words / 3` секунд (мин. 6, макс. 150), она отмечается
  прочитанной, и зелёная заливка квадрата урока растёт слева-направо.
- Пишите секции осмысленно: 4–10 секций на урок — хороший ориентир.

Рекомендуемый каркас тела:

```
(введение без заголовка или с '## Введение')
## Теория
## Инструменты и команды
## Разобранный пример
## Частые ошибки
## Квиз                ← обязательна
## Где пригодится      ← обязательна
```

## 4. Секция `## Квиз` — обязательна

Квиз теперь **интерактивный**: правильные ответы **не видны** в тексте урока.
Секция `## Квиз` должна содержать **один fenced-блок с языком `quiz`** —
небольшой YAML-список вопросов. Серверный загрузчик (`internal/content`,
функция `extractQuizBlock`) вырезает этот блок из markdown секции и
превращает его в `Lesson.Quiz` (массив `[]QuizQuestion`, см.
`internal/model/model.go`); читателю он отдаётся отдельным полем JSON, а
секция рендерится компонентом `Quiz.vue`. До нажатия «Проверить» правильный
ответ не отображается.

Требования: **3–5 вопросов**, у каждого **2–4 варианта** и **ровно один**
правильный ответ, заданный **0-базовым индексом** `answer`.

### Формат блока

````markdown
## Квиз

```quiz
- question: "Текст вопроса?"
  options:
    - "Вариант A"
    - "Вариант B"
    - "Вариант C"
  answer: 1
  explanation: "Почему верен вариант B (необязательно)"
- question: "Второй вопрос?"
  options:
    - "Вариант A"
    - "Вариант B"
  answer: 0
```
````

Поля элемента списка:

| Поле          | Обязательно | Описание |
|---------------|:-----------:|----------|
| `question`    | **да**      | Текст вопроса. Допускается `q:` как синоним. |
| `options`     | **да**      | Список вариантов (`- "..."`), минимум 2. |
| `answer`      | **да**      | **0-базовый индекс** правильного варианта: `0` — первый, `1` — второй, … |
| `explanation` | нет         | Разбор ответа, показывается после проверки. |

### Правила

- `answer` **0-базовый**: `answer: 1` указывает на **второй** вариант, а не
  на первый. Не путайте с буквенной нотацией — см. ниже.
- `parseAnswer` принимает также букву (`A`→0, `B`→1; кириллица `А`/`Б`→0/1)
  и целое число, но **рекомендуемый и однозначный способ — целое число**.
- Значения с `:` (например, вопрос с двоеточием) берите в кавычки —
  разбирается упрощённым YAML-парсером (`parseQuizYAML`).
- Невалидные вопросы (пустой текст, меньше 2 вариантов, `answer` вне
  диапазона `0..len(options)-1`) **молча отбрасываются** — блок может
  разобраться в 0 вопросов. Поэтому после генерации проверяйте, что квиз
  реально отдаётся в `Lesson.Quiz`.
- Правильный ответ **не должен дублироваться в прозе** секции: не пишите
  `(верно)`, `[x]`, `**жирным**`, `✅` — иначе ответ «утечёт» читателю до
  сдачи. Эти пометки относятся к устаревшему формату и здесь не нужны.

### Как это разбирается

1. `extractQuizBlock` ищет строку-ограждение ```` ```quiz ```` и парную
   ```` ``` ````, берёт содержимое между ними.
2. `parseQuizYAML` читает список вопросов и валидирует их.
3. Блок удаляется из markdown секции, а вопросы кладутся в `l.Quiz`
   (`l.Sections[i].Markdown = cleaned`).
4. Фронтенд (`LessonView.vue` + `Quiz.vue`) рендерит интерактивный тест;
   за каждый вопрос даётся 10 XP (`quiz_best × 10`), лучший результат
   хранится в профиле (`POST /api/progress/quiz`).

### Совместимость

Загрузчик всё ещё умеет разбирать и старый «прозаический» формат секции
(`parseQuizMarkdown`: `**1. Вопрос?**`, `- [x] вариант`, строка `Ответ: B`) —
это запасной путь для ещё не сконвертированных уроков. Но **новый контент
пишите только в формате `` ```quiz ``**: он единственный, где ответ гарантированно
скрыт от читателя.

## 5. Секция `## Где пригодится` — обязательна

Короткий список (2–5 пунктов) реальных ситуаций: CTF, bug bounty, пентест,
работа/SOC/IR, сертификации. Можно повторить/дополнить фронтматтерное
`useful_for`, но именно этот раздел показывается читателю в конце урока.

```markdown
## Где пригодится

- **CTF:** категория Web — инъекции в параметрах и формах.
- **Bug bounty:** поиск SQLi на реальных приложениях, отчёты.
- **Пентест:** веб-приложения и API, OWASP A03 Injection.
- **Работа:** разработка безопасных запросов, code review.
```
