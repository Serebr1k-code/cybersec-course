# CTF Learning Tree

Интерактивное **дерево обучения CTF**: набор markdown-уроков, собранных в
ветвящийся граф, с отслеживанием прочитанного, квизами, заметками, XP и
серией чтения (streak). Бэкенд — Go на стандартной библиотеке, фронтенд —
Vue 3 + Vite SPA.

Проект задуман как «маршрут» по кибербезопасности: каждая категория — это
отдельная ветвь, уроки связаны ссылками `parent` → `children`, а прогресс
читателя подсвечивается прямо на графе (зелёная заливка слева-направо).

---

## Установка в одну строку

Разверните весь проект на чистом сервере Debian/Ubuntu **одной командой**
(нужен `root`):

```bash
curl -fsSL https://raw.githubusercontent.com/Serebr1k-code/cybersec-course/main/install.sh | sudo bash
```

Установщик:

- доустанавливает недостающие зависимости — **Go ≥ 1.23** и **Node.js ≥ 18 + npm**
  (через `apt`, а Go — официальным тарболом, если в репозитории версия старее);
- клонирует проект в **`/opt/cybersec-course`**;
- собирает бэкенд (`bin/learningtree`) и фронтенд (`frontend/dist`);
- ставит **systemd-юнит `cybersec-course`** с `Restart=always` и включает его —
  сервис **поднимается автоматически при загрузке** и перезапускается после
  падения (переживает reboot/crash);
- печатает итоговый URL.

После установки приложение доступно на порту **41837**:

```
http://<IP-сервера>:41837/
```

Скрипт **идемпотентен** — его можно запускать повторно: он обновит код,
пересоберёт и перезапустит сервис.

Проверка статуса и логов:

```bash
systemctl status cybersec-course
journalctl -u cybersec-course -f
```

### Ручной запуск (без systemd)

Если systemd нет (например, в контейнере), запустите вручную:

```bash
/opt/cybersec-course/bin/learningtree \
  -addr :41837 -content content -data data -static frontend/dist
```

### Переопределение параметров установки

```bash
PORT=9000 INSTALL_DIR=/srv/course \
  curl -fsSL https://raw.githubusercontent.com/Serebr1k-code/cybersec-course/main/install.sh | sudo bash
```

## Возможности

- 🕸️ **Граф-дерево** — уроки как узлы, связи `parent` как рёбра; зум, панорама,
  подсветка прогресса.
- 📖 **Уроки из markdown** — обычные `.md` файлы с YAML-фронтматтером; никакой
  БД, контент правится в редакторе.
- ✅ **Прогресс по секциям** — сервер учитывает время чтения каждой секции
  (dwell time) и отмечает её прочитанной; урок считается пройденным, когда
  прочитаны все секции.
- 🧠 **Интерактивный квиз** — вопросы берутся из fenced-блока `` ```quiz `` в
  секции `## Квиз`; ответы скрыты до нажатия «Проверить», за верные
  начисляется XP.
- 🎯 **XP, уровни и серия** — очки за прочитанные секции, пройденные уроки и
  квизы; уровень каждые 500 XP; streak по календарю активности.
- 🔍 **Поиск** — полнотекстовый поиск по заголовкам, тегам, описаниям и телу
  уроков с подсветкой сниппетов.
- 📝 **Личные заметки** — конспект к каждому уроку, автосохранение.
- 📤 **Экспорт / импорт прогресса** — весь профиль читателя одним JSON.
- 🔥 **Hot-reload контента** — сервер сам перечитывает уроки при изменении
  файлов на диске (без перезапуска).
- 🌙 **Тёмная тема** — единая дизайн-система на CSS-переменных.

## Архитектура

```
┌──────────────────────────────────────────────────────────────┐
│  Браузер (Vue 3 SPA, тёмная тема)                             │
│   TreeView · LessonView · StatsView · AboutView               │
│   Pinia: tree / progress   ·   SearchBox · TreeGraph · Quiz   │
└───────────────▲───────────────────────────┬──────────────────┘
                │ JSON /api/*               │ статика (dist)
┌───────────────┴───────────────────────────▼──────────────────┐
│  Go-сервер (cmd/server, stdlib net/http)                      │
│   internal/api        — HTTP-хендлеры (JSON)                  │
│   internal/content    — загрузка и парсинг markdown-уроков    │
│   internal/progress   — профили читателей (JSON-файлы)        │
│   internal/model      — общие типы (Lesson, TreeNode, ...)    │
└───────┬───────────────────────────────┬──────────────────────┘
        │ читает                        │ пишет
   content/<category>/*.md          data/<user>.json
   (YAML-фронтматтер + markdown)    (прогресс, XP, заметки)
```

Ключевые принципы:

- **Go без внешних зависимостей.** `go.mod` объявляет только модуль
  `learningtree` (go 1.23) — ни одного стороннего пакета. YAML-фронтматтер
  разбирается вручную (`parseSimpleYAML`), что достаточно для нашего набора
  полей.
- **Контент — это файлы.** Источник истины по урокам — каталог `content/`.
  Сервер строит дерево и разбивает тело на секции при каждом запросе (с
  кэшем и перечитыванием при изменении mtime).
- **Прогресс — это JSON-файлы.** По одному файлу на анонимного пользователя
  в каталоге `data/`. Никакой БД, легко бэкапить и экспортировать.
- **SPA + API на одном порту.** В проде Go-сервер отдаёт собранный
  `frontend/dist` и обслуживает `/api/*`. В деве Vite проксирует `/api` на
  `:8090` (см. `frontend/vite.config.js`).

## Как работает отслеживание прогресса

Прогресс — это **время чтения по секциям**, а не просто «галочка».

1. **Разбиение на секции.** При загрузке урока тело markdown режется по
   строкам, начинающимся с `## ` (H2). Каждая секция получает id, заголовок,
   markdown, число слов и **`required_seconds`**:
   `words / 3` (≈180 слов/мин), но не меньше `6` и не больше `150` секунд.
   Это делает разбиение в [`internal/content/content.go`](internal/content/content.go)
   (`splitSections`).

2. **Dwell time.** Пока секция видна в окне чтения, фронтенд накапливает
   секунды и периодически отправляет `POST /api/progress/section`
   `{lesson_id, section_id, seconds}`. Сервер прибавляет время к секции
   (`internal/progress` → `SectionProgress.ReadSeconds`).

3. **Отметка «прочитано».** Когда накопленное время секции достигает
   `required_seconds`, секция помечается `read: true`.

4. **Доля урока.** `lessonRatio = прочитанные секции / всего секций` (0..1).
   Именно эта доля рисует **зелёную заливку слева-направо** в квадрате урока
   на графе: компонент `LessonNode.vue` (`<span class="fill" :style="{ width: pct+'%' }">`),
   а связи между узлами окрашиваются по прогрессу ребёнка (`TreeGraph.vue`).
   Когда прочитаны все секции, урок становится `completed` и получает ✓.

5. **XP и уровень.** `ComputeXP()` в `internal/progress/progress.go`:

   | Действие                          | XP        |
   |-----------------------------------|-----------|
   | Прочитанная секция (`read`)       | +5        |
   | Пройденный урок (`completed`)     | +40       |
   | Лучший результат квиза            | `best × 10` |

   Уровень = `floor(XP / 500) + 1`, прогресс-бар уровня = `XP % 500`.

6. **Серия (streak).** Каждое событие чтения увеличивает счётчик активности
   за текущую дату (`Activity[YYYY-MM-DD]`). `Streak()` считает подряд идущие
   дни с активностью, начиная с сегодняшнего (или вчерашнего — чтобы серия не
   рвалась до первого чтения за день).

7. **Завершение.** Явный `POST /api/progress/complete` помечает урок
   пройденным (кнопка «Завершить урок» на странице урока).

Всё хранится в `data/<user_id>.json` (`internal/progress`), запись атомарная
(через временный файл + `rename`).

## Дополнительные функции

- **Поиск** (`GET /api/search?q=`) — серверный скоринг: заголовок `+10`,
  тег `+6`, summary `+4`, вхождение в теле секции `+2`; возвращается до 60
  результатов со сниппетом. В UI — `SearchBox.vue` с дебаунсом 220 мс,
  навигацией ↑/↓/Enter.
- **Квиз-движок (интерактивный)** — секция `## Квиз` содержит fenced-блок
  `` ```quiz ``, который серверный загрузчик (`internal/content`,
  `extractQuizBlock`) разбирает в `Lesson.Quiz` (вопросы + 0-базовый индекс
  правильного ответа). Компонент `Quiz.vue` показывает вопросы без ключа,
  проверяет ответы, выводит разбор и сохраняет лучший результат
  (`POST /api/progress/quiz`). Правильный ответ никогда не попадает в текст
  урока.
- **Заметки** — `NotesPanel.vue`, автосохранение через 900 мс после последнего
  нажатия (`POST /api/notes`).
- **Экспорт/импорт** — `GET /api/export` отдаёт весь профиль одним JSON,
  `POST /api/import` загружает его обратно (перенос прогресса между
  устройствами).
- **Markdown-рендер** — `marked` + `DOMPurify` (санитизация) + `highlight.js`
  (подсветка кода), см. `frontend/src/utils/markdown.js`.
- **Hot-reload контента** — `Store.maybeReload()` сравнивает максимальный
  mtime файлов в `content/` и перечитывает уроки, если что-то изменилось.
  Добавили `.md` — обновите страницу, перезапуск не нужен.

## HTTP API (контракт)

Фронтенд ходит только сюда (см. `frontend/src/api/client.js`):

| Метод | Путь                        | Тело / параметры                          | Ответ |
|-------|-----------------------------|-------------------------------------------|-------|
| GET   | `/api/tree`                 | —                                          | `{categories, nodes, total}` |
| GET   | `/api/lessons`              | —                                          | список уроков |
| GET   | `/api/lessons/{id}`         | id или slug                                | `Lesson` с секциями |
| GET   | `/api/search?q=`            | строка поиска                              | `{results:[...]}` |
| GET   | `/api/meta`                 | —                                          | категории/сложности/мета |
| GET   | `/api/progress`             | —                                          | `{user, xp, streak, achievements}` |
| POST  | `/api/progress/section`     | `{lesson_id, section_id, seconds}`         | `{read_seconds, read, completed, xp}` |
| POST  | `/api/progress/quiz`        | `{lesson_id, score, total}`                | `{quiz_best, quiz_total, xp}` |
| POST  | `/api/progress/complete`    | `{lesson_id}`                              | `{xp}` |
| POST  | `/api/notes`                | `{lesson_id, text}`                        | `{ok}` |
| GET   | `/api/export`               | —                                          | профиль пользователя (JSON) |
| POST  | `/api/import`               | профиль (JSON)                             | `{ok}` |

Пользователь определяется cookie/идентификатором сессии; профиль хранится в
`data/<user_id>.json`. Все ответы — JSON, ошибки — `{"error": "..."}`.

## Как добавить контент

Полная спецификация — в [`CONTENT_FORMAT.md`](CONTENT_FORMAT.md). Кратко:

### Добавить урок

1. Скопируйте [`content/_template.md`](content/_template.md) в
   `content/<category>/<slug>.md` (имя файла = `<slug>`).
2. Заполните фронтматтер. Обязательны: `id`, `title`, `category`,
   `difficulty`, `order`. `parent` — id урока-родителя (пусто = корень ветви).
3. Напишите тело, разбитое заголовками `## ...`.
4. Добавьте финальные секции `## Квиз` (fenced-блок `` ```quiz ``, 3–5 вопросов
   с 0-базовым `answer`) и `## Где пригодится`.
5. Обновите страницу — сервер подхватит файл сам.

### Добавить новую категорию

1. Создайте каталог `content/<slug>/` с уроками (`category: <slug>`).
2. Добавьте категорию в массив `Categories` в
   `internal/content/content.go` (slug, имя, цвет, иконку, описание), чтобы
   она получила нормальные название/цвет на графе. Без этого урокам
   присвоится дефолтный серый стиль с именем = slug.

### Пусть ИИ-агент расширит ветку

Формат урока детерминирован и пригоден для генерации агентом:

- дайте агенту **`CONTENT_FORMAT.md`** и существующий урок-родителя как
  образец стиля;
- попросите создать файл `content/<category>/<slug>.md` с корректным
  фронтматтером, где `parent` = id родителя;
- требуйте обязательных секций `## Квиз` (fenced-блок `` ```quiz `` с 0-базовым
  `answer`; правильный ответ не виден в прозе) и `## Где пригодится`;
- после генерации проверьте: `id` уникален, `parent` существует, `category`
  совпадает с каталогом, значения `difficulty` из допустимого набора.

## Состояние и дорожная карта

Скелет проекта и контент-движок уже готовы; часть «клея» собирается:

- ✅ **Готово:** `internal/model`, `internal/content` (парсинг, дерево, поиск,
  hot-reload), `internal/progress` (XP/streak/заметки/квизы), фронтенд-логика
  (сторы, api-клиент, компоненты графа/квиза/поиска/заметок, дизайн-система),
  десятки markdown-уроков в категориях.
- 🚧 **В работе:** точка входа `cmd/server` (HTTP-сервер + статика `dist`),
  хендлеры `internal/api` (реализация контракта из таблицы выше) и
  представления `frontend/src/views/` (`TreeView`, `LessonView`, `StatsView`,
  `AboutView`).

Контракт API и структура данных зафиксированы в коде фронтенда и
`internal/*`; серверные пакеты реализуют именно его.
