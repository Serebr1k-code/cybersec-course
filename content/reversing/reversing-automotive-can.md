## Вопрос, с которого всё начинается

Современный автомобиль — это десятки компьютеров (**ECU**, Electronic Control
Unit), связанных сетью **CAN** (Controller Area Network). Диагностика идёт по
протоколу **UDS** (Unified Diagnostic Services). Если подключиться к шине,
можно читать и отправлять сообщения, а при удаче — прошивать блоки. Как это
реверсить и что искать? Разберём на реальных кадрах.

## Наш пример

У нас есть запись шины — несколько кадров в формате `candump` (так выводит
утилита `candump` из набора SocketCAN в Linux). Кадр CAN — это короткое
сообщение: **ID** (идентификатор/приоритет), длина **DLC** и до 8 байт данных.

```
can0  123   [8]  02 01 0C 00 00 00 00 00
can0  7E8   [8]  03 62 F1 90 00 00 00 00
can0  7E0   [8]  02 10 03 00 00 00 00 00
```

Здесь три кадра. Разберём их, потому что в этом и есть реверс CAN.

## Шаг 1: что такое CAN-кадр

В CAN нет «отправителя» и «получателя» — есть **ID**, по которому сообщение
адресуется и приоритезируется (меньший ID — выше приоритет). Кадр содержит до 8
байт данных (у CAN FD — до 64). В наших кадрах:

- `can0` — имя интерфейса;
- `123`, `7E8`, `7E0` — ID в hex;
- `[8]` — DLC, длина данных (8 байт);
- `02 01 0C ...` — сами байты.

Первые байты данных часто несут длину и счётчик, а дальше — полезная нагрузка.
Структуру выясняют, сравнивая много кадров и наблюдая, как меняются байты.

## Шаг 2: диагностические ID 0x7E0 и 0x7E8

В OBD-II/UDS зарезервированы «диагностические» ID:

- **0x7E0** — запросы к двигателю (диагностический «физический» адрес);
- **0x7E8** — ответы от двигателя.

Поэтому кадры `7E0`/`7E8` — это диалог диагностики. Разберём их как UDS:

```
UDS request  service=0x10
UDS response service=0x62 (positive = req+0x40) DID=0xF190 data=00
```

Первый байт данных — длина полезной нагрузки UDS (не путать с DLC), второй —
**сервис**. В запросе сервис `0x10` — «Start Diagnostic Session». В ответе сервис
`0x62` = `0x22 + 0x40`: положительный ответ к сервису `0x22` (Read Data By
Identifier), а `0xF190` — **DID** (идентификатор данных), например VIN-код.

## Шаг 3: сервисы UDS, которые надо знать

UDS — это набор «сервисов» (команд). Ключевые для реверса:

| Сервис | Название | Зачем |
|--------|----------|-------|
| 0x10 | Diagnostic Session Control | войти в расширенную сессию |
| 0x22 | Read Data By Identifier | читать данные (VIN, версии) |
| 0x2E | Write Data By Identifier | писать данные/конфиг |
| 0x27 | Security Access | seed/key (защита от прошивки) |
| 0x31 | Routine Control | запуск процедур (сброс, тесты) |
| 0x34/0x36/0x37 | Request/Transfer/Exit Download | загрузка прошивки |

Ответ на неизвестный сервис — `0x7F` + сервис + код ошибки (negative response).

## Шаг 4: seed/key — защита прошивки

Самый интересный сервис — **0x27 Security Access**. Он работает так:

1. Диагностический инструмент просит **seed** (зерно): `27 01`.
2. ECU отвечает случайным числом: `67 01 <seed>`.
3. Инструмент вычисляет **key** по секретному алгоритму и шлёт `27 02 <key>`.
4. Если key верный — доступ к защищённым сервисам (в том числе прошивке) открыт.

Алгоритм «seed → key» зашит в прошивке ECU. Его реверсят статически (ища
константы и таблицы в дампе) или динамически (подбирая по парам seed/key).
Взлом этого алгоритма = возможность прошивать блок.

## Шаг 5: прошивка ECU через UDS

Загрузка прошивки — последовательность сервисов:

1. `10 02` — войти в programming session;
2. `27` — пройти security access (seed/key);
3. `34` — Request Download (заявить размер и адрес);
4. `36` — Transfer Data (передать блоки прошивки);
5. `37` — Request Transfer Exit;
6. `31 01 02 03` — Routine Control (проверить/активировать).

Чтобы это реверсить, нужен и доступ к шине, и понимание алгоритма seed/key.

## Шаг 6: как подключиться к CAN

Физически к шине подключаются через **OBD-II** разъём (в машинах) или напрямую
к CAN-линиям (CAN-H, CAN-L). Устройства:

- **USB-CAN адаптер** (например, на MCP2515 или CANable) — в Linux работает как
  SocketCAN-интерфейс (`ip link set can0 up`).
- **CANtact / CANtroversy** — аппаратные интерфейсы для пентеста.

Дальше работают утилиты `candump` (читать), `cansend` (отправлять),
`can-utils` и скрипты на Python (`python-can`).

## Шаг 7: что искать при реверсе авто

- **Алгоритм seed/key** — ключ к прошивке.
- **Структуру кадров** — какие ID за что отвечают.
- **Конфигурацию и калибровки** — их можно менять сервисом `0x2E`.
- **Защиты** — проверки сессии, таймауты, счётчики попыток.
- **Безопасность** — открытые сервисы без аутентификации (частая проблема).

## Шаг 8: OBD-II и стандартные PID

Кроме UDS, есть более старый стандарт **OBD-II** (On-Board Diagnostics). В нём
данные читают по **PID** (Parameter ID) сервисом `0x01`:

- `01 0C` — обороты двигателя (RPM);
- `01 0D` — скорость;
- `01 05` — температура охлаждающей жидкости.

Ответ приходит сервисом `0x41` (= `0x01` + 0x40) и данными. В наших кадрах
запрос `10 03` — это переход в сессию `0x03` (extended diagnostic session), а
`62 F1 90` — чтение DID `0xF190` (VIN). Понимая эти коды, можно «читать» диалог
диагноста и ECU почти без документации.

## Частые вопросы

**Не могу отправить кадр.** Проверь, поднят ли интерфейс (`ip link set can0 up
type can bitrate 500000`) и правильная ли скорость (bitrate) — иначе шина
«молчит».

**ECU отвечает негативно (0x7F).** Возможно, неверная сессия или нет доступа.
Сначала `10 03`, потом нужный сервис.

**Как найти алгоритм seed/key?** Собери пары seed→key (запроси несколько раз) и
ищи в прошивке ECU функцию, которая по seed даёт key: константы, таблицы,
операции XOR/сдвигов.

**Опасно ли отправлять кадры в машине?** Да. Неверные команды могут нарушить
работу блоков. Работай на стенде или с разрешением владельца.

## Что мы теперь знаем

- CAN-кадр = **ID**, DLC и до 8 байт данных; ID задаёт приоритет и адрес.
- Диагностика UDS идёт по ID **0x7E0** (запрос) и **0x7E8** (ответ).
- Первый байт — длина UDS, второй — **сервис**; положительный ответ = сервис +
  0x40, а `0xF190` — пример **DID**.
- Ключевые сервисы: `0x10` сессия, `0x22/0x2E` чтение/запись, `0x27`
  **seed/key**, `0x34/0x36/0x37` прошивка.
- Подключаются через OBD-II/USB-CAN; алгоритм seed/key ищут в прошивке ECU.
