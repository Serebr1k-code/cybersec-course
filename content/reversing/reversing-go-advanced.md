Go-бинари отличаются от C/C++ радикально: они **статически слинкованы**, несут с собой весь рантайм, используют **собственные соглашения вызовов** (аргументы и результаты передаются по стеку, регистры задействованы иначе) и содержат встроенную таблицу метаданных **pclntab** (program counter line table), по которой восстанавливаются имена функций, файлы и строки даже после `strip`. Go-малварь (ботнеты, стилеры, кслайнеры) встречается всё чаще, поэтому реверс Go — обязательный навык. В этом уроке — определение версии, восстановление символов, анализ рантайма и горутин.

## Особенности Go, ломающие привычный реверс

Первое, что сбивает с толку: в Ghidra/IDA вызовы выглядят «странно» — аргументы кладутся на стек, а не в `rdi/rsi/rdx`, как в System V AMD64. Это следствие **stack-based calling convention** Go (начиная с 1.17 регистры используются частично, но не как в C). Второе: огромное количество функций рантайма (`runtime.*`, `internal/*`) засоряет листинг. Третье: строки и слайсы — это структуры `{ptr, len}` (и `cap` для слайса), передаваемые по значению, поэтому «строка» в аргументе — пара слов. Четвёртое: интерфейсы — пары `{type, data}`, а замыкания — объекты с полями. Без учёта этого моделирование падает.

## Определение версии и инструменты

Версия Go определяется по строке в бинаре:

```bash
strings -a ./sample | grep -E 'go1\.[0-9]+' | head
# go1.21.5
```

Инструменты: `go version ./sample` (Go >= 1.13 сохраняет версию), `redress`/`GoReSym` (восстановление символов), плагин **Ghidra** `golang` (автодетект pclntab и применение имён), `IDAGolangHelper` для IDA, `r2` с `rabin2 -zz`. Полезен `strings -n 6` для поиска путей пакетов.

```bash
go version ./sample
rabin2 -I ./sample
GoReSym -t -d -p ./sample > syms.json
```

`GoReSym` (Mandiant) восстанавливает pclntab, имена функций, файлы и даже типы — незаменим для stripped Go.

## pclntab: как восстанавливаются символы

pclntab — таблица, связывающая адреса PC с функциями (`_func`), исходными файлами и номерами строк. Формат менялся между версиями Go (магия `\xf1\xff\xff\xff` для 1.16-1.19, `\xf0\xff\xff\xff` для 1.18+, версия 1.20+). Инструменты сканируют `.rdata`/`.rodata`, находят магию, определяют версию и разбирают таблицу. Для ручного разбора:

```python
import struct
data = open("sample","rb").read()
for magic in (b"\xf1\xff\xff\xff", b"\xf0\xff\xff\xff"):
    off = data.find(magic)
    while off != -1:
        print(hex(off), data[off:off+8].hex())
        off = data.find(magic, off+1)
```

По найденному смещению инструменты вычисляют базовые адреса `funcnametab`, `pctab` и `functab`, а затем сопоставляют их с адресами в `.text`.

## Соглашения вызовов и передача аргументов

До Go 1.17 аргументы передавались на стек в порядке слева направо, результаты — тоже на стек. С 1.17 включена register ABI для части вызовов (`AX, BX, CX, DI, SI, R8-R11, X0-X14`), но рантайм и ассемблерные функции по-прежнему стековые. Практически: смотрите на пролог функции — она копирует аргументы из стека в регистры/локальные слоты. Слайс — три слова: указатель, длина, ёмкость; строка — два слова: указатель и длина. Интерфейс — два слова: itab (или тип) и указатель на данные.

```asm
; типичный пролог: аргументы по [rsp+8], [rsp+16], ...
MOVQ 0x8(SP), AX      ; arg0
MOVQ 0x10(SP), BX     ; arg1
```

## Строки, слайсы, карты и интерфейсы

`string` в Go — неизменяемая пара `{data, len}`. Слайс `[]byte` — `{data, len, cap}`. `map` — указатель на структуру `hmap` со бакетами; реверс карт сложен, но `runtime.mapaccess*` вызывается явно, что даёт подсказки. Интерфейс — `iface{tab, data}`. Понимание этих структур критично для аргументов функций: в дизассемблере вы увидите, как `len` берётся из соседнего слова. Типы восстанавливают через `GoReSym -t` или из `runtime.typelinks`.

## Анализ горутин и планировщика

Go-программы многопоточны: горутины запускаются через `runtime.newproc`/`go func()`. В малвари это часто C2-циклы, воркеры, таймеры. В отладчике:

```bash
gdb ./sample
(gdb) info threads
(gdb) thread apply all bt
```

`runtime.newproc` получает указатель на функцию и аргументы — точка входа горутины. Планировщик (`runtime.schedule`, `runtime.mstart`) и каналы (`runtime.chanrecv`, `runtime.chansend`) видны в бэктрейсах. Для malware это подсказки о логике: сетевые воркеры, обработчики команд.

## Сетевая и крипто-логика малвари

Go-малварь активно использует стандартную библиотеку: `net/http`, `crypto/tls`, `encoding/base64`, `crypto/aes`. Строки пакетов в бинаре выдают поведение:

```bash
strings -a ./sample | grep -E 'net/http|crypto/|encoding/|os/exec' | sort -u
```

Часто конфиг зашифрован; ключ ищут рядом с вызовами `aes.NewCipher`/`rc4.NewCipher`. Полезно поставить брейкпоинт на `crypto/aes.(*cipher).Encrypt` и посмотреть на ключ в аргументах. Для ботнетов ищут адреса C2 в строках или в расшифрованном буфере.

## Стрип, обфускация и Go-специфичные защиты

`garble` — обфускатор Go, переименовывающий функции, шифрующий строки и вставляющий мёртвый код. Против него: поиск runtime-функций (они не переименовываются), восстановление типов, анализ строковых литералов через места расшифровки. Стрип Go не удаляет pclntab, поэтому символы восстанавливаются. Если pclntab обрезана (редко), имена теряются, но структура функций и строк остаётся. `-ldflags "-s -w"` убирает таблицу символов, но не pclntab.

## Полный разбор: восстановление символов и поиск C2

**Шаг 1 — версия и разбор:**

```bash
go version ./bot
GoReSym -t -d ./bot > syms.json
python3 -c "import json;d=json.load(open('syms.json'));print(len(d['Funcs']))"
```

**Шаг 2 — загрузка в Ghidra** с применённым `syms.json` (через скрипт `apply_syms` или плагин): функции получают имена `main.*`, `net/http.*`.

**Шаг 3 — поиск C2:** в строках ищем URL/IP:

```bash
strings -a ./bot | grep -Eo 'https?://[^ ]+|[0-9]{1,3}(\.[0-9]{1,3}){3}' | sort -u
```

**Шаг 4 — анализ функции, читающей адрес:** находим `main.main` (или `main.run`), идём по вызовам `net.Dial`, ставим брейкпоинт, читаем расшифрованный адрес.

## Что дальше / решение

Маршрут: определите версию (`go version`), восстановите символы (`GoReSym` + Ghidra-плагин), разметьте `main.*` и `net/*`, найдите строки C2/конфига, поставьте брейкпоинты на крипто/сеть и снимите расшифрованные данные. Учитывайте stack-based вызовы и структуры `string`/`slice`/`iface` при чтении аргументов. Дальше изучите garble-обфускацию и восстановление типов через typelinks, а также анализ Go-малвари с сетевыми горутинами.

## Восстановление типов и рефлексия

Go хранит информацию о типах в таблице `runtime.typelinks`, а `reflect` использует её для динамического доступа к полям структур и методам. Это даёт аналитику возможность **восстанавливать структуры**: `GoReSym -t` извлекает определения типов, а плагины Ghidra применяют их к переменным. Зная тип, вы понимаете поля структуры и можете читать конфиг малвари по именам. Рефлексия в бинаре проявляется вызовами `reflect.*` (`reflect.TypeOf`, `reflect.Value.Field`), которые часто используются для сериализации JSON/конфигов. Если программа парсит JSON (`encoding/json`), строки тегов (`json:"..."`) в бинаре подсказывают имена полей.

## panic, defer и обработка ошибок

Go не использует исключения; ошибки — это возвращаемые значения (часто интерфейс `error`), а `panic`/`recover` — механизм для критических сбоев. В дизассемблере `defer` компилируется в вызовы `runtime.deferproc`/`runtime.deferreturn`, а `panic` — в `runtime.gopanic`. Бэктрейсы паник содержат строки файлов и номера строк, что бесценно для анализа. Проверки ошибок вида `if err != nil` превращаются в сравнение интерфейса с нулём (два слова: tab == 0). Понимание этого помогает читать поток управления: «ошибочные» ветки часто ведут к логам, а успешные — к основной логике.

## Практика: разбор ботнета с C2

Разберём типичный Go-ботнет. **Шаг 1:** `go version ./bot` — версия; `strings -a ./bot | grep -E 'http|tcp|/api'`. **Шаг 2:** `GoReSym -t -d -p ./bot > syms.json`, применяем в Ghidra. **Шаг 3:** находим `main.main` и `main.run` — обычно там цикл `for { select { ... } }` с горутинами. **Шаг 4:** ищем вызовы `net.Dial`/`http.NewRequest`, ставим брейкпоинт, читаем аргументы — там адрес C2. **Шаг 5:** если конфиг зашифрован, ставим bp на `crypto/aes.(*cipher).Encrypt` или `rc4.(*Cipher).XORKeyStream` и снимаем ключ из регистров. **Шаг 6:** проверяем расшифрованный C2 подключением в изолированной сети. Такой маршрут даёт полную картину поведения без исполнения на реальном хосте.

## Плагины и автоматизация

Для масштабной работы используют: Ghidra-плагин `golang` (автодетект pclntab, переименование), IDA `IDAGolangHelper`, `redress` (CLI: `redress info ./bin`, `redress packages`), `GoReSym` (JSON с функциями/типами). Скрипты на Python (через `pyghidra`) позволяют пакетно применять символы к десяткам образцов. Для Go-малвари полезны YARA-правила по строкам пакетов (`go1.`, `runtime.`, `main.`) — они устойчивы к переименованию, потому что рантайм не обфусцируется.

| Задача | Команда |
|---|---|
| Версия | `go version ./bin` |
| Символы+типы | `GoReSym -t -d -p ./bin` |
| Пакеты | `redress packages ./bin` |
| Автопереименование | Ghidra-плагин golang |
| YARA | строки `runtime.`, `main.` |
