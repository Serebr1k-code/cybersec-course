## Вопрос, с которого всё начинается

Ты распаковал APK игры и видишь `libil2cpp.so` — огромный нативный бинарник без символов. Логики в C#-файлах нет: Unity скомпилировала её в нативный код. Как вообще подступиться к такой игре?

## Наш пример

Распакуем `game.apk` (это zip) и осмотрим содержимое:

```bash
$ unzip -l game.apk | grep -E 'il2cpp|metadata|lib/'
  8123456  lib/arm64-v8a/libil2cpp.so
  1234567  assets/bin/Data/Managed/Metadata/global-metadata.dat
```

Две ключевые вещи: `libil2cpp.so` (сгенерированный нативный код) и `global-metadata.dat` (метаданные C#-классов, методов, строк). По отдельности они бесполезны — нужны вместе.

## Шаг 1: что такое IL2CPP и Mono

Unity умеет собирать игру двумя способами. **Mono**: C# компилируется в IL и исполняется виртуальной машиной Mono — логика лежит в `Assembly-CSharp.dll`, которую открывает `dnSpy`/`ILSpy`. **IL2CPP**: IL-код транслируется в C++ и компилируется в нативный `libil2cpp.so`; метаданные (имена классов/методов) выносятся в `global-metadata.dat`. Понимание, какой бэкенд использован, определяет весь дальнейший подход.

## Шаг 2: определяем бэкенд

Если в APK есть `Assembly-CSharp.dll` — это Mono, и анализ прост. Если есть `libil2cpp.so` + `global-metadata.dat` — IL2CPP. Иногда встречается гибрид (некоторые сборки Mono, некоторые IL2CPP). Проверяй `assets/bin/Data/Managed/` и `lib/*/`. Для нашего примера — чистый IL2CPP.

## Шаг 3: Il2CppDumper

Главный инструмент — **Il2CppDumper**. Он читает `global-metadata.dat` и `libil2cpp.so`, сопоставляет метаданные с нативными адресами и выдаёт: `dump.cs` (псевдо-C# со всеми классами и методами), `script.py`/`ida.py` (скрипт для IDA/Ghidra, который расставит имена), `il2cpp.h` (структуры). Запуск:

```bash
$ Il2CppDumper libil2cpp.so global-metadata.dat out/
Initializing metadata...
Detected Unity version: 2021.3.5f1
Dumping...
Done!
```

Версия Unity важна: от неё зависит раскладка структур метаданных, и Dumper подбирает её автоматически.

## Шаг 4: читаем dump.cs

`dump.cs` — это «карта» игры: классы, поля, методы с их адресами (RVA). Ищи по строкам ключевые классы: `Player`, `Money`, `Health`, `Check`, `License`. Например:

```csharp
// RVA: 0x1A2B3C Offset: 0x1A2B3C VA: 0x1A2B3C
public void SetScore(int value) { }
```

Здесь `RVA` — смещение метода в `libil2cpp.so`. Теперь ты знаешь, где в нативном коде искать логику.

## Шаг 5: связываем с нативным кодом

Импортируй `libil2cpp.so` в Ghidra/IDA и примени `script.py` из Dumper — имена методов встанут на свои места. Дальше анализируешь функцию как обычный ARM64-код (см. урок про ARM64). Или, если нужно быстро изменить поведение, правишь байты прямо по RVA (например, заставляешь `check` всегда возвращать 1).

## Шаг 6: патчинг и перепаковка

Меняешь `libil2cpp.so` (hex-патч или пересборка), кладёшь обратно в APK, подписываешь (`apksigner`) и устанавливаешь. Для этого нужен патч по адресу: например, заменить начало функции на `mov w0, #1; ret` (ARM64: `20 00 80 52 C0 03 5F D6`). Важно сохранить выравнивание и не сломать соседний код.

## Шаг 7: где это в реальной работе

Реверс Unity-игр нужен для анализа читов и античит-механик, для CTF, для исследования DRM. Тот же навык применяется к любому IL2CPP-приложению, а не только к играм: Unity используется в мобильных приложениях, VR/AR, симуляторах. Понимание метаданных — ключ ко всей логике.

## Что мы теперь знаем

- Unity собирает логику либо в Mono (IL в `Assembly-CSharp.dll`), либо в IL2CPP (нативный код + метаданные).

- `global-metadata.dat` хранит имена классов/методов, `libil2cpp.so` — скомпилированный код.

- Il2CppDumper связывает их и выдаёт `dump.cs` + скрипт для Ghidra/IDA.

- По RVA находишь метод в нативном коде и можешь анализировать или патчить.


## Шаг 8: анализ конкретной функции игры

Допустим, в `dump.cs` есть класс `Player` с методом `get_IsPremium` и полем `_premium`. По RVA из Dumper находим метод в Ghidra (после применения скрипта имя уже стоит). Читаем ARM64: метод просто возвращает значение поля `this->_premium` (загружает по смещению из `x0`). Чтобы разблокировать премиум, достаточно либо пропатчить возврат (`mov w0, #1; ret`), либо изменить поле в памяти через Frida. Так «логика игры» превращается в конкретную пару «адрес + байты», что и есть цель игрового реверса.

## Шаг 9: Frida для динамики Unity

Если игра защищена от патча на диске, идём в память. Frida-скрипт находит экспортированную функцию `il2cpp_resolve_icall`/`il2cpp_class_get_method_from_name`, получает адрес нужного метода по имени класса и метода и хукает его: `Interceptor.attach(addr, { onLeave(retval){ retval.replace(1); } })`. Это позволяет менять поведение без изменения файла. Для Unity есть готовые хелперы (`frida-il2cpp-bridge`), которые дают доступ к классам и полям по именам — это сильно ускоряет анализ.

## Шаг 10: шифрование метаданных

Некоторые студии шифруют `global-metadata.dat` (например, XOR-ом или AES), чтобы Il2CppDumper не смог его прочитать. Признак: Dumper падает на «metadata magic error». Решение: найти в `libil2cpp.so` функцию, которая читает метаданные (ищи строку `global-metadata.dat`), и воспроизвести расшифровку: обычно это простой XOR или вызов стандартного AES. После расшифровки Dumper работает как обычно. Иногда метаданные разбиты на части — тогда их собирают в памяти через Frida.

## Шаг 11: инструменты вокруг

Помимо Il2CppDumper: **Il2CppInspector** (строит более полный дамп, включая generics), **Il2CppDumper GUI**, **Zygisk-Il2CppDumper** (дамп метаданных прямо из памяти на устройстве, обходя шифрование на диске), **Frida-скрипты для Unity**. Для декомпиляции C# — `dnSpy` (если удаётся извлечь IL). Набор инструментов зависит от версии Unity и степени защиты.

## Шаг 12: где искать флаг/ключ в CTF

В CTF-задачах на Unity флаг обычно зашит в: (1) строку в `global-metadata.dat` (ищи `nto{` прямо в метаданных через `strings`), (2) поле класса, которое сравнивается в `check`-методе, (3) ресурс (текстура, звук), (4) результат вычисления в нативном коде. Порядок действий: `strings` по метаданным → Dumper → поиск `check`/`flag` в `dump.cs` → анализ метода. Часто флаг находится за пару минут.

## Шаг 13: чек-лист разбора Unity-игры

(1) Определить бэкенд (Mono/IL2CPP). (2) Для IL2CPP — извлечь `libil2cpp.so` и `global-metadata.dat`. (3) Прогнать Il2CppDumper. (4) Изучить `dump.cs`, найти ключевые классы. (5) Применить скрипт в Ghidra/IDA. (6) Проанализировать или пропатчить целевой метод. (7) Проверить результат динамически (Frida). Этот чек-лист покрывает 90% Unity-задач.

## Шаг 14: как устроены метаданные изнутри

`global-metadata.dat` начинается с магического числа `0xFAB11BAF`, затем идёт версия метаданных и таблица смещений к пулам: строки, типы, методы, поля, параметры. Пул строк — это просто последовательность C-строк с завершающим нулём, поэтому `strings` по файлу уже показывает имена классов и методов. Именно на этой структуре строится вся работа Dumper-а: он читает пулы и сопоставляет индексы методов с адресами в `libil2cpp.so` через таблицы, которые компилятор Unity сгенерировал в нативной библиотеке. Понимание этой структуры важно, когда Dumper не справляется: ты можешь вручную прочитать пул строк и найти нужное имя, а потом искать его использование в коде.

## Шаг 15: защита Unity-игр

Студии применяют: обфускацию имён (переименование классов в мусор — тогда `dump.cs` бесполезен по именам, но структура сохраняется), шифрование метаданных (см. выше), античит-плагины, проверки целостности `libil2cpp.so`. Против обфускации имён помогает анализ по поведению: ищи функции, работающие с деньгами/здоровьем, по константам и вызовам. Против шифрования — дамп метаданных из памяти (`Zygisk-Il2CppDumper`). Против античита — динамический анализ и понимание его проверок.

## Шаг 16: практический пример с CTF

Типичная CTF-задача: APK с Unity, флаг проверяется функцией `CheckFlag`. Порядок: `unzip` → находим `libil2cpp.so` + `global-metadata.dat` → Il2CppDumper → `dump.cs` → ищем `CheckFlag` → берём RVA → открываем `libil2cpp.so` в Ghidra со скриптом → читаем ARM64-логику → восстанавливаем проверку (часто XOR/сравнение) → считаем флаг. Весь путь занимает 10-20 минут при наличии инструментов. Если метаданные зашифрованы — сначала дамп из памяти.

## Шаг 17: инструменты в деталях

Il2CppDumper поддерживает разные версии Unity и режимы (`--method`-дамп, `--script`-генерация для IDA/Ghidra/Binary Ninja). Il2CppInspector строит полный граф типов, включая generics — полезно для сложных игр. Zygisk-Il2CppDumper работает как Magisk-модуль и дампит метаданные из памяти, обходя шифрование на диске. Frida-il2cpp-bridge даёт высокоуровневый доступ к объектам в рантайме. Набор выбирается по уровню защиты игры.
