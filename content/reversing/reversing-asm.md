## Вопрос, с которого всё начинается

В прошлом уроке мы нашли пароль `hunter2` прямо в строках. Но так везёт не всегда: в реальной
задаче строка может быть зашифрована, проверка — спрятана, а сравнение — самодельное. Тогда
единственный путь — **прочитать машинный код**. Но как его читать, если это не текст, а
мнемоники вроде `mov`, `lea`, `call`?

В этом уроке мы возьмём ту же функцию `check_password` из `crackme` и разберём её ассемблер
строка за строкой. Это ядро всего реверса.

## Наш пример

Дизассемблировать будем тем же `crackme`. Инструмент — `objdump` из пакета binutils. Флаг
`-d` говорит «дизассемблируй код», `-M intel` — «печатай в синтаксисе Intel» (он читается
проще, чем AT&T). Посмотрим функцию проверки:

```bash
$ objdump -d -M intel crackme | sed -n '/<check_password>:/,/ret/p'
0000000000001179 <check_password>:
    1179: 55                    push   rbp
    117a: 48 89 e5              mov    rbp,rsp
    117d: 48 83 ec 20           sub    rsp,0x20
    1181: 48 89 7d e8           mov    QWORD PTR [rbp-0x18],rdi
    1185: 48 8d 05 7c 0e 00 00  lea    rax,[rip+0xe7c]        # 2008
    118c: 48 89 45 f8           mov    QWORD PTR [rbp-0x8],rax
    1190: 48 8b 55 f8           mov    rdx,QWORD PTR [rbp-0x8]
    1194: 48 8b 45 e8           mov    rax,QWORD PTR [rbp-0x18]
    1198: 48 89 d6              mov    rsi,rdx
    119b: 48 89 c7              mov    rdi,rax
    119e: e8 cd fe ff ff        call   1070 <strcmp@plt>
    11a3: 85 c0                 test   eax,eax
    11a5: 0f 94 c0              sete   al
    11a8: 0f b6 c0              movzx  eax,al
    11ab: c9                    leave
    11ac: c3                    ret
```

Столбцы: адрес инструкции, её байты в hex, мнемоника. Читать будем по мнемонике — байты
пока пропускаем.

## Шаг 1: регистры — это быстрые ячейки процессора

У процессора есть маленькие сверхбыстрые ячейки — **регистры**. В x86-64 для нас важны:

- **rdi, rsi, rdx, rcx, r8, r9** — сюда по очереди кладут первые шесть аргументов функции.
- **rax** — обычно возвращаемое значение.
- **rsp** — указатель на вершину стека.
- **rbp** — «база кадра», опорная точка текущей функции.

У правил «какой регистр за что отвечает» есть название — **соглашение о вызовах** (calling
convention). Оно одинаковое у всех функций: если функция принимает строку первым аргументом,
компилятор положит её в `rdi`.

Увидев `mov rdi, rax`, читай буквально: «в регистр `rdi` кладём то, что в `rax`». Именно так
готовятся аргументы перед вызовом.

## Шаг 2: читаем check_password

Идём сверху вниз.

`push rbp` и `mov rbp, rsp` — это **пролог функции**: сохраняем старую базу кадра и ставим
новую. Дальше `rbp` — наша точка отсчёта, локальные переменные лежат по адресам вроде
`[rbp-0x18]`.

`sub rsp, 0x20` — резервируем 32 байта под локальные переменные (двигаем вершину стека вниз).

Ключевые строки:

```
1181: mov QWORD PTR [rbp-0x18], rdi   ; сохранили пришедший аргумент (указатель на ввод)
1185: lea rax, [rip+0xe7c]            ; в rax попал адрес строки по смещению → 0x2008
118c: mov [rbp-0x8], rax              ; сохранили этот адрес как локальную переменную
```

`lea` (load effective address) — «положи в регистр адрес». Здесь по адресу `0x2008` лежит
наша строка-секрет. А дальше:

```
1190: mov rdx, [rbp-0x8]   ; rdx = указатель на секрет
1194: mov rax, [rbp-0x18]  ; rax = указатель на ввод
1198: mov rsi, rdx         ; второй аргумент strcmp = секрет
119b: mov rdi, rax         ; первый аргумент strcmp = ввод
119e: call 1070 <strcmp@plt>
```

Получается: `strcmp(ввод, секрет)`. Мы своими глазами видим, **что с чем сравнивают** — а
значит, и где искать секрет (`0x2008`).

## Шаг 3: вызов функции — инструкция call

`call 1070 <strcmp@plt>` делает две вещи: кладёт на стек адрес возврата (чтобы функция знала,
куда вернуться) и прыгает на код `strcmp`. Сам `strcmp` лежит в библиотеке `libc` — запись
`@plt` означает «вызов через таблицу переходов» (об этом в отдельном уроке).

Функция возвращает результат в `rax`: `strcmp` возвращает `0`, если строки равны, и не ноль
в противном случае. Поэтому дальше:

```
11a3: test eax, eax      ; проверяем результат сравнения
11a5: sete al            ; al = 1, если eax == 0 (строки равны)
11a8: movzx eax, al      ; расширили 1 байт до 4: получаем 0 или 1
```

`test eax, eax` — это «сравни `eax` с нулём». `sete al` — «поставь байт `al` в 1, если флаг
равенства установлен». Итого функция возвращает `1`, если пароль верный, и `0` иначе.

## Шаг 4: ветвление — cmp и условные переходы

Ветвления мы увидим в `main`. Смысл такой: инструкция `cmp` (или `test`) выставляет флаги, а
условный переход (`je`, `jg`, `jne`, `jl`) прыгает или не прыгает в зависимости от флага.

```bash
$ objdump -d -M intel crackme | sed -n '/<main>:/,/call.*check_password/p' | tail -14
    123d: mov rax, [rbp-0x60]    ; rax = счётчик i
    1241: cmp rax, [rbp-0x58]    ; сравнили i с длиной ввода
    1245: jl  1218 <main+0x6b>   ; если i < длина — назад в цикл
    1247: lea rax, [rbp-0x50]    ; rax = адрес буфера ввода
    124b: mov rdi, rax           ; первый аргумент = буфер
    124e: call 1179 <check_password>
    1253: test eax, eax          ; вернула ли проверка 1?
    1255: je  1268 <main+0xbb>   ; если 0 — на ветку «Wrong»
```

Читается как обычный `if`: вызываем `check_password`, проверяем `eax`; если ноль — прыгаем
на блок с сообщением `Wrong`. Никакой магии — те же условия, что в C.

## Шаг 5: кадр стека

Стек — это область памяти, растущая «вниз» по адресам. Каждая функция создаёт свой **кадр**
(frame): `push rbp`/`mov rbp,rsp` в начале, `leave` в конце (это `mov rsp,rbp` + `pop rbp`).
Локальные переменные живут по адресам ниже `rbp`, например `[rbp-0x18]`.

В `main` мы видим ещё одну важную деталь:

```
11b5: mov rax, QWORD PTR fs:0x28   ; загрузили сторожевой маркер (canary)
11be: mov [rbp-0x8], rax           ; положили его на стек
...
1280: sub rdx, QWORD PTR fs:0x28   ; сверили с оригиналом в конце
128b: call __stack_chk_fail@plt    ; если изменился — аварийный выход
```

Это та самая защита `Canary found` из прошлого урока: перед возвратом функция сверяет
маркер и падает, если он изменён. Для реверса это просто шум в конце функции, который можно
мысленно вычеркнуть.

## Что мы теперь знаем

- **Регистры** — быстрые ячейки; первые аргументы функции идут в `rdi, rsi, rdx, ...`,
  результат — в `rax`.
- **mov** копирует, **lea** кладёт адрес, **call** вызывает функцию.
- **test/cmp** выставляют флаги, **je/jg/jl** прыгают по ним — так выглядят `if` и циклы.
- **Пролог/эпилог** (`push rbp`…`leave`) создают кадр стека; локальные переменные — ниже `rbp`.
- Мы прочитали `check_password` и увидели: `strcmp(ввод, секрет)`.

## Куда дальше

Теперь ты умеешь читать ассемблер. Следующий вопрос: откуда взялись адреса вроде `0x2008` и
что вообще лежит в разных частях файла — секциях и сегментах? В следующем уроке мы разберём
**форматы исполняемых файлов** и посмотрим, где именно хранится строка-секрет. А пока главное
запомни: `rdi, rsi, rdx...` — аргументы, `rax` — результат, `test`+`je` — это `if`.

## Где пригодится

- **CTF Reversing:** чтение проверок пароля/флага в дизассемблере — базовый навык.
- **Pwn:** понимание регистров и вызовов нужно для шеллкода, ROP и гаджетов.
- **Malware analysis:** по ассемблеру видно, что образец шифрует, куда звонит, что сравнивает.
- **Отладка без исходников:** в gdb/WinDbg вы читаете ровно те же инструкции.
- **Собес:** «как передаются аргументы в x86-64», «что делает `lea`» — частый вопрос.
