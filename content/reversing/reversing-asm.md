Ассемблер — это язык, на который компилятор переводит любой C/C++/Rust. Без умения читать
ассемблер реверс превращается в гадание. Хорошая новость: в 90% задач вы видите лишь десяток
типовых инструкций и два-три соглашения о вызовах. Эта статья — про то, как их читать.

## Регистры x86-64

В 64-битном режиме есть 16 регистров общего назначения по 64 бита. У каждого есть младшие
подрегистры (32/16/8 бит), которые меняются при записи.

| 64 бита | 32 | 16 | 8 | Назначение |
|---------|----|----|---|-----------|
| RAX | EAX | AX | AL | Аккумулятор, **возврат функции** |
| RBX | EBX | BX | BL | Калибруемый (callee-saved) |
| RCX | ECX | CX | CL | Счётчик циклов, 4-й аргумент |
| RDX | EDX | DX | DL | 3-й аргумент, старшая часть умножения |
| RSI | ESI | SI | SIL | **2-й аргумент** функции |
| RDI | EDI | DI | DIL | **1-й аргумент** функции |
| RBP | EBP | BP | BPL | Указатель базы стекового фрейма |
| RSP | ESP | SP | SPL | Указатель вершины стека |
| R8–R15 | R8D–R15D | … | R8B–R15B | 5-й…6-й аргументы и временные |

Важно: **запись в 32-битный регистр обнуляет старшие 32 бита**. `mov eax, 1` очищает весь RAX.

Плюс специальные:

- **RIP** — instruction pointer, адрес текущей инструкции (нельзя писать напрямую).
- **RFLAGS** — флаги (ZF, SF, CF, OF), управляют условными переходами.

## Основные инструкции

Заучите этот минимум — он покрывает почти всё, что вы увидите.

```asm
; Пересылка
mov  rax, rbx        ; rax = rbx
mov  eax, 0x10       ; rax = 0x10 (старшие обнуляются)
lea  rax, [rbx+8]    ; rax = rbx + 8  (адресная арифметика, НЕ читает память)
mov  rax, [rbx]      ; rax = *(long*)rbx  (квадратные скобки = разыменование)

; Арифметика
add  rax, 5          ; rax += 5
sub  rax, rcx        ; rax -= rcx
imul rax, rbx        ; rax *= rbx (знаковое)
xor  rax, rax        ; rax = 0 (идиома обнуления, компилятор любит её)
inc  rax / dec rax   ; ++ / --

; Стек
push rax             ; rsp -= 8; [rsp] = rax
pop  rax             ; rax = [rsp]; rsp += 8

; Управление
call func            ; push(rip_next); rip = func
ret                  ; rip = pop()
jmp  label           ; безусловный переход
je   label           ; jump if ZF=1 (равно)
jne  label           ; jump if ZF=0 (не равно)
jg / jl / jge / jle  ; знаковые сравнения
cmp  rax, rbx        ; выставить флаги по (rax - rbx)
test rax, rax        ; выставить флаги по (rax & rax) — проверка на 0
```

Ключевой момент: **`cmp`/`test` сами не ветвятся** — они только выставляют флаги, а следующая
`jXX` уже решает, куда идти. Поэтому в дизассемблере ищите пары `cmp` + `jXX`.

## Стек и стековый фрейм

Стек растёт **вниз** (от старших адресов к младшим). Пролог функции сохраняет старый RBP и
резервирует место под локальные переменные:

```asm
push rbp            ; сохранили RBP вызывающего
mov  rbp, rsp       ; rbp = кадр текущей функции
sub  rsp, 0x20      ; место под локальные переменные (32 байта)
...
leave               ; mov rsp, rbp; pop rbp   (эпилог)
ret
```

Локальные переменные адресуются как `[rbp-4]`, `[rbp-0x10]`; аргументы, «переползшие» в стек,
как `[rbp+0x10]`. Компилятор с оптимизацией (`-O2`) часто использует `rsp` вместо `rbp`
(frame pointer omission), и тогда ориентироваться нужно по смещениям от RSP.

## Соглашение о вызовах System V AMD64 (Linux)

Это самое важное для реверса. Порядок аргументов функции:

| Аргумент | Регистр |
|----------|---------|
| 1-й | RDI |
| 2-й | RSI |
| 3-й | RDX |
| 4-й | RCX |
| 5-й | R8 |
| 6-й | R9 |
| 7-й+ | через стек |

Возврат — в **RAX**. Функция обязана сохранять RBX, RBP, R12–R15 (callee-saved); RAX, RCX, RDX,
RSI, RDI, R8–R11 — «портящиеся» (caller-saved).

Пример: `printf("Result: %d\n", x)` компилируется примерно так:

```asm
lea  rdi, [rip+fmt]     ; 1-й аргумент = адрес строки формата
mov  esi, eax           ; 2-й аргумент = x
xor  eax, eax           ; вариативные функции: al = число векторных регистров
call printf@plt
```

Windows x64 использует другое соглашение: RCX, RDX, R8, R9 (первые 4), плюс 32 байта shadow
space. Это важно при реверсе PE-файлов.

## Практический пример: читаем функцию check

Пусть дизассемблер (radare2 `pdf` или Ghidra Listing) показывает:

```asm
check:
  push rbp
  mov  rbp, rsp
  mov  [rbp-8], rdi        ; сохранили указатель на ввод
  mov  rax, [rbp-8]
  movzx eax, byte [rax]    ; eax = input[0]
  cmp  al, 0x43            ; сравнить с 'C'
  jne  .wrong
  mov  rax, [rbp-8]
  movzx eax, byte [rax+1]  ; input[1]
  cmp  al, 0x54            ; 'T'
  jne  .wrong
  mov  eax, 1              ; вернуть 1 (успех)
  jmp  .done
.wrong:
  mov  eax, 0              ; вернуть 0
.done:
  pop  rbp
  ret
```

Читаем: функция берёт `rdi` (1-й аргумент — указатель на строку), сравнивает первый байт с
`0x43` ('C'), второй с `0x54` ('T'), и возвращает 1 при совпадении. Значит, пароль начинается
на `CT...`. В реальных задачах таких сравнений десятки, и вы просто собираете строку по байтам.

Как быстро читать такие блоки: **замените числовые константы на символы** (0x43 → 'C'), и код
сразу станет читаемым. В radare2 это делается включением режима `e asm.var.sub` и просмотром
аннотаций; в Ghidra символы подставляются автоматически в комментариях.

## Полезные приёмы при чтении

- **Ищите строку-подсказку.** Адрес строки `Wrong password` через `lea rdi, [rip+X]` рядом с
  вызовом `puts`/`printf` укажет на функцию проверки.
- **`strcmp`/`memcmp` — золотая жила.** `mov rdi, input; lea rsi, [rip+secret]; call strcmp` →
  secret и есть пароль.
- **Циклы.** Тело цикла между меткой и обратным `jmp`; счётчик часто в `rcx` или `rax`.
- **Таблицы переходов.** `jmp [rax*8 + table]` = `switch` — смотрите таблицу адресов.
- **`xor eax,eax; ret`** — функция возвращает 0 (заглушка).
- **Не путайте `lea` и `mov`.** `lea` считает адрес, `mov` с `[]` читает память.

## Типичные ошибки новичка

- **Считать `lea` загрузкой памяти.** `lea rax,[rbx+8]` — это `rax = rbx+8`, без обращения к памяти.
- **Путать порядок аргументов.** RDI — первый, RSI — второй (System V). В Windows — RCX, RDX.
- **Игнорировать размер.** `mov al, 0x41` пишет 1 байт, `mov eax, 0x41` — 4 (и обнуляет старшие).
- **Не смотреть на `movzx`/`movsx`.** `movzx` дополняет нулями, `movsx` — знаком; влияет на сравнения.
- **Читать без контекста.** Одна инструкция бессмысленна; смотрите блок целиком (пролог → логика → эпилог).
- **Забыть про AT&T vs Intel.** `objdump` по умолчанию AT&T (`mov %rsi,%rdi` — порядок обратный);
  используйте `objdump -M intel` или radare2/Ghidra с Intel-синтаксисом.

## Где пригодится

- **CTF Reversing:** чтение `check_password`, восстановление пароля по байтовым сравнениям.
- **Pwn:** понимание гаджетов ROP, шеллкода, утечек — тот же ассемблер.
- **Отладка нативного кода:** понять, почему крэшится `segfault` (адрес в RIP, регистры).
- **Malware analysis:** расшифровка рутинных процедур (XOR-циклы, копирование строк).
- **Собес:** «какой регистр первый аргумент», «что делает lea» — обязательный минимум.
