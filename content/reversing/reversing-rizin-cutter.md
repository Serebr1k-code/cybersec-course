radare2 долгое время был стандартом консольного реверса, но в 2020 году команда разработчиков
создала форк **rizin** — с переработанной кодовой базой, более чистым API и активной разработкой.
Поверх rizin построен **Cutter** — графический интерфейс, делающий интерактивный анализ удобным.
Эта пара инструментов даёт быстрый вход в бинарник без тяжёлого импорта: rizin анализирует файл за
секунды и позволяет перемещаться по функциям, строкам и ссылкам командами из одной буквы.

## Чем rizin отличается от radare2

Синтаксис команд почти совпадает (r2 → rz), но есть важные различия. Проект rizin развивается
открыто под эгидой сообщества, использует современные стандарты C, разделил библиотеки и переписал
часть подсистем. Команды начинаются с `rz-` (`rz-bin`, `rz-asm`, `rz-ax`), а интерактивный
интерпретатор — `rizin`. Проект radare2 продолжает существовать; выбирайте rizin, если хотите
актуальную поддержку и Cutter.

Практическая разница для пользователя минимальна: большинство скриптов r2 работают с минимальными
правками. Но экосистема Cutter, декомпилятор rz-ghidra и плагины интегрированы именно в rizin.

Владение rizin/Cutter окупается скоростью: пока Ghidra строит проект несколько минут, rizin уже
показывает нужную функцию. Это делает его инструментом первого выбора для быстрых задач, а Ghidra и
IDA остаются для глубокого анализа и декомпиляции сложных целей. Многие реверсеры держат оба
инструмента и переключаются по ситуации.

## Установка и базовые команды

Установка: `git clone https://github.com/rizinorg/rizin && meson setup build && ninja -C build`
или пакетом (`apt install rizin`). Cutter ставится отдельно (AppImage или пакет).

Базовый запуск: `rizin ./crackme`. Внутри — команды из одной-двух букв:

| Команда | Действие |
|---|---|
| `aaa` | полный анализ (функции, ссылки, строки) |
| `afl` | список функций |
| `pdf` | дизассемблировать текущую функцию |
| `pdf @ main` | дизассемблировать `main` |
| `s main` | перейти к символу `main` |
| `s 0x1140` | перейти по адресу |
| `px 64` | hexdump 64 байт |
| `psz @ str.hello` | вывести строку |
| `iz` / `izz` | строки в данных / во всём файле |
| `axt @ sym.imp.puts` | кто вызывает `puts` |
| `afl~?` | фильтр вывода (grep) |
| `V` | визуальный режим |
| `VV` | граф функции |

Символ `~` — фильтр (аналог grep), `@` — «временно перейти по адресу для команды». Комбинация
`pdf @ main` — одна из самых частых.

## Анализ и навигация

После `aaa` rizin строит карту функций и ссылок. `afl` выводит список с адресами, размерами и
именами. Функции без имён получают метки `fcn.00001234`. Переход `s <addr>` и дизассемблер `pdf`
дают локальную картину; `axt` (xrefs to) показывает, откуда функция вызывается, `axf` — куда она
вызывает. Это позволяет быстро строить граф вызовов.

Для поиска полезны `izz` (все строки), `iz~flag` (строки со словом flag), `/x 7f454c46` (поиск
байтов), `/r 0x...` (поиск ссылок на адрес). Флагманская особенность — единая адресация: и данные,
и код в одном пространстве, что удобно для анализа структур и указателей.

## Эмуляция: ESIL

rizin содержит **ESIL** (Evaluable Strings Intermediate Language) — промежуточный язык для
эмуляции инструкций. Команда `aei` инициализирует эмуляцию, `aeim` создаёт стек/память, `aeip`
устанавливает PC, `aesu <addr>` выполняет до адреса, `aer` показывает регистры. ESIL позволяет
прогонять участки кода без реального запуска — например, расшифровать строку или вычислить ключ.

Пример: загрузить бинарник, найти функцию расшифровки, установить входные регистры (`aer eax=0x...`),
выполнить `aesu` и прочитать память через `px`. Это мощный приём для CTF, где расшифровка проста, но
запускать бинарник неудобно.

ESIL особенно полезен для автоматического анализа: можно поставить ловушку на чтение памяти
(`aets`/`aez`), пройти по коду и собрать значения, которые вычисляются из констант. Это быстрее
полноценного символического исполнения и часто достаточно, чтобы восстановить простой алгоритм
(например, XOR-расшифровку строки или вычисление хеша). Для сложных случаев используйте angr
(см. уроки по символическому исполнению), но начинайте с ESIL — он даёт результат за секунды.

## Скриптинг: rz-pipe

Автоматизация — через `rz-pipe` (Python, JS, Rust, C). Установка: `pip install rzpipe`, затем:

```python
import rzpipe
rz = rzpipe.open("./crackme")
rz.cmd("aaa")
funcs = rz.cmdj("aflj")            # JSON-вывод
for f in funcs:
    print(hex(f["offset"]), f["name"])
strings = rz.cmdj("izzj")
for s in strings:
    if "flag" in s.get("string", ""):
        print(hex(s["vaddr"]), s["string"])
rz.quit()
```

`cmdj` возвращает JSON — удобно для разбора. Так строятся автоматические пайплайны: поиск всех
строк с «flag», дизассемблирование функций, которые к ним обращаются, извлечение сравнений.

## Cutter: графический интерфейс

Cutter — Qt-приложение, использующее rizin как движок. Возможности: дизассемблер с подсветкой,
граф функций, декомпилятор (через rz-ghidra), список строк, поиск, отладчик, эмуляция, консоль
rizin. Cutter удобен для быстрого визуального разбора: щёлкаете по функции — видите её код,
переходите по ссылкам, переименовываете, добавляете комментарии. Встроенная консоль позволяет
выполнять любые команды rizin, а декомпилятор — читать псевдо-C.

Для CTF Cutter — отличный выбор, когда нужен быстрый анализ без импорта в Ghidra/IDA. Минус —
меньше продвинутых функций, чем в IDA, и декомпилятор (rz-ghidra) уступает Hex-Rays.

## Практический разбор

Типичный сценарий разбора crackme:

```
$ rizin ./crackme
[0x00001050]> aaa
[x] Analyze all flags starting with sym. and entry0
[x] Analyze function calls
...
[0x00001050]> afl
0x00001050    1     22 entry0
0x00001140    1     45 main
0x00001180    1     30 sym.check
[0x00001140]> s main
[0x00001140]> pdf
┌ 45: int main (int argc, char **argv);
│  ; var char *s @ rbp-0x20
│           0x00001140      push rbp
│           0x00001141      mov rbp, rsp
│           0x0000114a      lea rax, [rip + 0xeb7]   ; "enter password"
│           0x00001151      mov rdi, rax
│           0x00001154      call sym.imp.puts
│           0x0000116a      call sym.check
│           0x00001170      test eax, eax
│           0x00001172      je 0x117a
│           0x00001174      lea rax, [rip + 0xea5]   ; "correct"
│           0x0000118b      ret
[0x00001140]> s sym.check
[0x00001180]> pdf
│  ; var char *s1 @ rbp-0x10
│           0x00001180      push rbp
│           0x00001181      mov rdi, rax
│           0x00001187      call sym.imp.strcmp
│           0x0000118c      test eax, eax
│           0x0000118e      sete al
│           0x00001191      ret
[0x00001180]> iz~secret
0   0x00002004 0x00002004 6  7   .rodata ascii secret
```

За несколько команд мы нашли `check`, увидели вызов `strcmp` и строку `secret`. Это и есть пароль.
В Cutter то же самое делается мышью: список функций → `main` → переход в `check` → граф.

## Визуальный режим и графы

rizin имеет встроенные визуальные режимы, доступные прямо из консоли. Команда `V` включает
интерактивный дизассемблер с прокруткой, подсветкой и переходами по клавишам (`j`/`k` — вниз/вверх,
`;` — комментарий, `d` — определить функцию, `u` — отменить переименование). Команда `VV` рисует
граф функции с блоками и стрелками потока управления — незаменимо для анализа ветвлений и циклов.
Внутри графа `hjkl` перемещают по блокам, `g` — перейти к адресу, `p` — переключить представление.

Комбинация `V` и `p` переключает режимы отображения: дизассемблер, hexdump, декомпилированный
псевдо-C (если установлен rz-ghidra), граф. Это позволяет, не выходя из терминала, получить почти
всё, что даёт GUI. При работе по SSH визуальный режим rizin часто удобнее, чем Cutter.

## Отладка в rizin

rizin умеет отлаживать: `rizin -d ./crackme` открывает файл в режиме отладки. Команды: `db <addr>`
— breakpoint, `dc` — продолжить, `ds` — шаг, `dso` — шаг с обходом вызовов, `dr` — регистры,
`dm` — карта памяти, `px @ rsp` — стек. Есть аппаратные точки останова (`dbh`) и точки наблюдения
(`dbw` на запись, `dbr` на чтение) — то, что нужно для самомодифицирующегося кода. Отладчик rizin
поддерживает локальные процессы, удалённую отладку (`-d remote://host:port`) и ядро.

Интеграция отладки с анализом — сильная сторона: вы можете перейти к функции, поставить breakpoint
на её начало, запустить и посмотреть аргументы и стек, не переключаясь в другой инструмент.

## Подводные камни

Первое: без `aaa`/`aa` многие функции не распознаны — `afl` покажет пусто. Второе: `pdf` требует,
чтобы курсор стоял на функции; иначе дизассемблирует мусор. Третье: `@` меняет временную позицию
только для одной команды. Четвёртое: ESIL эмулирует не всё (особенно сложные инструкции и системные
вызовы). Пятое: Cutter при больших бинарниках может потреблять много памяти — для больших целей
лучше консольный rizin.

## Что дальше / решение

Практика: откройте любой crackme в rizin, сделайте `aaa`, пройдите `afl`, `s main`, `pdf`, найдите
строки `izz` и их использования `axt`. Повторите то же в Cutter. Напишите небольшой `rz-pipe`
скрипт, который находит все строки с «flag» и печатает функции, которые к ним обращаются. Далее —
`reversing-lldb` (для macOS/Linux) и `reversing-windows-debuggers`.
