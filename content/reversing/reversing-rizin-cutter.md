## Вопрос, с которого всё начинается

Ты открыл бинарник в отладчике и вроде всё понял — но хочется быстрее: не
запускать программу, а просто «прочитать» её целиком: список функций,
дизассемблер, декомпилятор, поиск строк — в одном окне. И чтобы это работало
скриптом, без ручного кликанья. Для этого есть **rizin** — инструмент, который
совмещает дизассемблер, отладчик и фреймворк для автоматизации. Разберём его на
том же бинарнике `keygen`.

## Наш пример

```
$ file keygen
keygen: ELF 64-bit LSB executable, x86-64, version 1 (SYSV),
statically linked, BuildID[sha1]=c39b57c3..., not stripped
```

Напомню главное: это статический (без libc) ELF для x86-64, адреса фиксированы,
символы не вырезаны. Управление в rizin построено на **командах-буквах**: `a` —
анализ (analysis), `p` — печать (print), `s` — переход (seek), `i` — информация.
Команды можно объединять в одну строку через `;`.

## Шаг 1: анализ и список функций

Запустим rizin в тихом режиме и попросим проанализировать всё (`aa` — «analyze
all»), затем показать функции (`afl` — «analyze function list»):

```
$ rizin -q -e scr.color=0 -c 'aa; afl' keygen
0x00401000    8 152          entry0
```

Функция одна — `entry0` (точка входа). Почему не видно `loop`, `done`, `fail`?
Потому что это **метки внутри** одной функции, а не отдельные функции. В
статическом бинарнике без вызовов всё лежит в `_start`. Наши метки — это
**локальные символы** (LOCAL), их rizin показывает через таблицу символов:

```
$ rizin -q -e scr.color=0 -c 'aa; is~loop' keygen
```

`is` — список символов, `~loop` — фильтр по подстроке (в rizin тильда `~` это
grep). Так мы находим адрес метки `loop` — `0x401026`.

## Шаг 2: дизассемблируем функцию

Перейдём по адресу (`s` — seek) и напечатаем функцию (`pdf` — «print disassemble
function»):

```
$ rizin -q -e scr.color=0 -c 'aa; s 0x401026; pdf' keygen
            ;-- loop:
        ┌─> 0x00401026      cmp   r8, 8
       ┌──< 0x0040102a      jge   loc.done
       │╎   0x0040102c      mov   al, byte [rbx + r8]
       │╎   0x00401030      xor   al, 0x5a
       │╎   0x00401032      cmp   al, byte [r9 + r8]
      ┌───< 0x00401036      jne   loc.fail
      ││╎   0x00401038      inc   r8
      ││└─< 0x0040103b      jmp   loc.loop
```

Обрати внимание: rizin сам нарисовал **граф потока управления** стрелочками —
видно, что `loop` возвращается к себе, `jge` уходит на `done`, а `jne` — на
`fail`. Это и есть цикл побайтовой проверки: `al` = очередной байт ввода, XOR с
0x5a, сравнение с байтом по `r9`.

## Шаг 3: читаем данные и строки

Секрет лежит по адресу `r9`. Посмотрим память (`px` — «print hex») и строку
(`ps` — «print string»):

```
$ rizin -q -e scr.color=0 -c 's 0x401087; ps 8' keygen
hackme!!
```

Команда `ps` с числом 8 печатает 8 байт как строку. Мы получили `hackme!!` —
это и есть секрет. А правильный ключ получается из условия `input[i] ^ 0x5a ==
secret[i]`.

## Шаг 4: эмуляция через ESIL

У rizin есть собственный движок **ESIL** (Evaluable Strings Intermediate
Language) — «промежуточный язык», на который rizin переводит каждую инструкцию,
чтобы **эмулировать** её без реального процессора. Это позволяет «прогнать»
кусок кода, подставив свои значения. Включим эмуляцию и зададим начальные
регистры:

```
$ rizin -q -e scr.color=0 -e asm.emu=true -c 'aei; aeim; aeip' keygen
```

Здесь `aei` — инициализировать эмуляцию, `aeim` — выделить память для стека,
`aeip` — поставить «эмуляционный PC» на текущий адрес. Дальше шагаем (`aes` —
emulate step) и смотрим значения регистров. Для проверки ключа удобно задать
`r8=0`, `rbx` — адрес строки ввода, `r9=0x401087`, и выполнять по одной
инструкции, наблюдая, как `al` меняется после XOR.

ESIL — это не полноценный процессор (системные вызовы и сложные инструкции он
может не поддержать), но для арифметики, XOR, сравнений и переходов его хватает
с головой.

## Шаг 5: скриптуем через rz-pipe

Ручные команды хороши для разведки, но настоящая сила — в автоматизации. У rizin
есть **rz-pipe** — библиотека, которая соединяет твой скрипт с rizin. На Python
это выглядит так:

```python
import rzpipe
rz = rzpipe.open("keygen")
rz.cmd("aa")
funcs = rz.cmdj("aflj")          # тот же afl, но вывод — JSON
for f in funcs:
    print(hex(f["offset"]), f["name"])
print(rz.cmd("s 0x401087; ps 8"))
rz.quit()
```

Ключевой трюк — суффикс `j`: `aflj`, `pdj`, `izj` возвращают не текст, а
**JSON**, который удобно разбирать в Python. Так пишут плагины, которые ищут
паттерны, сравнивают функции, строят графы.

## Шаг 6: графический интерфейс Cutter

Если не хочется запоминать команды, есть **Cutter** — графическая оболочка над
rizin. В ней тот же анализ, но в виде окон: слева список функций, по центру
дизассемблер и декомпилятор (через плагин), снизу граф, панель отладки, консоль
с командами rizin. Cutter полезен для больших бинарников, где нужно долго
ориентироваться: подсветка путей, закладки, переименование функций в один клик.

## Шаг 7: rizin против radare2

rizin — это форк **radare2**, созданный, когда часть разработчиков ушла из
проекта. Что важно знать:

- **Совместимость команд** высокая: `pdf`, `afl`, `s`, `px` работают так же, но
  есть отличия в деталях (`aaa` в r2 против `aa` + плагины в rizin).
- **rizin** делает ставку на чистый API и `rz-pipe`, у него активнее развивается
  декомпилятор (RizinDec).
- **radare2** по-прежнему популярен, у него огромная база плагинов и скриптов.

В CTF выбор не критичен — важнее уметь читать дизассемблер и граф, а синтаксис
подсказка `?` в rizin выдаёт по любой команде.

## Шаг 8: отладка прямо в rizin

rizin умеет быть не только дизассемблером, но и отладчиком. Запустим его с флагом
`-d`:

```
$ rizin -d -e scr.color=0 -c 'db 0x401026; dc; dr' keygen
```

Разберём команды: `db 0x401026` — поставить точку останова (debug break), `dc` —
продолжить (debug continue), `dr` — показать регистры (debug registers). Синтаксис
тот же, что в сессии: `s` перейти, `pdf` посмотреть функцию, `px` почитать память.
Плюс отладки в rizin — единый интерфейс: то, что ты разведал статически, сразу
проверяется в динамике без второго инструмента.

Есть и готовые подсказки: команда `?` показывает справку, `a?` — все команды
анализа, `d?` — все команды отладки. В rizin не нужно держать в голове весь
список — набери префикс с вопросительным знаком и получишь меню.

## Частые вопросы

**Почему `afl` не показывает мои метки?** Потому что это не отдельные функции, а
локальные символы внутри одной. Смотри их через `is~имя`.

**Чем `aa` отличается от `aaa`?** `aa` — базовый анализ (функции и ветвления),
каждое лишнее `a` углубляет анализ (перекрёстные ссылки, строки, эмуляция). Для
больших бинарников начинают с `aa` и добавляют уровни по мере надобности.

**Как сохранить проект?** `Ps` сохраняет сессию, `Po` открывает её обратно — удобно
для долгого разбора.

## Что мы теперь знаем

- rizin — дизассемблер, отладчик и фреймворк в одном; команды строятся из букв
  (`a`, `p`, `s`, `i`) и объединяются через `;`.
- `aa` запускает анализ, `afl` печатает функции, `pdf` — дизассемблер функции с
  нарисованным графом, `ps`/`px` читают строку/память.
- Тильда `~` фильтрует вывод, суффикс `j` даёт JSON — это основа скриптов.
- ESIL позволяет эмулировать инструкции без реального запуска.
- Через rz-pipe автоматизируют анализ, а Cutter даёт то же самое мышкой.
