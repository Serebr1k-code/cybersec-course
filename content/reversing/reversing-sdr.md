Многие устройства (пульты, датчики, IoT, BLE) общаются по радио. **SDR** (Software Defined Radio) позволяет принимать и передавать произвольный сигнал программно и реверсить протокол: демодулировать, найти формат кадра, декодировать поля и воспроизвести сигнал (replay). Это отдельный, «аппаратно-радио» пласт реверса, требующий понимания модуляции, кодирования и синхронизации. Этот урок — практический workflow RF-реверса от захвата I/Q до replay.

## Основы RF и SDR

- **Модуляция**: OOK/ASK (амплитудная, простейшая — «есть/нет несущей»), FSK/GFSK (частотная, частые датчики), PSK, LoRa (chirp spread spectrum).
- **Несущие частоты**: 315/433/868/915 МГц (ISM, sub-GHz), 2.4 ГГц (BLE/Wi-Fi/Zigbee).
- **I/Q-данные**: комплексный сигнал (синфазная/квадратурная составляющие) — то, что выдаёт SDR.
- **Полоса/сэмплрейт**: ширина захвата и частота дискретизации (должна покрывать сигнал).

## Устройства и софт

| Устройство | Возможности |
|------------|-------------|
| RTL-SDR | только приём, дешёвый (24–1766 МГц) |
| HackRF One | приём + передача (1–6000 МГц) |
| LimeSDR / USRP | full-duplex, широкополосный |
| Yard Stick One | sub-GHz TX/RX (специализированный) |
| nRF Sniffer / Ubertooth | BLE-сниффинг |

| Софт | Назначение |
|------|------------|
| `rtl_sdr`/`hackrf_transfer` | запись/передача I/Q |
| `rtl_433` | декодирование десятков sub-GHz протоколов |
| Universal Radio Hacker (URH) | демодуляция, разбор кадров, replay |
| `inspectrum` | спектрограмма |
| GNU Radio | блок-схемы обработки сигнала |
| `gqrx`/SDR# | приём/просмотр спектра |

## Захват сигнала

```bash
# RTL-SDR: запись I/Q на частоте 433.92 МГц, сэмплрейт 2.048 Мвыб/с
rtl_sdr -f 433920000 -s 2048000 capture.iq
# Просмотр спектра
inspectrum capture.iq -r 2048000
# Декодирование известных протоколов
rtl_433 -f 433.92M
# HackRF: приём и передача
hackrf_transfer -r out.iq -f 433920000 -s 2000000
```

## Спектрограмма и демодуляция

1. **Спектрограмма**: найдите несущую и моменты передачи (всплески — нажатия кнопок).
2. **Демодуляция**: OOK/FSK → битовый поток.
3. **Синхронизация**: найдите преамбулу/пилот (для выравнивания).
4. **Кадр**: длина, поля, CRC.
5. **Кодирование линии**: Manchester, NRZ, PWM, 4b/6b — декодировать перед разбором полей.

URH делает всё это визуально: режет кадры, автоматически ищет преамбулу и CRC, показывает биты. `inspectrum` — для точной спектрограммы. GNU Radio — для кастомной обработки (фильтры, синхронизация, декодер).

## Формат кадра и кодирование

- **Известный протокол**: `rtl_433` распознаёт десятки (датчики погоды, пульты, счётчики).
- **Неизвестный**: вручную по битовому потоку — искать корреляции с действиями (нажать кнопку → изменились биты).
- **Поля**: ID устройства, команда, счётчик, CRC/checksum.
- **Кодирование**: часто несколько слоёв (например, PWM + Manchester); определить каждый.

## Replay и rolling code

- **Replay**: записать кадр и воспроизвести — работает, если нет rolling code.
- **Rolling code**: пульты (KeeLoq) меняют код при каждой передаче — replay не сработает; нужен криптоанализ или уязвимость генератора.
- **Jamming + replay**: заглушить приёмник и воспроизвести (активная атака).
- **BLE/Zigbee**: анализ на уровне стека (GATT, Zigbee-ключи).

## BLE/Sub-GHz/Zigbee

- **BLE**: Wireshark + nRF Sniffer/Ubertooth; разбор GATT-сервисов/характеристик, реверс обмена.
- **Sub-GHz датчики**: `rtl_433` распознаёт автоматически — быстрый способ понять протокол.
- **Zigbee**: ключи сети, захват и разбор (иногда через отладочные интерфейсы).

## Разобранный пример: реверс пульта 433 МГц

**Шаг 1. Захват.**

```bash
rtl_sdr -f 433920000 -s 2048000 capture.iq
inspectrum capture.iq -r 2048000
```

**Шаг 2. Демодуляция в URH.** Откройте I/Q в Universal Radio Hacker: найдите всплески (нажатия кнопок), демодулируйте OOK → биты.

**Шаг 3. Разбор кадра.**

```text
[преамбула][sync][ID устройства][команда][counter][CRC]
```

Найдите преамбулу (длинная последовательность), затем поля. Сопоставьте команды с кнопками (нажимайте и сравнивайте).

**Шаг 4. CRC.** Проверьте контрольную сумму. Если её нет — возможен replay.

**Шаг 5. Replay.**

```bash
hackrf_transfer -t captured.iq -f 433920000 -s 2000000 -a 1 -x 47
```

## Модуляции и кодирование в деталях

Понимание схемы модуляции и кодирования — половина успеха:

- **OOK/ASK.** «Есть несущая» = 1, «нет» = 0. Простейшая; пульты, дешёвые датчики. Демодуляция: огибающая → порог → биты.
- **FSK/GFSK.** Две частоты (0 и 1); устойчивее к помехам. Демодуляция: разность частот (дискриминатор).
- **PSK.** Фаза несёт биты; сложнее, но эффективнее.
- **LoRa.** Chirp spread spectrum (линейная частотная модуляция); свой формат, декодеры (gr-lora).
- **Кодирование линии.** NRZ (прямое), Manchester (переход в середине бита — самосинхронизация), PWM (ширина импульса = 0/1), 4b/6b. Без декодирования линии биты «плывут».
- **Преамбула/синхрослово.** Длинная периодическая последовательность для синхронизации приёмника, затем уникальное sync-слово для начала кадра.

## Продвинутые атаки и инструменты

- **Replay** — базовый; работает без rolling code.
- **Rolling code (KeeLoq).** Код = f(счётчик, ключ); перехваченная пара «нажатие → код» не переиспользуется. Атаки: криптоанализ KeeLoq (известные слабости), side-channel, «rolljam» (заглушить + записать два кода + использовать один позже).
- **Jamming.** Заглушить целевой приёмник, чтобы «заморозить» приём кода (в рамках research).
- **BLE-атаки.** MITM (GATT-подмена), replay аутентификации, слабая pairing (Just Works), десериализация характеристик.
- **Инструменты.** `URH` (демод/разбор/replay), `gnuradio` (кастомный DSP), `gr-lora`, `rtl_433` (готовые протоколы), `nRF Sniffer`/`Ubertooth` (BLE), `Yard Stick One`/`HackRF` (TX).

## Лабораторный стенд и подготовка

Для легального RF-реверса организуйте изолированный стенд:

- **Faraday-мешок/бокс.** Чтобы не мешать чужим сигналам и не «светить» передачей, работайте в экранированном боксе (или на минимальной мощности в лаборатории).
- **Свой передатчик + свой приёмник.** Тестируйте replay на **собственном** устройстве (например, купленном пульте), а не на чужом.
- **Калибровка.** Зафиксируйте частоту, полосу и усиление (gain) — при слабом сигнале увеличьте gain, при перегрузе (clipping) уменьшите.
- **Повторяемость.** Записывайте несколько сессий; сравнивайте, чтобы отделить протокол от шума.
- **Питание.** Некоторые устройства «спят» — нажимайте кнопку в момент захвата; для датчиков — ждите периодической передачи.

## Юридические аспекты

- Передача на многих частотах ограничена законом (лицензирование); в РФ/ЕС/США свои правила.
- Работайте в **лаборатории**/экранированном боксе или в рамках CTF, где передача разрешена.
- Не глушите (jamming) чужие сигналы и не атакуйте чужие устройства.

## Частые ошибки

- **Неверная частота/модуляция.** Сигнал не демодулируется — уточните несущую и схему.
- **Игнорирование кодирования.** Manchester/PWM требуют отдельного декодера перед разбором полей.
- **Replay при rolling code.** Не сработает — нужен криптоанализ.
- **Юридические ограничения.** Передача на многих частотах запрещена.
- **Шум.** Нужна фильтрация и правильная полоса; иначе биты «плывут».
- **Только приём.** Для replay нужен передатчик (HackRF/Yard Stick One).
- **Низкий сэмплрейт.** Недостаточная полоса искажает сигнал.

## Пример декодирования поля вручную

Пусть из URH получен битовый поток пульта, и вы подозреваете формат `[preamble][id(16)][btn(4)][counter(4)][crc(8)]`. Разберите его скриптом:

```python
bits = "1010101010101010" + "1100101011110000" + "0100" + "0011" + "10110100"
def field(s, n): return int(s[:n], 2), s[n:]
preamble = bits[:16]; rest = bits[16:]
dev_id, rest = field(rest, 16)
btn, rest = field(rest, 4)
ctr, rest = field(rest, 4)
crc, rest = field(rest, 8)
print(dev_id, btn, ctr, crc)
# Сравните ctr между двумя нажатиями: если растёт -> counter
# Сравните btn при разных кнопках -> команда
```

Если `ctr` растёт монотонно, а `crc` детерминирован — вы полностью восстановили кадр и можете сгенерировать свой (при отсутствии rolling code). Такой скрипт удобно собрать в генератор/парсер для повторного использования.

## Что делать дальше / решение

1. Определите частоту и модуляцию (по даташиту/спектру).
2. Захватите I/Q (`rtl_sdr`/`hackrf_transfer`), посмотрите спектрограмму.
3. Демодулируйте (URH), найдите преамбулу и синхрослово.
4. Разберите поля (ID/команда/counter/CRC) и кодирование линии.
5. Проверьте CRC; при отсутствии rolling code — replay.
6. Для BLE/Zigbee — переходите на уровень стека (Wireshark/Sniffer).
