## Вопрос, с которого всё начинается

У тебя есть файл `firmware.elf` из Arduino-подобной платы. Ты открываешь его дизассемблером — и видишь непривычные команды `ldi`, `out`, `lpm`. Почему код так странно обращается к памяти и как читать такую прошивку?

## Наш пример

Смотрим на файл:

```
$ file firmware.elf
firmware.elf: ELF 32-bit LSB executable, Atmel AVR 8-bit, version 1 (SYSV)
```

`file` определил `Atmel AVR 8-bit`. Это уже половина успеха: мы знаем ISA. Разберёмся, чем AVR отличается от привычных процессоров.

## Шаг 1: Гарвардская архитектура — два адресных пространства

Главное отличие AVR от x86/ARM — **Гарвардская архитектура**: код (флеш) и данные (SRAM/EEPROM) лежат в разных адресных пространствах и доступны разными инструкциями. В фон-Неймановской машине (x86) ты можешь прочитать байт кода как данные по его адресу. В AVR так нельзя «просто»: чтобы прочитать флеш как данные, нужна специальная инструкция `LPM` (Load Program Memory).

Это ломает привычные приёмы. Ты не найдёшь строку в памяти простым `ld` — сначала надо понять, что программа читает флеш через `LPM` или через указатель `Z` (пару регистров `R31:R30`).

## Шаг 2: регистры и их роли

У AVR 32 регистра общего назначения (`R0`–`R31`), но с нюансами. Регистры `R26`–`R31` образуют три 16-битные пары-указателя: `X` (`R27:R26`), `Y` (`R29:R28`) и `Z` (`R31:R30`). Именно через `Z` работает `LPM`. Первые регистры могут участвовать в операциях с константами.

Типичный фрагмент:

```
$ avr-objdump -d firmware.elf | head
  6c: e0 e0        ldi r30, 0x00
  6e: f0 e0        ldi r31, 0x00
  70: 05 90        lpm r0, Z
```

`ldi r30, 0x00` и `ldi r31, 0x00` обнуляют пару `Z`, затем `lpm r0, Z` читает байт флеша по адресу из `Z` в `R0`. Так компилятор достаёт константные данные — строки, таблицы.

## Шаг 3: GPIO и периферия

Прошивка почти всегда работает с железом. У ATmega есть порты ввода-вывода `PORTB`, `DDRB`, `PINB` и т.д., расположенные в области I/O-регистров. Доступ к ним идёт через инструкции `IN`/`OUT`:

```
  72: 2b 9a        sbi 0x05, 3   ; установить бит 3 в PORTB
```

`sbi` (Set Bit in I/O) — установка бита в регистре ввода-вывода. Читая код, ты видишь: вот здесь программа зажигает светодиод, здесь читает кнопку, здесь управляет ШИМ. Это и есть «бизнес-логика» прошивки.

## Шаг 4: прерывания

AVR реагирует на события через **прерывания**. В начале флеша лежит таблица векторов — адресов обработчиков. Вектор `RESET` (адрес 0) — точка входа после включения; далее векторы таймера, UART, внешних прерываний.

Реверс-инженер начинает с RESET-вектора: там инициализация, потом бесконечный цикл `main`. Обработчики прерываний находятся по остальным векторам. Найти их можно по адресам из таблицы в начале образа.

## Шаг 5: находим строки прошивки

Даже в 8-битной прошивке есть строки — версии, отладочные сообщения, ключи. Их удобно извлекать прямо из ELF:

```
$ strings -n 5 firmware.elf | head
ATmega328P
FW v1.2 build 2021
nto{avr_h4rv4rd_lpm_str1ng}
```

Артефакт нашли. В реальном анализе так же достают версии прошивок, имена моделей и захардкоженные ключи, которые разработчик «спрятал» в бинарнике.

## Шаг 6: откуда берётся прошивка

Прошивку получают по-разному: из обновления по воздуху (OTA), через ISP/JTAG, из дампа флеша программатором или из `firmware.bin`, выдернутого из файловой системы устройства. Иногда это чистый `.bin` без заголовка — тогда её грузят по адресу `0` и дизассемблируют как raw. ELF удобнее: он хранит секции и адреса.

## Что мы теперь знаем

- AVR — Гарвардская архитектура: код и данные в разных пространствах.
- 32 регистра; пары `X`, `Y`, `Z` — указатели; `LPM` читает флеш через `Z`.
- Периферия — регистры ввода-вывода, доступ через `IN`/`OUT`/`sbi`/`cbi`.
- Прерывания — таблица векторов в начале флеша, старт с RESET.
- Строки и ключи из прошивки достаются через `strings`.
