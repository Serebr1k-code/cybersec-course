## Задача

У нас есть бинарник `xorcheck` (тот же, что и раньше): он просит ключ и отвечает `Wrong.`
на неправильный. Мы уже разобрали его через `objdump`. Теперь задача другая: **не понять
ключ, а заставить программу принимать любой ввод** — то есть обойти проверку патчем. Для
такой работы удобен `radare2` (r2): он даёт дизассемблер, hex-редактор и патчер в одном CLI.

```bash
$ printf 'anything\n' | ./xorcheck
Enter key: Wrong.
```

## Почему r2/rizin

r2 — свободный фреймворк реверса: дизассемблер + отладчик + hex-редактор + скриптовый API.
Его форк **rizin** (совместимый, с улучшениями) и GUI **Cutter** образуют открытую
альтернативу IDA/Ghidra. Сильные стороны: работает из CLI, легко автоматизируется
(`r2pipe`), поддерживает десятки архитектур, а статика и отладка живут в одной сессии.
Базовый цикл прост: открыть → проанализировать (`aaa`) → исследовать → при необходимости
отладить или пропатчить.

## Данные, с которыми работаем

Откроем бинарник с автоанализом (`-A` — это `aaa` при старте):

```bash
$ r2 -A ./xorcheck
[0x00401080]> afl~check
0x00401166    8 202  sym.check
[0x00401080]> iI~canary
canary true
[0x00401080]> s sym.check
[0x00401166]> pdf
```

`afl` — список функций (`~check` — фильтр по подстроке, тильда в r2 работает как grep).
`s sym.check` переходит к функции (seek), `pdf` печатает её дизассемблер. Функция `check`
лежит по адресу `0x401166` — это подтверждает и `nm`:

```bash
$ nm xorcheck | grep check
0000000000401166 T check
```

## Приём 1: находим, что именно проверяется

Мы уже знаем из `objdump`, что `check` делает так: длина == 16, затем `in[i] ^ 0x5a`
сравнивается с таблицей. Посмотрим на **развилку, которая решает судьбу**:

```
  401182:	cmpq   $0x10,-0x8(%rbp)      # длина == 16 ?
  401187:	je     401190 <check+0x2a>    # да -> в цикл
  401189:	mov    $0x0,%eax              # нет -> return 0  <-- вот она
```

Здесь два выхода из функции с `return 0` (неверный ввод): по адресу `0x401189` (неверная
длина) и по `0x4011c2` (несовпадение байта в цикле). Если заменить `return 0` на `return 1`
в обоих местах, функция начнёт «говорить да» всегда.

## Приём 2: патчим в r2

Открываем на запись (`-w`) и правим байты. Инструкция `mov $0x0,%eax` — это байты
`b8 00 00 00 00`; чтобы получить `mov $0x1,%eax`, меняем второй байт на `01`:

```bash
$ r2 -w ./xorcheck
[0x00401080]> s 0x401189
[0x00401189]> wx b801000000      # записать mov $1,%eax
[0x00401189]> s 0x4011c2
[0x004011c2]> wx b801000000
[0x004011c2]> q
```

`wx` пишет сырые байты по текущему адресу. Альтернатива — ассемблерный синтаксис:
`wa mov eax, 1` (write assembly). Разница: `wx` пишет байты «как есть», `wa` собирает
инструкцию и учитывает её длину.

Проверяем результат — теперь любой ввод проходит:

```bash
$ printf 'anything\n' | ./xorcheck_fullpatch
Enter key: Correct!
$ printf 'x\n' | ./xorcheck_fullpatch
Enter key: Correct!
```

Патч сработал: мы не подбирали ключ, а убрали саму проверку. Именно так обходят
license-проверки и «вечные триалы».

## Приём 3: перекрёстные ссылки (xrefs)

В реальном бинарнике ты не знаешь заранее, где проверка. Тогда ищут от строки к коду:

```bash
[0x00401166]> izz~Wrong
0x0040202f 7 7 .rodata Wrong.
[0x00401166]> axt @@ str.Wrong.
```
`axt` — «кто ссылается на этот адрес». Строку `Wrong.` найдём через `izz` (все строки
файла) или `iz` (строки секции данных), а затем `axt` покажет функцию, которая её печатает,
— оттуда и идём к условию. В нашем случае это `main`, а он уже вызывает `check` — то есть
цепочка «строка → функция → проверка» строится за пару команд, без чтения всего листинга.

## Приём 4: графы и визуальный режим

`agf` рисует ASCII-граф текущей функции — наглядно видно ветвление:

```bash
[0x00401166]> agf
```
Визуальный режим `V` даёт интерактивную навигацию: `p` переключает представления,
`V` открывает граф, `q` — выход. Это ближайший аналог GUI, не покидая терминал.

## Приём 5: декомпиляция

С плагином **r2ghidra** (или **rz-ghidra** для rizin) доступна команда `pdg` — псевдо-C
текущей функции. Комбинируй `pdf` (ассемблер) и `pdg` (псевдо-C): первый точен, второй
быстрее для понимания логики.

```bash
[0x00401166]> pdg
```

## Приём 6: автоматизация через r2pipe

`r2pipe` — мост между r2 и Python. Он возвращает вывод команд, а вариант с `j`
(`aflj`, `axtj`) — сразу JSON:

```python
import r2pipe
r2 = r2pipe.open("./xorcheck")
r2.cmd("aaa")
for f in r2.cmdj("aflj"):
    print(f["name"], hex(f["offset"]), f["size"])
# кто вызывает функцию check
print(r2.cmdj("axtj sym.check"))
r2.quit()
```

Так можно автоматически находить «подозрительные» функции: например, все, что вызывают
`strcmp`, или все вызовы `system` с пользовательским вводом.

## Приём 7: ESIL, другие архитектуры и Cutter

Иногда нужно посчитать что-то без реального запуска — например, расшифровать строку,
которая собирается константными операциями. Для этого в r2 есть **ESIL** (Evaluable Strings
Intermediate Language) — промежуточное представление, позволяющее эмулировать инструкции:

```bash
[0x...]> aeim            # инициализировать эмуляционную память
[0x...]> aei             # инициализировать ESIL
[0x...]> aes             # сделать один шаг эмуляции
[0x...]> aer             # посмотреть регистры после эмуляции
```

Это удобно для трассировки константных вычислений без отладчика.

Второе большое преимущество r2 — десятки архитектур «из коробки». Для прошивок и CTF это
часто удобнее тяжёлых GUI: архитектуру переключают прямо в сессии.

```bash
[0x...]> e asm.arch=mips
[0x...]> e asm.bits=32
[0x...]> e cfg.bigendian=true
```

Наконец, **Cutter** — графический фронтенд к rizin: декомпилятор, графы, отладка и
hex-редактор в одном окне. Он полезен, когда нужен визуальный анализ, но не хочется
уходить в IDA/Ghidra. Скрипты `r2pipe` работают и из Cutter.

## Если не сработало

- **Правки не сохраняются** — забыл флаг `-w` (открытие на запись).
- **`/` ничего не находит** — `/` ищет строки, `/x` — hex-байты; для строк используй `izz`.
- **Адреса «плывут»** — при PIE в файле лежат смещения; переходи по символу (`s sym.main`),
  а не по абсолютному адресу.
- **`wx` ломает инструкцию** — если пишешь байты короче/длиннее исходной, добей остаток
  `nop` (`90`) или используй `wao` (overwrite с выравниванием).

## Что мы теперь знаем

- r2 объединяет дизассемблер, патчер и отладчик; открытие с `-A` = автоанализ `aaa`.
- `afl`/`pdf`/`axt`/`izz` — базовые команды навигации и поиска ссылок.
- Патч делается через `-w` + `wx` (байты) или `wa` (ассемблер).
- `r2pipe` превращает r2 в автоматизируемый движок анализа (JSON-вывод через `...j`).

## Шпаргалка команд r2/rizin

Ниже — команды, которые покрывают 90% работы в r2. Запомните структуру: буква — подсистема, дальше уточнение.

| Команда | Действие |
|---|---|
| `aaa` | полный автоанализ (функции, xrefs, строки) |
| `afl` | список функций |
| `pdf @ main` | дизассемблировать функцию `main` |
| `pdf @ sym.check` | дизассемблировать `check` |
| `s <addr>` | перейти по адресу |
| `pd 20` | дизассемблировать 20 инструкций |
| `axt @ str.flag` | кто ссылается на строку |
| `axt @ sym.check` | кто вызывает функцию |
| `V` / `VV` | визуальный режим / граф |
| `wx 9090 @ 0x401234` | записать байты (патч) |
| `wa nop @ 0x401234` | записать ассемблерную инструкцию |
| `ps @ str.x` | вывести строку |
| `izq` | строки в `.rodata` с адресами |
| `pdc` | псевдо-декомпиляция (r2dec: `pdd`) |
| `ood` / `doo` | открыть/переоткрыть в режиме отладки |

Патчинг в r2 не сохраняются на диск автоматически — используйте `wtf file` (write to file) или `-w` при запуске, если нужно зафиксировать изменения в бинарнике.

## Автоматизация через r2pipe

Для повторяющихся задач удобен `r2pipe`: r2 превращается в библиотеку, а команды возвращают JSON.

```python
import r2pipe, json

r2 = r2pipe.open("./crackme", flags=["-2"])   # -2 глушит stderr
r2.cmd("aaa")

# 1) найти все строки, похожие на флаг/ошибку
for s in json.loads(r2.cmd("izj")):
    if "flag" in s["string"].lower() or "win" in s["string"].lower():
        print(hex(s["vaddr"]), s["string"])
        for x in json.loads(r2.cmd(f"axtj @ {s['vaddr']}")):
            print("  <-", x.get("fcn_name"), hex(x["from"]))

# 2) перебрать функции и найти сравнения с константами
for f in json.loads(r2.cmd("aflj")):
    ops = json.loads(r2.cmd(f"pdfj @ {f['offset']}"))
    for op in ops.get("ops", []):
        if op["type"] == "cmp" and "0x" in op.get("disasm", ""):
            print(f["name"], op["disasm"])

r2.quit()
```

Такой скрипт заменяет ручной обход: он находит «горячие» сравнения и сразу показывает, откуда приходят данные.

## Краевые случаи

- **ASLR и PIE.** Адреса в отладке смещены относительно статического образа; включайте `e aslr=false` или работайте по смещениям от базы.
- **Архитектура.** r2 автоопределяет не всегда; для ARM/MIPS задайте `-a arm -b 16` или `e asm.arch`. Ошибка в разрядности даёт «мусор» в дизассемблере.
- **Динамическая загрузка.** Внешние функции (`plt`) до запуска без имён; используйте `aa` + загрузку символов (`-B`, `bin.dbginfo`).
- **Оптимизация компилятора.** `-O2` переставляет код так, что «логичный» порядок проверок теряется — доверяйте xrefs, а не визуальной последовательности.
- **Строки в куче/стеке.** `izq` видит только статически размещённые строки; динамически собранные ищите через `axt` на функции работы со строками.
- **Графы для больших функций.** `VV` на огромных функциях может подтормаживать — ограничьте область (`afb`, `agf`) вместо полного графа.

## Куда дальше

Мы научились обходить проверку патчем одного бинарника. Но в реальной работе чаще нужно
понять, **чем новая версия отличается от старой** — так по патчу восстанавливают
исправленную уязвимость. В следующем уроке мы возьмём два бинарника и сравним их код.
А пока главное запомни: **r2 — это не только «посмотреть», но и «изменить».**

## Где пригодится

- **CTF Reversing:** быстрый интерактивный разбор и патч проверок без тяжёлых GUI.
- **Malware analysis:** пакетный анализ образцов через `r2pipe`, извлечение строк и xrefs.
- **Автоматизация:** встраивание r2 в CI/пайплайны для триажа и диффинга.
- **Pwn:** поиск ROP-гаджетов (`/R`), анализ PLT/GOT.
- **Работа (RE-команда):** стандартный инструмент наравне с Ghidra/IDA; rizin — открытая замена.
