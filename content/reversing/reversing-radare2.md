**radare2 (r2)** — свободный фреймворк для реверса: дизассемблер, отладчик, hex-редактор, инструмент для бинарного анализа с мощным скриптовым API. Его форк **rizin** (совместимый, с улучшениями) и GUI **Cutter** образуют полноценную альтернативу IDA/Ghidra. Урок — глубокий разбор: от базового цикла и навигации до анализа, графов, патчинга, отладки, `r2pipe`-скриптов и полного разобранного примера.

## Почему r2/rizin

- **Открытый и лёгкий** — работает из CLI, легко автоматизируется.
- **Скриптуемость** — `r2pipe` для Python/JS/Rust/любого языка; сотни команд.
- **Мультиплатформенность** — десятки архитектур (x86, ARM, MIPS, RISC-V, ...).
- **Отладка + статика в одном** — не нужно переключать инструменты.
- **Гибкость** — всё через команды, легко строить пайплайны.

## Установка и базовый цикл

```bash
# установка
git clone https://github.com/radareorg/radare2 && cd radare2 && sys/install.sh
# rizin (форк)
git clone https://github.com/rizinorg/rizin && cd rizin && meson build && ninja -C build
# запуск
r2 ./target
```

Базовый цикл: открыть → проанализировать → исследовать → (опционально) отлаживать/патчить.

```bash
r2 -A ./target          # открыть с автоанализом (aaa)
r2 -d ./target          # открыть в режиме отладки
r2 -w ./target          # открыть на запись (патчинг)
```

## Навигация и seek

Всё вращается вокруг текущего адреса (seek). Команды `s` (seek).

```bash
[0x00401000]> s main          # перейти к main
[0x00401200]> s 0x401200      # по адресу
[0x00401200]> s+0x40          # сместиться вперёд
[0x00401200]> s-0x40          # назад
[0x00401200]> s-              # история seek
[0x00401200]> pd 20           # дизассемблировать 20 инструкций
[0x00401200]> pdf             # дизассемблировать текущую функцию
```

## Анализ

```bash
[0x00000000]> aa        # базовый анализ (символы, функции)
[0x00000000]> aaa       # aa + ссылки + эмуляция (рекомендуется)
[0x00000000]> aaaa      # ещё глубже (медленно)
[0x00000000]> af        # определить функцию на текущем адресе
[0x00000000]> axt        # перекрёстные ссылки на адрес
[0x00000000]> axf        # ссылки из функции
```

Уровни анализа: `aa` — быстро, `aaa` — оптимально (используйте по умолчанию), `aaaa` — максимально (для сложных бинарников, медленно).

## Информация о бинарнике

```bash
[0x00000000]> iI         # заголовок (arch, bits, endianness, os)
[0x00000000]> ii         # импорты
[0x00000000]> iE         # экспорты
[0x00000000]> iS         # секции
[0x00000000]> iz         # строки в data-секциях
[0x00000000]> izz        # все строки (включая весь файл)
[0x00000000]> iH         # хеши
[0x00000000]> i~...      # фильтр (grep) по выводу
```

`iI` — первое, что нужно смотреть: архитектура, битность, ОС, наличие PIE/NX/Canary (через `iI~canary`).

## Функции и графы

```bash
[0x00000000]> afl        # список функций
[0x00000000]> afl~main   # только main
[0x00000000]> afn new_name 0x401200   # переименовать функцию
[0x00000000]> agf        # ASCII-граф текущей функции
[0x00000000]> agfd       # граф с адресами
[0x00000000]> agC        # граф вызовов
[0x00000000]> V          # визуальный режим (навигация)
```

Визуальный режим `V` — интерактивный: `p` переключает представления, `V` — граф, `q` — выход.

## Поиск

```bash
[0x00000000]> / password       # поиск строки
[0x00000000]> /x 89504e47      # поиск hex-паттерна
[0x00000000]> /r 0x401200      # поиск ссылок (R_X86_64_...) на адрес
[0x00000000]> /w 0x401200      # поиск значений (word)
[0x00000000]> /a mov eax, 1    # поиск инструкций (asm)
[0x00000000]> /R             # поиск ROP-гаджетов
```

`/r` незаменим для поиска, кто ссылается на функцию/строку, — аналог xrefs.

## Патчинг и запись

```bash
r2 -w ./target
[0x00401200]> wx 909090        # записать байты (NOP NOP NOP)
[0x00401200]> wa nop;nop;nop   # записать инструкции (ассемблер)
[0x00401200]> wao nop          # overwrite asm (с выравниванием)
[0x00401200]> wv 0x1234        # записать значение
[0x00401200]> wci              # интерактивно править байты
```

Патчинг в r2 — байтовый, но с ассемблерным синтаксисом (`wa`), что удобно для точечных правок (инверсия переходов, NOP проверок).

## Отладка

```bash
r2 -d ./target
[0x...]> db 0x401200      # поставить breakpoint
[0x...]> db main          # по имени
[0x...]> dc               # continue
[0x...]> ds               # step
[0x...]> dso              # step over
[0x...]> dr               # показать регистры
[0x...]> dr rip=0x401200  # изменить регистр
[0x...]> px 64 @ rsp      # дамп стека
[0x...]> dbt              # backtrace
```

Комбинация статики и отладки в одной сессии — сильная сторона r2.

## r2pipe и скрипты

`r2pipe` — мост между r2 и языками программирования.

```python
import r2pipe
r2 = r2pipe.open("./target")
r2.cmd("aaa")
funcs = r2.cmdj("aflj")           # JSON-вывод
for f in funcs:
    print(f["name"], hex(f["offset"]), f["size"])
# декомпиляция (нужен r2dec/ghidra plugin)
print(r2.cmd("s main; pdf"))
r2.quit()
```

```python
# найти все вызовы strcmp и переименовать вызывающие функции
r2.cmd("aaa")
xrefs = r2.cmdj("axtj sym.imp.strcmp")
for x in xrefs:
    f = x["fcn_addr"]
    r2.cmd("afn check_strcmp_%x %d" % (f, f))
```

## Cutter GUI

**Cutter** — графический фронтенд к rizin: декомпилятор (r2ghidra), графы, отладка, hex-редактор. Удобен для визуального анализа и как замена IDA. Поддерживает r2pipe-скрипты и плагины.

## Разобранный пример: найти и пропатчить проверку

**Шаг 1. Анализ и поиск.**

```bash
r2 -A ./check
[0x...]> afl~main
[0x...]> s main; pdf
```

**Шаг 2. Найти сравнение.**

```bash
[0x...]> / password
[0x...]> axt @@ str.password      # кто ссылается на строку
```

**Шаг 3. Патч перехода.**

```bash
[0x...]> s 0x401245          # адрес jne
[0x...]> wa jmp 0x401260     # заменить на безусловный
[0x...]> pd 3                # проверить
```

**Шаг 4. Сохранить и проверить.**

```bash
[0x...]> q
./check
```

## Частые ошибки и подводные камни

- **Забыть `aaa`.** Без анализа нет функций/ссылок; `aa` часто мало.
- **`/` vs `/x`.** `/` ищет строки, `/x` — hex; путаница приводит к «ничего не найдено».
- **Патч без `-w`.** Без флага записи правки не сохраняются.
- **`wao` vs `wx`.** `wx` пишет байты без учёта длины инструкции; `wao` выравнивает.
- **Фильтр `~`.** Многословный вывод фильтруется через `~`; без него легко утонуть.
- **PIE/адреса.** При PIE используйте `s` по символам, а не абсолютные адреса.

## Что дальше / решение

Освойте базовый цикл (`-A` → `afl`/`pdf` → `/` → `wa`) и `r2pipe` для автоматизации. Для GUI — Cutter; для декомпиляции — плагин r2ghidra. Дальше — `reversing-static-tools`, `reversing-ghidra-deep` и `reversing-decompiler-plugin`.

## Декомпиляция в r2: r2ghidra и r2dec

Современный r2/rizin умеет декомпилировать. Два основных плагина: **r2ghidra** (на базе Ghidra decompiler, лучший результат) и **r2dec** (собственный, легче). После установки доступна команда `pdg`.

```bash
# установка плагина
r2pm -ci r2ghidra        # или r2pm -ci r2dec
# использование
r2 -A ./target
[0x...]> s main
[0x...]> pdg             # декомпилировать текущую функцию
[0x...]> pdg~"if"        # фильтр по выводу декомпилятора
```

`pdg` особенно полезен для быстрой оценки логики без переключения в Ghidra. Для rizin эквивалент — `pdg` из плагина `rz-ghidra`. Комбинируйте: `pdf` (ассемблер) + `pdg` (псевдо-C) для полной картины.

## Продвинутые команды: ESIL и эмуляция

r2 содержит **ESIL** (Evaluable Strings Intermediate Language) — промежуточное представление для эмуляции инструкций. Это позволяет исполнять код без реального запуска.

```bash
[0x...]> e asm.emu=true        # показывать эмуляцию при дизассемблировании
[0x...]> aeim                  # инициализировать ESIL-память
[0x...]> aei                   # инициализировать ESIL
[0x...]> aeip                  # установить IP
[0x...]> aes                   # шаг эмуляции
[0x...]> aer                   # регистры после эмуляции
[0x...]> aepc 0x401200         # установить PC
```

ESIL удобен для трассировки константных вычислений (например, расшифровки строк) без отладчика. Команда `aesu` (step until address) эмулирует до заданного адреса.

## Профили, конфигурация и скрипты

r2 полностью конфигурируем через переменные `e` и файл `~/.radare2rc`.

```bash
[0x...]> e asm.syntax=intel      # Intel-синтаксис
[0x...]> e asm.bytes=true        # показывать байты
[0x...]> e scr.color=3           # цвет
[0x...]> e asm.describe=true     # описывать инструкции
[0x...]> e <name>                # показать переменную
[0x...]> e?? <substr>            # поиск переменной
```

Скрипты можно передавать при запуске: `r2 -i script.r2 ./target`. Это удобно для повторяемых пайплайнов анализа (загрузить → aaa → найти строки → выписать функции).

## r2pipe на других языках и в CI

Кроме Python, `r2pipe` есть для Node.js, Rust, Go, Ruby, Java. Это позволяет встраивать анализ в пайплайны.

```javascript
// Node.js
const r2 = require("r2pipe").open("./target");
r2.cmd("aaa", () => {
  r2.cmdj("aflj", (funcs) => {
    funcs.forEach(f => console.log(f.name, f.offset));
    r2.quit();
  });
});
```

В CI такие скрипты автоматически прогоняют проверки (например, «есть ли вызовы `system` с пользовательским вводом»).

## Практический чеклист анализа в r2

1. `r2 -A ./target` (автоанализ) → `iI` (архитектура, mitigations).
2. `afl` — список функций; `izz` — строки; `/` — интересные строки.
3. `s <func>; pdf` + `pdg` — разбор ключевой функции.
4. `axt` — кто вызывает; `agf` — граф.
5. При необходимости — `r2 -d` для отладки и `-w` для патча.
6. Автоматизация — `r2pipe`.

## Работа с несколькими архитектурами

r2 поддерживает десятки архитектур из коробки — ключевое преимущество для embedded и CTF.

```bash
[0x...]> e asm.arch=mips        # сменить архитектуру
[0x...]> e asm.bits=32
[0x...]> e cfg.bigendian=true
r2 -a mips -b 32 -e cfg.bigendian=true ./fw_binary
```

Для ARM64/MIPS-прошивок и WASM r2 часто удобнее тяжёлых GUI-дизассемблеров: можно быстро переключить arch/bits/endianness без пересоздания проекта.

## Работа с WASM и firmware в r2

r2 разбирает WASM (`-a wasm`), а также сырые firmware-образы (`-b`, `-a`). Для WASM доступны команды `iW` (информация о модуле). Это делает r2 удобным для IoT/Cloud-задач, где тяжёлые дизассемблеры не поддерживают формат.

## Где пригодится

- **CTF Reversing:** быстрый интерактивный разбор без тяжёлых GUI; скрипты для авто-поиска проверок.
- **Malware analysis:** пакетный анализ образцов через r2pipe, извлечение строк и xrefs.
- **Автоматизация:** встраивание r2 в CI/пайплайны для диффинга и триажа.
- **Pwn:** поиск ROP-гаджетов (`/R`), анализ PLT/GOT в бинарнике.
- **Работа (RE-команда):** стандартный инструмент наравне с Ghidra/IDA; rizin — корпоративная замена.
