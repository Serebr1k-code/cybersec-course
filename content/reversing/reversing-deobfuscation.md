Деобфускация — это процесс превращения запутанного кода обратно в читаемый. Если обфускация
описана в соседнем уроке, то здесь — **практика**: как строить деобфускатор, какие инструменты
применять, как итеративно упрощать код и как автоматизировать это на Python. Деобфускация бывает
статической (переписать IR) и динамической (записать реальное поведение). Профессиональный подход —
комбинировать оба.

## Стратегия: что снимать первым

Порядок слоёв почти всегда одинаков:

1. **Упаковка/шифрование** — сначала распаковать (иначе анализировать нечего).
2. **Anti-debug/anti-VM** — нейтрализовать детект, чтобы работать динамикой.
3. **Строковое шифрование** — самое дешёвое, даёт мгновенную пользу.
4. **Instruction substitution / MBA** — нормализовать арифметику.
5. **Opaque predicates / dead code** — убрать недостижимое.
6. **Control-flow flattening** — восстановить реальный CFG.
7. **Виртуализация** — девиртуализация (самый тяжёлый этап).

Нарушение порядка = потеря времени. Например, попытка восстановить CFG до распаковки бессмысленна.

## Динамический путь: записать, что реально исполняется

Самый надёжный способ понять обфусцированный код — **пронаблюдать его в работе**. Обфускация
добавляет много ложных ветвей, но исполняется только истинный путь.

**Трассировка через Pin:**
```python
from pintool import *
def on_ins(addr, size):
    # логировать только реально исполненные инструкции
    print(hex(addr))
InstrumentInsCallback(on_ins)
StartInstrumentation(1)
```
Пишем поток адресов → строим реальный CFG (без мёртвых ветвей). Это «золотая» карта функции.

**Через DynamoRIO** (drrun/drcov):
```bash
drrun -t drcov -- ./target        # покрытие: какие блоки реально исполнены
```

**Через Frida** — перехват функций/адресов в рантайме:
```javascript
Interceptor.attach(ptr("0x401234"), {
    onEnter(args) { console.log("call", args[0].toInt32()); }
});
```

**Через Intel PT / rr** — полная запись потока с откатом (см. урок advanced-debugging).

## Статический путь: упрощение IR

Когда нужно покрыть **все** пути (не только исполненный), работаем с IR:

- **Hex-Rays microcode** / **Ghidra P-Code** / **LLVM IR (RetDec)** — представления, удобные для
  переписывания.
- **Символическое исполнение** (Triton, angr, Miasm) — выразить блок как систему уравнений и упростить.

**Пример: упрощение через Z3.**
```python
from z3 import *
x = BitVec("x", 32)
expr = (x ^ 0x41) - ((x & 0xff) | 0x41)      # MBA-выражение
simplify(expr)                                # Z3 упростит
```
Иногда `simplify` возвращает исходную форму — тогда помогает подстановка известных тождеств или
`z3`-солвер для проверки эквивалентности двух форм.

**Пример: angr для обхода opaque predicate.**
```python
import angr, claripy
p = angr.Project("./target", auto_load_libs=False)
state = p.factory.entry_state()
simgr = p.factory.simulation_manager(state)
simgr.explore(find=0x401200, avoid=0x401300)
print(simgr.found[0].posix.dumps(0))
```
angr проходит запутанный CFG и находит путь к цели — не нужно вручную разбирать opaque predicates.

## Деобфускация строк: автоматизация

Пишем скрипт, который находит все зашифрованные строки и расшифровывает их.

**Подход 1 — статический, по xref.**
```python
# IDAPython: найти вызовы дешифратора и расшифровать аргументы
import idautils, idc
DEC = 0x401500
for xref in idautils.XrefsTo(DEC):
    print("decrypt call at", hex(xref.frm))
    # прочитать аргументы (регистры/стек) — зависит от ABI
```

**Подход 2 — динамический, по breakpoint.** В x64dbg:
```text
bp 0x401520            ; на выходе дешифратора
commands:
  log "{s:rdi}"        ; залогировать расшифрованную строку
  run
```
Получаем дамп всех строк.

**Подход 3 — FLOSS.**
```bash
floss ./target -q          # только строки
floss ./target --no-static  # только дешифрованные
```

## Деобфускация control-flow flattening

Алгоритм `deflat` (упрощённо):

1. Найти переменную `state` (часто в начале функции инициализируется константой).
2. Найти `switch(state)` и все `case`.
3. Для каждого `case` определить, какое значение `state` он устанавливает и куда ведёт.
4. Построить граф переходов, вычислить доминирующие узлы.
5. Заменить `switch` на прямые переходы, «разложить» цикл.

Инструменты: плагин **deflat** (IDA), скрипты для Ghidra, `angr`/`Triton` для прохода графа.
Для Tigress CFF есть специализированные скрипты (`tigress-deobfuscation`).

## Девиртуализация: общий подход

VM-защита (VMProtect/Tigress/custom) — кульминация деобфускации. Общий конвейер:

1. **Найти dispatcher** и таблицу хендлеров.
2. **Восстановить формат байткода** (ширина опкода, операнды).
3. **Трассировать** конкретный путь (Unicorn/Pin/gdb) и получить поток виртуальных операций.
4. **Сопоставить хендлеры семантике** (по эффектам на vregs/vstack).
5. **Восстановить виртуальный CFG** и перевести в псевдо-C.

Инструменты: `VMAttack`, `vmattack`, `Miasm`, скрипты Unicorn, Triton. Для полной девиртуализации
VMProtect нужны недели, поэтому на практике девиртуализируют **только критичную функцию** (проверку
лицензии, ключевую валидацию), а не весь бинарник.

## Разобранный пример: снятие CFF скриптом

Дано: функция с `while(1){ switch(state) }`. Цель — восстановить нормальный CFG.

**Шаг 1. Найти `state`.** В псевдо-C видим:
```c
v5 = 0;
while (1) {
    switch (v5) {
        case 0: v3 = f(); v5 = 4; break;
        case 4: if (v3) v5 = 9; else v5 = 2; break;
        case 9: g(v3); v5 = 1; break;
        case 2: h(); v5 = 1; break;
        case 1: return;
    }
}
```

**Шаг 2. Построить граф.** 0→4→(9 или 2)→1. Видно: это `if (f()) g() else h()`.

**Шаг 3. Переписать.**
```c
v3 = f();
if (v3) g(v3); else h();
```

**Шаг 4. Автоматизировать** для больших функций: скрипт читает `switch`-узлы, строит граф `state`,
затем применяет реструктуризацию (или использует `deflat`).

## Крайние случаи и подводные камни

- **Упрощение может быть неполным.** Z3 `simplify` не всегда сворачивает MBA; комбинируйте с
  известными тождествами.
- **Символьное исполнение «взрывается»** на больших функциях — ограничивайте глубину, используйте
  трассировку как подсказку.
- **Самомодификация.** Статические деобфускаторы бессильны — только динамика/эмуляция.
- **Несколько техник одновременно.** CFF + MBA + opaque predicates вместе; снимайте по одному слою,
  проверяя результат.
- **Ошибки в автоматике опасны.** Неверная деобфускация может «спрятать» реальную логику — всегда
  проверяйте на тестовых данных.
- **Время vs полнота.** Часто достаточно понять одну функцию, а не деобфусцировать весь файл.
- **Анти-деобфускация.** Код может детектить хуки/трассировку и вести себя иначе — проверяйте
  консистентность.

## Что дальше / решение

1. Определить слои обфускации и снять их по порядку.
2. Для строк — FLOSS/динамика.
3. Для CFF — `deflat`/скрипт.
4. Для MBA — Z3/`gooMBA`.
5. Для VM — трассировка + семантика хендлеров.
6. Проверить результат на тестовых данных; зафиксировать восстановленный код.

Принцип: **деобфускация — итеративный процесс**. Не пытайтесь снять всё сразу; двигайтесь слоями,
автоматизируйте повторяющиеся шаги и всегда верифицируйте, что поведение сохранено.

## Построение собственного деобфускатора: конвейер

Профессиональная деобфускация — это **pipeline** из шагов, каждый из которых проверяется отдельно:

1. **Loader** — распаковать, загрузить в IR (микрокод/P-Code/LLVM).
2. **Normalizer** — убрать substitution: свернуть инструкции к каноническому виду.
3. **Constant propagation** — распространить константы (в т.ч. `state`).
4. **MBA simplifier** — упростить арифметику (Z3/тождества).
5. **Dead code eliminator** — убрать недостижимые блоки (после распространения `state`).
6. **CFG rebuilder** — восстановить реальные переходы, «разложить» flattening.
7. **Emitter** — сгенерировать псевдо-C/ассемблер.

Такой конвейер можно писать как плагин IDA (microcode), скрипт Ghidra (P-Code) или отдельный
инструмент на Miasm/LLVM. Ключ — **проверять каждый шаг** на тестовых данных: если после шага
поведение изменилось, ошибка в нём.

## Пример: снятие substitution через Triton

Инструкция-подстановка (`xor eax,eax; inc eax` вместо `mov eax,1`) сворачивается символическим
исполнением: Triton построит выражение и упростит его.

```python
from triton import TritonContext, ARCH, Instruction, MemoryAccess

ctx = TritonContext(ARCH.X86_64)
# ... загрузить код функции, символизировать входы ...
# symbolicExpression = ctx.getSymbolicRegister(ctx.registers.eax)
# simplified = ctx.simplify(symbolicExpression, True)
```

Triton отслеживает символьные выражения для регистров/памяти; после прохода можно получить
упрощённую формулу для результата — это и есть «снятая» обфускация. Аналогично работает Miasm
(`miasm.expression.simplifications`).

## Метрики качества деобфускации

Как понять, что деобфускация удалась:

- **Эквивалентность поведения.** Прогнать исходный и деобфусцированный код на наборе входов —
  результаты совпадают.
- **Уменьшение размера CFG.** Число базовых блоков падает (мёртвый код удалён).
- **Читаемость.** Псевдо-C содержит понятные `if`/`while`, а не `switch(state)`.
- **Восстановление констант.** `state`-значения и opaque-условия сведены.
- **Покрытие.** Деобфусцирован весь нужный путь, а не только один вход.

Если хотя бы один пункт не выполнен — ищите ошибку в конвейере.

## Ограничения и что делать, когда всё сложно

- **Полная девиртуализация VMProtect/Themida** может быть нереалистичной в разумное время. Тогда
  цель смещается: понять **конкретный путь** (например, проверку) и воспроизвести его.
- **Символика «взрывается»** на больших функциях — комбинируйте с трассировкой (она даёт конкретный
  путь, символика — обобщение).
- **Самомодификация** требует эмуляции (Unicorn) вместо статики.
- **Несколько слоёв** — снимайте по одному и сохраняйте промежуточные результаты.

Практический вывод: **деобфускация — это не «победить всё», а «получить достаточно»**. Часто
достаточно восстановить одну функцию, чтобы решить задачу.
