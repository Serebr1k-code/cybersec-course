## Вопрос, с которого всё начинается

В прошлом уроке мы научились **узнавать** обфускацию: плоский `switch`, ложные предикаты, странная
арифметика. Но узнать мало — нужно вернуть код к читаемому виду. Как из запутанной функции снова
получить простое `if (p == "rev42")`? Ответ: деобфускация — упрощение и динамический анализ.

Опираемся на прошлый урок: у нас есть функция `check` с control-flow flattening и opaque predicate.
Возьмём её же и распутаем.

## Наш пример

Напомним объект — функция проверки пароля из прошлого урока, скомпилированная в `obf`:

```
$ ./obf rev42
access GRANTED
$ ./obf nope
access DENIED
```

Цель: восстановить логику, не читая руками весь `switch`.

## Шаг 1: посмотреть, что не спрятано

Первое, что стоит проверить, — не лежат ли нужные данные в открытом виде. Обфускация структуры
кода и обфускация данных — разные вещи, и часто первую делают, а вторую забывают:

```
$ strings -n 4 obf | grep -E 'rev42|access'
rev42
access %s
```

Пароль `rev42` виден в открытом виде. Это уже ответ для этой задачи. Но приём «посмотреть строки»
работает только если строки не зашифрованы; в реальности чаще строки прячут, и тогда нужны
следующие шаги.

## Шаг 2: убрать ложные предикаты (opaque predicates)

Вспомним условие из `case 1`: оно вычисляет `x² − 14x + 49` и сравнивает с `0`, при том что `x`
жёстко задано 7. Это `(x−7)² == 0` — тождественно истинно. Проверим утверждение «предикат всегда
истинен» честно, перебором:

```python
def opaque(x): return (x*x - 14*x + 49) == 0
print("opaque(7) =", opaque(7))
```
```
opaque(7) = True
```

Практический вывод простой: **ветку `else` можно выбросить**, а `case 1` заменить на безусловный
переход `state = 2`. Так же и `case 3`: `if ((x & 1) == 1) A else B` — обе ветки делают одно и то
же (`state = 2`), значит условие лишнее. Убирая ложные предикаты один за другим, мы «выпрямляем»
граф.

## Шаг 3: упростить арифметику (MBA)

**MBA** (Mixed Boolean-Arithmetic) — замена простых выражений на смесь арифметики и битовых
операций. Классический пример: вместо `x + y` пишут `(x ^ y) + 2*(x & y)`. Убедимся, что это
одно и то же, полным перебором всех 8-битных значений:

```
$ python3 -c "..."
(x^y)+2*(x&y) == x+y for all 8-bit x,y : True
(x*x+x) mod 2 always 0 : True
```

Второе тождество объясняет, почему `(x & 1) == 1` в `case 3` не может быть ложным для чётного
`x*(x+1)`: произведение двух подряд идущих чисел всегда чётно. Такие тождества сворачиваются
подстановкой. Для больших выражений это делают инструменты-упрощатели (в том числе на базе SMT,
например Z3), но принцип один: **ищи выражение, эквивалентное простому, и заменяй**.

## Шаг 4: динамическая трассировка

Если статически запутано слишком сильно, помогает наблюдение за исполнением. Поставим точку
останова на диспетчере (`cmp [rbp-0x10], 4`) и будем печатать значение `state` при каждом входе:

```
$ gdb -q -batch -x trace.gdb --args ./obf rev42
state=0 state=1 state=2 state=3 state=2 state=3 state=2 state=3 state=2 state=3 state=2 state=4
```

Прочитаем путь: `0 → 1 → 2 → 3 → 2 → 3 → ... → 4`. Состояние `0` — инициализация, `1` — тот самый
ложный предикат (сразу переходит в `2`), затем цикл `2 ↔ 3` повторяется пять раз (по одному символу
пароля), и `4` — завершение. Мы **восстановили порядок блоков**, не разбирая дизассемблер целиком.
Динамика хороша тем, что показывает только реально исполненные пути — мёртвый код просто не
появляется в трассе.

## Шаг 5: собрать результат

Сложив всё вместе, получаем исходную логику:

```c
int check(const char *p){
    int i = 0;
    while (p[i] != 0) {
        if (p[i] != "rev42"[i]) return 0;   /* сравнение посимвольно */
        i++;
    }
    return i == 5;                          /* длина 5 */
}
```

Из «нечитаемого» `while/switch` остался обычный цикл. Именно так выглядит деобфускация: не «взлом
магии», а последовательное упрощение плюс наблюдение.

## Если строки зашифрованы

В нашем примере пароль лежал открыто, но так бывает не всегда. Если `strings` ничего не показал,
ищи **функцию-дешифратор**: обычно это короткая процедура, которая проходит по массиву байтов и
XOR'ит/складывает их с константой, после чего результат используется как строка. Простейший случай
— XOR с одним байтом. Покажем на «шифровании» того же пароля:

```python
key = 0x5a
enc = bytes(c ^ key for c in b"rev42")
print("encrypted:", enc.hex())
print("decrypted:", bytes(c ^ key for c in enc).decode())
```
```
encrypted: 283f2c6e68
decrypted: rev42
```

В бинарнике ты увидишь эти пять байтов `28 3f 2c 6e 68` где-нибудь в `.data` и рядом цикл,
который применяет XOR с `0x5a`. Достаточно повторить этот цикл у себя (или прямо в отладчике
дождаться, пока строка расшифруется, и прочитать её из памяти) — и секрет снова на виду. Ключ
подбирается тривиально: если знаешь хотя бы один символ открытого текста, `key = шифр ^ символ`.

## Если не сработало

Для серьёзных протекторов (VMProtect, Tigress) ручного упрощения мало. Тогда:

- **Символьное исполнение** (angr, Triton): инструмент сам проходит все пути и строит выражения.
- **Девиртуализация**: если логика вынесена в байткод своей VM, восстанавливают таблицу handler'ов
  и «выпрямляют» байткод обратно в инструкции.
- **Готовые деобфускаторы**: для MBA есть инструменты, сворачивающие выражения автоматически.

Но принцип остаётся тем же: понять, что делает каждый блок, и заменить его простым эквивалентом.

## Полный прогон от начала до конца

Соберём весь путь деобфускации в одну историю:

1. `strings obf` — вдруг данные не спрятаны: `rev42` сразу виден.
2. Если нет — ищем дешифратор (XOR-цикл) и повторяем его у себя.
3. Убираем opaque predicates: `(x−7)²==0` тождественно истинно — ветку `else` выбрасываем.
4. Сворачиваем MBA: `(x^y)+2*(x&y)` → `x+y`.
5. Гоняем трассу `state` под отладчиком: `0→1→2→3→2→3→…→4` показывает реальный порядок блоков.
6. Складываем блоки в исходный `while` + посимвольное сравнение.

Итог — обычный цикл из «нечитаемого» `switch`. Это и есть деобфускация: наблюдение плюс упрощение.

## Шаг 6: если логика в своей VM

Отдельный случай — **виртуализация**: логика вынесена в байткод, который исполняет интерпретатор
внутри бинарника. Тогда «деобфускация» означает **девиртуализацию**. Порядок такой:

1. Найти **диспетчер**: большой `switch` по опкоду, где каждый `case` — реализация одной операции.
2. Извлечь **таблицу обработчиков**: адреса handler'ов, обычно массив указателей в `.data`.
3. Извлечь **байткод**: массив байтов, который интерпретатор читает по одному.
4. Написать **дизассемблер байткода**: по опкоду выбирать из таблицы операцию и печатать её как
   инструкцию.
5. Собрать **лифтер** — перевести байткод обратно в читаемый C или в промежуточное представление.

Это большой объём работы, поэтому для популярных протекторов (VMProtect, Themida) уже есть
исследования и скрипты; для самодельных VM таблицу handler'ов восстанавливают вручную. Но принцип
тот же: **найди диспетчер — и логика станет данными**, которые можно разобрать отдельно от кода.

## Как это видят защитники

Обфускация — тоже сигнал. Антивирусы и песочницы ищут её признаки, потому что легитимный код обычно
не запутан:

- **плоский CFG**: одна функция с большим `switch` и сотнями мелких блоков;
- **opaque predicates**: условия, значение которых не зависит от входа (их вскрывает SMT-анализатор);
- **MBA**: арифметика вида `(x^y)+2*(x&y)` вместо `x+y` — аномалия для компилятора;
- **свой байткод/VM**: большой массив байтов и таблица обработчиков-функций.

Для реверсера это тот же список, только с обратным знаком: увидел `switch`-диспетчер с десятками
`case` — почти наверняка это flattening, и начинать надо с трассы путей.

## Что мы теперь знаем

- **Деобфускация** = упрощение (убрать ложные предикаты, свернуть MBA) + динамика (трасса путей).
- Данные часто **не** обфусцированы, даже когда код обфусцирован: `strings` может сразу выдать
  секрет.
- Тождества вроде `(x^y)+2*(x&y) == x+y` проверяются перебором и сворачиваются подстановкой.
- Динамическая трасса показывает реально исполненные пути и сразу отбрасывает мёртвый код.
- Для протекторов переходят к символьному исполнению и девиртуализации.
- Если логика в своей VM, цель — найти диспетчер и таблицу handler'ов: тогда логика станет данными.
- Opaque predicates вскрываются SMT-анализатором: он доказывает, что условие не зависит от входа.
- Динамическая трасса — самый дешёвый способ восстановить порядок блоков flattening'а: мёртвые
  ветки в неё просто не попадают.

## Куда дальше

Мы распутали код статикой и динамикой. Дальше возьмём случай, когда код **меняет себя во время
работы** — self-modifying и распаковку через эмуляцию, где статический дамп вообще бесполезен. А
пока главное запомни: **деобфускация — это упрощение плюс наблюдение, а не магия**.

## Где пригодится

- **CTF Reversing (expert):** ключевой навык для «нечитаемых» задач.
- **Malware analysis:** снять обфускацию — половина анализа.
- **Protector research:** девиртуализация и упрощение — основа работы с VMProtect/Themida.
- **Автоматизация:** скрипты-упрощатели и SMT экономят дни ручной работы.
- **Собес:** «как бы ты подошёл к MBA-обфускации?» — вопрос уровня senior RE.
