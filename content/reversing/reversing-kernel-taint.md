Обычный taint-анализ работает в userland. Для malware/rootkit, затрагивающих **ядро**, нужен **whole-system taint**: отслеживание данных от ввода (сеть, диск, syscall) через ядро и обратно. Это реализуется через **hypervisor-based** инструментацию (вне гостя) или модификацию ядра. Этот урок — концепции и инструменты.

## Зачем whole-system taint

- **Rootkit-анализ**: понять, откуда данные попадают в ядро и как влияют.
- **Утечки**: отследить, как секреты уходят наружу.
- **Уязвимости ядра**: от ввода до опасной операции.
- **Malware**: связать C2-данные с действиями в ядре.

## DTA (Dynamic Taint Analysis)

- **Источники (sources)**: ввод (network/disk/syscall args).
- **Приёмники (sinks)**: опасные операции (write, exec, jmp).
- **Распространение**: через регистры/память/структуры ядра.
- **Смешанность (shadow memory)**: карта «загрязнённости» параллельно данным.

## Hypervisor-based инструментация

- Гипервизор (ring -1) перехватывает события гостя, **не изменяя** ядро.
- **Panoramix** (академический): whole-system taint через QEMU/hypervisor.
- **TEMU** (BitBlaze): платформа для whole-system анализа.
- **QEMU-based**: модифицированный QEMU для трассировки ядра.
- Плюсы: невидимость для malware, полный контроль.
- Минусы: сложность, оверхед, специфичность.

## Инструменты

- **Panoramix** — whole-system DTA.
- **TEMU/BitBlaze** — платформа анализа.
- **QEMU** (модифицированный) — трассировка.
- **Volatility** — анализ памяти (не taint, но дополняет).
- **Intel PT** — поток управления для корреляции.

## Разобранный пример (концептуально)

```text
1) Запустить ОС+malware под инструментированным гипервизором.
2) Пометить сетевые пакеты (C2-данные) как «грязные».
3) Отслеживать распространение через стек TCP/IP -> ядро -> процессы.
4) Определить, куда «грязные» данные попадают (sink): запись в /etc, syscall.
5) Это раскрывает логику malware на уровне ядра.
```

## Практические ограничения

- **Оверхед**: whole-system taint очень тяжёл.
- **Настройка**: требует сборки инструментированного QEMU/гипервизора.
- **Полнота**: shadow memory для всего ядра — огромна.
- **Детектируемость**: продвинутый malware может заметить аномалии времени.

## Частые ошибки

- **Пытаться сделать whole-system taint в userland.** Нужен гипервизор/ядро.
- **Игнорировать оверхед.** Может быть неприемлемым для долгих прогонов.
- **Не определить sources/sinks.** Без них анализ бессмыслен.
- **Забыть про структуры ядра.** Taint должен следовать через struct, не только регистры.
- **Слишком широкий taint.** Всё «грязное» — нет полезного сигнала; уточняйте.
- **Специфичность инструмента.** Panoramix/TEMU — старые, требуют адаптации.

## Полный разбор: отслеживание C2-данных в ядре

**Шаг 1. Развернуть инструментированный гипервизор.** Соберите QEMU/Panoramix, запустите ОС+malware как гостя.

**Шаг 2. Пометить источники.** Сетевые пакеты (C2) помечаются «грязными» на входе.

**Шаг 3. Отслеживать распространение.**

```text
пакет -> стек TCP/IP -> буфер сокета -> read() процесса -> память malware
```

**Шаг 4. Найти sinks.** Куда попадают «грязные» данные: запись в `/etc`, `execve`, изменения реестра.

**Шаг 5. Сопоставить** с поведением: так раскрывается логика malware на уровне ядра без статического анализа.

## Инструменты

- **Panoramix/TEMU** — whole-system DTA.
- **QEMU (модифицированный)** — трассировка ядра.
- **Volatility** — анализ памяти (дополняет).
- **Intel PT** — поток управления для корреляции.

## Ограничения

Огромный оверхед и сложность настройки; требует сборки инструментированного гипервизора. Часто применяется в исследовательских работах.

## Модель DTA: sources/sinks/shadow

Dynamic Taint Analysis формализуется тремя понятиями:

| Понятие | Что это | Примеры |
|---------|---------|---------|
| Source | откуда приходят «грязные» данные | сеть, диск, аргументы syscall, ввод |
| Sink | опасные операции-приёмники | write, execve, jmp, запись в ФС/реестр |
| Shadow memory | карта «загрязнённости» | бит/байт на каждый байт данных |
| Propagation | правила распространения | арифметика, копирование, через struct |

Правила распространения задаются вручную/полуавтоматически: например, результат сложения «грязный», если грязный хотя бы один операнд; адрес памяти «грязный» — если грязный указатель. Качество анализа зависит от точности этих правил.

## Hypervisor-based инструментация: как работает

Гипервизор (ring -1) наблюдает за гостем, **не изменяя** его код — malware не может обнаружить модификацию ядра. События гостя (переключения, syscall, доступ к памяти) перехватываются.

```text
Guest OS + malware
        |
   Hypervisor (инструментация, shadow memory, taint propagation)
        |
   Host (сбор трассы, анализ)
```

Плюсы: невидимость, полный контроль над ядром. Минусы: оверхед (10x–100x), сложная настройка, специфичность инструментов.

## Panoramix/TEMU: установка и запуск (концептуально)

```bash
# Panoramix/TEMU собираются из исходников как модифицированный QEMU
git clone <repo>/panoramix && ./configure --target-list=x86_64-softmmu && make
# Запуск гостя под инструментированным QEMU
./qemu-system-x86_64 -m 2048 -hda guest.img -net nic -net user
# Внутри хоста-инструментатора: пометить sources и наблюдать sinks
```

```text
1) Развернуть гостя (ОС + образец).
2) Пометить сетевые пакеты (C2) как source.
3) Включить taint propagation.
4) Логировать достижения sinks (write/execve/ФС).
```

## QEMU-based трассировка ядра

Модифицированный QEMU логирует исполнение ядра: syscalls, доступы к памяти, ветвления. Это даёт трассу, по которой можно сопоставить «грязные» данные с действиями. Intel PT — аппаратный поток управления для корреляции на «железе».

## Intel PT и корреляция

Intel Processor Trace записывает поток управления (ветвления) с минимальным оверхедом. Комбинация PT + дампы памяти позволяет восстановить, какие данные влияли на решения, без полного taint-анализа. Инструменты: `perf`/`pt`-декодеры, `libipt`.

## Практический пайплайн анализа C2

```text
1) Пометить входящий C2-трафик как «грязный».
2) Проследить: пакет -> TCP/IP стек -> буфер сокета -> read() -> память процесса.
3) Отслеживать, куда «грязные» данные попадают дальше (sink):
   - запись в /etc, ~/.ssh, автозагрузку;
   - execve с «грязным» аргументом;
   - изменение реестра/сервисов.
4) По достигнутым sinks восстановить логику malware на уровне ядра.
5) Сопоставить с сетевыми событиями (кто/когда/что).
```

## Ограничения и оптимизация

- **Оверхед:** whole-system taint тяжёл; ограничивайте источники (только сеть) и sinks (только ФС).
- **Полнота shadow memory:** для всего ядра огромна; используйте сегментную shadow.
- **Детектируемость:** продвинутый malware замечает тайминговые аномалии; минимизируйте инструментацию.
- **Специфичность:** Panoramix/TEMU старые — нужна адаптация под современные ядра.

## Инструменты (таблица)

| Инструмент | Назначение | Примечание |
|------------|-----------|-----------|
| Panoramix | whole-system DTA | академический, QEMU |
| TEMU (BitBlaze) | платформа анализа | старая, но концептуальна |
| модифицированный QEMU | трассировка ядра | сборка из исходников |
| `libipt`/`perf` | Intel PT | аппаратный поток |
| Volatility | анализ памяти | дополняет taint |
| `qiling` | эмуляция | userland/syscall |

## Разобранные примеры

**1. Rootkit.** Пометили сетевые данные; taint дошёл до записи в `/etc/ld.so.preload` — обнаружен механизм персистентности.

**2. Утечка.** Taint от секрета в памяти дошёл до sendto() — выявлен канал эксфильтрации.

**3. Уязвимость ядра.** Taint от ввода syscall дошёл до опасной операции — локализована точка бага.

## Что делать дальше / дерево решений

1. Определите sources/sinks для вашей задачи.
2. Разверните инструментированный гипервизор/QEMU.
3. Помечайте источники, наблюдайте распространение.
4. Логируйте достижения sinks.
5. Коррелируйте с сетевыми/дисковыми событиями (Intel PT/Volatility).
