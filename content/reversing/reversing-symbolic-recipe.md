## Вопрос, с которого всё начинается

У тебя есть `keygen` — программа, которая проверяет ключ. Ты уже понял логику: каждый байт ввода
складывается по XOR с константой и сравнивается с секретом. Но подбирать ключ перебором долго, а
считать вручную легко ошибиться. Хочется получить вход **автоматически**, по готовому рецепту.

Такой рецепт — это **символическое решение**: заменяем неизвестный вход «символами» (не числами, а
заполнителями), переводим действия программы в условия и просим **SMT-решатель** (Z3) найти
значения. Разберём рецепт шаг за шагом на живом бинарнике.

## Наш пример

Вот проверка (внутри `keygen`): длина ключа 8, и `input[i] ^ 0x5a == secret[i]`, где
`secret = "hackme!!"`.

```c
static int check(const char *in){
    const char *secret = "hackme!!";
    if (strlen(in) != 8) return 0;
    for (int i = 0; i < 8; i++)
        if ((unsigned char)(in[i] ^ 0x5a) != (unsigned char)secret[i]) return 0;
    return 1;
}
```

Проверим поведение и найдём в дизассемблере саму операцию XOR:

```
$ ./keygen anything
wrong
$ objdump -d -M intel keygen | grep -A2 'xor'
  401147:  movzx  eax,BYTE PTR [rax]        ; in[i]
  40114a:  xor    eax,0x5a                   ; ^ 0x5a
  40114d:  mov    edx,eax
```

Видно: читается `in[i]`, XOR с `0x5a`, сравнивается с байтом секрета. Теперь переведём это в рецепт.

Секрет `hackme!!` в бинарнике лежит в секции данных и обычно находится сразу:

```
$ strings -a keygen | grep hackme
hackme!!
```

Так что для рецепта нужны два факта: константа XOR (`0x5a`) из дизассемблера и строка-секрет из
`strings`. Оба берутся статически, без запуска программы.

## Шаг 1: четыре части любого рецепта

Символическое решение всегда состоит из одних и тех же четырёх частей:

1. **Символы.** Каждый неизвестный вход — символическая переменная. Для байтов удобен `BitVec(name,
   8)` — 8-битное значение с модульной арифметикой.
2. **Ограничения.** Каждое действие программы становится условием над символами (`^`, `+`, `==`).
3. **Решатель.** `Solver` проверяет выполнимость: `sat` — решение есть, `unsat` — нет.
4. **Модель.** `model()` выдаёт конкретные значения символов — искомый вход.

Плюс важная деталь — **ограничение области**: без него решатель вернёт любой байт, в том числе
непечатный. Добавим диапазон `0x20..0x7e` (печатные ASCII), чтобы ответ был «человеческим».

## Шаг 2: записываем условия и решаем

Переносим логику из дизассемблера дословно: восемь байт, каждый после XOR равен байту секрета.

```python
from z3 import *
secret = b"hackme!!"
xs = [BitVec(f"c{i}", 8) for i in range(8)]     # 8 неизвестных байт
s = Solver()
for i in range(8):
    s.add(xs[i] ^ 0x5a == secret[i])            # условие программы
    s.add(xs[i] >= 0x20, xs[i] <= 0x7e)         # печатные ASCII
print("check:", s.check())
print("key =", bytes(s.model().eval(x).as_long() for x in xs))
```

Запускаем:

```
check: sat
key = b'2;917?{{'
```

`sat` означает «выполнимо» — решение найдено. Модель дала ключ `2;917?{{`.

## Шаг 3: проверяем на бинарнике

Решатель не исполняет программу — он решает формулы. Если модель неточна, ответ будет «правильным»
для неверной модели. Поэтому итог **всегда** проверяем на настоящем бинарнике:

```
$ ./keygen "2;917?{{"
correct
```

Совпало — рецепт сработал. Если бы бинарник ответил `wrong`, это означало бы расхождение модели с
программой: например, мы забыли про знаковость сравнения или про ширину регистра.

## Шаг 4: второй рецепт — цикл с суммой

Часто проверка не побайтовая, а суммирует байты в цикле. Пусть программа требует, чтобы сумма трёх
байт равнялась `0xd2`. Цикл превращается в одно ограничение через `Sum`, а байты расширяются до 32
бит (`ZeroExt(24, y)`), иначе сумма переполнится в 8-битной арифметике:

```python
ys = [BitVec(f"b{i}", 8) for i in range(3)]
s = Solver()
s.add(Sum([ZeroExt(24, y) for y in ys]) == 0xd2)
for y in ys: s.add(y >= 0x20, y <= 0x7e)
print("check:", s.check(), "answer:", bytes(s.model().eval(y).as_long() for y in ys))
```

```
check: sat answer: b'6WE'
```

Проверим арифметику: `'6' + 'W' + 'E'` = 54 + 87 + 69 = 210 = `0xd2`. Решатель вернул валидную
тройку. Расширение разрядности — ключевой момент: без `ZeroExt` сумма трёх 8-битных значений
обрезалась бы по модулю 256, и модель разошлась бы с программой.

## Шаг 5: когда логику вручную не выразить

Рецепт с Z3 работает, когда ты уже **выразил** логику формулой. Но если программа большая — сотни
функций, ветвления, вызовы библиотек — вручную её не перевести. Тогда берут **символическое
исполнение** (фреймворк angr): он сам «прогоняет» бинарник, трактуя ввод как символы, и ищет путь
к нужной точке. Внутри angr тоже использует Z3 — то есть рецепт тот же, просто условия собираются
автоматически.

Практический порядок такой: сначала попробуй перевести логику руками (быстро и точно для простых
проверок), и только если это тяжело — переходи к символическому исполнению. Для простого `keygen`
Z3 даёт ответ за секунды и не требует тяжёлого фреймворка.

## Шаг 6: что делать с `unsat`, `unknown` и несколькими ответами

Три исхода решателя требуют разной реакции. **`sat`** — решение есть, берём модель. **`unsat`** —
условия противоречивы: чаще всего это ошибка модели (перепутана знаковость, ширина или порядок
байт). Если проверить модель на бинарнике и он отвергает найденный ключ — модель неточна, ищи
расхождение. **`unknown`** — решатель не успел за отведённое время; это **не** доказательство, что
решения нет. Увеличь таймаут (`s.set('timeout', 60000)`), упрости формулу или снизь разрядность.

Ещё нюанс: у рецепта может быть **несколько** решений. Если ограничений меньше, чем неизвестных,
Z3 вернёт любое подходящее. Если нужен конкретный ключ (например, тот, что зашит в программе),
добавляй больше условий из кода — чем точнее модель, тем уже множество ответов. А для таблиц
подстановок (S-box) используют теорию массивов: `Select(A, i)` — чтение по индексу, `Store(A, i, v)`
— запись; но на больших таблицах это медленно, и их часто разворачивают в отдельные `BitVec`.

## Что мы теперь знаем

- Рецепт символического решения: символы → ограничения → `Solver` → модель.
- Неизвестные — `BitVec`; каждое действие программы — условие над ними.
- `sat`/`unsat` — есть/нет решение; `model()` даёт конкретный вход.
- Ограничение диапазона (`0x20..0x7e`) даёт печатный ключ.
- Суммы и смешанные ширины требуют `ZeroExt`; модель **всегда** проверяют на бинарнике.
- Для сложных программ рецепт автоматизирует символическое исполнение (angr).

## Инструмент: образец keygenme

Объект разбора — `keygenme`: бинарь, который принимает ключ и проверяет его
несколькими арифметическими условиями. Вместо ручного перебора условия
переводят в систему ограничений и решают солвером:

```
$ file keygenme
keygenme: ELF 64-bit LSB executable
$ strings keygenme | grep -i key
```

Каждая проверка (`if (x*3 == 42)`) становится ограничением для z3; решив всю
систему, получают валидный ключ, не подбирая его в лоб.
