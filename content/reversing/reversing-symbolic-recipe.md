Символическое исполнение — это способ заставить компьютер «решить» программу за вас. Вместо того
чтобы вручную разбирать проверку пароля, вы объявляете входные байты символами, исполняете программу
символически и спрашиваете: «какой вход приведёт к ветке success?». SMT-солвер (обычно Z3) находит
ответ. angr — самый популярный фреймворк для этого; он объединяет загрузку бинарников, символическое
исполнение и солвер. Этот урок — набор практических рецептов, которые закрывают большинство CTF-
задач на keygenme и проверку флагов.

## Когда символика полезна

Символическое исполнение выигрывает, когда:

- Проверка состоит из арифметики, битовых операций, сравнений (типичный crackme).
- Вы знаете, куда «идти» (адрес успеха) и откуда «стартовать» (точка ввода).
- Ручной разбор долог или запутан, а структура проверки понятна.

Оно проигрывает при: криптографии с большим числом раундов (взрыв выражений), проверках, зависящих
от внешних данных (сеть, время), и очень больших программах (взрыв путей). В этих случаях
символику комбинируют с конкретным исполнением (concolic) или сужают задачу.

## angr: базовый рецепт

Минимальный шаблон для ELF:

```python
import angr, claripy

proj = angr.Project("./crackme", auto_load_libs=False)
state = proj.factory.entry_state()
simgr = proj.factory.simulation_manager(state)
simgr.explore(find=0x401234, avoid=0x401250)   # адреса success / fail
if simgr.found:
    found = simgr.found[0]
    print(found.posix.dumps(0))   # что попало в stdin
```

`factory.entry_state()` создаёт начальное состояние, `simulation_manager` исследует пути,
`explore(find=..., avoid=...)` ищет состояние, достигающее `find`, минуя `avoid`. `posix.dumps(0)`
даёт байты, поданные на stdin. Это работает «из коробки» для многих задач.

## Символизация stdin и argv

По умолчанию `entry_state()` делает stdin символическим. Можно управлять этим:

```python
import angr, claripy

proj = angr.Project("./crackme", auto_load_libs=False)
flag = claripy.BVS("flag", 8 * 32)          # 32 байта
state = proj.factory.entry_state(stdin=flag)
for b in flag.chop(8):
    state.solver.add(b >= 0x20, b <= 0x7e)  # печатные символы
```

`BVS` создаёт символьный битвектор; `state.solver.add` накладывает ограничения (например, печатные
символы). После `explore` модель даёт конкретные байты. Для argv используют
`entry_state(args=[b"./crackme", flag])`.

## Z3: решение ограничений

Иногда удобнее работать с Z3 напрямую, восстанавливая ограничения вручную (например, после
декомпиляции проверки):

```python
from z3 import *

flag = [BitVec(f"f{i}", 8) for i in range(16)]
s = Solver()
for c in flag:
    s.add(c >= 0x20, c <= 0x7e)
# условие из декомпилированного кода:
s.add(flag[0] ^ 0x42 == ord('f'))
s.add((flag[1] + 3) & 0xff == ord('l'))
# ...
if s.check() == sat:
    m = s.model()
    print("".join(chr(m[c].as_long()) for c in flag))
```

Z3 незаменим, когда вы уже поняли алгоритм и нужно решить уравнение. Он быстрее и точнее angr для
«известных» ограничений.

## Практический разбор: keygenme

Пусть программа читает 8 байт и проверяет `hash(in) == const`. Рецепт:

```python
import angr

proj = angr.Project("./keygenme", auto_load_libs=False)
state = proj.factory.entry_state()
simgr = proj.factory.simulation_manager(state)

# адреса из дизассемблера
GOOD = 0x401300
BAD  = 0x401320
simgr.explore(find=GOOD, avoid=BAD)

if simgr.found:
    st = simgr.found[0]
    print("key:", st.posix.dumps(0))
else:
    print("не найдено — сузьте адреса или добавьте хуки")
```

Если angr «застревает», добавьте ограничения на ввод (печатные символы), отключите загрузку
библиотек (`auto_load_libs=False`) и используйте `find` по адресу инструкции, а не по функции.

## Хуки и избегание вызовов

Внешние функции (например, `strlen`, `printf`) символическому исполнению мешают. Их заменяют
хуками-заглушками:

```python
import angr

proj = angr.Project("./crackme", auto_load_libs=False)

@proj.hook(0x401100, length=5)   # адрес strlen
def fake_strlen(state):
    s = state.memory.load(state.regs.rdi, 64)
    # вернуть длину: используем символьную логику или конкретное значение
    state.regs.rax = 8

state = proj.factory.entry_state()
```

Хуки позволяют обойти криптографию (заменить вызов на возврат константы), ускорить исполнение и
избежать неподдерживаемых инструкций. Также используют `SIM_PROCEDURES` для замены известных
библиотечных функций (angr уже имеет многие встроенными).

## Управление взрывом путей

Главная проблема символики — экспоненциальный рост путей. Приёмы:

- **Ограничения на ввод**: печатные символы, известная длина, префикс (`flag{`).
- **`find`/`avoid`**: направляйте поиск, избегайте тупиков.
- **Техника `veritesting`**: автоматическое слияние путей (в angr: `veritesting=True`).
- **Разбиение на этапы**: решайте по частям (например, по байтам), используя результат предыдущего
  как фиксированный.
- **Concolic**: комбинируйте конкретное исполнение с символическим (angr `concretization`).

Для длинных проверок (100+ байт) часто помогает «посимвольный» подход: если проверка сравнивает
байты по одному и завершается при несовпадении, angr находит каждый байт отдельно.

## Инструменты и флаги

| Задача | API |
|---|---|
| Проект | `angr.Project(path, auto_load_libs=False)` |
| Состояние | `factory.entry_state()` |
| Менеджер | `factory.simulation_manager(state)` |
| Поиск | `simgr.explore(find=..., avoid=...)` |
| stdin | `state.posix.dumps(0)` |
| Символ | `claripy.BVS("x", 8*n)` |
| Ограничение | `state.solver.add(...)` |
| Хук | `proj.hook(addr, length=n)` |
| Z3 | `Solver()`, `check()`, `model()` |

## Concolic execution

Чисто символическое исполнение может «утонуть» в сложных вычислениях, где символьные выражения
разрастаются. Concolic (concrete + symbolic) исполнение решает это: программа исполняется с
конкретными входными данными, а символические выражения строятся только вдоль реального пути.
Когда встречается ветвление, concolic записывает условие и может «перевернуть» его, чтобы исследовать
альтернативный путь. Так сочетается скорость конкретного исполнения с полнотой символики.

В angr concolic-режим включается через опции `concretization` и `symbolic` в `explore`; в Triton
(см. отдельный урок) это основной режим. Для CTF concolic полезен, когда программа содержит хеши
или сжатие: символьные выражения для них не строятся целиком, а вычисляются конкретно с подстановкой
символов там, где это нужно.

## Практический пример: длинная проверка

Рассмотрим проверку, которая обрабатывает 32 байта и возвращает «success» только если все верны.
«В лоб» angr может взорваться. Рецепты:

1. **Ограничить ввод**: длина 32, печатные символы, известный префикс `flag{`.
2. **Разбить на этапы**: найти первый байт (по ветвлению раннего выхода), зафиксировать его,
   перейти к следующему. Многие проверки устроены так, что при несовпадении ранний выход.
3. **Хукать криптографию**: если проверка использует AES/SHA, заменить вызов заглушкой с известным
   поведением или перенести вычисление наружу.
4. **Использовать `find` по инструкции сравнения**: если видно `cmp al, byte [expected+i]`, ставьте
   `find` на адрес успеха для каждого байта.

Часто достаточно шага 1–2: посимвольный перебор через angr находит флаг за секунды, тогда как «в
лоб» не находит никогда.

## Визуализация и отладка angr

angr предоставляет инструменты для понимания происходящего. `simgr.active`, `simgr.deadended`,
`simgr.errored` показывают состояние исследования: сколько путей активно, сколько тупиковых, какие
ошибки. Если путей слишком много, вы увидите это в `active`. Для диагностики полезно:

```python
print("active:", len(simgr.active))
print("found:", len(simgr.found))
print("errored:", len(simgr.errored))
for e in simgr.errored[:3]:
    print(e.error)
```

Также можно задавать `find` как лямбду (условие на состояние), а не адрес: например, найти состояние,
где в памяти появилась строка `flag{`. Это гибче, когда адрес успеха неизвестен. Отладка через
`simgr.step()` по шагам помогает понять, где поиск сбивается.

## angr против ручного реверса

Не стоит применять символику ко всему подряд. Практическое правило: если проверка содержит простую
арифметику и вы видите адрес успеха — angr решит за минуты. Если проверка запутана обфускацией или
использует криптографию — сначала разберитесь с ней (хук, devirtualization), потом применяйте
символику к оставшейся части. Если программа требует внешних данных (файл, сеть, время), символика
не поможет без их моделирования.

Комбинированный подход часто оптимален: вручную найти точку, где проверяется ключ (например, вызов
`strcmp` с вычисленным значением), поставить `find` сразу за ней и позволить angr восстановить вход.
Так вы используете сильные стороны обоих методов: понимание структуры от человека, вычисления — от
солвера. Не бойтесь смешивать: символическое исполнение — это инструмент, а не замена анализа.

## Подводные камни

Первое: `find` по адресу функции может не сработать (angr останавливается на инструкции) — берите
адрес внутри функции. Второе: загрузка системных библиотек замедляет и добавляет пути —
`auto_load_libs=False`. Третье: без ограничений на ввод модель может дать непечатные байты.
Четвёртое: криптография с сотнями раундов вызывает взрыв выражений — хукайте её. Пятое: время работы
angr может быть большим; ставьте лимиты. Шестое: для нестандартных платформ (ARM/MIPS) нужна
поддержка в angr, иногда неполная. Седьмое: адреса в PIE — angr загружает по базе, проверьте
`proj.loader.main_object.mapped_base`. Восьмое: версия angr сильно влияет на API — примеры из
старых статей могут не работать; сверяйтесь с документацией вашей версии. Девятое: Z3 может
возвращать модель, где часть битов не определена, — всегда проверяйте результат на реальном запуске.
Десятое: `auto_load_libs=False` ускоряет, но может привести к неразрешённым символам — хукайте их.
