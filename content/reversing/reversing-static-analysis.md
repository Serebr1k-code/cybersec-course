Статический анализ — это чтение кода без запуска. Основной инструмент — **дизассемблер**
(превращает байты в ассемблер) и **декомпилятор** (превращает ассемблер в псевдо-C). Здесь мы
разберём три главных инструмента: radare2 (быстрый, консольный), Ghidra (бесплатный, мощный
декомпилятор) и IDA (стандарт индустрии). Навык один и тот же — меняется лишь интерфейс.

## radare2 / rizin: консольный фреймворк

radare2 (`r2`) есть практически в любом дистрибутиве и ставится в один клик. Rizin — форк с
совместимым синтаксисом. Базовый рабочий цикл:

```bash
r2 -A ./target          # -A: выполнить автоанализ при старте
# внутри интерактивной сессии:
afl                     # list functions — список найденных функций
s sym.main              # seek — перейти к main
pdf                     # print disassembly of function
V                       # визуальный режим (навигация стрелками)
q                       # выход
```

Ключевые команды (шпаргалка):

| Команда | Что делает |
|---------|-----------|
| `aaa` | Полный анализ (функции, ссылки, строки) |
| `afl` | Список функций |
| `s <addr/name>` | Перейти по адресу или имени |
| `pdf` | Дизассемблировать текущую функцию |
| `pd 20` | Дизассемблировать 20 инструкций |
| `iz` / `izz` | Строки в `.rodata` / во всём файле |
| `axt <addr>` | Кто вызывает/ссылается на адрес (xrefs) |
| `axf <addr>` | Откуда ссылается адрес |
| `afn new_name` | Переименовать функцию |
| `CC comment` | Добавить комментарий |
| `V` / `VV` | Визуальный режим / граф |
| `wx <bytes>` | Записать байты (патчинг, write mode) |

Быстрый поиск без интерактива (одной строкой):

```bash
r2 -q -c 'aaa; iz~flag; afl~check' ./target
r2 -q -c 'aaa; s sym.main; pdf' ./target
```

## Ghidra: бесплатный декомпилятор

Ghidra — открытый проект NSA. Главная ценность — **декомпилятор**, дающий C-подобный код. Рабочий
процесс:

1. `File → New Project` → создать проект.
2. `File → Import File` → выбрать бинарник. Ghidra спросит про формат — обычно автоопределение.
3. Двойной клик по файлу → откроется CodeBrowser. Согласиться на автоанализ (`Yes`).
4. Слева — **Symbol Tree** (функции), справа — **Listing** (ассемблер) и **Decompiler** (псевдо-C).

Полезные операции:

- **`g`** — Go to адресу или символу (`g` → `main`).
- **`Ctrl+Shift+E`** — список функций, отсортированный по ссылкам (xrefs). Функции с большим
  числом вызовов — обычно `printf`, `malloc`; малоизвестные маленькие — интересны.
- **`L`** — переименовать переменную/функцию. **Настоятельно рекомендуется**: переименовывайте
  `FUN_004011c8` → `check_password`, переменные `local_18` → `input`. Это резко повышает читаемость.
- **`Ctrl+Shift+G`** — применить тип; **`T`** — задать тип переменной.
- **Search → For Strings** (`Shift+Ctrl+F` или через окно Strings) — все строки с xrefs.
- **`Ctrl+Shift+F`** — поиск байтов (например, сигнатуры флага).
- **`Ctrl+Alt+B`** — patch byte; **`Ctrl+Shift+P`** — сохранить патч.

Типичный сценарий: находим строку `Correct!` в окне Strings, кликаем по её xref — попадаем в
функцию проверки. В декомпиляторе видим:

```c
if (strcmp(input, "s3cr3t_p4ss") == 0) {
    puts("Correct!");
} else {
    puts("Wrong.");
}
```

И пароль найден без единой инструкции вручную.

## IDA (Free / Pro)

IDA — коммерческий стандарт (есть бесплатная версия с ограничениями: только x86/x64, без
декомпилятора в Free). Если она есть:

- `File → Open` → выбрать файл → автоанализ.
- **Functions window** (`Shift+F3`) — список функций.
- **Strings window** (`Shift+F12`) — строки; двойной клик по строке → xref.
- **`X`** — cross references (кто ссылается на символ/адрес).
- **`N`** — rename, **`;`** — комментарий, **`Y`** — изменить тип.
- **`F5`** — декомпиляция (в версиях с Hex-Rays).
- **Space** — переключение Listing ↔ Graph view (граф — очень удобен для ветвлений).

Графовый режим IDA — лучший в классе: он наглядно рисует условия и слияния веток, что ускоряет
понимание логики.

## Сравнение инструментов

| Инструмент | Плюсы | Минусы |
|-----------|-------|--------|
| radare2/rizin | Быстрый, скриптуемый, везде, лёгкий | Крутая кривая обучения, слабее декомпилятор |
| Ghidra | Бесплатный, отличный декомпилятор, скрипты на Java/Python | Требует Java, интерфейс тяжеловат |
| IDA | Лучший UX и декомпилятор, графы | Дорогой (Pro), Free ограничена |

Практика: **Ghidra для декомпиляции + radare2 для быстрых проверок в терминале**. IDA — если
есть лицензия.

## Стратегия анализа незнакомого бинарника

Не читайте всё подряд. Двигайтесь по «маякам»:

1. **Точка входа и `main`.** С неё начинается управление. Найдите `main` (через Symbol Tree
   или по `__libc_start_main` → первый аргумент).
2. **Строки-подсказки.** `Correct`, `Wrong`, `Enter flag`, `%s`. Их xrefs ведут к проверкам.
3. **Вызовы сравнения.** `strcmp`, `memcmp`, `strncmp`. На входе — секрет.
4. **Циклы и математика.** Трансформации (XOR, сложения, перестановки) — тело цикла.
5. **Внешние вызовы.** `Import`/Symbol Tree покажет `read`, `fgets`, `fopen`, `connect` —
   понять, что делает программа (читает файл? сеть?).
6. **Неизвестные функции.** `FUN_xxx` без импорта, вызываемые из `main`, — самое интересное.

Хорошая техника — **сначала прочитать декомпилированный `main`**, он даёт «карту» программы:
какие функции вызываются в каком порядке.

## Практический пример: crackme с зашифрованной строкой

Бинарник `vault` просит ключ. В Ghidra строки не показывают пароль напрямую — только `Wrong`.
Находим `main`:

```c
int main(void) {
    char input[64];
    printf("Key: ");
    scanf("%63s", input);
    if (check(input)) {
        puts("Access granted");
        puts(flag);
    } else {
        puts("Wrong");
    }
    return 0;
}
```

Идём в `check`:

```c
bool check(char *in) {
    size_t n = strlen(in);
    if (n != 8) return false;
    char buf[8];
    for (int i = 0; i < 8; i++)
        buf[i] = in[i] ^ 0x2a;          // XOR с ключом
    return memcmp(buf, "\x59\x5e\x57\x54\x4f\x4a\x41\x48", 8) == 0;
}
```

Декомпилятор показал всю логику: длина 8, XOR с `0x2a`, сравнение с байтами. Осталось
посчитать обратное: `input[i] = cipher[i] ^ 0x2a`.

```python
c = bytes([0x59,0x5e,0x57,0x54,0x4f,0x4a,0x41,0x48])
print(bytes(b ^ 0x2a for b in c))   # b'secret!!'
```

Проверяем: `echo secret!! | ./vault` → `Access granted`.

## Ускорение: переименование и комментарии

Главный секрет продуктивной работы — **не читать `FUN_00401a3c` повторно**. Как только поняли
роль функции, переименуйте её (`afn`, `N`, `L`). То же с переменными. Через 20 минут вы получите
почти читаемый код с именами `decrypt_flag`, `verify_license`, `key`. Комментарии (`CC` в r2,
`;` в IDA) фиксируют гипотезы.

## Типичные ошибки новичка

- **Читать ассемблер, когда есть декомпилятор.** Начните с псевдо-C в Ghidra/IDA, ассемблер
  открывайте только там, где декомпилятор «врёт» (сложная оптимизация, обфускация).
- **Не переименовывать.** Без переименований вы утонете в `FUN_*` и `local_*`.
- **Доверять декомпилятору слепо.** Он ошибается на switch-таблицах, хвостовых вызовах и
  ручном ассемблере. Сверяйтесь с Listing.
- **Пропустить автоанализ.** Без него нет xrefs — половина навигации не работает.
- **Путать базу загрузки.** В Ghidra адреса условны; при пересчёте в отладчике учитывайте базу.
- **Не использовать граф.** Граф (`Space` в IDA, `VV` в r2) показывает структуру ветвлений лучше текста.
- **Забыть про 32-битные подрегистры.** Декомпилятор пишет `int`, но код мог работать с байтом.

## Где пригодится

- **CTF Reversing:** основной рабочий инструмент; 90% задач решаются в Ghidra/IDA/r2.
- **Malware analysis:** построение карты поведения образца без запуска.
- **Bug bounty / vuln research:** поиск опасных вызовов (`system`, `strcpy`) в закрытом ПО.
- **Аудит прошивок:** анализ MIPS/ARM-бинарей во встроенных устройствах.
- **Работа:** реверс-инженер, malware analyst, vulnerability researcher — ежедневный инструмент.
