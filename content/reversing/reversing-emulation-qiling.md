Не всегда можно (или безопасно) запустить анализируемый код. Malware может заразить машину, firmware
требует специфичного железа, а отдельная функция зависит от окружения, которого нет. Эмуляция решает
это: код исполняется в программной модели процессора, где вы полностью контролируете память,
регистры и системные вызовы. Два ключевых инструмента — **Unicorn** (движок эмуляции CPU) и
**Qiling** (фреймворк, добавляющий загрузку бинарников и ОС-уровень).

## Что такое эмуляция

Эмулятор — это программа, которая интерпретирует машинные инструкции одной архитектуры, обновляя
программную модель регистров и памяти. В отличие от реального запуска, эмуляция даёт полный контроль:
можно остановиться на любой инструкции, прочитать/изменить память, перехватить обращение к
несуществующему устройству, подменить результат системного вызова. Это идеально для анализа: вы
видите каждое действие, а код не «убегает» и не портит систему.

Unicorn — низкоуровневый движок (обёртка над QEMU), поддерживающий x86, ARM, MIPS, PowerPC и др.
Qiling строится поверх Unicorn и добавляет загрузчик бинарников, эмуляцию ОС (Linux, Windows, macOS,
Android, UEFI), файловую систему, реестр и хуки на API.

Важно различать два уровня. Эмуляция **инструкций** (Unicorn) отвечает на вопрос «что делает этот
код». Эмуляция **системы** (Qiling) отвечает на вопрос «как ведёт себя программа целиком»: какие
файлы открывает, что пишет в сеть, как взаимодействует с ОС. Для CTF чаще достаточно первого, для
malware-анализа — второго. Выбор инструмента диктуется задачей: не тяните Qiling там, где хватит
Unicorn, и не мучайтесь с ручной настройкой Unicorn там, где Qiling уже всё сделал.

## Unicorn: движок

Базовый сценарий Unicorn: создать эмулятор под архитектуру, отобразить память, записать код и
данные, установить регистры и запустить. Пример эмуляции фрагмента x86-64:

```python
from unicorn import *
from unicorn.x86_const import *

CODE = b"\x48\xc7\xc0\x01\x00\x00\x00\x48\x83\xc0\x02\x90"  # mov rax,1; add rax,2; nop
mu = Uc(UC_ARCH_X86, UC_MODE_64)
mu.mem_map(0x1000, 0x1000)
mu.mem_write(0x1000, CODE)
mu.reg_write(UC_X86_REG_RSP, 0x2000)
mu.emu_start(0x1000, 0x1000 + len(CODE))
print(hex(mu.reg_read(UC_X86_REG_RAX)))   # 0x3
```

Здесь мы вручную загрузили код и получили результат `rax = 3`. Unicorn идеален для эмуляции отдельных
функций: вы задаёте входные регистры, исполняете, читаете выходные. Для сложных бинарников придётся
самому настраивать память, релокации и системные вызовы — это трудоёмко.

## Qiling: фреймворк

Qiling берёт на себя рутину. Установка: `pip install qiling`, затем:

```python
from qiling import Qiling
from qiling.const import QL_VERBOSE

ql = Qiling(["./crackme", "arg1"], "rootfs/x8664_linux",
            verbose=QL_VERBOSE.DEFAULT)
ql.run()
```

Qiling загружает ELF/PE/Mach-O, отображает сегменты, настраивает стек, эмулирует системные вызовы
(`open`, `read`, `write`, `mmap`) и предоставляет виртуальную файловую систему (`rootfs`). Для
Windows-образцов он эмулирует часть WinAPI. Это позволяет запускать реальные бинарники без ОС и
наблюдать их поведение.

## Хуки на syscalls и API

Главная сила Qiling — хуки. Вы можете перехватывать системные вызовы, функции API и адреса в коде:

```python
from qiling import Qiling
from qiling.const import QL_VERBOSE

def hook_syscall(ql, intno, *args):
    print("syscall:", ql.os.syscall_name)

def hook_open(ql, *args):
    path = ql.mem.string(ql.os.function_arg(ql, 1)) if False else None
    # перехват openat: читаем путь
    print("open called")

ql = Qiling(["./sample"], "rootfs/x8664_linux", verbose=QL_VERBOSE.DISABLED)
ql.os.set_syscall("open", lambda ql, *a: print("open intercepted"))
ql.hook_address(lambda ql, addr: print("hit", hex(addr)), 0x401234)
ql.run()
```

Для Windows: `ql.os.set_api("CreateFileW", my_handler, QL_INTERCEPT.ENTER)`. Перехватывая API, вы
логируете поведение (какие файлы открываются, какие данные шифруются) и можете подменять результаты.
Это основа для распаковки, извлечения конфигурации и анализа протоколов.

## Практический разбор

Разберём crackme, который читает ввод и печатает результат. С Qiling мы эмулируем его и подменяем
ввод:

```python
from qiling import Qiling
from qiling.const import QL_VERBOSE

ql = Qiling(["./crackme"], "rootfs/x8664_linux", verbose=QL_VERBOSE.DISABLED)

def fake_read(ql, fd, buf, count):
    data = b"hunter2\n"
    ql.mem.write(buf, data)
    return len(data)

ql.os.set_syscall("read", fake_read)
ql.run()
```

Здесь мы перехватили `read` и вернули свой ввод. Если программа печатает «correct» — мы угадали. Для
автоматизации можно перебирать ввод, эмулируя функцию проверки напрямую. Так же эмулируются
упаковщики: запускаем стаб, ловим `mprotect`/`VirtualProtect` на распакованной области и снимаем
память.

Для firmware Qiling поддерживает MIPS/ARM: `Qiling(["./firmware.bin"], "rootfs/mipsel_linux")` с
указанием точки входа и карты памяти. Это позволяет анализировать IoT-образцы без реального
устройства.

## Обход анти-эмуляции

Malware умеет определять эмуляцию: проверяет неполноту реализации CPU (некоторые инструкции
эмулируются иначе), наличие «идеальных» значений (например, всегда одинаковый `rdtsc`), отсутствие
реальных устройств, специфичные ошибки эмулятора. Обход: настраивать `rdtsc` и время, эмулировать
больше API, добавлять устройства, использовать Qiling (он полнее Unicorn). Если не помогает —
переходите на отладку в изолированной ВМ.

## Инструменты и флаги

| Задача | Инструмент |
|---|---|
| Эмуляция CPU | Unicorn (`Uc`, `emu_start`, `hook_add`) |
| Загрузка бинарника | Qiling (`Qiling([...], rootfs)`) |
| Хук syscall | `ql.os.set_syscall(name, fn)` |
| Хук API (Win) | `ql.os.set_api(name, fn, QL_INTERCEPT.ENTER)` |
| Хук адреса | `ql.hook_address(fn, addr)` |
| Карта памяти | `ql.mem.map`, `ql.mem.read/write` |
| Firmware | Qiling + rootfs под MIPS/ARM |

## Виртуальная файловая система и rootfs

Qiling эмулирует файловую систему через каталог `rootfs`, который играет роль корня `/` для
эмулируемого процесса. Когда программа открывает `/etc/passwd`, Qiling ищет файл в
`rootfs/etc/passwd`. Это позволяет:

- Предоставить программе нужные файлы (конфигурации, библиотеки, словари).
- Перехватить чтение чувствительных файлов и подменить содержимое.
- Изолировать эмуляцию от реальной системы (программа не тронет ваш диск).

Для ELF нужно собрать rootfs с нужной libc и её зависимостями (Qiling включает готовые наборы для
популярных архитектур). Для PE Windows rootfs содержит минимальный набор системных DLL, которые
Qiling эмулирует на уровне API. Если файла нет, а программа его ожидает, эмуляция упадёт — следите
за сообщениями об ошибках и добавляйте недостающие файлы.

## Эмуляция firmware

Firmware — один из главных сценариев Qiling. Прошивки роутеров и IoT обычно собраны под MIPS
(mipsel/mipseb) или ARM и требуют специфичного окружения: NVRAM, специфичных устройств, сервисов.
Qiling позволяет:

1. Извлечь файловую систему из прошивки (`binwalk -e`).
2. Найти целевой бинарник (`httpd`, `telnetd`).
3. Запустить его в эмуляции с rootfs из прошивки:
   `Qiling(["./squashfs-root/usr/sbin/httpd"], "squashfs-root")`.
4. Перехватить вызовы (сеть, NVRAM) и наблюдать поведение.

Проблемы: неполная поддержка MIPS-инструкций, отсутствие эмуляции конкретных устройств (например,
`/dev/nvram`), анти-эмуляция. Решение — хуки: подменяйте `ioctl`/`open` на нужные устройства и
возвращайте реалистичные значения. Так можно запустить веб-интерфейс прошивки и найти уязвимости,
не имея устройства.

## Сравнение эмуляции с отладкой

Эмуляция и отладка дополняют друг друга. Отладка даёт максимальную точность (реальный CPU, реальная
ОС), но требует среды и может быть опасна. Эмуляция безопасна, воспроизводима и даёт полный контроль
памяти, но может «проговориться» и неполна. Практическое правило: начинайте с эмуляции (быстро и
безопасно), переходите к отладке, если эмуляция не справляется или образец её детектирует. Для CTF
эмуляция часто быстрее: можно подменить ввод и перебрать проверку без запуска бинарника.

| Критерий | Эмуляция | Отладка |
|---|---|---|
| Безопасность | высокая | средняя |
| Точность | неполная | полная |
| Скорость | медленнее | быстрее |
| Контроль памяти | полный | полный |
| Анти-эмуляция | уязвима | не применимо |
| Требования | только Python | среда, права |

## Эмуляция отдельных функций без ОС

Иногда не нужен весь бинарник — достаточно одной функции. Например, crackme содержит `verify(serial)`,
и нужно перебрать серийники. Вместо запуска программы эмулируем функцию напрямую. С Unicorn это
выглядит так: отображаем память, копируем код функции (из дизассемблера), помещаем аргумент в
регистр, исполняем до `ret` и читаем результат. Если функция вызывает библиотечные функции
(`strlen`, `memcmp`), их тоже эмулируют или хукают (`UC_HOOK_CODE` на адрес вызова → возвращаем
готовый результат).

Преимущество подхода — скорость и изоляция: тысячи итераций перебора выполняются без запуска
процесса. Именно так решают keygenme: извлекают функцию проверки, эмулируют её и подбирают
удовлетворяющий вход. Qiling позволяет то же самое на уровне «функция в загруженном бинарнике» через
`ql.run(begin=..., end=...)`. Это промежуточный вариант между полной эмуляцией и чистым Unicorn.

## Подводные камни

Первое: Unicorn не эмулирует ОС — syscalls надо обрабатывать самому. Второе: Qiling требует
корректного `rootfs` (библиотеки, файлы), иначе программа падает. Третье: не все инструкции и API
поддержаны. Четвёртое: эмуляция медленнее реального запуска в разы. Пятое: анти-эмуляция может
обнаружить среду — проверяйте, не «узнал» ли образец. Шестое: для больших бинарников настройка
памяти вручную (Unicorn) крайне трудоёмка — используйте Qiling.
