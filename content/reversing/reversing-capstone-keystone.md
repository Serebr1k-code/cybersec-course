## Вопрос, с которого всё начинается

Ты устал вручную открывать бинарники в GUI. Нужен **свой инструмент**: прочитать код, найти нужные инструкции, при необходимости изменить байты и выполнить их в эмуляторе. С чего начать?

## Наш пример

Возьмём `engine.elf` — ELF-бинарник, на котором мы будем строить анализатор:

```
$ file engine.elf
engine.elf: ELF 64-bit LSB executable, x86-64
```

Мы напишем на Python небольшой конвейер: дизассемблировать, распознать инструкции, собрать патч и исполнить.

## Шаг 1: Capstone — дизассемблер как библиотека

**Capstone** — движок дизассемблирования с API для многих языков. Он принимает байты, архитектуру и режим, а возвращает инструкции с мнемоникой, операндами и адресами.

```
from capstone import Cs, CS_ARCH_X86, CS_MODE_64
md = Cs(CS_ARCH_X86, CS_MODE_64)
for insn in md.disasm(code_bytes, 0x1000):
    print(f"{insn.address:#x}: {insn.mnemonic} {insn.op_str}")
```

Вывод — тот же, что у `objdump`, но в структурированном виде: с этим можно писать условия («найди все `call`»), строить графы и искать паттерны.

## Шаг 2: почему библиотека, а не парсинг вывода

Парсить текстовый вывод `objdump` хрупко: меняется формат, теряются детали. Capstone даёт структуры: `insn.mnemonic`, `insn.op_str`, `insn.bytes`, `insn.groups`. Это позволяет точно находить инструкции и их операнды, не полагаясь на строки.

## Шаг 3: Keystone — ассемблер как библиотека

**Keystone** — обратный к Capstone: собирает машинный код из ассемблера. Это нужно, когда ты хочешь **пропатчить** код: собрать нужные инструкции и вставить их в бинарник.

```
from keystone import Ks, KS_ARCH_X86, KS_MODE_64
ks = Ks(KS_ARCH_X86, KS_MODE_64)
encoding, count = ks.asm("nop; ret")
```

`encoding` — список байтов. Собрав патч, ты заменяешь им байты по нужному адресу — например, чтобы убрать проверку лицензии.

## Шаг 4: Unicorn — эмулятор как библиотека

**Unicorn** — эмулятор CPU: он исполняет машинный код без реальной машины. Это безопасно (код не выйдет в сеть и не тронет файлы) и удобно для анализа функций изолированно.

```
from unicorn import Uc, UC_ARCH_X86, UC_MODE_64
uc = Uc(UC_ARCH_X86, UC_MODE_64)
uc.mem_map(0x1000, 0x1000)
uc.mem_write(0x1000, code)
uc.emu_start(0x1000, 0x1000 + len(code))
```

Так можно «прогнать» функцию с разными входами и посмотреть, что она возвращает, — не запуская весь бинарник.

## Шаг 5: собираем конвейер

Три библиотеки складываются в конвейер:

1. **Capstone** — прочитать и найти целевую функцию/инструкции.
2. **Keystone** — собрать патч (например, заменить `jne` на `nop nop`).
3. **Unicorn** — эмулировать и проверить результат.

Это база для собственных деобфускаторов, эмуляторов и fuzz-скриптов.

## Шаг 6: артефакт

Извлечём строку движка:

```
$ strings -n 5 engine.elf | head
Capstone 5.0
Keystone 0.9
Unicorn 2.0
nto{c4pst0n3_k3yst0n3_un1c0rn}
```

В реальном скрипте артефактом был бы найденный адрес или результат эмуляции, а строка подтверждает версии библиотек.

## Что мы теперь знаем

- Capstone — дизассемблер как библиотека; даёт структурированные инструкции.
- Keystone — ассемблер как библиотека; нужен для патчей.
- Unicorn — эмулятор CPU; безопасно исполняет код изолированно.
- Вместе они образуют конвейер «прочитать → пропатчить → эмулировать».
- Парсить вывод objdump хрупко; библиотеки дают точные структуры.
