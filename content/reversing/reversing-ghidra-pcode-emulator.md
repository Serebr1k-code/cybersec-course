## Вопрос, с которого всё начинается

У тебя функция-обфускатор, которая считает результат длинной цепочкой операций, и ты хочешь получить ответ, **не запуская** программу. Можно ли «выполнить» её в песочнице внутри декомпилятора?

## Наш пример

`target.bin` содержит функцию, которая из входа вычисляет строку. Мы эмулируем её P-Code, не запуская бинарник, и получим результат.

## Шаг 1: что такое P-Code

**P-Code** — промежуточный язык Ghidra. Каждую машинную инструкцию (x86, ARM, MIPS — любую) Ghidra переводит в несколько **P-Code операций** (микроопераций): `COPY`, `LOAD`, `STORE`, `INT_ADD`, `CALL`, `BRANCH` и т.д.

Свойства P-Code:

- **Архитектурно-независимый** — один и тот же набор операций для всех ISA;
- **Явный** — каждая операция делает одно действие;
- **Доступный из API** — можно читать и интерпретировать.

Это делает P-Code не просто внутренним форматом, а **исполняемым** промежуточным языком.

## Шаг 2: зачем эмулировать

Эмуляция P-Code — это запуск **без запуска**:

- **Безопасно.** Не исполняется реальный код, нет риска для системы.
- **Изолированно.** Можно задать любое состояние регистров/памяти.
- **Обходимо.** Обфусцированный код всё равно должен посчитать результат — а значит, его можно вычислить эмуляцией, не понимая обфускации.

Классический пример: **opaque-предикат** `if (complicated_always_true())`. Вместо того чтобы разбирать `complicated_always_true`, эмулятор просто вычисляет её и получает `true`.

## Шаг 3: эмуляция в Ghidra

Ghidra даёт API для эмуляции (`PcodeEmulator`). Упрощённо:

```python
from ghidra.app.emulator import EmulatorHelper
emu = EmulatorHelper(currentProgram)
emu.writeRegister("RDI", 0x1000)     # задать аргумент
emu.writeMemory(0x1000, b"MAGIC")    # задать строку
while not emu.isAtBreakpoint():
    if not emu.step():
        break
print(emu.readMemory(0x2000, 32))    # прочитать результат
```

Эмулятор исполняет P-Code инструкция за инструкцией, пока не дойдёт до `ret`.

## Шаг 4: результат эмуляции

```bash
$ python3 emulate_pcode.py target.bin
loaded function @ 0x00401000
emulating 137 pcode ops...
result @ 0x00402000 = b'nto{pcode_3mul4t10n_d30bfusc4t10n}'
```

Мы получили строку, которую функция вычисляет, **не запуская бинарник**.

## Шаг 5: деобфускация через эмуляцию

Главный приём: **заменить вызов эмуляцией**. Если в коде есть вызов «чёрного ящика», который возвращает константу, можно:

1. поставить эмуляцию на входе этого вызова;
2. выполнить до возврата;
3. записать результат как константу в листинг.

Так снимают:

- **строковые дешифраторы** — эмулируешь функцию расшифровки, получаешь строку;
- **API hashing** — эмулируешь хеш, получаешь имя функции;
- **opaque-предикаты** — эмулируешь условие, получаешь ветку;
- **VM-протекторы** — эмулируешь handler, получаешь семантику.

## Шаг 6: ограничения

Эмуляция — не серебряная пуля:

- **Сложность окружения.** Если функция вызывает ОС (файлы, сеть), эмулятор её не выполнит — нужно подменять вызовы.
- **Производительность.** Эмуляция медленнее нативного запуска.
- **Анти-эмуляция.** Продвинутые протекторы детектируют эмуляцию и меняют поведение.
- **Недетерминизм.** Результат зависит от заданного начального состояния.

Тем не менее для **чистых вычислений** (дешифровка строк, хеши) эмуляция P-Code — самый быстрый путь к результату.

## Что мы теперь знаем

- P-Code — промежуточный язык Ghidra, в него переводится любая инструкция.
- P-Code можно эмулировать: выполнить, не запуская процесс.
- Эмуляция обходит обфускацию, вычисляя результат напрямую.
- Типовые применения: строки, API hashing, opaque-предикаты, VM-handler-ы.
- Ограничения: вызовы ОС, скорость, анти-эмуляция.

## Шаг 7: микрооперации P-Code

Каждая инструкция переводится в набор операций. Пример для x86 `mov eax, [rbx+4]`:

```text
$U1 = INT_ADD rbx, 0x4
$U2 = LOAD ram($U1)
eax  = COPY $U2
```

Видно три операции: вычислить адрес, прочитать память, записать в регистр. Такой вид **архитектурно-нейтрален**: для ARM будет то же самое (`LOAD`/`STORE`/`INT_ADD`), но из других инструкций.

## Шаг 8: пространства и регистры

P-Code работает с **адресными пространствами**: `ram` (память), `register`, `unique` (временные). Регистры — это тоже пространство, только маленькое. Эмулятор умеет читать/писать в любое из них.

```python
emu.writeRegister("RDI", 0x400000)   # пространство register
emu.writeMemory(0x400000, b"input")  # пространство ram
```

Это даёт полный контроль над начальным состоянием.

## Шаг 9: эмуляция как оракул

Главная ценность — использовать эмуляцию как **оракул**: «что вернёт эта функция при таком входе». Не нужно понимать, что она делает; нужно лишь корректно задать вход и прочитать выход.

Пример: функция дешифрует строку из массива байт. Ты:

1. находишь адрес массива;
2. пишешь его в память эмулятора;
3. задаёшь аргумент-указатель;
4. запускаешь до `ret`;
5. читаешь результат из памяти.

Результат — расшифрованная строка, без анализа алгоритма.

## Шаг 10: подмена внешних вызовов

Функция может вызывать ОС (`malloc`, `recv`). Эмулятор их не выполнит. Решение — **hooks**: перехватить вызов и вернуть фиктивное значение.

```python
def malloc_hook(emu):
    size = emu.readRegister("RDI")
    addr = 0x500000
    emu.writeRegister("RAX", addr)
    return True
```

Так эмулируются даже функции, зависящие от окружения: подменяешь системные вызовы, оставляешь «чистую» логику.

## Шаг 11: деобфускация через символьную эмуляцию

Более продвинутый вариант — **символьная эмуляция**: входные байты становятся символами, и эмулятор строит выражение результата. Так решают opaque-предикаты (получить `true`/`false`) и восстанавливают строковые дешифраторы аналитически.

```text
input = sym("in")
out = emulate(func, input)
simplify(out)   # -> "nto{...}"
```

Это уже не просто «выполнить», а «понять формулу» — мощный инструмент деобфускации.

## Шаг 12: таблица применений

| Задача | Приём |
|---|---|
| Строковый дешифратор | эмуляция + чтение результата |
| API hashing | эмуляция хеша |
| Opaque-предикат | эмуляция условия |
| VM-handler | эмуляция handler-а |
| Внешний вызов | hook |
| Формула | символьная эмуляция |

## Шаг 13: ограничения и обходы

Эмуляция ломается на: вызовах ОС (нужны hooks), анти-эмуляции (детект и смена поведения), недетерминизме (зависимость от времени/случая), больших циклах (медленно). Для каждого есть приём: hooks, подмена детекторов, фиксация начального состояния, ограничение числа шагов.

## Шаг 14: сравнение с реальным запуском

Эмуляция vs нативный запуск:

| | Эмуляция | Нативный запуск |
|---|---|---|
| Безопасность | высокая | низкая |
| Скорость | ниже | выше |
| Контроль состояния | полный | частичный |
| Внешние вызовы | нужно подменять | работают |
| Обход обфускации | да | не всегда |

Для чистых вычислений (строки, хеши) эмуляция предпочтительнее: она изолирована и даёт точный результат.

## Шаг 15: итоговый алгоритм

Открой функцию в Ghidra. Найди P-Code через API. Задай входные регистры и память. Поставь hooks на внешние вызовы. Эмулируй до `ret`. Прочитай результат. Для обфускации — используй символьную эмуляцию и упрощение выражений. Главное: **если код что-то вычисляет, это можно вычислить эмуляцией, не понимая обфускации**.

## Шаг 16: почему эмуляция обходит обфускацию

Обфускатор может запутать код как угодно, но он не может изменить **результат** вычисления. Функция-дешифратор обязана вернуть правильную строку, иначе программа не заработает. Это фундаментальное ограничение: обфускация усложняет чтение, но не меняет семантику. Эмуляция эксплуатирует именно это: вместо того чтобы разбирать запутанную логику, ты просто выполняешь её и читаешь ответ. Аналитик, который пытается понять обфусцированный дешифратор вручную, тратит часы; эмулятор получает тот же ответ за секунды. Именно поэтому эмуляция — один из самых мощных приёмов современного реверса. Она превращает задачу «понять, что делает код» в задачу «выполнить код и посмотреть результат», а второе несравнимо проще. Конечно, есть случаи, когда эмуляция не помогает: если код зависит от внешнего мира (сеть, время, файлы) или активно детектирует эмуляцию. Но для чистых вычислений — строк, хешей, предикатов, VM-handler-ов — она незаменима.

## Шаг 17: P-Code как основа для символьного исполнения

Эмуляция P-Code бывает конкретной и символьной. В конкретной вход — числа, выход — числа. В символьной вход — символы, и эмулятор строит **выражение** результата. Это открывает путь к деобфускации нового уровня: ты не просто получаешь ответ для конкретного входа, ты получаешь формулу, описывающую функцию. Например, для opaque-предиката символьная эмуляция вернёт `true` или `false` независимо от входа — значит, ветка фальшивая. Для строкового дешифратора — выражение, которое можно упростить до самой строки. Символьное исполнение поверх P-Code реализуют как надстройку: каждая микрооперация применяется к символьным выражениям, а не к числам. Так появляются инструменты, которые автоматически снимают целые классы обфускации. Это уже на границе реверса и формальных методов, но принцип прост: P-Code даёт исполняемую семантику, а символы — обобщение.

## Шаг 18: практические советы по эмуляции

Начинай с простого: выбери функцию, которая явно что-то вычисляет (дешифровка, хеш, проверка), и эмулируй её на конкретном входе. Убедись, что результат осмысленный. Если функция вызывает ОС — поставь hooks и верни фиктивные значения. Если эмуляция «уходит» в бесконечность — ограничь число шагов и посмотри, где зациклилась. Если результат зависит от неинициализированной памяти — задай её явно. Постепенно переходи от конкретной эмуляции к символьной там, где нужна формула. И помни: эмуляция — это инструмент, а не замена пониманию. Она даёт ответы, но чтобы использовать их в отчёте, нужно понимать, что они значат. Лучший результат — когда эмуляция даёт ответ, а анализ объясняет, почему он такой.
