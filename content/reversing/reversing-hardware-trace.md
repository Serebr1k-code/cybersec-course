**Аппаратная трассировка** записывает поток управления (какие ветвления, вызовы и переходы выполнились) на уровне CPU с минимальным оверхедом. Intel PT (Processor Trace) и ARM CoreSight ETM — ключевые технологии. Они незаменимы для **fuzzing-покрытия**, анализа malware, устойчивого к анти-отладке, и посмертного анализа (когда процесс уже упал). В отличие от DBI, аппаратная трассировка не модифицирует код и почти не замедляет программу, но даёт только поток управления без данных. В этом уроке — сбор и декодирование трасс Intel PT и ARM ETM.

## Что такое аппаратная трассировка

Аппаратный трассировщик пишет компактный поток пакетов, из которого восстанавливается последовательность исполненных адресов. Intel PT кодирует переходы дельтами и сжатием: записываются только «непредсказуемые» ветвления (косвенные переходы, возвраты, прерывания), а предсказуемые (условные переходы с известной целью) опускаются — декодер восстанавливает их по бинарю. Это даёт очень компактные трассы (мегабайты на минуты исполнения) при замедлении всего в 2–5 %. ARM ETM работает похоже (пакеты с адресами, сжатие). Обе технологии требуют поддержки CPU и ОС (perf_event, MSR).

## Intel PT: принцип и включение

Intel PT включается через MSR и настраивается через `perf` или напрямую. Основные компоненты: регионы вывода (ToPA — Table of Physical Addresses), фильтры (по адресам, по CR3, по IP), режимы (single-range, trace-enable MSR). Быстрое включение через perf:

```bash
# трассировать конкретный процесс
perf record -e intel_pt//u -o pt.data -- ./target arg
# трассировать систему с фильтром по CR3
perf record -e intel_pt//k -a -o pt.data -- sleep 10
# показать, что поддерживается
perf record -e intel_pt//u --help
ls /sys/bus/event_source/devices/intel_pt/
```

Опции PT: `cyc` (временные метки TSC), `mtc` (MTC-пакеты), `ptw` (Power Trace), `noretcomp`, `tsc`. Для пользовательского режима `u`, для ядра `k`.

## Декодирование трасс

Сырой поток PT декодируется в последовательность адресов с помощью `libipt` (Intel) или `perf script`. `perf` умеет декодировать сам:

```bash
perf script -i pt.data --itrace=i100us -F ip,sym > trace.txt
# или полный дамп
perf script --itrace=brstack -i pt.data | head
```

Инструменты: `ptxed` (из libipt) — консольный декодер:

```bash
ptxed --insn-trace --pt pt.data --raw | head -50
ptxed --block-trace --pt pt.data --elf ./target
```

`ptxed` восстанавливает инструкции и блоки, используя бинарь для предсказания условных переходов. Для программирования напрямую — библиотека `libipt` (C/C++/Python bindings) с классами `pt_packet_decoder`, `pt_insn_decoder`.

## ARM CoreSight ETM

На ARM трассировка называется **CoreSight**; компонент, пишущий поток управления — **ETM** (Embedded Trace Macrocell). Данные выводятся через ETB (встроенный буфер) или TPIU (внешний порт). Включение: через CoreSight-регистры (`ETMCR`, `ETMTRACEIDR`) или OpenCSD-инструменты. Декодирование — библиотека **OpenCSD** (`trc_pkt_lister`, `perf` с `cs_etm`):

```bash
# на ARM64 Linux
perf record -e cs_etm/@tmc_etr0/ -o etm.data -- ./target
perf script -i etm.data --itrace=i1000 -F ip,sym
```

Для embedded (без Linux) используют аппаратные пробники (Lauterbach, J-Link) и OpenOCD. ETM даёт поток адресов, который декодируется OpenCSD с опорой на образ.

## Применение: fuzzing-покрытие

Аппаратная трассировка идеальна для покрытия в фаззинге, потому что не требует инструментации кода (работает с «чёрным ящиком») и даёт точные адреса блоков. Схема: фаззер запускает цель под PT, собирает трассу, декодирует адреса базовых блоков, хеширует в битмап, сравнивает с предыдущим — новое покрытие сигнализирует об интересном входе. Инструменты: `honggfuzz` (поддержка Intel PT), `kAFL` (PT-based kernel fuzzer), AFL++ с `-Q`/PT-режимами. Преимущество: нет оверхеда DBI, устойчивость к анти-инструментации.

## Применение: анализ malware

Malware часто детектирует отладчики и DBI, но аппаратная трассировка незаметна для него (не меняет процесс). Схема: запустить образец под PT в изолированной ВМ, собрать трассу, декодировать, найти адреса расшифровки/распаковки и переход на OEP. Также PT используют для **посмертного анализа**: при краше сохраняют трассу и восстанавливают, что привело к падению (ценно для fuzzing-триажа и эксплойт-разработки). Дополнительно PT пишет TSC-метки — можно измерять тайминги и находить крипто-операции по времени.

## Ограничения

- **Только поток управления**: нет значений регистров и данных памяти (в отличие от DBI).
- **Требуется декодер и бинарь**: восстановление условных переходов опирается на образ; при самомодифицирующемся коде возможны расхождения.
- **Объём трассы**: длительное исполнение даёт много данных; нужна буферизация (ToPA) и своевременная выгрузка.
- **Поддержка CPU/ОС**: не все процессоры и ядра имеют PT/ETM; в ВМ PT может быть недоступен.
- **Привилегии**: включение PT требует прав (perf_event, MSR); в контейнерах может быть закрыто.

## Полный разбор: покрытие функции под Intel PT

**Шаг 1 — запись:** `perf record -e intel_pt//u -o pt.data -- ./target input`. **Шаг 2 — декодирование:** `perf script -i pt.data --itrace=i1 -F ip > ips.txt` (адреса инструкций). **Шаг 3 — блоки:** по адресам и образу восстанавливаем базовые блоки (используя `ptxed --block-trace`). **Шаг 4 — покрытие:** хешируем блоки в битмап, сравниваем между входами. **Шаг 5 — фаззинг:** интегрируем в цикл мутаций, отбирая входы с новым покрытием. **Шаг 6 — анализ:** по трассе падения находим путь к багу.

## Intel PT: ToPA и фильтры

Вывод PT пишется в память через **ToPA** (Table of Physical Addresses) — структуру, описывающую регионы вывода и порядок их заполнения. Каждый регион имеет базовый адрес, размер и флаг `STOP`; когда буфер заполняется, трассировщик переходит к следующему, а по `INT`-флагу генерирует прерывание — драйвер успевает выгрузить данные. Фильтры ограничивают объём: **IP-фильтр** (`IA32_RTIT_ADDR0/1`) трассирует только диапазон адресов; **CR3-фильтр** — только конкретный процесс; **TraceEn** через MSR. Для многопроцессных систем CR3-фильтр критичен, иначе трасса смешивается. Настройка через perf скрывает эти детали, но для тонкого контроля (например, трассировки ядра) настраивают MSR напрямую: `IA32_RTIT_CTL`, `IA32_RTIT_OUTPUT_BASE`, `IA32_RTIT_OUTPUT_MASK`. Понимание ToPA помогает не потерять данные при длительной трассировке.

## Ручной разбор пакетов PT

Поток PT состоит из пакетов: `PSB` (синхронизация), `TNT` (Taken/Not-taken для условных переходов), `TIP` (целевой IP для косвенных), `TSC`, `MTC`, `PIP` (процесс/CR3), `FUP` (flow update). Декодер идёт по пакетам, ведёт текущий IP и применяет TNT-биты к условным переходам (используя образ для поиска инструкций). Пример разбора через libipt на Python/C: создать `pt_packet_decoder`, читать пакеты, синхронизироваться по PSB, затем `pt_insn_decoder` для инструкций. Понимание формата нужно, когда `perf script` даёт неполную картину или трасса повреждена. Утилита `ptxed --raw` показывает сырые пакеты — полезно для отладки.

## Сравнение PT, ETM и DBI

| Свойство | Intel PT | ARM ETM | DBI (PIN/QBDI) |
|---|---|---|---|
| Данные | только поток управления | только поток управления | регистры и память |
| Оверхед | 2–5 % | 2–5 % | 5–100× |
| Модификация кода | нет | нет | да (JIT) |
| Модификация состояния | нет | нет | да |
| Требования | CPU/ОС/права | CoreSight | библиотека |
| Применение | coverage, посмертный анализ | embedded, coverage | taint, деобфускация |

PT/ETM идеальны для покрытия и анализа «чёрного ящика», DBI — для глубокой инструментации. На практике их комбинируют.

## Практика: триаж краша по трассе

Когда фаззер нашёл падение, PT-трасса позволяет восстановить путь к багу: декодируем трассу до момента краша, смотрим последние блоки, определяем функцию и входные данные. Схема: сохранять трассу для каждого запуска, при краше взять последнюю, декодировать с `ptxed --insn-trace`, найти границу модуля-виновника. Дополнительно TSC-пакеты дают тайминги — можно заметить аномально долгие операции (крипто, сеть). Для эксплойт-разработки трасса помогает понять, как достичь уязвимого состояния (какие ветвления пройти). Это стандартный приём в kAFL и honggfuzz.

## Отладка и типичные ошибки

- **Пустая трасса**: не включён PT в BIOS/ядре, нет прав, фильтр слишком узкий.
- **Обрезанная трасса**: переполнение ToPA без выгрузки — увеличьте буферы/поставьте `INT`.
- **Несовпадение адресов**: неверный бинарь или ASLR — используйте тот же образ и учитывайте базу.
- **Пропущенные блоки**: декодер не смог предсказать условный переход (самомодифицирующийся код) — трасса теряет синхронизацию до следующего PSB.
- **Смешение процессов**: без CR3-фильтра в трассе несколько процессов.
- **Оверхед выше ожидаемого**: включены `cyc`/`mtc`/`ptw` — отключите лишнее.
