Z3 — это SMT-решатель (Satisfiability Modulo Theories) от Microsoft Research, который лежит в основе символьного исполнения, генерации keygen'ов и автоматического решения CTF-крэкми. Базовый API (`Solver`, `add`, `check`, `model`) осваивается за десять минут, но реальные задачи требуют аккуратного **моделирования** семантики: битвекторов фиксированной ширины, знаковости сдвигов, байтовых буферов, массивов и точного порядка операций. Одна неверно смоделированная операция — и решатель выдаст «правильный» ответ для неверной модели. В этом уроке мы разберём продвинутые приёмы Z3 и полностью пройдём путь от дизассемблированной проверки до готового ключа.

## Зачем Z3 в реверсе и где он ошибается

Z3 применяют там, где нужен **поиск входа, удовлетворяющего ограничениям**: крэкми с проверкой пароля, keygen'ы, задачи на криптографию с известными парами открытый/зашифрованный текст, обход лицензионных проверок. Z3 не исполняет программу — он решает систему логических формул. Поэтому главный навык — не «запустить решатель», а **точно перевести машинный код в формулы**. Типичные ошибки: забыли знаковость сдвига, смешали 8- и 32-битные значения без расширения, проигнорировали порядок байт, смоделировали деление как вещественное. Z3 молча примет такую модель и вернёт неверный ответ, поэтому итоговую модель всегда проверяют на настоящем бинаре.

## Установка и базовый API

Устанавливается Z3 через pip (`pip install z3-solver`) или как системный пакет (`apt install python3-z3`). Базовый каркас:

```python
from z3 import *

x = BitVec('x', 32)
s = Solver()
s.add(x * 3 == 0x1337)
s.add(x & 0xff == 0x37)
print(s.check())        # sat / unsat / unknown
print(s.model())        # [x = 5439]
print(s.model()[x].as_long())
```

`check()` возвращает `sat`, если решение есть, `unsat` — если ограничения противоречивы, `unknown` — если решатель не смог за отведённое время. `model()` даёт конкретное присваивание. Ключевые классы: `BitVec` (битвектор), `Int`/`Real` (целые/вещественные), `Bool`, `Array`, `Function`. Для CTF почти всегда используют именно `BitVec` — регистры имеют фиксированную ширину.

## Битвекторы и точная семантика операций

Битвектор — значение фиксированной ширины, над которым определены операции с модульной арифметикой. Обязательно помнить: `>>` для `BitVec` — **арифметический** сдвиг (знаковый), логический делается через `LShR`; сравнения `ULT`/`ULE`/`UGT`/`UGE` — беззнаковые, `SLT`/`SLE`/`SGT`/`SGE` — знаковые. Обычные `<`, `>`, `<=`, `>=` для битвекторов знаковые.

```python
from z3 import *
x = BitVec('x', 32)
s = Solver()
s.add(x >> 4 == 0x0f)          # арифметический сдвиг
s.add(LShR(x, 4) == 0x0f)      # логический сдвиг
s.add(ULT(x, 0x1000))          # беззнаковое сравнение
s.add(SignExt(4, x) == 0)      # расширение со знаком
```

Ротация моделируется комбинацией сдвигов: `RotateLeft(x, 7)` или вручную `(x << 7) | LShR(x, 25)`. Для 8-битных байт и 32-битных слов смешивание требует явного расширения — `ZeroExt(k, x)` дописывает нулевые биты, `SignExt(k, x)` — знаковые, где `k` — число добавляемых бит.

## Байтовые массивы и моделирование строк

Пароли и флаги удобно моделировать как список 8-битных переменных. Обязательно ограничивают диапазон печатных символов, иначе решатель вернёт управляющие байты:

```python
from z3 import *
flag = [BitVec(f'c{i}', 8) for i in range(16)]
s = Solver()
for c in flag:
    s.add(c >= 0x20, c <= 0x7e)          # печатные
s.add(flag[0] == ord('f'))
s.add(flag[1] == ord('l'))
s.add(flag[2] + flag[3] == 0x9a)         # 8-битное сложение!
s.add(flag[4] ^ 0x2a == 0x00)
if s.check() == sat:
    m = s.model()
    print(bytes(m[c].as_long() for c in flag))
```

Здесь `flag[2] + flag[3]` — сложение в 8-битной модульной арифметике, как в C при работе с `unsigned char` (переполнение обрезается). Если оригинал складывал в 32-битном регистре, нужно расширять: `ZeroExt(24, flag[2]) + ZeroExt(24, flag[3])`.

## Массивы Z3 (Array/Select/Store) и моделирование памяти

Для S-box, таблиц подстановок и произвольной памяти используют теорию массивов. `Select(A, i)` — чтение, `Store(A, i, v)` — запись, возвращающая **новый** массив (функциональная семантика, без побочных эффектов):

```python
from z3 import *
A = Array('A', BitVecSort(32), BitVecSort(32))
s = Solver()
s.add(Select(A, 0) == 0x41)
s.add(Select(A, 1) == 0x42)
B = Store(A, 2, 0x43)
s.add(Select(B, 2) == 0x43)
s.add(Select(B, 0) == 0x41)      # сохраняется из A
```

Теория массивов мощная, но дорогая: решатель может «застрять». Для маленьких таблиц (S-box AES — 256 байт) часто выгоднее развернуть массив в константы или в отдельные `BitVec` и моделировать индексацию как `If(i == k, v_k, ...)`.

## Упрощение, тактики и инкрементальный решатель

`simplify(expr)` сокращает выражение до добавления. Инкрементальный решатель (`push`/`pop`) позволяет переиспользовать базовые ограничения, добавляя временные:

```python
s = Solver()
s.add(base_constraints)      # общие для всех кандидатов
s.push()
s.add(specific_candidate)
if s.check() == sat:
    print(s.model())
s.pop()                      # откат specific_candidate
```

`check(assumptions)` добавляет ограничения только на один вызов. Тактики настраивают конвейер решателя: `Then('simplify', 'propagate-values', 'solve-eqs', 'smt')` — полезно для тяжёлых формул. Для больших задач помогает разбиение на битвекторы меньшей ширины и ручное упрощение крипто-раундов.

## Оптимизация (Optimize) и мягкие ограничения

Когда нужен не любой ответ, а **лучший** (минимальный пароль, максимальное значение), применяют `Optimize`:

```python
opt = Optimize()
opt.add(x >= 0, x < 0x100000)
opt.maximize(x)
opt.check()
print(opt.model())
```

Мягкие ограничения (`opt.add_soft(cond, weight)`) позволяют нарушать часть условий с ценой — удобно, когда точных уравнений больше, чем неизвестных. Но злоупотребление `Optimize` сильно замедляет решение.

## Полный разбор: keygen крэкми end-to-end

Пусть после дизассемблирования `check` мы восстановили четыре условия для входа из четырёх байт. **Шаг 1 — записать модель:**

```python
from z3 import *
x = [BitVec(f'x{i}', 8) for i in range(4)]
s = Solver()
for c in x:
    s.add(c >= 0x20, c <= 0x7e)
s.add((x[0] ^ 0x13) + ZeroExt(0, x[1]) == 0xa7)
s.add(ZeroExt(0, x[0]) > ZeroExt(0, x[1]))
s.add(x[2] * 3 == x[3] + 0x20)
s.add(x[0] ^ x[1] ^ x[2] ^ x[3] == 0x2a)
```

**Шаг 2 — решить и распечатать:**

```python
print(s.check())                       # sat
m = s.model()
key = bytes(m[c].as_long() for c in x)
print(key)                             # b'...'
```

**Шаг 3 — проверить на реальном бинаре:** `./crackme "$(cat key.txt)"` — программа должна ответить «Correct». Если проверка падает, значит модель неточна (знаковость, ширина или порядок байт), и надо вернуться к дизассемблеру. Всегда проверяйте модель на настоящем исполнении — Z3 не гарантирует, что вы смоделировали оригинал.

## Моделирование реальной криптографии: ARX и TEA

Многие крэкми используют самописную криптографию. Её нужно развернуть в формулы по раундам. Пример ARX-раунда (add-rotate-xor):

```python
from z3 import *
def arx_round(a, b, k):
    a = (a + b) ^ k
    b = RotateLeft(b, 7) + a
    return a, b

a, b = BitVec('a', 32), BitVec('b', 32)
for i in range(8):
    a, b = arx_round(a, b, BitVecVal(0x1337 + i, 32))
s = Solver(); s.add(a == 0xdeadbeef)
```

Так же моделируют TEA/XTEA (раунды из сложений, сдвигов и XOR), а для AES, если ключ неизвестен, часто проще извлечь раундовые ключи из памяти, чем решать нелинейные S-box. Если крипто-примитив стандартный — берите готовую реализацию и подменяйте только ключ.

## Типичные ошибки и падение производительности

- **Знаковость сдвига:** `>>` — арифметический; для беззнакового используйте `LShR`.
- **Расширение разрядности:** смешивание 8 и 32 бит без `ZeroExt`/`SignExt` даёт неверную модель.
- **Нет ограничения диапазона:** без `>= 0x20, <= 0x7e` решатель вернёт непечатные байты.
- **Перебор вместо модели:** «пробовать все комбинации» — антипаттерн; сначала точная модель.
- **Медленный решатель:** упрощайте формулы, применяйте `push`/`pop`, снижайте битность, избегайте теории массивов на больших таблицах.
- **Порядок байт:** при загрузке 4 байт из памяти учитывайте little-endian (`Concat` в обратном порядке).
- **`unknown` вместо `unsat`:** таймаут — не доказательство отсутствия решения; увеличивайте `timeout` или упрощайте.

## Шпаргалка по API Z3

| Задача | Код |
|---|---|
| Переменная ширины N | `BitVec('x', N)` |
| Константа | `BitVecVal(0x10, 32)` |
| Логический сдвиг | `LShR(x, k)` |
| Ротация | `RotateLeft(x, k)` / `RotateRight(x, k)` |
| Расширение | `ZeroExt(k, x)` / `SignExt(k, x)` |
| Усечение | `Extract(hi, lo, x)` |
| Байт из слова | `Extract(7, 0, x)` |
| Сравнение беззнаковое | `ULT(a, b)` |
| Чтение/запись массива | `Select(A, i)` / `Store(A, i, v)` |
| Оптимизация | `Optimize()` + `maximize` |
| Инкрементальность | `s.push()` / `s.pop()` |
| Проверка | `s.check()` → `sat/unsat/unknown` |

## Что дальше / решение

Практический алгоритм: (1) найдите функцию проверки в дизассемблере; (2) выпишите условия и типы (ширина регистров, знаковость); (3) перенесите их в Z3 дословно, добавляя `ZeroExt`/`LShR`/`Rotate` по мере необходимости; (4) ограничьте диапазон печатными символами; (5) решите и **проверьте модель на бинаре**. Если решатель долго думает — упростите формулу и разбейте задачу. Дальше изучите символьное исполнение (angr/Triton), где Z3 применяется автоматически, и теорию массивов для моделирования памяти реальных алгоритмов.
