## Вопрос, с которого всё начинается

У тебя есть crackme. Ты открыл дизассемблер и видишь функцию `check`: она берёт твой пароль,
прогоняет его через десяток арифметических операций и сравнивает результат с константой. Читать
это глазами и подбирать пароль вручную — долго и муторно. Но эти операции — просто **уравнения**.
Значит, их можно решить.

Для этого есть **SMT-решатель** (Satisfiability Modulo Theories — «проверка выполнимости с учётом
теорий»). Самый популярный — **Z3** от Microsoft Research. Он принимает систему логических
формул и говорит: выполнима она или нет, а если выполнима — выдаёт конкретные значения переменных.
В этом уроке мы пройдём путь от дизассемблера до готового пароля.

## Наш пример

Соберём crackme с проверкой из нескольких условий. Пароль длиной 6, каждое условие — обычная
арифметика над байтами:

```c
static int check(const char *in){
    if (strlen(in) != 6) return 0;
    unsigned a=in[0],b=in[1],c=in[2],d=in[3],e=in[4],f=in[5];
    if (a*3 + b != 0x1a1) return 0;
    if (b + c   != 0x92)  return 0;
    if (c + d   != 0xc5)  return 0;
    if (d + e   != 0xda)  return 0;
    if (e + f   != 0xeb)  return 0;
    if (f       != 0x77)  return 0;
    return 1;
}
```

Проверим, что пароль `z3_ftw` подходит:

```
$ ./zcrackme z3_ftw
correct
$ ./zcrackme wrong
wrong
```

Задача: имея только бинарник, найти этот пароль.

## Шаг 1: выписываем уравнения из дизассемблера

Открываем `check` в `objdump` и смотрим, что она делает:

```
$ objdump -d -M intel zcrackme | sed -n '/<check>:/,/<main>:/p'
  40114e:  cmp    rax,0x6
  401152:  je     40115e
  4011c0:  mov    edx,DWORD PTR [rbp-0x18]     ; edx = a
  4011c5:  add    eax,eax                      ; eax = a+a
  4011c7:  add    edx,eax                      ; edx = a*3
  4011cc:  add    eax,edx                      ; + b
  4011ce:  cmp    eax,0x1a1
  4011d3:  je     4011dc
```

Читается однозначно: `a` умножают на 3 (сначала `add eax,eax` даёт `2a`, потом `add edx,eax` даёт
`3a`), прибавляют `b` и сравнивают с `0x1a1`. То же для остальных пар. У нас получилась система из
шести уравнений с шестью неизвестными — идеальный случай для Z3.

Важная деталь: компилятор использует **32-битные** регистры (`eax`, `edx`), хотя байты берутся из
строки. Значит, в модели переменные должны быть как минимум 32-битными, иначе сложение `a*3+b`
переполнится не там, где надо.

## Шаг 2: переводим уравнения в Z3

Модель — это те же уравнения, записанные на Python. Переменные объявляем как **битвекторы**
(`BitVec`) — значения фиксированной ширины с модульной арифметикой, как в регистрах:

```python
from z3 import *
a,b,c,d,e,f = [BitVec(x, 32) for x in "abcdef"]
s = Solver()
for v in (a,b,c,d,e,f):
    s.add(v >= 0x20, v <= 0x7e)          # печатные ASCII
s.add(a*3 + b == 0x1a1)
s.add(b + c   == 0x92)
s.add(c + d   == 0xc5)
s.add(d + e   == 0xda)
s.add(e + f   == 0xeb)
s.add(f       == 0x77)
print(s.check())
m = s.model()
print("password =", "".join(chr(m[v].as_long()) for v in (a,b,c,d,e,f)))
```

Запускаем:

```
$ python3 solve.py
sat
password = z3_ftw
```

`s.check()` вернул `sat` — решение есть. `s.model()` — конкретное присваивание, из которого мы
собрали строку. Три состояния `check()` важно различать: `sat` (есть решение), `unsat`
(противоречиво) и `unknown` (решатель не успел — это **не** доказательство отсутствия решения).

## Шаг 3: проверяем модель на настоящем бинарнике

Z3 не исполняет программу — он решает формулы. Если ты ошибся в модели, решатель молча вернёт
неверный ответ. Поэтому итог всегда проверяем на бинаре:

```
$ ./zcrackme "$(python3 -c "print('z3_ftw')")"
correct
```

Совпало — модель точна. Это правило номер один: **решатель проверяют на реальном исполнении**.

## Шаг 4: где модели ломаются — знаковость и ширина

Главные ошибки — неверная семантика операций. Разберём две самые частые.

**Сдвиг.** В Z3 оператор `>>` для битвектора — **арифметический** (сохраняет знак), а логический
сдвиг делается функцией `LShR`. Разница огромна:

```python
>>> simplify(BitVecVal(0xF0, 8) >> 2)
252
>>> simplify(LShR(BitVecVal(0xF0, 8), 2))
60
```

Если в дизассемблере видишь `shr` (логический) — пиши `LShR`, а не `>>`. Иначе для отрицательных
значений модель разойдётся с оригиналом.

**Ширина.** Смешивать 8- и 32-битные значения нельзя без явного расширения: `ZeroExt(k, x)`
дописывает `k` нулевых бит, `SignExt(k, x)` — знаковых. Если оригинал складывал байты в 32-битном
регистре, а ты сложил их как 8-битные, переполнение обрежется не там. Ровно это мы и учли в шаге 1.

Полезно и **байты из слова**: в памяти 4 байта лежат little-endian, поэтому младший байт — это
`Extract(7,0,x)`:

```python
>>> m.eval(Extract(7,0,y)).as_long()   # y == 0x41424344 -> 0x44 -> 'D'
68
```

## Шаг 5: когда условий больше, чем неизвестных

Иногда точных уравнений больше, чем переменных (данные избыточны). Тогда используют
**оптимизатор** `Optimize`: он ищет решение, нарушающее минимум «мягких» условий (`add_soft`), либо
максимизирует/минимизирует величину (`maximize`/`minimize`). Так ищут, например, самый короткий
пароль, удовлетворяющий проверке. Злоупотреблять им не стоит — `Optimize` заметно медленнее
обычного `Solver`.

Ещё два приёма для сложных задач: инкрементальный решатель (`s.push()` / `s.pop()`) — чтобы
переиспользовать общие ограничения для разных кандидатов, и тактики (`Then('simplify', ...)`) —
свой конвейер упрощения. Для самописной криптографии (ARX: сложение-вращение-XOR, как в TEA/XTEA)
раунды разворачивают в формулы: `a = (a + b) ^ k; b = RotateLeft(b, 7) + a` — и решают для нужного
выхода. Вращение в Z3 — это `RotateLeft(x, k)`.

Иногда проверка работает с таблицей подстановок (S-box). Её моделируют **теорией массивов**:
`Select(A, i)` — чтение по индексу, `Store(A, i, v)` — запись, возвращающая новый массив. Теория
мощная, но дорогая: на больших таблицах решатель может «зависнуть». Для таблицы из 256 байт чаще
выгоднее развернуть её в набор `If(i == k, v_k, ...)`, а не гонять массивы.

## Что мы теперь знаем

- Z3 — SMT-решатель: принимает систему формул, возвращает `sat`/`unsat`/`unknown` и конкретную модель.
- Переменные — `BitVec('x', N)`; арифметика модульная, как в регистрах.
- Уравнения берут прямо из дизассемблера `check`, сверяя ширину регистров.
- `>>` — арифметический сдвиг, логический — `LShR`; расширять надо `ZeroExt`/`SignExt`.
- Диапазон печатных символов ограничивают явно, иначе решатель вернёт мусорные байты.
- Модель **обязательно** проверяют на реальном бинарнике.

## Куда дальше

Мы вручную перевели проверку в уравнения и решили её. Но в реальных задачах условий бывают сотни,
а функция `check` — с циклами и ветвлениями. В следующем уроке мы посмотрим на **символьное
исполнение** (angr/Triton): там Z3 применяется автоматически, а за тебя код исполняется «по всем
веткам сразу». А пока главное запомни: дизассемблер даёт уравнения, Z3 их решает, бинарник
подтверждает ответ.

## Где пригодится

- **CTF Reversing:** keygen'ы и crackme с арифметической проверкой пароля.
- **Cryptanalysis:** восстановление ключа по известным парам открытый/зашифрованный текст.
- **Автоматизация:** генерация валидных лицензионных ключей, обход проверок.
