## Вопрос, с которого всё начинается

Мы нашли в бинарнике функцию `check`, которая что-то сравнивает. В дизассемблере виден вызов
`strcmp` — но в реальной задаче имя может быть потеряно, а функций-кандидатов десятки. Как
инструмент помогает не просто «прочитать ассемблер», а **быстро понять смысл** и
**автоматизировать** рутину?

IDA Pro — индустриальный стандарт реверса. Её сила не только в дизассемблере, но в экосистеме:
библиотека сигнатур **FLIRT** распознаёт функции стандартных библиотек, декомпилятор **Hex-Rays**
даёт лучший псевдо-C в индустрии, а **IDAPython** автоматизирует почти всё. Разберём это на том же
crackme, что и в прошлом уроке.

Опираемся на предыдущий урок про Ghidra: там мы автоматизировали поиск проверки скриптом. Здесь —
та же цель, но инструментами IDA.

## Наш пример

Посмотрим на функцию `check` глазами дизассемблера (здесь — `objdump`; IDA показывает то же
самое, только интерактивно):

```
$ objdump -d --no-show-raw-insn -M intel crackme | sed -n '/<check>:/,/^$/p'
0000000000401136 <check>:
  401136:  push   rbp
  401137:  mov    rbp,rsp
  40113e:  mov    QWORD PTR [rbp-0x8],rdi     ; rdi = аргумент s
  401142:  lea    rdx,[rip+0xebb]             ; rdx = адрес строки 0x402004
  401150:  mov    rdi,rax
  401153:  call   401040 <strcmp@plt>         ; strcmp(s, "s3cr3t!")
  401158:  test   eax,eax
  40115a:  sete   al                          ; al = (eax == 0)
  401161:  ret
```

Здесь ключевой факт: `call strcmp@plt`. Функция возвращает результат сравнения строки-аргумента
с константой по адресу `0x402004`. Вопрос: как узнать, что это `strcmp`, а не случайная функция,
и как быстро восстановить полный смысл?

## Шаг 1: FLIRT — почему IDA «узнаёт» библиотечные функции

Когда бинарник статически слинкован, внутри него лежит вся стандартная библиотека. Реверсить её
вручную — часы впустую. **FLIRT** (Fast Library Identification and Recognition Technology) —
это база **сигнатур**: коротких байтовых «отпечатков» библиотечных функций. IDA сверяет с ними
код и автоматически помечает функции именами `printf`, `memcpy`, `strcmp` и т.д.

```
File → Load file → FLIRT signature file...   (или авто из папки sig/)
```

Для статически слинкованного с libc бинарника примените `libc64.sig` — и `sub_401230` превратится
в `strcmp`. Для Windows — сигнатуры `vc6`, `vc7`, `mssdk`. Без FLIRT вы будете реверсить
стандартную библиотеку, которая вам не нужна.

## Шаг 2: Hex-Rays и типы — превращаем ассемблер в псевдо-C

Нажми `F5` — и IDA декомпилирует функцию в псевдо-C через **Hex-Rays**. Для нашего `check`
это даст примерно то, что мы уже видели в Ghidra:

```c
bool check(char *s) {
    return strcmp(s, "s3cr3t!") == 0;
}
```

Качество псевдо-C на 80% зависит от **типов**. Пока прототипы не заданы, вы видите
`sub_401230(a1, a2)`. Ключевые действия:

- `Y` на функции — задать прототип, например `int check_license(char *buf, size_t len)`.
- `Shift+F9 → Local Types → Insert` — создать свою структуру и «скомпилировать» её в базу типов:

```c
struct header {
    uint32_t magic;
    uint16_t len;
    uint8_t  data[0x100];
};
```

После `Y` на переменной с типом `header*` декомпилятор покажет `hdr->len` вместо
`*(int *)(param + 4)`. Для Windows подключите библиотеку типов `mssdk` (`Shift+F11`) — и
появятся `PEPROCESS`, `IRP`, `_CONTEXT`. Ещё точнее — загрузить PDB (`File → Load file → PDB file`).

Правило: **каждое переименование и каждый тип делают следующую декомпиляцию чище.** IDA «учится»
на вашей разметке.

## Шаг 3: IDAPython — автоматизируем поиск

IDAPython выполняется в консоли IDA или скриптом (`File → Script file`, `Alt+F7`). В IDA 7+
модули называются `ida_*` (`ida_bytes`, `ida_funcs`, `ida_hexrays`, `ida_xref`) плюс совместимые
`idc`/`idautils`.

Найти все ссылки на строку, содержащую «flag»:

```python
import idautils
for s in idautils.Strings():
    if "flag" in str(s).lower():
        print("0x%x  %s" % (s.ea, str(s)))
        for xref in idautils.XrefsTo(s.ea):
            print("    from 0x%x" % xref.frm)
```

Найти все функции, вызывающие `system` (то же, что мы делали для `strcmp` в Ghidra):

```python
import idautils, idc
system_ea = idc.get_name_ea_simple("system")
for xref in idautils.XrefsTo(system_ea):
    print("system called in %s @ 0x%x" % (idc.get_func_name(xref.frm), xref.frm))
```

И даже залезть в **AST** декомпилированного кода — основа для автодеобфускаторов:

```python
import ida_hexrays, ida_funcs
f = ida_funcs.get_func(0x401136)
cf = ida_hexrays.decompile(f.start_ea)
print(cf)                              # псевдо-C
for item in cf.treeitems:              # обход дерева
    if "strcmp" in item.print1(None):
        print("strcmp @ 0x%x" % item.ea)
```

| Действие | GUI | IDAPython |
|---|---|---|
| Декомпилировать | `F5` | `ida_hexrays.decompile(ea)` |
| Xrefs к адресу | `X` | `idautils.XrefsTo(ea)` |
| Переименовать | `N` | `idc.set_name(ea, "n")` |
| Задать тип | `Y` | `idc.SetType(ea, "int")` |
| Строки | `Shift+F12` | `idautils.Strings()` |
| Функции | `Ctrl+P` | `idautils.Functions()` |

## Шаг 4: микрокод и плагины

Между листингом и псевдо-C Hex-Rays использует **микрокод** — промежуточное представление из
базовых блоков и инструкций над виртуальными регистрами. Туда лезут, когда нужно:

- **оптимизировать декомпиляцию** — плагины переписывают микрокод, убирая мусор обфускации;
- **делать кастомный анализ** — taint, поиск паттернов на уровне IR;
- **деобфусцировать control-flow** — восстановить «сплющенный» поток управления.

Полезные плагины: **Keypatch** (патчинг инструкций прямо в листинге), **FindCrypt**
(крипто-константы), **HexRaysPyTools** (реконструкция структур), **Diaphora** (диффинг двух
версий бинарника — прямой путь к патчу уязвимости), **ret-sync** (синхронизация с gdb/x64dbg).

## Что мы теперь знаем

- **FLIRT** мгновенно опознаёт библиотечные функции в статически слинкованном коде — не реверси
  libc вручную.
- **Hex-Rays** (`F5`) декомпилирует функцию в псевдо-C, а **типы** (`Y`, `Shift+F9`, `Shift+F11`)
  делают его читаемым.
- **IDAPython** (`idautils`, `idc`, `ida_hexrays`) автоматизирует поиск xref, переименование,
  декомпиляцию и обход AST.
- **Микрокод** — IR под декомпилятором; там живут деобфускаторы и кастомные анализы.
- Всё разметка хранится в базе `.idb`/`.i64` — не потеряй её.

## На что смотреть дальше

- Не применяй FLIRT на статических бинарниках — потеряешь часы на реверс стандартной библиотеки.
- Не верь Hex-Rays на 100%: на косвенных вызовах, `longjmp` и inline asm он ошибается — сверяйся
  с листингом.
- Не путай `X` (все xrefs) и `Enter` (переход по одной ссылке).
- IDA 7+ перешла на модули `ida_*`; старый `idc` живёт лишь частично — проверяй API своей версии.
- Отладку malware делай только в изоляции (VM) — отладчик запускает код.

## Куда дальше

Мы разобрали два флагманских декомпилятора — Ghidra и IDA. Дальше возьмём бинарник, собранный на
Rust или Go, где компилятор оставляет после себя нестандартные артефакты, и посмотрим, как
меняется тактика реверса. А пока главное запомни: **IDA — это не только F5, но и FLIRT, типы и
IDAPython**, и автоматизация отличает профессионала от новичка.

## Где пригодится

- **CTF Reversing:** быстрый разбор через декомпилятор и распознавание библиотек.
- **Malware analysis:** восстановление типов структур (PEB, контексты), анализ API-вызовов.
- **Vuln research:** поиск уязвимых паттернов, автоматизация через IDAPython/Hex-Rays AST.
- **Работа (RE-команда):** IDA — стандарт в enterprise и malware-лабораториях.
- **Собес:** FLIRT, Hex-Rays microcode, IDAPython — маркеры профессионального уровня.
