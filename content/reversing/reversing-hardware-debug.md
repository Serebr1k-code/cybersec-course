Физический доступ к устройству открывает интерфейсы, недоступные по сети: **UART** (серийная консоль, часто даёт root shell или доступ к bootloader'у), **JTAG/SWD** (аппаратная отладка с пошаговым исполнением и дампом памяти), **SPI/I2C** (шины к микросхеме прошивки и периферии). Через них извлекают прошивку, получают shell, отлаживают ядро и обходят программные защиты. Этот урок — практические шаги hardware-реверса от поиска пинов до дампа flash и работы с U-Boot.

## Зачем физический доступ

Программные защиты (аутентификация, шифрование трафика) обходятся «снизу»:

- **Извлечение прошивки** для анализа — SPI-дамп даёт полный образ (см. `reversing-firmware`).
- **Root shell** через UART-консоль обходит веб-интерфейс и сетевые ограничения.
- **Отладка** через JTAG/SWD позволяет ставить breakpoints, читать память и обходить проверки.
- **Восстановление** «окирпиченных» устройств через запись полного дампа.

## Интерфейсы: сравнение

| Интерфейс | Пины | Что даёт | Инструмент |
|-----------|------|----------|------------|
| UART | TX, RX, GND, (VCC) | консоль, bootloader, shell | USB-UART (CP2102, FT232) |
| JTAG | TCK, TMS, TDI, TDO (+GND, VCC, TRST, SRST) | полная отладка | OpenOCD, J-Link, BMP |
| SWD | SWDIO, SWCLK (+GND, VCC) | отладка ARM | OpenOCD, J-Link, BMP |
| SPI | CLK, MOSI, MISO, CS, VCC, GND | дамп/запись flash | CH341A, Bus Pirate |
| I2C | SDA, SCL | EEPROM, периферия | Bus Pirate, логический анализатор |

## Поиск и идентификация UART

```text
1) Найти тестовые площадки (4 пина: VCC/GND/TX/RX) или разъём.
2) Мультиметром найти GND (звонкость с землёй/экраном) и VCC (3.3V/5V).
3) Логическим анализатором/осциллографом найти TX (данные при загрузке).
4) Подключиться USB-UART (TX->RX, RX->TX, GND-GND).
5) Поймать бутлог (baud: 115200/57600/9600).
```

Практические детали: GND прозванивается с металлическими частями и «землёй» — определите его первым. VCC — пин со стабильным 3.3/5 В относительно GND. TX «активен» при включении: на нём видны всплески (данные бутлога). Если не уверены, где TX/RX, попробуйте оба варианта — перепутывание TX/RX не вредит, только нет данных.

## Подключение и работа с консолью

```bash
# Подключение (115200 8N1 — самый частый baud)
picocom -b 115200 /dev/ttyUSB0
# или
screen /dev/ttyUSB0 115200
# или
minicom -D /dev/ttyUSB0 -b 115200
```

Частые baud: `115200`, `57600`, `38400`, `9600`. Что видно в бутлоге: U-Boot, kernel log, login-промпт. Если попали в U-Boot:

```text
# прервать автозагрузку (часто пробелом/клавишей)
U-Boot> help
U-Boot> printenv
U-Boot> md 0x80000000 0x100          # memory display
U-Boot> setenv bootargs console=ttyS0,115200 init=/bin/sh
U-Boot> boot
```

Модификация `bootargs` (например, `init=/bin/sh` или `single`) — классический путь к root shell. Если виден login — попробуйте дефолтные (root/root, admin/admin) или известные эксплойты прошивки.

## JTAG/SWD и OpenOCD

**SWD** (2 провода, SWDIO/SWCLK) — современная отладка ARM; **JTAG** (4+ проводов) — универсальный стандарт.

```bash
# OpenOCD: подключение к цели
openocd -f interface/ftdi/jtagkey.cfg -f target/stm32f1x.cfg
# В другом терминале — telnet-консоль
telnet localhost 4444
> halt
> reg
> dump_image firmware.bin 0x08000000 0x10000     # дамп флеша
> flash read_bank 0 dump.bin
> step
> resume
```

Инструменты: **OpenOCD** (софт), **J-Link** (аппарат), **Black Magic Probe** (SWD/JTAG, удобен в поле). Для ARM Cortex-M отладочный интерфейс часто залочен (RDP/readout protection) — иногда обходится понижением уровня защиты или glitch-атакой.

## SPI flash: дамп прошивки

```bash
# Определить чип по маркировке (напр. W25Q64) и подключить программатор
flashrom -p ch341a_spi -r firmware.bin
# Стабильность: прочитать дважды и сравнить
flashrom -p ch341a_spi -r f1.bin
flashrom -p ch341a_spi -r f2.bin
cmp f1.bin f2.bin          # должны совпасть (или diff <(xxd f1.bin) <(xxd f2.bin))
```

Важно: читайте при **отключённом питании** (или с clip-on), чтобы CPU не мешал шине; согласуйте напряжения (3.3 В!). При включённом CPU возможны конфликты и «плавающий» дамп. Если flash в схеме «мешает», применяют метод **SPI-отключения** (замыкание CS на GND / снятие чипа) или читают через clip.

## I2C/EEPROM

```bash
# Bus Pirate / i2c-tools
i2cdetect -y 1               # сканирование устройств на шине
i2cdump -y 1 0x50            # дамп EEPROM по адресу 0x50
i2cget -y 1 0x50 0x00        # чтение байта
```

I2C используется для EEPROM (серийники, ключи), датчиков, иногда конфигурации. Дамп EEPROM может содержать ключи шифрования или пароли.

## Разобранный пример: UART -> shell -> дамп flash

```text
1) Найти 4 пина; мультиметром определить GND (звонкость) и VCC (3.3V).
2) Оставшиеся два — TX/RX; подключить USB-UART (TX->RX, RX->TX, GND-GND).
3) picocom -b 115200 /dev/ttyUSB0; поймать бутлог.
4) Увидеть U-Boot: прервать автозагрузку, printenv, md (читать память).
5) setenv bootargs ... init=/bin/sh; boot -> root shell.
6) Снять дамп SPI: flashrom -p ch341a_spi -r firmware.bin (или dd из /dev/mtd0 на устройстве).
7) Проанализировать прошивку (binwalk -eM) -> найти файлы/конфиги/ключи.
```

Если U-Boot не даёт shell, но даёт login — пробуем дефолты или эксплойт веб-интерфейса для получения доступа, затем `dd if=/dev/mtd0 of=/tmp/dump.bin` и выгрузку по сети.

## Инструменты

| Инструмент | Назначение |
|------------|------------|
| USB-UART (CP2102/FT232/CH340) | подключение к UART-консоли |
| CH341A / Bus Pirate | дамп SPI/I2C flash/EEPROM |
| FT2232H / J-Link / Black Magic Probe | JTAG/SWD-отладка |
| OpenOCD | софт для JTAG/SWD |
| Логический анализатор (Saleae, sigrok) | поиск TX, разбор шин |
| Мультиметр | GND/VCC, прозвонка |
| `flashrom`, `picocom`, `minicom`, `i2c-tools` | софт |

## Безопасность и типичные поломки

- **Напряжение.** 5 В на 3.3 В-линии сжигает устройство; всегда проверяйте уровень (level shifter при необходимости).
- **GND обязателен.** Без общей земли сигналы «плавают», можно повредить входы.
- **Не пишите в flash без нужды.** Ошибка записи «окирпичивает» устройство; сначала сделайте и проверьте полный дамп.
- **Питание при дампе.** Отключайте питание цели при чтении SPI (clip-on), чтобы CPU не конфликтовал с программатором.
- **ESD.** Работайте с антистатикой.

## Логический анализ шин

Для поиска UART и разбора нестандартных шин незаменим логический анализатор:

```bash
# sigrok/PulseView: захват сигналов, декодирование протоколов
sigrok-cli -d fx2lafw --config samplerate=1m --time 5 -o capture.sr
sigrok-cli -i capture.sr -P uart:baudrate=115200,rx=D0
```

Анализатор показывает, какой пин «активен» при загрузке (TX), и декодирует UART/SPI/I2C. Это точнее, чем «перебор пинов», и позволяет восстановить baud и разметку шины.

## Частые ошибки

- **Неверное напряжение.** 5 В на 3.3 В-пине сжигает устройство.
- **Перепутать TX/RX.** Соединяйте TX->RX, RX->TX (не вредит, но нет данных).
- **Нет общего GND.** Обязательно соедините землю.
- **Чтение SPI при включённом CPU.** Конфликты шины; отключите питание.
- **Нестабильный дамп.** Читайте несколько раз и сравнивайте (`cmp`).
- **Брик.** Не пишите в flash без необходимости и бэкапа.
- **Неверный baud.** Пробуйте 115200/57600/9600 — «мусор» в консоли означает несовпадение.

## Безопасное чтение и обход защит

- **Read-out protection (RDP) на STM32.** Уровень 1 блокирует отладочный доступ; иногда обходится понижением уровня (стирает flash) или glitch-атакой. Уровень 2 — необратим.
- **Secure boot / подписанная прошивка.** Загрузчик проверяет подпись; UART-консоль может дать shell, но не позволит загрузить модифицированную прошивку — нужен обход проверки или уязвимость.
- **SPI в схеме.** Если флеш припаяна, читайте clip-on'ом при отключённом питании; при конфликтах — снимайте чип (hot-air) или замыкайте CS на GND.
- **Bootloader-пароли.** Некоторые U-Boot имеют `bootdelay`/пароль; обходится сбросом env (замыкание пина при старте) или перепрошивкой загрузчика.
- **Логирование.** Записывайте все команды и дампы: это доказательство для отчёта и основа для воспроизведения.

## Что делать дальше / решение

1. Осмотрите плату: найдите тестовые площадки (UART) и чип flash (маркировка).
2. Мультиметром определите GND/VCC, подключите USB-UART, поймайте бутлог.
3. Если есть U-Boot/login — получите shell (bootargs/дефолты/эксплойт).
4. Снимите дамп flash (`flashrom` или `dd` из MTD), проверьте стабильность (`cmp`).
5. При наличии JTAG/SWD — подключите OpenOCD, дампните память, отлаживайте.
6. Проанализируйте прошивку (`binwalk -eM`), извлеките конфиги/ключи/бинарники.
