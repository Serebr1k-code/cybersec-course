## Вопрос, с которого всё начинается

В прошлом уроке мы патчили один байт hex-редактором. Но что если правок десятки, или нужно автоматически пропатчить сотню файлов, или найти инструкцию не по смещению, а по секции? Ручной hex тут не масштабируется. Нужна библиотека, которая понимает структуру ELF/PE/Mach-O и позволяет менять её из кода. Это **LIEF**.

## Наш пример

Возьмём тот же `gate` и разберём его из Python:

```python
import lief
b = lief.parse('gate')
print("format:", b.format)
print("entry:", hex(b.entrypoint))
```

```text
format: FORMATS.ELF
entry: 0x1040
```

`lief.parse` сам определил формат (ELF), отдал объект с заголовком, секциями и символами. Одна строка — и у нас структурированный доступ ко всему файлу. С этого начинается любой скрипт на LIEF.

## Шаг 1: читаем структуру

LIEF даёт секции, импорты и символы без ручного парсинга заголовков:

```python
for s in b.sections:
    print(s.name, hex(s.virtual_address), s.size)
```

```text
.note.gnu.build-id 0x350 36
.interp 0x374 28
.gnu.hash 0x390 28
.dynsym 0x3b0 168
...
```

Импорты и символы:

```python
for f in b.imported_functions:
    print(f)
```

```text
__libc_start_main (0x0000 bytes)
puts (0x0000 bytes)
__cxa_finalize (0x0000 bytes)
```

Всё то, что мы вручную доставали `readelf`-ом, доступно как объекты Python. Это удобно для автоматизации: перебрать файлы, собрать статистику, найти нужные функции.

## Шаг 2: находим и патчим код

Ключевая возможность LIEF — **модификация**. Найдём секцию `.text`, в ней — наши байты `75 16` (`jne`), и заменим на `90 90` (`nop`):

```python
sec = b.get_section('.text')
print(".text va:", hex(sec.virtual_address), "offset:", hex(sec.file_offset))
data = bytearray(sec.content)
i = bytes(data).find(bytes.fromhex('7516'))
print("jne at section offset", hex(i), "-> vaddr", hex(sec.virtual_address + i))
data[i:i+2] = b'\x90\x90'
sec.content = list(data)
b.write('gate_lief_patched')
```

```text
.text va: 0x1040 size: 332 offset: 0x1040
jne at section offset 0x11e -> vaddr 0x115e
wrote gate_lief_patched
```

Проверяем результат:

```bash
$ chmod +x gate_lief_patched
$ ./gate_lief_patched n
Access granted
```

Патч применился, и мы получили его **скриптом**, а не руками. Обрати внимание на важный момент: LIEF сам пересчитал смещения и записал корректный файл — нам не пришлось вручную считать `vaddr - section_vaddr + offset`.

## Шаг 3: почему это удобнее hex-редактора

- **Работа на уровне секций/символов** — не нужно помнить смещения, ищешь по имени.
- **Кросформатность** — один и тот же код для ELF, PE и Mach-O (LIEF абстрагирует различия).
- **Автоматизация** — можно пропатчить сотни файлов циклом.
- **Проверки** — LIEF валидирует структуру и корректно пересобирает заголовки.

Пример кросформатности: `b.format` вернёт `FORMATS.ELF`, `FORMATS.PE` или `FORMATS.MACHO`, а работа с секциями одинакова. Это удобно для инструментов, поддерживающих все три платформы.

## Шаг 4: что ещё умеет LIEF

- **Импорты/экспорт** — читать и **добавлять** (инъекция своей библиотеки в PE/ELF).
- **Секции** — добавлять, удалять, менять содержимое.
- **Символы и релокации** — читать и перестраивать.
- **Подписи** — снимать подписи (полезно при анализе подписанного малвари).
- **Инъекция кода** — добавлять новый код в исполняемую секцию (техника используется и в эксплойтах).

Именно поэтому LIEF любят в malware research и tooling: разбор и модификация любых исполняемых форматов из одного API.

## Шаг 5: патч в контексте анализа

Патчинг через LIEF встраивается в конвейер:

1. **Разобрать** — `lief.parse`, найти секцию/функцию.
2. **Прочитать** — дизассемблировать нужный участок (capstone).
3. **Решить, что менять** — как в уроке про патчинг (NOP/инверсия/jmp).
4. **Пропатчить** — изменить байты через LIEF и записать файл.
5. **Проверить** — запустить и убедиться в новом поведении.

В отличие от ручного патча, шаги 1–4 легко автоматизировать: например, скрипт, который находит все проверки по сигнатуре и нейтрализует их.

## Шаг 6: на что смотреть дальше

- **Смещения** — всегда проверяй `sec.file_offset` vs `virtual_address`; не путай их.
- **Пересборка** — после записи проверь, что файл всё ещё исполняется (некоторые изменения ломают заголовки).
- **Подписи** — на подписанных PE/Mach-O патч сломает подпись; это ожидаемо.
- **Установка** — `pip install lief`; библиотека кроссплатформенная.

Начни с чтения (`parse`, секции, импорты) — это уже полезно. Патч — следующий шаг, когда понятно, что менять.

## Шаг 7: инъекция и снятие подписи

LIEF умеет не только читать и патчить байты. Две возможности, полезные в research:

**Добавление импорта.** Можно заставить PE/ELF импортировать твою библиотеку — техника, известная как DLL-hijack/injection:

```python
b.add_library('mylib.dll')          # PE
b.write('hijacked.exe')
```

**Инъекция кода в секцию.** Добавить новый код в исполняемую секцию и перенаправить точку входа — базовый приём для инструментов и эксплойтов:

```python
section = lief.ELF.Section('.inj')
section.content = list(b'\x90' * 16)
b.add(section, loaded=True)
```

**Снятие подписи.** У подписанных PE/Mach-O `lief.parse` может убрать подпись (`b.remove_signature()`), что удобно при анализе подписанной малвари: файл перестаёт проверяться системой как «подписанный», и его можно изучать.

Эти функции требуют аккуратности: некорректная инъекция ломает файл. Поэтому после любой правки — проверяй, что бинарник запускается.

## Шаг 8: полный скрипт патча

Соберём всё в один рабочий скрипт — типичный инструмент реверсера:

```python
import lief
def nop_jump(path, section_name, pattern):
    b = lief.parse(path)
    sec = b.get_section(section_name)
    data = bytearray(sec.content)
    i = bytes(data).find(bytes.fromhex(pattern))
    if i < 0:
        return False
    data[i:i+len(pattern)] = b'\x90' * len(pattern)
    sec.content = list(data)
    b.write(path + '.patched')
    return True

nop_jump('gate', '.text', '7516')
```

Такой скрипт можно запускать на десятках файлов: найти сигнатуру проверки и нейтрализовать её массово. Это и есть автоматизация, ради которой LIEF и существует.

## Что мы теперь знаем

- **LIEF** — Python-библиотека для разбора и модификации ELF/PE/Mach-O.
- `lief.parse` даёт доступ к заголовку, секциям, импортам, символам как к объектам.
- Секцию можно найти по имени, изменить её байты и записать файл — LIEF пересчитает структуру.
- Один API покрывает все три формата; это удобно для инструментов и автоматизации.
- LIEF умеет и больше: инъекция библиотек/кода, снятие подписей, правка символов.

## Куда дальше

Мы научились патчить и разбирать файлы программно. Но современные бинарники часто **защищены**: пакеры, анти-отладка, проверки целостности. Как их распознавать и обходить — в следующих уроках про anti-debug и anti-tamper. А пока запомни: `lief.parse` для чтения, `sec.content` для правки, `b.write` для сохранения.

## Частые вопросы

- **LIEF не находит секцию** — проверь точное имя (`.text`, `.rdata`); у PE имена другие.
- **Файл после записи не запускается** — проверь, что менял `content` корректно и не сломал заголовки.
- **Нужно патчить PE/Mach-O, а не ELF** — код тот же, меняется только имя секции; `b.format` подскажет.
- **Нужна установка** — `pip install lief`; библиотека кроссплатформенная.
- **Нужен разбор без записи** — LIEF умеет работать «только для чтения»: парсишь и анализируешь, не сохраняя изменения.

Практический совет: начинай с чтения (`parse`, перебор секций и импортов) — это безопасно и уже даёт много информации. К записи файла переходи, только когда точно понял, что и зачем меняешь.
