## Вопрос, с которого всё начинается

У тебя есть файл `loader` — небольшой ELF-бинарник, который, судя по всему, «звонит домой» на неизвестный адрес. Жёстко прописанного домена в строках нет. Как бот находит свой C2, и как это заблокировать?

## Наш пример

Смотрим на файл:

```
$ file loader
loader: ELF 64-bit LSB executable, x86-64, statically linked
```

Статически слинкованный ELF — типично для ботнет-загрузчиков: меньше зависимостей, проще запуск на чужой машине. Разберём, как он ищет управляющий сервер.

## Шаг 1: зачем ботнету DGA

Если в малвари прописать один домен C2, защита его быстро заблокирует, и ботнет умрёт. Поэтому операторы используют **DGA** — Domain Generation Algorithm: бот и оператор знают общий секрет (**seed**), и каждый день вычисляют один и тот же список доменов. Бот пробует их по очереди, пока не найдёт живой C2.

Свойство DGA: домены выглядят случайными (`xkfqweoirp.com`), их много (десятки тысяч), но они **детерминированы** — зная seed и алгоритм, ты можешь сгенерировать их сам.

## Шаг 2: находим seed

Seed — это вход алгоритма. Он может быть зашит константой или вычисляться из даты:

```
$ strings -n 5 loader | head
DGA v3
seed=2024-01-01
domain list
nto{dga_s33d_r3c0v3r}
```

Строка `seed=2024-01-01` — прямой ключ. Часто seed берут из текущей даты (`time()`), из версии ОС, из данных жертвы. Тогда алгоритм надо реконструировать из кода.

## Шаг 3: восстанавливаем алгоритм

Классическая DGA на C выглядит так:

```
for i in 0..N:
    srand(seed + i)
    domain = ""
    for j in 0..12:
        domain += 'a' + (rand() % 26)
    domain += ".com"
```

Здесь `srand(seed + i)` инициализирует генератор, `rand()%26` даёт букву. Твоя задача — вытащить константы (длина домена, TLD, число доменов) и реализовать алгоритм на Python.

## Шаг 4: генерируем домены

Реализовав DGA, ты получаешь список всех возможных C2 на сегодня:

```
$ python3 dga.py
xkfqweoirp.com
mznvbaqwer.com
...
```

Этот список отдают в защиту: DNS-sinkhole, блок-листы, ретро-хантинг по логам DNS. Если хоть один домен уже встречался в логах — есть следы заражения.

## Шаг 5: определяем C2-протокол

Найдя домен, бот шлёт запрос. Протокол часто замаскирован под обычный HTTP или DNS. Признаки: `GET /`, необычные User-Agent, кодированные параметры. Иногда используется DNS-туннель: данные кодируются в поддомены (`<hex>.c2.example`), что позволяет проходить фильтры.

## Шаг 6: загрузчик и полезная нагрузка

Botnet-loader обычно не содержит всей малвари — он скачивает основной модуль с C2 и запускает. Поэтому анализ делится: сначала loader (как находит C2), потом пейлоад (что делает). Признаки загрузки: сетевые вызовы + запись файла + `execve`/`CreateProcess`.

## Что мы теперь знаем

- DGA детерминированно генерирует домены C2 из seed.
- Seed бывает константой или вычисляется (дата, версия ОС).
- Алгоритм реконструируется по коду и реализуется на Python.
- Список доменов идёт в блок-листы и ретро-хантинг.
- C2-протокол может маскироваться под HTTP или DNS-туннель.

## Где пригодится

- **Threat intel:** отслеживание ботнет-кампаний.

- **IR:** определение C2 при инциденте.
