## Вопрос, с которого всё начинается

На CTF дали бинарник `chall` и сказали: «найди флаг». Время ограничено, а инструментов десятки.
С чего начать? Опытные решатели не перебирают инструменты случайно — они **классифицируют задачу**
и применяют подходящий рецепт. Этот урок — компиляция методик из всех предыдущих тем в практический
чек-лист, который экономит время на соревнованиях.

Опираемся на всё, что прошли: `file`/`strings`, дизассемблер, keygen, эмуляцию. Здесь соберём это в
системный алгоритм и прогоним на реальной задаче.

## Наш пример

Задача: ELF `chall`, просит флаг. Первым делом — **триаж** (быстрый осмотр):

```
$ file chall
chall: ELF 64-bit LSB executable, x86-64, dynamically linked, ..., not stripped
$ strings -a -n 6 chall | grep -iE 'flag|correct|wrong|usage'
usage: chall <flag>
Correct!
Wrong!
$ ./chall test
Wrong!
```

За две минуты мы узнали: это 64-битный ELF, не упакован, не обфусцирован, и у него есть ветки
`Correct!`/`Wrong!`. Это **flag checker** — классический тип. Дальше идём по рецепту.

## Шаг 1: классификация задачи

Тип задачи диктует инструмент. Основные типы:

- **Crackme/Keygenme** — просит пароль/серийник; цель — найти или сгенерировать.
- **Flag checker** — вводится флаг, программа проверяет; цель — восстановить флаг (наш случай).
- **Anti-debug** — проверки мешают отладке; цель — обойти и найти флаг.
- **Packed/Obfuscated** — код скрыт (UPX, VM, MBA); цель — распаковать/деобфусцировать.
- **VM-based** — собственная виртуальная машина; цель — понять её байткод.
- **Crypto** — проверка на криптографии; цель — восстановить ключ/алгоритм.
- **Custom format** — нестандартный контейнер; цель — распарсить.
- **Emulation** — бинарник под другую архитектуру (ARM/MIPS); цель — запустить/эмулировать.

Неправильная классификация — главная потеря времени. Наш `chall` — flag checker, значит рецепт:
найти проверку и обратить её.

## Шаг 2: чек-лист триажа

Быстрая последовательность (5–10 минут):

1. **`file`** — что это (ELF/PE/Mach-O/.pyc/.NET/Java/архив).
2. **`strings -a -n 6`** — ищи `flag`, `CTF{`, подсказки, URL.
3. **`checksec`** — защиты (RELRO, NX, PIE, canary) — важно для pwn-аспектов.
4. **Запуск** — что программа делает и просит.
5. **`rabin2 -I` / DIE** — упакована ли, какая архитектура.
6. **Дизассемблер** (Ghidra/IDA/r2) — найти `main` и проверку.
7. **Строки вокруг проверки** — `"Correct"`, `"Wrong"`, сравнения.

Если на шаге 2 виден флаг — задача решена. Иначе переходим к рецептам.

## Шаг 3: рецепты по типам

| Тип | Рецепт |
|---|---|
| Crackme с `strcmp` | breakpoint на `strcmp`, смотреть аргументы; или декомпилировать |
| Flag checker посимвольно | символическое исполнение (angr) или перебор по байту |
| Anti-debug | ScyllaHide/патчи, найти проверку (`ptrace`), обойти через регистры |
| Packed (UPX) | `upx -d`; кастомный — найти OEP через watchpoint, снять дамп |
| VM-based | восстановить опкоды или написать интерпретатор байткода |
| Crypto | определить алгоритм (S-box, RC4), восстановить ключ |
| Custom format | `binwalk`, hex-разбор, парсер на Python |
| Другая архитектура | Qiling/Unicorn или `qemu-user` |

## Шаг 4: полный прогон — от триажа до флага

Продолжаем нашу задачу. Декомпилируем проверку — она сравнивает вход, применив XOR:

```c
static const unsigned char T[15] = { 0x50,0x47,0x55,0x68,0x6b,0x23,0x61,0x4c,
                                     0x22,0x60,0x4c,0x75,0x66,0x7d,0x6e };

int check(char *s) {
    if (strlen(s) != 15) return 0;
    for (int i = 0; i < 15; i++)
        if ((s[i] ^ 0x13) != T[i]) return 0;   // XOR-маска 0x13
    return 1;
}
```

Таблица `T` лежит в секции `.rodata` — её видно прямо в дампе:

```
$ objdump -s -j .rodata chall | sed -n '4,5p'
 402000 01000200 00000000 50475568 6b23614c  ........PGUhk#aL
```

Байты `50 47 55 68 6b 23 61 4c ...` — это и есть `T`. XOR обратим, поэтому флаг восстанавливается
одной строкой Python:

```
$ python3 -c "print(''.join(chr(b^0x13) for b in [0x50,0x47,0x55,0x68,0x6b,0x23,0x61,0x4c,0x22,0x60,0x4c,0x75,0x66,0x7d,0x6e]))"
CTF{x0r_1s_fun}
$ ./chall 'CTF{x0r_1s_fun}'
Correct!
```

Задача решена за пару минут — благодаря методичному триажу, а не перебору инструментов.

## Шаг 5: автоматизация и тайм-менеджмент

Для повторяющихся задач пиши скрипты и храни их как артефакты («одно оружие, много выстрелов»):
keygen из `strcmp`, брутфорс посимвольной проверки, извлечение констант из `.rodata`,
интерпретатор VM-байткода. В следующий раз используешь готовое.

Правила на соревновании:

- **Триаж за 5 минут** — определи тип и сложность; если задача «не твоя» (например, VM) — отложи.
- **Тайм-бокс 20–30 минут** на подход; нет прогресса — смени рецепт или задачу.
- **Параллельность**: длительные операции (angr, брутфорс, распаковка) — в фон.
- **Документируй**: адреса, пароли, найденные строки — не полагайся на память.
- **Проверяй флаг** на формат `CTF{...}` — не гонись за «похожим на флаг» без проверки.

Комбинируй методы: статика подсказывает, где искать, динамика подтверждает поведение, символика
(angr) решает то, что не поддаётся руками. Сохраняй промежуточные артефакты — дампы и скрипты
пригодятся в связанных задачах.

## Что мы теперь знаем

- Реверс на CTF — это **система**, а не перебор инструментов.
- Первый шаг всегда — **классификация** задачи; тип диктует рецепт.
- **Триаж** (`file`, `strings`, `checksec`, запуск) за 5 минут решает половину задач.
- Для flag checker: найти проверку → обратить (XOR/сравнение/крипто) → проверить на бинарнике.
- Константы и таблицы лежат в `.rodata` — их видно в дампе.
- Тайм-менеджмент и повторно используемые скрипты важнее «глубины» в одной задаче.

## На что смотреть дальше

- Не начинай с самого сложного инструмента (angr, эмуляция) — триаж решает быстрее.
- Не игнорируй `strings` и ресурсы: флаг или подсказка могут лежать там.
- Не патчи код при проверке целостности — меняй регистры в отладчике.
- Не бойся другой архитектуры — эмуляция (`Qiling`/`qemu-user`) решает.
- Записывай неудачные подходы, чтобы не повторять их; веди заметки по ходу решения.
- Читай название и описание задачи — они часто намекают на технику.

## Куда дальше

Мы собрали весь арсенал в системную методику. Дальше возьмём аппаратную отладку и шины (JTAG,
CAN) — там реверс выходит за пределы файла и работает с железом. А пока главное запомни:
**на CTF побеждает система, а не случайный перебор** — триаж, классификация, рецепт.

## Где пригодится

- **CTF Reversing:** быстрый и системный триаж любых задач.
- **Обучение:** структурированный подход к практике.
- **Работа:** методика разбора незнакомых бинарников.
- **Собеседование:** демонстрация методики вместо «я просто кликаю».
