Скриптовые языки не компилируются в машинный код, но и не всегда поставляются в виде исходников.
Python распространяют как `.pyc` (скомпилированный байткод), Lua — как предкомпилированные чанки,
Perl и Ruby также имеют свои форматы. Для реверс-инженера это значит: нужно уметь восстанавливать
исходный скрипт из байткода и обходить нехитрые защиты (обфускация, шифрование исходника). Этот
урок — о практических инструментах для каждого языка.

## Python: pyc и как он устроен

Когда Python импортирует модуль, он компилирует `.py` в байткод и сохраняет его как `.pyc` (в
`__pycache__`). Файл `.pyc` начинается с magic-числа (зависит от версии Python), затем идут флаги и
сериализованный объект `code` (marshal). Байткод — это последовательность инструкций для виртуальной
машины CPython (стековой), похожая на JVM-байткод.

Определить версию: magic-число (первые 4 байта) уникально для версии. Если magic не совпадает с
вашей версией Python, интерпретатор откажется загружать файл — но декомпилятор всё равно прочитает.

## Python: дизассемблер и декомпиляторы

Штатный дизассемблер — `dis`:

```python
import dis, marshal, importlib.util
with open("module.pyc", "rb") as f:
    f.read(16)              # пропустить заголовок (версия-зависимо)
    code = marshal.load(f)
dis.dis(code)
```

Для декомпиляции используют **decompyle3** (Python 3.7–3.8), **uncompyle6** (2.7–3.8),
**pycdc** (C++, поддерживает много версий), **pycdas** (дизассемблер из состава pycdc). Командная
строка:

```
$ pycdc module.pyc > module.py
```

Если декомпилятор не поддерживает версию, читают байткод через `dis` и восстанавливают логику
вручную. Часто этого достаточно: инструкции вроде `LOAD_CONST`, `BINARY_XOR`, `COMPARE_OP`,
`CALL_FUNCTION` легко читаются.

## Python: защита и обход

Популярные защиты Python-скриптов:

- **Обфускация**: переименование переменных, вставка мусорного кода, `exec`/`eval` строк.
- **Шифрование исходника**: загрузчик расшифровывает `.py`/`.pyc` в памяти и исполняет через `exec`.
- **PyArmor**: коммерческий протектор (шифрование байткода, native-загрузчик).
- **PyInstaller**: упаковка в исполняемый файл (байткод внутри архива).
- **Nuitka**: компиляция Python в C/нативный код.

Обход: для `exec`-загрузчиков — перехватить `exec`/`eval` (или `compile`) и выгрузить расшифрованный
код; для PyInstaller — распаковать архив (`pyinstxtractor`), затем декомпилировать `.pyc`; для
PyArmor — сложнее (нужен дамп байткода в рантайме); для Nuitka — нативный анализ.

## Lua

Lua-скрипты компилируются в байткод (`.luac`). Определить: файл начинается с `\x1bLua`. Версия —
в следующем байте (например, `0x53` — Lua 5.3). Декомпиляторы: **luadec**, **unluac**,
**lua-decompiler**. Командная строка:

```
$ unluac luac.out > script.lua
$ luadec -dis luac.out        # дизассемблировать
```

Для конкретных версий Lua нужен соответствующий декомпилятор (байткод несовместим между версиями).
Частая защита — изменённое magic-число или шифрование чанка: тогда восстанавливают заголовок или
расшифровывают перед декомпиляцией. Lua часто используется в играх (аддоны, моды) и в embedded
(роутеры), поэтому задачи встречаются.

## Perl и Ruby

**Perl** компилируется в дерево опкодов, которое не предназначено для восстановления. Инструменты:
`B::Deparse` (восстанавливает исходник из опкодов в рантайме), `B::Concise` (дизассемблер опкодов).
Для `.pl`-скриптов, обёрнутых в бинарник (`perlcc`, PAR), извлекают встроенный скрипт. Часто проще
найти исходник в виде строки внутри файла (`strings`).

**Ruby** использует байткод YARV. Инструменты: `ruby -e 'puts RubyVM::InstructionSequence.disasm(...)'`,
**ruby-decompiler** (ограниченный). Файлы `.rbc`/упакованные (RubyEncoder) требуют извлечения в
рантайме. Для скриптов часто достаточно прочитать исходник, если он есть; защита встречается реже.

## Практический разбор

Пусть дана задача: `crackme.pyc`. Определяем версию Python по magic и запускаем декомпилятор:

```
$ pycdc crackme.pyc
# Source Generated with Decompyle++
import sys
def check(s):
    if len(s) != 8:
        return False
    t = 0
    for c in s:
        t = (t * 31 + ord(c)) & 0xffffffff
    return t == 0x1a2b3c4d
print("ok" if check(input()) else "no")
```

Алгоритм — полиномиальный хеш. Пишем keygen (подбираем строку с нужным хешем). Если `pycdc` не
поддерживает версию, дизассемблируем через `dis`:

```
$ python3 -c "import dis,marshal; f=open('crackme.pyc','rb'); f.read(16); dis.dis(marshal.load(f))"
  5           0 LOAD_CONST    1 (31)
              2 LOAD_FAST     0 (t)
              4 BINARY_MULTIPLY
  ...
```

По инструкциям восстанавливаем ту же логику.

Для PyInstaller: `pyinstxtractor crackme.exe` извлекает `.pyc`-файлы, затем декомпилируем нужный.
Для `exec`-загрузчика: ставим `breakpoint` на `exec` (или подменяем `builtins.exec` своим) и
печатаем аргумент — расшифрованный исходник.

| PyInstaller | `pyinstxtractor` |

## Python: marshal и версии

Байткод Python сериализуется модулем `marshal`, формат которого не документирован и меняется между
версиями. Это создаёт главную практическую проблему: `.pyc`, собранный Python 3.11, не загрузится в
3.8 (несовпадение magic), а декомпилятор, написанный под 3.7, споткнётся на новых инструкциях.
Практические приёмы:

- **Определить версию** по magic-числу (первые 2 байта) и по размеру заголовка (в новых версиях он
  16 байт, в старых — 8 или 12).
- **Подобрать декомпилятор**: `uncompyle6` для 2.7–3.8, `decompyle3` для 3.7–3.8, `pycdc` для
  широкого диапазона, но не всегда корректно.
- **Читать байткод вручную** через `dis`, если декомпилятор не справляется. Для Python 3.11+ это
  часто единственный путь.

Заголовок `.pyc` (16 байт в 3.7+) содержит magic, флаги, timestamp и размер исходника. При
извлечении из PyInstaller заголовок может быть обрезан — его восстанавливают вручную по magic нужной
версии, иначе `marshal.load` упадёт.

## Обфускация Python и её снятие

Обфускаторы Python (pyobfuscate, Oxyry, PyArmor) применяют разные приёмы. **Переименование** делает
имена бессмысленными (`_0x1234`), но структура сохраняется. **Строковое шифрование** заменяет
литералы вызовами декриптора. **Маршалинг с шифрованием** хранит байткод зашифрованным, а
загрузчик расшифровывает его в памяти и вызывает `exec`. **PyArmor** добавляет нативный загрузчик,
проверки и обфускацию байткода.

Рецепт против `exec`-загрузчиков: подменить `builtins.exec` (или `compile`) своей функцией, которая
печатает аргумент и вызывает оригинал. Аналогично перехватывают `marshal.loads`/`marshal.load` —
часто расшифрованный байткод проходит именно там. Для PyArmor дампают байткод в рантайме (например,
через `sys.settrace` или отладчик) — это сложнее, но выполнимо. Для Nuitka переходят к нативному
анализу сгенерированного C-кода.

## Практика: автоматизация

Скриптовые задачи хорошо автоматизируются. Полезные шаблоны:

```python
import dis, marshal, sys
# дамп всех констант и имён из code-объекта (включая вложенные)
def walk(code, depth=0):
    print("  " * depth, code.co_name, code.co_consts)
    for c in code.co_consts:
        if hasattr(c, "co_code"):
            walk(c, depth + 1)
with open("module.pyc", "rb") as f:
    f.read(16)
    walk(marshal.load(f))
```

Так рекурсивно выгружаются все вложенные функции и их константы — часто флаг или пароль лежит прямо
в `co_consts`. Для Lua аналогично можно извлечь строки из чанка (`strings` на `.luac`). Для
обфусцированного Python полезно искать строки после расшифровки: перехватить декриптор и логировать.

## Сравнение подходов

| Язык | Формат | Основной декомпилятор | Сложность защиты |
|---|---|---|---|
| Python | .pyc (marshal) | pycdc/decompyle3 | средняя (PyArmor) |
| Lua | .luac | unluac/luadec | средняя (кастом) |
| Perl | опкоды | B::Deparse | высокая |
| Ruby | .rbc (YARV) | ruby-decompiler | средняя |

Общий принцип: интерпретируемые языки принципиально восстанавливаемы (байткод содержит всю логику),
но защиты усложняют извлечение (шифрование, нативный загрузчик). Начинайте с простых инструментов
(декриптор строк, `dis`), переходите к рантайм-дампу, только если статически не получается.

## Lua в играх и embedded

Lua особенно популярен в двух нишах: игровые движки (WoW-аддоны, Roblox, моды) и embedded-устройства
(роутеры на OpenWrt, прошивки). В играх Lua-скрипты часто лежат в архивах (`.mpq`, `.pak`) и
скомпилированы в `.luac`; их извлекают, декомпилируют `unluac` и анализируют. В embedded Lua
используется для веб-интерфейсов и скриптов автоматизации — там встречается кастомная сборка Lua с
изменённым байткодом, что усложняет декомпиляцию.

Защита Lua обычно сводится к модификации magic-числа (чтобы стандартный декомпилятор отказался) или
шифрованию чанка. Обход: восстановить заголовок (первые байты `\x1bLua` + версия) или расшифровать
чанк перед декомпиляцией. Иногда логика вынесена в нативный C-модуль (`require` загружает `.so`),
и тогда нужен нативный анализ.

## Подводные камни

Первое: `.pyc` привязан к версии Python — magic-число должно совпадать, иначе интерпретатор не
загрузит файл. Второе: декомпиляторы отстают от новых версий Python — читайте `dis`. Третье:
`exec`/`eval` скрывают код — перехватывайте их. Четвёртое: PyInstaller-архив нужно сначала
распаковать. Пятое: PyArmor и Nuitka требуют рантайм-дампа или нативного анализа. Шестое: Lua-
байткод версионно-зависим — используйте декомпилятор под точную версию. Седьмое: Perl/Ruby-защита
редка, но встречается в коммерческих продуктах. Восьмое: строки в байткоде могут быть представлены
не как UTF-8, а как объекты — учитывайте это при поиске флага.

## Что дальше / решение

Практика: возьмите `crackme.pyc`, определите версию, декомпилируйте, напишите keygen. Затем

декомпилируйте `unluac`. Далее — `reversing-python-bytecode` (существующий урок) и
`reversing-managed-dotnet-java`.
