**Реверс ransomware** — одна из самых прикладных задач анализа вредоносного ПО: нужно понять схему шифрования, найти слабости генератора ключей и, если повезёт, восстановить данные без выкупа. Урок даёт полный практический workflow: от безопасного триажа и идентификации семейства до поиска крипто-примитивов, анализа RNG, известных атак на реализации и работы с образцами в изолированной среде.

## Зачем реверсить ransomware

- **Восстановление данных**: найти ключ/IV, слабый RNG, ошибку в схеме, чтобы расшифровать файлы.
- **Атрибуция**: определить семейство (LockBit, Conti, Hive, Phobos...) по строкам, нотам, расширениям.
- **IR/форензика**: понять, что зашифровано и что уцелело, найти артефакты.
- **Разработка детекторов/дешифраторов**: сигнатуры YARA, декрипторы для известных семейств.

Ключевой принцип: ransomware — это **обычно не «сильная криптография»**, а реализация. Ошибки в RNG, в режиме шифрования, в хранении ключа — то, за что цепляется реверс.

## Классификация схем шифрования

| Схема | Описание | Слабость |
|---|---|---|
| Гибридная (RSA+AES) | сессионный AES-ключ шифруется RSA-ключом атакующего | если приватный RSA-ключ утёк/слаб — расшифровка |
| Симметричная с общим ключом | один ключ на все файлы | утечка ключа = всё расшифровано |
| Симметричная, ключ на файл | ключ для каждого файла | нужен перебор/слабость RNG |
| XOR/RC4/слабые | потоковые, самодельные | частотный анализ, известный plaintext |
| С «отложенным» ключом | ключ на сервере, в файле только зашифрованный сессионный | offline-невосстановимо без сервера |

Для реверса важно быстро понять, **какая это схема** — от этого зависит вся стратегия.

## Первичный анализ и идентификация семейства

Работайте только в изолированной ВМ без сети (или с симулированной сетью), со снятыми снапшотами.

```bash
file sample.exe
sha256sum sample.exe
# строки и ноты выкупа
strings -a -n 8 sample.exe | grep -iE 'ransom|decrypt|bitcoin|onion|readme|\.locked|AES|RSA|chacha'
# энтропия и упаковка
binwalk -E sample.exe
upx -t sample.exe            # если UPX — распакуем
# подписи семейства (YARA)
yara -r rules/ransomware_index.yar sample.exe
```

Типовые индикаторы: расширение-маркер (`.locked`, `.encrypted`), файл-нота (`READ_ME.txt`), onion-адрес, название семейства в PDB-пути (если не вырезан).

## Статический анализ: поиск крипто-примитивов

```bash
# в Ghidra/IDA ищем константы и вызовы
# AES S-box, Rijndael, RSA-экспонента 0x10001, ChaCha-константы "expand 32-byte k"
strings -a -t x sample.exe | grep -iE 'expand 32-byte|Salsa|ChaCha|Rijndael'
# импорты крипто-API
objdump -T sample.exe 2>/dev/null | grep -iE 'Crypt|BCrypt|CryptoAPI|EVP_'
# в Ghidra — поиск по константам
```

Что искать в декомпиляторе:

- **AES S-box** — таблица 256 байт; сразу указывает на AES.
- **RSA-экспонента** `0x10001` и большие простые числа.
- **Константы ChaCha/Salsa** `"expand 32-byte k"`.
- **Вызовы Windows CryptoAPI** (`CryptGenKey`, `CryptEncrypt`) или **BCrypt**.
- **Собственный RNG** — `rand()`, `time(NULL)`, `GetTickCount()` как seed (классическая слабость).

## Динамический анализ в песочнице

```bash
# запуск в изолированной среде с мониторингом
strace -f -e trace=file,openat,write -o trace.log ./sample   # Linux-малварь
# Windows: Procmon + API Monitor + x64dbg под ВМ без сети
# точки останова на крипто-функциях
```

В x64dbg ставьте breakpoints на `CryptEncrypt`, `CryptGenKey`, `BCryptEncrypt`, `WriteFile` — и смотрите буферы ключа/IV в памяти. Часто ключ лежит открытым в куче до шифрования.

## Поиск ключей и слабостей RNG

Основные векторы:

- **Время как seed.** Если ключ генерируется от `time(NULL)`/`GetTickCount()`, пространство перебора — миллисекунды/секунды запуска.
- **`rand()` без srand или с фиксированным seed.** Предсказуемая последовательность.
- **Один и тот же ключ/IV на все файлы** — расшифровав один файл, расшифруете всё.
- **Повтор IV в CTR/OFB** — XOR двух шифртекстов даёт XOR двух открытых текстов (крипто-атака «two-time pad»).
- **Ключ в файле/реестре/конфиге** — рядом с зашифрованными файлами.

```python
# пример: перебор seed по времени запуска
import time, random
for t in range(start, end):
    random.seed(t)
    k = bytes(random.getrandbits(8) for _ in range(32))
    if try_decrypt(k, ciphertext):
        print("key found, seed", t); break
```

## Восстановление файлов без ключа

Известные классы атак (по мотивам исследований):

- **Атака на прерывание шифрования** — если малварь шифрует файлы последовательно и была прервана, часть файлов может быть не зашифрована; восстановление по «паре» plaintext/ciphertext.
- **Файлы в памяти/кэше** — ОС могла сохранить копию (shadow copies, temp).
- **Известный plaintext** — заголовки форматов (PNG, PDF, ZIP) позволяют восстановить keystream для потоковых шифров.
- **Слабый RSA** — общий множитель двух модулей (gcd), маленькая экспонента, факторизация.

```bash
# поиск теневых копий и недавних версий (Windows)
vssadmin list shadows
# форензика: ищем незашифрованные копии
foremost -i disk.img -o carved/
```

## Разобранный пример: анализ учебного шифровальщика

**Шаг 1. Триаж.**

```bash
strings -a -n 6 ransom.bin | grep -iE 'AES|key|seed|time'
# "AES-256-CBC key=seed(time)"
```

**Шаг 2. Декомпиляция генератора ключа** (Ghidra):

```c
key = malloc(32);
srand(time(NULL));                       // <-- слабость: seed = время
for (i=0;i<32;i++) key[i] = rand() & 0xff;
```

**Шаг 3. Эксплуатация слабости.** Восстанавливаем время запуска (по mtime файлов-маркеров) и перебираем seed:

```python
import ctypes, time
libc = ctypes.CDLL("libc.so.6")
for t in range(t0-5, t0+5):
    libc.srand(t)
    key = bytes(libc.rand() & 0xff for _ in range(32))
    if decrypt_and_check("file.locked", key):
        print("recovered", key.hex()); break
```

**Шаг 4. Расшифровка.**

```python
from Crypto.Cipher import AES
ct = open("file.locked","rb").read()
pt = AES.new(key, AES.MODE_CBC, ct[:16]).decrypt(ct[16:])
open("file.recovered","wb").write(pt)
```

## Безопасность и OPSEC при анализе

- **Изолированная ВМ** без сети; сеть — только через симулятор (INetSim) для C2-трафика.
- **Снапшоты** до запуска; откат после каждого запуска.
- **Никогда не запускайте на хосте**, особенно на Windows без ВМ.
- **Симуляция шифрования** на безобидных файлах-приманках; следите за диском.
- **Логирование сети** — ransomware может отправлять ключ на C2; перехватите его в симуляторе.

## Частые ошибки и подводные камни

- **Запуск без изоляции.** Образец может зашифровать хост или уйти в сеть — только ВМ + снапшоты.
- **Анализ только финального бинарника.** Стаб + дроппер: полезная нагрузка может быть во втором слое.
- **Игнорирование RNG.** Главная слабость ransomware — не AES, а генерация ключа.
- **Пренебрежение known-plaintext.** Заголовки форматов восстанавливают keystream потоковых шифров.
- **Вера в «сильную крипту».** Часто это самодельный XOR/RC4 с ошибками.
- **Отсутствие снапшотов.** Один запуск — и стенд «заражён» навсегда.

## Что дальше / решение

Маршрут: **триаж и семейство → статический поиск крипто-примитивов → динамика под изоляцией (ключи в памяти) → анализ RNG/схемы → атака (перебор seed, known-plaintext, слабый RSA)**. Если ключ хранится только на C2-сервере — offline-восстановление невозможно без сервера, и тогда цель — IR-отчёт, а не декриптор. Дальше — `reversing-crypto-advanced` (глубокий разбор крипто-примитивов) и `reversing-malware-dynamic` (динамический анализ малвари).

## Практика: YARA-правило для семейства

Сигнатуры помогают быстро атрибутировать образец и найти родственные файлы в наборе.

```yara
rule Ransom_Demo_AES_Seed {
    meta:
        description = "Demo ransomware using time-seeded AES key"
    strings:
        $a = "expand 32-byte k" ascii
        $b = "READ_ME.txt" ascii wide
        $c = { 6A 00 E8 ?? ?? ?? ?? 89 45 FC }   // srand(time(NULL)) паттерн
        $d = ".locked" ascii
    condition:
        uint16(0) == 0x5A4D and 2 of them
}
```

```bash
yara -r rules/ransom_demo.yar samples/
# Ransom_Demo_AES_Seed samples/sample2.exe
```

## Known-plaintext: полный разбор

Для потоковых шифров (RC4/ChaCha/XOR) известный открытый текст восстанавливает keystream. Типовой случай: файл формата PNG/ZIP, у которого первые байты всегда одинаковы.

```python
# известны первые 8 байт PNG: 89 50 4E 47 0D 0A 1A 0A
ct = open("image.locked","rb").read()
known = bytes.fromhex("89504E470D0A1A0A")
keystream = bytes(c ^ p for c, p in zip(ct[:8], known))
print("keystream[:8] =", keystream.hex())
# если шифр потоковый с повторяющимся keystream — расшифровываем остальное
```

Если тот же keystream используется для нескольких файлов (ошибка «one key/IV for all»), вы расшифровываете всё семейство файлов, не зная ключа.

## Работа с C2 и сетевым взаимодействием

Ransomware может генерировать ключ локально, но передавать его на C2. Перехват трафика даёт ключ.

```bash
# симулировать сеть и логировать DNS/HTTP
inetsim --conf inetsim.conf
# или перехват через mitmproxy с подменой сертификата
mitmproxy --mode transparent -p 8080
```

Если образец отправляет ключ в открытом виде (или с фиксированным XOR/base64) — вы восстанавливаете его из дампа трафика. Часто сессионный ключ уходит в первом POST-запросе.

## Форензика после атаки: что восстанавливать

- **VSS (теневые копии)** — если не удалены, файлы восстановимы штатно.
- **Temp/кэш** — ОС и приложения могли сохранить копии.
- **Незашифрованные файлы** — ransomware обычно щадит системные/уже зашифрованные.
- **Дампы памяти** — ключ может остаться в `pagefile.sys`/`hiberfil.sys`/дампе процесса.
- **Журналы** — Event Log, Prefetch, Amcache — таймлайн и путь образца.

```bash
# поиск ключа в дампе памяти по энтропии/структуре
volatility3 -f memory.dmp windows.malfind
volatility3 -f memory.dmp windows.strings --strings-file keys.txt
```

## Мини-лаборатория для безопасного реверса

Правильный стенд для анализа ransomware обязателен — иначе образец опасен:

- **ВМ без сети** (снапшоты до/после), либо сеть только через INetSim.
- **Приманки-файлы** (не настоящие данные) для наблюдения шифрования.
- **Снимок диска** до запуска и инструмент отката (VirtualBox/VMware snapshots).
- **Изоляция гипервизором** + отключённые общие папки с хостом.
- **Мониторинг** (Procmon, Sysmon, API Monitor) — чтобы видеть ФС/реестр/сеть.

## Что ещё проверить: подпись и PDB

Иногда в бинарнике остаётся **PDB-путь** или **Rich-заголовок** — они выдают среду сборки и автора, а также подсказывают, где искать исходники семейства.

```bash
strings -a sample.exe | grep -iE '\.pdb|Rich|build|\\Users\\'
```

## Ключевые выводы по ransomware

Итог: **смотрите на RNG и хранение ключа**, а не на силу алгоритма. Известный plaintext, повторный IV, time-seed, ключ на C2 — четыре главных вектора. Всегда работайте в изоляции со снапшотами и логируйте сеть.
