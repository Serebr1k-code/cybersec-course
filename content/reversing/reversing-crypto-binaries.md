В подавляющем большинстве реальных задач реверса — от crackme до прошивки роутера и образцов
шифровальщиков — где-то внутри крутится криптография. Она может быть стандартной (AES, RC4, SHA),
а может быть самодельной, собранной на коленке из XOR и подстановок. Задача реверсера — быстро
понять, **какой алгоритм используется, где лежит ключ и как данные преобразуются**, чтобы либо
восстановить пароль, либо расшифровать полезную нагрузку, либо просто найти слабое место.
Этот урок — про системный подход к поиску и разбору крипто-кода.

## Зачем искать криптографию в бинарнике

Крипто-код — это почти всегда «сердце» защиты. Если приложение шифрует лицензию, конфиг или C2-трафик,
то без понимания алгоритма дальше не продвинуться. Три типовые цели:

- **Восстановить ключ** — часто он лежит рядом с алгоритмом (хардкод), и после расшифровки задача решается.
- **Найти слабость** — самодельный «шифр» почти всегда ломается (XOR с коротким ключом, повтор nonce, ECB).
- **Понять протокол** — чтобы подделать трафик или расшифровать дамп памяти.

Ключевое наблюдение: **крипто-примитивы невозможно скомпилировать «незаметно»**. У AES, DES, MD5,
SHA и RC4 есть жёстко заданные константы, которые оказываются в `.rodata`/`.rdata` почти дословно.
Именно на них и строится весь поиск.

## Теория: как выглядит крипто в машинном коде

Алгоритмы делятся на три группы, и у каждой свой «отпечаток»:

- **Блочные шифры** (AES, DES, Blowfish, SM4) — таблицы подстановок (S-box) на 256 или 1024 байта,
  чередование операций над раундовыми ключами, характерные константы (`Rcon` у AES).
- **Потоковые шифры** (RC4, ChaCha20, Salsa20) — RC4 знаменит двумя массивами по 256 байт и
  циклом KSA/PRGA; ChaCha20 имеет строку `expand 32-byte k`.
- **Хеш-функции** (MD5, SHA-1/2, CRC) — инициализационные векторы (IV) из «магических» слов
  (например, MD5: `0x67452301, 0xefcdab89, 0x98badcfe, 0x10325476`).

Плюс повсеместно встречается **самодельная криптография**: побайтовый XOR, ROT, add/xor/sub
с переменным ключом, «шифрование» через таблицу замен. Оно узнаётся по простым циклам без
констант — и обычно ломается за минуты.

## Константы-маркеры: справочная таблица

| Алгоритм | Что искать (hex/ASCII) | Размер | Заметки |
|---|---|---|---|
| AES S-box | `63 7c 77 7b f2 6b 6f c5 30 01 67 2b fe d7 ab 76` | 256 B | начинается с `637c777b` |
| AES Te0 | `c66363a5 f87c7c84 ee777799 …` | 1 KB | T-таблицы в быстрых реализациях |
| AES Rcon | `01 02 04 08 10 20 40 80 1b 36` | 10 B | расширение ключа |
| DES IP/S-box | таблицы 64 и 8×64 | — | начальная перестановка |
| MD5 IV | `01 23 45 67 89 ab cd ef` | 16 B | little-endian слова |
| SHA-1 IV | `67 45 23 01 ef cd ab 89` | 20 B | + `98 ba dc fe` |
| SHA-256 IV | `6a09e667 bb67ae85 3c6ef372` | 32 B | H0..H7 |
| CRC32 | `edb88320` | 4 B | реверс-полином |
| RC4 | два массива `00..ff` + swap-цикл | — | узнаётся по коду |
| ChaCha20 | `expand 32-byte k` | 16 B ASCII | sigma-константа |
| Salsa20 | `expand 32-byte k` | 16 B ASCII | похоже на ChaCha |
| Base64 | `ABCDEFGHIJKLMNOPQRSTUVWXYZabcdef…` | 64 B | не шифр, но кодирование |

Запомнить стоит хотя бы начало AES S-box (`637c777b`) и IV хешей — они выдают реализацию мгновенно.

## Инструменты: как искать константы

**1. IDA — плагин FindCrypt / FindCrypt2.** Ищет таблицы AES, DES, Blowfish, MD5, SHA, CRC и др.
Установка: положить `findcrypt.plw`/`.dll` в `plugins/`, перезапустить, затем `Edit → Plugins →
FindCrypt`. В логе появится список адресов и алгоритмов.

**2. Ghidra — расширение FindCrypt** (скрипт `FindCrypt.py`). `Window → Script Manager → FindCrypt`.

**3. radare2/rizin — `/` поиск сигнатур.** Например, найти AES S-box:
```bash
r2 -A ./target
[0x00401000]> /x 637c777bf26b6fc53001672bfed7ab76
0x00403020 hit0_0
```
Или через встроенный `rabin2 -zz`/`/a crypto` (с плагином) — но ручной `/x` надёжнее.

**4. signsrch / YARA.** `signsrch` сканирует бинарник по базе из сотен крипто-сигнатур:
```bash
signsrch -e ./target | grep -i -A2 aes
```
YARA-правило для AES:
```yara
rule AES_Sbox {
    strings:
        $sbox = { 63 7c 77 7b f2 6b 6f c5 30 01 67 2b fe d7 ab 76 }
    condition:
        $sbox
}
```
```bash
yara aes.yar ./target
```

**5. `strings` + grep** для ASCII-маркеров (`expand 32-byte k`, `AES`, `RC4`, имена ошибок OpenSSL):
```bash
strings -a ./target | grep -Ei 'aes|rc4|chacha|salsa|blowfish|md5|sha1|sha256'
```

**6. `binwalk`** — для прошивок полезен, но для поиска алгоритма в ELF/PE слабее: он ищет форматы, не примитивы.

## Разобранный пример: RC4 в crackme

Дано: ELF-крякми просит «лицензионный ключ». Открываем в IDA и видим в `main` вызов подфункции,
которая принимает указатель на ввод и указатель на строку-ключ.

**Шаг 1. Опознаём RC4 по структуре кода.** Смотрим `sub_4011A0`:

```c
void sub_4011A0(unsigned char *data, int len, unsigned char *key, int keylen) {
    unsigned char S[256];
    for (int i = 0; i < 256; i++) S[i] = i;          // KSA init
    int j = 0;
    for (int i = 0; i < 256; i++) {                  // KSA
        j = (j + S[i] + key[i % keylen]) & 0xff;
        swap(&S[i], &S[j]);
    }
    int i = 0; j = 0;
    for (int k = 0; k < len; k++) {                  // PRGA
        i = (i + 1) & 0xff;
        j = (j + S[i]) & 0xff;
        swap(&S[i], &S[j]);
        data[k] ^= S[(S[i] + S[j]) & 0xff];
    }
}
```

Два цикла `0..255` с `swap` и `i % keylen` — это **100% RC4**. Никаких констант не нужно.

**Шаг 2. Находим ключ.** В `main` аргумент `key` указывает на строку в `.rodata`:
```
.rodata:00403040   aKey db 'S3cr3tK3y!',0
```

**Шаг 3. Проверяем.** Воспроизводим RC4 на Python:
```python
def rc4(key, data):
    S=list(range(256)); j=0
    for i in range(256):
        j=(j+S[i]+key[i%len(key)])&0xff; S[i],S[j]=S[j],S[i]
    i=j=0; out=bytearray()
    for b in data:
        i=(i+1)&0xff; j=(j+S[i])&0xff; S[i],S[j]=S[j],S[i]
        out.append(b ^ S[(S[i]+S[j])&0xff])
    return bytes(out)
print(rc4(b'S3cr3tK3y!', bytes.fromhex('...')))
```
Получаем расшифрованный «правильный» ключ — задача решена.

## Разобранный пример: AES-128 и восстановление ключа

Дано: бинарник, который шифрует конфиг AES-128-CBC. Находим S-box через FindCrypt:

```
[FindCrypt] AES: 0x00405020 (Sbox), 0x00405420 (Te0)
```

Смотрим xref на `0x00405020` — попадаем в функцию `sub_402000`, похожую на `AES_set_encrypt_key`.
Ключ обычно подаётся рядом:
```asm
lea     rdi, [rbp+key_schedule]
lea     rsi, [rip+hardcoded_key]     ; <-- вот он
mov     edx, 128
call    AES_set_encrypt_key
```
`hardcoded_key` в `.rodata` — 16 байт. Проверяем: расшифровываем конфиг через `openssl` или
`pycryptodome`:
```bash
echo -n "$(cat config.enc | xxd -p)" | xxd -r -p | \
  openssl enc -d -aes-128-cbc -K 00112233445566778899aabbccddeeff \
  -iv 00000000000000000000000000000000 -nopad | head
```
Если видим осмысленный JSON/строки — ключ верный.

## Хеши и их идентификация

Хеши не «расшифровываются», но часто нужно понять, **какой именно** алгоритм применён, чтобы
подобрать/перебрать пароль. Признаки:

- **CRC32**: цикл с `>> 1`, XOR с `0xEDB88320`, 256-элементная таблица.
- **MD5**: IV `67452301`, 64 итерации, константы `d76aa478`, `e8c7b756`, …
- **SHA-1**: IV `67452301`, константы `5a827999`, `6ed9eba1`, `8f1bbcdc`, `ca62c1d6`.
- **SHA-256**: IV `6a09e667`, константы `428a2f98`, `71374491`, …
- **Самопальный хеш**: часто просто `sum(bytes) % N` или `xor` всех байт — ломается коллизией.

Инструмент для быстрой идентификации: `hashid`, `haiti`, но для *бинарных* констант — FindCrypt/signsrch.

## Обфускация крипто: кастомные S-box и XOR-шифры

Злоумышленники и защита часто «мутируют» стандартную крипту, чтобы FindCrypt её не увидел:

- **XOR S-box с константой**: S-box генерируется на лету (`sbox[i] = base[i] ^ 0x55`).
  FindCrypt промахнётся. Спасает динамический анализ: сдампить S-box из памяти после генерации.
- **Разбиение таблицы** на части и сборка в рантайме.
- **XOR-«шифр»**: `data[i] ^= key[i % len]`. Ключ длиной 1–8 байт ломается частотным анализом;
  если ключ повторяется, смотрим XOR известного открытого текста (например, заголовка файла) — получаем ключ.
- **Add/Sub шифр**: `data[i] = (data[i] + key[i]) & 0xff` — аналогично XOR, но с вычитанием.

Для мутированного AES сдампим таблицу из отладчика:
```text
gdb> b *0x402050        ; после генерации S-box
gdb> run
gdb> x/256xb $rdi       ; дамп S-box
```
Затем сравним с оригиналом через XOR — получим «маску» обфускации и снимем её.

## Крайние случаи и подводные камни

- **Inline-реализация без таблиц.** Некоторые компиляторы (и obfuscator'ы) вычисляют S-box
  арифметически (bitsliced AES) — таблицы отсутствуют. Тогда опознаём по структуре (много `xor`,
  `shl`, `and`) и по алгоритму MixColumns.
- **Векторные инструкции (AES-NI).** На современных x86 AES реализован одной инструкцией `aesenc`.
  FindCrypt ничего не найдёт, но `aesenc`/`aesdec`/`aeskeygenassist` в листинге — явный признак.
- **Ложные срабатывания.** Короткие константы (4 байта, CRC-полином) встречаются случайно.
  Всегда подтверждайте найденную «крипту» контекстом кода.
- **Динамическая генерация ключа.** Ключ может выводиться из `time()`, PID, MAC-адреса или ввода.
  Тогда статического ключа нет — нужен динамический трейс.
- **Стриппинг.** В strip-нутом бинарнике нет имён `AES_encrypt`; ориентируйтесь только на константы/структуру.
- **Порядок байт.** IV/ключи в листинге могут быть в другом endianness — проверяйте оба варианта.

## Что дальше / решение

1. Прогнать FindCrypt + signsrch + `strings | grep` — за минуту получить список кандидатов.
2. Подтвердить алгоритм по структуре кода (не только по константам).
3. Найти, откуда берётся ключ: хардкод, KDF из пароля, из окружения, из сети.
4. Воспроизвести алгоритм в Python/pycryptodome и проверить на реальных данных.
5. Если крипта мутирована — сдампить таблицы/ключи динамически из отладчика.

Практический приём для крякми: часто достаточно **не расшифровывать, а сравнить** — реализовать
проверку в Python и брутить вход, если пространство ключей мало.

## Где пригодится

- **CTF Reversing/Crypto:** быстрый разбор шифров в crackme, восстановление ключа/флага.
- **Malware analysis:** идентификация алгоритма ransomware, поиск встроенных ключей и конфигов.
- **Vuln research:** аудит самописной криптографии, поиск слабых PRNG.
- **Работа (IR/threat intel):** определение возможностей шифровальщика и шансов на расшифровку.
- **Собес:** «как вы найдёте AES в бинарнике» — проверка практического опыта.
