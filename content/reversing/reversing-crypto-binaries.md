## Вопрос, с которого всё начинается

На CTF дают бинарник, который «что-то шифрует», а исходников нет. Открываешь дизассемблер — сотни строк непонятного кода. Как понять, **какой** это алгоритм (AES? RC4? свой?) и, главное, где лежит ключ? К счастью, криптография выдаёт себя: у каждого стандартного алгоритма есть узнаваемые константы и характерная структура.

## Наш пример

Возьмём бинарник `crypto_demo`, внутри которого есть таблица подстановки и функция с именем `rc4_ksa`. Начнём с самого дешёвого — строк и имён:

```bash
$ strings -n 4 crypto_demo | grep -iE 'sbox|rc4'
rc4_ksa
sbox
```

Даже без дизассемблера видно два слова-подсказки: `rc4` и `sbox`. Это уже гипотеза. Проверим её по данным.

## Шаг 1: константы — отпечаток алгоритма

У стандартных алгоритмов есть **фиксированные константы**, зашитые в код. Для AES это таблица подстановки **S-box**, которая начинается с байтов `63 7c 77 7b f2 6b 6f c5`. Найдём эту последовательность в файле:

```text
offset 0x3040: 63 7c 77 7b f2 6b 6f c5 30 01 67 2b fe d7 ab 76
```

Совпадение точное — в бинарнике лежит **AES S-box**. Вот как это выглядит в дампе секции `.data`:

```bash
$ objdump -s -j .data crypto_demo
 4040 637c777b f26b6fc5 3001672b fed7ab76  c|w{.ko.0.g+...v
```

Так работает поиск криптографии «по отпечатку»: не читая код, ты находишь алгоритм по его константам. Аналогично опознаются:

| Алгоритм | Что искать |
|---|---|
| AES | S-box `63 7c 77 7b...` или Rcon |
| MD5 | `0x67452301`, `0xefcdab89`, `0x98badcfe`, `0x10325476` |
| SHA-1 | `0x67452301`, `0xefcdab89`, `0x98badcfe`, `0x10325476`, `0xc3d2e1f0` |
| SHA-256 | `0x6a09e667`, `0xbb67ae85`, ... |
| CRC32 | таблица из 256 значений, `0xedb88320` |

Инструмент **findcrypt** (плагин для Ghidra/IDA) делает это автоматически — сканирует бинарник на сотни таких сигнатур.

## Шаг 2: структура кода — второй признак

Константы могут быть изменены или спрятаны, поэтому смотрим и на **структуру**. У нашего `rc4_ksa` в дизассемблере есть характерный цикл:

```text
    1168: mov    %dl,(%rax)
    116a: addl   $0x1,-0x8(%rbp)
    116e: cmpl   $0xff,-0x8(%rbp)
    1175: jle    1158 <rc4_ksa+0x1f>
```

Цикл на 256 итераций (`cmpl $0xff`), который записывает по байту в массив — это **инициализация перестановки** (KSA) в RC4. Сам алгоритм RC4 — это два цикла по 256: сначала `s[i]=i`, потом перемешивание с ключом. Даже без констант такая «256-петля дважды» узнаётся сразу. Похожие структурные признаки: блочный цикл по 16 байт (AES-блок), цикл по 64 (SHA-256-блок).

## Шаг 3: где ключ

Найдя алгоритм, ищем **ключ**. Он почти всегда рядом с вызовом шифрования и передаётся как аргумент. Три типовых места:

1. **Строка-литерал** — `strings crypto_demo` или дамп `.rodata`: ключ лежит открытым текстом.
2. **Массив байт** — ключ собран в `.data` как `unsigned char key[] = {...}`.
3. **Вычисляется** — например, XOR из нескольких констант; тогда читаем код инициализации.

В нашем примере функция принимает ключ аргументом (`k[i % n]`), а вызывающий `main` передаёт `{'k','e','y'}` — это видно по трём байтам, загружаемым перед вызовом. Так «найти алгоритм» и «найти ключ» — два последовательных шага.

## Шаг 4: что делать с нестандартным шифром

Если findcrypt молчит и структура незнакома — это **custom cipher**. Тогда:

- Смотри **операции**: XOR с повторяющимся ключом (простой XOR), перестановки (транспозиция), сложение/умножение по модулю (могут быть RC4/AES-подобные).
- Ищи **таблицу** — своя S-box тоже таблица на 256 байт.
- Пробуй **восстановить по данным**: если есть шифртекст и открытый текст (известная пара), атакуй по ней.

Нестандартные шифры — тема следующего урока; а пока важно, что даже «свой» алгоритм почти всегда строится из узнаваемых примитивов.

## Шаг 5: узнаём AES по раундам

Если S-box найден, следующий вопрос — «настоящий ли это AES». Настоящая реализация состоит из повторяющихся **раундов**: над блоком из 16 байт делают SubBytes (по таблице), ShiftRows (перестановка байт), MixColumns (умножение в поле Галуа) и AddRoundKey (XOR с раундовым ключом). Признаки в дизассемблере:

- **цикл на 10/12/14 итераций** — столько раундов у AES-128/192/256;
- **обращения к таблице 256 байт** — это SubBytes;
- **`xor` с 16-байтным блоком** — AddRoundKey;
- **`0x1b`** (или `0x1b`/`0x1d`) как константа — полином поля Галуа для MixColumns.

Увидел «S-box + раунды + 0x1b» — это AES, и можно искать **раундовый ключ** рядом (обычно 16 байт, XOR-ится в последнем раунде).

## Шаг 6: полный прогон от начала до конца

Соберём разбор типичного шифрующего бинарника в одну цепочку:

1. **`strings`** — ищем имена алгоритмов и ключи (`aes`, `rc4`, `key`, `iv`).
2. **Поиск сигнатуры** — S-box AES или инициализаторы MD5/SHA в дампе секций.
3. **`nm`/`objdump -d`** — находим функцию шифрования и смотрим её структуру (циклы, таблицы).
4. **findcrypt** — если вручную не нашлось, плагин просканирует сотни сигнатур.
5. **Извлекаем ключ** — строки, массивы, аргументы.
6. **Воспроизводим** — реализуем расшифровку на Python и проверяем на данных.

Эти шаги применимы и к CTF, и к разбору ransomware: в обоих случаях цель — найти алгоритм и ключ, а дальше расшифровать данные.

## Шаг 7: практический пример с ключом

Разберём, как выглядит извлечение ключа на конкретике. Пусть в бинарнике есть строки:

```bash
$ strings -n 4 vault | grep -iE 'key|iv|secret'
AES-128-CBC
supersecretkey12
```

Первая строка говорит «алгоритм AES-128-CBC», вторая — 16 байт ровно под ключ AES-128. Проверяем гипотезу: ищем S-box — находим; ищем цикл на 10 итераций (AES-128) — находим. Значит, `supersecretkey12` и есть ключ. Остаётся найти IV (обычно 16 байт рядом или в первых байтах файла) и расшифровать:

```python
from Crypto.Cipher import AES
c = AES.new(b'supersecretkey12', AES.MODE_CBC, iv)
print(c.decrypt(ciphertext))
```

Именно так решается большинство «шифрующих» CTF-задач: алгоритм — по константам, ключ и IV — по строкам/данным, расшифровка — готовой библиотекой. Твоя задача — не реализовать AES, а **опознать** его и найти параметры.

## Что мы теперь знаем

- Стандартные алгоритмы опознаются по **константам** (AES S-box, инициализаторы MD5/SHA).
- **Структура** — второй признак: цикл по 256 (RC4), по 16 (AES-блок), по 64 (SHA).
- **Ключ** ищут в строках, массивах `.data` или в коде инициализации.
- **findcrypt** автоматизирует поиск по сигнатурам.
- Нестандартный шифр выдаёт себя комбинацией XOR/перестановок/таблиц.

## Куда дальше

Мы научились опознавать стандартную криптографию. Но что если автор специально всё усложнил — custom cipher, white-box AES, размазанный по коду ключ? Этому посвящён следующий урок про **продвинутый реверс криптографии**. А пока запомни: `strings` + поиск S-box-сигнатуры + взгляд на циклы дают ответ «какой алгоритм» за минуты.

## Где пригодится

- **CTF Reversing:** опознать алгоритм по константам — быстрый путь к решению крипто-задач.
- **Malware analysis:** ransomware и стилеры используют AES/RC4; распознавание ведёт к ключу и расшифровке конфигов.
- **Анализ защищённого ПО:** понимание, где ключ, помогает обойти лицензионную защиту.
- **Автоматизация:** findcrypt и YARA-правила по константам масштабируют поиск на много файлов.
