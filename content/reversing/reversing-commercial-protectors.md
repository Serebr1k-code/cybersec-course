Этот урок — сравнительный обзор всего класса коммерческих протекторов. Здесь мы разбираем
таксономию защит, каталог популярных протекторов, способы их детекта по секциям/строкам/энтропии
и выбор стратегии анализа. Глубокий разбор внутренностей VMProtect и Themida (VM-диспетчер,
девиртуализация, обход лицензии) вынесен в отдельный урок `reversing-vmprotect-themida` — здесь
мы смотрим на поле целиком и учимся определять, с чем именно имеем дело, прежде чем выбирать
инструменты.

## Зачем нужны протекторы и рамки работы

Протектор решает задачу защиты интеллектуальной собственности: не дать скопировать алгоритм,
обойти лицензионную проверку, изменить поведение программы или отладить её. Коммерческие
протекторы продаются как «обёртка»: разработчик загружает готовый бинарник, помечает функции и
получает защищённый файл без изменения исходников. Именно поэтому один и тот же протектор
встречается в десятках несвязанных продуктов, а его сигнатуры легко распознать.

Рамки работы: анализ протекторов допустим для исследования, CTF, malware-анализа и защиты
собственного ПО. Обход лицензионной защиты с целью пиратства незаконен. Все эксперименты
проводите в изолированной виртуальной машине со снапшотом — некоторые протекторы ставят
ring-0 драйверы и могут повредить систему.

## Классы защит (таксономия)

Протекторы комбинируют несколько независимых механизмов. Важно разделять их, потому что техника
обхода у каждого своя.

| Класс | Что делает | Пример техники обхода |
|---|---|---|
| Упаковка/шифрование | код шифруется, расшифровывается в рантайме | найти OEP, снять дамп (Scylla) |
| Виртуализация (VM) | функции → байткод своей VM | девиртуализация (Triton/VTIL), трасса |
| Мутация (MBA) | инструкции → эквивалентные выражения | упрощение через z3/IR |
| Полиморфизм | код меняется между сборками | сигнатуры бесполезны, нужна семантика |
| Анти-отладка | обнаружение отладчиков | ScyllaHide/TitanHide, патчи проверок |
| Анти-дамп | защита памяти, стирание заголовков | дампить до срабатывания, аппаратно |
| Anti-tamper | проверки целостности кода | патч в данных/в рантайме |
| Лицензирование | привязка к ключу/HW, онлайн-активация | обход ветки проверки, а не снятие VM |

Ключевая мысль: упаковка — самый простой класс (снять дамп), виртуализация — самый сложный
(нужна девиртуализация). Большинство протекторов = упаковка + анти-отладка, и лишь часть
добавляет виртуализацию выбранных функций.

## Каталог популярных протекторов

- **VMProtect** — упаковка + мутация + виртуализация выбранных функций; секции `.vmp0`/`.vmp1`;
  уровни Mutation/Virtualization/Ultra. Анализ: дни–недели.
- **Themida / WinLicense** — агрессивная анти-отладка (часто ring-0 драйвер), Code Virtualizer,
  anti-dump; секции `.themida`/`.winlice`. Анализ: недели.
- **Enigma Protector** — упаковка + анти-отладка + лицензирование; проще VMProtect/Themida.
- **Obsidium** — упаковка + мутации; средняя сложность.
- **ASProtect** — устаревший, но всё ещё встречается; низкая-средняя сложность.
- **Code Virtualizer** — «чистая» виртуализация от разработчиков Themida.
- **.NET Reactor / ConfuserEx** — обфускация .NET-сборок (не нативный код).
- **Denuvo** — DRM для игр; комбинация виртуализации, анти-отладки и онлайн-проверок.
- **MPRESS / UPX** — простые упаковщики (не протекторы), снимаются за минуты.

Начинайте изучение с Enigma/Obsidium — на них отрабатывается полный цикл (детект → OEP →
дамп → обход анти-отладки) без многонедельной девиртуализации.

| Протектор | Упаковка | VM | Анти-отладка | Драйвер | Сложность |
|---|---|---|---|---|---|
| VMProtect | да | да (выборочно) | сильная | нет | высокая |
| Themida/WinLicense | да | да | очень сильная | часто | очень высокая |
| Enigma | да | редко | средняя | редко | средняя |

Таблица помогает выбрать стратегию: если VM нет — достаточно дампа и обхода анти-отладки; если
VM есть — придётся трассировать/девиртуализировать.

## Детект протектора: секции, строки, энтропия, импорты

Прежде чем что-либо анализировать, точно определите протектор — от этого зависит весь план.
Пять независимых признаков:

| Признак | VMProtect | Themida/WinLicense | Enigma | Obsidium |
|---|---|---|---|---|
| Секции | `.vmp0`, `.vmp1` | `.themida`, `.winlice` | `.enigma1/2` | случайные имена |
| Строки | `VMProtect`, `.vmp` | `SecureEngine`, `Themida` | `Enigma` | `Obsidium` |
| Импорты | минимум | шифрованы | шифрованы | шифрованы |
| Драйвер | нет | часто (ring 0) | редко | иногда |
| Точка входа | VM-стаб | VM-стаб | распаковщик | распаковщик |
| Энтропия | высокая | высокая | высокая | высокая |

Признак «минимум импортов» очень надёжен: реальные API резолвятся вручную через
`LoadLibrary`/`GetProcAddress`, поэтому таблица импортов почти пуста.

## DIE и автоматический детект

Detect It Easy (DIE) — самый быстрый способ. Он сопоставляет сигнатуры секций, строк и байтов
и выдаёт имя протектора с версией.

```bash
# Графически
diec sample.exe            # консольный вариант DIE
# Ожидаемый вывод:
#   PE64
#   Protector: VMProtect(3.x)[-]
```

Ручная проверка секций и строк (когда DIE не уверен):

```bash
python3 -c "import lief;e=lief.parse('sample.exe');[print(s.name,round(s.entropy,2),hex(s.size)) for s in e.sections]"
# .vmp0 7.98 0x12000
# .vmp1 7.99 0x8000
# .text 6.10 0x4000
strings -a sample.exe | grep -iE 'vmp|themida|enigma|obsidium|secureengine' | sort -u | head
# VMProtect v3.5
```

Проверка импортов:

```bash
python3 -c "import lief;e=lief.parse('sample.exe');[print(x.name) for x in e.imports]"
# kernel32.dll
#   LoadLibraryA
#   GetProcAddress
```

Пустая таблица импортов + секции `.vmp0/.vmp1` + строка `VMProtect` = однозначный вердикт.

## Выбор стратегии анализа (дерево решений)

```
1) Определи протектор (DIE + секции + строки).
2) Есть ли виртуализация?
   - Нет  -> снять упаковку: найти OEP, дамп (Scylla), восстановить IAT.
   - Да   -> сначала тоже дамп (распакованный код), затем для VM-функций трасса/девиртуализация.
3) Настроить среду: изолированная VM + ScyllaHide/TitanHide.
4) Обойти анти-отладку (плагины, патчи проверок).
5) Цель — флаг/лицензия? -> обход ветки проверки.
   Цель — алгоритм?       -> трассировка/девиртуализация.
```

Правило экономии усилий: **обход, а не снятие**. Если нужен флаг или лицензия, полная
девиртуализация избыточна — найдите проверку и обойдите её.

## Мини-разбор: Enigma Protector

Enigma — типичный «упаковщик с анти-отладкой», идеальная тренировка полного цикла.

```text
1) DIE: "Enigma Protector 3.x".
2) Секции .enigma1/.enigma2, высокая энтропия.
3) x64dbg: точка входа в распаковщик; ставим hardware BP на доступ к .enigma2.
4) Дожидаемся записи расшифрованного кода, ловим OEP (переход в .text).
5) Scylla: дамп памяти + восстановление IAT.
6) Проверяем дамп: код читаем, импорты на месте.
```

```bash
python3 -c "import lief;e=lief.parse('enigma.exe');[print(s.name,round(s.entropy,2)) for s in e.sections]"
# .enigma1 7.95
# .enigma2 7.97
# .text    5.80
```

За часы получаем распакованный, читаемый образ. Анти-отладку Enigma обычно снимает ScyllaHide.

## Мини-разбор: Obsidium и .NET Reactor

**Obsidium**: упаковка + мутации без VM. Снимается так же (OEP + дамп), но мутированные
участки упрощают через z3. Секции имеют случайные имена — детект по строке `Obsidium`.

**ConfuserEx / .NET Reactor**: это не нативный протектор, а обфускатор IL. Инструменты другие —
`dnSpy`/`de4dot`, а не Scylla. Детект: метаданные .NET, странные имена методов, control-flow
flattening. Полезно знать, чтобы не искать «секции» там, где их нет.

```bash
# .NET-детект
file app.exe                 # "PE32 executable ... .NET"
strings -a app.exe | grep -iE 'Confuser|Reactor|ConfusedByAttribute'
```

## Подводные камни

Первое: не всякий VM-подобный код — VMP/Themida; бывает самописная VM (см. `reversing-vm-crackmes`).
Второе: детект по одной строке ненадёжен — протектор может маскироваться; комбинируйте признаки.
Третье: анти-дамп портит образ при попытке снять его — используйте аппаратные точки останова и
снимайте до срабатывания. Четвёртое: Themida требует ядерного скрытия отладчика, пользовательских
плагинов недостаточно. Пятое: не тратьте дни на полную девиртуализацию, если цель — флаг.

## Что дальше / решение

1. Возьмите защищённый бинарник и определите протектор через DIE + секции + импорты.
2. Настройте изолированную VM и ScyllaHide.
3. Для упаковщиков (Enigma/Obsidium/ASProtect) снимите дамп и восстановите IAT.
4. Для VMProtect/Themida переходите к уроку `reversing-vmprotect-themida` (VM-диспетчер,
   девиртуализация, обход лицензии).
5. Закрепите на самописной VM: `reversing-vm-crackmes`, затем `reversing-deobfuscation`.
