## Вопрос, с которого всё начинается

В сети найден подозрительный файл `implant.exe`. Он не похож на массовую малварь: нет рекламных модулей, нет майнера. Похоже на целевой инструмент. Как понять его возможности и описать их так, чтобы защита могла реагировать?

## Наш пример

Смотрим на файл:

```
$ file implant.exe
implant.exe: PE32+ executable (console) x86-64, for MS Windows
```

Это PE-бинарник Windows. Дальше мы будем разбирать его по шагам: командная логика → C2 → техники → маппинг на ATT&CK.

## Шаг 1: что такое APT-инструментарий

**APT** (Advanced Persistent Threat) — это группировка, которая целенаправленно и долго атакует конкретные организации. Её инструменты (импланты) обычно **кастомные**: их пишут под кампанию, а не продают массово. Отсюда особенности: минимализм, отсутствие «шумных» функций, аккуратный C2.

Реверс-инженеру важно понять не «что это за вирус», а **какие техники** использует инструмент. Для этого есть общий язык — **MITRE ATT&CK**: каталог техник (Tactic, Technique) с идентификаторами вида `T1059` (Command and Scripting Interpreter).

## Шаг 2: командная логика импланта

Имплант — это удалённая командная оболочка. Его команды почти всегда видны строками:

```
$ strings -n 5 implant.exe | grep -Ei 'shell|upload|download|whoami|sleep'
shell
upload
download
sleep
whoami
nto{apt_1mpl4nt_c0mm4nds}
```

Из этого списка уже видно функциональность: выполнение команд (`shell`), загрузка/выгрузка файлов, разведка (`whoami`), таймауты (`sleep`). Каждая команда — отдельная техника в ATT&CK.

## Шаг 3: кастомный загрузчик

APT-инструменты редко запускаются «в лоб». Их ставит **загрузчик** (loader) — маленький код, который расшифровывает полезную нагрузку в памяти и передаёт управление, не касаясь диска. Признаки: вызовы `VirtualAlloc`, `VirtualProtect`, запись в память и переход по адресу.

В реверсе это значит: сначала найди точку входа загрузчика, пойми алгоритм расшифровки (часто XOR или RC4 с ключом в ресурсах), затем расшифруй пейлоад и анализируй уже его.

## Шаг 4: инфраструктура C2

Имплант должен связываться с оператором. Типовая схема — HTTPS с «прикрытием» под легитимный сервис. В строках ищем:

- URL и User-Agent (часто поддельные, например `Mozilla/5.0`),
- пути (`/api/v1/update`, `/cdn/beacon`),
- параметры-маркеры (`?id=`, `?session=`).

Протокол может быть **malleable** — оператор настраивает его под трафик конкретной сети, поэтому статический поиск домена не всегда срабатывает; тогда анализируют код парсинга ответа.

## Шаг 5: латеральное движение

APT живёт в сети долго, поэтому инструменты умеют двигаться. Признаки в бинарнике: встроенные креды, работа с `SMB`/`WinRM`, использование `PsExec`-подобных техник, дампы `lsass`. Маппинг: `T1021` (Remote Services), `T1003` (OS Credential Dumping), `T1570` (Lateral Tool Transfer).

## Шаг 6: маппинг на MITRE ATT&CK

Собрав наблюдения, составь таблицу «наблюдение → техника». Например:

```
strings 'shell'        -> T1059 Command and Scripting Interpreter
VirtualAlloc + jump    -> T1055 Process Injection / T1027 Obfuscation
sleep                  -> T1497 Virtualization/Sandbox Evasion (jitter)
whoami/hostname        -> T1033 System Owner/User Discovery
```

Такой маппинг — язык общения с SOC: по нему пишут правила и сравнивают кампании.

## Что мы теперь знаем

- APT-инструменты кастомны и минималистичны; цель анализа — техники, не «имя вируса».
- Команды импланта видны строками (`shell`, `upload`, `sleep`).
- Загрузчик расшифровывает пейлоад в памяти (`VirtualAlloc` + переход).
- C2 маскируется под HTTPS; протокол может быть malleable.
- Наблюдения маппятся на MITRE ATT&CK (`T1059`, `T1055`, `T1021`...).

## Куда дальше

Дальше — банкеры и инфостилеры: там техники нацелены на браузер и деньги. Пока главное запомни: **APT-анализ — это перевод наблюдений в техники ATT&CK, а не погоня за красивым именем семейства**.

## Где пригодится

- **SOC/IR:** приоритизация и описание угрозы.
- **Threat intel:** атрибуция кампаний по TTP.
- **Detection engineering:** правила Sigma по техникам.
