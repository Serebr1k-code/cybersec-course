## Вопрос, с которого всё начинается

В сети найден подозрительный файл `implant.exe`. Он не похож на массовую малварь: нет рекламных модулей, нет майнера. Похоже на целевой инструмент. Как понять его возможности и описать их так, чтобы защита могла реагировать?

## Наш пример

Смотрим на файл:

```
$ file implant.exe
implant.exe: PE32+ executable (console) x86-64, for MS Windows
```

Это PE-бинарник Windows. Дальше мы будем разбирать его по шагам: командная логика → C2 → техники → маппинг на ATT&CK.

## Шаг 1: что такое APT-инструментарий

**APT** (Advanced Persistent Threat) — это группировка, которая целенаправленно и долго атакует конкретные организации. Её инструменты (импланты) обычно **кастомные**: их пишут под кампанию, а не продают массово. Отсюда особенности: минимализм, отсутствие «шумных» функций, аккуратный C2.

Реверс-инженеру важно понять не «что это за вирус», а **какие техники** использует инструмент. Для этого есть общий язык — **MITRE ATT&CK**: каталог техник (Tactic, Technique) с идентификаторами вида `T1059` (Command and Scripting Interpreter).

## Шаг 2: командная логика импланта

Имплант — это удалённая командная оболочка. Его команды почти всегда видны строками:

```
$ strings -n 5 implant.exe | grep -Ei 'shell|upload|download|whoami|sleep'
shell
upload
download
sleep
whoami
nto{apt_1mpl4nt_c0mm4nds}
```

Из этого списка уже видно функциональность: выполнение команд (`shell`), загрузка/выгрузка файлов, разведка (`whoami`), таймауты (`sleep`). Каждая команда — отдельная техника в ATT&CK.

## Шаг 3: кастомный загрузчик

APT-инструменты редко запускаются «в лоб». Их ставит **загрузчик** (loader) — маленький код, который расшифровывает полезную нагрузку в памяти и передаёт управление, не касаясь диска. Признаки: вызовы `VirtualAlloc`, `VirtualProtect`, запись в память и переход по адресу.

В реверсе это значит: сначала найди точку входа загрузчика, пойми алгоритм расшифровки (часто XOR или RC4 с ключом в ресурсах), затем расшифруй пейлоад и анализируй уже его.

## Шаг 4: инфраструктура C2

Имплант должен связываться с оператором. Типовая схема — HTTPS с «прикрытием» под легитимный сервис. В строках ищем:

- URL и User-Agent (часто поддельные, например `Mozilla/5.0`),
- пути (`/api/v1/update`, `/cdn/beacon`),
- параметры-маркеры (`?id=`, `?session=`).

Протокол может быть **malleable** — оператор настраивает его под трафик конкретной сети, поэтому статический поиск домена не всегда срабатывает; тогда анализируют код парсинга ответа.

## Шаг 5: латеральное движение

APT живёт в сети долго, поэтому инструменты умеют двигаться. Признаки в бинарнике: встроенные креды, работа с `SMB`/`WinRM`, использование `PsExec`-подобных техник, дампы `lsass`. Маппинг: `T1021` (Remote Services), `T1003` (OS Credential Dumping), `T1570` (Lateral Tool Transfer).

## Шаг 6: маппинг на MITRE ATT&CK

Собрав наблюдения, составь таблицу «наблюдение → техника». Например:

```
strings 'shell'        -> T1059 Command and Scripting Interpreter
VirtualAlloc + jump    -> T1055 Process Injection / T1027 Obfuscation
sleep                  -> T1497 Virtualization/Sandbox Evasion (jitter)
whoami/hostname        -> T1033 System Owner/User Discovery
```

Такой маппинг — язык общения с SOC: по нему пишут правила и сравнивают кампании.

## Шаг 7: классификация импланта по возможностям

Импланты делят по набору команд и автономности. Простой «бэкдор» умеет: выполнить команду, загрузить/скачать файл, поспать. Продвинутый (framework) добавляет: прокси, порт-форвардинг, инъекцию в процессы, работу с несколькими протоколами, модули для конкретных задач (keylogger, screenshot, SOCKS).

Классификация помогает понять уровень угрозы. Признаки «framework»: таблица команд, плагины, конфигурация с множеством опций, поддержка нескольких C2-профилей. Признаки «кастомного минималистичного» импланта: одна-две команды, жёсткий C2, отсутствие обновлений.

## Шаг 8: анализ конфигурации

Многие импланты хранят конфиг зашифрованным (XOR, RC4, AES) или кодированным (base64). Шаги: найти строку-маркер конфига (например, `START`, `CONFIG`, `settings`), определить алгоритм по коду вокруг, расшифровать. Часто конфиг — это структура с фиксированными полями: интервал, список C2, порт, ключ.

```
config: sleep=60, jitter=20%, c2=[https://cdn.example/beacon], useragent=Mozilla/5.0
```

Интервал (`sleep`) и джиттер (`jitter`) — важны для защиты: они определяют периодичность «звонков», по которой строят сетевые детекты.

## Шаг 9: обнаружение и детекты

После разбора ты формулируешь детекты: сетевые (по User-Agent, путям, JA3-отпечатку TLS), хостовые (по строкам, именам мьютексов, ключам реестра), поведенческие (по цепочке действий). Маппинг на ATT&CK делает детекты сравнимыми между кампаниями.

Пример: если имплант использует `VirtualAlloc` + запись + переход, детект на уровне EDR ловит эту последовательность (`T1055`). Если он ходит на `/api/v1/update` с фиксированным User-Agent — сетевой детект по сигнатуре запроса.

## Шаг 10: отчётность для threat intel

Отчёт по APT-инструменту включает: названия (если атрибутирован), TTP-таблицу, IOC (домены, IP, хэши), описание C2-протокола, рекомендации. Такой отчёт используют для: блокировки инфраструктуры, хантирования по историческим логам, обновления правил. Это и есть «конечный продукт» реверса APT-инструментария — не сам факт разбора, а защитные действия на его основе.

## Шаг 11: жизненный цикл APT-атаки и место инструмента

APT-атака — это цепочка стадий: initial access (первичный доступ), execution (исполнение), persistence (закрепление), privilege escalation, defense evasion, credential access, discovery, lateral movement, collection, command and control, exfiltration, impact. Каждый инструмент отвечает за свою стадию, и, разобрав его, ты понимаешь, на какой стадии ты находишься при инциденте.

Наш `implant.exe` — это стадия command and control (плюс execution и частично lateral movement). Загрузчик, который его ставит, — стадия execution и defense evasion. Отдельные утилиты могут отвечать за credential access (дампы lsass) или discovery (сканирование сети).

Такой маппинг позволяет IR-команде быстро понять масштаб: если найден только C2-имплант, возможно, первичный доступ был через фишинг (ищи письмо), а закрепление — через службу или задачу.

## Шаг 12: почему APT-инструменты «скучные» и это важно

В отличие от массовой малвари, APT-инструменты не кричат: нет рекламы, майнера, шифрования файлов. Они делают минимум, чтобы не привлекать внимание. Нет лишних сетевых запросов, нет громких имён файлов, C2 маскируется под обычный трафик.

Для аналитика это означает: отсутствие «ярких» признаков не делает файл безопасным. Наоборот, минимализм — сам по себе признак целевого инструмента. Поэтому в отчёте важны мелочи: необычный User-Agent, интервал опроса с джиттером, специфичный путь запроса.

## Шаг 13: закрепление на нашем примере

Наш `implant.exe`: мы увидели PE, извлекли команды (`shell`, `upload`, `whoami`, `sleep`), вспомнили про загрузчик (`VirtualAlloc` + переход), разобрали C2-инфраструктуру и составили маппинг на MITRE ATT&CK. Это полный первичный разбор APT-инструмента.

Дальше в реальной задаче: расшифровать конфиг, восстановить протокол C2 (как кодируются команды и ответы), найти механизм закрепления (служба, задача, ключ реестра), собрать IOC и оформить детекты. Всё это опирается на понимание, что цель анализа — техники и защитные действия, а не «имя вируса».

## Разбор глубже: как отличить APT-инструмент от commodity-малвари

Признаки целевого инструмента: минимум функций, отсутствие «монетизации» (реклама, майнер, шифровальщик), аккуратный C2, поддержка прокси/туннелей, модульность. Commodity-малварь наоборот: массовая, с рекламой/майнером, простой C2, «одноразовые» домены.

Ещё признак — **качество кода**: APT-инструменты часто написаны аккуратно, с обработкой ошибок, с обфускацией только там, где нужно. Commodity — быстрее и грязнее. Это не абсолютный критерий, но хорошая подсказка.

Также смотри на **целевые артефакты**: список конкретных организаций, доменов, форматов файлов в строках. Если инструмент «знает» про конкретную компанию — он целевой.

## Разбор глубже: как оформить отчёт для IR

Отчёт по APT-инструменту должен быть действенным. Структура: (1) краткое резюме (что за инструмент, стадия атаки); (2) технические детали (структура, C2, команды); (3) TTP-таблица по ATT&CK; (4) IOC (домены, IP, хэши, мьютексы, ключи реестра); (5) детекты (правила); (6) рекомендации (что заблокировать, что проверить).

IOC особенно ценны: по ним IR-команда ищет следы в других системах (хантинг). Даже если сам образец не запускался, домен C2 в логах DNS — доказательство попытки связи. Поэтому реверсер обязан извлечь максимум индикаторов.

Отчёт идёт не «в стол», а в SOC/threat intel, где его превращают в правила и блокировки. Так реверс замыкается на защиту.

## Разбор глубже: почему APT-анализ — это про контекст

Один бинарник сам по себе мало что говорит: важно, в каком контексте он найден. Имплант на рабочей станции финансиста и имплант на сервере в DMZ — это разные истории с разными последствиями. Поэтому аналитик всегда уточняет: где найден образец, когда, с какими другими артефактами.

Контекст меняет приоритеты: если рядом найден дамп `lsass`, значит, вероятно, украдены креденшелы; если в логах есть обращения к C2, значит, связь была установлена. Реверс даёт «что», контекст — «насколько это серьёзно».

Итоговый отчёт объединяет технический разбор и контекст: только тогда он действенен для IR-команды.

## Инструмент: objdump — дизассемблер

`objdump` показывает машинный код бинарника в виде ассемблера. Именно по нему считают смещения буферов, находят вызовы и адреса — основа статического разбора.

Ключи, которые пригодятся:
* `objdump -d <файл>` — дизассемблировать секцию `.text` (машинный код функций);
* `objdump -d <файл> | less` — листать вывод, искать нужную функцию по имени;
* `objdump -M intel -d <файл>` — синтаксис Intel (привычнее, чем AT&T);
* в выводе важны пролог функции (`push rbp; mov rbp,rsp`) и `sub rsp,N` — по нему видно размер кадра.

### Рабочий пример (как в лаборатории)

```
$ objdump -d implant.exe
implant.exe:     file format pei-x86-64
Disassembly of section .text:
140001000 <main>:
140001000:	ff 15 f3 0f 00 00 	call QWORD PTR [rip+0xff3]  ; VirtualAlloc
140001007:	ff e0            	jmp rax
```

Подсказка из лаборатории: `objdump [-d] <файл> — дизассемблер PE`.

## Что мы теперь знаем

- APT-инструменты кастомны и минималистичны; цель анализа — техники, не «имя вируса».
- Команды импланта видны строками (`shell`, `upload`, `sleep`).
- Загрузчик расшифровывает пейлоад в памяти (`VirtualAlloc` + переход).
- C2 маскируется под HTTPS; протокол может быть malleable.
- Наблюдения маппятся на MITRE ATT&CK (`T1059`, `T1055`, `T1021`...).
