**Keygen** — это программа, которая генерирует валидные лицензионные ключи/серийники, восстановив алгоритм проверки из бинарника. Это классическая задача реверса: понять, как приложение проверяет ключ, и либо воспроизвести алгоритм (keygen), либо обойти проверку (патч). Урок разбирает типы проверок, техники разбора серийников, асимметричную крипту в лицензиях и полный разобранный пример с решателем.

## Что такое keygen и зачем

- **CTF/обучение** — типичная задача «сгенерируй валидный ключ».
- **Совместимость** — восстановление доступа к легально купленному ПО при утере ключа.
- **Анализ защиты** — понимание схемы лицензирования.
- **Этическая граница**: keygen для обхода лицензий проприетарного ПО — юридически спорно; применяйте в рамках обучения/аудита и закона.

## Типы лицензионных проверок

| Тип | Как работает | Сложность keygen |
|---|---|---|
| Прямое сравнение | ввод == константа | тривиально (просто строку) |
| Алгоритмический серийник | по входу вычисляется хеш, сверяется | средняя |
| Имя+серийник | ключ зависит от имени пользователя | средняя |
| Контрольная сумма/CRC | серийник удовлетворяет CRC-свойству | средняя |
| Блочные шифры | серийник — расшифрованный блок | высокая |
| Асимметричная крипта (RSA/ECDSA) | подпись проверяется публичным ключом | практически невозможно (только патч) |

Ключевой вывод: **при асимметричной подписи keygen невозможен** — приватный ключ у вендора; остаётся только патч проверки.

## Разбор serial-check

Стандартный маршрут: найти точку ввода → найти сравнение → восстановить алгоритм.

```bash
# в Ghidra/IDA: найти обработчик ввода (GetWindowText/scanf/argv)
# найти функцию проверки (xref от строк "Invalid serial")
strings -a ./app | grep -iE 'invalid|serial|license|key'
```

Пример псевдокода проверки:

```c
bool check_serial(const char *s) {
    if (strlen(s) != 16) return false;
    unsigned sum = 0;
    for (int i = 0; i < 16; i++) sum += s[i] * (i + 1);
    return (sum == 0x1234);
}
```

Keygen воспроизводит `check_serial` наоборот: подбирает строку с нужной суммой.

## Алгоритмы: хеш, CRC, блочные

- **Хеш (MD5/SHA).** Серийник — это хеш от имени/константы; keygen просто вычисляет хеш.
- **CRC/контрольная сумма.** Серийник удовлетворяет CRC-свойству; keygen подбирает байты.
- **Блочные шифры (AES/DES).** Серийник расшифровывается и проверяется на структуру; keygen шифрует нужный plaintext.
- **Собственные алгоритмы.** Разбираются по дизассемблеру — ищите циклы, таблицы, константы.

```bash
# найти крипто-константы
strings -a ./app | grep -iE 'expand 32-byte|Rijndael|MD5'
# в Ghidra — поиск S-box AES
```

## Асимметричная криптография в лицензиях

Современные лицензии часто используют **RSA/ECDSA-подпись**: вендор подписывает данные лицензии приватным ключом, приложение проверяет публичным.

- **Keygen невозможен** без приватного ключа (при корректной реализации).
- **Атаки**: слабый/маленький ключ (факторизация), повторно используемый nonce в ECDSA (восстановление ключа), ошибки реализации.
- **Обход**: патч проверки подписи (заменить `return false` на `return true`) — типовое решение для таких задач.

```c
// проверка подписи
if (!verify_signature(license, sig, pubkey)) return LICENSE_INVALID;
// обход: патч -> всегда true, либо подмена pubkey
```

## Патчинг vs keygen

| Подход | Плюс | Минус |
|---|---|---|
| Keygen | генерирует валидные ключи, «чисто» | невозможен при асимметричной подписи |
| Патч проверки | работает всегда | меняет бинарник, хрупко при CRC |
| Подмена pubkey | для RSA/ECDSA | нужен свой ключ и патч |

Часто практичнее **патч**: инвертировать ветку или заменить возврат функции проверки. Инструменты: Ghidra/IDA patch, `keypatch` (плагин IDA для ассемблерных патчей), r2 `wa`.

## Инструменты

| Инструмент | Назначение | Пример |
|---|---|---|
| Ghidra/IDA | анализ и патч | decompile, patch |
| `keypatch` | ассемблерный патч в IDA | `-` |
| r2 | патч | `wa jmp 0x...` |
| x64dbg | динамический патч | правка в рантайме |
| Python | keygen | реализация алгоритма |

## Разобранный пример: полный keygen

**Шаг 1. Найти проверку** (Ghidra). Функция `validate`:

```c
int validate(char *s) {
    if (strlen(s) != 8) return 0;
    for (int i = 0; i < 8; i++)
        if ((s[i] ^ 0x42) != expected[i]) return 0;
    return 1;
}
```

**Шаг 2. Извлечь `expected`.** В дампе по адресу таблицы:

```bash
# дамп 8 байт expected
r2 -qc 'px 8 @ 0x404060' ./app
# 0a 3f 2e 3c 4a 5d 0e 3a
```

**Шаг 3. Написать keygen.**

```python
expected = bytes.fromhex("0a3f2e3c4a5d0e3a")
key = bytes(b ^ 0x42 for b in expected)
print(key.decode())   # валидный серийник
```

**Шаг 4. Проверить.**

```bash
./app <<< "$(python3 keygen.py)"
# License OK
```

## Разобранный пример: keygen с именем

Иногда серийник зависит от имени: `serial = f(name)`.

```c
unsigned h = 0;
for (i = 0; name[i]; i++) h = h * 31 + name[i];
sprintf(buf, "%08X", h ^ 0xDEADBEEF);
if (strcmp(buf, serial) == 0) ok();
```

Keygen:

```python
name = "Alice"
h = 0
for ch in name:
    h = (h * 31 + ord(ch)) & 0xFFFFFFFF
serial = "%08X" % (h ^ 0xDEADBEEF)
print(serial)
```

## Частые ошибки и подводные камни

- **Попытка keygen при асимметричной подписи.** Невозможно — переходите к патчу.
- **Обфускация алгоритма.** Opaque-предикаты и запутанные вычисления; нормализуйте или эмулируйте.
- **Проверка через CRC кода.** Патч обнаружится — хукайте проверку.
- **Забыть про длину/формат.** Многие проверки включают `strlen`, дефисы, регистр.
- **Ошибка в решателе.** Проверяйте на реальном бинарнике, а не «на глаз».
- **Юридическая сторона.** Не используйте keygen для обхода лицензий без прав.

## Что дальше / решение

Маршрут: **найти проверку → понять алгоритм → keygen (или патч при асимметричной крипте) → проверить**. Для простых серийников — обратный алгоритм; для хешей — вычисление; для подписи — патч. Дальше — `reversing-patching`, `reversing-crypto-binaries` и `reversing-rust-go` (если таргет на Rust/Go).

## Разбор алгоритма: практические приёмы

Когда алгоритм запутан, помогает эмуляция. r2/ESIL или angr позволяют «прогнать» функцию проверки с конкретным входом и посмотреть промежуточные значения.

```bash
# r2: эмуляция функции с конкретным аргументом
r2 -A ./app
[0x...]> s sym.validate
[0x...]> aeim; aei
[0x...]> aeip
[0x...]> ; установить аргумент в rdi (указатель на строку)
[0x...]> aes; aer      # шаг и регистры
```

Для keygen-задачи эмуляция позволяет **не разбирать** алгоритм целиком: подавайте входы, наблюдайте выход и подбирайте. Если функция детерминирована и локальна — это быстрее ручного разбора.

## Работа с таблицами и константами

Многие серийники используют таблицы подстановки (S-box) или магические константы. Их нужно извлечь из дампа.

```bash
# дамп таблицы по адресу
r2 -qc 'px 256 @ 0x404080' ./app
# в Ghidra: правый клик на адресе -> Data -> определить как массив байт
```

Затем таблица используется в вашем keygen-скрипте напрямую. Часто достаточно **скопировать** таблицу, а не восстанавливать её генерацию.

## Keygen для CRC-серийников

Если серийник должен удовлетворять CRC-условию, keygen решает обратную задачу: подобрать последние байты так, чтобы CRC совпал.

```python
import zlib
# подбор 4 байт, дающих нужный CRC
target = 0x12345678
base = b"KEY-0000-"
for i in range(0x100000000):
    tail = i.to_bytes(4, "big")
    if zlib.crc32(base + tail) & 0xFFFFFFFF == target:
        print((base + tail).decode()); break
```

Для линейных CRC можно решить алгебраически (без перебора) — CRC линеен над GF(2), и хвост вычисляется обратной матрицей.

## Патч как альтернатива: keypatch

В IDA плагин **keypatch** позволяет писать патчи прямо на ассемблере, не считая байты.

```text
# в IDA: Edit -> Keypatch -> Assemble
# заменить проверку:
mov eax, 1
retn
```

Аналогично в x64dbg: правите инструкцию в рантайме и применяете к файлу. Патч — быстрый путь, когда keygen невозможен (асимметричная крипта) или не нужен.

## Итоговый маршрут keygen

1. Найти проверку (строки «invalid/license», xref от ввода).
2. Понять тип: прямое сравнение / алгоритм / CRC / блочный шифр / подпись.
3. Извлечь константы/таблицы.
4. Реализовать обратный алгоритм (или подобрать/эмулировать).
5. Проверить сгенерированный ключ на бинарнике.
6. Если подпись асимметричная — переходить к патчу.

## Реверс лицензий в Rust/Go/Java

Современные приложения на Rust/Go/Java имеют свои особенности.

- **Go**: строки — пары (ptr, len); проверки часто в `main.checkSerial`; восстанавливайте имена через `redress`/`GoReSym`.
- **Rust**: мономорфизация и `unwrap`-паники отмечают проверки; деманглируйте символы `rustfilt`.
- **Java/JAR**: декомпилируйте `jd-cli`/`cfr`, ищите методы `validate`/`checkLicense`; обфускация (ProGuard) переименовывает, ориентируйтесь на строки.

```bash
# Java
jd-cli app.jar -od out/
grep -rn 'serial\|license' out/ | head
```

Логика везде одна: найти проверку → восстановить алгоритм → keygen/патч. Меняется лишь инструмент навигации по коду.

## Итоговый чеклист keygen-задачи

1. Локализовать проверку (строки «invalid/license», xref от ввода, точка ввода).
2. Классифицировать схему: сравнение / алгоритм / CRC / блочный шифр / асимметричная подпись.
3. Извлечь константы, таблицы, публичный ключ.
4. Реализовать обратный алгоритм на Python; при невозможности — эмулировать/подобрать.
5. Проверить сгенерированный ключ на реальном бинарнике (read-back: «License OK»).
6. Для асимметричной крипты — патчить проверку, а не генерировать ключ.

Этот чеклист применим и к CTF, и к аудиту лицензионной защиты.
