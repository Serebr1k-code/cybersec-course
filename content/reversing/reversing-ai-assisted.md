**AI-ассистированный реверс** — это использование LLM (ChatGPT, Claude, локальные модели) и ML-инструментов для ускорения анализа бинарников: объяснение декомпилированного кода, восстановление имён и типов, генерация скриптов, поиск паттернов. Урок даёт практический workflow: какие задачи отдавать модели, как строить промпты, как интегрировать LLM в Ghidra/IDA/r2 и где модели ошибаются — чтобы вы не доверяли им слепо.

## Роль LLM в реверсе

LLM хорошо решают **локальные, текстовые** подзадачи и плохо — задачи, требующие точного состояния процесса:

- **Хорошо**: объяснить функцию на C/псевдо-C, предложить осмысленные имена, распознать алгоритм (AES, base64, CRC), сгенерировать декодер, написать IDAPython/Ghidra-скрипт, перевести ассемблер в C.
- **Плохо**: точные адреса, реальное поведение рантайма, криптоанализ, «угадать флаг», длинные цепочки без проверки.

Правильная рамка: LLM — **ускоритель гипотез**, а не источник истины. Каждую гипотезу проверяйте инструментом.

## Типовые задачи и промпты

1. **Объяснение функции.** «Вот декомпилированный C. Что делает функция? Опиши входы/выходы, побочные эффекты.»
2. **Именование.** «Предложи осмысленные имена для переменных и функции на основе поведения.»
3. **Распознавание алгоритма.** «Какой алгоритм реализует этот код? Есть ли константы, указывающие на AES/CRC?»
4. **Реверс формата.** «Разбери структуру этого бинарного блока: смещения, поля, размеры.»
5. **Генерация кода.** «Напиши Python-скрипт, который реализует обратную операцию к этому коду.»
6. **Ассемблер → C.** «Переведи этот фрагмент x86-64 в C с пояснениями.»

Шаблон хорошего промпта:

```
Контекст: x86-64 ELF, декомпилятор Ghidra, функция вызывается из main.
Задача: объяснить логику и предложить имена.
Ограничения: не выдумывай адреса; если не уверен — скажи.
Код:
<декомпилированный C>
```

## Workflow: объяснение декомпиляции

```bash
# 1) получить псевдо-C (Ghidra headless или вручную)
# 2) очистить и отдать в LLM
# 3) проверить гипотезу динамически
```

Пример псевдо-C:

```c
undefined8 FUN_00401200(char *param_1) {
  size_t sVar1 = strlen(param_1);
  if (sVar1 != 0x10) return 0;
  for (int i = 0; i < 0x10; i = i + 1) {
    if ((param_1[i] ^ 0x5a) != (&DAT_00404060)[i]) return 0;
  }
  return 1;
}
```

Промпт даёт ответ: «проверка длины 16, XOR с 0x5a, сравнение с таблицей по 0x404060». Проверка в gdb/r2 подтверждает — и вы уже знаете, что искать.

## Автопереименование и восстановление типов

LLM можно использовать как «советника» для аннотации. Скрипт, который готовит батч-запросы и применяет ответы:

```python
# собрать функции, отправить в LLM, применить имена
import json
funcs = [{"addr": "0x401200", "code": "..."}, ...]
prompt = "Для каждой функции предложи короткое имя в snake_case. Верни JSON addr->name."
# ... вызов API ...
names = json.loads(response)
for addr, name in names.items():
    idc.set_name(int(addr, 16), name, idc.SN_NOWARN)
```

Важно: **всегда просматривайте** предложенные имена — модель может назвать функцию `decrypt_flag`, хотя это просто `memcpy`.

## Интеграция с Ghidra/IDA/r2

- **Ghidra**: плагин `GhidraGPT`/скрипт, отправляющий декомпиляцию текущей функции и вставляющий ответ как комментарий/имя.
- **IDA**: `ida-llm`/`AIAssistant` — панель, где можно спросить о функции и получить псевдо-объяснение.
- **radare2**: `r2ai` — плагин для LLM-запросов прямо из r2 (`r2ai -d` для explain).
- **Binary Ninja**: `BinaryNinjaLLM`.

```bash
# r2ai пример
r2 -qc 'r2ai -d' ./target
# спрашивает модель про функцию на текущем адресе
```

## Локальные модели vs облако

| Критерий | Облако (GPT/Claude) | Локально (Llama/Qwen/DeepSeek) |
|---|---|---|
| Качество | высокое | растёт, но ниже |
| Приватность | код уходит наружу | всё локально |
| Стоимость | за токены | железо |
| Оффлайн | нет | да |
| Для секретных образцов | **нет** | да |

Для malware/приватных бинарников — **только локальные модели** (иначе утечка образца/кода на чужой сервер). Квантованные модели (GGUF, Q4) запускаются на потребительском железе.

## Разобранный пример: понять функцию через LLM

**Шаг 1. Получить псевдо-C** (r2 + декомпилятор или Ghidra).

```bash
r2 -A ./target -qc 's main; pdf' 
# или Ghidra: DecompInterface
```

**Шаг 2. Промпт.** Отправляем код с контекстом (архитектура, компилятор, назначение).

**Шаг 3. Гипотеза.** Модель: «функция вычисляет CRC32 табличным методом». 

**Шаг 4. Проверка.**

```bash
# проверяем: подаём строку, сравниваем с известным CRC32
./target --crc "test"       # выводит число
python3 -c 'import zlib; print(hex(zlib.crc32(b"test")))'
# совпало -> гипотеза верна
```

**Шаг 5. Применение.** Переименовываем функцию в `crc32_table`, комментируем таблицу.

## Ограничения и галлюцинации

- **Выдуманные адреса/символы.** Модель «помнит» похожий бинарник и приписывает чужие функции.
- **Уверенные ошибки.** Особенно в криптоанализе и в оценке поведения рантайма.
- **Устаревший контекст.** Длинные функции обрезаются — модель видит не всё.
- **Утечка.** Отправка образца/декомпиляции в облако — риск для приватных данных.
- **Не заменяет динамику.** LLM не запускает код; проверка только инструментами.

## Таблица инструментов

| Инструмент | Назначение | Примечание |
|---|---|---|
| ChatGPT/Claude | объяснение, скрипты | облако, не для секретов |
| Llama/Qwen/DeepSeek | локальный ассистент | приватность |
| GhidraGPT | LLM в Ghidra | плагин |
| r2ai | LLM в radare2 | `r2ai -d` |
| ida-llm | LLM в IDA | плагин |
| CodeQL/Semgrep | статический анализ | не LLM, но дополняет |

## Что дальше / решение

Используйте LLM как **первый проход**: объяснить функцию, предложить имена, распознать алгоритм, сгенерировать скрипт — затем **обязательно проверьте** динамикой (gdb/r2/запуск) или символьным исполнением. Для приватных образцов — локальная модель. Комбинируйте AI-гипотезы с `reversing-symbolic-execution` (проверка гипотез) и `reversing-decompiler-plugin` (автоматизация). Дальше — `reversing-analysis-methodology`, чтобы встроить AI в системный процесс, а не в случайные запросы.

## Промпт-инжиниринг: шаблоны под задачу

Качество ответа зависит от контекста. Три рабочих шаблона:

```
# 1) Объяснение функции
Ты — реверс-инженер. Архитектура: x86-64, компилятор GCC -O2.
Ниже декомпилированный C. Объясни назначение, входы/выходы и побочные эффекты.
Не выдумывай адреса и не угадывай флаг; если данных мало — скажи.
<code>

# 2) Генерация декодера
Вот алгоритм кодирования (C). Напиши на Python обратную функцию decode(data: bytes) -> bytes.
Учти порядок байт и границы. Приведи пример вызова.
<code>

# 3) Восстановление структуры
Дана функция парсинга. Опиши структуру сообщения: смещения, размеры, типы полей.
Верни таблицу поле|смещение|размер|тип.
<code>
```

Ключевые приёмы: давать архитектуру и оптимизацию, требовать явно указывать неопределённость, просить структурированный вывод (JSON/таблица), разбивать большие функции на части.

## Автоматизация батч-аннотации: полный скрипт

Скрипт готовит декомпиляцию каждой функции, шлёт в LLM и применяет предложенные имена (с ручной проверкой).

```python
import json, subprocess
import idautils, idaapi, idc

def decompile(ea):
    import ida_hexrays
    cf = ida_hexrays.decompile(ea)
    return str(cf) if cf else ""

def ask_llm(code):
    # заглушка: реальный вызов API/локальной модели
    prompt = ("Предложи имя функции в snake_case и короткое описание. "
              "Верни JSON {\"name\":..., \"desc\":...}.\n" + code)
    return json.loads(call_api(prompt))

for ea in idautils.Functions():
    code = decompile(ea)
    if not code:
        continue
    ans = ask_llm(code)
    idc.set_name(ea, ans["name"], idc.SN_NOWARN)
    idc.set_func_cmt(ea, ans["desc"], 0)
    print("%X -> %s" % (ea, ans["name"]))
```

Обязательно логируйте `(addr, code, ответ)` — чтобы откатить сомнительные переименования.

## Оценка качества: метрики и валидация

- **Проверка динамикой.** Гипотезу об алгоритме подтверждайте запуском/трассой.
- **Проверка символьным исполнением.** angr докажет/опровергнет условие ветвления.
- **Согласованность.** Спросите модель дважды разными формулировками — расхождения сигнал ошибки.
- **Компиляция сгенерированного кода.** Скрипт-декодер должен собираться и давать верный результат на тесте.
- **Не доверять адресам.** Любой адрес из ответа проверяйте в дизассемблере.

## Этические и юридические аспекты

- **Приватность образцов.** Отправка malware/декомпиляции в облако может нарушать NDA/законы; для чувствительных данных — локальные модели.
- **Авторские права.** Не публикуйте декомпилированный проприетарный код целиком.
- **Ответственность.** Сгенерированный «эксплойт» без понимания опасен; ответственность на аналитике.
- **Прозрачность.** В отчётах указывайте, где применялся AI, а где — ручная верификация.

## Ключевые выводы по AI-ассистированному реверсу

Итог: LLM — ускоритель гипотез для **локальных текстовых** задач (объяснение, именование, распознавание алгоритма, генерация скриптов). Никогда не доверяйте выводу без проверки динамикой/символикой. Для секретных образцов — локальная модель. Соединяйте AI с `reversing-symbolic-execution` и `reversing-decompiler-plugin`, встраивая его в системный процесс анализа.

## Практика: реверс протокола с помощью LLM

Когда бинарник общается по сети, LLM ускоряет разбор формата сообщений.

**Шаг 1. Собрать примеры.** Перехватите несколько сообщений (Wireshark/tcpdump) и декомпилируйте функции чтения/записи.

**Шаг 2. Промпт на структуру.** «Вот функция parse_msg на C и hex трёх сообщений. Опиши формат: magic, длина, тип, поля. Верни таблицу.»

**Шаг 3. Гипотеза.** Модель: «magic=0xCAFE, 2 байта длина LE, 1 байт тип, далее payload». 

**Шаг 4. Проверка.** Скармливаете парсеру синтезированное сообщение и смотрите, принимает ли он его. Если да — формат восстановлен.

**Шаг 5. Автоматизация.** Просите сгенерировать Python-парсер и сразу используете его для дальнейшего фаззинга.

## Пример сессии r2ai

```bash
r2 -A ./target
[0x00401000]> aaa
[0x00401000]> s sym.check_password
[0x00401200]> r2ai -d          # объяснить текущую функцию
# LLM: "функция сравнивает ввод с зашифрованной строкой, XOR 0x5a"
[0x00401200]> r2ai -q "напиши gdb-скрипт для перехвата этой функции"
```

Ответы вставляются как комментарии к функции, что ускоряет навигацию по бинарнику.

## Ограничения контекста и разбиение

Длинные функции не влезают в контекст модели. Приёмы: разбивать по базовым блокам, давать только релевантный фрагмент, суммировать промежуточные выводы, использовать модель с большим контекстом. Для рекурсивных структур — описывать их схемой, а не полным кодом.

## Ключевой практический вывод

LLM максимально полезен на этапе **гипотез и черновиков** (объяснение, имена, скрипты), но каждую гипотезу закрывайте инструментом: запуск, gdb-трасса, angr. Это даёт ускорение в разы без потери корректности.
