## Вопрос, с которого всё начинается

Ты запускаешь `strings malware.exe` в надежде найти домен C2, но видишь только мусор: `xWq3`, `aB9!`. А в отладчике строки откуда-то появляются. Как малварь прячет строки и как их достать?

## Наш пример

`strings.bin` — блоб, в котором лежат зашифрованные строки. `strings` покажет случайные символы. Мы разберём, как они шифруются, и расшифруем.

## Шаг 1: зачем прятать строки

Строки — самый быстрый путь к пониманию малвари. Домен C2, путь к файлу, ключ реестра, имя процесса — всё это строки. Если они лежат открытым текстом, аналитик (или антивирус по YARA) найдёт их за секунды.

Поэтому обфускаторы и малварь прячут строки: в бинарнике нет читаемого текста, а строки собираются **во время выполнения**. При статическом анализе ты видишь мусор.

## Шаг 2: XOR-шифрование строк

Самый частый приём — **XOR** каждого байта строки с ключом:

```c
char enc[] = {0x2f, 0x3a, 0x3a, 0x3b};   // зашифровано
for (i = 0; i < len; i++) buf[i] = enc[i] ^ 0x5e;
// -> "http"
```

XOR обратим: то же действие расшифровывает. Ключ может быть однобайтовым, многобайтовым (повторяющимся) или зависеть от позиции. Однобайтовый XOR легко ломается частотным анализом; многобайтовый — сложнее.

## Шаг 3: stack-strings

**Stack-strings** — строки, которые собираются прямо на стеке по частям, чтобы не лежать в памяти целиком:

```asm
mov dword ptr [rsp+0], 70747468h    ; 'http'
mov dword ptr [rsp+4], 2f3a2f73h    ; 's:/:'
mov word  ptr [rsp+8], 002fh         ; '/'
```

В дампе ты не найдёшь строку `http://...` — она появляется на стеке только при исполнении. Антивирусы, сканирующие статически, её не увидят. Восстановление: собрать константы, которые пишутся в стек, в одну строку.

## Шаг 4: API hashing

Вместо имён функций хранятся их **хеши**. Имплант обходит список экспортов модуля, считает хеш имени каждой функции и сравнивает со своей константой:

```c
if (hash("CreateProcessA") == 0xAABBCCDD) { ... }
```

В бинарнике нет строки `CreateProcessA` — только число `0xAABBCCDD`. Чтобы восстановить, нужно **знать алгоритм хеша** (CRC32, djb2, FNV, кастомный) и посчитать его для всех имён экспортов. Тогда число превращается в имя функции.

Это напрямую связано с уроком про PEB: ручной обход загрузчика + API hashing = полная скрытность вызовов.

## Шаг 5: расшифровка скриптом

Скрипт `decstrings.py` применяет найденный ключ к блобу:

```bash
$ python3 decstrings.py strings.bin
key = 0x5e (single-byte XOR)
[0] http://10.10.20.7/gate.php
[1] SOFTWARE\Microsoft\Windows\CurrentVersion\Run
[2] cmd.exe /c whoami
[3] nto{x0r_str1ngs_d3crypt3d}
```

Мы получили реальные строки — и это уже готовая разведка: C2, персистентность, команды.

## Шаг 6: как искать ключ

Если ключ неизвестен:

1. **Найди функцию-дешифратор** — она вызывается перед использованием строк; часто одна.
2. **Посмотри на константу XOR** в её коде.
3. **Частотный анализ** — для однобайтового XOR подбери ключ по ожидаемым символам (`http`, `\`, `.exe`).
4. **Эмуляция** — если алгоритм сложный, эмулируй функцию (см. P-Code) на зашифрованном блобе.

Именно поэтому дешифратор — одна из первых целей при реверсе малвари: найдя его, ты «открываешь» все строки сразу.

## Что мы теперь знаем

- Строки прячут, чтобы сорвать статический анализ и YARA.
- XOR — самый частый метод; ключ бывает одно- и многобайтовым.
- Stack-strings собираются на стеке по частям.
- API hashing прячет имена функций за числами.
- Найденный дешифратор раскрывает все строки разом.

## Шаг 7: многобайтовый XOR и его вскрытие

Однобайтовый XOR ломается частотным анализом. Многобайтовый (ключ длиной N) — сложнее, но тоже вскрывается:

1. **Определи длину ключа.** Попробуй разные N и смотри, при каком позиции «выравниваются» по частотным признакам.
2. **Разбей на N колонок.** Байты на позициях `i, i+N, i+2N...` зашифрованы одним байтом.
3. **Вскрой каждую колонку** как однобайтовый XOR (по ожидаемым символам: пробел, `\`, `.exe`, `http`).

Так восстанавливают даже длинные строки. Инструмент `xortool` автоматизирует это.

## Шаг 8: ключ, зависящий от позиции

Иногда ключ не константа, а функция позиции: `key[i] = i & 0xFF` или `key[i] = hash(i)`. Тогда XOR становится похож на шифр потока. Восстановление: зная алгоритм генерации ключа (из дешифратора), воспроизвести его. Если алгоритм неизвестен — эмулировать функцию генерации.

## Шаг 9: аддитивные и другие трансформации

XOR — не единственный. Часто используют:

- **сложение/вычитание константы** (`c[i] = s[i] + k`);
- **перестановку байт** (обратный порядок, swap);
- **замену по таблице** (S-box);
- **комбинации** (XOR + swap + add).

Ключ к вскрытию — найти дешифратор и понять, какие операции он делает в каком порядке. Эмуляция тут снова помогает.

## Шаг 10: API hashing подробнее

Хеши имён функций считают разными алгоритмами:

| Алгоритм | Формула |
|---|---|
| ROR13 | `h = ror(h,13) + c` |
| djb2 | `h = h*33 + c` |
| FNV-1a | `h = (h ^ c) * prime` |
| CRC32 | стандартный |

Зная алгоритм, строишь таблицу «хеш → имя» из списка экспортов и переводишь константы в бинаре обратно в имена. Инструменты (`api_hash.py`) поддерживают все популярные.

## Шаг 11: автоматизация расшифровки

Пайплайн: найти дешифратор (одна функция, вызывается часто) → понять алгоритм → применить ко всем блобам → получить строки. Часто дешифратор обфусцирован, тогда его эмулируют на каждом блобе.

```bash
$ python3 strings_pipeline.py sample.exe
found decryptor @ 0x401230 (xor, key from rdata)
decrypted 47 strings:
  http://c2.example/gate
  SOFTWARE\...\Run
  ...
```

## Шаг 12: таблица приёмов

| Приём | Сложность вскрытия | Метод |
|---|---|---|
| XOR 1 байт | низкая | частотный анализ |
| XOR N байт | средняя | разбиение по колонкам |
| позиционный ключ | высокая | эмуляция генератора |
| аддитивная | низкая | подбор константы |
| S-box | средняя | инверсия таблицы |
| API hashing | средняя | таблица хешей |

## Шаг 13: почему это критично в IR

В реагировании на инциденты строки — это индикаторы: домены, пути, ключи реестра. Без их расшифровки ты не поймёшь, что делала малварь и куда ходила. Поэтому дешифровка строк — один из первых шагов анализа, и она напрямую питает YARA/Sigma-правила.

## Шаг 14: итоговый алгоритм

Запусти `strings` — убедись, что строки скрыты. Найди дешифратор (часто вызываемая функция с XOR/сложением). Пойми алгоритм и ключ. Примени ко всем блобам (или эмулируй). Собери строки — это твоя разведка. Для API hashing построй таблицу имён. Главное: **малварь прячет данные так же тщательно, как код, и дешифратор — ключ ко всему**.

## Шаг 15: строки как источник индикаторов

В реагировании на инциденты расшифрованные строки — это готовые индикаторы компрометации. Домен C2 превращается в правило блокировки, путь персистентности — в правило детекта, имя mutex — в сигнатуру. Поэтому дешифровка строк — не академическое упражнение, а практический шаг, который сразу даёт результат. Аналитик, который расшифровал строки, уже знает, что делает малварь: куда ходит, что запускает, где прячется. Это экономит часы динамического анализа. И наоборот: без расшифровки ты смотришь на бессмысленные байты и не понимаешь ни назначения образца, ни его связей. Вот почему первым делом после базовой статики берутся именно за строки.

## Шаг 16: строки в разных языках и форматах

Строки прячут не только в нативных бинарниках. В .NET — через обфускаторы (ConfuserEx); в JavaScript — через eval и упаковщики; в Python — через base64 и marshal; в PowerShell — через Invoke-Obfuscation. Приёмы различаются, но принцип один: строка не лежит открытым текстом, а собирается в рантайме. Значит, и подход один: найти сборщик (дешифратор) и воспроизвести его. Для управляемых языков это часто проще — можно запустить код в песочнице и перехватить результат. Для нативных — сложнее, нужна эмуляция. Понимание общего принципа позволяет переносить навык между платформами.

## Шаг 17: почему дешифратор — приоритетная цель

Дешифратор — это «ключ» ко всем строкам сразу. Найдя одну функцию, ты открываешь сотни строк. Поэтому опытные аналитики ищут её целенаправленно: смотрят, какая функция вызывается перед использованием буфера; ищут цикл с XOR; проверяют, что возвращает функция. Часто дешифратор вызывается из множества мест — это тоже признак. Найдя его, ты можешь применить его ко всем зашифрованным блобам пакетно, а не разбирать каждую строку вручную. Это превращает задачу «расшифровать всё» в задачу «найти одну функцию и запустить её на всех данных».

## Шаг 18: вывод

Строковые обфускации — массовое явление, но не непреодолимое. Приёмы (XOR, stack-strings, API hashing, S-box, перестановки) известны, и для каждого есть метод вскрытия. Ключ — найти дешифратор и понять алгоритм, а дальше применить пакетно или эмулировать. Расшифрованные строки сразу дают индикаторы и понимание назначения образца. Поэтому дешифровка строк — обязательный этап анализа, а не опциональный. Освоив его, ты получаешь быстрый путь к сути малвари, минуя долгий разбор обфусцированной логики.
