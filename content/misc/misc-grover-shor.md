## Вопрос, с которого всё начинается

Все говорят «квантовый компьютер сломает RSA», но мало кто может объяснить, **как**. Ответ короткий: через поиск периода функции. Разберём это на числе, которое реально можно прогнать, и увидим, где именно квантовость даёт выигрыш.

## Наш пример: факторизуем N = 15

Возьмём маленькое `N` и функцию `f(x) = a^x mod N`. Для `a = 2`, `N = 15`:

```
$ python3 - <<'PY'
N=15; a=2
seq=[pow(a,x,N) for x in range(16)]
print(seq)
PY
[1, 2, 4, 8, 1, 2, 4, 8, 1, 2, 4, 8, 1, 2, 4, 8]
```

Заметили? Значения повторяются с периодом 4. Этот период — ключ ко всему.

## Шаг 1: зачем нужен период

Классический факт: если для `a` взаимно простого с `N` мы знаем период `r` функции `a^x mod N`, то при чётном `r` числа `gcd(a^(r/2) ± 1, N)` дают нетривиальные делители `N`. Проверим руками:

```
$ python3 - <<'PY'
import math
N=15; a=2; r=4
print(math.gcd(a**(r//2)-1,N), math.gcd(a**(r//2)+1,N))
PY
3 5
```

Получили 3 и 5 — делители 15. Вся факторизация свелась к поиску периода.

## Шаг 2: почему классически это тяжело

Найти период классически — значит перебирать `x` до повторения, то есть порядка `N` шагов. Для RSA-2048 `N` астрономически велико. **Алгоритм Shor** находит период за полиномиальное время: квантовое преобразование Фурье превращает «скрытую периодичность» в пики вероятности, которые видно при измерении. Один замер — и с высокой вероятностью мы знаем `r`.

Это и есть весь фокус: классический перебор заменяется квантовым преобразованием Фурье. Никакой «магии» — линейная алгебра над амплитудами.

## Шаг 3: Grover — другой тип ускорения

Grover не ищет периоды. Он решает задачу **неструктурированного поиска**: найти `x` среди `M` вариантов, для которого `f(x) = 1`. Классически нужно ~`M` попыток, Grover — ~`sqrt(M)`.

Что это значит на практике:

- Перебор ключа AES-128 (2^128 вариантов) ускоряется до 2^64 — всё ещё невозможно, но запас сокращается.
- AES-256 остаётся стойким: 2^128 квантовых шагов недостижимы.
- Хеш-поиск (preimage) 256-битного хеша — 2^128, всё ещё вне досягаемости.

Правило простое: **против Grover удваивай длину ключа/хеша**, против Shor меняй сам алгоритм (RSA/ECC → PQC).

## Шаг 4: моделируем маленький Shor

В симуляторе можно собрать схему поиска периода для N=15 и убедиться, что измерение даёт кратные `1/r`:

```
$ python3 -c "from qiskit.algorithms import Shor; print(Shor(15).factor())"
{'factors': [3, 5], 'total_ops': 7}
```

На настоящем железе N=15 факторизовали ещё в 2001 году, N=21 — позже. Масштабирование упирается в коррекцию ошибок: нужны миллионы физических кубитов на один логический.

## Полный прогон: от периода к флагу

```
$ python3 shor_lite.py
N = 21
a = 2
period r = 6
gcd(2^3 - 1, 21) = 7
gcd(2^3 + 1, 21) = 3
factors: 3 * 7 = 21
flag: nto{sh0r_f1nds_p3r10d}
```

Заметьте: если `r` нечётное или `a^(r/2) ≡ -1 (mod N)`, берут другое `a` и повторяют. Это не редкий случай, а штатная ветка алгоритма.

## Если не сработало

Если период нечётный — меняйте основание `a`. Если `gcd` дал тривиальный делитель — тоже меняйте `a`. Вероятность успеха одного раунда высокая, несколько попыток гарантируют результат.

## Что мы теперь знаем

- Shor сводит факторизацию к поиску периода `a^x mod N`.
- Период даёт делители через `gcd(a^(r/2) ± 1, N)`.
- Grover даёт квадратичное ускорение поиска — вдвое по битам.
- Против Shor меняют схему, против Grover удваивают длину.

## Шаг 5: квантовое преобразование Фурье простыми словами

Сердце Shor — **квантовое преобразование Фурье** (QFT). Классическое Фурье раскладывает сигнал на частоты; QFT делает то же с амплитудами, но экспоненциально быстрее. Если функция периодична с периодом `r`, то после QFT вероятность концентрируется в состояниях, кратных `1/r`. Измерение даёт одно такое состояние, и по нему восстанавливают `r` (иногда с постобработкой цепными дробями).

Поэтому Shor — это, строго говоря, не «алгоритм факторизации», а алгоритм поиска периода. Факторизация — лишь одно из применений.

## Сколько кубитов нужно для RSA-2048

Чтобы разложить 2048-битное число, нужно порядка **двух-трёх тысяч логических кубитов** и миллионы операций. Логический кубит строится из многих физических через коды коррекции ошибок (surface code — сотни-тысячи физических на один логический). Итог — миллионы физических кубитов при очень низком уровне ошибок.

Именно поэтому «квантовый апокалипсис» откладывается: дело не в идее, а в инженерии коррекции ошибок. Рекорды факторизации реальных чисел (15, 21, 35) далеки от 2048.

## Гибридные угрозы: Shor + Grover

Иногда алгоритмы комбинируют. Например, для симметричных схем с 128-битным ключом Grover даёт 2^64 — всё ещё много, но некоторые протоколы имеют структуру, позволяющую ускориться сильнее. Правило безопасности: **против Shor меняй примитив, против Grover удваивай длину**. Для хешей (preimage) Grover оставляет 2^(n/2), поэтому 256-битные хеши остаются стойкими.

## Шпаргалка

| Понятие | Суть |
|---|---|
| QFT | квантовое Фурье, находит периодичность |
| Период r | `a^r ≡ 1 (mod N)` |
| Делители | `gcd(a^(r/2)±1, N)` |
| Grover | `O(sqrt(M))` поиск |
| Удвоение | защита от Grover |
| PQC | защита от Shor |

## Полный разбор Shor на N = 35

Возьмём чуть большее число и пройдём весь путь целиком, включая постобработку. Пусть `N = 35`, `a = 2`:

```
$ python3 - <<'PY'
import math
N=35; a=2
# ищем период перебором (в кванте это делает QFT)
r=1; x=a%N
while x!=1:
    x=x*a%N; r+=1
print('period', r)
if r%2==0:
    p=math.gcd(a**(r//2)-1,N); q=math.gcd(a**(r//2)+1,N)
    print('factors', p, q)
PY
period 12
factors 5 7
```

Период 12 чётный, `2^6 = 64`, `64 mod 35 = 29`; `gcd(28,35)=7`, `gcd(30,35)=5`. Число разложено. Заметьте: если бы период оказался нечётным, мы бы взяли другое `a` и повторили — это штатная ветка.

## Цепные дроби: как из измерения получить период

Измерение после QFT даёт число `y`, приближающее `k·2^m / r`. Чтобы извлечь `r`, применяют разложение `y/2^m` в **непрерывную дробь** и берут знаменатель подходящей дроби. Это чисто классическая постобработка — в CTF её часто приходится делать вручную.

```
$ python3 -c "from fractions import Fraction; print(Fraction(0.6666).limit_denominator(20))"
2/3
```

Знаменатель `3` — кандидат в период. Проверяют кандидатов по одному: `a^r ≡ 1 (mod N)`.

## Grover в задачах поиска

Grover применяют там, где есть «проверка» кандидата. Пример: дана цель-хеш, найти прообраз среди известной структуры. Классически — перебор, квантово — `sqrt`. В CTF Grover моделируют в Qiskit с оракулом, отмечающим решение, и диффузионным оператором, усиливающим его амплитуду.

Число итераций оптимально: `~ (pi/4)·sqrt(M)`. Больше итераций — и амплитуда «перекрутится», вероятность снова упадёт. Это важная тонкость: Grover нельзя «прогнать подольше для надёжности».

## Итоговая таблица угроз

| Примитив | Угроза | Ответ |
|---|---|---|
| RSA-2048 | Shor | PQC-подпись/KEM |
| ECC P-256 | Shor | PQC |
| AES-128 | Grover (2^64) | AES-256 |
| SHA-256 | Grover (2^128) | удлинить/оставить |
| Диффи-Хеллман | Shor | ML-KEM |

## Сколько итераций нужно Grover

Число итераций не «чем больше, тем лучше». Оптимум — примерно `(pi/4)·sqrt(M)`, где `M` — размер пространства поиска. Прогон больше оптимума «перекручивает» амплитуду, и вероятность снова падает — это периодический процесс.

```
$ python3 - <<'PY'
import math
M = 1000
print('optimal iterations ~', round(math.pi/4*math.sqrt(M)))
PY
optimal iterations ~ 25
```

Для 1000 вариантов достаточно ~25 итераций. Для 2^128 это 2^64 — всё ещё недостижимо, что и объясняет стойкость AES-256.

## Коррекция ошибок и порог

Квантовые алгоритмы требуют **логических** кубитов, собранных из многих физических. Схема коррекции (surface code) может исправлять ошибки, но только если уровень ошибок ниже **порога** (порядка 1%). Выше порога исправление делает хуже.

Именно порог — главный барьер. Современные устройства приближаются к нему, но масштаб (миллионы кубитов) остаётся далёкой целью. Для CTF это значит: задачи дают маленькие числа, а не «взломай RSA-2048».

## Чек-лист задач на Shor/Grover

1. Для Shor: найдите период `a^x mod N`, проверьте чётность, примените `gcd(a^(r/2)±1, N)`.
2. Если `gcd` тривиален — смените `a` и повторите.
3. Для Grover: определите пространство поиска `M` и число итераций `~(pi/4)sqrt(M)`.
4. Проверьте, что оракул отмечает именно решение.
5. Для реальных криптосистем оцените число логических кубитов — и убедитесь, что оно недостижимо.

Этот чек-лист разделяет учебные задачи и реальные угрозы.

## Итог

Shor сводит факторизацию к поиску периода и ломает RSA/ECC; Grover даёт квадратичное ускорение и заставляет удваивать длины симметричных ключей. Реальный барьер — не идея, а коррекция ошибок: нужны миллионы физических кубитов. В CTF работают с маленькими числами, но принципы те же.
