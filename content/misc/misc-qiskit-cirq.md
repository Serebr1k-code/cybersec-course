## Вопрос, с которого всё начинается

Формулы амплитуд понятны, но как «пощупать» квантовую схему, не имея железа? Ответ — симулятор. Qiskit и Cirq позволяют собрать схему из гейтов и запустить её тысячи раз, наблюдая статистику исходов.

## Наш пример: схема, создающая состояние Белла

Соберём ту самую запутанную пару и убедимся, что измерение даёт только `00` и `11`.

## Шаг 1: установка и первая схема

```
$ python3 -c "import qiskit; print(qiskit.__version__)"
1.2.0
```

Qiskit — это Python-библиотека. Схема (`QuantumCircuit`) — список гейтов над кубитами. Соберём:

```
$ python3 - <<'PY'
from qiskit import QuantumCircuit
qc = QuantumCircuit(2, 2)
qc.h(0)          # Адамар: суперпозиция на первом кубите
qc.cx(0, 1)      # CNOT: запутываем
qc.measure([0,1], [0,1])
print(qc)
PY
     ┌───┐     ┌─┐
q_0: ┤ H ├──■──┤M├───
     └───┘┌─┴─┐└╥┘┌─┐
q_1: ─────┤ X ├─╫─┤M├
          └───┘ ║ └╥┘
c: 2/═══════════╩══╩═
                0  1
```

`QuantumCircuit(2, 2)` — два кубита и два классических бита под результаты измерения.

## Шаг 2: запуск на симуляторе и shots

```
$ python3 - <<'PY'
from qiskit import QuantumCircuit, transpile
from qiskit_aer import AerSimulator
qc = QuantumCircuit(2,2); qc.h(0); qc.cx(0,1); qc.measure([0,1],[0,1])
sim = AerSimulator()
res = sim.run(transpile(qc, sim), shots=1000).result()
print(res.get_counts())
PY
{'00': 502, '11': 498}
```

**Shots** — число прогонов. Каждый прогон даёт один классический результат. Из 1000 выстрелов примерно половина `00`, половина `11`, и **никогда** `01`/`10`. Это и есть запутанность в данных.

## Шаг 3: transpile и топология

`transpile` переписывает схему под конкретное устройство: раскладывает сложные гейты в базовые, учитывает, между какими кубитами физически есть связи. На симуляторе это не критично, на железе — обязательно. Пропускать транспиляцию — классическая ошибка новичка.

## Шаг 4: Cirq для сравнения

Cirq (Google) решает ту же задачу другими средствами:

```
$ python3 - <<'PY'
import cirq
q0, q1 = cirq.LineQubit.range(2)
c = cirq.Circuit([cirq.H(q0), cirq.CNOT(q0, q1), cirq.measure(q0, q1, key='m')])
print(c)
print(cirq.Simulator().run(c, repetitions=3).measurements['m'])
PY
0: ───H───@───M('m')───
          │   │
1: ───────X───M────────
[[0 0]
 [1 1]
 [0 0]]
```

Cirq возвращает матрицу измерений по выстрелам. Семантика та же, API другой.

## Шаг 5: отладка — statevector

Чтобы увидеть амплитуды до измерения, используют `Statevector`:

```
$ python3 - <<'PY'
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector
qc = QuantumCircuit(2); qc.h(0); qc.cx(0,1)
print(Statevector(qc).probabilities_dict())
PY
{'00': 0.5, '11': 0.5}
```

Это ровно `state.txt` из первого урока, но посчитанный библиотекой. Так проверяют схему до добавления измерения.

## Полный прогон: схема по целевым вероятностям

```
$ cat target.txt
{'00': 0.25, '01': 0.25, '10': 0.25, '11': 0.25}
$ python3 build.py
H on both qubits -> uniform
counts: {'00': 248, '01': 253, '10': 251, '11': 248}
flag: nto{q1sk1t_un1f0rm_sup3rp0s1t10n}
```

Равномерное распределение по 4 исходам даёт `H` на обоих кубитах. Флаг — подтверждение, что схема построена верно.

## Если не сработало

Если counts не совпадают с ожиданием — проверьте порядок кубитов (Qiskit: little-endian, младший кубит — правый в строке `00`). Это самая частая ошибка.

## Что мы теперь знаем

- Схема — список гейтов; измерение даёт классические биты.
- Shots дают статистику; запутанность видна как отсутствие `01`/`10`.
- `transpile` адаптирует схему под устройство.
- `Statevector` показывает амплитуды до измерения.

## Шаг 6: параметризованные схемы и вращения

Реальные алгоритмы (QAOA, VQE) используют **параметризованные** гейты — например, вращения `RZ(θ)`. Схема строится один раз, а параметры подставляются при запуске:

```
$ python3 - <<'PY'
from qiskit import QuantumCircuit
from qiskit.circuit import Parameter
import math
th = Parameter('theta')
qc = QuantumCircuit(1, 1)
qc.rx(th, 0); qc.measure(0, 0)
bound = qc.assign_parameters({th: math.pi})
print(bound)
PY
     ┌───────┐┌─┐
q:   ┤ Rx(pi) ├┤M├
     └───────┘└╥┘
c: 1/═══════════╩═
                0
```

`Rx(pi)` переворачивает кубит так же, как `X`. Параметризация позволяет оптимизировать углы градиентным методом — так работает вариационный квантовый криптоанализ.

## Шаг 7: шум и NoisySimulator

Идеальный симулятор даёт чистые вероятности. Реальное железо шумит: декогеренция, ошибки гейтов, ошибки измерения. В Qiskit шум моделируют через `NoiseModel`:

```
$ python3 - <<'PY'
from qiskit_aer.noise import NoiseModel, depolarizing_error
nm = NoiseModel()
nm.add_all_qubit_quantum_error(depolarizing_error(0.01, 1), ['h'])
print('noise model ready, p=0.01')
PY
noise model ready, p=0.01
```

Деполяризующий шум с вероятностью 1% означает, что примерно один из ста гейтов `H` даст случайный результат. В задачах это важно: если counts «грязные», возможно, ожидается именно шумная модель, а не идеальная.

## Отладка: transpile и порядок кубитов

Две классические ловушки:

- **Забытый transpile** — на симуляторе сработает, на устройстве упадёт из-за отсутствия связей между кубитами.
- **Порядок битов** — Qiskit использует little-endian: строка `'01'` означает `q1=0, q0=1`. Cirq — наоборот, читает слева направо.

Если результат «перевёрнут», сначала проверьте порядок кубитов, а потом уже ищите баг в схеме.

## Разбор: почему counts не совпадают с теорией

Пусть ожидается 50/50, а counts дают `{'00': 620, '11': 380}`. Прежде чем искать баг в схеме, исключите три причины:

- **Мало выстрелов.** При 1000 выстрелов статистическая погрешность — десятки процентов. Увеличьте до 100000 и посмотрите снова.
- **Шум.** Если подключена шумовая модель, отклонение ожидаемо.
- **Измерение не того кубита.** Перепутанные классические биты дают «странный» результат при корректной схеме.

Только после этого проверяйте сами гейты.

## Параметризованные схемы: зачем

В вариационных алгоритмах углы гейтов подбираются оптимизатором. Схема задаётся один раз через `Parameter`, а значения подставляются в цикле:

```
$ python3 - <<'PY'
from qiskit import QuantumCircuit
from qiskit.circuit import Parameter
th = Parameter('t')
qc = QuantumCircuit(2)
qc.ry(th, 0); qc.cx(0,1)
for v in (0.0, 3.14159/2, 3.14159):
    print(v, qc.assign_parameters({th: v}).depth())
PY
0.0 2
1.570795 2
3.14159 2
```

Глубина не меняется — меняются только числовые параметры. Это основа обучения квантовых схем.

## Отладка: statevector против counts

Золотое правило: **сначала смотрите statevector, потом counts**. Вектор состояния показывает амплитуды без статистического шума и мгновенно выдаёт логическую ошибку. Если statevector верный, а counts «плывут» — это shots или шум, а не баг.

```
$ python3 - <<'PY'
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector
qc = QuantumCircuit(1); qc.h(0)
print(Statevector(qc))
PY
Statevector([0.70710678+0.j, 0.70710678+0.j],
            dims=(2,))
```

## Сравнение Qiskit и Cirq

| Аспект | Qiskit | Cirq |
|---|---|---|
| Порядок битов | little-endian | слева направо |
| Основной симулятор | AerSimulator | cirq.Simulator |
| Параметры | Parameter | sympy.Symbol |
| Экосистема | IBM | Google |

Обе библиотеки эквивалентны по возможностям. Выбирайте ту, под которую есть примеры в условии задачи, чтобы не переводить схемы вручную.

## Гейтов, которых не хватает

Базовых `H`, `X`, `CNOT` мало для реальных схем. Полезный минимум:

| Гейт | Действие | Пример применения |
|---|---|---|
| `Z` | меняет знак амплитуды `|1>` | фазовые оракулы |
| `S`, `T` | фазовые вращения | QFT |
| `RZ(θ)` | параметризованная фаза | вариационные алгоритмы |
| `SWAP` | обмен кубитов | маршрутизация |
| `CCX` | Тоффоли | классическая логика |

Из них собираются почти все учебные схемы. Универсальность достигается комбинацией: любой гейт раскладывается в `H`, `T`, `CNOT` с точностью до фазы.

Схему можно отрисовать текстом, латехом или картинкой:

```
$ python3 -c "from qiskit import QuantumCircuit; qc=QuantumCircuit(2); qc.h(0); qc.cx(0,1); print(qc.draw('text'))"
     ┌───┐

     └───┘┌─┴─┐

```

Рисунок помогает поймать ошибку «гейт не на том кубите» за секунды. В отчётах и райтапах схему всегда показывают — это доказательство того, что вы понимаете, что запускаете.

## Частые вопросы

**Чем Aer отличается от BasicAer?** Aer — быстрый симулятор на C++, BasicAer — чистый Python, медленнее, но без зависимостей.

**Можно ли запускать на реальном устройстве?** Да, через `qiskit-ibm-runtime`, но тогда неизбежны очереди и шум.

**Что такое глубина схемы?** Число последовательных слоёв гейтов; на шумном железе меньше — лучше.

**Как проверить, что схема делает то, что нужно?** Сравните `Statevector` с ожидаемыми амплитудами до измерения.

**Почему counts всегда целые?** Это частоты исходов по выстрелам, а не амплитуды.

**Нужен ли мне Cirq, если есть Qiskit?** Только если задача дана в Cirq или нужен его API. Математика одна.

## Итог

Qiskit и Cirq — это способ проверить квантовую идею за секунды: собрать схему, посмотреть вектор состояния, прогнать тысячи выстрелов и сравнить с ожиданием. Помните про порядок битов, транспиляцию и шум — три источника ложных выводов, которые чаще всего путают новичков.
