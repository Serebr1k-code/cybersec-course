## Что такое CTF-методология

Методология — это набор повторяемых шагов, которые применяются к любой задаче. Вместо того чтобы перебирать всё подряд, вы **классифицируете** задачу, **собираете** данные и **применяете** подходящий инструмент. Это экономит время и снижает панику перед незнакомым.

## Категории и их признаки

| Категория | Что дают | Первый шаг |
|-----------|----------|-----------|
| Web | URL, исходник | посмотреть страницу, cookie, заголовки |
| Crypto | числа, шифртекст | определить схему |
| Pwn | бинарник, сервис | `checksec`, дизассемблер |
| Reversing | бинарник | `file`, `strings` |
| Forensics | образ, дамп | `file`, `binwalk` |
| Misc | «странный» файл | `file`, `strings`, `xxd` |
| Stego | картинка/аудио | `exiftool`, `binwalk` |

Признак часто прямо указывает на инструмент.

## Инструментарий по категориям

- **Универсальные:** `file`, `strings`, `xxd`, `binwalk`, `exiftool`.
- **Web:** `curl`, `ffuf`, `sqlmap`, Burp.
- **Crypto:** Python+sympy, CyberChef, sage.
- **Pwn:** pwntools, gdb/pwndbg, ROPgadget.
- **Reversing:** Ghidra, IDA, r2, angr.
- **Forensics:** foremost, Volatility, plaso.
- **Stego:** zsteg, stegsolve, steghide.

## Работа с условием задачи

Условие — источник подсказок. Обращайте внимание на:

- **формат флага** (`FLAG{...}`) — помогает `grep`;
- **описание** («аудио», «образ», «сеть») — подсказывает категорию;
- **имя файла** — часто говорит о формате;
- **размер** — большой файл намекает на карвинг/данные;
- **подсказки (hints)** — не игнорируйте их.

## Время и приоритеты

На соревновании ресурс — время. Правила:

1. Начинайте с задач, где есть ясная зацепка.
2. Оценивайте шансы: «могу решить за 15 минут» важнее «интересно».
3. Застряли больше 20 минут — переключитесь, вернитесь позже.
4. Ведите заметки: что пробовали, что не сработало.

## Разобранный пример

Дано: файл `challenge.bin`, описание «не всё то, чем кажется».

```bash
file challenge.bin        # PNG image data
binwalk challenge.bin     # ... Zip archive data
```

Категория — stego/misc. Применяем `binwalk -e`, извлекаем архив, читаем флаг. Методология сработала: классификация → инструменты → результат.

## Частые ошибки и подводные камни

- **Перебор инструментов наугад.** Сначала классифицируйте.
- **Игнорирование условия.** Там часто прямо указана категория.
- **Работа на «боевой» машине.** Используйте VM/контейнер.
- **Потеря заметок.** Без них вы повторяете тупиковые пути.
- **Зацикливание.** Ставьте тайм-бокс на задачу.

## Что дальше / решение

1. Прочитайте условие и выпишите «дано/требуется».
2. Классифицируйте задачу.
3. Примените первый инструмент категории.
4. Если застряли — смените инструмент, но не более 2–3 раз.
5. Ведите заметки и соблюдайте тайм-бокс.

## Шаблоны заметок

Хорошая заметка экономит десятки минут. Минимальный шаблон:

```
## Задача: <имя>
- дано: ...
- требуется: ...
- категория (гипотеза): ...
- проверки: file/strings/binwalk/exiftool -> ...
- гипотезы: ...
- результат: ...
```

Ведите заметку **с самого начала**, а не после успеха: именно процесс поиска содержит подсказки для возврата к задаче.

## Командная работа

В команде важно разделение:

- **роли по категориям** — каждый углубляется в свою;
- **общий документ** — кто что решает и какие зацепки нашёл;
- **флаг-борд** — что уже сдано;
- **передача контекста** — при переключении кратко описывайте состояние задачи.

Плохая коммуникация — главная причина, почему команда теряет время на дублирование.

## Частые вопросы по методологии

- **Много задач и мало времени?** Сначала «просеивание» — быстрый обзор всех, потом углубление.
- **Задача кажется нерешаемой?** Возможно, вы неверно классифицировали — перечитайте условие.
- **Инструмент не работает?** Проверьте входные данные, а не инструмент.
- **Где хранить инструменты?** В изолированном контейнере/VM, не на рабочей машине.

## Мини-шпаргалка методологии

```
1. прочитай условие -> дано/требуется
2. классифицируй задачу
3. инвентаризируй артефакты (file, strings, binwalk, exiftool)
4. примени первый инструмент категории
5. застрял >20 мин -> переключись
6. веди заметки и флаг-борд
```

## Итог по методологии

Сила в CTF — не в знании сотен команд, а в повторяемом процессе: классифицировать, собрать данные, применить инструмент, проверить. Этот процесс переносится между категориями и платформами. Инструменты меняются, методология — нет. Освоив её, вы перестанете «паниковать перед незнакомым» и начнёте решать системно.

## Кейс: незнакомая задача (пошагово)

Дано: файл `data.bin`, описание «внутри спрятано послание».

1. **Классификация.** Файл неизвестного типа → категория misc/stego.
2. **Инвентаризация.** `file data.bin`, `ls -la`.
3. **Быстрый проход.** `strings`, `binwalk`, `xxd head/tail`, `exiftool`.
4. **Гипотеза.** `binwalk` показал ZIP → распаковываем.
5. **Проверка.** В архиве — текст с флагом.
6. **Фиксация.** Записываем шаги в журнал.

Если бы ZIP не нашёлся, гипотезами были бы LSB-стего, дописанные данные, самодельный формат — и мы шли бы по списку.

## Кейс: командная гонка

На соревновании 40 задач и 4 часа. Стратегия:

- 10 минут — обзор всех задач, разметка по категориям и сложности;
- распределение по ролям (web/crypto/pwn/misc);
- «быстрые» задачи сдаём первыми (очки + уверенность);
- сложные — в фоне, с тайм-боксом;
- синхронизация каждые 20–30 минут.

Побеждает не тот, кто решает одну сложную, а тот, кто стабильно сдаёт много средних.

## Итог по методологии

Инструменты — вторичны; первичен процесс: классифицировать → собрать → применить → проверить. Ведите заметки, соблюдайте тайм-бокс, работайте в изоляции и распределяйте силы. Эта методология превращает хаос CTF в предсказуемый конвейер и делает вас сильнее в любой категории.

## Продвинутые подсказки в условиях

Опытный игрок читает условие «между строк»:

- **«не всё то, чем кажется»** → полиглот/стего;
- **«послушай»** → аудио-стего (спектрограмма, LSB);
- **«во времени»** → таймлайн/EXIF/тайминг;
- **«это просто»** → проверьте очевидное (метаданные, строки);
- **«внимательнее к деталям»** → байты, регистр, пробелы;
- **«следуй за белым кроликом»** → цепочка подсказок.

Названия задач часто содержат каламбуры, указывающие на инструмент.

## Инструменты автоматизации

Чтобы не делать одно и то же руками, автоматизируйте:

```bash
# проход по всем файлам в папке
for f in *; do echo "== $f"; file "$f"; strings -n 6 "$f" | head -3; done
```

```python
# массовый exiftool через piexif/PIL
from PIL import Image
from PIL.ExifTags import TAGS
img = Image.open("photo.jpg")
for k, v in img.getexif().items():
    print(TAGS.get(k, k), v)
```

Скрипты-обёртки экономят время при большом числе артефактов.

## Практикум: разбор трёх задач

1. **Web.** `curl -sI` → заголовки → cookies → `ffuf` → скрытый путь.
2. **Forensics.** `file` → `binwalk` → распаковка → метаданные → флаг.
3. **Misc.** `file` → `strings` → гипотеза (стего/архив) → инструмент.

Каждый раз фиксируйте шаги: так формируется «мышечная память» методологии.

## Итог по инструментам

Не существует одного «правильного» инструмента — существует правильный **порядок**. Классифицируйте задачу, примените первый инструмент категории, при неудаче смените гипотезу. Держите набор утилит под рукой в контейнере и автоматизируйте повторяющиеся действия. Это и есть методология CTF.
