## Вопрос, с которого всё начинается

На соревновании сорок задач и четыре часа. Открываешь первую — файл `challenge.bin` без расширения и описание «не всё то, чем кажется». С чего начать? Перебирать команды наугад — верный способ потерять время. Нужен **повторяемый процесс**, который работает на любой задаче.

## Наш пример: challenge.bin

Начинаем с самого дешёвого шага — определить, что это за файл:

```
$ file challenge.bin
challenge.bin: PNG image data, 800 x 600, 8-bit/color RGBA, non-interlaced
```

Это картинка. Уже зацепка: описание «не всё то, чем кажется» намекает, что внутри может быть спрятано что-то ещё. Проверяем, нет ли после картинки дописанных данных:

```
$ binwalk challenge.bin
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             PNG image, 800 x 600
108           0x6C            Zlib compressed data
1425634       0x15C022        Zip archive data, name: secret.txt
```

`binwalk` показывает структуру файла: PNG занимает начало, а в конце — **ZIP-архив** с файлом `secret.txt`. Вот и «не всё то, чем кажется». Извлекаем и читаем:

```
$ binwalk -e challenge.bin
$ cat _challenge.bin.extracted/secret.txt
flag{hidden_in_the_trailer}
```

Задача решена за пять минут — потому что мы шли по методологии, а не перебирали наугад.

## Шаг 1: классификация

Первый шаг методологии — определить **категорию**. Категория подсказывает первый инструмент:

| Категория | Что дают | Первый шаг |
|-----------|----------|-----------|
| Web | URL, исходник | посмотреть страницу, cookie, заголовки |
| Crypto | числа, шифртекст | определить схему |
| Pwn | бинарник, сервис | `checksec`, дизассемблер |
| Reversing | бинарник | `file`, `strings` |
| Forensics | образ, дамп | `file`, `binwalk` |
| Misc | «странный» файл | `file`, `strings`, `xxd` |
| Stego | картинка, аудио | `exiftool`, `binwalk` |

В нашем примере признак — картинка с описанием-намёком, то есть stego/misc.

## Шаг 2: инвентаризация артефактов

Прежде чем углубляться, соберите все дешёвые факты об объекте. Универсальный набор:

- `file` — тип файла;
- `strings` — читаемые строки;
- `xxd` — байты в начале и в конце;
- `binwalk` — вложенные структуры;
- `exiftool` — метаданные (для медиа).

```
$ strings -n 8 challenge.bin | tail -5
secret.txt
flag{
```

Даже `strings` иногда сразу показывает хвост флага. Это минута работы, а выигрыш — огромный.

## Шаг 3: инструмент по категории

Если инвентаризация не дала результата, берём инструмент категории:

- **Web:** `curl`, `ffuf`, `sqlmap`, Burp;
- **Crypto:** CyberChef, Python + sympy, sage;
- **Pwn:** pwntools, gdb/pwndbg, ROPgadget;
- **Reversing:** Ghidra, r2, angr;
- **Forensics:** foremost, Volatility, plaso;
- **Stego:** zsteg, stegsolve, steghide.

Не берите инструмент «наугад» — берите тот, что соответствует гипотезе. В нашем примере `binwalk -e` уже извлёк архив.

## Шаг 4: тайм-бокс и заметки

На соревновании ресурс — время. Правила:

1. Начинайте с задач, где есть ясная зацепка.
2. Застряли больше 20 минут — переключитесь, вернитесь позже.
3. Ведите заметки: что пробовали, что не сработало.

Минимальный шаблон заметки:

```
## Задача: challenge.bin
- дано: PNG 800x600, описание «не всё то, чем кажется»
- гипотеза: stego
- проверки: file -> PNG; binwalk -> ZIP в хвосте
- результат: flag{...}
```

Заметку ведите **с самого начала**: именно процесс поиска содержит подсказки для возврата.

## Шаг 5: подсказки в условиях

Опытный игрок читает условие между строк:

- **«не всё то, чем кажется»** → полиглот или стего;
- **«послушай»** → аудио-стего (спектрограмма, LSB);
- **«во времени»** → таймлайн, EXIF, тайминг;
- **«это просто»** → проверьте очевидное (метаданные, строки);
- **«внимательнее к деталям»** → байты, регистр, пробелы.

Названия задач часто содержат каламбуры, указывающие на инструмент.

## Шаг 6: расширенный инструментарий

Полезно держать под рукой набор по категориям — в контейнере или VM:

| Категория | Инструменты |
|-----------|-------------|
| Web | curl, ffuf, sqlmap, Burp, jwt-tools |
| Crypto | CyberChef, sympy, sage, hashcat |
| Pwn | pwntools, gdb/pwndbg, ROPgadget, one_gadget |
| Reversing | Ghidra, IDA, r2, angr, Z3 |
| Forensics | foremost, Volatility, plaso, exiftool |
| Stego | zsteg, stegsolve, steghide, outguess |
| Misc | file, strings, binwalk, xxd, python |

Большинство CTF-докеров уже включают эти утилиты — не тратьте время на установку во время соревнования.

## Шаг 7: командная работа

В команде важно разделение:

- **роли по категориям** — каждый углубляется в свою;
- **общий документ** — кто что решает и какие зацепки нашёл;
- **флаг-борд** — что уже сдано;
- **передача контекста** — при переключении кратко описывайте состояние задачи.

Плохая коммуникация — главная причина, почему команда теряет время на дублирование. Побеждает не тот, кто решает одну сложную задачу, а тот, кто стабильно сдаёт много средних.

## Шаг 8: автоматизация рутины

Чтобы не делать одно и то же руками, автоматизируйте повторяющиеся проходы:

```
$ for f in *; do echo "== $f"; file "$f"; strings -n 6 "$f" | head -3; done
```

Скрипты-обёртки экономят время при большом числе артефактов. Но не автоматизируйте «наугад»: сначала гипотеза, потом скрипт. И держите автоматизацию в изолированном окружении: недоверенный файл, прогнанный «на всякий случай» на рабочей машине, — это уже инцидент.

## Что мы теперь знаем

По-простому:

1. Методология — это классифицировать задачу, собрать данные, применить инструмент, проверить.
2. Категория подсказывает первый инструмент.
3. Инвентаризация (`file`, `strings`, `xxd`, `binwalk`) — самый дешёвый шаг.
4. Тайм-бокс 20 минут и заметки спасают от зацикливания.
5. Условие и имя файла часто прямо намекают на категорию.

## На что смотреть дальше

- **Не перебирайте инструменты наугад.** Сначала гипотеза, потом инструмент.
- **Не игнорируйте условие.** Там часто указана категория или намёк.
- **Работайте в VM или контейнере.** Недоверенный файл может быть опасен.
- **Не теряйте заметки.** Без них вы повторите тупиковые пути.
- **Не запускайте недоверенный код на рабочей машине.** Изоляция обязательна.

## Куда дальше

Мы освоили общий процесс. Дальше займёмся **разведкой условий**: как быстро понять, что дано и что требуется, и какие подсказки прячутся в формулировке задачи. А пока главное запомни: сила в CTF — не в знании сотен команд, а в повторяемом порядке «классифицировать → собрать → применить → проверить».

## Где пригодится

- **CTF:** любой турнир, любой уровень.
- **Работа:** методология разбора незнакомых артефактов.
- **Обучение:** быстрый вход в новые темы.
- **Bug bounty:** похожий процесс на web.
