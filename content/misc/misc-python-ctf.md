## Зачем Python в CTF

Python — универсальный язык для CTF: он закрывает кодировки, парсинг, работу с сетью, криптографию и автоматизацию интерактивных сервисов. Большинство задач, где нужно «написать скрипт», решаются на нём. Цель этого модуля — довести базовые приёмы до автоматизма, чтобы вы писали солверы без гугления синтаксиса.

## Работа с байтами и строками

В Python 3 важно различать `str` (текст) и `bytes` (байты). Кодировка/декодировка — источник половины ошибок новичков:

```python
s = "привет"
b = s.encode('utf-8')      # b'\xd0\xbf\xd1\x80...'
s2 = b.decode('utf-8')     # обратно
raw = bytes.fromhex('deadbeef')
hexs = raw.hex()           # 'deadbeef'
```

Для «грязных» данных всегда используйте `errors='replace'`, иначе скрипт упадёт на первом же невалидном байте. Для вывода непечатаемых байтов удобен `repr()`.

## Кодировки в одну строку

```python
import base64, binascii, codecs
base64.b64decode("RkxBR3t4fQ==")          # b'FLAG{x}'
base64.b32decode("...")
binascii.unhexlify("464c4147")             # b'FLAG'
codecs.decode("uryyb", "rot_13")           # 'hello'
```

Цепочку декодирований удобно гонять в цикле, пока результат не станет читаемым, ища флаг регуляркой:

```python
import re, base64
def looks_text(b):
    return sum(32 <= c < 127 for c in b) / max(1, len(b)) > 0.9
data = open('enc','rb').read()
for _ in range(10):
    if re.search(rb'FLAG\{[^}]*\}', data):
        print(data); break
    try:
        data = base64.b64decode(data)
    except Exception:
        break
```

## Работа с числами и битами

```python
x = 0b1010
x.bit_length()          # 4
bin(x), hex(x), oct(x)
int('ff', 16)           # 255
x ^ (1 << 3)            # переключить бит
```

XOR-«шифры» с повторяющимся ключом ломаются частотным анализом; для одноразового ключа достаточно `bytes(a ^ b for a, b in zip(ct, key))`.

## Криптопримитивы «из коробки»

Многие misc-крипто решаются без внешних библиотек:

```python
import hashlib, hmac
hashlib.md5(b'x').hexdigest()
hashlib.sha256(b'x').hexdigest()
# RSA-математика вручную
n, e, ct = 3233, 17, 855
phi = 3120
d = pow(e, -1, phi)      # Python 3.8+: модульная инверсия
m = pow(ct, d, n)
```

`pow(e, -1, phi)` — модульная инверсия, а `pow(a, b, m)` — быстрое возведение в степень по модулю. Эти две функции решают массу «математических» задач.

## Сеть и сокеты

```python
import socket
s = socket.create_connection(('host', 1337), timeout=5)
s.sendall(b'hello\n')
data = s.recv(4096)
```

Для HTTP проще `requests`:

```python
import requests
r = requests.get('https://host/api', params={'q':'x'}, timeout=5)
r.json()
```

Для потоковых бинарных протоколов удобнее `pwntools` (см. отдельный модуль).

## Разбор бинарных структур через struct

```python
import struct
data = open('packet.bin','rb').read()
magic, ver, length = struct.unpack('<IHH', data[:8])
print(hex(magic), ver, length)
```

`<` — little-endian, `>` — big-endian. Формат-строки: `I`=uint32, `H`=uint16, `f`=float, `s`=bytes. Это незаменимо в misc-задачах с кастомными форматами.

## Автоматизация интерактивных сервисов

```python
from pwn import *
io = remote('host', 1337)
io.recvuntil(b'name:')
io.sendline(b'admin')
print(io.recvline())
io.close()
```

Всегда ставьте `context.log_level='error'` для чистого вывода и добавляйте `timeout` при чтении, чтобы скрипт не зависал.

## Типичные ошибки и подводные камни

- **str vs bytes** — `TypeError: a bytes-like object is required`; решается `.encode()/.decode()`.
- **Кодировка при чтении файла** — указывайте `encoding=` и `errors='replace'`.
- **Забытый `timeout`** в сокете — скрипт висит вечно.
- **Целочисленное деление** — `//` вместо `/` там, где нужен int.
- **Случайность** — `random` предсказуем; для крипто нужен `secrets`.
- **Мутация при итерации** — не меняйте список/словарь во время перебора.
- **Рекурсия** — повышайте лимит или переходите на итерацию.

## Отладка

```python
import pdb; pdb.set_trace()   # интерактивная отладка
print(repr(data[:64]))        # что реально в переменной
```

При падении на декодировании оборачивайте в `try/except` и печатайте сырые байты — часто «непонятный» результат уже содержит подсказку.

## Что дальше / решение

Практический план: отработайте пять базовых блоков — байты/кодировки, регулярки, struct, сеть (requests/pwntools), крипто-функции. На реальной задаче соберите солвер из этих блоков, проверьте на маленьком примере и только потом отправляйте. Держите персональный файл-шпаргалку с готовыми сниппетами — со временем это превратится в личный фреймворк, ускоряющий решение в разы.

## Как быстро выбрать инструмент под задачу

В CTF почти всегда есть соблазн писать всё вручную, но правильнее сначала спросить себя: есть ли готовая библиотека, которая делает 80% работы. Для картинок — `PIL/Pillow` и `numpy`, для аудио — `numpy` и `scipy.io.wavfile`, для сетевых сервисов — `pwntools`, для HTTP — `requests`, для символьной математики — `sympy`, для крипто-математики — `pycryptodome` и `gmpy2`. Навык быстро вспоминать, какой модуль закрывает класс задач, экономит больше времени, чем знание синтаксиса. Поэтому заведите привычку после каждой решённой задачи записывать в шпаргалку одну строку: «задача такого-то типа решается вот этим модулем вот такой функцией».

Отдельно стоит освоить `numpy`: огромное число misc-задач про изображения, звук и «обработку матриц» решаются в три строки векторных операций там, где наивный Python-цикл работает минуты. Например, XOR двух картинок, наложение каналов, поиск пикселей с аномальными значениями — всё это естественно выражается массивами. Умение мыслить векторами, а не поэлементными циклами, — признак опытного солвер-разработчика.

## Чтение и запись файлов правильно

Новички часто читают файлы как текст там, где это бинарные данные, и наоборот. Правило простое: если вы не уверены в содержимом — открывайте в режиме `'rb'` и работайте с байтами, а к тексту переходите только явно, указав кодировку. Для больших файлов используйте построчное чтение в цикле, чтобы не забивать память. Для записи результата, который может содержать непечатаемые байты, применяйте бинарный режим `'wb'`. Отдельно помните про перевод строки: в бинарных протоколах он часто является разделителем сообщений, и лишняя нормализация окончаний строк ломает протокол.

Полезный приём — временные файлы для отладки: когда солвер «почти работает», сохраните промежуточный результат на диск и посмотрите на него глазами или через `xxd`. Это гораздо быстрее, чем гадать, что пошло не так внутри длинной цепочки преобразований.

## Пошаговый разбор типичной задачи

Рассмотрим задачу: дан файл, в котором чередуются куски base64, hex и gzip. Алгоритм: читаем байты, ищем флаг регуляркой, пробуем применить каждое преобразование по очереди, после каждого шага проверяем, не появился ли читаемый текст или сигнатура следующего формата. Такой «жадный» цикл с проверкой прогресса — универсальный шаблон для многослойных misc-задач. Если очередной шаг не даёт ни флага, ни узнаваемой сигнатуры, откатываемся и пробуем следующее преобразование. Именно поэтому важно сохранять промежуточные состояния, а не перезаписывать переменную безвозвратно.

## Что дальше / решение

Итог: освойте пять-шесть ключевых модулей, научитесь выбирать между текстовым и бинарным режимом чтения, мыслите векторами через `numpy` и держите шаблон «цикл преобразований с проверкой прогресса» для слоёных задач. Ведите личную шпаргалку сниппетов и после каждой задачи добавляйте туда одну строку с рецептом. Тогда следующая похожая задача будет решаться копированием и правкой готового кода, а весь ресурс уйдёт на понимание её уникальной логики.

## Где пригодится

- **Любая CTF-категория** — web, crypto, pwn, forensics: везде нужен скрипт-обвязка.
- **Автоматизация пентеста** — скрипты для перебора, парсинга ответов, взаимодействия с API.

- **Реальный инструментарий** — pwntools, requests, pycryptodome под капотом используют всё то же самое.
