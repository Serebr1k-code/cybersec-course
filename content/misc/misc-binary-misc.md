## Введение

Значительная часть misc-задач — это «грязные» байты: XOR-шифр, побитовые операции, непонятный формат, перепутанный порядок байтов. Здесь — базовый инструментарий для работы на уровне байт и бит: определение формата, XOR-восстановление, битовые операции, endianness и битовые плоскости.

## Определение формата по magic-байтам

```bash
file mystery.bin
xxd mystery.bin | head
```

| Hex | Формат |
|---|---|
| `50 4B 03 04` | ZIP (и docx/xlsx/apk/jar) |
| `89 50 4E 47` | PNG |
| `FF D8 FF` | JPEG |
| `25 50 44 46` | PDF |
| `7F 45 4C 46` | ELF |
| `4D 5A` | PE (Windows) |
| `1F 8B` | GZIP |
| `52 61 72 21` | RAR |
| `37 7A BC AF` | 7-Zip |

Если сигнатуры нет, но размер кратен 4/8 — возможно, это массив чисел.

## XOR: главный приём

```python
data = open('cipher.bin','rb').read()
for k in range(256):
    dec = bytes(b ^ k for b in data)
    if b'flag' in dec or b'CTF' in dec:
        print(k, dec[:60])
```

Многосимвольный XOR — повторяющийся ключ: определяют длину ключа (расстояние Хэмминга или индекс совпадений), затем решают каждый столбец как односимвольный XOR.

```python
key = b'KEY'
print(bytes(b ^ key[i % len(key)] for i, b in enumerate(data)))
```

Known-plaintext: если знаете префикс (`flag{`), ключ = `cipher ^ known`.

## Побитовые операции

```python
x & 0xFF          # младший байт
x >> 8            # сдвиг вправо
(x << 4) | y      # упаковка
bin(x), hex(x)    # представления
x.bit_length()
```

Данные «зашиты» через сдвиги и маски: восстановите исходные значения, зная схему упаковки (например, RGB в 24 бита).

## Порядок байтов (endianness)

```python
import struct
print(struct.unpack('<I', b'\x01\x00\x00\x00')[0])   # 1 (little)
print(struct.unpack('>I', b'\x00\x00\x00\x01')[0])   # 1 (big)
```

Если числа «неправильные» — попробуйте другой порядок. В сетевых протоколах обычно big-endian, в x86 — little-endian.

## Битовые плоскости

```python
data = open('image.png','rb').read()
for k in range(8):
    bits = [(b >> k) & 1 for b in data[:4096]]
    ones = sum(bits)
    print(k, ones)
```

Аномальная плотность единиц в плоскости — признак встроенных данных.

## Разобранный пример

Задача: файл `data.bin`, размер ровный, `file` не распознаёт.

1. `xxd data.bin | head` — первые байты и паттерны.
2. Считаем энтропию и частоты байт.
3. Пробуем XOR перебором (поиск `flag`).
4. Интерпретируем как массив `uint32` (little/big) → ищем ASCII.
5. Собираем результат через `bytes(...)`.

```python
import struct
raw = open('data.bin','rb').read()
nums = struct.unpack('<%dI' % (len(raw)//4), raw)
print(''.join(chr(n & 0xFF) for n in nums)[:80])
```

## Частые ошибки и подводные камни

- Игнорировать magic-байты и «лечить» уже распознанный формат.
- Пробовать только один порядок байтов.
- Забывать, что XOR обратим: `(c ^ k) ^ k == c`.
- Путать байты и биты в масках.
- Не проверять кратность размера (возможно, это массив чисел).
- Считать, что «нечитаемый» вывод означает провал — пробуйте разные интерпретации.

## Автоматизация XOR-взлома

Для односимвольного XOR используйте оценку «английскости» (частоты символов) вместо перебора по ключевому слову:

```python
from collections import Counter
FREQ = {'e':12.7,'t':9.1,'a':8.2,'o':7.5,'i':7.0,'n':6.7,' ':13.0}
def score(b):
    return sum(FREQ.get(chr(c).lower(),0) for c in b)
data = open('c.bin','rb').read()
best = max(range(256), key=lambda k: score(bytes(x ^ k for x in data)))
print(best, bytes(x ^ best for x in data)[:80])
```

Для повторяющегося ключа:

1. **Оценка длины ключа** — для каждого `keysize` разбейте на блоки и посчитайте нормализованное расстояние Хэмминга между соседними блоками; минимальное → вероятная длина.
2. **Транспонирование** — соберите «столбцы» (каждый `keysize`-й байт).
3. **Взлом каждого столбца** как односимвольного XOR.
4. **Сборка ключа и расшифровка.**

```python
def hamming(a, b):
    return sum(bin(x ^ y).count('1') for x, y in zip(a, b))
```

## Работа с энтропией

Энтропия помогает отличить шифр от сжатия и найти области с данными:

```python
import math, collections
def entropy(b):
    c = collections.Counter(b); n = len(b)
    return -sum((v/n)*math.log2(v/n) for v in c.values())
print(entropy(open('f','rb').read()))
```

Высокая энтропия (~8 бит/байт) — шифр/сжатие; низкая — структурированные данные/текст.


## Разбор неизвестного формата

1. `file`, `xxd | head`, `binwalk` — структура и вложенные форматы.
2. `strings -a` — читаемые фрагменты.
3. Энтропия по блокам — найти сжатые/шифрованные участки.
4. Проверить обе endianness для числовых полей.
5. Искать ASCII-подстроки в интерпретациях как `uint16/32/64`.

## Endianness в практике: ловушки

- **Сетевые протоколы** (TCP/IP, DNS) — big-endian («network byte order»).
- **x86/x64** — little-endian.
- **PNG** — big-endian (сетевой порядок).
- **ELF-заголовки** — зависят от целевой архитектуры (поле `e_ident`).

```python
import struct
# конвертация
val = struct.unpack('>H', b'\x01\x00')[0]   # 256
val = struct.unpack('<H', b'\x00\x01')[0]   # 256
```

Если число выглядит «сдвинутым» (например, 0x10000000 вместо 0x00000001) — перепутан порядок байтов.

## Практический конвейер разбора байтов

```bash
file data.bin && xxd data.bin | head -20
strings -a -n 6 data.bin | head
binwalk data.bin 2>/dev/null | head
python3 - <<'PY'
import collections, math
d = open('data.bin','rb').read()
c = collections.Counter(d); n = len(d)
H = -sum((v/n)*math.log2(v/n) for v in c.values())
print('size', n, 'entropy', round(H,3))
print('top', c.most_common(5))
PY
```

## Шпаргалка по байтовым задачам

| Признак | Действие |
|---------|----------|
| Есть magic | открыть нужным парсером |
| Размер кратен 4/8 | интерпретировать как массив чисел |
| Нечитаемо, энтропия ~8 | XOR/сжатие/шифр |
| Числа «сдвинуты» | сменить endianness |
| Есть ASCII-обрывки | XOR с известным префиксом |
| Вложение в картинке | битовые плоскости |

Начните с `file`/`xxd`, затем энтропия и интерпретации — это покрывает большинство байтовых CTF-задач.
