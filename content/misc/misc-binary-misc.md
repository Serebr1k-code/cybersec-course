## Вопрос, с которого всё начинается

Мы прошли строки, картинки, звук и документы. Остался самый «сырой» случай: дают файл `data.bin`, и про него ничего не понятно. `file` не может сказать, что это, а содержимое выглядит мусором. Это **байтовая головоломка** — данные спрятаны на уровне отдельных байтов и битов.

Здесь работает тот же принцип: сначала понять структуру, потом применить типовой приём. Разберём один файл.

## Наш пример: data.bin

```bash
$ file data.bin
data.bin: data
```

`file` сдался — сигнатуры известного формата нет. Смотрим первые байты в hex-дампе (`xxd`):

```bash
$ xxd data.bin | head
00000000: 3b2e 2d3a 2b2e 3a24 2e2c 2b28 3d26 2e28  ;.-:+. :$.,+(=&.(
00000010: 2d2b 3a24 2e2c 2b28 3d26 2e28 2b3a 3b2e  -+:$. ,+(=&.(+:;.
```

Видим: байты лежат в узком диапазоне `0x20–0x3f` — это печатные символы, но бессмысленные. Такое «равномерное, но нечитаемое» распределение — сильный намёк на **XOR-шифр**. Проверим размер:

```bash
$ ls -l data.bin
-rw-r--r-- 1 user user 4096 data.bin
```

Размер 4096 — кратен и 4, и 8. Держим это в уме: возможно, файл — массив чисел.

## Шаг 1: что такое XOR и почему он тут

**XOR** (исключающее ИЛИ, `^`) — побитовая операция: результат 1, если биты разные. Её главное свойство — **обратимость**: `(c ^ k) ^ k == c`. То есть если данные зашифрованы XOR'ом с ключом `k`, то тот же XOR с тем же ключом их расшифрует.

Простой случай — **односимвольный XOR**: весь файл зашифрован одним байтом. Переберём все 256 возможных ключей и поищем знакомую подстроку:

```python
data = open('data.bin','rb').read()
for k in range(256):
    dec = bytes(b ^ k for b in data)
    if b'flag' in dec or b'CTF' in dec:
        print(k, dec[:60])
```

```
66 b'flag{x0r_is_tr1vial}'
```

Ключ `66` (`0x42`, символ `B`). Данные расшифрованы. Приём сработал, потому что мы **знали, что искать** (`flag`). А если не знаем?

## Шаг 2: оценка «английскости» вместо перебора по слову

Если заранее неизвестно, как выглядит открытый текст, оценивают, насколько расшифровка похожа на естественный язык — по частотам букв. Самые частые буквы английского: `e`, `t`, `a`, `o` и пробел. Пишем функцию «очков» и берём ключ с максимумом:

```python
from collections import Counter
FREQ = {'e':12.7,'t':9.1,'a':8.2,'o':7.5,'i':7.0,'n':6.7,' ':13.0}
def score(b):
    return sum(FREQ.get(chr(c).lower(),0) for c in b)
best = max(range(256), key=lambda k: score(bytes(x ^ k for x in data)))
print(best, bytes(x ^ best for x in data)[:80])
```

Это **частотный анализ** — универсальный инструмент для XOR без известного префикса.

## Шаг 3: многосимвольный ключ

Если ключ длиннее одного байта, его применяют по кругу: `key[i % len(key)]`. Тогда частотный анализ по всему файлу не сработает. Схема такая:

1. оценить **длину ключа** — по расстоянию Хэмминга между блоками (число различающихся битов);
2. собрать «столбцы» — каждый `len`-й байт;
3. взломать каждый столбец как односимвольный XOR;
4. склеить ключ и расшифровать.

```python
def hamming(a, b):
    return sum(bin(x ^ y).count('1') for x, y in zip(a, b))
```

А если известен префикс (`flag{`), ключ вообще не нужно угадывать: `k = cipher ^ known`.

## Шаг 4: порядок байтов (endianness)

Возвращаемся к догадке «файл — массив чисел». Как байты складываются в число, зависит от **порядка байтов**. **Little-endian** кладёт младший байт первым, **big-endian** — старшим:

```python
import struct
print(struct.unpack('<I', b'\x01\x00\x00\x00')[0])   # 1
print(struct.unpack('>I', b'\x00\x00\x00\x01')[0])   # 1
```

Если число выглядит «сдвинутым» (например, `0x01000000` вместо `1`) — вы перепутали порядок байтов. В сетевых протоколах принят big-endian, на x86 — little-endian.

## Шаг 5: энтропия — понять, где данные

**Энтропия** измеряет хаотичность: около 8 бит/байт — шифр или сжатие; низкая — структурированные данные или текст. По блокам она показывает, где в файле спрятан «плотный» участок:

```python
import math, collections
def entropy(b):
    c = collections.Counter(b); n = len(b)
    return -sum((v/n)*math.log2(v/n) for v in c.values())
print(round(entropy(open('data.bin','rb').read()), 3))
```

## Шаг 6: конвейер разбора незнакомых байтов

Когда файл совсем непонятен, помогает фиксированный конвейер — прогоняем его по шагам и смотрим, что «загорится»:

```bash
$ file data.bin && xxd data.bin | head -20
$ strings -a -n 6 data.bin | head
$ binwalk data.bin 2>/dev/null | head
```

Первая команда — структура и первые байты; вторая — читаемые фрагменты (иногда там обрывок флага); третья — вложенные сигнатуры (вдруг внутри ZIP или картинка). Затем считаем размер и энтропию:

```python
import collections, math
d = open('data.bin','rb').read()
c = collections.Counter(d); n = len(d)
H = -sum((v/n)*math.log2(v/n) for v in c.values())
print('size', n, 'entropy', round(H,3))
print('top', c.most_common(5))
```

Энтропия около 8 — шифр/сжатие; низкая — структура. Кратность размера 4/8 — намёк на массив чисел: пробуйте `struct.unpack` в обоих порядках и ищите ASCII.

## Шаг 7: шелл-однострочники для байтов

Полезно уметь быстро конвертировать, не открывая редактор:

```bash
echo '414243' | xxd -r -p                 # hex -> байты (ABC)
xxd -p file                               # байты -> hex
cmp -l a b | head                         # побайтовое сравнение двух файлов
python3 -c "d=open('c','rb').read();open('o','wb').write(bytes(b^0x42 for b in d))"
```

Последняя строка — побайтовый XOR прямо из командной строки. А `cmp -l` показывает, в каких байтах два файла различаются — удобно для «почти одинаковых» артефактов.

## Что мы теперь знаем

- Байтовая задача начинается с `file` и `xxd`; отсутствие сигнатуры — не тупик.
- XOR обратим: односимвольный ключ ломается перебором или частотным анализом.
- Многосимвольный ключ: оценка длины → столбцы → односимвольный XOR.
- Порядок байтов (`struct.unpack('<I'/' >I')`) решает, как байты складываются в число.
- Энтропия по блокам показывает, где лежат зашифрованные/сжатые данные.
- Размер, кратный 4 или 8, намекает на массив чисел.

## На что смотреть дальше

- **Игнорировать magic-байты** — `file`/`xxd` первым делом; не «лечите» уже распознанный формат.
- **Только один порядок байтов** — всегда проверяйте оба.
- **Забыть обратимость XOR** — `(c ^ k) ^ k == c`; известный префикс сразу даёт ключ.
- **Путать байты и биты** в масках — `x & 0xFF` берёт младший байт, `(b >> k) & 1` — бит.
- **Не читаемый вывод ≠ провал** — пробуйте разные интерпретации (uint16/32/64).
