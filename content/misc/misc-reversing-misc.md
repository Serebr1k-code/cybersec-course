## Что такое реверс в misc

Реверс-инжиниринг — восстановление логики программы по её бинарнику. В misc это «лёгкий» реверс: маленький крекми, проверка пароля, разбор нестандартного формата. Полноценный реверс разбирается в категории `reversing`, но базовые приёмы нужны и здесь.

## Крекми и check-функции

Крекми — программа, которая просит правильный ввод. Классический сценарий:

```c
if (strcmp(input, "s3cr3t") == 0) puts("Win!");
else puts("Fail");
```

Очевидно, но в задачах условие прячут: хешируют ввод, сравнивают побайтово с зашифрованным буфером, проверяют по частям. Тогда ввод восстанавливают из check-функции.

## Форматы файлов

Задачи «что это за файл» требуют понимания форматов: ELF/PE заголовки, секции, магические байты. `file`, `readelf`, `objdump`, `xxd` — первые инструменты.

```bash
file mystery
readelf -h mystery
strings -n 6 mystery | head
```

## Дизассемблеры и отладчики

- **Ghidra** — бесплатный дизассемблер/декомпилятор от NSA; декомпилирует в C.
- **IDA** — индустриальный стандарт.
- **radare2 / rizin** — CLI-фреймворк.
- **gdb + pwndbg** — отладка.
- **objdump** — быстрый дизассемблер.

```bash
r2 -A ./crackme
[0x00401000]> pdf @ main
```

## Символическое исполнение

Когда check-функция сложная, её решают **angr** (символическое исполнение) или **Z3**:

```python
import angr
p = angr.Project("./crackme")
st = p.factory.entry_state()
sm = p.factory.simulation_manager(st)
sm.explore(find=0x401234, avoid=0x401300)
print(sm.found[0].posix.dumps(0))
```

Angr сам строит формулу из инструкций и просит Z3 найти вход, ведущий к «успеху».

## Инструменты

- **Ghidra / IDA / r2** — дизассемблирование.
- **gdb/pwndbg** — динамический анализ.
- **angr** — символическое исполнение.
- **Z3** — решение ограничений.
- **ltrace/strace** — библиотечные/системные вызовы.

## Разобранный пример

Дано: бинарник сравнивает хеш ввода с константой. Реверс:

```bash
ghidra ./crackme    # смотрим main и check
```

Если видим `sha256(input) == hardcoded`, и хеш не «ломается» — ищем подсказку: возможно, проверка по частям, и каждую часть можно решить отдельно. Для «математических» проверок подключаем Z3/angr.

## Частые ошибки и подводные камни

- **Игнорирование динамики.** Статический анализ упускает рантайм-проверки.
- **Анти-отладка.** Проверяйте `ptrace`, `IsDebuggerPresent` (на Windows).
- **Упаковка/обфускация.** Сначала распакуйте (`upx -d`), потом реверсьте.
- **Неверная база.** PIE смещает адреса; учитывайте `base + offset`.
- **Слишком ранний angr.** Сначала поймите логику вручную, потом автоматизируйте.

## Что дальше / решение

1. Определите тип бинарника (`file`, `readelf`).
2. Соберите строки и импорты.
3. Дизассемблируйте `main`/check-функцию.
4. Если логика сложная — отладьте и/или примените angr/Z3.
5. Проверьте найденный ввод на самом бинарнике.

## Патчинг и обход проверок

Иногда проще **изменить** бинарник, чем подобрать ввод. Патчинг убирает проверку или заставляет программу идти по «успешной» ветке.

```bash
# найти инструкцию условного перехода
objdump -d ./crackme | grep -A2 -B2 'cmp\|jne'
# в r2 — изменить jne на jmp
r2 -w ./crackme
[0x00401000]> /ad jne
[0x00401000]> wa jmp 0x00401020 @ 0x00401015
```

На Windows аналогично правят в отладчике (x64dbg) или патчат байты напрямую. Патчинг полезен, когда нужен **любой** проходящий ввод, а не конкретный флаг.

## Разбор форматов и структур

Многие misc-задачи — про формат: «дан файл неизвестного типа, извлеки данные». Приёмы:

```bash
file mystery.bin
xxd mystery.bin | head -20
binwalk mystery.bin
```

Ищите сигнатуры, длины, заголовки. Если формат самодельный — определите структуру (магия, размер, поля) и напишите парсер:

```python
import struct
data = open("mystery.bin", "rb").read()
magic, size = struct.unpack_from("<4sI", data, 0)
print(magic, size)
```

## Динамический анализ

Отладчик показывает, что происходит на самом деле:

```bash
gdb ./crackme
(gdb) break *main
(gdb) run
(gdb) x/s $rdi        # первый аргумент
(gdb) ni
```

Ключевые приёмы: точки останова на сравнениях, дамп памяти в момент проверки, трассировка `strace`/`ltrace` для вызовов. Анти-отладку обходят патчем или обходом проверок `ptrace`.

## Частые вопросы по реверсу

- **Статически сложно, динамически — нет.** Запустите под отладчиком.
- **Проверка «размазана» по коду.** Ищите константы и сравнения (`cmp`, `memcmp`).
- **Хеш-проверка?** Попробуйте Z3/angr или ищите слабость (по частям).
- **Файл упакован?** `upx -d`, затем анализ.

## Мини-шпаргалка реверса

```bash
file bin                     # тип
checksec --file=bin          # защиты (для pwn)
strings -n 6 bin | head      # текст
objdump -d bin | less        # дизассемблер
r2 -A bin                    # radare2
ghidra                       # декомпилятор
gdb bin                      # отладчик
angr                         # символическое исполнение
```

## Итог по реверсу в misc

Реверс в misc — это «быстрый» анализ: тип файла, строки, дизассемблер `main`, при необходимости отладчик и символическое исполнение. Не углубляйтесь в статику, если можно увидеть поведение под отладчиком; и не пишите angr-скрипт, пока не поняли логику вручную. Патчинг (изменить `jne` на `jmp`) часто решает задачу быстрее, чем подбор ввода. Для сложных проверок подключайте Z3/angr.

## Кейс: крекми на XOR

Дано: бинарник, который сравнивает `input XOR key` с константой.

```bash
strings -n 6 crackme | head
objdump -d crackme | grep -A3 'xor'
```

В дизассемблере видно `xor eax, 0x2a` и сравнение. Восстанавливаем ввод:

```python
data = bytes.fromhex("...")     # константа из бинарника
key = 0x2a
print(bytes(b ^ key for b in data))
```

## Кейс: крекми на хеше

Дано: программа сравнивает `md5(input)` с константой. Если хеш «не ломается» словарём — возможно, проверка **по частям**: каждый символ влияет отдельно. Тогда решаем Z3 или перебором по позициям. Иногда проверка — не криптостойкая (свой «хеш»), и её можно инвертировать.

## Кейс: разбор кастомного формата

Дано: файл с неизвестной структурой.

```bash
xxd mystery.bin | head -10
```

Видим: 4 байта магии, затем little-endian длина, затем данные. Пишем парсер:

```python
import struct
d = open("mystery.bin","rb").read()
magic = d[:4]; (size,) = struct.unpack_from("<I", d, 4)
print(magic, size, d[8:8+size])
```

Так извлекают скрытые поля и флаги из «самодельных» форматов.

## Итог по реверсу в misc

Реверс в misc — практический и быстрый: определите тип, посмотрите строки, дизассемблируйте ключевую функцию, при необходимости отладьте или примените Z3/angr. Патчинг часто быстрее подбора ввода. Не забывайте про упаковку (UPX) и анти-отладку. Навык переносится в полноценную категорию `reversing` и в анализ малвари.

## Разбор VM и байткода

Часть крекми реализуют собственную «виртуальную машину»: байткод + интерпретатор. Приёмы:

```bash
strings -n 6 vm_bin | head
objdump -d vm_bin | grep -A20 'main'
```

Ищите таблицу опкодов и цикл интерпретации. Затем пишите дизассемблер байткода или трассируйте его выполнение. Для задач на «кастомный байткод» удобно логировать каждый опкод под отладчиком.

## Символическое исполнение: практика

Angr хорошо работает, когда есть явный «success/fail»:

```python
import angr, claripy
p = angr.Project("./crackme", auto_load_libs=False)
st = p.factory.entry_state()
sm = p.factory.simulation_manager(st)
sm.explore(find=lambda s: b"Win" in s.posix.dumps(1),
           avoid=lambda s: b"Fail" in s.posix.dumps(1))
if sm.found:
    print(sm.found[0].posix.dumps(0))
```

Полезно ограничить ввод (`state.solver.add(flag_byte printable)`) и указать `find` по выводу, а не по адресу. Если angr «застревает», упростите бинарник или используйте Z3 напрямую.

## Z3 напрямую

Когда check-функция видна, ограничения выписывают вручную:

```python
from z3 import *
flag = [BitVec(f'c{i}', 8) for i in range(6)]
s = Solver()
for c in flag: s.add(c >= 0x20, c <= 0x7e)
s.add(flag[0] + flag[1] == 0xaa)
s.add(flag[2] ^ flag[3] == 0x10)
print(s.check(), s.model())
```

Это быстрее и предсказуемее angr, когда формула известна.

## Практикум: три крекми

1. **XOR-проверка** — восстановить константу и ключ.
2. **Хеш-проверка по частям** — решить каждую часть отдельно.
3. **VM-байткод** — дизассемблировать опкоды и найти ввод.

Эти три шаблона встречаются в большинстве misc-крекми.
