## Что такое разведка в CTF

Разведка (recon) в CTF — это первый этап любой задачи: понять, что дано, что требуется и где искать зацепки. Плохая разведка приводит к «перебору вслепую»; хорошая — сразу сужает круг инструментов.

## Чтение условия

Условие — это не только текст задания, но и метаданные:

- **название** — часто игра слов или намёк;
- **описание** — прямо указывает категорию («аудио», «образ», «сервис»);
- **формат флага** — позволяет `grep`-ать;
- **приложенные файлы** — их имена и размеры;
- **подсказки** — иногда раскрывают метод.

## Инвентаризация артефактов

Сначала — что вообще есть на входе:

```bash
ls -la
file *
du -h *
sha256sum * | head
```

Зафиксируйте: типы файлов, размеры, хеши. Хеши полезны для поиска в VirusTotal и сравнения.

## Быстрые проверки

Стандартный «первый проход» по файлу:

```bash
file challenge        # тип
strings -n 6 challenge | head   # текст
binwalk challenge     # вложенное
xxd challenge | head  # начало
xxd challenge | tail  # конец
exiftool challenge    # метаданные
```

Это 6 команд, которые за минуту дают 80% зацепок.

## Работа с подсказками

Подсказки — не «чит», а часть условия. Их нужно **интерпретировать**, а не копировать. Например, «посмотри на время» → таймлайн/EXIF; «это не то, чем кажется» → полиглот/стего; «важны детали» → байты/метаданные.

## Разобранный пример

Дано: `sound.wav`, описание «услышь истину».

```bash
file sound.wav
exiftool sound.wav
strings -n 6 sound.wav | head
```

В `strings` находим `FLAG{...}` — задача решена разведкой. Если нет — переходим к аудио-стего (спектрограмма, LSB).

## Частые ошибки и подводные камни

- **Пропуск метаданных.** `exiftool` часто даёт ответ.
- **Игнорирование конца файла.** Данные бывают дописаны в конец.
- **Слепой запуск.** Сначала `file`, потом действия.
- **Не записывать находки.** Ведите журнал разведки.
- **Трата времени на один файл.** Разделите: сначала обзор всех артефактов.

## Что дальше / решение

1. Прочитайте условие и выпишите «дано/требуется».
2. Инвентаризируйте артефакты (`ls`, `file`, `du`).
3. Сделайте быстрый проход (`strings`, `binwalk`, `xxd`, `exiftool`).
4. Интерпретируйте подсказки, а не копируйте.
5. Зафиксируйте зацепки и переходите к целевым инструментам.

## Инвентаризация сервисов (web/network задачи)

Если задача даёт URL или хост, разведка идёт по другому сценарию:

```bash
curl -sI http://target/            # заголовки
curl -s http://target/ | head      # тело
ffuf -w /usr/share/seclists/Discovery/Web-Content/common.txt -u http://target/FUZZ
```

Смотрите: `Server`, `X-Powered-By`, cookies, редиректы, `robots.txt`, `sitemap.xml`. В сетевых задачах — `nmap -sV -sC` и баннеры сервисов.

## Работа с архивами и вложенностью

Многие задачи — «матpёшка». Разворачивайте итеративно и следите за типом:

```bash
while [ -f f ]; do
  t=$(file -b f)
  case "$t" in
    *Zip*)  unzip -o f -d d && f=$(find d -type f | head -1);;
    *gzip*) mv f f.gz && gunzip -f f.gz && f=${f%.gz};;
    *tar*)  tar xf f && f=$(find . -type f -newer f | head -1);;
    *) break;;
  esac
done
```

`binwalk -e` часто делает это автоматически. Если архив с паролем — переходите к теме парольных задач.

## Журнал разведки

Ведите текстовый файл заметок:

```
# задача: sound.wav
- file: WAV audio
- exiftool: Software=Audacity
- strings: нашёл "FLAG{...}" -> РЕШЕНО
```

Это спасает при возврате к задаче и не даёт повторять тупиковые шаги. В командной работе — обязателен.

## Интерпретация «странностей»

- **Файл открывается, но «не то»** → полиглот.
- **Пустой на вид** → whitespace-стего.
- **Огромный без структуры** → карвинг/дамп.
- **Правильный, но с «лишним» в конце** → дописанные данные.
- **Несколько форматов в `file`** → составной файл.

## Частые вопросы по разведке

- **С чего начать?** `file`, `strings`, `binwalk`, `xxd`, `exiftool`.
- **Не понимаю условие?** Выпишите «дано/требуется» и ищите подсказки в названии.
- **Много файлов?** Сначала обзор всех, потом углубление в подозрительные.
- **Нашёл зацепку?** Запишите и сразу проверьте гипотезу.

## Мини-шпаргалка разведки

```bash
ls -la                      # что есть
file *                      # типы
strings -n 6 f | head       # текст
binwalk f                   # вложенное
xxd f | head; xxd f | tail  # начало/конец
exiftool f                  # метаданные
sha256sum f                 # хеш для поиска
```

Плюс для web: `curl -sI`, `ffuf`, `robots.txt`. Для сети: `nmap -sV -sC`.

## Итог по разведке

Разведка — самый дешёвый способ ускорить решение. Шесть команд «первого прохода» дают большинство зацепок, а аккуратный журнал спасает от повторения тупиков. Всегда начинайте с инвентаризации и интерпретации подсказок, а не с запуска тяжёлых инструментов. Классифицируйте задачу — и нужный инструмент найдётся сам.

## Кейс: анализ архива-матрёшки

Дано: `challenge.zip`. Проверяем и разворачиваем:

```bash
file challenge.zip
unzip -l challenge.zip
unzip challenge.zip -d out/
ls -R out/
```

Внутри может быть ещё архив, картинка или скрипт. Повторяем `file` на каждом файле, пока не упрёмся в флаг. Если внутри архив с паролем — переходим к теме паролей; если картинка — к стего.

## Кейс: изображение с секретом

Дано: `mystery.png`.

```bash
exiftool mystery.png          # метаданные
zsteg mystery.png             # LSB
binwalk mystery.png           # вложенное
strings mystery.png | head
```

Порядок проверок: метаданные → LSB → вложенные форматы → строки. Часто флаг находится на одном из первых шагов; если нет — углубляемся в каналы/плоскости (stegsolve).

## Кейс: бинарник без подсказок

Дано: `program`. Ни описания, ни имени формата.

```bash
file program
strings -n 6 program | head -30
./program            # запустить (в песочнице!)
```

Запуск часто сразу показывает, чего хочет программа. Если просит ввод — это крекми (реверс); если открывает порт — сетевая задача; если падает — pwn.

## Итог по разведке

Разведка — это про порядок и полноту. Быстрый проход шестью командами, фиксация находок, интерпретация подсказок и аккуратная классификация дают основную часть зацепок. Никогда не пропускайте метаданные и конец файла; не запускайте бинарники на рабочей машине; ведите журнал. Эти привычки делают решение предсказуемым даже для незнакомых задач.

## Анализ сетевых дампов

Если задача даёт `.pcap`, разведка начинается с протоколов и потоков:

```bash
tshark -r capture.pcap -q -z io,phs          # иерархия протоколов
tshark -r capture.pcap -Y http -T fields -e http.request.uri | head
tshark -r capture.pcap --export-objects http,out/
```

Часто флаг лежит в HTTP-ответе, в файле, переданном по сети, или в учётных данных (HTTP Basic, FTP). `--export-objects` выгружает все переданные файлы.

## Анализ памяти

Дампы RAM (`*.raw`, `*.dmp`) содержат пароли, ключи и открытые файлы.

```bash
strings -n 8 memory.raw | grep -i -a 'flag\|password'
volatility -f memory.raw imageinfo
volatility -f memory.raw --profile=Win10x64 pslist
```

Начните со `strings` и `grep` — часто этого хватает; полноценный анализ — через Volatility (списки процессов, файлов, дампы).

## Работа с бинарными форматами

Для неизвестного формата — структурируйте:

```bash
file mystery
xxd mystery | head
binwalk mystery
```

Определите магию, размеры, поля. Напишите парсер на Python (`struct`), извлеките данные. Если внутри — сжатые блоки (zlib), распакуйте (`zlib.decompress`).

## Практикум

1. **pcap** → `tshark -z io,phs`, затем экспорт объектов.
2. **memory.raw** → `strings | grep`, затем Volatility.
3. **mystery.bin** → `xxd`, определить структуру, распарсить.
4. **archive** → `binwalk -e`, распаковать матрёшку.

Каждый из этих путей — стандартный «маршрут разведки» для своего типа артефакта.
