## Вопрос, с которого всё начинается

В `misc-intro` мы научились классифицировать неизвестный артефакт. Самый частый случай на практике: вам дают **строку**, и она выглядит как бессмысленный набор символов. Что это — шифр, который надо ломать, или просто другая форма записи тех же данных?

Разница принципиальна. **Кодирование** — это обратимое представление данных в другом алфавите, без секрета. **Шифрование** — сокрытие данных, требующее ключ. Если строка просто «непонятно выглядит», сначала проверяйте кодировки: это дешевле, чем строить атаку.

Разберём один конкретный набор символов и доведём его до читаемого текста.

## Наш пример: строка из задания

В условии дана строка:

```
U0dWc2JHOD0=
```

Разберём её по шагам.

## Шаг 1: узнаём кодировку по виду

Первое действие — **посмотреть на алфавит**. Символы здесь — латинские буквы, цифры, плюс/слэш и знак `=` на конце. Это классические признаки **Base64** — способа записать любые байты, используя 64 «безопасных» символа. Знак `=` — выравнивание (padding).

Проверим декодированием. `base64 -d` — стандартная утилита, читает из stdin, пишет раскодированное:

```bash
$ echo 'U0dWc2JHOD0=' | base64 -d
SGVsbG8=
```

Получилась… снова строка, похожая на Base64. Значит, данные закодированы **несколько раз**. Это обычная практика в задачах: многослойные цепочки.

## Шаг 2: декодируем второй слой

```bash
$ echo 'SGVsbG8=' | base64 -d
Hello
```

Готово — читаемый текст. Итог: `U0dWc2JHOD0=` → `SGVsbG8=` → `Hello`. Два слоя Base64, никакого ключа, никакого шифра.

## Шаг 3: как распознавать другие кодировки

Base64 — лишь один из многих. Взгляните на таблицу признаков:

| Вид | Вероятная кодировка |
|-----|---------------------|
| `SGVsbG8=` | Base64 (с `=` на конце) |
| `48656c6c6f` | Hex |
| `%48%65%6c` | URL-encoding |
| `01101000` | Бинарный ASCII |
| `.... . .-..` | Морзе |
| `S$G$V$s` | ROT/подстановка |
| `JBSWY3DP` | Base32 |
| `StV1o` | Base58 (нет `0OIl`) |

Декодируем каждый своим инструментом:

```bash
$ echo '48656c6c6f' | xxd -r -p
Hello
$ python3 -c "import urllib.parse;print(urllib.parse.unquote('%48%65%6c%6c%6f'))"
Hello
$ echo 'Uryyb' | tr 'A-Za-z' 'N-ZA-Mn-za-m'
Hello
```

Три разных представления — один и тот же `Hello`. У `xxd -r -p` (`-r` — «обратно», `-p` — plain hex) получили байты из шестнадцатеричных пар. `unquote` разворачивает URL-проценты. А `tr` с наборами `A-Za-z`→`N-ZA-Mn-za-m` делает сдвиг на 13 букв — это **ROT13**.

## Шаг 4: ROT-N, а не только ROT13

ROT13 самообратен (применили дважды — вернулись к исходному), поэтому его любят в задачах. Но сдвиг может быть любым от 1 до 25. Если ROT13 не дал осмысленного текста — перебирайте все сдвиги:

```python
def caesar(s, n):
    return ''.join(chr((ord(c)-65+n)%26+65) if c.isupper() else c for c in s)
```

`ord(c)` — код символа, `%26` зацикливает алфавит. Ещё есть **Atbash** — обратный алфавит (`a`↔`z`): `''.join(chr(219-ord(c)) if c.isalpha() else c for c in s)`.

## Шаг 5: QR и штрихкоды — те же данные в картинке

Иногда кодировка спрятана в изображении. QR-код — это тоже представление строки, просто нарисованное. Читаем утилитой `zbarimg`:

```bash
$ zbarimg qr.png
QR-Code:flag{test}
```

Если код не читается (низкий контраст, инверсия, повреждение), помогает предварительная обработка картинки — бинаризация через PIL/OpenCV. А сгенерировать свой QR можно `qrencode -o out.png 'flag{test}'`.

## Шаг 6: Unicode-трюки — кодировки поверх текста

Помимо байтовых кодировок, есть **Unicode-трюки**. Одна и та же строка может быть записана разными последовательностями символов, а некоторые символы вообще не видны:

- **Zero-width:** `\u200b`, `\u200c`, `\u200d`, `\ufeff` — не отображаются, но могут кодировать биты.
- **Гомоглифы:** кириллическая `а` выглядит как латинская `a`, но это другой символ.
- **Нормализация:** NFC/NFD меняют представление; сравнение без нормализации ломается.

```python
import unicodedata
s = 'pаypal'                       # 'а' кириллическая
print([hex(ord(c)) for c in s])
print([c for c in s if unicodedata.category(c) == 'Cf'])   # невидимые
```

Так прячут данные (битами в zero-width) и обходят фильтры (гомоглифами). Подробно — в отдельном уроке про Unicode.

## Шаг 7: автоматизируем цепочки

Когда слоёв много, удобен рекурсивный декодер: пробуем декодеры по очереди, и если результат изменился и остался печатным — идём на следующий круг.

```python
import base64, binascii, urllib.parse, re
def autodecode(s, depth=0):
    if depth > 8 or not s.strip(): return s
    s = s.strip()
    for fn in (lambda x: base64.b64decode(x),
               lambda x: binascii.unhexlify(re.sub(r'[\s:]', '', x)),
               lambda x: urllib.parse.unquote(x).encode()):
        try:
            out = fn(s.encode())
            if out and out != s.encode():
                return autodecode(out.decode('utf-8', 'replace'), depth+1)
        except Exception:
            pass
    return s
```

Такой скрипт за секунды проходит цепочки base64/hex/URL. Для морзянки и ROT добавьте свои ветки.

## Чек-лист распознавания

Пробегаем по вопросам сверху вниз, пока не «щёлкнет»:

| Вопрос | Действие |
|--------|----------|
| Есть `=` в конце? | Base64 (`base64 -d`) |
| Только `0-9a-f`? | Hex (`xxd -r -p`) |
| Есть `%`? | URL (`unquote`) |
| Точки и тире? | Морзе (свой словарь) |
| Только `0`/`1`? | Бинарь (`int(x, 2)`) |
| Невидимые символы? | zero-width / Unicode |
| Картинка? | `zbarimg` / QR |

Держите под рукой `python3` с модулями `base64`, `binascii`, `codecs` — этого достаточно для 90% задач на кодировки. А для интерактивной работы удобен CyberChef: накидываете операции мышью (`From Base64` → `From Hex` → `ROT13`), а кнопка «Magic» подбирает цепочку автоматически.

## Что мы теперь знаем

- Кодирование обратимо без ключа; шифрование — нет. Сначала пробуем кодировки.
- Base64 узнаётся по алфавиту `A-Za-z0-9+/` и знаку `=`; декодируется `base64 -d`.
- Hex — `xxd -r -p`; URL — `urllib.parse.unquote`; ROT13 — `tr` или `codecs.decode(..., 'rot13')`.
- Данные часто закодированы **несколько раз** — декодируйте в цикле.
- QR/штрихкоды читаются `zbarimg`.

## На что смотреть дальше

- **Путаница кодирования и шифрования** — не ищите ключ там, где его нет.
- **Несколько слоёв** — base64 от base64 обычное дело; после каждого слоя смотрите, печатный ли результат.
- **Неверный алфавит Base** — base58/62/85 имеют собственные таблицы, стандартный `base64 -d` их не возьмёт.
- **Только ROT13** — не забудьте про остальные сдвиги и Atbash.
- **Плохой QR** — бинаризация перед `zbarimg`; инвертированный QR (белое на чёрном) тоже нужно инвертировать.
