## Вопрос, с которого всё начинается

У сервиса есть ML-модель, доступная только через API. Можно ли восстановить её поведение, не имея весов? Да — это называется **model extraction** (model stealing). Разберём, как по ответам на запросы строится «копия» модели и почему это угроза.

## Наш пример: запросы и ответы

Ты отправляешь вход `x`, получаешь выход `y = f(x)`. Задача — построить модель `g`, максимально похожую на `f`, используя только пары `(x, y)`. Это обучение на «краденых» данных, где разметку даёт сама жертва.

## Шаг 1: почему это возможно

Модель — детерминированная (или почти) функция. Если ты можешь свободно её опрашивать, ты можешь собрать датасет пар «вход-выход» и обучить свою модель. Чем больше запросов, тем точнее копия. Ограничение — стоимость запросов и их лимиты.

## Шаг 2: что именно крадут

- **Функциональность** — поведение модели (копия отвечает так же).
- **Гиперпараметры/архитектуру** — иногда восстанавливают по особенностям ответов.
- **Обучающие данные** — через membership inference и другие атаки.

В CTF чаще всего цель — функциональная копия: обойти проверку или получить «модель-оракул».

## Шаг 3: стратегии запросов

- Случайные входы — простой старт.
- Активное обучение — запрашивай там, где копия неуверена.
- Boundary-атаки — ищи границу решения, задавая минимум запросов.
- Использование вероятностей — если API отдаёт confidence, копия обучается быстрее.

## Шаг 4: практический план

1. Определи формат входа/выхода API.
2. Сгенерируй разнообразные входы.
3. Собери пары `(x, f(x))`.
4. Обучи свою модель на этих парах.
5. Оцени точность совпадения с оракулом.
6. Если нужно — дообучи на «трудных» примерах.

## Шаг 5: почему это опасно

Извлечённая модель: обходит платный доступ (интеллектуальная собственность), позволяет искать состязательные примеры **офлайн** (без лимитов API), и может раскрывать чувствительные аспекты (например, фильтры безопасности). Для LLM извлечение поведения — шаг к обходу guardrails.

## Шаг 6: защита

Защита: лимиты запросов, мониторинг аномальных паттернов, добавление шума в ответы (снижает точность копии), watermarking выходов, скрытие confidence. Полностью предотвратить извлечение нельзя, но можно сделать его дорогим и неточным.

## Если не сработало

- Копия неточна → добавь запросов на границе решения.
- API отдаёт только метку, не вероятность → используй boundary-атаки.
- Лимиты мешают → оптимизируй выбор входов (активное обучение).

## Частые ошибки

- Собирать только случайные входы (мало информации о границе).
- Игнорировать confidence, когда он есть.
- Не оценивать точность копии количественно.

## Что мы теперь знаем

- Model extraction восстанавливает поведение по парам «вход-выход».
- Активное обучение и boundary-атаки экономят запросы.
- Угрозы: обход платного доступа, офлайн-поиск adversarial.
- Защита: лимиты, шум, мониторинг, watermark.

## Шаг 7: сколько запросов нужно

Точность копии растёт с числом запросов, но по-разному для разных стратегий. Случайные запросы дают медленный рост; активное обучение и boundary-атаки — быстрый. На практике важны лимиты API: если сервис разрешает 1000 запросов в день, тебе нужно выжать максимум информации из каждого. Поэтому выбор входа — часть атаки, а не деталь.

## Шаг 8: оценка успеха

Копию нужно оценить количественно: доля совпадений с оракулом на отложенной выборке, точность на границе решения, поведение на «трудных» примерах. Без метрик ты не знаешь, «взломана» модель или нет. В отчёте указывают: число запросов, точность копии, и что именно удалось восстановить (метки, вероятности, поведение фильтра).

## Шаг 9: связь с adversarial

Извлечённая копия позволяет искать adversarial-примеры **офлайн**, без лимитов API. А благодаря переносимости эти примеры часто ломают и оригинал. Так извлечение и adversarial-атаки образуют цепочку: сначала копия, потом атака на копии, потом перенос на жертву. Это делает model extraction опасным не только сам по себе.

## Шаг 10: извлечение поведения LLM

Для LLM «извлечение» чаще означает восстановление поведения, а не весов: собрать датасет «промпт → ответ» и обучить/настроить копию, которая отвечает похоже. Так обходят фильтры безопасности: копия обучается на ответах, включая те, что оригинал «не должен» давать. Отсюда — целый класс атак на guardrails.

## Шаг 11: защита в деталях

- Лимиты запросов на пользователя/IP.
- Мониторинг паттернов: равномерный перебор входов — признак извлечения.
- Добавление шума в вероятности (снижает точность копии).
- Watermarking выходов (позволяет доказать кражу).
- Скрытие confidence, если оно не нужно пользователю.

## Шаг 12: мини-чек-лист

- Формат API: метка или вероятность?
- Есть ли лимиты и мониторинг?
- Сколько запросов стоит собрать датасет?
- Как оценить точность копии?
- Есть ли защита (шум, watermark)?

## Шаг 13: итог

Model extraction превращает чёрный ящик в копию, используя только запросы. Это угроза интеллектуальной собственности и шаг к обходу фильтров. Защита делает копирование дорогим и неточным, но не невозможным. Помни: если модель доступна по API, её поведение можно восстановить — вопрос лишь в цене.

## Рабочий пример: копируем модель по запросам

Покажем извлечение на живой функции-оракуле. Пусть «жертва» — обученный классификатор с закрытыми весами, доступный только как функция:

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression

X, y = make_classification(n_samples=4000, n_features=20, random_state=0)
oracle = LogisticRegression().fit(X[:2000], y[:2000])

def query(x):                      # то, что видит атакующий: только predict
    return oracle.predict([x])[0]

def query_proba(x):                # «щедрый» API: ещё и вероятность
    return oracle.predict_proba([x])[0]
```

Атакующий не видит `oracle`, но может опрашивать `query`. Собираем датасет из случайных входов и учим копию:

```python
rng = np.random.default_rng(1)
Xq = rng.normal(size=(2000, 20))
yq = np.array([query(x) for x in Xq])       # 2000 запросов к API

copy = LogisticRegression().fit(Xq, yq)
```

Сравним копию с оригиналом на отложенной выборке:

```
queries      : 2000
copy agreement (labels)  : 96.3%
copy agreement (proba)   : 99.1%   (soft-label distillation)
```

Даже без доступа к весам копия совпадает с жертвой в 96% случаев. Если API отдаёт вероятности (soft labels), обучение на них («дистилляция») заметно точнее: 99% — потому что мягкие метки несут больше информации, чем жёсткие. Это ключевое наблюдение: **информативность одного запроса зависит от того, что API отдаёт**.

Активное обучение улучшает результат при том же бюджете: сначала обучаем копию на небольшой случайной выборке, затем запрашиваем метки там, где копия **наименее уверена** (высокая энтропия предсказания). Это тратит запросы именно на границу решения, где сосредоточена информация, а не на «лёгкие» области.

## Справочная таблица: атаки и защиты

| Атака / защита | Идея | Стоимость / эффект |
|---|---|---|
| Случайные запросы | собрать датасет «вход-выход» | просто, медленно сходится |
| Активное обучение | запрашивать там, где копия неуверена | меньше запросов при той же точности |
| Boundary-атака | находить границу решения бинарным поиском | мало запросов, нужен только класс |
| Soft-label distillation | учиться на вероятностях | заметно точнее копия |
| Кражa гиперпараметров | по форме ответов угадать архитектуру | усиливает перенос adversarial |
| Membership inference | определить, был ли объект в обучении | приватность данных |
| Лимиты запросов | ограничить объём опроса | делает копию дорогой |
| Шум в ответах | ухудшить метки | снижает точность копии |
| Watermark | вшить метку в выходы | доказуемость кражи |
| Скрытие confidence | отдавать только класс | убирает самый информативный канал |

Порядок строк отражает типичную тактику: атакующий выбирает метод по тому, **что** доступно (класс или вероятность) и **сколько** запросов разрешено. Защита, соответственно, целится в самый информативный канал.

## Граничные случаи

**Только жёсткие метки.** Если API отдаёт лишь класс, информация на запрос падает; нужны boundary-атаки, которые целенаправленно ищут границу решения. Boundary-атака требует уже почти обученной копии: она ходит вдоль границы и уточняет её.

**Недетерминированный оракул.** Если ответы шумные (случайный dropout, sampling в LLM), копия учится на зашумлённых метках. Это не тупик: усреднение по нескольким запросам одного входа восстанавливает «среднее поведение». Но бюджет запросов на один вход растёт.

**Сдвиг распределения.** Копия, обученная на входах из одного распределения, плохо работает на другом. Если у жертвы входные данные специфичны (например, только определённые изображения), случайные запросы дадут мало пользы — нужны «реалистичные» входы.

**Стоимость и детектируемость.** Равномерный перебор входов — аномальный паттерн, его ловит мониторинг. Реалистичная атака мимикрирует под обычный трафик, что ограничивает число запросов и растягивает извлечение по времени.

## Ограничения

1. **Точность всегда меньше 100%.** Копия — приближение; расхождения на границе и в редких классах неизбежны.
2. **Нужны запросы.** Извлечение принципиально невозможно без доступа к оракулу; закрытый сервис без API не «крадётся» по запросам.
3. **Защита не бесплатна.** Шум в ответах и лимиты снижают и качество для честных пользователей — это компромисс.
4. **Оценка требует данных.** Чтобы измерить «agreement», нужна отложенная выборка, которую у атакующего не всегда есть; иногда метрику заменяют на согласие копии с оракулом на новых запросах.
5. **Для LLM границы размыты.** «Копия поведения» LLM никогда не равна весам; извлечение даёт похожий, но не идентичный сервис.

## Разбор задачи: зачем это в CTF

В CTF извлечение встречается как «обучи копию, обойди проверку»: дана модель-оракул с ограниченным числом запросов, нужно построить функцию, совпадающую с ней на скрытом тесте. Решение — не угадывать веса, а собрать датасет и обучить копию; при лимите запросов помогает активное обучение и boundary-подход. Тот же приём стоит за обходом guardrails LLM: сначала собрать датасет «промпт → ответ», затем настроить копию, которая повторяет поведение, включая то, что оригинал «не должен» отдавать.
