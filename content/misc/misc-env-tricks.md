## Вопрос, с которого всё начинается

Ты запускаешь скрипт, который делает `tar` в cron от root. Вроде всё безопасно. Но атакующий создаёт свой файл `tar` в каталоге, который оказался в `PATH` раньше системного, — и при следующем запуске выполняется его код от root. Почему? Потому что программа искала `tar` **по PATH**. Разберём переменные окружения как вектор.

## Наш пример

Возьмём переменную `PATH`. Выполним `echo $PATH`:

```
$ echo $PATH
/usr/local/bin:/usr/bin:/bin
```

Оболочка ищет команду слева направо. Значит, если `/usr/local/bin` доступен на запись, атакующий положит туда `tar`, и система найдёт его первым. Это и есть **PATH hijack**.

## Шаг 1: PATH — порядок поиска

`PATH` — список каталогов через `:`. Когда ты пишешь `tar`, оболочка проходит список и берёт первое совпадение. Если раньше системного каталога окажется каталог, куда может писать непривилегированный пользователь, — подмена неизбежна. Особенно опасно, если в cron-скрипте не указан абсолютный путь (`/bin/tar` вместо `tar`).

## Шаг 2: IFS — разделитель слов

`IFS` (Internal Field Separator) задаёт символы, которыми shell разбивает строку на слова. По умолчанию это пробел, таб и перевод строки. Если поменять `IFS`, можно сломать разбор команд и обойти фильтры. Редкий, но мощный приём в CTF: установив `IFS=/`, ты меняешь, как читается строка.

## Шаг 3: LD_PRELOAD и LD_LIBRARY_PATH

`LD_PRELOAD` заставляет динамический линкер загрузить указанную библиотеку **до** системных. Если ты подсунешь свою `.so` с переопределённой функцией (например, `strcmp`), программа выполнит твой код. Это классический способ перехвата. `LD_LIBRARY_PATH` делает похожее для поиска библиотек. Для setuid-программ линкер игнорирует эти переменные — иначе был бы тривиальный privesc.

## Шаг 4: BASH_ENV и ENV

При запуске неинтерактивного bash читает файл из `BASH_ENV` и исполняет его. Если атакующий контролирует `BASH_ENV`, он выполнит произвольные команды в контексте того, кто запустил bash. Аналогично `ENV` для sh. Это ещё один способ «впрыснуть» код через окружение.

## Шаг 5: как окружение попадает в привилегированный контекст

Вектор опасен, когда привилегированная программа (cron, setuid, systemd-юнит) наследует окружение пользователя или когда каталог из `PATH` доступен на запись. Тогда «данные» превращаются в «код». Классический privesc-чеклист: `sudo -l` (какие переменные разрешены), cron-скрипты без абсолютных путей, каталоги в `PATH` с правами на запись.

## Шаг 6: как искать

- `echo $PATH` и права на каждый каталог: `ls -ld`.
- `find / -perm -o+w -type d 2>/dev/null` — мировые каталоги, доступные на запись.
- `cat /etc/crontab` и `ls /etc/cron.*` — задачи с относительными путями.
- `sudo -l` — какие `env_keep` разрешены.

## Шаг 7: как защищаться

- В скриптах указывай абсолютные пути (`/bin/tar`).
- Задавай `PATH` явно в начале скрипта.
- Очищай окружение перед запуском привилегированных программ (`env -i`).
- Не храни каталоги с правом записи в `PATH`.
- В sudoers не разрешай `env_keep` для опасных переменных.

## Шаг 8: практический сценарий

В CTF: `sudo -l` показывает, что можно запустить скрипт от root, а скрипт вызывает `service` без пути. Ставим свой `service` в каталог из `PATH` — получаем root. Или: cron от root вызывает `backup.sh`, который использует `tar`; кладём `tar` в `/tmp`, добавляем `/tmp` в `PATH` через экспорт в cron-окружении. Общий шаблон: найти относительную команду в привилегированном контексте + каталог с правом записи.

## Частые ошибки

- Считать, что «скрипт безопасен», не проверив `PATH` и абсолютные пути.
- Забыть, что setuid сбрасывает `LD_PRELOAD`, но не все переменные.
- Игнорировать `BASH_ENV` в неинтерактивных оболочках.

## Что мы теперь знаем

- `PATH` определяет, какой бинарник найдётся первым.
- `IFS` меняет разбор слов; `LD_PRELOAD` перехватывает функции.
- `BASH_ENV`/`ENV` впрыскивают код в неинтерактивный shell.
- Опасность — когда окружение попадает в привилегированный контекст.
- Защита: абсолютные пути, чистка окружения, контроль прав каталогов.

## Практика: PATH hijack шаг за шагом

Соберём минимальный сценарий. Пусть есть setuid-скрипт, вызывающий `date` без пути:

```
$ sudo -l
User www-data may run the following commands:
    (root) NOPASSWD: /opt/backup.sh
$ cat /opt/backup.sh
#!/bin/sh
date > /var/log/backup.stamp
tar czf /var/backups/home.tgz /home
```

В `PATH` есть каталог, куда мы можем писать. Создаём там свою `date`:

```
$ echo 'cp /bin/sh /tmp/rootsh; chmod 4755 /tmp/rootsh' > /tmp/date
$ chmod +x /tmp/date
$ PATH=/tmp:$PATH sudo /opt/backup.sh
$ /tmp/rootsh -p -c id
uid=0(root) gid=0(root)
```

Скрипт искал `date` по `PATH`, нашёл нашу версию первой и выполнил её от root. Именно
поэтому в привилегированных скриптах пути обязаны быть абсолютными.

## Таблица: опасные переменные окружения

| Переменная | Что делает | Где опасна |
|------------|-----------|------------|
| `PATH` | порядок поиска программ | cron, sudo, setuid |
| `IFS` | разделитель слов | обход фильтров, разбор команд |
| `LD_PRELOAD` | форсирует загрузку `.so` | обычные процессы (не setuid) |
| `LD_LIBRARY_PATH` | путь поиска библиотек | запуск непривилегированных программ |
| `BASH_ENV` / `ENV` | файл, читаемый при старте shell | неинтерактивный bash/sh |
| `PYTHONPATH` | путь импорта модулей Python | скрипты, вызывающие python |
| `PERL5LIB` / `NODE_OPTIONS` | аналог для Perl/Node | соответствующие рантаймы |
| `HISTFILE` / `PROMPT_COMMAND` | файл истории / команда перед промптом | интерактивные сессии |

## Окружение в sudo и systemd

`sudo` по умолчанию **чистит** окружение, но список исключений настраивается в
`env_keep`. Проверяй:

```
$ sudo -l
    env_keep += "LD_PRELOAD"
```

Такая строка — почти гарантированный privesc: разрешено протащить свой `.so` в
привилегированный процесс. Аналогично смотри `Defaults env_keep` в `/etc/sudoers`.
У systemd-юнитов переменные задаются в `Environment=`/`EnvironmentFile=`; если файл
окружения доступен на запись непривилегированному пользователю — это тот же вектор.

## Если не сработало / не сработало

- **Не сработал `LD_PRELOAD`** на setuid-бинарнике — это норма: линкер игнорирует
  `LD_*` для setuid из соображений безопасности. Вектор применим только к обычным
  процессам, которые запускает привилегированный пользователь.
- **Не нашёлся каталог в `PATH`** — значит, все каталоги только на чтение от root.
  Тогда переходи к `sudo`-правилам, cron-файлам и writable-конфигам.
- **`env -i` перед запуском** — окружение очищено намеренно; вектор закрыт, ищи
  аргументы командной строки или конфиг-файлы вместо переменных.

## Ограничения

Переменные окружения — это «данные, которые становятся кодом» только тогда, когда
попадают в привилегированный контекст. Само по себе значение `PATH=/tmp` безвредно.
Поэтому на пентесте ищи не «странные переменные», а **точку соединения**: где
привилегированная программа наследует окружение или где каталог из `PATH` writable.

## Разбор: IFS в реальной задаче

`IFS` меняет, как shell разбивает строку на слова. Иногда это используют для обхода
проверок. Представим фильтр, который запрещает строку `cat /etc/passwd`:

```
$ IFS=/ read -r a b c <<< "/etc/passwd"; echo "$a"
cat: '': No such file or directory
```

Смена `IFS` заставляет оболочку делить ввод по `/`, и команда собирается из частей
иначе, чем ожидает наивный фильтр. Тот же приём работает с пробелами: `IFS=$'\t'`
меняет разделитель слов на таб. В защите это значит: не полагайся на строковый
фильтр команд — нормализуй ввод и не передавай его в shell.

## Окружение в рантаймах: PYTHONPATH и NODE_OPTIONS

Вектор не ограничен shell. Python импортирует модули по `PYTHONPATH`, Node читает
`NODE_OPTIONS`, Perl — `PERL5LIB`. Если привилегированный скрипт запускает
интерпретатор и не чистит окружение, атакующий подкладывает свой модуль:

```
$ echo 'import os; os.system("id")' > /tmp/sitecustomize.py
$ PYTHONPATH=/tmp python3 -c 'print("ok")'
uid=0(root) gid=0(root)
```

`sitcustomize` — модуль, который Python импортирует автоматически при старте, если
находит его в пути. Один экспорт `PYTHONPATH` — и код выполнен. Защита: `env -i`
перед запуском интерпретатора и явный `-S`/`-E` (игнорировать `PYTHON*`-переменные).

## Чек-лист проверки окружения на пентесте

- `sudo -l` — есть ли `env_keep` для `LD_PRELOAD`, `PATH`, `PYTHONPATH`.
- `find / -perm -o+w -type d` — writable-каталоги, которые могут попасть в `PATH`.
- `cat /etc/crontab` и `ls /etc/cron.*` — задачи с относительными командами.
- systemd-юниты: `EnvironmentFile=` на writable-пути.
- `printenv` под своим пользователем и под привилегированным (если можно).

Каждый пункт — потенциальная точка, где «данные» становятся «кодом».

## Разбор: BASH_ENV на практике

`BASH_ENV` указывает файл, который неинтерактивный bash исполняет при старте. Если
этот файл контролируем — контролируем и выполнение:

```
$ echo 'echo "[pwned] uid=$(id -u)"' > /tmp/e.sh
$ BASH_ENV=/tmp/e.sh bash -c 'echo start'
[pwned] uid=1000
start
```

Видно, что наш код выполнился **до** основной команды `echo start`. Если такую
переменную наследует cron-задача или привилегированный скрипт, вызывающий `bash -c`,
вектор срабатывает. Защита: `env -i` перед запуском и явный запрет `env_keep` для
`BASH_ENV`/`ENV` в sudoers.

## Как окружение «течёт» через sudo

`sudo` обычно делает `env_reset`, но конфигурация может разрешить протащить
переменные. Смотри две вещи:

- `Defaults env_keep += "..."` — белый список сохраняемых переменных;
- `SETENV` в правиле `sudoers` — разрешение передавать переменные с `sudo VAR=val cmd`.

Если в белом списке оказался `LD_PRELOAD`, `PATH` или `PYTHONPATH` — это privesc.
Проверяй `sudo -l` и `sudo -V` (видно, включён ли `env_reset`).

## Где пригодится

- Privilege escalation: PATH/IFS-атаки на cron и sudo.
