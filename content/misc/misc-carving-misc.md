## Вопрос, с которого всё начинается

Тебе дали файл `disk.raw` — побайтовый слепок диска. Никакой файловой системы поверх: ни FAT, ни ext4, ни каталогов. Просто миллионы байтов. Где-то среди них лежит картинка с флагом. Как её достать, если «файлов» как таковых нет?

Ответ — **carving**: восстановление файлов по их внутренним признакам, а не по записям файловой системы.

## Наш пример: сырой образ

```
$ file disk.raw
disk.raw: data
$ wc -c disk.raw
10485760 disk.raw
$ strings disk.raw | grep -i nto
```

`file` не распознал формат — значит, нет структуры, за которую зацепиться. `strings` показывает читаемые куски, но флаг может быть внутри сжатого или бинарного файла. Нужен структурный подход.

## Шаг 1: что такое carving

**Carving** (от англ. «вырезание») — извлечение файлов из потока байтов по их сигнатурам. Идея проста: у каждого формата есть характерное начало — **магические байты**, или **сигнатура**. PNG всегда начинается с `89 50 4E 47 0D 0A 1A 0A`, JPEG — с `FF D8 FF`, ZIP — с `PK`. Находишь сигнатуру — знаешь, что дальше начинается файл.

Carving работает там, где файловая система недоступна или повреждена: образы дисков, дампы памяти, сетевые потоки, «спрятанные» в файле архивы.

## Шаг 2: сигнатуры и footer

Начало файла задаёт сигнатура, конец — **footer** (концевая метка). У PNG footer — чанк `IEND`, у JPEG — `FF D9`. Алгоритм: найти сигнатуру, искать footer, вырезать всё между ними.

| Формат | Начало (hex) | Конец |
|---|---|---|
| PNG | 89 50 4E 47 | 49 45 4E 44 AE 42 60 82 |
| JPEG | FF D8 FF | FF D9 |
| GIF | 47 49 46 38 | 3B |
| ZIP | 50 4B 03 04 | 50 4B 05 06 |
| PDF | 25 50 44 46 | 25 25 45 4F 46 |

Если footer отсутствует (поток обрезан), берут максимальную длину и проверяют целостность.

## Шаг 3: инструменты

Три классических инструмента:

- **foremost** — старейший carver; конфиг `/etc/foremost.conf` со списком сигнатур.
- **scalpel** — форк foremost, быстрее и с более гибкими правилами.
- **binwalk** — специализируется на встроенных файлах и прошивках, умеет рекурсию.

```
$ foremost -t png,jpg -i disk.raw -o out/
Processing: disk.raw
|------------------------------------------------------------------
Num      Name (bs=512)     Size      File Offset     Comment
0:      00000012.png       45210     6144
1:      00000098.jpg       12044     50176
|------------------------------------------------------------------
```

Каждый найденный файл получает имя по смещению. Дальше — `file out/*` и `exiftool`, чтобы понять, что это.

## Шаг 4: ручной carving на Python

Инструменты не всегда есть; иногда нужен точный контроль. Тогда пишут свой carver:

```
$ python3 - <<'PY'
data = open('disk.raw','rb').read()
sig, foot = b'\x89PNG\r\n\x1a\n', b'IEND\xaeB`\x82'
i = 0
n = 0
while True:
    s = data.find(sig, i)
    if s < 0: break
    e = data.find(foot, s)
    if e < 0: break
    e += len(foot)
    open(f'carved_{n}.png','wb').write(data[s:e])
    print(f'carved_{n}.png', s, e-s)
    i, n = e, n+1
PY
carved_0.png 6144 45210
carved_1.png 1048576 2380
```

Двадцать строк — и ты извлёк все PNG из образа. Это и есть суть carving.

## Шаг 5: фрагментация

В реальности файл может быть **фрагментирован**: его куски лежат не подряд. Тогда простой «сигнатура→footer» склеит чужие байты. Признаки: картинка не открывается, ZIP битый, PDF «неожиданный конец». Приёмы:

- **Carve по заголовкам чанков.** PNG состоит из чанков с длиной; можно идти по ним, а не искать IEND.
- **Склейка по структуре.** Для ZIP — идти по локальным заголовкам и центральному каталогу.
- **Ручная сборка.** Найти все куски, собрать по смещениям.

Фрагментация — главная причина, почему carving не всегда даёт рабочий файл.

## Шаг 6: файлы без сигнатур

Не у всех форматов есть уникальное начало. Тогда работают иначе:

- **По энтропии.** Сжатые/шифрованные данные имеют высокую энтропию; их границы видны статистически.
- **По структуре.** Ищут осмысленные заголовки (например, `RIFF` для WAV/AVI).
- **По контексту.** Зная, что «рядом лежит ZIP», ищут его.

Для задач без сигнатур помогает `binwalk -E` (энтропийный график) и анализ распределения байтов.

## Полный прогон

```
$ foremost -t png -i disk.raw -o out/
$ file out/png/*
out/png/00000012.png: PNG image data, 640 x 480, 8-bit/color RGBA
$ python3 - <<'PY'
from PIL import Image
im = Image.open('out/png/00000012.png')
# метаданные и пиксели
print(im.size)
PY
```

Флаг часто лежит в пикселях (стеганография), в текстовом чанке PNG (`tEXt`) или в метаданных. Carving даёт файл — дальше его разбирают как обычный.

## Что мы теперь знаем

- Carving восстанавливает файлы по сигнатурам, без файловой системы.
- Сигнатура + footer задают границы; без footer нужна осторожность.
- foremost/scalpel/binwalk автоматизируют процесс; Python — для точного контроля.
- Фрагментация и отсутствие сигнатур — главные сложности.
- После carving файл анализируют как обычно.

## Carving не только из дисков

Carving работает везде, где есть поток байтов. Из **дампа памяти** вырезают процессы, ключи, изображения из кэша браузера. Из **сетевого потока** (pcap, сырой сокет) — переданные файлы. Из **недописанного файла** — потерянные данные. Правило одно: ищи сигнатуру, определяй границы, вырезай. Меняется лишь источник, и для памяти часто дополнительно нужен контекст — к какому процессу относились байты.

## Проверка целостности вырезанного

Вырезал файл — проверь, что он настоящий. Признаки битого: не открывается просмотрщиком; `file` не распознаёт; размер подозрительно круглый (например, ровно 4096); внутри — чужой формат. Для ZIP помогает `unzip -t`, для PNG — проверка CRC чанков, для PDF — наличие `%%EOF`. Если файл битый, скорее всего он фрагментирован или обрезан; тогда возвращайся к структурному разбору.

## Энтропия как ориентир

**Энтропия** — мера «случайности» байтов. Сжатые и зашифрованные данные имеют высокую энтропию, текстовые — низкую. Инструмент `binwalk -E` строит график энтропии по файлу: пики указывают на сжатые блоки, ровные участки — на текст или код. Это помогает найти границы того, у чего нет сигнатуры, и понять, где спрятан архив.

## Сетевые и потоковые задачи

В pcap-файлах carving идёт по потокам: для каждого TCP-соединения собираются байты, затем ищутся сигнатуры. Инструмент `tcpflow` разбивает поток на файлы по соединениям, а дальше работает обычный carver. Частая CTF-задача: переданная картинка, разбитая на пакеты. Решение — собрать поток и вырезать по сигнатуре.

## Автоматизация

Когда файлов много, пишут обёртку: прогон foremost, затем классификация результатов (`file`), затем фильтрация по типу. Можно добавить рекурсию — если вырезан ZIP, распаковать и снова карвить. Так находят «матрёшку»: архив в архиве в архиве. Главное — ограничить глубину, чтобы не уйти в бесконечность.

## Ограничения метода

Carving не панацея. Он даёт ложные срабатывания: сигнатура может встретиться в случайных данных. Он не восстанавливает метаданные (имя, время) — их нет без файловой системы. Он ломается на фрагментации. Поэтому в реальной форензике carving дополняют анализом ФС и журналов, а не заменяют его.

## Практический сценарий: флаг в пикселях

Частая CTF-задача: вырезать PNG, а флаг — не в текстовом чанке, а в младших битах пикселей. Тогда после carving открываешь изображение кодом, читаешь младший бит каждого канала и собираешь байты. Это уже стеганография поверх carving, но логика та же: сначала достань контейнер, потом разбирай содержимое. Инструменты: `zsteg`, `stegsolve`, собственный скрипт на PIL.

## Работа с большими образами

Образ на десятки гигабайт в память не влезет. Тогда carving ведут потоково: читают блоками, ищут сигнатуры в перекрывающемся окне, вырезают на диск. `foremost` и `scalpel` умеют это из коробки. Для ручного подхода используют `dd` с `skip`/`count` и обрабатывают куски по отдельности. Главное — не потерять сигнатуру на границе блоков: окно должно перекрываться на длину самой длинной сигнатуры.

## Этика и рамки

Carving — мощный инструмент, и применять его нужно только на данных, на которые есть право: свои образы, лабораторные задачи, разрешённые инциденты. Восстановление чужих удалённых файлов без основания — нарушение. В CTF и пентесте рамки заданы условиями задачи, и это как раз тот случай, когда инструмент уместен.

## Шпаргалка команд

Держи под рукой: `foremost -t png,jpg,pdf -i in.raw -o out/`; `scalpel -c scalpel.conf in.raw -o out/`; `binwalk -e image.bin`; `binwalk -E image.bin`; `strings -a -n 8 in.raw | grep -i nto`; `dd if=in.raw bs=1 skip=OFFSET count=LEN of=out.bin`. Этого набора хватает для большинства задач.
