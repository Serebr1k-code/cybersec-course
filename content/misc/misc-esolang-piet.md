Piet — эзотерический язык, где программа — это **изображение**. Код кодируется цветными блоками, а управление зависит от переходов между оттенками. В CTF Piet встречается как картинка, которую «нужно просто исполнить», или как способ спрятать программу в изображении. Этот урок — про распознавание, инструменты и ручную интерпретацию.

## Идея Piet

Название — в честь художника Пита Мондриана. Программа — растровое изображение, состоящее из «codels» — блоков одного цвета. Цвет кодирует две вещи:

- **оттенок** (hue): красный, жёлтый, зелёный, циан, синий, маджента;
- **светлоту** (lightness): светлый/нормальный/тёмный.

Итого 6 × 3 = 18 значимых цветов плюс белый и чёрный, которые управляют потоком:

- **белый** — переход к следующему codel;
- **чёрный** — «поворот» / зацикливание.

Движок Piet (DP — direction pointer, CC — codel chooser) перемещается по блокам, накапливая изменения `hue`/`lightness`, которые задают операцию.

## Как читается программа

1. Находим стартовый codel — левый верхний.
2. Определяем текущий блок и его цвет.
3. Переходим в следующий блок по правилам DP/CC.
4. Разница цветов (Δhue, Δlightness) даёт команду:

| Δhue | Δlightness | Операция |
|------|-----------|----------|
| 0 | 0 | nop |
| 0 | 1 | push |
| 0 | 2 | pop |
| 1 | 0 | add |
| 1 | 1 | subtract |
| 1 | 2 | multiply |
| 2 | 0 | divide |
| 2 | 1 | mod |
| 2 | 2 | not |
| 3 | 0 | greater |
| 3 | 1 | pointer |
| 3 | 2 | switch |
| 4 | 0 | dup |
| 4 | 1 | roll |
| 4 | 2 | in (число) |
| 5 | 0 | in (символ) |
| 5 | 1 | out (число) |
| 5 | 2 | out (символ) |

Числовые величины берутся из размера блока (число codels).

## Инструменты

| Инструмент | Назначение |
|-----------|-----------|
| `npiet` | эталонный интерпретатор Piet |
| `PietDev` | отладка с визуализацией |
| `piet` (веб) | онлайн-исполнитель |
| `PietCreator` | написание программ |

```bash
npiet program.png
# выполняет Piet-программу из изображения
npiet -t program.png    # трассировка
npiet -q program.png    # тихий режим
```

`npiet -t` печатает шаги: текущий цвет, Δ, операцию, стек — незаменимо для отладки.

## Скрытие программы в изображении

Piet-программу можно «спрятать» в обычной картинке, если цвета в ней случайно образуют валидные codels. Чаще задачу дают как «вот картинка, исполните». Если картинка выглядит как абстракция из цветных прямоугольников — почти наверняка Piet.

Признаки:

- блоки чистого цвета без градиентов;
- ограниченная палитра (18 цветов + чёрный/белый);
- прямоугольная структура.

## Разобранный пример

Дано: `art.png` — цветные прямоугольники.

```bash
file art.png
# PNG image data, 100 x 100
npiet art.png
# Hello, world!
```

Если программа выводит флаг напрямую — готово. Если «зависает» — запустите с трассировкой:

```bash
npiet -t art.png | head -40
# step 0: color (255,0,0), dp=right, cc=left
# ...
```

Если нужно ввести данные — `echo -n "input" | npiet art.png`.

## Ручная интерпретация

Когда интерпретатора нет, можно пройти программу вручную:

1. Выписать цвета блоков в порядке обхода.
2. Посчитать Δhue/Δlightness между последовательными блоками.
3. Сопоставить с таблицей операций.
4. Отследить стек и вывод.

Это трудоёмко, но на маленьких программах реально. Для больших — лучше `npiet`.

## Частые ошибки и подводные камни

- Путать DP/CC-повороты на белых и чёрных блоках — легко ошибиться вручную.
- Считать, что размер блока не важен — он задаёт число для `push`.
- Игнорировать «roll» (циклический сдвиг стека) — редкая, но встречается.
- Использовать не тот интерпретатор (разные реализации по-разному трактуют края).
- Открывать PNG в редакторе и «портить» цвета — сохраняйте оригинал.

## Дополнительная теория: DP, CC и правила движения

Поток управления в Piet задаётся двумя указателями: **DP** (Direction Pointer) — куда движемся (вправо/вниз/влево/вверх), и **CC** (Codel Chooser) — какой блок выбирать при выходе (слева/справа). Движок ищет границу текущего цветного блока в направлении DP и выбирает codel по CC. Если за границей есть блок другого цвета — переходим в него, разница цветов даёт команду. Если блоков нет — пробуем повернуть DP/CC по определённым правилам; если и это не помогает — программа завершается или зацикливается.

Белые блоки — «свободное пространство»: на них DP/CC продолжают вращаться, пока не найдут цветной блок. Чёрные блоки — «стены»: на них DP поворачивается. Именно эти правила делают Piet визуально запутанным: одна и та же картинка может исполняться по-разному в зависимости от начального DP/CC. Понимание DP/CC необходимо для ручной интерпретации и для написания своего интерпретатора.

## Стек и типы данных

Piet оперирует целыми числами произвольной точности на стеке. `push` кладёт число, равное размеру текущего блока (числу codels). `pop`, `dup`, `roll` манипулируют стеком. Арифметика (`add`, `subtract`, `multiply`, `divide`, `mod`) работает с двумя верхними значениями. `not` логическое. `greater` сравнивает. `pointer` меняет DP, `switch` меняет CC — то есть программа может управлять собственным потоком в зависимости от данных.

Операции `in`/`out` читают/пишут: `in (number)`, `in (char)`, `out (number)`, `out (char)`. В CTF программа часто выводит флаг символами (`out char`) или числами, которые надо преобразовать. Если вывод выглядит как последовательность чисел — соберите их в байты.

## Разбор ошибок и отладка

Если `npiet` сообщает об ошибке — читайте сообщение: часто это «стек пуст» (не хватает `push`) или «деление на ноль». Запустите с `-t` (трассировка) и посмотрите, на каком шаге стек не тот. Если программа «зависает» — возможно, бесконечный цикл на белых блоках; проверьте, есть ли выход. Если результат нечитаем — возможно, нужен ввод; подайте его через pipe. Если картинка «не похожа на Piet» — проверьте, нет ли альфа-канала или градиентов (Piet требует чистых цветов). В сложных случаях визуализируйте codels: увеличьте изображение (`convert -scale 800%`), чтобы видеть блоки.

## Практический разбор: от картинки до флага

Дано: `piet.png` (200×200). Шаги:

```bash
file piet.png
# PNG image data, 200 x 200, 8-bit/color RGB
npiet piet.png
# (пусто или ошибка)
```

Пустой вывод — вероятно, программа ждёт ввод или вывод в числах. Пробуем трассировку:

```bash
npiet -t piet.png 2>&1 | head -30
# step 1: color (255,0,0), dp=right, cc=left
# step 2: color (255,0,0) -> nop
# ...
```

Видим операции. Если программа печатает числа (`out number`), собираем их в байты:

```bash
npiet piet.png | python3 -c "import sys;print(bytes(int(x) for x in sys.stdin.read().split()))"
```

Если нужен ввод — подаём через pipe: `echo -n "answer" | npiet piet.png`. Если `npiet` падает с «stack underflow» — где-то не хватает `push`; это баг программы или неверный интерпретатор. Для больших программ используйте `-t` и следите за стеком. Визуализация (`convert -scale 800% piet.png`) помогает разглядеть codels. В большинстве CTF-задач достаточно запустить `npiet` — Piet редко требует ручной интерпретации целиком.
