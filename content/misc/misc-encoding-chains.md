В реальных misc-задачах данные почти никогда не закодированы одним способом. Классика — **цепочка**: base64 от hex от rot13 от бинарного представления. Задача — распознать каждый слой и снять их по порядку. Опытный игрок определяет кодировку по алфавиту и длине, а рутину отдаёт автоматике. Этот урок — про распознавание, инструменты и написание своего авто-декодера.

## Распознавание по алфавиту

Первое действие — посмотреть на множество символов:

```python
data = open('mystery.txt').read().strip()
print(sorted(set(data)))
```

| Кодировка | Признак |
|-----------|---------|
| Base64 | `A–Z a–z 0–9 + / =`, длина кратна 4 |
| Base64url | `A–Z a–z 0–9 - _`, без `+/` |
| Base32 | `A–Z 2–7 =`, длина кратна 8 |
| Hex | только `0–9 a–f`, чётная длина |
| Base85/Ascii85 | много символов, часто `<~ ~>` |
| Binary | только `0` и `1`, длина кратна 8 |
| ROT13/Цезарь | буквы, читаемый паттерн после сдвига |
| Morse | `.` `-` пробелы |
| URL | `%XX` |
| Braille/Unicode | не-ASCII глифы |

Base64 легко узнать по «хвосту» из `=` (padding) и смеси регистров. Hex — только `0-9a-f`, всегда чётной длины. Binary — только нули и единицы, длина кратна 8.

## Частые первые слои

```bash
# base64
echo 'ZmxhZ3tiYXNlNjR9' | base64 -d
# flag{base64}
echo 'ZmxhZ3tiYXNlNjR9' | base64 -d | base64 -d   # если дважды

# hex
echo '666c61677b6865787d' | xxd -r -p
# flag{hex}

# rot13
echo 'synz{ebg13}' | tr 'A-Za-z' 'N-ZA-Mn-za-m'
# flag{rot13}

# binary
python3 -c "print(bytes(int('01000110',2) for _ in [0]))"
```

`base64 -d` молча даёт мусор, если вход не base64, поэтому проверяйте результат `file` и глазами.

## Многослойные цепочки

Пример: дана строка, которая выглядит как base64, внутри — hex, внутри — rot13, внутри — флаг.

```bash
echo "$DATA" | base64 -d | xxd -r -p | tr 'A-Za-z' 'N-ZA-Mn-za-m'
```

Каждый слой меняет алфавит, и следующий инструмент подбирается по результату. Автоматизировать распознавание можно правилами:

```python
import base64, binascii, codecs, re

def try_decode(s):
    s = s.strip()
    if re.fullmatch(r'[01]{8,}', s) and len(s) % 8 == 0:
        return 'binary', bytes(int(s[i:i+8], 2) for i in range(0, len(s), 8))
    if re.fullmatch(r'[0-9a-fA-F]+', s) and len(s) % 2 == 0:
        try: return 'hex', bytes.fromhex(s)
        except: pass
    if re.fullmatch(r'[A-Za-z0-9+/]+={0,2}', s) and len(s) % 4 == 0:
        try: return 'base64', base64.b64decode(s)
        except: pass
    if re.fullmatch(r'[A-Za-z0-9\-_]+={0,2}', s):
        try: return 'base64url', base64.urlsafe_b64decode(s + '='*(-len(s)%4))
        except: pass
    return None, None

data = open('mystery.txt','rb').read().strip()
for _ in range(10):
    name, out = try_decode(data.decode('latin1'))
    if not out: break
    print(name, '->', out[:40])
    data = out
    if b'flag{' in data: print('FOUND', data); break
```

Такой «водопад» снимает слои, пока данные не перестанут распознаваться.

## CyberChef «Magic»

CyberChef — веб-инструмент (и Python-порт `cyberchef`), где есть операция **Magic**: она перебирает сотни декодеров и показывает вероятные результаты. Для CTF это часто самый быстрый путь: вставили blob — получили флаг. Полезные операции: `From Base64`, `From Hex`, `ROT13`, `XOR`, `Gunzip`, `From Charcode`, `Magic`. В оффлайне используйте `python3 -m cyberchef` или библиотеку.

## Кодировки, которые путают

- **Base64 vs Base64url** — разница в `+`/`-` и `/`/`_`. Многие декодеры принимают обе.
- **Base32** — только заглавные и цифры `2-7`, длина кратна 8.
- **Base58** — алфавит без `0OIl+/` (используется в Bitcoin).
- **Hex vs Base16** — синонимы.
- **ROT47** — сдвиг на 47 по печатному ASCII, не путать с ROT13.
- **URL-encoding** — `%41` = `A`; часто вложен дважды (`%2541`).
- **Quoted-printable** — `=41` = `A`, используется в почте.

## Разобранный пример

Дано: `encoded.txt` содержит:

```
4e6c53635a33744e5167674e5167674e5167674e516767
```

Алфавит `0-9a-f` → hex. Декодируем:

```bash
echo 4e6c53635a33744e5167674e5167674e5167674e516767 | xxd -r -p
# NlScZ3tNQggNQggNQggNQgg
```

Получили base64-подобную строку. Декодируем base64:

```bash
echo NlScZ3tNQggNQggNQggNQgg | base64 -d
# flag{...}
```

Два слоя, оба распознаны по алфавиту.

## Частые ошибки и подводные камни

- Декодировать base64 без проверки: `base64 -d` молча возвращает мусор.
- Забывать про padding `=`: некоторые данные приходят без него — добавляйте.
- Путать base64url и обычный base64 — `/` vs `_`.
- Останавливаться на первом слое, не проверив результат на «кодируемость» снова.
- Игнорировать ROT47/ROT13: текст «почти читаем», но не совсем.
- Пытаться декодировать hex, длина которого нечётна — это признак другого формата.
- Забывать про XOR с одним байтом — очень частая «кодировка» в CTF.

## Дополнительная теория: энтропия и статистика

Полезный признак кодировки — **энтропия** и структура. Base64-текст имеет ограниченный алфавит (64 символа) и обычно длину, кратную 4. Hex — 16 символов, чётную длину. Сжатые/зашифрованные данные — почти максимальную энтропию (все 256 байт равновероятно). Энтропия помогает отличить «сжатое» от «зашифрованного» от «простого текста». В Python: `collections.Counter` по байтам, формула Шеннона.

```python
import math, collections
def entropy(b):
    c = collections.Counter(b); n = len(b)
    return -sum((v/n)*math.log2(v/n) for v in c.values())
```

Если энтропия ~8 бит/байт — это, вероятно, шифр/сжатие; ~4-5 — текст; ~6 — base64. Это быстро отсекает неправильные гипотезы. Также помогает **автокорреляция** и поиск повторяющихся блоков (признак ECB-шифрования или структурного формата).

## Кодировки vs шифрование

Важно не путать кодирование (обратимое без ключа) и шифрование (нужен ключ). Base64/hex/URL — кодирования: снимаются без секрета. ROT13/Цезарь — «шифры» без ключа (сдвиг перебирается). XOR с ключом — шифрование (ключ нужен, но при коротком ключе подбирается). В CTF цепочка часто смешивает: base64 от XOR от hex. Определить, где шифрование, помогает энтропия и наличие паттернов. Если после декодирования данные выглядят «случайными», но имеют повторяющиеся блоки — возможно, ECB XOR.

Для XOR-брута ищите известный фрагмент (`flag{`, `CTF{`, `{`): подбираете ключ, при котором фрагмент появляется.

## Разбор ошибок и отладка

Если декодирование даёт «мусор» — вернитесь на шаг назад и проверьте, действительно ли предыдущий слой был распознан верно (например, строка могла быть base64url, а вы декодировали как base64). Если `base64 -d` падает — добавьте padding или замените `-`/`_` на `+`/`/`. Если после декодирования получился бинарь — сохраните его в файл и прогоните `file`/`binwalk`. Если цепочка «не заканчивается» — возможно, есть слой, который вы не распознали (ROT47, XOR). Ведите журнал каждого слоя: имя кодировки и результат. Инструмент CyberChef Magic делает это автоматически — сверьтесь с ним.

## Практический разбор: автоматический водопад с XOR

Расширим автодекодер XOR-брутом, чтобы ловить шифрование, а не только кодирование:

```python
import base64, re

def xor_brute(b, needle=b'flag{'):
    for k in range(1, 256):
        d = bytes(x ^ k for x in b)
        if needle in d:
            return k, d
    return None, None

data = open('mystery.bin','rb').read()
# сначала пробуем XOR по одному байту
k, d = xor_brute(data)
if d:
    print('xor key', k, d)
else:
    # затем цепочку кодировок
    s = data.decode('latin1').strip()
    for _ in range(8):
        if re.fullmatch(r'[0-9a-fA-F]+', s) and len(s)%2==0:
            data = bytes.fromhex(s); s = data.decode('latin1')
        elif re.fullmatch(r'[A-Za-z0-9+/]+={0,2}', s) and len(s)%4==0:
            data = base64.b64decode(s); s = data.decode('latin1')
        else:
            break
        print(s[:60])
        if 'flag{' in s: print('FOUND', s); break
```

Если XOR с одним байтом не срабатывает — попробуйте многочленный ключ (например, длиной 4-16 байт) через определение длины ключа (индекс совпадений) и брут по фрагменту. Если данные «случайны», но имеют повторяющиеся блоки — возможно, XOR с повторяющимся ключом; ищите период. Комбинируйте с CyberChef Magic для сверки. Ведите журнал слоёв и всегда проверяйте результат на наличие `flag{`.
