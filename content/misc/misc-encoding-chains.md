## Вопрос, с которого всё начинается

В `misc-encoding` мы сняли два слоя Base64 руками. Но в реальных задачах данные почти никогда не закодированы **одним** способом: классика — цепочка «base64 от hex от ROT13 от бинарного представления». Задача — распознать каждый слой и снять их по порядку, не запутавшись.

Опытный игрок определяет кодировку **по алфавиту** и длине, а рутину отдаёт автоматике. Разберём это на конкретной строке.

## Наш пример: encoded.txt

```
5a6d78685a33746f5a5868666447686c626c39694e6a5239
```

Смотрим на множество символов:

```python
data = open('encoded.txt').read().strip()
print(sorted(set(data)))
```

```
['0','3','4','5','6','7','8','9','a','d','e','f','h','i','l','m','n','o','r','s','t','x','z']
```

Только `0-9` и `a-f`, длина 52 — чётная. Это **Hex** (шестнадцатеричное представление). Декодируем:

```bash
$ echo 5a6d78685a33746f5a5868666447686c626c39694e6a5239 | xxd -r -p
ZmxhZ3toZXhfdGhlbl9iNjR9
```

Получилась строка из букв и цифр с `=` на конце — уже знакомый признак **Base64**. Декодируем второй слой:

```bash
$ echo ZmxhZ3toZXhfdGhlbl9iNjR9 | base64 -d
flag{hex_then_b64}
```

Флаг. Два слоя, оба распознаны по алфавиту — без всякой магии.

## Шаг 1: таблица распознавания по алфавиту

Главный навык — быстро отнести строку к классу:

| Кодировка | Признак |
|-----------|---------|
| Base64 | `A–Z a–z 0–9 + / =`, длина кратна 4 |
| Base64url | `A–Z a–z 0–9 - _`, без `+/` |
| Base32 | `A–Z 2–7 =`, длина кратна 8 |
| Hex | только `0–9 a–f`, чётная длина |
| Binary | только `0` и `1`, длина кратна 8 |
| Morse | `.` `-` и пробелы |
| URL | `%XX` |
| ROT13/Цезарь | буквы, читаемый паттерн после сдвига |

Base64 выдаёт «хвост» из `=` (padding) и смесь регистров. Hex — только `0-9a-f`, всегда чётной длины. Binary — только нули и единицы, длина кратна 8.

## Шаг 2: пишем «водопад» декодеров

Когда слоёв больше двух, руками долго. Пишем функцию, которая **угадывает** кодировку по алфавиту и снимает слой, пока данные распознаются:

```python
import base64, binascii, re

def try_decode(s):
    s = s.strip()
    if re.fullmatch(r'[01]{8,}', s) and len(s) % 8 == 0:
        return 'binary', bytes(int(s[i:i+8], 2) for i in range(0, len(s), 8))
    if re.fullmatch(r'[0-9a-fA-F]+', s) and len(s) % 2 == 0:
        try: return 'hex', bytes.fromhex(s)
        except: pass
    if re.fullmatch(r'[A-Za-z0-9+/]+={0,2}', s) and len(s) % 4 == 0:
        try: return 'base64', base64.b64decode(s)
        except: pass
    return None, None

data = open('encoded.txt','rb').read().strip()
for _ in range(10):
    name, out = try_decode(data.decode('latin1'))
    if not out: break
    print(name, '->', out[:40])
    data = out
    if b'flag{' in data:
        print('FOUND', data); break
```

Такой цикл снимает слои, пока данные не перестанут распознаваться. Обратите внимание на `re.fullmatch` — он проверяет, что **вся** строка состоит из нужного алфавита, а не содержит его как часть.

## Шаг 3: CyberChef и кнопка Magic

Есть веб-инструмент CyberChef, где собраны сотни операций (`From Base64`, `From Hex`, `ROT13`, `XOR`, `Gunzip`). Вставляете blob, накидываете операции мышью — видите результат на каждом шаге.

Отдельно есть операция **Magic**: она перебирает комбинации декодеров и показывает наиболее вероятные результаты. Для CTF это часто самый быстрый путь: вставили строку — получили флаг. В оффлайне доступен порт `python3 -m cyberchef`.

## Шаг 4: кодировки, которые путают

- **Base64 vs Base64url** — разница в `+`/`-` и `/`/`_`. Base64url применяют в URL.
- **Base32** — только заглавные и цифры `2-7`, длина кратна 8.
- **Base58** — алфавит без `0OIl+/` (Bitcoin).
- **ROT47** — сдвиг на 47 по печатному ASCII, не путать с ROT13.
- **URL-encoding** — `%41` = `A`; бывает вложен дважды (`%2541`).

## Шаг 5: энтропия — отсечь неверные гипотезы

Полезный признак — **энтропия** (мера хаотичности данных). Считается по частотам байтов:

```python
import math, collections
def entropy(b):
    c = collections.Counter(b); n = len(b)
    return -sum((v/n)*math.log2(v/n) for v in c.values())
```

Ориентиры: около 8 бит/байт — шифр или сжатие; 4–5 — обычный текст; ~6 — base64. Это быстро отсекает неправильные гипотезы: если после «декодирования» энтропия осталась максимальной, вы, скорее всего, ничего не сняли.

## Шаг 6: добавляем XOR в водопад

Очень часто первый «слой» — не кодировка, а **XOR с одним байтом**. Встраиваем его в тот же водопад: перебираем 256 ключей и ищем известный фрагмент (`flag{`).

```python
def xor_brute(b, needle=b'flag{'):
    for k in range(1, 256):
        d = bytes(x ^ k for x in b)
        if needle in d:
            return k, d
    return None, None
```

Если один байт не подходит — попробуйте повторяющийся ключ (определите длину по индексу совпадений и брутуйте по фрагменту). Так цепочка «XOR → base64 → hex» снимается автоматически.

## Шаг 7: отладка — что делать, когда «мусор»

Если декодирование даёт бессмыслицу, не перебирайте вслепую — вернитесь на шаг назад:

- **Проверьте предыдущий слой.** Строка могла быть base64url, а вы декодировали как base64 — замените `-`/`_` на `+`/`/`.
- **`base64 -d` падает** — добавьте padding `=` или исправьте алфавит.
- **Получился бинарь** — сохраните в файл и прогоните `file`/`binwalk`.
- **Цепочка «не заканчивается»** — вероятно, есть нераспознанный слой (ROT47, XOR).
- **Ведите журнал** каждого слоя: имя кодировки и результат. CyberChef Magic делает это автоматически — сверьтесь с ним.

Держите под рукой готовые рецепты для «сложных» слоёв:

```bash
# ROT47 — сдвиг по печатному ASCII
tr '!-~' 'P-~!-O'
# URL-декодирование (в т.ч. двойное)
python3 -c "import urllib.parse,sys;print(urllib.parse.unquote(sys.stdin.read()))"
```

## Что мы теперь знаем

- Распознаём кодировку по **алфавиту** и длине: hex — `0-9a-f` чётной длины, base64 — `A-Za-z0-9+/=`.
- Цепочки снимаются слой за слоем; каждый следующий инструмент подбирается по результату.
- «Водопад» на Python снимает слои автоматически, пока данные распознаются.
- CyberChef (операция Magic) перебирает декодеры и часто сразу даёт флаг.
- `base64 -d` молча отдаёт мусор, если вход не base64, — результат надо проверять.

## На что смотреть дальше

- **Декодировать base64 без проверки** — результат смотрите глазами или через `file`.
- **Забыть про padding `=`** — если его нет, добавьте или замените `-`/`_`.
- **Путать base64url и base64** — `/` против `_`.
- **Остановиться на первом слое** — проверьте, распознаётся ли результат снова.
- **Нечётная длина hex** — это признак другого формата, а не hex.
- **XOR как «кодировка»** — очень частый первый слой; добавьте в водопад перебор 256 ключей.
