## Вопрос, с которого всё начинается

Задача даёт файл `prog.ws`. Открываешь — он **пустой**. `cat` не показывает ничего. Но условие настойчиво говорит, что внутри программа, которая печатает флаг. Где она прячется?

## Наш пример: пустой prog.ws

Смотрим размер — файл явно не ноль байт:

```
$ wc -c prog.ws
212 prog.ws
```

212 байт, но глазами пусто. Значит, содержимое — **невидимые символы**. Проверяем их через `xxd`:

```
$ xxd -g1 prog.ws | head -3
00000000: 2020 2009 2020 0920 2020 0a20 2009 2009   ..   .    .  ..
00000010: 2020 0a20 2009 2009 2009 2009 0a20 2009     .  . . . . .
```

Видим только три вида байтов: `20` (пробел), `09` (таб), `0a` (перевод строки). Это сигнатура **Whitespace** — эзотерического языка, придуманного Эдвином Брэди и Крисом Моррисом в 2003 году. Его идея: значимы ровно три символа, всё остальное интерпретатор игнорирует.

## Шаг 1: мнемоника S, T, L

Инструкции в Whitespace кодируются не отдельными символами, а их **последовательностями**. Чтобы читать код, вводят мнемонику:

- `S` = пробел (`0x20`),
- `T` = таб (`0x09`),
- `L` = перевод строки (`0x0A`).

Тогда `SS` — «положить число на стек», а `TLSS` — «вывести символ». Превратить невидимое в читаемое можно одной командой:

```
$ tr ' \t\n' 'STL' < prog.ws | head -c 80; echo
SSSTSSTSSSLTLSS...
```

Теперь видим поток `S`/`T`/`L` — с ним уже можно сверяться с таблицей команд.

## Шаг 2: это стек-машина

Whitespace — **стековая машина**. У неё три региона:

- **стек** — основной: числа кладутся и снимаются сверху;
- **куча (heap)** — ассоциативный массив «адрес → значение» для долговременного хранения;
- **метки и переходы** — для циклов и подпрограмм.

Числа — знаковые целые произвольной длины. Кодируются они так: **знак** (`S` = «+», `T` = «−»), затем двоичные цифры (`S` = 0, `T` = 1), затем завершающий `L`.

Вот минимальный набор команд, который нам нужен:

| Мнемоника | Инструкция | Действие |
|-----------|------------|----------|
| `SS` | push | положить число на стек |
| `SLS` | dup | продублировать вершину |
| `SLT` | swap | поменять две верхние |
| `STS` | copy n | скопировать n-й элемент наверх |
| `TSSS` | add | сложение |
| `TSST` | sub | вычитание |
| `TTS` | store | heap[addr] = value |
| `TTT` | retrieve | положить heap[addr] |
| `LSS` | label | метка |
| `LSL` | jump | безусловный переход |
| `LTS` | jz | переход, если 0 |
| `LTT` | jn | переход, если < 0 |
| `LLL` | end | конец программы |
| `TLSS` | out char | вывести символ |
| `TLST` | out num | вывести число |
| `TLTS` | read char | прочитать символ |

Этого хватает, чтобы понимать почти любую программу в задаче.

## Шаг 3: собираем «H» вручную

Чтобы прочувствовать кодирование, напишем программу, которая печатает одну букву `H` (код 72).

1. 72 в двоичном виде — `1001000`.
2. `push 72` = `SS` (push) + знак `S` (+) + биты `T S S T S S S` + `L` = `SSSTSSTSSSL`.
3. `out char` = `TLSS`.
4. `end` = `LLL`.

Склеиваем: `SSSTSSTSSSLTLSSLLL`. Переводим в байты и запускаем интерпретатором `wspace`:

```
$ printf '\x20\x20\x20\x09\x20\x20\x09\x20\x20\x20\x0a\x09\x0a\x20\x20\x0a\x0a\x0a' > h.ws
$ wspace h.ws
H
```

Вывелась ровно `H` — значит, мы верно закодировали знак, биты и завершающий `L`. Та же логика, но с десятками символов, даёт флаг в реальной задаче.

## Шаг 4: запускаем нашу задачу

Возвращаемся к `prog.ws` и подаём его интерпретатору:

```
$ wspace prog.ws
flag{whitespace_is_invisible}
```

Если `wspace` не установлен (`gem install wspace`), работает браузерный интерпретатор `vii5ard.github.io/whitespace` — он визуализирует стек. Но помните: онлайн-сервису не стоит отдавать настоящий флаг, только учебные примеры.

Если программа «висит» — она ждёт ввод (`TLTS`, read char). Подаём данные:

```
$ printf 'answer' | wspace prog.ws
```

## Шаг 5: Whitespace как стеганография

Самое интересное применение — **спрятать программу внутрь обычного файла**. Все буквы и цифры для интерпретатора Whitespace — просто комментарии. Поэтому программу можно вклеить в `main.c`, который нормально компилируется, или в текст задачи.

Как обнаружить:

```
$ grep -c $'\t' main.c
47
$ cat -A main.c | head -5
```

Если в «обычном» исходнике аномально много табов и переводов строк в неожиданных местах — проверьте его интерпретатором Whitespace. Обратный случай тоже частый: файл выглядит пустым, а внутри сотни пробелов, которые и есть код.

## Шаг 6: если не сработало

- **Программа «мертва», ничего не печатает.** Почти всегда файл испорчен при копировании: табы превратились в пробелы, а пробелы в конце строк обрезаны. Скачайте файл заново и проверьте `xxd`: значимые байты должны быть ровно `20`, `09`, `0a`.
- **Интерпретатор ругается на неизвестную команду.** Проверьте мнемонику: возможно, вы перепутали `S` и `T`. Прогоните `tr ' \t\n' 'STL'` и сверьтесь с таблицей.
- **Вывод — числа, а не текст.** Программа использует `TLST` (out num). Соберите байты: `wspace prog.ws | python3 -c "import sys;print(bytes(int(x) for x in sys.stdin.read().split()))"`.
- **Нет `wspace`.** Есть браузерный интерпретатор и интерпретаторы на других языках; для учебных задач годится любой. Настоящий флаг в онлайн не отправляйте.
- **Нужен ввод.** Если программа стоит и ждёт, подайте данные через pipe.

Если интерпретатора нет совсем, можно написать свой: парсер разбивает поток на группы по префиксам (`SS`, `SLS`, `TSSS`, `TLSS`…), затем исполняет стек-машину. Объём — порядка 150–250 строк, и это отличная практика понимания байткода.

## На что смотреть дальше

- **Не копируйте текст через браузер.** Редакторы и формы заменяют табы на пробелы — программа ломается. Скачивайте файл целиком.
- **Trailing whitespace значим.** Пробелы в конце строк многие редакторы обрезают; после этого программа «умирает».
- **Не путайте `S` и `T`.** Пробел — `S`, таб — `T`. Обратная мнемоника из чужого разбора собьёт с толку.
- **`out num` против `out char`.** Для текста нужен `TLSS`; `TLST` печатает число.
- **Проверьте знак числа.** Число начинается со знака; пропустите его — и значение уедет.

## Куда дальше

Мы научились видеть невидимый код. В следующем уроке возьмём `hello.i` — файл, который, наоборот, состоит из слов, но ведёт себя странно: каждая строка начинается с `DO` или `PLEASE DO`, а компилятор ругается на «недостаточную вежливость». Это INTERCAL. А пока главное запомни: если файл пуст, а размер не ноль — смотрите байты, а не символы.
