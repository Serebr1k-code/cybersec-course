## Введение

Задача просит набрать сумму минимальным числом монет. Ты честно пишешь рекурсию: «для суммы `x` попробуй каждую монету и возьми минимум». Она работает на маленьких числах и намертво виснет на больших — потому что одни и те же подсуммы считаются миллионы раз. Спасает **динамическое программирование** (DP): мы считаем каждую подзадачу один раз и запоминаем результат.

В этом уроке мы решим задачу о монетах и увидим, почему DP превращает невозможное в мгновенное.

## Наш пример: минимум монет

Дано: монеты номиналом `[1, 3, 4]`, нужно набрать сумму `6`. Спрашивается: каким минимальным числом монет это можно сделать?

## Шаг 1: наивная рекурсия и почему она медленная

Наивное решение перебирает все варианты:

```python
def min_coins_naive(coins, amount):
    if amount == 0:
        return 0
    return 1 + min(min_coins_naive(coins, amount - c)
                   for c in coins if c <= amount)
```

Для суммы 6 это сработает, но для суммы 50 число вызовов растёт экспоненциально: подсумма 45 вычисляется снова и снова из разных ветвей. Здесь и появляется признак DP — **перекрывающиеся подзадачи**: одни и те же состояния считаются многократно.

## Шаг 2: мемоизация — сверху вниз

Самый быстрый способ это исправить — запомнить результат для каждой суммы. В Python это делает декоратор `lru_cache`:

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def min_coins(coins, amount):
    if amount == 0:
        return 0
    return 1 + min(min_coins(coins, amount - c)
                   for c in coins if c <= amount)
```

Теперь каждая сумма считается ровно один раз, и вместо экспоненты получается линейное время. Мемоизация («сверху вниз») — лучший способ быстро написать прототип.

## Шаг 3: табуляция — снизу вверх

Продакшн-вариант — **табуляция**: заполняем массив от меньших сумм к большим, без рекурсии. `dp[x]` — минимальное число монет для суммы `x`; `dp[0] = 0`, остальные — «бесконечность»:

```python
def min_coins(coins, amount):
    INF = float('inf')
    dp = [0] + [INF] * amount
    for x in range(1, amount + 1):
        for c in coins:
            if c <= x and dp[x - c] + 1 < dp[x]:
                dp[x] = dp[x - c] + 1
    return dp[amount]

print(min_coins([1, 3, 4], 6))
```

```
2
```

Ответ `2` — это `3 + 3`. Табуляция не тратит стек на рекурсию и часто экономит память (можно хранить только нужные «слои»). Общая схема: `dp[x] = min(dp[x], dp[x-c] + 1)` для каждой монеты.

## Шаг 4: задача о рюкзаке

Классика оптимизации: есть предметы с весом и ценностью, рюкзак ограничен по весу — как набрать максимальную ценность? Жадность («бери самое ценное на единицу веса») здесь **не работает**, поэтому нужен DP. `dp[cap]` — лучшая ценность для вместимости `cap`:

```python
def knapsack(items, W):
    dp = [0] * (W + 1)
    for w, v in items:
        for cap in range(W, w - 1, -1):     # обратный проход!
            dp[cap] = max(dp[cap], dp[cap - w] + v)
    return dp[W]

print(knapsack([(2, 3), (3, 4), (4, 5), (5, 6)], 5))
```

```
7
```

Ключевая тонкость — **обратный** проход по вместимости. Если идти вперёд, предмет может быть «взят» дважды (используется уже обновлённое состояние). Обратный проход гарантирует, что каждый предмет берётся не более раза.

## Шаг 5: как распознать DP

Признаки задачи, которая решается DP:

- нужен **оптимум** (минимум/максимум) или **число способов**;
- решение строится из решений меньших подзадач;
- подзадачи **перекрываются** (считаются многократно);
- жадный выбор не даёт оптимума.

Порядок работы: определить **состояние** (что описывает подзадачу — индекс, остаток, маска), **переход** (как из меньших состояний получить большее), **базу** (начальные значения) и выбрать порядок (мемоизация или табуляция).

Проверка «жадность или DP» проста: попробуй найти контрпример к жадному алгоритму на маленьких данных. Жадность работает, когда можно доказать, что локально лучший выбор не мешает глобальному (например, дробный рюкзак, выбор интервалов по раннему окончанию). Если контрпример находится — нужен DP.

## Шаг 6: родственные задачи

Тот же приём решает целое семейство задач:

- **Фибоначчи.** Мемоизация превращает экспоненту в линейное время: `fib(200)` считается мгновенно и даёт 42-значное число.
- **LCS** (наибольшая общая подпоследовательность) — сравнение строк, `dp[i][j]` по двум индексам.
- **Редакционное расстояние** (Левенштейн) — «похожесть» строк, минимум вставок/удалений/замен.
- **Подсчёт путей в сетке** — `dp[i][j] = dp[i-1][j] + dp[i][j-1]`.
- **DP по подмножествам** (битовая маска) — коммивояжёр, назначения; применимо только для малых `n` (до ~20), потому что сложность `O(2^n)`.

Разберём LCS подробнее — это двумерная таблица `dp[i][j]`, где хранится длина наибольшей общей подпоследовательности первых `i` символов первой строки и первых `j` символов второй:

```python
def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i-1] == b[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1        # символы совпали
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[-1][-1]
```

Если символы совпали — берём «диагональ плюс один»; иначе — максимум из двух соседей. Редакционное расстояние (Левенштейн) устроено так же, только вместо «плюс один» — стоимость операции (вставка/удаление/замена), и берётся минимум. Оно встречается в задачах на «похожесть строк» и в подсказках про опечатки.

Когда таблица большая, а нужен только ответ (не сам путь), память экономят: переход зависит лишь от предыдущей строки таблицы, поэтому достаточно хранить два ряда вместо всей матрицы. А если нужен и сам путь — хранят «родителя» каждого состояния или восстанавливают ответ обратным проходом по таблице.

## Что мы теперь знаем

1. DP = подзадачи считаются один раз и запоминаются.
2. Мемоизация (`lru_cache`) — сверху вниз; табуляция — снизу вверх.
3. Размен монет: `dp[x] = min(dp[x], dp[x-c] + 1)`.
4. 0/1 рюкзак требует **обратного** прохода по вместимости.
5. Признак DP: оптимум или число способов + перекрывающиеся подзадачи.
6. Схема: состояние → переход → база → порядок.

## На что смотреть дальше

- **Неправильный порядок циклов в рюкзаке.** Предмет возьмётся дважды.
- **Забыть базу.** Неверный ответ на краях (`dp[0] = 0`).
- **Слишком большой массив табуляции.** Оптимизируй память — храни один слой.
- **Путать «число способов» и «минимум».** Это разные переходы.
- **Рекурсия без `lru_cache`.** Получишь экспоненту и «висяк».
