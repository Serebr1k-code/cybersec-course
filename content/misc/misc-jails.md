## Что такое джейл (jail)

Джейл — это «тюрьма»: программа, которая даёт вам ограниченный интерфейс и не выпускает наружу. В CTF джейлы бывают на разных языках: Python, bash, Lua, JavaScript, Ruby. Вам нужно «убежать» — выполнить код или прочитать файл, которые джейл запрещает. В отличие от полноценной песочницы, джейл обычно реализован на уровне самого скрипта: чёрный список функций, ограниченный набор команд или отфильтрованный ввод. Именно поэтому побег — это игра в кошки-мышки с фильтром.

Цель модуля — дать системный метод: как понять, что фильтруется, найти незаблокированный путь и построить payload.

## Как анализировать джейл

Первое — прочитать исходник джейла (в CTF он обычно дан). Ищите:

1. что именно блокируется (какие слова/символы/функции);
2. как строится ввод (eval? exec? subprocess?);
3. есть ли ограничение по длине;
4. что доступно «из коробки».

Составьте таблицу «запрещено / разрешено». Побег почти всегда идёт через то, что «разрешено», но имеет доступ к «запрещённому».

## Python-джейлы

Типовой джейл:

```python
blacklist = ['import', 'os', 'subprocess', 'open', 'eval', 'exec', 'system']
code = input()
for b in blacklist:
    assert b not in code
eval(code)
```

Побег: доступ к builtins через объектную модель, обход подстрок.

```python
().__class__.__base__.__subclasses__()
```

Обход `import` через `__import__` (его нет в списке!):

```python
__import__('os').system('cat /flag')
```

Если и `system` запрещён — используйте `os.popen`, `subprocess.check_output` или чтение файла:

```python
open('/flag').read()
```

Если `open` запрещён — через `__builtins__`:

```python
__builtins__['op'+'en']('/flag').read()
```

## Bash-джейлы

В bash-джейле обычно ограничивают доступные команды и символы. Классические приёмы:

- **Обход через globbing**: вместо `cat /flag` — `cat /fla?` или `/???/??t /flag`.
- **Переменные**: `a=cat; $a /flag`.
- **Подстановка команд**: `$(cat /flag)`.
- **`${IFS}`** вместо пробела: `cat${IFS}/flag`.
- **Обратные слэши**: `c\at /fl\ag`.

Пример с wildcard:

```bash
/???/??t /????        # /bin/cat /flag (если flag — четыре буквы)
```

## Lua-джейлы

Lua-песочницы часто строятся через удаление `os`/`io` и запрет `loadstring`. Побег — через `debug` библиотеку или метатаблицы:

```lua
debug.getregistry()
debug.getinfo(1)
```

Если `debug` доступен, можно добраться до функций, которые песочница считала спрятанными. Также работает `getfenv`/`setfenv` (Lua 5.1) для смены окружения.

## JavaScript-джейлы

В Node.js-джейлах побег идёт через `constructor` и `process`:

```javascript
this.constructor.constructor('return process.mainModule.require("child_process").execSync("cat /flag")')()
```

Если `process` заблокирован, ищите альтернативы: `require` через `module`, доступ к `global`, `Buffer`, `fs` через другие модули.

## Стратегия побега: пошаговый метод

1. **Составьте список запретов.** Прочитайте исходник, проверьте, что реально фильтруется.
2. **Найдите «дыру».** Ищите доступ к builtins/нативному слою через рефлексию.
3. **Обойдите текстовый фильтр.** Конкатенация, getattr, кодировки, hex, base64.
4. **Достигните выполнения.** `os.system`, `subprocess`, `open`, `exec`.
5. **Проверьте локально.** Запустите джейл у себя, отладьте payload.
6. **Уложитесь в лимиты.** Если есть ограничение длины — сжимайте.

## Инструменты

- **`python -c`**, **`node -e`**, **`lua -e`** — локальная проверка.
- **`strace`** — увидеть, что реально вызывается.
- **Списки обходов pyjail** — держите под рукой чек-лист типовых payload'ов.
- **`ascii2hex`/`xxd`** — готовить hex/base64 payload'ы.

## Типичные ошибки и подводные камни

- **Фильтр по подстрокам** — обходится конкатенацией/кодировкой.
- **Забыть про альтернативные функции** — `popen`, `spawn`, `ctypes`.
- **Не проверить версию языка** — `getfenv` есть в Lua 5.1, нет в 5.2+.
- **Игнорировать вывод ошибок** — traceback подсказывает.
- **Пробелы/спецсимволы** — заменяйте на `${IFS}`, `$'...'`.
- **Слишком длинный payload** — сжимайте или используйте переменные.
- **Полагать, что «всё закрыто»** — почти всегда есть забытый путь.

## Что дальше / решение

План: всегда читайте исходник джейла и составьте список запретов; ищите путь через рефлексию к builtins/нативному слою; обходите текстовые фильтры конкатенацией, getattr, кодировками; проверяйте payload локально и читайте traceback. Держите под рукой чек-листы по каждому языку. Помните: джейл ломается там, где разработчик забыл закрыть путь, — ваша задача найти этот забытый угол.

## Практический пример: обход Python-джейла с фильтром

Разберём задачу. Джейл читает строку, проверяет отсутствие подстрок `os`, `import`, `system`, `subprocess`, `eval`, `exec`, затем делает `eval`. Пошагово. Проверяем доступ к объектной модели: `().__class__.__base__.__subclasses__()`. Ищем `subprocess.Popen` в списке классов. Если есть — вызываем: `[c for c in ().__class__.__base__.__subclasses__() if c.__name__=='Popen'][0]('cat /flag', shell=True)`. Подстрока `subprocess` не встречается в этом payload, поэтому фильтр пропускает. Если `Popen` нет — идём через `warnings.catch_warnings` и `__globals__`. Если `__globals__` заблокирован — собираем имя: `getattr(f, '__glo'+'bals__')`. Если и это нельзя — используем `().__class__.__mro__[1].__subclasses__()` и `__init__.__globals__`.

Каждый шаг — это обход конкретного запрета. Смысл в том, что запрещать нужно *все* пути, а их десятки; разработчик обычно закрывает два-три очевидных.

## Как строить payload системно

Составьте дерево: цель (выполнить команду) → примитивы (получить `os.system`/`subprocess`/`open`) → доступ (builtins через `__globals__`, нативно через `ctypes`) → обход фильтра (конкатенация, `chr`, `getattr`, hex). Затем идите от цели вниз, подбирая для каждого уровня незаблокированный вариант. Если уровень закрыт — переходите к альтернативе, а не сдаётесь.

## Частые вопросы

«Что делать при ограничении длины?» — используйте hex/base64 и `exec`, упаковывайте payload. «А если `eval` заменён на `exec`?» — `exec` принимает операторы, что даже удобнее. «Что если запрещены все опасные имена, но есть `open`?» — читайте файл напрямую. «А если вывод не возвращается?» — прячьте данные в исключении (`raise Exception(data)`).

## Что дальше / решение

Итог: для Python-джейлов используйте цепочку рефлексии (`__subclasses__` → `__globals__` → `__builtins__`), обходите фильтры конкатенацией/`getattr`/кодировками, ищите альтернативные примитивы (`open`, `popen`, `ctypes`). Стройте дерево «цель → примитив → доступ → обход» и перебирайте незаблокированные ветви. Проверяйте локально, читайте traceback. Джейл ломается там, где остался хотя бы один незакрытый путь.

## Частые вопросы по джейлам

«Джейл запрещает всё, что я знаю — тупик?» — нет, начните с чтения исходника и составьте список того, что реально доступно. «Что делать с ограничением длины?» — используйте hex/base64 и `exec`. «Как понять, что фильтруется?» — пробуйте по одному символу и смотрите на реакцию. «А если вывод не возвращается?» — прячьте данные в исключении. «Помогает ли traceback?» — да, он раскрывает доступные имена и пути. Помните: джейл — это фильтр, а фильтр почти всегда обходится конкатенацией, `getattr` и кодировками.

## Расширенный чек-лист по джейлам

Прочитайте исходник джейла и выпишите список запретов. Затем проверьте каждый примитив: `open`, `eval`, `exec`, `__import__`, `subprocess`, `os`, `ctypes`. Для обхода строковых фильтров используйте конкатенацию, `getattr`, `chr`. Проверяйте payload локально, читайте traceback, следите за ограничением длины. Помните: джейл ломается там, где разработчик забыл закрыть путь, — ваша задача найти этот угол. Держите список из десяти классических payload'ов и пробуйте их по очереди.
