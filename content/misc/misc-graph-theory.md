## Введение

Задача даёт карту лабиринта: решётку из символов, где `#` — стена, `.` — проход, `S` — старт, `E` — выход. Нужно найти путь и превратить последовательность шагов в строку — часто это и есть флаг. Перебирать пути вручную бессмысленно: лабиринт может быть сто на сто клеток.

Такие задачи — про **графы**. Граф — это набор «точек» (вершин) и «связей» между ними (рёбер). Лабиринт — частный случай: каждая проходимая клетка — вершина, а соседние клетки соединены ребром. В этом уроке мы решим лабиринт алгоритмом **BFS**.

## Наш пример: лабиринт

Вот наш лабиринт:

```
#########
#S..#...#
#.#.#.#.#
#.#...#.#
#.#####.#
#.......E
#########
```

Нужно найти кратчайший путь от `S` до `E` и записать его как строку из шагов: `U` (вверх), `D` (вниз), `L` (влево), `R` (вправо).

## Шаг 1: как представить граф

Первое, что нужно, — превратить сетку в граф. Простейший способ — **список смежности**: для каждой вершины хранить список соседей. Но для сетки удобнее не строить его явно, а вычислять соседей на ходу: у клетки `(r, c)` их максимум четыре — вверх, вниз, влево, вправо. Сосед годится, если он внутри сетки и не стена.

```python
def neighbors(grid, r, c):
    for dr, dc in ((1,0), (-1,0), (0,1), (0,-1)):
        nr, nc = r + dr, c + dc
        if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]) and grid[nr][nc] != '#':
            yield nr, nc
```

Это ленивый генератор: он выдаёт соседей по одному, не строя весь граф в памяти. Для больших лабиринтов это важно.

## Шаг 2: BFS — кратчайший путь без весов

Для поиска пути в невзвешенном графе (все шаги «стоят» одинаково) работает **обход в ширину**, или BFS (breadth-first search). Идея: исследуем вершины «слоями» — сначала все на расстоянии 1 от старта, потом на расстоянии 2, и так далее. Тогда первое достижение цели даёт **кратчайший** путь.

BFS использует **очередь** (первым пришёл — первым ушёл): кладём старт, достаём его, добавляем соседей, и так по кругу. Чтобы восстановить путь, храним для каждой вершины её **предшественника** — откуда мы в неё пришли:

```python
from collections import deque
grid = open('maze.txt').read().splitlines()
R, C = len(grid), len(grid[0])
start = next((r, c) for r in range(R) for c in range(C) if grid[r][c] == 'S')
goal  = next((r, c) for r in range(R) for c in range(C) if grid[r][c] == 'E')

q = deque([start])
prev = {start: None}
while q:
    u = q.popleft()
    if u == goal:
        break
    for v in neighbors(grid, *u):
        if v not in prev:
            prev[v] = u
            q.append(v)
```

Здесь `prev` одновременно служит «множеством посещённых»: если вершина уже в `prev`, мы её не добавляем повторно. Это защищает от бесконечного цикла.

## Шаг 3: восстанавливаем путь и превращаем в шаги

Когда цель достигнута, идём по предшественникам назад — от цели к старту — и переворачиваем:

```python
path, n = [], goal
while n is not None:
    path.append(n)
    n = prev[n]
path.reverse()
```

Осталось превратить последовательность клеток в строку шагов. Для каждой пары соседних клеток вычисляем разницу координат и сопоставляем ей букву:

```python
step = {(1,0):'D', (-1,0):'U', (0,1):'R', (0,-1):'L'}
moves = "".join(step[(b[0]-a[0], b[1]-a[1])] for a, b in zip(path, path[1:]))
print(len(path), moves)
```

```
12 DDDDRRRRRRR
```

Путь длиной 12 клеток, шаги — `DDDDRRRRRRR`. Если задача кодирует флаг этими шагами, осталось подставить их в нужный алфавит. Обрати внимание: BFS нашёл именно кратчайший путь — DFS (обход в глубину) мог бы найти более длинный и дать неверный флаг.

## Шаг 4: когда у шагов разная цена — Дейкстра

Если клетки имеют разную «стоимость» (например, песок дороже травы), BFS не подходит: он минимизирует **число** шагов, а не сумму цен. Тогда применяют алгоритм **Дейкстры**, который всегда расширяет вершину с наименьшей накопленной стоимостью, используя очередь с приоритетом:

```python
import heapq
def dijkstra(graph, start):
    dist = {start: 0}
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float('inf')):
            continue                      # устаревшая запись
        for v, w in graph[u]:             # graph[u] = [(v, вес), ...]
            nd = d + w
            if nd < dist.get(v, float('inf')):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist
```

Дейкстра требует **неотрицательных** весов. Если рёбра могут быть отрицательными, нужен алгоритм Беллмана-Форда.

## Шаг 5: обход, связность и порядок

Кроме путей, графы решают ещё три типовые задачи:

- **Связность.** Сколько отдельных «островов» в графе — обходом в глубину (DFS) или BFS из каждой непосещённой вершины.
- **Топологическая сортировка.** Упорядочить задачи так, чтобы зависимости шли раньше зависимых (порядок сборки пакетов). Если порядок не строится — в графе цикл.
- **Граф из «нестандартного» источника.** В CTF графы часто спрятаны: строки `A->B` — это рёбра, буквы шифротекста с переходами — граф де Брёйна, пиксели с похожими цветами — вершины.

Для готовых алгоритмов не пиши велосипед — есть библиотека **networkx**:

```python
import networkx as nx
G = nx.Graph()
G.add_weighted_edges_from([('A', 'B', 1), ('B', 'C', 2)])
print(nx.shortest_path(G, 'A', 'C', weight='weight'))   # ['A', 'B', 'C']
print(nx.dijkstra_path_length(G, 'A', 'C'))             # 3
```

## Что мы теперь знаем

1. Лабиринт — это граф: клетки — вершины, соседство — рёбра.
2. BFS даёт кратчайший путь в невзвешенном графе; храним предшественников для восстановления пути.
3. `prev` служит и «множеством посещённых» — защита от циклов.
4. Дейкстра — для путей с весами (неотрицательными); Беллман-Форд — для отрицательных.
5. DFS — связность и обход; топосорт — порядок зависимостей.
6. `networkx` даёт готовые алгоритмы — не изобретай их заново.

## На что смотреть дальше

- **DFS для кратчайшего пути.** DFS не гарантирует минимум по числу рёбер.
- **Забыть пометить узел посещённым.** Получишь бесконечный цикл.
- **Хранить весь путь в очереди BFS.** На большом графе это съедает память — храни предшественников.
- **Путать вес ребра и число шагов.** Если рёбра взвешены — нужна Дейкстра.
- **Устаревшие записи в куче Дейкстры.** Проверяй `if d > dist[u]: continue`.
- **Рекурсивный DFS на большом графе.** Переполнит стек — делай итеративную версию.

## Топологическая сортировка: порядок из зависимостей

Многие CTF-задачи прячут **DAG** (ориентированный ациклический граф): пакеты с зависимостями, шаги сборки, цепочки доверия, «A должен идти раньше B». Вопрос «в каком порядке выполнять» — это топологическая сортировка. Алгоритм **Кана** прост и понятен: находим вершины без входящих рёбер, забираем их в результат, удаляем их рёбра и повторяем.

```python
from collections import deque
def topo(nodes, edges):                 # edges: список (u -> v)
    indeg = {n: 0 for n in nodes}
    adj = {n: [] for n in nodes}
    for u, v in edges:
        adj[u].append(v); indeg[v] += 1
    q = deque([n for n in nodes if indeg[n] == 0])
    order = []
    while q:
        u = q.popleft(); order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == len(nodes) else None   # None => цикл
```

Если результат короче числа вершин — в графе есть **цикл**, и порядок невозможен. В CTF это часто и есть ответ: «зависимости противоречивы», значит, где-то подвох. Топологическая сортировка не единственна — валидных порядков может быть много, и иногда задача просит лексикографически наименьший: тогда очередь заменяют на кучу.

## Минимальное остовное дерево: Краскал и Прим

Задача «соединить все точки минимальной суммарной длиной» — это **MST** (minimum spanning tree). Классика CTF: точки на карте, между ними расстояния, надо проложить сеть дешевле всего. Алгоритм **Краскала** сортирует рёбра по весу и добавляет те, что не создают цикл, — для проверки цикла служит система непересекающихся множеств (**union-find**).

```python
def find(p, x):
    while p[x] != x:
        p[x] = p[p[x]]; x = p[x]
    return x

def kruskal(n, edges):                  # edges: (w, u, v)
    p = list(range(n)); total = 0; used = []
    for w, u, v in sorted(edges):
        ru, rv = find(p, u), find(p, v)
        if ru != rv:
            p[ru] = rv; total += w; used.append((u, v, w))
    return total, used
```

Алгоритм **Прима** решает то же, но иначе: начинает с одной вершины и жадно присоединяет ближайшую ещё не включённую, используя очередь с приоритетом. Краскал удобнее на разреженных графах (мало рёбер), Прим — на плотных. Оба дают дерево минимального суммарного веса; если задача требует «соединить N точек с минимальной длиной кабеля», это она.

## Максимальный поток и паросочетание

Отдельный класс задач — **потоки**. «Сколько груза можно провезти по сети дорог с ограничениями пропускной способности» — это задача о максимальном потоке, решаемая алгоритмом Эдмондса-Карпа (BFS по остаточной сети) или Диница. Рёбра имеют ёмкость, и надо найти поток, насыщающий сеть.

Частный и очень частый в CTF случай — **двудольное паросочетание**: есть исполнители и задачи, каждый исполнитель может взять лишь некоторые задачи, надо распределить максимально. Это сводится к максимальному потоку: источник → исполнители (ёмкость 1) → задачи (ёмкость 1) → сток. Алгоритм Куна (венгерский) решает паросочетание напрямую. Признак задачи: «составь расписание», «сопоставь», «каждому — своё» — думай про паросочетание, а не про перебор. Если данных мало, перебор укусит по времени, а поток решит за полином.
