## Вопрос, с которого всё начинается

В задаче дано изображение — скриншот, скан, фотография. Текст на нём не выделяется, `strings` не поможет. Нужно **распознать** символы. Это делает OCR (optical character recognition). Разберём, как им пользоваться.

## Наш пример

Возьмём картинку с текстом `FLAG: nto{...}`, но снятую под углом и с шумом. Прямое распознавание даст ошибки. Задача — предобработать и распознать корректно.

## Шаг 1: что такое OCR

**OCR** — преобразование изображения с текстом в текстовые символы. Движок анализирует форму символов и сопоставляет с моделями шрифтов. Самый известный открытый движок — **Tesseract** (поддерживает 100+ языков).

## Шаг 2: установка и базовый запуск

```
$ tesseract image.png output
$ cat output.txt
FLAG: nto{...}
```

Tesseract принимает изображение и пишет текст в файл. Флаг `-l` задаёт язык (`-l eng`, `-l rus`), `--psm` — режим сегментации страницы.

## Шаг 3: предобработка

Точность OCR сильно зависит от качества изображения:
- **Grayscale** — убрать цвет.
- **Бинаризация** — порог, чтобы текст был чёрным на белом.
- **Масштаб** — увеличить мелкий текст (Tesseract любит ~300 DPI).
- **Поворот** — выровнять наклон.
- **Удаление шума** — медианный фильтр.
- **Инверсия** — если текст белый на чёрном.

## Шаг 4: режимы PSM

`--psm` (page segmentation mode) задаёт, как искать текст:
- `--psm 6` — единый блок текста.
- `--psm 7` — одна строка.
- `--psm 8` — одно слово.
- `--psm 13` — сырая строка без разметки.

Для флага на картинке часто лучше всего `--psm 7` или `13`.

## Шаг 5: языковые данные

Tesseract использует файлы `*.traineddata`. Для смешанного текста (латиница + кириллица) можно указать несколько языков: `-l eng+rus`. Если язык неверный, символы распознаются как похожие из другого алфавита.

## Шаг 6: практический пайплайн

1. Открыть картинку (Pillow).
2. Grayscale → resize ×2 → threshold.
3. Сохранить преprocessed.
4. `pytesseract.image_to_string(img, config='--psm 7')`.
5. Проверить, при ошибках подкрутить порог/масштаб.

## Шаг 7: когда не работает

- Рукописный текст — Tesseract слаб, нужны специализированные модели.
- Сильный фон/градиент — нужна цветовая фильтрация.
- Стилизованные шрифты — шаблонный матчинг лучше.
- Очень низкое разрешение — апскейл не восстановит утраченное.

## Шаг 8: обратная задача

Если ты защищаешь текст от OCR (например, CAPTCHA), используй искажение и шум. Но помни: OCR-модели улучшаются, поэтому «спрятать текст от OCR» — временная мера.

## Частые ошибки

- Гнать OCR без предобработки.
- Забывать указать язык.
- Использовать PSM по умолчанию для одной строки.
- Не проверять результат на опечатки (OCR путает `0/O`, `1/l`).

## Разбор кейса: полный пайплайн на реальном изображении

Возьмём скан `scan.png` с одной строкой `FLAG: nto{0cr_r0cks}` и разберём его по шагам.

```
$ tesseract scan.png out --psm 7 -l eng
$ cat out.txt
FLAG: nto{0cr_r0cks}
```

Здесь `--psm 7` говорит «на изображении одна текстовая строка», `-l eng` — язык. Без предобработки на шумном скане тот же вызов часто даёт `FLAG: nto{0cr_r0cks}` с ошибками вроде `O`/`0`. Тогда добавляем предобработку:

```python
from PIL import Image
import pytesseract
im = Image.open('scan.png').convert('L').resize(lambda s: s*2, Image.LANCZOS)
im = im.point(lambda p: 0 if p < 150 else 255)
print(pytesseract.image_to_string(im, config='--psm 7 -l eng'))
```

Ключевые решения: увеличение вдвое (Tesseract лучше работает при ~300 DPI), порог `150` по гистограмме, PSM 7 для строки. Такой пайплайн стабильно вытягивает флаг из скриншота.

## Таблица: режимы `--psm`

| PSM | Смысл | Когда использовать |
|---|---|---|
| 0 | только ориентация и скрипт | определить поворот и язык |
| 3 | авто (по умолчанию) | страница обычного текста |
| 4 | колонки текста переменного размера | газетные колонки |
| 6 | единый блок текста | абзац, скриншот целиком |
| 7 | одна строка | одна строка флага/пароля |
| 8 | одно слово | одна метка |
| 10 | одно слово в строке | значение в таблице |
| 11 | разреженный текст | разбросанные подписи |
| 12 | разреженный с ориентацией | разбросанный + поворот |
| 13 | сырая строка без разметки | одна строка без анализа структуры |

Для флага почти всегда оптимальны 7 или 13. Режим 3 на одиночной строке часто добавляет лишние переводы строк и «призрачные» символы.

## Tesseract из CLI против pytesseract

Оба варианта — один движок. CLI удобен для разового прогона и отладки:

```
$ tesseract img.png stdout --psm 7 --oem 3
```

`--oem 3` — использовать и старый, и новый LSTM-движок вместе (по умолчанию). `stdout` вместо имени файла печатает результат в терминал — удобно для пайпа `| grep nto`. `pytesseract` удобен, когда предобработка делается в Python: он принимает объект PIL напрямую, без записи временного файла. `image_to_data` возвращает ещё и координаты и уверенность каждого слова — по ним видно, какие символы движок «не уверен», и их стоит перепроверить глазами.

## Если не сработало

- **Символы путаются (0/O, 1/l, 5/S).** Включи список допустимых символов: `tessedit_char_whitelist=0123456789abcdef...`. Тогда движок не будет выбирать похожие буквы.
- **Текст повёрнут.** `--psm 0` покажет угол; поверни изображение на этот угол (`Image.rotate`) и распознавай заново.
- **Русский + английский вперемешку.** Укажи `-l eng+rus`; иначе буквы одного алфавита распознаются как похожие из другого.
- **Мелкий текст.** Апскейл ×2–×3 с LANCZOS/LANCZOS до распознавания; интерполяция NEAREST для текста не годится.
- **Слишком низкое разрешение.** Апскейл не создаёт информации; если пиксели уже слились, восстановить нельзя — ищи другой источник изображения.

## Ограничения

Tesseract — не универсальное решение. Рукописный текст он распознаёт плохо (нужны специализированные модели вроде Kraken/TrOCR), сильно стилизованные шрифты и «шумные» фоны требуют отдельной обработки. Точность никогда не 100%: результат обязательно проверяют глазами, особенно для коротких критичных значений вроде флага или ключа. И помни: OCR — это шаг извлечения, а не интерпретации; распознанный текст дальше ещё может быть закодирован (base64, hex), и это уже следующая задача.

## Практика: извлечение флага из скриншота целиком

Соберём рабочий сценарий для типичной CTF-задачи: дано `shot.png`, на нём где-то в тексте флаг.

```bash
$ tesseract shot.png stdout --psm 6 2>/dev/null | grep -o 'nto{[^}]*}'
nto{th1s_w4s_ocr}
```

Если PSM 6 не находит строку, перебираем режимы и масштабы прямо из шелла:

```bash
$ for psm in 3 6 7 11 13; do
>   for s in 100 200 300; do
>     convert shot.png -resize "${s}%" /tmp/s.png
>     tesseract /tmp/s.png stdout --psm $psm 2>/dev/null | grep -o 'nto{[^}]*}'
>   done
> done
```

Этот «грубый перебор» (масштаб × режим сегментации) решает большинство скриншотных задач за секунды. Для каждого варианта ищем шаблон флага регуляркой `nto{...}` — это отсекает весь распознанный мусор и оставляет только нужное.

Полезный трюк — предварительно вырезать область с текстом, если известны координаты (например, из HTML-страницы): меньше площадь — меньше ошибок и быстрее перебор. А если флаг разбит на несколько строк, PSM 6 соберёт их как блок, тогда как PSM 7 склеит в одну строку и может испортить разделители.

## Сравнение с `strings` и зачем вообще OCR

Первый рефлекс при работе с изображением — `strings file.png`: он вытаскивает читаемые последовательности байт. Иногда флаг действительно лежит в метаданных PNG (в чанке `tEXt`) и `strings` его найдёт:

```bash
$ strings shot.png | grep nto
```

Но если текст нарисован пикселями, `strings` бессилен — в файле нет байтов символов, только цвета пикселей. Тогда и нужен OCR. Порядок действий: сначала `exiftool`/`strings` (быстро, вдруг повезёт), потом `zbarimg` (если это QR/штрихкод), и только затем OCR. Так ты не тратишь время на распознавание там, где данные уже лежат открытым текстом.

## Итоговый чек-лист OCR

- Сначала `strings`/`exiftool` — вдруг текст уже открытым текстом в метаданных.
- Затем `zbarimg` — если это QR или штрихкод.
- И только потом OCR: grayscale → апскейл ×2 → порог → `tesseract`.
- Режим `--psm 7` для строки, `6` для блока, `13` для сырой строки.
- Язык задавай явно (`-l eng`, `-l eng+rus`), иначе путаются алфавиты.
- `tessedit_char_whitelist` отсекает похожие символы.
- Результат всегда проверяй глазами: 0/O и 1/l — классическая ошибка.
- Не отправляй чужие картинки в публичные онлайн-OCR — это утечка.

## Что мы теперь знаем

- OCR превращает изображение текста в символы.
- Tesseract — основной открытый движок.
- Предобработка (порог, масштаб, поворот) резко повышает точность.
- PSM и языковые данные важны.
- OCR путает похожие символы — проверяй результат.
