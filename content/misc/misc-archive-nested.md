## Вопрос, с которого всё начинается

Задача даёт `bundle.zip`. Распаковываешь — внутри `data.tar`, в нём `layer.gz`, а в нём ещё что-то. Метка лежит где-то в глубине этой матрёшки. Как распаковывать неизвестные архивы, не запутавшись и не угробив диск?

## Наш пример: матрёшка

Начнём с первого уровня и будем идти вглубь, каждый раз определяя формат:

```
$ file bundle.zip
bundle.zip: Zip archive data
$ unzip -l bundle.zip
  data.tar
  notes.txt
```

Первый уровень — ZIP с двумя файлами. Один из них — снова архив.

## Шаг 1: определять формат по магии

Не полагайся на расширение: оно врёт. Смотри на **магию** — первые байты:

- `PK\x03\x04` — ZIP.
- `\x1f\x8b` — gzip.
- `BZh` — bzip2.
- `\xfd7zXZ` — xz.
- `ustar` (на смещении 257) — tar.
- `Rar!` — RAR.
- `7z\xbc\xaf\x27\x1c` — 7z.
- `\x28\xb5\x2f\xfd` — zstd.

```
$ file data.tar notes.txt
data.tar: POSIX tar archive
notes.txt: ASCII text
```

## Шаг 2: tar и сжатие внутри

`tar` — не архив в привычном смысле, а «склеивание» файлов в один поток. Сжатие добавляется снаружи (`tar.gz`, `tar.xz`). GNU tar сам определяет сжатие:

```
$ tar tf data.tar
layer.gz
readme
$ tar xf data.tar
```

Внутри — снова gzip. `gunzip -c layer.gz > layer` или `zcat`.

## Шаг 3: автоматизировать распаковку

Когда уровней много, помогает `binwalk` — он находит вложенные форматы по магии и извлекает их рекурсивно:

```
$ binwalk -e bundle.zip
$ find _bundle.zip.extracted -type f
```

`binwalk -e` раскручивает матрёшку автоматически. Но помни: он может создать много файлов, поэтому работай в отдельной директории.

## Шаг 4: zip-bomb — почему осторожно

**Zip-bomb** — архив, который при распаковке разворачивается в огромный объём (гигабайты из килобайт), потому что внутри — миллионы повторяющихся данных, сжатых с высоким коэффициентом. Классика — `42.zip` (несколько уровней, экспоненциальный рост). Если распаковать «в лоб», закончится диск или память.

Признаки: крошечный архив, огромный `uncompressed size` в листинге. Проверяй **до** распаковки:

```
$ zipinfo bundle.zip | tail -2
2 files, 12345 bytes uncompressed, 1024 bytes compressed: 91.7%
```

## Шаг 5: безопасная распаковка

Правила: распаковывай в изолированную директорию с ограничением по месту; используй лимиты (`ulimit -f`, `timeout`); не запускай `unzip` «в лоб» на неизвестном архиве; для подозрительных — читай отдельные файлы через `unzip -p`, не извлекая всё. Для tar есть `--to-command`, чтобы обработать поток без записи.

## Шаг 6: пароли на архивах

Архивы бывают зашифрованы. ZIP (ZipCrypto/AES) и RAR защищают паролем. Пароль часто лежит рядом (в подсказке, другом файле) или подбирается по словарю. Инструмент — `john`/`hashcat` по хешу архива или `fcrackzip`:

```
$ zip2john secret.zip > hash.txt
$ john hash.txt --wordlist=rockyou.txt
```

Важно: подбор **оффлайн** (по хешу) допустим; онлайн-атаки на сервисы — нет.

## Шаг 7: нестандартные контейнеры

Помимо классических архивов встречаются «свои» контейнеры: самораспаковывающиеся `.exe`, `.deb`/`.rpm` (ar + tar), `.jar` (zip), `.apk` (zip), `.docx` (zip). Все они распознаются по магии и раскрываются тем же подходом «определи → распакуй → смотри».

## Шаг 8: восстановление повреждённых архивов

Если архив «побит», помогает: `unzip -FF` (починка центрального каталога), `7z x` (часто терпимее), `zip -FF`. Данные иногда извлекаются даже без корректного каталога — читая локальные заголовки. В CTF повреждённый архив — частый приём, заставляющий не сдаваться после первой ошибки.

## Шаг 9: практический порядок

1. `file` — определить формат (не верь расширению).
2. `unzip -l`/`tar tf`/`7z l` — посмотреть содержимое без распаковки.
3. Оценить `uncompressed size` — нет ли бомбы.
4. Распаковать в отдельную директорию с лимитами.
5. Повторить для вложенных архивов (`binwalk -e`).
6. Проверять пароли по хешу, если нужно.

## Шаг 10: где прячут метку

Типичные места: (1) текстовый файл в глубине матрёшки; (2) имя файла; (3) комментарий архива (ZIP-комментарий); (4) «хвост» файла после конца архива; (5) пароль к следующему уровню, записанный в подсказке. Проверяй комментарий: `unzip -z bundle.zip`.

## Что мы теперь знаем

- Архивы — контейнеры, часто вложенные; формат определяют по магии.
- tar — склейка, сжатие добавляется снаружи (gz/xz/bz2).
- `binwalk -e` раскручивает матрёшку автоматически.
- zip-bomb опасен: проверяй размер до распаковки и ограничивай ресурсы.
- Пароли к архивам подбирают оффлайн по хешу.

## Шаг 11: чем tar отличается от zip по устройству

Это важно понять, а не запомнить. **ZIP** хранит центральный каталог в конце файла: список всех записей с их смещениями и размерами. Поэтому `unzip -l` мгновенно показывает содержимое, а повреждение каталога ломает весь архив. **tar** — это просто последовательность заголовков и данных, склеенных подряд, без центрального каталога: чтобы узнать содержимое, нужно прочитать весь поток с начала. Отсюда практические следствия: tar можно распаковывать потоково (`tar xf - < stream`), а zip требует доступа к концу файла. И ещё: сжатие у tar внешнее (gz/xz/bz2), поэтому `file` может показать «gzip», а внутри лежать tar — определяй по вложенной магии.

## Шаг 12: магия на смещении, а не в начале

Некоторые форматы опознаются не по первым байтам, а по смещению. У tar сигнатура `ustar` стоит на смещении 257 (после 512-байтового заголовка). У некоторых контейнеров (например, самораспаковывающихся) перед настоящим архивом идёт исполняемый заголовок, и магия ZIP оказывается на смещении в сотни байт. Поэтому `file` иногда говорит «data», хотя внутри архив. Решение — искать магию по всему файлу: `grep -abo 'PK\x03\x04' file` или `binwalk` без `-e`, который сканирует все смещения.

## Шаг 13: восстановление пароля по атаке на структуру

Если архив зашифрован слабым ZipCrypto, его можно атаковать не перебором пароля, а известным открытым текстом (known-plaintext): если внутри есть файл с предсказуемым содержимым, ключ восстанавливается почти мгновенно. Инструмент `bkcrack` делает это. Для AES-ZIP такой приём не работает — только словарь/перебор. Знание алгоритма шифрования архива определяет стратегию: ZipCrypto — KPA, AES — словарь.

## Шаг 14: «архив в архиве» как проверка на внимательность

В CTF матрёшка проверяет терпение и методичность. Ключевой навык — не пропускать уровни и не путать «не получилось распаковать» с «здесь конец». Признаки, что уровень не последний: имя файла намекает (`.tar`, `.gz`, `layer2`), магия внутри не текста, размер подозрительно «круглый». Веди список уровней и форматов на каждом — это спасает от блуждания.

## Шаг 15: безопасность распаковки на сервере

Если ты разбираешь не CTF, а реальную систему, где приложение распаковывает пользовательские архивы, — это класс уязвимостей. Zip Slip: имя файла в архиве содержит `../` и при распаковке пишет за пределы целевой директории. Symlink-атака: архив создаёт симлинк на `/etc`, затем пишет через него. Защита — канонизировать пути и проверять, что результат остаётся внутри целевой папки, а также лимитировать общий объём и число файлов.

## Шаг 16: где посмотреть содержимое без распаковки

Всегда начинай с листинга, не извлекая: `unzip -l`, `tar tf`, `7z l`, `rar l`, `zipinfo`. Это безопасно и быстро, и сразу показывает имена, размеры и коэффициент сжатия. Комментарий архива — `unzip -z`. Если видишь гигантский `uncompressed size` при крошечном сжатом размере — это красный флаг zip-bomb, и извлекать целиком нельзя.

## Шаг 17: расшифровка имён и кодировок

Имена файлов внутри архива могут быть в разных кодировках (CP866, UTF-8). Иногда метку прячут именно в имени: `nto{...}.txt`. Если имя отображается кракозябрами, попробуй `unzip -O cp866` или `7z` с опцией кодировки. Имя — это тоже данные, и парсеры его почти не проверяют.

## Итог

Вложенные архивы — про методичность: определить магию (в том числе на смещении), посмотреть листинг без распаковки, оценить риск zip-bomb, распаковать вглубь в изолированной директории, при необходимости — подобрать пароль оффлайн. Помни про Zip Slip при работе на сервере и про то, что метка может быть в имени файла или комментарии архива.

## Шаг 18: рекурсивная распаковка скриптом

Когда уровней много, удобно писать цикл, который на каждом шаге определяет формат и распаковывает в новую папку, пока не останется один файл без магии архива. Такой скрипт — 20 строк на bash/Python с `file`, `unzip`, `tar`, `gunzip`. Он экономит время и не даёт пропустить уровень. Главное — ограничить глубину (например, 20 шагов), чтобы не зациклиться на архиве, содержащем сам себя.

## Шаг 19: архивы внутри изображений и документов

Матрёшка бывает не только из архивов: ZIP/gzip часто прячут внутри PNG, JPEG, PDF, docx. Там их находит `binwalk -e`, который сканирует всё тело файла. Поэтому правило «проверь `binwalk` по любому бинарному артефакту» универсально — от картинки до диска.

## Шаг 20: контроль целостности

Если после распаковки файлы не открываются — проверь целостность: `unzip -t` (test), `gzip -t`. Повреждённый поток часто означает, что файл усечён или что перед ним был пропущен заголовок. В задачах усечение — намеренный приём: часть данных может лежать в «хвосте» после конца архива, и её нужно прочитать отдельно.

## Шаг 21: выводы

Навык работы с вложенными архивами — базовый для misc: определить формат, оценить риск, распаковать вглубь, найти метку в данных, имени или комментарии. Он повторяется в половине задач про контейнеры, поэтому доведи его до автоматизма.
