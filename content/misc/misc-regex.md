## Вопрос, с которого всё начинается

У тебя есть файл-лог на 50 тысяч строк, и где-то в нём спрятан флаг формата `flag{...}`. Искать глазами? Нет. Нужен инструмент, который опишет **шаблон** и найдёт всё, что ему соответствует. Этот инструмент — регулярные выражения (regex).

Regex — это язык поиска по образцу. Освоив его, ты сможешь за секунды вытаскивать из текста адреса, токены, флаги и поля. В этом уроке мы разберём его на одном практическом примере.

## Наш пример: вытащить флаг из лога

Допустим, есть файл `access.log`. Где-то в нём лежит строка с флагом. Наша цель — извлечь именно `flag{...}`, а не весь лог.

## Шаг 1: простой поиск

Начнём с самого простого — найти подстроку:

```python
import re
text = open("access.log").read()
for m in re.finditer(r"flag", text):
    print(m.start())
```

`re.finditer` находит все вхождения и возвращает их позиции. Но нам нужен не сам `flag`, а его содержимое.

## Шаг 2: символьные классы

Флаг выглядит как `flag{...}`, где внутри буквы, цифры и подчёркивания. Опишем это:

```python
matches = re.findall(r"flag\{[a-zA-Z0-9_]+\}", text)
print(matches)
```

```
['flag{r3g3x_1s_p0w3rful}']
```

Разберём шаблон по частям:

- `flag\{` — буквально `flag{` (фигурную скобку экранируем `\`, потому что в regex она специальная).
- `[a-zA-Z0-9_]` — класс символов: любая буква, цифра или подчёркивание.
- `+` — «один или больше» таких символов.
- `\}` — буквально `}`.

Так мы получили флаг, не зная его содержимого.

## Шаг 3: спецсимволы и экранирование

В regex часть символов имеет особый смысл. Их надо экранировать `\`:

| Символ | Значение в regex |
|--------|------------------|
| `.` | любой символ |
| `*` | 0 или больше |
| `+` | 1 или больше |
| `?` | 0 или 1 |
| `[]` | класс символов |
| `()` | группа |
| `{}` | квантификатор |

Если нужен сам символ, ставьте `\` перед ним: `\.`, `\{`, `\+`.

## Шаг 4: группы и извлечение

Часто нужен не весь шаблон, а его часть. Для этого служат **группы** в скобках:

```python
m = re.search(r"user=(\w+)\s+ip=(\d+\.\d+\.\d+\.\d+)", text)
print(m.group(1), m.group(2))
```

```
admin 10.0.0.5
```

`group(1)` — первая группа, `group(2)` — вторая. Так из строки лога достают поля по имени. `\d` — цифра, `\w` — буква/цифра/подчёркивание, `\s` — пробельный символ.

## Шаг 5: жадность

Квантификаторы по умолчанию **жадные** — они захватывают как можно больше. Иногда это ломает поиск:

```
текст: <a>первый</a> <a>второй</a>
жадный  r"<a>.*</a>"      → <a>первый</a> <a>второй</a>
ленивый r"<a>.*?</a>"     → <a>первый</a>
```

Знак `?` после квантификатора делает его **ленивым** — он захватывает минимум. Это одна из самых частых ошибок новичков: жадный `.` съедает слишком много.

## Шаг 6: lookaround

Иногда нужно найти текст **рядом** с известным словом, не включая его. Для этого есть lookahead/lookbehind:

```python
re.findall(r"(?<=token=)\w+", text)   # ищем после 'token='
re.findall(r"\w+(?==end)", text)      # ищем перед '=end'
```

`(?<=...)` — «позади идёт», `(?=...)` — «впереди идёт». Эти конструкции не включаются в результат, что удобно для чистого извлечения.

## Типовые CTF-шаблоны

Держите под рукой:

- **Флаг:** `flag\{[^}]+\}` — всё до закрывающей скобки.
- **Hex-строка:** `[0-9a-fA-F]{16,}`.
- **Base64:** `[A-Za-z0-9+/]{20,}={0,2}`.
- **Email:** `[\w.]+@[\w.]+`.
- **IP:** `\d{1,3}(\.\d{1,3}){3}`.
- **URL:** `https?://[^\s]+`.

## Продвинутые приёмы

- **Именованные группы:** `(?P<name>\w+)` — доступ по имени `m.group("name")`.
- **Опциональные блоки:** `(?:...)?` — необязательная часть.
- **Якоря:** `^` и `$` — начало и конец строки (с флагом `re.M` — каждой строки).
- **Флаги:** `re.I` (регистронезависимо), `re.S` (`.` включает перевод строки).
- **Замена:** `re.sub(r"\d+", "N", text)` — заменить все числа на `N`.

## Работа с большими файлами

Читать файл целиком в память не всегда можно. Читайте построчно:

```python
with open("huge.log") as f:
    for line in f:
        m = re.search(r"flag\{[^}]+\}", line)
        if m:
            print(m.group(0))
            break
```

Так обрабатываются гигабайты логов без переполнения памяти.

## Почему regex — не парсер

Важное ограничение: регулярные выражения не разбирают вложенные структуры (HTML, JSON, XML) корректно. Для них нужны настоящие парсеры (`BeautifulSoup`, `json`). Regex хорошо работает с «плоским» текстом: логами, списками, простыми форматами.

Правило: структура вложенная — берите парсер; текст линейный — regex.

## Типичные ошибки

- **Жадность:** `.*` вместо `.*?` съедает лишнее.
- **Забытый `re.escape`:** если шаблон строится из пользовательских данных, спецсимволы надо экранировать.
- **Катастрофический бэктрекинг (ReDoS):** шаблоны вида `(a+)+` могут «повесить» программу на длинном входе.
- **Смешение `search` и `match`:** `match` ищет только в начале строки.

## Полный разбор: извлекаем всё из лога

Вернёмся к нашему логу. Пошагово: читаем файл построчно → ищем флаг шаблоном `flag\{[^}]+\}` → находим `flag{r3g3x_1s_p0w3rful}` → дополнительно извлекаем все IP шаблоном `\d{1,3}(\.\d{1,3}){3}` → сохраняем результат. Один скрипт, тридцать строк — и весь лог разобран.

Если флаг закодирован (например, в hex), применяем ещё один regex: `[0-9a-fA-F]{16,}`, затем `bytes.fromhex`. Так regex комбинируется с инструментами из предыдущего урока.

## Шпаргалка по метасимволам

| Метасимвол | Значение |
|------------|----------|
| `.` | любой символ |
| `\d` / `\w` / `\s` | цифра / слово / пробел |
| `\D` / `\W` / `\S` | отрицание |
| `*` / `+` / `?` | 0+, 1+, 0-1 |
| `{n,m}` | от n до m повторов |
| `[]` | класс символов |
| `()` | группа |
| `^` / `$` | начало / конец |
| `\|` | или |

## Как тренироваться

Возьмите любой лог и попробуйте извлечь из него всё: IP, URL, email, статусы. Составьте свой набор шаблонов. Через десяток задач вы начнёте писать regex «с ходу».

## Regex вокруг нас

Regex встроен во множество инструментов: `grep -E`, `sed`, `awk`, фильтры Wireshark, поиск в редакторах, конфиги nginx, правила IDS. Поэтому навык выходит далеко за пределы Python и CTF — вы будете применять его постоянно.

## Что мы теперь знаем

По-простому:

1. Regex ищет по шаблону, а не по точной строке.
2. Классы символов (`[a-z]`, `\d`, `\w`) описывают множества.
3. Группы `()` извлекают части совпадения.
4. Жадность (`.*` против `.*?`) меняет результат.
5. Lookaround находит текст рядом со словом.

## На что смотреть дальше

- **Экранируйте спецсимволы.** `{`, `}`, `.`, `+` требуют `\`.
- **Проверяйте жадность.** Начните с `.*?`, если сомневаетесь.
- **Тестируйте онлайн.** `regex101.com` показывает группы и объясняет шаблон.
- **Не переусложняйте.** Простой шаблон надёжнее «умного».
