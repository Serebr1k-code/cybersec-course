## Зачем нужны регулярные выражения

Регулярные выражения (regex) — это язык описания шаблонов в тексте. В CTF они незаменимы: извлечь флаг из «грязного» вывода, распарсить нестандартный формат, вытащить все числа, IP или base64-блоки. Большая часть misc-задач решается связкой «регулярка + пара строк кода». Цель модуля — довести использование regex до автоматизма.

## Базовый синтаксис

| Шаблон | Значение |
|--------|----------|
| `.` | любой символ (кроме `\n` по умолчанию) |
| `\d` | цифра `[0-9]` |
| `\w` | буква/цифра/`_` |
| `\s` | пробельный символ |
| `*` | 0 или более |
| `+` | 1 или более |
| `?` | 0 или 1 (жадность-минимум) |
| `{n,m}` | от n до m повторов |
| `[...]` | класс символов |
| `(...)` | группа (захват) |
| `(?:...)` | группа без захвата |
| `\|` | или |
| `^` `$` | начало/конец строки |
| `\b` | граница слова |

Жадность: `.*` «съедает» максимум, `.*?` — минимум. Это самая частая причина «неправильного» захвата.

## Извлечение флагов и токенов

```python
import re
text = open('out.txt', encoding='utf-8', errors='replace').read()

# флаг стандартного вида
print(re.findall(r'[A-Za-z0-9_]*\{[^}]*\}', text))

# все email
print(re.findall(r'[\w.+-]+@[\w-]+\.[\w.-]+', text))

# все IPv4
print(re.findall(r'\b(?:\d{1,3}\.){3}\d{1,3}\b', text))

# все hex-строки длиной >=16
print(re.findall(r'\b[0-9a-fA-F]{16,}\b', text))
```

`[^}]*` — «всё, кроме закрывающей скобки», идеально для `FLAG{...}`.

## Группы и именованные группы

```python
m = re.search(r'(?P<user>\w+):(?P<pw>[^:]+)@(?P<host>[\w.]+)', line)
if m:
    print(m.group('user'), m.group('host'))
    print(m.groups())   # ('user', 'pw', 'host')
```

Именованные группы делают код читаемым и устойчивым к перестановке полей.

## Жадность: как не поймать лишнее

```python
s = "<a>one</a><a>two</a>"
re.findall(r'<a>.*</a>', s)    # ['<a>one</a><a>two</a>']  — жадно!
re.findall(r'<a>.*?</a>', s)   # ['<a>one</a>', '<a>two</a>'] — лениво
```

Правило: если между двумя маркерами ожидается короткий фрагмент — всегда `.*?`.

## Замены и очистка данных

```python
re.sub(r'\s+', ' ', text)          # нормализовать пробелы
re.sub(r'[^\x20-\x7e]', '', text)  # выкинуть непечатаемое
re.sub(r'0x[0-9a-fA-F]+', 'HEX', text)
```

`re.sub` удобен для «причесывания» вывода перед парсингом и для сокрытия длинных значений в отчётах.

## Компиляция и флаги

```python
pat = re.compile(r'flag\{[^}]*\}', re.IGNORECASE | re.MULTILINE)
pat.findall(text)
```

Флаги: `IGNORECASE` — без учёта регистра, `MULTILINE` — `^/$` на каждой строке, `DOTALL` — `.` включает `\n`, `VERBOSE` — пробелы в шаблоне игнорируются (для читаемости). Компилируйте шаблон, если используете его в цикле.

## Разбор структурированных логов

```python
line = '2024-01-01 12:00:00 INFO user=admin ip=10.0.0.5 status=200'
m = re.match(r'(\S+ \S+) (\w+) user=(\w+) ip=([\d.]+) status=(\d+)', line)
print(m.groups())
```

Для строго структурированных форматов (JSON/CSV) regex — не лучший выбор, берите `json.loads`/`csv`. Regex — для «почти структурированного» текста.

## Regex vs готовые парсеры

Не пытайтесь парсить HTML регулярками (это классическая ловушка). Для HTML берите `BeautifulSoup`/`lxml`, для JSON — `json`, для URL — `urllib.parse`. Regex оставляйте для извлечения простых токенов и «грязного» текста.

## Типичные ошибки и подводные камни

- **Жадность** — забыли `?` и захватили лишнее.
- **Спецсимволы** — `.` и `+` надо экранировать (`\.`, `\+`), если это литералы.
- **`re.match` vs `re.search`** — `match` только с начала строки, `search` — где угодно.
- **Нет `re.MULTILINE`** — `^`/`$` не работают построчно.
- **Catastrophic backtracking** — вложенные квантификаторы (`(a+)+`) вешают движок (см. ReDoS).
- **Unicode vs bytes** — для байтовых данных используйте `rb'...'` и `re` по `bytes`.
- **Неверная кодировка** — читайте файл с `errors='replace'`.

## Отладка шаблонов

Используйте `regex101.com` (с выбором flavor Python) или интерактивно:

```python
print(re.findall(r'\d+', 'a1b22c333'))
# ['1', '22', '333']
```

Всегда проверяйте шаблон на маленьком примере до применения к большому файлу.

## Справочная таблица быстрых шаблонов

| Что найти | Шаблон |
|-----------|--------|
| Флаг | `[A-Za-z0-9_]+\{[^}]*\}` |
| IPv4 | `\b(?:\d{1,3}\.){3}\d{1,3}\b` |
| Email | `[\w.+-]+@[\w-]+\.[\w.-]+` |
| URL | `https?://[^\s]+` |
| Hex ≥16 | `\b[0-9a-fA-F]{16,}\b` |
| Base64 | `[A-Za-z0-9+/]{16,}={0,2}` |
| MAC | `(?:[0-9a-fA-F]{2}:){5}[0-9a-fA-F]{2}` |

## Что дальше / решение

План: выучите таблицу метасимволов, отработайте жадность (`.*?`) и группы, держите готовые шаблоны для флагов/IP/hex/base64. На задаче сначала «причешите» текст (`re.sub`), затем извлеките токены, при необходимости — компилируйте шаблон. Не парсите HTML/JSON регулярками — для них есть готовые парсеры. И помните про ReDoS: никогда не строите шаблон с вложенными квантификаторами от недоверенного ввода.

## Практика: строим парсер «грязного» вывода

Разберём реальный сценарий. Задача выдаёт большой лог, в котором вперемешку лежат обычные строки, base64-блоки, hex-дампы и где-то спрятан флаг. Правильная последовательность действий такая. Сначала читаем файл целиком в байтах и приводим к тексту с заменой непечатаемых символов. Затем прогоняем несколько независимых шаблонов: ищем флаг, все hex-строки длиной от шестнадцати символов, все блоки, похожие на base64, и все числа. Каждый результат сохраняем отдельно, чтобы не потерять. После этого для каждой найденной hex-строки пробуем декодировать её в байты и снова прогнать поиск флага — часто флаг лежит именно на один слой глубже.

Ключевая идея — итеративность. Не пытайтесь написать один универсальный шаблон на всё. Лучше сделать набор маленьких точных шаблонов и прогонять их по кругу, пока не появится осмысленный результат. Такой подход устойчив: если один шаблон не сработал, остальные продолжают работать. И обязательно сохраняйте промежуточные данные — в многослойных задачах всегда хочется вернуться на шаг назад.

## Как не утонуть в ложных срабатываниях

Широкие шаблоны вроде `.{16,}` ловят буквально всё, включая мусор. Чтобы отсеять ложные срабатывания, используйте якоря границ слова (`\b`), ограничивайте классы символов и проверяйте длину. Полезно после извлечения отфильтровать кандидатов по «печатаемости»: настоящий текст почти целиком состоит из символов от пробела до тильды, а мусор содержит много управляющих байтов. Добавьте простую функцию оценки «текстовости» и сортируйте кандидатов по ней — самые читаемые окажутся сверху, и вы быстро найдёте нужное.

## Что дальше / решение

Итог: стройте решение как набор небольших точных шаблонов, применяемых итеративно, а не как один сложный regex. Сохраняйте промежуточные результаты, фильтруйте ложные срабатывания по печатаемости и длине, и всегда проверяйте шаблон на маленьком примере. Регулярки — это инструмент извлечения, а не парсинга структурированных форматов: для HTML берите BeautifulSoup, для JSON — json, для URL — urllib.parse. Освоив эти правила, вы будете уверенно вытаскивать нужные данные даже из самого неопрятного вывода.

## Частые вопросы по регулярным выражениям

«Шаблон не находит то, что должен?» — проверьте жадность (`.*` vs `.*?`) и якоря. «Нужно несколько строк?» — добавьте `re.MULTILINE`. «Точка не ловит перевод строки?» — используйте `re.DOTALL`. «Спецсимвол воспринимается буквально?» — экранируйте (`\.`, `\+`). «Работаю с байтами?» — используйте `rb'...'`. «Слишком много ложных срабатываний?» — ужесточите классы символов и границы. «Можно ли парсить HTML?» — не стоит, берите BeautifulSoup. Помните: регулярки — инструмент извлечения, а не парсинга структурированных форматов.
