## Вопрос, с которого всё начинается

В прошлом уроке мы оптимизировали код под лимит времени. Но есть задачи, где перебирать бесполезно в принципе: вариантов настолько много, что никакой скорости не хватит. Зато у задачи есть **структура** — набор условий, которым должен удовлетворять ответ.

Пример: вы разобрали check-функцию бинарника и знаете, что она требует от флага несколько арифметических равенств. Как найти флаг, не перебирая `256^k` строк? Ответ — описать условия формально и отдать их **SMT-солверу**.

## Наш пример: check-функция из crackme

После реверса (его мы разбираем в категории reversing) видно: флаг — 4 байта, и функция проверяет

- `f[0] + f[1] == 0x8f`,
- `f[2] ^ f[3] == 0x10` (это XOR — побитовое «исключающее или»),
- каждый байт — печатный символ (от `0x20` до `0x7e`).

Наивный перебор — `95^4 ≈ 8·10^7` комбинаций. Может, и переживём, но если байтов будет 8, это уже `95^8 ≈ 6·10^15` — невозможно. Нужен другой подход.

## Шаг 1: что такое SMT и как поставить Z3

SMT (Satisfiability Modulo Theories) — задача поиска значений переменных, при которых выполняются логические и арифметические ограничения. Z3 — самый популярный SMT-солвер (его сделали в Microsoft Research). Вместо перебора вы **описываете условия**, а Z3 находит решение сам.

```bash
$ pip install z3-solver
```

Проверим на простой системе `x + y = 10`, `x - y = 2`:

```python
from z3 import *
x, y = Int('x'), Int('y')
s = Solver()
s.add(x + y == 10, x - y == 2)
print(s.check())
print(s.model())
```

```
sat
[y = 4, x = 6]
```

Здесь `Int` — целое число, `Solver` — объект-солвер, `add` добавляет условия. `check()` возвращает одно из трёх: `sat` (решение есть), `unsat` (нет), `unknown` (солвер сдался). После `sat` модель достают через `s.model()`.

## Шаг 2: решаем наш crackme

Ключевой момент для байтов флага — брать `BitVec` (битовый вектор, машинное слово фиксированной ширины), а **не** `Int`. Причина: в бинарнике байт переполняется по модулю 256, и только `BitVec(…, 8)` воспроизводит это поведение.

```python
from z3 import *
f = [BitVec(f'f{i}', 8) for i in range(4)]
s = Solver()
s.add(f[0] + f[1] == 0x8f)
s.add(f[2] ^ f[3] == 0x10)
for c in f:
    s.add(c >= 0x20, c <= 0x7e)     # печатные символы
print(s.check())
m = s.model()
print(bytes([m[c].as_long() for c in f]))
```

```
sat
b'CTF{'
```

Солвер нашёл подходящий вариант мгновенно — и без перебора. Если флаг длиннее, переменные генерируют циклом, а ограничения добавляют по мере разбора check-функции.

## Шаг 3: почему `Int` здесь — ошибка

Классическая ловушка. Если заменить `BitVec(…, 8)` на `Int`, солвер будет считать `f[0] + f[1]` в обычной (бесконечной) арифметике, без переполнения по модулю 256. Тогда условие может стать нерешаемым (`unsat`) или дать значения больше 255. Для **любой машинной арифметики** — байты, 32-битные регистры — берите `BitVec`.

Аналогично для 32-битной крипто-задачи `y = (x * A + B) mod 2^32`:

```python
x = BitVec('x', 32)
s.add(x * 0x1234567 + 0x89abcdef == 0x0badf00d)
```

Умножение и сложение автоматически переполнятся по модулю `2^32` ровно так, как в бинарнике.

## Шаг 4: читаем `unsat` и `unknown`

Если система нерешаема, ошибка обычно в ограничениях. Включаем ядро нерешаемости:

```python
s.set(unsat_core=True)
s.add(x > 10)   # именованные утверждения помечают противоречие
```

`s.unsat_core()` покажет противоречивое подмножество — так вы найдёте лишнее или неверное условие.

Если солвер вернул `unknown`, чаще всего он «завис» на **нелинейности** (перемножении двух переменных). Лечится так: сузить диапазоны (`0x20..0x7e` для байт), зафиксировать известные константы и поставить таймаут `s.set('timeout', 10000)`.

## Шаг 5: та же идея на другой головоломке — судоку

Приём универсален. Судоку: каждая клетка — `Int` от 1 до 9, а строки, столбцы и блоки 3×3 содержат все цифры по разу. «Все значения разные» выражается предикатом `Distinct`:

```python
cells = [[Int(f'c{i}{j}') for j in range(9)] for i in range(9)]
s = Solver()
for i in range(9):
    for j in range(9):
        s.add(cells[i][j] >= 1, cells[i][j] <= 9)
for i in range(9):
    s.add(Distinct(cells[i]))                          # строки
    s.add(Distinct([cells[j][i] for j in range(9)]))   # столбцы
for bi in range(3):
    for bj in range(3):
        block = [cells[3*bi+r][3*bj+c] for r in range(3) for c in range(3)]
        s.add(Distinct(block))
s.add(cells[0][0] == 5)     # подсказки
print(s.check())            # sat
```

`Distinct`, `Sum`, `If(cond, a, b)` — базовые кирпичи. А если нужно не любое решение, а лучшее, берут `Optimize` и `maximize`/`minimize`.

## Шаг 6: перечисление нескольких решений

У системы ограничений может быть не одно решение. Чтобы получить **следующее**, после `sat` добавьте условие «не равно найденному» и вызовите `check()` снова — так перебираются все варианты:

```python
from z3 import *
x = BitVec('x', 8)
s = Solver()
s.add(x > 0x40, x < 0x45)
while s.check() == sat:
    v = s.model()[x].as_long()
    print(chr(v), end='')
    s.add(x != v)      # исключаем найденное, ищем следующее
# ABCD
```

Этот приём нужен, когда флаг «размазан» по нескольким подходящим вариантам, или когда задача просит «все возможные ключи».

## Шаг 7: если нужно не любое, а лучшее

Иногда требуется не «какое-нибудь» решение, а оптимальное. Тогда вместо `Solver` берут `Optimize` и задают цель:

```python
o = Optimize()
x, y = Ints('x y')
o.add(x + y == 10, x >= 0, y >= 0)
o.maximize(x)
o.check()
print(o.model())   # x = 10, y = 0
```

Это полезно и в задачах на восстановление: «минимизировать число отличий от известного текста».

## Что мы теперь знаем

- Z3 решает задачи вида «неизвестные + ограничения» без перебора; устанавливается `pip install z3-solver`.
- `check()` возвращает `sat` / `unsat` / `unknown`; модель достают через `model()`.
- Для машинных слов (байты, регистры) — только `BitVec`; `Int` не переполняется по модулю.
- Печатность байт задаётся диапазоном `0x20..0x7e` — иначе солвер вернёт случайные байты.
- `Distinct` — «все разные», `Optimize` — оптимум, `unsat_core()` — отладка нерешаемых систем.

## На что смотреть дальше

- **`Int` вместо `BitVec`** — классика реверса; условие молча не сойдётся.
- **Нет ограничений на печатность** — получите нечитаемые байты.
- **`unknown` из-за таймаута** — сузьте диапазоны и уберите нелинейность.
- **Перечисление всех решений** — после `sat` добавьте `s.add(x != old)` и вызовите `check()` снова.
- **Символическое исполнение** — angr под капотом решает те же формулы; понимание `BitVec` делает его предсказуемым.

## Массивы и неинтерпретированные функции

Кроме `Int` и `BitVec` у Z3 есть **массивы** — удобны, когда значение зависит от индекса:

```python
a = Array('a', BitVecSort(8), BitVecSort(8))
s.add(Select(a, 0x10) == 0x41)          # a[0x10] == 'A'
s.add(Store(a, 0x20, 0x42) == a2)       # a2 = a с a[0x20]='B'
```

`Select(a, i)` читает элемент, `Store(a, i, v)` — пишет. Ещё один кирпич — **`Function`**: «чёрный ящик», о котором известно только то, что одинаковый вход даёт одинаковый выход (консистентность). Это позволяет моделировать хеш или шифр, не зная его реализации, и проверять гипотезы о связях входов и выходов.

## Кейс: восстановление seed генератора

Частая CTF-задача: приложение сгенерировало «случайные» числа линейным конгруэнтным генератором `x_{n+1} = (a·x_n + c) mod 2^32`, и по нескольким выходам нужно найти начальный seed или предсказать следующий. Z3 решает это напрямую:

```python
from z3 import *
seed = BitVec('seed', 32)
outs = [BitVec(f'o{i}', 32) for i in range(4)]
s = Solver()
x = seed
for o in outs:
    x = x * 1103515245 + 12345     # переполнение по модулю 2^32 автоматом
    s.add(o == x)
s.add(outs[0] == 0x1a2b3c4d)       # известные выходы
s.add(outs[1] == 0x5e6f7a8b)
print(s.check(), s.model())        # sat: seed = ...
```

Ключ — снова `BitVec(…, 32)`, чтобы переполнение совпало с реальным. Тот же приём ломает «предскажи следующий пароль», «восстанови ключ XOR-генератора» и многие задачи на крипто-слабости.

## Как ускорить солвер

На больших задачах Z3 может «зависнуть». Практические приёмы:

- **Сужайте домены.** `c >= 0x20, c <= 0x7e` вместо свободного байта сокращает пространство на порядки.
- **Убирайте нелинейность.** Произведение двух переменных — самое тяжёлое; если одну из них можно зафиксировать, фиксируйте.
- **Разделяйте на независимые части.** Флаг из двух блоков лучше решать двумя солверами.
- **Ставьте таймаут.** `s.set('timeout', 10000)` возвращает `unknown` вместо бесконечного ожидания.
- **Пробуйте тактики.** `Tactic('qfbv')` или `Then('simplify','solve-eqs','smt')` для чисто битовых задач работают заметно быстрее стандартной стратегии.

Если система всё равно не решается — упростите модель: подозревайте, что перенесли условие из check-функции неточно.
