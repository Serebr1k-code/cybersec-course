## Вопрос, с которого всё начинается

В CTF дают три числа: `n = 1022117`, `e = 17`, `c = 70476` — и говорят, что это «зашифрованное сообщение». Обычный калькулятор тут бесполезен: нужно понимать, что такое модульная арифметика, и почему одни вычисления занимают микросекунды, а другие — часы.

В этом уроке мы расшифруем это сообщение и разберём, какие инструменты делают арифметику больших чисел быстрой и точной.

## Наш пример: три числа от сервиса

```
n = 1022117
e = 17
c = 70476
```

Это параметры схемы **RSA**: `n` — модуль (произведение двух простых), `e` — открытый показатель, `c` — шифртекст. Смысл RSA прост: сообщение `m` шифруется как `c = m^e mod n`, а расшифровывается как `m = c^d mod n`, где `d` — секретный показатель. Наша задача — восстановить `m`, зная слабый (маленький) модуль.

## Шаг 1: почему обычная арифметика ломается

Первая проблема — размер чисел. В языках вроде C или Go `int` имеет фиксированную разрядность (обычно 64 бита), и `2**64` уже переполняет его, «заворачиваясь» в ноль. В Python `int` — **число произвольной точности** (bignum), поэтому переполнения нет:

```python
>>> 2**256
115792089237316195423570985008687907853269984665640564039457584007913129639936
>>> import math; math.factorial(20)
2432902008176640000
```

Можно писать формулы напрямую, и они работают с числами любой длины. Это спасает в большинстве задач.

## Шаг 2: модульная арифметика — сердце крипто-задач

`m^e mod n` означает «возвести в степень и взять остаток от деления на `n`». Считать `m**e` целиком, а потом делить — катастрофа: при больших `e` число не влезет в память. В Python есть трёхаргументный `pow`, который делает это за `O(log e)` шагов, не раздувая число:

```python
>>> pow(2, 1000, 1000000007)
688423210
```

Вторая важная операция — **модульная инверсия**: число `a⁻¹`, такое что `a·a⁻¹ ≡ 1 (mod m)`. В обычной арифметике это `1/a`; по модулю деления нет, есть умножение на обратный элемент. Он существует только при `gcd(a, m) = 1` и считается так (Python 3.8+):

```python
>>> pow(17, -1, 1008)
```

`pow(a, -1, m)` — это и есть инверсия. Именно она даёт секретный показатель `d`.

## Шаг 3: факторизация и восстановление ключа

RSA держится на том, что разложить `n` на простые `p` и `q` трудно. Но наш `n` мал — разложим его:

```python
>>> from sympy import factorint
>>> factorint(1022117)
{1009: 1, 1013: 1}
```

Значит, `p = 1009`, `q = 1013`. Теперь по формуле Эйлера `φ(n) = (p−1)(q−1)`, а секретный показатель `d = e⁻¹ mod φ(n)`. Соберём атаку целиком:

```python
from sympy import factorint
n, e, c = 1022117, 17, 70476
f = factorint(n)                     # {1009: 1, 1013: 1}
p, q = list(f.keys())
phi = (p - 1) * (q - 1)              # 1008 * 1012 = 1020096
d = pow(e, -1, phi)                  # 180017
m = pow(c, d, n)                     # 26729
print(m.to_bytes((m.bit_length() + 7) // 8, 'big'))
```

```
b'hi'
```

Сообщение — `hi`. Обрати внимание на последнюю строку: число `26729` переводится в байты через `to_bytes`, потому что сообщение — это текст, закодированный числом. Ширина в байтах вычисляется из `bit_length()`, округляя вверх до целого числа байт.

Разные случаи требуют разных атак: если `e` мал и сообщение короткое — целочисленный корень (`gmpy2.iroot`); если `p` и `q` близки — атака Ферма; если два модуля имеют общий множитель — `gcd(n1, n2)`. Начни с самой дешёвой проверки: она часто решает задачу за одну строку.

## Шаг 4: точность — float против Decimal/Fraction

Обычные числа с плавающей точкой (`float`) хранят приближение, и это ломает задачи, где нужен точный ответ:

```python
>>> 0.1 + 0.2
0.30000000000000004
```

Для точных вычислений берут `Decimal` (десятичные) или `Fraction` (дроби):

```python
>>> from decimal import Decimal
>>> Decimal('0.1') + Decimal('0.2')
Decimal('0.3')
>>> from fractions import Fraction
>>> Fraction(1, 3) + Fraction(1, 6)
Fraction(1, 2)
```

Если задача просит точную дробь — выводи `Fraction`, она сама сокращает. Если ответ — десятичное число с заданным числом знаков — `Decimal`. И никогда не сравнивай `float` на строгое равенство: сравнивай модуль разности с маленьким эпсилоном.

## Шаг 5: битовые операции и системы счисления

Многие задачи сводятся к битам: XOR с ключом, сдвиги, маски. В Python это встроено:

```python
>>> x = 0b1100
>>> x << 2        # 48
>>> x & 0b1010    # 8
>>> x ^ 0b1111    # 3
>>> x.bit_length()
4
```

XOR обратим сам себе: `a ^ b ^ b == a` — поэтому «XOR с повторяющимся ключом» ломается повторным применением. А для перевода между системами счисления есть `int(s, base)` и `f'{n:x}'`:

```python
>>> int('ff', 16)     # 255
>>> f'{255:x}'        # 'ff'
>>> int('1010', 2)    # 10
```

Комбинаторика тоже считается точно и быстро: `math.comb(n, k)` — «сколькими способами выбрать k из n», `math.factorial` — факториал. Если нужен только остаток по модулю `p`, комбинируй факториалы с модульной инверсией: `comb(n, k) mod p = fact(n) · inv(fact(k)) · inv(fact(n−k)) mod p`. Это стандартный приём в задачах «ответ по модулю 10^9+7»: факториалы и обратные элементы считаются быстро, а результат не раздувается до миллионов цифр.

А для систем сравнений есть готовая функция CRT:

```python
>>> from sympy.ntheory.modular import crt
>>> crt([3, 5, 7], [2, 3, 2])   # x mod 3=2, x mod 5=3, x mod 7=2
(23, 105)
```

## Что мы теперь знаем

1. Python `int` — произвольной точности, переполнения нет.
2. `pow(a, b, m)` — быстрая модульная степень; `pow(a, -1, m)` — модульная инверсия.
3. Слабый RSA ломается факторизацией `n` и восстановлением `d = e⁻¹ mod φ(n)`.
4. Точная арифметика — `Decimal` (десятичные) и `Fraction` (дроби), а не `float`.
5. `int(s, base)` переводит из любой системы счисления; XOR обратим.

## На что смотреть дальше

- **`a**b % m` вместо `pow(a, b, m)`.** Медленно и съедает память на больших `b`.
- **Переполнение при переносе на другой язык.** В C/Go `int` конечен.
- **`float` для точных вычислений.** Используй `Decimal`/`Fraction`.
- **Неверный endian.** `to_bytes(n, 'big')` и `'little'` дают разный результат.
- **Забыть про взаимную простоту.** `pow(a, -1, m)` требует `gcd(a, m) = 1`.
