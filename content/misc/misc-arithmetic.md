## Почему арифметика — отдельная тема

В CTF постоянно встречаются задачи, где «обычная» арифметика ломается: числа не влезают в 64 бита, нужна точность до последнего знака, или требуется модульная арифметика. Языки с фиксированной разрядностью (C, C++, Go) переполняются, а плавающая точка теряет точность. Поэтому важно понимать, когда нужны целые произвольной длины и как ими пользоваться. Цель модуля — научиться быстро и без ошибок считать большие числа и модульные выражения.

## Целые произвольной точности в Python

Python хранит `int` произвольной длины, и это спасает в большинстве задач:

```python
>>> 2**256
115792089237316195423570985008687907853269984665640564039457584007913129639936
>>> 100!
>>> import math; math.factorial(100)
93326215443944152681699238856266700490715968264381621468592963895217599993229915608941463976156518286253697920827223758251185210916864000000000000000000000000
```

Никаких переполнений: просто пишите формулы. Для комбинаторики — `math.comb`, `math.perm`.

## Модульная арифметика

Три ключевые функции:

```python
pow(a, b, m)        # a**b mod m, быстро (O(log b))
pow(a, -1, m)       # модульная инверсия a^-1 mod m (Python 3.8+)
(a * b) % m         # умножение по модулю
```

`pow(a, b, m)` незаменим для RSA и «найди остаток от огромной степени». Никогда не считайте `a**b % m` напрямую для больших `b` — это медленно и жрёт память.

## Крипто-математика вручную

RSA без библиотек:

```python
n = 0xdead...          # modulus
e = 65537
ct = 0xbeef...
# если известна факторизация n = p*q
p, q = ...
phi = (p-1)*(q-1)
d = pow(e, -1, phi)
m = pow(ct, d, n)
print(m.to_bytes((m.bit_length()+7)//8, 'big'))
```

Если `e` маленький и сообщение короткое — попробуйте целочисленный корень (`gmpy2.iroot`). Если `n` маленький — факторизуйте (`sympy.factorint`, `factordb.com`).

## Факторизация и корни

```python
from sympy import factorint
factorint(1234567890123456789)
# {3: 2, 3607: 1, 3803: 1, ...}

import gmpy2
root, exact = gmpy2.iroot(ct, 3)   # кубический корень
```

`gmpy2` быстрее `math` на больших числах и умеет точные корни, что критично для атак на малый показатель.

## Перевод между системами счисления

```python
int('ff', 16)         # 255
hex(255)              # '0xff'
bin(255)              # '0b11111111'
f'{255:x}'            # 'ff'
int('1010', 2)        # 10
```

Для строк из «странных» цифр используйте `int(s, base)`. Для base > 36 — своя реализация.

## Точность: float против Decimal/Fraction

```python
0.1 + 0.2            # 0.30000000000000004
from decimal import Decimal
Decimal('0.1') + Decimal('0.2')   # Decimal('0.3')
from fractions import Fraction
Fraction(1,3) + Fraction(1,6)     # Fraction(1,2)
```

Если задача требует точного ответа «до копейки» или сравнения дробей — берите `Decimal`/`Fraction`. Для «найди значение» с плавающей точкой учитывайте погрешность.

## Битовые операции

```python
x = 0b1100
x << 2        # сдвиг влево
x >> 1        # сдвиг вправо
x & 0b1010    # AND
x | 0b0011    # OR
x ^ 0b1111    # XOR
x.bit_length()
```

Побитовые задачи часто сводятся к XOR с повторяющимся ключом или к маскам. Помните: XOR обратим сам себе (`a ^ b ^ b == a`).

## Типичные ошибки и подводные камни

- **`a**b % m` вместо `pow(a,b,m)`** — медленно и memory-heavy.
- **Переполнение при переносе на другой язык** — в C/Go `int` конечен.
- **`float` для денег/точной арифметики** — используйте `Decimal`.
- **Неверный endian при конвертации** — `to_bytes(n, 'big')` vs `'little'`.
- **Забытая модульная инверсия** — `pow(e,-1,phi)` требует взаимной простоты.
- **Отрицательные модули** — в Python `%` всегда неотрицателен, но в C — нет.
- **Потеря знака** при работе с байтами — используйте `int.from_bytes(..., signed=...)`.

## Быстрые рецепты

# gcd / НОК
import math

## Что дальше / решение

Практический вывод: для любой числовой задачи сначала оцените размер чисел — если они превышают 2^63, используйте Python `int` и `gmpy2`. Для «остатков» и RSA — `pow` с тремя аргументами. Для точной арифметики — `Decimal`/`Fraction`. Держите под рукой `sympy` для факторизации и CRT. Большинство «сложных» числовых задач сводятся к правильному выбору одной-двух функций — ключ в том, чтобы не считать большие степени наивно и не терять точность на float.

## Разбор типичной арифметической задачи

Рассмотрим классику: сервис выдаёт `n`, `e`, `c` и просит расшифровать RSA. Первый шаг — оценить размер `n`. Если он меньше шестидесяти бит, факторизуем напрямую через `sympy.factorint` и восстанавливаем закрытый ключ. Если `e` равен трём и сообщение короткое, пробуем целочисленный кубический корень: `gmpy2.iroot(c, 3)`. Если `n` — это произведение двух близких простых чисел, применима атака Ферма через разность квадратов. Если один и тот же модуль использован с двумя взаимно простыми показателями, работает обобщённая атака через расширенный алгоритм Евклида. Наконец, если модули разные, но общий простой множитель есть, его находят через `gcd` двух модулей.

Этот набор приёмов — базовый «швейцарский нож» для RSA-задач. Важно уметь быстро определить, какой именно случай перед вами, по размеру чисел и по взаимосвязи параметров.

## Точность в задачах на геометрию и вероятности

Отдельный класс задач требует аккуратной работы с рациональными и вещественными числами. Если ответ — точная дробь, используйте `fractions.Fraction`: она автоматически сокращает дроби и не теряет точность. Если ответ — десятичное число с заданным количеством знаков, берите `decimal.Decimal` с нужной точностью и режимом округления. Никогда не сравнивайте вещественные числа на строгое равенство: сравнивайте модуль разности с эпсилоном. Для задач «найди вероятность» часто достаточно вывести дробь, а не десятичную запись, чтобы проверяющая система приняла точный ответ.

## Комбинаторика и большие коэффициенты

Задачи на подсчёт часто сводятся к биномиальным коэффициентам, числам Каталана, перестановкам и разбиениям. Все они считаются в Python точно и быстро: `math.comb`, `math.perm`, `math.factorial`. Если числа огромны, а нужен только остаток по модулю, комбинируйте факториалы с модульной арифметикой, но помните, что деление по модулю требует инверсии: `comb(n,k) mod p = fact(n) * inv(fact(k)) * inv(fact(n-k)) mod p`. Это стандартный приём в задачах, где ответ просят «по модулю 10^9+7».

## Что дальше / решение

Практический план: сначала классифицируйте числовую задачу по размеру чисел и структуре (RSA, комбинаторика, точная арифметика, модульные уравнения), затем выберите соответствующую функцию из `pow`, `sympy`, `gmpy2`, `math`, `fractions`, `decimal`. Не считайте большие степени наивно, не используйте float там, где нужна точность, и не забывайте про модульную инверсию при делении по модулю. Держите под рукой шпаргалку с рецептами — большинство арифметических задач решается комбинацией двух-трёх стандартных вызовов.
