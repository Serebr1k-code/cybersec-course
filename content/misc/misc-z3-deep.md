## Вопрос, с которого всё начинается

В задаче есть функция, которая проверяет флаг серией арифметических и битовых операций, и нужно подобрать вход. Перебор невозможен — пространство огромно. Здесь на помощь приходит **z3** — SMT-решатель, который находит значения переменных, удовлетворяющие заданным условиям. Разберём его на примере.

## Наш пример: подбор входа

Пусть проверка такая:

```python
def check(x):
    return (x * 3 + 7) ^ 0x1234 == 0x5A5A
```

Вместо перебора опишем это в z3:

```python
from z3 import *
x = BitVec('x', 32)
s = Solver()
s.add((x * 3 + 7) ^ 0x1234 == 0x5A5A)
print(s.check())
print(s.model())
```

`check()` вернёт `sat`, `model()` — значение `x`. Решение найдено без перебора.

## Шаг 1: битовые векторы

Для CTF чаще всего нужны `BitVec` фиксированной ширины (8, 16, 32, 64 бита). Они моделируют машинную арифметику с переполнением — именно то, что делает программа. `BitVecVal` задаёт константу.

## Шаг 2: операции

z3 поддерживает обычные и битовые операции: `+`, `-`, `*`, `/`, `%`, `^`, `&`, `|`, `<<`, `>>`, сравнения. Это позволяет дословно перевести проверку из программы в ограничения.

## Шаг 3: массивы и строки

Для байтовых флагов удобно брать массив `BitVec`-ов или `BitVec` из 8 бит на символ. Для строк z3 умеет работать со `String`, но в CTF чаще моделируют флаг как вектор байтов и добавляют ограничения на диапазон печатных символов.

## Шаг 4: ограничения

Ключевой приём — добавлять условия-подсказки: «символы печатные», «флаг начинается с `nto{`». Они резко сокращают пространство поиска и ускоряют решатель:

```python
for i in range(n):
    s.add(flag[i] >= 0x20, flag[i] <= 0x7e)
```

## Шаг 5: решатель и модель

`s.check()` возвращает `sat`/`unsat`/`unknown`. При `sat` `s.model()` даёт значения. Если `unsat` — ограничения противоречивы (проверь, нет ли ошибки в переводе). Если `unknown` — добавь подсказок или таймаут.

## Шаг 6: практический приём — перевод программы

Самый частый сценарий: есть бинарь с функцией проверки. Ты либо реверсишь её и переписываешь в z3 вручную, либо используешь инструменты (angr, z3-плагины), которые делают это автоматически. Ручной перевод надёжнее и понятнее.

## Если не сработало

- `unsat` → ошибка в переводе или лишнее ограничение.
- Долго думает → добавь диапазоны символов, разбей задачу на части.
- `unknown` → упрости ограничения или задай таймаут.

## Частые ошибки

- Использовать Python-целые вместо `BitVec` (теряется переполнение).
- Забыть про ширину переменной.
- Не ограничивать символы печатным диапазоном.

## Что мы теперь знаем

- z3 решает системы ограничений, включая битовые векторы.
- Проверку из программы переводят в ограничения дословно.
- Подсказки (печатные символы, префикс) ускоряют поиск.
- `sat`/`unsat`/`unknown` — три исхода, каждый диагностичен.

## Шаг 7: BitVec против Int

Важно не путать `BitVec` и `Int`. `Int` — математическое целое без переполнения; `BitVec` — машинное слово с обёрткой по модулю `2^n`. Программа работает с `BitVec`-семантикой, поэтому для реверса нужны именно битовые векторы. Если взять `Int`, ты получишь «решение», которое программа никогда не выдаст.

Ширина тоже важна: 32-битная проверка должна моделироваться 32-битными `BitVec`, иначе арифметика с переполнением не совпадёт.

## Шаг 8: массивы и функции

Для флагов удобно:

```python
flag = [BitVec(f'c{i}', 8) for i in range(40)]
```

Затем добавляй ограничения по индексам. Если проверка использует таблицы подстановок, моделируй их как `Array` или как `If`-цепочки. z3 умеет `Select`/`Store` для массивов — это удобно для S-box и таблиц.

## Шаг 9: оптимизация

Решатель может «зависнуть» на большой задаче. Ускоряют его так: сузить диапазоны переменных, добавить известные символы (`nto{`), разбить задачу на независимые части, использовать `s.set('timeout', ms)`. Если проверка посимвольная — решай по одному символу, это на порядки быстрее.

## Шаг 10: пример — проверка флага

Пусть программа для каждого символа делает `out[i] = ((flag[i] << 3) ^ 0x2a) & 0xff` и сравнивает с массивом. В z3: создай `flag[i]`, задай соотношение и равенство известному массиву, ограничь печатными символами, вызови `check()`. Решение — готовый флаг. Это шаблон для большинства «проверок флага» в CTF.

## Шаг 11: z3 и реверс

Связка: реверс даёт логику проверки, z3 — решение. Инструменты вроде angr автоматизируют перевод, но ручной перевод в z3 надёжнее и понятнее: ты контролируешь каждое ограничение и сразу видишь ошибку. Начни с ручного перевода — это лучший способ понять и программу, и решатель.

## Шаг 12: мини-чек-лист z3

- Используешь `BitVec` нужной ширины?
- Учтено переполнение (машинная арифметика)?
- Добавлены подсказки (печатные символы, префикс)?
- Задача не слишком большая (иначе разбей)?
- Проверен результат `check()` (sat/unsat/unknown)?
- Модель проверена на реальной программе?

## Шаг 13: почему SMT, а не перебор

Перебор работает только при крошечном пространстве. Флаг из 20 печатных символов — это 95^20 вариантов, недостижимо. SMT-решатель не перебирает: он строит логическую формулу и ищет модель, используя структуру ограничений. Именно поэтому z3 решает за секунды то, что перебор не решит никогда.

Это ключевая идея: **формулируй задачу как ограничения, а не как перебор**. Как только ты видишь «подбери вход, чтобы проверка прошла», думай про z3.

## Шаг 14: как переводить проверку

Правило простое: каждая операция программы становится операцией z3 той же ширины. `+` → `+`, `^` → `^`, сдвиг → сдвиг, сравнение → ограничение. Условие «проверка истинна» становится `s.add(условие)`. Ничего больше не нужно — решатель сам найдёт значения.

Ошибки в переводе — главный источник `unsat`. Если решатель говорит «противоречие», перепроверь ширину переменных и порядок операций.

## Шаг 15: работа с циклами

Цикл в программе разворачивается в цепочку ограничений: каждая итерация — отдельные выражения. Если цикл длинный, задача становится большой; тогда разбивай её на части или упрощай. Часто цикл обрабатывает символы независимо — тогда решай по одному символу.

## Шаг 16: подсказки как ускоритель

Ограничения-подсказки (`флаг начинается с nto{`, символы печатные) не обязательны логически, но резко ускоряют поиск. Решатель быстрее отсекает невозможные варианты. Всегда добавляй известный формат флага — это бесплатно и очень полезно.

## Шаг 17: отладка модели

Если `sat`, но решение «не проходит» реальную проверку, значит, модель неточна. Прогони найденное значение через настоящую программу и сравни. Расхождение укажет на ошибку перевода (обычно ширина или пропущенная операция). Такой цикл «модель → проверка → исправление» — нормальная часть работы.

## Шаг 18: z3 для других задач

Помимо подбора флага, z3 решает: системы уравнений (крипто), планирование, задачи на графы, раскраску, головоломки (судоку, нонограммы). В CTF его применяют везде, где есть «условия и неизвестные». Это один из самых универсальных инструментов в наборе.

## Шаг 19: ограничения производительности

z3 может «думать» долго на больших задачах. Приёмы ускорения: сузить диапазоны, разбить на подзадачи, использовать `s.set('timeout', ...)`, применять `simplify()`. Иногда проще решить задачу в два этапа: сначала найти структуру, затем — конкретные значения.

## Шаг 20: типичные ошибки

Первая — использовать `Int` вместо `BitVec`. Вторая — забыть про ширину. Третья — не добавлять подсказки и ждать вечно. Четвёртая — не проверять модель на реальной программе. Все четыре — часть освоения инструмента.

## Шаг 21: мини-проект

Возьми бинарь с проверкой флага, реверсни её и переведи в z3. Найди флаг и проверь его на реальном бинаре. Это упражнение объединяет реверс и решение ограничений — ключевая связка для crypto/rev задач.

## Шаг 22: итог

z3 превращает «подбери вход» в «реши систему». Освоив `BitVec`, ограничения и подсказки, ты закрываешь целый класс задач. Помни главное: сначала переведи проверку дословно, затем добавь подсказки и проверь модель на реальной программе.

## Шаг 23: z3 в команде с другими инструментами

z3 — не единственный решатель: есть Boolector, CVC5, Yices. Для CTF z3 удобнее всего из-за Python-API. В связке с реверсом он даёт полный цикл: разобрал логику — перевёл в ограничения — получил вход. Если z3 не справляется, попробуй разбить задачу или сменить решатель.

## Шаг 24: как не утонуть в деталях

Начинай с грубой модели: только ключевые операции. Если `sat` и решение проходит — готово. Если нет — уточняй модель шаг за шагом. Не пытайся перевести всю программу сразу; решай то, что нужно для флага.

## Шаг 25: финальный совет

z3 окупается мгновенно: первая же решённая задача экономит часы перебора. Освой три вещи — `BitVec` нужной ширины, добавление ограничений и подсказки. Дальше всё сводится к аккуратному переводу логики. Помни: если задача звучит как «подбери вход», это задача для z3.

## Шаг 26: частые вопросы

Почему z3 говорит `unknown`? Задача слишком сложная или нелинейная: добавь подсказок, сузь диапазоны, поставь таймаут. Почему решение не проходит на реальном бинаре? Модель неточна — сверь ширину и операции. Почему долго думает? Разбей задачу или упрости ограничения. Все три вопроса — нормальная часть работы с решателем.

## Шаг 27: практический пример — посимвольный подбор

Если проверка обрабатывает символы независимо, решай по одному — это на порядки быстрее:

```python
from z3 import *
flag = []
for i in range(32):
    c = BitVec('c%d' % i, 8)
    s = Solver()
    s.add(transform(c) == expected[i])
    s.add(c >= 0x20, c <= 0x7e)
    if s.check() == sat:
        flag.append(chr(s.model()[c].as_long()))
print(''.join(flag))
```

Разбиение на независимые подзадачи — самый надёжный способ ускорить z3 и обойти таймауты.
