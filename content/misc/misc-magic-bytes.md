## Вопрос, с которого всё начинается

До сих пор мы разбирали файлы, зная их тип. Но самый частый первый шаг в misc — получить файл и **не знать, что это**. Расширение обманывает: `image.png`, внутри которого ZIP; `document.pdf`, внутри которого PNG; файл без расширения, который на самом деле tar.

Опытный игрок не открывает файл в любимом редакторе, а смотрит на **первые байты**. Разберём это на конкретном файле.

## Наш пример: mystery.bin

```bash
$ file mystery.bin
mystery.bin: PNG image data, 400 x 100, 8-bit/color RGBA, non-interlaced
```

`file` говорит: PNG 400×100. Но открываем картинку — она пустая. Что-то не так. Значит, не доверяем одному вердикту.

## Шаг 1: почему расширение — ненадёжно

Операционная система определяет тип файла двумя способами: по **расширению** (для ассоциаций) и по **magic bytes** — нескольким первым байтам, которые однозначно указывают формат. Расширение — это просто часть имени; его меняют одной командой. Поэтому правило номер один: **никогда не доверяй расширению**.

Есть и третий случай — **полиглот**: файл, который одновременно валиден как два формата (например, PNG + ZIP). Такие делают, дописывая один формат в конец другого.

## Шаг 2: `file` с ключом `-k`

Обычный `file` останавливается на первом совпадении. Ключ `-k` («keep going») заставляет его показать **все** найденные форматы — как раз для полиглотов:

```bash
$ file -k mystery.bin
mystery.bin: PNG image data, 400 x 100 ... \012- Zip archive data, at least v2.0
```

Вот оно: файл — и PNG, и ZIP одновременно. Ещё полезен `--mime-type` (даёт MIME для скриптов):

```bash
$ file --mime-type mystery.bin
mystery.bin: image/png
```

## Шаг 3: смотрим байты глазами (`xxd`)

Подтверждаем сигнатуру вручную — hex-дампом:

```bash
$ xxd mystery.bin | head -4
00000000: 8950 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR
00000010: 0000 0190 0000 0064 0806 0000 00ab 5f34  ... ...d......_4
```

Первые восемь байт `89 50 4E 47 0D 0A 1A 0A` — это `\x89PNG\r\n\x1a\n`, сигнатура PNG. Дальше `IHDR` — первый чанк изображения. Аналог с другим форматированием — `hexdump -C`.

## Шаг 4: `binwalk` находит встроенное

`binwalk` сканирует файл по сигнатурам и показывает **встроенные** файлы:

```bash
$ binwalk mystery.bin
DECIMAL       HEXADECIMAL     DESCRIPTION
--------------------------------------------------------------------------------
0             0x0             PNG image, 400 x 100
4096          0x1000          Zip archive data, at least v2.0
```

Вот где спрятано: после PNG, начиная с байта 4096, дописан ZIP. Извлекаем:

```bash
$ binwalk -e mystery.bin
$ ls _mystery.bin.extracted/
4096.zip
```

`binwalk -e` создаёт папку со всеми найденными файлами. Если `binwalk` нет — режем вручную через `dd`:

```bash
$ dd if=mystery.bin of=hidden.zip bs=1 skip=4096
$ unzip hidden.zip
Archive:  hidden.zip
  inflating: flag.txt
$ cat flag.txt
flag{p0lygl0t}
```

## Шаг 5: таблица сигнатур

Держите её под рукой:

| Hex | Формат | Расширение |
|-----|--------|-----------|
| `89 50 4E 47 0D 0A 1A 0A` | PNG | .png |
| `FF D8 FF` | JPEG | .jpg |
| `47 49 46 38` | GIF | .gif |
| `25 50 44 46` | PDF | .pdf |
| `50 4B 03 04` | ZIP (и docx/xlsx/apk/jar) | .zip |
| `1F 8B 08` | gzip | .gz |
| `37 7A BC AF 27 1C` | 7z | .7z |
| `52 61 72 21 1A 07` | RAR | .rar |
| `7F 45 4C 46` | ELF | (linux exe) |
| `4D 5A` | PE/EXE | .exe/.dll |
| `52 49 46 46` | RIFF (WAV/AVI) | .wav/.avi |
| `75 73 74 61 72` | tar (offset 257) | .tar |

Обратите внимание на две тонкости. Первая: сигнатура ZIP (`50 4B 03 04`) одинакова у docx, xlsx, pptx, apk, jar, epub — все это ZIP-контейнеры. Вторая: у tar магия `ustar` лежит **не в начале**, а по смещению 257, поэтому tar не так просто определить по первым байтам.

## Шаг 6: матрёшка — рекурсивное определение

Часто форматы вложены друг в друга. Дано: файл `mystery` без расширения.

```bash
$ file mystery
mystery: data
$ xxd mystery | head -1
00000000: 1f8b 0808 ...
```

Первые байты `1f 8b 08` — gzip. Распаковываем и определяем снова:

```bash
$ mv mystery mystery.gz && gunzip mystery.gz
$ file mystery
mystery: POSIX tar archive
$ tar tvf mystery
-rw-r--r-- 0/0   1234 image.png
-rw-r--r-- 0/0    256 readme.txt
-rw-r--r-- 0/0   4096 secret.zip
```

gzip → tar → внутри PNG и ZIP. Ведите **журнал слоёв**, чтобы не запутаться: каждый раз определяете формат, распаковываете, снова определяете.

## Шаг 7: рабочий порядок действий

Соберём всё в короткий чек-лист, чтобы не метаться:

1. `file mystery` — быстрый вердикт по сигнатуре.
2. `file -k mystery` — все совпадения (для полиглотов).
3. `xxd mystery | head` — подтвердить сигнатуру глазами.
4. `binwalk mystery` — найти встроенные файлы.
5. Нашли вложенное — `binwalk -e` или ручной `dd`.
6. Формат неизвестен — сверить первые байты с таблицей, попробовать `strings`.
7. Полиглот — открывать по частям разными инструментами.

Если сигнатура не в начале (tar, SFX), ищите её поиском по файлу:

```bash
$ grep -abo $'\x89PNG' firmware.bin      # смещение PNG
0:mystery.bin
$ dd if=firmware.bin of=carved.png bs=1 skip=0
```

`grep -abo` печатает **смещение** совпадения, а `-a` заставляет его работать с бинарным файлом. Дальше `dd` вырезает данные от нужного смещения. Для больших файлов берите больший `bs` или `tail -c +N` — `bs=1` медленный.

## Что мы теперь знаем

- Расширению доверять нельзя — тип определяют по magic bytes.
- `file` даёт быстрый вердикт, `file -k` показывает **все** совпадения (для полиглотов).
- `xxd`/`hexdump` позволяют подтвердить сигнатуру глазами.
- `binwalk` находит встроенные файлы; `binwalk -e` извлекает, `dd` режет вручную.
- Многие форматы — ZIP-контейнеры (docx, apk, jar); у tar магия по смещению 257.
- Форматы бывают вложены «матрёшкой» — определяйте рекурсивно и ведите журнал слоёв.

## На что смотреть дальше

- **Открывать файл в просмотрщике** и удивляться, что «не работает» — сначала `file`.
- **Искать сигнатуру только в начале** — tar и SFX-архивы прячут её дальше.
- **Ложные срабатывания `binwalk`** на случайных данных — проверяйте смещения.
- **`grep` без `-a`** не находит бинарные совпадения — используйте `grep -a`.
- **`dd bs=1`** на больших файлах медленный — берите больший `bs` или `tail -c +N`.
- **Регистр байт** в сигнатуре важен: `\x89PNG` — ровно эти байты.

## Контейнеры и вложенные форматы

Часть форматов — это контейнеры, внутри которых лежат другие файлы. Увидев такой
контейнер, нужно не просто определить его тип, а **распаковать** и посмотреть внутрь:

- **ZIP** (`PK\x03\x04`) — самый частый: внутри может быть картинка с секретом,
  исходник или ещё один архив.
- **PDF** (`%PDF`) — допускает встроенные потоки (`/EmbeddedFile`), которые достают
  `pdf-parser` или `pdfdetach`.
- **PNG/JPEG** — могут содержать `tEXt`-чанки или ZIP, приклеенный в конец файла.
- **Свои форматы** — игра, приложение или прошивка со своей сигнатурой в начале.

`binwalk` — основной инструмент: он сканирует файл по всем известным сигнатурам и
показывает смещения найденного. Флаг `-e` сразу извлекает вложенное.

## Когда сигнатуры нет

Не всё опознаётся по `file`. Если формат неизвестен, действуй от структуры:

- **Посмотри на энтропию.** `binwalk -E` покажет график: ровные участки — сжатые
  или зашифрованные данные, «пила» — обычный код или текст.
- **Найди повторяющиеся заголовки.** Одинаковые байты на равных смещениях выдают
  формат записей фиксированного размера.
- **Проверь строки.** `strings -n 6` часто показывает имена полей, пути или версию.
- **Сравни с известным.** Возьми похожий легитимный файл и посмотри, чем он
  отличается — отличие и есть встроенное сообщение.

Помни: расширение и даже `file` могут врать. Истина — в байтах и в структуре.

## Сигнатура в начале — не гарантия

Злоумышленники иногда подделывают первые байты, чтобы `file` ошибся. Полиглот —
файл, валидный сразу для двух форматов (например, ZIP и PNG одновременно). Поэтому
одной сигнатуры мало: сопоставляй её со всей структурой файла и с тем, открывается
ли он реальным парсером.
