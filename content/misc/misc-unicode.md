## Введение

Один и тот же текст можно закодировать разными последовательностями кодпоинтов. Это ломает фильтры, валидацию и сравнение строк. В CTF Unicode прячет данные и обходит проверки, а в веб — помогает обойти WAF. Урок про практические приёмы: нормализация, гомоглифы, невидимые символы, bidi-трюки и обход фильтров.

Ключевая идея: «равенство строк» и «совпадение с шаблоном» зависят от того, нормализованы ли данные. Разработчики часто сравнивают сырые байты, тогда как атакующий подаёт эквивалентную, но иную последовательность.

## Нормализация: NFC/NFD/NFKC/NFKD

Unicode-строку можно представить по-разному: `é` — это либо U+00E9, либо `e` + U+0301 (комбинирующая акутка).

| Форма | Что делает |
|-------|-----------|
| NFC | Каноническая композиция (собирает) |
| NFD | Каноническая декомпозиция (разбирает) |
| NFKC | Совместимостная композиция (упрощает) |
| NFKD | Совместимостная декомпозиция |

```python
import unicodedata
s = "café"
print(unicodedata.normalize("NFC", s) == unicodedata.normalize("NFD", s))  # False!
s2 = "а" + "\u0301"
print(unicodedata.normalize("NFC", s2))   # схлопнется в 'á'
```

Фильтр на подстроку `"admin"` обходится вставкой комбинирующих символов, которые при нормализации схлопываются.

## Гомоглифы (confusables)

Разные символы выглядят одинаково:

```python
"аdmin"  # первая 'а' — кириллическая U+0430
"pаypal" # 'а' кириллическая
"rn"     # визуально как 'm'
```

```python
import unicodedata
def confusable(s):
    return "".join(unicodedata.name(c, "?") for c in s)
print(confusable("аdmin"))
# CYRILLIC SMALL LETTER A, LATIN SMALL LETTER D, ...
```

Гомоглифы используются в фишинговых доменах (IDN), обходе списков запрещённых слов и подделке имён пользователей.

## Невидимые символы

- **Zero-width:** U+200B ZWSP, U+200C ZWNJ, U+200D ZWJ, U+FEFF BOM.
- **Комбинирующие:** U+0301 и другие.
- **Управляющие bidi:** U+202E RLO, U+202D LRO — меняют направление текста.

```python
hidden = "".join("\u200b" if bit=="0" else "\u200c" for bit in "0100110")
bits = ["0" if c=="\u200b" else "1" for c in text if c in "\u200b\u200c"]
```

Bidi-трюк: `"abc\u202Edef"` покажет `abc` + перевёрнутый `def`.

## Разобранный пример: флаг из невидимых символов

**Дано:** строка, выглядящая обычно, но подозрительно длинная.

```python
s = open("text.txt").read()
for c in s:
    if ord(c) > 127 or unicodedata.category(c).startswith("C"):
        print(hex(ord(c)), unicodedata.name(c, "?"))
```

Находим ZWSP/ZWNJ, собираем биты:

```python
bits = "".join("0" if c=="\u200b" else "1" for c in s if c in "\u200b\u200c")
n = int(bits, 2)
print(n.to_bytes((n.bit_length()+7)//8, "big"))
```

Декодируем байты → флаг.

## Обход фильтров и WAF

- **Двойная нормализация:** фильтр и бэкенд нормализуют по-разному.
- **Confusable-домены:** IDN-гомоглифы.
- **Case folding:** `ß` ↔ `ss`, `İ` ↔ `i`.
- **Overlong/неканоничные:** в UTF-8 отклоняются, но в других кодировках дают обход.
- **Точка-гомоглиф:** `http://example。com` (U+3002) нормализуется в `.`.

```python
import unicodedata
print(unicodedata.normalize('NFKC', "http://example。com"))
```

## Частые ошибки и подводные камни

- **Считать разные строки равными:** NFC и NFD не равны без нормализации.
- **Забывать про NFKC:** он меняет даже «похожие» символы (`①` → `1`).
- **Не искать невидимые символы:** они не видны в редакторе.
- **Игнорировать bidi:** управляющие символы меняют порядок и скрывают текст.
- **Путать байты и кодпоинты:** длина строки зависит от представления.
- **Не нормализовать перед сравнением:** корень многих багов валидации.

- Фильтр обходится → пробуем NFD/NFKC, confusables, bidi.
- Скрытые данные → собираем биты из zero-width.
- Смежные уроки: `misc-encoding`, `misc-crypto-misc`.

## Bidi-атаки: Trojan Source

Классическая современная атака — **Trojan Source** (CVE-2021-42574): с помощью bidi-управляющих символов (`U+202E`, `U+2066`…) можно заставить код отображаться в одном порядке, а исполняться в другом. Так можно спрятать уязвимость в коде, которая выглядит безобидно в редакторе.

```python
s = "if access_level != 'user':  # \u202E"
print(repr(s))
# в редакторе может отобразиться иначе, чем реальный порядок символов
```

Для аудита кода: ищите символы категории `Cf` (format) и bidi-controls в исходниках.

```bash
grep -rPn '[\x{202A}-\x{202E}\x{2066}-\x{2069}]' src/
```

## Нормализация в веб-контексте

- **Сравнение имён пользователей:** если приложение не нормализует, `admin` и `аdmin` (кириллица) — разные, но выглядят одинаково → подмена/обман.
- **Обход чёрных списков:** NFKC схлопывает `①`→`1`, `ﬁ`→`fi`, `㊙`→`秘`.
- **Домены:** IDN-гомоглифы обходят фильтры, но браузеры показывают punycode (`xn--…`).

```python
import unicodedata
print(unicodedata.normalize('NFKC', '㊙'))   # '秘'
print(unicodedata.normalize('NFKC', 'ﬁle')) # 'file'
```

## Извлечение и встраивание данных

Zero-width каналы часто кодируют ASCII по 8 бит (ZWSP=0, ZWNJ=1). Полезные операции:

```python
ZW = {'\u200b': '0', '\u200c': '1'}
bits = ''.join(ZW[c] for c in text if c in ZW)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
print(data)
```

Обратная операция — встраивание сообщения в безобидный текст, чтобы оно прошло через редактор/фильтр невидимым.

## Сравнение строк и нормализация: практические правила

- **Перед сравнением** приводите обе строки к одной форме (`NFC` для отображения, `NFKC` для «семантического» сравнения).
- **Перед поиском в чёрном списке** нормализуйте вход (иначе NFKC-обход).
- **Для имён пользователей/доменов** проверяйте, что все символы из одного скрипта.
- **Для логинов** храните и сравнивайте каноническую форму, но отображайте оригинал.

```python
import unicodedata
def canon(s):
    return unicodedata.normalize('NFKC', s).casefold()
print(canon('Admin') == canon('Аdmin'))  # False, но оба 'выглядят' похоже
```

## Типовые CTF-задачи

- **Строка выглядит короче, чем есть** → ищите zero-width/комбинирующие.
- **Фильтр не срабатывает на очевидный payload** → попробуйте NFKC-эквиваленты.
- **Флаг «не влезает»** → он может быть спрятан в невидимых символах.
- **Домен подозрительный** → декодируйте punycode (`xn--`).

## Что дальше

- Держите под рукой `unicodedata` и `confusable_homoglyphs`.
- Всегда проверяйте кодпоинты, а не только визуальный вид.
- Нормализация — и защита, и вектор обхода; смотрите, что делает именно целевое приложение.

## Итоговая шпаргалка

| Симптом | Причина | Действие |
|---------|---------|----------|
| «Похожие» строки не равны | NFC vs NFD | нормализовать |
| Фильтр пропускает payload | NFKC-эквивалент | канонизировать вход |
| Строка длиннее ожидаемого | zero-width | кодпоинты |
| Текст отображается не так | bidi | искать Cf-символы |
| Домен странный | IDN-гомоглиф | punycode |

Держите `unicodedata` под рукой и всегда проверяйте реальные кодпоинты, а не визуальный вид строки.
