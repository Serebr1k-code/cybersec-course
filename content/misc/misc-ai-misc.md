## Вопрос, с которого всё начинается

В прошлых уроках мы атаковали LLM словами. Но в CTF есть и другой класс AI-задач: классические модели машинного обучения — классификаторы картинок, текста, чисел. На странице задачи висит API: отправляешь точку (или картинку) — получаешь метку класса. Никаких исходников модели. Задача — «взломать классификатор»: понять, как он устроен, и заставить ошибиться. Это урок про **adversarial-примеры** и **извлечение модели**.

## Наш пример: чёрный ящик-классификатор

Дано: эндпоинт, который принимает две координаты и возвращает класс — 0 или 1:

```
$ curl -s 'https://classifier.ctf/predict?x=1.0&y=0.5'
{"label": 1, "class": "A"}
```

Внутри — линейная модель: она считает **логит** (взвешенную сумму входов) и сравнивает с порогом. Формула `logit = w1·x + w2·y + b`; если логит больше нуля — класс 1, иначе 0. Веса `w1, w2` и смещение `b` — секрет, который нам и нужен. Модель, доступную только по входам-выходам, называют **чёрным ящиком**.

## Шаг 1: что именно мы хотим получить

Цель атаки зависит от задачи. В CTF обычно одно из трёх:

- **adversarial** — найти вход, который модель уверенно относит к нужному классу (например, «пусть флаг-класс сработает»);
- **model extraction** — восстановить модель по её ответам, чтобы затем атаковать локально;
- **membership inference** — определить, входил ли объект в обучающую выборку.

Мы пойдём по пути extraction: восстановим границу решения, а потом сломаем её adversarial-примером.

## Шаг 2: извлекаем модель запросами

Каждый запрос к API даёт одну метку — это слабый сигнал, но запросов можно сделать сотни. Собираем датасет из случайных точек с их метками и обучаем **суррогатную модель** (заменитель) на этих парах:

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

np.random.seed(1)
w_true, b_true = np.array([0.8, -0.6]), 0.1
def api(x): return int(x @ w_true + b_true > 0)   # чёрный ящик

X = np.random.uniform(-2, 2, size=(400, 2))
y = np.array([api(x) for x in X])

clf = LogisticRegression().fit(X, y)
print("true w,b :", w_true, b_true)
print("surrogate:", np.round(clf.coef_[0], 3), round(float(clf.intercept_[0]), 3))
```

```
true w,b : [ 0.8 -0.6] 0.1
surrogate: [ 4.657 -3.377] 0.554
```

Коэффициенты суррогата — это положительный множитель (~5.7) к истинным: **граница решения та же**, просто масштаб другой. Проверим на свежих точках:

```python
X2 = np.random.uniform(-2, 2, size=(200, 2))
pred = clf.predict(X2); true = [api(x) for x in X2]
print("agreement:", round(float(np.mean(pred == true)), 3))
```
```
agreement: 1.0
```

Суррогат повторяет чёрный ящик на 100% свежих точек. Так **model extraction** превращает недоступную модель в локальную копию, которую можно ломать без rate-limit.

## Шаг 3: adversarial-пример — обманываем модель

Теперь у нас есть локальная копия. **Adversarial-пример** — это вход, отличающийся от нормального на незаметную мелочь, но меняющий предсказание. Для линейной модели работает **FGSM** (Fast Gradient Sign Method): делаем один шаг в сторону, увеличивающую ошибку.

Считаем градиент функции потерь по входу. Для логистической потери при истинном классе 1 градиент равен `(p − 1)·w`, где `p` — предсказанная вероятность класса 1:

```python
import numpy as np
w, b = np.array([1.0, -1.0]), 0.0
def model(x): return x @ w + b
def prob(x):  return 1 / (1 + np.exp(-model(x)))

x = np.array([1.0, 0.5])          # истинный класс 1
p = prob(x); grad = (p - 1) * w   # градиент по входу
eps = 1.0
x_adv = x + eps * np.sign(grad)   # шаг FGSM
print("clean:", round(float(model(x)), 4), "p1:", round(float(prob(x)), 4))
print("adv  :", round(float(model(x_adv)), 4), "p1:", round(float(prob(x_adv)), 4))
```

```
clean: 0.5 p1: 0.6225
adv  : -1.5 p1: 0.1824
prediction clean: 1 adv: 0
```

Метка перевернулась: класс 1 стал классом 0. Для картинок то же самое делают в пикселях — возмущение `eps·sign(grad)` визуально незаметно, но ломает классификатор. Против сильных моделей используют итеративный **PGD** (projected gradient descent) и методы для чёрного ящика (по запросам, эволюционные).

## Шаг 4: отравление и бэкдор

Иногда задача показывает модель, обученную на **отравленных данных** с «триггером»: при определённом слове или паттерне она ведёт себя иначе. Цель — найти триггер. Признак бэкдора — резкая смена поведения на «странной» последовательности:

```
$ curl -s 'https://classifier.ctf/predict?x=1.0&y=0.5'      → {"label": 1}
$ curl -s 'https://classifier.ctf/predict?x=1.0&y=0.5&t=42' → {"label": 0}   # триггер!
```

Ищите редкие токены, специфичные эмодзи, «невидимые» поля. Отравление опасно тем, что при обычном тестировании модель работает нормально — дефект проявляется только с триггером.

## Шаг 5: membership inference

**Membership inference** отвечает на вопрос «был ли этот объект в обучающей выборке». Модель обычно **увереннее** на данных, которые видела: меньше perplexity, выше вероятность, стабильнее ответ. Приёмы:

- сравнить вероятности для «своих» и «чужих» примеров и построить порог;
- использовать shadow-модели (обученные на похожих данных) для калибровки;
- попросить модель «повторить текст дословно» — если повторит, вероятно, он в датасете.

В CTF это обычно формулируют так: «определите, какой из двух секретов попал в датасет».

## Если не сработало

Задачи на модели редко дают «чистый» чёрный ящик. Разберём, что мешает и как обойти.

**Запросов мало, лимит не даёт собрать выборку.** Извлечение модели требует тысяч запросов. Обходим лимит: разные сессии, разные IP через прокси, разнесение по времени. Если лимит жёсткий — используй *активную* стратегию: выбирай запросы у границы решения, где неопределённость максимальна, чтобы получить больше информации за меньшее число обращений.

**Adversarial-пример не переносится.** FGSM и другие градиентные атаки на чёрном ящике заменяются **transfer attack**: обучи свою суррогатную модель на перехваченных парах вход-выход, посчитай градиент по ней и перенеси возмущение на целевую. Также работают query-based методы (Boundary attack) — они двигают вход к границе решения.

**Шум невидим на глаз, но модель его игнорирует.** Ограничение по норме (L-бесконечность, L2) может быть слишком жёстким, а препроцессинг цели (ресайз, JPEG) — «смывать» возмущение. Настраивай под препроцессинг цели и увеличивай бюджет возмущения до порога заметности.

**Model extraction даёт неточную копию.** Проверь **fidelity** (совпадение с целью) и **accuracy** (качество самой копии). Иногда достаточно точности по одному классу — например, чтобы обойти проверку на «свой/чужой».

**Membership inference не различает.** Смотри, нет ли переобучения: у обучающих примеров уверенность модели обычно выше. Сравнивай распределения уверенности на «членах» и «не-членах», а не отдельные значения.

## Частые вопросы

**Зачем извлекать модель?** Копия даёт бесплатные запросы (без лимитов), позволяет искать adversarial-примеры и, если модель ценна, сама является активом. В CTF — чтобы найти вход, дающий нужный класс.

**Что такое adversarial-пример?** Вход, отличающийся от обычного почти незаметно, но классифицируемый иначе. Классика — наклейка на знак «стоп», из-за которой модель видит «ограничение 80».

**Чёрный ящик — это только API?** Да. Ты видишь лишь вход и выход (иногда с вероятностями). Всё остальное — веса, архитектура — скрыто, и его приходится восстанавливать по поведению.

**Отравление данных и бэкдор — одно и то же?** Бэкдор — частный случай отравления: в обучающие данные подмешивают примеры с «триггером», и модель начинает ошибаться только при его появлении.

## Как строить атаку на модель

Сначала определи *цель*: обойти классификацию, извлечь модель, узнать членство примера в обучающем наборе или найти бэкдор. От цели зависит метод. Для обхода — adversarial-примеры (нужен доступ к градиентам) или query-based атаки (только к выходу). Для извлечения — активное обучение суррогата. Для членства — анализ распределения уверенности.

Всегда измеряй бюджет запросов и ограничения API. Многие задачи ограничивают число обращений — тогда важнее *качество* запросов (точки у границы решения), чем количество. И не забывай про препроцессинг: возмущение должно выживать после ресайза и сжатия, иначе оно бесполезно. Для CTF часто достаточно восстановить поведение модели на узком подмножестве входов, а не всю сеть.

## Что мы теперь знаем

- **Чёрный ящик** — модель, доступная только по входам и выходам.
- **Model extraction** восстанавливает модель по её ответам: суррогат повторяет границу решения.
- **Adversarial-пример** (FGSM/PGD) меняет предсказание малым возмущением входа.
- **Отравление** встраивает в модель триггер-бэкдор: поведение меняется только на нём.
- **Membership inference** определяет, входил ли объект в обучающую выборку.

## На что смотреть дальше

Дальше полезны инструменты: `foolbox` и `adversarial-robustness-toolbox` — для adversarial-примеров на картинках, `textattack` — для текста, `garak` — для сканирования LLM. Отдельно изучи **форматы моделей**: загрузка `.pkl`/`pickle` может выполнить произвольный код, поэтому «модель» из задачи иногда оказывается просто сериализованным эксплойтом. И помни про каналы вывода: длина ответа, время генерации и наличие поля тоже несут информацию.
