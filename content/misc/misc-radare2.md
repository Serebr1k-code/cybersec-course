## Вопрос, с которого всё начинается

Тебе дали бинарник `check`. Он просит пароль, и надо понять, какой. Запускать и перебирать — долго. Нужен инструмент, который покажет структуру: какие есть функции, где сравнение, что лежит в памяти. **radare2** — консольный фреймворк для реверса, который даёт всё это командами. Как им пользоваться?

## Наш пример: сессия radare2

Вот лог разбора:

```
$ r2 ./check
[0x00001060]> aaa
[x] Analyze all flags starting with sym. and entry0
[0x00001060]> afl
0x00001189  1  33  sym.check
0x000011c9  1  23  main
[0x00001060]> pdf @ sym.check
```

Команда `aaa` проанализировала бинарник, `afl` показала функции, `pdf` — дизассемблер выбранной. Разберём команды по порядку.

## Шаг 1: открыть файл

`r2 ./check` открывает бинарник и даёт приглашение `[адрес]>`. Ты внутри — но анализа ещё нет. radare2 — это «консоль», где каждая команда начинается с буквы и может иметь продолжения: `a` — анализ, `p` — печать, `i` — информация.

## Шаг 2: автоматический анализ

```
[0x00001060]> aaa
```

`aaa` запускает анализ: находит функции, ссылки, строки, переименовывает символы. Это самый частый первый шаг. Без него список функций будет пустым.

## Шаг 3: список функций

```
[0x00001060]> afl
0x00001189  1  33  sym.check
0x000011c9  1  23  main
```

`afl` (analyze function list) печатает адрес, размер и имя каждой функции. Видно `sym.check` — вероятно, проверка пароля. Это карта: куда смотреть.

## Шаг 4: дизассемблер

```
[0x00001060]> pdf @ sym.check
```

`pdf` (print disassembly function) печатает тело функции. Знак `@` означает «по адресу/имени» — так указывают цель. В выводе ты ищешь сравнения (`cmp`, `strcmp`) и ветвления — там логика проверки.

## Шаг 5: hex, строки и данные

- `px 64 @ 0x...` — hex-дамп 64 байт по адресу;
- `iz` — строки в бинарнике (аналог `strings`);
- `ps` — строка по адресу;
- `s 0x...` — «перейти» (seek) на адрес, чтобы все команды работали относительно него.

Эти команды заменяют `xxd`, `strings` и `grep` внутри сессии.

## Шаг 6: навигация и граф

- `s main` — перейти к `main`;
- `VV` — визуальный режим (граф);
- `V` — визуальный hex/дизасм;
- `q` — выход из режима, `q` в приглашении — выход из r2.

Визуальный режим полезен, когда функция большая: видно ветвления как блоки.

## Шаг 7: rizin — форк

**rizin** — форк radare2 с совместимым набором команд. Синтаксис почти тот же (`aaa`, `afl`, `pdf`), поэтому навык переносится. В некоторых дистрибутивах rizin ставят вместо r2.

## Шаг 8: скриптинг

radare2 можно автоматизировать: `r2 -c 'aaa; afl' ./check` выполняет команды и выходит, а `-A` запускает анализ сразу. Для пакетного разбора это удобнее интерактива.

## Шаг 9: практический порядок

1. `r2 ./file` — открыть.
2. `aaa` — проанализировать.
3. `afl` — увидеть функции.
4. `pdf @ <func>` — читать интересную.
5. `iz` / `px` — данные и строки.
6. `s` + `VV` — навигация и граф.

## Что мы теперь знаем

- radare2 — консольный фреймворк анализа бинарников.
- `aaa` анализирует, `afl` перечисляет функции, `pdf` дизассемблирует.
- `iz`, `px`, `ps` заменяют `strings`/`xxd` внутри сессии.
- `s` переходит по адресу, `VV` — граф.
- rizin — совместимый форк; r2 скриптуется флагами `-c` и `-A`.
