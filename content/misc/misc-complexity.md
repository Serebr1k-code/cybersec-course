## Вопрос, с которого всё начинается

В прошлом уроке мы проверяли гипотезу жадности. Но бывает иначе: алгоритм **логически верный**, а флаг всё равно не получить — потому что он не успевает. Сервис или проверяющая система даёт на решение ограниченное время, и наивный код в него не укладывается.

Как по одному числу в условии понять, какое решение «влезет»? Разберём это на конкретной задаче, которая сначала падает по времени.

## Наш пример: есть ли пара с суммой S

Условие: дан массив из `n = 200000` целых чисел и число `S`. Ответьте, найдутся ли два элемента, дающих в сумме ровно `S`. Лимит времени — **1 секунда**.

Первое, что пишет новичок, — двойной цикл по всем парам:

```python
def has_pair_slow(a, S):
    for i in range(len(a)):
        for j in range(i+1, len(a)):
            if a[i] + a[j] == S:
                return True
    return False
```

Логика верная. Но давайте измерим:

```python
import time
a = list(range(20000))          # для начала «всего» 20000
t = time.perf_counter()
print(has_pair_slow(a, 39997))
print("slow", round(time.perf_counter() - t, 3))
```

```
True
slow 1.42
```

Двадцать тысяч элементов — уже 1.42 секунды. А в задаче их **двести тысяч**. Значит, полное решение займёт часы. Наивный алгоритм провален, хотя он «правильный».

## Шаг 1: O-нотация — язык, на котором об этом говорят

Чтобы понять это *до* запуска, используют **O-нотацию**: она описывает, как растёт число операций при росте входа, отбрасывая константы.

| Класс | Пример | При `n = 10^6` |
|-------|--------|----------------|
| `O(1)` | доступ к элементу массива | мгновенно |
| `O(log n)` | бинарный поиск | ~20 |
| `O(n)` | один проход | 10^6 |
| `O(n log n)` | сортировка | ~2·10^7 |
| `O(n²)` | двойной цикл | 10^12 (слишком) |
| `O(2^n)` | перебор подмножеств | нереально |

Наш двойной цикл — `O(n²)`: при `n = 200000` это `4·10^10` операций. Даже миллиард операций в секунду не спасёт.

## Шаг 2: таблица бюджетов — по `n` сразу выбираем сложность

Ориентир для лимита ~1–2 секунды:

| Размер входа `n` | Допустимая сложность |
|------------------|----------------------|
| `≤ 10` | `O(n!)`, полный перебор |
| `≤ 20` | `O(2^n)` |
| `≤ 500` | `O(n³)` |
| `≤ 5000` | `O(n²)` |
| `≤ 10^6` | `O(n log n)` |
| `≤ 10^8` | `O(n)` |

Наш `n = 200000` попадает в строку `≤ 10^6` → нужен `O(n log n)` или лучше. Двойной цикл запрещён. Это чтение ограничения и есть навык: **число в условии подсказывает алгоритм**.

## Шаг 3: убираем квадрат хеш-таблицей

Идея: проходим массив один раз, а по дороге запоминаем уже встреченные числа в **множестве** (`set` — структура с поиском за `O(1)` в среднем). Для текущего `x` проверяем, встречалось ли `S - x`:

```python
def has_pair_fast(a, S):
    seen = set()
    for x in a:
        if S - x in seen:
            return True
        seen.add(x)
    return False

a = list(range(20000))
t = time.perf_counter()
print(has_pair_fast(a, 39997))
print("fast", round(time.perf_counter() - t, 3))
```

```
True
fast 0.002
```

Было `O(n²)`, стало `O(n)`. Разница на три порядка — ровно то, чего не хватало наивному решению. Проверка «встречалось ли раньше» вместо «перебрать все пары» — типовой приём.

## Шаг 4: измеряем и профилируем

Не оптимизируйте вслепую — сначала измерьте. Простой таймер мы уже применили. Для большого скрипта есть профилировщик:

```bash
$ python -m cProfile -s cumtime solve.py | head -20
```

Он покажет самые «дорогие» функции. Чаще всего узкое место — скрытый квадрат: `x in list` внутри цикла (это `O(n)` на каждую проверку), конкатенация строк `s += x` в цикле (тоже `O(n²)`), повторный пересчёт одного и того же.

## Шаг 5: арсенал стандартных оптимизаций

| Приём | Было | Стало |
|-------|------|-------|
| `set`/`dict` вместо `list` для поиска | O(n²) | O(n) |
| сортировка + два указателя | O(n²) | O(n log n) |
| префиксные суммы | O(n) на запрос | O(1) |
| скользящее окно | O(n·k) | O(n) |
| мемоизация | O(2^n) | O(n·states) |
| `deque` вместо `list.pop(0)` | O(n) | O(1) |

Отдельно запомните **амортизированную сложность**: `append` в динамический массив суммарно линеен (редкие расширения «размазываются» по множеству дешёвых добавлений), а вот `insert(0, x)` сдвигает весь массив и даёт `O(n)` за операцию. Для очереди слева берите `collections.deque`.

## Шаг 6: амортизированная сложность и память

Не всякая операция стоит одинаково. `append` в динамический массив обычно `O(1)`, но иногда расширение копирует весь массив за `O(n)`. Усредняя по всем операциям, получаем `O(1)` **амортизированно** — редкие дорогие шаги «размазываются» по множеству дешёвых.

Практический вывод: `append` в цикле не бойтесь — суммарно это `O(n)`. Но осторожно с `insert(0, x)` в списке: он сдвигает весь массив и даёт `O(n)` на операцию. Для очереди слева берите `deque`:

```python
from collections import deque
q = deque(range(100000))
q.popleft()   # O(1), в отличие от list.pop(0) — O(n)
```

Отдельно есть **сложность по памяти**. Массив из `10^9` чисел в память не влезет, поэтому обрабатывают потоково:

```python
with open('huge.txt') as f:
    for line in f:      # O(1) памяти — строка за строкой
        process(line)
```

Генераторы (`yield`) и построчное чтение дают `O(1)` памяти вместо `O(n)`.

## Что мы теперь знаем

- По размеру входа `n` сразу выбираем допустимую сложность — двойной цикл при `n = 200000` не проходит.
- `O(n²)` заменяется на `O(n)` хеш-таблицей, `O(n log n)` — сортировкой с двумя указателями.
- Измеряем (`time.perf_counter`) и профилируем (`cProfile`) **до** оптимизации.
- Скрытые квадраты: `x in list`, `s += x` в цикле, `list.pop(0)`.
- Память тоже ограничена: потоки и генераторы вместо загрузки всего в список.

## На что смотреть дальше

- **`x in list` внутри цикла** — самый частый скрытый `O(n²)`; замените на `set`.
- **Конкатенация строк** — собирайте список и делайте `"".join(...)`.
- **Рекурсия без мемоизации** — экспоненциальное дерево вызовов (классика — числа Фибоначчи).
- **Игнорирование константы** — иногда `O(n log n)` на Python проигрывает `O(n)` на numpy.
- **Память** — генератор `yield` и построчное чтение файла дают `O(1)` памяти.

## Справочная таблица структур

| Нужно | Структура | Сложность |
|-------|-----------|-----------|
| Быстрый поиск/дедуп | `set` / `dict` | O(1) средн. |
| Минимум/максимум | `heapq` | O(log n) |
| Очередь с двух концов | `deque` | O(1) |
| Поиск в отсортированном | `bisect` | O(log n) |
| Сумма на отрезке | префиксные суммы | O(1) запрос |
