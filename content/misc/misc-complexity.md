## Зачем оценивать сложность

В задачах категории programming флаг получают за корректное и **достаточно быстрое** решение. Часто наивный алгоритм верен логически, но не проходит: при `n = 10^6` перебор пар (`O(n²)`) — это `10^12` операций, то есть часы. Умение по ограничению на размер входа сразу выбрать асимптотику — ключевой навык.

## O-нотация на пальцах

`O(f(n))` описывает, как растёт число операций с размером входа, отбрасывая константы:

| Класс | Пример | При `n = 10^6` |
|-------|--------|----------------|
| `O(1)` | доступ к элементу массива | мгновенно |
| `O(log n)` | бинарный поиск | ~20 |
| `O(n)` | один проход | 10^6 |
| `O(n log n)` | сортировка | ~2·10^7 |
| `O(n²)` | двойной цикл | 10^12 (слишком) |
| `O(2^n)` | перебор подмножеств | нереально |

## Таблица бюджетов: n и допустимая сложность

Ориентир для типичного лимита ~1–2 секунды на Python/Go:

| Размер входа `n` | Допустимая сложность |
|------------------|----------------------|
| `≤ 10` | `O(n!)`, полный перебор |
| `≤ 20` | `O(2^n)` |
| `≤ 500` | `O(n³)` |
| `≤ 5000` | `O(n²)` |
| `≤ 10^6` | `O(n log n)` |
| `≤ 10^8` | `O(n)` |

Если ограничение `n ≤ 200`, а решение `O(n²)` — скорее всего, этого хватит. Если `n ≤ 10^5`, ищите `O(n log n)`.

## Как читать ограничения

- **Размер массива.** `n ≤ 10^5` — явный намёк на сортировку/хендмэп.
- **Диапазон значений.** Небольшой диапазон (`≤ 10^6`) намекает на массив-счётчик.
- **Число тестов.** Если тестов много, важен не только алгоритм, но и константа.
- **Ответ по модулю.** Значит, есть арифметика больших чисел — нужны быстрые модульные операции.

## Типичные оптимизации

- **Заменить вложенный цикл на хеш-таблицу.** Поиск пары с суммой `S`: вместо `O(n²)` — один проход с `set` (`O(n)`).
- **Сортировка + два указателя.** Вместо перебора — `O(n log n)`.
- **Префиксные суммы.** Запросы суммы на отрезке — `O(1)` вместо `O(n)`.
- **Скользящее окно.** Максимум/минимум на окне — `O(n)`.
- **Куча / deque.** Динамический минимум/максимум.
- **numpy-векторизация.** Массовые операции вместо Python-циклов дают ускорение в десятки раз.
- **Кэш/мемоизация.** Рекурсию по перекрывающимся подзадачам превращаем в ДП.

## Профилирование

Не оптимизируйте вслепую — измеряйте.

```bash
python -m cProfile -s cumtime solve.py | head -20
```

```python
import time
t = time.perf_counter()
# ... тяжёлый участок ...
print("elapsed", time.perf_counter() - t)
```

`cProfile` покажет самые «дорогие» функции; чаще всего узкое место — вложенный цикл или неявный `O(n²)` из-за `list.index`/`in`.

## Разобранный пример: от O(n²) к O(n)

Задача: найти, есть ли в массиве два числа с суммой `S`.

Наивно:

```python
def has_pair_slow(a, S):
    for i in range(len(a)):
        for j in range(i+1, len(a)):
            if a[i] + a[j] == S:
                return True
    return False
```

Быстро:

```python
def has_pair_fast(a, S):
    seen = set()
    for x in a:
        if S - x in seen:
            return True
        seen.add(x)
    return False

import time
a = list(range(20000))
t = time.perf_counter(); has_pair_slow(a, 39997); print("slow", round(time.perf_counter()-t, 3))
t = time.perf_counter(); has_pair_fast(a, 39997); print("fast", round(time.perf_counter()-t, 3))
```

```
slow 1.42
fast 0.002
```

Разница на три порядка — именно её и не хватает наивному решению на реальном тесте.

## Частые ошибки и подводные камни

- **`x in list` внутри цикла.** Это `O(n)` на каждую проверку → `O(n²)`. Используйте `set`.
- **Конкатенация строк в цикле.** `s += x` даёт `O(n²)`; собирайте список и делайте `"".join`.
- **Рекурсия без мемоизации.** Экспоненциальное дерево вызовов — классика Fibonacci.
- **Игнорирование константы.** Иногда `O(n log n)` на Python проигрывает `O(n)` на numpy.
- **Оптимизация не того места.** Профилируйте до, а не после.

## Справочная таблица

| Приём | Было | Стало |
|-------|------|-------|
| set/dict вместо list | O(n²) | O(n) |
| сортировка + два указателя | O(n²) | O(n log n) |
| префиксные суммы | O(n) на запрос | O(1) |
| скользящее окно | O(n·k) | O(n) |
| мемоизация | O(2^n) | O(n·states) |
| numpy | O(n) Python | O(n) C-вектор |

## Что дальше / решение

1. Прочитайте ограничение `n` и оцените допустимую сложность по таблице.
2. Если наивное решение не влезает — ищите стандартный приём (хеш, сортировка, префиксы).
3. Измерьте время на максимальном входе.
4. Профилируйте узкое место и оптимизируйте только его.
5. Если и это мало — векторизуйте (numpy) или перепишите горячий цикл.

## Амортизированная сложность

Не всякая операция стоит одинаково. В динамическом массиве `append` обычно `O(1)`, но иногда расширение копирует весь массив за `O(n)`. Если усреднить по всем операциям, получается `O(1)` **амортизированно** — редкие дорогие шаги «размазываются» по множеству дешёвых. Тот же принцип у `dict`/`set` в Python и у кучи.

Практический вывод: не бойтесь `append` в цикле — суммарно это `O(n)`, а не `O(n²)`. Но осторожно с `insert(0, x)` в списке: он сдвигает весь массив и даёт `O(n)` на операцию. Для очереди слева используйте `collections.deque` с `O(1)` на `popleft`.

```python
from collections import deque
q = deque(range(100000))
q.popleft()   # O(1), в отличие от list.pop(0) — O(n)
```

## Память и сложность по памяти

Сложность бывает не только по времени, но и по памяти. В CTF ограничение по памяти встречается реже, но оно есть: массив из `10^9` чисел не влезет. Тогда применяют потоки, генераторы и внешнюю сортировку.

```python
# вместо list(range(10**9)) — генератор
def stream(n):
    for i in range(n):
        yield i
```

`yield` не хранит весь диапазон в памяти — важно при обработке больших файлов построчно:

```python
with open("huge.txt") as f:
    for line in f:      # O(1) памяти
        process(line)
```

## Практика: разбор трёх задач

**Задача 1. Подсчёт частот.** `n = 10^6` слов, найти топ-10. Решение: `collections.Counter` (один проход, `O(n)`) и `most_common(10)`. Наивный `list.count` для каждого слова — `O(n²)`.

**Задача 2. Дубликаты.** Есть ли повтор в массиве. Решение: `set` за `O(n)`. Сортировка за `O(n log n)` тоже сойдёт, но медленнее.

**Задача 3. Префиксные суммы.** Много запросов «сумма на отрезке `[l, r]`». Решение: один проход строит `pref[i] = pref[i-1] + a[i]`, затем ответ `pref[r] - pref[l-1]` за `O(1)`.

```python
def prefix(a):
    p = [0]*(len(a)+1)
    for i, x in enumerate(a):
        p[i+1] = p[i] + x
    return p

p = prefix([1,2,3,4])
print(p[3]-p[1])   # сумма a[1..2] = 2+3 = 5
```

## Как выбрать структуру данных

| Нужно | Структура | Сложность |
|-------|-----------|-----------|
| Быстрый поиск/дедуп | `set` / `dict` | O(1) средн. |
| Минимум/максимум | `heapq` | O(log n) |
| Очередь с двух концов | `deque` | O(1) |
| Сортированные данные | `bisect` | O(log n) поиск |
| Префиксные суммы | список | O(1) запрос |
| Диапазонные минимумы | sparse table / segtree | O(1)/O(log n) |

## Частые вопросы по оптимизации

- **Как понять, что решение слишком медленное?** Оцените число операций: `n²` при `n = 10^5` — это `10^10`, не пройдёт.
- **Что делать с медленным Python-циклом?** Векторизуйте через numpy или переносите горячий код в C-функцию.
- **Помогает ли PyPy?** Да, для чистых Python-циклов ускорение в разы.
- **Когда `O(n log n)` хуже `O(n)`?** Когда `O(n)` — на C (numpy), а `O(n log n)` — на Python.

## Мини-шпаргалка по сложности

Ориентиры: `n ≤ 20` — перебор; `n ≤ 5000` — `O(n²)`; `n ≤ 10^6` — `O(n log n)`; `n ≤ 10^8` — `O(n)`. Ускоряйте так: `set`/`dict` вместо `list` для поиска, `deque` вместо `list.pop(0)`, префиксные суммы для запросов на отрезке, скользящее окно вместо пересчёта, мемоизация вместо рекурсии, numpy вместо Python-цикла. Измеряйте время (`perf_counter`) и профилируйте (`cProfile`) до оптимизации. Помните про амортизированную сложность: `append` в цикле суммарно линеен, а вот `insert(0, x)` — квадратичен.

## Итог по сложности

Главный навык — по ограничению `n` мгновенно отсекать неподходящие асимптотики и заменять наивные конструкции стандартными приёмами: `set`, `deque`, префиксные суммы, скользящее окно, мемоизация. Сначала измерьте, потом оптимизируйте: профилирование показывает реальное узкое место, которое почти всегда оказывается скрытым квадратом (`x in list`, конкатенация строк, повторный пересчёт).
