## Что такое вычислительная геометрия

Вычислительная геометрия — это алгоритмы над точками, отрезками и многоугольниками. В CTF она встречается в задачах вида «дано N точек, найди…»: периметр выпуклой оболочки, площадь многоугольника, пересекается ли отрезок со стеной, попадает ли точка внутрь фигуры, ближайшая пара точек. Ключевая сложность — не формулы, а **точность** и **выбор асимптотики**.

## Базовые примитивы: точки, векторы, произведения

Все построения держатся на двух операциях над векторами.

- **Скалярное произведение** `dot(a, b) = ax*bx + ay*by` — проекция, косинус угла.
- **Векторное (косое) произведение** `cross(a, b) = ax*by - ay*bx` — знак показывает ориентацию.

Знак `cross(a, b)`:

- `> 0` — поворот влево (против часовой),
- `< 0` — поворот вправо (по часовой),
- `= 0` — векторы коллинеарны.

Если координаты целые, `cross` целочислен и **точен** — это спасает от ошибок округления.

## Ориентация и пересечение отрезков

Ориентация точки `c` относительно направленного отрезка `a→b`:

```python
def cross(o, a, b):
    return (a[0]-o[0])*(b[1]-o[1]) - (a[1]-o[1])*(b[0]-o[0])

def orient(a, b, c):
    v = cross(a, b, c)
    return 0 if v == 0 else (1 if v > 0 else -1)  # 0 коллинеарны, 1 влево, -1 вправо
```

Отрезки `AB` и `CD` пересекаются, если ориентации взаимно противоположны и точки лежат на своих отрезках:

```python
def on_segment(a, b, p):
    return min(a[0],b[0]) <= p[0] <= max(a[0],b[0]) and \
           min(a[1],b[1]) <= p[1] <= max(a[1],b[1])

def segments_intersect(a,b,c,d):
    o1, o2 = orient(a,b,c), orient(a,b,d)
    o3, o4 = orient(c,d,a), orient(c,d,b)
    if o1 != o2 and o3 != o4:
        return True
    # коллинеарные частные случаи
    if o1 == 0 and on_segment(a,b,c): return True
    if o2 == 0 and on_segment(a,b,d): return True
    if o3 == 0 and on_segment(c,d,a): return True
    if o4 == 0 and on_segment(c,d,b): return True
    return False
```

## Выпуклая оболочка

Выпуклая оболочка (convex hull) — минимальный выпуклый многоугольник, содержащий все точки. Классический алгоритм — **monotone chain** Эндрю, сложность `O(n log n)`:

```python
def convex_hull(points):
    pts = sorted(set(points))
    if len(pts) <= 1:
        return pts
    lower = []
    for p in pts:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)
    upper = []
    for p in reversed(pts):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)
    return lower[:-1] + upper[:-1]
```

Проверим на квадрате с внутренней точкой:

```python
print(convex_hull([(0,0),(1,1),(2,0),(1,0),(0,2),(2,2)]))
```

```
[(0, 0), (2, 0), (2, 2), (0, 2)]
```

Внутренняя точка `(1,1)` отброшена — она не на оболочке.

## Площади и многоугольники

Площадь многоугольника по формуле шнурков (shoelace):

```python
def polygon_area(poly):
    s = 0
    for (x1,y1),(x2,y2) in zip(poly, poly[1:] + poly[:1]):
        s += x1*y2 - x2*y1
    return abs(s) / 2

print(polygon_area([(0,0),(2,0),(2,2),(0,2)]))   # 4.0
```

Точка внутри многоугольника — луч-кастинг (ray casting): считаем, сколько раз горизонтальный луч из точки пересекает рёбра; нечётное число — внутри.

## Инструменты и код

- **Чистый Python** — для большинства CTF-задач достаточно формул выше; это самый надёжный путь, потому что целочисленная арифметика точна.
- **shapely** — геометрическая библиотека (`pip install shapely`): `Polygon(...).area`, `.contains(point)`, `.convex_hull`.
- **scipy.spatial** — `ConvexHull`, `Delaunay`, `KDTree` для ближайших соседей (`pip install scipy`).
- **sympy.geometry** — символьная геометрия, когда нужны точные пересечения прямых.
- **numpy** — векторизация, когда точек миллионы и `O(n log n)` на чистом Python слишком медленный.

Быстрая проверка площади и оболочки через shapely:

```python
from shapely.geometry import MultiPoint
pts = [(0,0),(2,0),(2,2),(0,2),(1,1)]
print(MultiPoint(pts).convex_hull.area)   # 4.0
```

## Разобранный пример: периметр оболочки

Задача: дано N точек, вывести периметр выпуклой оболочки. Решение — построить оболочку и просуммировать длины рёбер:

```python
import math
def perimeter(poly):
    total = 0.0
    for (x1,y1),(x2,y2) in zip(poly, poly[1:] + poly[:1]):
        total += math.hypot(x2-x1, y2-y1)
    return total

h = convex_hull([(0,0),(2,0),(2,2),(0,2),(1,1)])
print(h, perimeter(h))
```

```
[(0, 0), (2, 0), (2, 2), (0, 2)] 8.0
```

## Геометрия на целых числах

Главный практический совет: если вход — целые координаты, **не переходите во float** без необходимости. Ориентацию и пересечения считайте целочисленным `cross` — тогда вы не получите ложный результат из-за `1e-16`. Float оставляйте только для длин и площадей, где корень/деление неизбежны.

## Частые ошибки и подводные камни

- **Сравнение float через `==`.** Никогда не сравнивайте координаты напрямую; используйте эпсилон или целые числа.
- **Забыты коллинеарные случаи.** Пересечение «касание концом» требует отдельной проверки `on_segment`.
- **Неверный порядок сортировки в оболочке.** Monotone chain требует сначала сортировки по `(x, y)`, иначе оболочка «сломается».
- **`O(n²)` на миллионе точек.** Наивный перебор пар не пройдёт по времени — нужен `O(n log n)`.
- **Дубликаты точек.** Их лучше удалить (`set`), иначе вырожденные случаи ломают оболочку.

## Справочная таблица

| Задача | Формула / алгоритм | Сложность |
|--------|--------------------|-----------|
| Ориентация | знак `cross` | O(1) |
| Пересечение отрезков | orient + on_segment | O(1) |
| Выпуклая оболочка | monotone chain | O(n log n) |
| Площадь | shoelace | O(n) |
| Точка в многоугольнике | ray casting | O(n) |
| Ближайшая пара | divide & conquer / KDTree | O(n log n) |
| Периметр оболочки | сумма `hypot` | O(h) |

## Что дальше / решение

1. Прочитайте ограничение: если `n` велико, выбирайте `O(n log n)`, а не перебор.
2. Всегда проверяйте, целые ли координаты — тогда считайте целочисленно.
3. Для оболочки берите monotone chain; для площади — shoelace; для «внутри» — ray casting.
4. При миллионах точек подключайте numpy/scipy.
5. Проверяйте вырожденные случаи: совпадающие точки, коллинеарность, пустой вход.

## Расстояния и ближайшая пара

Расстояние от точки `p` до отрезка `ab` — частая подзадача («насколько близко объект к стене»). Идея: если проекция точки падает на отрезок, расстояние — это перпендикуляр; иначе — минимум из расстояний до концов.

```python
def dist_point_segment(p, a, b):
    ax, ay = a; bx, by = b; px, py = p
    dx, dy = bx-ax, by-ay
    if dx == 0 and dy == 0:
        return math.hypot(px-ax, py-ay)
    t = ((px-ax)*dx + (py-ay)*dy) / (dx*dx + dy*dy)
    t = max(0.0, min(1.0, t))            # ограничиваем проекцию отрезком
    proj = (ax + t*dx, ay + t*dy)
    return math.hypot(px-proj[0], py-proj[1])
```

Ближайшая пара точек (closest pair) наивно — `O(n²)`, но для больших наборов применяют «разделяй и властвуй» за `O(n log n)` или, что проще в CTF, `scipy.spatial.KDTree`:

```python
from scipy.spatial import KDTree
pts = [(0,0),(5,5),(1,1),(10,10)]
tree = KDTree(pts)
d, i = tree.query(pts[0], k=2)
print(d, i)   # расстояние до ближайшей (включая себя)
```

## Повороты, углы и полярная сортировка

Угол между векторами находят через `atan2(cross, dot)` — это устойчивее, чем `acos`, потому что не требует деления на произведение длин:

```python
def angle_between(a, b):
    return math.atan2(a[0]*b[1]-a[1]*b[0], a[0]*b[0]+a[1]*b[1])
```

Полярная сортировка (сортировка точек вокруг центра) нужна для построения звёздчатых многоугольников и в задачах «расставить по кругу». В Python её делают ключом `math.atan2(y-cy, x-cx)`.

## Выпуклая оболочка: проверка и приложения

Оболочка — не только геометрический объект, но и инструмент оптимизации. Если задача просит «максимальное расстояние» или «самую выгодную комбинацию», часто достаточно рассмотреть только точки оболочки: внутренние точки заведомо не лучше. Это сокращает перебор с `O(n²)` до `O(h²)`, где `h` — число вершин оболочки (часто мало).

Проверить, лежит ли точка на оболочке, можно через ориентации: точка на границе, если она коллинеарна соседним рёбрам и находится между их концами.

## Частые вопросы по геометрии

- **Что если все точки коллинеарны?** Оболочка вырождается в отрезок; алгоритм должен вернуть две крайние точки.
- **Как избежать деления?** Сравнивайте не расстояния, а их квадраты — это убирает `sqrt` и ошибки.
- **Зачем целочисленный cross?** Он даёт точный знак ориентации без риска ложного нуля из-за округления.
- **Когда нужен float?** Только для длин, периметров и площадей, где без корня/деления не обойтись.

## Мини-шпаргалка по геометрии

Запомните опорный набор: `cross` — знак ориентации, `dot` — проекция; пересечение отрезков — через противоположные ориентации плюс проверка «на отрезке»; оболочка — monotone chain после сортировки по `(x, y)`; площадь — шнурки; «внутри многоугольника» — луч-кастинг; расстояния — квадрат расстояния без `sqrt`. Все вычисления с целыми координатами ведите целочисленно, а float оставляйте только для длин. Если точек больше `10^5`, подключайте `scipy.spatial`. Этих семи приёмов достаточно для подавляющего большинства геометрических задач в CTF.

## Итог по геометрии

Вычислительная геометрия в CTF — это прежде всего аккуратность. Держите координаты целыми, ориентацию считайте через `cross`, избегайте делений там, где можно сравнить квадраты, и всегда проверяйте вырожденные случаи: совпадающие точки, коллинеарность, пустой вход. Если задача «не сходится», в девяти случаях из десяти виновата точность, а не логика.
