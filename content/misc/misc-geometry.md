## Вопрос, с которого всё начинается

В прошлом уроке мы решали задачу про сервис, который задаёт вопросы. Теперь задача другого типа: нам дали **файл с координатами** и просят одно число. Такие задачи в CTF встречаются постоянно — «дано N точек, найди периметр оболочки / площадь многоугольника / пересекается ли отрезок со стеной».

Формулы тут несложные. Настоящая сложность в другом: **точность** и **скорость**. Разберём это на одном конкретном файле.

## Наш пример: файл с точками

В архиве задачи лежит `points.txt`:

```
$ cat points.txt
0 0
2 0
2 2
0 2
1 1
```

Пять точек. Читаем условие: «Выведите периметр **выпуклой оболочки**». Термин новый — разберём его по ходу. Пока просто запомним, что координаты **целые**.

## Шаг 1: что такое выпуклая оболочка

Выпуклая оболочка (convex hull) — это **минимальный выпуклый многоугольник, который накрывает все точки**. «Выпуклый» значит без вмятин: если взять две любые точки внутри фигуры, отрезок между ними тоже целиком внутри.

Представьте, что точки — это гвозди, вбитые в доску, а мы натянули на них резинку. Резинка прижмётся как раз по оболочке. В нашем примере точка `(1,1)` лежит внутри квадрата `(0,0)-(2,0)-(2,2)-(0,2)` и на оболочку не попадёт.

Вопрос: как программе понять, какие точки снаружи? Для этого нужен один геометрический примитив — **векторное произведение**.

## Шаг 2: векторное произведение и ориентация

Для двух векторов `a = (ax, ay)` и `b = (bx, by)` **векторное (косое) произведение** считается как

```
cross(a, b) = ax*by - ay*bx
```

Его знак говорит, куда повёрнут второй вектор относительно первого:

- `> 0` — влево (против часовой стрелки),
- `< 0` — вправо (по часовой),
- `= 0` — векторы лежат на одной прямой (коллинеарны).

Важнейшее свойство: **если координаты целые, `cross` тоже целое — а значит точное**. Никаких ошибок округления. Это спасает нас от ложных результатов.

Функция ориентации точки `c` относительно отрезка `a→b`:

```python
def cross(o, a, b):
    return (a[0]-o[0])*(b[1]-o[1]) - (a[1]-o[1])*(b[0]-o[0])

def orient(a, b, c):
    v = cross(a, b, c)
    return 0 if v == 0 else (1 if v > 0 else -1)
```

## Шаг 3: строим оболочку (monotone chain)

Классический алгоритм — **monotone chain** (цепочка Эндрю). Идея: отсортировать точки, пройти слева-направо, набирая «нижнюю» цепочку, затем справа-налево — «верхнюю».

```python
def convex_hull(points):
    pts = sorted(set(points))          # set убирает дубликаты
    if len(pts) <= 1:
        return pts
    lower = []
    for p in pts:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()                # точка делает поворот вправо -> выкидываем
        lower.append(p)
    upper = []
    for p in reversed(pts):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)
    return lower[:-1] + upper[:-1]
```

Проверяем на нашем файле:

```python
pts = [(0,0),(2,0),(2,2),(0,2),(1,1)]
print(convex_hull(pts))
```

```
[(0, 0), (2, 0), (2, 2), (0, 2)]
```

Внутренняя `(1,1)` отброшена — именно то, что мы предсказали. Сложность `O(n log n)`, потому что доминирует сортировка.

## Шаг 4: периметр — и где появляется float

Теперь просуммируем длины рёбер оболочки. Длина отрезка — это `hypot` (корень из суммы квадратов), здесь без `float` уже не обойтись:

```python
import math
def perimeter(poly):
    total = 0.0
    for (x1,y1),(x2,y2) in zip(poly, poly[1:] + poly[:1]):
        total += math.hypot(x2-x1, y2-y1)
    return total

h = convex_hull(pts)
print(h, perimeter(h))
```

```
[(0, 0), (2, 0), (2, 2), (0, 2)] 8.0
```

Квадрат со стороной 2 — периметр 8. Ответ сходится.

Заметьте разделение ролей: **ориентацию мы считали целыми числами** (точно), а `float` применили только там, где без корня не обойтись — в длинах.

## Шаг 5: а если спросят площадь?

Тот же многоугольник, другая формула — **формула шнурков** (shoelace): суммируем `x1*y2 - x2*y1` по всем рёбрам и берём модуль, делённый на два.

```python
def polygon_area(poly):
    s = 0
    for (x1,y1),(x2,y2) in zip(poly, poly[1:] + poly[:1]):
        s += x1*y2 - x2*y1
    return abs(s) / 2

print(polygon_area([(0,0),(2,0),(2,2),(0,2)]))   # 4.0
```

Обратите внимание: внутри шнурков тоже только целые произведения — точность сохраняется до самого деления на 2.

## Шаг 6: расстояние от точки до отрезка

Ещё одна частая подзадача — «насколько близко точка к стене». Расстояние от точки `p` до отрезка `ab`: если проекция точки попадает на отрезок — это перпендикуляр; иначе — минимум из расстояний до концов.

```python
import math
def dist_point_segment(p, a, b):
    ax, ay = a; bx, by = b; px, py = p
    dx, dy = bx-ax, by-ay
    if dx == 0 and dy == 0:
        return math.hypot(px-ax, py-ay)
    t = ((px-ax)*dx + (py-ay)*dy) / (dx*dx + dy*dy)
    t = max(0.0, min(1.0, t))          # ограничиваем проекцию отрезком
    proj = (ax + t*dx, ay + t*dy)
    return math.hypot(px-proj[0], py-proj[1])
```

Обратите внимание на `t`: без ограничения `0..1` мы получили бы расстояние до бесконечной прямой, а не до отрезка.

## Шаг 7: когда точек миллионы

Наивный перебор ближайшей пары — `O(n²)`. Для больших наборов либо «разделяй и властвуй» за `O(n log n)`, либо, что проще в CTF, `scipy.spatial.KDTree`:

```python
from scipy.spatial import KDTree
tree = KDTree([(0,0),(5,5),(1,1),(10,10)])
d, i = tree.query((0,0), k=2)
print(d, i)     # расстояние до ближайшей (включая себя)
```

А полезный трюк: если задача просит «максимальное расстояние» или «самую выгодную комбинацию», часто достаточно рассмотреть только точки оболочки — внутренние заведомо не лучше. Это сокращает перебор с `O(n²)` до `O(h²)`, где `h` — число вершин оболочки.

## Что мы теперь знаем

- Выпуклая оболочка — минимальный выпуклый многоугольник вокруг точек; строится алгоритмом monotone chain за `O(n log n)`.
- Знак `cross(a,b)` = ориентация: влево / вправо / коллинеарно; для целых координат он **точен**.
- Периметр — сумма `hypot` по рёбрам; площадь — формула шнурков.
- Дубликаты точек убираем `set`, иначе вырожденные случаи ломают оболочку.

## На что смотреть дальше

- **Сравнение float через `==`** — так делать нельзя; либо сравнивайте целые, либо используйте эпсилон.
- **Коллинеарные случаи** при пересечении отрезков: «касание концом» требует отдельной проверки `on_segment`.
- **Порядок сортировки** — monotone chain требует сортировки строго по `(x, y)`, иначе оболочка «сломается».
- **Миллион точек** — наивный `O(n²)` не пройдёт; monotone chain даёт `O(n log n)`.
- **Деление без нужды** — сравнивайте квадраты расстояний, чтобы не тянуть `sqrt`.

## Справочная таблица

| Задача | Формула / алгоритм | Сложность |
|--------|--------------------|-----------|
| Ориентация | знак `cross` | O(1) |
| Пересечение отрезков | orient + on_segment | O(1) |
| Выпуклая оболочка | monotone chain | O(n log n) |
| Площадь | shoelace | O(n) |
| Точка в многоугольнике | ray casting | O(n) |
| Ближайшая пара | divide & conquer / KDTree | O(n log n) |
| Периметр оболочки | сумма `hypot` | O(h) |
