## Что такое misc-форензика

Форензика в misc — это извлечение информации из «сырых» данных: образов диска, дампов памяти, документов, архивов. Задача обычно формулируется как «вот файл, найди в нём флаг». Флаг может быть спрятан в неиспользуемых областях, в метаданных, в удалённых файлах или в конце потока.

## Артефакты и их типы

| Артефакт | Что даёт |
|----------|----------|
| Заголовки/хвосты файлов | восстановление удалённого |
| Метаданные (EXIF/XMP) | GPS, камера, время, ПО |
| Неиспользуемые области | скрытые данные |
| Логи | последовательность событий |
| Slack-пространство | остатки старых файлов |

## Восстановление удалённых данных

Когда файл удалён, его содержимое часто остаётся на диске до перезаписи. **Карвинг** восстанавливает файлы по сигнатурам, не опираясь на файловую систему.

```bash
# foremost — карвинг по типам
foremost -i disk.img -o out/
# binwalk — сигнатуры и извлечение
binwalk -e disk.img
# scalpel — настраиваемый карвинг
scalpel -c scalpel.conf disk.img -o out/
```

`foremost` ищет заголовки (`JPEG`, `PDF`, `ZIP`…) и восстанавливает файл до «хвоста». Если хвост потерян, применяют `photorec` (по структуре формата).

## Анализ метаданных

**EXIF** изображений хранит модель камеры, дату, а иногда GPS-координаты и миниатюру — в которой может быть спрятан другой кадр.

```bash
exiftool image.jpg
exiftool -b -ThumbnailImage image.jpg > thumb.jpg   # извлечь превью
exiftool -a -u -g1 image.jpg                         # все группы, включая скрытые
```

**XMP/IPTC** (в PDF/JPEG) тоже может содержать комментарии и историю редактирования.

## Строки и hex-анализ

```bash
strings -n 6 file.bin | head -50
xxd file.bin | head
binwalk file.bin
```

`strings` часто сразу показывает флаг, URL или путь. `xxd` — для ручного поиска сигнатур и непечатаемых данных.

## Инструменты

- **foremost / scalpel / photorec** — карвинг.
- **binwalk** — сигнатуры и извлечение вложенных форматов.
- **exiftool** — метаданные.
- **strings / xxd / hexdump** — ручной анализ.
- **testdisk** — восстановление разделов.
- **bulk_extractor** — массовое извлечение артефактов (email, URL, номера).

## Разобранный пример: карвинг изображений

Дан образ `disk.img`, нужно найти все картинки.

```bash
foremost -t jpg,png,gif -i disk.img -o recovered/
ls -la recovered/jpg/
```

Если среди восстановленных есть изображение с «неправильным» размером или не открывается — вероятно, в нём спрятаны данные (см. стеганографию).

## Разобранный пример: метаданные и превью

```bash
exiftool -b -ThumbnailImage photo.jpg > thumb.jpg
file thumb.jpg
```

Если превью отличается от основного изображения — в нём может быть флаг. Это классика: EXIF-миниатюра остаётся от исходного кадра после редактирования.

## Частые ошибки и подводные камни

- **Работа с оригиналом.** Всегда делайте копию образа; операции меняют данные.
- **Игнорирование метаданных.** Флаг часто именно там, а не в пикселях.
- **Потеря хвоста при карвинге.** Без хвоста файл может быть обрезан — используйте photorec.
- **Пропуск вложенных архивов.** Проверяйте `binwalk` и конец файла.
- **Слепой `strings`.** Ищите по формату флага (`grep -a 'CTF{'`), а не глазами.

## Что дальше / решение

1. Определите тип входа: образ, дамп, документ, бинарь.
2. Прогоните `file`, `binwalk`, `strings`, `exiftool`.
3. Ищите флаг по формату (`grep -a 'FLAG\|CTF{'`).
4. Для удалённых файлов — карвинг (`foremost`/`photorec`).
5. Проверьте метаданные и превью — часто флаг там.

## Файловые системы и slack-пространство

Данные прячут не только в файлах, но и в структурах файловой системы. Полезно знать:

- **Slack space** — остаток последнего кластера файла: место между концом данных и концом блока может содержать фрагменты удалённых файлов.
- **$MFT / inode** — таблица метаданных: имена, размеры, времена, указатели на данные.
- **Журналы** (`$LogFile`, ext4 journal) — история изменений, помогающая восстановить удалённое.
- **ADS (Alternate Data Streams)** в NTFS — скрытые потоки, привязанные к файлу.

```bash
# посмотреть ADS в NTFS-образе (через sleuthkit)
fls -r -p disk.img | head
# дамп потока по inode
icat disk.img 12345 > recovered.bin
```

## Работа с дампами памяти

В CTF встречаются дампы RAM (`memory.dmp`, `*.raw`). Быстрый путь — `strings`, более полный — Volatility.

```bash
strings -n 8 memory.raw | grep -i -a 'flag\|password'
volatility -f memory.raw imageinfo
volatility -f memory.raw --profile=Win10x64 pslist
volatility -f memory.raw --profile=Win10x64 filescan | grep -i flag
```

`filescan` находит файлы в памяти, `dumpfiles` их извлекает. Для Linux — `linux_pslist`, `linux_bash`.

## Документы и офисные форматы

Офисные файлы (docx/xlsx/pptx) — это ZIP+XML. Внутри может быть скрытый текст, комментарии, встроенные объекты.

```bash
unzip -l document.docx
unzip document.docx -d doc_x/
grep -r -a 'flag' doc_x/
```

PDF хранит объекты, потоки (иногда сжатые `zlib`), JavaScript и вложения.

```bash
pdfinfo file.pdf
pdfdetach -list file.pdf
qpdf --qdf --object-streams=disable file.pdf out.pdf   # распаковать потоки
```

## Архивы и вложенные данные

Матpёшка из архивов — частая CTF-задача: ZIP внутри ZIP внутри gzip. Распаковывайте итеративно:

```bash
while file f >/dev/null 2>&1; do :; done   # псевдокод
# на практике: цикл по типу файла
for i in $(seq 1 20); do
  case "$(file -b f)" in
    *Zip*) unzip -o f -d d$i; f=$(ls d$i/*);;
    *gzip*) mv f f.gz; gunzip f.gz; f=f;;
    *) break;;
  esac
done
```

Помните про `binwalk -e` — он часто автоматизирует всю эту цепочку.

## Практический чек-лист форензики файла

1. `file` — что это.
2. `binwalk` — вложенные сигнатуры.
3. `strings`/`grep -a` — текст и флаг.
4. `exiftool` — метаданные.
5. `xxd | tail` — конец файла.
6. `foremost`/`photorec` — удалённое.

## Частые вопросы по форензике

- **Флаг не находится в пикселях?** Смотрите метаданные и превью.
- **Файл не открывается?** Возможно, он составной или обрезан.
- **Дамп памяти огромный?** Начните со `strings` и `grep`, потом Volatility.
- **Архив не распаковывается?** Проверьте пароль и вложенность.

## Кейс: образ диска целиком

Дано: `disk.img`. Полный маршрут:

```bash
file disk.img
fdisk -l disk.img                 # разделы
fls -r -m / disk.img > body.txt   # файлы
mactime -b body.txt -d > t.csv    # таймлайн
foremost -i disk.img -o out/      # карвинг
binwalk -e disk.img               # вложенное
```

Сначала смотрим разделы и файлы, затем карвинг удалённого и вложенные форматы. Флаг может быть в удалённом файле, в slack-пространстве или в метаданных.

## Кейс: документ с секретом

Дано: `report.pdf`. Проверяем вложения и потоки:

```bash
pdfinfo report.pdf
pdfdetach -list report.pdf
strings report.pdf | grep -a FLAG
binwalk report.pdf
```

PDF часто прячет вложения (`/EmbeddedFile`), JavaScript и сжатые потоки. `binwalk` найдёт вложенный ZIP, а `strings` — открытый текст флага.

## Итог по форензике файлов

Форензика в misc — это методичный обход артефакта: `file` → `binwalk` → `strings` → `exiftool` → `xxd tail` → карвинг. Ищите флаг по формату (`grep -a`), проверяйте метаданные и превью, не забывайте про конец файла и вложенные архивы. Всегда работайте с копией образа. Эти привычки превращают «странный файл» в решаемую задачу.
