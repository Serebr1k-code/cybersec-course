## Вопрос, с которого всё начинается

В задаче картинка с искажённым текстом, а в ответе нужны эти символы. Или нужно автоматизировать вход на сайт с CAPTCHA. Как из «картинки с шумом» получить текст? Разберём пайплайн распознавания CAPTCHA.

## Наш пример

Возьмём изображение с текстом, поверх которого линии и точки (шум). Прямое OCR даст мусор. Задача — **предобработать** изображение так, чтобы символы стали чёткими, и только потом распознать.

## Шаг 1: что такое CAPTCHA и зачем её ломать

**CAPTCHA** — тест «человек ли ты», обычно искажённый текст или картинки. Ломают её для автоматизации (в CTF — чтобы получить флаг) и для обхода защиты. Простейший вид — текстовые CAPTCHA с шумом.

## Шаг 2: предобработка — первый шаг

Сырое изображение почти всегда надо чистить:
- **Оттенки серого** — убрать цвет.
- **Бинаризация (порог)** — оставить только чёрное/белое.
- **Удаление шума** — медианный фильтр, удаление мелких объектов.
- **Усиление** — эрозия/дилатация для утолщения или утоньшения линий.

Цель — сделать символы однородными на однотонном фоне.

## Шаг 3: сегментация

Если символы слиплись, их надо **разделить**. Приёмы:
- По вертикальным «пробелам» (столбцы без пикселей).
- По компонентам связности (connected components).
- По проекции (профиль яркости по столбцам).

Иногда CAPTCHA намеренно не даёт разделить символы — тогда распознают целиком (модель на последовательность).

## Шаг 4: распознавание

После чистки:
- **OCR** (Tesseract) — если символы стандартного шрифта.
- **Шаблонный матчинг** — сравнение с эталонными символами.
- **Нейросеть** — для сложных CAPTCHA.

Для простых CTF-задач хватает бинаризации + Tesseract.

## Шаг 5: инструменты

- Python: PIL/Pillow, OpenCV, numpy.
- `tesseract` — OCR-движок.
- `pytesseract` — обёртка.
- Онлайн-сервисы распознавания (осторожно с приватностью).

## Шаг 6: практический пайплайн

1. Открыть изображение (Pillow).
2. Перевести в grayscale.
3. Применить порог (например, 128).
4. Убрать шум (медиана).
5. Подать в `pytesseract.image_to_string`.
6. Проверить результат, при необходимости подкрутить порог.

## Шаг 7: когда не работает

- Сильное искажение (волны, перекрытие) — нужен ML.
- Цветной фон — нужна цветовая фильтрация.
- Разный размер символов — нужна нормализация.
- Шум, неотличимый от текста — предобработка не поможет.

## Шаг 8: защита (обратная сторона)

Если ты защищаешь CAPTCHA: добавляй перекрытие символов, случайные линии через текст, вращение, неоднородный фон. Но помни: CAPTCHA не панацея — современные модели ломают многие из них.

## Частые ошибки

- Сразу гнать OCR без предобработки.
- Один фиксированный порог для всех изображений.
- Забывать про инверсию (белый текст на чёрном).

## Разбор кейса: предобработка в Pillow по шагам

Разберём конкретный пайплайн на реальном коде. Пусть есть `captcha.png` — серый текст на светлом фоне с точками-шумом.

```python
from PIL import Image, ImageFilter

im = Image.open('captcha.png').convert('L')          # в оттенки серого
bw = im.point(lambda p: 255 if p > 140 else 0)       # порог: фон -> 255, символы -> 0
bw = bw.filter(ImageFilter.MedianFilter(3))          # медиана убирает одиночные точки
bw = bw.point(lambda p: 0 if p < 128 else 255)       # повторная бинаризация после фильтра
bw.save('clean.png')
```

Порог `140` подобран под конкретное изображение: он должен попадать в «яму» гистограммы между фоном и текстом. Медианный фильтр размера 3 удаляет одиночные шумовые пиксели, не размывая линии символов — в отличие от усредняющего фильтра, который размыл бы края. Дальше `clean.png` отдаём в OCR или в сегментацию.

## Таблица: операции предобработки и что они лечат

| Операция | Инструмент | Какой дефект лечит | Побочный эффект |
|---|---|---|---|
| Grayscale | `Image.convert('L')` | цветной фон, разные каналы | теряется цветовая информация |
| Бинаризация (порог) | `Image.point`, `cv2.threshold` | плавный фон, слабый контраст | при неверном пороге теряются тонкие штрихи |
| Адаптивный порог | `cv2.adaptiveThreshold` | неравномерное освещение | чувствителен к размеру окна |
| Медианный фильтр | `ImageFilter.MedianFilter` | соль/перец, одиночные точки | при большом ядре съедает тонкие линии |
| Морфология (open) | `cv2.morphologyEx` | линии-перечёркивания | может стереть сам символ |
| Дилатация | `cv2.dilate` | разорванные символы | слипание соседних символов |
| Эрозия | `cv2.erode` | слипшиеся символы | утоньшение до исчезновения |
| Инверсия | `ImageOps.invert` | белый текст на чёрном | — |

Правило: применяй минимум операций. Каждая лишняя операция — риск потерять признак, по которому OCR узнаёт символ.

## Сегментация по профилю столбцов

Если символы разделены, их режут по «провалам» в проекции. Идея: сложить число тёмных пикселей в каждом столбце — там, где символы, сумма большая, в промежутках — ноль.

```python
import numpy as np
a = np.array(bw)                       # 0 = чёрный (символ), 255 = белый
dark = (a < 128).sum(axis=0)           # профиль по столбцам
# границы символов — там, где dark переходит из 0 в >0 и обратно
edges = np.where(np.diff((dark > 0).astype(int)) != 0)[0]
for i in range(0, len(edges) - 1, 2):
    glyph = a[:, edges[i]:edges[i+1]]
    # glyph — отдельный символ, можно скормить OCR по одному
```

Когда CAPTCHA намеренно накладывает символы друг на друга, провалов нет — тогда сегментация невозможна, и распознают всю строку целиком моделью на последовательность (CRNN) без предварительного разрезания.

## Если не сработало

- **OCR читает только часть символов.** Убедись, что вырезал рамку и границу: лишняя вертикальная линия по краю сбивает сегментацию. Обрежь поля.
- **Медиана стёрла линии.** Уменьши ядро до 3 или замени медиану на морфологическое открытие с ядром 2×2.
- **Порог «плывёт» между картинками.** Используй метод Оцу (`cv2.threshold(..., 0, 255, cv2.THRESH_BINARY+cv2.THRESH_OTSU)`) — он сам находит порог по гистограмме.
- **Символы цветные на цветном фоне.** Выдели канал с максимальным контрастом (например, разность красного и синего) до перевода в серый.

## Ограничения

CAPTCHA не обязана быть «честной»: перекрытие, волновая деформация, неоднородный фон и случайный шум специально ломают предобработку. Против таких достаточно обучают нейросеть на большом наборе примеров, а не подбирают фильтры руками. И помни про приватность: отправлять чужие картинки в публичный онлайн-распознаватель — это утечка. В CTF обычно хватает Pillow + Tesseract; в реальной автоматизации счёт идёт на доли процента точности и часто выгоднее использовать сервис «человеческого» решения, чем бороться с искажениями.

## Практика: полный скрипт решения

Соберём всё вместе — от сырой картинки до распознанного текста, с проверкой и повтором при неудаче:

```python
from PIL import Image, ImageFilter
import pytesseract

def solve(path):
    im = Image.open(path).convert('L')
    im = im.resize((im.width*2, im.height*2), Image.LANCZOS)
    for thr in (120, 140, 160, 180):
        bw = im.point(lambda p: 255 if p > thr else 0)
        bw = bw.filter(ImageFilter.MedianFilter(3))
        text = pytesseract.image_to_string(
            bw, config='--psm 7 -c tessedit_char_whitelist=abcdefghijklmnopqrstuvwxyz0123456789').strip()
        if text and all(ch.isalnum() for ch in text):
            return text, thr
    return None, None

print(solve('captcha.png'))
```

Здесь важны три приёма. Первый — перебор порогов: один фиксированный порог не работает на всех картинках, а последовательный перебор с проверкой «все символы алфавитно-цифровые» отсекает мусорные результаты. Второй — whitelist в Tesseract: если CAPTCHA состоит только из строчных букв и цифр, движок не будет выдавать похожие символы из других алфавитов. Третий — апскейл перед бинаризацией: он делает тонкие линии устойчивее к порогу.

Если и это не даёт результата, переходят к сегментации: режут изображение по провалам проекции и распознают каждый символ отдельно, а затем собирают строку. Для слипшихся символов единственный надёжный путь — обученная модель распознавания последовательности, а не классический OCR.

## Когда задача не про картинку

В CTF «CAPTCHA» иногда оказывается не картинкой, а проверкой, которую надо обойти логически: например, вопрос на арифметику, спрятанный в HTML-комментарии, или значение в поле, которое сверяется на сервере. Тогда решает не предобработка изображений, а чтение исходников страницы: `curl` и поиск подсказки, анализ JS, вычисление ответа. Поэтому первым делом определи, с чем именно ты имеешь дело — с изображением или с логикой.

## Итоговый чек-лист решения CAPTCHA

- Определи тип: изображение (предобработка + OCR) или логика (чтение исходников).
- Открой картинку, переведи в grayscale, оцени контраст по гистограмме.
- Подбери порог перебором (120/140/160/180), а не на глаз.
- Убери одиночный шум медианой 3×3, не размывая символы.
- Увеличь изображение в 2 раза — тонкие линии станут устойчивее.
- Задай `tessedit_char_whitelist` под известный алфавит CAPTCHA.
- Проверь результат на «разумность» (все символы из алфавита), иначе меняй параметры.
- Если символы слиплись — сегментируй по профилю столбцов или распознавай строку моделью.

## Что мы теперь знаем

- CAPTCHA ломают через предобработку + распознавание.
- Бинаризация, удаление шума, сегментация — ключевые шаги.
- Tesseract годится для простых CAPTCHA.
- Сложные требуют ML.
- Защита — искажение и перекрытие символов.
