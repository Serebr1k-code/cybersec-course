## Вопрос, с которого всё начинается

В прошлом уроке флаг прятался в картинке. Теперь дают **звуковой файл** `audio.wav`. Слушаешь — просто писк, ничего разобрать нельзя. Где тут данные?

Ключевая идея: то, что «не слышно», часто **видно**. Звук — это колебания на разных частотах во времени, и если их нарисовать, в картинке проступает текст. Прибор, который это рисует, называется **спектрограмма** — график, где по горизонтали время, по вертикали частота, а яркость = громкость на этой частоте.

## Наш пример: audio.wav

Начинаем с того, что это вообще за файл. `file` смотрит на сигнатуру, `soxi` показывает параметры аудио:

```bash
$ file audio.wav
audio.wav: RIFF (little-endian) data, WAVE audio, mono 44100 Hz

$ soxi audio.wav
Input File     : 'audio.wav'
Channels       : 1
Sample Rate    : 44100
```

Факты: это WAV (несжатый звук), моно, 44100 сэмплов в секунду. Частота дискретизации и число каналов нам ещё понадобятся — их надо читать из файла, а не угадывать.

## Шаг 1: строим спектрограмму

Быстрее всего — утилитой `sox`:

```bash
$ sox audio.wav -n spectrogram -o spec.png
```

`-n` означает «не создавать выходной звук», `spectrogram` — режим построения картинки, `-o spec.png` — куда сохранить. Открываем `spec.png` и видим: по ярким дорожкам «нарисован» текст.

```
FLAG{sp3ctr0}
```

Это классический приём CTF: буквы «рисуют», меняя частоту сигнала во времени. Если хочется контроля — тот же результат в Python:

```python
import numpy as np
from scipy.io import wavfile
import matplotlib.pyplot as plt
fs, data = wavfile.read('audio.wav')
if data.ndim > 1:
    data = data[:, 0]              # если стерео — берём один канал
plt.specgram(data, Fs=fs, NFFT=1024, noverlap=768)
plt.savefig('spec.png')
```

Здесь `fs` — частота дискретизации, `NFFT` — размер окна анализа. Маленькое окно даёт хорошее разрешение по времени, но плохое по частоте; большое — наоборот. Если текст «нечитаем», покрутите `NFFT` и `noverlap`.

## Шаг 2: а если это набор номера? DTMF

Иногда в файле слышны ритмичные двойные гудки — это **DTMF** (Dual-Tone Multi-Frequency), система тонального набора телефона. Каждая цифра — пара частот (одна низкая, одна высокая). Распознавать вручную не нужно:

```bash
$ multimon-ng -a DTMF -t wav audio.wav
DTMF: 5
DTMF: 3
DTMF: 9
```

Получили последовательность цифр — она и есть ответ или ключ к следующему шагу. Не путайте DTMF с морзе: DTMF — **пары** тонов на символ, морзе — одиночный тон разной длительности.

## Шаг 3: морзе и SSTV

Если тон один, но «пищит» ритмично (коротко-длинно), это **морзе**: точка — короткий сигнал, тире — длинный, паузы разделяют символы и слова. Декодирует `multimon-ng -a MORSE`.

А если звук похож на «картиночный» набор свистов (так радиолюбители гоняли картинки по радио) — это **SSTV** (Slow-Scan Television). Раскодировать в изображение можно `qsstv` или `RX-SSTV`.

## Шаг 4: не забыть про метаданные и вложения

Параллельно проверяем дешёвые вещи:

```bash
$ exiftool audio.wav       # метаданные, теги (ID3 в MP3)
$ binwalk audio.wav        # вдруг внутри дописан другой файл
```

И LSB в сэмплах — как в картинках, только по отсчётам WAV. В стереофайле данные часто лежат **только в одном канале**, а второй — приманка; разделите каналы (`sox in.wav out.wav channels 1`) и обработайте каждый.

## Шаг 5: если сигнал зашумлён — фильтрация и FSK

Иногда сигнал «грязный»: полезные тона тонут в шуме. Тогда применяют **полосовой фильтр** — пропускают только нужный диапазон частот. В `scipy.signal` есть `butter` (расчёт коэффициентов фильтра) и `filtfilt` (применение без сдвига фазы):

```python
from scipy.signal import butter, filtfilt
b, a = butter(4, [1000/(fs/2), 2000/(fs/2)], btype='band')
clean = filtfilt(b, a, data)
```

Отфильтрованный сигнал снова смотрим спектрограммой — текст становится читаемым.

Ещё один частый сценарий — **FSK** (Frequency-Shift Keying): биты кодируются сменой частоты (одна частота = 0, другая = 1). Тогда нужен детектор частотных переходов: считаем доминирующую частоту по окнам и переводим в биты.

## Шаг 6: пять команд, которые решают большинство задач

```bash
sox in.wav -n spectrogram -o spec.png          # спектрограмма
sox in.wav out.wav channels 1                  # свести в моно (или развести)
multimon-ng -a DTMF -t wav in.wav              # DTMF
multimon-ng -a MORSE -t wav in.wav             # морзе
binwalk -e in.wav                              # вложенные файлы
```

Держите их под рукой — вместе со скриптом спектрограммы на matplotlib они закрывают почти все аудио-задачи.

## Шаг 7: моно/стерео и скорость воспроизведения

Две ловушки, которые легко пропустить. Первая — **каналы**: в стереофайле данные часто лежат только в одном канале, а второй — «приманка». Разведите каналы и обработайте каждый:

```bash
$ sox in.wav left.wav remix 1        # только левый канал
$ sox in.wav right.wav remix 2       # только правый
```

Вторая — **скорость воспроизведения**: иногда сигнал специально замедлен или ускорен, и спектрограмма читается только при правильной скорости. Меняйте скорость и перестраивайте картинку:

```bash
$ sox in.wav slow.wav speed 0.5      # замедлить вдвое
```

Если задача даёт «живой» звук (радиопоток, микрофон), запишите его в файл и анализируйте офлайн — так удобнее крутить параметры.

## Что мы теперь знаем

- Спектрограмма — главный инструмент: рисует частоты во времени; текст в аудио часто «нарисован» на ней.
- Формат и параметры читаем из файла: `file`, `soxi`, `ffprobe`.
- DTMF — пары тонов на цифру (`multimon-ng -a DTMF`); морзе — одиночные тоны (`-a MORSE`); SSTV — картинки (`qsstv`).
- Проверяем метаданные (`exiftool`), вложения (`binwalk`) и LSB в сэмплах.
- В стерео данные могут быть в одном канале — разделяйте.

## На что смотреть дальше

- **Не построить спектрограмму** — половина задач решается именно ей; это первый шаг.
- **Игнорировать метаданные** — флаг бывает в тегах.
- **Неверная частота дискретизации** — читайте её из файла, иначе спектрограмма «поедет».
- **Слишком маленький NFFT** — картинка нечитаема; увеличьте окно.
- **Моно против стерео** — проверьте оба канала.
- **Скорость воспроизведения** — иногда сигнал замедлен/ускорен; правильная скорость делает спектрограмму читаемой.
