## Вопрос, с которого всё начинается

В CTF дают строку из заглавных букв: `KHOOR`. Похоже на бессмыслицу, но флаг где-то рядом. Это классический шифр — способ заменить буквы так, чтобы прочитать текст мог только тот, кто знает правило. Компьютерной криптографии тут нет, но именно с этих шифров начинается криптоанализ, и в CTF они встречаются постоянно.

Задача урока: научиться по виду строки определять, какой это шифр, и вскрывать его — часто без ключа.

## Наш пример: строка KHOOR

```
KHOOR
```

Пять заглавных букв, без пробелов и цифр. Первая гипотеза для такого «плоского» текста — **шифр Цезаря**: каждая буква сдвинута по алфавиту на одно и то же число позиций. Например, при сдвиге 3 буква `A` становится `D`, `B` — `E` и так далее.

## Шаг 1: перебрать все сдвиги

Ключей у Цезаря всего 25 (сдвиг на 1..25; сдвиг 0 — открытый текст). Их можно перебрать за секунду. Напишем функцию и напечатаем все варианты:

```python
def caesar(text, shift):
    out = []
    for c in text:
        if c.isalpha():
            base = ord('A') if c.isupper() else ord('a')
            out.append(chr((ord(c) - base + shift) % 26 + base))
        else:
            out.append(c)
    return "".join(out)

for s in range(26):
    print(s, caesar("KHOOR", s))
```

В выводе среди прочего будет строка `23 HELLO` — при сдвиге 23 (это то же, что сдвиг −3) получается `HELLO`. Нашли открытый текст. Заметь: `% 26` заворачивает алфавит по кругу, чтобы после `Z` снова шла `A`.

Частный случай — **ROT13**, сдвиг ровно на 13. Он сам себе обратный: применил дважды — вернулся к исходному. Для цифр и знаков есть ROT47 (по печатным ASCII-символам).

## Шаг 2: когда одна буква шифруется по-разному — Виженер

Если перебор сдвигов не дал осмысленного текста, шифр сложнее. **Шифр Виженера** использует ключевое слово: каждая буква текста сдвигается на величину соответствующей буквы ключа, и сдвиг «плывёт» от позиции к позиции. Поэтому одна и та же буква открытого текста шифруется по-разному — частотный анализ напрямую не работает.

Дано: `LXFOPVEFRNHR`, ключ `LEMON`. Расшифруем:

```python
def vigenere(text, key, decrypt=False):
    out, ki = [], 0
    for c in text:
        if c.isalpha():
            base = ord('A') if c.isupper() else ord('a')
            k = ord(key[ki % len(key)].lower()) - ord('a')
            if decrypt:
                k = -k
            out.append(chr((ord(c) - base + k) % 26 + base))
            ki += 1
        else:
            out.append(c)
    return "".join(out)

print(vigenere("LXFOPVEFRNHR", "LEMON", decrypt=True))
```

```
ATTACKATDAWN
```

Открытый текст — `ATTACKATDAWN`. Ключ повторяется циклически (`LEMONLEMONLE…`), поэтому `ki % len(key)` берёт нужную букву ключа.

## Шаг 3: взлом без ключа — частотный анализ

Что делать, если ключ Виженера неизвестен? Два шага. Сначала определяют **длину ключа**: считают так называемый индекс совпадений для длин 1..20 — на «правильной» длине совпадений букв аномально много. Затем текст разрезают на столбцы по длине ключа: каждый столбец зашифрован обычным Цезарем и вскрывается частотным анализом.

**Частотный анализ** — главный инструмент и против **моноалфавитной подстановки** (когда каждая буква заменяется другой по фиксированной таблице). Идея проста: в естественном языке буквы встречаются неравномерно. В английском чаще всего `e`, затем `t`, `a`, `o`. Считаем частоты в шифртексте:

```python
from collections import Counter
print(Counter(c for c in "LXFOPVEFRNHR").most_common(5))
```

```
[('F', 2), ('R', 2), ('L', 1), ('X', 1), ('O', 1)]
```

На коротком тексте частоты мало о чём говорят (почти все буквы по разу), но на длинном самая частая буква шифртекста почти наверняка соответствует `e`. Дальше гипотезы уточняют по частым парам букв (биграммам `th`, `he`, `in`) и словам из трёх букв (`the`). Инструмент **quipqiup** делает это автоматически: вставляешь шифртекст — получаешь кандидатов на открытый текст.

Типичный ход работы: сначала заменяешь самую частую букву на `e` и смотришь, появятся ли узнаваемые куски вроде `_he`. Каждая угаданная буква подсказывает соседние (по словам), и таблица замены постепенно заполняется. На длинном английском тексте так восстанавливают открытый текст почти целиком, даже не зная таблицу подстановки.

## Шаг 4: не путать шифр с кодировкой

Важное различие. **Кодировка** (Base64, hex, URL-encoding) обратима без ключа: любой может декодировать, секрета в ней нет. **Шифр** без ключа не читается — в этом и смысл. Если строка состоит из `A-Za-z0-9+/=` и оканчивается на `=`, это, скорее всего, Base64 (кодировка), а не шифр.

Ещё одно семейство — **перестановочные** шифры, где буквы не заменяются, а меняют порядок: Rail Fence (текст пишется зигзагом по строкам) и столбцовая перестановка (текст пишется в таблицу, столбцы переставляются по ключу). Их тоже вскрывают перебором параметров: для Rail Fence — числом строк, для столбцовой — длиной и порядком столбцов.

## Шаг 5: инструменты и порядок действий

Ручной разбор хорош для понимания, но в CTF время дорого. Порядок такой:

1. **Определи класс** по алфавиту и структуре: сдвиг? полиалфавит? подстановка? перестановка?
2. **Сдвиги** — перебери все 25 (или ROT13/ROT47).
3. **Полиалфавит** — найди длину ключа, потом частотный анализ по столбцам.
4. **Подстановка** — quipqiup или частотный анализ руками.
5. **Быстрая идентификация** — CyberChef (онлайн-«швейцарский нож» с десятками декодеров) и dCode.

CyberChef удобен тем, что операции собираются в цепочку: например, «ROT13» → «From Base64» → «Reverse». Можно перепробовать десятки комбинаций декодеров за минуту, не написав ни строчки кода.

Аффинный шифр `c = (a·p + b) mod 26` (где `a` взаимно просто с 26) — тоже переборный: всего 12 допустимых `a` и 26 значений `b`, то есть 312 ключей.

## Что мы теперь знаем

1. Цезарь — сдвиг алфавита; вскрывается перебором 25 ключей; ROT13 — сам себе обратный.
2. Виженер — сдвиг задаётся ключевым словом; без ключа вскрывается через длину ключа + частоты.
3. Моноалфавитная подстановка вскрывается частотным анализом и quipqiup.
4. Шифр отличается от кодировки: кодировка обратима без ключа.
5. Перестановочные шифры (Rail Fence, столбцовые) вскрываются перебором параметров.

## На что смотреть дальше

- **Неверный алфавит.** Латинский или русский, регистр, цифры — учитывай всё.
- **Путаница шифр/кодировка.** Base64 и hex — не шифры; их «взлом» — декодирование.
- **Игнорирование пробелов.** Некоторые шифры удаляют их перед шифрованием.
- **Слепой перебор вместо анализа.** Для длинных подстановок частотный анализ быстрее.
- **Короткий текст.** Частотный анализ на нём ненадёжен — нужен контекст.
