## Time, race и предсказуемость: суть класса

Задачи на время, гонки и предсказуемость объединяет одна идея: программа где-то полагается на то, что «время идёт правильно» или что «между двумя действиями ничего не произойдёт». Как только вы находите такую зависимость, появляется уязвимость. Это может быть проверка пароля по времени ответа, генерация токена из текущего времени, окно между проверкой и использованием (TOCTOU) или логика, которую можно обмануть, «перепрыгнув» время. Цель модуля — научиться распознавать временные допущения и эксплуатировать их.

## Гонки: TOCTOU и параллелизм

TOCTOU (time-of-check to time-of-use) — классика: программа проверяет условие, а затем использует результат, и между этими моментами состояние меняется. Пример — конкурсный баланс: два одновременных запроса на списание проверяют «хватает ли денег», оба видят достаточно, оба списывают, и баланс уходит в минус. Эксплуатация — отправить много запросов одновременно:

```bash
# параллельные запросы к уязвимому эндпоинту
seq 1 50 | xargs -P50 -I{} curl -s -X POST \
  'http://host/api/redeem?code=GIFT' -o /dev/null
```

В Python удобнее потоки:

```python
import threading, requests
def hit():
    requests.post('http://host/api/redeem', data={'code':'GIFT'})
ts = [threading.Thread(target=hit) for _ in range(50)]
[t.start() for t in ts]; [t.join() for t in ts]
```

Если сервер не блокирует операцию, один и тот же «подарок» применится несколько раз.

## Временные атаки: измерение задержки

Если проверка пароля сравнивает символы по очереди и делает паузу на совпадении, время ответа утекает информацию:

```python
import requests, time
def timed(guess):
    t = time.perf_counter()
    requests.post(url, data={'pw': guess})
    return time.perf_counter() - t
best = ''
for _ in range(20):
    times = {c: sum(timed(best+c) for _ in range(5)) for c in alphabet}
    best += max(times, key=times.get)
```

На практике шум велик, поэтому каждый кандидат измеряется многократно и берётся статистика (медиана/среднее). Это медленно, но для коротких секретов работает.

## Предсказуемость: PRNG и seed

Многие задачи дают «случайный» токен, сгенерированный предсказуемым генератором. Если seed — время (в секундах, миллисекундах) или константа, токен воспроизводится:

```python
import random, time
for seed in range(int(time.time())-5, int(time.time())+5):
    random.seed(seed)
    if random.getrandbits(32) == observed:
        print('seed =', seed)
```

В Python `random` — Mersenne Twister: после 624 выходов состояние восстанавливается полностью (см. атаки на MT19937). Для задач «угадай следующее число» это ключевой приём.

## Восстановление состояния Mersenne Twister

```python
from randcrack import RandCrack
rc = RandCrack()
for _ in range(624):
    rc.submit(observed.getrandbits(32))
print(rc.predict_getrandbits(32))   # следующее значение
```

624 подряд идущих 32-битных вывода достаточно, чтобы предсказать все дальнейшие. Это классика задач «казино».

## Логика времени: манипуляция датами

Иногда уязвимость в бизнес-логике: «купон действует до 23:59», и его можно использовать дважды, если запросы разнесены во времени, или обойти проверку «не старше суток» подделкой даты в заголовке. Проверяйте, доверяет ли сервер клиентским датам (`Date`, `X-Forwarded-For`, поле формы) и сравнивает ли он локальное время. Подмена времени может открыть доступ к «будущим» функциям или снять лимит.

## Гонки в файловой системе

Классическая уязвимость — симлинк-гонка: программа пишет в предсказуемый временный файл, атакующий подменяет его симлинком на `/etc/passwd` между проверкой и записью. В CTF это встречается в задачах с `mktemp`-ошибками и в приватных эскалациях. Общий признак — предсказуемое имя временного файла и небезопасный порядок операций.

## Инструменты и приёмы

- **Turbo Intruder** (Burp) — высокоскоростные параллельные запросы для гонок.
- **`xargs -P`/`GNU parallel`** — массовый параллелизм из CLI.
- **`ab`/`hey`/`wrk`** — нагрузочные генераторы для создания окна гонки.
- **`randcrack`, `mersenne-twister-predictor`** — предсказание PRNG.
- **`time.perf_counter()`** — точные замеры задержек.

## Типичные ошибки и подводные камни

- **Слишком медленные запросы** — окно гонки закрывается; нужен параллелизм.
- **Недостаточно повторов** — гонка вероятностна, делайте десятки попыток.
- **Игнорирование сетевого шума** при таймингах — усредняйте.
- **Локальный `random` в тестах** — не путайте с серверным генератором.
- **Забыть про часовой пояс** — даты могут сравниваться в UTC.
- **Путать секунды и миллисекунды** при seed-атаке.
- **Считать, что «гонка невозможна»** — попробуйте, часто сервер не блокирует.

## Что дальше / решение

План: при виде любой логики, зависящей от времени или «атомарности», сразу спрашивайте — что будет, если два действия произойдут одновременно или если время подделать. Для гонок готовьте параллельные запросы и повторяйте десятки раз; для таймингов — измеряйте и усредняйте; для «случайности» — проверяйте seed и восстанавливайте PRNG. Держите под рукой Turbo Intruder и скрипты на потоках — это ваш основной арсенал для класса time/race задач.

## Практический пример: гонка на балансе

Разберём задачу. Веб-приложение позволяет «обменять купон» один раз: в базе хранится флаг `used=true`. Обработчик читает флаг, проверяет, что он не использован, и только потом записывает `used=true`. Между проверкой и записью есть окно — TOCTOU. Эксплуатация: отправить много запросов одновременно, чтобы несколько из них успели пройти проверку до первой записи. Если сервер обрабатывает их параллельно (многопоточный/асинхронный), несколько запросов «сработают», и награда начислится многократно.

```python
import threading, requests
def hit():
    requests.post('http://host/redeem', data={'code':'GIFT'}, timeout=5)
ts = [threading.Thread(target=hit) for _ in range(100)]
[t.start() for t in ts]
[t.join() for t in ts]
```

Для веб-задач удобнее Turbo Intruder (Burp) — он шлёт запросы «одной волной». Ключ к успеху — параллельность, а не количество: 100 одновременных запросов бьют сильнее, чем 1000 последовательных.

## Практический пример: предсказание PRNG

Другой сценарий: сервис выдаёт «случайные» токены, seed — текущее время. Подбираем seed перебором вокруг текущего времени:

```python
import random, time
for seed in range(int(time.time())-60, int(time.time())+1):
    random.seed(seed)
    if random.getrandbits(32) == observed:
        print('seed', seed)
```

Если генератор — Mersenne Twister, соберите 624 вывода и восстановите состояние через `randcrack`. Это классика задач «казино»: после 624 чисел вы предсказываете все дальнейшие.

## Частые вопросы

«Почему гонка не срабатывает?» — сервер блокирует операцию (мьютекс); ищите другой эндпоинт. «Как измерить тайминг?» — усредняйте много запросов. «А если seed — миллисекунды?» — перебирайте шире. «Что если random в Go?» — Go использует другой PRNG, изучите его.

## Что дальше / решение

Итог: при любой проверке-потом-действие пробуйте гонку параллельными запросами; при «случайных» значениях проверяйте seed и восстанавливайте PRNG. Держите под рукой Turbo Intruder и скрипты на потоках. Помните, что time/race-задачи вероятностны — повторяйте десятки раз.
