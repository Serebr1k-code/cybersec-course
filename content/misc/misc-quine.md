## Вопрос, с которого всё начинается

Задача: «напиши программу, которая печатает ровно свой исходный код и ничего больше». Казалось бы, невозможно — чтобы напечатать себя, программе нужно где-то хранить себя, но это уже часть кода. Однако такие программы существуют. Они называются **квины**. Разберём, как они устроены.

## Наш пример

Классический квин на Python:

```python
s = 's = %r
print(s %% s)'
print(s % s)
```

Запустим — он печатает сам себя. Разберём, почему это работает, шаг за шагом.

## Шаг 1: почему наивный подход не работает

Первая мысль: `print("print(...)")`. Но тогда программа печатает строку, а не саму себя. Любая попытка «вписать себя в себя» упирается в рекурсию: чтобы напечатать код, код должен содержать себя, который содержит себя... Квин решает это **косвенно**: хранит **шаблон** и **данные**, которые вместе дают код.

## Шаг 2: идея шаблона

В нашем примере `s` — строка-шаблон с двумя частями: код до подстановки и формат `%r`, куда подставится сама строка `s`. `s % s` подставляет `s` в шаблон, и получается полный исходник. Ключ: программа не содержит себя напрямую, а **вычисляет** себя из шаблона.

## Шаг 3: почему `%r`

`%r` — repr-формат: печатает строку с кавычками и экранированием, ровно так, как её надо записать в коде. Поэтому `s = %r` превращается в `s = 's = %r\nprint(s %% s)'`. Обрати внимание на `%%` — в шаблоне экранированный процент, чтобы после форматирования остался один `%`. Эти тонкости и делают квин корректным.

## Шаг 4: квины в других языках

В C квин сложнее: строку можно напечатать через `printf` с `%s` и двойным экранированием. В shell — через переменную с шаблоном. В любом языке идея одна: **шаблон + подстановка себя**. Есть даже «квин-реле» — цепочка квинов на разных языках, где каждый печатает программу на следующем языке.

## Шаг 5: связь с теорией

Квин — практическая демонстрация **теоремы о рекурсии** (Клини, вторая теорема о неподвижной точке): для любой вычислимой функции существует программа, которая выдаёт свой код. В CTF это чаще головоломка, но понимание самореференции помогает в задачах на метапрограммирование.

## Шаг 6: где встречается в CTF

- «Напиши квин на языке X» — проверка на знание приёмов.
- «Программа печатает себя, но с подвохом» — надо понять, где шаблон.
- «Quine-relay» — цепочка языков.
- Саморепликация в вирусах — та же идея.

## Шаг 7: как писать квин

1. Выбери язык.
2. Раздели код на «шаблон» и «данные».
3. Используй формат, который сам экранирует строку (`%r`, `repr`, `JSON`).
4. Проверь: вывод должен совпадать с исходником **байт в байт**.
5. Убери всё лишнее (пустые строки, комментарии) — иначе не совпадёт.

## Шаг 8: практический чек

Сравни вывод с исходником: `diff <(python3 quine.py) quine.py`. Если пусто — квин верен. Эта команда — стандартный способ проверки.

## Частые ошибки

- Забыть экранировать `%` (двойной процент).
- Добавить лишний перевод строки в конце.
- Печатать код с другим форматированием (пробелы).
- Считать, что квин невозможен.

## Разбор кейса: квин на C пошагово

В Python квин короткий, потому что есть `%r`, который сам экранирует строку. В C такого формата нет, поэтому квин пишут через `printf` с двумя строками и явным экранированием. Разберём классический однострочный квин:

```c
#include <stdio.h>
int main(){char*s="#include <stdio.h>%cint main(){char*s=%c%s%c;printf(s,10,34,s,34,10);return 0;}%c";printf(s,10,34,s,34,10);return 0;}
```

Идея та же, что и в Python: `s` — это шаблон, содержащий собственный код с «дырками». Дырки — это `%c`, куда подставляются: `10` (перевод строки), `34` (двойная кавычка), сама строка `s`, снова `34` и `10`. При запуске `printf` собирает полный исходник и печатает его.

Разберём по частям:
- `char*s="...";` — объявление шаблона; внутри уже находится весь остальной код;
- `printf(s,10,34,s,34,10);` — вызов, который подставляет аргументы в `%c`-дырки;
- `10` = `\n`, `34` = `"` — символы, которые нельзя записать напрямую без нарушения структуры.

Проверка обязательна: вывод должен **байт в байт** совпасть с файлом исходника. Один лишний перевод строки в конце — и квин неверен.

## Таблица: шаблон + данные в разных языках

| Язык | «Экранирующий» формат | Идея |
|---|---|---|
| Python | `%r` (repr) | `s='...%r...'; print(s%s)` |
| Python | f-string | `s='...{!r}...'` |
| C | `%c` + коды символов | подстановка `10`/`34` вместо `\n`/`"` |
| Shell | `printf`/`echo` с переменной | `s='...'; printf "$s" "$s"` |
| JavaScript | шаблонная строка + `Function` | `s=>...` |
| Ruby | `%q`/heredoc | `s="..."; puts(s%s)` |
| Perl | `q{}` | аналогично Python |

Общий принцип: язык должен уметь «печатать значение так, как его записывают в коде» (repr-подобный формат). Где такого формата нет (C), его эмулируют подстановкой кодов символов.

## Проверка и отладка

Стандартный способ проверки — сравнить вывод с исходником:

```bash
$ diff <(python3 quine.py) quine.py && echo "OK"
OK
```

Если `diff` показывает расхождение, смотри по символам:
- лишний/недостающий перевод строки в конце;
- разное экранирование кавычек;
- лишний пробел, который есть в выводе, но не в файле (или наоборот).

Полезный приём: сохрани вывод в файл и сравни `xxd`-дампы обоих — так видно невидимые различия (переводы строк, пробелы):

```bash
$ python3 quine.py > out.txt
$ xxd out.txt | tail -2
$ xxd quine.py | tail -2
```

## Если не сработало

- **Вывод совпадает, но `diff` ругается.** Разное окончание строки: `\n` против отсутствия. Убери или добавь перевод строки в исходник.
- **Двойной процент не сработал.** В Python в шаблоне `%` нужно писать как `%%`, иначе интерпретатор попытается подставить аргумент.
- **В C квин печатает мусор.** Проверь число `%c`-аргументов: их должно быть ровно столько же, сколько дырок, и в правильном порядке.
- **Квин «почти» верен.** Обычно ошибка в одном символе экранирования — сравни дампы побайтово.

## Ограничения

Квин — учебная демонстрация самореференции (вторая теорема о неподвижной точке), но в реальном вредоносном коде та же идея встречается в самореплицирующихся вирусах и полиморфных движках, где код пересобирает себя. Ограничение: квин хрупок — любая правка форматирования его ломает, потому что вывод обязан совпадать с исходником точно. Именно эта хрупкость делает задачу хорошей проверкой понимания, как язык представляет строки и как их экранирует.

## Quine-relay: цепочка квинов

Продвинутая версия задачи — **quine-relay**: программа на языке A печатает программу на языке B, та — на C, и так по кругу, пока цепочка не вернётся к A. Каждый шаг — обычный квин, только «свой код» — это исходник на следующем языке. Такие цепочки строят автоматически: генератор хранит шаблоны и подставляет в них следующий язык. Практическая ценность для CTF — проверить, что ты понимаешь механизм шаблон-подстановки, а не запомнил один квин. В вредоносном коде аналогичный приём — полиморфизм: код на каждом запуске собирает себя заново в новом виде, поэтому сигнатурные антивирусы его не узнают.

## Итоговый чек-лист

- Квин = шаблон + подстановка себя, а не «код внутри кода».
- Язык должен уметь repr-подобное представление строки.
- В C нет `%r` — эмулируй через `%c` и коды символов (10, 34).
- Проверяй точно: `diff <(python3 quine.py) quine.py`.
- Один лишний перевод строки ломает квин.
- Сравнивай дампы (`xxd`), чтобы увидеть невидимые различия.
- Идея — вторая теорема о неподвижной точке (Клини).

## Кратко: что запомнить

Квин печатает собственный исходник, потому что хранит шаблон с «дырками» и подставляет в них себя. Ключевое требование — язык умеет repr-подобное представление строки (в C его эмулируют через `%c`). Проверка строгая: `diff <(python3 quine.py) quine.py` должен быть пуст. Идея — практическая форма теоремы о неподвижной точке, и та же самореференция лежит в основе полиморфных вирусов.

## Практика: квин на Python с нуля

Построим квин самостоятельно, чтобы понять механизм. Начнём с шаблона и места для подстановки.

```python
s = 'print(%r)'
print(s % s)
```

Что произойдёт: `s % s` подставит строку `s` (её repr) в `%r`. Первая строка `s = '...'` в исходнике исчезла из вывода, потому что её нет в шаблоне. Значит, нужно включить объявление в шаблон и учесть, что `s` встречается в коде дважды. Получаем классический вид:

```python
s = 's = %r\nprint(s %% s)'
print(s % s)
```

Здесь `%r` заменится на repr строки `s` (с кавычками и `\n`), а `%%` превратится в один `%` — иначе форматирование «съест» его как спецификатор. Проверим:

```bash
$ python3 quine.py > out.txt
$ diff out.txt quine.py && echo QUINE_OK
QUINE_OK
```

Пошаговый вывод: сначала определи, какие части кода должны присутствовать в шаблоне (обычно это сам оператор печати), затем добавь подстановку и экранируй все проценты, кроме нужного. Если `diff` ругается на один символ — почти всегда это `%`, кавычка или перевод строки.

## Что мы теперь знаем

- Квин — программа, печатающая свой код.
- Устройство: шаблон + подстановка себя.
- `%r`/`repr` дают корректное экранирование.
- Идея — практическая форма теоремы о рекурсии.
- Проверка: `diff <(запуск) исходник`.
