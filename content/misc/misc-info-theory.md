## Вопрос, с которого всё начинается

У тебя есть файл. Ты не знаешь, это текст, сжатые данные или шифротекст. Как понять по содержимому? Ответ даёт **теория информации**: она измеряет, сколько «непредсказуемости» в данных. Эта величина называется **энтропия**.

## Наш пример

У нас есть `info.log` — измерения энтропии для нескольких фрагментов:

```
sample: plain_text entropy: 4.12 bits/byte
sample: compressed entropy: 7.95 bits/byte
sample: random entropy: 8.00 bits/byte
```

Наша задача — понять, что означает каждое число и как по нему делать выводы.

## Шаг 1: что такое информация

В быту «информация» — это смысл. В теории информации Шеннона смысла нет вообще: информация — это **снятая неопределённость**. Сообщение тем ценнее, чем менее оно ожидаемо. «Завтра взойдёт солнце» несёт почти ноль информации; «завтра пойдёт снег в июле» — много.

Значит, мера информации должна зависеть от **вероятности**: чем реже событие, тем больше информации оно несёт.

## Шаг 2: количество информации одного события

Информация события с вероятностью `p` определяется как:

```
I = -log2(p)   (в битах)
```

Если `p = 1` (событие точно случится), `I = 0` — информации нет. Если `p = 1/2`, `I = 1` бит. Если `p = 1/256`, `I = 8` бит — ровно один байт. Отсюда интуиция: **один бит — это ответ на вопрос «да/нет» с равными шансами**.

## Шаг 3: энтропия источника

**Энтропия** — среднее количество информации на символ:

```
H = -Σ p_i * log2(p_i)
```

Для источника из `n` равновероятных символов `H = log2(n)`. Для байта (256 равновероятных значений) `H = 8` бит — максимум. В нашем логе `random entropy: 8.00` — идеально случайные байты. `plain_text entropy: 4.12` — английский текст: буквы распределены неравномерно, потому энтропия ниже.

## Шаг 4: избыточность

Разница между максимумом и фактической энтропией — **избыточность** (redundancy). Для английского текста она велика: буквы `e`, `t`, `a` встречаются часто, а `z`, `q` — редко. Именно избыточность позволяет сжимать текст: предсказуемые куски кодируются короче.

Формула: `R = H_max - H`. Для текста `H_max = 8`, `H ≈ 4`, значит `R ≈ 4` бита на байт — почти половина «лишняя».

## Шаг 5: как это помогает в задачах

Энтропия — быстрый способ **классифицировать данные**:

- **Текст/код/разметка**: энтропия заметно ниже 8 (обычно 3–5 бит/байт).
- **Сжатые данные** (zip, gzip, png): близко к 8, потому что сжатие уже убрало избыточность.
- **Шифротекст**: ровно ~8 — шифр делает данные неотличимыми от случайных.
- **Скрытая вставка**: локальные участки с аномальной энтропией выдают, что там «что-то есть».

Инструмент `binwalk`/`ent` считает энтропию по блокам — ищет такие аномалии.

## Шаг 6: предел сжатия

Теорема Шеннона о кодировании источника говорит: **нельзя сжать данные сильнее, чем их энтропия**. Если энтропия файла — 8 бит/байт (шифротекст или уже сжатый), дальнейшее сжатие бесполезно. Поэтому архивировать зашифрованное бессмысленно — размер не уменьшится.

Это же объясняет, почему «зашифруй и сожми» не работает: шифр уже довёл энтропию до максимума.

## Шаг 7: как это выглядит в задаче

Типовые приёмы:

- посчитать энтропию файла целиком (`ent file`);
- пройти блоками и найти участок с высокой энтропией — там, вероятно, зашифрованный или сжатый блок;
- сравнить энтропию «нормального» и подозрительного файла;
- оценить энтропию пароля/ключа по алфавиту и длине.

## Шаг 8: находим флаг в логе

В `info.log` есть строка `flag` в base64:

```
$ grep flag info.log
flag: bnRvezNudHIwcHlfMGZfNF9wNHNzdzByZH0=
```

Декодируем и пишем в файл:

```
$ grep flag info.log | cut -d: -f2 | base64 -d
nto{3ntr0py_0f_4_p4ssw0rd}
$ grep flag info.log | cut -d: -f2 | base64 -d > found.txt
$ check
```

Метка напоминает: энтропия — это мера «сколько угадывать» пароль или данные.

## Что мы теперь знаем

- Информация — снятая неопределённость; она зависит от вероятности.
- `I = -log2(p)` бит на событие; энтропия — среднее на символ.
- Для байта максимум 8 бит; текст ~3–5, шифр ~8.
- Избыточность позволяет сжимать; энтропия задаёт предел сжатия.
- Энтропия по блокам выдаёт скрытые вставки.
