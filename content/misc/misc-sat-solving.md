## Вопрос, с которого всё начинается

Есть набор логических условий: «если A, то B», «ровно одно из трёх истинно», «сумма битов чётна». Нужно найти значения переменных, при которых всё выполнено. Перебирать `2^n` вариантов — долго. Но эту задачу умеет решать специальный инструмент — **SAT-солвер**.

## Наш пример

У нас есть `sat.log` — формула в CNF:

```
c пример: 3 переменные, 2 клаузы
p cnf 3 2
1 -2 0
2 3 0
```

Здесь `1 -2 0` — клауза «переменная 1 ИЛИ НЕ переменная 2», ноль завершает клаузу. Наша задача — понять этот формат и как из него получают решение.

## Шаг 1: что такое SAT

**SAT** (Boolean satisfiability) — задача: дана булева формула, найти набор значений переменных, при котором она истинна. Если такой набор есть — формула **выполнима** (satisfiable). Это одна из базовых NP-полных задач: универсальная, но в худшем случае экспоненциально тяжёлая.

Практика, однако, показывает: реальные формулы решаются быстро. Современные солверы решают миллионы переменных.

## Шаг 2: CNF — стандартная форма

Солверы принимают формулу в **CNF** (conjunctive normal form, КНФ): **конъюнкция клауз**, где каждая клауза — **дизъюнкция литералов**. Литерал — это переменная или её отрицание.

Формат **DIMACS** (наш пример) выглядит так:

- строка `p cnf <переменных> <клауз>` — заголовок;
- каждая клауза — числа через пробел, `0` в конце;
- положительное число — переменная, отрицательное — её отрицание;
- строки, начинающиеся с `c`, — комментарии.

## Шаг 3: как работает солвер

Классический алгоритм — **DPLL**: выбираем переменную, пробуем `true`, упрощаем формулу; если противоречие — пробуем `false`. Современные солверы используют **CDCL** (conflict-driven clause learning): при противоречии они **выводят новую клаузу** и не повторяют ту же ошибку. Именно это делает их быстрыми.

Дополнительно: эвристики выбора переменных, «watched literals», рестарты, редукция базы клауз. Всё это — оптимизации вокруг одной идеи «учиться на конфликтах».

## Шаг 4: кодирование задачи

Главный навык — **свести задачу к CNF**:

- **Импликация** `A → B` — это `(¬A ∨ B)`;
- **XOR** `A ⊕ B` — две клаузы: `(A ∨ B) ∧ (¬A ∨ ¬B)`;
- **Ровно один из n** — попарные «не оба» плюс «хотя бы один»;
- **Схема** — каждому вентилю своя переменная, связи через клаузы;
- **Псевдобулевы ограничения** (сумма ≤ k) — кодируются через счётчики.

Умение кодировать — 90% успеха в SAT-задачах.

## Шаг 5: SMT против «сырого» SAT

**SAT** работает только с булевыми переменными. **SMT** (satisfiability modulo theories) — надстройка: переменные могут быть целыми, битвекторами, массивами. Z3 — самый популярный SMT-солвер. Вместо того чтобы вручную кодировать 32-битную арифметику в миллионы клауз, ты пишешь `x + y == 42` и передаёшь в Z3.

В CTF чаще берут Z3: он читаемее и быстрее в разработке. «Сырой» SAT (CryptoMiniSat, MiniSat) — когда нужна максимальная скорость на чисто булевой формуле (например, во взломе потоковых шифров).

## Шаг 6: как это выглядит в задаче

Типовые сценарии:

- **Головоломка** (судоку, нонограмма) — переменные «клетка=значение», клаузы на правила;
- **Схема/крекми** — переменные «бит ключа», клаузы на проверки;
- **Крипто** — восстановление ключа LFSR по известному keystream (линейные уравнения над GF(2)).

Везде схема одна: **переменные + ограничения → солвер → значения**.

## Шаг 7: находим флаг в логе

В `sat.log` есть строка `flag` в base64:

```
$ grep flag sat.log
flag: bnRve3M0dF9zMGx2M3JfdW5yNHYzbHNfdzFyM3N9
```

Декодируем и пишем в файл:

```
$ grep flag sat.log | cut -d: -f2 | base64 -d
nto{s4t_s0lv3r_unr4v3ls_w1r3s}
$ grep flag sat.log | cut -d: -f2 | base64 -d > found.txt
$ check
```

Метка описывает суть: SAT-солвер «распутывает провода» — находит выполняющее присваивание.

## Что мы теперь знаем

- SAT ищет значения булевых переменных, при которых формула истинна.
- Стандартный вход — CNF в формате DIMACS.
- Современные солверы (CDCL) учатся на конфликтах и потому быстры.
- Главный навык — кодирование задачи в клаузы.
- SMT (Z3) удобнее: целые, битвекторы, массивы вместо ручного CNF.
