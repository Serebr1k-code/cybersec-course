## Вопрос, с которого всё начинается

Тебе дали файл `font.ttf`. Он открывается как обычный шрифт, но задача говорит: внутри спрятано сообщение. Где в шрифте может лежать текст, если он «рисует буквы», а не хранит их?

Ответ: шрифт — это контейнер с таблицами, и в свободных местах легко спрятать данные. Это урок про разбор шрифтов.

## Наш пример: font.ttf

```
$ file font.ttf
font.ttf: TrueType Font data, 14 tables, 1st "GDEF", ...
```

`file` перечислил число таблиц. Значит, перед нами контейнер **sfnt**. Разберём его структуру.

## Шаг 1: контейнер sfnt

**sfnt** — общий контейнер TrueType и OpenType. Начинается с заголовка: магия (0x00010000 для TTF, `OTTO` для OTF, `wOFF` для WOFF), число таблиц и список **Table Directory** — для каждой таблицы: тег (4 буквы), смещение, длина.

```
$ xxd -l 32 font.ttf
00000000: 0001 0000 000e 0080 0003 0020 4744 4546  ........... GDEF
```

`0001 0000` — TrueType, `000e` = 14 таблиц, дальше теги: `GDEF`... Каждая таблица — самостоятельный блок.

## Шаг 2: ключевые таблицы

| Таблица | Что хранит |
|---|---|
| head | глобальные параметры, `indexToLocFormat` |
| hhea/hmtx | метрики строк и глифов |
| maxp | число глифов |
| cmap | соответствие символ → глиф |
| glyf | контуры глифов (TTF) |
| loca | смещения глифов в glyf |
| name | имена и строки (автор, версия) |
| CFF | контуры (OTF вместо glyf) |

Для данных интересны `name` (строки) и «щели» между таблицами.

## Шаг 3: читаем через fontTools

```
$ python3 - <<'PY'
from fontTools.ttLib import TTFont
f = TTFont('font.ttf')
print('tables:', f.keys())
print('numGlyphs:', f['maxp'].numGlyphs)
for rec in f['name'].names:
    print(rec.nameID, rec.toUnicode())
PY
tables: ['GDEF','GPOS','GSUB','OS/2','cmap','glyf','head','hhea','hmtx','loca','maxp','name','post']
numGlyphs: 218
4 Pixel Sans
6 PixelSans-Regular
```

Таблица `name` — первое место для скрытого текста: нестандартные строки, необычные `nameID`.

## Шаг 4: где прячут данные

- **name-таблица.** Лишние записи, невидимые в интерфейсе, но читаемые парсером.
- **Щели и padding.** Между таблицами бывают байты-заполнители; туда пишут данные.
- **Таблица glyf/loca.** Контуры можно заменить так, чтобы данные лежали в координатах.
- **Игнорируемые таблицы.** Парсеры пропускают неизвестные теги — идеальное место.
- **Хвост файла.** После последней таблицы может лежать полезная нагрузка (часто архив).

```
$ binwalk font.ttf
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             TrueType font
49201         0xC031          Zip archive data
```

`binwalk` нашёл ZIP в хвосте — классика.

## Шаг 5: ручной разбор таблиц

```
$ python3 - <<'PY'
import struct
d = open('font.ttf','rb').read()
num = struct.unpack('>H', d[4:6])[0]
off = 12
for i in range(num):
    tag = d[off:off+4].decode('latin1')
    o, l = struct.unpack('>II', d[off+8:off+16])
    print(tag, hex(o), l)
    off += 16
PY
GDEF 0x80 64
GPOS 0xc0 1024
...
```

Зная смещения и длины, видишь «дыры» между таблицами и хвост после последней. Там и ищут спрятанное.

## Шаг 6: WOFF и упаковка

**WOFF** — веб-шрифт: те же таблицы, но сжатые (zlib) и с обёрткой. **WOFF2** использует Brotli и преобразования. Для разбора распаковывают обратно в TTF через `fontTools.ttLib.woff2`:

```
$ python3 -c "from fontTools.ttLib import TTFont; TTFont('font.woff2').save('font.ttf')"
```

Дальше — как с обычным TTF.

## Полный прогон

```
$ binwalk font.ttf | tail -3
0             0x0             TrueType font
49201         0xC031          Zip archive data
$ dd if=font.ttf bs=1 skip=49201 of=tail.zip status=none
$ unzip -p tail.zip
nto{4_f0nt_0f_s3cr3ts}
```

Данные лежали после последней таблицы, в хвосте файла.

## Что мы теперь знаем

- Шрифт — контейнер sfnt со списком таблиц.
- Таблицы имеют теги, смещения и длины; между ними бывают щели.
- Данные прячут в name, glyf, неизвестных таблицах и хвосте.
- WOFF/WOFF2 — упакованный TTF/OTF, распаковывается fontTools.
- binwalk и ручной разбор находят скрытую нагрузку.

## Контуры глифов: simple и composite

Таблица `glyf` хранит контуры. Глифы бывают **simple** (свои точки и инструкции) и **composite** (собираются из других глифов со смещениями). Таблица `loca` даёт смещения глифов внутри `glyf`. Данные можно спрятать, изменив точки контура: визуально буква почти не меняется, а координаты несут информацию. Это шрифтовая стеганография.

## CFF и OpenType

В OTF вместо `glyf`/`loca` используется **CFF** — компактный формат контуров с собственными структурами (charstrings, subrs). Разбирать его сложнее, но принцип тот же: контуры — это данные, и в них можно спрятать сообщение. `fontTools` умеет читать CFF так же, как glyf.

## Уязвимости парсеров шрифтов

Исторически шрифтовые парсеры — источник серьёзных уязвимостей: неверные смещения в таблицах, переполнения при разборе `loca`, ошибки в интерпретаторе инструкций TrueType. Поэтому в задачах на реверс шрифт может быть эксплойтом, а не носителем текста. Для аудита смотрят на валидацию длин и границ таблиц.

## Стеганография в шрифтах

Помимо контуров, данные прячут: в неиспользуемых битах метрик, в порядке глифов, в таблице `name`, в «мёртвых» глифах (которые не отображаются), в хвосте файла. Иногда сообщение кодируют в отличиях между двумя похожими глифами — глаз не заметит, а программа прочитает.

## Создание и правка шрифта

`fontTools` позволяет программно менять шрифт: добавлять глифы, править метрики, вставлять данные. Это нужно и для CTF (собрать «задачу»), и для аудита (проверить, как парсер реагирует на правку). Простейший скрипт открывает TTF, меняет строку в `name`, сохраняет — и ты видишь, где именно парсер её читает.

## Инструменты

`fontTools` (Python) — разбор и правка. `ttx` — конвертация шрифта в XML-текст и обратно (удобно для диффов). `fontforge` — графический редактор. `binwalk` — поиск встроенного в шрифт. `otfinfo` — быстрая сводка таблиц. Комбинация `ttx` + diff особенно полезна: сравни два шрифта и увидишь, где спрятано отличие.

## Практический сценарий: ttx-дифф

Задача: найти отличие между двумя шрифтами. Решение: `ttx font_a.ttf` и `ttx font_b.ttf` дают XML-представления; `diff` показывает изменённые таблицы. Часто различие в одном глифе или строке `name` — там и спрятано сообщение. Такой дифф — быстрый способ локализовать «модифицированный» шрифт в CTF.

## Шрифт как вектор атаки в браузере

Шрифты загружаются в браузер и парсятся движком (FreeType/HarfBuzz). Ошибка в парсере может дать исполнение кода. Поэтому браузеры изолируют разбор шрифтов и ограничивают возможности. Для аудита важно: проверяй границы таблиц, длины `loca`, корректность composite-глифов. Исторически именно эти места давали уязвимости.

## Шпаргалка инструментов

`python3 -c "from fontTools.ttLib import TTFont; f=TTFont('x.ttf'); print(f.keys())"` — список таблиц; `ttx x.ttf` — в XML; `otfinfo -i x.ttf` — метаданные; `binwalk x.ttf` — встроенное; `fontforge` — визуальная правка. Для WOFF2: `TTFont('x.woff2').save('x.ttf')` распаковывает обратно.

## Итог

Шрифт — это контейнер, и как любой контейнер он прячет данные в «щелях»: хвосте, неизвестных таблицах, контурах, метриках. Навык разбора шрифтов переносится на любые табличные форматы: увидел список «тег — смещение — длина» — ищи то, что между ними.

## Как устроен разбор таблиц в парсере

Парсер шрифта читает заголовок, затем Table Directory, затем каждую таблицу по её смещению. Ошибка в одном смещении сдвигает разбор и может привести к чтению за границами — отсюда исторические уязвимости. Для задач полезно знать порядок: сначала `head` (масштаб и формат `loca`), потом `maxp` (число глифов), потом `loca`, потом `glyf`. Только с этими четырьмя таблицами можно обойти все контуры.

## Шрифт как носитель кастомного формата

Иногда в шрифте прячут не текст, а целую структуру: набор глифов кодирует байты по их контурам, или порядок глифов задаёт сообщение. Тогда задача — восстановить кодировку и декодировать. Подход: извлечь все глифы (`fontTools`), сравнить их, найти нестандартные, сопоставить с ASCII. Это смесь форензики и реверса формата.

## Валидация шрифта

Перед разбором полезно проверить целостность: совпадают ли смещения таблиц, нет ли выхода за пределы файла, корректен ли `loca`. `fontTools` при загрузке делает часть проверок и бросает исключение на битом шрифте. Если файл «не открывается» — это тоже сигнал: возможно, структура подделана намеренно, и данные лежат в нестандартном месте.

## Итог

Разбор шрифтов учит главному приёму форензики контейнеров: найди оглавление (Table Directory), пройди по элементам, проверь границы, посмотри на «щели» и хвост. Этот приём работает со шрифтами, архивами, медиа-контейнерами и прошивками. Один раз поняв принцип, ты разбираешь любой табличный формат.

## Финальная мысль

Шрифт кажется «просто картинкой букв», но это полноценный контейнер с оглавлением, таблицами и щелями. Поняв его структуру, ты получаешь универсальный навык: любой табличный формат (архив, медиа, прошивка) разбирается тем же приёмом — найди оглавление, пройди элементы, проверь границы, загляни в хвост. Начни с `TTFont(...).keys()`, а дальше иди по таблицам.
