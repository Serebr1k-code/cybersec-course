## Что такое таймлайн

Таймлайн (timeline) — упорядоченная по времени последовательность событий файловой системы и ОС. В форензике он отвечает на вопрос «что происходило и когда». В CTF таймлайн помогает найти «аномальный» файл (созданный в момент, отличный от остальных) или восстановить порядок действий.

## MAC-времена (MACB)

У каждого файла обычно четыре временные метки:

| Метка | Смысл |
|-------|-------|
| **M** (Modified) | изменение содержимого |
| **A** (Accessed) | последнее чтение |
| **C** (Changed/MFT) | изменение метаданных (inode) |
| **B** (Birth/Created) | создание файла |

Вместе их называют MACB. На разных ФС набор отличается: ext4 хранит `mtime/atime/ctime/crtime`, NTFS — `$STANDARD_INFORMATION` и `$FILE_NAME` (две копии времён, что важно при `timestomping`).

## Источники временных меток

- **Файловая система** — MACB всех файлов.
- **Реестр Windows** — время установки ПО, последние запуски.
- **Логи** — события с точным временем (EVTX, syslog, journald).
- **Браузер** — история, кэш, cookies.
- **Метаданные документов** — время создания/изменения внутри файла.

## Построение таймлайна

Основной инструмент — **plaso** (log2timeline):

```bash
log2timeline.py timeline.plaso disk.img
psort.py -o l2tcsv -w timeline.csv timeline.plaso
```

`log2timeline` собирает события из всех артефактов, `psort` сортирует и фильтрует. Для быстрого «только ФС» таймлайна есть `fls`/`mactime` из sleuthkit:

```bash
fls -r -m / disk.img > bodyfile.txt
mactime -b bodyfile.txt -d > timeline.csv
```

## Сортировка и фильтрация

Таймлайн огромен; его нужно фильтровать:

```bash
# события вокруг интересующего времени
grep '2024-03-1[0-5]' timeline.csv | head
# только создание файлов
awk -F, '$3=="..."' timeline.csv
```

Ищите кластеры событий: всплеск активности в одну минуту — типичный признак действий атакующего.

## Временные аномалии и timestomping

Атакующие подделывают времена (`timestomping`), чтобы замаскировать файл под системный. Признаки:

- `$STANDARD_INFORMATION` и `$FILE_NAME` в NTFS расходятся;
- время создания **позже** времени изменения;
- субсекундная точность не совпадает (одни — 0, другие — реальные наносекунды);
- время не попадает в общий кластер активности.

Эти несоответствия и есть ключ к флагу в CTF-задачах на timestomping.

## Инструменты

- **plaso / log2timeline / psort** — сбор и сортировка таймлайна.
- **sleuthkit (fls, mactime, istat)** — ФС-артефакты.
- **autopsy** — графический анализ.
- **timesketch** — совместный анализ таймлайнов.
- **evtx** — разбор Windows-логов.

## Разобранный пример

Дан образ, нужно найти файл, созданный «не в то время».

```bash
fls -r -m / disk.img > body.txt
mactime -b body.txt -d 2024-03-15 > t.csv
sort -t, -k1 t.csv | head -20
```

Ищем файл с временем создания, выбивающимся из кластера. В NTFS дополнительно сверяем `$SI` и `$FN`:

```bash
istat disk.img <inode>
```

Расхождение времён выдаёт подделку.

## Частые ошибки и подводные камни

- **Игнорирование часового пояса.** Метки в UTC и локальном времени путаются — приводите к одному.
- **Вера одной метке.** Смотрите все четыре (MACB) и их согласованность.
- **Пропуск субсекунд.** Аномалии часто в наносекундах.
- **Слишком большой таймлайн.** Фильтруйте по времени и типу.
- **Путаница источников.** Время из ФС и из логов может отличаться.

## Что дальше / решение

1. Соберите bodyfile (`fls -r -m`) или плазмо-таймлайн.
2. Отсортируйте и отфильтруйте по времени.
3. Ищите кластеры и аномалии (время создания позже изменения).
4. Для NTFS сверьте `$SI` и `$FN` (timestomping).
5. Сопоставьте таймлайн с логами для полноты картины.

## Таймлайн в контейнерах и облаке

В современных задачах события живут не только в ФС. Для контейнеров и облака источники другие:

- **Docker/containerd** — логи контейнеров, слои образов, `docker events`;
- **Kubernetes** — audit log (кто что делал с API), события подов;
- **Облако** — CloudTrail (AWS), Activity Log (Azure), Audit Log (GCP).

```bash
docker events --since 2024-03-15 --until 2024-03-16
kubectl get events --sort-by=.metadata.creationTimestamp
aws cloudtrail lookup-events --start-time 2024-03-15
```

В облачных логах важны поля `eventTime`, `userIdentity`, `sourceIPAddress` — они восстанавливают, кто и откуда выполнял действие.

## Субсекундная точность и её значение

Многие артефакты хранят время с точностью до наносекунд. При timestomping атакующий часто оставляет субсекундную часть равной нулю (потому что подставляет «круглое» время). Поэтому сравнение субсекундных частей у файлов в одной папке — быстрый способ найти подделку. В NTFS `$STANDARD_INFORMATION` хранит 100-наносекундные интервалы, а `$FILE_NAME` — тоже время, но записывается отдельно; их расхождение и есть улика.

## Частые вопросы по таймлайнам

- **Как быстро найти аномалию?** Отсортируйте по времени и ищите кластеры или «выпадающие» события.
- **Что если времена всех файлов одинаковы?** Возможно, образ был «выровнен» при упаковке — смотрите логами и USN.
- **Часовой пояс?** Приводите всё к UTC, иначе события «перепрыгивают».
- **Что важнее — M или B?** Для «когда создан» — B (birth); для «когда менялся» — M.

## Кейс: восстановление последовательности

Дано: образ, нужно понять порядок действий. Строим таймлайн и читаем «сюжет»:

```bash
fls -r -m / disk.img > body.txt
mactime -b body.txt -d > t.csv
sort -t, -k1 t.csv | head -40
```

Ищем связную историю: скачали архив → распаковали → запустили скрипт → удалили. Каждый шаг — событие с временем. Флаг часто лежит в файле, созданном на предпоследнем шаге.

## Аномалии как индикатор

Сравнивайте времена создания и изменения:

- файл создан **позже**, чем изменён — подделка;
- субсекундная часть у «системных» файлов равна нулю — timestomping;
- событие выбивается из кластера — возможно, добавлено вручную.

```python
import pandas as pd
df = pd.read_csv("t.csv", parse_dates=["time"])
df = df.sort_values("time")
df["gap"] = df["time"].diff()
print(df.nlargest(5, "gap"))   # большие паузы/перескоки
```

## Итог по таймлайнам

Таймлайн — универсальный инструмент форензики: он превращает разрозненные метки в связную хронологию. Соберите события (`fls`/`mactime` или plaso), отсортируйте, отфильтруйте по времени и ищите кластеры и аномалии. Для NTFS сверяйте `$SI`/`$FN`. В CTF именно таймлайн чаще всего вскрывает «что произошло» и приводит к файлу с флагом.

## Частые вопросы по таймлайнам (расширенно)

- **Какой инструмент выбрать?** Для ФС — `fls`+`mactime`; для «всего сразу» — plaso/log2timeline.
- **Что делать с гигантским таймлайном?** Фильтруйте по времени, типу и пути до разумного размера.
- **Как найти подделку времени?** Сверьте `$SI` и `$FN` в NTFS; ищите нулевую субсекундную часть.
- **Часовой пояс?** Приводите к UTC; иначе события «перескакивают».
- **Как связать с логами?** Наложите таймлайн ФС на события EVTX/syslog по времени.
