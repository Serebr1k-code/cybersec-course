## Вопрос, с которого всё начинается

Задача даёт файл `points.csv` — таблицу из тысяч строк с колонками `x` и `y`. В описании ни слова. Где здесь флаг? Иногда ответ прячется не в одной строке, а в **закономерности**: аномалии, частоте или даже картинке, которую образуют точки. Для этого и нужны навыки работы с данными.

## Наш пример: points.csv

Начинаем с загрузки и осмотра — как в прошлом уроке, только теперь инструмент не `strings`, а pandas:

```python
import pandas as pd
df = pd.read_csv("points.csv")
print(df.shape)
print(df.head())
```

```
(5120, 2)
      x     y
0  12.3  45.7
1  13.1  44.9
...
```

5120 строк, две колонки с координатами. `df.head()` показывает первые строки; `df.shape` — размер таблицы. Уже понятно, что это точки на плоскости.

## Шаг 1: описательная статистика

Прежде чем искать флаг, осмотрим данные целиком:

```python
print(df.describe())
print(df["x"].min(), df["x"].max())
```

```
              x             y
count  5120.0        5120.0
mean     50.2          49.8
std      28.7          28.9
min       0.1           0.2
max      99.9          99.8
```

Координаты лежат в диапазоне 0..100 — похоже на поле размером 100×100. `describe()` — метод pandas, который выдаёт count, mean, std, min, max по каждой числовой колонке. Это самый быстрый способ понять масштаб данных.

## Шаг 2: ищем аномалии

Если флаг — «выбивающаяся» строка, её находят статистикой. Классический приём — **z-score**: на сколько стандартных отклонений значение отличается от среднего.

```python
import numpy as np
z = np.abs((df.x - df.x.mean()) / df.x.std())
print(df[z > 3])
```

Если бы одна точка резко отличалась от остальных, она попала бы в вывод. В нашем случае выбросов нет — значит, дело не в отдельной строке. Пробуем другой взгляд.

## Шаг 3: визуализация — «нарисуй данные»

Самая недооценённая техника: построить график. Часто то, что не видно в числах, видно глазами.

```python
import matplotlib.pyplot as plt
plt.figure(figsize=(8, 8))
plt.scatter(df.x, df.y, s=1, c="black")
plt.axis("equal")
plt.axis("off")
plt.savefig("render.png")
```

`scatter` рисует каждую пару `(x, y)` точкой. `axis("equal")` сохраняет пропорции, `axis("off")` убирает рамку и оси. Открываем `render.png` — и видим, что точки образуют **текст**: флаг, выложенный координатами.

Это и есть ответ: данные — не таблица чисел, а картинка, закодированная в координатах. Приём «plot the data» вскрывает такие задачи за один вызов.

## Шаг 4: если данные — это лог

Похожая логика работает с логами. Дан `access.log` веб-сервера; разбираем его регуляркой в таблицу:

```python
import pandas as pd, re
rows = []
for line in open("access.log"):
    m = re.match(r'(\S+) - - \[(.*?)\] "(\S+) (\S+) .*?" (\d+) (\d+)', line)
    if m:
        rows.append(m.groups())
df = pd.DataFrame(rows, columns=["ip","time","method","path","status","size"])
print(df["ip"].value_counts().head())
```

`value_counts()` считает частоты — так находят брутфорс (много запросов с одного IP) или сканирование (много 404). Часто флаг лежит в пути редкого запроса.

## Шаг 5: большие файлы

Если CSV не влезает в память, читаем порциями:

```python
for chunk in pd.read_csv("huge.csv", chunksize=10**6):
    process(chunk)
```

`chunksize` возвращает данные блоками по миллиону строк. Внутри цикла обрабатываем каждый блок и не держим весь файл в памяти. Ещё быстрее — заменить циклы на операции NumPy над массивами (векторизация).

## Шаг 6: NumPy и векторизация

Когда строк миллионы, циклы Python слишком медленные. NumPy выполняет операции сразу над всем массивом на C и ускоряет код в десятки раз:

```python
import numpy as np
a = df.value.to_numpy()
z = np.abs((a - a.mean()) / a.std())
print(np.where(z > 4)[0][:10])
```

Здесь нет цикла: `(a - a.mean()) / a.std()` считается сразу для всех элементов. Приёмы, которые надо знать: **векторизация** (заменить цикл на операцию над массивом), **булевы маски** (`a[a > 0]`), **broadcasting** (операции между массивами разных форм), **агрегации** (`sum`, `mean`, `argmax`). В CTF это решает задачи, где наивный цикл не укладывается в таймаут.

## Шаг 7: временные ряды и аномалии

Если данные — метки времени, приведите их к `datetime` и работайте с окнами:

```python
df = pd.read_csv("events.csv", parse_dates=["ts"])
df = df.set_index("ts").sort_index()
print(df.resample("1min").size().head())
```

`resample("1min").size()` считает число событий в минуту; всплеск в одном окне — частый признак атаки или «правильного» действия.

Аномалии бывают разных видов:

- **числовой выброс** — одно значение резко отличается (z-score, IQR);
- **временной выброс** — событие вне кластера;
- **частотный выброс** — редкое значение в категориальном столбце;
- **структурный выброс** — строка с неверным числом полей.

```python
bad = [i for i, line in enumerate(open("data.csv")) if line.count(",") != 4]
print(bad[:10])
```

Структурный выброс — это строка, где число разделителей не совпадает с остальными. Часто именно она содержит флаг.

## Инструменты-помощники

Кроме pandas полезно держать под рукой CLI-утилиты:

- **jq** — быстрый разбор JSON (`curl ... | jq .`);
- **csvkit** — набор команд для CSV (`csvstat`, `csvgrep`);
- **awk** — однострочники по колонкам.

```
$ awk -F, '$3 > 100 {print $1}' data.csv | head
```

Если данные приходят в JSON-строках, `json_normalize` разворачивает вложенные объекты в колонки:

```python
import json
events = [json.loads(l) for l in open("events.jsonl")]
df = pd.json_normalize(events)
print(df["user"].value_counts())
```

Так глубоко вложенная структура (событие → пользователь → метаданные) превращается в плоскую таблицу, с которой снова работают `value_counts` и `groupby`. Если файл не парсится целиком, читайте его построчно — это часто спасает от падения на одной битой записи.

## Если не сработало

Данные не всегда «говорят» сами. Разберём, что мешает анализу.

**Колонок нет, файл — сплошная строка.** Определи разделитель и структуру: `head`, `awk -F`, проверь на табуляцию и `;`. Если строки фиксированной длины — режь по позициям. Если это лог — пиши парсер регуляркой.

**Статистика ничего не выделяет.** Возможно, сигнал не в значениях, а в *порядке* или *частоте*. Проверь сортировку, гистограммы, распределение по времени. Аномалия может быть одна на миллион строк — тогда не смотри на средние, ищи выбросы.

**Визуализация пустая.** Проверь, что данные действительно попали на график: оси, масштаб, пропуски (`NaN`). Иногда нужен лог-масштаб или другой тип графика (scatter вместо line).

**`pandas` не тянет объём.** Читай порциями (`chunksize`), фильтруй на лету, используй `dtype` (меньше памяти), или переходи на `polars`/`duckdb`. Для разового анализа `awk`/`grep` часто быстрее.

**NumPy не ускоряет.** Векторизация помогает только при операциях над массивами целиком. Если ты в цикле обращаешься к элементам — выигрыша нет. Переписывай на срезы и `np.where`/`np.select`.

**Временной ряд шумит.** Сгладь (скользящее среднее), выдели тренд и сезонность, ищи сдвиги (changepoint). Аномалия — это отклонение от *предсказанного* значения, а не от среднего.

## Частые вопросы

**Когда pandas, а когда numpy?** pandas — таблицы с именованными колонками и разными типами. numpy — однородные числовые массивы и математика. Для тяжёлых вычислений сначала переведи данные в numpy-массив.

**Что такое выброс?** Значение, резко отличающееся от остальных. Это может быть ошибка ввода, а может — искомая аномалия (флаг, мошенничество). Контекст решает.

**Зачем визуализация, если есть числа?** Глаз замечает структуру (кластеры, дырки, шаблоны), которую сводные статистики прячут. «Нарисуй данные» — частый совет в CTF.

**Как быстро разобрать неизвестный CSV?** `head` для структуры, `wc -l` для размера, `awk -F, '{print $3}' | sort | uniq -c` для распределения по колонке. Это дешевле, чем сразу грузить в pandas.

## Порядок анализа данных

Начни с «паспорта» датасета: размер (`wc -l`, `ls -la`), структура (`head`), типы колонок, пропуски. Затем — описательные статистики (min/max/среднее/медиана) и распределения. Только потом — визуализация и поиск аномалий. Такой порядок не даёт утонуть в деталях раньше времени.

Для поиска аномалий используй несколько методов: z-оценку, IQR (межквартильный размах), расстояние до ближайших соседей. Один метод может пропустить выброс, который найдёт другой. Если данные — временной ряд, смотри тренд, сезонность и сдвиги, а не только отдельные значения. И помни: «аномалия» может быть искомым ответом (флагом), а может — ошибкой ввода; контекст задачи решает.

## Что мы теперь знаем

По-простому:

1. Задачи на данные решают через pandas: загрузка, осмотр, фильтрация.
2. `describe()` и `value_counts()` — самый быстрый способ понять датасет.
3. Аномалии ищут статистикой (z-score) или частотой.
4. Визуализация (`scatter`, `hist`) часто вскрывает то, что не видно в числах.
5. Большие файлы читают порциями (`chunksize`) и векторизуют.

## На что смотреть дальше

- **Не загружайте гигантский файл целиком.** Используйте `chunksize` и `usecols`.
- **Проверяйте пропуски.** `NaN` ломает статистику: `dropna` или `fillna`.
- **Следите за типами.** Числа, прочитанные как строки, ломают арифметику (`astype`, `to_numeric`).
- **Всегда стройте график.** Глазами видно то, что не видно в числах.
- **Не переусложняйте.** Часто достаточно `value_counts` и одного scatter.
