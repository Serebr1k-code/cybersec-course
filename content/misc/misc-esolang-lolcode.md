## Вопрос, с которого всё начинается

Тебе дали файл `program.lol`. Открываешь — а там:

```
HAI 1.2
  VISIBLE "HAI WORLD!!!1!"
KTHXBYE
```

Это **LOLCODE** — язык, где синтаксис построен на «кошачьем» интернет-сленге. Задача может быть сложнее: посчитать что-то, расшифровать строку. Как исполнять такой код и читать его логику?

## Наш пример: считаем сумму

```
$ cat sum.lol
HAI 1.2
  I HAS A X
  GIMMEH X
  I HAS A Y
  GIMMEH Y
  VISIBLE SUM OF X AN Y
KTHXBYE
$ lci sum.lol
3
4
7
```

Программа просит два числа и печатает сумму. Разберём синтаксис по кусочкам.

## Шаг 1: каркас программы

Любая программа начинается с `HAI` (версия) и заканчивается `KTHXBYE`. Между ними — тело. Отступы необязательны, но улучшают читаемость. `BTW` — комментарий до конца строки, `OBTW ... TLDR` — блочный.

Это первый ориентир: увидел `HAI`/`KTHXBYE` — перед тобой LOLCODE.

## Шаг 2: переменные

Объявление: `I HAS A <имя>`. Присваивание: `<имя> R <значение>`.

```
I HAS A NAME
NAME R "World"
VISIBLE "HAI " AN NAME
```

`AN` — конкатенация строк (или просто соединитель). Переменные слабо типизированы: могут хранить число, строку, массив (BUKKIT).

## Шаг 3: ввод и вывод

- `VISIBLE <выражение>` — печать.
- `GIMMEH <имя>` — чтение строки в переменную.

```
GIMMEH X      BTW читает строку в X
VISIBLE X     BTW печатает
```

Числа при чтении остаются строками; арифметика приводит их автоматически.

## Шаг 4: выражения и операторы

Арифметика записывается словами:

| LOLCODE | Смысл |
|---|---|
| SUM OF a AN b | a + b |
| DIFF OF a AN b | a - b |
| PRODUKT OF a AN b | a * b |
| QUOSHUNT OF a AN b | a / b |
| MOD OF a AN b | a % b |
| BIGGR OF a AN b | max |

Логика: `BOTH OF` (и), `EITHER OF` (или), `NOT`. Сравнение: `BOTH SAEM a AN b`.

## Шаг 5: условия

```
O RLY?
  YA RLY
    VISIBLE "yes"
  NO WAI
    VISIBLE "no"
OIC
```

`O RLY?` проверяет последнее выражение (обычно сравнение), `YA RLY` — ветка «истина», `NO WAI` — «ложь», `OIC` — конец.

## Шаг 6: циклы

```
IM IN YR LOOP
  VISIBLE N
  N R SUM OF N AN 1
  BOTH SAEM N AN 10, O RLY?
    YA RLY, GTFO
  OIC
IM OUTTA YR LOOP
```

`IM IN YR <метка>` … `IM OUTTA YR <метка>` — цикл; `GTFO` — выход.

## Шаг 7: интерполяция и «:»-модификатор

Некоторые конструкции имеют «взрывной» вариант через `!` и интерполяцию через `:`. Например, `VISIBLE "value: " : X` подставляет значение. Это делает вывод похожим на шаблоны.

## Шаг 8: запуск и интерпретаторы

Официальный интерпретатор — `lci` (LOLCODE interpreter). Альтернативы: реализации на Python (`lolcode`), JS. Если `lci` нет, ставят из пакета или пишут свой интерпретатор — язык небольшой.

```
$ lci program.lol
HAI WORLD!!!1!
```

## Полный прогон

```
$ cat flag.lol
HAI 1.2
  VISIBLE "nto{l0lc0d3_h41_w0rld}"
KTHXBYE
$ lci flag.lol
nto{l0lc0d3_h41_w0rld}
```

Задача свелась к исполнению программы.

## Как решать LOLCODE-задачи

- Распознай язык по `HAI`/`KTHXBYE`.
- Найди интерпретатор (`lci`) или переведи вручную.
- Для «вычислительных» задач — трассируй переменные.
- Для задач с шифром — прочитай логику и повтори её на Python.

## Что мы теперь знаем

- LOLCODE — Тьюринг-полный язык с «кошачьим» синтаксисом.
- Каркас: HAI/KTHXBYE; переменные I HAS A; ввод GIMMEH, вывод VISIBLE.
- Арифметика и логика записываются словами.
- Условия O RLY?/YA RLY/NO WAI/OIC, циклы IM IN YR.
- Исполняется через `lci`.

## Типы и приведение

LOLCODE слабо типизирован: значение может быть числом (NUMBR), числом с плавающей точкой (NUMBAR), строкой (YARN) или массивом (BUKKIT). При арифметике строка приводится к числу, если возможно. При конкатенации число превращается в строку. Понимание приведения важно при трассировке: `SUM OF "3" AN "4"` даёт 7, а не "34".

## Массивы BUKKIT

Массив объявляется как `I HAS A arr ITZ A BUKKIT`. Элементы: `arr HAS A key ITZ value`, доступ — `arr'Z key`. Ключи — строки. Это ассоциативный массив, а не список с индексами. В задачах через BUKKIT часто строят таблицы подстановки для шифра.

## Функции

Функция объявляется `HOW IZ I name ... IF U SAY SO`, вызывается `I IZ name YR arg MKAY`. Внутри — `FOUND YR value` для возврата. Функции позволяют разбить логику, и в больших .lol-программах без них не обойтись.

## Типичные ошибки разбора

LOLCODE прощает многое, но путаница возникает с: отступами (незначимы, но путают), регистром (команды обычно заглавными), и «взрывными» вариантами операторов (`!` в конце). Читая чужой код, выписывай присваивания отдельно от выражений.

## Написание интерпретатора

LOLCODE достаточно прост, чтобы написать интерпретатор на Python за вечер: лексер по строкам, разбор присваиваний и VISIBLE, вычисление выражений. Это отличная тренировка перед `misc-interpreter-write`. Начни с подмножества: HAI/KTHXBYE, I HAS A, R, VISIBLE.

## Пример: расшифровка

Пусть программа читает строку и прибавляет к каждому символу 1. Тогда для расшифровки вычитаешь 1. Такие «сдвиговые» задачи на LOLCODE решаются трассировкой одной итерации и повторением на Python. Логика важнее синтаксиса.

## Шпаргалка

`HAI`/`KTHXBYE` — каркас; `I HAS A` — объявление; `R` — присваивание; `VISIBLE`/`GIMMEH` — вывод/ввод; `SUM OF ... AN ...` — арифметика; `O RLY?`/`YA RLY`/`NO WAI`/`OIC` — условие; `IM IN YR`/`IM OUTTA YR` — цикл; `GTFO` — break. Держи это под рукой.

## Почему это полезно

LOLCODE — пример языка, где читаемость для человека достигается ценой многословия. Разбирая его, ты тренируешь навык: видеть за «болтовнёй» формальную структуру (присваивания, ветвления, циклы). Этот навык переносится на любой незнакомый язык и DSL.

## Как распознать LOLCODE в задаче

Признаки: строки `HAI` и `KTHXBYE`, слова `VISIBLE`, `GIMMEH`, `I HAS A`, конструкции `O RLY?`/`YA RLY`/`OIC`, восклицания и «кошачий» сленг. Даже обфусцированный LOLCODE сохраняет эти ключевые слова, потому что парсер ищет именно их. Увидев `HAI`, ты знаешь язык и можешь искать интерпретатор.

## Перевод LOLCODE в Python

Самый надёжный способ решить сложную задачу — перевести её в Python. Присваивания становятся переменными, `VISIBLE` — `print`, `GIMMEH` — `input`, арифметика — обычными операторами. Условия `O RLY?` — `if`, циклы `IM IN YR` — `while`. После перевода задача решается стандартными средствами, а логика становится видимой.

## Отладка без интерпретатора

Если `lci` недоступен, исполняй вручную: выписывай переменные и обновляй их построчно. Для циклов — таблица «итерация → значения». Для строковой интерполяции — подставляй значения вручную. Это медленно, но для коротких программ быстрее, чем ставить интерпретатор.

## Упражнение: трассировка цикла

Возьми цикл `IM IN YR LOOP`, который прибавляет 1 к N до 10 и печатает N. Выпиши значения N на каждой итерации: 1..10. Теперь представь, что тело печатает `N * 2` — получишь 2,4,...,20. Такая трассировка — базовый навык для любой esolang-задачи.

## Итог

LOLCODE учит читать формальную структуру за многословием: присваивания, ветвления, циклы, функции. Навык перевода в Python универсален. Если видишь `HAI`/`KTHXBYE` — это LOLCODE, и задача решается исполнением или переводом.

## Практический вывод

LOLCODE-задачи почти всегда решаются одним из двух путей: запустить `lci` или перевести в Python. Первый быстрее, второй надёжнее для сложной логики. В обоих случаях ключ — распознать язык по `HAI`/`KTHXBYE` и понять поток данных. Не трать время на попытки «угадать» вывод — исполни или переведи.

## Что тренирует этот язык

Разбор LOLCODE тренирует навык «структурного чтения»: за необычным синтаксисом видеть стандартные конструкции. Присваивание, условие, цикл, функция — есть в любом языке. Научившись находить их в LOLCODE, ты легче разбираешь незнакомые DSL и обфусцированный код.

## Частый сценарий CTF

В задаче дан `.lol`-файл, который что-то печатает или преобразует. Если он просто печатает строку — флаг виден сразу. Если считает — переводишь арифметику в Python. Если читает ввод — подставляешь данные. Ответ почти всегда получается за несколько минут после распознавания языка.

## Финальная мысль

LOLCODE — не «шутка ради шутки»: это полноценный язык, и его разбор оттачивает универсальный навык — превращать незнакомый синтаксис в знакомые конструкции. Начни с `lci`, а если его нет — переведи программу в Python. Главное — не пугаться «кошачьего» вида: под ним обычные присваивания, условия и циклы.
