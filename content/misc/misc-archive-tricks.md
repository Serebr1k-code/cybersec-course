Архивы — один из самых частых сюжетов misc: внутри архива архив, внутри пароль, пароль в комментарии, а сам архив — полиглот с картинкой. Понимание внутренней структуры ZIP и tar превращает «магический» пароль в рутинную операцию. Разберём форматы, атаки и восстановление.

## Структура ZIP

ZIP — это последовательность **local file headers**, затем **central directory** и **end of central directory (EOCD)**. Каждый файл имеет локальный заголовок с сигнатурой `PK\x03\x04`, именем, методом сжатия и (опционально) **флагами шифрования**. В конце — центральный каталог (`PK\x01\x02`) и EOCD (`PK\x05\x06`).

```bash
unzip -l archive.zip
#  Length      Date    Time    Name
# --------  ---------- -----   ----
#      123  2024-01-01 00:00   flag.txt
# --------                     -------
#      123                     1 file

zipinfo -v archive.zip | head -40
# показывает метод сжатия, флаги, CRC
```

Важно: имена файлов видны даже без пароля (в локальных заголовках), если не включён флаг шифрования имён.

## Пароли и zipcrypto

Классический ZIP шифрует **zipcrypto** — слабый потоковый шифр. Известные атаки:

- **Known-plaintext (bkcrack)**: если у вас есть хотя бы 12 байт известного открытого текста (например, стандартный `PK\x03\x04` или известный файл внутри), можно восстановить ключи и расшифровать весь архив без пароля.
- **Brute force**: `fcrackzip -b -u -D -p rockyou.txt archive.zip` — только для простых паролей.
- **Zip2John + John**: `zip2john archive.zip > h.txt; john h.txt --wordlist=rockyou.txt`.

```bash
# известный открытый текст → ключи → расшифровка
bkcrack -C archive.zip -c secret.txt -p known.txt
# получив ключи:
bkcrack -C archive.zip -k <key0> <key1> <key2> -U out.zip newpass
```

Пароли ищут также в **комментарии архива**, в именах файлов, в EXIF картинки-полиглота — это типичный CTF-приём.

## tar: структура и трюки

tar — последовательность блоков по 512 байт. Каждый файл: заголовок 512 байт (имя, права, размер) + данные, выровненные до 512. Магия `ustar` — по смещению 257.

```bash
tar tvf archive.tar
tar xvf archive.tar -C out/
# GNU tar умеет списки, --strip-components, --wildcards
tar xvf archive.tar --wildcards '*.txt'
```

Трюки:

- **tar в tar** — вложенность; рекурсивно распаковывать.
- **Скрытые файлы** — начинаются с точки; `tar tvf` покажет все.
- **Пути с `../`** — path traversal (в реальных CVE), при распаковке осторожно.
- **Разреженные файлы** и длинные имена (GNU-расширения).

## 7z и другие

`7z l archive.7z` — список, `7z x` — распаковка. 7z использует AES-256 (сильнее zipcrypto), поэтому brute force почти безнадёжен — ищите пароль в метаданных. RAR аналогично. Также встречаются: `lz4`, `zstd` (`zstd -d`), `xz`, `bzip2`. Определить метод сжатия поможет `binwalk` и `file`.

## Вложенные архивы и автоматизация

Частый квест: 100 архивов, каждый с паролем, который — имя предыдущего. Автоматизация на Python:

```python
import zipfile, re
pwd = None
for i in range(1, 101):
    fn = f"layer{i}.zip"
    with zipfile.ZipFile(fn) as z:
        if pwd:
            z.extractall(path=f"out{i}", pwd=pwd.encode())
        else:
            z.extractall(path=f"out{i}")
        names = z.namelist()
        # пароль для следующего — из имени/содержимого
        pwd = names[0].replace('.zip','')
```

Или `unzip -P "$pwd" next.zip`. Ключ — вытащить пароль из предыдущего слоя.

## Полиглоты: архив + картинка

ZIP можно **дописать** в конец PNG/JPEG: картинка остаётся валидной, а `unzip` находит архив по EOCD в конце. Инструменты: `cat image.png archive.zip > poly.png`. Проверка:

```bash
file poly.png
# poly.png: PNG image data ...
binwalk poly.png
# 0    0x0     PNG image
# 1234 0x4D2   Zip archive data
unzip poly.png
```

Обратный случай: ZIP, начинающийся с картинки (SFX-подобный). `binwalk` и `unzip -o` справляются.

## Восстановление повреждённых архивов

- **`zip -FF broken.zip --out fixed.zip`** — исправление central directory.
- **`unzip -FF`** — то же.
- Если обрезан EOCD — ручное восстановление через поиск `PK\x01\x02` и `PK\x05\x06`.
- `7z x -y` часто распаковывает больше, чем `unzip`.

```bash
zip -FF broken.zip --out fixed.zip
# Fix archive? (y/n) y
unzip fixed.zip
```

## Частые ошибки и подводные камни

- Пытаться brute-force AES-7z/rar — бессмысленно без слабого пароля; ищите пароль.
- Не смотреть комментарий архива (`unzip -z archive.zip`).
- Забывать про вложенные слои — «распаковалось, но пусто» = внутри ещё архив.
- Игнорировать кодировку имён (CP866/UTF-8) — `unzip -O cp866`.
- Считать, что картинка «не архив», не прогнав `binwalk`.
- Терять восстановленный архив, распаковывая «в текущую папку» — используйте `-d`.

## Дополнительная теория: центральный каталог и восстановление

ZIP-файл читается **с конца**: `unzip` находит EOCD (`PK\x05\x06`), из него — смещение центрального каталога (`PK\x01\x02`), из каталога — локальные заголовки (`PK\x03\x04`). Поэтому ZIP можно **дописывать** (полиглот), а также восстанавливать при повреждении: если центральный каталог утерян, но локальные заголовки целы, можно пересобрать каталог. `zip -FF` и `7z` умеют это. Ручное восстановление: найти все `PK\x03\x04`, прочитать имена и размеры, собрать новый архив.

Ещё одна особенность — **data descriptors**: когда размер/CRC неизвестны заранее (потоковая запись), они пишутся **после** данных, а в локальном заголовке стоят нули. Это ломает наивные парсеры. Флаг в general purpose bit 3 указывает на наличие data descriptor. Учитывайте это при ручном разборе.

## Вложенность, рекурсия и автоматизация

CTF любит вложенность: архив в архиве в архиве, иногда 100+ слоёв. Автоматизируйте: скрипт, который распаковывает, находит следующий архив, повторяет. Учитывайте разные форматы (zip/tar/gz/bz2/xz/7z) и пароли, вытащенные из предыдущих слоёв. Иногда пароль — это имя файла, хеш содержимого или строка из комментария. Инструмент `binwalk -e --run-as=root` может распаковать многое автоматически, но при паролях нужен свой скрипт. Логируйте каждый слой: имя, формат, пароль, результат.

```python
import subprocess, os, glob
def unpack_all(d):
    changed = True
    while changed:
        changed = False
        for f in glob.glob(d + '/**/*', recursive=True):
            if f.endswith(('.zip','.tar','.gz','.bz2','.xz','.7z')):
                out = f + '_x'
                subprocess.run(['7z','x','-o'+out,f], capture_output=True)
                changed = True
```

## Разбор ошибок и отладка

Если `unzip` сообщает «неверный пароль» на пустом вводе — возможно, архив не зашифрован, а повреждён; попробуйте `7z x`. Если «пропущено N файлов» — часть повреждена; используйте `zip -FF`. Если полиглот «не распаковывается» — проверьте `binwalk` и `unzip -o poly.png` (unzip ищет EOCD с конца). Если пароль не подбирается brute-force — ищите его в метаданных (`unzip -z`, `exiftool`). Если архив «пустой» — возможно, имена файлов в неверной кодировке (`unzip -O cp866`). Всегда проверяйте комментарий архива — это классическое место для подсказки.

## Практический разбор: bkcrack known-plaintext

Дано: `secret.zip` с паролем, внутри `flag.txt`. Известно, что внутри также есть `README.md` со стандартным содержимым (например, известная лицензия). Zipcrypto позволяет восстановить ключи по ~12 байтам известного открытого текста.

```bash
# проверяем список файлов
unzip -l secret.zip
# README.md, flag.txt

# bkcrack требует минимум 12 байт plaintext (например, известное начало README)
printf '# My Project\n' > known.txt
bkcrack -C secret.zip -c README.md -p known.txt
# Keys: 12345678 9abcdef0 11223344

# получив ключи, расшифровываем flag.txt без пароля
bkcrack -C secret.zip -c flag.txt -k 12345678 9abcdef0 11223344 -d flag.out
cat flag.out
```

Если известного файла нет — используйте стандартные заголовки: локальный заголовок ZIP (`PK\x03\x04`) частично известен, но 12 байт нужно набрать. Часто в CTF внутри лежит файл с предсказуемым содержимым (пустой файл, известный текст, PNG с известными первыми байтами). Если файл сжат `deflate`, bkcrack работает со сжатым потоком — нужен известный **сжатый** plaintext (для метода deflate есть специальные утилиты). Как fallback — `fcrackzip`/`zip2john` для слабых паролей.
