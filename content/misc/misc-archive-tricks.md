## Вопрос, с которого всё начинается

Мы научились определять форматы и разбирать структурированный текст. Теперь дают **архив** `secret.zip`, и он закрыт паролем. Перебирать пароли вслепую — тупик. Но архивы устроены предсказуемо, и это даёт куда более умные пути.

Разберём один запертый архив и откроем его без перебора.

## Наш пример: secret.zip

```bash
$ unzip -l secret.zip
Archive:  secret.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
      512  2024-01-01 00:00   README.md
       42  2024-01-01 00:00   flag.txt
```

Два файла: `README.md` и `flag.txt`. Обратите внимание: **имена видны без пароля** — они лежат в открытых локальных заголовках, если не включено шифрование имён. Проверим комментарий архива — классическое место для подсказки:

```bash
$ unzip -z secret.zip
Archive:  secret.zip
Hint: README.md is a standard template
```

Подсказка: содержимое `README.md` известно (стандартный шаблон). Это открывает путь к **known-plaintext** атаке.

## Шаг 1: как устроен ZIP

ZIP — это последовательность **локальных заголовков** (`PK\x03\x04`) с именами и размерами файлов, затем **центральный каталог** (`PK\x01\x02`) и **конец каталога** (EOCD, `PK\x05\x06`).

Читается архив **с конца**: `unzip` находит EOCD, из него — смещение каталога, из каталога — файлы. Именно поэтому ZIP можно дописывать в конец картинки (полиглот) — он всё равно находится с конца.

Разбор деталей даёт `zipinfo -v`: метод сжатия, флаги, CRC.

## Шаг 2: zipcrypto — слабое шифрование

Классический ZIP шифрует **zipcrypto** — старый потоковый шифр. Его слабость: если известны хотя бы ~12 байт **открытого текста** одного из файлов, ключи восстанавливаются, и весь архив расшифровывается **без пароля**.

У нас как раз есть известный файл. Создаём его и запускаем `bkcrack`:

```bash
$ printf '# My Project\n' > known.txt
$ bkcrack -C secret.zip -c README.md -p known.txt
Keys: 12345678 9abcdef0 11223344
```

Получили три ключа. Теперь расшифровываем `flag.txt` прямо ими:

```bash
$ bkcrack -C secret.zip -c flag.txt -k 12345678 9abcdef0 11223344 -d flag.out
$ cat flag.out
flag{kn0wn_pl41nt3xt}
```

Флаг без единой попытки пароля. Это самый «взрослый» приём в архивах.

## Шаг 3: если известного текста нет

Тогда остаются:

- **Перебор по словарю** — только для простых паролей: `fcrackzip -b -u -D -p rockyou.txt secret.zip`.
- **Zip2John + John**: `zip2john secret.zip > h.txt; john h.txt --wordlist=rockyou.txt`.

А чаще всего пароль **где-то лежит**: в комментарии архива, в именах файлов, в EXIF картинки-полиглота. Это типичный CTF-приём — не ломать, а найти.

## Шаг 4: tar и его особенности

tar — последовательность блоков по 512 байт: заголовок (имя, права, размер) + данные. Магия `ustar` — по смещению 257.

```bash
$ tar tvf archive.tar
$ tar xvf archive.tar --wildcards '*.txt'
```

Трюки: **tar в tar** (рекурсивно распаковывать), **скрытые файлы** с точкой (их видно в `tar tvf`), пути с `../` (path traversal в реальных CVE — при распаковке осторожно).

## Шаг 5: 7z, RAR и другие

```bash
$ 7z l archive.7z      # список
$ 7z x archive.7z      # распаковка
```

7z и RAR используют **AES-256** — перебор практически безнадёжен, ищите пароль в метаданных. Ещё встречаются `zstd -d`, `xz`, `bzip2`; определить метод поможет `file` и `binwalk`.

## Шаг 6: полиглот архив + картинка

ZIP можно **дописать** в конец PNG — картинка остаётся валидной, а `unzip` находит архив по EOCD:

```bash
$ cat image.png archive.zip > poly.png
$ file poly.png
poly.png: PNG image data, ...
$ binwalk poly.png
0             0x0             PNG image
1234          0x4D2           Zip archive data
$ unzip poly.png
```

Именно поэтому «просто картинку» всегда стоит прогнать через `binwalk`.

## Шаг 7: вложенность и автоматизация

CTF любит вложенность: архив в архиве, иногда 100+ слоёв, и пароль каждого слоя — имя файла из предыдущего. Распаковывать вручную долго — пишем скрипт:

```python
import zipfile
pwd = None
for i in range(1, 101):
    fn = f"layer{i}.zip"
    with zipfile.ZipFile(fn) as z:
        z.extractall(path=f"out{i}", pwd=pwd.encode() if pwd else None)
        names = z.namelist()
        pwd = names[0].replace('.zip', '')   # пароль следующего слоя
```

Ключ — вытащить пароль из предыдущего слоя (имя файла, комментарий, содержимое). Логируйте каждый слой: имя, формат, пароль, результат.

## Шаг 8: восстановление повреждённых архивов

Архив может быть обрезан или с испорченным центральным каталогом. Тогда:

```bash
$ zip -FF broken.zip --out fixed.zip
$ unzip fixed.zip
```

`-FF` пересобирает структуру по уцелевшим локальным заголовкам. `7z x -y` часто распаковывает больше, чем `unzip`. А если EOCD утерян — вручную ищут `PK\x01\x02` и `PK\x05\x06`.

Особая деталь — **data descriptors**: при потоковой записи размер и CRC пишутся **после** данных, а в локальном заголовке стоят нули. Флаг в general purpose bit 3 указывает на это; учитывайте при ручном разборе.

## Шаг 9: пароль в метаданных

Прежде чем ломать архив, поищите пароль рядом — это быстрее любой атаки:

```bash
$ unzip -z secret.zip          # комментарий архива
$ zipinfo -v secret.zip        # имена, флаги, CRC
$ exiftool poly.png            # если архив внутри картинки
$ strings archive.zip | grep -i pass
```

Пароль часто лежит в комментарии архива, в имени файла, в EXIF картинки-полиглота или в подсказке задачи. «Не ломать, а найти» — главный принцип CTF-архивов.

## Что мы теперь знаем

- ZIP читается с конца (EOCD), поэтому его можно дописывать (полиглот).
- Имена файлов видны без пароля; комментарий (`unzip -z`) — частое место подсказки.
- zipcrypto ломается known-plaintext атакой `bkcrack` по ~12 байтам известного текста.
- 7z/RAR используют AES — перебор бессмыслен, пароль ищут в метаданных.
- Вложенные архивы распаковывают рекурсивно и автоматизируют скриптом.
- Повреждённый ZIP чинит `zip -FF broken.zip --out fixed.zip`.

## На что смотреть дальше

- **Brute-force против AES-7z/RAR** — безнадёжно без слабого пароля; ищите пароль.
- **Не смотреть комментарий** — `unzip -z` показывает подсказку.
- **Забыть про вложенность** — «распаковалось, но пусто» = внутри ещё архив.
- **Кодировка имён** — CP866/UTF-8; помогает `unzip -O cp866`.
- **Считать, что картинка не архив** — прогоните `binwalk`.
- **Распаковывать в текущую папку** — теряете восстановленное; используйте `-d`.

## Справочная таблица

| Задача | Команда |
|--------|---------|
| Список ZIP | `unzip -l`, `zipinfo -v` |
| Комментарий | `unzip -z archive.zip` |
| Brute-force ZIP | `fcrackzip -b -u -D -p rockyou.txt a.zip` |
| Zip→John | `zip2john a.zip > h.txt; john h.txt` |
| Known-plaintext | `bkcrack -C a.zip -c f -p known` |

| 7z | `7z l`, `7z x` |
| Полиглот | `binwalk poly.png` |
