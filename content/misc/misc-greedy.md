## Вопрос, с которого всё начинается

В прошлом уроке мы искали геометрический ответ. Теперь задача другая: у нас есть список дел с временем начала и конца, и нужно **успеть максимум**. Собственно, именно такие задачи — про «уложи максимум» и «потрать минимум» — решает **жадный алгоритм**: на каждом шаге выбираем локально лучший вариант и больше к нему не возвращаемся.

Вопрос только один: **какой выбор считать лучшим?** Интуиция здесь часто врёт, и в этом вся суть урока.

## Наш пример: список встреч

Дан список интервалов `[начало, конец)` — это встречи в календаре:

```python
meetings = [(1,3), (2,4), (3,5), (0,6), (5,7)]
```

Нужно выбрать максимум встреч так, чтобы они не пересекались. Первое, что приходит в голову: «брать самые короткие» или «брать те, что начинаются раньше». Проверим.

## Шаг 1: пробуем в лоб — и ошибаемся

Сортируем по **началу** и жадно берём всё, что начинается не раньше конца предыдущей:

```python
def by_start(intervals):
    intervals.sort(key=lambda iv: iv[0])
    chosen, last_end = [], float('-inf')
    for s, e in intervals:
        if s >= last_end:
            chosen.append((s, e)); last_end = e
    return chosen

print(by_start([(1,3),(2,4),(3,5),(0,6),(5,7)]))
```

```
[(0, 6)]
```

Всего одна встреча! А можно было взять три. Значит, сортировка по началу — **неверная стратегия**: длинная встреча `(0,6)` «съела» весь день.

Это и есть мотивация жадного алгоритма: порядок обработки решает всё.

## Шаг 2: правильный ключ — время окончания

Сортируем по **концу** и берём всё, что начинается не раньше конца последней выбранной:

```python
def max_non_overlapping(intervals):
    intervals.sort(key=lambda iv: iv[1])   # по КОНЦУ
    chosen, last_end = [], float('-inf')
    for s, e in intervals:
        if s >= last_end:
            chosen.append((s, e)); last_end = e
    return chosen

print(max_non_overlapping([(1,3),(2,4),(3,5),(0,6),(5,7)]))
```

```
[(1, 3), (3, 5), (5, 7)]
```

Три встречи — оптимум. Логика: встреча, которая кончается раньше, оставляет больше времени на всё остальное. Это и есть **свойство жадного выбора** — существует оптимальное решение, начинающееся с самого «раннего по концу» выбора.

## Шаг 3: сортировка — ключ и стабильность

Раз ключ сортировки так важен, разберёмся с ним. В Python `sorted(..., key=...)` принимает функцию, а `key` может возвращать кортеж — тогда сортировка идёт по нескольким полям:

```python
items = [("a", 2), ("b", 1), ("c", 2)]
print(sorted(items, key=lambda x: (x[1], x[0])))
```

```
[('b', 1), ('a', 2), ('c', 2)]
```

Сортировка в Python **стабильна**: равные элементы сохраняют исходный порядок. Это позволяет «хитрить» — сортировать в несколько проходов.

## Шаг 4: когда предметы делимы — дробный рюкзак

Жадность работает не только с интервалами. Другой сюжет: есть рюкзак вместимостью `W` и предметы с весом и ценой. Если предметы **можно резать** (делимая задача, «дробный рюкзак»), оптимально брать в порядке убывания `цена/вес`:

```python
def fractional_knapsack(items, W):
    items.sort(key=lambda it: it[1]/it[0], reverse=True)  # по value/weight
    total = 0.0
    for weight, value in items:
        take = min(weight, W)
        total += value * take / weight
        W -= take
        if W == 0:
            break
    return total
```

Жадность здесь верна, потому что любой кусочек предмета одинаково «полезен» — можно добрать остаток лучшим соотношением.

## Шаг 5: когда жадность ломается

А теперь ловушка. Если предметы **неделимы** (0/1-рюкзак: либо берём целиком, либо нет), жадность по `value/weight` даёт **неоптимальный** ответ. Контрпример: рюкзак на 10, предметы `(вес 6, цена 6)` и `(вес 5, цена 5)`. Жадность возьмёт первый (соотношение 1.0, но вес 6), потом не влезет второй, итог 6. А оптимум — взять второй и… тут нужен полный перебор вариантов, то есть **динамическое программирование**.

То же с разменом монет: для номиналов `{1, 5, 10, 25}` жадность оптимальна, а для `{1, 3, 4}` и суммы 6 — нет (жадность: 4+1+1, оптимум: 3+3).

Правило: **перед тем как довериться жадности, проверьте её брутфорсом на маленьких входах**. Если расходится — переходите к ДП.

## Шаг 6: когда «правильный порядок» не выражается ключом

Иногда жадный критерий — не поле, а **сравнение пар**. Классика: «составить наибольшее число из фрагментов». Сравнивать нужно не сами фрагменты, а их склейки `a+b` и `b+a`:

```python
from functools import cmp_to_key
def largest_number(parts):
    parts = list(map(str, parts))
    parts.sort(key=cmp_to_key(lambda a, b: -1 if a+b > b+a else (1 if a+b < b+a else 0)))
    return ''.join(parts)

print(largest_number([3, 30, 34, 5, 9]))   # 9534330
```

Сортировка по значению или по первой цифре дала бы неверный результат. `cmp_to_key` — способ задать нестандартный жадный критерий.

## Шаг 7: почему жадность вообще бывает верна

Теоретическое объяснение корректности жадности — **матроиды**. Если система «независимых множеств» образует матроид, то жадный алгоритм (сортировка по весу и добавление, пока множество остаётся независимым) даёт максимум.

Пример — минимальное остовное дерево (алгоритм Краскала): сортируем рёбра по весу и добавляем, если не образуется цикл.

```python
def kruskal(n, edges):
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]; x = parent[x]
        return x
    total = 0
    for w, u, v in sorted(edges):
        ru, rv = find(u), find(v)
        if ru != rv:
            parent[ru] = rv; total += w
    return total
```

Это тоже жадность — но доказанно оптимальная, потому что «не образует цикл» задаёт матроид.

## Что мы теперь знаем

- Жадный алгоритм выбирает локально лучший вариант и не возвращается назад; обычно это `O(n log n)` из-за сортировки.
- Для максимума непересекающихся интервалов сортируют **по времени окончания**, а не по началу.
- `key` умеет сортировать по кортежу полей; сортировка в Python стабильна.
- Дробный рюкзак решается жадностью по `цена/вес`; 0/1-рюкзак — нет.
- Жадность надо проверять контрпримером, иначе получите WA на скрытых тестах.

## На что смотреть дальше

- **Сортировка не по тому ключу** — самая частая ошибка; для интервалов ключ — конец.
- **Делимые и неделимые предметы** — это разные задачи; не путайте дробный и 0/1-рюкзак.
- **Проверка достижимости** — жадный выбор может завести в тупик (например, нет заправки впереди) — нужен код `-1`.
- **Max-куча на `heapq`** — Python умеет только min-кучу; для максимума кладите `-x` и следите за типами.
- **Когда нужна куча** — если на каждом шаге нужен текущий минимум/максимум (Хаффман, Dijkstra).

## Справочная таблица

| Задача | Жадный критерий | Сложность |
|--------|-----------------|-----------|
| Макс. непересек. интервалы | сортировка по концу | O(n log n) |
| Дробный рюкзак | `value/weight` убыв. | O(n log n) |
| Хаффман | две мин. частоты | O(n log n) |
| Покрытие отрезками | самый дальний конец | O(n log n) |
| Мин. заправок | самая дальняя достижимая | O(n log n) |
| Составить макс. число | компаратор конкатенации | O(n log n) |
