## Вопрос, с которого всё начинается

Последняя задача ветки даёт файл `hello.mal` — одну строку без пробелов и переносов, состоящую из символов вроде `(=<`#9]~6ZY...`. Выглядит как случайно набранные знаки. Но это **Malbolge**, и он должен что-то вывести. Как подступиться к коду, который даже не читается линейно?

## Наш пример: hello.mal

Смотрим файл:

```
$ wc -c hello.mal
64 hello.mal
$ head -c 64 hello.mal
(=<`#9]~6ZY32Vx/4Rs+0No-&Jk)"Fh}|Bcy?`=*z]Kw%oG4UUS0/@-ejc(:'8dc
```

Одна строка, 64 символа, ни пробелов, ни отступов. Это сигнатура Malbolge — языка, созданного Беном Олмстедом в 1998 году и названного по восьмому кругу ада из «Божественной комедии» Данте. Его задача — быть максимально враждебным к человеку: первая работающая «Hello World!» появилась лишь через два года после публикации спецификации.

## Шаг 1: почему код нельзя прочитать

Исходник Malbolge — поток печатных ASCII-символов с кодами 33..126 (всего 94 значения). Он загружается в память начиная с адреса 0.

Главная «злая» идея: **после выполнения каждой инструкции ячейка памяти, где она лежала, шифруется** (crazy-операция). Программа меняет себя прямо в процессе работы. Именно поэтому статический анализ бесполезен: одна и та же строка при повторном заходе даст уже другую инструкцию.

Отсюда признаки, по которым Malbolge узнаётся в CTF: короткая сплошная строка без пробелов из «странных» символов `(=<`#9]~6ZY`, `~`, `]`, `#`, `|`.

## Шаг 2: три регистра

У машины Malbolge три регистра:

| Регистр | Смысл |
|---------|-------|
| `a` | аккумулятор; часто индекс в память |
| `c` | указатель на текущую инструкцию |
| `d` | указатель на данные |

Один шаг машины:

1. Прочитать значение `[c]`.
2. Вычислить код операции: `op = ([c] + [d]) % 94`, затем «раскодировать» его таблицей.
3. Исполнить одну из восьми инструкций.
4. Зашифровать `[c]` crazy-операцией — ячейка мутирует.
5. `c = c + 1`, `d = d + 1` (по модулю размера памяти).

Шаг 4 и делает Malbolge самомодифицирующимся.

## Шаг 3: восемь инструкций

После декодирования остаётся одно из восьми действий:

| Код | Инструкция | Действие |
|-----|------------|----------|
| 4 | `jmp d` | безусловный переход: `c = d` |
| 5 | `out a` | вывести символ `[a]` |
| 23 | `in a` | прочитать символ в `[a]` |
| 39 | `rotr [d]` | циклический сдвиг `[d]` вправо на 1 бит |
| 40 | `mov d, [a]` | `d = [a]` |
| 62 | `crz [d], [a]` | crazy-операция над `[d]` и `[a]` |
| 68 | `nop` | ничего не делать |
| 81 | `hlt` | останов |

Crazy-операция (её применяют и для шифрования кода, и как инструкцию 62) сначала сдвигает значение `x = (x + 33) % 94`, а затем выполняет поразрядную операцию в троичной системе по таблице:

| `x` \ `y` | 0 | 1 | 2 |
|-----------|---|---|---|
| 0 | 1 | 0 | 0 |
| 1 | 1 | 0 | 2 |
| 2 | 2 | 2 | 1 |

Именно из этих кирпичиков программа «собирает» нужные значения и выводит их через `out a`.

## Шаг 4: запускаем готовый интерпретатор

Писать свой эмулятор почти никогда не нужно. Самый быстрый путь — локальный эталонный интерпретатор Бена Олмстеда:

```
$ gcc -O2 -o malbolge malbolge.c
$ ./malbolge hello.mal
Hello World!
```

Если интерпретатора нет под рукой, тот же файл можно прогнать на онлайн-песочнице `tio.run/#malbolge` — для учебной задачи это нормально. Но настоящий флаг в чужой сервис не отправляйте: запускайте локально.

В CTF программа обычно короткая и выводит ровно флаг, а не «Hello World».

## Шаг 5: если вывод пустой

Первое, что стоит проверить, — не является ли программа вариантом **Malbolge Unshackled**. Это расширение снимает ограничение на 94-символьный алфавит и позволяет писать длинные программы с более обычным синтаксисом. Классический интерпретатор такую программу не поймёт — нужен соответствующий.

Второе — корректность инициализации памяти. После кода идёт детерминированный «хвост»: ячейки заполняются повторяющимся циклом значений. Если инициализировать память нулями, машина сразу уйдёт в недопустимую операцию и «сломается». Готовый интерпретатор делает это правильно; свой эмулятор нужно писать по спецификации.

Если задача офлайн и интерпретатора нет, пишут эмулятор. Каркас на Python:

```python
CRZ = [[1,0,0],[1,0,2],[2,2,1]]
def crazy(x, y):
    x = (x + 33) % 94
    res, mul = 0, 1
    for _ in range(5):
        res += CRZ[x % 3][y % 3] * mul
        x //= 3; y //= 3; mul *= 3
    return res % 94
```

Важны только логика `crazy` и шаг декодирования; остальное — корректная эмуляция границ и «хвоста».

## Шаг 6: как отличить Malbolge от других esolang

Полезно держать в голове сравнительную таблицу — она экономит время на распознавание:

| Язык | Алфавит | Признак |
|------|---------|---------|
| Malbolge | ASCII 33..126, без пробелов | «злые» символы `(=<`#9]~6ZY` |
| Brainfuck | `+-<>[].,` | всего 8 символов |
| Whitespace | пробел/таб/LF | невидимый, пустой на вид |
| INTERCAL | слова | `DO`, `PLEASE`, `COME FROM` |
| Shakespeare | английский текст | «пьеса» с `Act`/`Scene` |

Если строка короткая, сплошная, без пробелов и переносов, и в ней есть `~`, `]`, `#`, `|` — почти наверняка Malbolge. Алгоритм прост: скопировать в интерпретатор, запустить, получить вывод.

## Что мы теперь знаем

По-простому:

1. Malbolge узнаётся по короткой сплошной строке из «злых» символов без пробелов.
2. Каждая инструкция шифрует свою ячейку — код самомодифицируется, поэтому статически его не разобрать.
3. У машины три регистра (`a`, `c`, `d`) и всего восемь инструкций.
4. Запускается готовым интерпретатором (`malbolge.c`) или онлайн-песочницей.
5. Если программа не идёт — проверьте Malbolge Unshackled и инициализацию «хвоста» памяти.

## На что смотреть дальше

- **Классический против Unshackled.** Первый ограничен 94 символами и короток; второй — для длинных программ.
- **Не пытайтесь декомпилировать.** Из-за самошифрования «декомпилятор» — это фактически эмулятор.
- **Хвост памяти.** Нулевая инициализация ломает программу на первой же недопустимой операции.
- **Таблица декодирования.** Смещение на единицу меняет всю программу — берите её из спецификации, а не по памяти.
- **Не ждите «Hello World».** В CTF вывод обычно ровно флаг и ничего лишнего.

## Куда дальше

На этом ветка esolang завершена: мы прошли от Brainfuck и Piet через Whitespace и INTERCAL к пьесе и Malbolge. Дальше ветка уходит в другую тему — **git-форензику**: возьмём репозиторий, из которого «удалили» секрет, и достанем его из истории коммитов. А пока главное запомни: если код выглядит как случайные символы и меняет себя на лету — это не шифр, а самомодифицирующаяся машина, и её нужно эмулировать.

## Где пригодится

- **CTF misc:** задачи «запусти этот мусор» с выводом флага.
- **Понимание эмуляции:** самомодифицирующийся код и таблицы декодирования встречаются и в реверсе.
- **Обфускация:** приём «код, который меняет себя на лету» — основа многих протекторов.
- **Общая эрудиция:** работа со спецификацией и написание интерпретатора с нуля.
