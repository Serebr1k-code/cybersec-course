## Что такое Malbolge

Malbolge — эзотерический язык программирования, созданный Беном Олмстедом (Ben Olmstead) в 1998 году и названный по восьмому кругу ада из «Божественной комедии» Данте. Его задача — быть максимально враждебным к человеку. Язык тьюринг-полон, но спроектирован так, чтобы писать на нём осмысленный код было почти невозможно: первая программа, печатающая «Hello World!», появилась только через два года после публикации спецификации, а написал её Лу Шеффер (Lou Scheffer), разобрав машину вручную.

Ключевая «злая» идея: после выполнения каждой инструкции содержимое ячейки памяти, которую эта инструкция занимала, **шифруется** («crazy operation»). Программа сама себя изменяет прямо в процессе работы, поэтому статически прочитать её как обычный код нельзя — нужно эмулировать машину шаг за шагом.

## Алфавит и структура программы

Исходник Malbolge — это поток печатных ASCII-символов с кодами 33..126 (всего 94 значения). Файл загружается в память начиная с адреса 0. Память — это массив ячеек, каждая из которых хранит значение 0..94. Всё, что идёт после кода программы, заполняется детерминированным «хвостом»: ячейки инициализируются повторяющимся циклом значений, порождённым той же crazy-операцией. Именно этот хвост и позволяет вообще исполнять код — если бы память была нулевой, машина быстро ушла бы в недопустимое состояние.

Из алфавита следуют три важных признака, по которым Malbolge узнаётся в CTF:

- строка состоит из «странной» смеси символов `(=<`#9]~6ZY...`, `@`, `~`, `|`, `\` без пробелов;
- нет переносов строк и отступов;
- программа короткая (десятки–сотни символов), но выглядит бессмысленной.

## Регистры и цикл выполнения

У машины Malbolge три регистра:

| Регистр | Смысл |
|---------|-------|
| `a` | аккумулятор; часто используется как индекс/указатель в память |
| `c` | указатель на текущую инструкцию (code pointer) |
| `d` | указатель на данные (data pointer) |

Один шаг машины выглядит так:

1. Прочитать значение `[c]`.
2. Вычислить код операции: `op = ([c] + [d]) % 94`, затем «раскодировать» его таблицей декодирования.
3. Исполнить одну из восьми инструкций по полученному коду.
4. Зашифровать `[c]` crazy-операцией (ячейка мутирует).
5. `c = c + 1`, `d = d + 1`; оба берутся по модулю размера памяти.

Именно шаг 4 делает Malbolge самомодифицирующимся: одна и та же строка кода при повторном достижении даст уже другую инструкцию.

## Таблица восьми инструкций

После декодирования операции остаётся одно из восьми действий:

| Код | Инструкция | Действие |
|-----|------------|----------|
| 4 | `jmp d` | безусловный переход: `c = d` |
| 5 | `out a` | вывести символ `[a]` |
| 23 | `in a` | прочитать символ в `[a]` |
| 39 | `rotr [d]` | циклический сдвиг `[d]` вправо на 1 бит |
| 40 | `mov d, [a]` | `d = [a]` |
| 62 | `crz [d], [a]` | применить crazy-операцию к `[d]` и `[a]` |
| 68 | `nop` | ничего не делать |
| 81 | `hlt` | останов |

Crazy-операция (её применяют и для шифрования кода, и как инструкцию 62) сначала сдвигает значение: `x = (x + 33) % 94`, а затем выполняет поразрядную операцию в троичной системе по таблице:

| `x` \ `y` | 0 | 1 | 2 |
|-----------|---|---|---|
| 0 | 1 | 0 | 0 |
| 1 | 1 | 0 | 2 |
| 2 | 2 | 2 | 1 |

## Инструменты и интерпретаторы

Готовых интерпретаторов несколько, и в CTF почти всегда быстрее запустить существующий, чем писать свой.

- **Онлайн:** `https://tio.run/#malbolge` — вставьте программу и запустите; вывод появится сразу. Это самый быстрый путь для одной задачи.
- **Эталонный интерпретатор:** оригинальный `malbolge.c` Бена Олмстеда; компилируется `gcc -O2 -o malbolge malbolge.c` и запускается `./malbolge prog.mal`.
- **Malbolge Unshackled** — вариант без ограничения на 94-символьный алфавит и с более гибкой памятью; позволяет писать длинные программы (например, генератор лабиринтов). Репозиторий живёт под именем `esoteric-programming/malbolge-unshackled`.
- **Спецификация и примеры:** `https://esolangs.org/wiki/Malbolge` — таблицы, ссылки на интерпретаторы и история.

Запуск через tio.run из командной строки (проверка «на глаз», если нужно быстро):

```bash
# сохраняем программу
cat > hello.mal <<'EOF'
(=<`#9]~6ZY32Vx/4Rs+0No-&Jk)"Fh}|Bcy?`=*z]Kw%oG4UUS0/@-ejc(:'8dc
EOF
# локальный интерпретатор
./malbolge hello.mal
```

Вывод:

```
Hello World!
```

## Разобранный пример

Возьмём классическую программу выше и проследим первые шаги, чтобы понять, почему её нельзя прочитать глазами.

- Первый символ `(` — код 40. При `d = 0` и `[d] = 40` операция `(40 + 40) % 94 = 80`, что таблицей декодирования сводится к `nop` или переходу в зависимости от раскладки — то есть первый такт ещё «безопасен».
- После такта ячейка `[0]` шифруется crazy-операцией и превращается в другое значение; при следующем заходе в тот же адрес (после `jmp`) инструкция будет уже другой.
- Итоговое поведение — эмерджентное: программа «собирает» нужные значения в аккумуляторе, применяя `rotr` и `crz` к числам, и выводит их через `out a`.

Именно из-за пункта 2 статический анализ бесполезен: любой «декомпилятор Malbolge» — это фактически эмулятор.

## Как читать Malbolge вручную

Если готового интерпретатора нет (например, в офлайн-CTF), пишут эмулятор. Минимальный каркас на Python:

```python
CRZ = [[1,0,0],[1,0,2],[2,2,1]]
def crazy(x, y):
    x = (x + 33) % 94
    res, mul = 0, 1
    for _ in range(5):
        xt, yt = x % 3, y % 3
        res += CRZ[xt][yt] * mul
        x //= 3; y //= 3; mul *= 3
    return res % 94

def decode(op, d_val):
    # таблица из 94 записей, повторяющая восемь кодов
    table = [4,5,23,39,40,62,68,81] * 12
    return table[(op + d_val) % 94] if (op + d_val) % 94 < len(table) else 0

def run(prog):
    mem = [ord(c) for c in prog]
    # хвост памяти заполняется детерминированно (см. спецификацию)
    while True:
        op = decode(mem[c], mem[d])   # c, d — регистры
        ...  # исполнить инструкцию и зашифровать mem[c]
```

Каркас намеренно упрощён: важна логика `crazy` и шаг декодирования. Реальная реализация должна корректно заполнить «хвост» памяти и обработать границы.

## Частые ошибки и подводные камни

- **Путают Malbolge и Malbolge Unshackled.** В первом программа ограничена 94-символьным алфавитом и коротка; во втором можно писать большие программы с обычным синтаксисом.
- **Пытаются декомпилировать статически.** Из-за самошифрования это не работает — нужна эмуляция.
- **Забывают про хвост памяти.** Если инициализировать память нулями, программа сразу «сломается» на недопустимой операции.
- **Неверная таблица декодирования.** Даже смещение на единицу меняет всю программу.
- **Ожидание «Hello World» из первой же программы.** Исторически на это ушло два года — в CTF программа обычно короткая и выводит ровно флаг.

## Что дальше / решение

Порядок действий для Malbolge-задачи:

1. Убедиться, что это действительно Malbolge: короткая строка без пробелов из «злых» символов `(=<`#9]~6ZY...`.
2. Скопировать программу и запустить на `tio.run/#malbolge` — часто этого достаточно.
3. Если офлайн — поднять локальный интерпретатор (`malbolge.c`) или написать эмулятор по спецификации.
4. Если программа ничего не выводит — проверить, не является ли она **Malbolge Unshackled**, и запустить соответствующим интерпретатором.

## Пошаговая эмуляция первых тактов

Чтобы понять Malbolge, полезно руками прокрутить несколько тактов. Пусть память инициализирована, `a = 0`, `c = 0`, `d = 0`, а первая ячейка `[0]` содержит код символа `(` = 40.

- **Такт 1.** `op = ([0] + [0]) % 94 = (40 + 40) % 94 = 80`. По таблице декодирования код 80 сводится к одной из восьми инструкций; для классического расклада это `nop`. Затем `[0]` шифруется crazy-операцией и уже не равна 40. Далее `c = 1`, `d = 1`.
- **Такт 2.** Читаем `[1]` — второй символ программы. Считаем `op = ([1] + [1]) % 94`, декодируем, исполняем. Опять шифруем `[1]`.
- **…и так далее.** Когда встречается `jmp d`, указатель `c` прыгает назад — и попадает в ячейку, которая уже была зашифрована. Именно поэтому повторный проход исполняет **другую** инструкцию.

Такое поведение называют самомодифицирующимся кодом. Практический вывод: писать «декомпилятор» бессмысленно, нужно эмулировать. Быстрее всего — взять готовый интерпретатор и не изобретать велосипед; свой эмулятор пишут только в офлайн-задаче, где нет доступа к сети.

## Как отличить Malbolge от других esolang

| Язык | Алфавит | Длина | Признак |
|------|---------|-------|---------|
| Malbolge | ASCII 33..126, без пробелов | десятки-сотни | «злые» символы `(=<`#9]~6ZY` |
| Brainfuck | `+-<>[].,` | любые | всего 8 символов |
| Whitespace | пробел/таб/LF | любые | невидимый, пустой на вид |
| INTERCAL | `DO`, `PLEASE`, `COME FROM` | длинные | слова, а не символы |

Если строка короткая, сплошная, без пробелов и переносов, и в ней есть `~`, `]`, `#`, `|` — почти наверняка это Malbolge. Тогда алгоритм действий прост: скопировать на `tio.run/#malbolge`, запустить, получить вывод.
