## Вопрос, с которого всё начинается

Последний язык ветки — Ruby. Сервис принимает код и исполняет его через `instance_eval` в контексте, где нет `Kernel` (а значит, нет `system`). Разработчик считает, что этого достаточно. Как восстановить доступ к системе?

## Наш пример: BasicObject-песочница

Условие даёт код:

```ruby
class Sandbox < BasicObject
end
Sandbox.new.instance_eval(input)
```

`BasicObject` — «минимальный» класс Ruby: у него нет методов `Kernel`, включая `system`, `puts`, `eval`. Наш код исполняется внутри такого объекта. Отправляем тест:

```
> 1 + 1
2
```

Арифметика работает. Но `system` недоступен напрямую — его нет в цепочке наследования `Sandbox`. Значит, нужно найти «мостик» к настоящему `Kernel`.

## Шаг 1: ментальная модель

Если у вас есть **любой** способ добраться до объекта, класса или binding за пределами песочницы — вы восстановите `Kernel` и выполните команду. Задача — найти такой мостик.

Методы-«джокеры», которые почти всегда ведут к RCE: `eval`, `instance_eval`, `class_eval`, `send`, `__send__`, `public_send`, `method`, `binding`, `const_get`, `define_method`, `open`.

## Шаг 2: восстанавливаем Kernel через ObjectSpace

`ObjectSpace` — модуль, дающий доступ ко **всем** живым объектам программы. Через него находим класс `Kernel`:

```ruby
ObjectSpace.each_object(Class).find { |c| c.name == "Kernel" }
  .send(:system, "cat /flag")
```

`each_object(Class)` перебирает все классы, `find` берёт нужный, `send(:system, ...)` вызывает метод. `send` здесь — «джокер»: он вызывает метод по имени в обход обычной видимости.

## Шаг 3: через const_get и send

Если `ObjectSpace` недоступен, но есть `Object`, достаём `Kernel` как константу:

```ruby
Object.const_get(:Kernel).system("cat /flag")
```

`const_get` ищет константу (в том числе класс) по имени — это ещё один способ добраться до «настоящего» пространства имён. Если фильтр запрещает литерал `system`, вызываем его через `send` с собранным именем:

```ruby
m = "sys" + "tem"
send(m, "id")
```

Символ `:system` тоже работает: `send(:system, "id")` — фильтр по строкам его не ловит.

## Шаг 4: альтернативные примитивы запуска

Часто фильтр ловит `system`, но пропускает другие способы запустить процесс:

```ruby
IO.popen("cat /flag") { |f| f.read }
Process.spawn("cat /flag")
`cat /flag`                      # backticks
open("|cat /flag")               # open с pipe
```

Проверяйте их по очереди: разработчики блокируют `system`, забывая, что в Ruby запуск команды есть минимум в пяти местах.

## Шаг 5: Marshal.load — почему это RCE

Отдельная большая тема — **десериализация**. `Marshal.load` восстанавливает Ruby-объекты из бинарного формата, и в формате можно указать **любой класс** с методом `marshal_load`/`_load`. При загрузке Ruby вызовет этот метод — а значит, выполнит код:

```ruby
class Evil
  def marshal_load(cmd)
    system(cmd)
  end
end
data = Marshal.dump(Evil.new("cat /flag"))
Marshal.load(data)      # вызовет system
```

Прямого «выполнить команду» в формате нет, но есть **gadget-цепочки**: классы из гемов (`Gem::Requirement`, `Gem::Package::TarReader`, `ERB`, `Net::WriteAdapter`), чьи методы при десериализации приводят к вызову `system`. Наборы зависят от версии Ruby.

**Правило: никогда не вызывайте `Marshal.load` на данных от пользователя.** Если сервер это делает — считайте, что у вас RCE.

## Шаг 6: YAML — второй путь

`YAML.load` (в отличие от `YAML.safe_load`) умеет создавать произвольные объекты Ruby по тегам вида `!ruby/object:ClassName`. Это второй путь к RCE через десериализацию:

```yaml
--- !ruby/object:Gem::Requirement
requirements: ...
```

Если сервер делает `YAML.load(params[:data])` — это RCE. Защита только одна: `YAML.safe_load` с явным белым списком классов.

## Шаг 7: если не сработало

- **Сдались после блокировки `system`.** Ищите `IO.popen`, backticks, `Process.spawn`, `open("|")`.
- **Забыли про `ObjectSpace`.** Это самый прямой путь к `Kernel`.
- **Считаете Marshal «просто сериализацией».** Это десериализация с вызовом методов.
- **Не проверили версию Ruby.** Набор gadget-цепочек зависит от версии.
- **Полагаетесь на `$SAFE`.** В Ruby 3 он удалён и ничего не защищает.

## Как строится Marshal-payload

Marshal-формат — это поток байт с тегами типов: `\x04\x08` — версия, далее объекты, символы и строки. Чтобы собрать payload, есть два пути.

Первый — **сгенерировать сериализацией**: создать нужный объект в Ruby и вызвать `Marshal.dump`, затем при необходимости подправить байты. Если сервер делает `Marshal.load(params[:payload])`, а вы контролируете payload, этого достаточно:

```ruby
class Gadget
  def marshal_load(cmd) = system(cmd)
end
File.binwrite('payload.bin', Marshal.dump(Gadget.new('cat /flag')))
```

Проблема в том, что класса `Gadget` на сервере нет. Поэтому для реальной атаки собирают комбинацию из классов, которые **точно присутствуют** в приложении: `Gem::Requirement`, `Gem::Package::TarReader`, `Net::WriteAdapter`, `ERB`. В такой цепочке `marshal_load` одного класса вызывает метод другого, и в итоге исполняется команда. Готовые цепочки публикуются под конкретные версии Ruby/Rails — в CTF обычно дают точную версию.

Второй путь — **собрать байты вручную** по спецификации. Он даёт полный контроль над классами и порядком, но трудоёмок. На практике сначала пробуют готовый PoC под версию, и только если его нет — собирают вручную.

## Что мы теперь знаем

По-простому:

1. Ruby-песочница ломается через «метод-джокер» (`send`, `eval`, `const_get`, `ObjectSpace`).
2. `ObjectSpace` и `Object.const_get(:Kernel)` восстанавливают доступ к `system`.
3. Запуск команды есть минимум в пяти местах: `system`, `IO.popen`, `Process.spawn`, backticks, `open("|")`.
4. `Marshal.load` и `YAML.load` на недоверенных данных — это RCE через gadget-цепочки.
5. Защита — не фильтры, а `safe_load` и изоляция процесса.

## На что смотреть дальше

- **Не сдавайтесь после блокировки `system`.** Проверьте альтернативные примитивы.
- **Помните про `ObjectSpace`.** Самый прямой путь к `Kernel`.
- **Относитесь к Marshal серьёзно.** Это полноценная десериализация.
- **Уточняйте версию Ruby.** Цепочки привязаны к версии.
- **Проверяйте обе точки.** `Marshal` и `YAML` — разные входы.
