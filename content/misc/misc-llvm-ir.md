## Вопрос, с которого всё начинается

В реверс-задаче дан бинарник, собранный clang. Читать ассемблер долго и мучительно: оптимизации перемешали код, регистры переиспользованы. Но у компилятора есть «серединный» язык — **промежуточное представление** (intermediate representation, IR). Он ближе к исходнику и понятнее ассемблера. Как его прочитать?

## Наш пример: module.ll

Вот фрагмент `.ll`-файла — текстового IR:

```
$ cat module.ll
define i32 @add(i32 %a, i32 %b) {
entry:
  %sum = add i32 %a, %b
  ret i32 %sum
}
```

Функция `add` берёт два числа и возвращает сумму. Уже видно имена (`%a`, `%b`, `%sum`) и типы (`i32`). Разберём структуру.

## Шаг 1: зачем нужно IR

Компилятор clang переводит C/C++ не сразу в машинный код, а в **LLVM IR** — язык, удобный для анализа и оптимизаций. Один и тот же IR потом компилируется под разные архитектуры. Для аналитика это золото: IR не зависит от конкретного процессора и сохраняет структуру программы.

## Шаг 2: как получить IR

Из исходника:

```
$ clang -S -emit-llvm -O0 add.c -o add.ll
```

Флаг `-S` означает «выдать текст», `-emit-llvm` — «в формате LLVM». `-O0` отключает оптимизации (чтобы код был ближе к исходнику). Без `-S` получится **биткод** (`.bc`) — тот же IR, но в двоичном виде; его читают через `llvm-dis`.

## Шаг 3: структура модуля

IR-файл — это **модуль**. В нём:

- `target` — целевая архитектура;
- глобальные переменные (`@name = global ...`);
- определения функций (`define ... @func(...) { ... }`);
- объявления внешних функций (`declare ...`).

Каждая функция — набор **базовых блоков** (basic blocks), помеченных метками (`entry:`). Блок — линейный участок без ветвлений внутри.

## Шаг 4: SSA-регистры

IR в форме **SSA** (static single assignment): каждой переменной присваивают ровно один раз. Поэтому переменные — это `%1`, `%2`, `%a`, `%sum`: имена с `%`. Если значение нужно изменить, создаётся новое имя. Это делает поток данных явным: видно, откуда пришло каждое значение. Для слияний ветвлений используется `phi`-инструкция.

## Шаг 5: типы

LLVM строго типизирован:

- `i32`, `i64`, `i8` — целые разной ширины;
- `i8*` — указатель (на байт);
- `[N x T]` — массив;
- `{...}` — структура;
- `void` — ничего.

Типы видны прямо в инструкциях: `add i32 %a, %b` — сложение 32-битных.

## Шаг 6: основные инструкции

- `alloca` — выделить память на стеке;
- `load` / `store` — читать/писать память;
- `add`, `sub`, `mul`, `and`, `or`, `xor`, `icmp` — арифметика и сравнения;
- `br` — переход (условный/безусловный);
- `call` — вызов функции;
- `ret` — возврат;
- `phi` — выбрать значение в зависимости от того, откуда пришли.

Читая их последовательно, восстанавливаешь логику.

## Шаг 7: оптимизации и их следы

Если собрать с `-O2`, IR изменится: лишние переменные исчезнут, циклы «раскрутятся», функции «инлайнятся». Приёмы реверса:

- сравнивать `-O0` и `-O2` — что пропало, то было несущественно;
- искать «магические» константы (побитовые маски, сдвиги) — часто это крипто/хеш;
- смотреть `phi`-узлы — там остатки циклов.

## Шаг 8: практический порядок

1. Получить `.ll` (`clang -S -emit-llvm`).
2. Найти нужную функцию (`define @...`).
3. Пройти по базовым блокам, читая инструкции.
4. Обращать внимание на константы и `phi`.
5. Сравнить с `-O2`, если что-то непонятно.

## Что мы теперь знаем

- LLVM IR — промежуточный язык между исходником и машинным кодом.
- Получают через `clang -S -emit-llvm`; текст — `.ll`, биткод — `.bc`.
- Модуль = функции + глобальные переменные; функции делятся на базовые блоки.
- SSA: каждое значение присвоено один раз; ветвления — через `phi`.
- Типы и инструкции (`load`, `add`, `br`, `call`) читаются напрямую.
