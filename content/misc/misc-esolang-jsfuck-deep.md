## Вопрос, с которого всё начинается

Веб-задача даёт строку из символов `[]()!+` — и больше ничего. Это не тарабарщина: это исполняемый JavaScript, записанный всего шестью символами. Так работает **JSFuck**. Как декодировать такую строку и понять, что она делает?

## Наш пример: строка JSFuck

```
$ cat payload.js
[][(![]+[])[+[]]+([![]]+[][[]])[+!+[]+[+[]]]+...]
```

Выглядит как случайные скобки. Но в JavaScript из шести символов `[]()!+` можно построить любую строку и любое значение — потому что всё в JS приводится к строке и обратно.

## Шаг 1: идея — строки из приведений типов

Ключ к JSFuck: в JavaScript выражения дают строки. Например, `![]` — это `false` (отрицание пустого массива, который «истинен»). `[]+[]` — пустая строка. `(![]+[])` — строка `"false"`. Из букв этих слов (`f`,`a`,`l`,`s`,`e`,`t`,`r`,`u`,`n`,`c`,`o`,`n`,`s`) можно собирать другие слова. Достаёшь буквы по индексу: `"false"[0]` — это `"f"`. Индексы тоже строятся из `[]()!+`.

## Шаг 2: числа и `+[]`

Числа получаются так: `+[]` — это `0` (пустой массив в число). `+!+[]` — это `1` (`!+[]` = `true`, `+true` = 1). Складывая их, строишь любые числа, а значит — индексы для доступа к буквам. Так из ничего строятся строки `constructor`, `return`, и в итоге — вызов функций.

## Шаг 3: почему это работает

JavaScript — язык с неявными приведениями: массив → строка, строка → число, значение → boolean. JSFuck эксплуатирует именно это. Поэтому строка из `[]()!+` — не «другой язык», а тот же JavaScript, просто записанный невероятно громоздко. Понимание приведений — ключ к чтению.

## Шаг 4: декодирование

Простейший способ — выполнить код в контролируемой среде и посмотреть результат (`alert`, `console.log`, значение выражения). Для статического анализа есть декодеры (`jsfuck`-decoder, `JSFuck` в консоли) и **jsbeautifier**, который разворачивает обфускацию в читаемый вид.

```
$ node -e "console.log(eval(require('fs').readFileSync('payload.js','utf8')))"
```

## Шаг 5: jjencode и AAencode

JSFuck — не единственный. **jjencode** кодирует JS в последовательность из символов `$`, `_`, `=` и других; **AAencode** — в набор японских смайликов (ｱﾊﾞｷﾞｮ). Оба — «обфускаторы», которые исполняются тем же движком. Распознаются по алфавиту: JSFuck — `[]()!+`, jjencode — `$_=`, AAencode — смайлики.

```
$ cat aa.js
ﾟωﾟﾉ= /｀ｍ´）ﾉ ~┻━┻ ...
```

## Шаг 6: безопасность

Обфусцированный JS часто используется в атаках (криптомайнеры, редиректы). Запускать его на рабочей машине опасно: код может обращаться к сети или браузеру. Правильно — статический анализ (beautifier, декодер) или запуск в изолированной среде (Node в контейнере без сети, песочница браузера).

## Шаг 7: где прячут метку

В web/misc-задачах метка — это либо **результат вычисления** обфусцированного кода (нужно декодировать/выполнить), либо строка, собранная в коде. Реже — имя функции или комментарий. Порядок: сначала попробовать декодировать, затем — выполнить в песочнице.

## Шаг 8: практический порядок

1. Определить алфавит: `[]()!+` → JSFuck; `$_=` → jjencode; смайлики → AAencode.
2. Прогнать через beautifier/декодер.
3. Если остаётся сложно — выполнить в изолированном Node.
4. Собрать вывод (метку).
5. Не запускать недоверенный JS вне песочницы.

## Что мы теперь знаем

- JSFuck — JavaScript из символов `[]()!+`, построенный на приведениях типов.
- Из `![]` получается `"false"`, из него — буквы, из букв — любые строки.
- Числа строятся из `+[]` и `+!+[]` и дают индексы.
- jjencode и AAencode — другие обфускаторы того же JS.
- Метка — результат декодирования/выполнения; запускать только в песочнице.

## Шаг 9: строим буквы из слов

Разберём механику подробнее, потому что это ядро JSFuck. Выражение `![]` даёт `false`, а `![]+[]` — строку `"false"`. Взяв символ по индексу — `(![]+[])[+[]]` — получаем `"f"` (индекс 0 задан как `+[]`). Аналогично `!![]` даёт `true`, `[][[]]` — `undefined`, `[![]+[]][+[]]` — функцию и т.д. Комбинируя буквы из `"false"`, `"true"`, `"undefined"`, `"constructor"`, ты собираешь любые слова: `"return"`, `"eval"`, имена свойств. Так из шести символов рождается весь язык.

## Шаг 10: `constructor` и доступ к Function

Ключевой трюк: у любой строки/числа есть свойство `constructor` — функция-конструктор. У числа это `Number`, у строки — `String`, а у функции — `Function`. Добравшись до `Function`, ты можешь **создавать новые функции из строки**: `Function("return 1")()`. А строку для неё тоже можно построить из букв. Так JSFuck в итоге получает доступ к полноценному `eval` и может выполнить любой код. Это и делает его «полным» языком.

## Шаг 11: почему фильтры его пропускают

WAF и «фильтры опасных слов» ищут строки вроде `eval`, `alert`, `script`, `onerror`. В JSFuck этих слов в исходнике **нет** — они собираются во время выполнения. Поэтому простой blacklist не срабатывает. Защита от такого кода — не фильтрация строк, а изоляция исполнения (CSP без `unsafe-eval`, песочница, отсутствие привилегий). Для атакующего это напоминание: фильтрация по словам обходится, а изоляция — нет.

## Шаг 12: jjencode детально

**jjencode** — другой обфускатор, использующий переменную `$` и цепочки присваиваний с `_` и `=`. Он не ограничен шестью символами, но результат всё равно нечитаем: код строится через `$=~[]`, `$={___:++$,...}` и обращается к свойствам по именам из чисел. Декодируется тем же способом — выполнением. Распознаётся по характерному началу `$=~[];$={...}`.

## Шаг 13: AAencode и «смайлики»

**AAencode** кодирует JS в последовательности японских полуширинных катакана-символов и смайликов, которые визуально образуют «мордочки». Внутри — те же приведения типов. Такой код часто вставляют в веб-страницы для сокрытия. Распознаётся мгновенно по алфавиту (символы `ﾟ`, `ω`, `｀`). Для декодирования — тот же приём: исполнить в изоляции и посмотреть результат.

## Шаг 14: инструменты деобфускации

Помимо выполнения, помогают: **jsbeautifier** (форматирует, иногда упрощает), **de4js** (онлайн-деобфускатор, поддерживает JSFuck/jjencode/AAencode), **AST-инструменты** (`esprima`, `babel`) для программного разбора. Стратегия: сначала попробовать автоматический декодер, затем — динамическое исполнение. Статический анализ безопаснее, но не всегда возможен.

## Шаг 15: безопасный запуск

Если решил выполнять — делай это в изолированной среде: Node в контейнере без сети, с ограничением памяти и времени, или отдельный браузерный профиль без доступа к реальным данным. Обфусцированный код может содержать криптомайнер, стилер или сетевой бэкдор. Никогда не выполняй его в основной сессии браузера или на рабочей машине.

## Шаг 16: где прячут метку

Метка бывает трёх видов: (1) результат вычисления (нужно выполнить/декодировать); (2) строка, которую код собирает и куда-то отправляет/печатает; (3) имя функции или переменной, собранное из букв. В первых двух случаях без выполнения (или полного ручного разбора) не обойтись. Поэтому «выполнить в песочнице» — основной рабочий приём для web/misc-задач с обфускацией.

## Шаг 17: чек-лист по обфусцированному JS

1. Определить алфавит: `[]()!+` — JSFuck; `$=~[]` — jjencode; смайлики — AAencode.
2. Попробовать деобфускатор (de4js/jsbeautifier).
3. Если нужно — исполнить в изолированном Node.
4. Собрать вывод (метку).
5. Не запускать в основной среде.

## Итог

JSFuck, jjencode и AAencode — обфускаторы одного и того же JavaScript, построенные на приведениях типов. JSFuck использует шесть символов и добирается до `Function`/`eval`, поэтому является полным. Фильтры по словам его не ловят — спасает только изоляция. Метка — это обычно результат вычисления, поэтому безопасный запуск в песочнице и есть решение.

## Шаг 18: как быстро проверить, что это JSFuck

Собери алфавит файла: посмотри уникальные символы. Если остались только `[ ] ( ) ! +` (и, возможно, пробелы) — это JSFuck. Если добавились `$`, `_`, `=` — вероятно jjencode; если смайлики — AAencode. Такой анализ занимает секунду и сразу направляет к нужному декодеру. Не пытайся читать JSFuck глазами — это принципиально нечитаемо без инструмента, и попытки «разобрать вручную» только тратят время.

## Шаг 19: безопасность прежде всего

Обфусцированный JS — любимый носитель вредоносного кода: он обходит фильтры по словам и часто используется для загрузки следующего этапа атаки (стилер, майнер, бэкдор). Поэтому единственный безопасный способ «посмотреть, что он делает» — изолированное исполнение (Node в контейнере без сети) или статический декодер. Никогда не открывай такой файл в основной сессии браузера и не запускай его на рабочей машине.

## Шаг 20: итог по обфускации JS

JSFuck, jjencode и AAencode — это один и тот же JavaScript, спрятанный за приведениями типов и экзотическим алфавитом. Они добираются до `Function`/`eval` и потому полны по возможностям, а фильтры по строкам их не ловят. Решение: распознать по алфавиту, деобфусцировать инструментом или исполнить в песочнице и прочитать результат. В web/misc-задачах это стандартный рабочий приём.
