## Вопрос, с которого всё начинается

Мы прошли кодировки и Unicode. Теперь дают **зашифрованный** файл `cipher.bin` и подсказку: «флаг начинается с `FLAG{`». Это misc-крипто — «лёгкая» криптография: классические шифры и XOR. Здесь почти никогда не нужна сложная математика; нужно **распознать схему** и применить правильный рецепт.

Разберём один файл от начала до флага.

## Наш пример: cipher.bin

```bash
$ ls -l cipher.bin
-rw-r--r-- 1 user user 512 cipher.bin
$ xxd cipher.bin | head -2
00000000: 1b32 0d0f 1e59 2c11 0a1b 3d26 1c04 0232  .2...Y,...=&...2
```

Данные бинарные, «мусорные», с повторами. Это не текст и не похоже на base64. Признак **XOR**: вывод бинарный, есть повторяющийся паттерн. Размер 512 — фиксированный.

## Шаг 1: пробуем самое простое — односимвольный XOR

Если весь файл зашифрован одним байтом-ключом, его ломает перебор всех 256 вариантов:

```python
ct = open('cipher.bin','rb').read()
for k in range(256):
    out = bytes(b ^ k for b in ct)
    if b'FLAG' in out:
        print(k, out[:40])
```

Запускаем — ничего. Значит, ключ **не один байт**. Дальше — повторяющийся ключ, но сначала проверим другой тип.

## Шаг 2: что если это классический сдвиг

Классика — **ROT/Цезарь** (сдвиг алфавита) и **Атбаш** (отражение `a↔z`). Их признак — текст из букв, но нечитаемый. Наш файл бинарный, поэтому это не они, но знать рецепт полезно:

```python
import codecs
print(codecs.decode('uryyb', 'rot_13'))    # 'hello'
# перебор всех сдвигов
for n in range(26):
    print(n, ''.join(chr((ord(c)-65-n)%26+65) if c.isupper() else c for c in s))
```

Если бы текст был буквенным, мы бы просто перебрали 26 сдвигов и глазами выбрали читаемый.

## Шаг 3: определяем длину ключа (расстояние Хэмминга)

При повторяющемся ключе `key` применяется по кругу: `key[i % len(key)]`. Тогда байты, отстоящие на `len(key)` друг от друга, зашифрованы **одним и тем же** байтом ключа — а значит, их «рисунок» похож.

Меру похожести даёт **расстояние Хэмминга** — число различающихся битов:

```python
def hamming(a, b):
    return sum(bin(x ^ y).count('1') for x, y in zip(a, b))
```

Для каждой предполагаемой длины `k` бьём файл на блоки по `k` байт и считаем нормализованное расстояние между соседними блоками. Минимум укажет истинную длину:

```python
best = min(range(1, 41),
           key=lambda k: sum(hamming(ct[i*k:(i+1)*k], ct[(i+1)*k:(i+2)*k])
                             for i in range(4)) / k)
print(best)      # 3
```

Ключ длиной 3.

## Шаг 4: восстановление ключа через crib

**Crib** — известный фрагмент открытого текста. У нас есть префикс `FLAG{`. Для повторяющегося XOR `key[i] = ct[i] ^ ord('FLAG{'[i])` — то есть XOR шифртекста с известным началом:

```python
known = b'FLAG{'
key = bytes(ct[i] ^ known[i] for i in range(len(known)))
print(key[:3])
```

```
b'KEY'
```

Первые три байта ключа — `KEY`. Остальные добираем **частотным анализом** по столбцам (для каждой позиции в ключе берём байты с этим остатком и ищем ключ как односимвольный XOR).

## Шаг 5: расшифровываем

```python
def xor(data, key):
    return bytes(b ^ key[i % len(key)] for i, b in enumerate(data))
print(xor(ct, b'KEY')[:40])
```

```
b'FLAG{r3p34t1ng_x0r}'
```

Флаг получен. Работала связка: определение длины ключа → crib → частотный анализ.

## Шаг 6: классические шифры — Виженер и подстановка

Кроме сдвига и XOR, в misc встречаются:

- **Виженер** — сдвиг каждой буквы на свой ключ. Признак: частотный анализ по всему тексту «не сходится», но если угадать длину ключа, каждый столбец становится обычным Цезарем. Длину оценивают **индексом совпадений** (IC) — мерой того, насколько часто буквы повторяются.
- **Подстановка** — каждая буква заменена другой по таблице. Ломается **частотным анализом**: в любом языке частоты букв устойчивы (`e`, `t`, `a`, пробел — самые частые), и они сохраняются при замене.
- **Rail fence** (перестановка) — буквы перемешаны; пробуйте разные числа «рельс».

```python
# перебор ROT — 26 вариантов, выбираем глазами читаемый
for n in range(26):
    print(n, ''.join(chr((ord(c)-65-n)%26+65) if c.isupper() else c for c in s))
```

## Шаг 7: хеши — это не шифр

Задачи «дан хеш, найди строку» решаются **словарём**, а не декодером: хеш необратим. Быстрая проверка по словарю:

```bash
$ hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt    # -m 0 = MD5
```

Для нестандартных хешей (со своей солью) читайте исходник и повторяйте логику — или перебирайте кандидатов. Не путайте: base64/hex — кодирование (обратимо без ключа), ROT/Цезарь — «шифр» без ключа (перебирается), XOR с ключом — шифрование (ключ нужен, но короткий подбирается).

## Шаг 8: роторные и исторические машины

Иногда встречаются не «шифры», а машины: **Энигма**, **Playfair**, **Bifid**, **ADFGX**. Признаки:

- буквы сгруппированы парами → Playfair (шифрует биграммы);
- алфавит без пробелов, группы по пять → ADFGX/Энигма;
- для Энигмы нужны настройки роторов — `py-enigma` их принимает;
- Playfair/Bifid — готовые реализации в сети, но проще написать самим по таблице.

## Шаг 9: порядок действий в misc-крипто

1. Определите тип по признакам (таблица ниже).
2. Начните с самого простого: перебор ROT (26) и односимвольный XOR (256).
3. Для XOR используйте crib — известный префикс (`flag{`, `CTF{`).
4. Для повторяющегося XOR — длина ключа (Хэмминг/IC), затем частотный анализ по столбцам.
5. Для base-кодировок — декодируйте в цикле, пока не станет читаемо.
6. Хеш — не шифр: ищите словарём, а не декодером.

Не усложняйте: misc-крипто почти всегда решается **правильным распознаванием схемы**, а не сложной математикой.

## Что мы теперь знаем

- Misc-крипто — про **распознавание схемы**, а не про сложную математику.
- Односимвольный XOR — перебор 256 ключей; повторяющийся — сначала длина ключа.
- Длину ключа оценивают нормализованным расстоянием Хэмминга между блоками.
- Crib (известный префикс, например `FLAG{`) сразу даёт первые байты ключа.
- Классические сдвиги (ROT, Атбаш) ломаются перебором; подстановки — частотным анализом.

## На что смотреть дальше

- **Не распознать двойное кодирование** — декодируйте итеративно (base64 поверх XOR и т.п.).
- **Игнорировать регистр** — ROT сохраняет регистр, base64 — нет.
- **Неверный алфавит** — base58/base85 различаются; стандартный `base64 -d` их не возьмёт.
- **Забыть про префикс флага** — он часто и есть crib для XOR.
- **Путать хеш и шифр** — хеш необратим, нужен словарь/`hashcat`, а не декодер.
- **Нестандартные алфавиты** — декодируйте вручную через `int(s, base)`.

| `[A-Z2-7]` | base32 | `base64 -d` (b32) |
