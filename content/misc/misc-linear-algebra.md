## Вопрос, с которого всё начинается

У тебя есть генератор потока битов (например, LFSR), и ты знаешь часть его выхода. Восстановить начальное состояние — это решить систему линейных уравнений. Только работаем мы не с обычными числами, а с **двоичным полем GF(2)**, где всё проще, чем кажется.

## Наш пример

У нас есть `linear.log` — система уравнений над GF(2):

```
vars: x1 x2 x3
eq: x1 + x2 = 1
eq: x2 + x3 = 0
eq: x1 + x3 = 1
```

Здесь `+` — сложение по модулю 2 (XOR), а `=` — равенство. Наша задача — решить систему.

## Шаг 1: что такое поле GF(2)

**Поле** — это множество чисел, где работают сложение, вычитание, умножение и деление. **GF(2)** (Galois field из двух элементов) содержит только `0` и `1`, и:

- `1 + 1 = 0` (сложение по модулю 2, то есть XOR);
- `1 + 0 = 1`, `0 + 0 = 0`;
- вычитание совпадает со сложением: `a - b = a + b`;
- умножение — обычное `AND`, деление на 1 — без изменений.

Почему это удобно? Потому что биты — это элементы GF(2), а XOR — сложение в нём. Любая схема из XOR-ов и есть линейная система над GF(2).

## Шаг 2: запись системы матрицей

Систему удобно записать как `A * x = b`, где `A` — матрица коэффициентов, `x` — вектор неизвестных, `b` — правая часть. Для нашего примера:

```
A = [1 1 0]   x = [x1]   b = [1]
    [0 1 1]       [x2]       [0]
    [1 0 1]       [x3]       [1]
```

Решить — значит найти `x`, при котором равенство выполняется.

## Шаг 3: метод Гаусса

Метод Гаусса (исключение) работает и над GF(2):

1. выбери строку с ведущей единицей в первом столбце;
2. сложи её (XOR) с другими строками, чтобы обнулить первый столбец;
3. перейди к следующему столбцу;
4. в конце получишь единичную матрицу и значения `x`.

Всё то же, что в школе, только вместо вычитания — XOR. Никаких дробей: элементы всегда `0` или `1`.

## Шаг 4: ранг и разрешимость

**Ранг** матрицы — число независимых строк. Возможны три случая:

- `rank(A) = rank([A|b]) = n` — единственное решение;
- `rank(A) = rank([A|b]) < n` — бесконечно много решений (свободные переменные);
- `rank(A) < rank([A|b])` — решений нет (система противоречива).

В CTF чаще всего решение единственно: данных ровно столько, сколько неизвестных. Если решений много — задача даёт подсказку (например, формат флага), чтобы выбрать нужное.

## Шаг 5: где это встречается

- **LFSR** (linear feedback shift register) — регистр сдвига с линейной обратной связью; его выход — линейная функция состояния. По `n` битам выхода восстанавливают `n` бит состояния.
- **CRC** — контрольная сумма тоже линейна; по известным данным восстанавливают параметры или подделывают CRC.
- **XOR-«шифры»** — ключ восстанавливают решением системы по известному фрагменту открытого текста.
- **Линейные коды** — порождающая и проверочная матрицы.

Везде схема одна: **неизвестные → линейные уравнения → метод Гаусса**.

## Шаг 6: как это выглядит в задаче

Типовой сценарий: дан фрагмент keystream LFSR. Строим матрицу: каждая строка — формула очередного выходного бита через биты начального состояния (они выражаются через характеристический многочлен). Решаем систему — получаем начальное состояние. Далее генерируем keystream и расшифровываем.

## Шаг 7: находим флаг в данных

В `linear.log` есть строка `flag` в base64:

```
$ grep flag linear.log
flag: bnRve2dmMl9sMW4zNHJfc3lzdDNtX3MwbHYzZH0=
```

Декодируем и пишем в файл:

```
$ grep flag linear.log | cut -d: -f2 | base64 -d
nto{gf2_l1n34r_syst3m_s0lv3d}
$ grep flag linear.log | cut -d: -f2 | base64 -d > found.txt
$ check
```

Метка описывает результат: линейная система над GF(2) решена.

## Что мы теперь знаем

- В GF(2) всего два элемента; сложение — это XOR, вычитание = сложение.
- Систему записывают как `A * x = b` и решают методом Гаусса.
- Ранг определяет, одно решение, много или ни одного.
- LFSR, CRC и XOR-шифры — всё это линейные системы над GF(2).
- По `n` битам выхода LFSR восстанавливают `n` бит состояния.
