## Вопрос, с которого всё начинается

Задача даёт файл `challenge.js`. Открываешь — а там одна длинная строка из японских смайликов: `ﾟωﾟﾉ= /｀ｍ´）ﾉ ~┻━┻`. Это точно JavaScript? И если да, что он делает — и как это посмотреть, не выполнив у себя на машине что-то опасное?

## Наш пример: challenge.js

Смотрим начало файла:

```
$ head -c 120 challenge.js
ﾟωﾟﾉ= /｀ｍ´）ﾉ ~┻━┻   //*´∇｀*/ ['_']; o=(ﾟｰﾟ)  =_=3; c=(ﾟΘﾟ) =(ﾟｰﾟ)-(ﾟｰﾟ);
```

Букв латиницы почти нет — только смайлики и символы. Это **обфусцированный JavaScript**: валидный код, записанный так, чтобы его было тяжело прочитать. Вид со смайликами — конкретная схема, **AAencode**.

Задача: понять, что внутри. Ключевая мысль урока — обфускация не шифрование: код всё равно должен исполниться движком, значит, где-то в конце он «раскрывается» в читаемую строку. Наша цель — перехватить этот момент.

## Шаг 1: почему нельзя просто запустить

Первое желание — `node challenge.js`. Но обфусцированный код может:

- читать ваши файлы (`fs`), ходить в сеть (`fetch`) и сливать данные;
- выполнять любые команды через `child_process`.

Запускать недоверенный JS на рабочей машине — плохая идея. Поэтому сначала — изолированное окружение без сети:

```
$ docker run --rm -i --network none -v "$PWD:/w" -w /w node:20 \
    node -e 'console.log("sandbox ok")'
sandbox ok
```

`--network none` отрезает сеть, `-v "$PWD:/w"` даёт доступ только к текущей папке. Теперь запуск внутри контейнера безопасен: даже если код вредоносный, ему некуда деться.

## Шаг 2: перехватываем eval

Большинство обфускаторов в финале вызывают `eval(...)` или `Function(...)` — встроенные функции JS, которые исполняют **строку как код**. Значит, если подменить их до запуска, мы увидим ту самую «настоящую» строку.

Пишем обёртку:

```javascript
const fs = require('fs');
const src = fs.readFileSync('challenge.js', 'utf8');
const realEval = global.eval;
global.eval = (x) => { console.log('=== EVAL ===\n' + x); return x; };
try { realEval(src); } catch (e) { console.log('ERR', e.message); }
```

Запускаем в контейнере без сети:

```
$ docker run --rm -i --network none -v "$PWD:/w" -w /w node:20 node wrapper.js
=== EVAL ===
console.log('flag{...}')
```

Вот и всё: перехват `eval` показал код, который обфускатор собирался исполнить. Часто после одного-двух слоёв появляется читаемый JavaScript — а иногда сразу флаг.

## Шаг 3: три схемы по алфавиту

Схем обфускации много, но распознаются они по «алфавиту» — как esolang из прошлого урока:

| Схема | Признак |
|-------|---------|
| JSFuck | только `[ ] ( ) ! +` |
| jjencode | много `$`, `_`, `{ }`, `~` |
| AAencode | смайлики `ﾟωﾟﾉ`, `｀ｍ´` |
| Packer | начинается с `eval(function(p,a,c,k,e,d)` |

**JSFuck** — самый эзотерический: любой JS записывается шестью символами. Он опирается на то, что `[]` — пустой массив, `![]` — `false`, `!![]` — `true`, а `+[]` — `0`. Из строк `"false"`, `"true"`, `"undefined"` вытаскиваются буквы, и постепенно собирается строка `"constructor"`, которой вызывают конструктор `Function` — он исполняет произвольный код.

**jjencode** выглядит как `$=~[];$={___:++$,...}` — использует `$`, `_` и скобки.

**AAencode** — наш `challenge.js`: программа притворяется японскими смайликами, но остаётся обычным JS.

## Шаг 4: Packer и авто-деобфускация

Отдельный частый гость — **Packer** Дина Эдвардса:

```javascript
eval(function(p,a,c,k,e,d){...}('...',62,62,'...'.split('|'),0,{}))
```

Он сжимает код в base62 и восстанавливает через `eval`. Деобфусцируется той же подменой `eval` на `console.log` — обёртка из Шага 2 подходит без изменений.

Для массовых задач есть готовые инструменты:

- `js-beautify` — расставляет отступы, часто этого достаточно, чтобы увидеть структуру;
- `de4js` — поддерживает десятки схем сразу (JSFuck, jjencode, AAencode, Packer);
- `@babel/parser` — разбирает код в AST и позволяет вытащить все строки статически, вообще без исполнения.

```
$ npx js-beautify packed.js > pretty.js
$ head -5 pretty.js
var _0x4f2a = ['flag', 'log', ...];
```

`js-beautify` не декодирует, но превращает однострочник в читаемую структуру — с него удобно начинать.

## Полный прогон от начала до конца

Соберём всё в одну историю. На входе — `challenge.js` (AAencode), цель — узнать, что внутри.

```
$ head -c 60 challenge.js
ﾟωﾟﾉ= /｀ｍ´）ﾉ ~┻━┻ ['_']; o=(ﾟｰﾟ)  =_=3;
```

1. По алфавиту (смайлики) понимаем: это AAencode, валидный JS.
2. Кладём рядом `wrapper.js` с перехватом `eval`/`Function`.
3. Запускаем в контейнере без сети: `docker run --rm -i --network none ...`.
4. В логе видим раскрытую строку — читаемый код или сразу флаг.

```
$ docker run --rm -i --network none -v "$PWD:/w" -w /w node:20 node wrapper.js
=== EVAL ===
console.log('flag{obfuscation_is_cosmetic}')
```

Пять минут — и обфускация снята. Никакого «деобфусцирования вручную по символам» не понадобилось.

## Если не сработало

- **Код не вызывает `eval`, а использует `Function`.** Наша обёртка перехватывает оба — но если автор применил `setTimeout('...', 0)` со строкой, добавьте и его.
- **Код рассчитан на браузер.** `document` и `window` в Node отсутствуют, и скрипт упадёт. Тогда запускайте в headless-браузере (Playwright) или подставьте заглушки-объекты.
- **Строки собираются динамически.** Если `Function` получает вычисленную строку, статический разбор не поможет — перехват покажет её аргумент в момент вызова.
- **Вывод пустой.** Возможно, код печатает не через `console.log`, а возвращает значение — оберните запуск в `console.log(...)`.

Правило простое: не запускайте недоверенный JS там, где лежат ценные данные. Изоляция без сети — обязательна, потому что обфусцированный код умеет ходить в `fetch` и сливать содержимое.

## Что мы теперь знаем

По-простому:

1. Обфусцированный JS — не шифр: он обязан раскрыться в читаемую строку перед исполнением.
2. Схему определяем по алфавиту: JSFuck (`[]()!+`), jjencode (`$ _`), AAencode (смайлики), Packer (`eval(function(p,a,c,k,e,d)`).
3. Ключевой приём — подменить `eval`/`Function` до запуска и увидеть настоящий код.
4. Запускать недоверенный JS только в контейнере без сети.
5. Для статического разбора — `js-beautify` и парсеры AST.

## На что смотреть дальше

- **Не только `eval`.** Обфускаторы используют и конструктор `Function`, и `setTimeout` со строкой — перехватывайте их тоже.
- **`document`/`window` нет в Node.** Если код падает, он рассчитан на браузер — запускайте в headless-браузере или подставьте заглушки.
- **Строки собираются динамически.** `String.fromCharCode` с вычислениями мешает статическому анализу — тогда перехват `Function` покажет финальный аргумент.
- **Ограничьте время.** Циклы возможны: `timeout 10 node wrapper.js`.
- **Не отправляйте флаг третьим лицам.** Онлайн-декодеры получают ваш код — для реальных задач только локально.

## Куда дальше

Мы научились распутывать обфусцированный JS до читаемого кода. Дальше заглянем в другой угол esolang: **Befunge** — язык, где программа двумерная, а исполнитель ходит по ней вправо, влево, вверх и вниз, меняя направление на лету. А пока запомни главное: обфускация — это косметика, и подмена `eval` почти всегда показывает её наизнанку.
