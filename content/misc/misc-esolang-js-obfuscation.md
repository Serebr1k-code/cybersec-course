JavaScript — язык с богатой культурой обфускации: от эзотерического JSFuck (только 6 символов) до самодельных packer-ов и eval-цепочек. В CTF такие задачи выглядят как «нечитаемый JS» и просят понять, что он делает, или выполнить его безопасно. Этот урок — про распознавание и деобфускацию.

## JSFuck

JSFuck — валидный JS, записанный только символами `[]()!+`. Он исполняется обычным движком. Основные примитивы:

- `[]` → массив → `![]` → `false`;
- `!![]` → `true`;
- `+[]` → `0`, `+!![]` → `1`;
- `(![]+[])[+[]]` → `f` (буква из строки `"false"`);
- из строк `"false"`, `"true"`, `"undefined"`, `"NaN"` собираются все буквы;
- через `[]["filter"]["constructor"]("return ...")()` вызывается произвольный код.

Пример: `alert(1)` в JSFuck — длинная строка из `[]()!+`. Распознать легко: длинная строка без букв и цифр.

```bash
node jsfuck.js
# alert(1)
```

Безопаснее — не запускать, а деобфусцировать через онлайн-декодер или в изолированном Node.

## jjencode и AAencode

- **jjencode** — обфускация в стиле `$=~[];$={___:++$,...}`; использует только `$`, `_`, символы.
- **AAencode** — программа выглядит как японские смайлики: `ﾟωﾟﾉ= /｀ｍ´）ﾉ ~┻━┻`.

Оба — валидный JS. Распознаются по алфавиту. Для деобфускации:

```javascript
// замените финальный eval на console.log, чтобы увидеть код
console.log(OBFUSCATED);
```

Или перехватите `eval`/`Function`:

```javascript
const orig = global.eval;
global.eval = (x) => { console.log("EVAL:", x); return orig(x); };
require('./obf.js');
```

## Packer-ы и eval-цепочки

Часто встречается `eval(function(p,a,c,k,e,d){...}('...',62,62,'...'.split('|'),0,{}))` — это **Packer** Дина Эдвардса. Он сжимает код в base62 и восстанавливает через eval. Деобфускация: замените `eval` на `console.log` или используйте `js-beautify` + ручной разбор.

```bash
# распаковка Packer через node
node -e "const s=require('fs').readFileSync('packed.js','utf8'); console.log(eval('('+s.replace(/^eval/,'')+')'))"
```

(Осторожно: выполнение недоверенного кода — только в песочнице.)

## Безопасный запуск

Никогда не запускайте недоверенный JS на хосте. Варианты:

- изолированный контейнер без сети: `docker run --rm -v $PWD:/w -w /w --network none node node script.js`;
- онлайн-песочница;
- перехват опасных API (`eval`, `Function`, `require`, `child_process`) до выполнения.

```bash
docker run --rm --network none -v "$PWD:/w" -w /w node:20 node script.js
```

## Разобранный пример

Дано: `challenge.js`, начинается с `ﾟωﾟﾉ= /｀ｍ´）ﾉ ~┻━┻`. Это AAencode.

Меняем конец файла, чтобы увидеть результат, либо перехватываем eval:

```javascript
// wrapper.js
const fs = require('fs');
const src = fs.readFileSync('challenge.js','utf8');
const realEval = eval;
global.eval = (x) => { console.log('DECODED:\n', x); return x; };
realEval(src);
```

Запускаем в контейнере без сети — получаем декодированный код или флаг.

## Частые ошибки и подводные камни

- Запускать обфусцированный JS на хосте — риск RCE/утечки.
- Считать JSFuck «безопасным» — внутри может быть любой код.
- Пытаться деобфусцировать вручную длинные Packer-строки — используйте инструменты.
- Забывать про `Function`-конструктор: не только `eval`.
- Игнорировать минификацию: `js-beautify` часто сразу проясняет структуру.
- Путать JSFuck и jjencode — разные алфавиты.

## Дополнительная теория: как работает JSFuck

JSFuck эксплуатирует динамическую природу JavaScript. Базовые кирпичи: `[]` — пустой массив, `![]` — `false` (массив истинен, отрицание даёт false), `!![]` — `true`, `+[]` — `0` (приведение пустого массива к числу), `+!![]` — `1`. Из этих чисел и строк строятся индексы и буквы. Строка `"false"` даёт буквы `f`, `a`, `l`, `s`, `e`; `"true"` — `t`, `r`, `u`, `e`; `"undefined"` — `u`, `n`, `d`, `e`, `f`, `i`; `"NaN"` — `N`, `a`. Комбинируя доступ к символам через `[число]` и конкатенацию через `+`, получают любые буквы и строят строки вроде `"constructor"`.

Ключевой приём — доступ к `Function`-конструктору: `[]["filter"]` даёт функцию `Array.prototype.filter`, `[]["filter"]["constructor"]` — конструктор `Function`, а `Function("return ...")()` исполняет произвольный код. Именно так JSFuck обходит отсутствие букв и цифр. Понимание этой цепочки позволяет не просто запускать, но и **читать** обфусцированный код: мысленно раскручивая примитивы к осмысленным строкам.

## Автоматическая деобфускация

Для массовых задач полезно автоматизировать. `js-beautify` расставляет отступы и переносы — часто этого достаточно, чтобы увидеть структуру. `de4js` (онлайн и npm) поддерживает десятки схем: JSFuck, jjencode, AAencode, Packer, URL-encode, `\x`/`\u`-escape. Для Packer можно написать распаковщик вручную: код вида `eval(function(p,a,c,k,e,d){...}(...))` легко превратить в функцию, подставив заглушку вместо `eval`. Ещё один приём — статический анализ AST: распарсите код через `esprima`/`@babel/parser`, обойдите дерево и выведите все строковые литералы и вызовы `eval`/`Function`. Это безопаснее, чем исполнение.

```javascript
const parser = require('@babel/parser');
const traverse = require('@babel/traverse').default;
const ast = parser.parse(src);
traverse(ast, {
  StringLiteral(p) { console.log('STR:', p.node.value); },
  CallExpression(p) { console.log('CALL:', p.node.callee.name); },
});
```

## Меры защиты и реальные сценарии

JS-обфускация используется не только в CTF: ей защищают проприетарную логику, маскируют малварь и обходят детекторы. Поэтому навык двусторонний. Для защиты кода применяют `javascript-obfuscator` (control-flow flattening, string array, dead code). Для анализа малвари — деобфускацию в песочнице с перехватом API. В bug bounty обфусцированный клиентский JS часто содержит скрытые endpoints, API-ключи и логику проверок на клиенте, которую можно обойти. Практическое правило: никогда не запускайте недоверенный JS там, где есть ценные данные, — используйте изолированный контейнер без сети и с ограниченными правами.

## Разбор ошибок и отладка

Если `node script.js` падает — не спешите считать код битым: часто не хватает глобальных объектов (`window`, `document`), которые есть только в браузере. В таком случае запускайте в headless-браузере (Playwright/Puppeteer) или подделывайте заглушки. Если код «ничего не выводит», перехватите `console.log`, `eval`, `Function` и посмотрите, что происходит внутри. Если код зацикливается — ограничьте время выполнения (`timeout 10 node script.js`). И помните про `require`/`process` в Node: обфусцированный код может пытаться читать файлы или сеть — изоляция обязательна.

## Частые вопросы

**Безопасно ли запускать JSFuck на онлайн-декодере?** Если внутри есть флаг/секрет — нет: вы отправляете код третьей стороне. Для учебных примеров — приемлемо, для реальных задач — только локально в изолированном контейнере без сети.

**Как отличить JSFuck от jjencode с первого взгляда?** JSFuck состоит исключительно из `[]()!+` (шесть символов). jjencode использует `$`, `_`, `{}`, `~`, цифры. AAencode — смайлики. Если видите буквы латиницы и `$` — вероятно, jjencode; если только скобки и знаки — JSFuck.

**Что если обфусцированный код использует `document`/`window`?** В Node этих объектов нет, и код упадёт. Запускайте в headless-браузере (Playwright) или подделывайте заглушки. Часто проще открыть код в браузерной консоли (в изолированном профиле).

**Может ли JSFuck делать сетевые запросы?** Да, через `fetch`/`XMLHttpRequest`, если они доступны. Поэтому изоляция должна включать запрет сети (`--network none`), иначе обфусцированный код может эксфильтрировать данные.

**Как деобфусцировать код, который использует динамическую генерацию строк?** Иногда строки собираются из `String.fromCharCode` с вычислениями. Тогда статический анализ затруднён — запустите в песочнице с перехватом `Function`/`eval` и залогируйте аргументы: часто код в итоге вызывает `Function(...)` с читаемой строкой.

## Практический разбор: деобфускация в изолированной песочнице

Дано: `obf.js` (AAencode), задача — понять, что он делает. Не запускаем на хосте. Полный цикл:

```bash
docker run --rm -i --network none -v "$PWD:/w" -w /w node:20 \
  node -e '
    const fs=require("fs");
    const src=fs.readFileSync("obf.js","utf8");
    const realEval=global.eval;
    global.eval=(x)=>{ console.log("=== EVAL ===\n"+x); return x; };
    global.Function=function(...a){ console.log("=== FUNCTION ===\n"+a.join("\n")); };
    try { realEval(src); } catch(e){ console.log("ERR", e.message); }
  '
```

Перехватив `eval`/`Function`, мы видим «настоящий» код. Часто после одного-двух уровней появляется читаемый JavaScript с флагом или логикой. Если код использует `document`/`window` и падает — подделываем заглушки или запускаем в headless-браузере. Если строки динамические — перехват покажет аргументы `Function`. Всегда без сети (`--network none`), чтобы исключить эксфильтрацию. Сохраняйте декодированные слои — они пригодятся для отчёта.
