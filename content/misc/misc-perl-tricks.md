## Вопрос, с которого всё начинается

В CTF-задаче категории Misc тебе дают файл `dump.log` — обычный текстовый лог на сотни строк. Где-то в нём спрятан флаг, но он закодирован, а руками листать лог — долго. Писать большой скрипт на Python тоже не хочется: задача решается за десять секунд, если знать правильные однострочники.

В этом уроке мы возьмём один реальный лог и вытащим из него флаг цепочкой коротких команд — `grep`, `awk`, `sed` и `perl`. Всё, что нужно, уже есть в любой Linux-системе.

## Наш пример: dump.log

Вот наш лог целиком (в реальной задаче он длиннее, но принцип тот же):

```
2026-10-12 10:01:02 INFO session=1 user=admin ip=10.0.0.5
2026-10-12 10:01:03 DEBUG payload=ZmxhZ3twZXJsX29uZWxpbmVyc30=
2026-10-12 10:01:04 INFO session=2 user=bob ip=10.0.0.7
2026-10-12 10:01:05 DEBUG token=QUJDTk9URkxBRw==
2026-10-12 10:01:06 WARN retry=3
2026-10-12 10:01:07 DEBUG payload=RkxBR3tiYXNlNjRfZGVjb2RlX2NoYWlufQ==
```

Видно, что после `payload=` и `token=` идут строки из букв и цифр, оканчивающиеся на `=`. Это похоже на **Base64** — способ записать произвольные байты шестьюдесятью четырьмя печатными символами (мы разбирали его в уроках про кодировки). Логично декодировать эти строки и посмотреть, что внутри.

## Шаг 1: разобрать лог на поля через awk

Сначала посмотрим на структуру. Строки разделены пробелами, и у каждой есть «поля»: дата, время, уровень, дальше ключ=значение. Инструмент, который режет строку на поля, — **`awk`**. По умолчанию он считает полем группу символов между пробелами, а `$1`, `$2` — это первое, второе поле.

```
$ awk '{print $4}' dump.log
session=1
payload=ZmxhZ3twZXJsX29uZWxpbmVyc30=
session=2
token=QUJDTk9URkxBRw==
retry=3
payload=RkxBR3tiYXNlNjRfZGVjb2RlX2NoYWlufQ==
```

Так можно вытащить любую колонку. А ещё `awk` умеет считать: если бы в логе были числа, `awk '{s+=$1} END{print s}'` сложил бы их все и напечатал сумму. Шаблон `END{...}` выполняется один раз после обработки всех строк — это удобно для итогов.

## Шаг 2: вытащить кандидатов через grep -aoE

Теперь нужно выхватить все Base64-подобные строки. Тут работает `grep` с регулярным выражением:

- `-o` — печатать только совпавшую часть, а не всю строку;
- `-a` — считать файл текстом, даже если внутри попадаются непечатные байты;
- `-E` — включить расширенные регулярные выражения.

```
$ grep -aoE '[A-Za-z0-9+/]{16,}={0,2}' dump.log
ZmxhZ3twZXJsX29uZWxpbmVyc30=
QUJDTk9URkxBRw==
RkxBR3tiYXNlNjRfZGVjb2RlX2NoYWlufQ==
```

Выражение `[A-Za-z0-9+/]{16,}` означает «шестнадцать и больше символов из алфавита Base64», а `={0,2}` — необязательное выравнивание в конце. Так мы отсекли короткие случайные слова и оставили три кандидата.

## Шаг 3: декодировать цепочкой пайпов

Дальше передаём каждый кандидат в `base64 -d`. Знак `|` — это **пайп**: выход одной команды становится входом следующей. Конструкция `while read -r b; do ... done` читает строки по одной и обрабатывает каждую.

```
$ grep -aoE '[A-Za-z0-9+/]{16,}={0,2}' dump.log \
    | while read -r b; do echo "$b" | base64 -d 2>/dev/null; echo; done
flag{perl_oneliners}
ABCNOTFLAG
FLAG{base64_decode_chain}
```

Один из кандидатов (`ABCNOTFLAG`) — не флаг, а просто строка. Поэтому добавим в конец ещё один `grep`, который оставит только строки вида `flag{...}`:

```
$ grep -aoE '[A-Za-z0-9+/]{16,}={0,2}' dump.log \
    | while read -r b; do echo "$b" | base64 -d 2>/dev/null; echo; done \
    | grep -aoE 'flag\{[^}]+\}|FLAG\{[^}]+\}'
flag{perl_oneliners}
FLAG{base64_decode_chain}
```

`[^}]+` — это «один или больше символов, кроме закрывающей фигурной скобки», так флаг не «съест» лишний текст после себя. Задача решена конвейером из четырёх команд.

## Шаг 4: когда нужен perl — сложная логика

`grep`/`awk`/`sed` хороши для простого, но иногда нужно внутри замены что-то *посчитать*. Тут берём **Perl** с его флагами:

- `perl -ne '...'` — выполнить код для каждой строки, текущая строка в `$_`;
- `perl -pe '...'` — то же, но результат печатается сам (`-p`);
- `-a` — автоматически разбить строку на поля `@F`.

Например, вытащим все IP-адреса из лога регуляркой:

```
$ perl -ne 'while(/(\d{1,3}(?:\.\d{1,3}){3})/g){print "$1\n"}' dump.log | sort -u
10.0.0.5
10.0.0.7
```

А вот killer-фича Perl — флаг `e` в подстановке `s///e`: он выполняет правую часть как Perl-код, а не как текст. Так можно декодировать hex прямо в замене:

```
$ echo '%41%42%43' | perl -pe 's/%([0-9A-Fa-f]{2})/chr(hex($1))/ge'
ABC
```

Здесь `chr(hex($1))` превращает «41» в шестнадцатеричное число 65 и берёт символ с этим кодом — `A`. Один `e` заменяет целый скрипт декодирования.

## Шаг 5: агрегация и частотный анализ

Ещё один частый приём — посчитать, что встречается чаще всего. Например, сколько раз встречается каждый уровень лога: `awk` берёт третье поле, `sort` сортирует, `uniq -c` считает повторы, `sort -rn` ставит большее вверх:

```
$ awk '{print $3}' dump.log | sort | uniq -c | sort -rn
      3 DEBUG
      2 INFO
      1 WARN
```

Тот же приём с `grep -o` вытащит всех пользователей:

```
$ grep -oE 'user=[a-z]+' dump.log | sort | uniq -c | sort -rn
      1 user=bob
      1 user=admin
```

А для частотного анализа букв (частая часть крипто-задач) удобен Perl с хешем — таблицей «ключ → значение»:

```
$ echo 'hello' | perl -ne 'for(split//){$c{$_}++} END{print "$_ $c{$_}\n" for sort keys %c}'
 1
e 1
h 1
l 2
o 1
```

`split//` разбивает строку на отдельные символы, `$c{$_}` — счётчик для каждого, а `END{...}` печатает итог после обработки. Так из «просто строки» получается статистика.

## Что мы теперь знаем

1. `awk` режет строку на поля (`$1`, `$2`, …) и умеет считать в блоке `END`.
2. `grep -aoE` выхватывает из файла только совпавшие фрагменты по регулярке.
3. Пайп `|` соединяет команды в конвейер — выход одной идёт во вход следующей.
4. `perl -ne`/`-pe` обрабатывают строки, а `s///e` выполняет код в замене.
5. `sort | uniq -c | sort -rn` — универсальный способ посчитать частоты.

## На что смотреть дальше

- **Забыть `-a` у grep.** На «грязном» файле `grep` без `-a` молчит, будто совпадений нет.
- **Путать `-n` и `-p`.** У `perl -n` результат нужно печатать самому, у `-p` — нет.
- **Жадные квантификаторы.** `.*` съедает больше, чем нужно; для «до ближайшего» используй `.*?` или класс `[^...]`.
- **`sed -i` без бэкапа.** Перезапись на месте необратима — делай копию или `-i.bak`.
- **Обрабатывать бинарный файл как текст.** Сначала `file` и `xxd`, потом текстовые инструменты.
