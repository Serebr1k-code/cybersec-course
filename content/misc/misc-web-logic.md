## Введение

Misc-web — это задачи, где есть веб-интерфейс, но уязвимость **не в стандартной категории** (не SQLi, не XSS). Сюжеты: «угадай число» / «успей нажать» / «пройди игру» (нужна автоматизация), капча (обход или распознавание), rate-limit (обход), логика (сломать правила), задачи на закономерности. Это самый «инженерный» подраздел: часто решение — скрипт на Python, а не эксплойт.

## Что такое misc-web

Это задачи, где есть веб-интерфейс, но уязвимость не в стандартной категории. Сюжеты:

- «Угадай число» / «успей нажать» / «пройди игру» — нужно автоматизировать.
- Капча, которую можно обойти или распознать.
- Rate-limit, который обходится хитростями.
- Логика, где нужно «сломать правила» (отрицательные суммы, переполнение, гонка).
- Задачи на закономерности, где ответ — результат перебора/анализа.

## Обход rate-limit

Ограничение «не более N запросов» часто наивно. Приёмы:

- **Заголовки** — подмена `X-Forwarded-For`, `X-Real-IP`, `X-Client-IP`, `X-Originating-IP`:

```bash
for i in $(seq 1 100); do
  curl -s -H "X-Forwarded-For: 10.0.0.$i" http://t/attempt?pin=$i
done
```

- **Разные сессии** — новый cookie/JWT на каждый запрос, если лимит привязан к сессии.
- **Case/пути** — `/api`, `/api/`, `/API`, `//api` могут считаться разными эндпоинтами.
- **Параметры-мусор** — `?x=1`, `?x=2` иногда обходит кэш лимитера.
- **Параллелизм** — лимит может проверяться **до** инкремента; гонка позволяет превысить.

## Race condition (гонки)

Когда проверка и действие не атомарны, параллельные запросы обходят лимит/баланс:

```python
import concurrent.futures, requests
s = requests.Session()
s.headers['Cookie'] = 'session=...'

def fire(_):
    return s.post('http://t/redeem', json={'code': 'GIFT'}).text

with concurrent.futures.ThreadPoolExecutor(max_workers=30) as ex:
    results = list(ex.map(fire, range(30)))
print(results)
```

Гонки встречаются в: применении купонов, выводе средств, голосовании, «одноразовых» токенах. Используйте barrier, чтобы ударить одновременно:

```python
import threading
barrier = threading.Barrier(30)
def worker():
    barrier.wait()
    s.post('http://t/redeem', json={'code': 'GIFT'})
```

## Слабые генераторы и предсказуемость

- **seed от времени** — угадайте timestamp (часто секунды).
- **Python `random` без seed** — Mersenne Twister; по 624 выходам предсказывается.
- **Инкрементные ID** — перебор.
- **Слабые хеши** — CRC, md5 от коротких строк.

```python
import random, time
random.seed(int(time.time()))
print(random.randint(0, 999999))
```

## Капчи и «человечность»

- **Простые капчи** (цифры) — OCR (`tesseract`) или вручную через `input()`.
- **«Нажми на все светофоры»** — автоматизируйте через Selenium/Playwright.
- **Логические капчи** — иногда подсказка в alt/классе элемента.
- **Аудио-капча** — speech-to-text.
- **Обход вовсе** — если проверка на клиенте, отправьте запрос напрямую (curl), минуя JS.

## Логические дыры

Классика misc-web:

- **Отрицательные значения** — `quantity=-1` даёт «возврат» денег.
- **Целочисленное переполнение** — огромная сумма обнуляется/уходит в минус.
- **Порядок проверок** — сначала действие, потом валидация.
- **Неверные типы** — `price=0`, `price=null`, `price[]=0`.
- **Сравнение строк/чисел** — `"1" == 1`, `"0e123" == "0e456"` (PHP-магия).
- **Скрытые поля** — подмена `role=user` на `role=admin`.
- **Множественные параметры** — `?id=1&id=2` (разное поведение фреймворков).

```bash
curl -s 'http://t/buy' -d 'item=1&qty=-100&price=9999'
```

## Задачи на закономерности

- **OEIS** — поиск последовательности чисел.
- **Статистика** — частотный анализ, гистограммы.
- **Автокорреляция** — периодичность.
- **Диффы** — сравнивайте соседние элементы.

## Разобранный пример

Дано: игра «угадай число от 0 до 10^9» с ограничением 50 попыток. Решение — бинарный поиск, автоматизированный скриптом:

```python
import requests
lo, hi = 0, 10**9
while lo <= hi:
    mid = (lo+hi)//2
    r = requests.post('http://t/guess', data={'n': mid}).text
    if 'more' in r: lo = mid+1
    elif 'less' in r: hi = mid-1
    else: print(r); break
```

## Инструменты

- `curl` — прямой запрос, минуя UI.
- `python` + `requests` — автоматизация.
- `Playwright`/`Selenium` — когда нужен JS/браузер.
- `tesseract` — OCR капч.
- `jq` — разбор ответов.
- `Burp Repeater`/`Intruder` — ручной перебор и гонки.

## Частые ошибки и подводные камни

- Решать капчу, когда её проверяет клиент (надо просто отправить запрос напрямую).
- Синхронизировать «гонку» последовательными запросами — нужен barrier.
- Забыть про cookies/CSRF-токен при автоматизации.
- Путать лимит по IP и по сессии.
- Игнорировать тип сравнения (`==` vs `===`) в логических задачах.

## Что дальше / решение

- Лимит по IP/сессии → подмена заголовка/новые сессии.
- Неатомарная проверка → гонка.
- Клиентская капча → запрос напрямую.
- Бизнес-логика → отрицательные значения, типы, переполнение.

## HTTP-механики, которые ломают логику

- **Клиентские проверки** (JS) — обходятся прямым запросом.
- **Скрытые поля форм** — подмена значений (`price`, `role`, `is_admin`).
- **Множественные значения параметра** — `?id=1&id=2` (первое/последнее/массив).
- **HTTP-метод** — `GET` вместо `POST`, `PUT`/`PATCH` без защиты.
- **Content-Type** — JSON вместо form, обход парсеров.
- **Кодировки** — двойное URL-кодирование, Unicode-нормализация.
- **Заголовки** — `X-Forwarded-*`, `X-Original-URL`, `X-Rewrite-URL` для обхода маршрутизации.

```bash
curl -s 'http://t/admin' -H 'X-Original-URL: /admin'
curl -s 'http://t/profile' -d 'role=admin'
curl -s 'http://t/api?x=1' -H 'Content-Type: application/json' -d '{"admin":true}'
```

## Гонки: тонкости

- Используйте **barrier**, чтобы запросы стартовали максимально одновременно.
- Иногда нужен один «прогревающий» запрос перед гонкой.
- HTTP/2 multiplexing помогает уложиться в окно гонки.
- Проверяйте как денежные операции, так и «одноразовые» токены/коды.

## Автоматизация игр и челленджей

Многие misc-web — это «пройди игру быстрее/точнее человека». Решение — Playwright/Selenium + логика:

```python
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b = p.chromium.launch()
    pg = b.new_page()
    pg.goto('http://t/game')
    while True:
        # прочитать состояние и нажать нужное
        state = pg.inner_text('#state')
        pg.click('#btn') if 'go' in state else None
        if 'flag' in pg.content(): break
    print(pg.content())
```

Если серверная логика проста, часто быстрее вообще отказаться от браузера и работать через `requests`.

## Кодировки и парсеры

Логические задачи часто эксплуатируют разные интерпретации одного ввода:

- JSON vs form-encoding;
- дубликаты ключей (`{"a":1,"a":2}`);
- параметры-массивы (`a[]=1&a[]=2`);
- разные регистры заголовков;
- переполнение int, `NaN`, `Infinity`.

## Что дальше

- Выбирайте инструмент по природе задачи: скрипт (requests) или браузер (Playwright).
- Проверяйте все точки расхождения парсеров.
- Гонки и лимиты — параллелизм с barrier.
