## Вопрос, с которого всё начинается

Задача даёт файл `drawing.dxf`. Это чертёж из CAD-программы, и где-то в нём спрятан текст или метка. Как разобрать формат, который ты никогда не видел, если он к тому же выглядит как набор чисел и ключевых слов?

## Наш пример: drawing.dxf

DXF (Drawing Exchange Format) — **текстовый** формат AutoCAD. Проверяем:

```
$ file drawing.dxf
drawing.dxf: ASCII text
$ head -12 drawing.dxf
0
SECTION
2
HEADER
9
$ACADVER
1
AC1015
```

Видно структуру: строки идут **парами** — код группы и значение.

## Шаг 1: группы кодов DXF

DXF — поток **пар** «код группы → значение». Код группы — целое число, задающее смысл. Основные:

| Код | Смысл |
|-----|-------|
| 0 | тип сущности (LINE, TEXT, …) |
| 2 | имя |
| 1 | строковое значение (текст!) |
| 8 | слой |
| 10/20/30 | координаты X/Y/Z |

Понимая пары, ты читаешь DXF без специальной библиотеки: `grep -A1 '^1$'` находит все строковые значения.

## Шаг 2: секции DXF

Файл делится на секции: `HEADER` (настройки), `TABLES` (слои, стили), `BLOCKS` (повторяемые элементы), `ENTITIES` (сами объекты), `OBJECTS`. Текст чертежа — сущности `TEXT`/`MTEXT` в секции `ENTITIES`. Их значения лежат под кодом 1:

```
$ grep -A1 '^TEXT$' drawing.dxf
TEXT
nto{dxf_t3xt_1s_pl41n}
```

## Шаг 3: где прячут данные в DXF

- **Текстовые сущности** (`TEXT`, `MTEXT`) — очевидное место.
- **Комментарии** (`999`) — свободный текст, часто с подсказкой.
- **Имена слоёв и блоков** (код 2) — тоже строки.
- **Расширенные данные** (`XDATA`, коды 1000+) — произвольные приложения.
- **Атрибуты блоков** (`ATTRIB`) — значения, привязанные к блокам.

`grep -oE 'nto\{[^}]*\}' drawing.dxf` ловит метку почти всегда.

## Шаг 4: DWG — бинарный родственник

**DWG** — нативный бинарный формат AutoCAD. Он версионирован: первые байты содержат строку версии (`AC1015`, `AC1027` и т.д.). Далее — заголовок, таблицы и объекты, часто со сжатием. Формат сложный и закрытый, поэтому готовые библиотеки (`libredwg`, `ezdxf` через конвертацию) — основной путь.

```
$ xxd drawing.dwg | head -2
00000000: 4143 3130 3135 0000 ...   AC1015..
```

## Шаг 5: конвертация DWG → DXF

Практичный приём: сконвертировать DWG в текстовый DXF и работать с ним. Инструменты: `libredwg` (`dwg2dxf`), онлайн-конвертеры, AutoCAD. После конвертации применяешь всё, что знаешь про DXF.

```
$ dwg2dxf drawing.dwg -o drawing.dxf
$ grep -oE 'nto\{[^}]*\}' drawing.dxf
```

## Шаг 6: бинарные строки и «хвосты»

Даже без конвертации DWG полезно прогнать `strings` — метка может лежать в незашифрованном виде в служебной части. Также проверяй **хвост** файла: данные после официального конца формата часто игнорируются просмотрщиком, но содержат полезное.

## Шаг 7: инструменты

- **ezdxf** (Python) — полноценный разбор DXF, доступ к сущностям.
- **libredwg** (`dwgread`, `dwg2dxf`) — чтение DWG.
- **ODA File Converter** — конвертация версий DWG.
- **strings / xxd / grep** — быстрый разбор без библиотек.

## Шаг 8: практический порядок

1. `file` — DXF (текст) или DWG (бинарь).
2. DXF: `head` (структура пар), `grep` по кодам 1/2/999, `grep nto`.
3. DWG: `xxd` (версия), `strings`, конвертация в DXF.
4. Проверить `XDATA`/атрибуты/хвост.
5. При необходимости — `ezdxf` для программного разбора.

## Шаг 9: зачем это в безопасности

CAD-файлы приходят на инженерные предприятия и вскрываются в просмотрщиках; известны уязвимости парсеров DWG/DXF (переполнения при разборе). Поэтому «просто открыть чертёж» может быть небезопасно — как и с любым форматом, разбирай инструментами. Плюс чертежи несут метаданные (автор, организация, пути) — источник OSINT.

## Что мы теперь знаем

- DXF — текст из пар «код группы → значение».
- Текст чертежа — сущности TEXT/MTEXT под кодом 1.
- DWG — бинарный, версионированный, сложный; конвертируется в DXF.
- Метку ищут в тексте, комментариях (999), именах и XDATA.
- `ezdxf`/`libredwg` — основные библиотеки; `strings` — быстрый путь.

## Шаг 10: как читать пары DXF программно

Ручной `grep` хорош для быстрого поиска, но для настоящего разбора нужен парсер. `ezdxf` даёт доступ к сущностям как к объектам:

```
$ python3 -c "import ezdxf; d=ezdxf.readfile('drawing.dxf'); \
  print([e.dxf.text for e in d.modelspace().query('TEXT')])"
['nto{dxf_t3xt_1s_pl41n}']
```

Это надёжнее `grep`, потому что учитывает контекст: какая сущность, в какой секции, с какими атрибутами. Если метка собрана из нескольких `TEXT`-сущностей по буквам — `ezdxf` покажет их по порядку, а `grep` — вразнобой.

## Шаг 11: MTEXT и форматирование

`MTEXT` (многострочный текст) содержит внутри собственный мини-язык форматирования: `\P` — перевод строки, `\f` — шрифт, `{}` — группировка. Поэтому «видимый» текст в чертеже отличается от сырых байтов: часть символов — управляющие. При поиске метки в `MTEXT` разэкранируй `\P` и убери коды форматирования, иначе метка «разорвана» вставками. Это частая причина «метка не находится», хотя она там есть.

## Шаг 12: расширенные данные XDATA

XDATA — механизм, позволяющий приложениям хранить в чертеже произвольные данные: числа, строки, списки, привязанные к сущностям. Для стороннего парсера это «непрозрачный» блок, а значит — идеальное место для сокрытия. Ищи коды группы 1000 (строка), 1001 (имя приложения), 1010+ (координаты) и читай их как обычные строки. В CTF XDATA — один из любимых тайников после комментариев.

## Шаг 13: бинарный DWG — уровни сложности

DWG сложнее DXF: заголовок версионирован, далее идут секции (объекты, таблицы, классы), данные часто **сжаты** (специфический алгоритм) и разбиты на «страницы». Восстанавливать это вручную почти нереально — поэтому путь один: конвертация через `libredwg` или чтение `strings` для быстрого поиска незакодированного текста. Если `strings drawing.dwg` находит метку — задача решена без полного разбора формата.

## Шаг 14: версии DWG и совместимость

Строка версии в начале (`AC1015` = AutoCAD 2000, `AC1027` = 2013, `AC1032` = 2018) определяет раскладку. Старые версии проще (меньше сжатия), новые — сложнее. Зная версию, ты выбираешь правильный конвертер: некоторые инструменты не читают новые версии. В задаче с DWG первым делом смотри версию — это подскажет, каким инструментом брать.

## Шаг 15: метаданные чертежа

CAD-файлы несут массу метаданных: имя автора, организацию, даты создания/правки, версию программы, иногда полные пути. В DXF они лежат в секции `HEADER` под переменными (`$ACADVER`, `$FINGERPRINTGUID`, `$LASTSAVEDBY`) и в `OBJECTS` (словарь). В DWG — в служебных секциях. Для OSINT и форензики это ценный источник: чертёж может выдать внутренние имена систем и сотрудников.

## Шаг 16: защита и практические риски

Парсеры CAD-форматов исторически уязвимы: переполнения буфера при разборе DWG/DXF позволяли RCE при открытии чертежа в редакторе. Поэтому «открыть чужой чертёж» — тот же риск, что открыть чужой документ. Разбирай инструментами и в изоляции. Для нас же вывод позитивный: формат настолько структурирован, что почти всегда есть готовый парсер или конвертер, и не нужно писать разбор с нуля.

## Шаг 17: полный чек-лист по CAD

1. `file` — DXF (текст) или DWG (бинарь)?
2. DWG: посмотреть версию (`xxd`), прогнать `strings`, при необходимости `dwg2dxf`.
3. DXF: `head` для структуры, `grep` по кодам 1/2/999, поиск метки.
4. Проверить `MTEXT` (разэкранировать), `XDATA`, имена слоёв/блоков.
5. Посмотреть метаданные `HEADER` для OSINT.
6. При необходимости — `ezdxf` для программного разбора.

## Итог

DXF — это поток пар «код группы → значение», где текст лежит под кодом 1, а прятать данные удобно в комментариях (999), именах и XDATA. DWG — сложный бинарный формат с версиями, который проще конвертировать в DXF, чем разбирать руками. В обоих случаях быстрый путь — `strings`/`grep`, а надёжный — готовая библиотека (`ezdxf`, `libredwg`).

## Шаг 18: координаты как данные

Помимо текста, в чертеже есть геометрия: линии, окружности, полилинии с координатами. Аномальные координаты могут кодировать данные: например, десять точек, выстроенных по возрастанию X, задают байты. В CTF это редкий, но встречающийся приём «данные в геометрии». Проверяй экстремальные значения координат — они сразу выбиваются из общего диапазона.

## Шаг 19: блоки и атрибуты

Блоки — переиспользуемые элементы (как символы), а атрибуты (`ATTRIB`) — значения, привязанные к вставкам блоков. Например, блок «рамка» с атрибутом «номер». Эти значения — тоже строки, и они хранятся отдельно от `TEXT`. `grep` по коду 1 найдёт и их, но для понимания структуры полезно `ezdxf`: он покажет, к какому блоку относится атрибут.

## Шаг 20: сравнение форматов CAD

DXF — обменный текстовый формат (читается везде). DWG — нативный бинарный (AutoCAD). DWF — формат для публикации (часто ZIP с бинарём внутри). STEP/IGES — инженерные обменные форматы (текстовые, ISO). Зная, какой формат перед тобой, выбираешь инструмент: DXF — `grep`/`ezdxf`, DWG — `libredwg`, DWF — сначала распаковать как ZIP.

## Шаг 21: выводы

CAD-форматы кажутся «сложными инженерными», но сводятся к знакомым идеям: пары ключ-значение (DXF), бинарные секции (DWG), контейнеры (DWF). Текст и метку ищут `grep`/`strings`, надёжный разбор — через библиотеку, а аномалии геометрии могут сами быть данными.
