Game hacking — это работа с чужой памятью и процессами в реальном времени: найти здоровье, золото, координаты, изменить их или заставить игру сделать что-то выгодное. В CTF это встречается как «дан бинарь-игра, добейтесь высокого счёта» или «вытащите флаг из процесса». Навыки пересекаются с reversing и malware analysis.

## Как устроена память процесса

Каждый процесс имеет виртуальное адресное пространство. Игра хранит переменные в **heap** (динамические объекты) и **static/data** (глобальные). Адреса меняются между запусками из-за ASLR и аллокаций, поэтому просто «запомнить адрес» не выйдет — нужен **pointer chain** (цепочка указателей от стабильного модуля).

Ключевые понятия:

- **Модуль** — загруженный исполняемый файл или DLL с базовым адресом (`game.exe+0x1234`).
- **Offset** — смещение внутри модуля или структуры.
- **Pointer scan** — поиск пути «статический указатель → … → целевое значение».

## Cheat Engine: базовый workflow

1. Запустить игру и Cheat Engine, приаттачиться к процессу (`Open Process`).
2. Найти значение: ввести текущее здоровье (например 100) → `First Scan` → `Exact Value`.
3. Изменить здоровье в игре (получить урон → 87) → `Next Scan` → ввести 87.
4. Остаётся несколько адресов — добавить в таблицу и менять.

```text
First Scan:  value=100   → 1 200 000 hits
Next Scan:   value=87    → 3 hits
Next Scan:   value=91    → 1 hit  ← наш адрес
```

Типы сканирования: `Exact Value`, `Unknown initial value` + `Increased/Decreased value` (когда точное число неизвестно), `Float`/`Double` для координат.

## Pointer scanning

Адрес найден, но после перезапуска он другой. Делаем `Pointer scan for this address`, перезапускаем игру, находим новый адрес, затем `Rescan memory` — CE оставляет цепочки, которые валидны в обоих запусках. Получаем что-то вроде:

```
"game.exe"+0x00A1B2C0 → 0x14 → 0x2C → 0x8   (health)
```

Это стабильный pointer chain для трейнера.

## Патчинг кода

Иногда проще изменить **инструкцию**, а не данные. В CE `Memory View` → дизассемблер → `Assemble` (Ctrl+A). Пример: инструкция `sub eax, ebx` (урон) заменяется на `nop; nop` — урон не наносится. Для постоянного патча правят сам файл:

```bash
# найти байты инструкции
xxd game.exe | grep "29 d8"   # sub eax, ebx
# заменить на 90 90 (nop)
```

## Работа с сохранениями

Сохранения — часто простой бинарный формат или XOR-обфускация. Смотрим энтропию:

```bash
file save.dat
xxd save.dat | head
# 00000000: 9a3f 0c7e ... — похоже на XOR/сжатие
```

Проверяем XOR на один байт:

```python
data = open('save.dat','rb').read()
for k in range(256):
    dec = bytes(b ^ k for b in data)
    if b'gold' in dec or b'level' in dec:
        print(k, dec[:64])
```

Часто JSON/ZIP после XOR или base64. Тогда правим значения и пишем обратно.

## DLL-инъекция и hooks

Чтобы менять значения программно, внедряют DLL и хукают функции. Инструменты: `Extreme Injector`, `x64dbg` + плагин `ScyllaHide`, а для написания — `Microsoft Detours` или ручной IAT-hook.

```cpp
// простейший hook через MinHook
MH_CreateHook(pTarget, &hkFunction, (LPVOID*)&origFunction);
MH_EnableHook(pTarget);
```

Также популярен **DLL sideloading**: игра грузит `foo.dll` из своей папки — подкладываем свою.

## Анти-читы и обход простых проверок

Анти-чит может: сканировать память на известные паттерны, проверять целостность кода (CRC), детектить дебаггер, ловить открытые хэндлы. Простейшие обходы:

- скрыть дебаггер (`ScyllaHide`, `PEB->BeingDebugged=0`);
- не патчить код, а менять данные (меньше сигнатур);
- использовать внешний DMA-ридер (аппаратный) — выходит за рамки софта;
- переименовать процесс/окно.

**Важно:** в CTF обходите только учебные/разрешённые анти-читы. В реальности обход коммерческих анти-читов нарушает EULA и часто закон.

## Полный разобранный пример

Задача: в бинаре есть функция `check_flag`, которая выводит «Access denied». Находим её и заставляем пройти.

```bash
gdb ./game
(gdb) disassemble main
(gdb) break *main+0x1a4      # сравнение результата check_flag
(gdb) run
(gdb) print $eax             # 0 = fail
(gdb) set $eax=1             # форсируем успех
(gdb) continue
```

Или патчим условный переход `jne` → `je`/`nop` в файле.

## Частые ошибки и подводные камни

- Искать `int32`, когда значение — `float` (координаты всегда float/double).
- Забывать про pointer chain — адрес «перестаёт работать» после перезапуска.
- Патчить код там, где анти-чит считает хэш.
- Работать с 32-битным процессом 64-битным сканером (или наоборот).
- Писать сохранение без пересчёта контрольной суммы — игра его отвергнет.

## Что дальше / решение

Пройдите учебный таргет (например, `Guided Hacking` или собственную игру на Unity/Godot) полным циклом: скан → pointer chain → трейнер. Затем разберите, как устроены реальные сохранения и как их подделывать. Смежно — `misc-weird-protocols` (сетевые игры) и reversing-ветка.

## Дополнительная теория: структуры данных, vtable и движки

Игры хранят объекты в куче как структуры. Игрок — это структура с полями (позиция, здоровье, инвентарь), часто в **связном списке** или **массиве указателей**. Поняв одну структуру, вы находите остальные: от указателя на игрока — к списку сущностей, от него — к позициям врагов. Полезно смотреть на **vtable** (таблица виртуальных функций) — по ней определяют тип объекта и находят его методы. В движках (Unity, Unreal) есть свои менеджеры и компонентные системы (ECS), что упрощает поиск: компоненты часто лежат рядом.

Инструменты вроде ReClass.NET позволяют реверс-инжинирить структуры визуально: вы задаёте поля, CE/ReClass показывает значения в памяти в реальном времени. Это превращает хаос памяти в понятную структуру. Для Unity есть `Il2CppDumper` (восстанавливает метаданные из `GameAssembly.dll`), для Unreal — `UE4SS`/`SDK dumpers`. С ними поиск полей становится тривиальным.

## Сетевые игры и анти-чит

В мультиплеере часть логики — на сервере. Тогда клиентские читы (например, «видеть сквозь стены») работают, если сервер доверяет клиенту. Но изменение урона/валюты часто валидируется сервером. Понимание модели доверия (client-authoritative vs server-authoritative) определяет, что вообще можно подделать. Сетевой трафик реверсится так же, как любой протокол (см. `misc-weird-protocols`): захват, разбор, повтор.

**Анти-читы** делятся на клиентские (сканируют память/процессы, проверяют целостность) и серверные (детект аномалий статистикой). Клиентские обходят скрытием/шифрованием, серверные — имитацией нормального поведения. В CTF это обычно учебные анти-читы; в реальности обход коммерческих нарушает EULA и закон — не делайте этого. Понимание анти-читов ценно и с защитной стороны: как разработчик вы делаете игры честнее.

## Разбор ошибок и отладка

Если скан не находит значение — проверьте тип (int vs float), размер (32/64 бита) и диапазон. Если адрес «плывёт» — нужен pointer chain, либо значение в структуре, доступной через другой указатель. Если игра крашится после патча — вы испортили критичную инструкцию; восстановите байты. Если анти-чит убивает процесс — отключите дебаггер-детект (ScyllaHide) или работайте только с данными. Если сохранение «не принимается» — вероятно, есть контрольная сумма/шифрование; реверсите формат. Ведите журнал адресов/смещений — они пригодятся для трейнера.

## Практический разбор: трейнер для здоровья и золота

Дано: простая игра, цель — бесконечное здоровье и золото. Цикл:

```text
1. CE → Open Process → выбираем игру
2. First Scan: health = 100, тип Int32 (или Float, если дробное)
3. В игре получаем урон (health = 73) → Next Scan: 73
4. Осталось 1-2 адреса → добавляем в таблицу, меняем на 9999
5. Перезапускаем игру — адрес изменился → Pointer scan
6. Pointer scan for this address → перезапуск → Rescan memory
7. Получаем цепочку "game.exe"+0x... → 0x14 → 0x8
```

С цепочкой пишем трейнер: скрипт, который открывает процесс, разыменовывает цепочку и пишет значения. На Python:

```python
import ctypes, struct
# OpenProcess, ReadProcessMemory, WriteProcessMemory через ctypes
# разыменовать базу модуля + offsets, записать новое значение
```

Для золота — тот же процесс: скан по значению, pointer chain, запись. Если игра шифрует значения (частая защита) — ищите «известное» значение через `Unknown initial value` + `Changed/Unchanged`. Если анти-чит — работайте только с данными (меньше сигнатур) и скрывайте дебаггер. В CTF обычно достаточно изменить одно значение или пропатчить одну инструкцию, чтобы получить флаг.
