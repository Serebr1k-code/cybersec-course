## Вопрос, с которого всё начинается

В CTF попадается задача: «составь регулярное выражение, которое матчит ровно такие-то строки», а принимающая система сравнивает длину твоего ответа с эталоном. Или наоборот — задача просит объяснить, почему готовое выражение вешает сервер. Оба случая требуют одного умения: думать регулярками как формальным языком, а не как «поиском подстроки».

В этом уроке мы возьмём одну задачу-гольф, решим её пошагово и заодно увидим, где прячется катастрофический перебор.

## Наш пример: строки без двух `b` подряд

Задача: написать регулярку, которая матчит строки из букв `a` и `b`, где **нигде не встречаются две `b` подряд**. Приниматься должны `abab`, `aab`, `ba`, а `bb` и `abb` — нет.

Сначала — наивная попытка. Хочется сказать «любые `a`, потом `b`, потом снова `a`»: `^a*(ba)*b?$`. Но это неверно: между `b` должна быть **хотя бы одна** `a`, иначе `bb` тоже подойдёт. Значит, вместо `ba` нужно `ba+` — «`b` и одна или больше `a`»:

```regex
^a*(?:ba+)*b?$
```

Разберём по частям: `^` — начало строки, `a*` — сколько угодно `a` в начале, `(?:ba+)*` — ноль или больше блоков «`b` + минимум одна `a`», `b?` — необязательная `b` в конце, `$` — конец строки. `(?:...)` — незахватывающая группа, она нужна только для группировки повтора, а не для «запоминания» текста.

Проверим на наборе строк:

```python
import re
pat = re.compile(r'^a*(?:ba+)*b?$')
for t in ['abab', 'bb', 'aab', 'abb', '', 'ba', 'abba']:
    print(repr(t), bool(pat.match(t)))
```

```
'abab' True
'bb' False
'aab' True
'abb' False
'' True
'ba' True
'abba' False
```

Работает: `bb` и `abb` отвергнуты. Из терминала то же самое делает `grep -P` (флаг `-P` включает PCRE):

```
$ printf 'abab\nbb\naab\nabb\nba\n' | grep -P '^a*(?:ba+)*b?$'
abab
aab
ba
```

## Шаг 1: приёмы гольфа

Гольф — это минимизация длины выражения. Основные приёмы:

- **Класс вместо альтернативы.** `[abc]` короче, чем `a|b|c`.
- **Квантификатор вместо повторов.** `a{3}` вместо `aaa`.
- **Классы-сокращения.** `\d` вместо `[0-9]`, `\w` вместо `[A-Za-z0-9_]`.
- **Обратные ссылки для повторяющегося.** `(.)\1` — «два одинаковых символа».
- **Lookahead для «и то, и другое».** Язык «есть и `a`, и `b`» записывается как `(?=.*a)(?=.*b)`.

Например, чётное число `a` — это `^(aa)*$`, а нечётное — `^a(aa)*$`:

```python
>>> import re
>>> for t in ['aa', 'aaaa', 'a', 'aaa']:
...     print(repr(t), bool(re.match(r'^(aa)*$', t)))
'aa' True
'aaaa' True
'a' False
'aaa' False
```

## Шаг 2: якоря и жадность — главные грабли

Две ошибки ломают гольф-решение чаще всего.

**Нет якорей.** Без `^` и `$` выражение матчит **подстроку**, поэтому «проходит» там, где не должно. Если задача требует «строка целиком», якоря обязательны.

**Жадность.** `.*` и `+` стараются захватить как можно больше. Иногда нужен ленивый вариант `.*?`, который берёт минимум. Например, чтобы вытащить текст между `<` и `>`, пишут `<.*?>` — иначе `.*` съест всё до последней `>`.

Ещё один нюанс — **порядок альтернатив**. В `(a|ab)` на строке `ab` сработает первая ветка `a`, а не вторая. Иногда это ломает логику, иногда — используется намеренно.

## Шаг 3: рекурсия — для вложенных структур

Обычными регулярками нельзя описать «сбалансированные скобки» или палиндром произвольной длины. Но в PCRE есть **рекурсия**: `(?R)` повторно применяет всё выражение, а `(?1)` — конкретную группу. Палиндром из `a`/`b` выглядит так:

```regex
^(a|b|(a(?1)a)|(b(?1)b))$
```

Читается как «либо один символ, либо `a`, внутри которой снова палиндром, и `a` в конце» — и симметрично для `b`. Это выходит за рамки «настоящих» регулярных языков, но PCRE позволяет. Важно: RE2 и Go/Rust `regex` рекурсию не поддерживают.

## Шаг 4: где прячется катастрофический перебор

Тот же движок, что даёт рекурсию, страдает от **катастрофического бэктрекинга**. Классический пример:

```regex
^(a+)+$
```

На строке из многих `a` и «плохого» символа в конце движок перебирает все способы разгруппировать `a`, и время растёт экспоненциально. Проверим замером:

```python
import re, time
for n in [18, 20, 22, 24]:
    s = 'a'*n + '!'
    t = time.time()
    re.match(r'^(a+)+$', s)
    print(n, round(time.time()-t, 4))
```

```
18 0.0099
20 0.0343
22 0.1372
24 0.5438
```

Каждые +2 символа — примерно ×4. Это и есть ReDoS (подробнее — в уроке `misc-regex-dos`). Лечится переписыванием (`a+` вместо `(a+)+`) или атомарной группой `(?>...)`, которая запрещает движку возвращаться внутрь уже сопоставленной группы.

## Шаг 5: движки и их различия

То, какая регулярка «хорошая», зависит от движка. Есть два семейства:

- **NFA с бэктрекингом** (PCRE, Perl, Python `re`, Java, JS): поддерживают обратные ссылки, lookaround, рекурсию — но подвержены экспоненциальному перебору.
- **DFA/линейные** (RE2, Go, Rust `regex`): работают за линейное время, но не поддерживают обратные ссылки и lookbehind переменной длины.

Отсюда практический вывод: если решение использует рекурсию или обратные ссылки — оно не скомпилируется в RE2; если задача про ReDoS — в RE2 уязвимости нет по построению. Всегда уточняй, какой движок на той стороне.

## Шаг 6: как отлаживать регулярки

Когда выражение «не матчит то, что должен», есть отработанный порядок проверок. Сначала проверь жадность: `.` и `+` могут «съесть» больше нужного — замени на `.*?`. Потом проверь якоря: без `m`-флага `^`/`$` относятся ко всей строке, а не к её строкам. Затем — Unicode-флаг: без него `\w` может не матчить кириллицу. Лучший инструмент для этого — `regex101.com`: он показывает **пошаговую трассировку** движка, и видно, где именно бэктрекинг уходит не туда.

Если выражение вешает процесс, запусти `regexploit` — он подберёт «злой» вход, и тогда перепиши шаблон через атомарные группы. В терминале для быстрой проверки PCRE удобно использовать `grep -P` или `perl -e`.

## Что мы теперь знаем

1. Regex-гольф — минимизация длины выражения, решающего задачу.
2. Классы, квантификаторы, обратные ссылки и lookahead сокращают запись.
3. Якоря `^`/`$` и жадность — главные источники ошибок.
4. Рекурсия PCRE описывает вложенные структуры (палиндромы, скобки).
5. Вложенные квантификаторы дают катастрофический бэктрекинг; атомарные группы лечат.
6. NFA-движки мощнее, DFA-движки линейны и не боятся ReDoS.

## На что смотреть дальше

- **Забыть якоря.** Regex матчит подстроку, а не всю строку.
- **Жадные квантификаторы там, где нужны ленивые.** Используй `.*?`.
- **Вложенные квантификаторы.** `(a+)+` — прямой путь к ReDoS.
- **Различия движков.** PCRE vs Python `re` vs RE2 — разный синтаксис и поведение.
- **Unicode-режим.** Без флага `\w` может не матчить кириллицу.
