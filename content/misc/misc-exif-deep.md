## Вопрос, с которого всё начинается

Тебе дали фотографию. На ней — обычная улица, без вывесок и указателей. Вопрос: где она сделана? Без карты и без подсказок — только файл. Ответ часто лежит в самом файле: **метаданные** камеры помнят GPS-координаты.

Это урок про EXIF, IPTC и XMP — три системы метаданных, встроенных в изображения.

## Наш пример: photo.jpg

```
$ file photo.jpg
photo.jpg: JPEG image data, EXIF standard: [TIFF image data, little-endian], ...
```

Уже `file` сообщил: внутри JPEG есть блок **EXIF**. Значит, там могут быть камера, дата, координаты.

## Шаг 1: что такое метаданные изображения

**Метаданные** — данные о данных. Для фотографии это: модель камеры, дата и время, параметры съёмки (выдержка, ISO), ориентация, а иногда — **GPS-координаты** и серийный номер. Есть три основных набора:

- **EXIF** — основной, хранится внутри JPEG/TIFF.
- **IPTC** — редакционные поля: автор, заголовок, ключевые слова.
- **XMP** — XML-метаданные Adobe: история правок, рейтинги.

Все три могут сосуществовать в одном файле.

## Шаг 2: структура EXIF

EXIF — это контейнер в формате **TIFF**. Внутри — **IFD** (Image File Directory): таблица записей «тег → значение». Каждый тег — число и тип. Ключевые теги:

| Тег | Смысл |
|---|---|
| 0x010F | Make (производитель) |
| 0x0110 | Model (модель) |
| 0x0132 | DateTime |
| 0x8825 | GPSInfo (указатель на GPS-IFD) |
| 0x0112 | Orientation |

Внутри GPS-IFD лежат координаты: `GPSLatitude`, `GPSLongitude`, `GPSLatitudeRef`.

## Шаг 3: читаем через exiftool

```
$ exiftool photo.jpg
Camera Model Name    : Pixel 6
Date/Time Original   : 2024:05:01 18:22:31
GPS Position         : 55 deg 45' 21.00" N, 37 deg 37' 4.00" E
```

`GPS Position` — готовые координаты. Их достаточно, чтобы найти место. В CTF флаг часто кодируют прямо в координатах или в нестандартном теге.

## Шаг 4: нестандартные и скрытые поля

Флаг может лежать не в GPS, а в теге, который не отображается по умолчанию:

```
$ exiftool -a -u -g1 photo.jpg | grep -i nto
Comment : nto{3x1f_s4ys_t00_much}
```

`-a` показывает все теги (включая дубли), `-u` — неизвестные, `-g1` группирует. Часто флаг прячут в `UserComment`, `ImageDescription`, `XMP` или в **thumbnail** (встроенной миниатюре). Проверяй и миниатюру:

```
$ exiftool -b -ThumbnailImage photo.jpg > thumb.jpg
$ strings thumb.jpg | grep nto
```

## Шаг 5: ручной разбор

Без exiftool можно разобрать EXIF вручную. Найди маркер `FFE1` (APP1) в JPEG:

```
$ xxd photo.jpg | head -5
00000000: ffd8 ffe1 1c2e 4578 6966 0000 4949 2a00  ......Exif..II*.
```

`FFD8` — начало JPEG, `FFE1` — APP1, `4578 6966` = `Exif`, `4949` = `II` (little-endian). Дальше — TIFF-структура. Парсится скриптом на Python с `PIL` или `piexif`:

```
$ python3 - <<'PY'
from PIL import Image, ExifTags
im = Image.open('photo.jpg')
for k, v in im.getexif().items():
    print(ExifTags.TAGS.get(k, k), '=', v)
PY
GPSInfo = 0
DateTime = 2024:05:01 18:22:31
```

## Шаг 6: удаление метаданных — неполное

Инструменты «убрать метаданные» часто чистят только видимые поля. Невидимые остаются:

- **thumbnail** — миниатюра может сохранить старую версию (до обрезки).
- **дубли тегов** — exiftool с `-a` покажет несколько значений одного тега.
- **XMP-история** — в XMP остаётся история правок.
- **padding** — между блоками бывают байты-заполнители с данными.

Поэтому при проверке утечки всегда смотри `exiftool -a -u -g1` и проверяй миниатюру.

## Полный прогон

```
$ exiftool photo.jpg | grep -i gps
GPS Position : 55 deg 45' 21.00" N, 37 deg 37' 4.00" E
$ exiftool -a -u -g1 photo.jpg | grep -i nto
Comment : nto{3x1f_s4ys_t00_much}
```

Сначала геолокация, потом — скрытая метка.

## Что мы теперь знаем

- EXIF/IPTC/XMP — три набора метаданных изображения.
- EXIF устроен как TIFF/IFD с тегами; GPS-IFD даёт координаты.
- exiftool с `-a -u -g1` показывает скрытые теги.
- Thumbnail и дубли тегов переживают «очистку».
- Метаданные — частая CTF- и OSINT-зацепка.

## JPEG-структура: где живут метаданные

JPEG — набор сегментов, каждый начинается маркером `FFxx`. `FFD8` — начало, `FFD9` — конец. `FFE1` — APP1, куда пишется EXIF; `FFED` — APP13 (IPTC); `FFE0` — JFIF. Понимая маркеры, ты находишь блок метаданных вручную: ищешь `FFE1`, читаешь длину и разбираешь TIFF внутри. Это пригодится, если exiftool недоступен или файл нестандартный.

## GPS-декодирование вручную

Координаты в EXIF хранятся как три рациональных числа (градусы, минуты, секунды) плюс ссылка N/S и E/W. Например, `55/1, 45/1, 2100/100` и `N` даёт 55°45'21" с.ш. Перевод в десятичные: `55 + 45/60 + 21/3600`. Умея это, ты читаешь GPS даже сырым дампом тегов.

## XMP и RDF

**XMP** — метаданные в формате XML (RDF). В них — история редактирования, рейтинги, инструменты, иногда авторские заметки. XMP может храниться как внутри JPEG (APP1 с сигнатурой `http://ns.adobe.com/xap/1.0/`), так и в отдельном `.xmp`-файле. При «очистке» XMP часто забывают — там остаётся старый текст и пути.

## Метаданные видео, PDF и офисных файлов

EXIF — не только про фото. Видео (MP4/MOV) хранит метаданные в атомах `udta`/`meta`; PDF — в словаре `/Info` и XMP-метаданных; офисные файлы — в свойствах OOXML. Принцип тот же: данные о происхождении и правках переживают конвертацию. Для каждого формата есть свои теги и свои инструменты.

## Инструменты

`exiftool` — универсальный, читает и пишет почти всё. `exiv2` — быстрый для EXIF/IPTC/XMP. `mat2` — удаляет метаданные (но проверяй, что удалил всё). `identify -verbose` (ImageMagick) — ещё один взгляд. Для глубокого анализа — `piexif`/`PIL` в Python: полный доступ к тегам и миниатюрам.

## OSINT-надстройка: не только GPS

Даже без координат метаданные дают зацепки: модель камеры сужает круг владельцев; дата и время помогают сопоставить с событиями; ориентация и фокус — с местом. А если GPS есть — по солнцу и теням можно уточнить время съёмки. Так метаданные превращаются в полноценную геолокацию.

## Практический сценарий: геолокация по фото

Задача: найти место по одной фотографии. Шаги: `exiftool photo.jpg` — есть ли GPS; если нет — смотрим модель камеры и время; ищем в кадре вывески, номера, архитектуру; сопоставляем с картой. Метаданные ускоряют, но не заменяют визуальный анализ. В CTF флаг часто уже в GPS-теге — тогда задача решается одной командой.

## Метаданные как источник утечки

Публикуя фото, люди утекают больше, чем думают: точные координаты дома, серийный номер устройства, имя пользователя в `Artist`, пути в XMP. Поэтому перед публикацией метаданные чистят. Но, как мы видели, очистка бывает неполной — thumbnail и дубли остаются. Аудит метаданных — стандартная часть проверки перед релизом контента.

## Анти-форензика метаданных

Против анализа: метаданные затирают, подделывают (ставят чужую модель и координаты), добавляют ложные теги-приманки. Поэтому найденный GPS не всегда правда. Проверяй согласованность: время съёмки, ориентация, наличие миниатюры, соответствие EXIF и XMP. Расхождения — сигнал подделки.

## Шпаргалка exiftool

`exiftool photo.jpg` — основное; `exiftool -a -u -g1 photo.jpg` — все и неизвестные теги; `exiftool -b -ThumbnailImage photo.jpg > t.jpg` — миниатюра; `exiftool -GPSPosition photo.jpg` — только координаты; `exiftool -all= photo.jpg` — удалить всё; `exiv2 -pa photo.jpg` — альтернативный просмотр. Держи этот набор под рукой.

## Как EXIF переживает конвертацию

Формат меняется — метаданные частично переносятся. При сохранении PNG→JPEG EXIF может сохраниться или обнулиться, в зависимости от инструмента. При загрузке в соцсеть — обычно вырезается, но не всегда из миниатюры. При копировании через файловый менеджер — сохраняется целиком. Поэтому нельзя считать «метаданные удалены», не проверив каждую копию файла: у каждой свой набор тегов.

## Частые CTF-приёмы

Флаг кладут: в `Comment`/`UserComment`; в `ImageDescription`; в XMP-поле; в GPS-координаты, закодированные как ASCII в числах; в `Make`/`Model` нестандартной строкой; в миниатюру (которая отличается от основного изображения). Иногда метаданные указывают на следующий файл («смотри вложение»), и задача становится цепочкой. Проверяй все группы тегов и миниатюру.

## Метаданные в других форматах

Не забывай, что метаданные есть и вне изображений: в MP4/MOV (атомы `meta`), в PDF (`/Info`, XMP), в офисных файлах (свойства OOXML), в архивах (комментарии ZIP), в звуке (ID3). Приём один: найти блок метаданных и прочитать. Инструменты разные, логика общая.

## Итог

Метаданные — это «слой поверх» файла, который легко пропустить и легко спрятать в нём данные. `exiftool -a -u -g1` — обязательный первый шаг. Помни про миниатюру, дубли тегов и XMP-историю: они переживают очистку. Для OSINT метаданные дают геолокацию, для CTF — флаг.

## Финальная мысль

Метаданные — самый недооценённый слой файла. Их легко забыть, легко пропустить при очистке и легко использовать для атаки. Поэтому привычка: получил изображение или документ — первым делом `exiftool -a -u -g1`, затем миниатюра, затем XMP. Три шага, которые в CTF дают флаг, а в аудите — найденную утечку координат или имени пользователя.
