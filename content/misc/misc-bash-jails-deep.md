## Restricted shell: что это и как его узнают

Restricted shell (обычно `rbash`, `rzsh` или bash, запущенный с флагом `-r`) — это оболочка, в которой отключены самые опасные возможности: смена директории (`cd`), изменение `PATH`, указание путей с `/`, перенаправления (`>`, `>>`), запуск команд по абсолютному пути, а иногда и вызов `exec`/`/bin/sh`. Такую оболочку часто выдают в CTF-джейлах и встречают в реальных системах при ограничении доступа. Цель модуля — научиться выходить из restricted shell и обходить его ограничения.

## Как распознать джейл

Признаки: `cd` не работает («cd: restricted»), `/bin/ls` не запускается, `echo $PATH` показывает урезанный путь, перенаправления запрещены. Проверьте:

```bash
echo $SHELL
echo $PATH
set -o | grep restricted   # не всегда
cat /etc/passwd | grep $USER
```

Если оболочка действительно restricted, `PATH` обычно указывает на одну директорию, где лежат лишь разрешённые программы.

## Базовые побеги: редакторы

Классика — запустить редактор и из него выполнить команду. `vi`/`vim`:

```
:!/bin/sh
:set shell=/bin/sh
:shell
```

`ed`:

```
!/bin/sh
```

Если в разрешённом PATH есть `vi`, `vim`, `ed`, `nano` — побег почти гарантирован.

## Побеги через программы с «escape»-функциями

Огромное число программ позволяют запустить shell:

- `less`/`more`: `!sh`
- `man`: `!sh` (в pager)
- `awk`: `awk 'BEGIN{system("/bin/sh")}'`
- `find`: `find / -exec /bin/sh \;`
- `python`/`perl`/`ruby`: `python -c 'import os;os.system("/bin/sh")'`
- `tar`: `tar cf /dev/null /dev/null --checkpoint=1 --checkpoint-action=exec=/bin/sh`
- `git`: `git help -a` → pager → `!sh`

```bash
awk 'BEGIN{system("/bin/sh")}'
find . -exec /bin/sh \;
```

## Обход запрета на «/» и абсолютные пути

Если нельзя писать `/`, используйте относительные пути или `PATH`:

```bash
ls           # если ls в PATH
cat flag     # относительный путь
./runme
```

Если `cd` запрещён, но нужна другая директория — попробуйте `pushd`/`popd`, если они не заблокированы, или запустите программу, которая сама сменит директорию.

## Обход через переменные и подстановки

- `${PATH:0:1}` даёт первый символ PATH (обычно `/`), если `/` запрещён:

```bash
cat ${PATH:0:1}flag
```

- `$IFS` вместо пробела.
- Подстановка команд: `$(...)` или обратные кавычки.
- Глоббинг: `?`, `*` вместо точных имён.

```bash
cat${IFS}/flag
/???/??t /????        # /bin/cat /flag
```

## Переменные PATH и IFS

Многие джейлы разрешают менять переменные окружения. `PATH` можно расширить, если есть право записи в директорию:

```bash
export PATH=/tmp:$PATH
```

Если `export` заблокирован, попробуйте присвоение `PATH=...` напрямую. `IFS` управляет разделителями слов — подмена даёт обход фильтра пробелов.

## Побег через интерпретатор

Если в PATH есть любой язык программирования, побег тривиален:

```bash
python3 -c 'import os; os.system("/bin/sh")'
perl -e 'exec "/bin/sh"'
ruby -e 'exec "/bin/sh"'
node -e 'require("child_process").spawn("/bin/sh",{stdio:[0,1,2]})'
```

Это самый частый путь: разработчик забывает убрать интерпретатор из PATH.

## Выход из rbash через известные трюки

- `bash` без `-r`: если можно запустить `bash` напрямую, ограничения снимаются.
- `exec bash`, `set +r` (не всегда).
- Через `sh` в `less`/`vi`.
- Через `sudo`/`su`, если есть права.
- Через `cron`/`at`, если доступны.

## Инструменты и ресурсы

- **GTFOBins** (gtfobins.github.io) — каталог программ с escape-функциями.
- **LOLBAS** — аналог для Windows.
- **`sudo -l`** — что разрешено.
- **`find / -perm -4000`** — SUID-бинарники.

## Типичные ошибки и подводные камни

- **Не проверить PATH** — там может быть интерпретатор.
- **Забыть про pager** (`less`/`more`/`man`) — лёгкий побег.
- **Игнорировать GTFOBins** — почти каждая программа имеет escape.
- **Пробелы заблокированы** — используйте `${IFS}`.
- **`/` заблокирован** — `${PATH:0:1}` или globbing.
- **`cd` не работает** — используйте программы, меняющие директорию.
- **Считать джейл непробиваемым** — почти всегда есть путь.

## Что дальше / решение

План: определите, что именно ограничено (cd, `/`, перенаправления, PATH). Затем проверьте PATH на наличие интерпретаторов и программ с escape-функциями — сверяйтесь с GTFOBins. Используйте pager'ы (`vi`/`less`/`man`) для выхода, `${IFS}` и `${PATH:0:1}` для обхода фильтров символов, globbing для обхода запрета на точные пути. Помните: restricted shell — это ограничение на уровне оболочки, а не системы, поэтому любая разрешённая программа с возможностью запуска команды снимает все ограничения.

## Практический пример: побег из джейла на bash

Разберём реальный сценарий. Вам дали SSH-доступ под ограниченным пользователем, оболочка — rbash. `cd` не работает, `/bin/ls` не запускается, `echo $PATH` показывает `/usr/local/rbash/bin`. Что делаем по шагам. Первое — `ls` этой директории: смотрим, какие программы разрешены. Допустим, там `vi`, `awk`, `less`. Второе — пробуем `vi`: `vi`, затем `:!/bin/sh` — если сработало, ограничения сняты, потому что мы запустили обычный shell из-под редактора. Третье — если `vi` нет, пробуем `awk 'BEGIN{system("/bin/sh")}'`. Четвёртое — если и его нет, но есть `less`, запускаем `less /etc/hostname` и жмём `!sh`.

Если оболочка запрещает слэши, обходим через `${PATH:0:1}`, который даёт первый символ PATH (обычно `/`): `cat ${PATH:0:1}flag`. Если запрещены пробелы — используем `${IFS}`: `cat${IFS}${PATH:0:1}flag`. Если запрещены точные имена — globbing: `/???/??t /????`.

## Почему restricted shell — не защита

Ключевая мысль: rbash ограничивает только интерпретацию команд *самим shell*, но не ограничивает программы, которые shell запускает. Как только вы запускаете любую программу, умеющую выполнить команду (редактор, pager, интерпретатор, архиватор), вы получаете полноценный доступ. Именно поэтому в GTFOBins собраны сотни таких «швейцарских ножей». Настоящая изоляция требует ограничений ОС: chroot, отдельный пользователь, seccomp, отсутствие интерпретаторов в PATH.

## Частые вопросы

«Что если PATH пуст?» — попробуйте абсолютные пути или `${PATH:0:1}` от другой переменной. «Что если нет ни одной программы?» — почти невозможно: для работы shell нужны утилиты. «А если `cd` нужен для чтения флага?» — используйте программы с собственной сменой директории (`tar -C`, `find`). «Как быстро найти escape-программу?» — сверяйтесь с GTFOBins по имени доступной программы.

## Что дальше / решение

Итог: определите, что ограничено, посмотрите разрешённые программы и PATH, запустите любую с escape-функцией (`vi`, `less`, `awk`, `find`, `tar`). Обходите фильтры символов через `${IFS}` и `${PATH:0:1}`. Помните: restricted shell — ограничение оболочки, а не системы, и любая программа с запуском команд снимает его.

## Частые вопросы по bash-джейлам

«PATH пуст — что делать?» — используйте абсолютные пути через `${PATH:0:1}` от другой переменной или globbing. «Нет ни одной «опасной» программы?» — почти невозможно: shell требует утилит, и почти каждая имеет escape. «Как быстро найти escape-программу?» — сверяйтесь с GTFOBins по имени доступной программы. «Запрещены пробелы?» — `${IFS}`. «Запрещён `/`?» — `${PATH:0:1}` или `?`. «Не работает `cd`?» — используйте программы со сменой директории (`tar -C`, `find`). Помните: restricted shell ограничивает оболочку, а не систему, — любая программа с запуском команды снимает ограничения.
