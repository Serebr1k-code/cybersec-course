## Вопрос, с которого всё начинается

Тебе дали файл `game.gb` и сказали: «флаг внутри, но игра его не показывает». Запускать игру бессмысленно — нужно понять, как устроен картридж, найти нужные байты и, возможно, поправить код, чтобы игра вывела флаг. Game Boy — идеальный полигон: его формат прост и полностью документирован.

## Наш пример: смотрим на файл

```
$ file game.gb
game.gb: Game Boy ROM image, 32768 bytes
$ xxd -l 64 game.gb
00000000: c3 50 01 ce ed 66 66 cc 0d 00 0b 03 73 00 83  .P...ff.....s...
00000010: 00 0c 00 0d 00 08 11 1f 88 89 00 0e dc cc 6e e6  ...............n.
```

Первые байты выглядят как данные, а не как текст. Разберём их.

## Шаг 1: точки входа и логотип

Заголовок Game Boy начинается с адреса `0x0100`. По смещению `0x0104`–`0x0133` лежит **логотип Nintendo** — 48 байт фиксированных данных. Они нужны, чтобы загрузчик проверил подлинность картриджа:

```
$ xxd -s 0x104 -l 48 game.gb
00000104: ce ed 66 66 cc 0d 00 0b 03 73 00 83 00 0c 00 0d  .ff.....s.......
00000114: 00 08 11 1f 88 89 00 0e dc cc 6e e6 dd dd d9 99  ...........n....
00000124: bb bb 67 63 6e 0e ec cc dd dc 99 9f bb b9 33 3e  ..gcn.........3>
```

Если логотип повреждён, реальный Game Boy не запустит картридж, а вот эмулятор — обычно да.

## Шаг 2: поля заголовка

После логотипа идут поля, описывающие картридж. Ключевые:

| Смещение | Поле | Смысл |
|---|---|---|
| 0x0134–0x0143 | Title | Название игры (ASCII) |
| 0x0147 | Cartridge type | Тип маппера (MBC) |
| 0x0148 | ROM size | Сколько банков по 16 КБ |
| 0x0149 | RAM size | Размер внешней RAM |
| 0x014D | Header checksum | Контрольная сумма заголовка |
| 0x014E–0x014F | Global checksum | Сумма всего ROM |

```
$ xxd -s 0x134 -l 16 game.gb
00000134: 46 4c 41 47 00 00 00 00 00 00 00 00 00 00 00 00  FLAG............
```

Название — `FLAG`. Уже интересно.

## Шаг 3: контрольные суммы

Загрузчик проверяет `header checksum` по алгоритму:

```
x = 0
for i in 0x134..0x14C: x = x - byte[i] - 1
checksum = x & 0xFF
```

Если после патча его не пересчитать, часть эмуляторов откажется запускать ROM. Поэтому при правке заголовка контрольную сумму обновляют.

## Шаг 4: мапперы (MBC)

Банк — это блок памяти. У Game Boy адресное пространство картриджа — 32 КБ, а ROM может быть больше, поэтому его делят на банки и переключают «маппером» (Memory Bank Controller): MBC1, MBC2, MBC3, MBC5. Тип записан в `0x0147`. Для чтения флага маппер обычно не нужен — данные лежат в первом банке.

## Шаг 5: ищем флаг

Флаг — обычная строка, и `strings` часто находит её сразу:

```
$ strings -n 5 game.gb | grep nto
nto{g4m3b0y_r0m_h34d3r_p4tch}
```

Если строки нет, значит, флаг закодирован или собирается кодом. Тогда пригодится дизассемблер (`rgbds`/`wla-dx` для SM83) и эмулятор с отладчиком (`mgba`, `bgb`).

## Шаг 6: патчинг

Иногда игра прячет флаг за проверкой, которую нужно обойти. Например, есть условие «если счёт > 100 — показать флаг». Патчим сравнение:

```
$ xxd -s 0x200 -l 8 game.gb
00000200: fe 64 30 05 ...      ; cp 100 ; jr nc, skip
```

Заменяем операнд `0x64` (100) на `0x00`, чтобы условие срабатывало всегда, и пересчитываем контрольную сумму.

## Полный прогон

1. `file game.gb` и `xxd -l 0x150` — понять структуру.
2. Проверить логотип и поля заголовка (`strings`, `xxd -s`).
3. Найти флаг через `strings` или дизассемблер.
4. При необходимости пропатчить проверку и пересчитать checksum.
5. Запустить в `mgba` для проверки.

## Что мы теперь знаем

- Заголовок GB начинается с `0x0100`, логотип — на `0x0104`.
- Поля заголовка описывают тип, размер и маппер.
- Контрольную сумму нужно обновлять после патча.
- Флаг часто лежит строкой, которую находит `strings`.
- Патчинг кода игры — обычная задача ROM-хакинга.

## Разбор: зачем логотип и как его проверяют

Логотип Nintendo — не просто картинка. Загрузчик сравнивает 48 байт в ROM с эталоном, зашитым в самом устройстве. Если хоть один байт отличается, реальный Game Boy показывает пустой экран и не передаёт управление в ROM. Эмуляторы обычно эту проверку пропускают, поэтому в CTF повреждённый логотип встречается как «игра запускается в mgba, но не на железе». Для решения задачи это важно: не трать время на восстановление логотипа, если флаг всё равно лежит в данных.

## Полный разбор полей заголовка

Пройдёмся по всем полям, которые стоит проверять при разборе:

- `0x0100–0x0103` — инструкция перехода к коду инициализации (обычно `nop; jp`).
- `0x0104–0x0133` — логотип Nintendo (48 байт).
- `0x0134–0x0143` — название игры, 16 байт ASCII, дополненное нулями.
- `0x0143` — флаг CGB (поддержка Game Boy Color).
- `0x0144–0x0145` — ASCII-код издателя (новый формат).
- `0x0146` — версия ROM.
- `0x0147` — тип картриджа (маппер).
- `0x0148` — размер ROM в банках по 16 КБ.
- `0x0149` — размер внешней RAM.
- `0x014A` — код региона.
- `0x014B` — код лицензии.
- `0x014C` — версия маски ROM.
- `0x014D` — контрольная сумма заголовка.
- `0x014E–0x014F` — глобальная контрольная сумма.

Если название выглядит осмысленно (например, `FLAG`), это подсказка: автор задачи специально положил данные в заголовок.

## Как устроен процессор SM83

Game Boy использует 8-битный процессор SM83 (близкий к Z80, но не он). Программы для него ассемблируются инструментами `rgbds` (`rgbasm`, `rgblink`, `rgbfix`). `rgbfix` умеет пересчитывать контрольные суммы после патча:

```
$ rgbfix -v -p 0xFF game.gb
```

Флаг `-v` исправляет заголовок, `-p` задаёт padding. Это избавляет от ручного пересчёта checksum.

## Работа с эмулятором

Для отладки используют эмуляторы с встроенным отладчиком: `mgba` (открытый), `bgb` (Windows), `SameBoy`. В `mgba` есть консоль с командами для дампа памяти, точек останова и пошагового исполнения. Если флаг собирается кодом, именно отладчик покажет, в какой момент он формируется в памяти.

## Типичные ошибки при патчинге

- Патчить, не сохранив копию оригинала: после нескольких правок непонятно, что сломалось.
- Забывать про checksum: часть эмуляторов отказывается стартовать.
- Менять длину строки названия: поле фиксированной длины, лишние байты затирают соседние.
- Искать флаг только через `strings`: если он собран из частей, строка не найдётся.
- Путать банк: при маппере данные могут быть не в первом банке.

## Сравнение с другими форматами картриджей

Понимая Game Boy, легко читать и другие форматы, потому что идея одна: заголовок плюс банки данных. Сравним:

| Платформа | Заголовок | Особенность |
|---|---|---|
| Game Boy | с 0x0100, логотип | контрольная сумма заголовка |
| Game Boy Color | тот же | флаг CGB в 0x0143 |
| NES (iNES) | 16 байт с 0 | сигнатура NES\x1a |
| SNES | внутренний заголовок | зависит от маппера HiROM/LoROM |
| GBA | с 0x04, фиксированный | логотип и контрольная сумма |

Общий приём: найти сигнатуру или логотип, от него отсчитать поля, затем искать строки в банках. Если сигнатуры нет, `binwalk` покажет вложенные структуры.

## Как оформлять решение ROM-задачи

Хороший разбор состоит из трёх частей: (1) определение формата — `file`, `xxd -l`, поиск сигнатуры; (2) карта данных — где заголовок, где банки, где смещения; (3) извлечение — `strings`, декодирование или патч. Такой порядок не даёт утонуть в байтах и объясняет каждое действие, что важно и для writeup, и для отчёта. Если флаг найден патчем, обязательно приложи diff байтов: `xxd` до и после.

## Итоговый разбор по шагам

Соберём всё вместе. Первым делом определяем формат: `file game.gb` и `xxd -l 0x150` показывают образ Game Boy и его заголовок. Проверяем логотип и читаем название по смещению 0x0134 — если оно осмысленно, данные рядом. Затем вычисляем контрольную сумму и, если планируем патч, запоминаем её алгоритм. Ищем флаг: сначала `strings`, при неудаче — дизассемблируем код и ищем, где он собирается в память. Патчим проверки, меняя только операнды, и пересчитываем checksum инструментом `rgbfix`. Проверяем результат в `mgba` с отладчиком.

Запомни главное правило ROM-разбора: сначала формат, потом карта данных, и только затем поиск. Такой порядок экономит время и делает решение воспроизводимым: любой сможет повторить твои шаги, потому что каждый из них объяснён и проверяем.
