## Что такое полиглот

Файл-полиглот — это файл, который **одновременно является валидным в нескольких форматах**. Один и тот же поток байт интерпретируется и как JPEG, и как ZIP, и как скрипт — потому что парсеры разных форматов смотрят на разные участки и разную структуру. В CTF полиглот — типичный сюжет: «файл открывается как картинка, но внутри архив», или «это валидный документ и валидный скрипт одновременно».

## Зачем нужны полиглоты

- **Обход проверок формата.** Валидатор видит картинку (по магическим байтам), а исполнитель — скрипт.
- **Контрабанда данных.** Секрет спрятан в части, которую «основной» парсер игнорирует.
- **Задачи на внимательность.** Нужно распознать, что формат не один, и извлечь вторую интерпретацию.

## Полиглоты изображений и архивов

Многие форматы «терпимы» к мусору в начале или конце файла:

- **JPEG/PNG/GIF** читаются от сигнатуры; данные до/после них часто игнорируются.
- **ZIP** читается от **конца** (End of Central Directory), поэтому ZIP можно приклеить к картинке в конец.
- **PDF** также ищется с конца (`%%EOF`), а мусор в начале допустим.

Отсюда классика: **изображение + ZIP** — картинка валидна, и `unzip` тоже сработает.

## ZIP + JPEG/PNG/GIF (GIFAR)

GIFAR — исторический пример: GIF-файл, который одновременно является валидным JAR-архивом (ZIP). Браузер (по MIME из HTML) видел картинку, а Java-плагин — апплет. Принцип переносится на любую пару «формат, читаемый с начала» + «формат, читаемый с конца».

Проверить двойственность:

```bash
file polyglot.gif        # GIF image data...
unzip -l polyglot.gif    # Archive: ... (если внутри ZIP)
```

## PDF + ZIP и PDF + JS

PDF поддерживает встраивание файлов (`/EmbeddedFile`) и JavaScript (`/JS`). Часто встречается PDF, внутри которого:

- лежит ZIP с флагом (извлекается через `binwalk -e` или вручную по смещению),
- спрятан JS, исполняемый при открытии.

```bash
binwalk polyglot.pdf
# 0       PDF document
# 12345   Zip archive data, ...
dd if=polyglot.pdf bs=1 skip=12345 of=out.zip
unzip -o out.zip
```

## Полиглоты скриптов

Один файл может быть валидным и для `sh`, и для Python/Perl/JS, если использовать комментарии, которые «съедаются» в одном языке и активны в другом. Простейший приём — «shebang + строковый литерал»:

```python
#!/bin/sh
""":" 
echo "я запустился как shell"
exit 0
" """
print("я запустился как python")
```

Как `sh`, первая строка — shebang, затем `"""` открывает строку, а `" """` её закрывает; как Python — модульная строка в `"""..."""` игнорируется, и выполняется `print`.

## Обнаружение и извлечение

Порядок действий для подозрительного файла:

1. `file` — что видит система.
2. `binwalk -e` — поиск вложенных сигнатур и автоизвлечение.
3. `foremost`/`scalpel` — карвинг по сигнатурам.
4. `strings` — текстовые артефакты (скрипты, пути, флаги).
5. Проверка конца файла: `xxd file | tail` — нет ли там ZIP/PDF.

```bash
file suspect.png
binwalk suspect.png
strings -n 6 suspect.png | head
xxd suspect.png | tail -5
```

## Инструменты

- **binwalk** — поиск и извлечение вложенных форматов.
- **foremost / scalpel** — карвинг файлов по сигнатурам.
- **xxd / hexdump** — ручной осмотр.
- **unzip / 7z / tar** — проверка архивной интерпретации.
- **python / perl / node** — проверка скриптовой интерпретации.

## Разобранный пример: изображение + ZIP

Соберём полиглот вручную:

```bash
zip secret.zip flag.txt
cat cover.png secret.zip > polyglot.png
file polyglot.png          # PNG image data
unzip -o polyglot.png      # извлекает flag.txt
```

Такой файл откроется как картинка, но останется валидным архивом — потому что ZIP читается с конца.

## Частые ошибки и подводные камни

- **Вера только одному `file`.** Он показывает первый распознанный формат, а полиглот их несколько.
- **Забыть про конец файла.** ZIP и PDF читаются с конца — смотрите `tail`, а не только начало.
- **Потеря байтов при извлечении.** Копируйте бинарно (`dd`, `cat`), не через текстовый редактор.
- **Неверное смещение.** Начало вложенного архива берите из `binwalk`, а не «на глаз».
- **Ломание при «нормализации».** Сервисы, пережимающие картинки, уничтожают полиглот.

## Справочная таблица

| Комбинация | Как читается | Инструмент |
|------------|--------------|------------|
| PNG + ZIP | картинка с начала, архив с конца | `unzip` |
| GIF + JAR | GIF / Java-архив | `unzip -l` |
| PDF + ZIP | PDF / архив | `binwalk -e` |
| PDF + JS | документ + скрипт | `strings`, анализ `/JS` |
| shell + python | два интерпретатора | `sh`, `python` |

## Что дальше / решение

1. Прогоните `file`, `binwalk`, `strings`, `xxd tail`.
2. Проверьте обе интерпретации: архивную (`unzip -l`) и скриптовую (`sh`/`python`).
3. Извлеките вложенный файл по смещению из `binwalk` через `dd`.
4. Если это обход загрузки — подумайте, какой валидатор видит первую сигнатуру, а какой исполнитель — вторую.

## Полиглоты в реальных атаках (загрузка файлов)

Полиглоты — не только CTF-игрушка. При загрузке файлов сервис часто проверяет **одно** свойство: расширение, `Content-Type` или магические байты. Если проверка видит картинку, а исполнитель — скрипт, получается обход. Классический сценарий:

1. Валидатор читает первые байты и видит `GIF89a` — «это картинка, пропускаем».
2. Сервер сохраняет файл как `.gif`, но раздаёт его с исполнением (старый PHP `AddHandler`).
3. Внутри — валидный PHP-код, который исполняется.

Поэтому в тестировании загрузки всегда проверяют, **какой именно** контроль стоит: по имени, по MIME, по сигнатуре, по содержимому. Полиглот обходит контроли, которые смотрят только «начало» или только «расширение».

## Полиглоты офисных документов

DOCX, XLSX, PPTX и многие современные форматы — это **ZIP-архивы** с XML внутри. Отсюда два следствия:

- их можно «склеить» с другим ZIP-содержимым, и оба распакуются;
- если сервис распаковывает документ, внутри можно спрятать произвольные файлы (вплоть до path traversal через имена записей — см. zip-slip).

```bash
unzip -l document.docx | head      # видим структуру ZIP
binwalk document.docx              # при желании ищем вложенное
```

## Как строить полиглот программно

Простейший конструктор «картинка + архив» на Python:

```python
png = open("cover.png", "rb").read()
import zipfile, io
buf = io.BytesIO()
with zipfile.ZipFile(buf, "w") as z:
    z.writestr("flag.txt", "FLAG{polyglot}")
open("polyglot.png", "wb").write(png + buf.getvalue())
```

Порядок важен: ZIP дописывается в конец, потому что парсер архива ищет структуру с конца файла. Для «скрипт + изображение» используют комментарии формата (например, JPEG-комментарий `FFFE`), внутри которого лежит валидный текст скрипта.

## Обнаружение скрытой интерпретации

Полезные команды, когда файл «ведёт себя странно»:

```bash
# все распознанные форматы
binwalk suspect.bin
# что видит система
file suspect.bin
# нет ли второй сигнатуры внутри
grep -abo $'PK\x03\x04' suspect.bin
# извлечь всё, что найдётся
binwalk -e --run-as=root suspect.bin
```

Если `grep -abo 'PK'` находит смещение ZIP внутри картинки — перед вами почти наверняка полиглот.

## Частые вопросы по полиготам

- **Всегда ли это безопасно?** Нет: полиглот может эксплуатировать парсеры (не только «нести» данные).
- **Как узнать число интерпретаций?** Последовательно пробуйте все известные форматы и смотрите, какие валидны.
- **Что делать при обрезке?** Некоторые сервисы пережимают файлы и убивают вторую интерпретацию — тогда полиглот не сработает.
- **Где искать флаг?** В «второй» интерпретации: в архиве, в комментарии, в конце файла.

## Полиглоты и WAF/антивирусы

Полиглоты применяют для обхода сигнатурных детекторов. Антивирус может распознать файл как изображение и не проверять содержимое как исполняемое; WAF — увидеть «картинку» в multipart-загрузке и пропустить. Тот же принцип: **разные парсеры смотрят на разные части файла**. Поэтому в защите важна проверка содержимого целиком, а не только по сигнатуре или расширению.

## Проверка гипотезы о полиглоте

Если файл подозрителен, действуйте методично: определите все форматы, которые он может представлять, и для каждого проверьте валидность независимым инструментом. Ведите список: `file`, `binwalk`, `unzip -l`, `pdfinfo`, `identify`, `python -c` для скриптовой интерпретации. Как только какая-то проверка «оживает» — вы нашли вторую интерпретацию и, скорее всего, путь к флагу.
