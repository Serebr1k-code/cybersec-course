## Что такое INTERCAL

INTERCAL — «Compiler Language With No Pronounceable Acronym» — язык, созданный Доном Вудсом (Don Woods) и Джеймсом Лайоном (James Lyon) в 1972 году как пародия на существующие языки. Название принципиально непроизносимо, а синтаксис сознательно неудобен. При этом INTERCAL формально полон по Тьюрингу и на нём действительно можно писать программы — именно поэтому он и попал в CTF.

Три вещи, по которым INTERCAL узнаётся мгновенно:

- почти каждая строка начинается с `DO` или `PLEASE DO`;
- встречается оператор `COMEFROM` — обратный аналог `GOTO`;
- в коде много символов `<-`, `~`, `&`, `,1`, `:1` и конструкций вида `,1 SUB #1 <- #238`.

## Алфавит и философия: PLEASE, DO, COMEFROM

Компилятор INTERCAL следит за **вежливостью**: доля строк с `PLEASE` должна оставаться в определённых границах (примерно от 1/5 до 1/3 от остальных операторов). Если вы слишком редко говорите `PLEASE`, компилятор ругается, что программа недостаточно вежлива; если слишком часто — что слишком уж вежлива. Это не шутка ради шутки: правило встроено в лексический анализ.

`COMEFROM` (в C-INTERCAL пишется `COME FROM`) — оператор, который «притягивает» управление: он объявляет точку, куда будет приходить управление из указанного места. Логически это `GOTO` наоборот, и читать такой код нужно «снизу вверх» по потоку управления.

## Типы данных: spark, twos, tail

INTERCAL оперирует не байтами, а **битовыми» типами:

| Тип | Синтаксис | Размер | Смысл |
|-----|-----------|--------|-------|
| spark | `.` | 1 бит | одиночный бит |
| twos | `:` | 2 бита | пара бит |
| tail | `,` | массив | группа битов («хвост») |
| 16-битное | `.1` | 16 бит | целое 0..65535 |
| 32-битное | `:1` | 32 бита | целое |
| массив | `,1` | массив | вектор значений |

Числа записываются с префиксом `#` (например, `#238`) — это «мес. значение», фактически константа. Переменные нумеруются (`:1`, `:2`, `,1`), а не именуются.

## Операторы: interleave, select, mingle

Побитовые операторы INTERCAL необычны и работают «наизнанку»:

- **interleave** (`~`) — вставляет биты одного значения между битами другого;
- **select** (`&`) — выбирает биты, определяемые маской;
- **mingle** (`%`) — «перемешивает» (оператор может быть унарным);
- **unary `&`** и **binary `~`** дают неожиданные результаты, потому что операнды обрабатываются бит за битом в специфичном порядке.

Именно из-за этих операторов значения в «Hello World» выглядят случайными: байты на выходе оказываются **побитово перевёрнутыми**, поэтому в коде стоят числа вроде `#238`, `#108`, `#194`.

## Компилятор ick и инструменты

Основной инструмент — компилятор `ick` из пакета C-INTERCAL.

```bash
# Debian/Ubuntu
sudo apt install intercal
# проверка
ick --version
```

Компиляция и запуск:

```bash
ick hello.i -o hello
./hello
```

Полезные флаги:

- `ick -c` — только компилировать в C (без сборки);
- `ick -m` — включить дополнительные проверки;
- `ick -O` — оптимизация;
- `ick -f` — «понятные» сообщения об ошибках.

Существуют также онлайн-интерпретаторы и транспайлеры INTERCAL→C, но классический путь — `ick`.

## Разобранный пример: Hello World

Классический C-INTERCAL «Hello, world!» (13 символов — по числу элементов массива):

```
DO ,1 <- #13
PLEASE DO ,1 SUB #1 <- #238
DO ,1 SUB #2 <- #108
DO ,1 SUB #3 <- #112
DO ,1 SUB #4 <- #0
DO ,1 SUB #5 <- #64
DO ,1 SUB #6 <- #194
DO ,1 SUB #7 <- #48
PLEASE DO ,1 SUB #8 <- #22
DO ,1 SUB #9 <- #248
DO ,1 SUB #10 <- #168
DO ,1 SUB #11 <- #24
DO ,1 SUB #12 <- #16
DO ,1 SUB #13 <- #162
PLEASE READ OUT ,1
PLEASE GIVE UP
```

Разбор по частям:

1. `DO ,1 <- #13` — создать массив `,1` из 13 элементов.
2. `DO ,1 SUB #n <- #v` — записать в n-й элемент значение `v` (значения перевёрнуты побитово).
3. `PLEASE READ OUT ,1` — вывести массив как поток символов.
4. `PLEASE GIVE UP` — завершить программу.

Запуск:

```bash
ick hello.i -o hello && ./hello
```

```
Hello, world!
```

Если значений `PLEASE` слишком мало, компилятор откажется собирать программу:

```
ICL129I PROGRAM HAS TOO FEW PLEASE ... 
```

## Частые ошибки и подводные камни

- **Неправильная доля `PLEASE`.** Слишком мало или слишком много вежливых строк — ошибка компиляции.
- **Забыт `PLEASE GIVE UP`.** Программа завершится аварийно.
- **Путаница с обратным порядком бит.** Значения в массиве почти всегда перевёрнуты — не пытайтесь вписать ASCII-код напрямую.
- **`COMEFROM` читается наоборот.** Поток управления идёт не сверху вниз; ищите, откуда «приходит» управление.
- **Индексация с 1.** `,1 SUB #1` — это первый элемент, а не нулевой.

## Что дальше / решение

1. Распознать INTERCAL: строки с `DO`/`PLEASE`, `COME FROM`, `,1 SUB #n <- #v`.
2. Поставить `intercal` (`apt install intercal`) или найти онлайн-компилятор.
3. Скомпилировать `ick prog.i -o prog` и запустить — обычно это сразу даёт флаг.
4. Если компиляция ругается на вежливость — добавьте или уберите `PLEASE` так, чтобы доля была в норме.
5. Если нужен разбор значений — помните про побитовую перевёрнутость чисел.

## Расширенный пример: чтение и вывод

Более содержательная программа читает символ и выводит его же, используя массив из одного элемента:

```
DO ,1 <- #1
PLEASE DO ,1 SUB #1 <- #0
DO READ OUT ,1
PLEASE GIVE UP
```

Разбор:

1. `DO ,1 <- #1` — создать массив `,1` длины 1.
2. `DO ,1 SUB #1 <- #0` — обнулить первый элемент (подготовка буфера).
3. `READ OUT ,1` — вывести содержимое массива.
4. `GIVE UP` — завершить.

При компиляции `ick` проверяет долю `PLEASE`. Если её слишком мало, вы получите сообщение о недостаточной вежливости; если слишком много — о чрезмерной. Правило простое: держите примерно одну вежливую строку на 3–5 невежливых.

## INTERCAL в CTF: типовые приёмы

- **Распознавание.** Код на INTERCAL узнаётся по словам `DO`, `PLEASE`, `COME FROM`, `READ OUT`, `GIVE UP` и массивам вида `,1 SUB #n <- #v`.
- **Быстрый запуск.** Если есть сеть — онлайн-компилятор; если нет — `apt install intercal` и `ick`.
- **Побитовая перевёрнутость.** Значения в массивах перевёрнуты; не пытайтесь вписать ASCII напрямую — используйте компилятор, а не ручной перевод.
- **Вежливость.** При ошибке компиляции о `PLEASE` — добавьте/уберите одну вежливую строку, а не переписывайте программу.
- **`COME FROM`.** Если поток управления непонятен, ищите `COME FROM` — он «притягивает» управление из указанной точки, и читать программу надо не сверху вниз.

## Сравнение с другими esolang

| Свойство | INTERCAL | Brainfuck | Whitespace |
|----------|----------|-----------|------------|
| Год | 1972 | 1993 | 2003 |
| Алфавит | слова | 8 символов | 3 символа |
| Уникальность | `COMEFROM`, `PLEASE` | минимализм | невидимость |
| Запуск | `ick` | bf-интерпретатор | `wspace` |
| Типовая задача | пародия | «исполни код» | «пустой файл» |

INTERCAL — самый «человекочитаемый» из трёх: в нём есть слова. Парадокс в том, что именно слова и делают его неудобным: `PLEASE` контролируется компилятором, а `COMEFROM` ломает привычное направление чтения кода.

## Частые вопросы по INTERCAL

- **Почему программа не компилируется из-за вежливости?** Компилятор требует, чтобы доля строк с `PLEASE` лежала в узком диапазоне. Добавьте или уберите одну вежливую строку.
- **Зачем перевёрнутые значения?** INTERCAL выводит биты в нестандартном порядке, поэтому константы в массиве заранее перевёрнуты. Не вписывайте ASCII напрямую.
- **Как отлаживать?** Скомпилируйте в C (`ick -c`), затем соберите `gcc` — так проще увидеть, что генерирует компилятор.
- **Что читать дальше?** Официальное руководство C-INTERCAL и примеры из репозитория `esoteric-programming`.
