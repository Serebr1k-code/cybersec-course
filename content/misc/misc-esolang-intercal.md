## Вопрос, с которого всё начинается

После Whitespace, где кода вообще не видно, приятно получить файл с настоящими словами. Но и он ставит в тупик: почти каждая строка начинается с `DO` или `PLEASE DO`, компилятор отказывается собирать программу со словами «слишком мало вежливых строк», а числа в массиве выглядят случайными. Это **INTERCAL** — язык-пародия, и он тоже попадает в CTF.

## Наш пример: hello.i

Смотрим файл:

```
$ head -8 hello.i
DO ,1 <- #13
PLEASE DO ,1 SUB #1 <- #238
DO ,1 SUB #2 <- #108
DO ,1 SUB #3 <- #112
DO ,1 SUB #4 <- #0
DO ,1 SUB #5 <- #64
DO ,1 SUB #6 <- #194
DO ,1 SUB #7 <- #48
```

Три вещи выдают INTERCAL мгновенно: строки с `DO`/`PLEASE DO`, конструкция `,1 SUB #n <- #v` и константы вида `#238` — явно не ASCII (буква `H` — это 72, а тут 238). Разберёмся, почему так.

INTERCAL — «Compiler Language With No Pronounceable Acronym» — создан Доном Вудсом и Джеймсом Лайоном в 1972 году как пародия. Но он формально полон по Тьюрингу, поэтому на нём реально пишут программы.

## Шаг 1: правило вежливости

Первое, что бросается в глаза — `PLEASE`. Это не декорация. Компилятор следит за **долей вежливых строк**: она должна оставаться примерно в диапазоне от 1/5 до 1/3 от остальных операторов.

- Слишком редко говорите `PLEASE` — компилятор отвечает, что программа недостаточно вежлива.
- Слишком часто — что уж слишком вежлива.

Правило встроено в лексический анализ, и с ним придётся считаться.

## Шаг 2: типы данных и биты

INTERCAL оперирует не байтами, а битовыми типами:

| Тип | Синтаксис | Размер | Смысл |
|-----|-----------|--------|-------|
| spark | `.` | 1 бит | одиночный бит |
| twos | `:` | 2 бита | пара бит |
| tail | `,` | массив | группа битов |
| 16-битное | `.1` | 16 бит | целое 0..65535 |
| 32-битное | `:1` | 32 бита | целое |
| массив | `,1` | массив | вектор значений |

Числа пишутся с префиксом `#` (например, `#238`) — это константа. Переменные **нумеруются** (`,1`, `:1`), а не именуются.

## Шаг 3: почему числа перевёрнуты

Ключ к «случайным» константам — побитовые операторы INTERCAL, которые работают нестандартно:

- **interleave** (`~`) — вставляет биты одного значения между битами другого;
- **select** (`&`) — выбирает биты по маске;
- **mingle** (`%`) — перемешивает биты.

При выводе байты оказываются **побитово перевёрнутыми**. Поэтому букве `H` (72) в массиве соответствует `#238`, а не 72. Практический вывод: не пытайтесь вписывать ASCII-коды напрямую — пусть этим занимается компилятор.

## Шаг 4: компилируем и запускаем

Основной инструмент — компилятор `ick` из пакета C-INTERCAL:

```
$ sudo apt install intercal
$ ick --version
C-INTERCAL 0.30
```

Собираем и запускаем:

```
$ ick hello.i -o hello
$ ./hello
Hello, world!
```

Получили классический вывод. В CTF на этом месте будет флаг — интерпретатор сам разворачивает все побитовые фокусы.

Полезные флаги: `ick -c` компилирует только в C (удобно посмотреть, во что превращается программа), `ick -m` включает дополнительные проверки, `ick -f` даёт понятные сообщения об ошибках.

## Шаг 5: если компилятор ругается

Самая частая ошибка — вежливость. Если `PLEASE` слишком мало, `ick` откажется собирать:

```
$ ick rude.i -o rude
ICL129I PROGRAM HAS TOO FEW PLEASE ...
```

Лечится добавлением одной вежливой строки (или убиранием лишней, если ругается на «слишком вежливо»). Держите примерно одну строку с `PLEASE` на 3–5 без него — и компиляция проходит.

Второй подводный камень — `COMEFROM` (в C-INTERCAL `COME FROM`). Это оператор, который **притягивает** управление: он объявляет точку, куда придёт поток из указанного места. Логически это `GOTO` наоборот, и такой код читается не сверху вниз — ищите, откуда «приходит» управление.

И третье: индексация с 1. `,1 SUB #1` — это **первый** элемент, а не нулевой.

## Расширенный пример: чтение и вывод

Второй файл — `echo.i` — читает символ и печатает его же:

```
DO ,1 <- #1
PLEASE DO ,1 SUB #1 <- #0
DO READ OUT ,1
PLEASE GIVE UP
```

1. `DO ,1 <- #1` — создать массив `,1` длины 1.
2. `DO ,1 SUB #1 <- #0` — обнулить первый элемент (буфер).
3. `READ OUT ,1` — вывести содержимое массива как поток символов.
4. `GIVE UP` — завершить.

```
$ ick echo.i -o echo && ./echo
```

Та же проверка вежливости: одна строка с `PLEASE` на несколько без него — норма. Если программа читает из стандартного ввода, данные можно подать через pipe, как в Whitespace.

## INTERCAL в CTF: типовые приёмы

- **Распознавание.** Код узнаётся по словам `DO`, `PLEASE`, `COME FROM`, `READ OUT`, `GIVE UP` и массивам `,1 SUB #n <- #v`.
- **Быстрый запуск.** Онлайн-компилятор, если есть сеть; иначе `apt install intercal` и `ick`.
- **Не переводите биты руками.** Значения перевёрнуты — пусть компилятор делает свою работу.
- **Вежливость.** При ошибке о `PLEASE` добавьте или уберите одну строку, не переписывайте программу.
- **`COME FROM`.** Если поток непонятен, ищите этот оператор: он меняет направление чтения кода.

## Что мы теперь знаем

По-простому:

1. INTERCAL узнаётся по строкам с `DO`/`PLEASE DO` и массивам `,1 SUB #n <- #v`.
2. Компилятор `ick` следит за долей `PLEASE` — за «невежливость» он отказывается собирать.
3. Данные — битовые типы (`spark`, `twos`, `tail`), а не байты.
4. Константы выглядят случайными, потому что байты при выводе побитово перевёрнуты.
5. `COMEFROM` меняет направление чтения кода; индексация массивов — с единицы.

## На что смотреть дальше

- **Доля `PLEASE`.** Ошибка компиляции чаще всего именно про вежливость — правьте одну строку, не переписывайте всё.
- **`PLEASE GIVE UP`.** Забытый оператор завершения — программа падает аварийно.
- **Перевёрнутые биты.** Значения в массивах перевёрнуты; доверьте преобразование `ick`, а не ручному переводу.
- **`COME FROM`.** Если поток управления непонятен — ищите этот оператор и читайте программу «снизу вверх».
- **Разбор через C.** `ick -c prog.i` сгенерирует C-код — его проще изучать, чем исходник.

## Куда дальше

Мы разобрали язык с вежливым синтаксисом и обратным `GOTO`. Дальше — ещё один «литературный» esolang: **Shakespeare**, где программа выглядит как пьеса с персонажами и репликами, а числа хранятся в «настроениях» героев. А пока главное запомни: INTERCAL — это слова, но правила у них нечеловеческие, и компилятор `ick` снимает большую часть боли.

## Где пригодится

- **CTF misc:** задачи-пародии на компиляторы и необычный синтаксис.
- **Понимание управления потоком:** `COMEFROM` тренирует чтение нестандартного control flow.
- **Работа со спецификацией:** компилятор со встроенными «шутками» заставляет читать правила буквально.
- **Общая эрудиция:** язык, ставший классикой жанра esolang.
