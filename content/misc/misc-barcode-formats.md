## Вопрос, с которого всё начинается

В задаче дана картинка с полосатым кодом — не QR, а **линейный штрихкод**. Сканера под рукой нет, но нужно понять, что в нём закодировано. Линейные коды устроены проще QR: это последовательность полос разной ширины, и их можно разобрать по структуре. Как?

## Наш пример: разбор линейного кода

```
$ cat barcode.txt
symbology=code128
value=nto-lab-2026
checksum=92
widths=211232...
```

Здесь указан тип (`code128`), значение, контрольная сумма и ширины полос. Разберём, откуда это берётся.

## Шаг 1: линейные и двумерные коды

- **Линейные (1D)** — полосы разной ширины в одну строку: Code 128, EAN-13, UPC, Code 39. Кодируют небольшой объём (десятки символов).
- **Двумерные (2D)** — QR, DataMatrix, PDF417. Кодируют много данных и имеют коррекцию ошибок.

QR мы разбирали в `misc-qr-barcode-deep`; здесь — линейные.

## Шаг 2: Code 128

**Code 128** — плотный линейный код, поддерживающий все ASCII-символы. Он состоит из:

- **стартового символа** (выбирает набор A/B/C — какие символы доступны);
- **символов данных** (каждый — 11 модулей: 3 полосы и 3 пробела);
- **контрольного символа** (checksum);
- **стоп-символа**.

Набор C кодирует пары цифр эффективнее — отсюда его любовь к номерам.

## Шаг 3: EAN-13 и контрольная цифра

**EAN-13** — 13 цифр, используемые в торговле. Последняя цифра — **контрольная**: она вычисляется по первым двенадцати. Алгоритм: сложить цифры на нечётных позициях, прибавить утроенную сумму чётных, взять дополнение до десяти. Это позволяет обнаружить ошибку чтения — если сумма не сходится, код прочитан неверно.

## Шаг 4: как читают коды

Программно — библиотеками/утилитами: `zbarimg` для картинок, встроенные сканеры. Но полезно понимать структуру вручную: по ширине полос и пробелов восстанавливают последовательность символов, затем проверяют контрольную сумму. Если сумма не сходится — где-то потеряна полоса.

## Шаг 5: генерация

Коды генерируют теми же библиотеками (Python `python-barcode`, онлайн-генераторы). В CTF генерация нужна, чтобы создать код с нужным значением (например, подделать метку). Важно соблюсти ширины модулей и контрольную цифру, иначе сканер не прочитает.

## Шаг 6: практический порядок

1. Определить тип: 1D или 2D, по структуре.
2. Для 1D — понять символологию (Code 128, EAN и т. п.).
3. Прочитать значение (сканером или по структуре).
4. Проверить контрольную сумму.
5. Если нужно — сгенерировать свой код с тем же форматом.

## Что мы теперь знаем

- Линейные (1D) коды — полосы в строку; 2D (QR) — матрица.
- Code 128 кодирует ASCII, имеет старт, данные, checksum и стоп.
- EAN-13 заканчивается контрольной цифрой.
- Читают сканером (`zbarimg`) или по структуре полос.
- Генерация требует точных ширин и корректной контрольной суммы.
