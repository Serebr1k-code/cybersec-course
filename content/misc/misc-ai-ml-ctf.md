## Вопрос, с которого всё начинается

В задаче дан сервис: ты отправляешь картинку или строку, он возвращает «класс» (например, «спам/не спам»). Взламывать бинарник негде — надо **обмануть саму модель**. Как, не имея ни весов, ни градиентов, заставить классификатор уверенно ответить неверно? Это класс задач на машинное обучение (ML), и здесь два основных вектора: **извлечь** поведение модели по API и построить **adversarial-пример** — вход, почти неотличимый от обычного, но классифицируемый иначе.

## Наш пример: чёрный ящик-классификатор

Дано: линейный классификатор на 3 класса, спрятанный за API. Мы не видим его веса, но можем вызывать `api(x)` и получать ответ. Цель — либо восстановить модель, либо найти вход, который она уверенно отнесёт к нужному классу. Разберёмся, что именно отдаёт API, потому что от этого зависит вся стратегия.

## Извлечение модели (model extraction)

Идея: вызвать API на множестве входов, собрать пары «вход → выход» и обучить **суррогатную** модель, которая повторяет поведение чёрного ящика. Ключевой вопрос — что API возвращает:

- **hard labels** — только класс (`0/1/2`). Информации мало: нужно много запросов.
- **soft labels** — вероятности по классам. Гораздо эффективнее: одна точка несёт информацию обо всех классах.

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(0)
W_true = rng.normal(size=(2, 3))          # неизвестная линейная модель, 3 класса
def api(x):
    logits = W_true @ x
    e = np.exp(logits - logits.max())
    return e / e.sum()                    # soft labels

Xs = rng.normal(size=(4000, 2))
Ys = np.array([api(x).argmax() for x in Xs])   # hard labels с API
surrogate = LogisticRegression().fit(Xs, Ys)
print(surrogate.coef_.shape, surrogate.score(Xs, Ys))
```

Если API отдаёт вероятности, обучай суррогат прямо на них — сойдётся быстрее и точнее. Это по сути **дистилляция знаний**: ученик перенимает не только ответы учителя, но и его неуверенность.

## Adversarial-примеры: FGSM

Adversarial-пример — вход `x'`, визуально почти неотличимый от `x`, но классифицируемый иначе. Базовый метод — **FGSM** (Fast Gradient Sign Method): сдвигаем вход на `ε` в сторону роста функции потерь. Для линейной модели градиент — это просто вектор весов:

```python
import numpy as np
w = np.array([1.0, -2.0]); b = 0.5       # score = w·x + b
x = np.array([0.3, 0.4])
eps = 0.5
grad = w                                 # d(score)/dx = w для линейной модели
x_adv = x + eps * np.sign(grad)
print("orig", w @ x + b, "adv", w @ x_adv + b)
```

```
orig -0.3 adv 0.75
```

Один шаг перевернул знак оценки. Для нейросетей градиент по входу берут автодиффом (`loss.backward()` в PyTorch). **PGD** — итеративный вариант: несколько малых шагов с проекцией в `ε`-шар; он сильнее FGSM.

## Переносимость и атака чёрного ящика

Прямой градиент есть не всегда, но adversarial-примеры обладают **переносимостью** (transferability): пример, подобранный для одной модели, часто обманывает и другую, обученную на тех же данных. Это и позволяет атаковать чёрный ящик: обучаем суррогат, генерируем пример на нём — и подаём в цель.

```python
rng = np.random.default_rng(1)
X = rng.normal(size=(2000, 4))
y = (X @ np.array([1, -1, 0.5, 2]) > 0).astype(int)
victim = LogisticRegression().fit(X, y)
surrogate = LogisticRegression().fit(X, y)
x = X[0]
x_adv = x + 0.5 * np.sign(surrogate.coef_[0])
print("victim on x    :", victim.predict([x])[0])
print("victim on x_adv:", victim.predict([x_adv])[0])
```

Если предсказание жертвы на `x_adv` меняется — переносимость сработала.

## Бэкдоры и отравление данных

- **Data poisoning** — атакующий подмешивает в обучающую выборку «плохие» примеры, чтобы сдвинуть решение модели в целом (например, чтобы спам классифицировался как не-спам).
- **Backdoor** — в данные добавляют **триггер** (небольшой паттерн). Модель ведёт себя нормально на чистых входах, но на входе с триггером всегда выдаёт заданный класс.

Типовой признак бэкдора: модель идеально работает на валидации, но реагирует на странный паттерн (пиксель в углу, редкое слово) непропорционально. В CTF это выглядит как «найди триггер, который заставит модель выдать флаг».

## Инференс членства

Атака **membership inference** отвечает на вопрос «был ли конкретный объект в обучающей выборке». Модели часто **переобучены** и дают на обучающих примерах более высокую уверенность, чем на новых. Значит, по уверенности можно судить о членстве: либо порогом по вероятности, либо обучением отдельного атакующего классификатора на выходах модели. Это задача про утечку приватности данных.

## Инструменты

- **numpy / scikit-learn** — база для линейных моделей и суррогатов.
- **PyTorch** — автодифф для градиентных атак.
- **ART (Adversarial Robustness Toolbox)** — готовые FGSM/PGD/DeepFool (`pip install adversarial-robustness-toolbox`).
- **foolbox** — библиотека adversarial-атак (`pip install foolbox`).
- **transformers** — для задач на LLM.
- **onnx / onnxruntime** — когда модель отдана в ONNX.

## Если не сработало

ML-задачи в CTF редко поддаются «в лоб». Разберём частые тупики.

**Извлечение модели упирается в лимит запросов.** Используй активное обучение: выбирай для запроса точки у границы решения, где модель наименее уверена, — они дают больше информации. Распределяй запросы по сессиям и прокси. Иногда достаточно восстановить не всю модель, а решение по одному классу.

**FGSM на чёрном ящике невозможен — градиента нет.** Обучи суррогат на перехваченных парах и перенеси возмущение (transfer attack). Либо используй query-based метод: Boundary attack двигает вход к границе решения, не требуя градиента.

**Возмущение не проходит препроцессинг.** Цель может масштабировать или сжимать вход (JPEG). Тогда оптимизируй возмущение *через* тот же препроцессинг (EOT — Expectation Over Transformation), чтобы оно выживало после преобразований.

**Бэкдор-триггер не находится.** Триггер может быть малозаметным паттерном (пиксель, шум) или текстовой фразой. Перебирай гипотезы: изменение одного пикселя, определённый цвет, редкое слово. Анализируй градиенты — нейроны, активирующиеся на триггере, выделяются.

**Membership inference даёт шум.** Ищи переобучение: сравнивай не отдельные примеры, а распределения уверенности. Иногда сигнал даёт не уверенность, а её *стабильность* под малым возмущением — на «членах» она выше.

## Частые вопросы

**Почему модель вообще извлекается?** API отдаёт ответы на запросы. По этим парам обучают суррогат, который ведёт себя как цель. Точность копии растёт с числом запросов.

**Adversarial-атака — это взлом модели?** Это обман классификатора. Модель не «ломается» внутри — её заставляют ошибиться на конкретном входе.

**Что такое FGSM?** Fast Gradient Sign Method: сдвиг входа на маленький шаг в направлении градиента функции потерь. Простейший способ построить adversarial-пример, когда есть доступ к градиентам.

**Отравление данных применимо в CTF?** Да, если задача позволяет влиять на обучающие данные. Тогда внедряют примеры с триггером и получают модель, ошибающуюся по команде.

## Мини-практика: атака на классификатор

Представь API: `POST /predict` с изображением, возвращает метку. Цель — заставить его выдать неверный класс. Первый шаг — собрать пары вход-выход (несколько тысяч запросов). Второй — обучить на них суррогатную модель. Третий — построить adversarial-пример на суррогате (FGSM или PGD) и перенести его на цель. Если переносимость низкая — используй query-based Boundary attack.

Проверяй бюджет: ограничение на число запросов делает активное обучение выгоднее пассивного. Учитывай препроцессинг (ресайз, нормализация) — возмущение должно его переживать. И измеряй успех честно: доля успешных обходов на *новых* входах, а не на тех, по которым обучался суррогат.

## Что мы теперь знаем

- ML-задачу решают, определив **интерфейс**: класс или вероятности, лимит запросов.
- Извлечение модели: суррогат по запросам; **soft labels** эффективнее hard.
- FGSM — один градиентный шаг по входу; PGD — итеративный, сильнее.
- **Переносимость** позволяет атаковать чёрный ящик без градиента.
- Бэкдор срабатывает на **триггере**, отравление смещает модель в целом.
- Adversarial-вход обязан быть **допустимым** (диапазоны, формат, нормализация).

## На что смотреть дальше

- **Сначала определи интерфейс.** Класс или вероятности? Есть ли лимит запросов? От этого зависит стратегия.
- **Экономь запросы.** Soft labels и активное обучение (выбор информативных точек) дают суррогат за меньше вызовов.
- **Держи вход допустимым.** Adversarial-пример должен проходить нормализацию и формат, иначе его отбросят до модели.
- **Ищи триггер, если поведение странное.** Идеальная валидация + реакция на редкий паттерн = бэкдор.
- **Не верь одной атаке.** FGSM слабее PGD; проверяй пример на нескольких запросах (модель может быть недетерминированной).
