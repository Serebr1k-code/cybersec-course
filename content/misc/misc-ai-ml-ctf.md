## Что такое AI/ML в CTF

Задачи на машинное обучение — относительно новый класс в CTF. Вместо того чтобы взламывать бинарник, вы атакуете **модель**: извлекаете её поведение через API, подбираете вход, который классификатор уверенно относит к неверному классу, или находите спрятанный бэкдор. Отдельная ветка — задачи на LLM (prompt injection, jailbreak), но она разбирается в модуле `misc-prompt-injection`; здесь — «классический» ML.

## Классификация задач

| Класс | Цель атакующего | Что даёт флаг |
|-------|-----------------|---------------|
| Model extraction | восстановить поведение чёрного ящика | суррогат, повторяющий API |
| Adversarial | обмануть классификатор | вход, меняющий предсказание |
| Membership inference | узнать, был ли объект в обучении | утечка приватности |
| Data poisoning | испортить обучение | смещённая модель |
| Backdoor | встроить триггер | срабатывание на паттерн |
| LLM | обойти инструкции | утечка системного промпта |

## Извлечение модели (model extraction)

Идея: у вас есть только API (чёрный ящик). Вы **запрашиваете** его на множестве входов, собираете пары «вход → выход» и обучаете собственную **суррогатную** модель, которая повторяет поведение. Чем информативнее ответы, тем лучше:

- **hard labels** (только класс) — медленно, нужно много запросов;
- **soft labels** (вероятности по классам) — гораздо эффективнее: одна точка несёт информацию обо всех классах.

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(0)
W_true = rng.normal(size=(2, 3))          # неизвестная линейная модель, 3 класса
def api(x):
    logits = W_true @ x
    e = np.exp(logits - logits.max())
    return e / e.sum()                    # soft labels

Xs = rng.normal(size=(4000, 2))
Ys = np.array([api(x).argmax() for x in Xs])   # hard labels с API
surrogate = LogisticRegression().fit(Xs, Ys)
print(surrogate.coef_.shape, surrogate.score(Xs, Ys))
```

Если API отдаёт вероятности, обучайте суррогат на них (distillation) — сойдётся быстрее и точнее.

## Adversarial-примеры

Adversarial-пример — вход `x'`, визуально почти неотличимый от `x`, но классифицируемый иначе. Базовый метод — **FGSM** (Fast Gradient Sign Method): сдвигаем вход на `ε` в сторону роста функции потерь.

```python
import numpy as np
w = np.array([1.0, -2.0]); b = 0.5       # линейный классификатор score = w·x + b
x = np.array([0.3, 0.4])
eps = 0.5
grad = w                                 # d(score)/dx = w для линейной модели
x_adv = x + eps * np.sign(grad)
print("orig", w @ x + b, "adv", w @ x_adv + b)
```

```
orig -0.3 adv 0.75
```

Один шаг перевернул знак оценки. **PGD** — итеративный вариант: несколько малых шагов с проекцией в `ε`-шар; он сильнее FGSM. Для нейросетей градиент берут автодиффом (`loss.backward()`).

## Отравление данных и бэкдоры

- **Data poisoning** — атакующий подмешивает в обучающую выборку «плохие» примеры, чтобы сдвинуть решение модели (например, чтобы спам классифицировался как не-спам).
- **Backdoor** — в данные добавляют триггер (небольшой паттерн). Модель ведёт себя нормально на чистых входах, но на входе с триггером всегда выдаёт заданный класс. В CTF это выглядит как «найди триггер, который заставит модель выдать флаг».

Типовой признак бэкдора: модель идеально работает на валидации, но реагирует на странный паттерн (пиксель в углу, редкое слово) непропорционально.

## Инструменты

- **numpy / scikit-learn** — база для линейных моделей и суррогатов.
- **PyTorch** — автодифф для градиентных атак.
- **ART (Adversarial Robustness Toolbox)** — готовые FGSM/PGD/DeepFool (`pip install adversarial-robustness-toolbox`).
- **foolbox** — библиотека adversarial-атак (`pip install foolbox`).
- **transformers** — для задач на LLM.
- **onnx / onnxruntime** — когда модель отдана в ONNX.

## Разобранный пример: обход линейного классификатора

Пусть модель решает «спам/не спам» по двум признакам, а флаг выдаётся, если модель уверена в классе `1`. Решаем как задачу оптимизации:

```python
import numpy as np
w = np.array([2.0, 1.5]); b = -3.0
# ищем x с ограничением 0 <= x <= 1, максимизируя score
from scipy.optimize import minimize
res = minimize(lambda x: -(w @ x + b), x0=[0.5,0.5],
               bounds=[(0,1),(0,1)])
print(res.x, w @ res.x + b)   # максимум score на границе
```

Если есть ограничение «`x` должен выглядеть как обычный текст», добавляют соответствующие bounds или штрафы — это уже adversarial с ограничениями.

## Частые ошибки и подводные камни

- **Забыть про ограничения на вход.** Adversarial-пример должен быть допустимым (пиксели `0..255`, текст печатный), иначе он бесполезен.
- **Мало запросов к API.** Для точного суррогата нужны тысячи пар; при soft labels — меньше.
- **Переобучение суррогата.** Проверяйте не на обучающих, а на новых запросах к API.
- **Игнорирование нормализации.** Модель могла обучаться на нормированных данных — учитывайте это при генерации входа.
- **Путать отравление и бэкдор.** Отравление смещает решение в целом, бэкдор срабатывает только на триггере.

## Что дальше / решение

1. Определите интерфейс: есть ли доступ к вероятностям или только к классу.
2. Для extraction — соберите датасет запросами и обучите суррогат.
3. Для adversarial — посчитайте градиент по входу и сдвиньте его на `ε` (FGSM) или итеративно (PGD).
4. Для бэкдора — ищите триггерный паттерн, сравнивая поведение на чистых и подозрительных входах.
5. Всегда проверяйте, что найденный вход допустим по условию задачи.

## Transferability и защита моделей

Adversarial-примеры обладают **переносимостью** (transferability): пример, подобранный для одной модели, часто обманывает и другую, обученную на тех же данных. Это позволяет атаковать чёрный ящик, не имея градиента: обучаем суррогат, генерируем пример на нём — и подаём в цель. В CTF это типовой приём, когда прямой доступ к градиенту закрыт.

Защита от таких атак строится на нескольких принципах:

- **adversarial training** — добавлять adversarial-примеры в обучение; модель становится устойчивее;
- **input sanitization** — нормализация и квантование входа (сглаживает малые возмущения);
- **randomized smoothing** — усреднение предсказаний по случайным возмущениям входа;
- **detection** — отдельный детектор аномальных входов.

Важно понимать: **абсолютной защиты нет**. Любая защита лишь повышает стоимость атаки. В задачах на обход вы ищете именно ту «щель», которую не закрыли: неограниченный вход, отсутствие нормализации, слишком маленькое `ε` в обучении.

## Разобранный пример: transfer attack

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(1)
X = rng.normal(size=(2000, 4))
y = (X @ np.array([1, -1, 0.5, 2]) > 0).astype(int)

victim = LogisticRegression().fit(X, y)          # белая модель-жертва
surrogate = LogisticRegression().fit(X, y)       # похожая модель

x = X[0]
grad = surrogate.coef_[0]                         # градиент суррогата
x_adv = x + 0.5 * np.sign(grad)
print("victim on x    :", victim.predict([x])[0])
print("victim on x_adv:", victim.predict([x_adv])[0])
```

Если предсказание жертвы на `x_adv` меняется — переносимость сработала. На практике суррогат обучают на запросах к чёрному ящику, а не на тех же данных, и всё равно получают значимую долю успешных переносов.

## Инференс членства

Атака membership inference отвечает на вопрос «был ли конкретный объект в обучающей выборке». Модели часто **переобучены** и дают на обучающих примерах более высокую уверенность. Значит, по уверенности можно судить о членстве. В CTF это выглядит как задача «определи, какие из записей попали в датасет», и решается порогом по вероятности или обучением атакующего классификатора на выходах модели.

## Чек-лист ML-задачи

1. Понять интерфейс: класс или вероятности, есть ли лимит запросов.
2. Если нужен обход — определить, можно ли считать градиент; если нет — суррогат + переносимость.
3. Проверить ограничения на вход (диапазоны, формат, нормализация).
4. Сгенерировать кандидата (FGSM/PGD/оптимизация) и проверить на цели.
5. Если задача про бэкдор — искать триггер по аномальной уверенности на редких паттернах.

## Итог по AI/ML в CTF

Главное в ML-задачах — правильно определить интерфейс и ограничения. Если есть вероятности — собирайте soft labels для точного суррогата; если доступен только класс — полагайтесь на переносимость и обучайте суррогат на запросах. Для обхода классификатора считайте градиент по входу (FGSM/PGD) и обязательно проверяйте допустимость результата. Бэкдоры ищите по аномальной уверенности на редких паттернах, а отравление — по систематическому смещению решения. И помните: абсолютной защиты от adversarial-атак не существует, любая защита лишь повышает стоимость атаки.
