## Теория чисел в misc: общий подход

Задачи по теории чисел в misc — это про делимость, простые числа, модульную арифметику и «найди закономерность в числах». Они редко требуют доказательств; обычно достаточно быстро посчитать или найти структуру. Главные инструменты — `sympy` (факторизация, простые, CRT, дискретный логарифм) и встроенные функции Python. Цель модуля — собрать рецепты для типовых задач: факторизация, НОД/НОК, сравнения по модулю, поиск простых.

## Простые числа и факторизация

```python
from sympy import isprime, nextprime, factorint, primerange
isprime(2**31 - 1)              # проверка простоты
factorint(600851475143)         # {71: 1, 839: 1, 1471: 1, 6857: 1}
list(primerange(1, 100))        # список простых до 100
nextprime(1000)
```

Задачи «разложи N» — это `factorint`. Если N очень велико (сотни бит) и «случайно» — проверьте, не произведение ли близких простых (атака Ферма) или не содержит ли общий множитель с другим модулем.

## НОД, НОК и линейные диофантовы уравнения

```python
import math
math.gcd(a, b)
a*b // math.gcd(a, b)           # НОК
from sympy import igcdex
g, x, y = igcdex(a, b)          # a*x + b*y = g
```

`igcdex` даёт коэффициенты Безу — основа модульной инверсии и решения `ax ≡ b (mod m)`.

## Сравнения и Китайская теорема об остатках

```python
from sympy.ntheory.modular import crt
crt([2, 3, 5], [3, 5, 7])       # (23, 105): x ≡ 23 mod 105
```

CRT — стандартный приём задач «найди число, которое при делении на ... даёт остатки ...». Если модули не взаимно просты — проверяйте согласованность остатков.

## Дискретный логарифм и порядок

```python
from sympy.ntheory.residue_ntheory import discrete_log
discrete_log(p, a, g)           # g^x ≡ a mod p, найти x
```

Для маленьких групп работает. Для больших — BSGS (baby-step giant-step) или специальные структуры.

## Последовательности и закономерности

Если даны числа и просят «следующее», проверяйте: арифметическую/геометрическую прогрессию, конечные разности (полином), рекурренты, простые числа, факториалы, числа Фибоначчи. Иногда последовательность — это цифры константы (π, e, √2). Ищите в OEIS.

```python
from sympy import fibonacci, prime
[fibonacci(n) for n in range(10)]
[prime(n) for n in range(1, 10)]
```

## Модульная арифметика и инверсия

```python
pow(a, b, m)                    # a^b mod m
pow(a, -1, m)                   # a^-1 mod m
```

Помните: инверсия существует только если `gcd(a, m) == 1`. Для задач «реши ax ≡ b mod m» — `x = b * pow(a, -1, m) % m`.

## Практический пример: RSA с близкими простыми

Дано `n` и `e`, `n` — произведение двух близких простых. Атака Ферма:

```python
from math import isqrt
def fermat(n):
    a = isqrt(n)
    if a*a < n: a += 1
    while True:
        b2 = a*a - n
        b = isqrt(b2)
        if b*b == b2:
            return a-b, a+b
        a += 1
```

Найдя `p, q`, считаем `phi`, `d` и расшифровываем.

## Типичные ошибки и подводные камни

- **Наивная факторизация** больших чисел — используйте `sympy`/`gmpy2`.
- **Деление по модулю без инверсии** — `pow(a,-1,m)`.
- **Модули не взаимно просты** в CRT — проверяйте согласованность.
- **Полагать, что «случайное N» не факторизуется** — проверьте gcd с другими.
- **Путать порядок и показатель** — `discrete_log` может быть медленным.
- **Не проверить OEIS** для последовательностей.
- **Переполнение** при ручной арифметике — Python спасает, но переносите аккуратно.

Для факторизации — `sympy.factorint`; для сравнений — CRT и инверсия; для последовательностей — проверьте прогрессии, рекурренты и OEIS. ## Практический пример: RSA с общим множителем

Разберём задачу. Даны два модуля `n1` и `n2` и одинаковый показатель `e`. Прямая факторизация невозможна, но если модули «случайно» имеют общий простой множитель, его находят за один шаг:

```python
from math import gcd
g = gcd(n1, n2)
if g > 1:
    p = g
    q1 = n1 // p
    phi = (p-1)*(q1-1)
    d = pow(e, -1, phi)
    m = pow(c1, d, n1)
    print(m.to_bytes((m.bit_length()+7)//8, 'big'))
```

Это классическая атака «shared prime»: генератор случайных чисел переиспользовал простое число. Всегда проверяйте `gcd` между всеми доступными модулями — это бесплатно и часто решает задачу.

## Практический пример: CRT для системы сравнений

Если условие задаёт систему `x ≡ a_i (mod m_i)`, применяйте Китайскую теорему об остатках:

```python
from sympy.ntheory.modular import crt
x, mod = crt([a1, a2, a3], [m1, m2, m3])
print(x % mod)
```

Если модули не взаимно просты, проверьте согласованность: остатки по общему делителю должны совпадать.

## Частые вопросы

«N огромный и случайный — тупик?» — проверьте gcd с другими модулями и близость простых. «e=3 и сообщение короткое?» — целочисленный кубический корень. «Нужно найти порядок элемента?» — `sympy.n_order`. «Как проверить, простое ли число?» — `sympy.isprime`.

## Расширенный чек-лист по теории чисел

Классифицируйте задачу за минуту. Если дано большое число и просят «разложить» — `factorint`; если число подозрительно похоже на произведение двух близких простых — атака Ферма; если дано несколько модулей с общим `e` — проверьте `gcd` между ними; если дана система сравнений — CRT; если дано «найди x в g^x ≡ a» — дискретный логарифм; если дана последовательность — проверьте прогрессии, рекурренты, простые, OEIS. Для каждой категории держите готовый сниппет. И помните про точность: `Decimal` для дробей, `pow(a,-1,m)` для инверсии, `gmpy2` для скорости. Большинство задач решается за несколько вызовов, если правильно определить категорию.

## Итоговая шпаргалка по теории чисел

Держите этот список под рукой: `sympy.isprime(n)` — проверка простоты; `sympy.factorint(n)` — факторизация; `sympy.primerange(a,b)` — простые в диапазоне; `math.gcd(a,b)` — НОД; `sympy.crt(mods, rems)` — Китайская теорема; `sympy.discrete_log(p,a,g)` — дискретный логарифм; `pow(a,b,m)` — степень по модулю; `pow(a,-1,m)` — модульная инверсия; `gmpy2.iroot(x,n)` — точный корень; `sympy.n_order(a,n)` — порядок элемента. Этого набора хватает для большинства задач. Определяйте категорию задачи и применяйте соответствующую функцию, а специальные структуры (общий множитель, близкие простые, малый показатель) проверяйте первыми — они бесплатны и часто решают задачу.
