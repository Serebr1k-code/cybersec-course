## Что такое эзотерическая обфускация

Обфускация — это намеренное усложнение кода, чтобы его было трудно понять, не меняя поведения. «Эзотерическая» — значит доведённая до крайности: код становится нечитаемым настолько, что выглядит как шум. В CTF и в анализе малвари такие приёмы встречаются постоянно: веб-шелл на 20 КБ символов, JS, где нет ни одной буквы, или Python-однострочник из `eval`-цепочек.

## JSFuck и jjencode

JSFuck использует только шесть символов: `[]()!+`. Этого достаточно, чтобы выразить любой JavaScript: `!` даёт булевы значения, `+` их складывает, `[]` обращается к свойствам, а `()` вызывает. Например, `![]` — это `false`, `!![]` — `true`, а `[][[]]` извлекает `undefined`.

```javascript
// классические «строительные блоки» JSFuck
![]            // false
!![]           // true
+!+[]          // 1  (число из булева)
[][[]]         // undefined
```

**jjencode** идёт дальше: использует только `$`, `_`, `+`, `(`, `)`, `[`, `]`, строя строки через `$`-переменные. Раскрыть такой код можно, выполнив его и перехватив результат (в изолированной среде), либо через `node` с `console.log`.

## Whitespace-обфускация

Тот же приём, что в esolang Whitespace, применяют для сокрытия полезной нагрузки в обычном тексте: значимы только пробелы и табы, а буквы — маскировка. В обфускации это даёт код, который выглядит как пустота. Снять — заменить пробелы/табы на видимые символы и разобрать мнемонику.

```bash
cat -A suspicious.txt | head
tr ' \t' 'ST' < suspicious.txt | head -c 300
```

## Цепочки eval / base64 / hex

Классика веб-обфускации — многослойное кодирование:

```javascript
eval(atob("ZXZhbCgnY29uc29sZS5sb2coNDIpJyk="))
```

Здесь `atob` декодирует base64 в строку `eval('console.log(42)')`, а внешний `eval` её исполняет. Снятие — итеративно: заменяем внешний `eval` на `console.log` (или `print`) и повторяем, пока не получим читаемый код. Аналогично работают `String.fromCharCode(...)`, hex-экранирование `\x..` и `unescape`.

```javascript
// безопасный приём раскрытия: печатаем, а не исполняем
let code = "eval(atob('...'))";
console.log(code.replace(/^eval\(/, "console.log(").replace(/\)$/, ")"));
```

## Полиморфизм и самомодификация

Полиморфный код меняет своё представление при каждом запуске, но поведение остаётся тем же. Классический приём — расшифровать тело полезной нагрузки ключом и исполнить его в памяти; при статическом анализе видна только «расшифровщик». В JS это `eval(decrypt(payload))`, в бинарниках — распаковка в RWX-память. Для анализа такие фрагменты исполняют под отладчиком/песочницей и снимают дамп расшифрованного кода.

## Минификация и жонглирование типами

Обфускаторы часто «жонглируют типами»: `1 + {}`, `[] + []`, `+!![]`. Это законно в JS и даёт неочевидные результаты:

```javascript
[] + []        // "" (пустая строка)
[] + {}        // "[object Object]"
+!![]          // 1
1 + "1"        // "11"
```

Умение читать такие выражения — ключ к «ручному» разбору минифицированного кода.

## Инструменты

- **js-beautify / prettier** — форматирование минифицированного JS.
- **de4js / JSFuck decoder** — раскрытие JSFuck/jjencode (онлайн).
- **node** — исполнение в песочнице для перехвата результата.
- **unminify / UglifyJS** — восстановление имён и структуры.
- **AST-инструменты** (Babel, acorn) — программная трансформация.
- **Динамический анализ** — запуск под отладчиком и логирование.

## Разобранный пример: раскрытие JSFuck

Дано: строка из `[]()!+`. Порядок действий:

1. Сохранить код в файл.
2. Обернуть в `console.log(...)`, если это выражение, и выполнить в `node`:

```bash
node -e 'console.log(/* JSFuck-выражение */)'
```

3. Если код — программа (состоит из вызовов), выполнить в песочнице и перехватить `eval`/`Function`, подменив их на логирование:

```javascript
const realEval = eval;
global.eval = (s) => { console.log("EVAL:", s); return realEval(s); };
```

Так вы увидите расшифрованное тело, не давая ему исполниться «вслепую».

## Разобранный пример: раскрытие eval-цепочки

Дано: `eval(String.fromCharCode(101,118,97,108,...))`. Решение — заменить внешний `eval` на `print`/`console.log` и выполнить один раз; затем повторить с полученной строкой.

```python
import re
code = "eval(String.fromCharCode(101,118,97,108,40,49,41,41))"
# шаг 1: вычислить аргумент
import ast
print(ast.literal_eval(re.search(r'fromCharCode\((.*)\)\)$', code).group(1)))
```

Итеративно «раздевая» слои, вы дойдёте до читаемой логики (обычно это `fetch`, `require` или печать флага).

## Частые ошибки и подводные камни

- **Исполнять недоверенный код.** Обфусцированный код может быть вредоносным — анализируйте в песочнице/VM.
- **Останавливаться на первом слое.** После первого `eval` часто спрятан второй.
- **Игнорировать жонглирование типами.** `[] + []` и `+!![]` неочевидны, но детерминированы.
- **Забыть про динамику.** Статический разбор полиморфного кода бесполезен — нужен запуск.
- **Портить байты.** Обфускация чувствительна к точным символам; работайте с бинарной копией.

## Справочная таблица

| Приём | Как выглядит | Как раскрыть |
|-------|--------------|--------------|

## Что дальше / решение

1. Определите природу: JSFuck/jjencode, whitespace, eval-цепочка, полиморфизм.
2. Для JS — форматируйте (`prettier`) и выполняйте в песочнице с перехватом `eval`/`Function`.
3. Для eval/base64/fromCharCode — «раздевайте» слои, заменяя исполнение на печать.
4. Для полиморфного кода — запускайте под отладчиком и снимайте расшифрованное тело.
5. Никогда не исполняйте недоверенный код на рабочей машине.

## Обфускация в Python и shell

Python-обфускация обычно строится на `exec`/`eval` и кодировках:

```python
exec(bytes.fromhex("7072696e7428276869212729").decode())
# выведет: hi!
```

Снять слой просто: заменить `exec`/`eval` на `print` и выполнить один раз. Многослойные варианты «раздевают» итеративно, пока не получится читаемый код. Часто встречается `zlib.decompress(base64.b64decode(...))` — раскрывайте снаружи внутрь.

Shell-обфускация использует переменные и `eval`:

```bash
a=ec;b=ho;eval "$a$b hello"   # выполнит: echo hello
```

Приёмы деобфускации: подстановка переменных, `set -x` для трассировки, замена `eval` на `echo`.

## Автоматическая деобфускация

Для JS-обфускации удобно комбинировать инструменты:

- **prettier/js-beautify** — форматирование;
- **de4js** — автоматическое раскрытие JSFuck/jjencode/packer;
- **AST-обход** (acorn + escodegen) — программное упрощение выражений;
- **перехват** — подмена `eval`/`Function` на логирование в песочнице.

Для Python — `uncompyle6`/`decompyle3` (байткод), `ast` для разбора, `pycdc` для `.pyc`.

## Частые вопросы по обфускации

- **Опасно ли запускать?** Да; используйте изолированную VM/контейнер без сети.
- **Помогает ли форматирование?** Часто да: минифицированный код после `prettier` становится читаемым.
- **Что если код исполняет payload?** Перехватывайте `eval`/`Function`/`require`, чтобы увидеть, что именно исполняется, до исполнения.
- **Как понять, что слой последний?** Когда после раскрытия получается обычный код без `eval`/`atob`/`fromCharCode`.

## Обфускация байткода и нативных форматов

Обфускация встречается не только в исходниках. Python-байткод (`.pyc`) можно перепутать версиями и модифицировать, а `.NET`/Java — обфусцировать именами и control flow (ConfuserEx, ProGuard). Приёмы снятия те же: восстановить структуру (decompiler), перехватить динамику, упростить выражения. Для `.pyc` используйте `uncompyle6`/`pycdc`; для Java — CFR/Procyon; для .NET — dnSpy. Если байткод обфусцирован, помогает сравнение с оригиналом (`uncompyle6` на эталонной версии) и динамическая трассировка.

## Стеганография в исходном коде

Отдельный приём — спрятать данные в самом коде: невидимые символы (zero-width), гомоглифы (похожие Unicode-буквы), порядок пробелов, длина строк. В CTF это выглядит как «обычный код», где секрет в непечатаемых символах. Инструмент — `grep -P '[\x{200b}-\x{200f}]'`, а также сравнение байтов через `xxd`. Не путайте с обфускацией логики: здесь скрыты **данные**, а не поведение.

## Итог по эзотерической обфускации

Главное правило — никогда не исполняйте обфусцированный код «как есть». Сначала форматируйте, затем перехватывайте динамику (`eval`/`Function`/`require`), и только потом разбирайте логику. Двигайтесь слоями: JSFuck → `eval` → `atob` → `fromCharCode` → читаемый код. Для полиморфного кода статический анализ бесполезен — снимайте расшифрованное тело отладчиком в песочнице. И помните: обфускация прячет **и логику, и данные** — проверяйте и непечатаемые символы, и структуру выражений.
