## Вопрос, с которого всё начинается

В CTF ты открываешь файл `payload.js` — а там нет ни одной буквы: только `[]()!+`. Или видишь `eval(atob("..."))`, за которым прячется ещё один `eval`. Как понять, что этот код делает, и не запустить его «вслепую»? Обфускация — это намеренное усложнение кода без изменения поведения; «эзотерическая» — доведённая до предела. В этом уроке мы возьмём такой файл и «разденем» его по слоям.

## Наш пример: строка из []()!+

Дано — JavaScript, записанный только шестью символами: `[`, `]`, `(`, `)`, `!`, `+`. Это **JSFuck**. Удивительно, но этих символов достаточно, чтобы выразить любой JavaScript. Разберёмся почему.

`!` — логическое отрицание, даёт булевы значения. `+` складывает и приводит типы. `[]` — пустой массив, у него можно брать свойства. `()` — вызов. Отсюда классические «строительные блоки»:

```javascript
![]            // false
!![]           // true
+!+[]          // 1  (число из булева)
[][[]]         // undefined
```

`![]` — «не пустой массив» → `false`; `!![]` → `true`; `+!+[]` — плюс перед `true` превращает его в число `1`. Комбинируя эти примитивы, JSFuck строит строки (через `[]+[]` = `""`), числа и, наконец, вызывает функции. **jjencode** идёт дальше и использует только `$ _ + ( ) [ ]`, строя строки через `$`-переменные.

## Whitespace-обфускация

Тот же приём, что в esolang Whitespace, применяют для сокрытия полезной нагрузки в обычном тексте: значимы только пробелы и табы, а буквы — маскировка. Снять — заменить пробелы и табы на видимые символы:

```bash
$ cat -A suspicious.txt | head
$ tr ' \t' 'ST' < suspicious.txt | head -c 300
```

`cat -A` показывает непечатаемые символы, `tr` заменяет пробел на `S`, таб на `T` — и «пустота» превращается в разбираемую мнемонику.

## Цепочки eval / base64 / fromCharCode

Классика веб-обфускации — многослойное кодирование:

```javascript
eval(atob("ZXZhbCgnY29uc29sZS5sb2coNDIpJyk="))
```

Здесь `atob` декодирует base64 в строку `eval('console.log(42)')`, а внешний `eval` её исполняет. Снятие — итеративное: заменяем внешний `eval` на `console.log` (печать вместо исполнения) и повторяем, пока не получим читаемый код. Так же работают `String.fromCharCode(...)`, hex-экранирование `\x..` и `unescape`.

```python
import re, ast
code = "eval(String.fromCharCode(101,118,97,108,40,49,41,41))"
print(ast.literal_eval(re.search(r'fromCharCode\((.*)\)\)$', code).group(1)))
```

`ast.literal_eval` безопасно вычисляет список чисел, не исполняя код.

## Жонглирование типами

Обфускаторы «жонглируют типами» — это законно в JS и даёт неочевидные результаты:

```javascript
[] + []        // "" (пустая строка)
[] + {}        // "[object Object]"
+!![]          // 1
1 + "1"        // "11"
```

Умение читать такие выражения — ключ к ручному разбору минифицированного кода. Форматируй его (`prettier`/`js-beautify`), и многие конструкции станут понятны.

## Раскрываем по слоям — безопасно

Главное правило: **не исполняй недоверенный код**. Перехватывай динамику, подменяя `eval`/`Function` на логирование:

```javascript
const realEval = eval;
global.eval = (s) => { console.log("EVAL:", s); return realEval(s); };
```

Теперь ты видишь расшифрованное тело **до** его исполнения. Для JSFuck-выражения достаточно обернуть в `console.log(...)` и выполнить в `node`; для программы — запустить в песочнице и перехватить вызовы. Для Python-обфускации замени `exec`/`eval` на `print`:

```python
exec(bytes.fromhex("7072696e7428276869212729").decode())  # выполнит: print('hi!')
```

Раскрывай снаружи внутрь: `zlib.decompress(base64.b64decode(...))` снимается по шагам.

## Полиморфизм и самомодификация

Полиморфный код меняет своё представление при каждом запуске, но поведение остаётся тем же: тело полезной нагрузки расшифровывается ключом и исполняется в памяти. При статическом анализе видна только «расшифровщик». В JS это `eval(decrypt(payload))`, в бинарниках — распаковка в RWX-память. Статический разбор здесь бесполезен: запускай под отладчиком или в песочнице и снимай дамп расшифрованного кода. Помни, что обфускация прячет **и логику, и данные**: иногда секрет лежит в непечатаемых символах (zero-width, гомоглифы) — проверь `grep -P '[\x{200b}-\x{200f}]'` и сравни байты через `xxd`.

## Инструменты

- **js-beautify / prettier** — форматирование минифицированного JS.
- **de4js / JSFuck decoder** — раскрытие JSFuck/jjencode (онлайн).
- **node** — исполнение в песочнице для перехвата результата.
- **AST-инструменты** (Babel, acorn) — программное упрощение выражений.
- **uncompyle6 / pycdc** — байткод Python; **dnSpy**, **CFR/Procyon** — .NET и Java.

## Полный разбор: снимаем слои с payload.js

Соберём методику в одну историю. Дано: файл, где видно `eval(atob("..."))`. Действуем снаружи внутрь и **никогда не исполняем недоверенный код**:

1. Форматируем и смотрим структуру: `js-beautify payload.js | head`. Сразу видно число слоёв.
2. Декодируем строку base64 вручную: `echo '<base64>' | base64 -d`. Получаем следующий слой — снова `eval(...)` или `String.fromCharCode(...)`.
3. Повторяем шаг 2, пока не останется читаемый код. Числа из `fromCharCode` превращаем в строку через `python3 -c "print(bytes([101,118,97,108]))"` → `eval`.
4. Если слой — JSFuck (`[]()!+`), оборачиваем выражение в `console.log(...)` и исполняем в `node` — получим исходную строку, не запуская полезную нагрузку.
5. На последнем слое, если код всё же нужно запустить, — только в песочнице, перехватив `eval`/`Function` на печать.

Так «нечитаемый» файл раскрывается в понятную логику без риска. Помни: цель деобфускации — **увидеть**, а не выполнить.

## Что мы теперь знаем

- JSFuck кодирует любой JS шестью символами `[]()!+`.
- Whitespace прячет данные в пробелах и табах (`cat -A`, `tr`).
- `eval`/`atob`/`fromCharCode` — слои; снимай их печатью, а не исполнением.
- Жонглирование типами (`[]+[]`, `+!![]`) детерминировано, но неочевидно.
- Полиморфный код требует **динамического** анализа.
- Обфускация прячет и логику, и данные (непечатаемые символы).

## На что смотреть дальше

- **Никогда не исполняй недоверенный код.** Сначала форматируй (`js-beautify`), потом снимай слои печатью.
- **Снимай снаружи внутрь.** Каждый `eval`/`atob`/`fromCharCode` — один слой; веди журнал, что уже раскрыто.
- **Смотри на данные, не только на логику.** Секрет бывает в непечатаемых символах: проверь `xxd` и zero-width.
- **Полиморфизм — только динамически.** Статический разбор видит лишь «расшифровщик»; запускай в песочнице.
- **Проверяй версию движка.** Поведение `eval`, `atob` и типов отличается в браузере, `node` и `deno`.
