## Вопрос, с которого всё начинается

Задача даёт `book.epub`. Это «электронная книга», но по сути — архив. Внутри — текст, картинки и метаданные, и в одном из них спрятана метка. Как разобрать книгу, если ты раньше имел дело только с ZIP и HTML?

## Наш пример: book.epub

EPUB — это **ZIP** с чёткими правилами. Проверяем:

```
$ file book.epub
book.epub: EPUB document
$ unzip -l book.epub
  mimetype
  META-INF/container.xml
  OEBPS/content.opf
  OEBPS/chapter1.xhtml
  OEBPS/cover.jpg
```

Файл `mimetype` (без сжатия, первым) содержит `application/epub+zip`. `META-INF/container.xml` указывает на **OPF** — файл манифеста со списком всех частей книги.

## Шаг 1: OPF как оглавление

**OPF** (Open Packaging Format) — XML-манифест: перечисляет все ресурсы (`<item>`), порядок чтения (`<spine>`) и метаданные (`<metadata>`: автор, название, ISBN).

```
$ unzip -p book.epub OEBPS/content.opf | head
<package ...>
  <metadata><dc:title>CTF Notes</dc:title><dc:creator>anon</dc:creator></metadata>
  <manifest><item id="c1" href="chapter1.xhtml" media-type="application/xhtml+xml"/>
```

Метаданные — первое место, куда стоит смотреть: там бывает флаг или подсказка.

## Шаг 2: текст и скрытые данные

Текст — обычные XHTML-файлы. Ищем метку по всем частям:

```
$ unzip -o book.epub -d book && grep -roE 'nto\{[^}]*\}' book
book/OEBPS/chapter1.xhtml:nto{3pub_1s_z1p}
```

Как и в документах, текст можно **спрятать**: белым цветом в CSS, в `display:none`, в комментариях HTML, в атрибутах `alt`. Проверяем `grep` по `#ffffff`, `display:none`, `<!--`.

## Шаг 3: ресурсы и вложенные файлы

В `OEBPS/` лежат картинки, шрифты, стили. В картинке может быть вложенный архив (как в docx), а в шрифте — данные. `binwalk` по извлечённым ресурсам помогает:

```
$ binwalk OEBPS/cover.jpg
DECIMAL  DESCRIPTION
0        JPEG image
20480    Zip archive data
```

## Шаг 4: MOBI — бинарный контейнер

**MOBI** (и его потомок AZW3) — не ZIP, а контейнер **PalmDB**: заголовок с именем базы, списком записей (record), каждая запись со смещением. Внутри — сжатый (PalmDOC) текст.

```
$ xxd book.mobi | head -2
00000000: 5465 7374 426f 6f6b 0000 0000 ...        TestBook....
```

Имя базы (`TestBook`) — читаемая строка в начале. Дальше разбирают записи: часть — заголовок MOBI, часть — сжатый текст. Инструменты `mobiunpack`, `kindleunpack` распаковывают содержимое в HTML.

## Шаг 5: DRM

Книги из магазинов бывают зашифрованы **DRM** (Adobe ADEPT, Kindle). Тогда текст не читается без ключа. В CTF DRM встречается редко, но если встречается — ключ обычно спрятан в самом файле или в подсказке. Инструменты `DeDRM` требуют ключ из приложения-читалки.

## Шаг 6: практический порядок

1. `file` — EPUB или MOBI?
2. EPUB: `unzip -l`, читать `META-INF/container.xml` и OPF.
3. Искать метку в метаданных и тексте: `grep -roE`.
4. Проверить скрытый текст (CSS, `display:none`, комментарии).
5. `binwalk` по ресурсам на вложенные данные.
6. MOBI: разобрать PalmDB, при необходимости `mobiunpack`.

## Что мы теперь знаем

- EPUB — это ZIP с `mimetype`, `META-INF/container.xml` и OPF-манифестом.
- Текст — XHTML; метаданные — в OPF (`<metadata>`).
- Метку прячут в метаданных, CSS и вложенных ресурсах.
- MOBI — бинарный PalmDB-контейнер со сжатым текстом.
- DRM шифрует текст; ключ нужен из читалки.

## Шаг 7: spine, nav и порядок чтения

В OPF есть `<spine>` — порядок чтения глав, и `<manifest>` — список всех ресурсов. EPUB3 добавляет навигацию `nav.xhtml` (а старый EPUB2 — `toc.ncx`). Зная spine, ты читаешь книгу в правильном порядке и не пропускаешь «служебные» страницы, где часто прячут текст. Проверь все элементы manifest — там могут быть файлы, не упомянутые в spine.

## Шаг 8: EPUB как ZIP — важные детали

Файл `mimetype` обязан лежать первым и **без сжатия** (stored) — по нему валидаторы узнают EPUB. Если распаковать и пересобрать архив обычным `zip`, это правило легко нарушить. Для нас важно: EPUB — обычный ZIP, поэтому работают `unzip`, `zipinfo`, а вложенные в ресурсы архивы — `binwalk`.

```
$ zipinfo -1 book.epub | head
mimetype
META-INF/container.xml
OEBPS/content.opf
```

## Шаг 9: метаданные и exiftool

`exiftool` читает метаданные EPUB/MOBI наравне с документами:

```
$ exiftool book.epub | grep -iE 'title|creator|identifier'
Title    : CTF Notes
Creator  : anon
```

Автор, издатель, даты, ISBN — всё это источники OSINT и места для спрятанной метки. В OPF метаданные лежат в `<metadata>`, и их легко посмотреть через `unzip -p ... content.opf`.

## Шаг 10: MOBI изнутри — PalmDOC

Текст в MOBI обычно сжат алгоритмом **PalmDOC** (или HUFF/CDIC в поздних версиях). PalmDOC — простой LZ-подобный алгоритм: байты < 0x80 — литералы, старшие значения — ссылки «назад» на повторы. Его распаковывают `mobiunpack`/`kindleunpack`, выдавая HTML. Заголовок MOBI (после PalmDB) содержит смещения и флаги сжатия.

## Шаг 11: скрытый текст и стеганография

В книгах текст прячут так же, как в документах: белый цвет (`color:#fff`), `display:none`, нулевой размер шрифта, комментарии HTML, `alt`-атрибуты у картинок, текст в метаданных. Отдельный приём — «нулевые» символы (zero-width space) внутри слов: визуально невидимы, но кодируют биты. Проверяй `grep` по Unicode-невидимкам.

## Шаг 12: инструменты

- **EPUB**: `unzip`, `zipinfo`, `epubcheck` (валидатор), `Calibre` (`ebook-convert`).
- **MOBI/AZW3**: `mobiunpack`, `kindleunpack`, `Calibre`.
- **Метаданные**: `exiftool`.
- **Вложенное**: `binwalk`, `foremost`.
- **Просмотр**: любой EPUB-ридер (но осторожно с недоверенным контентом).

## Шаг 13: где искать метку в книге

По порядку: (1) `<metadata>` в OPF; (2) текст глав (`grep -roE`); (3) скрытый CSS/HTML; (4) нулевые символы; (5) вложенные в ресурсы архивы; (6) для MOBI — заголовок PalmDB и распакованный HTML. Этого списка хватает почти для любой «книжной» задачи.

## Шаг 14: частые ошибки

- Открывать EPUB как обычный текст (это ZIP).
- Искать только в первой главе, забыв про manifest и служебные файлы.
- Не проверять CSS на скрытый текст.
- Путать EPUB (ZIP) и MOBI (PalmDB).
- Забывать про метаданные — а метка часто там.

## Итог

EPUB — это ZIP с манифестом OPF, текстом XHTML и ресурсами; MOBI — бинарный контейнер PalmDB со сжатым PalmDOC текстом. В обоих метку ищут в метаданных, скрытом тексте и вложенных ресурсах. Инструменты — `unzip`, `exiftool`, `binwalk`, `mobiunpack`. Помни: книга — это контейнер, а не просто текст.

## Шаг 15: EPUB2 против EPUB3

EPUB2 использует `toc.ncx` для оглавления; EPUB3 — `nav.xhtml`. Оба могут присутствовать. При разборе проверь обе навигационные части: в служебных ссылках иногда прячут текст. Версия указана в OPF (`version="3.0"`), и от неё зависит, какие части ожидать.

## Шаг 16: content.opf целиком

OPF — сердце книги. В нём: `<metadata>` (автор, ISBN, язык, даты), `<manifest>` (все ресурсы с id и media-type), `<spine>` (порядок чтения), `<guide>` (точки входа). Прогон `grep` по OPF часто находит метку быстрее, чем перебор глав:

```
$ unzip -p book.epub OEBPS/content.opf | grep -iE 'flag|nto|secret'
```

## Шаг 17: изображения и шрифты внутри

Книга содержит обложку и картинки; шрифты (`.ttf`/`.otf`) могут нести данные в таблицах. К каждому ресурсу применим `binwalk` (вложенный архив) и `exiftool` (метаданные). Обложка — частый носитель LSB-стеганографии: пиксели почти не меняются, но кодируют биты.

## Шаг 18: MOBI — разбор PalmDB по шагам

PalmDB-заголовок: имя базы (32 байта), атрибуты, версия, даты, число записей, затем таблица записей (смещение+атрибуты+id на запись). Первая запись — заголовок PalmDOC/MOBI с флагами сжатия и смещениями. `mobiunpack` автоматизирует всё это и выдаёт HTML-части книги, с которыми работают как с EPUB-главами.

## Шаг 19: DRM — что реально нужно

Если книга зашифрована, без ключа текст не читается. Ключ привязан к аккаунту/устройству читалки. В CTF DRM встречается редко; если встречается — подсказка обычно ведёт к ключу, спрятанному в самом файле или в задании. Не трать время на «взлом» DRM без ключа.

## Шаг 20: общий чек-лист по книге

1. `file` — EPUB или MOBI.
2. EPUB: `unzip -l`, OPF, `grep` метки, скрытый CSS/HTML, `binwalk` по ресурсам.
3. MOBI: PalmDB → `mobiunpack` → HTML, `grep` метки.
4. Метаданные: `exiftool`.
5. Нулевые символы и скрытый текст: отдельная проверка.

## Шаг 21: mimetype и целостность архива

Проверить, что перед тобой настоящий EPUB, можно так: `unzip -p book.epub mimetype` должен вернуть ровно `application/epub+zip` без перевода строки. Если mimetype сжат или лежит не первым — валидатор (и некоторые парсеры) книгу отвергнут. Это объясняет, почему нельзя «просто пересобрать» EPUB обычным `zip`: порядок и способ хранения первого файла важны.

## Шаг 22: мини-практика

Разбери свою книгу: `unzip -o book.epub -d b && cat b/META-INF/container.xml` — найдёшь путь к OPF. Затем `grep -r nto b/` — поиск метки по всем частям. Этот двухшаговый приём (найти OPF → грепнуть всё) решает большинство книжных задач.

## Шаг 23: сравнение EPUB и PDF как контейнеров

PDF и EPUB решают одну задачу (книга), но устроены противоположно. PDF — поток объектов, часто с инкрементальными обновлениями, поэтому «удалённый» текст реально остаётся в файле. EPUB — ZIP, который редакторы пересобирают целиком, поэтому старых версий в нём нет. Отсюда практическое правило: в EPUB ищи служебные и скрытые части, а в PDF — старые объекты и слои. Понимая разницу контейнеров, ты выбираешь правильный инструмент, а не перебираешь всё подряд.
