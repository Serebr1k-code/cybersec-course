## Вопрос, с которого всё начинается

Задача даёт файл `prog.ws`. Открываешь — пустота. Ни букв, ни цифр, ни символов. Но файл не пустой: его размер в сотни байт. Всё содержимое — пробелы, табы и переводы строк. Это **Whitespace** — язык, где значимы только «невидимые» символы. Как прочитать программу, которую не видно?

## Наш пример: hex-дамп

Проявим содержимое через hex-дамп:

```
$ cat ws_hex.txt
00000000: 20 20 09 20 0a 20 20 20 09 0a 20 09 20 0a 20 0a
00000010: 20 09 09 0a ...
```

Байты `20` (пробел), `09` (таб) и `0a` (перевод строки) — это и есть код. Разберём, как из них получается программа.

## Шаг 1: алфавит из трёх символов

Whitespace использует ровно три символа: **пробел** (Space), **таб** (Tab) и **перевод строки** (LF). Всё остальное игнорируется — поэтому в исходнике могут быть комментарии из любых других символов, и они не влияют на программу. Это делает язык идеальным для обфускации: код можно спрятать в «пробелах» обычного текста.

## Шаг 2: кодирование инструкций

Инструкции кодируются последовательностями этих символов, как в двоичном коде, где Space = 0, Tab = 1, а LF завершает:

- **Стек-манипуляции**: начинаются с пробела; далее — операция (push, dup, swap...).
- **Арифметика**: начинаются с таба + пробела; далее — операция (add, sub, mul...).
- **Heap-доступ**: начинаются с таба + таба.
- **Ввод-вывод**: начинаются с таба + перевода строки.
- **Управление потоком**: начинаются с перевода строки.

То есть первый символ задаёт категорию, следующие — конкретную команду.

## Шаг 3: стек и heap

Whitespace — стековый язык, как Brainfuck/FALSE (см. ветку esolang). Есть **стек** (для вычислений) и **heap** (адресуемая память, как массив). `push` кладёт число, арифметика берёт два верхних значения, `store`/`retrieve` работают с heap по адресу. Программа читает ввод, считает и печатает вывод.

## Шаг 4: числа и метки

Числа в Whitespace кодируются знаковым двоичным кодом: первый символ — знак (Space = плюс, Tab = минус), далее биты (Space = 0, Tab = 1), LF — конец. Метки для переходов (`label`, `call`, `jump`) — произвольные последовательности Space/Tab. Поэтому «пустой» файл на деле полон чисел и меток.

## Шаг 5: как проявить программу

Чтобы увидеть код, его нужно визуализировать: заменить пробел на видимый символ (например, `.`), таб — на `→`, перевод строки — на `¶`. Тогда программа «проявится». Это можно сделать простым `sed`/скриптом. Часто в задачах уже дан такой «проявленный» вид — читай его.

## Шаг 6: интерпретаторы

Готовых интерпретаторов много (официальный Haskell-компилятор, реализации на Python). Для CTF обычно хватает одного: запустить и получить вывод. Если интерпретатора нет — Whitespace несложно эмулировать: таблица команд + стек + heap, около 150 строк.

## Шаг 7: практический порядок

1. Понять, что файл не пуст (`wc -c`, `xxd`).
2. Убедиться, что алфавит — Space/Tab/LF.
3. Проявить код визуализацией.
4. Исполнить интерпретатором.
5. Если нужно — трассировать стек и heap.

## Разбор кейса: декодируем Whitespace вручную

Дан файл `prog.ws`, начинающийся байтами `20 20 09 20 0a`. Проявим его: заменим пробел на `.`, таб на `→`, перевод строки на `¶`.

```bash
$ sed -e 's/ /./g' -e $'s/\t/→/g' -e 's/$/¶/' prog.ws | head
..→.¶...
```

Теперь код виден. Разберём первую инструкцию `20 20 09 20 0a` — это `[Space][Space][Tab][Space][LF]`.

Первый символ `Space` = **стек-манипуляции**. Второй `Space` = `push`. Дальше идёт число: `[Tab][Space]` — знак `Tab` = минус, биты `Space` = 0, `Tab` = 1, `LF` — конец числа. Здесь после знака идёт один бит `Space` = 0, значит число = 0 (со знаком минус), то есть `push 0`.

Так, читая пары-тройки символов, восстанавливают всю программу. Числа, метки и операции — всё это последовательности Space/Tab, завершённые LF. Визуализация — первый шаг любой Whitespace-задачи: пока код «невидим», рассуждать невозможно.

## Таблица: инструкции Whitespace

Префикс задаёт категорию, далее — команда.

| Категория | Префикс | Команды (примеры) |
|---|---|---|
| Стек | `S` | `S` push число; `L` dup; `TS` copy n-го; `TL` slide n; `TT` swap |
| Арифметика | `TS` | `SS` add; `ST` sub; `SL` mul; `TS` div; `TT` mod |
| Heap | `TT` | `S` store; `T` retrieve |
| Поток | `L` | `SS` метка; `ST` call; `SL` jump; `TS` jump-if-zero; `TT` jump-if-neg; `TL` return; `LL` конец |
| Ввод/вывод | `TL` | `SS` вывод символа; `ST` вывод числа; `TS` чтение символа; `TT` чтение числа |

(`S` = пробел, `T` = таб, `L` = перевод строки.) Каждая инструкция завершается `LF`. Число кодируется знаковым двоичным кодом: `S`=+, `T`=−, затем биты `S`=0/`T`=1 до `LF`.

## Практика: визуализация и интерпретатор

Быстрая визуализация на Python:

```python
data = open('prog.ws', 'rb').read().decode()
vis = data.replace(' ', '.').replace('\t', '→').replace('\n', '¶\n')
print(vis)
```

Для исполнения есть готовые интерпретаторы (официальный на Haskell, реализации на Python/JS). Если интерпретатора нет, свой пишется за ~150 строк: цикл по символам, стек (список), heap (словарь), таблица переходов по префиксам и меткам. При отладке полезно печатать стек после каждой инструкции — так видно, где логика расходится с ожиданием.

Частый сценарий CTF: программа читает флаг со ввода и «проверяет» его арифметикой, печатая «ok» или «no». Тогда не нужно угадывать ввод — достаточно прочитать программу и увидеть сравнение, либо трассировать, какое число она ожидает. Whitespace, будучи стековым, оставляет всю логику в последовательности операций, и её можно прочитать глазами после визуализации.

## Если не сработало

- **Файл выглядит пустым.** Проверь размер (`wc -c`) и байты (`xxd`): возможно, редактор «съел» пробелы или в файле только один тип символов.
- **Интерпретатор выдаёт ошибку синтаксиса.** Где-то в начале есть непечатный символ или BOM; обрежь его, оставив только Space/Tab/LF.
- **Визуализация «поехала».** Разные редакторы по-разному показывают табы; используй явную замену символов, а не отображение.
- **Программа ждёт ввод и «висит».** Whitespace может читать символ/число; подай ввод или найди в коде инструкцию чтения.
- **Вывод — числа, а не текст.** Значит, используется вывод числа (`TL ST`), а не символа; переведи коды в символы через `chr()`.

## Ограничения

Whitespace — эзотерический язык, и его практическая ценность в том, что он тренирует «чтение невидимого»: тот же навык нужен при разборе обфусцированного кода, где полезная нагрузка спрятана среди незначащих символов. Ограничения: программы на Whitespace объёмны и медленны, инструментов мало, а отладка без визуализации почти невозможна. В CTF это чаще всего одна из стадий цепочки — расшифровать, исполнить, получить следующий артефакт.

## Итоговый чек-лист работы с Whitespace

- Убедись, что файл не пуст: `wc -c`, `xxd`.
- Алфавит ровно из трёх символов: Space (0x20), Tab (0x09), LF (0x0a).
- Прояви код визуализацией: пробел → `.`, таб → `→`, LF → `¶`.
- Первый символ задаёт категорию (стек/арифметика/heap/поток/ввод-вывод).
- Числа — знаковый двоичный код (`S`=+, `T`=−, `S`=0, `T`=1, `LF` — конец).
- Метки — произвольные последовательности Space/Tab.
- Исполни интерпретатором; если его нет — напиши стек + heap за ~150 строк.
- При отладке печатай стек после каждой инструкции.

## Кратко: что запомнить

Whitespace значим только тремя символами — пробелом, табом и переводом строки; первый символ инструкции задаёт категорию, дальше идёт команда. Числа кодируются знаковым двоичным кодом, метки — произвольными последовательностями. Первый шаг любой задачи — визуализация, без неё код «невидим». Навык «читать невидимое» переносится на разбор обфусцированного кода в реальных задачах.

## Практика: трассировка простой программы

Разберём, как исполнить Whitespace-программу вручную. Возьмём программу, которая кладёт на стек число 65 и печатает его как символ (`A`).

Инструкция `push 65`: `[Space][Space]` (стек + push), затем число `65` в знаковом двоичном виде — `Space` (плюс), потом биты `65 = 1000001`: `Tab Space Space Space Space Space Tab`, затем `LF`. Итого последовательность из десяти символов. Далее `output char`: `[Tab][LF][Space][Space]` — категория ввод/вывод, команда «вывести символ». Эти инструкции подряд дадут на выходе `A`.

Трассировка — самый надёжный способ понять программу, когда визуализация уже сделана, но логика неочевидна. Ведём два столбца: «инструкция» и «состояние стека». После `push 65` стек `[65]`; после `output char` стек `[]`, на выходе `A`. Для программ с переходами и heap трассировка становится обязательной: только так видно, почему программа пошла в одну ветку, а не в другую. Если под рукой есть интерпретатор, удобно пропустить программу по шагам (или вставить отладочную печать стека), но понимание кодирования инструкций позволяет прочитать программу и вовсе без него — глазами по визуализированному коду.

## Что мы теперь знаем

- Whitespace использует только пробел, таб и перевод строки.
- Инструкции кодируются последовательностями этих символов (Space=0, Tab=1, LF=конец).
- Язык стековый, с heap и управлением потоком.
- Числа и метки — тоже последовательности Space/Tab.
- Код «проявляют» визуализацией или исполняют интерпретатором.
