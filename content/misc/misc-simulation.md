## Вопрос, с которого всё начинается

Задача описывает игру: на столе куча из 21 камня, двое по очереди берут 1, 2 или 3 камня, выигрывает тот, кто забрал последний. Нужно найти выигрышную стратегию для первого игрока. Красивой формулы сразу не видно. Но игру можно **проиграть** в коде — шаг за шагом, от конца к началу. Это и есть симуляция.

## Наш пример: игра «возьми последний камень»

Правила простые: состояние — сколько камней осталось; ход — взять 1, 2 или 3; проигрывает тот, кто не может сделать ход (забрал последний — выиграл, значит после него осталось 0 и соперник проиграл).

Первый шаг любой симуляции — определить **состояние** и **переходы**. Здесь состояние — число камней `n`, а переходы — уменьшение на 1, 2 или 3. Позиция выигрышна, если существует ход, ведущий в проигрышную позицию соперника.

## Шаг 1: поиск с мемоизацией

Переберём позиции рекурсивно. Чтобы не считать одно и то же многократно, используем **мемоизацию** — сохранение уже посчитанных результатов:

```python
from functools import lru_cache

@lru_cache(None)
def win(n):
    return any(not win(n - take) for take in (1, 2, 3) if n - take >= 0)

print([n for n in range(22) if win(n)])
```

`@lru_cache` запоминает результат для каждого `n`, поэтому каждая позиция считается один раз. Запускаем:

```
[1, 2, 3, 5, 6, 7, 9, 10, 11, 13, 14, 15, 17, 18, 19, 21]
```

Смотрим на проигрышные позиции (те, что не попали в список): 0, 4, 8, 12, 16, 20 — все **кратные четырём**. Отсюда стратегия: первый игрок берёт 1 камень (оставляет 20), а дальше дополняет ход соперника до 4. Симуляция дала ответ, который глазами не был очевиден.

## Шаг 2: дискретно-событийная симуляция

Не все процессы сводятся к игре. Если задача описывает **очередь** (клиенты приходят, обслуживаются, ждут), её моделируют через приоритетную очередь по времени события:

```python
import heapq

def simulate(events):
    now, q = 0, [(0, "start")]
    while q:
        t, ev = heapq.heappop(q)
        now = t
        for (dt, nxt) in transitions(ev):
            heapq.heappush(q, (now + dt, nxt))
    return now
```

`heapq` — приоритетная очередь: `heappop` всегда достаёт событие с наименьшим временем. Так модель «перескакивает» от события к событию, не тратя шаги на пустое время. Это стандартный приём для систем с ожиданием и переполнением.

## Шаг 3: Монте-Карло — когда формула сложна

Если процесс случайный и точную вероятность вывести трудно, её **оценивают испытаниями**. Метод называют **Монте-Карло**: много раз проигрываем случайный сценарий и считаем долю успехов.

```python
import random

def return_prob(n, trials=200000):
    hits = 0
    for _ in range(trials):
        x = y = 0
        for _ in range(n):
            dx, dy = random.choice([(1,0),(-1,0),(0,1),(0,-1)])
            x += dx; y += dy
        if (x, y) == (0, 0):
            hits += 1
    return hits / trials

print(return_prob(10))
```

Здесь агент делает 10 случайных шагов по сетке, и мы оцениваем вероятность вернуться в начало. Точность оценки растёт как `1/√N`: чтобы уменьшить ошибку вдвое, нужно вчетверо больше испытаний. Для CTF-задач «угадай вероятность» этого достаточно.

## Шаг 4: клеточные автоматы

Отдельный сюжет — **клеточные автоматы**: состояние это сетка клеток, переход — правило, применяемое ко всем клеткам одновременно. Пример — правило 110:

```python
def rule110(tape, steps):
    for _ in range(steps):
        new = [0]*len(tape)
        for i in range(len(tape)):
            l = tape[i-1] if i > 0 else 0
            c = tape[i]
            r = tape[i+1] if i < len(tape)-1 else 0
            idx = (l << 2) | (c << 1) | r
            new[i] = (110 >> idx) & 1
        tape = new
    return tape
```

Три соседние клетки дают индекс 0..7; бит правила 110 по этому индексу определяет новое значение. Если шагов миллионы, прямой прогон не пройдёт — ищите **периодичность** состояния или сводите к быстрому преобразованию.

## Шаг 5: если симуляция «висит»

- **Нет предела шагов.** Добавьте счётчик и остановку после N итераций — иначе цикл не завершится.
- **Нет мемоизации.** Поиск без `lru_cache` взрывается на больших состояниях.
- **Результат не воспроизводится.** Зафиксируйте `random.seed(0)`, иначе прогоны будут разные.
- **Слишком мало испытаний.** В Монте-Карло увеличьте `trials` — оценка станет устойчивой.
- **Нужна скорость.** Переведите горячий цикл на NumPy.

## Шаг 6: симуляция против формулы

Как выбрать подход:

- **есть замкнутая формула** — считайте формулой: быстро и точно;
- **процесс сложный или случайный** — симулируйте (Монте-Карло);
- **нужно точное значение в огромном пространстве** — ищите периодичность или динамическое программирование.

Иногда симуляция даёт **ответ, который затем проверяют формулой** — комбинируйте. Например, Монте-Карло оценивает вероятность, а формула подтверждает порядок величины. В нашем примере с камнями перебор дал проигрышные позиции, а формула «кратные 4» объяснила, почему так.

## Шаг 7: полный прогон

Соберём решение задачи про камни от начала до конца:

1. Формализуем состояние (`n` — число камней) и переходы (`-1`, `-2`, `-3`).
2. Пишем рекурсию `win(n)` и оборачиваем её в `@lru_cache`.
3. Печатаем выигрышные позиции до 21.
4. Замечаем закономерность (проигрышные кратны 4).
5. Формулируем стратегию: первый ход оставляет сопернику кратное четырём число.
6. Проверяем на маленьком частном случае (например, куча из 4 камней — проигрышна).

Шесть шагов — и «непонятная игра» превратилась в проверенное решение. Тот же каркас работает для очередей, вероятностей и автоматов: состояние → переходы → прогон → закономерность → проверка.

## Что мы теперь знаем

По-простому:

1. Симуляция — это «проигрывание» процесса по правилам вместо вывода формулы.
2. Сначала определяют состояние и переходы.
3. Для игр — перебор с мемоизацией (`lru_cache`); в примере проигрышные позиции оказались кратны 4.
4. Для очередей — дискретно-событийная модель через `heapq`.
5. Для вероятностей — Монте-Карло; для автоматов — правило + детект циклов.

## На что смотреть дальше

- **Не определили состояние** — симуляция «плывёт». Сначала формализуйте модель.
- **Мало испытаний** — оценка шумная; увеличьте число прогонов.
- **Забыли про циклы** — добавьте предел шагов и детект повторяющегося состояния.
- **Случайность без seed** — не воспроизведётся; фиксируйте `random.seed`.
- **Сложный процесс** — сравните симуляцию с частным случаем или формулой.
