## Что такое симуляция в задачах

Симуляция — это «проигрывание» процесса по правилам, вместо вывода формулы. Если задача описывает динамику (игра, очередь, физика, случайный процесс), часто проще смоделировать её шаг за шагом и посмотреть результат. В CTF так решают задачи на игры, вероятности, клеточные автоматы и поиск.

## Моделирование состояний

Первый шаг — определить **состояние** и **переходы**. Пример: игра «жизнь» — состояние это сетка клеток, переход — правило рождения/смерти.

```python
def step(grid):
    # клеточный автомат: правило B3/S23
    R, C = len(grid), len(grid[0])
    new = [[0]*C for _ in range(R)]
    for r in range(R):
        for c in range(C):
            n = sum(grid[(r+dr)%R][(c+dc)%C]
                    for dr in (-1,0,1) for dc in (-1,0,1)
                    if (dr,dc) != (0,0))
            new[r][c] = 1 if (grid[r][c] and n in (2,3)) or (not grid[r][c] and n == 3) else 0
    return new
```

## Монте-Карло

Когда точный ответ сложен, его **оценивают случайными испытаниями**. Пример: вероятность выигрыша в игре.

```python
import random
def win_probability(trials=100000):
    wins = 0
    for _ in range(trials):
        if play_random_game():
            wins += 1
    return wins / trials

print(win_probability())
```

Чем больше испытаний, тем точнее оценка (`~1/sqrt(N)`). В CTF это применяют для вероятностных задач и «угадай исход».

## Дискретно-событийная симуляция

Для очередей и систем с событиями используют приоритетную очередь по времени события:

```python
import heapq
def simulate(events):
    now, q = 0, [(0, "start")]
    while q:
        t, ev = heapq.heappop(q)
        now = t
        # обработать ev, при необходимости запланировать новые события
        for (dt, nxt) in transitions(ev):
            heapq.heappush(q, (now + dt, nxt))
    return now
```

## Игровые задачи и поиск

Для игр с полной информацией применяют **minimax** и **альфа-бета**; для игр со скрытой информацией — Монте-Карло tree search (MCTS). В CTF часто достаточно полного перебора с мемоизацией.

```python
from functools import lru_cache
@lru_cache(None)
def win(state):
    if is_terminal(state):
        return is_win(state)
    return any(not win(next_state(state, m)) for m in moves(state))
```

## Разобранный пример

Дано: игра, где игрок и «противник» по очереди берут 1–3 камня из кучи 21; кто возьмёт последний — выиграл. Нужно найти выигрышную стратегию.

```python
from functools import lru_cache
@lru_cache(None)
def win(n):
    return any(not win(n - take) for take in (1, 2, 3) if n - take >= 0)
print([n for n in range(22) if win(n)])   # выигрышные позиции
```

Видно, что проигрышные — кратные 4; отсюда простая стратегия.

## Частые ошибки и подводные камни

- **Не определили состояние.** Без чёткого состояния симуляция «плывёт».
- **Мало испытаний в Монте-Карло.** Оценка шумная.
- **Нет мемоизации.** Поиск без `lru_cache` взрывается.
- **Забыли про циклы.** Симуляция может зациклиться — добавьте предел шагов.
- **Случайность без seed.** Для воспроизводимости фиксируйте `random.seed`.

1. Определите состояние и переходы.
2. Решите: формула, симуляция или поиск.
3. Для вероятностей — Монте-Карло с достаточным числом испытаний.

## Клеточные автоматы и паттерны

Клеточные автоматы (Game of Life, Rule 30/110) — частый сюжет misc. Задача: по начальному состоянию и правилу предсказать состояние через N шагов или найти паттерн.

```python
def rule110(tape, steps):
    for _ in range(steps):
        new = [0]*len(tape)
        for i in range(len(tape)):
            l = tape[i-1] if i > 0 else 0
            c = tape[i]
            r = tape[i+1] if i < len(tape)-1 else 0
            idx = (l << 2) | (c << 1) | r
            new[i] = (110 >> idx) & 1     # бит правила
        tape = new
    return tape
```

Если N огромно, прямой прогон не пройдёт — ищите периодичность (состояние повторяется) или используйте матричное возведение/быстрое преобразование.

## Практика: симуляция очереди

Дискретно-событийная модель очереди: клиенты приходят, обслуживаются, ждут. Цель — найти среднее время ожидания или момент переполнения.

```python
import heapq, random
def queue_sim(arrivals, service, cap):
    q, now, maxq, busy = [], 0, 0, None
    for t in arrivals:
        heapq.heappush(q, t)
    while q:
        t = heapq.heappop(q)
        now = max(now, t)
        if busy is None or busy <= now:
            busy = now + service
        else:
            if len(q) > cap:
                return "overflow", now
        maxq = max(maxq, len(q))
    return maxq, now
```

Такая модель отвечает на вопросы «когда система переполнится», часто встречающиеся в задачах.

## Симуляция против формулы

Выбор подхода:

- **есть замкнутая формула** — считайте формулой (быстро, точно);
- **процесс сложный/случайный** — симулируйте (Монте-Карло);
- **нужно точное значение в огромном пространстве** — ищите периодичность/ДП.

Иногда симуляция даёт **ответ, который нужно затем проверить** формулой — комбинируйте.

## Частые вопросы по симуляции

- **Симуляция «висит»?** Добавьте предел шагов и детект циклов.
- **Результат не воспроизводится?** Зафиксируйте `random.seed`.
- **Нужна скорость?** Переведите горячий цикл на NumPy.
- **Как проверить ответ?** Сверьте с частным случаем или формулой.

## Кейс: симуляция случайного блуждания

Дано: агент делает случайные шаги по сетке, нужно найти вероятность вернуться в начало за N шагов. Точная формула сложна — оцениваем Монте-Карло:

```python
import random
def return_prob(n, trials=200000):
    hits = 0
    for _ in range(trials):
        x = y = 0
        for _ in range(n):
            dx, dy = random.choice([(1,0),(-1,0),(0,1),(0,-1)])
            x += dx; y += dy
        if (x, y) == (0, 0):
            hits += 1
    return hits / trials
print(return_prob(10))
```

С ростом `trials` оценка стабилизируется. В задачах «угадай вероятность» этого достаточно.

## Кейс: автомат и предсказание

Если дана последовательность по правилу, её можно «проиграть» вперёд, но при огромном N — ищите цикл состояний:

```python
seen = {}
state = initial
i = 0
while state not in seen:
    seen[state] = i
    state = step(state)
    i += 1
cycle_start, cycle_len = seen[state], i - seen[state]
# ответ для N: если N < cycle_start -> прогон; иначе сводим к циклу
```

Детект цикла превращает «невозможный» прогон в O(1)-вычисление.

## Итог по симуляции

Симуляция — универсальный инструмент для динамических задач: определите состояние и переходы, выберите подход (формула, Монте-Карло, дискретно-событийная модель, поиск) и обязательно ограничьте число шагов и зафиксируйте seed. Для больших N ищите периодичность. В CTF симуляция часто «обходит» отсутствие красивой формулы и даёт ответ там, где аналитика слишком сложна.
