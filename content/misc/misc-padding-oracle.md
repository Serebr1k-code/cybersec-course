## Вопрос, с которого всё начинается

Сервис выдаёт зашифрованную cookie и честно отвечает разными ошибками: то «неверный формат», то «не удалось расшифровать». Кажется, что ошибки — мелочь. На самом деле по ним можно **полностью восстановить открытый текст**, не зная ключа. Атака называется **padding oracle**. Разберём, как она работает и почему.

## Наш пример: зашифрованная cookie

```
$ curl -s -b 'session=Q0JDQ0JDQ0JDQ0JD...' 'http://vault.ctf/profile'
Error: invalid padding
$ curl -s -b 'session=AAAAQ0JDQ0JD...' 'http://vault.ctf/profile'
Error: decryption failed
```

Два разных сообщения об ошибке — это и есть «оракул»: сервер сам говорит, угадали мы паддинг или нет.

## Шаг 1: как работает CBC

**CBC** (Cipher Block Chaining) — режим блочного шифра. Открытый текст режут на блоки по 16 байт. Каждый блок сначала **XOR**-ят с предыдущим шифртекстом, потом шифруют. Для первого блока роль предыдущего играет **IV** (вектор инициализации).

Ключевое свойство: чтобы расшифровать блок `C[i]`, нужно знать `C[i-1]` — он участвует в XOR. Значит, **подменяя предыдущий блок, мы управляем расшифровкой следующего**.

## Шаг 2: что такое паддинг

Открытый текст должен быть кратен 16 байтам. Если нет — добавляют **паддинг** (PKCS#7): `N` байт, каждый равен `N`. Например, не хватает 3 байт — дописывают `03 03 03`. Если хватает ровно — добавляют целый блок `10 10 ... 10` (16 байт).

Сервер расшифровал — и первым делом проверяет паддинг. Неверный паддинг → ошибка. Именно эта проверка и утекает наружу.

## Шаг 3: превращаем оракул в дешифратор

Хотим узнать последний байт открытого блока. Поставим в конец предыдущего блока подделанный байт `g` и будем перебирать его значение. Расшифрованный последний байт станет `P_last XOR g`. Если он равен `01` — паддинг из одного байта верен, сервер ответит «неверный паддинг» не будет. Значит, `g = P_last XOR 0x01`, и мы вычислили `P_last`!

Затем фиксируем последние два байта как `02 02` и перебираем предпоследний — и так по всему блоку. Для 16 байт это около `16 * 256 = 4096` запросов на блок.

## Шаг 4: идём по блокам

Расшифровав блок `C[i]` (через манипуляции с `C[i-1]`), переходим к предыдущему: для него роль «предыдущего» играет `C[i-2]`, а расшифрованный блок `C[i]` мы уже знаем и можем использовать как IV. Так восстанавливается весь шифртекст — от конца к началу.

## Шаг 5: автоматизация

Руками 4096 запросов не сделаешь. Пишут скрипт (или берут `padbuster`):

```
$ padbuster 'http://vault.ctf/profile' 'Q0JD...' 16 -cookies 'session=Q0JD...'
Block 1: nto{pad
Block 2: d1ng_0r4
Block 3: cl3_4nd_
Block 4: cbc}
```

Скрипт перебирает байты и по разнице ответов восстанавливает открытый текст.

## Полный прогон от начала до конца

```
$ python3 pad_oracle.py --url http://vault.ctf/profile --cookie session
[+] recovered: nto{p4dd1ng_0r4cl3_cbc_4tt4ck}
```

Инструмент сам ходит на сервер, отличает ответы и печатает plaintext.

## Если не сработало

- Режим не CBC (GCM/CTR) — паддинга нет, атака неприменима.
- Один общий ответ на все ошибки — оракула нет, но возможен timing-вариант.
- Данные сжаты — иногда помогает CRIME/BREACH, но это другая техника.
- Есть MAC поверх шифра — атака не пройдёт (правильный порядок: encrypt-then-MAC).

## Что мы теперь знаем

- Padding oracle восстанавливает CBC-plaintext по ошибкам паддинга.
- Управляя предыдущим блоком, мы управляем расшифровкой следующего.
- Атака требует ~4096 запросов на блок и автоматизируется.
- Защита — не показывать разницу ошибок и использовать encrypt-then-MAC.

## Куда дальше

Мы научились расшифровывать CBC без ключа. В следующем уроке — подделка MAC: как из «подписи» на блочном шифре сделать валидную подпись для чужого сообщения. А пока запомни: разница в ошибках = утечка.
