## Вопрос, с которого всё начинается

На CTF есть категория `misc`. Тебе дали файл с именем `mystery` без расширения. Открыть нечем, содержимое непонятное. С чего начать и как не утонуть в переборе?

`misc` (от англ. miscellaneous — «разное») — это категория для задач, которые не влезли в web, pwn, crypto, forensics и остальные. Здесь встречается что угодно: кодировки, эзотерические языки, головоломки, работа с данными. Общее у них одно — **надо методично разобрать неизвестный артефакт**. Этому навыку и посвящён урок.

## Наш пример: файл mystery

Весь урок — на одном объекте, файле `mystery` без расширения. Дальше мы задаём вопросы по очереди, и каждый ответ рождает следующий вопрос. Это и есть метод.

Первый вопрос: **что это вообще за файл?**

## Шаг 1: определяем тип

Команда `file` смотрит на «магические байты» в начале файла и говорит реальный тип, независимо от имени.

```
$ file mystery
mystery: ASCII text, with no line terminators
```

Читаем: это текстовый файл в ASCII, без переводов строки. Значит, это не бинарник и не картинка. Открываем и смотрим.

```
$ cat mystery
ZmxhZ3ttMXNjXzFzX2FiMHV0X3BhdHRlcm5zX2FuZF9jdXJpb3NpdHl9
```

Строка из букв и цифр, заканчивается на `=`, похожа на **Base64**. Но не будем гадать — проверим.

## Шаг 2: ищем зацепки в строках

Утилита `strings` вытаскивает печатные последовательности. Здесь файл маленький, но в больших артефактах это первый шаг:

```
$ strings mystery
ZmxhZ3ttMXNjXzFzX2FiMHV0X3BhdHRlcm5zX2FuZF9jdXJpb3NpdHl9
```

Ничего, кроме нашей строки. Зато виден алфавит: `A–Z`, `a–z`, `0–9`, и есть `=`. Это признаки Base64.

## Шаг 3: распознаём кодирование

**Base64** — способ представить любые байты только печатными символами. Работает так: каждые 3 байта (24 бита) делят на 4 группы по 6 бит и каждой группе сопоставляют символ из алфавита из 64 знаков. Поэтому длина результата всегда кратна 4, а в конце бывают символы `=` — заполнители.

Как отличить Base64 от других кодировок:

| Признак | Base64 | Base32 | Hex |
|---------|--------|--------|-----|
| Алфавит | A–Z a–z 0–9 + / | A–Z 2–7 | 0–9 a–f |
| Заполнитель | `=` | `=` | нет |
| Длина | кратна 4 | кратна 8 | чётная |

Наша строка состоит только из `A–Z a–z 0–9` и заканчивается на `=`. Это Base64.

## Шаг 4: декодируем

```
$ echo 'ZmxhZ3ttMXNjXzFzX2FiMHV0X3BhdHRlcm5zX2FuZF9jdXJpb3NpdHl9' | base64 -d
flag{m1sc_1s_ab0ut_patterns_and_curiosity}
```

Флаг. Задача решена. Обрати внимание: мы не подбирали и не гадали — мы **опознали паттерн** и применили к нему известный инструмент.

Именно так работает большинство misc-задач: найти знакомый признак (кодировку, формат, структуру) и применить стандартный приём.

## Шаг 5: универсальный чек-лист

Когда артефакт незнакомый, иди по списку, пока не поймаешь зацепку:

1. **Тип файла:** `file`, `xxd | head` (первые байты).
2. **Строки:** `strings`, `grep` по ключевым словам (`flag`, `key`, `pass`).
3. **Кодировки:** Base64/32/85, hex, URL, ROT13, двоичный.
4. **Метаданные:** `exiftool`, `pdfinfo`, свойства документа.
5. **Скрытые данные:** `binwalk`, `zsteg`, `steghide` (см. Stego).
6. **Архивы:** вложенные ZIP/RAR (иногда с паролем).
7. **Изображения/аудио:** открыть глазами, посмотреть спектр.

Этот список покрывает большинство задач категории.

## Из чего состоит misc

Категория `misc` на разных CTF включает:

- **Кодировки и преобразования:** Base64/32/85, hex, URL, ROT, морзе.
- **Эзотерические языки:** Brainfuck, Piet, Malbolge, Shakespeare.
- **Головоломки:** логика, математика, шахматы, пароли.
- **Работа с данными:** архивы, форматы, восстановление.
- **Автоматизация:** скрипты на Python, bash, регулярки.
- **AI/ML:** задачи на машинное обучение и промпт-инъекции.

Навык, который объединяет всё это, — умение быстро классифицировать артефакт и выбрать инструмент.

## Стартовый набор инструментов

Для большинства misc-задач хватит базового набора:

| Инструмент | Зачем |
|------------|-------|
| `file` | определить тип файла |
| `strings` | найти печатные строки |
| `xxd` / `hexdump` | смотреть байты |
| `base64` / `base32` | кодировки |
| `binwalk` | найти вложенные форматы |
| `exiftool` | метаданные |
| Python | любые преобразования и автоматизация |

Python — главный инструмент: почти любую задачу можно решить коротким скриптом.

## Разбираем пример до конца

Вернёмся к нашей задаче и проговорим путь целиком: `file` сказал «ASCII text» → `cat` показал строку → `strings` подтвердил, что других данных нет → алфавит и `=` указали на Base64 → `base64 -d` дал флаг. Пять шагов, ни одного лишнего.

Если бы строка оказалась не Base64, следующий шаг — проверить hex, затем URL-кодирование, затем ROT13. Порядок задаёт чек-лист, а не интуиция. Именно привычка идти по списку и отличает misc-решателя от того, кто перебирает случайные команды.

## Как тренироваться в misc

Лучшая тренировка — решать задачи и записывать приёмы. Начните с кодировок: возьмите любую строку и прогоните её через Base64, hex и ROT13 туда-обратно, пока не начнёте узнавать их с первого взгляда. Затем переходите к эзотерическим языкам: напишите интерпретатор Brainfuck на Python — это одновременно и тренировка, и готовый инструмент.

Заведите личную шпаргалку: команда → что делает → когда применять. Через десяток задач она станет вашим главным инструментом, потому что в misc побеждает не знание конкретной утилиты, а скорость распознавания паттерна.

## Частые ловушки

Новички в misc делают одни и те же ошибки. Первая — перебирать инструменты случайно, вместо того чтобы определить тип файла. Вторая — останавливаться после одного преобразования, хотя данных может быть несколько слоёв. Третья — игнорировать метаданные: имя файла, дату, EXIF, комментарии.

И ещё одна: считать задачу «сложной» и искать хитрость, когда решение лежит на поверхности. В misc самое простое объяснение часто и есть верное.

## Итог: метод важнее инструмента

В misc нет фиксированного набора тем, поэтому единственный устойчивый навык — метод. Определи тип, найди паттерн, примени стандартный приём, проверь результат, зафиксируй. Повторяя этот цикл, вы решаете задачи, которых никогда раньше не видели.

## Что мы теперь знаем

По-простому:

1. `misc` — всё, что не влезло в другие категории; подход один — методичный разбор.
2. Начинаем всегда с `file` и `strings`.
3. Кодировки узнают по алфавиту и длине, а не гадают.
4. Большинство задач решается распознаванием паттерна и стандартным инструментом.
5. Держите под рукой универсальный чек-лист.

## На что смотреть дальше

- **Не перебирайте вслепую.** Сначала определите тип и структуру.
- **Замечайте паттерны.** `=` в конце, алфавит, длина — это подсказки.
- **Пробуйте несколько слоёв.** После декодирования может быть ещё один уровень.
- **Ведите заметки.** Записывайте, что уже пробовали, чтобы не ходить по кругу.

## Куда дальше

В следующем уроке мы заглянем в **модуль «код и данные»**: как работать с текстом и данными скриптами на Python, парсить и преобразовывать артефакты. А пока запомни главное: любой незнакомый файл разбирается по одному чек-листу — тип, строки, кодировки, метаданные.

## Где пригодится

- **CTF (Misc):** задачи на кодировки, головоломки, работу с данными.
- **Forensics:** разбор незнакомых артефактов и форматов.
- **Реальная работа:** умение быстро классифицировать неизвестный файл или дамп.
- **Разработка:** понимание кодировок и форматов данных.
