## Вопрос, с которого всё начинается

Вы уже умеете запускать Python и разбирать артефакты — этот навык мы взяли в `misc-python-ctf`. Теперь представьте: задача даёт не файл, а **живой сервис**. Вы подключаетесь, и он начинает засыпать вас вопросами. Ответите на все — отдаст флаг. Ответите медленно — оборвёт соединение.

Руками такое не решить. Нужен скрипт, который говорит с сервисом вместо вас. Это и есть **programming-задача** (её ещё называют *скриптинг*): дан сервис или данные, требующие автоматической обработки, а ответ надо получить быстрее, чем вручную.

## Наш пример: сервис, который задаёт арифметику

Подключаемся к учебному сервису обычным `nc` (netcat — утилита «соединись с портом и покажи, что там говорят»):

```
$ nc arithmetic.ctf 1337
Welcome to the warmup bot!
Question 1/100: 17 + 25
```

Отвечаем вручную:

```
42
Correct!
Question 2/100: 91 * 3
```

Сто вопросов руками — долго и бессмысленно. Замечаем важное: **у каждой строки строгий формат** `Question N/100: A op B`. Значит, мы можем её распарсить программно. Это первый вопрос, который мы задаём себе при разборе любой programming-задачи: *какой здесь формат входа?*

## Шаг 1: каркас, который просто отвечает

Берём `pwntools` — библиотеку для скриптового общения с сетевыми сервисами (её же используют в pwn-задачах; интерфейс `remote` работает как обычный файл: читаешь строки, пишешь строки).

```python
from pwn import *
import re
context.log_level = 'error'   # не печатать отладку соединения

io = remote('arithmetic.ctf', 1337)
while True:
    line = io.recvline(timeout=5).decode(errors='replace').strip()
    if not line:
        break
    m = re.search(r'(\d+)\s*([+\-*/])\s*(\d+)', line)
    if m:
        a, op, b = int(m.group(1)), m.group(2), int(m.group(3))
        ans = {'+': a+b, '-': a-b, '*': a*b, '/': a//b}[op]
        io.sendline(str(ans).encode())
    elif 'flag' in line.lower():
        print(line)
        break
io.close()
```

Запускаем — и видим, что часть ответов неверна. Значит, пример задал следующий вопрос: *а что, если числа не влезают в обычную арифметику?*

## Шаг 2: большие числа

Сервис подсовывает `pow`-вопросы вида `2 ** 1000000 mod 1000000007`. В Python целые числа — **произвольной точности**: `2**1000000` посчитается честно, но это гигантское число, и `%` по нему займёт заметное время.

Правильный инструмент — встроенная функция `pow` с тремя аргументами. Она возводит в степень **по модулю**, не строя промежуточное гигантское число:

```python
>>> pow(2, 1000000, 1000000007)
305719095
```

Обратите внимание на ловушку: `float` (число с плавающей точкой) точность **теряет**. Если в задаче есть `0.1 + 0.2`, ответ будет `0.30000000000000004`. Поэтому там, где нужна точность — считайте целыми.

## Шаг 3: последовательности

Теперь сервис даёт первые члены ряда и просит продолжить: `1, 4, 9, 16, ?`. Это **полиномиальный ряд** — его члены равны значениям некоторого многочлена от номера. Есть приём: конечные разности. Но проще воспользоваться `sympy` — библиотекой символьной математики:

```python
from sympy import interpolate, symbols
x = symbols('x')
poly = interpolate([(0,1),(1,4),(2,9),(3,16)], x)
print(poly)              # x**2 + 2*x + 1
print(poly.subs(x, 100)) # 10201
```

`interpolate` строит многочлен, проходящий через данные точки. Дальше просто подставляем нужный номер.

## Шаг 4: таймаут — и зачем оптимизировать

Соединение обрывается на середине. Причина — **таймаут раунда**: сервис ждёт ответ ограниченное время, а наша функция интерполяции пересчитывает многочлен заново для каждого вопроса.

Вывод, который надо запомнить: **оптимизируйте только тогда, когда упёрлись в таймаут, и никогда раньше**. Преждевременная оптимизация усложняет код и добавляет багов.

Что помогает, когда таймаут реален:

- предпосчитать ответы один раз до цикла (в нашем случае — построить многочлен один раз, а не в каждом вопросе);
- читать данные потоково, а не грузить файл целиком в память;
- заменять вложенные циклы на `Counter`/`set`/`defaultdict`;
- для сумм диапазонов — **префиксные суммы**: один проход готовит массив, потом сумма любого отрезка берётся за одно действие.

```python
pref = [0]
for v in arr:
    pref.append(pref[-1] + v)
def rng(l, r):        # сумма arr[l:r] за O(1)
    return pref[r] - pref[l]
```

## Шаг 5: отладка солвера — как не гадать

Когда скрипт «не сходится», не переписывайте его вслепую. Соберите две вещи: тестовый прогон и лог сырых данных.

Если к задаче приложен локальный сервер, запускайте его через `process` из pwntools — это тот же интерфейс, что и `remote`, но без сети и без риска забанить себя:

```python
io = process(['./server'])   # тот же API: recvline/sendline
```

Оберните решение в `try/except` и при ошибке печатайте **сырой** ответ сервиса и трассировку:

```python
import traceback
try:
    solve()
except Exception:
    print('RAW:', io.recvrepeat(0.5))
    traceback.print_exc()
```

Эти двадцать строк экономят десятки минут: видно, на каком именно вопросе сервис «не понял» ответ и что он реально прислал.

И проверяйте на маленьком примере, где ответ известен вручную, — только потом гоняйте на полном входе.

## Формат вывода: почему правильный ответ бывает «неверным»

Отдельная частая причина провала — не логика, а формат. Проверяющая система может ожидать точную строку, число, `FLAG{...}` или множество значений. Лишний пробел, перевод строки или слово ломают сравнение.

Правило: сначала выведите «сырой» результат и сверьте с примером из условия. Если ответ — флаг, не добавляйте вокруг него пояснительный текст.

## Что мы теперь знаем

- Programming-задача = сервис или данные + ограничение по времени; решает скрипт, а не руки.
- Первое действие — выписать **формат входа**: файл, stdin или сокет? сколько данных?
- Большие степени — через `pow(a, b, m)`; для точности держитесь целых чисел, не `float`.
- Ряды продолжаем интерполяцией (`sympy.interpolate`) или конечными разностями.
- Оптимизацию подключаем **по факту таймаута**, предпосчёт — самый частый приём.

## На что смотреть дальше

- **Off-by-one** — самая частая причина неверного ответа: проверьте границы диапазонов и индексов.
- **Формат вывода** — часто нужен ровно флаг, без лишнего текста и пробелов. Сначала напечатайте сырой ответ и сверьте с примером.
- **Кодировка файла** — задавайте `errors='replace'`, иначе чтение упадёт на «битом» байте.
- **Рекурсия** — Python падает на глубине ~1000; для графов берите итеративный BFS.
- **Отладка** — при исключении печатайте сырой ответ сервиса (`io.recvrepeat(0.5)`); это экономит десятки минут слепого перебора.
