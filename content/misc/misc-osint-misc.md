## Вопрос, с которого всё начинается

Задача: «Это фото сделано в одном из городов Европы. Найдите город». Файл — `street.jpg`. Ни карты, ни подписи, только изображение. Как из одного снимка вытащить максимум информации?

OSINT (Open Source Intelligence) — это сбор сведений из открытых источников. В misc-задачах он чаще всего узкий: **по артефакту найти информацию** — где сделано, кто автор, чем отредактировано, что ещё связано с этим файлом. Весь урок — на одном фото `street.jpg`.

## Наш пример: фото street.jpg

Первый шаг — **метаданные**. Камеры и редакторы записывают в файл служебную информацию, которую называют **EXIF**. Смотрим её целиком:

```
$ exiftool street.jpg
File Name         : street.jpg
Camera Model Name : NIKON D3500
Serial Number     : 6123457
Software          : GIMP 2.10.34
Create Date       : 2023:08:14 17:30:11
Modify Date       : 2023:08:14 17:30:11
GPS Position      : (не указано)
Comment           : (не указано)
```

Читаем, что даёт каждый пункт:

- **Camera Model Name** — модель камеры;
- **Serial Number** — серийный номер; он уникален и связывает все фото с одного устройства;
- **Software: GIMP** — файл редактировали (GIMP — бесплатный графический редактор);
- **GPS Position** пусто — координаты стёрты при редактировании.

Итог: GPS нет, но есть серийник и след редактора. Значит, идём по содержимому и по «отпечатку» устройства.

## Шаг 1: вытаскиваем текст с картинки (OCR)

На фото есть вывеска, но читать глазами и набирать вручную — долго. Для распознавания текста на изображении есть **OCR** (Optical Character Recognition), инструмент `tesseract`:

```
$ tesseract street.jpg out -l eng+deu
$ cat out.txt
CAFÉ CENTRAL
Wien
```

`-l eng+deu` — распознавать латиницу и немецкий. На вывеске читается «CAFÉ CENTRAL» и «Wien». Это уже гипотеза: город **Вена** (нем. Wien). Но вывеска может быть копией — проверяем независимо.

## Шаг 2: обратный поиск по изображению

**Reverse image search** (обратный поиск) ищет похожие изображения в интернете. Открываем Google/Yandex/Bing Картинки, загружаем `street.jpg`. Результаты показывают тот же ракурс и подписывают место: «Café Central, Herrengasse, Vienna, Austria». Гипотеза подтверждена вторым, независимым источником.

Правило OSINT: **одно совпадение — не доказательство**. Вывеска + результат обратного поиска совпали — можно считать город установленным.

## Шаг 3: время по тени

Иногда в задаче просят не только место, но и время съёмки. Если GPS нет, но известна **широта** места и **направление тени**, время оценивают инструментом `suncalc`. Он по координатам и длине/направлению тени вычисляет положение солнца.

Метод простой: солнце на юге в полдень (для северного полушария), тень указывает на север. По длине тени судят о высоте солнца, а значит — о времени дня. В Вене (48° с. ш.) тень такой длины, как на фото, соответствует примерно 17:00 летом — что совпадает с EXIF-временем `17:30`.

## Шаг 4: связываем файлы по «отпечатку»

Часто в задаче дано несколько файлов, и надо понять, что они от одного источника. Серийный номер камеры в EXIF — уникальный «отпечаток». Сравниваем:

```
$ for f in *.jpg; do echo "== $f"; exiftool -SerialNumber -Model -Artist "$f"; done
== street.jpg
Serial Number     : 6123457
Camera Model Name : NIKON D3500
== park.jpg
Serial Number     : 6123457
Camera Model Name : NIKON D3500
```

Одинаковый серийник `6123457` связывает оба снимка с одной камерой. Аналогично в документах: `Document ID` в PDF и поля `Author`/`Company` в Office связывают файлы с одним автором. Это ключ к задачам «найди, что ещё сделал этот автор».

## Шаг 5: авторы в документах

Для PDF и Office метаданные лежат внутри. У PDF смотрим `pdfinfo` и `exiftool`:

```
$ pdfinfo report.pdf | grep -i author
Author:          Ivan Petrov
```

У DOCX (это ZIP+XML) — распаковываем только нужный файл:

```
$ unzip -p report.docx docProps/core.xml
<dc:creator>Ivan Petrov</dc:creator>
<cp:lastModifiedBy>editor</cp:lastModifiedBy>
```

Поля `dc:creator` и `cp:lastModifiedBy` дают имя автора и того, кто последним правил документ — иногда с названием организации.

## Шаг 6: проверка подлинности изображения

OSINT — это ещё и проверка, не подделано ли изображение. Признаки редактирования:

- **ELA (Error Level Analysis)** — области разного уровня сжатия выделяются на карте; вставки «светятся»;
- **несоответствие теней** — направление тени не совпадает с источником света;
- **метаданные после редактирования** — `Software: Photoshop`, неполный EXIF;
- **клонирование** — повторяющиеся фрагменты (детектится сервисами FotoForensics).

Полный EXIF, включая скрытые группы, покажет:

```
$ exiftool -a -u -g1 suspect.jpg
```

Флаг `-a` — показать все теги, `-u` — в том числе «неизвестные», `-g1` — сгруппировать. Так иногда вскрываются поля, которых нет в обычном выводе.

## Шаг 7: OSINT по домену и людям

OSINT в misc не ограничен картинками. Если в артефакте засветился домен, email или ник, добавляются стандартные приёмы:

- **WHOIS/RDAP** — владелец домена и даты регистрации;
- **DNS-история** — куда домен указывал раньше (`SecurityTrails`, `crt.sh`);
- **reverse WHOIS** — другие домены того же владельца;
- **username enumeration** — `sherlock`, `maigret` по нику;
- **email** — утечки (Have I Been Pwned), Gravatar;
- **архивы** — Wayback Machine для удалённых страниц.

```bash
$ whois example.com | grep -i 'registrant\|creation'
Creation Date: 2019-04-02T10:11:12Z
$ curl -s "https://crt.sh/?q=%25.example.com&output=json" | jq '.[].name_value' | sort -u
"mail.example.com"
"vpn.example.com"
```

Строка `curl ... crt.sh` забирает из журнала сертификатов все поддомены: каждый выпущенный сертификат попадает в публичный лог, и по нему видно имена хостов.

## Шаг 8: метаданные как «отпечаток»

Мы уже связали два фото по серийнику камеры. Тот же принцип работает и для документов: `Document ID` в PDF, поля `Author`/`Company` в Office, `Template` в DOCX — всё это «отпечатки», по которым разные файлы приписываются одному автору. В CTF это ключ к задачам «найди, что ещё сделал этот автор или устройство».

## Кейс: геолокация без GPS

Дано фото без EXIF. Порядок действий:

1. `tesseract photo.jpg out` — вытащить надписи с вывесок и табличек.
2. Обратный поиск по картинке — найти похожие кадры.
3. Сопоставить архитектуру, язык вывесок, номера машин.
4. `suncalc` по теням — оценить время и широту.

Часто достаточно одной вывески, чтобы определить город; флаг в задаче — это название места.

## Кейс: связываем несколько файлов

Дано несколько фото «одного автора». Сравниваем «отпечатки»:

```bash
$ for f in *.jpg; do echo "== $f"; exiftool -SerialNumber -Model -Artist "$f"; done
```

Одинаковый серийник связывает снимки с одной камерой; одинаковый `Artist` — с одним человеком. Аналогично связываются документы по автору. Так из разрозненных файлов собирается один «профиль» — и в нём находится флаг.

## Что мы теперь знаем

По-простому:

1. OSINT в misc начинается с **метаданных** (`exiftool`).
2. Если GPS стёрт — работаем по содержимому: OCR (`tesseract`) и обратный поиск.
3. Время можно оценить по тени (`suncalc`).
4. **Серийник камеры / автор** связывают файлы с одним источником.
5. Любую гипотезу подтверждаем вторым независимым источником.

## На что смотреть дальше

- **Работайте этично.** Только в рамках задачи или легальной программы, без преследования людей.
- **Проверяйте несколько признаков.** Reverse image может дать ложное совпадение.
- **Часовой пояс.** Время съёмки бывает в локальном поясе, а не UTC.
- **Не игнорируйте текст.** OCR часто решает задачу быстрее, чем поиск по картинке.
- **Смотрите скрытые теги.** `exiftool -a -u -g1` показывает больше обычного вывода.
