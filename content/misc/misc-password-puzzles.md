## Вопрос, с которого всё начинается

В CTF-задаче тебе дали файл `hash.txt` с одной строкой из букв и цифр. Никаких подсказок — что это и как из него достать флаг? На самом деле это **хеш**: результат необратимой функции от пароля. Обратить его «в лоб» нельзя, но можно перебрать кандидатов в пароль и сравнить их хеши с данным. Звучит как «тупой перебор», но на практике всё решает методика: сначала определить тип хеша, потом подобрать правильный инструмент и стратегию.

В этом уроке мы пройдём путь от «непонятной строки» до восстановленного пароля.

## Наш пример: одна строка в hash.txt

```
$ cat hash.txt
5f4dcc3b5aa765d61d8327deb882cf99
```

Тридцать два символа, только `0-9` и `a-f` — это **hex**-запись (шестнадцатеричная). Первый вопрос: что за алгоритм?

## Шаг 1: определить тип хеша по длине

Хеш — это «отпечаток» пароля фиксированной длины. Разные алгоритмы дают разную длину, поэтому по ней можно сузить круг. Ориентиры:

| Длина (hex) | Вероятный тип |
|-------------|---------------|
| 32 | MD5 или NTLM |
| 40 | SHA-1 |
| 64 | SHA-256 |
| 128 | SHA-512 |
| `$2a$...` | bcrypt |
| `$1$` | md5crypt |

У нас 32 символа — значит MD5 или NTLM (у них одинаковая длина, различаются алгоритмом). Инструмент `hashid` подсказывает варианты автоматически:

```
$ hashid 5f4dcc3b5aa765d61d8327deb882cf99
Analyzing '5f4dcc3b5aa765d61d8327deb882cf99'
[+] MD2
[+] MD5
[+] MD4
[+] NTLM
...
```

Точную природу хеша часто подсказывает контекст: в Windows-дампе это NTLM, в веб-базе — MD5.

## Шаг 2: словарная атака

Идея: люди выбирают пароли из ограниченного набора. Возьмём маленький словарь и посчитаем хеш каждого слова — совпадение даст пароль. Покажем на Python (так видно сам механизм):

```python
>>> import hashlib
>>> target = "5f4dcc3b5aa765d61d8327deb882cf99"
>>> for w in ["123456", "password", "admin", "letmein"]:
...     if hashlib.md5(w.encode()).hexdigest() == target:
...         print(target, "->", w)
5f4dcc3b5aa765d61d8327deb882cf99 -> password
```

Пароль — `password`. В реальности перебор делает **hashcat** — он гоняет миллиарды кандидатов в секунду на GPU. Режим задаётся флагом `-m`, атака словарём — `-a 0`:

```
$ hashcat -m 0 -a 0 hash.txt rockyou.txt
5f4dcc3b5aa765d61d8327deb882cf99:password
```

Здесь `-m 0` — режим MD5, `rockyou.txt` — большой словарь утёкших паролей. Результат выводится в виде `<хеш>:<пароль>`. Для NTLM тот же хеш ломался бы с `-m 1000` — вот почему важно правильно определить тип.

## Шаг 3: правила — когда слова не совпадают дословно

Пароли часто «мутируют» слова: `password` → `Password1!`. Чтобы не заводить каждую мутацию отдельным словарём, hashcat применяет **правила** — файлы-трансформации. Например, правило «сделать первую букву заглавной и добавить `123`». Посмотреть, что правило делает, не запуская перебор, можно флагом `--stdout`:

```
$ hashcat --stdout -r best64.rule <<< "password" | head -5
PASSWORD
Password
password1
password12
password123
```

`best64.rule` — встроенный набор из 64 типичных мутаций. Подключаем его к словарной атаке флагом `-r`:

```
$ hashcat -m 0 -a 0 hash.txt rockyou.txt -r best64.rule
```

Правило — это последовательность функций над словом. Основные:

| Функция | Действие |
|---------|----------|
| `l` | всё в нижний регистр |
| `u` | всё в верхний регистр |
| `c` | первая буква заглавная |
| `$X` | добавить символ X в конец |
| `^X` | добавить символ X в начало |
| `sXY` | заменить X на Y |

Строка `c $1 $2 $3` превращает `password` в `Password123`. Комбинируя десятки таких функций, правило покрывает типичные «человеческие» вариации. Для агрессивного покрытия используют `OneRuleToRuleThemAll.rule` — большой набор правил, но он и медленнее.

## Шаг 4: маска — когда шаблон известен

Если известно, что пароль — например, четыре цифры, незачем гонять словарь. **Маска** описывает шаблон: `?d` — цифра, `?l` — строчная буква, `?u` — заглавная, `?s` — спецсимвол, `?a` — любой. Атака маской — `-a 3`:

```
$ hashcat -m 0 -a 3 hash.txt '?d?d?d?d'
```

Маска `?u?l?l?l?l?d?d` — пароль вида «Заглавная, четыре строчных, две цифры» (как `Hello12`). Если длина неизвестна, добавляют `--increment`: hashcat пробует сначала длину 1, потом 2 и так далее.

Правило выбора простое: сначала словарь + правила (дешево и покрывает большинство), и только потом маска по уточнённому шаблону.

## Шаг 5: архивы и документы

Часто паролем защищён не хеш, а ZIP, RAR или PDF. Напрямую hashcat их не ест — сначала извлекают хеш из файла утилитами вида `*2john`:

```
$ zip2john secret.zip > zip.hash
$ john zip.hash --wordlist=rockyou.txt
```

`zip2john` читает структуру архива и выдаёт строку, которую понимает John the Ripper. Аналогично работают `rar2john`, `pdf2john`, `office2john`, `ssh2john`, `keepass2john`. Для 7z есть `7z2hashcat` (режим hashcat `-m 11600`).

Отдельный случай — архив с **ZipCrypto**-шифрованием, пароль которого неизвестен, но внутри лежит файл с предсказуемым содержимым (например, картинка PNG). Тогда пароль вообще не нужен: инструмент `bkcrack` по известному открытому тексту восстанавливает ключи и расшифровывает архив.

Второй популярный инструмент — **John the Ripper**. В отличие от hashcat, он сам угадывает тип хеша по формату строки, поэтому удобен, когда возиться с `-m` не хочется:

```
$ john hash.txt --wordlist=rockyou.txt
$ john --show hash.txt
```

Первая команда перебирает слова, вторая — показывает уже найденные пароли (`--show` не пересчитывает, а читает сохранённый файл `john.pot`). John медленнее hashcat на GPU, зато проще в запуске и умеет работать с множеством форматов «из коробки».

## Что мы теперь знаем

1. Хеш — необратимый отпечаток; восстановление идёт перебором кандидатов.
2. Длина hex подсказывает тип: 32 — MD5/NTLM, 40 — SHA-1, 64 — SHA-256.
3. hashcat: `-m` режим, `-a 0` словарь, `-a 3` маска, `-r` правила.
4. `--stdout` показывает мутации правил без запуска перебора.
5. Архивы/документы сначала конвертируют через `*2john`, потом ломают John.
6. Для ZipCrypto с известным plaintext пароль не нужен — `bkcrack`.

## На что смотреть дальше

- **Неверный режим hashcat.** NTLM и MD5 одинаковой длины: разница между `-m 1000` и `-m 0`.
- **Игнорировать соль.** Для bcrypt/md5crypt нужен полный хеш со солью, а не только digest.
- **Сразу большой словарь/маска.** Начни с rockyou + правила, потом уточняй.
- **Путать скорость алгоритмов.** bcrypt намеренно медленный: миллиардов в секунду не будет, важен точный словарь.
- **Не вести заметки.** Фиксируй, какой словарь и правило уже пробовал, чтобы не повторяться.
