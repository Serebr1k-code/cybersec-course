## Вопрос, с которого всё начинается

В задаче дана строка, которая «не читается»: сначала base64, внутри hex, а внутри — XOR с ключом. Раскручивать это вручную, командой за командой, муторно. **CyberChef** — инструмент, где преобразования собираются в цепочку, и результат виден сразу. Как собрать такую цепочку и не запутаться?

## Наш пример: блоб

```
$ cat blob.txt
bnRve2N5YjNyY2gzZl9yM2MxcDN9
```

Строка из букв и цифр с `=` на конце — типичный base64. В CyberChef это разбирается за один блок.

## Шаг 1: что такое CyberChef

CyberChef — браузерное приложение: слева список **операций**, в центре вход и выход, справа — «рецепт». Ты перетаскиваешь операции в рецепт, и они применяются к входу по порядку. Ничего не устанавливается, работает офлайн.

## Шаг 2: операции

Основные операции, которые нужны в CTF:

- `From Base64` / `To Base64` — декодировать/кодировать base64;
- `From Hex` / `To Hex` — hex-преобразование;
- `ROT13` — сдвиг букв;
- `XOR` — исключающее ИЛИ с ключом;
- `Gunzip` / `Unzip` / `From Gzip` — распаковка;
- `URL Decode` — разкодировать проценты.

Каждая операция — «блок» с настройками.

## Шаг 3: рецепт

**Рецепт** — упорядоченный список операций. Порядок критичен: `From Base64` → `From Hex` даст не то же, что `From Hex` → `From Base64`. Это визуальная замена цепочке конвейерных команд в терминале.

## Шаг 4: Magic

Кнопка **Magic** пробует много операций автоматически и предлагает вероятные декодирования. Это спасает, когда неизвестно, что за кодировка. Но Magic не всеведущ: он ранжирует догадки, и лучшую всё равно выбирает человек.

## Шаг 5: параметры операций

У операций есть параметры: у `XOR` — ключ, у `ROT13` — сдвиг, у `From Base64` — алфавит. Ошибка в параметре даёт «мусор» на выходе. Поэтому, если результат нечитаем, первым делом проверяй настройки блока.

## Шаг 6: как перенести в консоль

Рецепт легко воспроизвести командами:

- `From Base64` → `base64 -d`;
- `From Hex` → `xxd -r -p`;
- `XOR` → короткий скрипт на Python;
- `Gunzip` → `gunzip`.

Так ты сохраняешь воспроизводимость: рецепт в CyberChef для разведки, команда в консоли — для скрипта.

## Шаг 7: практический порядок

1. Посмотреть на данные: алфавит, длина, `=` на конце.
2. Попробовать `Magic` — получить догадки.
3. Собрать цепочку вручную, проверяя выход на каждом шаге.
4. Перенести рецепт в консольные команды.
5. Если «мусор» — проверить параметры операций.

## Откуда взялся инструмент

CyberChef появился как внутренний инструмент GCHQ для разбора данных и был открыт. Его идея — «кибер-швейцарский нож»: десятки преобразований в одном окне, без установки и без отправки данных на сервер. Всё считается в браузере, что важно для чувствительных данных.

## Категории операций

Операции сгруппированы: **Data format** (base64, hex, URL), **Encryption** (XOR, AES), **Compression** (gzip, zlib), **Hashing** (MD5, SHA), **Language** (JS/Python-выражения), **Forensics** (разбор форматов). В CTF чаще всего нужны первые три группы. Полезно знать, в какой категории искать нужное преобразование.

## Работа с бинарными данными

CyberChef умеет работать не только с текстом, но и с байтами: вход можно переключить в «raw bytes», и тогда операции применяются к содержимому файла. Это позволяет, например, распаковать gzip прямо из вставленного блоба. Без этого режима нечитаемые байты превратились бы в «мусор» при копировании.

## Автоопределение и его пределы

Кнопка Magic подбирает операции автоматически, но она не всемогуща: при глубокой или нестандартной кодировке она ранжирует догадки и может ошибиться. Правило: Magic — для подсказки, ручная цепочка — для решения. Всегда проверяй выход на каждом шаге, а не полагайся на «зелёный» результат целиком.

## Сохранение и обмен рецептами

Рецепт можно сохранить (кнопка Save) и передать ссылкой или файлом. Это удобно в команде: один нашёл цепочку — остальные воспроизвели. В задачах, где цепочка длинная, записывай рецепт по шагам, чтобы не потерять порядок операций.

## Альтернативы в консоли

Всё, что делает CyberChef, можно повторить командами: `base64 -d`, `xxd -r -p`, `openssl enc`, `gunzip`, `python3 -c`. В скриптах и автоматизации консоль предпочтительнее, а CyberChef — для интерактивной разведки. Комбинация «нашёл рецепт в CyberChef → перенёс в команды» даёт и скорость, и воспроизводимость.

## Типичная CTF-задача

Дан текстовый блоб: base64 от hex от XOR. Порядок: `From Base64` → `From Hex` → `XOR` с ключом. Если ключ неизвестен, `XOR Brute Force` перебирает однобайтовые ключи и показывает читаемые варианты. Такие многослойные «матрёшки» — хлеб misc-задач.

## Частые ошибки и чек-лист

Ошибки: перепутать порядок операций; забыть про raw bytes для бинарных данных; довериться Magic без проверки; потерять параметр (ключ/алфавит). Чек-лист: (1) посмотреть алфавит; (2) попробовать Magic; (3) собрать цепочку вручную; (4) проверить каждый шаг; (5) перенести в команды.

## Что мы теперь знаем

- CyberChef — визуальный конструктор преобразований.
- Операции применяются по порядку; порядок критичен.
- Рецепт = цепочка операций; его можно перенести в команды.
- Magic автоподбирает вероятные декодирования, но требует проверки.
- Параметры операций (ключ, алфавит) — частая причина «мусора».

## Рабочий пример: раскручиваем «матрёшку» в консоли

Соберём типичную многослойную задачу и пройдём её шаг за шагом командами, чтобы увидеть, что именно делает каждый блок рецепта. Исходный блоб — base64, внутри hex, внутри XOR с однобайтовым ключом:

```
$ cat blob.txt
NjQ3ZTY1NzE2OTYyM2UzYjY0Mzk2ZTU1NzgzOTY5M2I3YTM5Nzc=
```

Слой 1 — base64. Смотрим на алфавит: буквы и цифры, есть `=` на конце — характерный признак. Декодируем:

```
$ base64 -d blob.txt; echo
647e657169623e3b64396e557839693b7a3977
```

Получилась строка только из символов `0-9a-f` — значит, это был не конечный результат, а промежуточный слой. Слой 2 — hex. Раскодируем его в байты:

```
$ base64 -d blob.txt | xxd -r -p
d~eqib>;d9nUx9i;z9w
```

Теперь видно: печатные, но «сдвинутые» символы — похоже на XOR. Слой 3 — однобайтовый XOR, ключ неизвестен. Перебираем все 256 значений и печатаем те, что дают печатный результат:

```python
data = bytes.fromhex('647e657169623e3b64396e557839693b7a3977')
for k in range(256):
    out = bytes(b ^ k for b in data)
    if all(32 <= c < 127 for c in out):
        print(hex(k), out.decode())
```

```
0x0  d~eqib>;d9nUx9i;z9w
0x2  f|gsk`<9f;lWz;k9x;u
0x4  `zaumf:?`=jQ|=m?~=s
0x9  mwlx`k72m0g\q0`2s0~
0xa  nto{ch41n3d_r3c1p3}   <- осмысленный формат флага
0xb  ounzbi50o2e^s2b0q2|
...
```

Среди читаемых вариантов ровно один начинается с `nto{` — это ключ `0x0a`, и он даёт флаг. Весь путь — три команды; в CyberChef это те же три блока рецепта `From Base64` → `From Hex` → `XOR (key 0x0a)`. Разница лишь в том, что CyberChef показывает выход после каждого блока сразу, а в консоли вы наращиваете пайп.

## Справочная таблица: операция CyberChef ↔ команда

| Операция CyberChef | Консольный эквивалент |
|---|---|
| From Base64 | `base64 -d` |
| To Base64 | `base64 -w0` |
| From Hex | `xxd -r -p` |
| To Hex | `xxd -p` |
| XOR (однобайтовый) | `python3 -c "..."` или `xortool` |
| XOR Brute Force | `xortool -b -c 20 file` |
| Gunzip / Zlib Inflate | `gunzip` / `python3 -c "import zlib;..."` |
| URL Decode | `python3 -c "import urllib.parse..."` |
| ROT13 | `tr 'A-Za-z' 'N-ZA-Mn-za-m'` |
| MD5 / SHA256 | `md5sum` / `sha256sum` |
| AES Decrypt | `openssl enc -d -aes-256-cbc` |
| Magic | `binwalk` / `file` (частично) |

Это соответствие полезно на две стороны: в CyberChef вы быстро находите нужную операцию по названию, а потом воспроизводите её командой для скрипта. Обратно — зная команду, легко найти одноимённый блок.

## Граничные случаи

**Base64 без паддинга и с URL-алфавитом.** Стандартный `base64 -d` спотыкается на `-` и `_` (URL-safe алфавит) и на отсутствии `=`. В CyberChef у операции есть параметр алфавита — переключите на `URL safe`. В консоли: `tr '_-' '/+' | base64 -d`.

**Лишние символы и переносы.** Если в блоб попали пробелы/переводы строк, декодер вернёт мусор или ошибку. В CyberChef есть операция `Remove whitespace`. В консоли — `tr -d '\n '` перед декодированием.

**Порядок операций.** `From Hex` перед `From Base64` почти всегда даст ошибку (base64-строка не является валидным hex). Если после первого блока выход «не похож на текст», скорее всего порядок перепутан.

**Бинарные данные в браузере.** После распаковки gzip выход — байты, которые в текстовом поле отображаются «кракозябрами». Нужно переключить вход/выход в raw bytes. Иначе копирование испортит данные (непечатные байты потеряются).

**XOR с многобайтовым ключом.** Однобайтовый перебор здесь не поможет — нужен анализ повторяющегося ключа (расстояние Хэмминга, `xortool`). CyberChef-блок `XOR` принимает и многобайтовый ключ, но подобрать его автоматически нельзя.

## Ограничения

1. **Magic не панацея.** Он оценивает «читаемость» эвристикой и на глубоких или нестандартных цепочках ранжирует неверно. Решение всегда собирается вручную.
2. **Параметры не угадываются.** Ключ XOR, алфавит base64, IV у AES — Magic их не знает. Без них результат — мусор, и это не признак «неправильной операции».
3. **Воспроизводимость требует усилий.** Рецепт живой в браузере, но для автоматизации его надо перенести в команды или код. Ссылка-рецепт удобна для обмена, но не для CI.
4. **Нет «умного» перебора цепочек.** CyberChef не ищет комбинацию операций сам; подбор порядка и параметров остаётся за вами.
5. **Чувствительность к деталям.** Один пропущенный байт, не тот алфавит, лишний перевод строки — и цепочка «не работает». Поэтому правило «проверяй выход на каждом шаге» не формальность, а рабочий метод: именно на первом шаге, где выход перестал быть осмысленным, кроется ошибка.

## Рабочий пример: разбираем матрёшку целиком

Возьмём блоб посложнее — base64 от hex от XOR:

```
$ cat blob2.txt
N2Q2NzdjNjg3MDZhNzEyMDYxNzA3YjIwNzU0YzYxMjA3MDIyNjMyMDZl
```

Собираем рецепт `From Base64` → `From Hex` → `XOR` (ключ `0x13`) и проверяем каждый слой отдельно, командой. Первый слой — base64:

```
$ base64 -d blob2.txt
7d677c68706a712061707b20754c6120702263206e
```

На выходе — строка из шестнадцатеричных цифр чётной длины. Второй слой — hex:

```
$ base64 -d blob2.txt | xxd -r -p | xxd
00000000: 7d67 7c68 706a 7120 6170 7b20 754c 6120  }g|hpjq ap{ uLa
00000010: 7022 6320 6e                             p"c n
```

Байты нечитаемы, но структура «осмысленная»: есть пробелы (`0x20`) там, где во флаге стояли `_`. Значит, применён XOR с одним байтом. Третий слой — XOR с ключом `0x13`:

```
$ base64 -d blob2.txt | xxd -r -p | python3 -c \
  "import sys; d=sys.stdin.buffer.read(); print(bytes(b^0x13 for b in d).decode())"
nto{cyb3rch3f_r3c1p3}
```

Каждый шаг проверялся глазами: если бы `From Hex` дал нечётную длину или символы вне `0-9a-f`, слой был бы выбран неверно. Такой пошаговый разбор в CyberChef делается тем же рецептом, но там выход каждого блока виден сразу.

## Таблица соответствий: операция CyberChef ↔ команда

| Операция CyberChef | Консольный эквивалент |
|---|---|
| `From Base64` | `base64 -d` |
| `To Base64` | `base64 -w0` |
| `From Hex` | `xxd -r -p` |
| `To Hex` | `xxd -p` |
| `URL Decode` | `python3 -c 'import urllib.parse,sys;print(urllib.parse.unquote(sys.stdin.read()))'` |
| `Gunzip` | `gunzip` |
| `Zlib Inflate` | `python3 -c 'import zlib,sys;print(zlib.decompress(sys.stdin.buffer.read()))'` |
| `XOR` (один байт) | `python3 -c` с `^` по всем байтам |
| `ROT13` | `tr 'A-Za-z' 'N-ZA-Mn-za-m'` |
| `MD5` / `SHA2` | `md5sum` / `sha256sum` |
| `Strip HTML tags` | `sed 's/<[^>]*>//g'` |

Рецепт из CyberChef переносится в конвейер один-в-один: операции идут слева направо, команды — через `|`. Единственное, что «теряется» при переносе, — автоподбор `Magic`: в консоли его роль играют `file`, `strings` и перебор ключей.

## Ограничения и подводные камни

1. **Magic ошибается на «похожих» данных.** Ранжирование — эвристика; короткая строка может «декодироваться» правдоподобно, но неверно. Доверяй только осмысленному результату.
2. **Порядок не коммутативен.** `From Hex` перед `From Base64` на base64-строке даст мусор — порядок определяется структурой данных, а не удобством.
3. **Потеря байтов при копировании.** Если вход бинарный, вставка через буфер обмена портит данные; включай режим «raw bytes» или загружай файл.
4. **Ложная «распаковка».** Некоторые данные случайно похожи на gzip/zlib (сигнатуры `1f 8b` / `78 9c`) — `Gunzip` даст ошибку или мусор. Проверяй сигнатуру, а не только первый байт.
5. **CyberChef не «решает» за тебя.** Он ускоряет перебор гипотез, но гипотезу формулирует человек. В задачах с ключом без подсказок нужен перебор (`XOR Brute Force`, частотный анализ), а не Magic.
