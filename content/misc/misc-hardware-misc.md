## Что такое hardware в misc

Hardware-задачи в misc — это работа с «сырыми» сигналами: дампами логического анализатора, захватами радио, прошивками. Часто задача даёт файл с временными диаграммами, а нужно декодировать протокол и получить флаг. Полноценный hardware — отдельная категория, здесь же — базовые приёмы.

## Логические уровни и сигналы

Цифровой сигнал — это последовательность уровней 0/1 во времени. Логический анализатор оцифровывает линии и сохраняет переходы. Захват обычно в формате `.sr` (sigrok) или CSV.

```bash
# открыть дамп логического анализатора
pulseview capture.sr
# конвертировать в CSV
sigrok-cli -i capture.sr -O csv > capture.csv
```

## Интерфейсы

| Интерфейс | Линии | Назначение |
|-----------|-------|------------|
| UART | TX, RX | асинхронный последовательный |
| SPI | SCLK, MOSI, MISO, CS | синхронный, ведущий-ведомый |
| I2C | SCL, SDA | шина с адресацией |
| JTAG/SWD | TCK, TMS, TDI, TDO | отладка чипов |
| 1-Wire | DQ | Dallas (iButton, датчики) |

**UART** декодируют по известной скорости (baud). **SPI/I2C** — по тактовому сигналу: данные читаются на фронте/спаде. В sigrok есть готовые декодеры.

```bash
sigrok-cli -i uart.sr -P uart:baudrate=9600:rx=D0 -A uart
```

## Радио (RF, sub-GHz)

Радиозахваты (`.cu8`, `.wav`) содержат IQ-сигналы. Частые устройства: пульты 433/868 МГц, датчики. Инструменты — `rtl_433` (декодер), `Universal Radio Hacker` (U RH), GNU Radio.

```bash
rtl_433 -r capture.cu8
# URH — визуальный анализ модуляции (ASK/OOK/FSK)
```

Задачи: найти модуляцию, синхронизацию, декодировать биты (часто манчестерский код) и собрать сообщение.

## Захват и декодирование

Общий конвейер: **захват → определение параметров → декодирование → извлечение данных**. Для UART — baud и порядок бит; для SPI — режим (CPOL/CPHA); для RF — модуляция и скорость.

## Инструменты

- **sigrok / PulseView** — логический анализ и декодеры.
- **sigrok-cli** — CLI-декодирование.
- **rtl_433** — декодер радиоустройств.
- **Universal Radio Hacker** — анализ RF.
- **GNU Radio** — обработка сигналов.
- **Logic 2 (Saleae)** — коммерческий анализатор.

## Разобранный пример

Дан захват UART с флагом.

```bash
sigrok-cli -i capture.sr -P uart:baudrate=9600:rx=D0 -A uart
```

Вывод:

```
uart-1: RX: FLAG{uart_decoded}
```

Определив baud и линию, декодер сразу выдаёт ASCII-поток.

## Частые ошибки и подводные камни

- **Неверный baud.** Даёт «мусор»; перебирайте типовые значения.
- **Путаница линий.** RX/TX перепутаны — пробуйте обе.
- **Инверсия сигнала.** Некоторые протоколы инвертированы.
- **Неверная модуляция RF.** OOK vs FSK — разные декодеры.
- **Пропуск преамбулы.** Синхронизация важна для декодирования.

## Что дальше / решение

1. Определите тип захвата: логический (`.sr`) или радио (`.cu8`).
2. Для логического — откройте в PulseView, определите интерфейс.
3. Подберите параметры (baud, режим) и примените декодер.
4. Для радио — найдите модуляцию и синхронизацию.
5. Извлеките данные и проверьте формат флага.

## Декодирование кодировок линии

Многие протоколы кодируют биты не напрямую:

- **NRZ** — уровень соответствует биту;
- **Manchester** — переход в середине такта кодирует бит (0/1 по направлению);
- **дифференциальный Manchester** — важен факт перехода, а не уровень.

```python
def decode_manchester(samples):
    bits = []
    for i in range(0, len(samples) - 1, 2):
        a, b = samples[i], samples[i + 1]
        bits.append(1 if a < b else 0)   # пример: 0->1 = 1
    return bits
```

Определив кодировку, вы восстанавливаете поток бит, затем байты и ASCII.

## JTAG/SWD и отладка чипов

**JTAG** и **SWD** — интерфейсы отладки микроконтроллеров. Через них можно читать/писать память, останавливать ядро, дампить прошивку.

```bash
openocd -f interface/ftdi.cfg -f target/stm32f1x.cfg
# в telnet-консоли openocd:
# > dump_image firmware.bin 0x08000000 0x10000
```

Для ARM Cortex-M чаще используют **SWD** (две линии). Если чип защищён (readout protection), защиту иногда снимают массовым стиранием или glitch-атакой.

## Прошивки

Прошивка — это образ памяти устройства. Приёмы анализа:

```bash
binwalk firmware.bin          # сигнатуры и вложенные ФС
binwalk -e firmware.bin       # извлечь
strings -n 8 firmware.bin | grep -i flag
```

Внутри — файловые системы (squashfs, jffs2), скрипты, ключи. Часто флаг или пароль лежит в открытом виде в скрипте или в конфиге.

## Частые вопросы по hardware

- **Не могу определить baud?** Перебирайте 9600/19200/38400/57600/115200.
- **RF-сигнал «шумный»?** Проверьте модуляцию (OOK/FSK) и сдвиг частоты в URH.
- **Прошивка не распаковывается?** Возможно, сжата или зашифрована — ищите загрузчик.
- **Нужен реальный девайс?** Часто в CTF дают дампы; аппаратура не требуется.

## Итог по hardware

Hardware-задачи в misc сводятся к конвейеру: захват → параметры → декодирование → данные. Определите интерфейс (UART/SPI/I2C/RF), подберите параметры (baud, режим, модуляция) и примените декодер. В большинстве CTF реальное железо не нужно — даны дампы. Если «шумно» — проверьте инверсию, синхронизацию и преамбулу. Часто флаг лежит прямо в декодированном ASCII-потоке или в строках прошивки.

## Кейс: декодирование UART

Дано: `capture.sr` — захват логического анализатора с одной линии. Порядок:

```bash
sigrok-cli -i capture.sr -P uart:baudrate=115200:rx=D0 -A uart
```

Если вывод — «мусор», перебираем типичные baud (9600, 19200, 38400, 57600, 115200) и меняем линию (D0/D1). Найдя правильную комбинацию, получаем ASCII-поток, часто с флагом.

## Кейс: декодирование SPI-флеша

Дано: захват SPI (SCLK, MOSI, MISO, CS). Цель — прочитать содержимое флеш-чипа.

```bash
sigrok-cli -i spi.sr -P spi:clk=D0:mosi=D1:miso=D2:cs=D3 -A spi
```

Из потока восстанавливаем команды (`0x03` READ, `0x9F` JEDEC ID) и данные. Для «живого» чипа используют `flashrom` + CH341A:

```bash
flashrom -p ch341a_spi -r firmware.bin
```

## Кейс: радио-пульт

Дано: `signal.cu8`. В Universal Radio Hacker определяем модуляцию (ASK/OOK), находим повторяющийся паттерн и декодируем биты. `rtl_433` может распознать устройство автоматически:

```bash
rtl_433 -r signal.cu8
```

## Итог по hardware в misc

Конвейер один: захват → параметры → декодирование → данные. Определите интерфейс (UART/SPI/I2C/RF), подберите параметры (baud, режим, модуляция, инверсия) и примените декодер. Реальное железо в CTF обычно не нужно — даны дампы. Флаг почти всегда лежит в декодированном потоке или в строках прошивки.

## Частые вопросы по hardware (расширенно)

- **Какой baud перебирать?** 9600, 19200, 38400, 57600, 115200 — по порядку.
- **Что если сигнал инвертирован?** Инвертируйте уровни и повторите декодирование.
- **Как определить модуляцию RF?** В URH визуально: OOK (амплитуда) vs FSK (частота).
- **Как извлечь прошивку с чипа?** SPI-флеш через `flashrom`/CH341A или JTAG/SWD.
- **Нужно ли реальное железо?** В CTF почти всегда даны дампы — достаточно софта.
