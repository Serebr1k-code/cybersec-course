## Вопрос, с которого всё начинается

В CTF дают файл `capture.sr` — «захват» с логического анализатора. Внутри просто последовательность нулей и единиц во времени, никакого текста. В условии сказано: «на одной из линий идёт UART, флаг — в передаче». Как из набора уровней получить читаемую строку? Это класс **hardware-задач в misc**: работа с сырыми сигналами, а не с сетью или вебом.

Разберём декодирование такого захвата целиком.

## Наш пример: захват логического анализатора

**Логический анализатор** — устройство, которое оцифровывает линии (провода) и сохраняет их состояние во времени. На выходе — временная диаграмма уровней 0 и 1. Формат хранения у `sigrok` — `.sr`. Посмотрим на захват:

```bash
$ sigrok-cli -i capture.sr --show
capture.sr
  Channels (1): D0
  Samplerate: 96000 Hz
  Samples: 1810
```

Канал один (`D0`), частота дискретизации 96 кГц, 1810 отсчётов. Теперь надо понять, **что** за протокол на этой линии.

## Шаг 1: определяем интерфейс и параметры

Разные интерфейсы выглядят по-разному:

| Интерфейс | Линии | Назначение |
|-----------|-------|------------|
| UART | TX, RX | асинхронный последовательный |
| SPI | SCLK, MOSI, MISO, CS | синхронный, ведущий-ведомый |
| I2C | SCL, SDA | шина с адресацией |
| JTAG/SWD | TCK, TMS, TDI, TDO | отладка чипов |

У нас одна линия и нет отдельного тактового сигнала — значит, это **UART**: асинхронный протокол, где обе стороны заранее договорились о скорости. Скорость в **бодах** (baud) — число бит в секунду. Типовые значения: 9600, 19200, 38400, 57600, 115200. Параметр `baud` нам и нужен.

## Шаг 2: как устроен кадр UART

UART передаёт каждый байт кадром: **стартовый бит** (0), затем **8 бит данных** (младший бит первым, LSB-first), затем **стоповый бит** (1). Линия в покое держит 1. Получатель ждёт переход 1→0, отсчитывает половину бита до центра старта, затем — по центру каждого бита данных.

Смоделируем это, чтобы понять механику на реальных числах:

```python
def encode(msg, spb=10):          # spb — отсчётов на бит
    line = [1]*spb                # линия в покое
    for ch in msg.encode():
        line += [0]*spb           # стартовый бит
        for i in range(8):
            line += [(ch >> i) & 1]*spb   # данные, LSB первым
        line += [1]*spb           # стоповый бит
    return line

def decode(line, spb=10):
    out, i = bytearray(), 0
    while i + 10*spb <= len(line):
        if line[i] == 0:                       # нашли старт
            base = i + spb + spb//2            # центр бита 0
            b = 0
            for k in range(8):
                b |= (line[base + k*spb] & 1) << k
            out.append(b); i += 10*spb
        else:
            i += 1
    return out.decode(errors='replace')

line = encode("FLAG{uart_decoded}")
print("samples:", len(line))
print("decoded:", decode(line))
```

```
samples: 1810
decoded: FLAG{uart_decoded}
```

Вот и вся суть: зная `spb` (то есть baud и частоту дискретизации) и кадр, мы восстанавливаем байты и ASCII-поток. Обрати внимание на `1810` отсчётов — ровно столько же, сколько в нашем захвате. Значит, `capture.sr` — тот же формат, и декодер `sigrok` справится штатно.

## Шаг 3: декодируем захват штатным инструментом

`sigrok` умеет декодировать протоколы «из коробки». Указываем декодер `uart`, скорость и линию:

```bash
$ sigrok-cli -i capture.sr -P uart:baudrate=9600:rx=D0 -A uart
uart-1: RX: FLAG{uart_decoded}
```

Если вывод — «мусор», перебираем типичные baud (9600, 19200, 38400, 57600, 115200) и меняем линию (D0/D1 — вдруг RX и TX перепутаны). Один из вариантов даст читаемый ASCII. В графическом виде то же самое делают в **PulseView**: открываешь захват, добавляешь декодер и подбираешь параметры мышкой.

## Шаг 4: SPI-флеш — читаем содержимое чипа

Другой частый сюжет: на линиях SPI идёт обмен с флеш-памятью. SPI синхронный: данные читаются по фронту тактового сигнала `SCLK`, а выбор чипа — по `CS`. Декодируем:

```bash
$ sigrok-cli -i spi.sr -P spi:clk=D0:mosi=D1:miso=D2:cs=D3 -A spi
spi-1: MOSI: 03 00 00 00    MISO: ...содержимое флеша...
```

Команда `0x03` — READ, `0x9F` — JEDEC ID. Из потока восстанавливаем содержимое, часто с флагом. Для «живого» чипа флеш снимают программатором CH341A:

```bash
$ flashrom -p ch341a_spi -r firmware.bin
```

## Шаг 5: радио sub-GHz

Если файл — `signal.cu8` или `.wav`, это **IQ-данные** (синфазная и квадратурная составляющие сигнала) с радио. Частые устройства — пульты 433/868 МГц. Сначала определяем модуляцию: **OOK/ASK** (меняется амплитуда) или **FSK** (меняется частота). Инструмент **Universal Radio Hacker** показывает сигнал визуально; `rtl_433` умеет распознавать устройства автоматически:

```bash
$ rtl_433 -r signal.cu8
```

Дальше ищем повторяющийся паттерн (преамбулу), декодируем биты — часто это **манчестерский код**, где переход в середине такта кодирует бит. Собираем биты в байты и получаем сообщение.

## Шаг 6: прошивка и JTAG/SWD

Если дана прошивка (образ памяти устройства), её анализируют `binwalk`:

```bash
$ binwalk firmware.bin
DECIMAL    HEXADECIMAL   DESCRIPTION
0          0x0           Squashfs filesystem, little endian, size: 262144
$ binwalk -e firmware.bin
$ strings -n 8 firmware.bin | grep -i flag
FLAG{firmware_strings}
```

Внутри — файловые системы (squashfs, jffs2), скрипты и ключи; флаг часто лежит в открытом виде в скрипте или конфиге. Для снятия прошивки с живого чипа используют **JTAG/SWD** (интерфейсы отладки микроконтроллеров) через `openocd`: останавливают ядро и дампят память (`dump_image`). Если чип защищён readout protection — иногда защиту снимают массовым стиранием.

## Если не сработало

Аппаратные задачи требуют интерпретации сигналов. Разберём препятствия.

**Декодер не читает захват.** Проверь параметры: скорость (baud), число бит данных, чётность, стоп-биты, инверсию. UART по умолчанию — 8N1, но задача может использовать другое. Прогони несколько вариантов, пока не увидишь читаемый текст.

**Сигнал выглядит шумом.** Возможно, это не UART, а другой протокол (I²C, SPI, 1-Wire) или модуляция. Смотри форму сигнала: два провода с тактовым сигналом — I²C/SPI; один — 1-Wire или UART. Определи по числу каналов и наличию clock.

**SPI-флеш читается, но содержимое нечитаемо.** Флеш может быть сжата (в прошивке — образ ФС) или зашифрована. Признаки сжатия — высокая энтропия, сигнатуры (`gz`, `LZMA`, squashfs). Распакуй, потом ищи строки.

**Радио-сигнал не декодируется.** Нужны частота, модуляция (ASK/OOK, FSK), скорость. Если знаешь протокол (например, пульт), используй готовые декодеры (Universal Radio Hacker, `rtl_433`). Без модуляции — анализируй в спектре.

**JTAG/SWD не подключается.** Проверь распиновку (TCK/TMS/TDI/TDO для JTAG, SWCLK/SWDIO для SWD), питание и защиту (readout protection). Иногда нужен `openocd` с конфигом под конкретный чип.

**Захват неполный.** Логический анализатор имеет ограничение по глубине памяти. Триггерни захват на нужном событии (например, на первом байте), а не пиши всё подряд.

## Частые вопросы

**Логический анализатор и осциллограф — в чём разница?** Анализатор показывает логические уровни (0/1) — удобен для протоколов. Осциллограф показывает аналоговую форму — нужен для оценки качества сигнала и модуляции.

**Что такое UART?** Асинхронный последовательный интерфейс (без общего тактового сигнала). Скорость и формат кадра задаются заранее — отсюда важность параметров.

**Как понять, что перед нами — флеш-чип?** Маркировка на корпусе, 8 ножек, SPI-подключение. Читается напрямую (`flashrom`, `spi-tools`) или через программатор.

**Обязательно ли физическое устройство?** Нет. В CTF часто дают *запись* сигнала (`.sr`, `.logicdata`, `.vcd`) — её декодируют тем же инструментом, что и живой захват.

## Порядок работы с захватом

Сначала определи протокол: число каналов, наличие тактового сигнала, форма уровней. Один канал без clock — вероятно, UART или 1-Wire; два с clock — I²C/SPI. Затем подбери параметры декодирования (скорость, формат кадра, полярность) и прогони несколько вариантов. Читаемый текст или осмысленные байты — признак верных настроек.

Если сигнал модулирован (радио), определи частоту и тип модуляции (ASK/OOK, FSK). Для известных протоколов используй готовые декодеры (`rtl_433`, Universal Radio Hacker). Для флеш-памяти — читай дамп (`flashrom`) и анализируй энтропию: сжатый образ выдаст высокую энтропию и сигнатуры (`gz`, squashfs). И помни: в CTF часто дают запись, а не живое устройство, — инструменты те же.

## Что мы теперь знаем

- **Логический анализатор** оцифровывает линии в последовательность 0/1; формат `sigrok` — `.sr`.
- **UART** — асинхронный, декодируется по известному **baud**; кадр: start, 8 бит (LSB-first), stop.
- `sigrok-cli -P uart:baudrate=...:rx=... -A uart` выдаёт ASCII-поток.
- **SPI/I2C** декодируются по тактовому сигналу; SPI-флеш снимают `flashrom`+CH341A.
- **Радио** (`.cu8`) — IQ-данные; определяем модуляцию (OOK/FSK) и кодировку линии.
- **Прошивки** разбирают `binwalk`/`strings`, снимают через **JTAG/SWD** и `openocd`.

## На что смотреть дальше

Порядок для любого захвата: определи тип (логический `.sr` или радио `.cu8`) → определи интерфейс → подбери параметры (baud, режим SPI, модуляция) → примени декодер. Если «шумно» — проверь инверсию сигнала, синхронизацию и преамбулу. Помни: в CTF реальное железо обычно не нужно — даны дампы. Дальше — `misc-reversing-misc` и `misc-kernel-misc-deep`.
