## Вопрос, с которого всё начинается

Что печатали на принтере и что было в документе? Windows сохраняет задания печати в
**spool**, часто даже после печати. Разберём.

## Наш пример: очередь печати

## Шаг 1: где spool

```
C:\Windows\System32\spool\PRINTERS\
```

Здесь временные файлы заданий: `.SPL` (данные) и `.SHD` (заголовок задания).

## Шаг 2: .SPL и .SHD

- `.SPL` — поток данных для принтера (часто EMF или RAW);
- `.SHD` — метаданные: имя документа, пользователь, принтер.

```
$ strings 00001.SHD | head
Document: secret_report.docx
User: CORP\Ivan
Printer: HP-LaserJet
```

Так узнаёшь, **что** и **кто** печатал.

## Шаг 3: EMF-задания

Если `.SPL` — EMF (Enhanced Metafile), внутри — векторное представление страниц:

```
$ file 00001.SPL
00001.SPL: MS Windows Enhanced Metafile
```

EMF можно открыть/конвертировать и увидеть содержимое документа.

## Шаг 4: восстановление

Задания могут оставаться после печати (особенно если принтер выключен/в очереди). Их
извлекают из образа:

```
$ strings -el 00001.SPL | grep -i 'confidential'
```

RAW-задания (PCL/PostScript) тоже несут текст.

## Шаг 5: что искать

- имя документа и пользователя;
- содержимое (EMF/RAW);
- время печати;
- несколько копий/заданий.

## Шаг 6: журнал печати в Event Log

Помимо spool, Windows логирует печать в журнале `Microsoft-Windows-PrintService/Operational`:

```
$ evtx_dump.py 'Microsoft-Windows-PrintService%4Operational.evtx' | grep -i 'document'
Document 1, secret_report.docx owned by CORP\Ivan was printed on HP-LaserJet
```

Событие 307 фиксирует документ, пользователя и принтер — даже если `.SPL` уже удалён. Это независимый источник, который переживает очистку очереди.

## Шаг 7: формат RAW (PCL/PostScript)

Если `.SPL` в формате RAW, внутри — язык принтера:

```
$ file 00001.SPL
00001.SPL: HP PCL printer data
$ strings 00001.SPL | grep -iE 'confidential|secret'
```

PCL/PostScript содержат текст командами рисования; `strings` часто вытаскивает строки документа.

## Шаг 8: рендер EMF в изображение

EMF можно конвертировать и увидеть страницу:

```
$ libreoffice --headless --convert-to pdf 00001.SPL
```

Или открыть в просмотрщике EMF. Так восстанавливают вид напечатанного документа — иногда это единственная копия.

## Шаг 9: метаданные задания

`.SHD` — бинарный, но содержит структуру с именем документа и пользователем:

```
$ strings -el 00001.SHD
secret_report.docx
CORP\Ivan
```

`-el` читает UTF-16LE — формат строк Windows. Так достаём в том числе кириллицу и пробелы.

## Шаг 10: что искать

- имя документа и пользователя (`.SHD`, Event Log);
- содержимое (`EMF`/`RAW`);
- время печати и число копий;
- принтер и порт;
- остатки в очереди после инцидента.

## Шаг 11: сетевые принтеры и IPP

Принтер в сети слушает 631 (IPP) и 9100 (raw). Задания можно перехватить, если трафик не шифрован:

```
$ tshark -i eth0 -f 'tcp port 9100' -w print.pcap
```

В pcap окажется поток данных задания — часто PostScript/PCL с текстом документа. Это независимый от хоста источник: даже если очистили spool, сетевой дамп сохраняет содержимое.

## Шаг 12: реестр принтеров

Windows хранит конфигурацию принтеров в реестре:

```
HKLM\SYSTEM\CurrentControlSet\Control\Print\Printers
```

Здесь список принтеров, портов и драйверов. Ключ показывает, какие принтеры были подключены и через какие порты — важно, когда физический принтер уже увезли.

## Шаг 13: печать в PDF и «виртуальные» принтеры

Печать «в PDF» создаёт файл, а не бумагу. Такие файлы несут те же метаданные задания, но ещё и полные метаданные PDF (автор, программа). В расследовании виртуальные принтеры — источник документов, которые «не печатали», а сохраняли.

## Шаг 14: практический итог

Порядок разбора печати:

1. проверить spool/PRINTERS (`.SPL`, `.SHD`);
2. выгрузить журнал `PrintService/Operational`;
3. прочитать метаданные задания (документ, пользователь);
4. восстановить содержимое (EMF/RAW);
5. при необходимости перехватить трафик принтера.

Так отвечаем на «что, кто и когда печатал».

## Практика: что печатал подозреваемый

Дана копия диска. Ищем следы печати.

Сначала spool:

```
$ ls -l spool/PRINTERS/
00001.SPL  00001.SHD
```

Читаем заголовок задания:

```
$ strings -el 00001.SHD
contract_final.docx
CORP\Ivan
HP-LaserJet
```

Документ `contract_final.docx`, пользователь Ivan, принтер HP.

Теперь журнал печати (переживает очистку spool):

```
$ evtx_dump.py 'PrintService%4Operational.evtx' | grep -i 'was printed'
Document contract_final.docx owned by CORP\Ivan was printed on HP-LaserJet on 2026-01-14 03:20
```

Время совпадает с инцидентом. Восстанавливаем содержимое из `.SPL`:

```
$ file 00001.SPL
00001.SPL: MS Windows Enhanced Metafile
$ libreoffice --headless --convert-to pdf 00001.SPL
```

Получаем PDF — видим сам документ. Если `.SPL` в RAW-формате, извлекаем текст строками:

```
$ strings 00001.SPL | grep -iE 'confidential|sum|amount'
```

## Что важно

- `.SHD` даёт документ и пользователя (в UTF-16).
- Журнал `PrintService` сохраняет факт печати после чистки spool.
- EMF конвертируется в PDF; RAW читается `strings`.
- Время печати связывает событие с инцидентом.

## Ограничения метода

Печатная форензика полезна, но не всесильна.

**Spool перезаписывается.** Windows хранит задания временно; после успешной печати `.SPL` часто удаляется. Полагаться только на spool нельзя — нужен журнал `PrintService/Operational`, который сохраняет событие дольше.

**RAW-формат бывает закрытым.** Некоторые драйверы пишут проприетарный поток. Тогда `strings` вытащит мало, а рендер невозможен. В таком случае фиксируем метаданные задания (кто, что, когда), даже если содержимое недоступно.

**EMF не всегда полный.** Иногда в EMF только ссылка на шрифты/ресурсы; при конвертации на другой машине вид может отличаться. Рендерь в той же среде, где снимали образ.

**Сетевой перехват требует времени.** Снять трафик можно только пока задание идёт. Для постфактум-анализа остаются spool, журнал и реестр.

**Принтеры-МФУ.** МФУ хранит свои задания на внутреннем диске; при изъятии устройства это отдельный источник. Не ограничивайся хостом — проверь и само устройство.

Вывод: комбинируй хост-артефакты и данные устройства; каждый по отдельности даёт лишь часть картины.

## Что запомнить по печати

Коротко о главном. Печать оставляет два независимых следа: spool-файлы на диске (`.SPL`/`.SHD`) и журнал `PrintService/Operational`. Даже если spool очистили, журнал часто хранит документ, пользователя и время. Метаданные задания (`.SHD`) читаются в UTF-16 через `strings -el` и дают имя файла и владельца. Содержимое восстанавливается из EMF (конвертацией в PDF) или из RAW (через `strings`). Для сетевых принтеров добавляется третий источник — перехваченный трафик на портах 9100/631. Не забудь и реестр принтеров: он показывает подключённые устройства и порты. Комбинируя эти источники, ты отвечаешь на вопрос «кто, что и когда печатал» даже спустя время.

## Что мы теперь знаем

- Задания печати лежат в spool/PRINTERS.
- `.SHD` — метаданные, `.SPL` — данные.
- EMF несёт векторное содержимое.
- Задания могут оставаться после печати.
- Метаданные выдают документ и пользователя.

- Event Log `PrintService/Operational` (307) логирует печать.
- RAW-задания (PCL/PostScript) несут текст.
- EMF конвертируется в PDF/изображение.
- `strings -el` читает UTF-16 строки `.SHD`.
- Spool может пережить печать.

- Сетевой принтер (9100/631) даёт независимый pcap с содержимым.
- Реестр `Print\Printers` хранит принтеры, порты, драйверы.
- Виртуальный PDF-принтер оставляет документы и их метаданные.
- Порядок: spool → Event Log → метаданные → содержимое → трафик.

## Если не сработало

- Spool пуст? Смотри журнал печати (`PrintService` Event Log).
- RAW-формат? Парси PCL/PostScript.
- Нужен рендер? Конвертируй EMF.
