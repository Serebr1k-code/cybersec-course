## Вопрос, с которого всё начинается

Антивирус не находит малварь, а поведение системы странное: какая-то программа «падает»
или запускается не так. Возможно, атакующий перенаправил её запуск через **реестр**, не
трогая сам файл. Такие техники называют **хайджеком загрузки**.

Разберём сквозной пример: найдём в реестре три техники — IFEO, AppInit_DLLs и
AppCertDLLs — и поймём, как каждая уводит запуск на код атакующего.

## Техника 1: Image File Execution Options (IFEO)

**IFEO** — механизм отладки. Для программы можно указать «отладчик», который запустится
вместо неё. Ключ лежит по пути:

```
HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\<program.exe>
```

Значение **`Debugger`** задаёт, что запускать вместо `<program.exe>`. Легитимно это
используют разработчики; злонамеренно — чтобы, например, при запуске
`taskmgr.exe` (диспетчер задач) запустился чужой бинарник, а сам диспетчер не открылся.

Смотрим подозрительный ключ:

```
$ reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\sethc.exe" /v Debugger
    Debugger    REG_SZ    C:\Windows\Temp\svc.exe
```

`sethc.exe` — программа «Залипание клавиш», которая вызывается по Shift×5 **до входа в
систему**. Перенаправление её запуска — классический **backdoor на экране входа**.
Атакующий заменяет её «отладчиком», и тот получает системные права ещё до логина.

## Техника 2: AppInit_DLLs

**AppInit_DLLs** заставляет Windows загружать указанные DLL в **каждый** процесс,
который использует `User32.dll` (а это почти все GUI-программы). Путь:

```
HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows
```

Значения:

- `AppInit_DLLs` — список DLL (через пробел или запятую).
- `LoadAppInit_DLLs` — флаг «включено» (1).

```
$ reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows" /v AppInit_DLLs
    AppInit_DLLs    REG_SZ    C:\Users\Public\svc.dll
$ reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows" /v LoadAppInit_DLLs
    LoadAppInit_DLLs    REG_DWORD    0x1
```

Так **одна DLL** инжектится во все процессы сразу — мощный, но заметный приём. На
современных системах AppInit часто отключён политикой, поэтому если он включён и указывает
на нестандартный путь — это красный флаг.

## Техника 3: AppCertDLLs

**AppCertDLLs** заставляет систему загружать DLL в каждый процесс, который вызывает
функции `CreateProcess`, `CreateProcessAsUser` и т.п. Путь:

```
HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\AppCertDlls
```

```
$ reg query "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\AppCertDlls"
    AppCertDlls    REG_MULTI_SZ    C:\Windows\Temp\appcert.dll
```

Отличие от AppInit: срабатывает не при загрузке GUI, а при **создании процессов**, и
инжектится в них. Поэтому его следы ищут в связке с событиями создания процессов.

## Как это выглядит в анализе

Все три техники объединяет одно: **изменение реестра**, а не файлов. Поэтому их ищут
**офлайн по hive** и **по событиям** Sysmon (тип 12/13 — работа с реестром):

```
<EventID>13</EventID>
<Image>C:\\Windows\\Temp\\dropper.exe</Image>
<TargetObject>HKLM\\SOFTWARE\\Microsoft\\Windows NT\\CurrentVersion\\Image File Execution Options\\sethc.exe\\Debugger</TargetObject>
<Details>C:\\Windows\\Temp\\svc.exe</Details>
```

Событие 13 (SetValue) прямо показывает: процесс `dropper.exe` записал значение
`Debugger`. Это и есть улика закрепления.

## Частые ошибки

- **Искать только файлы.** IFEO/AppInit/AppCert — это реестр; без разбора hive их не
  найти.
- **Путать легитимное и вредоносное.** `Debugger` иногда ставят отладчики; смотреть на
  **путь** — временные каталоги, `Public`, `Temp` подозрительны.
- **Забыть про 32-битную ветвь.** На 64-битной Windows есть `Wow6432Node` — проверять обе.
- **Не сопоставлять с Sysmon.** События 12/13 показывают, **кто** и **когда** сделал
  правку.

## Как эти техники находят в реальном расследовании

Разберём порядок действий аналитика, который подозревает хайджек загрузки. Работа идёт по
**offline-hive**, потому что на живом хосте часть ключей может быть уже удалена.

Сначала подключаем hive и рекурсивно ищем ключевые ветви. Инструмент **RegRipper** имеет
готовые плагины под каждую технику:

```
$ rip.pl -r SOFTWARE -p appinitdlls
Launch AppInit_DLLs = 1
AppInit_DLLs = C:\Users\Public\svc.dll
```

```
$ rip.pl -r SOFTWARE -p ifeo
<...>\sethc.exe  Debugger = C:\Windows\Temp\svc.exe
```

Далее проверяем **AppCertDlls** в hive `SYSTEM`:

```
$ rip.pl -r SYSTEM -p appcertdlls
AppCertDlls = C:\Windows\Temp\appcert.dll
```

Такой набор плагинов за минуты закрывает все три техники. Важно смотреть **обе** ветви —
нативно-64-битную и `Wow6432Node` (32-битные программы).

## Приоритет техник и их заметность

Разные техники дают разный «уровень шума», и это влияет на то, как их искать:

- **IFEO `Debugger`** — точечный: срабатывает только для конкретной программы. Подмена
  `sethc.exe`/`utilman.exe`/`osk.exe` даёт доступ **до логина** — самая опасная форма.
- **AppInit_DLLs** — широкий: одна DLL во всех GUI-процессах. Заметен по всплеску загрузок
  одной и той же DLL (Sysmon Event 7).
- **AppCertDLLs** — инжектится при создании процессов; заметен по загрузкам DLL в процессах
  с разными родителями.

В CTF-задачах чаще всего прячут флаг прямо в **значении** `Debugger` или `AppInit_DLLs`,
поэтому ищут не только путь, но и любые «нештатные» строки в этих ключах.

## Почему хайджек живёт в реестре

Малварь выбирает реестр по нескольким причинам. Во-первых, правка реестра не создаёт нового
файла-исполняемого в привычном месте, поэтому многие антивирусы её пропускают. Во-вторых,
она «встраивается» в доверенный процесс — код исполняется под легитимным бинарником.
В-третьих, некоторые ключи (AppCertDlls) требуют прав администратора, но правка HKCU
доступна обычному пользователю.

Форензик-следствие: **при расследовании персистентности реестр проверяют наравне с файлами
и службами**, а не после них.

## Частые ошибки

- **Смотреть только `Run`-ключи.** IFEO/AppInit/AppCert находятся в других ветвях.
- **Пропускать `Wow6432Node`.** 32-битные правки живут отдельно.
- **Считать любую запись `Debugger` вредоносной.** Легитимные отладчики тоже его ставят —
  важен путь и контекст.
- **Не проверять флаг `LoadAppInit_DLLs`.** Без него `AppInit_DLLs` не работает.

## Шпаргалка команд

```
# RegRipper-плагины
rip.pl -r SOFTWARE -p ifeo
rip.pl -r SOFTWARE -p appinitdlls
rip.pl -r SYSTEM   -p appcertdlls
# Поиск подозрительных путей
strings SOFTWARE | grep -iE 'temp|public|appdata'
# Правки реестра в Sysmon
evtx_dump.py Sysmon.evtx | grep -B2 -A6 'Image File Execution Options'
```

## Что это даёт в отчёте

В отчёте фиксируют: какие программы перехвачены, какой код подставлен, когда и каким
процессом внесена правка. Отдельно отмечают подмену программ экрана входа (`sethc`,
`utilman`) — это критично, потому что даёт доступ до аутентификации.

## Практический сценарий: расследование «сломанного» диспетчера задач

Разберём реальную ситуацию, которая часто встречается при реагировании на инциденты.
Пользователь жалуется, что **диспетчер задач не открывается**: окно мелькает и закрывается,
либо вообще ничего не происходит. Само по себе это не похоже на компрометацию — но именно
так часто проявляет себя IFEO-хайджек.

Начинаем с гипотезы: запуск `taskmgr.exe` подменён. Проверяем соответствующий ключ IFEO.
Если там есть значение `Debugger`, указывающее на файл в `Temp` или `Public`, гипотеза
подтверждается: вместо диспетчера запускается код атакующего, а сам диспетчер «не
появляется».

Дальше важно понять **масштаб**. Проверяем все программы, которые могут быть перехвачены:
`taskmgr.exe`, `sethc.exe`, `utilman.exe`, `osk.exe`, `magnify.exe`, `narrator.exe`. Подмена
последних пяти особенно опасна: они вызываются с **экрана входа** и дают доступ к системе
до аутентификации. Если перехвачена `sethc.exe`, атакующий может нажать Shift пять раз и
получить консоль с правами `SYSTEM` на экране логина.

Затем ищем **источник** правки. В Sysmon событие 13 покажет процесс, который записал
значение `Debugger`, и время. Если этот процесс — загрузчик малвари, мы связываем хайджек с
первоначальным вектором. Если правка сделана из `reg.exe` или PowerShell — ищем
соответствующие журналы (4688/4104), чтобы восстановить команду.

Параллельно проверяем **AppInit_DLLs** и **AppCertDLLs** — часто эти техники используют
вместе. Всплеск загрузки одной DLL во многих процессах (Sysmon 7) укажет на AppInit, а
загрузка DLL при создании процессов — на AppCert.

В завершение восстанавливаем цепочку: как малварь попала на хост, как закрепилась и какой
код исполняет. Практический вывод: **хайджек загрузки часто маскируется под «поломку»**,
поэтому при странном поведении программ первым делом проверяют реестровые ветви IFEO,
AppInit и AppCert. Это простой и быстрый шаг, который часто сразу даёт ответ.

## Связь техник между собой

На практике IFEO, AppInit и AppCert редко встречаются поодиночке. Продвинутая малварь
комбинирует их для избыточности: если администратор удалит одну ветвь, закрепление
восстановится из другой. Поэтому, найдя одну технику, всегда проверяй остальные — это часть
методики, а не «дополнительная» проверка.

Отдельно стоит упомянуть **Silent Process Exit** — ещё одну ветвь IFEO
(`Image File Execution Options\<prog>\GlobalFlag` + `ReportingMode`). Она заставляет систему
запускать заданный код, когда отслеживаемый процесс **завершается**. Техника используется
для перехвата выхода из браузеров и защитных программ. Признак: в ключе IFEO выставлен
`GlobalFlag` и есть подраздел `SilentProcessExit` с путём к монитору. Это ещё один пример
того, почему реестр нужно разбирать **систематически по ветвям**, а не выборочно.

## Итоговая методика проверки

Полный порядок действий при подозрении на хайджек загрузки выглядит так: сначала снять
hive-файлы, затем прогнать RegRipper-плагины `ifeo`, `appinitdlls`, `appcertdlls`, затем
вручную проверить `SilentProcessExit`, после — сопоставить с событиями Sysmon 12/13 и 7.
Результат сводится в таблицу «программа → подставленный код → время → источник». Такой
системный подход гарантирует, что ни одна из ветвей не будет пропущена, и превращает
поиск персистентности из «угадывания» в воспроизводимую процедуру.

## Что мы теперь знаем

- **IFEO** перенаправляет запуск программы через значение `Debugger`; `sethc.exe` — путь
  к backdoor на экране входа.
- **AppInit_DLLs** инжектит DLL во все GUI-процессы; управляется флагом
  `LoadAppInit_DLLs`.
- **AppCertDLLs** инжектит DLL в процессы при их создании.
- Все три — **реестровые** техники; ищутся по hive и событиям Sysmon 12/13.
- Подозрительны нестандартные пути (Temp, Public, Users).

## Куда дальше

Мы разобрали три «реестровые» техники. Дальше возьмём **COM-хайджек** — подмену
зарегистрированного COM-объекта, которая тоже живёт в реестре и загружает чужой код. А
пока главное запомни: **хайджек загрузки живёт в реестре, ищи его по hive и Sysmon 12/13**.

## Где пригодится

- **CTF Forensics:** задачи с hive-файлами и поиском закрепления.
- **DFIR:** обнаружение персистентности без файлов на диске.
- **Threat Hunting:** охота на правки ключей IFEO/AppInit/AppCert.
- **Работа:** реагирование на инциденты, реверс-инжиниринг поведения.
