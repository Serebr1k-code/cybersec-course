Иногда систему нельзя выключить: это критичный сервер, или в памяти ещё живёт вредоносный процесс. Тогда применяют **live-forensics** — сбор данных с работающей системы. Главный принцип — **порядок волатильности**: сначала собирают то, что исчезнет быстрее всего, и только потом то, что живёт долго.

## Порядок волатильности

Классический порядок (от самого недолговечного):

1. **Регистры и кэш CPU** — исчезают мгновенно, на практике почти недоступны.
2. **Память (RAM)** — процессы, соединения, ключи, расшифрованные данные.
3. **Сетевые соединения, ARP, маршруты** — меняются постоянно.
4. **Запущенные процессы и их состояние** — живут минуты-часы.
5. **Временные файлы, swap/pagefile** — могут быть перезаписаны.
6. **Диск, логи, реестр** — сохраняются дольше всего.

Собирая диск первым, вы теряете память; собирая память первой, вы сохраняете максимум. Для CTF правило то же: если задача даёт живой образ, начинайте с памяти.

## Что собирать с живой системы

| Категория | Артефакт | Команда/инструмент |
|-----------|----------|--------------------|
| Память | полный дамп RAM | `winpmem`, `avml`, `LiME`, `dd if=/proc/kcore` |
| Процессы | список, командные строки | `ps`, `tasklist`, `Get-Process` |
| Сеть | соединения, listening | `netstat -anob`, `ss -tunap`, `Get-NetTCPConnection` |
| Пользователи | сессии, логины | `who`, `query user`, `logonsessions` |
| Автозапуск | реестр, задачи | `autorunsc`, `schtasks` |
| Временные | файлы, swap | копирование в изолированный каталог |
| Логи | EVTX, syslog | `wevtutil epl`, копирование `/var/log` |

## Сбор памяти

```bash
# Windows: WinPmem
winpmem_mini_x64.exe memdump.raw
# Windows: DumpIt (простой exe)
DumpIt.exe /O memdump.raw
# Linux: AVML (Microsoft)
avml mem.lime
# Linux: LiME (модуль ядра)
insmod lime.ko "path=/mnt/usb/mem.lime format=lime"
# Триаж-скрипт Windows (Zimmerman)
# KAPE / CyLR собирает артефакты и память
CyLR.exe -od C:\output
```

Память нужно снимать **на изолированный носитель** и считать хеш. После сбора — анализировать в Volatility3 (см. `forensics-volatility-deep`).

## Триаж-наборы

В реальном IR используют автоматизированные коллекторы:

- **KAPE** (Kroll) — модульный сбор артефактов и триаж.
- **CyLR** — быстрый сбор ключевых артефактов Windows.
- **Velociraptor** — агентный сбор и live-hunting в масштабе.
- **UAC** (Unix-like Artifacts Collector) — сбор на Linux/macOS.

```bash
# UAC на Linux
./uac -p ir_triage /tmp/out
# Velociraptor: артефакты через VQL
velociraptor --config server.config.yaml artifacts collect Windows.KapeFiles.Targets
```

Такие наборы уменьшают «ошибку оператора» и фиксируют единый таймлайн.

## Разобранный пример

```bash
$ sudo ./winpmem_mini_x64.exe mem.raw
Driver loaded.
Dumping memory to mem.raw ... done.
$ sha256sum mem.raw
9f2c... mem.raw
$ ps -eo pid,ppid,cmd --sort=-%mem | head
  PID  PPID CMD
 1234     1 /tmp/.hidden/update --daemon
$ ss -tunap | grep 1234
tcp ESTAB 0 0 10.0.0.5:51234 203.0.113.9:443 users:(("update",pid=1234,fd=3))
```

Вывод: подозрительный процесс `update` из `/tmp/.hidden/` держит соединение с внешним адресом. Память уже снята — можно искать инжектированный код и артефакты этого процесса в Volatility.

## Краевые случаи и подводные камни

- **Вы сами меняете систему.** Запуск инструментов создаёт файлы, процессы, записи в реестре. Документируйте, что и когда запускали.
- **Сбор памяти перезаписывает страницы.** Дамп может быть неполным (swap уже вытеснил данные).
- **Антифорензика.** Вредонос может детектировать запуск коллектора и самоуничтожиться.
- **Порядок.** Не начинайте с диска, если память ещё доступна.
- **Хеширование.** Считайте хеш каждого артефакта; фиксируйте в логе.
- **Изоляция вывода.** Не пишите на тот же том — рискуете перезаписать улики.
- **Привилегии.** Многие команды требуют root/Administrator; без них сбор неполон.
- **Сетевой сбор.** Соединения меняются за секунды — фиксируйте время.

## Инструменты и приёмы live-сбора

Набор зависит от ОС и цели. Ниже — рабочие команды.

### Linux

```bash
# Память
sudo avml /evidence/mem.lime
# Процессы с полными командными строками и окружением
ps -eo pid,ppid,user,etime,cmd --forest
for p in /proc/[0-9]*; do tr '\0' ' ' < $p/cmdline; echo " (pid ${p#/proc/})"; done
# Сеть
ss -tunap; ss -lntup; ip neigh; ip route
# Пользователи и сессии
who -a; w; last -a | head -20
# Автозапуск
crontab -l; ls -la /etc/cron.*; systemctl list-units --state=running
# Файлы, изменённые недавно
find / -xdev -mtime -1 -type f 2>/dev/null | head -100
# Логи
cp -a /var/log /evidence/var_log
```

### Windows (PowerShell)

```powershell
# Память (WinPmem/DumpIt)
.\winpmem_mini_x64.exe C:\evidence\mem.raw
# Процессы
Get-CimInstance Win32_Process | Select-Object ProcessId,ParentProcessId,Name,CommandLine | Export-Csv procs.csv
# Сеть
Get-NetTCPConnection | Select-Object LocalAddress,LocalPort,RemoteAddress,RemotePort,State,OwningProcess
# Автозапуск
Get-CimInstance Win32_StartupCommand
Get-ScheduledTask | Where-Object State -ne 'Disabled'
# Пользователи/сессии
query user; Get-LocalUser
# Логи
wevtutil epl Security C:\evidence\security.evtx
# Недавние файлы
Get-ChildItem -Recurse C:\Users -Include *.exe -ErrorAction SilentlyContinue | Sort LastWriteTime -Desc | Select -First 50
```

### Артефакты, которые легко забыть

- **ARP-таблица** (`arp -a`) — соседи по сети на момент сбора.
- **DNS-кэш** (`ipconfig /displaydns`) — недавние домены.
- **Загруженные модули** (`lsmod`, `Get-Process | Select -Expand Modules`).
- **Открытые файлы** (`lsof`).
- **Переменные окружения** процессов.
- **История shell** (`.bash_history`, PSReadLine).
- **Открытые порты и listening-сервисы**.

## Порядок и изоляция

Правило: **собирайте во волатильном порядке и не пишите на скомпрометированный том**. Вывод — на внешний носитель или по сети в изолированное хранилище.

```bash
# Монтирование внешнего носителя только для записи улик
mount /dev/sdc1 /evidence -o rw,noexec,nosuid
# Сбор памяти на него
sudo avml /evidence/mem.lime
# Хеширование
sha256sum /evidence/mem.lime > /evidence/mem.sha256
```

Параллельно фиксируйте метаданные: время (UTC), имя аналитика, версию инструмента.

## Типичные ошибки и как их избежать

- **Запуск «тяжёлых» инструментов до памяти.** Сначала память, потом всё остальное.
- **Сбор на тот же том.** Перезапись улик; используйте внешний носитель.
- **Игнорирование окружения процессов.** Именно там часто лежат C2-адреса и ключи.
- **Отсутствие хешей.** Без них сложно доказать неизменность.
- **Сбор без временных меток.** Таймлайн невозможен.
- **Забыть про DNS/ARP.** Быстро исчезающие, но ценные артефакты.
- **Работа без плана.** Импровизация приводит к пропускам; используйте чек-лист/коллектор.

## Связь с последующим анализом

Live-сбор — не самоцель, а вход для анализа:

- **Дамп памяти** → Volatility3 (`pslist`, `netscan`, `malfind`).
- **Список процессов** → сверка с baseline, поиск LOLBins.
- **Сетевые соединения** → сопоставление с NetFlow/PCAP.
- **EVTX/syslog** → таймлайн (plaso/EvtxECmd).
- **Автозапуск** → поиск персистентности.

Так live-данные складываются в единую картину инцидента.

## Сводный чек-лист live-сбора

1. Можно ли выключить систему? Если да — статический сбор.
2. Снять память первой (WinPmem/avml/LiME).
3. Собрать сеть (ss/netstat, ARP, DNS-кэш).
4. Собрать процессы (полные cmdline, окружение, модули).
5. Собрать пользователей и сессии.
6. Собрать автозапуск (cron, systemd, задачи, реестр Run).
7. Скопировать логи (EVTX, syslog).
8. Хешировать каждый артефакт.
9. Документировать время (UTC), инструменты, аналитика.
10. Передать данные в анализ (Volatility, plaso, timeline).

Порядок нарушать нельзя: сначала волатильное, потом устойчивое. Именно он отличает live-forensics от простого «сбора всего».

## Сбор по сети и изоляция

В управляемой среде полезно собирать данные централизованно, не «бегая» по хостам:

- **Velociraptor** — агентный сбор и live-hunting по всем хостам сразу.
- **Wazuh/OSQuery** — телеметрия и запросы к системам.
- **Netcat/SSH-туннели** — когда агент поставить нельзя.
- **Out-of-band канал** — чтобы не зависеть от скомпрометированной сети.

```bash
# Передача дампа через SSH
ssh user@host 'sudo avml -' | dd of=/evidence/remote_mem.lime
# Или сбор артефактов через Velociraptor artifact
```

При масштабном инциденте (много хостов) ручной сбор невозможен — нужны агенты и центральное хранилище. Это часть подготовки (см. `forensics-ir-nist`).

## Ключевые выводы

- Порядок волатильности — закон live-forensics: память первой.
- Сбор ведут на внешний носитель, с хешами и временными метками.
- Сами инструменты меняют систему — это документируют.
- Артефакты вроде ARP и DNS-кэша исчезают за секунды, но бесценны.
- Живой сбор — вход для анализа (Volatility, plaso, timeline), а не самоцель.

## Мини-чек-лист порядка сбора

1. Память → 2. Сеть (ss, ARP, DNS) → 3. Процессы → 4. Пользователи → 5. Автозапуск → 6. Логи → 7. Диск.

Каждый шаг хешируется и логируется. Нарушение порядка (например, диск первым) теряет волатильные улики безвозвратно.

## Мини-шпаргалка команд сбора

| Артефакт | Команда |
|----------|---------|
| Память | `avml /evidence/mem.lime` |
| Процессы | `ps -eo pid,ppid,cmd` |
| Сеть | `ss -tunap` |
| Сессии | `who -a` |
| Автозапуск | `crontab -l; systemctl list-units` |
| Логи | `cp -a /var/log /evidence/` |

Этот набор покрывает базовый live-триаж на Linux.

## Что дальше / решение

1. Определить, можно ли выключить систему (если да — статический сбор).
2. Собрать память первой.
3. Затем — сеть, процессы, пользователи, автозапуск.
4. В конце — диск и логи.
5. Хешировать всё, документировать порядок.

Дальше — `forensics-ir-nist` (фазы IR) и `forensics-evidence-handling` (обращение с доказательствами).

## Где пригодится

- **CTF:** задачи с живыми системами и дампами памяти.
- **IR:** сбор данных с работающих серверов и рабочих станций.
- **Threat Hunting:** live-hunting через Velociraptor/KAPE.
- **Судебная экспертиза:** обоснованный порядок сбора.
