## Вопрос, с которого всё начинается

На Mac появилось неизвестное приложение. Когда его поставили и что ещё менялось в тот
момент? macOS ведёт подробный журнал установок и базу «квитанций» (receipts). Это
позволяет восстановить всю историю инсталляций.

## Наш пример: подозрительная установка

## Шаг 1: основной журнал установок

```
$ grep -i 'install' /var/log/install.log | tail -5
2026-01-14 03:29:55+00 mac Installer: Package name is SuspiciousApp
2026-01-14 03:29:56+00 mac Installer: Installing at base path /
2026-01-14 03:30:01+00 mac Installer: The install was successful.
```

Здесь видно имя пакета и время. Тот же интервал `03:29–03:30`, что и другие события.

## Шаг 2: квитанции установок

macOS хранит receipts в `/var/db/receipts/`:

```
$ ls /var/db/receipts/ | grep -i suspicious
com.suspicious.app.bom
com.suspicious.app.plist
```

Каждая квитанция — `.bom` (bill of materials, список файлов) и `.plist` (метаданные).
Посмотрим метаданные:

```
$ plutil -p /var/db/receipts/com.suspicious.app.plist | head
{
  "PackageFileName" => "SuspiciousApp.pkg",
  "InstallPrefixPath" => "/",
  "InstallDate" => 2026-01-14 03:29:55 +0000
}
```

## Шаг 3: список файлов пакета

`.bom` — это архив со списком установленных файлов:

```
$ lsbom /var/db/receipts/com.suspicious.app.bom | head
.	.	drwxr-xr-x	root	admin
./Applications/SuspiciousApp.app	...
```

Так узнаёшь **все** файлы, которые принёс пакет, даже если приложение потом удалили.

## Шаг 4: обновления системы

Обновления macOS тоже логируются:

```
$ grep -i 'softwareupdate\|macOS' /var/log/install.log | tail -3
2026-01-14 02:00:00+00 mac softwareupdated: Downloaded macOS update
```

Необычное обновление в нерабочее время — повод проверить.

## Шаг 5: сопоставляем с карантином

Установленный пакет был откуда-то скачан. Связываем с `QuarantineEventsV2`:

```
$ sqlite3 ~/Library/Preferences/com.apple.LaunchServices.QuarantineEventsV2 \
  'SELECT LSQuarantineDataURLString FROM LSQuarantineEvent WHERE LSQuarantineAgentName="Safari";'
https://203.0.113.5/SuspiciousApp.pkg
```

Скачано с `203.0.113.5` в 03:28, установлено в 03:29 — полная цепочка.

## Что мы теперь знаем

- `/var/log/install.log` — журнал установок и обновлений.
- `/var/db/receipts/` хранит `.bom` и `.plist` каждой установки.
- `.bom` перечисляет все файлы пакета.
- `plutil -p` читает метаданные receipt.
- Связка с карантином даёт источник пакета.

## Если не сработало

- Журнал ротирован? Проверь `.gz`-версии.
- Установка вручную (drag&drop .app)? Тогда receipt нет — смотри карантин и `mdls`.
- Нужны удалённые файлы? Восстанавливай из Time Machine.

## Основной журнал установок

macOS ведёт центральный журнал установок `/var/log/install.log`, куда пишут как установщик
системы, так и сторонние `.pkg`:

```
$ grep -iE 'Installed|pkg' /var/log/install.log | tail -20
2026-01-14 03:25:11-03  Installed "Suspicious Tool" (1.0)
2026-01-14 03:25:12-03  PackageKit: ----- End install -----
```

Каждая запись содержит имя пакета, версию и время. Это прямой таймлайн «что устанавливали и
когда». Обрати внимание на установки в нерабочее время или от неизвестных вендоров.

## Квитанции установок: pkgutil

Каждый установленный пакет оставляет **квитанцию** (receipt) в `/var/db/receipts/`:

```
$ pkgutil --pkgs | tail
com.apple.pkg.XProtectPlistConfigData
com.vendor.suspicious-tool
$ ls /var/db/receipts/ | grep suspicious
com.vendor.suspicious-tool.bom
com.vendor.suspicious-tool.plist
```

Файл `.plist` содержит метаданные (версия, дата установки, идентификатор), а `.bom` — список
всех файлов, которые пакет установил. Читаем метаданные:

```
$ pkgutil --pkg-info com.vendor.suspicious-tool
package-id: com.vendor.suspicious-tool
version: 1.0
install-time: 1768360000
```

`install-time` — Unix-время установки, независимое подтверждение из журнала.

## Список файлов пакета

Квитанция `.bom` позволяет восстановить, **какие файлы** положил пакет — даже если часть из
них уже удалена:

```
$ pkgutil --files com.vendor.suspicious-tool
Library/LaunchDaemons/com.vendor.agent.plist
usr/local/bin/agent
Library/Application Support/Vendor/config.json
```

Это ключ к персистентности: если пакет ставит `LaunchDaemon` или `LaunchAgent`, значит
запускается автоматически. Проверяем, остались ли эти файлы:

```
$ ls -la /Library/LaunchDaemons/com.vendor.agent.plist
```

## Обновления системы

Системные обновления логируются отдельно. История — в `/Library/Receipts` и в
`system_profiler`:

```
$ system_profiler SPInstallHistoryDataType | grep -A3 -i 'security'
$ softwareupdate --history | head
```

Обновления важны, потому что показывают **версию ОС** на момент инцидента и наличие
патчей. Если система не обновлялась годами, круг возможных уязвимостей шире.

## Таблица: артефакты установок macOS

| Артефакт | Путь / команда | Что даёт |
|---|---|---|
| Журнал установок | `/var/log/install.log` | что и когда ставили |
| Квитанции | `/var/db/receipts/*.plist` | метаданные пакетов |
| Списки файлов | `pkgutil --files` | файлы пакета |
| История системы | `system_profiler SPInstallHistoryDataType` | обновления ОС |
| История обновлений | `softwareupdate --history` | патчи |
| Запуски | `launchctl list` | загруженные демоны |

## Сопоставление с карантином

Установка из интернета оставляет метку карантина на скачанном `.pkg`/`.dmg`. Соединяем:

```
$ xattr -p com.apple.quarantine /tmp/Suspicious.pkg 2>/dev/null
0083;65a1b2c3;Safari;...
```

Метка показывает, **откуда** пришёл установщик (Safari/Chrome), а `install.log` — когда его
запустили. Вместе они дают цепочку «скачал → установил → файлы на месте».

## Ограничения

`/var/log/install.log` **ротируется** и старые записи теряются — сохраняй копии. Квитанции
остаются, но их можно удалить вручную (`pkgutil --forget`), что типично для анти-форензики.
Пакеты, установленные через Homebrew или копированием в `/Applications`, квитанций **не
оставляют** вовсе — тогда работают только журналы и файловые артефакты. И помни: наличие
квитанции не доказывает, что пакет всё ещё установлен, — файлы могли удалить.

## Если сработало: что фиксировать

Зафиксируй: имя и версию пакета, время установки (из двух источников — журнала и квитанции),
список установленных файлов и наличие автозапуска. Это позволяет отличить легитимную
установку от внедрения и точно указать, что появилось в системе.

## Проверка автозапуска: LaunchAgents и LaunchDaemons

Пакет, устанавливающий автозапуск, — красный флаг. macOS использует два механизма:

- **LaunchDaemons** (`/Library/LaunchDaemons/`) — от root, до входа пользователя;
- **LaunchAgents** (`/Library/LaunchAgents/`, `~/Library/LaunchAgents/`) — от пользователя.

```
$ ls -la /Library/LaunchDaemons/ | grep -v apple
-rw-r--r--  root  wheel  com.vendor.agent.plist
$ plutil -p /Library/LaunchDaemons/com.vendor.agent.plist
{ "ProgramArguments" => ["/usr/local/bin/agent", "--daemon"],
  "RunAtLoad" => 1 }
```

`RunAtLoad = 1` означает запуск при загрузке. Сравни список демонов со списком из квитанций
пакетов: демон без квитанции — вероятное внедрение вручную.

## Сопоставление с историей обновлений

Установка пакета часто следует за обновлением системы. Строим общий таймлайн:

```
$ (grep -iE 'installed' /var/log/install.log; softwareupdate --history) | sort | tail -20
```

Так видно, не пришла ли подозрительная установка «в довесок» к легитимному обновлению — приём
маскировки.

## Проверка подписи пакета

Установщик может быть подписан, а может и нет. Проверяем:

```
$ pkgutil --check-signature /tmp/Suspicious.pkg
Package "Suspicious.pkg":
   Status: no signature
```

Отсутствие подписи у пакета, установленного на управляемой машине, — отклонение от политики.

## Ограничения

Журнал ротируется, квитанции можно удалить, а установки без `.pkg` (drag-and-drop,
`curl | sh`) следов в этих артефактах не оставляют. Тогда работают: список демонов, метка
карантина, история команд оболочки и логи `syspolicyd`. Всегда проверяй несколько источников.

## Если сработало: доказательство установки

Приведи три факта: запись в `install.log` (время), квитанция `pkgutil` (имя и файлы) и
наличие автозапуска (персистентность). Совпадение трёх источников превращает «пакет стоял» в
«пакет был установлен и настроен на автозапуск».

## Не-пакетные установки: что делать

Самый частый способ внедрения в обход журналов установок — копирование готового приложения
в `/Applications` или выполнение скрипта из интернета (`curl ... | sh`). Такие действия не
создают квитанций `pkgutil` и не пишут в `install.log`. Компенсировать это помогают другие
источники: метка карантина на скопированном файле показывает источник загрузки, журнал
`syspolicyd` фиксирует решения Gatekeeper при первом запуске, а история оболочки
(`~/.zsh_history`) хранит сами команды `curl`/`git clone`. Сопоставляя эти три источника со
временем появления файла в `/Applications`, можно восстановить установку, невидимую для
штатных журналов пакетов. Всегда проверяй оба пути — и «правильный» (pkg), и «ручной».

## Проверка даты и целостности квитанции

Квитанции тоже можно подделать: атакующий способен создать фиктивный `.plist` с правдоподобной
датой. Поэтому сверяй `install-time` из квитанции со временем создания самого файла квитанции
на диске (`stat`) и с записью в `install.log`. Расхождение — признак подделки. Для полноты
зафиксируй SHA-256 файлов пакета и самой квитанции: это позволит позже доказать, что улику не
меняли.

## Итог и порядок действий

Полный разбор установок macOS ведут в четыре шага. Сначала читают `/var/log/install.log` и
выделяют все установки за окно инцидента, затем по каждой берут квитанцию `pkgutil` и
выгружают список файлов пакета, после чего проверяют, какие из этих файлов остались на диске
и есть ли среди них автозапуск. Завершают сопоставлением с метками карантина и историей
обновлений системы, чтобы понять источник и контекст. Такой порядок даёт воспроизводимый
результат: не «кажется, что-то ставили», а конкретный пакет с временем, файлами и
персистентностью. Все действия выполняй на копии образа и фиксируй хеши исходных файлов.

## Проверка на живых системах

На работающей машине удобно получить быстрый обзор установок одной командой, не открывая
журнал целиком. `pkgutil --pkgs` перечисляет идентификаторы всех пакетов, а
`pkgutil --pkg-info` по каждому выдаёт версию и время. Сортируя вывод по времени установки,
ты сразу видишь самые свежие пакеты — именно они чаще всего связаны с инцидентом. Дополняй
обзор списком демонов через `launchctl list` и проверкой `/Library/LaunchDaemons`, чтобы
сразу заметить персистентность, добавленную вместе с пакетом. Эти три команды дают быстрый
и воспроизводимый снимок состояния системы.


## Замечание

Проверяй также `/Library/Receipts` — на старых системах квитанции лежали там, и часть истории установок может сохраниться только в этом каталоге.
