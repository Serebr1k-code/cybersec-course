## Вопрос, с которого всё начинается

Тебе дали файл `data.bin` — ни расширения, ни подсказок. `file` говорит «gzip», но при
распаковке получается ещё один контейнер, а внутри — пароль. Как пройти всю «матрёшку»
и достать флаг?

Сжатие и контейнеры — повседневный инструмент атакующих: данные прячут в многослойных
архивах, потоковых форматах без каталога и повреждённых контейнерах. В этом уроке мы
распакуем такую матрёшку целиком.

## Наш пример: data.bin

```bash
$ file data.bin
data.bin: gzip compressed data
```

`file` определяет формат по **сигнатуре** — первым байтам. У gzip это `1F 8B 08`. Смотрим
внутрь, не распаковывая на диск:

```bash
$ zcat data.bin | file -
/dev/stdin: POSIX tar archive
```

`zcat` распаковывает в поток, а `file -` определяет тип уже распакованных данных. Внутри
— **tar** (контейнер без сжатия). Первый слой снят.

## Шаг 1: распаковываем tar

```bash
$ zcat data.bin | tar -xf - -C out/
$ ls out/
payload.7z
```

`tar -xf -` читает архив из stdin (поток из `zcat`) и распаковывает в каталог `out/`.
Внутри — `payload.7z`. Второй слой.

## Шаг 2: смотрим, что в 7z

```bash
$ 7z l out/payload.7z
   ... flag.txt  (Encrypted)
```

`7z l` показывает содержимое архива. Файл `flag.txt` помечен как `Encrypted` — значит,
нужен пароль. Обратите внимание: если бы у архива был **зашифрован заголовок**
(encrypted header), даже список файлов не показался бы без пароля.

## Шаг 3: подбираем пароль офлайн

Пароли 7z подбирают **офлайн** — сначала извлекают хеш, потом ломают его `hashcat`:

```bash
$ 7z2john.pl out/payload.7z > h.txt
$ hashcat -m 11600 h.txt rockyou.txt
$ 7z x out/payload.7z -oout2/ -psecret
$ cat out2/flag.txt
CTF{nested_archives}
```

`7z2john.pl` достаёт хеш из архива, `hashcat -m 11600` подбирает пароль по словарю,
`7z x` распаковывает. Так мы прошли три слоя: gzip → tar → 7z.

## Шаг 4: сигнатуры форматов

Чтобы узнавать форматы по первым байтам, держите таблицу:

| Формат | Расширение | Сигнатура | Утилита |
|--------|-----------|-----------|---------|
| gzip | `.gz` | `1F 8B 08` | `gzip`, `zcat` |
| bzip2 | `.bz2` | `42 5A 68` | `bzip2`, `bzcat` |
| xz | `.xz` | `FD 37 7A 58 5A 00` | `xz` |
| zstd | `.zst` | `28 B5 2F FD` | `zstd` |
| zip | `.zip` | `50 4B 03 04` | `unzip` |
| 7z | `.7z` | `37 7A BC AF 27 1C` | `7z` |
| rar | `.rar` | `52 61 72 21 1A 07` | `unrar` |

```bash
$ xxd -l 8 archive.zst
00000000: 28b5 2ffd ...
```

## Шаг 5: потоковые форматы без каталога

gzip, bzip2, xz и zstd сжимают один поток и **не хранят имена каталогов**. Поэтому:

```bash
$ gzip -dk file.gz      # распаковать, сохранив оригинал (-k!)
$ bzip2 -dk file.bz2
$ xz -dk file.xz
$ zstd -d file.zst -o out
```

Флаг `-k` (keep) обязателен: без него исходный файл удалится. А `tar` — это контейнер,
который лишь **обрамляет** поток, поэтому `tar.gz` = сначала gzip, потом tar.

## Шаг 6: потоки без заголовка и битые архивы

Иногда данные — «сырой» сжатый поток без заголовка (после XOR или внутри другого файла).
Тогда его находят по сигнатуре:

```bash
$ binwalk file.bin            # покажет смещение gzip/xz/zstd
$ dd if=file.bin of=blob.bin bs=1 skip=<offset> status=none
$ zstd -d blob.bin -o out
```

А битые архивы часто ещё спасаемы:

```bash
$ zip -FF broken.zip --out fixed.zip && unzip -o fixed.zip
$ gzip -dc broken.gz > out 2>/dev/null || true
$ tar -xf broken.tar --ignore-zeros -C out/
```

`zip -FF` перестраивает центральный каталог ZIP, `gzip -dc` выдаёт данные до места
повреждения, `tar --ignore-zeros` пропускает битые блоки.

## Вложенность и рекурсивная распаковка

Матрешку удобно проходить автоматически:

```bash
$ binwalk -e -M nested.bin          # распаковать все слои
$ aunpack archive.7z -X out/        # единый интерфейс (atool)
$ find . -name '*.gz' -exec gunzip -k {} \;
```

`binwalk -e -M` сам распакует вложенные слои и спустится в них. Пароль верхнего слоя
часто подходит и к вложенным — применяйте найденный пароль повторно.

## Определяем формат без расширения

```bash
$ file -z mystery.bin      # заглядывает и внутрь сжатого
$ xxd -l 16 mystery.bin    # сигнатура первых байт
$ binwalk mystery.bin      # все встроенные сигнатуры со смещениями
```

| Задача | Команда |
|--------|---------|
| Определить формат | `file -z`, `xxd` |
| gzip | `zcat` / `gzip -dk` |
| xz | `xz -dk` |
| zstd | `zstd -d` |
| tar | `tar -xf` / `-tvf` |
| 7z | `7z x -pPASS` |
| Рекурсивно | `binwalk -e -M` |
| Битый ZIP | `zip -FF` |
| Хеш 7z | `7z2john` + `hashcat -m 11600` |

## 7z и encrypted headers

7z поддерживает AES-256 и опционально шифрование имён файлов (**encrypted header**,
`-mhe=on`). Тогда даже листинг требует пароля:

```bash
$ 7z l -slt archive.7z | grep -i encrypted
$ 7z x archive.7z -oout/ -pPASS
$ 7z x archive.7z -so file.bin > out.bin   # поток в stdout
```

Проверяйте `-slt`: если заголовок зашифрован, вы не увидите даже имён файлов, пока не
подберёте пароль.

## Частые ошибки

- **Забыть `-k`** у gzip/xz — оригинал удалится.
- **Путать `tar.gz` и `gz`** — сначала снимают gzip, потом читают tar.
- **Не проверять encrypted header** 7z — листинг не покажет имена.
- **Считать битый архив мёртвым** — `zip -FF`/`gzip -dc` часто спасают.
- **Онлайн-брут 7z** вместо офлайн (`hashcat -m 11600`).

## Что мы теперь знаем

- Формат определяется по сигнатуре (`file`, `xxd`), а не по расширению.
- Потоковые форматы (gzip/xz/zstd) не хранят каталоги; `tar` их обрамляет.
- `zcat | file -` показывает тип следующего слоя, не распаковывая на диск.
- 7z с паролем ломают офлайн: `7z2john` → `hashcat -m 11600`.
- Битые архивы восстанавливают `zip -FF`, `gzip -dc`, `tar --ignore-zeros`.

## На что смотреть дальше

- **Не забыть `-k`** у gzip/xz — иначе оригинал удалится.
- **Не путать `tar.gz` и `gz`** — сначала снимают gzip, потом читают tar.
- **Проверять encrypted header** 7z — иначе не увидеть даже список файлов.
- **Не считать битый архив мёртвым** — часто он ещё извлекается.

## Куда дальше

Мы прошли вложенные контейнеры. Дальше в категории начинается углубление: файловые
системы по типам, сетевой анализ, стеганография, облака. А пока запомни главное:
**`file` → распаковка → `binwalk` → пароль → повтор** покрывает почти любую матрёшку.

## Где пригодится

- **CTF:** матрёшки из архивов и битые контейнеры.
- **Malware analysis:** распаковка дропперов (nested gzip/cab).
- **Data recovery:** восстановление повреждённых архивов.
- **Linux-администрирование:** понимание форматов пакетов.
- **Криминалистика:** извлечение данных из вложенных контейнеров.
