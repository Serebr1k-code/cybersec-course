## Вопрос, с которого всё начинается

Связь из удалённых мест идёт через спутник (Iridium/Inmarsat/Starlink). Терминал хранит
свой идентификатор и логи. Разберём, какие следы оставляет спутниковая связь.

## Наш пример: спутниковый терминал

## Шаг 1: что это

Спутниковый терминал (SATCOM) — устройство с уникальным идентификатором:

- **IMEI** (у мобильных) или вендорный ID;
- **IMSI/абонентский номер** у провайдера;
- серийник терминала.

Эти ID связывают терминал с аккаунтом и оплатой.

## Шаг 2: локальные следы

Терминал может хранить:

- **конфигурацию** (провайдер, точка доступа);
- **логи подключений** (когда на связи);
- **буфер сообщений** (SMS через спутник).

```
$ strings terminal_firmware.bin | grep -iE 'iridium|inmarsat' | head
```

## Шаг 3: трафик

Спутниковый трафик на земле идёт через **шлюз провайдера**. Там ведётся биллинг и
CDR:

```
2026-01-14 03:20  IMEI=...  bytes=1200  dur=30s
```

CDR — главный источник: кто, когда, сколько. Запрашивается у провайдера.

## Шаг 4: что искать

- **геолокация** (спутник знает терминал);
- **время связи**;
- **объём** (что передавали);
- **адресаты** (SMS/данные).

## Шаг 5: ограничения

- трафик зашифрован/через шлюз;
- доступ к CDR только у провайдера (юридически);
- терминал может не хранить логи;
- антенна/наведение требуют условий.

## Что мы теперь знаем

- Терминал имеет уникальный ID (IMEI/серийник).
- Локально — конфиг и буферы.
- Трафик идёт через шлюз, где есть CDR.
- CDR — главный источник (через провайдера).
- Доступ ограничен юридически.

## Если не сработало

- Нет доступа к провайдеру? Работай с локальным терминалом.
- Нет логов? Смотри приложение/аккаунт.
- Нужна геолокация? Запрашивай у провайдера.

## Что вообще такое спутниковая связь в форензике

SATCOM (satellite communication) используют там, где нет сотовой сети: суда,
самолёты, удалённые объекты, военные. Системы: Iridium, Inmarsat, Starlink,
Globalstar. Для расследования важны три уровня:

- **терминал** (устройство на месте) — конфиг и буферы;
- **шлюз провайдера** (ground station) — биллинг и записи соединений;
- **космический сегмент** — сам спутник (данные почти недоступны).

## Идентификаторы: чем связывают терминал и аккаунт

У каждого терминала есть уникальные идентификаторы:

- **IMEI** — если терминал использует сотовый модуль (гибридные системы);
- **серийный номер** — вендорный ID устройства;
- **абонентский ID провайдера** — логин/номер в системе оператора;
- **SIM/чип** — в Iridium/Inmarsat используются свои смарт-карты.

Комбинация этих ID связывает «железо» с аккаунтом и оплатой. Если известен
один ID, можно запросить у провайдера связанные.

## Работа на примере: локальные следы терминала

Даже без доступа к провайдеру терминал хранит полезное. Извлекаем прошивку
или файловую систему и ищем упоминания сети:

```
$ strings terminal_firmware.bin | grep -iE 'iridium|inmarsat|apn|gateway' | head
provider=IRIDIUM
apn=data.iridium
```

Находим конфигурацию: провайдер, точку доступа, возможно — сохранённые
логины. Дальше ищем буферы сообщений (SMS через спутник) и журналы
подключений:

```
$ strings terminal_firmware.bin | grep -iE 'last_connect|session' | head
```

Терминалы часто хранят только последние сессии — глубокая история у
провайдера.

## CDR: главный источник

**CDR** (Call Detail Record) — запись о сессии: кто, когда, сколько данных.
Для спутника выглядит примерно так:

```
2026-01-14 03:20:11  TERMINAL=3002340...  bytes=1200  dur=30s  dest=+7...
```

Из CDR восстанавливают: время связи, объём, адресатов. Запрашивается у
провайдера по законным основаниям. Именно CDR даёт геолокацию (шлюз знает,
через какую станцию шёл сигнал) и полную историю — то, чего нет локально.

## Трафик и его анализ

Спутниковый трафик на земле сходится в шлюз провайдера, где может
логироваться и анализироваться:

- **метаданные** — всегда (кто/когда/сколько);
- **содержимое** — обычно шифровано end-to-end;
- **агрегация** — видно, общался ли терминал с конкретным адресатом.

Если есть доступ к трафику (например, свой шлюз), можно разбирать протоколы
(DVB-S2, Iridium Burst) специализированными инструментами.

## Ограничения

- **Шифрование** — содержимое недоступно.
- **Правовой доступ** — CDR только через провайдера.
- **Терминал может не вести логов** — экономят флеш.
- **Физика** — антенна требует прямой видимости спутника; данные о наведении
  тоже след.

## Справочная таблица

| Уровень | Что даёт | Доступ |
| --- | --- | --- |
| Терминал | конфиг, буферы, последние сессии | прямой, если есть устройство |
| Шлюз провайдера | CDR, биллинг, геолокация | по запросу/юридически |
| Спутник | параметры канала | практически недоступен |

## Если сработало / если нет

- **Есть терминал** — снимай конфиг и буферы, фиксируй ID.
- **Нужна история** — запрашивай CDR у провайдера.
- **Нужна геолокация** — шлюз даёт станцию/сектор, этого хватает для района.
- **Только «файл-артефакт» без железа** — работай по строкам конфигурации и
  связывай с аккаунтом.

## Геолокация через шлюз: как это работает

Спутниковый терминал связывается с ближайшей наземной станцией (gateway).
Провайдер знает, через какую станцию шёл сеанс, — а у каждой станции есть
координаты. Это даёт **грубую** геолокацию: терминал был в зоне покрытия
этой станции (сотни километров). Точнее — если у терминала есть GPS и он
передавал координаты (например, в телеметрии).

Дополнительно учитывают:

- **угол наведения антенны** (для направленных терминалов) — даёт сектор;
- **время сеанса** — сопоставление с другими событиями;
- **спутник** — для LEO (Starlink/Iridium) видно, с каким спутником была
  связь, что сужает зону.

## Сравнение систем

| Система | Орбита | Особенность для форензики |
| --- | --- | --- |
| Iridium | LEO | голос/SMS, покрытие полюсов, смарт-карты |
| Inmarsat | GEO | фиксированная зона, морская/авиа связь |
| Starlink | LEO | интернет, много спутников, логи в терминале |
| Globalstar | LEO | голос/данные, спасательные службы |

У LEO-систем спутник быстро меняется, поэтому в логах видна последовательность
спутников — это дополнительный признак маршрута.

## Данные в приложении-компаньоне

Терминалы (особенно потребительские, вроде Starlink) управляются
приложением. Оно хранит на телефоне или в облаке:

- историю сеансов и объём трафика;
- настройки сети и SSID;
- журнал событий (перезагрузки, ошибки);
- привязанный аккаунт и платёжные данные.

Если есть телефон владельца, приложение часто даёт больше, чем сам терминал.
Ищи базу приложения и облачный аккаунт.

## Что делать с «файлом-артефактом»

В учебной задаче часто дают не устройство, а файл: дамп прошивки, лог, JSON
конфигурации. Алгоритм:

1. Опознать формат (`file`, `xxd`, `strings`).
2. Извлечь идентификаторы (серийник, IMEI, ID аккаунта).
3. Найти конфигурацию сети (провайдер, точка доступа).
4. Найти временные метки сеансов.
5. Сопоставить ID с аккаунтом/провайдером.
6. Зафиксировать метку/флаг, если задача CTF.

Простой поиск по строкам часто даёт ключевые зацепки:

```
$ strings artifact.bin | grep -iE 'serial|imei|account|session' | head
```

## Практический пример: разбираем конфигурацию

Допустим, есть дамп терминала. Ищем не только строки, но и структуру
конфигурации:

```
$ strings -n 6 artifact.bin | grep -iE 'apn|provider|serial|imei|account' | sort -u | head
account=EXPLORER-9931
apn=data.iridium
provider=IRIDIUM
serial=300234065123450
```

Из этих строк собирается профиль: провайдер, точка доступа, аккаунт,
серийник. Дальше сопоставляем серийник с CDR у провайдера — так терминал
связывается с историей сеансов.

## Ограничения геолокации по спутнику

- **Точность зоны** — станция покрывает большой регион; точность — сотни
  километров.
- **Только сеансы** — если терминал молчал, связи не было, следа нет.
- **Спутник vs терминал** — данные о наведении антенны есть не всегда.
- **LEO-переключения** — для Starlink/Iridium спутники быстро меняются, что
  даёт последовательность, но усложняет привязку.

Поэтому спутниковую геолокацию используют как **подтверждающую**, а не
основную: она хорошо сужает район, но не даёт точку.

## Что запрашивать у провайдера

Для полноты картины у оператора запрашивают:

- CDR за нужный период;
- привязку абонентского ID к аккаунту и владельцу;
- список активных терминалов на аккаунте;
- историю геолокации (через какие станции шли сеансы).

Это юридически оформляется; в отчёте указывай, какие данные получены, а
какие запрошены, но ещё не предоставлены.

## Если сработало / если нет

- **Есть серийник** — связывай с аккаунтом и CDR.
- **Нет устройства, только ID** — работай через провайдера.
- **Нет ни того, ни другого** — зафиксируй факт спутниковой связи как
  гипотезу, без выдуманных координат.

## Справочная таблица: ID и где их искать

| Идентификатор | Что даёт | Где искать |
| --- | --- | --- |
| Серийный номер | связь с аккаунтом | прошивка/конфиг терминала |
| IMEI | устройство (гибрид) | лог модема |
| Абонентский ID | владелец у провайдера | CDR/аккаунт |
| Номер смарт-карты | привязка SIM | слот карты |
| ID спутника | маршрут (LEO) | лог терминала |

Эти поля — «ключи», которыми связывают разрозненные данные в единую картину.

## Куда смотреть в первую очередь

1. **Терминал** — серийник, провайдер, буфер сообщений.
2. **Приложение** — история сеансов, аккаунт, настройки.
3. **Провайдер** — CDR, геолокация, владелец.
4. **Сеть** — если есть свой шлюз, метаданные трафика.

Начинай с того, что доступно прямо сейчас, и параллельно запрашивай
недоступное. Не жди полного набора — фиксируй промежуточные факты.

## Если сработало / если нет

- **Есть серийник и провайдер** — связывай терминал с аккаунтом и запрашивай
  CDR.
- **Только приложение** — тяни историю сеансов и настройки из базы приложения.
- **Ничего не сохранилось** — фиксируй факт спутниковой связи как гипотезу,
  без выдуманных координат.
- **Нужна точная локация** — помни: спутник даёт район, а не точку; точность
  добавляй из других источников.
