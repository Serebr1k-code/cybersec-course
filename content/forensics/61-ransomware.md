## Задача форензики рансомварь

Ransomware шифрует файлы и требует выкуп. Задача DFIR: **идентифицировать** семейство, **восстановить** данные (или хотя бы часть), **доказать** вектор проникновения. Ключ к восстановлению — слабости в схеме шифрования: не всё шифруется полностью, ключи могут остаться в памяти/на диске, часть файлов не затронута.

## Идентификация семейства

- **Расширения зашифрованных файлов** (`.locked`, `.encrypted`, `.crypt`).
- **Note-файл** (`README.txt`, `HOW_TO_DECRYPT`).
- **Строки в бинарнике** (`strings`).
- **YARA-правила** и базы (ID Ransomware, NoMoreRansom).

```bash
strings sample.exe | grep -iE 'ransom|bitcoin|decrypt|\.locked'
# YARA
yara -r rules/ sample.exe
# Онлайн: ID Ransomware (upload sample/note)
```

## Схемы шифрования и их слабости

**Типовая схема:** случайный **симметричный** ключ (AES) на файл/сессию, зашифрованный **асимметричным** (RSA) публичным ключом атакующего. Слабости:

- **Только часть файла шифруется** (первые N байт) — остальное восстановимо из «головы».
- **Слабый RNG** — ключ предсказуем.
- **Ключ остался в памяти** (Volatility).
- **Ключ на диске** (не затёрт).
- **Interleaved/weak mode** — ECB, повтор nonce.
- **Reused keystream** — CTR с reused nonce.

```bash
# Проверить, зашифрован ли файл полностью
xxd encrypted.bin | head
# Если начало зашифровано, а хвост — оригинал: частичное шифрование
```

## Восстановление: источники

- **Теневые копии** (`vssadmin list shadows`, `vssadmin delete shadows` — атакующие удаляют, но не всегда успевают).
- **`$Recycle.Bin`**, **`pagefile.sys`**, **`hiberfil.sys`** — могут содержать фрагменты.
- **Backups** (внешние, облачные).
- **Файлы, открытые в момент шифрования** — могут быть не зашифрованы.
- **`USN Journal`/`MFT`** — следы переименования.
- **Известные ключи** (NoMoreRansom для старых семейств).

```bash
# Теневые копии
vssadmin list shadows
# Восстановление
mklink /d C:\shadow \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\
```

## Восстановление ключа из памяти

```bash
# Volatility: дамп процесса ransomware
vol -f mem.dmp windows.memmap --pid <pid> --dump
# Поиск AES-ключей/структур
vol -f mem.dmp windows.yarascan --yara-rules keys.yar
# pypykatz/скрипты для поиска ключей
```

Многие семейства держат ключ в памяти во время шифрования — если снять дамп, ключ можно извлечь.

## Практический пример: анализ образца

```bash
# 1. Статика
file sample.exe
strings -n 8 sample.exe | grep -iE 'aes|rsa|key|bitcoin|\.locked'
# 2. YARA
yara ransomware.yar sample.exe
# 3. Динамика (изолированно!) — в песочнице
# 4. Проверка схемы: зашифровать тестовый файл, сравнить
# 5. Поиск ключа в дампе памяти
vol -f mem.dmp windows.malfind
```

## Crypto-слабости конкретных семейств

- **WannaCry:** использует Windows CryptoAPI; ключ на диске/в памяти (есть инструменты).
- **Petya/NotPetya:** Salsa20; master key в памяти.
- **LockBit/Conti:** гибридная схема; ключи на C2.
- **Phobos/Dharma:** AES-256; утечки ключей в некоторых версиях.
- **STOP/Djvu:** для части версий есть offline-ключи.

Всегда проверяйте: **полное ли шифрование**, **какой режим**, **где ключ**.

```bash
# ID

NoMoreRansom.org (бесплатные для старых семейств)
```

## Схемы шифрования: детально

**Гибридная схема** (типовая): генерируется случайный **AES-ключ** на сессию; им шифруются файлы (быстро); AES-ключ шифруется **RSA-публичным ключом** атакующего и сохраняется (в файле/реестре/на C2). Приватный RSA-ключ — только у атакующего. Без него расшифровка невозможна.

**Слабости:**

- **Частичное шифрование:** многие шифруют только первые N КБ (для скорости), остальное — открыто. Тогда для некоторых файлов данные частично восстановимы.
- **Interleaved mode / ECB:** повторяющиеся блоки → паттерны.
- **Слабый RNG:** ключ предсказуем.
- **Ключ на диске:** в реестре, временном файле, не затёрт.
- **Ключ в памяти:** Volatility.
- **Reused keystream (CTR):** reused nonce → XOR.

## Известные декрипторы

**NoMoreRansom.org** — бесплатные декрипторы для старых/слабых семейств (Shade, CrySiS, TeslaCrypt, STOP/Djvu-частично, GandCrab-частично). **ID Ransomware** — определение семейства по образцу/note.

```bash
# Определение семейства
# 1. Загрузить образец/note на id-ransomware.malwarehunterteam.com
# 2. Или локально: strings sample.exe | grep -iE 'ransom|note|\.enc'
# 3. YARA-правила из репозиториев
```

## Практический пример: восстановление через теневые копии

```bash
# 1. Проверить наличие теневых копий
vssadmin list shadows
# 2. Если есть — смонтировать/скопировать
mklink /d C:\shadow \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\
copy C:\shadow\Users\victim\important.docx C:\restore\
# 3. Если нет — искать ключ в памяти (снять дамп до выключения)
```

## Инструменты и команды

```bash
# Идентификация
strings -n 8 sample.exe | grep -iE 'aes|rsa|ransom|\.locked|bitcoin'
yara -r rules/ sample.exe
# Memory
vol -f mem.dmp windows.pstree
vol -f mem.dmp windows.malfind
vol -f mem.dmp windows.yarascan --yara-file keys.yar
pypykatz lsa minidump lsass.dmp
# Recovery
vssadmin list shadows
photorec /dev/sdX
# Онлайн
# NoMoreRansom.org, ID Ransomware, Emsisoft Decryptor
```

## Действия при инциденте (порядок)

1. **Изолировать** заражённые хосты (не выключать!).
2. **Снять дамп памяти** (ключ может быть там).
3. **Зафиксировать** note/расширения/образцы.
4. **Определить семейство** (ID Ransomware, YARA).
5. **Проверить** теневые копии/бэкапы.
6. **Искать декриптор** (NoMoreRansom).
7. **Восстановить** данные, **отчитаться**, **усилить** защиту.

## Обнаружение ransomware в памяти

Дамп памяти — лучший шанс найти ключ. Ищите:

- **Процесс ransomware** (malfind, подозрительные cmdline).
- **AES/RSA-ключи** в памяти процесса (yarascan с правилами на структуры ключей).
- **Строки** note/расширений.
- **Сетевые соединения** к C2 (netscan).

```bash
vol -f mem.dmp windows.pstree | grep -iE 'encrypt|ransom|\.tmp'
vol -f mem.dmp windows.malfind --pid <pid>
vol -f mem.dmp windows.memmap --pid <pid> --dump
vol -f mem.dmp windows.yarascan --yara-file crypto_keys.yar
strings mem.dmp | grep -iE 'your files|bitcoin|decrypt'
```

Некоторые семейства держат ключ в памяти всё время шифрования — снятие дампа вовремя спасает данные.

## Вектор проникновения: как попали

Ransomware почти всегда попадает через:

- **RDP** (скомпрометированные креды, брутфорс) — самый частый.
- **Фишинг** (вложение/ссылка).
- **Уязвимости** (VPN, Exchange, публичные сервисы).
- **Supply chain** (обновления, MSP).
- **Начальный доступ брокеров** (IAB).

Артефакты: `4624`/`4625` (входы), RDP-логи, `Sysmon 1` (подозрительные процессы), почта, VPN-логи. Восстановление вектора критично для устранения и предотвращения повтора.

## Итог

Ransomware-форензика — гонка за ключом. Снимите память **до** выключения, идентифицируйте семейство, проверьте полноту шифрования и ищите ключ в памяти/на диске. Теневые копии и бэкапы — первый шанс восстановления, NoMoreRansom — второй. Не платите. Восстановите вектор проникновения (обычно RDP/фишинг) для предотвращения повтора.

## Резюме

Память до выключения → идентификация → полнота шифрования → ключ в памяти/на диске → теневые копии/бэкапы → NoMoreRansom. Не платите.

## Частые ошибки

- **Платить выкуп.** Не гарантирует и финансирует преступников.
- **Выключать питание** до снятия дампа памяти (теряется ключ).
- **Игнорировать теневые копии.**
- **Считать шифрование полным.** Часто частичное.
- **Не проверить память** на ключи.
- **Запускать образец вне песочницы.**

## Как не застрять

- **Идентифицируйте семейство** (расширения, note, YARA).
- **Проверьте полноту шифрования.**
- **Снимите дамп памяти** до выключения.
- **Ищите ключи** в памяти/на диске.
- **Проверьте теневые копии/бэкапы.**
- **Ищите бесплатный декриптор** (NoMoreRansom).
