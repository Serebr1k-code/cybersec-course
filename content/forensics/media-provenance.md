## Вопрос, с которого всё начинается

Как доказать, что изображение не подделано, а создано конкретным устройством/софтом?
Существует стандарт **C2PA** (Coalition for Content Provenance and Authenticity) —
подписанные «Content Credentials». Разберём.

## Наш пример: файл с манифестом

## Шаг 1: что такое C2PA

C2PA добавляет в файл **манифест**: кто создал, чем, какие правки вносились. Манифест
**криптографически подписан** — подделать без ключа нельзя.

## Шаг 2: где манифест

Он встроен в файл (JUMBF-бокс в JPEG/PNG/MP4) или лежит рядом (sidecar).

```
$ c2patool image.jpg
{
  "claim_generator": "Adobe Photoshop 25.0",
  "signature_info": { "issuer": "Adobe Inc." }
}
```

`c2patool` читает и проверяет манифест.

## Шаг 3: что внутри

- **claim** — утверждения о файле;
- **assertions** — действия (создано, отредактировано, сгенерировано ИИ);
- **signature** — подпись издателя;
- **ingredients** — исходные материалы.

Особенно важно: assertion может указывать **AI-generated**.

## Шаг 4: проверка подписи

```
$ c2patool image.jpg -d
signature: valid
```

Если подпись недействительна — файл меняли после подписи (манифест «отвалился»).

## Шаг 5: ограничения

- не все устройства/софт поддерживают C2PA;
- отсутствие манифеста ≠ подделка (просто нет данных);
- подпись подтверждает **происхождение от издателя**, не «правду»;
- манифест можно удалить (тогда следов нет).

## Что мы теперь знаем

- C2PA добавляет подписанный манифест происхождения.
- Манифест встроен в файл или sidecar.
- Содержит генератор, действия, подпись, ингредиенты.
- `c2patool` читает и проверяет.
- Отсутствие манифеста — не доказательство подделки.

## Если не сработало

- Манифеста нет? Проверь sidecar и метаданные.
- Подпись невалидна? Файл меняли после подписи.
- Нужен вердикт? Учитывай контекст.

## Как устроен манифест C2PA

C2PA (Coalition for Content Provenance and Authenticity) — открытый стандарт.
Манифест хранится в **JUMBF**-боксе (JPEG Universal Metadata Box Format)
внутри файла. Структура:

- **claim** — главное утверждение: «этот файл — такой-то, создан тогда-то»;
- **assertions** — конкретные факты: `c2pa.actions` (что делали),
  `c2pa.training-mining` (запрет на обучение ИИ), `stds.schema-org` (автор);
- **ingredients** — исходные материалы (из чего собрано);
- **signature** — криптографическая подпись издателя (X.509-сертификат).

Подпись связывает манифест с сертификатом. Если содержимое изменили после
подписи, хэш не сойдётся, и проверка покажет недействительность.

## Работа на примере: читаем манифест

Читаем манифест инструментом `c2patool`:

```
$ c2patool image.jpg
{
  "claim_generator": "Adobe Photoshop 25.0",
  "signature_info": { "issuer": "Adobe Inc.", "cert_serial_number": "..." },
  "assertions": [
    { "label": "c2pa.actions", "data": { "actions": [{ "action": "c2pa.created" },
      { "action": "c2pa.edited" }] } }
  ]
}
```

Разбираем: файл создан и отредактирован, подписан Adobe. Если бы среди
действий было `c2pa.placed` с источником «generative AI», это указывало бы
на ИИ-генерацию.

## Проверка цепочки доверия

Подпись проверяется по цепочке сертификатов до доверенного корня. `c2patool`
делает это автоматически:

```
$ c2patool image.jpg -d
...
signature: valid
```

Недействительная подпись означает одно из двух: файл меняли после подписи
(манифест «отвалился») или сертификат неизвестен. Второе не обязательно
подделка — просто издатель не в списке доверенных.

## Что доказывает подпись, а что нет

**Доказывает:** файл подписан конкретным издателем и не менялся после
подписи. **Не доказывает:** что содержимое «правдиво». Издатель мог
подписать отредактированное или сгенерированное изображение. Подпись — это
атрибуция, а не гарантия истинности.

## Инструменты и форматы

- **c2patool** — официальный CLI (чтение, проверка, запись);
- **Библиотеки** — c2pa-rs (Rust), c2pa-python, JS;
- **Форматы** — JPEG, PNG, MP4, WebP, PDF (JUMBF-боксы);
- **Sidecar** — если манифест нельзя встроить, он лежит отдельным файлом
  рядом.

## Ограничения

- Не все устройства/приложения поддерживают C2PA — отсутствие манифеста не
  улика.
- Манифест можно **удалить** (тогда следов происхождения нет).
- Издатель может быть «анонимным» сертификатом.
- Метаданные и манифест — разные вещи: EXIF легко правится, C2PA —
  подписан.

## Практический чек-лист

1. Опознать формат файла.
2. Извлечь манифест (`c2patool` или вручную из JUMBF).
3. Прочитать `claim_generator`, `actions`, `ingredients`.
4. Проверить подпись и цепочку сертификатов.
5. Учесть: нет манифеста ≠ подделка; невалидная подпись = правки после
   подписи.
6. Зафиксировать хэш файла и вывод проверки.

## Действия (actions) и их коды

В манифесте C2PA действия описаны стандартными кодами. Основные:

| Действие | Значение |
| --- | --- |
| `c2pa.created` | файл создан |
| `c2pa.edited` | отредактирован |
| `c2pa.placed` | вставлен фрагмент |
| `c2pa.cropped` | обрезан |
| `c2pa.resized` | изменён размер |
| `c2pa.transcoded` | перекодирован |

Особый случай — `c2pa.placed` с типом `c2pa.types.generated` (или ссылкой на
ИИ-сервис). Это прямое указание, что часть контента сгенерирована. Для
журналистики и суда это ключевой факт.

## Ingredients: цепочка происхождения

**Ingredients** (ингредиенты) — исходные материалы. Каждый ингредиент имеет
свой хэш и может ссылаться на отдельный манифест:

```
"ingredients": [
  { "title": "original.jpg", "hash": "sha256:...", "relationship": "parentOf" }
]
```

Так строится **граф** происхождения: из чего собрано, что было «родителем».
Если у ингредиента есть свой подписанный манифест, можно проверить всю
цепочку до исходного снимка.

## Работа с PDF и видео

C2PA поддерживает не только изображения:

- **PDF** — манифест в метаданных (JUMBF в XMP);
- **MP4/видео** — манифест в отдельном боксе; для фрагментов используется
  `c2pa.hash.data`/`c2pa.hash.boxes`.

```
$ c2patool video.mp4 | head -20
```

Для видео особенно важна **боксовая** модель хэширования: она позволяет
проверять подпись, даже если метаданные контейнера переписаны плеером.

## Отличие от водяных знаков и EXIF

- **EXIF** — обычные метаданные (камера, дата). Легко правится, не подписан.
- **Водяной знак** — встроен в пиксели, устойчив к правкам, но не доказывает
  авторство криптографически.
- **C2PA** — подписанный манифест: изменение файла ломает подпись.

C2PA не заменяет остальные методы — они дополняют друг друга. Водяной знак
скажет «это из сервиса X», C2PA — «подписано издателем Y и не менялось».

## Если сработало / если нет

- **Манифест есть и валиден** — зафиксируй генератор, действия, подпись.
- **Подпись невалидна** — файл правили после подписи; проверь, не переписан
  ли он конвертером.
- **Манифеста нет** — не делай вывод «подделка»; возможно, инструмент его не
  поддерживает.
- **Есть ingredients** — построй граф происхождения и проверь родителей.

## Практический сценарий: проверяем фото на подделку

Задача: есть изображение, нужно понять его происхождение.

1. **Опознать формат** — `file image.jpg`.
2. **Извлечь манифест** — `c2patool image.jpg`.
3. **Проверить подпись** — `c2patool image.jpg -d` → `signature: valid`?
4. **Прочитать действия** — есть ли `c2pa.edited` или `placed` (ИИ).
5. **Проверить ингредиенты** — из чего собрано.
6. **Сверить с EXIF** — совпадает ли дата/устройство с манифестом.

Если манифест говорит «создано камерой X», а EXIF — другое устройство,
возникает противоречие, требующее объяснения. Если манифеста нет, вывод
осторожный: «данных о происхождении нет».

## C2PA в браузерах и соцсетях

Content Credentials поддерживают всё больше платформ: Adobe, Microsoft,
некоторые браузеры показывают значок «CR» на изображениях с валидным
манифестом. Однако:

- **платформы часто удаляют манифест** при пережатии/ресайзе;
- **скриншот** теряет манифест (это уже новый файл);
- **соцсеть** может показывать урезанную версию метаданных.

Поэтому для проверки бери **оригинальный файл** из источника, а не то, что
показывает платформа. Отсутствие значка «CR» в соцсети ещё не значит, что у
оригинала манифеста не было.

## Если сработало / если нет

- **Подпись валидна, действия чистые** — файл атрибутирован; зафиксируй
  издателя.
- **Действия содержат placed/generated** — часть контента синтетическая.
- **Манифеста нет** — проверь sidecar и не делай вывод о подделке.

## Как встроить и проверить манифест самостоятельно

C2PA не только читается — манифест можно **создать**. Это полезно, чтобы
понять формат изнутри:

```
$ c2patool image.jpg --manifest manifest.json --output signed.jpg
```

В `manifest.json` описывают утверждения и подпись. После создания проверяем:

```
$ c2patool signed.jpg -d
signature: valid
```

Практическая ценность: разобравшись в структуре, ты быстрее распознаешь
подделку — например, манифест, «подписанный» неизвестным сертификатом, или
хэш, не совпадающий с файлом.

## Итог: происхождение как отдельный слой

C2PA добавляет к медиа **слой доверия**: подписанный манифест о том, кто,
чем и как создал файл. Он не заменяет EXIF и не доказывает «правду», но
даёт криптографическую привязку к издателю. В расследовании это значит:
если манифест валиден — мы знаем генератор и цепочку правок; если невалиден
— файл меняли после подписи; если отсутствует — данных просто нет.

## Итог: манифест — это подписанное утверждение

C2PA не «доказывает правду», он фиксирует **кто** и **что** заявил о файле,
скрепляя это подписью. Читай манифест как показание свидетеля: генератор,
действия, ингредиенты, издатель. Проверяй подпись — она говорит, менялся ли
файл после заявления. Отсутствие манифеста — это отсутствие данных, а не
приговор. Такой подход избавляет и от наивного доверия, и от наивного
недоверия к медиа.

## Что делать при противоречии

Если манифест и EXIF расходятся (разные устройства, даты), не спеши с
выводом. Возможные объяснения: файл прошёл через редактор (манифест
обновился, EXIF — нет), метаданные подделали, либо это разные версии одного
файла. Собери все версии, сравни хэши и определи, какая из них подписана.
Противоречие — это не конец анализа, а точка, где нужны дополнительные
данные.
