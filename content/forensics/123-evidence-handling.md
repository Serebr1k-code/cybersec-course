Цифровое доказательство ценно не только содержанием, но и **доказуемостью**: возможность показать, что данные не изменялись и получены законным путём. Обращение с доказательствами — набор процедур, обеспечивающих это. Даже в CTF понимание этих принципов помогает не «испортить» образ.

## Принципы работы с доказательствами

1. **Не изменять оригинал.** Любые действия — с копией.
2. **Идентифицировать.** Что это за носитель, кто, когда, где.
3. **Документировать.** Каждый шаг, инструмент, время.
4. **Хешировать.** Фиксировать целостность.
5. **Хранить.** Оригинал — в защищённом месте, опечатан.
6. **Соблюдать цепочку сохранности.** Кто держал/передавал доказательство.

## Цепочка сохранности (chain of custody)

Это журнал, в котором фиксируют каждое перемещение и передачу доказательства:

| Поле | Пример |
|------|--------|
| Идентификатор | CASE-2024-001-ITEM-01 |
| Описание | SSD 512 ГБ, S/N ABC123 |
| Кто изъял | И. Иванов |
| Когда | 2024-03-01 22:30 UTC |
| Где | серверная, стойка 4 |
| Передачи | Иванов → Петров (2024-03-02 09:00) |
| Хеш | sha256:9f2c… |

Разрыв цепочки — основание оспорить доказательство.

## Хеширование

```bash
# При снятии — хеш источника и образа
dc3dd if=/dev/sdb of=disk.dd hash=sha256 log=acq.log
# Проверка позже
sha256sum disk.dd
# Для EWF
ewfverify disk.E01
# Для нескольких артефактов
find /evidence -type f -exec sha256sum {} + > manifest.sha256
sha256sum -c manifest.sha256
```

MD5 быстрее, SHA-256 надёжнее; для суда часто фиксируют оба. Хеш образа должен совпасть с хешем источника (или со встроенным хешем EWF).

## Упаковка и хранение

- **Оригинал** — в антистатическом пакете/боксе, опечатан, с подписью.
- **Копии** — минимум две, на разных носителях.
- **Климат** — защита от температуры, влажности, магнитных полей.
- **Доступ** — только у уполномоченных лиц, с журналом.
- **Шифрование копий** — если содержат чувствительные данные.

## Документирование

Каждый отчёт об изъятии включает:

- описание носителя (модель, серийник, размер);
- состояние (включён/выключен, есть ли повреждения);
- действия (что и чем делали);
- хеши и результаты верификации;
- свидетелей;
- фотографии.

```bash
# Пример лога изъятия
cat > evidence_log.txt <<EOF
Case: CASE-2024-001
Item: ITEM-01
Device: Samsung SSD 870, S/N S1234567, 500GB
Seized by: I. Ivanov
Time: 2024-03-01T22:30:00Z
Method: dc3dd hash=sha256
sha256(src): 9f2c...
sha256(img): 9f2c...
EOF
```

## Разобранный пример

```bash
# 1) Изъятие
$ lsblk -o NAME,SIZE,SERIAL,MODEL | grep sdb
sdb    465.8G  S1234567  Samsung SSD 870
# 2) Снятие образа с хешами
$ sudo dc3dd if=/dev/sdb of=/evidence/ITEM-01.dd hash=sha256 log=/evidence/ITEM-01.log
# 3) Верификация
$ grep -i sha256 /evidence/ITEM-01.log
sha256 9f2c... /dev/sdb
sha256 9f2c... /evidence/ITEM-01.dd
# 4) Манифест всех файлов
$ (cd /evidence && find . -type f -exec sha256sum {} +) > /evidence/manifest.sha256
```

Все хеши совпали — доказательство целостно; манифест позволяет проверить неизменность позже.

## Краевые случаи и подводные камни

- **Забыть хеш источника.** Без него нельзя доказать, что копия идентична.
- **Работа с оригиналом.** Любая запись — потеря доказательства.
- **Разрыв цепочки.** Незадокументированная передача ставит под сомнение всё.
- **Один носитель.** Потеря/повреждение единственной копии — конец расследования.
- **Неверное время.** Часовой пояс и синхронизация важны.
- **Изменение метаданных.** Даже `ls`/`cat` может обновить access time; работайте с копией.
- **Смешение кейсов.** Доказательства разных дел не хранят вместе.
- **Публикация.** Утечка содержимого может раскрыть источники.

## Идентификация и описание носителя

Точная идентификация — основа доказательства. Фиксируют:

- **Тип и модель** устройства (SSD/HDD/USB, производитель).
- **Серийный номер** (не путать с номером модели).
- **Ёмкость в байтах** (точно, по `blockdev --getsize64`).
- **Состояние** (включён/выключен, повреждения, шифрование).
- **Контекст** (где, когда, у кого изъят).

```bash
lsblk -o NAME,MODEL,SERIAL,SIZE,RO
sudo blockdev --getsize64 /dev/sdb
sudo smartctl -i /dev/sdb | grep -Ei 'model|serial|firmware'
```

Хеш и серийный номер связывают физический носитель с его цифровым образом.

## Хеширование: алгоритмы и практика

- **MD5** — быстрый, исторически стандарт в форензике; коллизии известны, но для целостности копии достаточно.
- **SHA-1** — компрометирован для подписи, но для целостности ещё используется.
- **SHA-256** — рекомендуемый для новых расследований.

```bash
# Одновременно несколько хешей
dc3dd if=/dev/sdb of=disk.dd hash=md5,sha1,sha256 log=acq.log
# Пакетная верификация манифеста
sha256sum -c manifest.sha256
# Встроенные хеши EWF
ewfinfo disk.E01 | grep -i hash
ewfverify disk.E01
```

Манифест хешей (`manifest.sha256`) позволяет позже проверить, что ни один артефакт не изменился.

## Упаковка и маркировка

- **Антистатический пакет** + пломба с подписью и датой.
- **Маркировка**: уникальный ID кейса/предмета.
- **Фотографии** до и после упаковки.
- **Журнал доступа** к хранилищу.
- **Климат-контроль** для долгого хранения.

## Юридические аспекты

- **Санкция** на изъятие/исследование.
- **Права** третьих лиц (личные данные на устройстве).
- **Юрисдикция** (данные могут быть в другой стране/облаке).
- **Допустимость** — процедура должна соответствовать местным нормам.
- **Экспертная квалификация** — кто вправе давать заключение.

Даже в CTF эти принципы полезны как чек-лист: не изменять образ, документировать, хешировать.

## Воспроизводимость

Хорошее доказательство воспроизводимо: другой эксперт с теми же копиями и инструментами получит тот же результат. Для этого:

- фиксируйте **версии инструментов**;
- сохраняйте **командные строки**;
- записывайте **параметры** (offsets, фильтры);
- прикладывайте **логи** и **манифесты хешей**.

## Типичные ошибки

- **Работа с оригиналом.** Изменяет доказательство.
- **Один хеш и потеря.** Храните манифест в нескольких местах.
- **Незадокументированная передача.** Разрыв цепочки.
- **Нет пломбы.** Невозможно доказать, что носитель не вскрывали.
- **Смешение предметов.** Разные кейсы — раздельно.
- **Публикация содержимого.** Раскрытие чувствительных данных.
- **Игнорирование времени.** Неверные метки разрушают таймлайн.

## Инвентаризация доказательств (evidence inventory)

Ведите единый реестр всех предметов кейса:

| ID | Описание | Хеш | Место хранения | Статус |
|----|----------|-----|----------------|--------|
| ITEM-01 | SSD 512GB S/N ABC | sha256:9f2c | сейф 1 | опечатан |
| ITEM-02 | Копия ITEM-01 | sha256:9f2c | NAS /cases | рабочий |
| ITEM-03 | Дамп памяти | sha256:11ab | NAS /cases | рабочий |

Реестр — часть цепочки сохранности: по нему видно, где находится каждый предмет и его копии.

## Работа с копиями

Правило трёх копий: **оригинал + две копии на разных носителях**. Оригинал не используют для анализа; рабочие копии — верифицированные. Если одна копия повреждена, вторая сохраняет возможность продолжения.

## Формальная верификация

```bash
# Перед каждым использованием копии — проверка манифеста
sha256sum -c manifest.sha256
# Все OK — можно анализировать
```

Любое расхождение — сигнал, что копия изменена; используйте другую копию и выясните причину.

## Завершение кейса

По окончании расследования:

- Верните/утилизируйте данные по политике.
- Сохраните отчёт и манифесты.
- Зафиксируйте окончательное место хранения.
- Закройте журнал цепочки сохранности.

Так доказательство остаётся валидным и после завершения работы.

## Ошибки, обесценивающие доказательство

Сводка того, чего нельзя делать:

| Ошибка | Последствие |
|--------|-------------|
| Работа с оригиналом | изменение доказательства |
| Нет хеша источника | нельзя доказать идентичность |
| Разрыв цепочки | оспоримость в суде |
| Одна копия | потеря при сбое |
| Нет документации | невоспроизводимость |
| Неверное время | разрушенный таймлайн |
| Публикация данных | раскрытие чувствительного |

## Мини-протокол изъятия

1. Сфотографировать носитель и окружение.
2. Записать модель/серийник/размер.
3. Снять образ с хешами (не с оригинала).
4. Верифицировать хеши.
5. Опечатать оригинал, подписать.
6. Занести в реестр и цепочку сохранности.

Этого минимума достаточно, чтобы доказательство оставалось валидным.

## Ключевые выводы

- Доказательство ценно доказуемостью, а не только содержанием.
- Хеши источника и образа обязательны; манифест позволяет верификацию позже.
- Цепочка сохранности фиксирует каждое перемещение.
- Минимум три копии: оригинал + две рабочие.
- Любая запись в оригинал — потеря доказательства.

## Мини-таблица: что хешировать

| Объект | Хеш | Когда |
|--------|-----|-------|
| Источник (диск) | sha256 | при снятии |
| Образ | sha256 | сразу после |
| Манифест артефактов | sha256 | после обработки |
| Дамп памяти | sha256 | после сбора |

Хеш источника + образа — минимально необходимый набор для доказательства целостности.

## Мини-шпаргалка верификации

| Шаг | Команда |
|-----|---------|
| Хеш источника | `sha256sum /dev/sdb` |
| Хеш образа | `sha256sum disk.dd` |
| Проверка EWF | `ewfverify disk.E01` |
| Манифест | `find . -type f -exec sha256sum {} + > m.sha256` |
| Верификация | `sha256sum -c m.sha256` |

Верификация — обязательный шаг перед любым анализом копии.

## Что дальше / решение

1. Идентифицировать носитель и задокументировать.
2. Снять образ с хешами (никогда с оригинала).
3. Верифицировать хеши.
4. Опечатать оригинал, хранить копии раздельно.
5. Вести цепочку сохранности и манифест хешей.

Дальше — `forensics-chain-custody` (если нужно глубже) и `forensics-reporting` (оформление результатов).

## Где пригодится

- **CTF:** понимание корректного обращения с образами.
- **Судебная экспертиза:** допустимость доказательств.
- **IR:** документирование изъятия в реальных инцидентах.
- **Работа:** стандарты обращения с носителями.
