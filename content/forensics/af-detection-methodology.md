## Вопрос, с которого всё начинается

Мы разобрали конкретные техники: удаление, шифрование, подделку. Но как искать их
**системно**, когда заранее неизвестно, что именно сделал атакующий? Нужна методология, а
не список команд.

## Наш пример: «слишком чистая» система

Приезжаем на инцидент. Система выглядит ухоженной: журналы короткие, временные файлы
отсутствуют, антивирус «не находил ничего». Опытный следователь сразу настораживается —
именно **чистота** и есть первый сигнал.

## Принцип 1: аномалия отсутствия

Анти-форензика — это чаще **отсутствие** ожидаемого, чем присутствие странного:

- нет журналов за период, когда система точно работала;
- нет временных файлов у программы, которая их всегда создаёт;
- нет артефактов запуска (Prefetch, история) у подозрительного бинарника.

«Следов нет» само по себе — улика.

## Принцип 2: несоответствия между источниками

Ни один инструмент не может идеально «вылизать» **все** представления данных. Поэтому
ищем расхождения:

```
журнал хоста  vs  сетевой лог        -> пропущенное соединение
список файлов vs  MFT/USN            -> удалённый файл
pslist        vs  psscan             -> скрытый процесс
```

Каждое расхождение — точка приложения расследования.

## Принцип 3: следы самих инструментов

Инструменты анти-форензики оставляют свои следы:

- **SDelete/шредеры** — записи в журналах, характерные паттерны перезаписи;
- **очистка журналов** — события 1102/104, разрывы record ID;
- **timestomp** — одинаковые или невозможные метки времени;
- **архиваторы/шифровальщики** — созданные контейнеры, всплеск энтропии.

Ищем не «факт удаления», а **инструмент**, которым его делали.

## Принцип 4: проверка целостности

Улики должны быть проверяемы:

- **хеши** образов и файлов (SHA-256) на момент снятия;
- **цепочка хранения** (chain of custody);
- **сверка** с эталоном (например, оригинал системного файла из установочного образа).

Если целостность не подтверждена, выводы шатки.

## Принцип 5: контекст важнее единичного факта

Один артефакт может врать. Вывод строят на **совокупности**:

```
журналы + сеть + память + артефакты ФС + внешние источники  =>  вывод
```

Если несколько независимых источников сходятся — вывод устойчив. Если один выбивается —
это либо подделка, либо ошибка чтения.

## Практический чек-лист

1. Зафиксировать **время** и состояние системы.
2. Снять образы (диск, память) с проверкой хешей.
3. Составить **таймлайн** и найти в нём пробелы.
4. Сравнить **разные представления** одних данных.
5. Найти **следы инструментов** анти-форензики.
6. Проверить **целостность** ключевых артефактов.
7. Свести выводы по **нескольким источникам**.

## Что мы теперь знаем

- Анти-форензику ищут по аномалиям отсутствия.
- Расхождения между источниками выдают сокрытие.
- Инструменты анти-форензики оставляют собственные следы.
- Целостность улик подтверждают хешами и цепочкой хранения.
- Вывод строят на совокупности источников.

## Куда дальше

Мы прошли анти-форензику целиком: от конкретных техник до методологии их обнаружения.
Дальше ветка дерева ведёт к таймлайну и корреляции. А пока запомни: отсутствие следов —
тоже след, а вывод строится на совокупности источников.

## Где пригодится

- **DFIR / Incident Response** — системный поиск следов зачистки.
- **CTF Forensics** — задачи, где улики специально спрятаны.
- **Threat Hunting** — выявление анти-форензик-поведения.
