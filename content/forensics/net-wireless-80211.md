## Вопрос, с которого всё начинается

Устройство подключалось к беспроводной сети — а значит, где-то остался след: MAC,
SSID, время ассоциации. Если снят Wi-Fi-дамп, из него можно восстановить, кто и когда
подключался. Разберём, как читать 802.11.

## Наш пример: дамп Wi-Fi

## Шаг 1: типы кадров

В 802.11 три класса кадров:

- **management** — beacon, probe, association;
- **control** — ack, rts/cts;
- **data** — сами данные.

Для форензики важнее всего management: там видны SSID и ассоциации.

## Шаг 2: список сетей

```
$ tshark -r wifi.pcap -Y 'wlan.fc.type_subtype==8' -T fields -e wlan.ssid -e wlan.bssid | sort -u
CorpWiFi	02:42:0a:0a:14:01
Guest	02:42:0a:0a:14:02
```

`subtype==8` — это beacon. BSSID — MAC точки доступа.

## Шаг 3: кто подключался

Ассоциация — subtype 0/1 (assoc req/resp):

```
$ tshark -r wifi.pcap -Y 'wlan.fc.type_subtype==0' -T fields -e wlan.sa -e wlan.ssid | head
02:42:0a:0a:14:09	CorpWiFi
```

`wlan.sa` — MAC клиента. Так видно, какие устройства и к каким сетям подключались.

## Шаг 4: WPA-рукопожатие

Ключи WPA получаются из 4-way handshake. Если он есть в дампе, можно проверить пароль
офлайн:

```
$ tshark -r wifi.pcap -Y 'eapol' -T fields -e wlan.sa -e wlan.bssid | head
02:42:0a:0a:14:09	02:42:0a:0a:14:01
```

Пары клиент↔AP — кандидаты для проверки (это уже атакующая сторона, но в защитном
расследовании важно понять, что рукопожатие **перехвачено**).

## Шаг 5: следы на устройстве

На самом хосте остаётся список известных сетей:

```
$ cat /etc/NetworkManager/system-connections/*.nmconnection | grep -i ssid
ssid=CorpWiFi
```

А на macOS — в `com.apple.wifi.plist` (может содержать историю SSID и времени).

## Что мы теперь знаем

- Management-кадры несут SSID и ассоциации.
- `tshark` фильтрует по `wlan.fc.type_subtype`.
- BSSID — MAC точки доступа, `wlan.sa` — клиент.
- EAPOL-кадры = WPA-рукопожатие.
- Список известных сетей остаётся на хосте.

## Если не сработало

- Трафик шифрован? SSID и ассоциации всё равно видны в management.
- Нет дампа? Ищи профили сетей на хосте.
- Нужны данные? Расшифровка требует ключа/рукопожатия.

## Типы кадров 802.11

Wi-Fi на уровне протокола состоит из трёх классов кадров:

- **управляющие (management)** — Beacon, Probe Request/Response, Authentication,
  Association. Именно здесь виден SSID и процесс подключения;
- **контрольные (control)** — RTS/CTS, ACK (управление доступом к среде);
- **данные (data)** — собственно полезная нагрузка, часто зашифрованная.

Для форензики управляющие кадры — главные: они **не шифруются** даже в защищённых сетях, и
именно из них восстанавливается, кто и куда подключался.

```
$ tshark -r wifi.pcap -Y 'wlan.fc.type == 0' -T fields -e wlan.fc.subtype -e wlan.ssid | head
8  MyNetwork        # Beacon
4  OldNetwork       # Probe Request
```

`subtype 8` — Beacon (точка вещает сеть), `subtype 4` — Probe Request (клиент ищет сеть).

## Список сетей и клиентов

Из дампа собираем все SSID и точки доступа (BSSID — это MAC точки):

```
$ tshark -r wifi.pcap -Y 'wlan.fc.type_subtype == 0x08' -T fields -e wlan.bssid -e wlan.ssid | sort -u
aa:bb:cc:00:11:22  CorpWiFi
aa:bb:cc:00:11:23  GuestWiFi
de:ad:be:ef:00:01  FreeWiFi-Open   # открытая, подозрительно
```

Список клиентов и их «предпочтительные сети» — из Probe Request:

```
$ tshark -r wifi.pcap -Y 'wlan.fc.type_subtype == 0x04' -T fields -e wlan.sa -e wlan.ssid | sort -u
f0:18:98:aa:bb:cc  HomeNetwork
f0:18:98:aa:bb:cc  Airport_Free_WiFi
```

Клиент постоянно ищет «свои» сети. Если он шлёт Probe Request на **открытую** сеть с
известным именем, это потенциальный вектор: атакующий поднимает точку с тем же SSID и
заманивает устройство (evil twin).

## WPA-рукопожатие

WPA2-сеть защищена 4-этапным рукопожатием. Захватив его, можно **офлайн** подобрать пароль:

```
$ tshark -r wifi.pcap -Y 'eapol' -T fields -e frame.time -e wlan.sa -e eapol.type
2026-01-14 03:30:01  f0:18:98:aa:bb:cc  2   # ключевой ответ клиента
```

Пароль из рукопожатия не восстанавливается напрямую — перебираются кандидаты, каждый
превращается в PMK и проверяется против захваченных данных. Для этого нужны все четыре
кадра EAPOL; полный набор даёт `aircrack-ng` или `hashcat` (режим 22000).

## Следы на устройстве

Помимо дампа, «память» о сетях хранится на самом устройстве:

| ОС | Где | Что |
|---|---|---|
| macOS | `/Library/Preferences/com.apple.airport.preferences.plist` | известные сети, время |
| macOS | `com.apple.wifi.known-networks.plist` | SSID, тип защиты |
| Windows | реестр `...\WlanSvc\...` (XML) | профили сетей |
| Android | `/data/misc/wifi/WifiConfigStore.xml` | сети, пароли (часто) |
| iOS | `/var/preferences/SystemConfiguration/` | предпочтения |

На macOS список известных сетей показывает **историю подключений** с временем последнего
использования — это прямой таймлайн перемещений устройства.

## Таблица: подтипы кадров и их смысл

| Подтип | Имя | Значение |
|---|---|---|
| 4 | Probe Request | клиент ищет сеть |
| 5 | Probe Response | точка отвечает |
| 8 | Beacon | точка вещает SSID |
| 11 | Authentication | аутентификация |
| 0 | Association Request | подключение |
| 1 | Association Response | результат |

## Ограничения

Во-первых, **шифрование**: полезная нагрузка в WPA2/WPA3 закрыта; видны только заголовки и
управляющие кадры. Во-вторых, для захвата нужен **режим монитора** и правильный канал —
иначе дамп неполон. В-третьих, современные сети используют **PMF** (Protected Management
Frames), что усложняет подделку. В-четвёртых, **рандомизация MAC** на телефонах делает
идентификацию клиента по MAC ненадёжной. И помни: захват Wi-Fi в чужой сети может быть
незаконен без разрешения — всегда в рамках scope.

## Если сработало: фиксируем

Для отчёта собери: SSID и BSSID сетей в зоне, список клиентов с их Probe Request, факт
подключения к конкретной точке и (если удалось) рукопожатие с временем. Наличие клиента в
дампе доказывает **присутствие** устройства в зоне, а Probe Request — какие сети оно искало.

## Evil twin и зондирующие запросы

Самая практичная атака на Wi-Fi — **evil twin**: атакующий поднимает точку с тем же SSID,
что и «предпочтительная сеть» жертвы, и устройство подключается к ней автоматически. В
дампе это видно как:

- клиент шлёт Probe Request на SSID (ищет сеть);
- появляется точка с этим SSID и **другим** BSSID;
- клиент проходит аутентификацию и ассоциацию с ней.

```
$ tshark -r wifi.pcap -Y 'wlan.fc.type_subtype == 0x00 and wlan.sa == f0:18:98:aa:bb:cc' \
    -T fields -e wlan.da -e wlan.ssid
```

Совпадение SSID при разных BSSID и короткий интервал между Probe и Association — сильный
признак evil twin. Для доказательства сопоставь время с логами точки-двойника.

## Деаутентификация

Атакующие часто «сбрасывают» клиентов кадрами **deauthentication**, чтобы поймать
рукопожатие при повторном подключении. Это управляющие кадры, которые могут быть подделаны
(если нет PMF):

```
$ tshark -r wifi.pcap -Y 'wlan.fc.type_subtype == 0x0c' -T fields -e wlan.sa -e wlan.da | head
aa:bb:cc:00:11:99  ff:ff:ff:ff:ff:ff
```

Всплеск deauth-кадров, особенно широковещательных (`ff:ff:...`), от точки — типичный
признак атаки. Сопоставь: сразу после серии deauth обычно идёт повторное рукопожатие.

## Восстановление из мониторинга на клиенте

Если есть доступ к самому устройству, его сетевой стек хранит больше, чем дамп:

```
$ log show --predicate 'subsystem == "com.apple.wifi"' --last 1h | grep -i 'assoc\|join' | head
... wifi ... associated to CorpWiFi (bssid aa:bb:cc:00:11:22), channel 36 ...
```

На macOS журналы `wifi` фиксируют каждую ассоциацию с временем и BSSID. Это надёжнее
Probe-анализа: здесь записано именно **состоявшееся** подключение.

## Таблица: артефакты Wi-Fi по уровням

| Уровень | Артефакт | Что даёт |
|---|---|---|
| Радио | мониторинг-дамп | сети, клиенты, рукопожатия |
| Клиент (macOS) | `airport.preferences.plist` | известные сети, время |
| Клиент (Windows) | профили WlanSvc | сети и настройки |
| Клиент (лог) | `log show ... wifi` | ассоциации с BSSID |
| Точка доступа | контроллер/логи | кто подключался |
| DHCP/DNS | серверные логи | адрес после подключения |

## Ограничения

WPA3 с PMF закрывает деаутентификацию и усложняет evil twin. Шифрование скрывает полезную
нагрузку. Для полного дампа нужен мониторинг всех каналов, что требует нескольких адаптеров.
Рандомизация MAC мешает привязать клиента к устройству без дополнительных признаков. И
юридически: пассивный захват в чужой сети без разрешения недопустим — работай строго в scope.

## Если сработало: что фиксировать

Собери: SSID/BSSID, MAC клиента, время Probe/Assoc, факт evil twin или deauth-всплеска. Если
удалось — рукопожатие и его время. В отчёте разделяй **присутствие** (клиент в зоне) и
**подключение** (состоявшаяся ассоциация) — это разные по силе выводы.

## Сравнение с проводной сетью

В отличие от Ethernet, где каждый порт — отдельный сегмент и виден коммутатору, Wi-Fi — это
общая среда. Поэтому радиодамп содержит кадры **всех** устройств в зоне, а не только
выбранного. Это и плюс (видна общая картина), и минус (много шума). Проводную сторону
восстанавливают по ARP и DHCP, беспроводную — по 802.11, и вместе они дают полную картину
подключений устройства к сети.
