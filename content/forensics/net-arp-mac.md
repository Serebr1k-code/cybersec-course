## Вопрос, с которого всё начинается

В локальной сети устройства общаются не по IP, а по **MAC-адресам**. Протокол **ARP**
сопоставляет одно с другим. Если в дампе видно, как один MAC вдруг «присвоил» чужой
IP, — это атака. Разберём, как это устроено и как читать.

## Наш пример: ARP-таблица

## Шаг 1: как работает ARP

Отправляя пакет на `10.10.20.9`, хост спрашивает по broadcast: «кто такой 10.10.20.9?»
Владелец отвечает своим MAC. Ответ кэшируется:

```
$ ip neigh show
10.10.20.9 dev eth0 lladdr 02:42:0a:0a:14:09 REACHABLE
```

`02:42:...` — типичный MAC виртуального интерфейса. Обрати внимание на первые байты:
`02` означает «локально администрируемый» адрес (не заводской).

## Шаг 2: ARP в дампе

```
$ tshark -r capture.pcap -Y 'arp' -T fields -e arp.opcode -e arp.src.proto_ipv4 -e arp.src.hw_mac | head
1	10.10.20.5	02:42:0a:0a:14:05
2	10.10.20.9	02:42:0a:0a:14:09
```

`opcode=1` — запрос, `opcode=2` — ответ. По паре IP↔MAC строишь карту сегмента.

## Шаг 3: ARP-спуфинг

Атака: злоумышленник шлёт ответы «10.10.20.1 is at <его MAC>». Тогда весь трафик
шлюза идёт через него:

```
$ tshark -r capture.pcap -Y 'arp.opcode==2' -T fields -e arp.src.proto_ipv4 -e arp.src.hw_mac | sort | uniq -c | sort -rn | head
   900	10.10.20.1	02:42:0a:0a:14:66
     2	10.10.20.1	02:42:0a:0a:14:01
```

Один и тот же IP `10.10.20.1` анонсируется с **двух разных** MAC, причём «чужой» MAC
доминирует. Это отравление ARP — классический MITM.

## Шаг 4: следы на хосте

На скомпрометированном хосте таблица ARP может быть отравлена:

```
$ cat /proc/net/arp
IP address       HW type     Flags   HW address
10.10.20.1       0x1         0x2     02:42:0a:0a:14:66
```

Сверь MAC шлюза с эталоном — расхождение выдаёт атаку.

## Шаг 5: MAC как идентификатор

MAC-адрес (в части OUI) указывает производителя. Первые 3 байта — OUI:

```
$ grep -i '02:42' /usr/share/nmap/nmap-mac-prefixes
0242   (локально администрируемый)
```

Локально администрируемые MAC часто означают контейнеры/виртуалки или подделку.

## Что мы теперь знаем

- ARP сопоставляет IP и MAC в локальном сегменте.
- `ip neigh` и `/proc/net/arp` показывают текущую таблицу.
- `tshark -Y arp` даёт карту IP↔MAC из дампа.
- Один IP с двумя MAC = ARP-спуфинг.
- OUI в MAC указывает производителя.

## Если не сработало

- Дамп только прикладной? ARP не попал — снимай заново с L2.
- Таблица пуста? Кэш истёк — смотри логи switch.
- Нужна история? Ищи ARP в долгих дампах и на span-порту.
