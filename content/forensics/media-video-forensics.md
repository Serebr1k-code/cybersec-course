## Вопрос, с которого всё начинается

Видео — доказательство или носитель данных. Нужно понять: какой контейнер, какие
дорожки, что в метаданных, нет ли скрытого. Разберём.

## Наш пример: MP4

## Шаг 1: контейнер vs кодек

Важно различать:

- **контейнер** (MP4/MKV/AVI) — «коробка»;
- **кодек** (H.264/H.265) — как сжато видео.

```
$ ffprobe -v error -show_streams clip.mp4 | grep -E 'codec_name|width|height'
codec_name=h264
width=1920
height=1080
```

## Шаг 2: дорожки

В контейнере несколько дорожек: видео, аудио, субтитры, метаданные:

```
$ ffprobe -show_streams clip.mkv | grep codec_type
codec_type=video
codec_type=audio
codec_type=subtitle
```

Лишние дорожки — потенциальный носитель данных.

## Шаг 3: метаданные

```
$ ffprobe -show_format clip.mp4 | grep -iE 'creation|handler|encoder'
creation_time=2026-01-14T03:20:00Z
```

`creation_time` — когда записано (может быть подделано). `handler` — устройство/софт.

## Шаг 4: структура MP4

MP4 — набор «боксов» (`ftyp`, `moov`, `mdat`):

```
$ xxd -l 32 clip.mp4
00000000: 00000020 66747970 69736f6d ...
```

`mdat` — сами данные, `moov` — структура. Лишние/неизвестные боксы — признак
модификации.

## Шаг 5: что искать

- метаданные (время, устройство);
- лишние дорожки/боксы;
- несоответствие времени;
- встроенные данные после конца потока.

## Шаг 6: метаданные подробнее

`ffprobe` показывает и теги формата, и теги потока:

```
$ ffprobe -v quiet -print_format json -show_format clip.mp4 | grep -i tag
"encoder": "Lavf58.29.100",
"major_brand": "isom",
```

`encoder` говорит, каким софтом создан файл. Если видео снято камерой, а `encoder` — конвертер, файл перекодировали. `major_brand` — подтип MP4.

## Шаг 7: боксы MP4 и поиск лишнего

Структуру MP4 удобно смотреть `mp4dump` или вручную:

```
$ mp4dump clip.mp4 | head
[ftyp] size=32
[moov] size=...
  [mvhd] ...
[mdat] size=...
```

`moov` — описание, `mdat` — сами данные. Боксы, которых быть не должно (второй `moov` или неизвестные), — признак склейки или встраивания.

## Шаг 8: извлечение кадров и аудио

Чтобы увидеть содержимое или сравнить кадры:

```
$ ffmpeg -i clip.mp4 -vf fps=1 frame_%03d.png
$ ffmpeg -i clip.mp4 -vn -acodec copy audio.aac
```

Кадры используют для анализа сцен, аудио — для распознавания и сравнения.

## Шаг 9: скрытые данные

После конца потока или в лишних дорожках могут лежать данные:

```
$ binwalk clip.mp4
$ strings clip.mp4 | grep -iE 'PK|nto{'
```

`binwalk` находит встроенные архивы и файлы, `strings` — читаемые метки. Дополнительная дорожка субтитров тоже может нести payload.

## Шаг 10: что искать

- несоответствие `creation_time` и `encoder`;
- лишние/неизвестные боксы;
- дополнительные дорожки;
- данные после `mdat`;
- расхождение числа кадров и длительности.

## Шаг 11: контейнеры MKV и AVI

Не всё видео — MP4. Matroska (MKV) устроен иначе — это EBML-дерево из элементов:

```
$ mkvinfo clip.mkv | head
+ EBML head
+ Segment, size ...
  + Tracks
```

AVI — RIFF-контейнер с блоками `hdrl`/`movi`. Знание структуры важно: у каждого контейнера свои «лишние» элементы, где прячут данные.

## Шаг 12: проверка монтажа

При монтаже видео разрезают и склеивают — остаются швы. Ключевые кадры (I-frames) идут периодически; разрыв в их последовательности или скачок временных меток (PTS) указывает на склейку:

```
$ ffprobe -v error -show_frames -select_streams v clip.mp4 | grep -E 'pict_type|pkt_pts_time' | head
```

Неравномерные PTS, повторяющиеся кадры и «двойные» заголовки — признаки редактирования.

## Шаг 13: восстановление повреждённого видео

Если файл не открывается (обрезан заголовок), помогает пересборка:

```
$ untrunc broken.mp4 reference.mp4 fixed.mp4
$ ffmpeg -i broken.mp4 -c copy remux.mp4
```

`untrunc` берёт структуру из целого «эталонного» файла, `ffmpeg` перепаковывает поток без перекодирования. Часто так возвращают целостное видео для анализа.

## Шаг 14: практический итог

Порядок разбора видеофайла:

1. определить контейнер и кодеки (`ffprobe`);
2. прочитать метаданные (`creation_time`, `encoder`);
3. осмотреть боксы/элементы на лишнее;
4. проверить временные метки на монтаж;
5. извлечь кадры, аудио и скрытые вложения.

Так видео превращается из «плеера» в источник доказательств.

## Практика: проверяем подлинность записи

Дано видео «с камеры наблюдения». Проверяем.

```
$ ffprobe -v error -show_format clip.mp4 | grep -iE 'creation|encoder|handler'
creation_time=2026-01-14T03:20:00Z
encoder=Lavf60.3.100
```

`encoder=Lavf...` — это ffmpeg. Настоящая камера пишет своим энкодером, а не ffmpeg. Значит, запись **перекодировали** — возможно, монтировали.

Ищем швы по временным меткам:

```
$ ffprobe -v error -show_frames -select_streams v clip.mp4 | grep pkt_pts_time | head
pkt_pts_time=0.000
pkt_pts_time=0.040
pkt_pts_time=0.080
pkt_pts_time=0.160   <-- скачок
```

Скачок в 0.080 → 0.160 означает пропуск кадров — место склейки.

Проверяем структуру на лишнее:

```
$ binwalk clip.mp4 | head
DECIMAL  HEXADECIMAL  DESCRIPTION
0        0x0          ISO Media, MP4
1048576  0x100000     Zip archive data
```

Zip-архив внутри видео — явная вставка. Извлекаем и смотрим содержимое.

## Что важно

- Несоответствие `encoder` устройству — признак перекодирования.
- Скачки PTS указывают на монтаж.
- `binwalk` находит встроенные посторонние данные.
- Метаданные + структура вместе дают вывод о подлинности.

## Субтитры, главы и вложения

В контейнере прячется больше, чем видео и звук.

**Дорожка субтитров.** В MKV/MP4 может быть дорожка текста:

```
$ ffmpeg -i clip.mkv -map 0:s:0 subs.srt
```

Субтитры часто несут диалоги, которых нет в звуке (перевод, расшифровка). Иногда в них же прячут данные.

**Главы.** Контейнер хранит метки глав:

```
$ ffprobe -show_chapters clip.mkv
```

Список глав восстанавливает структуру записи и время событий.

**Вложения.** В MKV можно вложить файлы (шрифты, скрипты):

```
$ mkvextract clip.mkv attachments 1:out.bin
```

Вложенный файл — потенциальный носитель данных или вредоносной нагрузки.

**Метаданные потока.** Теги вроде `title`, `comment`, `location` (для записей с телефона) дают контекст:

```
$ ffprobe -show_entries format_tags clip.mkv
```

**Вывод.** Видео — это мини-архив. Перед выводом о подлинности перечисли все дорожки, главы и вложения: то, что «спрятано», часто лежит именно там.

## Что запомнить по видео-форензике

Коротко о главном. Видеофайл — это контейнер, внутри которого лежат дорожки (видео, звук, субтитры, вложения). Поэтому смотри не только на картинку: перечисляй все дорожки и главы. Метаданные (`creation_time`, `encoder`) подсказывают, чем и когда файл создан; несоответствие устройства и энкодера — признак перекодирования. Скачки временных меток указывают на монтаж, а `binwalk` находит встроенные посторонние данные. Если файл повреждён, пересборка `ffmpeg`/`untrunc` часто возвращает целостный поток для анализа. Держи в голове связку «контейнер → метаданные → дорожки → время» — и любой видеофайл перестанет быть чёрным ящиком.

## Что мы теперь знаем

- Контейнер ≠ кодек.
- В контейнере несколько дорожек.
- Метаданные: creation_time, handler.
- MP4 — набор боксов; лишние — подозрительны.
- Дополнительные дорожки — носитель данных.

- Теги формата (`encoder`, `major_brand`) выдают перекодирование.
- `mp4dump` показывает боксы; лишние — подозрительны.
- `ffmpeg` извлекает кадры и аудио.
- `binwalk`/`strings` находят встроенные данные.
- Доп. дорожки — потенциальный носитель.

- У MKV (EBML) и AVI (RIFF) своя структура и свои «лишние» элементы.
- Скачки PTS и разрывы I-frames указывают на монтаж.
- `untrunc`/`ffmpeg` восстанавливают обрезанные файлы.
- Порядок: контейнер → метаданные → боксы → монтаж → извлечение.

## Если не сработало

- Формат неизвестен? Используй `ffprobe`.
- Нужны кадры? Извлеки `ffmpeg`.
- Данные повреждены? Восстанавливай по боксам.
