## Вопрос, с которого всё начинается

Видео — доказательство или носитель данных. Нужно понять: какой контейнер, какие
дорожки, что в метаданных, нет ли скрытого. Разберём.

## Наш пример: MP4

## Шаг 1: контейнер vs кодек

Важно различать:

- **контейнер** (MP4/MKV/AVI) — «коробка»;
- **кодек** (H.264/H.265) — как сжато видео.

```
$ ffprobe -v error -show_streams clip.mp4 | grep -E 'codec_name|width|height'
codec_name=h264
width=1920
height=1080
```

## Шаг 2: дорожки

В контейнере несколько дорожек: видео, аудио, субтитры, метаданные:

```
$ ffprobe -show_streams clip.mkv | grep codec_type
codec_type=video
codec_type=audio
codec_type=subtitle
```

Лишние дорожки — потенциальный носитель данных.

## Шаг 3: метаданные

```
$ ffprobe -show_format clip.mp4 | grep -iE 'creation|handler|encoder'
creation_time=2026-01-14T03:20:00Z
```

`creation_time` — когда записано (может быть подделано). `handler` — устройство/софт.

## Шаг 4: структура MP4

MP4 — набор «боксов» (`ftyp`, `moov`, `mdat`):

```
$ xxd -l 32 clip.mp4
00000000: 00000020 66747970 69736f6d ...
```

`mdat` — сами данные, `moov` — структура. Лишние/неизвестные боксы — признак
модификации.

## Шаг 5: что искать

- метаданные (время, устройство);
- лишние дорожки/боксы;
- несоответствие времени;
- встроенные данные после конца потока.

## Что мы теперь знаем

- Контейнер ≠ кодек.
- В контейнере несколько дорожек.
- Метаданные: creation_time, handler.
- MP4 — набор боксов; лишние — подозрительны.
- Дополнительные дорожки — носитель данных.

## Если не сработало

- Формат неизвестен? Используй `ffprobe`.
- Нужны кадры? Извлеки `ffmpeg`.
- Данные повреждены? Восстанавливай по боксам.
