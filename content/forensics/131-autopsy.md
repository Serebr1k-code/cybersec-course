## Вопрос, с которого всё начинается

Вам дали образ диска на несколько гигабайт. Внутри — сотни тысяч файлов. Искать улики вручную через `fls`/`icat` можно, но долго: браузерная история, реестр, почта, картинки — всё в разных местах. Хочется инструмент, который **сам** извлечёт типовые артефакты и покажет их в удобном виде. Это и есть Autopsy.

## Наш пример: образ usb.E01

У нас есть образ флешки `usb.E01`. Прогоним его через **Autopsy** — графическую платформу поверх The Sleuth Kit (того самого набора `fls`/`icat` из прошлых уроков).

## Шаг 1: создаём кейс и добавляем образ

Работа в Autopsy идёт по шагам:

1. **New Case** — имя, каталог для результатов, тип (Single-user).
2. **Add Data Source** — образ диска (E01, RAW, VMDK, L01) или локальный диск.
3. **Configure Ingest** — выбрать модули обработки.
4. **Analyze** — дождаться обработки.

```bash
# Современный Autopsy 4.x — Java-приложение с GUI
$ ./autopsy-4.21.0/bin/autopsy
```

На больших образах обработка идёт часами, поэтому модули выбирают осознанно.

## Шаг 2: ingest-модули

**Ingest-модули** — это плагины, автоматически извлекающие артефакты. Основные:

| Модуль | Что извлекает |
|--------|---------------|
| Recent Activity | веб-история, cookies, загрузки (Chrome/Firefox/IE/Edge) |
| Windows Registry | реестр, USB, автозапуск, пользователи |
| Email Parser | PST/OST/MBOX |
| File Type Identification | определение типов по сигнатурам |
| Extension Mismatch | несоответствие расширения и содержимого |
| Picture Analyzer | EXIF, геолокация |
| Keyword Search | поиск по ключевым словам/regex |
| Hash Lookup | известные файлы (NSRL), вредоносные хеши |

## Шаг 3: ищем флаг через keyword search

Для CTF самое полезное — модуль **Keyword Search**. Он ищет строки и регулярные выражения. Флаг обычно имеет вид `flag{...}`, поэтому задаём regex:

```
flag\{[^}]+\}
```

Запускаем ingest и идём в **Results → Keyword Hits**:

```
1. New Case "case-2024", type Single-user.
2. Add Data Source -> Disk Image -> usb.E01.
3. Ingest: Recent Activity, Windows Registry, File Type ID, Keyword Search (flag regex).
4. Analyze -> Results -> Keyword Hits -> найдено "flag{autopsy_works}".
5. Tag as Notable, Generate Report -> HTML.
```

Отчёт содержит путь к файлу, время и источник — готовый к приложению к расследованию.

## Шаг 4: просмотр артефактов

В левой панели — дерево (Data Sources, Views, Results, Tags). Полезные представления:

- **Views → File Types** — файлы по типу (images, videos, documents).
- **Views → Deleted Files** — удалённые файлы.
- **Results → Extracted Content** — извлечённые артефакты (веб, реестр, EXIF).
- **Results → Keyword Hits** — найденные строки.

## Шаг 5: Autopsy и Sleuthkit CLI

Autopsy — это Java-фронтенд над The Sleuth Kit. Понимание этого помогает: когда GUI «не показывает» что-то, то же самое достаётся через CLI и наоборот.

```bash
$ fls -r -o 2048 disk.E01        # sleuthkit умеет E01 (через libewf)
$ icat -o 2048 disk.E01 <inode> > file.bin
```

Autopsy использует те же механизмы (offsets, inode), поэтому знание sleuthkit делает работу в GUI осознанной. Для нестандартных файловых систем CLI поддерживает больше, чем GUI.

## Полный проход по нашему образу

Соберём весь разбор `usb.E01` в один непрерывный сценарий — так видно, зачем нужен каждый шаг.

1. **Создаём кейс.** `New Case` → имя `case-2024`, каталог результатов, тип Single-user. Autopsy заводит базу кейса и хранит там индексы — исходный образ не трогает.
2. **Добавляем источник.** `Add Data Source → Disk Image → usb.E01`. Autopsy распознаёт формат E01 (через libewf) и показывает разделы и файловые системы.
3. **Настраиваем ingest.** Отмечаем `Recent Activity`, `Windows Registry`, `File Type Identification`, `Keyword Search` (regex флага). Лишние модули выключаем — это экономит часы.
4. **Ждём обработку.** По мере готовности артефакты появляются в `Results`; прогресс виден в правом нижнем углу.
5. **Идём по артефактам.** Сначала `Results → Keyword Hits` (флаг), затем `Views → Deleted Files` (что удаляли), затем `Results → Extracted Content` (веб, USB, EXIF).
6. **Тегируем находки.** Правый клик → `Add Tag` → `Notable`. Без тегов находки потеряются в отчёте на сотни страниц.
7. **Строим таймлайн.** `Tools → Timeline` (или экспорт CSV в плазо) — события по времени. Здесь видно порядок: когда файл появился, когда удалён.
8. **Генерируем отчёт.** `Generate Report` → HTML/Excel/CSV. Отчёт содержит путь, inode, время и источник каждой находки.

Ключевой момент: Autopsy — не «волшебная кнопка», а ускоритель рутины. Флаг он найдёт за вас, но связать события в историю всё равно нужно головой.

## Отчёт: что включить

Формат отчёта выбирают под адресата:

| Формат | Когда нужен |
|--------|-------------|
| HTML | читаемый отчёт для команды и руководства |
| Excel (XLS) | таблицы артефактов для дальнейшей обработки |
| CSV | загрузка в другой инструмент (Timesketch, Excel) |
| KML | геоданные (EXIF) на карте |
| Portable case | передача всего кейса коллеге |

В отчёт всегда включайте хеши образа и разделов — иначе доказательство не подтвердить. Autopsy показывает хеш в свойствах Data Source.

## Частые вопросы

**Autopsy заменяет sleuthkit CLI?** Нет, это надстройка. Когда GUI не показывает нестандартную ФС, те же данные достают `fls`/`icat` напрямую.

**Можно ли работать командой?** Да — многопользовательский режим с PostgreSQL и **Central Repository**: общая база хешей и артефактов между кейсами, чтобы разные аналитики не делали одну работу.

**Что если образ не открывается?** Проверьте формат (E01/RAW/VMDK), целостность (хеш) и не подключён ли он «на запись». Для RAW иногда нужно вручную указать смещение раздела (`offset`).

**Как не утонуть в мусоре?** Гибридный поток: GUI для первого прохода и отчёта, CLI для глубоких задач; отсекайте известные хорошие файлы через Hash Lookup (NSRL).

## Что мы теперь знаем

- **Autopsy** — GUI-платформа поверх Sleuth Kit для комплексного анализа образов.
- **Ingest-модули** автоматически извлекают веб, реестр, почту, медиа, типы файлов.
- **Keyword Search** с regex (`flag\{[^}]+\}`) — быстрый способ найти флаг в CTF.
- Результаты группируются в Views/Results; находки помечают **тегами**.
- Отчёты выгружаются в HTML/Excel/KML/CSV.
- GUI не заменяет CLI: для нестандартных ФС используйте `fls`/`icat`.

## Если не сработало: ограничения и приёмы

Autopsy ускоряет обзор, но не всесилен:

- **Ingest «всё подряд».** Часы обработки ради ненужного; включайте только нужные модули.
- **Мало heap.** На больших кейсах Java падает — увеличьте heap в `autopsy.conf` (`-Xmx4g`).
- **Нестандартные ФС.** GUI поддерживает их хуже, чем sleuthkit CLI.
- **Теги.** Без пометок находки теряются в отчёте — тегируйте по ходу.
- **Целостность.** Убедитесь, что образ подключён **read-only**; Autopsy не должен в него писать.

Для командной работы есть многопользовательский режим (PostgreSQL) и **Central Repository** — общая база хешей/артефактов между кейсами. Экспортированный timeline (CSV/plaso) можно загрузить в Timesketch для совместного анализа. Оптимальный поток — гибридный: GUI для первого прохода и отчёта, CLI для глубоких задач.

## Инструмент: mmls (разметка разделов)

Прежде чем Autopsy покажет файлы, нужно понять, где на образе начинается
файловая система. Это делает `mmls` из Sleuth Kit — консольный разбор таблицы
разделов:

```
$ mmls usb.E01
DOS Partition Table
Offset Sector: 0
Units are in 512-byte sectors
      Slot      Start        End          Length       Description
00:  Meta    0000000000   0000000000   0000000001   Primary Table (#0)
01:  -----   0000000000   0000002047   0000002048   Unallocated
02:  00:00   0000002048   0000409599   0000407552   NTFS (0x07)
```

`Start` раздела (в секторах) — это offset, с которого начинается ФС; его же
принимают `fls`/`icat`. Autopsy делает то же самое графически, но `mmls`
показывает разметку напрямую и незаменим, когда GUI не открывает образ.

## Карта: действие в GUI → команда Sleuth Kit

Autopsy скрывает за кнопками вызовы The Sleuth Kit. Если держать соответствие в голове,
GUI перестаёт быть «чёрным ящиком», а CLI — запасным аэродромом, когда графика не открывает
нестандартную ФС.

| Действие в Autopsy | Эквивалент в CLI |
|--------------------|------------------|
| Разметка разделов в дереве | `mmls image.E01` |
| Список файлов (в т.ч. удалённых) | `fls -r -o OFFSET image.E01` |
| Извлечь файл по inode | `icat -o OFFSET image.E01 INODE > file.bin` |
| Метаданные inode (времена) | `istat -o OFFSET image.E01 INODE` |
| Keyword Search | `grep -a -r -E 'flag\{[^}]+\}' /mnt/evidence/` |
| Timeline (CSV-экспорт) | `fls -m / -r -o OFFSET image.E01 > body.txt` → `mactime -b body.txt` |
| Проверка типа по сигнатуре | `file` / `foremost` |

Практический приём: когда Autopsy «не видит» раздел, повтори `mmls`, возьми `Start` сектора
и передай его в `-o`. Так же находится истина, если GUI показал пустое дерево.

## Автоматизация первого прохода из CLI

Когда образов много, GUI-клики не масштабируются. Минимальный скриптованный триаж:

```bash
$ mmls usb.E01                                   # находим offset NTFS-раздела
$ fls -r -o 2048 usb.E01 | head                  # обзор дерева
$ fls -r -o 2048 -p usb.E01 > listing.txt        # полный листинг с путями
$ grep -aEi 'flag\{|nto\{' listing.txt           # быстрый поиск метки в метаданных
$ icat -o 2048 usb.E01 4 | strings | grep nto    # достаём подозрительный inode
```

Такой прогон занимает секунды и сразу подсказывает, стоит ли вообще запускать тяжёлый
ingest. Ограничение: `grep` по листингу ищет только в **метаданных** (имена, пути), а не в
содержимом файлов — для содержимого нужен `icat`/`foremost` или keyword-модуль Autopsy.

- **CTF:** быстрый первый проход по образу.
