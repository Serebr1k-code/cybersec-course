FAT — старейшая из массово используемых файловых систем и до сих пор самая распространённая на съёмных носителях: флешки, SD-карты камер, прошивки, а также **EFI-раздел** любого UEFI-диска. Она устроена предельно просто — нет журналов, нет MFT, нет B-деревьев. Всё видно прямо в hex, поэтому FAT идеальна для обучения и для ручного recovery, когда автоматические инструменты не справляются.

## Загрузочный сектор и BPB

Первый сектор тома (offset 0) — загрузочный сектор. В нём лежит **BIOS Parameter Block (BPB)** — все геометрические параметры ФС. Байт по offset 3 — метка «FAT12», «FAT16» или «FAT32».

| Смещение | Размер | Поле | Значение |
|---------:|-------:|------|----------|
| 0x00 | 3 | jump | `EB 3C 90` (или `EB 58 90`) |
| 0x03 | 8 | OEM name | напр. `MSDOS5.0` |
| 0x0B | 2 | bytes/sector | обычно 512 |
| 0x0D | 1 | sectors/cluster | 1,2,4,8…64 |
| 0x0E | 2 | reserved sectors | для FAT32 обычно 32 |
| 0x10 | 1 | FAT count | обычно 2 |
| 0x11 | 2 | root entries | только FAT12/16 |
| 0x13 | 2 | total sectors 16 | если 0 — смотреть offset 0x20 |
| 0x15 | 1 | media descriptor | `F8` (жёсткий), `F0` (флешка) |
| 0x16 | 2 | FAT size 16 | размер одной таблицы в секторах |
| 0x20 | 4 | total sectors 32 | для больших томов |
| 0x24 | 4 | FAT size 32 | размер таблицы (FAT32) |
| 0x2C | 4 | root cluster | первый кластер корня (FAT32) |
| 0x1FE | 2 | signature | `55 AA` |

Ключевой вывод: **чтобы найти данные, нужно вычислить смещения**. Формулы:

- `fat_start = reserved_sectors * bytes_per_sector`
- `data_start = (reserved + fats*fat_size) * bytes_per_sector` (для FAT12/16 ещё + root_entries*32/512 секторов)
- `cluster_size = sectors_per_cluster * bytes_per_sector`

## Таблицы FAT и цепочки кластеров

FAT — это массив записей по одному элементу на кластер. Каждый элемент говорит, что делать дальше: указатель на следующий кластер цепочки или маркер конца/свободности.

| ФС | Размер элемента | Признаки |
|----|-----------------|----------|
| FAT12 | 12 бит | EOC ≥ 0xFF8, bad = 0xFF7 |
| FAT16 | 16 бит | EOC ≥ 0xFFF8, bad = 0xFFF7 |
| FAT32 | 32 бит (28 значащих) | EOC ≥ 0x0FFFFFF8, bad = 0x0FFFFFF7 |

Спец-значения: `0x000` — кластер свободен; `0x001` — зарезервирован; `0x002..max` — следующий кластер; EOC (End Of Chain) — конец файла; BAD — сбойный кластер.

Файл — это **цепочка кластеров**: в записи каталога хранится первый кластер, а дальше вы идёте по FAT. Обрыв цепочки (`0x000` посередине) — признак удалённого или повреждённого файла.

```bash
# Дамп начала таблицы FAT (после вычисления fat_start)
xxd -s <fat_start> -l 64 disk.img
# FAT32: 0x0FFFFFF8 = EOC; читаем little-endian 4 байта на кластер
```

## Каталоги, 8.3 и длинные имена (LFN)

Запись каталога — 32 байта. Для FAT12/16 корневой каталог лежит в фиксированной области сразу за таблицами; для FAT32 корень — обычная цепочка кластеров.

| Смещение | Размер | Поле |
|---------:|-------:|------|
| 0x00 | 8 | имя (8.3, пробелы) |
| 0x08 | 3 | расширение |
| 0x0B | 1 | атрибуты (`0x01` RO, `0x02` hidden, `0x04` system, `0x08` volume, `0x10` dir, `0x20` archive) |
| 0x0C | 2 | время создания |
| 0x0E | 2 | дата создания |
| 0x1A | 2 | первый кластер (lo) |
| 0x1C | 4 | размер файла |
| 0x14 | 2 | первый кластер (hi, для FAT32) |

Первый байт имени кодирует статус: `0x00` — конец каталога, `0xE5` — **удалённая запись**, `0x05` — имя начинается с символа 0xE5. Именно `0xE5` — ключ к recovery: запись помечена удалённой, но остальные поля (размер, первый кластер, время) могут быть целы.

Длинные имена (LFN) хранятся в **дополнительных** записях с атрибутом `0x0F`, идущих перед записью 8.3. Каждая LFN-запись несёт 13 символов в UTF-16LE, номер и контрольную сумму. Удаление очищает первый байт (`0xE5`) и у LFN-записей — так по «осиротевшим» LFN можно восстановить имя удалённого файла.

## Инструменты и флаги

```bash
# Определить ФС и параметры
fsstat -o <offset> disk.img           # печатает BPB, cluster size, fat_start
file -s disk.img

# Листинг и восстановление (sleuthkit)
fls -o <offset> -r disk.img           # рекурсивно, все записи
fls -o <offset> -r -d disk.img        # только удалённые (recoverable)
icat -o <offset> disk.img <inode> > recovered.bin

# Прямое монтирование (read-only!)
sudo mount -o ro,loop,offset=<bytes> disk.img /mnt/fat

# Автоматический recovery
photorec /dev/loop0                   # по сигнатурам, игнорируя ФС
foremost -t all -i disk.img -o out/   # каринг по заголовкам

# fatcat (Brian Carrier) — низкоуровневый доступ
fatcat -f disk.img info               # BPB
fatcat -f disk.img ls /               # список
fatcat -f disk.img cat /file.txt      # чтение
```

`fsstat` даёт готовые `First FAT Sector`, `First Data Sector`, `Cluster Size` — не нужно считать вручную. `fls -d` показывает удалённые записи, `icat` читает их содержимое по inode (номер записи каталога).

## Разобранный пример: восстановление удалённого файла

```bash
$ file usb.img

         sectors/cluster 8, Media 0xf8, sectors 204800 (volumes > 32 MB),
         FAT (32 bit), sectors/FAT 1595, reserved 32, serial 0x1a2b3c4d
$ mmls usb.img
DOS Partition Table
Offset Sector: 0
Units are in 512-byte sectors
      Slot      Start        End          Length       Description
      00:  -----   0000000000   0000002047   0000002048   Primary Table (#0)
      01:  -----   0000002048   0000004095   0000002048   Unallocated
      02:  00:00   0000004096   000000206847 000000202752  Win95 FAT32 (0x0b)
$ fsstat -o 4096 usb.img | head -20
```

Здесь `*` в выводе `fls` — признак удалённой записи. `icat` читает цепочку кластеров из FAT; пока кластеры не перезаписаны, содержимое восстанавливается целиком. Для `secret/notes.txt` путь сохранился, потому что запись каталога не переиспользована.

## Краевые случаи и подводные камни

- **Две таблицы FAT.** Обычно их две (копии). Если они расходятся — доверяйте более консистентной; при recovery иногда вторая таблица хранит старую цепочку удалённого файла.
- **Корень FAT12/16 в фиксированной области.** Для FAT32 корень — цепочка кластеров, начинающаяся с `root cluster` (offset 0x2C).
- **Fragmentация.** Цепочка может идти вразброс; нельзя просто читать последовательные кластеры — обязательно идти по FAT.
- **`0xE5` только у первой буквы.** У LFN-записей стирается первый байт последовательности, а не сама буква; имя собирается из «осиротевших» LFN.
- **Перезапись кластеров.** После удаления новые файлы могут занять те же кластеры — тогда recovery невозможен, остаётся только carving по сигнатурам (`photorec`).
- **EFI-раздел.** Это обычно FAT32; в нём лежат загрузчики и конфиги — частый источник улик о загрузке нештатной ОС.
- **`mount` меняет метку/access time.** Всегда `-o ro`; в идеале — через sleuthkit, не монтируя.
- **Кластер 0 и 1 зарезервированы.** Первый реальный кластер данных — 2.

## Сравнение FAT12/16/32

Три варианта FAT различаются только разрядностью записей в таблице и наличием корневого каталога в фиксированной области:

| Свойство | FAT12 | FAT16 | FAT32 |
|----------|-------|-------|-------|
| Размер элемента FAT | 12 бит | 16 бит | 32 бита (28 знач.) |
| Макс. кластеров | 4084 | 65524 | ~268 млн |
| Корневой каталог | фикс. область | фикс. область | цепочка кластеров |
| Метка типа | offset 0x36 | offset 0x36 | offset 0x52 |
| Типичное применение | дискеты | маленькие тома | флешки, SD, EFI |

Определить вариант можно по метке `FAT12`/`FAT16`/`FAT32` в BPB и по числу кластеров. Для FAT32 корневой каталог — обычная цепочка, начиная с `root cluster` (offset 0x2C); для FAT12/16 — фиксированная область сразу за таблицами.

## Вычисление смещений вручную

Если `fsstat` недоступен, всё считается по BPB:

```
bytes_per_sector   = u16 @ 0x0B
sectors_per_cluster= u8  @ 0x0D
reserved_sectors   = u16 @ 0x0E
num_fats           = u8  @ 0x10
root_entries       = u16 @ 0x11        (FAT12/16)
fat_size           = u16 @ 0x16  или  u32 @ 0x24 (FAT32)

fat_start   = reserved_sectors * bytes_per_sector
root_dir_start = fat_start + num_fats*fat_size*bytes_per_sector   (FAT12/16)
data_start  = root_dir_start + root_entries*32                     (FAT12/16)
data_start  = fat_start + num_fats*fat_size*bytes_per_sector        (FAT32)
cluster_offset(n) = data_start + (n-2)*sectors_per_cluster*bytes_per_sector
```

Читая таблицу FAT, помните про **packed 12-бит** для FAT12: два элемента упакованы в 3 байта, и граница может попадать в середину байта.

## Скрытые данные в FAT-образах

Помимо удалённых файлов, FAT даёт несколько мест для сокрытия:

- **Slack space в последнем кластере.** Данные после EOF в последнем кластере могут содержать остатки прежних файлов.
- **Нераспределённые кластеры.** Кластеры с `0x000` в FAT могут хранить целые файлы.
- **Кластеры за границей тома.** Если `total sectors` занижен, «лишние» кластеры физически есть, но ФС их не видит.
- **Записи каталога `0xE5`.** Удалённые записи с сохранившимися метаданными.
- **Осиротевшие LFN.** Имена удалённых файлов.
- **Вторая копия FAT.** Может хранить старую цепочку.

```bash
# Поиск в нераспределённом пространстве
fls -o <offset> -r -d disk.img
# Каринг по всему образу
foremost -i disk.img -o out/ -t all
# Скан slack space
blkls -o <offset> disk.img > unallocated.bin
strings unallocated.bin | grep -i flag
```

## Монтирование и работа с EFI-разделом

EFI System Partition (ESP) — это FAT32 (иногда FAT16) на 100–512 МиБ. Здесь живут загрузчики (`EFI/BOOT/BOOTX64.EFI`), конфиги и иногда сторонние утилиты. Форензик ESP может выявить подмену загрузчика или лишние EFI-бинарники.

```bash
mmls disk.img                       # найти ESP (тип EF00)
fsstat -o <esp_offset> disk.img
fls -o <esp_offset> -r disk.img | grep -i efi
icat -o <esp_offset> disk.img <inode> > bootx64.efi
```

## Типичные ошибки

- **12-битная упаковка FAT12.** Прямой `u16` даст неверный указатель.
- **Считать, что root cluster = 2.** Для FAT32 он задаётся в BPB (часто 2, но не всегда).
- **Игнорировать вторую FAT.** Расхождение таблиц — сигнал повреждения/антифорензики.
- **Монтировать read-write.** Изменит access time и метку тома.
- **Забыть про EFI-раздел.** Часто содержит ключевые улики о загрузке.
- **Путать offset раздела и offset ФС.** `fsstat -o` ждёт секторы раздела, `mount offset=` — байты.

## Что дальше / решение

Порядок работы с неизвестным FAT-образом:

1. `fsstat` (или `file -s`) — получить cluster size, fat_start, data_start.
2. `fls -r -d` — увидеть удалённые записи и их inode.
3. `icat` по inode — попытаться прочитать содержимое, пока кластеры целы.
4. Не восстановилось — `photorec`/`foremost` по сигнатурам (JPEG, PNG, PDF, ZIP).
5. Проверить LFN-«сироты» и корневой каталог EFI-раздела.

Дальше логично перейти к `forensics-exfat` (эволюция FAT для больших носителей) и к карингу (`forensics-carving`), если recovery по метаданным не сработал.

## Где пригодится

- **CTF:** образы флешек, SD-карт, EFI-разделов — удалённые файлы и скрытые данные.
- **DFIR:** разбор съёмных носителей, которые не NTFS.
- **Data recovery:** восстановление фото/видео с камер.
- **Пентест:** анализ извлечённых флешек и прошивок.
