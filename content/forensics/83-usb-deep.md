## Вопрос, с которого всё начинается

Из компании ушёл сотрудник, а через неделю документы оказались у конкурента. Есть подозрение, что он скопировал их на флешку. Сама флешка недоступна — осталась только рабочая станция. Вопрос: можно ли по одной машине доказать, что флешку подключали, и что именно с неё копировали?

Windows фиксирует подключения USB в **нескольких независимых источниках**. Их корреляция и даёт доказуемую картину. Разберём станцию сотрудника от подключения устройства до конкретного файла.

## Наш пример: рабочая станция с флешкой SanDisk

Главный источник по накопителям — ветка реестра `Enum\USBSTOR`. Реестр — это база настроек Windows, разбитая на «кусты» (файлы `SYSTEM`, `SOFTWARE` и т.д.). Инструмент `rip.pl` (RegRipper) вытаскивает из куста `SYSTEM` сведения об USB:

```bash
$ rip.pl -r SYSTEM -p usb | grep -A3 USBSTOR
USBSTOR\Disk&Ven_SanDisk&Prod_Cruzer&Rev_1.00
  S/N: 4C530001120523116345
  First Install: 2024-02-10 09:00:00
  Last Connected: 2024-03-01 12:00:00
```

Читаем: подключалась флешка **SanDisk Cruzer** с серийным номером `4C530001120523116345`. Время первого подключения — 10 февраля, последнего — 1 марта. Важно не путать ветки: `Enum\USB` хранит само устройство (интерфейс), а `Enum\USBSTOR` — именно **накопители**.

## Шаг 1: находим букву диска и серийник тома

Теперь надо понять, под какой буквой флешка была видна. За это отвечает ветка `MountedDevices`, где буква сопоставлена идентификатору тома:

```bash
$ rip.pl -r SYSTEM -p mountdev | grep 'DosDevices\\E:'
\DosDevices\E: -> Serial: 4C53-0001
```

Флешка получала букву `E:`, а её **Volume Serial Number** (VSN) — `4C53-0001`. Это уникальный номер, который файловая система присваивает тому при форматировании. Запомните его: именно по нему мы свяжем флешку с конкретными файлами.

## Шаг 2: уточняем время до секунды

USBSTOR даёт время подключения, но иногда нужно точнее. Для этого есть текстовый лог `setupapi.dev.log` — журнал установки драйверов:

```bash
$ grep -iA3 'USBSTOR' setupapi.dev.log | grep 'Section start'
>>>  Section start 2024/03/01 12:00:03.123
```

Здесь время указано с точностью до миллисекунд: 1 марта, 12:00:03. Логи ротируются (`.log`, `.log1`), поэтому старые записи могут лежать в предыдущих файлах — проверяйте и их.

## Шаг 3: связываем флешку с файлами

Ключевой вопрос: какие файлы открывали с этой флешки? Ответ — в **LNK-файлах**. LNK (ярлык Windows) хранит не только путь к целевому файлу, но и **Volume Serial** тома, на котором файл лежал:

```bash
$ LECmd.exe -d Recent --csv out --csvf lnk.csv
$ grep -i 'E:\\' out/lnk.csv
secret.docx, E:\backup\secret.docx, Volume Serial: 4C53-0001, Drive: Removable
```

Смотрим: открывался файл `E:\backup\secret.docx`, и его Volume Serial — `4C53-0001`. **Он совпадает** с серийником флешки из `MountedDevices`. Это и есть прямое доказательство: документ `secret.docx` лежал именно на этой флешке.

## Шаг 4: навигация по папкам

Дополнительно проверим **Shellbags** — записи о том, какие папки пользователь открывал в Проводнике. Они лежат в файле `UsrClass.dat`:

```bash
$ SBECmd.exe -d . --csv out --csvf sb.csv && grep -i 'E:' out/sb.csv
```

Если в Shellbags есть папка `E:\backup`, значит пользователь не просто вставил флешку, а **заходил** в неё и просматривал содержимое. Это дополняет картину и подтверждает осознанные действия.

## Шаг 5: подкрепляем событиями

Наконец, в журнале событий System есть записи о подключении устройств. Событие с ID 20001 фиксирует подключение PnP-устройства:

```bash
$ evtx_dump -o json System.evtx | jq 'select(.Event.System.EventID==20001) | .Event.EventData'
```

Так мы получаем **каждое** подключение и отключение флешки с точным временем. Сопоставляя USBSTOR, setupapi и EVTX, восстанавливают полную историю использования носителя.

## Если что-то не сходится

Несколько тонкостей, которые важно учитывать, чтобы не ошибиться:

- **Серийник USBSTOR может быть подделан** прошивкой — дешёвые флешки иногда имеют одинаковый S/N. Тогда опирайтесь на время и Volume Serial.
- **Буква диска переиспользуется**: `E:` в разное время могли быть разные носители. Связывать надо по VSN, а не по букве.
- **MTP-устройства** (телефоны) пишутся не в `USBSTOR`, а в `WpdBusEnumRoot` — там другие артефакты.
- **Удалённые ключи** USBSTOR можно восстановить из теневых копий или из нераспределённого пространства диска.

```bash
$ vshadowmount disk.img /mnt/vss
$ hivexregedit --export /mnt/vss/.../SYSTEM '\ControlSet001\Enum\USBSTOR' old_usb.reg
```

## Что мы теперь знаем

- `Enum\USBSTOR` хранит модель, серийный номер и время подключения накопителя.
- `MountedDevices` сопоставляет букву диска с **Volume Serial Number** тома.
- `setupapi.dev.log` даёт точное время установки драйвера.
- LNK хранит Volume Serial — по нему файл связывается с конкретной флешкой.
- Shellbags показывают, какие папки носителя открывали; EVTX — события подключения.
- Совпадение VSN во всех источниках — доказательство связи файла с носителем.

## Куда дальше

Мы научились доказывать связь файла с конкретной флешкой. Дальше в ветке мы углубимся в файловые системы: разберём FAT, exFAT, XFS и HFS+, с которыми приходится работать на флешках и серверных томах. А пока главное запомни: **флешку связывают с файлами через Volume Serial, который совпадает в USBSTOR, MountedDevices и LNK**.

## Где пригодится

- **CTF:** задачи «с какой флешки скопировали данные».
- **DFIR:** доказательство подключения и использования носителей.
- **Корпоративные расследования:** выявление утечек через USB.
- **Threat Hunting:** аномальные подключения устройств.
- **Судебная экспертиза:** связка USB ↔ файлы через VSN.
