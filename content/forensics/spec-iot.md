## Вопрос, с которого всё начинается

В умном доме/офисе десятки устройств: датчики, камеры, хабы. Одно из них
скомпрометировано. Где смотреть? IoT-форензика — это работа с маленькими Linux-системами
и их привязкой к облаку.

## Наш пример: умная розетка

## Шаг 1: что внутри

Типичное IoT-устройство: SoC (ARM/MIPS), флеш (SPI NAND), Wi-Fi, минимальный Linux
или RTOS. Данных мало — но они есть.

```
$ binwalk -e device_firmware.bin
$ ls _device_firmware.bin.extracted/squashfs-root/
bin  etc  lib  usr
```

`binwalk` извлёк корневую ФС. Внутри — конфиги, скрипты, ключи.

## Шаг 2: локальные артефакты

- **конфиг Wi-Fi** (SSID, пароль);
- **токены облака** (привязка к аккаунту);
- **логи** (короткие, во флеше);
- **сертификаты** (для TLS к облаку).

```
$ grep -riE 'token|password|ssid' squashfs-root/etc/ | head
```

Часто токены лежат **в открытом виде** — это ключ к облачному аккаунту.

## Шаг 3: сетевые следы

IoT говорит по MQTT/CoAP/HTTP. Дамп трафика показывает:

- брокер/сервер;
- топики;
- команды.

```
$ tshark -r iot.pcap -Y 'mqtt' -T fields -e mqtt.topic | sort -u | head
```

## Шаг 4: хаб как точка сбора

Умный хаб (Hubitat/Home Assistant/SmartThings) агрегирует устройства и **хранит
логи**:

```
$ sqlite3 homeassistant.db 'SELECT * FROM states LIMIT 3;'
```

Это лучший источник: одна точка со всей историей.

## Шаг 5: облако

Производитель хранит данные в облаке. Если есть доступ к аккаунту — там история,
события, записи. Иначе — только локальные остатки.

## Что мы теперь знаем

- IoT — маленькие Linux/RTOS-устройства.
- `binwalk` извлекает ФС прошивки.
- Токены/пароли часто в открытом виде.
- Трафик — MQTT/CoAP/HTTP.
- Хаб и облако — точки сбора истории.

## Если не сработало

- Флеш зашифрована? Нужен дамп с работающего устройства.
- Нет доступа к облаку? Работай с хабом и трафиком.
- Устройство простое (RTOS)? Данных минимум — смотри сеть.

## Разбор прошивки IoT

Прошивку снимают либо с флеш-чипа программатором, либо из обновления с сайта
производителя. Разбираем извлечённую файловую систему:

```
$ binwalk -e device_firmware.bin
$ ls _device_firmware.bin.extracted/squashfs-root/
bin  etc  lib  sbin  usr  var  www
$ cat _device_firmware.bin.extracted/squashfs-root/etc/passwd
root:x:0:0:root:/root:/bin/sh
admin:$1$abc$...:0:0:admin:/:/bin/sh
```

Прошивка даёт всё сразу: учётки, скрипты запуска, конфиги, ключи. Пароль
`admin` часто хеширован слабым DES-crypt — его подбирают за секунды.

## Таблица: артефакты IoT

| Артефакт | Где | Что даёт |
|---|---|---|
| Учётные записи | `/etc/passwd`, `/etc/shadow` | вход в устройство |
| Wi-Fi конфиг | `/etc/config/wireless` | SSID и пароль |
| Токен облака | `/etc/config/*`, NVRAM | доступ к аккаунту |
| Сертификаты | `/etc/ssl/` | ключ для TLS к облаку |
| Скрипты запуска | `/etc/init.d/` | что и как стартует |
| Веб-интерфейс | `/www/` | уязвимости, API |
| Логи | `/var/log/`, NVRAM | события устройства |

Токен облака — самый ценный артефакт: он открывает аккаунт, к которому
привязаны все устройства пользователя, а не только это.

## Пример: извлечение токена облака

Ищем токены и ключи в конфигах:

```
$ grep -riE 'token|api_key|secret|password' squashfs-root/etc/ | head
squashfs-root/etc/config/cloud: option token 'eyJhbGciOiJIUzI1NiIs...'
```

JWT-токен в открытом виде — прямой путь в облачный аккаунт. Проверь его срок
жизни и права (декодировав payload):

```
$ echo 'eyJhbGciOiJIUzI1NiIs...' | cut -d. -f2 | base64 -d 2>/dev/null
{"sub":"user_12345","exp":1770000000,"scope":"device:control"}
```

## Хаб и облако

Умный хаб агрегирует устройства и хранит историю — это лучший источник:

```
$ sqlite3 homeassistant.db "SELECT entity_id, state, last_changed FROM states
    ORDER BY last_changed DESC LIMIT 3;"
light.kitchen|on|2026-03-11 03:41:00
```

Облако производителя хранит события и записи камер. Если есть доступ к
аккаунту (через украденный токен), история доступна за месяцы. Без него
остаются только локальные остатки на самом устройстве.

## Если сработало

Нашёл токен/пароль — оцени радиус и зафиксируй:

1. Проверь токен: срок жизни, права, к какому аккаунту привязан.
2. Выгрузи конфиги и логи устройства с хешами.
3. Проверь хаб — он даёт историю по всем устройствам.
4. Определи, к каким ещё устройствам даёт доступ найденный токен.
5. Ротируй скомпрометированные ключи через веб-интерфейс/облако.

Один токен часто управляет всеми устройствами аккаунта — не ограничивайся
одним «умным» устройством при оценке ущерба.

## Ограничения и подводные камни

- **Зашифрованная флеш.** Некоторые устройства шифруют раздел — нужен дамп с
  работающего устройства и ключ из памяти.
- **RTOS без ФС.** Простые устройства не имеют файловой системы — данных
  минимум, работай с сетью.
- **Облако недоступно.** Без доступа к аккаунту история в облаке потеряна.
- **Обновление затирает следы.** Прошивка могла быть обновлена, стерев
  локальные артефакты.
- **Разнородность.** Производители используют разные SoC и форматы — единого
  подхода нет.
