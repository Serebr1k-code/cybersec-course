## Вопрос, с которого всё начинается

Тебе дали образ `damaged.img`. Открываешь — и ничего: ни один инструмент не видит
разделов. А данные где-то там точно есть, ведь диск не пустой. Как найти раздел, если
**таблица разделов** повреждена?

Таблица разделов — это карта: она говорит, где на диске начинается и кончается каждая
область. Потеря карты не означает потерю данных. В этом уроке мы восстановим раздел на
сломанном образе.

## Наш пример: образ, который «не открывается»

```bash
$ mmls damaged.img
Cannot determine partition type
```

`mmls` (из набора Sleuth Kit) показывает карту разделов образа. Раз карты нет — смотрим
первый сектор вручную:

```bash
$ xxd -l 16 damaged.img
00000000: 0000 0000 0000 0000 0000 0000 0000 0000  ................
```

Первые байты занулены. Значит, таблица разделов уничтожена — но не обязательно
безвозвратно.

## Шаг 1: что вообще такое таблица разделов

Диск — это последовательность **секторов** по 512 байт. Первый сектор (LBA 0) обычно
хранит **таблицу разделов**. Есть два основных формата: старый **MBR** и современный
**GPT**.

В MBR первые 446 байт — код загрузчика, затем четыре записи разделов по 16 байт, а в
самом конце — сигнатура `55 AA`. В каждой записи лежат смещение начала раздела и его
длина. Именно эти числа и потерялись.

## Шаг 2: GPT хранится дважды

Если бы это был MBR, восстановление было бы сложнее. Но посмотрим на конец диска — там
может лежать **резервная копия GPT**. Формат GPT специально хранит свою таблицу
дважды: в начале (сектор 1) и в конце диска.

```bash
$ xxd -s -512 damaged.img | tail -2
000001f0: ... 4546 4920 5041 5254 ...            EFI PART
```

Байты `EFI PART` — сигнатура заголовка GPT. Резервная копия цела! Значит, разделы
можно восстановить.

## Шаг 3: восстанавливаем из резервной копии

`gdisk` умеет пересобрать таблицу из backup-копии:

```bash
$ gdisk damaged.img
Command (? for help): r
Recovery/transformation command (? for help): b
Recovery/transformation command (? for help): w
```

`r` — режим восстановления, `b` — «rebuild from backup GPT», `w` — записать. **Важно:**
работаем с копией образа, потому что `w` пишет на диск. Проверяем результат:

```bash
$ mmls damaged.img
GUID Partition Table (EFI)
002:  000:00    0000002048   0000206847   0000204800   Linux (0x83)
```

Раздел снова виден: начинается с сектора 2048, длина — 204800 секторов. Теперь можно
читать файловую систему:

```bash
$ fsstat -o 2048 damaged.img | head
File System Type: Ext4
```

Флаг `-o 2048` — то самое смещение начала раздела в секторах. Оно же понадобится для
`fls -o 2048` и `icat -o 2048`.

## Шаг 4: если резервной копии нет

Тогда разделы ищут по **сигнатурам файловых систем** — характерным байтам в начале
каждой ФС:

```bash
$ grep -aboP 'FILE' disk.img | head      # кандидаты NTFS ($MFT)
$ grep -aboP '\x53\xEF' disk.img | head  # суперблок ext (магия 0xEF53)
$ testdisk disk.img                      # интерактивный поиск разделов
```

`grep -aboP` ищет байтовый шаблон и печатает смещение; `testdisk` сканирует весь диск и
предлагает найденные разделы. К этому прибегают, когда обе копии таблицы утеряны.

## Шаг 5: читаем MBR-разметку

Если диск размечен через MBR, картина проще:

```bash
$ xxd -l 64 disk.img
00000000: 33c0 8ed0 bc00 7c8e c08e d8be 007c bf00  3.....|......|..
...
000001c0: 0101 0083 fe3f 2000 0000 0800 0000 00    .....? .........
000001f0: 0000 0000 0000 0000 0000 0000 0000 55aa  ..............U.
```

`55 AA` в конце подтверждает MBR, `80` — активный раздел, а `83` в записи — тип
раздела «Linux». Таблица типов пригодится постоянно:

| Тип | Значение |
|-----|----------|
| 0x07 | NTFS / exFAT |
| 0x0B/0x0C | FAT32 |
| 0x83 | Linux |
| 0x82 | Linux swap |
| 0x8E | Linux LVM |
| 0xEE | GPT protective MBR |

## Шаг 6: инструменты

```bash
$ parted disk.img unit s print     # обзор разметки
$ fdisk -l disk.img                # MBR
$ gdisk -l disk.img                # GPT
$ sfdisk -d disk.img > layout.txt  # сохранить разметку
$ sfdisk disk.img < layout.txt     # восстановить
```

`sfdisk` сохраняет таблицу в текстовый файл — это и страховка перед правками, и способ
клонировать разметку на другой диск.

## Шаг 7: protective MBR и гибридные схемы

GPT-диск всё равно содержит в секторе 0 **protective MBR** — одну запись типа `0xEE`,
покрывающую весь диск. Это нужно, чтобы старые инструменты, читающие только MBR, не
«портили» GPT, приняв его за пустое место. Признак GPT: `0xEE` в MBR плюс `EFI PART` в
секторе 1.

```bash
$ xxd -l 512 disk.img | grep '1c0:'
000001c0: 0100 ee3f ...   # тип 0xEE = protective MBR
```

**Гибридный MBR** — нестандартная схема для dual-boot: protective MBR дополнен реальными
записями для legacy-загрузчиков. Это риск: правка одной таблицы не синхронизируется с
другой, и разделы могут «пропадать».

## Шаг 8: если утеряны обе таблицы

Тогда разделы ищут по суперблокам файловых систем:

- **ext4** — резервные superblock (`dumpe2fs` их перечисляет), `e2fsck -b 32768`.
- **NTFS** — `$MFT` начинается с сигнатуры `FILE`.
- **FAT** — загрузочный сектор с `FAT32` и сигнатурой `55 AA`.

```bash
$ grep -aboP 'FILE' disk.img | head          # кандидаты NTFS
$ testdisk disk.img                          # интерактивный поиск
```

## Шаг 9: сохраняем таблицу до правок

```bash
$ dd if=disk.img of=mbr.bak bs=512 count=1 status=none
$ sfdisk -d disk.img > layout.txt
$ gdisk -b gpt.bin disk.img      # backup GPT в файл
```

Перед любой правкой сохраните исходную таблицу — это и улика, и страховка.

## Что мы теперь знаем

- Таблица разделов — это карта диска; её потеря не значит потерю данных.
- MBR живёт в секторе 0 и заканчивается сигнатурой `55 AA`.
- GPT хранит копию в конце диска — из неё таблицу восстанавливают `gdisk`.
- `mmls` показывает карту и смещение каждого раздела; это смещение идёт в `fsstat -o`.
- Если обе копии утеряны — разделы ищут по сигнатурам ФС (`grep -aboP`, `testdisk`).

## На что смотреть дальше

- **Секторы против байтов** — `fsstat -o` принимает секторы, а `mount offset=` — байты.
- **Не писать на образ** — `testdisk`/`gdisk` могут писать; работайте с копией.
- **Расширенные разделы** — логические тома лежат в цепочке EBR, их легко пропустить.
- **CRC заголовка GPT** — «валидный» на вид заголовок может быть битым.

## Куда дальше

Мы научились находить разделы. Но и внутри раздела данные могут быть «потеряны»: файл
удалён, запись каталога стёрта. В следующем уроке мы восстановим удалённый файл прямо
из файловой системы. А пока запомни: **таблица разделов хранится дважды — проверь конец
диска**.

## Где пригодится

- **CTF:** образы со скрытыми или битыми разделами.
- **Data recovery:** восстановление карты разделов после сбоя.
- **Incident Response:** понимание структуры диска до анализа ФС.
- **Криминалистика:** работа с нестандартными раскладками.
- **Виртуализация:** конвертация и разбор виртуальных дисков.
