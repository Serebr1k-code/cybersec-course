## Вопрос, с которого всё начинается

Тебе дали файл `stego.png` — обычная картинка. На вид ничего необычного. Но задание
говорит, что внутри спрятан флаг. Как достать данные, которых «не видно»?

Это **стеганография** — сокрытие самого факта передачи данных (в отличие от
криптографии, которая скрывает лишь содержание). В этом уроке мы пройдём по картинке
всеми основными способами и найдём флаг.

## Наш пример: stego.png

```bash
$ file stego.png
stego.png: PNG image data, 800 x 600, 8-bit/color RGB, non-interlaced
```

Файл открывается как картинка. Начинаем с самого простого — метаданных.

## Шаг 1: метаданные и чанки

Данные часто прячут в **EXIF** (метаданные фото) или в текстовых чанках PNG:

```bash
$ exiftool stego.png | grep -i comment
Comment: not here
$ pngcheck -v stego.png
tEXt chunk: "Comment"
```

`exiftool` читает метаданные, `pngcheck` разбирает внутреннюю структуру PNG по чанкам.
Чанки `tEXt`/`zTXt`/`iTXt` — популярный контейнер для текста. Здесь попался ложный след
(«not here»), идём дальше.

## Шаг 2: данные после конца файла

Самый простой приём — дописать данные **после** конца изображения:

```bash
$ binwalk stego.png
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             PNG image, 800 x 600
```

`binwalk` ищет сигнатуры внутри файла. Здесь второй сигнатуры нет — значит, ничего не
дописано. Если бы была, её вырезали бы через `dd if=stego.png of=hidden.zip bs=1
skip=<offset>`.

## Шаг 3: LSB — младшие биты

Каждый пиксель PNG хранит цвет в байтах. Младший бит каждого байта почти не влияет на
вид картинки — его и используют для сокрытия. Инструмент `zsteg` перебирает все каналы
и битовые плоскости:

```bash
$ zsteg stego.png
[+] 1 b1,rgb,lsb,xy       .. text: "CTF{lsb_in_png}"
```

Читается это так: `b1` — первый бит, `rgb` — по каналам, `lsb` — младший бит, `xy` —
порядок. Найденный текст и есть флаг. `zsteg -a` перебирает **все** методы, `zsteg -E
'b1,bgr,lsb,xy'` извлекает конкретный.

## Шаг 4: стего с паролем

Некоторые инструменты (например, `steghide`) встраивают данные **с паролем** и
шифрованием. Без пароля извлечь нельзя, но пароль можно подобрать словарём:

```bash
$ steghide extract -sf image.jpg
Enter passphrase:
$ stegseek image.jpg /usr/share/wordlists/rockyou.txt
[i] Found passphrase: "sunshine"
[i] Extracting to "image.jpg.out"
```

`stegseek` проверяет миллионы паролей в секунду — это быстрая замена медленному
`stegcracker`. Если в задании есть JPEG и намёк на пароль — начинайте с него.

## Шаг 5: аудио — спектрограмма

В аудио текст часто прячут так, что он «виден» только на спектре:

```bash
$ sox audio.wav -n spectrogram -o spec.png
$ ffmpeg -i audio.wav -lavfi showspectrumpic=s=1024x512 spec.png
```

Откройте `spec.png` — иногда там прямо написаны буквы. Для WAV бывает и LSB:

```bash
$ stegoveritas audio.wav
```

`stegoveritas` — мета-инструмент: прогоняет десятки тестов (метаданные, LSB, палитры,
appended data) и складывает результаты в каталог. Удобен как «первый проход».

## Шаг 6: документы и архивы

Прячут и в документах: скрытый белым текстом, макросы, вложения в PDF, лишние байты в
ZIP:

```bash
$ unzip -o doc.docx -d docx_unz/ && grep -ri 'flag' docx_unz/ | head
$ pdf-parser.py --search flag doc.pdf
$ unzip -l a.zip && tail -c 64 a.zip | strings
```

## Справочная таблица методов

| Формат | Типичный метод | Инструмент |
|--------|----------------|-----------|
| PNG | LSB, tEXt/zTXt | `zsteg`, `pngcheck` |
| JPEG | DCT, steghide, appended | `steghide`, `stegseek`, `binwalk` |
| GIF | палитра, LSB | `stegsolve`, `zsteg` |
| WAV | LSB, спектр | `sox`, `stegoveritas` |
| MP3 | appended, ID3 | `binwalk`, `exiftool` |
| Документы | метаданные, скрытый текст | `exiftool`, `oletools` |

## Методика: как не пропустить

Метод стего заранее неизвестен, поэтому идём по чек-листу:

1. **Определите истинный тип** (`file -k`) — расширение врёт.
2. **Метаданные** — `exiftool -a -u -g1`, комментарии, чанки PNG.
3. **Appended data** — `binwalk`, `tail`, поиск сигнатур после конца формата.
4. **LSB** — `zsteg -a`, `stegsolve`.
5. **Парольная стего** — `stegseek` со словарём.
6. **Аудио** — спектрограмма (`sox`), LSB в WAV.
7. **Документы** — `olevba`, `pdf-parser`, распаковка OOXML.
8. **Мета-инструмент** — `stegoveritas` как «всё сразу».

## Дополнительные инструменты

| Инструмент | Назначение |

| `stegsolve` | визуальный перебор битовых плоскостей |
| `stegoveritas` | мета-инструмент: десятки тестов разом |


## Разобранный прогон целиком

Соберём разбор нашего `stego.png` в один непрерывный сценарий:

```bash
$ file -k stego.png                 # истинный тип
$ exiftool -a -u -g1 stego.png      # метаданные (ложный след)
$ pngcheck -v stego.png             # чанки: tEXt "Comment"
$ binwalk stego.png                 # appended data нет
$ zsteg -a stego.png                # LSB
[+] 1 b1,rgb,lsb,xy .. text: "CTF{lsb_in_png}"
```

Мы начали с самого дешёвого (тип и метаданные), затем проверили дописанные данные и
только потом младшие биты. Флаг оказался в LSB RGB. Если бы `zsteg` ничего не нашёл,
следующим шагом был бы `stegseek` со словарём (для JPEG) или `stegoveritas` как
«всё сразу».

## Как отличить стего от обычного файла

Иногда подсказка в самом файле: аномально большой размер для простой картинки,
несовпадение заявленного и реального разрешения, «шум» на однородном фоне. Сравнение с
«чистой» версией (если она есть) через `cmp` или diff сразу покажет, где изменены байты.

## Что мы теперь знаем

- Стеганография скрывает факт передачи данных, а не только содержание.
- Метаданные и чанки PNG (`tEXt`) — самый простой контейнер.
- `binwalk` находит данные, дописанные после конца формата.
- `zsteg` извлекает LSB из PNG/BMP без пароля.
- `stegseek` подбирает пароль для `steghide`; аудио разбирают спектрограммой.

## На что смотреть дальше

- **Не искать только LSB в JPEG** — там чаще DCT-стего или `steghide`.
- **Не забывать `binwalk`** — данные часто просто дописаны в конец.
- **Строить спектрограмму** для аудио — текст может быть «виден» в спектре.
- **Помнить про пароль** — `steghide` всегда шифрует, без `stegseek` не обойтись.
- **Не останавливаться на первом методе** — проверьте все три-четыре, прежде чем
  считать файл «чистым».

## Куда дальше

Мы разобрали файлы. Но большая часть следов в реальных расследованиях живёт в **сети** —
в дампах трафика PCAP. В следующем уроке мы разберём сетевой дамп и восстановим, что
передавалось. А пока запомни: **метод стего заранее неизвестен — иди по чек-листу от
простого к сложному**.
