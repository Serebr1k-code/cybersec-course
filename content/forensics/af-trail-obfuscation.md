## Вопрос, с которого всё начинается

В журнале ты видишь вход с адреса в другой стране, которого не было. Или пользователя,
которого не существует. Кто-то **подбросил** ложные следы, чтобы увести расследование в
сторону. Как отличить подделку от настоящей записи?

## Наш пример: странная запись в auth.log

Открываем `auth.log` и видим:

```
Mar 10 03:14:15 server sshd[9999]: Accepted password for ghost from 203.0.113.9
Mar 10 03:14:16 server sshd[9999]: session opened for user ghost
```

Пользователя `ghost` в системе нет. Запись выглядит правдоподобно, но что-то не так.

## Приём первый: инъекция в журнал

Атакующий может **дописать** записи в текстовый журнал (или подделать бинарный), чтобы:

- подставить другого пользователя/адрес;
- создать ложную временную метку;
- перегрузить следователя шумом.

Признаки подделки:

- **несоответствие PID**: `sshd[9999]` — слишком «круглый» и не встречается в других
  записях; настоящие PID последовательны;
- **нет парных событий**: успешному входу обычно предшествует `session opened`, а после —
  команды; «висячая» запись подозрительна;
- **нарушение формата**: другой порядок полей, лишние/недостающие пробелы, другая кодировка;
- **несоответствие времени**: запись выбивается из общего ритма системы.

## Приём второй: подмена времени (timestomp)

Атакующий меняет временные метки файлов, чтобы отвести подозрение:

```
$ touch -d '2019-01-01 00:00:00' evil.exe
$ stat evil.exe | grep Modify
Modify: 2019-01-01 00:00:00
```

Признаки timestomp:

- **время изменено раньше времени создания** — логически невозможно;
- **несоответствие `$STANDARD_INFORMATION` и `$FILE_NAME`** в NTFS: одни метки правят,
  другие часто забывают;
- **все файлы с одинаковой меткой** — явный признак массовой правки.

## Приём третий: приманки (decoys)

Иногда подбрасывают **фальшивые улики**: «пароли.txt» с мусором, поддельные документы,
ложные следы другой атаки. Цель — чтобы следователь пошёл не туда.

Как распознать: сверять находку с **независимыми источниками**. Если «улика» нигде, кроме
одного места, не подтверждается — это может быть приманка.

## Главный принцип: перекрёстная проверка

Любой отдельный артефакт может врать. Вывод строят на **согласовании нескольких
независимых источников**:

```
журнал хоста  +  сетевой лог  +  артефакты входа  +  память  =>  вывод
```

Если запись в журнале не подтверждается сетевым логом и артефактами — она поддельная.
Если подтверждается тремя источниками — почти наверняка настоящая.

## Шаг: разбор нашей записи

- Проверяем `sshd` PID 9999: в других записях PID другие и последовательны → аномалия.
- Смотрим сетевой лог файрвола на `203.0.113.9`: соединения нет → запись не подтверждена.
- Проверяем `ghost` в `/etc/passwd`: нет → пользователь выдуман.
- Проверяем метку времени: совпадает с временем, когда журнал не писался → вставка.

Вывод: запись **внедрена** вручную. Настоящий след надо искать в других источниках.

## Что мы теперь знаем

- Ложные записи внедряют в журналы, чтобы увести расследование.
- Признаки: аномальные PID, отсутствие парных событий, нарушение формата и времени.
- Timestomp меняет метки; выдают расхождения между `$STANDARD_INFORMATION` и `$FILE_NAME`.
- Приманки проверяют независимыми источниками.
- Вывод строят на согласовании нескольких источников, а не на одном артефакте.
