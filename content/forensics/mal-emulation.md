## Вопрос, с которого всё начинается

Запускать образец опасно, а статически он обфусцирован. Компромисс — **эмуляция**:
код исполняется по инструкциям в изолированной среде, без реальной ОС. Так видно
поведение и расшифровываются строки. Разберём.

## Наш пример: эмулируем функцию

## Шаг 1: что такое эмуляция

Эмулятор исполняет машинные инструкции, но не даёт настоящих системных вызовов. Вместо
этого ты **сам решаешь**, что вернёт каждый API. Это безопасно и контролируемо.

## Шаг 2: unicorn

`unicorn` — CPU-эмулятор (x86/ARM и др.):

```python
from unicorn import Uc, UC_ARCH_X86, UC_MODE_64
mu = Uc(UC_ARCH_X86, UC_MODE_64)
mu.mem_map(0x1000, 0x1000)
mu.mem_write(0x1000, code)
mu.emu_start(0x1000, 0x1000+len(code))
```

Он даёт регистры и память после исполнения. Годится для расшифровки строк и проверок.

## Шаг 3: Qiling

`Qiling` эмулирует уже **всю ОС** — загружает PE/ELF, эмулирует API:

```python
from qiling import Qiling
ql = Qiling([r"samples/packed.exe"], r"rootfs/x8664_windows")
ql.run()
```

Он перехватывает вызовы (например, `CreateFile`), и ты можешь логировать/подменять их.
Так видно, какие файлы, ключи реестра и адреса использует образец.

## Шаг 4: извлечение поведения

- **API-логи** — какие функции вызваны;
- **сетевые адреса** — куда «звонит»;
- **файлы/ключи** — что трогает;
- **расшифрованные строки** — после прогона.

Всё это — IOC без реального заражения.

## Шаг 5: ограничения

- эмулятор не всегда поддерживает все инструкции;
- анти-эмуляция (проверка тайминга, CPUID) ломает прогон;
- сложные образцы требуют ручной настройки API.

Поэтому эмуляцию комбинируют со статикой и песочницей.

## Что мы теперь знаем

- Эмуляция исполняет код без реальной ОС.
- `unicorn` — CPU-уровень, `Qiling` — ОС-уровень.
- API можно перехватывать и подменять.
- Извлекаются строки, адреса, поведение.
- Есть ограничения (поддержка инструкций, анти-эмуляция).

## Если не сработало

- Не поддерживается инструкция? Переключи движок/пропусти.
- Анти-эмуляция? Патчь проверки.
- Нужна полная ОС? Комбинируй с песочницей.

## Разбор эмуляции на практике

Пусть есть обфусцированный участок, который расшифровывает строку. Эмулируем
его и читаем результат из памяти:

```python
from unicorn import Uc, UC_ARCH_X86, UC_MODE_64
from unicorn.x86_const import UC_X86_REG_RIP
mu = Uc(UC_ARCH_X86, UC_MODE_64)
mu.mem_map(0x1000, 0x2000)
mu.mem_write(0x1000, open("blob.bin","rb").read())
mu.mem_map(0x8000, 0x1000)
mu.emu_start(0x1000, 0x1800)
data = mu.mem_read(0x8000, 64)
print(bytes(data))
```

Скрипт исполняет только нужный фрагмент и печатает расшифрованную строку. Так
вскрывают строки без запуска образца на реальной системе.

## Qiling: перехват API

`Qiling` загружает целый PE/ELF и даёт хуки на API:

```python
from qiling import Qiling
from qiling.const import QL_VERBOSE
ql = Qiling([r"samples/packed.exe"], r"rootfs/x8664_windows",
            verbose=QL_VERBOSE.DEBUG)
ql.run()
```

В логе видно последовательность вызовов: `CreateFileW`, `RegSetValueEx`,
`WinHttpSendRequest`. По ней восстанавливается поведение — какие файлы
создаются, какие ключи реестра правятся, куда идут данные.

## Таблица: unicorn против Qiling

| Критерий | unicorn | Qiling |
|---|---|---|
| Уровень | CPU/инструкции | ОС/API |
| Загрузка файла | вручную (blob) | PE/ELF целиком |
| Перехват API | сам пишешь | встроенные хуки |
| Сложность | низкая | средняя |
| Для чего | расшифровка, вычисления | поведение, IOC |

Выбор прост: нужна расшифровка одной функции — `unicorn`; нужно поведение
всей программы — `Qiling`.

## Пример: извлечение конфигурации

Частая задача — вытащить встроенный конфиг (C2, ключи) из образца:

```
$ python3 -c "
import unicorn
# эмулируем инициализацию, читаем буфер конфига
"
{"c2":"203.0.113.5:8443","key":"a1b2c3d4"}
```

Эмуляция даёт конфиг, не запуская малварь. Это безопаснее песочницы: код
исполняется без реальных системных вызовов, и образец не может «убежать».

## Ограничения и обход

- **Неподдерживаемые инструкции** — эмулятор останавливается; переключай
  движок или пропускай инструкцию.
- **Анти-эмуляция** — проверки CPUID, таймингов, `rdtsc`; патчь проверки или
  подсовывай правдоподобные значения.
- **Сложные API** — не все вызовы реализованы; задавай возвраты вручную.
- **Криптография** — эмуляция не «понимает» шифр; нужен реальный прогон
  крипто-функции или её воспроизведение.

Поэтому эмуляцию комбинируют со статикой и песочницей: каждая техника
дополняет другие.

## Если сработало

Эмуляция дала расшифрованные строки или конфиг — фиксируй результат:

1. Сохрани скрипт эмуляции и входной blob для воспроизводимости.
2. Запиши извлечённые IOC (C2, ключи, пути).
3. Прогони расшифрованные строки через YARA для поиска по другим образцам.
4. Отметь технику в отчёте — она показывает, как обошли обфускацию.

Эмуляционный скрипт — переиспользуемый артефакт: его можно применить к
другим образцам того же семейства без переписывания.

## Практика: Qiling с хуками на API

`Qiling` позволяет перехватывать конкретные вызовы и логировать их:

```python
from qiling import Qiling
from qiling.const import QL_VERBOSE

def on_connect(ql, address, params):
    print("connect ->", params)

ql = Qiling([r"samples/packed.exe"], r"rootfs/x8664_windows",
            verbose=QL_VERBOSE.DEFAULT)
ql.os.set_api("connect", on_connect)
ql.run()
```

Каждый вызов `connect` печатает параметры — так видно, куда образец
«звонит», без реального сетевого соединения. Тот же приём для `CreateFileW`,
`RegSetValueEx`, `WinHttpSendRequest`.

## Пример: эмуляция крипто-функции

Обфускаторы часто используют простой XOR или RC4. Воспроизводим расшифровку:

```python
def rc4(key, data):
    S = list(range(256)); j = 0
    for i in range(256):
        j = (j + S[i] + key[i % len(key)]) & 0xff
        S[i], S[j] = S[j], S[i]
    out = bytearray(); i = j = 0
    for b in data:
        i = (i + 1) & 0xff; j = (j + S[i]) & 0xff
        S[i], S[j] = S[j], S[i]
        out.append(b ^ S[(S[i] + S[j]) & 0xff])
    return bytes(out)

enc = bytes.fromhex("a1b2c3d4")
print(rc4(b"key", enc))
```

Воспроизведя алгоритм, ты расшифровываешь строки без эмулятора — быстро и
надёжно. Эмуляция нужна, когда алгоритм неочевиден; как только он понятен,
пиши эквивалент на Python.

## Таблица: что эмулировать, а что нет

| Задача | Подход |
|---|---|
| Расшифровка строк | unicorn / Python-эквивалент |
| Разбор конфига | Qiling + хук на чтение |
| Проверка анти-анализа | эмуляция + подмена значений |
| Сложная логика (VM) | unicorn с трассировкой |
| Полное поведение | песочница (не эмуляция) |
| Сетевые IOC | Qiling-хук на connect/send |

Правило: если нужно **поведение** — песочница; если нужно **вскрыть
обфускацию** — эмуляция; если нужен **конкретный расчёт** — Python-эквивалент.

## Связь со статикой и песочницей

Три техники образуют конвейер:

1. **Статика** — формат, строки, импорты, энтропия секций.
2. **Эмуляция** — вскрытие обфускации, извлечение конфига и строк.
3. **Песочница** — наблюдение реального поведения и сетевых IOC.

Статика подсказывает точки входа, эмуляция раскрывает скрытое, песочница
подтверждает поведение. Ни одна из техник не самодостаточна.

## Если сработало

Эмуляция вскрыла обфускацию — фиксируй результат:

1. Сохрани скрипт эмуляции и входные данные для воспроизводимости.
2. Запиши расшифрованные строки и конфиг.
3. Прогони их через YARA — найди другие образцы семейства.
4. Отметь технику обфускации как TTP семейства в отчёте.

Эмуляционный скрипт — переиспользуемый артефакт: его применяют к другим
образцам того же семейства, экономя часы ручного анализа.

## Ограничения и типичные ошибки

- **Не все API реализованы** — задавай возвраты вручную; иначе образец
  остановится.
- **Пропуск инструкций** — некоторые образцы используют редкие инструкции;
  эмулятор может не поддержать их.
- **Крипто не «понимается»** — для сложной криптографии нужен реальный
  прогон или воспроизведение алгоритма.
- **Эмуляция ≠ поведение** — извлечённые строки не доказывают, что образец
  действительно так действует; подтверждай песочницей.

## Практика: трассировка через unicorn

Чтобы понять, что делает функция, эмулируем её пошагово и логируем регистры:

```python
from unicorn import Uc, UC_ARCH_X86, UC_MODE_64, UC_HOOK_CODE
from unicorn.x86_const import UC_X86_REG_RAX, UC_X86_REG_RDI

def hook(mu, address, size, user):
    rax = mu.reg_read(UC_X86_REG_RAX)
    rdi = mu.reg_read(UC_X86_REG_RDI)
    print(hex(address), "rax=", hex(rax), "rdi=", hex(rdi))

mu = Uc(UC_ARCH_X86, UC_MODE_64)
mu.mem_map(0x1000, 0x2000)
mu.mem_write(0x1000, open("blob.bin","rb").read())
mu.hook_add(UC_HOOK_CODE, hook)
mu.emu_start(0x1000, 0x1800)
```

Пошаговый лог показывает, какие данные образец передаёт в функции — это
раскрывает аргументы (пути, ключи, адреса), которые в статике не видны.

## Пример: извлечение ключа из проверки

Многие образцы расшифровывают полезную нагрузку только при верном пароле.
Эмулируя ветку сравнения, можно подсмотреть ожидаемое значение:

```
$ python3 -c "
# hook на сравнение строк, лог ожидаемого аргумента
"
expected_key = b"xmr-secret-2026"
```

Подсмотренный ключ даёт доступ к расшифрованному коду — и это самый быстрый
путь к скрытой логике.

## Итог

Эмуляция — это безопасный способ вскрыть обфускацию: `unicorn` на уровне
инструкций, `Qiling` на уровне API, Python-эквивалент для известных
алгоритмов. Комбинируй её со статикой (что искать) и песочницей (что
происходит в реальности), чтобы получить полную картину без риска запуска.

## Краткий чек-лист

1. Определи формат (статика) и сохрани образец.
2. Вскрой обфускацию эмуляцией (`unicorn`/`Qiling`).
3. Извлеки конфиг и IOC из расшифрованных данных.
4. Подтверди поведение песочницей.
5. Сохрани эмуляционный скрипт как переиспользуемый артефакт.

Пункт 5 — то, что отличает разовый разбор от систематической работы: скрипт
применяется к другим образцам семейства без переписывания.
