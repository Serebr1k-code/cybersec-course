## Вопрос, с которого всё начинается

На сервере данных нет — они на сетевом ресурсе. Ты не можешь снять «диск», потому что
диска нет: есть **экспорт NFS**. Прежде чем что-то делать, нужно понять, что вообще
открыто и как получить данные, не изменив их.

## Наш пример: смонтированный экспорт

Смотрим таблицу монтирования:

```
$ mount | grep nfs
server:/export/data on /mnt/data type nfs4 (rw,relatime,vers=4.2)
```

Строка `server:/export/data` — это **экспорт**: каталог `/export/data` на хосте `server`,
отданный по сети. Локально лежит только «вид» на него; байты — на сервере.

## Что такое NFS

**NFS (Network File System)** — протокол, по которому один хост отдаёт свой каталог
другим как файловую систему. Клиент видит папки и файлы так, будто они локальные.
Ключевые версии: NFSv3 и NFSv4. Разница для форензика: v4 умеет ACL и более богатую
аутентификацию, v3 часто полагается на `uid`/`gid` и доверие к клиенту.

## Шаг 1: узнать, какие экспорты открыты

С сервера (или с клиента, если разрешено) спрашиваем список:

```
$ showmount -e server
Export list for server:
/export/data  10.0.0.0/24
/export/backup (everyone)
```

`(everyone)` — экспорт доступен всем. `/export/data` ограничен подсетью `10.0.0.0/24`.
Это сразу подсказывает, кто мог обращаться.

## Шаг 2: понять права

Опасная (и частая) настройка — `no_root_squash`: тогда `root` на клиенте сохраняет права
`root` на сервере. Проверить можно по файлу экспорта на сервере:

```
$ cat /etc/exports
/export/data 10.0.0.0/24(rw,no_root_squash,sync)
```

Для расследования это важно: с такой настройкой клиент мог менять права и владельцев
файлов на сервере, и следы будут выглядеть «легитимно».

## Шаг 3: снять экспорт правильно

Экспорт — это каталог на сервере. Поэтому снимать надо **сервер** (или его снимок), а не
клиента. Если доступа к серверу нет, монтируем экспорт **только на чтение**:

```
$ mkdir -p /mnt/ro && mount -t nfs -o ro,vers=4.2 server:/export/data /mnt/ro
```

`-o ro` критично: монтирование на запись может изменить `atime` и другие метаданные,
испортив улики.

## Шаг 4: логи обращений

Сам сервер хранит следы обращений:

- `rpc.mountd` пишет, какие клиенты монтировали экспорт;
- системные журналы (`/var/log/syslog`, `messages`) фиксируют монтирования;
- на клиенте остаются записи в `/etc/fstab`, истории команд, кэше.

Совокупность «кто монтировал + когда + какие файлы читали» часто важнее содержимого.

## Ловушка: клиентский кэш

NFS-клиент кэширует атрибуты файлов. Значит, `stat` на клиенте может показывать
устаревшие данные. Для доказательств опирайся на **сервер** и его снимки, а клиентский
кэш используй как вспомогательный источник.

## Что мы теперь знаем

- NFS отдаёт каталог сервера как локальную файловую систему.
- `showmount -e` показывает экспорты и их доступ.
- `no_root_squash` расширяет права клиента — важно для расследования.
- Снимать нужно сервер/снимок; монтировать только на чтение.
- Серверные логи фиксируют монтирования и доступ.
