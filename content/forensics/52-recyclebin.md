## Вопрос, с которого всё начинается

Пользователь удалил компрометирующий документ. Корзина очищена. Но нужно узнать
**что** это был за файл и **откуда** его удалили.

Хорошая новость: когда файл удаляют в Корзину, Windows не стирает его, а
**перемещает** — и создаёт рядом два служебных файла с метаданными. А если и корзина
очищена, превью документа может остаться в кэше миниатюр. В этом уроке мы восстановим
удалённое и узнаем его оригинальный путь.

## Шаг 1: как устроена Корзина

Корзина — это папка `C:\$Recycle.Bin\<SID>\`, где `<SID>` — идентификатор
пользователя (SID = Security Identifier, уникальный «номер» учётной записи). При
удалении файла туда кладут **два** файла:

- **`$I<id>`** — метаданные: оригинальный путь, размер, **время удаления**;
- **`$R<id>`** — сами данные файла (переименованные).

`$I` — это «паспорт» удалённого файла, `$R` — его «тело». По отдельности они
бесполезны, вместе дают полную картину.

## Шаг 2: разбираем $I-файл

Структура `$I` (Windows 10/11) такая:

| Смещение | Размер | Поле |
|---------:|-------:|------|
| 0 | 8 | версия (обычно 2) |
| 8 | 8 | размер файла |
| 16 | 8 | **время удаления** (FILETIME) |
| 24 | 4 | длина пути |
| 28 | var | путь (UTF-16LE) |

**FILETIME** — формат времени Windows: количество 100-наносекундных интервалов с
1 января 1601 года. Разбираем файл скриптом:

```bash
$ python3 - <<'EOF'
import struct, datetime
d = open("$IABCDEF", "rb").read()
size = struct.unpack("<Q", d[8:16])[0]
ft = struct.unpack("<Q", d[16:24])[0]
ts = datetime.datetime(1601,1,1) + datetime.timedelta(microseconds=ft/10)
path = d[28:].decode("utf-16-le", "ignore").rstrip("\x00")
print(size, ts, path)
EOF
1048576 2024-03-01 12:07:33 C:\Users\bob\Documents\secret.docx
```

Мы получили точное время удаления и **оригинальный путь**. Это уже доказательство.

## Шаг 3: автоматизируем разбор

Вручную парсить не обязательно — есть готовые инструменты:

```bash
$ rifiuti2 '$Recycle.Bin/'
$ RBCmd.exe -d C:\$Recycle.Bin -o out.csv
```

`rifiuti2` (Linux) и `RBCmd` (Windows) сами читают все `$I`-файлы и выдают CSV с
путями и временами. Содержимое (`$R`) при этом остаётся на месте — его копируют и
анализируют как обычный файл. Обратите внимание: `$R` может быть целой папкой, если
удалили каталог, — тогда внутри лежит дерево файлов, и путь из `$I` указывает на
исходный каталог.

## Шаг 4: Thumbcache — превью удалённого

Что делать, если и корзина очищена? На помощь приходит **Thumbcache** — кэш
миниатюр (превью) файлов. Windows показывает миниатюры картинок и документов в
проводнике и кэширует их в файлах `thumbcache_*.db`:

```bash
$ ls thumbcache_*.db
thumbcache_16.db  thumbcache_96.db  thumbcache_256.db
```

Формат начинается с сигнатуры `CMMM`, затем идут записи с миниатюрами. Число в имени
— размер миниатюры в пикселях. Извлекаем превью утилитой `thumbcache_viewer`:

```bash
$ python thumbcache_viewer.py -i thumbcache_256.db -o out/
$ ls out/
0123ab...jpg  45cd78...jpg
```

Даже если оригинал удалён, миниатюра **остаётся** в кэше до перезаписи. Это часто
единственное изображение удалённого файла.

Размер миниатюры выбирается по контексту: `16` и `32` — мелкие иконки, `96` и `256` —
то, что видно в проводнике, `1024` — крупные обложки. Просматривайте сразу несколько
файлов `thumbcache_*.db`: крупная миниатюра даст узнаваемую картинку, мелкая — хотя бы
общее представление. Помимо `thumbcache`, есть `iconcache_*.db` (иконки) и
`thumbcache_idx.db` (индексы).

## Шаг 5: что доказывает Корзина

| Факт | Источник |
|------|----------|
| Оригинальный путь | `$I` |
| Время удаления | `$I` |
| Содержимое | `$R` |
| Кто удалил | SID в пути |
| Внешний вид | Thumbcache |

Важно: если `$I`/`$R` остались, а корзина «пуста» (её частично очистили), данные всё
равно есть — просто не в интерфейсе. Очистка корзины удаляет записи из оглавления, но
файлы `$R` могут остаться на диске до перезаписи — их ищут тем же carving-ом.

## Шаг 6: если файл удалён мимо Корзины

При удалении через Shift+Delete файл не попадает в корзину. Но данные могут остаться
в других местах:

- **MFT** — метаданные (имя, размер, времена) удалённого файла, пока запись не
  переиспользована;
- **USN Journal** — журнал создания/удаления/переименования;
- **unallocated** — свободные блоки, где лежат данные (carving);
- **теневые копии тома** — снапшоты.

```bash
$ MFTECmd.exe -f '$MFT' --csv out/
$ photorec disk.img
```

## Шаг 7: полный чек-лист разбора

Чтобы ничего не упустить, идём по порядку:

1. Смонтировать образ **только для чтения**.
2. Найти Корзину по всем SID: `/mnt/$Recycle.Bin/*/`.
3. Разобрать `$I` (`rifiuti2`/`RBCmd`) — пути и время удаления.
4. Скопировать `$R` — содержимое файлов.
5. Извлечь `thumbcache_*.db` — превью.
6. Сверить с MFT/USN/LNK/Jump Lists.
7. При необходимости — carving по unallocated.

Отдельно проверьте **все** SID: у каждого пользователя своя папка корзины, и файл мог
удалить не тот, на кого вы думаете. А если `$I`-файл повреждён, оставшийся `$R` всё
равно можно опознать по содержимому (`file`, `strings`).

## Шаг 8: корреляция с другими артефактами

Корзина почти никогда не рассказывает всю историю в одиночку. Сопоставляйте:

- **`$I` → оригинальный путь** → ищите файл в MFT и USN (когда создан, переименован);
- **`$R` → содержимое** → восстановите файл целиком;
- **thumbcache → превью** → визуальное доказательство;
- **LNK/Jump Lists** → что открывали перед удалением;
- **Prefetch** → что запускалось.

```bash
$ MFTECmd.exe -f '$MFT' --csv out/
$ grep -i 'secret.docx' out/*.csv
```

Так вы получаете не просто «файл удалён», а полную цепочку: создан → открыт →
изменён → удалён, с точными временами из независимых источников.

## Разбор $I-файла вручную

Когда нет `RBCmd`, структура `$I`-файла читается напрямую: 8 байт заголовка, 8 байт размера, 8 байт времени удаления (FILETIME), затем путь в UTF-16LE.

```bash
$ xxd -l 32 '$IABC123.docx'
00000000: 0200 0000 0000 0000 00d0 1f00 0000 0000  ................
```

Смещение `0x08` — исходный размер, `0x10` — время удаления. Так восстанавливают путь и время даже без готового парсера.

## Что мы теперь знаем

- Корзина создаёт `$I` (метаданные) и `$R` (данные) для каждого удалённого файла.
- `$I` хранит оригинальный путь и точное время удаления (FILETIME).
- `rifiuti2`/`RBCmd` разбирают корзину автоматически.
- Thumbcache хранит превью удалённых изображений и документов.
- Удалённое мимо корзины ищут в MFT/USN/unallocated/теневых копиях.

## На что смотреть дальше

- **Считать «пустую» Корзину = нет данных** — проверьте `$I`/`$R`.
- **Путать `$I` и `$R`** — `$I` метаданные, `$R` содержимое.
- **Не учитывать per-user Корзину** — она у каждого SID своя.
- **Игнорировать thumbcache** — часто единственное превью удалённого.
- **Парсить FILETIME как Unix time** — это 100-нс интервалы с 1601 года.
- **Писать на образ** — только чтение.

## Куда дальше

Мы научились восстанавливать удалённое и доставать превью. Дальше возьмём самый
богатый источник форензических данных Windows — **журналы событий EVTX** и события
Sysmon. А пока запомни: **Корзина хранит паспорт удалённого файла, а thumbcache —
его лицо**.
