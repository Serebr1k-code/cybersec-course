## Вопрос, с которого всё начинается

Ботнет управляется с сервера — **C2** (command and control). Если сервер попал в руки
исследователей, его панель рассказывает о ботнете больше, чем сам образец: сколько
ботов, какие команды, кто оператор. Разберём.

## Наш пример: захваченная панель

## Шаг 1: что такое C2 и панель

C2 — сервер, которому «звонят» боты. Панель — веб-интерфейс оператора: список ботов,
отправка команд, статистика. Часто это PHP-приложение с MySQL.

## Шаг 2: структура

```
$ ls /var/www/html/
index.php  login.php  gate.php  panel/  db.php
```

`gate.php` — точка приёма от ботов (beacon). `panel/` — интерфейс оператора. `db.php` —
подключение к базе.

## Шаг 3: база ботов

```
$ sqlite3 bots.db '.tables'
bots  commands  logs
$ sqlite3 bots.db 'SELECT COUNT(*) FROM bots;'
1420
```

Таблица `bots` — список заражённых машин (IP, ID, ОС, страна). `commands` — очередь
заданий. Это карта заражения.

## Шаг 4: что делают боты

```
$ sqlite3 bots.db 'SELECT DISTINCT command FROM commands LIMIT 10;'
ddos
download
keylog
```

Набор команд раскрывает назначение ботнета: DDoS, кража данных, спам.

## Шаг 5: следы оператора

- **IP в логах** (`access.log` панели);
- **аккаунты** в БД (`users`);
- **стиль кода** и строки;
- **время активности** (часовой пояс).

Сопоставляя, можно деанонимизировать оператора (в рамках закона).

## Что мы теперь знаем

- C2 — сервер управления ботнетом; панель — его интерфейс.
- `gate.php` принимает beacon от ботов.
- База содержит список ботов и команды.
- Набор команд раскрывает назначение.
- Логи и БД хранят следы оператора.

## Если не сработало

- Панель удалена? Анализируй конфиг ботов (C2-адрес).
- Нет доступа? Работай с трафиком ботов.
- Нужны боты? Ищи beacon в дампах.

## Разбор захваченной панели

Панель ботнета — это чаще всего обычное веб-приложение (PHP/Node) с базой
данных ботов. После захвата сервера первым делом смотрим на структуру БД:

```
$ sqlite3 /var/www/panel/data/bots.db ".tables"
bots        commands    logs        users
$ sqlite3 /var/www/panel/data/bots.db "SELECT COUNT(*) FROM bots;"
14872
```

Таблица `bots` — реестр заражённых машин. Таблица `commands` — очередь
заданий. `logs` — история выполнения. `users` — операторы панели.

```
$ sqlite3 -header /var/www/panel/data/bots.db \
    "SELECT id,ip,country,os,last_seen FROM bots LIMIT 5;"
id|ip|country|os|last_seen
1|198.51.100.7|RU|Windows 10|2026-03-11 03:40:02
2|203.0.113.44|DE|Linux|2026-03-11 03:39:55
```

## Таблица: поля базы ботов

| Поле | Смысл |
|---|---|
| `id` | внутренний номер бота |
| `hwid` / `guid` | аппаратный идентификатор (устойчив к смене IP) |
| `ip`, `country` | текущий адрес и геолокация |
| `os`, `arch` | ОС и архитектура (какие команды исполнимы) |
| `last_seen` | время последнего «звонка» на C2 |
| `status` | online/offline/занят |

По `hwid` можно отличить один и тот же заражённый хост, даже если он меняет
IP (мобильный интернет) — это важно для доказательства повторных заражений.

## Команды оператора и их смысл

Очередь команд показывает, чего именно добивался оператор:

```
$ sqlite3 -header /var/www/panel/data/bots.db \
    "SELECT id,command,created_at FROM commands ORDER BY id DESC LIMIT 6;"
id|command|created_at
91|ddos https://victim.example 300|2026-03-11 03:50:11
90|update|2026-03-11 03:20:00
89|screenshot|2026-03-11 02:10:00
88|shell whoami|2026-03-11 01:55:00
```

`ddos` — атака на жертву, `update` — подмена модуля (persistence),
`screenshot`/`shell` — разведка на заражённых хостах. Каждая команда — это
отдельный эпизод инцидента с точным временем.

## Следы оператора

Даже если боты обезличены, оператор оставляет личные следы:

- **учётные записи панели** (`users`) — логины, хеши паролей, email;
- **IP-адреса входа** в веб-логах (`access.log` панели);
- **часовой пояс** — по смещению времени команд видно регион оператора;
- **сообщения/ошибки** — отладочные записи часто содержат пути и имена.

```
$ grep -E 'POST /login' /var/www/panel/access.log | awk '{print $1}' | sort | uniq -c
      7 185.220.101.33
      3 203.0.113.9
```

Основной IP с большинством входов — вероятный адрес оператора.

## Границы метода и типичные ошибки

- **C2 может быть проксирован.** Оператор почти всегда ходит через VPN/Tor,
  поэтому IP входа не равен домашнему адресу — нужна корреляция с другими
  инцидентами, а не прямая атрибуция.
- **База может быть удалена.** Ботнеты часто пишут логи в память или чистят
  таблицу; тогда единственный след — сетевой трафик.
- **Хеши могут быть подделаны.** Логин оператора не всегда реальный —
  проверяй, есть ли активность под этой учёткой.
- **Объём.** 15 000 ботов — это не 15 000 пострадавших в периметре; фильтруй
  по своим сетям, прежде чем объявлять масштаб.

## Если сработало

Собрав список ботов, отфильтруй те, что принадлежат твоей организации:

```
$ sqlite3 /var/www/panel/data/bots.db \
    "SELECT ip FROM bots WHERE ip LIKE '10.10.%';" | sort -u
```

Каждый такой хост — потенциально скомпрометированная машина в периметре.
Передай список в IR для изоляции, а C2-адрес добавь в блокировки.

## Жизненный цикл бота

По записям `first_seen`/`last_seen` строится хронология заражения:

```
$ sqlite3 -header /var/www/panel/data/bots.db \
    "SELECT hwid, datetime(first_seen) f, datetime(last_seen) l,
            (julianday(last_seen)-julianday(first_seen))*24 AS hours
     FROM bots ORDER BY hours DESC LIMIT 4;"
hwid|f|l|hours
a1b2|2026-01-02 10:00|2026-03-11 03:40|1657.6
c3d4|2026-03-10 22:00|2026-03-11 03:41|5.7
```

Хост, заражённый 10-го в 22:00 и активный уже 5 часов, — «свежий» бот. Массовое
появление свежих ботов в одном окне означает новую волну рассылки, и её
источник (фишинг/эксплойт) нужно искать в этом же окне.

## Определение «своих» хостов в периметре

Не все боты равны. Сопоставляем IP и hwid с инвентарём организации:

```
$ sqlite3 /var/www/panel/data/bots.db "SELECT ip,hwid FROM bots;" > bots.txt
$ while read ip hwid; do grep -q "$ip" inventory.txt && echo "IN PERIMETER: $ip"; done < bots.txt
IN PERIMETER: 10.10.5.21
IN PERIMETER: 10.10.7.88
```

Эти два хоста — подтверждённые жертвы. Остальные 14 870 — чужие боты, они
важны для картины атаки, но не для изоляции в своём периметре.

## Реконструкция командной сессии

Если в БД есть `results` от ботов, можно восстановить, что видел оператор:

```
$ sqlite3 -header /var/www/panel/data/bots.db \
    "SELECT bot_id,substr(result,1,60) FROM logs WHERE command_id=88;"
bot_id|substr(result,1,60)
21|nt authority\system
88|DESKTOP-4F2\\user
```

`nt authority\system` в ответе на `shell whoami` означает, что бот уже
работал с правами SYSTEM — компромисс максимальный, машину нужно считать
полностью подконтрольной атакующему.

## Что делать с панелью

1. **Не выключай сразу.** Пока панель жива, можно собрать истекающие
   `last_seen` и увидеть, какие боты ещё на связи.
2. **Заблокируй C2 на периметре** (DNS/ipset), чтобы боты внутри не могли
   получить новые команды.
3. **Собери IOC**: домены, IP C2, URL модулей, хеши.
4. **Синхронизируй с IR**: список «своих» хостов идёт в изоляцию.
5. **Сохрани дамп БД** для отчёта и возможного судебного разбирательства.

Панель — это одновременно и улика, и инструмент. Её выключение до сбора
данных уничтожает доказательства и обрывает наблюдение.

## Инструменты анализа панели

| Задача | Инструмент |
|---|---|
| Просмотр SQLite | `sqlite3`, `DB Browser` |
| Дамп MySQL/Postgres | `mysqldump`, `pg_dump` |
| Извлечение из веб-кода | `grep -r`, `ripgrep` |
| Геолокация IP | `whois`, `mmdbinspect` |
| Деобфускация PHP | `php -r`, `unphp` |
| Сетевой трафик | `tcpdump`, Zeek |

Исходники панели важны не меньше БД: в них лежат **логика команд**, адреса
C2 и часто захардкоженные токены оператора. `grep -rn "http" panel/` найдёт
endpoint'ы, к которым обращаются боты.

## Юридический аспект

Захват панели — это работа с чужими данными. Важно:

- фиксировать только необходимое, не копировать лишнее;
- хранить доказательства с хешами и протоколом;
- не «переиспользовать» панель (например, для рассылки команд своим ботам);
- согласовать действия с юристами до публикации IOC.

Незаконный доступ к панели в целях расследования недопустим, даже если она
преступная — действуй в рамках, установленных договором и законом.

## Быстрый триаж панели

Порядок, который экономит часы:

```
$ sqlite3 panel.db "SELECT COUNT(*) FROM bots;"          # масштаб
$ sqlite3 panel.db "SELECT command FROM commands \
    ORDER BY id DESC LIMIT 10;"                          # намерения
$ sqlite3 panel.db "SELECT ip FROM bots \
    WHERE ip LIKE '10.%' OR ip LIKE '192.168.%';"        # свои
$ grep -rhoE 'https?://[^"'\'' ]+' panel/ | sort -u      # C2
```

Первые две команды дают масштаб и цели, третья — жертв в периметре,
четвёртая — IOC для блокировки. С этого набора начинай любой разбор
захваченной панели.

## Частая ошибка: путать ботов с жертвами

Новичок видит в панели 15 000 строк и докладывает о 15 000 пострадавших. На
самом деле это **чужие** заражённые машины по всему миру. Для организации
важны только те, чей IP попадает в её подсети. Фильтруй по периметру прежде
чем оценивать масштаб: одна строка `WHERE ip LIKE '10.%'` отделяет реальных
жертв от общей картины ботнета.

## Итог

Панель ботнета — это база данных управления: реестр ботов, очередь команд,
логи выполнения и учётки операторов. Разбор начинается с масштаба и целей,
продолжается фильтрацией своих хостов по периметру и заканчивается сбором
IOC. Панель нельзя просто выключить — сначала собери доказательства.
