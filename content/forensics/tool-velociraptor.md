## Вопрос, с которого всё начинается

Инцидент в сети из 5000 машин. Обходить каждую вручную невозможно. **Velociraptor**
позволяет задать вопрос **сразу всем** хостам и собрать ответы. Разберём.

## Наш пример: охота на флоте

## Шаг 1: архитектура

Velociraptor: **сервер** + **агенты** на хостах. Агенты обращаются к серверу и
выполняют запросы. Управление — через веб-интерфейс.

## Шаг 2: VQL

Запросы пишутся на **VQL** (Velociraptor Query Language) — SQL-подобном языке:

```sql
SELECT Name, Pid, Exe FROM pslist() WHERE Name =~ "powershell"
```

VQL может обращаться к файлам, процессам, реестру, сети — на каждом хосте.

## Шаг 3: артефакты

Готовые «артефакты» — пакеты сбора:

- `Windows.System.Pslist`;
- `Windows.Registry.Run`;
- `Windows.EventLogs.Evtx`;
- `Linux.Sys.Users`.

Запускаешь артефакт → получаешь структурированные данные со всех хостов.

## Шаг 4: охота

Hunt (охота) — это запрос ко всему флоту:

```
Hunt: "find powershell with encoded command"
→ 37 hosts matched
```

Результаты агрегируются на сервере, можно скачать файлы/память.

## Шаг 5: применение

- **быстрый триаж** флота;
- **охота** по IOC;
- **live-сбор** без установки тяжёлых агентов;
- **мониторинг** (клиентские артефакты по расписанию).

## Шаг 6: установка и развёртывание

Velociraptor ставится как один бинарник. Сервер запускают:

```
$ velociraptor.exe --config server.config.yaml frontend
```

Агенты разворачивают через MSI/скрипт, они получают сертификат и «звонят домой». Ключевой момент — конфиг с CA и адресом сервера; без него агент не подключится. В расследовании важно, что агенты дают **live-доступ** к тысячам хостов без ручного обхода.

## Шаг 7: VQL глубже

VQL — это не просто SELECT. Он умеет вложенные запросы, функции и плагины:

```sql
SELECT Name, Pid, CommandLine, Username FROM pslist()
WHERE CommandLine =~ "encodedcommand"
```

```
SELECT * FROM glob(globs="C:/Users/*/AppData/**/update.exe")
```

`pslist()`, `glob()`, `registry()` — плагины-источники. Так одним запросом опрашиваешь процессы, файлы и реестр на всех хостах.

## Шаг 8: коллекции и результаты

Запуск артефакта создаёт **коллекцию** — набор результатов с конкретного хоста. Коллекции хранятся на сервере:

- результаты структурированы (таблицы/JSON);
- файлы можно скачать;
- у каждой коллекции есть хэши и время.

Это делает сбор воспроизводимым и пригодным для отчёта: всегда видно, откуда и когда получены данные.

## Шаг 9: охота и мониторинг

**Hunt** — разовый опрос флота по запросу. **Client monitoring** — артефакты, которые выполняются на клиентах постоянно (по событиям). Например, мониторинг новых процессов или изменений реестра:

```
Artifact: Windows.Events.ProcessCreation
```

Так из «разового сбора» Velociraptor превращается в систему обнаружения на флоте.

## Шаг 10: практика — читаем результат

Дано: `vql_results.json` из охоты. Действия:

1. посмотреть структуру (какой артефакт, какие поля);
2. найти подозрительные записи (необычный процесс/пользователь);
3. сопоставить `Hostname` — на каких машинах;
4. выгрузить связанные файлы, если есть.

Результат охоты — список хостов и артефактов, по которым дальше идёт точечный разбор.

## Шаг 11: что важно запомнить

- Velociraptor = сервер + агенты (один бинарник).
- VQL умеет вложенные запросы и плагины-источники.
- Коллекции воспроизводимы и хранят хэши/время.
- Hunt — разовый опрос; monitoring — постоянный.
- Результаты агрегируются на сервере.

## Разбор реального инцидента

В сети пять тысяч машин, и по одной пришёл алерт на подозрительный процесс. Вместо ручного обхода запускаем Hunt по всем хостам: ищем процессы с закодированной командной строкой PowerShell. Velociraptor выполняет VQL на каждом агенте и возвращает агрегированный результат: совпадение на 37 хостах. Для каждого хоста видим `Pid`, `CommandLine` и пользователя. Дальше сужаем: запускаем артефакт сбора процессов и автозапуска, получаем таблицы со всех 37 машин, находим общий признак — одинаковый путь к временному файлу. Затем собираем этот файл как артефакт (file collection) и считаем хэши: они совпадают, значит, это одна и та же программа. Так масштабная охота за минуты превращается в конкретный IOC и список заражённых узлов — то, что вручную заняло бы недели.

## Подводные камни

Velociraptor эффективен, но требует подготовки. Агенты должны быть развёрнуты заранее — на машинах без агента их не «спросить» постфактум. Конфигурация сертификатов критична: при неверном CA агент молча не подключится. VQL может быть тяжёлым: запрос, читающий огромные файлы на тысячах хостов, создаст нагрузку — используй фильтры и ограничения. Результаты надо уметь интерпретировать: одно совпадение по имени процесса не доказывает вредоносность, нужен контекст (путь, хэш, родитель). И помни о приватности: сбор данных с личных машин требует правовых оснований.

## Что делать после

По итогам охоты формируют список затронутых хостов и IOC. Для каждого узла решают: изоляция, сбор памяти, очистка. Артефакты и хэши сохраняют как доказательства. Velociraptor можно оставить включённым в режиме мониторинга — тогда следующий инцидент поймается быстрее. Это и есть переход от разового реагирования к постоянной готовности.

## Мини-справочник по VQL и артефактам

Запомни базовый синтаксис и готовые артефакты. Процессы: `SELECT Name, Pid, CommandLine, Username FROM pslist()` — список процессов с командной строкой. Файлы: `SELECT FullPath, Size, Mtime FROM glob(globs="C:/Users/*/AppData/**")` — поиск файлов по шаблону. Реестр: `SELECT * FROM registry(key="HKEY_LOCAL_MACHINE\\Software\\Microsoft\\Windows\\CurrentVersion\\Run")` — автозапуск. Пользователи: `SELECT Name FROM Artifact.Windows.Sys.Users()`. События: `SELECT * FROM parse_evtx(filename=...)`. Готовые артефакты: `Windows.System.Pslist`, `Windows.Registry.Run`, `Windows.EventLogs.Evtx`, `Windows.Network.Netstat`, `Linux.Sys.Users`. Охота: `Hunt` запускает артефакт/запрос на всех агентах и агрегирует результат; клиентский мониторинг выполняет артефакты по расписанию/событиям. Коллекции: каждая содержит результаты, файлы, хэши и время — их можно скачать и приложить к отчёту. Комбинируя эти примитивы, ты формулируешь вопрос («у кого запущен закодированный PowerShell?») и получаешь ответ сразу со всего флота, что и составляет главную силу Velociraptor в крупных сетях.

## Итог: как мыслить охотой

Velociraptor меняет сам подход: вместо «пойди на хост и посмотри» ты задаёшь вопрос всему флоту сразу. Формулируй вопрос точно — «у кого запущен процесс с закодированной командной строкой», «на каких машинах есть файл с таким хэшем», «где в реестре появился такой ключ». Чем конкретнее вопрос, тем меньше шума в результатах. Затем сужай: по хостам, по пользователям, по времени. Собрав кандидатов, переходи к доказательствам — выгрузи файлы, посчитай хэши, сопоставь с IOC. Помни о балансе: мощный запрос на тысячах хостов создаёт нагрузку, поэтому добавляй фильтры. И держи агентов развёрнутыми заранее — без них охота невозможна. Освоив этот цикл (вопрос → охота → сужение → доказательство), ты сможешь реагировать на инцидент в масштабе сети за минуты, а не за дни.

## Что мы теперь знаем

- Velociraptor = сервер + агенты.
- VQL — язык запросов к хостам.
- Артефакты — готовые пакеты сбора.
- Hunt спрашивает весь флот сразу.
- Результаты агрегируются централизованно.

- STL — геометрия; OBJ/GLTF/3MF несут метаданные.
- Бинарный STL: 80-байтовый заголовок + число треугольников.
- GLB = JSON+BIN; 3MF = ZIP+XML.
- Данные прячут в комментариях, чанках и самой геометрии.
- Сравнение с эталоном выявляет встраивание.

## Если не сработало

- Агенты не подключены? Проверь сеть/сертификаты.
- Нужен свой артефакт? Пиши на VQL.
- Нужны файлы? Используй file collection.
