## Вопрос, с которого всё начинается

Ты смотришь на образ Windows и чувствуешь неладное: события будто вырезаны, времена
файлов странные, а свободное место подозрительно чистое. Возможно, злоумышленник
**заметал следы**. Как это доказать?

Анти-форензика — это приёмы сокрытия следов. Но у каждого приёма есть обратная сторона:
само сокрытие оставляет следы. В этом уроке мы найдём их на одном образе.

## Наш пример: образ с признаками чистки

Проверим журнал событий на факт очистки:

```bash
$ evtx_dump -o json System.evtx | jq 'select(.Event.System.EventID==104)'
{"EventData":{"SubjectUserName":"bob","Channel":"Security"}}
```

Событие **104** означает «журнал очищен», а `SubjectUserName: bob` — кто это сделал.
Парадокс: атакующий стирает лог, но система записывает **факт стирания** в сам журнал.
Для журнала Security это событие **1102**.

## Шаг 1: классификация приёмов

| Приём | Цель | Индикаторы |
|-------|------|-----------|
| Timestomping | скрыть время файла | расхождение `$SI`/`$FN`, USN |
| Wiping | уничтожить данные | нули/паттерн, «дыры» в unallocated |
| Log clearing | скрыть действия | Event 1102/104, пробелы во времени |
| Rootkit | скрыть присутствие | несоответствия в памяти/API |
| Шифрование | сделать нечитаемым | энтропия ~8, нет сигнатур |
| ADS | спрятать файл | потоки `$DATA`, скрытые атрибуты |

## Шаг 2: timestomping

Метки времени файла можно подделать. Главный признак — **расхождение** двух наборов
меток в NTFS: `$STANDARD_INFORMATION` (`$SI`) и `$FILE_NAME` (`$FN`). Злоумышленник
правит `$SI`, но `$FN` обновляется только при переименовании и «выдаёт» реальное время.

```bash
$ MFTECmd.exe -f '$MFT' --csv out --csvf mft.csv
$ awk -F, '$10!=$14 {print $1}' out/mft.csv | head
```

`awk` сравнивает колонки времени создания `$SI` и `$FN`; несовпадение — красный флаг.
Подробнее — в уроке `forensics-timestomp`.

## Шаг 3: вайпинг

Утилиты (`sdelete`, `shred`, `cipher /w`) перезаписывают данные нулями или случайными
байтами. Признак — однородные блоки там, где ожидались файлы, и высокая энтропия:

```bash
$ blkls -o 2048 disk.img > unalloc.bin
$ xxd unalloc.bin | grep -c '0000 0000 0000 0000'   # много нулей = вайп
$ binwalk -E unalloc.bin | awk '$3>7.9' | head      # энтропия ~8 = вайп/шифр
```

Парадокс: полное затирание всего диска оставляет **отсутствие** артефактов — это тоже
индикатор. Граница между «данными» и «паттерном» показывает, где именно чистили.

## Шаг 4: скрытые потоки ADS

В NTFS у файла может быть несколько **потоков** данных. Основной — `$DATA`, но
злоумышленник может спрятать информацию в дополнительный поток, который не виден в
проводнике:

```bash
$ fls -o 2048 -r disk.img | grep ':'
r/r 42-128-3: C:\Users\bob\docs\report.docx:secret
$ icat -o 2048 disk.img 42-128-3
```

Строка `report.docx:secret` — это поток `secret` внутри обычного документа. `icat`
читает его по адресу `42-128-3` (inode-поток).

## Шаг 5: руткиты офлайн

Если есть дамп памяти, руткиты ловят сравнением «двух взглядов»: активный список
процессов против скана памяти:

```bash
$ vol -f mem.raw windows.pslist > ps.txt
$ vol -f mem.raw windows.psscan > scan.txt
$ comm -23 <(sort scan.txt) <(sort ps.txt)     # только в psscan = скрытые
```

`pslist` показывает то, что «признаёт» система, `psscan` — то, что реально есть в
памяти. Разница — скрытые процессы. `malfind` находит инъекции, `ssdt` — модификации
таблицы системных вызовов.

## Шаг 6: методология

1. **Снять образ немедленно** — до перезагрузки, которая может активировать «подчистку».
2. **Захватить память** — там руткиты и незашифрованные ключи.
3. **Сравнить источники** — ФС против сырого доступа, `$SI` против `$FN`, EVTX против USN.
4. **Искать пробелы** — отсутствие ожидаемых записей так же значимо, как наличие.
5. **Зафиксировать индикаторы** — сам факт очистки или вайпа уже доказательство.

## Rootkit: инструменты

На диске руткиты ищут `chkrootkit` и `rkhunter` (Linux), `GMER` и `RootkitRevealer`
(Windows). В памяти — через Volatility:

```bash
$ vol -f mem.raw windows.malfind
$ vol -f mem.raw windows.ssdt
```

`malfind` находит внедрённый код, `ssdt` — модификации таблицы системных вызовов.
Всегда помните о «двух взглядах»: если пользовательский API что-то скрывает, сырой
доступ к структурам памяти покажет правду.

## Следы удаления

Сокрытие полезно ловить и «от обратного» — по следам того, что удалили:

- **`$UsnJrnl`** (NTFS) фиксирует `FILE_DELETE` с именем даже после удаления файла.
- **Prefetch «Files referenced»** показывает недавно открытые, а затем удалённые файлы.
- **LNK** остаётся после удаления целевого файла.

```bash
$ MFTECmd.exe -f '$J' --csv out --csvf usn.csv
$ grep -i delete out/usn.csv | head
```

## Шифрование как сокрытие

Данные могут просто зашифровать (вымогатели, скрытые контейнеры): энтропия близка к 8,
сигнатур нет. Отличить шифрование от сжатия помогает контекст: сжатые данные обычно
лежат внутри известных контейнеров (ZIP, PNG), а шифр — «чёрный ящик» без структуры.

## Обнаружение офлайн-руткитов в памяти

```bash
$ vol -f mem.raw windows.pslist > ps.txt
$ vol -f mem.raw windows.psscan > scan.txt
$ comm -23 <(sort scan.txt) <(sort ps.txt)     # только в psscan = скрытые
```

`pslist` читает связанный список процессов, который ведёт ядро; руткит может из него
вырезать запись. `psscan` сканирует пул памяти напрямую и находит процесс даже без
записи в списке. Разница между двумя выводами и есть скрытые процессы.

## Типовые ошибки при разборе

- **Считать «нет улик» = «ничего не было»** — возможно, их уничтожили.
- **Анализировать уже перезагруженную систему** — память потеряна.
- **Игнорировать Event 1102/104** — факт очистки сам по себе улика.
- **Путать сжатие и шифрование** по энтропии без контекста.

## Что мы теперь знаем

- Анти-форензика сама оставляет следы: факт очистки, паттерны вайпа, расхождения меток.
- Event 104/1102 фиксирует очистку журнала и её инициатора.
- Timestomping выдаёт расхождение `$SI` и `$FN`.
- Вайп виден по нулям и высокой энтропии в unallocated.
- Скрытые процессы находят сравнением `pslist` и `psscan`.

## На что смотреть дальше

- **Не верить меткам файлов** — сверяйте `$SI`/`$FN` и USN-журнал.
- **Не считать очищенный лог пустым** — запись о факте очистки остаётся.
- **Проверять ADS** — секрет может лежать в потоке, а не в основном `$DATA`.
- **Путать сжатие и шифрование** по энтропии без контекста.
- **Сравнивать несколько источников времени** — USN-журнал хранит реальное время
  создания и обличает подделку `$SI`.
- **Фиксировать факт сокрытия** — он сам по себе доказательство (ATT&CK T1070).

## Куда дальше

Мы научились замечать сокрытие. Но иногда данные не удаляют, а **прячут на виду** — в
изображениях и медиафайлах. В следующем уроке мы займёмся стеганографией и достанем
флаг из обычной на вид картинки. А пока запомни: **любое сокрытие само оставляет
следы**.

## Где пригодится

- **CTF:** задачи «найди, что спрятали».
- **DFIR:** обнаружение попыток замести следы.
- **Threat Hunting:** выявление руткитов и аномалий.
- **Криминалистика:** доказательство умышленного сокрытия.
- **Пентест:** понимание, как атакующий может скрываться.
