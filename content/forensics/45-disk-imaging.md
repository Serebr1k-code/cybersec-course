Снятие образа (imaging) — первый и самый ответственный шаг форензики: ошибка здесь делает недопустимыми все дальнейшие доказательства. Образ должен быть побайтовой копией, неизменной и верифицируемой. Этот урок — про `dd`/`dc3dd`/`dcfldd`/`FTK Imager`, аппаратные write blockers, форматы (raw/E01/AFF4), хеширование и фиксацию целостности.

## Write blockers

Write blocker — аппаратное или программное устройство, запрещающее запись на исходный носитель. Это обязательное требование: без него любое подключение может изменить улику (обновление last-access, «repair» ФС).

- **Аппаратные**: Tableau, WiebeTech — подключаются между носителем и рабочей станцией.
- **Программные**: монтирование `ro`, `blockdev --setro`, режимы ядра.

```bash
# программная защита (не заменяет аппаратный блокер!)
$ blockdev --setro /dev/sdb
$ hdparm -r1 /dev/sdb
# проверить, что read-only
$ blockdev --getro /dev/sdb
1
```

## dd и его варианты

`dd` — базовый инструмент побайтового копирования, но у него есть недостатки: нет прогресса, хеширования, устойчивости к ошибкам. Поэтому используют улучшенные версии.

```bash
# базовый dd с прогрессом
$ sudo dd if=/dev/sdb of=disk.img bs=4M conv=noerror,sync status=progress
# dc3dd: хеширование, логирование, прогресс
$ sudo dc3dd if=/dev/sdb of=disk.img hash=sha256 log=dd.log
# dcfldd: хеши, split, verify
$ sudo dcfldd if=/dev/sdb of=disk.img hash=sha256 hashwindow=1G hashlog=hash.log
$ sudo dcfldd if=/dev/sdb of=disk.img bs=4M conv=noerror,sync
```

| Флаг | Назначение |
|------|-----------|
| `if`/`of` | вход/выход |
| `bs` | размер блока |
| `count`/`skip`/`seek` | объём/смещение |
| `conv=noerror,sync` | продолжать при ошибках, добивать нулями |
| `status=progress` | прогресс (GNU dd) |
| `hash=sha256` | dc3dd: считать хеш |
| `hashlog`/`log` | файл хеша/лога |

## FTK Imager

GUI-инструмент (Windows) для снятия образов с выбором формата, разбиением на части, хешированием и проверкой. Умеет E01, raw, SMART, монтирование образов. В CLI (`ftkimager`) используется в скриптах.

```bash
$ ftkimager /dev/sdb evidence --e01 --frag 2G --compress 6 \
    --verify --hash sha256
# вывод: evidence.E01, evidence.E02, ... + evidence.txt (хеши, метаданные)
```

FTK Imager автоматически считает MD5/SHA1/SHA256 и создаёт отчёт — это упрощает документирование.

## Форматы образов

| Формат | Особенности |
|--------|-------------|
| raw/dd | побайтовый, монтируется напрямую, без сжатия |
| E01 (EWF) | сжатие, сегменты, CRC/хеши, метаданные |
| AFF4 | открытый, сжатие, верификация |
| SMART | формат с метаданными (Linux) |
| VMDK/QCOW2 | для виртуалок (см. `forensics-vm`) |

```bash
# конвертация raw -> E01
$ ewfacquire disk.img
# E01 -> raw
$ ewfexport -t raw evidence.E01
# проверить E01
$ ewfverify evidence.E01
```

## Хеширование и верификация

Хеш доказывает, что образ идентичен источнику и не изменялся. Считайте хеш **исходного носителя** и **образа**, они должны совпадать.

```bash
$ sha256sum /dev/sdb            # хеш источника (только чтение!)
$ sha256sum disk.img            # хеш образа
# dc3dd считает оба в процессе
$ sudo dc3dd if=/dev/sdb of=disk.img hash=sha256
# E01 несёт встроенные хеши
$ ewfverify evidence.E01
# контроль после анализа
$ sha256sum -c disk.img.sha256
```

```bash
# создать и проверить файл хешей
$ sha256sum disk.img > disk.img.sha256
$ sha256sum -c disk.img.sha256
disk.img: OK
```

## Разобранный пример

Нужно снять образ USB-флешки `/dev/sdb`.

```bash
# 1. Подключить через write blocker, проверить read-only
$ blockdev --getro /dev/sdb
1
# 2. Снять образ с хешами и логом
$ sudo dc3dd if=/dev/sdb of=usb.img hash=sha256 log=usb.log
$ cat usb.log | grep -i hash
sha256 3a7f... usb.img
# 3. Верифицировать
$ sha256sum /dev/sdb
3a7f...  /dev/sdb
$ sha256sum usb.img
3a7f...  usb.img        # совпадает -> целостность подтверждена
# 4. Смонтировать ro для анализа
$ sudo mount -o ro,loop usb.img /mnt/img
```

## Документирование (chain of custody)

Фиксируйте: кто, когда, где, каким инструментом, с какого носителя, серийный номер, хеши, подписи. Формат — форма изъятия + лог. Любой разрыв цепочки ставит под сомнение допустимость.

| Поле | Пример |
|------|--------|
| Улика | USB SanDisk 16GB, S/N ... |
| Изъял | имя, должность |
| Дата/время | 2024-03-01 10:00 UTC |
| Инструмент | dc3dd 7.2, write blocker Tableau |
| Хеш | SHA256 3a7f... |
| Хранилище | сейф, номер |

## Частые ошибки

- **Снимать без write blocker** — улика изменится.
- **Писать образ на тот же носитель** — перезапись.
- **Не считать хеш источника** — нельзя доказать идентичность.
- **`dd` без `conv=noerror,sync`** — при ошибках чтения процесс встанет.
- **Хешировать образ, но не источник** — верификация неполна.
- **Забывать про метаданные** (серийник, модель, размер) в отчёте.

## Что дальше / решение

Конвейер: write blocker → `dc3dd`/`dcfldd`/`ftkimager` → хеш источника и образа → верификация → документирование. Связка: `forensics-disk-images` (форматы и монтирование), `forensics-chain-custody` (допустимость), `forensics-img-acquisition` (глубоко), `forensics-filesystems` (анализ).

## Сетевое снятие образа (network imaging)

Если носитель физически недоступен (сервер в стойке), образ снимают по сети через `dd`+SSH или специализированные агенты.

```bash
# удалённый образ через ssh + dd
$ ssh user@host "dd if=/dev/sda bs=4M conv=noerror,sync" | pv > remote.img
# или на стороне хоста, затем скачать
$ ssh user@host "sudo dc3dd if=/dev/sda of=/tmp/sda.img hash=sha256 log=/tmp/dd.log"
$ scp user@host:/tmp/sda.img .
# сетевые средства: F-Response, EnCase Enterprise, Velociraptor
```

Важно: сетевой сбор сам по себе изменяет систему (создаёт файлы, запускает процессы) — документируйте это и, где возможно, снимайте в порядке волатильности (память раньше диска).

## Особые случаи

- **SSD/TRIM**: TRIM физически обнуляет удалённые блоки; снимайте немедленно, отключите TRIM.
- **Зашифрованные диски** (BitLocker/LUKS): образ снимается, но без ключа не читается — ищите recovery key/пароль.
- **RAID**: нужно определить уровень и порядок дисков; образ снимается с каждого члена (см. `forensics-raid`).
- **LVM/динамические тома**: снимайте физический том, затем собирайте логические.
- **Неисправные носители**: используйте `ddrescue` (устойчив к ошибкам) вместо `dd`.

```bash
$ sudo ddrescue /dev/sdb disk.img disk.maplog
$ sudo ddrescue --idirect /dev/sdb disk.img map.log   # для плохих дисков
```

## Проверка образа перед анализом

Перед разбором убедитесь, что образ читается и целостен: проверьте хеш, смонтируйте ro, проверьте таблицу разделов. Для E01 — `ewfverify`. Фиксируйте результат проверки в отчёте.

## Типовые ошибки (расширенно)

- **Нет write blocker** — улика изменена.
- **Хешируется только образ** — нельзя доказать идентичность источнику.
- **`dd` без `conv=noerror`** — зависание на битых секторах.
- **Образ хранится на том же диске**, что анализируется.
- **Снимается после включения системы** — TRIM/обновления изменили данные.
- **Не документируется цепочка** — доказательство недопустимо.
- **Игнорируется память** — volatile-артефакты теряются.

## Где пригодится

- **CTF:** подготовка образа перед разбором (и понимание, что даёт хеш).
- **Incident Response:** корректное снятие копии инфицированного хоста.
- **Судебная экспертиза:** доказательность и chain of custody.
- **Работа:** лабораторные процедуры, SOP снятия образов.
- **Data recovery:** образ как страховка перед восстановлением.
