Виртуальные машины — обычная часть инфраструктуры и частый объект расследования. Их форензика сложнее физических хостов: диски представлены контейнерами (VMDK/VHDX/QCOW2), состояние размазано по снапшотам и дельта-дискам, а память лежит в отдельных файлах. Этот урок — про разбор VM: форматы дисков, снапшоты, дампы памяти и артефакты гипервизора.

## Форматы дисков

| Формат | Гипервизор | Особенности |
|--------|-----------|-------------|
| VMDK | VMware | monolithic/split, дельта-снапшоты |
| VHD/VHDX | Hyper-V | dynamic/fixed, дельта `.avhdx` |
| QCOW2 | QEMU/KVM | backing file, снапшоты |
| VDI | VirtualBox | dynamic, снапшоты |
| raw | любой | побайтовый |

```bash
$ file disk.vmdk
disk.vmdk: VMware4 disk image
$ qemu-img info disk.vmdk
image: disk.vmdk
file format: vmdk
backing file: base.vmdk          # дельта!
virtual size: 40G
```

## Снапшоты и дельта-диски

Снапшот — не копия диска, а **дельта** изменений относительно родителя. Чтобы получить состояние на момент снапшота, нужно наложить цепочку. В `.vmsd`/`.vmx` описано, какой дельта соответствует какому снапшоту.

```bash
# цепочка дельт
$ qemu-img info disk-000001.vmdk | grep backing
# собрать полный образ
$ qemu-img convert -O raw disk-000001.vmdk full.raw
# Hyper-V дельта
$ ls disk.avhdx
$ qemu-img convert -O raw disk.avhdx full.raw
# VirtualBox снапшоты
$ VBoxManage snapshot vm list
```

Для восстановления состояния на дату: найдите снапшот по времени в `.vmsd`/`.vbox`, наложите соответствующую цепочку.

## Дампы памяти VM

VMware хранит память гостя в `.vmem` (и `.vmss` при приостановке). Hyper-V — в `.bin`/`.vsv`/`.vmrs`. QEMU — в файле, заданном при запуске (`-mem-path`), или через `virsh dump`.

```bash
# VMware: память в .vmem — это raw-дамп
$ vol -f vm.vmem windows.info
# приостановленная VM: .vmss (содержит состояние CPU) + .vmem
# Hyper-V: .bin (память), конвертировать при необходимости
$ vol -f vm.bin windows.pslist
# QEMU/libvirt: дамп памяти
$ virsh dump --memory-only vm /path/mem.raw
```

`.vmss` — состояние приостановки (регистры, память); для анализа памяти нужен `.vmem` или сконвертированный дамп.

## Артефакты гипервизора

- **Конфиги**: `.vmx` (VMware), `.vbox` (VirtualBox), `.xml` (libvirt), `.vmcx` (Hyper-V).
- **Логи**: `vmware.log`, `VBox.log`, `hypervisor`-события.
- **Снапшоты**: `.vmsn`/`.vmsd`, `.vbox` снимки.
- **Хост-артефакты**: недавно запускавшиеся VM, монтированные образы.

```bash
# конфиг VMware: параметры гостя, сеть, диски
$ grep -iE 'displayName|memsize|ethernet|scsi' vm.vmx
# логи
$ tail -50 vmware.log
# VirtualBox
$ VBoxManage showvminfo vm | head
```

## Файловая система гостя

Внутри VMDK/VHDX/QCOW2 — обычная ФС. Монтируйте read-only или разбирайте через TSK.

```bash
# смонтировать через qemu-nbd
$ sudo modprobe nbd max_part=8
$ sudo qemu-nbd --connect=/dev/nbd0 disk.vmdk
$ sudo mount -o ro /dev/nbd0p1 /mnt/vm
# или guestmount
$ guestmount -a disk.vmdk -i --ro /mnt/vm
# TSK напрямую (если qemu-img конвертировал в raw)
$ qemu-img convert -O raw disk.vmdk disk.raw
$ mmls disk.raw && fsstat -o 2048 disk.raw
```

## Разобранный пример

Дан набор файлов VM: `web.vmx`, `web.vmdk`, `web-000001.vmdk`, `web.vmem`.

```bash
# 1. Снапшот активен?
$ qemu-img info web-000001.vmdk | grep backing
backing file: web.vmdk
# 2. Собрать актуальный диск
$ qemu-img convert -O raw web-000001.vmdk web_full.raw
$ mmls web_full.raw
002:  000:00  0000002048  0000411647  NTFS (0x07)
# 3. Смонтировать и найти следы
$ sudo mount -o ro,loop,offset=$((2048*512)) web_full.raw /mnt/vm
$ find /mnt/vm/Users -name '*.exe' -newermt '2024-03-01'
# 4. Память: процессы и C2
$ vol -f web.vmem windows.pslist | head
$ vol -f web.vmem windows.netscan | grep ESTABLISHED
# 5. Конфиг и логи
$ grep -iE 'displayName|ethernet0' web.vmx
$ grep -i 'snapshot' vmware.log | tail
```

## Частые ошибки

- **Анализировать базовый VMDK**, игнорируя дельту — увидите устаревшее состояние.
- **Не определить активный снапшот** по `.vmsd`/`.vbox`.
- **Монтировать rw** — гипервизор/ФС изменят улику.
- **Путать `.vmss` и `.vmem`** — первое состояние CPU, второе память.
- **Забывать про логи гипервизора** — там история запусков и подключений.
- **Не конвертировать формат** перед TSK, если он не raw.

## Что дальше / решение

Конвейер: `qemu-img info` (цепочка) → собрать дельту (`qemu-img convert`) → монтирование (`qemu-nbd`/`guestmount`) → ФС (`mmls`/`fsstat`) → память (`.vmem` → Volatility) → конфиги/логи. Связка: `forensics-disk-images` (образы), `forensics-containers` (виртуализация), `forensics-volatility-deep` (память), `forensics-filesystems` (ФС).

## Гостевые артефакты и хост-следы

Расследование VM — это два уровня: **гость** (ОС внутри) и **хост** (гипервизор).

**Гость**: всё, что в обычной системе (реестр, EVTX, MFT, память гостя). Память берётся из `.vmem`/`.bin`, диск — из сконвертированного образа.

**Хост**: 
- какие VM запускались и когда (`vmware.log`, `VBox.log`, `libvirt` events);
- смонтированные ISO/образы (артефакты монтирования в ОС хоста);
- общие папки (shared folders) — путь обмена данными;
- сетевые режимы (NAT/bridged/host-only) — важны для сетевого анализа;
- файлы VM на диске хоста (`.vmdk`, `.vmem`, снапшоты).

```bash
# история запусков VM
$ grep -iE 'vmx|powered on|powered off' vmware.log | tail
# общие папки
$ grep -iE 'sharedFolder|hgfs' vm.vmx
# монтированные образы на хосте
$ grep -iE '\.iso|\.vmdk' ~/.local/share/recently-used.xbel
```

## Чек-лист расследования VM

1. Зафиксировать файлы VM (диски, память, конфиги, логи, снапшоты).
2. Определить активный снапшот (`.vmsd`/`.vbox`/`*.avhdx`).
3. Собрать актуальный диск (`qemu-img convert`).
4. Смонтировать ro (`qemu-nbd`/`guestmount`).
5. Разобрать ФС (`mmls`/`fsstat`/`fls`).
6. Проанализировать память (`.vmem` → Volatility).
7. Проверить конфиги/логи гипервизора.
8. Сверить время гостя и хоста (часовые пояса, снапшоты).

## Синхронизация времени и артефакты снапшотов

Время в снапшотах и памяти относится к разным моментам. При построении таймлайна учитывайте, какой снапшот/дамп соответствует какому времени. Внутренние часы гостя могут расходиться с хостом — это нормально для VM (особенно после suspend/resume), но аномалии (сильный сдвиг) могут указывать на манипуляции.

## Ограничения

- **Зашифрованные VM** (BitLocker/LUKS внутри) — без ключа нет доступа.
- **Дельта без родителя** — не собрать состояние.
- **Повреждённый `.vmem`** — часть плагинов не отработает.
- **Снапшот-дерево** может быть глубоким; активная ветвь определяется конфигом, а не именем файла.
- **Гипервизор не всегда логирует** — старые версии пишут минимум.

## Краткое резюме

Форензика виртуальных машин ведётся на двух уровнях: гость (обычные артефакты ОС) и гипервизор (конфиги, логи, снапшоты, память). Главная сложность — дельта-диски и снапшоты: актуальное состояние получается наложением цепочки (`qemu-img convert`), а нужный момент определяется по `.vmsd`/`.vbox`. Память гостя лежит в `.vmem`/`.bin` и разбирается Volatility; диск монтируется через `qemu-nbd`/`guestmount`. Не забывайте про логи гипервизора и общие папки — они связывают гостя с хостом и дают дополнительные улики.
