## Вопрос, с которого всё начинается

Вам передали телефон, изъятый по делу. Вопрос простой: **что на нём есть?** Но телефон — это не диск: он зашифрован, заблокирован, а данные разбросаны по десяткам приложений. От того, каким способом вы попытаетесь их достать, зависит, увидите ли вы вообще хоть что-то.

## Наш пример: изъятый Android

У нас Android-телефон. Он включён и разблокирован — это удача, потому что доступ к зашифрованным данным зависит от состояния блокировки. Наша задача — выбрать **уровень извлечения**.

## Шаг 1: уровни извлечения

| Уровень | Что получаем | Требования |
|---------|--------------|------------|
| Manual | что видно на экране | разблокировка |
| Logical | файлы через API/бэкап | разблокировка, разрешённый бэкап |
| Filesystem | вся файловая система | root/jailbreak |
| Physical | сырой образ памяти | exploit/chip-off/JTAG/ISP |

Каждый следующий уровень включает предыдущий и даёт больше, но требует больше привилегий. Начинают всегда с максимально доступного уровня **как можно раньше**.

## Шаг 2: логическое извлечение через ADB

**ADB** (Android Debug Bridge) — штатный инструмент отладки. Проверяем, что устройство видно:

```bash
$ adb devices -l
List of devices attached
R58M12345	device
$ adb shell pm list packages | grep -i signal
package:org.thoughtcrime.securesms
```

Устройство подключено, и на нём установлен **Signal** (`org.thoughtcrime.securesms`). Пробуем логический бэкап:

```bash
$ adb backup -all -f backup.ab
Now unlock your device and confirm the backup operation.
$ abe.jar unpack backup.ab backup.tar
$ tar xf backup.tar
$ ls apps/org.thoughtcrime.securesms/
```

`adb backup` работает, только если пользователь разрешил отладку и подтвердил операцию. Современные Android ограничивают бэкап (`-shared` может быть запрещён). Даже логический бэкап может дать базы мессенджера, если приложение не запрещает бэкап.

## Шаг 3: файловое извлечение (нужен root)

Чтобы получить **всю** файловую систему, нужен root:

```bash
$ adb root
$ adb pull /data/data /evidence/data
```

Важная оговорка: разблокировка загрузчика (`fastboot oem unlock`), которая обычно нужна для root, **стирает userdata** — улики пропадут. Поэтому root применяют только если данные уже извлечены или есть отдельный эксплойт.

## Шаг 4: физическое извлечение

Когда логическое и файловое невозможны (устройство заблокировано, данные стёрты), применяют физическое:

- **Chip-off.** Микросхему памяти снимают с платы и читают программатором. Риск повредить чип.
- **ISP** (In-System Programming). Чтение чипа прямо на плате по линиям eMMC/UFS, без снятия.
- **JTAG.** Доступ через тестовые точки процессора.
- **Bootloader exploit.** Использование уязвимости загрузчика для доступа к ФС без разборки.

```bash
# После чтения дампа чипа — монтируем разделы
$ mmls emmc_dump.bin
$ fls -o <offset> -r emmc_dump.bin
```

## Шаг 5: шифрование и время

Современные устройства шифруют данные «на лету». Для Android это **FBE** (файловое шифрование): ключи хранятся в защищённом модуле (TEE), и без разблокировки доступны только метаданные. Для iOS — **Data Protection** с классами.

Ключевое различие — **AFU/BFU**: *After First Unlock* (после первого разблокирования) и *Before First Unlock* (до него). До первого разблокирования после включения доступ минимален; после — больше. Поэтому **время извлечения критично**: сразу после разблокировки доступно максимум.

Практический чек-лист:

1. Зафиксировать модель, ОС, состояние (AFU/BFU), заряд.
2. Включить режим полёта — остановить удалённое стирание (Find My / MDM).
3. Выбрать уровень: logical → filesystem → physical.
4. Извлечь, посчитать хеш, задокументировать инструмент и время.
5. Разобрать артефакты (`ALEAPP`/`iLEAPP`), проверить на шпионское ПО (`MVT`).

## Полный разбор: от изъятия к данным

Соберём сценарий с изъятым Android в один путь.

1. **Изоляция.** Телефон помещают в «глушилку» (Faraday bag) — чтобы его нельзя было стереть удалённо. Фиксируют состояние экрана.
2. **Блокировка.** Если экран заблокирован — нужен пароль/паттерн либо обход (сложно и зависит от версии). Фиксируйте это в отчёте.
3. **Выбор уровня извлечения** (см. таблицу ниже) — от него зависит, что вы вообще получите.
4. **Логическое извлечение** (без root):
   ```bash
   $ adb devices
   $ adb backup -apk -shared -all -f backup.ab
   ```
5. **Разбор бэкапа.** `backup.ab` — контейнер (сжатый, иногда с паролем); распаковывается `abe.jar` или `android-backup-extractor`.
6. **Анализ.** Базы SQLite (переписка, контакты, геолокация), медиа, `shared_prefs`.

Ключ: уровень извлечения определяет объём данных; логическое даёт меньше всего, физическое — максимум.

## Уровни извлечения в сравнении

| Уровень | Что получаем | Root нужен | Примечание |
|---------|--------------|------------|------------|
| Логическое | данные, экспортируемые API | нет | быстрее всего, неполно |
| Файловое | вся ФС (данные приложений) | да | нужен root/adb root |
| Физическое | образ всей памяти | часто | JTAG/ISP/chip-off |
| Облачное | синхронизированные данные | нет | через сервис/аккаунт |

Физическое извлечение даёт и удалённые данные, но требует разборки и рискует устройством — это крайняя мера.

## Если не сработало

- **`adb backup` пустой.** На новых Android приложения запрещают резервное копирование; нужен root или физическое извлечение.
- **Устройство зашифровано (FBE).** Без ключа физический образ бесполезен; ключ связан с экраном/аппаратным модулем.
- **Экран заблокирован, данных нет.** Обращайтесь к облачному извлечению или к брутфорсу (ограничен по попыткам и может стереть данные).
- **Устройство ушло в загрузку/обновилось.** Мог сработать удалённый вайп — фиксируйте время и сеть.
- **Инструмент не поддерживает модель.** Обновите Cellebrite/UFED или используйте низкоуровневый JTAG.

## Инструмент: sqlite3 — файл как база

`sqlite3` открывает файл БД и даёт SQL-консоль. В мобильной/веб-форензике это первый инструмент: приложения хранят данные в SQLite.

Ключи, которые пригодятся:
* `sqlite3 app.db` — открыть базу;
* `.tables` — список таблиц; `.schema <таблица>` — структура;
* `select * from <таблица>;` — вывести строки;
* `.dump` — весь дамп; `sqlite3 app.db "select ..."` — запрос одной командой.

### Рабочий пример (как в лаборатории)

```
$ sqlite3 msgstore.db ".tables"
message
```

Подсказка из лаборатории: `sqlite3 <база> [SQL] — эмуляция sqlite3 (вывод захвачен из реального запуска)`.

## Что мы теперь знаем

- Уровни извлечения: **manual → logical → filesystem → physical**; каждый даёт больше, но требует больше прав.
- `adb backup` — логическое извлечение; ограничено разрешениями приложений.
- Файловое извлечение требует root; разблокировка загрузчика **стирает данные**.
- Физическое извлечение (chip-off/ISP/JTAG) даёт сырой образ, но рискованно.
- **AFU/BFU** определяют, сколько зашифрованных данных доступно; извлекать надо как можно раньше.
- Включение Wi-Fi может запустить удалённое стирание — используйте режим полёта.

## Если не сработало: шифрование и инструменты

Современные устройства сопротивляются извлечению. Что делать:

- **Шифрование.** Android FBE и iOS Data Protection означают, что без разблокировки доступны в основном метаданные. Иногда помогает извлечение в состоянии AFU.
- **Инструменты.** Коммерческие (`Cellebrite UFED`, `MSAB XRY`, `Oxygen`, `Belkasoft`) покрывают весь спектр, но дороги; открытые (`adb`, `libimobiledevice`, `ALEAPP`/`iLEAPP`) достаточны для многих задач.
- **Проверка на шпионское ПО.** `MVT` (Amnesty) сверяет артефакты устройства с публичными IoC (например, Pegasus):

```bash
$ mvt-ios check-backup --output /evidence/mvt /evidence/ios_backup
```

- **Верификация.** После извлечения сверяйте логические и физические данные, считайте хеши разделов и фиксируйте версию прошивки.

Правовая сторона не менее важна: извлечение требует санкции, а переписка может затрагивать третьих лиц — минимизируйте собираемое.
