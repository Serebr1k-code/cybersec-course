Мобильная форензика начинается с выбора **уровня извлечения**. От него зависит, что вы вообще сможете увидеть: только файлы, доступные через API, всю файловую систему или сырой образ памяти. Уровни различаются требованиями (root/jailbreak, разблокировка) и глубиной (удалённые данные, ключи, кэши).

## Уровни извлечения

| Уровень | Что получаем | Требования | Инструменты |
|---------|--------------|------------|-------------|
| Manual | что видно на экране | разблокировка | камера, скриншоты |
| Logical | файлы через API/бэкап | разблокировка, бэкап | ADB, iTunes/Finder |
| Filesystem | вся ФС | root/jailbreak | ADB root, Frida |
| Physical | сырой образ памяти | exploit/chip-off/JTAG/ISP | Cellebrite, chip-off |

Каждый следующий уровень включает предыдущий и даёт больше, но требует больше привилегий.

## Android: логическое и файловое извлечение

```bash
# ADB: список устройств и базовое извлечение
adb devices -l
adb shell getprop ro.build.version.release
# Логический бэкап (если разрешён)
adb backup -apk -shared -all -system -f backup.ab
# Конвертировать .ab в tar
abe.jar unpack backup.ab backup.tar
# Файловое (нужен root)
adb root
adb pull /data/data /evidence/data
# Пакеты приложений
adb shell pm list packages -f
```

`adb backup` работает только если пользователь разрешил отладку и не заблокировал бэкап; современные Android ограничивают `-shared`.

## iOS: логическое и файловое извлечение

```bash
# libimobiledevice
idevice_id -l
ideviceinfo
# Логический бэкап (без пароля)
idevicebackup2 backup --full ./backup
# С паролем бэкапа
idevicebackup2 -i backup --full ./backup
# Извлечение из бэкапа
#   Manifest.db — SQLite-индекс бэкапа
sqlite3 backup/Manifest.db 'select fileID, relativePath, domain from Files;'
# Файловая система (нужен jailbreak + AFC2/ssh)
ssh root@<device-ip>
```

Бэкап iOS — это не ФС, а набор файлов с хешированными именами; `Manifest.db` связывает `fileID` с путём.

## Физическое извлечение

Когда логическое/файловое невозможно (заблокированное устройство, стёртые данные), применяют физическое:

- **Chip-off.** Микросхему памяти снимают с платы и читают программатором. Риск повреждения, требует reballing.
- **ISP (In-System Programming).** Чтение чипа прямо на плате по eMMC/UFS-линиям, без снятия.
- **JTAG.** Доступ через тестовые точки процессора; часто требует разборки и восстановления.
- **Bootloader exploit / full filesystem.** Использование уязвимости загрузчика для доступа к ФС без разборки.

```bash
# Пример работы с eMMC через easy-JTAG/Medusa (специализированное оборудование)
# Чтение дампа, затем монтирование разделов
mmls emmc_dump.bin
fls -o <offset> -r emmc_dump.bin
```

## Шифрование и блокировка

Современные устройства шифруют данные «на лету». Последствия:

- **Android (FBE).** Файловое шифрование: ключи в TEE/StrongBox; без разблокировки доступны только метаданные.
- **iOS.** Data Protection с классами; часть данных доступна после первого разблокирования, часть — только при активном устройстве.
- **AFU/BFU.** After First Unlock / Before First Unlock — ключевое различие: до первого разблокирования после включения доступ минимален.

Поэтому **время извлечения** критично: сразу после разблокировки доступно больше.

## Разобранный пример

```bash
$ adb devices
List of devices attached
R58M12345	device
$ adb shell pm list packages | grep -i signal
package:org.thoughtcrime.securesms
$ adb backup -all -f backup.ab
Now unlock your device and confirm the backup operation.
$ abe.jar unpack backup.ab backup.tar
$ tar xf backup.tar
$ ls apps/org.thoughtcrime.securesms/
```

Даже логический бэкап может дать базы мессенджера (если приложение не запрещает бэкап).

## Краевые случаи и подводные камни

- **Блокировка/шифрование.** Большинство современных устройств не дадут данные без разблокировки.
- **Разряд батареи.** Устройство может перейти в состояние с меньшим доступом.
- **Обновления ОС.** Метод, работавший на одной версии, не работает на другой.
- **Антифорензика.** Приложения с «паникой» (стирание при неверном пароле).
- **Целостность.** При chip-off можно повредить чип; фиксируйте исходное состояние.
- **Юрисдикция.** Извлечение требует санкции.
- **Время.** Извлекайте как можно раньше (AFU vs BFU).

## Инструменты коммерческие и открытые

| Инструмент | Назначение | Уровень |
|------------|------------|---------|
| Cellebrite UFED | полный спектр (logical→physical) | коммерческий |
| MSAB XRY | мобильная форензика | коммерческий |
| Oxygen Forensic | извлечение и анализ | коммерческий |
| Belkasoft | мобильные + ПК | коммерческий |
| MVT (Amnesty) | проверка на шпионское ПО (iOS/Android) | открытый |
| libimobiledevice | работа с iOS без iTunes | открытый |
| adb / scrcpy | Android | открытый |
| ALEAPP/iLEAPP | парсинг артефактов Android/iOS | открытый |
| MobSF | статический/динамический анализ APK | открытый |

```bash
# ALEAPP: разбор извлечённых Android-артефактов
python3 -m aleapp -t fs -i /evidence/android_fs -o /evidence/aleapp_out
# iLEAPP для iOS-бэкапа/ФС
python3 -m ileapp -t itunes -i /evidence/ios_backup -o /evidence/ileapp_out
# MVT: проверка iOS-бэкапа на IoC
mvt-ios check-backup --output /evidence/mvt /evidence/ios_backup
```

ALEAPP/iLEAPP автоматически разбирают сотни артефактов (история, сообщения, локации) — это огромная экономия времени.

## Проверка на шпионское ПО (MVT)

MVT сравнивает артефакты устройства с публичными IoC (например, Pegasus). Для iOS-бэкапа:

```bash
mvt-ios check-backup --iocs pegasus.stix2 --output ./mvt_out ./ios_backup
# Результат: JSON с подозрительными процессами, DNS, конфигами
cat ./mvt_out/*.json | jq '.'
```

Для Android — `mvt-android check-backup` и анализ логов `sysdiagnose`.

## Уровни доступа к Android

- **Non-root** — ADB, бэкап, установка агентов (ограничено).
- **Root** — полный доступ к `/data`, но требует разблокированного загрузчика (стирает данные).
- **Agent-based** — установка приложения-агента, снимающего данные (эквивалент root, но не всегда).

Важно: разблокировка загрузчика (fastboot oem unlock) **стирает userdata** — теряются улики. Поэтому root применяют только если данные уже извлечены или есть эксплойт.

## Учёт часовых поясов и времени

Мобильные устройства хранят время в UTC, но приложения могут использовать локальное время или «wall clock». При построении таймлайна:

- Приводите всё к UTC.
- Учитывайте `timestamp` в разных единицах (секунды/миллисекунды/наносекунды).
- Сверяйте время устройства с реальным (часы могли быть переведены).

## Практический чек-лист извлечения

1. Зафиксировать модель, ОС, состояние (AFU/BFU), уровень заряда.
2. Включить режим полёта (если возможно) — остановить удалённое стирание.
3. Выбрать уровень: logical → filesystem → physical.
4. Извлечь, посчитать хеш, задокументировать инструмент.
5. Разобрать артефакты (ALEAPP/iLEAPP), проверить на шпионское ПО (MVT).
6. Сопоставить с сетевыми/облачными данными.

## Типичные ошибки

- **Включение Wi-Fi.** Может сработать удалённое стирание (Find My / MDM).
- **Разблокировка загрузчика.** Стирает данные.
- **Позднее извлечение.** AFU→BFU теряет доступ.
- **Игнорирование облака.** Часть данных в iCloud/Google.
- **Единый инструмент.** Разные инструменты дают разное; сверяйте.
- **Нет хешей.** Сложно доказать целостность.
- **Часовые пояса.** Ошибки в таймлайне.

## Правовые и этические аспекты

Извлечение данных с мобильных устройств — наиболее чувствительная область форензика:

- **Санкция обязательна.** Извлечение требует законного основания.
- **Минимизация.** Извлекайте только то, что нужно для дела.
- **Личные данные третьих лиц.** Переписка может затрагивать непричастных.
- **Облако.** Данные могут быть вне юрисдикции.
- **Согласие владельца.** В корпоративном контексте — политика BYOD.

## Верификация извлечения

После извлечения полезно:

- Сравнить **логические и физические** данные (расхождения — сигнал).
- Проверить **хеши** разделов/образов.
- Убедиться, что инструмент **не изменил** устройство.
- Зафиксировать **версию прошивки** и ОС.

```bash
# Хеш извлечённого образа
sha256sum android_fs.tar > android_fs.sha256
# Сравнить с заявленным инструментом значением
```

## Итоговая таблица уровней

| Уровень | Удалённые данные | Ключи/шифрование | Сложность |
|---------|------------------|------------------|-----------|
| Logical | обычно нет | нет | низкая |
| Filesystem | частично | частично | средняя |
| Physical | да | да | высокая |

Чем выше уровень, тем больше шансов на удалённые данные и ключи, но тем выше требования и риск.

## Хранение и обмен извлечёнными данными

Извлечённые мобильные данные объёмны и чувствительны:

- **Шифрование при хранении** (LUKS/BitLocker на носителе улик).
- **Контроль доступа** — только уполномоченные.
- **Копии** — минимум две, раздельно.
- **Логирование доступа** — кто и когда открывал.
- **Минимизация** — не копируйте лишнее.

```bash
# Шифрованный контейнер для улик
cryptsetup luksFormat /dev/sdc1
cryptsetup open /dev/sdc1 evidence
mkfs.ext4 /dev/mapper/evidence
mount /dev/mapper/evidence /evidence
```

## Итог

Выбор уровня извлечения определяет всё дальнейшее: логическое быстро, но поверхностно; физическое глубоко, но сложно и рискованно. Всегда начинайте с максимально доступного уровня как можно раньше (AFU), фиксируйте состояние и хеши, а затем углубляйтесь по мере необходимости.

## Что дальше / решение

1. Определить модель, версию ОС, состояние блокировки.
2. Выбрать уровень: logical → filesystem → physical.
3. Собрать как можно раньше (особенно iOS AFU).
4. Извлечь и задокументировать (хеши, инструмент, время).
5. Разобрать артефакты приложений (см. `forensics-app-artifacts`).
