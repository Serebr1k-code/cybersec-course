## Вопрос, с которого всё начинается

В прошлом уроке мы вырезали из прошивки ZIP-архив. Открываем — а он требует пароль.
Всё, цепочка встала: флаг внутри, а ключа нет.

Так бывает очень часто. Архив — самый популярный контейнер и в CTF, и в реальных
инцидентах. В этом уроке научимся: определить, **чем именно** защищён архив, вытащить
из него хеш пароля и подобрать пароль. А иногда — вскрыть архив вообще без пароля.

## Наш пример: backup.zip

```bash
$ file backup.zip
backup.zip: Zip archive data, made by v6.3 UNIX, extract using at least v5.1,
last modified Oct 12 2026 08:13:08, uncompressed size 21, method=AES Encrypted
```

Ключевое слово в выводе — `method=AES Encrypted`. Это значит, что содержимое
зашифровано современным алгоритмом **AES**, а не старым ZipCrypto. Запомним это —
от типа шифрования зависит, какой способ взлома вообще применим.

Посмотрим список файлов, не распаковывая:

```bash
$ unzip -l backup.zip
Archive:  backup.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
       21  2026-10-12 08:13   flag.txt
---------                     -------
       21                     1 file
```

Имена файлов видны — значит, зашифровано только содержимое, а не список. (Бывает
и наоборот, когда прячут даже имена; об этом ниже.) Внутри — `flag.txt`. Пробуем
открыть:

```bash
$ unzip -P '' backup.zip
[backup.zip] flag.txt password:
```

Пустой пароль не подошёл. А если бы даже подошёл — Info-ZIP не умеет AES:

```bash
$ unzip -P secret123 -o backup.zip -d out/
   skipping: flag.txt   need PK compat. v5.1 (can do v4.6)
```

Поэтому AES-архивы распаковывают через `7z`, а не `unzip`. Эта деталь часто сбивает
новичков: они видят «password incorrect» или «не поддерживается» и думают, что пароль
неверный, хотя на деле инструмент просто не умеет нужный формат шифрования.

## Какой это тип шифрования — важно

У ZIP-архивов два вида защиты:

- **ZipCrypto** — старый, слабый. Пароль проверяется быстрой функцией, и если у тебя
  есть хоть 12 байт **известного открытого текста** одного из файлов, пароль можно
  не подбирать вовсе (атака известного открытого текста, инструмент `bkcrack`).
- **AES-256** — современный. Быстрых атак нет, только честный перебор по хешу.

Понять, что перед нами, помогает `7z`:

```bash
$ 7z l -slt backup.zip
Path = flag.txt
Size = 21
Encrypted = +
Method = AES-256 Store
```

`Method = AES-256` подтверждает: известный открытый текст не поможет, нужен словарь
или перебор. (Для ZipCrypto тут было бы `ZipCrypto Deflate`.)

## Извлекаем хеш пароля

Чтобы подбирать пароль **офлайн** (быстро, без обращений к архиву), нужен хеш.
Конвертер `zip2john` из набора John the Ripper достаёт его из архива:

```bash
$ zip2john backup.zip > zip.hash
$ head -c 80 zip.hash
backup.zip:$pkzip2$3*1*1*0*8*24*4a1c*...::flag.txt
```

Теперь подбираем пароль по словарю:

```bash
$ john --wordlist=/usr/share/wordlists/rockyou.txt zip.hash
Loaded 1 password hash (PKZIP [32/64])
secret123        (backup.zip)
```

Пароль — `secret123`. Подбор занял секунды, потому что пароль слабый. Альтернатива —
`hashcat` (у него свой набор режимов):

```bash
$ hashcat -m 13600 -a 0 zip.hash rockyou.txt      # 13600 = WinZip AES
$ hashcat -m 17200 -a 0 zip.hash rockyou.txt      # 17200 = ZipCrypto
$ hashcat -m 17200 -a 3 zip.hash '?d?d?d?d'       # перебор 4 цифр (маска)
```

Число после `-m` — это режим, соответствующий формату шифрования. Перепутаешь —
хеш «не сломается», хотя пароль верный.

| Формат | hashcat mode | Конвертер John |
|--------|-------------|----------------|
| ZIP (ZipCrypto) | 17200 | `zip2john` |
| ZIP (WinZip AES) | 13600 | `zip2john` |
| RAR5 | 13000 | `rar2john` |
| 7-Zip | 11600 | `7z2john` |

## Открываем архив

```bash
$ 7z x backup.zip -psecret123 -oout/ -y
$ cat out/flag.txt
CTF{n3st3d_4rch1v3s}
```

Готово. Обрати внимание: **подбор шёл по извлечённому хешу**, а не «в лоб» по
архиву. Онлайн-перебор пароля по архиву медленный и шумный; офлайн по хешу — быстрый.

## Если пароля нет, а есть известный текст

Для ZipCrypto есть отдельный трюк — атака известного открытого текста. Если внутри
архива есть предсказуемый файл (например, `readme.txt`, чью версию ты можешь
воссоздать), ключ восстанавливается без перебора:

```bash
$ bkcrack -C archive.zip -c readme.txt -p readme.txt
[keys] 8f3a2b1c 4d5e6f70 8192a3b4
$ bkcrack -C archive.zip -k 8f3a2b1c 4d5e6f70 8192a3b4 -D out.zip
```

Это работает только для ZipCrypto. Для AES такого пути нет.

## Если даже имён не видно

У 7z есть режим `-mhe=on`: тогда зашифрованы и имена файлов. `7z l` без пароля
ничего не покажет, и `7z2john` не сможет извлечь хеш — остаётся только перебор по
всему контейнеру:

```bash
$ 7z x secret.7z -pПАРОЛЬ
```

Ещё две ловушки:
- **Вложенные архивы** — `binwalk -e -M` распакует матрёшку рекурсивно.
- **Zip-bomb** — маленький архив, разворачивающийся в гигабайты. Не распаковывай
  «в лоб», сначала посмотри суммарный `Length` в `unzip -l` и ограничь размер.

## Как понять, что это за архив

Расширению верить нельзя, поэтому определяем формат по сигнатуре (первые байты):

| Формат | Сигнатура | Признак |
|--------|-----------|---------|
| ZIP | `50 4B 03 04` (`PK..`) | `file` → Zip archive |
| RAR | `52 61 72 21 1A 07` (`Rar!..`) | `file` → RAR archive |
| 7z | `37 7A BC AF 27 1C` | `file` → 7-zip archive |
| gzip | `1F 8B 08` | один файл, не список |

У RAR и 7z свои инструменты: `unrar` и `7z`. Помни: `unzip` не читает AES-архивы
и RAR/7z вовсе, поэтому универсальный выбор — `7z x`, он понимает почти всё.

## Вложенные архивы

Авторы задач любят «матрёшку»: ZIP внутри 7z внутри RAR. Распаковывать по одному
утомительно, а иногда формат внутреннего слоя заранее неизвестен. Тогда снова
выручает автоматика:

```bash
$ binwalk -e -M nested.bin          # найдёт и распакует все слои
$ 7z x nested.zip -oout/ -y         # один слой
```

Частый приём CTF: пароль от верхнего архива подходит и к вложенному. Поэтому,
подобрав пароль один раз, попробуй его на всех уровнях, прежде чем ломать заново.

## Гигиена: фиксируем хеш до распаковки

Архив — такая же улика, как и всё остальное. Прежде чем что-то с ним делать,
зафиксируй целостность и работай с копией:

```bash
$ sha256sum suspect.zip | tee hash.txt
$ cp suspect.zip suspect.work
$ 7z x suspect.work -oout/ -y
```

Ещё одна ловушка — **zip-bomb**: маленький архив, который разворачивается в гигабайты.
Не распаковывай «в лоб»: сначала посмотри суммарный размер в `unzip -l`, а при
сомнении ограничь размер файлов через `ulimit -f`.

## Что мы теперь знаем

- Тип шифрования определяет стратегию: ZipCrypto слабый, AES-256 — только перебор.
- `7z l -slt` показывает `Method` и `Encrypted`; `unzip` не умеет AES.
- `zip2john` достаёт хеш, `john`/`hashcat` подбирают пароль **офлайн**.
- Режим hashcat (`-m`) обязан соответствовать формату, иначе подбор не сработает.
- ZipCrypto при известном открытом тексте вскрывается `bkcrack` без перебора.

## Куда дальше

Архив открыт. Но часто нужные сведения лежат не внутри файлов, а **в их свойствах**:
кто создал, когда, где снято фото. В следующем уроке разберём метаданные — снимем
их через `exiftool` и найдём то, что автор не собирался показывать. А пока запомни:
**сначала пойми тип шифрования, потом извлекай хеш и подбирай офлайн**.

## Где пригодится

- **CTF:** задачи «архив с паролем» и «матрёшка из архивов».
- **Data recovery:** доступ к защищённым резервным копиям.
- **Incident Response:** анализ архивов, похищенных злоумышленником.
- **Криминалистика:** вскрытие зашифрованных контейнеров с доказательствами.
- **Пентест:** проверка стойкости паролей на архивах.
