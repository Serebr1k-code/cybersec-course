## Вопрос, с которого всё начинается

Перед тобой строка `S2FsaSBpcyBoZXJl` или blob в base64 внутри base64. Декодировать
руками больно. **CyberChef** — браузерный конструктор преобразований: собираешь
«рецепт» из операций и применяешь. Разберём.

## Наш пример: закодированные данные

## Шаг 1: идея

CyberChef — это **Input → Operations → Output**. Ты добавляешь операции в «рецепт»:

- From Base64;
- From Hex;
- Gunzip;
- XOR;
- Decrypt AES.

## Шаг 2: типовой рецепт

Строка в base64, внутри gzip, внутри текст:

```
Input:  H4sIAAAA...
Ops:    From Base64 → Gunzip
Output: "secret message"
```

CyberChef показывает результат по шагам — видно, что происходит.

## Шаг 3: XOR-брут

Классика CTF — XOR одним байтом:

```
Op: XOR Brute Force (key 1..255)
```

CyberChef прогоняет все ключи и показывает читаемые результаты.

## Шаг 4: «Magic»

Кнопка **Magic** автоматически подбирает операции:

```
Magic → detected: Base64 → Gunzip → UTF-8
```

Иногда угадывает; иногда подсказывает направление.

## Шаг 5: практика

- декодирование CTF-строк;
- расшифровка простых шифров;
- разбор вредоносных скриптов;
- работа с protobuf/JSON;
- извлечение из бинарных данных.

## Шаг 6: как читать результат по шагам

CyberChef показывает вывод каждой операции отдельно — это главное преимущество. Собирая рецепт, ты видишь, где данные «сломались»:

```
Ops: From Base64 → Gunzip → Decode text (UTF-8)
Step 1 output: <binary>
Step 2 output: <gzip data>
Step 3 output: "secret message"
```

Если на каком-то шаге мусор — операция выбрана неверно.

## Шаг 7: извлечение данных из бинарников

Операции «Strings», «Extract IP addresses», «Extract URLs» работают прямо в CyberChef:

```
Ops: Strings (min length 4) → Extract URLs
Output: http://203.0.113.5/stage2.sh
```

Так из вредоносного blob достают индикаторы, не поднимая отдельный инструмент.

## Шаг 8: типовые CTF-цепочки

- Base64 → Gzip → текст;
- Hex → XOR(key) → текст;
- URL-decode → Base64 → JSON;
- ROT13 → Base64;
- AES/ChaCha20 с известным ключом.

Для криптоопераций ключ и IV задаются в настройках операции.

## Шаг 9: автоматизация и офлайн

CyberChef можно запускать офлайн (один HTML-файл) и вызывать из скриптов через node API. Для повторяющихся задач удобен «рецепт в URL» — вся цепочка кодируется в ссылке, её можно сохранить и передать.

## Шаг 10: ограничения

- не заменяет настоящую криптоаналитику;
- Magic может ошибаться;
- для больших файлов браузер тяжёл;
- чувствительные данные прогоняй только локально, не в онлайн-версии.

## Шаг 11: структурированные данные

CyberChef умеет разбирать не только текст, но и структуры. «Parse protobuf», «From JSON»/«To JSON», «Parse TLV» превращают бинарные форматы в читаемый вид:

```
Ops: From Hex → Parse protobuf
Output: { field1: "user", field2: 42 }
```

Для малвари это способ вытащить конфигурацию из бинарного протокола без написания кода.

## Шаг 12: хэши и сверка

Операция «Compute hash» считает MD5/SHA-1/SHA-256 прямо в браузере:

```
Ops: SHA2 (256)
Output: 9f86d081... 
```

Это удобно, чтобы сверить хэш подозрительного файла с известным (VirusTotal/базой) или проверить, что два образца идентичны, не выгружая их наружу.

## Шаг 13: рецепт как артефакт расследования

Рецепт CyberChef кодируется в URL. Это значит, что последовательность преобразований можно зафиксировать в отчёте и воспроизвести позже — важное свойство для доказательной базы: «данные получены следующим рецептом» проверяемо.

## Шаг 14: практический кейс CTF

Строка вида `S2FsaSBpcyBoZXJl`:

1. From Base64 → «Kali is here» — просто;
2. если внутри снова base64/gzip — добавляем операции;
3. XOR Brute Force, если текст нечитаем;
4. Magic как подсказка, если зашли в тупик;
5. сохраняем рецепт для повторения.

Так одна строка «раскручивается» до флага пошагово.

## Практика: раскручиваем вложенную строку

Дана строка:

```
$ cat input.txt
SGVsbG8sIFdvcmxkIQ==
```

From Base64:

```
Ops: From Base64
Output: Hello, World!
```

Просто. Теперь посложнее — строка в base64, внутри hex, внутри текст:

```
Input: NjQ2OTZmNjU3NDNhNzQ2ODY1NzM2NTY3NzI2NTc0
From Base64  -> 64696f65743a746865736563726574
From Hex     -> diotet:thesecret
```

Хм, получилось «diotet:thesecret» — похоже на опечатку в данных, но структура ясна: две вложенные кодировки. Проверим порядок: если применить Hex первым — получим мусор. CyberChef показывает вывод каждого шага, поэтому перестановка операций видна сразу.

Если текст остаётся нечитаемым, добавляем XOR Brute Force:

```
Ops: From Base64 -> From Hex -> XOR Brute Force
Output (key 42): secret payload
```

XOR Brute Force прогоняет все ключи 1..255 и подсвечивает читаемые результаты.

Фиксируем рецепт в URL и сохраняем в отчёт — воспроизводимость важна для доказательной базы.

## Что важно

- Покаждому шагу видно, где данные «сломались».
- Порядок операций критичен.
- XOR Brute Force выручает при простой обфускации.
- Рецепт в URL = воспроизводимость.

## Когда CyberChef не подходит

CyberChef хорош для разбора, но у него есть границы.

**Настоящая криптография.** AES/RSA с неизвестным ключом CyberChef не «взломает». Он применяет операции при известном ключе, но не заменяет криптоанализ. Для реального взлома нужны специализированные инструменты и математика.

**Большие файлы.** Браузер держит данные в памяти. Гигабайтный дамп в CyberChef не загрузится — используй `strings`, `binwalk`, `bulk_extractor`.

**Повторяемые пайплайны.** Если задачу надо гонять на сотнях файлов, удобнее скрипт (`python`, `grep`, CLI-инструменты), а не ручной рецепт.

**Конфиденциальность.** Онлайн-версия отправляет данные в браузер, но привычка «вставить секрет в веб» опасна. Для чувствительных данных — только локальный офлайн-билд.

**Сложная логика.** Условные преобразования, циклы, работа с таблицами — не про CyberChef.

Итог: CyberChef — для быстрого интерактивного разбора небольших данных. Всё тяжёлое и массовое — скриптами.

## Что запомнить по CyberChef

Коротко о главном. CyberChef — это конструктор рецептов: вход, цепочка операций, выход. Его сила в пошаговом показе результата — сразу видно, какая операция испортила данные. Типовые задачи: декодирование Base64/Hex, распаковка Gzip, XOR Brute Force, разбор структур (protobuf/JSON). Кнопка Magic подсказывает цепочку, но ошибается — проверяй вручную. Рецепт кодируется в URL, что делает разбор воспроизводимым и пригодным для отчёта. Помни границы: настоящую криптографию он не взламывает, большие файлы не тянет, а чувствительные данные лучше прогонять только в офлайн-версии. Используй его для быстрого интерактивного разбора небольших данных.

## Что мы теперь знаем

- CyberChef собирает рецепты из операций.
- Работает по шагам, показывает промежуточный результат.
- XOR Brute Force и Magic ускоряют разбор.
- Идеален для CTF и разбора скриптов.

- Рецепт показывают по шагам — видно, где сбой.
- «Strings», «Extract URLs/IPs» достают индикаторы.
- Типовые цепочки: Base64→Gzip, Hex→XOR и др.
- Работает офлайн; рецепт кодируется в URL.
- Не заменяет криптоанализ; Magic ошибается.

- «Parse protobuf»/«From JSON» разбирают структуры, не только текст.
- «Compute hash» считает контрольные суммы локально.
- Рецепт кодируется в URL — воспроизводимое доказательство.
- Кейс CTF: пошагово раскручиваем вложенные кодировки.

## Если не сработало

- Слишком сложно для Magic? Разбирай по шагам вручную.
- Нужна криптография? Используй операции Decrypt.
- Данные большие? Ограничь объём/используй скрипт.
