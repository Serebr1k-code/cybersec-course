## Вопрос, с которого всё начинается

Нужно понять активность человека: где был, спал ли, тренировался. Ответ — в носимом
устройстве и его приложении. Данные чувствительные (здоровье, геолокация). Разберём,
как их достать.

## Наш пример: фитнес-трекер

## Шаг 1: два источника

Данные есть в двух местах:

- **на устройстве** (ограниченно, часто только за дни);
- **в синхронизированном приложении** (полная история, месяцы).

Приложение почти всегда богаче — начинай с телефона владельца.

## Шаг 2: приложение

Приложения (Fitbit/Garmin/Apple Health) хранят SQLite-базы:

```
$ find /data/data -name '*.db' | grep -i fit
```

Внутри: шаги, пульс, сон, GPS-точки, workouts. Apple Health — база `healthdb_secure.sqlite`.

## Шаг 3: устройство напрямую

Если приложения нет, устройство отдаёт данные по BLE:

- через вендорную утилиту;
- через отладочный интерфейс (если открыт);
- физическим снятием флеш (редко).

## Шаг 4: что искать

- **геолокация** (GPS-треки тренировок);
- **сон** (время, фазы);
- **пульс/активность** (коррелирует с событиями);
- **уведомления** (что приходило на часы).

Уведомления на часах дублируют сообщения телефона — полезно при расследовании.

## Шаг 5: ограничения

- данные на устройстве быстро перезаписываются;
- шифрование на некоторых моделях;
- облако производителя может быть недоступно.

## Что мы теперь знаем

- Данные — на устройстве и в приложении (приложение полнее).
- Приложения хранят SQLite с треками и здоровьем.
- Устройство отдаёт данные по BLE/утилите.
- Уведомления дублируют телефон.
- Есть ограничения по объёму и шифрованию.

## Если не сработало

- Нет приложения? Пробуй BLE-экспорт.
- Нужна история? Смотри облако аккаунта.
- Данные старые? Проверь бэкапы телефона.
