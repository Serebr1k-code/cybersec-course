## Вопрос, с которого всё начинается

У тебя образ Windows с десятками типов артефактов. Как собрать **единый** таймлайн,
где события из реестра, EVTX, MFT и браузера стоят рядом? Ответ — **plaso** (бывший
log2timeline). Разберём.

## Наш пример: образ Windows

## Шаг 1: что делает plaso

plaso собирает временные метки из **сотен** артефактов и приводит к общему формату:

- файловая система (MFT, USN);
- реестр (Shellbags, UserAssist);
- журналы событий (EVTX);
- браузеры, prefetch, LNK;
- метаданные файлов.

## Шаг 2: сбор

```
$ log2timeline.py --storage-file timeline.plaso /evidence/disk.E01
```

Он проходит по образу и извлекает события в хранилище `.plaso`. Это долгий этап.

## Шаг 3: фильтрация

Сырой таймлайн огромен. Фильтруем:

```
$ psort.py -o l2tcsv -w timeline.csv timeline.plaso "date > '2026-01-14 03:00:00' and date < '2026-01-14 04:00:00'"
```

Так получаем только окно инцидента — то, что реально нужно.

## Шаг 4: анализ

Результат открывают в **Timesketch** (веб) или разбирают CSV:

```
datetime,source,type,description
2026-01-14 03:28:11,WEBHIST,Safari,https://203.0.113.5/
```

События разных источников стоят рядом — видна причинно-следственная связь.

## Шаг 5: практика

- сначала **собери** всё;
- потом **фильтруй** по времени/источнику;
- ищи **аномалии** и цепочки;
- помни про **часовые пояса** и расхождения часов.

## Что мы теперь знаем

- plaso строит единый таймлайн из сотен артефактов.
- `log2timeline.py` собирает, `psort.py` фильтрует.
- Фильтр по времени/источнику — обязателен.
- Timesketch визуализирует.
- Часовые пояса надо учитывать.

## Если не сработало

- Сбор падает? Разбей образ на части.
- Таймлайн пуст? Проверь поддержку ФС.
- Нужна визуализация? Загрузи в Timesketch.

## Почему нужен именно супертаймлайн

На образе Windows временные метки разбросаны по десяткам источников: MFT
хранит времена файлов, реестр — время изменения ключей, EVTX — время
событий, браузер — время посещений. По отдельности каждый источник даёт
фрагмент. **Супертаймлайн** сводит их в одну ленту, отсортированную по
времени, и тогда видно причинно-следственную связь: сначала скачали файл,
потом запустили, потом появился процесс, потом — сетевое соединение.

## Из чего plaso собирает события

- **Файловая система** — MFT, USN journal (создание/изменение/удаление);
- **Реестр** — Shellbags, UserAssist, Run-ключи;
- **Журналы событий** — EVTX (вход, запуск сервисов, ошибки);
- **Артефакты выполнения** — Prefetch, LNK, Amcache;
- **Браузеры** — история, загрузки, кэш;
- **Метаданные** — EXIF, Office-документы.

Каждый парсер plaso знает формат своего артефакта и превращает его в
универсальное событие с полями `timestamp`, `source`, `type`, `description`.

## Разбор команды сбора

```
$ log2timeline.py --storage-file timeline.plaso /evidence/disk.E01
```

- `log2timeline.py` — сборщик;
- `--storage-file` — файл-хранилище (`.plaso`), куда пишутся события;
- `/evidence/disk.E01` — образ (E01 или raw).

Сбор долгий: он парсит весь образ. Для скорости можно ограничить
источники/фильтрами, но на первом проходе лучше собрать всё.

## Фильтрация и вывод: почему окно времени

Сырой таймлайн может содержать миллионы событий. Открывать его целиком
бессмысленно — нужен интервал инцидента:

```
$ psort.py -o l2tcsv -w window.csv timeline.plaso "date > '2026-01-14 03:00:00' and date < '2026-01-14 04:00:00'"
```

- `-o l2tcsv` — формат вывода (CSV, совместимый с log2timeline);
- `-w` — файл результата;
- фильтр в кавычках — выражение по полям.

Можно фильтровать и по источнику:

```
$ psort.py -o l2tcsv -w persist.csv timeline.plaso "source == 'REG' and parser == 'win:runkey'"
```

Так из «моря» остаётся только persistence — Run-ключи.

## Анализ результата

CSV открывают в таблице или грузят в **Timesketch** — веб-инструмент, где
события можно искать, строить графики и добавлять заметки. Пример строки:

```
datetime,source,type,description
2026-01-14 03:28:11,WEBHIST,Safari,https://203.0.113.5/payload.exe
2026-01-14 03:28:19,FILE,MFT,payload.exe created in \Users\bob\Downloads
2026-01-14 03:28:41,EVTX,Prefetch,payload.exe executed
```

Три события разных источников складываются в историю: скачал → создал →
запустил. Именно это и есть сила супертаймлайна.

## Работа с часовыми поясами

Главный источник ошибок — часовые пояса. plaso хранит время в UTC, а
артефакты могут быть в локальном времени. Если не учесть разницу, события
«разъедутся» на часы. Всегда выясняй таймзону системы и настраивай
конвертацию; сравнивай внутренние часы (например, `SystemTime` из реестра)
с реальными, чтобы выявить сдвиг.

## Практический чек-лист

1. Снять образ (с фиксацией хэша).
2. `log2timeline.py` — собрать в `.plaso`.
3. Определить окно инцидента по первым зацепкам.
4. `psort.py` с фильтром по времени/источнику.
5. Загрузить в Timesketch для визуализации.
6. Строить цепочки: скачивание → выполнение → сеть.
7. Учитывать часовые пояса и сдвиг часов.

## Оптимизация сбора

Полный сбор по образу может идти часами. Ускорить помогают:

- **ограничение парсеров** — `--parsers` оставляет только нужные;
- **фильтр по файлам** — `--file-filter`/`--extract` (например, только EVTX);
- **распараллеливание** — `--workers`;
- **предобработка** — заранее извлечь нужные артефакты и подать их.

Но на первом проходе лучше не срезать: пропущенный источник может оказаться
решающим. Оптимизируй, когда уже понимаешь, что ищешь.

## Имена парсеров: как фильтровать точно

Каждое событие помечено парсером. Примеры имён, полезных в фильтрах:

| Парсер | Что покрывает |
| --- | --- |
| `win:runkey` | ключи автозапуска Run |
| `win:userassist` | запуски программ |
| `win:prefetch` | выполнение приложений |
| `win:evtx` | журналы событий |
| `winevtx` | общий парсер EVTX |
| `chrome:history` | история браузера |

Фильтр по парсеру оставляет только нужный слой:

```
$ psort.py -o l2tcsv -w runkeys.csv timeline.plaso "parser == 'win:runkey'"
```

## Работа на примере: находим persistence

Задача — понять, как малварь закрепилась. Собираем Run-ключи и рядом —
созданные файлы:

```
$ psort.py -o l2tcsv -w p.csv timeline.plaso "parser == 'win:runkey' or parser == 'win:prefetch'"
```

В результате видим порядок: сначала создан файл в `\Users\bob\AppData\`,
потом появилась запись Run, потом Prefetch показал запуск. Цепочка
«persistence → выполнение» выстраивается по времени.

## Ограничения и типичные ошибки

- **Часовые пояса** — самая частая ошибка; без учёта TZ события «разъедутся».
- **Сдвиг часов** — если системные часы врали, метки смещены; выявляй по
  «внутренним» источникам.
- **Неполный сбор** — если образ снят «живьём» (не побайтово), часть
  артефактов потеряна.
- **Слишком узкий фильтр** — легко пропустить коррелирующее событие из
  другого источника.
- **Объём** — сырой `.plaso` может занимать десятки гигабайт; планируй место.

## Практический чек-лист

1. Снять побайтовый образ, зафиксировать хэш.
2. Собрать всё в `.plaso` (первый проход — без срезов).
3. Определить окно инцидента.
4. Фильтровать `psort.py` по времени и парсеру.
5. Строить цепочки из разных источников.
6. Загрузить в Timesketch для визуализации.
7. Учесть TZ и сдвиг часов.
