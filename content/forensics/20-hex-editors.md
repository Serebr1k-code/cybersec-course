Hex-редактор — рабочий инструмент форензика для ручного анализа и правки бинарных данных. Когда автоматика не справляется (нестандартный формат, повреждённый заголовок, хитро спрятанные байты), вы открываете файл и читаете байты напрямую. Этот урок — про `xxd`/`hexdump` в консоли, графические редакторы (`wxHexEditor`, `HxD`, `010 Editor`, `ImHex`), поиск/замену байтов и структурные шаблоны.

## Почему hex, а не текст

Файл — это байты, а текстовый просмотр искажает их (кодировки, непечатаемые символы). Hex-представление показывает каждый байт как два шестнадцатеричных знака плюс ASCII-колонку, где непечатаемые символы заменены точками. Это позволяет видеть сигнатуры, длины, смещения и структуру формата.

## xxd: hex в консоли

`xxd` — часть vim, есть почти везде.

| Флаг | Назначение |
|------|-----------|
| `-l N` | показать первые N байт |
| `-s OFFSET` | начать со смещения (`-s -N` — от конца) |
| `-c N` | N байт в строке (по умолчанию 16) |
| `-g N` | группировать по N байт |
| `-p` | plain hex без адресов/ASCII |
| `-r` | reverse: hex → бинарь |
| `-i` | вывод в виде C-массива |
| `-b` | бинарное представление (0/1) |
| `-u` | верхний регистр hex |

```bash
$ xxd -l 32 -g 1 image.png
00000000: 89 50 4e 47 0d 0a 1a 0a 00 00 00 0d 49 48 44 52  .PNG........IHDR
$ xxd -s -64 image.png              # последние 64 байта
$ xxd -p secret.bin | tr -d '\n'    # hex одной строкой
$ echo '48656c6c6f' | xxd -r -p     # -> Hello
```

## hexdump: гибкий формат

`hexdump` умеет произвольное форматирование через `-e`:

```bash
$ hexdump -C file.bin                 # канонический: offset | hex | ascii
$ hexdump -n 16 -e '"%08.8_ax  " 16/1 "%02x " "\n"' file.bin
$ hexdump -v -e '1/1 "%02x"' file.bin | head
```

`-C` (canonical) — самый читаемый; `-n` ограничивает длину; `-s` — смещение; `-v` — не сворачивать повторяющиеся строки.

## Графические редакторы

| Редактор | Платформа | Особенности |
|----------|-----------|-------------|
| `wxHexEditor` | Linux/Win/mac | открытый, работает с дисками, diff, поиск |
| `HxD` | Windows | быстрый, работа с RAM-дисками, checksum |
| `010 Editor` | Win/mac | **шаблоны структур** (парсинг форматов) |
| `ImHex` | кроссплатформенный | паттерн-язык, дизассемблер, плагины |
| `bvi`/`biew` | консоль | vi-подобный для бинарников |
| `GHex`/`Bless` | Linux | простые GUI |

`010 Editor` и `ImHex` сильны **шаблонами**: вы описываете структуру формата (PNG-чанки, PE-заголовки, записи MFT), и редактор подсвечивает поля, интерпретирует значения и позволяет переходить по структуре — это ускоряет разбор в разы.

```bash
# открыть образ диска в wxHexEditor (только чтение!)
$ wxHexEditor disk.img
# bvi: правка с vi-навигацией
$ bvi file.bin
```

## Поиск и замена байтов

```bash
# поиск сигнатуры с адресом
$ grep -aboP '\x89PNG' file.bin
# поиск hex через xxd + grep
$ xxd -p file.bin | tr -d '\n' | grep -bo '504b0304'
# замена байтов: xxd -r из подготовленного hex
$ xxd -p file.bin | sed 's/89504e470d0a1a0a/89504e470d0a1a0a/' | xxd -r -p > fixed.bin
# безопаснее: записать нужные байты через dd по смещению
$ printf '\x89PNG\r\n\x1a\n' | dd of=file.bin bs=1 seek=0 count=8 conv=notrunc
```

В GUI (`wxHexEditor`, `HxD`) поиск/замена делаются диалогом, но при работе с уликами правьте **копию** и фиксируйте исходный хеш.

## Структурные шаблоны (010/ImHex)

Шаблон описывает поля по смещениям. Пример псевдо-шаблона PNG:

```
struct PNG {
    uint64 signature;          // 89 50 4E 47 0D 0A 1A 0A
    while (pos < fileSize) {
        uint32 length;
        char   type[4];
        byte   data[length];
        uint32 crc;
    }
}
```

`ImHex` использует собственный pattern-язык, `010 Editor` — C-подобный. Оба позволяют найти аномалию (например, чанк с неверной длиной или лишний чанк после `IEND`).

## Работа с большими файлами

Гигабайтные образы в GUI тормозят. Приёмы:
- открывайте только нужный диапазон (`-s`/`-l` в xxd, «Go to offset» в GUI);
- вырезайте фрагмент `dd` и работайте с ним;
- используйте `hexdump -C -n` для быстрого просмотра;
- для поиска по всему образу — `grep -aboP` (потоково), а не GUI.

## Разобранный пример

Дан `broken.png`, который не открывается.

```bash
$ xxd -l 16 broken.png
00000000: 89 50 4e 47 0a 0d 1a 0a 00 00 00 0d 49 48 44 52  .PNG........IHDR
```

Сигнатура должна быть `89 50 4E 47 0D 0A 1A 0A`, а тут `0A 0D` вместо `0D 0A` — байты переставлены. Починим:

```bash
$ cp broken.png fixed.png
$ printf '\x89PNG\r\n\x1a\n' | dd of=fixed.png bs=1 count=8 conv=notrunc
$ file fixed.png
fixed.png: PNG image data, 800 x 600, 8-bit/color RGBA
```

Затем проверим, нет ли лишних данных после `IEND`:

```bash
$ grep -aboP 'IEND' fixed.png
$ xxd -s <offset_after_IEND> fixed.png | head
```

## Частые ошибки

- **Править оригинал улики** — только копия, и фиксируйте хеш до/после.
- **Путать hex и десятичное смещение** при `dd seek`/`skip`.
- **Считать ASCII-колонку истиной** — она лишь отображение; байты важнее.
- **Игнорировать порядок байтов (endianness)** — длина/CRC читаются по-разному.
- **Открывать большой образ в GUI целиком** — тормоза и риск случайной записи.
- **Забывать `conv=notrunc`** — `dd` обрежет файл до записанного фрагмента.

## Что дальше / решение

Для быстрого просмотра — `xxd -l`/`hexdump -C`; для структурного разбора — `010 Editor`/`ImHex` с шаблоном; для правки — `dd conv=notrunc` или GUI по копии. Связка: `forensics-file-magic` (сигнатуры), `forensics-carving` (извлечение), `forensics-ntfs-mft` (разбор записей), `forensics-partition-tables` (структуры MBR/GPT).

## Побитовый анализ и битовые операции

Иногда данные спрятаны в отдельных битах, и нужен уровень ниже байта. `xxd -b` показывает биты, а Python/`perl` позволяют вытаскивать LSB/MSB целых потоков.

```bash
# битовое представление первых байт
$ xxd -b -l 8 image.png
00000000: 10001001 01010000 01001110 01000111 ...
# извлечь младший бит каждого байта (LSB-стего) на Python
$ python3 - <<'PY'
data = open('image.png','rb').read()
bits = ''.join(str(b & 1) for b in data)
print(''.join(chr(int(bits[i:i+8],2)) for i in range(0,len(bits)//8*8,8))[:80])
PY
```

Так же читают MSB, биты конкретного канала (RGB), чередование каналов. Для PNG удобнее `zsteg`, но понимание битового уровня помогает при нестандартных схемах.

## Кодировки, XOR и восстановление

Побайтовый XOR — простейшее «шифрование», часто встречающееся в CTF и малвари. Ключ может быть один байт или повторяющаяся строка.

```bash
# XOR одним байтом через xxd -r (пример: ключ 0x42)
$ python3 -c "import sys;d=open('enc.bin','rb').read();sys.stdout.buffer.write(bytes(b^0x42 for b in d))" > dec.bin
# поиск одно-байтового ключа: перебрать 256 значений и искать 'CTF{'
$ for k in $(seq 0 255); do python3 -c "
import sys;d=open('enc.bin','rb').read();print(bytes(b^$k for b in d))" 2>/dev/null | grep -q 'CTF{' && echo "key=$k"; done
# base64/hex слои
$ base64 -d file.txt | xxd -r -p | strings
```

При работе с кодировками помните порядок слоёв: hex → base64 → XOR → gzip — типичная «матрёшка». `cyberchef` (GUI/CLI) автоматизирует такие цепочки.

## Контроль целостности при правке

После любой правки проверяйте, что изменились именно нужные байты:

```bash
$ cmp -l original.bin fixed.bin        # список отличающихся байт (1-based offset)
$ sha256sum original.bin fixed.bin
$ xxd -s <offset> -l 16 fixed.bin      # подтвердить изменение
```

`cmp -l` показывает каждое отличие с позицией — это и доказательство правки, и способ убедиться, что не задет лишний байт.

## Где пригодится

- **CTF:** правка magic-байтов, XOR-декод, поиск appended data.
- **Malware analysis:** разбор заголовков PE/ELF вручную, патчинг анти-анализа.
- **Восстановление данных:** исправление повреждённых структур.
- **Reverse engineering:** понимание форматов, ручное патчирование.
- **Incident Response:** извлечение фрагментов из больших дампов по offset.
