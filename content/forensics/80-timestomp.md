Timestomping — изменение временных меток файла, чтобы скрыть его реальное время создания/изменения. Атакующий «омолаживает» вредонос, подгоняя его под системные файлы. Обнаружить подделку можно, сравнив независимые наборы меток. Этот урок — про механизмы, признаки и инструменты детекта.

## Как хранятся метки в NTFS

В NTFS у каждого файла **два набора** временных меток:

- **`$STANDARD_INFORMATION` ($SI)** — в MFT-записи; обновляется при обычных операциях (запись, доступ). Именно его меняют утилиты timestomp.
- **`$FILE_NAME` ($FN)** — в записи имени (в каталоге); обновляется только при создании/переименовании.

Если `$SI` не совпадает с `$FN` — это **сильный признак** подделки: злоумышленник изменил `$SI`, но `$FN` остался с реальным временем.

```bash
# MFTECmd выводит оба набора
$ MFTECmd.exe -f '$MFT' --csv out --csvf mft.csv
# найти расхождения (SI created != FN created)
$ awk -F, '$10!=$14 {print $1, $10, $14}' out/mft.csv | head
```

## Другие независимые источники

- **USN-журнал** (`$UsnJrnl:$J`) — фиксирует реальное время создания/переименования/удаления.
- **EVTX** — Sysmon Event ID 2 (изменение времени файла!), Security 4688.
- **Файловая система** — некоторые ФС (ext4) хранят crtime отдельно.
- **Резервные копии/теневые копии** — старое время создания.
- **Prefetch/Amcache** — время первого запуска.

```bash
# Sysmon 2: изменение времени файла
$ evtx_dump -o json Sysmon.evtx | jq 'select(.Event.System.EventID==2) | .Event.EventData'
# USN: реальное создание
$ MFTECmd.exe -f '$J' --csv out --csvf usn.csv
```

## Признаки timestomping

| Признак | Как увидеть |
|---------|-------------|
| `$SI` ≠ `$FN` | MFTECmd/analyzeMFT |
| Время «из будущего» | сравнить с текущим |
| Время раньше установки ОС | сравнить с датой системы |
| Файл создан раньше, чем изменён | таймлайн |
| Sysmon 2 | EVTX |
| Резкое совпадение с системным файлом | MFT |

```bash
# файлы с одинаковым временем (подозрительно)
$ awk -F, '{print $10}' out/mft.csv | sort | uniq -c | sort -rn | head
# файлы «из будущего»
$ awk -F, '$10 > "2026-01-01" {print}' out/mft.csv | head
```

## Разобранный пример

Подозрение: вредонос с поддельным временем.

```bash
# 1. MFT: SI vs FN
$ MFTECmd.exe -f '$MFT' --csv out --csvf mft.csv
$ awk -F, '$1 ~ /evil.exe/ {print "SI:", $10, "FN:", $14}' out/mft.csv
SI: 2019-01-01 00:00:00  FN: 2024-03-01 12:00:00
# расхождение -> подделка
# 2. USN: реальное время
$ MFTECmd.exe -f '$J' --csv out --csvf usn.csv
$ grep -i evil out/usn.csv
evil.exe, created 2024-03-01 12:00:00
# 3. Sysmon 2
$ evtx_dump -o json Sysmon.evtx | jq 'select(.Event.System.EventID==2) | .Event.EventData'
{ "Image": "...\\evil.exe", "CreationUtcTime": "2019-01-01..." }
# 4. Таймлайн: файл «из прошлого» среди свежих
```

Итог: `$SI` подделан под 2019, но `$FN` и USN показывают реальное 2024-03-01 — timestomping подтверждён.

## Справочная таблица

| Набор | Обновляется | Подделывается |
|-------|-------------|---------------|
| `$SI` | при операциях | да (timestomp) |
| `$FN` | создание/переименование | редко |
| USN | реальные изменения | трудно |
| EVTX Sysmon 2 | при изменении времени | фиксирует факт |

## Частые ошибки

- **Верить только `$SI`** — подделывается в первую очередь.
- **Игнорировать `$FN`** — главный индикатор.
- **Не смотреть USN** — там реальное время.
- **Забывать про Sysmon 2** — прямое событие.
- **Считать любое расхождение подделкой** — копирование/перенос тоже меняет метки.
- **Не учитывать часовой пояс** — сравнение «из будущего» может быть ложным.

## Что дальше / решение

Конвейер: `MFTECmd` (SI/FN) → `$UsnJrnl` (реальное время) → Sysmon 2 (EVTX) → таймлайн. Связка: `forensics-anti-forensics` (приёмы), `forensics-ntfs-mft` (MFT), `forensics-usn` (USN), `forensics-timeline` (хронология).

## Linux и другие ФС

В Linux timestomping тоже возможен (`touch -t`, `touch -d`, изменение `atime` через `utimensat`). Признаки:

- **`crtime` vs `mtime`** — ext4 хранит `crtime` (birth), который `touch` не меняет. Если `crtime` позже `mtime` — подозрительно.
- **inode-журнал** (`jbd2`) — реальное время операций.
- **`debugfs stat`** — покажет `crtime`/`ctime`.

```bash
# сравнить crtime и mtime (ext4)
$ stat file.txt
$ debugfs -R 'stat /path/file' /dev/sda1 | grep -iE 'crtime|ctime|mtime'
# поиск файлов «из прошлого»
$ find / -newermt '2024-03-01' ! -newermt '2024-03-02' 2>/dev/null | head
```

Для FAT/macOS: FAT не хранит `crtime` надёжно; APFS/HFS+ имеют свои метки. Везде ищите расхождение независимых наборов.

## Сводный чек-лист

1. Разобрать MFT (`MFTECmd`), вывести SI и FN.
2. Найти расхождения SI/FN.
3. Проверить USN на реальное время.
4. Проверить Sysmon 2 (изменение времени).
5. Сравнить с текущим временем («из будущего») и датой установки ОС.
6. Для Linux — `crtime` vs `mtime`.
7. Свести таймлайн, искать несоответствия.

## Ограничения

- **Копирование/перенос** меняет метки (не всегда подделка).
- **FAT** — только локальное время, 2-сек точность.
- **Резервные копии** могут «сбросить» метки.
- **USN** может быть выключен/перезаписан.
- **Sysmon 2** требует включённого Sysmon.

## Сравнение с сетевыми и облачными метками

Временные метки есть и вне файловой системы: сетевые логи (PCAP timestamps), облачные аудиты (CloudTrail `eventTime`), журналы приложений. Если файл «создан» 2019, но в PCAP/CloudTrail он появился 2024 — это противоречие. Межсетевая корреляция обличает подделку, которую не видно внутри одного источника.

```bash
# время из PCAP
$ tshark -r capture.pcap -Y 'http.request.uri contains "evil.exe"' -T fields -e frame.time | head
# сравнить с SI файла (mft.csv)
$ grep -i evil out/mft.csv
```

## Практические приёмы

- **Всегда выводите SI и FN вместе** — иначе не увидите подделку.
- **Проверяйте USN** — реальное время создания.
- **Сравнивайте с «сейчас»** — метки «из будущего» подозрительны.
- **Ищите группы** файлов с одинаковым временем.
- **Коррелируйте с сетью/облаком**.
- **Не делайте поспешных выводов** — копирование тоже меняет метки.
