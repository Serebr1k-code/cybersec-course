Когда PCAP нет или он слишком велик, на помощь приходят **потоковые данные** — NetFlow, IPFIX, sFlow. Это не содержимое пакетов, а агрегированные записи: кто, кому, по какому протоколу, сколько пакетов и байт, когда начал и закончил. Такой уровень абстракции позволяет быстро найти аномалии: всплеск трафика, соединение к нетипичному порту, beaconing.

## Структура flow-записи

Классический NetFlow v5/v9 и IPFIX описывают «поток» (flow) — набор пакетов с общими полями. Типовые поля:

| Поле | Значение |
|------|----------|
| srcaddr / dstaddr | IP-адреса |
| srcport / dstport | порты |
| protocol | TCP/UDP/ICMP |
| packets / bytes | объёмы |
| first / last | время начала/конца |
| tcp_flags | OR флагов за поток |
| input / output | интерфейсы |

IPFIX (NetFlow v10) — расширяемый стандарт: шаблоны (templates) описывают набор полей, поэтому парсер должен сначала получить шаблон. sFlow — семплированные потоки с интерфейсов.

## Инструменты

```bash
# nfdump: работа с nfcapd-файлами
nfdump -r nfcapd.202403010000 -o extended | head
# Топ по байтам
nfdump -r nfcapd.* -s srcip/bytes -n 10
nfdump -r nfcapd.* -s dstip/bytes -n 10
# Фильтры
nfdump -r nfcapd.* 'src ip 10.0.0.5 and dst port 443'
# Список соединений (flows)
nfdump -r nfcapd.* -o fmt:'%ts %sa %sp -> %da %dp %pkt %byt'

# SiLK: большой набор утилит
rwfilter --start-date=2024/03/01 --proto=6 --pass=stdout flows.rw | rwstats --top --count=10
rwfilter flows.rw --saddress=10.0.0.5 --pass=out.rw
```

## Чтение из PCAP

Если есть только PCAP, потоковые записи можно построить:

```bash
# Сводка разговоров (conversations) через tshark
tshark -r capture.pcap -q -z conv,ip
tshark -r capture.pcap -q -z conv,tcp
# Экспорт в формат, пригодный для агрегации
tshark -r capture.pcap -T fields -e ip.src -e ip.dst -e tcp.dstport -e frame.len
# Или через joy/flow-tools
joy -f capture.pcap -o out.json
```

`-z conv,ip` даёт таблицу «Address A ↔ Address B, packets, bytes, duration» — быстрый способ увидеть, кто с кем и сколько.

## Обнаружение аномалий

Что искать:

- **Beaconing.** Регулярные соединения к одному адресу с постоянным интервалом и малым объёмом — признак C2.
- **Эксфильтрация.** Один хост, много исходящих байт на нетипичный адрес/порт.
- **Сканирование.** Много коротких потоков к разным портам одного адреса.
- **Туннели.** Аномально большой объём по DNS/ICMP (covert channel).
- **Нетипичные порты.** HTTPS на 8080/8443, DNS на нестандартном порту.

```bash
# Топ отправителей по байтам
nfdump -r nfcapd.* -s srcip/bytes -n 20
# Соединения на нестандартные порты
nfdump -r nfcapd.* 'proto tcp and not port 80 and not port 443 and not port 22'
# Периодичность (beaconing) — считаем потоки по минутам к адресу
nfdump -r nfcapd.* 'dst ip 203.0.113.9' -o fmt:'%ts' | cut -c1-16 | uniq -c
```

## Разобранный пример

```bash
$ nfdump -r nfcapd.* -s srcip/bytes -n 5
Date first seen   Duration Proto Src IP Addr        Flows  Packets   Bytes
2024-03-01 22:00  0:05:12  TCP  10.0.0.5            1420  1048576  524288000
$ nfdump -r nfcapd.* 'src ip 10.0.0.5 and dst port 8443' -o fmt:'%ts %da %byt'
2024-03-01 22:01:03  203.0.113.9  380928
2024-03-01 22:02:11  203.0.113.9  512000
...
```

Вывод: хост `10.0.0.5` передал ~500 МБ на `203.0.113.9:8443` мелкими порциями — типичная картина эксфильтрации на нестандартный порт. Дальше — искать соответствующий PCAP или файловые артефакты.

## Краевые случаи и подводные камни

- **Семплирование.** sFlow и некоторые IPFIX-экспортёры семплируют (1 из N), поэтому байты/пакеты — оценочные, а не точные.
- **Таймауты.** Экспортёр закрывает flow по таймауту (активному/неактивному); длинный поток дробится на несколько записей.
- **Направление.** NetFlow может быть unidirectional или bidirectional; суммируйте аккуратно.
- **Время.** Экспортёр может использовать своё время/часовой пояс; сверяйте с другими источниками.
- **Шаблоны IPFIX.** Без template запись не разобрать — нужен полный поток экспорта с начала.
- **Отсутствие payload.** NetFlow не покажет содержимое; для деталей нужен PCAP.
- **Порты не равны приложениям.** HTTPS на 8443 — легитимно в некоторых системах; не делайте вывод по одному порту.
- **NAT.** Внутренние адреса могут быть замаскированы; коррелируйте с логами NAT.

## Инструменты экосистемы

Потоковые данные обрабатывают несколько семейств инструментов:

- **nfcapd/nfdump** — приём и анализ NetFlow (наиболее распространённый).
- **SiLK** (CERT/CMU) — мощный набор для больших объёмов: `rwfilter`, `rwstats`, `rwcut`.
- **flow-tools** (`flow-cat`, `flow-print`) — старый формат NetFlow v5.
- **Joy** — извлечение flow + метаданных из PCAP в JSON (удобно для ML).
- **Argus** — аудит потоков с расширенными полями.

```bash
# SiLK: топ отправителей по байтам
rwfilter --proto=6 --start-date=2024/03/01 flows.rw --pass=stdout \
  | rwstats --fields=sip --values=bytes --top --count=10
# Отфильтровать конкретный хост и вывести записи
rwfilter flows.rw --saddress=10.0.0.5 --pass=out.rw
rwcut out.rw --fields=sip,dip,sport,dport,bytes --num-rec=20
# Joy: PCAP -> JSON flow
joy bidir=1 output=out.json capture.pcap
```

## Построение базовой линии

Аномалию легче заметить на фоне нормы. Соберите базовые показатели: типичные порты, объёмы, распределение по времени, список «обычных» внешних адресов. Затем ищите отклонения.

Практические эвристики:

- **Объём в час > X** для хоста, который обычно передаёт мало.
- **Ночная активность** (в нерабочие часы) — подозрительно.
- **Соединения к новым ASN/странам**, которых не было в базовой линии.
- **Постоянный размер пакета** — туннель/beacon.
- **Обратный DNS-трафик** большого объёма — туннелирование.

```bash
# Активность по часам
nfdump -r nfcapd.* -o csv | awk -F, '{print substr($1,12,2)}' | sort | uniq -c
# Новые внешние адреса за период
nfdump -r nfcapd.* -o fmt:'%da' | sort -u > today.txt
comm -13 baseline.txt today.txt | head
```

## Туннелирование и covert channels

Flow-данные хорошо ловят туннели по аномалиям:

- **DNS-туннель** — множество длинных поддоменов к одному серверу, большой объём UDP/53.
- **ICMP-туннель** — необычно большие ICMP-payload и регулярность.
- **HTTP-туннель** — длинные потоки к нетипичным портам с постоянным размером.

```bash
# Длинные DNS-имена (признак туннеля) — по PCAP
tshark -r capture.pcap -Y 'dns.flags.response==0' -T fields -e dns.qry.name | awk '{print length, $0}' | sort -rn | head
# В flow: много DNS-потоков к одному адресу
nfdump -r nfcapd.* 'proto udp and port 53' -s dstip/flows -n 10
```

## Хранение и производительность

NetFlow-данные могут быть очень объёмными. Практики:

- **Сжатие** nfcapd-файлов (`nfcapd -z` пишет сжатые).
- **Ротация** по расписанию (nfcapd ротирует каждые 5 минут по умолчанию).
- **Индексация** в базу (ClickHouse, Elasticsearch) для быстрых запросов.
- **Семплирование** на экспортёре для высоких скоростей (с потерей точности).

```bash
# Список nfcapd-файлов
ls -lh /var/flows/*/nfcapd.*
# Прочитать диапазон
nfdump -R /var/flows/2024/03/01 -r nfcapd.*
```

## Чек-лист анализа потоков

1. Определить источник (nfcapd, IPFIX, PCAP).
2. Построить топы по src/dst IP, портам, протоколам.
3. Сравнить с базовой линией.
4. Отфильтровать подозрительные потоки (объём, порт, время).
5. Для каждого — найти PCAP/логи и подтвердить гипотезу.
6. Задокументировать выводы с временными метками.

Потоковый анализ — это «карта» сети; детали вы затем добираете пакетным анализом.

## Корреляция с другими источниками

Потоковые данные почти никогда не используются в одиночку. Связки:

- **Flow + DNS-логи** — сопоставить домены с IP-потоками (какой хост «звонил» на какой домен).
- **Flow + Suricata** — алерт по 5-tuple → найти полный поток.
- **Flow + аутентификация** — связать вход пользователя со всплеском трафика.
- **Flow + DHCP** — сопоставить IP с MAC/хостом на момент инцидента.

```bash
# Кто был за IP 10.0.0.5 в момент инцидента (по DHCP-логам)
grep "10.0.0.5" dhcpd.log | tail
# Сопоставить с DNS
grep "203.0.113.9" dns.log | head
```

Так из абстрактных «500 МБ на адрес» вы получаете конкретного пользователя, домен и процесс.

## Мини-шпаргалка по nfdump

| Цель | Команда |
|------|---------|
| Топ источников по байтам | `nfdump -r nfcapd.* -s srcip/bytes -n 10` |
| Топ получателей | `nfdump -r nfcapd.* -s dstip/bytes -n 10` |
| Фильтр по хосту | `nfdump -r nfcapd.* 'src ip 10.0.0.5'` |
| Нетипичные порты | `nfdump -r nfcapd.* 'not port 80 and not port 443'` |
| Свои форматы | `nfdump -r nfcapd.* -o fmt:'%ts %sa -> %da %byt'` |
| По протоколу | `nfdump -r nfcapd.* 'proto tcp'` |

Этих команд достаточно для 90% задач по потоковым данным: сначала топы, затем фильтры, затем детальный PCAP.

## Что дальше / решение

1. Определить источник: nfcapd-файлы, IPFIX-экспорт или PCAP.
2. Построить топы (`nfdump -s`, `rwstats`).
3. Отфильтровать аномалии (порты, объёмы, периодичность).
4. Для подозрительных потоков найти PCAP/логи и разобрать глубже.
5. Сопоставить с Suricata/Zeek-событиями.

Дальше — `forensics-tshark-deep` (глубокий пакетный разбор) и `forensics-zeek` (протокольные логи).
