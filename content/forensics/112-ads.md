## Вопрос, с которого всё начинается

Вам дали образ NTFS-диска. Внутри — обычные файлы: документы, картинки, ничего примечательного. Но подозрение есть: на таких дисках злоумышленники прячут данные так, что в обычном проводнике их **вообще не видно**. Как найти то, чего «нет»?

## Наш пример: образ с «лишним» потоком

Смотрим список файлов утилитой `fls` из The Sleuth Kit — она показывает содержимое ФС по записям (inode). Обратите внимание на флаг `-r` (рекурсивно):

```bash
$ fls -r -o 2048 disk.img | grep ':'
r/r 64-128-1: notes.txt
r/r 64-128-3: notes.txt:hidden.txt
r/r 70-128-2: photo.jpg:Zone.Identifier
```

Странно: `notes.txt` есть, но рядом появилась запись `notes.txt:hidden.txt` — как будто у одного файла два имени. Двоеточие здесь не опечатка, а разделитель. Мы наткнулись на **Alternate Data Stream** (ADS, альтернативный поток данных).

## Шаг 1: что такое ADS

В NTFS любой файл — это набор **атрибутов** в записи MFT (Master File Table). Обычные данные лежат в атрибуте `$DATA`. У стандартного файла есть один такой атрибут — **без имени**. ADS — это ещё один атрибут `$DATA`, но **с именем**. Отсюда запись `file:stream`.

Что из этого следует:

- У одного файла может быть много потоков, каждый — со своим размером и содержимым.
- В обычном `dir` ADS не виден. В проводнике Windows 7+ размер ADS может «прилипнуть» к размеру папки, но сам поток не отображается.
- Поток бывает **resident** (мелкий, лежит прямо в MFT) или non-resident (в кластерах).
- ADS существует **только на NTFS**. При копировании на FAT/exFAT он теряется или вызывает ошибку.

## Шаг 2: достаём спрятанное

Запись в `fls` имеет формат `inode-type-id`. Чтобы прочитать **конкретный поток**, а не основной файл, нужно указать полный inode — `64-128-3` (а не `64-128-1`):

```bash
$ icat -o 2048 disk.img 64-128-3 > hidden.bin
$ file hidden.bin
hidden.bin: PE32 executable (GUI) Intel 80386
```

Поток `hidden.txt` оказался **исполняемым файлом PE** — то есть в безобидном `notes.txt` спрятана программа. Это классический приём малвари: payload живёт в потоке, а «носитель» выглядит безобидно.

Второй поток, `photo.jpg:Zone.Identifier`, читается так же:

```bash
$ icat -o 2048 disk.img 70-128-2
[ZoneTransfer]
ZoneId=3
ReferrerUrl=https://evil.example/payload
```

## Шаг 3: Mark-of-the-Web — тоже ADS

Поток `Zone.Identifier` — это не малварь, а **Mark-of-the-Web** (MOTW): метка, которую Windows ставит на файл, скачанный из интернета. Содержимое:

```
[ZoneTransfer]
ZoneId=3
ReferrerUrl=https://evil.example/payload.exe
```

`ZoneId=3` — интернет, `2` — доверенная зона, `4` — restricted. Наличие MOTW — сильный признак скачивания из сети. Удаление этого потока (`Remove-Item -Stream Zone.Identifier`) — распространённый шаг обхода SmartScreen; поэтому отсутствие MOTW у файла, который «якобы скачали», само по себе подозрительно.

## Шаг 4: как искать ADS в масштабе

На большом образе нельзя открывать файлы по одному. Ищем все потоки сразу и фильтруем подозрительные — с исполняемыми расширениями внутри:

```bash
$ fls -r -o 2048 disk.img | grep ':' > streams.txt
$ wc -l streams.txt
$ grep -Ei ':(.*\.(exe|dll|ps1|bat|vbs|scr))' streams.txt
r/r 64-128-3: notes.txt:hidden.txt
```

Затем каждый поток извлекаем по inode и прогоняем `file`/`strings`/YARA. `istat` подскажет, сколько потоков у файла:

```bash
$ istat -o 2048 disk.img 64
Attribute: Name: N/A   Type: Data   Size: 128
Attribute: Name: hidden.txt Type: Data Size: 14336
```

Две строки `Type: Data` — два потока. Это самый быстрый способ убедиться в наличии скрытых данных.

## Шаг 5: зачем это злоумышленнику

ADS активно применяется в атаках:

- **Хранение payload** — EXE/DLL в потоке безобидного файла.
- **Персистентность** — служба с `ImagePath`, указывающим на `file.txt:evil.exe`.
- **Сокрытие конфигов** — C2-конфиг в ADS.
- **Обход простых сканеров** — некоторые антивирусы исторически не проверяли ADS.

Поэтому при поиске персистентности проверяют `HKLM\SYSTEM\CurrentControlSet\Services\*\ImagePath` и задачи планировщика на наличие `:` в пути.

На Windows ADS создаётся тривиально:

```powershell
echo "hidden payload" > secret.txt:hidden.txt
type payload.exe > benign.txt:evil.exe
Get-Item -Path secret.txt -Stream *      # список потоков
dir /r                                    # в cmd: показать потоки
```

## Что мы теперь знаем

- **ADS** — дополнительный именованный атрибут `$DATA` у того же файла в NTFS.
- В `fls` потоки видны как записи с `:` в имени; читать их надо по **inode потока** (`<ino>-<type>-<id>`), а не по основному.
- `istat` показывает все потоки файла — быстрый способ их найти.
- ADS теряется при копировании на FAT/exFAT и при архивации в ZIP/TAR.
- **Zone.Identifier** — тоже ADS; хранит Mark-of-the-Web (происхождение файла).
- Мелкие потоки (resident) лежат в MFT и не находятся carving'ом по сигнатурам.

## Куда дальше

Мы научились находить и извлекать скрытые потоки NTFS. В следующем уроке мы вернёмся к сетевым артефактам и разберём **Suricata** — сигнатурный анализ PCAP. А пока главное запомни: **ADS — это дополнительный `$DATA` с именем; его видно по `:` в `fls`, читают по inode потока, и он теряется вне NTFS**.

## Где пригодится

- **CTF:** задачи с сокрытием данных в NTFS.
- **IR:** поиск замаскированной малвари и признаков запуска из потоков.
- **Malware Analysis:** анализ персистентности через ADS.
- **Судебная экспертиза:** доказательство сокрытия данных.
