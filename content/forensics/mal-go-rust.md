## Вопрос, с которого всё начинается

Современная малварь всё чаще пишется на **Go** и **Rust**. Такие образцы — большие,
статические, со своим рантаймом. Обычные приёмы анализа дают много шума. Разберём
особенности.

## Наш пример: Go-образец

## Шаг 1: как распознать

```
$ file sample.bin
sample.bin: ELF 64-bit LSB executable, statically linked, not stripped
$ ls -la sample.bin
-rwxr-xr-x 1 root root 8.2M sample.bin
```

Размер в мегабайты + `not stripped` + `static` — почти наверняка Go. Строки содержат
пути рантайма:

```
$ strings sample.bin | grep -m3 'go1\.'
go1.21.5
```

`go1.x` — версия компилятора. Для Rust — ищи `rustc` и `core::`.

## Шаг 2: символы Go

Go-бинарники часто **не stripped**, и это подарок:

```
$ go tool nm sample.bin 2>/dev/null | grep -i 'main\.' | head
```

Имена функций `main.main`, `main.beacon` дают структуру. `GoReSym` восстанавливает
символы, если их почистили.

## Шаг 3: строки и конфиг

```
$ strings sample.bin | grep -iE 'http|10\.10' | head
https://203.0.113.5/api
```

В Go-малвари строки лежат плотно; часто весь C2-конфиг виден в `strings`.

## Шаг 4: крипто-библиотеки

Go несёт в себе `crypto/tls`, `crypto/aes` — их символы указывают на шифрование:

```
$ go tool nm sample.bin 2>/dev/null | grep -i 'crypto/tls' | head
```

Rust использует `ring`, `openssl`; ищи соответствующие символы.

## Шаг 5: анализ

- **`strings` + `grep`** — быстрый старт;
- **`GoReSym`/`redress`** — восстановление типов и символов;
- **YARA** — правила под Go/Rust;
- **Динамика** — рантайм создаёт много потоков (goroutines).

## Что мы теперь знаем

- Go/Rust-образцы — большие статические бинарники.
- Go выдаёт `go1.x` в строках, Rust — `rustc`.
- Go часто не stripped — символы дают структуру.
- Конфиг C2 виден в `strings`.
- Рантайм-библиотеки (crypto/tls) дают зацепки.

## Если не сработало

- Символы удалены? Используй GoReSym.
- Обфускация (garble)? Часть имён восстановима по строкам.
- Нужна логика? Динамический анализ в песочнице.

## Почему Go и Rust-бинарники «толстые» и самодостаточные

Go и Rust компилируются в **статически слинкованные** бинарники: среда исполнения, сборщик
мусора (у Go), стандартная библиотека и часто сторонние пакеты — всё внутри одного файла.
Размер в несколько мегабайт для простой утилиты — норма. Практические следствия:

- **нет импортов к системным DLL**, кроме базовых (`kernel32`, `ntdll`) — обычный анализ
  импортов бесполезен;
- **много строк** — вкомпилированы пути, сообщения, имена пакетов;
- **отладочная информация** часто остаётся, если не собрано с `-ldflags "-s -w"`.

```
$ file agent.exe
agent.exe: PE32+ executable (console) x86-64, for MS Windows
$ ls -lh agent.exe
-rw-r--r-- 1 user user 6.2M agent.exe
```

6 МБ «пустой» утилиты — первый намёк на Go.

## Опознаём Go по сигнатурам

Go оставляет узнаваемые строки и структуры. Ищем магические маркеры:

```
$ strings -n 8 agent.exe | grep -iE 'go1\.|golang|runtime\.|Go build' | head
Go build ID: "aBcDeF..."
go1.21.5
runtime.main
runtime.goexit
```

Секции и символы тоже характерны: `runtime.`, `gopclntab`, `go.buildid`. В Ghidra/IDA
есть плагины (`GolangAnalyzer`, `GoReSym`) для восстановления имён функций Go.

## Rust: признаки и особенности

Rust-бинарники узнаются по строкам из стандартной библиотеки и характерным паникам:

```
$ strings -n 8 agent.exe | grep -iE 'rust|core::|std::|panicked at' | head
panicked at 'called `Result::unwrap()` on an `Err` value'
core::fmt::Formatter
/rustc/1.75.0/library/std/src/...
```

Строка `/rustc/<версия>/` раскрывает **точную версию компилятора** — полезно для атрибуции
и поиска известных уязвимостей в зависимостях. Rust часто использует crates (`tokio`,
`reqwest`, `serde`), чьи имена видны в строках.

## Извлечение конфигурации

Конфиг малвари обычно вкомпилирован как строки или в отдельном шифрованном блобе. Начинаем
со строк и ищем URL, IP, ключи:

```
$ strings -n 6 agent.exe | grep -oE 'https?://[^ "]+' | sort -u
https://api.telegram.org/bot123456:AA.../sendMessage
http://185.220.101.5:8443/gate
```

Строка Telegram Bot API с токеном — очень частый C2 у Go-малвари (простота реализации).
Если строки зашифрованы, ищи инициализирующую функцию, которая их расшифровывает (часто
срабатывает на `init()` до `main`).

## Таблица: Go vs Rust для аналитика

| Признак | Go | Rust |
|---|---|---|
| Размер | большой (2-10 МБ) | средний-большой |
| Символы | `runtime.`, `gopclntab` | `/rustc/`, `core::` |
| Паники | `panic: ...` | `panicked at ...` |
| Строки версии | `go1.x` | `/rustc/1.x/library/` |
| Точка входа | `main.main`, `init` | `main` (mangled) |
| Крипто | `crypto/aes` в строках | crates `aes`, `ring` |
| GC/потоки | много горутин | async-рантайм (`tokio`) |

## Анализ в дизассемблере

В IDA/Ghidra загружаем бинарник и применяем плагин для Go/Rust: он восстанавливает имена
функций по таблице символов, после чего граф вызовов становится читаемым. Для Rust манглинг
имён снимают утилитой `rustfilt`:

```
$ rustfilt _ZN4core3fmt9Formatter3pad17h...E
core::fmt::Formatter::pad
```

Так `_ZN...` превращается в человекочитаемое имя функции.

## Ограничения

Во-первых, если собрано с `-s -w` (Go) или strip (Rust), таблицы символов нет — приходится
работать по эвристикам. Во-вторых, **обфускатор `garble`** для Go искажает даже имена
пакетов и строки, ломая распознавание. В-третьих, статическая линковка означает, что
системные вызовы идут через обёртки рантайма, а не напрямую. В-четвёртых, Go-бинарники
содержат огромный `gopclntab`, который может восстанавливаться даже после strip — это
плюс для аналитика.

## Если сработало: что зафиксировать

Определи язык и версию (Go 1.21, Rust 1.75), извлеки конфиг (C2, токены), и восстанови имена
функций для понимания возможностей. В отчёте укажи: статический бинарник, язык, версия
компилятора, C2-индикаторы. Язык помогает предсказать поведение: Go-малварь часто
многопоточна и любит Telegram/HTTP, Rust — аккуратна с памятью и использует async.

## Распознаём статическую линковку на уровне загрузчика

Помимо строк, Go/Rust выдают себя **таблицей импортов** и поведением загрузчика. Открываем
PE и смотрим импорты:

```
$ python3 - <<'PY'
import pefile
pe = pefile.PE('agent.exe')
for e in pe.DIRECTORY_ENTRY_IMPORT:
    print(e.dll.decode(), [i.name.decode() for i in e.imports if i.name])
PY
KERNEL32.dll ['GetProcAddress', 'LoadLibraryA', 'VirtualAlloc', 'GetSystemTimeAsFileTime']
```

Если кроме `KERNEL32`/`ntdll` почти ничего нет, а размер большой — это статический рантайм.
Классический MSVC-бинарник тянул бы `msvcrt`, `user32`, `advapi32` и десятки функций.

## Извлечение вкомпилированных ресурсов и блобов

Go-малварь часто пакует дополнительную нагрузку внутрь себя (embedded files, `go:embed`).
Ищем большие высокоэнтропийные блобы внутри `.rdata` или секции данных и пробуем распознать
PE/ELF-заголовок (`MZ`, `\x7fELF`):

```
$ python3 - <<'PY'
d = open('agent.exe','rb').read()
for sig, name in ((b'MZ','PE'), (b'\x7fELF','ELF'), (b'PK\x03\x04','ZIP')):
    i = d.find(sig, 0x1000)
    print(name, hex(i) if i>=0 else 'not found')
PY
PE 0x2a3f10
```

Найденный по смещению 0x2a3f10 встроенный PE — вероятная вторая стадия. Вырезаем и
анализируем отдельно.

## Анализ криптографии и сетевого стека

Go-малварь тащит `crypto/aes`, `crypto/rc4`, `crypto/tls`, а Rust — crates `aes-gcm`,
`ring`, `rustls`. Их строки указывают на используемое шифрование:

```
$ strings -n 5 agent.exe | grep -iE 'aes|chacha|rc4|tls|cipher' | sort -u | head
crypto/aes
crypto/cipher
crypto/tls
```

Это подсказывает формат C2-трафика: если есть `crypto/tls`, обмен, скорее всего, по HTTPS с
самоподписанным сертификатом или pinning. Для перехвата понадобится хук на уровне библиотеки
или анализ в памяти.

## Динамика: точки перехвата

Статически восстановив имена функций (через плагин или `GoReSym`), ставь брейкпоинты на
сетевые вызовы и на функцию, читающую конфиг. У Go удобно ловить `net/http.(*Client).Do` и
`os.ReadFile`; у Rust — `reqwest::blocking::Client::send`. Логирование аргументов в этот
момент сразу даёт URL и тело запроса.

## Таблица: что искать и что это значит

| Наблюдение | Вывод |
|---|---|
| 5-10 МБ, мало импортов | статический рантайм Go/Rust |
| строки `go1.x`, `runtime.` | Go, известна версия |
| `/rustc/1.x/` | Rust, известна версия |
| embedded `MZ`/`ELF` | вторая стадия внутри |
| `crypto/aes`, `crypto/tls` | шифрованный C2 |
| Telegram Bot API строка | C2 через Telegram |

## Ограничения

`garble` (Go) и агрессивный strip (Rust) убирают имена и портят строки, оставляя только
эвристики. Обфускация строк (`garble -literals`) шифрует константы. Виртуализация рантайма
встречается редко, но существует. И помни: определение языка — это **не** вердикт о
вредоносности: легитимные утилиты (kubectl, Terraform, многие CLI) тоже Go/Rust и выглядят
так же. Язык лишь сужает круг гипотез.

## Если сработало: фиксируем результат

Запиши язык и версию компилятора, извлечённые C2/строки, встроенные стадии (с их хешами) и
восстановленные имена ключевых функций. Это даёт защите конкретные индикаторы, а аналитику —
понимание архитектуры образца.

## Итог

Статические Go/Rust-бинарники меняют привычный порядок анализа: импорты почти бесполезны, а
строки и таблицы символов — наоборот, богаты. Определив язык и версию компилятора, ты
получаешь ключ к плагинам дизассемблера и к предсказанию поведения. Всегда проверяй
встроенные блобы — вторая стадия часто спрятана прямо в теле файла.

## Проверка версии и зависимостей

Точную версию компилятора и список сторонних пакетов иногда удаётся восстановить из
встроенных метаданных модуля. Если бинарник не полностью зачищен, строка вида
`path/to/module@v1.2.3` выдаёт используемые библиотеки, а значит — и потенциальные уязвимые
зависимости. Собери все такие строки, отсортируй и зафиксируй: они ускоряют поиск известных
проблем и помогают связать образцы одного автора по одинаковому набору пакетов.
