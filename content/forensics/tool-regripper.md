## Вопрос, с которого всё начинается

Реестр Windows — это база данных конфигурации и следов активности. Читать его вручную
(бинарный формат) невозможно. **RegRipper** применяет **плагины** и выдаёт готовые
артефакты. Разберём.

## Наш пример: куст NTUSER.DAT

## Шаг 1: кусты реестра

Реестр — это набор «кустов» (hives):

- `SYSTEM` — конфигурация системы;
- `SOFTWARE` — установленное ПО;
- `SAM` — пользователи;
- `SECURITY` — политики;
- `NTUSER.DAT` — настройки пользователя.

## Шаг 2: запуск плагина

```
$ rip.pl -r NTUSER.DAT -p userassist
```

`userassist` — один из плагинов. Он показывает, какие программы запускал пользователь,
сколько раз и когда.

## Шаг 3: полезные плагины

- `run` — ключи автозапуска (`Run`/`RunOnce`);
- `shellbags` — какие папки открывали;
- `usb` — подключённые USB-устройства;
- `recentdocs` — недавние документы;
- `typedurls` — введённые URL.

```
$ rip.pl -r SYSTEM -p usb
```

## Шаг 4: массовый прогон

RegRipper умеет прогонять **все** плагины:

```
$ rip.pl -r NTUSER.DAT -a > all.txt
```

Или использовать `rip.pl` с `-l` для списка плагинов.

## Шаг 5: что искать

- **автозапуск** (persistence);
- **запущенные программы** (UserAssist, Prefetch-связка);
- **USB-история**;
- **недавние файлы**;
- **конфигурация** (RDP, сеть).

## Что мы теперь знаем

- Реестр — набор кустов (SYSTEM, SOFTWARE, SAM, NTUSER.DAT).
- RegRipper применяет плагины к кустам.
- Плагины: run, shellbags, usb, userassist, recentdocs.
- Можно прогнать все плагины сразу.
- Даёт persistence, запуски, USB, недавние файлы.

## Если не сработало

- Куст повреждён? Используй восстановление (reg-recovery).
- Нужен плагин? Проверь список (`-l`).
- Нужен другой артефакт? Пиши свой плагин.

## Как устроен реестр: кусты, ключи, значения

Реестр — иерархическая база. Верхний уровень — **кусты** (hives), каждый
хранится отдельным файлом:

| Куст | Путь в системе | Что внутри |
| --- | --- | --- |
| SYSTEM | `C:\Windows\System32\config\SYSTEM` | конфигурация, сервисы, USB |
| SOFTWARE | `...\config\SOFTWARE` | установленное ПО |
| SAM | `...\config\SAM` | учётные записи (хэши) |
| SECURITY | `...\config\SECURITY` | политики, LSA-секреты |
| NTUSER.DAT | `C:\Users\<user>\NTUSER.DAT` | настройки пользователя |
| UsrClass.dat | `...\AppData\Local\Microsoft\Windows\UsrClass.dat` | Shellbags |

Внутри куста — **ключи** (как папки) и **значения** (как файлы с данными).
Значения имеют тип: `REG_SZ` (строка), `REG_DWORD` (число), `REG_BINARY`
(бинарь), `REG_MULTI_SZ` (список строк). RegRipper знает, как читать эти
типы и превращать их в человекочитаемый отчёт.

## Работа на примере: разбираем UserAssist

**UserAssist** — ключ, куда Windows пишет запущенные пользователем программы
(с иконками в GUI). Данные закодированы **ROT13** и содержат счётчик запусков
и время последнего запуска.

```
$ rip.pl -r NTUSER.DAT -p userassist
userassist v.20200525
(NTUSER.DAT) UserAssist keys
{...GUID...}\Microsoft\Windows\Explorer\...
  Thu Jan 14 03:28:41 2026 Z
  C:\Users\bob\Downloads\payload.exe (1)
```

Здесь видно: программа `payload.exe` из `Downloads`, запущена один раз в
03:28. Время — в UTC. Это ключевая улика выполнения, которая часто
подтверждает гипотезу «скачал и запустил».

## Плагины по категориям

RegRipper — это набор плагинов, сгруппированных по задачам:

- **Persistence**: `run`, `runonce`, `services`, `imagefile` (IFEO);
- **Execution**: `userassist`, `appcompatcache`, `muicache`;
- **USB**: `usb`, `usbstor` (в SYSTEM) — когда подключали флешки;
- **User activity**: `shellbags`, `recentdocs`, `typedurls`, `wordwheelquery`;
- **Network/config**: `network`, `route`, `rdp`.

Каждый плагин — маленькая программа, знающая структуру конкретного ключа.
Прогнать всё сразу:

```
$ rip.pl -r NTUSER.DAT -a > ntuser_all.txt
```

Вывод большой, поэтому фильтруй по интересующей категории:

```
$ grep -iA3 'run\\' ntuser_all.txt | head
```

## Извлечение кустов из образа

Кусты — это файлы; их надо сначала достать из образа диска. Инструменты
Sleuth Kit читают их напрямую:

```
$ fls -r -p disk.E01 | grep -iE 'NTUSER.DAT|SYSTEM$|SAM$' | head
$ icat disk.E01 <inode> > NTUSER.DAT
```

Так мы получаем «чистый» куст, не поднимая систему. Это важно: работаем с
**копией**, оригинал не трогаем. Для повреждённых кустов есть `reg-recovery`
(реконструкция по транзакционным логам `.LOG1`/`.LOG2`).

## Массовый прогон и разбор вывода

Когда кустов много (несколько профилей), удобно пройтись циклом и сложить
отчёты:

```
$ for h in NTUSER.DAT.*; do rip.pl -r "$h" -a > "rip_$h.txt"; done
```

Затем ищем по всем отчётам сразу:

```
$ grep -riE 'run|payload|\.exe' rip_*.txt | grep -iE 'tmp|downloads|appdata' | head
```

Так быстро находятся подозрительные автозапуски во всех профилях.

## Ограничения и подводные камни

- **Реестр можно чистить** — продвинутая малварь удаляет свои ключи;
  сравнивай с транзакционными логами.
- **Время в UTC** — не забывай про таймзону.
- **Плагин зависит от версии** — структура ключей меняется между версиями
  Windows; бери актуальный RegRipper.
- **Не всё в одном кусте** — USB-история частично в SYSTEM, частично в
  NTUSER; сверяй оба.

## Практический чек-лист

1. Извлечь кусты из образа (копии!).
2. Прогнать `run`, `userassist`, `usb`, `shellbags`.
3. Сопоставить время выполнения с другими артефактами (Prefetch, EVTX).
4. Проверить persistence и USB-историю.
5. Учесть UTC и версию Windows.
6. Зафиксировать хэши кустов и вывод отчётов.

## Разбор Shellbags: куда заходил пользователь

**Shellbags** — ключи реестра, хранящие «представление папок» в Проводнике.
Они показывают, какие папки пользователь открывал, даже если папка удалена
или была на отключённом носителе. Это ценно: подозреваемый мог открыть
папку с уликами, а потом удалить её.

```
$ rip.pl -r UsrClass.dat -p shellbags
shellbags v.20200525
HKCU\...\BagMRU\...
  My Computer
    C:\Users\bob\Documents\secret_project
```

Shellbags живут в `UsrClass.dat` (не в NTUSER.DAT). Записи содержат время
последнего обращения (в некоторых версиях) и путь. Для полного анализа
применяют специализированные парсеры (ShellBags Explorer), но RegRipper
даёт быстрый обзор.

## USB-история: ключи USBSTOR и MountedDevices

Подключённые USB-устройства оставляют следы в **SYSTEM**-кусте:

- `USBSTOR` — модель и серийный номер флешки;
- `MountedDevices` — каким буквам дисков соответствовали устройства;
- `Enum\USB` — история подключений.

```
$ rip.pl -r SYSTEM -p usbstor
USBSTOR v.20200525
USBSTOR\Disk&Ven_SanDisk&Prod_Cruzer&Rev_1.00\...
  LastWrite: Thu Jan 14 03:15:02 2026
```

Так устанавливают, подключали ли к машине конкретную флешку и когда. Серийный
номер флешки — уникальный идентификатор, который связывает её с другими
эпизодами.

## Сравнение с рег-эксплорером

RegRipper — CLI и плагины; есть и GUI-инструменты (Registry Explorer,
Eric Zimmerman's tools). Для форензики важен не столько инструмент, сколько
понимание **структуры ключей**. RegRipper удобен в автоматизации (скрипты,
массовый прогон), GUI — в ручном исследовании незнакомого ключа. Часто их
комбинируют: RegRipper находит, GUI — уточняет.

## Типичные артефакты и их значение

| Артефакт | Ключ/куст | Что даёт |
| --- | --- | --- |
| Run/RunOnce | NTUSER/SOFTWARE | автозапуск программ |
| UserAssist | NTUSER | запуски из GUI |
| Shellbags | UsrClass.dat | открытые папки |
| USBSTOR | SYSTEM | подключённые флешки |
| TypedURLs | NTUSER | введённые адреса |
| RecentDocs | NTUSER | недавние документы |
| AppCompatCache | SYSTEM | выполнение бинарников |

## Если сработало / если нет

- **Нашёл автозапуск на payload.exe** — сопоставь время с Prefetch/EVTX,
  выстрой цепочку «создан → запущен».
- **Куст повреждён** — восстанови через `.LOG1`/`.LOG2`.
- **Плагин не поддерживает версию** — обнови RegRipper или разбирай ключ
  вручную.
- **Данные «пустые»** — возможно, чистили реестр; сверь с транзакционными
  логами и другими источниками.

## AppCompatCache: следы выполнения без Prefetch

Если Prefetch отключён или очищен, остаётся **AppCompatCache** (он же
ShimCache) — в кусте SYSTEM. Он хранит записи о бинарниках, которые
проверялись на совместимость, то есть запускались:

```
$ rip.pl -r SYSTEM -p appcompatcache
AppCompatCache v.20200525
...
  C:\Users\bob\Downloads\payload.exe
  Last Modified: 2026-01-14 03:28:11Z
```

Важно: время здесь — время изменения файла, а не запуска. Но сам факт
наличия пути в кэше означает, что бинарник **запускали**. В сочетании с
UserAssist и Prefetch это даёт трёхкратное подтверждение выполнения.

## Практический сценарий: разбор заражения

Соберём картину по реестру:

1. **UserAssist** — `payload.exe` запущен в 03:28 из `Downloads`.
2. **Run-ключ** — `Updater = payload.exe` (persistence).
3. **AppCompatCache** — путь `payload.exe` присутствует.
4. **USBSTOR** — незадолго до этого подключали флешку.

Каждый артефакт из своего куста, но вместе они складываются в связную
историю: флешка → запуск → закрепление. Именно так реестр превращается из
«набора ключей» в доказательство.

## Если сработало / если нет

- **Есть Run-ключ, но нет UserAssist** — возможно, запускали не из GUI
  (служба/скрипт); проверь `services` и планировщик.
- **AppCompatCache пуст** — Prefetch/кэш могли чистить; ищи альтернативы
  (Amcache, `$MFT`).
- **Кустов несколько профилей** — прогоняй каждый отдельно и не смешивай
  время пользователей.

## Разбор ключа вручную без плагина

Если плагина для нужного ключа нет, ключ разбирают вручную. Инструменты:

- **Registry Explorer** (GUI) — навигация по дереву;
- **reglookup** (CLI) — экспорт в CSV;
- **python-regf** — скриптовый доступ.

```
$ reglookup NTUSER.DAT | grep -i 'Updater'
/Software/Microsoft/Windows/CurrentVersion/Run,Updater,SZ,payload.exe
```

Строка показывает полный путь ключа, имя значения (`Updater`), тип (`SZ` —
строка) и данные (`payload.exe`). Так можно вытащить любое значение, даже
если готового плагина нет.

## Что фиксировать в отчёте

- **Путь ключа** целиком (например, `HKCU\...\Run`).
- **Имя и данные значения**.
- **Тип данных** (`REG_SZ`, `REG_BINARY`).
- **Время последней записи (LastWrite)** ключа.
- **Источник** — какой куст, какое устройство.
- **Хэш куста** на момент извлечения.

Фиксация пути и времени делает вывод проверяемым: другой специалист сможет
воспроизвести разбор на копии куста.

## Частые ошибки

- **Смешивать время** ключей разных профилей.
- **Игнорировать LastWrite** — ключ мог быть создан давно, а изменён недавно.
- **Верить только одному артефакту** — всегда подкрепляй вторым источником.
- **Работать на оригинале** — только на копии, оригинал в архив.
