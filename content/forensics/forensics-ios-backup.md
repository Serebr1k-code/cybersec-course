## Вопрос, с которого всё начинается

Самый доступный способ получить данные с iPhone — **бэкап**. Но структура нетривиальна:
файлы названы хешами. Разберём, как её читать.

## Наш пример: iTunes/Finder-бэкап

## Шаг 1: структура

```
$ ls ~/Library/Application\ Support/MobileSync/Backup/<UDID>/
Manifest.db  Manifest.plist  Status.plist  00/  01/ ...
```

Файлы разложены по двум символам хеша. Имена — SHA-1 от domain+path.

## Шаг 2: Manifest.db

Ключ к бэкапу — `Manifest.db` (SQLite):

```
$ sqlite3 Manifest.db 'SELECT fileID, domain, relativePath FROM Files LIMIT 5;'
1a2b...  AppDomain-com.apple.Maps  Library/Caches/cache.cell
```

`fileID` — имя файла в бэкапе, `domain` — приложение/система, `relativePath` — путь.

## Шаг 3: извлечение

```
$ sqlite3 Manifest.db 'SELECT fileID FROM Files WHERE domain="HomeDomain" AND relativePath LIKE "%SMS%"'
```

Затем файл лежит в `Backup/<UDID>/<первые 2 символа fileID>/<fileID>`.

## Шаг 4: шифрованный бэкап

Если бэкап зашифрован, нужен пароль:

```
$ iphone_backup_decrypt -i Backup/UDID -o out -p <password>
```

Шифрованные бэкапы содержат **больше** (в т.ч. keychain).

## Шаг 5: что искать

- SMS/звонки (`HomeDomain/Library/SMS`);
- базы приложений (`AppDomain-*`);
- локации (`AppDomain-com.apple.Maps`);
- health, заметки, фото.

## Что мы теперь знаем

- iOS-бэкап разложен по хешам файлов.
- `Manifest.db` связывает fileID↔domain↔path.
- Файл лежит по пути из первых символов fileID.
- Шифрованный бэкап требует пароля и даёт больше.
- Даёт SMS, приложения, локации.

## Если не сработало

- Manifest повреждён? Проверь Status.plist.
- Бэкап зашифрован? Нужен пароль.
- Нужен keychain? Только шифрованный бэкап/живое устройство.

## Структура бэкапа

Бэкап iPhone (iTunes/Finder) — это не дерево файлов с понятными именами, а набор
файлов, разложенных по подкаталогам, имена которых совпадают с первыми двумя
символами SHA-1. В корне лежат четыре метафайла:

| Файл | Что содержит |
|---|---|
| `Manifest.plist` | метаданные бэкапа: устройство, версия iOS, шифрование, ключи |
| `Manifest.db` | карта: логический путь → имя файла на диске |
| `Info.plist` | сводка: имя, телефон, версия ОС |
| `Status.plist` | состояние бэкапа (полный/инкрементальный) |

Именно `Manifest.db` превращает безымянные файлы в осмысленную структуру: в таблице
`Files` есть столбцы `fileID`, `domain`, `relativePath` и `flags`. Зная домен и
путь, можно вычислить, где лежит файл.

## Домены и как найти файл

`fileID` — это SHA-1 от строки `домен-относительный_путь`. Значит, найти файл можно
без базы:

```
$ echo -n 'HomeDomain-Library/SMS/sms.db' | shasum -a 1
```

Полученный хеш `abcd...` означает, что файл лежит в `ab/cd...`. Домены отражают
происхождение данных: `HomeDomain` — данные пользователя, `CameraRollDomain` —
медиа, `AppDomain-com.example` — приложение, `RootDomain` — системное, а
`WirelessDomain` — настройки Wi-Fi. Понимание доменов сразу подсказывает, где искать
переписку, фото или пароли.

## Шифрованный и нешифрованный бэкап

Нешифрованный бэкап не содержит keychain и части чувствительных данных. Шифрованный
(с паролем) включает их, но требует пароля для расшифровки. `Manifest.plist`
содержит признак `IsEncrypted`, а также обёрнутые ключи. Без пароля содержимое
остаётся недоступным — это не «битый архив».

## Инструменты извлечения

```
$ idevicebackup2 backup --full Backup/
$ iphone_backup_decrypt -i Backup/<UDID> -o out -p <password>
$ ileapp -i out -o report/          # iLEAPP: разбор артефактов
```

Для старта достаточно распаковать файлы по `Manifest.db` и применить парсеры
артефактов. Ручной поиск по хешу полезен, когда нужен конкретный файл.

## Что искать

- SMS/iMessage (`HomeDomain-Library/SMS/sms.db`);
- контакты, календарь, заметки;
- медиа с геотегами (`CameraRollDomain`);
- keychain (только в шифрованном бэкапе);
- базы приложений (`AppDomain-*`) — переписка мессенджеров;
- настройки Wi-Fi (`WirelessDomain`).

## Тонкие места

- `Manifest.db` — карта; без неё файлы безымянные, но восстановимы по SHA-1.
- Инкрементальный бэкап содержит не все файлы — сверяй `Status.plist`.
- Пароль бэкапа — не пароль устройства; они независимы.
- `fileID` считается от нормализованного пути — регистр и разделители важны.
- Локальный бэкап может быть усечён — проверяй целостность до анализа.

## Расширенный разбор: от бэкапа к переписке

Задача: восстановить переписку iMessage из бэкапа. Маршрут:

```
$ ls Backup/<UDID>/ | head
$ sqlite3 Backup/<UDID>/Manifest.db 'SELECT fileID,domain,relativePath FROM Files WHERE relativePath LIKE "%sms.db";'
$ echo -n 'HomeDomain-Library/SMS/sms.db' | shasum -a 1     # сверить fileID
```

Получив `fileID`, копируешь файл из подкаталога с именем из первых двух символов:

```
$ cp Backup/<UDID>/ab/abcdef... sms.db
$ sqlite3 sms.db '.tables'
$ sqlite3 sms.db 'SELECT datetime(date/1000000000+978307200,"unixepoch"),text FROM message LIMIT 5;'
```

Время в базах iOS — Apple epoch (секунды с 2001-01-01), а в `sms.db` оно ещё и в
наносекундах: дели на 1e9 и прибавляй 978307200. Текст сообщений — в таблице
`message`, вложения — ссылками на файлы в других доменах.

Если бэкап шифрован, сначала расшифровываешь:

```
$ iphone_backup_decrypt -i Backup/<UDID> -o out -p <password>
```

Только после этого `keychain-backup.plist` и чувствительные базы становятся
читаемыми.

## Ограничения

- Нешифрованный бэкап не содержит keychain и части чувствительных данных.
- Инкрементальный бэкап может не содержать старых файлов — сверяй `Status.plist`.
- `Manifest.db` может быть повреждён — тогда файлы восстанавливают по SHA-1 вручную.
- Пароль бэкапа и пароль устройства независимы; забытый пароль бэкапа = нет доступа.
- Имена файлов на диске — только хеши; без карты навигация бессмысленна.

## Что писать в отчёте

Укажи устройство, версию iOS, тип бэкапа (полный/инкрементальный), был ли он
шифрован и как получен пароль. Для каждого извлечённого артефакта — домен и
логический путь (`HomeDomain-Library/SMS/sms.db`), а не только имя на диске. Это
делает вывод проверяемым: любой сможет повторить путь от `Manifest.db` до файла.
Отдельно перечисли, что не удалось извлечь и почему (шифрование, отсутствие файла
в инкрементальном бэкапе, усечённый архив).

## Ручное восстановление по хешу

Иногда `Manifest.db` повреждён или отсутствует, но сами файлы на диске есть. Тогда
работают «от содержимого»: определяют тип файлов по магии и связывают их с
логическими путями вручную. Полезные команды:

```
$ find Backup/<UDID> -type f -name '????????????????????????????????????????' | head
$ for f in Backup/<UDID>/*/*; do file "$f"; done | grep -i sqlite | head
$ sqlite3 <файл> '.tables'
```

Файлы-базы SQLite опознаются по заголовку `SQLite format 3`. Найдя, например, базу с
таблицей `message`, ты понимаешь, что это `sms.db`, и можешь сопоставить её
логический путь. Такой «археологический» подход медленнее, но спасает повреждённые
бэкапы.

## Сравнение с Android-бэкапом

Android-бэкап (`adb backup` или AB-формат) устроен иначе: это архив с `apps/` и
`shared/`, без хешированных имён, но и без полного набора системных данных. iOS-бэкап
богаче по артефактам (keychain, домены приложений), но сложнее в навигации из-за
хеш-имён. Общий принцип один: есть карта (в iOS — `Manifest.db`), которая связывает
логические пути с физическими файлами; без неё остаётся ручное опознание.

## Практические заметки

Перед разбором сделай рабочую копию бэкапа и не трогай оригинал. Зафиксируй хеши
всех метафайлов. Проверь `IsEncrypted` в `Manifest.plist` — от этого зависит
маршрут. Если бэкап шифрован, пароль храни отдельно от выводов. Для каждого
извлечённого артефакта сохраняй исходный файл и логический путь, чтобы вывод был
воспроизводим. И помни про Apple epoch в каждом временном поле — это самая частая
ошибка при анализе iOS-бэкапов.

## Итог

Бэкап iOS — это хеш-хранилище плюс карта `Manifest.db`, связывающая логические пути
с физическими файлами. Зная домен и путь, ты находишь файл по SHA-1 без базы;
зная карту — идёшь напрямую. Шифрованный бэкап добавляет keychain и чувствительные
данные, но требует пароля. В отчёте для каждого артефакта указывай домен и
логический путь, а время переводи из Apple epoch. Так вывод становится
воспроизводимым, а не набором «каких-то баз из архива».

## Частые вопросы на защите отчёта

По бэкапу всегда спросят: полный он или инкрементальный? Инкрементальный может не
содержать старых файлов, и это надо указать заранее, иначе вывод «файла нет»
будет неверным. Далее — был ли бэкап шифрован и откуда взят пароль. От этого
зависит, доступны ли keychain и чувствительные базы. Затем — как связаны
логические пути и файлы на диске: покажи, что использовал `Manifest.db`, а при её
повреждении — восстановление по SHA-1. Отдельно уточни, что для каждого артефакта
указан домен и логический путь, а время переведено из Apple epoch. Такой отчёт
можно проверить шаг за шагом, и он не рассыпается при первом уточняющем вопросе.

## Кратко

Бэкап iOS — хеш-хранилище плюс карта `Manifest.db`. Логический путь находится по
SHA-1, шифрованный бэкап даёт keychain, а время всегда в Apple epoch. Указывай
домен и путь каждого артефакта — тогда вывод воспроизводим.



Запомни главное: без карты или SHA-1 файлы бэкапа остаются безымянными, а без пароля
шифрованного бэкапа keychain недоступен.



Проверяй целостность архива и `Status.plist` до анализа: усечённый или
инкрементальный бэкап объясняет «пропавшие» файлы лучше, чем гипотеза об удалении.



Итог: карта бэкапа плюс SHA-1 дают навигацию, шифрование определяет доступ к
keychain, а корректный пересчёт Apple-времени делает таймлайн достоверным.
