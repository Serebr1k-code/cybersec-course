## Вопрос, с которого всё начинается

Есть аудиозапись — возможно, доказательство, а возможно, носитель скрытых данных.
Нужно понять формат, метаданные и что внутри. Разберём.

## Наш пример: WAV-файл

## Шаг 1: определяем формат

```
$ file recording.wav
recording.wav: RIFF (little-endian) data, WAVE audio, PCM, 16 bit, mono 44100 Hz
```

WAV — несжатый PCM: `RIFF` + `fmt ` + `data`. Это удобно: каждый сэмпл на месте.

## Шаг 2: структура WAV

- `RIFF` — контейнер;
- `fmt ` — параметры (частота, каналы, битность);
- `data` — сами сэмплы;
- возможны **дополнительные чанки** (метаданные, скрытые данные).

```
$ xxd -l 64 recording.wav
00000000: 52494646 ... 57415645 666d7420
```

`52494646` = "RIFF", `57415645` = "WAVE".

## Шаг 3: метаданные

MP3/FLAC несут теги (ID3):

```
$ ffprobe -show_format recording.mp3 | head
artist : Ivan
comment : recorded at ...
```

Теги могут содержать GPS, время, устройство.

## Шаг 4: скрытые данные

Аудио — популярный носитель стеганографии:

- **LSB** (младшие биты сэмплов);
- добавленные чанки в WAV;
- **спектрограмма** (скрытый текст в спектре).

```
$ sox recording.wav -n spectrogram -o spec.png
```

На спектрограмме иногда видно текст, «нарисованный» в частотах.

## Шаг 5: что искать

- метаданные (автор, устройство, GPS);
- лишние чанки;
- LSB-модификации;
- аномалии спектра.

## Что мы теперь знаем

- WAV — RIFF с чанками fmt/data.
- MP3/FLAC несут теги (ID3).
- Аудио — носитель стеганографии (LSB, спектр).
- Спектрограмма выявляет скрытый текст.
- Метаданные дают контекст.

## Если не сработало

- Формат неизвестен? Используй `ffprobe`.
- Данные сжаты? Смотри сжатые контейнеры.
- Нужен звук? Воспроизведи/нормализуй (`sox`).

## Практический разбор: разбор WAV до сэмплов

WAV удобен тем, что каждый сэмпл лежит на месте. Разберём файл программно,
чтобы увидеть чанки и параметры:

```bash
$ python3 - <<'EOF'
import wave
w = wave.open('recording.wav','rb')
print('channels', w.getnchannels())
print('rate', w.getframerate())
print('width', w.getsampwidth())
print('frames', w.getnframes())
EOF
channels 1
rate 44100
width 2
frames 441000
```

441000 кадров при 44100 Гц — ровно 10 секунд. Зная длительность, можно сверять
её с метаданными и находить несоответствия. Перечислим все чанки вручную:

```bash
$ xxd recording.wav | grep -E 'RIFF|fmt |data|LIST|INFO'
00000000: 52494646 ... 57415645 666d7420  RIFF....WAVEfmt 
00000024: 64617461 ...                 data....
```

Чанк `LIST/INFO` — это метаданные: автор, программа записи, комментарий.

## Таблица форматов и их свойств

| Формат | Сжатие | Метаданные | Особенность |
|---|---|---|---|
| WAV | нет (PCM) | RIFF INFO | сэмплы видны напрямую |
| MP3 | с потерями | ID3v1/v2 | артефакты сжатия |
| FLAC | без потерь | Vorbis comment | целые сэмплы |
| OGG/Vorbis | с потерями | Vorbis comment | контейнер Ogg |
| AAC/M4A | с потерями | iTunes atoms | в MP4-контейнере |

Несжатые форматы удобны для стег-анализа, сжатые — сложнее модифицировать
незаметно.

## Метаданные: ID3, RIFF INFO, Vorbis

```bash
$ ffprobe -v quiet -show_format -show_streams recording.mp3 | grep -E 'TAG|artist|comment|date'
TAG:artist=Ivan
TAG:comment=recorded at office
TAG:date=2026
```

Теги могут содержать GPS-координаты, модель устройства и точное время записи —
это связывает файл с местом и автором. Однако теги легко подделать: не
полагайся на них как на единственное доказательство.

## Практический разбор: LSB и спектрограмма

Аудио — популярный контейнер стеганографии. Первый классический метод — младшие
биты (LSB) сэмплов. Их можно извлечь в сырой поток:

```bash
$ python3 - <<'EOF'
import wave, struct
w = wave.open('recording.wav','rb'); n = w.getnframes()
data = struct.unpack('<%dh' % n, w.readframes(n))
bits = [str(s & 1) for s in data]
b = bytes(int(''.join(bits[i:i+8]),2) for i in range(0, len(bits)-8, 8))
print(b[:80])
EOF
b'PK\x03\x04...'
```

Префикс `PK\x03\x04` означает, что в младших битах спрятан ZIP-архив. Второй
метод — текст, «нарисованный» в спектре. Строим спектрограмму:

```bash
$ sox recording.wav -n spectrogram -o spec.png
```

На спектрограмме иногда читается надпись — она появляется как горизонтальные
штрихи в определённых частотах.

## Анализ подлинности и монтажа

- **ENF (Electric Network Frequency).** Частота сети (~50 Гц) слегка колеблется
  и «впечатывается» в запись; по ней сверяют время и место.
- **Артефакты сжатия.** Склейки в MP3/AAC дают разрывы в спектре и сбои
  предсказания.
- **Волновая форма.** Резкие скачки амплитуды или тишина посередине — признак
  редактирования.
- **Фоновый шум.** Непрерывный шум помещения разрывается в месте склейки.
- **Метаданные.** Несоответствие длительности в теге и в потоке — красный флаг.

## Ограничения и типичные ошибки

- **Перекодирование.** Повторное сжатие уничтожает LSB и следы ENF.
- **Неверный формат.** `file` может ошибаться; проверяй `ffprobe`.
- **Спектрограмма как истина.** Не каждый «текст» в спектре осмыслен — бывает
  случайный узор.
- **Подделка тегов.** Метаданные легко изменить; подтверждай содержимым.
- **Нормализация.** `sox`/`ffmpeg` меняют сэмплы — работай с копией.

## Практический разбор: анализ каналов и шума

Стерео-запись даёт два независимых канала — иногда в них разное содержимое.
Разделим каналы и сравним:

```bash
$ sox stereo.wav left.wav remix 1
$ sox stereo.wav right.wav remix 2
$ sox left.wav -n stat 2>&1 | grep -E 'Maximum|RMS'
Maximum amplitude: 0.812
RMS amplitude: 0.101
```

Если в одном канале RMS заметно ниже, там может быть тишина или скрытый сигнал.
Спектральный анализ выявляет узкополосные пики — следы модуляции:

```bash
$ sox recording.wav -n spectrogram -x 1200 -y 513 -z 100 -o spec.png
```

Полосы на определённых частотах, не характерные для речи, — кандидаты на
скрытый канал.

## Инструменты аудио-форензики

| Инструмент | Назначение | Что даёт |
|---|---|---|
| `sox` | обработка/анализ | спектрограмма, stat, эффекты |
| `ffmpeg`/`ffprobe` | форматы/метаданные | теги, потоки |
| `steghide` | стег-контейнеры | извлечение из WAV/AU |
| `Audacity` | визуальный анализ | спектр,波形, метки |
| Sonic Visualiser | спектр/слои | детальный разбор частот |
| `python wave` | прямой доступ | сэмплы, чанки |

## Чек-лист аудио-форензики

1. Определи формат (`file`, `ffprobe`) и длительность.
2. Прочитай метаданные (ID3/RIFF INFO/Vorbis).
3. Проверь чанки WAV на лишние блоки.
4. Построй спектрограмму и осмотри аномалии.
5. Проверь LSB-модификации на целевом файле.
6. Сравни каналы стерео и фоновый шум.
7. Оцени подлинность (ENF, артефакты склейки).
8. Работай с копией, хэшируй результат.

## Частые заблуждения

- «Метаданные всегда правдивы» — теги легко подделать; подтверждай содержимым.
- «Спектрограмма не врёт» — случайный узор можно принять за текст.
- «Перекодирование безвредно» — оно уничтожает LSB и следы ENF.
- «WAV — это всегда PCM» — внутри могут быть сжатые чанки.

## Проверка результата

После извлечения скрытых данных подтверди, что это действительно осмысленное
содержимое, а не артефакт:

```bash
$ python3 lsb_extract.py recording.wav > out.bin
$ file out.bin
out.bin: Zip archive data, at least v2.0 to extract
$ unzip -l out.bin
Archive:  out.bin
  Length      Date    Time    Name
      512  2026-01-10 12:00   message.txt
```

Если тип определился и архив открывается — извлечение успешно. Иначе пересмотри
битовый порядок (LSB/MSB) и начало потока.

## Что записать в отчёт

- Хэш исходного аудиофайла и его формат/длительность.
- Метаданные (автор, устройство, время, GPS), если есть.
- Метод стег-анализа (LSB, спектр, чанки) и результат.
- Признаки монтажа/перекодирования и их основания.
- Ограничения: потери при сжатии, подделка тегов.

## Связь с другими артефактами

- **Видео.** Дорожка звука синхронизируется с видео по меткам; рассинхрон —
  признак монтажа.
- **Фото.** EXIF даёт устройство и время — сверяется с аудио-метаданными.
- **Мессенджеры.** Голосовые сообщения несут теги приложения и время отправки.
- **Телефония.** Записи звонков хранят номер и время — контекст разговора.

## Дополнительные методы стег-анализа

- **Фазовое кодирование.** Данные прячут в фазе спектра, устойчивее к сжатию,
  чем LSB; заметно по искажению формы сигнала.
- **Эхо-скрытие.** В сигнал добавляют слабое эхо с задержкой, кодирующей биты;
  обнаруживается автокорреляцией.
- **Расширение спектра.** Данные размазываются по широкой полосе под шумом —
  требует знания кода для извлечения.
- **Метаданные-чанки.** Лишние чанки в WAV/AU — самый простой, но легко
  находимый способ.

## Что записать в отчёт

- Хэш исходного файла, формат и длительность.
- Найденные метаданные и их происхождение.
- Метод стег-анализа и подтверждение извлечения (`file`, содержимое).
- Признаки монтажа и их основания.
- Ограничения: потери при перекодировании, подделка тегов, субъективность
  спектрального анализа.

## Связь с видео-форензикой

Аудио редко анализируют в отрыве от видео. Дорожка звука синхронизируется с
видеорядом по меткам; рассинхрон на доли секунды выдаёт монтаж. Кроме того,
фоновый шум помещения присутствует и в аудио, и в видео, поэтому разрыв шума
заметен сразу в обоих источниках.

Для сверки извлекают временные метки из контейнера (MP4/MKV), сравнивают их с
метаданными аудио и проверяют, совпадают ли длительности потоков. Несовпадение
— первый повод заподозрить редактирование.

## Правовые аспекты аудио-доказательств

Аудиозапись — потенциальное доказательство, поэтому важна её подлинность и
непрерывность хранения. Фиксируй хэш оригинала, работай только с копией и
документируй каждый шаг обработки, чтобы результат нельзя было оспорить.
