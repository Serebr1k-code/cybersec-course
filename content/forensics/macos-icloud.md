## Вопрос, с которого всё начинается

Файла на диске нет — возможно, он уже в iCloud. macOS синхронизирует документы, фото,
заметки, переписку. Для расследования это значит: часть данных **вне устройства**, но
локальные следы синхронизации остаются. Разберём их.

## Наш пример: iCloud Drive

## Шаг 1: где локальные данные

```
$ ls ~/Library/Mobile\ Documents/
com~apple~CloudDocs  com~apple~Notes  ...
```

Каталог `Mobile Documents` — локальное зеркало iCloud-контейнеров. Файлы могут быть
«выгружены» (только заглушка) или полными, в зависимости от статуса.

## Шаг 2: статус синхронизации

```
$ brctl status | head
iCloud Drive: enabled
```

`brctl` (bird control) управляет синхронизацией. Из его вывода видно, что включено,
что синхронизируется и есть ли ошибки.

## Шаг 3: журнал bird

Процесс синхронизации — `bird`. Он логирует:

```
$ log show --predicate 'process == "bird"' --last 1d | grep -i 'upload\|download' | head
2026-01-14 03:29:00 bird[400]: upload /Users/user/Documents/report.pdf
```

Отсюда видно, что и когда уходило в облако. Это критично: данные, ушедшие в iCloud,
находятся вне зоны вашего контроля.

## Шаг 4: заметки, фото, сообщения

Помимо файлов, iCloud синхронизирует:

- **Notes** (`~/Library/Group Containers/group.com.apple.notes/`);
- **Photos** (`~/Pictures/Photos Library.photoslibrary`);
- **Messages** (при включённом «Messages in iCloud»).

Локальные базы остаются, даже если контент выгружен.

## Шаг 5: оценка утечки

Ключевой вопрос расследования: ушли ли данные наружу? Проверяем:

```
$ brctl log --short | grep -i 'uploaded' | tail
```

И сопоставляем время загрузки с событиями инцидента. Файл, загруженный в iCloud за
минуту до удаления, — явный признак подготовки.

## Что мы теперь знаем

- `~/Library/Mobile Documents` — локальное зеркало iCloud.
- `brctl` управляет и показывает статус синхронизации.
- `bird` логирует загрузку/скачивание.
- Notes/Photos/Messages тоже синхронизируются.
- Загрузка перед удалением — признак эксфильтрации через облако.

## Если не сработало

- Данные выгружены? Заглушки сохраняют имена и метаданные.
- Нужно содержимое? Только через аккаунт Apple ID.
- Логи ротированы? Смотри архив unified log.

## Где живут данные iCloud на диске

iCloud Drive на macOS — это не отдельная «папка в облаке», а локальный каталог, который
демон `bird` синхронизирует с серверами Apple:

```
$ ls -la ~/Library/Mobile\ Documents/
com~apple~CloudDocs/            # iCloud Drive
com~apple~Notes/                # Заметки
com~apple~Reminders/            # Напоминания
$ ls -la ~/Library/Application\ Support/CloudDocs/
```

Файлы в `~/Library/Mobile Documents/` — это то, что реально лежит на диске. Часть из них
может быть «выгружена» (заглушка вместо содержимого). Проверить статус можно через
расширенные атрибуты и утилиту `brctl`:

```
$ brctl status com~apple~CloudDocs | head
$ brctl download ~/Library/Mobile\ Documents/com~apple~CloudDocs/secret.txt
```

`brctl download` заставляет систему подтянуть файл из облака (если есть сеть и учётка).
Для форензики важно: **выгруженные** файлы на диске пусты, поэтому их содержимое надо
либо скачивать, либо получать из облачного бэкапа.

## Статус синхронизации и метаданные

Каждый объект iCloud имеет набор расширенных атрибутов и метаданных, показывающих, куда и
когда он синхронизировался:

```
$ xattr -l ~/Library/Mobile\ Documents/com~apple~CloudDocs/report.pdf
com.apple.quarantine: ...
com.apple.icloud.desktop: ...
$ mdls ~/Library/Mobile\ Documents/com~apple~CloudDocs/report.pdf | grep -i icloud
kMDItemIsCloudy  = 0
```

`kMDItemIsCloudy = 0` означает, что файл материализован локально; `1` — только в облаке.

## Журналы демона bird

Самое ценное — **логи синхронизации**. Они фиксируют, что именно и когда уходило на сервер:

```
$ log show --predicate 'process == "bird"' --last 2h --style compact | head
... bird ... uploading 3 files, 12.4 MB ...
... bird ... downloaded "ProjectPlan.docx" ...
```

Через `log show` можно сузить по подсистеме `com.apple.clouddocs` и увидеть события
загрузки/выгрузки, конфликты и ошибки. Эти записи показывают **направление** обмена: файл
уходил с устройства или приходил на него.

## Заметки, фото и сообщения

iCloud синхронизирует не только файлы:

| Данные | Локальный артефакт | Что даёт |
|---|---|---|
| Заметки | `NoteStore.sqlite` (в контейнере Notes) | текст, вложения, история правок |
| Фото | `Photos.sqlite` + `originals/` | снимки, геометки, время |
| Сообщения | `chat.db` | переписка, синхронизированная через iCloud |
| Пароли | `~/Library/Keychains/` | связка ключей (end-to-end) |
| Здоровье | `Health` (на iOS) | активность, медданные |

Для Notes путь: `~/Library/Group Containers/group.com.apple.notes/NoteStore.sqlite`.
Blob-ы заметок зашифрованы ключом из связки ключей, поэтому для чтения текста нужен доступ
к keychain пользователя.

## Оценка утечки данных

Ключевой вопрос расследования: **что покинуло устройство**. Отвечаем так:

1. Смотрим, что лежит в `Mobile Documents` и имеет недавние изменения;
2. Проверяем логи `bird` на события upload в окно инцидента;
3. Сверяем с сетевыми логами (соединения к `*.icloud.com`);
4. Учитываем «Файлы рабочего стола и Документы» — если включено, эти папки тоже уходят.

```
$ log show --predicate 'process == "bird"' --start '2026-01-14 03:00:00' | grep -i upload
```

Если в окно атаки массово уходили файлы из рабочих папок, это признак **эксфильтрации через
легитимный канал**: трафик к Apple не выглядит подозрительно для сетевых средств защиты.

## Таблица: что синхронизируется по умолчанию

| Категория | По умолчанию | Примечание |
|---|---|---|
| iCloud Drive | вкл (если включён) | рабочие файлы |
| Фото | опционально | может тянуть гигабайты |
| Заметки/Напоминания | вкл с iCloud | через свои контейнеры |
| Ключ (Keychain) | опционально | пароли, end-to-end |
| Почта | опционально | правила и черновики |
| Резервные копии iOS | опционально | логический бэкап телефона |

## Ограничения

Во-первых, **сквозное шифрование** (Keychain, Здоровье, часть данных) означает, что даже
полный образ диска не даёт содержимого без ключей. Во-вторых, часть данных на устройстве —
только **заглушки**: содержимое в облаке. В-третьих, логи `bird` живут ограниченное время и
могут быть вытеснены. В-четвёртых, **два фактора и токены** iCloud хранятся в связке ключей,
и их компрометация — отдельный инцидент.

## Если сработало: подтверждаем утечку

Недостаточно сказать «файлы синхронизировались». Нужно показать: файл существовал локально
до инцидента, в окно инцидента есть событие upload в логах `bird`, и есть сетевое соединение
к `icloud.com` в то же время. Три совпадающих факта — вывод об утечке через iCloud.

## Файлы-заглушки и их обнаружение

Ключевая сложность iCloud — «облачные» файлы: на диске лежит только заглушка, а содержимое
в облаке. Их надо отличать от реальных, иначе легко сделать ложный вывод «файла нет».

```
$ find ~/Library/Mobile\ Documents -type f -exec sh -c 's=$(stat -f%z "$1"); [ "$s" -lt 16 ] && echo "STUB $s $1"' _ {} \; | head
STUB 0  .../com~apple~CloudDocs/archive.zip
```

Ноль байт при ненулевом имени — почти наверняка выгруженный файл. `mdls` подтверждает:

```
$ mdls -name kMDItemIsCloudy -name kMDItemLogicalSize stub.zip
kMDItemIsCloudy   = 1
kMDItemLogicalSize = 10485760
```

Логический размер 10 МБ при нуле на диске — содержимое в облаке. Для анализа его нужно
скачать (`brctl download`) или взять из облачного дампа.

## Пароли и связка ключей

Если включена синхронизация Keychain, пароли и токены уходят в iCloud под сквозным
шифрованием. Локально они лежат в `~/Library/Keychains/login.keychain-db`. Прочитать их можно
только с паролем входа или ключом:

```
$ security dump-keychain ~/Library/Keychains/login.keychain-db | head
```

Для форензики важно зафиксировать **факт** наличия элементов (какие сайты/приложения
хранят секреты), даже если расшифровать их не удаётся. Перечень аккаунтов сам по себе ценен.

## Что видно по логам: события sync

Демон `bird` пишет не только upload/download, но и ошибки, конфликты и подключения:

```
$ log show --predicate 'subsystem == "com.apple.clouddocs"' --last 3h --style compact | tail -30
... CloudDocs ... received push notification, syncing ...
... CloudDocs ... file conflict detected: report (2).pdf ...
```

Конфликтные копии `report (2).pdf` — важный артефакт: они показывают, что один и тот же
файл редактировался с нескольких устройств, и по времени копий можно восстановить порядок
правок и устройства-участники.

## Связь с устройствами

iCloud объединяет устройства под одним Apple ID. Артефакты синхронизации позволяют связать
их: один и тот же файл, появляющийся на нескольких устройствах, означает общий аккаунт.
Это полезно при расследовании, когда нужно доказать, что действия с телефона и с ноутбука
совершены одним человеком.

## Ограничения и подводные камни

Первое — **сквозное шифрование** закрывает содержимое Keychain и части данных даже при
полном образе. Второе — часть данных хранится только в облаке, и без доступа к Apple ID
(или судебного запроса) их не получить. Третье — логи `bird` ограничены по времени, старые
события вытесняются. Четвёртое — включённые «Оптимизация хранилища» и «Рабочий стол и
Документы» меняют набор локальных файлов, поэтому сравнивай конфигурацию с эталоном.

## Если сработало: что зафиксировать

Зафиксируй: перечень файлов, ушедших в облако (с временем из логов `bird`), их локальные
хеши (если содержимое доступно), и список устройств под общим Apple ID. Вместе это даёт
ответ на вопрос «что, когда и куда ушло», а не просто «включён iCloud».

## Итог

iCloud — это одновременно источник данных и канал утечки. Локальные контейнеры и логи `bird`
показывают, что синхронизировалось и в каком направлении, а сквозное шифрование ограничивает
доступ к самому чувствительному. Соединяй файловые артефакты с сетевыми и логическими.
