## Вопрос, с которого всё начинается

Мы умеем определять тип файла и доставать из него вложенные данные. Но у каждого
файла есть ещё один слой, который не виден при обычном просмотре, — **метаданные**:
сведения о самом файле. Кто его создал, когда, каким устройством, где снят снимок.

Именно там часто лежит то, что автор не собирался показывать. В этом уроке возьмём
одно фото и вытащим из него всё, включая координаты, где оно сделано.

## Наш пример: holiday.jpg

Тебе дали фотографию без подписи. Вопрос простой: где она сделана и чем?

Сначала — тип:

```bash
$ file holiday.jpg
holiday.jpg: JPEG image data, JFIF standard 1.01, resolution (DPI) ...
```

Обычный JPEG. Теперь читаем метаданные инструментом `exiftool` (он по умолчанию
только читает файл и ничего не меняет — это важно для улик):

```bash
$ exiftool holiday.jpg
File Name                       : holiday.jpg
File Size                       : 2.5 kB
Software                        : CameraApp 3.1
Artist                          : Ivan Petrov
Copyright                       : ACME Corp
Date/Time Original              : 2024:06:14 09:12:33
GPS Latitude Ref                : North
GPS Longitude Ref               : East
GPS Position                    : 55 deg 45' 20.88" N, 37 deg 37' 2.28" E
Image Width                     : 320
Image Height                    : 240
```

Смотри, сколько всего: программа (`Software`), автор (`Artist`), владелец прав
(`Copyright`), дата съёмки и — самое интересное — **GPS Position**.

Заметь: часть полей заполнил не человек, а устройство. `Software: CameraApp 3.1` —
это приложение, которым снимали; координаты — встроенный в камеру GPS. Такие
«машинные» поля подделать сложнее, чем имя автора, поэтому они ценнее как улика.

## Что такое EXIF

`exiftool` показал теги **EXIF** — это блок метаданных, который камеры и телефоны
записывают прямо в файл изображения. Туда попадают модель камеры, настройки, дата и,
если включена геолокация, координаты.

Координаты записаны в формате «градусы, минуты, секунды»:
`55° 45' 20.88" N, 37° 37' 2.28" E`. Переведём в привычные десятичные градусы, чтобы
вбить в карту:

```
55 + 45/60 + 20.88/3600 ≈ 55.7558
37 + 37/60 +  2.28/3600 ≈ 37.6173
```

Точка `55.7558, 37.6173` — центр Москвы. Мы только что определили место съёмки,
не имея никакой подписи. Так работает геолокация по EXIF — основа OSINT-разведки.

## Метаданные прячут не только геолокацию

`exiftool` показывает и менее очевидные поля. Посмотрим их все:

```bash
$ exiftool -a -u -g1 holiday.jpg | head -40
[ExifTool]      ExifTool Version Number : 12.76
[File]          File Name : holiday.jpg
[File]          File Type : JPEG
[EXIF]          Software : CameraApp 3.1
[EXIF]          Artist : Ivan Petrov
[EXIF]          Copyright : ACME Corp
[Composite]     GPS Position : 55 deg 45' 20.88" N, 37 deg 37' 2.28" E
```

Флаги: `-a` — показать все теги (включая дубли), `-u` — и «неизвестные» теги,
`-g1` — сгруппировать по разделам (`[File]`, `[EXIF]`, `[Composite]`). Полезно
точечно:

```bash
$ exiftool -Artist -Software -GPSPosition holiday.jpg
$ exiftool -s -GPS* holiday.jpg      # только GPS-теги, компактно
```

## Метаданные есть у всех форматов

EXIF — это про изображения. У документов свои метаданные:

```bash
$ exiftool report.pdf | grep -E 'Author|Creator|Producer|Create Date'
Author                          : Ivan Petrov
Creator                         : Microsoft Word
Create Date                     : 2024:06:14 09:20:00
```

У PDF, Office-документов (`docx`/`xlsx`), PNG (текстовые чанки `tEXt`), аудио (ID3)
и видео — везде свои поля: автор, организация, версия программы, иногда путь к файлу
на компьютере автора. В CTF это частый источник логинов и подсказок.

Проверить текстовые вставки в PNG можно и вручную:

```bash
$ strings -n 8 picture.png | head
tEXtAuthorIvan Petrov
tEXtCommentCTF{h1dd3n_1n_m3t4d4t4}
```

## А если метаданные — не то, чем кажутся

Две ловушки, о которых стоит знать:

1. **Метаданные можно подделать.** Любой может вписать чужое имя или другие
   координаты через `exiftool -Artist="..."`. Как улика метаданные слабее, чем
   содержимое: их нужно сопоставлять с другими источниками.
2. **В метаданные можно спрятать данные.** В поля комментария, в хвост после
   маркера конца файла. Если `exiftool` показывает что-то странное (длинную
   base64-строку) — декодируй её.

Полезный приём — увидеть, чем файл «чистили»:

```bash
$ exiftool -Software -History holiday.jpg
Software                        : CameraApp 3.1
```

Если `Software` = Photoshop или `exiftool`, значит файл редактировали — это тоже
зацепка.

## Убираем метаданные (для контраста)

Иногда задача обратная — опубликовать файл, не выдав себя. Метаданные удаляют так:

```bash
$ exiftool -all= -overwrite_original holiday.jpg
$ exiftool -GPSPosition holiday.jpg
```

Теперь GPS-полей нет. Это объясняет, почему в реальных утечках метаданные часто
«обнулены»: автор знал о них. А раз так — их отсутствие тоже информация.

## Что искать в первую очередь

Просматривая вывод `exiftool`, не читай всё подряд — ищи по приоритету:

1. **GPS-координаты** — прямое указание места (`GPSPosition`, `GPSLatitude`).
2. **Автор и организация** — `Artist`, `Author`, `Copyright`, `Company`.
3. **Программа и устройство** — `Software`, `Make`, `Model`.
4. **Даты** — `DateTimeOriginal` (съёмка), `CreateDate`, `ModifyDate` (правка).
5. **Комментарии и описания** — `Comment`, `ImageDescription`, `UserComment`
   (там часто прячут флаги).

Приём: если полей слишком много, отфильтруй только подозрительные:

```bash
$ exiftool holiday.jpg | grep -iE 'GPS|Author|Comment|Software|Date'
```

А если метаданных вообще нет — это тоже результат: файл «чистили», и, возможно,
именно поэтому он попал в задачу.

## Метаданные и время: маленькая улика

Метки времени в метаданных часто противоречат друг другу, и это само по себе
подсказка. Например:

```bash
$ exiftool photo.jpg | grep -iE 'Date'
Create Date                     : 2024:06:14 09:12:33
Modify Date                     : 2024:06:15 23:58:01
```

Снимок «создан» 14 июня, а изменён 15-го — значит, файл редактировали. Если при
этом `Software` показывает редактор, картина складывается: исходное фото
обрабатывали. Такие несоответствия помогают восстанавливать историю файла, когда
содержимое уже ничего не говорит.

## Метаданные за пределами картинок

Полезно помнить, что «метаданные» — это не только EXIF. Практически у любого формата
есть свой блок свойств, и все они читаются одним `exiftool`:

- **Офисные документы** (`docx`/`xlsx`) — автор, компания, время правки, иногда
  сохранённый путь к файлу на компьютере автора.
- **PDF** — программа-создатель (`Producer`), автор, даты; можно вытащить даже
  встроенные шрифты и вложения.
- **Аудио/видео** — ID3-теги, кодек, устройство записи.
- **Архивы** — комментарии, даты упаковки, имена инструментов.

Поэтому `exiftool` ставят «на всё» — это универсальный инструмент чтения свойств.

Метаданные — самый дешёвый способ узнать о файле то, чего не видно снаружи.

## Что мы теперь знаем

- Метаданные — сведения о файле: автор, дата, устройство, координаты.
- `exiftool` читает их по умолчанию без изменений; `-a -u -g1` покажет всё.
- EXIF-координаты переводятся в десятичные градусы и дают точку на карте.
- Метаданные есть у PDF, Office, PNG, аудио — везде ищи автора и программу.
- Метаданные подделываются и служат для сокрытия — сверяй с другими источниками.

## Практический разбор: цепочка улик из EXIF

Допустим, есть `holiday.jpg` с GPS-координатами. Порядок разбора:

```bash
exiftool holiday.jpg
exiftool -a -u -g1 holiday.jpg     # все теги, включая дубликаты и скрытые
exiftool -GPSLatitude -GPSLongitude -n holiday.jpg   # числовые значения
```

`-n` печатает координаты в десятичных градусах — их можно сразу вставить в карту. Дальше связываем: `Make`/`Model` (камера), `DateTimeOriginal` (когда снято), `Software` (чем обрабатывали — редактор может выдать монтаж), `ThumbnailImage` (старое встроенное превью, часто с исходными метаданными, даже если их «почистили» в основном изображении).

Ключевая идея: **метаданные могут противоречить друг другу**. Если `DateTimeOriginal` не совпадает с `ModifyDate`, а `Software` содержит редактор — это сигнал, что файл правили, и улику нужно перепроверить.

## Инструменты и команды

| Задача | Инструмент |
|---|---|
| чтение/запись EXIF | exiftool |
| извлечь встроенное превью | `exiftool -b -ThumbnailImage` |
| «сырые» сегменты JPEG | `xxd file.jpg`, `binwalk file.jpg` |
| проверить скрытые теги | `exiftool -a -u -g1` |
| массово снять метаданные | `exiftool -r dir/` |

Если теги выглядят «слишком аккуратно», проверь файл на стеганографию — метаданные часто служат лишь приманкой, а данные спрятаны в пикселях.

## Если не сработало

- **Метаданных нет:** их могли вырезать (`exiftool -all=`) — ищи встроенное превью и остатки в маркерах JPEG.
- **Координаты нулевые:** GPS-тег есть, но обнулён — проверь `GPSDateStamp` и направление (`GPSLatitudeRef`).
- **Файл «пересохранён»:** соцсети и мессенджеры чистят EXIF; ищи оригинал в кэше или бэкапах.
- **exiftool ругается на формат:** определи реальный тип по magic bytes (`file`, `xxd`), а не по расширению.

## Поля EXIF, которые выдают больше всего

В EXIF десятки тегов, но для расследования важнее всего несколько групп:

- **Make/Model** — производитель и модель камеры/телефона; часто однозначно указывает устройство;
- **Software** — прошивка камеры или редактор (Photoshop, GIMP, exiftool — значит, файл правили);
- **DateTimeOriginal / CreateDate / ModifyDate** — время съёмки и правок; расхождение выдаёт редактирование;
- **GPSLatitude/GPSLongitude/GPSAltitude** — координаты и высота; высота помогает отличить этаж/крышу;
- **LensModel, FNumber, ExposureTime, ISO** — оптика и настройки; полезно для проверки, одним ли аппаратом сделаны снимки;
- **OwnerName/Artist/Copyright** — автор и организация;
- **SerialNumber / InternalSerialNumber** — серийник камеры; связывает разные фото с одним устройством;
- **UserComment/ImageDescription** — свободное поле; классическое место для спрятанного флага.

Полезно знать, где EXIF **не** сохраняется: мессенджеры и соцсети часто вырезают метаданные при загрузке — поэтому «чистый» файл из чата ничего не доказывает.

## Как читать метаданные пачкой и по формату

Один файл — просто; задача начинается, когда их сотни. Полезные приёмы:

```bash
# рекурсивно по каталогу, только нужные поля
$ exiftool -r -GPSPosition -DateTimeOriginal -Make -Model -Software . | head -40
# CSV для дальнейшего анализа
$ exiftool -csv -r . > meta.csv
# только файлы с GPS
$ exiftool -if '$GPSLatitude' -p '$FileName $GPSPosition' -r .
```

По форматам: у **PNG** — чанки `tEXt`/`iTXt`/`zTXt` (иногда сжатые — `zTXt`); у **PDF** — `Author`/`Producer`/`Creator`, а также встроенные вложения и скрытые слои; у **Office** — `docProps/core.xml` и `docProps/app.xml` (распаковать как zip); у **аудио** — ID3 (v2.3/v2.4), у **видео** — контейнерные теги и субтитры.

Отдельный трюк — искать **склеенные/дописанные** данные: после корректного EOF у JPEG/PNG может лежать второй файл (`binwalk`, `foremost`, сравнение реального размера и заявленного). `exiftool` тут не поможет — нужен побайтовый взгляд.

## Практика: геолокация по фото

Полный маршрут «фото → место»:

1. **Прочитай GPS**: `exiftool -GPS* photo.jpg`; если координаты в DMS, переведи в десятичные градусы.
2. **Проверь знак**: `GPSLatitudeRef` S/W означает отрицательные значения — иначе уедешь в другую точку.
3. **Открой на карте**: вставь `lat, lon` (Google Maps, OpenStreetMap); свериться с картой важнее, чем с «центром города» из округления.
4. **Сверь с другими сигналами**: время съёмки (часовой пояс), погода, тени, вывески, номера домов.
5. **Зафиксируй неопределённость**: GPS в телефоне может врать на десятки метров, а высота — сильнее; указывай радиус, а не точку.

Если GPS нет — геолокация делается по визуальным признакам (вывески, архитектура, растительность) плюс метаданным времени; это уже классический гео-OSINT, но метаданные всегда проверяются первыми.

## Куда дальше

Метаданные — это «паспорт» отдельного файла. Дальше мы спустимся на уровень глубже —
к **файловым системам**: как из целого образа диска достать список всех файлов, в том
числе удалённых, и вытащить их содержимое. А пока запомни: **прежде чем разбирать
содержимое, посмотри на свойства — там часто уже есть ответ**.

## Где пригодится

- **CTF:** задачи на скрытые метаданные и геолокацию.
- **OSINT:** определение места съёмки по фото.
- **Incident Response:** атрибуция документов, поиск автора утечки.
- **Digital forensics:** сопоставление артефактов по времени создания.
- **Журналистика/расследования:** проверка подлинности присланных файлов.
