XFS — высокопроизводительная журналируемая ФС, по умолчанию в RHEL/CentOS и многих дистрибутивах, и типичная ФС больших серверных томов. Для форензика она интересна тем, что **масштабируется через allocation groups (AG)**: том делится на независимые области, каждая со своими метаданными. Это даёт параллелизм, но усложняет анализ: суперблок, inode и B-деревья нужно искать **по AG**, а не по «глобальному» смещению.

## Суперблок и его копии

XFS-том начинается с магии `XFSB` (offset 0). Суперблок — главная структура; его копии разбросаны по AG (`sb` в начале каждой AG).

| Смещение | Размер | Поле |
|---------:|-------:|------|
| 0x00 | 4 | magic `XFSB` |
| 0x04 | 4 | blocksize (обычно 4096) |
| 0x08 | 8 | dblocks (размер в блоках) |
| 0x10 | 8 | rblocks |
| 0x18 | 8 | rextents |
| 0x20 | 16 | uuid |
| 0x30 | 8 | logstart (блок начала журнала) |
| 0x38 | 8 | rootino (корневой inode) |
| 0x40 | 8 | rbmino |
| 0x48 | 8 | rsumino |
| 0x50 | 4 | rextsize |
| 0x54 | 4 | agblocks (блоков в одной AG) |
| 0x58 | 4 | agcount (число AG) |
| 0x5C | 4 | rbmblocks |
| 0x60 | 4 | logblocks |
| 0x64 | 2 | versionnum |
| 0x66 | 1 | sectsize (обычно 512) |
| 0x68 | 1 | inodesize (256 или 512) |
| 0x6A | 2 | inopblock (inode на блок) |

`agcount` и `agblocks` — ключ к навигации: том = agcount × agblocks блоков. AG начинается с сектора суперблока (копия), затем AGF/AGI/AGFL и B-деревья свободного места и inode.

## Allocation groups и inode

В каждой AG есть:
- **AGF** (AG Free space) — заголовок свободного места и корни B-деревьев.
- **AGI** (AG Inode) — заголовок inode и корни B-деревьев inode.
- **AGFL** (AG Free List) — список свободных блоков.

**Inode** в XFS — не таблица, а структура фиксированного размера (256/512 байт) в специальных блоках. Номер inode кодируется: `ino = (agno << agino_log) | agino`. Диапазон данных задаётся через **extents** (в v5 — B-дерево extents прямо в inode).

Заголовок inode (v3, v5):

| Смещение | Размер | Поле |
|---------:|-------:|------|
| 0x00 | 2 | magic `IN` (0x494E) |
| 0x02 | 2 | mode (тип + права) |
| 0x04 | 1 | version |
| 0x05 | 1 | format |
| 0x08 | 4 | nlink |
| 0x10 | 4 | uid |
| 0x14 | 4 | gid |
| 0x30 | 8 | size (размер файла) |
| 0x38 | 8 | nblocks |
| 0x50 | 4 | nextents |
| 0x58 | — | atime/mtime/ctime (v3 — 64-бит nanoseconds) |

## Каталоги и B-деревья

Каталог в XFS — это набор блоков с **directory entries** (shortform внутри inode для маленьких, block/leaf/node для больших). Имя + inode + тип хранятся в записи `xfs_dir2_*`. B-дерево extents описывает, в каких блоках лежат данные файла. Для форензика важно: **удалённый inode** может сохранить extents (данные) и `mode`, но `nlink` = 0 и запись в каталоге удалена.

```bash
# Низкоуровневый просмотр
xfs_db -r -c "sb 0" -c "print" disk.img        # суперблок
xfs_db -r -c "agf 0" -c "print" disk.img       # AGF
xfs_db -r -c "inode <num>" -c "print" disk.img # разбор inode
xfs_info disk.img                              # сводка ФС
```

## Инструменты и флаги

```bash
# Определение и параметры
fsstat -o <offset> disk.img | head -40
xfs_info disk.img

# Листинг/восстановление (sleuthkit поддерживает XFS)
fls -o <offset> -r disk.img
fls -o <offset> -r -d disk.img
icat -o <offset> disk.img <inode> > out.bin

# Монтирование read-only
sudo mount -o ro,loop,offset=<bytes> disk.img /mnt/xfs

# xfs_repair в режиме no-modify для проверки
xfs_repair -n disk.img
```

## Разобранный пример: файл из XFS-тома

```bash
$ fsstat -o 2048 disk.img | sed -n '1,14p'
FILE SYSTEM INFORMATION
File System Type: XFS
Volume Name:
File System Type: XFS
Block Size: 4096
Inode Size: 256
$ fls -o 2048 -r -d disk.img
r/r * 131: data/report.pdf
$ icat -o 2048 disk.img 131 > report.pdf
$ file report.pdf
report.pdf: PDF document, version 1.4
```

Inode 131 читается по `(agno, agino)`; sleuthkit сам раскладывает номер. Данные — по extents, сохранённым в inode.

## Краевые случаи и подводные камни

- **Навигация по AG.** «Абсолютный» блок данных = agno·agblocks + блок внутри AG. Прямой dd по смещению без учёта AG даст мусор.
- **V5 и CRC.** В XFS v5 метаданные защищены CRC и UUID; при ручном разборе нужно проверять self-describing заголовки.
- **Журнал (logstart).** Журнал метаданных может содержать старые значения — источник удалённых inode, но требует отдельного парсера (`xfs_logprint`).
- **Shortform-каталоги.** Маленькие каталоги хранятся прямо в inode; их не найти «по блокам».
- **Sparse-файлы.** extents не покрывают всю длину — читайте по карте extents, а не последовательно.
- **Inline xattr/ACL.** Атрибуты могут лежать в inode или в отдельном блоке (`attr1/attr2`).
- **realtime-устройство.** Если используется realtime-том, данные могут быть вне основной AG-схемы.
- **Удалённые inode.** `nlink=0` и mode может быть перезаписан; extents иногда сохраняются — проверяйте их перед выводом «не восстановится».

## Зачем XFS нужен отдельный разбор

XFS создавалась для больших серверных томов и высокой параллельной нагрузки. В отличие от ext4, где метаданные сосредоточены в начале и в inode-таблицах, XFS **распределяет их по allocation groups**: том делится на несколько независимых областей, каждая со своим суперблоком, свободным местом и inode. Это даёт масштабируемость, но означает, что «глобального» inode-пространства нет — номер inode нужно раскладывать на (AG, index).

Для аналитика это важно по трём причинам:

- **Данные файла могут лежать в другой AG**, чем inode; B-дерево extents связывает их.
- **Журнал (`logstart`)** хранит старые значения метаданных — источник информации об удалённых inode.
- **Self-describing метаданные v5** содержат UUID и CRC: подделанные/повреждённые структуры легко отличить.

## Практика с xfs_db

`xfs_db` — низкоуровневый интерактивный инструмент. Всегда запускайте с `-r` (read-only), чтобы не изменить образ.

```bash
# Суперблок
xfs_db -r -c "sb 0" -c "print" disk.img
# Копия суперблока во второй AG
xfs_db -r -c "sb 1" -c "print" disk.img
# Заголовок свободного места AG 0
xfs_db -r -c "agf 0" -c "print" disk.img
# Заголовок inode AG 0
xfs_db -r -c "agi 0" -c "print" disk.img
# Разбор конкретного inode (номер в десятичном виде)
xfs_db -r -c "inode 131" -c "print" disk.img
# B-дерево extents inode
xfs_db -r -c "inode 131" -c "bmap -v" disk.img
```

Поля вывода `inode`: `magicnum` (0x494e), `mode` (тип файла + права), `version`, `format` (local/extents/btree), `nlink`, `size`, `nblocks`, `nextents`. Если `format=extents`, сами экстенты лежат в inode; если `btree` — в отдельном блоке.

## Разбор журнала

Журнал XFS (`logstart`) — кольцевой буфер транзакций метаданных. Он содержит **предыдущие** версии блоков: удалённые inode, старые записи каталогов, прежние extents. Парсер:

```bash
xfs_logprint disk.img | head -100
# или через мета-утилиты
xfs_metadump disk.img meta.img   # дамп метаданных (без данных файлов)
```

`xfs_metadump` создаёт образ только метаданных — удобно для обмена и анализа без утечки содержимого. Затем его можно разбирать теми же инструментами.

## extents, sparse и inline-данные

- **Extents-формат** (маленькие/средние файлы): карта блоков прямо в inode.
- **B-tree-формат** (большие/фрагментированные): корень B-дерева в inode, листья — в отдельных блоках.
- **Sparse-файлы**: extents покрывают не всю длину; «дыры» читаются как нули.
- **Inline-данные** (v5): очень маленькие файлы и symlink хранятся прямо в inode (data fork), без отдельных блоков.
- **Extent size hints**: `rextsize` и `extsize` влияют на аллокацию, но не мешают чтению через extents.

## Типичные ошибки

- **Прямое dd по «номеру inode»** — номер inode не является байтовым смещением; нужно раскладывать на AG.
- **Игнорирование AG** при ручном поиске суперблока: копии суперблока идут с шагом `agblocks`.
- **Чтение v5-метаданных без проверки CRC** — повреждённую структуру легко принять за валидную.
- **Работа с журналом на смонтированной ФС** — журнал меняется; только образ.
- **Путаница block size и sector size** — `blocksize` обычно 4096, `sectsize` 512; смещения считайте в блоках там, где инструмент ждёт блоки.

## Что дальше / решение

1. `fsstat`/`xfs_info` — block size, inode size, agcount.
2. `fls -r -d` — найти удалённые inode.
3. `icat` — прочитать по extents.
4. Для глубокого разбора — `xfs_db` (inode/AGF/AGI).
5. Не вышло — carving по сигнатурам.

Дальше — `forensics-hfsplus` для macOS-томов и `forensics-lvm`, если XFS лежит на логическом томе LVM.
