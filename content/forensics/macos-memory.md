## Вопрос, с которого всё начинается

Память — самый быстро исчезающий источник улик: пароли, ключи, расшифрованные данные,
следы вредоносного ПО. Но на macOS снять память сложнее, чем на Windows/Linux.
Разберёмся, как и что искать.

## Наш пример: сбор памяти

## Шаг 1: инструменты

Классический путь — **osxpmem** (Portable Memory):

```
$ sudo osxpmem -o /evidence/mac.raw
Acquiring memory...
```

Альтернативы: `AVML`, средства коммерческих платформ. На Apple Silicon вариантов
меньше — часть ограничена Secure Boot/SIP.

## Шаг 2: что сразу видно

Даже простой `strings`/`grep` по дампу даёт результаты:

```
$ strings mac.raw | grep -i 'http://' | head
http://203.0.113.5/upd.bin
```

Адрес C2, команды, URL — всё это живёт в памяти, даже если файлы на диске подчищены.

## Шаг 3: артефакты в памяти

- **процессы** и их командные строки;
- **открытые файлы и сокеты**;
- **пароли и ключи** (особенно в незашифрованном виде);
- **расшифрованные данные** из шифрованных томов;
- **код вредоносного ПО**, который был только в памяти (fileless).

## Шаг 4: анализ

Для macOS-дампов используют Volatility (профили macOS ограничены) и платформенные
парсеры. Базовый подход — извлечь строки, процессы и сетевые индикаторы:

```
$ strings mac.raw | grep -E 'POST /|Authorization:' | head
```

А ещё — `bstrings` для UTF-16 и поиск конкретных IOC.

## Шаг 5: фиксируй порядок

Сбор памяти меняет систему (запускает инструмент). Поэтому:

1. зафиксируй время и версию ОС;
2. снимай память **до** выключения;
3. считай хеш дампа сразу;
4. опиши, отключал ли SIP и почему.

## Что мы теперь знаем

- Память даёт пароли, ключи и fileless-код.
- `osxpmem`/`AVML` — средства сбора на macOS.
- `strings`/`grep` дают быстрые IOC.
- Volatility поддерживает macOS ограниченно.
- Сбор меняет систему — фиксируй это в отчёте.

## Если не сработало

- Apple Silicon ограничивает сбор? Используй живые средства и логи.
- Нет прав? Нужен root и отключённый SIP.
- Дамп огромный? Сначала `strings`, потом целевой анализ.

## Способы получить память macOS

Захват RAM на macOS сложнее, чем на Windows: система не даёт просто так читать физическую
память. Основные пути:

1. **Инструмент захвата** — `osxpmem` (старый, требует kext), или современный
   **MAC Memory Reader**, работающий через драйвер;
2. **Файл гибернации** — `/var/vm/sleepimage` содержит образ памяти при переходе в сон;
3. **Снимок виртуальной машины** — если macOS в VM, память лежит в `.vmem` файле;
4. **Крэш-дамп ядра** — `/Library/Logs/DiagnosticReports/` и `/cores/`.

```
$ ls -la /var/vm/
-rw------  1 root  wheel  17179869184  sleepimage
swapfile0  swapfile1
```

`sleepimage` размером в объём RAM — это фактически полный образ физической памяти на момент
сна. Самый доступный источник без установки драйверов.

## Что сразу видно в памяти

Даже без глубокого анализа в памяти видны:

- **список процессов** — включая те, что уже завершились, но остались в кэше;
- **сетевые соединения** — IP, порты, состояние;
- **загруженные kext** — ядровые расширения (аналог драйверов);
- **открытые файлы** и командные строки;
- **следы bash/zsh** — история команд, переменные окружения.

Командные строки процессов — часто самый ценный артефакт: они показывают, что именно
запускали (`curl http://... | sh`, `python -c "..."`).

## Анализ через Volatility 3

Volatility 3 работает с macOS-образами через профиль, определяемый автоматически:

```
$ vol -f mac.mem mac.pslist | head
PID    PPID   COMM
1      0      launchd
123    1      bird
4321   1      suspicious
$ vol -f mac.mem mac.netstat
$ vol -f mac.mem mac.bash
$ vol -f mac.mem mac.kexts
```

`mac.bash` восстанавливает историю команд из памяти — она может отличаться от файла
`.zsh_history`, если его подчистили. `mac.netstat` показывает соединения, включая уже
закрытые (время ожидания сокета).

## Таблица: плагины Volatility для macOS

| Плагин | Что извлекает | Применение |
|---|---|---|
| `mac.pslist` | список процессов | найти подозрительный процесс |
| `mac.pstree` | дерево процессов | родитель-ребёнок |
| `mac.netstat` | сетевые соединения | C2-связи |
| `mac.bash` | история команд | действия атакующего |
| `mac.kexts` | загруженные расширения | руткиты |
| `mac.lsof` | открытые файлы | файлы в работе |
| `mac.malfind` | инъекции кода | невидимый код |
| `mac.ifconfig` | сетевые интерфейсы | IP, MAC |

`mac.malfind` ищет исполняемые страницы памяти, не привязанные к файлу на диске — типичный
признак инъекции (в т.ч. fileless-малвари, живущей только в памяти).

## Практический сценарий

Задача: найти вредоносный процесс, которого уже нет на диске. Идём по шагам:

1. `mac.pslist` — ищем процессы с подозрительными именами или несуществующими файлами;
2. `mac.netstat` — проверяем, есть ли у процесса соединение наружу;
3. `mac.malfind` — ищем исполняемую память без файла;
4. `mac.bash` — восстанавливаем команды, которые его запустили.

```
$ vol -f mac.mem mac.malfind | grep -A3 -i 'suspicious'
```

Найденные страницы можно выгрузить (`--dump`) и проанализировать как отдельный код.

## Гибернация: обратная сборка

`sleepimage` — это не «сырой» дамп, а образ со сжатыми страницами. Volatility умеет его
разбирать напрямую, но иногда нужно преобразовать формат. Для старых версий применяли
скрипты распаковки hibernation-образа. Для новых macOS образ может быть зашифрован вместе с
FileVault — тогда нужен ключ тома.

## Ограничения

Во-первых, **целостность**: любой захват меняет память, поэтому фиксируй порядок и хеши.
Во-вторых, современные macOS усилили защиту (SIP, hardened runtime), и некоторые регионы
памяти недоступны даже root. В-третьих, `sleepimage` отражает момент **сна**, а не момент
инцидента — если машина работала, данных может не быть. В-четвёртых, без keychain часть
данных процессов зашифрована. И помни: выключение машины **уничтожает** память — первое
действие при живом инциденте это захват, а не перезагрузка.

## Если сработало: что зафиксировать

Запиши хеш образа, версию ОС, время захвата и список извлечённых индикаторов (процессы, IP,
команды, выгруженные страницы). Дамп памяти — «одноразовая» улика: её нельзя воспроизвести
после выключения машины, поэтому фиксируй всё сразу и подробно.

## Сбор памяти без остановки системы

Живой захват требует драйвера, поэтому важен порядок и минимальное вмешательство. Типовой
план:

1. зафиксировать текущее время и uptime;
2. снять список процессов и соединений «лёгкими» средствами (`ps`, `netstat`);
3. запустить инструмент захвата в память или на внешний носитель;
4. посчитать хеш образа сразу после захвата.

```
$ date -u; uptime
$ ps -axo pid,ppid,user,lstart,command > /tmp/ps.txt
$ lsof -i -n > /tmp/net.txt
$ sudo ./osxpmem -o /ext/mac.mem
$ shasum -a 256 /ext/mac.mem
```

Предварительный снимок `ps` полезен, даже если сам дамп потом не разберётся: он даёт
«моментальный слепок» системы.

## Ищем fileless-активность

Малварь, живущая только в памяти, не имеет файла на диске. Признаки в дампе:

- исполняемая память процесса, не связанная с файлом (`mac.malfind`);
- процесс с родителем, которого уже нет (`PPID` не существует);
- код в регионе `rwx` (чтение-запись-исполнение);
- подозрительные строки прямо в памяти процесса (`strings` по дампу).

```
$ strings -n 8 mac.mem | grep -iE 'http://|/bin/sh|eval\(' | head
http://185.220.101.5/beacon
```

Простой `strings` по всему дампу часто находит URL и команды быстрее, чем полноценный анализ.

## Скрытые и переименованные процессы

Атакующие маскируют процессы под системные (`launchd`, `kernel_task`) или скрывают их через
хуки системных вызовов. В памяти такие процессы видны, потому что структуры ядра остаются:

```
$ vol -f mac.mem mac.pslist | grep -iE 'launchd|kernel' 
1      0      launchd
1      0      launchd        # дубль! подозрительно
```

Дубль процесса с тем же именем и PID-ом родителя `0` — красный флаг. Сравни список процессов
из памяти со списком на диске: **расхождение** и есть сокрытие.

## Сетевые артефакты и C2

`mac.netstat` показывает соединения с адресами и PID-ами. Ищем соединения процессов, которых
нет на диске, и адреса, не относящиеся к бизнес-инфраструктуре:

```
$ vol -f mac.mem mac.netstat | awk '$5=="ESTABLISHED"{print $1,$2,$3,$4,$5}'
suspicious  4321  tcp  10.0.0.57:51422  185.220.101.5:8443  ESTABLISHED
```

Соединение на нестандартный порт с «серого» IP — кандидат на C2.

## Таблица: сигналы в памяти

| Сигнал | Значение | Действие |
|---|---|---|
| процесс без файла | fileless | выгрузить память |
| PPID не существует | родитель удалён | искать историю |
| регион RWX | самомодификация | дамп страницы |
| дубли системных процессов | маскировка | сравнить с диском |
| ESTABLISHED на внешний IP | C2/эксфильтрация | сопоставить с логами |
| команда `curl ... | sh` | доставка | искать URL |

## Ограничения

Память — «одноразовая» улика: после выключения её не восстановить, а каждый запуск
инструмента её меняет. Volatility требует **правильного профиля** — неверный даст мусор.
Новые версии macOS с SIP могут блокировать чтение части регионов. И не забывай: захват
памяти без фиксации хешей легко оспорить как «изменённый».

## Если сработало: доказательная цепочка

Соедини три факта: процесс в памяти (имя, PID, командная строка), его сетевое соединение, и
отсутствие файла на диске. Три вместе — доказательство fileless-компромисса. Выгруженные
страницы и хеш образа приложи к отчёту как артефакты.
