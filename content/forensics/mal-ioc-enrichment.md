## Вопрос, с которого всё начинается

Ты извлёк из образца IP, домен и хеш. Это **IOC** — индикаторы компрометации. Но сами
по себе они мало значат: нужно понять, что за ними стоит. Это называется
**обогащение**. Разберём.

## Наш пример: набор IOC

## Шаг 1: типы IOC

- **хеши** (MD5/SHA256 файла);
- **домены и URL**;
- **IP-адреса**;
- **строки** (мутексы, ключи реестра);
- **правила YARA/Sigma**.

```
$ sha256sum sample.bin
a1b2c3...  sample.bin
```

## Шаг 2: репутация файла

Хеш проверяем в VirusTotal:

```
$ curl -s "https://www.virustotal.com/api/v3/files/a1b2c3..." -H "x-apikey: $VT_KEY" | head
```

Ответ даёт семейство, детекты AV, первый/последний раз, связи с другими образцами.

## Шаг 3: репутация сети

IP/домен:

```
$ whois 203.0.113.5 | grep -iE 'orgname|netname'
```

Смотрим ASN, геолокацию, хостинг. Часто C2 — на VPS с «серой» репутацией.

## Шаг 4: обогащение через платформы

- **MISP** — база IOC с корреляциями;
- **AlienVault OTX** — пульсы по угрозам;
- **Passive DNS** — история домена;
- **Shodan/Censys** — что ещё на этом IP.

Так одиночный индикатор превращается в «кампанию»: тот же C2, тот же сертификат, та же
инфраструктура.

## Шаг 5: применение

- **блокировка** — firewall/DNS/AV;
- **hunting** — поиск IOC по логам (SIEM);
- **отчёт** — контекст и уровень уверенности;
- **TTL** — у IOC есть срок жизни (инфраструктура меняется).

## Что мы теперь знаем

- IOC бывают файловые, сетевые, поведенческие.
- Хеш/домен проверяют в VT/OTX/MISP.
- Passive DNS и Shodan дают контекст.
- Обогащение связывает образец с кампанией.
- У IOC есть срок жизни — указывай дату и уверенность.

## Если не сработало

- Нет доступа к VT? Используй локальные базы.
- IOC «протух»? Ищи похожие по инфраструктуре.
- Нужно правило? Пиши YARA/Sigma по извлечённым строкам.
