Магические байты (magic bytes) — это короткая последовательность байтов в начале файла, по которой операционная система и утилиты понимают его реальный тип, независимо от расширения. В форензике это первый и самый дешёвый шаг триажа: расширение можно переименовать или подделать, а сигнатура в большинстве форматов жёстко зашита в структуре. Умение читать сигнатуры вручную отличает аналитика, который «верит `file`», от того, кто может доказать, что перед ним на самом деле и где спрятаны вложенные данные.

## Зачем это нужно

Атакующий часто маскирует полезную нагрузку: `invoice.pdf.exe`, картинка `photo.jpg`, которая на самом деле ZIP, или PE-файл с заголовком PNG. При триаже важно быстро классифицировать сотни файлов, а при глубоком анализе — найти истинную природу артефакта. Кроме того, форматы-контейнеры (ZIP, PDF, OLE, PNG) позволяют прятать данные внутри: магические байты и смещения сигнатур — ключ к их извлечению. Наконец, повреждённый или обрезанный файл с правильной сигнатурой можно «починить», восстановив заголовок.

## Инструмент file и его база

`file` читает несколько первых байтов и сверяет их с базой `/usr/share/misc/magic.mgc` (исходники — `/usr/share/file/magic/`). Ключевые флаги:

| Флаг | Назначение |
|------|-----------|
| `-b` | только тип, без имени файла |
| `-i` | вывести MIME-тип (`image/png`) |
| `--mime-type` | только MIME |
| `--mime-encoding` | только кодировку |
| `-k` | не останавливаться на первом совпадении (показать все) |
| `-z` | заглянуть внутрь сжатых файлов |
| `-s` | читать block/char-устройства |
| `-f list.txt` | пакетная проверка списка файлов |
| `-e` | отключить/включить тесты (`-e elf`, `-e soft`) |

```bash
$ file -k suspicious.bin
suspicious.bin: PNG image data, 1920 x 1080, 8-bit/color RGBA, non-interlaced
- Zip archive data, at least v2.0 to extract
```

Флаг `-k` здесь критичен: файл одновременно PNG и ZIP — классический полиглот.

## Ручной просмотр: xxd и hexdump

`file` — это гипотеза; доказательство даёт hex-просмотр. `xxd` и `hexdump` показывают смещение, hex и ASCII-представление.

```bash
$ xxd -l 64 photo.jpg
00000000: 8950 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR
00000010: 0000 0780 0000 0438 0806 0000 00bd 9f3c  .......8.......<
```

`89 50 4E 47 0D 0A 1A 0A` — это PNG, а не JPEG (у JPEG начало `FF D8 FF`). Полезные флаги:

| Команда | Назначение |
|---------|-----------|
| `xxd -l N` | первые N байт |
| `xxd -s OFFSET` | начать со смещения (можно `-s -N` — от конца) |
| `xxd -c 32` | по 32 байта в строке |
| `xxd -g 1` | группировать по 1 байту |
| `xxd -p` | «plain» hex без адресов и ASCII |
| `xxd -r` | обратно из hex в бинарь |
| `hexdump -C` | канонический вывод (hex+ASCII) |
| `hexdump -n 32 -e '"%04_ax  " 16/1 "%02x " "\n"'` | произвольный формат |

Поиск сигнатуры по всему файлу — не глазами, а через `grep -abo` или `xxd -p | grep`:

```bash
$ grep -aboP '\x89PNG\r\n\x1a\n' photo.jpg
0
$ grep -aboP 'PK\x03\x04' photo.jpg
4096
```

## Полиглоты и встроенные данные

Полиглот — файл, валидный сразу для нескольких форматов. Частые приёмы:

- **PNG + ZIP**: картинка читается, а после конца PNG-чанков (`IEND`) лежит ZIP (`PK\x03\x04`). `binwalk` найдёт вторую сигнатуру.
- **GIFAR**: GIF, внутри которого Java-архив.
- **PDF-полиглот**: `%PDF` в начале, но перед ним ещё допустимы байты, поэтому `%PDF` может быть не по нулевому смещению.

```bash
$ binwalk photo.jpg
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             PNG image, 1920 x 1080, 8-bit/color RGBA
1245380       0x1300C4        Zip archive data, at least v2.0 to extract
1245700       0x1301C4        End of Zip archive
```

## Повреждённые заголовки и восстановление

Если файл не открывается, сравните его первые байты с эталоном. Классика CTF — испорченный PNG: правильная сигнатура `89 50 4E 47 0D 0A 1A 0A`, но кто-то поменял `0D 0A` на `0A 0D`. Починка — записать корректные байты:

```bash
# записать правильную сигнатуру в начало
printf '\x89PNG\r\n\x1a\n' | dd of=broken.png bs=1 count=8 conv=notrunc
```

Для JPEG проверьте `FF D8 FF` в начале и `FF D9` в конце; отсутствие EOI (`FF D9`) означает обрезанный файл. Для ZIP поле длины может быть подделано — `zip -FF broken.zip --out fixed.zip` перестроит центральный каталог.

## Автоматический триаж

```bash
# тип всех файлов в дереве, машиночитаемо
find ./evidence -type f -print0 | xargs -0 file -i > types.txt
# только MIME, отсортировать по частоте
cut -d: -f2 types.txt | sort | uniq -c | sort -rn
# сигнатуры и вложенные данные
binwalk -e -M suspicious.bin   # -e извлечь, -M рекурсивно
```

`binwalk -e` извлекает всё, что распознал; `-M` спускается во вложенные образы. `foremost`/`scalpel` режут по сигнатурам, когда структуры нет.

## Разобранный пример

Дан `challenge.bin`. Определяем тип и находим скрытое:

```bash
$ file challenge.bin
challenge.bin: GIF image data, version 89a, 320 x 240
$ xxd -l 16 challenge.bin
00000000: 4749 4638 3961 0f00 0a00 f700 00    GIF89a........
$ grep -aboP 'PK\x03\x04' challenge.bin
8244
$ dd if=challenge.bin of=hidden.zip bs=1 skip=8244 status=none
$ unzip -o hidden.zip
Archive:  hidden.zip
  inflating: secret.txt
$ cat secret.txt
CTF{magic_bytes_matter}
```

Сначала GIF-заголовок, но `grep` нашёл ZIP по смещению 8244, а `dd` вырезал его без перекодирования (`bs=1` + `skip` в байтах).

## Частые ошибки

- **Верить расширению.** `.jpg` может быть чем угодно; всегда проверяйте `file -k`.
- **Обрезать вывод `file` без `-k`.** Пропустите вторую сигнатуру полиглота.
- **Путать смещение в hex и десятичное.** `xxd` показывает hex-смещение, `grep -abo` — десятичное.
- **Искать сигнатуру глазами.** На больших файлах используйте `grep -aboP` или `binwalk`.
- **Править файл без копии.** Для восстановления работайте с копией и хешируйте оригинал.
- **Забывать про регистр.** `grep -P` без `-i` не найдёт `%pdf`, если он в нижнем регистре.

## Что дальше / решение

Определив тип, переходите к соответствующему разбору: архивы — `forensics-archives`, извлечение вложенного — `forensics-carving`, метаданные — `forensics-metadata`, hex-редактирование — `forensics-hex-editors`. Универсальный рецепт: `file -k` → `xxd -l 64` → `grep -aboP` по сигнатурам → `binwalk -e` → `dd`/`foremost` по найденному смещению.

## Где пригодится

- **CTF:** половина задач Forensics решается на этом шаге.
- **Malware analysis:** определение истинного формата образца — первый шаг.
- **SOC:** триаж подозрительных вложений из почты.
- **Pentest:** анализ дампов и необычных файлов на скомпрометированных хостах.
- **Восстановление данных:** понимание структур при работе с повреждёнными носителями.
