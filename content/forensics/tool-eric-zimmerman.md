## Вопрос, с которого всё начинается

Windows хранит десятки бинарных артефактов: MFT, Prefetch, Amcache, журналы. Разбирать их
руками больно. Есть набор бесплатных инструментов, который делает это быстро и единообразно
— **EZ Tools** Эрика Циммермана. Что в него входит и что даёт каждый инструмент?

## Наш пример: вывод PECmd

Перед нами CSV-файл `PECmd_out.csv` — результат работы **PECmd** по файлам Prefetch. Prefetch
— механизм Windows, ускоряющий запуск программ; попутно он фиксирует, **что и сколько раз
запускалось**. Разберём вывод.

## Шаг 1: что такое EZ Tools

EZ Tools — набор утилит командной строки (и GUI) для парсинга Windows-артефактов в
читаемый вид (CSV/JSON). Главные:

| Инструмент | Что парсит |
|------------|-----------|
| `MFTECmd` | `$MFT` (файловая система NTFS) |
| `PECmd` | Prefetch (запуски программ) |
| `AmcacheParser` | Amcache.hve (история исполняемых файлов) |
| `AppCompatCacheParser` | ShimCache (совместимость приложений) |
| `EvtxECmd` | журналы событий EVTX |
| `JLECmd` | Jump Lists (недавние файлы) |
| `LECmd` | LNK-файлы (ярлыки) |
| `SBECmd` | Shellbags (папки в проводнике) |
| `RECmd` | реестр по batch-файлам |
| `SrumECmd` | SRUM (использование ресурсов) |

## Шаг 2: читаем Prefetch

```
$ PECmd.exe -f POWERSHELL.EXE-1.pf --csv out
```

В CSV мы видим колонки: `ExecutableName`, `RunCount`, `LastRun`, `Volume`. Из них:

- `powershell.exe` запускался 7 раз, последний — 2025-05-01 09:03:20;
- `cmd.exe` — 3 раза, в 09:03:18;
- `updater.exe` — 1 раз, в 09:03:25.

Связка `cmd` → `powershell` → `updater` в течение семи секунд — классическая цепочка
заражения. Prefetch даёт **время запуска** и **число запусков**, чего нет во многих других
артефактах.

## Шаг 3: как инструменты дополняют друг друга

Один артефакт редко даёт полную картину. `PECmd` скажет «запускалось», `AmcacheParser` —
«откуда файл пришёл» (путь и хеш), `MFTECmd` — «когда файл создан на диске», `EvtxECmd` —
«какое событие при этом записано». Объединяя их в таймлайн, ты получаешь связную историю.
Именно поэтому EZ Tools используют вместе, а не по одному.

## Шаг 4: почему это удобно

Все инструменты выдают **единообразный** вывод (CSV/JSON) с одинаковым стилем колонок. Это
позволяет строить автоматические конвейеры: распарсить всё, слить в одну таблицу, отсортировать
по времени. GUI-версии (например, Timeline Explorer) открывают эти CSV и дают фильтрацию и
поиск. Для аналитика это экономит часы ручной работы.

## Шаг 5: что искать

Приоритеты: нетипичные `ExecutableName` (инструменты атакующего), редкие `RunCount`, запуски
в нерабочее время, цепочки процессов, пути в `Temp`/`AppData`, совпадение времени запуска с
сетевыми событиями. В нашем примере `updater.exe` с одним запуском сразу после PowerShell —
главный подозреваемый.

## Что мы теперь знаем

- EZ Tools — набор парсеров Windows-артефактов в CSV/JSON.
- `PECmd` даёт имя программы, число запусков и время последнего запуска.
- Инструменты дополняют друг друга и складываются в таймлайн.
- Единый формат вывода позволяет автоматизировать конвейеры.
- Ищи нетипичные программы, редкие запуски и цепочки процессов.

## MFTECmd и $MFT

**$MFT** (Master File Table) — сердце NTFS: таблица, где каждая запись описывает файл или
каталог. `MFTECmd` превращает её в читаемый CSV с колонками: имя, родительский каталог,
размер, флаги (файл/каталог/удалён), а также **четыре временные метки** NTFS: `Created0x10`,
`Modified0x10`, `Accessed0x10`, `EntryModified0x10` (и аналогичные `0x30` из `$FILE_NAME`).
Именно здесь лежит ключ к **timestomping**: если `0x10` (STANDARD_INFORMATION) и `0x30`
(FILE_NAME) времена расходятся, метки, вероятно, подделывали.

```
$ MFTECmd.exe -f "$MFT" --csv out --csvf mft.csv
```

Колонки `ParentPath`, `FileName`, `FileSize`, `IsDeleted` позволяют найти удалённые файлы и
восстановить структуру каталогов на момент снятия образа. Для следователя `$MFT` — это карта
файловой системы и основа таймлайна.

## EvtxECmd и журналы

`EvtxECmd` парсит бинарные журналы EVTX в CSV/JSON, автоматически извлекая `EventID`,
время, `Provider`, `Channel`, `UserName`, `Payload` (все поля события). Он умеет работать с
каталогом журналов целиком и с отдельным файлом:

```
$ EvtxECmd.exe -d C:\Windows\System32\winevt\Logs --csv out
```

Особенность — поддержка **maps** (файлов сопоставления) для расшифровки специфичных событий
(например, Security). С их помощью `EventID` превращаются в человекочитаемые описания. Это
сильно упрощает разбор: вместо «событие 4624» ты видишь «успешный вход в систему».

## Amcache и ShimCache

**Amcache** (`Amcache.hve`) — реестровый артефакт с историей исполняемых файлов: путь, хеш
SHA-1, время первого появления. `AmcacheParser` извлекает её в CSV. Это отвечает на вопрос
«какие программы вообще были на машине», даже если их уже удалили.

**ShimCache** (AppCompatCache) — другой артефакт совместимости, хранит записи о запускавшихся
программах. `AppCompatCacheParser` разбирает его из `SYSTEM`-хайва. ShimCache не всегда
содержит время запуска, но подтверждает факт наличия/запуска. Вместе с Prefetch (время
запуска) и Amcache (происхождение и хеш) они образуют «триаду исполнения».

## Построение таймлайна

Главная ценность EZ Tools — возможность свести все артефакты в один таймлайн. Каждый
инструмент выдаёт CSV со временем; их объединяют (например, в Timeline Explorer) и
сортируют по времени. Тогда видно последовательность: файл создан (`$MFT`), запущен
(Prefetch), зафиксирован в журнале (`EVTX`), связался с сетью (flow). Такой таймлайн —
основа отчёта об инциденте, потому что показывает не отдельные факты, а их связь во времени.

## Практический чек-лист

- Начни с `$MFT` — это карта ФС и базовый таймлайн.
- Парси Prefetch для времени запусков и счётчиков.
- Разбери EVTX для событий входа, запуска, закрепления.
- Проверь Amcache и ShimCache на присутствие/запуск программ.
- Объедини CSV в единый таймлайн и отсортируй по времени.
- Сопоставь с сетевыми и мобильными артефактами.

## SRUM, Jump Lists и Shellbags

Помимо базовых, в EZ Tools входят парсеры менее очевидных артефактов, которые часто
оказываются решающими.

**SRUM** (System Resource Usage Monitor) — база, где Windows хранит статистику
использования ресурсов приложениями: сколько сети, диска и CPU потреблял каждый процесс за
час. `SrumECmd` извлекает её в CSV. Это отвечает на вопрос «какое приложение выкачивало
данные» — по объёму сетевого трафика на процесс. Если вредонос за ночь перекачал гигабайты,
SRUM это покажет, даже если сетевые логи недоступны.

**Jump Lists** — списки недавних файлов в меню «Пуск» и на панели задач. `JLECmd` парсит
их и показывает, какие документы открывались и когда. Полезно, когда нужно доказать, что
пользователь открывал конкретный файл (например, вложение фишинга).

**Shellbags** — записи о папках, которые пользователь просматривал в проводнике.
`SBECmd` извлекает их, позволяя восстановить, к каким каталогам обращались — включая
сетевые ресурсы и съёмные носители.

## Практический сценарий разбора

Полный разбор начинается с вопроса и идёт от него к артефакту. Пример: «Что делал
подозрительный процесс?». Шаги: по Prefetch (`PECmd`) узнаём, что процесс запускался и
когда; по Amcache (`AmcacheParser`) — откуда он взялся и его хеш; по `$MFT` (`MFTECmd`) —
когда файл создан; по журналам (`EvtxECmd`) — какое событие сопровождало запуск; по SRUM
(`SrumECmd`) — сколько сети он потребил. Каждый инструмент добавляет деталь, и вместе они
дают связную историю. Именно так EZ Tools превращаются из набора утилит в методику: гипотеза
→ набор артефактов → единый таймлайн → вывод.

## Как выбирать инструмент под вопрос

Полезно держать простую карту «вопрос → артефакт → инструмент». Вопрос «что запускалось?» —
Prefetch (`PECmd`). «Откуда файл?» — Amcache (`AmcacheParser`). «Когда файл появился?» —
`$MFT` (`MFTECmd`). «Какое событие было?» — журнал (`EvtxECmd`). «Какие файлы открывали?» —
Jump Lists (`JLECmd`) и LNK (`LECmd`). «Какие папки смотрели?» — Shellbags (`SBECmd`).
«Сколько сети потребил процесс?» — SRUM (`SrumECmd`). С этой картой ты не будешь метаться:
каждый вопрос ведёт к своему инструменту, а результаты сходятся в единый таймлайн.

## Почему единый формат важен на практике

Когда артефактов десятки, а инцидентов — не один, ценность имеет не отдельный парсер, а
**согласованность**. Все EZ Tools выдают колонки с одинаковыми именами времени, что позволяет
объединять их без ручной правки. Это экономит время и снижает риск ошибки: аналитик не
переносит данные вручную, а работает с уже нормализованными таблицами. Именно поэтому набор
стал де-факто стандартом в Windows-форензике.
