## Вопрос, с которого всё начинается

Изъят образ Windows-машины. Подозрение: на ней запускали вредоносный инструмент, потом файл удалили. Задача — установить, **что здесь запускалось**, даже если самих программ на диске уже нет.

Windows оставляет следы выполнения в нескольких независимых артефактах. По отдельности каждый неполон, но вместе они дают уверенную картину. Разберём один образ по трём из них.

## Наш пример: образ Windows

Первый артефакт — **Prefetch**. Это файлы в `C:\Windows\Prefetch\*.pf`, которые Windows создаёт, чтобы ускорить запуск программ. Заодно они фиксируют **что запускалось, сколько раз и когда последний раз**. Разбирает их инструмент `PECmd`:

```bash
$ PECmd.exe -d ./Prefetch --csv ./out --csvf pf.csv
Processed 47 .pf files.
$ head -3 ./out/pf.csv
SourceFilename,ExecutableName,Hash,LastRun,RunCount
CMD.EXE-1234ABCD.pf,CMD.EXE,1234ABCD,2025-03-01 22:11:03,7
POWERSHELL.EXE-5678EFGH.pf,POWERSHELL.EXE,5678EFGH,2025-03-01 22:12:40,3
```

Читаем: `cmd.exe` запускался **7 раз**, последний — в 22:11; `powershell.exe` — **3 раза**, последний в 22:12. PowerShell сразу после CMD — типичная картина атакующей активности. Это первая **гипотеза**, которую надо подтвердить другими артефактами.

## Шаг 1: что делать, если Prefetch пуст

Прежде чем радоваться или огорчаться — важная оговорка. Prefetch может быть **выключен** (на серверах параметр `EnablePrefetcher=0`) или **очищен** антифорензикой. Тогда пустая папка Prefetch **не значит**, что ничего не запускалось. Нужно опираться на два других артефакта.

## Шаг 2: ShimCache — файл, который «видел» загрузчик

Второй источник — **ShimCache** (он же AppCompatCache). Он хранит записи об исполняемых файлах, которые «видел» загрузчик Windows, в кусте реестра `SYSTEM`. Разбирает их `AppCompatCacheParser`:

```bash
$ AppCompatCacheParser.exe -f SYSTEM --csv out --csvf shimcache.csv
$ grep -i evil out/shimcache.csv
C:\Users\bob\AppData\evil.exe,2025-03-01 22:09:00,...
```

Ключевая ценность: ShimCache может сохранить **путь и время файла даже после его удаления**. Здесь виден `evil.exe` в `AppData` — файл, которого на диске, возможно, уже нет.

Но есть тонкость: ShimCache — это журнал «файлов, которые загрузчик видел», а **не** журнал запусков. Запись может означать, что файл просто существовал. На части версий Windows есть флаг `Executed` (запускался ли), но он присутствует не всегда. Поэтому отсутствие флага не означает «не запускался».

## Шаг 3: AmCache — идентичность файла

Третий артефакт — **AmCache** (`C:\Windows\AppCompat\Programs\Amcache.hve`), отдельный куст реестра-инвентарь. Он хранит пути, время первого запуска и — главное — **SHA-1 хеши** исполняемых файлов:

```bash
$ AmcacheParser.exe -f Amcache.hve --csv out --csvf amcache.csv
$ grep -i evil out/amcache.csv
C:\Users\bob\AppData\evil.exe,9a0364b9e99bb480dd25e1f0284c8555,2025-03-01 22:09:00
```

Хеш `9a0364...` позволяет **однозначно идентифицировать** файл, даже если он удалён: его можно пробить по VirusTotal или сверить с базой. Это и есть ответ на вопрос «что за бинарь».

## Шаг 4: сводим всё в таймлайн

Три артефакта дают разную точность, и вместе они складываются в историю:

| Артефакт | Что доказывает | Хранит время | Хранит хеш |
|----------|----------------|--------------|------------|
| Prefetch | запуск + число запусков | да (последний запуск) | нет |
| ShimCache | «видел» EXE (иногда запуск) | да (время изменения) | нет |
| AmCache | инвентарь: путь и хеш | да | да (SHA-1) |

Для нашего случая: Prefetch говорит, что PowerShell запускался 3 раза в 22:12; ShimCache показывает, что `evil.exe` существовал по пути в `AppData` с временем 22:09; AmCache даёт его SHA-1. Итог: файл существовал, был запущен, и мы знаем его хеш. Гипотеза подтверждена.

## Шаг 5: как читать Prefetch вручную

Если под рукой нет PECmd, заголовок `.pf` читается и вручную. Формат: по смещению `0x04` — сигнатура `SCCA`, по `0x10` — имя программы в UTF-16LE, дальше времена последних запусков и счётчик:

```bash
$ strings -e l CMD.EXE-1234ABCD.pf | head -2
CMD.EXE
$ xxd -s 0x94 -l 4 CMD.EXE-1234ABCD.pf   # run count
```

Время хранится как **FILETIME** — число 100-наносекундных интервалов с 1 января 1601 года (UTC). Это ещё одна «эпоха», как Apple-эпоха 2001-го в HFS+; при переводе не забывайте о сдвиге.

## Полный разбор: собираем историю запуска

Вернёмся к нашему образу и выстроим единую хронологию по трём артефактам.

```bash
$ PECmd.exe -d ./Prefetch --csv ./out --csvf pf.csv
$ AppCompatCacheParser.exe -f SYSTEM --csv out --csvf shimcache.csv
$ AmcacheParser.exe -f Amcache.hve --csv out --csvf amcache.csv
```

Объединив выгрузки по времени, получаем:

| Время (UTC) | Источник | Событие |
|-------------|----------|---------|
| 22:09:00 | AmCache | `C:\Users\bob\AppData\evil.exe` (SHA-1 `9a0364…`) |
| 22:09:00 | ShimCache | тот же путь «видел» загрузчик |
| 22:11:03 | Prefetch | `CMD.EXE` — 7-й запуск |
| 22:12:40 | Prefetch | `POWERSHELL.EXE` — 3-й запуск |

Картина: файл появился/был замечен в 22:09, затем через две минуты — командная строка, затем PowerShell. Классическая последовательность «запуск инструмента → выполнение команд → скрипт». Три независимых источника, совпадающие по времени, — это уже не догадка, а доказательство.

Обратите внимание: **Prefetch по evil.exe отсутствует**. Это не значит, что его не запускали — возможно, он был запущен под другим путём (и тогда `.pf` имел бы другое имя), либо Prefetch был очищен. Именно поэтому нужны все три артефакта.

## Если не сработало

- **Prefetch пуст.** Проверьте параметр `EnablePrefetcher` в `SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management\PrefetchParameters`: `0` — выключен, `3` — включён. Пустая папка может быть следствием антифорензики.
- **ShimCache без флага `Executed`.** На ряде версий Windows флага нет — тогда факт запуска подтверждают другие артефакты (Prefetch, AmCache, UserAssist, BAM).
- **AmCache не читается.** Это отдельный куст; если файл повреждён, ищите копию в `C:\Windows\AppCompat\Programs\`.
- **Время «уехало».** Часовой пояс и DST искажают трактовку; приводите всё к UTC.
- **Файла нет на диске.** Это норма — все три артефакта как раз и рассчитаны на удалённые файлы.

## Сравнение артефактов выполнения

Чтобы не перепутать источники, держите рядом эту таблицу:

| Артефакт | Путь | Даёт | Ограничение |
|----------|------|------|-------------|
| Prefetch | `Windows\Prefetch\*.pf` | запуск, run count, время | выключается, очищается |
| ShimCache | `SYSTEM` hive | пути «виденных» EXE | не всегда журнал запусков |
| AmCache | `AppCompat\Programs\Amcache.hve` | путь + SHA-1 | нет счётчика запусков |
| UserAssist | `NTUSER.DAT` | запуски из GUI | только через Explorer |
| BAM/DAM | `SYSTEM` hive | запуск по пользователю | требует SYSTEM |

Совпадение нескольких источников = уверенный вывод; расхождение = повод искать глубже.

## Защита и мониторинг

- Включённый Prefetch помогает и защитнику: он фиксирует запуск LOLBins (`rundll32`, `mshta`, `wmic`).
- **Sysmon** (события 1 и 11) даёт запуск и создание файла в реальном времени — не нужно ждать постфактум.
- Оповещения на запуск PowerShell с `-enc`, `-nop`, `-w hidden`.
- Храните копии Prefetch/AmCache/ShimCache при инцидентах: они малы, но бесценны для ретроспективы.

## Что мы теперь знаем

- **Prefetch** (`*.pf`) фиксирует запуск, число запусков и последнее время; может быть выключен/очищен.
- **ShimCache** хранит пути EXE, которые «видел» загрузчик, — иногда даже удалённых; это не журнал запусков.
- **AmCache** даёт инвентарь с **SHA-1** — идентификатор файла для VirusTotal.
- Три артефакта дополняют друг друга: время запуска, факт существования, идентичность.
- Prefetch-хеш зависит от полного пути запуска, поэтому один EXE из разных папок даёт разные `.pf`.
- Время в Prefetch — FILETIME (от 1601 года, UTC).
