Технический результат без документации бесполезен: его нельзя проверить, оспорить или использовать как доказательство. В форензике отчёт — не «бумажка в конце», а неотъемлемая часть работы: он превращает набор команд в воспроизводимый, защищаемый вывод. Этот урок — про методологию: как вести журнал, как строить цепочку сохранности, как формулировать выводы с правильным уровнем уверенности и как выглядит отчёт, который примет и заказчик, и суд, и жюри CTF.

## Зачем нужен отчёт

Хороший форензик-отчёт отвечает на пять вопросов: **что** произошло, **когда**, **где**, **как** и **почему**. Он должен позволить коллеге, не участвовавшему в расследовании, повторить каждый шаг и прийти к тому же выводу. Три аудитории, под которые пишется отчёт:

- **менеджмент** — читает только executive summary (что случилось, что делать);
- **технические специалисты** — читают методику, находки, приложения;
- **юристы/регуляторы** — проверяют целостность и цепочку сохранности.

## Цепочка сохранности (Chain of Custody)

Chain of custody — это журнал, фиксирующий движение доказательства от момента изъятия до возврата/уничтожения. Без него доказательство теряет юридическую силу.

| Поле | Пример |
|------|--------|
| Идентификатор | `EVID-001` |
| Описание | Образ диска ноутбука, S/N WD-XXXX |
| Источник | `/dev/sdb`, серийник |
| Хеш (SHA-256) | `a1b2c3...` |
| Кто изъял | Иванов И.И. |
| Дата/время (UTC) | 2024-10-10 12:00 |
| Способ изъятия | dc3dd, write blocker |
| Передача | кому, когда, подпись |
| Действия | копирование, анализ, возврат |

Правила:

- **Каждый переход** доказательства между людьми/местами фиксируется с подписью.
- **Хеш до и после** — доказательство неизменности (write blocker + повторный `sha256sum`).
- Оригинал хранится отдельно; анализ ведётся **только на копии**.
- Храните носители в защищённом месте, а метаданные (время изъятия) — в неизменяемом виде.

## Журнал действий (work log)

Записывайте каждую команду, которая меняет состояние или создаёт артефакт. Формат — время (UTC) + команда + результат.

```
2024-10-10 12:05 UTC  Снят образ: dd if=/dev/sdb of=disk.img bs=4M conv=noerror,sync
2024-10-10 12:07 UTC  Хеш: sha256sum disk.img -> a1b2c3...
2024-10-10 12:10 UTC  mmls disk.img -> раздел start=2048
2024-10-10 12:12 UTC  fls -o 2048 disk.img -> найдены удалённые inode 13,14
2024-10-10 12:15 UTC  icat -o 2048 disk.img 13 > rec.bin; sha256sum rec.bin
```

Автоматизируйте запись — так ничего не забудется:

```bash
# Простой способ логировать сессию (пишет всё, включая вывод)
script -a forensic_session.log

# Ещё удобнее — расширенный shell с временем в приглашении
export PS1='\[\e[31m\]\t\[\e[0m\] \w\$ '
```

Совет: держите `commands.sh` со всеми реальными командами, а журнал — отдельно, чтобы команды можно было воспроизвести без ручного копирования из лога.

## Принципы методологии

1. **Порядок изменчивости** — RAM → сеть → диск → бэкапы.
2. **Read-only** — никогда не менять оригинал; образ монтируется `mount -o ro,loop`.
3. **Хеширование** — фиксируйте целостность до и после.
4. **Повторяемость** — записывайте инструменты и версии.
5. **Минимизация вмешательства** — трогайте только нужное.
6. **Документирование** — если не записано, значит не сделано.

## Порядок сбора и типовые инструменты

| Этап | Что собираем | Инструменты |
|------|--------------|-------------|
| Память | RAM, процессы | `avml`, `winpmem`, `LiME` |
| Сеть | соединения, трафик | `netstat`, `ss`, `tcpdump`, `tshark` |
| Диск | образ | `dc3dd`, `dd`, `ewfacquire`, write blocker |
| Артефакты ОС | реестр, логи, ФС | `sleuthkit`, `regripper`, `evtx_dump` |
| Таймлайн | хронология | `plaso`, `log2timeline`, `mactime` |

## Структура отчёта

1. **Резюме (executive summary)** — 3–5 предложений для менеджмента.
2. **Область и цель** — что исследовали, зачем, границы.
3. **Методика** — инструменты и версии, порядок действий.
4. **Находки** — по каждому: артефакт, источник, время, интерпретация.
5. **Таймлайн** — хронология ключевых событий.
6. **Выводы** — что произошло, степень уверенности.
7. **Приложения** — хеши, сырые данные, полные команды.

## Уровни уверенности

Формулируйте аккуратно и отделяйте факт от интерпретации:

- **Подтверждено (confirmed)** — прямое доказательство (артефакт + корреляция нескольких источников).
- **Вероятно (likely)** — косвенные признаки, нет противоречий.
- **Возможно (possible)** — слабые признаки, требует проверки.

Избегайте категоричных выводов без доказательств: «атакующий вошёл в 12:03» и «в 12:03 зафиксирован успешный вход» — разные утверждения.

## Воспроизводимость: фиксируйте инструменты

```bash
# Версии инструментов — в отчёт
file --version
vol.py --version 2>/dev/null || vol -h 2>&1 | head -1
tshark -v | head -1
sleuthkit --version 2>/dev/null || fls -V
sha256sum disk.img
```

Хеш образа + версии инструментов = возможность воспроизвести результат на другом стенде.

## Практика: отчёт по CTF/инциденту

```bash
# 1. Собрать артефакты и хеши
find evidence/ -type f -exec sha256sum {} \; > hashes.txt
# 2. Записать команды (script или вручную)
# 3. Свести таймлайн
mactime -b bodyfile -d > timeline.csv
# 4. Написать отчёт в Markdown
```

Шаблон находки:

```markdown
### F-001: Удалённый файл secret.txt содержал флаг
- Артефакт: inode 13 раздела (offset 2048)
- Метод: fls -r -d; icat -o 2048 disk.img 13
- Время: crtime 2024-10-09 22:14 UTC
- Уверенность: подтверждено
- Доказательство: вывод icat, SHA-256 файла
```

## Сквозной пример: от изъятия до отчёта

Допустим, инцидент: подозрение на кражу данных с сервера.

1. **Изоляция и фиксация.** Хеш живого диска: `sha256sum /dev/sdb`. Изъятие — на write blocker.
2. **Сбор.** `dc3dd if=/dev/sdb of=srv.img hash=sha256 log=imaging.log`.
3. **Верификация.** `sha256sum srv.img` — совпал с `imaging.log`.
4. **Анализ на копии.** `mmls`, `fls -r`, `icat`, `plaso` для таймлайна.
5. **Находка.** Удалённый `export.csv` с базой клиентов, создан в 02:11, удалён в 02:19.
6. **Корреляция.** В auth.log — вход по SSH с внешнего IP в 02:05; в access.log — экспорт через web в 02:12.
7. **Вывод.** «Подтверждено: файл экспортирован через web-интерфейс в 02:12 с IP X; сессия установлена по SSH в 02:05».
8. **Отчёт.** Резюме → методика → находки → таймлайн → выводы → приложения с хешами.

## Юридические аспекты (кратко)

- Доказательство должно быть **подлинным** (integrity) и **непрерывным** (chain of custody).
- **Легальность получения** — важно, как добыты данные.
- **Полнота** — не скрывайте неудобные факты.
- В РФ — 149-ФЗ, УПК; в международной практике — ISO/IEC 27037, NIST SP 800-86.

## Типичные ошибки

- **Не считать хеши** — нельзя доказать неизменность.
- **Анализ на оригинале** — порча доказательств.
- **Отсутствие журнала** — невоспроизводимость.
- **Категоричные выводы** без уровня уверенности.
- **Смешивание факта и интерпретации** в одном разделе.
- **Забыть версии инструментов** — результат не воспроизвести.
- **Отчёт без приложений** — нечем подтвердить находки.
