## Вопрос, с которого всё начинается

Пришли четыре диска — по отдельности непонятные. Вместе они образуют RAID-массив.
Чтобы анализировать, нужно **собрать** их обратно. Разберём `mdadm`.

## Наш пример: RAID из четырёх дисков

## Шаг 1: определяем метаданные

Linux-RAID хранит метаданные в суперблоке. Посмотрим:

```
$ mdadm --examine /dev/sdb1
/dev/sdb1:
   Magic : a92b4efc
   Array UUID : 1a2b3c4d:...
   Raid Level : raid5
   Devices : 4
```

Здесь видно уровень (raid5), UUID массива и число устройств.

## Шаг 2: собираем

Собираем по копиям (чтобы не трогать оригиналы):

```
$ mdadm --assemble --readonly /dev/md0 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
mdadm: /dev/md0 has been started with 4 drives.
```

`--readonly` — критично: массив может запустить восстановление и изменить диски.

## Шаг 3: монтируем

```
$ mount -o ro /dev/md0 /mnt/raid
```

Если ФС распознана — читаем как обычный диск.

## Шаг 4: если сборка не идёт

- **не хватает диска** (degraded) — можно собрать в degraded-режиме;
- **неправильный порядок** — задай вручную (`--force` с порядком);
- **разные размеры** — учитывай.

```
$ mdadm --assemble --readonly --force /dev/md0 ...
```

## Шаг 5: определение уровня

- **RAID0** — страйп (нет избыточности);
- **RAID1** — зеркало;
- **RAID5/6** — чётность (нужны все, кроме одного/двух);
- **RAID10** — зеркало+страйп.

Уровень определяет, сколько дисков обязательно.

## Что мы теперь знаем

- `mdadm --examine` читает суперблок.
- `--assemble --readonly` собирает массив.
- Монтируем как обычный диск.
- Degraded-сборка возможна.
- Уровень определяет требования к дискам.

## Если не сработало

- Не собирается? Проверь уровень и UUID.
- Нужен порядок? Задай вручную.
- Диск мёртв? RAID5/6 переживёт один/два.

## Как работает Linux software RAID

Программный RAID в Linux строится утилитой `mdadm`. Метаданные (уровень,
UUID массива, порядок дисков) хранятся в **суперблоке** на каждом члене
массива. Формат суперблока обозначается версией: `0.90` (старый, в конце
диска), `1.0`, `1.1`, `1.2` (в начале диска, у 1.2 — на 4 КБ от начала).

Разные версии по-разному располагают метаданные, поэтому важно понять, с
чем имеешь дело, прежде чем собирать. `mdadm --examine` покажет и версию, и
все параметры.

## Работа на примере: examine и assemble

Начинаем с осмотра каждого диска:

```
$ mdadm --examine /dev/sdb1
/dev/sdb1:
          Magic : a92b4efc
        Version : 1.2
    Feature Map : 0x0
     Array UUID : 1a2b3c4d:5e6f7a8b:9c0d1e2f:3a4b5c6d
           Name : host:0
  Creation Time : Wed Jan 14 03:00:00 2026
     Raid Level : raid5
   Raid Devices : 4
```

Читаем: уровень `raid5`, массив из 4 устройств, UUID — общий для всех
членов. Теперь собираем по копиям (никогда по оригиналам!):

```
$ mdadm --assemble --readonly /dev/md0 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
mdadm: /dev/md0 has been started with 4 drives.
```

Ключ `--readonly` критичен: без него `mdadm` может запустить ребилд
(восстановление), который **перезапишет** диски и уничтожит улики. После
сборки монтируем только для чтения:

```
$ mount -o ro /dev/md0 /mnt/raid
```

## Порядок дисков и degraded-сборка

Если `--assemble` не собирает массив автоматически, причин обычно три:

- **Не хватает диска** — собирай в degraded-режиме:

```
$ mdadm --assemble --readonly --run /dev/md0 /dev/sdb1 /dev/sdc1 /dev/sdd1
```

- **Неправильный порядок** — задай вручную через `--force` с явным
  перечислением в порядке устройства.
- **Разные размеры** — массив берёт минимальный размер; лишнее остаётся за
  пределами массива (может содержать данные).

Иногда полезно **создать новый массив** с заданными параметрами, если
метаданные повреждены:

```
$ mdadm --create --readonly --assume-clean --level=5 --raid-devices=4 --chunk=64 /dev/md0 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
```

`--assume-clean` запрещает mdadm «чинить» массив и трогать данные.

## Уровни RAID и что они значат для анализа

| Уровень | Избыточность | Сколько дисков нужно |
| --- | --- | --- |
| RAID0 | нет | все (страйп) |
| RAID1 | зеркало | половина (любая из пары) |
| RAID5 | 1 диск | все, кроме одного |
| RAID6 | 2 диска | все, кроме двух |
| RAID10 | зеркало+страйп | по одному из каждой пары |

Понимание уровня определяет, **сколько дисков обязательно** для сборки и
что будет, если один утерян. Для RAID5/6 потеря одного/двух дисков — не
приговор: массив соберётся, а данные восстановятся по чётности.

## Монтирование и анализ файловой системы

После сборки массив ведёт себя как обычный диск. Определяем ФС:

```
$ file -s /dev/md0
/dev/md0: Linux rev 1.0 ext4 filesystem data
```

И монтируем read-only. Дальше — обычный форензик-анализ: `fls`/`icat`
(Sleuth Kit), `mmls` для таблицы разделов, поиск артефактов. Помни: RAID —
это лишь «слой» ниже файловой системы.

## Ограничения

- **Оригиналы нельзя трогать** — работай с копиями (`dd`).
- **Автосборка опасна** — она может «починить» массив и изменить улики.
- **Повреждённые метаданные** — требуют ручного создания массива.
- **Зашифрованные члены** — LUKS поверх RAID потребует ключа.
- **Разный chunk size** — влияет на разметку страйпа; указывай верно.

## Практический чек-лист

1. Сделать побайтовые копии всех дисков.
2. `mdadm --examine` каждого — узнать уровень, UUID, версию суперблока.
3. Собрать `--assemble --readonly` по копиям.
4. Если не выходит — degraded/ручное создание с `--assume-clean`.
5. Монтировать `-o ro`.
6. Определить ФС и анализировать как обычный диск.
7. Зафиксировать параметры массива (UUID, уровень, порядок) в отчёте.

## Суперблок: версии и расположение

Понимание версии суперблока решает, как читать метаданные:

- **0.90** — метаданные в конце диска, устаревший; максимум 28 устройств;
- **1.0** — в конце диска;
- **1.1** — в начале диска;
- **1.2** — на 4 КБ от начала (современный стандарт).

Почему это важно: при ручной сборке нужно знать, где лежит суперблок, чтобы
не перепутать с данными ФС. `mdadm --examine` печатает версию, а `mdadm
--detail` после сборки — состояние массива:

```
$ mdadm --detail /dev/md0
Raid Level : raid5
Array Size : 3145728 (3.00 GiB)
State : clean, degraded
Active Devices : 3
```

`degraded` в состоянии — сигнал, что один диск отсутствует.

## Практический сценарий: сборка RAID5 с потерей диска

Пришли три диска из четырёх (RAID5). Собираем degraded:

```
$ mdadm --assemble --readonly --run /dev/md0 /dev/sdb1 /dev/sdc1 /dev/sdd1
mdadm: /dev/md0 has been started with 3 drives (out of 4).
```

Массив поднимается, но помечен `degraded`. Данные читаются — чётность
позволяет восстановить отсутствующий диск «на лету». **Не запускай ребилд**:
`--readonly` и отсутствие нового диска гарантируют, что mdadm не начнёт
перезапись. Монтируем read-only и анализируем.

Если порядок дисков неизвестен, перебирай варианты порядка при ручном
создании массива, сверяя результат по сигнатурам ФС.

## RAID и шифрование (LUKS)

Часто поверх RAID лежит шифрование. Тогда массив соберётся, а ФС не
опознается — внутри LUKS-контейнер:

```
$ cryptsetup luksDump /dev/md0
LUKS header information for /dev/md0
Version: 2
```

Без ключа данные не читаются. Ищи ключ/пароль в других артефактах (записки,
менеджеры паролей, конфиги). Если ключа нет — фиксируй факт шифрования.

## Итог: RAID — слой ниже файловой системы

Сборка RAID — это не анализ, а **подготовка**: восстановление «цельного
диска» из осколков. Ошибки здесь (запуск ребилда, работа на оригиналах)
необратимы, поэтому правило одно — **копии + readonly**. Как только массив
собран, дальше работаешь с ним как с обычным диском: определяешь ФС,
монтируешь, ищешь артефакты.

## Сборка RAID0 и RAID10

Не всё сводится к RAID5. Для RAID0 (страйп) нужны **все** диски — потеря
одного уничтожает данные:

```
$ mdadm --assemble --readonly /dev/md0 /dev/sdb1 /dev/sdc1
```

Для RAID10 сначала собирают пары зеркал, затем страйпуют. Порядок и
соответствие пар критичны: неверная конфигурация даст мусор. Если метаданные
уцелели, `--assemble` сделает всё сам; если нет — придётся задавать
`--level=10 --layout` вручную и проверять результат по сигнатурам ФС.

## Частые ошибки

- **Работа на оригиналах** — только копии (`dd`).
- **Запуск ребилда** — без `--readonly` mdadm «починит» массив и изменит
  улики.
- **Неверный порядок дисков** — ФС не опознается; перебирай осторожно.
- **Игнорирование chunk size** — при ручном создании важен размер страйпа.
- **Попытка собрать без нужных дисков** — сначала оцени уровень и
  минимальный набор.

## Пример: RAID1 из двух дисков

Зеркало — простейший случай: достаточно **одного** диска из пары, чтобы
получить все данные. Собираем:

```
$ mdadm --assemble --readonly /dev/md0 /dev/sdb1 /dev/sdc1
mdadm: /dev/md0 has been started with 2 drives.
```

Даже если второй диск отсутствует, RAID1 соберётся degraded и отдаст полные
данные — зеркало не требует вычислений по чётности. Поэтому RAID1 самый
«дружелюбный» к анализу: потеря половины дисков не мешает.

## Коротко

RAID-анализ — это подготовка, а не поиск. Осмотри суперблоки, собери массив
на копиях с `--readonly`, при нехватке дисков используй degraded-режим, и
монтируй только для чтения. Дальше массив ведёт себя как обычный диск: ФС,
разделы, артефакты.

## Примечание о размерах

При ручной сборке учитывай, что массив берёт размер по наименьшему диску, а
«лишнее» пространство остаётся вне массива — там могут лежать данные,
которые стоит просмотреть отдельно.
