## Вопрос, с которого всё начинается

Ты собрал супер-таймлайн: полтора миллиона событий. Открываешь его в текстовом файле и
понимаешь, что так его не прочитать никогда. Где здесь атака? Как найти иголку в стоге
сена, если даже стог не помещается на экран?

## Зачем визуализировать

**Визуализация** превращает нечитаемую таблицу в картину, где аномалии видны глазом. Человек
плохо замечает отклонения в строках, но хорошо — на графике: всплеск, пропуск, ровную линию.

Главная польза — **сужение внимания**: из миллиона событий визуализация выделяет те сотни,
что стоят изучения.

## Timesketch: основа

**Timesketch** — открытая платформа для совместного анализа таймлайнов. Что она делает:

- принимает события из Plaso и других инструментов;
- строит **гистограмму** событий по времени;
- позволяет **фильтровать** и **искать** по запросам;
- даёт **добавлять заметки и теги** к событиям;
- поддерживает **разметку** подозрительных находок.

Рабочий приём: смотришь гистограмму, ищешь **всплески** (всплеск = много событий в короткое
время — часто действие атакующего) и **провалы** (пропал лог — возможно, его чистили).

## Наш пример: находим всплеск

Загрузим события и посмотрим на распределение:

```
09:00  |##                |  120 событий
09:10  |#                 |   40
09:13  |################  | 3800   <- всплеск
09:20  |##                |  150
```

Всплеск в 09:13 привлекает внимание. Фильтруем окно 09:12–09:15 и смотрим, что там:

```
09:13:55  sshd   Accepted password for deploy
09:13:58  fs     created /dev/shm/.index
09:14:02  proc   exec python3 /dev/shm/.index
09:14:03  net    connect 203.0.113.9:443
```

Вот и атака. Визуализация указала, куда смотреть; дальше работает фильтр.

## Фильтры и запросы

Ключевой навык — задавать точные вопросы к таймлайну:

- по времени (`timestamp > 09:12 and timestamp < 09:15`);
- по источнику (`source: syslog`);
- по значению (`message: "Accepted password"`);
- по ключу (`pid: 1842`).

Комбинируя фильтры, ты сужаешь миллион до десятков строк. Без фильтров визуализация остаётся
красивой картинкой без пользы.

## Графы связей

Помимо временной оси, полезны **графы**: узлы — сущности (процессы, файлы, IP, пользователи),
рёбра — связи между ними. Граф отвечает на вопрос «кто с кем связан», а не «когда».

Пример графа инцидента:

```
[deploy] --запускает--> [python3]
[python3] --создаёт--> [/dev/shm/.index]
[python3] --соединяется--> [203.0.113.9]
[deploy] --вход с--> [185.220.x.x]
```

Граф быстро показывает «звезду»: один узел, связанный со многими, — центр события.

## Что визуализировать

Полезные представления:

| Представление | Что показывает |
|---------------|----------------|
| Гистограмма по времени | всплески и провалы |
| Лента событий | хронологию эпизода |
| Граф связей | структуру «кто с кем» |
| Карта | географию адресов |
| Тепловая карта | активность по часам/дням |

Разные представления отвечают на разные вопросы. Гистограмма — «когда», граф — «кто с кем»,
карта — «откуда».

## Частые ошибки

- **Смотреть весь таймлайн без фильтра.** Бессмысленно.
- **Доверять всплеску без проверки.** Он может быть нормальным (бэкап, cron).
- **Забыть про провалы.** Отсутствие событий — тоже сигнал.
- **Строить граф без ключей корреляции.** Рёбра будут случайными.
- **Не фиксировать находки.** Визуализация без заметок теряется.

## Что мы теперь знаем

- Визуализация сужает внимание с миллионов событий до значимых.
- Timesketch строит гистограммы, фильтры и заметки.
- Всплески и провалы — первые кандидаты на аномалию.
- Графы показывают структуру связей, дополняя временную ось.
- Без фильтров и ключей корреляции визуализация бесполезна.

## Подготовка данных для визуализации

Визуализация начинается не с графика, а с данных. Чтобы картинка была осмысленной, события
нужно сначала привести в порядок:

- привести время к **UTC**;
- нормализовать поля (одинаковые имена: `timestamp`, `host`, `user`);
- убрать дубликаты;
- пометить источник у каждого события (provenance).

Если данные не подготовлены, на гистограмме будет «каша» из разных форматов времени, и
всплески окажутся артефактом формата, а не реальной активностью.

## Как читать гистограмму

Гистограмма по времени — основной инструмент. Что на ней искать:

| Признак | Возможная причина |
|---------|-------------------|
| Резкий всплеск | массовое действие: скрипт, атака, бэкап |
| Провал | пропали логи: очистка, сбой сбора |
| Сдвиг «нормального» паттерна | работа в необычные часы |
| Ровный «полочный» рост | автоматизированный процесс |
| Периодические пики | cron/задача по расписанию |

Гистограмма не отвечает на «что», она отвечает на «когда смотреть». Дальше работает фильтр.

## Запросы в Timesketch

Timesketch использует язык запросов, похожий на поиск по полям. Примеры:

```
message: "Accepted password"        # входы по SSH
source: syslog AND user: root       # действия root из syslog
timestamp: 2026-10-14T09:00..09:20  # окно времени
data_type: "fs:stat"                # только метаданные файлов
```

Комбинируя условия, ты сужаешь миллионы событий до десятков. Умение писать точные запросы —
ключевой навык: без него визуализация остаётся картинкой.

## Графы связей: как строить

Граф строится из **рёбер**, а ребро — это связь между двумя сущностями, найденная в
артефактах. Правила:

- узлы — сущности (процесс, файл, IP, пользователь, хост);
- рёбра — отношения (запускает, создаёт, соединяется, входит);
- у каждого ребра — источник (provenance).

Пример рёбер:

```
deploy    -> запускает    -> python3
python3   -> создаёт      -> /dev/shm/.index
python3   -> соединяется  -> 203.0.113.9:443
deploy    -> входит с     -> 185.220.x.x
```

На графе сразу видно «звезду» — узел `python3`, связанный со многими, есть центр эпизода.

## Сторителлинг таймлайна

Визуализация нужна ещё и для **объяснения** вывода читателю. Хороший приём — собрать из
таймлайна короткую историю с 5–7 ключевыми событиями:

```
09:13:55  вход по SSH (deploy)
09:13:58  создан /dev/shm/.index
09:14:02  запущен python3
09:14:03  соединение с 203.0.113.9
09:14:10  создана задача cron
```

Такая лента читается за секунды и передаёт суть. Полный таймлайн с миллионом строк остаётся
в приложении, а в отчёт идёт выжимка.

## Мини-упражнение

Загрузи таймлайн в Timesketch (или построй гистограмму в Python). Найди всплеск, отфильтруй
окно вокруг него и составь ленту из 5 ключевых событий. Проверь, объясняет ли эта лента
эпизод целиком.

## Резюме

Визуализация — это инструмент **сужения внимания** и **объяснения**. Гистограмма показывает
«когда», фильтры — «что именно», граф — «кто с кем», а лента ключевых событий — «суть».
Начинать всегда с подготовки данных и базовой линии, иначе визуализация покажет шум.

## Дашборды и совместная работа

В командном расследовании визуализация — это ещё и средство совместной работы. Хороший
дашборд позволяет нескольким аналитикам смотреть на одну картину:

- **общая гистограмма** — все видят одно окно событий;
- **заметки и теги** — аналитики помечают находки для коллег;
- **сохранённые представления** — часто используемые фильтры под рукой;
- **ссылки на события** — можно переслать конкретное событие, а не описывать словами.

Timesketch и подобные платформы дают это «из коробки». Ценность в том, что выводы не
дублируются, а накапливаются: один аналитик помечает подозрительный процесс, другой — его
сетевую активность, и картина собирается сообща.

## Типичные ошибки визуализации

- **Слишком много данных на одном графике.** Пять источников на одной гистограмме дают шум,
  а не инсайт. Разделяй по источникам.
- **Неправильный масштаб.** На недельном графике секундный всплеск не виден. Масштаб должен
  соответствовать вопросу.
- **Игнорирование базовой линии.** Без неё нормальный cron выглядит как атака.
- **Отсутствие подписей.** График без осей и единиц бесполезен для читателя.
- **Красота вместо смысла.** Наглядность должна служить вопросу, а не украшению отчёта.

## От графика к выводу

График — не вывод, а его подспорье. Порядок такой: график → подозрительное окно → фильтр →
события → проверка → вывод. Пропуск шагов приводит к поспешным заключениям по «страшному
всплеску», который на деле оказался плановым бэкапом.

Хороший аналитик всегда перепроверяет то, что подсказала картинка: открывает события,
смотрит контекст, сопоставляет с базовой линией. Визуализация направляет, но не решает.

## Визуализация для разных аудиторий

Одна и та же находка подаётся по-разному:

| Аудитория | Что показать |
|-----------|--------------|
| Технический аналитик | полный таймлайн, фильтры, граф |
| Руководство | короткая лента ключевых событий |
| Юрист | события с источниками и временем |
| Клиент | обезличенная хронология |

Умение переключать уровень детализации — часть мастерства. Полный таймлайн для руководства
так же бесполезен, как краткая выжимка для технического разбора.

## Резюме

Визуализация таймлайна — это инструмент сужения внимания, совместной работы и объяснения.
Она опирается на подготовленные данные и базовую линию, а её результат всегда перепроверяется
по событиям. Правильно выбранное представление под нужную аудиторию превращает миллион строк
в понятную и убедительную историю.

## Куда дальше

Мы умеем видеть таймлайн. Но насколько можно доверять каждому артефакту? Следующий урок —
**«Provenance и уверенность: сколько стоит улика»**.

## Где пригодится

- **DFIR:** быстрый поиск аномалий в больших таймлайнах.
- **CTF Forensics:** наглядное представление разбросанных событий.
- **Threat Hunting:** выявление всплесков и провалов.
- **Отчётность:** понятная читателю картина инцидента.
