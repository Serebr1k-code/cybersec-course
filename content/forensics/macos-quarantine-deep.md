## Вопрос, с которого всё начинается

На Mac нашли вредоносный файл. Первый вопрос следователя: **откуда он взялся** — скачали из
интернета, принесли на флешке или прислали почтой? macOS сама отвечает на это: каждый
скачанный файл помечается «карантином», а события карантина хранятся в базе.

## Наш пример: скачанный DMG

В `~/Downloads` лежит `Updater.dmg`. Нужно понять, кто и откуда его скачал. Начнём с
атрибута карантина у самого файла.

## Что такое карантин

Когда приложение скачивает файл, macOS ставит на него **расширенный атрибут** (xattr)
`com.apple.quarantine`. Посмотреть его:

```
$ xattr -p com.apple.quarantine Updater.dmg
0083;6a1b2c3d;Safari;1234ABCD-...-EF12
```

Значение — набор полей через `;`:

| Поле | Что означает |
|------|--------------|
| флаги | как обрабатывать (0001 запрещён к запуску и т. п.) |
| время | когда файл скачали (hex-время) |
| агент | кто скачал (Safari, Chrome, Mail) |
| UUID | идентификатор события |

## Шаг 1: база событий карантина

Xattr живёт на самом файле, но есть и центральная база событий:

```
~/Library/Preferences/com.apple.LaunchServices.QuarantineEventsV2
```

Это SQLite-база с таблицей `LSQuarantineEvent`. Колонки: `LSQuarantineTimeStamp`,
`LSQuarantineAgentName`, `LSQuarantineOriginURLString`, `LSQuarantineDataURLString`. По ним
видно **источник** (origin), **ссылку загрузки** (data URL) и **приложение-агента**.

## Шаг 2: сопоставляем файл и событие

UUID из xattr совпадает с записью в базе. Значит, для нашего `Updater.dmg` можно найти:

```
$ sqlite3 QuarantineEventsV2 \
  "SELECT datetime(LSQuarantineTimeStamp+978307200,'unixepoch'), LSQuarantineAgentName, LSQuarantineOriginURLString \
   FROM LSQuarantineEvent ORDER BY LSQuarantineTimeStamp"
2025-05-01 08:20:44|Safari|https://cdn.example.net/tools/Updater.dmg
```

Ответ: файл скачал Safari 1 мая в 08:20 с `cdn.example.net`. Это уже зацепка для анализа
домена и цепочки доставки.

## Шаг 3: зачем это расследованию

Карантин — это **провенанс**: связка «файл → приложение → URL → время». Если несколько
заражённых машин скачали один и тот же файл с одного домена, карантин докажет общий вектор.
Даже если файл удалили, запись в базе остаётся — и хранит URL.

## Шаг 4: тонкости и ограничения

- Пользователь может очистить xattr (`xattr -d`), но запись в базе `QuarantineEventsV2`
  остаётся — поэтому база ценнее атрибута.
- База хранит ограниченное число записей (старые вытесняются), поэтому её копируют сразу.
- Время снова в эпохе Apple — прибавляй 978307200.
- Если приложение скачало файл без карантина (некоторые CLI-загрузчики, `curl`), события не
  будет — тогда источник ищут по истории браузера и сетевым логам.

## Шаг 5: где искать ещё

Дополни `QuarantineEventsV2` базой FSEvents (создание файла) и историей Safari (`History.db`).
Три артефакта вместе дают полную картину: когда файл появился, каким браузером и по какой
ссылке. Это классический сценарий анализа «первого файла» в цепочке заражения.

## Что мы теперь знаем

- Скачанные файлы помечаются xattr `com.apple.quarantine`.
- События хранятся в SQLite-базе `QuarantineEventsV2`, таблица `LSQuarantineEvent`.
- Поля origin/data URL дают источник и ссылку загрузки.
- Время — эпоха Apple (+978307200 для Unix).
- База остаётся после удаления файла и ценнее самого атрибута.

## Флаги карантина подробно

Первое поле в значении xattr — это флаги (битовая маска). Практически важные:

| Флаг | Значение |
|------|----------|
| `0x0001` | файл запрещён к запуску без подтверждения |
| `0x0002` | карантин уже «подтверждён» пользователем |
| `0x0040` | скачан не из браузера (некоторые загрузчики) |

Флаг `0x0001` объясняет, почему macOS при первом запуске скачанного приложения спрашивает
«Открыть?» — система видит метку карантина. Если злоумышленник снимает карантин (`xattr -d`),
он обходит это предупреждение — и как раз факт удаления атрибута сам по себе подозрителен.

## Случай: загрузка нестандартным агентом

Не всё скачивается браузером. Если файл принёс `curl`, `wget` или менеджер пакетов, атрибут
карантина может не ставиться вовсе, и записи в `QuarantineEventsV2` не будет. Тогда вектор
ищут иначе: по истории браузера (`History.db`), по FSEvents (создание файла) и по сетевым
логам. Важно понимать: **отсутствие карантина — не доказательство безопасности**, просто
другой путь доставки.

## Мини-практика: связать файл и источник

Пошаговый разбор:

```
$ xattr -l ~/Downloads/Updater.dmg
$ sqlite3 ~/Library/Preferences/com.apple.LaunchServices.QuarantineEventsV2 \
  "SELECT LSQuarantineTimeStamp, LSQuarantineAgentName, LSQuarantineOriginURLString \
   FROM LSQuarantineEvent ORDER BY LSQuarantineTimeStamp DESC LIMIT 10"
```

Сначала читаем атрибут — видим агента и UUID. Потом ищем в базе строку с этим временем и
URL. Совпадение подтверждает: файл пришёл по указанной ссылке. Если URL ведёт на
неизвестный домен — это зацепка для анализа инфраструктуры атакующего.

## Карантин в разных браузерах

Браузеры помечают скачанное по-разному, и это влияет на полноту картины:

- **Safari** использует системный механизм, поэтому запись попадает и в xattr, и в
  `QuarantineEventsV2`;
- **Chrome/Edge** также ставят `com.apple.quarantine`, но в базе событий может быть меньше
  деталей;
- **Firefox** ведёт собственную базу загрузок в профиле, и её стоит смотреть отдельно.

Поэтому источник загрузки ищут в нескольких местах: xattr файла, системная база карантина,
внутренняя история загрузок браузера.

## Снятие карантина как признак обхода

Обычный пользователь не трогает атрибуты файлов. Если у скачанного файла **нет** метки
карантина, хотя он появился из интернета, — кто-то её снял. Это может быть:

- скрипт установки, который делает `xattr -d com.apple.quarantine`;
- инструкция «обойди Gatekeeper» из фишингового сайта;
- сам вредонос, готовящий payload к запуску.

Факт отсутствия карантина у свежего файла из интернета — самостоятельный индикатор.

## Построение цепочки доставки

Полная цепочка выглядит так: письмо или сайт → браузер скачивает файл (запись карантина с
URL) → пользователь открывает (событие Gatekeeper в unified log) → payload создаёт
автозапуск. Каждый шаг фиксируется своим артефактом. Собрав их, ты показываешь **провенанс**
файла от источника до закрепления, а не просто «файл есть на диске».

## Что делать при обнаружении

Зафиксируй URL, агента и время из базы, посчитай хеш файла, сохрани образец. Домен из
`LSQuarantineOriginURLString` проверь по внешним источникам — возможно, он связан с известной
кампанией. И не забудь, что база хранит ограниченное число записей: её копируют сразу, иначе
старые улики вытеснятся новыми загрузками.

## Расширенный разбор: карантин и Gatekeeper

Карантин — часть системы **Gatekeeper**, которая решает, можно ли запускать скачанный
код. Логика такая: файл получает метку карантина при скачивании; при первом запуске macOS
проверяет подпись и нотаризацию; если код не доверенный — спрашивает пользователя. Поэтому
карантин — это не только провенанс, но и **точка контроля**, которую обходит вредонос.

Обход обычно выглядит так: злоумышленник просит пользователя нажать «Открыть всё равно» или
выполнить команду снятия карантина. Оба действия оставляют след: первое — в unified log
(событие Gatekeeper), второе — в истории shell и в событиях `xattr`. Связав метку карантина,
запись Gatekeeper и команду снятия, ты восстановишь момент, когда пользователь осознанно
запустил недоверенный код.

## Извлечение данных из событий карантина

База `QuarantineEventsV2` — обычный SQLite. Кроме прямого запроса, её удобно выгружать в CSV
для отчёта:

```
sqlite3 -header -csv QuarantineEventsV2 \
  "SELECT datetime(LSQuarantineTimeStamp+978307200,'unixepoch') AS t,
          LSQuarantineAgentName AS agent,
          LSQuarantineOriginURLString AS origin
   FROM LSQuarantineEvent ORDER BY t" > quarantine.csv
```

Полученная таблица «время — агент — источник» — готовый раздел отчёта о векторе доставки.
Если в списке есть домены с плохой репутацией, отметь их как инфраструктуру атакующего.

## Связка карантина с другими артефактами macOS

Карантин редко рассматривают в одиночку. Его настоящая сила — в комбинации с другими
источниками. База FSEvents покажет момент появления файла на диске, unified log — событие
Gatekeeper при первом запуске, а `knowledgeC.db` — было ли приложение в фокусе в этот
момент. Сложив три артефакта, ты получишь полную цепочку: файл скачан (карантин с URL),
файл создан (FSEvents), файл запущен (Gatekeeper), пользователь был за машиной
(knowledgeC). Это и есть доказательный провенанс, а не отдельная запись. Держи в голове,
что у каждой записи своё время и свой часовой пояс: приведи всё к UTC, прежде чем
сопоставлять.

Карантин — это ещё и удобный индикатор для **threat hunting** на парке Mac: регулярная
выгрузка событий с доменами позволяет заметить всплеск скачиваний с одного источника задолго
до срабатывания антивируса. А в CTF-задаче с образом macOS запись карантина часто является
единственной зацепкой, ведущей от «вот вредоносный файл» к «вот откуда он пришёл». Поэтому
умение читать `QuarantineEventsV2` — обязательный навык macOS-форензики.

## Практика: разбор базы QuarantineEventsV2 через sqlite3

Атрибут `com.apple.quarantine` живёт на самом файле и легко теряется при копировании. Куда
надёжнее — центральная база `~/Library/Preferences/com.apple.LaunchServices.QuarantineEventsV2`.
Это обычный SQLite-файл, и его можно открыть читалкой:

```
$ sqlite3 ~/Library/Preferences/com.apple.LaunchServices.QuarantineEventsV2
sqlite> .tables
LSQuarantineEvent
sqlite> .schema LSQuarantineEvent
CREATE TABLE LSQuarantineEvent (LSQuarantineEventIdentifier TEXT PRIMARY KEY,
  LSQuarantineTimeStamp REAL, LSQuarantineAgentName TEXT,
  LSQuarantineAgentBundleIdentifier TEXT, LSQuarantineOriginURLString TEXT,
  LSQuarantineDataURLString TEXT, LSQuarantineSenderName TEXT,
  LSQuarantineSenderAddress TEXT, LSQuarantineTypeNumber INTEGER, ...);
```

Полезный запрос — «что скачивали за последние сутки», отсортированное по времени:

```
sqlite> SELECT datetime(LSQuarantineTimeStamp + 978307200, 'unixepoch'),
   ...>        LSQuarantineAgentName, LSQuarantineOriginURLString
   ...> FROM LSQuarantineEvent
   ...> ORDER BY LSQuarantineTimeStamp DESC LIMIT 10;
2024-03-11 18:22:04|Safari|https://cdn.example-downloads.net/Updater.dmg
2024-03-11 18:20:57|Mail|https://mail.attacker.tld/invoice.zip
```

Здесь `978307200` — смещение между эпохой Unix и эпохой Apple Cocoa (2001-01-01). Забыть его —
классическая ошибка: время уезжает на 31 год назад.

## Практика: восстановление цепочки «откуда → чем → когда»

Соберите три источника в одну строку улики: URL (`LSQuarantineOriginURLString`), агент
(`LSQuarantineAgentName`) и время. Если файл ещё существует, добавьте его `xattr`, хеш и
дату модификации. Получится таблица, которую можно защитить в отчёте:

| Поле | Источник | Значение |
|------|----------|----------|
| Время загрузки | QuarantineEventsV2 | 2024-03-11 18:22:04 |
| Агент | QuarantineEventsV2 | Safari |
| Источник | QuarantineEventsV2 | cdn.example-downloads.net |
| Хеш файла | sha256 | 9f2c… |
| Атрибут | xattr | 0083;6a1b2c3d;Safari |

Совпадение времени в базе и hex-времени в атрибуте подтверждает, что запись не подделана
вручную.

## Если не сработало

- **База пустая или отсутствует.** События карантина живут недолго: система периодически
  чистит старые записи. Проверьте резервные копии (Time Machine) и `~/Library/Preferences/`.
- **`sqlite3` не открывает файл.** Файл может быть занят процессом — снимите копию
  (`cp`), работайте с копией, иначе получите `database is locked`.
- **Время выглядит «сдвинутым».** Скорее всего, не прибавили `978307200` или взяли не ту
  колонку.
- **Файла уже нет.** База всё равно хранит URL и время — это ценнее, чем сам бинарник для
  установления вектора доставки.

## Ограничения метода

Карантин фиксирует только загрузки через приложения, помечающие файлы. Файлы, принесённые
на физическом носителе, скопированные по сети или созданные на месте, карантина не получают
— их провенанс придётся строить по другим артефактам (`fseventsd`, `knowledgeC.db`, логи
монтирования). Поэтому база карантина — важный, но не единственный источник.
