## Вопрос, с которого всё начинается

У тебя 2-ТБ образ, и нужно быстро найти все email, URL и номера карт. Разбирать
файловую систему долго. **Bulk Extractor** делает это потоком: сканирует байты и
выдёргивает структуры по сигнатурам. Разберём.

## Наш пример: образ диска

## Шаг 1: что делает инструмент

Bulk Extractor не смотрит на файловую систему. Он читает образ как поток байт и ищет:

- email-адреса;
- URL и домены;
- IP-адреса;
- номера кредитных карт;
- ключи (RSA/DSA);
- следы поиска и «exif».

Это «скальпель по всему диску» — быстро и без монтирования.

## Шаг 2: запуск

```
$ bulk_extractor -o outdir /evidence/disk.img
```

Он создаёт набор файлов-отчётов:

```
$ ls outdir/
email.txt  url.txt  domain.txt  ccn.txt  ...
```

Каждый файл — список найденного с offset (где именно в образе).

## Шаг 3: читаем результат

```
$ head -3 outdir/email.txt
1256789	user@example.com
2001234	admin@corp.local
```

Первое поле — смещение, второе — значение. Смещение позволяет вернуться к данным и
понять контекст.

## Шаг 4: полезные опции

- `-e all` — включить все сканеры;
- `-x` — исключить ненужные;
- `-f` — работа с уже созданным feature-файлом (быстро повторять).

Повторный анализ по feature-файлу занимает секунды.

## Шаг 5: когда применять

- **масштаб** — терабайты;
- **первичный триаж** — быстро найти зацепки;
- **вместе с карвингом** — дополняет `foremost`/`scalpel`;
- **IOC-хантинг** — поиск известных индикаторов.

## Что мы теперь знаем

- Bulk Extractor сканирует поток байт, не ФС.
- Извлекает email, URL, домены, IP, карты, ключи.
- Результат — файлы-отчёты с offset.
- `-f` ускоряет повторный анализ.
- Идеален для масштаба и триажа.

## Если не сработало

- Ничего не найдено? Проверь, включён ли нужный сканер.
- Нужен контекст? Возьми offset и посмотри байты вокруг.
- Данные сжаты? Сначала распакуй/раскодируй.

## Как устроен движок: сканеры и feature-файлы

Bulk Extractor — это не один анализатор, а конвейер независимых **сканеров**, каждый из
которых ищет свой класс структур. Основные сканеры и то, что они дают:

| Сканер | Что извлекает | Файл вывода |
|---|---|---|
| `email` | адреса вида `user@host` | `email.txt` |
| `url` | URL, `http(s)://`, `ftp://` | `url.txt` |
| `domain` | доменные имена (FQDN) | `domain.txt` |
| `net` | IPv4-адреса и MAC | `ip.txt` |
| `telephone` | номера телефонов | `telephone.txt` |
| `ccn` | номера кредитных карт (Luhn) | `ccn.txt` |
| `exif` | EXIF-поля JPEG/TIFF | `exif.txt` |
| `rfc822` | заголовки писем, границы сообщений | `rfc822.txt` |
| `wordlist` | слова по заданному словарю | `wordlist.txt` |
| `zip` | локальные заголовки ZIP | `zip.txt` |

Каждый сканер пишет свой **feature-файл** — построчный список найденного. Формат строки
универсален: `<offset>	<feature>	<context>`. Первое поле — смещение в байтах от начала
потока, второе — само значение, третье — необязательный контекст (например, имя файла или
родительская структура). Именно offset позволяет вернуться к месту находки и понять
контекст.

## Практический разбор: домен C2 в образе

Допустим, в задаче нужно найти домен, куда «звонил» вредонос. Быстрый путь:

```
$ bulk_extractor -o out -e domain,url /evidence/disk.img
$ cat out/domain.txt | head
178392145	ev1l-c2.example	<domain>
182004912	sync.example.org	<domain>
```

Затем фильтруем подозрительные и сверяем со стоп-листом популярных доменов:

```
$ cut -f2 out/domain.txt | sort -u | grep -viE 'windows|microsoft|gstatic' | head
ev1l-c2.example
```

Дальше берём offset и вырезаем контекст вокруг находки:

```
$ dd if=/evidence/disk.img bs=1 skip=$((178392145-64)) count=256 2>/dev/null | strings
```

Так в одном окне видно и домен, и URL запроса, и, возможно, HTTP-заголовок `Host`.

## Работа с feature-файлами повторно

Сканирование 2-ТБ образа занимает часы, но результат (`out/`) можно переиспользовать:

```
$ bulk_extractor -f out -o out2 /evidence/disk.img   # быстрый повтор по фичам
$ bulk_extractor -R -o out -e wordlist:custom.txt /evidence/disk.img
```

Ключ `-R` добавляет сканер к уже существующему набору, не пересканируя всё заново, а `-f`
вообще позволяет собрать вывод без повторного прогона тяжёлых сканеров. Это критично,
когда нужно быстро добавить новый словарь.

## Словари, стоп-листы и контекст

- `-w custom.txt` — свой словарь для сканера `wordlist` (поиск паролей, имён проектов);
- `-s stop.txt` — стоп-лист, чтобы не засорять вывод системными строками;
- `-E ccn:12` — включить конкретный сканер с параметром (для `ccn` — порог длины);
- `-S scan_name` — повторно запустить один сканер;
- `-C` — отключить запись контекста (экономит место на огромных образах).

Стоп-лист почти всегда нужен: без него `domain.txt` заполнится сотнями доменов из
системных библиотек, и настоящий индикатор утонет в шуме.

## Извлечение из памяти и сетевых дампов

Bulk Extractor одинаково хорошо работает не только с дисками, но и с другими потоками:

```
$ bulk_extractor -o mem_out /evidence/memory.raw        # дамп RAM
$ bulk_extractor -o pcap_out /evidence/capture.pcap     # сетевой дамп
```

В дампе памяти он находит URL, ключи и артефакты из кэшей браузеров, которых уже нет на
диске. В pcap — заголовки HTTP, `Host`, пользовательские агенты, домены, даже если
содержимое TLS не читается. Это делает его универсальным первым шагом триажа.

## Ограничения и типичные ошибки

- **Нет файловой системы.** Инструмент не понимает ФС, поэтому не скажет, какому файлу
  принадлежит находка, — только offset. Имя файла появляется лишь там, где сканер
  встретил структуру, где оно рядом (например, в ZIP-заголовке).
- **Пропуск при сжатии/шифровании.** Данные внутри архива, зашифрованного тома или
  сжатого потока не видны, пока их не распакуешь.
- **Ложные срабатывания.** `domain.txt` ловит и мусор; `ccn.txt` иногда даёт случайные
  числа, прошедшие Luhn. Всегда подтверждай контекстом.
- **Не заменяет экспертизу ФС.** Для привязки к файлам и удалённым записям нужны
  `sleuthkit`/`Autopsy`, а не Bulk Extractor.

## Если сработало / не сработало

Если сканер молчит, проверь, что он включён (`-e` без него отключает лишнее), и что ты
сканируешь нужный поток. Если находок слишком много — добавь стоп-лист и словарь. Если
нужен контекст — используй offset с `dd`/`strings`. Если данные сжаты — сначала распакуй
контейнер.

## Устройство feature-файлов

Bulk Extractor пишет результат не «одним отчётом», а набором **feature-файлов** — по
одному на каждый тип структуры. Внутри каталога `outdir/` ты увидишь:

```
$ ls outdir/
email.txt  url.txt  domain.txt  ccn.txt  telephone.txt  exif.txt
json.txt  winpe.txt  rfc822.txt  wordlist.txt  report.xml
```

Формат строки почти везде одинаковый: **смещение (offset), затем значение**, иногда с
дополнительным полем:

```
$ head -3 outdir/domain.txt
1256789\texample.com
2001234\tcorp.local
4096000\tcdn.example.net
```

Смещение — это байтовая позиция в исходном образе. Именно она превращает «список
строк» в улику: по offset ты возвращаешься к контексту и видишь, откуда строка взялась
(в каком файле, в каком заголовке, в каком поле письма). Есть также `report.xml` —
сводка: сколько фич каждого типа найдено, какие сканеры отработали, хеши образа.

## Какие сканеры есть и что они ищут

Bulk Extractor — это фреймворк сканеров; каждый умеет распознавать свой класс данных:

| Сканер | Что извлекает | Особенность |
|---|---|---|
| `email` | адреса электронной почты | из заголовков и тела |
| `rfc822` | целые письма | восстанавливает сообщения |
| `url` | URL и ссылки | протокол + хост + путь |
| `domain` | доменные имена | включая без `http://` |
| `ccn` | номера карт | проверка алгоритмом Луна |
| `telephone` | телефоны | по шаблонам стран |
| `exif` | EXIF из JPEG/TIFF | камера, GPS, время |
| `aes`/`rsa` | ключи шифрования | в форматах key/sha |
| `json` | JSON-структуры | токены, конфиги |
| `winpe` | PE-файлы в памяти | признаки загрузки exe |
| `wordlist` | частотный словарь | топ слов для паролей |

Сканеры включаются/выключаются опцией `-e` (включить) и `-x` (исключить). Например,
для задачи «найти только сетевые индикаторы» имеет смысл оставить `url` и `domain`:

```
$ bulk_extractor -e url -e domain -o outdir /evidence/disk.img
```

## Возврат к контексту по offset

Главная ценность offset — возможность посмотреть **окружение** находки. Прочитай
несколько сотен байт вокруг позиции:

```
$ dd if=/evidence/disk.img bs=1 skip=1256000 count=400 | strings
```

Так восстанавливается смысл: если `example.com` найден рядом со строкой
`POST /gate.php`, это уже не просто домен, а адрес C2. Для потоковых образов удобно
использовать `-C` (context) — Bulk Extractor сохранит вокруг каждой находки фрагмент
контекста, и его можно читать прямо из feature-файла.

## Типовые CTF-сценарии

В задачах Bulk Extractor обычно дают как «первый быстрый проход» по большому образу:

1. **Найти флаг в тексте.** `grep -r 'nto{' outdir/` — флаг часто лежит в `url.txt`,
   `json.txt` или `wordlist.txt` как часть строки.
2. **Найти C2-домен.** Смотри `domain.txt` на предмет редких доменов, которых нет в
   белом списке; beacon-трафик выдаёт регулярность в `report.xml`.
3. **Восстановить письмо.** Сканер `rfc822` собирает целые сообщения — их можно
   открыть как `.eml` и прочитать вложения.
4. **Найти ключи.** `aes.txt`/`rsa.txt` — приватные ключи, которыми что-то зашифровано.
5. **Найти пароли.** `wordlist.txt` содержит частотный словарь — кандидаты для
   перебора зашифрованного контейнера.

## Ограничения и тонкие места

- **Ложные срабатывания.** Регулярки ловят «похожее»: строка `1234-5678-9012-3456`
  может быть не картой. Проверяй контекст.
- **Сжатые и зашифрованные данные.** Внутри ZIP/GZIP/шифрованного контейнера сканер
  ничего не увидит — сначала распакуй (`binwalk -e`) или получи ключ.
- **Бинарные структуры.** Bulk Extractor не разбирает файловую систему; он не скажет
  «этот файл — письмо», он скажет «здесь байты похожи на письмо».
- **Производительность.** Для 2 ТБ делай `-f` после первого прохода, иначе каждый
  повторный анализ будет пересобирать feature-файлы с нуля.
- **Память.** На дампе памяти Bulk Extractor тоже работает и часто достаёт пароли и
  URL, которые не видны при анализе диска.

## Сравнение с альтернативами

Bulk Extractor — не единственный инструмент для массового извлечения. Полезно понимать,
когда он лучше, а когда нужен другой:

| Инструмент | Что делает | Когда выбирать |
|---|---|---|
| `bulk_extractor` | структуры по сигнатурам, offset | огромные образы, триаж IOC |
| `foremost` / `scalpel` | карвинг файлов по заголовкам | восстановить сами файлы |
| `photorec` | карвинг по сигнатурам + эвристика | картинки/медиа |
| `strings` | печатаемые строки | быстрый ручной поиск |
| `sleuthkit` (`fls`, `icat`) | разбор ФС | привязка к файлам и inode |
| `Autopsy` | GUI-надстройка над TSK | отчёт и визуальный анализ |

Ключевое отличие: Bulk Extractor **не** восстанавливает файлы и **не** знает ФС. Он даёт
карту находок с offset. Карвинг даёт сами файлы. Разбор ФС даёт имена и удалённые записи.
В реальном расследовании их комбинируют: сначала Bulk Extractor для карты, затем
карвинг/TSK для восстановления.

## Скорость, ресурсы и интеграция в пайплайн

Bulk Extractor оптимизирован под потоковую обработку и умеет параллелить сканеры:

```
$ bulk_extractor -j 4 -o out /evidence/disk.img   # 4 потока
$ time bulk_extractor -o out -e url,domain /evidence/disk.img
```

Что важно на практике:

- **Диск читается один раз** — все сканеры работают на одном проходе, поэтому включение
  дополнительных сканеров почти не увеличивает время чтения.
- **Многопоточность** (`-j`) ускоряет на многоядерных машинах.
- **Память** — вычитывает образ блоками, но `wordlist`-сканер на огромных словарях может
  потреблять заметно больше.
- **Воспроизводимость** — фиксируй версию и параметры запуска; разные версии дают разный
  набор сканеров по умолчанию.

В DFIR-пайплайне его обычно ставят сразу после снятия образа, параллельно с хэшированием:
пока считается хэш, Bulk Extractor уже выдаёт первые зацепки.

## Чек-лист быстрого запуска

1. Снять/принять образ, зафиксировать хэш (`sha256sum`).
2. Запустить `bulk_extractor -o out <образ>` (можно `-e` нужных сканеров).
3. Просмотреть `out/report.xml` — там перечень сканеров и статистика.
4. Отфильтровать ключевые файлы (`url.txt`, `domain.txt`, `email.txt`).
5. Подтвердить находки контекстом через offset + `dd`/`strings`.
6. Сохранить `out/` как артефакт — повторный анализ по фичам занимает секунды.
