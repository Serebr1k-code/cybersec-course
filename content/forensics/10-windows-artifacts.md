## Вопрос, с которого всё начинается

В прошлом уроке мы смотрели на память — но там были процессы, жившие в момент
снятия дампа. А что, если машина уже выключена и у нас есть только копия её диска?
Как узнать, **какие программы запускались**, **что прописалось в автозапуск** и
**кто входил в систему**?

В Windows для этого есть целый набор «артефактов» — файлов, которые система ведёт
для собственных нужд, а мы используем как улики. В этом уроке пройдём по одному
инциденту и соберём историю из нескольких артефактов.

## Наш пример: папка с уликами

У нас есть выгрузка с подозрительной машины:

```
case/
├── Prefetch/RUNDLL32.EXE-4B2C1D3A.pf
├── Registry/NTUSER.DAT
├── Registry/SOFTWARE
└── Logs/Security.evtx
```

С чего начать? С вопроса «что здесь запускалось». Первый артефакт — Prefetch.

Важно сразу настроиться: ни один артефакт сам по себе не доказывает атаку. Prefetch
скажет, что программа запускалась, реестр — что она прописана в автозапуск, журнал —
кто вошёл. Только вместе они дают картину. Поэтому в этом уроке мы будем не
разбирать артефакты по отдельности, а собирать из них одну историю.

## Prefetch: какие программы запускались

**Prefetch** — файл в `C:\Windows\Prefetch`, который Windows создаёт для ускорения
запуска программ. Он хранит имя программы, сколько раз её запускали и когда в
последний раз. Разбираем:

```bash
$ PECmd -d case/Prefetch --csv pf.csv
Parsed 1 Prefetch files

Source filename : RUNDLL32.EXE-4B2C1D3A.pf
Executable name : RUNDLL32.EXE
Run count       : 3
Last run        : 2024-06-14 09:41:25
Previous run    : 2024-06-14 09:38:10
```

Что мы поняли: `RUNDLL32.EXE` запускали **3 раза**, последний — 14 июня в 09:41.
Совпадение с временем из дампа памяти (процесс `rundll32.exe` держал соединение) —
сильная зацепка. Prefetch доказывает **факт запуска** программы, даже если её файл
уже удалили.

Важно: Prefetch есть только на обычных Windows-дисках; на SSD с отключённым
prefetching его может не быть.

## Реестр: что прописано в автозапуск

**Реестр** — это база настроек Windows. Нас интересуют ключи, откуда программы
стартуют автоматически. Проверяем `Run`:

```bash
$ reg query "HKLM\Software\Microsoft\Windows\CurrentVersion\Run" /s
HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run
    Updater    REG_SZ    C:\Users\Public\update.ps1
```

Ключ `Updater` запускает `update.ps1` из публичной папки. Скрипт PowerShell в
автозапуске — классическая **персистентность** (закрепление в системе). Теперь
понятна связка: скрипт запускает `rundll32`, тот соединяется с внешним IP.

Реестр — это файлы-**hives** (улей), которые можно разбирать офлайн:

| Улей | Что внутри |
|------|-----------|
| `SAM` | локальные учётные записи |
| `SOFTWARE` | установленные программы, настройки системы |
| `SYSTEM` | драйверы, службы, монтирование дисков |
| `NTUSER.DAT` | настройки пользователя, недавние файлы, USB |

`NTUSER.DAT` помнит подключённые **USB-устройства** — по ним можно понять, какие
флешки вставляли. А в `SAM` лежат хеши локальных паролей, которые потом ломают
офлайн (`john --format=nt`).

## Журналы событий (EVTX): кто и когда входил

**EVTX** — бинарные журналы событий Windows (`Security.evtx`, `System.evtx`).
Каждое событие имеет числовой `EventID`. Самые полезные:

| EventID | Событие |
|---------|---------|
| 4624 | успешный вход в систему |
| 4625 | неудачный вход |
| 4688 | запуск процесса |
| 4720 | создание учётной записи |
| 1102 | очистка журнала (следы заметали!) |

Читаем журнал:

```bash
$ evtx_dump case/Logs/Security.evtx | grep -A3 'EventID: 4624'
EventID: 4624
TimeCreated: 2024-06-14T09:40:58Z
TargetUserName: Administrator
IpAddress: 10.10.10.50
LogonType: 3 (Network)
```

Вход под `Administrator` с сетевого адреса `10.10.10.50` — вероятно, латеральное
движение атакующего. Обрати внимание на событие **1102**: если журнал очищали,
это само по себе улика.

## MFT: вся история файловых операций

**MFT** (Master File Table) — таблица всех файлов на NTFS-томе. Каждая запись хранит
имена, размеры и **несколько меток времени** (создание, изменение, доступ). Из MFT
можно восстановить, какие файлы создавались и удалялись, даже если записи уже нет:

```bash
$ MFTECmd.exe -f case/\$MFT --csv out/
RecordNumber  ParentPath  FileName      Created                 Modified
12948         .\Users\Public\  update.ps1  2024-06-14 09:39:02  2024-06-14 09:39:02
```

`update.ps1` создан в 09:39 — за две минуты до первого запуска `rundll32`. Время
сходится, картина складывается.

## Собираем таймлайн

Сопоставим артефакты по времени:

```
09:39:02  update.ps1 создан в C:\Users\Public  (MFT)
09:40:58  вход Administrator с 10.10.10.50      (Security.evtx, 4624)
09:41:22  запущен powershell.exe               (память, pslist)
09:41:25  RUNDLL32.EXE запущен (3-й раз)       (Prefetch)
09:41:31  соединение с 185.220.101.44          (память, netscan)
```

Один и тот же инцидент, восстановленный из четырёх независимых источников. Именно
так работает **форензический таймлайн**: каждое событие подтверждается артефактом.

Если хотя бы одно звено не сходится (например, программа запускалась, но её файла
нет и в MFT, и в журнале) — это тоже результат: возможно, следы подчищали, а значит,
машиной интересовались не случайно. Противоречия в таймлайне часто ценнее, чем
гладкая картина.

## Ещё артефакты, которые стоит знать

Кроме Prefetch, реестра, EVTX и MFT, в Windows есть целый набор «следов»:

| Артефакт | Что показывает |
|----------|----------------|
| `ShimCache`/`AmCache` | какие программы система «видела» (даже удалённые) |
| `JumpLists` | недавно открытые файлы у пользователя |
| `SRUM` | сетевая активность приложений |
| `$UsnJrnl` | журнал всех файловых операций на NTFS |
| `LNK`-файлы | ссылки на недавно открытые файлы и съёмные диски |
| `WMI`-репозиторий | записи о запуске через WMI (скрытая персистентность) |

Каждый из них — отдельная тема, и им посвящены следующие уроки категории. Общее у
них одно: все они **фиксируют активность**, которую пользователь не замечает.

## Порядок разбора артефактов

Когда артефактов много, помогает порядок:

1. **Автозапуск** — реестр `Run`-ключи, службы, задачи планировщика (персистентность).
2. **Факты запуска** — Prefetch, ShimCache, AmCache.
3. **Пользовательская активность** — JumpLists, LNK, браузер.
4. **Журналы** — EVTX (входы, запуски процессов, очистка).
5. **Файловая система** — MFT, USN (создание и удаление файлов).
6. **Таймлайн** — сопоставление всего вышеперечисленного по времени.

Так ты сначала находишь «что было настроено», потом «что реально запускалось», и
только затем связываешь это с конкретными людьми и временем.

## Где брать артефакты и чем читать

В CTF артефакты обычно дают папкой или образом. В реальной работе их собирают с
живой машины специальными скриптами (например, `KAPE`/`triage`-коллекторами),
которые выгружают реестр, журналы, Prefetch и метаданные за один прогон.

Читать артефакты удобнее специализированными утилитами, а не глазами:

| Артефакт | Инструмент |
|----------|-----------|
| Prefetch | `PECmd` |
| Реестр (hives) | `RegRipper`, `Registry Explorer`, `regipy` |
| Журналы EVTX | `evtx_dump`, `EvtxECmd`, Event Viewer |
| MFT / USN | `MFTECmd` |
| Таймлайн | `Plaso` / `log2timeline` |

Все они умеют выгружать результат в CSV — удобно для фильтрации и построения
хронологии. В CTF часто достаточно одной-двух команд из этой таблицы.

## Что мы теперь знаем

- Prefetch доказывает факт запуска программы и время, даже если файл удалён.
- Реестр (hives) хранит автозапуск, настройки, USB-историю и хеши паролей.
- EVTX — журналы событий; EventID 4624/4625/4688/1102 — ключевые для IR.
- MFT содержит записи всех файлов с несколькими метками времени.
- Таймлайн строится сопоставлением нескольких артефактов по времени.

## Куда дальше

Мы разобрали Windows. Теперь симметрично посмотрим на **артефакты Linux** — историю
команд, cron, журналы входов — и соберём такую же картину для сервера. А пока
запомни: **каждый артефакт — это отдельная деталь, а история складывается из
их сопоставления по времени**.

## Где пригодится

- **CTF:** задачи с артефактами Windows и таймлайном.
- **Incident Response:** восстановление картины атаки на Windows.
- **Threat Hunting:** поиск персистентности и подозрительных запусков.
- **Malware analysis:** определение времени и контекста запуска образца.
- **Криминалистика:** доказательная реконструкция действий пользователя.
