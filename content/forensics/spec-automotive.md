## Вопрос, с которого всё начинается

ДТП или угон — нужно понять, что делала машина. Современный автомобиль — это десятки
компьютеров на колёсах. Данные разбросаны по **ЭБУ**, телематике и инфотейнменту.
Разберём.

## Наш пример: автомобиль после ДТП

## Шаг 1: блоки управления (ЭБУ)

ЭБУ (ECU) управляют двигателем, тормозами, подушками. Некоторые хранят данные:

- **EDR** (Event Data Recorder, «чёрный ящик») — скорость, тормоз, ремни за секунды до
  события;
- коды ошибок (DTC);
- счётчики.

## Шаг 2: телематика

Телематический блок (у подключённых машин) пишет GPS-треки, скорость, события:

```
2026-01-14T03:20:00Z  55.75,37.61  62km/h
2026-01-14T03:20:30Z  55.76,37.62  0km/h  HARD_BRAKE
```

Это готовый таймлайн поездки.

## Шаг 3: инфотейнмент

Мультимедиасистема — по сути Linux/Android:

- **сопряжённые телефоны** (BT, история);
- **навигация** (последние адреса);
- **звонки/контакты**;
- **медиа**.

Извлекают через штатные средства или снятием флеш.

## Шаг 4: шина CAN

Внутри машины блоки общаются по шинам CAN/FlexRay. Записывая CAN, видят команды:

```
$ candump can0
can0  0C9   [8]  00 00 00 00 00 00 00 00
```

Запись CAN — это «сырой» след поведения (нажатия, обороты, скорость).

## Шаг 5: инструменты

- вендорные/дилерские сканеры (OBD-II);
- специализированные наборы (Bosch CDR);
- разбор инфотейнмент-прошивки (`binwalk`).

## Что мы теперь знаем

- Автомобиль = сеть ЭБУ.
- EDR хранит данные за секунды до события.
- Телематика даёт GPS-трек и события.
- Инфотейнмент хранит телефоны, навигацию, звонки.
- CAN — сырой след поведения.

## Если не сработало

- Нет доступа к дилеру? Работай с инфотейнментом и телематикой.
- ЭБУ закрыт? Нужен вендорный доступ.
- Нужен трек? Смотри телематику и телефон владельца.

## Расширенный разбор: реконструкция поездки

Разберём, как из разрозненных источников собирается единый таймлайн. Начнём с
телематического блока — он пишет записи с GPS и событиями:

```bash
$ python3 -c "import json;d=json.load(open('telemetry.json'));print(len(d['trips']))"
37
$ jq -r '.trips[-1].points[] | "\(.ts) \(.lat),\(.lon) \(.speed) \(.event)"' telemetry.json | head
2026-01-14T03:19:58Z 55.7501,37.6102 61 CRUISE
2026-01-14T03:20:00Z 55.7510,37.6115 62 CRUISE
2026-01-14T03:20:30Z 55.7602,37.6231 0 HARD_BRAKE
2026-01-14T03:20:31Z 55.7603,37.6233 0 STOP
```

Запись `HARD_BRAKE` с падением скорости до нуля — маркер события. Сверяем со
временем в EDR (Event Data Recorder), который хранит последние ~5 секунд:

```
t=-5s  speed 61 km/h  throttle 12%  brake 0%
t=-2s  speed 58 km/h  throttle 0%   brake 40%
t= 0s  speed 0 km/h   throttle 0%   brake 100%  seatbelt=on
```

Совпадение меток времени (с поправкой на часовой пояс блока) подтверждает
событие. Третьим источником служит инфотейнмент: он пишет, какой телефон был
сопряжён и куда шла навигация.

```bash
$ sqlite3 infotainment.db "SELECT name,last_connected FROM paired_devices;"
iPhone-Алексея|2026-01-14 03:15:12
```

## Справочная таблица: где какие данные автомобиля

| Источник | Что хранит | Глубина | Доступ |
|---|---|---|---|
| EDR (ЭБУ) | скорость, тормоз, ремни | ~5 с до события | дилерский сканер |
| Телематика | GPS-трек, события | недели–месяцы | облако/блок |
| Инфотейнмент | телефоны, навигация, звонки | месяцы | флеш/штатно |
| CAN-лог | сырые кадры шины | зависит от записи | запись шины |
| DTC | коды ошибок | до сброса | OBD-II |

## Краевые случаи и юридические ограничения

- **Часовые пояса и дрейф часов.** ЭБУ и телематика часто живут в UTC, а
  инфотейнмент — в локальном времени. Сверяй смещение, иначе таймлайн «съедет».
- **Циклический буфер.** EDR перезаписывает старые события; после нескольких
  поездок данные ДТП могут быть утеряны.
- **CAN без меток времени.** `candump` пишет с временем хоста-логгера, а не
  самой машины; привязка к реальному времени требует синхронизации.
- **Правовые рамки.** Доступ к EDR обычно требует согласия владельца или
  официального запроса; снятие инфотейнмента — это вмешательство в устройство.
- **Идентификация блока.** Номер VIN связывает данные с конкретной машиной;
  проверь, что образ снят именно с неё.

## Практический разбор: разбор прошивки инфотейнмента

Когда штатных средств мало, снимают флеш инфотейнмента и разбирают её. Первым
делом определяем состав и распаковываем вложенные образы:

```bash
$ binwalk infotainment.bin
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             Squashfs filesystem, little endian
5242880       0x500000        gzip compressed data
```

Squashfs монтируется напрямую, и внутри находятся базы данных приложений:

```bash
$ sudo mount -o loop,offset=0 infotainment.bin /mnt/iu
$ ls /mnt/iu/data/
navigation.db  contacts.db  bluetooth.conf
```

База навигации хранит последние адреса — это готовый маршрут владельца:

```bash
$ sqlite3 /mnt/iu/data/navigation.db "SELECT name,ts FROM recent_destinations ORDER BY ts DESC LIMIT 3;"
Дом, Москва|2026-01-13 22:40:11
Кафе, Тверская|2026-01-13 19:02:44
```

## Типичные сценарии расследования

- **Угон.** Сопоставляют GPS-трек телематики с временем срабатывания
  сигнализации и CAN-событиями открытия дверей.
- **ДТП.** EDR даёт последние секунды (скорость, тормоз, ремни), телематика —
  контекст поездки, инфотейнмент — отвлечение (звонок, музыка).
- **Мошенничество с пробегом.** Сравнивают одометр из ЭБУ, телематики и
  сервисной истории: расхождение — признак скрутки.
- **Утечка данных компании.** Инфотейнмент сопряжённых телефонов может
  раскрыть, кто и когда был в машине.

## Ограничения и типичные ошибки

- **Дрейф часов и пояса.** Всегда фиксируй смещение каждого блока относительно
  UTC, иначе таймлайн «поедет» на часы.
- **Циклический буфер.** EDR хранит лишь последние секунды; после нескольких
  поездок данные ДТП перезаписываются.
- **Разные форматы CAN.** Расшифровка кадров требует DBC-файла конкретной
  модели; без него значения — просто байты.
- **Юридические рамки.** Снятие блоков и чтение EDR обычно требует согласия
  владельца или официального ордера.
- **Целостность.** Снимай полный образ носителя, а не отдельные файлы, и
  фиксируй хэш, иначе доказательство оспорят.

## Расширенный пример: сопоставление CAN и телематики

Сырой лог шины выглядит как поток кадров без семантики. Применим DBC-файл
модели и получим расшифрованные сигналы:

```bash
$ candump -L can0 > can.log
$ python3 -m cantools decode vehicle.dbc < can.log | head
(0.000000) engine_rpm: 812
(0.010000) vehicle_speed: 61 km/h
(0.500000) brake_pressure: 0 bar
(1.200000) brake_pressure: 96 bar
```

Резкий рост `brake_pressure` в момент, когда телематика фиксирует
`HARD_BRAKE`, — это независимое подтверждение события. Сопоставляем время:

```bash
$ paste <(grep -o '^[0-9.]*' can_brake.txt) <(jq -r '.trips[-1].points[]|.ts' telemetry.json) | tail -3
1.200  2026-01-14T03:20:30Z
1.210  2026-01-14T03:20:30Z
```

Совпадение по времени (с учётом дрейфа) закрывает вопрос: событие реально.

## Контрольный список автомобильной форензики

- [ ] Зафиксировать VIN и идентификаторы блоков.
- [ ] Снять полный образ инфотейнмент-носителя, посчитать хэш.
- [ ] Извлечь EDR-данные дилерским сканером (с согласия/ордера).
- [ ] Выгрузить телематику из облака/блока.
- [ ] Записать CAN, если есть физический доступ и DBC.
- [ ] Свести все источники в единый UTC-таймлайн.
- [ ] Проверить расхождения одометра и часов.
- [ ] Оформить chain of custody.

## Что показывает каждый блок детально

| Блок | Данные | Типичный интервал | Нюанс |
|---|---|---|---|
| Engine ECU | обороты, нагрузка, температура | мс | стирается быстро |
| EDR | скорость, тормоз, ремни | ~5 с до события | циклический буфер |
| Телематика | GPS, события, диагностика | секунды | зависит от покрытия |
| Infotainment | телефоны, навигация | по событию | хранит долго |
| Body ECU | двери, свет, замки | по событию | полезно для угона |

## Ограничения и типичные ошибки

- **DBC не от той модели.** Расшифровка даст правдоподобный, но неверный
  результат — проверяй соответствие DBC и VIN.
- **Отсутствие GPS-покрытия.** Трек телематики может иметь разрывы (тоннели,
  подземные парковки); не принимай пропуск за «машина стояла».
- **Часовые пояса.** ЭБУ в UTC, инфотейнмент в локали; без нормализации
  таймлайн «разъедется».
- **Одометр и ЭБУ.** Скрутка пробега не меняет внутренние счётчики — ищи
  расхождение между панелью и блоками.
- **Юридические ограничения.** Чтение EDR без ордера/согласия недопустимо;
  фиксируй правовое основание доступа.

## Проверка результата

Убедись, что таймлайн согласован по независимым источникам:

```bash
$ sort -k1 timeline.csv | head -4
2026-01-14T03:19:58Z,telemetry,CRUISE,61km/h
2026-01-14T03:20:00Z,telemetry,CRUISE,62km/h
2026-01-14T03:20:30Z,telemetry,HARD_BRAKE,0km/h
2026-01-14T03:20:30Z,edr,brake=100%,seatbelt=on
```

Совпадение метки события в двух источниках — признак достоверности. Если EDR и
телематика расходятся больше чем на секунду, проверь часовые пояса и дрейф.

## Что записать в отчёт

- VIN и идентификаторы блоков, с которых снят образ.
- Хэши образов и метод извлечения (штатно/дилерский сканер).
- Реконструированный таймлайн с указанием источника каждой точки.
- Расхождения между одометром, ЭБУ и сервисной историей.
- Правовое основание доступа и цепочка сохранности.
- Ограничения: отсутствие DBC, разрывы GPS, дрейф часов.

## Таблица источников и методов извлечения

| Источник | Метод | Ограничение |
|---|---|---|
| EDR (ЭБУ) | дилерский сканер | циклический буфер ~5 с |
| Телематика | облако/блок | зависит от покрытия |
| Инфотейнмент | снятие флеш | разбор прошивки |
| CAN | запись шины | нужен DBC |
| DTC | OBD-II | сбрасывается |
| Одометр | сканер | скручивается |

Сопоставление минимум двух независимых источников делает вывод устойчивым.
