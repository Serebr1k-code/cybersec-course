## Что такое zsteg и как он устроен

`zsteg` — Ruby-инструмент для системного перебора **LSB-каналов** в PNG и BMP. Он не «угадывает» метод, а перебирает десятки комбинаций и печатает то, что похоже на текст, файл или просто данные. Установка:

```bash
sudo gem install zsteg
zsteg --version
```

Модель каналов zsteg описывается строкой вида `b1,rgb,lsb,xy`:

- **`b1`/`b2`/`b4`** — сколько младших бит на канал брать (1, 2 или 4).
- **`rgb`/`rgba`/`bgr`/`abgr`** — порядок каналов.
- **`lsb`/`msb`** — читать с младшего или старшего бита.
- **`xy`/`yx`** — порядок обхода пикселей (по строкам или по столбцам).

`zsteg` пробует все осмысленные сочетания и для каждого показывает, что нашлось.

## Синтаксис zsteg и все полезные флаги

```bash
zsteg file.png                 # авто-скан (b1,rgb,lsb,xy и др.)
zsteg -a file.png              # все известные комбинации (медленнее, полнее)
zsteg -l 0 file.png            # ограничить глубину/длину
zsteg -E 'b1,rgb,lsb,xy' file.png > out.bin   # извлечь конкретный канал
zsteg -e 'b1,rgb,lsb,xy' file.png             # печать с декодированием (text)
zsteg --min-str-len 8 file.png # минимальная длина строки для показа
zsteg -s all file.png          # включить все «странные» каналы
```

Ключевые флаги:

| Флаг | Смысл |
|---|---|
| `-a` | перебрать все комбинации (не только базовые) |
| `-E <chan>` | extract — выгрузить канал в файл |
| `-e <chan>` | вывести канал с попыткой декодировать |
| `-l <n>` | глубина/порог |
| `-s <state>` | фильтр по состоянию (all/…) |
| `-b <n>` | число бит по умолчанию |

## Чтение вывода zsteg

Вывод — список строк вида `[?] <канал> .. <тип>: <данные>`. Типы:

- `text:` — печатаемая строка (частый флаг/подсказка).
- `file:` — распознан сигнатурой (PE, ZIP, PNG).
- `zlib:` — zlib-поток, распаковывается автоматически.
- `image:` — вложенное изображение.

```bash
$ zsteg cat.png
[?] 0 b1,rgb,lsb,xy       .. text: "flag{lsb_1bit}"
[?] 0 b2,rgb,lsb,xy       .. text: "!x]p... (garbage)"
[?] 0 b1,rgba,lsb,xy      .. file: PNG image data, 16 x 16
```

Первый результат — готовый флаг. Третий — вложенная картинка, её нужно извлечь:

```bash
zsteg -E 'b1,rgba,lsb,xy' cat.png > inner.png
file inner.png
```

## stegsolve: визуальные плоскости

`stegsolve` — Java-приложение, показывает **битовые плоскости** и цветовые каналы визуально. Полезно, когда данные — не текст, а «картинка в канале» (QR, надпись, схема). Управление стрелками: переключение каналов (R/G/B/A), битов (0–7), режимов (LSB, XOR, AND, OR, subtract).

```bash
java -jar stegsolve.jar
# File → Open → cat.png
# Стрелки: Channel, Bit Plane, Frame; сохранить найденную плоскость
```

Аналог без GUI — генерация плоскостей скриптом:

```python
from PIL import Image
import numpy as np
img = np.array(Image.open('cat.png').convert('RGBA'))
for bit in range(8):
    plane = ((img >> bit) & 1) * 255
    Image.fromarray(plane.astype('uint8')).save(f'plane_{bit}.png')
```

## Методология: от zsteg к ручному скрипту

Порядок работы:

1. `zsteg -a file.png` — быстрый полный скан.
2. Если есть подозрительный канал — `zsteg -E` в файл, затем `file`/`strings`.
3. Если zsteg пуст, но задача «на LSB» — сгенерируйте битовые плоскости (скрипт выше) и просмотрите их глазами.
4. Если данные визуальны (QR/текст в плоскости) — декодируйте (zbar/OCR).
5. Если канал нестандартный — напишите свой обход (порядок, размер бит, interlace).

## Разобранный пример: двухслойная задача

```bash
$ zsteg -a mystery.png | grep -iE 'file|text|zlib' | head
[?] 0 b1,rgb,lsb,xy  .. zlib: data
[?] 1 b1,rgb,lsb,xy  .. text: "pass: hunter2"
$ zsteg -E 'b0,rgb,lsb,xy' mystery.png > layer.zip
$ file layer.zip
layer.zip: Zip archive data
$ unzip -P hunter2 layer.zip
Archive: layer.zip
 extracting: flag.txt
$ cat flag.txt
flag{zsteg_two_layers}
```

Здесь zsteg нашёл и пароль (текст), и вложенный ZIP (zlib-поток). Это типичная двухслойная схема: сначала извлечение, затем расшифровка.

## Ограничения и подводные камни

- **`zsteg` не работает с JPEG** — только PNG/BMP (в JPEG данные в DCT, нужен `jsteg`/`outguess`/`stegdetect`).
- **Базовый скан (`zsteg file`) неполон** — используйте `-a`.
- **Ложные срабатывания**: случайные пиксели дают «текст» из мусора. Проверяйте осмысленность (флаг/URL/пароль).
- **Interlaced (Adam7) PNG** — порядок обхода другой; zsteg это учитывает не всегда, проверяйте вручную.
- **Не тот порядок каналов** — если результат «почти текст», попробуйте `bgr`, `yx`, `msb`.
- **Извлечение в бинарный файл**, а не в stdout — чтобы не испортить данные.

## Глубокий разбор каналов: за пределами базовых

`zsteg` перебирает стандартные схемы, но существуют варианты, которые он показывает только с `-a` или не показывает вовсе:

- **Мультибитный LSB** (`b2`, `b4`) — 2 или 4 младших бита на канал. Ёмкость выше, заметность тоже.
- **MSB-режим** — иногда данные прячут в **старших** битах (редко, но бывает).
- **Нестандартный порядок** — `bgr`, `yx`, interlace (Adam7).
- **Палитровые PNG** — данные в индексах палитры, а не в RGB.
- **Alpha-канал** — данные в прозрачности (см. урок про alpha).

Пример извлечения 2 младших бит вручную:

```python
from PIL import Image
import numpy as np
img = np.array(Image.open('cat.png').convert('RGB'))
flat = img.reshape(-1, 3)
bits = ''.join(format(int(v) & 0b11, '02b') for v in flat.flatten())
out = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(out[:64])
```

Если результат «почти текст» — переберите порядок бит (MSB-first/LSB-first) и порядок каналов.

## zsteg vs stegsolve vs собственный скрипт

Выбор инструмента зависит от типа данных:

| Ситуация | Инструмент |
|---|---|
| Текст/файл в стандартном канале | `zsteg -a` |
| Визуальный образ (QR, надпись) в плоскости | `stegsolve` |
| Нестандартный порядок/биты | собственный скрипт |
| Данные в alpha/палитре | скрипт + `pngcheck` |
| Парольная стеганография (JPEG/BMP) | `steghide`/`stegseek` |

`stegsolve` незаменим, когда данные — **изображение**, а не строка: человеческий глаз мгновенно видит QR-код или текст в битовой плоскости. `zsteg` хорош для текста/файлов. Скрипт — когда оба бессильны.

## Ёмкость и почему zsteg иногда «не видит»

`zsteg` показывает только те каналы, где данные **похожи** на текст/файл (по энтропии и печатаемости). Если данные зашифрованы или это чистый бинарный блоб, он может их «не заметить». Признак: канал выглядит как случайный шум.

Что делать в таком случае:

1. Извлечь канал `-E` в файл и посмотреть `file`, `strings`, энтропию.
2. Проверить, не зашифрован ли блоб (XOR, base64, gzip-сигнатуры).
3. Оценить ёмкость: если файл слишком велик для своего разрешения — данные точно есть, ищите дописанное (`binwalk`).

```bash
zsteg -E 'b1,rgb,lsb,xy' cat.png > ch.bin
file ch.bin; entropy ch.bin 2>/dev/null || python3 -c "import sys;from collections import Counter;d=open('ch.bin','rb').read();import math;c=Counter(d);print(-sum(n/len(d)*math.log2(n/len(d)) for n in c.values()))"
```

Высокая энтропия (~8 бит/байт) — признак шифрования или сжатия, значит следующий этап — снять шифрование/распаковать.

## Быстрый справочник каналов zsteg

Компактная шпаргалка, которую удобно держать под рукой при разборе PNG:

```bash
zsteg file.png                      # авто: b1,rgb,lsb,xy и соседние
zsteg -a file.png                   # полный перебор всех схем
zsteg -E 'b1,rgb,lsb,xy' file.png   # извлечь канал в файл
zsteg -E 'b2,bgr,msb,yx' file.png   # 2 бита, порядок BGR, MSB, по столбцам
zsteg -E 'b1,rgba,lsb,xy' file.png  # учесть alpha
zsteg -l 100 file.png               # ограничить длину
zsteg -s all file.png               # показать все «странные» каналы
```

Мнемоника строки канала: `<биты>,<каналы>,<lsb|msb>,<xy|yx>`. Если стандартный скан пуст, а файл явно «с секретом» — перебирайте `bgr`, `yx`, `msb` и мультибитные варианты; для визуальных данных переходите на битовые плоскости (`stegsolve` или скрипт).

## Типичные признаки и быстрый triage

- `file` говорит PNG/BMP, но размер заметно больше ожидаемого для разрешения — данные почти наверняка есть.
- Базовый `zsteg` даёт «text», похожий на мусор, — попробуйте `-a` и другие порядки каналов.
- В выводе есть `zlib:` или `file:` — это вложенный контейнер, извлекайте `-E`.
- Всё пусто — переходите к `binwalk`, `exiftool`, `pngcheck` и битовым плоскостям.
- Помните: `zsteg` — инструмент для PNG/BMP; для JPEG он бесполезен.

## Что делать дальше / решение

- `zsteg -a` — первый шаг для любого PNG/BMP.
- Нашли `text:` — читайте; `file:` — извлекайте `-E` и разбирайте `file`/`strings`.
- Пусто — битовые плоскости скриптом + визуальный осмотр (stegsolve).
- Всё ещё пусто — проверьте `binwalk` (дописанное), `exiftool` (метаданные), `pngcheck` (чанки).
- Данные визуальны — `zbarimg`/OCR.
- Не PNG/BMP — переходите к инструментам под JPEG/аудио/документы.
