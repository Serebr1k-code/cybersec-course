## Вопрос, с которого всё начинается

Ты открываешь PNG-картинку и понимаешь: данные где-то в младших битах. Но вариантов много: какой канал (R/G/B/A), какой бит, какой порядок обхода, сколько бит на канал. Перебирать вручную долго и легко запутаться.

Для этого есть `zsteg` — он **системно перебирает** десятки комбинаций. А `stegsolve` показывает каналы глазами. Разберём оба на одном файле.

## Наш пример: cat.png

```
$ file cat.png
cat.png: PNG image data, 256 x 256, 8-bit/color RGBA, non-interlaced
```

PNG 256×256, четыре канала (RGBA). Запустим `zsteg`:

```
$ zsteg cat.png
[?] 0 b1,rgb,lsb,xy       .. text: "flag{zsteg_1bit}"
[?] 0 b1,rgba,lsb,xy      .. file: PNG image data, 16 x 16
```

Первая строка — готовый флаг. Вторая — вложенная картинка 16×16. Обе находки получены автоматически. Разберём, что означают эти строки.

## Шаг 1: как читать модель канала

Строка вида `b1,rgb,lsb,xy` — это описание способа извлечения:

- **`b1`/`b2`/`b4`** — сколько младших бит на канал брать;
- **`rgb`/`rgba`/`bgr`/`abgr`** — порядок каналов;
- **`lsb`/`msb`** — читать с младшего или старшего бита;
- **`xy`/`yx`** — порядок обхода пикселей (по строкам или столбцам).

`zsteg` сам пробует осмысленные сочетания и печатает то, где нашлись данные. Типы в выводе:

- `text:` — печатаемая строка (флаг/подсказка);
- `file:` — распознано сигнатурой (ZIP, PNG);
- `zlib:` — сжатый поток, распаковывается автоматически;
- `image:` — вложенное изображение.

## Шаг 2: полезные флаги zsteg

| Флаг | Смысл |
|---|---|
| `-a` | перебрать **все** комбинации, а не только базовые |
| `-E <chan>` | extract — выгрузить канал в файл |
| `-e <chan>` | вывести канал с попыткой декодировать |
| `-l <n>` | ограничить длину |
| `-s all` | показать все «странные» каналы |

Важно: базовый `zsteg file.png` перебирает не всё. Полный скан — с `-a`:

```
$ zsteg -a cat.png
```

## Шаг 3: извлекаем найденное

Найденный канал `file:` (вложенная картинка) нужно выгрузить в файл:

```
$ zsteg -E 'b1,rgba,lsb,xy' cat.png > inner.png
$ file inner.png
inner.png: PNG image data, 16 x 16
```

Дальше разбираем `inner.png` как обычное изображение — возможно, там следующий слой.

## Шаг 4: stegsolve — визуальные плоскости

`zsteg` хорош для текста и файлов, но если данные — **картинка в канале** (QR, надпись, схема), лучше смотреть глазами. `stegsolve` — Java-приложение, показывающее битовые плоскости и каналы.

```
$ java -jar stegsolve.jar
# File → Open → cat.png
# Стрелки: Channel (R/G/B/A), Bit Plane (0-7), режимы (LSB/XOR/AND/OR)
```

Аналог без GUI — генерация плоскостей скриптом:

```python
from PIL import Image
import numpy as np
img = np.array(Image.open('cat.png').convert('RGBA'))
for bit in range(8):
    plane = ((img >> bit) & 1) * 255
    Image.fromarray(plane.astype('uint8')).save(f'plane_{bit}.png')
```

Открой полученные `plane_*.png`: если вместо шума видна надпись — данные там.

## Шаг 5: методология

1. `zsteg -a file.png` — быстрый полный скан.
2. Есть `text:` — читай; `file:`/`zlib:` — извлекай `-E` и разбирай `file`/`strings`.
3. zsteg пуст, но задача «на LSB» — сгенерируй битовые плоскости и посмотри глазами.
4. Данные визуальны (QR/текст) — декодируй (`zbarimg`/OCR).
5. Канал нестандартный — напиши свой обход (порядок, биты, interlace).

## Шаг 6: почему zsteg иногда «не видит»

`zsteg` показывает только каналы, где данные **похожи** на текст/файл (по энтропии и печатаемости). Если данные зашифрованы или это чистый бинарный блоб, он может их пропустить. Тогда:

```
$ zsteg -E 'b1,rgb,lsb,xy' cat.png > ch.bin
$ file ch.bin
$ python3 -c "import math;from collections import Counter;d=open('ch.bin','rb').read();c=Counter(d);print(-sum(n/len(d)*math.log2(n/len(d)) for n in c.values()))"
```

Энтропия ~8 бит/байт — признак шифрования или сжатия: следующий шаг — снять шифрование/распаковать.

## Ограничения

- **`zsteg` не работает с JPEG** — только PNG/BMP (в JPEG нужны `jsteg`/`outguess`).
- **Базовый скан неполон** — используй `-a`.
- **Ложные срабатывания** — случайные пиксели дают «текст» из мусора; проверяй осмысленность.
- **Interlaced (Adam7) PNG** — другой порядок обхода; проверяй вручную.
- **Мультибитный LSB** (`b2`, `b4`) и **alpha-канал** — варианты, которые легко пропустить.

## Что мы теперь знаем

1. `zsteg` системно перебирает LSB-каналы PNG/BMP.
2. Строка канала: `<биты>,<каналы>,<lsb|msb>,<xy|yx>`.
3. `-a` — полный скан, `-E` — извлечь конкретный канал.
4. `stegsolve` показывает битовые плоскости визуально.
5. Если данные зашифрованы, zsteg может их не показать — смотри энтропию.

## Шаг 7: быстрый справочник каналов zsteg

Компактная шпаргалка, которую удобно держать под рукой при разборе PNG:

```bash
zsteg file.png                      # авто: b1,rgb,lsb,xy и соседние
zsteg -a file.png                   # полный перебор всех схем
zsteg -E 'b1,rgb,lsb,xy' file.png   # извлечь канал в файл
zsteg -E 'b2,bgr,msb,yx' file.png   # 2 бита, порядок BGR, MSB, по столбцам
zsteg -E 'b1,rgba,lsb,xy' file.png  # учесть alpha
zsteg -l 100 file.png               # ограничить длину
zsteg -s all file.png               # показать все «странные» каналы
```

Мнемоника строки канала: `<биты>,<каналы>,<lsb|msb>,<xy|yx>`. Если стандартный скан пуст, а файл явно «с секретом» — перебирай `bgr`, `yx`, `msb` и мультибитные варианты.

## Шаг 8: типичные признаки и быстрый triage

- `file` говорит PNG/BMP, но размер заметно больше ожидаемого для разрешения — данные почти наверняка есть.
- Базовый `zsteg` даёт «text», похожий на мусор, — попробуй `-a` и другие порядки каналов.
- В выводе есть `zlib:` или `file:` — это вложенный контейнер, извлекай `-E`.
- Всё пусто — переходи к `binwalk`, `exiftool`, `pngcheck` и битовым плоскостям.
- Помни: `zsteg` — инструмент для PNG/BMP; для JPEG он бесполезен.

## Шаг 9: извлечение нестандартного канала вручную

Пример извлечения 2 младших бит на канал, если `zsteg` не показал нужную комбинацию:

```python
from PIL import Image
import numpy as np
img = np.array(Image.open('cat.png').convert('RGB'))
bits = ''.join(format(int(v) & 0b11, '02b') for v in img.reshape(-1, 3).flatten())
out = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(out[:64])
```

Если результат «почти текст» — перебери порядок бит (MSB-first/LSB-first) и порядок каналов.

## Шаг 10: ёмкость и почему zsteg иногда «не видит»

`zsteg` показывает только те каналы, где данные **похожи** на текст/файл (по энтропии и печатаемости). Если данные зашифрованы или это чистый бинарный блоб, он может их пропустить. Тогда:

