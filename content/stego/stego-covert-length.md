## Вопрос, с которого всё начинается

Ты смотришь `len.pcap` и видишь обычный HTTP: запросы к одному серверу, нормальные заголовки, нормальные ответы. Ни одной подозрительной строки. `strings` чист. Но задача говорит, что данные утекли. Как передать информацию, **не меняя содержимое пакетов**?

Ответ: кодировать её в **метаданных** — длине пакета, энтропии или интервалах. Содержимое остаётся легитимным, поэтому сигнатурные IDS молчат. Разберём это на нашем pcap.

## Наш пример: len.pcap

Самый незаметный класс скрытых каналов вообще не трогает payload. Вместо этого данные кодируются в наблюдаемых величинах. Начнём с длины — выведем длины всех HTTP-запросов:

```bash
$ tshark -r len.pcap -Y 'http.request' -T fields -e frame.len -e ip.len -e data.len | head
102  60  40
108  66  46
97   55  35
103  61  41
123  81  61
125  83  63
```

Заметь: длины явно «прыгают» по значениям, близким к ASCII-кодам. Собираем их как байты:

```python
lens = [102, 108, 97, 103, 123, 125]  # 'flag{}'
print("".join(chr(x) for x in lens))
```

```bash
$ python3 len.py
flag{}
```

Каждый пакет нёс **один символ** флага в своей длине. Это простейшая схема — «длина = код символа».

## Шаг 1: каналы по энтропии

**Энтропия** блока — мера его случайности, от 0 до 8 бит на байт. Сжатый или зашифрованный блок даёт высокую энтропию (~8), текстовый — низкую (~4). Модулируя, сжимаем ли мы блок, кодируют биты: высокая энтропия = `1`, низкая = `0`.

```python
import math, collections
def entropy(b: bytes) -> float:
    c = collections.Counter(b); n = len(b)
    return -sum((v/n) * math.log2(v/n) for v in c.values())
```

Если энтропия блоков чередуется между двумя уровнями с периодом — это сигнал канала. Детект строится на **скользящей энтропии**: ищут искусственные скачки.

## Шаг 2: тайминги и интервалы

Данные кодируются межпакетным интервалом: короткая пауза = `0`, длинная = `1`. Выведем интервалы:

```bash
$ tshark -r timing.pcap -Y 'tcp.port==443' -T fields -e frame.time_delta
0.02
0.21
0.03
0.22
0.02
```

Пороговое решение: `delta > threshold` → `1`.

```python
deltas = [0.02, 0.21, 0.03, 0.22, 0.02]
bits = "".join("1" if d > 0.1 else "0" for d in deltas)
print(bits)
```

Тайминг — самый медленный, но самый незаметный канал.

## Шаг 3: схемы кодирования длины

Схема «длина = код символа» ёмкая, но заметная: гистограмма длин становится мультимодальной. Более скрытные варианты:

- **Бинарная модуляция** — два «нормальных» размера `L` и `L+1` кодируют 0 и 1;
- **Мультисимвольная** — k размеров кодируют `log2(k)` бит;
- **Маскировка под естественный трафик** — размеры берутся из реального распределения, кодируется отклонение.

```python
lens = [512, 513, 512, 513, 513, 512]
bits = "".join("0" if x == 512 else "1" for x in lens)
print(bits)
```

## Шаг 4: детект статистикой

Каналы по метаданным выдают себя статистически:

1. **Гистограмма длин** — аномальные пики или периодичность;
2. **Распределение `frame.time_delta`** — бимодальность;
3. **Энтропия payload во времени** — скачкообразность;
4. **Сравнение с эталонным профилем** приложения.

```bash
$ tshark -r x.pcap -T fields -e frame.len | sort -n | uniq -c | sort -rn | head
$ capinfos capture.pcap | grep -iE 'packet size|average'
```

Визуализация помогает глазами увидеть бимодальность:

```python
import matplotlib.pyplot as plt
plt.hist(deltas, bins=50); plt.savefig("delta_hist.png")
```

## Шаг 5: почему это плохо ловится

Канал по метаданным — частный случай «скрытого канала»: отправитель и получатель используют наблюдаемую среду так, что наблюдатель не может отличить наличие сообщения от его отсутствия. Содержимое не меняется, а наблюдаемые величины (длина, интервал) и так варьируются — сторож не может быть уверен. Поэтому такие каналы требуют **статистического**, а не сигнатурного детекта.

| Свойство | Содержимое (payload) | Метаданные (длина/тайминг) |
|---|---|---|
| Ёмкость | высокая | низкая–средняя |
| Заметность для IDS | средняя | очень низкая |
| Устойчивость к шуму | высокая | низкая |
| Сложность детекта | средняя | высокая (статистика) |

## Если не сработало

- **Смотришь только содержимое** — канал живёт в метаданных.
- **Считаешь сеть идеально равномерной** — джиттер и потери мешают, нужна коррекция.
- **Забыл о порядке** — собирай пакеты по времени/номеру.
- **Путаешь `frame.len` / `ip.len` / `data.len`** — учитывай, что именно кодируется.
- **Не проверил энтропию** — сжатые данные дают высокую энтропию естественно.
- **Путаешь канал с шумом** — нужен эталон.

## Таблица каналов по метаданным

| Канал | Кодирует | Ёмкость | Детект |
|---|---|---|---|
| Длина пакета | байт/биты | высокая | гистограмма длин |
| Энтропия | биты | средняя | энтропия во времени |
| Межпакетный интервал | 1 бит | низкая | распределение delta |
| Порядок пакетов | log2(n!) | средняя | аномалии sequence |
| Комбинированный | смешанно | высокая | многомерная статистика |

## Тайминг и коррекция ошибок

Тайминг — самый медленный канал, и шум сети мешает: задержки варьируются, получатель может ошибиться. Решения: большой разрыв между «0» и «1», избыточность и коды с коррекцией (Хэмминг, повтор), преамбула из известных интервалов для синхронизации, намеренно медленная скорость ради надёжности.

## Практический сценарий детекта

1. Профилировать нормальный трафик приложения (эталон).
2. Сравнить распределение длин и интервалов с эталоном.
3. Найти статистически значимые отклонения (тест хи-квадрат).
4. Проверить периодичность: канал даёт ритм.
5. Собрать байты по найденной схеме и декодировать.

Такой пайплайн отличает канал от естественного шума и подтверждает находку до отчёта.

## Шаг 6: полный разбор `len.pcap` от начала до конца

Соберём маршрут в одну историю:

```bash
# 1. убедиться, что содержимое чисто
$ strings len.pcap | head
$ tshark -r len.pcap -Y 'http.request' -T fields -e http.host | sort -u
# 2. вывести длины всех запросов
$ tshark -r len.pcap -Y 'http.request' -T fields -e ip.len > lens.txt
$ sort -n lens.txt | uniq -c | sort -rn | head
# 3. собрать как байты (в порядке времени)
$ python3 -c "print(''.join(chr(int(l)) for l in open('lens.txt')))"
flag{length_channel}
```

Порядок важен: сначала исключаем «обычные» каналы (payload, DNS, HTTP-заголовки), потом смотрим на
метаданные. Если длины группируются в узком диапазоне — попробуй **бинарную модуляцию** (два размера
= 0/1); если разброс большой и совпадает с печатным ASCII — «длина = код символа». В нашем случае
именно второй вариант.

## Шаг 7: коррекция ошибок на практике

Метаданные-каналы шумные: сеть добавляет джиттер, пакеты теряются. Чтобы сообщение собралось,
используют те же приёмы, что и в любом ненадёжном канале:

- **преамбула** — известная последовательность интервалов/размеров для синхронизации получателя;
- **пороговое решение** — `delta > T` → 1, с запасом между уровнями;
- **повтор и коды с коррекцией** (Хэмминг, тройной повтор) — против потери бит;
- **снижение скорости** — чем медленнее канал, тем меньше ошибок.

На практике для CTF достаточно порогового решения; в реальных каналах добавляют преамбулу и ECC.

## Как это видят защитники

Детект метаданных-каналов — это статистика и эталон:

- **гистограмма длин** с аномальными пиками или периодичностью;
- **бимодальное распределение** `frame.time_delta` (два «пола» интервалов);
- **скачкообразная энтропия** payload во времени;
- **ритм**: канал даёт почти идеальную периодичность, которой нет в живом трафике;
- **сравнение с профилем** приложения (тест хи-квадрат).

Практика: профилируй нормальный трафик приложения заранее; всё, что статистически значимо
отклоняется, — на разбор. Для атакующего из этого следует: чем ближе размеры к естественному
распределению и чем менее ровный ритм, тем сложнее детект.

## Инструменты для статистического разбора

Для каналов по метаданным полезен не один `tshark`, а набор:

| Инструмент | Что даёт |
|---|---|
| `tshark -T fields` | выгрузка длин/интервалов в текст |
| `capinfos` | средние и максимальные размеры пакетов |
| `python + scapy` | полный контроль: свои метрики, порядок |
| `matplotlib`/`gnuplot` | гистограммы и графики ритма |
| `zsteg`/`binwalk` | если после декода получился файл |

Типовой скрипт-разбор на scapy:

```python
from scapy.all import rdpcap
pkts = rdpcap('len.pcap')
lens = [len(p) for p in pkts if p.haslayer('IP')]
print(''.join(chr(l) for l in lens if 32 <= l < 127))
```

Здесь мы берём длину каждого IP-пакета и, если она попадает в печатный ASCII, собираем символы. Это
самый быстрый способ проверить гипотезу «длина = код символа» до более сложных схем.

## Что мы теперь знаем

1. Данные можно кодировать в **метаданных**: длина, энтропия, интервалы.
2. Простейшая схема — «длина = код символа»; скрытнее — бинарная модуляция.
3. **Тайминг** медленный, но почти невидимый.
4. Каналы выдают себя **статистически**, а не сигнатурно.
5. Детект — гистограмма длин, распределение `time_delta`, энтропия во времени.
