Самый незаметный класс скрытых каналов вообще не трогает содержимое пакета. Вместо этого данные кодируются в метаданных: длине пакета, его энтропии, размере интервала между пакетами. Поскольку содержимое остаётся легитимным, такие каналы не ловятся сигнатурными IDS и часто выживают даже при полном контроле полезной нагрузки. Их слабое место — статистика: именно статистические аномалии выдают канал.

## Каналы по длине пакета

Идея: длина пакета (или размер полезной нагрузки) принимает несколько значений, и каждое кодирует символ. Простейшая схема — размер прямо равен байту сообщения. Более скрытная — два-три «нормальных» размера, между которыми переключаются для кодирования битов.

Пример: файл пересылается обычным HTTP-запросом, но каждый запрос имеет длину, равную коду символа флага. Собрав длины в порядке появления, получаем сообщение.

```bash
tshark -r len.pcap -Y 'http.request' -T fields -e frame.len -e ip.len -e data.len
```

Сборка байтов из длин:

```python
lens = [102, 108, 97, 103, 123, 125]  # 'flag{}'
print("".join(chr(x) for x in lens))
```

## Каналы по энтропии

Энтропия блока данных (например, полезной нагрузки) — число от 0 до 8 бит на байт. Модулируя энтропию (сжимая/не сжимая блок, добавляя шум), можно кодировать биты: высокая энтропия = `1`, низкая = `0`. Детектируется по нехарактерному распределению энтропии во времени.

```bash
tshark -r ent.pcap -Y 'tcp' -T fields -e frame.number -e data.len | head
```

Оценка энтропии блока в Python:

```python
import math, collections
def entropy(b: bytes) -> float:
    c = collections.Counter(b)
    n = len(b)
    return -sum((v/n) * math.log2(v/n) for v in c.values())
```

## Тайминговые каналы и интервалы

Данные кодируются межпакетным интервалом: короткая пауза = `0`, длинная = `1`. Чтобы канал не бросался в глаза, «единице» дают лишь слегка большую задержку, а кодирование идёт с избыточностью и коррекцией. Извлечение:

```bash
tshark -r timing.pcap -Y 'tcp.port==443' -T fields -e frame.time_delta
```

Затем пороговое решение: `delta > threshold` → `1`.

```python
deltas = [0.02, 0.21, 0.03, 0.22, 0.02]
bits = "".join("1" if d > 0.1 else "0" for d in deltas)
print(bits)
```

## Комбинированные каналы

На практике каналы комбинируют: длина кодирует младшие биты, тайминг — старшие, энтропия — служебные. Иногда используется **скрытая передача по порядку** (перестановка пакетов) — sequence-номера перемешиваются по заранее известной перестановке.

Ещё один вариант — **packet-size covert channel** в реальном времени: голосовой или игровой трафик с «плавающим» размером пакетов, где размеры формируют поток байт.

## Обнаружение и анализ

Статистические методы:

1. Гистограмма длин пакетов — аномальные пики/периодичность.
2. Распределение `frame.time_delta` — бимодальность.
3. Энтропия полезной нагрузки во времени — скачкообразность.
4. Корреляция длины с содержимым (обычно нет — при канале появляется).
5. Сравнение с эталонным профилем того же приложения.

```bash
tshark -r x.pcap -T fields -e frame.len | sort -n | uniq -c | sort -rn | head
```

Визуализация интервалов помогает глазами увидеть бимодальность:

```python
import matplotlib.pyplot as plt
# deltas — список межпакетных интервалов
plt.hist(deltas, bins=50); plt.savefig("delta_hist.png")
```

## Частые ошибки и подводные камни

- **Смотреть только содержимое.** Канал живёт в метаданных.
- **Считать сеть идеально равномерной.** Реальные джиттер и потери мешают, нужна коррекция.
- **Забыть о порядке.** Собирайте пакеты по времени/номеру.
- **Игнорировать длину после инкапсуляции.** Учитывайте `frame.len` vs `ip.len` vs `data.len`.
- **Не проверять энтропию.** Сжатые данные дают высокую энтропию естественно.
- **Путать канал с шумом.** Нужен эталон или статистика по объёму.

## Теоретические основы: модель скрытого канала

Канал по метаданным — частный случай «скрытого канала» в смысле Симмонса: два процесса, которые хотят общаться, используют наблюдаемую среду (сеть) так, что наблюдатель (IDS) не может отличить наличие сообщения от его отсутствия. Формально это игра: отправитель выбирает распределение наблюдаемых величин, получатель декодирует, а сторож проверяет гипотезу «есть канал / нет канала». Стойкость канала = близость распределений, ёмкость = сколько бит на пакет можно передать незаметно.

Именно поэтому каналы по длине/таймингу интересны: содержимое не меняется, а наблюдаемые величины (длина, интервал) и так варьируются, так что сторож не может быть уверен.

## Каналы по длине: схемы кодирования

Простейшая схема — «длина = код символа». Она ёмкая, но заметная: гистограмма длин становится мультимодальной. Более скрытные схемы:

- **Бинарная модуляция**: два «нормальных» размера `L` и `L+1` кодируют 0 и 1. Ёмкость 1 бит/пакет, распределение почти не меняется.
- **Мультисимвольная**: k размеров кодируют log2(k) бит. Компромисс между ёмкостью и заметностью.
- **Маскировка под естественный трафик**: размеры берутся из реального распределения приложения, а кодируется отклонение.

```python
# декодирование бинарной модуляции
lens = [512, 513, 512, 513, 513, 512]
bits = "".join("0" if x == 512 else "1" for x in lens)
print(bits)
```

## Каналы по энтропии

Энтропия блока — мера его случайности. Сжатый/зашифрованный блок даёт высокую энтропию (~8 бит/байт), текстовый — низкую (~4). Модулируя, сжимаем ли мы блок, кодируют биты. Детект: строят скользящую энтропию и ищут искусственные скачки.

```python
import math, collections
def H(b):
    c = collections.Counter(b); n = len(b)
    return -sum((v/n)*math.log2(v/n) for v in c.values())
```

Если энтропия чередуется между двумя уровнями с периодом — это сигнал канала.

## Тайминговые каналы и коррекция

Тайминг — самый медленный, но самый незаметный канал. Проблема — шум сети: задержки варьируются, и получатель может ошибиться. Решения:

- **Большой разрыв** между «0» и «1» (например, 10 мс против 50 мс) при низком джиттере.
- **Избыточность и коды с коррекцией** (Хэмминг, повтор).
- **Синхронизация** — преамбула из известных интервалов в начале.
- **Медленная скорость** — жертвуют пропускной способностью ради надёжности.

```python
# пороговое декодирование с преамбулой
deltas = [0.01,0.05,0.01,0.05]   # ...
thr = 0.03
bits = "".join("1" if d > thr else "0" for d in deltas)
```

## Сравнение с каналами в содержимом

| Свойство | Содержимое (payload) | Метаданные (длина/тайминг) |
|---|---|---|
| Ёмкость | высокая | низкая–средняя |
| Заметность для IDS | средняя | очень низкая |
| Устойчивость к шуму | высокая | низкая |
| Требует доступа | приложение | сетевой стек |
| Сложность детекта | средняя | высокая (статистика) |

Вывод: метаданные-каналы выбирают, когда содержимое контролируется, а сеть — нет; они медленные, но почти невидимые.

## Инструменты статистического анализа

- **`tshark`** — извлечение `frame.len`, `frame.time_delta`, `data.len`.
- **Python + numpy/pandas** — гистограммы, распределения, корреляции.
- **`matplotlib`/`gnuplot`** — визуализация бимодальности.
- **`capinfos`** — общая статистика pcap (средние, дисперсии).

```bash
capinfos capture.pcap | grep -iE 'packet size|duration|average'
tshark -r capture.pcap -T fields -e frame.len | sort -n | uniq -c | sort -rn | head
```

## Практический сценарий детекта

1. Профилировать нормальный трафик приложения (эталон).
2. Сравнить распределение длин и интервалов с эталоном.
3. Найти статистически значимые отклонения (тест хи-квадрат).
4. Проверить периодичность: канал даёт ритм.
5. Собрать байты по найденной схеме и декодировать.

Такой пайплайн отличает канал от естественного шума и подтверждает находку до отчёта.
