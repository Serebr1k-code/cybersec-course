## Вопрос, с которого всё начинается

В задаче дан только `txid` — идентификатор транзакции Bitcoin, и подсказка «данные вечны». Никаких файлов, только строка из 64 hex-символов. Как из номера транзакции достать флаг?

Ответ: данные записаны **внутрь самой транзакции** — в специальное поле `OP_RETURN`. Блокчейн хранит их навсегда, и любой может прочитать. Разберём это на нашем `txid`.

## Наш пример: txid

**Блокчейн** — публичный, неизменяемый и реплицированный реестр. Эти свойства делают его необычным носителем: данные нельзя удалить, их видит весь мир, и они доступны вечно. Прятать в блокчейне имеет смысл не «чтобы не увидели», а «чтобы нельзя было стереть».

Получим «сырую» транзакцию через публичный API (эксплорер):

```bash
$ curl -s https://blockstream.info/api/tx/<txid>/hex | head -c 200
0200000001...6a0b666c61677b626974636f696e7d...
```

В hex-строке уже видно подозрительное `6a0b` — это и есть `OP_RETURN` с длиной. Разберём подробнее.

## Шаг 1: OP_RETURN — главный канал

**OP_RETURN** — это опкод, который делает выход транзакции «непотрачиваемым» (provably unspendable). После него можно записать произвольные данные: `OP_RETURN <push data>`. Стандартный лимит — ~80 байт, но нестандартные транзакции несут больше.

В hex `OP_RETURN` = `0x6a`. Найдём его:

```bash
$ curl -s https://blockstream.info/api/tx/<txid>/hex | xxd -r -p | xxd | grep -i ' 6a'
00000110: 6a0b 666c 6167 7b62 6974 636f 696e 7d0a  j.flag{bitcoin}.
```

`6a` — OP_RETURN, `0b` — длина (11 байт), дальше данные. Декодируем hex:

```bash
$ echo 666c61677b626974636f696e7d | xxd -r -p
flag{bitcoin}
```

## Шаг 2: разбор через bitcoin-cli

Если есть доступ к узлу, разбор удобнее:

```bash
$ bitcoin-cli getrawtransaction <txid> true | jq '.vout[] | select(.scriptPubKey.asm|test("OP_RETURN"))'
{
  "scriptPubKey": {
    "asm": "OP_RETURN 666c61677b626974636f696e7d"
  }
}
```

`jq` фильтрует выходы, `select` оставляет только тот, где в скрипте есть `OP_RETURN`. Данные в hex — декодируем `xxd -r -p`.

## Шаг 3: другие поля Bitcoin

Данные прячут не только в OP_RETURN:

- **Скрипты входов** (`scriptSig`) — могут содержать произвольные данные;
- **`nLockTime` / `nSequence`** — 32-битные поля, кодирующие числа;
- **Суммы выходов** — набор значений кодирует байты;
- **Порядок входов/выходов** — перестановка кодирует биты;
- **Witness (SegWit)** — поля свидетеля менее ограничены по размеру.

```bash
$ bitcoin-cli getrawtransaction <txid> true | jq '.vin[].txinwitness'
```

## Шаг 4: NFT и IPFS

**NFT** — токен, который хранит `tokenURI`, часто указывающий на объект в **IPFS**. IPFS — распределённое хранилище, где контент адресуется по **CID** (хэш содержимого). Сам контент лежит не в цепи, а у пиров, а в блокчейне — только CID.

```bash
$ curl -s https://ipfs.io/ipfs/<cid> | jq .
$ curl -s https://ipfs.io/ipfs/<cid> | grep -iE 'flag|base64|hidden'
```

Скрытые данные могут быть в неиспользуемых полях метаданных NFT, в самом изображении (обычная стеганография) или в нескольких CID, собранных по порядку.

## Шаг 5: EVM и смарт-контракты

В Ethereum данные пишут в `input data` вызова, в хранилище контракта или в **события** (`LOG`-опкоды, которые никто не чистит):

```bash
$ cast logs --address <contract> --from-block 0 --to-block latest | head
```

Данные в логах — частый способ «заякорить» хэш или сообщение.

## Шаг 6: большие объёмы и сборка

80 байт на транзакцию мало. Для больших сообщений используют несколько транзакций (с порядковыми номерами) или внешние хранилища (IPFS, Arweave), а в цепи держат только CID.

Порядок сборки: получить все транзакции по адресу → отсортировать по времени/номеру блока → склеить данные → декодировать.

```bash
$ curl -s https://arweave.net/<txid> | head
```

## Разбор OP_RETURN вручную

Посмотрим на `scriptPubKey` глазами. Соберём его из полезной нагрузки и разберём байт за байтом:

```bash
$ python3 -c "d=b'flag{op_return}'; print((b'\x6a'+bytes([len(d)])+d).hex())"
6a0f666c61677b6f705f72657475726e7d
```

Здесь `6a` — опкод `OP_RETURN`, `0f` — длина следующих данных (15 байт), дальше сама строка. Декодируем hex обратно в байты и убеждаемся, что структура читается:

```bash
$ echo 6a0f666c61677b6f705f72657475726e7d | xxd -r -p | xxd
00000000: 6a0f 666c 6167 7b6f 705f 7265 7475 726e  j.flag{op_return
00000010: 7d                                       }
```

Парсер отсекает первые два байта и берёт ровно `n` байт полезной нагрузки:

```bash
$ python3 -c "s=bytes.fromhex('6a0f666c61677b6f705f72657475726e7d'); n=s[1]; print(s[2:2+n].decode())"
flag{op_return}
```

Запомни формат: `6a` + длина + данные. Именно этот шаблон ищут в hex-дампах транзакции — `6a` в начале скрипта означает, что выход непотрачиваем и несёт произвольные байты.

Полезно помнить про лимит: стандартный `OP_RETURN` несёт примерно до 80 байт, поэтому длинное сообщение режут на несколько транзакций и собирают по порядку блоков. В CTF это значит, что одного `txid` может не хватить — проверь соседние транзакции того же адреса, прежде чем решать, что данных нет.

## Если не сработало

- **Путаешь блокчейн с приватным хранилищем** — всё публично.
- **Игнорируешь IPFS-часть** — контент часто не в цепи, а по CID.
- **Забыл про hex-декодирование** — данные в транзакциях в hex.
- **Считаешь, что данные удаляемы** — из блокчейна их не стереть.
- **Не проверил все выходы** — OP_RETURN может быть не в первом.
- **Пропустил метаданные NFT** — там чаще всего и лежит контент.

## Сравнение каналов в блокчейне

| Канал | Ёмкость | Публичность | Удаляемость |
|---|---|---|---|
| OP_RETURN | ~80 байт/транзакция | полная | нет |
| Метаданные NFT | высокая | полная | нет (контент в IPFS — да) |
| Суммы выходов | средняя | полная | нет |
| Смарт-контракт | высокая | полная | нет |
| IPFS-контент | очень высокая | по CID | возможно (unpin) |

## Обнаружение и ограничения

Блокчейн-данные не «прячутся» — они публичны, поэтому задача аналитика не «найти аномалию в трафике», а найти данные среди миллионов транзакций. Помогают фильтры эксплореров по `OP_RETURN`, парсеры блоков и API-скрипты.

```python
import requests
blk = requests.get("https://blockstream.info/api/block/<hash>/txids").json()
for txid in blk:
    tx = requests.get(f"https://blockstream.info/api/tx/{txid}").json()
    for vout in tx["vout"]:
        if "op_return" in vout["scriptpubkey_type"]:
            print(bytes.fromhex(vout["scriptpubkey"]))
```

Ограничения: **неизменяемость** (приватности нет), **стоимость** (комиссия за запись), **правовые риски** (запись незаконного контента в публичный реестр — правонарушение), **IPFS unpin** (контент может исчезнуть, если его перестали хранить). Вывод: блокчейн-стеганография — про цензуроустойчивость и вечность, а не про секретность.

## Что мы теперь знаем

1. Блокчейн — **публичный и неизменяемый**: данные видны всем и не удаляются.
2. Главный канал — **OP_RETURN** (`0x6a`) в транзакции Bitcoin.
3. Данные в транзакциях — в **hex**, декодируются `xxd -r -p`.
4. NFT/токены хранят контент в **IPFS** по CID, а не в цепи.
5. Большие объёмы собирают из нескольких транзакций или внешних хранилищ.
