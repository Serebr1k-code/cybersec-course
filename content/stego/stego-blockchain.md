Блокчейн — это публичный, неизменяемый и реплицированный реестр. Именно эти свойства делают его необычным носителем: данные нельзя удалить, их видит весь мир, и они доступны вечно. Для стеганографии это одновременно и преимущество (данные переживут любые попытки цензуры), и недостаток (полная публичность). Прятать в блокчейне имеет смысл не «чтобы не увидели», а «чтобы нельзя было стереть».

## Где в блокчейне прячут данные

- **OP_RETURN.** Специальный выход транзакции Bitcoin, в который можно записать до ~80 байт произвольных данных. Классическое место для сообщений/хешей.
- **Поля входа/выхода.** Скрипты, публичные ключи, `nSequence`, `nLockTime`.
- **Адреса и суммы.** Данные можно кодировать в значениях сумм или в генерируемых адресах.
- **Метаданные NFT/токенов.** В ERC-721/ERC-1155 токенах метаданные (часто IPFS-ссылка) могут содержать произвольный контент.
- **Смарт-контракты.** Данные в `data`-полях вызовов и в хранилище контракта.
- **IPFS/распределённые хранилища.** Не блокчейн, но часто используется вместе: CID ссылается на контент, который может содержать всё что угодно.

## Инструменты и команды

- **Эксплореры:** blockchain.com, blockstream.info, etherscan.io.
- **`bitcoin-cli`** — работа с локальным узлом.
- **`curl` + публичные API** — разбор транзакций.
- **`ipfs` CLI / шлюзы** — получение контента по CID.
- **`xxd`/`base64`** — декодирование данных.

Разбор транзакции Bitcoin через API:

```bash
curl -s https://blockstream.info/api/tx/<txid>/hex | head -c 400
```

Поиск OP_RETURN:

```bash
# в hex транзакции OP_RETURN = 0x6a, за которым идёт длина и данные
curl -s https://blockstream.info/api/tx/<txid>/hex | xxd -r -p | xxd | grep -i '6a'
```

## Разобранный пример: сообщение в OP_RETURN

Транзакция содержит выход с `OP_RETURN` и данными:

```bash
$ bitcoin-cli getrawtransaction <txid> true | jq '.vout[] | select(.scriptPubKey.asm|test("OP_RETURN"))'
{
  "scriptPubKey": {
    "asm": "OP_RETURN 666c61677b626974636f696e7d",
    ...
  }
}
```

Данные в hex — декодируем:

```bash
$ echo 666c61677b626974636f696e7d | xxd -r -p
flag{bitcoin}
```

## Метаданные NFT и IPFS

NFT-токен хранит `tokenURI`, часто указывающий на IPFS-объект. Сам объект (JSON/изображение) может содержать скрытые данные в неиспользуемых полях.

```bash
$ curl -s https://ipfs.io/ipfs/<cid> | jq .
$ curl -s https://ipfs.io/ipfs/<cid> | grep -iE 'flag|base64|hidden'
```

Иногда в метаданных прячут дополнительный CID или base64-строку.

## Кодирование в адресах и суммах

Экзотические каналы:

- **Суммы выходов.** Набор значений сумм кодирует байты (например, по номеру суммы).
- **Адреса.** Сгенерировать адрес, начинающийся с определённых символов (vanity), сложно, но возможно для коротких сообщений.
- **Порядок выходов.** Перестановка выходов кодирует биты.

## Сравнение каналов в блокчейне

| Канал | Ёмкость | Публичность | Удаляемость |
|---|---|---|---|
| OP_RETURN | ~80 байт/транзакция | полная | нет |
| Метаданные NFT | высокая | полная | нет (но контент в IPFS — да) |
| Суммы выходов | средняя | полная | нет |
| Смарт-контракт | высокая | полная | нет |
| IPFS-контент | очень высокая | по CID | возможно (unpin) |

## Частые ошибки и подводные камни

- **Путать блокчейн с приватным хранилищем.** Всё публично.
- **Игнорировать IPFS-часть.** Сам контент часто не в цепи, а по CID.
- **Забыть про hex-декодирование.** Данные в транзакциях — hex.
- **Считать, что данные удаляемы.** Из блокчейна их не стереть.
- **Не проверять все выходы.** OP_RETURN может быть не в первом.
- **Пропустить NFT-метаданные.** Там чаще всего и лежит контент.

## Что дальше / решение

- Получите hex транзакции через эксплорер/API.
- Ищите `OP_RETURN` (`6a`) и декодируйте hex.
- Проверьте метаданные NFT/токенов и связанные IPFS-CID.
- Скачайте IPFS-контент и поищите скрытые поля.
- Если цепь чистая — вернитесь к нейросетевым методам (`stego-deep-learning`).

## OP_RETURN: детали и ограничения

`OP_RETURN` — опкод, делающий выход «непотрачиваемым» (provably unspendable). Данные записываются после него скриптом: `OP_RETURN <push data>`. Стандартный лимит — 80 байт, но нестандартные транзакции несут больше. Данные видны всем и навсегда.

```bash
# извлечь OP_RETURN из raw-транзакции
bitcoin-cli decoderawtransaction $(bitcoin-cli getrawtransaction <txid>) \
  | jq '.vout[].scriptPubKey.asm | select(test("OP_RETURN"))'
```

Расшифровка: после `OP_RETURN` идёт `PUSHBYTES_N` и hex-данные. Декодируют `xxd -r -p`.

## Другие носители внутри Bitcoin

- **Скрипты входов** — `scriptSig` может содержать произвольные данные (в «non-standard» транзакциях).
- **`nLockTime` / `nSequence`** — 32-битные поля, кодирующие данные.
- **Суммы выходов** — набор значений кодирует байты.
- **Адреса** — генерация vanity-адресов для коротких сообщений.
- **Порядок входов/выходов** — перестановка кодирует биты.
- **Witness (SegWit)** — поля свидетеля менее ограничены.

```bash
bitcoin-cli getrawtransaction <txid> true | jq '.vin[].txinwitness'
```

## Смарт-контракты и EVM

В Ethereum данные можно писать:

- **В `input data` вызова** — при вызове контракта с произвольным calldata.
- **В хранилище контракта** — `SSTORE` с произвольными значениями.
- **В события (logs)** — `LOG`-опкоды пишут данные в лог, который никто не чистит.
- **В `CREATE`/`CREATE2`** — адрес контракта детерминированно зависит от salt и кода.

```bash
cast logs --address <contract> --from-block 0 --to-block latest | head
```

Данные в логах — частый способ «заякорить» хеш или сообщение.

## IPFS и распределённые хранилища

IPFS идентифицирует контент по CID (хэш). Данные хранятся у пиров; если контент «запиннен» (pinned), он доступен вечно. Часто цепочка хранит лишь CID, а сам контент (изображение/JSON) — в IPFS. Скрытые данные могут быть:

- **В неиспользуемых полях метаданных** NFT (`attributes`, `extra`).
- **В самом файле** (изображении) — обычная стеганография.
- **В нескольких CID**, собранных по порядку.

```bash
ipfs get <cid> -o out/
curl -s https://ipfs.io/ipfs/<cid> | head
```

## Практический разбор: CTF-сценарий

1. Дан txid/адрес/ссылка на NFT.
2. Открыть эксплорер, получить raw-транзакцию.
3. Искать `OP_RETURN`, witness, calldata.
4. Декодировать hex/base64.
5. Если есть CID — скачать контент из IPFS и проверить его.
6. Проверить метаданные токена на скрытые поля.

## Ограничения и предостережения

- **Неизменяемость**: данные нельзя удалить — приватность нулевая.
- **Стоимость**: запись в блокчейн стоит комиссию; большие объёмы дороги.
- **Публичность**: любой может прочитать; это не «тайник», а «вечный архив».
- **Правовые риски**: запись незаконного контента в публичный реестр — правонарушение.
- **IPFS unpin**: контент может исчезнуть, если его перестали хранить.

Для специалиста вывод: блокчейн-стеганография — про цензуроустойчивость и вечность, а не про секретность. Данные либо уже зашифрованы, либо публичны.

## Обнаружение и детект блокчейн-каналов

В отличие от сетевых каналов, блокчейн-данные не «прячутся» — они публичны. Задача аналитика не «найти аномалию в трафике», а **найти данные среди миллионов транзакций**. Инструменты:

- **Поиск по OP_RETURN**: эксплореры позволяют фильтровать транзакции с `OP_RETURN`.
- **`blockchain-parser`/`Chainalysis`** — автоматический разбор и классификация.
- **API-скрипты** — обход блоков и извлечение полей `scriptPubKey`.
- **Тематический поиск** — по известным адресам/контрактам.

```python
import requests
# пример обхода OP_RETURN в блоке (псевдокод)
blk = requests.get("https://blockstream.info/api/block/<hash>/txids").json()
for txid in blk:
    tx = requests.get(f"https://blockstream.info/api/tx/{txid}").json()
    for vout in tx["vout"]:
        if "op_return" in vout["scriptpubkey_type"]:
            print(bytes.fromhex(vout["scriptpubkey"]))
```

## Хранение и извлечение больших объёмов

80 байт на транзакцию мало. Для больших сообщений используют:

- **Несколько транзакций** с порядковыми номерами.
- **IPFS/Arweave/Filecoin** — контент хранится вне цепи, а CID — в цепи.
- **NFT-метаданные** — большой JSON по ссылке.
- **Смарт-контракты** с хранилищем.

Порядок сборки: получить все транзакции по адресу, отсортировать по времени/номеру блока, склеить данные, декодировать.

```bash
# Arweave: контент по tx id
curl -s https://arweave.net/<txid> | head
```

## Правовые и этические аспекты

Блокчейн-стеганография пересекается с вопросами законности: запись вредоносного или незаконного контента в публичный неизменяемый реестр создаёт проблемы для всей сети (никто не может удалить). С точки зрения защиты это значит, что «канал» обнаруживается постфактум и не может быть закрыт — только задокументирован. Для пентеста это скорее экзотика, для исследований — тема о цензуроустойчивости.

## Итог по блокчейн-каналу

Блокчейн — это не «тайник», а «вечный публичный архив». Прятать в нём имеет смысл для цензуроустойчивости (данные не удалить) и для привязки к времени (timestamping). Практический алгоритм: получить транзакцию → найти OP_RETURN/witness/calldata → декодировать hex → при наличии CID скачать контент из IPFS/Arweave → проверить метаданные. Инструменты простые: `curl` + `jq` + `xxd`.
