## Вопрос, с которого всё начинается
Бинарник ELF (Linux) — это заголовок, секции, сегменты. Ты запускаешь его,
работает. Но у ELF есть note-секции (`.note.*`) для произвольных «заметок»
(например, build-id), а также возможность **дописать данные после конца файла**
(overlay). Ни то, ни другое на работу не влияет — идеальное место для закладки.

## Наш пример
Возьмём `bin` — ELF-файл с данными, дописанными после последней секции. Найдём
overlay.

## Шаг 1: ELF-заголовок
Первые байты ELF:
- `7f 45 4c 46` — магия `\x7fELF`;
- класс (`01` = 32-bit, `02` = 64-bit);
- порядок байт (`01` = little-endian);
- версия;
- `e_shoff` (смещение таблицы секций), `e_shnum` (число секций),
  `e_shentsize` (размер записи) — в фиксированных смещениях.

Для 64-битного ELF: `e_shoff` — по смещению `0x28`, `e_shentsize` — `0x3a`,
`e_shnum` — `0x3c`.

## Шаг 2: overlay
«Конец ELF» — это максимум из конца таблицы секций (`e_shoff + e_shnum*e_shentsize`)
и конца таблицы сегментов. Всё, что лежит после, — overlay. Загрузчик его
игнорирует, но байты на месте. Простейшая закладка:

```python
import struct
d = open('bin','rb').read()
e_shoff = struct.unpack_from('<Q', d, 0x28)[0]
e_shnum = struct.unpack_from('<H', d, 0x3c)[0]
e_shentsize = struct.unpack_from('<H', d, 0x3a)[0]
end = e_shoff + e_shnum * e_shentsize
print(d[end:])
```

Вывод:

```
b'nto{elf_overlay_appended}\x00'
```

## Шаг 3: note-секции
Формат записи `.note`:
`[namesz(4)][descsz(4)][type(4)][name][desc][padding]`. Тип `NT_GNU_BUILD_ID`
(3) содержит build-id. Тип можно задать произвольный, а `desc` — произвольной
длины. `readelf -n bin` покажет заметки.

## Шаг 4: другие каналы в ELF
- **Секция `.comment`** — строки компилятора, легко дополнить.
- **Padding секций** — выравнивание до границы, туда помещаются данные.
- **Строковые таблицы** (`.strtab`, `.dynstr`) — строки, которые не используются.
- **Неиспользуемые символы** в таблице символов.
- **Заголовок** — поля `e_ident[7..15]` (padding) и зарезервированные байты.

## Шаг 5: инструменты
- `readelf -a bin` — заголовки, секции, заметки.
- `objdump -s -j .note.gnu.build-id bin` — содержимое заметки.
- `binwalk bin` — поиск встроенных/дописанных данных.
- `python3` + `struct` — ручной разбор.

## Полный разбор: от заголовка до overlay

Разберём `bin` целиком. Первый шаг — заголовок: `readelf -h bin` показывает класс (ELF64), порядок байт (LE), точку входа, смещения таблиц. Второй шаг — найти «конец ELF-структуры»: это максимум из конца таблицы секций и таблицы сегментов. Третий — overlay: всё после конца.

```bash
readelf -h bin
readelf -S bin | tail          # секции и их смещения
python3 - <<PY
import struct
d = open("bin","rb").read()
e_shoff = struct.unpack_from("<Q", d, 0x28)[0]
e_shnum = struct.unpack_from("<H", d, 0x3c)[0]
e_shentsize = struct.unpack_from("<H", d, 0x3a)[0]
end = e_shoff + e_shnum * e_shentsize
print("overlay:", d[end:end+64])
PY
```

Четвёртый шаг — note-секции: `readelf -n bin` печатает `.note.*`. Пятый — другие каналы: `.comment` (строки компилятора), padding секций, неиспользуемые символы, зарезервированные байты в `e_ident`. Каждый канал может нести данные.

## Note-секции: формат и практика

Формат записи `.note`: `[namesz(4)][descsz(4)][type(4)][name][desc][padding]`, где name и desc выровнены на 4 байта. `namesz`/`descsz` включают завершающий `\0` для name. Тип `NT_GNU_BUILD_ID` (3) — build-id; тип можно задать произвольный, и тогда `desc` становится произвольным контейнером.

```bash
readelf -n bin                       # список заметок
objdump -s -j .note.gnu.build-id bin # содержимое конкретной заметки
```

Практический приём: атакующий добавляет note-запись с нестандартным именем (например, `.note.custom`), кладёт в `desc` полезную нагрузку, и стандартные инструменты не обращают на неё внимания — она не влияет на загрузку. Для детекта проверяют все note-секции и их размеры: неожиданно большая `descsz` — сигнал.

Отдельно — build-id: он должен быть уникальным и соответствовать сборке; если он подменён или отсутствует там, где должен быть, это тоже аномалия.

## Инструменты и ограничения

Основные инструменты: `readelf` (заголовки, секции, заметки), `objdump` (дизассемблер, содержимое секций), `binwalk` (поиск встроенного/дописанного), `file`, `strings`, `python3` + `struct` для ручного разбора. Для динамического анализа — `gdb`, `ltrace`, `strace`.

Ограничения: `binwalk` ищет по сигнатурам и может пропустить нестандартно закодированные данные; `strings` пропускает бинарные данные; `readelf` не покажет overlay (он вне секций). Поэтому «чисто» проверяют комплексно: заголовок → секции → заметки → overlay → энтропия. И помни, что overlay бывает не только после таблицы секций, но и между секциями (в padding) — тогда его выдают аномальные размеры секций или несоответствие `p_filesz`/`p_memsz` в сегментах.

## Расширенный разбор: неочевидные каналы ELF

Помимо overlay и note-секций, в ELF есть менее очевидные каналы. Первый — padding секций: секции выравниваются на границу (обычно 8/16/4096 байт), и «хвост» между концом данных и границей может нести информацию. Признак — несоответствие `sh_size` и фактически использованного пространства. Второй — неиспользуемые записи в таблице символов (`.symtab`): там могут лежать символы, на которые никто не ссылается.

Третий — строковые таблицы (`.strtab`, `.dynstr`): неиспользуемые строки остаются в файле. Четвёртый — `.comment` (строки компилятора) и `.debug_*` (отладочная информация): часто содержит исходные пути, имена, а иногда и вставленные данные. Пятый — заголовок: `e_ident[7..15]` (padding и зарезервированные байты), поля `EI_*`, а также неиспользуемые байты в `e_*` структурах.

Шестой — program headers: несоответствие `p_filesz` и `p_memsz`, лишние сегменты, сегменты за пределами файла. Седьмой — relocation-таблицы: лишние записи. Восьмой — dynamic-секция: необычные теги или значения.

Практический подход: разобрать ELF «сверху вниз» (заголовок → program headers → section headers → содержимое секций → overlay) и на каждом уровне искать аномалии размеров/смещений. Инструмент `readelf -a` даёт полную картину; `binwalk` — быстрый обзор; `python3`+`struct` — точный разбор. Аномалия размера — почти всегда сигнал, что там что-то лежит.

## Пошаговое упражнение с ELF

Дано `bin`. Шаг первый — `file bin`, `readelf -h bin`. Шаг второй — найти конец ELF-структуры и прочитать overlay (скрипт выше). Шаг третий — заметки: `readelf -n bin`. Шаг четвёртый — `.comment` и строковые таблицы. Шаг пятый — энтропия (`binwalk -E bin`) на предмет скрытого сжатого/зашифрованного блока.

```bash
readelf -h bin && readelf -n bin
objdump -s -j .comment bin
binwalk bin
strings -n 6 bin | grep -i nto
```

Если overlay пуст, а заметок нет — проверь padding секций и несоответствия размеров. Иногда данные лежат в байтах между секциями.

## Итог по ELF

ELF — богатый контейнер: заголовок, program/section headers, секции, overlay, заметки, строковые таблицы, padding. Стего прячут в overlay (вне структур), в note-секциях (произвольный `desc`), в padding, в неиспользуемых символах/строках. Инструменты: `readelf`, `objdump`, `binwalk`, `python3`+`struct`. Порядок разбора — сверху вниз, с поиском аномалий размеров на каждом уровне.

## Что мы теперь знаем
- ELF: заголовок, таблицы секций/сегментов, секции, overlay.
- Overlay после конца ELF не влияет на работу, но хранит данные.
- Note-секции — штатное место для произвольных «заметок».
- `readelf` и `binwalk` — основные инструменты.
