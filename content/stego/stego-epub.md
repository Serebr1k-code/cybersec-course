## Вопрос, с которого всё начинается
EPUB — самый распространённый формат электронных книг. Ты открываешь его в
читалке, видишь текст. Но EPUB — это **ZIP-архив** со строго заданной структурой,
и внутри него легко спрятать файл, который ни одна читалка не покажет. Задача:
найти в книге то, чего в тексте нет.

## Наш пример
Возьмём `book.epub` — минимальную книгу. Разберём её как ZIP и найдём
непронумерованный файл.

## Шаг 1: EPUB — это ZIP
```
$ file book.epub
book.epub: EPUB document
$ unzip -l book.epub
  Length      Name
        20  mimetype
       250  META-INF/container.xml
      1024  OEBPS/content.opf
      2048  OEBPS/chapter1.xhtml
       120  OEBPS/secret.txt
```

Первая запись обязана быть `mimetype` со строкой `application/epub+zip` и
**без сжатия** — иначе валидатор EPUB отклонит файл. Всё остальное — обычные
ZIP-записи.

## Шаг 2: как устроена книга
- `META-INF/container.xml` — указывает путь к OPF-файлу (пакету).
- `OEBPS/content.opf` — манифест (список ресурсов), spine (порядок глав),
  метаданные (автор, ISBN, обложка).
- `OEBPS/*.xhtml` — сам текст.
- `OEBPS/*.css`, картинки — оформление.

Читалка показывает только то, что перечислено в spine/manifest. Файл, которого
там нет, остаётся невидимым.

## Шаг 3: где прячут данные в EPUB
- **Непронумерованные файлы.** Любая запись ZIP, не упомянутая в OPF, — невидима
  для читалки.
- **Метаданные OPF.** `<dc:description>`, `<meta property="dcterms:...">` —
  произвольные строки.
- **CSS-комментарии.** `/* ... */` в таблице стилей.
- **Обложка.** Данные в пикселях или в EXIF обложки.
- **Пустые/служебные записи.** `META-INF/encryption.xml` и подобное.

## Шаг 4: извлечение вручную
```python
import zipfile
z = zipfile.ZipFile('book.epub')
opf = z.read('OEBPS/content.opf').decode()
for name in z.namelist():
    if 'secret' in name or name not in opf:
        print(name, z.read(name))
```

Вывод:

```
OEBPS/secret.txt b'nto{epub_unreferenced_file}'
```

## Шаг 5: инструменты
- `unzip -l book.epub` — список записей.
- `epubcheck book.epub` — валидатор (лишние файлы выдаст предупреждением).
- `zipinfo -v` — детали записей.

## Полный разбор EPUB: от ZIP до скрытого файла

EPUB — это ZIP с определённой структурой. Начнём с листинга:

```bash
unzip -l book.epub
unzip -o book.epub -d book/
ls -la book/
```

Обязательные элементы: `mimetype` (первый, без сжатия), `META-INF/container.xml` (указывает на OPF), `content.opf` (манифест книги: список файлов, spine — порядок чтения), `toc.ncx`/`nav.xhtml` (оглавление), XHTML-файлы глав, стили, изображения. Первый признак стего — файлы в архиве, **не упомянутые** в манифесте OPF: они лежат, но читатель их не показывает.

```bash
python3 - <<PY
import re
opf = open("book/content.opf").read()
listed = set(re.findall(r'href="([^"]+)"', opf))
import os
for root,_,files in os.walk("book"):
    for f in files:
        p = os.path.relpath(os.path.join(root,f), "book")
        if p not in listed and not p.startswith("META-INF"):
            print("unlisted:", p)
PY
```

Неупомянутый файл — классический контейнер флага.

## Структура OPF/NCX и где прячут данные

`content.opf` — сердце книги: `<metadata>` (автор, язык, идентификатор), `<manifest>` (перечень ресурсов), `<spine>` (порядок глав). Каналы сокрытия: (1) файлы вне манифеста; (2) скрытый текст в `<metadata>` (например, в `<meta name="...">`); (3) данные в комментариях XHTML (`<!-- ... -->`); (4) невидимый текст (белый цвет, `font-size:0`, `display:none`); (5) данные в `toc.ncx`.

```bash
grep -rniE "nto\{|flag|secret" book/ | head
grep -rn "<!--" book/*.xhtml | head
```

Отдельно проверяй `mimetype`: он должен быть первым и несжатым; если это не так, файл мог быть пересобран инструментом, который оставил следы. И сравнивай заявленный в OPF список с фактическим содержимым архива — расхождение и есть канал.

## Инструменты и типичные ошибки

Инструменты: `unzip` (листинг/извлечение), `epubcheck` (валидация структуры — показывает несоответствия), `exiftool` (метаданные), `zipinfo -v` (детали ZIP: комментарии, extra-поля), `strings`, `binwalk` (если EPUB содержит вложенное).

Типичные ошибки: считать EPUB обычным ZIP и не проверять структуру OPF (пропустить неупомянутый файл); не смотреть ZIP-комментарий (он может нести данные); игнорировать `mimetype`; не проверять, не вложен ли в EPUB ещё один архив. Правильный порядок: листинг → структура OPF → сравнение манифеста с содержимым → метаданные → вложенность. EPUB удобен для стего именно потому, что структура сложная, а читатели игнорируют всё, что не описано в манифесте.

## Расширенный разбор: EPUB как контейнер

EPUB устроен как ZIP с жёсткими правилами, и каждое отклонение от них — потенциальный канал. Начнём с ZIP-уровня: `zipinfo -v book.epub` покажет комментарии архива, extra-поля, порядок файлов, метод сжатия. `mimetype` обязан идти первым и быть несжатым (`stored`) — если это не так, файл пересобирали нестандартным инструментом, что само по себе подозрительно. Комментарий ZIP может нести произвольные данные.

Уровень OPF: `content.opf` перечисляет ресурсы в `<manifest>` и порядок в `<spine>`. Любой файл в архиве, не упомянутый в манифесте, читателем игнорируется — идеальное место для флага. Метаданные (`<dc:title>`, `<dc:creator>`, `<meta>`) тоже могут содержать лишнее.

Уровень XHTML: комментарии `<!-- ... -->`, невидимый текст (белый на белом, `font-size:0`, `display:none`), данные в атрибутах `alt`/`title`, скрытые якоря. Уровень навигации: `toc.ncx` и `nav.xhtml` могут ссылаться на несуществующие или скрытые главы.

Уровень вложенности: в EPUB может быть вложен архив (внутри изображения или ресурса), что находит `binwalk`. Инструменты: `unzip`, `zipinfo`, `epubcheck` (валидация — подсвечивает несоответствия), `exiftool`, `binwalk`. Порядок: ZIP-уровень → OPF → XHTML → навигация → вложенность.

## Пошаговое упражнение с EPUB

Дано `book.epub`. Шаг первый — листинг архива: `unzip -l book.epub`. Обрати внимание на файлы, которых «не должно быть»: `flag.txt`, `secret/`, файл с странным расширением. Шаг второй — извлечь и сравнить с манифестом OPF: скрипт выше показывает unlisted-файлы. Шаг третий — прочитать найденный файл. Шаг четвёртый — проверить метаданные и комментарии.

```bash
unzip -l book.epub
unzip -o book.epub -d book/
grep -rniE "nto\{|flag" book/ | head
zipinfo -v book.epub | grep -i comment
```

Если ничего не нашлось — переходи к XHTML: комментарии, невидимый текст (белый, `font-size:0`), alt-текст картинок. Затем — к наложенным/вложенным данным (`binwalk book.epub`).

## Защита и детект

С точки зрения защищающейся стороны EPUB-стего — это «данные в контейнере», и основной приём детекта — сверка заявленной структуры с фактической. Первое: проверить, что `mimetype` первый и несжатый. Второе: сверить список файлов с манифестом OPF. Третье: валидировать через `epubcheck`. Четвёртое: сканировать содержимое на невидимые символы и подозрительные комментарии. Пятое: проверять вложенность (`binwalk`).

Для атакующего вывод простой: EPUB — это ZIP, и все «удалённые»/«скрытые» элементы видны при листинге. Никогда не полагайся только на читатель книги; работай с архивом напрямую и сверяй структуру.

## Что мы теперь знаем
- EPUB — ZIP с обязательным `mimetype` и OPF-манифестом.
- Непронумерованные файлы невидимы для читалки.
- Метаданные, CSS-комментарии, обложка — дополнительные каналы.
- Разбор начинается с `unzip -l` и чтения OPF.
