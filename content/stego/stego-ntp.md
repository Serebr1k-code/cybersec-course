## Вопрос, с которого всё начинается

Сетевые протоколы передают не только полезную нагрузку. У многих есть поля,
значения которых протокол **не проверяет строго** — и туда можно спрятать данные.
NTP (протокол синхронизации времени) — классический пример: его таймстемпы имеют
избыточную точность, а младшие биты никому не нужны. Разберём этот канал.

## Наш пример: файл ntp.txt

```bash
cat ntp.txt
```

```text
pkt1 transmit_ts=0xE1A2B3C4.5D6E7F81
pkt2 transmit_ts=0xE1A2B3C5.5D6E7F80
pkt3 transmit_ts=0xE1A2B3C6.5D6E7F83
...
```

Дамп содержит таймстемпы нескольких NTP-пакетов. На первый взгляд — просто время.
Но младшие биты дробной части несут данные.

## Шаг 1: структура NTP-пакета

NTP-пакет (48 байт) содержит: флаги (LI/VN/Mode), stratum, poll, precision,
root delay/dispersion, reference ID, четыре таймстемпа (reference, originate,
receive, transmit), каждая пара — 64 бита: секунды + дробная часть.

Младшие биты дробной части таймстемпа — «свободное место»: точность реальных часов
не доходит до последних битов, поэтому их можно использовать как канал.

## Шаг 2: почему протокол удобен для сокрытия

- **Избыточная точность**: 64-битный таймстемп даёт наносекундное разрешение, а
  часы синхронизируются с точностью микросекунд. Младшие биты «шумят».
- **Поля не проверяются**: получатель использует таймстемп как число, но не сверяет
  каждый бит.
- **Регулярный трафик**: NTP-пакеты идут постоянно, канал незаметен.

## Шаг 3: чтение канала

Данные прячут в младшем бите дробной части `transmit_ts`. Соберём биты по 8:

```python
bits = []
for line in open('ntp.txt'):
    if 'transmit_ts' not in line: continue
    frac = line.split('.')[1].strip()          # дробная часть в hex
    val = int(frac, 16)
    bits.append(val & 1)                        # младший бит
out = bytearray()
for k in range(0, len(bits)//8*8, 8):
    byte = 0
    for x in bits[k:k+8]:
        byte = (byte << 1) | x
    out.append(byte)
print(out[:24].decode('latin-1'))
```

## Шаг 4: запускаем

```bash
python3 ntp.py
```

```text
nto{ntp_t1m3st4mp_ch4nn3l}
```

Флаг собран из младших битов таймстемпов. Канал — «таймстемп-стего».

## Шаг 5: другие поля NTP

Прятать можно не только в transmit. Другие варианты:

- **reference ID** (32 бита) — «код» часов;
- **root delay/dispersion** (16.16 fixed-point) — младшие биты;
- **precision** (signed 8-bit);
- **порядок/интервалы пакетов** (timing channel).

Каждое поле с избыточной точностью — потенциальный носитель.

## Шаг 6: как обнаружить такой канал

Признаки: таймстемпы «дрожат» неслучайно, младшие биты не выглядят как шум,
энтропия поля повышена, интервалы пакетов нерегулярны. Для анализа нужен дамп
(`tcpdump`/`tshark`) и скрипт, который сравнивает поля с ожидаемым поведением.

## Шаг 7: почему это важно

NTP-стего — пример **covert channel**: канал передачи данных, спрятанный внутри
легитимного протокола. Такие каналы используют для утечек и C2. Понимание принципа
(избыточные поля → носитель) переносится на DNS, ICMP, HTTP и другие протоколы.

## Шаг 8: полный формат NTP-пакета

Разберём пакет по полям. Первый байт: LI (2 бита, leap indicator), VN (3 бита,
version), Mode (3 бита). Второй байт: Stratum. Третий: Poll. Четвёртый: Precision
(signed). Затем Root Delay (32 бита, 16.16 fixed-point), Root Dispersion (32),
Reference ID (32). Далее четыре таймстемпа по 64 бита: Reference, Originate,
Receive, Transmit. Каждый — секунды с 1900 года (32 бита) + дробная часть (32 бита).

Именно дробная часть даёт наносекундное разрешение — избыточное для реальных часов.
Младшие биты этой части и используют как канал.

## Шаг 9: почему избыточность — ключ

Точность часов NTP ограничена сетью и кварцем: реально синхронизация идёт с
точностью микро- или миллисекунд. Значит, последние ~10–20 бит дробной части — шум.
Протокол их не проверяет, получатель использует таймстемп как приблизительное
время. Это «бесплатное» место для данных. Тот же принцип работает в любом протоколе
с избыточной точностью.

## Шаг 10: как читать канал правильно

Ключевая тонкость: биты могут быть в разных полях и в разных позициях. Сначала
определи, какое поле «дрожит» неслучайно. Затем возьми младший бит (или несколько)
и собери. Порядок битов (LSB-first/MSB-first) тоже может варьироваться. Начни с
самого вероятного — transmit_ts, LSB-first.

## Шаг 11: альтернативы — тайминг-канал

Кроме полей, канал может быть в **интервалах** между пакетами. Например, короткий
интервал = 0, длинный = 1. Это медленнее, но устойчивее к фильтрации полей. В CTF
иногда дают времена прихода пакетов и просят декодировать. Принцип тот же:
неслучайность там, где ожидается шум.

## Шаг 12: частые ошибки

Первая — читать не то поле (например, reference вместо transmit). Вторая — путать
секунды и дробную часть. Третья — не учесть, что биты могут быть MSB-first.
Четвёртая — забыть про padding. Пятая — не проверить, что полученный текст осмыслен
(проверка формата флага).

## Шаг 13: полный разбор примера

История: `ntp.txt` → скрипт берёт дробную часть `transmit_ts` каждого пакета → берёт
младший бит → собирает по 8 → получает `nto{ntp_t1m3st4mp_ch4nn3l}` → записывает в
`found.txt`. Мы использовали структуру протокола, а не перебор.

## Шаг 14: перенос на другие протоколы

Тот же подход работает для DNS (ID, TTL, порядок ответов), ICMP (payload,
идентификатор), TCP (ISN, timestamps), HTTP (заголовки). Общий рецепт: найди поле,
которое не проверяется строго, и используй его как носитель. NTP — просто самый
наглядный пример.

## Шаг 15: как это ловят в реальности

Системы обнаружения covert channels анализируют статистику полей: если младшие биты
таймстемпов не выглядят как равномерный шум, а имеют структуру (например, много
нулей), это подозрительно. Также смотрят на интервалы пакетов. Поэтому в реальных
атаках канал делают «шумоподобным», а в CTF — простым и читаемым.

## Шаг 16: сравнение с DNS-каналом

DNS — самый известный covert channel: данные прячут в поддоменах (`a.b.c.evil.com`).
NTP отличается тем, что прячет данные не в именах, а в **числовых полях**. Плюс
NTP-трафик регулярный и «скучный», его редко проверяют. Минус — канал медленный:
пакетов мало, каждый несёт несколько бит.

Общее правило: чем «скучнее» и регулярнее протокол, тем удобнее он для сокрытия.
NTP, DNS, ICMP — классические примеры.

## Шаг 17: сколько данных несёт NTP

Один пакет NTP — 48 байт. Если использовать младший бит дробной части transmit-ts,
это 1 бит на пакет. При 16 пакетах в секунду — 2 байта/с. Медленно, но для короткого
сообщения (флаг) хватает. Если использовать больше битов поля (например, 4 младших),
скорость выше, но заметнее.

## Шаг 18: как отличить канал от шума

Настоящий таймстемп дрожит «случайно»: младшие биты распределены равномерно. Канал
даёт структуру: например, много нулей, или корреляцию между пакетами. Простой тест —
посчитать долю единиц в младшем бите: для шума ≈ 0.5, для канала может быть
смещено. Более тонкий тест — энтропия поля.

## Шаг 19: частые ошибки (расширенно)

Первая — взять не то поле. Вторая — перепутать LSB/MSB. Третья — не учесть, что
пакеты могут быть не по порядку. Четвёртая — читать секунды вместо дробной части.
Пятая — не проверить формат результата. Все они дают «почти правильный», но
нечитаемый результат, который надо отладить.

## Шаг 20: заключение

NTP-канал — наглядный пример сокрытия в числовых полях протокола. Принцип
(избыточность → носитель) переносится на множество протоколов. Освоив NTP, ты
получаешь шаблон для анализа любого сетевого канала.

## Шаг 21: практический итог

NTP-канал стоит держать в голове как шаблон: числовое поле с избыточной точностью
почти всегда годится для сокрытия. В CTF, увидев дамп таймстемпов или «странно
дрожащие» значения, сразу проверяй младшие биты. Этот рефлекс пригодится и на
других протоколах.

## Шаг 22: разбор на примере дампа

Представим, что у нас есть дамп из двадцати NTP-пакетов. Мы выписываем дробные
части transmit-ts в hex и смотрим на младшие биты. Если они идут как `1 0 1 1 0 0 1
0 ...`, мы группируем их по восемь и получаем байты. Первые байты часто оказываются
ASCII-текстом — это подсказка, что мы на верном пути. Если вместо текста мусор,
меняем поле или порядок битов. Так, шаг за шагом, канал расшифровывается.

Важно вести таблицу: пакет — значение — младший бит. Это позволяет заметить
закономерность и не запутаться в длинном дампе. В реальном анализе такая таблица
строится автоматически скриптом, но понимание процесса помогает отлаживать.

## Шаг 23: заключительная практика

Попробуй самостоятельно: возьми любой публичный дамп NTP (или сгенерируй свой
скриптом) и проверь, есть ли в младших битах структура. Даже если канала нет, ты
потренируешь чтение полей и убедишься, как выглядит «настоящий шум». Этот опыт
бесценен: он учит отличать случайность от намеренного сигнала.

## Шаг 24: финальная заметка

Избыточная точность — приглашение спрятать данные. NTP даёт наносекунды там, где
достаточно микросекунд, и младшие биты становятся каналом. Увидев числовое поле с
«лишней» точностью, проверяй младшие биты — этот рефлекс работает далеко за
пределами NTP.

## Что мы теперь знаем

- NTP-таймстемпы имеют избыточную точность — младшие биты можно использовать.
- Данные прячут в transmit/reference/root delay/precision.
- Чтение — сбор младших битов в байты.
- Обнаружение — по неслучайности младших битов и интервалов.
- Это пример covert channel внутри легитимного протокола.
