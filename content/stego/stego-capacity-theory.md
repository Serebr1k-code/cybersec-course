## Вопрос, с которого всё начинается

Ты хочешь спрятать в картинке 512×512 целый мегабайт. Влезет ли он? И если да — заметит ли это стегоаналитик? Ты уже знаешь, как считать ёмкость «по формуле», но тут вопрос глубже: **сколько вообще можно спрятать, не будучи пойманным?** Это не инженерная деталь, а теория.

Ответ даёт **теория стегоканала**: стеганографию формализуют как канал связи, у которого есть пропускная способность. Разберём её на нашем примере.

## Наш пример: cover.png 512×512 и сообщение

Введём термины. **Cover** — исходный «чистый» носитель (наша картинка). **Stego** — носитель после встраивания. **Встраивание** (embedding) кладёт сообщение в cover, **извлечение** (extraction) достаёт его обратно. **Стегоаналитик** (противник) видит только итоговый файл и решает: это стего или чистый cover?

Стеганография отличается от криптографии целью: она скрывает не **содержание**, а **факт** передачи. Поэтому метрика успеха — не стойкость к дешифровке, а **статистическая неотличимость** от естественного носителя.

## Шаг 1: bpp — базовая единица ёмкости

**bpp** (bits per pixel) — сколько бит встроено на один пиксель. Считается просто:

```python
import numpy as np
from PIL import Image
msg = b"flag{capacity}"
img = np.array(Image.open("cover.png"))
bpp = len(msg)*8 / (img.shape[0]*img.shape[1])
print("size", img.shape, "bpp=%.4f" % bpp)
```

```bash
$ python3 bpp.py
size (512, 512, 3) bpp=0.0004
```

Флаг занимает ничтожную долю процента. Но мегабайт на той же картинке — это уже `1048576*8 / (512*512) ≈ 32 bpp` — в 32 раза больше, чем один бит на пиксель. **Столько спрятать незаметно невозможно.**

## Шаг 2: rate-distortion — размен ёмкости и искажения

**Rate-distortion** описывает компромисс: сколько бит на пиксель можно встроить при допустимом искажении. Кривая выпуклая: сначала ёмкость растёт дёшево, затем каждое дополнительное вложение стоит всё больше искажений.

| Скорость (bpp) | Вид | Обнаружимость |
|---|---|---|
| 0.05 | едва заметно | очень низкая |
| 0.2 | незаметно | низкая |
| 0.4 | лёгкий шум | средняя |
| 0.8 | заметный шум | высокая |
| 1.0+ | порча | тривиальная |

Для аддитивных схем с гауссовым «шумом» есть аналог формулы Шеннона: `R(D) ≈ 0.5 · log2(σ² / D)`, где `σ²` — дисперсия cover, `D` — допустимое искажение.

```python
import numpy as np
from PIL import Image
x = np.array(Image.open("cover.png").convert("L")).astype(float)
sigma2 = x.var()
for frac in [1e-4, 1e-3, 1e-2]:
    D = frac*sigma2
    print(f"D={frac:.0e}  ->  R~{0.5*np.log2(sigma2/D):.2f} bpp")
```

```bash
$ python3 rate.py
D=1e-04  ->  R~6.64 bpp
D=1e-03  ->  R~4.98 bpp
D=1e-02  ->  R~3.32 bpp
```

Это оптимистичная **верхняя** оценка (для гауссова cover); реальные изображения дают меньше. Смысл: чем больше допустимое искажение, тем выше скорость.

## Шаг 3: формальная модель и KL-дивергенция

Формально вводят два распределения: `P_cover` (чистые изображения) и `P_stego` (со встраиванием). Противник минимизирует вероятность ошибки между ними, а схема стремится сделать их неотличимыми. Мера отличимости — **KL-дивергенция** `D(P_stego || P_cover)`. Идеальная стеганография требует `D = 0`, то есть полной неотличимости. Это достижимо только при **идеальной модели cover** — на практике её нет, поэтому всегда есть «утечка».

## Шаг 4: cover selection — выбор носителя

Не всякое изображение одинаково хорошо. **Cover selection** — выбор носителя, на котором встраивание наименее заметно:

- **Высокая текстурированность** — больше «дешёвых» пикселей → больше ёмкости;
- **Подходящая гистограмма** — «гладкая», без пиков;
- **Размер** — больше пикселей → больше абсолютная ёмкость;
- **Тип сжатия** — PNG (lossless) для LSB, JPEG — для частотных схем.

```python
from skimage.measure import shannon_entropy
from skimage.filters import sobel
print("entropy:", round(shannon_entropy(x), 3))
print("edge energy:", round(np.abs(sobel(x)).mean(), 2))
```

Чем выше энтропия и краевая энергия, тем лучше носитель. В CTF это помогает понять, не сгенерирован ли cover специально под сообщение (неестественно высокие показатели).

## Шаг 5: что принципиально невозможно

- **Спрятать больше, чем позволяет модель** — идеальная стеганография требует идеальной модели cover.
- **Обойти ML-детектор при большом объёме** — SRM-детекторы ловят даже малые вложения слабых схем.
- **Скрыть факт при многократном использовании носителя** — искажения накапливаются.
- **Максимум устойчивости и незаметности одновременно** — всегда размен.

## Полный прогон: считаем ёмкость и цену в PSNR

Переведём формулы в числа. Ёмкость носителя при заданном bpp считается как `число_каналов × bpp / 8` байт. Возьмём картинку 512×512 (три канала):

```python
W = H = 512; ch = 3
for bpp in (0.05, 0.1, 0.4, 1.0):
    print(f"bpp={bpp:<5} capacity={int(W*H*ch*bpp/8):>8} bytes")
```

```bash
$ python3 cap.py
bpp=0.05  capacity=    4915 bytes
bpp=0.1   capacity=    9830 bytes
bpp=0.4   capacity=   39321 bytes
bpp=1.0   capacity=   98304 bytes
```

Даже один бит на пиксель (`bpp=1.0`) даёт всего 96 КиБ на полумегапиксельной картинке. Теперь посмотрим цену. Чем выше bpp, тем сильнее падает **PSNR** — метрика качества в децибелах; чем она больше, тем ближе картинка к оригиналу:

```python
import numpy as np
from skimage.metrics import peak_signal_noise_ratio as psnr
rng = np.random.default_rng(3)
cover = rng.integers(0, 256, size=(256, 256, 3), dtype=np.uint8)
flat = cover.reshape(-1)
for bpp in (0.05, 0.2, 0.5, 1.0):
    n = int(flat.size * bpp)
    bits = rng.integers(0, 2, size=n, dtype=np.uint8)
    o = flat.copy(); o[:n] = (o[:n] & 0xFE) | bits
    print(f"bpp={bpp:<4} payload={n//8:>6}B  PSNR={psnr(cover, o.reshape(cover.shape)):6.2f} dB")
```

```bash
$ python3 psnr.py
bpp=0.05 payload=  1228B  PSNR= 64.12 dB
bpp=0.2  payload=  4915B  PSNR= 58.11 dB
bpp=0.5  payload= 12288B  PSNR= 54.17 dB
bpp=1.0  payload= 24576B  PSNR= 51.14 dB
```

Видно ту самую выпуклую кривую: от `bpp=0.05` к `0.2` мы вчетверо увеличили нагрузку, потеряв ~6 дБ, а от `0.5` к `1.0` — удвоили нагрузку, потеряв всего ~3 дБ. PSNR выше ~40 дБ глазом почти не отличить, ниже ~35 дБ появляется заметный шум. Это и есть rate-distortion на практике: вложение в «дешёвой» зоне почти бесплатно, в «дорогой» — резко заметно.

## Если не сработало

- **bpp ≠ реальная ёмкость** — часть уходит на заголовок и ECC.
- **Сжатие меняет всё** — для JPEG ёмкость считают на DCT-коэффициент, не на пиксель.
- **Клиппинг** — у границ 0/255 ёмкость падает.
- **Низкая энтропия** — в изображении с малым числом цветов встраивать некуда.
- **Теория ≠ CTF** — в задачах важнее найти схему, чем оптимизировать bpp.

## Справочная таблица

| Понятие | Смысл |
|---|---|
| bpp | бит на пиксель (или коэффициент) |
| rate-distortion | кривая ёмкость↔искажение |
| пропускная способность | максимум при заданном D |
| cover selection | выбор лучшего носителя |
| KL-дивергенция | мера отличимости стего от cover |

## Связь с реальными системами

Идеи rate-distortion и cover selection лежат в основе реальных систем защиты контента: DRM, систем отслеживания утечек, watermarking для стоковых фото. В них ёмкость сознательно ограничивают (десятки-сотни бит), чтобы обеспечить робастность и незаметность. Для CTF полезно понимать эти компромиссы: если задача про «водяной знак», ожидай малую ёмкость и высокую устойчивость, а не мегабайты данных.

## Практика: считаем ёмкость и предел

Проверим теорию числом. Возьмём RGB-изображение 1024×768 и посчитаем, сколько в него влезает при разных схемах встраивания:

```python
w, h = 1024, 768
values = w * h * 3          # три канала на пиксель
print("значений:", values)
print("1 бит/значение ->", values // 8, "байт =", round(values / 8 / 1024, 1), "KB")
print("2 бита/значение ->", values * 2 // 8, "байт =", round(values * 2 / 8 / 1024, 1), "KB")
```

```bash
$ python3 cap.py
значений: 2359296
1 бит/значение -> 294912 байт = 288.0 KB
2 бита/значение -> 589824 байт = 576.0 KB
```

Цифры показывают главный размен теории: **ёмкость растёт линейно**, а незаметность падает нелинейно. На одном бите в значение изменения почти невидимы (PSNR высокий), на двух — уже заметны статистике. Формально предел задаёт **rate-distortion**-граница: для каждого уровня искажения существует максимальная скорость, выше которой сообщение становится детектируемым. Поэтому в реальных схемах ёмкость никогда не берут «до упора» — оставляют запас, чтобы остаться под кривой обнаружимости.

## Что мы теперь знаем

1. Стегоканал — это **канал связи** со своей пропускной способностью.
2. **bpp** измеряет скорость встраивания; **rate-distortion** — размен ёмкости и искажения.
3. Предел скорости оценивают формулой `R(D) ≈ 0.5·log2(σ²/D)`.
4. **Cover selection** даёт выигрыш не хуже смены алгоритма.
5. Идеальная неотличимость требует идеальной модели cover — её нет.

## Ёмкость разных носителей: справочная таблица

Теория ёмкости становится полезной, когда её применяешь к конкретному формату.
Ниже — практические оценки для типичных носителей: сколько бит можно встроить и
насколько это заметно.

| Носитель | Канал | Ёмкость | Заметность |
|---|---|---|---|
| PNG | LSB 1 бит/канал | W·H·3 бит | низкая при 1 бите, растёт быстро |
| PNG | LSB 2 бита/канал | W·H·6 бит | средняя, видны артефакты |
| BMP | LSB | W·H·3·(бит) | низкая, но формат редкий |
| WAV (16-bit PCM) | LSB сэмпла | sr·dur·ch бит | очень низкая |
| JPEG | модификация DCT-коэффициентов | ~5–15 % размера файла | высокая, ломает статистику |
| MP3 | заполнение битовых резервуаров | единицы % | средняя |
| текст | пробел/табуляция | 1 бит на пробел | заметно при больших объёмах |

Формула для изображения с 24-битным цветом проста: при встраивании `b` бит в
каждый канал ёмкость равна `W · H · 3 · b` бит, то есть для картинки 512×512 при
`b = 1` это около 786 Кбит ≈ 98 Кбайт. Но чем больше `b`, тем сильнее
распределение младших битов отклоняется от равномерного, и тест хи-квадрат
ловит встраивание. Поэтому на практике выбирают компромисс: либо встраивают
мало (незаметно), либо встраивают много и принимают, что это найдут.

Для аудио ёмкость линейна по длительности: 44,1 кГц, стерео, 16 бит — это
44100 · 2 · 1 бит ≈ 88 Кбит/с скрытого канала при LSB-схеме, то есть за минуту
можно спрятать ~660 Кбайт. Именно поэтому WAV-LSB — любимый учебный носитель:
ёмкость огромна, а артефакты на слух неразличимы. Вывод простой: выбирай
носитель под задачу, а не наоборот — если сообщение большое, картинка LSB
перестанет быть незаметной раньше, чем закончится её ёмкость.
