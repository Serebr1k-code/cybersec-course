Сколько данных вообще можно спрятать, не будучи пойманным? Этот вопрос — не инженерная деталь, а теория. Стеганографию формализуют как канал связи: «передатчик» (встраивание) отправляет сообщение «получателю» (извлечение) через «носитель» (cover), а «противник» (стегоаналитик) пытается отличить стего от чистого изображения. У такого канала есть пропускная способность, и она ограничена. Понимание теории помогает выбирать носитель, оценивать реалистичную ёмкость и не гнаться за невозможным.

## Стегоканал как канал связи

Модель: есть источник сообщений, кодер (встраивание), носитель, канал (возможные искажения) и декодер. Противник видит только итоговый файл и решает: «стего или нет». Стеганография отличается от криптографии целью: не скрыть *содержание*, а скрыть *факт* передачи. Поэтому метрика успеха — не стойкость к дешифровке, а статистическая неотличимость от естественного носителя.

Формально вводят два множества распределений: `P_cover` (чистые) и `P_stego` (с встраиванием). Противник минимизирует вероятность ошибки между ними; схема стремится сделать распределения неотличимыми (KL-дивергенция мала).

## Пропускная способность стегоканала

Если противник не может отличить стего от cover, то теоретически можно передать сколь угодно много — но только если есть идеальная модель cover и неограниченный носитель. На практике есть ограничения:

- **Искажение.** Встраивание меняет носитель, и это ограничивает ёмкость.
- **Детектор.** Чем сильнее встраивание, тем выше вероятность обнаружения.
- **Модель.** Без точной модели cover схема «протекает» статистически.

Классический результат: при заданном допустимом искажении `D` существует максимальная скорость `R(D)` — пропускная способность. Прятать больше — значит выходить за пределы и быть обнаруженным.

## Rate-distortion: размен ёмкости и искажения

Rate-distortion описывает компромисс: сколько бит на пиксель (bpp, bits per pixel) можно встроить при допустимом искажении. Кривая обычно выпуклая: сначала ёмкость растёт дёшево, затем каждое дополнительное вложение стоит всё больше искажений. Для LSB это видно напрямую: при 0.1 bpp изменения незаметны, при 0.5 bpp появляется «шум», при 1.0 bpp картинка портится.

Практические ориентиры для пространственных схем:

| Скорость (bpp) | Вид | Обнаружимость |
|---|---|---|
| 0.05 | едва заметно | очень низкая |
| 0.2 | незаметно | низкая |
| 0.4 | лёгкий шум | средняя |
| 0.8 | заметный шум | высокая |
| 1.0+ | порча | тривиальная |

Адаптивные схемы (HUGO/WOW) сдвигают кривую: при той же детектируемости дают больше ёмкости.

## Cover selection: выбор носителя

Не всякое изображение одинаково хорошо. Cover selection — выбор носителя, на котором встраивание наименее заметно. Критерии:

- **Высокая текстурированность.** Больше «дешёвых» пикселей → больше ёмкости при той же стоимости.
- **Подходящая гистограмма.** Изображения с «гладкой» гистограммой легче испортить.
- **Размер.** Больше пикселей → больше абсолютная ёмкость (при той же bpp).
- **Тип сжатия.** PNG (lossless) подходит для LSB; JPEG — только для частотных схем.
- **Согласованность с сообщением.** Если cover генерируется под сообщение (synthesized cover), детект почти невозможен, но это уже другой класс.

В CTF cover selection редко нужен, но понимание помогает: если изображение подозрительно текстурированное и «шумное», возможно, его специально выбрали/сгенерировали.

## Инструменты и расчёты

- **`numpy`** — расчёт bpp, энтропии, гистограмм.
- **`scikit-image`** — текстурные признаки (entropy, contrast).
- **`matplotlib`** — кривые rate-distortion.
- **Детекторы (SRM+ML)** — для эмпирической оценки «детектируемости» при данной bpp.
- **Формулы** — оценивайте `bpp = бит_сообщения / число_пикселей`; для JPEG — на коэффициент.

Оценка bpp:

```python
import os, numpy as np
from PIL import Image
msg = b"flag{capacity}"
img = np.array(Image.open("cover.png"))
bpp = len(msg)*8 / (img.shape[0]*img.shape[1])
print("size", img.shape, "bpp=%.4f" % bpp)
```

Вывод:

```
size (512, 512, 3) bpp=0.0004
```

## Разобранный пример: оценка достижимой ёмкости

Для конкретной схемы можно оценить, при какой bpp детектор перестаёт «видеть» разницу. Упрощённо: строим ROC детектора на разных bpp и находим точку, где AUC ≈ 0.5 (неотличимо).

```python
# псевдокод эксперимента
for bpp in [0.05,0.1,0.2,0.4,0.8]:
    stego = embed(cover, random_bits(bpp))
    score = detector(stego)
    print(bpp, score)
```

Если detector — хи-квадрат, вы увидите, что классический LSB «палится» уже при 0.1 bpp, а LSB matching — при 0.4. Это и есть эмпирическая rate-distortion-граница.

## Пределы: что принципиально невозможно

- **Спрятать больше, чем позволяет модель.** Идеальная стеганография требует идеальной модели cover; на практике её нет.
- **Обойти детектор на основе ML при большом объёме.** Современные SRM-детекторы ловят даже малые вложения, если схема слабая.
- **Скрыть факт при многократном использовании одного носителя.** Многократное вложение накапливает искажения.
- **Устойчивость и незаметность одновременно на максимуме.** Всегда размен.

## Крайние случаи и подводные камни

- **bpp ≠ реальная ёмкость.** Часть уходит на заголовок/ECC; реальная полезная ёмкость меньше.
- **Сжатие меняет всё.** Для JPEG ёмкость считают на DCT-коэффициент, не на пиксель.
- **Клиппинг.** У границ 0/255 ёмкость падает (некуда сдвигать).
- **Энтропия.** На изображениях с низкой энтропией (мало цветов) встраивать некуда.
- **Теория ≠ CTF.** В задачах часто важнее найти схему, чем оптимизировать bpp.

## Что дальше / решение

- Нужно спрятать много — выбирайте текстурированный большой cover и адаптивную схему.
- Задача про «невозможность» — ищите синтезированный cover или side-channel.
- Оцениваете схему — стройте кривую rate-distortion и смотрите предел детектора.
- Для практики — начните с `stego-capacity`, затем этот урок для теории.

## Формальная модель стегоканала

Стеганографию формализуют как игру трёх участников: Алиса (отправитель), Боб (получатель) и Ева (стегоаналитик). У Алисы есть cover `c` и сообщение `m`; она порождает стего `s = Emb(c, m)`. Боб извлекает `m' = Ext(s)`. Ева видит `s` и решает бинарную задачу: `s` — стего или чистый cover? Успех схемы — когда Ева не может отличить распределения `P_s` и `P_c` лучше случайного угадывания.

Мера отличимости — информационная дивергенция (KL): `D(P_s || P_c)`. Идеальная стеганография (perfect steganography) требует `D = 0`, то есть полной неотличимости. Это достижимо только при идеальной модели cover — на практике её нет, поэтому всегда есть «утечка». Задача схемы — минимизировать эту утечку при заданной ёмкости.

## Пропускная способность и её оценка

Оценить достижимую скорость `R` можно через компромисс с искажением. Для аддитивных схем с гауссовым шумом существует аналог формулы Шеннона:

`R(D) ≈ 0.5 · log2(σ_c² / D)`

где `σ_c²` — «мощность» cover, `D` — допустимое искажение. Чем больше допустимое искажение, тем выше скорость. Для практики: измерьте дисперсию изображения и задайте `D` в единицах дисперсии (например, `D = 0.001·σ_c²`), получите порядок достижимой `R`.

```python
import numpy as np
from PIL import Image
x = np.array(Image.open("cover.png").convert("L")).astype(float)
sigma2 = x.var()
for frac in [1e-4, 1e-3, 1e-2]:
    D = frac*sigma2
    R = 0.5*np.log2(sigma2/D)
    print(f"D={frac:.0e} sigma^2  ->  R~{R:.2f} bpp")
```

Вывод:

```
D=1e-04 sigma^2  ->  R~6.64 bpp
D=1e-03 sigma^2  ->  R~4.98 bpp
D=1e-02 sigma^2  ->  R~3.32 bpp
```

Это оптимистичная верхняя оценка (для гауссова cover); реальные изображения дают меньше.

## Cover selection: количественные критерии

Выбор носителя можно формализовать. Хороший cover:

- имеет высокую **текстурную энтропию** (много «дешёвых» пикселей),
- «гладкую» гистограмму без выраженных пиков,
- достаточный **размер**,
- подходящий формат (lossless для LSB, lossy-тolerant для частотных схем).

Метрики для автоматического отбора:

```python
from skimage.measure import shannon_entropy
from skimage.filters import sobel
import numpy as np
from PIL import Image
x = np.array(Image.open("cover.png").convert("L"))
print("entropy:", round(shannon_entropy(x), 3))
print("edge energy:", round(np.abs(sobel(x)).mean(), 2))
```

Чем выше энтропия и краевая энергия, тем лучше носитель. В CTF это помогает понять, не сгенерирован ли cover специально под сообщение (неестественно высокие показатели).

## Практический вывод по теории

Теория ёмкости отвечает на три вопроса: сколько можно спрятать, почему нельзя спрятать больше и как выбрать носитель. На практике помните: (1) кривая rate-distortion выпукла, каждое дополнительное вложение дороже предыдущего; (2) современные ML-детекторы сдвигают предел, поэтому «незаметно» — понятие относительное; (3) cover selection даёт выигрыш не хуже смены алгоритма. Для CTF достаточно уметь оценить bpp и понять, реалистичен ли объём сообщения для данного носителя: если «флаг» не влезает — вы ищете не там.

## Связь с реальными системами

Идеи rate-distortion и cover selection лежат в основе реальных систем защиты контента: DRM, системы отслеживания утечек, watermarking для стоковых фото. В них ёмкость сознательно ограничивают (десятки-сотни бит), чтобы обеспечить робастность и незаметность. Для CTF полезно понимать эти компромиссы: если задача «водяной знак», ожидайте малую ёмкость и высокую устойчивость, а не мегабайты данных.
