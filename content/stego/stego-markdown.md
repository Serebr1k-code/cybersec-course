## Вопрос, с которого всё начинается
Markdown — «текст как есть»: заголовки, списки, ссылки. Но у него есть
синтаксические элементы, которые **не отображаются** в готовом виде: HTML-комментарии,
определения ссылок, хвостовые пробелы, alt-текст. Идеальное место для данных.
Ты получил `README.md`; на странице — чистый текст, а в исходнике — сообщение.

## Наш пример
Возьмём `README.md`. Разберём, как спрятать строку в HTML-комментарии и
reference-link, и как это выглядит после рендера.

## Шаг 1: HTML-комментарии
Markdown пропускает inline HTML. Комментарий `<!-- ... -->` не рендерится
вовсе:

```markdown
# Проект

<!-- TODO: fix later -->
```

В `README.md` внутри такого комментария может лежать base64 или метка.

## Шаг 2: reference-style ссылки
Ссылка может быть «ссылочной»: в тексте `[текст][id]`, а определение —
в другом месте файла: `[id]: https://example.com "title"`. Определение не видно
на странице (оно «поглощается»), но остаётся в исходнике. Длинные URL и title —
свободное место.

## Шаг 3: хвостовые пробелы
Два пробела в конце строки — это `<br>` в Markdown. Один или три пробела —
«ничего», но байты в файле есть. Количество хвостовых пробелов на строку кодирует
биты: ноль пробелов = 0, один пробел = 1, либо группы по 1..4 пробела = 2 бита.

## Шаг 4: alt-текст, title и URL картинок
`![alt](url "title")` — alt и title почти никто не читает. А `url` может быть
`data:`-URI с base64, который отрендерится как картинка (или не отрендерится, если
это не картинка) — и данные уедут вместе с файлом.

## Шаг 5: извлечение вручную
```python
import re, base64
text = open('README.md', encoding='utf-8').read()
m = re.search(r'<!--\s*(nto\{[^}]*\})\s*-->', text)
print(m.group(1))
```

Вывод:

```
nto{markdown_hidden_comment}
```

## Шаг 6: инструменты
- `markdown README.md` или `pandoc` — рендер (скрытое исчезнет из вывода).
- `grep -n '<!--' README.md` — комментарии.
- `grep -nE '^\s*\[[^]]+\]:' README.md` — определения ссылок.
- `cat -A README.md` — показать хвостовые пробелы (`$` в конце строк).

## Полный разбор Markdown-каналов

Markdown даёт несколько каналов. Первый — **HTML-комментарии** `<!-- ... -->`: они не отображаются, но лежат в тексте. Второй — **reference-style ссылки**: `[text][ref]` с определением `[ref]: url` в конце; порядок и содержимое определений могут нести данные. Третий — **хвостовые пробелы**: два пробела в Markdown означают перенос строки, поэтому их можно использовать как биты (1 пробел = 0, 2 = 1).

```bash
grep -n "<!--" README.md
grep -nE "\[.*\]:\s*\S+" README.md | tail
grep -nE " +$" README.md | head
```

Четвёртый — **alt-текст и title картинок**: `![alt](url "title")`; alt и title могут нести произвольные строки. Пятый — **URL картинок**: в query-параметрах или имени файла прячут данные. Шестой — **кодировки в ссылках** (percent-encoding, IDN).

Седьмой — **невидимые Unicode-символы** (zero-width, tags) прямо в тексте. Восьмой — **порядок элементов списка** и отступы. Все каналы работают, потому что Markdown рендерится в HTML, а лишнее отбрасывается.

## Извлечение и инструменты

Извлечение — по каналу. Комментарии: `grep -o "<!--.*-->"`. Хвостовые пробелы: скрипт, читающий каждую строку и считающий trailing-пробелы. Alt/title: регекс по `!\[[^]]*\]\([^)]*\)`. Невидимые символы: проверка кодов Unicode (U+200B–U+200D, U+FEFF, U+E0000–U+E007F).

```python
import re
txt = open("README.md", encoding="utf-8").read()
for m in re.findall(r"<!--(.*?)-->", txt, re.S):
    print("comment:", m)
zw = [c for c in txt if c in "\u200b\u200c\u200d\ufeff"]
print("zero-width count:", len(zw))
```

Инструменты: `grep`, `sed`, `python3`, `cat -A` (показать невидимое), `xxd`. Для системного поиска невидимых символов — скрипт, перебирающий коды. Типичные ошибки: смотреть отрендеренный Markdown (там каналы исчезают) вместо исходного файла; игнорировать reference-ссылки; не проверять Unicode.

## Расширенный разбор: Markdown как текстовый контейнер

Markdown — это текст, который рендерится в HTML. Избыточность синтаксиса даёт множество каналов. Начнём с самых простых. Первый — **HTML-комментарии**: `<!-- данные -->` не отображаются в отрендеренном виде, но лежат в исходнике. Их ищут `grep -o "<!--.*-->"`.

Второй — **reference-style ссылки**. Вместо `[текст](url)` пишут `[текст][ref]`, а определение `[ref]: url "title"` кладут в конец документа. Определения могут не использоваться, и тогда они — чистый канал. Порядок определений тоже может кодировать данные.

Третий — **хвостовые пробелы**. В Markdown два пробела в конце строки означают `<br>`. Значит, один пробел можно считать за 0, два — за 1. Читаешь строки, считаешь trailing-пробелы, собираешь биты.

Четвёртый — **alt-текст и title изображений**: `![alt](url "title")`. И alt, и title могут нести произвольные строки, которые не видны (alt виден только при ошибке загрузки). Пятый — **URL изображений**: данные прячут в query-параметрах (`?x=...`) или в имени файла.

Шестой — **невидимые Unicode-символы**: zero-width space (U+200B), zero-width joiner (U+200D), word joiner (U+2060), tags-блок (U+E0000–U+E007F). Они не видны вообще, но присутствуют в тексте. Седьмой — **порядок и отступы списков**, восьмой — **таблицы** (лишние пробелы в ячейках), девятый — **ссылки-сноски** и определения внизу.

```bash
grep -o "<!--.*-->" README.md
grep -nE "\[.+\]:\s*\S+" README.md
python3 -c "t=open('README.md',encoding='utf-8').read(); print([hex(ord(c)) for c in t if 0x200b<=ord(c)<=0x206f or 0xe0000<=ord(c)<=0xe007f])"
```

Извлечение — по каналу: комментарии регуляркой, хвостовые пробелы скриптом, невидимые символы перебором кодов. Инструменты: `grep`, `python3`, `cat -A`, `xxd`. Главное правило: работать с **исходным** файлом, а не с отрендеренным — рендер уничтожает каналы.

## Итог по Markdown

Markdown-стего — это частный случай «данные в тексте». Каналы: комментарии, reference-ссылки, хвостовые пробелы, alt/title, URL, невидимые Unicode, порядок элементов. Все они работают, потому что Markdown рендерится в HTML и лишнее отбрасывается.

Практический вывод: при анализе любого текстового формата (Markdown, HTML, YAML, JSON, конфиги) сначала проверяй невидимые символы и хвостовые пробелы — это самые простые каналы. Затем комментарии. Затем порядок/структуру. И всегда работай с байтами исходника, а не с текстом в редакторе, который подчищает пробелы.

## Дополнительные приёмы и частые ловушки

Помимо описанных каналов, в Markdown есть ловушки. Первая — **визуально одинаковые символы**: кириллическая `а` и латинская `a`, греческая `ο` и латинская `o`. Подмена символов в тексте незаметна, но кодирует биты (гомоглифы). Второй — **нормализация Unicode**: `é` можно записать как один код (U+00E9) или как `e` + combining accent (U+0065 U+0301); выбор формы — канал.

Третий — **порядок определений сносок**. Четвёртый — **ширина горизонтальных линий** (`---` vs `-----`). Пятый — **число пробелов после маркера списка**. Шестой — **экранирование** (`\*` vs `*`), которое визуально не отличается.

Седьмая ловушка — редакторы. Многие IDE и редакторы автоматически подчищают хвостовые пробелы и нормализуют Unicode, уничтожая канал. Поэтому анализировать нужно байты исходного файла (`xxd`, `python3` в режиме `rb`), а не текст, показанный редактором. Восьмая — кодировка: UTF-8 vs UTF-16 меняет представление и добавляет BOM.

```bash
xxd README.md | head
python3 -c "d=open('README.md','rb').read(); print(len(d), d[:32])"
```

Итог: Markdown-стего требует работы с байтами и внимания к Unicode. Самые простые каналы (комментарии, хвостовые пробелы, невидимые символы) находятся быстро; гомоглифы и нормализация — сложнее и требуют сравнения с ожидаемым текстом.

## Резюме по Markdown

Markdown-стего — данные в тексте: комментарии, reference-ссылки, хвостовые пробелы, alt/title, URL, невидимые Unicode, порядок элементов, гомоглифы. Работай с байтами исходника (`xxd`, `python3` в `rb`), а не с текстом редактора. Инструменты: `grep`, `python3`, `cat -A`.

## Что мы теперь знаем
- HTML-комментарии и reference-ссылки не рендерятся, но остаются в файле.
- Хвостовые пробелы и alt/title/URL — каналы разметки.
- Рендер (`markdown`/`pandoc`) — нормализация, убивающая каналы.
- `cat -A` — быстрый способ увидеть «невидимое».
