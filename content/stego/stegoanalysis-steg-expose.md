## Вопрос, с которого всё начинается

У тебя не один файл, а папка из сотни изображений — и нужно понять, в каких есть
данные. Гонять вручную хи-квадрат по каждому — долго и ненадёжно. Нужен
**пайплайн**: несколько детекторов, один агрегированный вердикт, порог. Именно так
работают StegExpose и Aletheia. Разберём, как их читать.

## Наш пример: файл image.png

```bash
python3 stegexpose.py
```

```text
[chi-square]  p=0.0003 -> STEGO
[RS analysis] alpha=0.41 -> STEGO
[SPA]         alpha=0.38 -> STEGO
[aggregate]   3/3 detectors -> STEGO (confidence=high)
```

Три независимых метода согласились. Итог — «stego» с высокой уверенностью.

## Шаг 1: зачем объединять детекторы

Каждый детектор ломается на своём: хи-квадрат слеп к ±1-matching, RS шумит на
текстурах, SPA ошибается на малых payload. Но их ошибки **не полностью
коррелированы**. Если проголосовать, случайные промахи компенсируются, а
согласованный сигнал усиливается. Это та же идея, что и ансамбль классификаторов,
но на уровне готовых эвристик.

## Шаг 2: StegExpose

StegExpose — открытый инструмент (Java) для пакетного анализа. Его конвейер:

1. Открыть изображение, привести к нужному виду.
2. Прогнать набор детекторов (хи-квадрат, RS, SPA, WS-подобный).
3. Сравнить каждый балл с порогом.
4. Если **большинство** детекторов выше порога — пометить файл как подозрительный.

Порог — ключевой параметр. Низкий порог → много ложных срабатываний (FP), высокий
→ пропуски (FN). В CTF порог часто занижают: лучше проверить лишний файл.

## Шаг 3: Aletheia

Aletheia — более «научный» инструмент: он строит собственные признаки (в том числе
из rich models) и классифицирует с обученной моделью. Он не просто «голосует», а
даёт вероятность. В отличие от StegExpose, Aletheia чувствительнее к адаптивным
схемам, но требует более тяжёлых вычислений.

## Шаг 4: FP, FN и рабочий порог

Разберём термины на пальцах:

- **FP (false positive)** — чистый файл помечен как stego. Стоит времени на
  проверку.
- **FN (false negative)** — stego-файл пропущен. Это худший случай в экспертизе.

Рабочий приём — **двухпороговая схема**: ниже нижнего порога — «чисто», выше
верхнего — «stego», между — «требует ручной проверки». Так не теряются пограничные
случаи.

## Шаг 5: практика — читаем агрегат

```bash
python3 extract.py
```

```text
nto{st3g3xp0s3_w0rkfl0w}
```

Пайплайн отметил файл, извлечение достало данные. В реальной работе после «STEGO»
всегда идёт ручной этап: определить метод, извлечь, проверить результат.

## Шаг 6: ограничения и подводные камни

- **Пересжатие.** Если файл прошёл JPEG, пиксельные детекторы врут — нужен
  DCT-пайплайн.
- **Малый payload.** Все три детектора могут молчать при α < 0.05.
- **Стегоключ.** Если данные зашифрованы, детект подтвердит наличие, но извлечь без
  ключа не выйдет.
- **Cover-source mismatch.** Модели, обученные на одном корпусе, ошибаются на другом.

## Шаг 7: как устроен StegExpose внутри

StegExpose — это Java-утилита с конвейером из нескольких классических детекторов.
Её внутренняя логика:

```text
for each image:
    bgr = read(image)
    scores = {}
    scores['chi'] = chi_square_attack(bgr)
    scores['rs']  = rs_analysis(bgr)
    scores['spa'] = spa_analysis(bgr)
    scores['ws']  = weighted_stego(bgr)
    votes = sum(1 for s in scores.values() if s > threshold)
    verdict = 'SUSPICIOUS' if votes >= ceil(len(scores)/2) else 'CLEAN'
```

Ключевое — `threshold` и правило большинства. Порог задаётся для каждого детектора
отдельно, потому что у них разные шкалы (p-value против доли α). Именно поэтому
StegExpose не «одна метрика», а **ансамбль с ручной калибровкой**.

## Шаг 8: как подобрать порог

Порог — компромисс между FP и FN. Рабочий метод: взять небольшой набор чистых
изображений (если есть) и прогнать по ним. Порог ставят так, чтобы на чистых
срабатываний было мало, но не терять реальные stego. Если чистых нет — берут
консервативный порог и **двухпороговую** схему:

- score < 0.3 → CLEAN
- 0.3 ≤ score < 0.7 → MAYBE (ручная проверка)
- score ≥ 0.7 → STEGO

Так пограничные файлы не выбрасываются и не помечаются ложно.

## Шаг 9: Aletheia в сравнении

| Свойство | StegExpose | Aletheia |
|---|---|---|
| Признаки | классические эвристики | rich-model + ML |
| Язык | Java | C++/Python |
| Скорость | быстрый | медленнее |
| Чувствительность | средняя | высокая (адаптивные схемы) |
| Настройка | порог | обученная модель |
| Вывод | голосование | вероятность |

Aletheia требует больше ресурсов, но на малых payload заметно чувствительнее.
Поэтому в серьёзной экспертизе сначала гоняют StegExpose (дешёвый триаж), а
подозрительные файлы добивают Aletheia.

## Шаг 10: как написать свой пайплайн

Свой пайплайн собрать несложно: объедини несколько оценщиков и проголосуй.

```python
import numpy as np
from PIL import Image

def detect(path, thr=0.5):
    img = np.asarray(Image.open(path).convert('RGB'))
    votes = 0
    votes += chi_square(img) > thr
    votes += rs_analysis(img) > thr
    votes += spa_analysis(img) > thr
    return votes >= 2
```

Плюс свой пайплайн: ты контролируешь пороги и можешь добавить доменную логику
(например, игнорировать пересжатые файлы).

## Шаг 11: частые ошибки

Первая — считать голосование «истиной»: если два детектора из трёх общие по
природе (например, оба пиксельные), их ошибки коррелируют, и ансамбль слабее, чем
кажется. Нужны **разнородные** детекторы. Вторая — не пересчитывать пороги после
смены корпуса. Третья — применять пиксельный пайплайн к JPEG без декодирования.
Четвёртая — забыть про масштаб: изображения разных размеров дают разные шкалы.

## Шаг 12: что дальше после вердикта

Получив «SUSPICIOUS», переходи к ручной работе: определи метод (`zsteg`, анализ
структуры), извлеки данные, проверь контрольные суммы. Если данные зашифрованы —
зафиксируй факт и длину, но отметь, что для извлечения нужен ключ. Именно так
автоматический детект превращается в экспертизу.

## Шаг 13: как читать отчёт StegExpose

Типичный вывод инструмента по файлу:

```text
image.png
  chi-square : 0.00021  (STEGO)
  RS         : 0.41     (STEGO)
  SPA        : 0.38     (STEGO)
  WS         : 0.40     (STEGO)
  verdict    : STEGO (4/4)
```

Читать надо **не итог**, а разброс по детекторам. Если все четыре согласны и числа
далеко от порога — вердикт надёжен. Если, скажем, WS молчит, а остальные кричат —
возможно, метод не LSB-replacement, и стоит пересмотреть гипотезу. Итоговая строка —
лишь агрегат, а детали говорят о методе.

## Шаг 14: пакетная обработка

StegExpose умеет рекурсивно обходить каталог. Рабочий сценарий: сначала прогон по
всему дереву, затем фильтрация строк со вердиктом STEGO/SUSPICIOUS. В CTF это
экономит время: вместо ручного перебора — один прогон и короткий список
подозрительных. Важно: инструмент не извлекает данные, только помечает.

## Шаг 15: связка с извлечением

Пайплайн — только начало. После пометки файла запускают извлечение: `zsteg` для PNG,
`steghide`/`outguess` для JPEG, `binwalk` для вложенных контейнеров. Если данные
зашифрованы, `steghide` попросит пароль — тогда фиксируют факт и переходят к
перебору/подсказкам. Так автоматический детект превращается в практический
результат.

## Шаг 16: пример на смешанной папке

Пусть в папке 50 изображений, из них 3 содержат данные. StegExpose отметит 3
истинных и, при низком пороге, 2 ложных. Ложные уйдут на ручную проверку и
отсеются. Итог: 3 из 3 найдены, 2 лишних проверки. Это нормальный размен: в
экспертизе пропуск (FN) дороже лишней проверки (FP), поэтому порог занижают.

## Шаг 17: почему пороги не универсальны

Порог зависит от типа изображений. На гладких картинках (небо, фон) детекторы
ведут себя иначе, чем на текстурных. Поэтому «порог 0.5» — лишь стартовая точка.
В пакетном режиме полезно разбить файлы по типу (пейзаж/портрет/скриншот) и
подбирать порог отдельно. Это удлиняет настройку, но резко снижает FP.

## Шаг 18: практическая ценность

Главная польза StegExpose в CTF — **скорость триажа**. Вместо того чтобы вручную
прогонять три теста на каждый файл, ты получаешь короткий список подозрительных.
Дальше работает ручная часть: определить метод и извлечь. Пайплайн не заменяет
аналитика, а расчищает ему фронт работы.

## Шаг 19: сводка модуля

StegExpose и Aletheia показывают главный принцип практического детекта: один метод
ненадёжен, а объединение разных методов даёт устойчивый вердикт. Пользуйся этим в
CTF: сначала быстрый пакетный прогон, затем ручная проверка помеченных файлов, и
только потом извлечение. Автоматика экономит время, но последнее слово всегда за
анализом структуры и извлечением данных.

## Шаг 20: что запомнить из пайплайна

Запомни три вещи. Первая: пайплайн нужен для скорости, а не для точности. Вторая:
разнородные детекторы важнее количества. Третья: любой вердикт — гипотеза, которую
подтверждают извлечением. Если держать эти три правила, автоматический детект
приносит пользу и не создаёт ложной уверенности.

## Шаг 21: заключение

StegExpose и Aletheia — не замена аналитику, а ускоритель. Они сужают область
поиска до нескольких подозрительных файлов, с которыми дальше работают вручную.
Именно такое разделение труда — автоматический триаж плюс ручной разбор — и есть
правильный рабочий процесс в задачах стегоанализа.

## Что мы теперь знаем

- Пайплайн объединяет несколько детекторов в один вердикт.
- StegExpose голосует по порогу, Aletheia даёт вероятность.
- FP/FN — цена выбора порога; используют двухпороговую схему.
- После автоматического вердикта всегда идёт ручное подтверждение и извлечение.
