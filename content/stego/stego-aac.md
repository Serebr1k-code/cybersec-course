## Вопрос, с которого всё начинается

`track.aac` — аудиофайл AAC. Сам AAC — это «голый» поток кадров, у него нет места под
метаданные. Но к нему спереди приклеивают тег **ID3v2** (тот же, что у MP3), а если
файл называется `.m4a`, он вообще лежит в MP4-контейнере. Значит, прятать есть где.
Разберём оба варианта.

## Наш пример: файл track.aac

```bash
file track.aac
xxd -l 64 track.aac
```

```text
track.aac: Audio file with ID3 version 2.3.0
00000000: 4944 3303 0000 0023 5458 5858 0000 0019  ID3.....#TXXX....
00000010: 0000 0364 6573 6300 6e74 6f7b 3461 635f  ...desc.nto{4ac_
00000020: 3164 3376 325f 7478 7878 7dfd f150 8000  1d3v2_txxx}..P..
```

Начинается с `ID3` — тег ID3v2.3. Дальше кадр `TXXX` (пользовательский текст), а в
нём ASCII-флаг. После тега — `FF F1 50 80` — начало кадра ADTS (сам AAC).

## Шаг 1: тег ID3v2

ID3v2 — это блок метаданных, который ставится перед аудиопотоком. Заголовок 10 байт:

```
ID3(3)
version(2)      — 0x03 0x00 = v2.3
flags(1)
size(4)         — размер тега БЕЗ заголовка, "syncsafe"
```

**Syncsafe** — важное: каждый байт размера хранит только 7 значащих бит, старший бит
всегда 0 (чтобы размер не содержал ложной sync-последовательности `FF`). Формула:
`size = b0*2^21 + b1*2^14 + b2*2^7 + b3`.

В нашем файле `00 00 00 23` syncsafe = 0x23 = 35. Тег занимает 35 байт.

## Шаг 2: кадры ID3v2

После заголовка идут **кадры**:

```
ID(4)                 — например TXXX, COMM, PRIV, APIC
size(4, big-endian)   — длина данных кадра
flags(2)
data(size)
```

Типы кадров:

- **`TXXX`** — пользовательский текст (описание + значение). Идеален для закладки.
- **`COMM`** — комментарий.
- **`PRIV`** — приватные бинарные данные (владелец + произвольные байты).
- **`APIC`** — картинка (обложка); внутрь можно спрятать что угодно.

В нашем кадре `TXXX` длиной `00 00 00 19` = 25: байт кодировки `03` (UTF-8),
описание `desc\0`, затем значение `nto{4ac_1d3v2_txxx}`.

## Шаг 3: достаём значение вручную

```bash
python3 - <<'PY'
d = open('track.aac','rb').read()
assert d[:3] == b'ID3'
sz = (d[6]<<21)|(d[7]<<14)|(d[8]<<7)|d[9]
i = 10
end = 10 + sz
while i + 10 <= end:
    fid = d[i:i+4]
    flen = int.from_bytes(d[i+4:i+8],'big')
    body = d[i+10:i+10+flen]
    if fid == b'TXXX':
        # кодировка(1) + описание + \0 + значение
        enc = body[0]
        parts = body[1:].split(b'\x00',1)
        print(parts[1].decode('utf-8'))
    i += 10 + flen
PY
```

```text
nto{4ac_1d3v2_txxx}
```

## Шаг 4: ADTS-кадры и MP4-обёртка

**ADTS** — потоковый формат AAC. Каждый кадр начинается с sync-слова `FF F` (12 бит
единиц), затем: профиль, частота, каналы, длина кадра, буфер. ADTS-кадры можно
проверять на «странные» длины, но закладки в них редки.

**MP4/M4A** (`.m4a`, `.mp4`): AAC лежит в ISOBMFF-контейнере, как AVIF. Теги — в
боксе `moov` → `udta` → `meta` → `ilst`. Закладка — в кастомном боксе или в
`ilst`-элементе `©cmt`/`----`. Разбирается тем же парсером ISOBMFF.

## Шаг 5: инструменты

```bash
exiftool -a -G1 track.aac | grep -iE 'Comment|Title|TXXX|User'
ffprobe -hide_banner track.aac
id3v2 -l track.aac            # список кадров ID3v2
strings track.aac | grep nto
```

`id3v2 -l` покажет все кадры, включая `TXXX`. `exiftool` вытащит пользовательские
поля. Ручной парсер нужен, если кадр нестандартный или инструмент не установлен.

## Шаг 6: кадры ID3v2 в деталях

Список кадров, которые чаще всего несут закладки:

| Кадр | Смысл | Почему удобен |
|---|---|---|
| `TXXX` | пользовательский текст | произвольные ключ и значение |
| `COMM` | комментарий | свободный текст + язык |
| `PRIV` | приватные данные | владелец + любые байты |
| `APIC` | картинка | внутрь можно вложить файл |
| `GEOB` | бинарный объект | произвольный контейнер |

`TXXX` — самый частый: у него есть поле «описание» и «значение», оба произвольные.
Если видишь `TXXX` с описанием вроде `flag`, `comment`, `stego` — читай значение.

## Шаг 7: ID3v1 в конце файла

Кроме ID3v2 в начале, у MP3/AAC есть старый тег **ID3v1** — ровно 128 байт в конце
файла, начинающиеся с `TAG`. В нём поля фиксированной длины: title, artist, album,
year, comment, genre. Комментарий (30 байт) — классическое место для короткого флага.
Проверить: `xxd` последние 128 байт и поискать `TAG`.

```bash
tail -c 128 track.aac | xxd | head
```

## Шаг 8: APE-теги и другие расширения

Некоторые файлы несут теги **APE** (Monkey's Audio) — блок `APETAGEX` с произвольными
парами ключ=значение. Они встречаются у MP3/AAC, если файл обрабатывали
соответствующим софтом. Общее правило: любой тег с полем «значение» — кандидат.

## Шаг 9: чек-лист по AAC

1. `xxd -l 16` — есть ли `ID3`.
2. Если есть — распарси тег ID3v2 (syncsafe размер!), обойди кадры.
3. Ищи `TXXX`/`COMM`/`PRIV`/`GEOB`.
4. Проверь конец файла на ID3v1 (`TAG`) и APE (`APETAGEX`).
5. Если файл `.m4a` — разбирай как ISOBMFF (`moov`/`ilst`).
6. Если всё чисто — смотри сами ADTS-кадры на аномалии длин.

AAC — это «поток плюс теги». Теги приносит контейнер, и почти вся стеганография здесь
живёт именно в них.

## Второй пример: ID3v1 в конце файла

Допустим, спереди тега нет. Тогда проверяем конец файла: ID3v1 — это ровно 128 байт,
начинающиеся с `TAG`. Разберём их.

```bash
python3 - <<'PY'
d = open('track.aac','rb').read()
if d[-128:-125] == b'TAG':
    tag = d[-128:]
    print('title  :', tag[3:33].decode('latin-1').strip())
    print('artist :', tag[33:63].decode('latin-1').strip())
    print('album  :', tag[63:93].decode('latin-1').strip())
    print('year   :', tag[93:97].decode('latin-1').strip())
    print('comment:', tag[97:127].decode('latin-1').strip())
else:
    print('no ID3v1 tag')
PY
```

ID3v1 стар и примитивен: поля фиксированной длины, кодировка latin-1. Но именно
поэтому флаг туда кладут без затей — он гарантированно переживёт копирование файла.
Проверять оба конца (ID3v2 спереди, ID3v1 сзади) — базовое правило для любого
медиафайла.

## Частые ошибки при разборе AAC

Первая ошибка — неверно читать syncsafe-размер. Начинающие считают размер тега как
обычное 32-битное число, и он получается в разы больше реального (потому что старшие
биты каждого байта — нули, но их всё равно умножают). Правильная формула:
`size = b0*2^21 + b1*2^14 + b2*2^7 + b3`. Ошибка здесь сдвигает весь разбор кадров.

Вторая ошибка — забыть про кодировку текстовых кадров. Первый байт кадра `TXXX` —
это код кодировки: `00` — latin-1, `01` — UTF-16 с BOM, `03` — UTF-8. Если её
проигнорировать, в значении будут лишние байты или «кракозябры». В примере выше мы
пропускаем первый байт (`body[1:]`).

Третья ошибка — путать теги и поток. Теги (ID3v2, ID3v1, APE) — это метаданные;
поток (ADTS-кадры) — это звук. Стеганография в AAC почти всегда в тегах, потому что
сам поток проверяется декодером и ломается от любого вмешательства.

## AAC в контейнере MP4

Если файл называется `.m4a` или `.mp4`, это ISOBMFF. Теги там лежат не в ID3, а в
боксе `moov` → `udta` → `meta` → `ilst`. Разбирается тем же рекурсивным обходчиком
боксов, что и AVIF. Полезные элементы `ilst`: `©nam` (название), `©ART` (исполнитель),
`©cmt` (комментарий), `----` (произвольные). Флаг часто лежит в `©cmt` или в `----`.

## Итоговая стратегия поиска в AAC

Практический порядок действий для незнакомого `.aac`/`.m4a`: сначала посмотри на
первые байты и определи, есть ли ID3v2. Если есть — распарси кадры и выпиши все
текстовые значения. Затем проверь последние 128 байт на ID3v1 и `APETAGEX`. Если файл
в контейнере MP4 — обойди боксы `moov`/`udta`/`meta`/`ilst`. И только если всё это
чисто — смотри сами ADTS-кадры на аномальные длины.

Такой порядок экономит время: теги находятся за секунды, а потоковый анализ требует
написания кода. В девяти случаях из десяти флаг лежит в тегах, и лишь в десятом —
в структуре кадров.

## Что проверять в последнюю очередь

Если теги и контейнер чистые, остаются сами ADTS-кадры. Каждый кадр имеет заголовок
с длиной, профилем и номером; можно искать аномальные длины или нестандартные
значения полей. Это уже низкоуровневый анализ, требующий аккуратного парсинга
битовых полей. Как и в Ogg, в CTF до этого доходят редко: теги находятся первыми.

Ещё один ориентир: если длина кадра ADTS в заголовке не совпадает с реальным смещением до следующего sync-слова, файл правили вручную — это признак закладки в потоке.

## Что мы теперь знаем

- AAC бывает потоком ADTS (sync `FF F`) с тегом ID3v2 впереди.
- ID3v2: заголовок 10 байт, размер **syncsafe**; затем кадры `ID+size+flags+data`.
- `TXXX`, `COMM`, `PRIV`, `APIC` — типовые кадры для закладок.
- `.m4a`/`.mp4` — это ISOBMFF, разбирается как AVIF.
- `id3v2 -l` и `exiftool` ускоряют, но ручной парсер надёжнее.
