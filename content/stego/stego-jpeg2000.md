## Вопрос, с которого всё начинается

Тебе дали `image.jp2` — файл JPEG 2000. Обычные просмотрщики показывают картинку, но
`zsteg` и `steghide` на нём ничего не находят. Где в JPEG 2000 вообще можно спрятать
сообщение? Чтобы ответить, надо понять две вещи: как устроено сжатие и как устроен
контейнер. Начнём с контейнера — он устроен проще, чем кажется.

## Наш пример: файл image.jp2

Смотрим тип и первые байты:

```bash
file image.jp2
xxd -l 64 image.jp2
```

```text
image.jp2: JPEG 2000 Part 1 (JP2)
00000000: 0000 000c 6a50 2020 0d0a 870a 0000 0014  ....jP  ........
00000010: 6674 7970 6a70 3220 0000 0000 6a70 3220  ftypjp2 ....jp2
00000020: 0000 0029 464c 4720 6e74 6f7b 6a32 6b5f  ...)FLG nto{j2k_
00000030: 6230 785f 7734 7633 6c33 745f 666c 3430  b0x_w4v3l3t_fl40
```

Первые 12 байт — **сигнатура** JPEG 2000: `00 00 00 0c` (длина 12) и ASCII `jP  `,
дальше `0d 0a 87 0a`. По этим байтам `file` и узнаёт формат. Дальше виден бокс
`ftyp`, а за ним — что-то с типом `FLG `. Вот это уже подозрительно.

## Шаг 1: JP2 — это блочный контейнер, а не «просто картинка»

В отличие от PNG, где чанки, JPEG 2000 Part 1 (формат **JP2**) — это набор
**боксов**. Бокс устроен ровно так же, как чанк PNG:

```
[ 4 байта: размер ][ 4 байта: тип ][ размер-8 байт данных ]
```

Размер в JPEG 2000 — **big-endian** (в PNG тоже big-endian, но в RIFF/WebP — little).
Тип — 4 ASCII-символа. Спецификация определяет десятки типов: `ftyp` (тип файла),
`jp2h` (заголовок изображения), `ihdr` (высота/ширина/число компонент), `colr`
(цветовое пространство), `jp2c` (собственно сжатые данные — кодстрим), `xml `, `uuid`.

Ключевая мысль: **любой неизвестный бокс просмотрщики игнорируют**. Они ищут
знакомые типы и пропускают остальные. Значит, закладку удобно положить в бокс,
которого нет в спецификации, или в `uuid`-бокс.

## Шаг 2: почему вейвлеты, а не DCT

JPEG (старый) режет картинку на блоки 8×8 и применяет к каждому **дискретно-косинусное
преобразование** (DCT). JPEG 2000 использует **дискретно-вейвлетное преобразование**
(DWT): картинку раскладывают на частотные поддиапазоны (LL, HL, LH, HH) рекурсивно,
и каждая «деталь» описывается коэффициентами. Сжатие — за счёт квантования этих
коэффициентов и энтропийного кодирования (EBCOT/арифметика MQ).

Для стеганографии это важно по двум причинам. Во-первых, коэффициенты DWT — тоже
носитель (как DCT-коэффициенты в уроке про jsteg), только другой домен. Во-вторых,
JPEG 2000 умеет **регионы интереса** (ROI) и **прогрессивную передачу**, поэтому
часть кодстрима может быть «неважной» — туда можно дописать данные.

Но самый простой путь — контейнерный. Вернёмся к нашему файлу.

## Шаг 3: находим нестандартный бокс вручную

Пишем парсер боксов — он идёт по файлу и печатает тип каждого бокса:

```bash
python3 - <<'PY'
import struct
d = open('image.jp2','rb').read()
i = 0
while i + 8 <= len(d):
    size = struct.unpack('>I', d[i:i+4])[0]
    typ = d[i+4:i+8]
    print(f'{i:>6}  {size:>6}  {typ}')
    if size == 0: break
    i += size
PY
```

```text
     0      12  b'jP  '
    12      20  b'ftyp'
    32      41  b'FLG '
```

Три бокса. Первый — сигнатура, второй — тип файла, третий — `FLG `. В спецификации
JP2 такого бокса нет. Читаем его данные:

```bash
python3 - <<'PY'
import struct
d = open('image.jp2','rb').read()
i = 32
size = struct.unpack('>I', d[i:i+4])[0]
print(d[i+8:i+size].decode())
PY
```

```text
nto{j2k_b0x_w4v3l3t_fl4g}
```

Флаг достали. Это и есть классическая закладка «в контейнере», а не «в пикселях».

## Шаг 4: что скажут готовые инструменты

`exiftool` покажет метаданные боксов `xml `, `uuid` и `exif`, если они есть:

```bash
exiftool image.jp2 | grep -iE 'Comment|XML|UUID'
```

`binwalk` найдёт вложенные файлы по сигнатурам:

```bash
binwalk image.jp2
```

А вот `zsteg`/`steghide` на JP2 обычно молчат — они заточены под PNG/BMP/JPEG. Это
нормально: у каждого кодека свои инструменты. `openjpeg` (`opj_dump`) покажет
структуру кодстрима, если закладка внутри `jp2c`.

## Шаг 5: другие места сокрытия в JP2

- **`uuid`-бокс** — по спецификации для частных расширений. Идеальное место: тип
  `uuid`, дальше 16 байт идентификатора и произвольные данные.
- **comment-бокс (`copt`/`cxml`)** — текстовые метаданные; в них часто пишут флаг.
- **appended data** — байты после последнего бокса. Парсеры дочитывают до конца, а
  некоторые просмотрщики — нет.
- **внутри `jp2c`** — LSB вейвлет-коэффициентов или дописанные пакеты в конце
  кодстрима (сложнее, требует понимания EBCOT).

## Что мы теперь знаем

- JP2 — контейнер из боксов `размер(4) + тип(4) + данные`, размер big-endian.
- Сигнатура — 12 байт `jP  ` + `0d 0a 87 0a`.
- Неизвестные боксы просмотрщики игнорируют — это и есть щель для закладки.
- Сжатие — вейвлетное (DWT), но контейнерные закладки ищутся до всякой математики.
- Парсер боксов пишется в 8 строк на Python и решает большинство CTF-задач.
