Файловая система хранит данные не только в содержимом файлов. Между логическими и физическими единицами (блоками, кластерами, секторами) остаются «щели»: файловый slack, неиспользуемые inode/MFT-записи, зарезервированные области, скрытые разделы. Всё это — готовые носители для стеганографии, потому что обычные средства (проводник, `ls`, `cat`) их не показывают.

## Файловый slack

Slack — это пространство между концом файла и концом последнего выделенного блока. Файл размером 1 КБ занимает кластер 4 КБ — 3 КБ остаются «пустыми» и могут нести данные, невидимые для самого файла.

Виды:

- **File slack** — от конца данных файла до конца последнего кластера.
- **RAM slack** — от конца данных до конца сектора.
- **Drive slack** — неиспользуемые кластеры в конце раздела.

Поиск данных в slack: карвинг (`foremost`, `scalpel`) и анализ неразмеченного пространства (`blkls` из sleuthkit).

```bash
# извлечь нераспределённое пространство образа
blkls -A disk.img > unallocated.bin
foremost -i unallocated.bin -o out/
```

## Альтернативные потоки NTFS (ADS)

NTFS поддерживает несколько потоков данных на файл: основной `file.txt` и дополнительные `file.txt:secret`. Проводник и многие инструменты показывают только основной поток. ADS — классическое место сокрытия в Windows.

Работа с ADS:

```bash
# список потоков
dir /r file.txt
# чтение потока
more < file.txt:secret
# запись в поток
echo hidden > file.txt:secret
```

В Linux для разбора NTFS-образов:

```bash
ntfsls --streams image.dd
ntfscat image.dd -s secret file.txt
```

## Скрытые разделы и «невидимые» области

Данные могут лежать в разделах, которые не отражены в таблице разделов (GPT/MBR), либо в «потерянных» разделах после переразбиения. Также бывают **host-protected areas (HPA)** и **device configuration overlay (DCO)** — области диска, скрытые самим накопителем.

Поиск:

```bash
fdisk -l disk.img              # что заявлено
mmls disk.img                  # таблица разделов
testdisk disk.img              # поиск потерянных разделов
```

## Стеганографические файловые системы

Существуют специализированные ФС для правдоподобия отрицания (deniable encryption), где наличие данных недоказуемо:

- **TrueCrypt/VeraCrypt hidden volumes** — скрытый том внутри свободного места внешнего тома.
- **StegFS** — исследовательская стеганографическая ФС.
- **Rubberhose** и подобные — правдоподобное отрицание.

Определить их существование сложно; часто требуется пароль и косвенные признаки (несоответствие заявленного и реального размера).

## Разобранный пример: ADS в CTF

Дан образ `disk.dd` (NTFS). Ищем потоки:

```bash
$ ntfsls --streams disk.dd
file.txt  secret
$ ntfscat disk.dd -s secret file.txt
flag{ntfs_ads}
```

Если это slack — карвим нераспределённое:

```bash
$ blkls -A disk.dd > unalloc.bin
$ strings -n 8 unalloc.bin | grep -iE 'flag|base64'
```

## Инструменты

- **sleuthkit**: `fls`, `icat`, `blkls`, `mmls`, `istat`.
- **`ntfs-3g`/`ntfsls`/`ntfscat`** — NTFS, включая ADS.
- **`foremost`/`scalpel`** — карвинг.
- **`testdisk`/`photorec`** — восстановление разделов/файлов.
- **`dd`/`dcfldd`** — образы, в т. ч. с HPA/DCO.

```bash
fls -r -p disk.img | head        # дерево файлов
istat disk.img <inode>           # метаданные узла
```

## Частые ошибки и подводные камни

- **Искать только файлы.** Данные живут в slack и неразмеченном пространстве.
- **Игнорировать ADS на NTFS.** Проводник их не показывает.
- **Считать таблицу разделов истиной.** Бывают скрытые HPA/DCO-области.
- **Работать с оригиналом.** Всегда делайте образ (`dd`).
- **Забыть про несколько потоков.** Их может быть много, с разными именами.
- **Путать slack с потерянными файлами.** Это разные классы.

## Таблица каналов в ФС

| Канал | Где | Обнаружение |
|---|---|---|
| File slack | конец последнего кластера | `blkls`, карвинг |
| Drive slack | нераспределённые кластеры | `blkls -A` |
| ADS | доп. потоки NTFS | `ntfsls --streams` |
| Скрытый раздел | вне таблицы разделов | `testdisk`, `mmls` |
| HPA/DCO | скрыт накопителем | `hdparm`, `dcfldd` |
| Скрытый том (VeraCrypt) | внутри свободного места | косвенно/пароль |

## Что дальше / решение

- Сделайте образ диска (`dd`), работайте с копией.
- Проверьте ADS (`ntfsls --streams`) и slack (`blkls`).
- Просмотрите таблицу разделов и поищите потерянные (`testdisk`).
- Проверьте HPA/DCO для физических дисков (`hdparm -N`).
- Карвите неразмеченное пространство и ищите сигнатуры.

## Журналирование ФС и его следы

Современные ФС ведут журналы (ext3/4 journal, NTFS $LogFile, APFS). Журнал хранит метаданные операций и может содержать копии данных, которые «уже удалены». Для forensics это золотая жила: запись из журнала позволяет восстановить содержимое, время и порядок операций.

```bash
# просмотр журнала ext4
debugfs -R "logdump -a" disk.img | head
# NTFS: анализ $LogFile
logfileparser.py -f '$LogFile' disk.img
```

Данные, спрятанные в ФС, часто выдают себя аномалиями в журнале: обращение к «пустым» кластерам, изменение ADS, правка timestamps.

## Временные метки как канал

Атрибуты файла (MACB: Modify, Access, Change, Birth) хранят время с точностью до наносекунд. Их можно использовать как канал: кодировать данные в младших разрядах nanosecond-полей. Детект — по неестественно «структурированным» временам (timestomping).

```bash
stat file.txt          # наносекундная точность
```

```python
import os
st = os.stat("file.txt")
print(st.st_mtime_ns % 1000)   # младшие разряды — потенциальный канал
```

## Зарезервированные и служебные области

Помимо slack и ADS, есть:

- **Загрузочная область (boot sector/partition)** — свободное место.
- **$MFT-записи NTFS** — неиспользуемые атрибуты.
- **Inode ext4** — неиспользуемые поля, зарезервированные байты.
- **Superblock backup** — копии суперблока.
- **Bad blocks / remapped sectors** — переназначенные сектора.

```bash
istat -o 0 disk.img <inode>     # поля inode
fsstat disk.img | head          # структура ФС
```

| Задача | Инструмент |
|---|---|
| Образ диска | `dd`, `dcfldd`, `ddrescue` |
| Дерево файлов | `fls`, `ntfsls` |
| Неразмеченное | `blkls`, `bulk_extractor` |
| Метаданные узла | `istat`, `fls -l` |
| Карвинг | `foremost`, `scalpel`, `photorec` |
| Разделы | `mmls`, `testdisk`, `parted` |
| Журнал | `debugfs`, `logfileparser` |

```bash
bulk_extractor -o out/ disk.img    # автоматический поиск артефактов
```

## Практический сценарий CTF

1. Определить тип ФС: `fsstat disk.img`.
2. Построить дерево: `fls -r disk.img`.
3. Проверить ADS (NTFS) и удалённые файлы (`fls -d`).
4. Извлечь неразмеченное (`blkls -A`) и прогнать карвинг.
5. Проверить slack и журнал.
6. Искать строки: `strings -n 6 | grep -iE 'flag|base64'`.

## Ловушки и подводные камни

- **Работать с оригиналом** — риск необратимо изменить улики; всегда образ.
- **Игнорировать журнал** — там данные, «удалённые» из дерева.
- **Забыть про nanosecond-поля** — канал в младших разрядах времени.
- **Не проверять загрузочную область** — там тоже свободное место.
- **Путать удалённые файлы и slack** — это разные источники.
- **Не учитывать HPA/DCO** — скрытые накопителем области.

## Восстановление удалённых данных

Удаление файла в большинстве ФС не стирает содержимое — оно лишь помечает кластеры как свободные. Пока они не перезаписаны, данные восстанавливаемы. Порядок:

1. Сделать образ диска (немедленно, чтобы не перезаписать).
2. Найти удалённые записи: `fls -d disk.img` (ext), `ntfsundelete` (NTFS).
3. Извлечь по inode/MFT: `icat disk.img <inode>`.
4. Если метаданные утеряны — карвинг по сигнатурам (`foremost`, `scalpel`).

```bash
fls -d -r disk.img | head
icat disk.img <inode> > recovered.bin
```

## Скрытые тома и правдоподобное отрицание

VeraCrypt/TrueCrypt позволяют создать скрытый том внутри свободного места внешнего. Снаружи том выглядит как случайные данные, и доказать существование скрытого тома без пароля нельзя. Признаки: внешний том почти заполнен «случайными» байтами при малом объёме реальных файлов, расхождение заявленного и фактического использования.

```bash
# внешний том монтируется по паролю; скрытый — по второму паролю
veracrypt --text --mount disk.img /mnt/vc --password=... --pim=0
```

## Стеганографические ФС и распределённые метаданные

Исследовательские ФС (StegFS) распределяют данные по «покрывающим» блокам так, что наличие скрытого содержимого статистически неотличимо. Практического инструмента для их извлечения обычно нет — только пароль и оригинальная реализация. В CTF такие задачи редки, но понимание принципа (данные размазаны по свободному пространству) помогает при анализе «странных» дисков.

## Итог по ФС-стеганографии

Файловая система даёт множество каналов: slack, ADS, неразмеченное пространство, скрытые разделы, HPA/DCO, скрытые тома, младшие разряды timestamps, журналы. Практический алгоритм: образ → дерево → ADS → удалённые → неразмеченное → карвинг → журнал. Инструменты: sleuthkit (`fls`, `icat`, `blkls`, `istat`, `mmls`), `ntfsls`/`ntfscat`, `foremost`/`scalpel`, `testdisk`/`photorec`. Ключевое правило — никогда не работать с оригиналом, только с образом.
