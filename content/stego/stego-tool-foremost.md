## Вопрос, с которого всё начинается

У тебя есть сырой образ `evidence.dd` — поток байтов без файловой системы. Внутри
где-то лежат файлы, но «открыть» образ нельзя: нет директорий, нет имён. Как
достать содержимое? Ответ — **карвинг**: поиск файлов по сигнатурам. Инструменты
`foremost` и `scalpel` делают это автоматически. Разберём.

## Наш пример: файл evidence.dd

```bash
foremost -i evidence.dd -o out
```

```text
Foremost version 1.5.7
Processing: evidence.dd
| * | Found: PNG (image/png)
Found 1 file.
  out/png/00000000.png  (4096 bytes)
  payload: nto{f0r3m0st_c4rv3d}
```

Инструмент нашёл PNG внутри сырого образа. Это и есть карвинг.

## Шаг 1: что такое карвинг

Карвинг — восстановление файлов по **сигнатурам** (магическим байтам) без опоры на
файловую систему. Для PNG сигнатура — `89 50 4E 47`, для JPEG — `FF D8 FF`, для
PDF — `%PDF`. Инструмент сканирует поток, находит начало файла и пытается
определить его конец (по структуре или по сигнатуре конца).

Карвинг не идеален: возможны ложные срабатывания и «склеенные» файлы. Но для
стего-задач он незаменим.

## Шаг 2: foremost

`foremost` — классический карвер. Он:

1. читает конфиг `/etc/foremost.conf` со списком типов;
2. сканирует вход по сигнатурам;
3. сохраняет найденные файлы в выходной каталог по типам.

Ключевые флаги: `-i` (вход), `-o` (выход), `-t` (типы), `-q` (тихий режим).
Тип можно ограничить, чтобы не собирать мусор: `foremost -t png,jpg,pdf`.

## Шаг 3: scalpel

`scalpel` — «наследник» foremost, быстрее и гибче. Он использует похожий конфиг,
но умеет задавать максимальные размеры и точнее определять границы. Синтаксис
аналогичен: `scalpel -c scalpel.conf -o out evidence.dd`.

## Шаг 4: карвинг и стего

В стего-задачах карвинг применяют, когда:

- данные **вложены** в другой файл (полиглот);
- данные лежат **после EOF** основного контейнера;
- есть **сырой дамп** (диск, память), а не файл.

Например, JPEG с приклеенным ZIP: `foremost` вырежет и JPEG, и ZIP.

## Шаг 5: извлечение флага

```bash
foremost -i evidence.dd -o out | grep nto > found.txt
cat found.txt
```

```text
nto{f0r3m0st_c4rv3d}
```

Инструмент вырезал PNG, внутри которого (или рядом) лежал флаг. Мы подтвердили
карвинг.

## Шаг 6: ограничения

- **Неполные файлы**: если конец потерян, карвер даст обрезанный файл.
- **Ложные срабатывания**: сигнатура может встретиться в случайных данных.
- **Сжатие/шифрование**: внутри архива карвинг не видит содержимое.
- **Кастомные форматы**: если сигнатуры нет в конфиге, файл не найдётся.

## Шаг 7: как строить процесс

Для сырого образа: `file` → `binwalk` (сигнатуры + энтропия) → `foremost`/`scalpel`
(карвинг) → `strings` → ручной разбор найденного. `binwalk` даёт карту, `foremost`
достаёт файлы.

## Шаг 8: справочник foremost

| Флаг | Что делает |
|---|---|
| `-i file` | входной образ |
| `-o dir` | выходной каталог |
| `-t png,jpg` | ограничить типы |
| `-c cfg` | свой конфиг |
| `-q` | тихий режим |
| `-v` | подробный режим |

Ограничение типов (`-t`) ускоряет работу и уменьшает мусор. Начни с одного-двух
типов, потом расширяй.

## Шаг 9: формат конфига

`foremost.conf` задаёт типы строками: имя, расширение, флаг, максимальный размер,
сигнатура начала, сигнатура конца. Пример для PNG:

```text
png y 2000000 \x89PNG\r\n\x1a\n \x00\x00\x00\x00IEND\xaeB`\x82
```

Здесь `y` — учитывать регистр, числа — максимальный размер. Понимая конфиг, ты
можешь добавить кастомный формат задачи (например, свой контейнер) и вырезать его
карвингом.

## Шаг 10: разбор работы карвера

Карвер идёт по потоку, ищет сигнатуру начала. Нашёл — начинает записывать байты в
новый файл. Останавливается, когда встретит сигнатуру конца или достигнет
максимального размера. Если конца нет — файл обрезан. Поэтому карвинг хорошо
работает для форматов с чётким маркером конца (PNG, JPEG, PDF), хуже — для форматов
без него.

## Шаг 11: scalpel подробнее

`scalpel` быстрее и точнее. Его конфиг похож, но позволяет задавать несколько
сигнатур конца и точнее определять границы. Для больших образов (гигабайты)
scalpel предпочтительнее: foremost может работать часами.

## Шаг 12: частые ошибки

Первая — не ограничить типы и получить мегабайты мусора. Вторая — карвить
зашифрованный образ (внутри ничего не видно). Третья — забыть, что неполный файл
всё равно сохраняется и может выглядеть «битым». Четвёртая — не проверить найденное
на вложенность (файл в файле).

## Шаг 13: полный разбор примера

История: `evidence.dd` → `foremost -i evidence.dd -o out` находит PNG → читаем
payload → флаг `nto{f0r3m0st_c4rv3d}` в `found.txt`. Если бы в образе был ещё и ZIP,
карвер вырезал бы и его: `out/zip/`. Так один прогон даёт все вложенные файлы.

## Шаг 14: связка с binwalk

`binwalk` и `foremost` дополняют друг друга. `binwalk` строит карту сигнатур и
показывает смещения, `foremost` вырезает файлы. Рабочий порядок: сначала `binwalk`
(понять, что внутри), потом `foremost` (достать), потом ручной разбор.

## Шаг 15: карвинг и память

Карвинг применяют не только к дискам, но и к дампам памяти. В дампе может лежать
сжатое изображение или документ — карвер их вырежет. Ограничение то же: если данные
в памяти были сжаты/зашифрованы, карвинг бессилен.

## Шаг 16: пошаговый сценарий на сыром образе

Шаг 1: `file evidence.dd` — что это. Шаг 2: `binwalk evidence.dd` — карта сигнатур
и энтропия. Шаг 3: `foremost -i evidence.dd -o out -t png,jpg,pdf,zip` — карвинг
основных типов. Шаг 4: просмотр `out/` по каталогам. Шаг 5: `strings` по найденным
файлам. Шаг 6: ручной разбор подозрительных. Такой конвейер даёт максимум за один
проход.

## Шаг 17: энтропия как подсказка

Энтропия — мера «случайности» байтов. У сжатых/зашифрованных данных она близка к 8
бит/байт, у текста и кода — ниже. `binwalk -E` рисует карту энтропии: высокие
участки — сжатые/шифрованные блоки. Это подсказывает, где искать контейнеры, и
отличает настоящие данные от заполнителей.

## Шаг 18: карвинг без конфига

Иногда нужно вырезать формат, которого нет в конфиге. Тогда пишешь правило сам:
сигнатуру начала и конца. Например, для кастомного контейнера с маркером
`MYST` и концом `END!`. Добавляешь строку в `foremost.conf` и запускаешь. Это
продвинутый, но полезный приём для задач с авторским форматом.

## Шаг 19: ложные срабатывания

Карвер может «найти» файл там, где его нет: сигнатура случайно встретилась в
данных. Признаки ложного: файл не открывается, размер подозрительно мал, CRC не
сходится. Всегда проверяй найденное (`file`, открытие, проверка структуры).

## Шаг 20: производительность

На больших образах карвинг занимает время. Ускорить: ограничить типы (`-t`),
использовать `scalpel`, разбить образ на части и карвить параллельно. Но помни:
карвинг — I/O-зависимая задача, и упор в диск.

## Шаг 21: полный разбор со вложенностью

Продолжим историю: `foremost` нашёл PNG с флагом. Но что если внутри PNG был ещё
ZIP? Тогда карвер вырезал бы оба, и мы разобрали бы ZIP (`unzip`, `zip2john`).
Правило: после карвинга всегда проверяй найденное на вложенность — рекурсивно.

## Шаг 22: где карвинг не работает

В шифрованном или сжатом без заголовков потоке карвинг бессилен: сигнатур нет.
Также он плохо работает с форматами без чёткого конца (некоторые бинарные
контейнеры). Тогда помогает ручной анализ по смещениям и размерам.

## Шаг 23: итог по инструменту

foremost и scalpel — основа восстановления данных из сырых потоков. Они находят
файлы там, где нет файловой системы, и достают вложенное. Их ограничение — сигнатуры
и конец файла; там, где их нет, карвинг не поможет. Но для образов дисков, дампов
памяти и полиглотов это незаменимый первый шаг.

## Шаг 24: карвинг ZIP и вложенность

ZIP — частый вложенный контейнер. `foremost -t zip` вырежет архивы, даже если у
них нет имени. Дальше `unzip` покажет содержимое; если архив зашифрован — `zip2john`
и `john`. Вложенность (ZIP в PNG в образе) разбирается рекурсивно: карвинг →
распаковка → снова карвинг. Так достаётся даже глубоко спрятанное.

## Шаг 25: заключение

Карвинг — универсальный ключ к сырым данным. Когда нет файловой системы, нет имён
и нет структуры, сигнатуры остаются единственной зацепкой. foremost и scalpel
превращают хаос байтов в набор файлов, которые дальше разбираются обычными
инструментами. Это обязательный навык для форензики и CTF-задач с образами.

## Шаг 26: практический чек-лист

Прежде чем карвить, ответь: что за образ, какие сигнатуры в нём ожидаются, и есть
ли смысл ограничивать типы. Затем запусти foremost, проверь найденное на
вложенность и валидность. Ложные срабатывания проверяй через `file` и открытие.
Если карвинг не дал ничего, проверь энтропию через binwalk — возможно, данные
зашифрованы и требуют другого подхода.

## Шаг 27: заметка о повторном карвинге

После первого карвинга полезно прогнать foremost повторно по **вырезанным** файлам:
внутри них может быть ещё один слой. Такой рекурсивный карвинг часто достаёт
данные, спрятанные в глубине. Не останавливайся на первом результате — проверь
каждый найденный файл как самостоятельный контейнер.

## Что мы теперь знаем

- Карвинг восстанавливает файлы по сигнатурам без файловой системы.
- `foremost`/`scalpel` — основные карверы; конфиг задаёт типы.
- Карвинг нужен для вложенных файлов, данных после EOF и сырых дампов.
- Ограничения: неполные файлы, ложные срабатывания, кастомные форматы.
