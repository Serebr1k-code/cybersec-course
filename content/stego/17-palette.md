## Что такое палитровый PNG

Палитровый PNG (color type 3) хранит не RGB-значения пикселей, а **индексы** в таблицу цветов `PLTE`. Каждый пиксель — число от 0 до N-1, указывающее на запись в палитре. Таблица `PLTE` содержит N RGB-троек. Такой формат компактнее, но даёт дополнительные каналы сокрытия: сами индексы, порядок записей палитры и «неиспользуемые» цвета.

## PLTE и индексы

```bash
$ pngcheck -v palette.png
  chunk PLTE at offset 0x00029, length 48   # 16 цветов
  chunk IDAT ...
```

48 байт / 3 = 16 цветов. Если в изображении реально используется, скажем, 12 из них, четыре записи `PLTE` — «мёртвые» и могут хранить данные. Индексы пикселей лежат в IDAT (после распаковки и снятия фильтров).

## Неиспользуемые цвета

Самый простой канал: в палитре есть цвета, которые **не встречаются** ни в одном пикселе. Их значения можно менять произвольно — визуально ничего не изменится. Автор прячет данные в младших битах RGB-троек таких записей.

```python
from PIL import Image
import numpy as np
img = Image.open('palette.png')
idx = np.array(img)                 # индексы
pal = img.getpalette()              # список [r,g,b, r,g,b, ...]
used = set(idx.flatten().tolist())
n = len(pal)//3
unused = [i for i in range(n) if i not in used]
print('unused entries:', unused)
```

Проверьте младшие биты `pal[3*i:3*i+3]` для неиспользуемых `i`.

## Порядок записей PLTE как канал

Даже если все цвета используются, **порядок** записей в палитре можно менять перестановками, кодируя данные. Палитра — это список; перестановка двух соседних записей меняет индексы в пикселях, но если соответствующим образом переиндексировать пиксели, изображение не изменится. Это классический приём «сортировка палитры как канал».

Практически: если задача даёт палитровый PNG и флаг не находится в LSB индексов, посмотрите на порядок `PLTE` — не отсортирован ли он «странно» (например, по какому-то признаку), и не кодирует ли перестановка биты.

## LSB в индексах

Индексы пикселей — тоже числа, и их младшие биты можно использовать. Но осторожно: изменение индекса меняет **цвет** пикселя на соседний из палитры, что может быть заметно, если палитра не «гладкая». Поэтому LSB индексов часто применяют к палитрам, где соседние цвета близки.

```python
bits = ''.join(format(int(v) & 1, '01b') for v in idx.flatten())
out = bytes(int(bits[i:i+8],2) for i in range(0,len(bits)-7,8))
print(out[:40])
```

## Инструменты

- **`pngcheck -v`** — увидеть `PLTE`, его длину и число цветов.
- **`Pillow`** (`getpalette`, `np.array(img)`) — доступ к палитре и индексам.
- **`exiftool`** — метаданные, включая `tRNS`.
- **`zsteg`** — иногда находит каналы в палитровых PNG (с `-a`).
- **`pngcrush`/`optipng`** — пересжатие (осторожно: может перестроить палитру).

## Разобранный пример

```python
from PIL import Image
import numpy as np
img = Image.open('task.png')
idx = np.array(img)
pal = img.getpalette()
used = set(idx.flatten().tolist())
bits = ''
for i in range(len(pal)//3):
    if i not in used:                       # неиспользуемая запись
        for c in range(3):
            bits += format(pal[3*i+c] & 1, '01b')
out = bytes(int(bits[i:i+8],2) for i in range(0,len(bits)-7,8))
print(out[:40])   # b'flag{plte_unused}'
```

Маршрут: `pngcheck` → число цветов; Pillow → неиспользуемые записи; LSB их RGB → флаг. Если неиспользуемых нет — проверьте порядок `PLTE` и LSB индексов.

## tRNS и прозрачность

Палитровый PNG может содержать чанк `tRNS` — массив альфа-значений для записей палитры. Прозрачные/полупрозрачные цвета — дополнительный канал: данные прячут в альфа-значениях `tRNS`, которые визуально почти незаметны.

```bash
exiftool palette.png | grep -i transparency
```

## Ёмкость и незаметность

- Неиспользуемые записи: 3 бита на запись (по одному в RGB) — ёмкость мала, но незаметность максимальна.
- LSB индексов: 1 бит на пиксель — ёмкость как у обычного LSB.
- Порядок палитры: ~`log2(N!)` бит на всю перестановку.

Комбинация этих каналов даёт неожиданно большую суммарную ёмкость при высокой скрытности.

## Частые ошибки и подводные камни

- **Конвертировать PNG в RGB** — потеряете палитру и канал.
- **Открыть и пересохранить** — палитра перестроится, данные погибнут.
- **Смотреть только пиксели** — данные могут быть в `PLTE`/`tRNS`.
- **Забыть про порядок записей** — перестановка тоже канал.
- **Игнорировать `pngcheck`** — он сразу показывает число цветов и чанки.
- **Путать палитровый PNG с индексированным GIF** — похоже, но формат другой.

## Итог

Палитровые изображения дают три независимых канала: значения неиспользуемых записей, порядок палитры и младшие биты индексов (плюс `tRNS`). Это делает их удобным носителем для небольших сообщений с высокой скрытностью. Ключ к разбору — доступ к самой палитре через Pillow и сравнение с множеством реально используемых цветов.

## Сортировка палитры как канал (подробно)

Перестановка записей палитры — мощный канал, потому что число перестановок `N!` огромно. Автор может задать **порядок** записей по некоторому правилу (например, сортировка по яркости, по имени, по хешу) и закодировать данные в отклонениях от «естественного» порядка. Либо использовать порядок как есть — тогда данные «читаются» прямо из перестановки.

Практическая проверка: сравните палитру с ожидаемой сортировкой.

```python
from PIL import Image
img = Image.open('palette.png')
pal = img.getpalette()
n = len(pal)//3
entries = [tuple(pal[3*i:3*i+3]) for i in range(n)]
by_lum = sorted(entries, key=lambda c: 0.299*c[0]+0.587*c[1]+0.114*c[2])
print('sorted by luminance?', entries == by_lum)
# если порядок "почти отсортирован" — различия кодируют биты
```

Если порядок «почти» отсортирован, разница между фактическим и отсортированным порядком — это данные.

## Сравнение с индексированным GIF

GIF тоже палитровый (до 256 цветов, глобальная и локальные палитры). Приёмы похожи, но есть отличия:

- GIF поддерживает **покадровость** и задержки между кадрами (отдельный канал).
- Локальные палитры у каждого кадра дают больше свободы.
- `PLTE` в PNG один (без локальных), но есть `tRNS`.

Поэтому GIF-задачи разбирают и как палитровые, и как покадровые. Если PNG-палитровый канал пуст, а формат GIF — проверьте задержки кадров и различия между кадрами.

## Инструменты для палитровых изображений

- **`pngcheck -v`** — число цветов, наличие `tRNS`.
- **`Pillow`** — `getpalette()`, `np.array(img)` (индексы), `convert('P')`.
- **`gifsicle`/`gifinfo`** — для GIF-палитр и кадров.
- **`zsteg`** — иногда находит LSB в палитровых PNG.
- **собственный скрипт** — для неиспользуемых записей и порядка.

## Практический чек-лист палитровой задачи

1. `file`/`pngcheck -v` — подтвердить палитровый формат и число цветов.
2. Pillow: получить палитру и множество используемых индексов.
3. Найти неиспользуемые записи → LSB их RGB.
4. Проверить порядок палитры на «почти-сортировку».
5. LSB индексов пикселей (если палитра гладкая).
6. `tRNS` — данные в альфа-значениях.
7. Пусто → IDAT-поток, чанки, хвост.

## Расширенный разбор: пиксели, палитра и фильтры вместе

Палитровый PNG — это пересечение двух тем: палитры и потока IDAT. Чтобы добраться до индексов пикселей, недостаточно открыть файл в Pillow и взять массив — нужно понимать, что индексы лежат в IDAT-потоке и после распаковки проходят через фильтры строк. Для палитровых изображений `bpp` (байт на пиксель) равен 1 при глубине 8 бит, но бывает и меньше (1/2/4 бита на пиксель при малой палитре). Это важно: при глубине, например, 4 бита два индекса упакованы в один байт, и наивное чтение даёт неверные значения.

```python
from PIL import Image
import numpy as np
img = Image.open('pal.png')
print(img.mode, img.size)          # 'P' — палитровый
idx = np.array(img)                # Pillow сам распакует битовую глубину
print(idx.dtype, idx.max())
pal = img.getpalette()
print('colors:', len(pal)//3)
```

Pillow корректно распаковывает любую битовую глубину, поэтому для извлечения индексов он предпочтительнее ручного разбора IDAT. Но для поиска «лишних» байт в потоке ручной разбор всё ещё нужен.

## Как палитра влияет на заметность LSB индексов

Если соседние записи палитры близки по цвету, изменение младшего бита индекса почти не видно. Если палитра «разноцветная», LSB индексов даёт заметные цветовые скачки. Поэтому авторы задач, прячущие данные в индексах, часто используют **гладкую** палитру (градиент) — тогда канал скрытен. Это подсказка: если палитра выглядит как аккуратный градиент, проверьте LSB индексов в первую очередь.

## Индексированный GIF и локальные палитры

В отличие от PNG, GIF может иметь **локальную палитру** для каждого кадра. Это множит каналы: данные можно разложить по палитрам разных кадров, а также по задержкам между кадрами. Поэтому GIF-задачи редко решаются одним проходом — проверяйте каждый кадр и его палитру отдельно (`gifsicle --info`, извлечение кадров через `convert`/Pillow).

## Итог по палитровой стеганографии

Палитровые форматы дают редкое сочетание высокой скрытности и приличной ёмкости: неиспользуемые записи, порядок палитры, LSB индексов и `tRNS` можно комбинировать. Ключевые инструменты — Pillow (доступ к палитре и индексам) и `pngcheck` (структура). Если палитровый канал пуст, не забудьте про IDAT-поток: индексы живут именно там, и «лишние» байты потока — отдельный канал.

## Что делать дальше / решение

- `pngcheck -v` — убедиться, что PNG палитровый, и узнать число цветов.
- Pillow → найти неиспользуемые записи → LSB их RGB.
- Неиспользуемых нет → проверить порядок `PLTE` и LSB индексов.
- Проверить `tRNS` на данные в альфе.
- Пусто → перейти к IDAT-потоку и дописанному хвосту.
