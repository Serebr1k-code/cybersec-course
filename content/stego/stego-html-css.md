## Вопрос, с которого всё начинается

У тебя есть файл `index.html`. Открываешь в браузере — обычная страница с текстом.
Но в задаче сказано: данные спрятаны **внутри** страницы, и браузер их не показывает.
Как страница может нести информацию, не отображая её?

HTML — текстовый формат, а значит, к нему применимы все приёмы **текстовой**
стеганографии. Плюс у него есть собственные «невидимые» конструкции. Разберём их.

## Наш пример

Открываем страницу:

```
$ file index.html
index.html: HTML document, ASCII text
$ head -8 index.html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>Отчёт за квартал</title>
  <!-- build: 2024-06-01 -->
  <link rel="stylesheet" href="style.css">
</head>
```

Выглядит как обычный HTML. Начнём с самого очевидного канала — **комментариев**.

## Шаг 1: HTML-комментарии

Комментарий `<!-- ... -->` браузер полностью игнорирует, но он остаётся в файле.

```
$ grep -o '<!--.*-->' index.html
<!-- build: 2024-06-01 -->
<!-- note: nto{html_c0mm3nt_st4sh} -->
```

Это базовый приём. Часто данные кладут не целиком, а **частями** в разные комментарии,
чтобы `grep` по `nto{` не сработал сразу.

## Шаг 2: zero-width символы

Между видимыми буквами можно вставить **невидимые** символы Unicode:

- `U+200B` ZERO WIDTH SPACE
- `U+200C` ZERO WIDTH NON-JOINER
- `U+200D` ZERO WIDTH JOINER
- `U+FEFF` ZERO WIDTH NO-BREAK SPACE (BOM)

Браузер их не рисует, но в исходнике они есть. Два разных zero-width символа кодируют
бит (0/1), а весь текст становится носителем. Извлечение — скриптом:

```
$ python3 zw_extract.py index.html
found 480 zero-width chars
decoded: nto{z3r0_w1dth_1n_html}
```

Важно: в терминале их не видно, поэтому `cat` не поможет — нужен `hexdump`/`xxd` или
скрипт.

## Шаг 3: порядок атрибутов и правил

В HTML порядок атрибутов в теге **не важен** для рендеринга:

```
<a href="/a" class="btn" id="x">
```

и

```
<a class="btn" id="x" href="/a">
```

отображаются одинаково. Значит, **перестановкой атрибутов** можно кодировать биты
(перестановочная стеганография). То же в CSS: порядок независимых правил и свойств
внутри блока не влияет на результат.

## Шаг 4: CSS-специфичные приёмы

CSS даёт дополнительные каналы:

1. **Свойство `content`** в `::before`/`::after` может добавлять невидимый текст:
   ```css
   .x::after { content: "nto{css_c0nt3nt}"; font-size: 0; }
   ```
   `font-size: 0` делает символы невидимыми, но они в DOM.
2. **Кастомные переменные** `--key: value;` — произвольные строки в стилях.
3. **`display:none` / `visibility:hidden`** — скрытые элементы, видимые в исходнике.
4. **`color` в точности `#ffffff` на белом фоне** — «невидимый» текст (не стеганография,
   но классический трюк).
5. **data-URI** в `background-image` — картинка прямо в CSS, куда встроен payload.

## Шаг 5: пайплайн разбора

1. `file index.html` — текстовый?
2. `grep -o '<!--.*-->' index.html` — комментарии.
3. `python3 zw_extract.py index.html` — zero-width символы (или `xxd` и глазами по `e2 80 8b`).
4. Просмотреть `style.css` на `content`, кастомные переменные, скрытые селекторы.
5. Проверить `display:none` элементы и невидимый текст.
6. Помнить: браузер **нормализует** разметку, поэтому смотреть надо **исходник**, а не
   «Inspect Element» (DOM может отличаться от файла).

## Что мы теперь знаем

- HTML-комментарии — простейший канал.
- **Zero-width символы** кодируют биты, невидимы в браузере.
- **Порядок атрибутов/правил** не влияет на рендеринг — годится для битов.
- CSS даёт каналы через `content`, кастомные переменные, скрытые элементы, data-URI.
- Разбирать нужно **исходный файл**, а не DOM в инспекторе.
