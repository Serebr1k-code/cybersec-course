## Как PNG хранит пиксели: фильтры и zlib

PNG хранит пиксели не «как есть», а в виде сжатого потока `IDAT`. Перед сжатием строки пикселей проходят **фильтрацию** (predictive filtering), а затем весь поток сжимается **zlib/DEFLATE**. Понимание этого конвейера критично: чтобы извлечь или изменить пиксели вручную, нужно распаковать IDAT, снять фильтры, а при обратной записи — применить фильтры и сжать.

Конвейер кодирования PNG:

1. Пиксели разбиваются на строки (scanlines), каждая с байтом фильтра в начале.
2. К каждой строке применяется фильтр (0–4) — предсказание по соседям.
3. Отфильтрованные строки сжимаются zlib.
4. Сжатый поток режется на чанки `IDAT`.
5. Чанки `IHDR`, `IDAT`, `IEND` идут в файл с CRC.

Именно поэтому «просто поменять байт в IDAT» не работает: сначала нужно снять фильтры.

## Чтение IDAT вручную

```python
import struct, zlib
raw = open('image.png','rb').read()
i = 8
idat = b''
w = h = None
while i < len(raw):
    ln = struct.unpack('>I', raw[i:i+4])[0]
    typ = raw[i+4:i+8]
    data = raw[i+8:i+8+ln]
    if typ == b'IHDR':
        w, h, bd, ct = struct.unpack('>IIBB', data[:10])
        print('width', w, 'height', h, 'bitdepth', bd, 'colortype', ct)
    if typ == b'IDAT':
        idat += data
    i += 12 + ln
decompressed = zlib.decompress(idat)
print('first bytes:', decompressed[:20])
```

Первые байты после распаковки — это байт фильтра (0–4) и первые пиксели строки. Если видите осмысленные данные в распакованном потоке (например, `flag{`) — они в IDAT.

## Фильтры строк (0–4)

| Фильтр | Название | Предсказание |
|---|---|---|
| 0 | None | 0 |
| 1 | Sub | пиксель слева |
| 2 | Up | пиксель сверху |
| 3 | Average | среднее слева/сверху |
| 4 | Paeth | Paeth-предиктор |

Для восстановления пикселей нужно применить обратную фильтрацию. Но для стего-задач чаще достаточно распаковать IDAT и посмотреть **сырой** отфильтрованный поток: иногда данные спрятаны именно там (в «мусоре» между строк), либо сам факт аномального фильтра/странных байт — подсказка.

```python
def paeth(a,b,c):
    p=a+b-c; pa=abs(p-a); pb=abs(p-b); pc=abs(p-c)
    return a if pa<=pb and pa<=pc else (b if pb<=pc else c)
```

## Чересстрочный режим Adam7

Если в IHDR `interlace=1`, PNG использует **Adam7**: изображение разбито на 7 проходов с разным разрешением. Порядок пикселей в IDAT отличается от обычного, и многие инструменты (включая LSB-скрипты «в лоб») дают неверный результат. `zsteg` учитывает interlace не всегда, поэтому для интерлейсных PNG стоит либо деинтерлейсить через Pillow (`Image.open(...).convert('RGB')` даёт уже собранный кадр), либо извлекать из «собранного» массива пикселей, а не из сырого потока.

```python
from PIL import Image
img = Image.open('interlaced.png')     # Pillow соберёт Adam7 автоматически
import numpy as np
arr = np.array(img.convert('RGB'))
```

## Манипуляции IDAT: скрытие и аномалии

Что искать в IDAT-слое:

- **Лишние байты** после валидного zlib-потока (padding).
- **Второй zlib-поток** внутри одного IDAT.
- **Аномальные фильтры** (например, все строки с фильтром 0 при «фотографичном» изображении).
- **Несовпадение длины** распакованного потока с ожидаемой (`(w*bpp+1)*h`).

```bash
python3 -c "
import struct,zlib
raw=open('image.png','rb').read(); i=8; idat=b''
while i<len(raw):
    ln=struct.unpack('>I',raw[i:i+4])[0]; t=raw[i+4:i+8]
    if t==b'IDAT': idat+=raw[i+8:i+8+ln]
    i+=12+ln
d=zlib.decompress(idat); print(len(d))
"
```

Сравнив `len(d)` с ожидаемым, вы сразу увидите, есть ли «лишние» данные в потоке.

## Инструменты

- **`pngcheck -v`** — структура чанков и проверка CRC.
- **`zlib`/`Pillow`/`numpy`** — ручной разбор IDAT и пикселей.
- **`zsteg`** — перебор LSB (для собранных пикселей).
- **`pngcrush`/`optipng`** — пересжатие (иногда выявляет аномалии).
- **`binwalk`** — вложенные потоки в IDAT.

## Разобранный пример

```bash
$ pngcheck -v deep.png
  chunk IHDR ... bit depth 8, color type 2, interlace 0
  chunk IDAT ... length 120000
$ python3 - <<'PY'
import struct, zlib
raw=open('deep.png','rb').read(); i=8; idat=b''
while i<len(raw):
    ln=struct.unpack('>I',raw[i:i+4])[0]; t=raw[i+4:i+8]
    if t==b'IDAT': idat+=raw[i+8:i+8+ln]
    i+=12+ln
d=zlib.decompress(idat)
import re
print(re.findall(rb'flag\{[^}]+\}', d))
PY
[b'flag{idat_stream}']
```

Здесь данные лежали прямо в распакованном IDAT-потоке, минуя LSB. Такой канал часто пропускают, потому что инструменты смотрят на пиксели, а не на поток.

## Частые ошибки и подводные камни

- **Пытаться читать пиксели без снятия фильтров** — получите «шум».
- **Игнорировать interlace** — Adam7 ломает линейный порядок.
- **Не распаковывать IDAT** — данные могут быть в самом потоке.
- **Забыть про CRC** — повреждённый чанк может быть намеренным (аномалия).
- **Открыть и пересохранить PNG** — IDAT пережмётся, канал погибнет.
- **Не сверять длину** распакованного потока с ожидаемой.

## Скрытие данных в фильтрах и padding

Помимо самих пикселей, PNG даёт два «служебных» канала. Первый — **выбор фильтра строки**: для одной и той же картинки фильтр 0 и фильтр 4 дадут разные байты, но одинаковый визуал. Значение фильтра (0–4) кодирует ~2.3 бита на строку — автор может «играть» фильтрами. Второй — **padding/лишние байты** в конце zlib-потока или между чанками.

```python
import struct, zlib
raw = open('x.png','rb').read(); i=8; idat=b''
while i < len(raw):
    ln = struct.unpack('>I', raw[i:i+4])[0]; t = raw[i+4:i+8]
    if t == b'IDAT': idat += raw[i+8:i+8+ln]
    i += 12 + ln
d = zlib.decompressobj().decompress(idat)
# d — отфильтрованный поток; первый байт каждой строки — фильтр
w = struct.unpack('>I', raw[16:20])[0]
bpp = 3   # для color type 2
stride = w*bpp + 1
filters = [d[r*stride] for r in range(len(d)//stride)]
print(set(filters))   # аномальный набор фильтров — подсказка
```

Если все строки используют фильтр 0 (None) при «фотографичном» изображении — это неестественно и, вероятно, канал.

## Сравнение с LSB и чанками

| Слой | Что содержит | Как искать |
|---|---|---|
| IDAT-поток | отфильтрованные пиксели + возможный «мусор» | распаковка zlib, `grep flag` |
| Пиксели (после снятия фильтров) | LSB-данные | `zsteg`, скрипт |
| Чанки `tEXt`/`zTXt`/`iTXt` | текст/метаданные | `pngcheck`, `exiftool` |
| Хвост после `IEND` | дописанный файл | `binwalk`, `xxd | tail` |
| CRC | может быть повреждён намеренно | `pngcheck` |

Это четыре независимых слоя; задачу нельзя считать «пустой», пока не проверены все.

## Практический чек-лист PNG-задачи

1. `file` + `xxd | head` — магические байты, не полиглот ли.
2. `pngcheck -v` — чанки, CRC, размеры.
3. Распаковать IDAT, `grep` по сигнатурам — данные в потоке.
4. Сверить длину распакованного потока с ожидаемой.
5. Interlace? → деинтерлейс через Pillow.
6. `zsteg -a` — LSB.
7. `exiftool` — `tEXt`/`zTXt`/`iTXt`.
8. `binwalk` + `xxd | tail` — дописанное.

## Инструменты глубоко

- **`pngcheck -v`**: `-v` показывает каждый чанк, `-t` проверяет CRC, `-f` ищет ошибки.
- **`python3` + `zlib`**: единственный способ заглянуть «внутрь» IDAT.
- **`Pillow`**: автоматически собирает Adam7 и снимает фильтры — удобно для LSB-анализа.
- **`pngcrush`/`optipng`/`zopflipng`**: пересжатие; разница в размере может выдать скрытый контент.
- **`exiftool`/`strings`**: текстовые чанки и хвост.

## Почему это важно для стегоанализа

PNG-стеганография бывает «пиксельной» (LSB) и «потоковой» (данные в IDAT/padding). Инструменты перебора каналов ловят первую, но вторую видит только ручной разбор. Поэтому в задачах высокого уровня умение распаковать IDAT и снять фильтры отличает «нашёл» от «не нашёл». Держите под рукой готовый сниппет распаковки IDAT — он экономит время в каждой второй PNG-задаче.

## Итог по PNG-глубине

PNG — самый «слоистый» из популярных форматов: под пикселями лежит отфильтрованный поток, под ним zlib, а сверху — чанки и хвост. Умение распаковать IDAT и снять фильтры открывает канал, который инструменты перебора каналов не видят вовсе. Поэтому в PNG-задачах всегда держите готовый сниппет распаковки IDAT и сверку длины потока: если распакованных байт больше ожидаемого, данные почти наверняка в потоке. И помните про interlace — Adam7 ломает наивный линейный обход пикселей.

## Что делать дальше / решение

- `pngcheck -v` — структура и CRC.
- Распакуйте IDAT и поищите `flag{`/сигнатуры в потоке.
- Сверьте длину потока с ожидаемой — есть ли лишнее.
- Interlace — деинтерлейсьте через Pillow перед LSB-анализом.
- Пусто — переходите к LSB (`zsteg`), чанкам (`tEXt`/`zTXt`) и дописанному хвосту. Порядок именно такой: сначала дешёвый разбор потока, потом перебор каналов, потом структурные аномалии.
