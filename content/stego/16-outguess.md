## OutGuess: история и назначение

OutGuess — инструмент стеганографии для JPEG, созданный Нильсом Провосом (Neils Provos) в конце 1990-х как исследовательский проект и одновременно демонстрация уязвимости простых методов. Его принципиальное отличие от JSteg и большинства «наивных» JPEG-методов в том, что он не просто пишет данные в младшие биты DCT-коэффициентов, а старается **сохранить статистические свойства** изображения, чтобы обойти хи-квадрат-детект. Именно поэтому OutGuess часто встречается в CTF-задачах высокого уровня: он требует понимания не только «где данные», но и «как инструмент их прячет».

Второе важное свойство — OutGuess поддерживает **ключ** (пароль), который задаёт псевдослучайный порядок обхода коэффициентов. Без ключа извлечь данные невозможно, поэтому в задачах либо дают ключ, либо используют режим без ключа, либо предполагают брут короткого ключа. Также OutGuess работает **только с JPEG** — это принципиальное ограничение, которое сразу отсекает PNG/BMP.

## Алгоритм OutGuess 0.13 (v1)

Первая версия OutGuess (0.13) встраивает данные в младшие биты **квантованных DCT-коэффициентов**, но делает это нелинейно: она пропускает коэффициенты, равные 0 или ±1, потому что их изменение заметнее всего. Обход ведётся в псевдослучайном порядке, заданном ключом. Такая схема уже лучше наивного JSteg, но всё ещё оставляет статистический след: распределение коэффициентов смещается.

Практически для извлечения это означает, что данные лежат в младших битах «устойчивых» коэффициентов, а порядок задаётся ключом. Если ключа нет, а задача ожидает OutGuess, попробуйте пустой ключ и стандартные короткие ключи (имя файла, `outguess`, подсказка из условия).

## OutGuess 0.2: статистическое восстановление

Версия 0.2 — качественный скачок. После встраивания данных в часть коэффициентов OutGuess **корректирует остальные** коэффициенты так, чтобы глобальная гистограмма DCT-коэффициентов вернулась к виду, характерному для «чистого» JPEG. Иными словами, он «размазывает» статистический след встраивания по всему изображению. Именно из-за этого классический хи-квадрат-анализ OutGuess 0.2 не ловит.

Это важнейшая теоретическая идея: **стеганография может быть статистически прозрачной**. Она объясняет, почему «не нашли аномалий» не означает «данных нет», и почему для OutGuess нужны либо ключ, либо знание алгоритма, а не просто стегоанализ.

## Извлечение: флаги и ключи

```bash
outguess -r image.jpg out.txt          # извлечь (без ключа)
outguess -k "hunter2" -r image.jpg out.txt   # с ключом
outguess -k "hunter2" -d secret.txt -t cover.jpg out.jpg   # встроить (для практики)
```

Если `outguess -r` выдаёт мусор или пустой файл, вероятны две причины: нужен ключ или данные встроены другой версией/инструментом. Проверьте размер исходного JPEG: OutGuess 0.2 слегка увеличивает файл, а также меняет байты в `APP`-сегментах.

## steghide глубоко: алгоритм

`steghide` прячет данные в JPEG/BMP/WAV/AU, используя **граф соответствия** коэффициентов (в JPEG) и статистически похожий подход в WAV. Он строит пары «взаимозаменяемых» коэффициентов, между которыми различие незаметно, и кодирует бит выбором одного из пары. Пароль задаёт перестановку (порядок обхода) через криптографическую функцию.

Ключевые следствия: без пароля данные не извлечь; пустой пароль тоже допустим; `steghide info` может показать наличие и размер данных даже без пароля. Форматы: JPEG, BMP, WAV, AU (PNG не поддерживается!).

## steghide: работа с паролем

```bash
steghide info image.jpg            # есть ли данные, размер
steghide extract -sf image.jpg     # извлечь (интерактивно спросит пароль)
steghide extract -sf image.jpg -p ''   # пустой пароль
stegseek image.jpg rockyou.txt     # быстрый брут пароля
```

Практика: если `steghide info` показывает данные, но пароля нет — сначала попробуйте пустой пароль и пароли из метаданных/условия, и только потом брут `stegseek` (не мега-словарём, а разумным: rockyou или подсказка).

## Сравнение OutGuess и steghide

| Свойство | OutGuess | steghide |
|---|---|---|
| Форматы | только JPEG | JPEG, BMP, WAV, AU |
| Ключ | да (обязателен для v0.2) | пароль (может быть пустым) |
| Стегоанализ | устойчив (0.2) | средне устойчив |
| Инструмент | `outguess` | `steghide`/`stegseek` |
| Признак наличия | размер/`APP`-сегменты | `steghide info` |

Выбор инструмента диктуется форматом: PNG → `zsteg`/`stegsolve`; JPEG → `steghide`/`outguess`/`stegseek`; WAV → `steghide`/DeepSound.

## Другие JPEG-инструменты

- **`jsteg`** — простейший JPEG-LSB (младшие биты DCT); легко детектируется хи-квадратом.
- **`jphide`/`jpseek`** — прячут в JPEG с паролем; есть собственный формат.
- **`stegdetect`** — автоматический детектор JSteg/JPHide/OutGuess/F5 (устаревший, но полезный).
- **`F5`** — матричное кодирование, отдельный алгоритм (см. соответствующий урок).

```bash
stegdetect image.jpg
jpseek image.jpg out.txt
```

## Разобранный пример

```bash
$ file cover.jpg
cover.jpg: JPEG image data, JFIF standard 1.01
$ steghide info cover.jpg
"cover.jpg": contains embedded data (size 0.1 KB)
$ steghide extract -sf cover.jpg -p ''
wrote extracted data to "flag.txt"
$ cat flag.txt
flag{steghide_empty_pass}
# если бы пароль не пустой:
$ stegseek cover.jpg rockyou.txt
[i] Found passphrase: "s3cr3t" -> wrote "flag.txt"
```

Маршрут: `file` → `steghide info` → пустой пароль → `stegseek` при необходимости → `outguess -r` как альтернатива.

## Частые ошибки и подводные камни

- **Применять `outguess`/`steghide` к PNG** — не поддерживают.
- **Брутить, не проверив `steghide info`** — тратите время зря.
- **Забыть про пустой пароль** — очень частая закладка.
- **Игнорировать `outguess -k`** — без ключа извлечения не будет.
- **Открыть и пересохранить JPEG** — данные погибнут.
- **Считать OutGuess «недетектируемым»** — он лишь устойчивее к хи-квадрату.

## Итог

OutGuess и steghide — два главных «парольных» инструмента для JPEG (и steghide — ещё для BMP/WAV). Понимание их алгоритмов объясняет, почему данные не извлекаются без ключа и почему стегоанализ может «не видеть» OutGuess 0.2. В CTF порядок действий прост: определить формат, проверить наличие данных, попробовать пустой пароль/ключ, затем брут или альтернативный инструмент.

## Как проверить, что это именно OutGuess/steghide

Прежде чем брутить пароль, полезно понять, **каким** инструментом сделан контейнер. Признаки:

- **steghide**: `steghide info` сразу отвечает «contains embedded data»; размер данных печатается. Файл JPEG/BMP/WAV/AU.
- **OutGuess 0.2**: файл чуть больше ожидаемого; в `APP`-сегментах возможны изменения; `stegdetect` может показать `outguess`.
- **JSteg/jphide**: `stegdetect` распознаёт по типу.

```bash
stegdetect -t jopi image.jpg     # j=jsteg o=outguess p=jphide i=invisible
```

Если `stegdetect` говорит `outguess`, а `steghide info` — «no data», значит контейнер сделан OutGuess, и нужен `outguess -r` (с ключом или без).

## Почему steghide не работает с PNG

`steghide` использует статистику **DCT-коэффициентов** (JPEG) и **сэмплов** (WAV/AU). У PNG нет ни того, ни другого в нужном виде — пиксели хранятся как значения каналов, а сжатие zlib без потерь. Поэтому для PNG применяют методы, рассчитанные на пиксели (`zsteg`, `stegsolve`, скрипты). Это не «недоработка», а принципиальное различие форматов: lossy-носители (JPEG) прячут в коэффициентах, lossless (PNG) — в пикселях/потоке.

## Встраивание «наоборот»: как авторы готовят задачи

Полезно уметь воспроизвести закладку, чтобы понимать её свойства:

```bash
# steghide
echo "flag{test}" > s.txt
steghide embed -cf cover.jpg -ef s.txt -p pass123
steghide info cover.jpg

# outguess
outguess -k "pass123" -d s.txt -t cover.jpg stego.jpg
outguess -k "pass123" -r stego.jpg out.txt
```

Практикуясь так, вы быстро начинаете «чувствовать», какие изменения оставляет каждый инструмент, и узнаёте контейнеры с первого взгляда.

## Ёмкость JPEG-методов

- **steghide**: ~1 бит на ненулевой DCT-коэффициент; зависит от качества JPEG.
- **OutGuess 0.2**: около 1 бита на коэффициент, но часть ёмкости уходит на статистическое восстановление.
- **JSteg**: до 1 бита на коэффициент, но легко детектируется.
- **F5**: матричное кодирование `(n,k)`, эффективнее по числу изменений.

Ёмкость мала по сравнению с PNG-LSB (десятки килобайт против мегабайт), поэтому в JPEG прячут флаги и ключи, а не архивы. Если в задаче ожидается большой payload, а носитель — JPEG, вероятно, используется не DCT-метод, а дописанный хвост или метаданные.

## Итог по JPEG-парольной стеганографии

Порядок: определить формат → `steghide info`/`stegdetect` → пустой пароль/ключ → брут `stegseek`/короткие ключи OutGuess → альтернативный инструмент. Понимание алгоритмов объясняет, почему без пароля извлечение невозможно и почему `stegdetect` иногда ловит контейнер, а `steghide` — нет.

## Что делать дальше / решение

- JPEG → `steghide info`, `steghide extract`, `outguess -r`, `stegseek`.
- Пусто → `jsteg`/`jphide`/`stegdetect` и F5.
- Ключ в условии/метаданных — используйте его.
- Ничего — переходите к структурным каналам JPEG (таблицы Хаффмана, `APP`-сегменты, хвост).
