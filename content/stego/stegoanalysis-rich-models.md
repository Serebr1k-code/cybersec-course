## Вопрос, с которого всё начинается
Ты уже умеешь строить ансамблевый детектор. Но на чём он учится? Если признаки
бедные (например, одна гистограмма остатка), современные адаптивные схемы
встраивания он пропустит. Настоящая сила — в **богатых моделях** (rich models):
десятках тысяч признаков, описывающих локальную текстуру изображения. DCTR, JRM и
GFR — три классические богатые модели, на которых держится стегоанализ JPEG и
изображений в целом.

## Наш пример
Возьмём JPEG-изображение `photo.jpg`. Для JPEG признаки строятся не в пикселях,
а в **коэффициентах DCT** (дискретно-косинусного преобразования) — потому что
встраивание в JPEG живёт именно там. Мы разберём, как из DCT-коэффициентов
получается вектор признаков размерности тысячи и почему это работает.

## Шаг 1: JPEG и DCT-коэффициенты
JPEG режет изображение на блоки 8×8 и для каждого считает DCT — 64
коэффициента. Верхний левый (DC) отвечает за средний цвет блока, остальные (AC) —
за «частоты». Встраивание (F5, JSteg, OutGuess) меняет младшие разряды этих
коэффициентов, оставляя пиксельный домен почти нетронутым. Значит, и детектор
должен смотреть в DCT.

## Шаг 2: остатки в DCT — DCTR
Идея DCTR (DCT Residuals): взять деквантованные DCT-коэффициенты и посчитать
остатки как разность с предсказанием по соседним коэффициентам. Остатки
квантуются в небольшие целые значения, и их попарные/групповые гистограммы
становятся признаками. Один только DCTR даёт десятки тысяч измерений.

## Шаг 3: JRM — JPEG Rich Model
JRM строит признаки из **абсолютных значений и знаков** DCT-коэффициентов в
разных частотных поддиапазонах. Коэффициенты делят на подмножества по позиции в
блоке и по величине; внутри каждого считается совместная гистограмма пар
соседей. Размерность JRM — порядка 20 000+. Это делает его мощным, но и
дорогим.

## Шаг 4: GFR — Gabor Filter Residuals
GFR применяет банк фильтров Габора (разные ориентации и частоты) к изображению,
считает остатки и их гистограммы. Это уже пиксельный домен, но с богатым
текстурным описанием. GFR хорошо ловит адаптивные схемы (HUGO, WOW, S-UNIWARD),
которые прячутся в «сложных» текстурах.

## Шаг 5: мини-реализация признака
```python
import numpy as np
from PIL import Image

def dct2(block):
    return np.fft.fft2(block).real  # упрощённо, для идеи

img = np.asarray(Image.open('photo.jpg').convert('L'), dtype=float)
H, W = img.shape
feats = []
for y in range(0, H-7, 8):
    for x in range(0, W-7, 8):
        blk = img[y:y+8, x:x+8] - 128
        coef = dct2(blk)
        # остаток: коэффициент минус предсказание по соседу
        feats.append(coef[0,1] - coef[0,2])
feats = np.array(feats)
hist, _ = np.histogram(np.round(feats), bins=np.arange(-5.5, 6.5))
print('feature vector length =', len(hist), hist)
```

## Шаг 6: сколько признаков «достаточно»
На практике:
- DCTR — ~8 000 признаков, быстрый.
- JRM — ~20 000, точнее на JPEG.
- SRM (пространственный) — ~34 000, лучший для пиксельных схем.
Чем больше признаков, тем сильнее нужен ансамбль (иначе переобучение) — вот
почему rich models всегда идут в паре с ensemble classifier из прошлого урока.

## Шаг 7: практический стек
- **Matlab Steganalysis Toolbox** (DDE) — референсные реализации DCTR/JRM/SRM.
- **Aletheia** — обвязка с rich models + EC.
- **Deep learning (SRNet, Zhu-Net)** — CNN, обучаемая end-to-end вместо ручных
  признаков (см. stegoanalysis-cnn).

## Что мы теперь знаем
- JPEG-стегоанализ работает в DCT-домене, а не в пикселях.
- DCTR/JRM/GFR — «богатые» модели из десятков тысяч признаков.
- Rich models всегда сочетаются с ансамблевым классификатором.
- Ручные признаки и CNN решают одну задачу разными средствами.

## Куда дальше
Ручные богатые модели — классика. Дальше их место занимают свёрточные сети,
которые учатся признакам сами. В следующем уроке (stegoanalysis-cnn) разберём
SRNet и Zhu-Net. А пока запомни: для JPEG смотри в DCT, для адаптивных схем —
в текстурные остатки.
