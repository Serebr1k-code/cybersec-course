## Вопрос, с которого всё начинается

Тебе дали `capture.pcap` — запись трафика. Все пакеты «нормальные»: обычные заголовки, обычный payload. Но данные где-то есть. Где?

Ответ: в **таймингах**. **Тайминговый covert-канал** прячет данные не в содержимом пакетов, а во **времени** — в интервалах между ними. Такой канал невидим для систем анализа трафика (DPI), потому что payload чистый. Разберём на конкретном PCAP.

## Наш пример: capture.pcap

Сначала посмотрим метки времени пакетов и их интервалы.

```
$ tshark -r capture.pcap -T fields -e frame.time_epoch -e ip.src -e ip.dst | head -5
1700000000.001000 10.0.0.5 10.0.0.9
1700000000.002000 10.0.0.5 10.0.0.9
1700000000.005000 10.0.0.5 10.0.0.9
...
```

`frame.time_epoch` — время пакета в секундах с дробной частью. Смотрим на разницу: 1 мс, потом 3 мс… Интервалы разные — подозрительно.

## Шаг 1: интервалы как биты

Договоримся: **короткий интервал = 0, длинный = 1**. Соберём времена и посчитаем разницы:

```python
import dpkt
times = []
with open('capture.pcap', 'rb') as f:
    for ts, buf in dpkt.pcap.Reader(f):
        times.append(ts)
deltas = [times[i+1] - times[i] for i in range(len(times) - 1)]
thr = sum(deltas) / len(deltas)          # порог = среднее
bits = ''.join('1' if d > thr else '0' for d in deltas)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data)
```

```
$ python3 extract.py
b'flag{timing_channel}'
```

Флаг был закодирован в задержках между пакетами. Payload при этом был абсолютно нормальным.

## Шаг 2: выбор порога — главная сложность

Среднее как порог работает не всегда: если кластеры близки, биты «смажутся». Надёжнее посмотреть **гистограмму** интервалов: если видны два «горба» (короткие и длинные), порог ставится между ними.

```python
import dpkt
ts = [t for t, _ in dpkt.pcap.Reader(open('capture.pcap', 'rb'))]
d = [round((ts[i+1] - ts[i]) * 1000, 1) for i in range(len(ts) - 1)]
print(sorted(d)[:20])
```

Другие методы: **медиана** (устойчивее среднего) и **k-means** на два кластера (устойчив к «размытым» данным):

```python
import numpy as np
from scipy.cluster.vq import kmeans2
d = np.array(deltas).reshape(-1, 1)
cent, lab = kmeans2(d, 2, minit='++')
order = np.argsort(cent.ravel())          # какой кластер — 0, какой — 1
bits = ''.join(str(order[l]) for l in lab)
```

## Шаг 3: другие схемы кодирования

Тайминговый канал — не только интервалы:

| Схема | Кодирование |
|---|---|
| Интервальная | короткий/длинный интервал = 0/1 |
| Порядковая | порядок двух типов пакетов |
| Задержка ответа | время request→response (RTT) |
| Размер+время | комбинация |
| Выбор из N | какой из N типов отправлен (4 = 2 бита) |

Например, в ICMP-канале `echo-reply` может значить 1, а `timestamp` — 0.

## Шаг 4: как извлечь через tshark

Быстрые выборки без Python:

```bash
# дельта между отображаемыми пакетами
tshark -r capture.pcap -T fields -e frame.time_delta_displayed
# только ICMP
tshark -r capture.pcap -Y icmp -T fields -e frame.time_epoch
```

## Шаг 5: детект в IR

Для защитника тайминговые каналы видны по аномалиям:

| Метрика | Признак |
|---|---|
| Дисперсия интервалов | необычно регулярна или бимодальна |
| Средний RTT | не соответствует протоколу |
| Периодичность | строгие «паттерны» пауз |
| Полезная нагрузка | мала, а пакетов много |
| Энтропия таймингов | низкая (структурированный канал) |

```bash
tshark -r capture.pcap -Y "ip.addr==10.0.0.5" -T fields -e frame.time_delta_displayed | sort -n | uniq -c | tail
```

## Если не сработало

- Не смотри только payload — данные в таймингах.
- Единый средний порог может не разделить близкие кластеры — используй k-means.
- Не учитывай ретрансмиссии/шум — фильтруй по хосту/протоколу.
- Если биты не дают ASCII — инвертируй (0↔1), попробуй MSB-first, отбрось первый/последний интервал (служебные).

## Что мы теперь знаем

1. Тайминговый канал кодирует данные временем, а не содержимым.
2. Интервалы → порог → биты → байты.
3. Порог подбирают по гистограмме, медиане или k-means.
4. Есть и другие схемы: порядок, задержка ответа, размер, выбор из N.
5. Детект — по дисперсии и периодичности таймингов.

## Шаг 6: шпаргалка — извлечение за четыре шага

```bash
# 1) времена пакетов
tshark -r c.pcap -T fields -e frame.time_epoch -e ip.src -e ip.dst
# 2) интервалы → биты (порог по медиане)
python3 -c "
import dpkt
ts=[t for t,_ in dpkt.pcap.Reader(open('c.pcap','rb'))]
d=[ts[i+1]-ts[i] for i in range(len(ts)-1)]; m=sorted(d)[len(d)//2]
b=''.join('1' if x>m else '0' for x in d)
print(bytes(int(b[i:i+8],2) for i in range(0,len(b)-7,8)))"
# 3) если не ASCII — k-means и инверсия бит
# 4) гистограмма для выбора порога
```

## Шаг 9: как устроен тайминговый канал

Тайминговый канал передаёт биты через **время**, а не через содержимое пакетов. Схемы модуляции:

| Схема | Кодирование | Пример |
|---|---|---|
| Интервальная | короткий/длинный интервал = 0/1 | паузы между ICMP |
| Порядковая | порядок двух типов пакетов | ACK/SYN как биты |
| Задержка ответа | время request→response | RTT-модуляция |
| Размер+время | комбинация | малый/большой + пауза |
| Выбор из N | какой из N отправлен | 4 варианта = 2 бита |

Преимущество: payload пакетов «чистый», поэтому DPI не видит данных. Недостаток: канал чувствителен к джиттеру и требует точных меток времени.
