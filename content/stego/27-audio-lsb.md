## Вопрос, с которого всё начинается

В задании дан файл `secret.wav`. Открываешь — играет обычный писк, ничего подозрительного. Но задание намекает, что внутри что-то спрятано. Как звук может хранить текст?

Аудио в формате **WAV** — это не «сжатая музыка», а сырые измерения звуковой волны, записанные подряд. Каждое измерение называется **сэмпл** (sample) — число, описывающее громкость в конкретный момент. Именно в этих числах и прячут данные. Разберём на `secret.wav` от начала до конца.

## Наш пример: файл secret.wav

Первым делом выясняем, что это вообще за файл:

```bash
file secret.wav
```

```text
secret.wav: RIFF (little-endian) data, WAVE audio, Microsoft PCM, 16 bit, stereo 8000 Hz
```

Читаем по словам: **RIFF/WAVE** — это контейнер WAV; **PCM** — «сырые» измерения без сжатия; **16 bit** — каждое измерение занимает 16 бит (2 байта); **stereo** — два канала (левый и правый); **8000 Hz** — 8000 измерений в секунду на канал. Это ключевые параметры для дальнейшего разбора.

## Шаг 1: смотрим заголовок в hex

Любой WAV начинается со служебного **заголовка** — блока служебных байтов, где записаны параметры файла. Смотрим его побайтово:

```bash
xxd secret.wav | head -3
```

```text
00000000: 5249 4646 247d 0000 5741 5645 666d 7420  RIFF$}..WAVEfmt 
00000010: 1000 0000 0100 0200 401f 0000 007d 0000  ........@....}..
00000020: 0400 1000 6461 7461 007d 0000 0000 0000  ....data.}......
```

Видно сигнатуру `RIFF`, слово `WAVE`, затем `fmt ` (формат) и `data` — здесь начинаются сами сэмплы (со смещения `0x2C`, то есть 44 байта от начала). Стандартный WAV-заголовок занимает **44 байта** — важно знать это, чтобы не спутать служебные байты с данными.

## Шаг 2: что такое LSB

Каждый сэмпл — это число, например 16-битное. Его **младший бит** (Least Significant Bit, LSB) — самый «слабый»: меняя только его, мы меняем громкость на 1 из 32768, что для слуха незаметно.

Идея **LSB-стеганографии** проста: заменяем младший бит каждого сэмпла битом нашего секрета. Звук на слух не меняется, а в файле появляется поток битов, из которых собираются байты. Поскольку сэмплов много, ёмкость огромна — десятки-сотни килобайт.

## Шаг 3: извлекаем LSB

Пишем короткий скрипт: читаем сэмплы, берём младший бит каждого, собираем по 8 бит в байт:

```python
import wave, numpy as np
w = wave.open('secret.wav', 'rb')
n = w.getnframes()
d = np.frombuffer(w.readframes(n), '<i2')          # '<i2' = 16-бит little-endian
def to_bytes(bits):
    return bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
for name, arr in [('all', d), ('L', d[0::2]), ('R', d[1::2])]:
    b = ''.join(str(int(s) & 1) for s in arr)       # & 1 оставляет младший бит
    print(name, to_bytes(b)[:40])
```

`d[0::2]` — это «взять каждый второй элемент начиная с нуля» (левый канал), `d[1::2]` — правый. Запускаем:

```text
all b">\xb4\x1c\xf0\x9c\x89\x1e7=O>\xfa\x15/\xbe,\x1bw-\t\x9c\xd6\x99W\xaf:\xb5\x19\xb4\x98\x8d\x0b'(\x1f{\xaa\x00*\xaa"
L b'|,\xaa5c\x7f\x07\xf65b\xa9\xa1\xf7\xc2\xca\xa3V7\xf0\x7fcV*\x9a\x1f|,\xaa5c\x7f\x07\xf65b\xa9\xa1\xf7\xc2\xca'
R b'flag{lsb_1n_4ud10}\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00'
```

Вот и ответ. Каналы `all` и `L` дают **мусор** (случайные байты), а правый канал `R` — читаемый текст `flag{lsb_1n_4ud10}`. Данные были спрятаны только в одном канале.

## Шаг 4: почему важны каналы и порядок

Ключевой урок: **«все сэмплы подряд» — не всегда правильный выбор**. В стерео каналы чередуются (L, R, L, R…), поэтому если данные лежат только в одном, чтение «всех» перемешивает два потока и даёт мусор. Поэтому перебор идёт по осям:

- **Канал:** все / только левый / только правый.
- **Бит:** младший (0), 2–4 младших, иногда старший (MSB).
- **Порядок бит:** LSB-first / MSB-first.
- **Порядок байт сэмпла:** little / big endian.
- **Сдвиг:** учитывать или пропускать 44-байтовый заголовок.

## Шаг 5: инструменты

Ручной скрипт хорош для понимания, но есть готовые утилиты:

```bash
pip install stegolsb
stegolsb wavsteg -r -i secret.wav -o out.bin -n 1000
```

`stegolsb` извлекает (`-r` = read) в файл `out.bin` 1000 байт. Другие полезные инструменты: **wav2png** (рисует LSB-сэмплы картинкой — иногда секрет виден как изображение), **Sonic Visualiser** и **Audacity** (спектрограмма), **DeepSound** (парольная стего в аудио под Windows).

## Ёмкость и незаметность

Аудио — один из самых ёмких носителей для LSB. Посчитаем для нашего файла: 8000 измерений в секунду, 2 канала, длительность 1 секунда. Это 16000 сэмплов, а значит 16000 младших битов — ровно 2000 байт скрытого текста, если использовать все каналы. Реальные треки длятся минуты, поэтому ёмкость растёт до десятков и сотен килобайт — можно спрятать целую картинку или архив.

Незаметность обеспечивается тем, что человек не слышит изменение громкости на 1 из 32768. Но у метода есть слабость: младшие биты обычного аудио выглядят почти случайно, а вот вставленный текст делает их **структурированными**. На этом строится **стегоанализ** — наука об обнаружении скрытых данных (см. `stego-steganalysis`): специальные метрики замечают, что распределение младших битов перестало быть случайным.

## Как отличить мусор от данных

Главная практическая проблема — понять, попали ли мы в правильную комбинацию канал/бит/порядок. Признак успеха — **сигнатура**: узнаваемое начало файла или текста. Если в выводе видно `flag{`, `PK` (архив ZIP), `\x89PNG` (картинка) или `%PDF` — вы на верном пути. Если же поток выглядит как случайные непечатаемые байты, комбинация неверна, и её надо сменить.

Полезно писать перебор автоматически: пройти все каналы, 1–3 младших бита, оба порядка и оба эндианности, и в каждом варианте искать сигнатуры. Так вы за один запуск находите правильную схему вместо ручного перебора.

## Полный прогон: от файла к флагу

```text
secret.wav
  → file → PCM 16 bit stereo 8000 Hz
  → xxd → заголовок 44 байта, данные с 0x2C
  → скрипт LSB → all = мусор, L = мусор, R = flag{lsb_1n_4ud10}
  → итог: данные в правом канале, 1 LSB
```

## Если не сработало

- **Все каналы дают мусор** — попробуйте 2–4 младших бита, MSB, порядок MSB-first и эндианность `>i2`.
- **Данные не текст** — соберите биты в матрицу ширины W и сохраните как PNG: возможно, секрет — картинка.
- **LSB вообще пусто** — секрет может быть в **эхо-скрытии** (задержка эха кодирует биты, `stego-audio-echo`), **фазе** или на **спектрограмме** (`stego-audio-spec`).
- **Нужен пароль** — DeepSound использует парольную схему; без пароля не обойтись.

## Что мы теперь знаем

- **WAV/PCM** хранит звук как последовательность чисел-сэмплов.
- **LSB** — младший бит сэмпла; его замена незаметна на слух.
- Заголовок WAV — **44 байта**, дальше идут сэмплы.
- В стерео данные могут быть **только в одном канале** — перебираем L/R/all.
- Собирая биты по 8, получаем байты секрета.
- Если LSB пусто — переходим к эхо, фазе, спектрограмме.
