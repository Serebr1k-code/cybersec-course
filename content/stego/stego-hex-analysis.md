Когда `zsteg`, `stegsolve` и `binwalk` молчат, остаётся «низкоуровневый» путь — смотреть на байты глазами (или скриптом). Ручной hex-анализ — базовый навык, который выручает в задачах, где данные спрятаны нестандартно: в служебных полях, в разнице между двумя версиями файла, в аномалии энтропии. Этот урок — практическая методика: как читать структуру, как делать diff, что искать в дампе.

## Чтение структуры через xxd

Начинайте с первых байт — там сигнатура и заголовок:

```bash
xxd image.png | head -5
# 00000000: 8950 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR
# 00000010: 0000 0200 0000 0200 0806 0000 00f4 78d4  ..............x.
```

Разбор: `89 50 4e 47` — PNG; далее IHDR с шириной/высотой (`0000 0200` = 512) и глубиной/типом (`08` глубина, `06` = RGBA). Смотрите на несоответствия: ширина в заголовке vs реальная, «лишние» чанки, данные после `IEND`.

```bash
xxd image.png | tail -5
# 0004ffe0: ... 4945 4e44 ae42 6082 504b 0304  .......IEND..BPK..
# ^ после IEND идёт PK — встроенный ZIP!
```

## Поиск сигнатур

Ищите известные сигнатуры прямо в дампе:

```bash
grep -aboP '\x89PNG' file.bin
grep -aboP 'PK\x03\x04' file.bin
grep -aboP '%PDF' file.bin
strings -n 8 file.bin | grep -iE 'flag|ctf|base64|secret'
```

`-a` — считать бинарным, `-b` — смещение, `-o` — только смещение. Это быстрый способ найти встроенные файлы без `binwalk`.

## Diff двух «одинаковых» файлов

Мощнейший приём: если есть cover и stego (или две версии), разница покажет встроенные данные. Для бинарных файлов используйте `cmp`/`radiff2`/`xxd`+`diff`:

```bash
cmp -l cover.png stego.png | head
#  42  61  62       # байт 42: было 0x31 ('1'), стало 0x32 ('2')
```

`cmp -l` выводит позиции и отличающиеся байты (восьмерично). Для изображений разница в младших битах = LSB-встраивание.

```bash
python3 - <<'PY'
a = open("cover.png","rb").read()
b = open("stego.png","rb").read()
diff = [i for i,(x,y) in enumerate(zip(a,b)) if x!=y]
print("diff bytes:", len(diff), "first:", diff[:20])
PY
```

Если различия идут «через один байт» в области IDAT — это LSB.

## Анализ энтропии

Стеганография повышает энтропию (вносит «шум»). Считайте энтропию по блокам и ищите аномально «шумные» участки:

```python
import math, collections
def entropy(b):
    c = collections.Counter(b); n = len(b)
    return -sum((v/n)*math.log2(v/n) for v in c.values())
data = open("suspicious.bin","rb").read()
for i in range(0, len(data), 4096):
    print(i, round(entropy(data[i:i+4096]),3))
```

Резкий скачок энтропии (близко к 8) там, где ожидался текст/сжатое изображение, — признак встроенного сжатого/зашифрованного блока.

## Инструменты и команды

- **`xxd`** (`-g1` по байтам, `-c16` по 16) — hex-дамп.
- **`hexdump -C`** — альтернативный дамп.
- **`cmp -l`** — побайтовое сравнение.
- **`radiff2 -c`** (radare2) — умный diff бинарников.
- **`binwalk`/`foremost`** — carving.
- **`strings -n 6`** — извлекаемые строки.
- **`bvi`/`wxHexEditor`** — интерактивные редакторы.
- **Python `bytes`/`bytearray`** — скриптовый анализ.

## Разобранный пример: находим данные через diff

Даны `a.png` и `b.png` — визуально одинаковые.

```bash
cmp -l a.png b.png | wc -l
# 256        (ровно 256 различий — подозрительно ровно)
cmp -l a.png b.png | awk '{printf "%d ", $3}' | head -c 400
# 62 61 67 7b ...   (восьмеричные!)
```

Переведём восьмеричные байты в ASCII:

```python
vals = [int(x,8) for x in open("diff_oct.txt").read().split()]
print(bytes(vals))
# -> b'flag{hex_diff}'
```

Различия в ровно 256 байтах и «читаемые» восьмеричные коды — классика: данные в LSB или в конкретных байтах.

## Аномалии, которые стоит искать

- **Данные после конца файла.** После `IEND`/`FFD9`/`%%EOF` — часто встроенный контейнер.
- **Несоответствие размеров.** Заголовок говорит одно, файл — другое.
- **Странные чанки/боксы.** Нестандартные имена (`tEXt`, `zTXt`, кастомные `trak`).
- **Повторяющиеся сигнатуры.** Несколько `PK`/`PNG` в одном файле.
- **Аномальная энтропия.** Блоки с энтропией 7.9+ там, где ожидается 3–6.
- **Паттерн в младших битах.** Чётность байтов, «через один» изменения.

## Крайние случаи и подводные камни

- **Сжатие маскирует.** В PNG/JPEG IDAT сжат — прямой diff «съеденных» пикселей не покажет; работайте после декодирования.
- **Несколько форматов.** Файл может быть полиглотом — проверяйте все сигнатуры, а не первую.
- **Байты vs биты.** Различия могут быть в 1 бите на байт — смотрите `xxd -b`.
- **Порядок байт.** При сравнении чисел учитывайте endianness.
- **Шум сенсора.** В реальных фото различия могут быть естественными — ищите закономерность.

## Что дальше / решение

- Инструменты молчат — сделайте `xxd | head/tail` и `cmp` с эталоном.
- Нашли различия — переведите их в ASCII/base64, проверьте на флаг.
- Высокая энтропия в блоке — режьте и распаковывайте (`binwalk`/`dd`).
- Данные после конца файла — `dd` по смещению и `file`.
- Есть cover — diff почти всегда решает задачу.

## Чтение полей заголовков форматов

Чтобы hex-анализ был осмысленным, нужно знать, где в каждом формате лежат «интересные» поля. Ниже — карта ключевых смещений, которые стоит проверять в первую очередь.

| Формат | Поле | Смещение/маркер | Признак аномалии |
|---|---|---|---|
| PNG | ширина/высота | IHDR+8 | не совпадает с реальным размером |
| PNG | тип цвета/глубина | IHDR+16 | неожиданный тип (3 = палитра) |
| JPEG | маркеры сегментов | `FFxx` | лишний APPn/COM-сегмент |
| GIF | версия | байт 3–5 | 89a vs 87a |
| ZIP | комментарий | после EOCD | произвольный текст |
| PDF | `%EOF` | конец | данные после `%%EOF` |

Практически: откройте `xxd` и найдите маркеры `IHDR`, `IDAT`, `IEND` (PNG), `FFD8`/`FFD9` (JPEG), `PK`/`EOCD` (ZIP). Всё, что лежит *между* служебных маркеров или *после* финального маркера, — кандидат на данные.

## Работа с несколькими файлами одновременно

В CTF часто дают набор «одинаковых» файлов (по одному на игрока/раунд). Разница между ними — метка или данные. Организуйте сравнение:

```bash
for f in samples/*.png; do md5sum "$f"; done          # хеши — найдите одинаковые/разные
for f in samples/*.png; do echo "$f $(stat -c%s "$f")"; done   # размеры
```

Файлы одинакового размера, но с разным хешем, различаются в нескольких байтах — это и есть канал. Файлы разного размера — данные дописаны в конец у некоторых. Для пакетного diff:

```bash
for f in samples/*.png; do cmp -l samples/ref.png "$f" | wc -l; done
```

Наибольшее число различий укажет на самый «нагруженный» экземпляр.

## Автоматизация анализа байтов на Python

Скриптовый hex-анализ масштабируется лучше ручного. Полезный шаблон: найти все сигнатуры, посчитать энтропию по блокам и вывести подозрительные участки.

```python
import re, math, collections
SIGS = {b"\x89PNG":"PNG", b"\xff\xd8\xff":"JPEG", b"PK\x03\x04":"ZIP",
        b"%PDF":"PDF", b"\x1f\x8b":"GZIP", b"BZh":"BZIP2"}
def entropy(b):
    c = collections.Counter(b); n = len(b)
    return -sum((v/n)*math.log2(v/n) for v in c.values())
data = open("mystery.bin","rb").read()
for sig,name in SIGS.items():
    for m in re.finditer(re.escape(sig), data):
        print(f"{name} at 0x{m.start():x}")
for off in range(0, len(data), 8192):
    e = entropy(data[off:off+8192])
    if e > 7.5:
        print(f"high entropy 0x{off:x} = {e:.2f}")
```

Такой скрипт за секунды найдёт все встроенные контейнеры и «шумные» блоки, которые вы бы искали глазами часами.

## Что считать «нормой» для формата

Ключ к аномалиям — знание нормы. У PNG всегда есть `IHDR`, минимум один `IDAT` и `IEND`; между ними могут быть `PLTE`, `tEXt`, `tIME`, `pHYs`. Лишние или нестандартные чанки — подозрительны. У JPEG — сегменты `APP0`/`APP1` (EXIF), `COM` (комментарий); неожиданные `APPn` с большим размером часто несут данные. У ZIP — записи, central directory и EOCD; данные *после* EOCD невидимы распаковщикам. Сравнивайте файл с «эталоном», сгенерированным тем же инструментом: всё отличие — потенциальный канал.

## Инструменты для сравнения и визуализации

Помимо `xxd`/`cmp`, полезны специализированные средства:

- **`radiff2 -c a b`** (radare2) — умный diff бинарников, группирует изменения.
- **`vbindiff`** — интерактивное сравнение двух файлов.
- **`hexdump -C -v`** — полный дамп без «звёздочек».
- **`python -c "..."`** — скриптовые проверки (энтропия, сигнатуры).
- **`ent`** — статистика энтропии файла целиком.
- **`file`/`trID`** — определение формата.

```bash
ent mystery.bin
# Entropy = 7.998 bits per byte.   <- почти максимум: сжато/зашифровано
```

Энтропия близка к 8 у сжатых/зашифрованных данных; у текста 4–5; у изображения с плавными переходами 6–7.

## Работа с битовым уровнем

Иногда различия — в одном бите на байт. `xxd -b` покажет двоичное представление:

```bash
xxd -b stego.png | head -3
# 00000000: 10001001 01010000 01001110 01000111  ...  .PNG
```

Для LSB-каналов полезно выводить младшие биты потока как картинку: соберите их в битовую плоскость и визуализируйте — текст/логотип станут видны.

```python
import numpy as np
from PIL import Image
a = np.array(Image.open("stego.png").convert("L"))
lsb = ((a & 1) * 255).astype(np.uint8)
Image.fromarray(lsb).save("lsb_plane.png")
```

## Частые ошибки

- **Доверие расширению.** `file` важнее имени; `.jpg` может быть ZIP.
- **Один diff.** Сравните со *всеми* доступными эталонами, а не с первым.
- **Игнор сжатия.** В PNG/JPEG данные сжаты — diff «сырых» байтов не покажет пиксели.
- **Порядок байт.** При разборе чисел учитывайте endianness.
- **Шум.** В реальных фото различия бывают естественными — ищите закономерность (периодичность, «через один»).

Hex-анализ — универсальный «последний рубеж»: когда все инструменты молчат, байты говорят правду.
