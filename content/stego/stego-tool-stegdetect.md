## Вопрос, с которого всё начинается

В CTF дали JPEG `image.jpg` и подсказку «здесь поработал неочевидный инструмент». `zsteg` для PNG не подходит, `steghide info` ничего не находит, метаданные чистые. Как понять, **каким** инструментом прятали данные, если даже неизвестно, что они там есть?

`zsteg` и StegSolve — это «посмотреть». **stegdetect** и компания — это «угадать, каким инструментом прятали». Он анализирует JPEG и выдаёт вероятный алгоритм, после чего ты берёшь парный извлекатель. Разберём эту логику на одном файле.

## Наш пример: image.jpg

Проверяем формат и запускаем детектор:

```bash
$ file image.jpg
image.jpg: JPEG image data, JFIF standard 1.01, 640x480
$ stegdetect image.jpg
image.jpg: jphide(***)
```

Вывод `image.jpg: jphide(***)` надо уметь читать. Имя в скобках — **гипотеза** об алгоритме (здесь `jphide`), а число звёздочек (1–3) — уверенность. Три звезды — сильный сигнал, одна — слабый.

`stegdetect` работает, сравнивая статистику JPEG (распределение DCT-коэффициентов) с эталонными «отпечатками» известных алгоритмов: jsteg, jphide, outguess, F5. Флаги помогают настроить чувствительность и набор тестов:

```bash
$ stegdetect -s 2.0 -t jopi image.jpg    # j=jsteg o=outguess p=jphide i=invisible
$ stegdetect -q -n image.jpg             # тихо, только имена файлов
```

Здесь `-s` задаёт чувствительность (выше — больше гипотез, но и больше ложных), а `-t` выбирает набор тестов буквами. Важно: звёздочки — это **приоритет**, а не вердикт. Отсутствие гипотез не гарантирует чистоту файла.

## Шаг 1: подбираем извлекатель по гипотезе

Гипотеза `jphide` означает, что данные встроены инструментом **jphide**, и парный извлекатель для него — **jpseek** (почти всегда с паролем):

```bash
$ jpseek image.jpg out.bin
Enter passphrase:
$ cat out.bin
flag{jphide_passphrase}
```

Держи под рукой карту соответствий «гипотеза → извлекатель»:

| Гипотеза | Алгоритм | Извлекатель |
|---|---|---|
| jsteg | LSB DCT | `jsteg reveal` |
| jphide | DCT + пароль | `jpseek` |
| outguess | DCT + коррекция | `outguess -r` |
| F5 | матричное кодирование | f5-steganography |
| invisible | LSB с секретом | invis-secrets |

Сверяться с этой таблицей важнее, чем перебирать наугад: неверный извлекатель на «правильном» файле молчит точно так же, как на пустом.

## Шаг 2: аудио — детектор не поможет

stegdetect работает только с JPEG. Для аудио подход другой — сначала ищем **признаки инструмента** прямо в файле. Многие программы оставляют в контейнере свою метку:

```bash
$ strings -n 8 track.wav | grep -iE 'deepsound|silenteye|password'
$ python3 -c "d=open('track.wav','rb').read(); print(b'DeepSound' in d)"
True
```

Строка `DeepSound` — сильный сигнал: файл обработан этим инструментом. Дальше извлекаем в GUI DeepSound или CLI-аналоге, а при пароле — перебираем по словарю из подсказки.

Если метки нет, смотрим **спектрограмму** — картинку, где по горизонтали время, по вертикали частота:

```bash
$ sox track.wav -n spectrogram -o spec.png
```

На `spec.png` в верхних частотах часто «нарисован» QR-код или текст — это спектральная стеганография. Сканируем картинку:

```bash
$ zbarimg spec.png
```

Ровные полосы на высоких частотах — признак FSK или азбуки Морзе, периодический узор — SSTV.

## Шаг 3: карта «инструмент → формат → извлекатель»

Главный практический инструмент этого урока — таблица соответствий. Держи её рядом:

| Инструмент | Формат | Извлекатель | Пароль |
|---|---|---|---|
| jsteg | JPEG | `jsteg reveal` | нет |
| jphide | JPEG | `jpseek` | да |
| outguess | JPEG | `outguess -r` | да |
| F5 | JPEG | f5-steganography | да |
| steghide | JPEG/BMP/WAV/AU | `steghide extract` | да |
| mp3stego | MP3 | `mp3stego-decode` | да |
| DeepSound | WAV/FLAC | DeepSound | да |
| SilentEye | img/audio | SilentEye | опц. |
| OpenStego | PNG/BMP/WAV | `openstego extract` | опц. |
| snow | текст | `snow -C` | да |

С примерами команд:

```bash
$ mp3stego-decode -P passphrase cover.mp3 out.txt
$ java -jar openstego.jar extract -a RandomLSB -sf marked.png -xd out/
$ snow -C -p password text_with_data.txt
```

Обрати внимание на формат: MP3 — сжатие с потерями, поэтому только `mp3stego`; WAV и FLAC — без потерь, поэтому `DeepSound`/`SilentEye` работают по LSB. Определяй формат по `file`, а не по расширению.

## Шаг 4: типовые ошибки и их лечение

Детекторы экономят время только при понимании их ограничений:

- **«Файл пуст», а stegdetect показывает гипотезу.** Скорее всего, нужен пароль — пробуй `stegseek`/`stegcracker` по словарю.
- **mp3stego не декодирует.** Возможно, файл на самом деле WAV (нужен DeepSound), или пароль неверный.
- **OpenStego `extract` пусто.** Не тот алгоритм (`-a`): попробуй RandomLSB или LSB.
- **snow возвращает пусто.** Неверный пароль или не тот тип файла (нужен текст с трейлинг-пробелами).
- **Слепое доверие stegdetect.** Он устарел и не покрывает современные схемы; одна неудачная попытка — повод проверить соседнюю гипотезу.

## Шаг 5: когда ничего не сработало

Если ни детектор, ни спектрограмма, ни LSB-аудио не дали результата — вернись к контейнеру. Аудио часто несёт данные **не в звуке**, а в метаданных и хвосте:

```bash
$ exiftool track.wav          # ID3-теги, комментарии
$ binwalk track.wav           # дописанные файлы после аудио-потока
$ strings -n 6 track.wav | tail
```

Проверь также конкатенацию: второй файл, дописанный после основного. Флаг в контейнерных метаданных встречается не реже, чем в спектре.

## Что мы теперь знаем

1. `stegdetect` определяет вероятный алгоритм в JPEG; формат вывода — `файл: гипотеза(звёзды)`.
2. Звёзды — это уверенность и приоритет, а не приговор: ложные срабатывания бывают.
3. Каждой гипотезе соответствует парный извлекатель: jphide → jpseek, outguess → outguess -r, F5 → f5.
4. Для аудио детектор не применяется: ищем метку инструмента через `strings` и смотрим спектрограмму (`sox`).
5. Формат определяет инструмент: MP3 → mp3stego, WAV/FLAC → DeepSound/SilentEye.
6. Если всё пусто — проверяй контейнер: метаданные (`exiftool`) и хвост (`binwalk`).

## Почему у каждого инструмента свой формат

Стеганография не стандартизована: каждый инструмент прячет данные **по-своему**, и «универсального декодера» не существует. steghide использует собственный алгоритм с паролем и поддерживает JPEG/BMP/WAV/AU; outguess — JPEG с ключом; F5 — своё матричное кодирование; mp3stego — MP3; DeepSound/SilentEye — аудио; OpenStego — изображения; snow — текст с пробелами. Поэтому **выбор извлекателя диктуется гипотезой о том, чем прятали**, а не наоборот.

Отсюда рабочая стратегия: не запускать все инструменты подряд вслепую, а сначала сузить пространство. Что за контейнер (JPEG? PNG? MP3? текст?)? Есть ли намёк на пароль? Есть ли подозрительные метаданные или дописанные данные? Затем — применить инструменты, подходящие формату, и проверить результат. Если контейнер «не тот», лучший инструмент не поможет: outguess не работает на PNG, steghide — на MP4.

Для детекта до извлечения используют `stegdetect` (для JPEG: jsteg, jphide, outguess, F5) и `stegseek` (быстрый брут пароля для steghide). Но детектор лишь подсказывает гипотезу; извлекает всё равно конкретный инструмент с правильным паролем. Аудио — отдельная история: там сначала слушают, смотрят спектрограмму (Sonic Visualiser, Audacity), ищут скрытые дорожки, и только потом пробуют встраиватели.

## Частые вопросы

**Что запускать первым для JPEG?** `binwalk`/`strings` (дописанное), `exiftool` (метаданные), `stegseek`/`steghide` (пароль), `outguess`, F5-декодер — по нарастанию сложности.

**А для PNG?** `zsteg`, `pngcheck -v`, `exiftool`, ручной LSB (`stegsolve`), затем чанки и дописанные данные.

**Аудио?** Послушать, спектрограмма, `mp3stego`, DeepSound, SilentEye, проверить ID3-метаданные и хвост файла.

**Что если ни один инструмент не берёт пароль?** Попробуйте пустой пароль и очевидные варианты, поищите пароль в задаче; `stegseek` с rockyou быстр для steghide. Если пароль случайный — вектор закрыт.

## Куда дальше

Теперь у тебя есть карта «инструмент → формат → извлекатель». В следующем уроке разберём **StegSolve, AperiSolve и StegOnline** — визуальные инструменты для каналов и битовых плоскостей. А пока запомни: сначала `file`, затем детектор (для JPEG) или `strings`/спектр (для аудио), затем парный извлекатель.
