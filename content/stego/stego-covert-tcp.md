## Вопрос, с которого всё начинается

В pcap ты видишь десятки SYN-пакетов к разным портам — выглядит как обычное сканирование. Но что-то в номерах последовательности не так: они «слишком красивые», как будто не случайные. Может ли сканирование портов нести данные?

Ответ: да. **ISN** (Initial Sequence Number) — 32-битное поле, которое в норме случайно, — идеальное место для данных, если обе стороны договорились. TCP богат такими полями. Разберём это на нашем pcap.

## Наш пример: isn.pcap

**TCP** — транспортный протокол, у которого каждый пакет несёт заголовок с полями: `seq` (номер последовательности), `ack`, флаги (`SYN`, `ACK`, `PSH`...), `window`, `options`. Многие поля на практике «случайны» или редко проверяются — значит, в них можно кодировать биты.

Поля, пригодные для сокрытия:

- **ISN** — 32 бита при установке соединения, обычно случайны;
- **Sequence / Acknowledgment** — 32+32 бита на пакет;
- **Флаги** — 9 бит, реально используются ~6;
- **TCP options** — опции переменной длины, включая padding;
- **Window size** — 16 бит;
- **Тайминги и порядок** — задержки и перестановки.

## Шаг 1: данные в ISN

Выведем `seq` всех SYN-пакетов (запросов на установку соединения):

```bash
$ tshark -r isn.pcap -Y 'tcp.flags.syn==1 && tcp.flags.ack==0' -T fields -e tcp.seq
1734437990
1953653108
1684957028
```

Фильтр `tcp.flags.syn==1 && tcp.flags.ack==0` оставляет только чистые SYN (без ACK). Значения выглядят случайными, но каждое — это 4 байта. Преобразуем в байты big-endian и соберём ASCII:

```python
vals = [1734437990, 1953653108, 1684957028]
out = b"".join(v.to_bytes(4, "big") for v in vals)
print(out.decode(errors="replace"))
```

```bash
$ python3 isn.py
flag...
```

Так из «случайных» ISN собирается осмысленная строка. Поэтому в CTF ISN-канал часто маскируют под сканирование портов.

## Шаг 2: флаги и опции

Поле флагов можно использовать как 6-битное значение: комбинация флагов в каждом пакете задаёт символ base64-алфавита.

```bash
$ tshark -r flags.pcap -Y tcp -T fields -e tcp.flags -e tcp.flags.str | head
```

**Опции TCP** — отдельная ниша. Они идут форматом `Kind-Length-Data`. Padding-опции (`Kind=0` EOL, `Kind=1` NOP) обычно не несут смысла, а экспериментальные (`Kind=253/254`) редко фильтруются — в них удобно писать данные.

```bash
$ tshark -r opts.pcap -Y "tcp.options" -T fields -e tcp.options | tr ',' '\n' | sort | uniq -c
```

## Шаг 3: сборка канала через scapy

Задать конкретный ISN:

```python
from scapy.all import IP, TCP, send
send(IP(dst="10.0.0.5")/TCP(dport=80, flags="S", seq=0x676c66), verbose=False)
```

Задать экспериментальную опцию с данными:

```python
from scapy.all import IP, TCP, send
pkt = IP(dst="10.0.0.5")/TCP(dport=80, flags="S",
      options=[(253, b"\x66\x6c\x61\x67")])
send(pkt, verbose=False)
```

Получатель читает `tcp.options` и восстанавливает данные. `hping3` позволяет задать поле вручную:

```bash
$ hping3 -S -p 80 -M 1734437990 10.0.0.5   # -M задаёт sequence number
```

## Шаг 4: тайминговые каналы TCP

Если менять поля нельзя (их нормализует NAT/IDS), кодируют интервалы между пакетами: короткая пауза — `0`, длинная — `1`. Такой канал медленный, но почти невидим для анализа содержимого.

```bash
$ tshark -r timing.pcap -Y tcp -T fields -e frame.time_delta | head
```

Аномально регулярные или бимодальные интервалы — признак таймингового канала.

## Шаг 5: детект на стороне защиты

IDS/IPS ловят TCP-каналы по признакам:

- **Редкие флаги** — комбинации, которых не бывает у настоящего стека (`FIN+SYN`);
- **Нестандартные опции** — экспериментальные Kind, странный padding;
- **Аномальный ISN** — если он не выглядит случайным (монотонный, ASCII);
- **Ритм** — бимодальные межпакетные интервалы;
- **Постоянный window** — хотя должен варьироваться.

```bash
$ tshark -r tcp.pcap -Y tcp -T fields -e tcp.flags.str | sort | uniq -c | sort -rn
```

## Если не сработало

- **Путаешь sequence и ISN** — данные обычно в ISN при установке соединения.
- **Ломаешь согласованность** — менять seq/ack «в лоб» нельзя, соединение порвётся.
- **Игнорируешь опции** — padding частое и незаметное место.
- **Забыл про порядок** — перестановка пакетов тоже кодирует биты.
- **Считаешь ISN всегда случайным** — в CTF он намеренно структурирован.
- **Не проверяешь флаги** — редкие комбинации прямой сигнал.

## Таблица каналов в TCP

| Канал | Биты на пакет | Согласованность | Заметность |
|---|---|---|---|
| ISN | 32 | только при handshake | средняя |
| Sequence/Ack | 64 | строгая | низкая |
| Флаги | ~6 | свободная | средняя |
| Options/padding | десятки | свободная | низкая |
| Window size | 16 | слабая | низкая |
| Тайминги | 1 | свободная | очень низкая |

## TCP options детально

Опции идут форматом `Kind-Length-Data`. Стандартные: MSS (2), Window Scale (3), SACK Permitted (4), Timestamps (8), NOP (1), EOL (0). Пространство для сокрытия:

- **Padding** — опции выравнивают до 4 байт через `NOP`; их количество может кодировать биты;
- **Экспериментальные Kind** (253, 254) — редко валидируются, идеальны для данных;
- **MSS** — нестандартные значения (1420 против 1460) кодируют биты.

## Ограничения

TCP-каналы на практике редки: они требуют доступа к уровню, где можно произвольно менять заголовки (raw socket), и легко ломаются NAT/файрволами, которые нормализуют заголовок. Поэтому в CTF они встречаются как «умные» задачи, а в реальной эксфильтрации чаще используют payload-каналы (DNS, HTTP), где не надо бороться с нормализацией.

## Практика: достаём байт из ISN

Ключевое поле для канала — **ISN** (Initial Sequence Number): 32-битный стартовый номер TCP-сессии, который отправитель выбирает сам. Он и так выглядит случайным, поэтому в его битах удобно прятать данные. Разберём на одном числе: пусть SYN пришёл с `seq = 0x10000066`.

```python
seq = 0x10000066
print("младший байт:", hex(seq & 0xff), "=", repr(chr(seq & 0xff)))
```

```bash
$ python3 isn.py
младший байт: 0x66 = 'f'
```

Отправитель кладёт байт сообщения в младшие 8 бит ISN, получатель вырезает их маской `& 0xff` — и так по одному символу на сессию. На реальном дампе то же самое делается через `tshark`, который умеет отдавать только поле `tcp.seq` (`tshark -r isn.pcap -T fields -e tcp.seq`): берём каждое значение, применяем `& 0xff` и собираем байты. Детект строится наоборот — у честного стека ISN распределён равномерно, а у канала младшие биты коррелируют между сессиями.

## Что мы теперь знаем

1. TCP-заголовок богат полями для сокрытия: **ISN, seq/ack, флаги, options**.
2. **ISN** — 32 бита, в норме случайны, идеальны для данных.
3. **Флаги** кодируют ~6 бит, **padding-опции** — десятки.
4. `tshark -e tcp.seq` даёт значения, которые переводят в байты.
5. Детект — по редким флагам, нестандартным опциям и аномальному ISN.
