## Вопрос, с которого всё начинается

В задаче дана `cover.png` с подсказкой: «данные переживут JPEG». Ты пересохраняешь её в JPEG, потом снова проверяешь LSB-инструментами — пусто. Но флаг точно есть, и он должен выжить после сжатия. Как спрятать данные так, чтобы сжатие их не убило?

Ответ: в **частотной области**, причём не в блоках DCT, а в **вейвлетах** (DWT). Вейвлет-разложение раскладывает картинку на «приближение» и детали на разных масштабах, и низкочастотная часть переживает сжатие. Разберём это на нашей картинке.

## Наш пример: cover.png, данные «переживают JPEG»

**Вейвлет** — короткая волна, которая «скользит» по сигналу и измеряет локальные изменения на разных масштабах. **DWT** (дискретное вейвлет-преобразование) — это «многомасштабный» аналог DCT: вместо блока 8×8 оно даёт иерархию.

## Шаг 1: вейвлеты в двух словах

DWT применяет пару фильтров (low-pass и high-pass) с прореживанием. Для изображения преобразование делают по строкам и столбцам, получая четыре поддиапазона:

- **LL** — приближение (низкие частоты по обоим направлениям), самая «энергетичная» часть;
- **LH** — горизонтальные детали;
- **HL** — вертикальные детали;
- **HH** — диагональные детали (самый шумный).

Дальше LL можно разложить снова — получается многоуровневая пирамида.

## Шаг 2: где встраивать данные

- **В детали (HH/HL/LH)** — изменения почти незаметны, но детали гибнут при сжатии;
- **В LL (аппроксимацию)** — робастно к сжатию, но правки заметнее;
- **В нескольких поддиапазонах** — компромисс;
- **Сравнение коэффициентов** — кодируют не абсолютное значение, а порядок (какой из пары больше), что устойчиво к масштабированию.

## Шаг 3: разложение через pywt

`PyWavelets` (`pywt`) — основной инструмент. Разложим картинку:

```python
import pywt, numpy as np
from PIL import Image
img = np.array(Image.open("cover.png").convert("L")).astype(float)
LL,(LH,HL,HH) = pywt.dwt2(img, "haar")
print("LL", LL.shape, "LH", LH.shape)
print("energy LL=%.3e  HH=%.3e" % (np.sum(LL**2), np.sum(HH**2)))
```

```bash
$ python3 dwt.py
LL (256, 256) LH (256, 256)
energy LL=6.831e+07  HH=1.204e+05
```

Видно, что энергия сосредоточена в LL: там данные «выживут», но их изменение заметнее.

## Шаг 4: встраивание и извлечение

Типовая схема — модулировать коэффициент относительно предсказания или через **QIM** (квантование). Игрушечный пример с квантованием:

```python
import pywt, numpy as np
from PIL import Image
DELTA = 6.0
def q(x, b): return DELTA*np.round((x - b*DELTA/2)/DELTA) + b*DELTA/2

img = np.array(Image.open("cover.png").convert("L")).astype(float)
LL,(LH,HL,HH) = pywt.dwt2(img, "haar")
bits = np.unpackbits(np.frombuffer(b"flag{dwt_qim}", dtype=np.uint8))
f = LL.reshape(-1)
for i, b in enumerate(bits):
    f[i] = q(f[i], b)
out = pywt.idwt2((f.reshape(LL.shape), (LH,HL,HH)), "haar")
Image.fromarray(np.clip(out,0,255).astype(np.uint8)).save("stego.png")
```

`q` придвигает коэффициент к ближайшему «слоту» квантования, соответствующему биту. Приёмник тем же квантованием восстанавливает бит.

## Шаг 5: многоуровневое разложение

LL можно разложить снова. Каждый уровень делает LL меньше, но «глубже» по частотам — это выбор точки на шкале «робастность ↔ ёмкость».

```python
import pywt, numpy as np
from PIL import Image
img = np.array(Image.open("cover.png").convert("L")).astype(float)
coeffs = pywt.wavedec2(img, "haar", level=3)
cA3, (cH3,cV3,cD3), (cH2,cV2,cD2), (cH1,cV1,cD1) = coeffs
print("level3 approx:", cA3.shape)
```

Для 512×512 уровень 3 даёт аппроксимацию 64×64 — 4096 коэффициентов с высокой робастностью.

## Шаг 6: сравнение с DCT и чек-лист

| Свойство | DCT (JPEG) | DWT |
|---|---|---|
| Локализация | блочная | многомасштабная |
| Артефакты | блочные | сглаженные |
| Робастность к JPEG | высокая | высокая (LL) |
| Ёмкость | высокая | средняя |

Чек-лист DWT-задачи:

1. `file`, `zsteg -a`, `exiftool` — исключи простые каналы;
2. разложи `pywt.wavedec2(img, "haar", level=2..3)`;
3. проверь статистику LL: аномалии, «полосы»;
4. попробуй разные вейвлеты (`haar`, `db2`, `bior2.2`);
5. проверь устойчивость: пересохрани в JPEG и посмотри, что выживает;
6. ищи параметры (уровень, α, вейвлет) в условии.

## Сквозной разбор: LL против HH под JPEG

Проверим ключевой тезис «LL выживает, HH гибнет» на настоящем эксперименте. Возьмём `cover.png` (256×256), разложим вейвлетом Хаара, встроим 200 случайных бит — сначала в LL через QIM, потом в HH — и пересохраним результат в JPEG качества 75.

Замеряем **BER** (bit error rate — доля неправильно прочитанных бит) и **PSNR** (пиковое отношение сигнал/шум; выше 40 дБ — правки невидимы):

```bash
$ python3 dwt_robust.py     # встраивание в LL (QIM)
DELTA= 8.0: JPEG-q75 BER=14.5%  PSNR= 47.3 dB
DELTA=16.0: JPEG-q75 BER= 1.5%  PSNR= 46.6 dB
DELTA=24.0: JPEG-q75 BER= 0.0%  PSNR= 46.1 dB
$ python3 dwt_robust.py     # встраивание в HH
embed HH: JPEG-q75 -> bit error rate 50.5%
```

Встраивание в LL: даже при шаге квантования `Δ=16` биты читаются почти без ошибок (1.5%), а картинка неотличима (PSNR 46 дБ). Встраивание в HH при том же JPEG даёт 50.5% — это чистый случайный шум, данные уничтожены. Заодно видно компромисс: больше `Δ` → меньше ошибок, но ниже PSNR.

## Если не сработало

- **Забыл про размер** — DWT может обрезать нечётный край; проверяй форму коэффициентов.
- **Путаница уровней** — `wavedec2` возвращает «аппроксимация, детали N, …, детали 1».
- **Округление** — `idwt2` даёт float; при сохранении в uint8 теряются младшие биты.
- **Не тот вейвлет** — схема могла использовать `db4`/`bior3.3`, а ты пробуешь `haar`.
- **Канал** — часто работают с яркостью или одним каналом; конвертация меняет данные.
- **Порог/α — часть ключа** — без них декодирование неоднозначно.

## Справочная таблица поддиапазонов

| Поддиапазон | Частоты | Незаметность | Робастность |
|---|---|---|---|
| LL | низкие | низкая | высокая |
| LH | гориз. детали | средняя | низкая |
| HL | верт. детали | средняя | низкая |
| HH | диагональ | высокая | очень низкая |

## Устойчивость к JPEG и фильтрам

- **LL-встраивание** переживает JPEG-q75 и лёгкое размытие;
- **детали (HH)** при JPEG-q75 почти полностью уничтожаются;
- **многоуровневое DWT** даёт лучшую робастность;
- **геометрия** (сдвиг/масштаб) ломает соответствие коэффициентов — нужны синхронизаторы.

Практическое правило: для робастного watermarking — LL + QIM; для максимальной незаметности — детали + адаптивная стоимость.

## Вейвлеты и сжатие: почему DWT устойчив

DWT-коэффициенты низкого уровня переживают сжатие потому, что JPEG (и большинство кодеков) сами построены на частотном разложении. Низкочастотная аппроксимация несёт основную энергию и сохраняется в первую очередь. Поэтому встраивание в LL выживает, а в HH — гибнет.

## Что мы теперь знаем

1. DWT раскладывает изображение на **LL/LH/HL/HH** на разных масштабах.
2. **LL** робастна к сжатию, но правки заметны; детали — незаметны, но хрупки.
3. `pywt.dwt2`/`wavedec2` — основной инструмент Python.
4. **QIM** в LL — золотая середина watermarking.
5. Если данные «переживают JPEG», но не видны в LSB — это частотная схема.
