Вейвлет-преобразование (DWT) — это «многомасштабный» аналог DCT: изображение раскладывается на низкочастотную аппроксимацию и детали на разных масштабах. Вместо одного блока 8×8, как в JPEG, вейвлеты дают иерархию: крупные структуры отделяются от мелких деталей. Для стеганографии это удобно: можно прятать в детали (незаметно) или в аппроксимацию (робастно), и выбирать уровень разложения под задачу. DWT лежит в основе многих watermarking-систем и встречается в задачах, где LSB и DCT уже «избиты».

## Вейвлеты в двух словах

Вейвлет — короткая волна с нулевым средним, которая «скользит» по сигналу и измеряет локальные изменения на разных масштабах. DWT применяет пару фильтров (low-pass и high-pass) и прореживание: после одного уровня одномерное преобразование даёт «приближение» (low) и «детали» (high). Для изображения преобразование применяют по строкам и столбцам, получая четыре поддиапазона:

- **LL** — приближение (низкие частоты по обоим направлениям), самая «энергетичная» часть;
- **LH** — горизонтальные детали;
- **HL** — вертикальные детали;
- **HH** — диагональные детали (высокие частоты, самый шумный).

Дальше LL можно разложить снова — получается многоуровневая пирамида.

## Где встраивать данные

- **В HH/HL/LH (детали).** Изменения почти незаметны, но детали страдают при сжатии сильнее — данные хрупкие.
- **В LL (аппроксимация).** Робастно к сжатию и фильтрации, но правки заметны, если их много.
- **В нескольких поддиапазонах.** Компромисс: часть данных в LL для робастности, часть в деталях для объёма.
- **Сравнение коэффициентов.** Вместо абсолютного значения кодируют порядок (какой из пары больше) — устойчивее к масштабированию.

Типовая схема: применить DWT, взять поддиапазон, прибавить `α·b` к коэффициенту (или использовать QIM в коэффициентах), применить обратное DWT.

## Инструменты и команды

- **`PyWavelets` (`pywt`)** — основной Python-инструмент: `pywt.dwt2`, `pywt.idwt2`, десятки вейвлетов (`haar`, `db1`, `bior2.2`).
- **`numpy`** — работа с коэффициентами.
- **`OpenCV`** — `cv2.dwt` нет, но есть `cv2.idwt`? нет — используйте `pywt`.
- **`steghide`** — использует не DWT, а свой алгоритм; для вейвлетов нужен свой код.
- **`ImageMagick`** — для конвертации/сжатия при проверке робастности.
- **`matplotlib`** — визуализация поддиапазонов.

Базовое разложение:

```bash
python3 - <<'PY'
import pywt, numpy as np
from PIL import Image
img = np.array(Image.open("cover.png").convert("L")).astype(float)
LL,(LH,HL,HH) = pywt.dwt2(img, "haar")
print("LL", LL.shape, "LH", LH.shape)
print("energy LL=%.3e  HH=%.3e" % (np.sum(LL**2), np.sum(HH**2)))
PY
```

Вывод:

```
LL (256, 256) LH (256, 256)
energy LL=6.831e+07  HH=1.204e+05
```

Видно, что энергия сосредоточена в LL — там данные «выживут», но их изменение заметнее.

## Разобранный пример: встраивание в LL

```python
import pywt, numpy as np
from PIL import Image

def embed(img, msg, alpha=4.0):
    a = np.array(img).astype(float)
    LL,(LH,HL,HH) = pywt.dwt2(a, "haar")
    bits = np.unpackbits(np.frombuffer(msg, dtype=np.uint8))
    flat = LL.reshape(-1)
    for i,b in enumerate(bits):
        flat[i] += alpha if b else -alpha
    a2 = pywt.idwt2((flat.reshape(LL.shape), (LH,HL,HH)), "haar")
    return Image.fromarray(np.clip(a2,0,255).astype(np.uint8))

def extract(path, n_bits, alpha=4.0):
    a = np.array(Image.open(path).convert("L")).astype(float)
    LL,_,_ = pywt.dwt2(a, "haar")
    # сравнение с «нулевым» решением: знак отклонения от локального среднего
    flat = LL.reshape(-1)[:n_bits]
    # в игрушечной схеме используем порог по среднему поддиапазона
    thr = flat.mean()
    bits = (flat > thr).astype(np.uint8)
    return np.packbits(bits).tobytes()

img = Image.open("cover.png").convert("L")
embed(img, b"flag{dwt}").save("stego.png")
print(extract("stego.png", len(b"flag{dwt}")*8))
```

Игрушечный приёмник выше нарочно неточен (LL-коэффициенты не центрированы), чтобы показать: в реальных схемах встраивание делают **относительно предсказания** или через QIM. Правильнее — модулировать знак отклонения от локального среднего:

```python
for i,b in enumerate(bits):
    sign = 1 if b else -1
    flat[i] = flat[i] + sign*alpha if abs(flat[i]) < alpha else flat[i]*(1 + sign*0.01)
```

Тогда приёмник смотрит на знак относительного отклонения и восстанавливает бит.

## Устойчивость к JPEG и фильтрам

- **LL-встраивание** переживает JPEG-q75 и лёгкое размытие: низкие частоты сохраняются.
- **Детали (HH)** при JPEG-q75 почти полностью уничтожаются — данные гибнут.
- **Многоуровневое DWT** даёт лучшую робастность: встраивание на 2–3 уровне LL переживает сильное сжатие.
- **Геометрия** (сдвиг/масштаб) ломает соответствие коэффициентов; нужны синхронизаторы.

Практическое правило: для робастного watermarking — LL + QIM; для максимальной незаметности — детали + адаптивная стоимость.

## Крайние случаи и подводные камни

- **Размер изображения.** DWT обычно требует чётных размеров; нечётные обрезаются или дополняются — это меняет индексацию.
- **Округление при обратном преобразовании.** `idwt2` даёт float, при клиппинге в uint8 теряются младшие биты — учитывайте при извлечении.
- **Выбор вейвлета.** `haar` прост и популярен в CTF; `db`/`bior` дают лучшую робастность.
- **Каналы.** Часто работают с яркостью (Y) или одним каналом — важно знать, с каким.
- **Порог/α — часть ключа.** Без них декодирование неоднозначно.

## Что дальше / решение

- Данные переживают JPEG, но не видны в LSB — стройте DWT-декомпозицию и смотрите LL.
- Нужна максимальная робастность — многоуровневый DWT + QIM в LL.
- Задача про watermarking — сравните `haar` и `bior` и проверьте устойчивость к сжатию.
- Не получается восстановить — ищите параметры (вейвлет, уровень, α) в условии или метаданных.

## Многоуровневое разложение и выбор уровня

Одноуровневое DWT даёт четыре поддиапазона; LL можно разложить снова. Каждый следующий уровень делает LL меньше, но «глубже» по частотам. Для стеганографии это означает выбор точки на шкале «робастность ↔ ёмкость»: чем глубже уровень LL, тем меньше коэффициентов (меньше ёмкость), но тем устойчивее данные.

```python
import pywt, numpy as np
from PIL import Image
img = np.array(Image.open("cover.png").convert("L")).astype(float)
coeffs = pywt.wavedec2(img, "haar", level=3)
cA3, (cH3,cV3,cD3), (cH2,cV2,cD2), (cH1,cV1,cD1) = coeffs
print("level3 approx:", cA3.shape)   # 64x64 для 512x512
```

Для 512×512 уровень 3 даёт аппроксимацию 64×64 — 4096 коэффициентов, в которые можно встроить (через QIM) до нескольких КБ с высокой робастностью.

## Сравнение с DCT (JPEG)

DWT и DCT — родственники, но с разницей в локализации. DCT работает блоками 8×8 (артефакты «по блокам»), DWT — «глобально», сглаженно. Для стеганографии это значит:

| Свойство | DCT (JPEG) | DWT |
|---|---|---|
| Локализация | блочная | многомасштабная |
| Артефакты | блочные | сглаженные |
| Робастность к JPEG | высокая | высокая (LL) |
| Ёмкость | высокая | средняя |
| Видимость правок | в блоках | распределена |

В watermarking часто комбинируют: DWT для «грубого» уровня и DCT/QIM внутри коэффициентов.

## Практический чек-лист DWT-задачи

1. `file`, `zsteg -a`, `exiftool` — исключите простые каналы.
2. Разложите изображение `pywt.wavedec2(img, "haar", level=2..3)`.
3. Проверьте статистику LL: аномалии, «полосы», необычные значения.
4. Попробуйте разные вейвлеты (`haar`, `db2`, `bior2.2`) — схема могла использовать конкретный.
5. Проверьте устойчивость: пересохраните в JPEG и посмотрите, что выживает.
6. Ищите параметры (уровень, α, вейвлет) в условии/метаданных.

Если данные «переживают» JPEG, но не читаются LSB-скриптами — почти наверняка это частотная схема (DCT или DWT). DWT-разложение и анализ LL — первый шаг.

## Вейвлеты и сжатие: почему DWT устойчив

DWT-коэффициенты низкого уровня переживают сжатие потому, что JPEG (и большинство кодеков) сами построены на частотном разложении. Низкочастотная аппроксимация несёт основную энергию и сохраняется в первую очередь. Поэтому встраивание в LL выживает, а в HH — гибнет. Практическое следствие: если задача требует «пережить JPEG», встраивайте в LL на 2–3 уровне, желательно через QIM. Если требуется максимальная незаметность и устойчивость не важна — используйте детали.

## Типичные ошибки при работе с DWT

- **Забыли про размер.** DWT по умолчанию может обрезать нечётный край; проверяйте форму коэффициентов и восстанавливайте исходный размер.
- **Путаница уровней.** `wavedec2` возвращает коэффициенты в порядке «аппроксимация, детали уровня N, … уровня 1». Распаковывайте внимательно.
- **Округление.** `idwt2` даёт float; при сохранении в uint8 теряются младшие биты. Учитывайте при извлечении (не полагайтесь на точное совпадение).
- **Не тот вейвлет.** Схема могла использовать `db4`/`bior3.3`, а вы пробуете `haar`. Перебирайте семейства.
- **Канал.** Часто работают с яркостью или одним каналом; конвертация RGB→L и обратно меняет данные.

## Расширенный пример: DWT + QIM

Комбинируем DWT и квантование для робастности:

```python
import pywt, numpy as np
from PIL import Image
DELTA = 6.0
def q(x, b): return DELTA*np.round((x-b*DELTA/2)/DELTA)+b*DELTA/2
img = np.array(Image.open("cover.png").convert("L")).astype(float)
LL,(LH,HL,HH) = pywt.dwt2(img,"haar")
bits = np.unpackbits(np.frombuffer(b"flag{dwt_qim}",dtype=np.uint8))
f = LL.reshape(-1)
for i,b in enumerate(bits): f[i] = q(f[i], b)
out = pywt.idwt2((f.reshape(LL.shape),(LH,HL,HH)),"haar")
Image.fromarray(np.clip(out,0,255).astype(np.uint8)).save("stego.png")
```

Такая схема — золотая середина watermarking: умеренная ёмкость, хорошая незаметность и устойчивость к сжатию. В CTF ищите её там, где данные «переживают» пересохранение и не читаются LSB-инструментами.
