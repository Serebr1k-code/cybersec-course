## Вопрос, с которого всё начинается

Ты запускаешь `zsteg` — ошибка. `stegsolve` не открывает файл. `binwalk` молчит.
Задача явно **сделана против инструментов**: автор испортил сигнатуру, поменял
порядок битов или использовал кастомный заголовок. Автоматика бессильна. Что
делать? Читать байты вручную и писать свой скрипт. Разберём.

## Наш пример: файл weird.png

```bash
file weird.png
```

```text
weird.png: data
```

`file` не распознал формат — сигнатура испорчена. Это и есть anti-tool: инструменты
опираются на сигнатуры, а её сломали. Смотрим байты:

```bash
xxd -l 16 weird.png
```

```text
00000000: 8850 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR
```

Видно `88 50 4E 47` вместо `89 50 4E 47`: первый байт изменён с `89` на `88`.
Формально это уже не PNG, но структура на месте. Мы восстановили сигнатуру
глазами.

## Шаг 1: почему инструменты ломаются

Инструменты проверяют сигнатуру, CRC, размеры. Anti-tool-задачи атакуют именно
эти проверки:

- меняют первый байт сигнатуры;
- портят CRC чанка;
- задают неверную длину;
- используют нестандартный порядок битов (LSB/MSB);
- добавляют «мусорный» заголовок перед настоящим.

Понимая, какую проверку сломали, ты обходишь её вручную.

## Шаг 2: восстанавливаем структуру

Первое действие — исправить сигнатуру на копии и посмотреть, откроется ли файл:

```bash
cp weird.png fixed.png
printf '\x89' | dd of=fixed.png bs=1 seek=0 conv=notrunc 2>/dev/null
file fixed.png
```

```text
fixed.png: PNG image data, 16 x 16, 8-bit/color RGB, non-interlaced
```

Теперь `file` распознал PNG. Но это только структура; данные ещё надо достать.

## Шаг 3: ручной разбор LSB

Если инструменты не извлекают, читаем младшие биты сами. Скрипт на Python:

```python
import zlib
d = open('weird.png','rb').read()
i = 8; idat = b''
while i < len(d):
    ln = int.from_bytes(d[i:i+4],'big'); t = d[i+4:i+8]
    if t == b'IDAT': idat += d[i+8:i+8+ln]
    i += 12 + ln
raw = zlib.decompress(idat)
w = int.from_bytes(d[16:20],'big')
bits = []
for b in raw[1:1+w*3]:
    bits.append(b & 1)
out = bytearray()
for k in range(0, len(bits)//8*8, 8):
    byte = 0
    for x in bits[k:k+8]:
        byte = (byte << 1) | x
    out.append(byte)
print(out[:24].decode('latin-1'))
```

Здесь мы сами разбираем PNG: находим `IDAT`, распаковываем zlib, читаем младшие
биты пикселей, собираем байты.

## Шаг 4: меняем порядок битов

Anti-tool часто использует **MSB-first** вместо LSB-first. Если скрипт даёт мусор,
попробуй инвертировать порядок внутри байта:

```python
for x in bits[k:k+8][::-1]:   # обратный порядок
    byte = (byte << 1) | x
```

Или читать биты не с младшего, а со старшего бита пикселя (`(b >> 7) & 1`).
Перебор нескольких вариантов — обычная практика.

## Шаг 5: запускаем и получаем флаг

```bash
python3 manual.py
```

```text
nto{4nt1_t00l_m4nu4l}
```

Мы обошли защиту, потому что поняли структуру, а не полагались на инструмент.

## Шаг 6: стратегия против anti-tool

1. Посмотреть байты (`xxd`) — найти, что сломано.
2. Восстановить сигнатуру/структуру на копии.
3. Написать короткий скрипт под конкретную схему.
4. Перебрать варианты: порядок битов, каналы, смещение.
5. Проверить результат глазами/по формату флага.

## Шаг 7: почему это ценно

Anti-tool-задачи проверяют понимание, а не знание флагов инструментов. Если ты
умеешь читать байты и писать скрипт — такие задачи решаются быстрее, чем «умные»
инструменты. Это навык, который переносится в реальную форензику: там тоже
встречаются нестандартные форматы.

## Шаг 8: полный разбор anti-tool

Разберём подробно. Файл `weird.png` не открывается. Мы смотрим байты: первый байт
`88` вместо `89`. Это ломает распознавание. Восстанавливаем на копии: пишем `89`
в нулевой байт. Теперь `file` говорит PNG.

Следующий барьер может быть в CRC: `pngcheck -v` покажет `CRC error`. Тогда
инструмент `zsteg` откажется работать. Обходим вручную: читаем `IDAT`,
распаковываем zlib, собираем биты.

## Шаг 9: разбор структуры PNG вручную

Чтобы читать вручную, надо понимать структуру. PNG — поток чанков: длина (4 байта,
big-endian), тип (4 байта), данные, CRC (4 байта). Первый чанк после сигнатуры —
`IHDR` с шириной и высотой. Мы читаем ширину из байтов 16–20:

```python
w = int.from_bytes(d[16:20], 'big')
h = int.from_bytes(d[20:24], 'big')
```

Затем идём по чанкам, собираем `IDAT`, распаковываем `zlib.decompress`. После
распаковки получаем сырые пиксели с фильтр-байтом в начале каждой строки. Именно
из этих байтов читаются LSB.

## Шаг 10: варианты кодирования

Anti-tool использует нестандартные варианты. Перечислим те, что стоит перебрать:

- **порядок битов**: LSB-first vs MSB-first;
- **бит внутри байта**: младший vs старший бит пикселя;
- **каналы**: R, G, B, alpha по отдельности или вместе;
- **интерлейс**: построчно или по Адамару;
- **смещение**: данные начинаются не с первого пикселя;
- **битовая глубина**: 8 бит на канал vs 1 бит (палитра).

Перебор этих вариантов — стандартный подход. Скрипт на несколько строк проверяет
все комбинации и ищет сигнатуру флага.

## Шаг 11: как писать универсальный скрипт

Вместо отдельного скрипта под каждый случай напиши один, который перебирает
варианты:

```python
import zlib, itertools
def extract(path, bit=0, msb=False, channels=(0,1,2)):
    d = open(path,'rb').read()
    # ... собрать IDAT, распаковать ...
    for mode in ['lsb','msb']:
```

## Шаг 12: восстановление других структур

Anti-tool не ограничивается PNG. Приёмы:

- **JPEG**: испорчен `FFD8`, изменён порядок маркеров;
- **ZIP**: испорчена сигнатура `PK`, неверный центральный каталог;
- **ELF/PE**: испорчен заголовок;
- **WAV**: неверный размер чанка `data`.

В каждом случае логика одна: понять структуру, найти повреждение, восстановить на
копии, разобрать вручную.

## Шаг 13: почему это проверка понимания

Anti-tool-задачи не проверяют, знаешь ли ты `zsteg`. Они проверяют, понимаешь ли
ты, **как устроен формат**. Если понимаешь — обойдёшь любую защиту. Если нет —
застрянешь, даже имея десяток инструментов.

## Шаг 14: частые ошибки

Первая — паниковать и пробовать инструменты наугад. Вторая — не делать копию перед
правкой (портишь оригинал). Третья — сдаваться после первой неудачной попытки
извлечения. Четвёртая — не перебирать варианты порядка битов. Пятая — не проверять,
что флаг действительно получен (формат).

## Шаг 15: перенос в реальную работу

В форензике тоже встречаются повреждённые и нестандартные форматы: частично
перезаписанные файлы, кастомные контейнеры, обфускация. Навык ручного разбора
позволяет достать данные там, где автоматика бессильна. Поэтому anti-tool — не
«игрушка», а тренировка реального мастерства.

## Шаг 16: разбор примера с несколькими защитами

Усложним: файл имеет испорченную сигнатуру, неверный CRC и нестандартный порядок
битов. Решение по шагам. Восстанавливаем сигнатуру на копии. Игнорируем CRC (наш
скрипт его не проверяет). Перебираем порядок битов (LSB, затем MSB). На одном из
вариантов появляется `nto{...}`. Каждая защита обходится отдельно; вместе они
отпугивают новичка, но не того, кто понимает структуру.

## Шаг 17: как отлаживать свой скрипт

Когда скрипт даёт мусор, добавляй печать промежуточных значений: сколько байтов
`IDAT`, удалось ли распаковать zlib, сколько битов собрано, что в первых байтах
результата. Ошибка почти всегда на одном из этих шагов. Печать — самый простой
отладчик.

## Шаг 18: частые защиты и обходы

| Защита | Обход |
|---|---|
| испорчена сигнатура | восстановить первый байт |
| битый CRC | игнорировать (свой парсер) |
| MSB-first | перебрать порядок битов |
| кастомный заголовок | найти смещение вручную |
| шифрование | искать пароль/ключ |

Таблица — шпаргалка для быстрого выбора тактики.

## Шаг 19: итог по anti-tool

Anti-tool проверяет не знание инструментов, а понимание форматов. Тот, кто умеет
читать байты и писать короткие скрипты, решает такие задачи быстрее «умных»
инструментов. Это навык, который пригодится и в реальной форензике.

## Шаг 20: заключение

Anti-tool учит главному: инструмент — лишь помощник, а понимание формата — основа.
Если ты знаешь, как устроен PNG, JPEG или ZIP, ты обойдёшь любую защиту от
автоматики. Это и есть настоящий навык, который отличает специалиста от пользователя
готовых утилит.

## Шаг 21: заметка о битовой глубине

Если PNG индексированный (1 бит на пиксель), LSB-чтение по пикселям не сработает:
там биты палитры, а не цвета. Тогда смотри индексы палитры или сами цвета. Проверь
тип цвета в `IHDR`: 0 — grayscale, 2 — RGB, 3 — палитра, 4/6 — с альфой. Тип
подсказывает, откуда читать биты.

## Шаг 22: заключительная заметка

Если инструменты отказываются работать, это не тупик, а приглашение к ручному
анализу. Возьми байты, пойми структуру, напиши десять строк кода — и защита
падает. Именно этот навык отличает того, кто решает anti-tool-задачи, от того, кто
ищет готовую утилиту.

## Что мы теперь знаем

- Anti-tool-задачи ломают сигнатуры, CRC, порядок битов.
- Первый шаг — `xxd`, найти повреждение.
- Структуру восстанавливают на копии (сигнатура, заголовок).
- Ручной скрипт читает биты и собирает данные.
- Перебор вариантов (LSB/MSB, каналы) — нормальная часть работы.
