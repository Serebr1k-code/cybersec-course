Палитровые форматы (PNG с типом цвета 3, GIF, BMP с палитрой) хранят не RGB каждого пикселя, а индекс в таблицу цветов. Таблица (PLTE в PNG, Global/Local Color Table в GIF) — это список до 256 записей RGB. Порядок записей почти всегда произволен: перестановка палитры не меняет картинку, если синхронно пересчитать индексы. А значит, порядок палитры — это канал: можно отсортировать цвета определённым образом и закодировать данные, или использовать «дырки» — неиспользуемые записи. Этот урок — про палитровые трюки.

## Как устроена палитра

- **PLTE-чанк (PNG).** Список RGB-троек. Число записей = `размер / 3`, не более 256.
- **tRNS-чанк (PNG).** Альфа для записей палитры (опционально).
- **GCT/LCT (GIF).** Глобальная и локальные палитры, каждая — список RGB.
- **BMP.** Палитра в конце заголовка (`biBitCount <= 8`).
- **Индексы.** Пиксели ссылаются на записи; порядок записей произволен.

Ключевой факт: две палитры с одинаковым набором цветов, но разным порядком, дают одинаковую картинку при пересчитанных индексах. Значит, перестановка — свободный канал.

## Перестановка как канал

Идея: отсортировать палитру по некоторому правилу и извлечь данные из получившегося порядка. Варианты:

- **Сортировка по яркости.** Если записи идут строго по возрастанию яркости — это сигнал, а «нарушения» монотонности кодируют биты.
- **Сортировка по частоте.** Порядок цветов по убыванию частоты использования; отклонения — данные.
- **Порядок как перестановка.** Сам порядок (номер перестановки) кодирует число/сообщение.
- **Разница соседних цветов.** Расстояние между соседними записями кодирует биты.

## Сортировка по яркости и «нарушения»

Практичный приём: проверить, отсортирована ли палитра по яркости `0.299R+0.587G+0.114B`. Если да — сравнить с «идеальной» сортировкой и посмотреть, какие элементы поменяли местами: их позиции могут кодировать биты. Если нет — возможно, палитра отсортирована по другому ключу (сумма каналов, hue).

```python
import numpy as np
from PIL import Image
im = Image.open("stego.png")
pal = np.array(im.getpalette()).reshape(-1,3)
lum = 0.299*pal[:,0] + 0.587*pal[:,1] + 0.114*pal[:,2]
sorted_idx = np.argsort(lum)
print("sorted by luminance?", np.array_equal(sorted_idx, np.arange(len(pal))))
print("first 8 palette entries:", pal[:8].tolist())
```

Вывод:

```
sorted by luminance? False
first 8 palette entries: [[0,0,0],[255,255,255],[255,0,0],[0,255,0],[0,0,255],[255,255,0],[0,255,255],[255,0,255]]
```

Если палитра «почти отсортирована» с парой инверсий — это классический признак скрытых бит.

## Неиспользуемые записи

Если в палитре 256 записей, а реально используются, скажем, 200, то 56 «лишних» цветов можно заполнить произвольными значениями — это контейнер. Проверка:

```python
import numpy as np
from PIL import Image
im = Image.open("stego.png")
idx = np.array(im)
used = set(np.unique(idx).tolist())
pal = np.array(im.getpalette()).reshape(-1,3)
unused = [i for i in range(len(pal)) if i not in used]
print("unused entries:", unused[:20], "... total", len(unused))
# данные часто лежат в RGB «неиспользуемых» записей
print("unused colors:", [pal[i].tolist() for i in unused[:8]])
```

Если в неиспользуемых цветах виден текст/base64 — это и есть данные. Например, `[102,108,97,103]` = `flag`.

## Инструменты и команды

- **`Pillow`** — `getpalette()`, `im.convert("RGB")`, доступ к индексам.
- **`pngcheck -v`** — покажет PLTE, число записей, tRNS.
- **`pngtools`/`zsteg`** — `zsteg -a` включает проверку палитры.
- **`GIMP`/`gifsicle`** — визуальный осмотр палитры.
- **`xxd`** — ручной разбор байтов PLTE.
- **`pygifsicle`** — палитры GIF.

Проверка PLTE:

```bash
pngcheck -v stego.png | grep -i plte
# PLTE chunk: 256 entries (768 bytes)
```

## Порядок индексов

Иногда данные кодируют не в палитре, а в порядке индексов пикселей: например, чётность индекса = бит. Это ближе к `stego-palette`, но проверять стоит:

```python
idx = np.array(im).reshape(-1)
bits = (idx & 1).astype(np.uint8)
data = np.packbits(bits).tobytes()
print(data[:40])
```

## Крайние случаи и подводные камни

- **Конвертация в RGB убивает палитру.** Если файл пересохранили как RGB/RGBA, палитра исчезает — данные теряются. Работайте с оригиналом.
- **Локальные палитры GIF.** Каждый кадр может иметь свою — проверяйте все.
- **Размер палитры.** PLTE может быть меньше 256 записей; индексы вне диапазона — ошибка.
- **Сортировка «почти».** Одна инверсия — это может быть и естественно; ищите закономерность.
- **tRNS.** Прозрачность тоже канал: значения альфы в палитре.
- **zsteg порядок.** `zsteg` перебирает много комбинаций, но палитровые трюки иногда пропускает — делайте вручную.

## Что дальше / решение

- Палитра отсортирована или «почти» — извлеките данные из инверсий.
- Есть неиспользуемые записи — проверьте их RGB на текст/base64.
- Ничего — смотрите порядок индексов и tRNS.
- GIF — проверьте локальные палитры каждого кадра и задержки (`stego-gif-animation`).

## Справочная таблица

| Формат | Палитра | Особенности |
|---|---|---|
| PNG | PLTE + tRNS | до 256 записей, индексный тип 3 |
| GIF | GCT + LCT | палитра на кадр |
| BMP | палитра в заголовке | при bitcount ≤ 8 |
| TIFF | ColorMap | отдельный тег |

## Извлечение палитры из разных форматов

Палитра лежит в разных местах в зависимости от формата, и путь к ней отличается. Для PNG — чанк PLTE; для GIF — GCT/LCT; для BMP — массив сразу после заголовка; для TIFF — тег ColorMap. Ниже — как добраться до записей в каждом случае.

```python
from PIL import Image
import numpy as np

# PNG/GIF/BMP с палитрой (режим "P")
im = Image.open("indexed.png")
if im.mode == "P":
    pal = np.array(im.getpalette()).reshape(-1, 3)
    idx = np.array(im)
    print("entries:", len(pal), "unique idx:", len(np.unique(idx)))

# TIFF: ColorMap через tifffile
import tifffile
with tifffile.TiffFile("indexed.tif") as t:
    page = t.pages[0]
    if 320 in page.tags:
        cmap = page.tags[320].value   # ColorMap
        print("colormap len:", len(cmap))
```

Для GIF палитра кадра может отличаться от глобальной — проверяйте `im.info` при `seek`.

## Сравнение двух палитр

Если есть cover и stego, различия в палитре покажут встроенные данные напрямую. Это самый быстрый путь:

```python
import numpy as np
from PIL import Image
a = np.array(Image.open("cover.png").getpalette()).reshape(-1,3)
b = np.array(Image.open("stego.png").getpalette()).reshape(-1,3)
diff = np.where((a != b).any(axis=1))[0]
print("changed entries:", diff)
print("stego colors:", b[diff].tolist())
```

Если изменённые записи содержат читаемые ASCII-коды (`102,108,97,103` = `flag`) — задача решена. Если изменён только *порядок* записей, а не содержимое, — это перестановочный канал: сравните позиции.

## Сортировка палитры и «идеальный» порядок

Чтобы понять, отсортирована ли палитра, постройте эталонную сортировку по нескольким ключам и сравните:

```python
import numpy as np
pal = np.array(Image.open("stego.png").getpalette()).reshape(-1,3)
keys = {
  "luminance": 0.299*pal[:,0] + 0.587*pal[:,1] + 0.114*pal[:,2],
  "sum": pal.sum(axis=1),
  "hue_r": pal[:,0],
}
for name, k in keys.items():
    order = np.argsort(k)
    match = np.array_equal(order, np.arange(len(pal)))
    print(f"{name}: sorted={match}")
```

Если палитра «почти отсортирована» по одному из ключей с несколькими инверсиями, позиции инверсий кодируют биты. Посчитайте инверсии и их знак:

```python
inv = [i for i in range(len(pal)-1) if k[i] > k[i+1]]
bits = [1 if k[i] > k[i+1] else 0 for i in range(len(pal)-1)]
```

## Неиспользуемые записи и tRNS

Два самых «дешёвых» канала палитровых изображений:

- **Неиспользуемые записи.** Записи палитры, на которые не ссылается ни один пиксель, — чистый контейнер. Сравните множество использованных индексов с полным диапазоном.
- **tRNS (PNG).** Массив прозрачности для палитры; значения альфы для неиспользуемых записей можно модулировать. Читайте через `im.info.get("transparency")`.

```python
print("transparency:", Image.open("stego.png").info.get("transparency"))
```

Часто данные лежат именно в «мёртвых» областях — там, где их никто не проверяет. Начните с неиспользуемых записей, затем tRNS, затем порядок.

## Стеганография в палитре vs LSB индексов

Два близких, но разных канала палитровых изображений: (1) содержимое/порядок *палитры* (PLTE) и (2) последовательность *индексов* пикселей. Их путают. Палитровый канал не зависит от картинки: перестановка записей и «дырки» видны только в самой палитре. Индексный канал — это фактически LSB по индексам: данные в младших битах индексов, которые видны как «шум» в значениях пикселей.

```python
import numpy as np
from PIL import Image
im = Image.open("stego.png")           # mode "P"
idx = np.array(im)
bits_lsb = (idx & 1).astype(np.uint8)   # индексный канал
pal = np.array(im.getpalette()).reshape(-1,3)
print("index lsb bytes:", np.packbits(bits_lsb.ravel()).tobytes()[:16])
print("palette entry0:", pal[0].tolist())
```

Проверяйте оба: сначала палитру (порядок/дырки), затем индексы. Если данные «не в палитре», но изображение шумное — почти наверняка индексный LSB.

## Типичные ошибки

- **Конвертация в RGB.** `im.convert("RGB")` уничтожает палитру — работайте в режиме `P`.
- **Одна палитра на все кадры (GIF).** Локальные палитры проверяйте отдельно.
- **Размер палитры.** Число записей ≠ 256; индексы вне диапазона — ошибка парсинга.
- **Сортировка по неверному ключу.** Пробуйте яркость, сумму, hue, насыщенность.
- **tRNS пропущен.** Прозрачность — тоже данные.
- **zsteg не всё видит.** Палитровые трюки делайте вручную.

Практический порядок: `pngcheck -v` → палитра (порядок/дырки/tRNS) → индексы (LSB/чётность) → конвертация при необходимости.
