Любая стегосистема балансирует три свойства: **ёмкость** (сколько данных), **незаметность** (imperceptibility) и **робастность** (устойчивость к обработке). Улучшение одного обычно ухудшает другое. В CTF/forensics полезно уметь быстро оценить максимальную ёмкость носителя — это подсказывает, где искать и сколько данных ожидать.

## Триада и компромиссы

| Свойство | Что означает | Цена |
|---|---|---|
| Ёмкость | объём скрываемых данных | больше ёмкость → заметнее |
| Незаметность | невидимость изменений | выше незаметность → меньше ёмкость |
| Робастность | устойчивость к сжатию/обрезке | выше робастность → меньше ёмкость |

## Расчёт ёмкости

- **Изображение LSB:** `width × height × каналы × бит_на_канал`. Для RGB 8-бит с 1 LSB: `W×H×3/8` байт. Пример 1024×768: 1024×768×3/8 ≈ 294 КБ.
- **Аудио LSB:** `samples × channels × бит_на_канал / 8`. 44100 Гц, 16-бит, моно, 60 с: 44100×60×1/8 ≈ 330 КБ на 1 LSB.
- **Видео:** `кадры × кадровая ёмкость`; DCT-коэффициенты дают меньше, но устойчивее.
- **Текст:** пробелы/zero-width — байт на пробел (низкая ёмкость).

## Скорость и незаметность

- Чем больше бит на пиксель, тем сильнее искажение (PSNR падает).
- Типично безопасно 1 LSB/канал; >2 — заметно.
- Адаптивные схемы прячут в «шумных» областях (края), повышая ёмкость без заметности.

## Практические оценки

```python
# оценка ёмкости PNG LSB
from PIL import Image
im = Image.open('image.png')
w,h = im.size; ch = len(im.getbands())
print('capacity bytes (1 LSB/ch):', w*h*ch//8)
```

Для forensics: если подозреваемая эксфильтрация — картинка 4 МБ, LSB-канал ≈ 1.5 МБ, что позволяет оценить объём возможной утечки.

## Разобранный пример

CTF: дан PNG 800×600 и «маленький» зашифрованный blob 50 КБ. Пентестер считает ёмкость LSB (800×600×3/8 ≈ 180 КБ) → 50 КБ влезает с запасом → данные, вероятно, в LSB RGB, а не в метаданных. Это сужает поиск.

## Частые ошибки

- Искать большой payload там, где ёмкость канала мала (например, в тексте).
- Считать, что «больше бит = лучше» (растёт заметность).
- Не учитывать сжатие (JPG/MP3 ломают LSB).
- Путать ёмкость изображения и его размер в байтах.

## Что делать дальше

- **Оцените ёмкость** → сузьте, в каком канале искать.
- **Payload большой** → ищите LSB RGB/аудио, а не метаданные.
- **Нужна устойчивость** → DCT/spread-spectrum (меньше ёмкость).
- **Нужна незаметность** → 1 LSB/канал, адаптивно.

## Формулы ёмкости по носителям

| Носитель | Формула (1 бит/элемент) | Пример |
|----------|-------------------------|--------|
| Изображение RGB | W×H×3/8 байт | 1024×768 → 294 КБ |
| Изображение RGBA | W×H×4/8 байт | 1024×768 → 393 КБ |
| 8-бит палитра | W×H/8 байт | 1024×768 → 98 КБ |
| Аудио PCM | samples×channels/8 | 44100×60×1/8 ≈ 330 КБ |
| Видео | frames × W×H×3/8 | 300×294 КБ ≈ 86 МБ |
| Текст (zero-width) | ~1 байт/вставка | зависит от числа вставок |
| DCT-коэффициенты | ~0.1–0.3 бит/пиксель | меньше, но робастно |

```python
from PIL import Image
im = Image.open('image.png')
w, h = im.size
ch = len(im.getbands())            # 3 (RGB) / 4 (RGBA) / 1 (L)
for k in (1, 2, 3):
    print(f'{k} LSB/ch: {w*h*ch*k//8} bytes')
```

## Скорость, PSNR и адаптивные схемы

- **1 LSB/канал** — искажение почти незаметно (PSNR > 50 дБ).
- **2–3 LSB** — заметно на гладких областях; PSNR ~40–45 дБ.
- **Адаптивные схемы** прячут в «шумных» областях (края, текстуры), где искажение маскируется; ёмкость растёт без роста заметности.
- **Проверка:** сравните стего и оригинал по PSNR/SSIM — большие значения = незаметно.

```python
import numpy as np
from PIL import Image
a = np.asarray(Image.open('orig.png').convert('RGB'), float)
b = np.asarray(Image.open('stego.png').convert('RGB'), float)
mse = ((a-b)**2).mean()
psnr = 10*np.log10(255**2/mse) if mse else float('inf')
print('PSNR dB:', round(psnr, 2))
```

## Робастность vs ёмкость (таблица методов)

| Метод | Ёмкость | Робастность | Заметность |
|-------|---------|-------------|-----------|
| LSB RGB | высокая | низкая | низкая |
| LSB палитры | средняя | низкая | низкая |
| DCT (JPEG) | средняя | высокая | средняя |
| Spread-spectrum | низкая | очень высокая | низкая |
| Эхо (аудио) | низкая-средняя | средняя | низкая |
| Фазовое (аудио) | средняя | средняя | низкая |

Правило: жертвуете ёмкостью ради робастности (или наоборот).

## Forensics: оценка объёма утечки

Зная канал, можно оценить, сколько данных физически могло быть вынесено. Это ключевой аргумент в отчёте IR.

```python
# сколько влезает в LSB картинки 4 МБ
from PIL import Image
im = Image.open('suspect.png')
w, h = im.size
print('max LSB payload:', w*h*len(im.getbands())//8, 'bytes')
```

Если подозреваемая утечка (секрет) больше ёмкости LSB — значит, использован другой канал (метаданные/аудио/DCT) или контейнер больше.

## Разобранные примеры

**1. Сужаем поиск.** PNG 800×600, blob 50 КБ. Ёмкость LSB ≈ 180 КБ → 50 КБ влезает → ищем в LSB RGB, а не в метаданных.

**2. Не влезает.** Payload 5 МБ, картинка 200 КБ → LSB не подходит → ищите видео/аудио-контейнер.

**3. Робастность.** Данные пережили пересжатие → вероятно DCT/spread-spectrum, а не LSB.

## Частые ошибки и отладка

- **Искать большой payload в малом канале** (текст, метаданные).
- **«Больше бит = лучше»** — растёт заметность.
- **Не учитывать сжатие** (JPG/MP3 ломают LSB).
- **Путать ёмкость и размер файла.**
- **Отладка:** сравните размер payload с расчётной ёмкостью канала — это отсекает невозможные варианты.

## Что делать дальше / дерево решений

1. Оцените ёмкость канала (формула).
2. Payload влезает в LSB? → ищите в LSB RGB/аудио.
3. Payload большой → видео/аудио-контейнер или DCT.
4. Нужна робастность → DCT/spread-spectrum.
5. Нужна незаметность → 1 LSB, адаптивно.

## Шпаргалка: оценка за секунды

```python
from PIL import Image
im = Image.open('x.png'); w,h = im.size; ch = len(im.getbands())
print('1 LSB/ch:', w*h*ch//8, 'bytes')     # ёмкость
print('file size:', __import__('os').path.getsize('x.png'), 'bytes')
```

```bash
# аудио
python3 -c "print(44100*60*1//8,'bytes for 60s mono 1 LSB')"
```

Практические правила: (1) payload влезает в LSB изображения? — ищите в LSB RGB; (2) не влезает — нужен аудио/видео-контейнер; (3) данные пережили пересжатие — DCT/spread-spectrum; (4) нужна незаметность — 1 LSB, адаптивно. Всегда сравнивайте расчётную ёмкость с размером подозреваемого payload — это мгновенно отсекает невозможные каналы. В forensics оценка ёмкости — аргумент о максимальном объёме утечки. В отчёте фиксируйте: формулу, расчёт и вывод о канале.

## Формула для оценки объёма утечки

Для отчёта IR удобно иметь готовую формулу: `ёмкость_байт = (элементов × бит_на_элемент) / 8`. Для изображения элементов = `W×H×каналы`; для аудио = `частота × длительность_с × каналы`; для видео = `кадры × W×H×каналы`. Умножая на число используемых бит (1, 2, 3), получаете верхнюю границу. Если реальный секрет больше этой границы — канал выбран неверно, ищите другой контейнер. Это самый быстрый способ сузить пространство поиска и обосновать выводы.
