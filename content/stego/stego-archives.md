Архивы — идеальный носитель стеганографии: они и сами часто содержат полезное, и обладают «метаданными», которые большинство инструментов игнорируют. У ZIP есть per-file и глобальные **комментарии**, **extra-поля** (`0x5455`, `0x7875` и кастомные) и возможность **конкатенации** (второй ZIP после `End of Central Directory`). GZIP допускает конкатенацию потоков, tar — произвольные «дыры» и `pax`-заголовки. Всё это даёт каналы для скрытых сообщений, а вложенные «матрёшки» (архив в архиве) — типовой CTF-паттерн.

## ZIP: структура и каналы

ZIP состоит из локальных заголовков (`PK\x03\x04`), центральной директории (`PK\x01\x02`) и `End of Central Directory` (`PK\x05\x06`).

| Канал | Где | Инструмент |
|---|---|---|
| Файловый комментарий | Central Directory | `unzip -z`, `zipdetails` |
| Глобальный комментарий | EOCD | `zipinfo -z` |
| Extra field | Local/CD header | `zipdetails` |
| Данные после EOCD | хвост файла | `binwalk`, `dd` |
| Имя файла | CD | `unzip -l` |

```bash
# комментарии
unzip -z archive.zip
zipinfo -z archive.zip
# полный разбор всех структур, включая extra-поля
zipdetails archive.zip
# посмотреть хвост после EOCD
python3 -c "d=open('archive.zip','rb').read(); i=d.rfind(b'PK\x05\x06'); print('EOCD@',i,'size',len(d),'tail',len(d)-i-22)"
```

## Extra-поля и кастомные заголовки

Extra-поле — это `id(2) + size(2) + data`. Стандартные: `0x5455` (Extended Timestamp), `0x7875` (Unix UID/GID), `0x0001` (Zip64). Приватные/неизвестные id — прямой канал.

```bash
zipdetails archive.zip | grep -i extra -A2
# или вручную по каждому локальному заголовку
python3 - <<'PY'
import struct
d=open('archive.zip','rb').read(); i=0
while True:
    i=d.find(b'PK\x03\x04', i)
    if i<0: break
    nlen,xlen=struct.unpack('<HH', d[i+26:i+30])
    name=d[i+30:i+30+nlen]; extra=d[i+30+nlen:i+30+nlen+xlen]
    print(name, 'extra_len', xlen, extra.hex())
    i+=4
PY
```

## Конкатенация и полиглоты

**Конкатенация gzip:** два gzip-потока подряд — `gunzip` распакует оба, но многие инструменты покажут только первый. **ZIP после ZIP:** второй архив лежит после EOCD первого — `unzip` возьмёт первый, а `binwalk`/`dd` достанут второй. Архивные полиглоты — когда файл одновременно ZIP и, например, PNG.

```bash
# конкатенация gzip
cat a.gz b.gz > both.gz
gunzip -c both.gz   # выведет данные обоих
# ZIP после ZIP
binwalk archive.zip
# извлечь второй архив по смещению
dd if=archive.zip bs=1 skip=<offset> of=second.zip && unzip -l second.zip
```

## Матрёшки и вложенность

Типовой CTF-паттерн: архив внутри архива, иногда с разными расширениями/паролями. Рекурсивная распаковка + `binwalk -e`.

```bash
# рекурсивный binwalk
binwalk -e -M archive.bin
# рекурсивный unzip по сигнатурам
python3 - <<'PY'
import subprocess, os
def unpack(path, depth=0):
    if depth>6: return
    r=subprocess.run(['7z','l',path],capture_output=True,text=True)
    if 'Everything is Ok' in r.stdout:
        out=f'x{depth}'; subprocess.run(['7z','x','-o'+out,path,'-y'],capture_output=True)
        for f in os.listdir(out): unpack(os.path.join(out,f),depth+1)
PY
```

## Разобранный пример

CTF: `secret.zip`.

```bash
$ unzip -z secret.zip
Archive:  secret.zip
  flag{zip_comment_in_archive}

$ zipdetails secret.zip | grep -i "extra" -A3
      0054 Extra ID 0x5455 'UT: Extended Timestamp'
      0059 Extra ID 0x7875 'Unix UID/GID'
      006e Extra ID 0x4141 'unknown'  <- 0x4141 = 'AA'

$ python3 -c "d=open('secret.zip','rb').read();i=d.find(b'AA');print(d[i+4:i+40])"
b'flag{zip_custom_extra_field}'
```

Два флага: комментарий и кастомное extra-поле `0x4141`. Дальше — проверка хвоста после EOCD и матрёшек.

## Краевые случаи и подводные камни

- **Zip64:** большие архивы используют extra `0x0001` и 64-битные поля — не путай с данными.
- **Шифрование:** `PK\x03\x04` с флагом encryption — содержимое зашифровано, но структура/комментарии доступны.
- **RAR/7z:** у них свои заголовки (7z — сигнатура `7z\xBC\xAF\x27\x1C`); комментарии и «мусорные» поля тоже есть, но инструменты другие (`7z l -slt`).
- **tar:** данные в «дырах» между записями и в `pax`-заголовках; `tar -tv` не покажет padding.
- **Повреждённый EOCD:** некоторые «задачи» портят EOCD, чтобы `unzip` падал, но данные остаются — `binwalk`/`dd` спасут.

## Что дальше / решение

Пайплайн: `zipdetails`/`unzip -z` (комментарии и extra) → `python`-скрипт по локальным заголовкам → `binwalk`/`dd` для данных после EOCD и конкатенации → `7z l -slt` для 7z/RAR → рекурсивная распаковка матрёшек → `file` по каждому вложенному файлу (может оказаться картинка со стего). Архивы — «контейнеры в контейнере»: распаковывай и рекурсивно прогоняй содержимое через общий пайплайн.

## RAR и 7z детально

RAR и 7z — проприетарные контейнеры со своими заголовками, но с теми же идеями: комментарии, дополнительные поля и «мусор». 7z начинается с сигнатуры `37 7A BC AF 27 1C`, RAR — с `Rar!\x1a\x07\x00` (RAR4) или `Rar!\x1a\x07\x01\x00` (RAR5).

```bash
# 7z: детальный листинг со всеми атрибутами и комментариями
7z l -slt archive.7z
# RAR: список с комментариями
unrar l archive.rar
unrar vt archive.rar        # технический листинг
# 7z умеет показать «сырые» метаданные
7z l -slt archive.7z | grep -iE "comment|method|attributes"
```

7z хранит структуру в «кодированных заголовках»: если включён `-mhc=on`, заголовки сжаты и зашифрованы — тогда комментарии не видны без пароля, но сами данные всё равно доступны по структуре.

## tar и pax-заголовки

tar не сжимает данные и не имеет глобального комментария, но у него есть «дыры» и расширенные `pax`-заголовки (`pax_global_header`, `SCHILY.*`). Данные в «дырах» между записями `tar` не видит, а `binwalk`/`dd` — да.

```bash
tar -tvf archive.tar
# показать pax-заголовки
tar --list --verbose --verbose -f archive.tar 2>&1 | head
# найти «дыры» и дописанные данные
binwalk archive.tar
# распаковать и проверить padding
tar -xf archive.tar -C out/
```

pax-заголовок — это текстовый блок с произвольными ключами; в нестандартные ключи легко спрятать данные.

## Автоматизация рекурсивной распаковки

Матрёшки удобно разбирать рекурсивно: `binwalk -e -M` или свой скрипт на `7z`/`unzip`.

```python
import subprocess, os, shutil
def unpack(path, depth=0, maxd=8):
    if depth>maxd: return
    for tool,args in (('7z',['x','-y']),):
        out=f'{path}.d{depth}'
        r=subprocess.run([tool,*args,'-o'+out,path],capture_output=True,text=True)
        if 'Everything is Ok' in r.stdout and os.path.isdir(out):
            for f in os.listdir(out):
                unpack(os.path.join(out,f), depth+1, maxd)
for f in os.listdir('.'):
    if f.endswith(('.zip','.7z','.rar','.tar','.gz','.bz2')):
        unpack(f)
```

Скрипт рекурсивно распаковывает и останавливается на заданной глубине — защита от бесконечных бомб.

## Защита от «архивных бомб»

Вложенные архивы могут быть zip-бомбой (много уровней, экспоненциальный рост). Всегда ограничивайте глубину и суммарный размер.

```bash
# 7z умеет лимиты
7z x -y -oout archive.zip -mx=0
# unzip с лимитом через ulimit
ulimit -f 1048576   # лимит 512 МБ на файл
unzip -o archive.zip -d out/
```

Практический совет: перед распаковкой смотрите `7z l -slt` (размеры до распаковки) и `binwalk` (сколько вложенных сигнатур). Так вы не «уроните» среду анализа.

## Итоговый чек-лист по архивам

1. `file` — определить формат по сигнатуре.
2. `zipdetails`/`7z l -slt`/`unrar vt` — комментарии и extra-поля.
3. `binwalk`/`dd` — данные после EOCD и конкатенация.
4. Рекурсивная распаковка матрёшек с лимитом глубины.
5. `file` по каждому вложенному файлу — он может быть картинкой/аудио со стего.
6. Прогнать извлечённое через общий стего-пайплайн.

## Разобранный пример 2: 7z и матрёшка

Задача: `data.7z`, подсказка «глубже».

```bash
$ 7z l -slt data.7z | grep -iE "Path|Comment|Encrypted"
Path = inner.zip
Encrypted = -
$ 7z x -y -oout data.7z && ls out
inner.zip
$ unzip -z out/inner.zip
Archive:  out/inner.zip
  flag{7z_inside_zip_comment}
```

Флаг — в комментарии вложенного ZIP. Приём «матрёшка» типичен: внешний контейнер безобиден, а данные — внутри. Рекурсивно распаковывайте до предела (обычно 5–8 уровней) и на каждом уровне проверяйте комментарии, extra-поля и хвосты. Если внутри окажется картинка/аудио — переключайтесь на соответствующий пайплайн.

Дополнительно: `7z l -slt` покажет поле `Comment` для каждого файла и метод сжатия. Если заголовки зашифрованы (`Encrypted = +` для заголовков), комментарии не видны, но структура файлов — видна; тогда работайте с данными напрямую и пробуйте пароль из подсказки. Не забывайте ограничивать глубину и размер, чтобы не «поймать» zip-бомбу.

## Частые ошибки и как их избежать

- **Смотреть только `unzip -l`:** листинг не показывает комментарии и extra-поля; используйте `zipdetails`/`unzip -z`.
- **Пропустить данные после EOCD:** второй ZIP, gzip-поток или произвольный blob легко не заметить; `binwalk`/`dd` обязательны.
- **Не учитывать Zip64:** extra `0x0001` и 64-битные поля можно спутать с данными; знайте структуру.
- **Забыть про матрёшку:** внешний архив часто «пустой», а данные — внутри; распаковывайте рекурсивно (с лимитом глубины).
- **Zip-бомба:** неограниченная рекурсия «уронит» среду; ставьте лимиты (`ulimit -f`, глубина ≤8).
- **7z с шифрованными заголовками:** комментарии не видны без пароля, но структура доступна; работайте с данными и подсказкой.

Практический вывод: архив — это контейнер контейнеров. Пайплайн `zipdetails` → `binwalk`/`dd` → рекурсивная распаковка → `file` по содержимому → общий стего-пайплайн закрывает почти все задачи. Не забывайте проверять комментарии и extra-поля на каждом уровне вложенности.
