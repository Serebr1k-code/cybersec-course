## Вопрос, с которого всё начинается

В задаче дан `secret.zip`. Ты распаковываешь его — внутри лежит обычный `readme.txt` с текстом «ничего интересного». Ты запускаешь `unzip -l` — тоже ничего. Но флаг где-то есть. Может ли архив прятать данные **сам по себе**, даже если всё его содержимое безобидно?

Ответ: да. У архивов есть «метаданные», которые большинство инструментов не показывает: комментарии, extra-поля и данные за концом архива. Разберём это на нашем файле.

## Наш пример: secret.zip

**ZIP** — формат архива, состоящий из трёх частей: локальные заголовки файлов (`PK\x03\x04`), **Central Directory** (каталог, `PK\x01\x02`) и **EOCD** (End of Central Directory, `PK\x05\x06`) — маркер конца.

| Канал | Где | Инструмент |
|---|---|---|
| Файловый комментарий | Central Directory | `unzip -z` |
| Глобальный комментарий | EOCD | `zipinfo -z` |
| Extra field | Local/CD header | `zipdetails` |
| Данные после EOCD | хвост файла | `binwalk`, `dd` |
| Имя файла | Central Directory | `unzip -l` |

## Шаг 1: читаем комментарии

Комментарий — легальное поле ZIP, которое `unzip -l` не показывает:

```bash
$ unzip -z secret.zip
Archive:  secret.zip
  flag{zip_comment_in_archive}
$ zipinfo -z secret.zip
Archive:  secret.zip
There is no zipfile comment.
```

`unzip -z` показал файловый комментарий с флагом. `zipinfo -z` выводит **глобальный** комментарий — здесь его нет, но проверять надо оба.

## Шаг 2: extra-поля

**Extra-поле** — это структура `id(2 байта) + size(2 байта) + data`, привязанная к заголовку. Стандартные id: `0x5455` (Extended Timestamp), `0x7875` (Unix UID/GID), `0x0001` (Zip64). А вот **неизвестные** id — прямой канал для данных.

```bash
$ zipdetails secret.zip | grep -i extra -A3
     0054 Extra ID 0x5455 'UT: Extended Timestamp'
     0059 Extra ID 0x7875 'Unix UID/GID'
     006e Extra ID 0x4141 'unknown'   <- 0x4141 = 'AA'
```

`0x4141` — нестандартное поле. Разберём его вручную:

```bash
$ python3 -c "d=open('secret.zip','rb').read();i=d.find(b'AA');print(d[i+4:i+40])"
b'flag{zip_custom_extra_field}'
```

Итак, два флага: комментарий и кастомное extra-поле. Дальше — проверка хвоста после EOCD.

## Шаг 3: данные после EOCD и конкатенация

Многие форматы допускают дописанные данные за своим маркером конца. У ZIP это второй архив после EOCD:

```bash
$ python3 -c "d=open('secret.zip','rb').read(); i=d.rfind(b'PK\x05\x06'); print('tail:', len(d)-i-22)"
tail: 4096
$ binwalk secret.zip
```

**Конкатенация gzip** работает так же: два потока подряд распакуются оба, но `gunzip` покажет только первый.

```bash
$ cat a.gz b.gz > both.gz
$ gunzip -c both.gz      # выведет данные обоих
$ python3 -c "d=open('both.gz','rb').read(); print(d.count(b'\x1f\x8b\x08'))"
2
```

Второй архив вырезают по смещению:

```bash
$ dd if=secret.zip bs=1 skip=<offset> of=second.zip
$ unzip -l second.zip
```

## Шаг 4: RAR, 7z и tar

У других форматов свои заголовки, но те же идеи:

- **7z** — сигнатура `37 7A BC AF 27 1C`; `7z l -slt` показывает комментарии и метод сжатия;
- **RAR** — `Rar!\x1a\x07`; `unrar vt` даёт технический листинг;
- **tar** — данные в «дырах» между записями и в `pax`-заголовках, которые `tar -tv` не покажет.

```bash
$ 7z l -slt data.7z | grep -iE "Path|Comment|Encrypted"
Path = inner.zip
Encrypted = -
$ unrar vt archive.rar | head
```

## Шаг 5: матрёшки и защита от бомб

Типовой паттерн — архив внутри архива. Распаковываем рекурсивно, но **с лимитами**:

```python
import subprocess, os
def unpack(path, depth=0, maxd=8):
    if depth > maxd:
        return
    out = f'{path}.d{depth}'
    r = subprocess.run(['7z','x','-y','-o'+out,path], capture_output=True, text=True)
    if 'Everything is Ok' in r.stdout and os.path.isdir(out):
        for f in os.listdir(out):
            unpack(os.path.join(out, f), depth+1, maxd)
```

`maxd` защищает от **zip-бомбы** — архива, который при распаковке растёт экспоненциально. Также ставьте лимит размера (`ulimit -f`).

## Если не сработало

- **Смотришь только `unzip -l`:** листинг не показывает комментарии и extra-поля; используй `zipdetails`/`unzip -z`.
- **Пропустил данные после EOCD:** второй ZIP или gzip-поток легко не заметить; `binwalk`/`dd` обязательны.
- **Не учёл Zip64:** extra `0x0001` и 64-битные поля можно спутать с данными.
- **Забыл про матрёшку:** внешний архив часто «пустой», а данные — внутри.
- **7z с шифрованными заголовками:** комментарии не видны без пароля, но структура доступна.

## Почему архивы удобны для сокрытия

Архивы — идеальный носитель: они и сами часто содержат полезное, и обладают метаданными, которые большинство инструментов игнорируют. Плюс архив «ожидаемо» содержит бинарные данные — на их фоне лишние байты не бросаются в глаза. Поэтому в CTF архивные задачи встречаются постоянно, а в реальных атаках архивы нередко используют как «упаковку» для второго этапа.

## Практика: ZIP-комментарий как канал

Самый быстрый канал в ZIP — **комментарий архива**: текстовое поле в конце файла, которое не влияет на распаковку. Запишем и прочитаем его:

```python
import zipfile
z = zipfile.ZipFile("a.zip", "w")
z.writestr("readme.txt", "nothing here")
z.comment = b"flag{zip_comment}"
z.close()
print(zipfile.ZipFile("a.zip").comment)
```

```bash
$ python3 zipc.py
b'flag{zip_comment}'
```

Комментарий виден и без Python: в хексе он лежит сразу перед сигнатурой End Of Central Directory (`PK\x05\x06`), а `unzip -z a.zip` печатает его человекочитаемо. Помимо комментария, данные кладут в **extra-поля** записей (произвольные байты в заголовке) и просто **дописывают после EOCD** — `zip` не жалуется на хвост, а `binwalk` и `foremost` его находят.

## Что мы теперь знаем

1. У ZIP есть **комментарии** (файловый и глобальный) и **extra-поля**.
2. Неизвестный id extra-поля — прямой канал для данных.
3. Данные могут лежать **после EOCD** или в **склеенных** потоках.
4. 7z/RAR/tar имеют свои метаданные и «дыры».
5. Матрёшки распаковывают рекурсивно, но **с лимитами**.

## Разобранный пример: 7z и матрёшка

Задача: `data.7z`, подсказка «глубже».

```bash
$ 7z l -slt data.7z | grep -iE "Path|Comment|Encrypted"
Path = inner.zip
Encrypted = -
$ 7z x -y -oout data.7z && ls out
inner.zip
$ unzip -z out/inner.zip
Archive:  out/inner.zip
  flag{7z_inside_zip_comment}
```

Флаг — в комментарии вложенного ZIP. Внешний контейнер безобиден, а данные — внутри. Рекурсивно распаковывай до предела (обычно 5–8 уровней) и на каждом уровне проверяй комментарии, extra-поля и хвосты.

## Итоговый чек-лист

1. `file` — формат по сигнатуре.
2. `zipdetails`/`7z l -slt`/`unrar vt` — комментарии и extra-поля.
3. `binwalk`/`dd` — данные после EOCD и конкатенация.
4. Рекурсивная распаковка матрёшек с лимитом глубины.
5. `file` по каждому вложенному файлу — он может быть картинкой со стего.
6. Прогнать извлечённое через общий стего-пайплайн.

## Чем ZIP отличается от gzip и tar для сокрытия

Архивы дают много «легальных» полей, куда можно положить данные, но у каждого формата свой набор. **ZIP** — самый богатый: у него есть комментарий архива (в EOCD), комментарий каждой записи, **extra-поля** (произвольные байты, которые парсеры обычно игнорируют), центральный каталог, который может дублировать или противоречить локальным заголовкам. Данные можно дописать и **после** EOCD — большинство распаковщиков не заметит.

**gzip** — один поток без каталога: тут канал — комментарий (поле FEXTRA/FCOMMENT) и **конкатенация**: `gzip` официально допускает несколько потоков подряд, и `gunzip` распакует все, а простой анализатор увидит только первый. Это классический приём «двойной gzip». **tar** — формат блоков по 512 байт; в конце два нулевых блока, но после них можно дописать данные, а заголовок каждой записи содержит неиспользуемые поля (например, `name` ограничен 100 байтами, остальное — свободно).

Общий принцип: у каждого формата есть **зарезервированные или игнорируемые поля** и **границы потока**. Сокрытие живёт именно там. Для анализа: `unzip -l -v` (покажет комментарии и extra), `zipinfo`, `7z l -slt`, `binwalk`, `strings`, `xxd` у конца файла. Ищите несоответствия: заявленный размер vs фактический, лишние байты, повторяющиеся сигнатуры.

## Частые вопросы

**Как прочитать ZIP-комментарий?** `unzip -z file.zip` или `zipinfo -z`; комментарий записи — `unzip -l -v`. Иногда флаг прямо в комментарии.

**Что такое extra-поле?** Дополнительные байты в записи ZIP (заголовок ID + размер + данные); стандарт их допускает, парсеры часто пропускают — идеальное место для полезной нагрузки.

**Как распаковать двойной gzip?** `gunzip` автоматически обрабатывает конкатенированные потоки; либо `python3 -c` с `gzip.open` в цикле, либо `binwalk -e`.

**Что если архив зашифрован?** `zip2john` → `hashcat -m 17200/17210/17225` (в зависимости от типа шифрования); проверьте тип в `zipinfo -v`.

## Практика: скрипт для перебора всех ZIP-каналов

Вместо ручного `unzip -z` соберём один проход, который проверяет комментарий, extra-поля и
данные после EOCD:

```
$ python3 - <<'EOF'
import zipfile, struct
p = 'secret.zip'
raw = open(p,'rb').read()
z = zipfile.ZipFile(p)
print('comment:', z.comment)
for i in z.infolist():
    print('extra:', i.extra[:16].hex(), i.filename)
# EOCD начинается с PK\x05\x06, ищем последнее вхождение
idx = raw.rfind(b'PK\x05\x06')
print('after-eocd:', raw[idx+22:idx+22+32])
EOF
comment: b'nto{zip_comment}'
extra: 5455 0a00... secret.txt
after-eocd: b'\x00\x00\x00\x00'
```

Комментарий архива и extra-поля — два самых частых канала; данные после EOCD — третий.

## Практика: матрёшка и защита от бомб

Матpёшка (архив в архиве) — классика CTF, но при автоматической распаковке легко получить
zip-бомбу. Считайте глубину и ограничивайте распаковку:

```
$ for i in $(seq 1 10); do unzip -o -q layer.zip -d layer$i 2>/dev/null || break; done
$ du -sh layer* | tail
$ ulimit -f 1048576   # не больше 1 ГБ на файл
```

Ограничители `ulimit`/таймаут спасают от бомбы, которая распакует 42.zip в петабайты.

## Сравнение форматов для сокрытия

| Формат | Канал сокрытия | Заметность |
|--------|----------------|------------|
| ZIP | комментарий, extra-поле, данные после EOCD | средняя |
| RAR | комментарий, recovery record | низкая |
| 7z | метаданные, порядок файлов | низкая |
| tar | padding-блоки, имена | средняя |
| gzip | имя/комментарий в заголовке | высокая |

## Если не сработало

- **Комментарий пуст, extra пусто.** Проверьте, не архивирован ли файл повторно —
  инструмент мог пересобрать ZIP и стереть канал.
- **`unzip` отказывается открывать.** Возможно, это не ZIP, а «ZIP с префиксом» (данные до
  `PK\x03\x04`). Найдите первый локальный заголовок и вырежьте префикс.
- **Данные после EOCD обрезаны.** Некоторые читатели нормализуют архив; работайте с
  исходным байтовым потоком.

## Ограничение: рекурсивный разбор

Глубокие матрёшки и бомбы делают «тупую» рекурсию небезопасной и медленной. Всегда
ограничивайте глубину, суммарный размер и число итераций — иначе анализ превратится в
самоподрыв среды.
