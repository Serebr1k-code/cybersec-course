## Вопрос, с которого всё начинается

В прошлом уроке мы видели JSteg: он пишет биты в младшие разряды DCT-коэффициентов, и его легко ловит хи-квадрат-тест. Задача: спрятать данные в JPEG так, чтобы этот тест **молчал**. Так родился алгоритм **F5**.

В этом уроке мы разберём один F5-контейнер и поймём, почему он «невидим» для классического стегоанализа.

## Наш пример: stego.jpg

```
$ stegdetect stego.jpg
stego.jpg: f5
```

`stegdetect` говорит `f5`. Условие задачи подсказывает пароль: `hunter2`. Применяем F5-декодер:

```
$ java -jar F5.jar d -p hunter2 -c stego.jpg
extracted: secret.txt
$ cat secret.txt
flag{f5_matrix_coding}
```

Флаг получен. Теперь разберёмся, что именно делает F5 — иначе при смене параметров (`k`, ключа) мы не сможем подстроиться.

## Шаг 1: в чём проблема JSteg

JSteg заменяет младший бит коэффициента. При этом значение может как вырасти, так и уменьшиться, и в гистограмме коэффициентов появляется «выравнивание» пар `2k` и `2k+1`. Классический **хи-квадрат-тест** это ловит: в естественном JPEG пары различаются, после JSteg — почти одинаковы.

F5 решает проблему двумя приёмами, которые мы разберём дальше.

## Шаг 2: приём первый — уменьшение вместо замены

F5 не заменяет бит, а **уменьшает абсолютное значение** коэффициента на 1, если бит не совпадает:

- если нужно записать бит, равный младшему биту коэффициента, — ничего не меняется;
- если не равный — `c := c − sign(c)` (модуль уменьшается на 1).

Изменение всегда «в одну сторону», и модель искажений другая, чем у JSteg. Чётность при этом меняется предсказуемо — и именно это мы используем при извлечении.

## Шаг 3: приём второй — матричное кодирование (n, k)

Сердце F5 — **матричное кодирование**. Вместо «один бит — один коэффициент» используется код `(1, 2^k − 1)`: группа из `2^k − 1` коэффициентов несёт `k` бит.

Возьмём `k = 3`: группа из `2^3 − 1 = 7` коэффициентов кодирует 3 бита. Код строится так, что при несовпадении меняется ровно **один** коэффициент, а при совпадении — ноль. Средняя плотность изменений — `1/(2^k + 1)`: для `k = 3` меняется в среднем 1 коэффициент из 8.

Сравни с JSteg: там 1 изменение на 1 бит. F5 в разы эффективнее и незаметнее.

## Шаг 4: перестановка по ключу

F5 использует **ключ**, задающий псевдослучайную **перестановку** коэффициентов. Без ключа извлечение невозможно — ты не знаешь, в каком порядке читать коэффициенты и как собирать группы. Ключ обычно дают в условии задачи или прячут в метаданных.

## Шаг 5: почему хи-квадрат молчит

F5 обманывает классический тест по трём причинам:

1. он не заменяет биты, а уменьшает коэффициенты — иная модель изменений;
2. матричное кодирование меняет **минимум** коэффициентов;
3. перестановка «размазывает» след по всему изображению.

В итоге распределение остаётся близким к естественному. Более тонкие детекторы (калибровочный анализ, анализ «двойных» значений) F5 всё же ловят — но в CTF проще определить метод и извлечь.

## Шаг 6: параметр k и извлечение

Для извлечения нужно знать **k** (обычно 3) и ключ. Если `k` неверный — данные декодируются в мусор. Поэтому при неудаче перебери `k = 1..5`.

```bash
# встроить (чтобы понять свойства контейнера)
java -jar F5.jar e -e secret.txt -p pass -c cover.jpg out.jpg
# извлечь
java -jar F5.jar d -p pass -c out.jpg
# старая C-версия
f5_extract out.jpg
```

Если ключа нет — попробуй пустой ключ, ключ из метаданных, имя файла.

## Шаг 7: F5 плюс шифрование

F5 часто комбинируют с шифрованием: данные сначала шифруют, потом встраивают. Тогда после извлечения получается «случайный» блоб:

```
$ java -jar F5.jar d -p key -c stego.jpg
$ file extracted.bin
extracted.bin: data
```

`data` вместо текста — признак шифртекста. Дальше определи тип (XOR, AES, RC4) и найди ключ.

## Если не сработало

- Подтверди метод через `stegdetect` или `Aletheia` (калибровочный стегоанализ).
- Собери все возможные ключи: пустой, из условия, метаданных, имени файла.
- Перебери `k = 1..5`.
- Не применяй к F5 `steghide` — у него другой алгоритм, он F5-контейнеры не читает.

## Что мы теперь знаем

1. F5 придуман, чтобы обойти хи-квадрат-тест, который ловит JSteg.
2. Он уменьшает модуль коэффициента, а не заменяет бит.
3. Матричное кодирование `(n,k)` даёт `k` бит на `2^k − 1` коэффициентов.
4. Ключ задаёт псевдослучайную перестановку; без него извлечения нет.
5. Для извлечения нужны ключ и параметр `k` (обычно 3).

## Шаг 8: расчёт ёмкости и параметр k

Ёмкость F5 зависит от числа пригодных DCT-коэффициентов и параметра `k` матричного кода. При `(1, 2^k − 1)` группа из `2^k − 1` коэффициентов несёт `k` бит. Чем больше `k`, тем меньше фактических изменений на бит, но тем длиннее нужны группы.

Практически для извлечения нужно знать `k`: при неверном `k` данные декодируются в мусор. Стандартные реализации используют `k = 3` по умолчанию, но задачи могут менять его — поэтому при неудаче перебери `k = 1..5`.

## Шаг 9: детекторы F5 и калибровочный стегоанализ

F5 устойчив к хи-квадрату, но не абсолютен. Детекторы используют:

- **калибровку** — перекодируют/обрезают изображение, получают эталонную гистограмму и сравнивают с фактической;
- **анализ «двойных» значений** коэффициентов (артефакт уменьшения);
- **оценку длины сообщения** через подгонку модели.

Инструмент **Aletheia** реализует ряд таких тестов. В CTF это полезно, чтобы подтвердить F5, когда `stegdetect` не уверен.

## Шаг 10: F5 плюс шифрование

F5 часто комбинируют с шифрованием: сначала данные шифруют, потом встраивают. Тогда извлечённый поток — «случайный» блоб с высокой энтропией. Действия: извлечь (`F5.jar d`), проверить `file` (вероятно `data`), определить тип шифрования (XOR, AES, RC4) и найти ключ. Ключ F5 и ключ шифрования могут совпадать или различаться.

## Шаг 11: практический чек-лист F5-задачи

1. `stegdetect`/`Aletheia` — подтверди F5.
2. Собери возможные ключи: пустой, из условия, метаданных, имени файла.
3. `F5.jar d -p <key>`; при мусоре перебери `k = 1..5`.
4. Извлечённое — проверь `file`; при `data` сними шифрование.
5. Ничего — рассмотри OutGuess/JSteg и структурные каналы JPEG.

Помни: `steghide` F5-контейнеры не читает — у него другой алгоритм.

## Почему F5 обходит хи-квадрат, а JSteg нет

Классический стегоанализ JPEG использует **хи-квадрат-тест** на гистограмме коэффициентов DCT. Идея: при естественном изображении гистограммы пар соседних значений (например, `2k` и `2k+1`) похожи, но не идентичны. JSteg заменяет младший бит коэффициента, «выравнивая» пары — и хи-квадрат это ловит: распределение становится подозрительно симметричным.

F5 это обходит двумя приёмами. Во-первых, вместо замены младшего бита он **уменьшает абсолютное значение** коэффициента на единицу, причём только когда это нужно. Уменьшение сдвигает коэффициент к нулю, а не переставляет пару — симметрия гистограмм не возникает, и хи-квадрат молчит. Во-вторых, **матричное кодирование (n, k)**: чтобы записать `k` бит, F5 меняет не все `n` коэффициентов, а в среднем лишь `n·(1 − 2^{-k})`; при `k = 3` правок почти втрое меньше. Меньше изменений — слабее статистический след.

Отсюда практика: F5 сложнее детектировать хи-квадратом, поэтому применяют калибровочный стегоанализ (сравнение с «очищенной» версией изображения) и специфичные детекторы. Для извлечения важны **два параметра**: ключ перестановки (порядок, в котором обходятся коэффициенты) и `k` матричного кода. Без них данные не читаются, поэтому в CTF их либо дают, либо перебирают.

## Частые вопросы

**Как узнать `k`?** Извлекают при нескольких `k` (1..5) и смотрят, где появляется осмысленный заголовок (например, `PK`, текст, base64). Иногда `k` фиксирован (часто 3).

**Почему F5 не использует DC-коэффициенты?** Изменение DC заметно визуально; F5 трогает AC-коэффициенты, а нулевые пропускает.

**Что если ключ неизвестен?** Перебор ключа парольной стеганографии (stegseek не для F5; есть специализированные F5-декодеры с брутом) либо поиск утечки ключа в задаче.

**Почему F5 всё же детектируют?** Матричное кодирование уменьшает число изменений, но не до нуля; калибровочные методы оценивают ожидаемое число правок и сравнивают с фактическим.

## Шаг 12: практический разбор F5-задачи

Соберём типовой порядок действий для JPEG, где подозревается F5.

1. **Осмотр.** `file stego.jpg`, `exiftool stego.jpg` — размер, метаданные, `Comment`.
2. **Быстрый LSB.** `zsteg -a stego.jpg` — вдруг это не F5, а обычный LSB.
3. **Пароль.** `steghide extract -sf stego.jpg` с пустым паролем; если просит — `stegseek`
   со словарём.
4. **F5-специфика.** Если `steghide` не открывает, а картинка «подозрительно чистая» по
   хи-квадрату, пробуем **`f5.jar`** (`java -jar f5.jar x -p пароль stego.jpg`).
5. **Оценка.** `stegdetect -s 1 -t j stego.jpg` — какой стегоанализ срабатывает.

```bash
java -jar f5.jar x -p '' stego.jpg
```

Ключевой признак F5 — **нет роста chi-square**, потому что алгоритм уменьшает
коэффициенты, а не заменяет LSB. Поэтому классические LSB-детекторы молчат, и решение
часто приходит только после подбора пароля. Если ни один шаг не дал результата,
проверьте, не дописан ли ZIP после `EOI` (`binwalk`), — это другой канал.

## Куда дальше

Дальше — **OutGuess и steghide**: два главных «парольных» инструмента для JPEG, где ключ задаёт порядок обхода коэффициентов. А пока запомни: F5 = уменьшение коэффициентов + матричное кодирование + ключ, и для извлечения нужны ключ и `k`.

## Где пригодится

- **CTF (Stego):** задачи с подсказками «F5», «matrix encoding», где простые тулзы бессильны.
- **Пентест:** продвинутые способы сокрытия полезной нагрузки в изображениях.
- **Forensics:** оценка устойчивости watermark-схем и их обнаружение.
- **Работа:** теория кодирования в защите информации, стойкая стеганография.
