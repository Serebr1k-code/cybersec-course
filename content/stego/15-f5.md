## Что такое F5 и зачем он нужен

F5 — алгоритм стеганографии для JPEG, предложенный Андреасом Вестфельдом и Андреасом Пфицманом (2001). Его цель — устранить главный недостаток JSteg: **изменение гистограммы DCT-коэффициентов**. JSteg просто заменяет младший бит ненулевого коэффициента, из-за чего классический хи-квадрат-тест легко обнаруживает встраивание. F5 решает эту проблему двумя приёмами: **уменьшением коэффициентов** (вместо замены бита) и **матричным кодированием** (встраивание нескольких бит в группу коэффициентов с минимальным числом изменений).

Именно поэтому F5 долгое время считался «недетектируемым» и часто встречается в CTF-задачах высокого уровня.

## Уменьшение коэффициентов вместо замены бита

Идея: вместо того чтобы **заменять** младший бит коэффициента (что может как увеличить, так и уменьшить значение), F5 только **уменьшает модуль** коэффициента на 1, если бит не совпадает. Это делает изменение предсказуемым и смещает гистограмму иначе, чем JSteg. В сочетании с матричным кодированием это резко снижает число фактических изменений.

## Матричное кодирование (n, k)

Сердце F5 — **матричное кодирование**. Вместо «один бит — один коэффициент» используется код `(1, 2^k - 1)`: группа из `2^k - 1` коэффициентов кодирует `k` бит, при этом в среднем изменяется лишь `2^k / (2^k + 1)` коэффициента. При `k = 3` один изменённый коэффициент кодирует 3 бита вместо 1 — втрое эффективнее и незаметнее.

Практически это означает, что ёмкость F5 выше, а след в статистике слабее. Для извлечения, однако, нужно знать **k** и порядок обхода.

## Перестановка по ключу

F5 использует ключ, задающий **псевдослучайную перестановку** коэффициентов. Без ключа извлечение невозможно. Ключ также определяет, какие коэффициенты попадают в матричные группы. Поэтому F5-контейнеры всегда требуют ключа (или он даётся в условии/метаданных).

## Почему F5 обманывает хи-квадрат

Классический хи-квадрат ищет выравнивание частот пар `2k`/`2k+1`. F5 же:
- не заменяет биты, а уменьшает коэффициенты (иная модель изменений);
- меняет минимум коэффициентов благодаря матричному кодированию;
- использует перестановку, «размазывая» след.

В результате распределение остаётся близким к естественному, и простые тесты молчат. Детекторы F5 используют более тонкие признаки (калибровка, анализ «двойных» значений), но в CTF проще определить F5 и извлечь.

## Извлечение

```bash
# F5-steganography (Java) — основной инструмент
java -jar F5.jar e -e secret.txt -p pass -c cover.jpg out.jpg   # встроить
java -jar F5.jar d -p pass -c out.jpg                            # извлечь
# старый C-инструмент
f5_extract out.jpg
```

Если ключа нет, попробуйте пустой ключ и ключи из условия/метаданных. Иногда F5 совмещают с шифрованием — тогда после извлечения данные ещё нужно расшифровать.

## Сравнение с JSteg и OutGuess

| Метод | Модель изменений | Детект хи-квадрат | Ключ |
|---|---|---|---|
| JSteg | замена LSB | легко | нет |
| OutGuess 0.2 | замена + статистическое восстановление | устойчив | да |
| F5 | уменьшение + матричное кодирование | устойчив | да |
| Model-based | синтез модели | очень устойчив | да |

F5 и OutGuess 0.2 — два самых «крепких» к хи-квадрату метода; оба используют ключ.

## Инструменты

- **`F5.jar`** (Java) — эталонная реализация.
- **`f5`/`f5_extract`** — C-версии.
- **`stegdetect`** — может определять F5.
- **`Aletheia`** — продвинутый стегоанализ F5.
- **Python-реализации** — для понимания и нестандартных параметров.

## Разобранный пример

```bash
$ stegdetect cover.jpg
cover.jpg: f5
$ java -jar F5.jar d -p hunter2 -c cover.jpg
extracted: secret.txt
$ cat secret.txt
flag{f5_matrix_coding}
```

Маршрут: `stegdetect` → F5 → `F5.jar d` с ключом. Ключ обычно в условии или метаданных.

## Частые ошибки и подводные камни

- **Применять `steghide`/`zsteg` к F5** — не сработает.
- **Не знать ключ** — F5 без ключа не извлекается.
- **Путать F5 с JSteg** — разные модели изменений.
- **Игнорировать `stegdetect`** — он подсказывает метод.
- **Забыть про второй слой** — после извлечения может быть шифрование.
- **Открыть и пересохранить JPEG** — данные погибнут.

## Итог

F5 — один из самых изящных JPEG-методов: он прячет данные в коэффициентах DCT, используя уменьшение значений и матричное кодирование `(n,k)`, что делает его устойчивым к хи-квадрату. В CTF F5-задачи решаются по цепочке «определить метод → взять ключ → извлечь `F5.jar`». Понимание F5 важно и для защиты: оно объясняет, почему классический стегоанализ ненадёжен.

## Расчёт ёмкости F5 и параметр k

Ёмкость F5 зависит от числа пригодных DCT-коэффициентов и параметра `k` матричного кода. При `(1, 2^k - 1)` группе из `2^k - 1` коэффициентов соответствует `k` бит. Чем больше `k`, тем меньше фактических изменений на бит, но тем длиннее нужны группы. Оптимальный `k` выбирается по ёмкости изображения.

Практически для извлечения нужно знать `k`: при неверном `k` данные декодируются в мусор. Стандартные реализации используют `k = 3` по умолчанию, но задачи могут менять его. Поэтому при неудаче переберите `k = 1..5`.

## Детекторы F5 и калибровочный стегоанализ

F5 устойчив к хи-квадрату, но не абсолютен. Детекторы используют:

- **калибровку**: перекодируют/обрезают изображение, получают эталонную гистограмму, сравнивают с фактической;
- **анализ «двойных» значений** коэффициентов (артефакт уменьшения);
- **оценку длины сообщения** через подгонку модели.

Инструмент **Aletheia** реализует ряд таких тестов. В CTF это полезно, чтобы подтвердить F5, когда `stegdetect` не уверен.

## Практика: F5 и шифрование

F5 часто комбинируют с шифрованием: сначала данные шифруются, потом встраиваются. Тогда после извлечения вы получаете «случайный» блоб, который нужно расшифровать (ключ может совпадать с ключом F5 или быть отдельным). Признак: извлечённый поток имеет высокую энтропию и не является текстом.

```bash
java -jar F5.jar d -p key -c stego.jpg
file extracted.bin        # data → возможно шифртекст
```

Дальше — определить тип (XOR, AES, RC4) и найти ключ.

## Практический чек-лист F5-задачи

1. `stegdetect` — подтвердить F5 (или `Aletheia`).
2. Собрать возможные ключи: пустой, из условия, метаданных, имени файла.
3. Извлечь `F5.jar d`; при мусоре перебрать `k`.
4. Извлечённое — проверить `file`; при «data» снять шифрование.
5. Ничего — рассмотреть OutGuess/JSteg и структурные каналы.

## F5: подробнее о матричном кодировании

Матричное кодирование `(1, 2^k - 1)` — сердце F5. Группа из `2^k - 1` коэффициентов несёт `k` бит. Код строится так, что при несовпадении меняется ровно один коэффициент (на 1 вниз), а при совпадении — ничего. Средняя плотность изменений — `1/(2^k + 1)` от числа коэффициентов. Для `k = 3` группа из 7 коэффициентов несёт 3 бита, а меняется в среднем 1 из 8 коэффициентов. Это в разы эффективнее JSteg (1 изменение на 1 бит).

Практический вывод: F5 меняет **минимум** коэффициентов, поэтому статистический след слаб, и хи-квадрат его не видит. Но для извлечения нужно точно знать `k` (обычно 3) и ключ.

## Детекторы F5 и калибровка

Калибровочный стегоанализ работает так: изображение декодируется, немного обрезается/перекодируется, из «эталона» строится ожидаемая статистика, и она сравнивается с фактической. F5 оставляет специфический артефакт в распределении коэффициентов, который калибровка выявляет. Инструмент `Aletheia` реализует такие тесты. В CTF детект реже нужен, чем извлечение, но полезен для подтверждения метода, когда `stegdetect` не уверен.

## F5 в комбинации с шифрованием

Часто данные сначала шифруют, затем встраивают F5. Тогда извлечённый поток — «случайный» блоб. Действия: извлечь (`F5.jar d`), проверить `file` (вероятно `data`), определить тип шифрования (XOR-ключ, AES, RC4) и найти ключ. Ключ F5 и ключ шифрования могут совпадать или различаться.

## Практический чек-лист F5

1. `stegdetect`/`Aletheia` — подтвердить F5.
2. Собрать ключи: пустой, из условия, метаданных, имени файла.
3. `F5.jar d -p <key>`; при мусоре перебрать `k = 1..5`.
4. Извлечённое — `file`; при `data` снять шифрование.
5. Ничего — OutGuess/JSteg и структурные каналы JPEG.

## Что делать дальше / решение

- `stegdetect` — определить F5.
- Найти ключ (условие, метаданные, короткие варианты).
- Извлечь через `F5.jar d` / `f5_extract`.
- Данные «случайные» — снять шифрование/XOR.
- Нет ключа — рассмотреть `Aletheia` и калибровочный стегоанализ.
