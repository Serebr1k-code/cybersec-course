## Вопрос, с которого всё начинается

На CTF тебе дали аудиофайл `sound.wav`. Слушаешь — обычный шум или короткая мелодия. Но флаг где-то внутри. Как искать данные в звуке, если «посмотреть» его глазами нельзя?

Аудио — удобный носитель для стеганографии: в одной секунде записи десятки тысяч чисел (сэмплов), и в младших битах каждого можно спрятать данные, не испортив звук для уха. В этом уроке мы разберём один WAV-файл по шагам и вытащим из него скрытое.

## Наш пример: файл sound.wav

Работаем с одним объектом — `sound.wav`. Дальше — цепочка вопросов, каждый из которых рождается из ответа на предыдущий. Это универсальный маршрут разбора любого аудиофайла.

Первый вопрос: **что это за файл и как он устроен?**

## Шаг 1: определяем формат и параметры

Утилита `file` смотрит на заголовок файла:

```
$ file sound.wav
sound.wav: RIFF (little-endian) data, WAVE audio, Microsoft PCM, 16 bit, mono 44100 Hz
```

Читаем: это WAV, несжатый PCM, 16 бит на сэмпл, один канал (моно), частота дискретизации 44100 Гц. Для нас важны два числа: **16 бит** и **PCM**. Это значит, что каждый сэмпл — целое число от −32768 до 32767, и его младший бит почти не влияет на звук.

Больше деталей даёт `soxi` — утилита из пакета `sox`:

```
$ soxi sound.wav
Input File     : 'sound.wav'
Channels       : 1
Sample Rate    : 44100
Precision      : 16-bit
Duration       : 00:00:12.34
File Size      : 1.09M
Bit Rate       : 706k
Sample Encoding: 16-bit Signed Integer PCM
```

Теперь мы знаем: 12 секунд, моно, 16 бит. Следующий вопрос: **нет ли в звуке чего-то, что видно глазами?**

## Шаг 2: слушаем и строим спектрограмму

Первое — просто прослушать файл. Иногда скрытое слышно: писк, морзянка, едва различимый голос. Если ничего не слышно, строим **спектрограмму** — картинку, где по горизонтали время, по вертикали частота, а яркость показывает громкость.

```
$ sox sound.wav -n spectrogram -o spectrogram.png
```

Открываем `spectrogram.png`. На ней часто проступают буквы, цифры или рисунок — данные, спрятанные в определённых частотах. Это самый частый трюк в аудиостеганографии: визуальное сообщение, невидимое на слух.

Если на спектре пусто, идём глубже — в сами сэмплы.

## Шаг 3: LSB в сэмплах

**LSB** (Least Significant Bit — младший бит) — это способ прятать данные в младшем бите каждого числа. Изменение младшего бита сдвигает громкость сэмпла на 1/32768 — ухо этого не замечает, а данные уже внутри.

Извлечь их можно скриптом на Python. Читаем байты после 44-байтового заголовка WAV и собираем младшие биты:

```python
import wave
w = wave.open("sound.wav", "rb")
frames = w.readframes(w.getnframes())
bits = ""
for b in frames:
    bits += str(b & 1)
# собираем биты в байты
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits), 8))
print(data[:64])
```

Если данные лежат в LSB, на выходе появится читаемый текст или заголовок файла (например, `PK` от ZIP). Порядок бит и каналов подбирают перебором — как в `zsteg` для картинок.

## Шаг 4: готовые инструменты

Писать скрипты не всегда нужно — есть инструменты:

- **steghide** — умеет WAV, AU, JPEG, BMP; требует пароль (если задан).
- **DeepSound** — Windows-инструмент для аудиостеганографии.
- **wav2png** — превращает WAV в картинку, где видно структуру сэмплов.
- **Audacity** — редактор, в котором вручную смотрят и правят сэмплы.

Пример с `steghide`:

```
$ steghide extract -sf sound.wav
Enter passphrase:
wrote extracted data to "secret.txt".
```

Если пароль не задан, `steghide` достанет данные сразу; если задан — придётся его подобрать (об этом в уроке про `stegseek`).

## Шаг 5: почему аудио удобно для сокрытия

Ёмкость аудио велика. В 12-секундном файле 44100 × 12 = 529 200 сэмплов; по одному биту на сэмпл это ~66 КБ скрытых данных — целый документ. Именно поэтому аудио любят для сокрытия файлов, а не коротких сообщений.

Важно помнить: если данные зашифрованы или сжаты, без ключа их не достать — но **след** (аномальный младший бит, лишний размер) остаётся, и его можно найти.

## Структура WAV

WAV — контейнер формата RIFF, состоит из чанков:

| Чанк | Смещение | Что хранит |
|------|----------|------------|
| `RIFF` | 0 | тип файла и общий размер |
| `fmt ` | 12 | каналы, частота, битность |
| `data` | 36–44 | сами сэмплы |
| `LIST` / `INFO` | после `data` | метаданные (автор, программа) |

Заголовок занимает первые 44 байта — поэтому скрипт их пропускает и читает только `data`. Если есть чанк `LIST`, там могут лежать метаданные — проверьте и их.

## Обзор инструментов

| Инструмент | Назначение |
|------------|------------|
| `file` | определить формат |
| `soxi` / `sox` | параметры и спектрограмма |
| `ffmpeg` | конвертация, извлечение каналов |
| `steghide` | извлечение из WAV/AU |
| DeepSound | аудиостеганография (Windows) |
| `wav2png` | WAV → картинка |
| Audacity | ручная работа с сэмплами |
| `sonic-visualiser` | детальный анализ спектра |

## Частые сценарии и что делать

- **Ничего не слышно, спектр пуст.** Проверьте LSB скриптом, переберите порядок бит.
- **`steghide` просит пароль.** Попробуйте пустой, имя файла, `password`.
- **Файл подозрительно большой.** Возможно, данные добавлены в конец — проверьте `binwalk`.
- **Многоканальный файл.** Данные могут быть только в одном канале — разделите `ffmpeg`.

## Что делать после извлечения

Если на выходе текст — это флаг или подсказка. Если заголовок файла (`PK`, `\x89PNG`) — сохраните байты как файл и откройте подходящей программой. Если мусор — порядок бит или канал выбраны неверно: вернитесь к шагу 3 и переберите варианты. Не удаляйте «мусорный» вывод — иногда данные портит один лишний сдвиг, и дальше они читаются.

## Что мы теперь знаем

По-простому:

1. WAV — это набор чисел-сэмплов с заголовком; `file` и `soxi` показывают параметры.
2. Спектрограмма может показать скрытый рисунок или текст.
3. LSB прячет данные в младшем бите каждого сэмпла.
4. Извлекают их скриптом или инструментами `steghide`, DeepSound.
5. Аудио даёт большую ёмкость для сокрытия.

## На что смотреть дальше

- **Сначала слушайте.** Иногда скрытое слышно без инструментов.
- **Стройте спектрограмму.** Это самый быстрый способ найти визуальное сообщение.
- **Пробуйте разные порядки бит.** Если LSB-скрипт дал мусор — меняйте порядок и каналы.
- **Проверяйте пароль.** `steghide` часто просит ключ — попробуйте пустой и типовые.
