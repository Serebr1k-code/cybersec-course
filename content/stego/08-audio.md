## Структура WAV: почему аудио удобно для LSB

WAV — несжатый контейнер PCM-аудио. Заголовок `RIFF`/`WAVE` описывает формат, за ним идут чанки `fmt ` (параметры) и `data` (сэмплы). Сэмплы хранятся как целые числа (8/16/24/32 бита), и младший бит каждого сэмпла почти не влияет на звук — его изменение неслышно. Это и есть основа аудио-LSB.

```bash
$ file song.wav
song.wav: RIFF (little-endian) data, WAVE audio, Microsoft PCM, 16 bit, mono 44100 Hz
$ xxd song.wav | head -3
00000000: 5249 4646 24f0 0100 5741 5645 666d 7420  RIFF$...WAVEfmt
```

Ёмкость WAV огромна: файл 44.1 кГц, 16 бит, стерео за минуту содержит ~10 МБ сэмплов, то есть ~1.3 МБ скрытых данных при LSB. Поэтому в аудио прячут не только флаги, но и целые архивы.

## LSB в сэмплах: как это работает

Каждый сэмпл — число; его младший бит заменяется битом сообщения. Порядок обхода: по сэмплам слева направо, по каналам (L/R), иногда по байтам (little-endian). Возможные вариации: 1–4 младших бита, MSB-режим, разные комбинации каналов.

Схема кодирования:

```python
import wave, struct
w = wave.open('out.wav', 'rb')
n = w.getnframes(); sw = w.getsampwidth()
raw = w.readframes(n)
samples = list(struct.unpack('<%dh' % (len(raw)//2), raw))  # 16-bit
msg = b'flag{audio_lsb}'
bits = ''.join(f'{b:08b}' for b in msg)
for i, bit in enumerate(bits):
    samples[i] = (samples[i] & ~1) | int(bit)
```

Извлечение — обратная операция: собрать младшие биты и склеить в байты.

## Извлечение вручную (Python)

```python
import wave, struct
w = wave.open('suspicious.wav', 'rb')
raw = w.readframes(w.getnframes())
samples = struct.unpack('<%dh' % (len(raw)//2), raw)
bits = ''.join(str(s & 1) for s in samples)
out = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
print(out[:128])
```

Если результат — мусор, переберите варианты: MSB вместо LSB, 2–4 бита, порядок каналов (стерео чередуется L/R), big-endian. Часто первый байт сигнатуры (`PK`, `\x89PNG`, `MZ`, `flag{`) сразу подсказывает, что порядок верный.

## Инструменты: steghide, DeepSound, wav2png

- **`steghide`** — работает и с WAV (формат AU/WAV), парольная стеганография: `steghide extract -sf song.wav`.
- **`stegseek`** — быстрый брут пароля для `steghide`.
- **DeepSound** — Windows-инструмент (популярен в CTF): прячет файлы в WAV/MP3, может требовать пароль.
- **`wav2png` / `sox`** — визуализация; спектрограмма часто раскрывает данные (см. урок про спектрограмму).
- **`multimon-ng`** — DTMF/морзе/FSK-декодирование.
- **`audacity`** — ручной просмотр волновой формы и спектра.

```bash
steghide extract -sf song.wav           # запросит пароль
stegseek song.wav rockyou.txt           # брут пароля
sox song.wav -n spectrogram -o spec.png # спектрограмма
```

## Метаданные аудио

Прежде чем лезть в сэмплы, проверьте метаданные: теги ID3 (MP3), комментарии RIFF (WAV), поля `LIST`/`INFO`.

```bash
$ exiftool song.mp3
Title   : Song
Comment : ZmxhZ3tpZDNfdGFnfQ==
$ strings -n 8 song.wav | grep -iE 'flag|http|base64'
```

Флаг или пароль часто лежит в `Comment`, `Album`, `TXXX`-фрейме или в `LIST INFO`-чанке WAV.

## Разобранный пример: от WAV до флага

```bash
$ file challenge.wav
challenge.wav: RIFF (little-endian) data, WAVE audio, 16 bit, stereo 44100 Hz
$ strings challenge.wav | grep -i flag
$ python3 extract_lsb.py challenge.wav
b'flag{w4v_lsb_st3r30}'
$ sox challenge.wav -n spectrogram -o spec.png   # на всякий случай
```

Маршрут: `strings`/`exiftool` → метаданные; скрипт LSB → данные; `sox`/спектрограмма → визуальные каналы. Если LSB пуст, а звук «странный» — смотрите спектрограмму (тональные сигналы, SSTV, DTMF).

## Ёмкость и незаметность

- **Ёмкость**: 1 бит на сэмпл. Для 16-бит стерео это ~1/16 от размера файла.
- **Незаметность**: LSB в младшем бите 16-битного сэмпла статистически малозаметен; в 8-битном — грубее.
- **Робастность**: нулевая к перекодированию (MP3-сжатие уничтожает LSB).

Поэтому WAV-LSB — «дешёвый» метод для передачи по каналу без перекодирования. В CTF это самый частый аудио-сценарий.

## Частые ошибки и подводные камни

- **Открыть в редакторе и пересохранить** — LSB и метаданные погибнут.
- **Не учесть число каналов/разрядность** — порядок байт и L/R меняют результат.
- **Искать только текст** — данные могут быть вложенным файлом (проверяйте `file`).
- **Игнорировать спектрограмму** — часть задач решается только визуально.
- **Забыть про метаданные** — флаг может быть в ID3-теге.
- **Пробовать только LSB-1** — бывает 2–4 бита и MSB.

## Расширенный разбор: стерео, разрядность, порядок байт

Главные вариации, из-за которых LSB-извлечение даёт «мусор»:

- **Разрядность**: 8/16/24/32 бита. Для 16+ бит важен порядок байт (обычно little-endian).
- **Каналы**: моно — линейно; стерео — чередование L,R (иногда только L или только R).
- **Число младших бит**: 1, 2 или 4.
- **Порядок бит внутри байта**: MSB-first или LSB-first.
- **Signed/unsigned** и **смещение** (у 8-бит WAV часто unsigned с центром 128).

Универсальный переборный скрипт (по всем вариантам) экономит время:

```python
import wave, struct, itertools
w = wave.open('x.wav','rb')
raw = w.readframes(w.getnframes())
sw = w.getsampwidth(); ch = w.getnchannels()
def samples(sw):
    fmt = {1:'B',2:'h',4:'i'}[sw]
    return struct.unpack('<%d%s' % (len(raw)//sw, fmt), raw)
for sw_try in (2,1,4):
    try: s = samples(sw_try)
    except: continue
    for nbits in (1,2,4):
        bits = ''.join(format(v & ((1<<nbits)-1), '0%db'%nbits) for v in s)
        for rev in (False,True):
            b = bits[::-1] if rev else bits
            out = bytes(int(b[i:i+8],2) for i in range(0,len(b)-7,8))
            if b'flag' in out[:200] or out[:2] in (b'PK',b'MZ'):
                print('HIT', sw_try, nbits, rev, out[:32])
```

## Инструменты глубоко: steghide, stegseek, DeepSound, sonic-visualiser

- **`steghide`**: `steghide embed -cf song.wav -ef secret.txt -p pass`; извлечение — `steghide extract -sf song.wav`. Пароль можно не указывать (тогда пустой), но обычно есть.
- **`stegseek`**: `stegseek song.wav rockyou.txt` — перебирает пароли к `steghide`-контейнеру, десятки тысяч в секунду.
- **DeepSound**: GUI, прячет файлы в WAV/MP3, часто используется авторами CTF; поддерживает пароль и шифрование.
- **`sonic-visualiser`**: профессиональная визуализация, спектрограмма высокого разрешения.
- **`sox`**: `sox song.wav -n spectrogram -o spec.png` — быстрая спектрограмма.
- **`multimon-ng`**: декодирование DTMF/морзе/FSK прямо из WAV.

Порядок применения: сначала `strings`/`exiftool` (метаданные), затем LSB-скрипт, затем `steghide`/`stegseek`, затем визуализация.

## Спектрограмма и визуальные каналы в аудио

Спектрограмма — преобразование Фурье по окнам, дающее картинку «частота × время». Данные часто прячут как **видимый рисунок** в верхних частотах: текст, QR-код, схема.

```bash
sox song.wav -n spectrogram -o spec.png
# открыть spec.png глазами; если виден текст — это канал
```

Если на спектрограмме виден текст — считайте его напрямую или через OCR. Если видны тональные «точки» — это DTMF/морзе/FSK, декодируйте `multimon-ng`.

## Ёмкость и практические оценки

Для WAV 16 бит стерео 44.1 кГц: за секунду ~176400 сэмплов → ~22 КБ скрытых данных при 1 бите. Минута — ~1.3 МБ. Это очень много, поэтому в аудио прячут и целые ZIP-архивы. Проверяйте результат `file` — если после извлечения получается `Zip archive`, распакуйте его.

Важное следствие: если «аудио-задача» явно рассчитана на большой payload, LSB — почти всегда правильный канал. Если payload мал (флаг) — возможна спектрограмма или `steghide`.

## Мини-чек-лист аудио-задачи

1. `file` — формат, разрядность, каналы, частота.
2. `exiftool` + `strings` — метаданные (ID3, RIFF INFO, комментарии).
3. LSB-скрипт с перебором: разрядность, каналы, число бит, порядок.
4. Проверьте сигнатуры результата (`flag`, `PK`, `MZ`, `\x89PNG`).
5. `steghide extract` / `stegseek` — если есть намёк на пароль.
6. `sox ... spectrogram` — визуальные каналы (текст, QR на спектре).
7. `multimon-ng` — DTMF/морзе/FSK, если слышны тональные сигналы.
8. Данные — вложенный файл: `file` → распаковка/`binwalk`.

## Итог по базовой аудиостеганографии

Аудио — самый «ёмкий» из популярных носителей: один WAV легко вмещает мегабайты. Поэтому аудио-LSB — идеальный канал для передачи целых архивов, а не только флагов. Основная сложность — вариативность (разрядность, каналы, порядок бит), из-за которой извлечение «с первого раза» часто даёт мусор. Универсальный переборный скрипт и проверка сигнатур результата решают эту проблему надёжно. Если же LSB-канал пуст, не забывайте про метаданные и визуальные каналы: спектрограмма и `steghide`/`stegseek` покрывают оставшиеся сценарии.

## Что делать дальше / решение

- `exiftool` + `strings` — метаданные и быстрые подсказки.
- Скрипт LSB-1 (порядок: сэмплы, каналы) → проверьте сигнатуры.
- Мусор — переберите биты/порядок; затем `steghide`/`stegseek`/DeepSound.
- Пусто — `sox` спектрограмма, `multimon-ng` для сигналов.
- Данные — вложенный файл → `file`/`binwalk`/распаковка.
