## Вопрос, с которого всё начинается
Бывает, что один слой — не предел: base64, внутри gzip, внутри снова base64.
Каждый слой выглядит безобидно, а вместе они прячут сообщение. Разматывать
вложенные слои нужно системно: определить, снять, повторить. Этот урок — про
многослойную стеганографию и как её не потерять.

## Наш пример
Возьмём `layers.txt` — текст. Размотаем его слой за слоем до метки.

## Шаг 1: как выглядит многослойность
Слои бывают разного рода:
- **кодирования** (base64/hex/base32),
- **сжатия** (gzip/zlib/bzip2),
- **шифры** (XOR/ROT),
- **контейнеры** (ZIP/PNG с вложенным файлом),
- **стего** (LSB, appended).

Часто они чередуются: кодирование → сжатие → кодирование → стего.

## Шаг 2: правило «один слой за раз»
После снятия слоя всегда заново определяй результат:
```
$ cat layers.txt | head -c 40
H4sIAAAAAA...
$ base64 -d layers.txt | file -
/dev/stdin: gzip compressed data
$ base64 -d layers.txt | gunzip | head -c 40
bnRve211...
$ base64 -d layers.txt | gunzip | base64 -d
nto{multi_layer_nested}
```

Ключ — проверять `file`/`head` после каждого шага и не «прыгать» на два слоя
сразу.

## Шаг 3: автоматизация разматывания
```python
import base64, gzip
d = open('layers.txt','rb').read()
step1 = base64.b64decode(d)          # base64
step2 = gzip.decompress(step1)       # gzip
step3 = base64.b64decode(step2)      # base64
print(step3.decode())
```

Вывод:

```
nto{multi_layer_nested}
```

## Шаг 4: как понять, что слой снят правильно
- Результат начинается с читаемых ASCII или с известной магии (`\x1f\x8b`, `PK`,
  `\x89PNG`).
- Длина «правдоподобна» (не мусор, не нули).
- Энтропия: сжатые данные ≈ максимальная; текст — низкая.

## Шаг 5: где ломаются многослойные задачи
- **Неверный порядок.** Сначала снять внешний слой, потом внутренний.
- **Потеря промежуточного результата.** Всегда сохраняй каждый шаг в файл.
- **Пропущенный слой.** Проверяй метаданные и хвост на каждом уровне.
- **Ловушка-приманка.** Внутри может быть «фальшивый флаг» — проверяй формат.

## Шаг 6: инструменты
- `file`, `head`, `xxd` — на каждом шаге.
- CyberChef Magic — автоматическая размотка.
- binwalk `-M` — рекурсивная распаковка контейнеров.
- `zsteg`, `steghide` — если слой оказался изображением/аудио.

## Полный пример: три слоя за один файл

Размотаем учебный пример. Дано: `data.txt`, содержимое — длинная строка из символов `A`/`B`. Слой первый — кодирование: `A`/`B` — это биты (0/1). Собираем их в байты.

```python
s = open("data.txt").read().strip()
bits = "".join("0" if c == "A" else "1" for c in s)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits), 8))
open("layer1.bin", "wb").write(data)
```

Слой второй — контейнер: `file layer1.bin` показывает «gzip compressed data». Распаковываем: `gunzip -c layer1.bin > layer2.bin`. Слой третий — текст: в `layer2.bin` оказывается base64-строка, декодируем — получаем флаг. Итог: биты → gzip → base64 → флаг. Каждый шаг менял формат, и именно поэтому важно проверять результат после каждого слоя, а не пытаться угадать финальный.

## Автоматизация размотки

Когда слоёв много, помогает полуавтоматизация. Скрипт, который на каждом шаге определяет формат и применяет подходящий декодер:

```python
import subprocess, base64
data = open("layer1.bin","rb").read()
while True:
    out = subprocess.run(["file","-b","-"], input=data, capture_output=True).stdout
    if b"gzip" in out:   data = subprocess.run(["gunzip","-c"], input=data, capture_output=True).stdout
    elif b"Zip" in out:  # распаковать и взять первый файл
        ...
    elif b"ASCII" in out and b"nto{" in data: break
    else: break
print(data)
```

Важно: автоматизация не отменяет проверку. На каждом шаге печатай формат и размер — так ты видишь, где размотка пошла не туда. И не забывай про лимит итераций: бесконечный цикл на самовоспроизводящемся слое останови счётчиком.

## Когда многослойная задача ломается

Типичные причины. Первая — неправильная граница слоя: например, ты вырезал SquashFS по смещению, но не до конца, и распаковка даёт битый результат. Лечится сверкой смещения и размера из `binwalk`. Вторая — нестандартный формат: `binwalk` не нашёл сигнатуру, но данные есть; тогда режь вручную и пробуй `file`/`7z`/`unzip` по очереди. Третья — шифрование на одном из слоёв: если после распаковки энтропия высокая, а `file` не определяет формат, возможно, нужен ключ (часто он лежит в предыдущем слое).

Четвёртая — потеря порядка: если слои можно снимать в разном порядке, но правильный только один, экспериментируй системно и записывай. Пятая — «ложный слой»: иногда `strings` показывает base64, который декодируется в мусор — это приманка. Проверяй осмысленность результата (текст, сигнатура формата) перед тем, как идти дальше.

## Практика: как не потерять нить в многослойной задаче

Многослойная стего требует дисциплины. Первое правило — «один слой за раз»: снял слой, сохрани результат отдельным файлом, проверь формат, и только потом переходи дальше. Если смешать шаги, ошибку не локализуешь. Второе — именование: `layer1.bin`, `layer2.gz`, `layer3.txt` — по имени видно, что и в каком порядке.

Третье — фиксация границ: при вырезании по offset всегда записывай `skip` и `count` (например, `dd bs=1 skip=1024 count=4096`), чтобы воспроизвести шаг. Четвёртое — проверка контрольных сумм: после распаковки сверь `sha256sum`, если эталон известен; при отсутствии эталона — проверь, что `file` определяет формат осмысленно. Пятое — счётчик итераций: автоматизированную размотку ограничивай (например, 10 слоями), иначе рискуешь зациклиться.

Шестое — не доверяй «магии»: если инструмент выдал «похоже на флаг», проверь структуру (формат `nto{...}`, длина, алфавит). Ложные срабатывания на многослойных задачах часты. Седьмое — держи под рукой декодеры всех типов (base64/base32/hex/rot13/morse) и проверяй их по очереди на каждом текстовом слое.

Примерный скелет автоматизации: цикл, который определяет формат (`file`), применяет соответствующий декодер, печатает «шаг N: формат X, размер Y» и останавливается, когда находит флаг или когда формат перестал распознаваться. Такой скрипт экономит время на рутинных слоях и оставляет тебе сложные.

## Разбор: где именно ломается размотка

Частая причина провала — неверная граница слоя. Если ты вырезал данные по offset, но не знаешь точную длину, возьми «с запасом» и передай распаковщику: он сам остановится на конце потока. Для `gzip` это `gunzip -c`, для `xz` — `xz -d`, для ZIP — `unzip` (игнорирует хвост). Так ты не потеряешь байты из-за неверного `count`.

```bash
dd if=file bs=1 skip=1024 | gunzip -c | file -
dd if=file bs=1 skip=1024 | xz -dc | head -c 64
```

Вторая причина — не тот декодер: строка может быть base32, а не base64. Проверяй алфавит: base64 использует `A-Za-z0-9+/=`, base32 — `A-Z2-7=`, hex — `0-9a-f`. Третья — двойное кодирование (base64 от base64): декодируй повторно, пока результат остаётся текстом в алфавите.

## Итог по многослойной стего

Многослойная стего — это последовательность преобразований, и успех зависит от дисциплины: один слой за раз, проверка формата после каждого шага, фиксация границ и имён файлов. Автоматизация ускоряет рутину, но требует ограничений и проверки осмысленности результата. Если застрял — вернись к началу, проверь, не пропустил ли базовый слой (overlay, `strings`, метаданные), и только потом усложняй.

## Расширенный практикум по размотке

Сценарий: флаг спрятан в цепочке «биты → XOR → base64 → gzip». Слой битов: строка из `0`/`1` собирается в байты. Слой XOR: результат XOR-ится с ключом (часто однобайтовым, который надо подобрать). Слой base64: декодируется в gzip. Слой gzip: распаковывается в текст с флагом.

```python
bits = "".join("0" if c=="A" else "1" for c in s)
data = bytes(int(bits[i:i+8],2) for i in range(0,len(bits),8))
data = bytes(b ^ 0x42 for b in data)          # XOR с ключом
import base64; data = base64.b64decode(data)  # base64
import gzip;  data = gzip.decompress(data)    # gzip
print(data)
```

Подбор XOR-ключа: перебери все 256 значений и на каждом шаге проверяй, похож ли результат на base64/gzip (сигнатура `\x1f\x8b`). Это быстро и автоматизируется.

Ключевой навык — распознавать формат по сигнатуре/алфавиту после каждого шага, а не угадывать. И вести журнал: какой слой, какой результат. Тогда цепочка из пяти шагов разматывается за минуты, а не превращается в перебор.

## Итог и переносимые приёмы

Приёмы многослойной стего переносимы: определение формата по сигнатуре, декодирование по алфавиту, распаковка по сигнатуре, подбор XOR-ключа по сигнатуре результата. Эти элементарные шаги комбинируются в цепочки любой длины.

Держи под рукой таблицу сигнатур: `PK` (ZIP), `\x1f\x8b` (gzip), `BZh` (bzip2), `\xfd7zXZ` (xz), `7z\xbc\xaf` (7z), `Rar!` (rar), `\x89PNG` (PNG), `\xff\xd8` (JPEG). По ним ты быстро понимаешь, что за слой перед тобой, даже если имя файла обманчиво.

И держи под рукой декодеры: base64/base32/base85/hex/rot13/morse. Большинство слоёв — это одна из этих кодировок плюс сжатие. Навык распознавания + дисциплина = решение многослойных задач.

- Правило: один слой за раз, проверка типа после каждого.
- Автоматизация — цикл «определи → сними → повтори».
- Приманки и порядок слоёв — главные ловушки.
