## Вопрос, с которого всё начинается

В задаче дан `bundle.js` — обычный минифицированный скрипт с сайта. Ты читаешь его глазами, ищешь `flag` — ничего. Открываешь в редакторе — всё выглядит как обычный код. Но подсказка говорит, что данные внутри. Как код может прятать данные, если визуально всё чисто?

Ответ: в **невидимых символах и структуре**. Исходный код большой, избыточный и редко проверяется построчно — идеальный носитель. Разберём это на нашем файле.

## Наш пример: bundle.js

Первое правило — **не форматируй файл до анализа**. Любой beautifier/prettier перепишет пробелы и уничтожит канал. Смотрим побайтово:

```bash
$ cat -A bundle.js | head -3
var x = 1;^I^I$
function f() {}$
```

`cat -A` показывает непечатаемые символы: `^I` — это таб, `$` — конец строки. В первой строке после `;` идут два таба — подозрительно.

## Шаг 1: whitespace-канал

Простейший и самый частый приём: **число пробелов или табов в конце строки кодирует символ**. Смешение табов и пробелов — это биты (tab=1, space=0). Считаем trailing-пробелы по строкам:

```python
lines = open("bundle.js", "rb").read().split(b"\n")
codes = [len(l) - len(l.rstrip(b" \t")) for l in lines]
print(bytes(c for c in codes if 0 < c < 256))
```

```bash
$ python3 ws.py
b'flag{code_whitespace}'
```

Инструмент `snow` делает то же самое для обычного текста:

```bash
snow -C -p "пароль" stego.txt          # извлечь
snow -C -m "секрет" cover.txt stego.txt  # спрятать
```

## Шаг 2: невидимые Unicode-символы

**Zero-width** символы не отображаются, но занимают место в байтах: `U+200B` (zero width space), `U+200C`, `U+200D`, `U+FEFF` (BOM). Два символа дают биты 0/1 — идеальный бинарный канал в тексте.

Найдём их:

```bash
$ grep -nP '[\x{200B}-\x{200F}\x{FEFF}]' bundle.js | head
12: var a\u200b=\u200c1;
```

Извлечём как биты:

```python
data = open("bundle.js", encoding="utf-8").read()
bits = "".join("1" if ch == "\u200b" else "0"
               for ch in data if ch in "\u200b\u200c")
bits = bits[: len(bits)//8*8]
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits), 8)))
```

```bash
$ python3 zw.py
b'flag{zero_width}'
```

## Шаг 3: комментарии и «мёртвый» код

Комментарии — классический тайник. В «пустом» комментарии часто лежит base64:

```bash
$ grep -nE '<!--|//' page.html | grep -iE 'flag|base64'
12: <!-- ZmxhZ3tjb2RlX2NvbW1lbnR9 -->
$ echo ZmxhZ3tjb2RlX2NvbW1lbnR9 | base64 -d
flag{code_comment}
```

Кроме комментариев, данные прячут в неиспользуемых импортах, отключённых блоках (`if False:`) и строках-константах, которые нигде не выводятся.

## Шаг 4: гомоглифы

**Гомоглифы** — символы разных алфавитов, выглядящие одинаково: латинская `a` и кириллическая `а`, латинская `o` и греческая `ο`. Код смешивает алфавиты, кодируя биты выбором символа.

```python
import unicodedata
for ch in "pаypal":        # одна буква кириллическая
    print(hex(ord(ch)), unicodedata.name(ch))
```

Визуально текст идентичен, но байты разные. Детект — проверка Unicode-блоков: если в «английском» слове встречаются кириллические или греческие буквы, это сигнал. Тот же приём используют в фишинговых доменах (IDN homograph attack).

## Шаг 5: CSS/HTML

Данные могут быть в вёрстке, а не в JS:

- **Порядок CSS-правил** и выбор селектора (`#id` vs `.class`) кодируют биты;
- **Значения свойств**, визуально эквивалентные (`margin: 4px` vs `4.0px`);
- **data-атрибуты** и неиспользуемые классы;
- **Цвета**: `#FFFFFF` vs `#ffffff` vs `rgb(255,255,255)`.

```bash
$ grep -oE 'data-[a-z]+="[^"]*"' page.html | head
data-hint="ZmxhZ3tjc3N9"
$ grep -oE '#[0-9a-fA-F]{6}' style.css | sort | uniq -c
```

## Шаг 6: автоматизация

Пайплайн для «кодовых» задач:

```python
import re
src = open("bundle.js", encoding="utf-8", errors="ignore").read()
zw = [ch for ch in src if ord(ch) in (0x200b, 0x200c, 0x200d, 0xfeff)]
b64 = re.findall(r"[A-Za-z0-9+/]{16,}={0,2}", src)
comments = re.findall(r"//(.*)|/\*(.*?)\*/", src, re.S)
print("zw:", len(zw), "b64:", b64[:3], "comments:", len(comments))
```

## Если не сработало

- **Форматировал файл до анализа** — prettier/beautifier уничтожает whitespace-канал.
- **Не заметил zero-width** — они невидимы, нужен `grep -P` или hex-взгляд.
- **Игнорировал комментарии** — «пустые» комментарии частый тайник.
- **Путал гомоглифы** — визуально одинаковые символы имеют разные коды.
- **Считал, что редактор покажет всё** — он скрывает невидимое.
- **Забыл про CSS/HTML** — данные могут быть в вёрстке.

## Порядок объявлений и имена

Ещё два тонких канала. **Порядок независимых объявлений** (функций, импортов, CSS-правил) можно переставлять, кодируя биты: получатель знает «правильный» порядок и читает перестановки. **Имена переменных** тоже несут информацию: выбор между синонимами (`count`/`total`) или между стилями (`snake_case`/`camelCase`) кодирует биты. Оба канала незаметны для чтения глазами, но исчезают при рефакторинге.

## Сравнение каналов в коде

| Канал | Ёмкость | Заметность | Стойкость к форматированию |
|---|---|---|---|
| Trailing whitespace | средняя | низкая | низкая (форматтеры чистят) |
| Комментарии | высокая | средняя | средняя |
| Zero-width Unicode | средняя | очень низкая | низкая (нормализация) |
| Порядок объявлений | средняя | низкая | средняя |
| Имена переменных | низкая | средняя | средняя |
| CSS-значения | средняя | очень низкая | низкая |

## Ограничения и предостережения

- **Форматтеры чистят whitespace** — никогда не прогоняй файл через prettier до анализа.
- **Нормализация Unicode** может удалить невидимые символы.
- **Минификация** сжимает whitespace-канал.
- **Контроль версий** (git) может показать различия, выдав канал — или, наоборот, скрыть его при `git diff --ignore-all-space`.

## Практика: находим канал «под микроскопом»

Прежде чем писать парсер, посмотри на файл в хексе — невидимые символы сразу выдают себя байтами. Возьмём тот самый `bundle.js` с zero-width каналом:

```bash
$ xxd bundle.js | head -2
00000000: 636f 6e73 7420 613d 313b 202f 2fe2 808c  const a=1; //...
00000010: e280 8be2 808b e280 8ce2 808c e280 8be2  ................
```

Пара `e2 80 8b` — это UTF-8-кодировка символа `U+200B` (zero width space), а `e2 80 8c` — `U+200C`. Глазами в редакторе их не видно, но в хексе они стоят там, где «ничего нет». Быстрая проверка одной строкой:

```bash
$ grep -cP '\x{200b}|\x{200c}' bundle.js
24
```

Если счётчик не ноль — в файле есть невидимые символы, и это почти наверняка канал. А на репозитории с `git` канал в пробелах выдаёт себя так: `git diff --ignore-all-space` показывает «пустые» изменения — значит, данные живут именно в whitespace.

## Полный прогон: прячем и достаём сообщение

Раз мы знаем каналы, соберём минимальную рабочую пару «спрятать → достать» на zero-width символах. Идея простая: бит `0` — это `U+200B`, бит `1` — `U+200C`. Получателю нужен только файл, никакого ключа.

```python
ZW0, ZW1 = "\u200b", "\u200c"
def hide(text, msg):
    bits = ''.join(f'{b:08b}' for b in msg)
    return text + ''.join(ZW1 if c == '1' else ZW0 for c in bits)
def reveal(text):
    z = ''.join('1' if c == ZW1 else '0' for c in text if c in (ZW0, ZW1))
    return bytes(int(z[i:i+8], 2) for i in range(0, len(z)//8*8, 8))

src = "function add(a,b){ return a+b } // total 42"
stego = hide(src, b"flag{zw_sp}")
print(reveal(stego))
```

```text
b'flag{zw_sp}'
```

Файл выглядит как обычная функция `add`, но в конце строки — 88 невидимых символов. Именно поэтому проверка `grep -cP '\x{200b}|\x{200c}'` обязательна: глазами и обычным `diff` этот канал не виден.

Whitespace-канал устроен так же, только вместо невидимых символов — пробел (бит 0) и таб (бит 1) в конце строки. В хексе это видно как чередование `20` и `09`:

```bash
$ xxd bundle_ws.js | tail -2
00000010: 2079 3d32 3b0a 2009 2020 2020 0909 2009   y=2;. .    .. .
00000020: 2009 2009 2020 2009 2020 2009 0920 0a     . .   .   .. .
```

Достаются эти биты тем же приёмом: `'0' if c == ' ' else '1'`, затем сборка по восемь бит в байт. Обрати внимание — обе пары симметричны: `hide` дописывает биты в конец, `reveal` их фильтрует и склеивает. Это и есть весь «протокол» таких каналов.

## Что мы теперь знаем

1. Код — избыточный носитель, который редко проверяют построчно.
2. **Whitespace** (trailing-пробелы, tab vs space) кодирует символы.
3. **Zero-width Unicode** — невидимый бинарный канал в тексте.
4. **Комментарии** и «мёртвый» код — классический тайник (base64).
5. **Гомоглифы** и CSS-значения — тонкие каналы в разметке.
