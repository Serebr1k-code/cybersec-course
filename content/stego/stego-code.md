Исходный код — почти идеальный носитель: он большой, избыточный и редко проверяется построчно. Данные можно спрятать в пробелах, в «пустых» комментариях, в порядке объявлений, в именах переменных и даже в невидимых Unicode-символах, которые не отображаются в редакторе. Для CTF это частая категория, а для supply-chain-атак — реальный способ протащить полезную нагрузку мимо ревью.

## Где именно прячут данные

- **Пробелы и табы.** Смешанные отступы (tab vs space), trailing whitespace, число пробелов кодируют биты.
- **Переводы строк.** CRLF/LF, лишние пустые строки.
- **Комментарии.** В «пустом» комментарии может быть base64 или шифротекст.
- **Порядок сущностей.** Перестановка независимых объявлений/функций кодирует данные.
- **Имена переменных.** Выбор между синонимами (`count`/`total`) или стиль именования кодирует биты.
- **Невидимые Unicode.** Zero-width space (`U+200B`), zero-width joiner (`U+200D`), `U+FEFF` — идеальный бинарный канал в тексте.
- **Гомоглифы.** Похожие по начертанию символы (кириллическая `а` vs латинская `a`) кодируют биты.
- **CSS/HTML.** Значения свойств, порядок правил, классы, data-атрибуты.

## Инструменты и команды

- **`grep`/`rg`** — поиск невидимых символов и аномалий.
- **`xxd`/`hexdump`** — байтовый взгляд на whitespace.
- **`cat -A`** — показать табы/переводы строк как `^I`, `$`.
- **`whitespace`/`snow`** — специализированные whitespace-стегосистемы.
- **`unicode`-скрипты** — детект zero-width и гомоглифов.
- **`js-beautify`** — нормализация, после которой аномалии видны.

Показать непечатаемые символы:

```bash
$ cat -A script.js | head
var x = 1;^I^I^I$
function f() {}$
```

Найти zero-width символы:

```bash
$ grep -nP '[\x{200B}-\x{200F}\x{FEFF}]' file.js
```

Извлечь их как биты:

```python
data = open("file.js", encoding="utf-8").read()
bits = "".join("1" if ch == "\u200b" else "0"
               for ch in data if ch in "\u200b\u200c")
bits = bits[: len(bits)//8*8]
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits), 8)))
```

## Разобранный пример: base64 в комментарии

```bash
$ grep -nE '^\s*//|/\*|<!--' page.html | head
12: <!-- ZmxhZ3tjb2RlX2NvbW1lbnR9 -->
$ echo ZmxhZ3tjb2RlX2NvbW1lbnR9 | base64 -d
flag{code_comment}
```

## Whitespace-стегосистемы

Инструменты `snow` (для текста) и SNOW-подобные схемы прячут данные в концевых пробелах строк: каждый символ кодируется числом пробелов. Считывание — обратный процесс.

```bash
snow -C -p "пароль" stego.txt     # извлечь
snow -C -m "секрет" cover.txt stego.txt  # спрятать
```

В коде тот же принцип: число trailing-пробелов каждой строки = код символа.

```python
lines = open("code.c", "rb").read().split(b"\n")
codes = [len(l) - len(l.rstrip(b" \t")) for l in lines]
print(bytes(c for c in codes if 0 < c < 256))
```

## CSS/HTML как канал

- **Порядок CSS-правил** и выбор селекторов (`#id` vs `.class`) кодируют биты.
- **Значения свойств**: `margin: 4px` vs `margin: 5px` при визуально равном результате.
- **data-атрибуты** и неиспользуемые классы.
- **HTML-комментарии** и лишние атрибуты.

```bash
grep -oE 'data-[a-z]+="[^"]*"' page.html | head
grep -nE '<!--.*-->' page.html | grep -iE 'flag|base64'
```

## Сравнение каналов в коде

| Канал | Ёмкость | Заметность | Стойкость к форматированию |
|---|---|---|---|
| Trailing whitespace | средняя | низкая | низкая (форматтеры чистят) |
| Комментарии | высокая | средняя | средняя |
| Zero-width Unicode | средняя | очень низкая | низкая (нормализация) |
| Порядок объявлений | средняя | низкая | средняя |
| Имена переменных | низкая | средняя | средняя |
| CSS-значения | средняя | очень низкая | низкая |

## Частые ошибки и подводные камни

- **Форматировать файл до анализа.** Prettier/beautifier уничтожает whitespace-канал.
- **Не заметить zero-width.** Они невидимы; нужен `grep -P` или hex-взгляд.
- **Игнорировать комментарии.** «Пустые» комментарии — частый тайник.
- **Путать гомоглифы.** Визуально одинаковые символы — разные коды.
- **Считать, что текстовый редактор покажет всё.** Он скрывает невидимое.
- **Забыть про CSS/HTML.** Данные могут быть в вёрстке, а не в JS.

## Что дальше / решение

- Посмотрите файл побайтово (`cat -A`, `xxd`), не форматируйте.
- Ищите zero-width и гомоглифы (`grep -P`).
- Проверьте комментарии и data-атрибуты на base64.
- Проверьте trailing-whitespace по строкам (число пробелов).
- Если пусто — переходите к классическим текстовым каналам (`stego-text-linguistic`) и null-шифру (`stego-null-cipher`).

## Невидимые Unicode-символы детально

Zero-width и управляющие символы — идеальный бинарный канал в тексте, потому что их не видно и они редко нормализуются:

- `U+200B` ZERO WIDTH SPACE
- `U+200C` ZERO WIDTH NON-JOINER
- `U+200D` ZERO WIDTH JOINER
- `U+2060` WORD JOINER
- `U+FEFF` ZERO WIDTH NO-BREAK SPACE (BOM)

Два символа дают биты 0/1, набор из четырёх — по 2 бита. Детект — только через hex или regex по кодовым точкам.

```bash
grep -aoP '[\x{200B}-\x{200F}\x{FEFF}\x{2060}]' file.txt | sort | uniq -c
```

```python
import collections
data = open("file.txt", encoding="utf-8").read()
print(collections.Counter(ch for ch in data if ord(ch) > 0x2000))
```

## Гомоглифы и их кодирование

Гомоглифы — символы разных алфавитов, выглядящие одинаково: латинская `a` и кириллическая `а`, греческая `ο` и латинская `o`. Код может смешивать алфавиты, кодируя биты выбором символа. Визуально текст идентичен, но байты разные. Детект — проверка Unicode-блоков: если в «английском» слове встречаются кириллические/греческие буквы, это сигнал.

```python
import unicodedata
for ch in "pаypal":        # одна буква кириллическая
    print(hex(ord(ch)), unicodedata.name(ch))
```

Это же используют в фишинговых доменах (IDN homograph attack).

## Пробелы, табы и переводы строк

Простейший и самый частый канал:

- **Trailing whitespace**: число пробелов в конце строки = код символа.
- **Смешение табов и пробелов**: tab=1, space=0.
- **CRLF vs LF**: два состояния = бит.
- **Лишние пустые строки**: их количество кодирует.

```python
lines = open("file.txt", "rb").read().split(b"\n")
codes = [len(l) - len(l.rstrip(b" \t")) for l in lines]
print(bytes(c for c in codes if 0 < c < 256))
```

```bash
cat -A file.txt | head     # покажет ^I (tab) и $ (конец строки)
```

## Комментарии и «мёртвый» код

Комментарии — классический тайник: base64, hex, зашифрованный текст. Также прячут в:

- **Неиспользуемых импортах** и переменных.
- **Отключённых блоках кода** (`if False:`).
- **Строках-константах**, которые нигде не выводятся.
- **Метаданных пакетов** (`package.json`, `setup.py`).

```bash
grep -rnE 'TODO|FIXME|XXX|flag|base64' src/ | head
```

## CSS/HTML: тонкие каналы

- **Порядок CSS-правил** и выбор селектора (`#a` vs `.a`).
- **Значения свойств**, визуально эквивалентные (`margin:4px` vs `4.0px`).
- **data-* атрибуты**, неиспользуемые классы.
- **HTML-комментарии**, лишние атрибуты, порядок тегов.
- **Цвета**: `#FFFFFF` vs `#ffffff` vs `rgb(255,255,255)`.

```bash
grep -oE '#[0-9a-fA-F]{6}' style.css | sort | uniq -c
```

## Автоматизация анализа

Пайплайн для «кодовых» задач:

```python
import re
src = open("bundle.js", encoding="utf-8", errors="ignore").read()
# 1. невидимые символы
zw = [ch for ch in src if ord(ch) in (0x200b, 0x200c, 0x200d, 0xfeff)]
# 2. base64-подобное
b64 = re.findall(r"[A-Za-z0-9+/]{16,}={0,2}", src)
# 3. комментарии
comments = re.findall(r"//(.*)|/\*(.*?)\*/", src, re.S)
print(len(zw), b64[:3])
```

## Ограничения и предостережения

- **Форматтеры чистят whitespace** — никогда не прогоняйте файл через prettier до анализа.
- **Нормализация Unicode** может удалить невидимые символы.
- **Минификация** сжимает whitespace-канал.
- **Контроль версий** (git) может показать различия, выдав канал (или скрыв).
