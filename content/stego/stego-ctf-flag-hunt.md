## Вопрос, с которого всё начинается

У тебя есть архив `container.zip` с десятком файлов. Флаг где-то внутри — но не
обязательно в очевидном месте. Он может быть в текстовом файле, в метаданных
картинки, в имени, в скрытом файле. Как искать **методично**, а не открывая всё
руками? Разберём системный поиск.

## Наш пример: файл container.zip

```bash
unzip container.zip
```

```text
  inflating: readme.txt
  inflating: photo.jpg
  inflating: data.bin
  inflating: .hidden_note
```

Обрати внимание на `.hidden_note` — скрытый файл (имя начинается с точки). Он не
виден в обычном `ls` без флага `-a`. Это первый урок: **смотри скрытое**.

## Шаг 1: рекурсивный grep

Самый быстрый способ найти строку флага — рекурсивный поиск по всем файлам:

```bash
grep -r "nto{" . 2>/dev/null
```

```text
./readme.txt:flag is not here, keep looking
./.hidden_note:nto{fl4g_hunt_syst3m}
```

`grep -r` ищет по содержимому всех файлов. `2>/dev/null` прячет ошибки от
бинарников. Это первый и часто достаточный шаг.

## Шаг 2: strings по бинарным файлам

Если флаг в бинарнике (`data.bin`), `grep` может не показать контекст, но
`strings` извлечёт текстовые фрагменты:

```bash
strings data.bin | grep nto
```

```text
(пусто)
```

Здесь пусто — значит, в `data.bin` флага нет. Не трать на него время, иди дальше.
Умение быстро **исключать** файлы так же важно, как находить.

## Шаг 3: скрытые и нестандартные имена

Скрытые файлы (`.hidden_note`), файлы с двойным расширением (`photo.jpg.zip`),
файлы с пробелами в имени — всё это места сокрытия. Проверяй листинг с `ls -la` и
обращай внимание на размеры: файл, несоразмерно большой для своего типа, —
подозрителен.

## Шаг 4: метаданные

Флаг может лежать в метаданных, а не в содержимом:

```bash
exiftool photo.jpg | grep -i nto
```

```text
Comment: nto{...}
```

Поэтому после `grep -r` (который видит и метаданные как текст) полезно отдельно
прогнать `exiftool` — он показывает структурированные поля, включая те, что `grep`
не выделяет.

## Шаг 5: вложенность

Часто внутри архива есть ещё один архив или образ. Тогда:

```bash
binwalk container.zip
```

```text
0   0x0   Zip archive data
```

`binwalk` покажет вложенные сигнатуры. Если внутри ZIP лежит PNG с ZIP — разбирай
рекурсивно. Правило: **каждый найденный файл — новый контейнер**, проверяй его
самостоятельно.

## Шаг 6: фиксируем результат

```bash
grep -r nto . 2>/dev/null | head
```

```text
./.hidden_note:nto{fl4g_hunt_syst3m}
```

Запишем флаг:

```bash
grep -rho "nto{[^}]*}" . | head -1 > found.txt
cat found.txt
```

```text
nto{fl4g_hunt_syst3m}
```

Обрати внимание на `-o`: он печатает только совпавшую часть, а не всю строку. Это
удобно, чтобы извлечь флаг чисто.

## Шаг 7: чего не делать

- Не останавливайся на **первом** совпадении: может быть приманка (`readme.txt:
  flag is not here`). Проверяй формат флага.
- Не открывай каждый файл руками — используй `grep`/`strings`.
- Не забывай про скрытые файлы и метаданные.
- Не игнорируй вложенность.

## Шаг 8: полный разбор поиска

Разберём поиск подробно. У нас архив `container.zip` с четырьмя файлами, один из
которых скрытый. Первое действие — распаковка: `unzip container.zip`. Затем —
листинг с флагом `-a`: `ls -la`. Скрытый файл `.hidden_note` сразу выдаёт себя
точкой в начале имени.

Дальше — рекурсивный поиск: `grep -r "nto{" .`. Он пройдёт по содержимому всех
файлов и покажет совпадения. Здесь важна деталь: `grep` по бинарникам может выдать
«Binary file matches» вместо строки. Тогда используй `grep -a` (считать бинарники
текстом) или `strings`.

## Шаг 9: почему приманки работают

Авторы задач специально кладут файл `readme.txt` со строкой «flag is not here».
Новичок видит первое совпадение и хватает его. Опытный проверяет формат: флаг
должен быть `nto{...}`, а не просто текстом. Правило: **сравнивай с ожидаемым
форматом**, а не с первым, что похоже на ответ.

## Шаг 10: метаданные как источник

Метаданные — отдельный слой. В `photo.jpg` может быть комментарий с флагом, в
`data.bin` — имя автора, в EXIF — GPS-координаты, кодирующие сообщение. `grep -r`
увидит часть метаданных как текст, но `exiftool` покажет структурированно:

```bash
exiftool -a -u -g1 photo.jpg
```

Флаг `-a` — все теги, `-u` — неизвестные, `-g1` — группировка. Это даёт полную
картину метаданных.

## Шаг 11: имена файлов как носитель

Иногда флаг закодирован **в именах файлов**. Например, архив с сотней файлов, чьи
имена образуют сообщение при сортировке. Проверь:

```bash
unzip -l container.zip | sort -k4
```

Или посмотри первые байты имён. Это редкий, но встречающийся приём.

## Шаг 12: рекурсивный разбор

Каждый найденный файл — потенциальный контейнер. Если внутри ZIP лежит PNG с ZIP,
разбирай рекурсивно. Инструмент `binwalk -e` умеет рекурсию, но ручной разбор
надёжнее. Правило: **не останавливайся на первом слое**.

## Шаг 13: автоматизация поиска

Если файлов много, напиши простой цикл (но помни про правило «не гоняй curl/for
loop по сети» — это локальные файлы, здесь цикл уместен):

```bash
for f in *; do echo "== $f"; strings "$f" | grep -i nto; done
```

Это даёт быстрый обзор. Но для сложных случаев всё равно нужен ручной анализ.

## Шаг 14: частые ошибки

Первая — останавливаться на приманке. Вторая — не проверять скрытые файлы.
Третья — игнорировать метаданные. Четвёртая — не разбирать вложенность. Пятая —
использовать `grep` без `-a` и терять совпадения в бинарниках.

## Шаг 15: связь с триажем

Поиск флага — это частный случай триажа. Ты применяешь те же шаги (формат,
сигнатуры, хвост), но в контексте набора файлов. Поэтому сначала освой триаж одного
файла, затем — поиск по контейнеру.

## Шаг 16: разбор многослойного поиска

Усложним: архив с вложенным архивом, внутри — изображение с флагом в метаданных.
Поиск: `unzip` → `ls -la` (находим внутренний архив) → `unzip` → `exiftool photo.jpg
| grep nto`. Каждый шаг сужает область. Важно проверять **все** слои: флаг может
быть не в первом файле, а в метаданных третьего.

## Шаг 17: как не пропустить файл

Пропуски случаются из-за скрытых файлов, нестандартных имён и бинарников без `-a`.
Чек-лист: `ls -la` (скрытые), `find . -type f` (все файлы), `grep -ra nto .`
(бинарники как текст), `exiftool` по медиа. Эти четыре команды покрывают почти
все места сокрытия.

## Шаг 18: приманки и как их распознать

Приманка — файл, который выглядит как ответ, но им не является. Признаки: текст
«flag is not here», строка в неверном формате, слишком «лёгкий» ответ. Правило:
настоящий флаг совпадает с ожидаемым форматом и подтверждается контекстом. Не
хватай первое совпадение.

## Шаг 19: итог по поиску флага

Поиск флага — это дисциплинированная фильтрация: сначала широкий рекурсивный
поиск, затем сужение по типам, затем разбор вложенности. Такой подход быстрее и
надёжнее, чем открывать файлы по одному.

## Шаг 20: заключение

Поиск флага выигрывается дисциплиной. Широкий рекурсивный поиск, проверка скрытых
файлов и метаданных, разбор вложенности и осторожность с приманками — вот и весь
рецепт. Он прост, но именно его пропускают новички, хватаясь за первый похожий на
ответ файл. Не спеши: методичность здесь важнее скорости.

## Шаг 21: практический пример с командной работой

В командных CTF поиск флага распределяют: один человек смотрит метаданные, другой —
вложенность, третий — LSB. Чтобы не дублировать работу, ведут общий список
проверенных мест. Тогда время тратится эффективно, а не на повторные проходы. Тот
же принцип применим к самому себе: заведи чек-лист и отмечай, что уже проверено.

## Шаг 22: как отличить настоящий флаг от шума

Флаги обычно имеют строгий формат: префикс, фигурные скобки, осмысленное
содержимое внутри. Случайная строка из `strings` редко совпадает с этим шаблоном.
Поэтому используй точный поиск по шаблону (`grep -o 'nto{[^}]*}'`), а не по общему
слову. Это отсекает большинство ложных срабатываний и экономит время.

## Шаг 23: что если флага нет в текстовом виде

Флаг может быть закодирован: base64, hex, XOR, ROT13. Тогда прямой `grep` не
найдёт его. Признак: в `strings` видны подозрительные строки (длинные base64,
hex-последовательности). Их декодируют по очереди. Поэтому поиск флага — это не
только `grep`, но и распознавание кодировок.

## Шаг 24: заключительная заметка

Помни: поиск флага — это итеративный процесс. Нашёл подозрительную строку — проверь
формат; нашёл закодированные данные — декодируй; нашёл вложенный файл — разбери.
Каждая итерация либо приближает к флагу, либо исключает гипотезу. Именно так
работает методичный поиск, в отличие от хаотичного перебора.

## Шаг 25: практический итог

Составь для себя короткую шпаргалку и держи её под рукой: `unzip`, `ls -la`,
`grep -ra nto .`, `exiftool`, `find . -type f`, `binwalk`. Эти шесть команд
покрывают большинство контейнерных задач. Когда они не дают результата, переходи к
ручному разбору и кодировкам. Так методичный поиск становится привычкой, а не
случайной удачей, и ты перестаёшь зависеть от везения.

## Что мы теперь знаем

- Рекурсивный `grep -r` — первый шаг поиска флага.
- `strings` помогает по бинарникам; пусто = исключаем файл.
- Скрытые файлы, двойные расширения и метаданные — частые места сокрытия.
- Вложенные контейнеры разбирают рекурсивно.
- Приманки существуют: проверяй формат флага, не хватай первое совпадение.
