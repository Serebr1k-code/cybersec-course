## Вопрос, с которого всё начинается

В задаче дан файл `seq.fasta` — внутри длинная строка из букв `A`, `C`, `G`, `T`. Никаких картинок, никаких архивов, только буквы. Как из «биологической» последовательности достать флаг?

Ответ: **ACGT — это алфавит из четырёх символов**, а четыре символа — это ровно два бита. Значит, любая такая строка — закодированные данные. Разберём это на нашем файле.

## Наш пример: seq.fasta

**ДНК** в природе — это цепочка из четырёх оснований: аденин (A), цитозин (C), гуанин (G) и тимин (T). **FASTA** — текстовый формат для таких последовательностей: строка с `>` — это заголовок записи, следующие строки — сама последовательность.

Смотрим файл:

```bash
$ head -3 seq.fasta
>chr1 synthetic construct
ACGTACGTGGTTACGTACGT...
```

Заголовок `>chr1` можно отбросить, а саму последовательность собрать в одну строку. Теперь у нас есть «сырые» данные, и вопрос — какая схема кодирования применена.

## Шаг 1: ACGT как base-4

**Base-4** — система счисления с четырьмя цифрами (в отличие от привычной base-10 и компьютерной base-2). Четыре основания идеально ложатся на неё: каждому сопоставляем пару бит.

Простейший маппинг — по алфавиту: `A=00`, `C=01`, `G=10`, `T=11`. Тогда каждые 4 основания дают 1 байт.

```python
s = ''.join(l.strip() for l in open('seq.fasta') if not l.startswith('>'))
m = {'A':'00','C':'01','G':'10','T':'11'}
bits = ''.join(m[c] for c in s)
out = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
print(out[:60])
```

Пробуем:

```bash
$ python3 decode.py
b'\x91\xa4\xc2...'
```

Мусор. Причина — **порядок маппинга неизвестен заранее**: четыре буквы можно расставить по четырём значениям 24 способами (перестановками). Наш «алфавитный» вариант — лишь один из них.

## Шаг 2: перебираем 24 перестановки

Вместо того чтобы угадывать, переберём все варианты и будем искать сигнатуру `flag{`:

```python
import itertools
s = ''.join(l.strip() for l in open('seq.fasta') if not l.startswith('>'))
for perm in itertools.permutations('ACGT'):
    m = {c: format(i, '02b') for i, c in enumerate(perm)}
    bits = ''.join(m[c] for c in s)
    out = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
    if b'flag{' in out:
        print(perm, out[:40])
        break
```

```bash
$ python3 brute.py
('T','G','C','A') b'flag{dna_base4}'
```

`itertools.permutations` генерирует все 24 перестановки, `format(i, '02b')` делает из числа 2-битную строку. Нашлась рабочая схема — флаг получен.

## Шаг 3: если не сработало — 1 бит на основание

Иногда данные кодируют не по два бита, а по одному: например, `A` и `C` (пурины) дают 0, `G` и `T` (пиримидины) — 1, а лишние буквы служат «наполнителем». Или бит кодируется выбором **комплементарной** пары (`A↔T`, `C↔G`).

```python
bits = ''.join('0' if c in 'AC' else '1' for c in s if c in 'ACGT')
out = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
```

Правило простое: если base-4 не дал ничего, пробуй 1 бит на основание — так выглядит «более биологично».

## Шаг 4: кодоны и рамка считывания

Если последовательность выглядит как **настоящая** ДНК (реалистичный состав, стоп-кодоны), данные могли спрятать косвенно. ДНК «читается» триплетами — **кодонами**: каждые три основания кодируют одну аминокислоту. Одну аминокислоту кодируют несколько разных кодонов (**синонимичные замены**), и автор может прятать биты в выборе синонима, не меняя «белок».

Здесь важен **offset** — с какой позиции начинать отсчёт триплетов. Данные могут начинаться не с первого основания:

```python
for off in (0, 1, 2):
    codons = [s[i:i+3] for i in range(off, len(s)-2, 3)]
    print('offset', off, 'first codons:', codons[:5])
```

## Шаг 5: комплементарность и ориентация

ДНК двуцепочечная: `A` комплементарен `T`, а `C` — `G`. Автор может кодировать бит **ориентацией** фрагмента — прямая цепь или обратная комплементарная. Тогда надо проверить обе.

```python
comp = s.translate(str.maketrans('ACGT','TGCA'))[::-1]   # reverse-complement
```

`str.maketrans` задаёт замену букв, `[::-1]` разворачивает строку — вместе это **реверс-комплемент**.

## Шаг 6: инструменты

- **`seqkit`** — статистика, трансляция, извлечение из FASTA/FASTQ;
- **`biopython`** — парсинг и анализ последовательностей;
- **`blastn`** — сравнение с известной ДНК (отличить «настоящую» от вставки);
- **`cyberchef`** — быстрый онлайн-разбор нестандартных кодировок.

## Ёмкость и незаметность

ДНК-носитель даёт 2 бита на основание — это огромная ёмкость для «текстового» носителя. Незаметность зависит от схемы: строка base-4 выглядит как случайная ДНК; синонимичные кодоны сохраняют «белок», но заметны статистически. В CTF важнее распознать схему, чем детектировать.

## Форматы FASTA/FASTQ

- **FASTA**: строка `>заголовок`, затем последовательность.
- **FASTQ**: 4 строки на запись — заголовок, последовательность, `+`, строка качества.

```python
seq = ''
for line in open('x.fasta'):
    if not line.startswith('>'):
        seq += line.strip()
```

Заголовки и строки качества — тоже потенциальные каналы: данные могут лежать в описании записи.

- **Игнорируешь регистр и пробелы** в FASTA — приведи к одному регистру, склей строки.
- **Путаешь прямой маппинг и кодонную схему.**
- **Забыл про комплементарность** и ориентацию.
- **Не проверил offset** (0/1/2) в кодонной схеме.
- **Считаешь «настоящую» ДНК данными** — возможно, данные в интронах.

## Что мы теперь знаем

1. ДНК — алфавит из 4 букв, то есть **base-4**: 2 бита на основание.
2. Прямой маппинг имеет 24 перестановки — их надо **перебирать**.
3. Если base-4 не сработал — пробуй **1 бит** на основание.
4. «Биологичная» последовательность может прятать данные в **кодонах** и offset.
5. Не забывай про **реверс-комплемент** и заголовки FASTA.

Инструменты `seqkit`, `biopython`, `blastn` помогают на шагах 5–6. В отчёте фиксируй формат, применённую схему и маппинг — это делает результат воспроизводимым.

## Почему ДНК вообще годится как контейнер

ДНК — это последовательность из четырёх «букв» (нуклеотидов): A, C, G, T. Каждая позиция несёт 2 бита информации, потому что `4 = 2²`. Значит, последовательность из `n` оснований вмещает `2n` бит — ровно как base-4 кодирование. Это делает ДНК естественным «четверичным» носителем: любое сообщение можно перевести в байты, разбить на пары бит и сопоставить парам основания.

Второе, что делает ДНК удобной для сокрытия: **избыточность**. В биологии большая часть генома не кодирует белки, и «мусорная» ДНК допускает замены, которые не меняют смысл. Это аналог свободного места в файле: можно менять «синонимичные» кодоны, не портя белок. Стеганография в ДНК использует именно это — прячет данные в позициях, где биологическая функция сохраняется, поэтому последовательность выглядит правдоподобной и для секвенатора, и для анализа.

Третье — **естественная вариативность**. Один и тот же белок кодируется разными кодонами (вырожденность генетического кода), и выбор синонима — это «неиспользуемый бит», куда можно записать данные. Отсюда целые схемы codon-based стеганографии. Практическая задача на CTF обычно проще: дают FASTA и просят декодировать, перебрав кодировку.

## Частые вопросы

**Почему в примере перебирают 24 перестановки?** Алфавит `ACGT` можно сопоставить парам бит `00,01,10,11` ровно `4! = 24` способами; порядок неизвестен, поэтому пробуют все и ищут осмысленный текст.

**Что делать, если на основание приходится один бит?** Тогда 2 бита base-4 не влезают, и биты кладут по одному (A/G = 0, C/T = 1); это второй по частоте вариант кодирования.

**Как понять рамку считывания?** Если данные спрятаны в кодонах (тройках), важен сдвиг от начала: рамок три, и правильная даёт осмысленный результат. Переберите все три.

**Что такое комплементарность и зачем она?** У ДНК есть вторая цепь (`A↔T`, `C↔G`); сообщение может быть в любой из цепей, поэтому проверяют и прямую, и обратную комплементарную последовательность.

## Обратная задача: как из сообщения получают последовательность

Полезно уметь не только декодировать, но и **строить** ДНК-канал — это сразу проясняет, какие схемы встречаются в задачах. Пайплайн кодирования зеркален декодированию и состоит из четырёх шагов.

**Кадрирование.** Сообщение разбивают на биты. Поскольку одна «буква» несёт 2 бита, длину сообщения искусственно доводят до чётного числа бит, а в начало кладут небольшой заголовок (длину или магию), чтобы получатель знал, где заканчиваются данные и начинается заполнение. Без кадрирования декодер не отличит полезную нагрузку от паддинга.

**Маппинг.** Пары бит `00/01/10/11` отображают в `A/C/G/T`. Порядок отображения произволен — отсюда те самые 24 перестановки, которые приходится перебирать при декодировании. Автор выбирает одну; получатель без подсказки обязан проверить все.

**Контроль целостности.** Хороший канал добавляет к данным контрольную сумму (CRC) или помехоустойчивый код, чтобы отличить «правильный маппинг» от случайного совпадения. При декодировании именно наличие валидной CRC — сильный признак, что ты угадал схему и порядок.

**Маскировка.** Наконец, последовательность «облагораживают»: подгоняют состав нуклеотидов под реалистичный (например, GC-состав), вставляют стоп-кодоны, оформляют в FASTA с правдоподобным заголовком. Это превращает base-4 строку в файл, который не бросается в глаза биологу. Понимание этих шагов подсказывает порядок действий при разборе: сначала кадр и маппинг, затем проверка CRC, и только потом — биологический слой.
