MP3 — самый распространённый формат аудио, и потому частый гость CTF. В отличие от WAV, где сэмплы лежат «как есть», MP3 хранит сжатые данные: MDCT-коэффициенты, квантованные с потерями. Это меняет и возможности сокрытия, и инструменты. Есть три основных направления: `mp3stego` (использование «запасных» бит кодера), фазовое кодирование (данные в фазе MDCT-коэффициентов) и банальные ID3-метаданные (не стеганография в строгом смысле, но в CTF считается). Разберём все три.

## Как устроен MP3 и где «щели»

MP3-кадр (frame) содержит заголовок, side information и сжатые данные основного канала. Психоакустическая модель решает, какие частоты «не слышны» и их можно огрубить. Кодер с потерями иногда не использует все выделенные биты — остаётся «запас». Эти запасные биты и использует `mp3stego`: данные не меняют звук, потому что пишутся туда, где кодер и так «молчал».

Фазовое кодирование (phase coding) работает иначе: MDCT даёт коэффициенты с амплитудой и фазой. Амплитуда определяет слышимость, а фаза — менее заметна. Данные кодируют в фазе, и это переживает часть обработки.

## mp3stego: команды и флаги

`mp3stego` — классический инструмент Фабиена Петитколаса. Синтаксис:

```bash
# спрятать: mp3stego <-E> <in.wav> <out.mp3> <-P password>
mp3stego -E cover.wav stego.mp3 -P secret

# извлечь: mp3stego <-X> <in.mp3> <out> <-P password>
mp3stego -X stego.mp3 hidden.txt -P secret

# без пароля (иногда задача без ключа)
mp3stego -X stego.mp3 hidden.txt
```

Ключевые флаги:

| Флаг | Значение |
|---|---|
| `-E` | embed (встроить) |
| `-X` | extract (извлечь) |
| `-P pass` | пароль |
| вход/выход | WAV на вход, MP3 на выход (и наоборот при извлечении) |

Важно: `mp3stego` работает с WAV→MP3, а не с готовым MP3. Для встраивания нужен несжатый источник.

## Другие инструменты

- **`steghide`** — не поддерживает MP3 (только JPEG/BMP/WAV/AU), но путают часто.
- **`mp3stego`** — основной.
- **`DeepSound`** — GUI-инструмент для аудио (WAV/FLAC/MP3), с паролем.
- **`SilentEye`** — WAV/BMP, не MP3.
- **`ffmpeg`/`ffprobe`** — разбор контейнера, потоки, битрейт, ID3.
- **`eyeD3`** — чтение/запись ID3-тегов (проверка на «данные в тегах»).
- **`strings`, `xxd`, `binwalk`** — быстрый поиск в файле.

Разбор контейнера:

```bash
ffprobe -v quiet -print_format json -show_format -show_streams stego.mp3
```

Вывод (фрагмент):

```json
{"streams":[{"codec_name":"mp3","sample_rate":"44100","channels":2}],
 "format":{"duration":"12.480000","bit_rate":"128000"}}
```

## Разобранный пример: mp3stego end-to-end

```bash
# готовим несжатый WAV из любого источника
ffmpeg -i source.flac -ar 44100 -ac 2 cover.wav

# встраиваем
mp3stego -E cover.wav stego.mp3 -P hunter2
# -> "Data appended successfully"

# извлекаем
mp3stego -X stego.mp3 out.txt -P hunter2
cat out.txt
# -> flag{mp3_stego}
```

Если пароль неизвестен — перебор `mp3stego` не поддерживает `stegseek`; придётся брутить вручную (медленно) или искать пароль в задаче. Часто пароль = имя файла, название трека или строка из метаданных.

## ID3-метаданные: не стеганография, но проверяйте

Прежде чем возиться с `mp3stego`, проверьте теги:

```bash
eyeD3 stego.mp3            # все теги
eyeD3 --preserve-file-times stego.mp3
exiftool stego.mp3         # EXIF-подобные поля, комментарии
```

Часто флаг лежит в `TXXX`-поле, `COMM` (комментарий), обложке (`APIC`) или в base64-строке внутри комментария. Это «низко висящий фрукт» — всегда проверяйте первым.

## Фазовое кодирование на практике

Схема: применить STFT/MDCT, изменить фазу выбранных коэффициентов, применить обратное преобразование. На numpy это выглядит так (упрощённо, для WAV):

```python
import numpy as np
from scipy.signal import stft, istft

sr, x = 44100, wav_read("cover.wav")
f, t, Z = stft(x, sr, nperseg=1024)
mag, phase = np.abs(Z), np.angle(Z)
bits = np.unpackbits(np.frombuffer(b"flag{phase}", dtype=np.uint8))
flat = phase.reshape(-1)
for i,b in enumerate(bits):
    flat[i] = (flat[i] + (0.3 if b else -0.3))
Z2 = mag * np.exp(1j*phase)
_, y = istft(Z2, sr, nperseg=1024)
wav_write("stego.wav", y)
```

Приёмник читает знак отклонения фазы относительно «нулевого» уровня. На MP3 это переносится на MDCT-коэффициенты, но требует разбора фреймов.

## Крайние случаи и подводные камни

- **mp3stego работает только с WAV→MP3.** Нельзя встроить в уже готовый MP3 без пересжатия.
- **Пересжатие разрушает данные.** Если stego.mp3 перекодировали (например, сменили битрейт), запасные биты меняются и данные гибнут.
- **Пароль обязателен по умолчанию.** Без `-P` встраивание использует пустой пароль — проверяйте оба варианта.
- **ID3v2 vs ID3v1.** Данные могут быть в обоих; `eyeD3` показывает v2, `strings` — v1 в конце файла.
- **Обложка.** `APIC`-кадр может содержать целый ZIP/PNG с данными — извлеките `ffmpeg -i stego.mp3 cover.jpg`.
- **Стерео.** Данные могут быть в одном канале; разделите каналы (`ffmpeg -ac 1`).

## Что дальше / решение

- MP3 с флагом, но `mp3stego -X` не работает — сначала проверьте ID3/обложку.
- Данные «пропали» после конвертации — попробуйте исходный файл или другой битрейт.
- Нужен свой алгоритм — используйте `ffmpeg` для декодирования в WAV и работайте с сэмплами (см. `stego-audio-lsb`).
- Фаза — если `mp3stego` не подходит, смотрите спектрограмму на аномалии.

## Анатомия MP3-фрейма

Чтобы понимать, куда писать, разберём фрейм. Каждый MP3-фрейм начинается с заголовка из 4 байт: синхрослово `0xFFE`, версия, слой, битрейт, частота, режим (stereo/joint). Далее — side information (сколько бит отдано каналам, масштабные множители), затем сжатые данные основного канала. Психоакустическая модель решает, какие частоты «замаскированы» и могут быть огрублены. «Запасные» биты — те, что выделены, но не использованы кодером. `mp3stego` их и заполняет.

```bash
# посмотреть битрейт и режим каждого фрейма
ffprobe -v error -select_streams a:0 -show_entries frame=pts_time -of csv stego.mp3 | head
# или грубее — по заголовку
xxd stego.mp3 | head -3
```

Признак встраивания `mp3stego`: файл звучит нормально, но размер чуть больше ожидаемого для данного битрейта, а на слух ничего не меняется.

## Извлечение аудио и работа с сэмплами

Если `mp3stego` не подходит, декодируйте MP3 в WAV и анализируйте сэмплы:

```bash
ffmpeg -i stego.mp3 -ac 1 -ar 44100 -sample_fmt s16 cover.wav
sox cover.wav -n spectrogram -o spec.png   # спектрограмма
```

Спектрограмма — главный визуальный инструмент аудио-стего: аномальные горизонтальные линии (морзе/FSK), «шумовые» полосы (spread-spectrum), эхо (двойные линии) видны сразу. В MP3-задачах часто прячут не в кодеках, а именно в аудиосодержимом — тогда работают приёмы из `stego-audio-spec`.

## Метаданные, обложка и хвост

Три «дешёвых» места, которые проверяют до всего сложного:

- **ID3v2 в начале файла** — `eyeD3`, `exiftool`, `id3v2 -l`.
- **ID3v1 в конце** — 128 байт в хвосте, `strings -n 4 stego.mp3 | tail`.
- **Обложка APIC** — `ffmpeg -i stego.mp3 -an -c:v copy cover.jpg`.
- **Данные после последнего фрейма** — `binwalk stego.mp3`, `dd`.

```bash
binwalk stego.mp3
# DECIMAL  HEXADECIMAL  DESCRIPTION
# 204800   0x32000      Zip archive data
```

Практический порядок для любой MP3-задачи: `file` → `exiftool`/`eyeD3` → `binwalk` → `mp3stego -X` (с паролем и без) → спектрограмма. Так вы не пропустите ни метаданные, ни запасные биты, ни визуальный канал.

## Сравнение MP3 с WAV и FLAC

Разные аудиоформаты по-разному годятся для сокрытия:

| Формат | Тип | Инструмент | Особенность |
|---|---|---|---|
| WAV | lossless PCM | steghide, LSB-скрипт | прямая работа с сэмплами |
| FLAC | lossless сжатие | LSB-скрипт (после декода) | без потерь, ёмкость как у WAV |
| MP3 | lossy | mp3stego, фазовое | запасные биты, MDCT |
| OGG/Vorbis | lossy | редко | свои поля |

WAV/FLAC дают максимум ёмкости (1 бит на сэмпл), но большие файлы. MP3 компактен, но каналов меньше (запасные биты, фаза). В задачах важно определить реальный формат через `file`, а не доверять расширению: `.wav` иногда содержит MP3 внутри.

## Распространённые ошибки с аудио

- **Плейер «сглаживает».** Проигрывание через динамики теряет высокие частоты; анализируйте файл, а не слушайте.
- **Стерео.** Данные могут быть в разнице каналов (mid/side); вычитайте каналы.
- **Спектрограмма в линейном масштабе.** Переключите на логарифмический — тонкие линии видны лучше.
- **Ресемплинг.** Конвертация частоты сэмплирования портит LSB/фазу; работайте в оригинале.
- **ID3v1 в хвосте.** Легко пропустить; `strings` по хвосту.

## Итоговый порядок для аудио-задачи

1. `file` + `ffprobe` — реальный формат, каналы, частота, длительность.
2. `exiftool`/`eyeD3` — ID3, комментарии, обложка.
3. `binwalk`/`strings` — дописанные данные и хвост.
4. Спектрограмма (`sox`/`audacity`) — визуальные аномалии.
5. LSB по сэмплам (WAV/FLAC) — скрипт.
6. `mp3stego -X` (MP3) — с паролем и без.
7. Разностный канал, mid/side — если стерео.

Аудио — многоканальный носитель: метаданные, сэмплы, фаза, спектр и контейнер. Пройдите все уровни, прежде чем считать задачу «пустой».
