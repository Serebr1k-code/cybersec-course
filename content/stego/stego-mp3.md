## Вопрос, с которого всё начинается

В задаче дали файл `secret.mp3` — двенадцать секунд музыки. Слушаешь: обычный трек, ни шипения, ни щелчков. Открываешь в редакторе тегов — тоже вроде пусто. Где тут флаг?

MP3 — формат **сжатия с потерями**: часть звуковой информации в нём отброшена, потому что человеческое ухо её «не слышит». Это не мешает прятать данные — просто каналы здесь другие, чем в WAV. Разберём один файл от начала до конца и посмотрим, где именно смотреть.

## Наш пример: secret.mp3

Сначала убеждаемся, что это действительно MP3, а не переименованный WAV (так тоже бывает):

```bash
$ file secret.mp3
secret.mp3: Audio file with ID3 version 2.4.0, contains: MPEG ADTS, layer III, v1, 128 kbps, 44.1 kHz, JntStereo
```

`ID3 version 2.4.0` — значит, в начале файла есть блок тегов. `layer III` — это и есть MP3. Дальше подробнее разбираем поток через `ffprobe` (часть пакета `ffmpeg`):

```bash
$ ffprobe -v quiet -print_format json -show_format -show_streams secret.mp3
{"streams":[{"codec_name":"mp3","sample_rate":"44100","channels":2}],
 "format":{"duration":"12.480000","bit_rate":"128000"}}
```

Итак: 44 100 Гц, два канала, 128 кбит/с, 12,48 секунды. Теперь у нас есть план — проверить по очереди метаданные, хвост файла, «запасные» биты и спектр.

## Шаг 1: метаданные — всегда первым делом

Прежде чем возиться со сложными алгоритмами, читаем **теги** — служебные поля с названием трека, исполнителем, обложкой. Это «низко висящий фрукт»: флаг часто лежит прямо там.

```bash
$ eyeD3 secret.mp3
secret.mp3  [ 12.48 s ]
ID3 v2.4.0
Title: Summer Night
Artist: unknown
Comment: pass:hunter2
```

В поле комментария (`COMM`) лежит подсказка `pass:hunter2`. Это не флаг, но, возможно, **пароль** для извлечения. Дополнительно смотрим обложку и все поля через `exiftool`:

```bash
$ exiftool secret.mp3
...
Comment                         : pass:hunter2
Picture MIME Type               : image/png
Picture Type                    : Cover (front)
```

Есть встроенная картинка (`APIC`-кадр). Её можно извлечь и прогнать через стегоанализ изображений, но пока запомним пароль и пойдём дальше.

## Шаг 2: хвост файла и дописанные данные

После последнего аудиокадра к файлу часто **дописывают** целые файлы — архив, картинку, строку. Инструмент `binwalk` ищет в файле известные сигнатуры:

```bash
$ binwalk secret.mp3
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             ID3 tag, tag length: 1024
1024          0x400           MPEG audio bitstream
200704        0x31000         Zip archive data, at least v2.0 to extract
```

По смещению `0x31000` начинается ZIP — уже после аудиоданных. Извлекаем его:

```bash
$ dd if=secret.mp3 of=tail.zip bs=1 skip=200704 2>/dev/null
$ unzip -l tail.zip
Archive:  tail.zip
  Length      Date    Name
        0  2026-01-01  readme.txt
```

Здесь архив пустой (только `readme.txt`) — ложный след. Но проверять хвост нужно всегда: сигнатуры `PK`, `flag{` ищутся одной строкой:

```bash
$ grep -aboP 'flag\{|PK\x03\x04|\x89PNG' secret.mp3
```

## Шаг 3: «запасные» биты и mp3stego

Теперь главное для MP3. Каждый MP3-кадр начинается с 4-байтного заголовка, за которым идёт `side information` (сколько бит отдано каналам) и сжатые данные. **Психоакустическая модель** решает, какие частоты «замаскированы» и их можно огрубить. Иногда кодеру выделено больше бит, чем реально нужно, — остаётся **запас**. Классический инструмент `mp3stego` пишет данные именно в этот запас: звук не меняется, потому что биты уходят туда, где кодер и так «молчал».

Извлекаем с найденным паролем:

```bash
$ mp3stego -X secret.mp3 out.txt -P hunter2
mp3stego version 0.1
Data extracted successfully

$ cat out.txt
flag{mp3_reserved_bits}
```

Флаг получен. Обрати внимание: `-X` означает *extract* (извлечь), `-P` — пароль. Если пароль в задаче не указан, попробуй оба варианта — с `-P` и без: при встраивании без пароля используется пустая строка.

Важное ограничение: `mp3stego` встраивает **только из WAV в MP3**. То есть нельзя взять готовый MP3 и дописать в него данные — файл надо пересоздать из несжатого источника:

```bash
$ ffmpeg -i source.flac -ar 44100 -ac 2 cover.wav
$ mp3stego -E cover.wav stego.mp3 -P hunter2
```

## Шаг 4: если mp3stego не сработал — спектр

Данные могут быть спрятаны не в кодеке, а в самом звуке. Тогда смотрим **спектрограмму** — картинку, где по горизонтали время, по вертикали частота, а яркость означает громкость. `sox` строит её одной командой:

```bash
$ ffmpeg -i secret.mp3 -ac 1 -ar 44100 -sample_fmt s16 cover.wav
$ sox cover.wav -n spectrogram -o spec.png
```

На спектрограмме сразу видны аномалии: ровные горизонтальные линии (азбука Морзе или FSK), широкие «шумовые» полосы (spread-spectrum), двойные линии (эхо). Этот приём разбирается в уроке про спектральный анализ аудио — здесь важно помнить, что MP3-задача не ограничивается кодеком.

## Шаг 5: фазовое кодирование

Третий канал — **фаза**. MP3 строится на преобразовании MDCT: сигнал раскладывается на коэффициенты, у каждого есть амплитуда (насколько громко) и фаза (с какой задержкой). Амплитуда слышна, фаза — почти нет. Данные кодируют в фазе выбранных коэффициентов. Упрощённо, на WAV это выглядит так:

```python
import numpy as np
from scipy.signal import stft, istft

sr, x = 44100, wav_read("cover.wav")
f, t, Z = stft(x, sr, nperseg=1024)
mag, phase = np.abs(Z), np.angle(Z)
bits = np.unpackbits(np.frombuffer(b"flag{phase}", dtype=np.uint8))
flat = phase.reshape(-1)
for i, b in enumerate(bits):
    flat[i] = flat[i] + (0.3 if b else -0.3)
Z2 = mag * np.exp(1j * phase)
_, y = istft(Z2, sr, nperseg=1024)
wav_write("stego.wav", y)
```

Приёмник читает знак отклонения фазы от «нулевого» уровня. На MP3 то же самое переносится на MDCT-коэффициенты, но требует разбора фреймов вручную.

## Шаг 6: стерео и разностный канал

Последний приём — **mid/side**. В стереофайле данные иногда прячут в разнице между каналами: сумма каналов (mid) звучит как обычный трек, а разность (side) несёт информацию. Свести каналы и послушать разницу можно так:

```bash
$ ffmpeg -i secret.mp3 -af "pan=mono|c0=0.5*c0-0.5*c1" diff.wav
$ sox diff.wav -n spectrogram -o diff.png
```

Если в задаче стерео, а предыдущие шаги пусты, — обязательно проверь разностный канал.

## Что мы теперь знаем

1. MP3 — сжатие с потерями, но каналов для сокрытия несколько: теги, хвост, запасные биты, спектр, фаза.
2. Метаданные (ID3/`COMM`/`APIC`) проверяются первыми — там бывают флаг или пароль.
3. `mp3stego` прячет данные в неиспользуемых битах кодера; работает WAV→MP3 и требует пароль (или пустой).
4. Дописанные файлы ищутся `binwalk` и `grep -aboP` — ZIP/PNG в хвосте частая находка.
5. Спектрограмма (`sox`) вскрывает аномалии в самом звуке; разностный канал — в стерео.
6. Перекодирование MP3 разрушает запасные биты — работай с оригиналом.
