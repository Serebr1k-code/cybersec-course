## Вопрос, с которого всё начинается
Ты копируешь текст из чужого документа, вставляешь в свой — и он выглядит
одинаково. Но байты другие. Unicode содержит **невидимые** символы: управляющие
«теги», вариационные селекторы, нулевой ширины. Из них можно собрать полноценное
сообщение прямо в строке текста, и глаз его не увидит. Это самый «чистый» текстовый
канал.

## Наш пример
Возьмём `note.txt` — короткую заметку. Она выглядит нормально, но после видимого
текста идут невидимые символы блока Unicode Tags, кодирующие сообщение.

## Шаг 1: блок Unicode Tags
Диапазон `U+E0000..U+E007F` — «Tags» (теги языка). Символ `U+E0001` — language tag,
`U+E0020..U+E007E` соответствуют ASCII 0x20..0x7E. То есть символ тега с кодом
`U+E0041` — это невидимая «A». Формула: `char = chr(0xE0000 + ord(visible))`.
Эти символы невидимы в большинстве шрифтов и редакторов.

## Шаг 2: вариационные селекторы
`U+FE00..U+FE0F` (VS1..VS16) и `U+E0100..U+E01EF` (VS17..VS256) меняют вид
предыдущего глифа, но сами не рисуются. Их наличие/отсутствие после символа —
двоичный канал. 16 селекторов = 4 бита на позицию.

## Шаг 3: символы нулевой ширины
`U+200B` (zero-width space), `U+200C` (ZWNJ), `U+200D` (ZWJ), `U+FEFF` (BOM/ZWNBSP)
— невидимы. Три-четыре разных символа кодируют 2 бита на позицию. Классический
zero-width-стего использует `U+200B` = 0, `U+200C` = 1, `U+200D` = разделитель.

## Шаг 4: извлечение вручную
```python
text = open('note.txt', encoding='utf-8').read()
msg = ''.join(chr(ord(c) - 0xE0000) for c in text if 0xE0000 <= ord(c) <= 0xE007F)
print(msg)
```

Вывод:

```
nto{unicode_tags_block}
```

## Шаг 5: почему это незаметно и опасно
- **Не отображается.** Ни в браузере, ни в терминале, ни в обычном редакторе.
- **Переживает копирование.** Ты копируешь строку вместе с невидимыми символами.
- **Портит сравнение.** Два визуально одинаковых логина различаются — основа для
  «гомоглиф»-атак и обхода фильтров.

## Шаг 6: инструменты
- `python3 -c "..."` — перебор кодов.
- `xxd note.txt | tail` — увидеть UTF-8-последовательности (`ee 80 81` = U+E001).
- `unicode` / `Unicode Explorer` — инспекция кодов.
- `sed`/`perl -pe 's/[\x{200B}-\x{200D}]//g'` — вычистить zero-width.

## Unicode Tags: как это устроено

В Unicode есть несколько «невидимых» блоков. **Tags** (U+E0000–U+E007F) изначально предназначены для языкового тегирования текста, но на практике не отображаются. Каждый символ Tags соответствует ASCII-символу: U+E0041 = `A`, U+E0042 = `B` и т.д. Значит, произвольную ASCII-строку можно закодировать как последовательность Tags-символов, и она будет невидима в большинстве редакторов.

```python
s = "secret"
enc = "".join(chr(0xE0000 + ord(c)) for c in s)
dec = "".join(chr(ord(c) - 0xE0000) for c in enc)
print(repr(enc), dec)   # enc невидим, dec == "secret"
```

Второй блок — **variation selectors** (U+FE00–U+FE0F и U+E0100–U+E01EF): они модифицируют предыдущий символ и сами по себе не видны. Их можно использовать как биты. Третий — **zero-width** символы: U+200B (zero-width space), U+200C (ZWNJ), U+200D (ZWJ), U+2060 (word joiner), U+FEFF (BOM/zero-width no-break space). Их последовательность тоже кодирует данные.

## Извлечение невидимых символов

Извлечение — перебор кодов. Читаешь файл, отбираешь символы из нужных диапазонов и декодируешь.

```python
txt = open("message.txt", encoding="utf-8").read()
tags = [c for c in txt if 0xE0000 <= ord(c) <= 0xE007F]
print("".join(chr(ord(c) - 0xE0000) for c in tags))
zw = [c for c in txt if ord(c) in (0x200B, 0x200C, 0x200D, 0x2060, 0xFEFF)]
print("zero-width:", len(zw))
```

```bash
python3 -c "import sys; t=open(sys.argv[1],encoding='utf-8').read(); print([hex(ord(c)) for c in t if ord(c)>0x2000])" message.txt | head
```

Для zero-width как битов: мапишь один символ в 0, другой в 1 (например, U+200B → 0, U+200C → 1), собираешь биты в байты. Для variation selectors — аналогично. Инструменты: `python3`, `xxd` (увидеть байты UTF-8), `cat -A` (не покажет невидимое, поэтому нужен скрипт), специализированные декодеры (`unicode-stego`, `zwsp-steg`).

## Почему это незаметно и опасно

Невидимые символы не отображаются, поэтому их можно спрятать в обычном тексте — посте, комментарии, README, сообщении. При копировании текста они переносятся вместе с ним, так что канал «путешествует» незаметно. Это делает Unicode-стего удобным для CTF и опасным в реальности: через него можно передать данные, обойти фильтры и оставить «водяной знак» в документе.

Опасность усиливается тем, что такие символы могут ломать парсеры, вызывать ошибки кодировки и использоваться для атак (например, «Trojan Source» — подмена порядка отображения кода через bidirectional-символы). Поэтому при анализе текста всегда проверяй наличие невидимых символов.

Для защиты: нормализовать текст (удалять невидимые символы), валидировать ввод, использовать редакторы/линтеры, которые подсвечивают невидимое. Для детекта — скрипт, перебирающий коды и выводящий статистику по диапазонам.

## Практика: декодирование Tags-блока

Полный цикл на файле `message.txt`, где после видимого текста спрятана Tags-строка. Шаг первый — найти невидимые символы:

```bash
python3 - <<PY
t = open("message.txt", encoding="utf-8").read()
tags = [c for c in t if 0xE0000 <= ord(c) <= 0xE007F]
print("found", len(tags), "tags")
print("".join(chr(ord(c) - 0xE0000) for c in tags))
PY
```

Шаг второй — если результат не ASCII, проверь другие диапазоны (variation selectors, zero-width). Шаг третий — если zero-width использованы как биты, определи маппинг (какой символ = 0, какой = 1) и собери байты. Часто маппинг очевиден по двум разным символам, встречающимся только в этой области.

```python
zw = [c for c in t if c in "\u200b\u200c"]
bits = "".join("0" if c == "\u200b" else "1" for c in zw)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data)
```

## Практика: variation selectors и порядок

Variation selectors (U+FE00–U+FE0F и U+E0100–U+E01EF) следуют за символом и не отображаются. Их можно использовать как биты: например, U+FE00 = 0, U+FE01 = 1. Порядок появления кодирует данные.

```python
vs = [c for c in t if 0xFE00 <= ord(c) <= 0xFE0F]
bits = "".join(str(ord(c) - 0xFE00) for c in vs)
```

Ещё один приём — **bidirectional control characters** (U+202A–U+202E, U+2066–U+2069): они управляют направлением текста и не видны. Их тоже используют для сокрытия (и для атак вроде Trojan Source). Найди их скриптом и проанализируй порядок.

Инструменты: `python3` (основной), `xxd` (байты UTF-8), специализированные декодеры (`unicode-stego`, `zwsp-steg`). Помни: `cat -A` не покажет невидимые символы — нужен скрипт, перебирающий коды.

## Итог по Unicode-стего

Невидимые символы (Tags, variation selectors, zero-width, bidi) — удобный канал сокрытия в любом тексте. Декодирование — перебор кодов и маппинг в биты/ASCII. Инструменты: `python3`, `xxd`. Для защиты — нормализация текста и линтеры, подсвечивающие невидимое.

## Разбор примера: Tags в README

Сценарий: в конце `README.md` спрятана Tags-строка с флагом. Шаг первый — найти невидимые символы:

```bash
python3 - <<PY
t = open("README.md", encoding="utf-8").read()
tags = [c for c in t if 0xE0000 <= ord(c) <= 0xE007F]
print("tags:", len(tags))
print("".join(chr(ord(c) - 0xE0000) for c in tags))
PY
```

Шаг второй — если Tags пусты, проверь zero-width (U+200B/200C/200D/2060/FEFF) и variation selectors (U+FE00–FE0F). Шаг третий — если zero-width использованы как биты, определи маппинг и собери байты. Шаг четвёртый — проверь bidi-символы (U+202A–202E, U+2066–2069).

```bash
python3 -c "import sys; t=open(sys.argv[1],encoding='utf-8').read(); print([hex(ord(c)) for c in t if 0x200b<=ord(c)<=0x206f])" README.md
```

## Разбор примера: zero-width как биты

Zero-width символы часто используют как биты. Маппинг: один символ = 0, другой = 1. Определить маппинг можно по двум разным символам, встречающимся в невидимой области.

```python
t = open("msg.txt", encoding="utf-8").read()
alphabet = sorted({c for c in t if ord(c) in (0x200B, 0x200C, 0x200D)})
print("alphabet:", [hex(ord(c)) for c in alphabet])
bits = "".join("0" if c == alphabet[0] else "1" for c in t if c in alphabet)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data)
```

Если маппинг неочевиден, перебери варианты (0/1 в обе стороны) и проверь, где результат осмыслен. Аналогично для variation selectors и bidi.

Инструменты: `python3`, `xxd`, декодеры (`unicode-stego`, `zwsp-steg`). Помни: невидимые символы переносятся при копировании текста, поэтому канал «путешествует» незаметно. Для детекта — скрипт, выводящий статистику по диапазонам кодов.

## Сводка по Unicode-стего

Невидимые символы: Tags (U+E0000–E007F), variation selectors (U+FE00–FE0F, U+E0100–E01EF), zero-width (U+200B/200C/200D/2060/FEFF), bidi (U+202A–202E, U+2066–2069). Декодирование — перебор кодов и маппинг в ASCII/биты. Инструменты: `python3`, `xxd`, декодеры. Работает в любом тексте и переносится при копировании.

## Последнее замечание

Для детекта невидимых символов удобно держать скрипт, который считает частоту кодов по диапазонам: Tags, variation selectors, zero-width, bidi. Любое ненулевое значение в этих диапазонах в «обычном» тексте — подозрительно. Это самый быстрый способ обнаружить канал, не зная заранее, какой именно механизм использован.

## Что мы теперь знаем
- Unicode Tags (`U+E0000..E007F`) кодируют ASCII и невидимы.
- Вариационные селекторы и zero-width-символы — каналы прямо в тексте.
- Такой текст переживает копирование и ломает сравнение строк.
- Очистка требует нормализации Unicode (NFKC) и удаления управляющих символов.
