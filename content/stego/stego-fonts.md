Шрифт — это тоже контейнер: файл (TTF/OTF/WOFF) содержит контуры глифов, метрики, кернинг и десятки таблиц. Каждый из этих слоёв можно модулировать: слегка изменить контур, сдвинуть пару кернинга, спрятать данные в неиспользуемой таблице или в порядке глифов. А на уровне вёрстки документа данные прячут в кернинге, трекинге и пробелах — так делают «водяные знаки» для отслеживания утечек.

## Где в шрифте прячут данные

- **Контуры глифов.** Младшие разряды координат точек контура — аналог LSB, но в векторной графике.
- **Таблицы OpenType.** Помимо стандартных (`glyf`, `cmap`, `kern`), есть редко проверяемые таблицы; можно добавить кастомную.
- **Кернинг/трекинг.** Значения пар кернинга кодируют биты.
- **Порядок глифов.** Перестановка в `cmap`/`post` кодирует данные.
- **Имена.** Поля `name` (copyright, version) часто содержат скрытый текст/base64.
- **Хинтинг и инструкции.** Bytecode TrueType-инструкций — ниша для сокрытия.

## Инструменты и команды

- **`fontTools` (Python)** — разбор и правка шрифтов.
- **`ttx`** — шрифт ↔ XML, удобно смотреть все таблицы.
- **`FontForge`** — визуальный редактор.
- **`ots-sanitize`** — валидация/санитизация.
- **`exiftool`** — метаданные файла шрифта.

Дамп всех таблиц в XML:

```bash
ttx font.ttf          # создаст font.ttx со всеми таблицами
```

Список таблиц и их размеров:

```python
from fontTools.ttLib import TTFont
f = TTFont("font.ttf")
for tag in f.keys():
    print(tag, f.reader.tables[tag].length if hasattr(f, "reader") else "")
```

## Разобранный пример: данные в таблице name

Скрытый текст часто лежит в именах:

```bash
$ ttx -t name font.ttf -o name.ttx
$ grep -iE 'flag|base64|copyright|version' name.ttx
<string>flag{font_name}</string>
```

Если данных в `name` нет — проверяем координаты контуров на младшие биты:

```python
from fontTools.ttLib import TTFont
f = TTFont("font.ttf")
glyf = f["glyf"]
bits = []
for gname in f.getGlyphOrder():
    g = glyf[gname]
    if g.isComposite():
        continue
    for x, y in g.coordinates:
        bits.append(x & 1)
bits = bits[: len(bits)//8*8]
msg = bytes(int("".join(map(str, bits[i:i+8])), 2)
            for i in range(0, len(bits), 8))
print(msg)
```

## Кернинг и вёрстка как канал

На уровне документа (PDF, DOCX) кернинг и трекинг между конкретными парами символов можно варьировать на доли пункта — глаз не заметит, а парсер извлечёт биты. Это классический метод «отслеживания» документа (fingerprinting): у каждого получателя свой узор, по утечке находят источник.

Извлечение кернинга из PDF:

```bash
pdftotext -layout doc.pdf -         # позиции/пробелы могут выдать узор
mutool draw -F txt doc.pdf          # координаты глифов
```

В DOCX кернинг живёт в настройках run (`w:spacing`); кастомный парсер `document.xml` покажет значения `w:kern`/`w:spacing`, которые могут кодировать данные.

## Сравнение каналов в шрифтах

| Канал | Где | Ёмкость | Заметность |
|---|---|---|---|
| Контуры глифов | координаты | высокая | очень низкая |
| Таблица name | строки метаданных | низкая | низкая |
| Кастомная таблица | OTF | высокая | низкая |
| Кернинг | пары глифов | средняя | очень низкая |
| Порядок глифов | cmap/post | средняя | средняя |
| Хинтинг-байткод | инструкции | средняя | высокая |

## Частые ошибки и подводные камни

- **Смотреть только текст, не сам шрифт.** Данные могут быть в контурах.
- **Игнорировать `name`.** Там чаще всего и лежит строка.
- **Забыть про кернинг документа.** Он не виден в текстовом извлечении.
- **Ломать валидность.** Грубая правка шрифта делает его нерабочим (`ots-sanitize`).
- **Пропускать составные глифы.** Composite-глифы ссылаются на другие.
- **Не проверять несколько таблиц.** Данные могут быть размазаны по слоям.

## Что дальше / решение

- `ttx font.ttf` — посмотрите все таблицы; ищите `flag`/base64 в `name`.
- Проверьте координаты контуров на младшие биты (`fontTools`).
- Для документов — анализируйте кернинг/трекинг (`mutool`, `pdftotext -layout`).
- Проверьте кастомные/нестандартные таблицы OpenType.
- Если шрифт чист — переходите к стеганографии в исходном коде (`stego-code`).

## Форматы шрифтов и их отличия

- **TrueType (TTF)** — квадратичные кривые, таблицы `glyf`/`loca`.
- **OpenType (OTF)** — либо CFF (кубические кривые), либо обёртка TrueType.
- **WOFF/WOFF2** — веб-шрифты, обычно сжатые (WOFF2 — Brotli).
- **Type 1 / PFB** — исторический PostScript-формат.
- **Битовые шрифты (BDF/PCF)** — растровые.

Для стеганографии важнее всего TTF/OTF: у них богатая табличная структура и координаты глифов.

```bash
file font.ttf
otfinfo -i font.otf        # метаданные (если установлен lcdf-typetools)
```

## Таблицы OpenType: карта для поиска

Основные таблицы: `cmap` (отображение символов в глифы), `glyf`/`CFF ` (контуры), `head` (глобальные параметры), `hmtx` (метрики), `kern`/`GPOS` (кернинг), `name` (имена), `post` (PostScript-имена глифов), `DSIG` (подпись). Каналы:

- **`name`** — строки copyright/version часто несут скрытый текст.
- **`cmap`** — лишние/неиспользуемые отображения.
- **`post`** — имена глифов могут содержать данные.
- **Кастомная таблица** — можно добавить свою.

```python
from fontTools.ttLib import TTFont
f = TTFont("font.ttf")
print(sorted(f.keys()))
for rec in f["name"].names:
    if rec.nameID in (0, 5):     # copyright, version
        print(rec.toUnicode())
```

## Кернинг и GPOS

Продвинутый кернинг в OpenType живёт в таблице `GPOS` (Glyph Positioning): пары `(глиф1, глиф2) → сдвиг`. Значения сдвига можно варьировать на доли единицы, кодируя биты. Визуально текст не меняется, а извлечение — прямое: читаем `GPOS` и смотрим на «нестандартные» значения.

```python
from fontTools.ttLib import TTFont
f = TTFont("font.ttf")
gpos = f.get("GPOS")
print(gpos)   # структура позиционирования
```

## Встраивание данных: практика

Мини-пример: спрятать байты в младших битах координат контура.

```python
from fontTools.ttLib import TTFont
f = TTFont("font.ttf")
glyf = f["glyf"]
secret = b"HI"
bits = "".join(f"{b:08b}" for b in secret)
i = 0
for gname in f.getGlyphOrder():
    g = glyf[gname]
    if g.isComposite():
        continue
    coords = list(g.coordinates)
    for k in range(len(coords)):
        x, y = coords[k]
        if i < len(bits):
            x = (x & ~1) | int(bits[i]); i += 1
            coords[k] = (x, y)
    g.coordinates = coords
f.save("stego.ttf")
```

Извлечение — обратная операция: собрать младшие биты в том же порядке.

## Отслеживание документов (fingerprinting)

Издатели и DLP-системы встраивают в вёрстку «водяной знак»: у каждого получателя свой узор сдвигов, интервалов и синонимов. По утёкшему документу находят источник. Обнаружить такой знак можно, сравнив несколько копий документа: там, где копии различаются в мелочах (пробелы, сдвиги), и спрятан идентификатор.

## Сводка инструментов

| Инструмент | Назначение |
|---|---|
| `ttx` | шрифт ↔ XML, все таблицы |
| `fontTools` | разбор/правка в Python |
| `FontForge` | визуальное редактирование |
| `ots-sanitize` | валидация шрифта |
| `mutool` | извлечение координат глифов из PDF |
| `pdftotext -layout` | сохранение раскладки (кернинг) |

```bash
ttx -l font.ttf            # список таблиц
ots-sanitize font.ttf      # проверка на битые таблицы
```

## Ограничения

- **Хрупкость**: правка контуров ломает хинтинг и растеризацию.
- **Валидация**: `ots-sanitize` отбросит некорректный шрифт.
- **Документы нормализуются**: при печати/конвертации кернинг теряется.
- **Размер**: большой объём данных требует много глифов.
