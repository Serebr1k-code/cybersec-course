## Вопрос, с которого всё начинается
YAML — формат конфигов «для людей»: отступы, комментарии, якоря. Эта гибкость —
подарок для стеганографии. Здесь можно спрятать данные в комментариях, в
повторяющихся пробелах, в якорях и алиасах, в стиле блочных скаляров — и файл
останется валидным. Ты получил `config.yaml`; где искать?

## Наш пример
Возьмём `config.yaml` небольшого сервиса. Разберём, как в нём закодирована
строка через якорь и base64.

## Шаг 1: комментарии
YAML-комментарий начинается с `#` и идёт до конца строки. Парсер его отбрасывает
целиком. Значит, в комментарии можно положить что угодно:

```yaml
version: 3
# build metadata: none
```

`yq` и `python3 -c 'import yaml'` комментарии не видят — а `grep` видит.

## Шаг 2: якоря и алиасы
Якорь (`&имя`) помечает узел, алиас (`*имя`) на него ссылается. Значение якоря
доступно в двух местах, и его легко спрятать в «техническом» поле:

```yaml
config: &flag "bnRve3lhbWxfYW5jaG9yX2I2NH0="
name: *flag
```

Строка — base64; после декодирования получаем сообщение. Ни один валидатор не
заподозрит неладное: это просто строка конфигурации.

## Шаг 3: блочные скаляры и стиль
Строку можно записать минимум четырьмя способами:
- `plain: abc`
- `single: 'abc'`
- `double: "abc"`
- `block: |` (literal) или `>` (folded).

Один и тот же текст в разных стилях — разное представление, и это канал:
выбор стиля кодирует биты.

## Шаг 4: документы и директивы
YAML-файл может содержать несколько документов, разделённых `---` и закрываемых
`...`. Лишние документы, директивы `%YAML` и `%TAG`, а также пустые документы —
тоже свободное место.

## Шаг 5: извлечение вручную
```python
import base64, re
text = open('config.yaml', encoding='utf-8').read()
m = re.search(r'&flag\s+"([^"]+)"', text)
print(base64.b64decode(m.group(1)).decode())
```

Вывод:

```
nto{yaml_anchor_b64}
```

## Шаг 6: инструменты
- `yq . config.yaml` — нормализованный разбор (якоря раскрываются).
- `python3 -c 'import yaml,sys; print(yaml.safe_load(open("config.yaml")))'`.
- `grep -n '#' config.yaml` — комментарии.

## YAML как текстовый контейнер

YAML богат синтаксисом, и это даёт много каналов. Первый — **комментарии** (`# ...`): они не влияют на данные, но лежат в файле. Второй — **якоря и алиасы** (`&a`/`*a`): позволяют ссылаться на узлы; лишние/неиспользуемые якоря могут нести данные. Третий — **стиль скаляров**: строку можно записать как `plain`, `'single'`, `"double"`, блочным (`|`) или folded (`>`); выбор стиля кодирует биты.

```yaml
key: value          # plain
key: "value"        # double
key: 'value'        # single
key: |
  value            # block
```

Четвёртый — **отступы и пробелы** (как в JSON). Пятый — **порядок ключей** (в YAML, как и в JSON, порядок не определён, но парсеры сохраняют). Шестой — **порядок документов** (`---` разделяет документы в потоке). Седьмой — **директивы** (`%YAML`, `%TAG`). Восьмой — **теги** (`!!str`, `!!int`, кастомные `!mytag`).

## Извлечение и инструменты

```bash
grep -n "#" data.yaml | head
grep -nE "&[a-zA-Z]|\*[a-zA-Z]" data.yaml
grep -nE "^---" data.yaml
```

Извлечение по каналу: комментарии — регуляркой; якоря — поиском `&`/`*`; стиль — сравнением с нормализованной сериализацией (`yaml.safe_load` + `yaml.dump`). Невидимые символы и хвостовые пробелы — как в любом тексте, скриптом.

```python
import yaml
data = yaml.safe_load(open("data.yaml"))
print(yaml.dump(data, default_flow_style=False))   # нормализованный вид
```

Инструменты: `python3` (`yaml`, `re`), `grep`, `xxd`, `cat -A`. Сравнение с нормализованной сериализацией — быстрый способ найти канал в структуре.

Типичные ошибки: смотреть только значения, а не комментарии/якоря/стиль; игнорировать порядок документов; не проверять невидимые символы. YAML — текстовый формат, поэтому все текстовые каналы применимы, плюс специфичные для YAML (якоря, стили, теги).

## Практический сценарий

Сценарий: флаг в комментариях. `grep -n "#" data.yaml` показывает строки с `#`, среди них — флаг. Сценарий второй: данные в неиспользуемых якорях — определяешь якоря, проверяешь, какие из них не используются алиасами. Сценарий третий: стиль скаляров кодирует биты — сравниваешь с нормализованным `yaml.dump` и считаешь различия.

Сценарий четвёртый: несколько документов в потоке (`---`), и один из них содержит данные, не ожидаемые приложением. Пятый: кастомный тег (`!secret`) с полезной нагрузкой. Шестой: невидимые Unicode-символы в значениях.

Итог: YAML — текстовый контейнер с богатым синтаксисом, поэтому каналов много. Проверяй комментарии, якоря, стили, документы, теги и невидимые символы. Работай с байтами и сравнивай с нормализованной версией — это выявляет структурные каналы.

## Практика: якоря, стили и документы

Сценарий с якорями. YAML позволяет ссылаться на узлы через `&anchor` и `*alias`. Неиспользуемый якорь — канал.

```yaml
a: &x nto{flag}     # якорь с данными
b: 1                # &x не используется
```

Найти якоря: `grep -nE "&[a-zA-Z_]" data.yaml`; проверить, используются ли они (`grep -nE "\*[a-zA-Z_]" data.yaml`). Неиспользуемые — подозрительны.

Сценарий со стилями: одна и та же строка может быть записана по-разному. Сравни файл с нормализованной сериализацией:

```bash
python3 -c "import yaml,sys; print(yaml.dump(yaml.safe_load(open('data.yaml')), default_flow_style=False))" > norm.yaml
diff data.yaml norm.yaml | head
```

Различия покажут скрытые каналы (пробелы, стиль, порядок, комментарии — нормализация их теряет).

## Практика: несколько документов и теги

YAML-поток может содержать несколько документов, разделённых `---` (и заканчивающихся `...`). Лишний документ — канал.

```yaml
---
main: config
---
secret: nto{flag}
```

Найти: `grep -nE "^---|^\.\.\." data.yaml`. Разобрать каждый документ отдельно. Второй канал — теги: `!!str`, `!!int`, кастомные `!secret`. Кастомный тег с payload — явный сигнал.

```bash
grep -nE "!!|![a-zA-Z]" data.yaml
```

Третий — директивы `%YAML`/`%TAG` с нестандартными значениями. Четвёртый — комментарии внутри многострочных скаляров (`|`, `>`), которые тоже сохраняются в тексте.

Инструменты: `grep`, `python3` (`yaml`, `re`), `xxd`, `cat -A`. Все каналы YAML — это текстовые каналы плюс специфичные для синтаксиса (якоря, стили, теги, документы). Сравнение с нормализованной версией и работа с байтами закрывают большинство задач.

## Разбор примера: комментарий и якорь

Сценарий первый: флаг в комментарии. `grep -n "#" data.yaml` покажет все комментарии; среди них — флаг. Сценарий второй: данные в неиспользуемом якоре.

```yaml
config: &c
  debug: false
secret: nto{flag}
# якорь &c объявлен, но нигде не используется
```

Шаг: найти якоря (`grep -nE "&[a-zA-Z_]"`), затем алиасы (`grep -nE "\*[a-zA-Z_]"`); якоря без алиасов — подозрительны. Третий сценарий: стиль скаляров — сравни нормализованной сериализацией (`yaml.safe_load` + `yaml.dump`). Четвёртый: несколько документов (`---`) — разбери каждый.

```bash
python3 -c "import yaml; print(yaml.dump(yaml.safe_load(open('data.yaml')),default_flow_style=False))" > norm.yaml && diff data.yaml norm.yaml | head
```

Пятый: кастомные теги (`!secret`) и директивы. Шестой: невидимые Unicode и хвостовые пробелы (как в любом тексте).

## Разбор примера: документы и теги

YAML-поток может содержать несколько документов. Приложение читает обычно первый, а остальные игнорирует — это канал.

```bash
grep -nE "^---" data.yaml
```

Прочитай каждый документ отдельно (`yaml.safe_load_all`). Дальше — теги: `grep -nE "!!|![a-zA-Z]" data.yaml`. Кастомный тег `!flag` с payload — явный канал. Директивы `%YAML 1.2` / `%TAG` с нестандартными значениями — тоже.

```python
import yaml
for i, doc in enumerate(yaml.safe_load_all(open("data.yaml"))):
    print(i, doc)
```

Инструменты: `grep`, `python3` (`yaml`, `re`), `xxd`, `cat -A`. Все каналы YAML — текстовые плюс синтаксические (якоря, стили, теги, документы). Работа с байтами и сравнение с нормализованной версией закрывают большинство задач.

## Дополнительные каналы YAML

Ещё места в YAML: **блочные скаляры** (`|`, `>`) с лишними отступами и переводами строк; **folded vs literal** — один и тот же текст разными стилями; **порядок ключей** внутри маппинга; **дубли ключей** (последний выигрывает); **числа в разных формах** (`0x10`, `16`, `0o20`); **логические значения** (`true`, `yes`, `on`); **null** (`~`, `null`, пусто). Каждый выбор формы кодирует биты.

Также **теги** (`!!str`, `!custom`) и **директивы** (`%YAML`, `%TAG`). И **комментарии внутри** многострочных скаляров. Все эти каналы выявляются сравнением с нормализованной сериализацией или ручным разбором структуры.

## Сводка по YAML

YAML — текстовый контейнер с богатым синтаксисом. Каналы: комментарии, якоря/алиасы, стиль скаляров, отступы, порядок ключей, документы (`---`), теги, директивы, невидимые Unicode. Инструменты: `grep`, `python3` (`yaml`), `xxd`. Работай с байтами и сравнивай с нормализованной версией.

## Последнее замечание по YAML

Обрати внимание на **порядок документов** и **завершающий маркер** `...`: поток может содержать документ, который приложение не читает, но который лежит в файле. И на **табуляции**: YAML запрещает табы для отступов, поэтому если они есть — либо это не валидный YAML, либо табы используются как канал. Проверь `cat -A data.yaml` на наличие `^I` (табов) и хвостовых пробелов.

## Резюме

YAML: комментарии, якоря/алиасы, стиль скаляров, отступы, порядок, документы, теги, директивы, невидимые Unicode. Сравнивай с нормализованной сериализацией и работай с байтами; табы и хвостовые пробелы — тоже каналы.

## Что мы теперь знаем
- Комментарии, якоря, стиль скаляров и документы — каналы в YAML.
- Якорь с base64-строкой — компактный и незаметный приём.
- Нормализация через `yq`/`safe_load` уничтожает часть каналов.
- Скрытность YAML-канала — в том, что всё выглядит как обычный конфиг.

Этого набора проверок достаточно для большинства задач на YAML.
