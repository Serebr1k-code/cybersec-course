## Вопрос, с которого всё начинается

Тебе дали файл `video.mp4` — короткий ролик. Где в нём может быть спрятан флаг? Казалось бы, нужно смотреть каждый кадр. Но на деле видео — это не один поток, а **несколько**: видеодорожка, аудиодорожка, метаданные, вложения. И флаг часто лежит в самом «скучном» из них.

В этом уроке мы разберём один MP4 и пройдём по каналам в правильном порядке — от самого дешёвого к самому трудоёмкому.

## Наш пример: video.mp4

Сначала посмотрим, что вообще внутри файла. `ffprobe` (из пакета `ffmpeg`) показывает потоки, кодеки и теги.

```
$ ffprobe -v error -show_streams -show_format video.mp4 | head -20
[STREAM]
index=0
codec_name=h264
width=640
height=480
[/STREAM]
[STREAM]
index=1
codec_name=aac
channels=2
[/STREAM]
[FORMAT]
format_name=mov,mp4,m4a
duration=10.000000
```

Читаем: два потока — видео (H.264, 640×480) и аудио (AAC, стерео), длительность 10 секунд. Это **контейнер** MP4, внутри которого лежат независимые дорожки.

## Шаг 1: метаданные контейнера — самое дешёвое

Прежде чем лезть в кадры, проверь теги. В MP4 есть блоки метаданных (`moov`/`udta`), где можно писать произвольные строки.

```
$ ffprobe -v error -show_entries format_tags video.mp4
TAG:title=Challenge
TAG:comment=ZmxhZ3ttcDRfbWV0YX0=
```

Тег `comment` выглядит как base64 (набор букв и цифр). Декодируем:

```
$ echo ZmxhZ3ttcDRfbWV0YX0= | base64 -d
flag{mp4_metadata}
```

Флаг нашёлся на первом же шаге, даже не дойдя до кадров. Поэтому правило: **видео-задачу всегда начинай с разбора контейнера**, а не с покадрового анализа.

## Шаг 2: аудиодорожка — отдельный канал

Извлечём аудио отдельным файлом (`-vn` — «без видео») и посмотрим на спектрограмму — картинку, где по осям время и частота, а яркость = громкость.

```
$ ffmpeg -i video.mp4 -vn -acodec pcm_s16le audio.wav
$ sox audio.wav -n spectrogram -o spec.png
```

На спектрограмме очень часто виден **текст** — его специально «рисуют» высокочастотными сигналами. Открой `spec.png` и посмотри глазами. Это классика аудиостего.

## Шаг 3: скрытые кадры

Если метаданные и аудио пусты — переходим к видео. Извлечём все кадры в PNG (`-vsync 0` запрещает дублировать кадры, иначе нумерация собьётся).

```
$ mkdir frames && ffmpeg -i video.mp4 -vsync 0 frames/%05d.png
$ ls frames | wc -l
250
$ ls -lS frames | head -3
-rw-r--r-- 1 user user 84210 frames/00037.png
-rw-r--r-- 1 user user 12480 frames/00001.png
```

`ls -lS` сортирует по размеру: кадр `00037.png` резко больше остальных. Это подозрительно — возможно, он и есть «лишний». Проверим его на LSB:

```
$ zsteg frames/00037.png | grep -i text
b1,rgb,lsb,xy .. text: "flag{hidden_frame}"
```

Кадр с текстом или с резко другим размером — самый частый признак закладки.

## Шаг 4: LSB в кадрах — только для несжатых

Важный нюанс: LSB напрямую работает только для **несжатых** кадров (PNG, BMP, MJPEG). В H.264/HEVC применяется сжатие с потерями, как в JPEG, — младшие биты разрушаются. Поэтому стратегия такая: извлечь кадры в PNG, а потом применять обычный арсенал изображений.

Ещё один приём — **вычитание кадров**: данные кодируют в разнице между соседними кадрами.

```python
from PIL import Image, ImageChops
a = Image.open('frames/00001.png'); b = Image.open('frames/00002.png')
ImageChops.difference(a, b).save('diff.png')
```

На `diff.png` может проступить то, что незаметно при воспроизведении.

## Шаг 5: дописанное и вложения

Как и в любом формате, после конца видео можно дописать файл — плеер его проигнорирует.

```
$ binwalk video.mp4
$ xxd video.mp4 | tail -5
```

А контейнер MKV поддерживает **вложения** (`Attachments`) — туда кладут целые файлы:

```
$ mkvinfo video.mkv | grep -i attach
$ mkvextract attachments video.mkv 1:attached.bin
```

## Порядок действий для видео-задачи

1. `ffprobe -show_streams -show_format` — потоки и теги.
2. `exiftool` / `-show_entries format_tags` — метаданные.
3. `strings -n 6 video.mp4 | grep -iE 'flag|http|base64'` — быстрые подсказки.
4. `-vn` извлечь аудио → спектрограмма (`sox`) → LSB-скрипт.
5. Кадры в PNG (`-vsync 0`) → подозрительные по размеру → `zsteg`.
6. `binwalk` + `xxd | tail` — дописанное.
7. MKV → `mkvinfo`/`mkvextract` — вложения.

## Если не сработало

- Не перекодируй видео — перекодирование уничтожает LSB в кадрах и меняет метаданные. Работай с копией оригинала.
- Проверь, нет ли **нескольких** аудиодорожек (`ffprobe` покажет все).
- Сравни кадры вычитанием, если ни один не «выбивается» по размеру.
- Для H.264 попробуй методы в DCT-коэффициентах (см. урок про JPEG).

## Что мы теперь знаем

1. Видео — контейнер с несколькими независимыми каналами.
2. Начинать надо с метаданных контейнера — часто флаг там.
3. Аудиодорожка — отдельный канал (спектрограмма, LSB, `steghide`).
4. Скрытый кадр находят по размеру или вычитанием.
5. LSB в кадрах работает только для несжатых; H.264 сжатие с потерями.

## Шаг 6: глубокий разбор контейнера MP4

MP4 устроен как дерево **боксов** (атомов): `ftyp`, `moov`, `mdat`, `moof`, `udta`. `mdat` содержит медиаданные, `moov` — метаданные и таблицы. Полезные для стеганографии места:

- **`udta`** — пользовательские данные, сюда пишут кастомные теги;
- **`free`/`skip`** — «пустые» боксы, которые можно заполнить;
- **`©xyz`-теги** в `moov/udta` — строки, где прячут base64;
- **пространство между боксами** — padding, не влияющий на воспроизведение.

Посмотреть дерево боксов можно без специальных инструментов:

```
$ AtomicParsley video.mp4 -t
$ strings -n 6 video.mp4 | grep -iE 'flag|base64|http'
```

## Шаг 7: MKV и вложения

MKV (Matroska) — EBML-формат с элементами `Segment`, `Tracks`, `Attachments`, `Tags`. `mkvinfo` показывает всё дерево, `mkvextract` извлекает дорожки и вложения:

```
$ mkvinfo video.mkv | grep -iE 'attachment|title|tag'
$ mkvextract attachments video.mkv 1:attached.bin
```

Вложения в MKV — полноценный канал: туда можно положить ZIP или PE, и плеер его не тронет.

## Шаг 8: таблица методов и стратегия

| Метод | Где данные | Устойчивость | Инструмент |
|---|---|---|---|
| Метаданные контейнера | `udta`/`Tags` | высокая | `ffprobe`, `exiftool` |
| Скрытый кадр | в потоке кадров | средняя | `ffmpeg` + просмотр |
| LSB в несжатых кадрах | пиксели PNG | низкая | `zsteg` |
| Аудиодорожка | аудиопоток | средняя | `sox`, LSB-скрипт |
| Дописанный файл | после контейнера | высокая | `binwalk` |
| Вложение (MKV) | `Attachments` | высокая | `mkvextract` |

Стратегия: сначала «высокоустойчивые» и дешёвые каналы (метаданные, вложения, дописанное), затем кадры и аудио.

## Шаг 9: практические подсказки

Если все кадры «одинаковы» по размеру, но видео странное — смотри метаданные и аудио. Если разница везде большая (сжатие с потерями) — извлекай кадры в PNG без потерь и сравнивай по перцептивному хешу. Не забывай про несколько аудиодорожек: `ffprobe` покажет все.

Не перекодируй видео без нужды: перекодирование уничтожает LSB-каналы в кадрах и меняет метаданные. Работай с копией оригинала.

```
$ cp video.mp4 work.mp4
$ ffprobe -v error -show_entries stream=index,codec_type,codec_name work.mp4
```

В отчёте фиксируй канал (метаданные/аудио/кадр/вложение), номер «выбивающегося» кадра и извлечённый артефакт — иначе результат невоспроизводим.

## Куда дальше

Дальше — **сетевая стеганография**: там носителем становится не файл, а последовательность пакетов, и данные прячут в полях заголовков и таймингах. А пока запомни: видео — это контейнер, и разбирать его надо по каналам, начиная с метаданных.

## Где пригодится

- **CTF (Steganography):** .mp4/.mkv/.avi задачи — проверка навыков работы с потоками.
- **Forensics:** анализ видео как контейнера для полезной нагрузки.
- **Blue team:** детект данных в метаданных и вложениях медиаконтейнеров.
- **Повседневность:** понимание, что метаданные видео могут нести лишнее.
