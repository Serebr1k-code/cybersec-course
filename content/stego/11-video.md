## Видео как многоканальный носитель

Видео — не один файл, а контейнер, внутри которого лежат несколько независимых потоков: видеодорожка (последовательность кадров), аудиодорожка (одна или несколько), субтитры, метаданные и произвольные вложения. Каждый из этих слоёв — отдельный канал для сокрытия данных. Именно поэтому видеостеганография «многослойна»: пока вы разбираете кадры, флаг может лежать в аудиодорожке или в метаданных контейнера.

Основные каналы:

- **Покадровый** — данные в различиях между кадрами, в «лишних» кадрах или в LSB пикселей.
- **Аудио** — отдельная дорожка со своим LSB/спектрограммой.
- **Контейнерный** — метаданные MP4/MKV, теги, названия дорожек.
- **Вложенный** — дописанный архив или второй файл после корректного контейнера.

Практический вывод: видео-задачу всегда начинайте с **разбора контейнера**, а не с покадрового анализа. Часто ответ находится в метаданных или в отдельной дорожке, и лезть в кадры вовсе не нужно.

## Разбор контейнера: ffmpeg и ffprobe

`ffprobe` показывает структуру контейнера: какие потоки, кодеки, длительность, метаданные.

```bash
$ ffprobe -v error -show_streams -show_format video.mp4
[STREAM] index=0 codec_name=h264 width=640 height=480
[STREAM] index=1 codec_name=aac channels=2
[FORMAT] format_name=mov,mp4,m4a duration=10.0
$ ffprobe -v error -show_entries format_tags video.mp4
TAG:title=Challenge
TAG:comment=ZmxhZ3ttcDRfbWV0YX0=
```

`ffmpeg` умеет извлекать отдельные потоки: `-an` (без аудио), `-vn` (без видео). Это первый шаг: разложить видео на составляющие и разбирать каждую по отдельности.

```bash
ffmpeg -i video.mp4 -map 0:v -c copy video_only.mp4
ffmpeg -i video.mp4 -map 0:a -c copy audio_only.aac
```

## Скрытые кадры и покадровые различия

Один из самых частых приёмов — **вставить лишний кадр**, который мелькает мгновение и не виден при обычном просмотре. Извлеките все кадры и просмотрите их:

```bash
mkdir frames && ffmpeg -i video.mp4 -vsync 0 frames/%05d.png
ls frames | wc -l
# быстрый поиск "выбивающегося" кадра — по размеру файла
ls -lS frames | head
```

Кадр с флагом часто либо резко отличается по размеру, либо содержит текст. Альтернативно данные кодируют **в различиях** между соседними кадрами (побитово), что незаметно при воспроизведении, но извлекается вычитанием кадров:

```python
from PIL import Image, ImageChops
a = Image.open('frames/00001.png'); b = Image.open('frames/00002.png')
diff = ImageChops.difference(a, b)
diff.save('diff.png')
```

## LSB в кадрах

Если кадры сохранены как несжатые PNG/BMP, к ним применим обычный LSB: `zsteg`, скрипт на Pillow. Для сжатых (H.264) LSB напрямую не работает — данные прячут либо в несжатых кадрах, либо в DCT-коэффициентах, либо в служебных полях. Поэтому стратегия: сначала извлечь кадры в PNG, затем применить весь арсенал изображений.

```bash
ffmpeg -i video.mp4 -vsync 0 frames/%05d.png
for f in frames/0000*.png; do zsteg "$f" 2>/dev/null | grep -i flag && echo "HIT $f"; done
```

Вручную — только для подозрительных кадров, найденных по размеру/различию.

## Аудиодорожка как отдельный канал

Аудио в видео разбирается теми же инструментами, что и обычный WAV: LSB-скрипт, спектрограмма, `steghide`. Извлеките дорожку и примените пайплайн аудио.

```bash
ffmpeg -i video.mp4 -vn -acodec pcm_s16le audio.wav
sox audio.wav -n spectrogram -o spec.png     # визуальный канал
steghide extract -sf audio.wav               # парольная стеганография
```

Часто на спектрограмме аудиодорожки видео виден текст или QR-код — это классика.

## Метаданные контейнера MP4/MKV

MP4 (ISO BMFF) и MKV (Matroska) содержат боксы/элементы с метаданными. В MP4 это `moov`/`udta`/`©xyz`-теги; в MKV — `Tags`/`Info`. Смотреть удобно `ffprobe` и `exiftool`.

```bash
exiftool video.mp4 | grep -iE 'comment|title|author|keyword'
ffprobe -v error -show_entries format_tags video.mp4
```

Помимо стандартных тегов, в контейнере могут быть **кастомные** метаданные и даже произвольные строки — ищите base64 и `flag{` через `strings`.

## Дописанные данные и вложенные потоки

Как и в других форматах, после корректного видео можно **дописать** файл: плеер его проигнорирует.

```bash
binwalk video.mp4
xxd video.mp4 | tail -5
```

MKV поддерживает **вложения** (`Attachments`) — туда можно положить произвольный файл:

```bash
mkvinfo video.mkv | grep -i attach
```

## Инструменты

- **`ffmpeg`/`ffprobe`** — разбор, извлечение потоков и кадров.
- **`mkvinfo`/`mkvextract`** — разбор Matroska/MKV.
- **`zsteg`/Pillow** — LSB в извлечённых кадрах.
- **`sox`/`multimon-ng`** — аудиодорожка.
- **`exiftool`** — метаданные контейнера.
- **`binwalk`/`foremost`** — вложенные/дописанные данные.

## Разобранный пример

```bash
$ ffprobe -v error -show_entries format_tags video.mp4 | grep -i comment
TAG:comment=flag{mp4_metadata}
$ ffmpeg -i video.mp4 -vn -acodec pcm_s16le a.wav
$ sox a.wav -n spectrogram -o s.png     # на спектре виден текст
$ mkdir fr && ffmpeg -i video.mp4 -vsync 0 fr/%05d.png
$ ls -lS fr | head -2                   # один кадр сильно больше
$ zsteg fr/00037.png | grep -i text
```

Маршрут: метаданные → аудиодорожка/спектр → кадры/LSB → вложенное. Так закрываются почти все видео-задачи, причём обычно хватает первых двух шагов.

## Частые ошибки и подводные камни

- **Начинать с покадрового LSB**, пропустив метаданные и аудио.
- **Извлекать кадры в JPEG** — потеряете LSB; используйте PNG.
- **Пропускать `-vsync 0`** — иначе дубликаты кадров исказят нумерацию.
- **Не смотреть MKV-вложения** — там может быть целый файл.
- **Игнорировать дописанный хвост** — `binwalk`/`xxd | tail`.
- **Забыть про несколько аудиодорожек** — бывает не одна.

## Глубокий разбор контейнеров MP4 и MKV

MP4 устроен как дерево **боксов** (атомов): `ftyp`, `moov`, `mdat`, `moof`, `udta` и т. д. `mdat` содержит собственно медиаданные, `moov` — метаданные и таблицы. Полезные для стеганографии места:

- **`udta`** — пользовательские данные, сюда часто пишут кастомные теги.
- **`free`/`skip`** — «пустые» боксы, которые можно заполнить данными.
- **`©xyz`**-теги в `moov/udta` — строки, где прячут base64.
- **Пространство между боксами** — padding, не влияющий на воспроизведение.

Просмотреть дерево боксов без специальных инструментов можно через `strings` и `xxd`, а также `AtomicParsley`:

```bash
AtomicParsley video.mp4 -t          # все теги
strings -n 6 video.mp4 | grep -iE 'flag|base64|http'
```

MKV (Matroska) — EBML-формат с элементами `Segment`, `Tracks`, `Attachments`, `Tags`. `mkvinfo` показывает всё дерево, `mkvextract` извлекает дорожки и вложения:

```bash
mkvinfo video.mkv | grep -iE 'attachment|title|tag'
mkvextract attachments video.mkv 1:attached.bin
```

Вложения в MKV — полноценный канал: туда можно положить ZIP/PE, и плеер его не тронет.

## Сравнение методов сокрытия в видео

| Метод | Где данные | Устойчивость | Инструмент |
|---|---|---|---|
| Метаданные контейнера | `udta`/`Tags` | высокая | `ffprobe`, `exiftool` |
| Скрытый кадр | в потоке кадров | средняя | `ffmpeg` + просмотр |
| Покадровое вычитание | разница кадров | средняя | Pillow/OpenCV |
| LSB в несжатых кадрах | пиксели PNG | низкая | `zsteg`, скрипт |
| Аудиодорожка | аудиопоток | средняя | `sox`, LSB-скрипт |
| Дописанный файл | после контейнера | высокая | `binwalk` |
| Вложение (MKV) | `Attachments` | высокая | `mkvextract` |

Стратегия: сначала «высокоустойчивые» и дешёвые каналы (метаданные, вложения, дописанное), затем кадры и аудио.

## Практический чек-лист видео-задачи

1. `ffprobe -show_streams -show_format` — потоки и теги.
2. `exiftool` — метаданные контейнера.
3. `strings -n 6 | grep -iE 'flag|http|base64'` — быстрые подсказки.
4. `-vn` извлечь аудио → аудио-пайплайн (LSB/спектр/steghide).
5. Кадры в PNG (`-vsync 0`) → подозрительные по размеру → `zsteg`.
6. `binwalk` + `xxd | tail` — дописанное.
7. MKV → `mkvinfo`/`mkvextract` — вложения.

## Инструменты глубоко

- **`ffmpeg`**: `-vsync 0` (без дублей кадров), `-map 0:v/-map 0:a` (выбор потоков), `-c copy` (без перекодирования).
- **`ffprobe`**: `-show_entries format_tags`, `-show_streams`, `-show_chapters`.
- **`mkvtoolnix`**: `mkvinfo`, `mkvextract`, `mkvmerge`.
- **`AtomicParsley`**: правка/чтение MP4-тегов.
- **`sox`/`multimon-ng`**: аудиодорожка.
- **`zsteg`/Pillow**: кадры.

Практический совет: не перекодируйте видео без нужды — перекодирование уничтожает LSB-каналы в кадрах и меняет метаданные. Работайте с оригиналом, копируя его для экспериментов.

## Итог по видеостеганографии

Видео выигрывает у статичных носителей тем, что даёт сразу несколько независимых каналов: метаданные контейнера, отдельная аудиодорожка, покадровые различия, LSB в несжатых кадрах и вложенные файлы. Практика показывает, что большинство задач решается на первых двух-трёх шагах, поэтому начинайте с разбора контейнера и аудио, а к покадровому анализу переходите только если там пусто. Универсальный совет: не перекодируйте видео, работайте с копией оригинала, и держите под рукой связку `ffprobe` → `ffmpeg -vn` → `sox` → `zsteg`.

## Что делать дальше / решение

- `ffprobe`/`exiftool` — структура и метаданные.
- `-vn` + аудио-пайплайн (LSB/спектр/steghide).
- Кадры в PNG + `zsteg` по подозрительным (по размеру/различию).
- `binwalk`/`mkvinfo` — вложенное и дописанное.
- Пусто — перепроверьте DCT/кодек-специфичные методы и сравните кадры.

## Где пригодится

- Видео-задачи объединяют навыки изображений, аудио и контейнеров — хорошая проверка всей ветки.
- Анализ потоков/боксов полезен в forensics и malware (видео как контейнер для полезной нагрузки).
- Frame differencing — общий приём видеонаблюдения и анализа движения.
