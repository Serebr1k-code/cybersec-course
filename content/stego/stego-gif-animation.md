GIF — формат палитровых изображений с поддержкой анимации. Помимо пикселей и палитры (см. `stego-palette-sort`), GIF хранит для каждого кадра две «служебные» величины: **задержку** (сколько кадр показывается, в сотых долях секунды) и **метод disposal** (что делать с областью перед следующим кадром). Обе не влияют на «смысл» картинки, но кодируют числа — а значит, идеальны для сокрытия. В CTF анимированный GIF с данными в таймингах — классика: картинка проигрывается нормально, а данные лежат в служебных полях.

## Анатомия GIF

- **Header/Logical Screen Descriptor.** Размер, флаги, фон, глобальная палитра.
- **Global/Local Color Table.** Палитра (до 256 цветов).
- **Graphic Control Extension (GCE).** Здесь `Delay Time` (2 байта) и `Disposal Method` (3 бита) — основной канал.
- **Image Descriptor + LZW-данные.** Пиксели кадра.
- **Application/Comment Extension.** Произвольные текстовые данные — тоже канал.
- **Trailer** (`0x3B`). Конец.

## Задержки кадров как канал

Задержка — 16-битное число в сотых секунды. В обычном GIF задержки «человеческие» (5–20 = 50–200 мс). Если в файле встречаются задержки вроде `1`, `2`, `4`, `8` — это похоже на биты или ASCII-коды. Простейшая схема: чётная задержка = бит 0, нечётная = бит 1; или кодировать байты напрямую значениями задержек. Проверить легко: извлечь список задержек и посмотреть.

## Метод disposal

Disposal method (0–3) говорит, как очищать область перед следующим кадром:

| Значение | Смысл |
|---|---|
| 0 | не указан |
| 1 | не очищать |
| 2 | очистить фоном |
| 3 | восстановить предыдущий |

Практически всё равно, какой из вариантов использовать для корректного проигрывания, поэтому последовательность disposal-методов можно использовать как троичный/четверичный код. В CTF встречается реже задержек, но проверять стоит.

## Порядок и число кадров

- **Порядок кадров.** Кадры можно переставить, а «правильный» порядок восстановить по данным (например, по номеру в комментарии). Или перестановка сама кодирует перестановку.
- **Число кадров.** Число кадров как число может кодировать длину/ключ.
- **Дублирующиеся кадры.** «Пустые» кадры могут нести данные в служебных полях.

## Инструменты и команды

- **`Pillow`** — `ImageSequence`, доступ к `info["duration"]` и `info["disposal"]`.
- **`gifsicle`** — `--info`, `--colors`, `--delay`; разбор и модификация.
- **`ImageMagick`** — `identify -verbose`, `convert -coalesce`.
- **`xxd`/`strings`** — ручной поиск `0x21 0xF9` (GCE) и комментариев.
- **`exiftool`** — метаданные, если есть.

Список задержек через Pillow:

```bash
python3 - <<'PY'
from PIL import Image
im = Image.open("anim.gif")
durs, disp = [], []
try:
    while True:
        durs.append(im.info.get("duration"))
        disp.append(im.info.get("disposal"))
        im.seek(im.tell()+1)
except EOFError:
    pass
print("durations:", durs)
print("disposal :", disp)
PY
```

Вывод:

```
durations: [7, 7, 6, 5, 7, 7, 7, 7, 6, 8, 7, 6]
disposal : [2, 2, 2, 2, 2, 2, 2, 2, 2, 2, 2, 2]
```

Задержки — повод копнуть глубже (если они не «круглые»).

## Разобранный пример: данные в задержках

Пусть биты кодируются чётностью задержки. Извлечём:

```python
from PIL import Image
im = Image.open("anim.gif")
bits = []
try:
    while True:
        d = im.info.get("duration")
        bits.append(d & 1)
        im.seek(im.tell()+1)
except EOFError:
    pass
import numpy as np
data = np.packbits(np.array(bits, dtype=np.uint8)).tobytes()
print(data[:64])
# -> b'flag{gif_delay}'
```

Если это не сработало, попробуйте кодирование самими значениями (задержка = байт), разницей соседних задержек, или disposal-последовательностью.

## Комментарии и расширения

GIF допускает Comment Extension (`0x21 0xFE`) — произвольный текст. `strings` покажет его:

```bash
strings -n 6 anim.gif | tail
# Comment: aGVsbG8= (base64!)
```

Base64/hex в комментарии — частый «лёгкий» флаг. Также проверьте Application Extension (`0x21 0xFF`) — там может быть NETSCAPE-цикл или кастомные данные.

## Крайние случаи и подводные камни

- **Pillow объединяет кадры.** `im.info` при `seek` даёт данные текущего кадра; не забудьте пройти все.
- **Задержка 0.** Некоторые редакторы ставят 0; тогда канал может быть в других полях.
- **Оптимизация GIF.** `gifsicle -O3` может переписать задержки — данные разрушатся.
- **Локальные палитры.** Каждый кадр может иметь свою палитру — не путайте с глобальной.
- **Перекодирование в MP4.** Потеряются все GIF-поля — работайте с оригиналом.
- **Число кадров.** `im.n_frames` даёт общее число — проверьте, совпадает ли с ожидаемым.

## Что дальше / решение

- Задержки не «круглые» — извлеките биты по чётности или по значению.
- Ничего — проверьте disposal, комментарии, палитру (`stego-palette-sort`).
- Подозрение на перестановку кадров — извлеките кадры и проанализируйте порядок.
- GIF с «шумными» кадрами — возможно, LSB в кадрах; смотрите `stego-gif`.

## Справочная таблица

| Поле GIF | Размер | Канал |
|---|---|---|
| Delay Time | 16 бит | задержки кадров |
| Disposal Method | 3 бита | троичный/четверичный код |
| Comment Extension | произвольно | текст/base64 |
| Global Color Table | до 768 Б | палитра |
| Frame order | — | перестановка |

## Извлечение кадров и анализ порядка

Кадры GIF можно выгрузить и проанализировать по отдельности. Это нужно, когда данные спрятаны в порядке кадров, в конкретных кадрах или в их пикселях. Выгрузка:

```bash
# все кадры в отдельные PNG
convert anim.gif -coalesce frame_%03d.png
# или через gifsicle
gifsicle --explode anim.gif
ls frame_*.png
```

Если какой-то кадр «выбивается» (другой размер, шум, текст) — он и есть носитель. Иногда порядок кадров кодирует перестановку: пронумеровав кадры по «правильному» порядку, вы получаете перестановку как сообщение.

## LZW-данные и локальные палитры

Пиксели GIF сжаты LZW, но сам поток — это индексы палитры. Можно анализировать последовательность индексов: чётность индекса, младший бит, повторяемость. Кроме того, каждый кадр может иметь **локальную** палитру (LCT), отличную от глобальной. Локальные палитры — отдельный канал: их порядок и содержимое можно модулировать (см. `stego-palette-sort`).

```python
from PIL import Image
im = Image.open("anim.gif")
im.seek(3)   # 4-й кадр
print("local palette?" , "palette" in im.info)
print("n_colors:", len(im.getpalette())//3)
```

## Тайминги и «цикл»

Application Extension с NETSCAPE-блоком задаёт число повторов анимации (`loop`). Значение цикла тоже число — его можно использовать как младший байт метаданных. Проверка:

```bash
python3 - <<'PY'
from PIL import Image
im = Image.open("anim.gif")
print("loop:", im.info.get("loop"))
print("n_frames:", im.n_frames)
PY
```

## Практический чек-лист по GIF

1. `file`, `xxd | head` — убедиться, что это GIF и посмотреть версию (87a/89a).
2. `strings -n 6` — комментарии и текстовые расширения.
3. Pillow — выгрузить `duration` и `disposal` всех кадров.
4. Проверить чётность/значения задержек на читаемость (ASCII/base64).
5. `gifsicle --explode` — посмотреть кадры по отдельности.
6. Проверить локальные палитры и `loop`.
7. `zsteg -a` — на случай LSB в кадрах.
8. `binwalk` — вдруг после trailer дописан файл.

Если ни один пункт не сработал — вернитесь к задержкам: в 80% GIF-задач данные именно там.

## Кодирование данными в комментариях и расширениях

GIF-расширения (`0x21`) — недооценённый канал. Помимо Comment Extension (`0x21 0xFE`), есть Plain Text Extension (`0x21 0x01`), который рисует текст поверх кадра и часто игнорируется, и Application Extension (`0x21 0xFF`), где NETSCAPE-блок задаёт цикл, но можно дописать свои данные. Разбор:

```bash
xxd anim.gif | grep -A2 '21 fe'   # комментарии
xxd anim.gif | grep -A2 '21 ff'   # application (netscape и др.)
```

```python
data = open("anim.gif","rb").read()
i = 0
while True:
    i = data.find(b"\x21\xfe", i)
    if i == -1: break
    ln = data[i+2]
    print("comment:", data[i+3:i+3+ln])
    i += 3+ln
```

Комментарии часто содержат base64/hex или просто флаг. Начинайте с них — это «низко висящий фрукт» перед анализом задержек.

## Проверка кадров на LSB

Если данные не в таймингах и не в комментариях, проверьте пиксели кадров на LSB. Выгрузите кадры и прогоните `zsteg`/скрипт по каждому:

```bash
gifsicle --explode anim.gif
for f in anim.gif.*; do echo "== $f"; zsteg -a "$f" 2>/dev/null | head -3; done
```

Иногда канал — не младший бит, а палитровые индексы (чётность). Проверяйте оба.

## Анимация и «frame disposal» подробнее

Disposal method влияет на то, как кадры накладываются: `restore to background` очищает область, `do not dispose` оставляет. Последовательность значений (0–3) — троичный/четверичный код. Извлеките её и посмотрите на закономерность:

```python
from PIL import Image
im = Image.open("anim.gif")
d=[]
try:
    while True:
        d.append(im.info.get("disposal", 0)); im.seek(im.tell()+1)
except EOFError: pass
print(d)
```

Если значения не «однотипны» (обычно все 2), возможен канал.

## Чек-лист по GIF (расширенный)

1. `xxd` — версия, наличие расширений.
2. Комментарии/Plain Text (`0x21`) — текст/base64.
3. Pillow — задержки и disposal всех кадров.
4. `gifsicle --explode` + `zsteg` — LSB кадров.
5. Локальные палитры и `loop`.
6. `binwalk` — данные после trailer.

GIF — маленький, но «слоёный» формат; комментарии и задержки закрывают большинство задач.
