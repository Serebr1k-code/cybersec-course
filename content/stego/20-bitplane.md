## Вопрос, с которого всё начинается

У тебя есть `planes.png` — картинка размером 120×120. Обычный LSB-инструмент ничего не находит. Но, может быть, данные спрятаны не во «всех» битах подряд, а в конкретном **бите конкретного канала**? И что вообще значит «бит-плоскость»?

Изображение — это числа. Каждый пиксель состоит из трёх чисел (красный, зелёный, синий), и у каждого числа есть восемь битов. Если взять один и тот же бит у всех пикселей, получится целая картинка из нулей и единиц — **бит-плоскость**. Именно там и прячут данные. Разберём на `planes.png`.

## Наш пример: planes.png

Открываем файл и убеждаемся, что он обычный — без текстовых чанков:

```bash
exiftool planes.png | grep -iE 'width|height|comment|type'
```

```text
Image Width                     : 120
Image Height                    : 120
Image Type                      : RGB
```

Никаких `Comment`, никаких подсказок. Значит, искать надо в пикселях.

## Шаг 1: что такое бит-плоскость

Число пикселя, например синее, лежит в диапазоне 0–255 и записывается восемью битами. Бит с номером 0 — **младший (LSB)**, он влияет на цвет меньше всего. Бит с номером 7 — **старший (MSB)**, он определяет, светлый цвет или тёмный.

**Бит-плоскость** — это матрица значений этого бита по всем пикселям. Младшая плоскость обычной фотографии выглядит как случайный шум, а если в неё вписали текст, она становится структурированной. Иногда такую плоскость сохраняют как чёрно-белую картинку и в ней **видно буквы**.

## Шаг 2: извлекаем LSB синего канала

Пишем скрипт: читаем картинку, берём у каждого пикселя младший бит **синего** канала и собираем из них байты:

```python
from PIL import Image
import numpy as np
im = np.array(Image.open('planes.png'))          # форма (H, W, 3)
blue = im.reshape(-1, 3)[:, 2]                    # все синие значения в строку
bits = ''.join(str(int(p) & 1) for p in blue)     # & 1 — младший бит
out = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
print('blue-LSB:', out[:40])
```

`reshape(-1, 3)` разворачивает картинку в список пикселей, `[:, 2]` берёт синий канал, `& 1` оставляет младший бит. Запускаем:

```text
blue-LSB: b'flag{bit_pl4n3s}\xa8\x829\x93i\xad\xf9\x0c\x00NJ\x03\xb5\x9c\xd1\xb8\x95\xf9\x05hd\xee\x9a\x8b'
```

Флаг найден: `flag{bit_pl4n3s}`. Обрати внимание — данные были **только в синем канале**, а не во всех сразу.

## Шаг 3: смотрим бит-плоскость как картинку

Иногда данные — не текст, а изображение, спрятанное в плоскости. Тогда плоскость сохраняют как картинку и разглядывают:

```python
from PIL import Image
import numpy as np
im = np.array(Image.open('planes.png'))
plane = ((im[:, :, 2] & 1) * 255).astype('uint8')   # LSB синего → 0/255
Image.fromarray(plane).save('plane0_blue.png')
```

```text
plane image saved (120, 120) set bits: 7273
```

Если в плоскости спрятан рисунок или текст, они станут видны на `plane0_blue.png`. Это классический приём: данные «проявляются» при визуализации нужного бита.

## Шаг 4: мультибитный LSB и схема 2-3-3

Один младший бит даёт мало ёмкости. Поэтому данные прячут в **несколько** младших битов: два, три, четыре. Тогда на один пиксель приходится больше скрытых битов, и картинка всё ещё выглядит нормально.

Особый случай — **схема 2-3-3**: разное число младших битов распределено по каналам. Например, 2 бита в красном, 3 в зелёном, 3 в синем. Сумма 2+3+3 = 8 — ровно байт на пиксель. Такое распределение подбирают под чувствительность глаза к каждому цвету. Извлекают данные, «нарезая» нужное число младших битов из каждого канала и склеивая их в поток:

```python
r = im[:, :, 0] & 0b00000011   # 2 младших бита красного
g = im[:, :, 1] & 0b00000111   # 3 бита зелёного
b = im[:, :, 2] & 0b00000111   # 3 бита синего
```

## Шаг 5: старшие биты (MSB)

Прятать можно не только в младших битах. Иногда данные лежат в **старшем** бите — тогда плоскость выглядит как грубый чёрно-белый рисунок. Проверяют оба конца:

```python
msb = ((im[:, :, 0] >> 7) & 1) * 255     # старший бит красного
```

Перебор «канал × бит» (0–7 для каждого из R/G/B) быстро показывает, где лежат данные.

## Как не испортить картинку: мультибитный LSB на практике

Чем больше битов вы занимаете под данные, тем сильнее портится изображение. Один младший бит незаметен почти всегда; два — уже дают лёгкий «шум» в градиентах; три-четыре видны как зернистость на гладких участках. Поэтому авторы стего подбирают число битов так, чтобы картинка осталась правдоподобной, а данные влезли целиком.

Классический приём для дополнительной скрытности — **адаптивность**: в гладких областях (небо, стена) прячут меньше битов, а в шумных (трава, текстура) — больше, потому что там изменение незаметно. Извлекать такие данные сложнее: нужно знать правило выбора битов. В CTF обычно используют простое фиксированное число битов, а адаптивные схемы оставляют для реальной стеганографии.

Ещё один нюанс — **порядок извлечения**. Байты могут собираться построчно (слева направо, сверху вниз) или по столбцам, а иногда — зигзагом. Если текст не читается, хотя биты явно структурированы, попробуйте другой порядок обхода пикселей: `reshape` в другой форме или транспонирование матрицы.

## Инструменты для визуализации

Ручной код хорош для понимания, но для быстрого осмотра есть готовые утилиты. **StegSolve** — классический GUI для просмотра бит-плоскостей: он показывает все восемь плоскостей каждого канала и позволяет листать их. **zsteg** — консольный инструмент для PNG/BMP, который перебирает каналы, биты и порядки автоматически:

```bash
zsteg planes.png
```

`zsteg` печатает найденные строки и подозрительные комбинации — это удобный «первый проход», после которого уже осмысленно смотреть конкретную плоскость вручную.

## Полный прогон: от картинки к флагу

```text
planes.png
  → exiftool → чистые метаданные, RGB 120×120
  → скрипт: LSB синего канала → flag{bit_pl4n3s}
  → визуализация плоскости → plane0_blue.png
  → при неудаче — перебор R/G/B × биты 0..7 и схема 2-3-3
  → итог: данные в младшем бите синего канала
```

## Если не сработало

- **Только в одном канале пусто** — переберите все три канала (R, G, B) и оба порядка (LSB/MSB).
- **Нужно больше ёмкости** — попробуйте 2–4 младших бита и схему 2-3-3.
- **Плоскость выглядит как шум** — возможно, данные не в ней; смотрите альфа-канал (`stego-alpha`) или другие каналы.
- **Есть картинка в плоскости** — сохраните каждую плоскость как PNG и просмотрите их.

## Что мы теперь знаем

- **Бит-плоскость** — это один бит по всем пикселям.
- Младший бит (LSB) влияет на цвет меньше всего — туда и прячут.
- Данные могут быть **в конкретном канале**, а не во всех сразу.
- Плоскость можно **сохранить как картинку** и увидеть скрытое.
- **Мультибитный LSB** и схема **2-3-3** дают больше ёмкости.
- Прятать можно и в старшем бите (MSB).
