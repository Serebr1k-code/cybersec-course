## Что такое стеганография и чем она отличается от криптографии

**Криптография** скрывает *содержание* сообщения: перехватчик видит, что ему передали что-то зашифрованное, но не может прочитать. **Стеганография** скрывает *сам факт* передачи: посторонний видит безобидную картинку, музыку или текст и даже не догадывается, что внутри есть секрет. Термин ввёл Иоганнес Тритемий в 1499 году («Steganographia»), а сама идея старше: Геродот описывал письмо, выбритое на голове раба и скрытое отросшими волосами.

Это фундаментальное различие определяет и методологию атаки:

| | Криптография | Стеганография |
|---|---|---|
| Что скрывается | смысл | наличие сообщения |
| Что видит противник | шифртекст | обычный файл |
| Как ломают | криптоанализ | стегоанализ (поиск аномалий) |
| Индикатор секрета | очевиден (нечитаемый блоб) | отсутствует |
| Отказоустойчивость | криптостойкость | ёмкость + незаметность |
| Комбинация | **стеганография + шифрование** — самый частый CTF-паттерн | |

На практике в CTF почти всегда комбинируют: сначала прячут зашифрованный блоб в носителе, потом могут ещё и запаролить контейнер. Поэтому задача разбивается на два независимых шага: **(1) извлечь скрытый блоб**, **(2) расшифровать его**. Ошибка новичка — начать с шага 2, не имея на руках ни блоба, ни ключа.

Ключевая идея стегоанализа: **любая модификация носителя оставляет след**. Файл-носитель после встраивания отличается от «чистого» оригинала статистически, структурно или побитово. Наша работа — найти это отличие. Если контейнер «чистый», а флаг не находится, значит вы ещё не посмотрели в правильный канал, а не «данных нет».

## Классификация носителей и техник

Стеганографию удобно делить по носителю и по способу встраивания — это две независимые оси.

**По носителю:**
- **Изображения** — LSB, палитры, чанки PNG, EXIF, дописанные данные, полиглоты. Самый частый класс в CTF.
- **Аудио** — LSB-сэмплы, спектрограмма, DTMF, SSTV, эхо-стеганография, фазовое кодирование.
- **Текст** — пробелы/табы, zero-width символы, регистр, синонимы, акростих, гомоглифы.
- **Видео** — LSB в кадрах, скрытые кадры, метаданные контейнера, отдельная аудиодорожка.
- **Сеть** — поля заголовков (IP ID, TTL, TCP-опции), тайминги, порядок пакетов, DNS/ICMP-туннели.
- **Файловые системы/архивы** — alternate data streams, дописанные архивы, slack space, неразмеченные области.

**По способу встраивания:**
- **Пространственная область (spatial)** — меняются сами пиксели/сэмплы (LSB, LSB-сдвиг, PVD).
- **Частотная область (transform)** — меняются коэффициенты DCT/DWT (JPEG, watermarking).
- **Структурная** — используются поля формата, порядок, палитры, паддинг, порядок объектов.

Понимание оси «способ» важнее носителя: если вы знаете, что данные в частотной области, вы сразу берёте JPEG-инструменты, а не перебираете `zsteg`.

## Триада свойств: ёмкость, незаметность, робастность

Любой стего-метод балансирует между тремя свойствами, и усиление одного ослабляет другие:

- **Ёмкость (capacity)** — сколько байт можно спрятать. LSB в 24-битном PNG даёт 3 бита на пиксель (≈1/8 размера файла); метаданные — сотни байт.
- **Незаметность (undetectability)** — насколько сложно отличить контейнер от чистого статистическими тестами (хи-квадрат, RS-анализ).
- **Робастность (robustness)** — переживёт ли сообщение сжатие, кадрирование, перекодирование.

LSB в PNG — высокая ёмкость, низкая робастность (сжатие в JPEG уничтожает данные), средняя незаметность. Spread-spectrum в аудио — низкая ёмкость, но высокая робастность. В CTF чаще всего важен именно компромисс, а не абсолютный максимум: поэтому в задачах попадаются и «простые» LSB, и хитрые трансформные методы.

## Универсальный пайплайн разбора контейнера

Когда дают «просто файл» без подсказок, порядок действий такой (от дешёвого к дорогому):

1. **Идентификация.** `file suspicious.png` — реальный ли это формат, что внутри. Проверь магические байты: `xxd file | head`.
2. **Метаданные.** `exiftool file`, `strings file | less`, `binwalk file`. Метаданные и «мусорные» строки — самый дешёвый источник секретов.
3. **Структура.** `binwalk -e file` — ищем встроенные архивы/файлы. `pngcheck -v file` для PNG, `identify -verbose` для изображений.
4. **Хвост файла.** Сравни размер с ожидаемым, посмотри последние байты: `xxd file | tail`. Дописанные данные — классика.
5. **Специализированные тулзы** по типу носителя: `zsteg`, `steghide`, `outguess`, `stegsolve`, `steghide`, аудио — `sox`/`audacity`, текст — свои скрипты.
6. **Брут пароля** — только если тул требует пароль и есть словарь/подсказка.

Запомни главный принцип: **не начинай с брутфорса и тяжёлых тулзов**. Сначала бесплатные проверки (`file`/`strings`/`exiftool`/`binwalk`/`tail`), и только потом — целенаправленные техники. Половина beginner-задач решается на шагах 2–3.

## Инструментарий: полный набор и установка

Минимальный набор для Stego-задач:

```
file, xxd, strings, binwalk        # идентификация и разбор
exiftool                            # метаданные всех форматов
zsteg, stegsolve, pngcheck, identify# изображения
steghide, outguess, stegseek        # парольная стеганография в JPEG/BMP
sox, ffmpeg, audacity, multimon-ng  # аудио
foremost, scalpel                   # carving
python3 + Pillow, numpy, pydub      # собственные скрипты
```

Установка типового набора (Debian/Ubuntu):

```bash
sudo apt install -y binwalk exiftool steghide outguess sox ffmpeg \
    pngcheck foremost ruby
sudo gem install zsteg
```

`zsteg` — Ruby-инструмент, покрывающий десятки LSB-комбинаций в PNG/BMP. `stegseek` — быстрый брут `steghide` по словарю (в тысячи раз быстрее оригинала, десятки тысяч паролей в секунду). `stegsolve` — Java-приложение для визуального просмотра битовых плоскостей; без GUI его заменяет `zsteg -a` и скрипты на Pillow.

## Первые команды: разбор «неизвестного файла» пошагово

Универсальная «разминка» перед чем угодно:

```bash
$ file suspect
suspect: PNG image data, 1024 x 768, 8-bit/color RGBA, non-interlaced
$ xxd suspect | head -3
00000000: 8950 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR
00000010: 0000 0400 0000 0300 0806 0000 00ba 4b3c  ..............K<
00000020: 0d00 0000 1474 4558 7443 6f6d 6d65 6e74  .....tEXtComment
$ strings -n 6 suspect | head -20
$ exiftool suspect
Comment  : cGFzc3dvcmQgaXMgc3RlZ29wYXNz
$ binwalk suspect
DECIMAL       HEXADECIMAL     DESCRIPTION
--------------------------------------------------------------------------------
0             0x0             PNG image, 1024 x 768, 8-bit/color RGBA
138           0x8A            Zlib compressed data, best compression
```

В этом примере `exiftool` показал комментарий в base64 — его декодируем: `echo cGFzc3dvcmQgaXMgc3RlZ29wYXNz | base64 -d` → `password is stegopass`. Дальше очевидно: `steghide extract -sf suspect` и пароль `stegopass`. Так бесплатные шаги ведут прямо к цели, не тратя время на брут.

Читай вывод внимательно. Часто флаг или пароль лежит прямо в `strings` или в комментарии EXIF. Не пропускай этот шаг.

## Разобранный пример: от файла до флага

Задача: дан `cat.png`. Полный проход по пайплайну:

```bash
$ file cat.png
cat.png: PNG image data, 500 x 500, 8-bit/color RGB, non-interlaced
$ pngcheck -v cat.png
File: cat.png (123456 bytes)
  chunk IHDR at offset 0x0000c, length 13
  chunk tEXt at offset 0x00031, length 40, keyword: Description
  chunk IDAT at offset 0x00065, length 120000
  chunk IEND at offset 0x12304a
  total filesize = 123456 bytes
$ zsteg cat.png
[?] 0 b1,rgb,lsb,xy       .. text: "flag{rgb_lsb_wins}"
[?] 0 b2,rgb,lsb,xy       .. text: "!x]p..."
$ zsteg -E 'b1,rgb,lsb,xy' cat.png | head -1
flag{rgb_lsb_wins}
```

Порядок: `file` → структура чанков (`pngcheck`) → перебор каналов (`zsteg`). Если `zsteg` пуст, но файл «подозрительный», переходим к `stegseek` (если есть намек на пароль), затем к битовым плоскостям вручную и к статистике (хи-квадрат). Каждый следующий инструмент дороже предыдущего — поэтому важен порядок.

## Частые ошибки и подводные камни

- **Смотреть только видимые символы** — пропустить zero-width, trailing whitespace, гомоглифы.
- **Начинать с брута** `steghide`/`outguess`, не проверив `strings`/`exiftool`/`binwalk`.
- **Портить файл**: открыть PNG в графическом редакторе и «пересохранить» — метаданные и LSB уничтожатся. Работай с оригиналом и копией.
- **Игнорировать размер**: если файл больше, чем должен быть при данных разрешении/каналах, в нём есть дописанное.
- **Не проверять `file`**: расширение `.png` может скрывать ZIP/PDF/полиглот.
- **Забывать про порядок бит** (MSB/LSB) и про порядок обхода каналов (RGB vs BGR, xy vs yx) — отсюда «пустой» вывод `zsteg`.
- **Считать «нет данных», не пройдя весь пайплайн** — часто секрет в последнем, а не первом канале.

## Что делать дальше / решение

- Если `strings`/`exiftool` дали подсказку (пароль, base64, ключ) — сразу примените её к контейнеру.
- Если `binwalk` нашёл встроенный файл — извлеките: `binwalk -e file` или `dd if=file bs=1 skip=<offset> of=extracted`.
- Если `file`/`xxd` видят второй формат после `IEND`/`%%EOF` — это appended/полиглот, смотри уроки про дописанные данные и полиглоты.
- Если есть пароль и JPEG/BMP — `steghide extract -sf f.jpg` или `stegseek f.jpg rockyou.txt`.
- Если ничего — переходите к LSB/битовым плоскостям (`zsteg -a`, скрипт на Pillow) и к стегоанализу.
- И помните порядок: **сначала извлечение, потом расшифровка**; не наоборот.

## Где пригодится

- Это корневой урок ветки: из него растут все остальные (изображения, аудио, текст, видео, сеть).
- Пайплайн `file → exiftool → strings → binwalk → tail` применяй к любому неизвестному файлу в любой CTF-категории.
- Понимание «стего vs крипто» помогает правильно разбить задачу: сначала извлечение, потом расшифровка.
