## Вопрос, с которого всё начинается

До сих пор мы всегда пытались данные **извлечь**. Но иногда полезно ответить на другой вопрос: «есть ли тут вообще стеганография?» Это обратная задача — **стегоанализ**. Он нужен, когда непонятно, за что браться: перебирать каналы или файл «чистый».

Разберём один файл, где автоматический детектор молчит, а данные всё же есть.

## Наш пример: image.jpg

Спросим у автоматического детектора:

```
$ stegdetect image.jpg
image.jpg: negative
```

«Negative» — данных не найдено. Но это ещё не приговор: детекторы не универсальны. Применим **визуальный стегоанализ** — построим младшую битовую плоскость:

```python
from PIL import Image
import numpy as np
img = np.array(Image.open('image.jpg').convert('RGB'))
Image.fromarray((((img >> 0) & 1) * 255).astype('uint8')).save('p0.png')
```

Открываем `p0.png` — и видим чёткий **QR-код**. Данные есть, просто детектор их не поймал. Декодируем:

```
$ zbarimg p0.png
QR-Code:flag{steganalysis_plane}
```

Вывод: автоматический детектор может сказать «negative», а визуальный анализ — «positive». Детекторы не истина в последней инстанции.

## Шаг 1: что такое стегоанализ формально

Стегоанализ — это проверка гипотез:

- `H0` (нулевая): данных нет;
- `H1` (альтернатива): данные есть.

Детектор — решающее правило. У него две ошибки: **пропуск** (false negative) и **ложная тревога** (false positive). Чем больше сообщение, тем легче его найти; маленький флаг может быть статистически невидим.

Ключевая идея: встраивание **нарушает естественную статистику** носителя. Пиксели, коэффициенты или сэмплы перестают подчиняться типичному распределению — это отклонение и ищет стегоанализ.

## Шаг 2: хи-квадрат-анализ (Pairs of Values)

Классический тест для LSB-встраивания. Наблюдение: в естественном изображении значения `2k` и `2k+1` встречаются с **разной** частотой. LSB-встраивание делает младший бит равновероятным, поэтому частоты `2k` и `2k+1` **выравниваются**.

```python
import numpy as np
from PIL import Image
from scipy.stats import chisquare
img = np.array(Image.open('x.png').convert('L')).flatten()
pairs = [(img[img == 2*k].size, img[img == 2*k+1].size) for k in range(128)]
obs = [a for a, b in pairs]
exp = [(a + b) / 2 for a, b in pairs]
chi2, p = chisquare(obs, exp)
print('p-value', p)   # p близко к 1 → похоже на LSB-встраивание
```

Высокий `p-value` (распределение «слишком ровное») — признак встраивания.

## Шаг 3: RS-анализ

**RS** (Regular-Singular) анализирует, как меняется «гладкость» изображения при перевороте младших битов. Пиксели группируются в маски, для каждой группы считается функция гладкости `f`. Группы делятся на **Regular** (гладкость растёт при флипе) и **Singular** (падает).

В чистом изображении числа R и S связаны определённым образом; встраивание нарушает это соотношение. RS даёт **количественную оценку** доли изменённых пикселей, то есть ёмкости.

## Шаг 4: SPA (Sample Pair Analysis)

**SPA** анализирует пары соседних сэмплов и их переходы. LSB-встраивание оставляет характерный след в матрице переходов между значениями. Метод оценивает длину сообщения и находит стего даже там, где хи-квадрат молчит — особенно при большом объёме встраивания.

## Шаг 5: калибровка для JPEG

Для JPEG стегоанализ сложнее: коэффициенты DCT коррелированы, а OutGuess 0.2 активно маскирует след. Подход **калибровки**: изображение перекодируется/обрезается, из него извлекается «эталонная» статистика, и она сравнивается с фактической. Разница — оценка встроенных данных. Так работают детекторы JSteg/F5/OutGuess.

## Шаг 6: почему стегоанализ «проигрывает» современным методам

Современные методы (модельная стеганография, HUGO, S-UNIWARD, нейросети) целенаправленно сохраняют статистику контейнера: минимизируют «стоимость» изменения по стегоаналитическим признакам. В результате детектор не может надёжно отличить контейнер от чистого изображения.

Для CTF это значит: **не полагайся на «стегоанализ ничего не нашёл»**. Ищи по каналам (LSB, чанки, хвост, метаданные), а статистика — вспомогательный инструмент.

## Шаг 7: связь с ёмкостью

Методы RS и SPA дают не только «есть/нет», но и **оценку длины** сообщения. Это навигация: зная примерный размер, понимаешь, что искать. Оценка в несколько килобайт при JPEG подсказывает, что дело не в DCT-методе (там ёмкость мала), а в дописанном хвосте или метаданных.

## Если не сработало

- Начни с визуального анализа младших плоскостей — быстро и надёжно.
- Для PNG/BMP — хи-квадрат/RS/SPA; для JPEG — калибровка.
- Данные есть, но не извлекаются — ищи ключ или нестандартный порядок.
- Детектор молчит — не исключай стего, проверь все каналы вручную.

## Что мы теперь знаем

1. Стегоанализ отвечает на вопрос «есть ли данные», а не извлекает их.
2. Хи-квадрат ловит выравнивание пар `2k`/`2k+1` при LSB.
3. RS и SPA дают количественную оценку ёмкости.
4. Для JPEG применяют калибровку.
5. «Детектор молчит» ≠ «данных нет» — современные методы статистически прозрачны.

## Шаг 8: практические тесты на Python

Простой и наглядный тест — доля единиц в младших битах. У естественного изображения она отклоняется от 0.5, а при LSB-встраивании стремится к 0.5 (энтропия младшей плоскости растёт):

```python
import numpy as np, math
from PIL import Image
img = np.array(Image.open('x.png').convert('L')).flatten()
lsb = img & 1
p = lsb.mean()
print('lsb ones ratio:', p)          # ~0.5 → похоже на встраивание
H = -(p*math.log2(p) + (1-p)*math.log2(1-p)) if 0 < p < 1 else 0
print('entropy:', H)                 # ~1.0 → похоже на встраивание
```

Хи-квадрат по парам значений:

```python
from scipy.stats import chisquare
pairs = [(img[img == 2*k].size, img[img == 2*k+1].size) for k in range(128)]
obs = [a for a, b in pairs]
exp = [(a + b) / 2 for a, b in pairs]
chi2, p = chisquare(obs, exp)
print('p-value', p)                  # близко к 1 → пары выровнены (встраивание)
```

## Шаг 9: почему стегоанализ «проигрывает» современным методам

Современные методы (модельная стеганография, HUGO, S-UNIWARD, нейросети) целенаправленно сохраняют статистику контейнера. Например, HUGO минимизирует «стоимость» изменения с учётом стегоаналитических признаков, а S-UNIWARD распределяет изменения по «дорогим» для детектора местам.

Для CTF это значит: **не полагайся на «стегоанализ ничего не нашёл»**. Ищи по каналам (LSB, чанки, хвост, метаданные), а статистика — вспомогательный инструмент, а не окончательный вердикт.

## Шаг 10: инструменты

- **`stegdetect`** — детектор JPEG-методов (JSteg/JPHide/OutGuess/F5);
- **`stegoveritas`** — комплексный анализ с отчётом;
- **`Aletheia`** — продвинутый стегоанализ (RS, SPA, хи-квадрат);
- **Python (`scipy`, `numpy`)** — собственные тесты;
- **`zsteg`** — косвенно: печатает каналы с «аномальными» данными.

## Шаг 11: формальное определение и метрики

Стегоанализ формализуется как проверка гипотез. Нулевая гипотеза `H0`: в контейнере нет встроенных данных. Альтернатива `H1`: данные есть. Детектор — решающее правило, которое по наблюдениям (пикселям, коэффициентам) выдаёт ответ.

Метрики качества: вероятность пропуска (false negative) и ложной тревоги (false positive). Чем больше сообщение, тем легче его обнаружить; чем меньше — тем выше риск пропуска.

Практический вывод для CTF: **маленькое сообщение (флаг) может быть статистически невидимым**, поэтому «чистый» результат теста не доказывает отсутствие данных. Всегда комбинируй статистику с прямым перебором каналов и визуальным анализом.
