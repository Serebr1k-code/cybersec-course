## Вопрос, с которого всё начинается

Тебе дали `clip.mp4` — короткое видео. В прошлом уроке мы уже знаем, что видео — контейнер с несколькими каналами. Но здесь метаданные чистые, аудиодорожки нет. Значит, данные спрятаны **в самих кадрах**. Как их найти, не просматривая 300 кадров глазами?

В этом уроке мы найдём «выбивающийся» кадр и достанем из него флаг.

## Наш пример: clip.mp4

Начнём с разбора контейнера — вдруг ответ на поверхности.

```
$ ffprobe -v error -show_streams -show_format clip.mp4 | head -20
[STREAM]
index=0
codec_name=h264
width=640
height=480
nb_frames=300
[/STREAM]
```

300 кадров, видео H.264 640×480, аудиопотока нет. Теперь разложим видео на кадры. Кадры извлекаем в **PNG** — формат без потерь, чтобы не испортить младшие биты.

```
$ mkdir frames && ffmpeg -i clip.mp4 -vsync 0 frames/%05d.png
$ ls frames | wc -l
300
```

`-vsync 0` запрещает дублировать кадры (иначе нумерация собьётся).

## Шаг 1: ищем отличающийся кадр

Просматривать 300 картинок глазами — долго. Сравним каждый кадр с первым и отсортируем по числу различающихся пикселей. `compare` из ImageMagick с метрикой `AE` (absolute error) печатает это число:

```
$ for f in frames/*.png; do
    v=$(compare -metric AE frames/00001.png "$f" null: 2>&1)
    echo "$v $f"
  done | sort -rn | head -3
18432 frames/00217.png
210 frames/00001.png
198 frames/00002.png
```

Кадр `00217.png` резко отличается от всех (18432 против ~200). Это кандидат. Откроем его глазами:

```
$ zbarimg frames/00217.png
QR-Code:flag{video_hidden_frame}
```

На кадре оказался QR-код. Флаг найден.

## Шаг 2: альтернатива — перцептивный хеш

Попиксельное сравнение ломается, если видео сжато с потерями: тогда даже «одинаковые» кадры различаются по краям. Надёжнее **перцептивный хеш** (`imagehash`) — он устойчив к мелким изменениям.

```python
import imagehash, glob
from PIL import Image
hs = {f: imagehash.phash(Image.open(f)) for f in sorted(glob.glob('frames/*.png'))}
base = list(hs.values())[0]
for f, h in hs.items():
    if (h - base) > 5:      # порог
        print('выбивается:', f, h - base)
```

## Шаг 3: разница между кадрами как канал

Иногда данные кодируют не в отдельном кадре, а в **разнице** соседних кадров — при воспроизведении это незаметно. Визуализируем разницу через `tblend`:

```
$ ffmpeg -i clip.mp4 -vf "tblend=all_mode=difference" diff_%05d.png
```

## Шаг 4: LSB и DCT в кадрах

Если отличающегося кадра нет, проверь пиксели кадров на LSB и DCT-каналы:

```
$ zsteg frames/00001.png
$ ffmpeg -i clip.mp4 -q:v 2 frames/%05d.jpg   # кадры в JPEG для DCT-анализа
$ stegdetect frames/00001.jpg
```

Помни: LSB работает только для несжатых кадров (PNG/BMP/MJPEG). В H.264 сжатие с потерями, поэтому данные прячут в DCT-коэффициентах — как в JPEG.

## Шаг 5: аудио и метаданные

Не забывай про остальные слои:

```
$ ffmpeg -i clip.mp4 -vn -acodec pcm_s16le audio.wav
$ sox audio.wav -n spectrogram -o spec.png
$ ffprobe -v quiet -show_format -show_streams clip.mp4
$ exiftool clip.mp4
```

Скрытые дорожки (субтитры, data) видны в `ffprobe`; извлечь их можно `ffmpeg -i clip.mp4 -map 0:s:0 subs.srt`.

## Шаг 6: хвост контейнера

Как и в любом формате, после конца видео может лежать дописанный файл:

```
$ binwalk clip.mp4
$ xxd clip.mp4 | tail -5
```

## Таблица каналов видео

| Слой | Канал | Как искать |
|---|---|---|
| Кадры | отличающийся/лишний кадр | экспорт, `compare`/phash |
| Пиксели кадра | LSB/RGB | `zsteg` на каждом кадре |
| DCT кадра | коэффициенты | стего-инструменты на JPEG-кадрах |
| Аудио | LSB/эхо/спектр | аудио-методы |
| Контейнер | метаданные, скрытые дорожки | `ffprobe`/`exiftool`/`mkvinfo` |
| Хвост файла | appended данные | `binwalk` |

## Если не сработало

- Смотри в плеере — кадры и тайминги не видны, всегда экспортируй.
- Не извлекай кадры в JPEG, если ищешь LSB — потеряешь младшие биты.
- Если `compare` даёт 0 для всех — кадры идентичны, ищи в пикселях/DCT/аудио.
- Если разница везде большая — видео сжато с потерями, используй перцептивный хеш.

## Что мы теперь знаем

1. Видео — контейнер + поток кадров + аудио, у каждого слоя свои каналы.
2. Отличающийся кадр находят `compare` (попиксельно) или phash (устойчиво).
3. Данные могут быть в разнице кадров (`tblend=difference`).
4. LSB в кадрах — только для несжатых; H.264 → DCT.
5. Не забывай аудио, метаданные и хвост контейнера.

## Шаг 7: полный конвейер ffmpeg

```bash
# 1) кадры + аудио + метаданные
ffmpeg -i clip.mp4 frames/%05d.png
ffmpeg -i clip.mp4 -vn audio.wav
ffprobe -v error -show_streams -show_format clip.mp4
# 2) поиск отличающегося кадра
for f in frames/*.png; do v=$(compare -metric AE frames/00001.png "$f" null: 2>&1); echo "$v $f"; done | sort -rn | head
# 3) LSB по кадрам и хвост
zsteg frames/00001.png
binwalk clip.mp4
```

Если `compare` даёт 0 для всех кадров — кадры идентичны, ищи в пикселях/DCT/аудио. Если разница везде большая (сжатие с потерями) — используй перцептивный хеш.

## Шаг 8: перцептивный хеш вместо попиксельного сравнения

```python
import imagehash, glob
from PIL import Image
hs = {f: imagehash.phash(Image.open(f)) for f in sorted(glob.glob('frames/*.png'))}
base = list(hs.values())[0]
for f, h in hs.items():
    if (h - base) > 5:      # порог
        print('выбивается:', f, h - base)
```

`phash` устойчив к мелким изменениям яркости/сжатия, поэтому надёжнее `compare` на видео с потерями.

## Шаг 9: аудиодорожка и скрытые дорожки

Аудио в видео — тот же WAV/AAC-поток: примени аудио-методы (LSB, спектрограмма, DTMF/SSTV/морзе):

```bash
ffmpeg -i clip.mp4 -vn -acodec pcm_s16le audio.wav
sox audio.wav -n spectrogram -o spec.png
multimon-ng -a DTMF -t wav audio.wav
```

Скрытые дорожки (субтитры, data) видны в `ffprobe` и извлекаются `ffmpeg -i clip.mp4 -map 0:s:0 subs.srt`.

## Шаг 10: структура видео и каналы сокрытия

| Слой | Канал сокрытия | Как искать |
|---|---|---|
| Кадры | отличающийся/лишний кадр | экспорт кадров, сравнение |
| Пиксели кадра | LSB/RGB внутри кадра | `zsteg` на каждом кадре |
| DCT кадра | младшие биты коэффициентов | стего-инструменты на JPEG-кадрах |
| Тайминги | PTS/длительность кадров | `ffprobe` |
| Аудио | LSB/эхо/спектр | аудио-методы |
| Контейнер | метаданные, скрытые дорожки, хвост | `ffprobe`/`exiftool`/`binwalk` |
| Хвост файла | appended данные | `binwalk`, `grep -abo` |

Стратегия: сначала дешёвые слои (метаданные, аудио, дописанное), затем кадры и DCT.

## Почему видео — богатый, но тяжёлый контейнер

Видеофайл — это не просто «много картинок». Внутри контейнера (MP4, MKV, AVI) лежат: видеодорожка (сжатая по H.264/H.265, где кадры делятся на I/P/B и сильно зависят друг от друга), аудиодорожка (AAC/MP3/Opus), метаданные контейнера, субтитры, иногда дополнительные дорожки. Каждый из этих слоёв — потенциальный канал сокрытия, поэтому видео даёт очень много мест спрятать данные.

Но это же делает анализ тяжёлым: нужно **демультиплексировать** контейнер (`ffmpeg -i`), затем работать с отдельными дорожками. Частые приёмы: скрытый кадр (одна картинка отличается от остальных), данные в **разнице между соседними кадрами**, LSB/DCT отдельных кадров, скрытая аудиодорожка или данные в её LSB, метаданные и **хвост контейнера** после конца потока.

Ключевая идея для анализа — не смотреть видео целиком, а **искать аномалии**: кадр, отличающийся по перцептивному хешу от соседей; дорожку, которой «не должно быть»; блок данных после конца контейнера. Для этого удобны `ffprobe` (структура), `ffmpeg` (извлечение кадров/дорожек), `binwalk` (вложенные файлы), перцептивный хеш (сравнение кадров). Помните: перекодирование видео разрушает большинство стего-каналов, поэтому анализировать надо оригинал.

## Частые вопросы

**Как найти скрытый кадр?** Извлеките все кадры (`ffmpeg -i clip.mp4 frames/%05d.png`) и сравните по перцептивному хешу (`imagehash`) — один кадр выбьется из ряда.

**Что если видео перекодировано?** Часть данных могла потеряться; но контейнерные хвосты и метаданные часто выживают, их проверяйте в первую очередь.

**Аудиодорожка как канал?** LSB сэмплов, скрытая вторая дорожка, спектрограмма с нарисованным текстом; проверьте `ffprobe -show_streams` на лишние дорожки.

**Почему перцептивный хеш, а не попиксельное сравнение?** Из-за сжатия соседние кадры не идентичны попиксельно; перцептивный хеш ловит смысловые отличия и не срабатывает на компрессионном шуме.
