## Вопрос, с которого всё начинается

Тебе дали `report.bin` — дамп USB HID-отчётов клавиатуры. Это «сырой» поток того, что
человек нажимал. На первый взгляд — просто коды клавиш. Но если собрать их в
правильном порядке и сопоставить с таблицей HID, получится осмысленный текст. USB-стены
используют этот приём, чтобы «печатать» сообщение без реального нажатия. Разберём.

## Наш пример: файл report.bin

```bash
xxd -l 32 report.bin
```

```text
00000000: 0004 0000 0000 0000 0000 1700 0000 0000  ................
00000010: 0000 1200 0000 0000 0000 0200 2f00 0000  ............/...
```

Каждые 8 байт — один HID-отчёт. В каждом первый байт — **модификатор** (нажатые
Ctrl/Shift/Alt), третий — **код клавиши**. Например, `00 04` — клавиша с кодом
`0x04`. По таблице HID `0x04` — это `a`. Но у нас первые отчёты дают `n`, `t`, `o`…
Разберём таблицу.

## Шаг 1: что такое HID-отчёт

**HID** (Human Interface Device) — класс USB-устройств: клавиатуры, мыши, геймпады.
Клавиатура шлёт **report** из 8 байт:

```
[ модификатор ][ зарезервировано ][ keycode1..keycode6 ]
```

Модификатор — битовая маска: `0x02` = Left Shift, `0x01` = Left Ctrl и так далее.
Keycode — **HID usage ID**: `0x04` = `a`, `0x05` = `b`, …, `0x1D` = `z`, `0x1E` = `1`,
`0x27` = `0`, `0x28` = Enter, `0x2C` = Space. Символы вроде `{` требуют Shift:
`{` = Shift + `[` (keycode `0x2F`, модификатор `0x02`).

## Шаг 2: почему USB — хороший канал

USB-трафик объёмный: клавиатура шлёт отчёт при каждом изменении. Среди «настоящих»
нажатий можно спрятать «лишние» — например, нажатия модификаторов без клавиш, или
клавиши, которые не печатаются в приложении. Получатель знает, как их отделить, а
обычный наблюдатель видит просто «поток ввода».

## Шаг 3: читаем HID-коды вручную

```bash
python3 - <<'PY'
KEY = {0x04:'a',0x05:'b',0x06:'c',0x07:'d',0x08:'e',0x09:'f',0x0A:'g',0x0B:'h',
0x0C:'i',0x0D:'j',0x0E:'k',0x0F:'l',0x10:'m',0x11:'n',0x12:'o',0x13:'p',0x14:'q',
0x15:'r',0x16:'s',0x17:'t',0x18:'u',0x19:'v',0x1A:'w',0x1B:'x',0x1C:'y',0x1D:'z',
0x1E:'1',0x1F:'2',0x20:'3',0x21:'4',0x22:'5',0x23:'6',0x24:'7',0x25:'8',0x26:'9',
0x27:'0',0x2C:' ',0x2D:'-',0x2F:'[',0x30:']'}
SHIFT = {'[':'{',']':'}', '-':'_'}
d = open('report.bin','rb').read()
out = ''
for i in range(0, len(d), 8):
    mod = d[i]; kc = d[i+2]
    if kc == 0:
        continue
    ch = KEY.get(kc, '?')
    if mod & 0x02 and ch in SHIFT:
        ch = SHIFT[ch]
    out += ch
print(out)
PY
```


## Шаг 4: где ещё прячут в USB

- **Модификаторы** без клавиш — «фантомные» Shift/Ctrl несут биты.
- **Порядок отчётов** — перестановочный канал.
- **Интервалы между отчётами** — тайминг-канал.
- **Дескрипторы** — строки производителя/серийника (произвольный текст).
- **Массивы хранения** — большие «пустые» области в дескрипторах.

## Шаг 5: инструменты

```bash
tshark -r capture.pcap -V          # разбор USB-трафика
usbmon / usbtop                    # мониторинг (Linux)
wireshark                          # визуальный разбор
```

Wireshark умеет разбирать HID-отчёты и даже показывать «нажатия». `tshark -V` печатает
все поля. Но в CTF обычно дают «сырой» дамп, и разбор идёт по 8 байт вручную.

## Шаг 6: почему это стеганография

USB-трафик — это «запись действий». Если в неё добавить «лишние» действия, получится
скрытое сообщение внутри обычного потока ввода. Это тот же принцип, что и в CAN:
использовать поле/событие, на которое получатель не реагирует. Разница в том, что
USB-отчёты человек читает как «нажатия», и не замечает добавленных.

## Шаг 7: частые ошибки

Первая — не пропускать отчёты с нулевым keycode: это «отпускание» клавиши, а не
символ. Вторая — забыть про Shift: без него `{` не получится. Третья — путать HID
usage ID с ASCII: `0x04` — это `a`, а не «EOT». Четвёртая — неверно определить
размер отчёта (8 байт для boot-протокола, но может быть и другой).

## Дескрипторы USB и строковые поля

Кроме HID-отчётов, у USB-устройств есть **дескрипторы** — структуры, описывающие
устройство. При подключении хост читает дескриптор устройства, конфигурации,
интерфейса и строк. Строковые дескрипторы содержат производителя, продукт и
серийный номер — произвольный текст, который никто не проверяет на «нормальность».

Спрятать данные там просто: серийный номер может быть длинной строкой с сообщением.
Для анализа нужен дамп трафика на этапе перечисления (enumeration). Wireshark
показывает дескрипторы как `Device Descriptor`, `String Descriptor` и так далее.

Ещё один носитель — **конечные точки (endpoints)** с «пустыми» передачами: USB
разрешает нулевые пакеты, которые можно использовать как сигнал или канал.

## Практика: разбор USBPcap через tshark

Захват USB на Windows делают USBPcap, на Linux — usbmon. Разберём без GUI:

```bash
tshark -r usb.pcap -Y 'usbhid' -T fields -e usbhid.data | head -20
```

Это выведет HID-отчёты как hex. Дальше их можно декодировать нашим скриптом. Если
устройство — клавиатура, фильтр `usb.capdata` покажет нажатия. Для строковых
дескрипторов используй фильтр `usb.string`.

```bash
tshark -r usb.pcap -Y 'usb.string' -T fields -e usb.string | sort -u
```

Если среди строк есть «мусор» из base64 или hex — это кандидат на закладку.

## BadUSB и почему это важно

**BadUSB** — атака, при которой устройство притворяется клавиатурой и «печатает»
команды. Для нашей темы важно обратное: если клавиатура может печатать что угодно,
значит, последовательность нажатий — это полноценный канал передачи. В CTF задачи на
USB часто строятся именно на этом: дамп нажатий нужно декодировать, как мы сделали
в примере. Понимая HID-коды, ты решаешь и «защитную» (анализ дампа), и «атакующую»
(эмуляция ввода) сторону.

## Итоговая стратегия для USB

Определи тип устройства по дескриптору; если HID-клавиатура — декодируй отчёты по
8 байт; пропускай отчёты с keycode 0; учитывай Shift; проверь строковые дескрипторы;
посмотри интервалы между отчётами. Для мыши отчёты другие (смещения X/Y), но принцип
тот же: «лишние» биты в полях. И помни, что Wireshark/`tshark` показывают отчёты
готовыми к декодированию.

## Как отличить закладку от штатного ввода

В реальном дампе клавиатуры «лишние» нажатия неотличимы от настоящих, если смотреть
только на HID-коды. Поэтому в задачах обычно дают «чистый» дамп, где весь поток —
это сообщение. В реальной форензике признаки закладки такие:

- **Отчёты модификаторов без клавиш.** Нажали Shift и отпустили, ничего не напечатав.
- **Повторяющиеся последовательности.** Один и тот же набор кодов через равные
  интервалы.
- **Отчёты с keycode вне таблицы.** Неизвестные HID-коды (например, > 0x65) —
  потенциальный канал.
- **Слишком ровные интервалы.** Человек печатает неравномерно; машина — идеально.

Практический приём: построй гистограмму HID-кодов. Если доминируют коды, дающие
осмысленный текст, — это сообщение; если разброс «человеческий» — настоящий ввод.

## Практика: декодирование с учётом модификаторов

В нашем скрипте модификатор учитывался только для Shift. В реальности модификаторов
несколько: Ctrl (`0x01`), Shift (`0x02`), Alt (`0x04`), GUI (`0x08`), а также их
правые версии. Полноценный декодер проверяет каждый бит:

```bash
python3 - <<'PY'
d = open('report.bin','rb').read()
for i in range(0, len(d), 8):
    mod, kc = d[i], d[i+2]
    flags = [name for bit,name in [(1,'Ctrl'),(2,'Shift'),(4,'Alt'),(8,'GUI')] if mod & bit]
    if kc:
        print(i//8, flags, hex(kc))
PY
```

Такой вывод показывает «сырые» события, и ты сам решаешь, как их трактовать. Для
задач с нестандартной кодировкой это важнее, чем готовый декодер.

## Почему USB-трафик — «событийный» канал

USB-HID передаёт состояние устройства, а не символы. Клавиатура шлёт «какие клавиши
нажаты сейчас». Значит, любое изменение состояния — событие, и событий можно
добавлять сколько угодно. Это принципиально отличается от текстового файла: там
данные лежат «в байтах», а здесь — «в переходах». Поэтому USB-стеганография ближе к
тайминговым каналам: важно не только «что», но и «когда». Понимая это, ты решаешь
задачи, где нажатия «не складываются» в текст напрямую — например, кодируют биты
чётностью интервалов между отчётами.

## Что мы теперь знаем

- HID-отчёт клавиатуры — 8 байт: модификатор + 6 кодов.
- HID usage ID: `0x04`..`0x1D` = `a`..`z`; Shift (`0x02`) даёт символы вроде `{`.
- Отчёты с keycode 0 — отпускание, их пропускают.
- Каналы: модификаторы, порядок, тайминги, дескрипторы.
- Инструменты: Wireshark, `tshark`, usbmon.
