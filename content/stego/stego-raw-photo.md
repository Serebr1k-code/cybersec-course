## Вопрос, с которого всё начинается

В CTF дали файл `holiday.nef` — фотографию, снятую на камеру Nikon в формате RAW. Открываешь в просмотрщике: обычный пейзаж, ничего подозрительного. Подсказка: «камера сохранила больше, чем один кадр». Что это значит?

**RAW-фото** — это «негатив» камеры: сырые данные с сенсора плюс обширные метаданные. Почти все RAW (Canon CR2/CR3, Nikon NEF, Adobe DNG, Sony ARW) — это **TIFF-контейнеры** со специфичными тегами и, что важно для стеганографии, со **встроенными JPEG-превью** разных размеров. Превью — полноценная картинка внутри файла, и она часто остаётся нетронутой даже после правки основного изображения. Разберём один файл целиком.

## Наш пример: holiday.nef

Определяем, с чем имеем дело:

```bash
$ file holiday.nef
holiday.nef: TIFF image data, big-endian
```

Файл начинается как TIFF. Причём `big-endian` — порядок байт, при котором старший байт идёт первым (для NEF это типично; CR2 и DNG обычно little-endian). Это важно запомнить: при ручном разборе смещения читаются с учётом endianness, и скрипт, который этого не делает, «не найдёт» данные.

Смотрим все теги разом:

```bash
$ exiftool -a -u -g1 holiday.nef | head -40
[ExifTool]      ExifToolVersion : 12.60
[File]          FileType        : NEF
[IFD0]          Make            : NIKON CORPORATION
[IFD0]          Model           : NIKON D5600
[SubIFD]        JpgFromRaw      : (Binary data 2456789 bytes, use -b option to extract)
[SubIFD]        PreviewImage    : (Binary data 123456 bytes, use -b option to extract)
[IFD0]          MakerNoteNikon  : (Binary data 28916 bytes, use -b option to extract)
```

Три подсказки: `JpgFromRaw` (полноразмерное превью, ~2,4 МБ), `PreviewImage` (среднее, ~123 КБ) и `MakerNoteNikon` (приватный блок производителя). Каждое из этих полей — отдельный носитель.

## Шаг 1: извлекаем встроенные превью

Превью — это готовые JPEG. Извлекаем их тегом `-b` (binary), который пишет сырые данные в файл:

```bash
$ exiftool -b -JpgFromRaw holiday.nef > full.jpg
$ exiftool -b -PreviewImage holiday.nef > preview.jpg
$ exiftool -b -ThumbnailImage holiday.nef > thumb.jpg 2>/dev/null
$ ls -l full.jpg preview.jpg
-rw-r--r-- 1 user user 2456789 full.jpg
-rw-r--r-- 1 user user  123456 preview.jpg
```

Ещё один способ найти все картинки внутри — `binwalk`, который ищет сигнатуры JPEG по всему файлу:

```bash
$ binwalk holiday.nef
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             TIFF image data, big-endian
8192          0x2000          JPEG image data, EXIF standard
...
```

Сигнатура JPEG начинается байтами `FF D8 FF`; их можно искать и напрямую: `grep -aboP '\xff\xd8\xff' holiday.nef`.

## Шаг 2: прогоняем превью через стегоанализ

Теперь по каждому извлечённому JPEG — `zsteg`:

```bash
$ zsteg full.jpg
b1,r,lsb,xy .. text: "flag{raw_embedded_preview}"
```

Флаг нашёлся в младших битах **встроенного превью**, а основное изображение при этом выглядело безобидно. Это типовой приём RAW-задач: правят не основную картинку, а превью внутри неё.

Если одно превью пустое — проверяем **все** подряд, включая миниатюру:

```bash
$ for t in JpgFromRaw PreviewImage ThumbnailImage; do
    exiftool -b -$t holiday.nef > "$t.jpg" 2>/dev/null && zsteg "$t.jpg";
  done
```

Почему важно проверить все? Потому что маленькая миниатюра может быть пустой, а полноразмерное превью — с данными, и наоборот. У каждого свой размер и свои LSB.

## Шаг 3: MakerNote и «дыры»

**MakerNote** — приватный блок производителя внутри метаданных. У него своя вложенная структура и свои теги: серийный номер, счётчик затвора и просто свободное место. Извлекаем блок целиком и ищем в нём строки:

```bash
$ exiftool -b -MakerNoteNikon holiday.nef > mn.bin
$ strings -n 6 mn.bin | head
SHOOTING MODE
flag{maker_note}
```

Дополнительно смотрим служебные значения камеры:

```bash
$ exiftool -ShutterCount -SerialNumber holiday.nef
Shutter Count : 8421
Serial Number : 6012345
```

Сенсорные данные (основной блок изображения) тоже часто содержат **padding** — байты выравнивания, в которых можно спрятать информацию. Их ищут `binwalk` и `grep -aboP`:

```bash
$ grep -aboP 'PK\x03\x04|flag\{' holiday.nef
```

## Шаг 4: сравнение превью и основного изображения

Мощный приём — сравнить версии одного и того же кадра. Превью внутри RAW могло остаться от момента съёмки, а основное изображение (или его метаданные) правили позже. Расхождение — сильный сигнал:

```bash
$ exiftool full.jpg | grep -iE "datetime|software"
$ exiftool thumb.jpg | grep -iE "datetime|software"
$ compare full.jpg thumb.jpg diff.png 2>/dev/null
```

Если в превью есть строка с флагом, а в основном изображении — нет (или наоборот), задача решена. Иногда в превью прячут LSB-данные, а основную картинку оставляют визуально чистой.

## Шаг 5: DNG и CR3 — особые случаи

Два формата выбиваются из общего правила.

**DNG** (Digital Negative) — открытый формат Adobe, тоже TIFF, но со своими тегами: `DNGVersion`, `UniqueCameraModel`, `ColorMatrix1/2`. Внутри часто несколько IFD (основное изображение, уменьшенное превью, иногда «флэт»-кадр) — проходить нужно всю цепочку:

```bash
$ exiftool -a -u -g1 -DNG:all photo.dng
$ dcraw -T photo.dng            # конвертирует в TIFF
$ exiftool -b -PreviewImage photo.dng > preview.jpg
```

**CR3** — новое поколение Canon — вообще не TIFF, а **ISOBMFF** (формат медиаконтейнера, как в MP4/HEIF). Для него работают инструменты из уроков по HEIF/AVIF, а не `tiffdump`. Проверить формат просто: если `file` говорит `ISO Media` или `ftyp`, а не `TIFF`, — это ISOBMFF.

## Что мы теперь знаем

1. Почти все RAW — это TIFF-контейнеры; порядок байт различается по бренду (NEF — big-endian, CR2/DNG — little-endian).
2. Внутри RAW лежат 1–3 встроенных JPEG-превью (`JpgFromRaw`, `PreviewImage`, `ThumbnailImage`) — это отдельные носители.
3. Данные чаще всего прячут в LSB встроенного превью, а не в основном изображении.
4. `exiftool -b -<тег>` извлекает бинарные поля; `binwalk` и `grep -aboP` находят все JPEG-потоки и дописанные файлы.
5. MakerNote — приватный блок с кастомными тегами и свободным местом.
6. CR3 — это ISOBMFF, а не TIFF; для него нужны другие инструменты.

## Почему RAW хранит больше, чем JPEG

RAW (CR2/NEF/DNG/ARW) — это **TIFF-контейнер** с сырыми сенсорными данными и целой обвязкой: метаданные съёмки, встроенные JPEG-превью, MakerNote вендора, иногда второе превью меньшего размера. JPEG же — уже сжатый результат, где пиксели и метаданные «утрамбованы». Отсюда следствие: RAW предоставляет **много мест для сокрытия**, которых в JPEG просто нет.

Самое очевидное — встроенное **превью**. Камера кладёт в RAW готовый JPEG (часто full-size), чтобы просмотрщики показывали картинку без обработки сенсора. Это отдельный файл внутри файла: в нём можно спрятать данные тем же стего-инструментарием, что и в обычном JPEG, а оригинал при этом не тронут. Второе место — **MakerNote**: приватный блок вендора, куда пишут всё что угодно, включая пользовательские теги; его формат не стандартизован, поэтому туда легко положить полезную нагрузку. Третье — «дыры» и выравнивание между IFD: TIFF состоит из тегов с указателями, и неиспользуемые байты — свободное место.

Практический вывод: RAW стоит препарировать послойно. Сначала `exiftool -a -u -g1` (все теги, включая неизвестные), затем извлечение всех превью, потом диффа превью и основного изображения — расхождения могут быть вписаны вручную.

## Если не сработало

- **Превью не извлекается.** У разных вендоров разные смещения; используйте `exiftool -b -PreviewImage`, `dcraw -e`, `exiv2`, `rawpy` — они знают структуру конкретного формата.
- **Стегоанализ превью ничего не даёт.** Возможно, данные в MakerNote или в неиспользуемых байтах IFD — смотрите hex-дампы, а не только картинку.
- **DNG/CR3 ведут себя иначе.** DNG — открытый TIFF, CR3 — ISO-BMFF (не TIFF); для CR3 нужны другие парсеры (`exiftool`, `cr3`).
- **Файл обрезан или пересжат.** Если RAW прошёл через конвертер, превью могло быть пересоздано — оригинальные данные потеряны.
- **Размеры не совпадают.** Сравнивайте превью не только визуально, но и по пикселям (`compare`, `ImageMagick`): вписанные данные видны как локальные различия.

## Частые вопросы

**Всегда ли в RAW есть JPEG-превью?** Почти всегда (иначе камера не показала бы снимок), но размер и качество различаются; иногда превью несколько.

**Что такое MakerNote простыми словами?** Приватный блок метаданных производителя, не описанный в стандарте EXIF; туда пишут серийники, настройки, а иногда и произвольные данные.

**Чем DNG отличается от CR2/NEF?** DNG — открытый формат Adobe (тоже TIFF), CR2/NEF — проприетарные TIFF-подобные контейнеры; структура похожа, но теги и превью отличаются.

## Куда дальше

RAW показал, что внутри одного «фото» живёт несколько изображений и служебных блоков. В следующем уроке разберём **типографику** — там данные прячут в кернинге, лигатурах и вариативных шрифтах. А пока запомни пайплайн для RAW: `file` → `exiftool` → извлечь **все** превью → `zsteg` → MakerNote → `binwalk`.
