## Вопрос, с которого всё начинается

В CTF дали `stego.mp4` — двенадцать секунд обычного видео. Проигрываешь, смотришь, слушаешь — ничего необычного. `strings` показывает мусор, `exiftool` — тишина. Но где-то в файле лежит флаг, и подсказка — «файл не то, чем кажется».

Ответ: MP4 — это не «видео», а **контейнер**, ящик с несколькими дорожками. Внутри могут лежать не только видео и звук, но и лишние потоки, вложения, метаданные и просто дописанные байты — всё то, что проигрыватель молча игнорирует. Разберём наш файл послойно.

## Наш пример: stego.mp4

Контейнер (по-английски **container**, «ящик») хранит несколько дорожек — **потоков** (streams): видео, аудио, субтитры, данные. Формат MP4 построен на «боксах» — блоках с именем: `moov` описывает дорожки, `mdat` хранит сами данные, `udta`/`meta` — метаданные. Проигрыватель читает `moov`, находит стандартные дорожки и играет их; всё остальное он не показывает.

Первый шаг — спросить контейнер, какие потоки он в себе несёт. Это делает `ffprobe`:

```bash
$ ffprobe -v error -show_entries stream=index,codec_type,codec_name,duration -of csv stego.mp4
0,video,h264,12.48
1,audio,aac,12.48
2,data,bin_data,0.00
```

Смотри на третью строку. Видео и аудио — ожидаемы. А вот поток `2` типа `data` с кодеком `bin_data` и длительностью `0.00` — это **не** видео и не звук. Это закладка: плеер такой поток не играет и не показывает. Классический признак спрятанного файла.

## Шаг 1: извлекаем поток данных

Каждый поток адресуется по индексу. В `ffmpeg` опция `-map 0:2` означает «взять из входа 0 поток номер 2», а `-c copy` — «скопировать байты как есть, без перекодирования». Перекодирование пересчитало бы данные и уничтожило закладку, поэтому `copy` обязателен:

```bash
$ ffmpeg -i stego.mp4 -map 0:2 -c copy hidden.bin
$ file hidden.bin
hidden.bin: Zip archive data, at least v2.0 to extract
```

Мы вытащили поток, и `file` по сигнатуре `PK` (первые байты ZIP) определил: это ZIP-архив. Смотрим содержимое, не распаковывая:

```bash
$ unzip -l hidden.bin
Archive:  hidden.bin
  Length      Date    Time    Name
--------  ---------- -----   ----
       24  2024-01-01 00:00   flag.txt
--------                     -------
       24                     1 file
```

Внутри — `flag.txt`. Задача решена. Ключевой урок: `ffprobe` показал поток, `-map` его вытащил.

## Шаг 2: если потока нет, а данные есть — binwalk

Иногда закладку не оформляют отдельным потоком, а просто дописывают файл в конец `mdat`. Тогда `ffprobe` ничего лишнего не покажет. На этот случай есть `binwalk` — он сканирует файл по сигнатурам и находит встроенные форматы по их «магическим» байтам:

```bash
$ binwalk stego.mp4
DECIMAL       HEXADECIMAL     DESCRIPTION
------------------------------------------------------------------------------
524288        0x80000         Zip archive data, at least v2.0 to extract, name: flag.txt
```

Число `524288` — **смещение** (offset, номер байта от начала файла), с которого начинается ZIP. Вырезаем этот кусок командой `dd`: `bs=1 skip=524288` означает «читать по одному байту, пропустив первые 524288 байт».

```bash
$ dd if=stego.mp4 of=hidden.zip bs=1 skip=524288
$ unzip -l hidden.zip
```

Если `binwalk` нашёл сигнатуру, но ты не уверен в конце блока — ищи второй сигнатуры или признак конца (`PK\x05\x06`, End Of Central Directory для ZIP).

## Шаг 3: несоответствие длительности A и V

Ещё один канал — рассинхрон. Если аудиодорожка длиннее видео на несколько секунд, в «хвосте» звука может быть спрятано сообщение. Проверяем длительности:

```bash
$ ffprobe -v error -show_entries stream=codec_type,duration -of csv stego.mp4
video,12.48
audio,14.02
```

Расхождение почти в две секунды — повод извлечь аудио целиком и проанализировать хвост:

```bash
$ ffmpeg -i stego.mp4 -map 0:a -c copy full_audio.aac
$ ffmpeg -i full_audio.aac -af "atrim=start=12.5" tail.wav
```

`atrim=start=12.5` обрезает всё до 12.5-й секунды — остаётся только «лишний» хвост. Его можно прослушать, прогнать через спектрограмму (`stego-audio-spec`) или поискать текст.

Тонкий вариант того же приёма — **audio-video offset**: биты кодируют не длиной, а задержкой между началом аудио и видео. Проверяют так: `ffprobe` с пакетами и сравнение первых `pts_time` видеопотока и аудиопотока. Разница и есть смещение.

## Шаг 4: вложения и главы в MKV

Формат Matroska (`.mkv`) умеет хранить **вложения** (attachments) — целые файлы внутри видео. Их перечисляет `mkvinfo`, а извлекает `mkvextract`:

```bash
$ mkvinfo stego.mkv | grep -A3 Attachments
|+ Attachments
| + Attached
|  + File name: secret.txt
|  + Mime type: text/plain
$ mkvextract attachments stego.mkv 1:secret.txt
$ cat secret.txt
flag{mkv_attachment}
```

Кроме вложений у Matroska есть **главы** (chapters) и **теги** (tags) — текстовые блоки с произвольным содержимым. В них часто прячут base64 или hex:

```bash
$ mkvextract chapters stego.mkv
$ mkvextract tags stego.mkv
```

И субтитры — отдельная текстовая дорожка. Её тоже извлекают и смотрят отдельно, потому что и тайминги, и текст можно модулировать (см. урок про текстовые каналы).

## Шаг 5: метаданные, обложка и «сироты»

Кроме потоков у контейнера есть метаданные — боксы `udta`/`meta` в MP4 и теги в MKV. Это произвольные строки, которые тоже служат каналом: в них прячут base64 или hex. Обложка (attached picture) — вложенное изображение; её извлекают как обычный файл и проверяют на LSB отдельно. Наконец, встречаются «сироты» — потоки, на которые нет ссылки в `moov`: декодер их игнорирует, но байты в `mdat` лежат. `ffprobe` их не покажет, поэтому ищут по сигнатурам внутри области данных.

```bash
$ strings stego.mp4 | grep -iE 'flag|base64|==$'
$ exiftool stego.mp4 | grep -iE 'comment|title|description'
```

## Если ничего не нашли

Контейнер многослоен, поэтому пройди чек-лист по порядку:

1. `ffprobe -show_streams` — все потоки и их типы.
2. Сравни длительности видео, аудио и субтитров.
3. `binwalk`/`strings` — дописанные данные и метаданные (`udta`/`meta`).
4. Для MKV — `mkvinfo`/`mkvextract`: дорожки, вложения, главы, теги.
5. `ffmpeg -i in.mp4 -map 0 -c copy out.mp4` — скопировать **все** потоки; если их стало меньше, исходник содержал лишние.
6. Обложку (attached picture) проверь как отдельное изображение — в ней может быть LSB.

Важная ошибка: не полагайся на проигрывание. Плеер скрытые и отключённые (`enabled=false`) дорожки не показывает — «выглядит нормально» ничего не доказывает.

## Что мы теперь знаем

1. MP4/MKV/AVI — контейнеры: «файловая система в файле» с несколькими потоками.
2. `ffprobe -show_streams` показывает все потоки; поток `data`/`bin_data` — закладка.
3. Извлекать надо с `-map` и `-c copy`, иначе перекодирование уничтожит данные.
4. `binwalk` + `dd` вырезают файлы, дописанные в конец контейнера.
5. Расхождение длительностей A/V — сигнал проверить «хвост».
6. В MKV данные живут во вложениях, главах, тегах и субтитрах.

## Куда дальше

Мы разобрали контейнер как «файловую систему» и научились вытаскивать из него лишние потоки, вложения и хвосты. Дальше спустимся ещё глубже — в сам кодек — и посмотрим, как данные прячут не в дорожках, а в векторах движения и режимах предсказания H.264/HEVC. А пока запомни: видео — это ящик, и в нём всегда есть служебные области, куда смотрят в первую очередь.
