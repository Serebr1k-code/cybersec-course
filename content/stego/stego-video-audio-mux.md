Мультимедийный контейнер (MP4, MKV, AVI, MOV) — это не «видеофайл», а ящик с несколькими дорожками: видео, аудио, субтитры, главы, метаданные, иногда вложения. Каждый уровень можно использовать для сокрытия: добавить невидимую дорожку, спрятать данные в метаданных главы, «дописать» поток за концом видео или закодировать биты в рассинхронизации аудио и видео. Стандартные инструменты показывают контейнер как единое целое, поэтому лишний поток легко не заметить. Этот урок — про то, как найти и извлечь данные из мультиплекса.

## Анатомия контейнера

- **MP4/MOV (ISOBMFF).** Боксы `moov`, `trak`, `mdat`. Дорожки описываются в `moov`; данные — в `mdat`. Можно добавить `trak`, который плееры игнорируют.
- **MKV/WebM (Matroska/EBML).** Гибкая структура из элементов; легко добавляются новые дорожки, вложения (`Attachments`), теги.
- **AVI (RIFF).** Список `strl`-потоков; можно дописать поток или данные после конца.
- **Дорожки.** Бывают «скрытые» (флаг `enabled=false`, `default=false`), но присутствующие в файле.

Ключевая идея: контейнер допускает существование данных, которые не отображаются при обычном воспроизведении.

## Инструменты и команды

- **`ffprobe`** — показать все потоки: `ffprobe -v error -show_streams -show_format in.mp4`.
- **`ffmpeg`** — извлечь/перекодировать потоки, картинки обложек.
- **`mkvmerge`/`mkvinfo`** (MKVToolNix) — детальный разбор Matroska, список дорожек и вложений.
- **`MP4Box`** (gpac) — разбор/сборка ISOBMFF.
- **`binwalk`** — поиск встроенных файлов по сигнатурам внутри контейнера.
- **`mediainfo`** — человекочитаемая сводка.
- **`xxd`, `strings`** — ручной осмотр.

Список потоков:

```bash
ffprobe -v error -show_entries stream=index,codec_type,codec_name,duration -of csv in.mp4
```

Вывод (подозрительный — 3 потока, один «data»):

```
0,video,h264,12.48
1,audio,aac,12.48
2,data,bin_data,0.00
```

Поток `data` с длительностью 0 — классический признак спрятанного файла.

## Разобранный пример: скрытая дорожка в MP4

```bash
# 1) смотрим потоки
ffprobe -v error -show_streams stego.mp4 | grep -E "index|codec_name|codec_type"

# 2) извлекаем поток данных
ffmpeg -i stego.mp4 -map 0:2 -c copy hidden.bin
file hidden.bin
# -> hidden.bin: Zip archive data

unzip -l hidden.bin
```

Вывод:

```
Archive:  hidden.bin
  Length      Date    Time    Name
       24  2024-01-01 00:00   flag.txt
```

Альтернатива — `binwalk` найдёт сигнатуру ZIP прямо внутри MP4:

```bash
binwalk stego.mp4
# DECIMAL   HEXADECIMAL   DESCRIPTION
# 524288    0x80000       Zip archive data, at least v2.0
dd if=stego.mp4 of=hidden.zip bs=1 skip=524288
```

## Несоответствие длины и рассинхронизация

Если аудиодорожка длиннее видео (или наоборот) на несколько секунд — в «хвосте» может быть спрятан звук/данные. Проверка:

```bash
ffprobe -v error -show_entries stream=codec_type,duration -of csv in.mp4
```

Расхождение длительностей — повод извлечь «хвост»:

```bash
ffmpeg -i stego.mp4 -map 0:a -c copy full_audio.aac
# сравнить с длительностью видео, послушать/проанализировать хвост
```

Иногда данные прячут, закодировав биты в задержке между A и V (audio-video offset) — тогда нужен покадровый анализ.

## Вложения и главы (MKV)

Matroska позволяет прикреплять файлы как вложения:

```bash
mkvinfo stego.mkv | grep -A3 Attachments
# |+ Attachments
# | + Attached
# |  + File name: secret.txt
# |  + Mime type: text/plain

mkvextract attachments stego.mkv 1:secret.txt
cat secret.txt
# -> flag{mkv_attachment}
```

Главы (`Chapters`) и теги (`Tags`) тоже текстовые — проверяйте на base64/hex:

```bash
mkvextract chapters stego.mkv
mkvextract tags stego.mkv
```

## Cover selection и генерация

Иногда видео генерируют под сообщение (синтезированный cover) — тогда детект почти невозможен, но и «естественного» источника нет. Признаки: идеальная равномерность, отсутствие шума сенсора, слишком «чистые» кадры. Для CTF это редкость, но если контейнер выглядит искусственно — возможно, данные в самом процессе генерации.

## Крайние случаи и подводные камни

- **Плеер не показывает лишний поток.** Не полагайтесь на проигрывание — используйте `ffprobe`/`mkvinfo`.
- **Флаги enabled/default.** Дорожка может быть отключена по умолчанию, но данные в ней есть.
- **Дописанные данные после `mdat`.** `binwalk`/`dd` по смещению — стандартный путь.
- **Перекодирование теряет структуру.** Если файл прогнали через `ffmpeg -c copy` без `-map`, лишние потоки исчезнут.
- **Кодек не распознан.** Поток `bin_data`/`unknown` часто и есть контейнер с данными.
- **Метаданные ISOBMFF.** Боксы `udta`, `meta` содержат произвольные строки — `strings` их покажет.

## Что дальше / решение

- Потоков больше, чем ожидается — извлеките все через `-map` и проверьте `file`.
- `binwalk` нашёл сигнатуру — режьте `dd` по смещению и распаковывайте.
- MKV с вложениями — `mkvextract attachments`.
- Рассинхрон A/V — анализируйте хвост и задержки покадрово.
- Ничего не нашли — проверьте метаданные (`udta`/`meta`) и субтитры.

## Справочная таблица

| Контейнер | Структура | Где прячут |
|---|---|---|
| MP4/MOV | ISOBMFF боксы | лишний `trak`, `udta`/`meta`, хвост `mdat` |
| MKV/WebM | EBML | дорожки, Attachments, Chapters, Tags |
| AVI | RIFF | доп. поток, данные после конца |
| MOV | ISOBMFF | как MP4 |

## Покадровый анализ и субтитры

Помимо дорожек, контейнер хранит субтитры и метаданные, которые тоже бывают каналом. Субтитры (SRT/ASS/WebVTT) — это текст с таймингами; тайминги можно слегка смещать, кодируя биты, а сам текст — использовать как носитель (acrostic, zero-width, base64). Извлеките дорожку субтитров и посмотрите на неё отдельно:

```bash
ffprobe -v error -select_streams s -show_entries stream=index,codec_name -of csv in.mkv
ffmpeg -i in.mkv -map 0:s:0 subs.srt
cat subs.srt | head
```

Если тайминги идут «неровно» (0.997с вместо 1.000с), это может быть кодирование. Метаданные глав (`chapters`) в MKV — отдельный текстовый блок; `mkvextract chapters` покажет названия, в которых прячут строки.

## Аудио-видео offset как канал

Тонкий канал — рассинхронизация аудио и видео. Кодеры хранят начальное смещение и задержки; если A начинается на `d` миллисекунд позже V, это число. Последовательность таких смещений по сегментам кодирует данные. Проверить сложнее: нужен покадровый разбор PTS/DTS.

```bash
ffprobe -v error -show_entries packet=stream_index,pts_time -of csv in.mp4 | head
```

Сравните первые `pts_time` видео- и аудио-пакетов: разница и есть offset. В задачах это редкость, но признак — «идеально синхронные» или «странно смещённые» потоки.

## Расчёт и проверка через ffmpeg

Полезные команды для полного разбора контейнера:

- `ffprobe -v error -show_streams -show_format -show_chapters in.mp4` — всё сразу.
- `ffmpeg -i in.mp4 -map 0 -c copy out.mp4` — копия всех потоков (проверка, что не теряются).
- `ffmpeg -i in.mp4 -f data -map 0:2 raw.bin` — извлечь поток данных.
- `mediainfo --Full in.mp4` — расширенная сводка.
- `mkvmerge -i in.mkv` — список дорожек Matroska.

Практический приём: сравните `ffprobe` «как есть» и после `-map 0 -c copy`. Если число потоков уменьшилось — исходный файл содержал «лишние» дорожки, которые ffmpeg по умолчанию выбрасывает.

## Дополнительные векторы в контейнерах

- **Обложка (attached picture).** В MP4/MKV можно вложить изображение — оно может содержать LSB-данные.
- **Метаданные ISO.** Боксы `udta`/`meta` содержат произвольные строки; `strings` их покажет.
- **Пустые/нулевые дорожки.** Дорожка с нулевыми данными — контейнер под данные.
- **Дописанные байты.** После последнего бокса можно дописать что угодно; `binwalk`/`dd` найдут.
- **Разные кодеки на одном потоке.** Редко, но встречается подмена.

Итог: контейнер — это «файловая система в файле», и в ней всегда есть служебные области, не влияющие на воспроизведение. Именно туда смотрят в первую очередь.

## Субтитры и телетекст как канал

Контейнеры с субтитрами дают ещё один текстовый слой. Форматы SRT/ASS/WebVTT хранят текст и тайминги; оба можно модулировать. Данные прячут:

- **В таймингах.** Микро-сдвиги начала/конца (0.997с) кодируют биты.
- **В тексте.** Zero-width, акростих, base64 в репликах.
- **В стилях ASS.** Цвета, позиции, шрифты — числовые параметры.
- **В количестве реплик.** Лишние «пустые» субтитры.

```bash
ffmpeg -i in.mkv -map 0:s:0 subs.srt
python3 - <<'PY'
import re
t = open("subs.srt").read()
times = re.findall(r"(\d+):(\d+):(\d+),(\d+)", t)
print("first 6 timestamps:", times[:6])
PY
```

Неровные миллисекунды — сигнал.

## Метаданные ISO и главы

В MP4/MKV метаданные (`udta`, `meta`, `Tags`) — произвольные строки. Главы (`chapters`) — отдельный текстовый блок. Оба часто содержат base64/hex.

```bash
mkvextract chapters in.mkv
mkvextract tags in.mkv
strings in.mp4 | grep -iE 'flag|http|base64|==$'
```

## Скрытые потоки и «сироты»

Поток может быть помечен отключённым (`enabled=false`) и не отображаться. Некоторые контейнеры допускают потоки без ссылки в `moov` («сироты»), которые декодер игнорирует, но байты в `mdat` присутствуют. `ffprobe` покажет активные потоки; «сироты» ищут `binwalk`/`dd` по сигнатурам внутри `mdat`.

## Чек-лист по контейнеру

1. `ffprobe -show_streams` — все потоки и их типы.
2. Сравните длительности A/V и субтитров.
3. `binwalk`/`strings` — дописанные данные, метаданные.
4. `mkvinfo`/`mkvextract` (MKV) — дорожки, вложения, главы, теги.
5. `ffmpeg -map 0 -c copy` — проверка, что не теряются потоки.
6. Проверьте обложки/вложения как отдельные файлы.
7. Субтитры — тайминги и текст.

Контейнер всегда многослоен; «лишние» байты и потоки — главный источник находок.

## Практический вывод

Контейнер — это «файловая система в файле»: дорожки, вложения, метаданные, главы и хвост. Каждый уровень не влияет на воспроизведение, но хранит байты. Начинайте с `ffprobe`/`mkvinfo`, затем `binwalk`/`strings`, затем субтитры и вложения. В большинстве видео-задач данные находятся именно в этих «служебных» областях, а не в пикселях.
