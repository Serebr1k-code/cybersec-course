## Вопрос, с которого всё начинается

Ты привык, что в картинке данные лежат в младших битах пикселей, и запускаешь `zsteg`. Но для JPEG это не работает: `zsteg` ничего не находит. Почему? Потому что JPEG **сжимает с потерями**, и младшие биты пикселей просто не сохраняются в файле.

Значит, в JPEG прячут в другом месте — в **коэффициентах сжатия**. Разберём это на конкретном файле.

## Наш пример: photo.jpg

Сначала стандартная проверка метаданных и подсказок:

```
$ file photo.jpg
photo.jpg: JPEG image data, JFIF standard 1.01
$ strings -n 6 photo.jpg | grep -iE 'flag|base64'
(пусто)
$ exiftool photo.jpg | grep -iE 'comment|title'
(пусто)
```

Метаданные чистые. Теперь `stegdetect` — инструмент, который по статистике определяет, **каким алгоритмом** спрятаны данные:

```
$ stegdetect photo.jpg
photo.jpg: jsteg
```

`stegdetect` говорит `jsteg`. Значит, применяем соответствующий инструмент:

```
$ jsteg reveal photo.jpg out.txt
$ cat out.txt
flag{jsteg_dct}
```

Готово. Ключевой шаг — **определить метод**, а потом взять инструмент под него.

## Шаг 1: как JPEG сжимает картинку

Чтобы понять, где живут данные, разберём конвейер JPEG:

1. Изображение переводится в цветовое пространство **YCbCr** (яркость + две цветности).
2. Картинка режется на блоки **8×8** пикселей.
3. Для каждого блока считается **дискретное косинусное преобразование (DCT)** — блок раскладывается на 64 коэффициента: один DC (средняя яркость) и 63 AC (частоты).
4. Коэффициенты **квантуются**: делятся на значения из таблицы квантования и округляются. Здесь и теряется информация — появляется сжатие.
5. Результат кодируется энтропийно (Хаффман).

Квантованные коэффициенты после `SOS`-сегмента — то самое место, где прячут данные.

## Шаг 2: почему именно коэффициенты

Младшие биты пикселей после квантования **не сохраняются** — их съедает округление. А вот сами квантованные AC-коэффициенты сохраняются, и их младший бит можно менять. Изменение одного коэффициента чуть-чуть меняет блок — глазу незаметно.

Данные прячут в **ненулевых** коэффициентах: нулей после квантования много, и менять их заметно (ломает сжатие). Таблицы квантования лежат в сегменте `DQT` — их можно посмотреть:

```
$ djpeg -verbose photo.jpg > /dev/null 2>&1 | grep -i quant
```

## Шаг 3: JSteg — простейший метод

**JSteg** заменяет младший бит ненулевых квантованных коэффициентов на бит сообщения. Просто, но легко детектируется: младшие биты пар `2k`/`2k+1` выравниваются, и хи-квадрат-тест это видит.

```
$ stegdetect photo.jpg          # покажет jsteg
$ jsteg reveal photo.jpg out.txt
```

## Шаг 4: F5 и OutGuess — «укреплённые» методы

JSteg ловится статистикой, поэтому придумали методы хитрее:

- **F5** не заменяет бит, а **уменьшает модуль** коэффициента, и кодирует несколько бит одним изменением (**матричное кодирование**). Требует ключ.
- **OutGuess 0.2** после встраивания **корректирует остальные** коэффициенты, чтобы гистограмма вернулась к естественному виду. Тоже требует ключ.

Под них — свои инструменты:

```
$ outguess -r photo.jpg out.txt              # OutGuess без ключа
$ outguess -k hunter2 -r photo.jpg out.txt   # с ключом
$ java -jar F5.jar d -p pass -c photo.jpg    # F5
```

## Шаг 5: не только коэффициенты

Помимо коэффициентов, в JPEG есть служебные сегменты — и они тоже канал. JPEG — это поток сегментов, каждый с маркером `FF xx`:

| Маркер | Сегмент | Содержимое |
|---|---|---|
| FFD8 | SOI | начало |
| FFE0 | APP0 | JFIF |
| FFE1 | APP1 | EXIF/XMP (метаданные) |
| FFDB | DQT | таблицы квантования |
| FFC4 | DHT | таблицы Хаффмана |
| FFDA | SOS | начало данных |
| FFD9 | EOI | конец |

Данные прячут в `APP`/`COM`-сегментах и таблицах. Проверь их:

```
$ exiftool -a -u -g1 photo.jpg
$ exiftool -b -ThumbnailImage photo.jpg > thumb.jpg    # превью может содержать флаг
$ strings -n 6 photo.jpg | grep -iE 'flag|base64|comment'
```

Нередко флаг лежит в `COM`-комментарии или во встроенном превью, которого нет в основном изображении.

## Если не сработало

- Не применяй `zsteg`/`steghide` к JPEG вслепую — сначала `stegdetect`.
- Для F5/OutGuess нужен ключ — ищи его в условии, метаданных, имени файла.
- Не пересохраняй JPEG — данные погибнут.
- Данные «случайные» — возможно, поверх шифрование: сними XOR или расшифруй.

## Что мы теперь знаем

1. JPEG сжимает с потерями, поэтому LSB в пикселях не работает.
2. Данные прячут в квантованных DCT-коэффициентах.
3. JSteg, F5, OutGuess — три метода с разной устойчивостью.
4. `stegdetect` определяет метод — это первый шаг.
5. Служебные сегменты (`APP`/`COM`) и превью — тоже каналы.

## Шаг 6: структура JPEG по сегментам

JPEG — последовательность сегментов, каждый начинается с маркера `FF xx`. Данные прячут не только в коэффициентах, но и в служебных сегментах. Разобрать структуру можно скриптом:

```python
raw = open('photo.jpg', 'rb').read()
i = 2
while i < len(raw) - 1:
    if raw[i] != 0xFF:
        break
    marker = raw[i+1]
    if marker in (0xD8, 0xD9):
        print(hex(marker)); i += 2; continue
    ln = (raw[i+2] << 8) | raw[i+3]
    print(hex(marker), 'len', ln)
    i += 2 + ln
```

## Шаг 7: извлечение коэффициентов вручную

Полный ручной разбор JPEG (энтропийное декодирование) трудоёмок — на практике используют готовые инструменты. Но полезно уметь вытащить массив коэффициентов для анализа через `jpegio`:

```python
import jpegio
j = jpegio.read('photo.jpg')
print(j.coef_arrays[0].shape)          # массив DCT-коэффициентов
print('ненулевых:', (j.coef_arrays[0] != 0).sum())   # ~ ёмкость метода
```

Число ненулевых коэффициентов сразу даёт верхнюю границу ёмкости скрытого сообщения.

## Шаг 8: таблица JPEG-методов

| Метод | Изменение | Детект | Ключ | Инструмент |
|---|---|---|---|---|
| JSteg | замена LSB коэффициента | лёгкий | нет | `jsteg` |
| JPHide | с паролем | средний | да | `jphide`/`jpseek` |
| OutGuess 0.2 | замена + восстановление | трудный | да | `outguess` |
| F5 | уменьшение + матрица | трудный | да | `F5.jar` |
| steghide | граф коэффициентов | средний | пароль | `steghide` |

Определение метода через `stegdetect` — первый шаг, дальше выбираешь инструмент из таблицы.

## Шаг 9: практический чек-лист JPEG-задачи

1. `file` + `exiftool -a -u -g1` + `strings` — метаданные и подсказки.
2. Проверь превью (`exiftool -b -ThumbnailImage`) — отдельный канал.
3. `stegdetect` — определи метод.
4. `steghide info` → `extract`/`stegseek`; `outguess -r`; `jsteg reveal`; `F5.jar d`.
5. Проверь `APP`/`COM`-сегменты и таблицы `DQT`/`DHT`.
6. Данные «случайные» — сними шифрование/распакуй.

Не открывай и не пересохраняй JPEG — данные погибнут. Работай с копией.

## Куда дальше

Дальше мы разберём **F5** — самый изящный из JPEG-методов: как уменьшение коэффициентов и матричное кодирование `(n,k)` делают его почти невидимым для стегоанализа. А пока запомни: в JPEG сначала определяй метод через `stegdetect`, потом применяй инструмент.

- **CTF (Stego):** JPEG-задачи, где классические LSB-тулзы не срабатывают.

- **Forensics:** поиск скрытых данных в фотографиях, проверка подлинности.
