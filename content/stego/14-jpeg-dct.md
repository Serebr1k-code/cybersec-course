## Сжатие JPEG и DCT

JPEG сжимает изображение с потерями. Конвейер: перевод в YCbCr → разбиение на блоки 8×8 → **дискретное косинусное преобразование (DCT)** → **квантование** коэффициентов → энтропийное кодирование (Хаффман/арифметика). После DCT каждый блок представлен 64 коэффициентами: один DC (среднее) и 63 AC (частоты). Квантование делит коэффициенты на значения из таблицы и округляет — именно квантованные коэффициенты и есть «место» для стеганографии.

Стеганография в JPEG меняет **квантованные** коэффициенты (JSteg, F5) или использует статистику для маскировки (OutGuess). Это принципиально отличается от LSB в PNG: данные живут в частотной области.

## Квантование и таблицы

Таблицы квантования задаются в сегменте `DQT`. Большие значения = сильнее сжатие и больше нулей среди коэффициентов. Данные прячут в **ненулевых** коэффициентах (обычно AC), потому что изменение нуля заметно и ломает сжатие.

```bash
djpeg -verbose image.jpg > /dev/null     # показывает таблицы
exiftool image.jpg | grep -i quant
```

## JSteg: простейший метод

JSteg заменяет **младший бит** ненулевых квантованных коэффициентов на бит сообщения. Просто, но легко детектируется: хи-квадрат по гистограмме коэффициентов видит выравнивание пар. Обход — последовательный (или по ключу).

```bash
jsteg reveal image.jpg out.txt     # извлечь
stegdetect image.jpg               # покажет jsteg
```

## F5 и OutGuess

**F5** использует уменьшение коэффициентов и матричное кодирование `(n,k)`, что резко снижает число изменений и обманывает хи-квадрат. **OutGuess 0.2** после встраивания корректирует остальные коэффициенты, восстанавливая гистограмму. Оба требуют ключа/пароля. Детали — в отдельных уроках.

## Извлечение: порядок действий

```bash
stegdetect image.jpg                     # определить метод
steghide info image.jpg                  # если steghide
steghide extract -sf image.jpg           # извлечь
outguess -r image.jpg out.txt            # если OutGuess
java -jar F5.jar d -p pass -c image.jpg  # если F5
```

Начинайте с `stegdetect` — он сэкономит время, подсказав метод.

## Инструменты

- **`stegdetect`** — детектор JSteg/JPHide/OutGuess/F5.
- **`jsteg`** — извлечение JSteg.
- **`outguess`** — OutGuess.
- **`F5.jar`** — F5.
- **`steghide`/`stegseek`** — парольная стеганография (тоже DCT).
- **`djpeg`/`jpegtran`** — анализ структуры и таблиц.

## Разобранный пример

```bash
$ stegdetect cover.jpg
cover.jpg: jsteg
$ jsteg reveal cover.jpg out.txt
$ cat out.txt
flag{jsteg_dct}
```

Маршрут: `stegdetect` → метод → соответствующий инструмент. Для F5/OutGuess нужен ключ.

## Частые ошибки и подводные камни

- **Применять LSB/zsteg к JPEG** — не работает.
- **Не определять метод** — тратите время на перебор.
- **Игнорировать ключ** — F5/OutGuess без ключа не извлекаются.
- **Открыть и пересохранить** — данные погибнут.
- **Путать квантованные и неквантованные коэффициенты**.
- **Забыть про метаданные** — пароль может быть в EXIF.

## Итог

JPEG-стеганография работает в частотной области через квантованные DCT-коэффициенты. Методы (JSteg, F5, OutGuess) различаются моделью изменений и устойчивостью к стегоанализу. В CTF ключ к решению — определить метод (`stegdetect`) и применить соответствующий инструмент с ключом.

| Метод | Изменение | Детект | Ключ | Инструмент |

## Таблицы Хаффмана и APP-сегменты

Помимо коэффициентов, в JPEG есть служебные структуры:

- **DHT** — таблицы Хаффмана; неиспользуемые коды можно переопределить.
- **DQT** — таблицы квантования.
- **APP0/APP1/APP2** — метаданные (JFIF, EXIF, ICC); сюда часто прячут данные.
- **COM** — комментарий (произвольный текст).

```bash
djpeg -verbose image.jpg > /dev/null | grep -A2 -i huffman
strings -n 6 image.jpg | grep -iE 'flag|base64|comment'
exiftool -a -u image.jpg
```

`APP`-сегменты и `COM` — частые места для флагов и паролей.

## Структура JPEG по сегментам

JPEG — последовательность сегментов, каждый начинается с маркера `FF xx`:

| Маркер | Сегмент | Содержимое |
|---|---|---|
| FFD8 | SOI | начало изображения |
| FFE0 | APP0 | JFIF (версия, плотность) |
| FFE1 | APP1 | EXIF/XMP (метаданные) |
| FFDB | DQT | таблицы квантования |
| FFC0 | SOF0 | параметры кадра |
| FFC4 | DHT | таблицы Хаффмана |
| FFDA | SOS | начало сжатых данных |
| FFD9 | EOI | конец |

Данные прячут в `APP`/`COM`-сегментах, в таблицах (`DQT`/`DHT`) и в коэффициентах после `SOS`.

```python
raw = open('x.jpg','rb').read()
i = 2
while i < len(raw)-1:
    if raw[i] != 0xFF: break
    marker = raw[i+1]
    if marker in (0xD8,0xD9): print(hex(marker)); i += 2; continue
    ln = (raw[i+2]<<8) | raw[i+3]
    print(hex(marker), 'len', ln)
    i += 2 + ln
```

## Извлечение коэффициентов вручную

Полный ручной разбор JPEG (энтропийное декодирование) трудоёмок; на практике используют готовые инструменты (`jsteg`, `outguess`, `F5.jar`, `steghide`). Но полезно уметь вытащить коэффициенты для анализа: `djpeg -verbose` показывает прогресс, а библиотеки (например, `jpegio`/`libjpeg`) дают доступ к массиву коэффициентов.

```python
import jpegio
j = jpegio.read('x.jpg')
print(j.coef_arrays[0].shape)   # массив DCT-коэффициентов
```

## JPEG: структура и места для закладок

JPEG — поток сегментов с маркерами `FF xx`. Начало — `SOI` (FFD8), конец — `EOI` (FFD9). Между ними: `APP0` (JFIF), `APP1` (EXIF/XMP), `DQT` (таблицы квантования), `SOF` (параметры кадра), `DHT` (таблицы Хаффмана), `SOS` (начало данных) и сжатые данные. Каждое место — потенциальный канал:

- **`APP`/`COM`** — произвольные метаданные, часто с флагом/base64.
- **`DQT`/`DHT`** — таблицы; неиспользуемые коды можно переопределить.
- **Коэффициенты после `SOS`** — основное место DCT-методов.

```python
raw = open('x.jpg','rb').read(); i = 2
while i < len(raw)-1 and raw[i] == 0xFF:
    m = raw[i+1]
    if m in (0xD8,0xD9): print(hex(m)); i += 2; continue
    ln = (raw[i+2]<<8)|raw[i+3]; print(hex(m),'len',ln); i += 2+ln
```

## Быстрый обзор APP-сегментов

Метаданные — дешёвый источник секретов:

```bash
exiftool -a -u -g1 image.jpg
strings -n 6 image.jpg | grep -iE 'flag|http|base64|comment'
exiftool -b -ThumbnailImage image.jpg > thumb.jpg   # превью может содержать флаг
```

Нередко флаг лежит в `COM`-комментарии или в превью (`ThumbnailImage`), которого нет в основном изображении.
