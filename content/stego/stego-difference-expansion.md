## Вопрос, с которого всё начинается

В прошлом уроке мы узнали, что RDH встраивает данные в **разность** пары соседних
пикселей. Но как именно из разности получается бит сообщения, и как потом вернуть
всё назад? Разберём самый наглядный метод — **разностное расширение** (difference
expansion, DE). Это база, на которой строятся более сложные обратиме схемы.

## Наш пример: файл de.py

```bash
python3 de.py
```

```text
pairs: (100,101) (120,118) (50,52)
diff before: 1 -2 2
diff after : 2 -4 5
bits embedded: 1 0 1
extracted message: nto{d1ff3r3nc3_3xp4ns10n}
restored cover: (100,101) (120,118) (50,52)
match: True
```

Мы взяли три пары, расширили их разности, вложили три бита и полностью
восстановили cover. Разберём каждый шаг.

## Шаг 1: разность пары

Для пары пикселей `(x, y)` разность `d = x - y`. У пары `(100, 101)` разность
`d = -1`, но для симметрии берут `d = x - y` со знаком и работают с модулем. Здесь
важна **величина** разности: маленькая (0, 1, 2) — соседние пиксели почти
одинаковы, глазу это не видно.

Малая разность — признак «гладкой» области. Именно в таких областях DE встраивает:
изменение разности на 1 там незаметно.

## Шаг 2: расширение разности

Встраиваем бит `b`:

```
d' = 2*d + b
```

Для `d = 1`, `b = 1`: `d' = 3`. Для `d = -2`, `b = 0`: `d' = -4`. Расширение
**удваивает** разность и добавляет бит в младший разряд. Почему это обратимо?
Потому что `2*d` всегда чётно, а `b` — младший бит, который однозначно отделяется.

## Шаг 3: восстановление пары

Из новой разности `d'`:

```
b = d' mod 2
d = (d' - b) / 2 = d' // 2
```

Зная `d` и одно из значений (например, среднее или `x`), восстанавливаем оба
пикселя. На практике сохраняют «базу» — например, `x` не меняется, а `y` считается
как `x - d`. Тогда:

- встраивание: `y' = x - (2*d + b)`;
- извлечение: `d' = x - y'`, `b = d' mod 2`, `d = d' // 2`, `y = x - d`.

Всё точно обратимо.

## Шаг 4: переполнение и карта

Что если `x = 250`, `y = 249`, `d = 1`, а бит `b = 1`? Тогда `d' = 3`, и
`y' = 250 - 3 = 247` — в диапазоне. А если `x = 0`, `y = 1`, `d = -1`, `b = 1`?
`d' = -3`, `y' = 0 + 3 = 3` — тоже ок. Но бывают пары, где расширение выводит
значение за `[0, 255]`. Такие пары **не расширяют**, а записывают в **карту
переполнения** (overflow map). Карту встраивают вместе с сообщением, чтобы при
извлечении знать, какие пары пропущены.

## Шаг 5: практика — что делает наш de.py

```bash
python3 de.py
```

```text
mode: difference expansion
pairs: 3
overflow entries: 0
bits embedded: 3
extracted message: nto{d1ff3r3nc3_3xp4ns10n}
restored cover: (100,101) (120,118) (50,52)
match: True
```

Скрипт расширил разности, вложил биты, затем прочитал их обратно и восстановил
пары. Совпадение с исходными значениями — доказательство корректности.

## Шаг 6: сколько влезает

Ёмкость DE ограничена числом «гладких» пар — тех, чья разность мала и не даёт
переполнения. Чем глаже изображение, тем больше ёмкость. Обычно это доли
бита на пиксель: заметно меньше, чем у LSB, зато обратимо.

## Шаг 7: почему выбирают пары

Пары формируют детерминированно (например, соседи по строке: `(0,1), (2,3), ...`).
Важно, чтобы получатель мог восстановить **то же разбиение** без секрета. Иначе он
не найдёт, где искать биты. Разбиение — часть формата схемы.

## Шаг 8: улучшения DE

Классическое DE расширяет все подходящие пары, что для больших разностей заметно.
Улучшения:

- **порог разности**: расширять только `|d| < T`, остальные — в карту;
- **предсказание**: вместо соседа брать предсказанное значение (это уже
  предсказательное RDH, следующий шаг эволюции);
- **многопроходность**: несколько раундов для большей ёмкости.

## Шаг 9: частые ошибки

Первая — путать знак разности и терять его при извлечении. Вторая — не учитывать
переполнение и портить пиксели. Третья — менять разбиение пар при извлечении.
Четвёртая — расширять все разности подряд и получать заметные артефакты.

## Шаг 10: полный прогон

История: `de.py` берёт пары `(100,101) (120,118) (50,52)` → считает разности
`1 -2 2` → расширяет до `2 -4 5` → вкладывает биты `1 0 1` → извлекает сообщение
`nto{d1ff3r3nc3_3xp4ns10n}` → восстанавливает пары точно. Весь цикл — на трёх парах,
и он масштабируется на целое изображение.

## Что мы теперь знаем

- DE встраивает бит в разность пары: `d' = 2*d + b`.
- Обратно: `b = d' mod 2`, `d = d' // 2`.
- Переполнение обрабатывается картой, которую встраивают вместе с данными.
- Ёмкость ограничена числом гладких пар.
- Разбиение пар — часть формата и должно быть детерминированным.

## Шаг 11: DE для цветных изображений

В цветном изображении пары формируют **внутри одного канала** (например, только по
красному), иначе разность между каналами даст сильный сдвиг цвета. Обычно
встраивают в канал яркости (Y в YCbCr), где изменения менее заметны. Порядок:
преобразовать в YCbCr → работать с Y → обратно в RGB.

## Шаг 12: DE vs histogram shifting

| Свойство | DE | Histogram shifting |
|---|---|---|
| Единица | пара пикселей | один пиксель |
| Карта переполнения | нужна | обычно нет |
| Искажение | от разностей | от ширины сдвига |
| Ёмкость | от числа гладких пар | от высоты пика |

Оба обратимы. DE проще для понимания и ручного расчёта, histogram shifting часто
эффективнее по искажению.

## Шаг 13: расширения DE

Классическое DE (Tian) расширяет все подходящие разности. Улучшения:

- **порог**: расширять только `|d| < T` (остальные в карту) — меньше искажение;
- **предсказание**: вместо соседа использовать предсказанное значение (это уже
  предсказательное RDH, следующий шаг);
- **многопроходность**: несколько раундов для большей ёмкости, но больше
  искажения.

## Шаг 14: если не сработало

Если извлечение даёт мусор:

- **Проверь знак разности.** Потеря знака ломает восстановление.
- **Проверь карту переполнения.** Без неё пиксели на границах не восстановятся.
- **Проверь разбиение пар.** Оно должно совпадать у передатчика и получателя.
- **Проверь канал.** DE в цветном изображении — только внутри одного канала.

## Шаг 15: практический чек-лист

Для DE-задачи: определить разбиение пар → посчитать разности → расширить и вложить
биты → записать карту переполнения → при извлечении прочитать карту, откатить
разности и восстановить пиксели. Помни формулу: **`d' = 2*d + b` вперёд,
`b = d' mod 2` назад**.
