## Вопрос, с которого всё начинается

В задаче дали `hidden.png` — на вид однотонный серый прямоугольник. `zsteg -a` печатает «nothing found in standard planes», `exiftool` молчит. Но подсказка: «данные спрятаны на виду». Как увидеть то, чего не видит глаз и не находят авто-инструменты?

Ответ — **посмотреть на картинку по-другому**: разложить её на каналы и битовые плоскости. Именно это делают StegSolve, AperiSolve и StegOnline. Разберём методологию на нашем файле.

## Наш пример: hidden.png

Смотрим формат:

```bash
$ file hidden.png
hidden.png: PNG image data, 480 x 120, 8-bit/color RGB
```

Три канала (R, G, B), 480×120. Глазом — ровный серый прямоугольник. Первый шаг любого визуального анализа — разложить изображение на составляющие.

## Шаг 1: что умеет StegSolve

**StegSolve** — Java-приложение (и его веб-аналоги AperiSolve, StegOnline), которое показывает то, что не видно глазом. Ключевые операции:

| Операция | Что делает | Когда смотреть |
|---|---|---|
| Colour/Channel | R/G/B/A по отдельности | данные в одном канале |
| Bit Planes | битовые плоскости 0…7 | LSB/MSB-данные |
| Frame Browser | кадры GIF/анимации | данные в кадре |
| Image Combiner | XOR/ADD/SUB двух изображений | diff двух версий |

**Битовая плоскость** — это изображение, собранное из одного и того же бита всех пикселей. Плоскость 0 — младшие биты (классический LSB), плоскость 7 — старшие. Если в каком-то бите спрятан текст, он «проявится» на соответствующей плоскости.

## Шаг 2: разбираем каналы вручную

StegSolve может не быть под рукой, а те же операции легко воспроизвести на Python. Разложим изображение на битовые плоскости:

```python
from PIL import Image
import numpy as np
im = np.array(Image.open("hidden.png").convert("RGB"))
for b in range(8):
    for ci, name in enumerate("RGB"):
        plane = ((im[:, :, ci] >> b) & 1) * 255
        Image.fromarray(plane.astype("uint8")).save(f"plane_{name}_{b}.png")
print("saved 24 planes")
```

`im[:,:,ci]` берёт один канал, `>> b & 1` — бит номер `b`, `*255` делает из бита чёрно-белый пиксель. Среди 24 картинок одна окажется не шумом, а текстом.

## Шаг 3: находим текст в младшем бите

Проверим младшую плоскость красного канала — сохраним её отдельно:

```python
Image.fromarray(((im[:, :, 0] & 1) * 255).astype("uint8")).save("lsb_r.png")
```

На `lsb_r.png` проявляется читаемый текст: `flag{r_lsb}`. Вот почему `zsteg` не нашёл его: данные лежали **только в красном канале, только в бите 0** — нестандартная комбинация, которую авто-инструмент не перебрал. Ручной просмотр плоскостей это ловит.

Мораль: если авто-инструмент говорит «пусто», это не значит «данных нет» — посмотри плоскости по каналам сам.

## Шаг 4: XOR каналов

Ещё один мощный режим — **XOR** (исключающее ИЛИ) двух каналов или изображений. Он проявляет данные, спрятанные в **разности** каналов. Возьмём `noise.png`, где одиночные каналы выглядят чистым шумом:

```python
im = np.array(Image.open("noise.png").convert("RGB")).astype(int)
xor = (im[:, :, 0] ^ im[:, :, 1]).astype("uint8")
Image.fromarray(xor).save("xor_rg.png")
```

На `xor_rg.png` появляется текст. Идея: в канал R записан шум, а в канал G — тот же шум, покомпонентно сложенный с данными. По отдельности каждый канал — шум, но их XOR убирает общую часть и обнажает сообщение. В StegSolve то же самое делается через Image Combiner.

## Шаг 5: кадры и порядок просмотра

Для GIF/APNG данные часто лежат в одном кадре или в таймингах. StegSolve имеет **Frame Browser**; вручную кадры разбирают так:

```python
from PIL import Image
im = Image.open("animation.gif")
i = 0
try:
    while True:
        im.seek(i); im.convert("RGB").save(f"f{i:03d}.png"); i += 1
except EOFError:
    pass
print("frames", i)
```

Методология просмотра по порядку:

1. **Alpha-канал** — часто пустой, но если есть вариации — смотри первым.
2. **Битовая плоскость 0** по каналам R/G/B — классический LSB.
3. **Остальные плоскости** (1…7) — multibit и нестандартные схемы.
4. **XOR** каналов и изображений — diff-анализ.
5. **Frame browser** — для анимаций.

## Шаг 6: когда визуальный анализ пуст

Если 5 минут просмотра не дали результата — не зацикливайся, переходи к систематике: `zsteg -a` → `binwalk` → `exiftool` → форматный разбор (чанки/теги/боксы) → частотные методы (DCT/DWT) → стегоанализ (хи-квадрат/RS). Визуальный анализ — быстрый первый шаг, а не единственный инструмент.

Важные оговорки:

- **Lossy-форматы (JPEG).** Битовые плоскости почти всегда шумны — не трать время, иди в метаданные/DCT.
- **Порядок каналов.** PIL даёт RGB, OpenCV — BGR; путаница ломает XOR.
- **Масштаб.** StegSolve показывает 1:1; мелкий текст можно не заметить — увеличивай.
- **Онлайн-сервисы = утечка.** AperiSolve/StegOnline загружают файл на чужой сервер; для чувствительных данных — только локальные инструменты.

## Шаг 7: автоматизация перебора плоскостей

Ручной просмотр 24 плоскостей утомителен. Скрипт генерирует их и сразу помечает подозрительные по доле белых пикселей (текстовая плоскость обычно не чисто белая и не чисто чёрная):

```python
from PIL import Image
import numpy as np
im = np.array(Image.open("image.png").convert("RGB"))
for b in range(8):
    for ci, name in enumerate("RGB"):
        plane = ((im[:, :, ci] >> b) & 1) * 255
        Image.fromarray(plane.astype("uint8")).save(f"p_{name}{b}.png")
        frac = plane.mean() / 255
        if 0.1 < frac < 0.6:
            print("suspicious plane", name, b, "white frac", round(frac, 3))
```

Плоскость, где доля белого в «среднем» диапазоне, — кандидат на текст. Дополнительный режим StegSolve — **channel offset**: сдвиг канала на N пикселей, который проявляет данные, встроенные с синхронизацией:

```python
im[:, :, 2] = np.roll(im[:, :, 2], shift=1, axis=1)   # сдвиг синего канала
```

## Шаг 8: сравнение инструментов

| Инструмент | Что делает | Плюсы | Минусы |
|---|---|---|---|
| StegSolve (локальный) | полный набор | приватность, скорость | требует Java |
| AperiSolve (веб) | авто-набор (zsteg, exiftool, binwalk, плоскости) | быстро, всё сразу | утечка файла |
| StegOnline (веб) | StegSolve в браузере | без установки | ограниченный размер |
| `zsteg -a` (CLI) | перебор каналов и комбинаций | скриптуется | не показывает визуально |

Правило: для чувствительных файлов — только локальные инструменты; онлайн-сервисы — для публичных CTF-задач. А `zsteg` и ручные скрипты хорошо дополняют визуальный анализ: они перебирают то, что глазами не обойти.

## Что мы теперь знаем

1. StegSolve/AperiSolve/StegOnline показывают то, что не видно глазом: каналы, битовые плоскости, XOR, кадры.
2. **Битовая плоскость** — изображение из одного бита всех пикселей; плоскость 0 — классический LSB.
3. Данные могут быть **только в одном канале** — тогда авто-инструмент пропускает их.
4. **XOR** каналов проявляет данные, спрятанные в разности (R — шум, G — шум + сообщение).
5. Frame Browser — для GIF/APNG; данные бывают в отдельном кадре.
6. Визуальный анализ — первый шаг; для JPEG он малоэффективен, а онлайн-сервисы небезопасны.

## Куда дальше

Визуальный анализ — это «глаза» стего-анализа. Дальше разберём **водяные знаки** (watermarking) — метки, встроенные так, чтобы переживать сжатие, и потому невидимые для LSB-инструментов. А пока запомни: авто-инструмент сказал «пусто» — разложи картинку на каналы и плоскости сам.

## Где пригодится

- **CTF Stego:** быстрый визуальный анализ изображений.
- **Bug bounty:** проверка изображений на скрытый контент.
- **Форензика:** выявление аномалий в каналах.
- **Работа:** построение пайплайна анализа медиа.
