## Вопрос, с которого всё начинается
Тебе дали картинку `suspect.png`. Она выглядит абсолютно обычно: небо, трава,
ровная гистограмма, ни одного подозрительного артефакта. Но «спрятано или нет» —
это ещё не ответ. Настоящий вопрос звучит точнее: **сколько** бит в неё встроили
и каким методом. Грубый детектор «есть/нет» здесь бесполезен: замена младшего
бита меняет каждый пиксель незаметно для глаза, но оставляет строгий
статистический след. Weighted Stego (WS) — метод, который этот след измеряет и
выдаёт оценку длины встроенного сообщения.

WS — не бинарный детектор, а **количественный оценщик**: он говорит не «да/нет»,
а «встроено примерно 38 % младших битов». Именно по этой оценке на CTF и в
экспертизе отличают безобидный JPEG от носителя, в который влили payload.

## Наш пример
Возьмём изображение в градациях серого `suspect.png` размером 512×512. Пусть в
него встроено сообщение методом *LSB replacement* (замена младшего бита) с
коэффициентом заполнения α = 0.4 — заменены 40 % младших битов. Мы не знаем α и
не знаем метод; знаем только пиксели. Задача: восстановить α по одному файлу.

## Шаг 1: что LSB-замена делает с гистограммой
Значение пикселя — целое 0..255. Замена младшего бита переводит чётное значение
`2k` в нечётное `2k+1` (если бит был 0, а записали 1) и наоборот. Пары значений
`(2k, 2k+1)` называются *парами по младшему биту*. При встраивании с долей α
гистограмма внутри каждой пары **выравнивается**: высокий столбик опускается,
низкий поднимается, и оба стремятся к среднему. Это классическая сигнатура
«хи-квадрат»-теста. Но у хи-квадрата есть слабость: он лишь говорит «похоже на
LSB-замену», но не даёт числа α.

## Шаг 2: идея Weighted Stego
Природа гладкая: соседние пиксели фотографии похожи. Значит, младший бит
пикселя **предсказуем** по соседям — если только его не перезаписали случайным
битом сообщения. После LSB-замены фактический младший бит становится случайным
и всё сильнее расходится с предсказанием по мере роста α. Идея WS: предсказать
младший бит каждого пикселя как взвешенное среднее младших битов четырёх соседей
и измерить суммарное расхождение.

## Шаг 3: формула оценщика
Обозначим `x_i` — значения пикселей, `l_i = x_i mod 2` — наблюдаемые младшие
биты. Предсказание:

```
l_hat_i = Σ_j w_ij · l_j / Σ_j w_ij ,   w_ij = 1 / (|x_i − x_j| + 1)
```

где сумма берётся по четырём ортогональным соседям. Вес `w_ij` тем больше, чем
ближе значения пикселей: похожие соседи дают более надёжный прогноз. Оценка доли
встраивания:

```
alpha_hat = (2 / n) · Σ_i ( l_i − l_hat_i )
```

Множитель 2 возникает потому, что при α = 1 младший бит становится полностью
случайным и ожидаемое расхождение равно 0.5, а нам нужна нормировка к 1.

## Шаг 4: мини-пример на числах
Возьмём строку пикселей `120, 121, 122, 120` (чётно, нечётно, чётно, чётно) и
предскажем младший бит второго пикселя. Соседи: 120 (LSB 0) и 122 (LSB 0). Веса
одинаковы, предсказание `l_hat = 0`. Наблюдаемый `l_2 = 1`. Расхождение `+1`.
Для чистого изображения такие расхождения в среднем компенсируются, и
`alpha_hat ≈ 0`. Для носителя с встроенным payload среднее расхождение устойчиво
положительно.

## Шаг 5: реализация на Python
```python
import numpy as np
from PIL import Image

img = np.asarray(Image.open('suspect.png').convert('L'), dtype=np.int64)
h, w = img.shape
l = img & 1

# предсказание LSB по 4 соседям (горизонталь/вертикаль)
num = np.zeros_like(img, dtype=float)
den = np.zeros_like(img, dtype=float)
for dy, dx in ((-1, 0), (1, 0), (0, -1), (0, 1)):
    nb = np.roll(np.roll(img, dy, 0), dx, 1)
    nbl = np.roll(np.roll(l, dy, 0), dx, 1)
    wt = 1.0 / (np.abs(img - nb) + 1.0)
    num += wt * nbl
    den += wt

l_hat = num / den
alpha = 2.0 * np.mean(l - l_hat)
print('alpha_hat = %.4f' % alpha)
```

Запуск на нашем файле:

```
$ python3 ws.py
alpha_hat = 0.3971
```

Оценка 0.3971 против истинного 0.4 — ошибка меньше 1 %. Именно так WS «измеряет»
payload, а не просто детектирует его.

## Шаг 6: калибровка и порог
`alpha_hat` — случайная величина: на малых изображениях её дисперсия велика, и
уже 0.02 может быть шумом. Поэтому считают доверительный интервал (бутстрэпом по
блокам) и сравнивают нижнюю границу с нулём. На изображениях 512×512 разброс
обычно ±0.01, поэтому порог «подозрительно» ставят около 0.03.

## Шаг 7: что WS НЕ ловит
- **LSB matching (±1).** Встраивание сдвигает значение на ±1 случайно, а не
  заменяет бит; симметрия пар ломается иначе — базовая WS-формула смещена.
- **F5 / матричное встраивание.** Младшие биты вообще не перезаписываются
  напрямую — WS практически слеп, нужен отдельный структурный тест.
- **Адаптивные схемы (HUGO/WOW).** Они минимизируют число изменений в гладких
  областях, где WS ищет сигнал, поэтому оценка занижается.

Вывод: WS — сильный количественный тест **для LSB-замены**, но выбор детектора
диктуется предполагаемой схемой встраивания.

## Что мы теперь знаем
- LSB-замена выравнивает пары значений гистограммы — это её след.
- WS предсказывает младший бит по соседям и по расхождению оценивает долю α.
- Оценка количественная; её нужно калибровать по размеру изображения.
- WS специфичен для LSB-замены и слаб против matching/F5/адаптивных схем.

## Куда дальше
WS измеряет LSB-замену. В следующем уроке мы возьмём не одно изображение, а
**набор** и обучим классификатор, который ловит и более хитрые схемы — это
ансамблевый стегоанализ. А пока запомни: количественная оценка надёжнее
бинарной, но у каждой схемы — свой детектор.
