## Вопрос, с которого всё начинается

У тебя есть `image.png`, и ты подозреваешь, что в него встроено сообщение методом LSB.
Хи-квадрат молчит — значит, встраивание не «последовательное». Как вообще понять,
есть ли там данные и сколько? Ответ даёт **Weighted Stego (WS)** — метод, который
сравнивает каждый пиксель с предсказанием по соседям и по разнице оценивает
вероятность встраивания.

## Наш пример: файл image.png

```bash
file image.png
python3 ws.py
```

```text
image.png: PNG image data, 16 x 16, 8-bit/color RGB, non-interlaced
WS estimate: embedding rate ~0.02 bpp (probably clean)
```

Для маленького изображения оценка неточная, но идея видна: WS выдаёт число «бит на
пиксель» (bpp). Ноль — чисто, больше нуля — есть данные.

## Шаг 1: идея WS

Ключевая мысль: в натуральном изображении пиксель **предсказуем** по соседям. Если
пиксель отличается от предсказания на ±1 в младшем бите — это может быть встраивание.
WS строит предсказание `x̂` по соседям (средневзвешенное) и смотрит на разность
`x - x̂`.

Для LSB-встраивания с вероятностью `p` (доля изменённых пикселей) разность ведёт себя
предсказуемо: если `x` — чётный, а встроенный бит — 1, пиксель стал `x+1`; если `x` —
нечётный и бит 0, стал `x-1`. Усредняя по изображению, можно оценить `p`.

## Шаг 2: формула

WS использует **весовую поправку**: каждый пиксель получает вес, обратный локальной
дисперсии (в гладких областях предсказание надёжнее, в шумных — нет). Оценка:

```
p̂ = (2 / N) * Σ w_i * (x_i - x̂_i) / w̄
```

где `N` — число пикселей, `w_i` — вес пикселя, `x̂_i` — предсказание. На практике
формула реализуется численно, и результат — доля изменённых пикселей.

## Шаг 3: реализация (упрощённая)

```bash
python3 - <<'PY'
import zlib, struct
def read_png(p):
    d = open(p,'rb').read()
    i = 8; w=h=None; idat=b''
    while i < len(d):
        ln = int.from_bytes(d[i:i+4],'big'); t = d[i+4:i+8]
        if t == b'IHDR':
            w,h = struct.unpack('>II', d[i+8:i+16])
        elif t == b'IDAT':
            idat += d[i+8:i+8+ln]
        i += 12 + ln
    raw = zlib.decompress(idat)
    return w, h, raw
w,h,raw = read_png('image.png')
print('size', w, h, 'raw bytes', len(raw))
# WS-подобная статистика: доля пикселей, отличающихся от предсказания на 1
row = raw[1:1+w*3]
diffs = sum(1 for i in range(1,len(row)) if abs(row[i]-row[i-1]) == 1)
print('adjacent +-1 fraction:', diffs/(len(row)-1))
PY
```

Для настоящего WS нужен полный предсказатель и веса; упрощённая статистика показывает
принцип — считать локальные разности.

## Шаг 4: извлечение сообщения

Если WS подтверждает встраивание, дальше — извлечение. Для последовательного LSB это
сбор младших бит каналов:

```bash
python3 - <<'PY'
import zlib, struct
d = open('image.png','rb').read()
i = 8; idat=b''
while i < len(d):
    ln = int.from_bytes(d[i:i+4],'big'); t = d[i+4:i+8]
    if t == b'IDAT': idat += d[i+8:i+8+ln]
    i += 12 + ln
raw = zlib.decompress(idat)
w = int.from_bytes(d[16:20],'big'); h = int.from_bytes(d[20:24],'big')
bits = []
for y in range(h):
    line = raw[y*(1+w*3)+1:(y+1)*(1+w*3)]
    for b in line:
        bits.append(b & 1)
out = bytearray()
for k in range(0, len(bits)//8*8, 8):
    byte = 0
    for x in bits[k:k+8]:
        byte = (byte << 1) | x
    out.append(byte)
print(out[:40])
PY
```

## Шаг 5: где применяется WS

- **Детект LSB/LSB-matching** — основной сценарий.
- **Оценка длины сообщения** — количественная мера.
- **Сравнение изображений** — «оригинал vs подозрительный».
- **Пре-фильтр** — перед более тяжёлым ML-детектором.

## Шаг 6: ограничения

WS работает, когда встраивание меняет пиксели на ±1 и предсказание по соседям
адекватно. На **адаптивных** схемах (HUGO, WOW) он слабеет: они меняют пиксели там,
где это менее заметно, и предсказание «проваливается». Для таких нужны rich models
(следующий урок). Также WS чувствителен к шуму и малому размеру изображения.

## Шаг 7: частые ошибки

Первая — путать bpp и «да/нет»: WS даёт оценку, а не вердикт. Вторая — не учитывать
размер: на 16×16 оценка шумная. Третья — забыть про фильтр PNG (первый байт строки).
Четвёртая — применять WS к JPEG: там другой домен, нужен DCTR/JRM.

## Практика: WS на реальном изображении

Разберём полный цикл на `image.png`. Сначала читаем пиксели, строим предсказание,
считаем веса.

```bash
python3 - <<'PY'
import zlib
def load(p):
    d = open(p,'rb').read(); i = 8; idat = b''
    while i < len(d):
        ln = int.from_bytes(d[i:i+4],'big'); t = d[i+4:i+8]
        if t == b'IHDR':
            w = int.from_bytes(d[i+8:i+12],'big'); h = int.from_bytes(d[i+12:i+16],'big')
        if t == b'IDAT': idat += d[i+8:i+8+ln]
        i += 12 + ln
    return w, h, zlib.decompress(idat)

w, h, raw = load('image.png')
# построчная развёртка в массив пикселей
rows = []
for y in range(h):
    line = raw[y*(1+w*3)+1:(y+1)*(1+w*3)]
    rows.append(line)
# предсказание: среднее левого и верхнего (упрощённо)
err = 0; cnt = 0
for y in range(1, h):
    for x in range(1, w*3):
        pred = (rows[y][x-1] + rows[y-1][x]) // 2
        err += abs(rows[y][x] - pred); cnt += 1
print('mean prediction error:', err/cnt)
PY
```

Чем меньше средняя ошибка, тем «предсказуемее» изображение. Встраивание эту ошибку
слегка увеличивает — и по приросту оценивается embedding rate.

## WS против RS и SPA

Базовые методы (хи-квадрат, RS, SPA) ищут **пары значений** (2k, 2k+1), которые при
LSB-встраивании «выравниваются». Они хороши для последовательного LSB, но ломаются на
**LSB matching** (когда пиксель меняется на ±1 случайно). WS отличается тем, что
работает не с гистограммой значений, а с **остатком от предсказания** — и потому
устойчивее к matching. Именно поэтому WS — «следующий шаг» после RS/SPA.

Для сравнения: RS даёт оценку длины сообщения для классического LSB; WS даёт оценку для
более широкого класса схем. Если RS молчит, а WS «шумит» — вероятно, встраивание
matching-типа.

## Чек-лист по WS

1. Декодируй PNG в пиксели (учти фильтр строки!).
2. Построй предсказание по соседям и веса (обратные дисперсии).
3. Посчитай взвешенную оценку embedding rate.
4. Если rate > 0 — извлеки LSB-биты и декодируй.
5. Если WS молчит, а данные есть — переходи к ансамблям (следующий урок).

Такой порядок покрывает большинство задач на LSB-стеганографию в изображениях.

## Почему WS работает: интуиция

Представь гладкую область: пиксели почти равны. Если в один из них встроить бит, он
отличается на ±1 — это «выброс» на фоне гладкой области. WS именно такие выбросы и
ищет: он взвешивает пиксели так, чтобы гладкие области вносили больший вклад. В шумной
текстуре ±1 незаметен, поэтому такие пиксели получают меньший вес.

Формально WS опирается на то, что при LSB-встраивании распределение разности
`x - x̂` приобретает характерную асимметрию. Из этой асимметрии и оценивается доля
изменённых пикселей. Чем больше сообщение, тем сильнее асимметрия.

## Ограничения и обходы

WS предполагает, что предсказание по соседям адекватно. На реальных фотографиях с
текстурами и краями это не всегда так. Обходы:

- **Локальная калибровка** — предсказание подстраивают под локальную статистику.
- **Мультимасштабность** — считают WS на нескольких масштабах.
- **Комбинация с RS/SPA** — если один метод молчит, другой может сработать.

Практический вывод: WS — не «серебряная пуля», а один из инструментов. В CTF его
часто достаточно, потому что задачи на LSB простые. В реальной форензике WS
комбинируют с ансамблями и rich models.

## Итоговая стратегия для количественного стегоанализа

1. Определи формат и домен (PNG/BMP — пиксели, JPEG — DCT).
2. Для пиксельного домена запусти WS и/или RS/SPA.
3. Если оценка > 0 — извлеки LSB-биты.
4. Если оценка ~0, но данные есть — переходи к ансамблям.
5. Для JPEG — сразу к DCTR/JRM.

Такой маршрут экономит время: ты не применяешь тяжёлые методы там, где хватает
простого WS.

## Итог

WS — это количественный метод: он не просто говорит «есть/нет», а оценивает долю
изменённых пикселей. Для CTF этого достаточно, чтобы понять, стоит ли вообще
извлекать данные. Для реальной форензики WS — быстрый пре-фильтр перед тяжёлыми
моделями.

## Заключение

WS показывает, что стегоанализ — это не только «есть или нет», но и «сколько». Оценка длины сообщения помогает выбрать дальнейшие шаги: маленький payload требует более тонких методов, большой — легко ловится даже простыми метриками.

## Что мы теперь знаем

- WS сравнивает пиксель с предсказанием по соседям и оценивает долю изменённых.
- Результат — «бит на пиксель» (bpp).
- Веса обратны локальной дисперсии (гладкие области важнее).
- WS хорош для LSB/LSB-matching, слабее на адаптивных схемах.
- После детекта — извлечение младших бит.
