## Что такое дописанные данные

Самая частая и самая «дешёвая» техника файловой стеганографии — **дописать данные после конца корректного файла**. Почти все форматы читаются по внутренним структурам (размерам, маркерам, таблицам), поэтому «хвост» после конца образа парсеры игнорируют. Вы открываете картинку — она показывается; но за последним байтом изображения лежит ZIP, PDF или ещё одна картинка. В CTF это, пожалуй, самая распространённая закладка после LSB.

Ключевая идея: сравнивайте **фактический размер файла** с ожидаемым по структуре. Для PNG ожидаемый конец — после чанка `IEND`; для JPEG — после маркера `FFD9`; для GIF — после `0x3B`; для PDF — после последнего `%%EOF`; для ZIP — после End of Central Directory. Всё, что лежит дальше, — дописанное.

## Сигнатуры и поиск встроенного

Встроенные файлы легко найти по **магическим байтам**: `PK\x03\x04` (ZIP), `\x89PNG` (PNG), `%PDF` (PDF), `\xff\xd8\xff` (JPEG), `GIF8` (GIF), `Rar!` (RAR), `7z\xbc\xaf` (7z), `\x1f\x8b` (gzip), `BZh` (bzip2), `\x7fELF` (ELF), `MZ` (PE).

```bash
grep -abo $'PK\x03\x04' file.png        # смещения ZIP
grep -abo $'\x89PNG' file.png           # вложенные PNG
xxd file.png | tail -20                 # посмотреть хвост
binwalk file.png                        # автоматический поиск
```

`binwalk` делает это автоматически и показывает смещения и типы.

## binwalk, foremost и carving

- **`binwalk`** — сканирует по сигнатурам, `-e` извлекает.
- **`foremost`** — carving по типам файлов (свой конфиг).
- **`scalpel`** — быстрый carving с настраиваемыми сигнатурами.
- **`dd`** — ручное извлечение по смещению.

```bash
binwalk -e file.png                     # извлечь в _file.png.extracted/
foremost -t zip,png,jpg -i file.png -o out/
dd if=file.png of=hidden.zip bs=1 skip=123456   # извлечь по смещению
```

Ручное `dd` по смещению из `binwalk`/`grep -abo` — самый надёжный способ, когда автоматика путается.

## Slack space и данные между структурами

Помимо «после конца», данные прячут **внутри** файла, в неиспользуемых областях:

- **Slack space** файловой системы — остаток последнего кластера файла (актуально для образов дисков).
- **Padding** между чанками/боксами.
- **«Мёртвые» области** форматов (неиспользуемые поля, зарезервированные байты).

Для образов дисков slack space извлекают `dls`/`blkls` (Sleuth Kit); для отдельных файлов — ручной разбор структуры.

## ZIP-специфика: склеенные архивы

ZIP читается с конца (End of Central Directory), поэтому к ZIP можно дописать второй ZIP или данные. Более того, **склеенные ZIP** (`cat a.zip b.zip > c.zip`) открываются как один архив со всеми файлами. Это удобный канал.

```bash
cat part1.zip part2.zip > combined.zip
unzip -l combined.zip
python3 -c "d=open('c.zip','rb').read(); print([hex(i) for i in [m for m in range(len(d)) if d[m:m+4]==b'PK\x03\x04'][:10]])"
```

## PDF, JPEG и другие концы

- **PDF**: после последнего `%%EOF`; также инкрементальные обновления.
- **JPEG**: после `FFD9`; часто там ZIP.
- **PNG**: после `IEND`.
- **GIF**: после `3B`.
- **MP4**: после `mdat`/в `free`-боксах.

```bash
grep -abo '%%EOF' doc.pdf
grep -abo $'\xff\xd9' img.jpg | tail -1
```

## Инструменты

- **`binwalk`/`foremost`/`scalpel`** — поиск и carving.
- **`dd`/`xxd`/`grep -abo`** — ручное извлечение.
- **`pngcheck`/`file`** — определение концов форматов.
- **Sleuth Kit** (`blkls`, `dls`) — slack space на дисках.

## Разобранный пример

```bash
$ binwalk suspicious.png
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             PNG image, 512 x 512
262144        0x40000         Zip archive data, at offset 0x40000
$ dd if=suspicious.png of=hidden.zip bs=1 skip=262144
$ unzip -o hidden.zip
 extracting: flag.txt
$ cat flag.txt
flag{appended_zip}
```

Маршрут: `binwalk` → смещение → `dd` → распаковка.

## Частые ошибки и подводные камни

- **Открыть и пересохранить** — хвост уничтожится.
- **Доверять только расширению** — `file` покажет реальный тип.
- **Не смотреть размер** — «лишние» байты выдают закладку.
- **Игнорировать склеенные архивы** — их несколько, а не один.
- **Пропускать slack space** в образах дисков.
- **Путать конец формата** — у каждого свой маркер.

## Итог

Дописанные данные — базовый, но очень частый канал. Навык «сравнить размер с ожидаемым и посмотреть хвост» решает огромное число задач. Комбинация `binwalk` + `dd` + распаковка — рабочий инструмент, а понимание концов форматов позволяет находить закладки вручную.

## Практика carving по смещениям

Самый надёжный способ извлечь встроенное — найти смещение и «вырезать» по нему. `binwalk` даёт смещение в десятичном и hex-виде; `dd` вырезает:

```bash
binwalk file.png                       # найти смещение, напр. 262144
dd if=file.png of=part.bin bs=1 skip=262144
file part.bin
```

Если встроенный файл имеет свой «конец» (например, ZIP), лучше вырезать до конца файла — распаковщик разберётся. Для нескольких вложенных файлов повторяйте по каждому смещению. `grep -abo` даёт смещения сигнатур:

```bash
grep -abo $'PK\x03\x04' file.png
grep -abo $'\x89PNG' file.png
```

## Сравнение с другими контейнерными каналами

| Канал | Где данные | Заметность | Инструмент |
|---|---|---|---|
| Дописанное после конца | после маркера формата | высокая (виден размер) | `binwalk`, `dd` |
| Склеенные архивы | несколько ZIP подряд | средняя | `unzip`, ручной разбор |
| Slack space | остаток кластера | очень высокая | Sleuth Kit |
| Внутренние «мёртвые» области | padding между структурами | высокая | ручной разбор |

Все они опираются на одно: парсер читает по структуре и игнорирует «лишнее». Поэтому навык «найти и вырезать лишнее» универсален.

## Ёмкость и сценарии применения

Дописанные данные дают **неограниченную ёмкость** — можно дописать файл любого размера. Поэтому этот канал используют, когда нужно спрятать большой payload (архив, второе изображение, PE). Признак: файл-носитель «слишком большой» для своего содержимого. В реальных атаках так прячут полезные нагрузки; в CTF — целые архивы с флагами.

## Практический чек-лист дописанных данных

1. `file` — реальный тип и размеры.
2. `binwalk` — список встроенных сигнатур.
3. `xxd | tail` — визуальный осмотр хвоста.
4. `grep -abo` — смещения сигнатур.
5. `dd`/`binwalk -e` — извлечь.
6. `file`/`unzip`/`zcat` — разобрать извлечённое.
7. Образ диска — slack space (`blkls`/`dls`).

## Дописанные данные в реальных форматах: детали

Каждый формат имеет свой «конец», и знание этих маркеров ускоряет поиск. В **PNG** последний чанк — `IEND`, после него допустимо ничего (кроме, возможно, `tEXt`-после-конца — уже аномалия). В **JPEG** маркер `FFD9` (EOI) завершает изображение; всё после — дописано. В **GIF** конец — байт `0x3B` (trailer). В **PDF** файл может содержать несколько `%%EOF` из-за инкрементальных обновлений, поэтому «конец» — последний из них. В **ZIP** структура читается с конца, и после End of Central Directory можно дописать что угодно. В **MP4** «пустые» боксы `free`/`skip` — легальное место для данных.

Практический приём: сравните размер файла с тем, что должно быть. Для PNG можно прикинуть: `8 + сумма(12 + длина чанка)`. Если фактический размер больше — есть хвост. Для JPEG — размер примерно равен сумме сегментов; «лишнее» в конце — закладка.

```bash
python3 -c "
import struct
raw=open('x.png','rb').read(); i=8
while i<len(raw):
    ln=struct.unpack('>I',raw[i:i+4])[0]; t=raw[i+4:i+8]
    i+=12+ln
print('expected end', i, 'actual', len(raw), 'extra', len(raw)-i)
"
```

Такая проверка мгновенно показывает наличие дописанного.

## Slack space и неразмеченные области

На образах дисков помимо «дописанного после файла» есть **slack space** — пространство между концом данных файла и концом занимаемого им кластера. Оно может содержать старые данные или намеренно спрятанное сообщение. Извлекается через Sleuth Kit:

```bash
blkls -s image.dd > slack.bin      # только slack-пространство
dls image.dd > deleted.bin         # удалённые файлы
strings -n 8 slack.bin | grep -i flag
```

Неразмеченные области (после последнего раздела, между разделами) тоже могут содержать данные — их ищут `binwalk` по всему образу.

## Сравнение инструментов carving

| Инструмент | Сильная сторона | Слабость |
|---|---|---|
| `binwalk` | много сигнатур, `-e` | иногда переусердствует |
| `foremost` | надёжный carving | нужен конфиг типов |
| `scalpel` | быстрый, настраиваемый | ручной конфиг |
| `dd` | точный, предсказуемый | нужен точный offset |
| Sleuth Kit | диски/slack | для образов ФС |

Комбинируйте: `binwalk` для обзора, `dd` для точного извлечения, Sleuth Kit для дисков.

## Почему это важно

Дописанные данные — самый «невидимый» канал с точки зрения инструментов перебора каналов: `zsteg` их не видит, `exiftool` — тоже. Только структурный анализ (размер, маркеры, сигнатуры) их выявляет. Поэтому в любом пайплайне разбора файла шаг «сравнить размер с ожидаемым и посмотреть хвост» обязателен — он стоит секунды, а решает часто.

## Что делать дальше / решение

- `file`, `binwalk`, `xxd | tail` — найти «лишнее».
- `binwalk -e` / `dd` по смещению — извлечь.
- Распаковать/разобрать извлечённое (`file`, `unzip`).
- Образы дисков — slack space (`blkls`).
- Ничего — вернуться к LSB/метаданным.

## Где пригодится

- Техника «дописанные данные» встречается в Stego и Forensics постоянно.
- Carving нужен, когда файл — дамп, образ или «сломанный» контейнер.
- Навык определения магических байтов универсален: пригодится в malware-анализе, PCAP, любом разборе бинарей.
- Дальше — урок про полиглоты и QR/баркоды: там данные прячут на стыке двух форматов.
