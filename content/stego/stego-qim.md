## Вопрос, с которого всё начинается

В задаче картинку с закладкой несколько раз пересохранили в JPEG — и данные всё равно читаются. С обычным LSB это невозможно: одно сжатие стирает младшие биты начисто. Значит, использована схема, которая **выживает** после сжатия. Как она устроена?

Ответ — **QIM** (Quantization Index Modulation, модуляция индекса квантования). Она кодирует данные не «в младшем бите», а **выбором решётки**, к которой притянуто значение. Разберём на нашем примере.

## Наш пример: cover_qim.png

Возьмём `cover_qim.png` — сглаженный шум 256×256 в оттенках серого (у него плавная гистограмма, как у фото). Спрячем в него строку `flag{qim_ok}` и посмотрим, как меняется поведение схемы при разном шаге квантования.

**Квантование** — это округление значения к ближайшей точке из заранее заданного набора. Если набор — это числа, кратные `Δ` (шаг), то квантование по шагу `Δ` записывается так:

```
Q(x) = Δ · round(x / Δ)
```

Например, при `Δ = 16` значение 130 округлится к 128, а 138 — к 144. Все значения «прилипают» к решётке с шагом 16.

## Шаг 1: две решётки вместо одного бита

QIM берёт не одну решётку, а **две**, сдвинутые друг относительно друга на полшага `Δ/2`. Каждая решётка — это «слот» для одного из значений бита:

```
Q_0(x) = Δ · round(x / Δ)                       # решётка для бита 0
Q_1(x) = Δ · round((x − Δ/2) / Δ) + Δ/2         # решётка для бита 1
```

Чтобы записать бит `b`, значение `x` **заменяется** на ближайшую точку решётки `Q_b(x)`. Никакого младшего бита: кодируется, в какой из двух «половин» интервала квантования сидит значение.

## Шаг 2: встраиваем и извлекаем

Встраивание — пройти по значениям и притянуть каждое к нужной решётке:

```python
delta = 16
q0 = lambda x: delta * np.round(x / delta)
q1 = lambda x: delta * np.round((x - delta/2) / delta) + delta/2

a = np.array(img).astype(np.float64).reshape(-1)
bits = np.unpackbits(np.frombuffer(b"flag{qim_ok}", dtype=np.uint8))
for i, b in enumerate(bits):
    a[i] = q1(a[i]) if b else q0(a[i])
Image.fromarray(np.clip(a, 0, 255).astype(np.uint8).reshape(256, 256)).save("stego_qim16.png")
```

Извлечение — обратная логика: смотрим, к какой решётке значение **ближе**:

```python
a = np.array(Image.open("stego_qim16.png").convert("L")).astype(np.float64).reshape(-1)[:96]
bits = (np.abs(a - q1(a)) < np.abs(a - q0(a))).astype(np.uint8)
print(np.packbits(bits).tobytes())
```

```
b'flag{qim_ok}'
```

Флаг читается. Обрати внимание: `zsteg` тут бесполезен — данные лежат не в младших битах, которые он проверяет.

## Шаг 3: почему QIM переживает шум

После встраивания значение лежит **ровно на решётке**. Если добавить шум (или применить сжатие), значение сместится на небольшую величину `ε`. Декодер ищет ближайшую точку решётки, и пока `|ε| < Δ/4`, решение **не меняется**.

То есть у QIM есть «запас прочности» порядка `Δ/4`. Это и есть ручка управления: **чем больше `Δ`, тем устойчивее схема, но тем сильнее искажение носителя.** Классический размен «робастность ↔ незаметность».

## Шаг 4: проверяем на JPEG

Теперь честный эксперимент. Пересохраним стего в JPEG с качеством 90 и попробуем извлечь при разных `Δ`:

```
delta=  8 clean=b'flag{qim_ok}'  jpeg90=b"\x00\x142'\x183\x01mD\x07qQ"
delta= 16 clean=b'flag{qim_ok}'  jpeg90=b'~lacyUfiHokr'
delta= 24 clean=b'flag{qim_ok}'  jpeg90=b'fdag{qio__k}'
delta= 32 clean=b'flag{qim_ok}'  jpeg90=b'flag{qio\x1fok\x7f'
delta= 48 clean=b'flag{qim_ok}'  jpeg90=b'flag{qim_ok}'
```

Вывод важный и честный: при `Δ = 8` и `16` JPEG-q90 ломает данные, при `24–32` — частично, и только при `Δ = 48` флаг выживает целиком. То есть устойчивость к сжатию **требует большого шага** — и тогда на изображении уже видны «ступеньки» квантования. Если в задаче данные пережили JPEG, `Δ` почти наверняка большой.

## Шаг 5: оцениваем Δ по гистограмме

QIM оставляет след: значения «прилипают» к решётке, и на гистограмме появляются периодические пики на расстоянии `Δ`. Особенно хорошо это видно, если данных встроено много. Возьмём плоский носитель и встроим половину ёмкости:

```python
ac = np.correlate(h - h.mean(), h - h.mean(), mode="full")[len(h)-1:]
peaks = [i for i in range(2, 80) if ac[i] > ac[i-1] and ac[i] >= ac[i+1]]
print(peaks[:10])
```

```
[2, 4, 8, 10, 12, 16, 18, 20, 24, 26]
```

Среди кандидатов есть **16** — наш шаг. Автокорреляция гистограммы выдаёт период квантования. Зная `Δ` и порядок обхода, можно декодировать QIM-данные даже без знания схемы.

## Шаг 6: dither и ключ

Если решётки сдвинуты детерминированно, атакующий может угадать их по гистограмме. Поэтому в реальных схемах добавляют **dither** — псевдослучайный сдвиг решётки, зависящий от ключа:

```
Q_b(x) = Δ · round((x − d_b) / Δ) + d_b
```

Без ключа `d_b` извлечение невозможно. В CTF ключ (или `Δ`) обычно лежит в условии задачи. DM-QIM (Dither Modulation QIM) — стандартная форма такой схемы, база многих watermarking-стандартов.

## Шаг 7: QIM в частотной области

В пространственной области (по пикселям) QIM даёт умеренную незаметность. Гораздо чаще её применяют к **коэффициентам частотного преобразования** — DCT (как в JPEG) или DWT (вейвлеты). Тогда робастность частотного встраивания складывается с точностью квантования, и метка переживает перекодирование лучше.

Схема та же, но над коэффициентами: применить преобразование, выбрать группу коэффициентов, квантовать их решёткой, применить обратное преобразование.

```python
import pywt, numpy as np
from PIL import Image
DELTA = 8.0
def q_b(x, b):
    return DELTA*np.round((x - b*DELTA/2)/DELTA) + b*DELTA/2
img = np.array(Image.open("cover_qim.png").convert("L")).astype(float)
LL, (LH, HL, HH) = pywt.dwt2(img, "haar")
bits = np.unpackbits(np.frombuffer(b"flag{qim_dwt}", dtype=np.uint8))
flat = LL.reshape(-1)
for i, b in enumerate(bits):
    flat[i] = q_b(flat[i], b)
out = pywt.idwt2((flat.reshape(LL.shape), (LH, HL, HH)), "haar")
Image.fromarray(np.clip(out, 0, 255).astype(np.uint8)).save("stego_dwt.png")
```

Извлечение — снова сравнение расстояний до двух решёток. Вариант с DCT проще всего проверить через ту же схему над коэффициентами `cv2.dct` блока 8×8.

## Если не сработало

- **Данные не читаются при известном `Δ`** — скорее всего, сдвинут порядок обхода или область (пространство vs DCT/DWT). Пробуй обе.
- **Гистограмма не показывает период** — `Δ` мал или данных встроено мало; попробуй оценить `Δ` по «лестнице» значений.
- **Есть подозрение на dither** — без ключа решётки не восстановить; ищи ключ в условии задачи.
- **Значения у границ 0/255** — клиппинг ломает декодирование; проверь, не «уплыли» ли крайние пиксели.
- **Двойное квантование** — если изображение уже проходило JPEG, решётки накладываются и данные портятся; в таком случае `Δ` должен быть заметно больше шага JPEG.

## Что мы теперь знаем

1. QIM кодирует данные **индексом решётки** квантования, а не младшим битом.
2. Две решётки сдвинуты на `Δ/2` — какая ближе, тот и бит.
3. Запас прочности к шуму ≈ `Δ/4`; больше `Δ` — устойчивее, но заметнее.
4. Наш эксперимент: JPEG-q90 переживает только `Δ = 48`, при малых `Δ` данные гибнут.
5. Периодические пики гистограммы выдают `Δ`; автокорреляция их находит.
6. Dither по ключу защищает решётки от угадывания.

## QIM и LSB: что устойчивее и почему

LSB-стеганография меняет младший бит пикселя. Она незаметна глазу, но гибнет от
любой перекодировки: JPEG-сжатие, изменение размера или даже лёгкая фильтрация
затирают младшие биты первыми. QIM (quantization index modulation) устойчивее,
потому что прячет данные не в «шумовой» бит, а в **расстояние до узла решётки**.

Проще говоря, LSB-сообщение живёт в младшем разряде, который при сжатии округляют
первым. QIM-сообщение живёт в выборе «на какую из двух соседних точек шкалы
округлили значение» — и пока искажение меньше половины шага решётки Δ, выбор
читается верно. Отсюда правило: **чем больше Δ, тем устойчивее, но заметнее**.

## Извлекаем QIM-сообщение без ключа

Если Δ и шаг решётки известны (часто их берут круглыми — 16, 32, 64), сообщение
читается без ключа. Гистограмма — лучший помощник: QIM-пиксели сбиваются в группы
вокруг узлов решётки, и на гистограмме появляются характерные «зубцы» с шагом Δ.

```python
from PIL import Image
im = Image.open('cover_qim.png').convert('L')
px = list(im.getdata())
delta = 32
bits = ''
for v in px[:512]:
    bits += '1' if (v % delta) > delta // 2 else '0'
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits), 8))
print(data[:32])
```

Этот скрипт — грубая, но рабочая проверка гипотезы: если в первых байтах видна
осмысленная строка, значит Δ угадан. Ключ (перестановка порядка пикселей или
псевдослучайная маска) добавляет второй слой, но саму модуляцию он не меняет,
поэтому детект QIM почти всегда сводится к подбору Δ.

## Куда дальше

QIM даёт робастность, но привязана к позиции пикселя: сдвинь изображение на пару точек — и соответствие «пиксель ↔ бит» рассыплется. В следующем уроке разберём **spread-spectrum (SSIS)**: приём, который размазывает один бит по многим пикселям и потому переживает даже обрезку. А пока запомни: данные выжили после JPEG — подозревай квантование и оценивай `Δ` по гистограмме.

## Где пригодится

- **CTF:** Stego — изображения, где данные переживают пересохранение в JPEG.
- **Watermarking:** защита прав и отслеживание копий, робастные метки.
- **Работа:** проектирование схем встраивания с заданной устойчивостью к сжатию.
