## Вопрос, с которого всё начинается
На CTF дают файл. Времени мало, инструментов много: zsteg, steghide, binwalk,
exiftool, спектрограмма… С чего начать? Бессистемный перебор сжигает время.
Правильный ответ — **decision tree**: фиксированный порядок проверок от самого
дешёвого и вероятного к сложному. Этот урок — про такой порядок.

## Наш пример
Возьмём `mystery.dat` — файл без расширения. Пройдём по дереву решений и
«размотаем» его до метки.

## Шаг 1: уровень 0 — идентификация
```
$ file mystery.dat
mystery.dat: ASCII text, with very long lines
$ head -c 64 mystery.dat
SGVsbG8sIHRoaXMgaXMg...
```

`file` говорит «ASCII text» — значит, это текстовое кодирование (base64?).
Первый шаг всегда — `file`, `head`, `xxd -l 64`.

## Шаг 2: уровень 1 — кодирования
Пробуем стандартные: base64, base32, hex, ROT13, URL-encode. Онлайн-декодеры или
CyberChef Magic. Если после декодирования видна магия файла (`\x1f\x8b`, `PK`,
`\x89PNG`) — переходим к распаковке.

## Шаг 3: уровень 2 — распаковка/вложенность
```
$ base64 -d mystery.dat > step1
$ file step1
step1: gzip compressed data
$ gunzip -c step1 > step2
$ file step2
step2: ASCII text
```

«Матрёшка»: base64 → gzip → текст. Здесь помогает binwalk и ручной `file` после
каждого шага.

## Шаг 4: уровень 3 — инструменты по типу
- **Изображение:** `zsteg`, `steghide`, `stegsolve`, `exiftool`, `pngcheck`.
- **Аудио:** спектрограмма (`sox`/Audacity), `steghide`, LSB.
- **Архив:** `unzip -l`, `7z l`, пароль-брутфорс (`zip2john`+`john`).
- **Документ:** распаковать как ZIP, посмотреть XML.
- **Бинарник:** `strings`, `readelf`, overlay.

## Шаг 5: уровень 4 — продвинутое
Если ничего не сработало: адаптивные методы, стего в коэффициентах, кастомные
схемы, крипто поверх стего. Здесь нужен анализ кода/структуры, а не перебор.

## Шаг 6: наш файл целиком
```python
import base64, gzip
d = open('mystery.dat','rb').read()
raw = gzip.decompress(base64.b64decode(d))
print(raw.decode())
```

Вывод:

```
nto{decision_tree_chain}
```

## Шаг 7: типичные ошибки
- Пропустить `file` и сразу запускать `steghide` — трата времени.
- Не проверять метаданные (`exiftool`) — там часто флаг.
- Игнорировать хвост файла (overlay) и лишние записи архива.
- Не сохранять промежуточные шаги — теряется цепочка.

## Полный разбор файла по дереву решений

Пройдём дерево на конкретном файле `challenge.png`. Уровень 0 — идентификация: `file challenge.png` показывает «PNG image data, 800x600». `exiftool` не даёт ничего подозрительного, но `pngcheck -v challenge.png` сообщает о лишних байтах после `IEND` — это уже сигнал overlay.

Уровень 1 — кодирования: `strings challenge.png | tail` показывает base64-подобную строку. Пробуем декодировать: `strings challenge.png | tail -1 | base64 -d`. Если это текст — возможно, флаг; если бинарь — идём дальше.

```bash
file challenge.png
pngcheck -v challenge.png      # лишние байты после IEND
strings -n 8 challenge.png | tail
```

Уровень 2 — вложенность: если base64 декодировался в архив, `binwalk -e` или `7z x` распакуют его. Уровень 3 — инструменты по типу: для изображений `zsteg`/`stegsolve`, для аудио `sox`/спектрограмма, для текста — невидимые символы. Уровень 4 — продвинутое: LSB с нестандартной битовой глубиной, кастомное шифрование, каналы в метаданных.

Смысл дерева — не пропускать уровни и фиксировать, что именно сработало. В отчёте ты пишешь: overlay после IEND → base64 → gzip → флаг. Это воспроизводимый путь, а не «повезло».

## Расширение дерева для упрямых файлов

Когда базовые уровни не дали результата, расширяй проверки системно. Первое — сравни размеры: заявленный в заголовке (`pngcheck`, `identify`) против фактического размера файла. Расхождение — это спрятанные байты. Второе — энтропия: `binwalk -E` покажет аномально высокую энтропию в области, где её быть не должно (признак шифрования или сжатия).

Третье — побитовые каналы: LSB в разных каналах (R/G/B/A), в разных битовых плоскостях (bit 0, bit 1), с разным порядком (MSB/LSB first). `zsteg -a image.png` перебирает большинство комбинаций автоматически. Четвёртое — сравнение с оригиналом: если у тебя есть «чистая» версия картинки, `compare`/`ImageMagick` покажет разницу, и именно там будет сообщение.

```bash
zsteg -a image.png            # перебор LSB-каналов
binwalk -E image.png          # карта энтропии
compare clean.png suspect.png diff.png
```

Пятое — форматы-контейнеры: проверь все чанки (`pngcheck`, `exiftool -v3`), все сегменты (JPEG), все атомы (MP4). Скрытое часто лежит в необязательном чанке с нестандартным именем.

## Частые ошибки в CTF-стего

Первая ошибка — прыгать через уровни: сразу запускать `zsteg`, не проверив overlay и `strings`. Вторая — не проверять, что слой снят корректно: если после распаковки получился мусор, возможно, ты вырезал не тот диапазон или не тот формат. Третья — игнорировать метаданные: EXIF, комментарии, имена чанков часто содержат подсказку или сам флаг. Четвёртая — забывать про регистр и кодировки: флаг может быть в UTF-16, ROT13, base32.

Пятая ошибка — не фиксировать путь: без записи шагов ты не сможешь воспроизвести решение и объяснить его. Шестая — использовать инструмент, который «угадывает» (Magic в CyberChef), и принимать его вывод за истину без проверки. Седьмая — не проверять длину/энтропию после каждого шага: это ловит ошибку сразу, а не через десять шагов. Дерево решений работает, только если ты его соблюдаешь дисциплинированно.

## Расширенный разбор: инструменты каждого уровня

Уровень идентификации требует не только `file`, но и `exiftool`, `pngcheck`/`jpeginfo`, `xxd` (первые и последние байты), `stat` (размер) и `binwalk` (обзор сигнатур). Часто уже здесь видно несоответствие: например, `identify` сообщает 800x600, а `pngcheck` — лишние байты после `IEND`.

Уровень кодирований: `base64`, `base32`, `hex`, `rot13`, `atbash`, `morse`, бинарные кодировки (`A`/`B`, точки/тире), «нулевой ширины» символы. Для каждого — свой декодер; CyberChef `Magic` перебирает большинство автоматически, но результат надо проверять. Признак кодирования — ограниченный алфавит символов и длина, кратная 4/8.

Уровень вложенности: `binwalk -e`, `7z`, `unzip`, `tar`, `gunzip`, `bunzip2`, `xz`. Каждый формат имеет сигнатуру (`PK`, `\x1f\x8b`, `BZh`, `\xfd7zXZ`), поэтому `binwalk` их находит. Если сигнатуры нет, но данные сжаты — пробуй все декомпрессоры по очереди.

Уровень инструментов по типу: изображения — `zsteg`, `stegsolve`, `steghide`, `outguess`, `jsteg`; аудио — `sox`, спектрограмма, `steghide`, `mp3stego`; текст — невидимые символы, пробелы, комментарии; архивы — скрытые файлы, метаданные, whiteouts; документы — каналы OOXML/ODF (см. отдельные уроки).

Уровень продвинутого: LSB с нестандартной глубиной, кастомные схемы, шифрование, стего в сжатых данных (сложнее всего), каналы в метаданных контейнера. Здесь универсального инструмента нет — нужно понимать формат и читать спецификацию. Именно поэтому дерево идёт от простого к сложному: 80% CTF-задач решаются на первых трёх уровнях, и тратить время на продвинутое, не проверив базовое, — типичная потеря.

Практический совет: веди журнал проверок. Каждый шаг — команда, вывод, вывод о том, что это значит. Тогда, если ты застрял, видно, какие уровни уже закрыты, и не повторяешь одно и то же.

## Как пользоваться деревом на реальной задаче

Дерево — это чек-лист, а не догма. Начни с уровня 0 и двигайся вниз, пока не найдёшь флаг или не исчерпаешь уровни. На каждом шаге записывай команду и вывод. Если задача «не поддаётся», вернись и проверь пропущенные уровни: часто флаг лежит в простом месте (комментарий, метаданные, хвост файла), а ты сразу ушёл в LSB-анализ.

```text
0 идентификация -> 1 кодирования -> 2 вложенность -> 3 инструменты -> 4 продвинутое
```

Для каждой категории файла держи свой набор инструментов: изображения, аудио, текст, архивы, документы, бинарники. Дерево универсально, а инструменты — по типу.

## Итог по дереву решений

Ключевая идея — системность и порядок. Большинство CTF-стего решается на уровнях 0–2: идентификация, декодирование, распаковка. Уровни 3–4 (специфичные инструменты и продвинутые каналы) нужны для меньшинства задач, но именно они отличают опытного решателя. Веди журнал проверок, проверяй каждый результат и не пропускай базовое — тогда даже упрямые задачи разбираются по шагам, а не «на удачу».

## Практикум: применяем дерево к архиву

Дано `challenge.zip`. Уровень 0: `file challenge.zip` — «Zip archive». `unzip -l` показывает несколько файлов. Уровень 1: один из файлов — `flag.txt.enc`, другой — `key.txt` с hex-строкой. Уровень 2: `flag.txt.enc` может быть XOR/base64. Уровень 3: применяешь декодер по типу.

```bash
unzip -l challenge.zip
unzip challenge.zip -d ch/
file ch/*
xxd ch/key.txt | head
```

Дальше — по алфавиту `key.txt` определяешь, что это (hex → байты → ключ), а по `flag.txt.enc` — что за шифрование (сравни энтропию; если это XOR, энтропия низкая). Собираешь: расшифровка + ключ = флаг.

Смысл практикума — показать, что дерево работает не только на «картинках». Для архивов оно то же самое: идентификация → декодирование → вложенность → инструменты. Веди журнал и проверяй каждый шаг.

## Что мы теперь знаем
- Начинай с `file`/`head`/`xxd`, а не с экзотики.
- Кодирования → распаковка → инструменты по типу → продвинутое.
- После каждого шага заново определяй тип (`file`).
- Сохраняй промежуточные результаты и веди цепочку.
