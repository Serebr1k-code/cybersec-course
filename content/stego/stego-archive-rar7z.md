## Вопрос, с которого всё начинается

Мы уже разбирали ZIP: комментарии и extra-поля. Но в реальности встречаются и другие
архивы — **RAR** и **7z**, а ещё **ISO-образы** дисков. Там другие структуры, другие
служебные записи и другие места для сокрытия. Как искать в них?

## Наш пример

Дан архив:

```
$ file backup.rar
backup.rar: RAR archive data, v5
$ unrar l backup.rar
UNRAR 6.24 freeware
Archive: backup.rar
 Name             Size   Date    Attr
 docs/            0      2024-06-01  drwxr-xr-x
 notes.txt        124    2024-06-01  -rw-r--r--
```

Внутри — всего пара файлов, а сам архив «толще», чем нужно. Значит, есть скрытое.

## Шаг 1: RAR — комментарии и recovery record

RAR v5 — блочный формат: каждый блок имеет заголовок с типом и CRC. Каналы для сокрытия:

1. **Комментарий архива.** `rar c` добавляет текстовый комментарий — читается `unrar c`.
   ```
   $ unrar c backup.rar
   Archive: backup.rar
   Comment: exfil: nto{r4r_c0mm3nt_st4sh}
   ```
2. **Recovery record.** Служебный блок для восстановления при повреждении. Его размер
   можно раздуть, а внутрь положить данные — `unrar` его не покажет.
3. **Заголовок и дописанные данные.** Как в ZIP, после «официального» конца архива можно
   дописать произвольные байты. `unrar` их игнорирует, `binwalk`/`strings` — находят.

## Шаг 2: 7z — comment и структура

7z — контейнер с заголовком, описывающим сжатые потоки. Особенности:

1. **Комментарий архива** — отдельное поле в заголовке.
2. **Имена файлов** — UTF-16, могут содержать zero-width символы.
3. **Заголовок сжат** (LZMA): «мусорные» поля сложнее, но возможны.
4. **Дописанные данные** после конца архива — так же, как в ZIP/RAR.

```
$ 7z l backup.7z
...
$ 7z l -slt backup.7z | grep -i comment
Comment = nto{7z_h3ad3r_st4sh}
```

## Шаг 3: ISO-образы — свободные сектора

ISO9660 — формат оптического диска: сектора по 2048 байт, таблицы путей и каталогов.
Здесь есть два классических канала:

1. **Дописанные данные.** Если образ «толще», чем сумма размеров файлов, — смотрим хвост.
   ```
   $ isoinfo -d -i image.iso | head
   Volume size is: 5120
   $ ls -l image.iso
   -rw-r--r-- 1 user user 12582912 image.iso   # 6144 сектора — больше заявленного
   ```
2. **Свободные сектора и slack.** Между логическим концом ФС и концом файла — «пустые»
   сектора, которые можно заполнить данными.
3. **El Torito / гибридные образы.** Загрузочный образ внутри ISO может нести данные.
4. **Rock Ridge / Joliet** — дополнительные структуры имён.

```
$ strings image.iso | grep -i nto
nto{1s0_5l4ck_s3ct0r_h1dd3n}
```

## Шаг 4: общий приём — «лишний вес»

Универсальный приём для всех архивов и образов: **сравнить заявленный размер с реальным**.
Если файл больше суммы содержимого — где-то есть дописанные данные. Инструменты:

- `binwalk file` — находит сигнатуры вложенных форматов.
- `strings file | grep nto` — быстрый поиск.
- `xxd file | tail` — хвост файла.
- `7z l -slt` / `unrar l` / `isoinfo -l -i` — метаданные.

## Шаг 5: почему это работает

Архивные форматы создавались с расчётом на **потоковое чтение**: парсер идёт по блокам
и останавливается, когда встречает «конец». Всё, что после, для него не существует —
но для `strings`/`binwalk` существует. Плюс многие форматы содержат **служебные
записи** (recovery, комментарии, выравнивание), размер которых варьируется и не
проверяется.

## Что мы теперь знаем

- **RAR:** комментарий, раздутый recovery record, дописанные данные.
- **7z:** comment, имена в UTF-16, дописанные данные после конца архива.
- **ISO:** свободные сектора, slack, El Torito, Rock Ridge/Joliet.
- Универсальный признак — **«лишний вес»** файла относительно содержимого.
- Инструменты: `unrar`/`7z`/`isoinfo` для метаданных, `binwalk`/`strings`/`xxd` для поиска.

## RAR v5: структура блоков и где смотреть

RAR v5 — блочный формат. Каждый блок начинается с заголовка: CRC, тип, флаги,
размер. Полезные команды:

```
$ unrar l backup.rar          # список файлов
$ unrar lt backup.rar         # подробно: сжатый/несжатый размер, CRC, метод
$ unrar c backup.rar          # показать комментарий архива
$ unrar v backup.rar          # очень подробный листинг
$ unrar p backup.rar notes.txt > notes.txt   # извлечь в stdout
```

На что смотреть в листинге:

1. **`Packed` vs `Size`.** Если `Packed` подозрительно мал при большом `Size`, файл
   хорошо сжался — это нормально. Аномалия — когда **сумма** размеров меньше
   реального размера файла.
2. **Комментарий.** `unrar c` покажет текст — классический канал.
3. **Метод сжатия** (`m0`…`m5`). `m0` — «без сжатия» (store): внутри сырые байты,
   легко искать `strings`.
4. **Recovery record** (`-rr`) — служебный блок; его размер варьируется, внутрь
   можно дописать данные, `unrar` их не покажет.

## 7z: сжатый заголовок и `-slt`

7z хранит оглавление в **сжатом** виде, поэтому `strings` по началу файла часто
бесполезен. Зато `7z l -slt` печатает полную техническую информацию:

```
$ 7z l -slt backup.7z
Path = backup.7z
Type = 7z
Physical Size = 131072
Headers Size = 214
Method = LZMA2:24
Solid = +
...
Path = docs/notes.txt
Size = 124
Packed Size = 98
CRC = 3F9A1C2B
```

Поля для поиска: **`Comment`** (комментарий архива), **`Headers Size`** (если
необычно велик — в оглавлении что-то лишнее), имена файлов в UTF-16 (zero-width
символы). Дописанные после конца архива байты ищутся так же, как в ZIP.

## ISO9660: сектора, пути и свободное место

ISO-образ — это последовательность **секторов по 2048 байт**. Первые 16 секторов
(32 КиБ) — системная область, затем Primary Volume Descriptor с корневым каталогом.
Полезное:

```
$ isoinfo -d -i image.iso          # описание тома
$ isoinfo -l -i image.iso          # рекурсивный листинг файлов
$ isoinfo -i image.iso -x '/README.TXT' > README.TXT   # извлечь файл
```

Дополнительные структуры, которые тоже могут нести данные:

- **El Torito** — загрузочный образ внутри ISO (может быть любой ОС).
- **Rock Ridge** — POSIX-атрибуты (права, длинные имена) поверх ISO9660.
- **Joliet** — имена в UTF-16.
- **Multi-session** — несколько «сессий» записи; каждая со своим оглавлением.

Ключевой признак сокрытия — **«лишний вес»**: `Volume size is: 5120` секторов, а
файл занимает 6144 — последние сектора вне логической ФС.

## Поиск «лишнего веса»: сравнение размеров

Универсальный приём для любого архива/образа — сравнить заявленное с реальным:

```bash
# сколько «официально» занимает образ
isoinfo -d -i image.iso | grep -i 'volume size'
# сколько занимает файл (в секторах по 2048)
python3 -c "import os; print(os.path.getsize('image.iso')//2048)"

# хвост файла
xxd image.iso | tail -20
strings image.iso | grep -i -E 'nto|flag|key'
```

Если реальный размер больше заявленного — смотрим «хвост» от границы ФС до конца
файла: там обычно и лежит payload.

## Инструменты: binwalk, foremost, dd, unar

- **`binwalk file`** — сигнатуры вложенных форматов.
- **`binwalk -e file`** — извлечь найденное автоматически (`--run-as=root` иногда нужен).
- **`foremost -i file -o out/`** — карвинг по сигнатурам (восстановить вложенные файлы).
- **`dd if=file bs=1 skip=N count=M of=part`** — вырезать участок по смещению.
- **`unar file.rar`** — кроссплатформенный распаковщик (The Unarchiver), понимает RAR/7z.
- **`bsdtar -tf file`** — листинг многих форматов без внешних утилит.
- **`7z x -oout file`** — распаковка (поддерживает и RAR при плагине `p7zip-rar`).

## Edge cases и подводные камни

- **Пароль на архиве.** `7z`/`unrar` с `-p` — но это уже не стеганография, а
  крипто-задача (брутфорс offline). Проверь `--password` и словами из задачи.
- **Solid-архивы 7z.** Файлы сжаты вместе — «вырезать» один нельзя; распаковывай всё.
- **Многотомные архивы** (`.part1.rar`, `.001`). Собирай через `unrar x`/`7z x` по
  первому тому — иначе структура не читается.
- **SFX-архивы.** RAR/7z могут начинаться с EXE-заглушки; тогда смещение данных
  сдвинуто — `binwalk` подскажет, где начинается архив.
- **CRC-обман.** Правка байтов в заголовке ломает CRC — парсер откажется читать
  архив. Поэтому данные обычно кладут туда, где CRC не считается (хвост, паддинг).

## Что дальше / решение

Сквозной пример: `unrar c backup.rar` отдаёт комментарий `nto{r4r_c0mm3nt_st4sh}`;
для 7z — `7z l -slt | grep -i comment`; для ISO — сравнение размера тома и
`strings image.iso | grep nto`. Если ничего не видно — `binwalk -e` и `strings` по
всему файлу.

## Шпаргалка: инструменты по форматам

| Формат | Листинг | Комментарий | Поиск данных |
|--------|---------|-------------|--------------|
| RAR | `unrar lt` | `unrar c` | `binwalk`, `strings`, `xxd` |
| 7z | `7z l -slt` | `7z l -slt \| grep -i comment` | `binwalk`, `strings` |
| ISO | `isoinfo -l -i` | — | `strings`, сравнение размеров |
| ZIP | `unzip -l` | `unzip -z` | `binwalk`, `foremost` |
| любой | `file` | — | `binwalk -e`, `foremost` |

## Куда дальше

Мы разобрали архивы и образы. Дальше — **современные сетевые каналы**: как прячут
данные в HTTP/2, HTTP/3 и QUIC, где заголовки и кадры дают новые поля для сокрытия.
А пока главное запомни: **архив — это поток блоков**, и всё после «конца» остаётся
доступным для анализа.
