## Вопрос, с которого всё начинается

В forensics изъяли документ, напечатанный на цветном лазерном принтере. Задача — понять, **на каком именно** устройстве и **когда** его напечатали. На листе нет ни серийного номера, ни даты — только текст. Как их получить?

Оказывается, принтер сам оставил метку: почти невидимый узор из **жёлтых точек**. Это Machine Identification Code (MIC). Разберём, как его извлечь, на нашем скане.

## Наш пример: scan.tiff

Смотрим файл:

```bash
$ identify scan.tiff
scan.tiff TIFF 800x600 8-bit sRGB
```

Это скан цветного документа в TIFF (без сжатия — важно, о причинах ниже). На листе — обычный текст, а в жёлтом канале спрятана решётка точек.

## Шаг 1: что такое MIC

**MIC** (Machine Identification Code) — узор из жёлтых точек, который цветные лазерные принтеры и копиры печатают на каждом листе. Он кодирует:

- **серийный номер** устройства;
- **дату и время** печати;
- иногда **модель/вендор**.

Точки крошечные (диаметр около 0.1 мм) и наложены на страницу по **решётке** с шагом примерно 0.1 мм. При обычном просмотре лист выглядит белым: жёлтый цвет с низкой контрастностью почти сливается с бумагой. Это самая настоящая физическая стеганография — маркировка, которую печатающее устройство оставляет незаметно для глаза.

## Шаг 2: выделяем жёлтый канал

Ключевая мысль: точки видны **только в жёлтом канале**. В модели RGB жёлтый — это смесь красного и зелёного при почти нулевом синем. Значит, «жёлтость» пикселя можно вычислить как `(R + G)/2 − B`: у бумаги (белой) R≈G≈B, и разность ≈0; у жёлтой точки синего меньше, и разность положительна. Разделим каналы и построим карту жёлтости:

```python
import cv2, numpy as np
im = cv2.imread("scan.tiff").astype(np.int16)
b, g, r = cv2.split(im)                       # OpenCV читает в порядке BGR
yellow = np.clip((r + g)//2 - b, 0, 255).astype(np.uint8)
cv2.imwrite("yellow.png", yellow)
```

ImageMagick умеет то же через цветовое пространство CMYK (жёлтый = канал Y):

```bash
$ convert scan.tiff -colorspace CMYK -channel Y -separate -negate yellow.png
```

После этого на `yellow.png` точки становятся яркими на тёмном фоне.

## Шаг 3: детект точек

Теперь нужно найти сами точки. Простейший путь — порог по яркости и подсчёт связных компонент (blob-ов):

```python
mask = (yellow > 10).astype(np.uint8) * 255
n, labels, stats, centroids = cv2.connectedComponentsWithStats(mask)
print("dot components:", n - 1)
```

```
yellow max: 30 dot components: 29
```

Двадцать девять точек — это решётка. `yellow.max()=30` показывает, насколько слабый сигнал: разница всего 30 уровней из 255, поэтому без усиления канала точки не видны.

## Шаг 4: декодирование узора

Зная шаг решётки, для каждой её позиции решаем: есть точка или нет. Наличие точки — бит `1`, отсутствие — `0`. Восстановим биты по сетке и соберём байты:

```python
step = 18
bits = []
for y in range(30, H-30, step):
    for x in range(30, W-30, step):
        bits.append(1 if yellow[y, x] > 10 else 0)
s = "".join(map(str, bits))
print(bytes(int(s[i:i+8], 2) for i in range(0, len(s)-7, 8)))
```

```
b'12345678'
```

Мы восстановили последовательность `12345678` — в реальном MIC это была бы часть серийного номера или даты. В настоящих задачах биты сопоставляются с таблицей конкретного вендора (Xerox, Canon, HP, Epson, Brother): у каждого своя кодировка.

## Шаг 5: разрешение, сжатие и шум

Точки крошечные, поэтому требования к скану жёсткие:

- **Разрешение 600–1200 dpi.** При 72 dpi точки просто сливаются с бумагой.
- **Без потерь: TIFF или PNG.** JPEG-артефакты размывают узор и маскируют точки.
- **Очистка шума.** Реальные сканы зашумлены; помогают медианный фильтр (убирает «соль-перец», сохраняя точки), морфология (выделение круглых пятен), нормализация освещения (`cv2.divide` на размытие).

```python
blur = cv2.GaussianBlur(yellow, (0, 0), 3)
norm = cv2.divide(yellow, blur, scale=255)     # выравниваем фон
```

Шаг решётки устойчиво определяется через FFT — периодичность даёт чёткий пик.

## Шаг 6: forensics-кейс

Как это работает в расследовании:

1. Документ сканируется в TIFF 1200 dpi.
2. Усиливается жёлтый канал.
3. Декодируется серийный номер и дата.
4. Серийник сопоставляется с базой устройств организации.
5. Вывод: документ напечатан на конкретном принтере в конкретное время.

Это стандартный, юридически значимый артефакт. Технология появилась как средство борьбы с подделкой банкнот и документов; публично о ней узнали после проекта «Seeing Yellow» (2005). Важно помнить: MIC печатают в основном **цветные лазерные** устройства — у струйных и чёрно-белых точек может не быть.

## Шаг 7: структура узора и таблицы вендоров

В типовой схеме (например, у Xerox) решётка накладывается с шагом около 1/100 дюйма, и узор образует повторяющиеся блоки. Внутри блока часть ячеек кодирует серийный номер (в десятичной кодировке, по 2–3 цифры в строке), часть — дату в формате `YYMMDD` и время, иногда — код модели. Точки настолько мелкие, что нужен скан 600–1200 dpi и хорошая оптика.

У разных вендоров кодировки различаются: Xerox, Canon, HP, Epson, Brother используют свои таблицы. Поэтому «универсального декодера» нет — после детекта точек нужно сопоставить узор с таблицей производителя. В CTF часто достаточно визуально увидеть в усиленном жёлтом канале цифры или QR-подобный узор.

| Поле | Что кодирует | Ценность в forensics |
|---|---|---|
| Серийный номер | уникальный ID принтера | привязка документа к устройству |
| Дата | день/месяц/год | установление времени печати |
| Время | часы/минуты | сужение окна печати |
| Модель/вендор | тип устройства | сужение круга моделей |

## Шаг 8: родственные виды маркировки

MIC — не единственная скрытая маркировка. Тот же принцип «невидимо глазу, видимо сканеру» используют:

- **Microdots** — микроскопические точки с текстом, наносимые на документы.
- **Низкоконтрастные QR/баркоды**, напечатанные «на просвет».
- **Стелс-водяные знаки** в банкнотах — для защиты от подделки.

Все они эксплуатируют одно: невооружённый глаз не различает деталь, а сканер или микроскоп — различает. Частые заблуждения: «точки видны на глаз» (нет), «MIC есть у всех принтеров» (в основном у цветных лазерных), «достаточно низкого разрешения» (нет, нужно 600+ dpi), «кодировка универсальна» (нет, у вендоров разные таблицы).

## Что мы теперь знаем

1. MIC — почти невидимый узор жёлтых точек, кодирующий серийник принтера и дату.
2. Точки видны **только в жёлтом канале**; «жёлтость» = `(R+G)/2 − B`.
3. Узор наложен по решётке; наличие/отсутствие точки в ячейке = бит.
4. Нужен скан 600–1200 dpi в TIFF/PNG (JPEG маскирует узор).
5. Кодировка у вендоров разная; биты сопоставляются с таблицей производителя.
6. MIC печатают в основном цветные лазерные принтеры.

## Куда дальше

Мы научились читать метки, которые оставляет оборудование. Дальше вернёмся к цифровым форматам и разберём **водяные знаки** (watermarking) — устойчивые метки, встроенные прямо в изображение. А пока запомни: дали скан документа — усиливай жёлтый канал и ищи решётку точек.

## Где пригодится

- **Forensics:** идентификация устройства печати по изъятому документу.
- **CTF:** задачи, где на скане листа спрятан код.
- **ИБ-аудит:** понимание скрытых меток, которые оставляет офисная печать.
