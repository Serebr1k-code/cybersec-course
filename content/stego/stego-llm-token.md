## Вопрос, с которого всё начинается

Тебе дали `tokens.json` — дамп генерации LLM: список идентификаторов токенов. LLM
работает не с буквами, а с токенами, и каждый токен — это целое число. Может ли
последовательность чисел нести скрытое сообщение? Да, и несколькими способами.
Разберём дамп.

## Наш пример: файл tokens.json

```bash
cat tokens.json
```

```text
{"model": "demo", "tokens": [100110, 100116, 100111, 100123, 100108, ...]}
```

Идентификаторы большие (100000+), но обрати внимание: они идут подряд и отличаются
на небольшие значения. Если вычесть базу, получим байты. Разберём.

## Шаг 1: что такое токены LLM

LLM не читает символы — она читает **токены**: кусочки текста (слова, части слов,
знаки). У каждой модели свой **словарь** (vocab): таблица «токен → целое число».
Например, в BPE-словаре токен `"cat"` может иметь id `4823`, а `" the"` — id `262`.

Генерация — это последовательность id: модель предсказывает следующий токен, выбирает
его (по вероятностям), добавляет к последовательности. Значит, поток id — это данные,
и их можно использовать.

## Шаг 2: три способа спрятать в токенах

- **Смещение id.** Если модель нестандартная (fine-tune) или дамп синтетический, id
  могут быть сдвинуты на базу: `id - base` = байт. Именно наш случай.
- **Выбор токена.** Из нескольких равновероятных токенов выбирается тот, чей id
  кодирует бит. Наблюдатель видит «нормальный» текст, а биты спрятаны в выборе.
- **Порядок/количество токенов.** Паузы, длина ответа, повтор — тоже каналы.

## Шаг 3: извлекаем сообщение вручную

```bash
python3 - <<'PY'
import json
data = json.load(open('tokens.json'))
toks = data['tokens']
base = 100000
out = bytes(t - base for t in toks)
print(out.decode('latin-1'))
PY
```

```text
nto{llm_t0k3n_fl4g}
```

## Шаг 4: словарь как носитель

Помимо id, носителем может быть сам **словарь**: в `vocab.json` можно добавить
«лишние» токены или переставить существующие. Строки токенов — текст, и в них можно
спрятать данные (например, первые буквы токенов образуют сообщение). Если задача даёт
`vocab.json` вместе с `tokens.json`, проверь оба.

## Шаг 5: sampling как covert-канал

В реальных LLM-стегосистемах (например, для watermarking) биты прячут в **sampling**:
на каждом шаге модель даёт распределение вероятностей, и из него выбирается токен,
кодирующий бит. Получатель, зная ключ, восстанавливает биты; внешний наблюдатель
видит обычный текст. Это самый «естественный» канал для LLM, но он требует доступа к
модели и распределению.

## Шаг 6: инструменты

```bash
python3 -c "import json; print(json.load(open('tokens.json')))"
transformers / tokenizers            # загрузка словаря
jq '.tokens[:10]' tokens.json
```

Для реального словаря используй `tokenizers`, чтобы сопоставить id и строки. Для
CTF обычно хватает простого смещения или первых букв токенов.

## Шаг 7: почему LLM — удобный носитель

Объём генерации огромен, а «нормальность» текста проверять сложно. Выбор токена
практически не влияет на смысл (много синонимов), поэтому биты в выборе незаметны.
Плюс метаданные генерации (model, temperature, seed) — свободные поля. Всё это делает
LLM-артефакты хорошим носителем.

## Шаг 8: частые ошибки

Первая — пытаться декодировать id как ASCII напрямую: они слишком большие. Вторая —
не найти базу: посмотри минимальный id и разности. Третья — игнорировать `vocab.json`.
Четвёртая — считать, что «текст нормальный, значит чисто»: закладка как раз в том,
чтобы текст оставался нормальным.

## Практика: watermarking через sampling

Самый «естественный» LLM-канал — выбор токена. На каждом шаге модель выдаёт
распределение вероятностей. Если сгруппировать токены по ключу (например, хэш
предыдущего токена), то в каждой группе можно выбрать «зелёные» токены так, чтобы
кодировать бит. Получатель, зная ключ, считает долю «зелёных» и восстанавливает биты;
без ключа текст выглядит обычным. Это основа watermarking LLM.

```bash
python3 - <<'PY'
import json, hashlib
d = json.load(open('tokens.json'))
# пример: младший бит id как канал
bits = [t & 1 for t in d['tokens']]
out = bytearray()
for k in range(0, len(bits)//8*8, 8):
    b = 0
    for x in bits[k:k+8]:
        b = (b << 1) | x
    out.append(b)
print(out)
PY
```

Такой скрипт показывает, что даже «обычный» поток id можно переосмыслить как биты.

## Словарь и метаданные генерации

Если задача даёт `vocab.json`, `config.json` или лог генерации — проверь их. В
`vocab.json` можно добавить «лишние» токены или переставить существующие. В
`config.json` — свободные поля (`name`, `description`). В логе генерации — `seed`,
`temperature`, `top_p`, а также сырой поток токенов.

Признаки закладки: токены, которых нет в словаре; строки токенов, складывающиеся в
сообщение по первым буквам; необычные метаданные. В CTF часто дают `tokens.json` с
явным смещением, как в нашем примере, — это самый простой вариант.

## Как отличить закладку в LLM-артефактах

Смотри на «неестественность»: id, выстроенные в арифметическую последовательность;
текст, который выглядит нормально, но его низкоуровневые id «слишком ровные»; лишние
поля в словаре. Практический приём — вычислить разности соседних id: если они
постоянны, это смещение, а не настоящая генерация. Настоящие токены «прыгают»
непредсказуемо.

## Почему LLM-стеганография — горячая тема

Генеративный ИИ создаёт огромные объёмы текста, и проверить «нормальность» каждого
сложно. Это делает LLM идеальным носителем: биты прячут в выборе токенов, и снаружи
текст выглядит обычным. Исследователи предлагают схемы, где водяной знак (watermark)
устойчив к правкам и при этом незаметен человеку. Обратная задача — детектирование:
по статистике «зелёных» токенов можно определить, сгенерирован ли текст моделью с
водяным знаком.

Для CTF важно более простое: понять, что поток токенов можно переосмыслить как
данные. Наш пример — смещение id, но в задачах встречаются и младшие биты id, и
выбор из синонимов, и «лишние» токены в словаре. Все они решаются разбором
`tokens.json` и `vocab.json`.

## Практика: младшие биты id

Если смещение не очевидно, попробуй младшие биты. Идентификаторы токенов — обычные
целые; их младший бит «шумит» так же, как младший бит пикселя.

```bash
python3 - <<'PY'
import json
d = json.load(open('tokens.json'))
bits = [t & 1 for t in d['tokens']]
out = bytearray()
for k in range(0, len(bits)//8*8, 8):
    b = 0
    for x in bits[k:k+8]:
        b = (b << 1) | x
    out.append(b)
print(out)
PY
```

Попробуй оба порядка бит (MSB-first и LSB-first) — как в IQ-стеганографии. Если ни
смещение, ни младшие биты не дали результата, смотри `vocab.json`.

## Чек-лист по LLM-артефактам

1. `cat tokens.json` — посмотри значения; есть ли смещение?
2. Попробуй `id - base` и младшие биты id.
3. Проверь `vocab.json` на «лишние» токены и первые буквы строк.
4. Проверь `config.json`/лог генерации на свободные поля (`seed`, `name`).
5. Попробуй декодировать найденные байты как ASCII/base64.

Такой порядок покрывает и CTF, и анализ реальных LLM-артефактов на водяные знаки.

## Итоговая стратегия для LLM-артефактов

Начни с `tokens.json`: посмотри значения и разности. Если разности постоянны — это
смещение, вычти базу. Если нет — попробуй младшие биты id (в обоих порядках). Затем
проверь `vocab.json` и `config.json`. Декодируй найденные байты как ASCII/base64.
Если ничего — смотри лог генерации и метаданные (seed, temperature). Помни: текст
может оставаться совершенно нормальным, а данные — ехать в низкоуровневых id. Именно
это делает LLM-канал таким интересным и опасным.

## Замечание о «естественности» текста

Главная сила LLM-стеганографии в том, что она не портит текст. В отличие от замены
символов (которые видно), выбор токена из равновероятных синонимов не меняет смысл.
Человек читает нормальное предложение, а машина, знающая ключ, извлекает биты. Это
делает канал устойчивым и незаметным. Обратная сторона — детектирование требует
статистики: нужно оценить, не «слишком ли часто» выбираются определённые токены. Для
CTF достаточно более простых вариантов (смещение, младшие биты), но понимать принцип
sampling-канала полезно: он объясняет, почему LLM-артефакты — перспективный носитель.

## Ещё одна мысль

Если задача даёт и `tokens.json`, и `vocab.json`, всегда проверяй оба: канал может быть в любом из них. Иногда сообщение собирается не из id, а из строк токенов словаря — например, по первым буквам или по «лишним» записям.

## Итог

LLM-артефакты — это последовательности чисел, и любые числа можно переосмыслить как данные. Смещение, младшие биты, выбор токена и словарь — четыре канала, которые стоит проверять по порядку. Главное, что отличает LLM-стеганографию от классической: носитель «живой» и постоянно меняется, поэтому закладку особенно трудно заметить без знания схемы.

Проверяй каналы по порядку и не пропускай ни один: закладка может быть в самом неожиданном из них.

Всегда проверяй и словарь, и метаданные, и сам поток идентификаторов.
