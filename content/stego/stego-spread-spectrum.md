## Вопрос, с которого всё начинается

В задаче картинку обрезали, зашумили и пересохранили — а сообщение всё равно читается. Ни LSB, ни QIM такого не переживут: каждый их бит привязан к одному пикселю, и стоит его испортить — бит потерян. Значит, использована схема, где **один бит размазан по сотням пикселей**. Как её декодировать?

Это **spread-spectrum** (SSIS, spread-spectrum image steganography) — приём, пришедший из радиосвязи. Разберём его на нашем примере.

## Наш пример: cover_ss.png

Возьмём `cover_ss.png` — сглаженный шум 256×256 в оттенках серого. Спрячем в него строку `flag{ssis}` и посмотрим, как схема ведёт себя при шуме и при неверном ключе.

## Шаг 1: идея размазывания

В радиосвязи, чтобы передать сигнал через шумный канал, его «размазывают» по широкой полосе: каждый бит умножается на длинную **псевдослучайную последовательность** (PN-код), и на приёмнике сворачивают обратно — «собирая» энергию сигнала и подавляя шум.

В стеганографии то же самое делают с пикселями. Бит кодируется **знаком** произведения изображения на PN-последовательность, и этот вклад распределён по сотням пикселей. Отсюда высокая устойчивость: часть пикселей можно испортить, а корреляция всё равно «увидит» знак.

## Шаг 2: PN-последовательность и seed

**PN-последовательность** — детерминированный набор из `+1` и `−1`, воспроизводимый из короткого ключа — **seed**. Генерируется PRNG:

```python
SEED = 1337
def pn(seed, n):
    r = np.random.default_rng(seed)
    return r.choice([-1.0, 1.0], size=n)
```

Без знания seed последовательность случайна, и данные неотличимы от шума. Именно seed играет роль ключа.

## Шаг 3: встраивание

Сообщение раскладывается в биты. Каждый бит умножается на кусок PN-последовательности длиной **CHIP** (чип — число пикселей на бит) и прибавляется к изображению с силой `α`:

```
x'_j = x_j + α · s · p_j        где s = +1 для бита 1, s = −1 для бита 0
```

```python
ALPHA = 6.0
CHIP = 256
flat = np.array(img).astype(np.float64).reshape(-1)
p = pn(SEED, flat.size)
pos = 0
for b in np.unpackbits(np.frombuffer(b"flag{ssis}", dtype=np.uint8)):
    s = 1.0 if b else -1.0
    flat[pos:pos+CHIP] += ALPHA * s * p[pos:pos+CHIP]
    pos += CHIP
```

Встраивание почти незаметно: каждая правка — доли единицы яркости, размазанные по чипу.

## Шаг 4: корреляционный приёмник

Декодер не «читает» пиксели по одному — он **накапливает статистику**. Для каждого бита считается корреляция — сумма произведений пикселей чипа на тот же кусок PN:

```
C = Σ (x'_j · p_j)
```

Если встроен бит `+1`, сумма положительна; если `−1` — отрицательна. Знак и есть бит.

Тут есть важная тонкость. Наш cover — серое изображение со средней яркостью 128. Сумма `128 · p_j` по чипу — это случайное блуждание порядка `128·√CHIP`, которое **перебивает** полезный сигнал `α·CHIP`. Поэтому корреляцию считают по **высокочастотной** части: вычитают среднее (постоянную составляющую, DC).

```python
def extract(path, n_bits, seed, chip):
    a = np.array(Image.open(path).convert("L")).astype(np.float64).reshape(-1)
    a = a - a.mean()                       # убираем DC-компоненту
    p = pn(seed, a.size)
    bits = []
    for i in range(n_bits):
        seg = slice(i*chip, (i+1)*chip)
        bits.append(1 if np.sum(a[seg] * p[seg]) > 0 else 0)
    return np.packbits(np.array(bits, dtype=np.uint8)).tobytes()
```

Прогон:

```
clean:  b'flag{ssis}'   corr bit0..3: [-1381, 1570, 1584, -1565]
```

Знаки корреляции чередуются в точности как биты символа `f` (`01100110`): `0,1,1,0` → `−,+,+,−`. Приёмник работает.

## Шаг 5: проверяем робастность

Добавим к стего гауссов шум со среднеквадратичным отклонением 12 и снова извлечём:

```
noise sd12: b'flag{ssis}'
```

Флаг выжил. В этом и сила spread-spectrum: шум «размазывается» по всей корреляции и подавляется, а сигнал собирается обратно. Точно так же схема переживает обрезку (уцелевшие пиксели дают верный знак) и мягкое JPEG-сжатие.

## Шаг 6: неверный seed

Попробуем извлечь с другим seed — 9999 вместо 1337:

```
wrong seed: b'\xbeg?(\xe39\xa3\xab\xac\x06'
```

Мусор. Без правильного seed корреляция случайна, и данные не восстановить. Это делает seed настоящим ключом: в задаче его ищут в условии, метаданных или перебором.

## Шаг 7: ёмкость и CHIP

`CHIP` — ручка размена «робастность ↔ ёмкость». Чем больше пикселей на бит, тем устойчивее, но тем меньше влезает:

| CHIP | Ёмкость (512²) | Робастность |
|---|---|---|
| 64 | ~512 Б | низкая |
| 256 | ~128 Б | средняя |
| 1024 | ~32 Б | высокая |

Для нашего изображения 256² при `CHIP=256` доступно `65536/256 = 256` бит = 32 байта — как раз под короткий флаг.

## Шаг 8: DSSS и FHSS

Spread-spectrum бывает двух основных видов:

- **DSSS** (Direct Sequence) — PN-последовательность умножается на сигнал напрямую. Именно этот вариант мы разобрали; в картинках встречается чаще всего.
- **FHSS** (Frequency Hopping) — несущая «прыгает» по частотам по PN-закону. В стеганографии аналог — выбор, в какие пиксели или частотные коэффициенты писать, в зависимости от PN. Сложнее, но устойчивее к узкополосным помехам.

В CTF почти всегда DSSS: он просто реализуется и легко читается корреляционным приёмником.

## Как детектируют spread-spectrum

Против SSIS инструменты вроде `zsteg` бесполезны — данные не в младших битах. Работают другие приёмы:

- **Корреляционный тест.** Если прогнать корреляцию с перебором seed, при «угаданном» ключе величина корреляции устойчиво отклоняется от нуля, а биты складываются в осмысленный текст.
- **Анализ спектра.** В частотной области SSIS выглядит как равномерный «шумовой» фон в определённой полосе — на спектрограмме аудио или на Фурье-образе изображения это заметно.
- **Геометрические искажения.** SSIS слаб к повороту и масштабу: нарушается соответствие «пиксель ↔ элемент PN». Для борьбы с этим встраивают синхронизационные метки.

Практический порядок разбора: `zsteg -a` (на случай LSB) → построить корреляционный приёмник → перебрать seed (числа, строки, пароли из условия) → оценить `CHIP` по сходимости корреляции → проверить устойчивость обрезкой и шумом.

## Что мы теперь знаем

1. Spread-spectrum кодирует бит **знаком корреляции** изображения с PN-последовательностью.
2. Бит размазан по `CHIP` пикселям, поэтому схема переживает шум и обрезку.
3. **seed** PN-последовательности — это ключ; без него данные неотличимы от шума.
4. Корреляцию считают по высокочастотной части: **DC-компоненту вычитают**, иначе средняя яркость перебивает сигнал.
5. Больше `CHIP` — робастнее, но меньше ёмкости.
6. Знак корреляции — бит: `+` → 1, `−` → 0.

## Куда дальше

Spread-spectrum живёт в пикселях, но ту же математику применяют к **аудио**: PN модулирует сэмплы, а слух толерантен к шумовому фону в высоких частотах. Мы ещё вернёмся к аудио-носителям. А пока запомни: данные пережили обрезку и шум — строй корреляционный приёмник и перебирай seed.

## Где пригодится

- **CTF:** Stego — робастные водяные знаки, задачи на корреляцию.
- **Watermarking:** аудио/видео-метки, переживающие сжатие и обработку.
- **Работа:** помехоустойчивое кодирование и скрытые каналы.
