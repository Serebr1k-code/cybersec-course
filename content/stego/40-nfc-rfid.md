## Вопрос, с которого всё начинается

В CTF по hardware тебе выдали пластиковую карту — «ключ от двери» в офисе компании. Ты прикладываешь её к считывателю Proxmark3, видишь какой-то номер, но флага нет. При этом задание намекает, что на карте «что-то ещё». Где на пластике размером с визитку можно спрятать данные?

Ответ: в **памяти микросхемы**, которая внутри карты. Считыватель обычно смотрит лишь несколько байт, а всё остальное пространство — свободно, и туда можно записать что угодно. Разберём это на конкретной карте.

## Наш пример: карта доступа Mifare Classic 1K

**RFID** (Radio Frequency Identification) — технология, где микросхема в метке отвечает по радио на запрос считывателя. **NFC** (Near Field Communication) — частный случай RFID на частоте 13.56 МГц с очень малой дистанцией (несколько сантиметров), которую используют банковские карты, пропуска и смартфоны.

Наша карта — **Mifare Classic 1K**, самый распространённый тип пропуска. Начнём с определения типа:

```bash
pm3 --> hf search
 UID: 9A1B2C3D
 ATQA: 0004  SAK: 08
 TYPE: NXP MIFARE CLASSIC 1k | Plus 2k SL1
```

**UID** (Unique IDentifier) — уникальный номер метки, который считыватель проверяет в первую очередь. Но сам UID — это только «имя». Настоящие данные лежат в памяти.

## Шаг 1: как устроена память Mifare Classic

Память Mifare Classic 1K разбита на **16 секторов**, в каждом секторе — **4 блока** по 16 байт. Последний блок сектора (его называют **trailer**) хранит два ключа — **A** и **B** — и биты доступа. Ключи — это пароли: чтобы прочитать блок, нужно знать ключ этого сектора.

```
Сектор 0: [блок 0 — manufacturer/UID] [блок 1] [блок 2] [блок 3 = trailer A|B|права]
Сектор 1: [блок 4] [блок 5] [блок 6] [блок 7 = trailer]
...
Сектор 15: [блок 60] [блок 61] [блок 62] [блок 63 = trailer]
```

Ключи Mifare Classic — 48-битная криптография, которую давно сломали. Поэтому появились атаки (`nested`, `darkside`), подбирающие ключ и дающие полный доступ. Именно поэтому карта считается «незащищённой»: если ключ по умолчанию не сменён, читается всё.

## Шаг 2: подбираем ключи

Первый шаг к полному дампу — узнать ключи. Пробуем известные дефолтные:

```bash
$ printf 'FFFFFFFFFFFF\nA0A1A2A3A4A5\n000000000000\nD3F7D3F7D3F7\n' > keys.lst
pm3 --> hf mf chk --1k -f keys.lst
[+] Found key A: FFFFFFFFFFFF (sector 0)
```

Сработал дефолтный `FFFFFFFFFFFF`. Если нет — `hf mf autopwn` запускает автоматический подбор (словарь + криптоатаки) и сразу делает дамп:

```bash
pm3 --> hf mf autopwn
[+] -----+-----+--------------+---+--------------+----
[+]  Sec | Blk | key A        |res| key B        |res
[+] -----+-----+--------------+---+--------------+----
[+]  0   | 000 | FFFFFFFFFFFF | D | FFFFFFFFFFFF | D
[+]  1   | 004 | A0A1A2A3A4A5 | D | FFFFFFFFFFFF | D
[+] Saved 1024 bytes to binary file hf-mf-9A1B2C3D-dump.bin
```

Без ключей полного дампа Mifare Classic получить нельзя — поэтому начинать всегда надо с подбора.

## Шаг 3: дамп и поиск данных в «пустых» блоках

Теперь у нас есть дамп памяти. Смотрим его целиком, а не только UID:

```bash
$ xxd hf-mf-9A1B2C3D-dump.bin | sed -n '61,64p'
000003c0: 0000 0000 0000 0000 0000 0000 0000 0000  ................
000003d0: 666c 6167 7b72 6669 645f 7365 6372 6574  flag{rfid_secret
000003e0: 7d00 0000 0000 0000 0000 0000 0000 0000  }...............
000003f0: ffff ffff ffff ff07 8069 ffff ffff ffff  .........i......
```

Видим прямо в **секторе 15** ASCII-строку `flag{rfid_secret}`. Сектор 15 — последний, и большинство систем доступа читают только сектор 0 (UID) и пару следующих. Данные в дальнем секторе никто не смотрит — идеальное место для сокрытия.

Это и есть RFID-стеганография: **использование памяти, которую приложение не читает**. Помимо неиспользуемых секторов, прячут данные в:

- **trailer/access-битах** — нестандартные права доступа (например, все ключи открыты);
- **manufacturer-блоке** — на клонах его перезаписывают;
- **NDEF-записях** — под видом URI или текста.

## Шаг 4: если метка — NTAG (NDEF)

**NTAG** — более новые метки с памятью под NDEF. **NDEF** (NFC Data Exchange Format) — стандартный формат сообщений: URI, текст, визитка. Данные часто прячут именно там, под видом «ссылки»:

```bash
pm3 --> hf mfu dump
pm3 --> hf mfu ndefread
[+] Record 1: URI
[+] URI: https://aGVsbG8tZnJvbS1uZGVm.evil-corp.com/
```

Ссылка выглядит обычной, но её поддомен — это base32. Декодируем:

```bash
$ echo aGVsbG8tZnJvbS1uZGVm | base64 -d
hello-from-ndef
```

NTAG/Ultralight читаются без ключей (`hf mfu dump`), поэтому в CTF с ними возни меньше — просто проверяй NDEF.

## Шаг 5: клонирование и детект подделки

Клонирование — это копирование метки на «болванку». Обычные карты имеют **неизменяемый UID**, но существуют **Magic-карты** — карты, у которых UID можно перезаписать:

```bash
pm3 --> hf mf cload -f hf-mf-9A1B2C3D-dump.bin   # залить дамп на Magic-карту
pm3 --> hf mf restore                            # восстановить из дампа
```

Отличить клон от оригинала помогают признаки:

| Признак | Что означает |
|---|---|
| UID ≠ manufacturer-блок | метку правили или клонировали |
| Все ключи `FF..` / открытый доступ | защита не настроена либо сброшена |
| Данные вне ожидаемого диапазона | сокрытие |
| Две метки с одним UID | клон |

## Шаг 6: не путайте частоты

Частая ошибка новичка — искать Mifare на частоте 125 кГц. Есть два больших семейства:

- **125 кГц** — простые метки только с UID: EM4100, HID Prox. Читаются и клонируются тривиально.
- **13.56 МГц** — «умные» метки: Mifare, NTAG, DESFire. Здесь есть память, ключи, NDEF.

Антенны и режимы у Proxmark для этих частот разные, поэтому первым делом всегда делайте `hf search` (13.56 МГц) или `lf search` (125 кГц).

## Шаг 7: если ключ не подобрался

Иногда дефолтные ключи сменены и словарь не помогает. Тогда идёт в ход **nested-атака**: она использует уже известный ключ одного сектора, чтобы вытащить ключ соседнего.

```bash
pm3 --> hf mf nested --1k --blk 0 -a -k FFFFFFFFFFFF -t
[+] Testing sector 1 with key A (nested)...
[+] Found key A: A0A1A2A3A4A5
```

Если и это не сработало — расширяйте словарь ключей. Но помните: смена ключей не делает Classic по-настоящему стойким, потому что криптоалгоритм 48-бит слабый. Единственная реально надёжная защита — метки с AES/DES, например DESFire или iClass.

## Что фиксировать в отчёте

Для аудита системы контроля доступа записывайте: тип метки (Classic/Ultralight/NTAG), найденный ключ (A или B), сектор и блок с данными, метод декодирования (hex/base32/NDEF). Без этого результат невоспроизводим, а «клонирование удалось» нельзя подтвердить повторно.

## Если не сработало

- **Виден только UID** — вероятно, это 125 кГц-метка (EM4100) либо ты читаешь не тот сектор. Перепроверь `hf search` / `lf search`.
- **`autopwn` не находит ключи** — добавь словарь и попробуй `nested` с уже известным ключом.
- **Дамп есть, данных не видно** — смотри не только ASCII, но и hex: данные могут быть закодированы (base32, XOR) или разбиты по блокам.
- **Чтение нестабильно** — держи метку ровно над антенной, не двигай, проверь питание Proxmark.

## Что мы теперь знаем

1. RFID/NFC-метка — микросхема с **памятью**, доступной по радио.
2. Mifare Classic делится на **сектора по 4 блока**; в trailer лежат ключи A/B.
3. Без ключей полного дампа Classic не получить — начинай с `autopwn`/`chk`.
4. Прячут данные в **неиспользуемых секторах**, trailer, NDEF, manufacturer-блоке.
5. Magic-карта с перезаписываемым UID позволяет клонировать пропуск.
