NFC/RFID-метки — это микросхемы с блоками памяти, доступными по радио. «Стеганография» здесь — использование неиспользуемых/зарезервированных блоков, manufacturer-блоков, trailer-секторов и нестандартных значений для сокрытия данных. Для CTF и физической безопасности важно уметь читать/дамплить метки, клонировать их и находить данные вне «ожидаемых» полей.

## Типы меток

- **Mifare Classic (1K/4K):** 16/40 секторов по 4 блока; последний блок сектора — trailer (ключи A/B + access bits).
- **Mifare Ultralight:** 16 страниц по 4 байта; page 0-1 — UID/производитель.
- **NTAG21x:** пользовательская память + конфиг.
- **EM4100 (125 kHz):** только UID, часто клонируется.

## Чтение и дамп

```bash
# Proxmark3
pm3 --> hf search
pm3 --> hf mf autopwn           # подбор ключей + дамп Mifare Classic
pm3 --> hf mf dump              # дамп в файл
pm3 --> hf mf chk --1k -f keys.lst
# Flipper Zero
# 125 kHz Read, NFC → Read
# извлечь блоки
pm3 --> hf mf rdbl --blk 1 -k FFFFFFFFFFFF
```

Ищите данные в блоках, которые приложение/система не использует: резервные сектора, manufacturer block (перезапись на клонах), trailer-биты, блоки за пределами используемого диапазона.

## Сокрытие и клонирование

- **Скрытые блоки:** записать данные в неиспользуемые сектора (например, сектор 15 на Mifare Classic, если система читает только 0-4).
- **NDEF-записи:** данные в NDEF-сообщении под видом URI/текста.
- **Клонирование:** Magic-карты (UID-перезаписываемые) для копирования метки доступа.
- **Emulation:** Proxmark/Flipper эмулируют метку — вход по копии.

## Детект подделки

- Различия UID vs manufacturer block.
- Нестандартные access bits (все ключи/доступ открыты).
- Дубликаты UID на разных метках.
- Данные в блоках вне ожидаемого диапазона.

## Разобранный пример

CTF Hardware: дана Mifare-метка, «ключ» доступа — в неиспользуемом секторе. Пентестер:
1. `hf mf autopwn` → ключи + полный дамп.
2. Просматривает блоки → в секторе 15 ASCII-строка → декодирует → флаг.

## Частые ошибки

- Читать только UID, пропуская пользовательскую память.
- Не подбирать ключи Mifare Classic (autopwn) — без них нет дампа.
- Игнорировать trailer/manufacturer-блоки.
- Путать 125 kHz (EM4100) и 13.56 MHz (Mifare/NTAG).

## Что делать дальше

- **Есть дамп** → просмотрите все блоки на ASCII/структуры.
- **Ключи не подобрались** → расширенный словарь ключей (`hf mf chk`).
- **Найдены данные** → декодируйте (hex/base64/NDEF).
- **Клонирование** → Magic-карта + запись UID/блоков.

## Типы меток и их память (таблица)

| Метка | Частота | Память | Ключи | Заметка |
|-------|---------|--------|-------|---------|
| Mifare Classic 1K | 13.56 МГц | 16 секторов × 4 блока | A/B | крипто 48-бит (сломан) |
| Mifare Classic 4K | 13.56 МГц | 40 секторов | A/B | как 1K, больше памяти |
| Mifare Ultralight | 13.56 МГц | 16 страниц × 4 байта | нет | page 0-1 = UID |
| NTAG213/215/216 | 13.56 МГц | 144/504/888 байт | нет (пароль опц.) | NDEF-память |
| EM4100 | 125 кГц | только UID (40 бит) | нет | легко клонируется |
| HID Prox | 125 кГц | UID + facility code | нет | клонируется |
| iClass/DESFire | 13.56 МГц | сектора | DES/AES | стойкие |

## Чтение и дамп: Proxmark/Flipper

```bash
# --- Proxmark3 ---
pm3 --> hf search                 # определить тип метки
pm3 --> hf 14a info               # общая информация
pm3 --> hf mf autopwn             # подбор ключей + полный дамп (Mifare Classic)
pm3 --> hf mf dump                # сохранить дамп в файл
pm3 --> hf mf chk --1k -f keys.lst   # подбор по словарю ключей
pm3 --> hf mf rdbl --blk 4 -k FFFFFFFFFFFF   # читать блок с известным ключом
pm3 --> hf mf wrbl --blk 4 -k FFFFFFFFFFFF -d 00112233   # запись (осторожно)
pm3 --> hf mfu dump               # Ultralight/NTAG
# --- Flipper Zero ---
# 125 kHz → Read; NFC → Read; затем NFC → Saved → Emulate
```

## Подбор ключей Mifare Classic

Ключи по умолчанию: `FFFFFFFFFFFF`, `A0A1A2A3A4A5`, `000000000000`, `D3F7D3F7D3F7`. `autopwn` использует известные уязвимости (nested, darkside) и словарь.

```bash
# словарь ключей
printf 'FFFFFFFFFFFF\nA0A1A2A3A4A5\n000000000000\nD3F7D3F7D3F7\n' > keys.lst
pm3 --> hf mf chk --1k -f keys.lst
pm3 --> hf mf nested --1k --blk 0 -a -k FFFFFFFFFFFF -t   # nested-атака
```

Без ключей полный дамп Mifare Classic получить нельзя — начинайте с подбора.

## Каналы сокрытия и клонирование

- **Неиспользуемые блоки/сектора:** система читает лишь 0–4, а данные — в секторе 15.
- **NDEF-записи:** под видом URI/текста лежат данные; читайте `hf mfu ndefread`.
- **Trailer/access bits:** нестандартные права (все ключи открыты) — признак правки.
- **Manufacturer block:** на Magic-картах перезаписывается — проверка клонов.
- **Клонирование:** Magic-карта (UID-перезаписываемая) + запись UID/блоков → копия метки доступа.

```bash
pm3 --> hf mfu ndefread            # прочитать NDEF-записи
pm3 --> hf mf cload -f dump.bin    # загрузить дамп на Magic-карту
pm3 --> hf mf restore              # восстановить дамп
```

## Детект подделки

| Признак | Что означает |
|---------|--------------|
| UID ≠ manufacturer block | клон/правка |
| Все ключи `FF..`/открытый доступ | не настроена защита или правка |
| Данные вне ожидаемого диапазона | сокрытие |
| Два объекта с одним UID | клонирование |
| NTAG с паролем/настроенной конфигурацией | возможна защита данных |

## Разобранные примеры

**1. Скрытый сектор.** Mifare Classic: `autopwn` → дамп; в секторе 15 ASCII-строка → декод → флаг.

**2. NDEF.** NTAG: `hf mfu ndefread` показывает URI с данными; декодируем.

**3. Клон.** Даны две метки с одинаковым UID; manufacturer block различается → одна — клон.

## Частые ошибки и отладка

- **Читать только UID** — пропустите пользовательскую память.
- **Не подбирать ключи** Mifare Classic — без них нет дампа.
- **Игнорировать trailer/manufacturer.**
- **Путать 125 кГц (EM4100) и 13.56 МГц (Mifare/NTAG)** — разные антенны/режимы.
- **Отладка:** если `autopwn` не находит ключи — добавьте словарь; если чтение нестабильно — держите метку ровно, питание антенны.

## Что делать дальше / дерево решений

1. `hf search`/`nfc-list` → тип метки.
2. Mifare Classic → `autopwn`/`chk` → дамп.
3. NTAG/Ultralight → `hf mfu dump` + `ndefread`.
4. Просмотрите все блоки на ASCII/hex/структуры.
5. Клон/эмуляция → Magic-карта + `cload`/`restore`.

## Шпаргалка: чтение метки

```bash
# определить тип
pm3 --> hf search
# Mifare Classic: ключи + дамп
printf 'FFFFFFFFFFFF\nA0A1A2A3A4A5\n' > keys.lst
pm3 --> hf mf chk --1k -f keys.lst
pm3 --> hf mf autopwn
pm3 --> hf mf dump
# NTAG/Ultralight: дамп + NDEF
pm3 --> hf mfu dump
pm3 --> hf mfu ndefread
```

Рабочий процесс: определите тип метки, получите дамп (для Classic — сначала ключи), затем просмотрите **все** блоки на ASCII/hex/структуры — данные обычно в неиспользуемых секторах. Для NTAG проверьте NDEF-записи. Если ключи не подбираются — расширьте словарь и попробуйте nested-атаку. В отчёте фиксируйте: тип метки, найденный ключ, блок/сектор с данными и метод декодирования.
