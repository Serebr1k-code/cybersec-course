## Формат PNG: чанки как строительные блоки

PNG состоит из **чанков** — блоков с 4-байтовой длиной, 4-байтовым типом, данными и 4-байтовым CRC. Файл начинается с сигнатуры `89 50 4E 47 0D 0A 1A 0A`, затем идут чанки. Обязательные: `IHDR` (заголовок), один или несколько `IDAT` (данные изображения), `IEND` (конец). Дополнительные: `PLTE` (палитра), `tEXt`/`zTXt`/`iTXt` (текст), `tRNS` (прозрачность), `gAMA`, `bKGD`, `pHYs` и другие.

Понимание структуры чанков — основа разбора PNG. Каждый чанк можно прочитать, декодировать и проверить; аномалии (лишние чанки, неверный CRC, странные текстовые поля) — потенциальные каналы.

## Разбор чанков вручную

```python
import struct, zlib
raw = open('image.png','rb').read()
assert raw[:8] == b'\x89PNG\r\n\x1a\n'
i = 8
while i < len(raw):
    ln = struct.unpack('>I', raw[i:i+4])[0]
    typ = raw[i+4:i+8].decode('latin1')
    data = raw[i+8:i+8+ln]
    crc = struct.unpack('>I', raw[i+8+ln:i+12+ln])[0]
    ok = (zlib.crc32(raw[i+4:i+8+ln]) & 0xffffffff) == crc
    print(f'{typ} len={ln} crc_ok={ok}')
    if typ in ('tEXt','iTXt'):
        print('  text:', data[:100])
    i += 12 + ln
```

`pngcheck -v` делает то же самое и дополнительно проверяет целостность.

## Текстовые чанки: tEXt, zTXt, iTXt

- **`tEXt`** — ключ и значение (Latin-1), разделены нулевым байтом.
- **`zTXt`** — сжатое значение (zlib).
- **`iTXt`** — UTF-8, поддерживает язык и сжатие.

Сюда часто кладут флаг, пароль или base64. `exiftool` и `pngcheck` их показывают.

```bash
exiftool image.png | grep -iE 'comment|description|title'
python3 -c "
import struct,zlib
raw=open('image.png','rb').read(); i=8
while i<len(raw):
    ln=struct.unpack('>I',raw[i:i+4])[0]; t=raw[i+4:i+8]
    if t in (b'tEXt',b'iTXt'): print(t, raw[i+8:i+8+ln])
    if t==b'zTXt':
        d=raw[i+8:i+8+ln]; print('zTXt', zlib.decompress(d.split(b'\x00',1)[1]))
    i+=12+ln
"
```

## CRC-аномалии

CRC каждого чанка — контрольная сумма. Аномалии (неверный CRC, но работоспособный файл) — намёк: возможно, данные «спрятаны» в самом CRC или в подменённом чанке. `pngcheck -t` проверяет CRC и сообщает о повреждениях. Намеренно повреждённый CRC тоже может быть каналом (данные в разнице).

## IDAT и сжатие

`IDAT` содержит zlib-поток (см. отдельный урок про PNG-глубину). Быстрая проверка: распакуйте IDAT и поищите сигнатуры.

```bash
python3 -c "
import struct,zlib
raw=open('image.png','rb').read(); i=8; idat=b''
while i<len(raw):
    ln=struct.unpack('>I',raw[i:i+4])[0]; t=raw[i+4:i+8]
    if t==b'IDAT': idat+=raw[i+8:i+8+ln]
    i+=12+ln
print(zlib.decompress(idat)[:64])
"
```

## Лишние и нестандартные чанки

Признаки закладки: чанки с неизвестным типом, чанки после `IEND` (не должны существовать), дублирующиеся `IHDR`, чанки нулевой длины, кастомные типы (`prIV`, `stEg`). Просматривайте список чанков и ищите «не по спецификации».

## Инструменты

- **`pngcheck`** — структура, CRC, размеры (`-v`, `-t`).
- **`exiftool`** — текстовые чанки.
- **`python3` + `struct`/`zlib`** — полный контроль.
- **`binwalk`** — вложенное/дописанное.
- **`pngcrush`/`optipng`** — пересжатие (осторожно).

## Разобранный пример

```bash
$ pngcheck -v task.png
  chunk tEXt at offset 0x00029, length 32, keyword: Comment
  chunk IDAT at offset 0x00051, length 4096
  chunk IEND at offset 0x001059
$ exiftool task.png | grep -i comment
Comment : ZmxhZ3twbmdfdGV4dH0=
$ echo ZmxhZ3twbmdfdGV4dH0= | base64 -d
flag{png_text}
```

Маршрут: `pngcheck` → увидели `tEXt` → `exiftool`/ручной разбор → base64 → флаг.

## Частые ошибки и подводные камни

- **Открыть и пересохранить** — чанки перестроятся.
- **Смотреть только IDAT** — флаг может быть в `tEXt`/`iTXt`.
- **Игнорировать CRC** — аномалия может быть каналом.
- **Не проверять чанки после `IEND`** — там может быть дописанное.
- **Забыть про `zTXt`** — сжатый текст требует распаковки.
- **Путать чанки и метаданные** — `tEXt` это чанк, а не EXIF.

## Итог

Разбор чанков PNG — фундаментальный навык: он даёт доступ к тексту, палитре, IDAT и аномалиям. Начните с `pngcheck -v` и `exiftool`, затем ручной разбор при необходимости. Текстовые чанки и нестандартные типы — частые места закладок.

## Сравнение текстовых чанков PNG

| Чанк | Кодировка | Сжатие | Особенность |
|---|---|---|---|
| `tEXt` | Latin-1 | нет | ключ\0значение |
| `zTXt` | Latin-1 | zlib | ключ\0метод\0сжатые данные |
| `iTXt` | UTF-8 | опц. | язык, переведённый ключ |

`iTXt` — самый гибкий (UTF-8 и сжатие), `zTXt` — сжатый `tEXt`, `tEXt` — простой. Все три читаются `exiftool`, но ручной разбор через `struct`/`zlib` надёжнее для нестандартных случаев.

## Аномалии структуры и их значение

- **Чанки после `IEND`** — не по спецификации, значит дописанное/канал.
- **Неверный CRC** — либо повреждение, либо намеренная аномалия (данные в CRC).
- **Дублирующиеся критичные чанки** (`IHDR`, `PLTE`) — нарушение спецификации.
- **Неизвестные типы** (`prIV`, `stEg`, кастомные) — прямые закладки.
- **Нулевая длина** у информативного чанка — странно.

`pngcheck -v` показывает всё это; просматривайте вывод на предмет «не по спецификации».

## Практический чек-лист PNG-чанков

1. `pngcheck -v` — список чанков, CRC, размеры.
2. `exiftool` — текстовые поля.
3. Ручной разбор — `tEXt`/`zTXt`/`iTXt`.
4. Проверить чанки после `IEND`.
5. Распаковать IDAT и поискать сигнатуры.
6. Аномальные типы/CRC — отдельно.
7. `binwalk` — вложенные файлы.

## Инструменты глубоко

- **`pngcheck -v -t`**: `-v` подробно, `-t` проверка CRC.
- **`python3` + `struct`/`zlib`**: полный доступ к чанкам.
- **`exiftool`**: быстрый просмотр текстовых полей.
- **`pngcrush`/`optipng`**: пересжатие — иногда выявляет «лишнее» (сравнение размеров).
- **`binwalk`**: вложенное/дописанное.

Понимание чанков превращает «чёрный ящик» PNG в читаемую структуру, где каждая аномалия — потенциальная подсказка.

## Полный скрипт разбора чанков PNG

Собранный инструмент, который печатает все чанки, декодирует текст и проверяет CRC:

```python
import struct, zlib, sys
raw = open(sys.argv[1], 'rb').read()
if raw[:8] != b'\x89PNG\r\n\x1a\n':
    print('not a PNG'); sys.exit(1)
i = 8
while i < len(raw):
    ln = struct.unpack('>I', raw[i:i+4])[0]
    typ = raw[i+4:i+8].decode('latin1')
    data = raw[i+8:i+8+ln]
    crc_ok = (zlib.crc32(raw[i+4:i+8+ln]) & 0xffffffff) == struct.unpack('>I', raw[i+8+ln:i+12+ln])[0]
    print(f'{typ:6} len={ln:6} crc={"ok" if crc_ok else "BAD"}')
    if typ == b'tEXt':
        k, v = data.split(b'\x00', 1); print('   ', k.decode('latin1'), '=', v.decode('latin1', 'replace'))
    elif typ == b'zTXt':
        k, rest = data.split(b'\x00', 1); print('   ', k.decode(), '=', zlib.decompress(rest[1:]).decode('latin1', 'replace'))
    elif typ == b'iTXt':
        print('   iTXt:', data[:120])
    i += 12 + ln
```

Этот скрипт — ваш основной инструмент для PNG: он показывает и структуру, и текст, и аномалии CRC в одном проходе.

## Аномалии и что они означают

- **BAD CRC** — либо файл повреждён, либо CRC намеренно изменён (данные в самом CRC).
- **Чанк после IEND** — дописанное/канал.
- **Неизвестный тип** (не из стандартного набора) — прямая закладка.
- **Дубликат IHDR/PLTE** — нарушение спецификации.
- **Странная длина** (нулевая или огромная) — аномалия.

Каждая из этих аномалий — повод посмотреть внимательнее; вместе они часто указывают на конкретный канал.

## Связь чанков и других каналов

PNG-стеганография многослойна: чанки (`tEXt`/`iTXt`), IDAT-поток, пиксели (LSB), хвост после `IEND`, аномалии CRC. Полный разбор проверяет все пять слоёв. Инструменты автоматизируют часть (например, `zsteg` — пиксели), но структурные каналы требуют ручного прохода скриптом выше.

## Инструменты и их роль

- **`pngcheck -v -t`** — быстрый обзор и проверка CRC.
- **Python-скрипт** — полный контроль.
- **`exiftool`** — текстовые поля «из коробки».
- **`binwalk`** — вложенное и дописанное.

Комбинация «pngcheck → скрипт → exiftool → binwalk» закрывает почти все PNG-задачи, связанные со структурой.

## Что делать дальше / решение

- `pngcheck -v` — список чанков и CRC.
- `exiftool` + ручной разбор — текст и метаданные.
- Распаковать IDAT — данные в потоке.
- Проверить чанки после `IEND` — дописанное.
- Аномальные типы/CRC — отдельный канал.
