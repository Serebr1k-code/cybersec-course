## Вопрос, с которого всё начинается

У тебя есть `chunks.png`. Никаких признаков LSB-стего, картинка выглядит как случайный шум. Но файл на 12 КБ, а картинка всего 64×64 — куда уходит объём? Может быть, внутри есть что-то помимо пикселей?

PNG — это не «просто картинка», а **контейнер**, собранный из блоков, которые называются **чанки**. В одних лежат пиксели, в других — параметры, а в третьих могут быть спрятаны данные. Разберём `chunks.png` на уровне байтов.

## Наш пример: файл chunks.png

Каждый PNG начинается с **сигнатуры** — восьми фиксированных байтов, по которым формат узнаётся:

```text
89 50 4E 47 0D 0A 1A 0A
```

Это `\x89PNG\r\n\x1a\n`. После сигнатуры файл состоит из чанков, идущих друг за другом до чанка `IEND` (конец). Знание этой структуры — ключ к разбору.

## Шаг 1: разбираем чанки вручную

Каждый чанк устроен одинаково: 4 байта длины, 4 байта типа, сами данные и 4 байта **CRC** (контрольной суммы). Пишем короткий скрипт, который проходит по файлу и печатает чанки:

```python
import struct
d = open('chunks.png', 'rb').read()
print('signature ok:', d[:8] == b'\x89PNG\r\n\x1a\n')
off = 8
while off < len(d):
    ln = struct.unpack('>I', d[off:off+4])[0]
    typ = d[off+4:off+8].decode('latin1')
    data = d[off+8:off+8+ln]
    print(f'{typ:4s} len={ln}', repr(data[:40]) if typ in ('tEXt','zTXt','iTXt') else '')
    off += 12 + ln
    if typ == 'IEND':
        break
```

Запускаем:

```text
signature ok: True
IHDR len=13 
tEXt len=28 b'Comment\x00flag{chunk5_4r3_fun}'
tEXt len=17 b'Author\x00ctf-author'
IDAT len=12363 
IEND len=0
```

Вот и ответ. Чанки `IHDR` (заголовок с размерами) и `IDAT` (пиксели) — обычные, а между ними два **текстовых** чанка `tEXt`, и в первом лежит `flag{chunk5_4r3_fun}`.

## Шаг 2: читаем через exiftool

Текстовые чанки понимает `exiftool` — он показывает их как обычные метаданные:

```bash
exiftool chunks.png
```

```text
File Type                       : PNG
Image Width                     : 64
Image Height                    : 64
Bit Depth                       : 8
Color Type                      : RGB
Comment                         : flag{chunk5_4r3_fun}
Author                          : ctf-author
```

Так флаг извлекается одной командой — но только если знать, что его стоит искать.

## Шаг 3: текстовые чанки — три вида

Текст в PNG хранится в трёх типах чанков:

- **`tEXt`** — текст в открытом виде, пара «ключ\0значение».
- **`zTXt`** — тот же текст, но **сжатый** (через zlib).
- **`iTXt`** — текст в UTF-8, может быть сжат.

`tEXt` виден в hex сразу, а `zTXt`/`iTXt` нужно распаковать:

```python
import zlib
# для zTXt: ключ\0 метод\0 сжатые_данные
data = ...  # содержимое чанка
key, rest = data.split(b'\x00', 1)
method, compressed = rest[0:1], rest[1:]
print(zlib.decompress(compressed))
```

Поэтому если `exiftool` показывает текст как «кучу символов» — вероятно, это `zTXt` и его надо распаковать.

## Шаг 4: IDAT и сжатие

Пиксели лежат в чанке `IDAT`, но не «как есть», а **сжатыми** алгоритмом Deflate. Иногда данные прячут прямо в потоке сжатия (см. `stego-png-deflate`). Распаковать IDAT можно через `zlib`:

```python
import zlib
# собрать все IDAT, затем
raw = zlib.decompress(b''.join(idat_parts))
```

`raw` — это уже отфильтрованные строки пикселей; для полноценной картинки их надо ещё развернуть с учётом фильтров, но для поиска текста в сжатом потоке хватает и сырых данных.

## Шаг 5: CRC-аномалии

У каждого чанка есть **CRC** — контрольная сумма, которой проверяется целостность. Если файл «сломанный» или в него вписали данные вручную, CRC не сойдётся. Проверяют так:

```python
import zlib, struct
def check_crc(chunk_type, data, crc):
    return zlib.crc32(chunk_type + data) & 0xffffffff == crc
```

Несовпадение CRC — сигнал, что чанк подделан или повреждён. Часто именно там и лежит секрет. Бывает и обратное: злоумышленник специально портит CRC, чтобы стандартные парсеры пропустили чанк.

## Аномалии структуры и что они означают

Помимо текста, о скрытых данных говорят **аномалии** структуры. Нормальный PNG содержит чанки в строгом порядке: сначала `IHDR`, затем опциональные (палитра, метаданные), затем `IDAT` и в конце `IEND`. Если порядок нарушен, чанк повторяется, или между `IDAT` и `IEND` появляется посторонний блок — это повод присмотреться.

Частые аномалии и их значение: **лишний `IDAT`** может нести данные, не относящиеся к картинке; **неизвестный тип чанка** (например, четыре случайные буквы) часто создают вручную для хранения секрета; **чанк после `IEND`** — данные, которые стандартный парсер вообще игнорирует, но которые видны при ручном чтении. Отдельный случай — **неверная длина**: она не совпадает с реальным объёмом данных, и парсер либо падает, либо пропускает хвост.

Полезно помнить, что часть инструментов молча игнорирует битые чанки. Поэтому если автоматика «не находит ничего», а файл выглядит странно, ручной разбор по байтам часто решает задачу.

## Полный скрипт-разборщик

Соберём всё вместе: скрипт печатает каждый чанк, его длину, а для текстовых — содержимое, и отдельно проверяет CRC:

```python
import struct, zlib
d = open('chunks.png', 'rb').read()
off = 8
while off < len(d):
    ln = struct.unpack('>I', d[off:off+4])[0]
    typ = d[off+4:off+8]
    data = d[off+8:off+8+ln]
    crc = struct.unpack('>I', d[off+8+ln:off+12+ln])[0]
    ok = (zlib.crc32(typ + data) & 0xffffffff) == crc
    name = typ.decode('latin1', 'replace')
    if name in ('tEXt', 'zTXt', 'iTXt'):
        print(name, 'CRC', ok, data[:60])
    elif not ok:
        print(name, 'BAD CRC len', ln)
    off += 12 + ln
    if typ == b'IEND':
        break
```

Такой скрипт заменяет десяток отдельных утилит и сразу показывает и текст, и подозрительные чанки. Его удобно держать под рукой как «первый проход» по любому подозрительному PNG.

## Полный прогон: от файла к флагу

```text
chunks.png
  → сигнатура 89 50 4E 47 0D 0A 1A 0A
  → разбор чанков → IHDR, tEXt×2, IDAT, IEND
  → tEXt Comment → flag{chunk5_4r3_fun}
  → exiftool подтверждает
  → при «сломанности» — проверка CRC
```

## Если не сработало

- **Текст выглядит как мусор** — это `zTXt`/`iTXt`, распакуйте через `zlib.decompress`.
- **Стандартные тулзы молчат** — смотрите байты вручную: лишний чанк мог быть добавлен с неизвестным типом.
- **Картинка не открывается** — проверьте CRC: возможно, чанк повреждён намеренно.
- **Есть подозрительно большой IDAT** — распакуйте его и поищите сигнатуры (`flag`, `PK`, `%PDF`).

## Что мы теперь знаем

- **PNG** — это контейнер из **чанков**, а не монолитный файл.
- Каждый чанк: длина, тип, данные, **CRC**.
- **`tEXt`/`zTXt`/`iTXt`** хранят текст (открыто, сжато, UTF-8).
- `exiftool` читает текстовые чанки как метаданные.
- Пиксели лежат в `IDAT`, сжатые **Deflate**.
- Несовпадение **CRC** — признак подделки чанка.
