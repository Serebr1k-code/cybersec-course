## Вопрос, с которого всё начинается
Ты получил файл без расширения. `file` говорит «data». Внутри что-то есть, но
что именно и где — непонятно. **binwalk** сканирует файл на сигнатуры (магии)
известных форматов и показывает, что и по какому смещению встроено. Это первый
инструмент, когда файл — «матрёшка».

## Наш пример
Возьмём `firmware.bin` — кусок данных, в который по смещению 32 встроен gzip.
Найдём его и распакуем.

## Шаг 1: сигнатурное сканирование
binwalk ищет в файле байтовые «магии»: `\x89PNG`, `\x1f\x8b` (gzip), `PK\x03\x04`
(zip), `\xff\xd8\xff` (JPEG), `7z\xbc\xaf` (7z) и тысячи других. Для каждой
находки печатает смещение и описание:

```
$ binwalk firmware.bin
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             (data)
32            0x20            gzip compressed data, ...
```

## Шаг 2: распаковка встроенного
```
$ binwalk -e firmware.bin
$ ls _firmware.bin.extracted/
20  ...
```

binwalk извлекает найденные объекты в каталог `_<файл>.extracted`. Для gzip —
распаковывает.

## Шаг 3: карта энтропии
`binwalk -E firmware.bin` строит график энтропии по блокам. Высокая энтропия
(~1.0) = сжатые/шифрованные данные; скачки — границы встроенных файлов. Это
помогает понять структуру даже без сигнатур.

## Шаг 4: точное извлечение
- `binwalk --dd='gzip:gz' file` — извлечь только gzip.
- `binwalk -M file` — рекурсивно распаковать (matryoshka).
- `binwalk -y 'png' file` — фильтр по типу.
- `dd if=file bs=1 skip=32 | gunzip` — вручную по найденному смещению.

## Шаг 5: извлечение вручную
```python
import gzip
d = open('firmware.bin','rb').read()
i = d.find(b'\x1f\x8b')
print(gzip.decompress(d[i:]).decode())
```

Вывод:

```
nto{binwalk_signature_offset}
```

## Шаг 6: ограничения
- Сигнатуры могут давать **ложные срабатывания** (магия встречается случайно).
- Сжатые/шифрованные вложения без магии binwalk не найдёт — нужна энтропия и
  ручной анализ.
- Рекурсивная распаковка может «зациклиться» на вложенных архивах — следи за
  глубиной.

## binwalk глубже: сигнатуры, энтропия, точность

binwalk ищет в файле сигнатуры известных форматов (magic bytes) и показывает их смещения. Сигнатуры описаны в `magic`-файлах; их можно расширять своими. Основные режимы: `binwalk file` (обзор), `binwalk -e file` (извлечение), `binwalk -E file` (энтропия), `binwalk -Me file` (рекурсивно).

```bash
binwalk image.png
binwalk -E image.png          # график энтропии
binwalk -e image.png          # извлечь в _image.png.extracted/
binwalk -Me image.png         # рекурсивно
```

Энтропия — ключевой инструмент. Сжатые/зашифрованные данные имеют высокую энтропию (близко к 8 битам/байт), текстовые — низкую. График `-E` показывает, где начинается сжатый блок: резкий скачок энтропии — граница встроенного архива. Это помогает, когда сигнатура нестандартная.

Ограничения: binwalk ищет по сигнатурам, поэтому пропускает форматы без чёткой сигнатуры или модифицированные; не всегда правильно определяет длину блока (для форматов без явного размера); может давать ложные срабатывания на случайных байтах. Поэтому вывод binwalk всегда проверяют вручную (`xxd` по смещению, `file`).

## Практика: извлечение и ручная проверка

Когда `binwalk -e` не справляется, режут вручную. Определи смещение и «длину» (следующая сигнатура или конец файла), вырежи и проверь.

```bash
binwalk image.png                    # смещение встроенного
dd if=image.png of=part.bin bs=1 skip=1024
file part.bin && unsquashfs part.bin  # или unzip/gunzip по формату
```

Часто вырезают «с запасом» (до конца файла) и дают распаковщику самому определить конец (`gunzip -c`, `unzip`, `xz -d` игнорируют хвост). Так не теряешь байты из-за неверной длины.

Инструменты в дополнение: `foremost`, `scalpel` (carving по сигнатурам), `dd`, `file`, `xxd`, `binwalk -D` (свой тип). Для энтропии — `binwalk -E` или скрипт на Python, считающий энтропию по окнам. Типичные ошибки: слепо доверять `-e` (иногда извлекает мусор); не проверять вырезанный блок `file`; игнорировать энтропию (пропустить зашифрованный блок).

## Magic-файлы и свои сигнатуры

binwalk использует базу сигнатур (libmagic-совместимые описания). Сигнатура — это правило: байтовый шаблон по смещению и описание. Например, SquashFS определяется по `hsqs` в начале, gzip — по `\x1f\x8b`, ZIP — по `PK\x03\x04`.

```bash
# посмотреть встроенные сигнатуры
binwalk --list
# свои сигнатуры в файле
binwalk -C custom.sig file
```

Свой magic-файл позволяет искать нестандартные форматы (проприетарные прошивки, кастомные контейнеры). Формат описания: `0 string/magic <bytes> <description>`. Это полезно, когда задача использует самодельный формат и стандартные сигнатуры не срабатывают.

Практика: если binwalk ничего не находит, но файл явно содержит данные, попробуй написать сигнатуру под известную «магию» задачи (например, ASCII-строку `NTO{` или нестандартный заголовок). Так ты найдёшь данные, которые стандартный binwalk пропустил.

## Энтропия подробнее

Энтропия измеряет «случайность» данных: 0 бит/байт — всё одинаково (например, нули), 8 бит/байт — равномерный шум (сжатое/зашифрованное). График `binwalk -E` показывает энтропию по окнам и позволяет увидеть границы блоков.

```bash
binwalk -E firmware.bin
# резкий рост энтропии -> начало сжатого/зашифрованного блока
```

Как читать график: плато низкой энтропии — текстовые/структурированные данные; плато высокой — сжатие/шифрование; резкие переходы — границы встроенных файлов. Например, если после низкоэнтропийного заголовка начинается плато 7.9 — там сжатый архив, и его смещение можно вырезать.

Практика: энтропия не говорит, ЧТО за формат, но говорит, ГДЕ искать. Комбинируй её с сигнатурами: сначала найди границы по энтропии, затем определи формат (`file`, `binwalk`) и распакуй. Если энтропия высокая, но сигнатуры нет — возможно, шифрование, и нужен ключ.

## Carving и восстановление файлов

Когда `binwalk -e` не справляется, используют carving — восстановление файлов по сигнатурам и структуре. Инструменты: `foremost` (по конфигу с сигнатурами), `scalpel` (быстрее, настраиваемый), `photorec` (для медиа), `dd` (ручное вырезание).

```bash
foremost -i disk.img -o out/        # восстановить файлы по сигнатурам
scalpel disk.img -o out/            # быстрее foremost
dd if=disk.img of=part.bin bs=1 skip=1048576 count=524288
```

Carving полезен, когда файлы «плавают» в потоке без таблицы размещения (например, в дампе памяти или образе диска). Для форматов с явной длиной (PNG, JPEG, ZIP) восстановление надёжнее; для форматов без длины (некоторые raw-форматы) — менее.

Практика: сначала попробуй `binwalk -e` (он умнее для встроенных форматов), затем `foremost`/`scalpel` (для «плавающих» файлов), затем ручное `dd` по смещениям. Проверяй каждый вырезанный блок `file` и, если нужно, открывай.

## Итог по binwalk

binwalk — основной инструмент поиска встроенных форматов: сигнатуры, энтропия, извлечение. Сильные стороны — быстрое обнаружение известных форматов и карта энтропии. Слабые — пропускает нестандартные форматы и иногда ошибается с длиной. Поэтому binwalk дополняют: своими magic-файлами, `foremost`/`scalpel` (carving), ручным `dd` и проверкой `file`. Комбинация «сигнатуры + энтропия + ручная проверка» закрывает большинство задач.

## Разбор примера: образ прошивки

Разберём `firmware.bin` с binwalk. Шаг первый — обзор: `binwalk firmware.bin` показывает сигнатуры (например, SquashFS по смещению 24). Шаг второй — энтропия: `binwalk -E firmware.bin` показывает, где сжатые блоки. Шаг третий — извлечение: `binwalk -e firmware.bin` распаковывает в `_firmware.bin.extracted/`.

```bash
binwalk firmware.bin
binwalk -E firmware.bin
binwalk -e firmware.bin
ls _firmware.bin.extracted/
```

Если `-e` не сработал (нестандартное сжатие), режем вручную: `dd if=firmware.bin of=root.sqfs bs=1 skip=24`, затем `unsquashfs root.sqfs`. Дальше — разбор ФС: `etc/passwd`, `etc/init.d`, веб-корень, приватные ключи.

Частый сценарий — вложенность: внутри SquashFS лежит ещё один архив или ФС. `binwalk -Me` извлекает рекурсивно; если не помогает, распаковывай вручную на каждом уровне.

## Ограничения и обходы

binwalk пропускает форматы без чёткой сигнатуры (проприетарные прошивки, кастомные контейнеры), иногда неверно определяет длину блока, даёт ложные срабатывания на случайных байтах. Обходы: свои magic-файлы (`binwalk -C custom.sig`), энтропия для поиска границ, `foremost`/`scalpel` для carving, ручное `dd` по смещениям.

```bash
binwalk --list | head            # встроенные сигнатуры
foremost -i firmware.bin -o out/ # carving
dd if=firmware.bin of=part.bin bs=1 skip=<off> count=<len>
```

Практика: комбинируй методы. Сначала binwalk (быстро, известные форматы), затем энтропия (границы), затем foremost (плавающие файлы), затем ручное dd (точное). Проверяй каждый результат `file`.

## Итог по binwalk

binwalk — первый инструмент при разборе образов и контейнеров: сигнатуры, энтропия, извлечение, рекурсия. Дополняй его своими сигнатурами, carving-инструментами и ручным анализом. Помни: binwalk показывает смещения и типы, но окончательное решение о том, что за данные, принимаешь ты — через `file`, `xxd` и проверку структуры.

## Финальные замечания по binwalk

binwalk — инструмент обнаружения и первого извлечения, а не «кнопка ответа». Его вывод всегда проверяй: `file` по смещению, `xxd` для структуры, ручная распаковка, если `-e` не сработал. Комбинируй с энтропией (границы), `foremost`/`scalpel` (carving) и своими magic-сигнатурами. Тогда даже нестандартные образы разбираются полностью.

## Ещё раз о проверке результата

После любого `binwalk -e` всегда проверяй извлечённое: `ls _file.extracted/`, `file *`. Если извлеклось несколько файлов — определи, какой из них осмысленный. Если ничего не извлеклось, но сигнатуры были — вырезай вручную `dd` и пробуй распаковщик по формату. Если и это не помогло — проверь энтропию: возможно, данные зашифрованы и нужен ключ.

## Что мы теперь знаем
- binwalk сканирует файл на сигнатуры известных форматов и показывает смещения.
- `-e` извлекает встроенное, `-E` строит карту энтропии.
- `-M` рекурсивно распаковывает «матрёшку».
- Ложные срабатывания и «безмагические» данные — главные ограничения.
