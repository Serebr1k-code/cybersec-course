Водяной знак — это стеганографическая метка, встроенная так, чтобы служить конкретной цели: доказать авторство (устойчивый), поймать модификацию (хрупкий) или отследить утечку (fingerprint). В отличие от «просто спрятанного сообщения», водяной знак проектируется под модель атак: устойчивый переживает JPEG-сжатие, кадрирование и масштабирование; хрупкий наоборот ломается при малейшем изменении и служит детектором правок. В CTF это обычно означает, что данные встроены в **частотную область** (DCT/DWT/DFT), и LSB-скрипты по пикселям ничего не найдут.

## Устойчивые vs хрупкие

| Свойство | Устойчивый | Хрупкий |
|---|---|---|
| Цель | доказать авторство | детектировать правки |
| Переживает сжатие | да | нет |
| Переживает кадрирование | часто | нет |
| Область | DCT/DWT/DFT | LSB/пространственная |
| Ёмкость | низкая | выше |

## LSB-водяной знак (база)

Простейший водяной знак — повторяющийся паттерн в младших битах. Он хрупкий, но демонстрирует идею.

```python
from PIL import Image
import numpy as np
im=np.array(Image.open('cover.png').convert('RGB'))
wm='WATERMARK'
bits=''.join(f'{ord(c):08b}' for c in wm)*100   # повторяем для устойчивости
flat=im.reshape(-1)
for i,b in enumerate(bits[:flat.size]):
    flat[i]=(flat[i]&0xFE)|int(b)
Image.fromarray(im).save('wm.png')
```

## DCT-водяной знак (устойчивый)

Данные встраиваются в среднечастотные DCT-коэффициенты 8×8-блоков — там, где изменения незаметны глазу, но переживают сжатие.

```bash
# инструменты для DCT-водяных знаков
# - стего в JPEG (jsteg/F5/outguess — см. урок stego-jpeg-dct)
# - специализированные: watermark-утилиты, zsteg по DCT
python3 -c "print('используйте jsteg/F5/outguess для JPEG')"
# проверить блоки DCT
jpegtran -v -crop 16x16+0+0 cover.jpg > /dev/null
```

Типовой приём: сравнить коэффициенты двух версий (оригинал vs помеченная) и найти стабильно изменённые позиции — там и лежит метка.

## DWT/DFT-водяные знаки

- **DWT (вейвлеты):** данные прячут в низкочастотных (LL) или среднечастотных субдиапазонах; устойчиво к сжатию.
- **DFT (Фурье):** метка в магнитуде/фазе спектра; устойчиво к сдвигу и масштабу.

```python
import pywt, numpy as np
from PIL import Image
im=np.array(Image.open('cover.png').convert('L')).astype(float)
coeffs=pywt.dwt2(im,'haar'); cA,(cH,cV,cD)=coeffs
cA[0,0] += 42     # встроить метку в LL
out=pywt.idwt2((cA,(cH,cV,cD)),'haar')
Image.fromarray(np.clip(out,0,255).astype('uint8')).save('dwt_wm.png')
```

## Fingerprinting

Fingerprint — уникальная метка на каждую копию (для отслеживания утечек). Отличается от обычного водяного знака тем, что копий много и метка у каждой своя; задача — извлечь ID.

```bash
# часто fingerprint — это ID в устойчивом коде (например, повторяющийся паттерн)
# искать периодичность в LSB-плоскостях
zsteg -a suspect.png | grep -iE 'b[0-9]'
```

## Разобранный пример

CTF: `marked.jpg` — «найдите скрытую метку».

```bash
$ zsteg -a marked.jpg
b1,rgb,lsb,xy .. text: "\x00\x00\x00..."   # мусор — LSB пуст

$ exiftool -Comment marked.jpg
Comment : watermark-id:7

$ python3 - <<'PY'
# проверить DCT: сравнить с эталоном
# в задачах часто дают cover и marked
PY
```

Вывод: LSB не дал результата → метка в метаданных или в DCT. Инструменты DCT-анализа (jsteg/outguess) плюс сравнение с cover-версией раскрывают позицию.

## Краевые случаи и подводные камни

- **Re-encode убивает хрупкий знак:** если файл прошёл через редактор, LSB-метка исчезнет — ищи в устойчивых областях.
- **Ёмкость ограничена:** устойчивые знаки вмещают десятки-сотни бит, а не килобайты.
- **Нужен cover для сравнения:** при наличии оригинала diff-анализ резко упрощает задачу.
- **Цветовые пространства:** DCT/DWT считают в Y (яркость), а не в RGB — учитывай при извлечении.
- **Ложные срабатывания:** детекторы водяных знаков дают false positives на сильно текстурированных изображениях.

## Что дальше / решение

Пайплайн: сначала `exiftool` (часто метка в метаданных) → `zsteg`/StegSolve (LSB, хрупкий знак) → при наличии cover сделать diff → `jsteg`/`outguess` и DCT-анализ → DWT/DFT-проверка через `pywt`/спектр. Помни главное: если данные проектировались как устойчивый водяной знак, они в частотной области, и пространственные LSB-инструменты их не увидят.

## Справочные таблицы

| Область | Устойчивость | Ёмкость | Инструмент |
|---|---|---|---|
| LSB | низкая | высокая | zsteg, StegSolve |
| DCT | средняя | средняя | jsteg, F5, outguess |
| DWT | высокая | средняя | pywt |
| DFT | высокая | низкая | спектральный анализ |
| Метаданные | низкая | высокая | exiftool |

| Тип | Назначение | Детект |
|---|---|---|
| Robust | авторство | корреляция с эталоном |
| Fragile | детект правок | локальный сбой |
| Fingerprint | отслеживание копий | извлечение ID |

## Математика извлечения: корреляция и порог

Устойчивый водяной знак извлекают не «чтением битов», а **корреляцией** известного паттерна с сигналом. Если паттерн (псевдослучайная последовательность, PRN) известен или задан ключом, его коррелируют с коэффициентами и по превышению порога решают «бит 1 / бит 0».

```python
import numpy as np
# PRN-паттерн из ключа
rng=np.random.default_rng(seed=12345)
pattern=rng.choice([-1,1], size=1000)
# корреляция с наблюдаемыми коэффициентами coeffs
corr=float(np.dot(pattern, coeffs)/len(pattern))
bit = 1 if corr>0.02 else 0     # порог подбирается эмпирически
print('corr', corr, 'bit', bit)
```

Порог критичен: слишком высокий — пропуск бита, слишком низкий — ложные срабатывания. В задачах с известным cover-файлом порог калибруют по разнице между cover и marked.

## Атаки на водяные знаки

Понимание атак помогает и при извлечении, и при защите:

| Атака | Суть | Влияние |
|---|---|---|
| Сжатие (JPEG q<50) | удаляет высокочастотные компоненты | ломает хрупкие, ослабляет устойчивые |
| Кадрирование | убирает часть изображения | сдвигает синхронизацию |
| Масштабирование | меняет частоты | ломает не-инвариантные схемы |
| Шум | добавляет случайность | снижает корреляцию |
| Collusion | усреднение многих копий | стирает fingerprint |
| Поворот | геометрическое искажение | ломает синхронизацию |

Для CTF вывод простой: если файл «прошёл» через редактор, ищите метку в устойчивых областях (DWT/DFT), а не в LSB.

## Разбор задачи с cover-версией

Если в CTF даны `cover.png` и `marked.png`, задача сводится к diff-анализу:

```bash
python3 - <<'PY'
from PIL import Image
import numpy as np
a=np.array(Image.open('cover.png').convert('RGB')).astype(int)
b=np.array(Image.open('marked.png').convert('RGB')).astype(int)
d=np.abs(a-b)
# где изменения стабильны — там метка
mask=(d.sum(axis=2)>0).astype('uint8')*255
Image.fromarray(mask).save('diff_mask.png')
print('changed pixels:', int((d.sum(axis=2)>0).sum()))
PY
```

Маска изменений показывает позиции метки; дальнейший анализ (по каналам, по блокам 8×8) восстанавливает сами биты.

## Практический чек-лист

1. `exiftool` — метка может быть в метаданных (самый быстрый путь).
2. `zsteg`/StegSolve — LSB (хрупкий знак).
3. При наличии cover — diff-анализ и корреляция.
4. DCT/DWT-анализ (`jsteg`, `outguess`, `pywt`).
5. Проверить устойчивость: перекодировать и посмотреть, сохранилась ли метка.
6. Задокументировать область (пространственная/частотная) и тип (robust/fragile/fingerprint).

## Разобранный пример 2: DWT-метка

Задача: `art.png`, сказано «устойчивый водяной знак».

```bash
$ zsteg -a art.png
(пусто)          # LSB чист
$ exiftool -Comment art.png
Comment : (нет)
```

Значит, метка в частотной области. Разложим по вейвлетам и поищем аномалию в низкочастотном субдиапазоне:

```python
import pywt, numpy as np
from PIL import Image
im=np.array(Image.open('art.png').convert('L')).astype(float)
cA,(cH,cV,cD)=pywt.dwt2(im,'haar')
# ищем периодический паттерн в cA
flat=cA.flatten()
# автокорреляция — метка даёт пик на периоде
ac=np.correlate(flat-flat.mean(), flat-flat.mean(), 'full')[len(flat)-1:]
peaks=np.argsort(ac[1:200])[::-1][:5]+1
print('candidate periods', peaks)
```

Если автокорреляция даёт выраженный период — метка встроена в LL-субдиапазон с этим шагом. Дальше извлекаем биты по порогу относительно среднего. Такой анализ объясняет, почему LSB-инструменты «слепы» к устойчивым водяным знакам: данные распределены по всему изображению, а не лежат в младших битах конкретных пикселей. Для DFT-меток аналогично смотрите магнитуду спектра на предмет симметричных пиков.

## Частые ошибки и как их избежать

- **Искать LSB там, где метка частотная:** устойчивый водяной знак не лежит в младших битах; `zsteg` вернёт пусто, и это ожидаемо.
- **Игнорировать метаданные:** часто метка проще всего — в `Comment`/XMP; проверяйте `exiftool` до сложного анализа.
- **Нет калибровки порога:** при извлечении корреляцией порог надо подбирать; слишком высокий — пропуски, слишком низкий — ложные срабатывания.
- **Забыть про цветовое пространство:** DCT/DWT считают в яркости (Y), а не в RGB; конвертируйте перед анализом.
- **Ложные срабатывания:** текстурированные изображения дают высокую корреляцию случайно; подтверждайте метку на нескольких фрагментах.
- **Re-encode перед анализом:** не пересохраняйте файл — это уничтожит хрупкий знак.

Практический вывод: если данные проектировались как устойчивый водяной знак, пространственные LSB-инструменты бессильны. Переходите к DCT/DWT/DFT и, при наличии cover-версии, к diff-анализу — это самый быстрый путь к метке.
