## Вопрос, с которого всё начинается

В CTF дали `marked.jpg` и подпись «найдите скрытую метку». `zsteg -a` выдаёт мусор, `binwalk` чист, но `exiftool` показывает поле `Comment: watermark-id:7`. Метка нашлась — но что если бы её там не было? Как искать метку, которую специально проектировали, чтобы она пережила сжатие, кадрирование и масштабирование?

Ответ: это **водяной знак** — метка, встроенная в частотную область (DCT/DWT/DFT), а не в младшие биты пикселей. Пространственные LSB-инструменты её «слепы». Разберём наш файл и общий метод.

## Наш пример: marked.jpg

Водяной знак — это стеганографическая метка, встроенная ради конкретной цели: доказать авторство (**устойчивый**, robust), поймать модификацию (**хрупкий**, fragile) или отследить утечку (**fingerprint**). Ключевое отличие от «просто спрятанного сообщения»: знак проектируется под модель атак. Устойчивый переживает JPEG-сжатие и кадрирование, хрупкий ломается при малейшей правке и потому служит детектором.

Смотрим метаданные — самый быстрый путь:

```bash
$ exiftool marked.jpg | grep -iE 'comment|xmp|description'
Comment                         : watermark-id:7
```

Метка оказалась в метаданных. Но в нашем примере проверим и более глубокие слои, чтобы понять метод.

## Шаг 1: устойчивый против хрупкого

| Свойство | Устойчивый | Хрупкий |
|---|---|---|
| Цель | доказать авторство | детектировать правки |
| Переживает сжатие | да | нет |
| Переживает кадрирование | часто | нет |
| Область | DCT/DWT/DFT | LSB/пространственная |
| Ёмкость | низкая | выше |

Устойчивый знак размазан по всему изображению и прячется в коэффициентах частотного преобразования. Хрупкий — наоборот, лежит в младших битах конкретных пикселей и потому ломается от любого пересжатия.

## Шаг 2: хрупкий LSB-знак (база)

Простейший водяной знак — повторяющийся паттерн в младших битах. Он хрупкий, но демонстрирует идею: паттерн дублируют, чтобы извлечь даже из повреждённой копии.

```python
from PIL import Image
import numpy as np
im = np.array(Image.open('cover.png').convert('RGB'))
wm = 'WATERMARK'
bits = ''.join(f'{ord(c):08b}' for c in wm) * 100   # повтор для устойчивости
flat = im.reshape(-1)
for i, b in enumerate(bits[:flat.size]):
    flat[i] = (flat[i] & 0xFE) | int(b)             # затираем бит 0 и пишем свой
Image.fromarray(im).save('wm.png')
```

`& 0xFE` очищает младший бит, `| int(b)` пишет нужный. Такой знак найдёт `zsteg`, но он исчезнет после первого же пересохранения в JPEG.

## Шаг 3: устойчивый DCT-знак

Чтобы пережить сжатие, данные встраивают в **среднечастотные DCT-коэффициенты** блоков 8×8. DCT (дискретное косинусное преобразование) — это то же преобразование, что использует JPEG; правка средних частот незаметна глазу, но сохраняется при сжатии. В JPEG-стего это делают jsteg, F5, outguess (см. урок `stego-jpeg-dct`). Типовой приём извлечения — сравнить коэффициенты двух версий (оригинал и помеченная) и найти стабильно изменённые позиции.

## Шаг 4: DWT/DFT-знаки

- **DWT (вейвлеты):** данные прячут в низкочастотном (LL) или среднечастотном субдиапазоне; устойчиво к сжатию.
- **DFT (Фурье):** метка в магнитуде/фазе спектра; устойчиво к сдвигу и масштабу.

Вейвлет-разложение делается библиотекой `pywt`:

```python
import pywt, numpy as np
from PIL import Image
im = np.array(Image.open('cover.png').convert('L')).astype(float)
cA, (cH, cV, cD) = pywt.dwt2(im, 'haar')
cA[0, 0] += 42                                     # встроить метку в LL-субдиапазон
out = pywt.idwt2((cA, (cH, cV, cD)), 'haar')
Image.fromarray(np.clip(out, 0, 255).astype('uint8')).save('dwt_wm.png')
```

`dwt2` разбивает картинку на четыре субдиапазона: `cA` (низкие частоты, «общий вид») и `cH/cV/cD` (детали). Правка `cA` меняет всю картинку слегка — знак распределён и устойчив.

## Шаг 5: извлечение корреляцией, а не чтением битов

Устойчивый знак извлекают не «чтением битов», а **корреляцией** известного паттерна с сигналом. Паттерн (псевдослучайная последовательность, PRN) задаётся ключом; его умножают на коэффициенты и по знаку суммы решают «бит 1 / бит 0»:

```python
import numpy as np
rng = np.random.default_rng(seed=12345)
pattern = rng.choice([-1, 1], size=1000)
corr = float(np.dot(pattern, coeffs) / len(pattern))
bit = 1 if corr > 0.02 else 0     # порог подбирают эмпирически
print('corr', corr, 'bit', bit)
```

Порог критичен: слишком высокий — пропуск бита, слишком низкий — ложные срабатывания. Если в задаче есть cover-версия, порог калибруют по разнице cover и marked.

## Шаг 6: fingerprint

**Fingerprint** — уникальная метка на каждую копию файла, чтобы отследить, чья копия утекла. От обычного водяного знака отличается тем, что копий много и у каждой свой ID. Ищут периодичность или известный ID в устойчивом коде, часто через перебор LSB-плоскостей:

```bash
$ zsteg -a suspect.png | grep -iE 'b[0-9]'
```

## Шаг 7: diff с cover-версией

Если даны `cover.png` и `marked.png`, задача сводится к **diff-анализу** — где картинки стабильно различаются, там метка:

```python
from PIL import Image
import numpy as np
a = np.array(Image.open('cover.png').convert('RGB')).astype(int)
b = np.array(Image.open('marked.png').convert('RGB')).astype(int)
d = np.abs(a - b)
mask = (d.sum(axis=2) > 0).astype('uint8') * 255
Image.fromarray(mask).save('diff_mask.png')
print('changed pixels:', int((d.sum(axis=2) > 0).sum()))
```

Маска изменений показывает позиции метки; дальнейший анализ по каналам и блокам 8×8 восстанавливает биты.

## Атаки и частые ошибки

Понимание атак помогает и при извлечении: зная, какое преобразование уничтожит знак, ты выбираешь правильную область поиска, а не перебираешь всё подряд. Основные атаки:

| Атака | Влияние |
|---|---|
| Сжатие JPEG (q<50) | ломает хрупкие, ослабляет устойчивые |
| Кадрирование | сдвигает синхронизацию |
| Масштабирование | ломает не-инвариантные схемы |
| Шум | снижает корреляцию |
| Collusion (усреднение копий) | стирает fingerprint |

Частые ошибки: искать LSB там, где метка частотная (`zsteg` вернёт пусто — это ожидаемо); игнорировать метаданные (часто метка проще всего в `Comment`/XMP); забывать, что DCT/DWT считают в яркости Y, а не в RGB; не пересохранять файл перед анализом — это уничтожит хрупкий знак.

## Шаг 8: инструменты

Для практики полезны готовые библиотеки. **OpenStego** (`openstego.jar`) встраивает и извлекает LSB-водяные знаки из командной строки; **PyWavelets** (`pywt`) и **NumPy/SciPy** дают DWT/DCT/DFT и корреляцию; **invisible-watermark** (Python) реализует устойчивые знаки сразу на DWT+DCT.

```bash
$ java -jar openstego.jar embed -a RandomLSB -mf watermark.png -cf cover.png -sf marked.png
$ java -jar openstego.jar extract -a RandomLSB -sf marked.png -xd out/
```

Не путай инструменты под разные задачи: `steghide` — это парольное сокрытие данных с шифрованием, а не водяной знак в строгом смысле.

## Что мы теперь знаем

1. Водяной знак проектируется под цель: устойчивый, хрупкий или fingerprint.
2. Устойчивый живёт в частотной области (DCT/DWT/DFT), хрупкий — в LSB.
3. Хрупкий LSB-знак повторяют для извлечения, но он гибнет при пересжатии.
4. Устойчивый извлекают корреляцией PRN-паттерна, а не чтением битов.
5. При наличии cover-версии быстрее всего работает diff-анализ.
6. Метаданные (`exiftool`) — первый и самый дешёвый шаг.
