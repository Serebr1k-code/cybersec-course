## Вопрос, с которого всё начинается

Тепловизор отдаёт кадр `thermal.raw`. Открываешь — это не PNG и не JPG, а поток
байтов. И пиксели здесь не 8-битные: температура требует больше градаций. Как
прочитать из такого кадра спрятанные данные? Разберём 16-битный одиночный канал.

## Наш пример: файл thermal.raw

```bash
file thermal.raw
```

```text
thermal.raw: data
```

Формат не распознан — нет сигнатуры. Размер 65536×2 байт = 256×256 пикселей ×
16 бит. Порядок байтов обычно little-endian.

## Шаг 1: почему 16 бит

Тепловизор измеряет температуру в диапазоне, например, от −20 до +150 °C. Чтобы
передать 170 градусов с разрешением 0.01 °C, нужно ~17000 уровней — это больше
255 (8 бит). Поэтому один канал, но 16 бит. Для стего это плюс: у каждого значения
16 бит, и младшие из них — свободное место.

## Шаг 2: где именно «младший бит»

Ошибка новичка — брать младший бит **байта**. Но пиксель — 16-битное значение.
«Младший бит» здесь — бит 0 всего значения. В little-endian это младший бит
**первого** байта пары; в big-endian — второго. Читаем правильно:

```python
import struct
d = open('thermal.raw','rb').read()
vals = struct.unpack('<%dH' % (len(d)//2), d)   # little-endian uint16
bits = [v & 1 for v in vals]
out = bytearray()
for k in range(0, len(bits)//8*8, 8):
    b = 0
    for x in bits[k:k+8]:
        b = (b << 1) | x
    out.append(b)
print(out[:24])
```

## Шаг 3: почему высокая разрядность выгодна

- **Больше младших бит**: биты 0 и 1 можно использовать, изменения на 1–3 из 65535
  невидимы.
- **Шум сенсора**: тепловизор и так шумный — встроенные данные маскируются.
- **Нет сжатия**: RAW без потерь.
- **Инструменты**: 16-битные RAW-кадры не поддерживает обычный стего-тулкит.

## Шаг 4: запускаем

```bash
python3 thermal.py
```

```text

pixels: 65536
nto{th3rm4l_1r_16b1t}
```

Флаг получен. Мы прочитали младший бит 16-битных значений, а не байтов — это и
есть ключевой момент урока.

## Шаг 5: big-endian и нормализация

Иногда сенсор отдаёт big-endian (`>H`). Если читать не тем порядком, байты
переставятся и биты «съедут». Всегда проверяй: размер файла кратен 2 (16 бит) или
4 (float32)? Попробуй оба порядка и смотри, где появляется текст.

Иногда после калибровки значения становятся **float32** — тогда «младший бит»
надо брать из мантиссы (например, бит 0 мантиссы), а не из целого.

## Шаг 6: сколько бит использовать

Можно встраивать не только бит 0, но и биты 1–2. Это увеличивает ёмкость в 2–3
раза. Цена — чуть больше искажение температуры. Для CTF обычно хватает бита 0.

## Шаг 7: частые ловушки

- **Endianness**: little vs big — самый частый промах.
- **Разрядность**: 14-битные сенсоры упакованы в 16; лишние биты — шум.
- **Нормализация**: конверсия в 8-бит для просмотра уничтожает LSB.
- **Ориентация**: строки могут идти снизу вверх.
- **Заголовок**: реальные форматы (FLIR) имеют свой заголовок перед данными.

## Что мы теперь знаем

- Тепловизионный кадр — один канал, но 16 бит на пиксель.
- «Младший бит» берётся из 16-битного значения, а не из байта.
- Endianness критична: little vs big меняет всё.
- Высокая разрядность даёт больше свободных бит и маскирует изменения шумом.
- Просмотр/нормализация в 8 бит убивает данные.
