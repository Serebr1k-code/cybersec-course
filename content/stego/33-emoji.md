## Почему эмодзи — удобный носитель

Эмодзи — это не «картинки», а Unicode-символы из высоких плоскостей (в основном U+1F300–U+1FAFF). Один эмодзи может занимать **несколько кодовых точек**, склеенных невидимыми модификаторами. Именно эти модификаторы и служат каналом: сообщение выглядит как обычный набор эмодзи, но внутри невидимо закодированы данные.

Три механизма создают пространство для сокрытия:

- **ZWJ-последовательности** — семейные и профессиональные эмодзи собираются из базовых символов, соединённых U+200D (zero-width joiner).
- **Вариационные селекторы** — U+FE0E/U+FE0F переключают текстовое/эмодзи-представление, визуально почти не меняя символ.
- **Модификаторы тона кожи и теги** — U+1F3FB–U+1F3FF и блочные теги U+E0020–U+E007F, которые не отображаются, но хранят данные.

Поскольку все эти символы невидимы, задача сводится к тому, чтобы найти их в потоке и сопоставить с битами.

## Zero-width joiner в эмодзи-последовательностях

Семейный эмодзи 👨👩👧👦 — это последовательность `U+1F468 ZWJ U+1F469 ZWJ U+1F467 ZWJ U+1F466`. Наличие или отсутствие ZWJ между базовыми эмодзи кодирует бит: с ZWJ = 1, без = 0. Автор задачи может собрать «семью» из произвольных эмодзи и спрятать последовательность нулей и единиц в расстановке joiners.

```python
s = open('emoji.txt', encoding='utf-8').read()
ZWJ = '\u200d'
bits = []
prev = None
for c in s:
    if c == ZWJ:
        bits.append('1')
# либо: между двумя базовыми эмодзи есть ZWJ → 1, нет → 0
seq = [c for c in s if ord(c) >= 0x1F000]
bits = ''.join('1' if (i < len(s)-1 and s[s.index(seq[i])+1] == ZWJ) else '0'
               for i in range(len(seq)-1))
out = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
print(out)
```

Ключевой приём — сначала **выделить невидимые символы** (ZWJ/VS/теги), потом решать, что из них бит.

## Вариационные селекторы (VS15/VS16)

`U+FE0E` (текстовое представление) и `U+FE0F` (эмодзи-представление) — два разных символа, визуально дающих почти одинаковый результат. Их наличие/значение — готовый бинарный канал: VS15 = 0, VS16 = 1 (или наоборот). Такой текст неотличим от обычного в любом редакторе.

```python
VS15, VS16 = '\ufe0e', '\ufe0f'
s = open('f.txt', encoding='utf-8').read()
bits = ''.join('1' if c == VS16 else '0' for c in s if c in (VS15, VS16))
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8)))
```

## Тональность кожи и гендерные модификаторы

Модификаторы тона кожи `U+1F3FB`–`U+1F3FF` (5 штук) дают 5 вариантов — это уже не бит, а «пятеричный» символ. Пять значений можно отобразить в 2 бита (с потерей) или использовать как base-5 кодирование. Аналогично `U+2640/U+2642` (женский/мужской знак) в профессиональных эмодзи.

Если видите эмодзи с разными тонами кожи в необычном порядке — это, скорее всего, канал. Сопоставляйте тон с числом и декодируйте base-5 или маппингом.

## Теги (tag characters) и региональные индикаторы

Блочные **tag-символы** `U+E0020`–`U+E007F` полностью невидимы и предназначены для тегов (subdivision flags). Они дают ровно 128 значений, отображаемых в ASCII-подобный код: `U+E0020 + n`. Это **прямой** канал — можно закодировать целую строку.

```python
s = open('tagged.txt', encoding='utf-8').read()
chars = [c for c in s if 0xE0020 <= ord(c) <= 0xE007E]
print(''.join(chr(ord(c) - 0xE0000) for c in chars))
```

**Региональные индикаторы** `U+1F1E6`–`U+1F1FF` (A–Z) образуют флаги парами. Пары можно читать как буквы: `U+1F1E6 + n` = `A+n`. Последовательность флагов, не складывающаяся в реальные страны, — верный признак сообщения.

Невидимые символы сразу видны как `0x200b`, `0x200d`, `0xfe0f`, `0xe00xx`.

## Разобранный пример

Задача: строка из эмодзи, флаг не виден.

```python
s = open('msg.txt', encoding='utf-8').read()
hidden = [c for c in s if ord(c) in (0x200b, 0x200c, 0x200d, 0xfe0e, 0xfe0f)]
print(len(hidden), [hex(ord(c)) for c in hidden[:16]])
# два вида → биты
bits = ''.join('1' if c in ('\u200b','\ufe0f') else '0' for c in hidden)
print(bytes(int(bits[i:i+8],2) for i in range(0,len(bits)-7,8)))
# b'flag{em0j1_zwj}'
```

Маршрут: дамп кодовых точек → выделить невидимые → маппинг в биты → декод. Если невидимых два вида — бинарно; четыре — по 2 бита; tag-символы — напрямую в ASCII.

## Гомоглифы и похожие эмодзи

Помимо невидимых символов, встречаются **визуально похожие** эмодзи разных кодовых точек (например, разные «сердечки» или «звёзды»). Выбор варианта кодирует бит. Здесь помогает только дамп кодовых точек: глаз разницы не видит, а `hex(ord(c))` — видит.

## Частые ошибки и подводные камни

- **Копировать через мессенджер** — ZWJ и VS-селекторы могут схлопнуться; берите исходный файл.
- **Считать эмодзи одним символом** — он часто состоит из нескольких кодовых точек.
- **Не фильтровать по диапазону** — среди «шума» легко пропустить tag-символы.
- **Путать VS15/VS16 с данными флага** — проверяйте оба направления бит.
- **Игнорировать base-5** (тона кожи) — не всё бинарно.
- **Забыть про BOM** в начале файла — иногда это просто метка кодировки, а не канал.

## Полный скрипт-перебор Unicode-каналов

Когда правила неизвестны, быстрее прогнать все невидимые диапазоны одним скриптом, чем гадать:

```python
s = open('text.txt', encoding='utf-8').read()
ranges = {
    'zw':      (0x200B, 0x200F),
    'wj':      (0x2060, 0x2064),
    'vs':      (0xFE00, 0xFE0F),
    'tags':    (0xE0020, 0xE007F),
    'ri':      (0x1F1E6, 0x1F1FF),   # regional indicators A-Z
    'skin':    (0x1F3FB, 0x1F3FF),
}
def bits_to_bytes(b):
    return bytes(int(b[i:i+8],2) for i in range(0,len(b)-7,8))
for name,(lo,hi) in ranges.items():
    chars = [c for c in s if lo <= ord(c) <= hi]
    if not chars: continue
    print(name, len(chars), [hex(ord(c)) for c in chars[:8]])
    if name == 'tags':
        print('  ascii:', ''.join(chr(ord(c)-0xE0000) for c in chars))
    elif name == 'ri':
        print('  letters:', ''.join(chr(ord(c)-0x1F1E6+65) for c in chars))
    else:
        # два вида → бит
        kinds = sorted({ord(c) for c in chars})
        if len(kinds) == 2:
            b = ''.join('1' if ord(c)==kinds[1] else '0' for c in chars)
            print('  bits:', bits_to_bytes(b))
```

Такой «веер» за один прогон проверяет все эмодзи/Unicode-каналы и печатает результат в читаемом виде.

## Эмодзи в веб и чатах: где встречается

Эмодзи-стеганография встречается не только в CTF:

- **Соцсети и мессенджеры**: невидимые символы переживают отправку (иногда — нет), используются для «водяных знаков» сообщений.
- **Веб-формы**: валидация часто не фильтрует невидимые символы, что даёт канал.
- **Спуфинг**: похожие эмодзи в именах пользователей/доменах.
- **Watermarking**: скрытая маркировка сгенерированного контента.

Для тестировщика это повод проверять входные данные на невидимые символы (нормализация Unicode), а для CTF — лишний раз проверить «обычный» текст на наличие эмодзи-каналов.

## Инструменты и онлайн-декодеры

- **CyberChef**: `Extract Zero-Width`, `From Unicode`, `Find / Replace` по hex-диапазонам.
- **`unicode.py`**, `unicode-explorer` — исследование кодовых точек.
- **`stegoveritas`** — общий анализатор, часть Unicode-трюков.
- **Собственный скрипт** — самый гибкий вариант для специфичных наборов символов.

Практика показывает: 80 % эмодзи-задач решаются дампом кодовых точек и бинарным маппингом двух невидимых символов. Остальные 20 % — tag-символы (напрямую в ASCII), региональные индикаторы (буквы) и тона кожи (base-5).

## Мини-чек-лист эмодзи-задачи

1. Сделайте дамп всех кодовых точек: `[hex(ord(c)) for c in s]`.
2. Отфильтруйте невидимые диапазоны: 200B–200F, FE00–FE0F, E0000–E007F.
3. Если невидимых ровно два вида — маппинг в биты, оба порядка.
4. Tag-символы (E00xx) — вычтите 0xE0000 и получите ASCII напрямую.
5. Региональные индикаторы (1F1E6–1F1FF) — это буквы A–Z.
6. Тона кожи (1F3FB–1F3FF) — base-5, пять значений.
7. Нет невидимых — ищите визуально похожие эмодзи разных кодовых точек.
8. Пусто — текст может быть носителем другого канала (whitespace, base64).

## Итог по эмодзи-каналу

Эмодзи-стеганография — это, по сути, частный случай Unicode-стеганографии, где носителем служат многокодовые последовательности. Ключевой навык — не «увидеть» разницу глазами (её нет), а выгрузить кодовые точки и найти среди них невидимые или избыточные. Как только вы это сделали, задача сводится к уже знакомому маппингу символов в биты (или в base-5/ASCII). Практически любой эмодзи-контейнер разбирается дампом `[hex(ord(c)) for c in s]` и последующим перебором диапазонов, поэтому заведите себе этот однострочник и применяйте к любому «странному» тексту.

## Что делать дальше / решение

- Дамп всех кодовых точек, фильтр по невидимым диапазонам (200B–200F, FE00–FE0F, E0000–E007F).
- Два вида → биты; пять (тона) → base-5; tag-символы → ASCII напрямую.
- Нет невидимых — ищите визуально похожие эмодзи разных кодовых точек.
- Пусто — текст может быть носителем другого канала (whitespace, base64 в описании).
