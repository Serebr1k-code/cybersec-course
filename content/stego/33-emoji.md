## Вопрос, с которого всё начинается

Тебе дали строку из эмодзи. На вид — обычный набор смайликов, флаг не виден. Но сообщение где-то есть. Как?

Эмодзи — это не «картинки», а Unicode-символы, и один эмодзи может состоять из **нескольких кодовых точек**, склеенных невидимыми модификаторами. Именно эти модификаторы и несут данные. Разберём на конкретной строке.

## Наш пример: msg.txt

```
$ cat msg.txt
👨👩👧👦❤️🌟🎉
```

Смотрим в файл — видим несколько эмодзи. Сделаем дамп **кодовых точек** (числовых номеров символов):

```python
s = open('msg.txt', encoding='utf-8').read()
print([hex(ord(c)) for c in s])
```

```
$ python3 dump.py
['0x1f468', '0x200d', '0x1f469', '0x200d', '0x1f467', '0x200d', '0x1f466', '0x2764', '0xfe0f', '0x1f31f', '0x1f389']
```

Заметь: между эмодзи людей (`0x1f468` — мужчина, `0x1f469` — женщина) стоят символы `0x200d`. Это **ZWJ** (zero-width joiner) — невидимый «склейщик». А после сердца `0x2764` идёт `0xfe0f` — **вариационный селектор**.

## Шаг 1: почему эмодзи — удобный носитель

Три механизма дают пространство для сокрытия:

- **ZWJ-последовательности** — семейные эмодзи собираются из базовых символов, соединённых `U+200D`;
- **вариационные селекторы** `U+FE0E`/`U+FE0F` — переключают текстовое/эмодзи-представление, визуально почти не меняя символ;
- **тона кожи и теги** — `U+1F3FB`–`U+1F3FF` и блочные теги `U+E0020`–`U+E007F`, которые не отображаются, но хранят данные.

Все эти символы невидимы, поэтому задача сводится к тому, чтобы найти их в потоке и сопоставить с битами.

## Шаг 2: ZWJ как бинарный канал

Наличие или отсутствие ZWJ между базовыми эмодзи кодирует бит: с ZWJ = 1, без = 0. Соберём все ZWJ по порядку:

```python
s = open('msg.txt', encoding='utf-8').read()
hidden = [c for c in s if ord(c) in (0x200b, 0x200c, 0x200d, 0xfe0e, 0xfe0f)]
print(len(hidden), [hex(ord(c)) for c in hidden[:16]])
bits = ''.join('1' if c in ('\u200b', '\ufe0f') else '0' for c in hidden)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data)
```

$ python3 extract.py

## Шаг 3: вариационные селекторы

`U+FE0E` (текстовое представление) и `U+FE0F` (эмодзи-представление) — два разных символа с почти одинаковым видом. Их наличие — готовый бинарный канал: VS15 = 0, VS16 = 1.

```python
VS15, VS16 = '\ufe0e', '\ufe0f'
bits = ''.join('1' if c == VS16 else '0' for c in s if c in (VS15, VS16))
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8)))
```

## Шаг 4: тона кожи и теги

**Модификаторы тона кожи** `U+1F3FB`–`U+1F3FF` (5 штук) дают 5 вариантов — это уже не бит, а base-5. Пять значений можно отобразить в 2 бита или декодировать как base-5.

**Tag-символы** `U+E0020`–`U+E007F` полностью невидимы и дают ровно 128 значений, отображаемых в ASCII напрямую:

```python
chars = [c for c in s if 0xE0020 <= ord(c) <= 0xE007E]
print(''.join(chr(ord(c) - 0xE0000) for c in chars))
```

**Региональные индикаторы** `U+1F1E6`–`U+1F1FF` (A–Z) образуют флаги парами; их можно читать как буквы: `ord(c) - 0x1F1E6 + 65`.

## Шаг 5: полный скрипт-перебор Unicode-каналов

Когда правило неизвестно, прогоним все невидимые диапазоны одним скриптом:

```python
s = open('text.txt', encoding='utf-8').read()
ranges = {
    'zw':   (0x200B, 0x200F),
    'wj':   (0x2060, 0x2064),
    'vs':   (0xFE00, 0xFE0F),
    'tags': (0xE0020, 0xE007F),
    'ri':   (0x1F1E6, 0x1F1FF),
    'skin': (0x1F3FB, 0x1F3FF),
}
def b2b(b):
    return bytes(int(b[i:i+8], 2) for i in range(0, len(b) - 7, 8))
for name, (lo, hi) in ranges.items():
    chars = [c for c in s if lo <= ord(c) <= hi]
    if not chars:
        continue
    kinds = sorted({ord(c) for c in chars})
    if name == 'tags':
        print(name, ''.join(chr(ord(c) - 0xE0000) for c in chars))
    elif name == 'ri':
        print(name, ''.join(chr(ord(c) - 0x1F1E6 + 65) for c in chars))
    elif len(kinds) == 2:
        print(name, b2b(''.join('1' if ord(c) == kinds[1] else '0' for c in chars)))
```

Такой «веер» за один прогон проверяет все эмодзи/Unicode-каналы.

## Шаг 6: где это встречается

Эмодзи-стеганография — не только CTF:

- **Соцсети и мессенджеры:** невидимые символы переживают отправку и служат «водяными знаками»;
- **Веб-формы:** валидация часто не фильтрует невидимые символы;
- **Спуфинг:** похожие эмодзи в именах и доменах;
- **Watermarking:** скрытая маркировка сгенерированного контента.

## Если не сработало

- Не копируй через мессенджер — ZWJ/VS могут схлопнуться; бери исходный файл.
- Помни, что эмодзи — это несколько кодовых точек, а не одна.
- Фильтруй по диапазонам, иначе пропустишь tag-символы.
- Нет невидимых — ищи визуально похожие эмодзи разных кодовых точек (дамп `hex(ord(c))` покажет).

## Что мы теперь знаем

1. Эмодзи — Unicode-символы, часто из нескольких кодовых точек.
2. ZWJ, вариационные селекторы и теги — невидимые каналы.
3. Два вида невидимых → биты; tag-символы → ASCII напрямую.
4. Региональные индикаторы — буквы A–Z; тона кожи — base-5.
5. Разбор начинается с дампа `[hex(ord(c)) for c in s]`.

## Шаг 7: мини-чек-лист эмодзи-задачи

1. Сделай дамп всех кодовых точек: `[hex(ord(c)) for c in s]`.
2. Отфильтруй невидимые диапазоны: 200B–200F, FE00–FE0F, E0000–E007F.
3. Если невидимых ровно два вида — маппинг в биты, оба порядка.
4. Tag-символы (E00xx) — вычти 0xE0000 и получи ASCII напрямую.
5. Региональные индикаторы (1F1E6–1F1FF) — это буквы A–Z.
6. Тона кожи (1F3FB–1F3FF) — base-5, пять значений.
7. Нет невидимых — ищи визуально похожие эмодзи разных кодовых точек.
8. Пусто — текст может быть носителем другого канала (whitespace, base64).

## Шаг 8: эмодзи в веб и чатах

Эмодзи-стеганография встречается не только в CTF:

- **соцсети и мессенджеры** — невидимые символы переживают отправку и служат «водяными знаками»;
- **веб-формы** — валидация часто не фильтрует невидимые символы, что даёт канал;
- **спуфинг** — похожие эмодзи в именах пользователей и доменах;
- **watermarking** — скрытая маркировка сгенерированного контента.

Для тестировщика это повод проверять входные данные на невидимые символы (нормализация Unicode), а для CTF — лишний раз проверить «обычный» текст.

## Шаг 9: инструменты

- **CyberChef** — `Extract Zero-Width`, `From Unicode`;
- **`unicode.py`/unicode-explorer** — исследование кодовых точек;
- **`stegoveritas`** — общий анализатор;
- **собственный скрипт** — самый гибкий вариант.

Практика: 80 % эмодзи-задач решаются дампом кодовых точек и бинарным маппингом двух невидимых символов; остальные 20 % — tag-символы, региональные индикаторы и тона кожи.

## Шаг 10: почему эмодзи — удобный носитель (углублённо)

Один эмодзи может занимать **несколько кодовых точек**, склеенных невидимыми модификаторами. Именно эти модификаторы и служат каналом: сообщение выглядит как обычный набор эмодзи, но внутри невидимо закодированы данные. Три механизма создают пространство:

- **ZWJ-последовательности** — семейные и профессиональные эмодзи собираются из базовых символов, соединённых `U+200D`;
- **вариационные селекторы** — `U+FE0E`/`U+FE0F` переключают представление, визуально почти не меняя символ;
- **тона кожи и теги** — `U+1F3FB`–`U+1F3FF` и блочные теги `U+E0020`–`U+E007F`, которые не отображаются, но хранят данные.

Ключевой навык — не «увидеть» разницу глазами (её нет), а выгрузить кодовые точки и найти среди них невидимые или избыточные.

## Шаг 11: прячем данные сами

Декодировать — половина навыка; вторая — уметь спрятать. Соберём сообщение из эмодзи, где невидимые ZWJ кодируют биты:

```python
def hide(text, emojis):
    bits = ''.join(f'{b:08b}' for b in text.encode())
    out = []
    for i, bit in enumerate(bits):
        out.append(emojis[i % len(emojis)])
        if bit == '1':
            out.append('\u200d')
    return ''.join(out)
```

Каждый бит сообщения превращается в наличие или отсутствие ZWJ после очередного эмодзи. Внешне строка выглядит как обычный набор смайликов — невидимые символы глазом не различить.

## Шаг 12: почему данные теряются

Невидимые символы хрупкие. Мессенджеры, формы и «умные» редакторы нормализуют Unicode и вырезают ZWJ/теги. Проверить это просто — сравните длину строки до и после копирования:

```python
before = len(open('msg.txt', encoding='utf-8').read())
after  = len(pasted)
print(before, after)   # уменьшилось -> канал пострадал
```

Поэтому в CTF всегда берите исходный файл, а не копию из чата: сохранённые байты — единственный надёжный источник.

## Шаг 13: нормализация как защита

Защита от таких каналов — нормализация входа: `unicodedata.normalize('NFKC', s)` сводит совместимые символы к каноничным и часто срезает невидимые модификаторы. Для веб-приложений это стандартная практика валидации имён и текстов, где невидимые символы не нужны.

## Шаг 14: проверка невидимых символов одной строкой

Не всегда под рукой есть CyberChef. Проверить невидимые символы можно встроенными средствами:

```python
s = open('msg.txt', encoding='utf-8').read()
inv = [hex(ord(c)) for c in s if 0x200b <= ord(c) <= 0x200f or 0xfe00 <= ord(c) <= 0xfe0f]
print(len(inv), inv[:20])
```

Если список непуст — канал есть, дальше маппинг в биты. Если пуст — смотри tag-диапазон `0xE0000–0xE007F` и региональные индикаторы.

## Шаг 15: отличие от обычной текстовой стеганографии

Классическая текстовая стеганография (пробелы, регистр) живёт в **ASCII** и видна в обычном дампе. Эмодзи-стеганография работает на уровне **кодовых точек Unicode**: один видимый символ — это несколько чисел, и данные прячутся между ними. Поэтому `cat` показывает «нормальный» текст, а `xxd` — лишние байты. Правило простое: невидимое ищи не глазами, а перебором `ord()`.
