## Вопрос, с которого всё начинается

В задаче дали `qr.png` — обычный QR-код. Сканируешь телефоном — открывается ссылка `https://example.com`. Но задача явно не про ссылку: где-то здесь спрятано ещё что-то. Как достать второй слой?

QR-код — это **контейнер с избыточностью**. Кроме самой ссылки, в нём есть ECC-байты, маска, служебная информация и, конечно, пиксели изображения. Любой из этих слоёв может нести данные. Разберём на нашем примере.

## Наш пример: qr.png

```bash
$ file qr.png
qr.png: PNG image data, 450 x 450, 8-bit/color RGB, non-interlaced
```

Это обычный QR версии 5 с высоким уровнем коррекции ошибок (H). Внутри — ссылка, но закладка лежит в другом слое.

## Шаг 1: QR как контейнер

QR-код устроен из нескольких частей:

- **Функциональные шаблоны** — три «глаза» по углам, выравнивающие узоры, тайминг-линии. Они фиксированы стандартом.
- **Формат-информация** — 15 бит: уровень коррекции (L/M/Q/H) и номер маски (0–7), защищённые кодом БЧХ.
- **Версия** — от 1 до 40, задаёт размер матрицы (21×21 … 177×177).
- **Данные + ECC** — полезная нагрузка плюс байты Рида-Соломона.
- **Маска** — XOR-шаблон, накладываемый на модули данных.

Ключевой факт: **ECC-байты избыточны**. Декодер исправляет ошибки, поэтому если слегка испортить часть служебных байт, QR всё равно прочитается, а «испорченные» байты можно занять под данные.

## Шаг 2: декодируем полезную нагрузку

Первый слой читается штатным декодером — из командной строки это `zbarimg`:

```bash
$ zbarimg -q qr.png
QR-Code:https://example.com
```

Осмысленный текст есть — значит, QR валиден. Но это лишь «слой 1». Смотрим дальше.

## Шаг 3: второй слой — LSB изображения

QR — это картинка, а значит, к ней применимы все техники изображений. Проверим младшие биты (LSB) пикселей:

```python
import numpy as np
from PIL import Image
a = np.array(Image.open("qr.png").convert("RGB")).reshape(-1)
data = np.packbits(a & 1).tobytes()
i = data.find(b"flag{")
print(data[i:i+18])
```

```
b'flag{qr_lsb_layer}'
```

Флаг найден в LSB. При этом `zbarimg` продолжает читать ссылку — декодер игнорирует младшие биты, для него важны «крупные» чёрно-белые модули. Так один файл несёт **два независимых сообщения**: видимое (ссылка) и скрытое (LSB).

Полезно сразу прогнать и другие слои:

```bash
$ zsteg -a qr.png        # перебор каналов и битовых плоскостей
$ binwalk qr.png         # вдруг внутри встроен ещё один файл
$ strings qr.png         # метаданные, padding
```

## Шаг 4: ECC и padding как канал

Второй «служебный» слой — **ECC-байты** Рида-Соломона и **padding** (заполнители). Уровень коррекции задаёт, сколько ошибок прощается:

| Уровень | Восстановление |
|---|---|
| L | ~7% |
| M | ~15% |
| Q | ~25% |
| H | ~30% |

Если данных мало, а уровень H, остаётся много ECC-байт, которые можно «занять» под сообщение: декодер воспримет их как ошибки в пределах бюджета и всё равно восстановит нагрузку. Ещё один канал — **padding**: после данных идут байты-заполнители `0xEC 0x11`, их тоже можно заменить своими. Практический приём: сгенерируй **эталонный** QR той же версии и уровня с той же нагрузкой и сравни матрицы — различия в служебных областях и есть данные.

```python
import qrcode
qr = qrcode.QRCode(version=5, error_correction=qrcode.constants.ERROR_CORRECT_H)
qr.add_data("https://example.com"); qr.make(fit=True)
# matrix эталона -> сравнить с фактической
```

## Шаг 5: маска и формат-информация

**Маска** — XOR-шаблон, который применяют к модулям данных, чтобы избежать «некрасивых» больших однотонных областей. Стандарт выбирает маску по минимуму штрафной функции, но её можно задать вручную. Если в задаче маска явно **неоптимальна** — это сигнал: возможно, её номер (0–7, три бита) кодирует данные.

**Формат-информация** — 15 бит (2 бита уровня ECC + 3 бита маски + 10 бит кода БЧХ). Она записана **дважды** вокруг двух «глаз»; сравнение двух копий выявляет расхождения. Нестандартный код БЧХ или инвертированные биты формата — тоже признак вмешательства.

## Шаг 6: если QR не читается

Иногда код специально «ломают», чтобы заставить повозиться:

- **Инверсия.** Отрази цвета: `convert qr.png -negate qr_inv.png`; `zbarimg` не всегда читает инвертированные.
- **Масштаб.** Декодируй в исходном размере; апскейл интерполяцией размывает модули.
- **Поворот.** `zbarimg` терпим к малым углам, но 90° — нет.
- **Несколько кодов.** `zbarimg` выведет все; проверь, нет ли второго QR в изображении.
- **Тихая зона.** Белая рамка вокруг QR (4 модуля) тоже может нести данные — LSB или «фальшивые» модули.
- **Слишком много повреждений.** Если вышли за бюджет ECC, часть данных не восстановить.

## Шаг 7: QR внутри QR и вложенность

Ещё один класс приёмов — вложенность:

- **QR внутри QR.** Один код кодирует изображение, на котором нарисован второй QR.
- **Несколько кодов.** В одном изображении может быть несколько QR; `zbarimg` выводит все — проверь, нет ли второго.
- **Инвертированный QR.** Отрази цвета; некоторые декодеры понимают инверсию только с флагом.
- **Частично повреждённый QR.** ECC восстанавливает код даже при заметных повреждениях — иногда их вносят специально.

Практический путь для вложенного QR: декодировать внешний, получить данные (возможно, base64 картинки), декодировать её и повторить. Каждый уровень может добавлять новый формат-носитель, поэтому не останавливайся на первом успешном декоде.

## Шаг 8: разбор структуры через библиотеку

Ручной парсинг матрицы QR утомителен, но библиотека `qrcode` даёт доступ к версии, маске и матрице модулей:

```python
import qrcode
qr = qrcode.QRCode(version=5, error_correction=qrcode.constants.ERROR_CORRECT_H)
qr.add_data("https://example.com"); qr.make(fit=True)
print("version", qr.version, "mask", qr.mask_pattern)
m = qr.matrix
print(len(m), "x", len(m[0]))
```

Сравнивая эталонную матрицу (сгенерированную с теми же версией, уровнем и нагрузкой) с фактической, можно локализовать различия: в области данных, в ECC или в padding. Различия в служебных областях — и есть скрытое сообщение. Полный чек-лист: `file` → `zbarimg` (нагрузка) → `zsteg -a`/`strings` (LSB и метаданные) → инверсия/масштаб → несколько кодов и тихая зона → `binwalk` (вложенные файлы) → разбор маски/ECC и сравнение с эталоном.

## Что мы теперь знаем

1. QR — контейнер с избыточностью: шаблоны, формат, данные, ECC, маска.
2. Полезная нагрузка читается `zbarimg`; это только «слой 1».
3. Пиксели изображения — отдельный носитель: LSB даёт второй слой.
4. ECC-байты и padding можно занять данными в пределах бюджета ошибок.
5. Номер маски и формат-информация — тонкие каналы; аномалия = сигнал.
6. Если не читается — проверь инверсию, масштаб, несколько кодов и тихую зону.

## Куда дальше
