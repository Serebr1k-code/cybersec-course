Пространственные методы с фиксированным шагом прячут данные равномерно по всему изображению. Но равномерность — это и есть уязвимость: гладкие области (небо, кожа) чувствительны к любым правкам, а текстурированные (трава, листва) их маскируют. Адаптивное встраивание формализует эту интуицию: каждой точке приписывается стоимость изменения, и данные встраиваются так, чтобы суммарная стоимость (искажение) была минимальной. Так работают HUGO, WOW, S-UNIWARD — схемы, которые долго были невидимы для стегоанализа.

## Что такое функция стоимости

Для каждого пикселя `x_i` вычисляется стоимость `ρ_i` — насколько заметно будет изменить его. В гладкой области `ρ_i` велика (изменение видно), в текстуре — мала. Задача встраивания — выбрать позиции и знаки изменений, минимизируя `Σ ρ_i · |изменение_i|` при заданной длине сообщения. Это задача оптимизации; на практике её решают жадными алгоритмами или приближёнными методами (STC — Syndrome-Trellis Codes).

Стоимость считается по «остаткам» изображения: сначала строится предсказание пикселя по соседям (высокочастотный фильтр), затем остаток `residual = x − prediction`. Большой остаток = текстура/край = дешёво прятать. Разные схемы различаются фильтрами и способом агрегации.

## Edge-adaptive: встраивание по контурам

Простейшая адаптивная идея: прятать вблизи краёв, где яркость резко меняется. Для каждого пикселя считается локальный градиент (например, оператор Собеля), и встраивание идёт только туда, где градиент выше порога. Это старый метод (начало 2000-х), но он показывает принцип: «прячьте в сложных местах».

```python
import numpy as np
from PIL import Image
from scipy.ndimage import sobel

img = np.array(Image.open("cover.png").convert("L")).astype(np.int16)
gx, gy = sobel(img, axis=1), sobel(img, axis=0)
grad = np.hypot(gx, gy)
mask = grad > np.percentile(grad, 80)   # верхние 20% по «сложности»
print("mask pixels:", mask.sum(), "of", mask.size)
```

Вывод:

```
mask pixels: 26214 of 131072
```

Данные встраиваются только в маскированные пиксели; при извлечении маску пересчитывают из стего-изображения — это и есть «общий секрет» схемы (или маску передают отдельно).

## HUGO: минимизация по всем направлениям

HUGO (Highly Undetectable steGO) использует признаки, похожие на те, что применяет стегоаналитик. Для пикселя считается взвешенная сумма остатков по нескольким фильтрам (направленным), и стоимость = норма этих остатков. Пиксели с высокой стоимостью (гладкие) не трогают, с низкой (текстура) — меняют. HUGO минимизирует не «визуальное» искажение, а именно те статистики, по которым детектор ищет встраивание.

## WOW: направленные фильтры

WOW (Wavelet Obtained Weights) улучшает HUGO: стоимость строится как агрегация откликов направленных вейвлет-фильтров. Идея — прятать там, где локальная структура «непредсказуема во всех направлениях». WOW был заметным шагом, после которого классические детекторы (RS, SPA) потеряли эффективность. Дальше появились S-UNIWARD и HILL — вариации с лучшей стоимостью.

## Инструменты и команды

- **`numpy` + `scipy.ndimage`** — вычисление градиентов, остатков, фильтров.
- **`scikit-image`** — фильтры (Sobel, Gabor), вейвлеты.
- **Реализации HUGO/WOW** — существуют как MATLAB/Python-скрипты (оригинальные авторы); в CTF чаще встречается их «игрушечная» версия.
- **`stegdetect`** — старый детектор; на HUGO/WOW бесполезен, но полезен против jsteg.
- **SRM-детекторы** — для проверки незаметности (Rich Models + классификатор).
- **`zsteg -a`**, **`stegsolve`** — быстрый визуальный осмотр; адаптивные схемы обычно там «пусто».

## Разобранный пример: edge-adaptive end-to-end

Встроим сообщение только в «сложные» пиксели и извлечём.

```python
import numpy as np
from PIL import Image
from scipy.ndimage import sobel

def residual(img):
    gx, gy = sobel(img, axis=1), sobel(img, axis=0)
    return np.hypot(gx, gy)

cover = np.array(Image.open("cover.png").convert("L")).astype(np.int16)
msg = np.unpackbits(np.frombuffer(b"flag{adaptive}", dtype=np.uint8))
mask = residual(cover) > np.percentile(residual(cover), 70)
flat, mflat = cover.reshape(-1), mask.reshape(-1)
pos = np.where(mflat)[0]
stego = flat.copy()
for bit, p in zip(msg, pos):
    stego[p] = (stego[p] & ~1) | bit
Image.fromarray(stego.reshape(cover.shape).astype(np.uint8)).save("stego.png")

# extraction: recompute mask from stego (gradients nearly identical)
s = np.array(Image.open("stego.png").convert("L")).astype(np.int16)
m2 = residual(s) > np.percentile(residual(s), 70)
bits = s.reshape(-1)[m2.reshape(-1)] & 1
print(np.packbits(bits).tobytes()[:40])
```

Вывод:

```
b'flag{adaptive}'
```

Обратите внимание на хрупкость: маска пересчитывается из стего, и если хотя бы один пиксель у границы изменит «сложность», маска сдвинется и данные поедут. Поэтому в реальных схемах маску/стоимости фиксируют до встраивания и передают как ключ.

## Крайние случаи и подводные камни

- **Маска должна быть устойчивой.** Если при извлечении маска отличается от встраивания, сообщение разваливается. Либо маска вычисляется из стего тем же детерминированным способом, либо передаётся как ключ.
- **Порог — секрет.** Процентиль/порог выбора «сложных» пикселей может быть частью ключа.
- **Ёмкость падает.** Адаптивность снижает доступную ёмкость: прятать можно только в части пикселей.
- **HUGO/WOW не для CTF «в лоб».** Их реализации тяжёлые; в задачах чаще встречаются упрощения — смотрите на подозрительные области визуально.
- **JPEG-устойчивость.** Пространственные адаптивные схемы так же нежны к JPEG, как LSB; для устойчивости нужны частотные методы.

## Что дальше / решение

- Изображение выглядит «слишком гладко», но что-то есть — проверьте битовые плоскости и края (адаптивные схемы оставляют след в высокочастотных областях).
- Нужен детект — используйте SRM-признаки и ML, классические RS/SPA тут не помогут.
- Хотите понять современный уровень — смотрите S-UNIWARD/HILL и STC-кодирование.
- Для CTF-практики чаще достаточно edge-adaptive с фиксированным порогом.

## Остатки и предсказание пикселей

Сердце адаптивной схемы — предсказание. Для каждого пикселя строится оценка `p̂` по соседям, и остаток `r = x − p̂` показывает, насколько пиксель «выбивается». В гладкой области предсказание точное (`r ≈ 0`), поэтому изменение заметно и стоимость высока. В текстуре `|r|` велик, изменение маскируется. Простейшие предикторы: среднее четырёх соседей, медиана, направленные фильтры. Чем лучше предиктор, тем точнее карта стоимости.

Практически стоимость агрегируют по нескольким направлениям, чтобы поймать и горизонтальные, и вертикальные края:

```python
import numpy as np
from scipy.ndimage import convolve

K_H = np.array([[0,0,0],[-1,2,-1],[0,0,0]], float)   # горизонтальный остаток
K_V = np.array([[0,-1,0],[0,2,0],[0,-1,0]], float)   # вертикальный остаток
r = convolve(img.astype(float), K_H) + convolve(img.astype(float), K_V)
cost = 1.0 / (np.abs(r) + 1e-6)      # большая стоимость там, где остаток мал
```

Чем меньше `cost`, тем «дешевле» изменить пиксель. Встраивание идёт в порядке возрастания стоимости.

## STC-кодирование на пальцах

Syndrome-Trellis Codes (STC) — способ встроить сообщение, минимизируя суммарную стоимость. Идея: у нас есть сообщение `m` и матрица `H` (свёрточная, «секретная»). Нужно найти вектор изменений `e` такой, что `H·e = m` и `Σ ρ_i·|e_i|` минимальна. Это задача декодирования по Витерби по решётке — решается динамическим программированием. На выходе получается «оптимальный» набор правок: схема трогает только дешёвые пиксели. Именно STC + хорошая стоимость = невидимость HUGO/WOW. Для CTF знать формулу не обязательно, но понимать, что «правки распределены не случайно, а по стоимости» — важно.

## Практика: HILL и S-UNIWARD

HILL (2015) строит стоимость двумя высокочастотными фильтрами: «дорого» там, где после фильтрации отклик мал. S-UNIWARD (2014) использует вейвлет-остатки и хорошо работает и на изображениях, и на JPEG. Обе схемы дают почти нулевую детектируемость у классических детекторов. В CTF их «полные» реализации встречаются редко, но упрощённый HILL легко написать самому: два свёрточных фильтра + агрегация + порог. Если задача явно про современную стеганографию, ожидайте именно адаптивный подход.

## Чек-лист анализа адаптивного встраивания

1. Проверьте, не спрятано ли в гладких областях (там адаптив ничего не пишет) — сравните локальную статистику.
2. Постройте карту остатков и посмотрите, нет ли аномального «шума» только в текстурах.
3. Примените SRM-признаки, если есть ML-детектор.
4. Помните: извлечение без знания схемы/стоимости почти невозможно — ищите утечку параметров (порог, seed, маску) в задаче.
5. Если схема — «игрушечная» edge-adaptive, воспроизведите её с тем же порогом.

## Сравнение адаптивных схем между собой

Все адаптивные схемы делят одну идею — «прячь там, где дешевле», — но различаются функцией стоимости. Edge-adaptive проста и груба; HUGO использует взвешенные остатки; WOW — направленные вейвлеты; S-UNIWARD и HILL — более современные вариации. Практическое следствие для CTF: чем современнее схема, тем меньше шансов у автоматических детекторов и тем важнее найти утечку параметров (порог, seed, стоимость) в условии. Если задача явно про «невидимую» стеганографию, ожидайте адативный подход и готовьтесь воспроизводить его «игрушечную» версию, а не искать готовый инструмент.

## Итог по адаптивному встраиванию

Адаптивное встраивание — современный стандарт незаметной стеганографии. Его суть: не «прятать везде», а «прятать там, где это статистически невидимо». Если вы встретили изображение, которое выглядит абсолютно чистым для всех классических детекторов, но подозрительно текстурировано, — это повод искать адаптивную схему и её параметры, а не считать задачу пустой.
