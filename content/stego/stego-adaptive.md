## Вопрос, с которого всё начинается

Тебе дали `cover.png`. Ты прогоняешь `zsteg -a`, `steghide`, `stegsolve` — всё пусто. Классический LSB-анализ не находит ничего, хи-квадрат показывает «чистое» изображение. Но задача намекает, что данные есть. Как их спрятать так, что даже детекторы молчат?

Ответ: **адаптивное встраивание**. Вместо «прятать везде понемногу» данные кладут только туда, где изменение статистически незаметно — в текстуры и края. Разберём, как это работает.

## Наш пример: cover.png, «пустой» по zsteg

Обычный **LSB** (Least Significant Bit, младший бит) меняет младший бит каждого пикселя равномерно. Но равномерность — это и есть уязвимость: гладкие области (небо, кожа) чувствительны к любым правкам, а текстурированные (трава, листва) их маскируют. Адаптивные схемы формализуют эту интуицию: каждой точке приписывается **стоимость** изменения, и данные встраивают так, чтобы суммарная стоимость была минимальной.

## Шаг 1: что такое функция стоимости

Для каждого пикселя `x_i` вычисляется стоимость `ρ_i` — насколько заметно будет его изменить. В гладкой области `ρ_i` велика (изменение видно), в текстуре — мала. Задача встраивания — выбрать позиции и знаки изменений, минимизируя `Σ ρ_i · |изменение_i|` при заданной длине сообщения.

Стоимость считают по **остаткам** изображения: сначала строится предсказание пикселя по соседям, затем остаток `residual = x − prediction`. Большой остаток = текстура или край = дёшево прятать.

```python
import numpy as np
from scipy.ndimage import convolve

K_H = np.array([[0,0,0],[-1,2,-1],[0,0,0]], float)   # горизонтальный остаток
K_V = np.array([[0,-1,0],[0,2,0],[0,-1,0]], float)   # вертикальный остаток
r = convolve(img.astype(float), K_H) + convolve(img.astype(float), K_V)
cost = 1.0 / (np.abs(r) + 1e-6)      # большая стоимость там, где остаток мал
```

Чем меньше `cost`, тем «дешевле» изменить пиксель. Встраивание идёт в порядке возрастания стоимости.

## Шаг 2: edge-adaptive — прячем по контурам

Простейшая адаптивная идея: прятать вблизи **краёв**, где яркость резко меняется. Для каждого пикселя считают локальный градиент (например, оператором Собеля) и встраивают только туда, где градиент выше порога.

```python
import numpy as np
from PIL import Image
from scipy.ndimage import sobel

def residual(img):
    gx, gy = sobel(img, axis=1), sobel(img, axis=0)
    return np.hypot(gx, gy)

cover = np.array(Image.open("cover.png").convert("L")).astype(np.int16)
msg = np.unpackbits(np.frombuffer(b"flag{adaptive}", dtype=np.uint8))
mask = residual(cover) > np.percentile(residual(cover), 70)
flat, mflat = cover.reshape(-1), mask.reshape(-1)
pos = np.where(mflat)[0]
stego = flat.copy()
for bit, p in zip(msg, pos):
    stego[p] = (stego[p] & ~1) | bit
Image.fromarray(stego.reshape(cover.shape).astype(np.uint8)).save("stego.png")
```

`sobel` даёт градиент по осям, `np.percentile(..., 70)` выбирает «верхние 30% по сложности». Извлечение пересчитывает маску из стего-изображения — это «общий секрет» схемы.

```python
s = np.array(Image.open("stego.png").convert("L")).astype(np.int16)
m2 = residual(s) > np.percentile(residual(s), 70)
bits = s.reshape(-1)[m2.reshape(-1)] & 1
print(np.packbits(bits).tobytes()[:40])
```

## Шаг 3: HUGO и WOW

**HUGO** (Highly Undetectable steGO) считает стоимость как взвешенную сумму остатков по нескольким направленным фильтрам. **WOW** (Wavelet Obtained Weights) улучшает её: стоимость — агрегация откликов направленных вейвлет-фильтров. Идея — прятать там, где локальная структура «непредсказуема во всех направлениях».

| Схема | Основа стоимости | Стойкость к RS/SPA |
|---|---|---|
| Edge-adaptive | градиент | низкая |
| HUGO | взвешенные остатки | высокая |
| WOW | направленные вейвлеты | очень высокая |
| S-UNIWARD | вейвлет-остатки | очень высокая |

## Шаг 4: STC — как распределяются правки

**STC** (Syndrome-Trellis Codes) — способ встроить сообщение, минимизируя суммарную стоимость. Есть сообщение `m` и «секретная» свёрточная матрица `H`; нужно найти вектор изменений `e` такой, что `H·e = m` и `Σ ρ_i·|e_i|` минимальна. Это решается динамическим программированием (декодирование Витерби). Для CTF формулу знать не обязательно, но важно понимать: правки распределены **не случайно, а по стоимости**.

## Шаг 5: почему классические детекторы слабы

Детекторы вроде **RS** и **SPA** проверяют низкоуровневые статистики пикселей. Адаптивные схемы их сохраняют: они не трогают гладкие области, поэтому распределение «выглядит» естественным. Для детекта используют **SRM** (Spatial Rich Model) — сотни признаков, которые скармливают классификатору (ML). Но даже SRM против WOW/UNIWARD даёт заметный процент ошибок.

## Если не сработало

- **Маска должна быть устойчивой.** Если при извлечении маска отличается от встраивания — сообщение развалится. Либо маска детерминированно считается из стего, либо передаётся как ключ.
- **Порог — секрет.** Процентиль выбора «сложных» пикселей может быть частью ключа.
- **Ёмкость падает.** Адаптивность снижает доступную ёмкость: прятать можно только в части пикселей.
- **HUGO/WOW не для CTF «в лоб».** Их реализации тяжёлые; в задачах чаще встречаются упрощения.
- **JPEG-устойчивость.** Пространственные адаптивные схемы так же нежны к JPEG, как LSB.

## Предсказание пикселей — сердце схемы

Для каждого пикселя строится оценка `p̂` по соседям, и остаток `r = x − p̂` показывает, насколько пиксель «выбивается». В гладкой области предсказание точное (`r ≈ 0`), поэтому изменение заметно и стоимость высока. В текстуре `|r|` велик, изменение маскируется. Простейшие предикторы: среднее четырёх соседей, медиана, направленные фильтры. Чем лучше предиктор, тем точнее карта стоимости.

## Инструменты

- **`numpy` + `scipy.ndimage`** — градиенты, остатки, фильтры;
- **`scikit-image`** — фильтры (Sobel, Gabor), вейвлеты;
- **реализации HUGO/WOW** — MATLAB/Python-скрипты авторов (в CTF чаще «игрушечные» версии);
- **`stegdetect`** — старый детектор; против jsteg полезен, против HUGO/WOW бесполезен;
- **SRM-детекторы** — проверка незаметности (Rich Models + классификатор).

## Чек-лист анализа адаптивного встраивания

1. Проверь, не спрятано ли в гладких областях (там адаптив ничего не пишет) — сравни локальную статистику.
2. Построй карту остатков и поищи аномальный «шум» только в текстурах.
3. Примени SRM-признаки, если есть ML-детектор.
4. Помни: извлечение без знания схемы/стоимости почти невозможно — ищи утечку параметров (порог, seed, маску) в задаче.
5. Если схема «игрушечная» edge-adaptive — воспроизведи её с тем же порогом.

## Что мы теперь знаем

1. Адаптивное встраивание прячет данные там, где **изменение незаметно** (текстуры, края).
2. **Функция стоимости** `ρ_i` формализует «насколько заметна правка».
3. Стоимость считают по **остаткам** предсказания пикселя.
4. HUGO/WOW/S-UNIWARD различаются фильтрами; **STC** оптимизирует правки.
5. Детект — через **SRM** и ML, а не через RS/SPA.

## Почему адаптивные схемы труднее детектировать

Классический LSB меняет пиксели **равномерно**: каждый пиксель с одинаковой вероятностью трогается, и статистика всего изображения сдвигается предсказуемо. Детектор это видит: гистограмма пар значений выравнивается, шум становится однородным, RS-анализ даёт устойчивый сигнал. Адаптивные схемы ломают эту предсказуемость.

Идея адаптивности — **встраивать туда, где искажение наименее заметно**, и не встраивать туда, где оно бросится в глаза. Для этого каждому пикселю (или коэффициенту) приписывают **функцию стоимости** `ρ`: она оценивает, насколько изменение этого элемента заметно. Дальше задача — минимизировать суммарную стоимость при заданном числе изменений. Классические схемы: **edge-adaptive** (меняем у контуров и в текстурах, не трогаем гладкие области), **HUGO** (стоимость через разницу с предсказанием по SPAM-признакам), **WOW** (стоимость через направленные фильтры, штрафует изменения вдоль контуров). Финальный шаг — **STC** (Syndrome-Trellis Codes), который распределяет нужные правки так, чтобы суммарная стоимость была минимальна.

Результат: изменения «размазаны» по шумным областям, а гладкие остаются нетронутыми. Детекторы на простых признаках (RS, chi-square) слабеют, и нужен **богатый набор признаков** (SRM — 34671 признака) с классификатором. Отсюда практический вывод для CTF: если контейнер выглядит «пустым» для `zsteg`, это не значит, что данных нет — возможно, применена адаптивная схема, и нужны специализированные инструменты.

## Частые вопросы

**Как узнать, что применена адаптивная схема?** Прямо — почти никак; косвенно — простые детекторы не срабатывают, а классические LSB-инструменты ничего не находят. В CTF такие схемы редки: они требуют сложного кода.

**Что такое SRM?** Spatial Rich Model — набор из десятков тысяч фильтров-признаков, которые улавливают микроскопические искажения; используется в современных стегоаналитических детекторах.

**Почему STC важен?** Он решает задачу оптимального распределения правок: при заданном числе изменений выбирает позиции с наименьшей суммарной стоимостью, что и даёт незаметность.

**Как извлечь из адаптивной схемы?** Нужны те же параметры, что и при встраивании: ключ, функция стоимости, схема STC. Без них извлечение невозможно — поэтому в задачах либо дают код, либо применяют более простую схему.
