Типографика — это слой между текстом и его отображением, и он полон «настраиваемых» величин: расстояние между парами букв (кернинг), общий трекинг, выбор лигатур, альтернативные глифы, вариативные оси. Все эти параметры можно слегка варьировать, не меняя смысл текста, — а значит, использовать как канал. В отличие от сокрытия в самом шрифте (`stego-fonts`), здесь данные живут в *вёрстке*: два документа с одинаковым текстом, но разным кернингом, могут нести разные метки. Так работают системы отслеживания утечек и канареечные метки.

## Кернинг и трекинг как канал

Кернинг — коррекция расстояния между конкретными парами символов (например, `AV`, `To`). Трекинг — равномерное изменение межбуквенного расстояния. Оба параметра не видны «на глаз» при малых величинах, но кодируют числа.

Схема сокрытия: каждому символу/паре приписывается небольшой сдвиг (`±0.01em`), который кодирует бит. Получатель измеряет позиции глифов и восстанавливает биты. Это устойчиво к копированию текста (текст не меняется), но ломается при переформатировании.

```python
# приблизительная модель: позиции глифов в PDF/растре
positions = [10.0, 16.02, 22.01, 28.03, 34.00]  # x-координаты
# кодирование бита: смещение вверх/вниз от "идеальной" сетки
import numpy as np
ideal = np.round(np.array(positions))
bits = ((np.array(positions) - ideal) > 0).astype(np.uint8)
print(np.packbits(bits).tobytes())
```

В реальном документе позиции берут из PDF (`pdffonts`, `mutool draw -F trace`) или из SVG/DOCX.

## Лигатуры и альтернативные глифы

OpenType поддерживает фичи `liga` (лигатуры), `dlig`, `salt` (stylistic alternates), `ss01`–`ss20`. Один и тот же символ может иметь несколько глифов; выбор варианта не меняет текст, но кодирует данные. Схема:

- **Лигатура vs раздельные буквы.** `fi` как лигатура = 1, раздельно = 0.
- **Stylistic set.** Включён `ss01` или нет — бит.
- **Альтернативный глиф.** Для `a` выбирается один из двух вариантов.

Проверка в шрифте:

```bash
ttx -t GSUB font.otf        # смотрим таблицу подстановок
python3 - <<'PY'
from fontTools.ttLib import TTFont
f = TTFont("font.otf")
if "GSUB" in f:
    print("features:", [fr.FeatureTag for fr in f["GSUB"].table.FeatureList.FeatureRecord])
PY
```

Вывод:

```
features: ['liga', 'salt', 'ss01']
```

## Вариативные шрифты (variable fonts)

Variable fonts содержат несколько «мастеров» и оси (`wght`, `wdth`, `slnt`, `ital`, кастомные). Значение оси можно менять непрерывно. Это новый канал: экземпляр шрифта с `wght=400.3` вместо `400.0` кодирует данные в дробной части. Инструменты:

```bash
python3 - <<'PY'
from fontTools.ttLib import TTFont
f = TTFont("var.ttf")
if "fvar" in f:
    for a in f["fvar"].axes:
        print(a.axisTag, a.minValue, a.defaultValue, a.maxValue)
PY
# wght 100.0 400.0 900.0
```

Значения осей, лежащие вне «круглых» чисел, — признак сокрытия.

## OpenType-фичи в документах

В DOCX/PDF можно включать/выключать фичи на уровне участков текста. `w:rPr` в OOXML содержит настройки; PDF — словарь шрифта. Разница между «ожидаемым» и «фактическим» набором фич кодирует биты. Сравнивайте два документа с одинаковым текстом.

## Инструменты и команды

- **`fontTools`/`ttx`** — разбор GSUB/GPOS/fvar, извлечение таблиц.
- **`FontForge`** — визуальный просмотр кернинга и глифов.
- **`pdffonts`, `mutool draw -F trace`, `qpdf --qdf`** — позиции и фичи в PDF.
- **`pdfplumber`** — координаты символов в PDF (Python).
- **`python-docx`** — вёрстка DOCX, rPr-настройки.
- **`ots-sanitize`** — валидация шрифтов.
- **`diff`** — сравнение двух «одинаковых» документов.

## Разобранный пример: кернинг-канал в PDF

```bash
python3 - <<'PY'
import pdfplumber
bits = []
with pdfplumber.open("doc.pdf") as pdf:
    for ch in pdf.pages[0].chars:
        x = ch["x0"]
        frac = x - round(x)
        if abs(frac) > 1e-6:
            bits.append(1 if frac > 0 else 0)
import numpy as np
print(np.packbits(np.array(bits, dtype=np.uint8)).tobytes()[:40])
PY
# -> b'flag{kerning}'
```

Идея: символы, стоящие «ровно», не кодируют; символы с микро-сдвигом кодируют бит знаком сдвига. На практике сетку восстановить сложнее (нужна модель вёрстки), но принцип тот же.

## Fingerprinting и канареечные метки

Кернинг/трекинг используют для «уникализации» копии документа на каждого получателя: у каждого своя микро-вариация, по которой можно отследить утечку. Это не совсем стеганография, но техника та же. При анализе: сравните два экземпляра одного документа — различия в позициях/фичах и есть метка.

## Крайние случаи и подводные камни

- **Переформатирование убивает данные.** Копирование текста в другой редактор пересчитает кернинг.
- **Шрифт-подстановка.** Если у читателя нет шрифта, метрики заменятся — данные пропадут.
- **Слишком большие сдвиги заметны.** Держите величину в пределах десятых долей пикселя/em.
- **PDF-рендер.** Позиции в `pdftotext` не сохраняются; нужен `pdfplumber`/`mutool`.
- **Лигатуры скрыты от поиска.** Текст с лигатурами плохо ищется — учитывайте.
- **fvar-оси.** Изменение веса меняет вид — при большом отклонении заметно.

## Что дальше / решение

- Два «одинаковых» документа — сравните через `diff`/`pdfplumber` на микро-сдвиги.
- Подозрительный шрифт — `ttx` на GSUB/GPOS/fvar.
- Текст не ищется — возможны лигатуры/альтернативные глифы.
- Данные не в самом шрифте — смотрите вёрстку (`stego-fonts` — про файл шрифта).
- Watermark-задача — ищите уникальную вариацию между копиями.

## Справочная таблица

| Слой | Параметр | Канал |
|---|---|---|
| Кернинг | пары символов | микро-сдвиг |
| Трекинг | межбуквенное | равномерный сдвиг |

## Сравнение вёрсток двух документов

Основной приём анализа типографической стеганографии — сравнить два «одинаковых» документа и найти микро-различия. Для PDF удобно извлекать координаты символов и вычитать их.

```python
import pdfplumber
def positions(path):
    out = []
    with pdfplumber.open(path) as pdf:
        for page in pdf.pages:
            for ch in page.chars:
                out.append((ch["text"], round(ch["x0"], 4), round(ch["top"], 4)))
    return out

a = positions("doc_v1.pdf")
b = positions("doc_v2.pdf")
for (ta, xa, ya), (tb, xb, yb) in zip(a, b):
    if (xa, ya) != (xb, yb):
        print(ta, "moved:", (xa,ya), "->", (xb,yb))
```

Различия в `x0` порядка 0.01–0.1 pt — это канал: знак сдвига кодирует бит. Различия в `top` — вертикальный кернинг. В DOCX аналогично сравнивают `w:rPr` (свойства участка) и `w:spacing` (межбуквенный интервал) через распаковку OOXML:

```bash
unzip -o doc.docx -d doc_x && grep -o 'w:spacing w:val="[-0-9]*"' doc_x/word/document.xml
```

## Кернинг-таблицы в шрифте

В самом шрифте кернинг лежит в таблице `kern` (TrueType) или парах `GPOS` (OpenType). Их тоже можно модулировать: значения пар слегка варьируют, кодируя данные. Разбор:

```bash
ttx -t kern font.ttf        # TrueType kern
ttx -t GPOS font.otf        # OpenType positioning
python3 - <<'PY'
from fontTools.ttLib import TTFont
f = TTFont("font.ttf")
if "kern" in f:
    for st in f["kern"].kernTables:
        items = list(st.kernTable.items())[:10]
        print(items)
PY
```

Аномально «некруглые» значения кернинга (например, −41 вместо −40) — признак встраивания.

## Водяные знаки в вёрстке

Схемы fingerprinting встраивают в документ уникальный код через микро-вариации кернинга, трекинга и выбора глифов. Задача аналитика — обнаружить сам факт метки и, если возможно, восстановить код. Методика:

1. Получите два экземпляра документа (у разных получателей).
2. Выровняйте текст (одинаковый ли он).
3. Сравните координаты символов и набор OpenType-фич.
4. Различия = метка; повторяющиеся паттерны = структура кода.
5. Сопоставьте позиции различий с идентификаторами получателей, если они есть.

В реальных системах (например, отслеживание утечек PDF) метка может быть закодирована в паре «символ-сдвиг» и защищена ECC, чтобы переживать копирование части текста.

## Вариативные шрифты на практике

Variable fonts дают непрерывные оси — тонкий, но мощный канал. Экземпляр шрифта инстанцируется при конкретных значениях осей; дробные значения кодируют данные.

```python
from fontTools.varLib.instancer import instantiateVariableFont
from fontTools.ttLib import TTFont
f = TTFont("var.ttf")
inst = instantiateVariableFont(f, {"wght": 400.37})   # дробное значение!
inst.save("instance.ttf")
```

Если в задаче есть несколько «экземпляров» одного вариативного шрифта, сравните значения осей — их дробные части и есть сообщение. Обратите внимание: инстанцирование «съедает» вариативность, поэтому в CTF чаще дают сам вариативный файл с необычными значениями по умолчанию.

## Шрифт как контейнер vs вёрстка как канал

Важно разделять два уровня. Сокрытие *в файле шрифта* (таблицы, контуры, name) живёт внутри TTF/OTF и не зависит от документа. Сокрытие *в вёрстке* (кернинг, трекинг, выбор фич) — это данные в документе, который лишь *использует* шрифт. Первое ищут в шрифте (`ttx`), второе — в документе (`pdfplumber`, OOXML). В CTF встречается и то, и другое; начните с `file` — если дан TTF/OTF, это файл шрифта; если PDF/DOCX — вёрстка.

## Извлечение и модификация вёрстки

Для PDF координаты символов извлекают `pdfplumber`/`mutool`; для DOCX — распаковывают OOXML и смотрят `w:spacing`/`w:kern`/`w:rPr`. Пример по DOCX:

```bash
unzip -o doc.docx -d doc_x
grep -o 'w:kern w:val="[0-9]*"' doc_x/word/document.xml | sort | uniq -c
grep -o 'w:spacing w:val="[-0-9]*"' doc_x/word/document.xml | head
```

Нестандартные значения (`kern` не 0/2, «дробный» spacing) — признак канала.

## Частые ошибки

- **Поиск данных в тексте.** В типографической стеганографии текст «чистый»; данные в метриках.
- **Переформатирование.** Открытие в другом редакторе пересчитает вёрстку и убьёт данные.
- **Один инструмент.** PDF-рендер (`pdftotext`) не даёт координат — нужен `pdfplumber`.
- **Игнор OpenType-фич.** `liga`/`salt`/`ss01` не видны в тексте, но кодируют биты.
- **Вариативные оси.** Дробные значения `wght`/`wdth` легко пропустить.

Практический порядок: определите уровень (шрифт/вёрстка) → сравните с эталоном → ищите микро-различия в координатах и фичах → декодируйте.
