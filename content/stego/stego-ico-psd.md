## Вопрос, с которого всё начинается

В задаче дали `app.ico` — обычную иконку приложения. Открываешь — маленькая картинка. `zsteg` по видимой картинке ничего не находит. Но `file` пишет «4 icons»: внутри **четыре** изображения. Может, данные в одном из них?

Да. ICO и PSD — «многослойные» форматы: ICO содержит несколько вложенных картинок, а PSD — слои и каналы. Любой из них может нести данные. Разберём на нашем примере.

## Наш пример: app.ico

```bash
$ file app.ico
app.ico: MS Windows icon resource - 4 icons, 16x16 ..., 32x32 ...
```

`4 icons` — значит, в файле четыре записи. Иконка выглядит как одна картинка, потому что система выбирает подходящий размер, но внутри лежат все. Посмотрим на структуру.

## Шаг 1: структура ICO — директория записей

**ICO** начинается с 6-байтной шапки:

- 2 байта — `reserved` (0);
- 2 байта — `type` (1 = ICO, 2 = CUR — курсор);
- 2 байта — `count` — число изображений.

За шапкой идёт **директория**: по 16 байт на каждое изображение (`width, height, colors, reserved, planes, bpp, size, offset`). Смотрим начало файла:

```bash
$ xxd app.ico | head -3
00000000: 0000 0100 0400 1010 0000 0100 2000 5404  ............ .T.
00000010: 0000 4600 0000 2020 0000 0100 2000 6410  ..F...  .... .d.
00000020: 0000 9a04 0000 3030 0000 0100 2000 7424  ......00.... .t$
```

Читаем: `0000 0100 0400` — reserved=0, type=1, count=4. Дальше идут записи директории: `1010 0000 0000 0100 2000 5404 0000 4600 0000` — это первая запись (16×16, bpp=32, размер 0x454=1108, смещение 0x46=70). Так в шапке видно всю карту файла.

## Шаг 2: извлекаем записи

Разберём директорию программно — прочитаем все записи и их смещения:

```python
import struct
d = open("app.ico", "rb").read()
_, typ, cnt = struct.unpack("<HHH", d[:6])
print("type", typ, "count", cnt)
for i in range(cnt):
    w, h, _, _, pl, bpp, size, offset = struct.unpack("<BBBBHHII", d[6+i*16:6+(i+1)*16])
    print(f"entry {i}: {w or 256}x{h or 256} bpp={bpp} size={size} off={offset}")
```

```
type 1 count 4
entry 0: 16x16 bpp=32 size=1108 off=70
entry 1: 32x32 bpp=32 size=4196 off=1178
entry 2: 48x48 bpp=32 size=9332 off=5374
entry 3: 256x256 bpp=32 size=262804 off=14706
```

`w or 256` — хитрость формата: ширина 0 в записи означает 256 (в байт не влезает). Каждая запись — отдельное изображение; для размеров ≥256 оно хранится как **PNG** (можно проверить по сигнатуре `\x89PNG`), для меньших — как DIB (BMP без заголовка).

## Шаг 3: LSB в большой PNG-записи

Маленькие записи (16×16) слишком малы для полезной нагрузки, а вот 256×256 — идеальный носитель. Откроем последнюю запись как PNG и проверим младшие биты:

```python
import io, numpy as np
from PIL import Image
w, h, _, _, pl, bpp, size, offset = struct.unpack("<BBBBHHII", d[6+3*16:6+4*16])
im = np.array(Image.open(io.BytesIO(d[offset:offset+size])).convert("RGBA")).reshape(-1)
data = np.packbits(im & 1).tobytes()
j = data.find(b"flag{")
print(data[j:j+20])
```

```
b'flag{ico_png_entry}\x90'
```

Флаг был в младших битах 256-пиксельной PNG-записи. Маленькие записи чистые, поэтому «на глаз» закладку не видно. Практика: прогоняй **все** записи, а не только первую.

## Шаг 4: PSD — многослойный формат

**PSD** (Photoshop Document) — редакторский формат со слоями, каналами и масками. Начинается с сигнатуры `8BPS`:

```python
import struct
d = open("test.psd", "rb").read()
print("signature:", d[:4], "version:", struct.unpack(">H", d[4:6])[0])
print("channels:", struct.unpack(">H", d[12:14])[0], "size:", struct.unpack(">II", d[14:22]))
print("depth,color:", struct.unpack(">HH", d[22:26]))
```

```
signature: b'8BPS' version: 1
channels: 3 size: (64, 64)
depth,color: (8, 3)
```

Поля: `8BPS` — сигнатура, `version` (1 = PSD, 2 = PSB — большой документ), число каналов, высота/ширина, глубина и цветовой режим. Дальше идут секции: Color Mode Data, Image Resources, Layer and Mask Information и Image Data. Слои описаны в Layer and Mask Information.

## Шаг 5: скрытые слои и маски

Самый частый приём в CTF — **скрытый слой** (`visible=False`) с текстом или картинкой. Второй — данные в канале, который не отображается (например, лишний alpha), или в маске слоя. Список слоёв и их видимость достаются через библиотеку `psd-tools`:

```python
from psd_tools import PSDImage
psd = PSDImage.open("poster.psd")
print([(l.name, l.visible) for l in psd])
```

```
[('background', True), ('logo', True), ('hidden', False)]
```

Слой `hidden` не отображается — но он есть. Форсируем видимость и композитим его в PNG:

```python
for i, layer in enumerate(psd):
    layer.visible = True
    layer.composite().save(f"layer_{i}_{layer.name}.png")
```

Дальше — обычный `zsteg` по каждому сохранённому слою.

## Шаг 6: смарт-объекты и дописанные данные

- **Смарт-объект** — слой, внутри которого лежит целый вложенный файл (другой PSD, PNG, вектор). Это буквально «файл в файле»; `psd-tools` умеет его достать (`layer.smart_object.open()`).
- **PSB** (`version=2`) — большой документ с 64-битными размерами; часть старых парсеров его не открывает — «слепая зона».
- **Дописанные данные** после секции Image Data ищутся так же, как везде: `binwalk poster.psd`, `grep -aboP 'flag\{|PK\x03\x04' poster.psd`.

## Шаг 7: неиспользуемые поля и пайплайн

В записи директории ICO есть поля, которые рендерер почти не проверяет: `planes` (обычно 1) и `colors` (число цветов палитры, 0 для true-color). Аномальные значения там — сигнал, что в них что-то закодировано. Проверяй директорию `xxd`-ом и смотри на необычные байты.

Пайплайн для PSD: `file` (версия — PSD или PSB) → `psd-tools` для списка слоёв → форсировать `visible` и композитить **все** слои → `zsteg` по каждому → извлечь смарт-объекты → `binwalk`/`grep -aboP` по файлу → проверить Image Resources. Для ICO: разобрать директорию, извлечь все записи, `zsteg` по каждой, затем `binwalk`/`grep -aboP` на «мусор» между записями. В обоих форматах главное правило одно: не доверяй одной видимой картинке — данные в скрытом слое или вложенном изображении.

## Что мы теперь знаем

1. ICO — контейнер из нескольких изображений: 6-байтная шапка + 16-байтные записи директории.
2. Ширина 0 в записи означает 256; крупные записи хранятся как PNG.
3. Каждая запись — отдельный носитель; проверяй все, а не только первую.
4. PSD начинается с `8BPS`; версия 2 = PSB (64-битные размеры).
5. Скрытый слой (`visible=False`) — самый частый приём в PSD; форсируй видимость и композити.
6. Смарт-объекты хранят вложенные файлы — обрабатывай рекурсивно.
7. В обоих форматах проверяй дописанные данные (`binwalk`, `grep -aboP`).
