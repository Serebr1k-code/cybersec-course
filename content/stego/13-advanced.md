## Вопрос, с которого всё начинается

Бывает, что все «обычные» инструменты пусты. `zsteg` молчит, `strings` чист, `binwalk` ничего не находит — а флаг где-то есть. Значит, применён **продвинутый** метод: данные спрятаны не в пикселях, а в коэффициентах преобразования или в структуре формата.

В этом уроке мы разберём один JPEG, где обычные методы не работают, и пройдём путь до флага.

## Наш пример: cover.jpg

Пробуем стандартный инструмент:

```
$ steghide info cover.jpg
"cover.jpg": no data
```

Пусто. Теперь спросим у **стегоанализа** — программы, которая определяет, каким алгоритмом спрятаны данные. Инструмент `stegdetect` умеет различать jsteg, outguess, jphide и другие методы.

```
$ stegdetect cover.jpg
cover.jpg: jsteg
```

`stegdetect` говорит: похоже на **jsteg**. Это метод, работающий с DCT-коэффициентами JPEG. Применим соответствующий инструмент:

```
$ jsteg reveal cover.jpg out.txt
$ cat out.txt
flag{dct_jsteg}
```

Ключевой навык здесь — **определить метод**, а потом взять под него инструмент. Разберём, почему это работает.

## Шаг 1: что такое DCT и почему данные не в пикселях

JPEG сжимает изображение с потерями. Он разбивает картинку на блоки 8×8 пикселей и для каждого блока считает **дискретно-косинусное преобразование** (DCT) — раскладывает блок на 64 коэффициента (числа). Затем коэффициенты **квантуются** (делятся на табличные значения и округляются) — именно здесь теряется информация и появляется сжатие.

Данные прячут не в пикселях, а в этих коэффициентах:

- **JSteg** заменяет младший бит ненулевых коэффициентов;
- **F5** уменьшает модуль коэффициента;
- **OutGuess** прячет данные и восстанавливает статистику, чтобы обмануть стегоанализ.

Чтобы прочитать коэффициенты, нужен полный JPEG-декодер до стадии квантованных коэффициентов. Именно это делают `jsteg`, `outguess`, `F5` изнутри. Своими руками — через `jpegio`:

```python
import jpegio
j = jpegio.read('image.jpg')
coef = j.coef_arrays[0]
print('ненулевых коэффициентов:', (coef != 0).sum())   # ~ ёмкость метода
```

## Шаг 2: карта частотных методов

| Метод | Область | Детект | Ключ |
|---|---|---|---|
| JSteg | DCT | лёгкий | нет |
| OutGuess 0.2 | DCT | трудный | да |
| F5 | DCT | трудный | да |
| Model-based | DCT | очень трудный | да |
| Spread-spectrum | DCT/аудио | трудный | да |
| DWT (JPEG2000) | вейвлеты | средний | часто |

Определив метод (`stegdetect`), ты выбираешь инструмент и понимаешь, нужен ли ключ.

## Шаг 3: spread-spectrum — «размазать» сигнал

**Spread-spectrum** («широкополосная модуляция») размазывает сообщение по широкому диапазону частот с помощью псевдослучайной последовательности (**PN-кода**). Приёмник коррелирует сигнал с тем же PN-кодом и восстанавливает сообщение. Без PN-кода сигнал выглядит как обычный шум.

Признак в задаче: высокая энтропия без видимой структуры, при этом обычные методы пусты. Нужен ключ/PN-код.

## Шаг 4: структурные каналы — данные вне пикселей

Отдельный класс — использование **структурных** свойств формата:

- порядок записей **палитры** (переставили цвета — поправили индексы);
- неиспользуемые («мусорные») цвета палитры;
- порядок объектов и паддинг между структурами.

Визуально картинка не меняется вообще, поэтому такие каналы часто пропускают. Их ищут разбором структуры формата, а не пиксельными инструментами.

## Шаг 5: эзотерические носители

Стеганография не ограничена медиа. Данные прячут в чём угодно, где есть «свободный выбор»:

- **Шахматы** — выбор хода кодирует бит;
- **Ноты / MIDI** — высоты и длительности;
- **Эзотерические языки** (Brainfuck, Whitespace) — программа сама является сообщением;
- **Списки, стихи, рецепты** — выбор слова.

Общий приём: найди **степени свободы** (где возможны эквивалентные варианты) и сопоставь выборы с битами: два варианта = 1 бит, четыре = 2 бита.

## Шаг 6: комбинированные (многослойные) задачи

Реальные задачи часто многослойны: стего → архив → крипто. Порядок всегда один: **сначала извлечение, потом распаковка, потом расшифровка**. Пример цепочки: LSB в PNG → ZIP → пароль из метаданных → AES.

Не пытайся угадать финал — иди по слоям и веди журнал находок.

## Если не сработало

- Определи формат и тип носителя.
- Прогони `stegdetect`/`stegoveritas`.
- Проверь обычные методы первыми (LSB, метаданные, appended) — они дешевле.
- Для частотных методов возьми соответствующий инструмент и ключ.
- Ищи структурные аномалии (палитра, порядок, паддинг).

## Что мы теперь знаем

1. Продвинутая стего работает в частотной области (DCT/DWT) или со структурой.
2. `stegdetect` определяет метод — это экономит время.
3. JSteg/F5/OutGuess прячут данные в DCT-коэффициентах JPEG.
4. Spread-spectrum «размазывает» сигнал по PN-коду (нужен ключ).
5. Многослойные задачи решаются по слоям: извлечь → распаковать → расшифровать.

## Шаг 7: модельная стеганография

Самый продвинутый класс методов — **модельные**. Они строят статистическую модель естественного изображения и встраивают данные так, чтобы распределение осталось «естественным». Методы **MB**, **HUGO**, **S-UNIWARD** минимизируют «стоимость» каждого изменения по набору стегоаналитических признаков, поэтому их почти невозможно детектировать классическими тестами.

В CTF такие методы редки (сложны), но их идея объясняет, почему «стегоанализ молчит, а данные есть».

## Шаг 8: эзотерика — как искать «свободные выборы»

Общий приём для любого экзотического носителя: найти **степени свободы** — места, где возможны эквивалентные варианты. В шахматах это равнозначные ходы, в нотах — выбор длительности, в стихах — выбор синонима. Затем сопоставить выборы с битами: два варианта = 1 бит, четыре = 2 бита.

Навык «заметить, где есть выбор» универсален и для медиа, и для структурных каналов.

## Шаг 9: инструменты и таблица методов

| Метод | Область | Изменение | Детект | Ключ |
|---|---|---|---|---|
| JSteg | DCT | замена LSB | лёгкий | нет |
| OutGuess 0.2 | DCT | замена + восстановление | трудный | да |
| F5 | DCT | уменьшение + матрица | трудный | да |
| Model-based | DCT | синтез модели | очень трудный | да |
| Spread-spectrum | DCT/аудио | размазывание по PN | трудный | да |

Инструменты: `jsteg`, `outguess`, `F5.jar`, `steghide` (DCT-методы), `stegdetect`/`stegoveritas` (детект), `OpenPuff` (многоканальная стего).

## Шаг 10: практический чек-лист продвинутой задачи

1. Определи формат и тип носителя (`file`).
2. Прогони обычные методы первыми (LSB, метаданные, appended) — они дешевле.
3. `stegdetect`/`stegoveritas` — определи метод.
4. Для частотных методов возьми соответствующий инструмент и ключ.
5. Ищи структурные аномалии (палитра, порядок, паддинг).
6. Эзотерика — распознай «свободные выборы» в данных.
7. Многослойно — извлекай по слоям и веди журнал находок.

Ключевой навык — распознать класс метода и применить соответствующий инструмент, а не перебирать всё подряд.

- **CTF (Steganography):** задачи с «молчащими» инструментами — обычно частотные методы.
- **Watermarking / DRM:** понимание DCT/DWT — основа защиты контента.
- **Стегоанализ:** детект скрытых каналов в защите информации.
- **Misc-задачи:** эзотерические носители тренируют «мышление по алфавиту».
