PNG поддерживает альфа-канал (прозрачность). Прозрачные пиксели не видны глазу, но их RGB и альфа-значения существуют в файле — идеальный канал. Данные прячут в LSB альфы, в RGB полностью прозрачных пикселей, в отличиях между «невидимыми» областями. Инструменты: `zsteg` (канал `a`), `stegsolve` (Bit Plane по Alpha), скрипты на PIL.

## Каналы в альфе

- **LSB альфы:** младший бит alpha-байта.
- **Полностью прозрачные пиксели:** `alpha=0`, но RGB может нести данные (часто зануляют при сохранении — проверяйте).
- **MSB альфы:** иногда данные в старшем бите.
- **Разница alpha vs «ожидаемая»:** сглаженные края несут шум.

## Извлечение

```bash
# zsteg: канал a (alpha)
zsteg -E 'b1,a,lsb,xy' image.png
zsteg image.png | grep -i 'a,'
# stegsolve: Bit Plane → Alpha
```

```python
from PIL import Image
im = Image.open('image.png').convert('RGBA')
px = list(im.getdata())
# LSB альфы
bits = ''.join(str(p[3] & 1) for p in px)
print(bytes(int(bits[i:i+8],2) for i in range(0,len(bits)-7,8)))
# RGB прозрачных пикселей
bits2 = ''.join(str(p[0] & 1) for p in px if p[3] == 0)
```

## Премультипликация

При премультипликации RGB умножается на альфу; для прозрачных пикселей RGB может обнуляться. Если данные в RGB прозрачных пикселей «пропали» — значит, приложение премультиплицировало; ищите данные в других каналах или используйте оригинал.

## Разобранный пример

CTF: PNG с прозрачным фоном. Пентестер:
1. `zsteg image.png` → находит `b1,a,lsb,xy .. text: "..."`.
2. Извлекает и декодирует → флаг.

## Частые ошибки

- Смотреть только RGB, забывая альфу.
- Конвертировать PNG в JPG (теряется альфа и данные).
- Игнорировать RGB полностью прозрачных пикселей.
- Не проверять MSB альфы.

## Что делать дальше

- **LSB альфы** → zsteg `a`/скрипт.
- **RGB прозрачных** → извлеките по alpha==0.
- **Не сходится** → проверьте MSB, премультипликацию, другие каналы.
- **Пусто** → бит-плоскости в stegsolve.

## RGBA: полная модель каналов

PNG хранит пиксель как 4 байта: R, G, B, A. Каждый байт — 8 бит, каждый бит — потенциальный носитель. 4 канала × 8 бит = 32 бита на пиксель, из которых обычно занят лишь младший бит одного-двух каналов.

| Канал | Виден глазу | Частота использования в стего |
|-------|-------------|-------------------------------|
| R/G/B | да | LSB, битовые плоскости |
| Alpha (A) | нет (прозрачность) | **LSB альфы, MSB, RGB прозрачных** |
| Прозрачные пиксели | нет | RGB полностью прозрачных |

Важно: при конвертации PNG→JPG альфа **теряется целиком** (JPG не поддерживает прозрачность), поэтому конвертация в JPG уничтожает канал. Всегда работайте с исходным PNG.

## Извлечение LSB альфы (скрипт с вариантами)

```python
from PIL import Image
im = Image.open('image.png').convert('RGBA')
px = list(im.getdata())

def bits_to_bytes(bits):
    return bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))

# 1) LSB альфы, порядок пикселей слева-направо, сверху-вниз
b = ''.join(str(p[3] & 1) for p in px)
print('A lsb :', bits_to_bytes(b))

# 2) MSB альфы (старший бит)
b = ''.join(str((p[3] >> 7) & 1) for p in px)
print('A msb :', bits_to_bytes(b))

# 3) 2 младших бита альфы
b = ''.join(format(p[3] & 3, '02b') for p in px)
print('A 2lsb:', bits_to_bytes(b))

# 4) RGB полностью прозрачных пикселей (alpha == 0)
b = ''.join(str(p[0] & 1) for p in px if p[3] == 0)
print('RGB transparent:', bits_to_bytes(b))
```

Если текст «съезжает» — переберите offset (0..7), порядок бит (MSB↔LSB) и порядок обхода (по строкам/по столбцам).

## Полностью прозрачные пиксели: RGB-канал

Когда альфа = 0, пиксель невидим, но его RGB **может** храниться. Это классический канал: картинка выглядит пустой, а в RGB спрятан текст или другое изображение.

```python
from PIL import Image
im = Image.open('image.png').convert('RGBA')
W, H = im.size
out = Image.new('RGB', (W, H))
out.putdata([p[:3] for p in im.getdata()])   # игнорируем альфу
out.save('no_alpha.png')                      # проявить скрытое изображение
```

Если при сохранении редактором RGB прозрачных пикселей обнулился — данные «потеряны» именно из-за премультипликации (см. ниже), ищите оригинал.

## Премультипликация и «пропавшие» данные

Многие движки хранят цвет **премультиплицированным**: RGB' = RGB × A/255. Для A=0 это даёт RGB'=0, то есть цвет прозрачных пикселей затирается. Последствия:

- Данные в RGB прозрачных пикселей, «прошедшие» через такой пайплайн, обнуляются.
- Решение: искать исходный файл (до редактора) или данные в других каналах.
- Проверка: если `no_alpha.png` полностью чёрный, а файл выглядел «пустым», вероятна премультипликация.

## Бит-плоскости и stegsolve

```bash
# stegsolve: Bit Plane Slicer → выбрать канал (R/G/B/A) и бит 0..7
# полезно: Frame Browser, Extractor, Steregom
# CLI-альтернатива — скрипт:
```

```python
from PIL import Image
im = Image.open('image.png').convert('RGBA')
W, H = im.size
for ch, name in [(3, 'A'), (0, 'R')]:
    for bit in range(8):
        o = Image.new('L', (W, H))
        o.putdata([((p[ch] >> bit) & 1) * 255 for p in im.getdata()])
        o.save(f'plane_{name}{bit}.png')
```

Часто текст/QR «проступает» в одной конкретной плоскости альфы.

| Инструмент | Назначение | Пример |
|------------|-----------|--------|
| `zsteg` | авто-перебор каналов, включая `a` | `zsteg -E 'b1,a,lsb,xy' i.png` |
| `stegsolve` | бит-плоскости, каналы, XOR (GUI) | — |
| PIL/NumPy | свои скрипты | см. выше |
| `pngcheck` | целостность чанков | `pngcheck -v i.png` |
| `binwalk` | дописанные данные | `binwalk i.png` |
| `pngout`/`optipng` | перепаковка (осторожно: меняет данные) | — |

## Разобранные примеры

**1. LSB альфы.** `zsteg image.png` → строка `b1,a,lsb,xy .. text: "flag{alpha}"`.

**2. Скрытое изображение.** `no_alpha.png` показывает второй рисунок с флагом.

**3. Бит-плоскость.** stegsolve → Alpha, бит 0 → виден текст.

## Частые ошибки и отладка

- **Конвертация в JPG** — теряется альфа.
- **Смотреть только RGB** — данные в альфе.
- **Игнорировать RGB прозрачных пикселей.**
- **Не пробовать MSB и 2 LSB.**
- **Премультипликация** «стирает» RGB прозрачных.
- **Отладка:** если поток бит «почти читается» — сдвиньте offset и попробуйте инверсию; проверьте, не интерлейснуты ли каналы.

## Что делать дальше / дерево решений

1. `zsteg image.png` → канал `a` даёт текст? → готово.
2. Нет → скрипт по LSB/MSB/2-LSB альфы.
3. Нет → сохраните RGB без альфы (`no_alpha.png`) — проявите скрытое.
4. Нет → бит-плоскости в stegsolve.
5. Нет → `binwalk`/`pngcheck` — чанки и хвост.

## Шпаргалка: команды и быстрые проверки

```bash
# 1) Автоперебор всех каналов, включая альфу
zsteg image.png
zsteg -E 'b1,a,lsb,xy' image.png        # LSB альфы
zsteg -E 'b1,a,msb,xy' image.png        # MSB альфы
# 2) Проявить скрытое изображение из RGB прозрачных пикселей
python3 -c "from PIL import Image;im=Image.open('i.png').convert('RGBA');Image.new('RGB',im.size).putdata([p[:3] for p in im.getdata()]) or None" 2>/dev/null
# 3) Целостность чанков
pngcheck -v image.png
```

Типичные ошибки на практике и что делать: если `zsteg` показывает «пусто», но картинка выглядит подозрительно прозрачной — почти всегда данные в RGB прозрачных пикселей (`alpha == 0`); если поток бит читается «почти», сдвиньте offset и попробуйте инверсию; если редактор обнулил цвет прозрачных пикселей, нужен исходный файл (премультипликация). В отчёте фиксируйте, какой канал использовался (A-lsb/A-msb/RGB-transparent) — это важно для воспроизводимости.
