## Вопрос, с которого всё начинается

У тебя есть `alpha.png`. На экране — обычная картинка, но у неё есть прозрачность: часть изображения «просвечивает». Инструменты LSB по каналам R, G, B ничего не находят. Где ещё искать?

У PNG-картинки может быть **четвёртый канал** — прозрачность. Он называется **альфа-канал**, и его часто игнорируют, а данные прячут именно там. Потому что «невидимый» канал — идеальное место для секрета. Разберём на `alpha.png`.

## Наш пример: файл alpha.png

Смотрим параметры:

```bash
exiftool alpha.png | grep -iE 'width|height|color type|alpha'
```

```text
Image Width                     : 80
Image Height                    : 80
Color Type                      : RGBA
```

Тип **RGBA** — это четыре канала: красный, зелёный, синий и **альфа**. Значит, у каждого пикселя есть ещё одно число — степень непрозрачности: 0 (полностью прозрачный) … 255 (полностью непрозрачный).

## Шаг 1: что такое альфа-канал

Обычный цвет — это три числа: сколько красного, зелёного, синего. **Альфа** — четвёртое число, которое говорит, насколько пиксель непрозрачен. При наложении картинки на фон альфа определяет, сколько «просвечивает» фон.

Ключевое для нас: если пиксель **полностью прозрачный** (альфа = 0), его цвет (R, G, B) на экране не виден вообще. Но в файле эти байты **остаются**. То есть можно спрятать данные в цветах невидимых пикселей, и на картинке не будет ни малейшего следа.

## Шаг 2: извлекаем LSB альфа-канала

Как и в обычном LSB, младший бит альфы незаметен глазу. Извлекаем его тем же приёмом:

```python
from PIL import Image
import numpy as np
im = np.array(Image.open('alpha.png'))        # форма (H, W, 4)
a = im[:, :, 3].reshape(-1)                    # альфа-канал в строку
bits = ''.join(str(int(p) & 1) for p in a)
out = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
print('alpha-LSB:', out[:40])
```

`im[:, :, 3]` берёт четвёртый канал (индексы начинаются с нуля). Запускаем:

```text
alpha-LSB: b'flag{alpha_ch4nn3l}\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff\xff'
```

Флаг `flag{alpha_ch4nn3l}` найден. Заметь: после текста идут `\xff` — это непрозрачные пиксели, где младший бит равен 1. Данные лежали в самом начале изображения.

## Шаг 3: данные в полностью прозрачных пикселях

Ещё интереснее случай, когда часть пикселей сделана полностью прозрачной (альфа = 0), а в их цветах спрятаны данные. На экране таких пикселей просто «нет», но в файле они есть. Достают их так:

```python
import numpy as np
from PIL import Image
im = np.array(Image.open('alpha.png'))
mask = im[:, :, 3] == 0                 # где пиксель полностью прозрачен
hidden = im[mask]                        # их цвета (R,G,B,A)
print('transparent pixels:', len(hidden))
```

В нашем файле `fully transparent pixels: 0` — здесь прозрачных пикселей нет, и это тоже важный вывод: отсутствие прозрачности не значит, что альфа пуста. Данные были в **младших битах непрозрачной** альфы. Проверять надо оба варианта.

## Шаг 4: премультипликация — подводный камень

Некоторые редакторы хранят цвета уже **умноженными** на альфу (так называемая **премультипликация**). Если картинку сохранили так, а читаете вы её как обычную, цвета в прозрачных областях будут искажены — и данные «не прочитаются».

Признак: прозрачные пиксели содержат «странные» тёмные значения RGB вместо ожидаемых. Тогда нужно делить цвет на альфу (или наоборот, умножать), чтобы восстановить исходные байты. Всегда проверяйте, как именно сохранён файл, прежде чем делать вывод «данных нет».

## Шаг 5: инструменты

Вручную удобно, но есть готовые утилиты. **zsteg** умеет смотреть альфа-канал автоматически:

```bash
zsteg -a alpha.png
```

Флаг `-a` включает все методы и каналы, включая альфу. **StegSolve** позволяет вручную полистать плоскости каждого канала, в том числе альфа-канала (канал 3). А `exiftool` и разбор чанков (`stego-png-chunks`) помогут, если данные окажутся не в пикселях, а в метаданных.

## Прозрачность как носитель: реальные схемы

На практике альфа-канал используют несколькими способами. Первый — обычный LSB, который мы разобрали: младший бит каждого значения альфы несёт по одному биту секрета. Второй — **данные только в прозрачных пикселях**: автор делает часть картинки невидимой (альфа = 0) и прячет сообщение в цветах именно этих пикселей. Тогда даже визуальный анализ не поможет — на экране этих пикселей попросту нет.

Третий способ — **двухслойные картинки**: при одном значении альфы видна одна картинка, при другом — вторая. Это уже не совсем стеганография, а «скрытое изображение», но принцип тот же: информация лежит в канале, который зритель не воспринимает. Четвёртый — данные в **разнице** между предсказанным и реальным значением альфы (аналог разностного кодирования, см. `stego-pvd`).

Из этого следует практическое правило: получив RGBA-картинку, проверяйте альфу на трёх уровнях — младшие биты, прозрачные пиксели и распределение значений. Только пройдя все три, можно уверенно сказать, что канал пуст.

## Проверка целостности и типичные ловушки

Отдельная ловушка — **потеря альфы при конвертации**. Если картинку пересохранили в JPEG (где альфы нет) или «сплющили» на белый фон, данные в прозрачных областях пропадут безвозвратно. Поэтому всегда работайте с исходным PNG, а не с его копией из мессенджера или скриншотом.

Вторая ловушка — **палитровые PNG**. В них цвет хранится не как RGB-числа, а как индекс в таблице палитры; отдельного альфа-канала там может не быть, зато есть **tRNS**-чанк с прозрачностью (см. `stego-palette`). Если скрипт читает такой файл как RGBA, он либо выдаст ошибку, либо подставит нули — и вы сделаете неверный вывод. Всегда проверяйте `Color Type`: 6 — RGBA, 3 — палитра, 2 — RGB.

Третья ловушка — **шум в младших битах**. Если картинку сохранили с потерями и обратно перегнали в PNG, младшие биты станут случайными, и LSB-данные разрушатся. Признак — плоскость выглядит как равномерный шум без структуры.

## Полный прогон: от картинки к флагу

```text
alpha.png
  → exiftool → Color Type RGBA (есть альфа)
  → скрипт: LSB альфа-канала → flag{alpha_ch4nn3l}
  → проверка прозрачных пикселей → 0 (данные в непрозрачной альфе)
  → при искажении — учёт премультипликации
  → итог: данные в младшем бите альфы
```

## Если не сработало

- **Альфа пуста** — проверьте, есть ли вообще прозрачные пиксели; данные могут быть в их цветах.
- **Цвета в прозрачных областях странные** — учтите премультипликацию.
- **Не нашли в альфе** — вернитесь к каналам R/G/B (`stego-bitplane`).
- **Данные не текст** — соберите биты в картинку и сохраните как PNG.

## Что мы теперь знаем

- **Альфа-канал** — четвёртый канал RGBA, задаёт прозрачность.
- Младший бит альфы незаметен, как и обычный LSB.
- Полностью **прозрачные пиксели** хранят цвета, невидимые на экране.
- Отсутствие прозрачных пикселей **не значит**, что альфа пуста.
- **Премультипликация** может исказить данные — её надо учитывать.
- `zsteg -a` и StegSolve проверяют альфу автоматически.
