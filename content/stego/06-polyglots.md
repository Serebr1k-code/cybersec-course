## Вопрос, с которого всё начинается

Обычно файл — это один формат: картинка, или архив, или PDF. Но иногда попадается файл, который ведёт себя странно: открываешь его как картинку — всё нормально, а `unzip` вдруг распаковывает из него архив. Один файл — сразу два формата. Такое чудо называется **полиглот**.

В этом уроке мы разберём один такой файл, поймём, почему так вообще возможно, и достанем из него данные.

## Наш пример: challenge.png

Начнём с определения формата.

```
$ file challenge.png
challenge.png: PNG image data, 400 x 400, 8-bit/color RGB, non-interlaced
```

Обычная картинка. Но давай сделаем неочевидное: попробуем открыть её архиватором.

```
$ unzip -l challenge.png
Archive:  challenge.png
  Length      Date    Time    Name
       20  2024-03-01 10:00   flag.txt
       20                     1 file
```

`unzip` не жалуется и показывает файл `flag.txt` внутри. Значит, `challenge.png` — одновременно и PNG, и ZIP. Это и есть полиглот.

## Почему это возможно

Секрет в том, что разные парсеры читают **разные части** файла и не проверяют остальное.

PNG читается с начала: чанк `IHDR`, потом данные изображения, потом `IEND`. Просмотрщик картинки идёт строго по чанкам от начала и доходит до `IEND`.

ZIP же читается **с конца**: архиватор ищет в конце файла «End of Central Directory» (EOCD, сигнатура `PK\x05\x06`), по нему находит оглавление и уже оттуда разбирает содержимое.

Совместив эти два независимых механизма, получают один файл, который оба инструмента считают «своим».

## Шаг 1: подтверждаем оба формата

`file` останавливается на первом совпадении. Флаг `-k` («keep going») заставляет его не останавливаться и показать **все** найденные форматы:

```
$ file -k challenge.png
challenge.png: PNG image data, 400 x 400, 8-bit/color RGB, non-interlaced \012- Zip archive data, at least v2.0 to extract
```

Вот и оба формата в одной строке. `binwalk` тоже увидит обе сигнатуры:

```
$ binwalk challenge.png
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             PNG image, 400 x 400
262144        0x40000         Zip archive data, at offset 0x40000
```

## Шаг 2: разбираем оба «слоя»

Ключевое правило полиглотов: применяй к файлу **все** релевантные инструменты, а не только тот, что подсказало расширение.

```
$ unzip -o challenge.png
Archive:  challenge.png
  inflating: flag.txt
$ cat flag.txt
flag{png_zip_polyglot}
$ python3 -c "from PIL import Image; im=Image.open('challenge.png'); print(im.size)"
(400, 400)
```

Оба слоя «настоящие»: картинка открывается и имеет размер 400×400, архив распаковывается и отдаёт флаг. Часто один слой — приманка (безобидная картинка), а данные лежат во втором.

## Шаг 3: собираем полиглот сами

Понять приём проще всего, собрав его. Простейший PNG+ZIP — это обычная склейка: дописываем архив к картинке.

```
$ cat image.png archive.zip > polyglot.png
$ file polyglot.png
polyglot.png: PNG image data, 400 x 400, 8-bit/color RGB, non-interlaced
$ unzip -l polyglot.png
Archive:  polyglot.png
  Length      Date    Time    Name
       20  2024-03-01 10:00   secret.txt
```

`file` видит PNG (читает начало), `unzip` — ZIP (читает конец). Готово, мы только что сделали полиглот. Для CTF такого «наивного» варианта почти всегда достаточно.

## Таблица популярных комбинаций

| Комбинация | Читается с начала | Читается с конца | Инструменты |
|---|---|---|---|
| PNG + ZIP | PNG | ZIP | `file`, `unzip` |
| GIF + JAR | GIF | ZIP | `file`, `unzip` |
| PDF + ZIP | PDF | ZIP | `pdfinfo`, `unzip` |
| JPEG + ZIP | JPEG | ZIP | `file`, `unzip` |
| PNG + JPEG | PNG | JPEG | `file`, Pillow |

Исторический пример — **GIFAR** (GIF + JAR): GIF-картинка, которая одновременно является Java-архивом. Так обходили проверки загрузки файлов.

## Где это встречается в реальности

Полиглоты — не только CTF-игрушка:

- **GIFAR** — Java-апплет в GIF для обхода загрузки;
- **PDF + PE/JS** — исполняемый контент внутри PDF;
- **картинка + код** (`GIF89a<?php ...`) — обход проверок `getimagesize()`, файл проходит как картинка, но исполняется как скрипт;
- **обход WAF и антивирусов** — для одного сканера файл выглядит безобидным.

## Если не сработало

- Попробуй **все** «вторые» инструменты: `unzip`, `7z`, `tar`, `pdfinfo`.
- Посмотри маркеры через `strings -n 4 file | grep -E 'PK|%PDF|GIF8|JFIF'`.
- Запусти `binwalk` — он покажет обе сигнатуры со смещениями.
- Если полиглот «внутренний» (второй формат встроен в тело, а не дописан), может понадобиться ручной разбор структуры.

## Что мы теперь знаем

1. Полиглот — файл, валидный сразу в нескольких форматах.
2. Работает потому, что разные парсеры читают разные части файла.
3. Обнаруживают `file -k`, `binwalk`, `strings`, «лишними» инструментами.
4. Разбирают **все** слои, а не только очевидный.
5. Простейший PNG+ZIP собирается командой `cat image.png archive.zip > out.png`.

## Шаг 4: чем полиглот отличается от дописанного хвоста

Полиглот и «дописанные данные» похожи, но это разные вещи. В дописанных данных второй формат лежит **после** логического конца первого, и первый формат про него «не знает». В полиглоте структуры переплетены так, что **оба** парсера считают файл своим.

На практике различие не критично — маршрут разбора один: применить все инструменты. Но полезно понимать, почему `file -k` иногда показывает оба формата одной строкой (полиглот), а иногда только первый (дописанный хвост, до которого `file` не дочитывает).

## Шаг 5: как строят «настоящие» полиглоты

Наивный полиглот — это склейка (`cat image.png archive.zip > out.png`). Более хитрые строят так, чтобы структуры не мешали друг другу:

- **разные концы файла** — один формат читается с начала (PNG/GIF), другой с конца (ZIP);
- **комментарии и пустые поля** — PNG `tEXt`, `free`-боксы MP4, куда встраивают второй формат;
- **подбор длин** — размеры подгоняют так, чтобы смещения совпали;
- **химеры** — разные «срезы» файла интерпретируются разными парсерами.

Для CTF почти всегда достаточно наивного варианта.

## Шаг 6: полиглоты в защите

С точки зрения blue team полиглот — вектор обхода фильтров загрузки. Признаки:

- файл с расширением одного типа содержит сигнатуру другого (`binwalk`, `file -k`);
- `file` и антивирус дают разные вердикты;
- `strings` показывает чужие маркеры (`PK`, `%PDF`, `GIF8`);
- размер не соответствует заявленному содержимому.

Правильная защита валидирует не расширение, а **реальный** формат по магическим байтам и отклоняет файлы, у которых сигнатур больше одной.

## Куда дальше

Дальше мы разберём **QR-коды и баркоды** — ещё один «двойной» носитель: сначала это код с текстом, а потом обычное изображение со своими стего-каналами. А пока запомни главное: если `file` и второй инструмент дают разные вердикты — перед тобой полиглот, и разбирать надо оба слоя.

## Где пригодится

- **CTF:** «босс-уровень» форматов — проверяет понимание структур, а не заучивание тулз.
- **Web-задачи:** тот же приём (картинка + код) обходит проверки загрузки файлов.
- **Malware-анализ:** распознавание противоречивой идентификации файла.
- **Blue team:** детект файлов, которые «притворяются» безобидными.
