## Что такое полиглот

Полиглот (polyglot) — файл, который **одновременно является валидным в нескольких форматах**. Например, файл может быть и корректным PNG, и корректным ZIP: программа просмотра откроет картинку, а `unzip` распакует архив. Полиглоты — мощный приём стеганографии: «невидимый» второй формат спрятан в том же файле, и инструмент, рассчитанный на один формат, второй не замечает.

Идея опирается на то, что парсеры форматов читают **разные части файла** и игнорируют «чужие». PNG читает чанки, ZIP читает центральный каталог в конце; каждый игнорирует структуру другого. Совместив их, получают один файл — два формата.

## PNG + ZIP

Классика. PNG состоит из чанков, а ZIP читается с конца. Встраивая ZIP так, чтобы его структура не ломала PNG, получают файл, который открывается как картинка и распаковывается как архив.

```bash
file polyglot.png          # PNG image data
unzip -l polyglot.png      # показывает содержимое ZIP!
```

Признак: `file` говорит PNG, но `unzip -l` не жалуется. Это уже подсказка.

## GIF + JAR и другие комбинации

- **GIF + JAR/ZIP** — GIF читается по маркеру `GIF8` и трейлеру `0x3B`; JAR — это ZIP.
- **PDF + ZIP** — PDF читается по `%PDF` и `%%EOF`; ZIP прячется в хвосте.
- **JPEG + ZIP/GZIP** — JPEG по `FFD8…FFD9`; ZIP после EOI.
- **PNG + JPEG** — оба изображения в одном файле.
- **ZIP + PDF**, **GIFAR** (GIF+JAR) — исторические примеры.

## Как распознать полиглот

- `file` показывает один формат, но **второй инструмент** работает.
- `binwalk` находит вторую сигнатуру.
- Размер «не сходится» с первым форматом.
- `strings` показывает «чужие» маркеры (`PK`, `%PDF`, `GIF8`).

```bash
binwalk polyglot.png
strings -n 4 polyglot.png | grep -E 'PK|%PDF|GIF8|JFIF'
```

## Разбор обоих слоёв

Ключ — применить **оба** инструмента:

```bash
file polyglot.png
unzip -l polyglot.png          # если ZIP
python3 -c "from PIL import Image; Image.open('polyglot.png').show()"   # если картинка
binwalk -e polyglot.png
```

Если один слой содержит данные, второй — приманка (или наоборот). Разбирайте оба.

## Инструменты

- **`file`** — первый формат.
- **`unzip`/`7z`/`tar`** — второй формат (архив).
- **`binwalk`** — обе сигнатуры.
- **`strings`/`xxd`** — маркеры.
- **`polyglot`-генераторы** — для понимания (например, скрипты совмещения PNG+ZIP).

## Разобранный пример

```bash
$ file challenge.png
challenge.png: PNG image data, 400 x 400
$ unzip -l challenge.png
Archive:  challenge.png
  Length      Name
       20  flag.txt
$ unzip -o challenge.png && cat flag.txt
flag{png_zip_polyglot}
```

Маршрут: `file` → PNG; попробовать `unzip` → работает → распаковать.

## Частые ошибки и подводные камни

- **Проверять только один формат** — второй остаётся невидимым.
- **Открыть и пересохранить** — полиглот разрушится.
- **Не пробовать `unzip`/`7z`** на картинке.
- **Игнорировать `binwalk`** — он видит обе сигнатуры.
- **Считать размер ошибкой** — это может быть второй формат.
- **Забыть про `strings`** — маркеры видны.

## Итог

Полиглоты — это «файл с двумя личностями». Их сила в том, что стандартные инструменты видят только один формат. Защита/разбор просты: применяйте **все** релевантные инструменты (картинка + архив + `binwalk`), и второй слой проявится. Понимание устройства форматов (где начало, где конец, что парсер игнорирует) позволяет и строить полиглоты, и разбирать их.

## Техники построения полиглотов

Полиглот строится так, чтобы структуры двух форматов не мешали друг другу. Основные приёмы:

- **Разные концы файла**: один формат читается с начала (PNG/GIF), другой — с конца (ZIP). Совмещая, получают оба.
- **Комментарии/пустые поля**: один формат позволяет произвольные байты в определённом месте (комментарии PNG `tEXt`, `free`-боксы MP4), куда встраивается второй.
- **Полиглоты по длине**: подбор размеров так, чтобы смещения совпали.
- **Химеры**: разные «срезы» файла интерпретируются разными парсерами.

Практически чаще всего встречаются «наивные» полиглоты (ZIP в хвосте картинки), которые строятся простым `cat image.png archive.zip > out.png`.

## Полиглоты в реальных атаках

Полиглоты — не только CTF-приём. Они использовались в реальных атаках:

- **GIFAR** (GIF+JAR) — Java-апплет в GIF для обхода загрузки.
- **PDF+JS/PE** — исполняемый контент в PDF.
- **ZIP+картинка** — обход фильтров загрузки, доставка payload.
- **Полиглоты для обхода WAF/детекторов** — файл выглядит безобидным для одного сканера.

Поэтому навык «проверять файл на несколько форматов» полезен и в защите.

## Практический чек-лист полиглота

1. `file` — первый формат.
2. Попробовать все «вторые» инструменты: `unzip`, `7z`, `pdfinfo`, `tar`.
3. `binwalk` — обе сигнатуры.
4. `strings` — маркеры (`PK`, `%PDF`, `GIF8`, `JFIF`).
5. Разобрать оба слоя; искать настоящий payload.
6. Ничего — вернуться к обычным каналам (LSB/IDAT/хвост).

## Построение полиглота вручную

Понять полиглот проще, собрав его. Простейший PNG+ZIP: дописать ZIP к PNG.

```bash
cat image.png archive.zip > polyglot.png
file polyglot.png        # PNG image data
unzip -l polyglot.png    # работает — читает ZIP из хвоста
```

Более «красивый» полиглот (где второй формат встроен внутрь, а не дописан) требует совмещения смещений, но для CTF достаточно наивного варианта. Аналогично: `cat a.gif b.jar > poly.gif` (GIF+JAR), `cat doc.pdf b.zip > poly.pdf` (PDF+ZIP).

## Обнаружение в защите

С точки зрения blue team полиглоты — вектор обхода фильтров загрузки. Признаки:

- Файл с расширением одного типа содержит сигнатуру другого (`binwalk`, `file -k`).
- Несоответствие «заявленного» и «реального» размера/структуры.
- `file` и антивирус дают разные вердикты.
- `strings` показывает чужие маркеры.

Инструмент `file -k` (keep going) не останавливается на первом совпадении и часто показывает **оба** формата — это простой способ обнаружить полиглот.

```bash
file -k polyglot.png     # покажет и PNG, и Zip archive data
```

## Практика: двойной разбор

Всегда разбирайте **оба** слоя и ищите, где «настоящий» payload:

```bash
file -k polyglot.png
binwalk polyglot.png
unzip -l polyglot.png && unzip -o polyglot.png -d out_zip/
python3 -c "from PIL import Image; im=Image.open('polyglot.png'); print(im.size)"
```

Часто один слой — приманка (безобидная картинка), а данные — во втором (архив).

## Итог

Полиглоты эксплуатируют то, что парсеры форматов читают разные части файла. Разбор сводится к простому правилу: **применяйте все релевантные инструменты к одному файлу**. `file -k`, `binwalk`, `unzip`/`7z`/`pdfinfo` и `strings` быстро выявляют второй формат. Понимание устройства форматов (начало/конец/игнорируемые области) делает и построение, и разбор полиглотов предсказуемым.

## Что делать дальше / решение

## Где пригодится

- Полиглоты — «босс-уровень» форматов: проверяют понимание структур, а не заучивание тулз.
- Тот же приём (картинка+код) используется в web-задачах для обхода загрузки файлов.
- Умение распознавать противоречивую идентификацию файла полезно в malware-анализе и детекте.
- QR/баркоды — частый элемент misc-задач и OSINT (коды на фото, документах).
