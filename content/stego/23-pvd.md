## Вопрос, с которого всё начинается

У тебя есть `pvd.png` — серая картинка 32×32. Инструменты LSB по ней ничего не находят, бит-плоскости выглядят как шум. Но задание намекает, что данные внутри. Как прячут информацию так, что её не видно ни в младших битах, ни в плоскостях?

Есть целый класс методов, которые работают не с отдельным пикселем, а с **разницей между соседними пикселями**. Он называется **PVD** — Pixel Value Differencing, «разностное кодирование значений пикселей». Разберём его на `pvd.png`.

## Наш пример: файл pvd.png

Смотрим параметры:

```bash
exiftool pvd.png | grep -iE 'width|height|color type'
```

```text
Image Width                     : 32
Image Height                    : 32
Color Type                      : Grayscale
```

Оттенки серого, 32×32. В таком изображении каждый пиксель — одно число от 0 до 255.

## Шаг 1: идея PVD

Вспомним главный принцип незаметности: **изменение, которое глаз не замечает, безопасно**. В гладкой области (два соседних пикселя почти одинаковы) изменение на пару единиц видно. А в контрастной (перепад большой) можно изменить больше — и никто не заметит.

**PVD** использует именно это: смотрит на разницу `d = |b − a|` двух соседних пикселей и решает, сколько битов спрятать, **исходя из величины разницы**. Большая разница — больше битов. Так встраивание становится **адаптивным**: оно подстраивается под контраст изображения.

## Шаг 2: диапазоны и число битов

Разницу разбивают на диапазоны, каждому из которых сопоставлено число битов:

| Разница | Битов |
|---|---|
| 0–7 | 0 |
| 8–15 | 3 |
| 16–31 | 4 |
| 32–63 | 5 |
| 64–127 | 6 |
| 128–255 | 7 |

Чем больше разница, тем шире диапазон и тем больше битов в него влезает. В гладкой области (разница 0–7) ничего не прячется — там изменение было бы заметно. В контрастной (разница 128–255) помещается 7 битов.

## Шаг 3: как встраивают

Берём пару пикселей, находим диапазон, берём нужное число битов из сообщения и **переписываем разницу** так, чтобы она кодировала эти биты:

```python
def embed(img, msg):
    bits = ''.join(f'{c:08b}' for c in msg) + '0'*32
    flat = img.reshape(-1).astype(int).copy(); bi = 0
    for i in range(0, len(flat)-1, 2):
        if bi >= len(bits): break
        a, b = flat[i], flat[i+1]; d = abs(b-a)
        for (l, u, n) in RANGES:
            if l <= d <= u:
                if n == 0 or bi+n > len(bits): break
                newd = l + int(bits[bi:bi+n], 2); bi += n
                if b >= a:
                    a2 = min(a, 255-newd); b2 = a2 + newd
                else:
                    b2 = min(b, 255-newd); a2 = b2 + newd
                flat[i], flat[i+1] = a2, b2; break
    return flat.reshape(img.shape).astype('uint8')
```

Ключевой момент — `newd = l + int(bits)`: мы присваиваем разнице значение внутри того же диапазона, так что при извлечении поймём, сколько битов читать. Пара `a2, b2` подбирается так, чтобы их разница точно равнялась `newd` и оба остались в пределах 0–255.

## Шаг 4: как извлекают

Извлечение — обратная операция: идём по парам, считаем разницу, определяем диапазон, читаем из разницы число битов:

```python
def extract(img, nbytes=40):
    flat = img.reshape(-1).astype(int); bits = ''
    for i in range(0, len(flat)-1, 2):
        d = abs(flat[i+1]-flat[i])
        for (l, u, n) in RANGES:
            if l <= d <= u:
                if n > 0: bits += format(d-l, '0%db' % n)
                break
        if len(bits) >= nbytes*8: break
    return bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-7, 8))
```

Применяем к `pvd.png`:

```text
extracted: b'flag{pvd_d1ff3r3nc3}\x00\x00\x00\x05\x07\x8d\xed\xfc\xb6\x1e\xff\xcb\x98}\x03_\x08(o}'
```

Флаг найден: `flag{pvd_d1ff3r3nc3}`. После него идёт мусор — данные кончились, а дальше извлекаются «естественные» разницы изображения.

## Шаг 5: почему это сложнее детектировать

Классический LSB легко поймать: он меняет младшие биты так, что их распределение перестаёт быть случайным. PVD устойчивее: он **не трогает гладкие области** вообще и меняет разницы в контрастных, где изменения естественны. Поэтому статистические тесты на «равномерность младших битов» его не ловят.

Детект PVD требует анализа **гистограммы разниц** между соседними пикселями: встраивание оставляет характерные «ступеньки» на границах диапазонов (8, 16, 32, 64, 128). Если в гистограмме разниц видны аномальные пики на этих значениях — вероятно, применён PVD.

## PVD на цветных изображениях и порядок обхода

В нашем примере картинка серая, поэтому пары берутся из одной плоскости яркости. В цветном изображении PVD применяют к **каждому каналу** отдельно (или к яркости Y из модели YCbCr), а порядок обхода может быть построчным, по столбцам или даже зигзагом. От порядка зависит, какие именно пары образуются, — а значит, и то, прочитается ли сообщение.

Практический совет: если данные «почти читаются», но с ошибками, попробуйте другой порядок обхода и другую ось (пары по горизонтали vs по вертикали). Также помогает смена того, какой пиксель в паре считается первым — от этого зависит знак разницы.

Ещё нюанс — **границы диапазонов**. Стандартный набор (0–7, 8–15, 16–31, …) распространён, но авторы иногда берут свои границы. Если извлечение даёт мусор, переберите несколько разумных разбиений: 3-битные шаги, логарифмические диапазоны, фиксированную ширину.

## Где ещё встречается адаптивное встраивание

Идея «прятать больше там, где это незаметно» встречается во многих методах. **BPCS** (bit-plane complexity segmentation) прячет данные в сложных бит-плоскостях, оставляя простые нетронутыми. **Адаптивный LSB** выбирает пиксели по локальной дисперсии: в шумных областях меняет больше битов. **Методы на основе вейвлетов** (`stego-dwt`) прячут данные в коэффициентах преобразования, тоже с учётом локальной текстуры.

Общее у всех — использование **человеческого восприятия**: глаз и статистические тесты менее чувствительны к изменениям в сложных областях. Понимание этого принципа важнее знания конкретного алгоритма: увидев, что встраивание «привязано» к контрасту или текстуре, вы сразу знаете, где искать данные — и где искать аномалии для детекта.

## Полный прогон: от картинки к флагу

```text
pvd.png
  → exiftool → Grayscale 32×32
  → LSB и бит-плоскости пусты
  → извлечение по разницам соседних пикселей
  → flag{pvd_d1ff3r3nc3}
  → итог: данные спрятаны в разностях, а не в отдельных битах
```

## Если не сработало

- **Разницы пусты** — возможно, другой набор диапазонов; попробуйте варьировать границы (0–7, 8–15, …).
- **Данные не текст** — соберите биты в изображение и сохраните как PNG.
- **Извлечение даёт мусор** — проверьте порядок обхода пар (горизонтальный, вертикальный).
- **Всё пусто** — вернитесь к LSB (`stego-audio-lsb`) и бит-плоскостям (`stego-bitplane`).

## Что мы теперь знаем

- **PVD** прячет данные в **разнице** соседних пикселей.
- Число битов зависит от величины разницы — это **адаптивный** метод.
- Гладкие области не трогаются, чтобы сохранить незаметность.
- Извлечение читает разницу и определяет диапазон.
- Детект ищет аномальные пики на границах диапазонов в гистограмме разниц.
