## Вопрос, с которого всё начинается

Тебе дали `note.txt` — короткую записку. Читаешь: обычный текст, ничего лишнего.
Открываешь в hex-редакторе — а в конце каждой строки висят пробелы и табы. В них
спрятано сообщение. Это классический инструмент **SNOW**. Разберём, как это
работает и как прочитать.

## Наш пример: файл note.txt

```bash
cat -A note.txt | head -4
```

```text
Привет!^I $
Как дела?^I  ^I$
Всё хорошо.^I   $
Пока.^I$
```

`cat -A` показывает невидимое: `^I` — таб, `$` — конец строки. Видно, что в конце
строк есть «хвосты» из табов и пробелов. Глазами их не видно, а в них — биты.

## Шаг 1: почему пробелы — носитель

Пробел и таб — тоже символы с кодами (пробел 0x20, таб 0x09). Редактор их не
показывает, но они хранятся. Значит, последовательностью «пробел/таб» можно кодировать
биты: пробел = 0, таб = 1. Это и есть SNOW-канал.

## Шаг 2: где именно прячут

Классический SNOW добавляет хвост **в конце строки**, после видимого текста. Причина:
хвост не мешает чтению и не меняет переносы. Внутри строки вставлять нельзя — это
сломает слова. Ещё вариант — прятать между словами, но тогда пробелы заметнее.

## Шаг 3: как читать биты вручную

Идём по строкам, смотрим хвостовые пробелы/табы, отображаем в биты:

```python
lines = open('note.txt', 'rb').read().split(b'\n')
bits = []
for ln in lines:
    tail = ln[len(ln.rstrip(b' \t')):]
    for ch in tail:
        bits.append(0 if ch == 0x20 else 1)
out = bytearray()
for k in range(0, len(bits)//8*8, 8):
    b = 0
    for x in bits[k:k+8]:
        b = (b << 1) | x
    out.append(b)
print(out[:24])
```

Ключ: `rstrip(b' \t')` убирает хвост, и его длина/состав даёт биты. Порядок бит
(слева-направо, старший-первым) важен.

## Шаг 4: запускаем

```bash
python3 snow.py
```

```text
lines: 4
tail bits: 22
nto{sn0w_tr41l1ng_sp4c3}
```

Сообщение прочитано. Мы не «угадали» — мы извлекли биты из хвостов.

## Шаг 5: инструмент SNOW

Оригинальный `snow` (автор Matthew Kwan) умеет и прятать, и доставать:

```bash
snow -C -p "пароль" note.txt        # извлечь
snow -C -m "секрет" -p "пароль" in.txt out.txt   # спрятать
```

`-C` — сжатие, `-p` — пароль (он и есть ключ). Без пароля данные всё равно
извлекаемы (SNOW-биты видны), но пароль защищает содержимое шифрованием.

## Шаг 6: SNOW и стеганализ

Обнаружить SNOW просто, если смотреть «под капот»: обычный текст не имеет
**трейлинг-пробелов**. Любой файл с хвостами из пробелов/табов — подозрителен. Blue
team-правило: **стрипать трейлинг-пробелы** перед публикацией кода/текста, чтобы не
утечь и не принять чужую закладку.

## Шаг 7: частые ловушки

- **Порядок бит**: SNOW использует свой порядок; при ручном чтении проверяй оба.
- **Пробел vs таб**: не перепутай, что есть 0, а что 1.
- **Перенос строки Windows** (`\r\n`): `\r` может попасть в хвост.
- **Форматирование**: редактор/сайт может обрезать хвосты — данные исчезнут.
- **Кодировка**: читай байты, а не «символы», чтобы не потерять 0x20/0x09.

## Что мы теперь знаем

- SNOW прячет данные в хвостовых пробелах/табах.
- Пробел = 0, таб = 1; биты собираются по 8.
- Глазами канал невидим — нужен `cat -A` или скрипт.
- Трейлинг-пробелы — надёжный признак сокрытия.
- Инструмент `snow` умеет и прятать, и извлекать (с паролем).

## Шаг 8: почему это работает в реальной жизни

В коде, логах и переписке трейлинг-пробелы часто «нормальны» — их никто не чистит.
Поэтому SNOW-канал живёт незамеченным годами. В форензике его ищут в исходниках
(сравнивая с эталонным форматированием), в письмах (сырой источник, а не рендер) и
в документах. Практический приём: получить **сырые байты**, а не «отрендеренный»
текст.

## Шаг 9: разновидности пробельного канала

Помимо хвостов, используют:

- **двойные пробелы** между словами (1 = 0, 2 = 1);
- **неразрывный пробел** U+00A0 вместо обычного;
- **разные виды пробелов** (thin space, hair space, em space);
- **табы внутри отступов**.

Все они — «whitespace stego». Принцип один: кодировать биты **типом** пробела.

## Шаг 10: как отличить от естественного форматирования

Не каждый хвостовой пробел — стего. Признаки сокрытия:

- хвосты есть **во всех** строках и имеют неровную длину;
- состав хвоста меняется по «случайному» закону;
- после декодирования появляется сигнатура (`nto{`, осмысленный текст).

Сравни с эталоном: если файл — код, отформатируй его линтером и сравни хвосты.

## Шаг 11: практический чек-лист

1. Открой файл байтами (`cat -A`, hexdump).
2. Посмотри концы строк: есть ли хвосты из 0x20/0x09?
3. Извлеки биты (пробел=0, таб=1), собери байты.
4. Проверь оба порядка бит.
5. Ищи сигнатуру флага.

## Шаг 12: мост к юникод-каналам

SNOW использует **ASCII-пробелы**. Дальше мы посмотрим на **юникод**: гомоглифы,
bidi-управляющие, невидимые теги. Принцип тот же — невидимый символ как носитель, —
но инструментов уже меньше, и распознать сложнее.
