## Вопрос, с которого всё начинается

Тебе дали текстовый файл — письмо, README или стихотворение. На вид самый обычный текст. Но где-то в нём спрятано сообщение. Как вообще можно что-то спрятать в тексте, где нет ни пикселей, ни сэмплов?

Ответ: у текста много «невидимой» структуры. Символы можно заменить на визуально неотличимые, добавить невидимые символы, закодировать данные регистром букв или выбором слов. В этом уроке мы разберём один такой файл и вытащим из него флаг.

## Наш пример: msg.txt

```
$ file msg.txt
msg.txt: UTF-8 Unicode text
$ cat msg.txt
Напоминание: встреча перенесена на четверг.
```

Фраза как фраза. Но размер файла подозрительно большой для одной строки:

```
$ wc -c msg.txt
312 msg.txt
```

В строке примерно 44 символа, а файл — 312 байт. Куда делись остальные? Значит, в тексте есть невидимые символы.

## Шаг 1: смотрим непечатаемое

`cat -A` показывает то, что обычно скрыто: табы как `^I`, конец строки как `$`, пробелы как есть.

```
$ cat -A msg.txt
Напоминание: встреча перенесена на четверг.$
```

Хвостовых пробелов и табов нет. Значит, невидимое — это не пробелы, а что-то другое. Выведем **кодовые точки** (числовые номера) всех символов:

```
$ python3 -c "print([hex(ord(c)) for c in open('msg.txt',encoding='utf-8').read()][:30])"
['0x41d', '0x430', ..., '0x200b', '0x200c', '0x200b', ...]
```

Видим символы `0x200b` и `0x200c`. Это **zero-width** символы: `U+200B` (ZERO WIDTH SPACE) и `U+200C` (ZERO WIDTH NON-JOINER). Они невидимы в любом редакторе, но реально хранятся в файле. Вот откуда лишние байты.

## Шаг 2: как из невидимых символов получаются биты

Договоримся: `U+200B` — это бит `1`, `U+200C` — бит `0`. Собираем все такие символы по порядку, получаем поток битов, группируем по 8 и переводим в байты.

```python
s = open('msg.txt', encoding='utf-8').read()
zw = [c for c in s if c in '\u200b\u200c\u200d\ufeff\u2060']
bits = ''.join('1' if c == '\u200b' else '0' for c in zw)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data)
```

Запускаем:

```
$ python3 extract.py
b'flag{text_zerowidth}'
```

Готово. Невидимые символы несли обычный ASCII-текст.

## Шаг 3: другие невидимые каналы

Zero-width — не единственный невидимый носитель. Часто встречаются:

- **Пробел vs таб в конце строки**: пробел = 0, таб = 1 (одна строка — один бит);
- **Два вида пробелов** (обычный `U+0020` и неразрывный `U+00A0`);
- **Unicode-модификаторы** и теги;
- **BOM** (`U+FEFF`) — иногда метка, иногда канал.

Для хвостовых пробелов скрипт ещё проще — один бит на строку:

```python
lines = open('text.txt').read().split('\n')
bits = ''.join('1' if l.endswith('\t') else '0' for l in lines if l)
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8)))
```

## Шаг 4: структурные каналы — регистр и акростих

Данные прячут и в **видимой** структуре текста:

- **Регистр**: заглавная буква = 1, строчная = 0;
- **Пунктуация**: запятая против точки;
- **Акростих**: первые буквы строк или слов;
- **Число слов в строке** (унарный код).

```python
words = open('t.txt').read().split()
bits = ''.join('1' if w[0].isupper() else '0' for w in words if w[0].isalpha())
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8)))
```

Акростих читается совсем просто — берём первую букву каждой строки:

```python
print(''.join(l[0] for l in open('poem.txt').read().splitlines() if l))
```

## Шаг 5: гомоглифы и семантика

**Гомоглифы** — символы разных алфавитов, визуально неотличимые: латинская `a` и кириллическая `а`. Автор заменяет часть букв «двойниками», и выбор алфавита кодирует бит. Обнаруживают по имени символа:

```python
import unicodedata as u
from collections import Counter
names = [u.name(c) for c in open('t.txt', encoding='utf-8').read() if u.category(c).startswith('L')]
print(Counter(n.split()[0] for n in names))   # LATIN vs CYRILLIC vs GREEK
```

Если смешаны ровно два алфавита — это бинарный канал.

Самые «дорогие» в анализе — **семантические** каналы: выбор синонима из пары кодирует бит, а null-шифры прячут сообщение в «лишних» словах. Их проверяют последними, потому что нужен словарь.

## Ёмкость: сколько влезает в текст

Ёмкость текстовых каналов невелика. Zero-width даёт ~1 бит на символ, то есть абзац в 2000 символов — около 250 байт. Хвостовой пробел — 1 бит на строку: 100 строк ≈ 12 байт.

Вывод: **флаг помещается, большой архив — почти нет**. Если после извлечения получилась ссылка или base64 — значит, дальше второй этап.

## Если не сработало

- Сначала `cat -A` (пробелы/табы), потом дамп кодовых точек (zero-width).
- Попробуй оба порядка бит (0/1 могут быть перепутаны).
- Проверь регистр, пунктуацию, акростих.
- Если ничего — возможно, текст лишь контейнер: внутри base64, URL или вложенный документ.

## Что мы теперь знаем

1. Текстовые каналы делятся на невидимые, структурные и семантические.
2. Невидимые (`U+200B/200C/...`) ищут дампом кодовых точек.
3. Хвостовые пробелы/табы видны через `cat -A`.
4. Регистр, пунктуация, акростих — структурные каналы.
5. Ёмкость мала: хватает на флаг, не на архив.

## Шаг 6: гомоглифы в доменах (IDN-спуфинг)

Гомоглифы не ограничены текстом — они лежат в основе **IDN-спуфинга**: домены с символами разных алфавитов выглядят идентично. Например, `аpple.com` с кириллической `а` внешне неотличим от настоящего. В стеганографии тот же приём: выбор алфавита для каждой буквы кодирует бит.

Обнаружение — сравнение `unicodedata.name` каждой буквы; смешение `LATIN`/`CYRILLIC`/`GREEK` — признак канала:

```python
import unicodedata as u
from collections import Counter
s = open('t.txt', encoding='utf-8').read()
print(Counter(u.name(c).split()[0] for c in s if u.category(c).startswith('L')))
```

## Шаг 7: сравнительная таблица текстовых каналов

| Канал | Носитель | Заметность | Ёмкость | Как ловить |
|---|---|---|---|---|
| Пробел/таб в хвосте | 1 бит на строку | средняя | низкая | `cat -A` |
| Zero-width | 1–2 бита на символ | очень низкая | средняя | дамп кодовых точек |
| Гомоглифы | 1 бит на букву | низкая | средняя | `unicodedata.name` |
| Регистр | 1 бит на букву | средняя | высокая | `.isupper()` |
| Пунктуация | 1 бит на знак | низкая | средняя | разбор предложений |
| Акростих | 1 символ на строку | высокая | низкая | первые буквы |
| Синонимы | 1 бит на слово | очень низкая | средняя | словарь |

Таблица задаёт порядок проверок: сначала невидимые (zero-width, пробелы), затем структурные, затем семантические.

## Шаг 8: автоматизация перебора

Когда правило неизвестно, быстрее прогнать все каналы одним скриптом:

```python
import re, unicodedata as u
raw = open('text.txt', encoding='utf-8').read()
def b2b(bits):
    return bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
zw = [c for c in raw if c in '\u200b\u200c\u200d\ufeff\u2060']
if zw:
    print('zw:', b2b(''.join('1' if c == '\u200b' else '0' for c in zw)))
letters = [c for c in raw if u.category(c).startswith('L')]
print('homoglyph:', b2b(''.join('1' if u.name(c).startswith('CYRILLIC') else '0' for c in letters)))
words = re.findall(r'\b[A-Za-zА-Яа-я]+\b', raw)
print('case:', b2b(''.join('1' if w[0].isupper() else '0' for w in words)))
print('acrostic:', ''.join(l[0] for l in raw.splitlines() if l))
```

Такой «веер» закрывает большинство текстовых задач за один прогон.

## Где пригодится

- **CTF (Steganography):** письма, README, логи с «лишними» символами.

- **OSINT:** метки zero-width в документах для отслеживания копий.
- **Blue team:** детект скрытых каналов в переписке и документах.
