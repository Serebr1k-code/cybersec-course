## Пробелы и табы: базовый бинарный канал

Самый старый и самый надёжный текстовый канал: пробел (`0x20`) = бит `0`, таб (`0x09`) = бит `1`. Данные размещают либо в конце каждой строки, либо в отступах в начале. Такой текст выглядит абсолютно нормально в браузере и редакторе без подсветки, но выдаёт себя при `cat -A`.

```bash
$ cat -A note.txt
Hello world^I
Goodbye world $
^I^IThird line$
```

Здесь `^I` — таб (1), `$` — конец строки; в первой строке таб, во второй — пробел. Считываем биты по строкам: `1 0 1 ...`. Собрав 8 бит, получаем байт.

Порядок бит (MSB-first / LSB-first) и порядок чтения (по строкам / по позициям / по словам) — главные источники «пустого» результата. Всегда пробуй оба порядка: если получилась каша из непечатаемых символов — инвертируй порядок бит.

## Trailing whitespace и отступы: практика извлечения

Полезно помнить, что многие редакторы автоматически удаляют хвостовые пробелы при сохранении — поэтому в задачах файл дают «как есть» (raw). Если вы скопируете текст через веб-форму, канал, скорее всего, погибнет. Работайте с оригинальным файлом.

Подсветить хвостовые пробелы/табы:

```bash
grep -nP '[\t ]+$' note.txt        # строки с trailing whitespace
sed -n 's/\([ \t]*\)$/[\1]/p' note.txt   # обернуть хвост в скобки
```

Извлечение бит (пробел=0, таб=1) по последнему символу строки:

```python
lines = open('note.txt').read().split('\n')
bits = ''.join('1' if line.endswith('\t') else '0' for line in lines if line)
# игнорируем пустые строки; если строк не кратно 8 — возможно, канал в отступах
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data)
```

Если канал в отступах, а не в хвосте, считайте количество ведущих пробелов и сравнивайте с порогом: `≥4 пробела = 1`, `<4 = 0` (или наоборот). Иногда кодируют не бинарно, а по числу пробелов: `1 пробел = A`, `2 = B`… — это уже не бинарный, а унарный канал.

## Zero-width символы Unicode

Невидимые символы, которые не занимают места и не отображаются, но присутствуют в потоке. Основные:

| Символ | Код | Имя |
|---|---|---|
| ZWSP | U+200B | zero width space |
| ZWNJ | U+200C | zero width non-joiner |
| ZWJ | U+200D | zero width joiner |
| BOM | U+FEFF | zero width no-break space |
| WJ | U+2060 | word joiner |
| LTR/RTL marks | U+200E/U+200F | direction marks |

Два разных невидимых символа → бит (0/1). Четыре → два бита. Восемь → байт напрямую. Порядок и набор символов задаёт автор задачи; перебирайте комбинации.

```python
s = open('text.txt', encoding='utf-8').read()
zw = [c for c in s if c in '\u200b\u200c\u200d\ufeff\u2060']
print(len(zw), [hex(ord(c)) for c in zw[:20]])
# два вида → бит
bits = ''.join('1' if c == '\u200b' else '0' for c in zw)
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8)))
```

## Гомоглифы и смешанные алфавиты

Гомоглифы — символы разных алфавитов, визуально неотличимые: латинская `a` и кириллическая `а`, латинская `o` и греческая `ο`. Автор задачи заменяет часть букв «двойниками»; выбор алфавита кодирует бит. Обычно это работает в доменах (IDN-спуфинг), но в CTF встречается и в тексте.

```python
import unicodedata as u
s = open('t.txt', encoding='utf-8').read()
names = [u.name(c) for c in s if u.category(c).startswith('L')]
print(names[:30])
# LATIN SMALL LETTER A vs CYRILLIC SMALL LETTER A — разные имена
```

Определите, какие алфавиты смешаны (`LATIN`, `CYRILLIC`, `GREEK`), и сопоставьте их с битами. Если гомоглифов ровно два «сорта» на каждую букву — это бинарный канал.

## Структурные каналы: акростих, регистр, пунктуация, порядок слов

Структурные каналы не требуют невидимых символов — они используют уже присутствующую структуру:

- **Акростих** — первая буква каждого слова/строки складывается в сообщение.
- **Регистр** — заглавная/строчная буква = 1/0 (`CaSeD` текст).
- **Пунктуация** — запятая vs точка, наличие/отсутствие точки в конце строки.
- **Порядок слов** — перестановки, сортировка.
- **Первая/последняя буква** слова или строки.
- **Число слов в строке** — унарный канал.

```python
lines = open('poem.txt').read().split('\n')
print(''.join(l[0] for l in lines if l))       # акростих
bits = ''.join('1' if w[0].isupper() else '0'
               for w in open('case.txt').read().split())
```

## Инструменты и CyberChef-рецепты

- **CyberChef**: рецепты `Extract Zero-Width`, `From Unicode`, `To/From Base64`, `From Charcode`. Удобно грузить файл целиком и цеплять операции.
- **`cat -A` / `xxd`** — увидеть невидимое.
- **`unicode.py`** (pip `unicode` / вручную) — дамп кодовых точек.
- **`stegoveritas`** — общий анализатор, умеет часть текстовых трюков.
- **Собственные скрипты** — почти всегда быстрее, чем искать готовый тул под конкретный канал.

## Разобранный пример: от «пустого» текста до флага

Задача: `message.txt` содержит один абзац, флаг не виден.

```bash
$ cat -A message.txt | head
The quick brown fox^I
jumps over the lazy dog $
$ python3 - <<'PY'
lines=[l for l in open('message.txt').read().split('\n') if l]
bits=''.join('1' if l.endswith('\t') else '0' for l in lines)
print(bytes(int(bits[i:i+8],2) for i in range(0,len(bits)-7,8)))
PY
b'flag{t4bs_4nd_sp4c3s}'
```

Если бы `cat -A` показал обычный текст, следующим шагом был бы поиск zero-width, затем гомоглифов, затем акростих/регистр. Именно такой порядок (дешёвые проверки → сложные) экономит время.

## Частые ошибки и подводные камни

- **Смотреть только видимые символы** — zero-width и trailing whitespace невидимы в браузере.
- **Копировать текст через мессенджер/веб** — канал разрушается; берите исходный файл.
- **Не проверять оба порядка бит и оба направления обхода.**
- **Игнорировать смешанные алфавиты** — гомоглифы часто принимают за «опечатки».
- **Пропускать структурные каналы**, когда невидимых символов нет: акростих/регистр решают такие задачи.
- **Путать BOM в начале файла** (U+FEFF) с данными — иногда это просто метка кодировки.

## Сравнение текстовых каналов и выбор стратегии

Все текстовые каналы удобно свести в одну таблицу — это ускоряет выбор инструмента в задаче:

| Канал | Носитель данных | Заметность | Ёмкость | Чем ловить |
|---|---|---|---|---|
| Пробел/таб в хвосте | 1 бит на строку | средняя (`cat -A`) | низкая | `cat -A`, скрипт |
| Пробел/таб в отступе | 1 бит на строку | средняя | низкая | подсчёт отступов |
| Zero-width | 1–2 бита на символ | очень низкая | средняя | дамп кодовых точек |
| Гомоглифы | 1 бит на букву | низкая | средняя | `unicodedata.name` |
| Регистр | 1 бит на букву | средняя | высокая | проверка `.isupper()` |
| Пунктуация | 1 бит на знак | низкая | средняя | разбор по предложениям |
| Акростих | 1 символ на строку/слово | высокая | низкая | первые буквы |
| Число слов/строк | унарный | высокая | низкая | подсчёт |

Практическая стратегия: начинать с **самых дешёвых проверок** (`cat -A` и дамп кодовых точек), потому что они дают ответ мгновенно и не требуют догадок. Только если оба пусты, переходить к структурным каналам, которые требуют «угадать» правило кодирования.

## Ёмкость текстовых каналов

Ёмкость — это сколько байт реально помещается. Для текстовых каналов она невелика, и это важно понимать: если в задаче ожидается большой файл (архив, картинка), то он спрятан **не** в текстовом канале, а скорее всего в дописанном хвосте или в base64-блоке внутри текста.

- Zero-width: 1 символ = 1 бит → ~8 символов на байт. Абзац из 2000 символов ≈ 250 байт.
- Регистр: 1 бит на букву → похожая ёмкость.
- Хвостовой пробел/таб: 1 бит на строку → 100 строк = ~12 байт.

Отсюда правило: **флаг влезает легко, архив — почти никогда**. Если из текстового канала извлеклась строка вида `https://…` или `aHR0cHM6…`, дальше идёт второй этап (скачать/декодировать base64).

## Автоматизация перебора текстовых каналов

Когда правила неизвестны, полезно прогнать все каналы одним скриптом:

```python
import re, unicodedata as u
raw = open('text.txt', encoding='utf-8').read()

def bits_to_bytes(bits):
    out = bytearray()
    for i in range(0, len(bits) - 7, 8):
        out.append(int(bits[i:i+8], 2))
    return bytes(out)

# 1) zero-width (два вида → бит)
zw = [c for c in raw if c in '\u200b\u200c']
if zw:
    b = ''.join('1' if c == '\u200b' else '0' for c in zw)
    print('zw:', bits_to_bytes(b))

# 2) гомоглифы: LATIN vs CYRILLIC
letters = [c for c in raw if u.category(c).startswith('L')]
b = ''.join('1' if u.name(c).startswith('CYRILLIC') else '0' for c in letters)
print('homoglyph:', bits_to_bytes(b))

# 3) регистр
words = re.findall(r'\b[A-Za-zА-Яа-я]+\b', raw)
b = ''.join('1' if w[0].isupper() else '0' for w in words)
print('case:', bits_to_bytes(b))
```

Такой «веер» закрывает 90 % текстовых задач за один прогон: печатаемый результат в одном из каналов почти наверняка окажется флагом или подсказкой.

## Что делать дальше / решение

- `cat -A` → пробелы/табы → биты → байты (проверьте оба порядка).
- Нет — ищите zero-width: дамп кодовых точек, маппинг 2/4/8 символов в биты.
- Нет — смешанные алфавиты: `unicodedata.name`, латиница/кириллица → биты.
- Нет — структурные каналы: акростих, регистр, пунктуация, число слов.
- Совсем пусто — текст может быть контейнером для другого носителя (base64, QR в описании, PDF/DOCX-метаданные).
