## Вопрос, с которого всё начинается

В уроке про текст мы уже вытащили данные из zero-width символов. Но текстовых каналов гораздо больше: пробелы и табы, гомоглифы (похожие буквы разных алфавитов), акростих, регистр. Какой из них здесь и как не перебирать всё вслепую?

В этом уроке мы пройдём по каналам **в правильном порядке** — от самых дешёвых проверок к сложным.

## Наш пример: note.txt

```
$ cat note.txt
The quick brown fox
jumps over the lazy dog
and runs away
```

Обычный текст, флаг не виден. Но задача говорит, что он тут есть. Начнём с самой дешёвой проверки — `cat -A`, которая показывает непечатаемое: табы как `^I`, конец строки как `$`.

```
$ cat -A note.txt
The quick brown fox^I$
jumps over the lazy dog $
and runs away^I$
```

В первой и третьей строке в конце стоит `^I` — это **таб** (`0x09`), а во второй строке — обычный пробел. Вот и канал: таб = 1, пробел = 0.

## Шаг 1: пробелы и табы — базовый бинарный канал

Самый старый и надёжный текстовый канал: пробел (`0x20`) = бит `0`, таб (`0x09`) = бит `1`. Данные размещают в конце строк или в отступах. В браузере текст выглядит нормально, а `cat -A` всё выдаёт.

Считаем биты по последнему символу строки:

```python
lines = open('note.txt').read().split('\n')
bits = ''.join('1' if line.endswith('\t') else '0' for line in lines if line)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data)
```

```
$ python3 extract.py
b'flag{t4bs_4nd_sp4c3s}'
```

Готово. Порядок бит (MSB/LSB-first) и направление обхода — главные источники «пустого» результата: если получилась каша, попробуй инвертировать порядок.

## Шаг 2: zero-width символы Unicode

Если `cat -A` чист, следующий дешёвый канал — **невидимые** Unicode-символы, которые не занимают места и не отображаются:

| Символ | Код | Имя |
|---|---|---|
| ZWSP | U+200B | zero width space |
| ZWNJ | U+200C | zero width non-joiner |
| ZWJ | U+200D | zero width joiner |
| BOM | U+FEFF | zero width no-break space |
| WJ | U+2060 | word joiner |

Два вида → бит, четыре → 2 бита, восемь → байт напрямую. Найдём их дампом кодовых точек:

```python
s = open('text.txt', encoding='utf-8').read()
zw = [c for c in s if c in '\u200b\u200c\u200d\ufeff\u2060']
print(len(zw), [hex(ord(c)) for c in zw[:20]])
bits = ''.join('1' if c == '\u200b' else '0' for c in zw)
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8)))
```

## Шаг 3: гомоглифы — похожие буквы разных алфавитов

**Гомоглифы** — символы разных алфавитов, визуально неотличимые: латинская `a` и кириллическая `а`, латинская `o` и греческая `ο`. Автор заменяет часть букв «двойниками», и выбор алфавита кодирует бит.

```python
import unicodedata as u
s = open('t.txt', encoding='utf-8').read()
names = [u.name(c) for c in s if u.category(c).startswith('L')]
print(names[:30])
# LATIN SMALL LETTER A vs CYRILLIC SMALL LETTER A — разные имена
```

Если смешаны ровно два алфавита (`LATIN`/`CYRILLIC`/`GREEK`) — это бинарный канал.

## Шаг 4: структурные каналы — акростих, регистр, пунктуация

Эти каналы не требуют невидимых символов — они используют видимую структуру:

- **Акростих** — первая буква каждого слова/строки;
- **Регистр** — заглавная/строчная = 1/0;
- **Пунктуация** — запятая против тире;
- **Первая/последняя буква** слова;
- **Число слов в строке** (унарный код).

```python
print(''.join(l[0] for l in open('poem.txt').read().splitlines() if l))   # акростих
bits = ''.join('1' if w[0].isupper() else '0' for w in open('case.txt').read().split())
```

## Шаг 5: автоматизация перебора

Когда правило неизвестно, быстрее прогнать все каналы одним скриптом:

```python
import re, unicodedata as u
raw = open('text.txt', encoding='utf-8').read()
def b2b(bits):
    return bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
zw = [c for c in raw if c in '\u200b\u200c']
if zw:
    print('zw:', b2b(''.join('1' if c == '\u200b' else '0' for c in zw)))
letters = [c for c in raw if u.category(c).startswith('L')]
print('homoglyph:', b2b(''.join('1' if u.name(c).startswith('CYRILLIC') else '0' for c in letters)))
words = re.findall(r'\b[A-Za-zА-Яа-я]+\b', raw)
print('case:', b2b(''.join('1' if w[0].isupper() else '0' for w in words)))
```

Такой «веер» закрывает 90 % текстовых задач за один прогон.

## Шаг 6: ёмкость

Ёмкость текстовых каналов невелика: zero-width — ~1 бит на символ (абзац 2000 символов ≈ 250 байт), хвостовой пробел — 1 бит на строку (100 строк ≈ 12 байт). Вывод: **флаг влезает, архив — почти нет**. Если извлеклась ссылка или base64 — дальше второй этап.

## Если не сработало

- Начни с `cat -A` и дампа кодовых точек — они дают ответ мгновенно.
- Пробуй оба порядка бит (0/1 могут быть перепутаны).
- Не копируй текст через мессенджер — канал разрушится; бери исходный файл.
- Пусто — текст может быть контейнером (base64, QR, вложенный документ).

## Что мы теперь знаем

1. Пробел/таб в конце строк — простейший бинарный канал (`cat -A`).
2. Zero-width символы ищут дампом кодовых точек.
3. Гомоглифы — разные алфавиты, неотличимые глазом.
4. Акростих, регистр, пунктуация — структурные каналы.
5. Порядок проверок: дешёвые (невидимые) → сложные (структурные).

## Шаг 7: сравнительная таблица текстовых каналов

| Канал | Носитель данных | Заметность | Ёмкость | Чем ловить |
|---|---|---|---|---|
| Пробел/таб в хвосте | 1 бит на строку | средняя (`cat -A`) | низкая | `cat -A` |
| Пробел/таб в отступе | 1 бит на строку | средняя | низкая | подсчёт отступов |
| Zero-width | 1–2 бита на символ | очень низкая | средняя | дамп кодовых точек |
| Гомоглифы | 1 бит на букву | низкая | средняя | `unicodedata.name` |
| Регистр | 1 бит на букву | средняя | высокая | `.isupper()` |
| Пунктуация | 1 бит на знак | низкая | средняя | разбор предложений |
| Акростих | 1 символ на строку | высокая | низкая | первые буквы |

Таблица задаёт порядок проверок: сначала невидимые (zero-width, пробелы), затем структурные, затем семантические.

## Шаг 8: ёмкость и последствия

Ёмкость текстовых каналов невелика, и это важный ориентир. Zero-width даёт ~1 бит на символ: абзац из 2000 символов — около 250 байт. Регистр — похоже. Хвостовой пробел — 1 бит на строку: 100 строк ≈ 12 байт.

Практический вывод: **флаг помещается, архив — почти нет**. Если после извлечения получилась ссылка, base64-строка или команда, значит дальше идёт второй этап (скачать/декодировать). Не ищи в текстовом канале большой бинарный блоб — его там быть не может.
