## Вопрос, с которого всё начинается
Ты получил файл `blob.txt`: длинная строка из букв, цифр и `=`. Похоже на base64,
но декодирование даёт мусор. Значит, поверх кодирования есть второй слой —
например, XOR. Вручную перебирать комбинации долго; CyberChef делает это
автоматически через операцию **Magic**.

## Наш пример
Возьмём `blob.txt`. Прогоним его через CyberChef-подобную цепочку: base64 →
XOR → текст, и получим метку.

## Шаг 1: что такое CyberChef
CyberChef — браузерный «швейцарский нож» для данных. Ты собираешь **рецепт** из
операций: `From Base64`, `XOR`, `Gunzip`, `Extract LSB`, `Detect File Type`,
`Strings` и сотен других. Каждая операция принимает вход и отдаёт выход; рецепт
применяется слева направо.

## Шаг 2: операция Magic
`Magic` перебирает десятки операций и их параметров, пытаясь превратить вход во
что-то осмысленное. Это быстрый способ «размотать» неизвестную цепочку. Magic
часто сам определяет base64 → gzip → текст.

## Шаг 3: ключевые операции для стего
- **From Base64 / To Base64** — кодирование.
- **XOR / XOR Brute Force** — перебор однобайтового ключа.
- **Gunzip / Zlib Inflate / Raw Inflate** — распаковка.
- **Extract LSB** — извлечение младших битов из изображения.
- **Detect File Type** — определение формата по магии.
- **Strings / Extract** — извлечение строк/подстрок по шаблону.
- **Rot13 / ROT47 / Atbash** — простые шифры.

## Шаг 4: ручной рецепт для нашего файла
Если Magic не сработал, строим цепочку вручную. Наш `blob.txt` — base64, после
декодирования — байты, XOR-нутые ключом `0x42`:

```python
import base64
raw = base64.b64decode(open('blob.txt','rb').read())
print(bytes(b ^ 0x42 for b in raw).decode())
```

Вывод:

```
nto{cyberchef_recipe_xor}
```

В CyberChef то же самое — рецепт `From Base64` → `XOR (0x42)`.

## Шаг 5: автоматизация и CLI
CyberChef — браузерный, но есть CLI-обёртки (`cyberchef-cli`, `node cyberchef`)
для пакетной обработки. Для CTF удобно держать набор готовых рецептов:
`base64→gunzip`, `xor-bruteforce→strings`, `extract-lsb→png`.

## CyberChef: рецепты, Magic и CLI

CyberChef — веб-приложение (и CLI `cyberchef`), которое применяет к данным цепочку операций («рецепт»). Это удобно для быстрого перебора кодирований и преобразований. Операция **Magic** автоматически подбирает декодер, анализируя данные (энтропия, алфавит, сигнатуры).

Ключевые операции для стего: `From Base64`, `From Hex`, `From Base32`, `From Charcode`, `ROT13`, `XOR`, `Gunzip`, `Unzip`, `Detect File Type`, `Extract Files`, `Strings`, `To Hexdump`, `Entropy`. Рецепт собирается перетаскиванием, результат виден сразу.

```bash
# CLI (если установлен): применить цепочку операций
cyberchef --recipe "From_Base64('A-Za-z0-9+/=',true)" input.txt
```

Практический рецепт для нашего файла: `From Base64` → `Gunzip` → `Strings` → `Extract Files`. Если на каком-то шаге результат не имеет смысла, вернись и попробуй другой декодер (Base32, Hex, ROT13).

Плюсы: наглядность, много операций, Magic. Минусы: Magic — эвристика, её вывод надо проверять; для больших файлов веб-версия тормозит; некоторые операции специфичны. Поэтому CyberChef хорош для быстрого исследования, но финальный разбор часто делают скриптом.

## Практика: Magic и проверка результата

Операция Magic анализирует вход и предлагает вероятные декодирования. Она смотрит на энтропию (сжато/зашифровано?), алфавит (base64/hex/base32?), сигнатуры (известный формат?) и пробует применить подходящие операции. Вывод Magic — список кандидатов с оценкой.

```text
Input: "S2xhc3M6IG50b3tmbGFnfQ=="
Magic suggests: From Base64 (100%) -> "nto{flag}"
```

Правило: Magic — подсказка, а не истина. Всегда проверяй результат: если после декодирования получился текст с флагом — хорошо; если мусор — попробуй следующий кандидат или собери рецепт вручную. Часто Magic останавливается на первом слое и не разматывает цепочку.

Для многослойных данных собирай рецепт по шагам: сначала один декодер, посмотри результат, затем добавь следующий. Так ты видишь, где цепочка ломается, и не принимаешь мусор за данные.

## Ключевые операции для стего подробнее

`From Base64` / `From Base32` / `From Base85` — декодирование текстовых кодировок. `From Hex` — hex → байты. `From Charcode` — числа → символы. `ROT13` — сдвиг латиницы. `XOR` — с указанием ключа (однобайтовый, hex, base64). `Gunzip`/`Unzip`/`Bzip2 Decompress`/`XZ Decompress` — распаковка. `Detect File Type` — определить формат. `Extract Files` — вырезать вложенные файлы по сигнатурам. `Strings` — печатаемые строки. `Entropy` — энтропия. `To Hexdump` — hex-дамп.

```text
From Base64 -> Gunzip -> Strings -> Extract Files
```

Комбинируя эти операции, можно размотать большинство CTF-стего. Важно понимать, что делает каждая: например, `XOR` требует ключа, а `Gunzip` ожидает gzip-сигнатуру (`\x1f\x8b`) — если её нет, операция упадёт.

Полезная связка для неизвестных данных: `Detect File Type` → если base64, то `From Base64` → снова `Detect File Type` → распаковать/декодировать. Так ты идёшь по цепочке, определяя формат на каждом шаге.

## Автоматизация и CLI

CyberChef есть в веб-версии (gchq.github.io/CyberChef) и как CLI (Node.js-пакет `cyberchef` или `cook`). CLI принимает рецепт в виде строки операций и файл на входе.

```bash
npm install -g cyberchef
cyberchef -i input.b64 -o output.bin "From Base64"
cyberchef -i data.gz -o data.txt "Gunzip"
```

Рецепт можно экспортировать из веб-версии как строку и передать в CLI. Это удобно для воспроизводимых разборов: сохранил рецепт — воспроизвёл результат. Для больших файлов CLI быстрее веб-версии.

Альтернатива — написать разбор на Python (`base64`, `gzip`, `binascii`, `struct`), что даёт полный контроль и легко коммитится в репозиторий как скрипт. Для разовых задач CyberChef быстрее, для повторяемых — скрипт.

## Ограничения и типичные ошибки

Ограничения: Magic — эвристика и ошибается на нестандартных данных; веб-версия тормозит на больших файлах; некоторые операции (например, кастомные шифры) отсутствуют. Типичные ошибки: принимать вывод Magic за истину; не проверять, что результат осмыслен; применять `Gunzip` без сигнатуры gzip; путать base64 и base32 (разные алфавиты); забывать про порядок операций (сначала декодировать, потом распаковывать).

Практический вывод: CyberChef — отличный инструмент для быстрого исследования и перебора, но финальный разбор лучше фиксировать скриптом. Тогда результат воспроизводим и его можно приложить к отчёту.

## Разбор примера: рецепт для base64+gzip

Возьмём типичную CTF-строку, которая на самом деле gzip, закодированный в base64. Начнём в CyberChef с операции `From Base64`: на выходе — бинарные данные, начинающиеся с `\x1f\x8b` (сигнатура gzip).

```text
Input : H4sIAAAAAAAAA8tIzcnJBwCGphA9BQAAAA==
Op    : From Base64
Output: \x1f\x8b\x08\x00...   (gzip)
```

Добавляем `Gunzip`: получаем текст. Если текст — ещё base64, добавляем ещё один `From Base64`. Так рецепт растёт по одному слою, и на каждом шаге видно результат.

Практический приём: добавь в конец рецепта `Strings` — тогда в выводе видны только печатаемые строки, и флаг легко заметить. Ещё удобно добавить `Extract Files` — если в данных есть вложенный файл, он будет извлечён автоматически.

Экспортируй рецепт (кнопка Export) в виде строки и сохрани — это документирует твой путь решения. Для отчёта приложи рецепт и результат.

## Автоматизация перебора

Когда неясно, какое кодирование применено, помогает перебор. В CyberChef есть операция `Magic` (автоподбор), а также возможность вручную перебрать декодеры. Для однобайтового XOR можно использовать операцию `XOR` с `Brute force` (перебор ключей 0–255) и смотреть, где результат «читаем».

```text
XOR (Brute force) -> Strings   # найти читаемый результат
```

Аналогично для ROT: операция `ROT13` с `Rotate amount` и `Rotate by` перебирает сдвиги. Для base-кодировок — попробовать `From Base64`, `From Base32`, `From Base85` по очереди.

Практический порядок перебора: сначала определить алфавит (base64? hex? текст?), применить соответствующий декодер; если результат бинарный — определить формат и распаковать; если текст — проверить на ещё одно кодирование. Так перебор становится направленным, а не слепым.

## Работа с большими файлами

Веб-версия CyberChef держит всё в памяти браузера, поэтому большие файлы (десятки МБ) могут её подвесить. Для больших данных используй CLI или скрипт.

```bash
# извлечь вложенное из большого файла через CLI
cyberchef -i big.bin "Extract Files"
```

Альтернатива — разбить задачу: сначала `binwalk`/`foremost` (быстрые, потоковые), затем CyberChef на вырезанном фрагменте. Для повторяемых разборов пиши Python-скрипт: он работает с любым размером и воспроизводим.

Практический вывод: CyberChef — инструмент для исследования небольших фрагментов и быстрого перебора, а не для обработки гигабайтных образов. Выбирай инструмент по размеру задачи.

## Итог по CyberChef

CyberChef — визуальный конструктор преобразований с автоподбором (Magic) и CLI. Сильные стороны: наглядность, множество операций, быстрый перебор. Слабые: Magic — эвристика, большие файлы тормозят, не все кастомные шифры поддержаны. Используй его для исследования, а финальный разбор фиксируй скриптом или экспортированным рецептом. Ключевые операции: base-декодеры, XOR, распаковщики, `Detect File Type`, `Extract Files`, `Strings`, `Entropy`.
