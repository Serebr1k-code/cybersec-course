## Вопрос, с которого всё начинается

Тебе дали `cat.gif` — короткую анимацию. Открываешь — кот машет лапой, ничего необычного. Но флаг где-то внутри. GIF — не простая картинка: это **палитровый** формат с поддержкой **анимации**, и у него куча «свободных» параметров: задержки кадров, отдельные палитры, служебные блоки. Каждый из них — канал.

Разберём это на конкретной анимации.

## Наш пример: cat.gif

Начнём с общей информации: сколько кадров, какие задержки, сколько цветов.

```
$ identify -verbose cat.gif | grep -iE "delay|scene|colors" | head
  Delay: 10x100
  Scene: 0 of 12
  Delay: 20x100
  Scene: 1 of 12
  ...
```

`identify` — часть ImageMagick. Мы видим: 12 кадров, а задержки принимают ровно **два** значения — `10` и `20` (в сотых долях секунды). Два значения — это уже подозрительно: похоже на бинарный канал.

## Шаг 1: задержки как биты

Договоримся: задержка `10` = бит `0`, задержка `20` = бит `1`. Вытащим список задержек в удобном формате:

```
$ identify -format "%s %T\n" cat.gif
0 10
1 20
2 10
3 10
4 20
...
```

Теперь соберём из них биты и байты. Удобнее всего на Python через Pillow:

```python
from PIL import Image, ImageSequence
im = Image.open('cat.gif')
delays = [f.info.get('duration', 0) for f in ImageSequence.Iterator(im)]
bits = ''.join('1' if d == 20 else '0' for d in delays)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data)
```

```
$ python3 extract.py
b'flag{gif_timing}'
```

Флаг был закодирован в **таймингах** — на глаз анимация выглядит обычно. Это, пожалуй, самый частый канал в GIF-задачах.

## Шаг 2: что ещё можно извлечь из задержек

Задержки бывают не только двух значений:

- **два значения** — бинарный канал (как у нас);
- **несколько значений** — можно кодировать базу-N (например, 3 значения = триты);
- **короткая/длинная пауза** — код Морзе.

Если `10`/`20` не сработало, посмотри распределение задержек: возможно, порог нужно взять другим (медиану).

## Шаг 3: скрытые и лишние кадры

Иногда данные — в кадре, который «не успевает» показаться (задержка 0) или просто спрятан. Разложим анимацию на кадры:

```
$ convert cat.gif frames/frame_%03d.png
$ ls frames | wc -l
13
```

Видимых кадров 12, а файлов — 13. Лишний кадр — кандидат на закладку. Или просто посмотрим последний кадр глазами: там часто текст или QR.

Есть и трюк с **позицией кадра**: Image Descriptor задаёт, где кадр рисуется. Кадр может быть нарисован **за пределами** видимой области — тогда его не видно, но он есть.

## Шаг 4: палитра — отдельный канал

GIF палитровый: пиксель хранится как **индекс** в палитре (0..255), а не как RGB. Поэтому LSB «пикселей» — это LSB **индексов**, а не цветов. Вот почему обычный RGB-LSB тут часто молчит.

```python
from PIL import Image
im = Image.open('cat.gif')
pal = im.getpalette()
idx = list(im.convert('P').getdata())
bits = ''.join(str(i & 1) for i in idx)
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8)))
# LSB самой палитры
pbits = ''.join(str(c & 1) for c in pal)
print(bytes(int(pbits[i:i+8], 2) for i in range(0, len(pbits) - 7, 8)))
```

Каналы палитры: **порядок** цветов (перестановка кодирует данные), «неиспользуемые» записи за пределами числа цветов, дубликаты с разными LSB.

## Шаг 5: структура GIF — где ещё искать

GIF — поток блоков, и каждый блок может нести данные:

| Блок | Маркер | Канал |
|---|---|---|
| Header | `GIF87a`/`GIF89a` | версия |
| Global Color Table | — | порядок/LSB цветов |
| Comment Extension | `21 FE` | **текст-флаг напрямую** |
| Graphic Control Extension | `21 F9` | **задержка, disposal** |
| Image Descriptor | `2C` | позиция/размер кадра |
| Image Data | — | LSB индексов |
| Trailer | `3B` | **данные после него** |

Проверим комментарий и хвост:

```
$ strings -a cat.gif | head
$ binwalk cat.gif
$ grep -abo $'\x3b' cat.gif
```

Комментарий (`21 FE`) часто содержит флаг или подсказку, а после трейлера `3B` может лежать целый ZIP.

## Шаг 6: различия между кадрами

Ещё один приём — данные в **разнице** соседних кадров. Попарный XOR/вычитание выявляет то, что незаметно при воспроизведении:

```python
from PIL import Image, ImageChops
a = Image.open('frames/frame_001.png'); b = Image.open('frames/frame_002.png')
ImageChops.difference(a.convert('RGB'), b.convert('RGB')).save('diff.png')
```

## Если не сработало

- Смотри **задержки** в первую очередь — самый частый канал.
- Проверь **лишние/нулевые** кадры, включая последний.
- Для палитрового GIF извлекай LSB **индексов**, а не RGB.
- Не забудь про хвост после `3B` и Comment Extension.
- Если GIF «битый» — восстанови через `gifsicle --repair` или `convert`.

## Что мы теперь знаем

1. GIF — палитровый анимированный формат с множеством «свободных» параметров.
2. Задержки кадров кодируют биты (10=0, 20=1) — частый канал.
3. Лишние/нулевые кадры и кадры за пределами экрана прячут данные.
4. В палитровом GIF LSB берут у **индексов**, а не у RGB.
5. Комментарий и хвост после `3B` — тоже каналы.

## Шаг 7: полная структура GIF (byte-level)

GIF — поток блоков, и каждый блок — потенциальный канал. Точная структура позволяет вырезать данные там, где автоинструменты слепы:

| Блок | Маркер | Стего-канал |
|---|---|---|
| Header | `GIF87a`/`GIF89a` | версия |
| Logical Screen Descriptor | — | aspect/фон |
| Global Color Table | — | порядок/LSB цветов |
| Application Extension | `21 FF` | счётчик циклов NETSCAPE |
| Comment Extension | `21 FE` | **текст-флаг напрямую** |
| Graphic Control Extension | `21 F9` | **задержка, disposal** |
| Image Descriptor | `2C` | позиция/размер кадра |
| Image Data | LZW | LSB индексов |
| Trailer | `3B` | **данные после него** |

```
$ xxd animation.gif | grep -iE '21 f9|21 fe|21 ff|2c|3b'
$ strings -a animation.gif | head
```

## Шаг 8: разбор кадров полным набором инструментов

```
$ convert cat.gif frames/frame_%03d.png      # кадры
$ gifsicle --info cat.gif                    # информация о кадрах/задержках
$ gifsicle --explode cat.gif                 # каждый кадр отдельным .gif
$ gifsicle -b -d 10 cat.gif                  # установить задержку
$ ffmpeg -i cat.gif frames/%04d.png          # альтернатива
```

Ключевой приём: посмотреть **все** кадры, включая те, что «не успевают» показаться (задержка 0), и последний кадр — там часто текст или QR.

## Шаг 9: скрытые и смещённые кадры

- **кадр с задержкой 0** — визуально не появляется, но данные в нём есть;
- **кадр «за» видимым** — последний кадр может быть полным флагом;
- **смещённый кадр** — Image Descriptor задаёт позицию, кадр может быть нарисован за пределами экрана;
- **disposal method** (0..3) — способ очистки кадра тоже может кодировать биты.

```
$ gifsicle --explode cat.gif && ls frame*
$ for f in frame*; do zsteg "$f"; done
```
