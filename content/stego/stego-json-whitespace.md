## Вопрос, с которого всё начинается
Ты открыл `config.json`, посмотрел глазами — обычный конфиг: несколько ключей,
числа, строки. `jq . config.json` парсит без ошибок. Но что, если данные спрятаны
не в значениях, а в **пробелах**? JSON — свободный формат: между токенами можно
ставить любое количество пробелов, табов и переводов строк, и парсер этого даже
не заметит. Именно это «незначащее» пространство и становится каналом.

## Наш пример
Возьмём `config.json` — маленький конфиг приложения. Мы разберём его байты и
покажем, что отступы в начале строк кодируют сообщение.

## Шаг 1: JSON игнорирует пробелы
Спецификация JSON разрешает необязательные пробельные символы (`0x20`, `0x09`,
`0x0A`, `0x0D`) между любыми токенами. `{"a":1}` и `{  "a" : 1  }` — один и тот
же объект. Более того, порядок ключей и повторяющиеся ключи тоже допускаются
(поведение при дублях зависит от парсера). Всё это — свободное место.

## Шаг 2: отступ как бит
Договоримся: в начале каждой строки ставим ровно один пробел (`0`) или один таб
(`1`). Тогда каждая строка несёт один бит. Восемь строк — один символ.

```python
bits = ''.join(f'{ord(c):08b}' for c in 'Hi')
# '01001000' + '01101001'
```

Строим JSON, где ведущий пробел/таб каждой строки — это бит:

```
{
  "a": 1,
	"b": 2,
  "c": 3,
...
```

Парсер `json` его проглотит, а наш скрипт прочитает биты.

## Шаг 3: извлечение
```python
lines = open('config.json', encoding='utf-8').read().split('\n')
bits = ''
for ln in lines:
    if not ln or ln[0] not in (' ', '\t'):
        continue
    bits += '0' if ln[0] == ' ' else '1'
msg = ''.join(chr(int(bits[i:i+8], 2)) for i in range(0, len(bits) - 7, 8))
print(msg)
```

На нашем файле это печатает строку-метку, спрятанную в отступах.

## Шаг 4: другие каналы в JSON
- **Порядок ключей.** `{"a":1,"b":2}` и `{"b":2,"a":1}` семантически равны;
  перестановка ключей кодирует биты.
- **Дублирующиеся ключи.** `{"x":0,"x":1}` — многие парсеры берут последний;
  значения можно использовать как канал.
- **Unicode-escape.** `"a"` и `"\u0061"` — одна строка, разное написание.
- **Хвост после объекта.** `{"a":1}` + мусор: строгий парсер ошибётся, мягкий —
  проигнорирует; данные в хвосте.

## Шаг 5: инструменты и проверка
- `jq . config.json` — валидность и содержимое.
- `python3 -m json.tool config.json` — нормализация (убирает лишние пробелы —
  полезно, чтобы «убить» канал).
- `xxd config.json | head` — увидеть табы (`09`) и пробелы (`20`).

Нормализация — ключевой приём защиты: если пропустить JSON через строгий
сериализатор, скрытый канал в пробелах исчезнет.

## Полный разбор: пробелы как биты

JSON игнорирует пробелы, поэтому отступы и хвостовые пробелы — идеальный канал. Простейшая схема: один пробел = 0, два пробела = 1 (или таб = 1, пробел = 0). Читаешь файл построчно, извлекаешь разделители отступа и собираешь биты.

```python
bits = ""
for line in open("data.json"):
    indent = len(line) - len(line.lstrip(" "))
    if indent in (1, 2):
        bits += "0" if indent == 1 else "1"
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data)
```

Более тонкие схемы: кодировать данные **хвостовыми** пробелами (trailing whitespace) в конце строк, чередованием таба и пробела, числом пробелов после запятой. Все они работают, потому что JSON-парсер отбрасывает незначащие пробелы, а значит, файл остаётся валидным.

Проверка: `json.load` должен успешно распарсить файл (если нет — возможно, канал в чём-то другом). Сравни файл с «нормализованной» версией (пере-сериализуй через `json.dumps` с `indent=0`): разница покажет скрытые пробелы.

## Другие каналы в JSON

Помимо пробелов, в JSON есть несколько каналов. Первый — **порядок ключей**: JSON-объекты неупорядочены по стандарту, но парсеры сохраняют порядок вставки, и перестановка ключей может кодировать данные. Второй — **дубли ключей**: `{"a":1,"a":2}` технически допустим, парсеры берут последний, но первый можно использовать как канал. Третий — **формат чисел**: `1.0` vs `1`, `1e0`, `0x...` (не все валидны) — запись числа тоже может нести биты.

Четвёртый — **порядок элементов массива** и лишние запятые (не валидны в строгом JSON, но парсеры прощают). Пятый — **Unicode-escape**: `\u0041` и `A` эквивалентны, и выбор формы кодирует биты. Шестой — **BOM** и переводы строк (CRLF vs LF).

```bash
python3 -m json.tool data.json > /dev/null && echo "valid JSON"
diff <(cat data.json) <(python3 -c "import json;print(json.dumps(json.load(open('data.json')),indent=0))") | head
```

Практика: если пробельный анализ не дал результата, проверяй остальные каналы по очереди — порядок ключей, дубли, форму чисел, Unicode-escape.

## Инструменты и проверка

Инструменты: `python3` (`json`, `re`) — основной; `jq` (нормализация); `diff` (сравнение с нормализованной версией); `xxd` (байты, в том числе невидимые); `cat -A` (показать пробелы как `$`/`^I`).

```bash
cat -A data.json | head    # видно табы и концы строк
jq -c . data.json > norm.json && diff data.json norm.json | head
```

Проверка гипотезы: после извлечения битов проверь, что результат осмыслен (текст, сигнатура формата, флаг). Если получился мусор — попробуй другой порядок битов (MSB/LSB first), другую схему (таб/пробел), другой канал.

Типичные ошибки: считать, что JSON «безопасен» для сокрытия (наоборот — избыточность пробелов делает его удобным); игнорировать хвостовые пробелы (редакторы их подчищают, поэтому проверяй исходные байты, а не текст в IDE); забывать про кодировку (UTF-8 vs UTF-16 меняет представление).

## Практика: извлекаем и нормализуем

Полный цикл на файле `data.json`. Шаг первый — проверить валидность: `python3 -m json.tool data.json`. Шаг второй — показать невидимые символы: `cat -A data.json`. Шаг третий — извлечь отступы и собрать биты. Шаг четвёртый — проверить результат.

```bash
python3 -m json.tool data.json > /dev/null && echo valid
cat -A data.json | head -5
python3 - <<PY
bits = ""
for line in open("data.json"):
    ind = len(line) - len(line.lstrip(" "))
    if ind in (1,2): bits += "0" if ind==1 else "1"
print(bytes(int(bits[i:i+8],2) for i in range(0,len(bits)-7,8)))
PY
```

Шаг пятый — если биты не сложились в текст, попробуй другой канал: хвостовые пробелы, порядок ключей, Unicode-escape.

## Итог по JSON

JSON — удобный канал сокрытия из-за избыточности пробелов и неопределённого порядка ключей. Каналы: отступы, хвостовые пробелы, порядок ключей, дубли, форма чисел, Unicode-escape, BOM. Инструменты: `python3`, `jq`, `cat -A`, `diff` с нормализацией. Ключ — нормализовать файл и сравнить с исходным: разница покажет скрытое.

## Расширенный разбор каналов JSON

Разберём каждый канал подробно. Первый — **отступы**: число пробелов в начале строки. Схема «1 пробел = 0, 2 = 1» или «пробел = 0, таб = 1». Читаешь построчно, извлекаешь префикс, собираешь биты. Второй — **хвостовые пробелы**: в конце строки, тоже биты.

Третий — **порядок ключей**: JSON-объект по стандарту неупорядочен, но парсеры сохраняют порядок вставки. Перестановка ключей кодирует данные. Четвёртый — **дубли ключей**: `{"a":1,"a":2}` — парсеры берут последний, а первый можно использовать как канал (и как «приманку»).

Пятый — **форма записи чисел**: `1`, `1.0`, `1e0`, `0.1e1` эквивалентны, но различаются байтами. Шестой — **Unicode-escape**: `\u0041` и `A` эквивалентны; выбор формы кодирует биты. Седьмой — **порядок элементов массива**. Восьмой — **BOM** и переводы строк (LF vs CRLF).

```bash
cat -A data.json | head       # видно табы и концы строк
jq -c . data.json > norm.json
diff data.json norm.json | head
```

Извлечение — по каналу. Для отступов/хвостовых пробелов — скрипт. Для порядка ключей — сравнить с алфавитным порядком. Для Unicode — перебрать коды. Инструменты: `python3`, `jq`, `cat -A`, `xxd`, `diff`.

## Итог по JSON

JSON — удобный контейнер для сокрытия из-за избыточности (пробелы, форма записи) и неопределённого порядка ключей. Каналы: отступы, хвостовые пробелы, порядок ключей, дубли, форма чисел, Unicode-escape, BOM. Инструменты: `python3`, `jq`, `cat -A`. Ключ — нормализовать файл (`json.dumps` с `indent=0`) и сравнить с исходным: разница покажет скрытое.

## Дополнительные приёмы по JSON

Ещё несколько мест. Первое — **порядок вложенных объектов**: вложенная структура даёт больше возможностей для кодирования порядка. Второе — **ключи с разными кавычками** (невалидно, но некоторые парсеры прощают). Третье — **число пробелов внутри массивов** (`[1, 2]` vs `[1,2]`).

Четвёртое — **длина ключей** (можно подобрать ключи разной длины для кодирования). Пятое — **экранирование в строках** (`\n` vs настоящий перевод строки, `\/` vs `/`). Шестое — **порядок пар в объекте верхнего уровня** может отличаться от сортированного, что само по себе подозрительно.

Седьмое — **вложенные комментарии** (невалидны в JSON, но в JSON5/JSONC валидны). Восьмое — **дублирование структуры**: лишние пустые объекты/массивы.

Практика: нормализуй файл через `json.dumps(obj, indent=0, sort_keys=True)` и сравни с исходным побайтово (`cmp`, `diff`). Всё, что отличается, — потенциальный канал: пробелы, порядок, форма записи. Это самый быстрый способ найти канал в JSON.

## Что мы теперь знаем
- JSON игнорирует пробелы, порядок и дубли ключей — это канал.
- Один пробел/таб на строку = один бит; восемь бит = символ.
- Канал живёт в «незначащем» синтаксисе, а не в значениях.
- Нормализация через сериализатор уничтожает канал.
