## Вопрос, с которого всё начинается

Тебе дали файл `hidden.pcap` — запись сетевого трафика. Задача: найти в нём скрытое сообщение. В файле тысячи пакетов. Где искать?

Сеть — идеальный носитель для **covert channel** (скрытого канала): у протоколов есть поля, которые получатель не проверяет, и «свободные степени свободы» — порядок и время пакетов. В этом уроке мы разберём один PCAP и вытащим данные из неожиданного места.

## Наш пример: hidden.pcap

Начнём с общего обзора — что за трафик, сколько пакетов, какие протоколы.

```
$ tshark -r hidden.pcap -q -z io,stat,0
| IO Statistics |
| Interval | Frames | Bytes |
| 0.000 <> 5.000 | 200 | 24000 |
```

200 пакетов, все — IPv4. Теперь посмотрим на поля заголовка IP. Нас интересует **IP ID** — 16-битное поле, которое обычно меняется предсказуемо.

```
$ tshark -r hidden.pcap -Y ip -T fields -e ip.id | head
12341
12342
12343
...
```

`tshark -T fields -e <поле>` печатает выбранное поле по каждому пакету. Значения почти подряд — но это неважно. Ключевая идея: можно взять **младший бит** каждого IP ID и собрать из них данные.

## Шаг 1: извлекаем младшие биты IP ID

Для программируемого извлечения удобен `scapy`. Собираем младший бит (`id & 1`) каждого пакета, группируем по 8 бит в байты.

```python
from scapy.all import rdpcap, IP
bits = ''.join(str(p[IP].id & 1) for p in rdpcap('hidden.pcap') if IP in p)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))
print(data[:40])
```

```
$ python3 extract.py
b'flag{ip_id_lsb}'
```

Готово. Младшие биты IP ID несли флаг.

## Шаг 2: почему это работает

IP ID нужен для сборки фрагментированных пакетов — он связывает фрагменты одного датаграмма. Но когда фрагментации нет, поле всё равно присутствует и часто заполняется произвольно. Приёмник его не проверяет — значит, в младших битах можно передавать данные.

Аналогично устроены и другие поля-каналы:

| Уровень | Поле | Ёмкость | Заметность |
|---|---|---|---|
| IP | IP ID | 1–16 бит/пакет | низкая |
| IP | TTL | 1 бит/пакет | низкая |
| IP | ToS/DSCP | несколько бит | низкая |
| TCP | seq/ack | много бит | средняя |
| TCP | flags/options | 1–4 бита | низкая |
| любой | порядок пакетов | log2(n!) | низкая |
| любой | тайминг | 1 бит/пакет | очень низкая |

## Шаг 3: TTL и TCP-флаги

Если IP ID пуст, проверь другие поля. TTL обычно фиксирован (64/128) — его изменения кодируют данные.

```python
from scapy.all import rdpcap, IP, TCP
pkts = rdpcap('cap.pcap')
bits = ''.join('1' if p[IP].ttl % 2 else '0' for p in pkts if IP in p)
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))[:40])
```

TCP-флаги тоже подходят: например, наличие флага PSH как бит.

```python
bits = ''.join('1' if (p[TCP].flags & 0x08) else '0' for p in pkts if TCP in p)
```

## Шаг 4: тайминги — самый скрытный канал

Даже если все поля «нормальные», данные прячут в **интервалах** между пакетами. Договоримся: короткая пауза = 0, длинная = 1.

```python
pkts = [p for p in rdpcap('cap.pcap') if IP in p]
times = [float(p.time) for p in pkts]
deltas = [times[i+1] - times[i] for i in range(len(times) - 1)]
bits = ''.join('1' if d > 0.01 else '0' for d in deltas)   # порог подбирается
print(bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))[:40])
```

Порог подбирается экспериментально: посмотри распределение `deltas` и найди естественную границу между «короткой» и «длинной» паузой.

## Шаг 5: ICMP и DNS — классические туннели

**ICMP-туннель** прячет данные в payload эхо-запросов (`ping`). Признак — необычно большой или «случайный» payload и постоянные запросы к одному хосту.

```
$ tshark -r cap.pcap -Y icmp -T fields -e data | head
```

**DNS-туннель** кодирует данные в поддоменах или TXT-записях. Признак — длинные высокоэнтропийные поддомены (`aGVsbG8.tunnel.example.com`) и много запросов к одному домену.

## Частые ловушки

- **Смотреть только payload** — данные часто в заголовках.
- **Фильтровать неправильно** — если взять все пакеты подряд, в биты попадут служебные (ARP, DNS-ответы) и поток «съедет». Всегда фильтруй по протоколу/направлению.
- **Сортировка** — при слиянии файлов порядок пакетов может сбиться; сортируй по времени.
- **Не тот бит** — если младший бит даёт мусор, попробуй другой бит или поле.

## Если не сработало

- Проверь все поля: IP ID, TTL, ToS, TCP seq/flags/options, порты.
- Проверь тайминги и порядок пакетов.
- Проверь ICMP/DNS payload — классические туннели.
- Если данные «случайные» — возможно, они сжаты или зашифрованы: сними XOR или распакуй.

## Что мы теперь знаем

1. Covert channel использует поля, тайминги или неиспользуемые протоколы.
2. Младшие биты IP ID / TTL — частый канал в PCAP-задачах.
3. Тайминги — самый скрытный, но требует синхронного приёмника.
4. ICMP и DNS — классические туннели.
5. `tshark -T fields` для быстрого просмотра, `scapy` — для извлечения.

## Шаг 6: практические тонкости извлечения

Три вещи чаще всего ломают извлечение из PCAP. Первое — **фильтрация**: если взять все пакеты подряд, в биты попадут служебные (ARP, DNS-ответы), и поток «съедет». Всегда фильтруй по нужному протоколу/направлению. Второе — **порядок**: сортируй пакеты по времени, при слиянии файлов порядок может сбиться. Третье — **выбор бита/поля**: если младший бит одного поля даёт мусор, попробуй другой бит, другое поле или комбинацию.

```
$ tshark -r hidden.pcap -Y 'ip.src==10.0.0.5 && tcp' -T fields -e ip.id > ids.txt
$ python3 -c "
bits=''.join(str(int(x)&1) for x in open('ids.txt'))
print(bytes(int(bits[i:i+8],2) for i in range(0,len(bits)-7,8)))
"
```

## Шаг 7: детект сетевых covert-каналов

Для blue team полезны признаки:

- необычные значения IP ID/TTL в потоке;
- тайминги с «ступеньками» (бимодальное распределение интервалов);
- ICMP с большим или энтропийным payload;
- DNS с длинными поддоменами (туннель);
- постоянные потоки к одному хосту с «пустым» payload.

```
$ tshark -r cap.pcap -Y ip -T fields -e ip.id | sort | uniq -c | sort -rn | head
```

## Шаг 8: инструменты сетевой стеганографии

- **`tshark`/`wireshark`** — выборки по полям и статистика;
- **`scapy`** — программируемое извлечение (порядок, тайминги, младшие биты);
- **`ptunnel`/`icmptunnel`** — ICMP-туннели (для понимания трафика);
- **`iodine`/`dnscat2`/`dns2tcp`** — DNS-туннели;
- **NetworkMiner** — быстрый обзор трафика.

## Куда дальше

Дальше — **продвинутые техники**: частотная стеганография (DCT/DWT), spread-spectrum и структурные каналы, где данных не видно ни в пикселях, ни в полях. А пока запомни: в PCAP сначала смотри поля заголовков (`tshark -T fields`), потом тайминги и туннели.

## Где пригодится

- **Network forensics / SOC:** детект эксфильтрации данных.
- **Red team:** туннелирование (DNS/ICMP) для обхода фильтров.
- **CTF:** PCAP-задачи — постоянная рубрика.
- **Blue team:** понимание, где искать аномалии в трафике.
