Ты уже разобрал kubelet, network policy, CSI и operator в `cloud-k8s-deep`, RBAC и pod security — в соседних модулях. Этот подмодуль закрывает слои, которые ставят поверх кластера: Helm (пакетный менеджер), API server (ядро управления), Gateway API (новый роутинг) и Kustomize (шаблонизация без шаблонов). Каждый из них либо хранит секреты, либо определяет, кто и куда может ходить, — и каждый даёт свои мисконфиги.

## Что покрывает подмодуль

1. **Helm** (`cloud-k8s-helm`) — чарты, templates, values, secrets и история релизов, hooks и plugins.
2. **API server** (`cloud-k8s-apiserver`) — authn/authz, анонимный доступ, aggregation, impersonation и abuse.
3. **Gateway API** (`cloud-k8s-gateway-api`) — Gateway/HTTPRoute, path-матчинг, backend и SSRF.
4. **Kustomize** (`cloud-k8s-kustomize`) — overlays, patches, генераторы секретов и удалённые базы.

## Почему такой порядок

Идём от «как разворачивается» к «как управляется» и «как маршрутизируется». Helm и Kustomize описывают, что попадёт в кластер (и какие секреты). API server — точка, через которую всё управляется. Gateway API — точка, через которую всё приходит снаружи. Секреты и маршрутизация — две главные цели: первая даёт доступ, вторая — путь внутрь.

## Как проходить подмодуль

Один вопрос на все слои: «что здесь хранится в открытом виде и кто это может прочитать?». Helm хранит релизы и значения (в том числе секреты), Kustomize — сгенерированные секреты, API server — все объекты и токены, Gateway API — маршруты к бэкендам. Поняв, что лежит в открытом виде и кому доступно, ты находишь и данные, и путь в кластер.

## Куда дальше

Дальше — Helm: пакетный менеджер, в истории которого лежат секреты. А пока главное: платформенные слои хранят секреты и определяют маршруты, и оба открывают кластер.
