Этот подмодуль — часть ветки «Провайдеры глубоко». Большая тройка (AWS, Azure, GCP) разобрана в соседних модулях. Здесь — провайдеры второго эшелона, которых всё чаще встречают в реальных компаниях и CTF. Модель атаки та же: найти креденшел → прочитать права → эскалировать. Меняются названия сущностей и API, а не логика.

## Что покрывает подмодуль

1. **Oracle Cloud (OCI): tenancy, compartments, IAM и instance principals** (`cloud-oci-basics`) — как читать OCI-политики и захватывать ресурсы по утёкшему API-ключу.
2. **Alibaba Cloud (Aliyun): RAM, STS и confused deputy** (`cloud-aliyun-basics`) — RAM-политики, OSS-бакеты и метаданные ECS.
3. **IBM Cloud: IAM, API keys и service IDs** (`cloud-ibm-cloud`) — ключи, доверие и COS-бакеты.
4. **DigitalOcean / Linode / Vultr: API-токены, дроплеты и снапшоты** (`cloud-do-linode`) — простые API, которые легко забыть закрыть.

## Почему такой порядок

Начинаем с OCI — там самая непривычная модель прав (verb + resource-type + compartment), и её понимание переносится на остальных. Дальше Alibaba (близка к AWS по духу), затем IBM (мало материалов, но много корпоративных сред) и, наконец, простые хостинг-провайдеры, где вся защита — один API-токен.

## Как проходить подмодуль

Идите по списку. После каждого урока закрепляйте идею: какой креденшел даёт доступ, какие права он несёт и какой ресурс за ним стоит. Держите в голове одну таблицу соответствий: tenancy≈аккаунт, compartment≈проект, RAM-user≈IAM-user, API-token≈долгоживущий ключ.

## Куда дальше

В следующих уроках мы возьмём каждый провайдер по отдельности и прогоним полный путь: утёкший ключ → перечисление прав → захват ресурса. А пока запомни главное: у каждого облака своя терминология, но одна логика прав.

## Где пригодится

- Пентест компаний, которые используют не только AWS/Azure/GCP.
- Разбор утечек API-ключей из репозиториев и CI.
- CTF-задачи категории cloud.
