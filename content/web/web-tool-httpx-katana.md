## Задача

У тебя есть список целей — поддомены, IP, URL. Нужно быстро понять две вещи: **что из этого живо и с чем мы говорим** (сервер, технологии) и **какие внутри эндпоинты** (пути, параметры). Первое решает **httpx**, второе — **katana**. Вместе они составляют основу разведки.

Пройдём по одному списку целей.

## Данные, с которыми работаем

Есть список поддоменов `subs.txt`:

```text
shop.example
api.example
old.example
```

## Шаг 1: httpx — проба хостов

httpx берёт список и для каждой цели печатает «паспорт». Ключевые флаги: `-title` (заголовок страницы), `-tech-detect` (технологии), `-status-code` (код ответа), `-silent` (только результат).

```bash
$ httpx -l subs.txt -title -tech-detect -status-code -silent
https://shop.example [200] [Example Shop] [nginx,PHP,Laravel]
https://api.example [401] [] [nginx,Express,Node.js]
https://old.example [301] [] [Apache]
```

Из вывода видно: `shop.example` — PHP/Laravel, `api.example` требует авторизации (`401`), `old.example` редиректит (`301`) на Apache. Заметь: httpx сам достроил `https://` и определил технологии.

## Шаг 2: httpx — фильтры и вывод

Часто целей много и нужен только определённый срез. Флаги матчинга/фильтрации отсеивают лишнее:

| Флаг | Что делает |
|------|-----------|
| `-mc 200,301` | оставить только эти коды |
| `-fc 404` | исключить эти коды |
| `-ms 'Shop'` | оставить по строке в ответе |
| `-fs 'Not Found'` | исключить по строке |
| `-ports 80,443,8080` | проверить порты |
| `-path /admin,/api` | добавить пути к каждой цели |
| `-json` | вывод в JSON (для пайплайна) |
| `-o out.txt` | сохранить результат |

Пример: оставить только живые с редиректом и сохранить в JSON:

```bash
$ httpx -l subs.txt -mc 200,301,302 -json -o httpx.json
```

## Шаг 3: katana — краулинг

**katana** — это «паук»: он обходит приложение по ссылкам и собирает URL с параметрами. Запускается по живому хосту, найденному httpx.

```bash
$ katana -u https://shop.example -d 3 -silent
https://shop.example/
https://shop.example/product?id=1
https://shop.example/api/user?id=1
https://shop.example/login
https://shop.example/static/app.js
```

Флаг `-d 3` задаёт **глубину** обхода (на сколько ссылок уходить от стартовой страницы). `-silent` — только URL.

## Шаг 4: katana — JS и формы

Много эндпоинтов спрятано в JavaScript. Флаг `-jc` включает разбор JS-файлов на предмет URL:

```bash
$ katana -u https://shop.example -jc -silent | grep -E '/api/'
https://shop.example/api/user?id=1
https://shop.example/api/admin/export
```

Флаг `-fx` включает заполнение форм (form extraction), а `-kf all` — проверку известных файлов (`robots.txt`, `sitemap.xml`). Полезно и ограничение области: `-fs rdn` (same-domain).

| Флаг katana | Что делает |
|-------------|-----------|
| `-u` / `-list` | одна цель / список |
| `-d N` | глубина обхода |
| `-jc` | парсить JavaScript на URL |
| `-fx` | разбирать формы |
| `-kf all` | известные файлы (robots, sitemap) |
| `-fs rdn` | только тот же домен |
| `-json` / `-o` | JSON / сохранить |
| `-c N` / `-p N` | параллелизм |

## Шаг 5: httpx на большом списке — скорость и устойчивость

Когда целей тысячи, важна не только корректность, но и управляемая нагрузка. Полезные флаги:

| Флаг | Что делает |
|------|-----------|
| `-rl N` | лимит запросов в секунду |
| `-retries N` | повторы при сетевой ошибке |
| `-timeout N` | таймаут на запрос |
| `-threads N` | число воркеров |
| `-x http://proxy:8080` | через прокси (Burp/ZAP) |
| `-nc` | без цвета (для логов) |

```bash
$ httpx -l subs.txt -rl 100 -retries 2 -timeout 10 -threads 50 -silent -o live.txt
```

`-rl` здесь — защита цели от перегрузки, а `-x` пропускает весь трафик через перехватчик: удобно,
когда хочешь видеть запросы в Burp и править их на лету.

## Шаг 6: katana — headless и точные фильтры

Обычный katana разбирает HTML/JS статически. Для SPA, где ссылки строятся в рантайме, нужен
**headless-режим** — katana запускает настоящий браузер:

```bash
$ katana -u https://shop.target.local -hl -jc -d 3 -silent
https://shop.target.local/#/dashboard
https://shop.target.local/api/v2/orders
```

`-hl` (headless) исполняет JS в браузере, поэтому находит маршруты, которых нет в исходном HTML.
Ограничивай область и типы файлов:

| Флаг | Что делает |
|------|-----------|
| `-hl` | headless-браузер (JS в рантайме) |
| `-jsluice` | извлекать пути/секреты из JS |
| `-ef css,png,jpg` | исключить расширения |
| `-fqdn` | только этот домен и поддомены |
| `-timeout N` | таймаут на страницу |

`-ef css,png,jpg` убирает из вывода статику — остаются только значимые эндпоинты. Без `-fqdn`
краулер может уйти на внешние ресурсы (CDN, аналитику), что раздувает вывод и создаёт лишний шум.

## Пайплайн: httpx → katana → ffuf/nuclei

Инструменты соединяются через `|`: httpx даёт живые URL, katana — эндпоинты, дальше ffuf/nuclei работают по ним.

```bash
$ cat subs.txt | httpx -silent -mc 200 | katana -d 3 -silent | tee urls.txt
$ cat urls.txt | grep '?' | ffuf -w params.txt:FUZZ -u 'https://shop.example/product?id=FUZZ' -mc all
$ cat urls.txt | nuclei -severity high,critical -silent
```

## Полный прогон от начала до конца

1. `httpx -l subs.txt -title -tech-detect` → три живых хоста, стек.
2. `httpx -mc 200,301 -json -o httpx.json` → отфильтрованный список.
3. `katana -u https://shop.example -d 3` → эндпоинты с параметрами.
4. `katana -u ... -jc` → API-пути из JavaScript.
5. Найденные URL с `?` → в ffuf/nuclei/sqlmap.

## Частые ошибки

- **katana без ограничения области.** Без `-fs` он уйдёт на внешние домены.
- **Слишком большая глубина.** `-d 10` даёт горы мусора; начинай с 2–3.
- **Забыть `-silent`/`-json` в пайплайне.** Иначе вывод с баннером неудобно парсить.
- **Игнорировать JS.** Часть эндпоинтов видна только через `-jc`.
- **Путать httpx от ProjectDiscovery с python-httpx.** Это разные инструменты.
- **Шум.** Краулинг и пробы видны в логах; ограничивай `-c/-p`.

## На что смотреть дальше

- **httpx отвечает «что живо», katana — «что внутри».**
- **`-json` — мост между инструментами.** Пайплайн строится на машинном выводе.
- **JS-краулинг обязателен.** Современные SPA прячут API в бандлах.
- **Ограничивай scope.** `-fs rdn` и глубина защищают от расползания.
- **Параметры — цель.** URL с `?` отдавай фаззерам и сканерам.
- **Соблюдай правила.** Активный краулинг — нагрузка на цель; согласуй лимиты.

## Как это видят защитники

httpx и katana — «вежливые» инструменты, но их отпечатки заметны. На стороне защиты:

- **User-Agent** по умолчанию содержит подпись ProjectDiscovery; в логах это сразу выдаёт скан.
- **Много запросов с одного IP** за короткое время — пробинг списка.
- **Headless-краулинг** оставляет характерные заголовки браузера без обычных ресурсов (картинок,
  шрифтов) — нечеловеческий паттерн загрузки.
- **Параметризованные URL** в большом количестве — краулер собрал все ссылки.

Практика: ставь реальный `User-Agent` (через `-H`), ограничивай `-rl`, а headless используй точечно —
на конкретных хостах, а не на всём списке.

## Если не сработало

- **httpx не находит живых хостов** — возможно, порты нестандартные: добавь `-ports 80,443,8080,8443`.
- **katana возвращает пусто** — сайт целиком на JS; включи `-hl` (headless).
- **katana уходит на чужие домены** — добавь `-fqdn`, чтобы ограничить область.
- **Слишком много мусора в выводе** — исключи статику (`-ef`) и работай с `-json`, чтобы фильтровать
  программно.
- **Путаница с python-httpx** — это разные инструменты: CLI-`httpx` из ProjectDiscovery, а
  python-библиотека `httpx` используется в скриптах.

## Шпаргалка: флаги httpx

| Флаг | Что делает |
|------|-----------|
| `-l` / `-u` | список / одна цель |
| `-sc` | код ответа |
| `-title` / `-td` | title / технологии |
| `-cl` | длина контента |
| `-mc` / `-fc` | матчить / исключить коды |
| `-ms` / `-fs` | матчить / исключить строку |
| `-path` / `-ports` | добавить путь / проверить порты |
| `-json` | вывод в JSON |
| `-x` | прокси |
| `-rl` | лимит скорости |

## Что мы теперь знаем

- `httpx` отвечает на вопрос «что живо и с чем говорим», `katana` — «что внутри».
- Связка строится через `-silent`/`-json`: машинный вывод питает следующие инструменты.
- Для SPA обязателен `-jc`, а часто и `-hl`; без ограничения области краулер расползается.
- Флаги `-rl`/`-retries`/`-timeout` делают прогон устойчивым и вежливым к цели.
- Найденные URL с `?` — вход для фаззеров и сканеров, а headless-режим находит маршруты, которых
  нет в статическом HTML.

## Куда дальше

Следующий урок (`web-tool-nuclei`) разберёт шаблонный сканер, который превращает найденные URL в конкретные находки CVE и мисконфигов. А пока главное запомни: `httpx` даёт карту хостов, `katana` — карту эндпоинтов, а связка через `-silent`/`-json` питает фаззеры и сканеры.

## Где пригодится

- **CTF (Web):** быстрая карта цели и сбор эндпоинтов.
- **Bug bounty:** автоматизация разведки по сотням поддоменов.
- **Пентест:** построение поверхности атаки перед тестами.
- **Работа (AppSec):** инвентаризация собственных сервисов и их стека.
