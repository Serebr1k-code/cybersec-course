## Задача

В прошлом уроке мы собрали карту цели и получили живой хост `https://shop.acme-lab.test`. Паук нашёл только те ссылки, на которые есть `<a href>` или `fetch()` в JS. А что, если на сервере лежит `/backup.zip`, `/admin` или скрытый API `/api/users.json`, на который ничто не ссылается?

Такие вещи ищут **фаззингом** — систематическим перебором. Это не «угадывание», а инженерный перебор: подаём словарь имён, инструмент шлёт тысячи запросов и оставляет только отклонения от обычного ответа.

## Данные, с которыми работаем

Одна цель — `https://shop.acme-lab.test`. Один словарь — `seclists/Discovery/Web-Content/raft-medium-directories.txt` (около 30 000 имён путей).

## Пробуем в лоб

Запускаем перебор «в лоб» — большой словарь по корню:

```bash
$ ffuf -u https://shop.acme-lab.test/FUZZ -w raft-medium-directories.txt -t 40
...
/index.php              [Status: 200, Size: 5211, Words: 120, Lines: 88]
/about                  [Status: 200, Size: 5211, Words: 120, Lines: 88]
/zxcvbnm                [Status: 200, Size: 5211, Words: 120, Lines: 88]
/backup                 [Status: 200, Size: 5211, Words: 120, Lines: 88]
```

Видишь проблему? **Всё отдаёт `200` и одинаковый размер `5211`.** Это **soft-404**: приложение-одностраничник на любой несуществующий путь возвращает одну и ту же страницу-заглушку. Формально код 200, но находки здесь нет. Если бы мы просто отфильтровали `404`, мы бы утонули в ложных срабатываниях.

## Приём: калибровка против soft-404

Лечится это **фильтрацией по отпечатку ответа**. Сначала один запрос на заведомо случайный путь — узнаём «отпечаток» заглушки:

```bash
$ curl -s -o /dev/null -w '%{http_code} %{size_download}\n' https://shop.acme-lab.test/random123
200 5211
```

Теперь мы знаем: размер `5211` = «ничего не найдено». Значит, надо оставить всё, что **не** `5211`. У ffuf за это отвечает флаг `-fs` (filter-size), а `-ac` включает **авто-калибровку** — ffuf сам шлёт случайные пути и вычисляет фильтр:

```bash
$ ffuf -u https://shop.acme-lab.test/FUZZ -w raft-medium-directories.txt \
       -ac -mc all -t 40 -s
/admin                  [Status: 301, Size: 178, Words: 6, Lines: 8]
/api                    [Status: 200, Size: 1024, Words: 40, Lines: 12]
/backup                 [Status: 403, Size: 512, Words: 30, Lines: 9]
```

Три реальных отклонения. `-mc all` означает «принимать любые коды», а фильтр `-ac` уже отсеял шум. `301` у `/admin` — редирект (значит, каталог существует), `403` у `/backup` — доступ запрещён (каталог есть, но закрыт).

> **Термин.** `-mc` — *match codes*: какие коды считать попаданием. `-fc` — *filter codes*: какие исключить. `-fs` — *filter size*: исключить ответы заданного размера.

## Шаг: расширения и файлы

Пути нашли — теперь ищем **файлы** с опасными расширениями. Флаг `-e` добавляет расширения к каждому слову словаря:

```bash
$ ffuf -u https://shop.acme-lab.test/api/FUZZ -w raft-medium-files.txt \
       -e .json,.bak,.old -mc 200 -fs 0 -s
/users.json             [Status: 200, Size: 2048, Words: 60, Lines: 40]
/config.bak             [Status: 200, Size: 512, Words: 12, Lines: 10]
```

`/api/users.json` — прямая утечка списка пользователей. `/api/config.bak` — резервная копия конфига, часто с паролями БД. Оба — «низковисящие фрукты».

## Шаг: параметры и значения

Теперь перебираем **параметры** у найденного эндпоинта. Меняем позицию: `FUZZ` стоит в имени параметра.

```bash
$ ffuf -u 'https://shop.acme-lab.test/api/users?FUZZ=1' \
       -w burp-parameter-names.txt -fs 0 -mc all -s
/debug                  [Status: 200, Size: 4096, Words: 80, Lines: 50]
```

Появился скрытый `debug=1` — размер ответа вырос вдвое (включилась отладка). Последний шаг — перебор **значений** `id` диапазоном (ffuf умеет читать словарь из процесса):

```bash
$ ffuf -u 'https://shop.acme-lab.test/api/users?id=FUZZ' -w <(seq 1 500) -mc 200 -fs 0 -s
42                      [Status: 200, Size: 8192, Words: 120, Lines: 60]
```

Объект `id=42` отдаёт целых 8192 байта — возможно, чужой профиль. Это уже кандидат на IDOR: проверим, сменив `id` под другой сессией.

## Полный прогон от начала до конца

1. `curl .../random123` → отпечаток soft-404 (`200 5211`).
2. `ffuf ... -ac -mc all` → реальные пути (`/admin`, `/api`, `/backup`).
3. `ffuf ... -e .json,.bak` → файлы (`/api/users.json`, `/api/config.bak`).
4. `ffuf ...?FUZZ=1` → скрытый параметр (`debug`).
5. `ffuf ...?id=FUZZ` → объект `id=42`.

Каждого кандидата — в руки: `curl`/Burp, проверить IDOR, утечку, обход `403`.

## Если не сработало

- **Сервер тормозит или банит.** Снизь потоки: `-t 20` и добавь лимит `-rate 50`, паузу `-p 0.1`.
- **Большой словарь не успевает.** Ограничь время: `-maxtime 300` (ffuf) или `--time-limit 5m` (feroxbuster) — ниже таймаута твоей shell, иначе JSON не сохранится.
- **Нужен рекурсивный обход.** `gobuster` не углубляется сам — бери `feroxbuster` (`-d 3`).
- **Сложные комбинации payload.** У `wfuzz` богаче движок: `-z file,users.txt -z file,pass.txt --hc 404` для логина, `-z file,list,base64` для кодирования payload.
- **Нужны виртуальные хосты.** Подставляй не в путь, а в заголовок: `ffuf -H 'Host: FUZZ.acme-lab.test' -w subs.txt`.

## Сравнение инструментов

| Инструмент | Сильная сторона | Типичный запуск |
|------------|-----------------|-----------------|
| **ffuf** | скорость, фильтры, JSON, vhost | `ffuf -u https://t/FUZZ -w list -ac` |
| **gobuster** | надёжные режимы dir/dns/vhost | `gobuster dir -u https://t -w list -x php` |
| **feroxbuster** | рекурсия, авто-фильтр, extract-links | `feroxbuster -u https://t -w list -d 3` |
| **wfuzz** | payload/encoders/iterators | `wfuzz -z file,list --hc 404 https://t/?p=FUZZ` |

## Что мы теперь знаем

- Фаззинг = **позиция** (где подставляем) + **словарь** (чем).
- На SPA первым делом снимай **отпечаток soft-404** и фильтруй по размеру (`-fs`) или авто-калибровкой (`-ac`).
- `-mc` — что считать находкой, `-fc` — что исключить.
- Расширения задаются `-e`, скрытые параметры ищут подстановкой в имя параметра.
- Автоматический `200` — не баг; решение принимаешь ты после ручной проверки.

## На что смотреть дальше

- **Учёт словарей.** Не гоняй один и тот же список по одному `host:port` дважды — веди запись, что уже применено.
- **Разные словари под разное.** Пути, параметры, значения, поддомены — отдельные списки, не смешивай.
- **«Мягкий 403».** Иногда `403` обходится регистром, `/.`/`//` или заголовком `X-Original-URL`.
- **Внутри авторизации.** С cookie поверхность другая — передавай `-b` или `-H 'Cookie: ...'`.
- **Не забывай про API.** `/api/v2/`, `/graphql`, `/swagger.json` часто живут отдельно от HTML.

## Куда дальше

Дальше (`web-tool-ffuf`) мы разберём `ffuf` детально: все матчеры и фильтры, режимы, JSON-вывод и связку с `jq`. А пока главное запомни: прежде чем верить перебору, сними отпечаток soft-404 — иначе найдёшь сотни «находок», которых нет.

## Где пригодится

- **CTF (Web):** быстрый поиск скрытых путей/параметров, флаг часто лежит в `/backup` или скрытом API.
- **Bug bounty:** массовое обнаружение контента и параметров — основа расширения поверхности атаки.
- **Пентест:** стандартный этап content discovery; доказательства (коды, размеры) идут в отчёт.
- **Работа (AppSec/DevSecOps):** регулярный перебор в CI, поиск забытых бэкапов и админок после релизов.
