## Задача

Мы уже нашли на `https://shop.acme-lab.test` каталог `/api`. Паук не показал, какие эндпоинты внутри — ссылок на них нет. Нужно перебрать имена и вытащить те, что реально существуют, не утонув в ложных срабатываниях.

Инструмент по умолчанию для такой задачи — **ffuf** (Fuzz Faster U Fool). Он подставляет значение словаря в любое место запроса (URL, заголовок, cookie, тело) и оставляет только «отклонения» от нормы. Разберём его на этой задаче, а таблицу всех флагов дадим в конце.

## Данные, с которыми работаем

Цель `https://shop.acme-lab.test/api/`, словарь `api-endpoints.txt`. Ключевое слово подстановки по умолчанию — `FUZZ`: ffuf заменит его на строку из словаря.

## Пробуем в лоб

```bash
$ ffuf -u https://shop.acme-lab.test/api/FUZZ -w api-endpoints.txt
...
users        [Status: 200, Size: 2048, Words: 60, Lines: 40]
products     [Status: 200, Size: 5120, Words: 140, Lines: 90]
zzz          [Status: 200, Size: 2048, Words: 60, Lines: 40]
nothere      [Status: 200, Size: 2048, Words: 60, Lines: 40]
```

`users` и `products` — настоящие эндпоинты. А `zzz` и `nothere` — нет, но они тоже дали `200` и **тот же размер `2048`**. Это классическая ловушка: API на любой неизвестный путь отдаёт одну заглушку. Формально `200`, находки нет.

## Приём 1: матчеры и фильтры

Сердце ffuf — два набора флагов:

- **Матчеры** (`-m*`) говорят, **что считать попаданием**: `-mc` — коды, `-ms` — размер, `-ml`/`-mw` — строки/слова, `-mr` — regexp по телу.
- **Фильтры** (`-f*`) говорят, **что выбросить**: `-fc` — коды, `-fs` — размер, `-fl`/`-fw`, `-fr` — regexp.

По умолчанию ffuf считает попаданием коды `200-299,301,302,307,401,403,405,500` и фильтрует `404`. У нас заглушка отдаёт `200 2048` — значит, её надо отфильтровать по размеру:

```bash
$ ffuf -u https://shop.acme-lab.test/api/FUZZ -w api-endpoints.txt -fs 2048 -s
users        [Status: 200, Size: 3072, Words: 90, Lines: 55]
products     [Status: 200, Size: 5120, Words: 140, Lines: 90]
admin        [Status: 403, Size: 178, Words: 6, Lines: 8]
```

Чисто: три настоящие находки, весь мусор размером `2048` отфильтрован. Но ручной размер хрупок: у другой цели заглушка будет другого размера, а иногда она ещё и меняется от запроса к запросу.

## Приём 2: авто-калибровка `-ac`

Надёжнее включить **авто-калибровку**: ffuf сам шлёт случайные пути, вычисляет отпечаток «не найдено» и фильтрует по нему. Флаг `-ac` делает это автоматически, `-mc all` разрешает принимать любые коды.

```bash
$ ffuf -u https://shop.acme-lab.test/api/FUZZ -w api-endpoints.txt -ac -mc all -s
users        [Status: 200, Size: 3072, Words: 90, Lines: 55]
products     [Status: 200, Size: 5120, Words: 140, Lines: 90]
admin        [Status: 403, Size: 178, Words: 6, Lines: 8]
```

Тот же результат без ручного измерения размера. Авто-калибровка — то, что стоит включать почти всегда на живом приложении.

## Приём 3: расширения и рекурсия

Флаг `-e` добавляет расширения к каждому слову словаря (ffuf делает из `config` ещё и `config.php`, `config.bak`):

```bash
$ ffuf -u https://shop.acme-lab.test/api/FUZZ -w api-endpoints.txt -e .json,.bak -ac -mc all -s
users.json   [Status: 200, Size: 4096, Words: 120, Lines: 60]
config.bak   [Status: 200, Size: 512, Words: 12, Lines: 10]
```

`/api/users.json` — утечка списка, `/api/config.bak` — резервная копия конфига. Рекурсивный обход включается `-recursion` (URL обязан кончаться на `FUZZ`), глубина — `-recursion-depth`.

## Приём 4: vhost, параметры, значения

ffuf подставляет `FUZZ` не только в путь. **Виртуальные хосты** — в заголовок `Host`:

```bash
$ ffuf -u https://shop.acme-lab.test/ -H 'Host: FUZZ.acme-lab.test' -w subdomains.txt -fs 5211 -s
staging      [Status: 200, Size: 3120, Words: 80, Lines: 50]
```

(Размер `5211` — отпечаток дефолтного сайта, его снимаем заранее через `curl`.)

**Имена параметров** — подстановкой в имя:

```bash
$ ffuf -u 'https://shop.acme-lab.test/api/users?FUZZ=1' -w burp-parameter-names.txt -fs 2048 -mc all -s
debug        [Status: 200, Size: 4096, Words: 80, Lines: 50]
```

**Значения** — из процесса (`<(seq 1 500)`):

```bash
$ ffuf -u 'https://shop.acme-lab.test/api/users?id=FUZZ' -w <(seq 1 500) -mc all -fs 2048 -s
42           [Status: 200, Size: 8192, Words: 120, Lines: 60]
```

**Логин** — подстановка в тело POST, с фильтром по размеру страницы ошибки:

```bash
$ ffuf -u https://shop.acme-lab.test/login -X POST \
       -d 'username=admin&password=FUZZ' -w top100.txt -fs 812 -s
admin        [Status: 302, Size: 0, Words: 1, Lines: 1]
```

## Полный прогон от начала до конца

1. `curl .../random` → снять отпечаток заглушки.
2. `ffuf -u .../api/FUZZ -ac -mc all` → реальные эндпоинты (`users`, `products`, `admin`).
3. `ffuf ... -e .json,.bak` → файлы (`users.json`, `config.bak`).
4. `ffuf -H 'Host: FUZZ...'` → vhost (`staging`).
5. `ffuf '...?FUZZ=1'` → скрытый параметр (`debug`).
6. `ffuf '...?id=FUZZ' -w <(seq 1 500)` → объект `id=42`.

Каждого кандидата — в руки: проверить IDOR, утечку, обход `403`.

## Если не сработало

- **Слишком много ложных.** Всегда снимай отпечаток дефолтного ответа и используй `-ac` или `-fs`.
- **Сервер банит.** Снизь потоки: `-t 20`, добавь `-rate 50` и паузу `-p 0.1`.
- **Скан убит таймаутом.** Ограничь `-maxtime 300` (ниже таймаута shell) или запусти в фоне.
- **Нужны cookie/сложные заголовки.** Сохрани запрос из Burp и подай его: `ffuf -request request.txt -request-proto https -w values.txt`.
- **Нужно закодировать payload.** `-enc FUZZ:urlencode` или `-enc FUZZ:b64encode`.

## Шпаргалка: флаги ffuf

| Флаг | Что делает |
|------|-----------|
| `-u URL` | цель (обязательно содержит `FUZZ`) |
| `-w PATH[:KEY]` | словарь (можно несколько, со своими ключами) |
| `-e .php,.bak` | расширения к `FUZZ` |
| `-X` / `-d` / `-b` / `-H` | метод / тело / cookie / заголовок |
| `-mc`/`-ms`/`-ml`/`-mw`/`-mr` | матчеры: коды/размер/строки/слова/regexp |
| `-fc`/`-fs`/`-fl`/`-fw`/`-fr` | фильтры (те же оси) |
| `-ac` / `-acc` | авто-калибровка против wildcard |
| `-t` / `-rate` / `-p` | потоки / запросов в сек / пауза |
| `-recursion` / `-recursion-depth` | рекурсивный обход |
| `-request FILE` / `-request-proto` | сырой запрос из Burp |
| `-mode` | `clusterbomb` / `pitchfork` / `sniper` для нескольких словарей |
| `-o FILE` / `-of json` / `-json` | вывод в файл / формат / NDJSON в stdout |
| `-maxtime` | общий лимит времени, сек |

Выбор инструмента: пути с тонкими фильтрами и автоматизация — **ffuf**; глубокая рекурсия — **feroxbuster**; DNS — **gobuster dns**; хитрые payload/encoders — **wfuzz**; GUI и payload processing — **Burp Intruder**.

## Что мы теперь знаем

- `FUZZ` — маркер подстановки; ffuf заменяет его в URL, заголовках, cookie, теле.
- Матчеры задают «что считать находкой», фильтры — «что выбросить».
- На живом приложении почти всегда нужен `-ac` (авто-калибровка).
- Один инструмент закрывает пути, vhost, параметры, значения и логины — меняется только позиция `FUZZ`.
- JSON-вывод (`-of json`, `-json`) связывает ffuf с `jq` и пайплайном.

## На что смотреть дальше

- **Сначала отпечаток, потом перебор.** Один `curl` на случайный путь экономит часы разбора мусора.
- **Малый словарь на логины.** Онлайн-брутфорс — это EV-минус: дефолты и 100 самых частых, не `rockyou`.
- **`403` не значит «закрыто».** Проверь обход регистром, `/.`, `//`, заголовком `X-Original-URL`.
- **IDOR-разведка через `-w <(seq ...)`.** Соседние ID часто отдают чужие объекты.
- **Учёт словарей.** Не гоняй один список по одному `host:port` дважды.

## Несколько словарей и режимы `-mode`

Одна из самых недооценённых возможностей ffuf — работа **несколькими словарями одновременно**. Каждому словарю даётся свой ключ, а `-mode` определяет, как они комбинируются:

```bash
$ ffuf -u 'https://shop.acme-lab.test/api/FUZZ1?id=FUZZ2' \
       -w endpoints.txt:FUZZ1 -w <(seq 1 200):FUZZ2 \
       -mode clusterbomb -mc all -fs 2048 -s
```

Режимы повторяют логику Burp Intruder:

- **`clusterbomb`** (по умолчанию) — декартово произведение: каждый `FUZZ1` с каждым `FUZZ2`. Годится, когда надо перебрать все комбинации (пользователь × пароль).
- **`pitchfork`** — идёт по словарям параллельно, строка к строке: слово N из первого со словом N из второго. Нужен, когда пары уже согласованы (логины и их пароли в двух файлах).
- **`sniper`** — по одному ключу за раз, остальные остаются «как есть». Классический режим для одного payload-места.

Практический пример: перебор пары `username`/`password` без комбинаторного взрыва — `pitchfork` по двум файлам одинаковой длины; перебор всех сочетаний — `clusterbomb`, но помни, что объём растёт как произведение размеров словарей.

## Читаем вывод: JSON и `jq`

Для отчёта и пайплайна удобнее машинный вывод. Флаг `-of json -o out.json` пишет результаты в файл, а `-json` печатает NDJSON (по объекту на строку) прямо в stdout. С `jq` это превращается в фильтр находок:

```bash
$ ffuf -u https://shop.acme-lab.test/api/FUZZ -w api-endpoints.txt -ac -mc all -of json -o out.json -s
$ jq -r '.results[] | "\(.status) \(.length) \(.url)"' out.json | sort -n
200 3072 https://shop.acme-lab.test/api/users
200 5120 https://shop.acme-lab.test/api/products
403 178  https://shop.acme-lab.test/api/admin
```

Так ты отделяешь находки от шума скриптом и складываешь их в общий отчёт. Поле `input` содержит слово словаря, `position` — номер, `duration` — время ответа (по нему удобно искать тайминговые аномалии).

## Тайминговый фильтр `-ft` и медленные эндпоинты

Иногда эндпоинт отличается не размером и не кодом, а **временем ответа**: валидный объект идёт в БД и отвечает на 200 мс дольше, чем мгновенная заглушка. Флаг `-ft` (filter time) отбрасывает ответы быстрее порога, `-mt` (matcher time) — оставляет медленнее. Это спасает в blind-сценариях, где статус и размер одинаковы, а различие только в задержке. Сочетай с `-ac`, чтобы не ловить тайминговый шум от сети.

## Ограничения и подводные камни

- **Soft-404 не всегда стабилен.** Заглушка может отдавать слегка разный размер при каждом запросе (например, случайный токен в HTML). Тогда `-fs` по конкретному числу не работает — нужен `-fr` (regexp) или `-ac`.
- **Авто-калибровка не всесильна.** `-ac` снимает отпечаток один раз; если сервер отдаёт заглушку с редиректом на уникальный URL, фильтр промахнётся — добавь `-acc` (калибровка на каждый ответ) или ручной `-fr`.
- **Rate limit и WAF.** Высокий `-t` упирается в лимиты и ловит бан. Держи `-t 20`–`40`, ставь `-rate` и паузу `-p`, следи за долей `403`/`429` в выводе.
- **Рекурсия дорога.** `-recursion` на большом словаре даёт лавину запросов; ограничивай `-recursion-depth` и словарь для рекурсии через `-recursion-strategy`/`-w` с фильтром.
- **ffuf не разбирает JS.** Он не найдёт эндпоинты, «зашитые» в бандл: их сначала надо вытащить из JS (линковка, `grep` по исходникам), а потом уже фаззить по готовому списку.

## Куда дальше

Дальше (`web-tool-gobuster-feroxbuster`) мы разберём рекурсивный обход дерева каталогов и DNS-перебор. А пока главное запомни: `ffuf` — это «один инструмент, много позиций», и почти всегда его надо запускать с `-ac`, иначе найдёшь сотни несуществующих находок.

## Где пригодится

- **CTF (Web):** быстрый поиск скрытых путей и параметров; флаг часто лежит в забытом эндпоинте или файле.
- **Bug bounty:** массовое обнаружение контента, vhost и параметров — основа расширения поверхности.
- **Пентест:** стандартный content discovery; JSON-вывод идёт в отчёт как доказательство.
- **Работа (AppSec):** регулярный перебор в CI на появление забытых бэкапов и админок.
