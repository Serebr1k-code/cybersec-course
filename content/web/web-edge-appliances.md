## Вопрос, с которого всё начинается

На периметре любой крупной сети стоят шлюзы: балансировщик нагрузки, VPN-концентратор, secure-access-устройство. Это F5 BIG-IP, Fortinet FortiGate, Ivanti Connect Secure (бывший Pulse Secure). Через них проходит **весь** входящий трафик, и у них есть CVE, которые срабатывают **до входа в систему**. Именно такие уязвимости становились причиной самых громких взломов десятилетия. Разберём, почему этот класс appliance — вершина приоритета.

## Почему edge-appliance — цель номер один

Первое: **они на периметре**. К ним есть сетевой доступ из интернета — не нужен ни фишинг, ни внутренний плацдарм. Второе: **они pre-auth**. Критичные CVE в F5/Fortinet/Ivanti позволяют читать файлы или выполнять код без единой попытки входа. Третье: **за ними — внутренняя сеть**. VPN-шлюз видит её всю; балансировщик знает все внутренние сервисы. Четвёртое: **их долго не патчат** — обновление шлюза означает простой для всех сотрудников.

Из этого следует практический вывод: при пентесте периметра начинай именно с них. Одна pre-auth уязвимость на VPN-шлюзе стоит дороже десятка XSS на публичном сайте.

## Три семейства — три почерка

Каждый вендор оставил свой «почерк» уязвимостей:

- **F5 BIG-IP.** Управление через REST-API (iControl REST) на `/mgmt/tm/`. Классика — обход аутентификации через подделку заголовков (CVE-2022-1388) и RCE через TMUI (CVE-2020-5902). Есть также AJP-баг (CVE-2023-46747).
- **Fortinet FortiGate.** SSL-VPN-портал на `/remote/`. Классика — path traversal, читающий сессионные файлы с паролями (CVE-2018-13379), и обход аутентификации через заголовок (CVE-2022-40684).
- **Ivanti Connect Secure.** Портал на `/dana-na/`. Классика — комбинация обхода аутентификации (CVE-2023-46805) и инъекции команд (CVE-2024-21887), а также SSRF (CVE-2024-21893).

Заметь: у всех трёх критические баги — **pre-auth**. Это не совпадение: код, обрабатывающий запросы до аутентификации, — самая атакуемая часть шлюза.

## Наш пример: три шлюза в подсети

Тебе дали периметр. Прогоняем фингерпринт:

```
$ httpx -l edge.txt -title -tech-detect -status-code -silent
https://203.0.113.10 [200] [BIG-IP] [F5 Networks]
https://203.0.113.11 [200] [FortiGate SSL-VPN]
https://203.0.113.12 [200] [Ivanti Connect Secure]
```

Три продукта — три вектора. Дальше — одинаковая методика для каждого.

## Шаг 1: определить продукт и версию

- **F5 BIG-IP:** заголовок `Server: BIG-IP`, страница `/tmui/login.jsp`. Версия — в `/mgmt/tm/sys/version` (если доступно) или по статике.
- **FortiGate:** страница `/remote/login`, заголовок `Server: xxxxxxxx-xxxxx`. Версия — по `/remote/fgt_lang?lang=/../../../..` (в уязвимых).
- **Ivanti:** страница `/dana-na/auth/url_default/welcome.cgi`, cookie `DSID`. Версия — по `/dana-na/auth/url_default/welcome.cgi` и статике.

Версия — обязательна: без неё нельзя выбрать CVE.

## Шаг 2: сопоставить с CVE и проверить

Для каждого продукта — свой список CVE. Проверка всегда **неразрушающая**: traversal читает безобидный файл, обход аутентификации — запрашивает служебный эндпоинт, инъекция команд — выполняет `id`. Полная эксплуатация — только после подтверждения.

## Шаг 3: почему заголовочные баги так часты

Многие обходы аутентификации в этих продуктах — **заголовочные**. Продукт доверяет заголовку (например, `X-Forwarded-For` или `X-F5-Auth-Token`), считая, что его поставил внутренний компонент. Но заголовок можно поставить самому. Это называется **header trust abuse** — доверие к заголовку. Запомни: если шлюз проверяет заголовок, а не криптографию, его можно обойти.

## Шаг 4: пост-эксплуатация

Из шлюза достают: конфиги с кредами к AD/LDAP, сертификаты и приватные ключи (TLS-терминация на периметре!), сессионные файлы с паролями пользователей, список внутренних маршрутов. VPN-шлюз часто подключён к AD — значит, оттуда идут в домен.

## Шаг 5: приоритизация

Порядок: интернет-доступные pre-auth → интернет-доступные с утечкой кред → внутренние. Не трать время на внутренний пропатченный балансировщик, когда на периметре висит непропатченный VPN.

## Что мы теперь знаем

- Edge/VPN-appliance — цель номер один: периметр, pre-auth, доступ внутрь.
- Три семейства: F5 (iControl REST), Fortinet (SSL-VPN traversal), Ivanti (auth bypass + cmd injection).
- Общая методика: версия → CVE → неразрушающая проверка.
- Многие баги — заголовочные (header trust abuse).
- Ценность — в кредах, ключах и пути в домен.

## Куда дальше

Дальше — каждый шлюз отдельно: F5, Fortinet, Ivanti. А пока главное: **edge-appliance = периметр + pre-auth; определи продукт, версию, CVE.**
