## Задача

Тебе дали домен `target.local` и сказали «ищи уязвимости». С чего начать? Наивный порыв — сразу перебирать каталоги большим словарём. Но это дорого: сотни тысяч запросов, бан по IP и тонна мусора, потому что половина путей — «мягкие 404» (сервер отдаёт 200 на всё). Хочется порядок, при котором сначала **дёшево** строится карта, а уже потом **дорого** долбятся пути.

Этот урок — про конвейер разведки: от живых хостов до скрытых путей, где каждый этап решается своим инструментом.

## Данные, с которыми работаем

У нас есть корневой домен `target.local`. Из него мы хотим выжать: поддомены, живые сервисы, технологический стек, эндпоинты и, наконец, скрытые пути.

> **Пассивная разведка** — сбор данных без прямых запросов к цели (из DNS, публичных источников). **Активная** — прямые запросы, которые цель видит. Начинаем с дешёвой пассивной.

## Приём: конвейер из четырёх шагов

Порядок задаётся стоимостью: сначала дешёво, потом дорого.

1. **Поддомены** — `subfinder`.
2. **Живые хосты и стек** — `httpx`.
3. **Эндпоинты и JS** — `katana`.
4. **Известные баги** — `nuclei`; **скрытые пути** — `ffuf`.

Первый шаг — пассивный сбор имён:

```
$ subfinder -d target.local -silent | tee subs.txt
shop.target.local
api.target.local
staging.target.local
```

Три хоста. Теперь прогоняем их через `httpx` — массовую HTTP-пробу: она оставляет только живые и добавляет «паспорт» каждого.

```
$ httpx -l subs.txt -sc -title -td -silent
https://shop.target.local [200] [Shop] [nginx/1.18.0, PHP/7.4]
https://api.target.local [401] [Unauthorized] [Express]
https://staging.target.local [200] [Staging] [next.js/13.4]
```

Что мы прочли: `shop` — nginx + PHP, `api` требует авторизацию, а `staging` крутит Next.js 13.4. Уже есть зацепка: конкретная версия фреймворка — кандидат на известную CVE.

> **Tech-detect (`-td`)** — определение технологий по заголовкам и отпечаткам. **Title** — текст в `<title>` страницы, помогает понять назначение хоста.

## Шаг 3: краулинг — где `ffuf` бессилен

`staging` — одностраничное приложение (SPA). Перебор каталогов тут бесполезен: все пути вернут 200. Ссылки генерируются в JavaScript, поэтому краулим JS:

```
$ katana -u https://staging.target.local -jc -d 3 -silent -o urls.txt
$ grep -oE '"/api/[a-zA-Z0-9_/.-]+"' urls.txt | sort -u
"/api/internal/users"
"/api/debug/config"
```

`-jc` заставляет katana исполнять JS и искать эндпоинты внутри бандлов. Вот они — скрытые поверхности, которых нет в UI.

## Шаг 4: nuclei — известные баги по содержимому

Теперь дешёвый шаблонный скан. `nuclei` ищет по **содержимому** ответа, а не по имени продукта.

```
$ nuclei -l subs.txt -tags cve,misconfig -silent
[staging.target.local] [CVE-2023-XXXX] [critical] Next.js Middleware RCE
```

> ⚠️ Не грепай библиотеку шаблонов по названию продукта — CVE-шаблоны названы по `CVE-id`, и такой поиск пропустит нужный. Просто запусти `nuclei -u <target>` и дай отработать (при необходимости подними таймаут).

## Шаг 5: ffuf — скрытые пути

Когда карта построена и мы знаем, что `shop` — обычный nginx+PHP, перебор путей уместен:

```
$ ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
       -u https://shop.target.local/FUZZ -mc 200,301,302,401,403 -t 40
admin                   [Status: 301, Size: 178]
backup                  [Status: 403, Size: 153]
```

`-mc` оставляет только интересные коды, `-t 40` — 40 потоков. Но помни про **«мягкие 404»**: если сервер отвечает 200 на любой путь, фильтруй по размеру (`-fs`) или словам (`-fw`), а не по коду.

## Если не сработало

- **Wildcard DNS** — если `*.target.local` резолвится в один IP, любой несуществующий поддомен «жив». Фильтруй по содержимому.
- **Rate limiting** — `429`/`503`, капча, обрывы. Снижай `-t`, добавляй паузу (`ffuf -p 0.1`), меняй User-Agent.
- **SPA** — перебор каталогов не работает; крауль JS (`katana -jc`).
- **Словарь не тот** — `rockyou` по каталогам или `common.txt` по API. Подбирай список под стек.
- **Повторный прогон** — не запускай один словарь к одному `host:port` дважды: это шум без новой информации.

## Что мы теперь знаем

- Конвейер: поддомены → живые хосты → стек → эндпоинты → CVE → скрытые пути.
- `httpx` оставляет живые и даёт «паспорт»: код, title, технологии.
- `katana -jc` находит то, чего нет в HTML — эндпоинты из JS.
- `nuclei` ищет по содержимому; запускай его **до** глубокого ручного анализа.
- `ffuf` нужен для скрытых путей, но требует фильтров против «мягких 404».

## На что смотреть дальше

- **Версии.** `PHP/7.4`, `next.js/13.4` — сверь с известными CVE.
- **Vhost-фаззинг.** `ffuf -H 'Host: FUZZ.target.local'` находит скрытые виртуальные хосты.
- **Параметры.** `arjun` или `ffuf` по `?FUZZ=1` вскрывают необъявленные параметры.
- **Исторические URL.** `gau`/`waybackurls` дают забытые эндпоинты из архивов.
- **Каждый вывод — кандидат.** Подтверждай `curl` перед отчётом.

## Куда дальше

В следующем уроке мы задержимся на трёх инструментах этого конвейера — `httpx`, `katana` и `nuclei` — и разберём их флаги подробно. А пока главное запомни: **сначала дёшево построй карту, потом дорого бей по путям** — и никогда не перебирай каталоги на SPA.

## Где пригодится

- **CTF (Web):** быстро найти скрытый эндпоинт/параметр, который не виден в ссылках.
- **Bug bounty:** стандартный пайплайн subfinder → httpx → katana → nuclei → ffuf даёт карту программы за минуты.
- **Пентест:** приоритизация целей и доказательства находок для отчёта.
- **Работа (AppSec/DevSecOps):** регулярные сканы в CI и мониторинг изменений поверхности атаки.
