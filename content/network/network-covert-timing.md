## Вопрос, с которого всё начинается

Ты разбираешь PCAP из CTF-задачи. Трафик выглядит как обычный `ping` — ничего лишнего в payload. Но интервалы между пакетами подозрительно ровные: то короткая пауза, то длинная. Случайность ли это — или так прячут данные?

Covert-каналы скрывают данные там, где их не ждут: в **таймингах** между пакетами и в **полях** заголовков. Они не меняют payload, поэтому почти невидимы для DPI. Разберём, как найти такой канал.

## Наш пример: слишком ровный ping

Смотрим временные метки ICMP-пакетов:

```
$ tshark -r cap.pcap -Y 'icmp' -T fields -e frame.time_relative | head -6
0.000000
0.102341
0.401212
0.502871
0.604121
0.905432
```

Интервалы группируются вокруг двух значений: ~0.1 с и ~0.3 с. Для «живого» ping это слишком аккуратно — пахнет кодированием.

## Шаг 1: timing против storage

Есть два больших класса каналов:

- **Timing-каналы** — данные в **интервалах** между пакетами (пауза = бит 0/1) или в скорости потока.
- **Storage-каналы** — данные в **полях** заголовков (IP ID, TTL, TCP-опции, window), в **размерах** пакетов, в **padding**, в HTTP-заголовках.

Timing не меняет ни один байт содержимого, поэтому его не видит DPI по сигнатурам.

## Шаг 2: декодируем timing

Порогом делим интервалы на два класса. Пусть пауза >0.2 с — это `1`, иначе `0`:

```
$ tshark -r cap.pcap -Y 'ip.src==10.0.0.5 and icmp' -T fields -e frame.time_relative | \
    awk 'NR>1{d=$1-prev; print (d>0.2?"1":"0")} {prev=$1}' | tr -d '\n'
0100100001100101011011000110110001101111
```

Разбиваем по 8 бит: `01001000 01100101 01101100 01101100 01101111` — это ASCII `Hello`. Канал найден: данные лежали в паузах, а не в payload.

Порог подбирают по **гистограмме**: если интервалы образуют два чётких кластера, это почти наверняка канал.

```
$ tshark -r cap.pcap -Y 'udp' -T fields -e frame.time_relative | \
    awk 'NR>1{d=$1-prev; printf "%.3f\n",d} {prev=$1}' | sort -n | uniq -c | head
```

## Шаг 3: storage-каналы в полях

Если timing пуст, смотрим поля заголовков. **IP ID** в норме инкрементный или случайный; если значения образуют паттерн — в них кодируют данные. **Размер пакета** может напрямую кодировать байт (100+n = n). **TTL**, **window size**, **TCP-опции** редко валидируются.

```
$ tshark -r cap.pcap -T fields -e ip.id -e ip.ttl | head
$ tshark -r cap.pcap -T fields -e frame.len | sort -n | uniq -c | head
$ tshark -r cap.pcap -T fields -e tcp.window_size_value | head
```

## Шаг 4: детект (для SOC)

Признаки скрытого канала:

- **бимодальное** распределение интервалов (два кластера = биты 0/1);
- аномальная **регулярность** пакетов (beaconing-подобно);
- однотипные мелкие пакеты с высокой частотой;
- монотонные/структурированные IP ID, TTL, window;
- ограниченный «алфавит» размеров пакетов.

Проверить периодичность можно через стандартное отклонение интервалов:

```
$ tshark -r cap.pcap -Y 'ip.src==10.0.0.5' -T fields -e frame.time_relative | \
    awk 'NR>1{d=$1-prev; s+=d; ss+=d*d; n++} {prev=$1} END{m=s/n; print "mean",m,"std",sqrt(ss/n-m*m)}'
```

## Шаг 5: защита — нормализация

Единственный надёжный ответ на метаданные — **нормализация**: shaping (выравнивание задержек), padding до фиксированного размера, перезапись полей (случайный IP ID, фиксированный TTL), ограничение частоты мелких пакетов и ML-детект аномалий на baseline. Сетевой jitter — главный враг timing-канала: маршрутизаторы и очереди размывают кластеры, поэтому такие каналы работают лучше на коротких стабильных участках.

## Синхронизация и помехоустойчивость

Timing-канал бесполезен без **синхронизации начала**: получатель должен понять, где стартует поток и как размечать биты. Приёмы:

- **Преамбула** из фиксированной последовательности (`10101010`) для калибровки порога.
- **Маркер начала/конца** сообщения отдельным паттерном интервалов.
- **CRC** в конце для проверки целостности.
- **Избыточное кодирование** (повтор бита трижды, мажоритарное декодирование).
- **Адаптивный порог** по скользящему окну (медиана интервалов).

Сетевой jitter — главный враг: маршрутизаторы и очереди размывают кластеры. Поэтому timing-каналы работают лучше на коротких стабильных участках (LAN, один маршрут) и хуже через интернет.

```
$ tshark -r base.pcap -Y 'ip.src==10.0.0.5' -T fields -e frame.time_relative | \
    awk 'NR>1{d=$1-prev; s+=d; ss+=d*d; n++} {prev=$1} END{m=s/n; print "mean",m,"std",sqrt(ss/n-m*m)}'
```

## Сравнение каналов по заметности

| Канал | Что меняет | Ломается о | Детект |
|---|---|---|---|
| Timing | интервалы | shaping/buffering | бимодальность |
| IP ID | поле заголовка | нормализация IP ID | паттерн значений |
| Размер пакета | длину | padding/normalize | алфавит размеров |
| HTTP-заголовки | текст | DPI на L7 | аномальные поля |
| Padding | мусорные байты | канонизация | энтропия хвоста |

Порядок гипотез при разборе «странного» трафика: выделить поток → интервалы → гистограмму размеров → поля IP ID/TTL/window → HTTP-заголовки → padding. Чаще всего канал находится на втором или третьем шаге.

## Практическая лаборатория

Соберите собственный канал, чтобы понять обе стороны. Отправитель кодирует сообщение паузами 0.1/0.3 с через ICMP, получатель захватывает и декодирует:

```
$ sudo tcpdump -i eth0 -n icmp -w timing.pcap -c 40
$ tshark -r timing.pcap -T fields -e frame.time_relative | \
    awk 'NR>1{d=$1-prev; print (d>0.2?"1":"0")} {prev=$1}' | tr -d '\n'
```

Дальше усложняйте: добавьте преамбулу, CRC, повтор бита — и посмотрите, как меняется устойчивость к добавленному jitter (например, через `tc netem delay`).

## Что мы теперь знаем

- Covert-каналы бывают timing (интервалы) и storage (поля, размеры, padding).
- Бинарный timing-канал выдаёт бимодальное распределение интервалов.
- Порог по гистограмме превращает интервалы в биты; далее — ASCII.
- Storage-каналы прячутся в IP ID, TTL, window, размерах пакетов.
- Защита — нормализация трафика и ML-детект аномалий.

| Тип | Где данные | Пропускная способность | Детект |
|---|---|---|---|
| Timing | интервалы | низкая | бимодальность |
| Storage (поле) | заголовки | средняя | структура поля |
| Storage (размер) | длины пакетов | средняя | алфавит размеров |
| Туннель DNS/ICMP | запросы/ответы | средняя | объём, энтропия меток |

## Куда дальше

Мы научились читать данные в метаданных и защищаться нормализацией. На этом ветка скрытых каналов замыкается с анализом трафика — дальше идут практические задачи разбора PCAP. А пока запомни: **если содержимое выглядит обычно, смотри на форму — интервалы, размеры и поля расскажут то, что скрыто.**
