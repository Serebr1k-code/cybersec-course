Сканирование портов — это первый активный шаг разведки: определить, какие сервисы слушают на хосте. От качества скана зависит вся дальнейшая атака, потому что пропущенный порт = пропущенный вход. В уроке — устройство TCP/UDP-скан-техник, nmap во всех режимах, masscan и определение версий.

## Что такое сканирование портов и зачем

Порт — это 16-битное число (0–65535), идентифицирующее сервис на хосте. Сканер отправляет пакеты и по ответу определяет состояние порта:

- **open** — сервис слушает и отвечает.
- **closed** — хост доступен, порт закрыт (RST).
- **filtered** — ответа нет (firewall дропает).
- **open|filtered** — nmap не может различить (типично для UDP).

Цель сканирования — построить карту поверхности атаки: какие порты открыты, какие сервисы и версии за ними, какие могут быть уязвимы. Сканирование бывает **полным** (`-p-`, все 65535 портов) и **быстрым** (топ-1000 или топ-100).

## Типы сканов nmap

| Тип | Флаг | Механика | Плюсы/минусы |
|---|---|---|---|
| TCP connect | `-sT` | полное 3-way handshake | не требует root, шумно |
| TCP SYN (half-open) | `-sS` | SYN→SYN/ACK→RST | быстрый, скрытный, нужен root |
| UDP | `-sU` | UDP-датаграмма + ICMP | медленный, для DNS/SNMP |
| ACK | `-sA` | только ACK | карта firewall-правил |
| FIN/NULL/Xmas | `-sF/-sN/-sX` | обход stateless-firewall | не работает на Windows |
| Idle | `-sI` | через «зомби»-хост | максимальная анонимность |

Базовый SYN-скан: `-sS`. Если нет root — `-sT`. Для проверки firewall-правил — `-sA` (результат unfiltered/filtered).

## Практика: nmap с нуля

```bash
# быстрый скан топ-1000 портов
nmap 10.0.0.5

# полный скан всех портов в высоком темпе
nmap -p- --min-rate 5000 10.0.0.5

# определение версий и ОС
nmap -sV -O -p 22,80,443 10.0.0.5

# агрессивный режим (версии, скрипты, traceroute, ОС)
nmap -A 10.0.0.5

# UDP-скан популярных сервисов
sudo nmap -sU --top-ports 50 10.0.0.5

# вывод в XML для парсинга
nmap -sS -sV -oX scan.xml 10.0.0.5
```

Фрагмент вывода:

```text
PORT     STATE SERVICE     VERSION
22/tcp   open  ssh         OpenSSH 8.9p1 Ubuntu 3ubuntu0.4
80/tcp   open  http        nginx 1.18.0
443/tcp  open  ssl/https   nginx 1.18.0
3306/tcp open  mysql       MySQL 8.0.32
```

## Nmap NSE: скриптовый движок

NSE (Nmap Scripting Engine) расширяет сканер сотнями скриптов: от баннеров до эксплуатации.

```bash
# все безопасные скрипты + версии
nmap -sV -sC 10.0.0.5

# конкретная категория
nmap --script vuln 10.0.0.5

# один скрипт с аргументами
nmap -p445 --script smb-vuln-ms17-010 10.0.0.5
nmap -p80 --script http-enum,http-headers 10.0.0.5
nmap -p161 --script snmp-brute 10.0.0.5
```

Категории: `auth`, `broadcast`, `brute`, `default`, `discovery`, `dos`, `exploit`, `external`, `fuzzer`, `intrusive`, `malware`, `safe`, `version`, `vuln`.

## Masscan: скорость против скрытности

Masscan — асинхронный сканер, способный проверять миллионы пакетов в секунду. Плата — шумность.

```bash
# скан подсети на всех портах
masscan 10.0.0.0/24 -p1-65535 --rate 10000

# конкретные порты с выводом в JSON
masscan 10.0.0.0/24 -p80,443,22 --rate 1000 -oJ out.json

# исключить диапазон
masscan 0.0.0.0/0 -p443 --excludefile exclude.conf --rate 100000
```

Ключевой параметр — `--rate` (пакетов/сек). Слишком высокий = потери и блокировки; слишком низкий = долго.

## Определение сервисов и версий

`-sV` шлёт «пробы» и сопоставляет ответы с базой сигнатур (nmap-service-probes). Интенсивность задаётся `--version-intensity 0..9` (по умолчанию 7). Для точного определения TLS-сервисов помогает `--script ssl-cert`.

```bash
nmap -sV --version-all -p 443 10.0.0.5
```

## Разобранный пример: полный цикл скана

Цель: `10.0.0.5`. Шаг 1 — быстрый обзор:

```bash
nmap -sS -T4 --top-ports 1000 10.0.0.5 -oG quick.txt
```

Шаг 2 — полный скан найденных и остальных портов:

```bash
nmap -sS -p- --min-rate 5000 -T4 10.0.0.5 -oG all.txt
grep -oP '\d+/open' all.txt
```

Шаг 3 — версии и скрипты по открытым портам:

```bash
nmap -sV -sC -p22,80,443,3306 10.0.0.5 -oX svc.xml
```

Шаг 4 — целевые проверки уязвимостей через NSE. Итог: карта сервисов с версиями, готовая к сопоставлению с CVE.

## Тайминги и скрытность

Шаблоны `-T0..-T5`: `-T0` (paranoid) и `-T1` (sneaky) — для IDS-обхода, крайне медленно; `-T4` (aggressive) — норма для лаборатории; `-T5` (insane) — максимально быстро, риск потерь.

Скрытность: `--data-length`, `--randomize-hosts`, `-D RND:10` (декои), `--spoof-mac`, `--source-port 53` (иногда проходит сквозь firewall), `-f` (фрагментация пакетов).

## Edge cases и подводные камни

- **Rate limiting / fail2ban**: частые SYN приводят к бану IP — используйте `--scan-delay`, `-T2`.
- **NAT/балансировщик**: разные порты отвечают с разных бэкендов; повторный скан даёт разные результаты.
- **UDP**: отсутствие ответа ≠ закрыто (может быть filtered); используйте `--reason`.
- **tarpit** (LaBrea): порт «открыт», но соединение висит — таймаут спасает.
- **ICMP rate-limit** ломает host-discovery (`-Pn` отключает пинг).
- **Контейнеры/loopback**: сервис слушает только на 127.0.0.1 и не виден снаружи.

## Частые ошибки

- Сканировать без `-p-` и упустить сервис на высоком порту (8080, 8443, 27017).
- Забыть `-Pn`, когда ICMP заблокирован → «host seems down».
- Игнорировать UDP-порты (53, 161, 123).
- Полагаться только на баннер: `-sV` точнее.
- Запускать `-T5` по продакшену и получить бан.

## Что дальше / решение

После скана: (1) сохраните результат в XML (`-oX`) и распарсите; (2) по каждой версии сервиса ищите CVE; (3) переходите к network-service-enum для глубокой энумерации SMB/RDP/LDAP/NFS; (4) для скрытности изучите network-firewall-evasion. Решение: сканирование — это итеративный процесс «обзор → полный скан → версии → проверки», а не одна команда.

|---|---|---|
| -T0 | крайне медленно | максимальная |
| -T2 | медленно | высокая |
| -T3 | по умолчанию | средняя |

## Разобранный пример: от разведки до версий сервисов

Полный прогон по вымышленной цели `10.10.10.42`.

Шаг 1. Быстрый поиск живых хостов в подсети:

```bash
nmap -sn 10.10.10.0/24 -oG live.txt
grep Up live.txt | awk '{print $2}'
# 10.10.10.42
```

Шаг 2. Массовый поиск открытых портов:

```bash
nmap -sS -p- --min-rate 3000 -T4 -n -Pn 10.10.10.42 -oX ports.xml
# Not shown: 65529 closed tcp ports
# PORT     STATE SERVICE
# 22/tcp   open  ssh
# 80/tcp   open  http
# 8080/tcp open  http-proxy
# 3306/tcp open  mysql
```

Шаг 3. Версии и скрипты по найденным портам:

```bash
nmap -sV -sC -p 22,80,8080,3306 10.10.10.42 -oX services.xml
# 22/tcp   open  ssh     OpenSSH 8.4p1 Debian 5+deb11u1
# 80/tcp   open  http    Apache httpd 2.4.51 ((Debian))
# 8080/tcp open  http    Jetty 9.4.43
# 3306/tcp open  mysql   MySQL 5.7.36
```

Шаг 4. Целевые vuln-скрипты по версиям:

```bash
nmap --script http-vuln-cve2021-41773 -p 80 10.10.10.42
nmap --script mysql-info,ssl-enum-ciphers -p 3306 10.10.10.42
```

Шаг 5. UDP по ключевым портам:

```bash
nmap -sU --top-ports 20 10.10.10.42
```

Итог: Apache 2.4.51 — проверяем path traversal CVE-2021-41773; Jetty 9.4.43 — известные deserialization; MySQL 5.7 — тестируем дефолтные учётки. Сохранённые `-oX` уходят в парсер и в отчёт.

## Reference-таблица: скорость и скрытность

| Цель | Флаги | Комментарий |
|---|---|---|
| Быстро, локальная сеть | `-T4 --min-rate 2000 -n -Pn` | риск ложных filtered |
| Тише, через IDS | `-T2 --scan-delay 1s` | медленно |
| Обход фильтра портов | `--source-port 53` | доверенные порты |
| Скрыть источник | `-D RND:10` | decoys |
| Полная скрытность | `-sI zombie` | idle-скан |
| Обход фрагмент-фильтра | `-f` / `-ff` | мелкая фрагментация |

## Чек-лист сканирования

1. Живые хосты (`-sn`), затем полный диапазон портов (`-p-`).
2. Версии (`-sV`) и скрипты (`-sC`) — обязательно сохранять `-oX`.
3. UDP по 53/123/161/500.
4. Проверить IPv6 (`nmap -6`).
5. Сопоставить версии с CVE, прогнать targeted NSE.
6. Не забыть повторить скан после изменений (смена таймингов, source-port).

## Продвинутые техники NSE

Скриптовый движок nmap умеет гораздо больше, чем баннеры. Полезные приёмы для реальной работы:

```bash
# передать аргументы скрипту
nmap -p80 --script http-title,http-headers,http-methods 10.0.0.5
nmap -p443 --script ssl-enum-ciphers,ssl-cert 10.0.0.5
nmap -p445 --script "smb-enum-*,smb-vuln-*" 10.0.0.5

# записать результаты всех скриптов в отдельные файлы
nmap -sV --script vuln --script-args=unsafe=1 10.0.0.5 -oN vuln.txt

# найти скрипт по ключевому слову
ls /usr/share/nmap/scripts/ | grep -i 'smb'
```

Полезные категории: `discovery` (обнаружение сервисов), `version` (уточнение версий), `vuln` (проверка CVE), `brute` (перебор учёток), `safe`/`default` (безопасные по умолчанию). Для эксплуатации используйте только `vuln`-скрипты с известными CVE, а `brute` — с малой базой кандидатов.

## Сканирование через pivot и прокси

Когда прямой доступ закрыт, скан идёт через скомпрометированный узел или прокси:

```bash
# через SOCKS5-прокси (например, chisel/ssh -D)
proxychains4 nmap -sT -Pn -p22,80,443 10.10.10.20

# через SSH-динамический туннель
ssh -D 9050 user@pivot -N -f
nmap --proxies socks4://127.0.0.1:9050 -sT -Pn 10.10.10.20
```

Важно: SYN-скан (`-sS`) через прокси не работает — нужен `-sT` (полное соединение), потому что прокси не пересылает сырые пакеты. Для pivoting удобнее `proxychains` + `-sT -Pn`.

## Автоматизация и пайплайны

Ручной скан плохо масштабируется. Типовой пайплайн:

```bash
# 1. обнаружение живых хостов
nmap -sn 10.0.0.0/24 -oG - | awk '/Up$/{print $2}' > live.txt
# 2. быстрый скан портов по каждому
while read ip; do nmap -sS -T4 --top-ports 1000 "$ip" -oG "scan_$ip.gnmap"; done < live.txt
# 3. извлечь открытые порты
grep -h 'Ports:' scan_*.gnmap | grep -oP '\d+/open' | sort -u
# 4. передать в энумерацию
nmap -sV -sC -iL live.txt -oX full.xml
```

Разбор XML: `nmap_parse` в рамках пентест-пайплайна превращает XML в структурированный список хостов/портов/версий. Параллельно удобно использовать `httpx` для веб-портов:

```bash
cat open_web.txt | httpx -title -tech-detect -status-code -silent
```

## Оценка результатов и приоритизация

Не все открытые порты равны. Приоритет по «урожайности»:

| Приоритет | Порты | Почему |
|---|---|---|
| Высокий | 445, 389, 3389, 5985 | AD-атаки, доступ, RCE |
| Средний | 80, 443, 8080 | веб-уязвимости |
| Средний | 22, 21, 1433, 3306 | креды, БД |
| Низкий | 111, 135, 139 | вспомогательные |

Сопоставляйте версии с CVE и учитывайте дату сборки. Версия `nginx 1.18.0` сама по себе не уязвима, но связка с конфигом, модулями и заголовками даёт контекст.

## Ложные срабатывания и валидация

Сканер ошибается: «open» может быть tarpit или балансировщик, отвечающий нестабильно. Валидируйте ручным подключением:

```bash
nc -nv 10.0.0.5 8080
curl -sv http://10.0.0.5:8080/
openssl s_client -connect 10.0.0.5:443 -servername example.com </dev/null
```

Повторите скан с `--reason`, чтобы увидеть, на основании чего порт признан открытым (`syn-ack`, `reset`, `no-response`). Это отсекает ложные «open|filtered».

## Где пригодится

- **CTF:** поиск открытых сервисов и версий.
- **Пентест:** инвентаризация сервисов периметра и внутренней сети.
- **Bug bounty:** определение технологий на хостах.
- **Работа:** аудит собственных сетей, обнаружение лишних сервисов.
- **IR:** понимание, что было доступно атакующему.
