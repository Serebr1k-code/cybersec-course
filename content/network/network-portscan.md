## Вопрос, с которого всё начинается

Ты нашёл хост в сети. Что на нём запущено? Какие двери открыты? Пока не знаешь — атаковать нечего. Первый активный шаг разведки — **сканирование портов**: перебор портов и определение, какие сервисы на них отвечают.

В этом уроке мы разберём, как устроен скан на уровне пакетов, и прогоним реальное сканирование инструментом nmap.

## Наш пример: скан в дампе scan.pcap

Сначала посмотрим, как скан выглядит со стороны сети. У нас есть дамп `scan.pcap`, снятый на хосте-цели. Достанем из него попытки соединения:

```
$ tshark -r scan.pcap -Y 'tcp.flags.syn==1 && tcp.flags.ack==0' -T fields -e ip.src -e tcp.dstport
10.0.0.9	22
10.0.0.9	80
10.0.0.9	443
10.0.0.9	3306
10.0.0.9	8080
```

Термины:

- **Порт** — номер «двери» на хосте. У каждого сервиса свой: SSH — 22, HTTP — 80, HTTPS — 443, MySQL — 3306.
- **SYN** — флаг TCP «хочу установить соединение». Сканер шлёт SYN на каждый порт и по ответу понимает, открыт он или нет: `SYN,ACK` — открыт, `RST` — закрыт, тишина — фильтруется файрволом.
- **SYN-скан** (он же half-open, `-sS`) — самый быстрый: сканер не доводит соединение до конца, поэтому оно не попадает в логи приложения.

Из дампа видно: хост `10.0.0.9` за доли секунды постучался в пять портов — типичный скан. Мы получили картину глазами защитника; теперь посмотрим на неё глазами атакующего.

## Шаг 1: базовый скан nmap

**nmap** — стандартный инструмент сканирования. Начнём с простого TCP-скана популярных портов:

```
$ nmap -sT --top-ports 20 127.0.0.1
PORT     STATE  SERVICE
21/tcp   closed ftp
22/tcp   closed ssh
80/tcp   closed http
443/tcp  closed https
3306/tcp closed mysql
8080/tcp closed http-proxy
...
Nmap done: 1 IP address (1 host up) scanned in 0.02 seconds
```

Разбор: `-sT` — **TCP connect-скан** (полное соединение, работает без прав root), `--top-ports 20` — проверить 20 самых популярных портов, а не все 65535. `STATE` бывает `open` (сервис слушает), `closed` (порт отвечает, но сервиса нет) и `filtered` (ответ не пришёл — вероятно, файрвол).

## Шаг 2: определение версий

Знать, что порт открыт, мало — нужна **версия сервиса**, ведь от неё зависит, какой эксплойт применим. Ключ `-sV` включает определение версий: nmap шлёт сервису несколько запросов и сравнивает ответы со своей базой.

```
$ nmap -sV -Pn -p 2200,3306,6379,8000 127.0.0.1
PORT     STATE SERVICE VERSION
2200/tcp open  ssh     OpenSSH 8.9p1 Ubuntu 3ubuntu0.6 (Ubuntu Linux; protocol 2.0)
3306/tcp open  mysql   MySQL 8.0.36
6379/tcp open  redis?
8000/tcp open  http    SimpleHTTPServer 0.6 (Python 3.14.4)
Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel
```

Теперь у нас точные версии: `OpenSSH 8.9p1`, `MySQL 8.0.36`, `SimpleHTTPServer`. `-Pn` означает «считать хост живым, не проверяя ping» (полезно, когда ICMP заблокирован), `-p` перечисляет конкретные порты. Пометка `redis?` с вопросительным знаком — nmap узнал сервис, но не уверен в версии.

## Шаг 3: UDP и «невидимый» периметр

TCP — не единственный транспорт. Часть сервисов работает по **UDP**: DNS (53), SNMP (161), NTP (123). Их тоже нужно проверять, но UDP-скан (`-sU`) медленный и ненадёжный, поэтому обычно сканируют только топовые UDP-порты:

```
$ sudo nmap -sU --top-ports 20 10.0.0.20
```

Пропущенный UDP-порт — это пропущенный вход (например, открытый SNMP с community `public`).

## Шаг 4: masscan — когда портов слишком много

Если нужно просканировать не один хост, а целую сеть `/16`, nmap будет слишком медленным. Здесь помогает **masscan** — сканер, работающий асинхронно и умеющий выдавать миллионы пакетов в секунду:

```
$ masscan 10.0.0.0/16 -p80,443 --rate 10000
```

`--rate 10000` — 10 тысяч пакетов в секунду. masscan не определяет версии и не разбирает протоколы — он только говорит «порт открыт». Поэтому схема такая: **masscan находит хосты и порты, nmap уточняет версии**. Обратная сторона скорости — шумность: такой поток пакетов почти наверняка попадёт в IDS.

## Шаг 5: как уменьшить заметность

Пентестеру часто нужно сканировать тихо. Приёмы:

- **Замедлить.** `-T2` вместо агрессивного `-T4` не превышает порог IDS-правил.
- **Разнести по времени.** Сканировать порты с паузами, а не подряд.
- **Сменить тип скана.** SYN-скан не завершает соединения, поэтому не пишется в логи приложений.
- **Использовать разные источники.** Сканировать с нескольких хостов, чтобы не выделяться.

## Шаг 6: как ведёт себя файрвол

Результат скана сильно зависит от того, как настроена фильтрация. Различай три состояния порта:

- **open** — сервис ответил (`SYN,ACK`). Дверь открыта.
- **closed** — хост ответил `RST`: порт доступен, но сервиса на нём нет. Сам по себе это признак живого хоста.
- **filtered** — ответа нет вообще. Скорее всего, пакет проглотил файрвол. Такие порты иногда «открываются», если сменить порт источника или добавить фрагментацию.

Практический нюанс: файрвол, который **дропает** пакеты, замедляет скан — nmap ждёт таймаут. Ключ `--max-retries 1` и `--host-timeout` помогают не увязнуть. А `-Pn` нужен, когда хост вообще не отвечает на ping, но порты при этом могут быть открыты.

## Шаг 7: результат — в машиночитаемый файл

Скан бесполезен, если результат некуда положить. nmap умеет писать сразу в несколько форматов:

```
$ nmap -sV -oA scan 10.0.0.0/24
```

`-oA scan` создаёт `scan.nmap` (для глаз), `scan.xml` (для парсеров) и `scan.gnmap` (для `grep`). Дальше эти файлы забирает инструмент автоматизации — например, конвертирует в таблицу или загружает в сканер уязвимостей. Не парси вывод глазами: пусть его читает скрипт.

## Шаг 8: скан диапазона и CIDR

В реальной разведке цель — не один хост, а подсеть. nmap принимает диапазоны прямо в аргументе:

```
$ nmap -sS -T4 --open -p 22,80,443,3389 10.0.0.0/24
```

`/24` — это 256 адресов. nmap сам разберёт, кто жив, и покажет открытые порты по каждому. Для нескольких несвязанных целей удобнее файл: `-iL hosts.txt`, где каждая строка — адрес, диапазон или CIDR. Так удобно готовить скан заранее и запускать его одной командой.

Отдельный приём — **исключения**: `--exclude 10.0.0.1,10.0.0.5` не даёт случайно просканировать критичные хосты (например, шлюз или свою же машину).

## Что мы теперь знаем

По-простому:

1. Скан портов — первый шаг разведки; по нему строят карту сервисов.
2. SYN-скан (`-sS`) быстрый и малозаметный; `-sT` — полное соединение без root.
3. `-sV` определяет версии сервисов — ключ к выбору эксплойта.
4. UDP-порты (`-sU`) тоже надо проверять, иначе пропустишь вход.
5. masscan — для больших диапазонов, nmap — для точных версий.
6. Заметность снижают замедлением и сменой типа скана.

## На что смотреть дальше

- **Сначала порты, потом версии.** Не трать `-sV` на закрытые порты.
- **Не забывай UDP.** DNS, SNMP, NTP живут только на UDP.
- **Соотноси скорость и заметность.** Быстрый скан шумный, тихий — медленный.
