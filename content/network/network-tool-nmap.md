## Вопрос, с которого всё начинается

nmap — инструмент, к которому возвращаешься постоянно. Но у него десятки ключей, и каждый раз вспоминать синтаксис долго. Этот урок — справочник, но не сухой список: мы прогоним nmap по одному хосту и по ходу решения покажем, какой флаг зачем, а таблицу всех флагов соберём в конце.

## Наш пример: разведка одного хоста

Задача: узнать всё о хосте `127.0.0.1`. Начнём с быстрой проверки популярных портов.

```
$ nmap -sT --top-ports 20 127.0.0.1
PORT     STATE  SERVICE
21/tcp   closed ftp
22/tcp   closed ssh
80/tcp   closed http
443/tcp  closed https
...
Nmap done: 1 IP address (1 host up) scanned in 0.02 seconds
```

`-sT` — TCP connect-скан (без root), `--top-ports 20` — двадцать популярных портов. Все закрыты — значит, идём искать конкретные порты вручную.

## Шаг 1: находим открытые порты и версии

```
$ nmap -sV -Pn -p 2200,3306,6379,8000 127.0.0.1
PORT     STATE SERVICE VERSION
2200/tcp open  ssh     OpenSSH 8.9p1 Ubuntu 3ubuntu0.6 (Ubuntu Linux; protocol 2.0)
3306/tcp open  mysql   MySQL 8.0.36
6379/tcp open  redis?
8000/tcp open  http    SimpleHTTPServer 0.6 (Python 3.14.4)
```

`-Pn` — не проверять доступность хоста ping-ом (нужно, когда ICMP блокируется), `-p` — список портов, `-sV` — версии. У нас четыре открытых сервиса с версиями.

## Шаг 2: копаем скриптами

```
$ nmap -sV -p 8000 --script=http-title 127.0.0.1
8000/tcp open  http    SimpleHTTPServer 0.6 (Python 3.14.4)
|_http-title: Directory listing for /
```

Скрипт `http-title` достал заголовок страницы. Теперь соберём флаги по категориям.

## Справочник: выбор цели и хостов

| Флаг | Значение |
|------|----------|
| `-iL hosts.txt` | читать цели из файла |
| `-iR N` | N случайных хостов из интернета |
| `-Pn` | не пинговать, считать хост живым |
| `-sn` | только обнаружить хосты, без портов (ping-scan) |
| `--exclude` | исключить хосты из скана |
| `-n` | не разрешать DNS-имена (быстрее) |

## Справочник: типы сканов

| Флаг | Значение |
|------|----------|
| `-sS` | SYN-скан (half-open), нужен root |
| `-sT` | TCP connect-скан, без root |
| `-sU` | UDP-скан |
| `-sV` | определение версий |
| `-O` | определение ОС |
| `-A` | агрессивно: `-sV -O -sC --traceroute` |
| `-sC` | скрипты категории default |

## Справочник: порты

| Флаг | Значение |
|------|----------|
| `-p 80,443` | только указанные порты |
| `-p 1-1000` | диапазон портов |
| `-p-` | все 65535 портов |
| `--top-ports 100` | топ-100 популярных |
| `-F` | быстрый режим (топ-100) |
| `--open` | показывать только открытые |

## Справочник: NSE-скрипты

| Флаг | Значение |
|------|----------|
| `--script=name` | конкретный скрипт |
| `--script=default` | набор по умолчанию |
| `--script=vuln` | проверки уязвимостей |
| `--script-args k=v` | аргументы скрипта |
| `--script-help name` | справка по скрипту |

## Справочник: тайминги и обход

| Флаг | Значение |
|------|----------|
| `-T0..-T5` | шаблон скорости |
| `--min-rate N` | минимум пакетов в секунду |
| `--max-retries N` | число повторов |
| `-f` | фрагментировать пакеты |
| `-D RND:10` | приманки (decoys) |
| `--source-port 53` | подменить порт источника |
| `--spoof-mac 0` | случайный MAC |

## Справочник: вывод

| Флаг | Значение |
|------|----------|
| `-oN out.txt` | обычный текстовый вывод |
| `-oX out.xml` | XML (для парсеров) |
| `-oG out.gnmap` | greppable-формат |
| `-oA base` | сразу все три формата |
| `-v` | подробно |

`-oA scan` создаёт `scan.nmap`, `scan.xml` и `scan.gnmap` сразу — удобно, когда дальше результат читает скрипт или парсер.

## Готовые рецепты

```
# быстрая разведка: топ-порты + версии + скрипты
nmap -sV -sC -T4 --top-ports 100 target

# полный скан всех портов с выводом только открытых
nmap -p- --open -T4 target

# проверка уязвимостей
nmap -sV --script=vuln target

# UDP по важным портам
sudo nmap -sU -p 53,123,161 target

# тихий скан для обхода IDS
nmap -sS -T2 -f --source-port 53 target

# весь диапазон в файл
nmap -sV -oA internal_scan 10.0.0.0/24
```

## Сравнение типов сканов

Чтобы выбирать осознанно, держи в голове разницу:

| Скан | Флаг | Root | Заметность | Когда применять |
|------|------|------|-----------|-----------------|
| SYN (half-open) | `-sS` | да | низкая | основной TCP-скан |
| Connect | `-sT` | нет | средняя | когда нет root |
| UDP | `-sU` | да | низкая, но медленно | DNS/SNMP/NTP |
| ACK | `-sA` | да | средняя | карта правил файрвола |
| FIN/Xmas/Null | `-sF/-sX/-sN` | да | обход простых фильтров | нестандартные ситуации |

SYN-скан по умолчанию самый практичный: быстрый и не завершает соединение. Connect-скан — запасной вариант без привилегий.

## Частые ошибки

- **Сканировать `-p-` «на всякий случай».** Полный скан 65535 портов долгий и шумный; сначала топ-порты.
- **Забыть `-Pn`.** Хост может не отвечать на ping, но иметь открытые порты.
- **Игнорировать UDP.** Многие входы (SNMP, DNS) живут только на UDP.
- **Доверять `-sV` на 100%.** Версия может быть скрыта или подделана баннером.
- **Читать вывод глазами.** Используй `-oX`/`-oG` и парсеры.

## Как читать результат скана

Понимание вывода nmap экономит время при разборе. Ключевые моменты:

- **Состояние порта.** `open`, `closed`, `filtered` — мы разбирали их в уроке про сканирование; здесь важно, что `filtered` часто означает файрвол, а не «порт закрыт».
- **Строка `Service Info`.** В конце отчёта nmap может указать ОС, CPE-идентификаторы и версию ядра — полезно для подбора эксплойтов.
- **`Nmap done`.** Время скана говорит о поведении фильтра: если очень долго — пакеты дропаются и nmap ждёт таймауты.
- **Дерево скриптов.** Строки с `|` — вывод NSE, привязанный к порту.

Не пытайся запомнить весь вывод: сохраняй `-oX` и открывай в визуализаторе (например, Zenmap) или парсь скриптом. Ценность nmap — в структурированных данных, а не в тексте на экране.

## Что мы теперь знаем

По-простому:

1. nmap — универсальный сканер: порты, версии, ОС, скрипты.
2. `-sV -sC` — базовый набор для разведки сервиса.
3. NSE (`--script`) добавляет проверки уязвимостей.
4. Тайминги и флаги обхода управляют скоростью и заметностью.
5. `-oA` сохраняет результат во все форматы сразу.

## На что смотреть дальше

- **Не гонись за `-p-` без причины.** Полный скан шумный и долгий.
- **`-A` — это много сразу.** Он шумит; для тихого пентеста собирай флаги вручную.
- **Парси результат.** `-oX`/`-oG` читают скрипты; не парси глазами.
