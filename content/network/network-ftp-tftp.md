FTP и TFTP — старейшие протоколы передачи файлов. Оба лишены шифрования, часто допускают анонимный доступ, а TFTP вообще не имеет аутентификации. Для пентеста это быстрый путь к файлам, учётным данным и подмене конфигураций. Урок продолжает [`network-module-services`](network-module-services).

## FTP: два соединения

FTP использует **два** соединения: управляющее (21/tcp) и данные. Режимы:

- **Active** — сервер сам подключается к клиенту (порт 20 → клиент); мешает NAT/firewall.
- **Passive** — клиент подключается к серверу на случайный порт; дружелюбен к NAT.

```text
Клиент -> 21: USER/PASS/PORT/PASV/RETR/STOR
Active:  сервер:20 -> клиент:порт
Passive: клиент -> сервер:случайный порт
```

```bash
# Ручная сессия
nc -nv 10.0.0.1 21
# Клиент
ftp 10.0.0.1
# lftp (удобнее для скриптов)
lftp -u user,pass 10.0.0.1
```

## Анонимный доступ

Многие FTP-серверы разрешают вход `anonymous`/`ftp` (часто с любым паролем). Это раскрывает файлы и структуру каталогов.

```bash
# NSE-скрипт
nmap -p 21 --script ftp-anon 10.0.0.1
# Вручную
ftp 10.0.0.1   # логин: anonymous, пароль: пусто/email
# Проверить запись
ftp> put test.txt
```

```bash
# Рекурсивно скачать всё доступное
wget -m --no-passive ftp://anonymous:anonymous@10.0.0.1/
```

## FTP bounce

**FTP bounce** использует команду `PORT` для открытия соединения от имени сервера к произвольному хосту. Это позволяет сканировать сети «через» FTP-сервер и обходить фильтры.

```bash
# NSE: bounce-скан через FTP
nmap -p 21 --script ftp-bounce 10.0.0.1
# Ручная проверка bounce
ftp 10.0.0.1
ftp> PORT 10.0.0.2,0,80
ftp> LIST
```

## TFTP: без аутентификации

**TFTP** (69/udp) — тривиальная передача файлов без аутентификации. Часто используется для загрузки прошивок/конфигов сетевого оборудования. Если TFTP writable — можно подменить конфигурацию.

```bash
# Скачать файл
tftp 10.0.0.1 -c get running-config.txt
# Загрузить файл (если разрешено)
tftp 10.0.0.1 -c put malicious.cfg
# Скрипт NSE
nmap -sU -p 69 --script tftp-enum 10.0.0.1
```

## Практика: анонимный FTP и поиск интересного

```bash
# 1. Обнаружить и проверить аноним
nmap -sV -p 21 --script ftp-anon,ftp-bounce 10.0.0.1
# 2. Скачать всё
wget -m --no-passive ftp://anonymous:x@10.0.0.1/ 2>/dev/null
# 3. Поискать секреты в файлах
grep -rEi 'password|passwd|secret|key|token' . 2>/dev/null | head
# 4. Проверить запись
curl -T test.txt ftp://anonymous:x@10.0.0.1/ 2>&1 | head
```

```bash
# Брутфорс FTP (осторожно, малый список)
```

## Атаки

- **Анонимный вход** — чтение/запись файлов;
- **Брутфорс** — слабые пароли;
- **FTP bounce** — сканирование через сервер;
- **Перехват** — нет шифрования (логин/пароль открыто);
- **TFTP-подмена** — загрузка вредоносной конфигурации;
- **Утечка конфигов** — через анонимный TFTP.

```bash
# Перехватить FTP-креды в дампе
tshark -r cap.pcap -Y 'ftp.request.command=="USER" || ftp.request.command=="PASS"' \
  -T fields -e ftp.request.arg
```

## Защита

| Мера | Против чего |
|---|---|
| Заменить FTP на SFTP/FTPS | перехват |
| Отключить анонимный доступ | утечка файлов |
| Запретить bounce (проверять PORT) | сканирование |
| Ограничить права записи | подмена файлов |
| TFTP только в доверенной сети | подмена конфигов |
| Мониторинг FTP/TFTP | аномалии |

## Частые ошибки

- **Игнорировать активный/пассивный режим** — клиент «висит».
- **Не проверять запись** — загрузка файлов остаётся незамеченной.
- **Забывать про bounce** — сканирование через FTP.
- **Считать TFTP «редким»** — он повсюду в сетевом оборудовании.
- **Не искать секреты в файлах** — пароли/ключи в конфигах.
- **Путать 20/21** — данные и управление.
- **Не перехватывать FTP-креды** — они идут открыто.

## Практика: FTP и TFTP end-to-end

```bash
# FTP: аноним + загрузка + проверка записи
nmap -p 21 --script ftp-anon,ftp-bounce 10.0.0.1
wget -m --no-passive ftp://anonymous:anonymous@10.0.0.1/ 2>/dev/null
curl -T test.txt ftp://anonymous:x@10.0.0.1/ 2>&1 | head
# Поиск секретов в скачанных файлах
grep -rEi 'password|secret|token|key' . 2>/dev/null | head
# TFTP: скачать и (если можно) загрузить
tftp 10.0.0.1 -c get startup-config.txt
tftp 10.0.0.1 -c put evil.cfg
nmap -sU -p 69 --script tftp-enum 10.0.0.1
```

## Сравнение протоколов передачи файлов

| Протокол | Транспорт | Порт | Шифрование | Аутентификация |
|---|---|---|---|---|
| FTP | TCP | 21/20 | нет | user/pass (plain) |
| FTPS | TCP | 990/21 | TLS | user/pass/серт |
| SFTP | TCP | 22 | SSH | ключ/пароль |
| TFTP | UDP | 69 | нет | нет |
| SCP | TCP | 22 | SSH | ключ/пароль |

## Чек-лист FTP/TFTP

1. Открыт ли **анонимный** доступ?
2. Разрешена ли **запись** (STOR/put)?
3. Уязвим ли сервер к **bounce** (команда PORT)?
4. Есть ли **секреты** в доступных файлах?
5. Используется ли **TFTP** для конфигов оборудования?
6. Заменены ли FTP/TFTP на **SFTP/SCP**?
7. Логируются ли загрузки/выгрузки?

```bash
# Перехват FTP-кред из дампа
```

Вывод: FTP и TFTP — быстрый путь к файлам и конфигам, но обе технологии устарели. Миграция на SFTP/SCP и ограничение TFTP доверенной сетью закрывает и перехват, и подмену.

## Продвинутые техники FTP

```bash
# Список файлов через NSE
nmap -p 21 --script ftp-anon --script-args ftp-anon.maxlist=100 10.0.0.1
# Пассивный режим вручную
ftp -p 10.0.0.1
# Рекурсивная выгрузка lftp
lftp -u anonymous,x 10.0.0.1 -e 'mirror / ./loot; bye'
# Поиск по содержимому
grep -rEi 'BEGIN (RSA|OPENSSH|EC) PRIVATE KEY' loot/ 2>/dev/null
# Проверить права записи в конкретный каталог
ftp> cd upload; put shell.php
```

FTP-серверы часто хранят бэкапы, конфиги и ключи — и анонимный доступ делает их общедоступными.

## Итог по FTP/TFTP

FTP и TFTP дают доступ к файлам без шифрования. Практические векторы:

- **анонимный вход** — чтение (иногда запись);
- **bounce** — сканирование через сервер;
- **перехват** — пароли в открытом виде;
- **TFTP-подмена** — загрузка вредоносного конфига;
- **утечка ключей** — приватные ключи в бэкапах.

Защита однозначна: **SFTP/SCP вместо FTP**, отключение анонима, запрет bounce, TFTP только в доверенной сети. Это устраняет и перехват, и подмену, и утечку.

## Заметка о bounce и SSRF-подобных техниках

FTP bounce — частный случай более общего класса: сервер устанавливает соединение по указанию клиента. Аналогично ведут себя некоторые HTTP-прокси (CONNECT), SMTP (EXPN/VRFY), а также SSRF в веб-приложениях.

```bash
# Идея bounce: сервер — «прокси» для сканирования
ftp 10.0.0.1
ftp> PORT 192,168,1,10,0,22   # соединиться с 192.168.1.10:22
ftp> LIST
```

Если ответ различается для открытых/закрытых портов — сервер используется как сканер. Защита — отклонять команду `PORT` на чужие адреса. Для TFTP аналогичный риск — загрузка конфигов на устройства, что позволяет подменить маршрутизацию или учётные данные.
