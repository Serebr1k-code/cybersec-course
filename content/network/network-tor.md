## Вопрос, с которого всё начинается

В CTF-артефакте ты нашёл адрес `.onion` — скрытый сервис, который доступен только внутри сети Tor. Снаружи его нет ни в DNS, ни по IP. Как вообще достучаться до ресурса, у которого нет видимого адреса — и что при этом видно в твоём трафике?

Tor маршрутизирует трафик через несколько узлов с многослойным шифрованием («луковица»). Разберём его на примере доступа к onion-сервису.

## Наш пример: подключаемся к onion-сервису

Запускаем Tor — он поднимает локальный SOCKS-прокси на порту 9050:

```
$ tor &
$ curl -s --socks5-hostname 127.0.0.1:9050 https://check.torproject.org/api/ip
{"IsTor":true,"IP":"185.220.x.x"}
```

Ответ подтверждает: мы в сети Tor, а наружу виден адрес выходного узла, не наш. Теперь — к onion-сервису:

```
$ curl -s --socks5-hostname 127.0.0.1:9050 -sI http://<addr>.onion/
HTTP/1.1 200 OK
```

`--socks5-hostname` (или `socks5h`) важен: DNS-резолвинг тоже идёт через Tor, иначе имена утекают.

## Шаг 1: как устроена цепь

Трафик идёт через три узла:

```text
Вы --TLS--> Guard --TLS--> Middle --TLS--> Exit --plain--> Сайт
```

- **Guard** (входной) знает твой IP, но не назначение.
- **Middle** (средний) добавляет слой анонимности.
- **Exit** (выходной) знает назначение, но не твой IP.

Каждый узел снимает свой слой шифрования — отсюда «луковица». Guard выбирается на длительный срок (месяцы) — частая смена облегчила бы корреляцию.

## Шаг 2: что видно в трафике

На проводе видно только соединение к Guard. Но его выдают характерные признаки:

```
$ sudo tcpdump -i eth0 -nn 'tcp port 9001' -c 2
10.0.0.50.51322 > 198.51.100.7.9001: Flags [P.], length 514
10.0.0.50.51322 > 198.51.100.7.9001: Flags [P.], length 514
```

Порт 9001 и **ячейки фиксированного размера** (512 байт + заголовок) — типичный паттерн Tor. А публичный список узлов лежит в **consensus**, который можно скачать и сопоставить IP с relay:

```
$ curl -s https://onionoo.torproject.org/summary | head -c 200
```

## Шаг 3: onion-сервисы v3

У onion-сервиса нет exit-узла: обе стороны встречаются внутри сети Tor. Адрес v3 — это base32 от публичного ключа ed25519, 56 символов. Схема такая:

1. Сервис публикует **descriptor** (список introduction points) в распределённой хэш-таблице HSDir.
2. Клиент скачивает descriptor и через introduction point передаёт «rendezvous cookie».
3. Обе стороны строят цепь к **rendezvous point** и встречаются там — ни клиент, ни сервис не знают IP друг друга.

Onion v2 (16 символов) полностью отключён с 2021 года — если в задаче встречается такой адрес, он нерабочий.

## Шаг 4: мосты и обход цензуры

Если соединения к Guard-узлам блокируются, используют **bridges**. `obfs4` делает трафик похожим на случайные байты, `meek` — на HTTPS к CDN:

```text
UseBridges 1
ClientTransportPlugin obfs4 exec /usr/bin/obfs4proxy
Bridge obfs4 <ip:port> <fingerprint> cert=<...> iat-mode=0
```

## Шаг 5: детект и атаки на анонимность

Tor не делает тебя невидимым. Слабые места:

| Атака | Механика |
|---|---|
| End-to-end correlation | сопоставить вход и выход по таймингам/объёму |
| Website fingerprinting | классификация сайта по паттерну ячеек |
| DNS/application leak | приложение ходит в сеть мимо SOCKS |
| Exit-node подмена | exit отдаёт изменённый контент |

Проверить утечку DNS просто — слушать порт 53, пока идёт запрос через Tor:

```
$ sudo tcpdump -i eth0 -n 'udp port 53' &
$ curl --socks5-hostname 127.0.0.1:9050 https://example.com
```

Если в `tcpdump` видны запросы к `8.8.8.8` — утечка (нужен `socks5h`). Для SOC признаки Tor — обращения к портам 9001/9030/443 с ячейками 512 байт, запросы `.onion` в DNS, а также паттерн мостов obfs4/meek.

## Шаг 6: поднимаем собственный onion-сервис

Onion-сервис может развернуть любой — это часть сети Tor, а не что-то «тёмное». В `torrc` добавляют два параметра:

```
HiddenServiceDir /var/lib/tor/hs/
HiddenServicePort 80 127.0.0.1:8080
```

Tor создаёт каталог, ключи и файл `hostname` с твоим `.onion`-адресом:

```
$ sudo cat /var/lib/tor/hs/hostname
abcdefghijklmnopqrstuvwxyz234567abcdefghijklmnopqrstuv.onion
```

Дальше обычный веб-сервер на `127.0.0.1:8080` доступен всем, кто знает адрес, — при этом ни твой IP, ни IP клиента не раскрываются. Так в CTF и публикуют «скрытые» сервисы.

## Как устроена ячейка и handshake

Анонимность Tor — это не только маршрут, но и **формат данных**. Трафик разбит на ячейки фиксированного размера (512 байт): команда, идентификатор цепи и полезная нагрузка. Постоянный размер скрывает, сколько данных реально идёт.

Цепь строится пошагово. Клиент отправляет узел-за-узлом команду **CREATE** с материалом для общего ключа (современный handshake называется **ntor**), узел отвечает **CREATED**. Каждый узел знает ключ только со своим соседом — поэтому «снять» всю луковицу разом нельзя: нужен контроль над всеми узлами цепи.

Отсюда и наблюдаемые признаки: ровные ячейки по 512 байт, соединения к известным relay-портам (9001/9030/443) и TLS без браузерного отпечатка.

## Tor в пентесте: где полезен, а где мешает

Tor — инструмент анонимности, но в пентесте он чаще мешает, чем помогает:

- **Скорость и таймауты.** Медленные цепи и нестабильные exit-узлы рвут сканы; `nmap` через `proxychains` требует `-sT` и терпения.
- **Блокировки.** Многие цели блокируют exit-узлы Tor по спискам — получишь `403` на пустом месте.
- **Не для «внутренней» работы.** Tor анонимизирует внешний периметр; для пивота во внутреннюю сеть он не нужен.

Когда он реально нужен: доступ к `.onion`-ресурсам, обход геоблокировок, сокрытие источника при внешней разведке. Запускают так:

```
$ torsocks curl -s https://check.torproject.org/api/ip
$ proxychains4 -q nmap -sT -Pn -p80,443 target.onion
```

## Tor и другие способы анонимизации

| Способ | Модель | Слабость |
|---|---|---|
| **Tor** | распределённая цепь из 3 узлов | корреляция, медленно |
| **VPN** | один шифрованный туннель | оператор VPN видит всё |
| **VPN-цепочка** | несколько VPN подряд | доверие каждому звену |
| **I2P** | сеть внутри сети, «garlic» | меньше узлов, свой стек |

Ключевое отличие Tor — **нет единой точки доверия**: ни один узел не знает сразу «кто» и «куда». У VPN же оператор видит обе стороны целиком. Но и Tor не абсолютен: глобальный наблюдатель, контролирующий вход и выход, коррелирует поток и деанонимизирует пользователя.

## Если не сработало

- **`.onion` не открывается.** Проверь, что Tor запущен и запрос идёт через SOCKS5 (`--socks5-hostname`), а не напрямую: `.onion` резолвится только внутри Tor.
- **Соединение к guard висит.** Провайдер может блокировать порты relay — включи мосты (`obfs4`).
- **`check.torproject.org` показывает `IsTor: false`.** Трафик ушёл мимо прокси — проверь переменные `ALL_PROXY` и опцию `socks5h`.
- **Сайт отдаёт капчу/`403`.** Это блокировка exit-узла, а не ошибка настройки; попробуй другой exit (`ExitNodes`) или мост.

## Как Tor выбирает путь

Цепь не случайна. Узлы отбираются по **флагам** из consensus-документа, который Tor скачивает раз в несколько часов:

- **Guard** — узел с флагом `Guard`; выбирается на срок до нескольких месяцев, чтобы частая смена не облегчала корреляцию.
- **Exit** — узел с флагом `Exit`, разрешающий выход в обычный интернет; для `.onion`-сервисов exit не нужен вовсе.
- **Middle** — всё остальное; подходит любой узел без конфликтующих флагов.

Узлы одной цепи выбираются из **разных подсетей и разных операторов** — иначе один провайдер увидел бы сразу несколько её звеньев. Если цепь строится слишком медленно, Tor пересобирает её; если узел помечен `BadExit`, его исключают.

## Практический чек-лист

- `check.torproject.org` подтверждает использование Tor.
- DNS не утекает (проверить `tcpdump` на интерфейсе).
- Приложение полностью проксировано (`socks5h` для DNS).
- Для цензуры — мосты `obfs4`/`meek`.
- Не логиниться в личные аккаунты через Tor.
- Помнить, что Tor не спасает от корреляционных атак.
- Помнить, что exit-узлы Tor блокируются многими сайтами — нужен мост или смена выхода.
- Каждый вход в личный аккаунт через Tor — потенциальная ниточка к твоей личности.

```
$ torsocks curl https://check.torproject.org/api/ip
$ proxychains4 -q nmap -sT -Pn -p80,443 target.onion
```

## Что мы теперь знаем

- Tor строит цепь из Guard, Middle и Exit; каждый знает только соседей.
- Exit видит назначение, но не отправителя; onion-сервисы обходятся без exit.
- На проводе видно TLS к Guard и ячейки фиксированного размера.
- Onion v3 — base32 от ключа ed25519; rendezvous point соединяет обе стороны.
- Tor защищает транспортную анонимность, но не от DNS-утечек и корреляции.
- Узлы цепи выбираются по флагам Guard/Exit/Middle из consensus и из разных подсетей.
- Onion-сервис поднимается парой строк в torrc; адрес лежит в файле hostname.
