Полный PCAP дорог в хранении, поэтому на реальных сетях чаще собирают **метаданные потоков** — NetFlow/IPFIX. Они не содержат содержимого, но отвечают на ключевые вопросы: кто, куда, сколько, когда. Для SOC это основа охоты и IR, для пентестера — то, что о нём «видит» защита. Урок продолжает [`network-module-analysis`](network-module-analysis).

## Что такое поток

**Поток (flow)** — набор пакетов с общими признаками. Классический 5-tuple: **src IP, dst IP, src port, dst port, protocol**. Поток «закрывается» по таймауту или TCP-финалу. Для каждого потока считают пакеты, байты, время начала/конца, флаги.

```text
flow: 10.0.0.5:49152 -> 93.184.216.34:443 TCP
      packets=120 bytes=98304 start=12:00:01 end=12:00:40 flags=...AP...
```

## NetFlow v5/v9 и IPFIX

| Версия | Особенности |
|---|---|
| NetFlow v5 | фиксированный формат, только IPv4 |
| NetFlow v9 | шаблоны (template), IPv6, гибкость |
| IPFIX | стандарт IETF на основе v9 |
| sFlow | сэмплирование пакетов + counters |

**Экспортёр** (роутер/коммутатор) шлёт записи **коллектору** (UDP, обычно 2055/9995). v9/IPFIX используют шаблоны: сначала экспортёр присылает описание полей, потом — данные.

```bash
# Собрать NetFlow коллектором (пример: nfcapd)
nfcapd -w -D -l /var/netflow -p 2055
# Список файлов
ls /var/netflow
```

## Анализ: nfdump и SiLK

```bash
# Топ источников по объёму
nfdump -r nfcapd.202610111200 -s srcip/bytes -n 10
# Топ назначений
nfdump -r nfcapd.202610111200 -s dstip/bytes -n 10
# Фильтр по хосту
nfdump -r nfcapd.202610111200 'host 10.0.0.5'
# Фильтр по порту и объёму
nfdump -r nfcapd.202610111200 'port 443 and bytes > 1000000'
# Топ разговоров (bidirectional)
nfdump -r nfcapd.202610111200 -s record/bytes -n 20
```

SiLK — альтернативный набор утилит (`rwfilter`, `rwstats`, `rwuniq`).

```bash
# SiLK: топ отправителей
rwfilter --start-date=2026/10/11 --type=in --pass=stdout flow.rwf | rwstats --fields=sIP --top=10
```

## Что видно без PCAP

NetFlow отвечает на вопросы:

- **объём** — кто передал больше всего (эксфильтрация);
- **периодичность** — beaconing C2 (равные интервалы);
- **редкие порты** — нестандартные сервисы;
- **вертикальный скан** — много dst port с одного src;
- **горизонтальный скан** — много dst IP;
- **время активности** — «ночные» подключения.

```bash
# Beaconing: регулярные потоки к одному dst
nfdump -r nfcapd.202610111200 'dst host 203.0.113.10' | head -30
# Вертикальный скан: много dst-портов
nfdump -r nfcapd.202610111200 'src host 10.0.0.9' -s dstport/records -n 20
```

## NetFlow в расследовании

Метаданные позволяют быстро ответить на вопросы IR: «когда хост впервые связался с подозрительным IP», «сколько данных ушло», «был ли lateral movement». Полный PCAP поднимают только для нужного окна.

```bash
# Первое появление контакта
nfdump -r 'nfcapd.20261011*' 'host 10.0.0.5 and host 203.0.113.10' | head
# Объём эксфильтрации
nfdump -r 'nfcapd.20261011*' 'src host 10.0.0.5' -s dstip/bytes -n 10
```

## Обход и ограничения

- **шифрование** — содержимое невидно (только метаданные);
- **low-and-slow** — растянутая атака теряется в объёме;
- **сэмплирование (sFlow)** — часть пакетов не учитывается;
- **таймауты** — потоки агрегируются, теряются детали;
- **туннели** — внутренний трафик скрыт;
- **NAT** — адреса искажены.

## Защита и настройка

| Мера | Эффект |
|---|---|
| NetFlow/IPFIX на границах | видимость потоков |
| Хранение 30–90 дней | ретроспектива IR |
| Детект beaconing/скан | охота |
| Корреляция с IDS/DNS | контекст |
| Учёт слепых зон (шифр/туннели) | реализм |

## Частые ошибки

- **Считать NetFlow заменой PCAP** — нет содержимого.
- **Игнорировать таймауты** — потоки агрегированы.
- **Не хранить историю** — нет ретроспективы.
- **Забывать про NAT** — адреса искажены.
- **Смотреть только объём** — beaconing по периодичности.
- **Не учитывать sFlow-сэмплирование** — неполнота.
- **Не коррелировать с другими источниками** — контекст теряется.

## Практика: коллектор и анализ потоков

```bash
# Поднять коллектор (nfcapd)
mkdir -p /var/netflow
nfcapd -w -D -l /var/netflow -p 2055
# Через некоторое время — анализ
ls /var/netflow
# Топ по объёму
nfdump -r /var/netflow/nfcapd.202610111200 -s srcip/bytes -n 10
# Поиск beaconing (регулярные потоки)
nfdump -r /var/netflow/nfcapd.202610111200 -s dstip/records -n 20
# Вертикальный скан
nfdump -r /var/netflow/nfcapd.202610111200 'src host 10.0.0.9' -s dstport/records -n 20
```

## Сравнение NetFlow, IPFIX и sFlow

| Технология | Тип | Сэмплирование | Шаблоны |
|---|---|---|---|
| NetFlow v5 | экспорт | нет | фиксированный |
| NetFlow v9 | экспорт | нет | да |
| IPFIX | экспорт | нет | да (IETF) |
| sFlow | сэмплирование | да | counters + samples |

sFlow сэмплирует пакеты (например, 1 из 1000), что даёт оценку объёмов, но пропускает детали. NetFlow/IPFIX считают все пакеты потока.

## Итог по NetFlow

NetFlow/IPFIX — «телескоп» сетевого анализа: видно объём, направления, периодичность, сканы — но не содержимое. Это идеально для охоты (beaconing, эксфильтрация, lateral movement) и для быстрого IR. Ограничения: таймауты агрегируют потоки, NAT искажает адреса, шифрование/туннели скрывают детали. Комбинируйте с IDS/Zeek и PCAP для полной картины.

## IR по метаданным: практический сценарий

Представьте алерт: «хост 10.0.0.5 подозрительно активен ночью». Порядок действий по метаданным:

1. **Объём** — сколько данных ушло и куда (nfdump по srcip/bytes).
2. **Направления** — топ dst по байтам и записям.
3. **Периодичность** — равные интервалы к одному dst (beaconing).
4. **Редкие порты** — нестандартные назначения.
5. **Первое появление** — когда впервые связался с подозрительным IP.
6. **Lateral movement** — внутренние соединения к другим хостам.

```bash
# 1-2. Объём и направления
nfdump -r nfcapd.20261011* 'src host 10.0.0.5' -s dstip/bytes -n 10
# 3. Периодичность к конкретному dst
nfdump -r nfcapd.20261011* 'host 10.0.0.5 and host 203.0.113.10' | head -40
# 4. Редкие порты
nfdump -r nfcapd.20261011* 'src host 10.0.0.5' -s dstport/records -n 20
# 6. Внутренние соединения
nfdump -r nfcapd.20261011* 'src host 10.0.0.5 and dst net 10.0.0.0/8'
```

Так за минуты строится картина инцидента без хранения полного PCAP. PCAP поднимают лишь для окна, где нужно содержимое. Этот же метод помогает пентестеру понять, какие его действия «светятся» в мониторинге, и спланировать менее заметные (если это в рамках задачи).

## Итоговый вывод

NetFlow превращает горы пакетов в компактные метаданные, по которым восстанавливается поведение хоста: объём, периодичность, направления, сканы. Это основа охоты и IR, дополняющая IDS/Zeek и PCAP.

## Сравнение с другими источниками видимости

| Источник | Что даёт | Слепая зона |
|---|---|---|
| NetFlow/IPFIX | объём, направления, периодичность | содержимое |
| PCAP | всё содержимое | TLS, объём хранения |
| IDS/Zeek | алерты и события | неинспектируемый трафик |
| DNS-логи | имена и частоты | DoH/DoT |
| TLS-метаданные | SNI, JA3, сертификаты | ECH |

NetFlow не заменяет PCAP, а дополняет его. В паре они дают и «где», и «что». Для beaconing и эксфильтрации метаданных достаточно; для содержимого — поднимают PCAP по окну.

## Итоговый вывод

NetFlow — самый масштабируемый источник видимости. Он дешёв в хранении и отвечает на большинство вопросов охоты: объём, периодичность, направления, сканы. Его ограничения (нет содержимого, агрегация, NAT, шифр) компенсируются корреляцией с PCAP, IDS и DNS. Для SOC это основа ретроспективы, для пентеста — то, что о нём «знает» защита.
