Канальный уровень (L2) — фундамент локальной сети: коммутаторы строят таблицу MAC (CAM) и запускают STP против петель. Ошибки в этих механизмах позволяют перехватить трафик, вывести сеть из строя или выйти за пределы сегмента. Урок опирается на [`network-mitm`](network-mitm) и [`network-arp-deep`](network-arp-deep).

## Как коммутатор принимает решения

Коммутатор — устройство L2, которое учится и пересылает кадры по **MAC-адресам**. Три ключевые подсистемы:

- **CAM-таблица** (Content-Addressable Memory) — соответствие `MAC → порт`. Ограничена по размеру (типично 8k-128k записей).
- **STP/RSTP** — Spanning Tree Protocol, устраняет петли: выбирает один **корневой мост** (root bridge), а на остальных портах блокирует передачу.
- **Forwarding logic** — если MAC получателя известен, кадр идёт в один порт; если нет (unknown unicast) или это broadcast/multicast — **во все порты**, кроме входного.

Именно эта последняя логика делает L2 уязвимым: заставив коммутатор «забыть» адрес, вы превращаете его в хаб, транслирующий всё всем.

## STP и захват корневого моста

STP выбирает корневой мост по наименьшему **Bridge ID** = приоритет (2 байта, по умолчанию 32768) + MAC-адрес. Атакующий присылает BPDU с приоритетом **0** и своим MAC — становится корнем, после чего трафик сегмента идёт через него, и он его видит.

```bash
# Инструмент: yersinia (STP mode)
yersinia stp -attack 4 -interface eth0     # захват корневого моста
# Наблюдение
tcpdump -i eth0 -n -e stp
```

Приоритет 0 гарантированно «выигрывает» любой легитимный мост. После захвата корня атакующий может и перехватывать, и **выводить сеть из строя**, периодически «дёргая» топологию. Защита: **BPDU Guard** (отключает access-порт при получении BPDU — там BPDU быть не должно), **Root Guard** (запрещает порту принимать превосходящие BPDU, оставляя корнем легитимный мост).

## MAC-flooding (переполнение CAM)

Коммутатор учит `MAC → порт` в **CAM-таблице** ограниченного размера. Если её переполнить поддельными MAC, новые записи не помещаются, коммутатор перестаёт различать порты и **флудит кадры во все порты** — как хаб. Тогда атакующий видит весь трафик сегмента, не выполняя ARP-спуфинг.

```bash
# macof из dsniff: генерирует тысячи кадров со случайными MAC
macof -i eth0 -n 100000
# Наблюдение: CAM переполнена
# (на Cisco: show mac address-table count)
```

`macof` шлёт кадры со случайными source-MAC на случайные адреса, быстро заполняя таблицу. Защита: **port security** (лимит MAC на порт, sticky, violation shutdown) и **storm control** (ограничение broadcast/unknown-unicast).

## Port security и его обход

Port security ограничивает число MAC на порту (например, `maximum 1`). Обходы:

- **Разрешить один MAC** — атакующий просто **спуфит** разрешённый MAC (узнав его через `tcpdump`).
- **Sticky MAC** — MAC обучаются динамически; можно занять «место» первым, пока легитимное устройство отключено.
- **Violation protect/restrict/shutdown** — при `shutdown` атакующий может **DoS-ить** легитимные порты, отправляя кадры с чужими MAC.

## Инструменты и команды

```bash
# dsniff-набор
macof -i eth0                 # CAM-flooding
arpspoof -i eth0 -t A B       # ARP-спуфинг
# yersinia — атаки на L2-протоколы
yersinia -I                    # интерактивный режим
yersinia stp -attack 4
yersinia dtp -attack 1         # DTP (для VLAN hopping)
yersinia dhcp -attack 1        # rogue DHCP
# Scapy для кастомных кадров
python3 - <<'PY'
from scapy.all import *
sendp(Ether(src=RandMAC(),dst="ff:ff:ff:ff:ff:ff")/ARP(op=2,psrc="10.0.0.1",pdst="10.0.0.5"), iface="eth0", loop=1)
PY
```

## Разобранный пример: CAM-flood → перехват

```bash
# 1. Переполняем CAM
macof -i eth0 -n 50000
# 2. Включаем перехват
tcpdump -i eth0 -n -w flood.pcap
# 3. Ищем интересное
tshark -r flood.pcap -Y 'http.request' -T fields -e http.host -e http.request.uri
# 4. Параллельно можно поднять ARP-спуфинг для надёжности
```

Флудинг даёт «широкий, но шумный» захват: вы видите кадры всех хостов сегмента. Комбинация с ARP-спуфингом («узкий, но точный») делает перехват стабильным.

## VLAN hopping

Выход за пределы своего VLAN — отдельный класс L2-атак:

- **Switch spoofing (DTP)**: атакующий притворяется коммутатором и договаривается о **trunk**-порту (DTP), получая трафик всех VLAN. Защита: `switchport nonegotiate`, отключить DTP.
- **Double tagging (802.1Q)**: кадр с двумя тегами — внешний (native VLAN) снимается первым коммутатором, внутренний доставляется в чужой VLAN. Защита: сменить native VLAN, не использовать VLAN 1.
- **Native VLAN mismatch** — эксплуатируется в double tagging.

```bash
# Проверить, отвечает ли порт на DTP
yersinia dtp -attack 1 -interface eth0
# Double tagging (scapy)
# sendp(Dot1Q(vlan=native)/Dot1Q(vlan=target)/Ether(...)/IP(...))
```

## Обход port security и NAC

- **Спуфинг разрешённого MAC** — если порт привязан к одному MAC.
- **Sticky MAC** — занять «место» первым или дождаться очистки.
- **802.1X**: MAB (MAC Authentication Bypass) — подмена MAC разрешённого устройства; hub-порты; EAP-даунгрейд.
- **VoIP VLAN** — телефон аутентифицируется, а ПК за ним может пройти.

## Практическая последовательность

1. Разведка: `tcpdump -e` — увидеть теги, DTP, CDP/LLDP.
2. DTP-атака или double tagging для выхода в целевой VLAN.
3. MAC-flooding/ARP-спуфинг внутри нового сегмента.
4. Обход NAC при необходимости.
5. Захват/движение дальше.

## Мониторинг и детект

- Всплеск **DTP/STP BPDU** с access-портов.
- **Смена корневого моста** (топология «прыгает»).
- **Один порт — много MAC** (flooding).
- **CDP/LLDP** от не-коммутатора.
- Аллерты на `err-disable` (port security violation).

## Резюме защит

| Атака | Защита |
|-------|--------|
| STP root takeover | BPDU Guard, Root Guard |
| MAC-flooding | port security, storm control |
| DTP/VLAN hopping | disable DTP, change native VLAN |
| NAC bypass | 802.1X + MAB-политики, не доверять MAC |
| ARP/DHCP | DAI + DHCP snooping |

## Частые ошибки

- **Думать, что коммутатор всегда «умный»** — при переполнении он флудит.
- **Забывать про port security violation** — `shutdown` можно использовать для DoS.
- **Путать STP-атаку и ARP-спуфинг** — разные уровни/механизмы.
- **Спуфить разрешённый MAC** — обход port security одной строкой.
- **Не включать storm control** — CAM-flood может «уронить» сеть.
- **Игнорировать BPDU Guard** — без него захват корня тривиален.

## Что дальше / решение

Маршрут: **разведка L2 (`tcpdump -e`) → выход в целевой VLAN (DTP/double tagging) → MAC-flooding или ARP-спуфинг для перехвата → обход NAC → движение дальше**. Защита строится на связке BPDU Guard + Root Guard + port security + storm control + DAI/DHCP snooping + 802.1X. Дальше — [`network-vlan-hopping`](network-vlan-hopping), [`network-arp-deep`](network-arp-deep) и [`network-nac-bypass`](network-nac-bypass).

## STP глубже: типы BPDU, таймеры и RSTP

Классический STP (802.1D) и RSTP (802.1w) отличаются скоростью сходимости и типами BPDU. В STP BPDU рассылаются каждые 2 секунды от корня; в RSTP используется механизм proposal/agreement, и сходимость занимает доли секунды. Для атакующего это значит: в RSTP корневой мост можно захватить почти мгновенно, а «дёрганье» топологии (периодическая смена корня) вызывает быстрые перестройки и всплески потерь. Полезные таймеры STP: Hello (2 с), Max Age (20 с), Forward Delay (15 с). Понимание таймеров помогает и в атаке (когда ждать сходимости), и в защите (как быстро BPDU Guard среагирует).

Ещё один вектор — **BPUD DoS**: поток BPDU с приоритетом 0 заставляет коммутатор постоянно пересчитывать топологию, загружая CPU и вызывая микропотери. Это уже не перехват, а отказ в обслуживании.

## CDP и LLDP как источник разведки

Перед атакой L2 разведайте топологию через служебные протоколы. **CDP** (Cisco) и **LLDP** (открытый стандарт) объявляют имя устройства, модель, версию IOS, VLAN и даже адрес управления. `tcpdump -nn -v -i eth0 -s1500 -c1 'ether proto 0x88cc'` покажет LLDP-кадры, а `tcpdump -nn -v -s1500 -c1 'ether[20:2] == 0x2000'` — CDP. Из одного кадра можно узнать модель коммутатора, его управляющий IP и native VLAN — это резко упрощает планирование VLAN hopping и выбор эксплойта под конкретную прошивку. Защита — отключить CDP/LLDP на портах доступа (или ограничить их).

## Storm control, err-disable и почему DoS прост

**Storm control** ограничивает долю broadcast/multicast/unknown-unicast на порту; при превышении порт уходит в **err-disable** (отключается). Парадокс: сам storm control можно превратить в вектор DoS — отправив поток broadcast, вы заставляете коммутатор отключить порт, и легитимный пользователь теряет связь. Аналогично **port security violation shutdown** отключает порт при превышении числа MAC. Отсюда практическое правило защиты: использовать `restrict`/`protect` (с логированием) вместо `shutdown` там, где DoS критичен, и настраивать авто-восстановление (`errdisable recovery`).

## L2-атаки в контексте пентеста и CTF

На CTF L2-задачи обычно дают «плоский» сегмент с коммутатором и просят перехватить трафик между хостами. Порядок: разведка (`tcpdump -e`, CDP/LLDP) → ARP-спуфинг (проще всего) → при защите от спуфинга — MAC-flooding → при VLAN-изоляции — DTP/double tagging. В реальном пентесте L2-доступ часто означает компрометацию «порта в переговорной» и цель выйти из гостевого VLAN в корпоративный. Помните: активные L2-атаки могут «уронить» сеть и заметны — согласуйте их с заказчиком и держите план отката.
