## Вопрос, с которого всё начинается

В корпоративной сети стоят IP-телефоны. Они общаются по протоколам SIP и RTP — и, если не настроено шифрование, весь разговор может лежать в дампе открытым текстом. Как это выглядит и что из этого можно извлечь?

Разберём на конкретном примере: один звонок между двумя телефонами.

## Наш пример: телефон звонит другому

Пусть телефон `10.0.0.50` (абонент `1001`) звонит телефону `10.0.0.30` (абонент `1002`). SIP работает по **UDP/5060** (или TCP/5060). Первое, что уходит в сеть, — сообщение **INVITE**.

Поймаем его:

```
$ tshark -r sip.pcap
    1  0.000000  10.0.0.50 → 10.0.0.30  SIP 296 Request: INVITE sip:1002@10.0.0.30 |
```

`INVITE` — это приглашение начать сессию. Разберём содержимое.

```
$ tshark -r sip.pcap -V | grep -iE "Request-Line|From:|To:|Call-ID|CSeq|Contact"
    Request-Line: INVITE sip:1002@10.0.0.30 SIP/2.0
    From: <sip:1001@10.0.0.50>;tag=abc
    To: <sip:1002@10.0.0.30>
    Call-ID: 1234@10.0.0.50
    CSeq: 1 INVITE
    Contact: <sip:1001@10.0.0.50>
```

SIP — текстовый протокол, похожий на HTTP. Разберём поля:

- **From / To** — кто звонит и кому (номера `1001` → `1002`);
- **Call-ID** — уникальный идентификатор звонка, объединяет все сообщения сессии;
- **CSeq** — номер и метод команды по порядку;
- **Contact** — куда отвечать (адрес устройства).

Всё это **открытым текстом**: кто кому звонил и когда — видно без пароля.

## Шаг 1: диалог установки звонка

Дальше идёт стандартная последовательность:

1. `100 Trying` — «запрос принят, ищу абонента»;
2. `180 Ringing` — «у него идут гудки»;
3. `200 OK` — «он ответил»;
4. `ACK` — подтверждение.

Коды ответов напоминают HTTP (`180`, `200`, `404` = «абонент не найден»). По этому диалогу можно даже **подсчитать звонки** и построить граф, кто с кем общается, — без прослушки.

## Шаг 2: где же сам голос — RTP

Голос идёт **не по SIP**, а по отдельному протоколу **RTP** (Real-time Transport Protocol), обычно по UDP с динамическими портами (часто 10000–20000). Параметры RTP (адрес, порт, кодек) согласуются в SIP-сообщении через **SDP** (Session Description Protocol) — текстовый блок внутри INVITE/200 OK.

Посмотрим, что там:

```
$ tshark -r sip.pcap -V | grep -iE "Media Attribute|Media Description|Connection Information"
    Media Description: audio 40000 RTP/AVP 0
    Connection Information: 10.0.0.50
```

Здесь `audio 40000 RTP/AVP 0` означает: голос пойдёт на порт `40000`, профиль `RTP/AVP`, а кодек `0` — это **PCMU/G.711** (несжатый, 64 кбит/с). Именно эта строка говорит, куда смотреть за голосом.

## Шаг 3: восстановление разговора из PCAP

Если RTP не шифрован, аудио можно собрать обратно в `.wav`. Инструмент `rtpcap`/`rtpdump` или встроенная функция Wireshark (`Telephony → RTP → Show all streams → Play/Export`) делают это.

Логика простая: RTP-пакеты несут маленькие кусочки аудио с **последовательным номером** (sequence number) и **таймстампом**. Собрав их по порядку и склеив, получаем разговор.

```
$ tshark -r call.pcap -q -z rtp,streams
Stream  Payload  Packets  Lost  Jitter  Start  Duration
   1    PCMU     1520      0    0.4ms  12.3s   24.5s
```

Отсюда видно: 1520 пакетов, кодек PCMU, длительность ~24 секунды. Экспорт в wav — и вот запись звонка, который никто не шифровал.

## Шаг 4: атаки на регистрацию

Телефон должен **зарегистрироваться** на сервере (SIP REGISTER), предъявив логин и пароль (обычно через **digest-аутентификацию**, похожую на HTTP). Если пароль слабый или трафик не шифрован, возможны:

- **Перехват пароля** — если аутентификация прошла по незашифрованному каналу, её можно собрать и подбирать оффлайн;
- **Регистрация чужого устройства** — зная учётку, зарегистрировать свой софтфон под номером жертвы и принимать её звонки;
- **SIP-скан** — перебор расширений/учёток небольшим списком.

## Шаг 5: toll fraud — кража денег на звонках

Самая дорогая атака — **toll fraud**. Получив доступ к SIP-аккаунту, злоумышленник совершает звонки на платные международные номера. Счёт приходит компании. Схема часто автоматизируется: скомпрометированный аккаунт используют как «провайдера» для тысяч вызовов за ночь.

Это не про «прослушку», а про **злоупотребление доверием** — классическая бизнес-логика на уровне инфраструктуры.

## Шаг 6: защита

- **Шифрование сигнализации** — SIP over TLS (порт 5061), **SRTP** для голоса.
- **Сложные пароли и MFA** для SIP-учёток, запрет «дефолтных» экстеншенов.
- **Сегментация** — телефония в отдельном VLAN, с ACL.
- **Мониторинг:** аномальные исходящие направления (международные), всплеск REGISTER, звонки в нерабочее время — сигналы toll fraud.
- **Отключить лишние сервисы** (TFTP-провижининг с паролями в открытом виде).

Для SOC полезно помнить: VoIP-трафик по умолчанию **не** шифруется во многих старых установках, поэтому запись разговоров — реальная, а не теоретическая угроза.

## Шаг 7: мини-практика — находим звонок в дампе

Покажем процедуру поиска VoIP в незнакомом дампе. Первый шаг — найти SIP-трафик:

```
$ tshark -r big.pcap -Y "sip" | head
    1  0.000000  10.0.0.50 → 10.0.0.30  SIP 296 Request: INVITE sip:1002@10.0.0.30 |
    3  0.012000  10.0.0.30 → 10.0.0.50  SIP 401 Status: 100 Trying |
```

По наличию INVITE и последующих кодов видно, что был звонок. Затем ищем **SDP** внутри INVITE, чтобы узнать порт RTP:

```
$ tshark -r big.pcap -Y "sdp" -T fields -e sdp.media.port
40000
```

Теперь у нас есть порт `40000`, на котором лежит голос. Дальше фильтруем RTP и экспортируем:

```
$ tshark -r big.pcap -Y "rtp" -w rtp_only.pcap
$ tshark -r rtp_only.pcap -q -z rtp,streams
```

Осталось открыть `rtp_only.pcap` в Wireshark и через `Telephony → RTP → Stream Analysis` воспроизвести или экспортировать аудио. Вся цепочка — от «есть SIP» до «слышу разговор» — занимает несколько минут, если трафик не зашифрован.

## Шаг 8: инъекция SIP и подделка звонков

SIP-сообщения можно не только читать, но и **подделывать**. Классические векторы:

- **BYE-инъекция.** Зная `Call-ID` из открытого дампа, можно послать `BYE` от имени одной из сторон и оборвать чужой звонок.
- **Спуфинг INVITE.** Отправить приглашение от чужого номера — жертва увидит «звонок от директора» (vishing/фрод).
- **Фальшивый 200 OK.** Подменить ответ, чтобы звонок пошёл не туда.

Инъекция BYE в Scapy-стиле выглядит так (концептуально):

```python
payload = (
    "BYE sip:1002@10.0.0.30 SIP/2.0\r\n"
    "Via: SIP/2.0/UDP 10.0.0.50:5060\r\n"
    "From: <sip:1001@10.0.0.50>;tag=abc\r\n"
    "To: <sip:1002@10.0.0.30>\r\n"
    "Call-ID: 1234@10.0.0.50\r\n"
    "CSeq: 2 BYE\r\n\r\n"
)
send(IP(src="10.0.0.50", dst="10.0.0.30")/UDP(sport=5060, dport=5060)/payload)
```

Защита — аутентификация сообщений внутри диалога и TLS, иначе любой, кто видит трафик, может вмешаться.

## Шаг 9: детект VoIP-аномалий (для SOC)

Защитнику важно ловить не только прослушку, но и злоупотребления. Практичные фильтры:

- **Всплеск REGISTER** — перебор учёток:
```
$ tshark -r big.pcap -Y 'sip.Method=="REGISTER"' -T fields -e ip.src | sort | uniq -c | sort -rn | head
```
- **Неуспешные ответы** (`401`/`403`/`404`) от одного источника — признак перебора:
```
$ tshark -r big.pcap -Y 'sip.Status-Code>=400' | wc -l
```
- **Необычные направления** — звонки на международные префиксы в нерабочее время (toll fraud).

Ровный поток REGISTER от одного IP с множеством ошибок — почти всегда автоматизированный подбор.

## Где прячется голос: типовые кодеки

Кодек из SDP определяет и полосу, и то, как звук лежит в RTP. Частые варианты:

| Payload | Кодек | Полоса | Восстановление |
|---|---|---|---|
| 0 | PCMU (G.711u) | 64 кбит/с | прямая склейка |
| 8 | PCMA (G.711a) | 64 кбит/с | прямая склейка |
| 9 | G.722 | 64 кбит/с | нужен кодек |
| 101 | telephone-event | — | DTMF-цифры! |

`telephone-event` (payload 101) — это **DTMF-сигналы**: нажатия клавиш, которые абонент вводит (номера карт, PIN). Их часто видно отдельным потоком и можно расшифровать в цифры — прямой путь к чувствительным данным без полного аудио.

## Что мы теперь знаем

- SIP — текстовый протокол сигнализации по UDP/TCP 5060; голос идёт отдельно по RTP.
- Из SIP видно, кто, кому и когда звонил (From/To/Call-ID).
- SDP внутри SIP указывает адрес, порт и кодек RTP.
- Незашифрованный RTP можно собрать обратно в аудиофайл.
- Атаки: перехват регистрации, подмена устройства, toll fraud.
- Защита — TLS/SRTP, сильные пароли, сегментация, мониторинг.
- SIP-сообщения можно подделать: BYE обрывает чужой звонок, INVITE спуфит звонящего.
- DTMF (telephone-event, payload 101) выдаёт введённые цифры — PIN, номера карт.
- Детект перебора — всплеск REGISTER и ответы 4xx от одного IP.
- Голос идёт по RTP на динамических портах (10000–20000), не по 5060.
- SRTP шифрует медиа; если видишь только SIP без RTP — голос зашифрован.
- Из SIP видно, кто кому звонил и когда — даже без прослушки.
- Триада Call-ID / CSeq / tag связывает сообщения одной сессии.
- Защита голоса — TLS (5061) + SRTP, а не смена порта.
