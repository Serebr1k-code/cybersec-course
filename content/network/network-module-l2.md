Этот модуль собирает всё, что происходит **до IP**: как выглядит кадр Ethernet, как коммутатор принимает решения по MAC, как работают VLAN и протоколы дерева (STP), и как сеть сама рассказывает о себе через LLDP/CDP. Без понимания L2 невозможно ни корректно перехватить трафик, ни объяснить, почему VLAN hopping или MAC-flooding вообще работают. Модуль опирается на [`network-layer2-attacks`](network-layer2-attacks) и [`network-vlan-hopping`](network-vlan-hopping) и ведёт к практическим урокам `network-ethernet`, `network-stp-deep`, `network-vlan-qinq`, `network-lldp-cdp`.

## Зачем отдельный модуль по L2

Большинство «сетевых» атак на внутреннем периметре начинается с уровня 2: ARP-спуфинг, переполнение CAM-таблицы, захват корневого моста STP, двойное тегирование VLAN. Все они опираются на одну и ту же модель — **коммутатор учится по источнику и пересылает по назначению**. Если вы понимаете эту модель, вы видите и атаку, и защиту.

Второй повод — **диагностика**. Когда «сеть не работает», а ping молчит, причина часто на L2: петля без STP, неверный native VLAN, порт в err-disable после port-security. Умение читать кадры и состояние коммутатора экономит часы.

Третий — **разведка**. Протоколы discovery (LLDP, CDP) и таблица MAC сами раскрывают топологию: какие модели коммутаторов стоят, сколько VLAN, кто к какому порту подключён.

## Кадр Ethernet: что видит коммутатор

Классический Ethernet II кадр:

```text
+----------------+----------------+--------+-------------------------+-------+
| Dst MAC (6)    | Src MAC (6)    | Type   | Payload (46-1500)       | FCS 4 |
+----------------+----------------+--------+-------------------------+-------+
```

- **Dst MAC** — кому. `ff:ff:ff:ff:ff:ff` = broadcast, старший бит первого байта = multicast.
- **Src MAC** — от кого; по нему коммутатор **учится** (MAC → порт).
- **Type/Length** — `0x0800` (IPv4), `0x0806` (ARP), `0x86DD` (IPv6), `0x8100` (802.1Q VLAN), `0x8847` (MPLS).
- **FCS** — контрольная сумма; коммутатор отбрасывает битые кадры.

Минимальный кадр — 64 байта (иначе padding), максимальный полезный размер — 1500 байт (MTU), jumbo — до 9000.

```bash
# Показать MAC-адреса и типы в реальном времени
tcpdump -i eth0 -e -nn -c 10
# -> 12:34:56:aa:bb:cc > 12:34:56:dd:ee:ff, ethertype IPv4 (0x0800), length 74
```

## Как коммутатор принимает решения

Коммутатор хранит **CAM-таблицу** (Content-Addressable Memory): MAC → порт → возраст. Алгоритм:

1. Пришёл кадр — запомнить `Src MAC` и порт входа (learning).
2. Посмотреть `Dst MAC`:
   - есть в таблице → отправить в один порт (forward);
   - нет → **flood** во все порты, кроме входного (unknown unicast);
   - broadcast/multicast → flood всегда.
3. Если Dst MAC = порт входа → **фильтрация** (drop, не пересылать обратно).

Эта модель — корень всех L2-атак: если переполнить CAM (macof), таблица «поплывёт», и коммутатор начнёт flood-ить всё, превращаясь в hub — тогда снифер видит чужой трафик.

```bash
# Посмотреть CAM/MAC-таблицу на Cisco
show mac address-table
# Linux bridge
bridge fdb show
```

## VLAN: логическая сегментация

VLAN делит один физический коммутатор на несколько логических L2-доменов. Кадры между VLAN не ходят без L3-устройства. Тегирование — стандарт **802.1Q**:

```text
+--------+--------+--------+---------+----------------+
| Dst MAC| Src MAC| 0x8100 | TCI/PCP | Type  | ...    |
+--------+--------+--------+---------+----------------+
                           | VLAN ID (12 бит) + PCP(3)
```

- **Access-порт** — трафик без тега (VLAN назначается портом).
- **Trunk-порт** — несёт несколько VLAN с тегами.
- **Native VLAN** — на trunk-порту трафик без тега; классический вектор атаки, если native не совпадает.

Двойное тегирование (**QinQ**, 802.1ad) добавляет второй тег — подробности в `network-vlan-qinq`.

```bash
# Создать tagged-интерфейс и посмотреть теги
sudo ip link add link eth0 name eth0.100 type vlan id 100
sudo ip link set eth0.100 up
tcpdump -i eth0 -e -nn vlan
```

## STP/RSTP/MSTP: защита от петель

Коммутаторы не имеют TTL: кадр в петле зацикливается навсегда и убивает сеть (broadcast storm). **Spanning Tree Protocol** строит дерево без петель:

- выбирается **Root Bridge** (по минимальному Bridge ID = priority + MAC);
- каждый коммутатор выбирает **Root Port** (лучший путь к root) и блокирует избыточные порты (Blocking/Discarding);
- BPDU-кадры (Bridge Protocol Data Unit) ходят каждые 2 секунды.

| Протокол | Сходимость | Особенности |
|---|---|---|
| STP (802.1D) | 30–50 с | один инстанс, медленно |
| RSTP (802.1w) | < 1 с | быстрые роли, edge-порты |
| MSTP (802.1s) | < 1 с | несколько инстансов, mapping VLAN→instance |
| PVST+ | < 1 с | по инстансу на VLAN (Cisco) |

Атака: вбросить BPDU с минимальным priority и стать root — трафик пойдёт через атакующего. Подробно — в `network-stp-deep`.

```bash
# Отправить «агрессивные» BPDU (лаборатория)
sudo tcpreplay --intf1=eth0 bpdu_root.pcap
```

## LLDP и CDP: сеть рассказывает о себе

- **LLDP** (802.1AB) — вендоронезависимый: отправляет имя устройства, порт, VLAN, capabilities.
- **CDP** (Cisco) — проприетарный аналог, болтливый: модель, IOS-версия, management IP, native VLAN.

Оба протокола — **золото для разведки** и одновременно утечка: по ним видно топологию, версии ПО и адреса. Подробности — в `network-lldp-cdp`.

```bash
# Захватить LLDP/CDP
sudo tcpdump -i eth0 -nn -v -c 5 'ether proto 0x88cc or ether proto 0x2000'
```

## Как читать L2-трафик: практический конвейер

```bash
# 1. Кто вообще в сегменте (ARP + MAC)
sudo arp-scan --interface=eth0 --localnet
# 2. MAC-таблица и порты (если есть доступ к коммутатору)
show mac address-table
# 3. VLAN-теги в дампе
tcpdump -i eth0 -e -nn vlan | head
# 4. Топология через LLDP/CDP
sudo tcpdump -i eth0 -nn -v -c 20 'ether[12:2] == 0x88cc or ether[12:2] == 0x2000'
# 5. Поиск петель/штормов
tcpdump -i eth0 -nn 'broadcast' -c 100 | wc -l
```

Читать L2-дамп удобнее всего в Wireshark: он раскрывает VLAN-теги, LLDP TLVs и STP-поля человекочитаемо. Для скриптов — `tshark -T fields`.

## Типовые ошибки

- **Считать, что «L2 не важен»** — почти все внутренние атаки начинаются здесь.
- **Путать access и trunk** — отсюда неверные выводы про видимость трафика.
- **Игнорировать native VLAN** — классический канал для VLAN hopping.
- **Забывать про FCS/MTU** — «битые» кадры коммутатор молча дропает.
- **Смотреть только IP-фильтром** в tcpdump — STP/LLDP/ARP невидимы.
- **Верить, что STP всегда включён** — на многих портах (edge) его выключают, и петля мгновенна.
- **Забывать про storm control / port security** — атаки, работающие в лабе, могут дать err-disable в продакшене.

## Коммутация и маршрутизация: где проходит граница

Коммутатор работает в пределах одного broadcast-домена (VLAN) и принимает решения по **MAC**. Маршрутизатор разделяет домены и принимает решения по **IP**. Граница важна для анализа: ARP-трафик, STP, LLDP и VLAN-теги видны только на L2 и не пересекают L3-границу. Когда вы видите в дампе только IP, значит вы уже за маршрутизатором или порт настроен как access к одному сегменту.

Промежуточное звено — **multilayer switch (L3 switch)**: он коммутирует внутри VLAN и маршрутизирует между ними, часто на скорости провода. Для пентеста это означает, что «прыжок» между VLAN через L3 требует либо доступа к самому SVI, либо уязвимости в ACL.

## Таблица MAC и ageing

CAM-запись живёт ограниченное время (по умолчанию 300 секунд на Cisco, 5 минут на многих коммутаторах). Пока по адресу идёт трафик, таймер сбрасывается. Как только хост замолчал, запись удаляется, и коммутатор снова флудит неизвестный unicast.

Из этого следуют практические выводы:

- **Тихий хост теряется** из таблицы, и трафик к нему временно флудится — это шанс для снифера.
- **Переполнение таблицы** (macof) вытесняет легитимные записи и превращает коммутатор в hub.
- **Статическая привязка** MAC↔порт (port security) защищает от подмены и переполнения.

```bash
# Размер и возраст MAC-таблицы на Linux-бридже
bridge fdb show br br0 | wc -l
bridge fdb show br br0 | head
```

## Лабораторный стенд для практики

Для отработки L2 удобно собрать стенд из виртуальных машин, соединённых Linux-бриджем:

```bash
# Создать bridge и два tap-интерфейса
sudo ip link add br0 type bridge
sudo ip tuntap add tap1 mode tap
sudo ip tuntap add tap2 mode tap
sudo ip link set tap1 master br0
sudo ip link set tap2 master br0
sudo ip link set br0 up
# Теперь VM на tap1/tap2 видят друг друга через bridge
```

На этом стенде можно воспроизвести MAC-flooding, ARP-спуфинг, VLAN hopping и захват STP, не рискуя реальной сетью. Wireshark на `br0` покажет весь обмен, включая broadcast и discovery-кадры.
