## Вопрос, с которого всё начинается

Светофоры, динамические табло на дорогах и заградительные шлагбаумы управляются контроллерами, которые общаются по **NTCIP** — семейству стандартов для транспортных систем (ITS). В основе лежит знакомый SNMP. Значит, приёмы те же — а последствия серьёзнее, чем в обычной сети.

## Наш пример: опрос контроллера

Достаём состояние фаз светофора через SNMP:

```
$ snmpwalk -v2c -c public 10.0.0.60 1.3.6.1.4.1.1206.4.2.1.1.1
iso.3.6.1.4.1.1206.4.2.1.1.1.4.0 = INTEGER: 2
```

Мы прочитали объект по OID и получили число 2. Что это за дерево OID и что означает значение — разберём по шагам.

## Шаг 1: что такое NTCIP

NTCIP (National Transportation Communications for ITS Protocol) — набор стандартов для взаимодействия устройств транспортной инфраструктуры: контроллеров светофоров, табло, детекторов, метеостанций. Он определяет не только сообщения, но и **словарь объектов** — какие параметры есть у устройства и как их читать.

Ключевая идея: устройство представляется набором объектов, к которым обращаются по OID. Это делает NTCIP расширяемым и предсказуемым — как SNMP, на котором он и построен.

## Шаг 2: SNMP как транспорт

Большинство профилей NTCIP используют SNMP (UDP 161/162) с общей MIB. Ветка `1.3.6.1.4.1.1206` — это частное предприятие (PEN) NTCIP. Внутри — группы: глобальные, конфигурация, статус, управление.

```
$ snmpwalk -v2c -c public 10.0.0.60 1.3.6.1.4.1.1206 | head
iso.3.6.1.4.1.1206.4.2.1.1.1.1.0 = INTEGER: 1
iso.3.6.1.4.1.1206.4.2.1.1.1.2.0 = INTEGER: 0
iso.3.6.1.4.1.1206.4.2.1.1.1.3.0 = INTEGER: 0
```

`snmpwalk` проходит дерево и печатает объекты. Читая их, ты понимаешь состояние устройства.

## Шаг 3: SNMP-версии и сообщества

Как и в обычном SNMP, безопасность держится на «community string». Версия 1/2c передаёт её открыто, и по умолчанию это часто `public` (чтение) и `private` (запись). Версия 3 умеет аутентификацию и шифрование, но в legacy-контроллерах её часто нет.

Практический вывод: если контроллер отвечает на `public`, ты читаешь всё состояние. Если он принимает `private` для записи — ты можешь им управлять.

## Шаг 4: STMP — компактный вариант

Для узких каналов NTCIP определяет **STMP** (Simple Transportation Management Protocol) — облегчённый аналог SNMP. Он экономит байты и используется на медленных линиях. С точки зрения безопасности принцип тот же: нет аутентификации по умолчанию, значит, есть чтение и запись.

## Шаг 5: опасность set

Вот где NTCIP отличается от «обычной» сети. Объекты управления позволяют менять **режим работы** контроллера: длительность фаз, планы координации, состояние табло. Команда set способна изменить поведение светофора.

```
$ snmpset -v2c -c private 10.0.0.60 1.3.6.1.4.1.1206.4.2.1.1.1.4.0 i 1
```

**Этот пример приведён исключительно для понимания механики.** Выполнять такие команды на реальной дорожной инфраструктуре нельзя — это создаёт угрозу жизни. Все эксперименты — только на изолированном лабораторном стенде или симуляторе (например, в учебном эмуляторе контроллера).

## Шаг 6: анализ дампа

Если у тебя есть перехват, ищи в нём SNMP-пакеты к контроллерам:

```
$ tshark -r its.pcap -Y "snmp" -T fields -e ip.src -e snmp.community -e snmp.request_id
10.0.0.10  public  12345
```

Видно, кто опрашивает контроллер и с каким community. Если community `public`/`private` — это находка: слабая аутентификация. Обрати внимание на `set`-запросы (PDU type 3): они означают, что кто-то меняет параметры.

## Шаг 7: защита

Что должно быть сделано: переход на SNMPv3 с аутентификацией и шифрованием, смена community (или отказ от v1/2c), ACL по IP на доступ к 161, изоляция контроллеров в отдельный сегмент, запрет set с управляющих станций, где это не нужно. И мониторинг set-операций как аномалий.

## Что мы теперь знаем

- NTCIP — стандарт для дорожной инфраструктуры на базе SNMP.
- Устройство — набор объектов по OID; есть STMP для узких каналов.
- Community `public`/`private` — типичная слабость.
- set-команды меняют режим работы контроллера и опасны на реальных объектах.

## Если не сработало

Если SNMP не отвечает — проверь community и версию (`-v2c`). Если порт закрыт — контроллер может быть за шлюзом. Если объекты «неизвестны» — нужна MIB NTCIP; `snmpwalk` и так покажет числовые OID. Если идёт STMP — SNMP-диссектор его не покажет, смотри сырые байты.

## Сравнение NTCIP с Modbus и DNP3

Три протокола ICS часто встречаются рядом. **Modbus** — простой, без аутентификации вообще, только регистры. **DNP3** — сложнее, с адресацией и (опционально) Secure Authentication. **NTCIP** — SNMP-модель с богатым словарём объектов.

Практическая разница в безопасности такая. Modbus защитить почти нечем — только сетью. DNP3 умеет криптографическую аутентификацию, если её включили. NTCIP опирается на SNMP: v1/2c небезопасны, v3 — приемлемы. Поэтому на пентесте первым делом выясняют, какая версия SNMP и какие community настроены.

## Разбор SNMP-пакета в дампе

Посмотрим, как выглядит опрос контроллера на уровне пакета.

```
$ tshark -r its.pcap -Y "snmp.get-request" -T fields -e ip.src -e udp.dstport -e snmp.community -e snmp.name
10.0.0.10  161  public  1.3.6.1.4.1.1206.4.2.1.1.1.4.0
```

Здесь `snmp.community=public` — та самая слабость: community читается прямо из пакета. `snmp.name` — OID, к которому идёт запрос. Если в дампе есть `snmp.set-request`, значит кто-то меняет конфигурацию — ищи источник: если это не управляющая станция, возможен несанкционированный доступ.

## Историческая справка и стандарты

NTCIP развивался с 1990-х как способ унифицировать зоопарк проприетарных протоколов дорожного оборудования. Семейство включает десятки документов: NTCIP 1103 (транспорт), NTCIP 1201 (глобальные объекты), NTCIP 1202 (контроллеры сигналов), NTCIP 1203 (динамические табло) и другие. Общая нить — SNMP-модель и общий словарь.

Понимание структуры документов помогает на практике: когда видишь незнакомый OID, посмотри, к какой группе NTCIP он относится — так восстанавливается смысл без вендорской документации.

## Типичные ошибки

Первая — путать NTCIP и SNMP: NTCIP использует SNMP как транспорт, но определяет свою модель объектов. Вторая — считать, что «раз это дорожная инфраструктура, туда не добраться»: контроллеры часто за шлюзами с дефолтными community. Третья — пытаться «проверить set» на реальном объекте: это недопустимо. Четвёртая — игнорировать STMP в старых системах и искать только SNMP.

## Как ориентироваться в OID

Дерево NTCIP большое, но ориентироваться в нём несложно, если знать верхний уровень. Все объекты лежат под `1.3.6.1.4.1.1206`. Дальше идут группы, и, читая `snmpwalk` построчно, ты видишь одинаковые префиксы: они и есть группы.

```
$ snmpwalk -v2c -c public 10.0.0.60 1.3.6.1.4.1.1206.4.2.1.1.1.1 | head -3
iso.3.6.1.4.1.1206.4.2.1.1.1.1.1.0 = INTEGER: 1
iso.3.6.1.4.1.1206.4.2.1.1.1.1.2.0 = INTEGER: 0
iso.3.6.1.4.1.1206.4.2.1.1.1.1.3.0 = INTEGER: 0
```

Обрати внимание на предпоследнее число: `1`, `2`, `3` — это индекс (номер фазы/канала). Так NTCIP описывает повторяющиеся сущности: у контроллера сигналов несколько фаз, и каждая — отдельный набор объектов.

Полезный приём: сначала `snmpwalk` верхнего уровня, затем сужай префикс. Не нужно знать все OID наизусть — достаточно понимать структуру.

## Стенд и симулятор

Работать с реальными дорожными контроллерами нельзя, поэтому для практики используют симуляторы и эмуляторы. Простой вариант — поднять SNMP-агент с NTCIP-подобной MIB на изолированной машине:

```
$ snmpsimd.py --data-dir=./ntcip-sim --agent-udpv4-endpoint=127.0.0.1:1161 &
$ snmpwalk -v2c -c public 127.0.0.1:1161 1.3.6.1.4.1.1206
```

`snmpsim` отдаёт заранее записанные ответы и позволяет безопасно отрабатывать `snmpwalk`/`snmpset` и разбор дампов. Для учебных задач по ICS этого достаточно, а риск нулевой.

## Безопасность по умолчанию: что чаще всего не так

Соберём типичный список проблем дорожного контроллера, который встречается снова и снова.

Первое — SNMP v1/2c с community `public`. Это открытое чтение всего состояния. Второе — `private` для записи, иногда с тем же простым значением. Третье — отсутствие ACL: к порту 161 допускается любой, кто дошёл до сети. Четвёртое — общий сегмент с офисной сетью, из-за чего «плоская» сеть сводит всю защиту на нет. Пятое — неудалённые сервисы: telnet, FTP, веб-интерфейс с дефолтным паролем.

Проверять это надо в порядке «сначала пассивно, потом активно»: снять дамп и посмотреть community, затем `snmpwalk` на чтение. Команды `set` — только на стенде.

Защитнику стоит начать с инвентаризации: какие контроллеры отвечают, какие community, какие версии. Часто уже это выявляет проблемы без единой активной проверки.

## Шпаргалка по PDU SNMP

| PDU type | Запрос |
|---|---|
| 0 | GetRequest |
| 1 | GetNextRequest |
| 2 | GetResponse |
| 3 | SetRequest |
| 4 | Trap |
| 5 | GetBulkRequest |

PDU type 3 (SetRequest) — команда изменения. В дампе её появление от неизвестного источника — красный флаг.

## Итог по протоколу

Главное: NTCIP наследует слабости SNMP. Смена community, переход на v3 и ACL — минимальный набор. Любые команды изменения режима — исключительно на изолированном стенде.
