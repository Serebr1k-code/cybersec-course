## Вопрос, с которого всё начинается

Радиоинтерфейс NR — это «труба», по которой терминал разговаривает с сетью. Но сам разговор «кто ты и что тебе разрешено» идёт на другом слое — **NAS** (Non-Access Stratum, «слой вне доступа»). Именно здесь терминал регистрируется, проходит аутентификацию и запрашивает интернет-сессию.

Если ты понял [`network-5g-nr`](network-5g-nr), следующий естественный вопрос: как выглядит этот диалог и что в нём можно сломать?

## Наш пример: последовательность регистрации

Возьмём фрагмент NAS-лога регистрации:

```
[NAS] Registration Request  type=initial  supi=imsi-001010000000001
[NAS] Identity Request     type=SUCI
[NAS] Identity Response    suci=...
[NAS] Authentication Request  rand=...  autn=...  ngKSI=0
[NAS] Authentication Response  res*=<res-star>
[NAS] Security Mode Command  ciphering=NEA2  integrity=NIA2
[NAS] Security Mode Complete
[NAS] Registration Accept  tai=00101-00000001  5g-guti=...
[NAS] PDU Session Establishment Request  psi=1  sst=1  dnn=internet
[NAS] PDU Session Establishment Accept  ueIp=10.45.0.7
```

Разберём это по шагам — здесь вся логика 5G NAS.

## Шаг 1: два подпротокола NAS

NAS в 5G делится на две части:

- **5GMM** (5G Mobility Management) — мобильность: регистрация, аутентификация, идентификация, отслеживание местоположения.
- **5GSM** (5G Session Management) — сессии: установка, изменение и освобождение PDU-сессий (это аналог PDP-контекста в GPRS/4G).

В нашем логе первые восемь строк — это 5GMM, последние две — 5GSM. Разделение важно: ломать их можно по-разному.

## Шаг 2: идентификация и SUCI

Строка `supi=imsi-001010000000001` — это **SUPI** (Subscriber Permanent Identifier), постоянный идентификатор абонента. Внутри него IMSI. Открыто гонять IMSI по радио — плохо (IMSI-catcher), поэтому 5G вводит **SUCI** (SUPI Concealed Identifier): зашифрованную обёртку SUPI, которую умеет расшифровать только домашняя сеть.

Смотришь в логе: `Identity Request type=SUCI` → `Identity Response suci=...`. Терминал показывает замаскированный идентификатор. Это часть privacy-защиты 5G.

## Шаг 3: аутентификация 5G-AKA

`Authentication Request rand=... autn=...` — сеть присылает случайное число `RAND` и токен аутентификации `AUTN`. Терминал проверяет `AUTN` (убеждается, что сеть настоящая), вычисляет ответ и отправляет `Authentication Response res*=<res-star>`.

Ключевое отличие от 4G: в 5G-AKA используется `RES*` (res-star) — производное значение, а не «сырой» RES. Домашняя сеть `AUSF`/`UDM` может обнаружить, что где-то перехватили и повторно используют ответ (так ловят фейковые базовые станции). `ngKSI=0` — индекс ключа, по которому потом шифруется сигнализация.

## Шаг 4: Security Mode Command

После аутентификации сеть командует: `ciphering=NEA2 integrity=NIA2`. **NEA** (New Encryption Algorithm) и **NIA** (New Integrity Algorithm) — это алгоритмы шифрования и контроля целостности NAS. NEA0/NIA0 — «null», то есть отсутствие защиты.

`Security Mode Command` / `Security Mode Complete` включают защиту. С этого момента NAS-сообщения шифруются и подписываются. До этого момента всё видно в открытом виде — это окно и есть цель атак.

## Шаг 5: PDU-сессия

`PDU Session Establishment Request psi=1 sst=1 dnn=internet` — терминал просит сессию данных. `psi` — идентификатор сессии, `sst` — тип среза (SST=1 — eMBB, «широкополосный»), `dnn` — имя сети данных (аналог APN). Сеть отвечает `Accept ueIp=10.45.0.7` и выдаёт IP.

Здесь живут атаки на срезы (slicing): если сеть доверяет параметру `sst` от терминала, можно попросить срез, к которому тебя не должны пускать.

## Шаг 6: где здесь атака

- **Downgrade до 4G.** Спуфим gNB, который «не умеет» 5G-AKA, и терминал откатывается на EPS-AKA 4G — там слабее privacy.
- **Null-схемы.** Навязать `NEA0/NIA0` через поддельный Security Mode Command — сигнализация пойдёт без шифрования.
- **Replay/манипуляция.** До включения защиты можно подменять сообщения: например, отклонить регистрацию или навязать параметры.
- **Абьюз срезов.** Просить `sst`, к которому нет прав.

Для практики это воспроизводится на srsRAN + OAI и симуляторах UE; дампы удобно смотреть фильтром `tshark -Y 'nas-5gs'`.

```
$ tshark -r nas.pcap -Y 'nas-5gs' -T fields -e nas_5gs.mm.message_type
0x41
0x42
0x56
0x57
0x5d
```

Здесь `0x41` — Registration Request, `0x56` — Authentication Request и так далее: tshark выдаёт числовой код типа сообщения, который расшифровывается по таблице 24.501.

## Что мы теперь знаем

- NAS делится на 5GMM (мобильность) и 5GSM (сессии).
- SUCI маскирует постоянный идентификатор SUPI/IMSI.
- 5G-AKA использует RES* — сеть может ловить реплей.
- Security Mode Command включает NEA/NIA; NEA0/NIA0 = без защиты.
- PDU-сессия задаётся psi/sst/dnn; срезы можно абьюзить.

## Шаг 7: коды типов сообщений NAS

В дампе tshark показывает числовые коды. Ниже — самые частые типы из спецификации 24.501:

| Код | Сообщение | Подпротокол |
|---|---|---|
| 0x41 | Registration Request | 5GMM |
| 0x42 | Registration Accept | 5GMM |
| 0x43 | Registration Complete | 5GMM |
| 0x44 | Registration Reject | 5GMM |
| 0x45 | Deregistration Request | 5GMM |
| 0x54 | Identity Request | 5GMM |
| 0x55 | Identity Response | 5GMM |
| 0x56 | Authentication Request | 5GMM |
| 0x57 | Authentication Response | 5GMM |
| 0x5d | Security Mode Command | 5GMM |
| 0x5e | Security Mode Complete | 5GMM |
| 0x67 | PDU Session Establishment Request | 5GSM |
| 0x68 | PDU Session Establishment Accept | 5GSM |

Зная таблицу, ты читаешь дамп без расшифровки текста: только по кодам видно последовательность процедур.

## Шаг 8: контекст безопасности и ngKSI

После `Security Mode Complete` терминал и сеть держат общий контекст безопасности: ключи шифрования и целостности, привязанные к индексу `ngKSI` (next-generation Key Set Identifier). Когда `ngKSI=7` — это специальное значение «нет ключа», то есть защиты ещё нет.

Практически: всё, что идёт **до** Security Mode Command, читается открыто. Это окно используют для сбора идентификаторов и подмены параметров.

## Шаг 9: мобильность и обновление регистрации

Терминал не регистрируется один раз навсегда. Он периодически делает **Registration Update** (например, при смене зоны отслеживания — TAI) и **Service Request** (когда нужно быстро выйти из IDLE в CONNECTED без полной регистрации).

В дампе это выглядит как чередование `Registration Request type=mobilityUpdate` и коротких `Service Request`. Аномально частые обновления могут означать либо плохое покрытие, либо попытку удержать терминал в фейковой сети.

## Шаг 10: где хранить контекст при анализе

При разборе длинного NAS-дампа удобно вести таблицу по каждому UE:

- SUPI/SUCI (если виден),
- 5G-GUTI (временный идентификатор),
- текущий TAI (зона),
- статус безопасности (до/после SMC),
- активные PDU-сессии.

Так ты не теряешь нить между десятками сообщений. Для CTF этого достаточно, чтобы ответить на типовой вопрос «к какой сети подключился абонент и был ли он аутентифицирован».

## Ссылки на спецификации и дальнейшее чтение

Телеком-протоколы описаны в спецификациях 3GPP и ITU — это первоисточник, к которому стоит обращаться, когда дамп непонятен. Полезно знать, где что лежит.

Для SS7 и MAP: ITU-T Q.700-серия описывает MTP, Q.711-716 — SCCP, Q.771-775 — TCAP, а MAP определён в 3GPP TS 29.002. Для Diameter базовый протокол — RFC 6733, приложения S6a/Gx/Gy — в TS 29.272/29.212/32.299. Для GTP — TS 29.060 (GTPv1) и TS 29.274 (GTPv2-C), GTP-U — TS 29.281.

Для IMS базовый SIP — RFC 3261, а профиль для 3GPP — TS 24.229; SDP описан в RFC 4566. Для 5G ядро — TS 23.501 (архитектура), NAS — TS 24.501, SBI — TS 29.500-серия.

Практический приём: когда видишь незнакомое поле или код, ищи его имя в соответствующей спецификации. Регулярно это делать полезно, потому что dissector в Wireshark показывает ровно те имена, что и стандарт.

Наконец, для тренировки поднимай открытые стенды: srsRAN и OpenAirInterface для радио, free5GC и Open5GS для ядра, Kamailio для IMS/SIP. На них безопасно воспроизводится почти любая описанная здесь атака — и, что важнее, видна реакция сети на неё.

## Практика: собери стенд и воспроизведи

Теорию 5G лучше всего закрепить на живом стенде — благо всё нужное открыто. Минимальный набор: ядро (free5GC или Open5GS), симулятор базовой станции и терминала (UERANSIM), плюс захват трафика (tshark) на интерфейсах.

Порядок работы такой. Сначала подними ядро и убедись, что функции зарегистрировались в NRF — в логах увидишь `NF registered`. Затем запусти gNB-симулятор и подключи UE: терминал пройдёт регистрацию, а в дампе появится цепочка NAS-сообщений. Сними их и сопоставь с тем, что разбирали в уроке: Registration Request, Authentication, Security Mode Command, PDU Session Establishment.

Дальше экспериментируй с настройками. Выключи проверку RES* и посмотри, как изменится поведение при повторном ответе. Навяжи NEA0/NIA0 и убедись, что сигнализация пойдёт открыто. Смени профиль SUCI и сравни, что видно в дампе. Каждое изменение — это гипотеза, которую ты проверяешь своими глазами.

## Типичные ошибки при разборе 5G

Первая ошибка — путать слои. RRC, NAS и SBI живут на разных уровнях и в разных дампах; смешивать их нельзя. Сначала определи, что именно ты смотришь.

Вторая — считать заявленное равным фактическому. Сеть может *поддерживать* шифрование, но *согласовать* null. Всегда проверяй, что реально в дампе, а не что в описании.

Третья — игнорировать переходные режимы. NSA (5G с 4G-ядром) ведёт себя иначе, и часть защиты там слабее. Учитывай, к какому ядру привязан терминал.

Четвёртая — забывать про время. Сигнализация чувствительна к задержкам; аномалии часто видны именно в таймингах, а не в отдельных полях.
