## Вопрос, с которого всё начинается

На CTF тебе дали файл `capture.pcap` — запись сетевого трафика. Внутри тысячи пакетов. Где искать флаг? И вообще, что такое «пакет» и почему у него столько слоёв?

Чтобы отвечать на такие вопросы, нужно понимать, как устроена сеть. В этом уроке мы не будем перечислять протоколы списком — вместо этого поймаем **один-единственный пакет** и разберём его по слоям. Всё остальное — ответы на вопросы, которые из этого разбора родятся.

## Наш пример: один HTTP-запрос

Мы отправим с машины `10.0.0.5` один HTTP-запрос на сервер `93.184.216.34` (это `example.com`) и посмотрим, что при этом пошло по сети. Поймать пакет можно утилитой `tcpdump` — она слушает сетевой интерфейс и печатает проходящие пакеты.

```
$ sudo tcpdump -i eth0 -n -c 1 'tcp port 80'
tcpdump: listening on eth0, link-type EN10MB (Ethernet)
14:22:31.412 IP 10.0.0.5.51234 > 93.184.216.34.80: Flags [P.], seq 1:75, ack 1, win 502, length 74
```

`-i eth0` — какой интерфейс слушать, `-n` — не превращать адреса в имена, `-c 1` — поймать ровно один пакет, а `'tcp port 80'` — фильтр: нас интересует только TCP-трафик на порт 80.

Мы поймали один пакет. Теперь вопрос: **что внутри него?**

## Шаг 1: смотрим содержимое пакета

Добавим `-A`, чтобы `tcpdump` показал содержимое в виде текста, и `-X`, чтобы увидеть байты в hex.

```
$ sudo tcpdump -i eth0 -n -c 1 -A 'tcp port 80'
14:22:31.412 IP 10.0.0.5.51234 > 93.184.216.34.80: Flags [P.], seq 1:75, ack 1, length 74
E..L..@.@...........<...:...P.3.....P...G.ET / HTTP/1.1
Host: example.com
User-Agent: curl/8.4.0
Accept: */*
```

Вот и смысл: внутри пакета лежит текст `GET / HTTP/1.1` с заголовками. Это HTTP-запрос. Но сам текст — лишь верхушка. Под ним ещё несколько слоёв.

## Шаг 2: разбираем пакет по слоям

Тот же пакет можно открыть в Wireshark — программе с графическим разбором. Wireshark покажет его как «матрёшку» из слоёв:

```
Frame 1: 74 bytes on wire
  └ Ethernet II: src 00:0c:29:..:..  dst 52:54:00:..:..
      └ Internet Protocol Version 4: 10.0.0.5 → 93.184.216.34
          └ Transmission Control Protocol: 51234 → 80 [PSH, ACK]
              └ Hypertext Transfer Protocol: GET / HTTP/1.1
```

Читаем снизу вверх, потому что именно так пакет собирался при отправке:

- **HTTP** — прикладной слой: сам запрос, который мы хотим передать.
- **TCP** — транспортный слой: разбивает данные на сегменты, следит за доставкой и порядком. Здесь видно порты `51234` (случайный порт клиента) и `80` (порт сервера).
- **IP** — сетевой слой: адреса `10.0.0.5` и `93.184.216.34`, чтобы пакет нашёл путь между сетями.
- **Ethernet** — канальный слой: MAC-адреса, чтобы доставить кадр внутри локальной сети.

Каждый слой заворачивает данные предыдущего в свою «обёртку». Это и называется **инкапсуляция**.

## Шаг 3: инкапсуляция — главная идея сети

Представь, что ты отправляешь письмо в конверте, который кладут в другой конверт, а тот — в посылку. На каждом уровне свой адрес: на посылке — адрес дома (MAC), внутри — адрес города (IP), внутри — имя получателя (порт), внутри — само письмо (HTTP).

Именно поэтому у пакета столько слоёв: каждый решает свою задачу и не знает о деталях других. Это позволяет менять один слой, не ломая остальные — например, передавать тот же HTTP и по Wi-Fi, и по оптоволокну.

## Шаг 4: две модели, которые описывают одно и то же

Слои удобно описывать двумя моделями:

- **OSI** — теоретическая, 7 слоёв (физический, канальный, сетевой, транспортный, сеансовый, представления, прикладной).
- **TCP/IP** — практическая, 4 слоя (канальный, интернет, транспортный, прикладной).

Наш пакет раскладывается по TCP/IP в четыре слоя ровно так, как мы разобрали: Ethernet → IP → TCP → HTTP. OSI дробит то же самое мельче — и это единственное, что новичку нужно о ней знать.

## Что вообще ищут в сетевых задачах

Понимание слоёв нужно не само по себе, а чтобы знать, где искать. В CTF и на пентесте сетевые задачи сводятся к нескольким типам:

- **Восстановить переданное.** В потоке лежит скачанный файл — его собирают из пакетов (в Wireshark: File → Export Objects).
- **Найти учётные данные.** Пароли часто идут открытым текстом в FTP, Telnet, HTTP Basic.
- **Разобрать сессию.** `Follow TCP Stream` показывает всю переписку одного соединения.
- **Обнаружить аномалию.** Сканирование портов, ARP-spoof, DNS-туннель выделяются на фоне обычного трафика.
- **Скрытый канал.** Данные прячут в неиспользуемых полях протокола.

Общее правило: сначала понять, о каком протоколе речь, потом искать в нём смысл.

## Клиент, сервер и порты

Большинство сетевых протоколов работают по схеме **клиент — сервер**. Клиент (браузер, `curl`) обращается к серверу на определённый **порт** — число от 1 до 65535, обозначающее сервис. Порт 80 — HTTP, 443 — HTTPS, 22 — SSH, 21 — FTP. Когда ты видишь в пакете `51234 → 80`, это значит: случайный порт клиента обратился к порту 80 сервера, то есть к веб-серверу.

Порты — это «двери» к сервисам, и именно их перебирает сканер вроде `nmap`. Поэтому следующий естественный вопрос в любой сети: **какие двери открыты?**

## Как читать вывод tcpdump

Строка из шага 2 содержит много полезного, и её стоит уметь читать:

```
14:22:31.412 IP 10.0.0.5.51234 > 93.184.216.34.80: Flags [P.], seq 1:75, length 74
```

- `14:22:31.412` — время с точностью до миллисекунды.
- `IP` — сетевой протокол.
- `10.0.0.5.51234` — адрес и порт отправителя.
- `>` — направление: слева направо.
- `93.184.216.34.80` — адрес и порт получателя.
- `Flags [P.]` — флаги TCP; `P` (PSH) означает «передать данные приложению сразу».
- `seq 1:75` — номера байтов в потоке.
- `length 74` — сколько байтов данных в этом сегменте.

Разобрав строку по частям, ты можешь без графической программы понять, кто с кем и о чём говорит. Это и есть навык чтения трафика.

## Что мы теперь знаем

По-простому:

1. Сеть — это матрёшка слоёв; данные спускаются по слоям при отправке и поднимаются при получении.
2. Каждый слой добавляет свой адрес и свою задачу.
3. `tcpdump` ловит пакеты, `Wireshark` их разбирает по слоям.
4. Один пакет — это один «конверт», а сессия — целая переписка из множества пакетов.

Именно поэтому анализ трафика начинается не с «посмотреть все пакеты», а с вопроса: какой слой и какое поле нам интересны?

## На что смотреть дальше

- **Фильтруйте, а не листайте.** В `tcpdump` используйте фильтры (`'tcp port 80'`), в Wireshark — display-фильтры.
- **Следите за портами.** Порт — это «дверь» к сервису; он говорит, о каком протоколе речь.
- **Помните про инкапсуляцию.** Если не понятно, где поле, спросите себя: какому слою оно принадлежит.
- **Не путайте кадр и сессию.** Один пакет почти никогда не содержит всю картину.

## Куда дальше

В следующем уроке мы разберём **основы сетей предметно**: адресацию, ARP и то, как машины в одной сети находят друг друга. А пока запомни главное: сеть — это слои, и почти любой вопрос «что это за трафик» решается разбором пакета сверху вниз.

## Где пригодится

- **CTF (Network / Forensics):** анализ PCAP, восстановление переданных файлов, поиск флага в трафике.
- **Пентест:** перехват и анализ трафика, поиск слабых протоколов и утечек.
- **Blue team / SOC:** разбор инцидентов по сетевым логам и захватам.
- **Администрирование:** диагностика сетевых проблем «на уровне пакетов».
