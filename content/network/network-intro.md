Сетевые задачи — это не только «поймать флаг из трафика». Это целый пласт: анализ PCAP, перехват и модификация трафика, сканирование, MITM, туннели и обход фильтрации. Этот урок задаёт понятийную базу и показывает, куда двигаться дальше по ветке.

## Зачем нужна сетевая категория

Любая атака в современном пентесте проходит по сети: разведка портов, перехват сессии, эксплуатация сервисов, эксфильтрация данных. Сетевая ветка учит не «запомнить команды», а понимать, что именно происходит на проводе, потому что без этого невозможно ни воспроизвести атаку, ни защититься от неё.

В CTF сетевые задачи встречаются в двух видах:

- **Офлайн-анализ** — дают файл `capture.pcap` (или `.pcapng`), и нужно найти в нём флаг, пароль, восстановленный файл или ключ. Здесь важнее всего терпение и умение фильтровать.
- **Онлайн/интерактив** — есть живой сервис (иногда с MITM-прослойкой), нужно перехватить, подменить или расшифровать трафик. Здесь важнее инструментарий и тайминг.

Прежде чем анализировать трафик, нужно понимать, как он устроен. Этому посвящены первые уроки ветки: разбор пакета, TCP/IP, порт-скан, энумерация сервисов. Дальше идут атаки на протоколы (ARP, DNS, DHCP), перехват (MITM, evil twin), туннелирование (DNS/ICMP/SSH) и анализ захваченного трафика.

## Модель OSI и стек TCP/IP

Эталонная модель **OSI** описывает семь уровней. На практике используют более простой стек **TCP/IP** из четырёх уровней.

| OSI | TCP/IP | Примеры | Единица данных |
|---|---|---|---|
| 7–5 (Application, Presentation, Session) | Application | HTTP, DNS, TLS, SSH | сообщение |
| 4 (Transport) | Transport | TCP, UDP | сегмент / датаграмма |
| 3 (Network) | Internet | IP, ICMP, ARP* | пакет |
| 2 (Data Link) | Link | Ethernet, Wi-Fi, ARP | кадр |
| 1 (Physical) | — | кабель, радио | биты |

*ARP формально относится к L2/L3, его удобно рассматривать как связку между ними. Ветка Network опирается именно на эту модель: каждая атака живёт на конкретном уровне, и это определяет, какие инструменты нужны.

## Инкапсуляция: как пакет проходит по уровням

Каждый уровень добавляет свой заголовок — это называется **инкапсуляцией**. Путь данных сверху вниз (отправка):

1. Приложение формирует сообщение (например, HTTP-запрос `GET / HTTP/1.1`).
2. Транспорт добавляет TCP-заголовок (порты, seq/ack, флаги) → **сегмент**.
3. Сеть добавляет IP-заголовок (src/dst IP, TTL, protocol) → **пакет**.
4. Канальный уровень добавляет Ethernet-заголовок (MAC src/dst, EtherType) и FCS → **кадр**.

На приёмнике всё разбирается в обратном порядке (декапсуляция). В Wireshark это видно как «дерево» протоколов:

```text
Frame 1: 74 bytes on wire
  Ethernet II, Src: 02:42:ac:11:00:02, Dst: 02:42:ac:11:00:03
  Internet Protocol Version 4, Src: 172.17.0.2, Dst: 172.17.0.3
  Transmission Control Protocol, Src Port: 54321, Dst Port: 80, Seq: 1
  Hypertext Transfer Protocol: GET / HTTP/1.1
```

Понимание инкапсуляции критично для анализа PCAP: чтобы добраться до полезной нагрузки приложения, нужно «снять» все внешние заголовки в правильном порядке. Именно поэтому флаг часто прячут в неожиданном слое — в опциях TCP, в поле TTL, в MAC-адресе.

## Ключевые протоколы, порты и их роль

| Порт | Протокол | Транспорт | Роль в атаке/анализе |
|---|---|---|---|
| 22 | SSH | TCP | брутфорс, туннели, ключи |
| 25/587 | SMTP | TCP | спуфинг, open relay |
| 53 | DNS | UDP/TCP | спуфинг, туннели, эксфильтрация |
| 80/443 | HTTP/S | TCP | веб-атаки, SSL stripping |
| 139/445 | SMB | TCP | null-сессии, EternalBlue |
| 161 | SNMP | UDP | утечки community, энумерация |
| 389/636 | LDAP/S | TCP | энумерация AD |
| 3389 | RDP | TCP | брутфорс, BlueKeep |

Каждый из этих протоколов разбирается в отдельном уроке ветки; здесь важно запомнить карту и понимать, что за открытым портом стоит конкретная поверхность атаки.

## Инструменты: полный арсенал с флагами

Захват и анализ:

```bash
# tcpdump: базовый захват с интерфейса
sudo tcpdump -i eth0 -nn -w capture.pcap
# читать pcap и показывать только HTTP-запросы (ASCII)
tcpdump -r capture.pcap -nn -A 'tcp port 80'
# фильтр по хосту и порту
tcpdump -i any -nn 'host 10.0.0.5 and tcp port 443'
# захват с ограничением размера и количества
sudo tcpdump -i eth0 -s 0 -c 1000 -w cap.pcap

# tshark (CLI Wireshark): список пакетов с нужными полями
tshark -r capture.pcap -Y 'http.request' -T fields -e ip.src -e http.host -e http.request.uri
# статистика по протоколам
tshark -r capture.pcap -z io,phs -q

# Wireshark (GUI): фильтры отображения
#   ip.addr == 10.0.0.5 && tcp.port == 80
#   http.request.method == "POST"
#   tcp.flags.syn == 1 && tcp.flags.ack == 0
```

Сканирование и разведка:

```bash
nmap -sS -p- --min-rate 2000 10.0.0.5          # SYN-скан всех портов
nmap -sV -sC -p 22,80,443 10.0.0.5             # версии + NSE-скрипты
masscan 10.0.0.0/24 -p1-65535 --rate 10000     # быстрый масс-скан
```

## Разобранный пример: чтение реального кадра

Дан PCAP с подозрительной активностью. Задача — понять, что произошло.

Шаг 1 — обзор протоколов:

```bash
tshark -r susp.pcap -z io,phs -q
```

Видим аномально много DNS-запросов к одному домену — намёк на DNS-туннель.

Шаг 2 — смотрим длину запросов:

```bash
tshark -r susp.pcap -Y 'dns.qry.name' -T fields -e dns.qry.name | awk '{print length, $0}' | sort -rn | head
```

Шаг 3 — декодируем base32-подобные метки: длинные случайные поддомены = эксфильтрация. Вывод: инкапсуляция позволяет спрятать данные в «легальном» протоколе — это тема урока про covert-каналы.

## Edge cases и подводные камни

- **VLAN/инкапсуляция 802.1Q** добавляет 4 байта в Ethernet-заголовок — смещения полей меняются.
- **Jumbo frames** (MTU 9000) ломают наивные парсеры, ожидающие 1500.
- **IPv6** — другой формат заголовка и никакого ARP (его заменяет NDP).
- **VXLAN/GRE-туннели** прячут внутренние пакеты внутри внешних — нужен второй проход декапсуляции.
- **TLS 1.3** шифрует почти все метаданные, кроме SNI (и то скрывается в ECH).
- **TCP segmentation offload** может показывать «странные» размеры сегментов на loopback.

## Частые ошибки

- Смотреть только на L7 и игнорировать L2/L3 (там часто и прячется флаг).
- Забывать про направление трафика (кто клиент, кто сервер).
- Путать `src`/`dst` при чтении фильтра.
- Считать, что «зашифровано = неанализируемо»: метаданные (размеры, тайминги, SNI) утекают.
- Игнорировать reassembly: флаг может быть разрезан между сегментами.

## Что дальше / решение

Практический маршрут: (1) разобрать учебный PCAP в Wireshark, пройдя по дереву протоколов; (2) воспроизвести захват tcpdump в своём окружении; (3) просканировать локальную лабораторию nmap и сопоставить открытые порты с сервисами; (4) перейти к network-tcpip и network-arp для глубокого разбора заголовков. Решение любой сетевой задачи начинается с ответа на вопрос: «на каком уровне спрятано искомое?» — и дальше двигаться вниз/вверх по стеку.

## Где пригодится

- **CTF:** корневой урок ветки Network — из него растут разбор трафика, MITM, туннели и реверс протоколов.
- **Пентест:** правильная декомпозиция «по уровням» ускоряет диагностику любой сетевой проблемы.
- **Работа:** понимание инкапсуляции — база для написания собственных парсеров и сканеров.
