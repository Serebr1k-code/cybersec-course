## Вопрос, с которого всё начинается

VPN соединяет сети или пользователей через недоверенную среду, шифруя трафик. Но «VPN» — это не один протокол, а целое семейство: от классического IPsec до современного WireGuard. У каждого своя модель аутентификации, свой формат на проводе и свой набор слабостей.

Вопрос, с которого начинается модуль: **как понять, какой VPN стоит на периметре, что о нём видно без ключей и какие мисконфигурации делают его бесполезным?** Этот модуль — база для [`network-ipsec-ike`](network-ipsec-ike) и [`network-sstp-l2tp`](network-sstp-l2tp), опирается на [`network-vpn`](network-vpn), [`network-openvpn`](network-openvpn) и [`network-wireguard`](network-wireguard).

## Наш пример: что открыто на периметре

Берём шлюз `203.0.113.10` и смотрим VPN-порты. VPN-протоколы живут на разных портах и протоколах, поэтому сканируем и TCP, и UDP:

```
$ sudo nmap -sU -p 500,4500,1194,51820,1701 203.0.113.10
PORT      STATE SERVICE
500/udp   open  isakmp
4500/udp  open  ipsec-nat-t
1194/udp  open  openvpn
$ sudo nmap -sS -p 443,1723 203.0.113.10
PORT     STATE SERVICE
443/tcp  open  https
1723/tcp open  pptp
```

Уже по портам видно много: `500/4500` — IPsec, `1194` — OpenVPN, `1723` — PPTP (устаревший). Разберёмся, что это значит.

## Шаг 1: IPsec — три части и два режима

**IPsec** — семейство протоколов, которое состоит из:

- **IKE** (Internet Key Exchange) — согласование ключей и параметров, UDP-порт 500 (а 4500 — для работы через NAT, **NAT-T**);
- **ESP** (Encapsulating Security Payload, IP-протокол 50) — шифрование и аутентификация полезной нагрузки;
- **AH** (Authentication Header, протокол 51) — только аутентификация заголовка, встречается редко;
- **SA** (Security Association) — однонаправленный «канал» с согласованными параметрами.

Есть два режима: **transport** защищает только полезную нагрузку, **tunnel** — весь исходный IP-пакет целиком (так делают site-to-site).

Версию и вендора IPsec видно без ключей:

```
$ sudo nmap -sU -p 500 --script ike-version 203.0.113.10
PORT    STATE SERVICE
500/udp open  isakmp
| ike-version:
|   attributes:
|     XAUTH
|_    Dead Peer Detection v1.0
```

Атакующему эти метаданные говорят, какой вендор и какие возможности включены.

## Шаг 2: TLS-VPN — OpenVPN и SSTP

Второе большое семейство прячет свои пакеты в TLS. **OpenVPN** инкапсулирует их в TLS поверх TCP или UDP (по умолчанию UDP-1194). **SSTP** — это TLS поверх TCP-443, поэтому внешне он похож на обычный HTTPS.

```
$ nmap -sV -p 1194 --script openvpn-info 203.0.113.10
PORT     STATE SERVICE
1194/udp open  openvpn
```

Если включён `tls-auth` (статический ключ для подписи хендшейка), посторонний даже не начнёт согласование. Если нет — виден TLS-хендшейк и, иногда, сертификаты.

## Шаг 3: WireGuard и PPP-based

**WireGuard** — современный VPN: не использует TLS, у него собственный протокол с фиксированными примитивами (Curve25519, ChaCha20-Poly1305) и статическими публичными ключами. По умолчанию — UDP-51820, и по проводу он почти неотличим от случайных данных.

А вот **PPP-based** — красный флаг:

- **PPTP** (порт 1723) использует аутентификацию **MS-CHAPv2**, которая ломается офлайн-перебором (инструменты `asleap`, `chapcrack`);
- **L2TP** сам по себе не шифрует и применяется только вместе с IPsec (L2TP/IPsec).

Чистый PPTP или L2TP без IPsec в 2026 году — почти гарантированная находка.

## Шаг 4: что видно на проводе без расшифровки

Даже не имея ключей, из трафика извлекают:

```
$ sudo tcpdump -i eth0 -nn -w vpn.pcap 'udp port 500 or udp port 4500 or ip proto 50'
$ tshark -r vpn.pcap -Y 'isakmp' -T fields -e isakmp.version -e isakmp.exchangetype | head
2       34
2       35
```

Здесь `isakmp.version=2` — это IKEv2, а типы обмена (`34`, `35`) показывают начало согласования. Видны версия, тип обмена, идентификаторы (в IKEv1 **aggressive mode** утекает идентификатор и хэш пароля) и выбранные алгоритмы.

## Шаг 5: две фазы IKE

IKEv1/IKEv2 согласуют IPsec в две фазы:

- **Фаза 1** — строится защищённый канал (IKE SA) между шлюзами; в ней аутентифицируются стороны (PSK или сертификаты) и согласуются алгоритмы.
- **Фаза 2** — внутри канала согласуются параметры **ESP** (шифр, хэш) и создаются IPsec SA.

Ключевая слабость — **aggressive mode** в фазе 1 (IKEv1): в нём идентификатор и хэш пароля летят открыто, и PSK можно перебрать офлайн. IKEv2 так не умеет — это одна из причин его использовать.

## Что мы теперь знаем

- «VPN» — семейство: IPsec, TLS-VPN (OpenVPN/SSTP), WireGuard, PPP-based.
- IPsec = IKE (UDP 500/4500) + ESP (proto 50) + SA; два режима — transport и tunnel.
- По портам можно быстро опознать тип: 500/4500 — IPsec, 1194 — OpenVPN, 51820 — WireGuard, 1723 — PPTP.
- Даже без ключей видны версия IKE, тип обмена, вендор и алгоритмы.
- PPTP/L2TP без IPsec и IKEv1 aggressive mode — устаревшие и опасные.
- IKE согласует IPsec в две фазы: сначала защищённый канал, затем параметры ESP.
- WireGuard использует собственный протокол (не TLS) и статические публичные ключи.

| Протокол | Транспорт | Шифрование | Порт/прото |
|---|---|---|---|
| IPsec/IKEv2 | UDP | да (ESP) | 500/4500, 50 |
| WireGuard | UDP | да | 51820 |
| OpenVPN | TCP/UDP | да (TLS) | 1194 |
| SSTP | TCP | да (TLS) | 443 |
| L2TP/IPsec | UDP | да (IPsec) | 1701 + 500 |
| PPTP | GRE | слабое | 1723, 47 |

## Если защита мешает

- **Сервис не отвечает на сканер.** VPN может фильтровать по источнику — тогда по IKE-порту идёт молчание, хотя сервис жив. Проверяй с разрешённого адреса.
- **TLS-VPN прячется на 443.** SSTP неотличим от HTTPS — опознавай по поведению (специфичный хендшейк), а не по баннеру.
- **Aggressive mode выключен.** В IKEv2 идентификаторы шифруются — тогда остаются только метаданные.
- **MFA.** Перебор пароля не поможет; ищи мисконфиги (split-tunnel, широкий доступ), а не слабый пароль.

## Практика: аудит VPN-периметра

```
$ sudo nmap -sU -p 500,4500,1194,51820,1701 203.0.113.10
$ sudo nmap -sS -p 443,1723 203.0.113.10
$ sudo nmap -sU -p 500 --script ike-version 203.0.113.10
$ sudo tcpdump -i eth0 -nn -w vpn.pcap 'udp port 500 or udp port 4500 or ip proto 50'
```

Шесть вопросов, на которые отвечает этот прогон: какие протоколы открыты наружу; какая версия IKE; не осталось ли IKEv1 aggressive; какие алгоритмы разрешены (нет ли DES/3DES/MD5); обязательна ли MFA; не утекает ли трафик при split-tunnel.
