## Вопрос, с которого всё начинается

Иногда в CTF дают не сетевой дамп, а захват USB. Задача звучит странно: «восстанови, что печатал пользователь». USB — это не сеть, но принцип тот же: есть записанные кадры, в них — данные, и по ним можно восстановить действие.

В этом уроке мы разберём реальный USB-захват клавиатуры и восстановим набранный текст — а по ходу поймём, как вообще читают USB-трафик.

## Наш пример: дамп usb.pcap с нажатиями клавиатуры

У нас есть файл `usb.pcap` — захват обмена USB-клавиатуры с компьютером. USB-дампы пишут утилитой `usbmon` (Linux) или драйвером USBPcap (Windows); формат файла — тот же pcap, поэтому его открывает и Wireshark, и `tshark`.

Сначала — обзор: какие устройства вообще есть в дампе.

```
$ tshark -r usb.pcap -T fields -e usb.device_address -e usb.endpoint_address
3	0x81
3	0x81
3	0x81
3	0x81
3	0x81
3	0x81
3	0x81
3	0x81
```

Термины, которые тут появились:

- **device address** — номер устройства на шине USB. Здесь всё общение идёт с устройством №3.
- **endpoint** (конечная точка) — «канал» внутри устройства. Адрес `0x81`: старший бит означает направление **IN** (от устройства к хосту), младший бит `1` — номер точки. Значит, мы читаем данные, которые устройство отдаёт компьютеру.

## Шаг 1: определяем тип устройства

Чтобы понять, клавиатура это или, скажем, флешка, смотрим подробности кадра:

```
$ tshark -r usb.pcap -V
USB URB
    URB bus id: 1
    Device address: 3
    Endpoint: 0x81, Direction: IN
    URB transfer type: URB_INTERRUPT (0x01)
```

**URB** (USB Request Block) — структура-описание одного обмена по USB. **Transfer type: INTERRUPT** — прерывающий тип передачи. Именно так работают клавиатуры и мыши: они «прерывают» хост, когда есть новое событие (нажатие). Массовое хранилище (флешки) использует тип **BULK**. Уже по типу передачи видно: перед нами HID-устройство ввода.

**HID** (Human Interface Device) — класс USB-устройств «человеко-машинного ввода»: клавиатуры, мыши, геймпады. Для клавиатуры формат пакета фиксирован: 8 байт, где первый байт — модификаторы (Ctrl/Shift/Alt), второй зарезервирован, а следующие шесть — коды нажатых клавиш.

## Шаг 2: достаём коды нажатий

Полезную нагрузку кадра `tshark` отдаёт полем `usb.capdata`:

```
$ tshark -r usb.pcap -T fields -e usb.capdata
0000090000000000
0000000000000000
00000f0000000000
0000000000000000
0000040000000000
0000000000000000
00000a0000000000
0000000000000000
```

Каждая строка — это те самые 8 байт HID-отчёта в hex. Разберём первую: `00 00 09 00 00 00 00 00`. Модификаторов нет (`00`), а третья позиция (первый из шести слотов клавиш) — `09`. Пустые строки `0000000000000000` — это отпускание клавиши (все нули). Каждое нажатие сопровождается отпусканием, поэтому строк вдвое больше, чем букв.

## Шаг 3: переводим коды в символы

Код `09` — это не ASCII-код буквы, а **HID usage code** — номер клавиши в стандартной таблице HID. У неё своя нумерация: `04` = `a`, `05` = `b`, …, `09` = `f`, `0a` = `g`, `0f` = `l`. То есть таблица идёт по алфавиту от `04` (a), но не совпадает с ASCII.

Напишем декодер: берём только ненулевые третьи байты и переводим по таблице.

```
$ python3 decode.py
flag
```

Где `decode.py` — это:

```python
keymap = {0x04:'a',0x05:'b',0x06:'c',0x07:'d',0x08:'e',
          0x09:'f',0x0a:'g',0x0f:'l'}
caps = open('caps.txt').read().split()
out = ''
for c in caps:
    b = bytes.fromhex(c)
    if b[2]:                       # есть нажатая клавиша
        out += keymap.get(b[2], '?')
print(out)
```

Результат — `flag`. Набранный текст восстановлен: четыре нажатия `f`, `l`, `a`, `g`.

## Шаг 4: а если это была флешка

Тот же подход работает и для USB-накопителей. Отличие — в типе передачи и в том, что данные идут потоком больших блоков:

- Тип передачи будет **BULK**, а не INTERRUPT.
- Данные собираются по endpoint'ам и склеиваются в файл.
- В Wireshark есть готовое меню **File → Export Objects → USB** (или `tshark --export-objects`), которое соберёт переданный файл.
- Полезно смотреть `usb.src`/`usb.dst`, чтобы понять, кто кому что передавал.

Практический приём: если в дампе много bulk-трафика на неизвестное устройство, выгрузи объекты и проверь их сигнатуры (`file`), не прячется ли там документ или архив.

## Шаг 5: как получить такой дамп самому

- **Linux:** `sudo modprobe usbmon`, затем слушать интерфейс вида `usbmon1` в `tshark`/`tcpdump`: `tshark -i usbmon1 -w usb.pcap`.
- **Windows:** драйвер USBPcap + Wireshark.
- **CTF:** дамп обычно уже дан; твоя задача — разобрать, а не снять.

## Шаг 6: не только клавиатура

Формат HID-отчёта зависит от устройства. Мышь шлёт другие байты: кнопки, смещение по X и Y, прокрутку. Разобрать её так же можно, но таблица полей другая. Графические планшеты, геймпады, считыватели — всё это HID с собственными отчётами; в CTF чаще всего встречается клавиатура, потому что она даёт читаемый текст.

Ещё один частый сценарий — **USB-накопитель**. Здесь данные идут не в HID-отчётах, а потоком по bulk-endpoint. Приёмы разбора:

- Смотреть `usb.src` и `usb.dst` — они показывают направление и участников обмена.
- Собирать данные по endpoint'ам и склеивать в файл.
- Проверять сигнатуру полученного файла через `file` и `binwalk` — не спрятан ли внутри архив или документ.

Есть и готовые инструменты: `ctf-usb-keyboard-parser`, `UsbKeyboardDataExtractor` — они делают шаг «HID-код → символ» за тебя, но понимать, как это работает внутри, всё равно нужно.

## Шаг 7: модификаторы — Shift, Ctrl, Caps Lock

В HID-отчёте первый байт — это **модификаторы**: битовая маска зажатых клавиш. Значения: `0x02` — левый Shift, `0x20` — правый Shift, `0x01` — левый Ctrl, `0x04` — левый Alt, `0x40` — AltGr. Заглавная буква на клавиатуре — это не отдельный код, а тот же код клавиши плюс установленный бит Shift.

Например, отчёт `20 00 04 00 00 00 00 00` означает «Shift зажат, нажата клавиша `a`» → символ `A`. А `02 00 04 ...` — левый Shift + `a` → тоже `A`. Восстанавливая текст из дампа, ты обязан учитывать этот байт, иначе заглавные буквы и символы (`!`, `@`, `?`) будут потеряны. Для цифр и знаков есть отдельная таблица «Shift + клавиша».

Практический декодер поэтому смотрит два байта: модификатор и код клавиши. Если модификатор ненулевой — применяется «верхний» вариант символа.

## Что мы теперь знаем

По-простому:

1. USB-дампы — это pcap, их читают Wireshark/tshark.
2. `usb.device_address` и `usb.endpoint_address` показывают, кто с кем говорит; бит направления в endpoint.
3. Тип передачи INTERRUPT — устройства ввода, BULK — накопители.
4. Клавиатура шлёт 8-байтный HID-отчёт; нажатия — в байтах 3–8.
5. Коды клавиш — HID usage codes, а не ASCII; переводи по таблице.

## На что смотреть дальше

- **Различай устройства по transfer type.** INTERRUPT → ввод, BULK → данные.
- **Не путай HID code и ASCII.** `0x04` — это `a`, а не символ с кодом 4.
- **Отпускания не пропускай как «пустые».** Они помогают отделять нажатия друг от друга.
