Корпоративный Wi-Fi (WPA2/WPA3-Enterprise) и проводной NAC используют **802.1X**: прежде чем пустить устройство в сеть, коммутатор или точка доступа требует аутентификацию через RADIUS-сервер. Идея надёжна, но реализация на стороне клиента часто доверяет любому сертификату сервера — и тогда атакующий поднимает свой «радиус» и выманивает учётные данные. Это одна из самых результативных атак на enterprise-сети.

## 802.1X и RADIUS

Три роли:

- **Supplicant** — клиент (ноутбук, телефон), запрашивающий доступ;
- **Authenticator** — коммутатор/AP, пропускающий трафик только после аутентификации;
- **Authentication Server** — RADIUS (обычно NPS/FreeRADIUS), проверяющий креды.

Протокол аутентификации — **EAP** (Extensible Authentication Protocol), который инкапсулируется в EAPoL (по проводу/L2) или в RADIUS (между authenticator и сервером). До аутентификации трафик клиента ограничен: разрешён только EAPoL и, иногда, DHCP/DNS.

| Компонент | Роль |
|---|---|
| Supplicant | Клиент |
| Authenticator | Коммутатор/AP |
| RADIUS | Сервер аутентификации |
| EAP | Протокол аутентификации |

## EAP-методы

- **EAP-TLS** — взаимная аутентификация сертификатами (клиент и сервер). Самый стойкий, требует PKI на клиентах.
- **PEAP-MSCHAPv2** — сервер даёт сертификат, клиент отправляет логин/пароль внутри TLS через MSCHAPv2. Уязвим, если клиент не проверяет сертификат сервера: атакующий поднимает свой PEAP и перехватывает **challenge/response**, который затем офлайн-ломается.
- **EAP-TTLS** — похож на PEAP, туннелирует произвольный внутренний метод.
- **EAP-FAST, LEAP** — устаревшие, ещё слабее.
- **TEAP** — современный вариант с channel binding (защита от релеинга).

Ключевая уязвимость PEAP-MSCHAPv2: MSCHAPv2-хэш ломается офлайн (`hashcat -m 5500` — NetNTLMv1-подобный формат), а если пароль в корпоративном словаре — быстро.

## Инструменты

- **eaphammer** — rogue AP с EAP-фейком, сбором PEAP/MSCHAPv2 и обходом channel binding.
- **hostapd-mana** — патченый hostapd для фейкового RADIUS/EAP.
- **wpa_supplicant** — клиент для тестов.
- **bettercap / airgeddon** — беспроводные атаки в целом.
- **freeradius** — легитимный сервер для лабы.
- **hashcat** — офлайн-взлом захваченного MSCHAPv2.

```bash
# eaphammer: rogue AP, крадёт MSCHAPv2 и EAP-identity
sudo ./eaphammer -i wlan0 --auth wpa-eap --essid "CORP-WIFI" \
  --creds --negotiate balanced
# hostapd-mana
sudo ./hostapd-mana mana.conf
```

## Разобранный пример: захват MSCHAPv2

1. Сканируем эфир, находим enterprise-сеть (WPA2-EAP) и её BSSID.
   ```bash
   sudo airodump-ng wlan0mon
   ```
2. Поднимаем rogue AP с тем же ESSID и **самоподписанным сертификатом**:
   ```bash
   sudo ./eaphammer -i wlan0 --auth wpa-eap --essid "CORP-WIFI" --creds
   ```
3. Клиент (если не проверяет сертификат) подключается и присылает **EAP-identity** (обычно доменный логин) и MSCHAPv2-обмен.
4. eaphammer сохраняет challenge/response:
   ```
   hostname: CORP\j.doe
   username: j.doe
   challenge: 1a2b3c4d5e6f7081
   response: ...
   ```
5. Конвертируем в hashcat-формат и ломаем:
   ```bash
   hashcat -m 5500 mschapv2.txt rockyou.txt
   ```
6. С найденным паролем — доступ к корпоративным сервисам, VPN, почте.

## Rogue AP и обход проверки сертификата

Почему клиент вообще подключается к фейковому серверу? Потому что:

- в профиле Wi-Fi **не включена проверка сертификата сервера** (или указан неправильный CA/имя);
- пользователь нажал «Подключиться» на всплывающем предупреждении;
- используется EAP-метод без серверного сертификата (LEAP, EAP-MD5).

Также практикуют **KARMA-атаки** (отвечать на все probe-запросы), **evil twin** с deauth жертвы от легитимной AP и **downgrade** на более слабый EAP. `eaphammer` умеет `--negotiate balanced`/`weak` для управления даунгрейдом и обхода channel binding.

## Обход NAC на проводе

802.1X защищает и проводной доступ. Обходы:

- **MAC-spoofing**: если порт после аутентификации привязан к MAC, а устройство выключено — клонируем MAC и подключаемся.
- **MAB (MAC Authentication Bypass)**: устройства без supplicant аутентифицируются по MAC; можно подделать MAC принтера/камеры и получить доступ.
- **Hub/sharing**: если за портом разрешено несколько MAC, подключаем коммутатор.
- **Rogue device на уже аутентифицированном порту**.

## Защита

| Мера | Против чего |
|---|---|
| EAP-TLS (взаимный) вместо PEAP | Кража MSCHAPv2 |
| Проверка сертификата сервера на клиентах | Rogue AP |
| TEAP / channel binding | Релеинг EAP |
| MFA для Wi-Fi/VPN | Компромисс пароля |
| MAB + профилирование устройств | Подмена MAC |
| Мониторинг rogue AP | Фейковые точки |
| Короткие session timeout | Захват после аутентификации |

Главное: **включить на клиентах проверку сертификата RADIUS-сервера** (доверенный CA + имя сервера). Это ломает rogue AP-атаку на PEAP.

## Частые ошибки и подводные камни

- **Забывать про deauth.** Легитимная AP держит клиента; для подключения к фейку нужен deauth (с оговоркой про PMF/WPA3).
- **Путать EAPoL и RADIUS-трафик.** Клиент говорит EAPoL, сервер — RADIUS (UDP/1812).
- **Ожидать, что eaphammer «просто работает».** Нужны правильные сертификаты, драйверы и карта с поддержкой AP-режима.
- **Игнорировать WPA3/PMF.** При включённом PMF deauth не проходит, и часть атак усложняется.
- **Ломать MSCHAPv2 без правил.** Используйте `best64`/`OneRuleToRuleThemAll` и корпоративные словари.
- **Считать MAB надёжным.** MAC легко подделать.

## Что дальше / решение

802.1X — это про то, как enterprise-сеть пытается «закрыться», и почему это часто не работает. Изучите `network-wpa3` (PMF, SAE), `network-evil-twin` и `network-nac-bypass`. Для защиты разверните EAP-TLS с device-сертификатами, включите проверку сервера на клиентах, используйте TEAP и MFA. Для CTF/лаб потренируйтесь поднимать FreeRADIUS + hostapd-mana и проходить полный цикл захвата.

|---|---|---|
| EAP-TLS | Высокая | Взаимные сертификаты |

| 1813/udp | RADIUS accounting |

## Комбинация с беспроводными атаками

802.1X-атаки редко идут в одиночку — их комбинируют с классикой Wi-Fi:

- **Deauth + evil twin.** Отправляем deauth легитимной AP (если PMF выключен), жертва переподключается к нашему rogue AP. `aireplay-ng --deauth` или `mdk4`.
- **KARMA.** Отвечаем на все probe-запросы клиента, вынуждая его подключиться к нам без знания SSID.
- **Captive portal phishing.** Rogue AP отдаёт фейковый портал, собирающий креды (против гостевых сетей).
- **WPA3/PMF обход.** При включённом PMF deauth не работает; тогда используют другие векторы (например, SAE-атаки или downgrade-транзишн). См. `network-wpa3`.
- **EAP identity harvesting.** Даже без захвата пароля eaphammer собирает доменные логины через EAP-identity — полезно для дальнейшего phishing/Password Spray.

Связка «evil twin + 802.1X-фейк» даёт доменные креды без единого касания внутренней сети.

## Лаборатория: rogue RADIUS

1. Установите `hostapd-mana` и `eaphammer` на Linux с картой в AP-режиме.
2. Поднимите FreeRADIUS как легитимный сервер (для сравнения) с сертификатом.
3. Клиент (тестовая Windows-машина) с профилем Wi-Fi **без** проверки сертификата сервера.
4. Запустите `eaphammer --auth wpa-eap --essid CORP --creds`; при необходимости добавьте deauth.
5. Клиент подключится и отдаст MSCHAPv2; проверьте лог eaphammer.
6. Взломайте: `hashcat -m 5500 mschapv2.txt rockyou.txt`.
7. Включите в профиле клиента проверку сертификата (CA + имя) и повторите — подключение к фейку не произойдёт.

Так вы на практике видите, что именно защищает клиент и как это ломается.
