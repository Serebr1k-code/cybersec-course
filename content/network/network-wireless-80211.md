## Вопрос, с которого всё начинается

Wi-Fi вокруг нас повсюду, и он тоже «сетевой протокол» — со своими кадрами, рукопожатием и слабостями. Как из эфира получить материал для взлома пароля сети? И почему WPA2-«рукопожатие» можно собрать, даже не подключаясь?

Разберём на конкретном примере: аудит одной WPA2-сети.

## Наш пример: сеть HomeWiFi

Пусть есть точка доступа (AP, Access Point) с именем сети (**SSID**) `HomeWiFi` и клиент — ноутбук. Чтобы работать с Wi-Fi, сетевую карту переводят в **monitor mode** — режим, в котором она принимает **все** кадры эфира, а не только адресованные ей.

Инструмент `airmon-ng` создаёт такой интерфейс:

```
$ sudo airmon-ng start wlan0
PHY     Interface   Driver      Chipset
phy0    wlan0       iwlwifi     Intel ...
        (monitor mode enabled on wlan0mon)
```

Дальше смотрим, что вообще есть в эфире.

## Шаг 1: разведка эфира

Кадры Wi-Fi (802.11) бывают нескольких типов. Нас интересуют **beacon** — периодические объявления точек доступа. Сканер `airodump-ng` собирает их в таблицу:

```
$ sudo airodump-ng wlan0mon
 BSSID              PWR  Beacons  #Data  CH  ENC   CIPHER  AUTH  ESSID
 AA:BB:CC:11:22:33  -42      120     14   6  WPA2  CCMP    PSK   HomeWiFi
 DE:AD:BE:EF:00:01  -71       88      0  11  WPA2  CCMP    PSK   GuestNet
```

Разберём колонки:

- **BSSID** — MAC точки доступа;
- **PWR** — уровень сигнала (чем ближе к 0, тем сильнее);
- **CH** — канал;
- **ENC/CIPHER/AUTH** — тип шифрования (`WPA2`), шифр (`CCMP` = AES) и аутентификация (`PSK` = общий пароль);
- **ESSID** — имя сети.

Мы нашли цель `HomeWiFi` на канале 6.

## Шаг 2: что такое 4-way handshake

WPA2 с общим паролем (PSK) работает так. Из пароля и SSID выводится **PMK** (Pairwise Master Key). При подключении клиента и AP обмениваются **четырьмя кадрами** — это и есть **4-way handshake**:

1. AP → клиент: случайное число **ANonce**;
2. клиент → AP: своё число **SNonce** + **MIC** (контрольная метка);
3. AP → клиент: ключ для шифрования;
4. клиент → AP: подтверждение.

Ключевое: в этом обмене участвует **MIC**, вычисленный из PMK. Пароль по эфиру **не идёт**, но handshake содержит всё, чтобы **оффлайн** проверить кандидата: если из угаданного пароля получается тот же MIC — пароль верный.

То есть перехваченный handshake — это «зашифрованный замок», к которому можно подбирать ключ оффлайн.

## Шаг 3: как поймать handshake

Чтобы handshake случился, клиент должен подключаться. Можно **подождать** его естественного подключения, а можно **ускорить** — отправить **deauth**-кадр: поддельное «отключение» от имени точки доступа. Клиент переподключится и заново пройдёт handshake.

```
$ sudo aireplay-ng --deauth 5 -a AA:BB:CC:11:22:33 wlan0mon
```

Параллельно пишем эфир в файл:

```
$ sudo airodump-ng -c 6 --bssid AA:BB:CC:11:22:33 -w home wlan0mon
```

Когда handshake пойман, `airodump-ng` покажет `WPA handshake: AA:BB:CC:11:22:33`. Теперь у нас есть файл `home-01.cap` с handshake — материал для оффлайн-подбора.

## Шаг 4: PMKID — без клиента

Есть ещё элегантнее. При подключении AP в некоторых реализациях отдаёт **PMKID** — идентификатор, тоже зависящий от пароля. Его можно запросить **самому**, без ожидания клиента: подключаемся к AP (первый кадр handshake) и получаем PMKID в ответе.

Современный инструмент `hcxdumptool` умеет это делать:

```
$ hcxdumptool -i wlan0mon -w capture.pcapng
```

Он в пассивно-активном режиме собирает и handshake, и PMKID. Прелесть PMKID в том, что **не нужен ни один клиент** — достаточно самой точки доступа.

## Шаг 5: оффлайн-подбор

Полученный материал конвертируют в формат hashcat (режим `22000`) и подбирают пароль **локально**, на GPU:

```
$ hashcat -m 22000 capture.22000 wordlist.txt
```

Это ключевой момент методологии: **взлом WPA2 — всегда оффлайн**. Онлайн-атака на Wi-Fi бессмысленна. Результат зависит только от словаря и мощности железа: слабый пароль (из словаря) подбирается за минуты, длинный случайный — практически нет.

## Шаг 6: evil twin и WPA3

**Evil twin** — это поддельная точка доступа с тем же SSID. Клиенты автоматически подключаются к ней (она «знакомая»), и дальше мы применяем всё, что умеем: captive portal для сбора пароля, MITM для трафика. Разберём подробно в следующем уроке.

**WPA3** меняет игру: вместо PSK-handshake используется **SAE** (Simultaneous Authentication of Equals, «Dragonfly»). Его важное свойство — **устойчивость к оффлайн-подбору**: перехваченное рукопожатие не даёт возможности проверять кандидатов локально. Даже слабый пароль нельзя брутить оффлайн — только онлайн-взаимодействие, которое можно ограничить. Но WPA3 требует поддержки на обеих сторонах, поэтому часто включают **переходный режим** WPA2/WPA3 — и тогда WPA2-атаки снова работают.

## Шаг 7: защита

- **WPA3 или WPA2 с длинным случайным паролем** — оффлайн-подбор становится нереальным.
- **PMF** (Protected Management Frames, 802.11w) — защищает от deauth-атак.
- **Отключить WPS** — PIN-WPS брутфорсится.
- **Не использовать переходный режим** без необходимости.
- **Мониторинг:** детект deauth-штормов, поддельных AP с тем же SSID (evil twin), rogue-устройств.

## Шаг 8: важные мелочи эфира

Несколько деталей, которые пригодятся на практике. **Канал важен**: если клиент и точка на канале 6, а монитор слушает канал 1, ты не увидишь ничего. `airodump-ng` можно запустить с `--band abg`, чтобы охватить сразу несколько диапазонов, но одна карта ловит только один канал в момент времени. **Скрытые SSID** (`<length: 0>`) не означают невидимость: имя всё равно видно в кадрах, когда клиент подключается. **MAC-фильтрация** легко обходится — разрешённый MAC можно подсмотреть в эфире и подделать. **5 ГГц** даёт больше каналов и меньше помех, но и радиус меньше.

Все эти детали напоминают: Wi-Fi-безопасность — это не только пароль, но и настройка эфира, и защита управляющих кадров.

## Что мы теперь знаем

- Wi-Fi — это кадры 802.11; beacon-кадры выдают точки доступа.
- WPA2-PSK при подключении проходит 4-way handshake с MIC, зависящим от пароля.
- Перехваченный handshake или PMKID даёт материал для **оффлайн**-подбора.
- Deauth заставляет клиента переподключиться и выдать handshake.
- PMKID собирается без клиента, только с AP.
- WPA3/SAE закрывает оффлайн-подбор, но переходный режим возвращает WPA2-дыры.
