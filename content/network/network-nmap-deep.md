## Вопрос, с которого всё начинается

Ты уже умеешь находить открытые порты и определять версии сервисов. Но nmap умеет куда больше: сам доставать данные с сервиса скриптами, определять операционную систему, сканировать UDP и обходить фильтры. Как этим пользоваться и когда — разберём в этом уроке.

## Наш пример: HTTP-сервер на порту 8000

Возьмём хост `127.0.0.1`, на котором на порту 8000 отвечает HTTP-сервис. Сначала убедимся, что он жив, и посмотрим базовую версию:

```
$ nmap -sV -p 8000 127.0.0.1
PORT     STATE SERVICE VERSION
8000/tcp open  http    SimpleHTTPServer 0.6 (Python 3.14.4)
```

Обычный `-sV` уже дал версию. Но что именно отдаёт сервис — заголовок страницы, HTTP-заголовки — можно узнать глубже. Для этого у nmap есть **NSE**.

## Шаг 1: NSE — скриптовый движок

**NSE** (Nmap Scripting Engine) — это встроенный Lua-движок со сотнями готовых скриптов. Скрипты умеют проверять уязвимости, собирать баннеры, находить общие файлы, перебирать учётки. Подключаются ключом `--script`:

```
$ nmap -sV -p 8000 --script=http-title,http-headers 127.0.0.1
PORT     STATE SERVICE VERSION
8000/tcp open  http    SimpleHTTPServer 0.6 (Python 3.14.4)
|_http-title: Directory listing for /
|_http-server-header: SimpleHTTP/0.6 Python/3.14.4
| http-headers:
|   Server: SimpleHTTP/0.6 Python/3.14.4
|   Content-type: text/html; charset=utf-8
|_  (Request type: HEAD)
```

Скрипт `http-title` достал заголовок страницы (`Directory listing for /` — листинг каталога, частая утечка), а `http-headers` — все заголовки ответа. Обрати внимание на формат вывода: дерево с вертикальными чертами — это результат скрипта, привязанный к порту.

Скрипты бывают по категориям, и категорию можно подключать целиком:

- `default` — безопасные и полезные (запускаются с `-sC`).
- `safe` — не влияют на сервис.
- `vuln` — проверки уязвимостей.
- `intrusive` — могут шуметь и ломать; только с разрешения.

Так, `nmap -sV -sC -p 8000 127.0.0.1` запустит набор скриптов по умолчанию.

## Шаг 2: тайминги

Скорость скана управляется **шаблонами тайминга** `-T0`…`-T5`:

| Шаблон | Смысл |
|--------|-------|
| `-T0` / `-T1` | параноидальный / хитрый: очень медленно, для обхода IDS |
| `-T2` | вежливый: медленнее обычного |
| `-T3` | нормальный (по умолчанию) |
| `-T4` | агрессивный: быстро, для быстрых сетей |
| `-T5` | бешеный: максимально быстро, часто теряет точность |

Правило: в локальной сети бери `-T4`, через интернет — `-T3`, при активном IDS — `-T2` и ниже. Слишком агрессивный скан теряет пакеты и даёт ложные `filtered`.

## Шаг 3: определение операционной системы

Ключ `-O` включает **OS-фингерпринт**: nmap анализирует особенности стека TCP/IP (размер окна, порядок опций, TTL) и сравнивает с базой отпечатков операционных систем. Требует прав root, потому что шлёт «сырые» пакеты.

```
$ sudo nmap -O 10.0.0.20
Running: Linux 5.X
OS CPE: cpe:/o:linux:linux_kernel:5
OS details: Linux 5.4 - 5.15
```

Точность не абсолютная: nmap даёт диапазон версий и **confidence** (уверенность). Полезно для выбора эксплойтов, зависящих от платформы.

## Шаг 4: UDP-сканирование

Многие сервисы живут только на UDP. Ключ `-sU` включает UDP-скан, но он медленный: у UDP нет рукопожатия, и открытый порт может вообще не ответить. Поэтому обычно сканируют только важные UDP-порты:

```
$ sudo nmap -sU -p 53,123,161 10.0.0.20
PORT    STATE SERVICE
53/udp  open  domain
161/udp open  snmp
```

Открытый `snmp` (161/udp) — частый вход: со стандартным community-строкой `public` можно выкачать много информации о хосте.

## Шаг 5: обход фильтров

Когда между тобой и целью стоит файрвол или IDS, помогает:

- **Фрагментация.** `-f` разбивает пакеты на мелкие фрагменты — простые фильтры не собирают их обратно.
- **Подмена источника порта.** `--source-port 53` заставляет пакеты выглядеть как DNS-ответы, которые часто пропускают.
- **Приманки (decoys).** `-D RND:10` сканирует от имени десяти случайных адресов, и в логах цель видит не тебя.
- **Добавление данных.** `--data-length 25` меняет размер пакетов, ломая простые сигнатуры.

## Шаг 6: скрипты vuln на практике

Отдельно стоит категория `vuln` — проверки известных уязвимостей. Она объединяет скрипты для конкретных сервисов и CVE. Запуск:

```
$ nmap -sV --script=vuln -p 445 10.0.0.30
```

Такой скан проверяет, например, SMB на уязвимости типа MS17-010 (EternalBlue), и в выводе пишет `VULNERABLE` с идентификатором CVE. Это удобно для быстрой триажной проверки, но не заменяет полноценный сканер уязвимостей: NSE знает ограниченный набор проверок.

Важно: часть скриптов категории `vuln` относятся к `intrusive` и могут уронить сервис (например, вызвать отказ в обслуживании при проверке). Поэтому на боевой цели их запускают только с письменного разрешения и вне критичного времени.

## Шаг 7: как читать вывод скриптов

Вывод NSE привязывается к порту деревом:

- `|` — продолжение строки результата.
- `|_` — последняя строка скрипта.
- Отступ показывает вложенность полей.

Именно поэтому результат выглядит как «ёлочка». Если скрипт ничего не вернул, строки с `|` не появятся вовсе — это не ошибка, а отсутствие находки.

## Шаг 8: практический сценарий целиком

Соберём всё вместе. Допустим, есть подсеть `10.0.0.0/24`, и нужно понять, что в ней есть, не поднимая тревогу. Действуем так:

1. **Обнаружение хостов** без сканирования портов: `nmap -sn 10.0.0.0/24`. Быстро находим живые адреса.
2. **Быстрый скан топ-портов** по живым хостам: `nmap -sS --top-ports 100 -T3 -oA quick 10.0.0.0/24`. Умеренный тайминг, результат в файл.
3. **Уточнение версий** только для найденных открытых портов: `nmap -sV -sC -p <список> 10.0.0.10`.
4. **Точечные проверки** скриптами: `--script=http-title` на веб-порты, `--script=smb-*` на 445.
5. **UDP-добор** по важным портам: `sudo nmap -sU -p 53,123,161 10.0.0.10`.

Такой порядок экономит время: тяжёлые шаги (версии, скрипты, UDP) применяются только к реально найденным целям. И на каждом шаге результат сохраняется в файл, чтобы его читал следующий инструмент, а не ты глазами. Если скан прерывается на середине, ты не теряешь уже собранные данные и продолжаешь с нужного места.

## Что мы теперь знаем

По-простому:

1. NSE (`--script`) расширяет nmap до проверки уязвимостей и сбора данных.
2. Категории скриптов: `default`, `safe`, `vuln`, `intrusive`.
3. Тайминги `-T0`…`-T5` задают скорость и заметность.
4. `-O` определяет ОС по отпечатку стека TCP/IP.
5. `-sU` сканирует UDP-порты (DNS, SNMP, NTP).
6. Обход: `-f`, `--source-port`, `-D`, `--data-length`.

## На что смотреть дальше

- **Сначала `-sC`, потом точечные скрипты.** Не запускай всё подряд.
- **`intrusive` — с разрешения.** Такие скрипты могут положить сервис.
- **OS-фингерпринт не точен.** Всегда смотри confidence.
