VLAN — основа сегментации на канальном уровне: один физический коммутатор делится на несколько логических сетей. Но сегментация часто настроена слабо, и атакующий в одном VLAN может «перепрыгнуть» в другой — получить доступ к сегменту с более ценными активами. Этот урок разбирает механику и практические техники.

## Как работает 802.1Q

VLAN-тег — 4 байта между Source MAC и EtherType:

```
| Dst MAC | Src MAC | 802.1Q (4) | EtherType | Payload |
                          ^ TPID=0x8100, PCP, DEI, VLAN ID
```

- **Access-порт:** трафик без тега, коммутатор сам навешивает VLAN.
- **Trunk-порт:** несёт несколько VLAN с тегами (обычно между коммутаторами).
- **Native VLAN:** VLAN для нетегированного трафика на транке (по умолчанию VLAN 1) — ключ к double tagging.

## Виды портов и тегирование

Понимание ролей портов — основа всех атак:

- **Access**: один VLAN, кадры без тега; хост «не знает» про VLAN.
- **Trunk**: несколько VLAN, кадры с тегами; между коммутаторами и к гипервизорам.
- **Hybrid**: смешанный режим (некоторые VLAN тегированы, некоторые — нет).
- **Native VLAN на транке**: нетегированный трафик; если это VLAN 1, double tagging тривиален.

Если порт хоста по ошибке настроен как trunk (или согласован по DTP), хост видит тегированный трафик всех разрешённых VLAN — и может их читать/инжектить.

## DTP и автоматическое согласование

**DTP (Dynamic Trunking Protocol)** от Cisco автоматически согласует режим порта. Если порт в режиме `dynamic auto/desirable`, атакующий может **предложить** стать транком — и коммутатор согласится, отдав доступ ко всем VLAN. Это самая частая и самая простая техника.

Режимы DTP: `trunk`, `access`, `dynamic auto` (ждёт предложения), `dynamic desirable` (сам предлагает), `nonegotiate`. Опасность — в двух «dynamic» режимах: они открывают согласование, которым пользуется атакующий.

## Double tagging (двойной тег)

Идея: атакующий шлёт кадр с **двумя** тегами. Первый тег (его VLAN) снимает первый коммутатор, второй остаётся и попадает в **native VLAN** транка. Так кадр уходит в чужой VLAN, минуя access-порт.

Ограничение: работает в одну сторону (ответы не возвращаются), поэтому подходит для однонаправленных атак (например, подделка ARP/DHCP в чужом сегменте).

## Voice VLAN и PVLAN

Отдельные сценарии сегментации, которые тоже обходятся:

- **Voice VLAN**: телефон в отдельном VLAN; подделка MAC телефона (см. `network-nac-bypass`) даёт доступ.
- **PVLAN (private VLAN)**: изоляция хостов внутри VLAN; при неверной настройке promiscuous-порт становится «мостом».
- **VLAN 1 как native + management**: пользовательский трафик смешивается с управлением — цель атаки.

## Инструменты и команды

Проверить режим порта и DTP:

```bash
# Yersinia: интерактивные L2-атаки (DTP, STP, DHCP)
sudo yersinia -I
#  выбрать dtp -> enabling trunking
```

Создать 802.1Q-интерфейс в чужом VLAN:

```bash
sudo ip link add link eth0 name eth0.100 type vlan id 100
sudo ip link set eth0.100 up
sudo dhclient eth0.100     # попытка получить адрес в VLAN 100
```

Double tagging через Scapy (лаборатория):

```python
from scapy.all import *
pkt = Ether(dst="ff:ff:ff:ff:ff:ff")/Dot1Q(vlan=1)/Dot1Q(vlan=100)/ARP(op=1, pdst="10.0.100.1")
sendp(pkt, iface="eth0")
```

## Разобранный пример: выход из VLAN 10 в VLAN 100

Сценарий: атакующий в VLAN 10, на порту включён `dynamic desirable`.

1. `yersinia -I` → DTP-атака: порт соглашается стать транком.
2. Создаём sub-интерфейс `eth0.100`, поднимаем, запрашиваем DHCP.
3. Получаем адрес в VLAN 100 — сегменте с серверами.
4. Сканируем: `nmap -sn 10.0.100.0/24`, затем атакуем цели.
5. Альтернатива без DTP — double tagging: отправляем кадр с тегами 10 и 100; он выходит в native VLAN.
6. Вывод: слабая настройка портов и native VLAN = VLAN 1 превращают сегментацию в фикцию.

## Лабораторная проверка

Стенд для отработки: два коммутатора (или один с несколькими VLAN), trunk между ними, native VLAN, хост-атакующий и хост-жертва в другом VLAN.

- Проверьте DTP: `yersinia -I` → предложение транка → видите ли тегированные кадры.
- Проверьте double tagging: отправьте кадр с двумя тегами и смотрите ARP-ответ (если есть).
- Убедитесь, что после `switchport nonegotiate` и смены native VLAN атаки перестают работать.

## Защита

- **Отключить DTP:** `switchport nonegotiate`, явные `access`/`trunk` режимы.
- **Сменить native VLAN:** не использовать VLAN 1 как native на транках.
- **Не использовать VLAN 1** для пользовательских портов.
- **BPDU Guard / Root Guard** (для защиты от STP-атак, см. `network-layer2-attacks`).
- **Port security** и ограничение разрешённых VLAN на транках.
- **Мониторинг:** детект DTP-кадров от хостов, необычных тегов.

## Частые ошибки

- **Доверять сегментации по умолчанию.** Без отключения DTP порт может стать транком.
- **Оставлять native VLAN = 1.** Это усиливает double tagging.
- **Ждать двусторонней связи при double tagging.** Атака однонаправленная.
- **Путать access и trunk.** Access не несёт теги от хоста; trunk — несёт.
- **Тестировать атаки на проде** без разрешения.

## Что делать дальше / решение

- **Нужен доступ в чужой VLAN** → DTP (если dynamic) или double tagging.
- **Нужен двусторонний доступ** → только DTP/ошибочный trunk; double tagging односторонний.
- **Нужна защита** → `nonegotiate`, native VLAN ≠ 1, port security, BPDU Guard.
- **Нужна проверка** → лабораторный стенд с двумя VLAN.

## Быстрая шпаргалка

```bash
# DTP: узнать/согласовать транк
sudo yersinia -I          # dtp → enabling trunking
# создать интерфейс в чужом VLAN
sudo ip link add link eth0 name eth0.100 type vlan id 100
sudo ip link set eth0.100 up && sudo dhclient eth0.100
# double tagging (лаборатория)
python3 -c "from scapy.all import *; sendp(Ether(dst='ff:ff:ff:ff:ff:ff')/Dot1Q(vlan=1)/Dot1Q(vlan=100)/ARP(op=1,pdst='10.0.100.1'), iface='eth0')"
# увидеть теги
sudo tcpdump -i eth0 -e -nn
```

## Почему это работает

В основе всех техник — недоверие между уровнем 2 и уровнем 3: коммутатор верит тегам, которые присылает хост, а хост может их подделывать. Как только на порт приходит кадр с «чужим» тегом (или согласуется транк), граница VLAN перестаёт быть барьером. Именно поэтому защита строится на явной конфигурации портов, а не на «сегментации по умолчанию».
