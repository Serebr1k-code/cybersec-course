## Вопрос, с которого всё начинается

На заводе, в энергосети и в умном здании работают **PLC** (программируемые логические контроллеры) — маленькие компьютеры, которые читают датчики и дёргают реле. Общаются они по протоколам, придуманным для надёжности, а не для безопасности. Если атакующий дотянется до сети контроллеров, он может не «украсть данные», а **изменить физический процесс**: закрыть клапан, отключить питание, сорвать технологический цикл.

Этот модуль — про четыре самых распространённых ICS-протокола и про то, как их читать и защищать. Опирается на [`network-module-embedded`](network-module-embedded).

## Общая картина ICS

Промышленная сеть делится на уровни (модель Purdue): датчики и приводы → контроллеры (PLC/RTU) → SCADA/HMI → корпоративная сеть. Каждый уровень говорит своим протоколом:

| Протокол | Домен | Транспорт | Особенность |
|---|---|---|---|
| BACnet | здания (HVAC, доступ) | UDP 47808 | объекты и свойства, broadcast |
| IEC 60870-5-104 | энергетика, телеметрия | TCP 2404 | APCI/ASDU, обмен «станция-контроллер» |
| IEC 61850 (MMS/GOOSE) | подстанции | TCP 102 / L2 | GOOSE — по Ethernet, без IP |
| S7comm | Siemens PLC | TCP 102 (ISO-TSAP) | read/write/stop, загрузка логики |

## Почему это опасно

Все четыре протокола исторически **не имеют аутентификации**. У BACnet достаточно знать объект и свойство, чтобы прочитать или записать значение. У S7comm функция «Stop» останавливает PLC одним пакетом. У IEC 104 команда `C_SC_NA_1` (single command) может переключить выключатель. А **GOOSE** в IEC 61850 передаётся прямо в Ethernet-кадре, поэтому его легко подделать из той же L2-сети.

## Как это выглядит в дампе

```
$ tshark -r ics.pcap -Y "bacnet" -T fields -e ip.src -e bacnet.object.type -e bacnet.property.id
10.0.0.20	0	85
$ tshark -r iec.pcap -Y "iec60870_asdu.typeid==45" -T fields -e ip.dst -e iec60870_asdu.ioa
10.0.0.5	1
$ tshark -r s7.pcap -Y "s7comm.param.func==0x05" -T fields -e ip.src
10.0.0.7
```

`bacnet.object.type==0` — Analog Input, `iec60870_asdu.typeid==45` — одиночная команда (C_SC_NA_1), `s7comm.param.func==0x05` — функция Write Var. Такие фильтры — основа и разбора CTF-дампов, и правил детекта в SOC.

## Правила работы в OT

- **Пассивно**: сначала зеркалируйте трафик, не сканируйте.
- **Read-only**: если нужно активное — только чтение, с согласия заказчика.
- **Не валить**: даже «просто скан» портов может уронить старый PLC.
- **Изолировать**: пентест OT обычно ведут в отдельном сегменте или на стенде-двойнике.

## Куда дальше

Дальше начнём с BACnet — протокола умных зданий, где объекты читаются и пишутся почти без защиты. А пока запомни: ICS-протоколы не имеют аутентификации, и в OT-пентесте безопасность процесса важнее полноты скана.
