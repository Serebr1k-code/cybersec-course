## Вопрос, с которого всё начинается

nmap отлично сканирует один хост или небольшую сеть. Но что делать, если в задании диапазон `/16` — это 65536 адресов? nmap будет идти часами. Для таких задач есть инструменты, рассчитанные на **интернет-масштаб**: masscan и naabu.

В этом уроке мы разберём, чем они отличаются от nmap, как задавать диапазоны и как встроить их в разведку.

## Наш пример: быстро находим открытый порт

Возьмём naabu — высокоскоростной сканер портов, написанный на Go. Начнём с локального хоста и топ-100 портов:

```
$ naabu -host 127.0.0.1 -top-ports 100 -silent
127.0.0.1:8000
```

Формат вывода — просто `хост:порт` для каждого открытого порта. `-top-ports 100` задаёт набор популярных портов, `-silent` убирает баннер и оставляет только результат. Уже видно принципиальное отличие от nmap: **никаких версий, никаких состояний портов** — только «этот порт открыт».

## Шаг 1: зачем нужны такие сканеры

Скорость достигается за счёт асинхронности. nmap ведёт состояние каждого соединения и ждёт ответов; masscan и naabu шлют пакеты потоком и не хранят соединения. Результат — миллионы пакетов в секунду и полный обход больших диапазонов за минуты.

Цена скорости:

- **Нет определения версий.** masscan/naabu только говорят «открыт». Версии уточняет nmap потом.
- **Шумность.** Такой поток пакетов почти наверняка попадёт в IDS и системы детекта сканирования.
- **Точность.** При высокой скорости возможны пропуски; приходится подбирать `--rate`.

Поэтому их роль в разведке — **первый, грубый проход**: найти живые хосты и открытые порты. Затем точечно по найденному идёт nmap с `-sV -sC`.

## Шаг 2: masscan — синтаксис

masscan работает с диапазонами и требует задать порты и скорость:

```
$ masscan 10.0.0.0/16 -p80,443,22 --rate 10000 -oL out.txt
```

Разбор: `10.0.0.0/16` — диапазон; `-p80,443,22` — порты; `--rate 10000` — 10 тысяч пакетов в секунду; `-oL out.txt` — вывод в «list»-формате, по строке на каждый найденный порт. Без `--rate` masscan может залить сеть и обрушить оборудование, поэтому скорость задавать обязательно.

masscan умеет и массовую проверку одного порта по всему интернету (`-p443 0.0.0.0/0`), но это уже не пентест, а исследование — и делать так без явного разрешения нельзя.

## Шаг 3: naabu — синтаксис

naabu ближе по духу к экосистеме ProjectDiscovery (httpx, nuclei). Он читает цели из файла, умеет исключения и вывод в JSON:

```
$ naabu -list targets.txt -top-ports 1000 -exclude-ports 21 -o result.txt
$ naabu -host example.com -json -silent
```

`-list` — файл со списком целей, `-top-ports 1000` — тысяча популярных портов, `-exclude-ports` — исключить порты, `-json` — машиночитаемый вывод. naabu сам по себе часто используют как первый шаг пайплайна: его результат подают в httpx, который проверяет, какие порты говорят по HTTP.

## Шаг 4: связка с nmap

Классическая схема из двух шагов:

```
# шаг 1: быстро находим открытые порты по всей сети
naabu -list subnet.txt -top-ports 1000 -o ports.txt

# шаг 2: точечно определяем версии на найденном
nmap -sV -sC -iL ports.txt -oA detailed
```

Первый шаг дешёвый и быстрый, второй — дорогой, но применяется только к реально найденным целям. Так экономятся часы.

## Шаг 5: что писать в отчёт и как не навредить

Три правила безопасного использования:

- **Задавай скорость осознанно.** Слишком высокий `--rate` перегружает каналы и устройства.
- **Ограничивай диапазон.** Сканируй только то, что в scope; `--exclude` — твой друг.
- **Не путай «открыт порт» и «есть уязвимость».** Сканер нашёл дверь, а не дыру в ней.

В отчёте указывай не только результат, но и параметры скана: диапазон, порты, скорость. Иначе результат нельзя воспроизвести и перепроверить.

## Шаг 6: если не сработало

Быстрые сканеры дают сбои, которые легко принять за «портов нет». Разберём частые случаи.

**Слишком высокая скорость → пропуски.** На перегруженном канале masscan теряет ответы. Снижаем `--rate` и повторяем — если пропуски исчезли, дело было в скорости:

```
$ masscan 10.0.0.0/24 -p22,80,443 --rate 100000 -oL fast.txt
$ wc -l fast.txt
17
$ masscan 10.0.0.0/24 -p22,80,443 --rate 1000 -oL slow.txt
$ wc -l slow.txt
23
```

На медленном прогоне нашлось больше хостов — значит, быстрый «проглотил» часть ответов.

**Порт открыт, но ответа нет.** Некоторые хосты молчат на ICMP-пинг, и naabu пропускает их. Тогда отключают зависимость от пинга или сразу запускают полный nmap по подозрительному диапазону.

**Ложные «открыто».** И masscan, и naabu иногда показывают порт открытым там, где его нет. Поэтому результат быстрого скана всегда подтверждают вторым, точным проходом.

**Правило:** вывод массового сканера — это *гипотеза* о сети, а не факт. Факт даёт только подтверждающий скан `nmap -sV`, поэтому всегда планируй второй, точный проход.

**UDP-скан не отвечает.** Для UDP быстрые сканеры мало полезны: открытый порт часто молчит и не шлёт ответа. masscan умеет `-pU:53`, но результат неоднозначен — UDP-сервисы надёжнее проверять прицельно (`nmap -sU --top-ports 50`), а не массово. То же касается фильтрующих файрволов: `DROP` не отличить от закрытого порта, поэтому отсутствие ответа — не доказательство.

## naabu или masscan: что выбрать

Оба сканера быстрые, но для разных сценариев:

| Критерий | masscan | naabu |
|---|---|---|
| Скорость | до миллионов пакетов/с | до сотен тысяч пакетов/с |
| Механика | «сырые» пакеты по диапазонам | TCP SYN/connect |
| Вывод | list / JSON / grepable | text / JSON |
| Пайплайн | отдельный инструмент | часть экосистемы ProjectDiscovery |
| Права | нужен root | root для SYN, иначе connect |

Правило простое: **masscan** — когда надо «прочесать» огромный диапазон (`/8`) максимально быстро. **naabu** — когда цель конкретнее и результат пойдёт в httpx/nuclei. В обычном пентесте `/16` чаще берут naabu, а masscan оставляют для интернет-масштаба.

## Шаг 7: пайплайн naabu → httpx → nmap

Быстрый скан бесполезен, пока не превратишь «порт открыт» в понятную цель. Соберём полный конвейер веб-разведки.

Сначала naabu находит порты и пишет их в файл:

```
$ naabu -list subnet.txt -top-ports 1000 -silent -o ports.txt
$ wc -l ports.txt
142
```

Затем httpx проверяет, какие из них говорят по HTTP, и снимает код ответа и заголовок:

```
$ httpx -l ports.txt -silent -status-code -title
https://10.0.0.5 [200] [Dashboard]
http://10.0.0.7:8080 [403] [nginx]
```

Теперь видно не просто порты, а живые веб-сервисы. Только их передаём в nmap для точного определения версий:

```
$ nmap -sV -sC -iL <(grep -oE '^[0-9.]+' ports.txt) -oA web
```

Итог: тысячи адресов сузились до десятка реальных веб-целей — без часов ожидания nmap по всему диапазону.

## Шаг 8: установка и типичные грабли

Оба инструмента ставятся одной строкой (Go уже установлен):

```
$ go install -v github.com/projectdiscovery/naabu/v2/cmd/naabu@latest
$ go install -v github.com/projectdiscovery/httpx/cmd/httpx@latest
```

Частые ошибки:

- **naabu требует root для SYN-скана.** Без прав он падает на `socket: operation not permitted` — запускай через `sudo` либо добавь `-scan-type c` для connect-скана.
- **`--rate` выше возможностей канала** даёт пропуски (см. Шаг 6).
- **Узкий `-top-ports`** пропускает сервис на нестандартном порту — при инвентаризации лучше `-p-`.

## Что попадёт в отчёт

Массовый скан — это ещё и про воспроизводимость. В отчёт по каждому прогону выноси:

- **Команду целиком** — диапазон, порты, `--rate`.
- **Время и длительность** — по нему видно, укладывался ли скан в согласованное окно.
- **Число найденных хостов/портов** — динамика между прогонами.
- **Расхождения** с подтверждающим nmap-сканом — ложные и пропущенные порты.

Без параметров скан невоспроизводим, и его результат нельзя ни перепроверить, ни защитить в отчёте.

## Что мы теперь знаем

По-простому:

1. masscan/naabu — высокоскоростные сканеры для больших диапазонов.
2. Они не определяют версии — только «порт открыт».
3. Скорость задаётся `--rate` (masscan) и `-top-ports` (naabu).
4. Типовая связка: сначала быстрый скан, потом nmap с `-sV`.
5. Шумность — обратная сторона скорости; применяй с оглядкой на scope.
6. Пайплайн naabu → httpx → nmap превращает порты в понятные веб-цели.
7. В отчёт выносят команду, скорость и расхождения с подтверждающим сканом — иначе прогон невоспроизводим.

## На что смотреть дальше

- **Не гонись за скоростью.** Перегрузка сети — реальный вред, а не «просто скан».
- **naabu + httpx + nuclei** — готовый пайплайн для веб-разведки.
- **Проверяй результат nmap-ом.** Скорость даёт ложные срабатывания.
- **Учитывай egress-фильтры.** Если наружу открыт только 443, массовый скан по всем портам даст мало — начинай с разрешённых.
