## Вопрос, с которого всё начинается

Мы умеем читать один пакет по байтам. Но в реальной задаче пакетов тысячи. Как из всего трафика сети выловить только нужное — скажем, чьё-то скачивание файла — и сохранить его для анализа?

Для этого есть `tcpdump` — консольный перехватчик трафика. Он умеет слушать интерфейс, фильтровать пакеты по правилам и записывать их в файл. В этом уроке мы поймаем скачивание файла и достанем его из захвата.

## Наш пример: поймать скачивание файла

Задача: в сети кто-то скачивает файл по HTTP. Мы должны поймать трафик, сохранить и вытащить файл. Начнём с базового захвата.

## Шаг 1: базовый захват

```
$ sudo tcpdump -i eth0 -n -w capture.pcap
tcpdump: listening on eth0, link-type EN10MB (Ethernet), snapshot length 262144 bytes
```

Разбираем флаги:

- `-i eth0` — слушать интерфейс `eth0` (узнать список: `tcpdump -D`).
- `-n` — не превращать адреса и порты в имена (быстрее и без DNS-запросов).
- `-w capture.pcap` — записать пакеты в файл, а не печатать на экран.

Запись идёт, пока вы не нажмёте `Ctrl+C`. После остановки:

```
^C
42 packets captured
42 packets received by filter
0 packets dropped by kernel
```

Полезно видеть `dropped`: если пакеты теряются, нужно сузить фильтр или увеличить буфер.

## Шаг 2: читаем записанный pcap

Файл `capture.pcap` можно читать тем же `tcpdump` флагом `-r`:

```
$ tcpdump -r capture.pcap -n
14:22:31.412 IP 10.0.0.5.51234 > 93.184.216.34.80: Flags [P.], length 74
14:22:31.420 IP 93.184.216.34.80 > 10.0.0.5.51234: Flags [P.], length 1460
14:22:31.421 IP 93.184.216.34.80 > 10.0.0.5.51234: Flags [.], length 1460
```

Видим поток данных: клиент запросил, сервер отвечает двумя большими сегментами по 1460 байт — похоже на скачивание. Этот файл потом откроют в Wireshark или обработают скриптом.

## Шаг 3: фильтры BPF

Печатать всё — шумно. `tcpdump` фильтрует пакеты языком **BPF** (Berkeley Packet Filter). Основные выражения:

- `host 93.184.216.34` — только трафик с этим адресом (в обе стороны).
- `src host 10.0.0.5` — только от этого адреса.
- `dst port 80` — только на порт 80.
- `net 10.0.0.0/24` — вся подсеть.
- `tcp`, `udp`, `icmp` — по протоколу.

Пример: поймать только HTTP-трафик к серверу:

```
$ sudo tcpdump -i eth0 -n 'host 93.184.216.34 and port 80'
```

Правило берётся в кавычки, чтобы оболочка не трогала скобки и пробелы.

## Шаг 4: комбинируем условия

Фильтры соединяются логическими операторами:

- `and` (или `&&`) — оба условия.
- `or` (или `||`) — любое из условий.
- `not` (или `!`) — исключить.

Примеры:

```
$ sudo tcpdump -i eth0 -n 'tcp and not port 22'
$ sudo tcpdump -i eth0 -n 'port 80 or port 443'
$ sudo tcpdump -i eth0 -n 'src net 10.0.0.0/24 and dst port 53'
```

Последний фильтр поймает DNS-запросы из локальной сети — полезно при разборе, кто и что запрашивает.

## Шаг 5: смотрим содержимое

Чтобы увидеть данные пакета, есть `-A` (ASCII) и `-X` (hex + ASCII):

```
$ sudo tcpdump -i eth0 -n -A 'port 80' -c 20
GET /file.zip HTTP/1.1
Host: example.com
User-Agent: curl/8.4.0
```

`-c 20` — остановиться после 20 пакетов. Мы видим HTTP-запрос на скачивание `file.zip`.

## Шаг 6: извлекаем файл

Самый простой способ достать скачанный файл — открыть pcap в Wireshark: **File → Export Objects → HTTP**. Wireshark соберёт файл из сегментов автоматически.

Из командной строки помогает `tcpflow` или `tcpick`, которые собирают потоки в файлы:

```
$ tcpflow -r capture.pcap -o out/
$ ls out/
10.0.0.5.51234-93.184.216.34.0080
```

В файле — восстановленный HTTP-обмен, включая тело ответа (сам файл).

## Таблица флагов tcpdump

| Флаг | Значение |
|------|----------|
| `-i` | интерфейс |
| `-n` | не разрешать имена |
| `-w file` | писать в pcap |
| `-r file` | читать из pcap |
| `-c N` | остановиться после N пакетов |
| `-A` | содержимое в ASCII |
| `-X` | содержимое в hex+ASCII |
| `-s 0` | захватывать пакет целиком |
| `-D` | список интерфейсов |

## Почему tcpdump, а не Wireshark

Wireshark удобен, но его нет на серверах без графики. `tcpdump` есть почти везде, работает через SSH и умеет писать pcap, который потом открывают в Wireshark. Рабочий процесс такой: **захват на сервере — анализ на машине аналитика**.

## Расширенные фильтры

Кроме базовых, BPF умеет многое:

- `tcp[tcpflags] & tcp-syn != 0` — только SYN-пакеты (признак сканирования).
- `ip[8] < 10` — пакеты с малым TTL.
- `greater 1000` — пакеты длиннее 1000 байт.
- `ether host 00:11:22:33:44:55` — по MAC-адресу.

Эти выражения читают байты заголовка напрямую: `ip[8]` — девятый байт IP-заголовка, то есть TTL. Так отбирают очень специфичный трафик.

## Сниффинг на коммутаторе

Важный нюанс: в коммутируемой сети вы видите только свой трафик. Чтобы поймать чужой, нужен либо зеркальный порт (SPAN), либо ARP-spoof, либо режим монитора на Wi-Fi. `tcpdump` показывает то, что дошло до интерфейса, — за остальное отвечает настройка сети.

## Как не потерять пакеты

На быстрых сетях `tcpdump` может не успевать. Помогают:

- **Узкий фильтр** — меньше пакетов к обработке.
- **Большой буфер** (`-B 4096`) — больше памяти под захват.
- **`-s 0`** — захват пакета целиком.
- **Запись на диск** (`-w`), а не печать на экран.

## Короткий итог по практике

Запомните рабочий цикл: сузить фильтр → записать в pcap (`-w`) → проанализировать (`-r` или Wireshark). Фильтр на захвате экономит диск и не теряет пакеты, а pcap позволяет вернуться к разбору позже и прогнать его скриптом.

## Что делать с pcap дальше

Записанный pcap — это «сырьё» для нескольких инструментов:

- **Wireshark** — графический разбор, follow stream, экспорт объектов.
- **`tshark`** — тот же разбор из командной строки.
- **`scapy`** — обработка скриптом (например, вытащить все URL).
- **`tcpflow`/`tcpick`** — сборка потоков в файлы.

Так один захват превращается в набор данных, с которым можно работать любым способом.

## Что мы теперь знаем

По-простому:

1. `tcpdump -i ... -w` записывает трафик в pcap.
2. `-r` читает записанный файл.
3. BPF-фильтры (`host`, `port`, `net`) отсекают лишнее.
4. `and`/`or`/`not` комбинируют условия.
5. Файлы из HTTP достают через Wireshark Export Objects или `tcpflow`.

## На что смотреть дальше

- **Фильтруйте на захвате.** Меньше данных — быстрее и без потерь.
- **Записывайте в pcap.** К нему можно вернуться и разобрать в Wireshark.
- **Следите за `dropped`.** Потери пакетов портят анализ.
- **Берите `-s 0`.** Иначе длинные пакеты обрежутся.

## Куда дальше

В следующем уроке мы возьмём **Wireshark и tshark** и научимся разбирать трафик графически: display-фильтры, follow stream и статистика. А пока запомни главное: `tcpdump` ловит и фильтрует трафик, а `-w`/`-r` позволяют сохранить его для глубокого анализа.

## Где пригодится

- **CTF (Network / Forensics):** захват и разбор трафика.
- **Пентест:** перехват данных в сети, анализ протоколов.
- **Blue team / SOC:** запись трафика для расследования инцидента.
- **Администрирование:** диагностика сетевых проблем.
