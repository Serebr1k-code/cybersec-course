## Вопрос, с которого всё начинается

У провайдера тысячи клиентов, и у многих — одинаковые внутренние адреса, например `10.0.0.0/24`. Как он не путает их между собой и не смешивает их трафик? Ответ — две технологии: **MPLS** (коммутация по меткам) и **VRF** (отдельные таблицы маршрутов). Вместе они образуют изоляцию, на которой держатся провайдерские сети.

Но изоляция — не магия. Она держится на корректной конфигурации, и ошибка в ней превращает «непрозрачную» сеть в проходимую. Разберём, как устроены метки и таблицы маршрутов и где их ломают.

Этот урок продолжает [`network-module-routing`](network-module-routing).

## Наш пример: пакет с меткой

Захватываем трафик и смотрим на MPLS-пакеты:

```
$ sudo tcpdump -i eth0 -nn -e 'ether proto 0x8847' -c 2
14:20:01.001 52:54:00:aa:bb:cc > 08:00:27:11:22:33, ethertype MPLS unicast (0x8847), length 102
14:20:01.002 52:54:00:aa:bb:cc > 08:00:27:11:22:33, ethertype MPLS unicast (0x8847), length 102
```

EtherType `0x8847` — это MPLS. Вместо анализа IP на каждом хопе пакет несёт короткую **метку**, по которой коммутатор решает, куда его отправить. Разберём, как это устроено.

## Шаг 1: MPLS и метки

**MPLS** (Multiprotocol Label Switching) коммутирует по **метке** фиксированной длины (20 бит) вместо разбора IP. Метка вставляется между L2- и L3-заголовками:

```text
+--------+--------+---------+--------+----------+------+
| Dst MAC| Src MAC| 0x8847 | Label  | IP-пакет | FCS  |
+--------+--------+---------+--------+----------+------+
```

Пакет идёт по заранее построенному **LSP** (Label Switched Path). Роутер на входе в домен (**ingress LER**) навешивает метку, промежуточные (**LSR**) меняют её (**swap**), на выходе (**egress LER**) снимают.

Посмотрим стек меток в дампе:

```
$ tshark -r mpls.pcap -Y 'mpls' -T fields -e mpls.label -e mpls.ttl
1002    64
2005    63
```

Внешняя метка — транспорт до выхода, внутренняя — идентификатор VPN. У метки есть и своё поле **TTL**, независимое от IP.

## Шаг 2: VRF — изоляция маршрутов

**VRF** (Virtual Routing and Forwarding) — это отдельная таблица маршрутов и отдельная таблица forwarding. Проще говоря, это «свой маленький роутер» для каждого клиента внутри одного физического устройства. Провайдер создаёт по VRF на клиента, поэтому два клиента с одинаковыми `10.0.0.0/24` не конфликтуют.

Идентификация клиента — **RD** (Route Distinguisher): он делает префикс уникальным. А какие маршруты между VRF импортировать/экспортировать, решает **RT** (Route Target).

Посмотреть VRF и маршруты внутри:

```
$ ip link show type vrf
5: blue: <POINTOPOINT,NOARP,UP> mtu 1500
$ ip route show vrf blue
10.20.0.0/16 via 10.0.0.1 dev eth0
```

## Шаг 3: утечки и атаки

- **Route leak между VRF** — маршруты одного клиента попадают в таблицу другого. Причина — неверные **RT**.
- **Label spoofing** — подделка метки для инъекции в чужой LSP.
- **LDP/RSVP-инъекция** — поддельные привязки меток.
- **MPLS как обход** — трафик в MPLS не фильтруется обычными ACL по IP.

Найти утечку можно так:

```
$ ip route show vrf blue | grep '10.99.0.0'
10.99.0.0/16 via 10.0.0.1 dev eth0
```

Если в VRF `blue` виден префикс `10.99.0.0/16`, который принадлежит другому клиенту, — изоляция нарушена.

## Шаг 4: защита

| Мера | Против чего |
|---|---|
| Корректные **RT** (import/export) | route leak |
| Аутентификация **LDP/RSVP** | поддельные привязки меток |
| Фильтрация MPLS на границе домена | инъекции извне |
| Раздельные VRF + ACL внутри | боковое перемещение |
| Мониторинг таблиц меток | детект атак |
| Не тянуть MPLS до access-порта | поверхность атаки |

Важно не путать **RD** и **RT**: первое уникализирует префикс, второе управляет импортом. Именно неверный RT — самая частая причина утечки.

## Если не сработало

Не видишь MPLS-трафика или утечки? Проверь:

- **MPLS не доходит до твоего порта.** На access-портах меток обычно нет — смотри транзитные линки.
- **VRF изолированы корректно.** Тогда утечки не будет — это ожидаемый результат, а не ошибка теста.
- **Смотришь только IP-заголовок.** Метка лежит **вне** IP — обычный фильтр по IP её не покажет.
- **PHP (penultimate hop popping).** Предпоследний роутер может снять метку раньше — тогда на выходе её уже не будет.

Полезно помнить, чем изолируют на разных уровнях:

| Уровень | Технология | Единица изоляции |
|---|---|---|
| L2 | VLAN / PVLAN | broadcast-домен |
| L3 | VRF | таблица маршрутов |
| MPLS | L3VPN (VRF+метки) | VPN-инстанс |
| Оверлей | VXLAN/GRE | тенант |

## Лаборатория: MPLS на Linux

MPLS можно поднять прямо в ядре Linux и наблюдать за метками без железа:

```
$ sudo modprobe mpls_router mpls_iptunnel
$ sudo sysctl -w net.mpls.platform_labels=100000
$ sudo sysctl -w net.mpls.conf.eth0.input=1
$ sudo ip -f mpls route add 100 via inet 10.0.0.2 dev eth0
$ sudo ip -f mpls route show
```

На таком стенде удобно наблюдать swap меток, поведение TTL и воспроизводить инъекцию в чужой LSP. А проверить изоляцию VRF проще всего так: посмотреть, не видны ли изнутри своего VRF префиксы другого клиента.

```
$ ip route show vrf blue | grep -v '10.20.0.0'
```

Если вывод пуст — изоляция работает. Если появился чужой префикс — где-то неверно настроен RT.

## Что мы теперь знаем

- MPLS коммутирует по 20-битной метке, а не по IP; путь называется LSP.
- Метка вставляется между L2 и L3; EtherType `0x8847` (unicast).
- VRF — отдельная таблица маршрутов; RD уникализирует префикс, RT управляет импортом.
- Ошибка в RT даёт утечку маршрутов между клиентами (route leak).
- Защита — корректные RT, аутентификация LDP/RSVP, фильтрация на границе, мониторинг.
- Аномальная метка (не из диапазона провайдера) — признак инъекции в чужой LSP.
- Стек меток позволяет нести и транспорт (внешняя метка), и VPN-идентификатор (внутренняя).
- Обычные ACL по IP не фильтруют MPLS-трафик — это отдельная поверхность фильтрации на границе домена.
