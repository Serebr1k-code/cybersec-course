NAC (Network Access Control) и 802.1X решают задачу «не пускать неавторизованные устройства в сеть»: порт не даёт трафик, пока устройство не аутентифицируется (сертификат, логин/пароль, MAC). Но NAC часто настраивают слабо, и при физическом доступе к порту его можно обойти. Этот урок разбирает механику и техники обхода — как атакующие, так и защитные.

## Как работает 802.1X

Три роли:

- **Supplicant:** клиент (ПК, телефон).
- **Authenticator:** коммутатор/AP.
- **Authentication server:** обычно RADIUS.

Порт стартует в состоянии **unauthorized** (разрешён только EAPOL). После успешной аутентификации — **authorized**. Методы: EAP-TLS (сертификаты), PEAP-MSCHAPv2 (логин/пароль), EAP-TTLS.

## Виды NAC и точки контроля

NAC бывает на разных уровнях, и от этого зависят обходы:

- **802.1X (порт-контроль)** — аутентификация на коммутаторе/AP.
- **MAB (MAC Authentication Bypass)** — fallback для устройств без 802.1X.
- **Web-аутентификация (captive portal)** — редирект на портал до авторизации.
- **Agent-based** — клиентское ПО на хосте проверяет соответствие (posture).
- **MAC-notification / port-security** — ограничения по числу MAC на порту.

Каждая точка контроля имеет свои слабости: 802.1X — rogue authenticator и downgrade; MAB — подмена MAC; captive portal — часто вообще не защищает L2 (трафик уже в VLAN).

## Слабые места и техники обхода

- **MAB (MAC Authentication Bypass):** если устройство не умеет 802.1X (принтер, камера), коммутатор аутентифицирует по MAC. Атакующий подслушивает разрешённый MAC (в трафике) и **подделывает** его — порт авторизуется.
- **Hub-порт / «dumb» switch:** подключить между собой и целью недорогой коммутатор; если порт настроен на один MAC или MAB — цель «легитимизирует» порт, а атакующий видит трафик.
- **MAC-спуфинг разрешённого устройства:** занять MAC доверенного хоста.
- **Voice VLAN:** телефоны часто на отдельном VLAN с более слабой политикой; подделка MAC телефона даёт доступ.
- **Rogue 802.1X authenticator:** поднять свой RADIUS/authenticator, чтобы перехватить EAP-обмен (особенно PEAP без проверки сертификата) — кража учётных данных.
- **Downgrade:** заставить supplicant использовать менее защищённый метод.

## MAB глубоко: почему он почти не защищает

MAB задумывался как «костыль» для устройств, которые не умеют 802.1X. Но MAC-адрес:

- **Передаётся в открытом виде** в каждом кадре — его легко подслушать.
- **Не является секретом** — печатается на корпусе устройства.
- **Тривиально подделывается** одной командой.

Единственная защита MAB — если после аутентификации устройство попадает в **изолированный VLAN** с профилированием (какой трафик разрешён). Если MAB-устройства живут в общем пользовательском/серверном VLAN, атакующий, подделав MAC принтера, оказывается внутри сегмента.

## Rogue authenticator и перехват EAP

Если клиент использует PEAP-MSCHAPv2 **без проверки сертификата сервера**, он доверится любому RADIUS. Атакующий:

1. Поднимает rogue authenticator (hostapd-wpe/eaphammer).
2. Клиент проходит аутентификацию против него.
3. Атакующий получает **MSCHAPv2-хэш** учётных данных.
4. Хэш взламывается офлайн (hashcat) или релеится.

Защита: EAP-TLS с сертификатами и обязательная проверка CA/имени сервера на клиенте, а также конфигурация supplicant, запрещающая доверять произвольным серверам.

## Инструменты и команды

Смена MAC (Linux):

```bash
sudo ip link set eth0 down
sudo macchanger -m aa:bb:cc:dd:ee:ff eth0
sudo ip link set eth0 up
```

Сниффинг EAPOL/трафика на порту:

```bash
sudo tcpdump -i eth0 -nn -e 'ether proto 0x888e'
```

Инструменты для rogue-аутентификатора: `hostapd-wpe`, `eaphammer` (для лаборатории/аудита).

```bash
# eaphammer: поднять rogue 802.1X (только в своей среде)
sudo ./eaphammer -i eth0 --auth wpa-eap --essid CORP --creds
```

## Разобранный пример: обход через MAB

Сценарий: на порту включён 802.1X с fallback на MAB (для принтера).

1. Слушаем трафик порта: видим кадры от принтера с MAC `00:11:22:33:44:55`.
2. Меняем свой MAC на MAC принтера и подключаемся — коммутатор авторизует порт по MAB.
3. Теперь у нас доступ в VLAN, где живёт принтер (часто совпадает с пользовательским или серверным).
4. Сканируем сегмент и атакуем цели.
5. Вывод: MAB не аутентифицирует личность, только MAC — легко подделать. Защита: MAB только там, где неизбежно, с ограничением VLAN и профилированием устройства.

## Лабораторная проверка

Чтобы отработать техники легально, поднимите стенд:

- Коммутатор с 802.1X (или Linux-хост с `hostapd`/`wpa_supplicant` и `freeradius`).
- Клиент-жертва и атакующий хост.
- Тест: включаем MAB для «принтера», слушаем MAC, подменяем, проверяем доступ.
- Тест: PEAP без проверки сертификата → rogue authenticator → перехват хэша.

```bash
# на атакующем: слушать EAPOL и подменить MAC
sudo tcpdump -i eth0 -e 'ether proto 0x888e'
sudo macchanger -m 00:11:22:33:44:55 eth0
```

## Защита

- **Отказ от MAB**, где возможно; для MAB — изоляция в отдельный VLAN и профилирование.
- **EAP-TLS с сертификатами** вместо паролей; проверка сертификата сервера на клиенте.
- **Один MAC на порт**, отключение hub-режима, port security.
- **Мониторинг:** детект смены MAC, rogue authenticator, аномалий EAPOL.
- **Физическая безопасность:** контроль доступа к портам, отключение неиспользуемых.

## Инструменты и флаги

| Инструмент | Назначение |
|---|---|
| `macchanger` | смена MAC |
| `tcpdump 'ether proto 0x888e'` | сниффинг EAPOL |
| `hostapd-wpe` / `eaphammer` | rogue authenticator (лаборатория) |
| `hashcat -m 5500` | взлом NetNTLM/MSCHAPv2 |
| `freeradius` | тестовый RADIUS |
| `nmap` | скан сегмента после доступа |

## Частые ошибки

- **Считать NAC непробиваемым.** MAB, voice VLAN и hub-порты дают обходы.
- **Использовать PEAP-MSCHAPv2 без проверки сертификата.** Rogue authenticator перехватит учётные данные.
- **Забывать про физический вектор.** NAC защищает от удалённого, но не от доступа к порту.
- **Не сегментировать MAB-устройства.** Они попадают в общий VLAN и становятся мостом.
- **Тестировать rogue authenticator в чужой сети** — это атака, а не аудит.

## Что делать дальше / решение

- **Нужен доступ в сегмент** → найти MAB-устройство → подменить MAC.
- **Нужны учётные данные** → rogue authenticator (если нет проверки сертификата).
- **Нужен широкий доступ** → voice VLAN / hub-порт.
- **Нужна защита** → EAP-TLS, изоляция MAB, port security, мониторинг EAPOL.

## Пост-аутентификационные атаки

Даже успешно пройдя NAC, атакующий не останавливается — доступ в сегмент открывает следующий слой:

- **Сканирование сегмента** после авторизации: какие сервисы, какие подсети.
- **ARP-спуфинг / MITM** внутри доверенного VLAN (см. `network-mitm`).
- **LLMNR/NBT-NS poisoning** для перехвата хэшей Windows.
- **DHCP-спуфинг** и подмена шлюза.
- **802.1X на других портах**: полученный сертификат/учётка может работать на других коммутаторах.

Ключевой вывод: NAC — это барьер на входе, но не микросегментация. Внутри VLAN доверия по-прежнему нужны L2-защиты.

## Защита на уровне дизайна

NAC — не единственная линия; правильный дизайн снижает ценность его обхода:

- **Микросегментация**: даже внутри «доверенного» VLAN разделяйте хосты политиками (ACL, PVLAN).
- **802.1X + MAB с профилированием**: после аутентификации устройство попадает в VLAN, соответствующий его типу.
- **Динамические VLAN/ACL** (RADIUS CoA): права назначаются по результату аутентификации.
- **Certificate-based EAP-TLS**: без паролей, с проверкой сертификата сервера.
- **Мониторинг и NAC-детект**: алерты на смену MAC, rogue authenticator, аномалии EAPOL.
- **Физическая защита портов**: блокировка неиспользуемых, контроль доступа.

## Кейс: voice VLAN

На большинстве корпоративных портов настроен телефон + ПК: телефон получает voice VLAN, ПК — data VLAN. Слабость: телефонный MAC часто аутентифицируется через MAB, а не 802.1X. Атакующий подделывает MAC телефона и попадает в voice VLAN, где политика мягче (голосовой трафик, доступ к IP-PBX). Оттуда можно атаковать телефонию (см. `network-voip`) или пройти дальше. Защита: 802.1X и для телефонов, профилирование voice-устройств, отдельные ACL между voice и data.
