## Вопрос, с которого всё начинается

В 2G мы видели одностороннюю аутентификацию и сломанный A5/1. В 4G (LTE) операторы обещают совсем другой уровень: взаимную аутентификацию, надёжные шифры, разделение данных и сигнализации. Но если ядро сети выставлено в интернет, всё это можно обойти не через радио, а через служебные интерфейсы.

Разберём, как устроено ядро LTE и что именно атакуют, — на дампе Diameter-сессии.

## Наш пример: дамп S6a

Файл `s6a.log` — текстовый дамп обмена между двумя узлами ядра. Первые строки:

```
$ head -6 s6a.log
Diameter peer: MME-01 (10.40.0.11)  <->  HSS-01 (10.40.0.5)  port=3868
Command: 316 Update-Location-Request (ULR)
  AVP Session-Id        value="mme01;10.40.0.11;1234;1"
  AVP User-Name         value="262011234567890"
  AVP Experimental-Result-Code value=bnRve2QxYW0zdDNyX3M2YV8wcDNuX2MwcjN9
Command: 316 Update-Location-Answer (ULA)
  AVP Result-Code       value=2001
```

Мы видим команду **Update-Location-Request** — это уже знакомое нам обновление местоположения, но теперь оно идёт не по SS7, а по **Diameter** между **MME** и **HSS**.

## Шаг 1: из чего состоит ядро LTE (EPC)

**Evolved Packet Core (EPC)** — ядро 4G. Его узлы:

- **eNodeB** — базовая станция (RAN).
- **MME (Mobility Management Entity)** — «мозг» сигнализации: регистрация, аутентификация, управление сессиями.
- **SGW / PGW** — шлюзы пользовательского трафика (данные).
- **HSS (Home Subscriber Server)** — база абонентов (бывший HLR): IMSI, ключи, профили.
- **PCRF** — политики качества и тарификации.

Интерфейсы между ними — это отдельные протоколы со своими портами:

| Интерфейс | Между кем | Протокол | Транспорт |
|---|---|---|---|
| S1-MME | eNodeB ↔ MME | S1AP | SCTP (36412) |
| S1-U | eNodeB ↔ SGW | GTP-U | UDP (2152) |
| S6a | MME ↔ HSS | Diameter | SCTP/TCP (3868) |
| S11 | MME ↔ SGW | GTP-C | UDP (2123) |
| X2 | eNodeB ↔ eNodeB | X2AP | SCTP |

Именно S6a мы и разбираем: это Diameter.

## Шаг 2: аутентификация EPS-AKA

В LTE телефон и сеть проходят **EPS-AKA** (Authentication and Key Agreement) — уже **взаимную** аутентификацию:

1. MME шлёт телефону случайное число **RAND** и токен **AUTN**.
2. SIM проверяет AUTN по секретному ключу **K** — так телефон убеждается, что сеть настоящая (в 2G этого не было!).
3. Обе стороны вычисляют **RES/XRES** и корневой ключ **Kasme**.
4. Из Kasme выводятся ключи шифрования и целостности: **Kenb** (для радио) и **Knas** (для сигнализации NAS).

Ключевое отличие от 2G: **телефон проверяет сеть**. Поэтому «просто поставить фальшивую вышку» в 4G не выйдет — нужен либо настоящий ключ, либо downgrade до 2G.

## Шаг 3: Diameter — это «SS7 для 4G»

Диаметр — протокол сигнализации 4G. Он заменил MAP из SS7, но унаследовал ту же проблему: **слабое доверие между операторами**.

Сообщение Diameter состоит из **команд** и **AVP** (Attribute-Value Pair) — пар «атрибут = значение». В нашем дампе:

- `Command: 316 Update-Location-Request` — код команды 316.
- `AVP User-Name` — здесь IMSI абонента.
- `AVP Result-Code value=2001` — успех.

Диаметр ходит по **SCTP/TCP порт 3868**. Если этот порт смотрит в интернет (а такое регулярно находят у операторов), можно слать произвольные команды: запрашивать местоположение, менять профиль абонента, перехватывать SMS.

## Шаг 4: GTP — туннель данных

Пользовательский трафик в EPC идёт в туннелях **GTP** (GPRS Tunnelling Protocol):

- **GTP-C** (UDP 2123) — управление туннелями (создание/удаление сессий).
- **GTP-U** (UDP 2152) — сам пользовательский трафик внутри туннеля.
- **GTP'** (UDP 3386) — тарификация.

Туннель идентифицируется **TEID** (Tunnel Endpoint Identifier). GTP не шифрует и почти не аутентифицирует содержимое — если порт 2152 доступен снаружи, можно инжектить пакеты в туннель (об этом — отдельный урок [`network-gtp`](network-gtp)).

## Шаг 5: полный прогон

В нашем дампе одно из AVP-значений закодировано в base64 (так иногда логируют бинарные значения). Найдём его и раскодируем:

```
$ grep 'value=' s6a.log
  AVP Session-Id        value="mme01;10.40.0.11;1234;1"
  AVP User-Name         value="262011234567890"
  AVP Experimental-Result-Code value=<base64>
  AVP Result-Code       value=2001
```

Декодируем подозрительное значение и получаем флаг. Запиши его в `answer.txt` и набери `check`.

## Что мы теперь знаем

- Ядро LTE — это EPC из MME, SGW, PGW, HSS; интерфейсы S1-MME (SCTP), S1-U (GTP-U), S6a (Diameter).
- EPS-AKA даёт взаимную аутентификацию — телефон проверяет сеть.
- Diameter (порт 3868) — «SS7 для 4G»; при слабом межоператорском доверии опасен.
- GTP-U (2152) несёт данные в открытом виде внутри туннелей.

## Процедура Attach: пошагово

Чтобы читать LTE-логи, нужно знать порядок процедуры подключения (Attach). Он одинаков и для реальной сети, и для дампа:

1. **RRC Connection Setup** — телефон синхронизируется с eNodeB и поднимает радио-соединение.
2. **Attach Request** (NAS/EMM) — телефон представляется (GUTI или IMSI) и сообщает свои возможности.
3. **Authentication** — MME инициирует EPS-AKA: `Authentication Request` с RAND/AUTN, телефон отвечает `Authentication Response` с RES.
4. **Security Mode** — `Security Mode Command`/`Complete`: включаются шифрование NAS и проверка целостности.
5. **Update Location** (S6a) — MME идёт в HSS по Diameter (наша команда 316).
6. **Attach Accept** — MME выдаёт GUTI, список TAI и настройки сессии.

Смотреть это в дампе удобно по NAS-слою:

```
$ tshark -r attach.pcap -Y "nas-eps" -T fields -e _ws.col.Info | head
Attach request
Authentication request
Authentication response
Security mode command
Security mode complete
Attach accept
```

Обрати внимание на порядок: сначала аутентификация, только потом — Security Mode. Именно между ними (в 2G/3G) и проскакивает незащищённый IMSI, а в 4G эта дыра закрыта взаимной аутентификацией.

## EPS-AKA и иерархия ключей

EPS-AKA (3GPP TS 33.401) — это Milenage поверх AES. Упрощённо:

1. HSS хранит долговременный ключ **K** (он же в USIM).
2. HSS генерирует **RAND** (128 бит) и **SQN**, считает:
   - `MAC = f1(K, RAND, SQN, AMF)` — для проверки сети;
   - `XRES = f2(K, RAND)` — ожидаемый ответ телефона;
   - `CK = f3(K, RAND)`, `IK = f4(K, RAND)` — шифр и целостность;
   - `AK = f5(K, RAND)` — маскировка SQN.
3. Телефон получает **AUTN = (SQN ⊕ AK) ‖ AMF ‖ MAC**. Он проверяет MAC и свежесть SQN — так убеждается, что сеть настоящая.
4. Обе стороны считают `Kasme = KDF(K, SN id, SQN ⊕ AK)`.

Из Kasme выводится иерархия:

| Ключ | Назначение |
|---|---|
| K_ASME | корень для NAS и AS |
| K_NASenc / K_NASint | шифрование и целостность сигнализации NAS |
| K_eNB | переносится в eNodeB при handover |
| K_RRCenc / K_RRCint | защита RRC |
| K_UPenc | шифрование пользовательских данных |

Важно: **K_eNB** передаётся на eNodeB, поэтому компрометация базовой станции не раскрывает K_ASME — это шаг вперёд по сравнению с 2G, где Kc был «плоским».

## Diameter: команды, AVP и приложения

Diameter — это peer-to-peer протокол с командами и AVP. Коды, которые встречаются на S6a:

| Команда | Код | Смысл |
|---|---|---|
| Update-Location-Request/Answer | 316 | регистрация абонента в MME |
| Cancel-Location-Request/Answer | 317 | отмена регистрации |
| Authentication-Information-Request/Answer | 318 | запрос векторов аутентификации |
| Multimedia-Auth-Request/Answer | 319 | аутентификация (IMS) |
| Notify-Request/Answer | 323 | уведомление о смене профиля |

Ключевые AVP: `User-Name` (IMSI), `Result-Code` (268), `Experimental-Result` (297), `Subscription-Data`. Каждому интерфейсу соответствует `Application-Id`: S6a = 16777251, S6d = 16777251, Sh = 16777217, Gx = 16777238.

```
$ tshark -r s6a.pcap -Y "diameter.cmd.code==318" -T fields -e diameter.User-Name
$ tshark -r s6a.pcap -Y "diameter.cmd.code==316" -V | grep -i "Result-Code"
```

Слабость Diameter — та же, что у SS7: если межоператорский фильтр настроен слабо, чужой узел может слать произвольные команды. Через `318 AIR` можно запросить векторы аутентификации, через `316 ULR` — подменить местоположение, а через S6c/SGs — добраться до SMS.

## GTP: заголовок и эксплуатация

GTP-C (управление) и GTP-U (данные) живут на UDP. Заголовок GTPv1-U минималистичен:

| Поле | Размер | Смысл |
|---|---|---|
| Flags | 1 байт | версия, наличие опциональных полей |
| Message Type | 1 байт | 0xFF = G-PDU (данные), 0x01 = Echo |
| Length | 2 байта | длина |
| TEID | 4 байта | идентификатор туннеля |
| Sequence | 2 байта | в управляющих сообщениях |

GTP **не шифрует** и **не аутентифицирует** полезную нагрузку. Атаки:

- **TEID-перебор**: угадав TEID, можно инжектировать пакет в чужой туннель.
- **GTP-in-GTP**: вложенный туннель для обхода тарификации/файрвола.
- **Echo-флуд**: переполнение таблицы туннелей.

Крафт на Scapy:

```python
>>> from scapy.contrib.gtp import GTP_U_Header
>>> pkt = IP(dst="10.40.0.1")/UDP(dport=2152)/GTP_U_Header(teid=0x1234)/IP(dst="8.8.8.8")/ICMP()
>>> send(pkt)
```

Сканирование открытых интерфейсов ядра:

```
$ nmap -sU -p 2152,2123 --open 10.40.0.0/24
$ nmap -sS -p 3868,36412,36422 --open 10.40.0.0/24
```

## Перехват SMS и трекинг: что делают через сигнализацию

Классический сценарий атаки на межоператорскую сигнализацию (SS7 в 2G/3G, Diameter в 4G):

1. **ATI (Any Time Interrogation)** по SS7 — узнать текущее местоположение абонента (Cell ID, LAC).
2. **ULR (Update Location)** — «прикинуться», что абонент пришёл в вашу сеть, и получить профиль.
3. **CLR (Cancel Location)** — отключить абонента от настоящей сети (DoS).
4. **mt-forwardSM** — перехватить входящую SMS, включая коды 2FA.

Инструменты для легального тестирования: `sigploit`, `ss7MAPer` (MAP-фаззер на Python), `smpp`-клиенты. Для Diameter — `freeDiameter` в режиме peer и фаззеры на базе Scapy.

Ключевой вывод: **SMS-OTP не является надёжным вторым фактором**, если оператор не фильтрует межоператорскую сигнализацию. Именно поэтому банки всё чаще переходят на push-подтверждения и TOTP.

## Как это защищают

- **GTP firewall** (GSMA FS.20): проверка TEID, IMSI, IP-адресов SGW/PGW, запрет GTP-in-GTP.
- **Diameter edge agent / SEPP** (FS.19): белые списки команд по роуминговым соглашениям, блокировка ATI/ULR из чужих сетей.
- **SS7 firewall** (FS.11): фильтрация MAP-операций, детект аномальных запросов.
- **NAS/AS security**: обязательные NEA/NIA-шифры, проверка целостности S1AP.
- **Сегментация**: интерфейсы ядра (3868/2123/2152/36412) не должны смотреть в интернет — только в доверенный GRX/IPX.

Если пентест оператора находит открытый S6a или нефильтрованный GTP — это находка уровня «критично», потому что через них можно добраться до абонентских данных и SMS.
