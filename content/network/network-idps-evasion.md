IDS/IPS сравнивает трафик с сигнатурами (Snort/Suricata) или аномалиями. Атака на них — это атака на **расхождение** между тем, как видит поток сенсор, и тем, как его соберёт целевая ОС. Если сенсор и цель собирают пакеты по-разному, атакующий прячет полезную нагрузку «между» ними.

## Почему возможен обход

Ключевые источники расхождений:

- **Реконструкция TCP:** сенсор и цель по-разному обрабатывают перекрывающиеся сегменты, ретрансмиссии, переупорядочивание.
- **IP-фрагментация:** сенсор может не пересобирать фрагменты (или делать это иначе), а цель — пересобрать.
- **TTL и маршрутизация:** пакет, «просроченный» для сенсора, может дойти до цели в другой топологии.
- **Кодировки:** разные интерпретации Unicode, сжатия, chunked-кодирования в HTTP.

Классическая модель — «Insertion & Evasion» Паксcона: атакующий вставляет данные, которые цель отбросит, а сенсор примет (insertion), или наоборот (evasion).

## Snort/Suricata: как устроены правила

Понимание формата правил — ключ к обходу. Правило Snort/Suricata:

```text
alert http $EXTERNAL_NET any -> $HOME_NET any (msg:"SQLi union"; \
  content:"union select"; nocase; http_uri; sid:1000001; rev:1;)
```

- **`content:`** — байтовая подстрока; ищется буквально.
- **`nocase`** — игнорировать регистр.
- **`http_uri`** — область поиска (URI, заголовок, тело).
- **`pcre:`** — регулярное выражение (мощнее, но медленнее).
- **`flow:`** — состояние соединения.
- **`threshold`/`detection_filter`** — пороги срабатывания.

Если правило ищет `content:"union select"` в URI, то `union/**/select` или `union%09select` его не сработает, хотя приложение поймёт.

## Техники

- **Фрагментация:** разбить полезную нагрузку на крошечные фрагменты; простые сенсоры не пересобирают.
- **Перекрывающиеся фрагменты:** разные политики пересборки (BSD/Linux/Windows) дают разный итог.
- **TCP-обфускация:** перекрывающиеся сегменты, разные SN, tiny-сегменты, out-of-order.
- **Полиморфизм/кодирование:** URL-кодирование, двойное кодирование, регистр, Unicode, сжатие, `Transfer-Encoding: chunked`.
- **Тайминг:** медленные сканы (укладываться в пороги), `nmap --scan-delay`, `-T0`.
- **Протокольные трюки:** HTTP request smuggling на уровне сенсора, `Content-Length` vs `Transfer-Encoding`.

## HTTP-обфускация глубоко

HTTP — самый частый вектор обхода, потому что парсеров много (сенсор, прокси, WAF, приложение) и они расходятся:

- **URL-кодирование**: `%75%6e%69%6f%6e` = `union`.
- **Двойное кодирование**: `%2575` → приложение декодирует дважды.
- **`+` и `%20`**: пробел в разных формах.
- **Комментарии в SQL**: `union/**/select`, `union/*!50000select*/`.
- **Регистр и табы**: `UnIoN%09SeLeCt`.
- **`Transfer-Encoding: chunked`**: тело разбито на чанки, сигнатура по телу не срабатывает.
- **`Content-Length` vs `Transfer-Encoding`**: smuggling, где сенсор и приложение видят разные тела.
- **Unicode/overlong UTF-8**: `%c0%ae` для `..` в path traversal.

```bash
# проверить, срабатывает ли правило на обфускацию (лаборатория)
curl -s "http://10.0.0.10/?id=1%2f**%2funion%2f**%2fselect" -o /dev/null -w '%{http_code}\n'
```

## Инструменты и команды

Nmap evasion:

```bash
# медленный скан с фрагментацией и подделкой источника
sudo nmap -sS -f --mtu 8 -T1 --scan-delay 2s --data-length 32 -D RND:10 target
# декапа с произвольным источником
sudo nmap -sS -S 10.0.0.99 -e eth0 -Pn target
```

Проверка, видит ли Snort то же, что цель: поднять сенсор и тестировать в лаборатории.

```bash
# в лаборатории: запустить snort с правилом на "GET /admin"
sudo snort -A console -q -c /etc/snort/snort.conf -i eth0
# затем отправить обфусцированный запрос и проверить, сработала ли сигнатура
```

Fragment-обфускация (Scapy):

```python
from scapy.all import *
# разбить payload на фрагменты по 8 байт (лаборатория)
frags = fragment(IP(dst="10.0.0.10")/TCP(dport=80)/Raw(b"GET /admin HTTP/1.0\r\n\r\n"), fragsize=8)
send(frags)
```

## Нормализация и препроцессоры

Современные IPS защищаются **нормализацией**: прежде чем искать сигнатуру, поток приводят к канонической форме.

- **Пересборка IP-фрагментов** (defrag) — устраняет фрагментационную обфускацию.
- **Пересборка TCP-потока** (stream5/stream) — устраняет перекрытия и reorder.
- **Декодирование HTTP** (http_inspect) — декодирует URL, чанки, сжимает.
- **Политика ОС** — эмулирует целевую ОС (Linux/Windows/BSD) для пересборки.

Если нормализация настроена, обходы резко усложняются. Если нет — сенсор видит «сырой» поток и расходится с целью.

## Разобранный пример: обход сигнатуры через кодирование

Сценарий: Snort ловит строку `union select` в HTTP.

1. Базовая атака `?id=1 union select 1,2` → сигнатура срабатывает, IPS блокирует.
2. Пробуем обфускацию: `?id=1/**/union/**/select/**/1,2` — комментарии ломают сигнатуру.
3. Двойное URL-кодирование: `%25%36%35` вместо `e` — сенсор декодирует иначе, чем приложение.
4. Смешанный регистр/пробелы: `UnIoN%09SeLeCt` — табуляция вместо пробела.
5. Проверяем на цели (лаборатория), что приложение исполнило инъекцию, а сигнатура — нет.
6. Вывод: сигнатурный IDS обходится обфускацией; защита — нормализация потока и декодирование на сенсоре, поведенческий анализ.

## Тестирование правил на устойчивость

Хорошая практика для SOC — регулярно проверять свои правила на обходы:

- Собрать корпус обфусцированных payload'ов (кодирование, чанки, регистр).
- Прогнать через сенсор и убедиться, что правило срабатывает.
- Если нет — включить нормализацию или переписать правило на `pcre` с декодированием.
- Автоматизировать: CI-пайплайн, который проверяет правила на известные evasion-техники.

## Защита (для синей команды)

- **Нормализация:** IPS должен нормализовать поток (пересобирать фрагменты, декодировать) **до** сигнатур.
- **Политики ОС:** настроить пересборку как у целевых хостов.
- **Поведенческий/аномальный детект:** не только сигнатуры.
- **TLS-инспекция:** видеть содержимое зашифрованного трафика (осторожно с приватностью).
- **Тестирование обходов:** периодически проверять IDS техниками evasion.

## Частые ошибки

- **Считать IPS всевидящим.** Расхождения реконструкции — основа обхода.
- **Забывать про фрагментацию.** Многие сенсоры её не пересобирают.
- **Обфусцировать без учёта цели.** Если приложение не поймёт payload, атака бесполезна.
- **Игнорировать тайминг.** Быстрый скан — сигнал для пороговых детекторов.
- **Тестировать обходы на проде** без разрешения — это атака.

## Что делать дальше / решение

- **Нужна скрытность** → тайминг + фрагментация + декапы.
- **Нужен обход сигнатуры** → обфускация, сохраняющая смысл для приложения.
- **Нужна защита** → нормализация, политика ОС, поведенческий детект.
- **Нужна проверка правил** → лабораторный корпус evasion-техник + CI.

## Аномальный и поведенческий детект

Сигнатуры обходятся обфускацией, поэтому современные системы добавляют поведенческий слой:

- **Аномалии трафика**: необычные объёмы, всплески, порты.
- **Поведенческие правила**: «много неудачных логинов», «скан портов».
- **ML/эвристика**: выявление отклонений от профиля.
- **Fingerprinting клиента**: JA3/JA4 (TLS-отпечаток), p0f (ОС по TCP/IP).

Атакующему важно понимать: даже если сигнатура не сработала, поведенческий детектор может заметить скан или аномалию. Отсюда — тайминг и «размазывание» активности.

## Обход при сканировании

Сканирование — самый заметный этап. Приёмы снижения заметности:

```bash
# медленный скан: укладывается в пороги
sudo nmap -sS -T0 --max-rate 5 --scan-delay 5s target

# случайный порядок портов
sudo nmap -sS --randomize-hosts -p- --max-retries 1 target

# распределённые декапы (только с разрешения)
sudo nmap -sS -D RND:20 target

# фрагментация + малый MTU
sudo nmap -sS -f --mtu 16 target
```

Помните: декапы и спуфинг источника могут ломать сам скан (ответы уходят не вам); используйте их осознанно, чаще для заметания следов, а не для получения результатов.

## Шифрование и слепые зоны

TLS — естественная слепая зона сигнатурного IDS. Что это значит:

- **SNI-фильтрация**: сенсор видит только домен из ClientHello, не путь и тело.
- **TLS-инспекция** (MITM с доверенным CA) возвращает видимость, но требует развёртывания и затрагивает приватность.
- **Encrypted Client Hello (ECH)** скрывает даже SNI.
- **DoH/DoT** прячет DNS-запросы от пассивного наблюдения.

Для атакующего это плюс (payload внутри TLS не виден), для защитника — необходимость инспекции и корреляции метаданных.
