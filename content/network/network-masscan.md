Masscan — асинхронный сканер портов, способный обойти весь IPv4 за минуты. В отличие от nmap (который ведёт состояние соединений), masscan генерирует и рассылает пакеты без ожидания, отслеживая ответы собственным стеком. Это даёт скорость, но ценой точности. Урок опирается на [`network-portscan`](network-portscan) и [`network-nmap-deep`](network-nmap-deep).

## Чем masscan отличается от nmap

| | nmap | masscan |
|---|---|---|
| Модель | синхронная, stateful | асинхронная, stateless |
| Скорость | тысячи pps | миллионы pps |
| Точность | высокая (ретраи, фингерпринт) | зависит от потерь |
| Скрипты | NSE | нет |
| OS-детект | да | нет |

Masscan — «разведчик портов»; nmap — «детальный фингерпринт». Идеальный тандем: masscan быстро находит открытые порты по огромному диапазону, nmap глубоко изучает только найденное.

Ключевая архитектурная разница: masscan **не использует сетевой стек ОС**. Он открывает raw-сокет, сам формирует SYN-пакеты, сам читает ответы и ведёт собственные таблицы. Поэтому ему нужен root (или `CAP_NET_RAW`) и корректно заданный шлюз/MAC, но он не упирается в лимиты файловых дескрипторов и таблиц соединений ядра, которые ограничивают nmap.

## Базовое использование

```bash
# SYN-скан диапазона по портам
masscan 10.0.0.0/24 -p80,443 --rate 10000
# Всё пространство портов
masscan 10.0.0.0/16 -p0-65535 --rate 100000
# Список портов из файла + вывод в файл
masscan -iL targets.txt -p22,80,443,3389 --rate 5000 -oB masscan.out
# Читать бинарный вывод
masscan --readscan masscan.out -oL -
# Исключения
masscan 0.0.0.0/0 -p443 --rate 100000 --excludefile exclude.txt
```

Ключевые флаги: `--rate` (pps), `-p` (порты), `-iL` (входной список), `--excludefile` (исключения), `-oB/-oX/-oL/-oG` (форматы вывода), `--interface`, `--router-mac`, `--adapter-port`.

## Ограничения и тонкости

- **Свой сетевой стек**: masscan использует raw-сокеты (нужен root) и **не** использует ОС для TCP — поэтому работает даже без маршрута, но требует корректного шлюза/MAC.
- **Потери**: при высоком `--rate` пакеты теряются (и на стороне атакуемого, и на канале). Отсутствие порта в выводе ≠ «закрыт».
- **Firewall/NAT**: ответы могут искажаться; некоторые сети «съедают» SYN.
- **TCP только для портов**; UDP-скан ограничен и менее надёжен.

```bash
# Ограничить интерфейс/шлюз, если автоопределение не работает
masscan 10.0.0.0/24 -p80 --rate 10000 --interface eth0 --router-mac 00:11:22:33:44:55
```

## Сочетание с nmap

Классический workflow: masscan находит **открытые порты** по большому диапазону, nmap уточняет **версии/скрипты** только на найденном.

```bash
# 1. Быстрая разведка
masscan 10.0.0.0/16 -p0-65535 --rate 100000 -oG masscan.gnmap
# 2. Собрать живые хосты+порты и передать в nmap
grep 'Ports:' masscan.gnmap | awk '{print $2}' | sort -u > hosts.txt
nmap -sV -sC -iL hosts.txt -oX nmap.xml
# 3. Или через конвертер masscan->nmap
masscan --readscan masscan.out -oX - | xsltproc - > nmap_targets.xml
```

## Разобранный пример: разведка /16

```bash
# 1. Скан популярных портов
masscan 10.0.0.0/16 -p22,80,443,445,3306,3389,8080 --rate 50000 -oG scan.gnmap
# 2. Какие порты нашлись
grep -oE '[0-9]+/open' scan.gnmap | sort | uniq -c | sort -rn
#    142 80/open
#     37 443/open
#      9 3389/open
# 3. Живые хосты
grep 'Ports:' scan.gnmap | awk '{print $2}' | sort -u > live.txt
wc -l live.txt
# 188 live.txt
# 4. Детальный фингерпринт
nmap -sV -sC -iL live.txt -oX nmap.xml
# 5. Быстрый парсинг
grep -oE 'open +[a-z0-9/.-]+' nmap.xml | sort | uniq -c | sort -rn | head
```

За 50 000 pps диапазон /16 (65 536 адресов) по семи портам проходится за секунды, а nmap получает уже готовый список живых хостов — экономия времени на порядки.

## Производительность и тюнинг

- **`--rate`** — ключевой параметр; начните с 1000-5000 и повышайте, следя за потерями.
- **`--banners`** — masscan может захватить баннеры (медленнее, но информативнее).
- **`--wait`** — подождать после завершения для прихода поздних ответов.
- **`--retries`** — число повторов (по умолчанию 2).
- **`--source-port`** — фиксировать source port (иногда помогает с NAT).
- **`--adapter-ip`/`--adapter-mac`** — ручная настройка при нестандартной сети.
- **`--shard`** — разбить работу на N частей (`--shard 1/4`), удобно для распределённого скана.

```bash
masscan 10.0.0.0/24 -p0-65535 --rate 50000 --banners --wait 5 -oB out
```

## Крупномасштабные сценарии и шардирование

```bash
# Топ-порты по всему интернету (только в своих диапазонах!)
masscan 0.0.0.0/0 -p80,443,22,3389 --rate 100000 --excludefile exclude.txt -oG web.gnmap
# Разбить на шарды для параллельного скана
masscan 0.0.0.0/0 -p443 --shard 1/4 --rate 25000 -oB s1 &
masscan 0.0.0.0/0 -p443 --shard 2/4 --rate 25000 -oB s2 &
# Интеграция с nmap
masscan --readscan out -oX - | nmap -sV -iX -
```

## zmap и альтернативы

- **zmap** — однопакетный сканер (ещё быстрее, но только один порт за прогон и требует явный source-port).
- **naabu** — быстрый сканер портов (Go), удобен в пайплайнах (`naabu -host x -p - -silent`).
- **nmap `--min-rate`** — для умеренных объёмов без отдельного инструмента.

## Правовые и операционные границы

- Сканировать **только** авторизованные диапазоны. Массовый скан «всего интернета» без разрешения — противозаконно и вредит.
- `--rate` выше пропускной способности → потери и жалобы провайдера.
- В облаке высокий `--rate` может выглядеть как **DoS** и привести к блокировке инстанса.
- Всегда используйте `--excludefile` для критичных/чужих сетей.

## Частые ошибки

- **Слишком высокий `--rate`** — эффект DoS, потери, жалобы.
- **Полагаться на masscan для версий** — он не определяет сервисы; нужен nmap.
- **Забывать про root** — raw-сокеты требуют привилегий.
- **Не проверять `--router-mac`/интерфейс** — скан «в никуда».
- **Сканировать чужие диапазоны** — правовые последствия.
- **Игнорировать потери** — отсутствие порта в выводе не значит «закрыт».

## Что дальше / решение

Маршрут: **masscan по большому CIDR → собрать живые хосты (`-oG`) → nmap `-sV -sC` на найденном → разбор сервисов**. masscan = скорость, nmap = точность; сканируйте только авторизованные диапазоны и всегда задавайте `--excludefile` и разумный `--rate`. Дальше — [`network-nmap-deep`](network-nmap-deep), [`network-portscan`](network-portscan) и [`network-tool-masscan-naabu`](network-tool-masscan-naabu).

## Как masscan находит хосты: механика stateless-скана

Обычный сканер для каждого соединения держит запись в таблице ядра, поэтому упирается в лимиты (файловые дескрипторы, conntrack). masscan устроен иначе: он формирует SYN-пакет, отправляет его и **забывает** — а затем отдельным потоком читает все ответы с raw-сокета и сопоставляет их по адресу/порту с отправленными. Состояние хранится в компактной собственной структуре, что и позволяет рассылать миллионы пакетов в секунду. Цена — отсутствие надёжного ретрансмит-механизма и фингерпринтинга: если SYN потерялся на канале или в сети жертвы, порт просто не появится в выводе. Поэтому массовый скан всегда даёт **нижнюю оценку** числа открытых портов, и потери растут с `--rate`.

Практический вывод: для инвентаризации критичных сетей не полагайтесь на один прогон при высоком `--rate` — сделайте два-три прогона на умеренной скорости и объедините результаты, либо повышайте `--retries`. Для «разведки по площадям» скорость важнее полноты, поэтому один быстрый прогон допустим.

## Автоматизация: парсинг вывода и пайплайны

masscan умеет четыре формата: `-oL` (простой список), `-oG` (greppable, как у nmap), `-oX` (XML) и `-oB` (бинарный, для последующего `--readscan`). Для пайплайнов удобнее всего `-oG`: каждая строка с открытым портом начинается с `Host:` и `Ports:`.

```bash
# Только живые хосты (уникальные IP)
masscan --readscan out -oL - | grep 'open' | awk '{print $4}' | sort -u
# В XML для nmap
masscan --readscan out -oX - | xsltproc - > targets.xml
# Быстрый подсчёт по портам
grep -oE '[0-9]+/open' scan.gnmap | sort | uniq -c | sort -rn
```

Связка `masscan → nmap` — стандарт разведки больших сетей. Иногда вместо XML удобнее сгенерировать список `ip:port` и подать его напрямую: `awk '/open/{print $2":"$4}' scan.gnmap | tr -d '/tcp' > targets.txt`, затем `nmap -sV -iL targets.txt`.

## Сравнение с zmap и naabu

| Инструмент | Пакетов за прогон | Скорость | Плюс | Минус |
|---|---|---|---|---|
| masscan | много портов | очень высокая | гибкий, много портов | свой стек, root |
| zmap | один порт | максимальная | эталон скорости | один порт, source-port |
| naabu | много портов | высокая | Go, удобен в пайплайне | меньше контроля L2 |
| nmap | много портов | низкая | точность, NSE | медленный на /8 |

zmap — «однопакетный»: он сканирует один порт по огромному диапазону, но требует явно указать `--source-port` и whitelist. naabu проще встраивается в автоматизированные пайплайны (например, перед `httpx`). Выбирайте по задаче: masscan для гибкой разведки, zmap для измерений, naabu для конвейера, nmap для финального фингерпринта.

## OPSEC: как скан выглядит со стороны

Массовый скан — громкий. Со стороны цели это тысячи SYN от одного адреса: IDS/IPS помечает как port-scan, провайдер может прислать abuse-жалобу, а облачный провайдер — заблокировать инстанс. Снизить заметность помогают `--source-port` (замаскировать под легитимный трафик), распределённые source-адреса и умеренный `--rate`, но полностью скрыть скан нельзя. Для авторизованного пентеста согласуйте окно и диапазоны заранее и держите `--excludefile` для чужих сетей.
