IPv6 — это не «IPv4 с длинными адресами». Здесь нет ARP и broadcast, вместо них — **Neighbor Discovery (ND)** и multicast, а адреса часто назначаются автоматически через **SLAAC**. Эти отличия создают целый класс атак, которые многие защитные системы (заточенные под IPv4) не видят. IPv6 — ещё и удобный способ обойти IPv4-фильтры, поэтому в пентесте его проверяют в первую очередь, а не «потом».

Разбираем адресацию, автоконфигурацию, все пять сообщений ND, полный сценарий rogue Router Advertisement, NDP-спуфинг, туннели и методы обнаружения.

## Адресация IPv6: типы, форматы, зоны

Адрес IPv6 — 128 бит, записывается восемью группами по 16 бит в hex, разделёнными двоеточием. Ведущие нули группы опускаются, одна (и только одна) последовательность нулевых групп сворачивается в `::`.

| Тип префикса | Диапазон | Назначение |
|---|---|---|
| Global unicast | `2000::/3` | маршрутизируемый в интернете адрес |
| Link-local | `fe80::/10` | всегда есть на интерфейсе, только внутри сегмента |
| Unique local (ULA) | `fc00::/7` | аналог RFC1918, не маршрутизируется наружу |
| Multicast | `ff00::/8` | групповые адреса (`ff02::1` — все узлы) |
| Loopback | `::1/128` | аналог 127.0.0.1 |
| Unspecified | `::/128` | «адрес не задан» |

Пример канонизации: `2001:0db8:0000:0000:0000:ff00:0042:8329` → `2001:db8::ff00:42:8329`. Обратите внимание: `::` можно использовать один раз, иначе адрес неоднозначен.

**Зона (zone id).** Link-local адреса неоднозначны между интерфейсами, поэтому при работе с ними указывают зону: `fe80::1%eth0`. Без `%eth0` ядро не знает, через какой интерфейс отправлять. Это самая частая ошибка новичка при `ping6`.

## Автоконфигурация SLAAC по шагам

Stateless Address Autoconfiguration заменяет DHCP для адресации. Последовательность:

1. Хост формирует link-local адрес из префикса `fe80::/64` и интерфейсного идентификатора (EUI-64 из MAC либо случайный при privacy extensions).
2. Делает **Duplicate Address Detection (DAD)**: отправляет Neighbor Solicitation на свой «пробный» адрес, ждёт ответа. Нет ответа — адрес уникален.
3. Отправляет **Router Solicitation** на `ff02::2` (все роутеры).
4. Роутер отвечает **Router Advertisement** с префиксом, флагами `A` (autonomous) и `M`/`O` (managed/other config — про DHCPv6).
5. Хост формирует global-адрес: префикс из RA + интерфейсный идентификатор.
6. Если в RA флаг `O`, хост отдельно спрашивает DHCPv6 о DNS и других опциях.

Ключевая уязвимость заложена в шаге 4: **RA от любого узла принимается без аутентификации**. Спецификация SEND (Secure Neighbor Discovery), которая должна была это исправить, практически нигде не развёрнута.

## Neighbor Discovery: пять типов сообщений

ND работает поверх ICMPv6 (IP-протокол 58) и объединяет функции ARP, router discovery и redirect:

| Сообщение | Тип ICMPv6 | Аналог в IPv4 | Назначение |
|---|---|---|---|
| Router Solicitation (RS) | 133 | — | хост спрашивает роутеры |
| Router Advertisement (RA) | 134 | — | роутер объявляет префикс/шлюз |
| Neighbor Solicitation (NS) | 135 | ARP request | разрешение адреса / DAD |
| Neighbor Advertisement (NA) | 136 | ARP reply | ответ с MAC-адресом |
| Redirect | 137 | ICMP redirect | «лучший маршрут вот здесь» |

Все пять **подделываются** тривиально — достаточно уметь отправлять raw ICMPv6. Именно поэтому IPv6-сегмент без RA-Guard/NDP-monitoring — лёгкая добыча для MITM.

## Rogue Router Advertisement: полный сценарий

Цель — заставить жертву считать атакующего шлюзом по умолчанию. Порядок в лаборатории:

```bash
# 1. Включить форвардинг и определить интерфейс
sysctl -w net.ipv6.conf.all.forwarding=1
ip -6 addr show dev eth0

# 2. Отправить поддельный RA (thc-ipv6)
fake_router6 eth0 2001:db8:dead:beef::/64
# либо более гибко: параметры префикса, lifetime, DNS
```

После этого жертвы обновляют default route на адрес атакующего, и весь IPv6-трафик идёт через него. Дальше — обычный MITM: `tcpdump -ni eth0 -vvv` показывает чужой трафик, `bettercap` может модифицировать DNS/HTTP.

Важный нюанс: даже если сеть «работает на IPv4», на хостах часто включён IPv6 (Windows и Linux включают его по умолчанию). Один rogue RA — и появляется параллельный путь, которого нет в IPv4-схеме безопасности. Именно поэтому защитники часто не замечают утечку.

## NDP-спуфинг: аналог ARP-спуфинга

Чтобы перехватить трафик конкретной жертвы, не меняя шлюз целиком, атакующий шлёт поддельные NS/NA:

```bash
# отравить кэш: сказать жертве, что адрес шлюза — это MAC атакующего
# инструменты: parasite6 (thc-ipv6) — непрерывная отправка поддельных NA
parasite6 eth0
```

`parasite6` отвечает поддельным NA на все NS в сегменте, вставая «посередине». Аналог `arpspoof`, но для ICMPv6. Для детекта смотрят на частоту NA и несоответствия MAC↔IPv6 в таблице соседей (`ip -6 neigh show`).

## RA-flood и отказ в обслуживание

Отправляя тысячи RA с разными префиксами и source-адресами, атакующий переполняет таблицы маршрутизации/соседей на хостах и коммутаторах, вызывая рост памяти и отказ в обслуживании. Инструмент — `flood_router6` из thc-ipv6. Отдельно `flood_advertise6` заливает сегмент NA. Защита — RA rate-limiting на коммутаторах и RA-Guard.

## Обход IPv4-фильтров через IPv6

Классический приём: firewall настроен только на IPv4, но стек IPv6 разрешён. Тогда:

- сервис, слушающий `::` (all interfaces), доступен по IPv6 там, где IPv4-порт закрыт;
- ACL, написанный для `192.168.0.0/24`, не покрывает `2001:db8::/64`;
- IPv6-адрес можно получить «из воздуха» через SLAAC и попасть в сегмент, который по IPv4 заблокирован.

Практический шаг: `nmap -6` по IPv6-адресу цели. Часто открываются порты, которые `nmap` по IPv4 показал как `filtered`.

## Туннели: 6to4, Teredo, ISATAP

Туннели инкапсулируют IPv6 в IPv4 и нередко включены по умолчанию в старых ОС:

- **6to4** (`2002::/16`): адрес выводится из публичного IPv4, трафик уходит на relay `192.88.99.1`.
- **Teredo** (`2001::/32`): IPv6 в UDP/3544 для хостов за NAT; relay-серверы публичные.
- **ISATAP**: IPv6 внутри IPv4 внутри организации, идентификатор `::5efe:<IPv4>`.

Уязвимости: неаутентифицированные relay-серверы позволяют обходить firewall и смешивать IPv6-трафик в IPv4-периметр. Проверяют через `ip -6 tunnel show` и анализ трафика на UDP/3544, IP-протокол 41 (6in4).

## Сканирование IPv6-сетей

Подсеть `/64` содержит 2^64 адресов — перебор бессмысленен. Работают другие методы:

```bash
# найти всех в сегменте через multicast (одним пакетом)
ping6 -c 3 ff02::1%eth0
# затем посмотреть, кто ответил
ip -6 neigh show dev eth0

# nmap по IPv6 (нужен -6, иначе протокол не тот)
nmap -6 -sn 2001:db8::/120        # ping sweep только по маленькой подсети
nmap -6 -sS -p 22,80,443 2001:db8::42
```

Multicast-адреса `ff02::1` (все узлы) и `ff02::2` (все роутеры) дают «список живущих» одним запросом — это самый эффективный вход в IPv6-сегмент.

## Инструменты и команды

```bash
ip -6 addr show
ip -6 route show
ip -6 neigh show
ip -6 tunnel show
sysctl -a | grep 'net.ipv6.conf.*disable_ipv6'
ping6 -c 3 ff02::1%eth0
nmap -6 -sS -sV -p- 2001:db8::42
# thc-ipv6 (atk6): fake_router6, parasite6, flood_router6, redir6, alive6, detect-new-ip6
alive6 eth0
```

`detect-new-ip6` в реальном времени показывает новые IPv6-адреса в сегменте — удобно для инвентаризации и для обнаружения rogue RA.

## Обнаружение и защита

- **RA-Guard** на коммутаторах: пропускать RA только от доверенных портов.
- **IPv6 First-Hop Security** (SEND, ND Inspection, DHCPv6 Guard).
- **Отключение IPv6**, где он не нужен: `sysctl net.ipv6.conf.all.disable_ipv6=1`.
- **Мониторинг ND**: алерты на RA от неавторизованных адресов, на рост NA/NS.
- **Сегментация**: не полагаться на то, что IPv4-ACL защищает IPv6.

## Частые ошибки

- Забыть зону `%eth0` при работе с link-local — пакеты «уходят не туда».
- Путать `ping` и `ping6`, `nmap` и `nmap -6` — сканируется не тот протокол.
- Считать IPv6 «безопасным, потому что его никто не использует» — он включён по умолчанию.
- Игнорировать `::` (all interfaces) в конфигурациях сервисов — сервис оказывается доступен по IPv6.
- Строить `/64`-sweep — это 18 квинтиллионов адресов, используйте multicast.

## Что дальше / решение

IPv6 надо проверять на каждом сегменте: сначала `ping6 ff02::1%eth0` и `ip -6 neigh`, затем `nmap -6`. Если видите неожиданные RA — это либо rogue-роутер, либо мисконфиг, и оба варианта интересны. Практический вывод для пентеста: IPv6 — это часто «вторая дверь» в сеть, закрытую по IPv4. Для защиты — RA-Guard, ND Inspection и выключение IPv6 там, где он не нужен.

## Сравнение IPv4 и IPv6 в пентесте

| Аспект | IPv4 | IPv6 |
|---|---|---|
| Разрешение адреса | ARP (broadcast) | ND (multicast ICMPv6) |
| Автоконфигурация | DHCP | SLAAC + DHCPv6 |
| Аутентификация | нет | SEND (почти не развёрнут) |
| Сканирование | перебор /24 | multicast `ff02::1` |
| Обход firewall | сложнее | IPv6 часто не покрыт правилами |
| Туннели | — | 6to4, Teredo, ISATAP |

## Чек-лист аудита IPv6-сегмента

1. `ip -6 addr show` — есть ли link-local и global адреса.
2. `ping6 ff02::1%eth0` — кто живёт в сегменте.
3. `ip -6 route show` — какой шлюз по умолчанию, откуда он взялся.
4. `ip -6 neigh show` — нет ли подозрительных MAC↔IPv6.
5. `nmap -6 -sS -sV` по найденным адресам — какие порты открыты только по IPv6.
6. Проверить RA-Guard/ND Inspection на коммутаторе, если есть доступ.
7. `sysctl net.ipv6.conf.all.disable_ipv6` — включён ли IPv6 там, где он не нужен.

Регулярный прогон этого чек-листа на каждом сегменте ловит и rogue RA, и «вторую дверь», и случайные туннели.

## Где пригодится

- **CTF:** IPv6-задачи, обход фильтров, разбор ICMPv6 в PCAP.
- **Пентест:** RA/NDP-атаки, поиск IPv6-обходов периметра.
- **Bug bounty:** редко напрямую, но полезно при оценке сетевой инфраструктуры.
- **Работа (SOC/NOC):** инвентаризация IPv6, настройка RA Guard, детект аномалий.
