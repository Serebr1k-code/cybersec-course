## Вопрос, с которого всё начинается

Ты в сегменте, где «всё на IPv4»: адреса `10.0.0.0/24`, firewall настроен на IPv4, администратор уверен, что IPv6 не используется. Ты смотришь на свой интерфейс — и обнаруживаешь, что у него уже есть IPv6-адрес, о котором никто не знал.

IPv6 — это не «IPv4 с длинными адресами». Здесь нет ARP и broadcast, вместо них — **Neighbor Discovery** и multicast, а адреса часто назначаются автоматически через **SLAAC**. Эти отличия создают целый класс атак, которые IPv4-защиты просто не видят.

## Наш пример: неожиданный IPv6-адрес

```
$ ip -6 addr show dev eth0
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 state UP
    inet6 fe80::a00:27ff:fe4e:66a1/64 scope link
    inet6 2001:db8:1:1::a00:27ff:fe4e:66a1/64 scope global dynamic
       valid_lft 2591978sec preferred_lft 604778sec
```

Два адреса. `fe80::/64` — **link-local**: он есть всегда и живёт только внутри сегмента. `2001:db8:...` — **global unicast**, и он «dynamic», то есть получен автоматически. Откуда? Разберёмся — это и есть ключ к атаке.

## Шаг 1: как устроены адреса IPv6

Адрес IPv6 — 128 бит, восемь групп по 16 бит. Ведущие нули опускаются, а одна последовательность нулевых групп сворачивается в `::`:

```
2001:0db8:0000:0000:0000:ff00:0042:8329
2001:db8::ff00:42:8329
```

| Тип префикса | Диапазон | Назначение |
|---|---|---|
| Global unicast | `2000::/3` | маршрутизируемый адрес |
| Link-local | `fe80::/10` | только внутри сегмента |
| Unique local (ULA) | `fc00::/7` | аналог RFC1918 |
| Multicast | `ff00::/8` | групповые адреса |

`::` можно использовать только один раз, иначе адрес неоднозначен. А link-local адреса неоднозначны между интерфейсами, поэтому к ним добавляют **зону**: `fe80::1%eth0`. Забыть `%eth0` — самая частая ошибка новичка: пакет «уходит не туда».

## Шаг 2: откуда взялся адрес — SLAAC

**SLAAC** (Stateless Address Autoconfiguration) заменяет DHCP для адресации. Порядок такой:

1. Хост делает себе link-local из префикса `fe80::/64` + идентификатор интерфейса.
2. Проверяет уникальность через **DAD** (Duplicate Address Detection).
3. Шлёт **Router Solicitation** на `ff02::2` («все роутеры»).
4. Роутер отвечает **Router Advertisement** с префиксом.
5. Хост собирает global-адрес: префикс из RA + идентификатор.

Уязвимость заложена в шаге 4: **RA от любого узла принимается без аутентификации**. Спецификация SEND, которая должна была это закрыть, почти нигде не развёрнута.

## Шаг 3: Neighbor Discovery вместо ARP

ND работает поверх ICMPv6 (протокол 58) и объединяет ARP, router discovery и redirect:

| Сообщение | Тип ICMPv6 | Аналог |
|---|---|---|
| Router Solicitation | 133 | — |
| Router Advertisement | 134 | — |
| Neighbor Solicitation | 135 | ARP request |
| Neighbor Advertisement | 136 | ARP reply |
| Redirect | 137 | ICMP redirect |

Все пять подделываются тривиально — достаточно уметь отправлять raw ICMPv6. Проверим, кто живёт в сегменте, — одним multicast-пакетом:

```
$ ping6 -c 3 ff02::1%eth0
64 bytes from fe80::a00:27ff:fe4e:66a1: icmp_seq=1 ttl=64 time=0.032 ms
64 bytes from 2001:db8:1:1::cafe:1: icmp_seq=1 ttl=64 time=0.41 ms
$ ip -6 neigh show dev eth0
2001:db8:1:1::cafe:1 dev eth0 lladdr 08:00:27:cafe:01 REACHABLE
fe80::a00:27ff:fe4e:66a1 dev eth0 lladdr 08:00:27:4e:66:a1 REACHABLE
```

`ff02::1` — «все узлы». Один запрос — и мы знаем всех соседей. Для `/64` (это 2^64 адресов) перебор бессмысленен, а multicast даёт «список живущих» мгновенно.

## Шаг 4: rogue RA — становимся шлюзом

Цель — заставить жертву считать нас шлюзом по умолчанию. Включаем форвардинг и отправляем поддельный RA:

```
$ sudo sysctl -w net.ipv6.conf.all.forwarding=1
net.ipv6.conf.all.forwarding = 1
$ sudo fake_router6 eth0 2001:db8:dead:beef::/64
```

Теперь жертвы обновляют default route на наш адрес, и весь IPv6-трафик идёт через нас:

```
$ sudo tcpdump -ni eth0 -vvv -c 2 'ip6 and not icmp6'
2001:db8:1:1::cafe:1.44321 > 2001:db8:1:1::10.443: Flags [P.], length 220
```

Обрати внимание: даже если сеть «работает на IPv4», IPv6 включён по умолчанию и в Windows, и в Linux. Один rogue RA — и появляется параллельный путь, которого нет в IPv4-схеме безопасности. Защитники его часто не замечают.

## Шаг 5: вторая дверь в периметр

Самое практичное следствие: сервис, слушающий `::` (все интерфейсы), доступен по IPv6 там, где IPv4-порт закрыт фильтром.

```
$ sudo nmap -sS -Pn -p445 10.10.20.5
445/tcp filtered microsoft-ds
$ sudo nmap -6 -sS -Pn -p445 2001:db8:20::5
445/tcp open  microsoft-ds
```

ACL, написанный для `192.168.0.0/24`, не покрывает `2001:db8::/64`. Поэтому IPv6 в пентесте проверяют в первую очередь, а не «потом».

## Шаг 6: туннели и отказ в обслуживании

Туннели инкапсулируют IPv6 в IPv4 и нередко включены по умолчанию в старых ОС: **6to4** (`2002::/16`), **Teredo** (`2001::/32`, IPv6 в UDP/3544), **ISATAP**. Они позволяют обходить firewall и смешивать IPv6-трафик в IPv4-периметр. Отдельный вектор — **RA-flood**: тысячи RA с разными префиксами переполняют таблицы соседей и маршрутов (инструмент `flood_router6`).

## Инструменты и чек-лист

Полезные команды для IPv6-разведки:

```
$ ip -6 addr show
$ ip -6 route show
$ ping6 -c3 ff02::1%eth0
$ nmap -6 -sS -p22,80,443 2001:db8::42
$ alive6 eth0
```

`alive6` из набора thc-ipv6 находит всех живущих в сегменте, а `detect-new-ip6` показывает новые адреса в реальном времени — удобно и для инвентаризации, и для обнаружения rogue RA.

Чек-лист аудита IPv6-сегмента:

1. `ip -6 addr show` — есть ли link-local и global адреса.
2. `ping6 ff02::1%eth0` — кто живёт в сегменте.
3. `ip -6 route show` — какой шлюз и откуда он взялся.
4. `nmap -6 -sS -sV` — какие порты открыты только по IPv6.
5. Проверить RA Guard / ND Inspection на коммутаторе.
6. `sysctl net.ipv6.conf.all.disable_ipv6` — не включён ли IPv6 там, где не нужен.

## Что мы теперь знаем

- IPv6 назначает адреса через SLAAC, не аутентифицируя роутера.
- Neighbor Discovery (ICMPv6 133–137) заменяет ARP и подделывается тривиально.
- `ping6 ff02::1%eth0` даёт список всех узлов сегмента одним пакетом.
- Rogue RA делает атакующего шлюзом по умолчанию — параллельный путь MITM.
- IPv6 часто остаётся «второй дверью» там, где правила настроены только на IPv4.

## Разбираем IPv6-адрес по частям

Вернёмся к нашему «неожиданному» адресу. Возьмём глобальный адрес и разложим его:

```
2001:0db8:85a3:0000:0000:8a2e:0370:7334
|-------prefix--------|-------interface ID----|
```

Первые 64 бита — **префикс сети** (его выдаёт роутер), последние 64 — **идентификатор интерфейса** (его хост строит сам). Внутри префикса первые 48 бит часто выдают провайдеру (глобальная маршрутизация), а следующие 16 — конкретной подсети.

Хост может построить interface ID двумя способами: случайно (**privacy extensions**) или из MAC по схеме **EUI-64**. Во втором случае в середину MAC вставляют `ff:fe` и переворачивают один бит — и адрес «выдаёт» железо:

```
MAC:     08:00:27:aa:bb:cc
EUI-64:  0a00:27ff:feaa:bbcc
```

Заметь `0a` вместо `08` — седьмой бит (U/L) перевёрнут. Это важная деталь: адрес с EUI-64 раскрывает производителя железа, а privacy-адреса — нет.

| Тип адреса | Префикс | Смысл |
|---|---|---|
| Link-local | `fe80::/10` | только в пределах линка, авто |
| Unique local | `fc00::/7` | «серые» адреса внутри организации |
| Global unicast | `2000::/3` | маршрутизируемые в интернете |
| Multicast | `ff00::/8` | групповые |
| Loopback | `::1/128` | сам хост |

## RA в дампе: что именно раздаёт роутер

Ключевой для атак протокол — **Router Advertisement** (ICMPv6 тип 134). Роутер периодически рассылает его на `ff02::1` (все узлы). Разберём содержимое:

```
$ tshark -r ipv6.pcap -Y "icmpv6.type==134" -V -c 1 | grep -E 'Prefix|Router lifetime|Flags|MTU'
    Router lifetime: 1800
    Flags: 0xc0 (Managed, Other)
    Prefix: 2001:db8:1::/64
    MTU: 1500
```

Читается так: роутер живёт 1800 секунд, флагами `Managed`/`Other` требует ещё и DHCPv6, раздаёт префикс `2001:db8:1::/64`. Хост, получив RA, **сам** строит адрес (SLAAC) и добавляет роутер как шлюз по умолчанию — без всякой аутентификации. Именно поэтому rogue RA так эффективен: один поддельный пакет делает атакующего шлюзом для всего сегмента.

## Neighbor Discovery вместо ARP

В IPv6 нет ARP — его роль играет **NDP** (Neighbor Discovery). Чтобы узнать MAC соседа по адресу, хост шлёт **Neighbor Solicitation** (тип 135) на solicited-node multicast, а получает **Neighbor Advertisement** (тип 136). Проблема та же, что у ARP: ответ не аутентифицирован, поэтому NA-спуфинг даёт MITM. Дополнительно работает **Duplicate Address Detection** (DAD) — проверка, что адрес свободен; злоумышленник может отвечать на DAD и блокировать назначение адреса (DoS).

## Если не сработало: IPv6 «не работает», хотя адрес есть

Частая ситуация. Проверь по порядку: есть ли **link-local** адрес (`ip -6 addr show` — он должен быть всегда), приходит ли RA (`tcpdump -i eth0 icmp6 and ip6[40]==134`), прописан ли маршрут по умолчанию (`ip -6 route`). Если RA приходит, а интернета нет — проверь, не блокирует ли firewall протокол 41 и не сломан ли MTU (в IPv6 фрагментацию делает только отправитель, поэтому PMTU критичен). И помни: адрес `fe80::` есть почти всегда, но он **link-local** — по нему нельзя выйти за пределы сегмента.

## Куда дальше

Мы увидели, что IPv6 живёт рядом с IPv4 и открывает «вторую дверь». Дальше разберём, как адреса выдаются в IPv6 глубже — SLAAC против DHCPv6, rogue-серверы и RDNSS. А пока запомни: **в IPv6 никто не аутентифицирует роутера — значит, роутером может стать кто угодно.**

## Где пригодится

- **CTF:** IPv6-задачи, обход фильтров, разбор ICMPv6 в PCAP.
- **Пентест:** RA/NDP-атаки, поиск IPv6-обходов периметра.
- **Bug bounty:** полезно при оценке сетевой инфраструктуры.
- **Работа (SOC/NOC):** инвентаризация IPv6, RA Guard, детект аномалий.
