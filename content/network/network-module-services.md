После сканирования портов начинается работа с сервисами: понять протокол, найти слабость, эксплуатировать. Классические сервисы (FTP, Telnet, VNC, RDP) и IoT-протоколы (MQTT, CoAP, AMQP) имеют свои особенности и типовые ошибки. Этот модуль — база для [`network-ftp-tftp`](network-ftp-tftp), [`network-telnet-rservices`](network-telnet-rservices), [`network-vnc-rdp`](network-vnc-rdp) и [`network-iot-messaging`](network-iot-messaging), опирается на [`network-service-enum`](network-service-enum).

## Зачем отдельный модуль по сервисам

Сервисы — это то, что реально «открыто» на хосте. Их анализ включает:

- **идентификацию** (баннер, версия, реализация);
- **аутентификацию** (анонимный доступ, дефолты, брутфорс);
- **функции** (что сервис умеет: загрузка файлов, исполнение, публикация);
- **слабости** (CVE, отсутствие шифрования, доверие).

Один открытый анонимный FTP или MQTT-брокер без пароля часто важнее десятка закрытых портов.

## Классические сервисы: FTP и Telnet

- **FTP** (21/20) — передача файлов; часто анонимный доступ, слабые пароли, иногда запись.
- **TFTP** (69/udp) — передача без аутентификации; удобна для загрузки/подмены конфигов.
- **Telnet** (23) — удалённый доступ **без шифрования**; пароли и данные видны на проводе.
- **r-services** (513/514/512) — rlogin/rsh/rexec; доверие по `.rhosts`.

Подробно — в `network-ftp-tftp` и `network-telnet-rservices`.

## Удалённый доступ: VNC и RDP

- **VNC** (5900+) — RFB-протокол; пароль хранится в отдельном файле, часто слабый, иногда без пароля.
- **RDP** (3389) — Microsoft; NLA/CredSSP, уязвимости вроде BlueKeep, перебор credentials.

Подробно — в `network-vnc-rdp`.

## IoT-протоколы: MQTT, CoAP, AMQP

- **MQTT** (1883/8883) — pub/sub; брокер без аутентификации = полный контроль над топиками.
- **CoAP** (5683/udp) — REST-подобный протокол для constrained-устройств; часто без DTLS.
- **AMQP** (5672) — очереди сообщений; дефолтные guest/guest.

Подробно — в `network-iot-messaging`.

## Как энумерировать сервис

```bash
# Баннеры и версии
nmap -sV -p 21,23,3389,5900,1883 10.0.0.1
# NSE-скрипты
nmap -p 21 --script ftp-anon,ftp-bounce 10.0.0.1
nmap -p 3389 --script rdp-enum-encryption,rdp-vuln-ms12-020 10.0.0.1
# Ручной баннер
nc -nv 10.0.0.1 21
```

```bash
# Мультисервисная проверка
nmap -sV -sC -p- 10.0.0.1
```

## Атаки: карта векторов

- **Анонимный доступ** — FTP, MQTT, VNC без пароля;
- **Брутфорс credentials** — RDP, VNC, FTP, SSH;
- **Перехват** — Telnet/FTP/r-services (нет шифрования);
- **Эксплуатация CVE** — BlueKeep (RDP), реализации FTP;
- **Запись файлов** — FTP/TFTP для подмены конфигов;
- **Утечка через топики** — MQTT/AMQP.

## Типовые ошибки

- **Доверять баннеру** — версия подделывается.
- **Игнорировать UDP-сервисы** — TFTP, CoAP.
- **Забывать про анонимный доступ** — FTP/MQTT.
- **Считать RDP «просто GUI»** — там CVE и брутфорс.
- **Не проверять запись** — FTP/TFTP могут быть writable.
- **Путать порты** — 5900 VNC, 5901 второй экран.
- **Не логировать сервисы** — аномалии невидимы.

## Практика: энумерация сервисов

```bash
# 1. Полный скан с версиями и NSE
nmap -sV -sC -p- 10.0.0.1 -oA full
# 2. Целевые проверки
nmap -p 21 --script ftp-anon,ftp-bounce 10.0.0.1
nmap -p 23 --script telnet-ntlm-info 10.0.0.1
nmap -p 3389 --script rdp-enum-encryption,rdp-ntlm-info 10.0.0.1
nmap -p 5900 --script vnc-info 10.0.0.1
nmap -sU -p 69,5683 --script tftp-enum 10.0.0.1
# 3. Ручной баннер
for p in 21 23 3389 5900 1883; do echo "== $p"; nc -nv -w2 10.0.0.1 $p </dev/null 2>&1 | head -2; done
```

## Сравнение сервисов

| Сервис | Порт | Шифрование | Типовая слабость |
|---|---|---|---|
| FTP | 21 | нет | аноним, bounce |
| TFTP | 69/udp | нет | нет аутентификации |
| Telnet | 23 | нет | перехват паролей |
| r-services | 512–514 | нет | доверие .rhosts |
| VNC | 5900+ | слабое | пароль ≤8, без пароля |
| RDP | 3389 | TLS/NLA | брутфорс, BlueKeep |
| MQTT | 1883 | опц. TLS | открытый брокер |
| CoAP | 5683/udp | опц. DTLS | запись ресурсов |

## Чек-лист сервисов

1. Какие сервисы открыты (**-sV -sC**)?
2. Есть ли **анонимный/безпарольный** доступ?
3. Используется ли **шифрование** (TLS/NLA/DTLS)?
4. Какие **версии** и есть ли известные CVE?
5. Разрешена ли **запись** (FTP/TFTP/CoAP)?
6. Логируются ли **входы и публикации**?
7. Сегментированы ли **management/IoT** сервисы?

```bash
# Снимок открытых портов с версиями
nmap -sV -p 21,23,512,513,514,3389,5900,5901,1883,8883,5672,5683 10.0.0.1
```

Вывод: сервисы — это «лицо» хоста. Каждый открытый порт нужно идентифицировать, проверить на анонимный доступ, шифрование и известные CVE, а затем либо закрыть, либо защитить аутентификацией и шифрованием.

## Диагностика сервисов

```bash
# Проверить, что сервис реально отвечает
nc -nv -w2 10.0.0.1 21 </dev/null
# Проверить шифрование
nmap -p 21 --script ftp-anon 10.0.0.1
# TLS-сервисы: сертификат
openssl s_client -connect 10.0.0.1:8883 -brief </dev/null
# UDP-сервисы (TFTP/CoAP)
nmap -sU -p 69,5683 10.0.0.1
```

## Практический конвейер энумерации сервисов

```bash
# 1. Скан
nmap -sV -sC -p- 10.0.0.1 -oA scan
# 2. Извлечь открытые порты
grep -oE '^[0-9]+/tcp' scan.nmap | cut -d/ -f1 > ports.txt
# 3. Прогнать NSE по сервисам
nmap -p $(paste -sd, ports.txt) --script 'default,safe' 10.0.0.1
# 4. Проверить анонимный доступ
for s in ftp vnc mqtt; do echo "== $s"; done
# 5. Захватить баннеры
nmap -p $(paste -sd, ports.txt) -sV --version-intensity 9 10.0.0.1
```

Такой конвейер превращает «список портов» в список сервисов с версиями, известными слабостями и точками для ручной проверки.

## Итог по сервисам

Сервисы — это поверхность атаки, которая реально «открыта». Работа с ними циклична: **идентифицировать → проверить аутентификацию/шифрование → найти CVE → эксплуатировать/защитить**. Открытый анонимный FTP, брокер MQTT без пароля или RDP без NLA — типовые находки, каждая из которых закрывается конкретной мерой.

## Заметка о шифровании сервисов

Простое правило для аудита: **если сервис не шифрует — считайте его данные публичными**. Это относится к FTP, Telnet, r-services, TFTP, а также к MQTT/CoAP без TLS/DTLS. Даже если аутентификация формально есть, пароль и содержимое видны на проводе.

```bash
# Быстро определить, шифрует ли сервис
# 1. Захватить трафик
sudo tcpdump -i eth0 -nn -A -c 20 'port 21 or port 23 or port 1883'
# 2. Если видны читаемые команды/логины — шифрования нет
```

Практический вывод: для каждого сервиса проверяйте три вопроса — **есть ли аутентификация**, **есть ли шифрование**, **есть ли известные CVE**. Ответ «нет/нет/есть» означает готовый вектор.
