Между клиентом и сервером почти всегда есть посредники: прокси, CDN, WAF, балансировщики. А на стороне обороны — IDS/IPS и системы анализа потоков (NetFlow). Понимание этой «инфраструктуры на пути» нужно и для атаки (обход детекта, поиск origin), и для защиты (правильный мониторинг). Этот модуль — база для [`network-netflow`](network-netflow), [`network-ids-suricata`](network-ids-suricata) и [`network-proxy-cdn-waf`](network-proxy-cdn-waf), опирается на [`network-pcap-analysis`](network-pcap-analysis) и [`network-zeek`](network-zeek).

## Зачем отдельный модуль по анализу

Анализ трафика бывает трёх уровней:

- **полный PCAP** — всё содержимое (тяжело, дорого по хранению);
- **NetFlow/IPFIX** — только метаданные потоков (кто, куда, сколько);
- **IDS-логи** — алерты по сигнатурам/поведению.

Каждый уровень отвечает на свои вопросы. NetFlow покажет «аномальный объём в 3 часа ночи», PCAP — «что именно передавалось», IDS — «сработало правило».

## NetFlow/IPFIX: метаданные потоков

**NetFlow** (v5/v9) и **IPFIX** описывают **поток** (5-tuple: src/dst IP, src/dst port, protocol) с counters. Экспортёры (роутеры) шлют записи коллектору. Это компактно и масштабируется.

```bash
# nfdump: анализ NetFlow
nfdump -r nfcapd.202610111200 -s srcip/bytes -n 10
nfdump -r nfcapd.202610111200 'src ip 10.0.0.5' | head
```

Подробно — в [`network-netflow`](network-netflow).

## IDS/IPS: Suricata и Zeek

- **Suricata** — сигнатурный IDS/IPS: правила на содержимое и поведение, алерты и блокировки.
- **Zeek** — «network security monitor»: пишет богатые логи (conn, dns, http, ssl) для анализа.

```bash
# Suricata: прогон pcap с правилами
suricata -r capture.pcap -S rules.rules -l out/
# Zeek: логи из pcap
zeek -r capture.pcap
ls conn.log http.log dns.log ssl.log
```

Подробно — в [`network-ids-suricata`](network-ids-suricata) и [`network-zeek`](network-zeek).

## Прокси, CDN и WAF

- **Прокси** — forward (для клиентов) и reverse (перед сервером);
- **CDN** — кэш и защита на границе (Cloudflare, Akamai);
- **WAF** — фильтр HTTP-запросов (правила, аномалии, rate-limit).

Эти системы меняют модель: реальный origin скрыт, а клиент видит edge-адреса. Подробно — в [`network-proxy-cdn-waf`](network-proxy-cdn-waf).

## Что видно и что нет

| Уровень | Видно | Не видно |
|---|---|---|
| PCAP | всё (если нет шифрования) | содержимое TLS |
| NetFlow | метаданные потоков | содержимое, URL |
| IDS-логи | алерты по сигнатурам | неинспектируемый трафик |
| За CDN/WAF | edge-адреса | реальный origin |

Ключевая мысль: каждая технология добавляет **слепую зону**. DoH/DoT скрывает DNS, TLS — содержимое, CDN — origin.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `nfdump`/`SiLK` | NetFlow/IPFIX |
| `suricata` | сигнатурный IDS/IPS |
| `zeek` | логи соединений/протоколов |
| `tcpdump`/`tshark` | PCAP |
| `dig`/`whois` | поиск origin |

## Атаки и уклонение

- **Шифрование** — TLS/DoH прячут содержимое;
- **Фрагментация/обфускация** — обход сигнатур (см. `network-idps-evasion`);
- **Разбиение сессий** — обход корреляции;
- **Поиск origin** — обход CDN/WAF;
- **Спуфинг X-Forwarded-For** — обман логов;
- **Low-and-slow** — медленные атаки против детекта.

## Типовые ошибки

- **Считать NetFlow заменой PCAP** — нет содержимого.
- **Игнорировать шифрованный трафик** — слепая зона.
- **Доверять X-Forwarded-For** — подделывается.
- **Не искать origin за CDN** — «защищено» ≠ недоступно.
- **Не тюнить IDS** — ложные срабатывания и пропуски.
- **Хранить только алерты** — нет контекста.
- **Забывать про IPv6/DoH** — мониторинг не видит.

## Практика: мониторинг с NetFlow и IDS

```bash
# 1. NetFlow: топ разговоров
nfdump -r nfcapd.202610111200 -s record/bytes -n 10
# 2. IDS: прогон pcap с правилами
suricata -r capture.pcap -S local.rules -l out/ && cat out/fast.log
# 3. Zeek: логи
zeek -r capture.pcap && ls *.log
# 4. Корреляция: подозрительный хост
cat conn.log | zeek-cut id.orig_h id.resp_h | grep 10.0.0.5 | head
nfdump -r nfcapd.202610111200 'host 10.0.0.5' -s dstip/bytes -n 10
```

## Сравнение уровней анализа

| Уровень | Что хранит | Плюсы | Минусы |
|---|---|---|---|
| PCAP | полный пакет | всё содержимое | объём, шифр |
| NetFlow/IPFIX | метаданные потока | масштаб, дёшево | нет содержимого |
| IDS-алерты | срабатывания правил | приоритет | пропуски/ложные |
| Zeek-логи | структурированные события | богатый контекст | объём, тюнинг |

## Итог по анализу трафика

Мониторинг строится слоями: **NetFlow** для видимости потоков и охоты, **IDS/Zeek** для детекта и контекста, **PCAP** для глубокого разбора нужного окна. Ни один слой не полон: шифрование, туннели и CDN создают слепые зоны. Задача аналитика — знать эти зоны и комбинировать источники. Для пентестера те же знания означают понимание того, что «видит» защита и как это обойти.

## Модель слепых зон анализа

Каждая технология на пути трафика создаёт слепую зону, и хороший аналитик знает их наперечёт. Шифрование (TLS, SSH, VPN) скрывает содержимое — остаются только метаданные. DoH и DoT скрывают DNS-запросы, ломая фильтрацию по именам. CDN и WAF скрывают origin и фильтруют HTTP, но не дают видеть трафик внутри. Туннели (GRE, VXLAN, ICMP) прячут внутренний поток внутри разрешённого. NAT искажает адреса, а балансировщики разрывают сессии.

Практический вывод для защиты: нельзя полагаться на один источник видимости. Стройте слои — NetFlow для объёмов и периодичности, IDS для сигнатур, Zeek для контекста, DNS-логи для имён, TLS-метаданные (JA3/SNI) для fingerprint. Для пентестера это означает: чем «обычнее» ваш трафик (HTTPS на 443, DoH, CDN), тем меньше вас видно. Но аномалии в метаданных (периодичность, объём, редкие порты) остаются заметными даже при шифровании.

## Итоговый вывод

Анализ трафика — это про **уровни и слепые зоны**. Знайте, что видит каждый слой, комбинируйте источники и не делайте выводов «нет данных = нет атаки». Тот же принцип работает и наоборот: для обхода детекта выбирайте трафик, который сливается с легитимным.

## Инструментальный минимум аналитика

```bash
# PCAP
tcpdump -i eth0 -w cap.pcap; tshark -r cap.pcap
# Потоки
nfdump -r nfcapd.* -s srcip/bytes -n 10
# IDS/логи
suricata -r cap.pcap -S rules -l out/; zeek -r cap.pcap
# TLS-метаданные
tshark -r cap.pcap -Y 'tls.handshake.type==1' -T fields -e tls.handshake.extensions_server_name
# DNS
tshark -r cap.pcap -Y 'dns' -T fields -e dns.qry.name | sort -u
```

Минимальный набор покрывает все три уровня: содержимое (PCAP), метаданные (NetFlow), события (IDS/Zeek). Дополните его TLS-метаданными (SNI/JA3) и DNS-логами — это то, что остаётся видимым даже при шифровании.

## Итог по анализу

Три уровня анализа трафика образуют пирамиду: **PCAP** (содержимое, дорого), **NetFlow** (метаданные, масштабно), **IDS/Zeek** (события, приоритетно). Посредники (прокси, CDN, WAF) добавляют слои доверия и слепые зоны. Умение работать на всех уровнях и учитывать слепые зоны отличает реальный мониторинг от «галочки»: NetFlow ловит beaconing и эксфильтрацию, IDS — сигнатуры, PCAP — детали, а знание слепых зон не даёт принять «нет данных» за «нет атаки».
