## Вопрос, с которого всё начинается

В логах мелькнул хост `10.0.0.5`: ночью он качал данные куда-то наружу. У тебя нет полного дампа за ту ночь — только статистика потоков. **Как понять, что происходило, если содержимого нет?**

Ответ — в уровнях анализа. Между клиентом и сервером почти всегда есть посредники (прокси, CDN, WAF), а на стороне обороны — системы анализа потоков (NetFlow) и детекта (IDS). Понимание этой «инфраструктуры на пути» нужно и для атаки (обход детекта, поиск origin), и для защиты. Модуль опирается на [`network-pcap-analysis`](network-pcap-analysis) и [`network-zeek`](network-zeek) и ведёт к [`network-netflow`](network-netflow), [`network-ids-suricata`](network-ids-suricata) и [`network-proxy-cdn-waf`](network-proxy-cdn-waf).

## Наш пример: что делал хост 10.0.0.5

Начинаем с метаданных потоков. **NetFlow** — это формат записей о **потоках**: каждый поток описывается **5-tuple** (IP источника, IP назначения, порт источника, порт назначения, протокол) плюс счётчики байт и пакетов. Экспортёры (роутеры) шлют такие записи коллектору.

```
$ nfdump -r nfcapd.202610110000 'host 10.0.0.5' -s dstip/bytes -n 5
Date first seen  Proto  Src IP Addr    Dst IP Addr    Bytes  Packets
2026-10-11 03:11 TCP    10.0.0.5       198.51.100.7   812340  912
2026-10-11 03:14 TCP    10.0.0.5       198.51.100.7   798120  903
```

Хост `10.0.0.5` раз в три минуты шлёт примерно одинаковый объём на `198.51.100.7`. Это похоже на **beaconing** — периодические «пульсы» связи с C2-сервером. Содержимого нет, но ритм виден.

## Шаг 1: три уровня анализа

Один и тот же трафик можно смотреть на трёх уровнях:

- **полный PCAP** — всё содержимое (тяжело, дорого по хранению);
- **NetFlow/IPFIX** — только метаданные потоков (кто, куда, сколько);
- **IDS-логи** — алерты по сигнатурам и поведению.

NetFlow отвечает на «аномальный объём в 3 часа ночи», PCAP — «что именно передавалось», IDS — «сработало правило». Начнём с того, что у нас есть.

## Шаг 2: IDS — Suricata и Zeek

- **Suricata** — сигнатурный IDS/IPS: правила на содержимое и поведение, выдаёт алерты и умеет блокировать.
- **Zeek** — сетевой монитор: пишет богатые структурированные логи (`conn`, `dns`, `http`, `ssl`) для анализа.

```
$ suricata -r capture.pcap -S local.rules -l out/ && cat out/fast.log
10/11/2026-03:11:22  [**] [1:2000001:1] Possible C2 beacon [**] {TCP} 10.0.0.5:49152 -> 198.51.100.7:443
$ zeek -r capture.pcap
$ ls conn.log http.log dns.log ssl.log
conn.log  dns.log  http.log  ssl.log
```

Suricata пометила соединение как возможный C2, а Zeek расписал его по логам. В `conn.log` видно, кто с кем говорил и сколько передал.

## Шаг 3: прокси, CDN и WAF

Между клиентом и сервером почти всегда стоит посредник:

- **Прокси** — forward (для клиентов) и reverse (перед сервером);
- **CDN** — кэш и защита на границе (Cloudflare, Akamai);
- **WAF** — фильтр HTTP-запросов (правила, аномалии, rate-limit).

Эти системы меняют модель: реальный **origin** (исходный сервер) скрыт, а клиент видит edge-адреса. Это важно и для пентеста — «защищено» не значит «недоступно», origin часто находится через DNS-историю и утечки заголовков.

## Что видно и что нет

| Уровень | Видно | Не видно |
|---|---|---|
| PCAP | всё (если нет шифрования) | содержимое TLS |
| NetFlow | метаданные потоков | содержимое, URL |
| IDS-логи | алерты по сигнатурам | неинспектируемый трафик |
| За CDN/WAF | edge-адреса | реальный origin |

Ключевая мысль: каждая технология добавляет **слепую зону**. Шифрование скрывает содержимое, DoH/DoT — DNS-запросы, CDN — origin, туннели — внутренний поток.

## Шаг 4: как поймать beaconing по метаданным

**Beaconing** — периодические «пульсы» связи с C2-сервером. Его видно по метаданным без содержимого: одинаковые интервалы и похожий объём. Проверить ритм можно так:

```
$ nfdump -r nfcapd.202610110000 'host 10.0.0.5' -o 'fmt:%ts %pkt %byt' | head -4
2026-10-11 03:11:22 912 812340
2026-10-11 03:14:20 903 798120
2026-10-11 03:17:19 909 805600
```

Интервалы (`03:11`, `03:14`, `03:17`) почти равны, объём стабилен — классический признак «low-and-slow». Легитимный трафик обычно «рваный»: всплеск при загрузке страницы, тишина при чтении.

## Что мы теперь знаем

- Анализ строится слоями: PCAP (содержимое), NetFlow (метаданные), IDS/Zeek (события).
- NetFlow описывает поток 5-tuple и счётчиками — по ритму видно beaconing и эксфильтрацию.
- Suricata даёт алерты по сигнатурам, Zeek — богатые логи.
- Прокси, CDN и WAF создают слепые зоны (скрытый origin, edge-адреса).
- «Нет данных» ≠ «нет атаки»: шифрование и посредники оставляют только метаданные.
- По метаданным ловится beaconing: равные интервалы и стабильный объём — признак C2.
- Порядок разбора: сначала NetFlow (кто и сколько), затем IDS (что сработало), затем PCAP нужного окна.
- Каждый слой отвечает на свой вопрос: объём — NetFlow, сигнатура — IDS, содержимое — PCAP.
- Тюнинг правил обязателен: иначе IDS тонет в ложных срабатываниях и пропускает реальное.

| Уровень | Что хранит | Плюсы | Минусы |
|---|---|---|---|
| PCAP | полный пакет | всё содержимое | объём, шифр |
| NetFlow/IPFIX | метаданные потока | масштаб, дёшево | нет содержимого |
| IDS-алерты | срабатывания правил | приоритет | пропуски/ложные |
| Zeek-логи | структурированные события | богатый контекст | объём, тюнинг |

## Если защита мешает

Этот модуль читают с двух сторон. Для атакующего «если защита мешает» — значит, обойти детект:

- **Шифруйся.** TLS/DoH прячут содержимое от сигнатур.
- **Фрагментируй и обфусцируй.** Обход сигнатур — см. [`network-idps-evasion`](network-idps-evasion).
- **Сливайся с легитимным.** HTTPS на 443, CDN, обычные User-Agent — меньше заметно.
- **Не подделывай слепо X-Forwarded-For.** XFF легко подделать только если прокси не доверенный; иначе он перезапишет значение.
- **Помни про метаданные.** Даже при шифровании остаются периодичность, объём и редкие порты — «low-and-slow» уменьшает, но не убирает их.

## Практика: три слоя по одному инциденту

```
$ nfdump -r nfcapd.202610110000 'host 10.0.0.5' -s dstip/bytes -n 10
$ suricata -r capture.pcap -S local.rules -l out/ && cat out/fast.log
$ zeek -r capture.pcap && cat conn.log | zeek-cut id.orig_h id.resp_h id.resp_p | grep 10.0.0.5 | head
$ tshark -r capture.pcap -Y 'tls.handshake.type==1' -T fields -e tls.handshake.extensions_server_name -e tls.handshake.ja3 | sort -u
```

Минимальный набор покрывает все три уровня плюс TLS-метаданные (SNI/JA3) — то, что остаётся видимым даже при шифровании.
