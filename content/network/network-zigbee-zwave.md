Устройства умного дома и промышленного IoT общаются по радио: Zigbee (2.4 ГГц) и Z-Wave (sub-GHz). Их безопасность часто держится на дефолтных или статических ключах, а перехват и реплей доступны с недорогим оборудованием. Урок продолжает [`network-module-wireless`](network-module-wireless).

## Zigbee: стек и 802.15.4

Zigbee работает поверх **IEEE 802.15.4** (2.4 ГГц, 250 кбит/с). Сеть имеет **координатора** (создаёт сеть), роутеры и end-devices. Безопасность — на уровне NWK (сеть) и APS (приложение) с ключами: network key, link key, TC link key.

```bash
# killerbee: сканировать сети Zigbee
sudo zbid
sudo zbstumbler -i zbd0
# Захватить трафик
sudo zbdump -i zbd0 -w zigbee.pcap
tshark -r zigbee.pcap -Y 'zbee' | head
```

## Управление ключами и слабости

- **Дефолтный TC link key** (`ZigBeeAlliance09`) — известен, если не заменён;
- **network key** передаётся по воздуху при вступлении (при слабой защите);
- **отсутствие ротации** — один ключ на всю жизнь сети;
- **replay** — команды повторяются без защиты.

```bash
# Извлечь ключи из захвата
tshark -r zigbee.pcap -Y 'zbee_nwk' -T fields -e zbee_nwk.security | head
# killerbee: перехват и инъекция
sudo zbreplay -i zbd0 -r capture.bin
```

## Z-Wave: sub-GHz и классы безопасности

**Z-Wave** работает на sub-GHz (868/908 МГц), имеет контроллер и узлы. Классы безопасности: **S0** (общий ключ, уязвим к реплею) и **S2** (аутентифицированный, современный). Устройства с S0 — слабое звено.

```bash
# RTL-SDR + декодер Z-Wave (например, zwave-js / rtl_zwave)
rtl_433 -f 868.42M -F json
# Proxmark3 для некоторых sub-GHz задач
pm3 --> hw tune
```

## Перехват и реплей

Основные атаки:

- **Sniffing** — перехват команд;
- **Replay** — повтор команды (открыть дверь/шлюз);
- **Key extraction** — вытащить network key и расшифровать;
- **Jamming** — заглушить канал;
- **Injection** — отправить свою команду.

```bash
# Захват и реплей с HackRF (лаборатория)
hackrf_transfer -r cmd.bin -f 868420000 -s 2000000 -n 2000000
hackrf_transfer -t cmd.bin -f 868420000 -s 2000000
```

## Детект в SOC

- **аномальный радио-трафик** (затруднительно без мониторинга);
- **частые реплеи** одинаковых команд;
- **неизвестные устройства** в сети Zigbee/Z-Wave;
- **всплески jamming** (рост потерь).

## Защита

| Мера | Против чего |
|---|---|
| Заменить дефолтные ключи | перехват/расшифровка |
| Использовать S2 в Z-Wave | реплей S0 |
| Ротация ключей | долгоживущая компрометация |
| Защита от реплея (nonce/counter) | повтор команд |
| Физический контроль периметра | jamming/sniffing |
| Обновление прошивок | известные уязвимости |

## Частые ошибки

- **Оставлять дефолтный TC link key** — сеть читается.
- **S0 в Z-Wave** — реплей.
- **Считать радио «локальным»** — антенна добивает издалека.
- **Игнорировать реплей** — команды не защищены counter'ом.
- **Путать Zigbee и Z-Wave** — разные частоты/протоколы.
- **Не ротировать ключи** — компрометация навсегда.
- **Не мониторить радио** — атаки невидимы.

## Практика: Zigbee-перехват

```bash
# 1. Определить адаптер и сети
sudo zbid
sudo zbstumbler -i zbd0
# 2. Захватить трафик нужного канала
sudo zbdump -i zbd0 -c 15 -w zigbee.pcap
# 3. Разобрать в Wireshark
tshark -r zigbee.pcap -Y 'zbee_nwk' | head
# 4. Проверить, шифруется ли трафик
tshark -r zigbee.pcap -Y 'zbee_nwk.sec' -T fields -e zbee_nwk.security
# 5. Реплей (если не защищено counter'ом)
sudo zbreplay -i zbd0 -r capture.bin
```

Если сеть использует дефолтный TC link key, перехваченный обмен расшифровывается, и команды можно повторять.

## Сравнение Zigbee и Z-Wave

| Свойство | Zigbee | Z-Wave |
|---|---|---|
| Частота | 2.4 ГГц | sub-GHz (868/908) |
| Стандарт | IEEE 802.15.4 | ITU-T G.9959 |
| Топология | mesh | mesh |
| Ключи | network/link | S0/S2 |
| Дальность | десятки м | десятки м |
| Инструменты | killerbee | RTL-SDR/Proxmark |

## Чек-лист IoT-радио

1. Заменён ли **дефолтный TC link key** в Zigbee?
2. Используется ли **S2** в Z-Wave?
3. Есть ли **ротация ключей**?
4. Защищены ли команды от **реплея** (counter)?
5. Мониторится ли эфир на **неизвестные устройства**?
6. Обновляются ли **прошивки** устройств?
7. Ограничен ли **физический радиус** (стены/экранирование)?

```bash
# Приём sub-GHz
rtl_433 -f 868.42M -F json
# Определение Zigbee-сети
sudo zbstumbler -i zbd0
```

Вывод: IoT-радио почти всегда «на доверии». Дефолтные ключи, S0 и отсутствие counter'ов делают реплей и расшифровку тривиальными. Защита — сильные ключи, S2, ротация и свежесть сообщений.

## Харденинг IoT-радио

```text
# Zigbee: заменить TC link key на уникальный (пример политики)
# - не использовать ZigBeeAlliance09
# - включить APS link keys и ротацию
# Z-Wave: включать только S2-устройства
# - избегать S0 или изолировать их
```

Чек-лист:

1. **Уникальные ключи** — заменить все дефолтные.
2. **S2** в Z-Wave — исключить S0.
3. **Ротация** ключей периодически.
4. **Свежесть сообщений** (counter) — против реплея.
5. **Обновления прошивок** — закрыть известные уязвимости.
6. **Мониторинг** неизвестных устройств.
7. **Физический контроль** зоны и экранирование.

```bash
# Приём sub-GHz для инвентаризации
rtl_433 -f 868.42M -F json
# Zigbee-разведка
sudo zbstumbler -i zbd0
```

## Итог по IoT-радио

Zigbee и Z-Wave проектировались под низкое энергопотребление и простоту, а не под строгую безопасность. Дефолтные ключи, S0 и отсутствие counter'ов делают перехват, расшифровку и реплей доступными. Защита — уникальные ключи, S2, ротация и свежесть сообщений, подкреплённые обновлениями прошивок и мониторингом.

## Дополнительно: SDR и декодирование

Для IoT-радио универсальный инструмент — **SDR**. Он позволяет не только слушать, но и декодировать протоколы:

```bash
# Обзор спектра (найти активные частоты)
gqrx
# Датчики 433/868 МГц в JSON
rtl_433 -f 433.92M -F json
# Запись IQ-сигнала для анализа
hackrf_transfer -r iq.bin -f 868420000 -s 2000000 -n 4000000
# Анализ в GNU Radio / inspectrum
```

SDR превращает «чёрный ящик» устройства в наблюдаемый протокол: видно модуляцию, структуру кадров, повторы. Это основа и для реверса неизвестных протоколов, и для поиска устройств с дефолтными ключами.

## Итог

IoT-радио (Zigbee, Z-Wave, sub-GHz датчики) объединяет одна проблема: слабая или отсутствующая криптография и управление ключами. SDR и недорогие адаптеры делают перехват и реплей доступными. Защита — уникальные ключи, S2, ротация, свежесть сообщений и обновления прошивок.
