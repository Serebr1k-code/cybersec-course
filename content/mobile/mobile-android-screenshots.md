## Вопрос, с которого всё начинается

Приложение банка показывает баланс и номер карты. Можно ли просто сделать скриншот? Если на
экране стоит **FLAG_SECURE** — нет. Если флаг забыли — да, и скриншот ляжет в галерею, откуда
уедет в облако и бэкап. Как проверить, какие экраны защищены?

## Наш пример: список окон

Смотрим окна приложения и их флаги:

```bash
$ adb shell dumpsys window windows | grep -E 'Window #|flags'
Window #3 Window{... com.example.bank/.CardActivity}:
    mAttrs=... flags=FLAG_SECURE
Window #5 Window{... com.example.bank/.StatementActivity}:
    mAttrs=... flags=0x0
```

`CardActivity` защищён, `StatementActivity` — нет. Весь урок ведём этот список.

## Шаг 1: что делает FLAG_SECURE

**FLAG_SECURE** — флаг окна, запрещающий системе включать его в скриншоты, запись экрана и
отображение на внешних дисплеях. В приложении его ставят так:

```java
getWindow().setFlags(WindowManager.LayoutParams.FLAG_SECURE,
        WindowManager.LayoutParams.FLAG_SECURE);
```

Для всей Activity — до отрисовки. Без него любой скриншот и запись захватят содержимое.

## Шаг 2: как проверить наличие флага

Способы:
- Статически: искать `FLAG_SECURE` в smali для каждой Activity.
- Динамически: `dumpsys window windows` и смотреть flags у нужного окна.
- Практически: сделать скриншот и посмотреть, есть ли содержимое.

```bash
$ grep -rn 'FLAG_SECURE' smali/ | head
smali/com/example/bank/CardActivity.smali: ...
# StatementActivity — отсутствует
```

## Шаг 3: где его забывают

- Экраны с балансом, выпиской, номером карты.
- Экраны с одноразовыми кодами (OTP).
- Формы ввода пароля и PIN.
- Экраны чата и персональных сообщений.
- QR-коды для платежей.

Каждое такое окно без флага — находка приватности.

## Шаг 4: скриншот и бэкап

Даже если приложение не даёт «сохранить» данные, скриншот ложится в системную галерею. Оттуда
он: попадает в облачную синхронизацию, в общий бэкап, в медиа-сканер других приложений.
FLAG_SECURE разрывает эту цепочку в самом начале.

## Шаг 5: обход FLAG_SECURE

FLAG_SECURE — защита уровня окна, но не абсолютная: на root-устройстве можно попытаться снять
его хуком (`setFlags` без FLAG_SECURE) или сделать дамп памяти/буфера. Поэтому флаг —
необходимый, но не единственный слой. Для критичных экранов его дополняют: не показывать
секрет целиком, скрывать при потере фокуса, маскировать поля.

## Шаг 6: маскирование и потеря фокуса

Хорошая практика: при уходе приложения в фон (`onPause`) экран перекрывается заставкой, а
секретные поля маскируются. Это защищает и от «меню недавних задач», где система показывает
миниатюру последнего экрана. Проверяют: видно ли содержимое в переключателе приложений.

```bash
$ adb shell am start -a android.intent.action.MAIN -c android.intent.category.HOME
```

## Шаг 7: недавние задачи

Переключатель приложений показывает **снимок** последнего экрана. Если приложение не маскирует
содержимое в `onPause`, секрет виден там без всякого скриншота. Поэтому аудит включает
проверку «что видно в Recent Apps».

## Шаг 8: как оформить находку

«Activity `StatementActivity` отображает персональные данные без FLAG_SECURE: содержимое
доступно для скриншотов и записи экрана, попадает в галерею и облачный бэкап; миниатюра видна
в переключателе приложений.» Указывают конкретный экран и способ проверки.

## Шаг 9: как защищают правильно

Ставить FLAG_SECURE на все чувствительные экраны, маскировать содержимое в `onPause`, не
показывать секреты целиком, чистить буфер обмена, использовать `setRecentsScreenshotEnabled(false)`
где доступно. Защита экрана — это набор мер, а не один флаг.

## Что мы теперь знаем

- FLAG_SECURE запрещает скриншоты и запись окна.
- Проверяют статически (smali) и динамически (dumpsys window).
- Часто забывают на выписке, OTP, чатах, PIN.
- Без флага скриншот уходит в галерею и бэкап.
- Правильно — флаг + маскирование + защита Recent Apps.
