## Введение

Современные смартфоны синхронизируют большую часть данных в облако: iCloud (Apple) и Google-аккаунт (Android). Облачный уровень извлечения не требует физического доступа к устройству — достаточно доступа к аккаунту (легально полученного или восстановленного). Для форензики это дополнительный источник; для пентеста — вектор утечки данных через слабо защищённые синхронизации и способ найти токены/историю, которых нет на устройстве.

Важно: облачные данные — это отдельный правовой и этический периметр. Работайте только в рамках авторизации.

## Что синхронизируется

| Платформа | Сервис | Данные |
|-----------|--------|--------|
| Apple | iCloud Backup | бэкап устройства (без Keychain из iCloud) |
| Apple | iCloud Drive | документы приложений |
| Apple | Photos/Messages/Contacts | медиа, сообщения, контакты |
| Google | Google Backup | данные приложений, Wi-Fi, SMS (Android) |
| Google | Google Drive app data | app-specific data |
| Google | Contacts/Photos/Gmail | аккаунт-данные |
| Прочее | WhatsApp/Telegram/… | собственные облачные бэкапы |

Особенность: iCloud-бэкап **не содержит Keychain** (он защищён отдельно, привязан к устройству/паролю), в отличие от локального шифрованного бэкапа.

## Извлечение iCloud-данных (легально)

Инструменты: `iMazing`, `Elcomsoft Phone Breaker`, `iphone-dataprotection`, `pyicloud` (для скриптов). Требуется Apple ID и пароль (и часто 2FA/токен).

```bash
# pyicloud: список устройств и бэкапов
pip install pyicloud
python3 - <<'EOF'
from pyicloud import PyiCloudService
api = PyiCloudService('user@example.com', 'password')
for d in api.devices: print(d)
EOF
```

Коммерческие инструменты умеют скачивать iCloud-бэкап и разбирать его как локальный.

## Google-синхронизации

Google Backup (Android) хранится в аккаунте; данные приложений можно восстановить на новом устройстве. Google Takeout даёт экспорт данных аккаунта (активность, локации, контакты). Для форензики полезны: история местоположений (Timeline), активность приложений, устройства.

```bash
# Google Takeout -> скачать архив, разобрать JSON
unzip takeout-*.zip -d takeout
ls takeout/Takeout/Location\ History/
```

## Полный сквозной пример: сопоставление устройства и облака

```bash
# 1. Локальный бэкап устройства (см. mobile-forensics-android/ios)
# 2. iCloud/Takeout-артефакты
# 3. Ищем общие идентификаторы: device id, account, session
grep -rIl "device_id\|account_id" takeout/ | head
# 4. Сопоставляем временные метки активности
# 5. Находим данные, которых нет на устройстве (удалённые/синхронизированные)
```

В пентесте облачные артефакты помогают найти API-токены приложений (в app-data синхронизации) и понять, какие данные приложение выгружает наружу — потенциальная находка «избыточная синхронизация секретов».

## Приложения и собственные облака

Многие приложения имеют свой бэкенд-бэкап (WhatsApp → Google Drive/iCloud, Telegram → облако). Это отдельные артефакты, часто содержащие переписку/медиа. Для пентеста интересны: токены, URL API, настройки, которые приложение синхронизирует в свой бэкенд (может включать секреты, которые не должны покидать устройство).

## Частые ошибки

- **Ожидать Keychain в iCloud-бэкапе**: его там нет.
- **Игнорировать 2FA**: современные аккаунты требуют второй фактор — токен/код.
- **Путать локальный и облачный бэкап**: разные артефакты и доступность.
- **Забыть про Takeout**: там много данных аккаунта, помимо бэкапа.
- **Не проверять app-specific облака**: собственные бэкенды приложений — отдельный слой.
- **Нарушить периметр авторизации**: облако — чувствительная зона.

## Что дальше / решение

Облако дополняет локальный дамп. Свяжите с `mobile-forensics-android`, `mobile-forensics-ios`, `mobile-ios-backup`. В пентесте проверьте, не синхронизирует ли приложение секреты/токены в облако (находка). Рекомендация: iMazing/Elcomsoft (коммерческие) или pyicloud (скрипты) для iCloud; Takeout для Google.

## Сквозной кейс облачной форензики

Рассмотрим расследование, где часть данных удалена с устройства, но осталась в облаке.

Сценарий: сотрудник удалил приложение и его данные с телефона, но включена синхронизация. Задача — восстановить, какие данные приложение выгружало. Начинаем с легального доступа к аккаунту (по политике компании или с согласия). Для iCloud используем iMazing или Elcomsoft Phone Breaker: они скачивают iCloud-бэкап и app-specific данные (iCloud Drive). Для Google — Google Takeout, дающий экспорт активности, локаций, контактов и данных приложений.

Скачанные данные разбираем: ищем идентификаторы устройства и аккаунта, сопоставляем временные метки активности с локальными артефактами. Даже если приложение удалено, его данные могут остаться в облачном бэкапе. Это ключевое преимущество облачного уровня: он «переживает» удаление на устройстве.

В пентест-контексте облачный анализ выявляет избыточную синхронизацию: не выгружает ли приложение в свой бэкенд секреты, токены, ПДн, которые должны оставаться на устройстве. Это находка класса «утечка через синхронизацию». Пример: приложение синхронизирует API-ключ в облако для «бесшовного» входа — ключ доступен любому, кто получит аккаунт.

## iCloud: что и где лежит

iCloud Backup хранит бэкап устройства, но не Keychain (он защищён отдельно и привязан к устройству). iCloud Drive хранит документы приложений, которые они явно туда пишут. Photos/Messages/Contacts — отдельные сервисы. Для форензики важно понимать, что «облако» — это не один сервис, а набор, и данные распределены. Инструмент iMazing показывает дерево и позволяет выборочно скачивать.

## Google: Takeout и Backup

Google Backup (Android) хранит данные приложений и восстанавливается на новом устройстве. Takeout даёт «сырые» данные аккаунта: Timeline (локации), активность приложений, устройства, контакты. Разбираем JSON/CSV. Для пентеста интересны активность и устройства: они показывают, какие устройства и сессии связаны с аккаунтом.

## Собственные бэкенды приложений

WhatsApp, Telegram, Signal, банки — у каждого свой бэкенд. Их бэкапы (например, WhatsApp → Google Drive) содержат переписку. Для пентеста это отдельный слой: проверьте, что приложение синхронизирует и насколько защищено. Слабые места: незашифрованные бэкапы, слабая аутентификация API, избыточные данные в синхронизации.

## Ограничения и этика

Облако требует аутентификации (часто 2FA). Доступ к нему — чувствительная операция с правовыми последствиями. Работайте строго в рамках авторизации, фиксируйте согласия. Не анализируйте данные, выходящие за задачу. По завершении удаляйте копии.

## Чек-лист облачного анализа

Определите сервисы синхронизации, получите легальный доступ, скачайте данные, сопоставьте с локальными артефактами, выявите избыточную синхронизацию секретов, оформите находки и рекомендации (минимизировать синхронизацию, шифровать бэкапы, ограничивать данные на сервере).

## Юридические и организационные аспекты

Облачный уровень — самый чувствительный с точки зрения права: данные в аккаунте принадлежат пользователю и могут содержать информацию третьих лиц. В рамках корпоративного расследования доступ оформляется через политику и согласие; в пентесте приложения облачные данные анализируются только если это входит в scope. Фиксируйте источник данных, время доступа, объём. Не выгружайте лишнее.

## Практические инструменты

Для iCloud: iMazing (GUI), Elcomsoft Phone Breaker, pyicloud (скрипты). Для Google: Takeout (веб-экспорт), gcloud (для корпоративных аккаунтов с правами). Для собственных бэкендов приложений — их API/экспорт. Ведите журнал: что скачано, когда, каким инструментом.

## Сопоставление с локальными данными

Ключевая ценность облака — данные, которых нет на устройстве (удалённые, старые). Сопоставляйте временные метки и идентификаторы устройства/аккаунта с локальными артефактами. Так восстанавливается картина: что приложение синхронизировало и когда.

## Итог

Облачная форензика дополняет локальную и выявляет избыточную синхронизацию секретов — находку для отчёта. Работайте строго в рамках авторизации, документируйте каждый шаг и удаляйте копии по завершении.

## Практикум: сопоставление облака и устройства

Разберём сценарий, где нужно связать облачные данные с локальными.

Шаг 1. Локальный дамп. Извлекаем данные приложения с устройства (см. `mobile-forensics-android`/`mobile-forensics-ios`). Фиксируем хэши.

Шаг 2. Облачные данные. Для iCloud — скачиваем бэкап (iMazing/Elcomsoft) или app-specific данные; для Google — Takeout. Для собственных бэкендов — экспорт/API.

Шаг 3. Сопоставление. Ищем общие идентификаторы: `device_id`, `account_id`, серийный номер, временные метки. Сопоставляем активность приложения в облаке с локальными артефактами.

Шаг 4. Поиск удалённого. Если приложение удалено, его данные могут остаться в облачном бэкапе. Извлекаем и анализируем — это уникальная ценность облачного уровня.

Шаг 5. Выявление избыточной синхронизации. Проверяем, не выгружает ли приложение в бэкенд секреты (токены, ключи), которые должны оставаться на устройстве. Это находка «утечка через синхронизацию».

## Инструменты

iMazing, Elcomsoft Phone Breaker, pyicloud (iCloud); Takeout, gcloud (Google); собственные API приложений. Для анализа — iLEAPP/ALEAPP, json-парсеры.

## Что писать в отчёте

Для каждой находки: источник (облако/устройство), тип данных, факт избыточной синхронизации, рекомендацию. Отметьте ограничения (2FA, доступность). Соблюдайте периметр авторизации и приватность.
