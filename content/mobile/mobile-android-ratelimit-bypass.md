## Вопрос, с которого всё начинается

Ты нашёл эндпоинт с 4-значным кодом подтверждения. Перебираешь — а сервер через несколько
попыток отвечает `429 Too Many Requests`. Защита от перебора — это хорошо, но её часто считают
по ключу, который атакующий контролирует. Проверим, по чему считает лимит наш API.

## Наш пример: ответы с заголовками

Смотрим ответы сервера на серию запросов:

```bash
$ curl -si -X POST https://api.example.com/verify -d 'code=1234' | grep -i 'HTTP\|ratelimit\|x-'
HTTP/2 200
X-RateLimit-Limit: 10
X-RateLimit-Remaining: 3
```

Заголовки `X-RateLimit-*` показывают, что лимит есть. Весь урок ведём этот ответ.

## Шаг 1: что такое rate-limit и зачем

**Rate-limit** — ограничение числа запросов за промежуток времени. Защищает от перебора паролей,
кодов, токенов, от DoS. Считается по **ключу**: чаще всего по IP-адресу, по аккаунту/токену, по
устройству. Проблема в том, что не все ключи уникальны и не все атакующий не может подделать.

## Шаг 2: определяем ключ

Меняем параметры и смотрим, когда счётчик сбрасывается:
- Меняем пароль, но не IP → счётчик растёт (ключ — IP).
- Меняем IP (через прокси) → счётчик сбрасывается (ключ — IP).
- Меняем `X-Forwarded-For` → счётчик сбрасывается (ключ — доверенный заголовок).

```bash
$ curl -si -H 'X-Forwarded-For: 1.2.3.4' -X POST https://api.example.com/verify -d 'code=1' \
  | grep -i 'x-ratelimit-remaining'
X-RateLimit-Remaining: 10
```

Счётчик вернулся к 10 — значит, лимит привязан к IP, а IP сервер берёт из заголовка, который
мы контролируем. Это и есть обход.

## Шаг 3: подделка заголовков

Самая частая причина обхода — сервер за обратным прокси берёт клиентский IP из
`X-Forwarded-For`, `X-Real-IP`, `X-Client-IP`, `Forwarded`. Если прокси не вычищает эти
заголовки, каждый запрос с новым значением — «новый клиент».

```bash
$ for i in $(seq 1 50); do curl -s -H "X-Forwarded-For: 10.0.0.$i" ... ; done
```

## Шаг 4: смена «устройства»

Если лимит привязан к устройству (device ID, установочный ID), помогает сброс идентификатора:
переустановка, очистка данных, подмена заголовка с device ID. В мобильном API это часто
контролируемый клиентом параметр.

## Шаг 5: другие ключи

- По аккаунту: если перебор идёт по многим аккаунтам, лимит на один аккаунт не мешает
  (**password spraying**).
- По эндпоинту: обход через старую версию API или альтернативный путь.
- По токену: если токен можно создать много, лимит не работает.

## Шаг 6: логика вместо ключа

Иногда лимит есть, но сбрасывается при успешной операции, при смене тела, при добавлении
пробела/регистра. Тогда его обходят вариациями запроса. Важно: это не «взлом шифра», а
недоработка счётчика.

## Шаг 7: как понять, что обход сработал

Признак — сервер перестал отвечать `429` и продолжает обрабатывать запросы. Правильный тест:
серия из N запросов, где N заведомо больше лимита. Если все прошли — лимит обойдён.

```bash
$ for i in $(seq 1 30); do
    code=$(curl -s -o /dev/null -w '%{http_code}' -H "X-Forwarded-For: 10.0.0.$i" ...);
    echo "$i:$code";
  done | grep -c 429
0
```

Ноль ответов `429` при 30 запросах — обход подтверждён.

## Шаг 8: почему это критично

Обход rate-limit сам по себе не даёт доступ, но **снимает защиту от перебора**. Вместе с
коротким кодом или слабым паролем он превращается в захват аккаунта. Поэтому это находка
высокой важности, даже если «просто» лимит.

## Шаг 9: как защищают правильно

Считать лимит по нескольким ключам (IP + аккаунт + устройство), брать IP из доверенного
источника (реальный peer, а не заголовок от клиента), чистить `X-Forwarded-For` на прокси,
использовать экспоненциальную задержку, капчу, блокировку после N неудач. И не полагаться
только на IP — за NAT он общий.

## Шаг 10: порядок проверки

1. Найти эндпоинт с ограничением (логин, verify, reset).
2. Определить ключ лимита (менять IP/заголовок/аккаунт).
3. Проверить подделку заголовков.
4. Проверить альтернативные ключи и версии.
5. Оформить: сколько запросов прошло сверх лимита.

## Что мы теперь знаем

- Rate-limit считается по ключу: IP, аккаунт, устройство, токен.
- Если IP берётся из `X-Forwarded-For`, лимит обходится заголовком.
- Смена «устройства» и старые версии API — тоже обходы.
- Обход лимита снимает защиту от перебора.
- Правильная защита — несколько ключей и доверенный источник IP.
