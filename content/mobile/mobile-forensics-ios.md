## Введение

iOS-форензика сложнее Android: устройство зашифровано, песочницы изолированы, а полный доступ требует jailbreak или аппаратных методов. Но доступны уровни извлечения: iTunes/Finder-бэкап (логический), полный файловый дамп (jailbreak + checkm8/palera1n), облачные данные (iCloud). Для пентестера ключевое — Keychain и артефакты приложений. Этот урок — практический конвейер извлечения и анализа iOS.

Принцип тот же: копия → хэш → анализ. Учитывайте, что `IsEncrypted` в бэкапе определяет доступность Keychain.

## Уровни извлечения iOS

| Уровень | Метод | Данные |
|---------|-------|--------|
| Логический | iTunes/Finder backup | файлы песочниц (+ Keychain при шифровании) |
| Полный | checkm8/palera1n + файловый дамп | всё, включая system |
| Аппаратный | chip-off/JTAG | весь flash |
| Облако | iCloud API | синхронизации |

## Логическое извлечение (бэкап)

```bash
idevice_id -l
idevicebackup2 backup --full ./ios_backup
plutil -p ./ios_backup/Manifest.plist | grep -i encrypted
# анализ Manifest.db
sqlite3 ./ios_backup/Manifest.db "SELECT domain,count(*) FROM Files GROUP BY domain ORDER BY 2 DESC LIMIT 20;"
```

При шифрованном бэкапе — расшифровка (`iOSbackup`, `iphone-dataprotection`), см. `mobile-ios-backup`.

## Полный дамп через checkm8/palera1n

checkm8 — неисправимый аппаратный эксплойт для чипов A5–A11 (iPhone 5s–X). Он позволяет загрузить нестандартный образ и получить доступ к файловой системе. `palera1n` — современный инструмент для checkm8-устройств (в т.ч. на новых iOS).

```bash
# palera1n (на поддерживаемом устройстве)
palera1n -f            # tethered/rootless режим
# после загрузки — SSH/файловый доступ
ssh root@<device-ip>
# сбор контейнеров приложений
tar czf /tmp/containers.tgz /var/mobile/Containers/Data/Application
```

Полный дамп даёт всё, включая `keychain-2.db` (для классов, доступных после разблокировки).

## Артефакты iOS

| Артефакт | Путь |
|----------|------|
| Песочницы приложений | `/var/mobile/Containers/Data/Application/<uuid>` |
| Preferences | `.../Library/Preferences/*.plist` |
| Cookies | `.../Library/Cookies/Cookies.binarycookies` |
| Кэш | `.../Library/Caches/` |
| Keychain | `/private/var/Keychains/keychain-2.db` |
| SMS/iMessage | `/var/mobile/Library/SMS/sms.db` |
| Геолокации | `/var/mobile/Library/Caches/com.apple.routined/` |
| Звонки | `/var/mobile/Library/CallHistoryDB/` |
| Аккаунты | `/var/mobile/Library/Accounts/Accounts3.sqlite` |

## Полный сквозной пример: извлечение токена

```bash
# 1. Бэкап (шифрованный -> доступен Keychain)
idevicebackup2 -i backup --full ./ios_backup   # вводим пароль
# 2. Расшифровка
python3 -m iOSbackup -b ./ios_backup -p 'pass' -o ./out
# 3. Файлы приложения
grep -rIl "eyJ\|token\|secret" ./out/AppDomain-com.target.app/ | head
# 4. Preferences
plutil -p ./out/AppDomain-com.target.app/Library/Preferences/com.target.app.plist | grep -i token
# 5. Keychain
sqlite3 ./out/KeychainDomain/keychain-2.db "SELECT svce,acct FROM genp;" | head
```

## iLEAPP: автоматический анализ

```bash
pip install ileapp
python3 ileapp.py -t itunes -i ./ios_backup -o ./ileapp_out
# открыть ileapp_out/index.html
```

iLEAPP разбирает: сообщения, звонки, геолокации, установленные приложения, cookies, Keychain-метаданные, подключённые сети, фотографии. Для полного дампа — `-t fs`.

## Частые ошибки

- **Незашифрованный бэкап**: Keychain недоступен — не делайте вывод «секретов нет».
- **Нет пароля бэкапа**: расшифровка невозможна — данные частично недоступны.
- **checkm8 не поддерживает устройство**: A12+ (XS и новее) не уязвимы — нужен другой подход.
- **Игнорировать `binarycookies`**: cookies в бинарном формате, нужен парсер.
- **Забыть про контейнеры**: путь с UUID — получайте актуальный из `Manifest.db`.
- **Работа на живом устройстве**: риск изменить данные.

## Что дальше / решение

Порядок: бэкап → (при необходимости) расшифровка → полный дамп (jailbreak) → сбор артефактов → iLEAPP → Keychain. Свяжите с `mobile-ios-backup`, `mobile-ios-keychain`, `mobile-ios-data-protection`. Рекомендация: iLEAPP + полный дамп на checkm8-устройстве.

## Сквозной кейс iOS-форензики: от устройства до отчёта

Разберём полный цикл на конкретном примере — извлечение данных банковского приложения с checkm8-совместимого iPhone X.

Первым делом фиксируем состояние устройства: модель, версию iOS, состояние блокировки. Это определяет доступный уровень извлечения. iPhone X (A11) уязвим к checkm8, значит доступен полный файловый дамп. Если бы это был iPhone 12 (A14), оставался бы только логический бэкап или аппаратный chip-off, что кардинально меняет объём доступных данных. Поэтому первая таблица решения — совместимость устройства.

Далее выбираем метод. Для полного дампа используем palera1n в rootless-режиме. После загрузки устройство даёт SSH-доступ к файловой системе. Важно сразу сделать побитовую копию интересующих разделов, а не работать с живой ФС: изменения метаданных (atime, журналы) искажают доказательства. Копируем контейнеры приложений и системные базы через `tar` с сохранением атрибутов, затем считаем SHA-256 архива для цепочки сохранности.

После извлечения начинается анализ. Ключевые артефакты банковского приложения: песочница с базами SQLite, Preferences, Cookies, Keychain. Отдельно берём системные артефакты: `accounts3.sqlite` (учётные записи), `sms.db` (сообщения, часто с OTP), геолокации `routined`. Сопоставление времени активности приложения с SMS даёт картину, какие OTP использовались.

Для Keychain важна оговорка: значения расшифровываются системным ключом, но при полном дампе с разблокированного устройства часть классов доступна. Таблица `genp` в `keychain-2.db` содержит сервис, аккаунт и зашифрованное значение; расшифровка требует ключей из keybag. Инструменты `iphone-dataprotection` автоматизируют это. Полученные пароли и токены — самое ценное.

Наконец, прогоняем всё через iLEAPP: он строит HTML-отчёт с разделами по артефактам, временными линиями и связями. Отчёт — основа для выводов. В пентест-отчёте мы выписываем: какие секреты хранились незащищённо, какой класс Data Protection у критичных файлов, попадали ли токены в бэкап.

## Работа с заблокированным устройством

Если устройство заблокировано и пароль неизвестен, доступ ограничен классами Data Protection. Файлы с классом `NSFileProtectionComplete` без разблокировки не читаются — их ключи выгружены из памяти. Файлы `UntilFirstUserAuthentication` доступны, если устройство хоть раз разблокировали после включения. Поэтому на практике извлекают то, что доступно, и фиксируют ограничение в отчёте, не делая вывода «данных нет».

Аппаратные методы (chip-off, JTAG, извлечение NAND) позволяют получить сырой образ, но требуют оборудования и навыков пайки, а также не гарантируют расшифровку без Secure Enclave. Для типового пентеста приложения такие методы избыточны — достаточно бэкапа и jailbreak-дампа.

## Организация лаборатории

Для воспроизводимости держите: отдельный тестовый iPhone, мак или Linux с libimobiledevice, инструменты (iLEAPP, iphone-dataprotection), изолированную сеть. Фиксируйте версии инструментов и iOS. Ведите журнал: что извлечено, когда, какими командами, с какими хэшами. Это основа профессионального отчёта и защиты результатов в суде при необходимости.

## Работа с бэкапами в расследовании

Бэкап — часто единственный легальный источник данных, когда устройство недоступно (утрачено, заблокировано, изъято). В этом случае вы работаете с копией, которую нужно связать с конкретным устройством: сверяйте `Info.plist`/`Manifest.plist` (серийный номер, версия iOS, дата) с известными данными. Это подтверждает происхождение доказательства.

Если бэкап шифрован, а пароль неизвестен, восстановление ограничено. Иногда пароль известен из корпоративной политики (managed-устройства). Для корпоративных бэкапов проверяйте, включено ли шифрование принудительно.

## Комбинирование уровней извлечения

На практике уровни комбинируют: логический бэкап даёт песочницы, jailbreak-дамп — системные базы и Keychain, облако — удалённые данные. Полная картина складывается из нескольких источников. Сопоставляйте их по идентификаторам и времени.

## Инструменты

iLEAPP для бэкапов и дампов, MVT для проверки на компрометацию (шпионские программы), Autopsy для образов. Для Keychain — iphone-dataprotection. Комбинация даёт полный конвейер от извлечения до отчёта.

## Итог

iOS-форензика — многоуровневый процесс: выбор метода по устройству, извлечение копии, фиксация хэшей, разбор артефактов (iLEAPP/MVT), Keychain, сопоставление источников. Ключевые находки для пентеста — незащищённые секреты и слабые классы Data Protection.

## Практикум: извлечение Keychain из бэкапа

Разберём пошагово извлечение секретов Keychain из шифрованного бэкапа.

Шаг 1. Создаём шифрованный бэкап (нужен пароль):

```bash
idevicebackup2 -i backup --full ./ios_backup
plutil -p ./ios_backup/Manifest.plist | grep -i encrypted   # => true
```

Шаг 2. Расшифровываем:

```bash
python3 -m iOSbackup -b ./ios_backup -p 'password' -o ./out
ls ./out | head
```

Шаг 3. Находим Keychain-базу:

```bash
ls ./out/KeychainDomain/
sqlite3 ./out/KeychainDomain/keychain-2.db "SELECT svce,acct FROM genp;" | head -20
```

Шаг 4. Расшифровываем значения (iphone-dataprotection):

```bash
python3 keychain_tool.py -k ./out/BackupKeyBag -d ./out/KeychainDomain/keychain-2.db
```

На выходе — пары сервис/аккаунт/значение: пароли, токены, ключи.

## Анализ

Ищите: токены сессий, пароли, API-ключи, Wi-Fi PSK. Сопоставляйте с приложениями по `svce` (обычно bundle id или сервисное имя). Для каждой находки — тип, значение, приложение.

## Если бэкап не шифрован

Keychain недоступен. Тогда работайте с файлами песочницы (`Library/Preferences`, SQLite, Cookies) — секреты часто дублируются там (небезопасное хранение). Это тоже находка.

## Что писать в отчёте

Для каждой находки: приложение, сервис, тип секрета, факт наличия в бэкапе, рекомендацию (использовать `ThisDeviceOnly`, не дублировать секреты в файлах).
