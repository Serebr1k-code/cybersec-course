## Вопрос, с которого всё начинается

В рамках реагирования на инцидент у тебя оказался iPhone. Нужно понять, что на нём происходило: какие приложения установлены, какие сообщения и звонки были, куда ходил трафик, есть ли следы малвари. Бэкап тут не подойдёт — нужен более полный снимок устройства. Как его получить и разобрать?

## Наш пример: полный образ и его артефакты

Мобильная форензика iOS — это получение **образа** (снимка данных) и извлечение из него **артефактов** (следов). Уровни извлечения такие:

| Уровень | Метод | Что даёт | Нужен jailbreak |
|---------|-------|----------|-----------------|
| Логический | бэкап, `idevicebackup2` | данные приложений | нет |
| Файловая система | jailbreak-дамп `/` | полная песочница | да |
| Полный образ | checkm8/checkra1n | весь раздел | аппаратно |
| Облако | API iCloud | синхронизации | нет |

Начнём с самого доступного — файловой системы, полученной с jailbreak-устройства. Внутри неё ключевые артефакты:

- `/var/mobile/Library/SMS/sms.db` — сообщения;
- `/var/mobile/Library/CallHistoryDB/CallHistory.storedata` — звонки;
- `/var/mobile/Library/Preferences/*.plist` — настройки;
- `/private/var/keychains/keychain-2.db` — Keychain;
- `/var/mobile/Containers/Data/Application/<uuid>/` — песочницы приложений.

## Шаг 1: Keychain как источник

Мы уже разбирали Keychain в `mobile-ios-keychain`. В форензике он — один из главных источников: там токены, пароли Wi-Fi, ключи. Посмотрим записи:

```
$ sqlite3 keychain-2.db "SELECT CAST(acct AS TEXT), CAST(svce AS TEXT) FROM genp;"
alice@demo.example|demo.session
alice@demo.example|demo.pin
```

`genp` — общие пароли, `inet` — интернет-пароли, `cert` — сертификаты. Записи из разных приложений разделяются по `agrp` (access group). В отчёте фиксируй, какие аккаунты и сервисы найдены.

## Шаг 2: сообщения и звонки

SMS-база — это SQLite. Разберём её схему и вытащим сообщения:

```
$ sqlite3 sms.db ".tables"
chat  handle  message  attachment
$ sqlite3 -header sms.db "SELECT datetime(date/1000000000 + 978307200,'unixepoch') dt, text FROM message LIMIT 3;"
dt                   text
2026-01-15 09:12:01  Встречаемся в 10
2026-01-15 09:13:44  Ок
```

Обрати внимание на дату: iOS хранит время в формате **Apple Cocoa/WebKit** — секунды с 2001-01-01, а не с 1970. Поэтому нужно прибавить `978307200` секунд (сдвиг между эпохами) перед преобразованием в Unix-время. Это частая ошибка новичка — «1970-е» даты в выводе.

## Шаг 3: песочницы приложений

Каждое приложение хранит данные в своём контейнере. Имя каталога — UUID, и связь UUID → bundle лежит в базе `containers`:

```
$ sqlite3 /var/mobile/Library/MobileContainerManager/containers.db \
  "SELECT uuid, identifier FROM app;"
```

Теперь видно, какой UUID какому приложению принадлежит. Внутри контейнера — `Documents/`, `Library/`, `tmp/`. Здесь ищем следы: базы, plist, кэш, файлы, созданные малварью.

## Шаг 4: checkm8 — аппаратный уровень

Для старых чипов Apple (A5–A11) есть аппаратная уязвимость **checkm8**. Она позволяет загрузить собственный код на уровне загрузчика и снять полный образ, даже если устройство заблокировано. Инструмент `checkra1n` использует её для jailbreak. Это самый полный уровень извлечения, но применим только к уязвимым чипам.

## Шаг 5: анализ через iLEAPP

Собранные артефакты удобно разбирать не вручную, а через **iLEAPP** — фреймворк, который автоматически парсит сотни артефактов iOS (сообщения, геолокации, история браузера, установленные приложения, Bluetooth) и формирует HTML-отчёт:

```
$ python3 ileapp.py -t itunes -i ./backup_dir -o ./report
$ ls report/
index.html
```

`-t itunes` указывает тип источника (бэкап), `-i` — входной каталог, `-o` — куда сложить отчёт. Аналоги: `iTunes Backup Analyzer`, `Axiom`.

## Шаг 6: облачные артефакты

Часть данных не лежит на устройстве, а синхронизирована с iCloud: заметки, контакты, история Safari, резервные копии приложений. Для их получения нужны учётные данные пользователя и API iCloud (или официальный запрос к Apple). Это отдельная ветвь — `mobile-forensics-cloud`.

## Шаг 7: порядок действий

Правильный порядок форензики: зафиксировать состояние устройства (модель, версию iOS, время), сделать образ на низком уровне, не изменяя данные, извлечь артефакты, разобрать их через iLEAPP, оформить таймлайн. Ключевое правило — **не изменять оригинал**: работаем с копией, а оригинал храним нетронутым. Иначе доказательства потеряют ценность. Записывай каждое действие с временем: даже простое подключение к устройству меняет некоторые метки, и это нужно учитывать.

## Шаг 8: построение таймлайна

Артефакты по отдельности мало что значат — ценность появляется, когда они выстроены в **таймлайн** (хронологию). Собрав временные метки из разных источников (сообщения, звонки, установленные приложения, история браузера, логи), ты видишь последовательность событий: когда устройство включили, что устанавливали, с кем общались. Инструмент `plaso` (на базе `log2timeline`) автоматически извлекает метки времени из множества форматов и сводит их в одну таблицу. Для мобильных артефактов его используют вместе с iLEAPP: iLEAPP достаёт данные, plaso строит хронологию.

Практический приём — искать «якорные» события. Например, время установки подозрительного приложения; дальше смотрим, что происходило в следующие минуты: сетевые соединения, созданные файлы, запущенные процессы. Так восстанавливается картина инцидента.

## Шаг 9: что не попадает в образ

Как и у любого метода, у форензики есть границы. Часть данных зашифрована классом защиты и недоступна на заблокированном устройстве (см. `mobile-ios-data-protection`). Часть хранится только в iCloud и не синхронизируется локально. Часть удаляется системой по таймеру. Поэтому полный образ — это «почти всё», но не «всё», и в отчёте перечисляют, что именно осталось за пределами извлечения. Чем раньше сделан образ после инцидента, тем больше данных сохранится — система постепенно вытесняет старые артефакты. Практически это означает: если есть подозрение на инцидент, образ снимают сразу, а не «когда дойдут руки», иначе часть следов исчезнет.

## Шаг 10: таймлайн из Manifest.db

Форензика держится на времени. Из бэкапа его достают из индекса `Manifest.db` и метаданных файлов. Сначала посмотрим, какие домены вообще есть:

```
$ sqlite3 Manifest.db "SELECT domain,count(*) FROM Files GROUP BY domain;"
AppDomain-com.demo.sec|2
HomeDomain|1
KeychainDomain|1
```

Дальше каждый `relativePath` превращают в реальный файл (через `fileID`) и читают его mtime/ctime, а для баз (SMS, CallHistory, мессенджеры) — временные поля внутри. Так собирают единый таймлайн: когда пришло сообщение, когда сделан звонок, когда приложение впервые записало токен. В облачных артефактах те же события лежат с серверными таймстемпами — их полезно сверить, чтобы поймать расхождение часов. Помни: `KeychainDomain` в незашифрованном бэкапе зашифрован отдельно, и без пароля записи оттуда не прочитать.

## Что мы теперь знаем

- Форензика iOS идёт по уровням: бэкап → файловая система → полный образ → облако.
- Keychain, SMS-база, история звонков и песочницы приложений — главные артефакты.
- iOS хранит время с 2001 года; нужен сдвиг `978307200`.
- UUID контейнера связан с bundle через `containers.db`.
- checkm8 даёт полный образ на уязвимых чипах.
- iLEAPP автоматизирует разбор артефактов в HTML-отчёт.
- Оригинал не изменяют — работают с копией.
