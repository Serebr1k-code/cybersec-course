## Вопрос, с которого всё начинается

Ты поставил приложение на устройство с jailbreak — и оно отказывается запускаться, показывая «device is jailbroken». Банковские и защищённые приложения проверяют это первым делом. Как приложение понимает, что устройство модифицировано, и что вообще такое jailbreak на iOS?

## Наш пример: DemoApp и его детект

В статике мы нашли в `DemoApp` метод `isJailbroken`. Откроем его псевдокод (по дизассемблеру) и увидим типичную логику:

```
BOOL isJailbroken() {
    if (fileExists("/Applications/Cydia.app")) return YES;
    if (fileExists("/bin/bash")) return YES;
    if (fileExists("/usr/sbin/sshd")) return YES;
    if (canOpenURL("cydia://package/com.example")) return YES;
    if (stat("/etc/apt")) return YES;
    return NO;
}
```

Метод ищет **следы** jailbreak: менеджер пакетов Cydia, стандартный `bash` (на iOS его нет по умолчанию), SSH-демон, файлы пакетного менеджера. Чтобы понять эти проверки, разберёмся, что даёт jailbreak.

## Шаг 1: что такое jailbreak

На Android аналог jailbreak — root. На iOS jailbreak снимает программные ограничения системы: после него появляется доступ к файловой системе за пределами песочницы, можно ставить неофициальные приложения и инструменты (Cydia/Sileo), запускать `frida-server`, читать чужую песочницу и дампить Keychain.

Технически jailbreak бывает двух видов:

| Вид | Что делает | Примеры |
|-----|-----------|---------|
| **Untethered** | переживает перезагрузку | исторические |
| **Tethered/Semi-tethered** | требует повтора после ребута | большинство современных |

Современные инструменты — `palera1n`, `Dopamine` (rootless). Отдельно стоит **checkm8** — аппаратная уязвимость в старых чипах, позволяющая сделать jailbreak даже на заблокированном устройстве.

## Шаг 2: rootless vs rootful

Раньше jailbreak писал файлы прямо в `/` (rootful). С iOS 15 Apple сделала системный том **подписанным и read-only**, поэтому появился **rootless**-jailbreak: изменения кладутся в `/var/jb` и подмешиваются через bind-монтирование. Это важно для тестирования: путь `/var/jb` — маркер rootless-jailbreak, который тоже детектят.

Проверить наличие jailbreak-окружения можно так:

```
$ ssh root@device
root@device # ls /var/jb
Applications  Library  usr
```

## Шаг 3: методы детекта

Приложения проверяют jailbreak десятками способов. Основные категории:

- **Файлы**: `/Applications/Cydia.app`, `/bin/bash`, `/usr/sbin/sshd`, `/etc/apt`, `/var/jb`.
- **URL-схемы**: `canOpenURL:@"cydia://..."`.
- **Права записи**: попытка записать файл вне песочницы (`/private/var/...`) — на чистом устройстве это запрещено.
- **`fork()`**: на чистом iOS приложение не может форкать процесс; на jailbreak — может.
- **Подозрительные симлинки и монтирования**: `/etc/apt`, нестандартные точки монтирования.

Каждая проверка клиентская — а значит, её можно обойти на клиенте. Это ключевой принцип: если детект исполняется на устройстве, у атакующего есть контроль над устройством.

## Шаг 4: обход через Objection

Самый быстрый путь — Objection, который автоматически находит и снимает известные проверки:

```
$ objection -g com.demo.secapp explore
com.demo.secapp # ios jailbreak disable
(agent) Hooking jailbreak detection
(agent) Found 3 jailbreak detection methods
```

Под капотом он перехватывает методы вроде `NSFileManager.fileExistsAtPath:` и `canOpenURL:` и подменяет результат. После этого приложение считает устройство чистым.

## Шаг 5: обход через Frida — точечно

Если Objection не нашёл кастомную проверку, пишем хук сами. Например, перехватим проверку файла:

```javascript
var fm = ObjC.classes.NSFileManager['- fileExistsAtPath:'];
Interceptor.attach(fm.implementation, {
  onEnter: function (args) {
    var p = new ObjC.Object(args[2]).toString();
    this.block = p.indexOf('Cydia') !== -1 || p.indexOf('/var/jb') !== -1;
  },
  onLeave: function (retval) {
    if (this.block) retval.replace(0);   // «файла нет»
  }
});
```

Здесь `args[2]` — путь, который проверяет приложение (нумерация: self, selector, аргумент). Если путь похож на след jailbreak, мы подменяем ответ на «нет». Такой хук гибче: он ловит любые пути, а не только заранее известные.

## Шаг 6: обход через перепаковку

Иногда динамика недоступна (нет jailbreak, но есть IPA). Тогда правят код и переподписывают: находят `isJailbroken` в дизассемблере, патчат инструкцию ветвления, чтобы метод всегда возвращал «нет», и подписывают IPA заново. Это работает, но меняет подпись — tamper-проверки могут заметить (см. `mobile-integrity`).

## Шаг 7: что делать защитнику

Если ты на другой стороне, помни: клиентский детект обходится. Правильная защита — **серверная**: привязка токена к устройству, аттестация (DeviceCheck/App Attest), лимиты и аномалии. Клиентские проверки лишь поднимают планку, но не дают гарантий: они замедляют атакующего, но не останавливают его. Именно поэтому jailbreak-детект в отчёте — это не «дыра», а фактор, который нужно обойти, чтобы добраться до настоящей цели: данных и логики. Если детект удаётся снять за пару минут, его ценность близка к нулю.

Помни, что детектов обычно несколько, и они независимы: снятие одного не отключает остальные. Проверяй приложение после каждого обхода — пока оно не запустится и не дойдёт до нужного экрана, работа не закончена.

## Шаг 8: если детект нестандартный

Бывает, что Objection не находит проверку: приложение использует собственную нативную функцию (например, вызов `stat` или `access` напрямую из C). Тогда идём глубже. Смотрим в дизассемблере, какие системные вызовы делает метод, и перехватываем их через Frida:

```javascript
var stat = Module.findExportByName(null, 'stat');
Interceptor.attach(stat, {
  onEnter: function (args) {
    this.path = args[0].readUtf8String();
  },
  onLeave: function (retval) {
    if (this.path && this.path.indexOf('jb') !== -1) retval.replace(-1);
  }
});
```

Хук на `stat` возвращает «файла нет» для любых jailbreak-путей — универсальнее, чем перечисление конкретных проверок. Главное — не забыть, что детект бывает не один, а несколько уровней, и снимать нужно все.

## Шаг 9: почему rootless-jailbreak меняет правила

Современные jailbreak (Dopamine, palera1n) часто **rootless**: они не монтируют изменяемый `/`, а живут в `/var/jb`. Это ломает наивный детект — проверки вроде `FileManager.default.fileExists(atPath: "/bin/bash")` или `/Applications/Cydia.app` дают `false`, хотя устройство взломано. Поэтому грамотная защита смотрит не только на пути, но и на:

- открываемость схем (`canOpenURL("cydia://")`);
- возможность записи вне песочницы (в rootless `/private/var/mobile` доступен только на чтение);
- вызов `fork()` — на iOS он запрещён;
- следы инъекции: `DYLD_INSERT_LIBRARIES`, нестандартные симлинки.

Вывод для теста: приложение, проверяющее только старые пути, пропустит актуальный jailbreak. Проверяй защиту на свежем jailbreak, а не на устаревшем чек-листе — иначе «детект» даёт ложное чувство безопасности.

## Что мы теперь знаем

- Jailbreak — аналог root: снимает ограничения iOS и открывает доступ к системе.
- Бывает rootful и rootless; rootless кладёт файлы в `/var/jb`.
- Детект ищет следы: файлы Cydia/bash/sshd, URL-схемы, `fork()`, записи вне песочницы.
- `objection ios jailbreak disable` автоматически снимает известные проверки.
- Frida-хук на `fileExistsAtPath:` даёт точечный обход кастомных проверок.
- Перепаковка — альтернатива, когда динамика недоступна.
- Клиентский детект обходится; надёжная защита — серверная.
