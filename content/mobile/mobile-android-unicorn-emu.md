## Вопрос, с которого всё начинается

В нативной библиотеке есть функция расшифровки: на вход байты, на выход — строка. Запускать
всё приложение на устройстве ради одной функции долго, а читать ассемблер вручную — нудно.
Хочется просто «вызвать» эту функцию в песочнице и получить результат. Для этого есть эмулятор
процессора.

## Наш пример: функция расшифровки в libcrypto.so

Из Ghidra мы знаем адрес функции `decrypt` (например, `0x1f40`). Хотим выполнить её без
устройства и получить расшифрованные байты.

## Шаг 1: что такое эмуляция процессора

**Unicorn** — это библиотека, которая эмулирует процессор (ARM, x86, MIPS и др.): вы даёте ей
машинный код и память, она исполняет инструкции одну за другой. Никакой ОС, никакого реального
устройства — только CPU и память. Это идеально для изолированных функций.

## Шаг 2: карта памяти

Эмулятору нужно сказать, где лежат код и данные:

```python
from unicorn import Uc, UC_ARCH_ARM64, UC_MODE_ARM
from unicorn.arm64_const import UC_ARM64_REG_X0, UC_ARM64_REG_PC

mu = Uc(UC_ARCH_ARM64, UC_MODE_ARM)
BASE = 0x1000
mu.mem_map(BASE, 0x10000)          # 64 КиБ памяти
```

`mem_map` выделяет регион памяти. `UC_ARCH_ARM64` — целевая архитектура (AArch64).

## Шаг 3: загрузка кода и данных

```python
code = open('decrypt.bin','rb').read()      # машинный код функции
mu.mem_write(BASE, code)
mu.mem_write(BASE + 0x8000, b'\x11\x22\x33\x44')  # зашифрованные байты
```

Мы кладём в память машинный код функции и входные данные. `decrypt.bin` — это извлечённые
байты функции (их можно вырезать из `.so` по адресу и размеру).

## Шаг 4: аргументы и запуск

По соглашению вызова ARM64 первый аргумент — в регистре `X0`, второй — `X1`:

```python
mu.reg_write(UC_ARM64_REG_X0, BASE + 0x8000)  # указатель на данные
mu.emu_start(BASE, BASE + len(code))
```

`emu_start(начало, конец)` запускает исполнение до конечного адреса. Эмулятор пройдёт
инструкции и остановится.

## Шаг 5: хуки и результат

Чтобы видеть промежуточные значения, вешаем хук на инструкции:

```python
def on_code(mu, address, size, user_data):
    print('exec at', hex(address))
mu.hook_add(UC_HOOK_CODE, on_code)
```

А чтобы забрать результат — читаем память после остановки:

```python
out = mu.mem_read(BASE + 0x8000, 16)
print(out)
```

## Шаг 6: типичные подводные камни

- Функция может вызывать другие — их надо подгрузить или захукать заглушкой.
- Нужен правильный стек: без выделенного стека вызовы упадут.
- Данные могут требовать выравнивания.
- Если функция обращается к `JNIEnv`, эмуляция усложняется — иногда проще Frida.

## Шаг 7: альтернативы

Кроме Unicorn есть Qiling (эмулятор с поддержкой ОС) и Frida Stalker (трассировка реального
процесса). Выбор зависит от задачи: изолированная функция — Unicorn; целая программа —
Qiling/Frida.

## Что мы теперь знаем

- Unicorn эмулирует CPU и память без устройства.
- Нужно замапить память, записать код и данные.
- Аргументы передаются через регистры (X0, X1).
- Хуки показывают промежуточные значения.
- Сложные функции требуют подгрузки зависимостей.
