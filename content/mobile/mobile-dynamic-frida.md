## Вопрос, с которого всё начинается

Статический анализ показал: где-то есть проверка пароля. Но код обфусцирован, и понять, что именно сравнивается, не выходит. Как подсмотреть за приложением **во время работы** — увидеть, какие функции вызываются и с какими данными?

## Наш пример: программа, которая сверяет ввод с секретом

Чтобы показать механику без «магии», возьмём маленькую программу, которая сравнивает аргумент с секретом через `strcmp`, и перехватим это сравнение вживую. Тот же приём в точности применяется к Android-приложению: меняется только цель.

Вот поведение программы без инструментации:

```
$ ./crackme wrongpass
Nope, try again.
```

## Шаг 1: что такое динамический анализ и Frida

**Динамический анализ** — это наблюдение за программой в момент выполнения, в отличие от статики (чтение кода без запуска). **Frida** — инструмент, который внедряется в процесс и позволяет перехватывать вызовы функций, читать и менять их аргументы и результаты.

Ключевое понятие — **хук**: Frida «цепляется» за функцию и выполняет твой код до/после неё. Через `onEnter` смотрим аргументы, через `onLeave` — возвращаемое значение. Так можно узнать секрет, не читая код.

## Шаг 2: attach или spawn

Запустить инструментацию можно двумя способами:

- **attach** — приложение уже работает, Frida подключается к нему. Подходит для анализа на ходу.
- **spawn** — Frida запускает приложение сама и ставит хуки **до** первого кода. Это критично, если проверка выполняется при старте (иначе она обгонит хук).

В Frida spawn делается так: `frida -f <package>` (или через API `frida.spawn([...])`), затем `resume`.

## Шаг 3: первый хук — перехватываем сравнение

Напишем скрипт, который цепляется за `strcmp` и печатает оба аргумента:

```javascript
const f = Module.getGlobalExportByName("strcmp");
Interceptor.attach(f, {
  onEnter(args) {
    console.log("[strcmp] arg1 = " + args[0].readUtf8String());
    console.log("[strcmp] arg2 = " + args[1].readUtf8String());
  }
});
```

Запускаем программу под Frida (spawn) и получаем:

```
[*] strcmp at 0x7f7727c53b50
[strcmp] arg1 = wrongpass
[strcmp] arg2 = 7h15_15_4_53cr37
```

Секрет найден: `7h15_15_4_53cr37`. Мы не читали ни строчки кода — просто посмотрели, что и с чем сравнивается. `arg1` — наш ввод, `arg2` — эталон. Это и есть вся суть динамического анализа.

Обрати внимание: `Module.getGlobalExportByName` — актуальный API Frida 17; в старых версиях он назывался `findExportByName`. Если хук молчит, первым делом проверьте, что имя функции найдено (адрес `0x...` вывелся).

## Шаг 4: находим процесс

Прежде чем подключаться, нужно понять, что вообще запущено на устройстве. Frida умеет перечислять процессы:

```
$ frida-ps
   PID  Name
------  ----------------------
  3546  -bash
  5139  FlClashX
  3623  Hyprland
  3711  Xwayland
  3952  crashhelper
```

Это реальный вывод по локальной системе. На Android то же самое, но с `-U` (подключение к устройству по USB):

```
$ frida-ps -U
  PID  Name
------  ------------------
 1234  com.target.app
```

Здесь `com.target.app` — наш процесс; по нему можно делать `attach`. Название пакета берётся из `AndroidManifest.xml` (`package="..."`), а имя процесса иногда отличается — например, `:remote`.

## Шаг 5: Java-хуки — язык приложения

На Android логика обычно в Java/Kotlin, и Frida умеет перехватывать методы напрямую, без ассемблера:

```javascript
Java.perform(function () {
  var Checker = Java.use("com.target.app.Checker");
  Checker.check.implementation = function (s) {
    console.log("[*] check called with: " + s);
    var result = this.check(s);        // вызываем оригинал
    console.log("[*] original result: " + result);
    return true;                        // принудительно "успех"
  };
});
```

Здесь мы одновременно **логируем** аргумент и **подменяем** результат. Это универсальный приём: если проверка возвращает `boolean`, заставляем её всегда возвращать `true` — и приложение пропускает нас дальше.

## Шаг 6: Objection — готовые команды

Писать скрипты каждый раз неудобно. **Objection** — надстройка над Frida с готовыми командами. Подключение и типовые действия:

```
$ objection -g com.target.app explore
com.target.app on (android: 14) [usb] # android root disable
com.target.app on (android: 14) [usb] # android sslpinning disable
com.target.app on (android: 14) [usb] # android hooking list activities
```

Одной командой `android sslpinning disable` отключается проверка сертификатов — это то, что иначе пришлось бы писать десятками строк на Frida. `android root disable` снимает root-детект. Objection удобен для быстрых операций, а для нестандартной логики возвращаются к Frida-скриптам.

## Шаг 7: дамп и модификация в рантайме

Что ещё делает динамический анализ:

- **Дамп памяти** — выгрузка расшифрованных строк, ключей, DEX-файлов. Например, `frida-dexdump` вытаскивает DEX из памяти (см. `mobile-frida-dexdump`).
- **Перехват аргументов криптографии** — хук `Cipher.init` показывает ключ шифрования.
- **Модификация потока** — подмена результатов проверок, разворот редиректов, отключение детекта.

Динамика особенно сильна там, где статика упирается: обфускация, шифрование, нативный код. Не важно, как написан код, — важно, какие значения доходят до функций.

## Шаг 8: полный сценарий на Android

Соберём всё вместе — как выглядит типичная сессия анализа защищённого приложения:

1. **Запуск.** `frida -U -f com.target.app -l hook.js` — Frida стартует приложение и сразу ставит хуки.
2. **Определяем поверхность.** Смотрим, какие классы и методы есть: `Java.perform` + `Java.enumerateLoadedClasses`. По именам (если они не обфусцированы) находим проверки.
3. **Хукаем подозрительное.** Ставим `implementation` на метод проверки, логируем аргументы и результат.
4. **Обходим.** Если метод возвращает `false` при неверном пароле — подменяем на `true`.
5. **Идём глубже.** Если проверка уходит в нативный код, переключаемся на `Interceptor.attach` по смещению в `.so`.
6. **Дампим.** Выгружаем расшифрованные строки и DEX из памяти.

На каждом шаге главный вопрос один: **какое значение решает судьбу проверки?** Нашли его — нашли обход.

Отдельно стоит сказать про стабильность: не все хуки безопасны. Перехват функции, которую приложение вызывает очень часто (например, сетевой стек), может замедлить его или уронить. Поэтому хуки ставят точечно и снимают, когда они больше не нужны. И помните: инструментация меняет поведение приложения, поэтому выводы о «нормальной» работе делают только без активных хуков.

## Что мы теперь знаем

По-простому:

1. Динамический анализ — наблюдение за программой в работе; Frida — основной инструмент.
2. `spawn` ставит хуки до кода, `attach` подключается к работающему процессу.
3. `Interceptor.attach` перехватывает нативную функцию и показывает её аргументы/результат.
4. `Java.use(...).implementation` подменяет Java-метод и его результат.
5. Objection даёт готовые команды: снять root-детект, отключить SSL-pinning, дампить память.

## На что смотреть дальше

- **Секрет виден в сравнении.** Хук на `strcmp`/`equals` часто решает задачу сразу.
- **Ставьте хук через spawn.** Если проверка на старте — иначе опоздаете.
- **Проверяйте, что хук встал.** Нет адреса — нет хука.
- **Objection — для типового, Frida — для своего.**

## Куда дальше

Мы научились подсматривать за приложением в рантайме. В следующем уроке применим это к конкретным защитам: обход root-детекта, anti-debug и anti-Frida.
