## Вопрос, с которого всё начинается

Вы запускаете приложение под Frida — и оно сразу закрывается. Без Frida работает. Значит, есть
защита, которая замечает инструмент и реагирует. Это RASP. Как её найти и обойти?

## Наш пример: app.apk, падающий под Frida

```bash
$ frida -U -f com.example
[+] Process terminated
```

Приложение стартует и мгновенно завершается. Мы должны найти проверку и понять, что она делает.

## Шаг 1: что такое RASP

RASP (Runtime Application Self-Protection) — набор проверок, которые приложение выполняет о
себе во время работы: не root ли устройство, не подключён ли отладчик, не внедрён ли хук, не
эмулятор ли это, не изменён ли код. При обнаружении приложение меняет поведение: закрывается,
показывает ошибку, портит данные.

## Шаг 2: типовые проверки

- **root**: наличие `su`, `magisk`, файлов `/system/xbin/su`.
- **отладчик**: `TracerPid` в `/proc/self/status`.
- **хуки**: наличие Frida-портов, библиотек `frida-agent`, подозрительных потоков.
- **эмулятор**: характеристики, отсутствие датчиков, `ro.kernel.qemu`.
- **целостность**: хеши DEX/.so, подпись APK.

Каждая — потенциальная точка, где можно перехватить.

## Шаг 3: как найти проверку

Раз запуск под Frida ломает приложение, ищем в коде обращения к `/proc/self/status`, `su`,
`frida`. Статически:

```bash
$ grep -rn -E 'TracerPid|/proc/self/status|frida|su' out/sources | head
Security.java:41:  if (new File("/system/xbin/su").exists()) exit();
```

Нашли проверку. Часто их несколько — RASP состоит из цепочки.

## Шаг 4: динамический обход

Самый гибкий путь — перехватить проверку и заставить вернуть «всё чисто»:

```javascript
Java.perform(function () {
  var F = Java.use('java.io.File');
  F.exists.implementation = function () {
    if (this.getPath().indexOf('su') >= 0) return false;  // прячем root
    return this.exists();
  };
});
```

Так же подменяют чтение `TracerPid` и результаты проверок. Это базовый Frida-обход.

## Шаг 5: статический обход

Если динамика нежелательна, проверку патчат в smali: метод проверки возвращает false/true
нужное значение. Для нативных проверок — патч `.so` (NOP-ить ветку завершения) или подмена
сигнатуры функции.

## Шаг 6: комбинирование проверок

RASP редко состоит из одной проверки: обход одной часто активирует другую. Поэтому сначала
находят **все** проверки (по строкам, системным вызовам), потом нейтрализуют их пакетом.
Готовые скрипты (например, frida-antiroot) уже содержат набор обходов.

## Шаг 7: защита в ответ

Разработчики усложняют: обфусцируют проверки, прячут их в native, проверяют целостность самого
Frida. Это гонка. Практический вывод: сначала понять, что именно проверяется, потом обходить
минимально — иногда достаточно спрятать один признак.

## Что мы теперь знаем

- RASP — набор runtime-проверок среды.
- Типовые проверки: root, отладчик, хуки, эмулятор, целостность.
- Проверки находят по системным строкам/вызовам.
- Динамический обход — подмена результата проверки.
- Проверки комбинируются, обходить нужно пакетом.

## Каталог проверок RASP и их признаки

RASP — это не одна проверка, а набор. Чтобы обходить их системно, полезно держать каталог: что
проверяется, по каким признакам, где искать в коде.

**Root.** Приложение ищет бинарник `su`, каталог Magisk, `ro.debuggable`, `ro.secure`, теги сборки
`test-keys`, подозрительные точки монтирования в `/proc/mounts`. В коде это файловые проверки
(`new File("/system/xbin/su").exists()`) или вызовы `Runtime.exec("which su")`.

**Отладчик.** Читается `TracerPid` из `/proc/self/status` (ненулевое значение = есть отладчик),
вызывается `Debug.isDebuggerConnected()`, проверяется `ptrace`.

**Хуки.** Ищутся следы Frida: порт 27042, именованные каналы `frida-*`, поток `gum-js-loop`,
библиотеки `frida-agent`, `linjector`, подозрительные записи в `/proc/self/maps`.

**Эмулятор.** Проверяются `ro.kernel.qemu`, `/dev/qemu_pipe`, набор датчиков, характерные поля
`Build`.

**Целостность.** Считаются хеши DEX и `.so`, проверяется подпись APK через `PackageManager`.

```bash
$ grep -rn -E 'TracerPid|qemu|frida|getPackageInfo' out/sources | head
Security.java:41: if (new File("/system/xbin/su").exists()) exit();
Anti.java:88: String t = read("/proc/self/status"); if (t.contains("TracerPid:\t0")) ...
```

## Как быстро локализовать проверку

Есть три рабочих приёма, от быстрого к точному.

Первый — статический `grep` по строкам-маркерам (`su`, `frida`, `TracerPid`, `qemu`,
`isDebuggerConnected`). Это сразу даёт список подозрительных мест.

Второй — перехват завершения. Хукаем `System.exit`, `Process.killProcess`,
`Runtime.halt` и печатаем стек. Проверка, которая завершила приложение, окажется в стеке.

```javascript
Java.perform(function () {
  var P = Java.use('android.os.Process');
  P.killProcess.implementation = function (pid) {
    console.log(Java.use('android.util.Log').getStackTraceString(
      Java.use('java.lang.Exception').$new()));
    return this.killProcess(pid);
  };
});
```

Третий — для нативных проверок: перехват `open`/`fopen` и логирование путей, которые приложение
открывает. Если оно читает `/proc/self/status` или ищет `su`, вы это увидите.

## Пакетный Frida-скрипт обхода

Обходить проверки по одной неудобно: часто снятие одной активирует другую. Поэтому готовят один
скрипт, который нейтрализует весь набор сразу.

```javascript
Java.perform(function () {
  // root: прячем su и magisk
  var File = Java.use('java.io.File');
  File.exists.implementation = function () {
    var p = this.getPath();
    if (p.indexOf('su') >= 0 || p.indexOf('magisk') >= 0) return false;
    return this.exists();
  };
  // отладчик: TracerPid = 0
  var BR = Java.use('java.io.BufferedReader');
  BR.readLine.implementation = function () {
    var line = this.readLine();
    if (line && line.indexOf('TracerPid') === 0) return 'TracerPid:\t0';
    return line;
  };
  // отладчик на уровне Java
  var D = Java.use('android.os.Debug');
  D.isDebuggerConnected.implementation = function () { return false; };
});
```

Такой скрипт подгружают при спавне (`frida -U -f com.example -l bypass.js`) — до того, как
приложение выполнит проверки.

## Нативные проверки и патч

Если проверка вынесена в `.so`, хуки на Java-уровне её не тронут. Тогда:

- находят нативную функцию (по строкам-маркерам рядом с ней или по экспортам);
- патчат ветку завершения — заменяют условный переход на NOP;
- либо хукают нативную функцию через `Interceptor.attach` и подменяют возврат.

```javascript
var f = Module.findExportByName('libsecurity.so', 'Java_com_example_Native_isRooted');
Interceptor.attach(f, { onLeave: function (retval) { retval.replace(0); } });
```

Патч `.so` в файле проще, но требует пересборки и повторной подписи APK. Рантайм-хук быстрее для
исследования.

## Таблица: проверка и обход

| Проверка | Признак | Обход |
|---|---|---|
| root | File.exists('/system/xbin/su') | подмена exists |
| отладчик | TracerPid != 0 | подмена readLine |
| Frida | порт 27042, gum-js-loop | переименование/скрытие агента |
| эмулятор | ro.kernel.qemu | подмена Build/getprop |
| целостность | хеш DEX/подпись | патч ожидаемого значения |

## Если не сработало

Если приложение падает до загрузки скрипта, — используйте `frida-gadget`, встроенный в APK, или
спавн-режим с `--no-pause`. Проверка на раннем этапе (`attachBaseContext`) может сработать раньше
подключения.

Если обход одной проверки не помогает, — значит, их цепочка. Пройдите по всем маркерам сразу и
нейтрализуйте пакетом.

Если проверка нативная и не находится, — ищите не имя функции, а строки, которые она использует
(`su`, `/proc/self/status`), и находите код, который на них ссылается.

## Ограничения

RASP повышает стоимость динамического анализа, но не заменяет серверную защиту. Клиентские
проверки можно обойти, потому что они выполняются на устройстве под контролем атакующего. Цель
RASP — усложнить и замедлить, а не сделать невозможным.

Кроме того, агрессивные проверки иногда ломают легальных пользователей: устройства с
кастомными прошивками или включённой отладкой могут блокироваться без причины. Это компромисс
между безопасностью и удобством, который разработчики выбирают сознательно.

## Мини-практика: полный обход за один запуск

Соберём всё в один сценарий: найти проверки, снять их, дойти до интересного кода.

Шаг 1. Разведка статикой — ищем маркеры:

```bash
$ grep -rn -E 'su|magisk|frida|TracerPid|qemu|isDebuggerConnected|getPackageInfo' out/sources | wc -l
37
```

37 совпадений — проверок много. Шаг 2: запускаем приложение под Frida со скриптом-обходом
(подмена `File.exists`, `readLine`, `isDebuggerConnected`, результатов проверки подписи). Шаг 3:
смотрим, дошло ли приложение до рабочего экрана.

Шаг 4. Если снова падает — перехватываем `System.exit`/`killProcess` и читаем стек: там будет
метод проверки, который мы пропустили. Добавляем его в скрипт.

```javascript
Java.perform(function () {
  var PM = Java.use('android.app.ApplicationPackageManager');
  PM.getPackageInfo.overload('java.lang.String', 'int').implementation = function (pkg, flags) {
    var info = this.getPackageInfo(pkg, flags);
    // можно подменить signatures при проверке целостности
    return info;
  };
});
```

Итеративно дополняя скрипт, добиваемся, чтобы приложение работало под Frida. Тогда дальнейший
анализ (хуки на бизнес-логику, дамп данных) становится доступен.

## Частые ошибки

Ошибка первая — снимать проверки по одной и удивляться, что приложение всё равно падает. Проверки
связаны: нейтрализация одной включает другую. Обходить нужно пакетом.

Ошибка вторая — подключаться к уже запущенному приложению. Часть проверок проходит на старте
(`attachBaseContext`), до вашего подключения. Используйте спавн-режим `-f`.

Ошибка третья — хукать только Java. Если проверка в `.so`, Java-хуки не помогут; нужен
`Interceptor.attach` на нативную функцию.

## Как не сломать легитимные устройства

При пентесте важно различать «проверка срабатывает законно» и «ложное срабатывание». Устройство с
разблокированным загрузчиком или включённой отладкой может блокироваться без злого умысла. При
аудите это отмечают как побочный эффект: агрессивный RASP ухудшает опыт честных пользователей.

## Шпаргалка: проверки RASP

| Проверка | Где искать | Обход |
|---|---|---|
| root | `File('/system/xbin/su')` | подмена `exists` |
| отладчик | `TracerPid` в `/proc/self/status` | подмена `readLine` |
| Frida | порт 27042, `gum-js-loop` | скрытие агента |
| эмулятор | `ro.kernel.qemu` | подмена `getprop` |
| целостность | хеш/подпись APK | патч ожидаемого значения |

Начинайте с перехвата `System.exit`/`killProcess` — стек укажет проверку, которую вы пропустили.
Обходите проверки пакетом, а не по одной: они связаны между собой.
