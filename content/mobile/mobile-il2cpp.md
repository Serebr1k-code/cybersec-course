## Вопрос, с которого всё начинается

Unity-игра собрана с backend IL2CPP. Вы открываете APK и ожидаете увидеть `Assembly-CSharp.dll`
с C#-кодом — а его нет. Вместо него `libil2cpp.so` и `global-metadata.dat`. Куда делся C# и
как теперь понять логику игры? Разберём, как IL2CPP компилирует C# в нативный код и как
вернуть структуру обратно.

## Наш пример: содержимое APK

```bash
$ unzip -l game.apk | grep -E 'il2cpp|metadata|Assembly'
  4102464  lib/arm64-v8a/libil2cpp.so
   921344  assets/bin/Data/Managed/Metadata/global-metadata.dat
```

`libil2cpp.so` — движок и скомпилированный C#. `global-metadata.dat` — таблица с именами
классов, методов и полей. Вместе они позволяют восстановить почти всю логику игры.

## Шаг 1: что такое IL2CPP

IL2CPP (Intermediate Language To C++) — технология Unity: C#-код компилируется в CIL, затем
транслируется в C++ и собирается в нативный бинарник. В результате C#-кода в приложении нет,
но есть нативный код плюс метаданные, описывающие типы. Это и защита (сложнее реверсить), и
подсказка (метаданные остаются).

## Шаг 2: global-metadata.dat

Этот файл — таблица: имена классов, методов, полей, строк. Он нужен движку, чтобы знать
структуру C#-типов. Даже если код нативный, метаданные дают «карту». Их версия привязана к
версии Unity, поэтому инструменты требуют указать версию.

## Шаг 3: восстановление символов

Стандартный инструмент — **Il2CppDumper**: он читает `global-metadata.dat` и `libil2cpp.so` и
создаёт скрипты для IDA/Ghidra с осмысленными именами методов:

```bash
$ Il2CppDumper libil2cpp.so global-metadata.dat out/
$ ls out/
dump.cs  script.py  stringliteral.json
```

`dump.cs` — восстановленные объявления классов и методов (без тел). Теперь в дизассемблере
функции называются `Player__TakeDamage` вместо `sub_1234AB`.

## Шаг 4: реверс логики

С восстановленными именами работа идёт как с обычным нативным кодом: находим интересный метод
(проверка покупки, генерация уровня, античит), смотрим его реализацию. Важное отличие — вызовы
между C#-методами идут через таблицы указателей, поэтому полезно сопоставлять `dump.cs` с
адресами.

## Шаг 5: хукинг через Frida

Хукать методы IL2CPP удобно по адресам из `Il2CppDumper`:

```javascript
var addr = ptr("0x1234ABCD"); // Player__TakeDamage из dump
Interceptor.attach(addr, {
  onEnter: function (args) { console.log("damage called"); }
});
```

Это позволяет менять поведение игры (например, отключить проверку покупки) без пересборки.

## Шаг 6: защита и обход

Разработчики защищают IL2CPP так: шифруют `global-metadata.dat`, обфусцируют имена,
используют анти-отладку и проверку целостности. Обход: найти расшифровку метаданных в
рантайме (например, через дамп памяти после загрузки), снять обфускацию по таблицам строк.
Это гонка вооружений, но структура метаданных всегда где-то присутствует, потому что движку
она нужна.

## Что мы теперь знаем

- IL2CPP компилирует C# в нативный код.
- `global-metadata.dat` хранит имена типов и методов.
- Il2CppDumper восстанавливает структуру.
- Frida хукает методы по адресам.
- Защита: шифрование метаданных и обфускация.

## Шаг 7: версии метаданных и совместимость

`global-metadata.dat` начинается с магического числа и номера версии. Версия привязана к
версии Unity, и именно поэтому Il2CppDumper спрашивает её при запуске — от версии зависит
раскладка полей структуры. Если указать неверную версию, дамп получится мусорным.

```bash
$ xxd -l 16 global-metadata.dat
00000000: af1b b1fa 1f00 0000 ...     # magic + version 0x1f (31)
```

Если инструмент не поддерживает версию напрямую, можно указать ближайшую и проверить
результат. Иногда версию метаданных подменяют (модифицированная Unity), и тогда нужен
кастомный парсер — но магическое число и структура обычно сохраняются, потому что движку
нужна совместимость.

## Шаг 8: работа с обфусцированными именами

Многие игры включают обфускацию: имена классов превращаются в `a`, `b`, `c`. `dump.cs`
всё равно даёт структуру (какие методы есть, сколько аргументов), но без осмысленных имён.
Восстановить смысл помогают: строковые литералы (в `stringliteral.json`), которые
обфускатор не всегда прячет; порядок вызовов; сигнатуры методов.

```bash
$ grep -i 'purchase\|premium\|unlock' out/stringliteral.json | head
"premium_unlocked"
```

Строки часто остаются читаемыми даже при обфускации имён — и именно по ним находят нужный
метод. Так, найдя строку `premium_unlocked`, вы ищете метод, который её использует.

## Шаг 9: практический разбор — проверка покупки

Разберём типичную задачу: игра проверяет, куплен ли премиум. В `dump.cs` находим метод
`Shop__IsPremium` и переходим к его адресу в дизассемблере. Часто оказывается, что метод
читает флаг из локального хранилища или делает запрос к серверу. Если проверка только
локальная, её легко обойти хуком:

```javascript
Interceptor.attach(ptr("0x00A1B4D0"), {
  onLeave: function (retval) { retval.replace(1); }  // всегда premium
});
```

Если проверка серверная, обход сложнее: нужно либо подделать ответ сервера, либо найти, как
игра кэширует результат. Разница между локальной и серверной проверкой — ключевая при реверсе
игр, и она видна из того, есть ли в методе сетевой вызов.

## Шаг 10: чек-лист реверса IL2CPP

1. Извлечь `libil2cpp.so` и `global-metadata.dat` из APK.
2. Определить версию Unity/метаданных.
3. Прогнать Il2CppDumper и получить `dump.cs` + скрипты.
4. Найти целевые методы по строкам и именам.
5. Разобрать их в IDA/Ghidra по восстановленным символам.
6. Понять, локальная проверка или серверная.
7. При необходимости — хукнуть через Frida и проверить гипотезу.

Этот порядок экономит время: сначала карта (метаданные), потом цель (строки), потом код.

## Шаг 11: почему IL2CPP всё ещё реверсится

Иногда считают, что IL2CPP «защищает» C#-код. На практике он усложняет реверс, но не
скрывает структуру: метаданные нужны движку, а строки нужны логике. Поэтому IL2CPP — это
повышение порога, а не стена. Настоящая защита добавляется поверх: шифрование метаданных,
анти-отладка, проверка целостности. И даже тогда расшифрованные метаданные в итоге появляются
в памяти, потому что движок должен их прочитать, — и их можно снять дампом. Понимание этого
помогает реалистично оценивать трудозатраты на реверс конкретной игры.

## Шаг 12: от строк к методу — рабочий приём

Когда имён нет, самый быстрый путь к цели — строки. Логика игры почти всегда опирается на
читаемые тексты: названия экранов, сообщения об ошибках, ключи хранилища, URL. Строки лежат
в `global-metadata.dat` и извлекаются в `stringliteral.json`. Дальше вы ищете метод, который
использует нужную строку, — по ссылке на литерал в дизассемблере.

Практический приём: возьмите подозрительную строку (например, `no_premium` или
`license_invalid`), найдите её адрес в бинарнике и посмотрите, какие функции на него ссылаются.
Обычно это и есть проверка. Так реверс IL2CPP-игры сводится к «найти строку → найти ссылку →
разобрать функцию», что гораздо быстрее, чем читать весь нативный код подряд.

## Шаг 13: динамический дамп метаданных

Если `global-metadata.dat` зашифрован, статический дамп не сработает. Тогда применяют
динамический подход: запускают игру под отладчиком/Frida, ждут, пока движок расшифрует
метаданные в память, и снимают их оттуда. Точка входа — функция инициализации IL2CPP, которая
принимает указатель на метаданные; перехватив её, вы получаете расшифрованный буфер.

```javascript
// псевдо-хук: перехватить инициализацию метаданных
Interceptor.attach(Module.findExportByName("libil2cpp.so", "il2cpp_init"), {
  onEnter: function (args) { this.ptr = args[0]; },
  onLeave: function () { dumpMetadata(this.ptr); }
});
```

Этот приём — общий для любой защиты, которая расшифровывает данные «на лету»: расшифрованное
всегда появляется в памяти, и его можно снять. Поэтому шифрование метаданных повышает порог,
но не делает реверс невозможным.

## Шаг 14: как это связано с другими платформами

IL2CPP — не единственный «непрозрачный» рантайм. Похожие ситуации: Flutter (Dart AOT),
React Native (Hermes bytecode), .NET MAUI, Kotlin/Native. В каждом случае компилятор превращает
высокоуровневый код в нативный, но сохраняет метаданные или байткод, нужные рантайму. Общий
подход один: найти, где рантайм хранит структуру, извлечь её и восстановить имена. Освоив
IL2CPP, вы легко перенесёте навык на Flutter и Hermes — принцип тот же, меняются лишь форматы
и инструменты. Именно поэтому этот урок полезен шире, чем «реверс Unity-игр».

## Шаг 15: итог по IL2CPP

IL2CPP компилирует C# в нативный код, но оставляет метаданные, по которым восстанавливается
структура приложения. Рабочий процесс: извлечь `libil2cpp.so` и `global-metadata.dat`,
прогнать Il2CppDumper, найти цель по строкам, разобрать метод и при необходимости хукнуть его
через Frida. Защита (шифрование метаданных, обфускация имён) повышает порог, но не отменяет
подход, потому что движку нужны расшифрованные метаданные в памяти. Понимание этого делает
реверс Unity-игр предсказуемым, а не магическим.

## Шаг 16: типичные ошибки новичка

Первая ошибка — пытаться искать C# в APK: его там нет, только нативный код и метаданные. Вторая —
запускать Il2CppDumper с неверной версией Unity и получать мусор вместо имён. Третья — реверсить
`libil2cpp.so` целиком, не восстановив символы: без `dump.cs` вы утонете в безымянных функциях.
Правильный порядок — сначала метаданные, потом цель по строкам, потом конкретный метод. И ещё:
не забывайте, что проверка может быть серверной, и тогда обход хука на клиенте не поможет.
Понимание этих грабель экономит дни работы и делает реверс предсказуемым.

## Шаг 17: инструменты помимо Il2CppDumper

Il2CppDumper — стандарт, но не единственный. Ghidra с плагином Il2Cpp поддерживает импорт
метаданных прямо в дизассемблер, IDA — через скрипты, сгенерированные дампером. Для мобильных
удобны Frida-скрипты, которые логируют вызовы методов по адресам из дампа. Есть и специализированные
решения (например, il2cppdumper + Il2CppInspector), дающие более удобный навигатор по типам.

Важно понимать принцип: любой из инструментов делает одно и то же — сопоставляет адреса в
`libil2cpp.so` с записями в метаданных и даёт имена. Поэтому выбор инструмента — вопрос удобства,
а не принципиальной возможности. Освоив один, вы легко перейдёте на другой, потому что основа
одна: метаданные плюс нативный код дают восстановленную структуру приложения.
