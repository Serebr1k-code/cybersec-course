## Вопрос, с которого всё начинается

Тебе дали файл `app.apk` — установочный пакет Android-приложения. С чего начать? Он же «бинарный», его не открыть в редакторе. Как вообще устроено мобильное приложение и где в нём искать проблемы?

Хорошая новость: Android-приложение — это, по сути, **ZIP-архив с кодом и ресурсами**. Значит, его можно распаковать и читать. В этом уроке мы разберём один APK по слоям и попутно поймём, чем мобильный пентест отличается от веб-пентеста.

## Наш пример: файл app.apk

Весь урок — на одном объекте, `app.apk`. Начнём с простого: посмотрим, что это за файл.

```
$ file app.apk
app.apk: Zip archive data, at least v2.0 to extract, compression method=deflate
```

Уже первый факт: `file` говорит, что это ZIP-архив. Значит, можно заглянуть внутрь без специальных инструментов.

## Шаг 1: APK — это ZIP

Перечислим содержимое архива:

```
$ unzip -l app.apk
Archive:  app.apk
  Length      Date    Time    Name
---------  ---------- -----   ----
     4320  2024-03-01 10:00   AndroidManifest.xml
  4821112  2024-03-01 10:00   classes.dex
    12044  2024-03-01 10:00   resources.arsc
   180233  2024-03-01 10:00   res/layout/activity_main.xml
      512  2024-03-01 10:00   META-INF/CERT.RSA
```

Что мы видим:

- `AndroidManifest.xml` — «паспорт» приложения: имя пакета, разрешения, компоненты.
- `classes.dex` — скомпилированный код (Dalvik Executable).
- `resources.arsc` — таблица ресурсов.
- `META-INF/CERT.RSA` — подпись приложения.

Следующий вопрос: **что приложение вообще умеет?**

## Шаг 2: читаем манифест

`AndroidManifest.xml` внутри APK — бинарный, обычным текстом не читается. Его декодирует `apktool`:

```
$ apktool d app.apk -o app_decoded
I: Using Apktool 2.9.3
I: Loading resource table...
I: Decoding AndroidManifest.xml with resources...
```

Теперь манифест читается:

```
$ grep -E 'package=|uses-permission|android:exported' app_decoded/AndroidManifest.xml
<manifest package="com.example.app">
  <uses-permission android:name="android.permission.INTERNET"/>
  <uses-permission android:name="android.permission.READ_CONTACTS"/>
  <activity android:name=".MainActivity" android:exported="true">
  <activity android:name=".SecretActivity" android:exported="true">
```

Ключевые находки:

- `package="com.example.app"` — идентификатор приложения.
- Разрешения: `INTERNET`, `READ_CONTACTS` — приложение лезет в интернет и в контакты.
- `android:exported="true"` у `SecretActivity` — этот компонент доступен **другим приложениям** на устройстве. Часто именно так находят уязвимости: чужое приложение может открыть твой скрытый экран.

Следующий вопрос: **а что в коде?**

## Шаг 3: декомпилируем код

`classes.dex` — это байткод. Его превращают обратно в читаемый Java-код инструментом `jadx`:

```
$ jadx -d app_src app.apk
INFO - loading ...
INFO - done
```

Теперь у нас есть исходники на Java. Ищем чувствительные строки:

```
$ grep -rEn 'api[_-]?key|secret|password|token' app_src | head
app_src/com/example/app/Api.java:12: private static final String API_KEY = "sk_live_51H...";
app_src/com/example/app/Api.java:13: private static final String BASE_URL = "https://api.example.com";
```

Вот типичная находка: **зашитый в приложение секрет**. Он есть у каждого, кто скачал APK, — то есть у всего мира. Такой ключ часто даёт доступ к API без всякой авторизации.

## Шаг 4: что ещё бывает

Мобильные уязвимости сводятся к нескольким классам (это карта всей ветки Mobile):

- **Хранение данных:** секреты в коде, в `SharedPreferences`, в логах, в бэкапах.
- **Компоненты Android:** экспортированные активности, ресиверы, провайдеры (IPC).
- **Сеть:** отсутствие проверки сертификата (pinning), доверие пользовательским сертификатам.
- **Защита кода:** обфускация, антиотладка, детект рута — и их обход.
- **Криптография:** самодельные шифры, захардкоженные ключи.

## Шаг 5: Android и iOS — в чём разница

Принцип один: приложение — это архив с кодом. Но есть отличия:

| | Android | iOS |
|---|---|---|
| Формат | APK (ZIP) | IPA (ZIP) |
| Код | DEX (Java/Kotlin) | Mach-O (Swift/ObjC) |
| Декомпилятор | `jadx`, `apktool` | `Ghidra`, `Hopper`, `IDA` |
| Запуск на устройстве | эмулятор/рутованный телефон | только jailbreak |
| Отладка | `Frida`, `adb` | `Frida`, `lldb` |

Android проще для старта: инструменты открытые, эмулятор доступен всем. С него и начинают.

## Где проходит граница доверия

Мобильное приложение живёт в **sandbox** — изолированной «песочнице», где другие приложения не видят его файлы. Граница доверия проходит там, где приложение общается с внешним миром: с сервером, с другими приложениями через компоненты, с системой через разрешения.

Типичная ошибка разработчика — считать, что раз код «внутри» и обфусцирован, ему можно доверять. Но клиент всегда в руках злоумышленника: его можно распаковать, изменить, запустить под отладчиком. Поэтому любая проверка, которую приложение делает на устройстве (подпись, лицензия, рут), в принципе обходима.

## Типовой рабочий процесс

Работа с мобильным приложением идёт по шагам:

1. **Разведка.** Собрать APK/IPA, определить технологии.
2. **Статика.** `apktool` для манифеста и ресурсов, `jadx` для кода, поиск секретов.
3. **Динамика.** Запустить в эмуляторе, подключить `Frida`, перехватить вызовы.
4. **Сеть.** Настроить прокси и перехватить API-трафик.
5. **Обход защит.** Снять pinning, антиотладку, детект рута.

OWASP MASTG — стандарт тестирования мобильных приложений: список проверок по категориям (хранение, криптография, сеть, платформа, код). Держите его как чек-лист — он покрывает почти все реальные находки.

## Что такое Frida и эмулятор

Для динамического анализа нужны два инструмента. **Эмулятор** (Android Studio AVD, Genymotion) — виртуальный телефон на компьютере, где можно запускать приложение и наблюдать его поведение. **Frida** — среда для внедрения в работающее приложение: она перехватывает вызовы функций, подменяет результат и читает данные в памяти.

Пример: приложение проверяет пароль в функции `checkPassword`. С помощью Frida можно перехватить эту функцию и посмотреть, что в неё передают, или заставить её всегда возвращать «успех». Так обходят проверки, которые невозможно прочитать в статике. Связка «эмулятор + Frida» — базовый динамический инструмент мобильного пентестера.

## Как перехватить трафик

Мобильное приложение почти всегда общается с сервером по API. Чтобы увидеть эти запросы, на телефон ставят доверенный корневой сертификат и направляют трафик через прокси (Burp Suite, mitmproxy). Тогда видно, какие данные уходят и приходят.

Если приложение «запинено» (проверяет сертификат сервера), перехват не сработает — и это уже отдельная задача: снять pinning через Frida. Поэтому сеть и динамика идут в мобильном тесте рука об руку.

## Что мы теперь знаем

По-простому:

1. APK — это ZIP-архив с манифестом, кодом и ресурсами.
2. Манифест показывает разрешения и экспортированные компоненты.
3. `jadx` превращает байткод обратно в читаемый код.
4. Секреты в коде доступны каждому, кто скачал приложение.
5. Android проще iOS для обучения: открытые инструменты и эмулятор.

## На что смотреть дальше

- **Начинайте с манифеста.** Разрешения и `exported`-компоненты — быстрый источник находок.
- **Ищите секреты grep'ом.** `api_key`, `secret`, `token`, `password` — первые слова для поиска.
- **Не верьте обфускации.** Она усложняет чтение, но строки часто остаются.
- **Думайте про сеть.** Даже «защищённое» приложение часто можно перехватить.

В следующем уроке мы разберём **платформы Android и iOS** подробнее: как устроены их системы безопасности, что такое sandbox и разрешения и почему одно и то же приложение ведёт себя по-разному на двух платформах. ## Где пригодится

- **CTF (Mobile):** задачи на распаковку APK, поиск секретов и обход проверок.
- **Bug bounty:** анализ мобильных приложений и их API.
- **Пентест:** аудит мобильных приложений по OWASP MASTG.
- **Разработка:** понимание, почему нельзя хранить секреты в клиенте.
