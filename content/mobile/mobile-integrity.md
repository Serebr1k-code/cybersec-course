## Что такое Integrity и SafetyNet/Play Integrity

Приложения, работающие с чувствительными данными (банки, платёжные сервисы), проверяют «целостность» окружения: не рутован ли телефон, не эмулируется ли он, не подделан ли APK, соответствует ли устройство требованиям Google. Для этого используются SafetyNet Attestation (устаревший) и Play Integrity API (современный). Если проверка срабатывает, приложение блокирует функции. Задача пентестера — понять, как проверка устроена, и обойти её. Цель модуля — освоить типовые проверки целостности и их обход.

## Что проверяют

- **Root detection** — наличие `su`, `Magisk`, признаков рута.
- **Emulator detection** — признаки эмулятора (`goldfish`, `ranchu`, sensors, файлы).
- **APK integrity** — хеш/подпись APK.
- **SafetyNet/Play Integrity** — аттестация от Google.
- **Debugger detection** — см. анти-отладку.
- **Hook detection** — детект Frida/Xposed.

## Root detection и обход

Приложения проверяют наличие `su`, `/system/xbin/su`, `test-keys` в build, `Magisk`-артефакты, `RootBeer`. Обход:

```bash
objection -g com.example.app explore
android root disable
```

Или Frida-хук на конкретный метод проверки, возвращающий `false`. Часто детект реализован библиотекой `RootBeer` — хукайте её методы (`isRooted`, `detectRootManagementApps`).

## Emulator detection и обход

Проверки: `Build.FINGERPRINT`, `Build.MODEL`, `Build.MANUFACTURER`, наличие сенсоров, файлов эмулятора. Обход — хуки на `Build`:

```javascript
Java.perform(function () {
    var Build = Java.use('android.os.Build');
    Build.FINGERPRINT.value = 'google/sdk_gphone/...';
    Build.MODEL.value = 'Pixel 5';
});
```

Или используйте физическое устройство с Magisk.

## Play Integrity API

Play Integrity — серверная аттестация: приложение получает токен и отправляет его на свой сервер, сервер проверяет вердикт у Google. Обойти полностью сложно, потому что решение принимает сервер. Подходы:

- подменить результат локальной проверки до отправки (если сервер доверяет клиенту — ошибка);
- использовать устройство, проходящее аттестацию;
- хук на метод получения токена (если приложение само проверяет вердикт).

```javascript
Java.perform(function () {
    var Integrity = Java.use('com.google.android.play.core.integrity.IntegrityManager');
    Integrity.requestIntegrityToken.implementation = function (req) {
        // вернуть поддельный токен
    };
});
```

## Проверка подписи и APK integrity

Приложение может сравнивать хеш APK или подпись с эталоном. Обход — хук на `getPackageInfo` и подмена подписи, либо патч сравнения.

## Инструменты

- **`objection`** — `android root disable`.
- **`Magisk` + `Zygisk` + `Shamiko`** — скрытие root.
- **Frida-хуки** — для кастомных проверок.
- **`RootBeer`-хуки** — готовые скрипты.

## Типичные ошибки и подводные камни

- **Обойти root, но не эмулятор** — приложение всё равно заблокируется.
- **Игнорировать серверную аттестацию** — Play Integrity решается на сервере.
- **Хук не срабатывает** из-за порядка загрузки.
- **Мало скрыть `su`** — Magisk оставляет следы.
- **Забыть про проверку подписи** — пересборка не запустится.
- **Детект Frida мешает** — обойдите его первым.
- **Проверок несколько** — обходите все.

## Справочная таблица

| Проверка | Обход |
|----------|-------|
| Root | `android root disable`, хуки |
| Emulator | хуки на `Build` |
| Подпись | хук `getPackageInfo` |
| Play Integrity | подмена токена/вердикта |
| Hook detection | anti-anti-frida |

## Что дальше / решение

План: определите, какие проверки целостности есть (поведение, строки, библиотеки). Обходите root и эмулятор хуками/Objection, подпись — хуком `getPackageInfo`, Play Integrity — подменой токена или устройством с аттестацией. Комбинируйте с обходом детекторов Frida. Помните: клиентские проверки обходятся, серверные (Play Integrity) — сложнее, но подмена клиентского результата часто работает.

## Практический пример: обход root detection

Разберём сквозной сценарий. Приложение при старте проверяет root и при обнаружении показывает «Device compromised» и закрывается. Шаг 1: запускаем на эмуляторе с root, видим блокировку. Шаг 2: `objection -g com.example.app explore`, затем `android root disable` — часто этого достаточно. Шаг 3: если не помогло, ищем класс проверки: `android hooking list classes | grep -i root` или `grep -rIn 'RootBeer\|isRooted\|su' app_java`. Шаг 4: хукаем метод и возвращаем `false`:

```javascript
Java.perform(function () {
    var Checker = Java.use('com.example.app.RootChecker');
    Checker.isRooted.implementation = function () { return false; };
});
```

Шаг 5: если проверка в нативном коде — `Interceptor` на функцию. Если детект Frida мешает — сначала обходим его.

## Практический пример: обход проверки эмулятора

Приложение проверяет `Build.MODEL`/`FINGERPRINT`. Хукаем:

```javascript
Java.perform(function () {
    var Build = Java.use('android.os.Build');
    Build.MODEL.value = 'Pixel 6';
    Build.FINGERPRINT.value = 'google/raven/raven:13/TQ3A/...';
    Build.MANUFACTURER.value = 'Google';
});
```

Или запускаем на физическом устройстве с Magisk. Иногда проверка комплексная (сенсоры, файлы) — тогда комбинируем хуки.

## Частые вопросы

«`android root disable` не помогает?» — кастомная проверка; хукайте конкретный метод. «Проверка в `.so`?» — Interceptor. «Play Integrity?» — подмена токена или реальное устройство. «Мало обойти root?» — обходите и эмулятор, и подпись. «Детект Frida?» — обойдите первым.

## Что дальше / решение

Итог: определите проверки целостности, обходите root/эмулятор хуками или Objection, подпись — хуком `getPackageInfo`, Play Integrity — подменой токена. Комбинируйте с обходом детекторов. Клиентские проверки обходятся; серверные сложнее, но подмена клиентского результата часто работает.

## Расширенный чек-лист по проверкам целостности

Порядок. Первое: наблюдайте поведение — приложение блокируется на root/эмуляторе? Второе: ищите проверки — `grep -rIn 'RootBeer\|isRooted\|su\b\|FINGERPRINT\|SafetyNet\|Integrity' app_java`. Третье: для root — `android root disable` и хуки на `RootBeer`. Четвёртое: для эмулятора — хуки на `android.os.Build`. Пятое: для подписи — хук `getPackageInfo` с подменой `signatures`. Шестое: для Play Integrity — хук метода получения токена или подмена вердикта. Седьмое: обойдите детекторы Frida до всего остального. Восьмое: проверок обычно несколько — обходите все.

## Как понять, что проверка серверная

Если приложение получает токен и отправляет на сервер, а блокировка приходит от сервера — проверка серверная. Тогда локальные хуки не помогут полностью; нужно либо устройство, проходящее аттестацию, либо уязвимость в том, что сервер доверяет клиенту. Всегда смотрите, где принимается решение.
