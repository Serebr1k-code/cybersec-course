## Вопрос, с которого всё начинается

Вы разобрали APK, но приложение делает что-то, чего в этом коде нет. Логика будто «дополняется»
во время работы. Значит, код загружается динамически. Как его достать?

## Наш пример: app.apk с загрузчиком

В коде находится:

```java
DexClassLoader loader = new DexClassLoader(dexPath, optDir, null, getClassLoader());
Class<?> c = loader.loadClass("com.example.Payload");
```

`DexClassLoader` — класс Android, который загружает DEX-файл в рантайме. Код `Payload` берётся
не из APK, а из `dexPath`.

## Шаг 1: что такое DexClassLoader

Обычно все классы приложения уже в APK. Но иногда код грузят позже: из скачанного файла, из
расшифрованного блоба, из assets. `DexClassLoader` позволяет загрузить DEX из произвольного
пути и создать классы. Это и гибкость, и поверхность атаки.

## Шаг 2: откуда берётся DEX

Источники динамического DEX:

- файл в `assets` или во внутреннем каталоге;
- скачанный по сети (обновление логики);
- расшифрованный из блоба (защита);
- собранный/сгенерированный на устройстве.

Первый шаг анализа — понять, откуда.

## Шаг 3: как найти загрузку

```bash
$ grep -rn -E 'DexClassLoader|loadDex|PathClassLoader|InMemoryDexClassLoader' out/sources
PayloadLoader.java:31: new DexClassLoader(dexPath, ...)
```

Нашли загрузчик. Смотрим, как формируется `dexPath`: где файл создаётся, что в него пишется.
Если пишется из расшифрованного массива — идём к расшифровке.

## Шаг 4: дамп динамического DEX

Самый надёжный путь — выгрузить DEX из памяти, как при распаковке:

```bash
$ frida-dexdump -U -f com.example
```

Он находит все DEX в памяти, включая динамически загруженные. Так получают код, которого нет в
APK.

## Шаг 5: анализ

Полученный DEX читают JADX. Часто это как раз «интересная» часть: проверки, платёжка, защита.
Именно её и прятали.

## Шаг 6: RCE-риски

Если приложение грузит код из внешнего источника без проверки подписи, злоумышленник может
подсунуть свой DEX — это путь к удалённому исполнению кода. Поэтому безопасная реализация
проверяет подпись/хеш динамического кода. При пентесте это проверяют в первую очередь.

## Шаг 7: практика

Типовой порядок: найти DexClassLoader → понять источник DEX → дампнуть из памяти → прочитать.
Если источник внешний — проверить, валидируется ли он.

## Что мы теперь знаем

- DexClassLoader грузит DEX в рантайме.
- Источник может быть файлом, сетью, блобом.
- Загрузку находят по имени класса-загрузчика.
- Динамический DEX дампят из памяти.
- Внешний код без проверки — риск RCE.
