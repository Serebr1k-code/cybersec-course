Мобильное приложение — это тонкий клиент над API. Мы уже разобрали IDOR, BOLA, mass-assignment
и утечки. Здесь копаем в четыре вещи, которые пентестер встречает почти в каждом серьёзном
приложении: **JWT-токены**, **GraphQL**, **версионирование API** и **rate-limit**. Каждая из
них — отдельный класс ошибок: слабый алгоритм подписи, открытая интроспекция, «забытая» старая
версия эндпоинта и защита от перебора, которую легко обойти заголовком.

## Что покрывает модуль

1. **JWT в мобильных** (`mobile-android-jwt-mobile`) — где приложение хранит токен, как
   проверяет подпись и почему `alg: none` всё ещё встречается.
2. **GraphQL-API** (`mobile-android-api-graphql`) — интроспекция, вложенные запросы и
   авторизация на уровне полей.
3. **Версионирование** (`mobile-android-api-versioning`) — как старые `/v1/` живут рядом с
   `/v3/` и почему в них нет новых проверок.
4. **Обход rate-limit** (`mobile-android-ratelimit-bypass`) — счётчики по IP, по заголовкам и
   по токену, и что из этого подделывается.

## Почему такой порядок

Сначала — токен: без него нечего подставлять в запросы. Затем GraphQL — самый «разговорчивый»
интерфейс, где один запрос тянет данные всего графа. Дальше — версии: старый эндпоинт часто
обходит все проверки, добавленные в новый. И в конце — rate-limit: даже правильная авторизация
не спасает, если перебор не ограничен. Опираемся на `mobile-api-security-deep` (BOLA, IDOR,
mass-assignment) — оттуда берём язык запросов и модели угроз.

## Чему вы научиться

- Разбирать JWT, находить слабую подпись и проверять, как приложение её валидирует.
- Работать с GraphQL: интроспекция, вложенность, авторизация полей.
- Находить старые версии API и проверять их на отсутствие защит.
- Понимать, по какому ключу считается rate-limit, и обходить его.

## Связь с другими ветками

Перехват трафика — в модуле `mobile-android-network-deep` и ветке `mobile-ssl-pinning`.
Проверка BOLA/IDOR — в `mobile-api-testing` и `mobile-api-security-deep`. Аутентификация на
устройстве — в `mobile-account-takeover`.

## Квиз

Проверь себя.

```quiz
- question: Чем опасен алгоритм alg: none в JWT?
  options:
    - Токен становится длиннее
    - Подпись не проверяется, токен можно подделать
    - Он медленнее
    - Он не поддерживается сервером
  answer: 1
  explanation: alg: none означает отсутствие подписи — любой может изменить claims.
- question: Что даёт открытая GraphQL-интроспекция?
  options:
    - Ускорение запросов
    - Полную схему API: типы, поля, мутации
    - Шифрование
    - Кэширование
  answer: 1
  explanation: Интроспекция раскрывает всю схему — удобная карта для атаки.
- question: Почему старая версия API опасна?
  options:
    - Она медленнее
    - В ней могут отсутствовать проверки, добавленные в новую
    - Она не поддерживает JSON
    - Она всегда без аутентификации
  answer: 1
  explanation: /v1 часто остаётся живой и без новых защит.
- question: По чему обычно считается rate-limit мобильного API?
  options:
    - По цвету интерфейса
    - По IP, токену или заголовку (X-Forwarded-For и т.п.)
    - По модели телефона
    - По версии Android
  answer: 1
  explanation: Счётчик привязан к ключу; если ключ подделывается — лимит обходится.
```
