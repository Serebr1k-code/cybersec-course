## Вопрос, с которого всё начинается

Мы знаем карту бинарника, но код выполняется — а нам нужно поймать его в конкретный момент:
увидеть, что лежит в регистрах, какой пароль сравнивается, какая ветка выбирается. Для этого
нужен **отладчик**. В iOS это LLDB, работающий в паре с `debugserver` на устройстве. Разберём,
как подключиться и что делать дальше.

## Наш пример: проверка лицензии

В приложении есть метод `-[LicenseManager validate:]`, который решает, разблокирован ли
премиум. Мы хотим остановиться внутри него и посмотреть, что он сравнивает. Именно этот метод
мы будем ловить весь урок.

## Шаг 1: подключение к процессу

На jailbreak-устройстве `debugserver` уже может быть запущен. Подключаемся по USB:

```bash
$ lldb
(lldb) process connect connect://127.0.0.1:1234
Process 4321 stopped
```

Если `debugserver` не поднят, его запускают на устройстве с нужным PID. После подключения
процесс **остановлен** — отладчик держит его на паузе, пока мы не скажем продолжить.

## Шаг 2: точки останова по символу и адресу

Поставить **точку останова** (breakpoint) — значит попросить отладчик остановиться в этом месте:

```bash
(lldb) breakpoint set -n '-[LicenseManager validate:]'
Breakpoint 1: where = MyApp`-[LicenseManager validate:], address = 0x0000000100004a20
```

`-n` — по имени символа. Если символов нет (стрипованный бинарник), ставят по адресу из Mach-O:

```bash
(lldb) breakpoint set --address 0x100004a20
```

Затем `continue` — и как только управление дойдёт до метода, процесс снова замрёт.

## Шаг 3: чтение регистров и памяти

В момент останова смотрим регистры и память:

```bash
(lldb) register read x0 x1
      x0 = 0x0000000283a1c240
      x1 = 0x000000016b2f5a10
(lldb) memory read --format c --count 32 0x0000000283a1c240
0x283a1c240: PREMIUM-UNLOCK-KEY-2024
```

`x0` в ARM64 — первый аргумент метода (объект `self`), `x1` — второй (в Objective-C это
селектор). Чтение памяти по адресу в строковом формате сразу показало секретный ключ — вот
зачем нужен отладчик.

## Шаг 4: вызов методов из отладчика

LLDB умеет выполнять выражения в контексте процесса. Это позволяет **вызвать** любой метод:

```bash
(lldb) expr -l objc -O -- [(LicenseManager *)0x283a1c240 validate:@"anything"]
$0 = NO
```

Так мы спрашиваем у самого объекта, что он думает о нашем вводе, — не переписывая код.

## Шаг 5: обход ptrace-анти-отладки

Многие приложения вызывают `ptrace(PT_DENY_ATTACH, ...)`, чтобы отладчик не мог подключиться.
Точка останова на `ptrace` ловит этот вызов:

```bash
(lldb) breakpoint set -n ptrace
(lldb) continue
Process stopped
(lldb) thread return 0
```

`thread return 0` заставляет функцию немедленно вернуть 0, как будто она успешно отработала, —
и защита думает, что отладчика нет. Это классический приём.

## Шаг 6: что делать без символов

Если бинарник стрипован, символы восстанавливают по строкам и адресам: находим строку
`PREMIUM` в `__cstring`, берём её адрес, ставим точку останова на код, который к ней обращается
(через `breakpoint set --source-pattern-regexp` или перебором `memory find`). Работа медленнее,
но принцип тот же.

## Что мы теперь знаем

- LLDB + debugserver дают полный контроль над живым iOS-процессом.
- `breakpoint set -n` ставит точку по символу, `--address` — по адресу.
- `register read` и `memory read` показывают живые значения и строки.
- `expr` позволяет вызывать методы, `thread return` — обходить анти-отладку.

## Если не сработало

Если подключение отваливается, проверьте, что `debugserver` собран под нужную архитектуру и
запущен с `--lockdown`/`--connect`. Если точка останова не срабатывает, значит метод
инлайнится или вызывается через `objc_msgSend` — ставьте точку на `objc_msgSend` и фильтруйте
по селектору. На не-jailbreak устройстве LLDB доступен только через Xcode для своего
приложения.

## Частые вопросы

**Почему процесс сразу падает при подключении?** Скорее всего, сработала анти-отладка; ловите
`ptrace` и `sysctl`.

**Можно ли отлаживать Release-сборку?** Да, но символов может не быть.

**Что быстрее — LLDB или Frida?** LLDB точнее, Frida удобнее для подмены; часто их сочетают.

## Практика: автоматизация через LLDB-скрипты

Ставить точки останова вручную долго. LLDB умеет исполнять Python-скрипты прямо в
сессии — так настраивают отладку одной командой:

```
(lldb) script
Python Interactive Interpreter. Type 'quit()' to exit.
>>> import lldb
>>> def bp(frame, loc, internal_dict):
...     print("validate called, arg:", frame.FindRegister("x2"))
...     return False
>>> target = lldb.debugger.GetSelectedTarget()
>>> bpnum = target.BreakpointCreateByName("-[LicenseManager validate:]")
>>> bpnum.SetScriptCallbackFunction("bp")
```

Теперь при каждом вызове метода срабатывает наша функция и печатает аргумент — без
ручного `continue`. Так автоматизируют трассировку проверок и собирают значения
лицензионных ключей в один прогон.

## Таблица: команды LLDB для реверса iOS

| Команда | Назначение |
|---------|-----------|
| `process connect connect://...` | подключиться к `debugserver` |
| `breakpoint set -n NAME` | точка останова по символу |
| `breakpoint set --address 0x...` | точка останова по адресу |
| `breakpoint modify -c '...' 1` | условная точка останова |
| `register read x0 x1` | прочитать регистры (аргументы) |
| `memory read --format c 0x...` | прочитать строку из памяти |
| `expr -l objc -O -- [...]` | вызвать Objective-C-метод |
| `thread return 0` | вернуть значение, обойдя анти-отладку |

## Чтение Objective-C объектов: po и x/4gx

Для объекта удобнее `po` (print object), а не ручное чтение памяти:

```
(lldb) po (LicenseManager *)0x283a1c240
<LicenseManager: 0x283a1c240> unlocked=0 key=PREMIUM-UNLOCK-KEY-2024
(lldb) x/4gx 0x283a1c240
0x283a1c240: 0x0000000100a1b000 0x0000000000000000
0x283a1c250: 0x0000000283a1c300 0x0000000000000001
```

`po` вызывает `description` и печатает состояние объекта. `x/4gx` показывает сырые
8-байтовые слова: первый указатель — `isa` (класс), дальше — поля. Так читают
значения ivar-ов без символов.

## Если сработало / не сработало

- **Сработало:** точка останова срабатывает, `register read`/`memory read` показывают
  секрет или аргументы проверки. Дальше можно патчить `thread return`.
- **Точка не срабатывает:** метод мог быть заинлайнен или вызван через `objc_msgSend`.
  Ставь точку на `objc_msgSend` и фильтруй по селектору через `breakpoint command`.
- **Процесс падает при подключении:** активна анти-отладка (`ptrace`/`sysctl`).
  Лови `ptrace`, сделай `thread return 0`, продолжай.

## Ограничения

LLDB даёт контроль, но требует **jailbreak** (или сборку под своим сертификатом).
На современных устройствах с Secure Enclave часть секретов в принципе недоступна в
памяти — они живут в аппаратном модуле. Плюс многие приложения активно
детектируют отладчик (проверки `sysctl`, `getppid`, `PT_DENY_ATTACH`), поэтому обход
анти-отладки — отдельная, иногда долгая, работа.

## Watchpoint: поймать изменение памяти

Точка останова ловит **исполнение**, watchpoint — **запись** в память. Это нужно,
когда неизвестно, какой код меняет флаг, но известен адрес:

```
(lldb) watchpoint set expression -- (int *)0x283a1c260
Watchpoint 1: addr = 0x283a1c260 size = 4 state = enabled
(lldb) continue
Watchpoint 1 hit:
    old value: 0
    new value: 1
```

Мы поймали момент, когда `unlocked` сменился с 0 на 1, — и видим функцию, которая это
сделала (по стектрейсу `bt`). Для обхода лицензии это часто короче, чем искать функцию
проверки: патчим именно то место, где флаг записывается.

## Условные точки останова

Если метод вызывается тысячи раз, поставь условие:

```
(lldb) breakpoint set -n '-[LicenseManager validate:]'
(lldb) breakpoint modify -c '(BOOL)$x2 == 0' 1
```

Теперь останавливаемся только при определённом аргументе (`x2` — третий регистр
ARM64, здесь условно аргумент). Это экономит часы ручного `continue` на «шумных»
методах вроде `-[NSObject init]`.

## Ошибки при отладке iOS

- Ставить точку по символу в стрипованном бинарнике — символов нет, используй адрес.
- Забыть, что после `expr` состояние процесса меняется — перечитывай регистры.
- Не снять анти-отладку: процесс падает при каждом подключении.
- Путать `po` (вызывает `description`) с `p` (печатает выражение) — для объектов
  нужен `po`.
