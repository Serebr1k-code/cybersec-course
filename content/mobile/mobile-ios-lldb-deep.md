## Вопрос, с которого всё начинается

Мы знаем карту бинарника, но код выполняется — а нам нужно поймать его в конкретный момент:
увидеть, что лежит в регистрах, какой пароль сравнивается, какая ветка выбирается. Для этого
нужен **отладчик**. В iOS это LLDB, работающий в паре с `debugserver` на устройстве. Разберём,
как подключиться и что делать дальше.

## Наш пример: проверка лицензии

В приложении есть метод `-[LicenseManager validate:]`, который решает, разблокирован ли
премиум. Мы хотим остановиться внутри него и посмотреть, что он сравнивает. Именно этот метод
мы будем ловить весь урок.

## Шаг 1: подключение к процессу

На jailbreak-устройстве `debugserver` уже может быть запущен. Подключаемся по USB:

```bash
$ lldb
(lldb) process connect connect://127.0.0.1:1234
Process 4321 stopped
```

Если `debugserver` не поднят, его запускают на устройстве с нужным PID. После подключения
процесс **остановлен** — отладчик держит его на паузе, пока мы не скажем продолжить.

## Шаг 2: точки останова по символу и адресу

Поставить **точку останова** (breakpoint) — значит попросить отладчик остановиться в этом месте:

```bash
(lldb) breakpoint set -n '-[LicenseManager validate:]'
Breakpoint 1: where = MyApp`-[LicenseManager validate:], address = 0x0000000100004a20
```

`-n` — по имени символа. Если символов нет (стрипованный бинарник), ставят по адресу из Mach-O:

```bash
(lldb) breakpoint set --address 0x100004a20
```

Затем `continue` — и как только управление дойдёт до метода, процесс снова замрёт.

## Шаг 3: чтение регистров и памяти

В момент останова смотрим регистры и память:

```bash
(lldb) register read x0 x1
      x0 = 0x0000000283a1c240
      x1 = 0x000000016b2f5a10
(lldb) memory read --format c --count 32 0x0000000283a1c240
0x283a1c240: PREMIUM-UNLOCK-KEY-2024
```

`x0` в ARM64 — первый аргумент метода (объект `self`), `x1` — второй (в Objective-C это
селектор). Чтение памяти по адресу в строковом формате сразу показало секретный ключ — вот
зачем нужен отладчик.

## Шаг 4: вызов методов из отладчика

LLDB умеет выполнять выражения в контексте процесса. Это позволяет **вызвать** любой метод:

```bash
(lldb) expr -l objc -O -- [(LicenseManager *)0x283a1c240 validate:@"anything"]
$0 = NO
```

Так мы спрашиваем у самого объекта, что он думает о нашем вводе, — не переписывая код.

## Шаг 5: обход ptrace-анти-отладки

Многие приложения вызывают `ptrace(PT_DENY_ATTACH, ...)`, чтобы отладчик не мог подключиться.
Точка останова на `ptrace` ловит этот вызов:

```bash
(lldb) breakpoint set -n ptrace
(lldb) continue
Process stopped
(lldb) thread return 0
```

`thread return 0` заставляет функцию немедленно вернуть 0, как будто она успешно отработала, —
и защита думает, что отладчика нет. Это классический приём.

## Шаг 6: что делать без символов

Если бинарник стрипован, символы восстанавливают по строкам и адресам: находим строку
`PREMIUM` в `__cstring`, берём её адрес, ставим точку останова на код, который к ней обращается
(через `breakpoint set --source-pattern-regexp` или перебором `memory find`). Работа медленнее,
но принцип тот же.

## Что мы теперь знаем

- LLDB + debugserver дают полный контроль над живым iOS-процессом.
- `breakpoint set -n` ставит точку по символу, `--address` — по адресу.
- `register read` и `memory read` показывают живые значения и строки.
- `expr` позволяет вызывать методы, `thread return` — обходить анти-отладку.

## Если не сработало

Если подключение отваливается, проверьте, что `debugserver` собран под нужную архитектуру и
запущен с `--lockdown`/`--connect`. Если точка останова не срабатывает, значит метод
инлайнится или вызывается через `objc_msgSend` — ставьте точку на `objc_msgSend` и фильтруйте
по селектору. На не-jailbreak устройстве LLDB доступен только через Xcode для своего
приложения.

## Частые вопросы

**Почему процесс сразу падает при подключении?** Скорее всего, сработала анти-отладка; ловите
`ptrace` и `sysctl`.

**Можно ли отлаживать Release-сборку?** Да, но символов может не быть.

**Что быстрее — LLDB или Frida?** LLDB точнее, Frida удобнее для подмены; часто их сочетают.
