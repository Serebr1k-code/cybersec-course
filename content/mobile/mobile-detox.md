## Вопрос, с которого всё начинается

Приложение на React Native — это JavaScript, который рисует интерфейс на нативной платформе.
Monkey его тыкает случайно, скриншоты ловят внешний вид, но ни то, ни другое не проверяет
**сценарий**: «открой профиль → нажми „Сохранить“ → убедись, что появилось подтверждение».
Для сценариев нужен e2e-фреймворк. Для React Native стандарт — Detox.

## Наш пример: конфиг Detox

E2e расшифровывается как *end-to-end*: тест проходит весь путь пользователя, от входа до
результата. Detox описывается двумя файлами: конфигурацией и самими тестами. Начнём с
конфига:

```javascript
// .detoxrc.js
module.exports = {
  configurations: {
    'android.emu.debug': {
      device: { type: 'AndroidEmulator', avdName: 'Pixel_6_API_34' },
      app: { type: 'android.apk', binaryPath: 'android/app/build/outputs/apk/debug/app-debug.apk' }
    }
  }
};
```

Здесь сказано: брать APK по указанному пути и ставить на эмулятор `Pixel_6_API_34`.
`avdName` — имя виртуального устройства (Android Virtual Device).

## Шаг 1: структура теста

Тест Detox пишется на JavaScript и читается почти как инструкция:

```javascript
describe('Профиль', () => {
  it('сохраняет имя', async () => {
    await element(by.id('open-profile')).tap();
    await element(by.id('name-input')).typeText('Alice');
    await element(by.id('save')).tap();
    await expect(element(by.text('Сохранено'))).toBeVisible();
  });
});
```

`element(by.id(...))` ищет элемент по `testID` — идентификатору, который разработчик
проставляет виджетам специально для тестов. `tap()`, `typeText()`, `toBeVisible()` —
действия и проверки.

## Шаг 2: почему Detox не «мигает»

Классическая боль мобильных тестов — асинхронность: тест нажал кнопку и пошёл дальше, пока
анимация ещё играет. Detox решает это **автоматической синхронизацией**: перед каждым шагом
он ждёт, пока приложение «успокоится» — закончатся анимации, сетевые запросы, таймеры. Это
встроенный механизм, а не `sleep(2000)`. Именно поэтому тесты Detox стабильнее.

## Шаг 3: запуск

Локально тест запускается командой, которая поднимает эмулятор, собирает и ставит приложение:

```bash
$ npx detox test -c android.emu.debug
 PASS  e2e/profile.test.js
  Профиль
    ✓ сохраняет имя (3120 ms)
```

Detox сам собрал debug-APK, установил его и прогнал сценарий. Если что-то упало, он делает
скриншот и видео — их кладут в артефакты.

## Шаг 4: в конвейере

В CI Detox ставят после Monkey: сначала дешёвая проверка на падения, потом точные сценарии.
Важная деталь — **кэш эмулятора** и фиксированная версия образа, иначе «зелёный» тест вдруг
краснеет из-за другой версии Android. Обычно используют заранее собранный снапшот эмулятора.

## Шаг 5: что даёт пентестеру

E2e-тесты — это готовые **сценарии**, описывающие, как приложение ходит по API. Читая их,
пентестер быстро понимает поток данных: какие экраны, какие запросы, где токены. Иногда в
`testID` и в тестовых аккаунтах утекают имена внутренних эндпоинтов. Это законная разведка:
тесты лежат в репозитории и часто попадают в сборку.

## Что мы теперь знаем

- Detox — e2e-фреймворк для React Native, тесты на JavaScript.
- Элементы ищутся по `testID`, действия — `tap`/`typeText`.
- Автосинхронизация заменяет `sleep` и убирает «мигание».
- Запуск: `npx detox test -c <конфигурация>`.
- В CI Detox идёт после Monkey, с фиксированным образом эмулятора.

## Жизненный цикл теста

Detox проходит несколько фаз. Сначала `beforeAll` поднимает приложение и ждёт его готовности;
затем каждый `it` выполняет шаги; в `afterAll` приложение закрывается. Важная деталь — между
тестами Detox обычно перезапускает приложение (`reloadReactNative`), чтобы состояние не
перетекало из одного сценария в другой. Если этого не делать, тест может «протекать»: логин
из прошлого теста делает следующий сценарий невалидным.

## Устройство и сборка

Detox различает **конфигурацию устройства** и **конфигурацию приложения**. Устройство — это
эмулятор или реальный телефон; приложение — APK/IPA и способ его установки. Для CI обычно
готовят снапшот эмулятора: один раз запускают, настраивают, сохраняют образ, а в конвейере
поднимают из него. Это экономит минуты на каждой сборке и, что важнее, убирает разницу между
прогонами.

## Стабилизация и ожидания

Даже с автосинхронизацией бывают моменты, которые Detox не отслеживает: анимация, запущенная
вне UI-потока, или сетевой запрос, идущий через нативный код. Тогда используют `waitFor`:
тест ждёт появления элемента с таймаутом. Важно не злоупотреблять этим: `waitFor` с большим
таймаутом маскирует настоящие проблемы производительности. Хороший тест ждёт конкретное
условие, а не «просто время».

## Отладка упавших тестов

Когда тест падает, Detox сохраняет скриншот и видео. Порядок разбора: сначала видео — оно
показывает, на каком шаге всё сломалось; затем скриншот — видно состояние экрана; затем лог
приложения — видно исключение. Частая причина падения — изменение `testID`: разработчик
переименовал идентификатор, и тест перестал находить элемент. Это не баг приложения, а
рассинхронизация теста.

## Что даёт пентестеру

Detox-тесты — это карта пользовательских путей. Читая их, вы видите, какие экраны существуют,
какие кнопки нажимаются и какие запросы уходят. Иногда в комментариях остаются реальные
эндпоинты и тестовые учётки. Это законная разведка: тесты лежат в репозитории, а иногда и
попадают в сборку. Отдельно стоит проверить, не включён ли debug-режим Detox в релизной
сборке — это открывает отладочный мост.

## Реальный случай: тест зелёный, баг есть

Сценарий «сохранить профиль» проходил, но в реальности данные не сохранялись при плохой сети.
Тест не ловил это, потому что эмулятор всегда был онлайн. Урок: e2e-тест проверяет только те
условия, которые в нём воспроизведены. Хорошая практика — добавить сценарии с обрывом сети и
медленным откликом.

## Чек-лист

- приложение перезапускается между тестами;
- образ эмулятора зафиксирован в CI;
- ожидания привязаны к условию, а не к времени;
- падения разбираются по видео, скриншоту и логу;
- проверены сценарии с плохой сетью.

## Куда дальше

Мы прошли всю цепочку: Monkey, скриншоты, Detox. Дальше — как из результатов прогонов
собрать отчёт, который примут: `mobile-pentest-report`. А пока запомни: Detox — это точный
сценарий с автосинхронизацией, и его тесты — отличная разведка API.

## Где пригодится

- **QA:** стабильные e2e-сценарии на каждый релиз.
- **Пентест:** понимание потоков данных приложения из его тестов.
- **Разработка:** защита ключевых сценариев от регрессий.
- **CTF:** автоматизированное прохождение сценариев.
