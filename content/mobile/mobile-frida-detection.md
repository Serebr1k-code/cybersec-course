## Anti-Frida и анти-отладка: что это

По мере роста популярности Frida разработчики стали встраивать в приложения детекторы: проверки наличия `frida-server`, портов Frida, следов в памяти, а также общие анти-отладочные механизмы (ptrace, проверка `TracerPid`, тайминги). Если детектор срабатывает, приложение может выйти, показать ошибку или изменить поведение. Задача пентестера — обнаружить эти проверки и обойти их, чтобы динамический анализ работал. Цель модуля — освоить типовые детекторы и методы обхода.

## Как приложения детектят Frida

- **Порт 27042** — по умолчанию Frida слушает на нём; проверка `connect()`.
- **Имя процесса/потоков** — поиск `frida` в `/proc/self/task/*/comm`.
- **Строки в памяти** — сканирование maps на `frida`, `gum-js-loop`.
- **Файлы** — наличие `frida-server`, `linjector`.
- **Импорты** — проверка загруженных библиотек.

```bash
# проверить, детектится ли Frida
frida-ps -U
adb shell "cat /proc/net/tcp | grep 6970"   # 27042 в hex
```

## Как детектят отладчик

- **`ptrace(PTRACE_TRACEME)`** — если уже отлаживают, вызов падает.
- **`/proc/self/status` → `TracerPid`** — ненулевой означает отладку.
- **Тайминги** — измерение времени выполнения (отладчик замедляет).
- **SIGTRAP** — ловушка.

```javascript
// проверка TracerPid
// cat /proc/self/status | grep TracerPid
```

## Обход: переименование и порт

Самый простой обход — запустить `frida-server` под другим именем и на другом порту:

```bash
adb push frida-server /data/local/tmp/fs
adb shell "/data/local/tmp/fs -l 0.0.0.0:1234 &"
frida -H 192.168.1.10:1234 -f com.example.app -l hook.js
```

Это обходит детекторы по имени файла и порту.

## Обход: скрытие через Frida-скрипты

Существуют готовые anti-anti-frida скрипты, которые перехватывают проверки:

```javascript
// скрыть потоки frida
Java.perform(function () {
    var Thread = Java.use('java.lang.Thread');
    // перехват методов, ищущих 'frida' в именах
});
```

Популярные решения: `frida-detection-bypass`, `anti-frida-bypass`, `magu`. Они перехватывают `open`, `read`, `strstr` и фильтруют следы Frida.

## Обход анти-отладки

- **TracerPid** — хук на `open`/`read` для `/proc/self/status`, подмена значения.
- **ptrace** — хук на `ptrace`, возврат 0.
- **Тайминги** — хук на функции времени (`clock_gettime`, `System.nanoTime`).
- **SIGTRAP** — игнорирование сигнала.

```javascript
var ptrace = Module.findExportByName(null, 'ptrace');
Interceptor.replace(ptrace, new NativeCallback(function () {
    return 0;
}, 'long', ['int', 'int', 'pointer', 'pointer']));
```

## Обход root/integrity detection

Часто тесно связано: приложение проверяет root и целостность. Обход через Objection (`android root disable`) и Frida-хуки на `RootBeer`, `SafetyNet`, `Play Integrity`. Про Play Integrity подробнее — в отдельном модуле.

## Инструменты

- **`frida-server`** — с переименованием и сменой порта.
- **anti-anti-frida скрипты** — готовые коллекции.
- **Objection** — `android root disable`.
- **`medusa`** — фреймворк с модулями обхода.
- **`Magisk` + `Zygisk`** — скрытие root.

## Типичные ошибки и подводные камни

- **Оставить дефолтный порт** — детектится сразу.
- **Не обновить скрипты** — новые версии Frida меняют API.
- **Хук не срабатывает** из-за порядка загрузки — используйте `setImmediate`/`Java.perform`.
- **Детектор в нативном коде** — нужен Interceptor, не Java-хук.
- **Приложение крашится при обходе** — проверьте типы.
- **Не проверить, что детектор вообще есть** — сначала наблюдайте поведение.
- **Забыть про несколько детекторов** — их обычно несколько.

## Что дальше / решение

План: сначала определите, какие детекторы есть (наблюдайте за поведением, смотрите строки и импорты). Затем обходите простыми методами (переименование, смена порта), далее — готовыми anti-anti-frida скриптами, при нативных детекторах — Interceptor. Комбинируйте с обходом root/integrity. Помните, что детекторов обычно несколько, и обходить нужно все.

## Практический пример: обходим детектор Frida

Разберём сценарий. Приложение при запуске ищет `frida-server` по имени файла и порту и завершает работу. Шаг 1: наблюдаем — с Frida приложение падает, без неё работает. Значит, детектор есть. Шаг 2: запускаем `frida-server` под другим именем и на нестандартном порту:

```bash
adb push frida-server /data/local/tmp/fs
adb shell "chmod 755 /data/local/tmp/fs && /data/local/tmp/fs -l 0.0.0.0:1234 &"
frida -H 127.0.0.1:1234 -f com.example.app
```

Шаг 3: если всё равно падает — детектор ищет строки в памяти (`frida`, `gum-js-loop`). Тогда применяем anti-anti-frida скрипт, перехватывающий `open`/`read`/`strstr`:

```javascript
var open = Module.findExportByName(null, 'open');
Interceptor.attach(open, {
    onEnter: function (args) {
        var path = args[0].readCString();
        if (path && path.indexOf('frida') !== -1) {
            this.block = true;
        }
    },
    onLeave: function (retval) {
        if (this.block) retval.replace(-1);   // делаем вид, что файла нет
    }
});
```

Шаг 4: приложение запускается, и мы работаем дальше. Такой подход «спрятать следы» — стандартная практика при обходе анти-анализа.

## Обход анти-отладки

Для TracerPid перехватывайте чтение `/proc/self/status` и подменяйте значение. Для `ptrace` — заменяйте функцию заглушкой, возвращающей 0. Для тайминговых проверок — хукайте функции времени. Помните, что детекторов обычно несколько, и обходить нужно все сразу, иначе приложение всё равно поймёт, что его анализируют.

## Частые вопросы

«Приложение падает сразу?» — детектор в нативном коде, нужен Interceptor. «Не знаю, какой детектор?» — смотрите строки в бинаре (`strings | grep -i frida`), импорты, сетевые проверки. «Порт менять не помогает?» — детектор ищет строки в памяти. «Хук не работает?» — порядок загрузки; используйте `setImmediate`. «Есть готовое?» — да, коллекции anti-anti-frida скриптов.

## Что дальше / решение

Итог: определите детекторы (поведение, строки, импорты), обходите их по возрастанию сложности — переименование/порт, готовые скрипты, нативные хуки. Комбинируйте с обходом root/integrity. Помните, что анти-анализ — это игра в кошки-мышки, и гибкость Frida даёт вам преимущество: почти любую проверку можно перехватить и подменить.

## Расширенный чек-лист по анти-анализу

Определите детекторы. Первое: строки в бинаре — `strings lib/arm64-v8a/*.so | grep -iE 'frida|ptrace|tracer|magisk|su'`. Второе: импорты — какие функции вызываются (`ptrace`, `open`, `connect`). Третье: поведение — приложение падает при Frida, но работает без неё. Четвёртое: сетевые проверки — некоторые детекторы стучатся на localhost:27042.

Обход по возрастанию сложности. Простой: переименовать `frida-server`, сменить порт. Средний: готовые anti-anti-frida скрипты (перехват `open`/`read`/`strstr`). Сложный: нативные детекторы — Interceptor на конкретные функции. Для анти-отладки: хук `ptrace` → 0, подмена TracerPid, хук функций времени.

## Комбинирование с обходом root и integrity

Детекторы часто идут в связке: root + Frida + целостность. Обходите их вместе: `android root disable`, хуки на `RootBeer`, `SafetyNet`, `Play Integrity`. Если обойти только один, приложение всё равно откажется работать.

## Частые вопросы

«Приложение падает без сообщений?» — детектор в нативном коде, смотрите строки и импорты. «Порт и имя не помогают?» — ищут строки в памяти. «Хук `open` не работает?» — используйте `Interceptor.attach` на правильный экспорт. «Готовые скрипты не помогают?» — детектор кастомный, нужен ручной анализ. «Как проверить обход?» — приложение должно работать с Frida.

## Что дальше / решение

Итог: анти-анализ обходится по каскаду — строки/импорты → переименование/порт → готовые скрипты → нативные хуки. Комбинируйте с обходом root/integrity. Помните, что детекторов обычно несколько, и гибкость Frida позволяет перехватить и подменить почти любую проверку.

## Итог по анти-анализу

Запомните последовательность: строки/импорты бинаря → переименование и порт → готовые anti-anti-frida скрипты → нативные хуки. Комбинируйте обход детекторов с обходом root и integrity. Держите коллекцию скриптов и умейте адаптировать их под кастомные проверки. Гибкость Frida — ваше главное преимущество: почти любую проверку можно перехватить и подменить, если понять, что именно она делает.
