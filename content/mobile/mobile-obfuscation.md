## Что такое обфускация и защита от анализа

Обфускация — это намеренное усложнение кода, чтобы затруднить его понимание и модификацию. В мобильных приложениях она бывает нескольких видов: переименование (ProGuard/R8), шифрование строк, control-flow flattening, вставка мёртвого кода, нативные проверки. Отдельно стоят анти-анализ (детект Frida/отладчика) и анти-тампер (проверка целостности). Цель модуля — понять виды обфускации и методы их снятия.

## Виды обфускации

- **Переименование** — ProGuard/R8: имена классов/методов становятся короткими.
- **Шифрование строк** — строковые константы зашифрованы, расшифровываются в рантайме.
- **Control-flow flattening** — логика превращена в switch по состоянию.
- **Мёртвый код / вставки** — затрудняют чтение.
- **Рефлексия** — вызовы через строки, статически не видны.
- **Нативный код** — логика в `.so`, вне DEX.
- **Динамическая загрузка** — код подгружается из сети/файла.

## Деобфускация переименования

```bash
jadx -d out --deobf app.apk
```

`--deobf` восстанавливает часть имён по эвристикам. Полностью — нельзя, но строки и структура остаются. Ищите вызовы стандартных API: они не переименовываются.

## Шифрование строк

Признак — массив байт, операция XOR/Base64/AES, вызов из множества мест. Найдите функцию расшифровки и воспроизведите:

```python
# пример: строки расшифровываются XOR с ключом
def dec(s, key):
    return ''.join(chr(c ^ key[i % len(key)]) for i, c in enumerate(s))
```

Извлеките зашифрованные данные из smali/ресурсов и примените ту же логику. Часто ключ лежит рядом.

## Control-flow flattening

Логика превращена в диспетчер (switch по индексу состояния). Восстановить граф можно вручную (в Ghidra) или полуавтоматически. Иногда проще анализировать рантайм: смотреть реальные значения через Frida.

## Динамическая загрузка

Если код подгружается в рантайме, статика бесполезна — дампите его из памяти (`frida-dexdump`) или перехватывайте загрузку (`DexClassLoader`).

## Анти-анализ и анти-тампер

Детекторы Frida, отладчика, root, целостности. Обход — хуки через Frida (см. отдельные модули). Комбинируйте: сначала обойдите детекторы, потом анализируйте.

## Инструменты

| Защита | Инструмент/подход |
|--------|-------------------|
| Переименование | `jadx --deobf` |
| Шифр строк | воспроизвести функцию |
| Flattening | Ghidra + рантайм |
| Динамика | `frida-dexdump` |
| Анти-анализ | Frida-хуки |
| Пакер | дамп DEX |

## Типичные ошибки и подводные камни

- **Пытаться восстановить все имена** — невозможно; идите от строк.
- **Игнорировать нативный код** — логика может быть в `.so`.
- **Не дампить динамику** — при пакере статика бесполезна.
- **Не обойти детекторы** — Frida не запустится.
- **Сдаваться на flattening** — анализируйте рантайм.
- **Забыть про рефлексию** — вызовы скрыты в строках.
- **Не проверить несколько DEX** — мультидекс.

|---------|---------|----------|

## Что дальше / решение

План: определите вид обфускации (переименование → `--deobf`, шифр строк → воспроизвести функцию, flattening → Ghidra/рантайм, динамика → дамп). Комбинируйте со обходом детекторов. Помните: обфускация усложняет, но не делает анализ невозможным — строки, стандартные API и рантайм всегда дают зацепки.

## Практический пример: деобфускация зашифрованных строк

Разберём сквозной сценарий. `jadx --deobf` показывает класс `a` с методом `b(String)` и массив байт. Приложение использует строки, которых нет в открытом виде. Шаг 1: находим метод, который вызывается из множества мест с аргументом-числом — это типичная функция расшифровки строк. Шаг 2: смотрим её логику: обычно XOR с ключом или Base64 + XOR. Шаг 3: воспроизводим функцию на Python, подавая индексы/байты из smali. Шаг 4: получаем читаемые строки, среди которых — URL'ы, ключи, флаги.

```python
def dec(i):
    # воспроизведённая логика из smali
    return bytes(b ^ 0x5a for b in enc[i]).decode()
print([dec(i) for i in range(20)])
```

Этот приём — стандартный: найти функцию расшифровки и вызвать её для всех строк. Часто он раскрывает всю картину приложения.

## Практический пример: обход flattening через рантайм

Если логика «расплющена» в switch, статический анализ медленный. Быстрее — наблюдать рантайм: хукать метод и печатать аргументы и результат, подавая разные входы. Через Frida вы увидите реальное поведение, не восстанавливая граф вручную.

## Частые вопросы

«Не нахожу функцию расшифровки?» — ищите метод, вызываемый много раз с числовым аргументом. «Строки XOR с ключом?» — извлеките ключ из константы рядом. «Flattening?» — анализируйте рантайм. «Пакер?» — дамп DEX. «Рефлексия?» — ищите `Class.forName` и `Method.invoke`.

## Что дальше / решение

Итог: обфускация снимается комбинацией методов — `--deobf` для переименования, воспроизведение функции для шифра строк, Ghidra и рантайм для flattening, дамп DEX для пакеров. Строки, стандартные API и рантайм всегда дают зацепки. Комбинируйте статику и динамику, не сдавайтесь на «нечитаемом» коде.

## Расширенный чек-лист по обфускации

Порядок. Первое: `jadx --deobf` — посмотрите, насколько код читаем. Второе: найдите строки — они не переименовываются; `grep` по URL, ключам, подсказкам. Третье: ищите вызовы стандартных API (`Cipher`, `Http`, `Reflection`, `Runtime`) — они дают каркас логики. Четвёртое: если строки зашифрованы — найдите функцию расшифровки (метод, вызываемый много раз с числовым аргументом) и воспроизведите. Пятое: если control-flow flattening — анализируйте рантайм через Frida, а не восстанавливайте граф вручную. Шестое: если логика в `.so` — Ghidra. Седьмое: если пакер — дамп DEX. Восьмое: если детекторы — обойдите их.

## Комбинирование статики и динамики

Самая эффективная стратегия — чередовать: статически находите точку интереса (метод, строку, вызов), затем динамически наблюдаете её в рантайме (аргументы, результат), затем возвращаетесь к статике с новым пониманием. Так вы обходите и обфускацию, и рантайм-проверки.

## Частые вопросы

«Строки зашифрованы, ключ неизвестен?» — ищите константу рядом с функцией. «Flattening — тупик?» — рантайм. «Рефлексия скрывает вызовы?» — хукайте `Method.invoke`. «Пакер + обфускация?» — сначала дамп, потом `--deobf`. «Нативный код?» — Ghidra.

## Что дальше / решение

Итог: обфускация — это усложнение, а не защита. Используйте `--deobf`, поиск строк, воспроизведение функций расшифровки, рантайм для flattening, дамп для пакеров, Ghidra для нативного кода. Комбинируйте статику и динамику. Помните: любая клиентская защита обходится, потому что исполняется на контролируемом устройстве.
