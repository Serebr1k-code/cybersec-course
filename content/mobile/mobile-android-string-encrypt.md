## Вопрос, с которого всё начинается

Вы ищете в декомпилированном коде URL сервера — и не находите: `grep` по строкам пусто. Причина
в том, что строки зашифрованы и расшифровываются в рантайме. `strings` по APK тоже ничего не
даёт. Как добраться до спрятанных строк?

## Наш пример: app.apk без читаемых строк

```bash
$ strings app.apk | grep -i http
$ grep -rn 'http' out/sources | head
```

Оба пусто. Значит, строки где-то зашифрованы. Ищем след расшифровки.

## Шаг 1: зачем шифруют строки

Строковые константы — самый быстрый путь для аналитика: URL, ключи, тексты ошибок. Чтобы
затруднить анализ, приложение хранит их зашифрованными, а в коде оставляет вызов `decrypt()`.
Это **не** криптографическая защита (ключ всё равно в приложении), а обфускация: повышает
стоимость анализа.

## Шаг 2: поиск функции расшифровки

```bash
$ grep -rn -iE 'decrypt|deobf|xor|decode' out/sources --include='*.java' | head
Cipher.java:23:  public static String d(String s) { return xor(s, KEY); }
```

Функция `d` (короткое имя — типичный приём обфускации) расшифровывает строки XOR-ом с ключом.
Нашли точку входа.

## Шаг 3: разбор алгоритма статически

Открываем `Cipher.java`:

```java
static String d(String s) {
  byte[] b = Base64.decode(s, 0);
  for (int i = 0; i < b.length; i++) b[i] ^= (byte) KEY[i % KEY.length];
  return new String(b);
}
```

Алгоритм прост: Base64-декодировать, затем XOR с ключом. Теперь мы можем расшифровать все
строки сами — или перехватить результат в рантайме.

## Шаг 4: динамика через Frida

Надёжнее не реализовывать алгоритм повторно, а перехватить вызов расшифровки:

```javascript
Java.perform(function () {
  var C = Java.use('com.example.Cipher');
  C.d.overload('java.lang.String').implementation = function (s) {
    var out = this.d(s);
    console.log('dec: ' + out);
    return out;
  };
});
```

Каждый раз, когда приложение расшифровывает строку, мы видим результат. Запускаем приложение,
проходим по экранам — и собираем все строки.

## Шаг 5: массовая выгрузка

Чтобы не ходить по экранам вручную, можно дампить пул строк. Приём — вызвать расшифровку для
всех зашифрованных констант. Если известен список зашифрованных строк (из smali/Java), прогоняем
их через функцию:

```javascript
var enc = ['SGVsbG8=', 'V29ybGQ='];   // зашифрованные
enc.forEach(function (s) { console.log(C.d(s)); });
```

Так за один прогон получаем весь словарь строк.

## Шаг 6: автоматизация

В инструментах вроде `frida-dexdump`/скриптов на Frida есть готовые рецепты дампа строк. Для
нативных строк-шифровальщиков используют Unicorn (эмуляция функции расшифровки) или angr.

## Шаг 7: защита

Продвинутые обфускаторы (DexGuard, Stringer) не оставляют одну простую функцию: строки
расшифровываются инлайн, ключи зависят от контекста, используется несколько алгоритмов. Тогда
применяют трассировку (Stalker) и автоматический деобфускатор.

## Что мы теперь знаем

- Строки прячут за шифрованием, чтобы усложнить анализ.
- Функцию расшифровки находят grep-ом по именам.
- Frida перехватывает вызов и показывает результат.
- Массовая выгрузка собирает весь словарь строк.
- Продвинутые обфускаторы требуют трассировки.
