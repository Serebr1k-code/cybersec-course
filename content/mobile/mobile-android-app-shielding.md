## Вопрос, с которого всё начинается

JADX открыл APK — а внутри почти нет классов: только маленький загрузчик. Настоящий код где-то
прячется и появляется только во время работы. Это упаковщик (shielding). Как достать настоящий
код?

## Наш пример: app.apk с упаковщиком

```bash
$ unzip -l app.apk | grep -E 'classes.*dex'
  64   classes.dex
$ jadx -d out app.apk
$ find out/sources -name '*.java' | wc -l
7
```

Всего 7 классов и крошечный `classes.dex` — явный признак упаковщика. Настоящий код загружается
из зашифрованного блоба.

## Шаг 1: что такое шилдинг

Упаковщик (protector) шифрует оригинальный DEX и прячет его внутри APK (в assets или нативной
библиотеке). При запуске загрузчик расшифровывает DEX и подгружает его в память, после чего
работает обычный код. Статически виден только загрузчик.

## Шаг 2: жизненный цикл упаковщика

1. Приложение стартует с классом-загрузчиком.
2. Загрузчик читает зашифрованный DEX.
3. Расшифровывает его в память.
4. Создаёт `DexClassLoader` и загружает настоящие классы.
5. Передаёт управление реальному коду.

Ключевой момент — шаг 3–4: расшифрованный DEX существует в памяти, и его можно выгрузить.

## Шаг 3: поиск загрузчика

В манифесте `application android:name` указывает на класс-загрузчик. В JADX он выглядит как
`attachBaseContext`/`onCreate`, который читает ассеты и что-то расшифровывает. Это наша точка
входа.

## Шаг 4: дамп из памяти

Самый надёжный путь — дамп уже расшифрованного DEX:

```bash
$ frida-dexdump -U -f com.example
[+] Searching dex in memory
[+] Dumped 3 dex files
```

Инструмент сканирует память процесса в поисках сигнатуры DEX (`dex\n035`) и сохраняет найденные
файлы. Это обходит шифрование: мы берём код уже после расшифровки.

## Шаг 5: пересборка

Полученные DEX можно прочитать JADX напрямую. Если классы разбросаны по нескольким DEX —
объединяют или анализируют по отдельности. Иногда требуется починить заголовки — для этого есть
скрипты.

## Шаг 6: anti-dump

Продвинутые упаковщики противодействуют дампу: стирают заголовки DEX в памяти, запускают
проверки, искажают память. Тогда дамп делают «на лету» — перехватывают момент сразу после
расшифровки, до искажения. Для этого хукают нативный дешифратор.

## Шаг 7: практика

Типовой пайплайн: определить упаковщик по структуре APK → найти загрузчик → запустить приложение
под Frida → дампнуть DEX → проанализировать в JADX. Это стандартный способ вскрытия защищённых
приложений.

## Что мы теперь знаем

- Шилдинг шифрует DEX и грузит его в рантайме.
- Статически виден только загрузчик.
- Расшифрованный DEX можно дампнуть из памяти.
- frida-dexdump находит DEX по сигнатуре.
- Продвинутые упаковщики мешают дампу.
