## Вопрос, с которого всё начинается

SPARC — архитектура с самой необычной моделью регистров из всех, что ты видел.
Здесь нет фиксированного набора из 16 регистров: процессор переключает целые
**окна**. Понимание этой модели — обязательное условие для эксплуатации
SPARC-бинарей (например, на старых Solaris-серверах). Разберём её на реальном
листинге.

## Наш пример

```
$ file sparc.elf
sparc.elf: ELF 64-bit MSB relocatable, SPARC V9
$ readelf --file-header sparc.elf
  Class:                             ELF64
  Data:                              2's complement, big endian
  Machine:                           Sparc v9
```

SPARC V9 — 64-битная big-endian архитектура. Дальше смотрим листинг функции.

## Шаг 1: окна регистров

В SPARC регистровый файл — это «карусель» окон. В каждый момент активны 32
регистра, разделённые на четыре группы по 8:

- **global** — `%g0`..`%g7`, видны всегда;
- **out** — `%o0`..`%o7`, в них передаются аргументы вызываемому;
- **local** — `%l0`..`%l7`, локальные для текущей функции;
- **in** — `%i0`..`%i7`, сюда приходят аргументы из `out` вызывающего.

Регистр `%g0` всегда равен нулю. `%o6` — это указатель стека (`%sp`), `%i6` —
указатель кадра (`%fp`).

Когда функция вызывается, инструкция `save` **сдвигает окно**: старое окно
становится `in` для новой функции, а новое — `out`/`local`. Так аргументы
«переезжают» в `in` без копирования.

## Шаг 2: пролог и эпилог

Смотрим реальный листинг (`sparc.s`):

```
f:
	save %sp, -144, %sp
	st %i0, [%fp+2043]
	ld [%fp+2043], %i0
	add %i0, 1, %i0
	ret
	restore
```

Пролог — **`save %sp, -144, %sp`**: он открывает новое окно и сразу сдвигает
указатель стека на 144 байта. Эпилог — `ret` (вернуться) и `restore` (закрыть
окно, вернув окно вызывающего).

Именно `save`/`restore` — сердце модели. Забыть их — классическая ошибка при
написании SPARC-шеллкода: без `restore` ты «утечёшь» окном и обрушишь стек.

## Шаг 3: delay slot

У SPARC есть **delay slot**: инструкция, стоящая сразу **после** ветвления,
выполняется **до** того, как переход реально произойдёт. В листинге видно:

```
	ret
	restore     <-- это delay slot, выполнится до фактического возврата
```

Это значит, что при построении ROP и шеллкода нельзя игнорировать инструкцию
после `call`/`jmp`/`ret` — она исполнится. В шеллкоде часто в delay slot
ставят `nop`, чтобы ничего лишнего не произошло.

## Шаг 4: где адрес возврата

SPARC не кладёт адрес возврата на стек при вызове. Инструкция `call` сохраняет
адрес возврата в `%o7`. Затем `save` «переезжает» и `%o7` оказывается `%i7`.
Возврат `ret` — это, по сути, `jmp %i7+8` (плюс 8 — чтобы пропустить delay slot
вызова).

Значит, **адрес возврата живёт в окне регистров**, а на стеке лежит сохранённая
копия при переполнении кадра. Переполнив локальный буфер, ты добираешься до
сохранённых `%i7`/`%i6` и перезаписываешь адрес возврата — как везде, но с
поправкой на окна.

## Шаг 5: поиск гаджетов и смещения

Гаджеты ищем по `ret`/`jmp`/`call`-окончаниям, помня о delay slot. Смещение до
сохранённого `%i7` считаем от `%fp` (он же `%i6`). Практически удобно
пользоваться `ROPgadget --rawArch=sparc` или кросс-`objdump` из
`sparc64-linux-gnu-*`.

## Шаг 6: собираем эксплойт

```python
from pwn import *
context.arch = 'sparc64'
context.endian = 'big'
p = process('./challenge')
offset = 128          # до сохранённого %i7 (зависит от кадра)
payload  = b'A' * offset
payload += p64(ret2win_addr)   # перезаписанный адрес возврата
payload += p64(0)              # delay slot / выравнивание
p.sendline(payload)
p.interactive()
```

Порядок байт — big-endian, адреса 8-байтовые. Не забудь про delay slot: если
гаджет возврата не заполнит его сам, добавь `nop`.

## Шаг 7: почему SPARC до сих пор встречается

Хотя SPARC вытеснена с десктопов, она живёт в legacy-инфраструктуре: банковские
системы, старые СУБД Oracle, промышленные контроллеры. На пентестах такие хосты
попадаются, и понимание register windows отличает специалиста от того, кто умеет
только x86.

## Что мы теперь знаем

- SPARC использует окна регистров; `save`/`restore` переключают их.
- Аргументы передаются в `%o0`.., приходят в `%i0`..
- У ветвлений есть delay slot — инструкция после перехода исполняется.
- Адрес возврата — в `%i7`, копия сохраняется на стеке при переполнении.

## Куда дальше

Дальше — **s390x**, где снова другая модель: возврат через регистр связи, но без
окон. А пока запомни: **на SPARC окна переключаются `save`/`restore`, а delay
slot нельзя игнорировать**.
