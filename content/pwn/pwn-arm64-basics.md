ARM64/AArch64 pwn — эксплуатация 64-битных ARM-бинарей, которые доминируют на мобильных устройствах, в облаке (AWS Graviton, Apple Silicon) и в embedded. ARM64 имеет собственный ABI (AAPCS64), регистры и особенности: адрес возврата в `x30` (LR), отсутствие флага NX-аналога для отдельных страниц, иные гаджеты. Понимание ARM64 необходимо для эксплуатации современных устройств и облачных задач. В этом уроке — регистры, ABI, вызовы, ROP, ret2win и практические примеры под qemu-user.

## Регистры ARM64

ARM64 имеет 31 целочисленный регистр (`x0`–`x30`), `sp` и `xzr`/`wzr` (ноль). Регистры `w0`–`w30` — младшие 32 бита. По соглашению:

| Регистр | Роль |
|---|---|
| `x0`–`x7` | аргументы/возврат |
| `x8` | косвенный результат syscall |
| `x9`–`x15` | временные |
| `x16`–`x17` | IP0/IP1 (PLT) |
| `x18` | platform register |
| `x19`–`x28` | callee-saved |
| `x29` | frame pointer |
| `x30` | link register (LR) |
| `sp` | stack pointer |

Аргументы — `x0`–`x7`, возврат — `x0`. Адрес возврата — `x30`.

## Соглашение о вызовах и стек

Функции сохраняют `x30` на стеке в прологе (`stp x29, x30, [sp, #-16]!`) и восстанавливают в эпилоге (`ldp x29, x30, [sp], #16; ret`). `ret` — псевдоним `br x30`. Стек должен быть выровнен на 16 байт. Ключевая особенность: адрес возврата не «лежит» на стеке постоянно — он сохраняется и восстанавливается, поэтому переполнение перезаписывает сохранённый `x30`.

## Поиск offset и гаджетов

```bash
aarch64-linux-gnu-objdump -d ./chall
ROPgadget --binary ./chall --only "ldp|ret" | grep "ldp x29, x30"
ROPgadget --binary ./chall | grep "ldr x0"
```

Гаджеты: `ldp x29, x30, [sp], #16; ret`, `ldr x0, [sp, #N]; ret`, `mov x0, x19; ...`. Для ROP в ARM64 часто используют `ldp`-гаджеты для загрузки регистров из стека.

## Разобранный пример: ret2win

```python
from pwn import *
context.binary = elf = ELF('./chall')
context.arch = 'aarch64'
p = process('./chall')
offset = cyclic_find(0x61616161)   # из gdb
win = elf.symbols['win']
p.sendline(flat(b'A'*offset, win))
p.interactive()
```

Переполнение перезаписывает сохранённый `x30`, и `ret` прыгает на `win`.

## ROP на ARM64

Цепочка: установить `x0` (аргумент) и вызвать функцию. Гаджет `ldr x0, [sp, #N]; ret` загружает `x0` из стека; затем `ldp x29, x30, [sp], #16; ret` восстанавливает `x30`. Пример:

```python
rop  = flat(
    ldr_x0_ret,
    binsh_addr,
    ldp_ret,
    0, 0,           # x29, x30 (перезапишутся)
    system_addr
)
```

Порядок и смещения зависят от гаджетов; проверяйте в gdb. Для многоаргументных функций используйте `ldp x0, x1, [sp], #16; ret`.

## Отладка под qemu-user

```bash
qemu-aarch64 -g 1234 ./chall
gdb-multiarch ./chall -ex 'set architecture aarch64' -ex 'target remote :1234'
```

Смотрите `x30`, `sp`, `x0`. Команда `x/10gx $sp` покажет стек. Для системных вызовов используйте `x8` (номер) и `x0`–`x5` (аргументы).

## Особенности ARM64-эксплуатации

- **PAC** на arm64e (Apple) подписывает `x30` — обход сложен.
- **BTI** (Branch Target Identification) — аналог CFI, требует `bti`-инструкций.
- **MTE** (Memory Tagging) — аппаратная защита памяти.
- **Выравнивание** стека 16 байт.
- **Syscall ABI:** `x8` = номер, `x0`–`x5` = аргументы, `svc #0`.

## Частые ошибки

- **Не та архитектура в gdb.** `set architecture aarch64`.
- **Неверный offset.** Сохранённый `x30` — цель переполнения.
- **Выравнивание.** 16 байт.
- **PAC/BTI.** На новых устройствах требуют обхода.
- **Гаджеты.** Ищите `ldp`/`ldr`-гаджеты.

## Полный разбор ARM64 ROP

Разберём сквозной пример. Дано: AArch64-бинарь с переполнением стека, есть `system` и строка `"/bin/sh"`. Цель — вызвать `system("/bin/sh")`. Шаги: (1) найти offset до сохранённого `x30` (cyclic + gdb: `info registers x30`, `x/20gx $sp`); (2) найти гаджет `ldr x0, [sp, #N]; ret` и `ldp x29, x30, [sp], #16; ret`; (3) выяснить смещения загрузки; (4) собрать payload: на нужном смещении `binsh_addr` для `x0`, затем `ldp`-гаджет с `system_addr` в `x30`; (5) отправить. Учитывайте выравнивание стека (16 байт) — при необходимости добавьте `ret`-гаджет. Проверяйте в gdb: `b *system`, `info registers x0 x30`. ARM64 ROP отличается от x86-64 отсутствием `pop`-гаджетов и использованием `ldp`/`ldr`.

## Syscalls и shellcode на ARM64

Для shellcode на ARM64 нужны syscalls: `execve` (номер 221), `read` (63), `write` (64), `openat` (56). Регистры: `x8` — номер, `x0`–`x5` — аргументы, инструкция `svc #0`. Пример shellcode `execve("/bin/sh", 0, 0)`:

```asm
mov x0, #0          ; адрес строки (загрузить через adr)
adr x0, binsh
mov x1, xzr
mov x2, xzr
mov x8, #221
svc #0
binsh: .ascii "/bin/sh\0"
```

Shellcode должен быть позиционно-независимым; используйте `adr`/`adrp`. Для ROP-цепочки вместо shellcode можно вызвать `system`/`execve` через гаджеты.

## Митигации ARM64: PAC, BTI, MTE

На современных ARM64 (особенно Apple arm64e) включены дополнительные защиты. **PAC** подписывает `x30` и другие указатели — переполнение адреса возврата не даёт контроля без обхода. **BTI** (Branch Target Identification) требует, чтобы косвенные переходы попадали на `bti`-инструкции — аналог CFI. **MTE** (Memory Tagging Extension) помечает указатели и память тегами, обнаруживая UAF/OOB. Обход этих защит — отдельная исследовательская задача. В CTF обычно PAC/BTI выключены, но в реальных устройствах — включены.

## Расширенные приёмы ARM64

Помимо базового ROP, в ARM64 важно понимать **branch/return** механику: `bl` сохраняет адрес возврата в `x30`, `ret` прыгает по `x30`. Гаджеты-загрузчики (`ldp x0, x1, [sp], #16; ret`) позволяют устанавливать несколько аргументов сразу. Для вызова функций с 4+ аргументами ищите `ldp` на нужные регистры. **SROP** (sigreturn-oriented programming) на ARM64 использует syscall `rt_sigreturn` (номер 139) для восстановления всего контекста из поддельного `sigframe` — мощный приём для получения контроля над всеми регистрами. Изучите структуру `sigcontext` для AArch64. Также **ret2csu**-аналог на ARM64 использует эпилоги функций для загрузки регистров. Все эти приёмы расширяют арсенал при нехватке гаджетов.

## Список syscall-номеров и пример ORW

Для ORW на ARM64: номер в `x8`, аргументы в `x0`–`x5`, `svc #0`. Номера: `openat` = 56, `read` = 63, `write` = 64, `execve` = 221, `rt_sigreturn` = 139. Цепочка: `ldp x0, x1, [sp], #16; ret` для загрузки аргументов, затем `mov x8, #N; svc #0`. Для seccomp-задач, запрещающих `execve`, используйте ORW: открыть флаг, прочитать, записать в stdout. SROP через `rt_sigreturn` позволяет установить все регистры разом из поддельного `sigframe` — мощный приём. Изучите структуру `sigcontext` для AArch64 и соберите SROP-цепочку.


## Практика: ROP-цепочка под qemu-aarch64

Соберите полную цепочку: (1) offset до `x30`; (2) гаджеты `ldr x0, [sp, #N]; ret` и `ldp x29, x30, [sp], #16; ret`; (3) payload: на смещении `N` — `binsh_addr`, затем `ldp`-гаджет с `system_addr`; (4) проверка в gdb (`b *system`, `info registers x0 x30`). Для многоаргументных функций используйте `ldp x0, x1, [sp], #16; ret`. Для syscall — `x8` (номер), `x0`–`x5` (аргументы), `svc #0`. Практикуйтесь под qemu-aarch64, постепенно переходя к SROP и heap. ARM64 — ключевая архитектура; освоив её, вы откроете мобильные и облачные цели.


## Практика: SROP и syscalls

Для SROP на AArch64: найдите `svc #0` и способ установить `x8=139` (`rt_sigreturn`). Поддельный `sigframe` задаёт все регистры (включая `pc`/`sp`). Для ORW: `x8`=56/63/64, `x0`–`x2` — аргументы. Соберите цепочку и проверьте под qemu-aarch64. Для многоаргументных вызовов — `ldp`-гаджеты. Практикуйтесь, постепенно усложняя. ARM64 — доминирующая архитектура мобильных и облачных систем; уверенное владение ею открывает множество целей.
