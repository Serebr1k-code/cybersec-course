## Вопрос, с которого всё начинается

RISC-V — открытая ISA, которая быстро завоёвывает embedded, серверы и даже
ноутбуки. Базу ты уже видел, но для эксплуатации нужны детали: как именно
функция возвращается, как сохраняется адрес возврата и что даёт C-расширение
сжатых инструкций. Разберём на реальном листинге 64-битной сборки.

## Наш пример

```
$ file riscv64.elf
riscv64.elf: ELF 64-bit LSB relocatable, UCB RISC-V
$ readelf --file-header riscv64.elf
  Class:                             ELF64
  Data:                              2's complement, little endian
  Machine:                           RISC-V
```

64 бита, little-endian. Смотрим листинг (`riscv64.s`):

```
f:
	addi	sp, sp, -32
	sd	ra, 24(sp)
	sd	s0, 16(sp)
	addi	s0, sp, 32
	...
	ld	ra, 24(sp)
	ld	s0, 16(sp)
	addi	sp, sp, 32
	ret
```

## Шаг 1: регистр ra

`ret` — это псевдоним инструкции **`jalr x0, ra, 0`** (jump and link register):
прыгнуть по адресу в `ra` и результат записи «никуда» (`x0`). То есть адрес
возврата лежит в **`ra`** (`x1`). Инструкция `jal`/`jalr` при вызове кладёт в
`ra` адрес возврата.

В листинге видно `sd ra, 24(sp)` — сохранение `ra` на стек в прологе, и
`ld ra, 24(sp)` — восстановление в эпилоге. **Вот и точка перезаписи:** переполнив
буфер, добираемся до слота `ra` на стеке.

## Шаг 2: ABI регистров

RISC-V использует ABI-имена: `ra` (x1) — адрес возврата, `sp` (x2) — стек,
`s0`/`fp` (x8) — указатель кадра, `a0`..`a7` (x10..x17) — аргументы,
`s0`..`s11` — сохраняемые регистры. Возврат значения — в `a0`.

Отсюда шаблон гаджета для вызова `system("/bin/sh")`: нужно загрузить указатель
на строку в `a0` (`ld a0, ...; ret` или `mv a0, ...; ret`) и перейти на `system`.

## Шаг 3: сжатые инструкции (C-расширение)

Большинство RISC-V сборок включают расширение **C** — сжатые 16-битные версии
частых инструкций. Например, `ret` — это `c.jr ra`, а `addi sp, sp, -32` может
стать 16-битной формой. Для эксплуатации это важно:

- гаджеты могут быть **невыровнены на 4 байта** (2-байтовые инструкции);
- `ROPgadget --rawArch=riscv64` или Ghidra должны учитывать C-расширение;
- иногда полезный гаджет «прячется» в середине обычной инструкции.

## Шаг 4: смещение и упаковка

```python
from pwn import *
context.arch = 'riscv64'
p = process('./challenge')
offset = 40
payload  = b'A' * offset
payload += p64(ret2win_addr)   # перезаписанный ra
p.sendline(payload)
p.interactive()
```

Little-endian, адреса 8-байтовые. Проверь выравнивание: если цель ждёт `a0`,
добавь гаджет загрузки.

## Шаг 5: GOT и утечки

Как на других RISC-V/Linux, доступ к GOT идёт через `auipc`+`ld` (PC-relative).
Утечка адреса из GOT (`puts@got`) даёт базу libc, дальше — стандартный ret2libc.
Схема та же, что на x86-64, меняются лишь инструкции загрузки.

## Шаг 6: собираем эксплойт

1. Определяем offset до сохранённого `ra`.
2. Находим адрес `system`/строки `/bin/sh` или цель ret2win.
3. При необходимости — гаджет `ld a0, ...; ret` для аргумента.
4. Собираем payload, запускаем, проверяем shell.

## Шаг 7: где встречается

RISC-V — в новых embedded-платформах (ESP32-C3, GD32V, SiFive), в Linux-серверах
и в учебных CTF. Открытость ISA означает, что гаджеты и митигации очень
предсказуемы, а сообщество растёт.

## Что мы теперь знаем

- Возврат RISC-V — `ret` = `jalr x0, ra, 0`; адрес возврата в `ra`.
- Не-leaf функции сохраняют `ra` на стек (`sd ra, N(sp)`).
- C-расширение даёт 16-битные инструкции — гаджеты могут быть невыровнены.
- Little-endian, адреса 8 байт.
