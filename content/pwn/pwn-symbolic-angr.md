## Вопрос, с которого всё начинается

Фаззинг перебирает входы **случайно**. Но если задача — «подбери пароль, при котором программа дойдёт до функции `win`», случайный перебор может идти вечно. Есть ли способ **решить** это аналитически? Да — **символьное исполнение**: мы говорим движку «вход неизвестен» и просим найти такой вход, при котором выполнение дойдёт до нужной точки. Инструмент — **angr**.

## Наш пример

Возьмём простой crackme: программа читает пароль и сравнивает его посимвольно с секретом. Функция `win` печатает флаг, если пароль верный. Наша цель — заставить исполнение дойти до `win`, не подбирая пароль вручную.

## Шаг 1: идея символьного исполнения

Обычное исполнение: вход **конкретный** (`argv[1] = "abc"`), программа идёт по одному пути. Символьное: вход — **символьная переменная** `x` (неизвестное). Движок исполняет программу, накапливая **ограничения** на `x`:

- прошли проверку `x[0] == 's'` → ограничение `x[0] = 's'`;
- прошли `x[1] == '3'` → добавляем `x[1] = '3'`;
- и так далее, пока не дошли до `win`.

В конце движок отдаёт ограничения **решателю (solver)**, который находит конкретное значение `x`, удовлетворяющее всем им. Это и есть «решение» пароля — без перебора.

## Шаг 2: запускаем angr

Загружаем бинарник и указываем, куда хотим дойти и чего избегать:

```python
import angr, claripy
proj = angr.Project('./crackme', auto_load_libs=False)

# 32 байта символьного ввода со стандартного входа
flag = claripy.BVS('flag', 8 * 32)

state = proj.factory.entry_state(stdin=flag)
for b in flag.chop(8):
    state.solver.add(b >= 0x20, b <= 0x7e)   # печатаемые символы

simgr = proj.factory.simulation_manager(state)
simgr.explore(find=0x401200, avoid=0x401230)  # find=win, avoid=проигрыш
```

- **`claripy.BVS`** — символьная переменная (bitvector symbol).
- **`entry_state(stdin=flag)`** — входной поток программы становится символьным.
- **`solver.add(...)`** — ограничения на символы (например, только печатаемые).
- **`explore(find=..., avoid=...)`** — «дойди до адреса `find`, не заходя в `avoid`».

## Шаг 3: читаем решение

После запуска смотрим, нашёлся ли путь:

```python
if simgr.found:
    s = simgr.found[0]
    print(s.posix.dumps(0))   # 0 = stdin
```

Типичный вывод:

```
$ python3 solve.py
b's3cr3t_p4ssw0rd\x00...'
```

Движок сам собрал пароль. Именно так решается большая часть «crackme»-задач: указал `find`/`avoid` — получил вход.

## Шаг 4: хуки — заменяем функции

Символьное исполнение плохо работает с реальными библиотеками: `strlen`, `memcmp`, `printf` реализованы в машинном коде и порождают лавину путей. Решение — **хуки**: заменить функцию простой моделью.

```python
@proj.hook(0x401080, length=5)      # адрес call strlen
def strlen_hook(state):
    s = state.memory.load(state.regs.rdi, 64)
    state.regs.rax = state.solver.eval(...)   # модель длины
```

Хуки нужны, чтобы:

- **ускорить** поиск (убрать «тяжёлые» функции);
- **смоделировать** функцию точно (например, `memcmp` как ограничение равенства);
- **обойти** антисимвольные проверки.

Часто `auto_load_libs=False` (не грузить системные библиотеки) плюс хуки на внешние вызовы — рабочий набор по умолчанию.

## Шаг 5: подводные камни

- **Path explosion.** Если ветвлений много (особенно в циклах), число путей растёт экспоненциально. Спасение — хуки, ограничения, `avoid`, декомпозиция.
- **Неподдерживаемые инструкции.** Angr не всегда эмулирует всё (некоторые syscall, самописные VM, обфускацию).
- **Внешние данные.** Если путь зависит от «настоящего» файла/сети, angr не знает значения — надо моделировать.
- **Антисимволические трюки.** Авторы задач специально добавляют код, который angr не может решить. Тогда — фаззинг или ручной анализ.
- **Время.** Иногда angr «думает» часами. Начни с маленького `find`-адреса и `avoid` рядом, постепенно расширяя.

Практическое правило: **angr — не серебряная пуля**. Он отлично берёт «линейные» проверки ввода, но против сложной логики часто проигрывает ручному разбору. Выбирай инструмент под задачу.

## Шаг 6: где это встречается

- **CTF:** crackme, задачи «найди вход», обход простых проверок.
- **Bug hunting:** поиск входа, приводящего к конкретной опасной функции.
- **Реверс:** автоматический анализ проверок лицензий/паролей.
- **Malware analysis:** обход анти-анализа и поиск путей к полезной нагрузке.

## Шаг 7: angr для ROP и «нестандартных» целей

Символьное исполнение годится не только для «введи пароль». Ещё один частый сценарий — **автоматическое построение пути до `win` при переполнении**: angr сам выяснит, какая последовательность байт приведёт к нужному адресу.

Идея: вместо символьного stdin ты можешь сделать символьным **буфер, в который попадает переполнение**, и попросить angr дойти до `win`. Движок учтёт, что часть байт затирает адрес возврата, и найдёт вход, при котором управление уходит на `win`. Это удобно, когда смещение или логика проверок неочевидны.

Ещё angr полезен для **разбора виртуальных машин и обфускации**: если задача «прогоняет» твой ввод через самописную VM, angr может исполнить её символически и найти вход, при котором VM выдаёт «правильно». Руками это часто нереально.

Но помни ограничения: чем больше кода и ветвлений, тем хуже работает angr. На больших бинарниках (браузеры, ядра) символьное исполнение «в лоб» не масштабируется — там нужны специализированные инструменты и декомпозиция. Поэтому angr — это **точечный инструмент** для небольших, хорошо очерченных задач.

Ещё одна типичная цель — **сравнение с хешем**: программа берёт твой ввод, считает хеш и сравнивает с константой. Angr «перевернёт» это только если хеш-функция целиком символьная и не слишком тяжёлая; часто проще вынести её в хук и задать ограничение «hash(x) == const» в самом solver. Понимание, что именно стоит заменить моделью, — половина успеха.

## Шаг 8: практические приёмы ускорения

- **Сужай пространство.** Ограничь символы печатаемым диапазоном, известной длиной, известным префиксом — меньше вариантов у solver.
- **Ставь `avoid` вокруг тупиков.** Чем раньше отсечёшь бесполезные ветки, тем меньше путей.
- **Хукай библиотеки.** `strlen`, `memcmp`, `printf`, `atoi` — моделируй, а не исполняй.
- **Разбивай задачу.** Реши подзадачу (например, найти длину), зафиксируй её как константу, реши следующую.
- **Ограничь время.** Запускай с таймаутом и смотри, продвинулся ли `find`; иногда помогает переставить порядок.

Если angr «завис» на сложной функции — не бейся в неё, а **замени моделью**. Часто быстрее написать десятистрочный хук, чем ждать, пока solver справится с настоящим кодом.

## Что мы теперь знаем

- **Символьное исполнение** трактует вход как неизвестное и накапливает ограничения по пути.
- **angr** запускает символьное исполнение: `Project`, `entry_state`, `simulation_manager.explore(find, avoid)`.
- Решение выдаёт **solver** (z3 внутри angr) — конкретный вход, удовлетворяющий ограничениям.
- **Хуки** заменяют тяжёлые функции моделями и ускоряют поиск.
- Главные проблемы — **path explosion**, неподдерживаемые инструкции и антисимволические приёмы.
