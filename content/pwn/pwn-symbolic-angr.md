Символьное исполнение в pwn (angr) — это автоматический анализ программ, при котором входные данные рассматриваются как символьные переменные, а движок исследует пути и решает ограничения (через SMT-солвер z3). Angr позволяет находить вход, приводящий к целевому состоянию (например, вызову `win`-функции), без ручного реверса. Это мощный инструмент для задач, где нужно «угадать» правильный ввод (crackme, проверки паролей, простые pwn). В этом уроке — устройство angr, сетап, типовые сценарии (find/avoid), работа с символическими переменными и практические примеры.

## Основы angr

Angr загружает бинарь в виде CFG, создаёт `SimState` (состояние: регистры, память) и исследует пути через `SimulationManager`. Вы задаёте: (1) `find` — адрес/условие цели; (2) `avoid` — адреса, которых избегать; (3) символьные переменные для ввода. Angr автоматически решает, какой ввод ведёт к цели. Это особенно полезно для проверок (`if (input == correct)`), где ручной реверс трудоёмок.

## Сетап и базовый скрипт

```python
import angr, claripy

proj = angr.Project('./chall', auto_load_libs=False)
# символьный ввод: 32 байта на stdin
arg = claripy.BVS('arg', 8 * 32)
state = proj.factory.entry_state(stdin=angr.SimFileStream)
for b in arg.chop(8):
    state.solver.add(b >= 0x20)
    state.solver.add(b <= 0x7e)
# можно также через state.posix.stdin
sm = proj.factory.simulation_manager(state)
sm.explore(find=0x400123, avoid=0x400456)   # find/avoid адреса
if sm.found:
    inp = sm.found[0].solver.eval(arg, cast_to=bytes)
    print(inp)
```

Angr исследует пути и находит ввод, ведущий к `find`, избегая `avoid`.

## Типовые сценарии

- **Crackme.** Find = адрес вывода «correct», avoid = «wrong». Angr найдёт пароль.
- **Проверка флага.** Find = функция, читающая флаг; avoid = выход.
- **Bypass проверок.** Find = путь к `system`/`win`, avoid = падения.
- **Многостадийные проверки.** Разбивайте на этапы (angr медленно растёт с путями).

## Символические переменные и ограничения

`claripy.BVS('name', bits)` создаёт символьную переменную. Добавляйте ограничения (`state.solver.add(...)`) для сужения пространства (например, печатные символы). Для строк/массивов используйте `claripy.BVV`/`BVS` и конкатенацию. Результат — `state.solver.eval(var, cast_to=bytes)`. Для нескольких решений — `eval` с `extra_constraints`. Правильные ограничения ускоряют анализ.

## Разобранный пример: crackme

```python
import angr

proj = angr.Project('./crackme', auto_load_libs=False)
sm = proj.factory.simulation_manager(proj.factory.entry_state())
sm.explore(find=lambda s: b'Correct' in s.posix.dumps(1),
           avoid=lambda s: b'Wrong' in s.posix.dumps(1))
if sm.found:
    print(sm.found[0].posix.dumps(0))   # stdin, ведущий к Correct
```

Angr найдёт ввод, при котором программа печатает «Correct».

## Оптимизация и подводные камни

Angr может быть медленным. Оптимизации: (1) `auto_load_libs=False` (не грузить libc); (2) использовать `find`/`avoid` по адресам, а не строкам; (3) ограничивать символьные переменные; (4) разбивать на этапы; (5) использовать `Veritesting` (`angr.options`); (6) для больших бинарей — символьное исполнение только нужной функции. Помните, что angr не справляется с криптостойкими проверками (хеши, шифры) — там нужен другой подход. Angr эффективен для логических проверок.

## Частые ошибки

- **Слишком много путей.** Ограничьте `find`/`avoid`.
- **Libc загружена.** `auto_load_libs=False`.
- **Нет ограничений.** Добавьте печатные символы.
- **Крипто.** Angr не решит хеши.
- **Медленно.** Оптимизируйте или используйте символьную функцию.

## Полный разбор angr-сценария

Разберём сквозной пример: crackme с проверкой пароля. Шаги: (1) `angr.Project('./crackme', auto_load_libs=False)`; (2) создайте состояние: `proj.factory.entry_state()`; (3) задайте символьный stdin: `state.posix.stdin` — angr создаёт символьный поток автоматически; (4) определите `find`/`avoid`: `find=lambda s: b'Correct' in s.posix.dumps(1)`, `avoid=lambda s: b'Wrong' in s.posix.dumps(1)`; (5) запустите `sm.explore(find=find, avoid=avoid)`; (6) получите ввод: `sm.found[0].posix.dumps(0)`. Angr исследует пути и найдёт пароль. Если проверок несколько, разбейте на этапы. Для ограничений (печатные символы) добавьте их на stdin. Проверяйте, что `find` действительно достигается.

## Оптимизация angr

Angr может быть медленным. Приёмы: (1) `auto_load_libs=False` — не грузить libc (ускоряет); (2) `find`/`avoid` по адресам, а не строкам (быстрее); (3) ограничивайте символьные переменные (печатные символы, длина); (4) используйте `Veritesting` (`state.options.add(angr.options.VERITESTING)`); (5) для больших бинарей — анализируйте только нужную функцию (`proj.factory.call_state(addr)`); (6) `simulation_manager.explore` с лимитом; (7) для крипто — angr не справится, используйте другой подход. Правильная настройка сокращает время с часов до минут.

## Ограничения и альтернативы

Angr эффективен для логических проверок, но не для криптостойких (хеши, шифры) — там пространство поиска огромно. Альтернативы: (1) **z3 напрямую** — если вы извлекли ограничения вручную; (2) **concolic execution** (Triton, Manticore); (3) **ручной реверс** — иногда быстрее. Angr также может не справиться с анти-отладочными/обфусцированными бинарями. Используйте angr как один из инструментов, комбинируя с ручным анализом. Для простых проверок angr незаменим; для сложных — дополняйте.

## Расширенный angr: сценарии и трюки

Дополним. Для ввода через аргументы/файлы: `state = proj.factory.entry_state(args=['./chall', claripy.BVS('arg', 64)])` или `state.posix.files[fd].read(...)`. Для сетевых программ — `state.posix.socket`. Для проверок с хешами angr бесполезен (пространство огромно); используйте ручной реверс или символьное исполнение конкретной функции с известным алгоритмом. Для обфусцированных бинарей — комбинируйте с деобфускацией. `proj.factory.call_state(func_addr, arg1, arg2)` позволяет анализировать конкретную функцию, что быстрее. `state.solver.eval(var, cast_to=bytes)` даёт значение; `eval_upto` — несколько решений. Логируйте найденные пути и ограничения. Angr — мощный, но требовательный инструмент; правильная постановка задачи — половина успеха.

## z3 и альтернативы

Если вы извлекли ограничения вручную, используйте z3 напрямую — быстрее и гибче:

```python
from z3 import *
x = BitVec('x', 32)
s = Solver()
s.add(x * 4 == 0x10)
s.add(x > 0x10000000)
print(s.check(), s.model())
```

z3 — SMT-солвер под angr; прямой доступ даёт контроль. Альтернативы angr: Manticore (symbolic execution), Triton (concolic), SymCC. Выбор зависит от задачи. Для простых проверок z3 достаточно; для сложных — angr/ручной анализ. Комбинируйте инструменты: angr для навигации, z3 для решения ограничений.

## Пошаговый разбор crackme с несколькими проверками

Если проверок несколько (например, сначала длина, затем символы), angr может «утонуть» в путях. Разбейте задачу: сначала найдите ввод, проходящий первую проверку (find = адрес после неё), затем вторую, комбинируя ограничения. Либо используйте `Veritesting` и ограничьте пространство. Для строковых проверок `strcmp` angr эффективен; для хешей — нет. Логируйте найденные состояния (`sm.found`), извлекайте stdin/stdout (`posix.dumps`). Проверяйте, что `find` действительно достигается (иначе измените адрес/условие). Практикуйтесь на задачах с последовательными проверками — это типичный сценарий angr. Помните, что правильная постановка (find/avoid/ограничения) — половина успеха.


## Разбор angr-отладки и логирования

При работе с angr логируйте состояние: `sm.active`, `sm.found`, `sm.avoid`, а также `state.solver.constraints`. Если `found` пуст, проверьте адрес `find` (правильный ли он) и ограничения (не слишком ли узкие). Используйте `state.solver.eval` для извлечения значений и `eval_upto` для нескольких решений. Для stdin/stdout — `posix.dumps`. Если angr «висит», уменьшите пространство: ограничьте длину ввода, добавьте печатные символы, используйте `Veritesting`. Для больших бинарей анализируйте только нужную функцию (`call_state`). Логирование и итерации — ключ к успеху с angr.
