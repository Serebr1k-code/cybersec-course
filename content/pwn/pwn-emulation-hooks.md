## Вопрос, с которого всё начинается

Ты запустил бинарь под эмулятором, и он отказывается работать. Сначала он проверяет `cpuid` (и, увидев эмулятор, выходит), потом берёт ключ из `getrandom` (а нам нужен предсказуемый), а в конце сравнивает ввод через `strcmp`, который мы не видим.

Обычный хук, который просто печатает события, тут не поможет. Нужны **продвинутые хуки** — те, что меняют состояние: переписывают регистры, подменяют память и результаты функций.

## Наш пример: бинарь с тремя препятствиями

```text
1) cpuid         -> anti-VM проверка
2) getrandom()   -> ключ, который должен быть предсказуем
3) strcmp(input, secret) -> сравнение пароля
```

Разберём, как пройти каждое препятствие и восстановить пароль.

## Шаг 1. Типы хуков в Unicorn

Unicorn вызывает наши функции на разных событиях:

| Хук | Когда вызывается | Применение |
|---|---|---|
| `UC_HOOK_CODE` | перед каждой инструкцией | трассировка, подмена регистров |
| `UC_HOOK_BLOCK` | на базовый блок | ускоренная трассировка |
| `UC_HOOK_MEM_READ` | чтение памяти | перехват доступа к данным |
| `UC_HOOK_MEM_WRITE` | запись памяти | детект порчи данных |
| `UC_HOOK_INSN` | конкретная инструкция | `syscall`, `cpuid`, `rdtsc` |

Ключевой для anti-VM — `UC_HOOK_INSN` на инструкции `cpuid`. Перехватим её и вернём «обычный Intel»:

```python
from unicorn import *
from unicorn.x86_const import *

def hook_cpuid(mu, user_data):
    mu.reg_write(UC_X86_REG_RAX, 0x0000000b)
    mu.reg_write(UC_X86_REG_RBX, 0x756e6547)   # "Genu"
    mu.reg_write(UC_X86_REG_RCX, 0x6c65746e)   # "ineI"
    mu.reg_write(UC_X86_REG_RDX, 0x49656e69)   # "ntel"

mu.hook_add(UC_HOOK_INSN, hook_cpuid, None, 1, 0, UC_X86_INS_CPUID)
```

Теперь программа «видит» нормальный процессор и идёт дальше.

## Шаг 2. Хуки в Qiling: высокий уровень

В Qiling то же самое делается проще — по имени функции или по адресу:

```python
from qiling.const import QL_INTERCEPT

ql.os.set_syscall("open", lambda ql, path, flags, mode: 3)          # подменить syscall
ql.os.set_api("IsDebuggerPresent", lambda ql, *a: 0, QL_INTERCEPT.CALL)  # подменить API

def at_check(ql):
    ql.reg.rax = 1              # «проверка пройдена»
ql.hook_address(at_check, 0x400123)   # сработает на адресе
```

`QL_INTERCEPT.CALL` значит «заменить вызов», а `ENTER`/`EXIT` — «до/после вызова». Это позволяет логировать аргументы перед вызовом и результат после.

## Шаг 3. Подменяем ключ: getrandom

Программа вызывает `getrandom()` и использует результат как ключ шифрования. Подменим его на нули, чтобы крипто-логика стала предсказуемой:

```python
def fake_getrandom(ql, buf, buflen, flags):
    ql.mem.write(buf, b"\x00" * buflen)   # нулевой ключ
    return buflen

ql.os.set_syscall("getrandom", fake_getrandom)
ql.run()
```

Теперь ключ всегда нулевой, и шифрование можно воспроизвести. Тем же способом подменяют `time`, `getpid`, `ptrace` и чтение `/dev/urandom`.

## Шаг 4. Перехватываем strcmp и достаём пароль

Вот главный приём. Вместо того чтобы угадывать пароль, перехватим `strcmp` и напечатаем **оба** аргумента:

```python
def on_strcmp(ql, a, b):
    s1 = ql.mem.string(a)   # что ввёл пользователь
    s2 = ql.mem.string(b)   # что ожидает программа
    print(f"strcmp({s1!r}, {s2!r})")
    return 0                # «строки равны»

ql.os.set_api("strcmp", on_strcmp, QL_INTERCEPT.CALL)
```

```text
strcmp('guess', 'S3cr3tP4ss')
```

Второй аргумент — это и есть искомый пароль. Мы восстановили его, вообще не реверсируя код сравнения.

## Шаг 5. Автоматический реверс: скелет проверки

Для ручных проверок (побайтовое сравнение в цикле) помогает хук кода с дизассемблером **Capstone**. Фильтруем только сравнения и переходы — получаем «скелет» логики:

```python
from capstone import Cs, CS_ARCH_X86, CS_MODE_64
md = Cs(CS_ARCH_X86, CS_MODE_64)

def hook_code(mu, address, size, user_data):
    insn = next(md.disasm(bytes(mu.mem_read(address, size)), address))
    if insn.mnemonic in ("cmp", "test", "je", "jne"):
        print(f"{address:#x}: {insn.mnemonic} {insn.op_str}")

mu.hook_add(UC_HOOK_CODE, hook_code)
```

Так видно, какие байты сравниваются и куда идут ветки, — алгоритм восстанавливается в разы быстрее.

## Шаг 6. Брутфорс с «оракулом»

Хук можно использовать не только для обхода, но и для **ускорения** брутфорса. Если проверка побайтовая, перехватим `memcmp` и посчитаем, сколько байт совпало:

```python
def on_memcmp(ql, a, b, n):
    s1 = ql.mem.read(a, n)
    s2 = ql.mem.read(b, n)
    match = sum(1 for x, y in zip(s1, s2) if x == y)
    print(f"match {match}/{n}")   # прогресс подбора
    return 0
ql.os.set_api("memcmp", on_memcmp, QL_INTERCEPT.CALL)
```

Число совпавших байт показывает прогресс — это детерминированный оракул. Под Unicorn, эмулируя только функцию проверки, миллионы кандидатов прогоняются за секунды.

## Шаг 7. Подменяем сеть

Malware часто ждёт команду от C2. Под эмулятором сеть подменяется хуками на `recv`:

```python
def fake_recv(ql, fd, buf, length, flags):
    data = b"RESPONSE"
    ql.mem.write(buf, data)
    return len(data)
ql.os.set_syscall("recv", fake_recv)
```

Мы «становимся» сервером и смотрим, что образ делает дальше, не поднимая реальную инфраструктуру.

## Отладка хуков и грабли

Хуки сами могут быть источником ошибок. Веди лог каждого перехвата и проверяй, что аргументы имеют ожидаемый тип. В Qiling аргументы приходят как Python-числа (адреса): строки читаются через `ql.mem.string(addr)`, байты — через `ql.mem.read(addr, n)`. Забудешь — получишь «адрес» вместо содержимого и удивишься, почему сравнение не работает. И держи хуки узкими: чем меньше событий ты перехватываешь, тем предсказуемее поведение и тем проще понять, что именно сломалось.

## Эмуляция или Frida

| Критерий | Эмуляция | Frida |
|---|---|---|
| Нужна реальная ОС | нет | да |
| Чужая архитектура | да | нет |
| Скорость | медленнее | быстрее |
| Скрытность | высокая | зависит от anti-Frida |
| Простота хуков | средняя | высокая (JS) |

Эмуляция выигрывает, когда бинарь нельзя запустить (чужая арка, malware, анти-отладка). Frida — когда бинарь работает нативно и нужна скорость. На практике их комбинируют.

## На что смотреть дальше

- **Хук влияет на тайминг.** В динамике это ломает гонки; в эмуляции — «поведение, зависящее от времени».
- **Забыл `UC_HOOK_INSN` для `syscall`** — обычные хуки кода не перехватывают семантику syscall.
- **Слишком широкий хук.** `UC_HOOK_CODE` на всю программу печатает гигабайты — ограничивай диапазон.
- **Рекурсия.** Хук на `strcmp`, внутри которого снова `strcmp`, зациклится — ставь флаг «внутри хука».
- **Аргументы — адреса, а не строки.** Читай их через `ql.mem.string(addr)`.
- **Эксплойт, отработавший под эмулятором, не обязан работать на цели** — адреса и ASLR отличаются. Эмуляция — для понимания и поиска.

## Что мы теперь знаем

- Продвинутый хук **меняет** состояние, а не только логирует.
- `UC_HOOK_INSN` перехватывает `cpuid`/`syscall`; Qiling — по имени и адресу.
- `set_syscall`/`set_api` подменяют результаты (`getrandom`, `strcmp`, `recv`).
- Перехват `strcmp`/`memcmp` даёт пароль и оракул для брутфорса.
- Эмуляция дополняет Frida и отладчик, но не заменяет их.

## Таблица: Unicorn против Qiling против Frida

Три инструмента решают похожие задачи, но на разных уровнях. Выбор зависит от того, что именно вы хотите перехватить и сколько ОС нужно эмулировать.

| Инструмент | Уровень | ОС | Хуки | Когда использовать |
|------------|---------|----|------|--------------------|
| Unicorn | CPU (инструкции) | нет | code/mem/intr | чистый реверс алгоритма без ОС |
| Qiling | ОС (syscalls) | Linux/Win/macOS | API + syscall | бинарь с libc/syscall-ами |
| Frida | процесс | любая | native + Java | живой процесс, рантайм |
| Triton | CPU + символ. | нет | символ. исполнение | решение ограничений, а не хуки |
| angr | CPU + символ. | частично | символ. | авто-поиск пути |

Практическое правило: **Unicorn** — когда нужно просто посчитать функцию; **Qiling** — когда бинарь делает `read`/`write`/`open`; **Frida** — когда бинарь уже запущен и его нельзя пересобрать.

## Рабочий пример: хук на memcmp с дампом аргументов

Классический приём — перехватить сравнение и напечатать оба буфера, чтобы узнать ожидаемый пароль без реверса цикла.

```python
from unicorn import *
from unicorn.x86_const import *
import struct

def hook_memcmp(uc, addr, size, user):
    # System V: rdi, rsi — указатели на буферы, rdx — длина
    rdi = uc.reg_read(UC_X86_REG_RDI)
    rsi = uc.reg_read(UC_X86_REG_RSI)
    rdx = uc.reg_read(UC_X86_REG_RDX)
    a = uc.mem_read(rdi, rdx)
    b = uc.mem_read(rsi, rdx)
    print(f"[memcmp len={rdx}] ours={a!r} expected={b!r}")

ADDR_MEMCMP = 0x401230  # адрес PLT-заглушки memcmp в бинаре
uc = Uc(UC_ARCH_X86, UC_MODE_64)
uc.hook_add(UC_HOOK_CODE, hook_memcmp, begin=ADDR_MEMCMP, end=ADDR_MEMCMP)
```

Важно: хук вешают на **адрес вызова** (`begin=end=ADDR_MEMCMP`), а не на всю память. Читая регистры в момент входа, вы получаете аргументы ровно так, как их видит целевая функция — это снимает необходимость вручную разбирать соглашение вызова.

## Ограничения и типичные ошибки

- **Хук на неверный адрес.** Если хук не срабатывает, проверьте, что адрес — это вход функции (после PLT-резолва), а не сама PLT-строка.
- **Забыть про calling convention.** Для Windows x64 аргументы в `rcx/rdx/r8/r9`, для System V — `rdi/rsi/rdx`; перепутаете — получите мусор.
- **Хук меняет состояние.** Если в хуке модифицировать память или регистры, можно сломать эмуляцию; сохраняйте и восстанавливайте контекст.
- **Unicorn не знает syscall-ов.** Для `read`/`write` нужен Qiling или ручной хук `UC_HOOK_INTR` с реализацией syscall.
- **Qiling медленнее Unicorn.** Полная ОС-эмуляция удобнее, но на больших прогонах в разы медленнее; комбинируйте.

## Полный проход: обход трёх препятствий с логом

Соберём всё в один сценарий и посмотрим, как выглядит вывод на каждом шаге.

```
[emu] загружаем blob.bin, база 0x400000, стек 0x7fff0000
[emu] cpuid -> хук подменяет: "GenuineIntel"
[emu] getrandom -> хук возвращает нули
[emu] strcmp('A'*8, 'S3cr3tP4ss') -> хук печатает оба аргумента
[emu] exit(0)
```

Видно, как каждый хук снимает одно препятствие: `cpuid` возвращает «нормальный Intel», `getrandom` делает ключ нулевым, а перехват `strcmp` выдаёт секрет прямо в логе. Код этого прогона:

```python
from qiling import Qiling
from qiling.const import QL_INTERCEPT

ql = Qiling(["./blob.bin"], "./rootfs/x86_linux")
ql.os.set_syscall("getrandom", lambda ql, buf, n, f: (ql.mem.write(buf, b"\x00"*n), n)[1])
ql.os.set_api("strcmp", lambda ql, a, b: (print("strcmp", ql.mem.string(a), ql.mem.string(b)), 0)[1],
              QL_INTERCEPT.CALL)
ql.run()
```

Обратите внимание на трюк с кортежем: `set_api`-колбэк должен вернуть значение, поэтому «побочный эффект + возврат» упаковывают в `(side_effect, ret)[1]`. Это частый источник багов, когда хук «ничего не делает».

## Таблица: соответствие Unicorn и Qiling

| Задача | Unicorn (низкий уровень) | Qiling (высокий уровень) |
|--------|--------------------------|--------------------------|
| Перехват инструкции | `UC_HOOK_INSN` + `UC_X86_INS_*` | `hook_address`, декодер |
| Перехват syscall | `UC_HOOK_INSN` на `syscall` + ручной разбор ABI | `os.set_syscall("open", ...)` |
| Перехват API-функции | нет (нужен свой символ) | `os.set_api("strcmp", ...)` |
| Подмена регистра | `mu.reg_write(REG_RAX, v)` | `ql.reg.rax = v` |
| Чтение строки | `mu.mem_read(addr, n)` + декод | `ql.mem.string(addr)` |
| Замена вызова | переписать PC вручную | `QL_INTERCEPT.CALL` |

Правило: для чужой архитектуры и «голого» кода (шеллкод, фрагмент) берите Unicorn; для целого бинаря под Linux/Windows с загрузкой библиотек — Qiling, где syscall и API перехватываются по имени.

## Ограничения и типичные грабли

- **Хук `UC_HOOK_CODE` без диапазона.** `hook_add(UC_HOOK_CODE, cb)` без `begin`/`end` вызывается на каждой инструкции всей программы — на реальном бинаре это миллионы вызовов и гигабайты лога. Всегда ограничивайте адресным диапазоном.
- **Рекурсия в хуке.** Если хук на `strcmp` внутри сам вызывает `strcmp` (например, через Python-сравнение строк с эмуляцией), получите бесконечную рекурсию. Ставьте флаг `in_hook`.
- **Хук меняет тайминг.** В эмуляции «поведение, зависящее от времени» (rdtsc, sleep) ломается: подменяйте `rdtsc`/`clock_gettime` предсказуемо.
- **Аргументы — адреса, не строки.** `ql.mem.string(addr)` для C-строк, `ql.mem.read(addr, n)` для буферов; передача «адреса» в `print` даёт число, а не содержимое.
- **Эксплойт под эмулятором ≠ на цели.** Адреса, ASLR и libc отличаются; эмуляция — для понимания логики, а не как оружие «в лоб».

## Куда дальше

Модуль эмуляции закрыт. Родственный, но иной подход к тем же задачам — **символьное исполнение** (`pwn-symbolic-angr`): там мы не перехватываем конкретные вызовы, а просим решатель найти вход, приводящий к нужной ветке. А пока главное: **хук, который меняет состояние, превращает эмулятор из проигрывателя байтов в управляемую среду — обходи anti-VM, подменяй случайность, доставай секреты из сравнений.**
