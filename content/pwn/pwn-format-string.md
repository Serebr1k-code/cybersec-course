## Вопрос, с которого всё начинается

Бывает, что переполнения нет вовсе, а программа просто печатает то, что ты ввёл. Казалось бы, безобидно. Но если печатает она через `printf` и передаёт ему твою строку **как формат**, ты можешь читать и даже записывать память. Это уязвимость **format string**.

Разберём её на маленькой программе от первого `%p` до чтения произвольного адреса.

## Наш пример: printf, которому отдали наш ввод

```c
// fmt.c
#include <stdio.h>
int main(void) {
    char buf[128];
    fgets(buf, sizeof(buf), stdin);
    printf(buf);      // <- buf уходит как ФОРМАТ, а не как данные
    return 0;
}
```

```bash
$ gcc -o fmt fmt.c
$ ./fmt
hello
hello
```

Программа печатает ввод. Ошибка в строке `printf(buf)`: правильная запись — `printf("%s", buf)`. Но почему это опасно?

## Шаг 1. Как printf читает аргументы

`printf` — функция с переменным числом аргументов. Её первый аргумент — строка формата, в которой специальные последовательности вроде `%d`, `%s`, `%p` означают «подставь сюда значение». Значения `printf` берёт **из регистров и стека** — по одному на каждый спецификатор.

Когда программист пишет `printf("%s", buf)`, он честно передаёт строку вторым аргументом. А если написано `printf(buf)`, и ты вводишь `%p`, то `printf` считает, что значение для `%p` где-то передано, и берёт его из регистра. Ты управляешь тем, **сколько** значений он прочитает и **откуда**.

Подадим `%p` несколько раз и посмотрим, что печатается:

```bash
$ echo '%p %p %p %p %p' | ./fmt
0x7ffd3a2b4c10 0x7f2b6a1d2a00 (nil) 0x7ffd3a2b4d18 0x1
```

Мы получили содержимое регистров и стека. Среди этих значений — адреса стека и libc. Это и есть **утечка**: мы узнаём адреса, которых нам знать не положено.

## Шаг 2. Ищем, где на стеке наш ввод

Чтобы прочитать конкретное место, нужно понять, на какой позиции `printf` видит нашу строку. Подадим метку `AAAA` и посмотрим, где она появится:

```bash
$ echo 'AAAA %p %p %p %p %p %p %p %p' | ./fmt
AAAA 0x7ffd... (nil) 0x1 0x41414141 ...
```

Число `0x41414141` — это наши `AAAA` (0x41 = 'A'). Позиция этого `%p` и есть смещение до нашего буфера. В CTF обычно берут длинную метку `AAAAAAAA` и считают позицию точно:

```python
>>> from pwn import *
>>> p = process('./fmt')
>>> p.sendline(b'AAAAAAAA ' + b'%p '*12)
>>> print(p.recvline())
b'AAAAAAAA 0x7f... 0x1 0x4141414141414141 ...'
```

Пусть наша метка оказалась на позиции 6. Это значит: `%6$p` печатает первые 8 байт нашего буфера. Запись `%N$p` — это «взять N-й аргумент», так называемый **прямой доступ к позиции**. Он нужен, чтобы не перебирать `%p` по одному.

## Шаг 3. Произвольное чтение через %s

`%p` печатает само значение, а `%s` — **читает память по этому значению как по адресу** и печатает строку. Это даёт произвольное чтение.

Схема: кладём в буфер нужный адрес, а форматом просим `printf` прочитать по нему строку. Адрес окажется на стеке по нашей позиции, поэтому используем `%6$s`:

```python
addr = elf.got['printf']          # адрес, который хотим прочитать
payload = p64(addr) + b'%6$s'
p.sendline(payload)
leak = p.recv()
```

`printf` увидит наш `p64(addr)` как 8 байт на стеке, `%6$s` возьмёт эти 8 байт как адрес и напечатает содержимое — например, реальный адрес функции libc. Так обходят ASLR: узнав адрес одной функции, вычисляют базу libc.

## Шаг 4. Точное определение позиции

Позицию своего буфера лучше определять аккуратно: подаём метку из 8 одинаковых байт и ищем её среди выводов `%p`. Метка должна быть уникальной, чтобы не спутать с мусором на стеке.

```python
from pwn import *
p = process('./fmt')
p.sendline(b'AAAAAAAA' + b'.%p' * 12)
print(p.recvline())
```

В выводе мы ищем `0x4141414141414141` — это наши восемь `A`. Номер `%p`, на котором он появился, и есть смещение. Если метка встречается не целиком (потому что выравнивание съело пару байт), сдвигаем начало метки и повторяем.

Дальше это смещение используется везде: `%6$p` для чтения и `fmtstr_payload(6, ...)` для записи. Ошибиться на единицу легко, поэтому проверку позиции делают всегда, а не «на глаз».

## Шаг 5. Запись через %n

Ещё опаснее спецификатор `%n`: он **не печатает**, а записывает в указатель, переданный аргументом, количество уже выведенных символов. Управляя этим количеством, можно записать произвольное значение по произвольному адресу.

Приём классический — перезаписать запись в GOT так, чтобы функция вела в нужное место. Например, подменить адрес `printf` в GOT на адрес `system`, и тогда следующий `printf(buf)` выполнит `system(buf)`, то есть `system("/bin/sh")`.

Запись делают по байтам (младший байт, потом следующий), потому что целиком записать 8-байтовый адрес за один `%n` мешает ограничение длины вывода. Общая идея:

```python
# хотим записать system по адресу got['printf']
payload = fmtstr_payload(offset, {elf.got['printf']: system_addr})
p.sendline(payload)
```

Функция `fmtstr_payload` из pwntools собирает всю эту магию с `%n` и выравниванием длины автоматически. Главное понимать, что она делает: разбивает целевое значение на байты и записывает их через несколько `%n` по нужным адресам.

## Шпаргалка по спецификаторам

| Спецификатор | Что делает | Зачем в эксплойте |
|---|---|---|
| `%p` | печатает значение аргумента | утечка адресов стека/libc |
| `%N$p` | печатает N-й аргумент | прямой доступ к позиции |
| `%s` | печатает строку по адресу-аргументу | произвольное чтение |
| `%n` | пишет число выведенных символов | произвольная запись |
| `%N$n` | пишет в N-й аргумент-указатель | запись по выбранному адресу |
| `%<ширина>c` | печатает нужное число символов | подготовка значения для `%n` |


## Откуда это берётся в реальном коде

Уязвимость выглядит «искусственной», но встречается постоянно. Типичные места:

- логирование пользовательского ввода: `printf(user)` или `syslog(LOG_ERR, user)`;
- отладочные ветки, забытые в релизе: `printf(input);` вместо `printf("%s", input);`;
- обёртки над `printf`, которые просто прокидывают строку дальше.

Достаточно одного такого вызова, чтобы получить утечку адресов или запись в память. Поэтому при аудите кода ищут вызовы `printf`/`fprintf`/`snprintf`/`syslog`/`setproctitle`, где формат берётся из переменной, а не из константы.

## Что мы теперь знаем

- Опасен не сам `printf`, а вызов `printf(buf)` — когда ввод становится форматом.
- Спецификаторы `%p`, `%s`, `%n` позволяют читать и писать память.
- `%N$p` — прямой доступ к N-му аргументу; так находят позицию своего буфера.
- `%s` даёт произвольное чтение: адрес кладут в буфер, `%s` читает по нему.
- `%n` пишет число выведенных символов по указанному адресу.
- `fmtstr_payload` собирает запись через `%n` автоматически.

## Куда дальше

Format string даёт нам утечку и запись — это универсальный инструмент, но пока мы вызываем лишь существующие функции. В следующем уроке (`pwn-rop`) соберём из кусочков кода настоящую цепочку вызовов, чтобы обойти NX. Запомни главное: **если твой ввод попадает в printf как формат — ты можешь читать и писать память.**

## Где пригодится

- **CTF Pwn:** задачи без переполнения часто решаются именно format string.
- **Аудит C/C++ кода:** `printf(user_input)`, `syslog(fmt)` — классическая находка в отчётах.
- **Утечки памяти:** обход ASLR/PIE через чтение адресов libc и стека.
- **Реальное ПО:** CVE с format string встречаются в принтерах, роутерах, демонах.
