Browser/JIT exploitation — это эксплуатация браузерных движков (V8 в Chrome, SpiderMonkey в Firefox, JavaScriptCore в Safari) через баги в JIT-компиляторах, сборщике мусора и объектной модели. Такие уязвимости класса type confusion и UAF позволяют получить arbitrary read/write в контексте рендерера, обойти песочницу и добиться RCE. Это одна из самых сложных и востребованных областей pwn. В этом уроке — устройство JIT, типовые баги (type confusion, UAF), приёмы построения примитивов, обход песочницы и практические примеры (в обобщённом виде, без конкретных эксплойтов).

## Устройство JS-движка и JIT

JS-движки интерпретируют JavaScript, а «горячие» функции компилируют в нативный код (JIT). V8 использует TurboFan/Maglev, SpiderMonkey — IonMonkey, JavaScriptCore — DFG/FTL. JIT оптимизирует код на основе предположений о типах объектов; если предположение нарушено (type confusion), оптимизированный код обращается с объектом неверно. Это классический источник уязвимостей.

## Type confusion

Type confusion возникает, когда движок считает объект одного типа, а он другого. Пример: оптимизированный код предполагает, что массив содержит числа (float), а на деле — объекты (pointers). Тогда чтение элемента даёт утечку указателя (или запись произвольного значения). Эксплуатация: (1) спровоцировать confusion; (2) получить разницу представлений (например, float ↔ pointer) для arbitrary read/write; (3) построить примитивы; (4) обойти песочницу.

## UAF в GC

Сборщик мусора освобождает объекты; если движок ошибочно считает объект живым, возникает UAF. Эксплуатация: переиспользовать освобождённую память объектом с контролируемыми полями, затем через «висячий» указатель манипулировать им. Часто комбинируется с JIT-оптимизациями.

## Примитивы: addrof и fakeobj

Классические примитивы для V8:
- **addrof(obj)** — получить адрес объекта как число (через confusion).
- **fakeobj(addr)** — создать ссылку на произвольный адрес.
С их помощью строят arbitrary read/write: создают поддельный `ArrayBuffer`/`TypedArray` с контролируемым указателем на данные, затем читают/пишут память. Это стандартный маршрут браузерных эксплойтов.

```javascript
// концептуально (не реальный эксплойт)
let f = () => { /* JIT-функция с type confusion */ };
// addrof/fakeobj -> arbitrary r/w
```

## Обход песочницы

Рендерер работает в песочнице (seccomp на Linux, sandbox на macOS/Windows). Чтобы получить RCE, нужно: (1) добиться arbitrary r/w в рендерере; (2) найти баг/примитив для выхода из песочницы (например, через IPC-интерфейсы, GPU-процесс, Mojo в Chrome); (3) выполнить код вне песочницы. Часто используют цепочку из двух багов: один в JS-движке, другой в IPC.

## Разобранный пример (структура)

```text
1) Найти баг (patch diff, fuzzing).
2) Написать JS, провоцирующий type confusion/UAF.
3) Построить addrof/fakeobj.
4) Построить arbitrary read/write через fake ArrayBuffer.
5) Найти WASM-инстанс или JIT-страницу для исполнения.
6) Обойти песочницу через IPC-баг.
7) Выполнить shellcode.
```

## Частые ошибки

- **Неверная версия движка.** Баг привязан к конкретному коммиту.
- **JIT-детерминизм.** Оптимизация может не сработать; используйте циклы/`%OptimizeFunctionOnNextCall`.
- **GC-тайминг.** UAF требует точного управления GC.
- **Песочница.** Без обхода — только рендерер.
- **Отладка.** Символы V8 нужны для анализа.

## Полный разбор V8 type confusion

Разберём обобщённый сценарий эксплуатации V8. Дано: баг в оптимизации TurboFan, приводящий к type confusion между `float64`-массивом и массивом объектов. Цель — arbitrary read/write. Шаги: (1) написать JS-код, который JIT-оптимизирует функцию с ошибочным предположением о типе; (2) спровоцировать confusion, чтобы один и тот же буфер интерпретировался и как числа, и как указатели; (3) реализовать `addrof(obj)` — поместить объект в массив, прочитать его как float, преобразовать в адрес; (4) реализовать `fakeobj(addr)` — записать адрес как float в массив объектов, получить ссылку; (5) создать поддельный `ArrayBuffer`/`TypedArray` с контролируемым `backing_store`, чтобы читать/писать произвольную память; (6) использовать примитив для получения RIP (например, перезаписать JIT-страницу или WASM-код). Всё это делается в `d8` для отладки, затем переносится в браузер.

## JIT-спрей и RWX-страницы

Для исполнения кода нужна исполняемая память. В V8 это JIT-страницы (RWX или W^X с переключением) и WASM-инстансы. Приём: создать WASM-модуль, найти его исполняемую страницу через arbitrary read, записать туда shellcode и вызвать функцию. Это стандартный способ обхода W^X в V8. Альтернатива — перезаписать указатель на JIT-код или использовать `ArrayBuffer` для записи в JIT-страницу. В современных V8 (с W^X) нужны дополнительные шаги, но принцип тот же. WASM-инстансы часто остаются RWX, что делает их удобной целью.

## Обход песочницы Chrome

Рендерер Chrome работает в песочнице (seccomp-bpf на Linux). Чтобы получить RCE, нужно выйти из неё. Пути: (1) баги в IPC-интерфейсах (Mojo), (2) GPU-процесс (часто менее изолирован), (3) sandbox escape через системные вызовы/драйверы. Цепочка эксплойта обычно состоит из двух багов: один в JS-движке (для arbitrary r/w в рендерере), другой в IPC (для выхода из песочницы). Публичные эксплойты (например, для Pwn2Own) демонстрируют такие цепочки. Изучайте writeup'ы, чтобы понять типовые IPC-баги.

## Отладка и инструменты

Для отладки используйте `d8` (shell V8) с флагами `--allow-natives-syntax`, `--trace-opt`, `--trace-deopt`. Команды `%DebugPrint(obj)`, `%SystemBreak()` помогают в отладке. `Turbolizer` визуализирует графы оптимизации — invaluable для понимания type confusion. GDB с символам V8 позволяет смотреть объекты в памяти. Для браузера используйте `--js-flags="--allow-natives-syntax"` и devtools. Логируйте адреса и типы.

## Практические рекомендации

Начните с `d8` и простых багов (patch diff, публичные PoC). Освойте `addrof`/`fakeobj` и построение fake ArrayBuffer. Затем изучите JIT/WASM для исполнения и IPC для песочницы. Browser/JIT — одна из самых сложных областей pwn, требующая глубоких знаний движка, GC и песочницы. Практикуйтесь на CTF-задачах и публичных эксплойтах, постепенно усложняя. Эта область высоко ценится в реальных атаках.

## Сравнение движков и цепочка эксплойта

V8, SpiderMonkey и JavaScriptCore имеют похожие классы багов (type confusion, UAF), но разные детали. V8 — самый популярный (Chrome), с богатой документацией. Цепочка браузерного эксплойта обычно: (1) баг в JS-движке → arbitrary r/w в рендерере; (2) примитив для исполнения (JIT/WASM); (3) баг в IPC → выход из песочницы; (4) shellcode. Каждый этап — отдельная задача. Изучайте публичные эксплойты (Pwn2Own, Project Zero) и патчи — они показывают, как баги выглядят и как их эксплуатируют. Начните с `d8` и простых багов, затем добавляйте песочницу.

## Практика и ресурсы

Ресурсы: блог Project Zero, writeup'ы Pwn2Own, `v8` issue tracker, статьи о TurboFan. Практика: `d8` с `--allow-natives-syntax`, отладка через GDB, Turbolizer. Начните с известных type confusion (например, CVE-2020-16040), воспроизведите PoC, разберите его. Постепенно переходите к более сложным багам и песочнице. Browser/JIT — марафон, но результат (RCE в браузере) — один из самых впечатляющих в безопасности.

## Sandbox escape: типовые векторы

Песочница Chrome изолирует рендерер, но IPC-интерфейсы (Mojo) и GPU-процесс дают поверхность атаки. Типовые векторы: (1) баги в десериализации IPC-сообщений; (2) ошибки в правах доступа к ресурсам; (3) баги в GPU-драйвере/командах; (4) обход через `file://`/навигацию. Цепочка: JS-баг → arbitrary r/w в рендерере → поиск IPC-примитива → выполнение кода вне песочницы. Изучайте writeup'ы Pwn2Own и Project Zero: они детально разбирают обе половины цепочки. Sandbox escape — отдельный навык, и его освоение делает вас специалистом по browser exploitation.

## Итоговая мысль

Browser/JIT exploitation — вершина pwn-навыков. Освойте JS-движок, JIT-оптимизации, примитивы addrof/fakeobj и построение arbitrary r/w. Затем изучите исполнение (JIT/WASM) и выход из песочницы (IPC). Практикуйтесь на `d8` и публичных PoC, разбирайте патчи и writeup'ы. Это марафон, но навыки переносятся на реальные атаки и высоко ценятся в индустрии.

Изучайте writeup'ы Pwn2Own и Project Zero: они детально разбирают обе половины цепочки (движок и песочницу) и являются лучшим источником практических знаний по browser exploitation.

## Финальный совет

Постройте окружение для отладки: `d8` со всеми флагами, GDB с символами V8, Turbolizer. Начните с простого type confusion, отработайте addrof/fakeobj и arbitrary r/w, затем переходите к исполнению и песочнице. Разбирайте каждый публичный PoC построчно — это лучший способ научиться.
