Квантовый компьютер не «перебирает быстрее» — он меняет асимптотику конкретных задач. Шор сводит факторизацию и дискретный логарифм к поиску периода, который квантово решается за полиномиальное время, — и это обнуляет RSA, DH и ECC. Гровер даёт лишь квадратичное ускорение, поэтому симметрика и хэши выживают при удвоении длины ключа. Эта глава объясняет *почему*, какие размеры нужны, и как это проверить на симуляторе.

## Что именно даёт квантовый компьютер

Три квантовых примитива, на которых стоит вся криптоаналитика:

- **Суперпозиция** — регистр из `n` кубитов представляет `2^n` амплитуд одновременно.
- **Интерференция** — амплитуды складываются и гасятся, усиливая «правильные» ответы.
- **Запутанность** — корреляции между кубитами, позволяющие эффективно реализовать оракулы.

Классический компьютер «пробует» варианты по одному (или параллельно на ограниченном числе ядер). Квантовый за один прогон обрабатывает амплитудный вектор экспоненциального размера — но измерить можно лишь один результат, поэтому вся хитрость в том, чтобы интерференция сконцентрировала вероятность на ответе.

## Алгоритм Шора: факторизация

Задача факторизации сводится к **нахождению периода** функции `f(x) = a^x mod N`. Если период `r` чётный и `a^{r/2} ≠ -1 mod N`, то `gcd(a^{r/2} ± 1, N)` даёт нетривиальные делители.

Квантовая часть:

1. Готовим два регистра, `|0⟩|0⟩`.
2. Адамаром создаём суперпозицию всех `x` в первом регистре.
3. Вычисляем `f(x) = a^x mod N` во втором (обратимая схема).
4. Применяем **квантовое преобразование Фурье (QFT)** к первому регистру — оно интерферирует так, что измерение даёт значения, кратные `2^n / r`.
5. По нескольким измерениям восстанавливаем `r` через **цепные дроби** (см. `crypto-continued-fractions`).

Сложность: `O((log N)^3)` — полиномиально, против субэкспоненциального GNFS для классики. Для 2048-битного RSA классике нужно ~2^110 операций; Шору — порядка нескольких тысяч логических кубитов и миллиарды вентилей (оценки ~20 млн физических кубитов для отказоустойчивой машины).

```python
# Классическая часть (цепные дроби) — то, что делают ПОСЛЕ квантовых измерений
from fractions import Fraction
def period_from_measurement(meas, n_qubits, N):
    frac = Fraction(meas, 2**n_qubits).limit_denominator(N)
    return frac.denominator          # кандидат в r
```

## Алгоритм Шора: дискретный логарифм и ECC

Тот же период-поиск решает **дискретный логарифм**: по `g^x = h` найти `x` (в DH) и **ECDLP** (в ECC). Именно поэтому Шор ломает не только RSA, но и Diffie-Hellman, DSA, ECDSA, EdDSA — все схемы на «трудности DLP». ECDLP решается с меньшими ресурсами, чем факторизация, но всё равно полиномиально.

## Алгоритм Гровера: ускорение перебора

Гровер ищет элемент в неструктурированном множестве из `M` за `O(√M)` обращений к оракулу вместо `O(M)`. Для криптографии это значит:

- **Перебор ключа длиной `k`** — `2^{k/2}` вместо `2^k`: AES-128 → ~2^64, AES-256 → ~2^128.
- **Поиск прообраза хэша** — `2^{n/2}` вместо `2^n`: SHA-256 → ~2^128.

Это **не** «ломает AES». Квадратичное ускорение компенсируется удвоением длины ключа: AES-256 и SHA-384 остаются стойкими в пост-квантовом мире.

## Влияние на реальные схемы

| Схема | Классическая стойкость | Стойкость против Шора | Против Гровера |
|-------|:----------------------:|:---------------------:|:--------------:|
| RSA-2048 | ~112 бит | сломана | — |
| DH/ECDH | ~112–128 бит | сломана | — |
| ECDSA/EdDSA | ~128 бит | сломана | — |
| AES-128 | 128 бит | — | ~64 бита |
| AES-256 | 256 бит | — | ~128 бит |
| SHA-256 | 256 бит | — | ~128 бит |

Практический вывод: **удвойте симметричные ключи и хэши**, а асимметрию **замените** пост-квантовой.

## Практика: qiskit и симуляция

Полноценный Шор на реальном железе невозможен, но на симуляторе можно прочувствовать период-поиск для маленьких чисел.

```bash
pip install qiskit qiskit-aer
```

```python
from qiskit import QuantumCircuit, Aer, execute
from qiskit.circuit.library import QFT

def shor_circuit(a, N, n):
    qc = QuantumCircuit(2*n, n)
    qc.h(range(n))                    # суперпозиция
    # ... оракул a^x mod N (обратимая схема) ...
    qc.append(QFT(n, do_swaps=True), range(n))   # обратное QFT
    qc.measure(range(n), range(n))
    return qc

qc = shor_circuit(a=7, N=15, n=4)
result = execute(qc, Aer.get_backend('aer_simulator'), shots=1024).result()
print(result.get_counts())            # пики на кратных 2^n / r
```

На симуляторе это работает для `N = 15, 21, 35` — достаточно, чтобы увидеть, как измерение концентрируется на кратных `1/r`. Для реальных `N` нужны тысячи кубитов и коррекция ошибок.

## Пост-квантовая криптография (переход)

Раз Шор ломает всю асимметрию, NIST стандартизировал замену:

- **ML-KEM (Kyber)** — обмен ключами на решётках (LWE), замена RSA/ECDH.
- **ML-DSA (Dilithium)** — подписи на решётках.
- **SLH-DSA (SPHINCS+)** — хэш-подписи (консервативная опция).
- **FN-DSA (Falcon)** — компактные решёточные подписи.

Детали — в `crypto-post-quantum` и `crypto-lattice`. Гибридные схемы (классика + PQ) — текущий стандарт перехода: ломается, только если сломаны оба.

## Частые ошибки и мифы

- **«Гровер ломает AES».** Нет: только `2^{k/2}`, что компенсируется ключом ×2.
- **«Нужен один кубит на бит».** Нет: отказоустойчивость требует тысяч физических кубитов на логический.
- **«Шор ускоряет перебор».»** Шор — про структуру (период), а не перебор.
- **«Симметрика в опасности».»** AES-256/SHA-384 стойки; удваивайте длину.
- **Путать QFT и классический FFT.** QFT работает над амплитудами, а не над вектором чисел.
- **Считать симулятор доказательством.** Симуляция `N=15` — это демонстрация, а не «взлом RSA».

## Что дальше (decision)

1. Тема — «сломать RSA/ECC в будущем» → изучайте Шор + `crypto-post-quantum`.
2. Тема — «ускорение перебора» → Гровер, удвоение ключей.
3. Нужно понять решёточную замену → `crypto-lattice`, `crypto-ntru`.
4. CTF-задача с «квантовым» условием → почти всегда классическая (цепные дроби, дискретный лог).
5. Аудит систем → планируйте миграцию на гибридные PQ-схемы.

| Алгоритм | Ускоряет | Сложность | Ломает |
|----------|----------|-----------|--------|
| Шор | факторизацию | O((log N)^3) | RSA |
| Шор | DLP/ECDLP | полином | DH, ECDSA, EdDSA |

## Оценки ресурсов и timeline

Полезно понимать порядки величин, чтобы не путать демонстрации с реальной угрозой:

- **Шор для RSA-2048.** Требуется порядка `2n+2 ≈ 4098` логических кубитов (плюс ancilla) и ~`n³ ≈ 10^10` вентилей. С коррекцией ошибок (surface code) на один логический кубит уходят тысячи физических — суммарно миллионы физических кубитов и часы/дни работы.
- **Симуляция.** Классический симулятор хранит `2^n` амплитуд; уже `n=50` — это петабайты памяти. Поэтому реально симулируют `N=15..35`.
- **Гровер.** Для AES-128 нужно ~`2^64` квантовых вентилей — практически недостижимо для «сломать сегодня», но это мотивирует AES-256.
- **Timeline.** Экспертные оценки «криптографически значимого» квантового компьютера — 10–30 лет; отсюда стратегия «harvest now, decrypt later» и миграция на PQ уже сейчас.

Для CTF достаточно понимать редукцию (период → цепные дроби) и не путать асимптотику с реальным железом.

## Быстрые рецепты для CTF

- **«Квантовое» условие, но числа маленькие** → почти всегда классическая редукция: цепные дроби для периода, дискретный лог, факторизация.
- **Дано `a^r ≡ 1 mod N`** → восстановите `r` цепными дробями и факторизуйте `N`.
- **Задача про «Гровер»** → удвойте длину ключа, ищите `2^{k/2}`-перебор (на практике нереально, значит подсказка на что-то другое).
- **Post-quantum в условии** → `crypto-post-quantum`, `crypto-lattice`.
- **Симулятор qiskit** → только для демонстрации `N=15..35`; для реального `N` не поможет.
