## Зачем нужны режимы

Сам AES — это детерминированная перестановка на множестве 128-битных блоков: для фиксированного ключа `K` он отображает ровно **16 байт** открытого текста в ровно 16 байт шифротекста, и это отображение обратимо. Если бы мы просто шифровали каждый блок отдельно и одинаковым способом, то одинаковые куски текста давали бы одинаковый шифротекст — и вся структура сообщения «просвечивала» бы наружу. Режим работы (mode of operation) — это надстройка над блочным шифром, которая превращает его в схему для шифрования сообщений произвольной длины и решает проблему повторяющихся блоков (рандомизация, сцепление, аутентификация).

Ключевая мысль урока: **в CTF ломают не AES, а режим**. AES-128/256 сам по себе не имеет практичных атак (brute-force 2^128 недостижим), поэтому задачи строятся на ошибках применения: ECB без сцепления, CBC без MAC, CTR/GCM с переиспользованным nonce, усечённые теги. Понимание каждого режима — это карта того, какую атаку искать.

**Ключевые понятия:**

- **Block** — 16 байт (128 бит) для AES.
- **IV (Initialization Vector)** — начальное значение для режимов CBC/CFB/OFB. Не секрет, но должен быть случайным и уникальным.
- **Nonce** — «number used once», уникальное значение для CTR/GCM. Секретности не требует, уникальности — требует.
- **Padding** — добивка последнего блока до 16 байт. Для CBC/ECB почти всегда PKCS#7: если не хватает `n` байт, добавляют `n` байт со значением `n`.
- **Keystream** — поток, который XORится с текстом в потоковых режимах (CTR/OFB/CFB).

## ECB (Electronic Codebook) — катастрофа

Каждый блок шифруется **независимо и одинаково**: `C_i = E_K(P_i)`. Никакой рандомизации нет.

Следствие, которое надо запомнить наизусть: **одинаковые блоки открытого текста дают одинаковые блоки шифротекста**. ECB не скрывает паттерны — он работает как «кодовая книга» (codebook): один и тот же вход всегда даёт один и тот же выход.

Классическая иллюстрация — «ECB-пингвин»: картинка, зашифрованная ECB, сохраняет очертания, потому что повторяющиеся области (фон) шифруются в повторяющиеся блоки. На CTF ECB ломается двумя способами:

- **Детект по повторам:** если в шифротексте есть два одинаковых 16-байтных блока — это ECB. Признак работает, даже не зная ключа.
- **ECB oracle:** сервер шифрует `prefix || attacker_input || SECRET`, где attacker управляет частью ввода. Выравнивая блоки и перебирая байты, секрет восстанавливается побайтово (см. `crypto-ecb-oracle`).

```python
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad
key = b"0123456789abcdef"
cipher = AES.new(key, AES.MODE_ECB)
ct = cipher.encrypt(pad(b"A"*32, 16))
# ct[:16] == ct[16:32]  -> ECB! (два одинаковых блока 'A')
```

Функция детекта ECB по повторам блоков — это первая вещь, которую пишут на любой crypto-задаче:

```python
def is_ecb(ct, bs=16):
    blocks = [ct[i:i+bs] for i in range(0, len(ct) - len(ct) % bs, bs)]
    return len(blocks) != len(set(blocks))
```

Важно: детект работает только если на входе было достаточно повторяющегося текста. Отправьте 32+ одинаковых байта — тогда при ECB гарантированно получите два одинаковых блока.

## CBC (Cipher Block Chaining)

Каждый блок открытого текста XORится с **предыдущим шифротекстом** перед шифрованием, поэтому одинаковые блоки текста дают разные блоки шифротекста:

```
C_0 = E_K(P_0 ⊕ IV)
C_i = E_K(P_i ⊕ C_{i-1})
```

Расшифрование: `P_i = D_K(C_i) ⊕ C_{i-1}` (где `C_{-1} = IV`). IV — случаен и уникален на каждое сообщение (но не секретен). CBC скрывает паттерны, однако его «ковкость» (malleability) порождает три классические атаки:

- **Bit-flipping:** изменение байта `C_{i-1}` предсказуемо искажает соответствующий байт `P_i` (см. `crypto-cbc-bitflip`).
- **Padding oracle:** разные ответы сервера на «padding valid/invalid» утекают информацию и позволяют расшифровать всё сообщение (см. `crypto-padding-oracle`).
- **Фиксированный/предсказуемый IV:** позволяет сравнивать первый блок двух сообщений и атаковать BEAST-класс сценариев.

```python
import os
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad
cipher = AES.new(key, AES.MODE_CBC, iv=os.urandom(16))
ct = cipher.encrypt(pad(pt, 16))
```

Критично: CBC **не даёт целостности**. Голый CBC всегда нужно комбинировать с MAC (encrypt-then-MAC), иначе шифротекст можно изменять.

## CFB и OFB — близкие родственники

CFB (Cipher Feedback) и OFB (Output Feedback) превращают блочный шифр в потоковый, но по-разному:

- **CFB:** `C_i = P_i ⊕ E_K(C_{i-1})`, то есть keystream зависит от предыдущего шифротекста. Расшифрование симметрично, ошибка в байте портит один блок и «сдвигает» следующий.
- **OFB:** keystream генерируется независимо от текста: `O_i = E_K(O_{i-1})`, `C_i = P_i ⊕ O_i`. Ошибка в шифротексте портит ровно один бит открытого текста (нет распространения).

Оба режима требуют уникального IV. При переиспользовании IV для одного и того же ключа OFB даёт **одинаковый keystream** → `C1 ⊕ C2 = P1 ⊕ P2`, то есть many-time pad. Подробнее — в `crypto-cfb-ofb`.

## CTR (Counter) — потоковый режим

CTR генерирует keystream из шифрования счётчика: `O_i = E_K(nonce || counter_i)`, `C_i = P_i ⊕ O_i`. Плюсы: параллелизуемо, не нужен padding (длина шифротекста равна длине текста), произвольный доступ к блокам. Минус — тот же, что у OFB: **катастрофа при переиспользовании `(key, nonce)`**.

Если два сообщения зашифрованы одним `(key, nonce)`, keystream совпадает, и `C1 ⊕ C2 = P1 ⊕ P2` — это many-time pad (см. `crypto-xor-otp` и `crypto-iv-reuse`). Зная один из текстов (или угадав его), второй восстанавливается мгновенно.

```python
cipher = AES.new(key, AES.MODE_CTR, nonce=os.urandom(8))
ct = cipher.encrypt(pt)   # без padding, длина == len(pt)
```

**Правило:** nonce должен быть **уникален** для каждого шифрования одним ключом. Переиспользование = полный взлом. Именно поэтому в GCM/CTR нельзя «просто сбросить счётчик при рестарте».

## GCM (Galois/Counter Mode) и AEAD

GCM = CTR + аутентификация (тег GHASH). Это **AEAD** (Authenticated Encryption with Associated Data): обеспечивает и конфиденциальность, и целостность. Associated Data (AAD) — данные, которые не шифруются, но аутентифицируются (заголовки, метаданные).

```
C = CTR-encrypt(P)
tag = GHASH(H, C, AAD) ⊕ E_K(J0),  где H = E_K(0^128)
```

Опасности:

- **Переиспользование nonce в GCM катастрофично:** раскрывает XOR текстов И позволяет восстановить ключ аутентификации `H` (решив систему над GF(2^128)), после чего подделывать теги для произвольных сообщений (forbidden attack). См. `crypto-gcm`.
- **Отсутствие проверки тега** → нет целостности; данные нельзя использовать до проверки тега.
- **Усечённые теги** (например, 32 бита) снижают стойкость до 2^32 подделок.
- **Атаки на реализацию** (timing, nonce-reuse в библиотеках).

Правильно: уникальный nonce (обычно random 96 бит), проверка тега **до** использования расшифрованных данных.

## Как определить режим по шифротексту

Это первое, что делают на задаче с неизвестным шифром. Таблица — рабочая шпаргалка:

| Признак | Режим |
|---|---|
| Повторяющиеся 16-байтные блоки | ECB |
| Длина кратна 16, без повторов, ошибки «на границах» блоков | CBC |
| Длина равна открытому тексту (не кратна 16) | CTR/OFB/CFB (потоковый) |
| Есть 16-байтный тег аутентификации в конце | GCM/CCM |
| Ошибки padding / «invalid padding» / «bad decrypt» | CBC (или ECB) с PKCS#7 |
| Keystream XOR — сравнение двух шифротекстов даёт осмысленный XOR | CTR/OFB с reused nonce |

```python
def guess_mode(ct):
    if is_ecb(ct): return "ECB"
    if len(ct) % 16 == 0: return "CBC (или блочный)"
    return "потоковый (CTR/CFB/OFB)"
```

## Практический пример: детект и цепочка атак

Дана «cookie»: `session=<base64>` и оракул, шифрующий `prefix || user_input || secret`.

```python
import base64
def oracle(user_input):
    # возвращает base64 шифротекста; внутри prefix + user_input + SECRET
    ...

# 1. Определяем размер блока: увеличиваем ввод, ищем прыжок длины
base = len(oracle(""))
for i in range(1, 64):
    if len(oracle("A"*i)) > base:
        print("block size:", len(oracle("A"*i)) - base); break
# -> block size: 16

# 2. Проверяем ECB: 32 'A' должны дать два одинаковых блока
ct = base64.b64decode(oracle("A"*32))
print("ECB?", is_ecb(ct))
# Если True -> открываем crypto-ecb-oracle и восстанавливаем SECRET побайтово.
```

Если бы длина не была кратна 16 — это сигнал о потоковом режиме, и дальше мы искали бы переиспользование nonce (`C1 ⊕ C2 = P1 ⊕ P2`). Если бы сервер отвечал «invalid padding» — шли бы в padding oracle. Каждый режим задаёт своё дерево решений.

## Частые ошибки

- **Путать кодировку с шифрованием.** base64 — не защита; «взломать base64» обычно значит просто раскодировать.
- **Считать ECB «иногда нормальным».** ECB допустим только для одного блока или для данных без повторов; для сессий/токенов — всегда нет.
- **Забывать про padding.** В CBC/ECB последний блок добит PKCS#7; при расшифровке `0x01`/`0x02` в конце — это padding, а не данные.
- **Переиспользовать nonce/IV.** Самая частая и самая разрушительная ошибка CTR/GCM/OFB.
- **Доверять CBC без MAC.** Голый CBC изменяем; нужен encrypt-then-MAC или AEAD.
- **Сравнивать hex-строки вместо байтов.** Регистр hex и `=` могут «съесть» сравнение.

## Как не застрять

- **Первым делом детектируйте ECB.** 32 одинаковых байта на входе → смотрите повторы блоков.
- **Смотрите на длину.** Не кратна 16 → потоковый (CTR/OFB/CFB), скорее всего XOR с keystream.
- **Ищите IV/nonce в коде/задаче.** Переиспользование — самая частая дыра.
- **CBC → думайте про padding oracle и bit-flipping.**
- **CTR → думайте про many-time pad и crib-dragging.**
- **GCM → переиспользование nonce ломает всё (forbidden attack).**
- **Не путайте режим с алгоритмом.** AES в разных режимах — разные свойства.
- **Автоматизируйте рутину** скриптом на Python; ручной перебор 256 байт глазами не делают.

## Где пригодится

- **CTF** — база для ECB oracle, CBC bit-flip, padding oracle, IV reuse.
- **Web-пентест** — cookies/tokens, шифрованные параметры, «crypto» в приложениях.
- **TLS/протоколы** — понимание CBC/GCM, BEAST, Lucky13, padding oracle.
- **Разработка** — правильный выбор режима (GCM/OAEР) и уникальных nonce.
- **Forensics** — распознавание шифрования в дампах и трафике.
