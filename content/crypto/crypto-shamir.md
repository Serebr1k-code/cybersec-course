Разделение секрета (secret sharing) решает задачу, которую не решает обычное шифрование: как раздать «ключ» нескольким людям так, чтобы ни один в одиночку им не владел, но любая согласованная группа могла им воспользоваться. В CTF это регулярная категория задач: дают набор долей `(x_i, y_i)` и модуль, а восстановить нужно секрет. В этой главе — не только схема Шамира «из учебника», но и полный практический инструментарий: скрипты интерполяции, распознавание схемы, атаки на самодельные и небрежные реализации.

## Идея разделения секрета

**Пороговая схема `(k, n)`** — это схема, в которой секрет делится на `n` долей так, что:

- **любые `k` долей** однозначно восстанавливают секрет;
- **любые `k-1` долей** не дают о секрете *никакой* информации (информационно-теоретическая стойкость, не вычислительная).

Классическое применение: HSM и корневые ключи CA, мультисиг-кошельки (TSS), MPC-подписи, схемы disaster recovery. В отличие от «просто раздать части ключа по XOR», пороговая схема не деградирует постепенно: пока долей меньше `k`, пространство возможных секретов равномерно.

## Схема Шамира: полином и доли

Секрет `S` кодируется как **свободный член** полинома степени `k-1` над конечным полем `GF(p)` (обычно `p` — большое простое):

```
f(x) = S + a1·x + a2·x² + ... + a_{k-1}·x^{k-1}  (mod p)
```

Коэффициенты `a1..a_{k-1}` выбираются случайно. Доля `i` — это точка `(x_i, f(x_i))`, где `x_i` — публичные ненулевые метки (часто `1, 2, ..., n`). Секрет — это `f(0) = S`.

Ключевое свойство: полином степени `k-1` однозначно определяется любыми `k` точками (теорема о единственности интерполяционного полинома). Меньше `k` точек — бесконечно много полиномов через них, и значение в нуле может быть любым, то есть равновероятным.

## Восстановление: интерполяция Лагранжа

Формула Лагранжа даёт значение полинома в точке `x=0` (то есть секрет) напрямую, без восстановления всех коэффициентов:

```
S = Σ_i  y_i · Π_{j≠i} (0 - x_j) / (x_i - x_j)   (mod p)
```

Все деления — умножение на обратный элемент по модулю `p` (`pow(den, -1, p)` в Python 3.8+). Готовый скрипт без внешних зависимостей:

```python
def lagrange_at_zero(shares, p):
    """shares = [(x_i, y_i), ...]; ровно k штук. Возвращает f(0) mod p."""
    S = 0
    for i, (xi, yi) in enumerate(shares):
        num = den = 1
        for j, (xj, _) in enumerate(shares):
            if i == j:
                continue
            num = num * (-xj) % p
            den = den * (xi - xj) % p
        S = (S + yi * num * pow(den, -1, p)) % p
    return S
```

Для полного восстановления полинома (когда нужны `a_i`, а не только `S`) удобнее `sympy`/`sage`:

```python
from sage.all import PolynomialRing, GF
R = PolynomialRing(GF(p), 'x')
f = R.lagrange_polynomial(shares)   # shares = [(x_i,y_i),...]
S = int(f(0))
```

## Схемы Блэкли и CRT

- **Blakley** — доли это гиперплоскости в `k`-мерном пространстве, секрет — точка их пересечения. Геометрически наглядна, но требует больше памяти и плохо переносит «шумные» доли.
- **CRT-схема (Asmuth-Bloom)** — секрет восстанавливается по китайской теореме об остатках из остатков `S mod m_i`; порог достигается, когда произведение `k` наименьших модулей превосходит произведение `k-1` наибольших (условие `M > S·m_max`). Аналог `crypto-rsa-multi` и `crypto-crt-advanced`. Атака: если модули не попарно взаимно просты или произведение слишком мало — секрет достаётся меньшим числом долей.
- **XOR-схемы** — «самодельный Shamir»: `share_i = S XOR r_i`, все доли нужны одновременно. Порога нет; ломается, если один `r_i` утёк.

## Практика: инструменты и рецепты

- **Чистый Python** — функция `lagrange_at_zero` выше, для любого `p`. Работает и когда `p` не простое, если обратные элементы существуют (но тогда схема уже сломана).
- **Sage** — `R.lagrange_polynomial()`, `GF(p)`, решение линейных систем над полем; удобно для схем с матрицами (Blakley, линейные схемы).
- **sympy** — `sympy.interpolate` / `sympy.polys` для символьной интерполяции, если модуль не задан явно.
- **PyCryptodome** — `Crypto.Protocol.SecretSharing.Shamir` реализует схему Шамира «из коробки» (внутри GF(2^128)); полезно, когда задача — воспроизвести поведение библиотеки, а не ломать её.

```bash
pip install pycryptodome sympy
python3 - <<'EOF'
from Crypto.Protocol.SecretSharing import Shamir
shares = Shamir.split(3, 5, b'\x00'*16)   # (k=3, n=5), секрет 16 байт
secret = Shamir.combine(shares[:3])        # любые 3 доли
print(secret.hex())
EOF
```

## Разобранный пример: схема (3, 5)

Дано: `p` известен, пять долей, три из них «настоящие», две — шум (поддельные). Порог `k = 3`.

```python
p = 0x1ffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff
shares = [(1, 0x...), (2, 0x...), (3, 0x...), (7, 0x...), (11, 0x...)]

# 1) берём любые 3, считаем кандидата
cand = lagrange_at_zero(shares[:3], p)

# 2) проверяем кандидата на ВСЕХ долях: он должен лежать на полиноме
from itertools import combinations
for trio in combinations(shares, 3):
    S = lagrange_at_zero(trio, p)
    f = None  # строим полином по trio (sympy) и проверяем остальные доли
    # если все 5 долей согласованы — S верный

print(cand.to_bytes((cand.bit_length()+7)//8, 'big'))
```

Мораль: если долей больше `k` и среди них есть шум, **нельзя** брать первые попавшиеся `k`. Перебирайте комбинации и выбирайте ту, что согласована со всеми долями (или с большинством). Ошибка согласованности = не тот полином.

## Атаки на небрежные реализации

- **Малый модуль `p`.** Если `p` мал (или его легко факторизовать), секрет перебирается по одному `y_i`, либо система решается по меньшему числу долей.
- **Повторное использование коэффициентов.** Если сервер разделил *разные* секреты с одним и тем же `a1` (или всеми `a_i`), вычитание полиномов даёт `S1 - S2` — секреты восстанавливаются по XOR/разности.
- **Недостаток долей + структура.** Когда `k-1` долей, но известен, что секрет — ASCII-флаг или лежит в узком диапазоне, возможен перебор свободного члена.
- **Линейные/самодельные схемы.** `share_i = S + r_i mod p` без случайных `a_i` — секрет восстанавливается вычитанием. `share_i = S XOR r_i` — прямая линейная утечка.
- **Утечка промежуточных значений.** Если сервер логирует `a_i` или `f(x)` для известных `x`, добавьте точки и решайте систему.
- **Малые `x_i`.** Доли с `x = 1, 2, 3` и малым `p` часто дают переполнение/усечение в наивной реализации — проверяйте целочисленную арифметику без модуля.
- **Отрицательные/неприведённые `y_i`.** Реализация без `% p` может «слить» секрет при интерполяции в целых числах (без модуля).

## Частые ошибки и тупики

- **Неверный `p`.** Модуль должен быть простым и строго больше секрета; если `S ≥ p`, восстановится `S mod p`.
- **Меньше `k` долей.** Секрет не определён однозначно — не тратьте время на «магию».
- **Путаница `S` и `f(0)`.** Секрет — именно `f(0)`; свободный член, а не сумма долей.
- **Ошибки знаков.** `(-xj)` и `(xi - xj)` считайте строго по модулю: в Python отрицательное `% p` корректно, но в C/Go — нет.
- **Игнорирование лишних долей.** Всегда проверяйте кандидата на согласованность со всеми долями.
- **Порядок `x`.** `x_i` должны быть различны; дубликат `x` ломает интерполяцию (деление на ноль).

## Что дальше (decision)

1. Даны доли и `p` → стройте `lagrange_at_zero`, восстановите `f(0)`, декодируйте в байты.
2. Долей больше `k` → перебирайте комбинации, отбирайте согласованную.
3. Схема не Шамира (CRT/Blakley/линейная) → распознайте по структуре долей и решайте соответственно (`crypto-crt-advanced`).
4. Есть `k-1` долей, но секрет в узком диапазоне → перебор + проверка по известному формату флага.
5. Схема используется для подписи (TSS) → смотрите на nonce: переиспользование `k` в TSS ломает ключ как в `crypto-ecdsa-nonce`.

## Справочная таблица

| Схема | Основа | Порог | Типичная атака |
|-------|--------|:-----:|----------------|
| Shamir | полином над `GF(p)` | любые `k` | малый `p`, повтор `a_i`, `k-1` + перебор |
| Blakley | гиперплоскости | любые `k` | вырожденные плоскости, утечка уравнений |
| CRT/Asmuth-Bloom | китайская теорема | произведение модулей | малые/не взаимно простые модули |
| XOR | побитовое сложение | все `n` | утечка любого `r_i` |

## Где пригодится

- **CTF (medium):** восстановление секрета по долям, атаки на «самодельный Shamir».
- **Blockchain:** TSS-кошельки, MPC-подписи, пороговое хранение seed-фраз.
- **Аудит HSM/CA:** корректность пороговых схем защиты корневых ключей.
- **Работа:** резервное копирование ключей, disaster recovery, разделение мастер-паролей.
- **Крипто-разработка:** правильный выбор `p`, `k`, источников случайности для `a_i`.
