## Вопрос, с которого всё начинается

Есть секрет — например, ключ, дающий доступ к казне. Его нельзя доверить одному
человеку (украдут или потеряет), но и «разрезать пополам по XOR» плохо: тогда
любая половина даёт половину информации, а две половины — весь ключ. Хочется
схему, где **любые `k` долей** восстанавливают секрет, а **любые `k-1`** не дают
вообще ничего.

Такую схему придумал Шамир. Разберём её и восстановим секрет из долей на реальном
примере.

## Шаг 1: идея пороговой схемы

**Пороговая схема `(k, n)`** делит секрет на `n` долей так, что:

- любые `k` долей однозначно восстанавливают секрет;
- любые `k−1` долей не дают о нём **никакой** информации (стойкость
  информационно-теоретическая, не вычислительная).

Это используют HSM и корневые ключи CA, мультисиг-кошельки (TSS), MPC-подписи,
disaster recovery. В отличие от «раздать части ключа по XOR», здесь нет
постепенной деградации: пока долей меньше `k`, пространство секретов равномерно.

## Шаг 2: полином и доли

Секрет `S` кодируется как **свободный член** полинома степени `k−1` над конечным
полем `GF(p)`:

```
f(x) = S + a1·x + a2·x² + ... + a_{k-1}·x^{k-1}   (mod p)
```

Коэффициенты `a1..a_{k-1}` выбираются случайно. Доля `i` — это точка
`(x_i, f(x_i))`, где `x_i` — публичные ненулевые метки (обычно `1..n`). Секрет —
это `f(0) = S`.

Почему это работает: полином степени `k−1` однозначно определяется любыми `k`
точками (теорема о единственности интерполяционного полинома). Меньше `k` точек —
через них проходит бесконечно много полиномов, и значение в нуле может быть любым,
то есть равновероятным.

## Шаг 3: интерполяция Лагранжа

Формула Лагранжа даёт значение полинома сразу в точке `x = 0`, без восстановления
коэффициентов:

```
S = Σ_i  y_i · Π_{j≠i} (0 − x_j) / (x_i − x_j)   (mod p)
```

Все деления — умножение на обратный элемент по модулю `p` (`pow(den, -1, p)`):

```python
def lagrange_at_zero(shares):
    S = 0
    for i, (xi, yi) in enumerate(shares):
        num = den = 1
        for j, (xj, _) in enumerate(shares):
            if i == j: continue
            num = num * (-xj) % p
            den = den * (xi - xj) % p
        S = (S + yi * num * pow(den, -1, p)) % p
    return S
```

## Полный прогон от начала до конца

```
$ python3 shamir_demo.py
восстановлено по долям 1,2,3: b'flag{shamir_threshold_3of5}'
```

Трёх долей хватило, чтобы точно восстановить секрет. Заметь: с долями 1, 2 и 3
работает так же, как с любыми другими тремя — пороговая схема симметрична
относительно выбора долей.

## Атаки на небрежные реализации

Пороговая схема стойка **математически**, но реализации часто ломают её:

- **Малый модуль `p`.** Если `p` мал или легко факторизуется, секрет перебирается
  по одному `y_i` либо система решается по меньшему числу долей.
- **Повторное использование коэффициентов.** Если сервер разделил *разные* секреты
  с одними и теми же `a_i`, вычитание полиномов даёт `S1 − S2` — разность секретов
  восстанавливается без долей. Проверим:

```
$ python3 shamir_demo.py
атака повторных коэффициентов:
  S1 - S2 = 57896044618658097711785492504343952795556363998049526920280356926480290086637
  проверка: (s1-s2) mod p = 57896044618658097711785492504343952795556363998049526920280356926480290086637
  совпало: True
```

(Значение `S1 − S2` совпало с истинным.) Зная формат одного секрета, второй легко
вывести.

- **Лишние доли с шумом.** Если долей больше `k` и среди них есть поддельные,
  **нельзя** брать первые попавшиеся `k`. Нужно перебирать тройки и выбирать
  максимально согласованную:

```
согласованность троек (сколько из 5 долей лежат на полиноме):
   ((1, ...), (2, ...), (3, ...)) -> согласовано 4 из 5
   ((1, ...), (2, ...), (6, 3735928559)) -> согласовано 3 из 5
   ...
лучшая тройка согласована с 4 долями -> S = b'flag{shamir_threshold_3of5}'
```

Правильная тройка согласуется с 4 долями из 5, а тройка с подделкой — только с 3.

- **Утечка промежуточных значений.** Если сервер логирует `a_i` или `f(x)` для
  известных `x`, добавьте точки и решайте систему.
- **`k−1` долей + узкий диапазон.** Если секрет — ASCII-флаг, свободный член
  перебирается по формату.

## Варианты схем

| Схема | Основа | Порог | Типичная атака |
|-------|--------|:-----:|----------------|
| Shamir | полином над `GF(p)` | любые `k` | малый `p`, повтор `a_i`, `k−1` + перебор |
| Blakley | гиперплоскости | любые `k` | вырожденные плоскости, утечка уравнений |
| CRT/Asmuth-Bloom | китайская теорема | произведение модулей | малые/не взаимно простые модули |
| XOR | побитовое сложение | все `n` | утечка любого `r_i` |

## Инструменты и порядок действий

- **Чистый Python** — функция `lagrange_at_zero` выше, для любого `p`; работает и
  когда `p` не простое, если обратные элементы существуют (но тогда схема уже
  сломана).
- **Sage** — `R.lagrange_polynomial()` и `GF(p)` удобны для схем с матрицами
  (Blakley, линейные схемы).
- **PyCryptodome** — `Crypto.Protocol.SecretSharing.Shamir` реализует схему «из
  коробки» (внутри GF(2^128)); полезно, когда надо воспроизвести поведение
  библиотеки.

Порядок в задаче: распознайте схему по структуре долей → найдите модуль `p` →
постройте `lagrange_at_zero` → проверьте кандидата на согласованность со всеми
долями → декодируйте число в байты.

## Что мы теперь знаем

- Пороговая схема `(k, n)`: любые `k` долей восстанавливают секрет, `k−1` — нет.
- Секрет — свободный член полинома степени `k−1`; доли — точки на нём.
- Интерполяция Лагранжа даёт `f(0)` напрямую по `k` долям.
- Схема стойка математически, но ломается реализацией: малый `p`, повтор
  коэффициентов, лишние доли, утечки.
- Если долей больше `k` — отбирайте согласованную комбинацию, а не первые попавшиеся.

## Куда дальше

Мы научились восстанавливать секрет по долям. Дальше ветвь crypto идёт в реальные
протоколы: `crypto-tls-attacks` (TLS, Heartbleed, POODLE) и `crypto-real-world`.
А главное запомни: **пороговая схема стойка, но проверяйте модуль, коэффициенты и
лишние доли — именно там ломаются самодельные реализации**.

## Где пригодится

- **CTF (medium)** — восстановление секрета по долям, атаки на «самодельный Shamir».
- **Blockchain** — TSS-кошельки, MPC-подписи, пороговое хранение seed-фраз.
- **Аудит HSM/CA** — корректность пороговых схем защиты корневых ключей.
- **Работа** — резервное копирование ключей, disaster recovery, разделение паролей.
- **Крипто-разработка** — правильный выбор `p`, `k`, источника случайности для `a_i`.
