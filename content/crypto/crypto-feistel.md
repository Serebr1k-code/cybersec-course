## Вопрос, с которого всё начинается

В CTF часто попадается «самодельный блочный шифр»: половина задачи — понять, как он устроен, и только потом ломать. Многие такие шифры построены на **Feistel-сети** — конструкции, которая делает шифр обратимым, даже если его внутренняя функция необратима. Разберём, почему это работает, и покажем, как восстановить ключ редуцированного Feistel.

## Наш пример

Возьмём простейший Feistel из одного раунда с round-функцией `F(R, K) = R XOR K`. Зашифруем блок и посмотрим на результат:

```python
def feistel_enc(block, keys, F, half=32):
    mask = (1 << half) - 1
    L, R = block >> half, block & mask
    for K in keys:
        L, R = R, (L ^ F(R, K)) & mask
    return (L << half) | R

F = lambda R, K: (R ^ K)
L0, R0, K = 0x12345678, 0x9abcdef0, 0xdeadbeef
P = (L0 << 32) | R0
C = feistel_enc(P, [K], F)
print("C = %08x" % C)
```

```
C = 9abcdef056253667
```

Вопрос: зная `P` и `C`, можно ли восстановить ключ `K`?

## Шаг 1: как устроен раунд

Блок делится на две половины `(L, R)`. Каждый раунд:

```
L_{i+1} = R_i
R_{i+1} = L_i XOR F(R_i, K_i)
```

где `F` — произвольная функция (может быть необратимой), `K_i` — раундовый ключ. Обратимость достигается тем, что раунд обратен сам себе, если применить ключи в обратном порядке:

```
L_i = R_{i+1} XOR F(L_{i+1}, K_i)
R_i = L_{i+1}
```

Именно поэтому Feistel не требует обратимой `F`: половина просто переставляется, а изменение «защищено» XOR-ом. DES устроен так же; AES — нет, он использует SPN, где каждый слой обязан быть обратимым.

## Шаг 2: восстанавливаем ключ из одной пары

Для одного раунда:

```
C = (L1, R1) = (R0, L0 XOR R0 XOR K)
```

Значит, ключ выражается напрямую:

```python
L1, R1 = C >> 32, C & 0xffffffff
print("recovered K = %08x" % (L0 ^ R0 ^ R1))
```

```
recovered K = deadbeef
```

Ключ восстановлен из **одной** пары `(P, C)`. Для 2–4 раундов так уже не получится — промежуточные значения неизвестны, и нужен другой подход.

## Шаг 3: редуцированные раунды и Z3

Если раунды содержат сложение и сдвиги (так называемая ARX-структура: Addition, Rotation, XOR), вручную выразить ключ трудно, зато справляется SMT-решатель **Z3**. Идея — описать раунды символическими битовыми векторами и потребовать, чтобы шифрование известных пар дало известные шифротексты:

```python
from z3 import BitVec, BitVecVal, Solver, sat
Ks = [BitVec(f'k{i}', 32) for i in range(4)]
s = Solver()
def enc(l0, r0):
    L, R = l0, r0
    for K in Ks:
        L, R = R, L ^ ((R << 3) ^ K)
    return L, R
# для каждой известной пары (p, c): s.add(enc(...) == c)
```

Важная тонкость: **числа пар должно хватать**. На одной-двух парах система может оказаться недоопределённой, и Z3 выдаст *эквивалентный* набор ключей, который тоже переводит `P` в `C`. Поэтому кандидатов проверяют на дополнительных парах. Для чисто линейных Feistel (без S-box) быстрее решить систему над GF(2) методом Гаусса — см. `crypto-finite-fields`.

## Шаг 4: DES и key schedule

DES — 16-раундовая Feistel-сеть над 64-битным блоком (56 реальных бит ключа + 8 бит чётности):

- **F** = расширение `E` (32→48 бит), XOR с `K_i`, восемь S-box (6→4 бита), перестановка `P`.
- **Key schedule:** из ключа выбором бит (PC-1) получают 56 бит, делят на `C, D` по 28, циклически сдвигают на 1–2 бита по раунду и через PC-2 получают `K_i`.

Единственный нелинейный элемент — S-box. Именно он делает DES стойким к линейному и дифференциальному анализу при полных 16 раундах. А вот редуцированные версии (меньше раундов) — излюбленная цель CTF.

## Шаг 5: атаки на Feistel

- **Редуцированные раунды.** 1–4 раунда ломаются напрямую: выражаем половины через вход, выход и ключи.
- **Slide attack.** Если раундовые ключи одинаковы (расписание «зациклилось»), шифр распадается на «сдвинутые» копии, и атака находит ключ по парам. Защита — различающиеся `K_i`.
- **Differential/linear cryptanalysis.** Работают по статистике S-box; на полном DES нужно ~`2^43`–`2^47` пар, на редуцированном — намного меньше.
- **MITM на два раунда.** См. `crypto-mitm`.
- **Related-key attacks.** Если `F` зависит от ключа предсказуемо.

## Шаг 6: как распознать самодельный Feistel

Типовые условия и первые ходы:

- «Шифр на 4 раундах» → инверсия раундов и подбор `K_i` по парам.
- «Round-функция — XOR с ключом» → линейно, ключ через Гаусс над GF(2).
- «Round-функция — `(x + K) mod 2^32`» → ARX, ломается Z3.
- «Ключи повторяются» → slide attack.
- «Дана возможность шифровать/расшифровать произвольное» → оракул плюс дифференциалы.

## Шаг 7: варианты конструкции

Feistel — целое семейство. **Unbalanced Feistel** использует половины разной длины (на нём строят Format-Preserving Encryption, FF1/FF3). **Generalized Feistel** имеет `k` ветвей вместо двух (CAST, CLEFIA). Есть и Type-1/2/3 — разные способы перемешивания ветвей. Важно не путать Feistel со **SPN** (AES): там обратимость каждого слоя обязательна, и атаки другие (differential, integral).

| Свойство | Feistel | SPN (AES) |
|----------|---------|-----------|
| Обратимость `F` | не нужна | обязательна |
| Раунд | половина + `F` | полный блок |
| Пример | DES, 3DES, Blowfish | AES, PRESENT |
| Атаки | slide, differential, MITM | differential, integral |

## Что мы теперь знаем

- Feistel делает шифр обратимым, **не требуя** обратимой round-функции.
- Раунд обратен сам себе при обратном порядке ключей.
- 1-раундовый линейный Feistel восстанавливается из **одной** пары.
- Для ARX-раундов удобен Z3, но пар должно хватать — иначе получите эквивалентный ключ.
- DES — 16-раундовый Feistel; нелинейность даёт S-box.
- Повторяющиеся ключи открывают slide attack.

## На что смотреть дальше

- **Забыть порядок ключей** при расшифровании — нужен `reversed(keys)`.
- **Перепутать L и R** — классическая ошибка: `L_{i+1} = R_i`, а не наоборот.
- **Пытаться инвертировать round-функцию** — Feistel работает и с необратимой `F`.
- **Не заметить повтор ключей** — slide attack останется незамеченной.
- **Игнорировать S-box** — если он слабый, работают differential/linear, а не перебор.
- **Забыть маску половины** — без `& mask` ARX-раунд «уезжает» за 32 бита.
