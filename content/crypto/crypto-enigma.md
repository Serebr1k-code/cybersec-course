## Вопрос, с которого всё начинается

Enigma — немецкая шифровальная машина Второй мировой, и её взлом в Блетчли-Парке — самый известный эпизод криптоанализа в истории. В CTF она встречается в двух видах: либо нужно **реализовать** машину и расшифровать сообщение по известным настройкам, либо нужно **взломать** её по угаданному фрагменту текста. Вопрос новичка: «Если пространство ключей огромное, почему машину вообще смогли сломать?» Ответ — в одной структурной детали.

## Наш пример

У нас есть Enigma с роторами `I`, `II`, `III`, отражателем `B`, начальными позициями `AAA` и без коммутационной панели. Мы зашифруем этой машиной фразу `ATTACKATDAWN`, посмотрим на результат, расшифруем обратно — и на этом же примере найдём ту самую слабость.

## Шаг 1: из чего состоит машина

Enigma собирается из четырёх частей, и каждую стоит понять отдельно.

**Роторы** — диски с перепутанной проводкой: буква на входе выходит другой буквой на выходе. Возьмём три ротора `I`, `II`, `III` (их взаимная подстановка — фиксированные таблицы). После каждой нажатой клавиши правый ротор поворачивается на шаг, иногда увлекая соседний — как одометр.

**Отражатель** (`reflector`) замыкает цепь: сигнал, дойдя до него, разворачивается и идёт через те же роторы обратно. Именно он делает машину самообратной.

**Коммутационная панель** (`plugboard`) попарно меняет буквы местами до входа в роторы и после выхода. В нашей машине она пустая — это упростит разбор, но не изменит суть.

Путь одной буквы: `plugboard → ротор I → II → III → отражатель → III → II → I → plugboard → лампа`.

## Шаг 2: почему Enigma обратима

Заметьте: сигнал проходит один и тот же путь «туда и обратно», а отражатель — это **инволюция**, то есть перестановка, обратная самой себе. Отсюда два следствия.

Первое: `E(E(m)) = m`. Если зашифровать текст, а потом зашифровать шифротекст **на той же машине с теми же настройками**, получится исходный текст. Расшифровка — это не отдельная операция, а то же самое шифрование.

Второе следствие — роковое: **буква никогда не шифруется в саму себя**. Проверим на всей азбуке:

```
A -> F      B -> U      ...      any letter maps to itself? False
```

Ни одна буква не остаётся на месте. Для конструкторов это казалось безобидным свойством, но именно оно и погубило Enigma.

## Шаг 3: шифруем нашу фразу

Соберём эмулятор — ключевой метод `enc` реализует путь сигнала, а `_step` — поворот роторов с «двойным шагом» (в определённый момент средний ротор прокручивается дважды; без этого длинные тексты расшифруются неверно).

```python
m = Enigma(['I','II','III'], "AAA", "AAA", [])
ct = "".join(m.enc(c) for c in "ATTACKATDAWN")
print(ct)
```

```
FAEMDMSPQPTO
```

Проверим обратимость: заведём новую машину с теми же настройками и «зашифруем» шифротекст.

```python
m2 = Enigma(['I','II','III'], "AAA", "AAA", [])
print("".join(m2.enc(c) for c in ct))
```

```
ATTACKATDAWN
```

Сработало. Но обратите внимание: чтобы расшифровать, надо знать **все** настройки — порядок роторов, их начальные позиции, кольца и панель. Без них мы имеем только `FAEMDMSPQPTO`.

## Шаг 4: главная слабость — буква не в себя

Теперь представим, что настройки неизвестны, но мы догадываемся о содержании. Немецкие радисты каждое утро передавали прогноз погоды словом `WETTER` («погода»). Такая догадка о фрагменте открытого текста называется **crib**.

Возьмём перехват `OZZMXYLATDYXHGJI` и попробуем приложить crib `WETTER` в разные позиции. Работает простое правило: если на позиции `i` crib содержит букву `X`, то в шифротексте на позиции `i` буквы `X` быть **не может** (свойство «не в себя»). Такие позиции сразу отбрасываются.

```python
def crib_check(ct, crib, off):
    for i, ch in enumerate(crib):
        if ct[off + i] == ch:
            return False        # буква зашифровалась в себя -> невозможно
    return True

print([o for o in range(len(ct)-len(crib)+1) if crib_check(ct, crib, o)])
```

```
[0, 1, 2, 3, 4, 7, 8, 9, 10]
```

Из 11 позиций десять выжили — проверка `WETTER` сама по себе отсеивает мало. Зато она **дёшева**: перебор по позициям роторов (`26³ = 17576`) с такой проверкой на каждой конфигурации становится выполнимым. Именно это и делала **Bombe** — электромеханическая машина Тьюринга: она проверяла логические цепочки совпадений и отбрасывала заведомо неверные установки, не перебирая ключи слепо.

## Шаг 5: сколько же всего ключей

Чтобы понять масштаб, посчитаем пространство:

- выбор и порядок трёх роторов из пяти: `5·4·3 = 60`;
- начальные позиции: `26³ = 17576`;
- кольцевые установки (`ring settings`): `26³ = 17576`;
- коммутационная панель (10 пар из 26): порядка `1.5·10¹⁴`.

Полное произведение — около `1.6·10²⁰`. Перебрать это «в лоб» нереально даже сегодня. Ломает машину не сила, а структура: свойство «не в себя» + crib отсекают почти всё, а оставшиеся варианты проверяются на реальной машине. В CTF чаще всего вам дают **часть** настроек, и задача сводится к перебору оставшихся (`26³` позиций — секунды работы скрипта).

## Шаг 6: инструменты и как не застрять

Реализовать машину вручную полезно один раз — чтобы понять механику. Дальше берите готовое:

```bash
$ pip install py-enigma
$ python3 -c "from enigma.machine import EnigmaMachine; \
m = EnigmaMachine.from_key_sheet(rotors='I II III', reflector='B', \
    ring_settings='A A A', plugboard_settings='AV BS CG DL FU HZ IN KM OW RX'); \
print(m.process_text('HELLO'))"
```

Чек-лист при разборе задачи. Уточните модель: сколько роторов, какой отражатель, есть ли plugboard. Не перепутайте **ring setting** (сдвиг проводки ротора) с **начальной позицией** (текущий угол поворота) — это разные параметры, и оба входят в ключ. Помните про двойной шаг, иначе длинный текст расшифруется неверно. Ищите crib: стандартные фразы, известный формат флага, приветствие. Применяйте «буква не в себя» для отсева вариантов и перебирайте позиции `26³` — это секунды работы скрипта. Если дана лишь часть настроек, перебирайте только оставшиеся, а не всё пространство `~1.6·10²⁰`.

## Что мы теперь знаем

- Enigma = роторы + отражатель + коммутационная панель; роторы вращаются как одометр.
- Отражатель делает машину **самообратной**: расшифровка = шифрование с теми же настройками.
- Следствие отражателя — **буква не шифруется в себя**; это главная уязвимость.
- **Crib** — угаданный фрагмент открытого текста; им отсеивают неверные позиции.
- Полный перебор `~1.6·10²⁰` невозможен, но `26³` позиций роторов — вполне.
- Не забывайте «двойной шаг» роторов, иначе длинные тексты расшифруются неверно.

## Куда дальше

Мы увидели, как **структурная слабость** убивает машину с огромным пространством ключей. Дальше — принципиально другой полюс криптографии: в уроке **crypto-xor-otp** мы возьмём шифр, который при честном использовании не ломается вообще (одноразовый блокнот), и увидим, что именно его «честность» нарушают на практике. А пока главное: **Enigma ломает не перебор, а свойство отражателя — «буква не в себя».**

## Где пригодится

- **CTF crypto/forensics:** задачи с историческими шифрмашинами и «машиной, которую надо реализовать».
- **История криптоанализа:** понимание crib-атак, важных и сегодня (known-plaintext в протоколах).
- **Образование:** наглядный пример, почему «сложная машина» не равно «стойкий шифр».
- **Работа (SOC/IR):** распознавание нестандартной обфускации.
- **Исследования:** изучение роторных систем и атак на них (Bombe, M4).
