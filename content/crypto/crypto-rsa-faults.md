RSA-CRT-подпись ускоряет вычисления вдвое, но ценой хрупкости: **одна ошибка** в одном из двух модульных возведений выдаёт факторизацию модуля `n`. Это атака Bellcore (Boneh-DeMillo-Lipton): `gcd` между «правильной» и «ошибочной» подписью мгновенно даёт `p` или `q`. В CTF это задачи «даны подписи, одна из них испорчена», а в реальности — атаки через сбой питания, клока или лазера на смарт-карты.

## Модель: ошибка при подписи

Атакующий не знает приватный ключ, но может вызвать **сбой** в момент вычисления подписи. Если ошибка попадёт в одно из промежуточных значений (например, в `m^{d_p} mod p`), подпись станет неверной — и по ней восстанавливается ключ. Сбои инжектируют:

- провалом питания (voltage glitch);
- сбоем клока;
- лазером/EM-импульсом;
- программно — если есть уязвимость, портящая вычисление.

## Bellcore-атака (CRT)

RSA-CRT:

```
d_p = d mod (p-1),  d_q = d mod (q-1),  q_inv = q^{-1} mod p
m_p = c^{d_p} mod p
m_q = c^{d_q} mod q
s = m_q + q·(q_inv·(m_p - m_q) mod p)     # mod n
```

Пусть в `m_p` (или `m_q`) произошла ошибка: `m_p' = m_p + Δ`. Тогда:

```
s' = m_q + q·(q_inv·(m_p' - m_q) mod p)   # неверная подпись
s'^e ≠ c (mod n),  но  s'^e ≡ c (mod q)
```

Следовательно, `s'^e - c` делится на `q`, но не на `p`. Значит:

```
gcd(s'^e - c mod n, n) = q      (или p)
```

**Одна** ошибочная подпись и соответствующее сообщение дают факторизацию. После — `p = n/q`, и весь ключ восстановлен.

## Формулы и GCD

```python
from math import gcd
def factor_from_faulty_signature(n, e, c, s_faulty):
    # s_faulty — подпись, вычисленная с ошибкой
    g = gcd(pow(s_faulty, e, n) - c, n)
    if 1 < g < n:
        return g, n // g
    return None
```

Проверка: `g` — простое, `n % g == 0`. Если `gcd` вернул `n` или `1` — ошибка не «односторонняя» (например, обе половины испорчены).

## Single-fault и multi-fault

- **Single-fault (классика):** ровно одна из `m_p`/`m_q` испорчена → GCD даёт множитель.
- **Обе испорчены:** GCD = 1 или n — атака не проходит.
- **Несколько ошибочных подписей:** каждая даёт кандидата; пересечение подтверждает.
- **Ошибка в `q_inv`/рекомбинации:** может дать тот же эффект — проверяйте все `gcd` с `n`.
- **Fault в key generation:** может сделать `n` факторизуемым (`crypto-rsa-factorization`).

## Практика инъекции сбоя

- **Аппаратно:** ChipWhisperer (voltage/clock glitch), лазер, EM-импульс.
- **Программно:** если сервис подписывает «испорченным» кодом (например, округление, переполнение, race).
- **CTF:** обычно дают `(n, e, c, s)` с известной ошибочной подписью и подсказкой «одна из подписей неверна».
- **Обнаружение:** проверьте `pow(s, e, n) == c` для каждой подписи; неверная — цель.

## Разобранный пример

Дано: `n`, `e=65537`, сообщение `c`, и подпись `s`, где сервер (по условию) допустил ошибку в CRT.

1. Проверяем: `pow(s, e, n) != c` — подпись действительно ошибочна.
2. `g = gcd(pow(s, e, n) - c, n)` → `q`.
3. `p = n // q`; `phi = (p-1)(q-1)`; `d = pow(e, -1, phi)`.
4. Восстанавливаем `m = pow(c, d, n)`; декодируем флаг.

Мораль: ошибка в одном модульном возведении «протекает» через тот множитель, который не был испорчен.

## Варианты и родственные атаки

- **Boneh-DeMillo-Lipton** — общая теория: сбой в любой реализации с проверкой даёт факторизацию.
- **Подпись с ошибкой в `d`** — если `d` испорчен, GCD может дать множитель `n`.
- **`e` слишком мал** и подпись неверна — см. `crypto-rsa-small-e-hastad`.
- **Fault в RSA-OAEP/padding** — может дать Bleichenbacher-подобный оракул (`crypto-rsa-bleichenbacher`).
- **Fault + partial key** — комбинируется с `crypto-rsa-partial-key`.

## Частые ошибки и тупики

- **Не проверить, какая подпись ошибочна.** GCD по верной подписи даст `n`.
- **Использовать `s^e - c` без `mod n`.** Вычисляйте `pow(s, e, n) - c`, затем `gcd(..., n)`.
- **Обе половины испорчены.** Тогда GCD = 1; ищите другую пару.
- **Путать `d` и `d_p`.** Ошибка в `d_p` даёт множитель, в `d` — иногда тоже, но иначе.
- **Считать, что нужен полный сбой.** Достаточно односторонней ошибки.
- **Игнорировать CTF-подсказку.** «Подпись с ошибкой» — почти всегда Bellcore.

## Что дальше (decision)

1. Есть подпись, не проходящая проверку → Bellcore через GCD.
2. Несколько подписей → перебирайте на «ошибочность».
3. GCD = n/1 → обе половины испорчены, ищите другую пару.
4. Ошибка в `d`/`e` → проверьте related-key/partial-key атаки.
5. Аппаратный доступ → инъекция сбоя (ChipWhisperer).
6. Нужна защита → верификация подписи перед выдачей, счётчики, redundancy.

## Справочная таблица

| Сбой | Что ломает | Метод |
|------|-----------|-------|
| ошибка в `m_p`/`m_q` | факторизация `n` | `gcd(s^e - c, n)` |
| ошибка в `d_p` | множитель | GCD/перебор |
| обе половины | ничего | — |
| fault + padding | оракул | Bleichenbacher |

## Полный разбор: Bellcore на нескольких подписях

На практике дают пачку подписей `s_i` для сообщений `c_i`, и лишь одна из них «сломана» (или несколько). Алгоритм:

```python
from math import gcd
def try_factor(n, e, pairs):
    # pairs = [(c_i, s_i), ...]
    for c, s in pairs:
        if pow(s, e, n) == c:
            continue                      # подпись валидна
        g = gcd(pow(s, e, n) - c, n)
        if 1 < g < n:
            return g, n // g
    return None

p, q = try_factor(n, e, pairs)
d = pow(e, -1, (p-1)*(q-1))
m = pow(c, d, n)
print(bytes.fromhex(hex(m)[2:]))
```

Если `gcd` вернул `1` или `n` — сбой был «двусторонним» (испорчены обе половины) или подпись валидна. Перебирайте все подписи: в CTF часто лишь одна из многих ошибочна. Второй частый вариант — **ошибка в `dp`/`dq`** (не в `m_p`): тогда GCD даёт множитель через другое соотношение, но техника та же — ищите `gcd(что-то, n)`.

## Чек-лист: fault-задача

- даны подписи, одна из которых **не проходит** `pow(s, e, n) == c`;
- в условии «подпись с ошибкой», «faulty signature», «glitch»;
- доступен оракул подписи, и можно «сбоить»;
- несколько подписей одного/разных сообщений;
- рядом с подписью — «сообщение не совпадает».

Быстрая проверка: прогоните все подписи через `pow(s, e, n) == c`; для неверной возьмите `gcd(pow(s,e,n)-c, n)`. Если GCD даёт простой множитель — задача решена.

## Быстрые рецепты для CTF

- **Одна подпись не проходит проверку** → `gcd(pow(s,e,n)-c, n)`.
- **Несколько подписей** → переберите все на «ошибочность».
- **GCD = 1 или n** → обе половины испорчены, ищите другую пару.
- **Ошибка в `dp`** → другой GCD, та же идея.
- **Аппаратный доступ** → инъекция сбоя (ChipWhisperer).
