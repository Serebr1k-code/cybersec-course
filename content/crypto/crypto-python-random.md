Модуль `random` в Python — не криптографически стойкий генератор. Внутри это Mersenne Twister (MT19937), и по 624 последовательным 32-битным выходам его состояние восстанавливается полностью, после чего можно предсказать **все** будущие значения. На CTF это один из самых частых «лёгких» способов обойти генерацию токенов, паролей сброса, OTP и игровых последовательностей. Здесь — практика: как собрать нужные значения, как восстановить состояние и seed, и какие ловушки поджидают.

## Устройство: почему это ломается

MT19937 хранит состояние из **624 32-битных слов** (плюс индекс). Каждый выход проходит через «темперирование» — обратимое линейное преобразование над GF(2). Значит:

- **624 подряд идущих 32-битных выхода** → состояние восстанавливается однозначно (untemper + инверсия рекурсии).
- **Меньше 624** → недоопределено, но при частичных наблюдениях помогает Z3 (`crypto-mt19937-deep`).
- **Seed** — 32-битный (или от `os.urandom`, если не задан), поэтому по одному-двум выходам seed перебирается за секунды.

Python-специфика: `random.random()` возвращает 53-битное число, склеенное из **двух** 32-битных выходов (27 и 26 бит), а `randint`/`getrandbits` маскируют выходы — это усложняет сбор ровно 624 полных слов.

## Сбор выходов

Что именно собирать, зависит от того, как приложение использует `random`:

| Примитив | Что даёт | Сколько нужно |
|----------|----------|---------------|
| `getrandbits(32)` | полное 32-битное слово | 624 |
| `random()` | 53 бита (2 слова: 27+26) | ~1250 вызовов |
| `randint(a,b)` | усечённый диапазон | больше 624 |
| `random.randbytes(n)` | `n` байт из слов | 2496 байт |
| `choice`/`shuffle` | индексы | восстанавливается сложнее |

Для `getrandbits(32)` всё просто. Для `random()` нужно разложить каждое значение: `x * 2**53` → верхние 27 бит и нижние 26 бит — два последовательных выхода MT.

## Инструменты и команды

- **randcrack** — восстановление по 624 значениям `getrandbits(32)`.
- **Z3** — восстановление при частичных выходах (см. `crypto-mt19937-deep`).
- **Собственный untemper** — когда нужен полный контроль.
- **`python-random-predict`** / готовые скрипты — для `random()`/`randint`.

```python
from randcrack import RandCrack
rc = RandCrack()
for _ in range(624):
    rc.submit(next_output_32())   # ровно 32-битные значения
print(rc.predict_getrandbits(32))
print(rc.predict_randint(0, 2**32-1))
print(rc.predict_random())        # следующий random()
```

Важно: `RandCrack.submit` принимает **32-битные** значения; если у вас `random()` или `randint`, их нужно предварительно «распаковать».

## Разобранный пример: токен сброса пароля

Сервер генерирует токен так:

```python
import random
def reset_token():
    return ''.join(random.choice('0123456789abcdef') for _ in range(32))
```

`choice` по 16 символам = `randbelow(16)` = 4 бита на символ. Токен из 32 символов = 128 бит энтропии, но **seed** всего 32-битный, а состояние — 19968 бит. Классический ход CTF: получить несколько токенов **после** известного seed (или при фиксированном seed) и предсказать следующий.

Если seed фиксирован (например, `random.seed(int(time.time()))` в момент старта), перебираем окно времени:

```python
import random, time
known = "3f9a..."            # известный токен
for t in range(start, end):
    random.seed(t)
    if ''.join(random.choice('0123456789abcdef') for _ in range(32)) == known:
        print("seed =", t)
        # теперь предсказываем СЛЕДУЮЩИЙ токен
        print(''.join(random.choice('0123456789abcdef') for _ in range(32)))
        break
```

Если seed от `os.urandom` (неизвестен) — остаётся путь через 624 выхода: соберите 624 значения `getrandbits(32)` (например, сервис отдаёт 32-битные «случайные» ID), скормите в `RandCrack`, предскажите следующие.

## Восстановление seed по одному выходу

Если приложение печатает **один** 32-битный выход (например, `random.getrandbits(32)` в ответе), seed (32 бита) перебирается полным пространством за минуты на CPU. Прямая атака:

```python
import random
target = 0x8f3a1c2d          # один выход getrandbits(32)
for s in range(2**32):
    random.seed(s)
    if random.getrandbits(32) == target:
        print("seed =", s); break
```

Ускорение: первый выход MT — почти линейная функция seed, поэтому существует обратное преобразование (seed recovery через `init_by_array`). На CTF чаще хватает перебора окна (`time.time()`, `os.getpid()`), а не всего 2^32.

## Частичные выходы и Z3

Когда выходы усечены (`randint(0, 9)` — по 4 бита, или `random()` — 53 бита), `RandCrack` не применим напрямую. Используйте Z3: закодируйте MT как битовые векторы и добавьте наблюдения.

```python
from z3 import BitVec, BitVecVal, Solver, LShR, If
# MT state = 624 BitVec(32); tempering и twist как формулы;
# для каждого наблюдения x: assert(Extract(...) == известный фрагмент)
```

Так восстанавливают состояние даже из потоков «случайных» цифр, координат, паролей из ограниченного алфавита. Подробнее — в `crypto-mt19937-deep`.

## Атаки на реальные конструкции

- **Токены сессий/сброса.** Если `random` (не `secrets`) — предсказуемы.
- **OTP/2FA.** 6-значный код = 20 бит; по нескольким кодам состояние восстанавливается, следующий предсказывается.
- **`uuid.uuid4` с random.** `uuid1` содержит время+MAC (утечка), `uuid4` на `random` — предсказуем.
- **Игровые последовательности.** «Угадай число» с `random` ломается после 624 наблюдений.
- **Перемешивание.** `random.shuffle`/`sample` восстанавливают порядок, если известны индексы.
- **`os.urandom` vs `random`.** Только `secrets`/`os.urandom` стойки; `random` — нет.

## Частые ошибки и тупики

- **Считать `random()` одним 32-битным выходом.** Это 53 бита из двух слов — при сборке в RandCrack будет ошибка.
- **Смешивать разные генераторы.** Каждый `Random()`-инстанс имеет своё состояние; модульный `random` — одно глобальное.
- **Пропустить вызовы.** Любой промежуточный `random()` сдвигает поток — учитывайте все.
- **`randint` включительно.** `randint(a,b)` = `randrange(a, b+1)`; границы важны.
- **`shuffle` необратим по выходам.** Соберите индексы, а не итоговый порядок.
- **Версия Python.** Реализация MT и `random()` стабильны, но `randbytes` появился в 3.9; проверяйте версию.
- **`seed=None` = os.urandom.** Тогда seed неизвестен — нужен путь через состояние.

## Что дальше (decision)

1. Видите `getrandbits(32)` или 32-битные ID → соберите 624, `RandCrack`, предскажите.
2. Видите `random()` (float) → распакуйте 27+26 бит, соберите 624 слова.
3. Видите `randint(0, 9)`/токен из алфавита → Z3 (`crypto-mt19937-deep`).
4. Знаете примерное время seed → переберите окно `time.time()`.
5. Один полный 32-битный выход → перебор seed / seed recovery.
6. Приложение использует `secrets`/`os.urandom` → PRNG-атака не работает, ищите другой вектор.

## Полный разбор: восстановление из randint

Пусть сервер отдаёт `random.randint(0, 99)` — каждое значение несёт `log2(100) ≈ 6.6` бит. `RandCrack` требует полные 32-битные выходы, поэтому напрямую не применим. Варианты:

1. **Если между вызовами генератор не трогается** — собирайте значения и решайте систему Z3: `randint(0,99)` = `randbelow(100)`, который внутри вызывает `getrandbits(7)` с rejection. Закодируйте это как формулы над состоянием MT.
2. **Если доступен `getrandbits(32)`** (например, сервис отдаёт «случайный ID» рядом) — соберите 624 значения и `RandCrack`.
3. **Если seed — время** — переберите окно `time.time()` и сравните первый выход.

```python
from randcrack import RandCrack
rc = RandCrack()
# ТОЛЬКО для полных 32-битных выходов:
for _ in range(624):
    rc.submit(server_getrandbits32())
print("next int:", rc.predict_randint(0, 99))
```

Практическая ловушка: `random()` (float) — это 53 бита из двух слов; чтобы скормить их в RandCrack, распакуйте: `hi = int(x * 2**27)`, `lo = int(x * 2**53) & 0x3ffffff`, и подайте `hi`, `lo` как отдельные 32-битные слова. Иначе восстановление «съедет».
