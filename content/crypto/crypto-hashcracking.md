## Вопрос, с которого всё начинается

Мы поняли, что хэш необратим: по `MD5(password)` нельзя «расшифровать» пароль. Но на практике хэши всё равно ломают — и очень успешно. Вопрос новичка: «Если хэш необратим, что именно делает hashcat?» Ответ: он не расшифровывает, а **угадывает**: перебирает кандидатов, хэширует каждого и сравнивает с целью. Разберём это на конкретном хэше из дампа.

## Наш пример

В дампе паролей мы нашли строку:

```
5f4dcc3b5aa765d61d8327deb882cf99
```

Задача — восстановить пароль. Пройдём весь путь: идентификация → выбор режима → словарь → правила → маска.

## Шаг 1: идентифицируем хэш

Первое, что нужно, — понять **что** мы ломаем. Помогает длина в hex-символах:

```python
h = "5f4dcc3b5aa765d61d8327deb882cf99"
print(len(h))
```

```
32
```

32 hex-символа — это MD5, NTLM или MD4. Различить помогает контекст: NTLM приходит из Windows SAM/дампов, MD5 — из веба или файлов. Другие длины: 40 hex — SHA-1, 64 — SHA-256, 128 — SHA-512. А префиксы говорят сами за себя: `$2a$`/`$2b$` — bcrypt, `$6$` — sha512crypt, `$argon2id$` — Argon2, `$P$` — phpass (WordPress). Быстро подсказать режим помогает `hashid -m '<hash>'`.

## Шаг 2: определяем режим hashcat

hashcat не угадывает алгоритм — ему указывают режим флагом `-m`. Ключевые режимы стоит знать:

| `-m` | Тип | `-m` | Тип |
|---|---|---|---|
| `0` | MD5 | `1000` | NTLM |
| `100` | SHA-1 | `5600` | NetNTLMv2 |
| `1400` | SHA-256 | `13100` | Kerberoast |
| `1700` | SHA-512 | `3200` | bcrypt |
| `1800` | sha512crypt | `22000` | WPA-PMKID |

Для нашего 32-hex из Windows-дампа логичен `-m 1000` (NTLM) или `-m 0` (MD5). Неверный `-m` — самая частая причина «почему не ломается».

## Шаг 3: словарь — первая атака

hashcat не перебирает всё подряд — он берёт **словарь** и проверяет каждое слово. Воспроизведём суть на маленьком словаре:

```python
import hashlib
h = "5f4dcc3b5aa765d61d8327deb882cf99"
for w in ["123456","password","letmein","qwerty","admin"]:
    if hashlib.md5(w.encode()).hexdigest() == h:
        print("CRACKED:", w)
```

```
CRACKED: password
```

Пароль — `password`. Настоящая команда выглядит так:

```bash
$ hashcat -m 1000 hashes.txt rockyou.txt
```

`rockyou.txt` — базовый словарь на 14 миллионов паролей. Если он не помог, добавляем **правила**.

## Шаг 4: правила — мутации словаря

Люди не хранят пароли как есть — они их «мутируют»: капитализируют, меняют `a` на `@`, дописывают `1` или `123`. **Правила** (`-r`) применяют такие мутации к каждому слову словаря. Покажем идею вручную:

```python
def best64(w):
    return {w, w.capitalize(), w.upper(), w+"1", w+"123", w.replace("a","@")}
```

Именно это и делают файлы правил: `best64.rule` (64 популярные мутации), `OneRuleToRuleThemAll.rule` (большое сообщество-правило). Команда:

```bash
$ hashcat -m 1000 hashes.txt rockyou.txt -r rules/best64.rule
```

## Шаг 5: маска и гибрид

Когда словарь не помогает, но известен **паттерн** пароля (например, «4 цифры»), применяют **маску** (`-a 3`): `?l` — строчная буква, `?u` — заглавная, `?d` — цифра, `?s` — спецсимвол, `?a` — всё.

```bash
$ hashcat -m 1000 hashes.txt -a 3 '?d?d?d?d'        # PIN из 4 цифр
$ hashcat -m 1000 hashes.txt -a 3 '?u?l?l?l?d?d'    # Abcd12
```

А самый частый случай — «слово + цифры»: это **гибридная** атака (`-a 6` — словарь + маска):

```bash
$ hashcat -m 1000 hashes.txt -a 6 rockyou.txt '?d?d?d?d'
```

Порядок атак экономит часы: **словарь → словарь+best64 → словарь+агрессивные правила → маска → гибрид**. Полный перебор (`?a?a?a?a?a?a`) для длинных паролей непрактичен — не начинайте с него. И запомните главное: хэш не «расшифровывают», а **угадывают** — поэтому качество словаря и правил важнее, чем мощность железа.

## Шаг 6: bcrypt, argon2 и архивы

**bcrypt** (`-m 3200`) и **argon2** намеренно медленные и солёные: на GPU перебор ограничен, поэтому работает только **целевой словарь**. Это не «баг», а защита: слабый пароль ещё ломается, сильный — нет. Для архивов и файлов сначала извлекают хэш утилитами `*2john`:

```bash
$ zip2john secret.zip > zip.hash
$ rar2john secret.rar > rar.hash
$ keepass2john db.kdbx > kp.hash
$ john --wordlist=rockyou.txt zip.hash
```

## Шаг 7: стратегия и как не застрять

Правильный порядок: **идентифицировать** хэш (`hashid`); проверить `--show` (вдруг уже взломано); **словарь + best64**; **агрессивные правила**; **маска** под известную политику паролей; **гибрид**; **комбинация** двух словарей. Для bcrypt/argon2 — только целевой словарь. Частые ошибки: неверный `-m`; забыть `--show` и ломать уже сломанное; использовать CPU вместо GPU (hashcat на CPU медленный); огромный словарь без правил (иногда правила важнее размера); не учитывать формат файла (`user:hash` против «один хэш на строку»).

## John the Ripper

У hashcat есть родственник — **John the Ripper**. Он удобнее для некоторых форматов и умеет автоматически определять тип хэша, а также поставляется с утилитами извлечения `*2john`. Базовое использование: `john --wordlist=rockyou.txt hashes.txt`; принудительно указать формат — `john --format=bcrypt hashes.txt`; показать уже взломанные — `john --show hashes.txt`. Если хэш лежит внутри файла (архив, документ, база KeePass), сначала извлекают его: `zip2john`, `rar2john`, `pdf2john`, `keepass2john`, `ssh2john`. Полученный «хэш» подают в john или hashcat.

## Извлечение хэшей и оптимизация

Для архивов и документов хэш не «достают» вручную — его конвертируют утилитой в формат `*2john`, а затем ломают:

```bash
$ zip2john secret.zip > zip.hash
$ rar2john secret.rar > rar.hash
$ pdf2john secret.pdf > pdf.hash
$ keepass2john db.kdbx > kp.hash
$ ssh2john id_rsa > ssh.hash
$ john --wordlist=rockyou.txt zip.hash
```

Пара практических флагов hashcat: `-w 1..4` задаёт рабочую нагрузку, `-O` включает оптимизированное ядро (ограничивает длину пароля), `-o out.txt` сохраняет результат, `--show` показывает взломанное, `--session` делает возобновляемую сессию. И помните про базу словарей: `rockyou.txt` — точка отсчёта, дальше SecLists, `crackstation.txt`, а для целевых атак — словари из рекон-данных (имена, домены, термины компании).

## Что мы теперь знаем

- hashcat **не расшифровывает** — он угадывает кандидатов и сравнивает хэши.
- Тип хэша определяют по длине и префиксу; режим задаётся `-m`.
- Порядок атак: **словарь → правила → маска → гибрид**.
- Правила мутируют слова; маски задают паттерн (`?l?u?d?s`).
- **bcrypt/argon2** медленные — только целевой словарь.
- Из архивов хэш достают через `zip2john`/`rar2john`/`keepass2john`.
- Качество словаря и правил важнее мощности железа — hashcat угадывает, а не расшифровывает.

## Куда дальше

Мы научились восстанавливать пароли из хэшей. Дальше — как из этих хэшей делать **свой** стойкий: в уроке **crypto-hash-forge** мы разберём длинное расширение (length extension), коллизии и то, почему `hash(secret ‖ message)` — плохой MAC. А пока главное: **хэш ломают не «расшифровкой», а угадыванием кандидатов — и порядок атак важнее мощности железа.**

## Где пригодится

- **CTF** — почти всегда есть задача «взломай хэш/архив/дамп».
- **Пентест** — после дампа хэшей (SAM, /etc/shadow, БД) нужен их взлом для lateral movement.
- **Red team** — Kerberoast/AS-REP хэши, NetNTLMv2, NTLM relay.
- **Форензика** — восстановление паролей из конфигов и архивов.
- **Защита** — понимание скорости перебора мотивирует использовать bcrypt/argon2 и длинные пароли.
