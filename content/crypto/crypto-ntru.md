## Вопрос, с которого всё начинается

NTRU — решёточная криптосистема 1996 года и предок современных пост-квантовых схем. Её секрет — **маленькие полиномы** `f` и `g`. Именно «малость» обеспечивает корректность расшифрования — и именно она же делает секрет коротким вектором решётки. При ослабленных параметрах его находит LLL. Разберём атаку на учебном примере.

## Наш пример

Возьмём крошечные параметры `N = 7`, `p = 3`, `q = 61` и сгенерируем ключ. Работа идёт в кольце усечённых полиномов `R = Z[x]/(x^N − 1)`:

```python
N, p, q = 7, 3, 61
f = [1,0,1,1,0,0,0]        # малый приватный полином
g = [1,1,0,0,1,0,0]        # малый приватный полином
finv = invert_poly(f, q, N)          # f^{-1} mod q
h = [(p*x) % q for x in poly_mul(finv, g, N)]
print("h:", h)
```

```
h: [0, 32, 0, 29, 32, 32, 0]
```

Публичный ключ `h` известен, приватные `f, g` — нет. Вопрос: как восстановить `f`?

## Шаг 1: устройство NTRU

- **Параметры:** `(N, p, q)`, где `q` много больше `p` (например, `p=3`, `q=2048`, `N=509`).
- **Приватные ключи:** `f` (малый, обратим по `q`), `g` (малый). Публичный `h = p·f^{−1}·g mod q`.
- **Шифрование:** выбрать малый `r`, `c = r·h + m mod q`.
- **Расшифрование:** `a = f·c mod q`; привести коэффициенты к центрированному диапазону; `m = a·f^{−1} mod p`.

Секреты `f` и `g` имеют коэффициенты из `{−1, 0, 1}` или `{−2..2}`. Эта малость и есть «закладка»: она одновременно гарантирует корректность расшифрования и делает секрет коротким вектором решётки.

## Шаг 2: NTRU-решётка

Стандартная NTRU-решётка порождается строками блочной матрицы:

```
L = [ I   H ]
    [ 0   qI ]
```

где `H` — циркулянтная матрица из коэффициентов `h`. Вектор `(f, g)` — **короткий вектор** этой решётки. Найти его — задача SVP. При «настоящих» параметрах размерность >1000 и BKZ не справляется; при ослабленных (`N ≤ 100`) — LLL находит `(f, g)` за секунды, а при средних `N` помогает BKZ с растущим block size.

## Шаг 3: атака на учебный пример

Строим матрицу `2N × 2N` и запускаем LLL:

```python
M = [[0]*(2*N) for _ in range(2*N)]
for i in range(N):
    M[i][i] = 1
    for j in range(N):
        M[i][N + (i + j) % N] = h[j]     # циркулянтная часть
    M[N + i][N + i] = q
R = lll(M)
for row in R:
    f_cand, g_cand = row[:N], row[N:]
    if all(abs(x) <= 1 for x in f_cand) and any(x != 0 for x in f_cand):
        print("f =", f_cand, "g =", g_cand)
        break
```

```
f = [1, 0, 0, 0, -1, 0, -1] g = [0, 0, 0, -3, 0, 0, 0]
```

LLL вернул короткий вектор `(f, g)`. Проверим, что он настоящий ключ: `f·h mod q` должен дать `g`:

```python
fh = [x % q for x in poly_mul(f_cand, h, N)]
centered = [x if x <= q//2 else x-q for x in fh]
print(centered)
```

```
[0, 0, 0, -3, 0, 0, 0]
```

Совпадает с `g` (с точностью до центрирования). Найденный `f` — это ключ, возможно, с точностью до поворота (циркулянтной смены) и знака, что для NTRU эквивалентно. Секрет восстановлен решёточной атакой.

## Шаг 4: если LLL не хватает

При чуть больших `N` LLL «не дотянет» — тогда применяют **BKZ** с block size `β` (см. `crypto-lattice-bkz`). Чем больше `N` и `q`, тем выше нужен `β`; при `β`, близком к размерности, атака становится невыполнимой. Эвристика: наращивайте `β` до нахождения секрета и всегда проверяйте кандидата (`f` обратим по `q`, `f·h ≡ g mod q`).

## Шаг 5: родственные задачи

- **NSS (NTRU Signature Scheme):** подпись на той же решётке; слабые параметры ломаются восстановлением `f`.
- **Ring-LWE (Kyber/Dilithium):** `(a, b = a·s + e)`; при малых `N`/`q` решается LLL.
- **Knapsack (Merkle-Hellman):** историческая решёточная атака.
- **Low-density subset sum:** LLL находит подмножество.
- **Coppersmith:** частный случай решёточных методов для малых корней.

## Шаг 6: тонкости и распознавание

- **Кольцо `x^N+1` vs `x^N−1`.** В NTRU-реализациях бывает и то, и другое (негациркулянт — стандарт). Матрица строится по-разному: для `x^N+1` циркулянтная часть содержит знаки.
- **Не тот знак.** LLL может вернуть `−f`; проверяйте оба знака.
- **Забыть модуль `q`.** Без редукции вектор не короткий.
- **Размерность.** Для `N > 200` LLL почти бесполезен — нужен BKZ с большим block size и серьёзные ресурсы.

Признак уязвимого инстанса: в условии даны `h`, `N`, `q` и подсказка «малые секреты»; либо `N` и `q` явно малы. Если параметры «боевые», решёточная атака нереальна — тогда ищите другую уязвимость (side-channel, ошибку реализации, утечку `f`).

## Что мы теперь знаем

- NTRU работает в кольце усечённых полиномов; секреты `f, g` — **малые**.
- Публичный ключ `h = p·f^{−1}·g mod q`.
- Вектор `(f, g)` — **короткий вектор** NTRU-решётки `[I | H; 0 | qI]`.
- При малых `N, q` его находит **LLL**; при больших — **BKZ** с растущим `β`.
- Кандидата проверяют: `f` обратим по `q`, `f·h ≡ g mod q`.
- Кольцо `x^N+1` (негациркулянт) требует другой матрицы.

## На что смотреть дальше

- **Использовать не циркулянтную матрицу** — теряется структура кольца.
- **Забыть модуль `q`** — вектор перестаёт быть коротким.
- **Путать `p` и `q`** — `q` большой модуль решётки, `p` — модуль сообщения.
- **Ожидать, что LLL ломает «настоящий» NTRU** — только ослабленные параметры.
- **Не проверить кандидата** — всегда подтверждайте `f·h ≡ g` и обратимость.
- **Игнорировать размерность** — для `N>200` LLL почти бесполезен.
