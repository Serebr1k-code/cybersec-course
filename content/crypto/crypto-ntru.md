NTRU — одна из старейших практических решёточных криптосистем (1996) и прямой предок современных пост-квантовых схем (Kyber/Dilithium — «родственники» по решёткам). В CTF она встречается как задача «дана решётка/полиномы — восстанови ключ», где параметры специально ослаблены, и обычный LLL/BKZ находит секрет. Эта глава — устройство NTRU, его решётка и полный практический разбор атак.

## Устройство NTRU

Работа идёт в кольце **усечённых полиномов** `R = Z[x]/(x^N - 1)` (или `x^N + 1`), где `N` — простое (часто 509, 677, 701). Элементы — векторы длины `N` с целыми коэффициентами, умножение — циклическая свёртка.

- **Параметры:** `(N, p, q)`, где `q` много больше `p` (например, `p=3`, `q=2048`, `N=509`).
- **Приватные ключи:** `f` (малый, обратим по `q`), `g` (малый). Публичный ключ `h = p·f^{-1}·g mod q`.
- **Шифрование:** выбрать малый `r`, `c = r·h + m mod q`, где `m` — сообщение с коэффициентами по модулю `p`.
- **Расшифрование:** `a = f·c mod q`; привести коэффициенты к центрированному диапазону; `m = a·f^{-1} mod p`.

Секреты `f` и `g` — «малые» (коэффициенты из `{-1,0,1}` или `{-2..2}`), и именно эта малость делает их уязвимыми для решёточных атак при малых `N`/`q`.

## NTRU-решётка и задача

Стандартная NTRU-решётка порождается строками блочной матрицы:

```
L = [ I   H ]
    [ 0   qI ]
```

где `H` — циркулянтная матрица из коэффициентов `h`. Вектор `(f, g)` — **короткий вектор** этой решётки (коэффициенты малы). Найти его — задача SVP. Эквивалентно, зная `h`, задача поиска `(f, g)` при `f·h ≡ g mod q` — это CVP/SVP в решётке размерности `2N`.

При «настоящих» параметрах решётка имеет размерность >1000 и BKZ не справляется. При ослабленных (`N ≤ 100`, малый `q`) — LLL/BKZ находит `(f, g)` за секунды.

## Атаки: LLL/BKZ на NTRU

1. Построить базис решётки `L` из `h` и `q`.
2. Применить LLL (`fpylll`, Sage `matrix.LLL()`).
3. Просмотреть короткие векторы: искать кандидата `(f, g)`.
4. Проверить: `f` обратим по `q`? `f·h ≡ g mod q`?

```python
# Sage: атака на NTRU при малых параметрах
N, p, q = 29, 3, 61
# h — публичный ключ (вектор длины N)
M = Matrix(ZZ, 2*N, 2*N)
for i in range(N):
    M[i, i] = 1
    for j in range(N):
        M[i, N + (i + j) % N] = h[j]      # циркулянтная часть
    M[N + i, N + i] = q
B = M.LLL()
# ищем строки, где первые N коэффициентов малы -> кандидат в f
for row in B.rows():
    f = row[:N]
    g = row[N:]
    if all(abs(x) <= 2 for x in f):
        print("f =", list(f))
        break
```

Если LLL не даёт короткого вектора, применяйте **BKZ** с большим block size (`crypto-lattice-bkz`). Чем больше `N` и `q`, тем выше нужен `β`; при `β`, близком к размерности, атака становится невыполнимой.

## NSS и родственные задачи

- **NTRU Signature Scheme (NSS)** — подпись на той же решётке; слабые параметры ломаются восстановлением `f`.
- **Ring-LWE** — Kyber/Dilithium: `(a, b = a·s + e)`; при малых `N`/`q` тоже решается LLL.
- **Knapsack (Merkle-Hellman)** — историческая решёточная атака (см. `crypto-lattice`).
- **Low-density subset sum** — LLL находит подмножество.
- **Coppersmith** — частный случай решёточных методов для малых корней (см. `crypto-rsa-coppersmith-deep`).

## Разобранный пример: NTRU с N=29

Дано: `N=29, p=3, q=61`, публичный `h`. Цель — восстановить `f` (и `g`).

1. Строим матрицу `2N × 2N` (см. код выше).
2. `B = M.LLL()`; ищем строку с малыми первыми `N` коэффициентами — это `f` (возможно, с точностью до знака).
3. Проверяем `f·h mod q == g` и `f` обратим по `q`.
4. Расшифровываем `m` и/или подтверждаем ключ.

Мораль: малость `f, g` — одновременно гарантия корректности расшифрования и «закладка» для атаки; критично лишь соотношение `N`/`q` и стойкость LLL/BKZ.

## Варианты и edge cases

- **Не тот знак.** LLL может вернуть `-f`; проверяйте оба знака.
- **Умножение `x^N+1` vs `x^N-1`.** В NTRU-реализациях кольцо бывает `x^N - 1` (циркулянт) или `x^N + 1` (негациркулянт, стандарт). Матрица строится по-разному.
- **Сдвиг/перестановка коэффициентов.** Циркулянтная структура требует аккуратной индексации.
- **Не LLL, а BKZ.** При чуть больших `N` LLL «не дотянет» — нужен BKZ-β.
- **Ослабление параметров в задаче.** Проверьте, не дали ли `f`/`g` «малыми» намеренно (подсказка на решётку).

## Частые ошибки и тупики

- **Использовать обычную (не циркулянтную) матрицу.** Потеря структуры кольца.
- **Забыть модуль `q`.** Без редукции вектор не короткий.
- **Путать `p` и `q`.** `q` — большой модуль решётки; `p` — модуль сообщения.
- **Ожидать, что LLL ломает «настоящий» NTRU.** Нет — только ослабленные параметры.
- **Не проверить кандидата.** Всегда подтверждайте `f·h ≡ g` и обратимость.
- **Игнорировать размерность.** Для `N>200` LLL почти бесполезен — нужен BKZ и большие ресурсы.

## Что дальше (decision)

1. Даны `h`, `N`, `q` и подсказка «малые секреты» → стройте NTRU-решётку и LLL.
2. LLL не находит → поднимайте BKZ-β (`crypto-lattice-bkz`).
3. Кольцо `x^N+1` → негациркулянтная матрица.
4. Задача про подпись/подделку → NSS-вариант, тот же ключ.
5. Kyber/Dilithium с малыми параметрами → Ring-LWE, та же техника.
6. Параметры «боевые» → атака нереальна, ищите другую уязвимость (side-channel, ошибка реализации).

## Полный разбор: NTRU с N=61

Возьмём учебные параметры `N=61, p=3, q=2048`. Публичный `h = p·f^{-1}·g mod q`. Строим решётку `2N × 2N` (циркулянтная структура), запускаем LLL и ищем строку с малыми первыми `N` коэффициентами:

```python
# Sage
N, p, q = 61, 3, 2048
h = [...]                       # публичный ключ, длина N
M = Matrix(ZZ, 2*N, 2*N)
for i in range(N):
    M[i, i] = 1
    for j in range(N):
        M[i, N + (i + j) % N] = h[j]
    M[N + i, N + i] = q
B = M.LLL()
for row in B.rows():
    f, g = list(row[:N]), list(row[N:])
    if all(abs(x) <= 1 for x in f) and any(x != 0 for x in f):
        print("candidate f =", f)
        # проверить f*h mod q == g и обратимость f
        break
```

Если LLL не находит — переходите на `BKZ(30..50)`. Если и это не помогает, вероятно, параметры «боевые» (или кольцо `x^N+1`, а матрица построена как для `x^N-1`). Всегда проверяйте кандидата: `f` обратим по `q`, и `f·h ≡ g (mod q)`.
