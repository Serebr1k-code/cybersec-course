## PKCS#1 v1.5 padding

Перед шифрованием сообщение `M` дополняется до длины модуля:

```
EM = 0x00 || 0x02 || PS || 0x00 || M
```

где `PS` — случайные ненулевые байты (не менее 8). `c = EM^e mod n`. При расшифровке проверяют: первый байт `0x00`, второй `0x02`, есть разделитель `0x00` не раньше 8-го байта. Если структура неверна — «ошибка padding».

## Bleichenbacher (1998)

**Million message attack.** Если сервер (oracle) различает «padding корректен» и «некорректен» (по времени, коду ошибки, поведению), атакующий восстанавливает `M` за ~`10^6` запросов:

1. Выбираем множители `s`, чтобы `(c·s^e) mod n` при расшифровке давало валидный padding.
2. Каждый «валидный» ответ сужает интервал `[a, b]`, в котором лежит `M`.
3. Повторяем с новыми `s` — интервал сжимается до одного значения.

Ключевая идея: padding-проверка = oracle, сообщающий, попадает ли `M·s mod n` в «узкое» множество (начинается с `0x00 0x02`). Формально — вариант chosen-ciphertext атаки, дающий ~1 бит на запрос.

## Детали алгоритма

Пусть `B = 2^(8(k-2))` для `k`-байтного модуля. Множество «валидных» `m` — интервал `[2B, 3B−1]`.

**Этап 1 (blinding):** если `c` уже даёт валидный padding, `s0 = 1`; иначе ищем `s0`, перебирая `s`, пока `oracle(c·s0^e)` не станет валидным.

**Этап 2 (поиск `s`):** для каждого `s` проверяем, что `M·s mod n ∈ [2B, 3B)`. Интервалы сужаются.

**Этап 3 (уточнение):** когда остаётся один интервал, ищем минимальный `s`, сохраняющий валидность.

**Этап 4:** повторяем, пока `a == b`. Тогда `M = a`.

Полная реализация — сотни строк; на практике берут готовые скрипты (`robots.txt`/`tlsfuzzer`/Bleichenbacher PoC).

## Почему это работает

Padding-проверка утечка **одного бита** («структура верна?») на запрос. Как и parity oracle (`crypto-rsa-oracle`), это позволяет **бинарно сужать** интервал возможных `M`. Мультипликативность textbook RSA (`(m·s)^e = m^e·s^e`) позволяет «управлять» значением `M·s mod n`, а oracle сообщает, попало ли оно в узкое множество.

## ROBOT и реальные системы

**ROBOT (Return Of Bleichenbacher's Oracle Threat, 2017)** — набор реальных реализаций TLS/почты/API, всё ещё уязвимых к вариантам Блейхенбахера (разные коды ошибок, разные тайминги). Проверка:

```bash
python3 robot-detect.py -H target.example.com
# или tlsfuzzer
```

Признак уязвимости: сервер по-разному реагирует на некорректный padding и на прочие ошибки расшифровки.

## Варианты

- **Marvin (2023)** — timing-вариант на OpenSSL RSA, восстановление сообщения по времени.
- **Klima / ORACLE-варианты** — модификации при разных проверках.
- **Интерактивные версии** — когда oracle доступен только по таймингу.
- **Manger** — аналог для OAEP (`crypto-rsa-oracle`).

## Практический пример: локальная отладка

```python
from Crypto.PublicKey import RSA
from Crypto.Util.number import bytes_to_long, long_to_bytes
import os

key = RSA.generate(1024)
n, e, d = key.n, key.e, key.d

def pkcs1_encrypt(m):
    # EM = 00 02 PS 00 m, PS >= 8 ненулевых байт
    k = (n.bit_length() + 7) // 8
    ps = os.urandom(k - 3 - len(m)).replace(b"\x00", b"\x01")
    em = b"\x00\x02" + ps + b"\x00" + m
    return pow(bytes_to_long(em), e, n)

def oracle(c):
    m = pow(c, d, n)
    em = long_to_bytes(m, (n.bit_length()+7)//8)
    # проверка структуры PKCS#1 v1.5
    return em[0] == 0 and em[1] == 2 and b"\x00" in em[2:]

c = pkcs1_encrypt(b"secret")
# ... запускаем Bleichenbacher PoC, используя oracle ...
```

## Распознавание

**Признак CTF:**

- сервер расшифровывает RSA и отвечает «padding valid/invalid» (или разным временем);
- дано `n, e`, целевой `c`;
- сказано «oracle», «PKCS#1 v1.5», «million message».

## Защита

- **Единый ответ об ошибке:** не различать «padding invalid» и другие ошибки.
- **Constant-time** обработка (устранение timing-утечек).
- **OAEP** вместо PKCS#1 v1.5 (устраняет саму структуру-oracle).
- **Не использовать RSA без AEAD** там, где важен oracle.
- **ROBOT-тесты** в CI для TLS-стеков.

## Частые ошибки

- **Нет oracle.** Атака требует различения «padding valid/invalid».
- **Шумный/нестабильный oracle.** Тайминги плывут — нужна статистика и повторы.
- **Неправильные границы интервала.** `B = 2^(8*(k-2))` для `k`-байтного модуля; ошибка в `k` ломает всё.
- **Мало запросов.** Нужно ~`10^6`.
- **Считать OAEP неуязвимым.** Для OAEP есть свой oracle — Manger.
- **Забыть про blinding.** Первый шаг часто нужен, если `c` не даёт валидный padding.

## Blinding: зачем и как

Первый шаг атаки — **blinding**. Если исходный `c` уже даёт валидный padding, `s0 = 1`. Иначе атакующий ищет `s0`, при котором `c·s0^e mod n` расшифровывается в валидный padding. Это нужно, чтобы «запустить» интервальный алгоритм с известной точки. Blinding также используется как защита (RSA blinding): сервер умножает `c` на случайный `r^e`, расшифровывает, затем делит на `r` — это разрывает корреляцию между входом и временем, снижая timing-утечки.

## Реальные инциденты

- **1998:** оригинальная публикация Bleichenbacher против SSL (PKCS#1 v1.5).
- **2003:** атака на OpenSSL (устранена патчем).
- **2016:** CVE в Java/Android, восстанавливавший ключи TLS.
- **2017:** ROBOT — десятки популярных реализаций (F5, Citrix, Cisco, Erlang, Go, ...) оказались уязвимы. Многие — из-за различимых сообщений об ошибке.
- **2023:** Marvin — timing-вариант на OpenSSL.

Вывод: Bleichenbacher — не историческая атака; она жива, потому что разработчики продолжают различать ошибки padding.


## Разбор: определяем oracle в задаче

Часто в CTF-задаче сервер прямо не говорит «padding invalid». Признаки оракула:

- Разный **HTTP-код** (200 vs 500) при изменённом `c`.
- Разная **длина** ответа.
- Разный **текст** ошибки.
- Разное **время** обработки (медленнее, если padding валиден и идёт дальше).
- **Побочные эффекты** (лог, email).

```python
# Быстрая проверка: отправляем c и c*s^e, сравниваем ответы
r1 = send(c)
r2 = send((c * pow(s, e, n)) % n)
if r1 != r2:
    print("различие -> возможен oracle")
```

## Разбор: почему v1.5 нельзя «просто убрать ошибку»

Даже если сервер возвращает единый текст ошибки, **тайминг** может различаться: ветвление `if padding_ok` занимает разное время. Поэтому нужен **constant-time** код и, желательно, **blinding**. Именно поэтому современные стеки переходят на OAEP (где сам oracle другой — Manger).

## Как не застрять

- **Ищите разницу в ответах/времени.** Это oracle.
- **Возьмите готовый PoC** (Bleichenbacher/ROBOT) — не пишите с нуля.
- **Определите `k`** (длина модуля) — от неё зависит `B`.
- **Соберите статистику** при timing-oracle.
- **Проверяйте сходимость** (`pow(M,e,n)==c`).
- **Если padding = OAEP** — переходите к Manger.
