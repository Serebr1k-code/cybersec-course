## Что такое RC4

RC4 (Ron Rivest, 1987) — потоковый шифр с переменным ключом (обычно 40–2048 бит) и очень простой реализацией. Долгое время был популярен (WEP, WPA-TKIP, SSL/TLS, RDP, Microsoft Office). Сегодня **запрещён** в TLS (RFC 7465), но встречается в legacy-системах и CTF.

Устройство: два этапа — **KSA** (Key Scheduling Algorithm) и **PRGA** (Pseudo-Random Generation Algorithm), работающие с S-боксом из 256 байт.

## KSA: инициализация

```python
def ksa(key):
    S = list(range(256))
    j = 0
    for i in range(256):
        j = (j + S[i] + key[i % len(key)]) & 0xff
        S[i], S[j] = S[j], S[i]
    return S
```

KSA «перемешивает» S в зависимости от ключа. Слабость: начальные шаги коррелируют с байтами ключа — это и есть источник смещений.

## PRGA: генерация keystream

```python
def prga(S):
    i = j = 0
    while True:
        i = (i + 1) & 0xff
        j = (j + S[i]) & 0xff
        S[i], S[j] = S[j], S[i]
        yield S[(S[i] + S[j]) & 0xff]
```

Шифрование: `C = P ⊕ keystream`.

## Смещения (biases)

Идеальный потоковый шифр даёт равномерный keystream: каждый байт равен любому значению с вероятностью `1/256`. У RC4 есть **статистические отклонения**:

- **Второй байт keystream равен 0** с вероятностью ~`2/256` (вдвое выше случайной) — знаменитое смещение.
- **Первый байт** также смещён.
- **Многие байты на позициях 1..256** имеют смещения (работа Fluhrer–McGrew, «biases in RC4 keystream»).

Эти смещения позволяют отличать RC4-трафик от случайного и, в комбинации с известным открытым текстом, восстанавливать байты.

## FMS-атака на WEP

WEP использует RC4 с ключом `IV || K` (IV передаётся открыто, 3 байта). **FMS** (Fluhrer–Mantin–Shamir, 2001) использует связанные ключи (IV меняется, `K` фиксирован):

- Для определённых IV первый байт keystream коррелирует с байтом секретного ключа `K`.
- Собрав ~миллионы пакетов с «слабыми» IV, для каждого байта `K` выбирается значение с максимальной частотой — и ключ восстанавливается.

Это сделало WEP полностью сломанным (aircrack-ng реализует атаку).

## RC4 NOMORE

**NOMORE** (2015) — атака на RC4 в TLS: статистические смещения в первых ~256 байтах keystream позволяют восстанавливать **cookie** (или другой известный/повторяющийся текст) при большом числе запросов. Потребовалось ~2^26–2^32 запросов, но это практично для HTTPS с повторяющимся cookie. Показала: даже «шифрование без known-plaintext» утекает из-за смещений.

## Практический пример: статистическая атака

```python
# Дано: много шифротекстов, зашифрованных RC4 с одним ключом,
# но разными/связанными IV, и известная структура открытого текста.
# Собираем keystream-байты: ks = C ^ P
from collections import Counter
counts = [Counter() for _ in range(256)]
for c, p in samples:   # c = шифротекст, p = угаданный открытый текст
    ks = bytes(x ^ y for x, y in zip(c, p))
    for i, b in enumerate(ks[:256]):
        counts[i][b] += 1
# наиболее частый байт на позиции i — кандидат
for i in range(256):
    print(i, counts[i].most_common(3))
```

При достаточном числе образцов «мода» совпадает с истинным байтом keystream.

## Частые ошибки

- **Считать RC4 безопасным.** Запрещён; смещения известны.
- **Мало образцов для статистики.** Нужны миллионы/тысячи в зависимости от смещения.
- **Не учитывать IV.** В WEP ключ = IV||K; связанные ключи критичны.
- **Путать RC4 и RC4A.** RC4A — усиленный вариант.
- **Игнорировать дроп первых байт.** Некоторые реализации отбрасывают 256/768/3072 первых байт — это снижает, но не устраняет смещения.
- **Забыть про «RC4-horse»** и другие варианты.

## Слабости KSA детально

Первые шаги KSA сильно коррелируют с ключом, потому что S-бокс ещё почти не перемешан. Отсюда:

- **Смещение второго байта:** после KSA `S[1]` имеет высокую вероятность быть 0, что даёт keystream[1] = 0 с вероятностью ~2/256.
- **Смещения на позициях 1..256:** работа Fluhrer–McGrew каталогизировала их; они используются в статистических атаках (NOMORE).
- **Связанные ключи:** если ключи отличаются только в суффиксе (как IV в WEP), корреляции предсказуемы.
- **Дроп первых байт:** реализации иногда отбрасывают 256/768/3072 первых байт (RC4-drop), что снижает смещения, но не устраняет их полностью.

## RC4 в разных протоколах

- **WEP:** ключ = `IV || K`; FMS-атака; полностью сломан.
- **WPA-TKIP:** использует RC4 с дополнительными мерами (MIC, счётчик); атаки (Beck-Tews) возможны.
- **TLS/SSL:** RC4 был популярен; запрещён RFC 7465 (2015).
- **RDP:** исторически RC4; современный RDP использует TLS.
- **Microsoft Office (старый):** RC4 в шифровании документов; атаки на слабые ключи.

## Разбор: отличаем RC4 от случайного

```python
from collections import Counter
# Собираем много keystream-байт на позиции 1 (например, из известных текстов)
c = Counter(ks[1] for ks in keystreams)
total = sum(c.values())
print("P(ks[1]==0) =", c[0]/total)   # для RC4 ~0.0078, для случайного ~0.0039
```

Если вероятность вдвое выше — это RC4 (или его вариант).

## RC4 в TLS: NOMORE детально

Атака NOMORE (Vanhoef & Piessens, 2015) использует смещения в **первых 256 байтах** keystream. Если атакующий знает/угадывает часть открытого текста (например, HTTP-cookie), он может с высокой вероятностью восстановить байт за байтом, используя статистику по многим сессиям с разными ключами. Требуется ~2^26–2^32 запросов — практично для HTTPS-серверов с повторяющимся cookie. Это стало одной из причин запрета RC4.

## Разбор: восстановление ключа RC4 при известном keystream

Если известен **весь** keystream (например, через известный открытый текст), ключ всё равно **не** восстанавливается напрямую (RC4 — необратимая схема KSA). Атака идёт через **связанные ключи** (WEP) или **статистику** — то есть нужно много образцов, а не один.

## Разбор: реализация RC4 и проверка смещения

```python
def rc4_keystream(key, n):
    S = list(range(256)); j = 0
    for i in range(256):
        j = (j + S[i] + key[i % len(key)]) & 0xff
        S[i], S[j] = S[j], S[i]
    i = j = 0; out = []
    for _ in range(n):
        i = (i+1) & 0xff; j = (j+S[i]) & 0xff
        S[i], S[j] = S[j], S[i]
        out.append(S[(S[i]+S[j]) & 0xff])
    return bytes(out)

# статистика: сколько раз ks[1]==0 по 100000 ключей
import random
cnt = 0; N = 100000
for _ in range(N):
    ks = rc4_keystream(random.randbytes(16), 2)
    if ks[1] == 0: cnt += 1
print(cnt/N)   # ~0.0078 (ожидание случайного 0.0039)
```

## Как не застрять

- **Определите RC4** по контексту (WEP, старый TLS, RDP).
- **Соберите много шифротекстов** с одним ключом/связанными IV.
- **Используйте известный/угаданный текст** для восстановления keystream.
- **Применяйте статистику** (мода по позициям).
- **Для WEP** — aircrack-ng с миллионами пакетов.
- **Проверяйте дроп-байты.** Реализации могут отбрасывать начало.
