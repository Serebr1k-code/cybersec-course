## Почему быстрый хэш не годится для паролей

SHA-256 вычисляется на GPU **миллиарды раз в секунду**. Если хранить пароли как `SHA256(password)`, то даже длинный пароль из словаря подбирается за минуты. Проблема в том, что криптографические хэши спроектированы быть **быстрыми** — а для паролей нужно ровно обратное: **медленно и дорого** вычислять каждую попытку.

**KDF** (Key Derivation Function) для паролей — это функция, намеренно требующая значительных ресурсов (времени, памяти, параллелизма) на одно вычисление. Это замедляет перебор в тысячи-миллионы раз.

## Соль (salt)

Соль — случайная строка, хранящаяся **рядом** с хэшем (не секрет). Она:

- делает одинаковые пароли **разными** (уникальные хэши),
- убивает **радужные таблицы** (предвычисленные),
- не даёт атакующему ломать «пачкой» (каждый пароль считается отдельно).

Соль должна быть уникальной на пользователя и достаточно длинной (16+ байт).

## PBKDF2

PBKDF2 (RFC 2898) применяет HMAC к паролю многократно:

```
DK = T1 || T2 || ... || Tdklen/hlen
Ti = F(password, salt, iterations, i)
F = U1 ⊕ U2 ⊕ ... ⊕ Uc   (U1 = HMAC(password, salt||i), Uj = HMAC(password, U_{j-1}))
```

Параметр — число итераций (обычно 100k–600k). PBKDF2 **не memory-hard**: атакуется GPU/ASIC эффективно. Но прост и стандартизован (используется в WPA2, BitLocker, 1Password).

```python
import hashlib
dk = hashlib.pbkdf2_hmac('sha256', b'password', b'salt', 100000)
print(dk.hex())
```

## bcrypt

bcrypt (1999, Provos & Mazières) основан на Blowfish с «EksBlowfish» key schedule. Параметр — **cost factor** (лог2 числа раундов): `cost=12` = 2^12 раундов.

- Намеренно медленный (адаптивный: увеличивайте cost по мере роста GPU).
- Соль встроена в выход (`$2b$12$salt...hash`).
- **Ограничение:** пароль обрезается до **72 байт** (важно: длинный пароль с одинаковым префиксом даёт тот же хэш).
- Устойчив к GPU лучше, чем PBKDF2, но всё же параллелизуем на ASIC.

```python
import bcrypt
h = bcrypt.hashpw(b"password", bcrypt.gensalt(rounds=12))
bcrypt.checkpw(b"password", h)
```

## scrypt

scrypt (2009) — **memory-hard**: требует много памяти на попытку (`N`, `r`, `p`). Память дорога для GPU/ASIC, поэтому scrypt значительно медленнее перебирается. Используется в криптовалютах (Litecoin), некоторых менеджерах паролей.

```python
import hashlib
dk = hashlib.scrypt(b"password", salt=b"salt", n=2**14, r=8, p=1)
```

## Argon2

Argon2 — победитель Password Hashing Competition (2015). Варианты: Argon2d (устойчив к GPU), Argon2i (устойчив к side-channel), **Argon2id** (гибрид, рекомендован). Параметры: память (MiB), итерации, parallelism. Современный стандарт для новых приложений.

```
$argon2id$v=19$m=65536,t=3,p=4$<salt>$<hash>
```

```python
from argon2 import PasswordHasher
ph = PasswordHasher()
h = ph.hash("password")
ph.verify(h, "password")
```

## Сравнение и параметры

| KDF | Memory-hard | Параллелизм | Рекомендация |
|---|---|---|---|
| PBKDF2 | нет | нет | 600k+ итераций (2023) |
| bcrypt | частично | нет | cost ≥ 12 |
| scrypt | да | ограничен | N=2^15+, r=8, p=1 |
| Argon2id | да | да | m=64MiB, t=3, p=4 |

## Практический пример: подбор в hashcat

```bash
# bcrypt
hashcat -m 3200 bcrypt.txt rockyou.txt
# sha512crypt ($6$)
hashcat -m 1800 shadow.txt rockyou.txt
# PBKDF2-HMAC-SHA256
hashcat -m 10900 pbkdf2.txt rockyou.txt
# Argon2
hashcat -m 34000 argon2.txt rockyou.txt
# scrypt
hashcat -m 8900 scrypt.txt rockyou.txt
```

Для bcrypt/argon2 словарь важнее железа: сильные пароли не ломаются.

## Частые ошибки

- **Использовать SHA-256 для паролей.** Быстро → ломается.
- **Малое число итераций/cost.** Не защищает.
- **Не использовать соль.** Радужные таблицы.
- **Одинаковая соль для всех.** Ломает уникальность.
- **bcrypt с паролем > 72 байт.** Обрезается.
- **Хранить соль отдельно от хэша** и терять её.

## Атаки на KDF

- **Rainbow-таблицы** — против несолёных хэшей; убиваются солью.
- **GPU/ASIC перебор** — против быстрых KDF (PBKDF2 без большого числа итераций).
- **Memory-hard обход** — ASIC с большим объёмом памяти дороги, что защищает scrypt/Argon2.
- **Side-channel** — Argon2d уязвим к side-channel на некоторых платформах; Argon2i/Argon2id — нет.
- **Слабые параметры** — `cost=5`, `iterations=1000`, малый `m` в Argon2 → ломается словарём.
- **Pepper** — секретный «перец» (ключ) добавляется к паролю вне БД; усложняет офлайн-атаку при утечке только хэшей.

## Миграция и практика

- Храните **алгоритм + параметры + соль** вместе с хэшем (формат `$argon2id$...`).
- При входе проверяйте хэш и **обновляйте параметры**, если они устарели (rehash on login).
- Не логируйте пароли и хэши.
- Для новых систем — **Argon2id** (m=64MiB, t=3, p=4) или bcrypt cost≥12.
- Для legacy — PBKDF2 с ≥600k итераций SHA-256.
- Проверяйте параметры автоматизированно (аудит БД хэшей).

## Разбор: оценка стойкости утечки

```python
# Определяем KDF по формату и оцениваем
# $2b$12$...        -> bcrypt cost 12 (~0.25s/попытка на CPU) -> словарь реально работает только для слабых паролей
# $argon2id$m=65536,t=3,p=4$ -> сильная защита, перебор непрактичен
# $6$rounds=5000$   -> sha512crypt с малым числом раундов -> ломается GPU
```

## Разбор: PBKDF2 и bcrypt изнутри

**PBKDF2-HMAC-SHA256** для пароля `p`, соли `s`, `c` итераций:

```python
import hashlib, hmac
def pbkdf2(p, s, c=600000, dklen=32):
    return hashlib.pbkdf2_hmac('sha256', p, s, c, dklen)
# каждая итерация = один HMAC -> c итераций = c HMAC
```

Чем больше `c`, тем медленнее. Атака: перебирать пароли, для каждого считать `c` HMAC — дорого, но GPU/ASIC справляются при малом `c`.

**bcrypt** использует модифицированный Blowfish (EksBlowfish): 2^cost раундов key schedule. Формат `$2b$cost$salt22$hash31`. Важно: пароль обрезается до 72 байт; salt 16 байт base64.

## Рекомендации по параметрам (2024)

| KDF | Параметры |
|---|---|
| Argon2id | m=19456 KiB (19 MiB), t=2, p=1 (OWASP min) |
| bcrypt | cost ≥ 12 |
| PBKDF2-HMAC-SHA256 | ≥ 600 000 итераций |
| scrypt | N=2^17, r=8, p=1 |

## Разбор: подбор bcrypt

```bash
# хэш: $2b$12$...
hashcat -m 3200 hash.txt rockyou.txt -w 3
# или john
john --format=bcrypt hash.txt --wordlist=rockyou.txt
```

Скорость: единицы-тысячи попыток/сек на GPU — поэтому только целевой словарь.

## Разбор: Argon2 и scrypt изнутри

**Argon2** использует «блоки» памяти и заполняет их в параллельных «полосах» (lanes), с зависимостями по данным (Argon2d) или по индексу (Argon2i). Argon2id — гибрид: первый проход по данным, остальные — по индексу. Параметры: `m` (память KiB), `t` (итерации), `p` (lanes).

**scrypt** — `N` (число блоков), `r` (размер блока), `p` (параллелизм). Память ~`128·N·r` байт. Атака требует столько же памяти на попытку, что дорого для GPU/ASIC.

## Разбор: подбор scrypt/PBKDF2

```bash
# PBKDF2-HMAC-SHA256
hashcat -m 10900 pbkdf2.txt rockyou.txt
# scrypt
hashcat -m 8900 scrypt.txt rockyou.txt
# Argon2id
hashcat -m 34000 argon2.txt rockyou.txt
```

## Как не застрять

- **Определите KDF по формату хэша** (`$2b$`, `$argon2id$`, `$6$`).
- **Выберите режим hashcat.**
- **Словарь + правила** для слабых паролей.
- **Не тратьте время** на bcrypt/argon2 с сильным паролем.
- **Проверьте параметры** — малый cost/итерации = уязвимо.
- **Для аудита** сравните параметры с OWASP-рекомендациями.
