## Вопрос, с которого всё начинается

В прошлом уроке мы собирали общий секрет DH. Но есть приём, который встречается почти в каждом серьёзном RSA-коде: разбить большое вычисление на два маленьких и собрать ответ обратно. Этот приём — китайская теорема об остатках (CRT). Вопрос новичка: «CRT я знаю как „систему сравнений“ — при чём тут взлом RSA?» При том, что именно сборка по CRT создаёт роковую уязвимость: **одна ошибочная подпись полностью раскрывает ключ**.

## Наш пример

В задаче даны модуль `n`, экспонента `e` и подпись `s` известного сообщения `m`, для которой `pow(s, e, n) != m` — подпись «испорчена». Задача: разложить `n`. Разберём, как устроен RSA-CRT, почему подпись может испортиться и как из этого вытащить множители.

## Шаг 1: CRT своими руками

Даны попарно взаимно простые модули `n1, …, nk` и остатки `a1, …, ak`. Нужно найти `x` со сравнениями `x ≡ ai (mod ni)`. Решение единственно по модулю `N = n1·…·nk`.

Почему единственно: если `x` и `y` — два решения, то `x − y` делится на каждый `ni`, а так как они взаимно просты — и на их произведение `N`. Значит `x ≡ y (mod N)`.

Как построить: положим `Ni = N / ni`, `yi = Ni⁻¹ mod ni`, тогда

```
x = Σ ai · Ni · yi   (mod N)
```

Проверка простая: для каждого `j` слагаемое с `i ≠ j` содержит множитель `Nj`, который делится на `nj` и обнуляется. Остаётся `aj·Nj·yj ≡ aj`. Работает.

## Шаг 2: формула Гарнера

Классический вариант требует `k` обратных элементов и промежуточных чисел размером `N` — для 20 модулей по 2048 бит это медленно. **Формула Гарнера** строит решение **по одному модулю за раз** и никогда не работает с числом размера `N`:

```
x1 = a1
x2 = (a2 - x1) · n1⁻¹            mod n2
x3 = (a3 - (x1 + n1·x2)) · (n1·n2)⁻¹   mod n3
...
x  = x1 + n1·x2 + n1·n2·x3 + ...
```

Каждый шаг использует только обратный элемент по текущему малому модулю. Именно так реализован аппаратный RSA-CRT.

## Шаг 3: RSA-CRT ускоряет расшифровку

Наивная расшифровка — `m = c^d mod n` с `d` длиной 2048 бит. Вместо этого считают отдельно:

```
mp = c^dp mod p,   dp = d mod (p-1)
mq = c^dq mod q,   dq = d mod (q-1)
```

Каждое возведение — это `O(log p)` умножений 1024-битных чисел, примерно вчетверо быстрее. Затем `mp` и `mq` собираются по CRT (это и есть формула Гарнера для двух модулей):

```
qinv = q⁻¹ mod p
h = qinv · (mp - mq) mod p
m = mq + h·q
```

Приватный ключ в этом режиме хранится как `(p, q, dp, dq, qinv)`.

## Шаг 4: одна ошибка ломает ключ

Теперь уязвимость. Пусть при вычислении `mq` произошёл сбой (питание, перегрев, радиация): `mq' = mq + ошибка`. Тогда итоговая подпись `s'`:

```
s' ≡ m (mod p)     ← половина по p не пострадала
s' ≢ m (mod q)     ← половина по q испорчена
```

Значит `s'^e ≡ m (mod p)`, но `s'^e ≢ m (mod q)`. Разность `s'^e − m` **делится на p**, но **не делится на q**. Следовательно:

```
gcd(s'^e − m, n) = p     ← n разложен одним gcd!
```

Важно: `gcd` берётся именно от `s'^e − m`, а не от `s' − m`. И подпись должна быть **действительно** ошибочной — иначе `gcd(n, 0) = n`, это не множитель. Проверяйте `pow(s', e, n) != m`.

## Шаг 5: полный прогон

Соберём атаку на маленьких числах, чтобы увидеть её целиком:

```python
p, q = 1000003, 1000033
n = p*q; e = 65537; d = pow(e, -1, (p-1)*(q-1))
m = 0x414243
dp, dq = d % (p-1), d % (q-1); qinv = pow(q, -1, p)
mp, mq = pow(m, dp, p), pow(m, dq, q)
h = (qinv*(mp - mq)) % p; s_good = mq + h*q
assert pow(s_good, e, n) == m                 # честная подпись верна

mq_bad = (mq + 1) % q                          # имитируем сбой
h = (qinv*(mp - mq_bad)) % p; s_bad = mq_bad + h*q
assert pow(s_bad, e, n) != m                   # подпись ошибочна

rec = gcd((pow(s_bad, e, n) - m) % n, n)
print(rec, n // rec)
```

```
good signature valid: True
faulty signature invalid: True
recovered factor: 1000003   == p: True
other factor: 1000033
recovered d works: True
```

Множители `p` и `q` найдены из **одной** испорченной подписи. Дальше `d = e⁻¹ mod (p−1)(q−1)` — и ключ полностью восстановлен. В реальности, если `m` неизвестно, но есть **две** ошибочные подписи одного сообщения, `gcd(s1 − s2, n)` тоже часто даёт множитель: ошибки разные, а их разность делится на один из простых.

## Шаг 6: подъём Гензеля и неполные остатки

Иногда модули **не** взаимно просты. Тогда решение может не существовать, а если существует — единственно лишь по модулю `lcm(ni)`. Для степеней одного простого (`p^k`) на помощь приходит **лемма Гензеля**: решение по модулю `p` поднимается до `p²`, затем до `p³` и так далее. Это основа атак на RSA с частично известным `p` и решёточных атак (Coppersmith).

И ещё одно применение: если секрет `s` разбит схемой разделения и известны лишь **некоторые** сравнения `s ≡ ai (mod ni)`, CRT даёт единственное значение по модулю произведения известных модулей. Когда это произведение превышает `s`, секрет восстанавливается полностью — так ломают «неполные» secret-sharing задачи.

## Что мы теперь знаем

- CRT собирает `x` из остатков; решение единственно по модулю `N`.
- **Формула Гарнера** строит его по одному модулю за раз, без чисел размера `N`.
- RSA-CRT считает `c^d mod p` и `c^d mod q`, затем собирает ответ — это в ~4 раза быстрее.
- Ошибка в одной половине даёт `gcd(s^e − m, n) = p` — **Bellcore**.
- `gcd` берётся от `s^e − m`; подпись обязана быть действительно ошибочной.
- **Гензель** поднимает решение по `p^k`; CRT реконструирует секрет из частичных долей.
