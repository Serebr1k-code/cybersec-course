В `crypto-number-theory` вы познакомились с CRT на уровне «система сравнений имеет единственное решение». Здесь мы пойдём дальше: научимся строить решение без `sympy`, поймём **формулу Гарнера**, которой реально пользуются аппаратные RSA-модули, и главное — научимся **ломать RSA-CRT** по одной ошибочной подписи (классическая атака Bellcore). Это один из самых «денежных» навыков в крипто-CTF: одна подпись с ошибкой из-за сбоя питания или космического луча полностью раскрывает приватный ключ.

## CRT: конструктивное доказательство

Напомним постановку. Даны попарно взаимно простые модули `n1, n2, ..., nk` и остатки `a1..ak`. Нужно найти `x`, удовлетворяющий всем сравнениям `x ≡ ai (mod ni)`. Решение единственно по модулю `N = n1·n2·...·nk`.

**Почему единственно.** Если `x` и `y` — два решения, то `x - y ≡ 0 (mod ni)` для всех `i`, значит `x - y` делится на каждое `ni`. Так как модули попарно взаимно просты, `x - y` делится на их произведение `N`. Значит `x ≡ y (mod N)`.

**Как построить.** Классический рецепт (интерполяция Лагранжа по кольцу `Z/NZ`): положим

```
Ni = N / ni          (произведение всех модулей кроме i)
yi = Ni^{-1} mod ni  (обратный элемент существует, т.к. gcd(Ni, ni) = 1)
x  = Σ ai · Ni · yi  (mod N)
```

Проверка: для каждого `j` слагаемое `ai·Ni·yi` при `i ≠ j` содержит множитель `Nj`, который делится на `nj`, то есть обнуляется по модулю `nj`. Остаётся `aj·Nj·yj ≡ aj·1 = aj (mod nj)`. Работает.

```python
def egcd(a, b):
    if b == 0: return a, 1, 0
    g, x, y = egcd(b, a % b)
    return g, y, x - (a // b) * y

def crt_classic(remainders, moduli):
    N = 1
    for m in moduli: N *= m
    x = 0
    for a, m in zip(remainders, moduli):
        Ni = N // m
        g, inv, _ = egcd(Ni % m, m)
        assert g == 1, "модули не взаимно просты"
        x = (x + a * Ni * (inv % m)) % N
    return x, N
```

Этот вариант хорош для понимания, но требует `k` обратных элементов и промежуточных чисел размером `N`. Для больших `k` (например, 20+ модулей по 2048 бит) это неудобно и медленно.

## Формула Гарнера

**Формула Гарнера (Garner's algorithm)** строит решение **последовательно**, по одному модулю за раз, и никогда не работает с числом размером `N`. Вместо этого поддерживается набор цифр `(x1, x2, ..., xk)` в смешанной системе счисления:

```
x1 = a1
x2 = (a2 - x1) · n1^{-1}   mod n2
x3 = (a3 - (x1 + n1·x2)) · (n1·n2)^{-1}  mod n3
...
```

Итоговое `x = x1 + n1·x2 + n1·n2·x3 + ...`. Каждый шаг использует только обратный элемент по текущему малому модулю.

```python
def garner(remainders, moduli):
    x = [0] * len(moduli)
    for i in range(len(moduli)):
        acc = remainders[i]
        for j in range(i):
            acc = (acc - x[j]) * pow(moduli[j], -1, moduli[i]) % moduli[i]
        x[i] = acc
    # собрать значение по модулю N
    result = 0
    mult = 1
    for i in range(len(moduli)):
        result += x[i] * mult
        mult *= moduli[i]
    return result % mult, mult
```

**Зачем это в крипто.** Именно так реализован RSA-CRT: аппаратный модуль считает `m mod p` и `m mod q`, а затем **собирает** ответ по формуле Гарнера (не храня `N`-разрядных промежуточных значений). Понимая Гарнера, вы понимаете, где именно возникает ошибка при сбое и почему одна ошибка рушит весь ключ.

## RSA-CRT: как ускоряют расшифрование

Наивная расшифровка RSA — это `m = c^d mod n`, где `d` может быть 2048 бит. Возведение в такую степень стоит `O(log d)` модульных умножений 2048-битных чисел. Оптимально: считать отдельно

```
mp = c^dp mod p,   dp = d mod (p-1)
mq = c^dq mod q,   dq = d mod (q-1)
```

Каждое возведение — это `O(log p)` умножений 1024-битных чисел, то есть примерно в **4 раза быстрее** (по времени ~в 3–4 раза). Затем собираем `m` по CRT:

```
qinv = q^{-1} mod p
h = qinv · (mp - mq) mod p
m = mq + h · q
```

Это и есть формула Гарнера для двух модулей. Приватный ключ в этом режиме хранится как `(p, q, dp, dq, qinv)`.

```python
def rsa_crt_decrypt(c, p, q, dp, dq, qinv):
    mp = pow(c, dp, p)
    mq = pow(c, dq, q)
    h = (qinv * (mp - mq)) % p
    return mq + h * q
```

## Атака по ошибкам (Bellcore / Boneh–DeMillo–Lipton)

Теперь самое интересное. Предположим, при вычислении одной из половин (`mp` или `mq`) произошла **ошибка** — сбой питания, перегрев, радиация. Пусть правильны `mp`, но `mq' = mq + e` (ошибочно). Тогда итоговая подпись `s'`:

```
s' ≡ m (mod p)     ← половина по p не пострадала
s' ≢ m (mod q)     ← половина по q испорчена
```

Значит `s'^e ≡ m (mod p)`, но `s'^e ≢ m (mod q)`. Тогда разность `s'^e - m` **делится на p**, но **не делится на q**. Следовательно:

```
gcd(s'^e - m, n) = p     ← и n разложен!
```

Одна ошибочная подпись — и `n` факторизуется одним `gcd`. Осталось проверить, что подпись действительно ошибочна (иначе `gcd` вернёт `n`).

```python
from math import gcd

def bellcore(n, e, m, s_faulty):
    # m — известное подписанное сообщение (или его хэш), s_faulty — подпись с ошибкой
    diff = (pow(s_faulty, e, n) - m) % n
    p = gcd(diff, n)
    if 1 < p < n:
        q = n // p
        return p, q
    return None
```

**Когда применять.** В условии даны `n, e` и **несколько подписей** одного сообщения (или подписи разных сообщений), из которых одна ведёт себя «не так»: `s^e mod n ≠ m`. Также классика — даны `n, e` и подпись, для которой `pow(s, e, n) != m`, но сообщение известно. Тогда Bellcore.

**Важно:** `gcd` надо брать от `s^e - m`, а не от `s - m`. Если `m` неизвестно (нельзя восстановить), но известны **две** ошибочные подписи `s1, s2` одного `m`, то `gcd(s1 - s2, n)` тоже часто даёт множитель (ошибки разные, их разность делится на один из простых).

## Подъём Гензеля и неполные остатки

Иногда модули **не** взаимно просты. Тогда решение может не существовать, а если существует — оно единственно лишь по модулю `lcm(ni)`. Для степеней одного простого (`p^k`) CRT вырождается, и на помощь приходит **лемма Гензеля**: решение по модулю `p^k` поднимается до `p^(k+1)`.

Пример: если `x ≡ a (mod p)` и `f(x) ≡ 0 (mod p)`, то `x' = x - f(x)·(f'(x))^{-1} mod p` даёт решение по `p^2`. Это основа атак на RSA с частично известным `p` и на Coppersmith.

```python
def hensel_lift(f, fp, x, p, k):
    # поднять корень x по модулю p до p^k
    mod = p
    for _ in range(k - 1):
        x = (x - f(x) * pow(fp(x), -1, p)) % (mod * p)
        mod *= p
    return x
```

**Реконструкция секрета из частичных долей.** Если секрет `s` разбит схемой разделения на доли и известны только некоторые сравнения `s ≡ ai (mod ni)`, CRT даёт **единственное** значение по модулю произведения известных модулей. Когда это произведение превышает `s`, секрет восстанавливается полностью — именно так ломают «неполные» secret-sharing задачи.

## Разобранный пример: Bellcore на конкретных числах

```python
from math import gcd

p, q = 1000003, 1000033        # маленькие простые для наглядности
n = p * q
e = 65537
phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)

m = 0x414243                      # подписываем "ABC"

# честная RSA-CRT подпись
dp, dq = d % (p - 1), d % (q - 1)
qinv = pow(q, -1, p)
mp = pow(m, dp, p)
mq = pow(m, dq, q)
h = (qinv * (mp - mq)) % p
s_good = mq + h * q
assert pow(s_good, e, n) == m

# имитируем сбой: одна половина (mq) испорчена
mq_bad = (mq + 1) % q
h = (qinv * (mp - mq_bad)) % p
s_bad = mq_bad + h * q
assert pow(s_bad, e, n) != m         # подпись ошибочна

# Bellcore
diff = (pow(s_bad, e, n) - m) % n
recovered = gcd(diff, n)
print("recovered factor:", recovered)
print("is p?", recovered == p, " is q?", recovered == q)
# recovered = 1000003 (или 1000033) -> n разложен по одной подписи
```

Запустите — увидите, что `recovered` совпадает с одним из простых множителей. Дальше `q = n // p`, `d = e^{-1} mod (p-1)(q-1)` — и ключ полностью восстановлен.

## Частые ошибки

- **Брать `gcd(s - m, n)` вместо `gcd(s^e - m, n)`.** Множитель даёт именно разность **степени** и сообщения.
- **Забыть проверить ошибочность подписи.** Если подпись корректна, `gcd(n, 0) = n` — это не множитель. Всегда проверяйте `pow(s, e, n) != m`.
- **Считать `Ni^{-1}` в классическом CRT при больших числах.** Используйте Гарнера — он не строит промежуточное `N`-разрядное значение.
- **Путать `d mod (p-1)` и `d`.** В RSA-CRT показатель по `p` — это `d mod (p-1)`, а не `d`.
- **Игнорировать `gcd` двух ошибочных подписей.** Если `m` неизвестно, `gcd(s1 - s2, n)` часто всё ещё работает.

## Где пригодится

- **CTF crypto:** атаки Bellcore, реконструкция секрета из частичных долей, разбиение секрета.
- **Bug bounty / пентест:** анализ аппаратных HSM/смарт-карт, где RSA-CRT уязвим к сбоям.
- **Аудит кода:** понимание, как библиотеки хранят и собирают ключ RSA-CRT, и где ошибка раскрывает ключ.
- **Работа (SOC/IR):** понимание класса fault-атак на устройства и их детекции.
- **Крипто-разработка:** почему нельзя «молча» возвращать результат при обнаружении ошибки подписи.
