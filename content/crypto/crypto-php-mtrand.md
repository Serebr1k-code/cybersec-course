## Зачем это нужно

`crypto-prng` и `crypto-mt19937-deep` дают теорию: MT19937 предсказуем по 624 выходам, LCG восстанавливается по нескольким значениям. Но на практике атака зависит от **конкретного языка и его обёртки** над генератором. PHP, Java, Python по-разному усекают и сидят свои ГПСЧ, и знание этих деталей превращает «теоретически предсказуемо» в «восстановил за минуту». На CTF токены, пароли, сессии и «случайные» id почти всегда генерируются слабым ГПСЧ, и именно эта специализация решает задачу.

## PHP mt_rand: MT19937 с нюансами

PHP использует MT19937, но с двумя важными особенностями:

- **Диапазон**: `mt_rand()` без аргументов возвращает число от 0 до `mt_getrandmax()` = `2^31 - 1`. То есть выход — **31 бит**, а не 32. Это значит, что старший бит теряется.
- **`mt_rand($min, $max)`** делает `min + mt_rand() % (max - min + 1)` — при этом может браться несколько выходов генератора, и восстановление усложняется.
- **`mt_rand` — не `rand`**: до PHP 7.1 `rand()` был отдельным (libc) генератором; в 7.1+ `rand` — алиас `mt_rand`. Это важно: старые приложения используют два независимых состояния.

Инициализация: `mt_srand(seed)` задаёт состояние; без явного seed PHP берёт энтропию. Если seed известен или мал (например, время), состояние восстанавливается.

Ключевой факт: 31-битный выход — это MT19937 с **обнулённым старшим битом** (tempering сохраняет старший бит, поэтому его можно восстановить перебором двух вариантов на выход). По 624 выходам состояние восстанавливается полностью, и дальше все `mt_rand` предсказуемы.

## Восстановление состояния и php_mt_seed

Два сценария:

**Известен вывод (624+ значений)**: восстанавливаем состояние MT19937, учитывая усечение до 31 бита. Для каждого выхода есть 2 варианта старшего бита, что даёт `2^624` комбинаций — но на практике используют более умные методы (например, решение через решётки или инкрементальное восстановление), а чаще просто **seed**.

**Известен seed (или его диапазон)**: `php_mt_seed` перебирает seed и ищет тот, который даёт наблюдаемые выходы. Это самый частый сценарий на CTF: приложение делает `mt_srand(time())`, и нужно найти seed.

```bash
# php_mt_seed: дать первые несколько выходов mt_rand
php_mt_seed 1234567890 987654321 555555555
# программа переберёт seed и выведет найденные
```

Пример: если приложение сгенерировало токен из `mt_rand()` и мы видим пару значений, `php_mt_seed` находит seed, после чего можно предсказать следующие значения.

## Java Random: 48-битный LCG

`java.util.Random` — **линейный конгруэнтный генератор** с 48-битным состоянием:

```
seed = (seed * 0x5DEECE66D + 0xB) & ((1<<48)-1)
```

`next(bits)` возвращает старшие `bits` бита нового состояния. `nextInt()` возвращает 32 бита (старшие 32 из 48), `nextInt(n)` может комбинировать.

**Восстановление по двум выходам**: `nextInt()` даёт 32 старших бита состояния. Два последовательных выхода дают 64 бита, из которых 48 — это состояние (после первого вызова). Перебором 16 неизвестных младших бит (2^16) восстанавливается полное состояние, и далее все значения предсказуемы.

```python
def java_random_recover(out1, out2):
    # out1, out2 — два последовательных nextInt() (32 бита)
    for low in range(1 << 16):
        seed1 = (out1 << 16) | low
        # продвигаем LCG один раз
        seed2 = (seed1 * 0x5DEECE66D + 0xB) & ((1 << 48) - 1)
        if (seed2 >> 16) == (out2 & 0xFFFFFFFF):
            return seed1
    return None
```

Это классическая CTF-задача: два «случайных» числа → полное предсказание.

## Другие языки: краткое сравнение

- **Python `random`** — MT19937, `getrandbits(32)` даёт 32 бита; восстановление по 624 выходам (`randcrack`). `random.seed()` из времени/строки легко перебирается.
- **C `rand()`** — зависит от libc: glibc использует additive feedback (не LCG), MSVC — LCG. Поведение различается, что усложняет переносимые атаки.
- **`Math.random()` в JS** — обычно xorshift128+ (V8), предсказуем по нескольким выходам (см. z3-решатели).
- **Ruby `rand`** — MT19937, но с другим seeding.

Общий принцип: найдите генератор, определите его состояние и число необходимых выходов, восстановите состояние, предскажите.

## Инструменты и команды

## Разобранный пример: предсказание токена PHP

1. Приложение выдаёт «случайный» токен из `mt_rand()` при регистрации.
2. Мы регистрируемся и видим свой токен, а также токены других (если утекают).
3. Запускаем `php_mt_seed` по наблюдаемым значениям.
4. Находим seed (например, `time()`), восстанавливаем состояние.
5. Генерируем следующие значения и предсказываем токен жертвы/админа.
6. Используем предсказанный токен для доступа.

Это реальный класс уязвимостей (CVE в PHP-приложениях, где токены сброса пароля брались из `mt_rand`).

## C rand() и glibc: additive feedback

Отдельного внимания заслуживает C `rand()`, потому что он встречается в огромном количестве legacy-кода и встроенных систем, и его поведение зависит от libc.

**glibc `rand()`** использует не LCG, а **additive feedback generator** (TRANSFORM с массивом из 31 значения). Состояние — 31 число типа `int32`, и генератор продвигается по формуле `r[i] = r[i-3] + r[i-31]` (по модулю 2^32). Это даёт период порядка `2^31 * 31`. Восстановление состояния возможно, но требует больше выходов, чем LCG, и часто используется предсказание через решётки или прямую реконструкцию массива.

**MSVC `rand()`** — простой LCG с 32-битным состоянием, восстанавливается по нескольким значениям. **BSD `rand()`** — другой LCG. Это означает, что переносимая атака на `rand()` требует сначала определить libc, а затем применить соответствующий метод.

Практический вывод для CTF: если в задаче есть C-код с `rand()` и `srand(time(NULL))`, сначала определите платформу (по бинарнику, по выводу), затем переберите seed в диапазоне времени или восстановите состояние. Для glibc часто проще перебрать seed (диапазон времени небольшой), чем восстанавливать 31-элементное состояние.

## Практические сценарии: токены, пароли, id

Слабые ГПСЧ встречаются в безопасности повсюду, и понимание конкретного генератора превращает это в практическую атаку. Разберём типичные сценарии.

**Токены сброса пароля.** Приложение генерирует токен через `mt_rand()` или `Random.nextInt()`. Если токен короткий или сгенерирован предсказуемо, атакующий, получив свой токен (или увидев чужие в логах/письмах), восстанавливает состояние и предсказывает токен жертвы. Это реальный класс CVE: множество PHP-приложений использовали `mt_rand` для токенов.

**«Случайные» id и сессии.** Если id сессии или заказа генерируется LCG, по нескольким своим значениям можно предсказать чужие (IDOR через предсказание). Java-приложения с `new Random()` особенно уязвимы — два `nextInt()` дают полное состояние.

**Верификационные коды и OTP.** Если код из 6 цифр генерируется `mt_rand(0, 999999)`, и известен seed (или несколько выходов), код предсказуем без перебора миллиона.

**Крипто-ключи из слабого ГПСЧ.** Худший случай: ключ шифрования выводится из `mt_rand`/`Random`. Тогда атакующий восстанавливает состояние и получает ключ напрямую — это полная компрометация.

Общий рабочий процесс: (1) определить язык и генератор по коду/поведению, (2) собрать достаточное число выходов, (3) восстановить seed или состояние, (4) предсказать целевое значение. На CTF это почти всегда решаемый за минуты сценарий, если правильно определить генератор.

## Частые ошибки и подводные камни

- **Забыть про 31 бит PHP** — старший бит теряется, нужен перебор.
- **Путать `rand` и `mt_rand`** в старых версиях PHP.
- **`mt_rand(min,max)`** использует модуль — выход не прямое значение ГПСЧ.
- **Java `nextInt(n)`** комбинирует вызовы — нужно понимать, сколько.
- **Seed из времени** — нужен диапазон (например, ±несколько часов), а не точное значение.
- **Считать генератор «безопасным»**, потому что он «криптографический» — mt_rand/random не криптостойки.
- **Забыть про версию языка**: поведение `rand`/`mt_rand` менялось между версиями PHP, а `Random` — между JDK.

## Контрмеры и защита

- Для токенов/паролей/сессий используйте **криптостойкие** генераторы: `random_bytes`/`random_int` (PHP), `SecureRandom` (Java), `secrets`/`os.urandom` (Python), `crypto.randomBytes` (Node).
- Никогда не сидьте ГПСЧ временем для безопасности.
- Для токенов сброса — достаточная длина (128+ бит энтропии).
- Регулярно аудируйте код на `mt_rand`/`Random` в безопасности-критичных местах.

Предсказание ГПСЧ соединяет `crypto-prng`, `crypto-mt19937-deep` и `crypto-lcg`. Дальше: `crypto-cache-attacks` (side-channel), `crypto-jwt-crypto` (токены). На CTF определите язык/генератор, соберите нужное число выходов, восстановите состояние — и предсказывайте.
