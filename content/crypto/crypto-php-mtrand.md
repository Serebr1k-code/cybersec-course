## Вопрос, с которого всё начинается

Java-приложение выдаёт «случайные» идентификаторы заказов: `1820451251`, `1221384887`. Мы видим два своих ID и хотим предсказать ID чужого заказа — классический IDOR через предсказание. Оказывается, `java.util.Random` — это не Mersenne Twister, а маленький линейный генератор, и двух чисел достаточно, чтобы восстановить всё состояние. Разберём это, а заодно особенности PHP `mt_rand`.

## Наш пример

У нас есть два последовательных значения `nextInt()` из Java `Random`:

```
1820451251
1221384887
```

Вопрос: можно ли по ним восстановить генератор и предсказать третье? Да — но сначала посмотрим, как `java.util.Random` устроен внутри.

## Шаг 1: Java Random — это LCG

`java.util.Random` — не MT19937, а **линейный конгруэнтный генератор** (LCG) с 48-битным состоянием. Каждый шаг обновляет состояние по формуле:

```
seed = (seed * 0x5DEECE66D + 0xB) & ((1 << 48) - 1)
```

Затем `next(bits)` возвращает **старшие** `bits` бит нового состояния. `nextInt()` — это `next(32)`, то есть верхние 32 бита из 48. Значит, каждое число, которое мы видим, — это 32 из 48 бит состояния; младшие 16 бит скрыты.

## Шаг 2: восстановление по двум выходам

Два числа дают 64 бита наблюдений, а состояние — 48 бит. Переберём всего `2^16 = 65536` вариантов неизвестных младших бит первого выхода, продвинем LCG на шаг и проверим, совпадает ли второй выход:

```python
def java_next(seed):
    return (seed * 0x5DEECE66D + 0xB) & ((1 << 48) - 1)

v1, v2 = 1820451251, 1221384887
for low in range(1 << 16):
    cand = (v1 << 16) | low
    if (java_next(cand) >> 16) == v2:
        print("recovered state:", cand)
        break
```

```
recovered state: 119305093197820
```

Перебор мгновенный. Теперь состояние известно, и все будущие `nextInt()` предсказуемы — включая ID жертвы. Это и есть «два числа → полное предсказание», самая частая Java-задача на CTF.

## Шаг 3: PHP mt_rand — MT19937 с усечением

PHP тоже использует MT19937, но с двумя важными особенностями:

- `mt_rand()` без аргументов возвращает число от 0 до `2^31 - 1`, то есть **31 бит**, а не 32. Старший бит теряется.
- `mt_rand($min, $max)` делает `min + mt_rand() % ($max - $min + 1)` — при этом может браться несколько выходов, и восстановление усложняется.
- До PHP 7.1 `rand()` был отдельным (libc) генератором; в 7.1+ `rand` — алиас `mt_rand`. Старые приложения держат два независимых состояния.

31-битный выход — это MT19937 с обнулённым старшим битом, поэтому по 624 значениям состояние всё ещё восстанавливается (нужно лишь перебрать варианты старшего бита). Но на практике почти всегда проще найти **seed**.

## Шаг 4: php_mt_seed — перебор seed

Если приложение делает `mt_srand(time())` при старте, seed — это метка времени, и её окно небольшое. Инструмент `php_mt_seed` перебирает seed и ищет тот, который воспроизводит наблюдаемые выходы:

```bash
# дать первые несколько значений mt_rand()
php_mt_seed 1234567890 987654321 555555555
```

Программа выведёт найденные seed-кандидаты. Взяв seed, вы восстанавливаете состояние и предсказываете все следующие `mt_rand` — включая токен жертвы. Это реальный класс уязвимостей: множество PHP-приложений брали токены сброса пароля из `mt_rand`.

## Шаг 5: другие языки — общий принцип

- **Python `random`** — MT19937, 32 бита, восстановление по 624 выходам (`randcrack`).
- **C `rand()`** — зависит от libc: glibc использует additive feedback (не LCG), MSVC — LCG. Сначала определите платформу.
- **`Math.random()` в JS** — обычно xorshift128+ (V8), предсказуем по нескольким выходам.
- **Ruby `rand`** — MT19937, но с другим seeding.

Общий рабочий процесс одинаков: определить язык и генератор, собрать достаточное число выходов, восстановить seed или состояние, предсказать целевое значение.

Инструменты для этого: `php_mt_seed` перебирает seed PHP, `randcrack` восстанавливает MT19937 по 624 значениям, `z3` решает нестандартные случаи, а для Java LCG хватает пары десятков строк своего кода. Всегда уточняйте **версию** языка: поведение `rand`/`mt_rand` менялось между версиями PHP, а `Random` — между релизами JDK.

## Шаг 6: C rand() и glibc — генератор зависит от libc

Отдельного внимания заслуживает C `rand()`, потому что он встречается в legacy-коде и встроенных системах, а его поведение зависит от библиотеки. **glibc** использует не LCG, а **additive feedback generator** с массивом из 31 значения: состояние продвигается как `r[i] = r[i-3] + r[i-31]` по модулю 2^32. Восстановление возможно, но требует больше выходов, чем LCG. **MSVC** `rand()` — простой 32-битный LCG, восстанавливается по нескольким значениям; **BSD** — свой LCG. Вывод для CTF: если есть C-код с `rand()` и `srand(time(NULL))`, сначала определите платформу (по бинарнику или выводу), затем либо переберите seed в окне времени, либо восстановите состояние. Для glibc чаще проще перебрать seed, чем реконструировать 31-элементный массив.

## Полный прогон: предсказание ID заказа на Java

Соберём атаку целиком. Приложение делает `new Random()` (или сидит текущим временем) и выдаёт ID заказов. Мы создаём два заказа и записываем их ID — это два последовательных `nextInt()`.

1. Берём два числа `v1`, `v2` и восстанавливаем состояние перебором 2^16 младших бит (Шаг 2).
2. Убеждаемся, что найденное состояние воспроизводит оба ID.
3. Продвигаем LCG вперёд нужное число шагов — и получаем ID чужого заказа, который сервер ещё не выдал.

Если приложение использует `SecureRandom`, атака не работает: там нет линейной структуры. Поэтому первый шаг аудита — определить **класс** генератора по коду: `java.util.Random` и `Math.random` ломаются, `SecureRandom` — нет.

## Что мы теперь знаем

- `java.util.Random` — **48-битный LCG**; двух `nextInt()` хватает для полного восстановления.
- PHP `mt_rand()` даёт **31 бит** (старший бит теряется) поверх MT19937.
- Для PHP чаще всего находят seed инструментом `php_mt_seed`.
- До PHP 7.1 `rand` и `mt_rand` — разные генераторы.
- `randint`/`mt_rand(min,max)` используют модуль, а не прямое значение генератора.
- Стойкие альтернативы: `SecureRandom` (Java), `random_bytes`/`random_int` (PHP), `secrets` (Python).

## На что смотреть дальше

- **Забыть про 31 бит PHP** — старший бит теряется, нужен перебор вариантов.
- **Путать `rand` и `mt_rand`** в старых версиях PHP — там два независимых состояния.
- **`mt_rand(min, max)`** — выход не прямое значение ГПСЧ, а результат модуля.
- **Java `nextInt(n)`** комбинирует несколько вызовов — считайте, сколько именно.
- **Seed из времени** — нужен диапазон (часы), а не точное значение.
- **Считать генератор «безопасным»**, потому что он «криптографический» — `mt_rand`/`Random` не криптостойки.
