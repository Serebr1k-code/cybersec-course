## Вопрос, с которого всё начинается

Разбирая чужой RSA-ключ, вы замечаете странность: экспонента `e` не 65537, а огромное число почти в размер `n`. Это верный признак того, что кто-то выбрал **маленький приватный ключ `d`** ради скорости расшифрования. И это фатально: малый `d` восстанавливается из публичного ключа. Разберём, как именно, и где проходит граница.

## Наш пример

Сгенерируем уязвимый ключ и убедимся, что `e` действительно огромно:

```python
from sympy import nextprime
from math import gcd
p = nextprime(2**511); q = nextprime(2**512)
n = p*q; phi = (p-1)*(q-1)
d = 0x1a2b3
while gcd(d, phi) != 1: d += 1
e = pow(d, -1, phi)
print("e bits:", e.bit_length(), "n bits:", n.bit_length())
```

```
e bits: 1024 n bits: 1024
```

`e` практически совпадает по размеру с `n`. Вопрос: как восстановить `d`?

## Шаг 1: атака Винера (малый d)

При `d < n^{0.25}/3` ключ ломается **цепными дробями** (см. `crypto-continued-fractions`). Идея: из `e·d ≡ 1 (mod φ)` следует `e·d − k·φ = 1`, то есть `e/φ ≈ k/d`. Поскольку `φ ≈ n`, дробь `k/d` — приближение к `e/n`, и по теореме Лежандра она попадает среди подходящих дробей (convergents).

```python
from sympy import Rational, continued_fraction, continued_fraction_convergents
from math import isqrt

def wiener(n, e):
    for conv in continued_fraction_convergents(continued_fraction(Rational(e, n))):
        k, d = int(conv.p), int(conv.q)
        if k == 0: continue
        if (e*d - 1) % k: continue
        phi = (e*d - 1) // k
        s = n - phi + 1; disc = s*s - 4*n
        if disc < 0: continue
        t = isqrt(disc)
        if t*t == disc and (s+t) % 2 == 0:
            return d
    return None

print("d =", hex(wiener(n, e)))
```

```
d = 0x1a2b5
```

Ключ восстановлен. Расшифровываем и получаем сообщение — так же, как в уроке про цепные дроби.

## Шаг 2: как распознать малый d

- `e` **почти равен** `n` (совпадает большая часть бит) → сильный намёк.
- Задача говорит «быстрая расшифровка», «оптимизация параметров».
- `e` нестандартное (не 65537) и огромное.
- `d` перебирается быстро (десятки бит) → вообще brute-force.

Если хоть один признак есть — пробуйте Винера первым делом: он дешёвый.

## Шаг 3: проверка кандидата

Для каждой подходящей дроби `(k, d)`:

1. `(e·d − 1) % k == 0`? Иначе пропускаем.
2. `φ = (e·d − 1) // k`.
3. `s = n − φ + 1` (это `p+q`).
4. Дискриминант `s² − 4n` — полный квадрат? Тогда `p, q` целые.

Если все условия выполнены — нашли `d`. Кандидатов немного, проверка мгновенна. Восстановив `d`, легко получить и `p, q`:

```python
phi = (e*d - 1) // k
s = n - phi + 1
t = isqrt(s*s - 4*n)
p, q = (s + t)//2, (s - t)//2
```

## Шаг 4: граница и Boneh-Durfee

Винер работает до `d < n^{0.25}/3`. Если `d` больше, он не сработает — но есть усиление. **Boneh–Durfee** расширяет границу до `d < n^{0.292}`, используя **решётки** (LLL/BKZ, см. `crypto-lattice`). Основное уравнение переписывается через `A = n + 1` и `s = p + q`:

```
e·d = 1 + k·(A − s)
```

Строится полином `f(x, y) = 1 + x·(A − y)` с малыми корнями `(k, s)`, из его коэффициентов собирается решётка, применяется LLL/BKZ, и из короткого вектора извлекаются `k` и `d`.

```python
# Sage (скелет):
# 1. построить полиномы x^i * f(x,y)^j * e^(m-j)
# 2. составить решётку (basis)
# 3. LLL / BKZ
# 4. извлечь d из найденного вектора
```

| Метод | Граница `d` | Инструмент |
|---|---|---|
| Винер | `< n^0.25 / 3` | цепные дроби (sympy) |
| Boneh-Durfee | `< n^0.292` | решётки (Sage+LLL) |
| Полный перебор | десятки бит | brute-force |

Обратите внимание: граница `0.292` — **асимптотическая**. Для конкретного 1024-битного `n` практическая граница ближе к `n^0.28`, потому что решёточные атаки зависят от размеров и параметров решётки. Но направление верное: Boneh-Durfee покрывает диапазон шире, чем Винер, ценой сложной реализации.

## Шаг 5: почему `e/n` даёт `k/d`

Из `e·d − k·φ(n) = 1` следует `e/φ(n) = k/d + 1/(d·φ(n))`. Поскольку `φ(n) ≈ n`, а `1/(d·φ)` очень мало, дробь `e/n` близка к `k/d`. Теория цепных дробей гарантирует: если `|e/n − k/d| < 1/(2d²)`, то `k/d` — подходящая дробь `e/n`. Условие `d < n^{0.25}/3` как раз обеспечивает это неравенство. Именно поэтому Винер требует именно такой границы — не «магическое число», а следствие теоремы Лежандра.

## Шаг 6: другие атаки на малый d

- **Wiener:** `d < n^0.25/3` — цепные дроби, быстро.
- **Boneh-Durfee:** `d < n^0.292` — решётки, медленно (Sage).
- **Перебор:** `d` совсем мал (десятки бит) — brute-force по `k`.
- **Partial d:** известны старшие биты `d` — решётка/HNP (hidden number problem).

Последний случай особенно практичен: если задача утекает половину бит `d`, решёточная атака восстанавливает остальное. Общий принцип у всех один — малый или частично известный `d` оставляет в публичном ключе «структуру», которая извлекается цепными дробями или решётками. Чем меньше `d`, тем проще атака; Винер — самый дешёвый вход в это семейство.

## Что мы теперь знаем

- Малый `d` — результат «оптимизации», и он ломается.
- **Винер:** `d < n^{0.25}/3`, цепные дроби `e/n` дают `k/d`.
- **Boneh–Durfee:** `d < n^{0.292}`, решётки (LLL/BKZ), Sage.
- Признак: `e` огромное, почти как `n`.
- Кандидат проверяют по делимости `(e·d−1)` на `k` и полному квадрату дискриминанта.
- Из `d` легко восстановить `p, q`.

## На что смотреть дальше

- **Проверять Винер только при «e огромном»** — иногда большое `e` замаскировано нотацией.
- **Путать границы** — Винер 0.25, Boneh-Durfee 0.292.
- **Не проверять дискриминант** — кандидат `d` может быть ложным.
- **Пытаться решить Винер вручную** — используйте sympy/Sage.
- **Игнорировать асимметрию** — для больших `d` нужны решётки.
- **Считать, что Винер всегда срабатывает** — за границей 0.25 нужен Boneh-Durfee.
