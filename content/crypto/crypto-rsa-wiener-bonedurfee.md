## Зачем оптимизируют d

Приватная экспонента `d` большая (порядка `n`) — расшифрование медленное. Некоторые реализации «оптимизируют», выбирая малый `d`. Это катастрофа: малый `d` восстанавливается по публичному ключу.

## Атака Винера (малый d)

Если `d < n^0.25 / 3`, её можно найти через **непрерывные (цепные) дроби** из `e/n`.

Идея: `e·d ≡ 1 (mod φ(n))`, значит `e·d − k·φ(n) = 1` для некоторого `k`, и `e/φ ≈ k/d`. Разложение `e/n` в цепную дробь даёт среди подходящих дробей `k/d`.

```python
from sympy import Integer, continued_fraction, continued_fraction_convergents

def wiener(n, e):
    for conv in continued_fraction_convergents(continued_fraction(Integer(e), Integer(n))):
        k, d = int(conv.p), int(conv.q)
        if k == 0: continue
        if (e*d - 1) % k != 0: continue
        phi = (e*d - 1) // k
        s = n - phi + 1              # p+q
        disc = s*s - 4*n             # (p-q)^2
        if disc < 0: continue
        t = int(disc**0.5)
        if t*t == disc and (s+t) % 2 == 0:
            return d
    return None

d = wiener(n, e)
if d:
    m = pow(c, d, n)
```

**Признак:** `e` подозрительно большой (почти как `n`). Это прямой намёк на малый `d`.

## Boneh-Durfee (усиление)

Boneh-Durfee расширяет границу до `d < n^0.292` через построение **решётки** и LLL (см. `crypto-lattice`). Уравнение `e·d = 1 + k·φ(n)` переписывается, строится решётка с малым вектором `(k, d)`, и LLL/BKZ находит его. Требует Sage + fpylll.

```python
# Sage (упрощённо): Boneh-Durfee
# Строим решётку из коэффициентов полинома f(x,y) = 1 + x*(n - y + 1) - e*d
# ... LLL/BKZ ...
# Извлекаем d
```

Граница `0.292` — теоретическая для асимптотики; на практике для конкретных размеров чуть меньше. Boneh-Durfee сложнее Винера в реализации, но покрывает больший диапазон `d`.

## Сравнение границ

| Метод | Граница `d` | Инструмент |
|---|---|---|
| Винер | `< n^0.25 / 3` | цепные дроби (sympy) |
| Boneh-Durfee | `< n^0.292` | решётки (Sage+LLL) |
| Полный перебор | `d` мал (десятки бит) | brute-force |

## Практический пример: полный разбор Винера

```python
n = 0x...   # большой
e = 0x...   # почти как n -> подозрение на малый d
c = 0x...

d = wiener(n, e)
if d is None:

else:
    m = pow(c, d, n)
    print(m.to_bytes((m.bit_length()+7)//8, "big"))
```

## Частые ошибки

- **Проверять Винер только при «e огромном».** Иногда `e` большой неявно (в другой нотации).
- **Путать границы.** Винер 0.25, Boneh-Durfee 0.292.
- **Не реализовать проверку `disc`.** Кандидат `d` может быть ложным.
- **Забыть про `gcd(e1,e2)`-варианты.** Здесь другое.
- **Пытаться решить Винер вручную.** Используйте sympy/Sage.
- **Игнорировать асимметрию.** Для больших `d` нужны решётки.

## Реализация Boneh-Durfee (структура)

Boneh-Durfee строит решётку из полинома, связывающего `e`, `d` и `n`. Основное уравнение:

```
e·d ≡ 1 (mod φ(n)),  φ(n) = n - (p+q) + 1
```

Обозначим `A = n + 1`, `s = p + q`. Тогда `e·d = 1 + k·(A - s)` для некоторых `k, s`. Атакующий ищет малые `k` и `d` как корни полинома `f(x, y) = 1 + x·(A - y) mod e` (с соответствующей редукцией). Строится решётка с параметрами `m`, `t`, применяется LLL/BKZ, и из короткого вектора извлекаются `k` и `d`.

```python
# Sage: skeleton Boneh-Durfee
# 1. Построить полиномы x^i * f(x,y)^j * e^(m-j) для подходящих i, j
# 2. Составить решётку (basis)
# 3. LLL / BKZ
# 4. Извлечь d из найденного вектора
```

Граница `n^0.292` — асимптотическая; для 1024-битного `n` практическая граница ближе к `n^0.28`. Для реальных CTF-задач чаще достаточно Винера (0.25).

## Другие атаки на малый d

- **Wiener:** `d < n^0.25/3` — цепные дроби (быстро).
- **Boneh-Durfee:** `d < n^0.292` — решётки (медленно, Sage).
- **Перебор:** `d` совсем мал (десятки бит) — brute-force по `k`.
- **Partial d:** известны биты `d` — решётка/HNP.

## Разбор: полная реализация Винера

```python
from sympy import Integer, continued_fraction, continued_fraction_convergents
from Crypto.Util.number import long_to_bytes

def wiener(n, e):
    for conv in continued_fraction_convergents(continued_fraction(Integer(e), Integer(n))):
        k, d = int(conv.p), int(conv.q)
        if k == 0: continue
        if (e*d - 1) % k: continue
        phi = (e*d - 1) // k
        s = n - phi + 1
        disc = s*s - 4*n
        if disc < 0: continue
        t = int(disc**0.5)
        if t*t == disc and (s+t) % 2 == 0:
            return d
    return None

n = 0x...; e = 0x...; c = 0x...
d = wiener(n, e)
if d: print(long_to_bytes(pow(c, d, n)))
```

## Разбор: как распознать малый d

- `e` **почти равен** `n` (большая часть бит совпадает) → сильный намёк.
- Задача говорит «быстрая расшифровка», «оптимизация».
- `e` нестандартный (не 65537), огромный.

## Разбор: как получить `p` и `q` после нахождения `d`

```python
d = wiener(n, e)
k = (e*d - 1)
phi = k // ((e*d - 1) // (e*d - 1))  # phi = (e*d-1)//k для верного k
# проще: перебираем k, пока (e*d-1) % k == 0
for k in range(1, e):
    if (e*d - 1) % k == 0:
        phi = (e*d - 1) // k
        s = n - phi + 1
        disc = s*s - 4*n
        if disc >= 0 and int(disc**0.5)**2 == disc:
            p = (s + int(disc**0.5))//2
            q = (s - int(disc**0.5))//2
            print(p, q)
```

## Разбор: цепные дроби — интуиция

Цепная дробь представляет `e/n` как `[a0; a1, a2, ...]`. Подходящие дроби `p_i/q_i` — наилучшие рациональные приближения. Так как `e/φ ≈ k/d` и `φ ≈ n`, подходящая дробь `k/d` появляется среди них, когда `d` мал. Проверяем каждый кандидат `(k, d)`: если `(e·d − 1)` делится на `k` и получается «правильная» `φ`, дающая целые `p, q` — нашли.

## Разбор: почему `e/n` даёт `k/d`

Из `e·d − k·φ(n) = 1` следует `e/φ(n) = k/d + 1/(d·φ(n))`. Поскольку `φ(n) ≈ n`, а `1/(d·φ)` очень мало при большом `d·φ`, дробь `e/n` близка к `k/d`. Теория цепных дробей гарантирует: если `|e/n − k/d| < 1/(2d²)`, то `k/d` — подходящая дробь `e/n`. Условие `d < n^0.25/3` обеспечивает это неравенство.

## Разбор: как быстро проверить кандидата

Для каждой подходящей дроби `(k, d)`:
1. `(e·d − 1) % k == 0`? Иначе пропускаем.
2. `φ = (e·d − 1) // k`.
3. `s = n − φ + 1` (это `p+q`).
4. Дискриминант `s² − 4n` — полный квадрат? Если да, `p, q` целые.

Если все условия выполнены — нашли `d`. Обычно кандидатов немного, проверка мгновенна.

## Как не застрять

- **`e` большой** → Винер (цепные дроби).
- **Винер не сработал** → Boneh-Durfee (Sage).
- **`d` совсем мал** → brute-force.
- **Проверяйте кандидата** через разложение `φ` и `p+q`.
- **RsaCtfTool** умеет Винер «из коробки».
- **Для решёток** — Sage + готовый скрипт.
