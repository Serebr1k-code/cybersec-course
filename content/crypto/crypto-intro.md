## Что такое crypto-задачи

Crypto-категория на CTF — это задачи, где нужно **восстановить секрет** (флаг), используя слабость криптографической схемы или ошибку её применения. В отличие от web (где ищут инъекции) или pwn (где эксплуатируют память), здесь работают с математикой, данными и протоколами. Типичные формулировки: «дан шифротекст», «дан публичный ключ», «дан оракул», «вот исходник генератора — найди ошибку».

Важный принцип: **на CTF ломают не примитивы, а их применение.** AES-256 не взломать перебором, но ECB без сцепления, CTR с повторным nonce, RSA без padding — ломаются мгновенно. Ваша задача — распознать, какая именно ошибка допущена.

## Карта ветви crypto

Вся ветвь делится на крупные блоки:

- **Основы:** кодировки, XOR/OTP, хэши, HMAC, KDF, введение.
- **Симметричная криптография:** AES и режимы (ECB/CBC/CTR/GCM), потоковые шифры (RC4, ChaCha20, LFSR), PRNG.
- **Атаки на режимы:** ECB oracle, CBC bit-flip, padding oracle, IV reuse, GCM forbidden attack, cut-and-paste.
- **RSA:** основы, малый e, общий модуль, Wiener, Håstad, Fermat, shared primes, Coppersmith, Bleichenbacher, Manger.
- **Дискретный логарифм:** Diffie-Hellman, ECC/ECDSA, малые подгруппы.
- **Классика:** Caesar, Vigenère, Enigma, частотный анализ.
- **Продвинутое:** решётки (LLL/BKZ), пост-квантовая криптография, спаривания.

Начинайте с «Основ» и «Симметричной криптографии» — они дают 70% практики на лёгких/средних задачах.

## Кодирование ≠ шифрование ≠ хэширование

Это различие — фундамент. Запомните:

| Свойство | Кодирование | Шифрование | Хэширование |
|---|---|---|---|
| Обратимо | да | только с ключом | нет |
| Нужен ключ | нет | да | нет (или для MAC) |
| Примеры | base64, hex, base32 | AES, RSA, ChaCha20 | MD5, SHA-256 |
| Признак | «красивый» алфавит | бинарный/случайный | фиксированная длина |

Практическое правило: **внешний слой почти всегда — кодирование.** Сначала декодируйте base64/hex, и только потом вы увидите шифротекст или хэш.

## Универсальный алгоритм действий

С любым крипто-артефактом работайте так:

1. **Соберите всё.** Все параметры, ключи, шифротексты, исходники, оракулы.
2. **Определите тип данных.** Текст? base64? hex? бинарный файл? Хэш?
3. **Декодируйте внешний слой.** base64/hex → байты.
4. **Определите примитив.** Длина кратна 16 → блочный шифр. Фиксированная длина (32/40/64 hex) → хэш. Точки `(x,y)` → ECC.
5. **Ищите структурную слабость.** Повтор nonce? Малый e? Гладкое p−1? ECB-повторы?
6. **Применяйте атаку.** Из соответствующих уроков ветви.
7. **Проверяйте результат.** Расшифрованный текст должен быть осмысленным; `pow(m,e,n)==c` должен сходиться.

def classify(s):
    if re.fullmatch(r'[0-9a-fA-F]+', s) and len(s)%2==0: return "hex/base16"

## Практический пример: первая задача

Дано: `Y3J5cHRvIGlzIGZ1bg==`. 

1. Классифицируем: смешанный регистр + `==` → base64.
2. Декодируем: `base64 -d` → `crypto is fun`.
3. Это не флаг, но даёт подсказку. Если бы это был флаг — задача решена.

Более сложный пример: `e = 3`, `n` большой, `c` маленький, `m^3 < n`. Это задача на целочисленный корень — см. `crypto-rsa-basics`.

## Частые ошибки новичков

- **Пытаться «расшифровать» хэш.** Нельзя; можно только подобрать.
- **Игнорировать внешнюю кодировку.** Прямой `int(c)` на base64-строке даст мусор.
- **Перебирать ключ там, где есть структурная атака.** RSA-задачи почти никогда не решаются перебором.
- **Не проверять результат.** Всегда проверяйте, что атака «сошлась».
- **Пропускать исходник.** Часто ответ — в коде генератора (слабый seed, фиксированный IV).
- **Забывать про padding/длину.** PKCS#7, кратность блока.

## Методология по классам задач

**Симметричные (AES/режимы).** Признак: длина кратна 16, есть IV/несколько блоков. Проверьте: ECB (повторы), reused nonce (XOR двух текстов), padding oracle (ошибки), bit-flip (структура cookie).

**RSA.** Признак: большие целые `n, e, c`. Проверьте: малый `e` (корень), слабый `n` (факторизация/Ферма/gcd), большой `e` (Wiener), несколько пар (Håstad/common modulus), oracle (padding).

**Дискретный логарифм.** Признак: `g^x mod p`, точки на кривой. Проверьте: гладкое `p−1` (Полиг–Хеллман), малые подгруппы, invalid-curve, nonce reuse в ECDSA.

**Классика.** Признак: буквы латиницы/кириллицы. Частотный анализ, Caesar/Vigenère/Enigma.

**Хэши/MAC.** Признак: фиксированная длина. Length extension (`H(K||m)`), коллизии (MD5/SHA-1), слабый ключ HMAC.

**PRNG.** Признак: последовательность «случайных» чисел. MT19937 (624), LCG, слабый seed.

## Учимся на примерах: три задачи

**Задача 1 (кодировки).** `Vm0wd2QyUXlVWGxWV0d4V1YwZDRWMVl3WkRSV01WbDNXa1JTVjAxV2JETlhhMUpUVjBaS2RHVkVRbUZXVmxs...` — это **многослойная base64** (внутри снова base64). Решение: цикл декодирования (`auto_decode`), пока не появится читаемый текст/флаг.

**Задача 2 (XOR).** Даны два шифротекста `c1`, `c2` одинаковой длины, ключ один. `c1⊕c2` даёт `P1⊕P2`; crib-dragging по известному формату флага восстанавливает тексты (см. `crypto-xor-otp`).

**Задача 3 (RSA).** Даны `n`, `e=3`, маленький `c`. Проверяем `iroot(c, 3)` — если точный, `m` найден (см. `crypto-rsa-basics`).

Три разные категории, один подход: определить примитив, найти слабость, применить инструмент.

## Как читать условие

- **«дано n, e, c»** → RSA.
- **«oracle», «encrypt», «decrypt»** → интерактивная атака.
- **«cookie», «token»** → режимы/bit-flip/HMAC.
- **«seed», «random»** → PRNG.
- **«flag зашифрован...»** + base64 → сначала декодируйте.
- **«известны старшие биты»** → Coppersmith.

## Ресурсы для практики

- **Cryptopals** (cryptopals.com) — 8 сетов задач, от XOR до атак на TLS. Обязателен.
- **CTF-платформы:** picoCTF, HackTheBox, TryHackMe, OverTheWire.
- **Книги:** «Serious Cryptography» (Aumasson), «An Introduction to Mathematical Cryptography».
- **Инструменты:** RsaCtfTool, sage, hashcat, CyberChef.
- **Write-ups:** CTFtime, GitHub-репозитории разборов.

Начните с Cryptopals set 1 (кодировки, XOR, ECB) — это даст прочный фундамент.

## Типичные «ловушки» задач

- **Скрытый padding** в RSA (нужен Coppersmith, а не корень).
- **Переиспользованный nonce** в AES-CTR/GCM (нужен XOR).
- **Слабый seed** PRNG (перебор времени).
- **Двойная кодировка** (base64 внутри base64).
- **Оракул по времени** (нужна статистика).
- **Частичный ключ** (нужны решётки).

## Как не застрять

- **Соберите ВСЕ параметры** — атаку диктует структура условия.
- **Декодируйте внешние слои** первым делом.
- **Определите примитив по длине/формату.**
- **Ищите повтор/малые значения/гладкие числа** — это слабости.
- **Используйте готовые инструменты** (RsaCtfTool, Sage, hashcat).
- **Проверяйте сходимость** результата.
- **Читайте исходники** — часто там вся подсказка.

## Где пригодится

- **CTF любого уровня** — crypto есть на каждом турнире, часто с большим весом очков.
- **Анализ реальных протоколов** — TLS, JWT, SSH, VPN; понимание режимов и padding критично для пентеста.
- **Реверс/форензика** — зашифрованные конфиги, обфускация, ключи в бинарниках.
- **Разработка** — правильный выбор криптопримитивов спасает от катастрофических утечек.
- **Багбаунти** — неверная криптография (ECB, слабый PRNG, переиспользование IV) регулярно приносит critical-находки.
