## Вопрос, с которого всё начинается

Тебе дали строку символов и сказали: «это криптография, найди флаг». Ты не знаешь, что это за шифр, есть ли вообще ключ и с какой стороны подступиться. С чего начать, чтобы не тыкаться вслепую?

Crypto на CTF — это не «взломать AES-256» (его не взломать). Это найти **ошибку применения** шифра: забытый IV, повторённый nonce, слабый генератор, открытый оракул. Но прежде чем искать ошибку, нужно понять, **что за артефакт перед тобой**. Этим мы и займёмся на одном конкретном примере.

## Наш пример

Задача выдаёт ровно одну строку:

```
Y3J5cHRvX2lzX2Z1bg==
```

Не запускаем никаких «расшифровщиков». Сначала просто смотрим глазами на признаки: смешанный регистр (A–Z и a–z), цифры, а в конце — два знака `=`. Это очень характерная картина. Запомним её и проверим гипотезу.

## Шаг 1: декодируем

Гипотеза — base64. Проверяем:

```bash
$ echo 'Y3J5cHRvX2lzX2Z1bg==' | base64 -d
crypto_is_fun
```

Получили осмысленный текст — гипотеза верна. И вот первое важное открытие: **нам не понадобился никакой ключ**. Это не шифрование. Это *кодирование* — способ упаковать байты в текст, который может распаковать любой желающий.

Зачем вообще что-то кодируют? Байты нельзя надёжно передать по email, вставить в JSON или в URL — текстовые каналы «ломают» непечатаемые символы. Поэтому бинарные данные оборачивают в base64 или hex. На CTF кодировку используют как **первый слой**: под ней может лежать что-то настоящее.

## Шаг 2: кодирование ≠ шифрование ≠ хэширование

Это различие — фундамент всей категории. Разберём на трёх строках.

**(а) Кодирование.** `Y3J5cHRvX2lzX2Z1bg==` декодируется без ключа в `crypto_is_fun`. Обратимо кем угодно.

**(б) Шифрование.** Настоящий шифротекст после снятия внешней кодировки выглядит как случайные байты. Прочитать его без ключа нельзя.

**(в) Хэширование.** Возьмём ту же строку и посчитаем SHA-256:

```bash
$ echo -n 'crypto_is_fun' | sha256sum
4f11db8284504dec67ad8658164fa5fdab0bc8f45eb208a089c31adefbb25c4c  -
```

Флаг `-n` здесь важен: без него в хэш попадёт лишний перевод строки, и результат будет другим. Сводка различий:

| | Кодирование | Шифрование | Хэширование |
|---|---|---|---|
| Обратимо | без ключа | только с ключом | нет |
| Нужен ключ | нет | да | нет |
| Длина результата | растёт предсказуемо | растёт | фиксированная |
| Примеры | base64, hex | AES, RSA | MD5, SHA-256 |

Практический вывод: **внешний слой почти всегда кодирование**. Пока ты не снял base64/hex, ты не видишь ни шифротекста, ни хэша.

## Шаг 3: как отличить их по виду

Каждый тип оставляет отпечаток. Хэш — фиксированная длина и только hex-символы:

```bash
$ echo -n 'crypto_is_fun' | md5sum
7fbef9779960363fa4f1a3d2f0fcff40  -
```

Здесь ровно 32 символа `0-9a-f` — это MD5. У SHA-256 их будет 64. Хэш **невозможно «расшифровать»**: можно лишь подобрать исходное значение по словарю.

Шифротекст, выведенный в текст, тоже часто обёрнут в base64 или hex — но после декодирования он даёт **случайные, нечитаемые байты**. Кодировка же после декодирования даёт осмысленный текст или другой узнаваемый слой.

## Универсальный алгоритм

С любым крипто-артефактом работай по шагам:

1. **Собери всё.** Все числа, строки, исходники, оракулы из условия.
2. **Классифицируй строку.** hex? base64? фиксированная длина (хэш)? точки `(x, y)` (ECC)?
3. **Сними внешние слои.** Декодируй base64/hex, пока результат декодируется.
4. **Определи примитив по структуре.** Длина кратна 16 → блочный шифр; 32/40/64 hex → хэш; два больших числа `n, e` → RSA.
5. **Ищи слабость, а не перебор.** Повтор nonce, малый `e`, гладкое `p−1`, ECB-повторы.
6. **Примени атаку** из урока соответствующей темы.
7. **Проверь результат.** Текст должен быть осмысленным, а `pow(m, e, n)` — сходиться с `c`.

Классификация строки на Python:

```python
import re
def classify(s):
    if re.fullmatch(r'[0-9a-fA-F]+', s) and len(s) % 2 == 0:
        return "hex или hex-хэш"
    if re.fullmatch(r'[A-Z2-7]+=*', s):
        return "base32"
    if re.fullmatch(r'[A-Za-z0-9+/]+=*', s) and len(s) % 4 == 0:
        return "base64"
    return "непонятно"

print(classify("Y3J5cHRvX2lzX2Z1bg=="))          # base64
print(classify("7fbef9779960363fa4f1a3d2f0fcff40"))  # hex или hex-хэш
```

Второй вывод — `hex или hex-хэш` — честная подсказка: у hex-данных и у хэша одинаковый алфавит. Различает их **контекст**: рядом с хэшем обычно стоит `md5(`, `sha256(` или длина 32/40/64.

## Карта ветви crypto

Чтобы понимать, куда идти дальше, держи в голове общую структуру:

- **Основы:** кодировки, классика, XOR/OTP, теория чисел — это ближайшие уроки.
- **Симметричная криптография:** AES и режимы (ECB/CBC/CTR/GCM), потоковые шифры, PRNG.
- **Атаки на режимы:** ECB-оракул, CBC bit-flip, padding oracle, переиспользование IV.
- **RSA:** малый `e`, общий модуль, Wiener, Håstad, факторизация, Coppersmith.
- **Дискретный логарифм:** Diffie-Hellman, ECC/ECDSA, малые подгруппы.
- **Продвинутое:** решётки (LLL/BKZ), пост-квантовая криптография.

70% лёгких и средних задач закрывают «Основы» и «Симметричная криптография» — с них и начинай.

## Как читать условие задачи

Формулировка сама подсказывает тип задачи. Несколько частых шаблонов:

- **«даны `n`, `e`, `c`»** → RSA; смотри на размер `e` и на то, сколько пар ключей дано.
- **«есть оракул encrypt/decrypt»** → интерактивная атака, нужен `pwntools` для связи с сервисом.
- **«cookie», «token»** → режим блочного шифра или подпись (bit-flip, HMAC).
- **«seed», «random»** → предсказание генератора (PRNG).
- **«известны старшие биты»** → Coppersmith (продвинутый RSA).
- **строка в base64/hex** → сначала сними кодировку, потом решай.

## Что мы теперь знаем

- Кодирование обратимо без ключа; шифрование — только с ключом; хэш необратим.
- Внешний слой задачи почти всегда кодировка; снимай её первым делом.
- Тип артефакта виден по алфавиту и длине.
- На CTF ломают не шифр, а ошибку его применения.
- Любая задача решается по одному алгоритму: собрать → классифицировать → декодировать → найти слабость → проверить.

## Куда дальше

Мы научились читать артефакт, но ещё ни разу не снимали реальную многослойную цепочку. В следующем уроке **crypto-encodings** мы возьмём строку из трёх наложенных кодировок (hex → base32 → base64) и раскрутим её шаг за шагом. Главное запомни сейчас: **прежде чем что-то «взламывать», посмотри, не обёрнут ли артефакт в кодировку**.

## Где пригодится

- **CTF любого уровня** — crypto есть на каждом турнире и часто весит много очков.
- **Пентест и багбаунти** — base64/hex в JWT, cookies, токенах; распознавание «самодельной» криптографии.
- **Форензика** — разбор закодированных артефактов в дампах, логах, письмах.
- **Разработка** — понимание, что кодирование не даёт секретности, спасает от ложных выводов об «шифровании».
