## Вопрос, с которого всё начинается

Сервер отдаёт «случайные» числа — например, сброс пароля или токен сессии
считается как `next = (a·seed + c) mod m`. На вид это шум. Но что, если этот
генератор **линейный**? Тогда по нескольким подряд выданным числам можно
восстановить его параметры и предсказать **все** будущие значения — включая
токен следующего пользователя.

Разберём это на двух реальных генераторах: учебном 32-битном LCG и настоящем
`java.util.Random`. Оба мы взломаем и предскажем следующее число.

## Наш пример: последовательность чисел

Пусть нам дали такую последовательность «случайных» 32-битных чисел:

```
[42, 1083814273, 378494188, 2479403867, 955863294, 1613448261, ...]
```

Первое число подозрительно маленькое, а разности — вроде бы хаотичны. Но есть
один намёк: все числа лежат в диапазоне `[0, 2^32)`. Это типично для **линейного
конгруэнтного генератора** (LCG). Проверим гипотезу и восстановим параметры.

## Шаг 1: устройство LCG

LCG — простейший PRNG:

```
x_{n+1} = (a · x_n + c) mod m
```

- `m` — **модуль** (часто степень двойки `2^k`);
- `a` — **множитель**;
- `c` — **инкремент**;
- `x_0` — начальное значение (**seed**).

Если `c = 0`, генератор называют мультипликативным. Качество зависит от выбора
`a`, `c`, `m` (теорема Халла–Добелла), а период не превышает `m`. Главное для
нас: генератор **полностью детерминирован**, а его состояние — одно число.

## Шаг 2: восстанавливаем m, a, c

Ключевое наблюдение: если `x_{n+1} = a·x_n + c (mod m)`, то вторые разности
пропорциональны. Обозначим `t_i = x_{i+1} − x_i`. Тогда
`t_{i+2}·t_i − t_{i+1}²` делится на `m`. Значит, `m` делит **gcd** всех таких
выражений — это и есть способ найти модуль:

```python
from math import gcd
def recover_modulus(xs):
    t = [xs[i+1]-xs[i] for i in range(len(xs)-1)]
    g = 0
    for i in range(len(t)-2):
        g = gcd(g, abs(t[i+2]*t[i] - t[i+1]**2))
    return g
```

Дальше всё просто: `a` находится делением, а `c` — подстановкой:

```
a ≡ (x_{i+2} − x_{i+1}) · (x_{i+1} − x_i)^{−1}  (mod m)
c ≡ x_{i+1} − a·x_i                              (mod m)
```

## Полный прогон от начала до конца

```
$ python3 lcg_demo.py
выходы: [42, 1083814273, 378494188, 2479403867, 955863294, 1613448261] ...
recovered m = 4294967296 (2^32 = 4294967296 )
recovered a = 1664525  c = 1013904223
predict next = 508781842  true next = 508781842
```

Модуль восстановился как `2^32`, множитель `a = 1664525` и инкремент
`c = 1013904223` — это классические константы **Numerical Recipes**, которые
разработчики берут «по привычке». И предсказанное следующее число
(`508781842`) совпало с истинным. Теперь мы можем генерировать все будущие
значения, не зная seed.

## Шаг 3: настоящий java.util.Random

Теперь реальный пример. `java.util.Random` — это **48-битный LCG**:

```
seed = (seed * 0x5DEECE66D + 0xB) & ((1<<48) - 1)
next(bits) = seed >>> (48 - bits)
```

`nextInt()` (без аргумента) вызывает `next(32)`, то есть отдаёт **старшие 32 бита**
48-битного состояния. Значит, в одном числе мы видим 32 бита состояния из 48 —
не хватает **16 младших бит**. Их всего `2^16 = 65536` вариантов, а второй выход
отсеивает все ложные:

```python
for low in range(1 << 16):
    s1 = (v1 << 16) | low
    s2 = (s1 * A + C) & M
    if (s2 >> 16) == v2:
        found = s2; break
```

```
$ python3 lcg_demo.py
java.util.Random: v1 = 419617198  v2 = 1755248688
восстановленное состояние: 0x689ef830b5d6
предсказание следующего: 4134577507
истинный следующий   : 4134577507
```

Мы перебрали 65536 вариантов младших бит, нашли состояние `0x689ef830b5d6` и
предсказали следующий `nextInt()` — он совпал. Именно так ломают «угадай
следующее число» и токены на `java.util.Random` в Java-приложениях. Для
безопасности нужен `SecureRandom`.

## Что мы теперь знаем

- LCG линеен: `x_{n+1} = (a·x_n + c) mod m`; состояние — одно число.
- Модуль `m` делит gcd вторых разностей; `a` и `c` находятся делением и
  подстановкой.
- Несколько последовательных выходов полностью восстанавливают генератор.
- `java.util.Random` — 48-битный LCG; из двух `nextInt()` состояние
  восстанавливается перебором `2^16` младших бит.
- `glibc rand()` — не LCG, а **аддитивный** генератор (`r[i] = r[i-3] + r[i-31]`),
  но тоже линеен и восстанавливается по 31 выходу.
- Усечённые выходы (только старшие биты) требуют решёточных методов (LLL).

## glibc rand и усечённые выходы

`glibc` `rand()` — не чистый LCG, а **аддитивный** генератор:

```
r[i] = r[i-3] + r[i-31] mod 2^32
output = r[i] >> 1
```

Состояние — 31 предыдущее значение; по 31 выходу оно восстанавливается. Сдвиг
`>>1` скрывает младший бит, но линейная структура позволяет решить систему.

Если видны только **старшие** биты (`drand48`, `x_n >> k`), задача превращается в
поиск малых ошибок — это классическая решётка (как hidden number problem): строим
уравнения на неизвестные младшие биты и ищем короткий вектор алгоритмом LLL. На
CTF такие задачи решают в Sage.

## Как не застрять

1. Посмотрите на диапазон чисел: `[0, 2^k)` — сильный намёк на LCG.
2. Соберите ≥5 последовательных выходов и вызовите `recover_modulus`.
3. Проверьте `m`, затем восстановите `a` и `c`; проверьте предсказание на
   следующем значении.
4. `java.util.Random` → два `nextInt()` и перебор `2^16` младших бит.
5. Видны только старшие биты → решётка (Sage/LLL).
6. Генератор — MT19937 → это `crypto-mt19937-deep`, не LCG.

## Справочная таблица

| Генератор | Формула | Состояние | Восстановление |
|-----------|---------|:---------:|----------------|
| LCG | `a·x+c mod m` | 1 | 3–5 выходов |
| java.util.Random | 48-бит LCG | 48 бит | 2 выхода |
| glibc rand | аддитивный | 31 слово | 31 выход |
| drand48 | 48-бит LCG | 48 бит | старшие биты |
| MT19937 | twist+temper | 19937 бит | 624 выхода |

## Чек-лист: это LCG?

- последовательность выглядит линейно предсказуемой;
- значения в диапазоне `[0, m)` (часто степень двойки);
- разности `x_{i+1} − x_i` имеют общий делитель;
- в коде `seed = (seed * A + C) % M`;
- `java.util.Random`, `drand48`, `rand()` в C, самодельный генератор.

## Почему восстановление вообще возможно

LCG линеен, и это его приговор. Из формулы `x_{n+1} = a·x_n + c mod m` следует, что последовательные разности `t_i = x_{i+1} − x_i` связаны линейно: `t_{i+1} = a·t_i mod m`. Значит, `t_{i+1}·t_i − t_{i+1}²` пропорционально `m`, и модуль делит gcd всех таких выражений. Как только `m` найден, `a` находится из отношения двух разностей, а `c` — подстановкой. Никакого перебора: три-четыре выхода дают полную систему.

Это фундаментальное свойство **любого линейного генератора**: выход — линейная функция состояния, поэтому по достаточному числу выходов состояние восстанавливается решением линейной системы. Именно так падают самодельные «случайные» токены, `java.util.Random`, `drand48`, glibc `rand` (там аддитивная линейность, состояние — 31 слово). Для CSPRNG (например, `SecureRandom`) такого выхода нет: связь между состоянием и выходом нелинейна, и предсказание невозможно.

Практический признак в коде: `seed = (seed * A + C) % M`, `x = (x * 1103515245 + 12345) & 0x7fffffff`, использование `Random` вместо `SecureRandom`. Если видите такое — считайте, что генератор предсказуем, и собирайте последовательность выходов.

## Если не сработало

- **Модуль не восстанавливается.** Нужны ≥3 последовательных выхода и ненулевые разности; если разности имеют общий делитель, gcd может оказаться кратным `m` — берите больше членов.
- **Видны только старшие биты (усечённый LCG).** Прямая формула не работает — нужен решёточный метод (LLL), как в задачах на `drand48` и `x_n >> k`.
- **Последовательность не LCG.** Проверьте на MT19937 (Python `random`, PHP `mt_rand`): там нужно 624 выхода и `randcrack`, а не формула LCG.
- **Данных слишком мало.** Два выхода дают лишь кандидатов; для однозначного `m, a, c` нужно несколько.
- **Смешаны потоки.** Если сервер отдаёт числа из нескольких генераторов или вперемешку, порядок нарушен — восстановите, какие выходы идут подряд.

## Частые вопросы

**Как быстро отличить LCG от CSPRNG?** По предсказуемости: соберите выходы, восстановите параметры и проверьте предсказание следующего. У CSPRNG параметры не восстановятся.

**Работает ли это на `random` в Python?** Нет, там MT19937 (19937-битное состояние), ломается по 624 выходам — это отдельный урок (`crypto-mt19937-deep`).

**Что делать разработчику?** Для токенов, паролей и ключей использовать CSPRNG (`secrets`, `os.urandom`, `SecureRandom`), а LCG — только для не-криптографических задач вроде симуляций.

## Куда дальше

Мы сломали LCG — самый простой линейный генератор. Дальше логично взять
**MT19937** (`crypto-mt19937-deep`), который стоит за Python `random` и PHP
`mt_rand`: он тоже предсказуем, но состояние у него 19937 бит, а восстановление
требует 624 выхода. А главное запомни: **любой линейный генератор предсказуем по
нескольким выходам — для токенов и секретов нужен CSPRNG**.
