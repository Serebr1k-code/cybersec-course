Линейный конгруэнтный генератор (LCG) — простейший PRNG: `x_{n+1} = a·x_n + c mod m`. Он полностью детерминирован, а его параметры и состояние восстанавливаются по нескольким последовательным выходам. На LCG построены `java.util.Random`, `glibc rand`, множество самодельных генераторов, и на CTF они — частый источник предсказуемых токенов. Эта глава — формулы восстановления, ломка реальных реализаций и работа с усечёнными выходами.

## Устройство LCG

```
x_{n+1} = (a · x_n + c) mod m
```

- `m` — модуль (часто степень двойки `2^k`).
- `a` — множитель.
- `c` — инкремент.
- `x_0` — seed.

Если `c = 0` — мультипликативный LCG. Качество зависит от `a`, `c`, `m` (теорема Халла-Добелла). Период не превышает `m`.

## Восстановление параметров a, c, m

По выходам `x_0, x_1, x_2, ...`:

- **Модуль `m`:** `t_i = x_{i+1} - x_i`; `m` делит `gcd(t_{i+2}·t_i - t_{i+1}², ...)`. Если `m` — степень двойки, часто угадывается по разрядности.
- **Множитель `a`:** `a ≡ (x_{i+2} - x_{i+1})·(x_{i+1} - x_i)^{-1} mod m`.
- **Инкремент `c`:** `c ≡ x_{i+1} - a·x_i mod m`.

```python
from math import gcd
def recover_modulus(xs):
    t = [xs[i+1] - xs[i] for i in range(len(xs)-1)]
    diffs = [abs(t[i+2]*t[i] - t[i+1]**2) for i in range(len(t)-2)]
    g = 0
    for d in diffs:
        g = gcd(g, d)
    return g      # кандидат в m (или его делитель)
```

## Восстановление состояния

Если параметры известны, по одному выходу `x_n` предсказывается весь ряд. Если известен только seed-диапазон — перебор. Если выходы усечены (например, берутся старшие биты), применяют решёточные методы (см. ниже).

## java.util.Random

`java.util.Random` — 48-битный LCG:

```
seed = (seed * 0x5DEECE66D + 0xB) & ((1<<48) - 1)
next(bits) = seed >>> (48 - bits)
```

`nextInt(bound)` использует rejection sampling и `next(31)`. Ключевое: **48-битный seed** перебирается за 2^48 (много, но на GPU реально), а при утечке двух последовательных `nextInt()` (или значений, дающих старшие биты seed) состояние восстанавливается аналитически:

```python
# из двух nextInt(2^31)-подобных значений восстановить 48-битное состояние
seed = (v1 << 16) | v2_low16   # приблизительно; нужна аккуратная реконструкция
# затем можно предсказать nextInt(bound)
```

`java.util.Random` небезопасен для токенов; для них нужен `SecureRandom`.

## glibc rand

`glibc` `rand()` — аддитивный генератор (не чистый LCG):

```
r[i] = r[i-3] + r[i-31] mod 2^32
output = r[i] >> 1
```

Состояние — 31 предыдущее значение. По 31 выходу (даже усечённому на 1 бит, `>>1`) состояние восстанавливается. Особенность `>>1` делает вывод нечётных бит неопределённым — но линейная структура позволяет решить систему.

## Другие линейные PRNG

- **`rand()`/`srand()` в C (разные libc)** — MSVC, BSD: LCG; glibc: additive.
- **`drand48`** — 48-битный LCG, выход — старшие биты.
- **Python `random`** — MT19937 (не LCG, см. `crypto-mt19937-deep`).
- **Truncated LCG** — если выход = `x_n >> k`, применяют lattice (похоже на biased nonce).

## Truncated LCG и решётки

Если наблюдаются старшие биты `x_n`, задача сводится к нахождению малых ошибок — решётка, как в hidden number problem. Общая идея: составить уравнения на младшие неизвестные биты и найти короткий вектор LLL.

## Разобранный пример: 32-битный LCG

Дано: `x0=..., x1=..., x2=...` (полные выходы). Восстанавливаем `m`, `a`, `c` и предсказываем `x3`:

```python
from math import gcd
xs = [x0, x1, x2, x3, x4]
m = recover_modulus(xs)
a = (xs[2] - xs[1]) * pow(xs[1] - xs[0], -1, m) % m
c = (xs[1] - a * xs[0]) % m
assert (a * xs[0] + c) % m == xs[1]
print("next:", (a * xs[-1] + c) % m)
```

Если `recover_modulus` вернул делитель `m`, проверьте предсказание на следующем выходе и при необходимости домножьте.

## Частые ошибки и тупики

- **Считать LCG криптостойким.** Он полностью предсказуем.
- **Забыть про `c=0`.** Мультипликативный LCG — частный случай.
- **Неверный `m`.** `recover_modulus` может дать делитель; проверяйте.
- **Путать типы выходов.** `nextInt(bound)` ≠ `next(31)`.
- **Игнорировать усечение.** `drand48`/glibc отдают старшие биты.
- **Перебор 2^48 без нужды.** Для java.util.Random часто есть аналитика.
- **Применять MT-инструменты к LCG.** `randcrack` не подходит.

## Что дальше (decision)

1. Полные последовательные выходы → восстановите `m, a, c`.
2. Параметры известны → предскажите следующий выход.
3. `java.util.Random` → восстановите 48-битное состояние.
4. `glibc rand` → аддитивная модель, 31 значение.
5. Выходы усечены → решётка/LLL.
6. Генератор — MT19937 → `crypto-mt19937-deep`.

## Полный разбор: предсказание java.util.Random

`java.util.Random` хранит 48-битное состояние и обновляет его как `seed = (seed*0x5DEECE66D + 0xB) & (2^48-1)`. `nextInt(bound)` вызывает `next(31)` и rejection sampling. Если сервер отдаёт два последовательных значения `nextInt()` (даже по модулю небольшого `bound`), состояние восстанавливается:

```python
A = 0x5DEECE66D
C = 0xB
M = (1 << 48) - 1

def unshift_next(v, bits=31):
    # v = next(31); старшие 17 бит состояния = v
    return v << (48 - 31)

# при двух значениях можно собрать 48 бит состояния
# и предсказать следующий nextInt(bound)
def next_int(seed, bound):
    while True:
        seed = (seed * A + C) & M
        r = seed >> 17
        bits = bound.bit_length()
        val = r >> (31 - bits)
        if val < bound:
            return val, seed
```

На практике: перебирают 16 неизвестных младших бит, проверяют согласованность со вторым наблюдением, затем предсказывают. Именно так ломают «угадай следующее число» и токены на `java.util.Random` в Java-приложениях (для безопасности нужен `SecureRandom`).

## Чек-лист: это LCG?

- последовательность выглядит линейно предсказуемой;
- значения в диапазоне `[0, m)` (часто степень двойки);
- разности `x_{i+1} - x_i` имеют общий делитель;
- в коде `seed = (seed * A + C) % M`;
- `java.util.Random`, `drand48`, `rand()` в C, самодельный генератор;
- «угадай следующее число».

Порядок: соберите ≥5 последовательных выходов; `recover_modulus` → `a` → `c`; проверьте предсказание на следующем значении. Если выходы усечены (старшие биты) — переходите к решётке.

## Быстрые рецепты для CTF

- **5+ последовательных выходов** → `recover_modulus` → `a` → `c` → предсказание.
- **`java.util.Random`** → восстановите 48-битное состояние из двух значений.
- **glibc `rand()`** → аддитивная модель, 31 значение.
- **Усечённые выходы** → решётка/LLL.
- **MT19937** → `crypto-mt19937-deep` (другая техника).
