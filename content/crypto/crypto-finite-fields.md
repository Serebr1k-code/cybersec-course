## Вопрос, с которого всё начинается

Мы умеем делить по простому модулю и ломать DH. Но в криптографии постоянно встречаются поля, которые на числа по модулю не похожи: AES работает в `GF(2^8)`, GCM — в `GF(2^128)`, эллиптические кривые — в `GF(p)`. Вопрос новичка: «Почему нельзя просто умножать числа по модулю и зачем какие-то полиномы?» Разберём это на одном конкретном поле — том, в котором живёт AES.

## Наш пример

Возьмём стандартный тестовый вектор из спецификации AES: умножение `0x57 · 0x83` в поле `GF(2^8)` даёт `0xC1`. Мы проведём этот пример через весь урок: поймём, что за «умножение» здесь имеется в виду, почему ответ именно `0xC1`, как найти обратный элемент и как всё это связано с реальными шифрами.

## Шаг 1: `GF(p)` — знакомые числа по модулю

Начнём с простого случая. Множество `{0, 1, …, p−1}` с операциями по модулю простого `p` — это поле `GF(p)`. Поле означает: есть сложение, умножение, вычитание и **деление** (кроме деления на ноль), и все привычные законы выполняются. Обратный элемент находится по малой теореме Ферма: `a⁻¹ = a^(p−2) mod p`.

```python
p = 97
inv = pow(17, p-2, p)
print(inv, (17*inv) % p, (42*inv) % p)
```

```
40 1 31
```

`inv(17) = 40`, потому что `17·40 = 680 = 97·7 + 1`. А `42/17` в этом поле равно `42·40 mod 97 = 31`. Обратите внимание: `p` обязано быть **простым** — по составному модулю деление существует не всегда.

## Шаг 2: `GF(2^m)` — полиномы из битов

Теперь второй случай, важный для AES. Элемент `GF(2^m)` — это многочлен степени меньше `m` с коэффициентами `0` или `1`:

```
a(x) = a_{m-1}·x^{m-1} + … + a₁·x + a₀
```

Его удобно хранить как целое число, где бит `i` — коэффициент при `x^i`. Например, для `m = 8` число `0x57` — это `x⁶ + x⁴ + x² + x + 1`. **Сложение** — побитовый XOR, потому что коэффициенты складываются по модулю 2. **Умножение** — обычное умножение полиномов, а затем взятие остатка по **неприводимому полиному** `f(x)` степени `m`. Неприводимый полином — аналог простого числа: он не раскладывается в произведение полиномов меньшей степени. Без редукции произведение вылезло бы за пределы поля.

## Шаг 3: умножаем `0x57 · 0x83` в `GF(2^8)`

AES использует полином `f(x) = x⁸ + x⁴ + x³ + x + 1`, то есть число `0x11B`. Реализуем умножение «в столбик» с редукцией:

```python
def gf_mul(a, b, m=8, poly=0x11B):
    res = 0
    for _ in range(m):
        if b & 1: res ^= a
        b >>= 1
        a <<= 1
        if a & (1 << m): a ^= poly
    return res

print(hex(gf_mul(0x57, 0x83)))
```

```
0xc1
```

Получили `0xC1` — ровно то, что обещала спецификация. Это не случайное совпадение: любой тестовый вектор AES можно проверить этой функцией. Полезно свериться и с более простым случаем `0x57 · 0x02 = 0xAE` — это «умножение на x» с редукцией.

## Шаг 4: обратный элемент и примитивный элемент

**Обратный элемент** в `GF(2^m)` можно найти тем же приёмом Ферма: ненулевых элементов `2^m − 1`, и `a⁻¹ = a^(2^m − 2)`. Для `m = 8` это `a^254`.

```python
inv57 = gf_pow(0x57, 254)
print(hex(inv57), hex(gf_mul(0x57, inv57)))
```

```
0xbf 0x1
```

`0x57 · 0xBF = 0x1` — обратный найден.

**Примитивный элемент** — это образующий мультипликативной группы `GF(q)^*`: его степени `g⁰, g¹, …, g^(q−2)` пробегают все ненулевые элементы. Порядок элемента — наименьшее `k` с `a^k = 1`, и он всегда делит `q−1`. Проверим в `GF(97)`:

```python
g, order, x = 5, 1, 5
while x != 1:
    x = (x*g) % 97; order += 1
print(order)
```

```
96
```

`96 = 97 − 1`, значит `5` — примитивный элемент. Это важно для безопасности: если порядок `g` в DH/ElGamal не является большим простым числом, работают атаки вроде Полига–Хеллмана.

## Шаг 5: где это в криптографии

**AES.** S-box и шаг MixColumns — это арифметика именно в `GF(2^8)` с полиномом `0x11B`: обращение элемента и умножение на константы.

**GHASH (аутентификация в AES-GCM).** Умножает блоки на ключ `H` в `GF(2^128)` по модулю `x¹²⁸ + x⁷ + x² + x + 1`. Повтор nonce в GCM позволяет собрать систему линейных уравнений над этим полем и восстановить `H` (forbidden attack) — без умения умножать в `GF(2^128)` эксплойт не написать.

**Эллиптические кривые.** Кривые над `GF(p)` и `GF(2^m)` — это те же поля, только точки складываются по формулам. Выбор неприводимого полинома — это параметр доверия: если производитель «зашил» свой полином, это потенциальный бэкдор, как подозрительные константы в генераторах. Практический навык здесь — уметь переключаться между «число по модулю» и «полином по модулю» и не терять неприводимый полином при редукции: именно на этой ошибке ломается больше всего самодельных реализаций.

## Шаг 6: как не застрять

Три частые ошибки. Первая — путать `GF(p)` и целые по модулю: `p` обязано быть простым. Вторая — забыть редукцию по неприводимому полиному: тогда результат уже не элемент поля. Третья — использовать **приводимый** полином: тогда `GF(2^m)` не поле, появляются делители нуля и вся арифметика ломается. И всегда сверяйтесь с тестовыми векторами (`0x57·0x83 = 0xC1`) — это лучший способ поймать ошибку в реализации.

## Коды Рида–Соломона и `GF(2^m)`

Отдельно стоит сказать, почему `GF(2^m)` важен за пределами шифров. Помехоустойчивые коды Рида–Соломона строятся над `GF(2^m)` и умеют **исправлять** ошибки: сообщение раскладывается в полином, вычисляются избыточные символы, и по ним восстанавливаются потерянные. Именно поэтому QR-коды, CD/DVD, RAID-6 и спутниковая связь используют `GF(2^8)` или `GF(2^16)`. Арифметика там ровно та же: сложение — XOR, умножение — с редукцией по полиному. Понимая поле, вы понимаете и эти коды.

## Что мы теперь знаем

- **`GF(p)`** — числа по простому модулю; `a⁻¹ = a^(p−2)`, деление через обратный элемент.
- **`GF(2^m)`** — полиномы из битов; сложение = XOR, умножение = полиномы + редукция.
- Неприводимый полином — аналог простого числа; для AES это `0x11B`.
- **Примитивный элемент** порождает все ненулевые элементы; его порядок = `q−1`.
- Эти поля — фундамент AES, GHASH, ECC и кодов Рида–Соломона.
