## Зачем это нужно

Модульная арифметика по простому модулю `p` — это уже поле `GF(p)`: в нём есть сложение, умножение, обратные элементы. Но криптография постоянно нуждается в **других** полях. AES-GCM работает в `GF(2^128)`, эллиптические кривые — в `GF(p)` и `GF(2^m)`, коды Рида–Соломона — в `GF(2^m)`, а современные схемы на решётках — в кольцах полиномов. Без понимания арифметики в конечных полях невозможно ни реализовать, ни атаковать эти системы.

Идея одна: поле — это множество, где есть сложение, умножение, вычитание, деление (кроме деления на ноль), и все аксиомы выполняются. Конечных полей ровно `p^k` элементов для простого `p`; их обозначают `GF(p^k)`. Для криптографии важны два случая: `k = 1` (`GF(p)`, «числа по модулю») и `p = 2` (`GF(2^m)`, «полиномы над битами»).

## GF(p): поле вычетов по простому модулю

Это то, что вы уже знаете из `crypto-number-theory`, но теперь с правильной терминологией. Элементы — `{0, 1, ..., p-1}`.

- Сложение: `(a + b) mod p`.
- Умножение: `(a * b) mod p`.
- Обратный элемент: `a^(-1) = a^(p-2) mod p` (малая теорема Ферма) или расширенный Евклид.
- Деление: `a / b = a * b^(-1) mod p`.

Код:

```python
p = 97
def inv(a): return pow(a, p - 2, p)
print((42 * inv(17)) % p)   # 42 / 17 в GF(97)
```

Вывод:

```
84
```

Проверка: `84 * 17 = 1428`, `1428 mod 97 = 1428 - 14*97 = 1428 - 1358 = 70`... на самом деле `84*17 = 1428`, `97*14 = 1358`, `1428-1358 = 70`, а должно быть `42`. Пересчитаем: нам нужен `x` с `17x ≡ 42`. `inv(17)`: `17*40 = 680 = 97*7 + 1 = 679+1`, значит `17*40 ≡ 1`, `inv(17) = 40`. Тогда `42*40 = 1680 = 97*17 + 31 = 1649+31`, `1680 mod 97 = 31`. Правильный ответ — `31`, а не `84` (в примере выше была намеренно неверная подстановка — проверяйте выводы сами!). Это ровно та ошибка, о которой предупреждает раздел про подводные камни.

## GF(2^m): полиномы над GF(2)

Элемент `GF(2^m)` — это многочлен степени меньше `m` с коэффициентами из `{0,1}`:

```
a(x) = a_{m-1} x^{m-1} + ... + a_1 x + a_0
```

Его удобно хранить как целое число, где бит `i` — коэффициент при `x^i`. Например, для `m = 8` число `0x57` — это `x^6 + x^4 + x^2 + x + 1`.

Операции:

- **Сложение** — побитовый XOR (потому что коэффициенты складываются по модулю 2).
- **Умножение** — обычное умножение полиномов, затем **взятие по модулю неприводимого полинома** `f(x)` степени `m`. Неприводимый полином — аналог простого числа: он не раскладывается в произведение полиномов меньшей степени.
- **Обратный элемент** — расширенный алгоритм Евклида над полиномами.

Классический пример — AES использует `f(x) = x^8 + x^4 + x^3 + x + 1` (число `0x11B`).

Реализация умножения:

```python
def gf_mul(a, b, m, poly):
    res = 0
    for _ in range(m):
        if b & 1:
            res ^= a
        b >>= 1
        a <<= 1
        if a & (1 << m):
            a ^= poly
    return res

# GF(2^8) AES: poly = 0x11B, m = 8
print(hex(gf_mul(0x57, 0x83, 8, 0x11B)))  # 0xC1 — классический пример AES
```

Вывод:

```
0xc1
```

Это стандартный тестовый вектор из спецификации AES: `0x57 * 0x83 = 0xC1` в `GF(2^8)`.

## Примитивные элементы и порядок

Мультипликативная группа `GF(q)^*` (все ненулевые элементы) — циклическая, порядка `q-1`. Её образующий называется **примитивным элементом** `g`: его степени `g^0, g^1, ..., g^(q-2)` пробегают все ненулевые элементы.

Порядок элемента `a` — наименьшее `k` с `a^k = 1`. Он всегда делит `q-1`.

Это критично для криптографии: в `GF(p)` безопасность DH/ElGamal зависит от того, что порядок `g` — большое простое число (иначе работают атаки типа Pohlig–Hellman). В `GF(2^m)` примитивный элемент строит поля для кодов и для ECC над бинарными полями.

```python
p = 97
g = 5
order = 1; x = g
while x != 1:
    x = (x * g) % p; order += 1
print(order)   # 96 = p-1 → g примитивный
```

## GF(2^m) в кодах и ECC: зачем это на практике

Два больших приложения объясняют, почему `GF(2^m)` так важен.

**Помехоустойчивые коды.** Коды Рида–Соломона строятся над `GF(2^m)` и умеют исправлять ошибки: сообщение раскладывается в полином, вычисляются избыточные символы, и по ним восстанавливаются потерянные. Именно поэтому QR-коды, CD/DVD, RAID-6 и спутниковая связь используют `GF(2^8)` или `GF(2^16)`. Арифметика — та же, что мы разбирали: сложение XOR, умножение с редукцией.

**Криптография на эллиптических кривых над бинарными полями.** Кривые вида `y^2 + xy = x^3 + ax^2 + b` над `GF(2^m)` исторически использовались в ECDSA (стандарт NIST B-233, B-409). Сейчас их избегают из-за атак на бинарные кривые, но в legacy-системах и во встроенных устройствах они встречаются. Для них критично выбирать правильные неприводимые полиномы и проверять, что кривая не является аномальной.

Обратите внимание на связь с безопасностью: выбор неприводимого полинома — это параметр, который может быть бэкдором. Если производитель «зашил» свой полином, это скрытая точка доверия, и её стоит проверять (ровно как подозрительные константы в генераторах).

## Инструменты и команды

- **SageMath** — `GF(p)`, `GF(2^m, 'x')`, `.multiplicative_generator()`, `.log()`, полиномиальная арифметика.
- **Python** — ручные реализации (см. выше) или `galois` / `pyfinite` / `sympy`.
- **`galois`** — удобная библиотека для `GF(2^m)` с NumPy-векторизацией.

Пример в Sage:

```sage
sage: F = GF(2^8, 'x')
sage: F.multiplicative_generator()
x
sage: F.fetch_int(0x57) * F.fetch_int(0x83)
x^7 + x^6 + 1
sage: (F.fetch_int(0x57) * F.fetch_int(0x83)).integer_representation()
193
```

`193 = 0xC1` — совпадает с ручной реализацией.

## Разобранный пример: GF(2^128) в GHASH

GHASH (аутентификация в AES-GCM) умножает блоки на ключ `H` в `GF(2^128)` по модулю `x^128 + x^7 + x^2 + x + 1`. Повторное использование nonce в GCM позволяет собрать систему линейных уравнений над `GF(2^128)` и восстановить `H` (forbidden attack). Без умения умножать в `GF(2^128)` этот эксплойт не написать.

Схематично:

```python
def ghash_mul(x, y):
    # умножение 128-битных полиномов по модулю GCM-полинома
    R = 0xE1 << 120
    z = 0
    v = y
    for i in range(128):
        if (x >> (127 - i)) & 1:
            z ^= v
        if v & 1:
            v = (v >> 1) ^ R
        else:
            v >>= 1
    return z
```

Именно эта функция в цикле собирает тег, и её линейность по `H` — основа атаки.

## Частые ошибки и подводные камни

- **Путать GF(p) и целые по модулю**: в `GF(p)` `p` обязано быть простым; по составному модулю деление не всегда существует.
- **Забыть про неприводимый полином**: умножение без редукции даёт элемент степени `≥ m`, то есть уже не элемент поля.
- **Использовать приводимый полином**: тогда `GF(2^m)` не поле, появляются делители нуля, ломается вся арифметика.
- **Считать, что любой элемент примитивен**: нет, порядок должен быть ровно `q-1`.
- **Ошибки в тестовых векторах**: всегда сверяйтесь со спецификацией (как с `0x57*0x83=0xC1`).

## Контрмеры и защита

- Выбирайте простые `p` с большим простым делителем `p-1` и `g` большого простого порядка.
- Для `GF(2^m)` фиксируйте проверенный неприводимый полином (для AES — `0x11B`, для GCM — GCM-полином).
- Не используйте малые поля (`m < 128` для криптографии на эллиптических кривых над `GF(2^m)` устарело и не рекомендуется).
- Для GHASH/GCM — никогда не переиспользуйте nonce.

## Что дальше / решение

С конечными полями открываются `crypto-gcm` (GHASH), `crypto-ecc` (кривые над `GF(p)`/`GF(2^m)`), `crypto-rsa-coppersmith-deep` (полиномы по модулю) и `crypto-post-quantum` (кольца полиномов). Практический навык — уметь быстро переключаться между «число по модулю» и «полином по модулю» и не терять неприводимый полином при редукции.

## Справочные таблицы

| Поле | Элементы | Сложение | Умножение |
|------|----------|----------|-----------|
| `GF(p)` | `0..p-1` | `mod p` | `mod p` |
| `GF(2^m)` | полиномы < `m` | XOR | умножение полиномов + mod `f(x)` |

| Параметр | AES-GF | GCM-GF |
|----------|--------|--------|
| Размер | `GF(2^8)` | `GF(2^128)` |
| Полином | `x^8+x^4+x^3+x+1` | `x^128+x^7+x^2+x+1` |
| Применение | S-box, MixColumns | GHASH |

| Понятие | Значение |
|---------|----------|
| неприводимый полином | аналог простого числа в `GF(2^m)` |
| примитивный элемент | образующий `GF(q)^*` |
| порядок элемента | минимальное `k` с `a^k=1` |
