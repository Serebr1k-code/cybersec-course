Наивная интуиция: если зашифровать дважды разными ключами, стойкость удвоится (2^56 → 2^112). Это **неверно**: meet-in-the-middle (MITM) сводит 2DES к 2^57 при 2^56 памяти. Атака настолько важна, что именно из-за неё появился 3DES (EDE), а не 2DES. В этой главе — устройство атаки, точные сложности, структура 3DES и обобщения MITM за пределы блочных шифров.

## Идея meet-in-the-middle

Пусть `C = E_{k2}(E_{k1}(P))`. Атакуем, «встречаясь посередине»:

- для всех `k1`: считаем `X = E_{k1}(P)`, кладём `X → k1` в таблицу;
- для всех `k2`: считаем `Y = D_{k2}(C)`, ищем `Y` в таблице.

Совпадение `X = Y` даёт кандидата `(k1, k2)`. Сложность: `2^k1 + 2^k2` операций и `2^k1` памяти вместо `2^{k1+k2}`. Для 2DES (56-битные ключи) — около **2^57** операций и **2^56** памяти вместо 2^112.

Ключевой момент: MITM работает, когда криптосистема **разложима** на два независимых слоя с раздельными ключами. Один слой (обычный DES) от этого не страдает — промежуточного состояния нет.

## Атака на 2DES: пошагово

1. Собрать одну пару (открытый текст `P`, шифротекст `C`).
2. Построить таблицу `{E_{k1}(P) : k1}` по всем `2^56` ключам (это ~2^56 записей — огромная память).
3. Для каждого `k2` вычислить `D_{k2}(C)` и искать в таблице.
4. Каждое совпадение — кандидат; проверить на второй паре (P', C'), чтобы отсеять ложные.

Практика: полный 2^56 обход дорог, поэтому на CTF используют **редуцированный DES** (ключ 20–28 бит) — тогда атака мгновенна и воспроизводима.

```python
from Crypto.Cipher import DES
def enc(key, pt):
    return DES.new(key, DES.MODE_ECB).encrypt(pt)
def dec(key, ct):
    return DES.new(key, DES.MODE_ECB).decrypt(ct)

def mitm_2des(pt, ct, keybits=20):
    table = {}
    for k1 in range(1 << keybits):
        kb = k1.to_bytes(8, 'big')
        table[enc(kb, pt)] = k1
    for k2 in range(1 << keybits):
        kb = k2.to_bytes(8, 'big')
        mid = dec(kb, ct)
        if mid in table:
            return table[mid], k2        # кандидат (k1, k2)
    return None
```

Ложные срабатывания: ожидаемое число ложных совпадений ≈ `2^{2·keybits} / 2^{blocksize}`; проверяйте кандидатов на второй паре.

## 3DES: 2-key и 3-key

3DES = **EDE** (Encrypt-Decrypt-Encrypt): `C = E_{k3}(D_{k2}(E_{k1}(P)))`. Варианты:

- **3-key (K1≠K2≠K3):** ключ 168 бит, эффективная стойкость ~112 бит (из-за MITM-атак с `2^112`).
- **2-key (K1=K3):** ключ 112 бит, стойкость ~80 бит (MITM сводит к `2^{2·56}=2^{112}` операций, но с оптимизациями ~`2^80`).
- **1-key:** эквивалентен DES (EDE с одинаковыми ключами = E).

Почему EDE, а не EEE: EDE позволяет сконфигурировать систему как обычный DES, задав `k1=k2=k3`, — обратная совместимость.

| Схема | Ключ | Эффективная стойкость | Причина |
|-------|:----:|:---------------------:|---------|
| DES | 56 | 56 | перебор |
| 2DES | 112 | ~57 | MITM |
| 3DES 2-key | 112 | ~80–90 | MITM |
| 3DES 3-key | 168 | ~112 | MITM |

## Память и time-memory tradeoff

Полный MITM упирается в память (`2^56` записей — петабайты). Обходные пути:

- **Hellman / rainbow tables** — компромисс время↔память для перебора.
- **Partial matching** — сравнивать не все биты середины, а фрагмент: память падает, время растёт.
- **Distinguished points** — хранить только «особые» точки.
- **Разбиение ключевого пространства** — распределённый перебор (boolector-style) по узлам.

Для 3-key 3DES известны атаки сложнее `2^{112}` (например, `2^{90}` при большом объёме данных), но они требуют `2^{2^...}` данных и на практике не применяются.

## Обобщения MITM за пределы блочных шифров

- **Двойной HMAC с независимыми ключами** — MITM не даёт выигрыша, если внутренний слой — криптостойкая хэш-функция (нет обратной функции для произвольного входа). HMAC специально устроен так, чтобы не разлагаться.
- **Композиция хэшей** `H2(H1(x))` — MITM даёт коллизию за `2^{n/2}` при определённых условиях (multicollision), см. `crypto-hash-forge`.
- **MAC-then-encrypt** — MITM-подобные атаки на композиции.
- **Cascade ciphers** — любая «двойная» конструкция с независимыми ключами уязвима к MITM.
- **Key whitening** — добавление XOR-ключей до/после не спасает от MITM, но усложняет.

## Разобранный пример: редуцированный 2DES

Задача: даны `(P, C)` и известно, что ключи 20-битные, схема — двойной DES. Полный скрипт:

```python
from Crypto.Cipher import DES
from itertools import product

P = b'01234567'
C = bytes.fromhex('...')      # шифротекст

table = {}
for k1 in range(1 << 20):
    key = k1.to_bytes(8, 'big')
    table[DES.new(key, DES.MODE_ECB).encrypt(P)] = k1

for k2 in range(1 << 20):
    key = k2.to_bytes(8, 'big')
    mid = DES.new(key, DES.MODE_ECB).decrypt(C)
    if mid in table:
        print("found", table[mid], k2)
```

Проверка: расшифруйте `C` найденными ключами и сравните с `P`; затем проверьте на второй паре, чтобы исключить ложное совпадение.

## Частые ошибки и тупики

- **Путать EDE и EEE.** 3DES = EDE; EDE с равными ключами = DES.
- **Забыть про вторую пару.** Без неё кандидатов может быть много (ложные).
- **Неверный размер ключа в bytes.** DES-ключ — ровно 8 байт; редуцированный ключ дополняется нулями.
- **Пытаться сделать полный MITM на 2^56.** Нужна память петабайтного масштаба — на CTF всегда редуцируют.
- **Ожидать, что MITM «ломает HMAC».** HMAC не разложим — MITM не применим.
- **Игнорировать parity bits.** В DES 8 бит каждого байта — чётность; реальных бит 56.
- **Считать 3DES мёртвым.** Он deprecated, но всё ещё встречается в legacy (и в задачах).

## Что дальше (decision)

1. Даны две пары и двойное шифрование → MITM с таблицей.
2. Ключи большие, но редуцируемы (условие задачи) → MITM на редуцированных ключах.
3. Три слоя (3DES) → MITM на два слоя + перебор третьего или 2-key атака.
4. HMAC/хэш-композиция → MITM неприменим, смотрите `crypto-hash-forge`.
5. Нужен компромисс память↔время → rainbow/partial matching.
6. Задача про «двойное шифрование не помогает» → это она, применяйте MITM.

## Полный разбор: 3DES 2-key

В 2-key 3DES (`K1 = K3`, `K2` независим) шифрование — `C = E_{K1}(D_{K2}(E_{K1}(P)))`. MITM-атака сводит перебор к ~`2^{2·56}` с оптимизациями до ~`2^{80}`:

1. Перебираем `K1` (56 бит), считаем `X = E_{K1}(P)` и `Y = D_{K1}(C)`.
2. Ищем `K2` такие, что `D_{K2}(X) = E_{K2}(Y)` — встреча посередине.
3. Каждое совпадение — кандидат; проверяем на второй паре.

```python
from Crypto.Cipher import DES3
# учебно: редуцированные ключи
# table[X] = K1; затем для K2: mid = D_{K2}(X) ... сравнение с E_{K2}(Y)
```

Практическая сложность: `2^80` и `2^56` памяти делают полную атаку нецелевой, но это объясняет, почему 2-key 3DES даёт лишь ~80–90 бит, а не 112. В CTF всегда редуцируют ключи (например, 16–20 бит на компоненту) — тогда скрипт выше работает мгновенно.
