## Зачем это нужно

Обычное шифрование защищает данные, но делает их «чёрным ящиком»: пока шифротекст не расшифрован, с ним ничего не сделаешь. **Гомоморфное шифрование** позволяет вычислять над шифротекстами: перемножив два шифротекста, вы получаете шифротекст произведения открытых текстов, не зная самих текстов. Это фундамент приватных вычислений (электронное голосование, агрегация телеметрии, приватный ML).

Но у гомоморфности есть обратная сторона: она же — **malleability**, то есть возможность изменять шифротекст предсказуемым образом. Это порождает целые классы атак, и на CTF гомоморфные схемы встречаются именно в этом качестве.

## Виды гомоморфности

- **Мультипликативная**: `E(a) * E(b) = E(a*b)`. Есть у textbook RSA и ElGamal.
- **Аддитивная**: `E(a) * E(b) = E(a+b)`. Есть у Paillier, экспоненциального ElGamal, схемы Бенало.
- **Полная (FHE)**: поддерживает и сложение, и умножение произвольное число раз (Gentry, 2009). На практике — TFHE/BFV/CKKS, но сложна и медленна.

Для CTF чаще всего встречаются первые два типа — на RSA/ElGamal/Paillier.

## Мультипликативность RSA и ElGamal

**Textbook RSA**: `E(m) = m^e mod n`. Тогда

```
E(a) * E(b) = a^e * b^e = (ab)^e = E(ab) (mod n)
```

Это мультипликативная гомоморфность. Она же — основа атаки на подписи: если у вас есть подписи `s1` для `m1` и `s2` для `m2`, то `s1*s2` — подпись для `m1*m2`, хотя вы её не запрашивали. Это **existential forgery** textbook RSA.

**ElGamal**: `E(m) = (g^r, m * h^r)`. Перемножение двух шифротекстов даёт `(g^(r1+r2), m1*m2 * h^(r1+r2))` — снова валидный шифротекст для `m1*m2`. Гомоморфность снова бесплатна и снова опасна.

```python
# RSA malleability: удвоение сообщения без ключа
n, e = 3233, 17
c = pow(42, e, n)
c2 = (c * pow(2, e, n)) % n     # шифротекст для 84
print(pow(c2, 413, n))          # 84, если d=413
```

## Аддитивность Paillier

Схема Paillier (1999) даёт **аддитивную** гомоморфность и потому широко используется (голосование, приватная агрегация).

Ключи: `n = p*q`, `λ = lcm(p-1, q-1)`, `g = n+1`, `μ = (L(g^λ mod n^2))^{-1} mod n`, где `L(u) = (u-1)/n`.

- Шифрование: `c = g^m * r^n mod n^2` для случайного `r`.
- Расшифрование: `m = L(c^λ mod n^2) * μ mod n`.

Свойства:

```
E(m1) * E(m2)     = E(m1 + m2)
E(m)^k            = E(m * k)
```

То есть можно складывать зашифрованные значения и умножать на открытую константу — идеально для подсчёта сумм без раскрытия слагаемых.

```python
from math import gcd
import random

def lcm(a, b): return a * b // gcd(a, b)
def L(u, n): return (u - 1) // n

def paillier_keygen(bits=512):
    p = gen_prime(bits); q = gen_prime(bits)
    n = p * q
    g = n + 1
    lam = lcm(p - 1, q - 1)
    mu = pow(L(pow(g, lam, n * n), n), -1, n)
    return (n, g), (lam, mu)

def encrypt(pk, m):
    n, g = pk
    r = random.randrange(1, n)
    while gcd(r, n) != 1:
        r = random.randrange(1, n)
    return (pow(g, m, n * n) * pow(r, n, n * n)) % (n * n)

def decrypt(sk, pk, c):
    n, g = pk
    lam, mu = sk
    return (L(pow(c, lam, n * n), n) * mu) % n
```

Гомоморфность проверяется так:

```python
c = (encrypt(pk, 3) * encrypt(pk, 4)) % (n * n)
print(decrypt(sk, pk, c))   # 7
```

## Инструменты и команды

- **Python + gmpy2/sympy** — реализация Paillier и арифметика больших чисел.
- **`phe`** — библиотека Partially Homomorphic Encryption (Paillier, ElGamal, Benaloh, Damgård–Jurik).
- **`python-paillier`** — готовая реализация Paillier.
- **SEAL / OpenFHE / TFHE** — библиотеки для FHE (полного гомоморфного шифрования).

Пример с `phe`:

```python
from phe import paillier
pub, priv = paillier.generate_paillier_keypair()
c1, c2 = pub.encrypt(5), pub.encrypt(10)
print(priv.decrypt(c1 + c2))    # 15
```

## Разобранный пример: атака через гомоморфный оракул

Многие CTF-задачи дают сервер, который расшифровывает **не всё**, а лишь «валидные» шифротексты (проверяет, что открытый текст — определённой формы). Гомоморфность позволяет обойти ограничение:

1. У вас есть `c = E(secret)`, который сервер расшифровывать отказывается.
2. Вы вычисляете `c' = c * E(k)` для открытой константы `k` — это `E(secret + k)`.
3. Просите расшифровать `c'`, получаете `secret + k`.
4. Вычитаете `k` — восстановили `secret`.

Это классический обход «проверки на допустимость» и одновременно иллюстрация, почему malleability опасна: без аутентификации шифротекста гомоморфность даёт атакующему оракул.

## Контрмеры и защита

- **Аутентифицируйте шифротексты**: гомоморфное шифрование не даёт целостности; добавляйте подпись/MAC, проверяемый до расшифровки.
- **Ограничивайте оракул**: не расшифровывайте произвольные шифротексты; используйте zero-knowledge-доказательства корректности.
- **Rerandomization**: в некоторых схемах добавляйте свежую случайность, чтобы затруднить манипуляции.
- Для FHE — выбирайте стойкие параметры (уровни безопасности 128+ бит), избегайте малых `n` в Paillier.

## FHE: краткий обзор и практика

Частично гомоморфные схемы (RSA, ElGamal, Paillier) поддерживают **одну** операцию: либо сложение, либо умножение. Этого достаточно для голосования и агрегации, но не для произвольных вычислений. **Полностью гомоморфное шифрование (FHE)** поддерживает обе операции неограниченно, что позволяет вычислять любую функцию над шифротекстами. Первую FHE-схему предложил Крейг Джентри в 2009 году; она была теоретической и крайне медленной, но открыла целое направление.

Современные практические FHE-схемы делятся на семейства:

- **BFV/BGV** — для точной целочисленной арифметики;
- **CKKS** — для приближённых вычислений над вещественными числами (ML, статистика);
- **TFHE** — для быстрых булевых схем и сравнений.

Общая идея — шум (noise) в шифротексте, который растёт при вычислениях. Чтобы схема работала неограниченно, применяют **bootstrapping** — процедуру «перезагрузки» шума. Именно bootstrapping делает FHE полным, но и дорогим. На CTF полноценный FHE встречается редко (слишком сложен), но его **параметры** — частая тема: если уровень безопасности выбран слишком низким, шум можно устранить и восстановить сообщение (например, атаки на малые параметры в задачах на LWE).

Практически FHE реализуют в библиотеках **SEAL** (Microsoft), **OpenFHE**, **TFHE-rs**, **HElib**. Типовой код на SEAL слишком объёмный для CTF, но понимание «шум + bootstrapping» полезно: во многих задачах «сломать FHE» означает найти способ убрать шум.

## Приватная агрегация и голосование: разобранный сценарий

Рассмотрим, как аддитивная гомоморфность Paillier решает реальную задачу — подсчёт голосов без раскрытия индивидуальных бюллетеней.

1. Избирательная комиссия публикует открытый ключ Paillier.
2. Каждый избиратель шифрует свой голос (0 или 1) и отправляет `E(v_i)`.
3. Комиссия перемножает все шифротексты: `C = ∏ E(v_i) = E(Σ v_i)`.
4. Расшифровав `C`, комиссия получает сумму голосов — не видя ни одного индивидуального бюллетеня.

Это работает благодаря `E(a)*E(b)=E(a+b)`. Аналогично считают сумму телеметрии, среднюю зарплату, распределение по категориям.

Но здесь же кроется атака: **без доказательств корректности** злоумышленник может отправить не 0/1, а `E(1000000)`, исказив результат. Поэтому в реальных системах каждый бюллетень сопровождается **zero-knowledge-доказательством** того, что зашифрованное значение лежит в `{0,1}` (range proof). Без такого доказательства гомоморфная агрегация небезопасна — и это классический CTF-сюжет: найти отсутствие проверки и «проголосовать» много раз или большим значением.

Ещё один практический момент: Paillier требует случайного `r` при каждом шифровании. Если реализация переиспользует `r` (или делает его детерминированным), два одинаковых голоса дадут одинаковые шифротексты, и приватность рушится. Проверяйте случайность `r` в коде — это частая ошибка самодельных реализаций.

## Частые ошибки и подводные камни

- **Забыть про случайность в Paillier**: без `r^n` шифрование детерминировано и ломается.
- **Считать, что гомоморфность — всегда баг**: это фича, но требует аутентификации.
- **Использовать textbook RSA как «гомоморфное шифрование»**: без padding это небезопасно (атаки Блейхенбахера, мультипликативные подделки).
- **Малый `n` в Paillier**: 512 бит недостаточно, нужны 2048+.
- **Оракул без ограничений**: если сервер расшифровывает всё, атака тривиальна.

## Что дальше / решение

Гомоморфное шифрование — мост к `crypto-threshold-mpc` (несколько участников) и `crypto-zk-proofs` (доказательства корректности). На CTF ищите оракул расшифровки и возможность домножить шифротекст — это почти всегда решающий шаг. В разработке — используйте `phe`/SEAL и не забывайте про аутентификацию.
