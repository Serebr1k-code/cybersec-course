## Вопрос, с которого всё начинается

Обычное шифрование делает данные «чёрным ящиком»: пока шифротекст не расшифрован, с ним ничего не сделаешь. А если нужно посчитать **сумму** зашифрованных чисел, не расшифровывая их? Это умеет **гомоморфное шифрование**: перемножив два шифротекста, вы получаете шифротекст суммы или произведения. У него же есть тёмная сторона — **malleability** (возможность предсказуемо менять шифротекст), из которой растут атаки.

## Наш пример

Реализуем **Paillier** — аддитивную схему: `E(a)·E(b) = E(a+b)`. Термин **аддитивная гомоморфность** — сложение открытых значений соответствует умножению шифротекстов.

```python
import random
from math import gcd
from sympy import randprime
def lcm(a, b): return a * b // gcd(a, b)
def L(u, n): return (u - 1) // n

p, q = randprime(2**255, 2**256), randprime(2**255, 2**256)
n = p * q; g = n + 1
lam = lcm(p - 1, q - 1)
mu = pow(L(pow(g, lam, n * n), n), -1, n)

def enc(m):
    r = random.randrange(1, n)
    while gcd(r, n) != 1:
        r = random.randrange(1, n)
    return (pow(g, m, n * n) * pow(r, n, n * n)) % (n * n)

def dec(c):
    return (L(pow(c, lam, n * n), n) * mu) % n
```

Реальный прогон:

```
Paillier: dec(E(5)*E(10)) = 15 (ожидаем 15)
Paillier: dec(E(5)^3)     = 15 (ожидаем 15)
RSA malleability: dec(c * E(2)) = 84 (ожидаем 84)
```

Мы сложили `5 + 10 = 15`, не расшифровывая слагаемые, и «удвоили» сообщение RSA без ключа.

## Шаг 1: виды гомоморфности

- **Мультипликативная:** `E(a)·E(b) = E(a·b)`. Есть у textbook RSA и ElGamal.
- **Аддитивная:** `E(a)·E(b) = E(a+b)`. Есть у Paillier, экспоненциального ElGamal, схемы Бенало.
- **Полная (FHE):** поддерживает и `+`, и `×` неограниченно (Gentry, 2009). На практике — TFHE/BFV/CKKS.

Для CTF чаще всего встречаются первые два типа.

## Шаг 2: мультипликативность RSA и ElGamal

**Textbook RSA:** `E(m) = m^e mod n`. Тогда `E(a)·E(b) = a^e·b^e = (ab)^e = E(ab)`. Это мультипликативная гомоморфность — и она же основа атаки на подписи: если есть подписи `s1` для `m1` и `s2` для `m2`, то `s1·s2` — подпись для `m1·m2`, хотя вы её не запрашивали (**existential forgery**).

**ElGamal:** `E(m) = (g^r, m·h^r)`. Перемножение двух шифротекстов даёт `(g^{r1+r2}, m1·m2·h^{r1+r2})` — валидный шифротекст для `m1·m2`.

## Шаг 3: аддитивность Paillier

Ключи: `n = p·q`, `λ = lcm(p-1, q-1)`, `g = n+1`, `μ = (L(g^λ mod n²))^{-1} mod n`, где `L(u) = (u-1)/n`.

- Шифрование: `c = g^m · r^n mod n²` для случайного `r`.
- Расшифрование: `m = L(c^λ mod n²) · μ mod n`.

Свойства:

```
E(m1) · E(m2) = E(m1 + m2)
E(m)^k       = E(m · k)
```

Можно складывать зашифрованные значения и умножать на открытую константу — идеально для подсчёта сумм без раскрытия слагаемых.

## Шаг 4: атака через гомоморфный оракул

Многие CTF-задачи дают сервер, который расшифровывает **не всё**, а лишь «валидные» шифротексты (проверяет форму открытого текста). Гомоморфность обходит ограничение:

1. Есть `c = E(secret)`, который сервер расшифровывать отказывается.
2. Вычисляем `c' = c · E(k)` для открытой константы `k` — это `E(secret + k)`.
3. Просим расшифровать `c'`, получаем `secret + k`.
4. Вычитаем `k` — восстановили `secret`.

Это классический обход «проверки на допустимость» и иллюстрация, почему malleability опасна: без аутентификации шифротекста гомоморфность даёт атакующему оракул.

## Шаг 5: приватная агрегация и защита

Аддитивная гомоморфность Paillier решает задачу электронного голосования:

1. Комиссия публикует открытый ключ Paillier.
2. Каждый избиратель шифрует голос (0 или 1) и отправляет `E(v_i)`.
3. Комиссия перемножает: `C = ∏ E(v_i) = E(Σ v_i)`.
4. Расшифровав `C`, комиссия получает сумму голосов, не видя индивидуальных бюллетеней.

Но здесь же кроется атака: **без range proof** злоумышленник отправит `E(1000000)` и исказит результат. Поэтому каждый бюллетень сопровождается ZK-доказательством, что значение лежит в `{0,1}` (`crypto-zk-proofs`).

**Контрмеры:**

- **Аутентифицировать шифротексты** (подпись/MAC до расшифровки).
- **Ограничивать оракул**: не расшифровывать произвольные шифротексты, требовать ZK-доказательства корректности.
- **Rerandomization** — свежая случайность в шифротексте.
- Для FHE — стойкие параметры (уровень 128+ бит), `n` ≥ 2048 бит в Paillier.

| Схема | Тип гомоморфности | Операция над шифротекстами |
|-------|-------------------|----------------------------|
| RSA | мультипликативная | `E(a)·E(b)=E(ab)` |
| ElGamal | мультипликативная | `E(a)·E(b)=E(ab)` |
| Paillier | аддитивная | `E(a)·E(b)=E(a+b)` |
| FHE (BFV/CKKS) | полная | и `+`, и `×` |

## Шаг 6: контрмеры и частые ошибки

- **Аутентифицируйте шифротексты.** Гомоморфное шифрование не даёт целостности; добавляйте подпись/MAC, проверяемый **до** расшифровки.
- **Ограничивайте оракул.** Не расшифровывайте произвольные шифротексты; требуйте zero-knowledge-доказательство корректности.
- **Не берите малый `n`.** Для Paillier 512 бит недостаточно — нужны 2048+.
- **Не забывайте случайность.** Без `r^n` шифрование Paillier детерминировано и ломается.
- **Не используйте textbook RSA как «гомоморфное шифрование»** — без padding это небезопасно (атаки Блейхенбахера, мультипликативные подделки).

На практике Paillier реализуют готовыми библиотеками: `phe` (Partially Homomorphic Encryption), `python-paillier`, а для FHE — SEAL/OpenFHE/TFHE. Пример на `phe` короче учебного:

```python
from phe import paillier
pub, priv = paillier.generate_paillier_keypair()
print(priv.decrypt(pub.encrypt(5) + pub.encrypt(10)))    # 15
```

Но даже с библиотекой помните про **rerandomization**: чтобы затруднить манипуляции, шифротекст иногда «освежают» свежей случайностью. А аутентификацию (MAC/подпись, проверяемые до расшифровки) библиотека за вас не добавит.

## Что мы теперь знаем

- Гомоморфность позволяет считать над шифротекстами.
- RSA/ElGamal — **мультипликативные**, Paillier — **аддитивная**.
- Paillier даёт `E(a)·E(b)=E(a+b)` и `E(m)^k=E(mk)`.
- Malleability без аутентификации превращается в оракул расшифровки.
- Range proof обязателен для гомоморфной агрегации.
- FHE (BFV/CKKS/TFHE) — полная, но дорогая.

## Почему гомоморфность — это и удобство, и дыра

Гомоморфное шифрование позволяет считать над шифротекстами, не расшифровывая их: `E(a) ⊙ E(b) = E(a ∗ b)` для подходящей операции. В RSA это умножение: `(m1^e)(m2^e) = (m1·m2)^e mod n`. В ElGamal — тоже умножение. В Paillier — сложение: `E(a)·E(b) = E(a+b)`, потому что шифрование живёт в мультипликативной группе `Z*_{n²}`, а показатели складываются.

Полезно это для приватной агрегации: клиенты шлют `E(x_i)`, сервер перемножает и получает `E(Σx_i)`, не видя ни одного `x_i`. Но та же алгебраическая структура — источник атак. **Malleability** означает, что шифротекст можно осмысленно изменить, не зная ключа. Если протокол принимает изменённый шифротекст как валидный, атакующий получает **гомоморфный оракул**: он подставляет `E(a)·E(b)` и просит расшифровать, извлекая информацию о `a` или `b`. Классический пример — Bleichenbacher-подобные атаки на RSA-HE и атаки на электронные голосования, где «умножение бюллетеня на константу» искажает голос.

Защита — **CCA-безопасность**: расшифровщик должен отвергать любой шифротекст, которого сам не породил. Достигается подписью или commitment'ом на шифротекст либо ZK-доказательством корректности, а не только гомоморфной структурой.

## Если не сработало

- **Оракул отвергает изменённые шифротексты.** Значит, включена CCA-защита (подпись, ZK-proof, проверка формата) — гомоморфный оракул закрыт, ищите другой путь.
- **Не сходится формула.** Проверьте группу: Paillier аддитивен по `mod n`, RSA/ElGamal мультипликативны; перепутать сложение и умножение — типичная ошибка.
- **Секрет не восстанавливается.** Возможно, `gcd(c, n) ≠ 1` (тогда факторизация сама даёт ключ) или параметры сгенерированы с общей простой компонентой.
- **Рандомизация отсутствует.** Детерминированное RSA (без OAEP) даёт одинаковые шифротексты для равных сообщений — это сразу утечка равенства и путь к атакам.
- **Paillier с малым `n`.** Если `n` мал, дискретный логарифм в `Z*_{n²}` считается перебором; модуль должен быть RSA-размера.

## Частые вопросы

**Какое шифрование «полностью гомоморфное» (FHE)?** То, что поддерживает и сложение, и умножение произвольно много раз (Gentry, CKKS, BFV, TFHE). RSA/ElGamal/Paillier гомоморфны лишь по одной операции и ограниченно.

**Почему Paillier аддитивен, а RSA нет?** В RSA показатель степени перемножается, поэтому умножаются сами сообщения. В Paillier сложение показателей даёт сложение сообщений по модулю — отсюда аддитивность.

**Где это реально применяют?** Приватная агрегация метрик, электронные выборы, PIR, federated learning с защитой градиентов, MPC-протоколы.
