## Вопрос, с которого всё начинается

Сервер шифрует сообщение `m`, а затем `m + 1` (например, счётчик), одним и тем же RSA-ключом с малой экспонентой `e = 3`. По отдельности каждый шифротекст неприступен. Но вместе они дают **два полиномиальных уравнения** с общим корнем, и задача решается без факторизации. Разберём атаку Franklin-Reiter.

## Наш пример

Зашифруем `m` и `m+1` под одним ключом с `e = 3`:

```python
from sympy import nextprime
p = nextprime(2**256); q = nextprime(2**257)
n = p*q; e = 3
m = 0x123456789abcdef0
c1 = pow(m, e, n)
c2 = pow(m + 1, e, n)
```

Вопрос: как восстановить `m`, зная только `n, e, c1, c2`?

## Шаг 1: превращаем шифротексты в полиномы

Определим полиномы от `x`:

```
f1(x) = x^e − c1
f2(x) = (a·x + b)^e − c2
```

В нашем случае `a = 1, b = 1`. Оба полинома имеют общий корень `x = m` по модулю `n`: подстановка `m` даёт `m^e − c1 = 0` и `(m+1)^e − c2 = 0`. Их **gcd** (наибольший общий делитель) над кольцом `Z_n[x]` делится на `(x − m)`, и при малом `e` оказывается линейным.

## Шаг 2: считаем gcd полиномов

В Sage это одна строка, но полезно понять механику — реализуем gcd над `Z_n[x]` вручную (Евклид с модульными обратными):

```python
def poly_mod(a, b, n):
    a = a[:]; inv = pow(b[-1], -1, n)
    while len(a) >= len(b) and any(a):
        coef = (a[-1] * inv) % n
        shift = len(a) - len(b)
        for i in range(len(b)):
            a[shift+i] = (a[shift+i] - coef*b[i]) % n
        while a and a[-1] == 0: a.pop()
    return a

def poly_gcd(a, b, n):
    while any(b):
        a, b = b, poly_mod(a, b, n)
    inv = pow(a[-1], -1, n)
    return [(c * inv) % n for c in a]

f1 = [(-c1) % n, 0, 0, 1]         # x^3 - c1
f2 = [(1 - c2) % n, 3, 3, 1]      # (x+1)^3 - c2
g = poly_gcd(f1, f2, n)
print("degree:", len(g) - 1)
```

```
degree: 1
```

НОД оказался **линейным** — то есть `x − m`. Из него `m` восстанавливается напрямую:

```python
m_rec = (-g[0] * pow(g[1], -1, n)) % n
print("recovered m == original:", m_rec == m)
```

```
recovered m == original: True
```

Сообщение восстановлено без факторизации `n`.

## Шаг 3: почему gcd линеен

`f1` и `f2` оба делятся на `(x − m)` в `Z_n[x]`. Их НОД тоже делится на `(x − m)`. При аффинной связи `m2 = a·m + b` и малом `e` НОД оказывается ровно `x − m` (степень 1). Тогда `m = −constant / leading` по модулю `n`. Алгоритм Евклида для полиномов работает над `Z_n[x]`, если старшие коэффициенты обратимы по `n` — для малых `e` обычно так.

## Шаг 4: вариант без Sage для e = 2

Для `e = 2` можно обойтись элементарной алгеброй. Пусть `c1 = m²`, `c2 = (a·m + b)² = a²m² + 2abm + b²`. Подставим `m² = c1`:

```
c2 = a²·c1 + 2ab·m + b²   =>   m = (c2 − a²·c1 − b²) · (2ab)^{−1} mod n
```

Это линейное уравнение — gcd полиномов не нужен.

## Шаг 5: обобщения и связь с другими атаками

- **Полиномиальная связь** `m2 = P(m1)`: gcd может быть выше степени, но всё ещё решается.
- **Неизвестная связь** `m2 = a·m1 + b`: переберите малые `a, b` и на каждом пробуйте gcd.
- **Сообщение = другое + суффикс**: связь `m2 = m1·2^k + suf`; перебирайте длину суффикса и его значение.
- **Håstad:** одно сообщение под **разными** `n` → CRT + целочисленный корень (`crypto-rsa-small-e-hastad`).
- **Coppersmith:** малые корни полиномов по модулю `n` — обобщение, где Franklin-Reiter частный случай.

Различие ключевое: **Franklin-Reiter — один `n`**, **Håstad — разные `n`**.

## Шаг 6: чек-лист

- один и тот же `n`, два (или больше) шифротекста;
- малое `e` (`3`, `5`, `17`);
- сообщения связаны линейно (в условии сказано, или очевидно: `m+1`, суффикс, префикс);
- даны `a, b` или их можно угадать (малые).

Порядок: проверьте связь `m2 = a·m1 + b`; постройте `f1, f2`; возьмите gcd; при линейном gcd восстановите `m`; верифицируйте `pow(m, e, n) == c1`. Если `n` разные — это Håstad.

## Полный скрипт: перебор неизвестной связи

Если связь `m2 = a·m1 + b` не дана, но известно, что она аффинная с малыми `a, b`, переберите варианты и на каждом пробуйте gcd:

```python
# Sage
R.<x> = PolynomialRing(Zmod(n))
for a in range(1, 6):
    for b in range(-5, 6):
        g = (x^e - c1).gcd((a*x + b)^e - c2)
        if g.degree() == 1:
            m = int(-g[0] / g[1]) % n
            if pow(m, e, n) == c1:
                print("a,b =", a, b, "m =", hex(m)); raise SystemExit
```

Частая вариация: `m2 = m1 + suffix`, то есть связь `m2 = m1·2^k + suf`; тогда `a = 2^k`, `b = suf`. Пробуйте длины суффикса (1–4 байта) и перебирайте его значение при малом диапазоне. Ещё один практический случай — сервер шифрует `m` и `m+1` (счётчик): тогда `a = 1, b = 1`, и gcd даёт `m` сразу.

## Что мы теперь знаем

- Franklin-Reiter ломает два **линейно связанных** сообщения под одним ключом с малым `e`.
- Шифротексты превращаются в полиномы `x^e − c1` и `(a·x+b)^e − c2`.
- Их **gcd** даёт линейный полином `x − m`.
- Для `e = 2` есть линейная формула без gcd.
- **Один `n`** отличает FR от Håstad (разные `n`).
- Защита — правильный padding (OAEP), убирающий линейную связь.

## На что смотреть дальше

- **Большой `e`** — gcd становится дорогим; FR рассчитан на малый `e`.
- **Неверная связь** — угадайте `a, b` или переберите малые варианты.
- **Старший коэффициент не обратим** — gcd над `Z_n[x]` ломается; попробуйте факторизацию.
- **Путать с Håstad** — Håstad это разные `n`, FR — один `n`.
- **Забыть про `mod n` при делении** — все операции в `Z_n`.
- **Не проверить корень** — всегда `pow(m, e, n) == c1`.

## Куда дальше

Мы научились атаковать связанные сообщения. Дальше — атаки на **ошибки в реализации** RSA: одна испорченная подпись выдаёт факторизацию. В уроке **crypto-rsa-faults** мы разберём Bellcore. А пока главное: **один `n`, малый `e`, линейная связь — gcd полиномов восстанавливает `m`.**

## Где пригодится

- **CTF (hard):** related-message RSA, малый `e`, связанные паддинги.
- **Bug bounty:** нестандартные схемы шифрования с общим ключом.
- **Аудит:** оценка использования RSA (паддинги, связи).
- **Работа:** анализ крипто-протоколов.
- **Разработка:** обязательный OAEP-паддинг.
