RSA с малым показателем `e` (часто `e=3`) и **связанными** сообщениями ломается без факторизации. Если под одним ключом зашифрованы `m` и `m' = a·m + b` (например, одно сообщение и оно же с добавленной подписью), то два шифротекста дают систему полиномиальных сравнений, и **gcd полиномов по модулю n** восстанавливает `m`. Это атака Franklin-Reiter — простая в реализации и очень частая в CTF.

## Идея атаки

Дано: `c1 = m^e mod n`, `c2 = (a·m + b)^e mod n` при одном `(n, e)`.

Определяем полиномы от `x`:

```
f1(x) = x^e - c1
f2(x) = (a·x + b)^e - c2
```

Оба имеют общий корень `x = m` по модулю `n`. Их **gcd** (над `Z_n[x]`) даёт линейный полином `x - m`, откуда `m` восстанавливается напрямую.

## Почему gcd работает

`f1` и `f2` делятся на `(x - m)` в кольце `Z_n[x]` (при корректных `c1, c2`). НОД — наибольший общий делитель — тоже делится на `(x - m)`. Если связь аффинная и `e` мал, НОД оказывается **линейным**: `x - m`. Тогда `m = -constant / leading` по модулю `n`.

Алгоритм Евклида для полиномов работает над `Z_n[x]`, если старшие коэффициенты обратимы по `n` (для малых `e` обычно да).

## Обобщение на произвольную связь

- **Линейная (аффинная):** `m2 = a·m1 + b` — классический случай, `gcd` линеен.
- **Полиномиальная:** `m2 = P(m1)` для известного полинома `P` — gcd может быть выше степени, но всё ещё решается.
- **Одинаковый `m` с разными паддингами:** если паддинги линейно связаны, применимо.
- **Несколько пар:** каждое уравнение сужает множество; можно объединять.

## Вариант без Sage (для e = 2)

Для `e=2` можно обойтись элементарной алгеброй:

```
c1 = m²
c2 = (a·m + b)² = a²m² + 2abm + b²
```

Подставляем `m² = c1`: `c2 = a²·c1 + 2ab·m + b²` → линейное уравнение на `m`:

```
m = (c2 - a²·c1 - b²) · (2ab)^{-1} mod n
```

Для `e>2` нужен gcd полиномов (Sage/`sympy`).

## Связь с Håstad и Coppersmith

- **Håstad (broadcast):** одно сообщение зашифровано несколькими **разными** ключами с малым `e` → CRT + целочисленный корень. См. `crypto-rsa-small-e-hastad`.
- **Franklin-Reiter:** одно сообщение (связь) под **одним** ключом → gcd полиномов.
- **Coppersmith:** обобщение на малые корни полиномов по модулю `n` (или делителя). Franklin-Reiter — частный случай, когда связь линейна и `e` мал.

## Инструменты и код

| Инструмент | Назначение |
|-----------|-----------|
| Sage | `gcd` полиномов над `Zmod(n)` |
| `sympy` | полиномиальный gcd |
| `pycryptodome` | шифрование/проверка |
| RsaCtfTool | автоопределение |

```python
# Sage
n, e = ..., ...
R.<x> = PolynomialRing(Zmod(n))
f1 = x^e - c1
f2 = (a*x + b)^e - c2
g = f1.gcd(f2)          # ожидаем линейный x - m
m = int(-g[0] / g[1])   # m = -constant/leading
print(bytes.fromhex(hex(m)[2:]))
```

## Распознавание и decision

Признаки задачи Franklin-Reiter:

- малое `e` (`3`, `5`, `17`);
- два шифротекста, и в условии сказано, что сообщения связаны (или дано `a`, `b`);
- «одно сообщение — другое с добавленным суффиксом/префиксом»;
- один и тот же `n` для обоих.

Порядок действий: если связь линейна и известна → gcd полиномов; если связь неизвестна → попробуйте угадать (`m2 = m1 + k`, `m2 = k·m1`) или перейдите к Coppersmith; если ключи разные → Håstad.

## Разобранный пример

Дано: `n`, `e=3`, `c1`, `c2`, и известно `m2 = m1 + 1`.

```python
R.<x> = PolynomialRing(Zmod(n))
g = (x^3 - c1).gcd((x+1)^3 - c2)
m = int(-g[0] / g[1])
print(bytes.fromhex(hex(m)[2:]).decode(errors='ignore'))
```

Проверка: `pow(m, e, n) == c1` и `pow(m+1, e, n) == c2`.

## Частые ошибки и тупики

- **Большой `e`.** gcd становится дорогим/нелинейным; FR рассчитан на малый `e`.
- **Неверная связь.** Угадайте `a`, `b` или переберите малые варианты.
- **Старший коэффициент не обратим.** Тогда gcd над `Z_n[x]` ломается — попробуйте `sympy`/факторизацию.
- **Путать с Håstad.** Håstad — разные `n`, FR — один `n`.
- **Забыть про `mod n` при делении.** Все операции — в `Z_n`.
- **Не проверить корень.** Всегда проверяйте `pow(m, e, n) == c1`.

## Что дальше (decision)

1. Один `n`, два связанных сообщения, малый `e` → gcd полиномов.
2. Связь неизвестна → перебор малых `a, b` или Coppersmith.
3. Разные `n` → Håstad (`crypto-rsa-small-e-hastad`).
4. Малый корень по модулю делителя `n` → Coppersmith (`crypto-rsa-coppersmith-deep`).
5. `e` большой → FR не работает, ищите другую уязвимость.
6. Нужна защита → не используйте малый `e` без правильного паддинга (OAEP).

## Справочная таблица

| Атака | Условие | Метод |
|-------|---------|------|
| Franklin-Reiter | один `n`, связь `a·m+b`, малый `e` | gcd полиномов |
| Håstad | разные `n`, один `m`, малый `e` | CRT + корень |
| Coppersmith | малый корень `mod n`/делителя | решётка |
| Wiener | малый `d` | цепные дроби |

## Полный скрипт: перебор неизвестной связи

Если связь `m2 = a·m1 + b` не дана, но известно, что она аффинная с малыми `a, b`, переберите варианты и на каждом пробуйте gcd:

```python
# Sage
n, e = ..., ...
R.<x> = PolynomialRing(Zmod(n))
for a in range(1, 6):
    for b in range(-5, 6):
        try:
            f1 = x^e - c1
            f2 = (a*x + b)^e - c2
            g = f1.gcd(f2)
            if g.degree() == 1:
                m = int(-g[0] / g[1]) % n
                if pow(m, e, n) == c1:
                    print("a,b =", a, b, "m =", hex(m)); raise SystemExit
        except Exception:
            continue
```

Частая вариация: `m2 = m1 + "suffix"` — то есть связь `m2 = m1·2^k + suf`; тогда `a = 2^k`, `b = suf`. Пробуйте длины суффикса (1–4 байта) и перебирайте его значение при малом диапазоне (например, 3-значный номер).

Ещё один практический случай: сервер шифрует `m` и `m+1` (счётчик). Тогда `a=1, b=1`, и gcd даёт `m` сразу — это самая частая формулировка в CTF.

## Чек-лист: связанные сообщения

- один и тот же `n`, два (или больше) шифротекста;
- малое `e` (`3`, `5`, `17`);
- в условии сказано, что сообщения связаны, либо связь очевидна (`m+1`, суффикс, префикс);
- «одно сообщение зашифровано, другое — с добавленным текстом»;
- даны `a, b` или их можно угадать (малые).

Порядок действий: 1) проверьте связь `m2 = a·m1 + b`; 2) постройте `f1, f2`; 3) возьмите gcd; 4) при линейном gcd восстановите `m`; 5) верифицируйте `pow(m, e, n) == c1`. Если `n` разные — это Håstad, а не Franklin-Reiter.

## Быстрые рецепты для CTF

- **`c1`, `c2`, один `n`, `e=3`** → gcd полиномов `x³-c1` и `(ax+b)³-c2`.
- **`e=2`** → решайте линейно без Sage (формула выше).
- **Связь неизвестна** → переберите `a∈[1,5]`, `b∈[-5,5]`.
- **Сообщение = другое + суффикс** → связь `m2 = m1·2^k + suf`, перебирайте `k` и `suf`.
- **Разные `n`** → это Håstad, CRT + целочисленный корень.
