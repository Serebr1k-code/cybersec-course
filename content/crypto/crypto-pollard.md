В `crypto-rsa-attacks` разобраны структурные атаки: common modulus, Wiener, Håstad, shared primes, Ферма. Но иногда задача сводится к «просто факторизуй `n`» — и тут нужен правильный инструмент. Этот урок — набор алгоритмов факторизации, каждый из которых бьёт по своей слабости числа: гладкий `p-1`, случайное `n`, наличие маленького множителя или близкие `p, q`.

## Как выбирать метод

| Свойство `n` | Метод | Сложность |
|---|---|---|
| `p-1` гладкое | Поллард `p-1` | `O(B log B)` |
| есть маленький простой множитель | trial division / ECM | зависит от множителя |
| `p ≈ q` | метод Ферма | `O(|p-q|)` |
| общий случай, `n` до ~120 бит | Поллард rho | `O(n^{1/4})` |
| общий случай, `n` до ~200+ бит | ECM / QS / NFS | субэкспоненциально |
| нужно «с нуля» | yafu, pari `factor`, sage | автоматом перебирает методы |

**Золотое правило:** сначала дёшево проверяем `gcd` всех модулей и маленькие делители, потом пробуем Полларда `p-1` и rho, и лишь затем — тяжёлые ECM/QS/NFS.

## Поллард p-1 (гладкий p-1)

Если у `n` есть простой множитель `p` такой, что `p-1` **гладкое** (все простые делители `p-1` малы), то по малой теореме Ферма `a^(p-1) ≡ 1 (mod p)` для любого `a`. Выберем `M` кратное всем числам до границы `B` (то есть `M = lcm(1..B)`), тогда `a^M ≡ 1 (mod p)` (если `p-1 | M`), значит `p | a^M - 1`, и `gcd(a^M - 1, n)` даст `p`.

```python
from math import gcd

def pollard_p1(n, B=100000):
    a = 2
    for j in range(2, B):
        a = pow(a, j, n)          # накапливаем a^(j!)
        g = gcd(a - 1, n)
        if 1 < g < n:
            return g
        if g == n:
            return None           # слишком далеко, перезапустить с другим a/меньшим B
    return None
```

**Признак:** `n` «случайное», но, например, `p` сгенерировано как `p = k·(2·3·5·...·B) + 1`. Частый сценарий в CTF — специально слабый ключ. Также `--attack p-1` в RsaCtfTool.

## Поллард rho (общий случай)

Идея: псевдослучайная последовательность `x_{i+1} = f(x_i) = x_i^2 + c mod n`. По парадоксу дней рождения два значения совпадут **по модулю неизвестного множителя p** раньше, чем по модулю `n`. Тогда `gcd(x_i - x_j, n) = p`.

```python
from math import gcd
import random

def pollard_rho(n, c=None):
    if n % 2 == 0: return 2
    while True:
        c = c or random.randrange(1, n)
        f = lambda x: (x * x + c) % n
        x = y = random.randrange(2, n)
        d = 1
        while d == 1:
            x = f(x)            # черепаха
            y = f(f(y))         # заяц
            d = gcd(abs(x - y), n)
        if d != n:
            return d
```

**Плюс:** константная память, простой. **Минус:** `O(n^{1/4})` — годится до ~120 бит. Для больших — ECM.

**Brent's improvement** (замена «зайца» на накопление произведений и батч-gcd) ускоряет rho в 2–4 раза:

```python
def brent(n):
    if n % 2 == 0: return 2
    y, c, m = random.randrange(1, n), random.randrange(1, n), 128
    g = r = q = 1
    while g == 1:
        x = y
        for _ in range(r): y = (y*y + c) % n
        k = 0
        while k < r and g == 1:
            ys = y
            for _ in range(min(m, r - k)):
                y = (y*y + c) % n
                q = q * abs(x - y) % n
            g = gcd(q, n); k += m
        r *= 2
    if g == n:
        g = 1
        while g == 1:
            ys = (ys*ys + c) % n
            g = gcd(abs(x - ys), n)
    return g
```

## ECM (Elliptic Curve Method)

ECM находит **маленький простой множитель** большого `n` за время, зависящее в основном от размера множителя, а не от `n`. Метод строит случайную эллиптическую кривую по модулю `n`, берёт случайную точку и вычисляет `k!·P`; если порядок кривой по модулю неизвестного `p` гладкий, `P` «схлопывается» и `gcd` координаты с `n` даёт `p`.

ECM — лучший друг, когда `n` большое (200+ бит), но у него есть 40–60-битный множитель. Реализовывать вручную не нужно — используйте `gmp-ecm`:

```bash
# найти множитель ~40 бит у большого n
echo "N" | ecm -c 100 1e5
# или наращивать B1
ecm -c 50 11000
```

```python
# Sage/PARI: ECM из коробки
sage -c "print(ecm.factor(2^128+1, 1000, 10))"
```

```bash
# PARI/GP
gp -q <<< "factor(2^128+1)"
```

## Метод Ферма (близкие p и q)

`n = a² - b² = (a-b)(a+b)`, где `a = (p+q)/2`, `b = (p-q)/2`. Перебираем `a` от `⌈√n⌉` вверх, пока `a² - n` не станет квадратом.

```python
from gmpy2 import isqrt

def fermat(n, limit=10**7):
    a = isqrt(n) + 1
    for _ in range(limit):
        b2 = a*a - n
        b = isqrt(b2)
        if b*b == b2:
            return int(a - b), int(a + b)
        a += 1
    return None
```

**Признак:** `p` и `q` сгенерированы «подряд» — `n` почти квадрат. Смотрите, насколько `⌈√n⌉² - n` мало: если близко к квадрату, Ферма выстрелит.


**Порядок в реальной задаче:**
1. trial division до 10^6;
2. `gcd` всех `n` между собой;
3. Поллард `p-1` (быстро);
4. Поллард rho/Brent до ~2^100;
5. ECM (наращивать B1);
6. Ферма, если `p ≈ q`;
7. QS/NFS (yafu/sage) для больших.

## Разобранный пример: слабый p-1

```python
from math import gcd

# p с гладким p-1
B = 1000
p = 1
for i in range(2, B):
    p *= i                      # p-1 = (B-1)! -> точно гладкое
p += 1
# найдём такое p, чтобы оно было простым (иначе возьмём p-1 как есть)
# для демонстрации используем "почти простой" вариант
```

Более практичный пример — распознать гладкий `p-1` из условия:

```python
from sympy import factorint

n = 0x...   # из задачи
# Дёшево: разложить n-1? Нет — n. Гладкость ищем у p-1, но p неизвестен.
# Поэтому просто прогоняем Полларда p-1 с нарастающим B:
for B in (1000, 10000, 100000, 1000000):
    f = pollard_p1(n, B)
    if f:
        print("factor:", f); break
```

Если `pollard_p1` вернул множитель — ключ сломан. Дальше стандартно: `q = n // p`, `d = pow(e, -1, (p-1)*(q-1))`, `m = pow(c, d, n)`.

## Частые ошибки

- **Сразу брать NFS.** Для `n` с маленьким множителем ECM найдёт его за секунды, а NFS будет считать часы.
- **Забыть про `gcd` всех модулей.** Две строки кода, а решают задачу мгновенно (shared primes).
- **Поллард `p-1` без перезапуска.** Если `gcd` вернул `n` (перебрали), надо уменьшить `B` или сменить `a`.
- **Считать `a**M` вместо `pow(a, M, n)`.** Для больших `M` это неподъёмно.
- **Игнорировать метод Ферма.** Он бесплатный и часто ловит «сгенерированные подряд» `p, q`.
- **Не проверить, что найденный делитель простой.** После факторизации разложите множитель (он может быть составным).

## Где пригодится

- **CTF crypto:** любая RSA-задача, где параметры «просто слабые» и нужна факторизация.
- **Аудит инфраструктуры:** поиск слабых/сгенерированных с ошибкой ключей (сглаженное p-1, близкие p,q, общие простые).
- **Bug bounty:** анализ криптографических библиотек и генераторов ключей.
- **Работа (SOC/IR):** понимание атак на смарт-карты и HSM.
- **Исследования:** базовый инструментарий криптоаналитика для любого RSA-анализа.
