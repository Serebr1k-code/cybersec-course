## Вопрос, с которого всё начинается

Структурные RSA-атаки (общий модуль, малая экспонента, близкие простые) не сработали, и задача сводится к простому «разложи `n` на множители». Перебирать делители бесполезно, если `n` большое. Но у каждого числа есть **своя слабость**, и правильный алгоритм бьёт именно по ней. Разберём арсенал и применим его к конкретным `n`.

## Наш пример

Возьмём 59-битное `n`, сгенерированное с умышленно слабым простым `p`:

```python
from math import gcd
from sympy import nextprime, isprime
prod = 2*3*5*7*11*13*17*19
for k in range(2, 200):
    p = prod*k + 1
    if isprime(p): break
q = nextprime(0xdeadbeef)
n = p * q
print("p =", p, "q =", q, "bits =", n.bit_length())
```

```
p = 106696591 q = 3735928579 bits = 59
```

`p-1 = prod*k` состоит только из маленьких простых — оно **гладкое**. Вопрос: как это использовать?

## Шаг 1: метод Полларда p-1

Идея — малая теорема Ферма. Если у `n` есть простой множитель `p`, у которого `p-1` гладкое, то для любого `a` выполнено `a^(p-1) ≡ 1 (mod p)`. Возьмём `M`, кратное всем числам до границы `B` (то есть `M = lcm(1..B)`); тогда `p-1 | M`, значит `a^M ≡ 1 (mod p)`, откуда `p | a^M − 1`, и `gcd(a^M − 1, n)` даёт `p`.

```python
def pollard_p1(n, B=100000):
    a = 2
    for j in range(2, B):
        a = pow(a, j, n)          # накапливаем a^(j!)
        g = gcd(a - 1, n)
        if 1 < g < n: return g
        if g == n: return None    # перебрали: уменьшить B или сменить a
    return None

print("factor:", pollard_p1(n, 200))
```

```
factor: 106696591
```

Множитель найден за доли секунды, хотя `n` — 59 бит. **Признак** применения: `n` «случайное», но `p` сгенерировано как `k·(2·3·5·…) + 1`. Частый сценарий в CTF — специально слабый ключ.

## Шаг 2: метод Полларда rho

Если `p-1` не гладкое, работает **rho** — метод для общего случая. Он строит псевдослучайную последовательность `x_{i+1} = x_i² + c mod n`. По парадоксу дней рождения два значения совпадут **по модулю неизвестного множителя `p`** раньше, чем по модулю `n`. Тогда `gcd(x_i − x_j, n) = p`.

```python
import random
def pollard_rho(n):
    if n % 2 == 0: return 2
    while True:
        c = random.randrange(1, n); f = lambda x: (x*x + c) % n
        x = y = random.randrange(2, n); d = 1
        while d == 1:
            x = f(x)          # черепаха
            y = f(f(y))       # заяц
            d = gcd(abs(x - y), n)
        if d != n: return d
```

Применим к 122-битному произведению двух больших простых:

```python
a = nextprime(2**61); b = nextprime(2**62)
print("factor:", pollard_rho(a*b))
```

```
factor: 2305843009213693967
```

Сложность rho — `O(n^{1/4})`, поэтому он годится примерно до 120 бит. **Brent's improvement** (накопление произведений и батч-`gcd`) ускоряет его в 2–4 раза.

## Шаг 3: метод Ферма для близких простых

Если `p` и `q` близки, `n = a² − b² = (a−b)(a+b)`, где `a = (p+q)/2`, `b = (p−q)/2`. Перебираем `a` от `⌈√n⌉` вверх, пока `a² − n` не станет полным квадратом:

```python
from sympy import integer_nthroot
def fermat(n, limit=10**7):
    a = integer_nthroot(n, 2)[0] + 1
    for _ in range(limit):
        b2 = a*a - n; b = integer_nthroot(b2, 2)[0]
        if b*b == b2: return a - b, a + b
        a += 1
```

```python
p = nextprime(2**64); q = nextprime(p + 1000)
print(fermat(p*q))
```

```
(18446744073709551629, 18446744073709552697)
```

**Признак:** `n` почти квадрат; `⌈√n⌉² − n` мало. Проверять Ферма стоит всегда — это дёшево.

## Шаг 4: ECM для маленьких множителей большого n

**ECM** (Elliptic Curve Method) находит маленький простой множитель большого `n` за время, зависящее в основном от **размера множителя**, а не от `n`. Он строит случайную эллиптическую кривую по модулю `n`; если порядок кривой по модулю неизвестного `p` гладкий, точка «схлопывается» и `gcd` даёт `p`. ECM — лучший друг, когда `n` большое (200+ бит), но у него есть 40–60-битный множитель. Реализовывать вручную не нужно — есть `gmp-ecm`:

```bash
ecm -c 200 43000 < n.txt      # наращивать B1 при неудаче
```

## Шаг 5: инструменты и порядок действий

```bash
yafu "factor(N)"                              # автоматический факторизатор
gp -q <<< "factor(1234567891011121314151617)" # PARI/GP
python3 RsaCtfTool.py -n N -e 65537 --attack p-1,pollard,fermat
```

**Порядок в реальной задаче:**

1. trial division до 10^6;
2. `gcd` всех `n` между собой (общие простые);
3. Поллард `p-1` (быстро);
4. Поллард rho/Brent до ~2^100;
5. ECM (наращивать B1);
6. Ферма, если `p ≈ q`;
7. QS/NFS (yafu/sage) для больших.

**Золотое правило:** сначала дёшево, потом дорого. Не запускайте NFS, если ECM найдёт множитель за секунды.

## Шаг 6: таблица выбора метода

| Свойство `n` | Метод | Сложность |
|---|---|---|
| `p-1` гладкое | Поллард `p-1` | `O(B log B)` |
| есть маленький множитель | trial division / ECM | зависит от множителя |
| `p ≈ q` | метод Ферма | `O(|p-q|)` |
| общий случай, `n` до ~120 бит | Поллард rho | `O(n^{1/4})` |
| общий случай, `n` до ~200+ бит | ECM / QS / NFS | субэкспоненциально |
| нужно «с нуля» | yafu, pari `factor`, sage | автоматом перебирает методы |

Таблица — это карта: сначала смотрим на структуру `n`, потом выбираем метод, а не наоборот. Часто достаточно одной строки из этой таблицы, чтобы понять, какая слабость заложена в задачу.

## Что мы теперь знаем

- Поллард `p-1` бьёт по **гладкому** `p-1`.
- Поллард rho — общий случай, сложность `O(n^{1/4})`, до ~120 бит.
- Метод Ферма выстреливает при **близких** `p, q`.
- ECM зависит от размера **множителя**, а не от `n`.
- Сначала `gcd` всех модулей, затем лёгкие методы, затем тяжёлые.
- Для больших чисел используйте yafu/PARI/sage — они перебирают методы сами.

## На что смотреть дальше

- **Сразу брать NFS** — для `n` с маленьким множителем ECM быстрее на порядки.
- **Забыть про `gcd` всех модулей** — shared primes решаются мгновенно.
- **Поллард `p-1` без перезапуска** — если `gcd` вернул `n`, уменьшите `B` или смените `a`.
- **Считать `a**M` вместо `pow(a, M, n)`** — для больших `M` это неподъёмно.
- **Игнорировать метод Ферма** — он бесплатный и часто ловит «сгенерированные подряд» простые.
- **Не проверить, что делитель простой** — после факторизации разложите множитель.

## Куда дальше

Мы собрали практический арсенал факторизации. Дальше — продолжение разложения чисел: метод непрерывных дробей для приближений. В уроке **crypto-continued-fractions** мы свяжем это с атакой Винера. А пока главное: **под каждое `n` есть свой метод — гладкое p-1, близкие p и q, маленький множитель; сначала дёшево, потом дорого.**

## Где пригодится

- **CTF crypto:** любая RSA-задача, где параметры «просто слабые» и нужна факторизация.
- **Аудит инфраструктуры:** поиск слабых/сгенерированных с ошибкой ключей.
- **Bug bounty:** анализ криптографических библиотек и генераторов ключей.
- **Работа (SOC/IR):** понимание атак на смарт-карты и HSM.
- **Исследования:** базовый инструментарий криптоаналитика для любого RSA-анализа.
