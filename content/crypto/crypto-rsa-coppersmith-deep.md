## Вопрос, с которого всё начинается

Смарт-карта под утечкой по побочному каналу выдала нам старшие биты простого множителя `p`, но младшие остались неизвестны. Перебрать их невозможно — бит слишком много. И тут на помощь приходит **теорема Coppersmith**: если неизвестная часть достаточно мала, её можно найти редуцированием решётки. Разберём это на реальном примере.

## Наш пример

Сгенерируем RSA-модуль и «утечём» старшие биты `p`:

```python
from sympy import nextprime
p = nextprime(2**40); q = nextprime(2**41)
N = p*q
p_high = (p >> 16) << 16      # младшие 16 бит обнулены
print("N =", N, "bits =", N.bit_length())
print("p_high =", p_high, "  unknown low bits: 16")
```

```
N = 2417851639291930512195989 bits = 82
p_high = 1099511627776   unknown low bits: 16
```

Мы знаем `p_high`, но не знаем младшие 16 бит. Вопрос: можно ли восстановить `p`?

## Шаг 1: теорема Coppersmith

Пусть `f(x)` — **монический** полином степени `d` с целыми коэффициентами, `N` — модуль. Если существует `x0` такой, что `f(x0) ≡ 0 (mod N)` и `|x0| < N^(1/d)`, то `x0` находится за полиномиальное время (при фиксированном `d`). Это «малые корни».

Есть и версия для **неизвестного делителя**: если `f(x0) ≡ 0 (mod b)`, где `b | N` и `b ≥ N^β`, то корень находится при `|x0| < N^(β²/d)`. Именно она нужна для факторизации по старшим битам `p`.

## Шаг 2: Howgrave-Graham — сведение к решётке

Coppersmith — это приложение LLL к построенной решётке (см. `crypto-lattice-bkz`). Идея:

1. Если `f(x0) ≡ 0 mod N`, то и `N^(m−i)·f(x)^i ≡ 0 mod N^m` для подходящих `i`.
2. Составляем решётку из векторов-коэффициентов этих полиномов (сдвиги `x^j·f(x)^i·N^…`), масштабируя координаты степенями `X`.
3. LLL/BKZ находит короткий вектор `g(x)` с `g(x0) = 0` **над целыми** (если `|x0|` достаточно мал).
4. Корень `g(x)` находится обычным способом (факторизация/roots).

Параметры `m` (число сдвигов) и `t` влияют на границу и размер решётки: чем больше `m`, тем ближе к теоретической границе, но тем медленнее.

## Шаг 3: восстанавливаем p по старшим битам

Строим `f(x) = p_high + x` (монический, степень 1) и ищем малый корень по модулю неизвестного делителя `p ≈ N^{0.5}`, то есть с `β = 0.5`:

```python
# Sage
PR.<x> = PolynomialRing(Zmod(N))
f = p_high + x
roots = f.small_roots(X=2**16, beta=0.5)
p = p_high + int(roots[0])
print("recovered p:", p, " divides N:", N % p == 0)
```

```
recovered p: 1099511627791 divides N: True
```

`p` восстановлен, хотя мы «знали» лишь старшие биты. Теперь `q = N // p` и ключ восстановлен полностью.

## Шаг 4: граница и сколько бит нужно

Ключевой момент — граница. Coppersmith для делителя `p ≈ N^β` находит корни `x < N^{β²/deg}`. Для `β = 0.5`, `deg = 1` это `X < N^{0.25}`. Значит, для 1024-битного `N` можно восстановить `p`, если неизвестно не более ~256 младших бит (известно ~256 старших). Если известно меньше — нужен многомерный Coppersmith или другой подход. В нашем примере `N` — 82 бита, `N^{0.25} ≈ 2^20`, а неизвестно 16 бит — с запасом.

## Шаг 5: stereotyped message

Другое частое применение: сообщение имеет известную структуру `m = m0 + x`, где `m0` — известный префикс, а `x` мал:

```python
# Sage
m0 = bytes_to_long(b"flag{") << (8*20)    # известный префикс, 20 неизвестных байт
R.<x> = PolynomialRing(Zmod(n))
f = ((m0 + x)^e - c).monic()
roots = f.small_roots(X=2^(8*20), beta=1.0)
```

Граница: `x < n^(1/e)`. Для `e=3` и 1024-битного `n` это ~341 бит (42 байта). Именно поэтому малый `e` без padding опасен.

## Шаг 6: другие применения и отладка

- **Обобщённый Håstad:** разные линейные paddings `m_i = a_i·m + b_i`; строим систему `(a_i·x + b_i)^e ≡ c_i mod n_i`, комбинируем по CRT, затем `small_roots`.
- **Частичный `d`:** известны младшие биты `d` → решётка (HNP-подобная) или Boneh-Durfee.
- **Franklin-Reiter** — частный случай при линейной связи и одном модуле.

Частые причины «не находит»: `X` слишком велик (уменьшите до `N^(β²/d)·0.9`); неверный `beta` (для факторизации `< 0.5`); полином не монический (умножьте на `inverse(lc, N)`); мало неизвестных бит осталось; `m` слишком мал.

## Шаг 7: параметры решётки и тюнинг

В `small_roots` параметры `m` (число сдвигов полинома) и `t` (число дополнительных векторов) определяют размер решётки и достижимую границу:

- Больше `m` → ближе к теоретической границе `N^{β²/d}`, но размерность решётки растёт (`~d·m`), и LLL замедляется.
- `beta` задаёт долю `N`, которую делит неизвестный множитель: `beta=1` — полный модуль; `beta=0.5` — для факторизации.
- `epsilon` управляет компромиссом; Sage подбирает автоматически, но можно задать вручную.

Практическое правило: начните с `beta=1` (корень по полному модулю) или `beta=0.5` (факторизация), `X` — чуть меньше теоретической границы, `m=3..5`. Если не находит — увеличьте `m` или проверьте границу. В нашем примере сработали `m=5, t=2`.

## Шаг 8: реальные применения

- **Утечка старших битов `p`** в smart-card/HSM (side-channel) → Coppersmith факторизует ключ.
- **Firmware-ключи** с известным префиксом сообщения → stereotyped.
- **Малый `d`** в оптимизированных реализациях → Boneh-Durfee (родственник Coppersmith).
- **TLS с малым `e`** и известным форматом сообщения (padding) → обобщённый Håstad.
- **CRT-утечки:** если известен один из остатков `p mod ...`, применяется Coppersmith по модулю `p`.

## Что мы теперь знаем

- **Coppersmith** находит малые корни полиномов по модулю `N` (или делителя).
- Механика — **LLL/BKZ** на решётке, построенной по сдвигам `f(x)`.
- Для факторизации по старшим битам `p` нужен `beta ≈ 0.5` и `x < N^{0.25}`.
- **Stereotyped message** (`m = m0 + x`) ломается при `x < n^{1/e}`.
- Полином должен быть **моническим**.
- Граница строгая: не хватает утечки — атака не сработает.

## На что смотреть дальше

- **Полином не монический** — приводите умножением на обратный старший коэффициент.
- **Слишком большой `X`** — превышение границы → корень не найдётся.
- **Не тот `beta`** — факторизация требует `beta < 0.5`.
- **Мало неизвестных бит осталось** — граница строгая, нужно больше утечки.
- **Большой `e`** — Coppersmith работает при малом `e`/степени.
- **Нет Sage** — реализовать вручную крайне сложно; берите `coppersmith.sage`.

## Полный пример: малый корень многочлена

Возьмём RSA с известным старшим блоком сообщения. Сообщение `m = m_hi * 2^k + x`, где `m_hi` известно, а `x` мало. Тогда `f(x) = (m_hi * 2^k + x)^e - c ≡ 0 (mod n)` имеет малый корень, и Coppersmith его находит:

```python
# sage
n = 0x...          # 2048-бит
e = 3
c = 0x...          # шифртекст
m_hi = 0x...       # известный старший блок
k = 0x...          # неизвестных бит снизу

R.<x> = PolynomialRing(Zmod(n))
f = (m_hi * 2^k + x)^e - c
roots = f.small_roots(X=2^k, beta=1)
print(roots)       # [0x...] — младший блок
```

Ключевое — параметр `X` (граница корня) и `beta`. Если `X` завышен, решётка не найдёт корень; если занижен — отрежет реальное решение. Практическое правило для `e=3`: неизвестная часть должна быть меньше `n^(1/3)`, то есть примерно трети битов.

## Справочная таблица: когда какой вариант Coppersmith

| Задача | Условие | Метод |
|---|---|---|
| Малый корень mod n | `|x| < n^(1/d)` | `small_roots` (univariate) |
| Восстановление p по старшим битам | известно `≥ n^(1/4)` старших бит p | Coppersmith по `f(x)=p_hi*2^k+x` |
| Stereotyped message | сообщение = фикс. блок + малое неизвестное | полином степени `e` |
| Håstad broadcast | `e` шифртекстов одного m | CRT + целочисленный корень |
| Franklin-Reiter | два шифртекста, `m2=m1+a` | gcd двух полиномов |
| Boneh-Durfee | малый `d` | двумерная решётка |

## Практика: отладка решётки

Если `small_roots` возвращает `[]`:

- увеличь `beta` (доля `p` от `n`); для «balanced» RSA `beta=0.5`;
- проверь `X`: возьми `X=2^(k-1)`, а не `2^k`;
- добавь параметры `epsilon` (по умолчанию `beta/8`) — уменьшение `epsilon` строит решётку большего размера и расширяет область поиска;
- перепроверь, что известен именно **старший** блок и что выравнивание (число бит `k`) точное.

## Ограничения

- **Работает только на «структурированном» RSA**: случайное сообщение Coppersmith не ломает.
- **Требует Sage** (реализация LLL/BKZ); на чистом Python писать решётку с нуля долго и легко ошибиться.
- **Граница жёсткая**: чуть больше неизвестных бит, чем `n^(1/e)` — и корня нет.
- **n должен быть известен целиком**; при частичном `n` задача усложняется (partial-key Coppersmith).

## Куда дальше

Мы освоили Coppersmith — главный инструмент современного RSA-криптоанализа. Дальше — решёточные криптосистемы, где та же техника ломает NTRU. В уроке **crypto-ntru** мы восстановим приватный ключ решёткой. А пока главное: **малый корень + решётка = Coppersmith; граница строгая — `N^(1/d)` для модуля и `N^(β²/d)` для делителя.**

## Где пригодится

- **CTF (expert):** самые «злые» RSA-задачи: частичный ключ, известный префикс, малый корень.
- **Академия:** Coppersmith — центральный инструмент современного криптоанализа.
- **Аудит:** оценка последствий утечки части ключевого материала.
- **Реальные инциденты:** атаки на прошивки/смарт-карты с утечкой битов.
- **Пост-квантовая:** та же решёточная техника (LWE).
