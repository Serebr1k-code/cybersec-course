## Вопрос, с которого всё начинается

Многие приложения генерируют токены и «ключи» через `rand()` или `random`. Но эти генераторы — **не криптографические**: они линейны, и по нескольким выходам можно предсказать всё остальное. Разберём конкретный пример: у нас есть 31 значение генератора, и мы предскажем следующее.

## Наш пример: 31 выход glibc rand

У нас `outputs.txt` с 31 подряд идущим значением (упрощённая модель glibc TYPE_3).

```
$ cat outputs.txt
1804289383
846930886
1681692777
...
```

## Шаг 1: как устроен glibc rand

glibc `rand()` по умолчанию использует **TYPE_3** — аддитивный лаговый генератор Фибоначчи:

```
r[i] = (r[i-3] + r[i-31]) mod 2^32
```

То есть новое значение — сумма значения **три шага назад** и **тридцать один шаг назад**. Это линейная рекурсия: она полностью определяется 31 предыдущим значением. Никакой нелинейности здесь нет.

## Шаг 2: предсказание

Если у нас есть 31 подряд идущее значение `o[0..30]`, то следующее вычисляется прямо:

```
next = (o[0] + o[28]) mod 2^32
```

Почему `o[0]` и `o[28]`? Потому что `o[31] = o[28] + o[0]` (сдвиг на 31 и на 3 от позиции 31). Никакого перебора — просто сложение.

```
$ python3 predict.py
next output = 424238335
flag: nto{gl1bc_r4nd_1s_4_l4gg3d_f1b0n4cc1}
```

## Шаг 3: xorshift и PCG

**xorshift** — ещё проще: `x ^= x << 13; x ^= x >> 17; x ^= x << 5`. Все операции линейны над GF(2), поэтому состояние восстанавливается линейной алгеброй. **PCG** добавляет нелинейный выходной фильтр (сложение и сдвиг), что затрудняет восстановление, но состояние всё ещё восстанавливается по достаточному числу выходов. **splitmix64** использует смешивание через умножения и XOR — нелинейно, но всё равно детерминировано и имеет период `2^64`, что для криптографии мало.

## Шаг 4: как правильно

Для криптографии нужен **CSPRNG** (cryptographically secure PRNG): в Python — `secrets` или `os.urandom`, в C — `getrandom()`/`/dev/urandom`. Они нелинейны и не предсказуемы по выходам. Ключевое правило: **никогда не генерируй ключи/токены через `rand()`, `random` или `Math.random()`**.

## Полный прогон от начала до конца

1. `cat outputs.txt` — 31 значение.
2. Вспоминаем рекурсию `r[i] = r[i-3] + r[i-31]`.
3. Следующее = `o[0] + o[28]`.
4. `python3 predict.py | grep nto > found.txt`.

## Если не сработало

Проверь: (1) это действительно TYPE_3, а не TYPE_0/1/2 (у glibc несколько алгоритмов); (2) значения — полные 32-битные (`rand()` возвращает 31-битные — старший бит всегда 0, что тоже подсказка); (3) если дают меньше 31 значения — нужна линейная алгебра по GF(2) для восстановления состояния. Для xorshift восстановление — решение системы уравнений, а не простое сложение.

## Почему линейность означает предсказуемость

Любой генератор, построенный только из **сложения и XOR**, линеен над своим полем. Для glibc TYPE_3 поле — это кольцо `Z/2^32`; для xorshift — `GF(2)`. Линейность означает, что каждый новый бит выхода — это **линейная комбинация** предыдущих битов состояния. А линейные системы решаются: имея достаточно выходов, можно составить систему уравнений и найти состояние.

Для лагового Фибоначчи решение тривиально: рекурсия имеет порядок 31, поэтому 31 подряд идущего выхода уже **содержат** всё состояние (при правильном сдвиге). Для xorshift нужно собрать матрицу над GF(2) и решить её — но это тоже полиномиально. Для PCG выходной фильтр нелинейный, поэтому нужно больше выходов, но состояние всё равно восстанавливается.

Вывод: **нелинейность необходима для криптографической стойкости**. CSPRNG (ChaCha20, AES-CTR) нелинейны, поэтому их выходы нельзя связать линейной системой.

## Другие небезопасные PRNG

- **Mersenne Twister** (`random` в Python, `mt_rand` в PHP) — огромный период `2^19937`, но полностью линеен над GF(2). По 624 выходам (или 624×32 бита) состояние восстанавливается целиком. Именно поэтому `crypto-mt19937-deep` и `crypto-php-mtrand` — отдельные уроки.
- **Java `Random`** — 48-битный LCG, состояние восстанавливается по двум выходам (`nextInt`), а не по одному.
- **C `rand` в MSVC** — 32-битный LCG, состояние восстанавливается по одному выходу.
- **`Math.random()` в JS** — зависит от движка; V8 использует xorshift128+, который восстанавливается по нескольким выходам.

Общее у всех: **они не предназначены для криптографии**, но регулярно используются там, где нужны токены.

## Инструменты и практика

На CTF для предсказания PRNG удобно:

```python
import random
# восстановление MT по выходам
from randcrack import RandCrack
rc = RandCrack()
for _ in range(624):
    rc.submit(observed_32bit_output)
print(rc.predict_getrandbits(32))
```

Для glibc — просто рекурсия, как в лабе. Для xorshift — библиотека `z3` (символическое решение) или ручная линейная алгебра. Проверяй гипотезу о типе генератора: длина периода, статистика, размер выхода. Если выход 31-битный (старший бит 0) — это glibc `rand()`; если 32-битный с равномерным распределением — что-то другое.

## Разбор: восстановление состояния xorshift

Покажем, как восстановить состояние xorshift128+ (используется в V8/Node.js). Генератор хранит два 64-битных слова `s0`, `s1` и на каждом шаге:

```
s1 ^= s1 << 23
s1 ^= s1 >> 17
s1 ^= s0
s0 ^= s0 >> 26
s1 ^= s0
out = (s0 + s1) mod 2^64
```

Выход — это **сумма** двух слов, но сами слова обновляются линейно (XOR и сдвиги). Это значит, что каждый бит `s0`/`s1` — линейная функция от начального состояния над GF(2). Имея несколько выходов, можно составить систему уравнений и решить её (например, через `z3` или гауссово исключение по битам). На CTF это делают так:

```python
from z3 import BitVec, Solver, LShR
s0 = BitVec('s0', 64); s1 = BitVec('s1', 64)
# ... моделируем шаги, добавляем равенства out == observed ...
```

Если выход усечён (например, `Math.random()` возвращает 52 бита мантиссы), нужно больше выходов, но система всё ещё решается. Именно поэтому V8 **не** используется для криптографии.

## Частые вопросы

**Можно ли восстановить состояние, если выходы усечены?** Да, но нужно больше выходов. Если `rand()` возвращает 31 бит (а не 32), каждый выход даёт 31 уравнение. Для порядка 31 нужно минимум 31 выход (как в лабе), но на практике берут с запасом. Если биты отбрасываются (например, `% 100`), восстановление сложнее — приходится моделировать модульную редукцию.

**Помогает ли seed, если он неизвестен?** Иногда да: если seed — маленькое число (время, PID), его перебирают. Если seed большой и случайный, состояние восстанавливают напрямую по выходам (как для Mersenne Twister по 624 значениям).

**Чем `secrets` отличается от `random`?** `secrets` использует `os.urandom` (CSPRNG), `random` — Mersenne Twister (не криптографический). Никогда не используй `random` для паролей, ключей, токенов.

**Что если нужен воспроизводимый, но безопасный генератор?** Используй HKDF или AES-CTR-DRBG: seed можно хранить, но выход криптографически стоек.

## Что мы теперь знаем

- glibc rand (TYPE_3) — лаговый Фибоначчи `r[i]=r[i-3]+r[i-31]`.
- 31 выхода достаточно для предсказания будущего.
- xorshift линеен над GF(2) и предсказуем.
- PCG/splitmix сложнее, но тоже не криптографичны.
- Для ключей нужен CSPRNG (`os.urandom`, `secrets`).
