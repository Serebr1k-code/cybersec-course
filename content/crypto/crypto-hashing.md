## Что такое хэш-функция

Хэш-функция отображает данные произвольной длины в значение **фиксированной длины** (дайджест). Требования:

- **Детерминизм:** одинаковый вход → одинаковый выход.
- **Быстрое вычисление** (для обычных хэшей).
- **Preimage resistance:** по `h` трудно найти `m`.
- **Second-preimage resistance:** по `m1` трудно найти `m2 ≠ m1` с тем же хэшем.
- **Collision resistance:** трудно найти любые `m1 ≠ m2` с одинаковым хэшем.
- **Лавинный эффект:** изменение 1 бита меняет ~половину выходных битов.

Хэш **необратим**: нельзя «расшифровать» SHA-256. Но можно **подобрать** вход по словарю (см. `crypto-hashcracking`) — это не взлом функции, а перебор слабых паролей.

## Семейства и длины

| Алгоритм | Выход (бит) | Hex-длина | Статус |
|---|---|---|---|
| MD5 | 128 | 32 | сломан (коллизии) |
| SHA-1 | 160 | 40 | сломан (коллизии) |
| SHA-256 | 256 | 64 | безопасен |
| SHA-512 | 512 | 128 | безопасен |
| SHA3-256 | 256 | 64 | безопасен (Keccak) |
| BLAKE2/3 | перем. | — | безопасен, быстрый |
| CRC32 | 32 | 8 | **не** криптографический |

**CRC** — контрольная сумма для обнаружения ошибок, не для безопасности. Её можно подделать тривиально.

## Конструкция Merkle–Damgård

MD5, SHA-1, SHA-256 используют **Merkle–Damgård**: сообщение разбивается на блоки, каждый обрабатывается компрессионной функцией с состоянием:

```
h_0 = IV
h_i = f(h_{i-1}, m_i)
digest = h_n
```

Именно эта структура открывает **length extension** (см. `crypto-merkle`): зная `H(secret || msg)` и длину секрета, можно вычислить `H(secret || msg || padding || extra)` без знания секрета, потому что финальный дайджест — это внутреннее состояние, с которого можно «продолжить».

SHA-3 (Keccak) использует **sponge**-конструкцию и **не** подвержен length extension.

## Length extension на практике

Наивный MAC вида `H(secret || message)` ломается:

```python
import hashpumpy
# hashpumpy(original_hash, original_data, data_to_append, key_length)
new_hash, new_data = hashpumpy.hashpump(
    original_hash, "user=guest", "&role=admin", len("secret"))
print(new_hash, new_data)
```

Если сервер проверяет `H(secret || data) == provided_hash` — вы добавляете данные и подпись остаётся валидной. Защита — **HMAC**, который использует два прохода и внешний хэш, устраняя атаку.

## Коллизии MD5/SHA-1

- MD5: коллизии строятся за секунды (`fastcoll`), chosen-prefix — за минуты.
- SHA-1: коллизии (SHAttered, 2017), chosen-prefix (2020).
- Последствия: подделка подписей, обход «проверки по хэшу», подделка сертификатов.

Подробно — в `crypto-hash-forge`.

## Хэши для паролей: почему не SHA-256

Быстрый хэш — плохое хранилище паролей: GPU перебирает **миллиарды** SHA-256 в секунду. Нужны **медленные** функции:

- **bcrypt:** cost factor, адаптивная сложность; пароль обрезается до 72 байт.
- **scrypt:** memory-hard (требует много памяти на попытку).
- **Argon2:** финалист PHC, memory-hard + parallelism; Argon2id — рекомендованный вариант.
- **PBKDF2:** итерации HMAC; прост, но не memory-hard.

Все они используют **соль** (уникальную случайную строку), что убивает радужные таблицы и делает одинаковые пароли разными. Подробно — в `crypto-kdf`.

## Практический пример: определение и проверка

```python
import hashlib
h = "5d41402abc4b2a76b9719d911017c592"
print(len(h))                       # 32 -> MD5/NTLM
print(hashlib.md5(b"hello").hexdigest())   # 5d41402abc4b2a76b9719d911017c592

# length extension
import hashpumpy
nh, nd = hashpumpy.hashpump(hashlib.md5(b"secret" + b"user=guest").hexdigest(),
                            b"user=guest", b"&role=admin", len(b"secret"))
print(nh)
```

## Частые ошибки

- **Путать хэш и шифрование.** Хэш необратим.
- **Использовать MD5/SHA-1 для безопасности.** Сломаны.
- **`H(secret||msg)` вместо HMAC.** Length extension.
- **Быстрый хэш для паролей.** Нужны bcrypt/argon2.
- **Забывать соль.** Радужные таблицы.
- **Путать CRC и криптографический хэш.**

## SHA-3 и sponge-конструкция

SHA-3 (Keccak) использует **sponge**: данные «впитываются» (absorbing) в состояние, затем «выжимаются» (squeezing). Внутри — перестановка Keccak-f на 1600 битах. Важные отличия от Merkle–Damgård:

- **Не подвержен length extension** (нет «продолжаемого» состояния).
- **Разные варианты выхода** (SHA3-224/256/384/512, SHAKE128/256 с переменной длиной).
- **BLAKE2/BLAKE3** — быстрые современные хэши (BLAKE3 очень быстрый, tree-based).

## Деревья Меркла

**Merkle tree** — структура, где листья — хэши данных, а узлы — хэши конкатенации детей. Корень — «отпечаток» всего набора. Используется в:

- Git (коммиты, объекты).
- Блокчейн (Bitcoin: корень транзакций в заголовке блока).
- IPFS (content addressing).
- Certificate Transparency (логи сертификатов).
- Tor (onion services), ZFS/Btrfs (контрольные суммы).

Знание деревьев Меркла важно для forensics (проверка целостности, Git-объекты) и понимания доказательств включения (Merkle proof).

## Итог: какой хэш когда

| Задача | Хэш |
|---|---|
| Целостность файла | SHA-256/512, BLAKE3 |
| Пароли | Argon2id, bcrypt, scrypt |
| MAC | HMAC-SHA256, Poly1305 |
| Быстрый неблокирующий | BLAKE3 |
| Legacy (не использовать) | MD5, SHA-1 |

## Разбор: length extension шаг за шагом

```python
import hashpumpy
# Сервер: token = data + "|" + H(secret + data)
# Знаем: data="user=guest", sig=H(secret+data), len(secret)=16
data = b"user=guest"
sig = "..."            # известный хэш
new_sig, new_data = hashpumpy.hashpump(sig, data, b"&admin=1", 16)
# new_data = b"user=guest" + padding + b"&admin=1"
# new_sig = H(secret + new_data)
print(new_data, new_sig)
```

Ключевое: padding — это `0x80 || 0x00... || (len(secret+data)*8)`, вычисляется по длине. Сервер, проверяя `H(secret + new_data)`, получит тот же `new_sig`.

## Хэш-функции и их «раунды»

SHA-256 — 64 раунда, SHA-512 — 80, MD5 — 64. Внутри — нелинейные функции, сложение по модулю 2^32, циклические сдвиги. Лавинность достигается за счёт этих раундов. Понимание устройства помогает в реверсе/криптоанализе, но для практики достаточно знать свойства (Merkle–Damgård, sponge) и длины.

## Хэши в блокчейне и Git

- **Bitcoin:** двойной SHA-256 для блоков и адресов, RIPEMD-160 для адресов, SHA-256 для Merkle-корня транзакций.
- **Ethereum:** Keccak-256 (не стандартный SHA3-256!) для адресов и хэшей.
- **Git:** SHA-1 для объектов (переход на SHA-256 в новых версиях); объекты — дерево Меркла.

Знание этих деталей важно для forensics (Git-объекты, кошельки) и задач про блокчейн.

## Сравнение: хэш vs MAC vs подпись

- **Хэш** (`SHA256(m)`) — целостность без ключа; любой может пересчитать.
- **MAC** (`HMAC(K,m)`) — целостность + подлинность (общий ключ).
- **Подпись** (`sign(SK,m)`) — целостность + подлинность + неотказуемость (приватный/публичный ключ).

Выбор зависит от задачи: для проверки скачанного файла — хэш; для API-токена — HMAC; для сертификата — подпись.

## Разбор: определение хэша по контексту

| Контекст | Вероятный хэш |
|---|---|
| `$6$...` в /etc/shadow | sha512crypt |
| 32 hex в SAM | NTLM |
| 32 hex в веб-БД | MD5 |
| 64 hex, файл | SHA-256 |
| `$argon2id$` | Argon2 |
| `$2b$` | bcrypt |
| 40 hex | SHA-1 |

## Как не застрять

- **Определите длину** → тип хэша.
- **MD5/SHA-1** → думайте о коллизиях.
- **`H(secret||...)`** → length extension.
- **Пароли** → bcrypt/argon2, не SHA.
- **Для подбора** → hashcat/john.
- **SHA-256 с ключом** → HMAC, а не конкатенация.

## Где пригодится

- **CTF** — length-extension, коллизии, «сломай самодельный токен».
- **Пентест** — анализ хранения паролей, JWT-подписи (alg confusion с MD5/HMAC), утечки дампов БД.
- **Форензика** — проверка целостности, сопоставление файлов по хэшам, поиск известных образцов.
- **Малварь-анализ** — IOCs по хэшам, идентификация сэмплов.
- **Разработка** — выбор правильного KDF для паролей, HMAC для токенов.
