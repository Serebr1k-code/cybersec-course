## Вопрос, с которого всё начинается

ECDH выглядит просто: сервер получает от нас точку `P` и отвечает `d·P`, где `d` — его секретный скаляр. Если сервер **не проверяет**, что наша точка лежит на нужной кривой и в правильной подгруппе, мы можем подсунуть специальные точки и восстановить `d` по кусочкам. Разберём эту атаку на маленькой кривой, где всё видно.

## Наш пример

Возьмём крошечную кривую над `F_101`: `y² = x³ + x + 1`. Посчитаем все её точки и их порядки:

```python
p, a, b = 101, 1, 1
pts = [None] + [(x, y) for x in range(p) for y in range(p)
                if (y*y - x*x*x - a*x - b) % p == 0]
print("group order:", len(pts))
```

```
group order: 105
```

Порядок группы `105 = 3·5·7` — **гладкий**, то есть состоит только из маленьких простых. Это ключ к атаке. Пусть секрет сервера `d = 17`; мы хотим его найти, не решая полный дискретный логарифм.

## Шаг 1: точки малого порядка

В группе порядка `105` есть подгруппы порядков 3, 5, 7. Найдём точки этих порядков и отправим их «серверу» (у нас он локальный, `Q = d·P`):

```python
def order(P):
    Q, n = P, 1
    while Q is not None:
        Q = add(Q, P); n += 1
    return n
# для m in {3,5,7}: берём точку порядка m, получаем Q = d*P
# перебираем r от 0 до m-1, пока r*P != Q
```

Для каждой подгруппы восстанавливаем остаток `d mod m`:

```
d mod 3 = 2
d mod 5 = 2
d mod 7 = 3
```

Каждый остаток получен перебором всего `m` вариантов — это мгновенно, потому что `m` мало. Мы **не** решали задачу дискретного логарифма в большой группе.

## Шаг 2: собираем d через CRT

Три остатка — это система сравнений. **Китайская теорема об остатках** (CRT) собирает их в одно значение по модулю произведения `3·5·7 = 105`:

```python
from sympy.ntheory.modular import crt
D, M = crt([3, 5, 7], [2, 2, 3])
print("d =", D, "mod", M)
```

```
d = 17 mod 105
```

`d = 17` — точно наш секрет. Если бы группа была больше и её порядок состоял из нескольких малых простых, мы бы собрали `d` так же: когда произведение модулей превышает порядок базовой точки, `d` восстанавливается однозначно.

## Шаг 3: две разновидности атаки

- **Small-subgroup.** Точка малого порядка лежит на **самой** кривой. Именно это мы только что сделали: кофактор `h > 1` (у нас `h = 1` здесь, но малые подгруппы есть из-за гладкости порядка).
- **Invalid-curve.** Мы подсовываем точку, которая **не лежит** на кривой, но лежит на кривой-двойнике (**twist**) с гладким порядком. Сервер считает `d·P` в арифметике своей кривой, хотя точка ей не принадлежит, — и утекает компоненту `d`.

Обе требуют одного: сервер **не валидирует** точку.

## Шаг 4: twist и почему X25519 клэмпит

Для Curve25519 кофактор `h = 8`, и у её twist тоже есть малые множители. Наивная реализация, принимающая точку без проверки, позволяет отправить точки малого порядка на twist, собрать остатки `d mod m` и восстановить `d` по CRT. Именно поэтому **X25519 «клэмпит» скаляр**: делает его кратным 8, и компонента малой подгруппы обнуляется независимо от присланной точки. Это защита и от twist, и от small-subgroup.

## Шаг 5: обязательная валидация точки

- **Проверка уравнения кривой:** `y² == x³ + ax + b mod p` (для Edwards — своё уравнение).
- **Проверка подгруппы:** `n·P == O` (точка в подгруппе простого порядка `n`).
- **Умножение на кофактор:** результат `h·P` вычищает компоненту малой подгруппы.
- **Clamping (X25519):** скаляр кратен 8.
- **Prime-order группы:** Ristretto255, Decaf — убирают проблему кофактора.
- **Проверка каноничности координат** для Montgomery/Edwards.

## Шаг 6: как распознать уязвимость

- Сервер принимает точку и отвечает `d·P` без проверки уравнения кривой.
- Кофактор `h > 1`, и результат не умножается на `h`.
- Доступны точки малого порядка на кривой или twist.
- В условии есть слова «invalid curve», «small subgroup», «twist».
- Реализация не проверяет `n·P == O`.

Порядок действий: соберите точки малых порядков, отправьте, восстановите `d mod m` перебором, соберите CRT. Если малых порядков мало — используйте twist с более гладким порядком. И всегда проверяйте, что сервер действительно возвращает `d·P`, а не отвергает точку: если он отвергает — значит, валидация есть, и атака не пройдёт.
## Шаг 7: полный разбор twist на Curve25519

Порядок twist-кривой Curve25519 равен `2·q_twist`, где `q_twist` — большое простое, но у twist есть малые множители. Наивная реализация ECDH, принимающая точку без проверки, позволяет:

1. найти точки малого порядка на twist (порядки 2, 4, 8 и т.д.);
2. отправить их серверу, получить `d·P`;
3. восстановить `d mod m` для каждого `m`;
4. собрать `d` по CRT, когда произведение модулей превысит `n`.

Именно поэтому X25519 выполняет **clamping**: скаляр делается кратным 8, и компонента малой подгруппы обнуляется независимо от точки. Если реализация не клэмпит и не проверяет — атака проходит.

## Что мы теперь знаем

- ECDH без валидации точки уязвим: специальные точки утекают `d` по частям.
- Точка малого порядка `m` даёт `d mod m` простым перебором.
- Несколько остатков собираются в полный `d` через **CRT**.
- **Small-subgroup** — точки на самой кривой; **invalid-curve/twist** — точки на кривой-двойнике.
- X25519 защищён **clamping**; правильные реализации проверяют уравнение и подгруппу.
- Условие уязвимости — кофактор `h > 1` и отсутствие валидации.

## На что смотреть дальше

- **Считать, что ECDH «сам по себе» безопасен** — без валидации нет.
- **Забыть про кофактор** — `h > 1` открывает малые подгруппы.
- **Ошибиться в порядке twist** — `#E' = p + 1 − t`, а не `p + 1 + t`.
- **Не проверить каноничность** — non-canonical точки обходят проверки.
- **Путать invalid-curve и twist** — twist это частный, самый практичный случай.
- **Игнорировать CRT-сборку** — остатки бесполезны, пока не собраны.

## Куда дальше

Мы научились атаковать ECDH без валидации. Дальше — атаки на саму задачу дискретного логарифма при слабых параметрах кривой. В уроке **crypto-ecdsa-advanced** мы применим Pohlig-Hellman, Smart и MOV. А пока главное: **нет валидации точки — малые подгруппы утекают `d` по частям, а CRT собирает его целиком.**

## Где пригодится

- **CTF (hard):** самодельные ECDH, утечки по малым подгруппам.
- **Bug bounty:** протоколы обмена ключами без валидации.
- **Аудит:** проверка корректности ECDH в крипто-библиотеках.
- **Разработка:** обязательная валидация точек.
- **Работа:** оценка стойкости протоколов на эллиптических кривых.
