ECDH выглядит просто: обе стороны умножают присланную точку на свой секретный скаляр. Но если протокол **не проверяет, что присланная точка лежит на нужной кривой и в правильной подгруппе**, атакующий подсовывает специальные точки и по ответам восстанавливает приватный ключ по кусочкам. Это invalid-curve и small-subgroup атаки — классика CTF и реальный источник уязвимостей в самодельных протоколах.

## Суть атак

В ECDH сервер получает точку `P'` от клиента и отвечает `Q = d·P'`, где `d` — его секрет. Если `P'` выбрана так, что её порядок мал (`m`), то `Q` лежит в подгруппе порядка `m`, и `d mod m` восстанавливается перебором. Собрав остатки `d mod m_i` для нескольких `m_i`, собираем `d` по CRT.

Две разновидности:

- **Small-subgroup:** `P'` — точка малого порядка на **самой** кривой.
- **Invalid-curve:** `P'` не лежит на кривой, но лежит на **twist** (кривой-двойнике) с гладким/малым порядком.

Обе требуют одного: сервер **не валидирует** точку.

## Малые подгруппы

Если порядок группы `= h·n` (кофактор `h > 1`, например `h=8` у Curve25519), есть точки порядка 2, 4, 8. Атакующий перебирает все точки малого порядка, отправляет их и по ответу определяет `d mod m`. Для `m=8` это 3 бита; для составных гладких порядков — больше.

## Invalid-curve

Если `P'` подменить на точку другой кривой `E'` (не `E`), сервер посчитает `d·P'` в арифметике `E` — но точка не принадлежит `E`, и результат «утечёт» компоненту `d`. Если порядок `E'` гладкий, `d` восстанавливается по частям. Часто `E'` — это **quadratic twist** кривой, порядок которого `p + 1 - t` (где `t` — trace).

## Twist-атака

Для Curve25519 twist — это `E'(F_p)` с порядком, содержащим малые множители. Если реализация не проверяет, что точка на основной кривой, и не умножает на cofactor, twist-точки дают утечки. Именно поэтому X25519 «клэмпит» скаляр (кратен 8) — это защита от twist/small-subgroup.

## Практический расчёт (CRT)

Алгоритм:

1. Разложить порядок twist/группы на малые множители `m_1, m_2, ...`.
2. Для каждого `m_i` найти точку `P_i` порядка `m_i` (на кривой или twist).
3. Отправить `P_i` серверу, получить `Q_i = d·P_i`.
4. Восстановить `d mod m_i` (перебор/BSGS в подгруппе порядка `m_i`).
5. Собрать `d` по CRT: `d ≡ Σ r_i·M_i·inv(M_i, m_i) (mod M)`, где `M = Π m_i`.

Когда `M > n`, `d` восстанавливается однозначно.

```python
from sympy.ntheory.modular import crt
# остатки d mod m_i
residues = [(r1, m1), (r2, m2), (r3, m3)]
d, M = crt([m for _, m in residues], [r for r, _ in residues])
```

## Разобранный пример: Curve25519 с cofactor 8

Сервер принимает любую точку и отвечает `d·P`. Отправляем точки порядка 8 (их несколько) и по ответу определяем `d mod 8`. Затем используем twist с порядком, содержащим другие малые простые, и собираем больше остатков. Когда произведение модулей превышает `n`, CRT даёт `d`.

Ключевая проверка: сервер **не** умножает результат на cofactor и **не** проверяет принадлежность точки кривой — тогда атака проходит.

## Защита (валидация точки)

- **Проверка уравнения кривой:** `y² == x³ + ax + b mod p` (и для Edwards — соответствующее).
- **Проверка подгруппы:** `n·P == O` (точка в подгруппе простого порядка).
- **Cofactor multiplication:** умножить результат на `h` (вычищает компоненту малой подгруппы).
- **Clamping (X25519):** скаляр кратен 8.
- **Использование prime-order групп:** Ristretto255, Decaf.
- **Проверка каноничности координат** (для Montgomery/Edwards).

## Варианты и edge cases

- **Гладкий порядок twist.** Чем больше малых множителей, тем полнее восстановление.
- **`h=1` кривые.** Small-subgroup-атака не проходит, но invalid-curve — да, если нет проверки.
- **Partial key recovery.** Если удаётся собрать лишь часть `d`, остаток перебирается.
- **Combined с nonce-атакой.** Остатки `d` сужают пространство для biased-nonce.
- **Атака на статический ключ.** Эфемерный ключ атакуется только при переиспользовании.

## Частые ошибки и тупики

- **Считать, что ECDH «сам по себе» безопасен.** Без валидации — нет.
- **Забыть про cofactor.** `h>1` открывает малые подгруппы.
- **Ошибиться в порядке twist.** `#E' = p + 1 - t`, а не `p + 1 + t`.
- **Не проверить каноничность.** Non-canonical точки обходят проверки.
- **Путать invalid-curve и twist.** Twist — частный, наиболее практичный случай.
- **Игнорировать CRT-сборку.** Остатки бесполезны, пока не собраны.

## Что дальше (decision)

1. Сервер принимает произвольную точку → попробуйте точки малого порядка.
2. Малых точек мало → переходите на twist (invalid-curve).
3. Собрали остатки → CRT до полного `d`.
4. Группа prime-order и точка проверяется → атака не проходит, ищите другое.
5. Реализация X25519 → проверьте clamping.
6. Нужна защита → валидация точки + cofactor + prime-order группа.

## Справочная таблица

| Атака | Условие | Что даёт |
|-------|---------|----------|
| small-subgroup | кофактор `h>1`, нет проверки | `d mod m` |
| invalid-curve | нет проверки принадлежности | `d mod ord(E')` |
| twist | нет проверки + cofactor | утечка частями |
| CRT-сборка | несколько остатков | полный `d` |

## Полный разбор: twist Curve25519

Порядок twist-кривой Curve25519 равен `2·q_twist`, где `q_twist` — большое простое, но **у twist есть малые множители**. Наивная реализация ECDH, принимающая точку без проверки, позволяет:

1. Найти точки малого порядка на twist (порядки 2, 4, 8 и т.д.).
2. Отправить их серверу, получить `d·P`.
3. Восстановить `d mod m` для каждого `m`.
4. Собрать `d` по CRT, когда произведение `m` превысит `n`.

```python
# Sage: точки twist и их порядки
p = 2**255 - 19
Et = EllipticCurve(GF(p), [486662, 1])     # twist (пример)
for P in Et.torsion_points():              # при малом cofactor
    print(P.order())
```

Именно поэтому X25519 выполняет **clamping**: скаляр делается кратным 8, и компонента малой подгруппы обнуляется независимо от точки. Если же реализация не клэмпит и не проверяет — атака проходит.

## Чек-лист: ECDH без валидации

- сервер принимает точку и отвечает `d·P` без проверки уравнения кривой;
- cofactor `h > 1` и результат не умножается на `h`;
- доступны точки малого порядка на кривой или twist;
- в условии «invalid curve», «small subgroup», «twist»;
- реализация не проверяет `n·P == O`.

Порядок: соберите точки малых порядков, отправьте, восстановите `d mod m` перебором, соберите CRT. Если малых порядков мало — используйте twist с более гладким порядком. Всегда проверяйте, что сервер действительно возвращает `d·P`, а не отвергает точку.
