## Почему ChaCha20, а не RC4

RC4 — старый потоковый шифр с известными статистическими смещениями и запрещён в TLS (RFC 7465). ChaCha20 (Daniel Bernstein, 2008) — современный потоковый шифр, спроектированный для **высокой скорости в софте** (без аппаратного ускорения AES) и **устойчивости** к известным атакам. Он лежит в основе TLS 1.3, WireGuard, SSH, QUIC, Signal. Понимание ChaCha20 — это понимание того, как выглядит «правильный» потоковый шифр.

ChaCha20 относится к семейству **ARX** (Add-Rotate-XOR): все операции — сложение по модулю 2^32, циклический сдвиг и XOR. Никаких S-box и таблиц — только эти три операции, что делает его быстрым и защищённым от cache-timing атак (в отличие от AES с таблицами).

## Раскладка состояния

Состояние ChaCha20 — это **16 слов по 32 бита** (матрица 4×4):

```
c0 c1 c2 c3     c0..c3   — константа "expand 32-byte k"
k0 k1 k2 k3     k0..k7   — ключ (256 бит)
k4 k5 k6 k7
c4 c5 n0 n1     n0..n2   — nonce (96 бит)
b0 b1 b2 b3     b0..b3   — счётчик (32 бита)
```

Ключ 256 бит (8 слов), nonce 96 бит (3 слова) и счётчик 32 бита (1 слово). XChaCha20 использует nonce 192 бита (24 байта) через HChaCha20 для вывода подключ — это удобно для случайных nonce (меньше риск повтора).

## Quarter-round и блок-функция

**Quarter-round (QR)** — базовый нелинейный шаг над четырьмя словами:

```
a += b; d ^= a; d <<<= 16;
c += d; b ^= c; b <<<= 12;
a += b; d ^= a; d <<<= 8;
c += d; b ^= c; b <<<= 7;
```

Блок-функция: 10 итераций «двойного раунда», каждая состоит из 4 column-round (по столбцам) и 4 diagonal-round (по диагоналям). Итого **20 раундов** — отсюда имя ChaCha20. Есть ChaCha8 и ChaCha12 (reduced-round, используются в некоторых системах для скорости; в задачах CTF именно они дают «зацепку»).

После 20 раундов результат **прибавляется** к исходному состоянию (feed-forward) — это важно для необратимости и защиты от некоторых атак. Затем 64 байта состояния XORятся с открытым текстом; счётчик инкрементируется для следующего блока.

## Реализация на Python (учебная)

```python
import struct

def rotl(x, n): return ((x << n) | (x >> (32 - n))) & 0xffffffff

def qr(s, a, b, c, d):
    s[a] = (s[a] + s[b]) & 0xffffffff; s[d] ^= s[a]; s[d] = rotl(s[d], 16)
    s[c] = (s[c] + s[d]) & 0xffffffff; s[b] ^= s[c]; s[b] = rotl(s[b], 12)
    s[a] = (s[a] + s[b]) & 0xffffffff; s[d] ^= s[a]; s[d] = rotl(s[d], 8)
    s[c] = (s[c] + s[d]) & 0xffffffff; s[b] ^= s[c]; s[b] = rotl(s[b], 7)

def block(key, nonce, counter):
    const = b"expand 32-byte k"
    st = list(struct.unpack("<4I", const)) + list(struct.unpack("<8I", key)) \
         + [counter] + list(struct.unpack("<3I", nonce))
    w = st[:]
    for _ in range(10):
        qr(w,0,4,8,12); qr(w,1,5,9,13); qr(w,2,6,10,14); qr(w,3,7,11,15)
        qr(w,0,5,10,15); qr(w,1,6,11,12); qr(w,2,7,8,13); qr(w,3,4,9,14)
    out = [(w[i] + st[i]) & 0xffffffff for i in range(16)]
    return struct.pack("<16I", *out)

def chacha20(key, nonce, counter, data):
    ks = b""
    for i in range(0, len(data), 64):
        ks += block(key, nonce, counter)
        counter += 1
    return bytes(a ^ b for a, b in zip(data, ks))
```

Обратите внимание на feed-forward `w[i] + st[i]` — без него шифр был бы обратимым и слабым.

## Атака: повтор nonce

Как и любой потоковый шифр, ChaCha20 фатален при повторе `(key, nonce)`:

```
C1 ⊕ C2 = P1 ⊕ P2
```

Дополнительно, при использовании ChaCha20-Poly1305 повтор nonce повторяет и ключ Poly1305 `(r, s)`, что даёт возможность подделки тега (см. `crypto-ccm-aead`). Это самая частая реальная ошибка (например, инциденты с клонированием VM, где состояние RNG дублировалось).

## Reduced-round атаки и дифференциалы

Полный ChaCha20 не имеет практических атак. Но **ChaCha7 и меньше** ломаются дифференциальным криптоанализом: существуют характеристики с высокой вероятностью через несколько раундов, позволяющие отличить keystream от случайного и восстановить ключ. На CTF часто дают «ChaCha с N раундами» — смотрите на число раундов: если меньше 8, вероятно, нужна дифференциальная атака (см. `crypto-block-analysis`).

**Related-key / related-nonce атаки:** если задача позволяет контролировать связь между nonce или ключами, может применяться атака на основе предсказуемых разностей.

## Практический пример: расшифровка при reused nonce

```python
c1 = bytes.fromhex(open("c1.hex").read().strip())
c2 = bytes.fromhex(open("c2.hex").read().strip())
xor = bytes(a ^ b for a, b in zip(c1, c2))   # P1 ^ P2
# crib-dragging: предполагаем известный префикс
crib = b"flag{"
partial = bytes(x ^ y for x, y in zip(xor, crib))
print("начало P2:", partial[:len(crib)])
```

## Частые ошибки

- **Повтор nonce.** Убивает и конфиденциальность, и целостность (в AEAD-версии).
- **Путать ChaCha20 и Salsa20.** Разная раскладка состояния и порядок QR; несовместимы.
- **Забыть feed-forward.** Учебные реализации без `+st[i]` неверны.
- **Игнорировать число раундов.** Reduced-round версии — отдельная задача.
- **Считать, что «ARX = просто».** Нелинейность даёт сложение по модулю 2^32, а не только XOR.
- **Использовать XChaCha20 nonce как ChaCha20** (размеры несовместимы).

## Salsa20 против ChaCha20 и XChaCha20

Salsa20 — предшественник ChaCha20. Отличия важны, если в задаче дана одна из версий:

- **Раскладка состояния.** В Salsa20 quarter-round работает над столбцами/строками иначе; ChaCha20 «перемешивает» diagonal-round по-другому, что даёт лучший diffusion на раунд.
- **Порядок QR.** В ChaCha20 QR применяется к столбцам, затем к диагоналям; в Salsa20 — к строкам, затем к столбцам. Это значит, что реализации **не взаимозаменяемы**.
- **XChaCha20** использует nonce 192 бита: `HChaCha20(key, nonce[0:16])` даёт подключ, затем ChaCha20 с nonce `nonce[16:24]`. Это снижает риск случайного повтора nonce (192 бита против 96). XChaCha20-Poly1305 — популярный выбор в libsodium.

Если видите nonce 24 байта — это XChaCha20. Если 8 байт и счётчик 64 бита — это оригинальный ChaCha (не RFC 8439). Размеры nonce — быстрый способ определить вариант.

## Poly1305: почему ключ одноразовый

Ключ Poly1305 `(r, s)` выводится из **первых 32 байт keystream** ChaCha20 для данного nonce: `(r, s) = ChaCha20(key, nonce, counter=0)[0:32]`. Отсюда прямая связь: повторился nonce — повторился и ключ MAC. Poly1305 — это полиномиальный MAC: тег есть значение многочлена `f(c)` от ключа `r` над полем по модулю `2^130 − 5`, плюс `s`. Если атакующий получает **два** тега с одним `r`, разность даёт уравнение `f1(r) − f2(r) = t1 − t2`, которое решается относительно `r` (степень мала). Восстановив `r`, атакующий подделывает теги для любых сообщений. Это и есть причина, по которой Poly1305 нельзя использовать «дважды».

## ChaCha20 в реальных протоколах

- **TLS 1.3:** ChaCha20-Poly1305 — обязательный шифр наряду с AES-GCM; выбирается, когда нет AES-NI (мобильные, embedded).
- **WireGuard:** использует ChaCha20-Poly1305 для инкапсуляции пакетов; nonce — 64-битный счётчик.
- **SSH:** `chacha20-poly1305@openssh.com` — популярный шифр.
- **QUIC/HTTP3:** ChaCha20-Poly1305 как один из AEAD.
- **libsodium:** `crypto_aead_chacha20poly1305_ietf` (RFC 8439) и `xchacha20poly1305`.

Знание этих протоколов помогает: если в задаче фигурирует WireGuard/QUIC, ищите ошибки управления счётчиком/nonce, а не криптоанализ примитива.

## Дифференциальный анализ ChaCha: детали

Для ChaCha существует хорошо изученная дифференциальная характеристика: одна битовая разность во входе через `r` раундов даёт предсказуемую разность с вероятностью, которая для полных 20 раундов пренебрежимо мала, но для 7–8 раундов становится практичной. Атаки на ChaCha7 (2^246 операций для восстановления ключа) и ChaCha6 быстрее перебора. Поэтому «ChaCha с N раундами» в задаче — сигнал: если N ≤ 7, применяйте дифференциальный криптоанализ (строите характеристики, ищете вероятностный след); если N = 20 — ищите ошибку применения (nonce reuse), а не криптоанализ.

## Как не застрять

- **Сравните два шифротекста** — reused nonce даст XOR текстов.
- **Смотрите на раунды.** Меньше 20 → возможен дифференциальный криптоанализ.
- **Знаете один текст** — восстановите keystream.
- **Для Poly1305-forgery** нужен ключ `(r, s)` — ищите повтор nonce или утечку.
- **Проверьте размер nonce.** 12 байт — ChaCha20, 24 байта — XChaCha20.
- **Реализуйте сами** — это лучший способ понять и найти ошибку в чужой реализации.
- **Не путайте Salsa20 и ChaCha20** — разная раскладка, несовместимые реализации.
- **Помните про feed-forward** — без него реализация неверна и уязвима.
