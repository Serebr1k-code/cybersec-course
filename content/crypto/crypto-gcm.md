## Что такое AES-GCM

AES-GCM (Galois/Counter Mode, NIST SP 800-38D) — самый популярный AEAD-режим. Он сочетает:

- **CTR-режим** AES для шифрования (keystream из `E_K(J0 + counter)`).
- **GHASH** — аутентификацию на основе умножения в поле GF(2^128).

GCM используется в TLS 1.2/1.3, IPsec, SSH, QUIC, AES-GCM-SIV (производная), Wi-Fi (GCMP). Он быстрый (аппаратное ускорение), параллелизуемый и стандартизованный. Но у него есть **одна фатальная слабость** — повтор nonce, порождающий так называемую **forbidden attack**.

## Как строится GCM

Параметры: ключ `K`, nonce `N` (рекомендуется 96 бит), AAD `A`, открытый текст `P`.

1. `H = E_K(0^128)` — **ключ GHASH** (секретный, выводится из `K`).
2. `J0 = N || 0^31 || 1` (для 96-битного nonce).
3. **Шифрование:** `C = P ⊕ CTR_K(J0+1)` (keystream начинается со счётчика 1).
4. **Тег:** `T = E_K(J0) ⊕ GHASH_H(A, C)`.

**GHASH** — это полиномиальный MAC: блоки AAD и шифротекста интерпретируются как коэффициенты многочлена над `GF(2^128)`, вычисляется значение в точке `H`:

```
GHASH_H(X) = X_1·H^m ⊕ X_2·H^(m-1) ⊕ ... ⊕ X_m·H
```

Полином неприводимый: `x^128 + x^7 + x^2 + x + 1`. Умножение в GF(2^128) — это «carry-less multiplication» с редукцией.

Критично: `H` **фиксирован** для данного ключа и не зависит от nonce. Именно поэтому повтор nonce раскрывает `H`.

## Forbidden attack: повтор nonce

Если **два сообщения** зашифрованы одним `(K, N)`:

1. **Совпадение keystream:** `J0` и счётчики совпадают → `C1 ⊕ C2 = P1 ⊕ P2` (прямая утечка XOR текстов). Зная один текст, получаем второй.
2. **Совпадение `H`:** теги `T1` и `T2` вычислены с одним `H`. Если атакующий знает `A` и `C` (они передаются открыто), то:
   ```
   T1 ⊕ T2 = GHASH_H(A1,C1) ⊕ GHASH_H(A2,C2)
   ```
   Это полиномиальное уравнение относительно `H` (степень = число блоков). Решив его (найти корни в GF(2^128)), атакующий восстанавливает **`H`**.

3. **Подделка тега:** зная `H`, для **любого** нового `(A', C')` вычисляется корректный тег:
   ```
   T' = GHASH_H(A', C') ⊕ E_K(J0)
   ```
   Часть `E_K(J0)` неизвестна, но если атакующий имеет **один валидный `(C, T)`** с тем же nonce, он получает `E_K(J0) = T ⊕ GHASH_H(A,C)` и может подделать тег для любого сообщения с этим nonce. Это и есть **полный взлом целостности**.

Важно: для подделки нужен хотя бы один валидный тег; для восстановления `H` — два тега с одним nonce.

## Алгебра GF(2^128) и решение уравнения

Работа с GF(2^128) реализуется через carry-less multiplication. В Python удобно использовать библиотеку `galois` или реализовать вручную.

```python
# pip install galois
import galois
GF = galois.GF(2**128, irreducible_poly="x^128 + x^7 + x^2 + x + 1")

def ghash(H, data, aad=b""):
    def blocks(b):
        b = b + b"\x00" * (-len(b) % 16)
        return [int.from_bytes(b[i:i+16], "big") for i in range(0, len(b), 16)]
    # упрощённо (без length block)
    y = GF(0)
    for x in blocks(aad) + blocks(data):
        y = (y ^ GF(x)) * GF(H)
    return int(y)

# Дано два тега с одним nonce: строим полином и ищем корень H
# Степень = число блоков; корни ищем перебором/факторизацией
```

На практике для решения полиномиального уравнения над GF(2^128) строят разность многочленов `f(H) = 0` и находят корни (Berlekamp's algorithm / перебор при малой степени). В CTF-задачах степень обычно невелика (2–10 блоков), поэтому можно решать и подбором.

## Практический пример: подделка тега

```python
# Сценарий: сервер шифрует сообщения с ФИКСИРОВАННЫМ nonce (ошибка!)
# Мы получаем (c1, t1) и (c2, t2) для известных aad.
# 1. Восстанавливаем H из разности тегов.
# 2. Считаем E_K(J0) = t1 XOR GHASH_H(aad, c1).
# 3. Для желаемого c3 вычисляем t3 = GHASH_H(aad, c3) XOR E_K(J0).
# 4. Отправляем (c3, t3) -> сервер принимает как валидное.
```

Если keystream тоже переиспользуется (тот же nonce), `c3` можно выбрать так, чтобы `p3 = c3 ⊕ keystream` было нужным текстом: `c3 = p3 ⊕ (c1 ⊕ p1)`.

## Практический пример: прямая расшифровка

```python
c1 = bytes.fromhex(open("c1.hex").read().strip())
c2 = bytes.fromhex(open("c2.hex").read().strip())
xor = bytes(a ^ b for a, b in zip(c1, c2))   # = P1 ^ P2
# crib-dragging, как в XOR-OTP
known = b"flag{"
print(bytes(x ^ y for x, y in zip(xor, known)))
```

## Частые ошибки

- **Повтор nonce.** Убивает и конфиденциальность, и целостность.
- **Не проверять тег до расшифрования.** `decrypt_and_verify`, а не `decrypt` + отдельная проверка.
- **Использовать короткий/предсказуемый nonce.** 96 бит, уникальный.
- **Не включать метаданные в AAD.** Тогда их можно переставить между сессиями.
- **Сбрасывать счётчик nonce при рестарте.** Даёт повтор.
- **Считать GCM «неуязвимым».** Forbidden attack реален.

## Реализация GHASH вручную

Для понимания и для CTF полезно уметь считать GHASH без библиотек:

```python
def gf_mul(x, y):
    """Умножение в GF(2^128) с полиномом x^128+x^7+x^2+x+1."""
    R = 0xe1000000000000000000000000000000
    z = 0
    for i in range(128):
        if (y >> (127 - i)) & 1:
            z ^= x
        if x & 1:
            x = (x >> 1) ^ R
        else:
            x >>= 1
    return z

def ghash(H, aad, ct):
    def blocks(b):
        b = b + b"\x00" * (-len(b) % 16)
        return [int.from_bytes(b[i:i+16], "big") for i in range(0, len(b), 16)]
    y = 0
    for x in blocks(aad) + blocks(ct):
        y = gf_mul(y ^ x, H)
    return y
```

Зная `H`, тег вычисляется как `E_K(J0) ⊕ GHASH`. Для forbidden attack: разность тегов двух сообщений с одним nonce даёт уравнение на `H`.

## Варианты и производные

- **AES-GCM-SIV:** nonce-misuse-resistant; nonce выводится из содержимого, поэтому повтор «случайного» nonce не фатален. Рекомендован там, где уникальность nonce не гарантирована.
- **AES-GMAC:** только аутентификация (без шифрования).
- **GCM с 64-битным nonce:** требует GHASH-вывода `J0` (медленнее, реже).
- **GCMP (Wi-Fi):** GCM в 802.11ad/ay.

## Практический чек-лист по GCM-задачам

1. Один nonce на два сообщения? → forbidden attack.
2. Известен один открытый текст? → восстановите keystream, расшифруйте второй.
3. Есть два тега? → восстановите `H`.
4. Есть `H` и один тег? → подделайте тег для нового сообщения.
5. Метаданные в AAD? → проверьте, можно ли их переставить.

## Как не застрять

- **Ищите повтор nonce.** Это атака №1 для GCM.
- **Сравните два шифротекста.** XOR даёт `P1⊕P2`.
- **Восстановите `H`** из двух тегов с одним nonce.
- **Подделайте тег** для нового сообщения.
- **Проверьте, включены ли метаданные в AAD.**
- **Если nonce уникален и непредсказуем** — ищите другой вектор (утечка ключа, реализация).
