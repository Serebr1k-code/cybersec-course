## Вопрос, с которого всё начинается

В прошлом уроке мы ломали шифры по частоте букв. Но современные шифры работают не с буквами, а с **байтами**, и главная операция там — XOR. Казалось бы, если ключ случайный и той же длины, что сообщение, — взломать нельзя. И это правда... ровно до тех пор, пока ключ не переиспользовали. Разберёмся, где именно ломается.

## Наш пример

У нас есть **два** перехваченных сообщения. Известно, что их шифровали одним и тем же ключом (та же длина). Вот они в hex:

```
c1 = 116a5124755c3f067313550e7e570530483d4807541b45473d52255a0b630747
c2 = 2e7756574765250c32145f7162570c317223090a655242703a00127e3c2c79
```

Прежде чем атаковать, разберёмся с самой операцией.

## Шаг 1: почему XOR обратим

XOR (исключающее ИЛИ, `^`) для двух битов даёт 1, если биты **разные**, и 0, если одинаковые. Главное свойство: `a ^ a = 0`, а `a ^ 0 = a`. Поэтому если зашифровать `c = m ^ k`, то расшифровать можно той же операцией: `c ^ k = m ^ k ^ k = m`.

Отсюда два практических вывода. Первый: если мы угадали фрагмент сообщения (`m`), мы сразу получаем кусок ключа `k = c ^ m`. Второй: если **два** сообщения зашифрованы одним ключом, то

```
c1 ^ c2 = (m1 ^ k) ^ (m2 ^ k) = m1 ^ m2
```

— ключ **сокращается**! Остаётся XOR двух открытых текстов.

## Шаг 2: один байт ключа — перебор 256

Начнём с простого случая: ключ — один байт. Дано:

```
09372011161739312b2c252e271d203b36271d3a2d303f
```

Перебираем все 256 возможных байтов ключа и печатаем «самые текстовые» результаты:

```python
import string
ct = bytes.fromhex("09372011161739312b2c252e271d203b36271d3a2d303f")
def score(b):
    return sum(1 for c in b if chr(c) in string.ascii_letters + string.digits + '_{}! ')
best = sorted(((score(bytes(x ^ k for x in ct)), k, bytes(x ^ k for x in ct)) for k in range(256)), reverse=True)
for s, k, d in best[:3]:
    print(f"key=0x{k:02x} score={s} -> {d}")
```

Вывод:

```
key=0x42 score=23 -> b'KubSTU{single_byte_xor}'
```

Один байт `0x42` — и сообщение читается. Перебор 256 вариантов занимает миллисекунды.

## Шаг 3: повторяющийся ключ — это Виженер для байтов

Теперь ключ длиннее одного байта, но **повторяется** (например, `KEY`, `KEY`, `KEY`…). Тогда каждый байт с индексом `i` сдвигается на `key[i mod L]`. Это ровно та же идея, что у Виженера, только вместо алфавита из 26 букв — 256 значений байта.

Ломается так же, как Виженер:

1. **Угадываем длину ключа `L`.** Классический приём — считать **расстояние Хэмминга** (число различающихся битов) между соседними блоками длины `L`, нормировать на `L` и выбрать `L` с минимумом. Правильная длина даёт наименьшее расстояние, потому что блоки зашифрованы «согласованно».
2. **Разбиваем шифротекст на колонки** по длине `L` — каждая колонка зашифрована одним байтом.
3. **Ломаем каждую колонку** как однобайтовый XOR из шага 2.

Это в точности Cryptopals Set 1, задача 6 — хорошая тренировка.

## Шаг 4: два сообщения с одним ключом

Вернёмся к нашему примеру. Ключ уникален для каждого байта, но **использован дважды** — это «many-time pad». Посчитаем XOR двух шифротекстов:

```python
c1 = bytes.fromhex("116a5124755c3f067313550e7e570530483d4807541b45473d52255a0b630747")
c2 = bytes.fromhex("2e7756574765250c32145f7162570c317223090a655242703a00127e3c2c79")
x = bytes(a ^ b for a, b in zip(c1, c2))
print(x.hex())
# 3f1d077332391a0a41070a7f1c0009013a1e410d3149073707523724374f7e
```

Мы получили `m1 ^ m2` — ключ исчез. Теперь у нас нет случайного ключа, а есть XOR двух **осмысленных текстов**. Это уже ломается.

## Шаг 5: crib-dragging

Если один текст — флаг, его начало почти наверняка `KubSTU{` (или `flag{`, `CTF{`). «Приложим» эту догадку к каждой позиции и посмотрим, не получится ли во втором тексте осмысленное слово.

```python
x = bytes.fromhex("3f1d077332391a0a41070a7f1c0009013a1e410d3149073707523724374f7e")
crib = b"KubSTU{"
for pos in range(len(x) - len(crib) + 1):
    guess = bytes(x[pos + i] ^ crib[i] for i in range(len(crib)))
    if all(32 <= b < 127 for b in guess):
        print(pos, guess)
```

На позиции 0 сразу видно читаемый кусок второго текста — `the fla`. Значит, `crib` угадан верно. Теперь мы знаем фрагмент `m2` и можем восстановить кусок ключа: `k = c2 ^ m2`. Дальше процесс повторяется: чем больше кусков текста мы угадали, тем больше ключа раскрыто, и оставшиеся символы достраиваются.

Этот метод называется **crib-dragging** («протаскивание известного текста»). Он опирается на **избыточность языка**: в осмысленном тексте угадываемые слова встречаются постоянно.

## Шаг 6: почему одноразовый блокнот рушится

Одноразовый блокнот (OTP) математически невзламываем, **если** ключ:
- абсолютно случаен,
- не короче сообщения,
- используется **ровно один раз**.

Стоит переиспользовать ключ — и `c1 ^ c2 = m1 ^ m2` уничтожает всю секретность. Именно поэтому в реальных протоколах нельзя повторять nonce/IV в потоковых режимах: одна ошибка — и расшифровка становится упражнением на избыточность языка.

## Как точно определить длину ключа

В шаге 3 мы упомянули расстояние Хэмминга — разберём его подробнее, потому что это самый надёжный автоматический способ. **Расстояние Хэмминга** между двумя строками — число различающихся битов. В Python это `bin(a ^ b).count('1')`.

Идея: возьмём блоки шифротекста длиной `L` и сравним соседние. Если `L` совпадает с настоящей длиной ключа, то одинаковые позиции внутри блоков зашифрованы одним байтом, и расстояние окажется **маленьким**. Если `L` неверна, позиции «съезжают» и расстояние близко к случайному (4 бита на байт).

```python
def hamming(a, b):
    return sum(bin(x ^ y).count('1') for x, y in zip(a, b))

ct = bytes.fromhex("00303b18110c3036302522352e1a3b32313c143d363938")
for L in range(1, 9):
    blocks = [ct[i:i+L] for i in range(0, len(ct) - L, L)]
    dist = sum(hamming(blocks[i], blocks[i+1]) for i in range(len(blocks)-1))
    norm = dist / (L * (len(blocks)-1))
    print(L, round(norm, 2))
```

Правильная длина даёт минимальное нормированное расстояние. Найдя `L`, делим шифротекст на `L` колонок и каждую ломаем как однобайтовый XOR — так же, как ломали колонки Виженера по частоте букв.

## Что мы теперь знаем

- XOR обратим: `c ^ k = m`, а `a ^ a = 0`.
- Однобайтовый XOR ломается перебором 256 ключей.
- Повторяющийся ключ — это Виженер для байтов: сначала длина (расстояние Хэмминга), потом колонки.
- Два текста с одним ключом дают `m1 ^ m2` — ключ сокращается.
- crib-dragging восстанавливает тексты по известному формату флага.
- OTP безопасен только при одноразовом случайном ключе нужной длины.

## Куда дальше

Мы увидели XOR в чистом виде. В следующем уроке **crypto-number-theory** мы возьмём математический аппарат, который понадобится для настоящих асимметричных шифров: модульную арифметику, НОД, обратный элемент и CRT. А пока главное: **переиспользование ключа — самый частый и самый разрушительный дефект криптосхем**.

## Где пригодится

- **CTF** — огромный класс задач «XOR с ключом» и «many-time pad».
- **Разбор реальных инцидентов** — повтор nonce/IV в потоковых шифрах регулярно приводит к утечкам.
- **Реверс и форензика** — XOR-обфускация строк в бинарниках и вредоносном ПО.
- **Пентест** — оценка «самодельного» шифрования, которое на деле оказывается XOR с коротким ключом.
