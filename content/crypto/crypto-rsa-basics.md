## Вопрос, с которого всё начинается

Мы разобрали всю математику: обратный элемент, `φ(n)`, модульная арифметика. Пора собрать из неё RSA — шифр, на котором держится половина интернета. Вопрос новичка: «если RSA так надёжен, как его вообще ломают на CTF?» Ответ: ломают не сам RSA, а **плохие параметры** — малую экспоненту, слабый модуль, отсутствие padding. Соберём RSA своими руками и тут же вскроем его двумя способами.

## Наш пример

Публичный ключ: `n = 3233`, `e = 17`. Шифротекст: `c = 2790`. Задача — восстановить сообщение `m`. Параметры намеренно крошечные, чтобы всё считалось в уме, но принципы те же, что у 2048-битного ключа.

## Шаг 1: как устроен RSA

1. Берут два простых числа `p` и `q`. В нашем примере `p = 61`, `q = 53`.
2. Считают модуль `n = p·q = 3233`. Он публикуется.
3. Считают `φ(n) = (p−1)(q−1) = 60·52 = 3120`. **Это секрет.**
4. Выбирают открытую экспоненту `e = 17` (`gcd(e, φ) = 1`).
5. Находят секретную `d = e⁻¹ mod φ(n) = 2753`.

Шифрование: `c = m^e mod n`. Расшифровка: `m = c^d mod n`. Проверим на `m = 65`:

```python
p, q, e = 61, 53, 17
n = p * q
phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)

m = 65
c = pow(m, e, n)
print(c)              # 2790
print(pow(c, d, n))   # 65
```

`c` совпал с условием, а расшифровка вернула `m`. Вся стойкость RSA держится на том, что по `n` невозможно быстро найти `p` и `q` (факторизация), а значит и `φ(n)`, и `d`.

## Шаг 2: что такое textbook RSA и почему он слаб

Только что мы шифровали «голое» число без всякой обвязки. Это **textbook RSA** — учебная версия. В реальности сообщение перед шифрованием дополняют **padding** (PKCS#1 v1.5 или OAEP), который добавляет случайность и структуру. Без padding вылезают классические атаки, две из которых разберём.

## Шаг 3: атака малого e — целочисленный корень

Пусть `e = 3`, а сообщение короткое. Тогда `m^3` может оказаться **меньше `n`**, и модуль вообще не сработает — `c = m^3` как обычное целое. Восстановить `m` тривиально: взять целочисленный корень третьей степени.

```python
from sympy import integer_nthroot

mm = int.from_bytes(b"flag", "big")   # 1718378855
c = mm ** 3
print(c)                    # 5074073570688783701917376375
print(integer_nthroot(c, 3))  # (1718378855, True)
```

Флаг `True` во втором элементе означает, что корень извлёкся **нацело** — `m` найден без всякого ключа. Признак такой задачи в условии: `e = 3` (или другое маленькое), большой `n`, маленький `c`. В реальном CTF остаётся перевести число обратно в байты: `mm.to_bytes(...)`.

## Шаг 4: факторизация слабого n

Вторая классика — «слабый» модуль. Если `p` и `q` подобраны неудачно, `n` разлагается быстро.

**Слишком близкие простые.** Если `p ≈ q`, работает метод Ферма: `n = a² − b² = (a−b)(a+b)` при `a = ⌈√n⌉`. Проверим на `p = 1000000007`, `q = 1000000009`:

```python
import math
n = 1000000016000000063
a = math.isqrt(n) + 1
while True:
    b2 = a * a - n
    b = math.isqrt(b2)
    if b * b == b2:
        print(a - b, a + b)   # 1000000007 1000000009
        break
    a += 1
```

Корень нашёлся за один шаг. **Слишком маленькие простые** — ещё проще: `sympy.factorint` разложит `n` мгновенно.

```python
from sympy import factorint
print(factorint(3233))   # {53: 1, 61: 1}
```

Признак такой задачи: `n` подозрительно мал (десятки-сотни бит) или `p` и `q` близки. Факторизовав `n`, мы получаем `φ(n)`, а затем `d` и расшифровываем.

## Шаг 5: инструменты

Не изобретай велосипед — начни с готового:

- **RsaCtfTool** — автоматически перебирает десятки атак (малый `e`, близкие простые, общий модуль, Wiener и др.) по публичному ключу.
- **sympy** — `factorint`, `integer_nthroot`, `nextprime` для ручной работы.
- **SageMath** — для задач, где нужны решётки/LLL (это уже следующий уровень).
- **gmpy2** — быстрые большие целые и корни.

Рабочий порядок: прочитал условие → определил слабость (`e`? `n`? сколько пар ключей?) → применил нужную атаку → **проверил**, что `pow(m, e, n) == c`. Если найденное `m` не даёт осмысленного текста, а `pow(m, e, n)` не сходится с `c` — значит, ты применил не ту атаку или ошибся в параметрах: вернись к условию и перепроверь каждое число. Не трать время на перебор там, где есть структурный дефект.

## Генерация ключей и проверка параметров

Полезно уметь собрать RSA целиком, чтобы понимать, откуда берутся слабости. Генерация: выбираем два простых нужного размера, считаем `n`, `φ(n)`, `e`, `d`.

```python
from sympy import nextprime, mod_inverse
import random

def gen_keys(bits=16):
    p = nextprime(random.getrandbits(bits))
    q = nextprime(random.getrandbits(bits))
    while q == p:
        q = nextprime(random.getrandbits(bits))
    n = p * q
    phi = (p - 1) * (q - 1)
    e = 65537
    if phi % e == 0:      # e обязан быть взаимно прост с φ(n)
        e = 3
    d = mod_inverse(e, phi)
    return (n, e), (n, d), p, q

pub, priv, p, q = gen_keys()
print(pub, priv)
```

Теперь проверка «здоровья» чужого ключа — набор типичных дефектов:

- `e` слишком мал (3, 5, 17) → риск целочисленного корня;
- `n` слишком мал или имеет общие множители с другим `n` → факторизация;
- `p` и `q` близки → метод Ферма;
- дано несколько пар `(n, e, c)` → возможны Håstad и common modulus.

Каждый пункт — отдельная атака, и большинство из них реализовано в RsaCtfTool. Твоя задача — распознать дефект по условию, а не изобретать математику заново.

## Что мы теперь знаем

- RSA строится на паре простых `p, q`; секрет — `φ(n)` и `d = e⁻¹ mod φ(n)`.
- Шифрование `c = m^e mod n`, расшифровка `m = c^d mod n`.
- Textbook RSA без padding слаб.
- Малый `e` и короткое сообщение ломаются целочисленным корнем.
- Слабый `n` (малый или с близкими простыми) факторизуется быстро (Fermat, `factorint`).
- Признаки задачи читаются прямо из условия: размер `e`, размер `n`, число пар.

## Куда дальше

Мы вскрыли RSA «в лоб» — через слабый `e` и слабый `n`. Но в реальных задачах параметры выглядят прилично, и атака идёт через структуру. В следующем уроке **crypto-aes-modes** мы переключимся на симметричную криптографию и увидим, как одна и та же ошибка — отсутствие случайности — губит блочные шифры. А пока главное: **RSA ломается не «взломом», а слабыми параметрами**.

## Где пригодится

- **CTF** — RSA-задачи есть на каждом турнире; базовые атаки дают быстрые очки.
- **Анализ протоколов** — проверка параметров сертификатов и TLS-ключей.
- **Криптоаудит** — поиск малых экспонент, общих модулей, плохих генераторов простых.
- **Багбаунти** — неверная реализация RSA регулярно приводит к critical-находкам.
