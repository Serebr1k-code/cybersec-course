## Вопрос, с которого всё начинается

Сервис на Python выдаёт «случайные» восьмизначные коды через `random.randint(0, 9)`. Мы видим поток цифр, но не видим ни ключа, ни seed. Казалось бы — случайность. На деле внутри сидит **Mersenne Twister** (MT19937), и его состояние полностью восстанавливается по достаточному числу выходов. Разберём, почему это так, и добьём случай, когда выходы **неполные** — как раз наш поток цифр.

## Наш пример

Возьмём генератор, который мы завели с seed `12345`, и посмотрим на его настоящие выходы:

```python
import random
r = random.Random(12345)
print([r.getrandbits(32) for _ in range(3)])
```

```
[1789368711, 3146859322, 43676229]
```

Три 32-битных числа. Вопрос: зная такие числа, можно ли предсказать следующее? Да — но сначала надо понять, как генератор устроен.

## Шаг 1: почему MT19937 предсказуем

MT19937 держит состояние из **624 32-битных слов** `mt[0..623]` и индекс. Обновление («twist») пересобирает слова:

```
y = (mt[i] & 0x80000000) | (mt[i+1] & 0x7fffffff)
mt[i] = mt[(i+397) % 624] ^ (y >> 1)
if y & 1: mt[i] ^= 0x9908b0df
```

Ключевое слово — **линейность**. Все операции здесь и ниже — только XOR, сдвиги и побитовое И. А такие операции линейны над полем GF(2): нет умножения, нет необратимых шагов. Значит, если у нас достаточно выходов, мы можем решить систему линейных уравнений и получить состояние — а по нему предсказать всё будущее.

## Шаг 2: tempering и обратная операция

Прежде чем отдать слово наружу, генератор прогоняет его через **tempering** — перемешивание битов:

```python
def temper(y):
    y ^= (y >> 11)
    y ^= (y << 7) & 0x9d2c5680
    y ^= (y << 15) & 0xefc60000
    y ^= (y >> 18)
    return y & 0xffffffff
```

Tempering тоже линейно и, что важнее, **обратимо**: каждую операцию XOR-со-сдвигом можно развернуть по частям. Функция `untemper` восстанавливает исходное слово из выхода:

```python
def unshift_right_xor(y, shift):
    x = y
    for _ in range(5):          # итеративно достраиваем биты
        x = y ^ (x >> shift)
    return x & 0xffffffff

def unshift_left_xor_mask(y, shift, mask):
    x = y
    for _ in range(5):
        x = y ^ ((x << shift) & mask)
    return x & 0xffffffff

def untemper(y):
    y = unshift_right_xor(y, 18)
    y = unshift_left_xor_mask(y, 15, 0xefc60000)
    y = unshift_left_xor_mask(y, 7, 0x9d2c5680)
    y = unshift_right_xor(y, 11)
    return y & 0xffffffff
```

Пять итераций хватает, потому что каждый сдвиг переносит биты не дальше 32 позиций, а за пять проходов «эхо» гаснет.

## Шаг 3: полное восстановление и проверка

Собираем 624 подряд идущих 32-битных выхода, снимаем tempering — и получаем состояние. Дальше подсовываем его новому объекту `random` и предсказываем следующее число:

```python
r2 = random.Random(12345)
o = [r2.getrandbits(32) for _ in range(625)]
st = [untemper(x) for x in o[:624]]
cl = random.Random()
cl.setstate((3, tuple(st + [624]), None))
print("actual 625th:", o[624])
print("predicted   :", cl.getrandbits(32))
```

```
actual 625th: 4171722749
predicted   : 4171722749
```

Совпало. Обратите внимание на формат `setstate`: Python ждёт кортеж `(3, tuple(state + [624]), None)` — если передать просто список, генератор откажется работать.

## Шаг 4: когда выходов не хватает — частичные наблюдения

В реальности сервис редко отдаёт полные 32 бита. Наш пример — `randint(0, 9)`, это всего `log2(10) ≈ 3.3` бита на выход. 624 полных слов набрать неоткуда. Но линейность спасает и здесь: **недоопределённую** систему можно решить символьным решателем **Z3**. Идея — завести состояние как битовые векторы и добавить уравнения-наблюдения:

```python
from z3 import BitVec, BitVecVal, Solver, LShR, Extract

mt = [BitVec(f'm{i}', 32) for i in range(624)]
s = Solver()

def z3_temper(y):
    y = y ^ LShR(y, 11)
    y = y ^ ((y << 7) & BitVecVal(0x9d2c5680, 32))
    y = y ^ ((y << 15) & BitVecVal(0xefc60000, 32))
    y = y ^ LShR(y, 18)
    return y

out = z3_temper(mt[i])
s.add(Extract(3, 0, out) == observed_low4)   # известны 4 младших бита
```

Каждое наблюдение добавляет несколько бит. Чтобы покрыть состояние (19937 бит), при 4 битах на выход нужно несколько тысяч цифр. Z3 решает такую систему за секунды–минуты. Альтернатива для больших систем — собрать матрицу линейных уравнений над GF(2) и решить её методом Гаусса: это быстрее и не боится объёма.

## Шаг 5: восстановление seed, когда выходов совсем мало

Иногда известен только один выход, но seed — 32-битное число. Тогда состояние не нужно: перебираем seed и сравниваем первый выход. Если seed — время запуска, окно крошечное:

```python
import random, time
t0 = int(time.time())
first = random.Random(t0).getrandbits(32)
for s in range(t0 - 100, t0 + 100):
    random.seed(s)
    if random.getrandbits(32) == first:
        print("seed found:", s)
        break
```

```
seed found: 1791785586
```

Если seed задан неявно (`random.seed()` без аргумента), Python берёт энтропию `os.urandom` — тогда перебор бесполезен, и остаётся путь через 624 выхода.

## Шаг 6: чужие реализации — tempering не везде одинаков

Всё, что мы делали, опирается на **точный** вид tempering. Python, PHP, Ruby и C++ берут один и тот же MT19937, но по-разному перемешивают выход. PHP `mt_rand()` не делает финальный `>> 18` и возвращает только 31 бит — если применить `untemper` от Python, получится мусор. Поэтому в чужом коде сначала уточняют реализацию и версию, а потом берут подходящую обратную функцию. Для готовых генераторов есть инструменты: `randcrack` восстанавливает состояние по 624 значениям `getrandbits(32)`, а `z3-solver` справляется с частичными выходами. Ставятся они одной командой:

```bash
pip install randcrack z3-solver
```

## Что мы теперь знаем

- MT19937 **линеен** над GF(2), поэтому предсказуем, несмотря на огромное состояние.
- **Tempering** — обратимое перемешивание; обратная функция — `untemper`.
- **624** подряд идущих 32-битных выхода дают полное состояние.
- При **частичных** выходах работает Z3 или Гаусс над GF(2).
- При малом числе выходов и 32-битном seed — перебор/восстановление seed.
- Формат `setstate` важен: `(3, tuple(state + [624]), None)`.

## На что смотреть дальше

- **Другая реализация** (PHP `mt_rand`, Java `Random`) — свой tempering, свой untemper: смотрите `crypto-php-mtrand`.
- **`random()` (float)** — это 53 бита из двух слов, а не один выход: распаковывайте перед подачей.
- **Пропущенные вызовы** сдвигают поток — учитывайте каждый вызов генератора между наблюдениями.
- **`secrets`/`os.urandom`** — атака неприменима, ищите другой вектор.
- **Мало наблюдений для Z3** — добавьте любые другие выходы того же генератора (ID, токены).
