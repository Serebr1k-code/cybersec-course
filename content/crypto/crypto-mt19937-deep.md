Mersenne Twister (MT19937) — генератор с огромным состоянием (19937 бит), но полностью **линейным** над GF(2): каждый выход — линейная функция состояния. Поэтому по достаточному числу выходов состояние восстанавливается, а по неполным наблюдениям — решается как система линейных уравнений. Эта глава — внутреннее устройство MT19937, операция untempering, полное восстановление, и главное — работа с **частичными** выходами через Z3, что нужно в реальных CTF, где приложение отдаёт усечённые значения.

## Устройство MT19937 и tempering

Состояние — 624 слова `mt[0..623]` (32 бита) плюс индекс. Обновление — «twist»:

```
y = (mt[i] & 0x80000000) | (mt[i+1] & 0x7fffffff)
mt[i] = mt[(i+397) % 624] ^ (y >> 1)
if y & 1: mt[i] ^= 0x9908b0df
```

Каждый выход проходит **tempering** (обратимое линейное преобразование):

```python
def temper(y):
    y ^= (y >> 11)
    y ^= (y << 7) & 0x9d2c5680
    y ^= (y << 15) & 0xefc60000
    y ^= (y >> 18)
    return y & 0xffffffff
```

Ключевое: все операции — XOR и сдвиги, то есть линейны над GF(2) и **обратимы**.

## Untempering: обратная операция

Зная выход, восстанавливаем «сырое» слово `y`, инвертируя сдвиги по частям:

```python
def unshift_right_xor(y, shift):
    x = y
    for _ in range(5):        # итеративно восстанавливаем биты
        x = y ^ (x >> shift)
    return x & 0xffffffff

def unshift_left_xor_mask(y, shift, mask):
    x = y
    for _ in range(5):
        x = y ^ ((x << shift) & mask)
    return x & 0xffffffff

def untemper(y):
    y = unshift_right_xor(y, 18)
    y = unshift_left_xor_mask(y, 15, 0xefc60000)
    y = unshift_left_xor_mask(y, 7, 0x9d2c5680)
    y = unshift_right_xor(y, 11)
    return y & 0xffffffff
```

После untemper 624 подряд идущих выходов дают состояние `mt[0..623]` — и можно предсказать всё дальнейшее.

## Полное восстановление состояния

```python
state = [untemper(x) for x in outputs[:624]]
# теперь клонируем генератор
import random
r = random.Random()
r.setstate((3, tuple(state + [624]), None))
print(r.getrandbits(32))   # совпадёт со следующим выходом
```

`randcrack` делает это «под капотом» (см. `crypto-python-random`), но для `random()` и `randint` нужна ручная распаковка: `random()` — это 53 бита из двух слов (27 верхних + 26 нижних).

## Частичные выходы и Z3

Реальные приложения редко отдают полные 32 бита. Если сервис возвращает `randint(0, 9)` (4 бита) или `random()` (53 бита), состояние недоопределено — но линейно решаемо. Подход: закодировать twist и tempering как битовые векторы Z3, добавить наблюдения.

```python
from z3 import BitVec, BitVecVal, Solver, LShR, Extract, If

N = 624
mt = [BitVec(f'm{i}', 32) for i in range(N)]
s = Solver()
# twist-рекурсия как формулы (или задать mt напрямую и связать с выходами)
def z3_temper(y):
    y = y ^ LShR(y, 11)
    y = y ^ ((y << 7) & BitVecVal(0x9d2c5680, 32))
    y = y ^ ((y << 15) & BitVecVal(0xefc60000, 32))
    y = y ^ LShR(y, 18)
    return y
# наблюдение: 4 бита из randint(0,9)
out = z3_temper(mt[i])
s.add(Extract(3, 0, out) == observed_low4)
```

На практике для `randint(0,9)` требуется несколько десятков наблюдений (каждое даёт ~4 бита, нужно покрыть 19937 бит). Z3 справляется за секунды–минуты. Альтернатива — построить матрицу линейных уравнений над GF(2) и решить Гауссом (быстрее для больших систем).

## Восстановление seed

Если наблюдений мало, но seed — 32-битный, его перебирают:

- **Перебор 2^32** — минуты на CPU, секунды с GPU/оптимизацией.
- **Seed recovery (обратное `init_genrand`)** — первый выход как функция seed почти линеен; существует обратное преобразование, восстанавливающее seed по одному выходу за O(1).
- **Окно `time.time()`/`getpid()`** — если seed = время старта, перебирают ±минуты.

```python
import random, time
target = next_output_32()
for s in range(int(time.time()) - 3600, int(time.time())):
    random.seed(s)
    if random.getrandbits(32) == target:
        print("seed", s); break
```

## Варианты и другие реализации

- **Python `random`** — MT19937, `random()` = 53 бита.
- **PHP `mt_rand`** — другой tempering (нет последнего `>>18`, другое `>>11`); нужен свой untemper.
- **Ruby, Perl** — свои варианты MT.
- **C++ `std::mt19937`** — стандартный MT19937.
- **`numpy.random`** (legacy) — MT19937, но с другим способом сборки выходов.
- **MT19937-64** — 64-битная версия (другой tempering, состояние 312 слов).

Всегда уточняйте реализацию: untemper зависит от точного tempering.

## Частые ошибки и тупики

- **Untemper под Python, а генератор — PHP.** Разный tempering → мусор.
- **Считать `random()` одним 32-битным выходом.** Это 53 бита из двух слов.
- **Пропускать вызовы.** Любой промежуточный `random()` сдвигает поток.
- **Мало наблюдений для Z3.** Нужно покрыть ~19937 бит; 4-битные выходы → тысячи.
- **Забыть про twist между выходами.** 624 выхода — это состояние, но следующий выход уже после twist.
- **Путать seed-recovery и state-recovery.** Первое — по малому числу выходов при известном seed-пространстве, второе — по 624.
- **`setstate` не в том формате.** Python ждёт `(3, tuple(state+[624]), None)`.

## Что дальше (decision)

1. 624 полных 32-битных выхода → untemper + `setstate` (или randcrack).
2. Выходы усечённые → Z3 или GF(2)-Гаусс.
3. Мало выходов, seed 32-бит → перебор/seed recovery.
4. Известно окно времени seed → перебор окна.
5. Другая реализация (PHP/Ruby) → свой untemper.
6. Генератор `secrets`/`os.urandom` → атака неприменима, ищите иное.

## Полный разбор: PHP mt_rand

PHP использует MT19937, но с **другим tempering** (нет финального `>>18`, и `>>11` заменён на `>>11`-вариант). Поэтому untemper под Python даст мусор. Правильные операции для PHP:

```python
def php_untemper(y):
    # обратный tempering PHP mt_rand
    y = y ^ (y >> 18)          # в PHP его нет — убрать соответствующую строку
    y = y ^ ((y << 15) & 0xefc60000)
    y = y ^ ((y << 7) & 0x9d2c5680)
    y = y ^ (y >> 11)
    return y & 0xffffffff
```

`mt_rand()` возвращает `>> 1` от 32-битного выхода (31 бит), а `mt_rand(a,b)` делает `randrange`. Собрав 624 значения `mt_rand()`, восстановите состояние и предскажите следующие — это классическая задача «PHP-токен». Всегда сверяйте tempering с версией PHP: в разных сборках детали менялись.
