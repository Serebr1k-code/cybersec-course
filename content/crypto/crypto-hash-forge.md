## Три разных свойства хэш-функции

Путать их — классическая ошибка. Различайте:

- **Preimage resistance:** по данному `h` найти `m`, что `H(m) = h`. Сложность `2^n`.
- **Second-preimage resistance:** по данному `m1` найти `m2 ≠ m1`, что `H(m1) = H(m2)`. Сложность `2^n`.
- **Collision resistance:** найти **любые** два `m1 ≠ m2` с `H(m1) = H(m2)`. Сложность `2^(n/2)` (birthday paradox).

Коллизии строить проще всего — и именно они ломают MD5/SHA-1. Важно: **коллизия ≠ second-preimage**. Если у вас есть конкретный файл и вы хотите второй с тем же хэшем — это second-preimage, и для MD5 он **не** построен. Но если вы можете **выбрать оба** файла — коллизия реальна.

## Почему MD5 и SHA-1 сломаны

- **MD5:** коллизии известны с 2004 (Wang et al.). Строятся за секунды на обычном CPU. Chosen-prefix коллизии — с 2009 (Stevens et al.).
- **SHA-1:** коллизии (SHAttered) продемонстрированы в 2017 — два разных PDF с одинаковым SHA-1. Chosen-prefix коллизии SHA-1 — с 2020 (Leurent & Peyrin).
- **SHA-256/SHA-3:** коллизии не построены.

Структурная причина — конструкция **Merkle–Damgård**: сообщение обрабатывается блоками с фиксированным IV; коллизии в компрессионной функции распространяются на весь хэш.

## Идентично-префиксные (identical-prefix) коллизии

Даны **одинаковые** префиксы `P`; находятся два разных блока `B1`, `B2`, что `H(P || B1) = H(P || B2)`. Инструмент — `fastcoll` (для MD5).

```bash
fastcoll -p prefix.bin -o out1.bin out2.bin
# out1.bin и out2.bin начинаются с prefix.bin и имеют одинаковый MD5
md5sum out1.bin out2.bin   # одинаковые!
```

Классика — задача Cryptopals 50 (MD5 collision) и подделка «двух файлов с одинаковым хэшем» в системах дедупликации.

## Chosen-prefix коллизии

Даны **разные** префиксы `P1` и `P2`; находятся суффиксы `S1`, `S2`, что `H(P1 || S1) = H(P2 || S2)`. Это мощнее: позволяет создать два «осмысленных» файла с одинаковым хэшем (например, два разных сертификата или два разных документа). Инструменты: `uniqcoll` (MD5), `sha1collisiondetection`, `collide` (SHA-1, проект SHAttered).

```bash
# pip install pycollisions / сборка из исходников
uniqcoll -p1 file1 -p2 file2 -o out1 out2
```

Применение: подделка X.509-сертификата (MD5-сертификаты доверенного CA), подделка подписанного кода, обход «проверки целостности по хэшу».

## Практический пример: обход проверки «по хэшу»

Сценарий: сервер принимает файл, проверяет, что его MD5 не совпадает с «запрещённым» (например, антивирус по чёрному списку), но иначе доверяет содержимому. Атакующий:

1. Создаёт безобидный файл `A` и вредоносный `B`.
2. Строит chosen-prefix коллизию: `A'` и `B'` с одинаковым MD5.
3. Отдаёт `A'` на проверку (проходит), затем `B'` на исполнение.

Другой сценарий — **два PDF-документа** с одинаковым SHA-1 (SHAttered): один подписывается легитимно, второй содержит изменённый текст, подпись остаётся валидной.

## Collision vs length extension

Не путайте с length extension (см. `crypto-merkle`):

- **Коллизия** ищет два сообщения с одинаковым хэшем (нужен поиск/инструмент).
- **Length extension** использует структуру Merkle–Damgård, чтобы достроить `H(secret||msg||extra)` **без** поиска коллизии, по известному `H(secret||msg)`.

Это разные атаки. Коллизия ломает «проверку целостности», length extension — наивные MAC.

## Частые ошибки

- **Путать collision и second-preimage.** Для MD5 second-preimage не построен.
- **Думать, что «MD5 сломан полностью».** Preimage всё ещё дорог; сломаны именно коллизии.
- **Использовать SHA-256 там, где нужна коллизионная стойкость** — он в порядке.
- **Забывать про chosen-prefix.** Он сложнее identical-prefix, но именно он даёт подделку подписей.
- **Считать коллизию «теоретической».** Инструменты работают за секунды/минуты.
- **Игнорировать контекст.** Коллизия в хэше ≠ коллизия в конкретном приложении (формат, парсинг).

## Практические сценарии эксплуатации

**1. Подделка подписи кода / сертификата (MD5).** Многие старые системы подписывали артефакты MD5. Атакующий готовит два файла (безобидный и вредоносный) с одинаковым MD5 через chosen-prefix, легитимно получает подпись для безобидного и использует её для вредоносного.

**2. Обход «проверки по чёрному списку».** Антивирус/фильтр проверяет хэш файла. Коллизия позволяет загрузить вредоносный файл с «разрешённым» хэшем.

**3. Дедупликация в бэкап-системах.** Система хранит один экземпляр файла по хэшу. Коллизия позволяет «подменить» содержимое, не меняя хэш.

**4. PDF-коллизия (SHAttered).** Два PDF с одинаковым SHA-1: один показывает одно содержимое, второй — другое, подпись общая.

## Почему это важно для «настоящей» безопасности

Даже если сегодня SHA-256 безопасен, урок остаётся: **никогда не используйте хэш, сломана ли коллизионная стойкость, как единственную защиту целостности**. Для целостности используйте HMAC/AEAD или подпись на современном хэше. Для «отпечатков» файлов — SHA-256/512 или BLAKE3. Для паролей — bcrypt/argon2 (см. `crypto-kdf`).

## Теория: как строятся коллизии MD5

Коллизии MD5 используют **дифференциальный криптоанализ** (см. `crypto-block-analysis`): ищутся два блока `B1`, `B2` с малой разностью, которые после компрессионной функции MD5 дают одинаковое состояние. Ключевые ингредиенты:

- **Дифференциальная характеристика** компрессионной функции с высокой вероятностью.
- **Message modification:** атакующий подправляет биты блока, чтобы удержать характеристику на нужном пути (это превращает вероятность из `2^-40` в практичную).
- **Identical-prefix:** оба блока идут после общего префикса.
- **Chosen-prefix:** сначала строится «мост» между двумя произвольными префиксами, затем identical-prefix коллизия.

Для SHA-1 аналогично, но сложнее (SHAttered потребовал ~2^63 работы, распределённой на GPU; chosen-prefix — ~2^63 с).

## Разбор: почему `md5(a||b) == md5(a||c)`, но не `md5(a) == md5(b)`

Коллизия **распространяется по цепочке блоков** Merkle–Damgård: если два состояния совпали после обработки блока, всё последующее будет одинаковым. Поэтому найденная коллизия в блоках `B1`, `B2` даёт `md5(P||B1||S) == md5(P||B2||S)` для **любого** суффикса `S`. Это и позволяет «приклеивать» осмысленный суффикс (PDF-структуру) к каждому из коллидирующих файлов.

Важное следствие для эксплуатации: вы **не** можете произвольно выбрать оба файла целиком; вы выбираете префиксы (chosen-prefix) или фиксируете общий префикс (identical-prefix), а «мост» и суффиксы строит инструмент.

## Как проверять и не ошибиться

- Всегда проверяйте **оба** файла хэшем (`md5sum out1 out2`) — коллизия должна подтвердиться.
- Убедитесь, что файлы **различны** (`cmp out1 out2` → различие).
- Для chosen-prefix проверьте, что оба начинаются с заданных вами префиксов (`head -c`).
- Помните: инструмент может требовать **точного** размера префикса/выравнивания — читайте его README.

## Как не застрять

- **Определите тип атаки:** collision или second-preimage?
- **MD5/SHA-1** → коллизии реальны; используйте fastcoll/uniqcoll.
- **SHA-256** → коллизий нет; ищите length extension или логику.
- **Для подписи нужна chosen-prefix** — проверьте, поддерживается ли.
- **Проверяйте инструмент на тестовых данных.**
- **Помните: dedup-системы уязвимы** к identical-prefix коллизиям.
