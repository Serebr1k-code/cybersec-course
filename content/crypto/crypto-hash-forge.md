## Вопрос, с которого всё начинается

В прошлом уроке мы ломали хэши перебором — угадывали пароль. Но хэши используют не только для паролей: по ним проверяют целостность файлов, подписывают сертификаты, делают «отпечатки». Вопрос новичка: «Если найти коллизию — два файла с одинаковым хэшем — можно обмануть такую проверку?» Да, и на MD5/SHA-1 это делают на практике. Разберём, чем коллизия отличается от «расшифровки» и как её строят.

## Наш пример

Возьмём игрушечный хэш — 32-битное усечение SHA-256 — и найдём для него коллизию прямым перебором. Это покажет сам принцип. Затем перенесём вывод на настоящие MD5 и SHA-1 и посмотрим, как коллизия превращается в подделку подписи.

## Шаг 1: три разных свойства хэш-функции

Их постоянно путают. Различайте:

- **Preimage resistance** — по данному `h` найти `m` с `H(m) = h`. Сложность `2^n`.
- **Second-preimage resistance** — по данному `m1` найти `m2 ≠ m1` с `H(m1) = H(m2)`. Тоже `2^n`.
- **Collision resistance** — найти **любые** два `m1 ≠ m2` с `H(m1) = H(m2)`. Сложность `2^(n/2)` — из-за парадокса дней рождения.

Коллизии строить **проще всего**, и именно они ломают MD5/SHA-1. Ключевое различие: если у вас есть **конкретный** файл и вы хотите второй с тем же хэшем — это second-preimage, и для MD5 он **не построен**. Но если вы можете выбрать **оба** файла — коллизия реальна.

## Шаг 2: почему коллизии проще всего — полный прогон

Парадокс дней рождения: в группе из ~23 человек вероятность совпадения дней рождения > 50%. Для `n`-битного хэша коллизия находится примерно за `2^(n/2)` попыток. Проверим на нашем игрушечном 32-битном хэше:

```python
import hashlib
def toy(m):
    return int.from_bytes(hashlib.sha256(m).digest()[:4], "big")

seen = {}
for i in range(200000):
    m = i.to_bytes(4, "big")
    h = toy(m)
    if h in seen and seen[h] != m:
        print("collision after", i, "tries")
        print(seen[h].hex(), m.hex(), hex(h))
        break
    seen[h] = m
```

```
collision after 45652 tries
0000a036 0000b254 0xf4580cc2
```

Коллизия найдена после **45 652** попыток — это порядка `2^15.5`, ровно как предсказывает граница `2^(32/2) = 2^16`. Принцип тот же для MD5: сложность коллизии `2^64`, что давно достижимо. А вот preimage для 32-битного хэша требовал бы `2^32` — в тысячи раз больше. Отсюда вывод: **коллизии ломать на порядки легче, чем preimage.**

## Шаг 3: MD5 и SHA-1 сломаны

- **MD5:** коллизии известны с 2004 года (Wang et al.), строятся за секунды на обычном CPU. Chosen-prefix коллизии — с 2009 (Stevens et al.).
- **SHA-1:** коллизии продемонстрированы в 2017 (SHAttered) — два разных PDF с одинаковым SHA-1. Chosen-prefix — с 2020.
- **SHA-256/SHA-3:** коллизии не построены.

Структурная причина — конструкция **Merkle–Damgård**: сообщение обрабатывается блоками с фиксированным начальным состоянием, и коллизия в компрессионной функции распространяется на весь хэш. Инструмент для MD5 — `fastcoll`:

```bash
$ fastcoll -p prefix.bin -o out1.bin out2.bin
$ md5sum out1.bin out2.bin
# одинаковые хэши, разные файлы
```

Это **identical-prefix** коллизия: оба файла начинаются с одного префикса `prefix.bin`. Классика — подмена файлов в системах дедупликации, где «одинаковый хэш = одинаковый файл».

## Шаг 4: chosen-prefix — подделка подписей

**Chosen-prefix** коллизия мощнее: даны **разные** префиксы `P1` и `P2`, находятся суффиксы `S1`, `S2` с `H(P1‖S1) = H(P2‖S2)`. Это позволяет создать два **осмысленных** файла с одинаковым хэшем — например, два разных сертификата. Сценарий подделки: вы готовите безобидный документ `A` и вредоносный `B`, строите chosen-prefix коллизию `A'`, `B'`, легитимно получаете подпись для `A'` — и она валидна для `B'`. Инструменты: `uniqcoll` (MD5), `collide` (SHA-1).

## Шаг 5: collision vs length extension

Не путайте коллизию с **length extension** (см. `crypto-merkle`). Коллизия ищет два сообщения с одинаковым хэшем (нужен поиск/инструмент). Length extension использует структуру Merkle–Damgård, чтобы достроить `H(secret‖msg‖extra)` **без** поиска коллизии, зная `H(secret‖msg)`. Это разные атаки: коллизия ломает «проверку целостности», length extension — наивные MAC вида `hash(secret‖msg)`.

## Шаг 6: как эксплуатируют и как не застрять

Сценарии эксплуатации: подделка подписи кода или X.509-сертификата (MD5-сертификаты доверенного CA); обход «проверки по чёрному списку» (антивирус сверяет хэш — коллизия даёт «разрешённый» хэш вредоносному файлу); дедупликация в бэкап-системах; PDF-коллизия SHAttered (два разных документа, одна подпись).

Чек-лист: определите тип атаки (collision или second-preimage); для MD5/SHA-1 коллизии реальны — используйте `fastcoll`/`uniqcoll`; для SHA-256 коллизий нет — ищите length extension или логику; для подписи нужна именно **chosen-prefix**; всегда проверяйте **оба** файла хэшем и убеждайтесь, что они **различны** (`cmp`). И главный вывод для защиты: **никогда не используйте хэш, у которого сломана коллизионная стойкость, как единственную защиту целостности** — для этого есть HMAC, AEAD или подпись на современном хэше.

## Почему это важно для реальной безопасности

Даже если сегодня SHA-256 безопасен, урок остаётся навсегда: **нельзя использовать хэш как единственную защиту целостности, если его коллизионная стойкость сломана**. Для целостности применяйте HMAC, AEAD или подпись на современном хэше; для «отпечатков» файлов — SHA-256/512 или BLAKE3; для паролей — bcrypt/argon2. Показательно, что MD5-коллизии использовались против реальных удостоверяющих центров: если CA подписывает сертификат по MD5, атакующий может получить валидный сертификат на чужой домен. Именно поэтому MD5 и SHA-1 объявлены небезопасными для подписей и сертификатов во всех современных стандартах. Мораль: «хэш необратим» — это про preimage, а не про целостность; коллизионная стойкость — отдельное, более слабое свойство.

## Что мы теперь знаем

- **Collision** (`2^(n/2)`) строится на порядки легче, чем **preimage** (`2^n`).
- **Collision ≠ second-preimage**: для MD5 second-preimage не построен.
- **MD5/SHA-1** коллизии реальны; **SHA-256/SHA-3** — нет.
- **Identical-prefix** (общий префикс) и **chosen-prefix** (разные префиксы) — два вида коллизий; подписи ломает chosen-prefix.
- **Length extension** — другая атака, про наивные MAC `hash(secret‖msg)`.
- Для целостности — HMAC/AEAD/подпись, а не голый хэш.
- Игрушечный 32-битный хэш дал коллизию за ~`2^16` — ровно по границе дней рождения.
- Настоящие MD5/SHA-1 ломаются инструментами (`fastcoll`, `uniqcoll`) за секунды-минуты.
- Хэш необратим по preimage, но целостность он не защищает — это разные свойства.
- Коллизия — про выбор обоих входов; подделка подписи требует именно chosen-prefix.

## Куда дальше

Мы научились строить коллизии и подделывать целостность. Дальше — инструмент, который делает хэш по-настоящему стойким ключом: в уроке **crypto-kdf** мы разберём функции вывода ключа (PBKDF2, bcrypt, scrypt, argon2) и почему именно они защищают пароли. А пока главное: **коллизии MD5/SHA-1 реальны и ломают целостность — для защиты нужен HMAC/AEAD, а не голый хэш.**

## Где пригодится

- **CTF crypto:** подделка подписей, обход проверок, задачи на MD5/SHA-1.
- **Bug bounty / пентест:** подделка сертификатов, обход дедупликации, атаки на «проверку по хэшу».
- **Работа (SOC/IR):** понимание инцидентов с подделкой подписей (MD5-сертификаты).
- **Аудит кода:** выявление использования устаревших хэшей для целостности.
- **Разработка:** почему MD5/SHA-1 нельзя использовать для безопасности.
