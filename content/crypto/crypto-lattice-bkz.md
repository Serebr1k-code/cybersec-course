## Вопрос, с которого всё начинается

LLL даёт «приблизительно короткий» базис решётки. Но часто секрет — не самый короткий вектор, а **ближайший** к известной цели (например, когда известны старшие биты секрета). Это задача CVP. Как её решить, если LLL для этого не предназначен? Ответ — приём **embedding**: свести CVP к SVP и применить редуцирование. Разберём на маленьком примере.

## Наш пример

Возьмём решётку, порождённую векторами `(7, 0)` и `(0, 7)`, то есть все точки `7·(a, b)`. Пусть секрет — вектор `v = (14, 7)`, а цель `t = (15, 9)` получена как `v` плюс небольшая ошибка `(1, 2)`. Задача: найти `v`, зная `t` и базис решётки.

## Шаг 1: LLL vs BKZ

- **LLL** — полиномиальный алгоритм, гарантия `||b1|| ≤ 2^{(n−1)/2}·det^{1/n}`. Быстро, но грубо.
- **BKZ** — блочное обобщение: разбивает базис на блоки размера `β` и решает SVP в каждом. При `β = n` даёт точное SVP, но экспоненциален. На практике `β = 20..60` часто хватает.

Качество редуцирования измеряют **root Hermite factor** `δ = ||b1|| / det^{1/n}`; LLL даёт `δ ≈ 1.02`, BKZ с ростом `β` улучшает его.

```python
from fpylll import IntegerMatrix, BKZ
A = IntegerMatrix.from_matrix(M)
BKZ.reduction(A, BKZ.Param(block_size=40))
```

Ориентиры: `block_size=2` ≈ LLL; 20–30 заметно лучше; 40–60 — «боевой» диапазон CTF; `=n` — точное SVP (нереально для больших `n`). Наращивайте `β` до нахождения секрета.

## Шаг 2: CVP и алгоритм Бабаи

**CVP (Closest Vector Problem):** дана решётка `L` и цель `t`, найти `v ∈ L`, ближайший к `t`. Часто секрет — именно «ближайший» вектор.

**Babai's nearest plane** — приближённый CVP по LLL-базису: двигаемся от старших координат к младшим, округляя проекции. Быстро, но приближённо. Точное решение требует другого приёма.

## Шаг 3: embedding (Kannan)

Идея: добавить цель как дополнительную координату с большим масштабом `M`:

```
L' = [ B   0 ]
     [ t   M ]
```

Тогда короткий вектор `(v − t, M)` в `L'` соответствует `v`, ближайшему к `t`. Чем больше `M`, тем точнее отбор. После LLL/BKZ ищем вектор с последней координатой `±M`.

Применим к нашему примеру:

```python
L = [[7,0,0], [0,7,0], [t[0], t[1], M]]   # M = 1000
R = lll(L)
for row in R:
    if abs(row[-1]) == M:
        cand = [int(x) for x in row[:2]]
        v = [t[0] - cand[0], t[1] - cand[1]]
        print("closest vector:", v)
```

```
row: [1, 2, 1000] -> v = [14, 7]
```

Редуцирование нашло короткий вектор `(1, 2, 1000)`, а `v = t − (1, 2) = (14, 7)` — ровно наш секрет. Обратите внимание: первые координаты найденного вектора — это **ошибка** `v − t`, а не сам `v`.

## Шаг 4: где это применяется

- **Knapsack (Merkle-Hellman):** решётка `[I | a; 0 | −s]`; короткий вектор даёт подмножество.
- **LWE:** embedding/dual-атака восстанавливает `s` (см. `crypto-post-quantum`).
- **NTRU:** решётка `[I | H; 0 | qI]`, короткий вектор `(f, g)` (см. `crypto-ntru`).
- **Truncated LCG:** уравнения на младшие биты → решётка.
- **Coppersmith:** малые корни полиномов через решётку (см. `crypto-rsa-coppersmith-deep`).
- **Hidden number problem:** biased nonce ECDSA.

Во всех этих задачах общий шаблон один: сформулировать соотношение как «линейное уравнение с малыми неизвестными», построить решётку так, чтобы секрет оказался коротким вектором, и применить LLL/BKZ. Ключ к успеху — правильно выбрать, какие величины малы и как их масштабировать.

## Шаг 5: выбор β и нормировка

Практическая стратегия подбора `block_size`:

1. Начните с `BKZ(20)` — секунды, часто хватает.
2. Не находит — повышайте: 30 → 40 → 50. Стоимость растёт экспоненциально по `β`, двигайтесь постепенно.
3. «Плотные» задачи (малый зазор) — `β ≈ 50–60`.
4. `β=60` не помогает — скорее всего неверна конструкция решётки, а не мало `β`.

Ориентиры по размерности: `n < 40` — LLL обычно достаточен; 40–80 — BKZ-20..40; 80–120 — BKZ-40..60 и терпение; >150 — на ноутбуке нереально.

Важный приём — **нормировка координат**: если одни координаты в тысячи раз больше других, LLL/BKZ «не видит» короткий вектор. Приводите базис к сравнимому масштабу до редуцирования. В нашем embedding за это как раз отвечает параметр `M`.

## Шаг 6: чек-лист «решётка или не решётка»

Признаки, что задача решается решёткой:

- есть линейные соотношения с **малыми** неизвестными (`s`, `e`, `f`, `k`);
- даны «приблизительные» значения (старшие биты) — это CVP;
- knapsack/subset-sum с малым весом;
- LWE/NTRU с ослабленными параметрами;
- нужно найти короткий вектор/полином с малыми коэффициентами;
- размерность < ~150.

- **Игнорировать проверку** — всегда верифицируйте найденный вектор на исходной задаче.

## Разбор: knapsack (Merkle–Hellman) через решётку

Классический пример решёточного сведения — задача о рюкзаке. Дана последовательность `a = (a1, …, an)` и сумма `s`; нужно найти подмножество с суммой `s`. Если рюкзак имеет «низкую плотность» (мало единиц в решении), строят решётку:

```
L = [ I_n   a^T ]
    [ 0…0   s   ]
```

и ищут короткий вектор вида `(x1, …, xn, 0)`, где `xi ∈ {0,1}` — индикатор выбранных элементов. Покажем на маленьком примере.

```python
from sage.all import matrix, ZZ

a = [3, 7, 11, 19, 23, 31]
s = 49
n = len(a)

B = matrix(ZZ, n + 1, n + 1)
for i in range(n):
    B[i, i] = 1
    B[i, n] = a[i]
B[n, n] = s

R = B.LLL()
for row in R:
    if row[-1] == 0 and all(x in (0, 1) for x in row[:-1]):
        print("подмножество:", list(row[:-1]))   # [1,1,1,0,0,1] -> 3+7+11+31 = 52?
```

Обратите внимание: LLL находит вектор, у которого последняя координата **нулевая** — именно он кодирует точное подмножество. Если последняя координата не ноль, LLL не сошёлся и нужен BKZ с большим `β` либо другой масштаб. Этот шаблон («матрица единичного базиса + строка целей») переиспользуется почти во всех решёточных атаках: меняются лишь целевая строка и способ кодирования малых неизвестных.

## Сравнение алгоритмов редуцирования

Разные задачи требуют разной силы редуцирования. Держите в голове ориентиры:

| Алгоритм | Сложность | Качество (`δ`) | Когда брать |
|---|---|---|---|
| Gauss | полином | точный (n=2) | 2-мерные решётки |
| LLL | полином | ≈ 1.02 | «разреженные» задачи, `n < 40` |
| BKZ-20 | ~секунды | ≈ 1.012 | первый заход, часто хватает |
| BKZ-40 | минуты | ≈ 1.008 | плотные задачи, `n 40–80` |
| BKZ-60 | часы | ≈ 1.005 | «боевой» предел CTF |
| Enumeration/SVP | экспонента | точный | малые `n`, нужна гарантия |

Начинайте с LLL, затем поднимайте `β` шагами. Полезно логировать `||b1||` после каждого шага: если норма перестала падать, дальнейший рост `β` бесполезен — ищите ошибку в построении решётки, а не в параметрах.

## Практика: нормировка и проверка результата

Три вещи чаще всего ломают решёточную атаку.

- **Плохое масштабирование.** Если одна координата измеряется тысячами, а другая — единицами, короткий вектор «не виден» редукции. Приводите координаты к сравнимому порядку (в embedding это делает `M`, в knapsack — общий множитель).
- **Неверная кодировка неизвестных.** Секрет должен быть **коротким** вектором. Если в решётке он длинный, никакое `β` не поможет — переформулируйте задачу.
- **Отсутствие проверки.** Найденный короткий вектор всегда верифицируйте на исходной задаче (подставьте в уравнение). Ложные короткие векторы — обычное дело при плохой нормировке.

```python
# масштабирование строки целей
scale = 1 << 20
B[n, n] = s * scale
for i in range(n):
    B[i, n] = a[i] * scale
R = B.BKZ(block_size=40)
```

Ещё один приём — **dual-атака** для LWE: строится решётка, двойственная к `q·Z^m + A·Z^n`, и короткий вектор в ней даёт линейную комбинацию, «обнуляющую» ошибку, что позволяет восстановить `s` после угадывания нескольких координат. Идея та же: сформулировать соотношение с малыми неизвестными и найти в решётке короткий/близкий вектор.

## Полный разбор: embedding для knapsack (Merkle–Hellman)

Классическая демонстрация решёточного CVP — рюкзак. Публичный ключ `a = [3, 7, 12, 20]`, целевая сумма `s = 22`; ищем подмножество с `Σ x_i·a_i = s`, `x_i ∈ {0,1}`. Перебор даёт `3+7+12 = 22`, то есть `x = (1,1,1,0)`, но на 100–200 элементах перебор невозможен — нужна решётка.

Строим `(n+1)×(n+1)`-матрицу: по диагонали `2`, последний столбец — коэффициенты `a_i`, а нижняя строка — из единиц и цели:

```text
B = [ 2 0 0 0  3 ]
    [ 0 2 0 0  7 ]
    [ 0 0 2 0 12 ]
    [ 0 0 0 2 20 ]
    [ 1 1 1 1 22 ]
```

Идея: комбинация `Σ x_i·row_i − row_last` для правильного подмножества даёт вектор из `±1` и `0` в последней координате:

```python
from sage.all import matrix, ZZ
B = matrix(ZZ, [[2,0,0,0,3],[0,2,0,0,7],[0,0,2,0,12],
                [0,0,0,2,20],[1,1,1,1,22]])
R = B.LLL()
for row in R:
    if row[-1] == 0 and all(abs(v) == 1 for v in row[:-1]):
        x = [1 if v == 1 else 0 for v in row[:-1]]
        print("subset:", x)
```

```text
subset: [1, 1, 1, 0]
```

LLL нашёл вектор `(1, 1, 1, −1, 0)` нормы `2` — короче всех строк базиса. Знак `+1` означает «взять элемент», `−1` — «не брать». Последняя координата `0` — признак того, что сумма сошлась. Тот же шаблон (диагональ, столбец коэффициентов, строка-цель) работает для LWE, NTRU и HNP: меняются лишь модуль и масштаб.

| Ситуация | Метод | Ориентир по времени |
|----------|-------|---------------------|

| `n 40–80`, зазор средний | BKZ-20..30 | минуты |

## Частые ошибки масштабирования

Решётки «не находят» секрет чаще не из-за малого `β`, а из-за плохой нормировки. Три типичные ошибки:

1. **Координаты разных порядков.** Если одни столбцы содержат значения `~10⁹`, а другие `~1`, короткий вектор «тонет» в больших координатах. Умножайте «малые» столбцы на масштаб, чтобы выровнять вклад.
2. **Слишком большой `M` в embedding.** Гигантский масштаб даёт численные ошибки и «ложные» короткие векторы, не связанные с целью. Подбирайте `M` так, чтобы зазор между истинным и ложными векторами был заметен.
3. **Нет проверки результата.** После редуцирования ВСЕГДА проверяйте кандидата на исходной задаче (`Σ x_i·a_i == s`). Решётка может выдать короткий вектор, не являющийся решением.
