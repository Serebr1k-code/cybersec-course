LLL даёт «приблизительно короткий» базис, но часто этого мало: секрет — не самый короткий вектор, а ближайший (CVP) или требует более сильного редуцирования (BKZ). Эта глава — переход от базового LLL к BKZ и CVP: как выбрать block size, как через embedding свести CVP к SVP, и как применять это к реальным задачам (knapsack, LWE, NTRU, truncated LCG).

## LLL vs BKZ

- **LLL** — полиномиальный алгоритм, гарантия `||b1|| ≤ 2^{(n-1)/2}·det^{1/n}`. Быстро, но грубо. Справляется при малой размерности и большом «зазоре».
- **BKZ** — блочное обобщение: разбивает базис на блоки размера `β` и решает SVP в каждом (точный перебор). При `β = n` даёт точное SVP, но экспоненциален. На практике `β = 20..60` часто хватает.

Качество редуцирования измеряют **root Hermite factor** `δ = ||b1|| / det^{1/n}`; LLL даёт `δ ≈ 1.02`, BKZ-β улучшает его с ростом `β`.

## BKZ: block size и качество

```python
# Sage
from fpylll import IntegerMatrix, BKZ
A = IntegerMatrix.from_matrix(M)
BKZ.reduction(A, BKZ.Param(block_size=40))
# или через Sage
B = M.BKZ(block_size=40)
```

- `block_size=2` ≈ LLL.
- `block_size=20–30` — заметно лучше LLL.
- `block_size=40–60` — «боевой» диапазон для CTF.
- `block_size=n` — точное SVP (нереально для больших `n`).

Эвристика: чем меньше «зазор» между секретом и случайными векторами, тем больше нужен `β`. Наращивайте `β` до нахождения секрета.

## CVP и Babai

**CVP (Closest Vector Problem):** дана решётка `L` и цель `t`, найти `v ∈ L`, ближайший к `t`. Часто секрет — именно «ближайший» вектор (например, при известных старших битах).

**Babai's nearest plane:** приближённый CVP по LLL-редуцированному базису: двигаемся от старших координат к младшим, округляя проекции. Быстро, но приближённо.

```python
# Sage: Babai через LLL
B = M.LLL()
# solve via integer linear algebra: t ≈ Σ c_i b_i
c = B.solve_left(t)          # рациональные коэффициенты
v = sum(round(c[i]) * B[i] for i in range(len(B)))
```

## Embedding technique (Kannan)

Точное сведение CVP к SVP: добавляем цель как дополнительную координату с масштабом `M` (большое число):

```
L' = [ B   0 ]
     [ t   M ]
```

Короткий вектор `(v - t, M)` в `L'` соответствует `v`, ближайшему к `t`. Чем больше `M`, тем точнее. После LLL/BKZ ищем вектор с последней координатой `±M`.

```python
# Sage: embedding для CVP
def cvp_embedding(B, t, M=1000):
    n = B.nrows()
    Bp = B.stack(t)                      # добавляем цель строкой
    Bp = Bp.augment(matrix(ZZ, n+1, 1, [0]*n + [M]))
    Bred = Bp.BKZ(block_size=30)
    for row in Bred.rows():
        if abs(row[-1]) == M:
            return vector(ZZ, row[:n])
    return None
```

## Применение

- **Knapsack (Merkle-Hellman).** Строим решётку `[I | a; 0 | -s]`; короткий вектор даёт подмножество.
- **LWE.** Embedding/dual-атака: короткий вектор восстанавливает `s` (см. `crypto-post-quantum`).
- **NTRU.** Решётка `[I|H; 0|qI]`, короткий вектор `(f,g)` (см. `crypto-ntru`).
- **Truncated LCG.** Уравнения на младшие биты → решётка.
- **Coppersmith.** Малые корни многочленов через решётку (см. `crypto-rsa-coppersmith-deep`).
- **Hidden number problem.** Biased nonce ECDSA (`crypto-ecdsa-nonce`).

## Разобранный пример: CVP через embedding

Дано: решётка `B` (базис), цель `t` (известны старшие биты секрета). Ищем ближайший вектор.

1. Строим `L'` по формуле Kannan с большим `M`.
2. `BKZ(block_size=30)`.
3. Ищем строку с `|row[-1]| == M` — её первые `n` координат и есть `v ≈ t`.
4. Проверяем: `v ∈ L` (выражается через исходный базис) и `||v - t||` мала.

Если BKZ не находит — увеличивайте `β` и/или `M`.

## Частые ошибки и тупики

- **Слишком маленький `β`.** LLL/BKZ-20 не находит секрет — поднимайте.
- **Неверное масштабирование `M`.** Малое `M` даёт ложные векторы, большое — численные проблемы.
- **Путать SVP и CVP.** Секрет может быть «ближайшим», а не «кратчайшим».
- **Забыть про размерность.** `n>100` требует больших ресурсов.
- **Ошибки в построении решётки.** Проверяйте, что секрет действительно короткий вектор.
- **Считать, что LLL всегда достаточен.** Часто нужен именно BKZ.
- **Игнорировать проверку.** Всегда верифицируйте найденный вектор на исходной задаче.

## Что дальше (decision)

1. LLL не находит → BKZ с `β=20..60`.
2. Задача «ближайший вектор» → CVP через embedding (Kannan).
3. Известны старшие биты секрета → CVP.
4. Knapsack/LWE/NTRU → соответствующая решётка + BKZ.
5. Coppersmith → решётка малых корней.
6. Параметры «боевые» → атака нереальна.

## Выбор β и практические ориентиры

Практическая стратегия подбора `block_size`:

1. Начните с `BKZ(20)` — секунды, часто уже хватает.
2. Если секрет не найден, повышайте: 30 → 40 → 50. Стоимость растёт экспоненциально по `β`, поэтому двигайтесь постепенно и проверяйте результат на каждом шаге.
3. Для «плотных» задач (малый зазор между секретом и случайными векторами) нужен `β ≈ 50–60`.
4. Если `β=60` не помогает, скорее всего задача требует другой конструкции решётки (неверно масштабированы координаты, забыт множитель `M` в embedding), а не большего `β`.

Ориентиры по размерности: `n < 40` — LLL обычно достаточен; `40–80` — BKZ-20..40; `80–120` — BKZ-40..60 и терпение; `> 150` — на ноутбуке нереально.

Полезный приём — **нормировка координат**: если одни координаты в тысячи раз больше других, LLL/BKZ «не видит» короткий вектор. Приводите базис к сравнимому масштабу (например, умножьте строки на веса) до редуцирования.

## Чек-лист: решётка или не решётка

Признаки, что задача решается решёткой:

- есть линейные соотношения с **малыми** неизвестными (`s`, `e`, `f`, `k`);
- даны «приблизительные» значения (старшие биты) — это CVP;
- задача knapsack/subset-sum с малым весом;
- LWE/NTRU с ослабленными параметрами;
- нужно найти короткий вектор/полином с малыми коэффициентами;
- размерность < ~150 (иначе нужны огромные ресурсы).

Что проверить до запуска: правильно ли масштабированы координаты (иначе короткий вектор «не виден»), достаточно ли велик `M` в embedding, не забыт ли модуль `q`. Если LLL не находит — повышайте `β` постепенно и всегда верифицируйте найденный вектор на исходной задаче.

## Быстрые рецепты для CTF

- **LLL не нашёл** → `BKZ(20)`, затем 30 → 40 → 50.
- **«Ближайший вектор»** → embedding (Kannan) с большим `M`.
- **Knapsack** → решётка `[I|a; 0|-s]`, BKZ.
- **LWE/NTRU** → соответствующая решётка, `β` по зазору.
- **Координаты разного масштаба** → нормируйте до редуцирования.
