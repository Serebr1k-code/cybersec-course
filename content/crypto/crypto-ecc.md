## Эллиптические кривые за минуту

Эллиптическая кривая над конечным полем `F_p` задаётся уравнением Вейерштрасса:

```
y^2 = x^3 + a·x + b (mod p)
```

Точки `(x, y)`, удовлетворяющие уравнению, плюс «точка на бесконечности» `O`, образуют **абелеву группу** с операцией сложения. **Скалярное умножение** `k·P = P + P + ... + P` (k раз) — односторонняя функция: зная `P` и `k`, легко вычислить `k·P` (double-and-add), но по `P` и `k·P` найти `k` — это **ECDLP** (elliptic curve discrete log problem), для которой лучший общий алгоритм — Pollard's rho за `O(√n)`.

Преимущество ECC: для 128-битной стойкости хватает 256-битной кривой (против 3072-битного RSA). Поэтому ECC доминирует в TLS, SSH, криптовалютах, Signal.

## ECDH и ECDSA

- **ECDH** — аналог DH: обмен `A = a·G`, `B = b·G`, общий секрет `a·b·G`.
- **ECDSA** — подпись. Даны `(r, s)` для сообщения с хэшем `z`: `r = (k·G).x mod n`, `s = k⁻¹(z + r·d) mod n`, где `k` — nonce, `d` — приватный ключ, `n` — порядок базовой точки `G`.

Именно `k` (nonce) — самая частая точка отказа ECDSA.

## Атака 1: переиспользование nonce k в ECDSA

Если два сообщения подписаны **одним `k`**, то `r` совпадает, и:

```
s1 = k⁻¹(z1 + r·d)
s2 = k⁻¹(z2 + r·d)
```

Вычитая: `s1 − s2 = k⁻¹(z1 − z2)`, откуда `k = (z1 − z2)·(s1 − s2)⁻¹ mod n`, а затем `d = (s1·k − z1)·r⁻¹ mod n`. **Приватный ключ восстановлен.** Это не теоретическая атака: Sony PS3 (2010) потеряла мастер-ключ именно так, и множество криптокошельков были опустошены.

```python
n = ...       # порядок кривой
z1, z2 = ...  # хэши сообщений
r, s1, s2 = ...
k = (z1 - z2) * pow(s1 - s2, -1, n) % n
d = (s1 * k - z1) * pow(r, -1, n) % n
print("private key:", hex(d))
```

**Признак:** два `(r, s)` с одинаковым `r` — немедленно атакуйте.

## Атака 2: invalid-curve

Если сервер принимает **произвольную точку** `P` и вычисляет `d·P`, не проверяя, что `P` лежит на кривой, атакующий подсовывает точку на другой кривой (с малым порядком). Результат `d·P` даёт информацию о `d mod (малый порядок)`. Повторяя для разных малых порядков, собирают `d` по CRT.

Защита — проверка `P` на кривой и что `P` в подгруппе большого простого порядка. Многие реализации (и CTF-задачи) эту проверку опускают.

## Атака 3: twist / малые подгруппы

Кривая имеет «скручивание» (twist) — кривую с тем же `p`, но другим `b`. Если порядок twist **гладкий**, а сервер не проверяет принадлежность точки, можно отправить точку twist-кривой и решить ECDLP через Полига–Хеллмана. Это комбинация invalid-curve и гладкого порядка.

## Атака 4: гладкий порядок n

Если `n` (порядок `G`) гладкое, ECDLP решается Полига–Хеллмана. Признак — факторизация `n` на малые множители. В Sage: `discrete_log(P, Q)` автоматически использует этот путь.

## Атака 5: малые/известные биты k

Если `k` генерируется с утечкой (младшие биты известны), применяется **lattice attack** (hidden number problem, HNP) — построение решётки и LLL. Инструменты: `ecdsa` с частичными nonce, Sage + `fpylll`. Это продвинутая тема, но встречается на CTF (например, «nonce имеет 8 известных младших бит»).

## Практический пример (Sage)

```python
# ECDH с известной кривой
p = 0xffffffff00000001000000000000000000000000ffffffffffffffffffffffff
a = -3
b = 0x5ac635d8aa3a93e7b3ebbd55769886bc651d06b0cc53b0f63bce3c3e27d2604b

G = E(...)
# invalid curve: берём точку малого порядка на кривой с b=0

# сервер вернёт d*P_small -> даёт d mod 3
```

## Стандартные кривые и их параметры

Важно узнавать стандартные кривые по имени или по размеру `p`:

| Кривая | `p` (бит) | `n` (порядок) | Применение |
|---|---|---|---|
| NIST P-256 (secp256r1) | 256 | простое | TLS, ECDSA |
| secp256k1 | 256 | простое | Bitcoin |
| Curve25519 (X25519) | 255 | простое (2^252+…) | TLS, Signal |
| Ed25519 | 255 | простое | подписи |
| P-384/P-521 | 384/521 | простое | высокий уровень |

Если в задаче дана нестандартная кривая с **гладким порядком** или малым `p` — это почти наверняка CTF-задача на ECDLP/Полига–Хеллмана.

## Проверка точек: почему это критично

Перед скалярным умножением сервер **обязан** проверить:

1. `P != O` (не точка на бесконечности).
2. `P` лежит на кривой: `y² == x³ + ax + b (mod p)`.
3. `n·P == O` (точка в подгруппе порядка `n`), либо `P` не в малой подгруппе.

Если проверки 2 и 3 отсутствуют — работают invalid-curve и twist-атаки. Многие библиотеки и самописные реализации их опускают ради скорости.

```python
# проверка точки на кривой
def on_curve(P, a, b, p):
    x, y = P
    return (y*y - (x*x*x + a*x + b)) % p == 0
```

## Полная атака nonce reuse: пример с числами

```python
n  = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141
z1 = 0x4b1c...   # хэш сообщения 1
z2 = 0x9f3a...   # хэш сообщения 2
r  = 0x2d5e...   # одинаковый r!
s1 = 0x71ab...
s2 = 0xc3f0...

k = (z1 - z2) * pow(s1 - s2, -1, n) % n
d = (s1 * k - z1) * pow(r, -1, n) % n
print("k =", hex(k))
print("private key d =", hex(d))
# проверка: подписать новое сообщение и убедиться, что подпись валидна
```

Даже если `r` не полностью совпадает, а лишь несколько младших битов `k` известны — работает **HNP** (hidden number problem): строится решётка, и LLL находит `d`.

## Скалярное умножение: реализация double-and-add

```python
def add(P, Q, a, p):
    if P is None: return Q
    if Q is None: return P
    x1, y1 = P; x2, y2 = Q
    if x1 == x2 and (y1 + y2) % p == 0:
        return None
    if P == Q:
        lam = (3*x1*x1 + a) * pow(2*y1, -1, p) % p
    else:
        lam = (y2 - y1) * pow(x2 - x1, -1, p) % p
    x3 = (lam*lam - x1 - x2) % p
    y3 = (lam*(x1 - x3) - y1) % p
    return (x3, y3)

def mul(k, P, a, p):
    R = None
    while k:
        if k & 1: R = add(R, P, a, p)
        P = add(P, P, a, p)
        k >>= 1
    return R
```

Уязвимость **timing side-channel**: наивный double-and-add ветвится по битам `k` (`if k & 1`), и время выполнения зависит от секрета. Атака по времени восстанавливает `k` побитово. Защита — **constant-time** лестница Монтгомери и скалярное умножение без ветвлений. Это реальный класс атак на смарт-карты и HSM.

## Спаривания и MOV-атака

Для некоторых кривых существует **спаривание** (pairing) `e: G1 × G2 → GT`, которое переводит ECDLP в кривой в DLP в конечном поле `GT`. Если степень вложения мала, MOV-атака (Menezes–Okamoto–Vanstone) переносит задачу в `F_{p^k}`, где индексный метод решает её быстрее. Поэтому «кривые с малой степенью вложения» небезопасны — CTF-задачи иногда дают именно такие. Признак: нестандартная кривая, у которой порядок группы делит `p^k − 1` для маленького `k` (обычно k ≤ 6).

## Частые ошибки

- **Повтор nonce `k`.** Фатально; самое частое.
- **Не проверять точку на кривой.** invalid-curve.
- **Использовать кривые с гладким порядком.** Полиг–Хеллман.
- **Полагаться на «слабый» генератор `k`.** Даже частичная утечка → HNP.
- **Путать `p` (модуль поля) и `n` (порядок точки).** Разные числа.
- **Считать, что «ECC = всегда безопасно».** Всё зависит от параметров и реализации.

## Как не застрять

- **Ищите два `r` с одинаковым значением** — nonce reuse.
- **Факторизуйте порядок кривой `n`.** Гладкое → Полиг–Хеллман.
- **Проверьте валидацию точки.** Нет проверки → invalid-curve/twist.
- **Смотрите на генерацию `k`.** Утечка битов → решётки.
- **Используйте Sage** для ECDLP — он автоматически выбирает метод.
- **Сверяйте параметры с известными кривыми** (P-256, secp256k1).
- **Проверьте степень вложения.** Малая → MOV-атака.
- **Помните про timing.** Наивное скалярное умножение течёт по времени.

## Где пригодится

- **CTF** — ECC-задачи, ECDSA nonce reuse, invalid-curve.
- **Крипто-кошельки** — реальные кражи из-за nonce reuse (Sony PS3, блокчейн).
- **TLS/SSH** — ECDHE, ECDSA; аудит параметров.
- **Крипто-разработка** — выбор кривых и валидация точек.
- **Пост-квантовая** — переход от ECC к решёткам (см. `crypto-lattice`).
