## Зачем это нужно

`crypto-block-analysis` даёт дифференциальный и линейный криптоанализ. Интегральный (он же Square) метод — третий классический инструмент, и он особенно красив: вместо вероятностных характеристик он использует **точное** свойство суммы по множеству входов. Для AES это свойство держится 3 раунда, и его расширяют до 4, восстанавливая последний раундовый ключ. Именно так ломают редуцированные AES и самодельные SPN-шифры на CTF, где полный AES заменён на 3-4 раунда ради решаемости.

Интегральный криптоанализ был предложен против AES (Square) в 1997 году — практически одновременно с публикацией AES. Он не ломает полный AES (10/12/14 раундов), но отлично работает на редуцированных версиях и на учебных шифрах.

## Модель SPN и активные байты

Блочный шифр представляют как **SPN** (substitution-permutation network): раунд = нелинейная замена (S-box) + линейное перемешивание (сдвиги/перестановки) + сложение с ключом. AES — это SPN с 16 байтами состояния в матрице 4×4.

Интегральный анализ работает с **множеством** входов (обычно 256 значений) и отслеживает состояние каждого байта:

- **A (Active)** — байт пробегает все 256 значений ровно по разу.
- **C (Constant)** — байт одинаков во всех входах.
- **B (Balanced)** — сумма всех 256 значений байта равна нулю (XOR-сумма), но байт не обязательно активен.
- **S (Sum)** — конкретное значение суммы.

Продвижение по раундам — это таблица состояний. Для AES-подобной структуры:

| Раунд | Состояние байтов |
|-------|------------------|
| 0 (вход) | 1 активный байт, 15 констант |
| 1 (после S и ShiftRows) | 1 активный, затем расширение |
| 2 (после MixColumns) | 4 активных байта |
| 3 | все 16 байт активны |
| 4 (после S) | все 16 байт **сбалансированы** (B) |

Ключевое свойство: после 3 полных раундов **XOR-сумма по всем 256 входам каждого из 16 байт состояния равна нулю**. Это свойство не вероятностное, а детерминированное — отсюда сила метода.

## Как атаковать: восстановление последнего раундового ключа

Свойство балансировки держится до входа в 4-й раунд. Атакующий:

1. Шифрует 256 (или больше, для статистики) выбранных входов, различающихся в одном байте.
2. Получает шифротексты **после** 4 раундов.
3. **Откатывает последний раунд** (SubBytes + ShiftRows + AddRoundKey) гипотетическим ключом.
4. Проверяет балансировку: сумма значений после отката должна быть нулём.
5. Перебирает 256 вариантов последнего байта ключа — правильный даст баланс.

Для 4-раундового AES перебор идёт по одному байту последнего раундового ключа (256 вариантов) — тривиально. Для 5 раундов приходится угадывать больше байт, и сложность растёт экспоненциально, что и защищает полный AES.

```python
# Псевдокод атаки на 4-раундовый AES: проверка байта последнего ключа
def integral_attack(encrypt_4r, position=0):
    for k in range(256):
        total = 0
        for x in range(256):
            pt = bytearray(16); pt[position] = x
            ct = encrypt_4r(bytes(pt))
            # откат последнего раунда для байта position гипотетическим k
            inv = inv_subbytes(ct[position] ^ k)
            total ^= inv
        if total == 0:
            return k          # кандидат правильного байта ключа
    return None
```

Для одного активного байта и одного байта ключа кандидатов может быть несколько (ложные срабатывания), поэтому используют несколько разных активных байтов и пересечение кандидатов.

Пример построения множества:

```python
import pyaes
def make_delta_set(pos=0):
    return [bytes([ (x if i==pos else 0) for i in range(16)]) for x in range(256)]
print(len(make_delta_set(0)))   # 256
```

## Разобранный пример: самодельный SPN на 3 раунда

Пусть шифр `E` — 3 раунда: `S` (побайтовый S-box), `P` (перестановка), `AddKey`. Известно свойство: сумма по delta-множеству на выходе — ноль. Восстановим ключ последнего раунда.

Шаги:

1. Строим delta-множество: один активный байт на входе.
2. Шифруем все 256, получаем выходы.
3. Для каждого байта выхода и каждого гипотетического байта ключа `k`: откатываем `AddKey` (`c ^ k`), затем `S^{-1}`; суммируем.
4. Правильный `k` даёт сумму 0.

```python
def recover_round_key(enc, sbox_inv):
    delta = [bytes([x if i==0 else 0 for i in range(16)]) for x in range(256)]
    cts = [enc(pt) for pt in delta]
    key = bytearray(16)
    for pos in range(16):
        for k in range(256):
            s = 0
            for ct in cts:
                s ^= sbox_inv[ct[pos] ^ k]
            if s == 0:
                key[pos] = k
                break
    return bytes(key)
```

На учебном шифре это восстанавливает весь последний раундовый ключ, а из него (обратным key schedule) — мастер-ключ.

## Атаки на самодельные шифры и расширения

- **Высокопорядковые интегралы** — для шифров, где 1-байтовое delta-множество не даёт баланса, используют суммы более высоких порядков (по 2-3 байтам), что «продлевает» свойство на раунд.
- **Интеграл + дифференциал** — комбинируют методы (integral-differential), чтобы добрать раунды.
- **Применение к другим шифрам** — Square-подход работает на AES-подобных (Square, Khazad, SHARK), а также на Feistel с подходящими свойствами.
- **Интеграл на 6 раундов AES** — существуют расширения до 6 раундов с дополнительной сложностью (2^32 и выше), что уже вне CTF-масштаба.

## Почему метод называется Square и немного истории

Интегральный криптоанализ был опубликован в 1997 году группой авторов (Daemen, Knudsen, Rijmen) как атака на шифр Square — предшественник AES, разработанный той же командой. Отсюда второе название — Square-атака. Когда Square превратился в AES, метод естественно перенёсся на него: структура SPN с побайтовым S-box и линейным перемешиванием сохранилась. Исторически интегральный анализ стал одним из трёх «классических» методов (наряду с дифференциальным и линейным), и его часто преподают именно на AES, потому что свойство балансировки там видно «в чистом виде» и не требует сложной вероятностной бухгалтерии.

Важно понимать разницу в философии. Дифференциальный анализ отслеживает **разности** между парами и оперирует вероятностями: характеристика «держится с вероятностью p», и для успеха нужно много пар. Линейный анализ ищет линейные приближения с ненулевым смещением. Интегральный же метод отслеживает **сумму по целому множеству** входов и опирается на точное, а не вероятностное свойство: XOR всех значений сбалансированного байта равен нулю **всегда**, при любой ключевой добавке. Именно эта детерминированность делает интеграл удобным учебным примером и мощным практическим инструментом для редуцированных шифров.

Ещё одна причина популярности: интегральные свойства хорошо комбинируются с другими методами. Если чистого интеграла не хватает на лишний раунд, его объединяют с дифференциальными или алгебраическими приёмами, получая так называемые integral-differential атаки. В CTF это редко нужно (там шифры урезаны до 3-4 раундов), но в реальном криптоанализе такие гибриды встречаются.

## Интегралы высоких порядков в деталях

Когда одного активного байта не хватает, чтобы «дотянуть» свойство до нужного раунда, используют delta-множества большего порядка. Идея проста: если взять множество, в котором **два** байта активны (каждый пробегает 256 значений независимо), то это `2^16` входов, и свойство балансировки продлевается на дополнительный раунд. Формально интеграл порядка `d` — это сумма по `d`-мерному дельта-множеству, и каждый дополнительный порядок «стоит» множителя `256` во входных данных, но даёт лишний раунд покрытия.

На практике это выглядит так: для 4-раундового AES достаточно 1-байтового дельта-множества (256 входов). Для 5 раундов берут 2-байтовое (`2^16` входов) или применяют частичные суммы. Для 6 раундов — ещё больше. Экспоненциальный рост стоимости и есть причина, по которой полный AES (10 раундов) интегралом не берётся: потребовалось бы `2^32`+ входов и огромная память. Но на CTF шифры редуцированы, и интеграл — идеальный выбор.

Отдельная тонкость — **частичные суммы** (partial sums). Вместо того чтобы реально шифровать `2^16` входов, можно группировать вычисления и отбрасывать «неинтересные» биты по мере продвижения, экономя память. Это стандартный приём в реальных интегральных атаках, но для понимания достаточно знать, что свойство балансировки работает на множествах любого порядка, а порядок выбирается по числу раундов, которые нужно покрыть.

## Частые ошибки и подводные камни

- **Путать B и A**: сбалансированный байт (сумма 0) — не то же самое, что активный (все значения по разу).
- **Забыть про ShiftRows/MixColumns** при откате: порядок операций важен, ошибочный откат ломает баланс.
- **Мало входов**: свойство точное, но при неверной реализации или шуме нужен запас (несколько delta-множеств).
- **Ложные кандидаты ключа**: один байт может дать несколько `k` с суммой 0 — нужен перебор по нескольким активным позициям.
- **Пытаться сломать полный AES**: 10 раундов интегралом не берутся; это инструмент для редуцированных версий.

## Что дальше / решение

Интегральный анализ — база для `crypto-differential-linear` (другой класс) и для понимания, почему полный AES считается стойким. На CTF сначала определите число раундов шифра: если их 3-4, интеграл почти наверняка сработает. Держите под рукой шаблон `recover_round_key` и не забывайте про порядок отката раунда.
