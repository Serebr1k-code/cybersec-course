## Вопрос, с которого всё начинается

Мы знаем, что ECB — плохой режим, потому что одинаковые блоки дают одинаковый шифротекст. Но насколько плохой? Вопрос новичка: «Что реально можно сделать, если у меня есть только оракул шифрования и я не знаю ключ?» Оказывается, можно вытащить **весь секрет** — побайтово. Покажем это на живом оракуле.

## Наш пример

Есть сервис, который берёт наш ввод, приклеивает к нему секрет и шифрует всё в режиме ECB фиксированным ключом:

```python
def oracle(user_input):
    return AES_ECB_encrypt(pad(user_input + SECRET, 16))
```

Ключа мы не знаем, `SECRET` тоже. Единственное, что нам доступно, — ответы этой функции. Прогоним атаку и восстановим `SECRET` целиком.

## Шаг 1: почему ECB вообще ломается

В режиме ECB каждый 16-байтный блок шифруется независимо и **детерминированно**: одинаковый открытый блок всегда даёт одинаковый шифротекст. Значит, оракул шифрования превращается в **оракул сравнения**: если наш входной блок совпал с блоком, где «сидит» секрет, шифротексты этих блоков совпадут. Управляя выравниванием, мы по одному байту ставим неизвестный байт в конец блока, где остальные 15 байт нам известны, и перебираем 256 значений.

## Шаг 2: определяем размер блока и что это ECB

Сначала найдём размер блока: увеличиваем ввод и смотрим, когда длина шифротекста «прыгнет». Прыжок происходит, когда мы заполнили блок и следующий байт заставляет шифр добавить новый:

```python
def find_block_size(oracle):
    base = len(oracle(b""))
    for i in range(1, 64):
        if len(oracle(b"A"*i)) > base:
            return len(oracle(b"A"*i)) - base
```

Проверим заодно, что режим действительно ECB: подадим 32 одинаковых байта и посмотрим, есть ли два одинаковых блока.

```python
bs = find_block_size(oracle)
ct = oracle(b"A"*32)
blocks = [ct[i:i+bs] for i in range(0, len(ct), bs)]
print(bs, len(blocks) != len(set(blocks)))
```

```
16 True
```

Размер блока `16`, и ECB подтверждён (два одинаковых блока). Если бы это был CBC/CTR, атака не сработала бы.

## Шаг 3: атака побайтово

Теперь восстанавливаем секрет слева направо. Для очередного байта:

1. Шлём `b"A" * (bs - 1 - len(secret) % bs)` — это сдвигает целевой байт секрета на **последнюю позицию** блока, остальные 15 байт которого нам известны.
2. Запоминаем шифротекст этого блока (эталон).
3. Перебираем все 256 значений `guess`: шлём `prefix + secret + guess` и сравниваем тот же блок.
4. Совпал — значит, `guess` и есть следующий байт.

```python
def attack(oracle, bs):
    secret = b""
    for _ in range(1000):
        pad_len = bs - 1 - (len(secret) % bs)
        prefix = b"A" * pad_len
        bidx = (pad_len + len(secret)) // bs
        target = oracle(prefix)[bidx*bs:(bidx+1)*bs]
        found = None
        for g in range(256):
            if oracle(prefix + secret + bytes([g]))[bidx*bs:(bidx+1)*bs] == target:
                found = g; break
        if found is None:
            break
        secret += bytes([found])
    return secret
```

## Шаг 4: полный прогон

Запускаем против оракула:

```python
raw = attack(oracle, bs)
print(raw)
```

```
b'KubSTU{ecb_byte_at_a_time}\x01'
```

Секрет восстановлен! Обратите внимание на `\x01` в конце — это **padding** (PKCS#7): когда мы добили последний блок до 32 байт одной буквой `A`, padding стал ровно один байт. Атака честно дошла до конца секрета и «подцепила» этот байт; на следующей итерации совпадений уже нет, и цикл останавливается. Отделите padding — и получите `KubSTU{ecb_byte_at_a_time}`. Цена: около `256 × len(secret)` запросов к оракулу. И это принципиально: **атака не требует ни ключа, ни знания секрета** — только детерминированного ECB и возможности управлять частью ввода. Любая схема `encrypt(user_input + secret)` в ECB уязвима ровно так же.

## Шаг 5: неизвестный префикс (Cryptopals 14)

Иногда оракул добавляет **неизвестный префикс**: `AES_ECB(prefix + input + secret)`. Тогда блоки сдвинуты, и простое сравнение промахнётся. Решение — сначала вычислить длину префикса, а потом выровнять секрет по границе блока:

1. Шлём `b"A"*n` и ищем `n`, при котором два соседних блока станут одинаковыми — это точка выравнивания.
2. Из неё получаем `prefix_len` и добавляем «добивку» `offset = (bs - prefix_len % bs) % bs`, чтобы секрет начинался на границе.
3. В атаке индекс блока считаем как `(prefix_len + offset + pad_len + len(secret)) // bs`.

После этого работает тот же цикл, что и в шаге 3 — меняется только вычисление `bidx`.

## Шаг 6: как не застрять

Сначала **подтвердите ECB**: 32 буквы `A` должны дать два одинаковых блока, иначе режим другой и атака неприменима. Найдите размер блока — без него индекс блока считается неверно. Помните, что секрет может заканчиваться **padding**: когда перебор не находит совпадения, это нормальный конец, а не ошибка. Сравнивайте **сырые байты**, а не hex-строки. И проверьте, что оракул **детерминирован**: если сервер подмешивает случайный nonce или timestamp, блоки перестанут совпадать, и атаку нужно сначала «очистить». 256 запросов на байт — нормально, но не забивайте сервер и не триггерьте rate-limit.

## Где ещё встречается эта идея

Атака не ограничивается учебным оракулом. Всюду, где приложение шифрует `что-то_пользователя + секрет` в ECB, работает тот же приём. Классика веб-пентеста — зашифрованный cookie вида `AES_ECB(user_id + ";role=guest")`: выравнивая свой ввод, можно вытащить секретные поля или подставить нужные. Отдельно стоит знать **ECB-penguin**: если зашифровать картинку с большими однотонными областями, на ней проступают контуры — визуальное доказательство детерминизма ECB. И обратное: если режим CTR/OFB/CFB, где каждый блок зависит от счётчика или предыдущего состояния, побайтовая атака **не работает** — блоки не совпадают между запросами. Поэтому первый шаг всегда один и тот же: подтвердить ECB двумя одинаковыми блоками.

## Ключевая идея, которую стоит запомнить

Вся атака держится на одном факте: **ECB — это шифрование без состояния**, и одинаковый вход всегда даёт одинаковый выход. Именно поэтому оракул шифрования становится оракулом сравнения, а мы восстанавливаем секрет без ключа. Любой режим, где блок зависит от позиции (CTR, CBC, CFB, OFB), это свойство ломает — и побайтовая атака перестаёт работать. Поэтому в реальных системах ECB не применяют для данных, а для детекции ECB-режима достаточно 32 одинаковых байт.

## Что мы теперь знаем

- ECB **детерминирован**: одинаковые блоки → одинаковый шифротекст, значит оракул становится оракулом сравнения.
- Размер блока находят по «прыжку» длины шифротекста.
- **Byte-at-a-time**: выравниваем неизвестный байт в конец блока и перебираем 256 значений.
- Секрет заканчивается **padding**; отсутствие совпадения — признак конца.
- Неизвестный **префикс** обрабатывается вычислением его длины и сдвигом индекса блока.
