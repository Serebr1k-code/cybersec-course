## Постановка задачи

Есть **оракул** — функция, которая берёт наш ввод, склеивает его с секретом и шифрует в режиме ECB фиксированным ключом:

```python
def oracle(user_input: bytes) -> bytes:
    return AES_ECB_encrypt(prefix + user_input + SECRET + suffix)
```

Мы не знаем `SECRET`, но знаем, что используется ECB. Цель — восстановить `SECRET` **побайтово**, используя только этот оракул (chosen-plaintext attack). Никакого доступа к ключу у нас нет и не будет.

Почему это вообще возможно: в ECB одинаковые 16-байтные блоки дают одинаковый шифротекст. Если мы выровняем неизвестный байт так, чтобы он попал в блок вместе с полностью известным нам текстом, то сможем перебрать все 256 вариантов этого байта, зашифровать каждый и сравнить блоки с «эталоном». Совпадение блока = угадали байт.

Это одна из самых красивых атак в криптографии: **оракул шифрования превращается в оракул сравнения**, потому что ECB детерминирован.

## Интуиция: почему работает

Представьте блок из 16 байт, где 15 байт нам известны, а 16-й — неизвестный байт секрета. Мы формируем **свой** блок, где 15 известных байт совпадают, а на 16-й позиции перебираем `guess`. Если `guess` совпал с настоящим байтом секрета, наш входной блок побайтово равен блоку, в котором «сидел» секрет, — а значит, их шифротексты совпадут (ECB детерминирован). Мы «сдвигаем» секрет по одному байту за раз, используя уже восстановленный префикс как известную часть.

## Базовая атака (без префикса)

Пусть `SECRET` неизвестен. Алгоритм восстанавливает его слева направо, по одному байту.

**Шаг для байта с индексом `i` (начиная с 0):**

1. Отправляем `"A" * (block_size - 1 - i % block_size)`. Это сдвигает целевой байт секрета на **последнюю позицию** некоторого блока, а остальные байты этого блока мы знаем (наши `A` + уже восстановленный префикс секрета).
2. Запоминаем шифротекст «эталонного» блока.
3. Перебираем все 256 значений `guess`: отправляем `"A" * pad + known_prefix + guess` и сравниваем блок.
4. Если блок совпал с эталоном — `guess` и есть следующий байт секрета.

```python
def attack_ecb(oracle, block_size=16, secret_len=None):
    secret = b""
    for i in range(1000):
        pad_len = block_size - 1 - (len(secret) % block_size)
        prefix = b"A" * pad_len
        target_block_idx = (pad_len + len(secret)) // block_size
        ct = oracle(prefix)
        target = ct[target_block_idx*block_size:(target_block_idx+1)*block_size]

        found = None
        for guess in range(256):
            trial = prefix + secret + bytes([guess])
            ct2 = oracle(trial)
            block = ct2[target_block_idx*block_size:(target_block_idx+1)*block_size]
            if block == target:
                found = guess
                break
        if found is None:
            break   # секрет закончился или добавлен padding
        secret += bytes([found])
        if secret_len and len(secret) >= secret_len:
            break
    return secret
```

**Проверка на примере:** если `SECRET = b"KubSTU{ecb_oracle}"`, атака вернёт его побайтово за ~256 × len(secret) запросов.

## Определение размера блока

Прежде чем атаковать, найдите `block_size` — его подскажет «прыжок» длины шифротекста:

```python
def find_block_size(oracle):
    base = len(oracle(b""))
    for i in range(1, 64):
        if len(oracle(b"A"*i)) > base:
            return len(oracle(b"A"*i)) - base
    return None
```

Идея: увеличиваем ввод на один байт и смотрим длину. Когда мы полностью заполним последний блок, следующий байт заставит шифр добавить новый блок — длина «прыгнет» ровно на `block_size`. Обычно это 16.

## Неизвестный префикс (Cryptopals 14)

Часто оракул добавляет **неизвестный префикс** перед нашим вводом: `AES_ECB(prefix + input + secret)`. Тогда нужно:

1. **Найти длину префикса.** Отправляем одинаковые байты (`"A"*k`) и ищем, при каком `k` два соседних блока станут равны — это даёт выравнивание.
2. **Найти длину префикса по модулю 16.** Сдвигаем ввод так, чтобы секрет начинался на границе блока.
3. **Учесть смещение** при сравнении блоков (индекс блока = `(prefix_len + pad + i) // 16`).

```python
def find_prefix_len(oracle, block_size=16):
    for n in range(block_size, 3*block_size):
        ct = oracle(b"A"*n)
        blocks = [ct[i:i+block_size] for i in range(0, len(ct), block_size)]
        for i in range(len(blocks)-1):
            if blocks[i] == blocks[i+1]:
                return i*block_size - (n - block_size)  # приблизительно
    return 0
```

Точный расчёт: если при `n` байт `A` два одинаковых блока оказались на позициях `i` и `i+1`, то длина префикса `= i*16 - (n - 16)` (округлённая до фактического значения). После этого все индексы блоков при атаке сдвигаются на `prefix_len // 16`.

Полный рабочий пример для Cryptopals 14 (обработка префикса):

```python
def attack_with_prefix(oracle, bs=16):
    plen = find_prefix_len(oracle, bs)
    # сколько байт нужно добрать, чтобы префикс выровнялся по границе блока
    offset = (bs - plen % bs) % bs
    secret = b""
    for i in range(1000):
        pad_len = bs - 1 - (len(secret) % bs)
        filler = b"A" * (offset + pad_len)
        block_idx = (plen + offset + pad_len + len(secret)) // bs
        target = oracle(filler)[block_idx*bs:(block_idx+1)*bs]
        found = None
        for guess in range(256):
            trial = filler + secret + bytes([guess])
            blk = oracle(trial)[block_idx*bs:(block_idx+1)*bs]
            if blk == target:
                found = guess; break
        if found is None: break
        secret += bytes([found])
    return secret
```

## Практический пример (Cryptopals #12)

```python
import base64
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad

key = b"0123456789abcdef"
SECRET = base64.b64decode("Um9sbGluJyBpbiBteSA1LjAKV2l0aCBteSByYWctdG9wIGRvd24gc28gbXkg"
                          "aGFpciBjYW4gYmxvdwpUaGUgZ2lubnllIGJ1dG...")

def oracle(inp):
    return AES.new(key, AES.MODE_ECB).encrypt(pad(inp + SECRET, 16))

bs = find_block_size(oracle)
print("block size:", bs)                 # 16
print("is ECB:", is_ecb(oracle(b"A"*32))) # True
secret = attack_ecb(oracle, bs)
print(secret)
```

Это в точности задача Cryptopals 12. Задача 14 добавляет префикс — используйте `find_prefix_len` и смещайте индексы.

## Обобщение: если секрет в начале или между

- **`SECRET || input`** — атака тоже работает (нужно выравнивать с начала и «двигать» секрет вправо).
- **`input || SECRET`** — базовая атака выше.
- **`prefix || input || SECRET || suffix`** — комбинируйте: сначала найдите длину префикса, потом атакуйте.
- **Секрет длиннее, чем можно вытянуть за раз** — просто продолжайте цикл; каждая новая итерация добавляет байт.
- **Секрет содержит бинарные байты** — всё нормально, алгоритм работает с байтами, а не с текстом.

## Оптимизация и подводные камни реализации

- **Кэшируйте эталонные блоки.** На каждом байте эталонный блок можно запомнить и не запрашивать повторно.
- **Секрет может заканчиваться padding.** Последний «байт» может быть `0x01`/`0x02` от PKCS#7 — не путайте: когда перебор не находит совпадения, вероятно, вы дошли до padding.
- **Учитывайте `suffix`.** Если после секрета есть суффикс, он не мешает базовой атаке, пока вы сравниваете правильный блок.
- **Ограничьте число запросов.** 256 запросов на байт × длина — это может быть заметно; не забивайте сервер и не триггерьте rate-limit.
- **Сравнивайте сырые байты, а не hex-строки.** Иначе легко «поймать» ложное совпадение по регистру.
- **Не перепутайте блоки.** Индекс блока должен учитывать и padding-префикс, и длину уже восстановленного секрета.

## Частые ошибки

- **Не подтвердили ECB.** Если 32 `A` не дают двух одинаковых блоков — это не ECB (возможно CBC/CTR), атака неприменима.
- **Не нашли размер блока.** Без него неверно вычисляется `target_block_idx`.
- **Не учли префикс** (Cryptopals 14) — сравнение идёт не с тем блоком.
- **Перепутали `len(secret)` и `i`.** Паддинг вычисляется от длины **уже восстановленного** секрета.
- **Остановились слишком рано.** Совпадение может не найтись для padding-байта — это нормальный конец.
- **Слишком длинный секрет.** Иногда задача ограничивает длину; не крутите цикл до бесконечности.

## Как не застрять

- **Сначала подтвердите ECB.** 32 `A` → два одинаковых блока. Если нет — это не ECB (см. `crypto-aes-modes`).
- **Найдите размер блока** функцией выше.
- **Найдите длину префикса** для Cryptopals 14.
- **Секрет может заканчиваться padding.** Последний «байт» может быть `0x01`/`0x02` от PKCS#7 — не путайте.
- **256 запросов на байт — нормально.** Ограничьте длину, чтобы не забить сервер.
- **Кодируйте байты правильно.** Сравнивайте сырые байты, а не hex-строки.
- **Автоматизируйте** — один скрипт решает и 12, и 14 с небольшой правкой.
- **Проверьте, что оракул детерминирован.** Если сервер добавляет случайный префикс/соль на каждый запрос, ECB-атака не сработает — сравнение блоков сломается. Убедитесь, что при одинаковом вводе вы получаете одинаковый шифротекст.
- **Держите оракул «чистым».** Иногда приложение добавляет timestamp или nonce в префикс — тогда сначала придётся вычислить их влияние, а не атаковать напрямую.
