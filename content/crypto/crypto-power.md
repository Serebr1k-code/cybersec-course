Пока алгоритм выполняется, транзисторы переключаются — и потребляют разное количество энергии в зависимости от обрабатываемых данных и ключа. Осциллограф или EM-зонд рядом с чипом снимает эту зависимость как «трассу» мощности. Это и есть power/EM side-channel: по тысячам трасс восстанавливают ключ AES, не вскрывая корпус. Эта глава — от физики утечки до работающего CPA-скрипта.

## Физика утечки

CMOS-логика потребляет энергию в основном в моменты переключения (0↔1). Ток зависит от:

- **числа переключившихся бит** (Hamming distance);
- **значения данных** (Hamming weight) в регистрах;
- **последовательности операций** (какой путь выполнения).

Если промежуточное значение алгоритма — функция открытого текста и ключа (например, `SBox(p ⊕ k)` в AES), то его Hamming weight коррелирует с мощностью в соответствующий момент. По этой корреляции ключ восстанавливают.

## SPA (Simple Power Analysis)

Простейшая атака: визуально/по форме трассы читают операции.

- **RSA квадрат-и-умножай** — умножение «длиннее» квадрата; по форме трассы читают биты экспоненты (аналог timing Кохера, но точнее).
- **AES** — видно 10 раундов (10 «горбов»); при наивной реализации видна разница операций.
- **PIN-код** — по времени/форме проверки.

SPA работает при малом числе трасс (иногда одна), но требует «чистого» сигнала и слабой реализации.

## DPA/CPA (Differential/Correlation Power Analysis)

Мощная атака: собирают `N` трасс для `N` разных открытых текстов, для каждого байта ключа проверяют **гипотезу** о промежуточном значении и коррелируют с трассой.

Алгоритм CPA на первый байт AES:

1. Собрать `N` трасс (каждая — массив отсчётов по времени) и соответствующие открытые тексты.
2. Для каждого байта `p_i` открытого текста и каждой гипотезы ключа `k ∈ 0..255`:
   `v = SBox(p_i ⊕ k)`, взять Hamming weight `HW(v)`.
3. Для каждого момента времени `t` посчитать корреляцию Пирсона между `HW(v)` (по всем трассам) и `trace[t]` (по всем трассам).
4. Ключ — гипотеза с максимальной корреляцией (пик на «правильном» `t`).

Сложность: 256 гипотез × число отсчётов × `N` трасс. Обычно достаточно 1000–5000 трасс.

```python
import numpy as np

def hamming_weight(x):
    return bin(x).count('1')

def cpa(traces, plaintexts, sbox):
    # traces: (N, T) float; plaintexts: (N,) байты
    N, T = traces.shape
    traces = traces - traces.mean(axis=0, keepdims=True)
    std_t = traces.std(axis=0) + 1e-12
    best = np.zeros(256)
    for k in range(256):
        hw = np.array([hamming_weight(sbox[p ^ k]) for p in plaintexts], dtype=float)
        hw -= hw.mean()
        std_h = hw.std() + 1e-12
        corr = (hw @ traces) / (N * std_h * std_t)   # корреляция по всем t
        best[k] = np.max(np.abs(corr))
    return int(np.argmax(best)), best
```

## Разобранный пример: AES-128 первый байт

1. Собираем 3000 трасс для случайных открытых текстов (ChipWhisperer: `cw.capture_trace()`).
2. Применяем `cpa` — получаем гипотезу `k0` с максимальной корреляцией.
3. Проверяем: пик корреляции резко выделяется на фоне остальных 255 гипотез.
4. Повторяем для остальных 15 байт первого раунда — получаем 16 байт раундового ключа `K0`.
5. Обратный key schedule AES → мастер-ключ.

Признак успеха: корреляция правильной гипотезы ~0.1–0.3 (для 3000 трасс), остальные < 0.05. Если пик размыт — увеличьте `N`, синхронизируйте трассы (alignment) и отфильтруйте шум.

## Подготовка трасс (важно!)

- **Alignment.** Трассы «плывут» по времени; перед CPA их выравнивают (cross-correlation, `scipy.signal`).
- **Фильтрация.** Убрать дрейф, отбросить «битые» трассы.
- **Точка утечки.** Ищите момент, где корреляция максимальна (обычно после S-box первого раунда).
- **Выбор модели.** Hamming weight / Hamming distance; для аппаратного AES — HD, для софтового — HW.
- **Много отсчётов.** 5000–50000 трасс типично; качество зависит от шума.

## Контрмеры

- **Hiding (скрытие):**
  - постоянный ток/шум (random precharge, dual-rail);
  - рандомизация времени/порядка операций;
  - детекторы и датчики (затирание при обнаружении).
- **Masking (маскирование):** значение `v` представляется как `v ⊕ m`, где `m` — случайная маска; операции ведутся над долями. Порядок маски `d` усложняет DPA как `~N^d`.
- **Constant-time + blinding** (RSA) — комбинация с timing-контрмерами.
- **Асимметрия и алгоритмические меры:** не использовать ключ как индекс, не оставлять секрет в регистре дольше необходимого.
- **Проверка:** `dudect`, тесты на TVLA (Test Vector Leakage Assessment).

## Связь с timing и cache

- **Timing** (`crypto-timing`) — программная утечка по времени; power — физическая.
- **Cache** — утечка по обращениям к памяти (Prime+Probe, Flush+Reload); табличный AES уязвим.
- **EM** — то же, что power, но бесконтактно (зонд ловит излучение).
- **Fault injection** — родственный физический канал: сбой в вычислении (Bellcore, см. `crypto-rsa-faults`).

## Частые ошибки и тупики

- **Мало трасс.** 100–200 не хватит; нужно тысячи.
- **Нет alignment.** Смазанные пики убивают корреляцию.
- **Неверная модель утечки.** HW vs HD — выберите под реализацию.
- **Забыть про маскирование.** На защищённом чипе CPA первого порядка не работает — нужен второй порядок.
- **Игнорировать шум/дрейф.** Фильтруйте и нормируйте.
- **Путать SPA и DPA.** SPA — «по форме», DPA/CPA — «по статистике».
- **Ожидать атаку по сети.** Power/EM — только при физическом доступе к устройству.

## Что дальше (decision)

1. Есть физический доступ и осциллограф → SPA/CPA на трассах.
2. Есть ChipWhisperer → учебный AES и готовый CPA.
3. Реализация в софте, удалённый доступ → скорее timing (`crypto-timing`).
4. Аппаратный AES с маскированием → CPA второго порядка или ищите другую утечку.
5. RSA с ошибками → `crypto-rsa-faults` (Bellcore).
6. Нужна проверка стойкости → TVLA/dudect.

## Полный разбор: CPA на ChipWhisperer

Учебный пайплайн (ChipWhisperer Lite + встроенный AES):

```python
import chipwhisperer as cw
scope = cw.scope()
scope.default_setup()
target = cw.target(scope, cw.targets.SimpleSerial)

N = 5000
traces = []
texts = []
for i in range(N):
    pt = bytearray([random.randrange(256) for _ in range(16)])
    texts.append(pt)
    scope.arm()
    target.write(pt)
    ret = scope.capture()
    traces.append(scope.get_last_trace())

# CPA по первому байту
import numpy as np
T = np.array(traces); P = np.array([t[0] for t in texts])
key_guess, corr = cpa(T, P, AES_SBOX)
print("key[0] =", hex(key_guess))
```

Практические детали: выровняйте трассы (`cw.analyzer.preprocessing`), уберите DC-составляющую, увеличьте `N` до 10000 при слабом сигнале. После восстановления 16 байт `K0` — обратный AES key schedule даёт мастер-ключ. Если на устройстве включено маскирование, CPA первого порядка не сработает — понадобится CPA второго порядка (перемножение трасс с разными масками).
