## Вопрос, с которого всё начинается

Классический сюжет CTF: «флаг отправлен трём людям», у каждого свой публичный ключ, но экспонента одна — `e = 3`. По отдельности каждый шифротекст неприступен. Но три шифротекста **одного** сообщения вместе раскрывают его полностью. Разберём, почему, и соберём атаку.

## Наш пример

Возьмём сообщение и зашифруем его под тремя разными модулями с `e = 3`:

```python
from sympy import nextprime
from sympy.ntheory.modular import crt
from gmpy2 import iroot
ns = [nextprime(2**513)*nextprime(2**512) for _ in range(3)]
msg = int.from_bytes(b'Hastad!', 'big')
cs = [pow(msg, 3, n) for n in ns]
```

Три пары `(n_i, c_i)`, одно сообщение. Вопрос: как восстановить `msg`?

## Шаг 1: почему малый e опасен

Малый `e` (3, 5, 17) ускоряет шифрование, но открывает атаки. Основная идея: если `m^e < n`, то модуль **не срабатывает**, и `c = m^e` в точности — тогда `m = c^(1/e)`.

```python
m, exact = iroot(c, e)     # e = 3
if exact:
    print(m.to_bytes((m.bit_length()+7)//8, 'big'))
```

**Признак:** маленький `c`, `e = 3`, большой `n`. Условие `m^e < n` значит `m < n^(1/e)`.

## Шаг 2: Håstad broadcast через CRT

Если `m^e ≥ n`, простой корень не поможет. Но если **одно** сообщение зашифровано под `k ≥ e` разными модулями, работает китайская теорема об остатках (**CRT**). Она собирает из остатков `c1, c2, ..., ck` одно число `M = m^e mod (n1·n2·…·nk)`. Если произведение модулей `N = Π n_i` больше `m^e`, то `M` — это точное `m^e` **без модуля**, и `m = корень_e(M)`:

```python
M, N = crt(ns, cs)         # M = m^e mod (n1*n2*n3)
root, exact = iroot(M, 3)
print("exact:", exact, "msg:", int(root).to_bytes(8, 'big'))
```

```
exact: True msg: b'\x00Hastad!'
```

Сообщение восстановлено. Именно поэтому малый `e` без padding опасен: три получателя с `e = 3` ломают «секрет».

## Шаг 3: сколько нужно шифротекстов

CRT даёт точное `m^e`, только если `N = n1·n2·…·nk > m^e`. Для `e = 3` и сообщения в 200 бит `m^3 ≈ 600` бит, что меньше каждого 1024-битного `n` — хватает и трёх (и даже одного). Если сообщение длиннее (400 бит → `m^3 ≈ 1200` бит > `n`), модуль срабатывает, и нужен `k > e` шифротекстов или Coppersmith.

**Ключевая проверка:** `m^e < N`. Для `e = 3` и `n` 1024 бита это `m < 2^341` (примерно 42 байта).

## Шаг 4: когда есть padding — Coppersmith

Если у получателей **разный линейный padding** (`m_i = a_i·m + b_i`), простой корень не сработает. Тогда применяется **Coppersmith** (см. `crypto-rsa-coppersmith-deep`): строится система полиномов `(a_i·x + b_i)^e − c_i ≡ 0 mod n_i`, комбинируется по CRT в один полином mod `N`, и находится малый корень `x = m`. Это «обобщённый Håstad».

## Шаг 5: Franklin-Reiter — линейно связанные сообщения

Родственная атака: **один** модуль, но два сообщения линейно связаны `m2 = a·m1 + b`, зашифрованы с малым `e`. Тогда `gcd` двух полиномов `x^e − c1` и `(a·x+b)^e − c2` над `Z_n[x]` даёт линейный множитель, из которого находится `m1`:

```python
# Sage
R.<x> = PolynomialRing(Zmod(n))
g = (x^e - c1).gcd((a*x + b)^e - c2)
```

Отличие от Håstad простое: **Håstad — разные модули (CRT)**, Franklin-Reiter — **один модуль и линейная связь сообщений (gcd полиномов)**. Если в задаче один `n` и два связанных сообщения — это Franklin-Reiter; если несколько `n` — Håstad. Перепутать легко, поэтому первым делом смотрите, сколько модулей дано: это сразу определяет инструмент.

## Шаг 6: почему CRT даёт точное m^e

Разберём интуицию CRT. Каждый `c_i = m^e mod n_i` — это «остаток» числа `m^e` по модулю `n_i`. Китайская теорема об остатках утверждает: система остатков по **взаимно простым** модулям однозначно определяет число по модулю их произведения. Поэтому `M = m^e mod N`, где `N = n1·n2·…·nk`. Если `N` больше самого `m^e`, то «mod N» ничего не отбрасывает — `M` равно `m^e` точно. Значит, корень `e`-й степени даёт `m` без всякой неоднозначности. Именно поэтому трёх 1024-битных модулей с запасом хватает для короткого сообщения: их произведение огромно.

## Шаг 7: защита и выбор e

Правильная реализация RSA **обязана** использовать padding (OAEP). Даже при `e = 3` OAEP рандомизирует сообщение, поэтому `m^e` не имеет структуры и атаки не работают. Отсюда правила выбора `e`:

- `e = 3` — быстрый, но требует OAEP.
- `e = 65537` — стандарт: достаточно большой, чтобы избежать small-e атак, и быстрый.
- Случайный большой `e` — риск малого `d` (см. `crypto-rsa-wiener-bonedurfee`).

## Шаг 7: когда `m^e` чуть больше n

Иногда `m^e = n + x` с малым `x` — то есть `m^e` лишь немного превышает модуль. Тогда `c = m^e − n`, и остаётся найти корень от `c + n`. Обобщим: если известно, что `m^e = k·n + c` для малого `k`, перебираем `k` и проверяем точность корня:

```python
from gmpy2 import iroot
for k in range(1000):
    m, ok = iroot(c + k*n, e)
    if ok:
        print(int(m).to_bytes((int(m).bit_length()+7)//8, 'big')); break
```

Это спасает в задачах, где «просто корень» не сработал из-за одного «лишнего» модуля. Всегда проверяйте несколько малых `k`, прежде чем отказываться от атаки и уходить в Coppersmith.

## Что мы теперь знаем

- Малый `e` опасен: при `m^e < n` работает **целочисленный корень**.
- **Håstad broadcast:** одно сообщение под `k ≥ e` модулями, CRT собирает точное `m^e`.
- Условие успеха — `N = Π n_i > m^e`.
- С padding нужен **Coppersmith** (обобщённый Håstad).
- **Franklin-Reiter:** один модуль, линейная связь сообщений, gcd полиномов.
- Защита — **OAEP**; `e = 65537` — безопасный стандарт.

## На что смотреть дальше

- **Считать, что малый e всегда ломается** — только при `m^e < N` или `k ≥ e`.
- **Забыть про padding** — с ним нужен Coppersmith, а не простой корень.
- **Неверный CRT** — модули должны быть взаимно просты (обычно да).
- **Мало шифротекстов** — нужно `k ≥ e`.
- **Путать Håstad и Franklin-Reiter** — разные условия (разные модули против одного).
- **Игнорировать конвертацию в байты** — результат корня ещё нужно превратить в строку.

## Куда дальше

Мы разобрали атаки на малую экспоненту `e`. Дальше — противоположный случай: малый **приватный** ключ `d`. В уроке **crypto-rsa-wiener-bonedurfee** мы восстановим `d` цепными дробями и решётками. А пока главное: **малый `e` без padding ломается корнем или CRT; OAEP — обязателен.**
