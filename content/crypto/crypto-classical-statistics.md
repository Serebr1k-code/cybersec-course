## Вопрос, с которого всё начинается

У нас есть текст, зашифрованный Виженером, но ключ **неизвестен**. Простой частотный анализ не работает: многоалфавитный шифр сглаживает частоты. Как определить длину ключа, если мы не знаем даже её? Ответ дают **статистические методы**, разработанные ещё до компьютеров. Разберём их на конкретном шифртексте.

## Наш пример: Виженер с неизвестным ключом

У нас `cipher.txt` — текст, зашифрованный Виженером. Мы хотим найти ключ и открытый текст.

```
$ cat cipher.txt
VTVLZGIWPTKPZOVKYXWVQMPEKRSP...
```

## Шаг 1: тест Касиски

Идея Касиски: если ключ повторяется с периодом `L`, то одинаковые фрагменты открытого текста на расстоянии, кратном `L`, дадут одинаковые фрагменты шифртекста. Ищем **повторяющиеся триграммы** и смотрим расстояния между ними. Их общие делители — кандидаты на `L`.

```python
from collections import Counter
def kasiski(ct, n=3):
    pos = {}
    for i in range(len(ct) - n + 1):
        pos.setdefault(ct[i:i+n], []).append(i)
    dists = []
    for g, ps in pos.items():
        for i in range(1, len(ps)):
            dists.append(ps[i] - ps[0])
    return dists
```

## Шаг 2: индекс совпадений (IC)

Более надёжный метод — **индекс совпадений**. Он измеряет вероятность того, что две случайно взятые буквы текста совпадают:

```
IC = sum(count(c) * (count(c) - 1)) / (n * (n - 1))
```

Для английского текста IC ≈ 0.066, для случайного — ≈ 0.038. Если разбить шифртекст на `L` столбцов (буквы на позициях 0, L, 2L, ...), то при **правильной** `L` каждый столбец — это обычный сдвиг Цезаря, и его IC ≈ 0.066. При неправильной — IC ≈ 0.038. Значит, правильная длина — та, где средний IC столбцов максимален.

```python
def ic(t):
    n = len(t)
    return sum(t.count(c)*(t.count(c)-1) for c in set(t)) / (n*(n-1))
for L in range(2, 13):
    print(L, sum(ic(ct[i::L]) for i in range(L)) / L)
```

## Шаг 3: восстановление ключа

Зная `L`, разбиваем шифртекст на `L` столбцов. Каждый столбец — сдвиг Цезаря. Для каждого столбца подбираем сдвиг, при котором частоты букв после сдвига лучше всего совпадают с частотами английского языка (максимум скалярного произведения):

```python
def best_shift(col):
    return max(range(26), key=lambda k: sum(ENG[(ord(c)-65-k) % 26] for c in col))
key = ''.join(AL[best_shift(ct[i::L])] for i in range(L))
```

```
$ python3 vbreak.py
key length: 6  key: CIPHER
plaintext: THEFLAGISNTOINDEXOFCOINCIDENCEFINDSKEYLENGTH...
flag: nto{1nd3x_0f_c01nc1d3nc3_f1nds_k3y_l3ngth}
```

## Шаг 4: тест Фридмана и авточастотный анализ

**Тест Фридмана** даёт оценку длины ключа по IC всего текста:

```
L ≈ (0.027 * n) / ((n - 1) * IC - 0.038 * n + 0.065)
```

Это быстрая прикидка, когда Касиски не срабатывает (короткий текст). **Авточастотный анализ** обобщает метод на случай, когда длина ключа известна неточно: сравнивают текст с самим собой, сдвинутым на разные позиции, и по пикам находят период.

## Полный прогон от начала до конца

1. `cat cipher.txt` — шифртекст.
2. Считаем IC для длин 2..12 — находим `L=6`.
3. Разбиваем на 6 столбцов, восстанавливаем каждый сдвиг → ключ `CIPHER`.
4. Расшифровываем, получаем открытый текст.
5. `python3 vbreak.py | grep nto > found.txt`.

## Если не сработало

Если IC не даёт чёткого пика — текст слишком короткий; попробуй Касиски или тест Фридмана. Если ключ «почти верный», но буквы в нём сдвинуты — проверь **частотную таблицу языка**: для русского нужны другие частоты. Если шифр оказался не Виженером, а Бофором — формула столбца другая (`K = C + P`), и нужно перебрать обе. Для текста без пробелов и с редкими буквами (`Q`, `Z`) статистика слабее — используй биграммы.

## Биграммный анализ и crib-dragging

Индекс совпадений и частоты отдельных букв — не единственные инструменты. **Биграммный анализ** смотрит на пары букв: в английском `TH`, `HE`, `IN`, `ER` встречаются чаще всего. Для Виженера с коротким ключом биграммы помогают уточнить ключ, когда частоты букв «шумят». **Crib-dragging** — приём для случая, когда известен предполагаемый фрагмент открытого текста (например, `FLAG{` или `THE`). Его «протаскивают» по всем позициям, вычисляют соответствующий фрагмент ключа и смотрят, складывается ли ключ в осмысленное слово.

```python
def crib_drag(ct, crib):
    for i in range(len(ct) - len(crib) + 1):
        ks = ''.join(AL[(ord(ct[i+j]) - ord(crib[j])) % 26] for j in range(len(crib)))
        print(i, ks)
```

Если на какой-то позиции ключевой фрагмент повторяется или образует слово — crib угадан. Этот приём работает и против running-key, и против many-time pad.

## Применение к другим шифрам

Статистика Касиски и IC — не только про Виженера. Тот же индекс совпадений отличает **сжатый** текст (высокий IC из-за повторов) от **зашифрованного** (IC ≈ 0.038). Тест Фридмана применяют к любым шифрам с периодическим ключом: Autokey, Бофор, Гронсфельд. А авточастотный анализ лежит в основе современных атак на потоковые шифры с повторяющимся состоянием. Освоив эти методы на классике, ты будешь узнавать их в более сложных схемах.

## Пример: определяем длину ключа вручную

Разберём маленький пример, чтобы метод не остался абстрактным. Возьмём шифртекст `VTVLZ...` и посчитаем IC для длин 2, 3, 4. Для `L=2` получаем два столбца, в каждом перемешаны несколько сдвигов — IC около 0.04. Для `L=3` — около 0.043. Для `L=6` — 0.067, заметно выше. Именно скачок до 0.067 и есть сигнал: длина ключа равна 6.

Теперь восстановим ключ. Разобьём текст на 6 столбцов. В первом столбце (позиции 0, 6, 12, ...) буквы — это открытый текст, сдвинутый на первую букву ключа. Сравним частоты столбца с английскими: максимум корреляции даёт сдвиг `C`. Повторяем для остальных столбцов и получаем `CIPHER`. Ключевое наблюдение: **мы не перебирали ключ** — мы вычислили его по одной букве за раз, независимо для каждого столбца.

## Оценка надёжности и ограничения

Статистический взлом Виженера работает тем лучше, чем длиннее текст. Практические ориентиры: при длине ключа `L` и тексте `N` символов на столбец приходится `N/L` букв. Для надёжного восстановления сдвига нужно хотя бы 30–50 букв в столбце, то есть `N ≳ 40L`. Если текст короче, IC «шумный» и длина ключа определяется неуверенно — тогда помогают Касиски (если есть повторы) и crib-dragging (если известен фрагмент открытого текста).

Ещё ограничение — **алфавит**. Мы считали частоты латинского алфавита без пробелов. Если текст содержит пробелы и знаки, их либо удаляют (как делали классические шифры), либо расширяют алфавит до 27+ символов и меняют таблицу частот. Для русского языка нужна отдельная таблица частот (`О` — самая частая буква). Универсальное правило: **сначала определи алфавит, потом строй статистику под него.**

## Что мы теперь знаем

- Касиски ищет повторяющиеся фрагменты и их расстояния.
- IC ≈ 0.066 для языка, ≈ 0.038 для случайного текста.
- Правильная длина ключа максимизирует средний IC столбцов.
- Столбец = сдвиг Цезаря; ключ восстанавливается частотным анализом.
- Тест Фридмана даёт быструю оценку длины.
