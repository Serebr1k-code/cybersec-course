## Вопрос, с которого всё начинается

Все подстановки, которые ты видел, имеют одну общую слабость: **каждая буква открытого текста превращается в одну конкретную букву шифртекста**. Значит, частоты букв сохраняются, и частотный анализ работает. Возникает вопрос: можно ли шифровать так, чтобы буква открытого текста влияла на несколько букв шифртекста? Да — с помощью **дробящих** (fractionating) шифров. Разберём их на конкретном примере.

## Наш пример: шифр Бифид

У нас есть текст, зашифрованный шифром **Бифид** (`cipher.txt`), и квадрат Полибия (`square.txt`). Мы хотим восстановить открытый текст и найти спрятанный в нём флаг.

```
$ cat square.txt
A B C D E
F G H I K
L M N O P
Q R S T U
V W X Y Z
```

Квадрат 5x5, где I и J объединены (потому что в латинском алфавите 26 букв, а клеток 25). Каждая буква получает **координату** — пару (строка, столбец), числа от 0 до 4.

## Шаг 1: координаты вместо букв

Заменим каждую букву открытого текста её координатой. Слово `MEET` превращается в поток пар:

```
M -> (1,1)   E -> (0,4)   E -> (0,4)   T -> (3,3)
```

Если просто склеить координаты и заменить их на буквы, получится обычная подстановка — слабость сохранится. Фокус Бифида в том, что делают **дальше**.

## Шаг 2: смешивание строк и столбцов

Бифид записывает сначала **все строки** координат, потом **все столбцы**. Для `MEET`:

```
строки:   1 0 0 3
столбцы:  1 4 4 3
поток:    1 0 0 3 1 4 4 3
```

Теперь поток разбивают заново на пары и каждую пару читают как координату:

```
(1,0)->G   (0,3)->D   (1,4)->K   (4,3)->T
```

Итог шифртекста — `GDKT`. Обрати внимание: каждая буква шифртекста зависит от **двух разных** букв открытого текста. Частоты сглаживаются, и простая подстановка ломается.

## Шаг 3: расшифровка

Расшифровка — та же операция в обратную сторону. Из шифртекста берём координаты и пишем их **подряд**:

```
GDKT -> (1,0)(0,3)(1,4)(4,3) -> 1 0 0 3 1 4 4 3
```

Этот поток делим пополам. Первая половина — строки, вторая — столбцы:

```
строки:   1 0 0 3
столбцы:  1 4 4 3
```

Собираем пары и получаем буквы. Всё. В нашем примере:

```
$ python3 bifid.py
plaintext: MEETMEATTHEBRIDGETHEFLAGISNTOBIFIDSPLITSROWSANDCOLS
flag: nto{b1f1d_spl1ts_r0ws_4nd_c0ls}
```

Флаг прямо в открытом тексте — мы восстановили его, зная только квадрат, то есть «алгоритм», а не секретный ключ в привычном смысле.

## Шаг 4: Трифид и ADFGX

Бифид работает с координатами из **двух** чисел. **Трифид** использует куб 3x3x3 (27 ячеек: 26 букв + точка) и координаты из трёх чисел — поток ещё сильнее перемешивается. Есть и «гибридные» схемы: **ADFGX** кодирует буквы парами из пяти букв A/D/F/G/X (квадрат Полибия), а затем **транспонирует** результат колонками. **ADFGVX** добавляет шестой символ V, чтобы включить цифры и получить квадрат 6x6. Именно ADFGVX использовала германская армия в Первой мировой.

## Полный прогон от начала до конца

1. `cat square.txt cipher.txt` — видим квадрат и шифртекст.
2. Мысленно или скриптом превращаем шифртекст в поток координат.
3. Делим поток пополам, собираем пары, читаем буквы.
4. `python3 bifid.py` — скрипт делает всё автоматически и печатает открытый текст.
5. `python3 bifid.py | grep nto > found.txt` — сохраняем флаг.

## Если не сработало

Если открытый текст «мусорный», проверь два момента. Первое — **чётность**: если длина шифртекста нечётная, поток координат не делится пополам; обычно это признак, что где-то потерян символ. Второе — **версия квадрата**: некоторые реализации используют квадрат 6x6 с цифрами (тогда координаты от 0 до 5). И помни про I/J: если в тексте есть J, её сначала заменяют на I. Для Трифида типичная ошибка — неправильный порядок трёх координат (например, сначала столбцы, потом строки).

## Ключевой квадрат и его роль

До сих пор мы считали квадрат Полибия **фиксированным** (`ABCDE / FGHIK / ...`). Но квадрат можно переставлять по ключевому слову — тогда он становится секретом. Например, ключ `SECRET` даёт начало алфавита `SECRTA...` (повторяющиеся буквы пропускаются), и все координаты меняются. Такой «ключевой квадрат» превращает Бифид из простого упражнения в настоящий шифр с ключом: без знания квадрата расшифровать нельзя.

На CTF ключевой квадрат часто дают **частично**: показывают первые строки или оставляют подсказку. Тогда задача сводится к восстановлению оставшихся букв по известному фрагменту открытого текста (crib). Это типичная «крипто-дедукция»: ты знаешь, что в тексте есть слово `FLAG` или `THE`, и подбираешь позиции букв в квадрате, чтобы координаты сходились.

## Пишем Бифид сами

Разберём реализацию по шагам, чтобы ты мог расшифровать любой вариант. Сначала квадрат и обратная таблица координат:

```python
sq = 'ABCDEFGHIKLMNOPQRSTUVWXYZ'          # 25 букв, без J
inv = {c: (i // 5, i % 5) for i, c in enumerate(sq)}
```

Теперь расшифровка: превращаем шифртекст в поток цифр, делим пополам, собираем пары.

```python
ct = open('cipher.txt').read().split()[0]
seq = []
for c in ct:
    seq += list(inv[c])          # [row, col] подряд
n = len(ct)
rows, cols = seq[:n], seq[n:]    # первая половина — строки, вторая — столбцы
pt = ''.join(sq[r * 5 + c] for r, c in zip(rows, cols))
print(pt)
```

Ключевая деталь — **порядок половин**. Если поменять их местами, получится другой (неверный) текст. Именно на этом чаще всего спотыкаются: в некоторых учебниках сначала идут столбцы, потом строки. Определить правильный порядок можно так: расшифруй обоими способами и посмотри, где текст осмысленный.

## Как распознать Бифид по шифртексту

Дробящие шифры оставляют характерный след. Во-первых, **частоты сглажены**: пик самой частой буквы заметно ниже, чем в обычном языке (для английского ожидается ~12% на `E`, а тут может быть 7–8%). Во-вторых, **нет явных биграмм**: пары вроде `TH`, `HE`, `THE` не выделяются. В-третьих, длина текста обычно совпадает с длиной открытого текста (без пробелов), потому что дробящий шифр не расширяет сообщение — он лишь переставляет координаты. Если видишь всё это вместе и в задании упомянут «квадрат» или «Полибий» — почти наверняка Бифид.

## Сравнение: подстановка, дробящий, транспозиция

| Свойство | Подстановка | Дробящий (Бифид) | Транспозиция |
|---|---|---|---|
| Частоты букв | сохранены | сглажены | сохранены |
| Длина текста | равна | равна | равна |
| Зависимость буквы шифртекста | от 1 буквы | от 2+ букв | от 1 буквы (другой позиции) |
| Тип атаки | частотный анализ | перебор/структура | анаграммирование |

Эта таблица — твой быстрый тест. Если частоты «плоские» — дробящий или многоалфавитный. Если частоты на месте, но текст нечитаем — транспозиция. Если есть пик частот и текст нечитаем — подстановка.

## Трифид и ADFGVX детальнее

Трифид использует куб 3×3×3 (27 ячеек: 26 букв и точка). Каждая буква получает три координаты `(x, y, z)` в диапазоне 0–2. Поток координат записывают как **три строки** подряд (все x, потом все y, потом все z), затем перегруппировывают по три. Так одна буква шифртекста зависит уже от трёх букв открытого текста — сглаживание сильнее, чем у Бифида.

ADFGVX устроен иначе: сначала буква кодируется парой из шести символов (квадрат 6×6, включает цифры), затем весь поток символов **транспонируется** по ключу. Здесь объединены два разных механизма — подстановка и перестановка — и это делает шифр заметно крепче для ручного взлома.

## Что мы теперь знаем

- Квадрат Полибия превращает букву в пару координат.
- Дробящий шифр **смешивает** координаты, поэтому одна буква шифртекста зависит от нескольких букв открытого текста.
- Бифид: все строки, потом все столбцы; расшифровка — обратная операция.
- Трифид — трёхмерный вариант; ADFGX/ADFGVX — Полибий + транспозиция.
- I/J объединяются в 5x5, а цифры требуют 6x6.
