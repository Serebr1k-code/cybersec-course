## Зачем крипто-задачам кодировки

Кодировки — это фундамент. Почти каждая crypto-задача начинается с того, что зашифрованный или закодированный артефакт представлен в текстовом виде. Прежде чем применить атаку на RSA или AES, нужно **превратить строку в байты**. Если вы ошибётесь на этом шаге, дальше всё развалится: `pow(c, d, n)` с неправильно декодированным `c` даст мусор.

Важно: кодирование **не является шифрованием**. Оно не даёт секретности — любой может раскодировать. На CTF кодировки используют как «упаковку», как первый слой многослойной головоломки или как маскировку, чтобы данные выглядели невинно. Разработчики применяют их для передачи бинарных данных через текстовые каналы (email, JSON, URL, cookies).

Главный навык — **распознавание по алфавиту**: по набору символов и выравниванию почти всегда видно, какая это кодировка.

## Base16 (hex) — самый простой

**Алфавит:** `0-9a-f` (или `0-9A-F`). Каждый байт = ровно 2 символа, поэтому длина всегда чётная.

```python
>>> bytes.fromhex("48656c6c6f")
b'Hello'
>>> "Hello".hex()
'48656c6c6f'
```

**Распознавание:** только символы `0-9a-fA-F`, чётная длина. Часто с префиксом `0x` или суффиксом. В дампах (`xxd`, `hexdump`) hex идёт колонками.

```bash
$ echo 48656c6c6f | xxd -r -p
Hello
```

Ошибка новичка: hex-строка с нечётной длиной. Допишите ведущий `0`. Ещё: `bytes.fromhex` игнорирует пробелы, так что `xxd`-дамп можно скормить напрямую.

## Base32 — алфавит без строчных букв

**Алфавит:** `A-Z2-7`, выравнивание `=` (до 6 символов). Регистр **не важен** на входе, но на выходе — заглавные.

```python
>>> import base64
>>> base64.b32encode(b'Hello')
b'JBSWY3DP'
>>> base64.b32decode(b'JBSWY3DP')
b'Hello'
```

**Распознавание:** только заглавные буквы и цифры 2-7, часто много `=`. Base32 менее плотный, чем base64 (5 бит на символ против 6), поэтому строка заметно длиннее. Ещё признак — цифры 8 и 9 в base32 **не встречаются** (алфавит заканчивается на 7).

Вариант **base32hex** использует `0-9A-V` — встречается реже, но иногда в задачах.

## Base64 — рабочая лошадка

**Алфавит:** `A-Za-z0-9+/` (стандарт) или `A-Za-z0-9-_` (URL-safe), выравнивание `=` (0, 1 или 2 символа).

```python
>>> import base64
>>> base64.b64encode(b'Hello, world!')
b'SGVsbG8sIHdvcmxkIQ=='
>>> base64.b64decode(b'SGVsbG8sIHdvcmxkIQ==')
b'Hello, world!'
```

**Распознавание:** смешанный регистр + цифры + `+`/`/`, длина кратна 4, в конце `=` или `==`. URL-safe вариант использует `-` и `_` вместо `+` и `/`.

**Тонкости:**

- Base64 часто встречается **без выравнивания**. Тогда добавляйте `=` до кратности 4: `s + '=' * (-len(s) % 4)`.
- Несколько слоёв base64 — классика. Декодируйте в цикле, пока результат остаётся base64.
- base64 **не сжимает**: 3 байта → 4 символа, то есть размер растёт на 33%.

```python
import base64, re
s = "VmpKSmR3bzlWbWx1YzJoaA=="
while re.fullmatch(r'[A-Za-z0-9+/=]+', s):
    try:
        nxt = base64.b64decode(s).decode()
        if nxt == s: break
        s = nxt
    except Exception:
        break
print(s)
```

## Base85 / ASCII85 — плотная кодировка

**Алфавит (ASCII85):** символы с ASCII 33 (`!`) по 117 (`u`), 5 символов на 4 байта (эффективность ~25% против 33% у base64). Обрамляется `<~ ... ~>`.

**Base85 (RFC1924 / Adobe / ZeroMQ)** — разные алфавиты, их много. Python поддерживает:

```python
>>> base64.b85encode(b'Hello')
b'NM&qnZ!'
>>> base64.a85encode(b'Hello')
b'87cURD]'
>>> base64.a85decode(b'87cURD]')
b'Hello'
```

**Распознавание:** плотный набор «странных» печатных символов, часто с `<~` и `~>`. Base85 встречается в PDF (фильтр ASCII85Decode), PostScript, Git (binary patch).

## uuencode / xxencode

Старый Unix-формат для передачи бинарников по почте. Заголовок `begin 644 filename`, строки начинаются с символа-счётчика, конец — `end`.

```python
>>> import binascii
>>> binascii.b2a_uu(b'Hello')
b'&2&5L;&\\\n'
>>> binascii.a2b_uu(b'&2&5L;&\\\n')
b'Hello'
```

**Распознавание:** первая строка `begin <mode> <name>`, последняя `end`, строки начинаются с символа из диапазона `` ` ``–`~` (счётчик длины). `xxencode` использует другой алфавит (`+-0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`).

## Base58, Base62, Base91 — без «опасных» символов

- **Base58** — алфавит Bitcoin: `123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz` (исключены `0OIl` для читаемости). Используется в Bitcoin-адресах, IPFS, Tor onion-адресах.
- **Base62** — `0-9A-Za-z` (только буквы и цифры, без `+/=`); популярен в URL-коротких ссылках.
- **Base91** — плотнее base64 (13 бит на ~1.6 символа), алфавит почти весь печатный ASCII.

```python
# pip install base58
import base58
base58.b58encode(b'Hello')      # b'8KLrpgwDMj'
```

## URL-кодирование и прочие текстовые слои

- **URL-encoding (percent-encoding):** `%41` = `A`. Встречается в параметрах, путях, JWT. Python: `urllib.parse.unquote`.
- **Punycode:** `xn--` префикс для интернационализированных доменов.
- **Quoted-printable:** `=41` (MIME/email) — байт в hex с `=`-префиксом.
- **ROT13/Caesar/Atbash:** не кодировки, а простые подстановки — но часто идут в одной цепочке с кодировками.

```python
import urllib.parse, codecs
urllib.parse.unquote("Hello%20World%21")   # 'Hello World!'
codecs.decode("Uryyb", "rot13")            # 'Hello'
```

## Цепочки и автоматизация

Реальные задачи любят **многослойность**: `base64 → hex → base32 → ROT13`. Стратегия:

1. **Определите слой** по алфавиту.
2. **Декодируйте**, посмотрите на результат.
3. **Повторяйте**, пока не увидите читаемый текст или формат флага.

Автоматизация через CyberChef «Magic» или собственный скрипт:

```python
import base64, binascii, codecs

def try_all(s):
    tests = {
        'hex': lambda x: bytes.fromhex(x).decode('latin1'),
        'b64': lambda x: base64.b64decode(x + '=' * (-len(x) % 4)).decode('latin1'),
        'b32': lambda x: base64.b32decode(x.upper() + '=' * (-len(x) % 8)).decode('latin1'),
        'b85': lambda x: base64.b85decode(x.encode()).decode('latin1'),
        'a85': lambda x: base64.a85decode(x.encode()).decode('latin1'),
        'rot13': lambda x: codecs.decode(x, 'rot13'),
    }
    for name, fn in tests.items():
        try:
            out = fn(s)
            print(f"[{name}] {out[:120]}")
        except Exception:
            pass

try_all("S3ViU1RVe2t1YjUwX2lzX2Vhc3l9")
```

## Практический пример: трёхслойная задача

Дана строка: `4e4253575933504b4e525557593433544f4e5158454e4a5747354a544b4e525553534B4A4B4E35575335425A463435544D4E525547513354474E5A5648553D3D3D`

```python
import base64
s = "4e4253575933504b4e525557593433544f4e5158454e4a5747354a544b4e525553534B4A4B4E35575335425A463435544D4E525547513354474E5A5648553D3D3D"
# Слой 1: hex (только 0-9a-f)
s = bytes.fromhex(s).decode()
print(s)   # NBSWY3PKNRUWY43TONQXENJWG5JTKNRUSSKJKN5WS5BZF45TMNRUGQ3TGNZVHU===
# Слой 2: base32 (заглавные + 2-7, много '=')
s = base64.b32decode(s).decode()
print(s)   # base64-next-layer-...
# Слой 3: base64 (смешанный регистр + '+/=')
print(base64.b64decode(s).decode())
```

Вывод: каждый слой виден по алфавиту. Hex — только `0-9a-f`; base32 — заглавные + `2-7`; base64 — смешанный регистр + `+/=`.

## Распознавание: сводная таблица

| Кодировка | Алфавит | Длина/выравнивание | Типичный признак |
|---|---|---|---|
| hex | `0-9a-fA-F` | чётная | дампы, `0x`, `\x` |
| base32 | `A-Z2-7` | кратна 8, `=` | заглавные, много `=` |
| base64 | `A-Za-z0-9+/` | кратна 4, `=` | `+/`, смешанный регистр |
| base64url | `A-Za-z0-9-_` | кратна 4 | `-_`, JWT |
| base85/a85 | печатный ASCII | `5 симв.→4 байта` | `<~ ~>`, плотно |
| base58 | без `0OIl` | переменная | Bitcoin-адреса |
| uuencode | `begin/end` | строки по 60 | `begin 644` |
| quoted-printable | `=XX` | — | email/MIME |

## Кодировка или шифр? Как отличить

Полезно с первого взгляда понимать, что перед вами: кодировка (обратима без ключа) или шифрование (нужен ключ/атака).

- **Кодировка** детерминирована, не требует ключа, даёт «красивый» алфавит (base64/base32/hex). Длина строго предсказуема: base64 = `ceil(n/3)*4`, base32 = `ceil(n/5)*8`.
- **Шифрование** (AES/RSA) даёт бинарные или «случайные» данные; при выводе в текст их обычно дополнительно кодируют в base64/hex. То есть base64 часто — лишь внешняя обёртка шифротекста.
- **Хэш** имеет фиксированную длину (32/40/64 hex-символа для MD5/SHA-1/SHA-256) и не декодируется ни во что осмысленное.
- **Сжатие** (gzip/zlib) узнаётся по магическим байтам `1f 8b` / `78 9c`; после декодирования base64 вы часто попадаете прямо на них.

Практический приём: декодируйте слой и смотрите на **энтропию** результата. Осмысленный текст → возможно, есть ещё слой. Случайные байты → вероятно, вы дошли до шифротекста или хэша.

## CyberChef и автоматизация цепочек

CyberChef (веб) и его CLI-версия — стандартный инструмент для многослойных задач. «Magic» сам подбирает цепочку операций, но полагаться только на него нельзя: он иногда выбирает неверный порядок. Лучше строить цепочку вручную из операций `From Base64`, `From Hex`, `XOR`, `AES Decrypt`, `Gunzip`, `ROT13`. В CLI:

```bash
# node cyberchef-cli или npm install -g cyberchef
# сохраните рецепт в JSON и применяйте к файлам
cyberchef -recipe recipe.json -in cipher.txt -out plain.txt
```

Собственный «жадный» декодер (декодировать, пока возможно) — это 15 строк Python, которые вы уже видели выше. В реальной задаче держите под рукой шаблон `try_all` и добавляйте в него нужные слои по мере распознавания.

## Как не застрять

- **Проверяйте регистр.** Base32 декодируется только в верхнем регистре (в Python), base64 различает регистр.
- **Не забывайте про padding.** Если base64 не кратен 4 — допишите `=`.
- **URL-safe vs стандарт.** `-` и `_` означают base64url (JWT, cookie).
- **Смотрите на длину выравнивания.** `==` в конце base64 говорит, что исходных байт было на 1 меньше кратности 3.
- **Пишите свой декодер**, если алфавит нестандартный: соберите таблицу символов и декодируйте побитово.
- **Не считайте кодировку защитой** — если задача просит «взломать» base64, скорее всего это просто первый слой.
- **Проверяйте вывод на печатность.** Если декодирование даёт бинарный мусор — возможно, это не тот слой или это уже шифротекст.

## Где пригодится

- **Первые шаги любой crypto-задачи** — превратить строку в байты.
- **Web-пентест** — base64 в JWT, cookies, параметрах; base64url критичен для подделки токенов.
- **Форензика** — PEM/DER, base64-вложения в письмах, uuencode в старых дампах.
- **Реверс** — строки в бинарниках часто закодированы для сокрытия.
- **CTF misc** — слои кодировок поверх стего.
