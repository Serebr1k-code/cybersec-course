## Вопрос, с которого всё начинается

Ты уже знаешь из `crypto-intro`, что внешний слой задачи — почти всегда кодировка. Но в реальной задаче слоёв может быть **несколько**, наложенных друг на друга. Как их раскрутить и не запутаться, какой слой сейчас перед тобой?

Разберём одну конкретную длинную строку и снимем с неё все слои по очереди.

## Наш пример

Условие даёт строку из 128 символов:

```
4c4a575851324332474e3247575753584a5a33465552334d4f564e44434f4c514d4d595453354c43474e4a474d574a544a493257475343534f5a544643504a35
```

Первое, что бросается в глаза: **только символы `0-9` и `a-f`**, и длина чётная. Это hex (base16). Проверим.

## Шаг 1: снимаем hex

Hex — самая простая кодировка: каждые два символа задают один байт. Раскодировать можно через `xxd -r -p` (режим «plain hex»):

```bash
$ echo '4c4a575851324332474e3247575753584a5a33465552334d4f564e44434f4c514d4d595453354c43474e4a474d574a544a493257475343534f5a544643504a35' | xxd -r -p
LJWXQ2C2GN2GWWSXJZ3FUR3MOVNDCOLQMMYTS5LCGNJGMWJTJI2WGSCSOZTFCPJ5
```

Получили строку из **заглавных букв и цифр `2`–`7`**. Никаких строчных букв, никаких `8` или `9`. Такой алфавит — подпись base32.

## Шаг 2: снимаем base32

Base32 использует 32 символа: `A–Z` плюс `2–7`. Пять бит на символ — поэтому строка получается длиннее, чем в base64. Декодируем утилитой `base32`:

```bash
$ echo 'LJWXQ2C2GN2GWWSXJZ3FUR3MOVNDCOLQMMYTS5LCGNJGMWJTJI2WGSCSOZTFCPJ5' | base32 -d
ZmxhZ3tkZWNvZGluZ19pc19ub3RfY3J5cHRvfQ==
```

Теперь алфавит **смешанный**: есть и заглавные, и строчные буквы, и цифры, а на конце — `==`. Это base64.

Важная деталь base32: стандартный алфавит использует только заглавные буквы, поэтому если строка пришла в нижнем регистре, её нужно перевести в верхний перед декодированием. Ещё признак — выравнивание `=` (до 6 знаков).

## Шаг 3: снимаем base64

Base64 использует 64 символа `A–Z a–z 0–9 + /` и знак выравнивания `=`. Каждые 3 байта превращаются в 4 символа:

```bash
$ echo 'ZmxhZ3tkZWNvZGluZ19pc19ub3RfY3J5cHRvfQ==' | base64 -d
flag{decoding_is_not_crypto}
```

Вот и флаг. Мы прошли **три слоя** — hex → base32 → base64 — каждый раз определяя кодировку по алфавиту.

## Шаг 4: автоматизируем цепочку

Вручную перебирать слои на большой задаче утомительно. Напишем «жадный» декодер, который пробует все знакомые кодировки и печатает результат:

```python
import base64, binascii, codecs

def try_all(s):
    tests = {
        'hex':  lambda x: bytes.fromhex(x).decode('latin1'),
        'b64':  lambda x: base64.b64decode(x + '=' * (-len(x) % 4)).decode('latin1'),
        'b32':  lambda x: base64.b32decode(x.upper() + '=' * (-len(x) % 8)).decode('latin1'),
        'a85':  lambda x: base64.a85decode(x.encode()).decode('latin1'),
        'rot13': lambda x: codecs.decode(x, 'rot13'),
    }
    for name, fn in tests.items():
        try:
            print(f"[{name}] {fn(s)[:80]}")
        except Exception:
            pass

try_all("4c4a575851324332474e3247575753584a5a33465552334d4f564e44434f4c514d4d595453354c43474e4a474d574a544a493257475343534f5a544643504a35")
```

Вывод покажет строку `[hex] LJWXQ2C2...` — значит, первый слой найден; подставляем результат снова. Такой цикл «декодируй, пока получается» закрывает 90% многослойных задач. В готовом виде его умеет делать CyberChef в режиме «Magic», но проверять его цепочку глазами всё равно нужно.

## Как распознавать по алфавиту

Сводная шпаргалка — что искать во внешнем виде строки:

| Кодировка | Алфавит | Длина/выравнивание | Признак |
|---|---|---|---|
| hex (base16) | `0-9a-fA-F` | чётная | дампы, `0x`, `\x` |
| base32 | `A-Z2-7` | кратна 8, `=` | только заглавные, нет `8/9` |
| base64 | `A-Za-z0-9+/` | кратна 4, `=` | смешанный регистр, `+/` |
| base64url | `A-Za-z0-9-_` | кратна 4 | `-_`, встречается в JWT |
| base85/a85 | печатный ASCII | 5 симв. → 4 байта | `<~ ~>`, очень «плотно» |
| base58 | без `0OIl` | переменная | Bitcoin-адреса |
| uuencode | `begin`/`end` | строки по 60 | первая строка `begin 644` |

Правило: **сначала смотри на алфавит, потом на длину и выравнивание**. Если алфавит не подходит ни под одну строку таблицы — возможно, это уже не кодировка, а шифротекст или нестандартный вариант.

## Когда встречаются base85, base58 и uuencode

Иногда задача использует менее популярные кодировки.

**Base85 / ASCII85** плотнее base64 (5 символов на 4 байта). Встречается в PDF и PostScript, часто обрамлён `<~ ... ~>`:

```python
>>> import base64
>>> base64.b85encode(b'Hello')
b'NM&qnZv'
>>> base64.a85encode(b'Hello')
b'87cURDZ'
```

**uuencode** — старый Unix-формат для передачи файлов по почте. Узнаётся по первой строке `begin 644 name` и последней `end`:

```python
>>> import binascii
>>> binascii.b2a_uu(b'Hello')
b'%2&5L;&\\ \n'
```

**base58** — алфавит Bitcoin, из него убраны похожие символы `0OIl`, чтобы адреса не путались. Ставится пакетом `pip install base58`.

## Частые грабли

- **Пропущенное выравнивание.** Если base64 не кратен 4, допиши `=` до кратности: `s + '=' * (-len(s) % 4)`.
- **Регистр base32.** Python-функция `b32decode` принимает только верхний регистр — переведи строку через `.upper()`.
- **URL-safe вариант.** Символы `-` и `_` вместо `+` и `/` означают base64url (JWT, cookies).
- **Не всякий «мусор» — кодировка.** Если после декодирования выходят случайные байты — возможно, это уже шифротекст, а не следующий слой.

## URL-кодирование и текстовые слои

Кроме base-семейства в цепочки попадают текстовые обёртки:

- **URL-encoding (percent-encoding):** `%41` — это `A`. Встречается в параметрах, путях, JWT.
- **Quoted-printable:** `=41` — байт в hex с `=`-префиксом, стандарт email/MIME.
- **Punycode:** префикс `xn--` у интернационализированных доменов.
- **ROT13 / Atbash:** формально не кодировки, а подстановки, но идут в тех же цепочках.

```python
import urllib.parse, codecs
print(urllib.parse.unquote("Hello%20World%21"))  # Hello World!
print(codecs.decode("Uryyb", "rot13"))           # Hello
```

## Свой декодер для нестандартного алфавита

Иногда задача использует «сдвинутый» или перемешанный алфавит base64 — стандартные библиотеки на нём падают. Тогда собери таблицу символов вручную: у base64 каждый символ кодирует 6 бит, поэтому декодирование — это накопление битов и нарезка их по 8. Достаточно поменять строку алфавита в своей реализации:

```python
import base64
alt = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"  # свой порядок
std = base64.b64encode(b"flag{...}").decode()
custom = std.translate(str.maketrans(
    "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/", alt))
print(custom)   # теперь строка выглядит нестандартно
```

Признак такой задачи: строка похожа на base64, но стандартный декодер выдаёт мусор. Решение — вернуть алфавит на место (обратной таблицей) и декодировать обычным способом.

## Что мы теперь знаем

- Кодировки различаются **алфавитом**, длиной и выравниванием.
- Многослойные задачи решаются циклом «определи → декодируй → повтори».
- base16 = 2 символа/байт, base32 = только заглавные + `2–7`, base64 = смешанный регистр + `+/=`.
- base85/base58/uuencode узнаются по характерным деталям (плотность, `begin`, алфавит Bitcoin).
- «Жадный» декодер на 15 строк закрывает большинство цепочек.

## Практика: определяем кодировку за секунды

Разберём настоящий пример — строку из условия:

```
$ head -c 40 payload.txt
aHR0cHM6Ly9leGFtcGxlLmNvbS9mbGFn
```

Алфавит: буквы обоих регистров, цифры, ни `+`, ни `/` пока не видны, длина кратна четырём → похоже на base64. Проверяем:

```
$ base64 -d payload.txt
https://example.com/flag
```

Второй пример — `41424344`. Только `0-9a-f`, длина чётная → hex:

```
$ echo 41424344 | xxd -r -p
ABCD
```

Порядок действий всегда один: **алфавит → длина/выравнивание → попытка декодирования → проверка читаемости**. Если результат печатный — слой снят, продолжаем; если случайные байты — дальше уже шифр или сжатие.

## Сколько бит на символ — таблица плотности

| Кодировка | Символов | Бит/символ | Рост размера | Padding |
|---|---|---|---|---|
| base16 (hex) | 16 | 4 | +100 % | нет |
| base32 | 32 | 5 | +60 % | до 6 `=` |
| base64 | 64 | 6 | +33 % | до 2 `=` |
| base85 | 85 | ~6.4 | +25 % | нет |
| base58 | 58 | ~5.86 | ~+37 % | нет |

Понимание плотности помогает оценивать длину: 16 байт (например, MD5) в hex дают 32 символа, в base64 — 24 (`22` + `==`), в base32 — 26 (`24` + `======`). Если длина не совпадает ни с одним вариантом, слой нестандартный или данных меньше ожидаемого.

## Где ломаются автоматические декодеры

«Жадный» декодер, пробующий все кодировки подряд, ошибается в трёх местах:

- **ложные срабатывания.** Короткая hex-строка может «успешно» декодироваться как base64 и дать мусор. Поэтому проверяй читаемость результата (`isprintable()`), а не просто отсутствие исключения;
- **URL-safe base64.** `-` и `_` вместо `+` и `/` роняют `b64decode`. Чинится так: `s.replace('-', '+').replace('_', '/')`, затем допиши `=`;
- **порядок слоёв.** Строка из одних `a-f` бывает валидным base64. Правило: сначала снимай слой с более **узким** алфавитом (hex, base32), затем base64.

## Сравнение инструментов

| Инструмент | Сильные стороны | Слабые стороны |
|---|---|---|
| `base64`/`base32` (coreutils) | везде есть, точный контроль | по одной кодировке за раз |
| Python `base64`/`binascii` | скрипты, цепочки, base85/58 | нужен интерпретатор |
| CyberChef «Magic» | угадывает цепочку целиком | перебирает много, бывает шумно |
| `xxd -r -p` | hex→байты, ничего лишнего | только hex |

## Ограничения

Кодирование не даёт секретности — это лишь представление данных. Любая строка, которую можно раскодировать без ключа, — кодировка, и её вскрытие не требует криптоанализа. Если после снятия всех слоёв остаются нечитаемые байты, значит начался шифр или сжатие, и нужны уже другие приёмы (частотный анализ, перебор ключа, распознавание формата по magic-байтам).
