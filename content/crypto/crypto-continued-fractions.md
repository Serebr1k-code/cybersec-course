## Вопрос, с которого всё начинается

Публичный ключ RSA выглядит так: `n` — 1024 бита, а `e` — почти такое же огромное число, сотни бит. Обычно `e` маленькое (65537). Почему оно огромное? Потому что кто-то «оптимизировал» расшифрование, выбрав маленький приватный ключ `d`. И именно это делает ключ ломаемым. Инструмент атаки — **цепные дроби**.

## Наш пример

Сгенерируем намеренно слабый ключ: возьмём большие `p, q`, но маленькое `d`:

```python
from sympy import nextprime
from math import gcd
p = nextprime(2**511); q = nextprime(2**512)
n = p*q; phi = (p-1)*(q-1)
d = 0x1a2b3
while gcd(d, phi) != 1: d += 1
e = pow(d, -1, phi)          # e становится огромным
```

Теперь `e` — почти как `n`. Зашифруем сообщение и попробуем восстановить `d`, зная только `(n, e)`.

## Шаг 1: что такое цепная дробь

Любое рациональное `a/b` раскладывается в **цепную (непрерывную) дробь**:

```
a/b = q0 + 1/(q1 + 1/(q2 + ...)) = [q0; q1, q2, ...]
```

Коэффициенты `qi` даёт алгоритм Евклида:

```python
def continued_fraction(a, b):
    cf = []
    while b:
        q = a // b; cf.append(q); a, b = b, a - q*b
    return cf
print(continued_fraction(415, 93))
```

```
[4, 2, 6, 7]
```

**Подходящие дроби (convergents)** — это усечения `[q0; q1, ..., qk]`. Они дают **наилучшие рациональные приближения** исходного числа со знаменателем, не превышающим `q_k`. Рекуррентно: `p_k = q_k·p_{k-1} + p_{k-2}`, `q_k = q_k·q_{k-1} + q_{k-2}`.

## Шаг 2: почему цепные дроби появляются в RSA

Из соотношения `e·d ≡ 1 (mod φ)` следует существование целого `k`:

```
e·d = 1 + k·φ     =>     e/φ = k/d + 1/(d·φ)
```

Значит `k/d ≈ e/φ`. Но `φ = (p-1)(q-1) = n − (p+q) + 1 ≈ n`, потому что `p+q` мало по сравнению с `n`. Поэтому `e/n ≈ k/d`. И тут работает **теорема Лежандра**: если `|x − p/q| < 1/(2q²)`, то `p/q` — одна из подходящих дробей `x`. При достаточно малом `d` дробь `k/d` попадает в список convergents `e/n`.

## Шаг 3: атака Винера целиком

Условие успеха — `d < n^{0.25}/3`. Для каждого convergent `(k, d)` проверяем: делится ли `(e·d − 1)` на `k`; если да, то `φ = (e·d − 1)/k`, и тогда `p+q = n − φ + 1`. Дискриминант `(p+q)² − 4n` должен быть полным квадратом — это признак настоящего `d`:

```python
from sympy import Rational, continued_fraction, continued_fraction_convergents
from math import isqrt

def wiener(n, e):
    for conv in continued_fraction_convergents(continued_fraction(Rational(e, n))):
        k, d = int(conv.p), int(conv.q)
        if k == 0: continue
        if (e*d - 1) % k: continue
        phi = (e*d - 1) // k
        s = n - phi + 1; disc = s*s - 4*n
        if disc < 0: continue
        t = isqrt(disc)
        if t*t == disc and (s+t) % 2 == 0:
            return d
    return None

print("d =", hex(wiener(n, e)))
```

```
d = 0x1a2b5
```

Ключ восстановлен. Проверяем расшифрование:

```python
c = pow(0x4142434445464748, e, n)
print(pow(c, wiener(n, e), n).to_bytes(8, 'big'))
```

```
b'ABCDEFGH'
```

**Признак:** `e` огромное, почти как `n`. Обычное `e` — 65537; большое `e` — сигнал малого `d`. Если этот признак есть, Винер срабатывает за миллисекунды, и весь разбор укладывается в пару экранов кода.

## Шаг 4: rational reconstruction

Иногда известен не `e/n`, а **приближённое значение** отношения (например, из «шумных» данных). **Rational reconstruction** ищет дробь `num/den` с малыми числителем и знаменателем, такую что `num ≡ a·den (mod m)`. Делается это тоже цепными дробями: останавливаемся, когда знаменатель convergent превышает границу.

```python
def rational_reconstruction(a, m, bound):
    old_r, r = a, m; old_s, s = 1, 0
    while r != 0 and abs(r) > bound:
        q = old_r // r
        old_r, r = r, old_r - q*r
        old_s, s = s, old_s - q*s
    return (old_s, old_r) if abs(old_s) <= bound else None
```

Это ядро многих задач, где «известно приближение» к секретному отношению, и предшественник атаки **Боне–Дюрфе**.

## Шаг 5: Boneh–Durfee (обзорно)

Винер требует `d < n^{0.25}/3`. **Боне–Дюрфе** расширяет границу до `d < n^{0.292}`, используя полиномиальное уравнение `e·d − k·φ = 1` и метод Копперсмита на **решётках** (LLL/BKZ). Идея: обозначив `A = n+1` и `s = p+q`, получить `f(x, y) = 1 + x·(A − y)` с малыми корнями `(k, s)`, построить решётку и найти короткий вектор. Цепные дроби — «одномерный» предшественник; решётки — многомерное обобщение. Именно поэтому цепные дроби стоит понимать до конца: они дают интуицию, почему малый `d` вообще уязвим, а решётки лишь расширяют границу применимости той же идеи.

## Что мы теперь знаем

- Цепная дробь — разложение `a/b` алгоритмом Евклида; convergents — наилучшие приближения.
- В RSA `e/n ≈ k/d`, потому что `φ ≈ n`.
- **Теорема Лежандра** гарантирует попадание `k/d` в convergents.
- Винер ломает `d < n^{0.25}/3`; проверка — делимость `(e·d−1)` на `k` и полный квадрат.
- Большое `e` (почти как `n`) — сигнал малого `d`.
- **Rational reconstruction** восстанавливает отношение из приближённых данных.
- Боне–Дюрфе расширяет границу до `n^{0.292}` через решётки.

## На что смотреть дальше

- **Разлагать `e/n`, а не `e/φ`** — Винер работает именно потому, что `φ ≈ n`.
- **Забыть `k == 0`** — первый convergent `[q0]` даёт `k=0`, его пропускают.
- **Проверять только один convergent** — нужно перебрать все и проверить дискриминант.
- **Путать границы** — `n^{0.25}/3` для Винера, `n^{0.292}` для Боне–Дюрфе.
- **Игнорировать rational reconstruction** — часто он сам даёт секрет из шумных данных.

## Куда дальше

Мы освоили цепные дроби и атаку Винера. Дальше — атаки на RSA, где ключей несколько: общие простые множители и общий модуль. В уроке **crypto-rsa-multi** мы соберём все модули и найдём общий делитель одним `gcd`. А пока главное: **большое `e` — сигнал малого `d`; цепные дроби `e/n` находят `k/d`.**

## Где пригодится

- **CTF crypto:** RSA с малым `d`, «шумными» соотношениями, частично известным ключом.
- **Аудит крипто:** выявление небезопасной генерации `d`.
- **Bug bounty / пентест:** анализ самописных реализаций RSA.
- **Работа:** понимание требований к размеру `d` в стандартах.
- **Исследования:** мост от цепных дробей к решёточным атакам (LLL, Coppersmith).
