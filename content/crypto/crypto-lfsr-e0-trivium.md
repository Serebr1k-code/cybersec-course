## Вопрос, с которого всё начинается

Регистр сдвига с линейной обратной связью (LFSR) — идеальный «генератор битов»: дёшев, быстр, огромный период. Но он **линеен**, а значит, полностью предсказуем. Как из линейных регистров построить нелинейный поток? И почему даже это часто ломается? Разберём на конкретном примере восстановления состояния LFSR.

## Наш пример: 16 бит потока

У нас `keystream.txt` с 16 битами потока 16-битного LFSR с отводами 0,2,3,5.

```
$ cat keystream.txt
keystream = 1011001110001111
```

## Шаг 1: как работает LFSR

LFSR хранит состояние из `n` битов. На каждом такте:

1. Выход — младший бит.
2. Сдвиг вправо.
3. В старший бит записывается XOR отводов.

```python
def step(state, n, taps):
    out = state & 1
    fb = 0
    for t in taps: fb ^= (state >> t) & 1
    return (state >> 1) | (fb << (n-1)), out
```

Всё линейно: `state` и `out` связаны XOR-ами.

## Шаг 2: восстановление состояния

Так как выход линеен, каждый выходной бит — линейная комбинация начальных битов. Построим матрицу: для каждого из `n` выходов найдём вектор коэффициентов, а затем решим систему над GF(2) гауссовым исключением. 16 выходов достаточно для 16-битного состояния.

```
$ python3 lfsr.py
recovered state = 0xbeef
flag: nto{lfsr_st4t3_r3c0v3r3d_by_l1n34r_4lg3br4}
```

## Шаг 3: Берлекамп-Месси

Если структура LFSR неизвестна, применяют **алгоритм Берлекампа-Месси**: по 2n битам потока он находит минимальный LFSR, его длину и отводы. Это значит, что **любой** одиночный LFSR восстанавливается по потоку — линейность убивает его как шифр.

## Шаг 4: E0, Trivium, Grain, SNOW

Чтобы скрыть линейность, регистры **комбинируют нелинейно**:

- **E0** (Bluetooth) — 4 LFSR, комбинируемые конечным автоматом.
- **Trivium** — 288-битное состояние из трёх регистров с нелинейной обратной связью.
- **Grain** — LFSR + нелинейный сдвиговый регистр (NFSR), выход через фильтр.
- **SNOW** — LFSR над GF(2^32) + нелинейная функция FSM.

Общая идея: **линейное состояние + нелинейный выход**. Но если выход **коррелирует** с отдельным регистром, атака всё равно возможна.

## Полный прогон от начала до конца

1. `cat keystream.txt` — 16 бит потока.
2. Строим линейную систему: выход = функция начального состояния.
3. Решаем гауссовым исключением над GF(2).
4. `python3 lfsr.py | grep nto > found.txt`.

## Если не сработало

Если битов меньше `n`, система недоопределена — нужно больше потока. Если структура неизвестна, применяй Берлекампа-Месси (2n бит). Если LFSR комбинируются нелинейно, одной линейной системы мало — нужны корреляционная или алгебраическая атака.

## Trivium детальнее

Trivium — один из финалистов конкурса eSTREAM, финалист и в NIST LWC. Его состояние — 288 бит, разделённых на три регистра (93, 84, 111 бит). Каждый такт:

1. Из каждого регистра вычисляется нелинейная функция (AND двух битов + XOR третьего).
2. Три результата XOR-ятся и дают выходной бит.
3. Результаты подаются обратно в регистры (сдвиг с нелинейной обратной связью).

Нелинейность (AND) не даёт применить чистую линейную алгебру. Но корреляции остаются: выход коррелирует с отдельными битами, что позволяет корреляционные атаки на урезанные версии. Для полного Trivium лучшие атаки требуют порядка `2^80` — стойкость на уровне ключа.

## Grain и SNOW

**Grain-128** использует LFSR (128 бит) и NFSR (нелинейный регистр, 128 бит), а выход формируется нелинейным фильтром из битов обоих регистров. NFSR добавляет нелинейность, но и создаёт корреляции — их минимизируют выбором отводов. Grain-128a — обновлённая версия с аутентификацией.

**SNOW 3G** — стандарт для 3G/4G. Он использует LFSR над `GF(2^32)` (16 слов) и **FSM** (finite state machine) — небольшой нелинейный автомат, смешивающий выход. SNOW 3G применяется в KASUMI-замене и в LTE. Атаки на него требуют `2^128`+ операций, то есть стойкость по ключу.

**E0** (Bluetooth) — 4 LFSR (25, 31, 33, 39 бит) и конечный автомат для нелинейности. E0 известен слабостями: корреляционные атаки и атаки на инициализацию. В Bluetooth его заменили на AES-CCM (LE) и усиленные режимы.

## Быстрая корреляционная атака

Пусть выход генератора коррелирует с выходом одного LFSR с вероятностью `1/2 + ε`. Тогда:

1. Перебираем начальное состояние этого LFSR (`2^n` вариантов).
2. Для каждого генерируем поток и считаем, сколько битов совпадает с наблюдаемым.
3. Правильное состояние даёт заметно больше совпадений (смещение `ε`).

При `ε = 0.1` и потоке в `N` бит правильное состояние выделяется, если `N > 1/ε^2`. **Fast correlation attack** использует **LDPC-коды** или **Walsh-Hadamard** для ускорения и работает при очень малых `ε`. Именно так ломали урезанные версии E0 и Grain.

Защита — сделать так, чтобы выход не коррелировал ни с одним отдельным регистром (использовать несколько нелинейных функций, «выравнивающих» вероятности).

## A5/1: три регистра и мажоритарное тактирование

A5/1 — потоковый шифр GSM. У него три LFSR: R1 (19 бит), R2 (22), R3 (23). Выход — XOR младших битов всех трёх. Особенность — **мажоритарное тактирование**: на каждом такте вычисляется мажоритарный бит из специальных «тактовых» битов регистров (R1 бит 8, R2 бит 10, R3 бит 10), и тактируются только те регистры, чей тактовый бит совпал с большинством. Это делает поток нелинейным по времени и мешает прямой линейной атаке.

Инициализация: регистры обнуляются, затем 64 такта XOR с битами ключа, затем 22 такта XOR с номером кадра. После этого генерируется поток для шифрования кадра.

```python
def step(regs):
    maj = (clk(regs[0]) + clk(regs[1]) + clk(regs[2])) >= 2
    for i in range(3):
        if clk(regs[i]) == maj:
            regs[i] = clock(regs[i], A5[i])
    return regs
```

Слабости A5/1: мажоритарное тактирование создаёт корреляции, а короткие регистры (всего 64 бита состояния) позволяют **guess-and-determine**: угадать состояния двух регистров и проверить третий по потоку. На практике A5/1 ломается за минуты на обычном компьютере (проект A5/1 Cracking Project, 2009). A5/2 (экспортный вариант) ещё слабее — ломается мгновенно. Поэтому GSM-шифрование считают ненадёжным.

## Практика: как ломают потоковые шифры

Порядок действий на CTF:

1. **Определи схему.** Линейный LFSR → Берлекамп-Месси. Комбинация LFSR → ищи корреляции. Есть нелинейный фильтр → пробуй алгебраическую атаку.
2. **Собери поток.** Обычно это XOR известного открытого текста с шифртекстом (many-time pad). Известный фрагмент (`FLAG{`, HTTP-заголовки) даёт часть потока.
3. **Реши.** Линейная алгебра, z3, или перебор (guess-and-determine).
4. **Проверь.** Расшифруй остальное и убедись, что текст осмысленный.

Ключевой инструмент — **z3** для моделирования битовых операций и **SageMath** для линейной алгебры над GF(2). Часто задача сводится к «собери 2n бит потока и реши систему».

## Что мы теперь знаем

- LFSR линеен и восстанавливается по `n` выходным битам.
- Берлекамп-Месси находит LFSR по 2n битам.
- Нелинейность достигается комбинированием регистров.
- Корреляции с отдельными регистрами — источник атак.
- Trivium/Grain/SNOW/E0 — практические LFSR-схемы.
