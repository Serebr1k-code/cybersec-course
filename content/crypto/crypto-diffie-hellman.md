## Вопрос, с которого всё начинается

Мы научились собирать общий секрет из модульной арифметики. Но как две стороны, никогда не встречавшиеся, договариваются о секретном ключе **по открытому каналу**, где всё подслушивают? Ответ — Diffie-Hellman (DH). Вопрос новичка: «Если DH такой красивый, где он ломается?» Ломается он не сам по себе, а на **плохих параметрах** — и это видно прямо из условия задачи.

## Наш пример

В задаче даны параметры DH и публичный ключ сервера:

```
p = 14852535553478910211
g = 2
A = 13514202762355479771        # публичный ключ сервера = g^a mod p
```

Задача — найти общий секрет, не зная секрета `a`. Разберём протокол и вскроем его.

## Шаг 1: как устроен DH

Две стороны договариваются о простом числе `p` и генераторе `g` (это открытые параметры). Затем:

1. Алиса выбирает секрет `a` и посылает `A = g^a mod p`.
2. Боб выбирает секрет `b` и посылает `B = g^b mod p`.
3. Алиса считает `B^a = g^(ab)`, Боб — `A^b = g^(ab)`. Общий секрет — `g^(ab)`.

Подслушивающий видит `p`, `g`, `A`, `B`, но не может найти `a` или `b`. Стойкость держится на сложности **задачи дискретного логарифмирования** (DLP): по `g` и `g^a mod p` найти `a`. Все атаки ниже ломают **параметры** или **реализацию**, а не саму задачу при правильных параметрах.

## Шаг 2: маленькое `p` — дискретный логарифм в лоб

Первая проверка — размер `p`. Если он меньше ~512 бит, DLP решается общими методами: baby-step giant-step (BSGS) или Pollard's rho за `O(√p)`. Наш `p` всего 64 бита — это мгновенно. Проверим:

```python
from sympy.ntheory.residue_ntheory import discrete_log
a = discrete_log(p, A, g)
print("recovered a =", a)
```

```
recovered a = 163095115222987398
pow(g, a, p) == A: True
```

Число `a` восстановлено. Проверка `pow(g, a, p) == A` обязательна: если она сходится, решение верное. Признак такой задачи простой: `p` короче 512 бит — считайте, что сломано.

## Шаг 3: гладкое `p−1` — алгоритм Полига–Хеллмана

Даже большой `p` может быть слабым, если число `p−1` **гладкое** — раскладывается на малые простые множители. Дело в том, что порядок группы равен `p−1`, и DLP можно решить **по частям**: в каждой подгруппе малого порядка, а потом собрать ответ по CRT. Это и есть **алгоритм Полига–Хеллмана**: сложность `O(Σ √qᵢ · log p)`, где `qᵢ` — простые делители `p−1`. Если максимальный `qᵢ` мал, всё решается мгновенно.

Проверим наш `p`:

```python
from sympy import factorint
print(factorint(p-1))
```

```
{2: 1, 3: 1, 5: 1, 7: 1, 11: 1, 19: 1, 23: 1, 29: 1, 31: 1, 37: 1, 41: 1, 47: 1, 53: 1, 61: 1, 71: 1}
```

Все множители — крошечные простые. Это учебный пример, но принцип ровно тот же для больших `p` с одним маленьким множителем: чем глаже `p−1`, тем легче атака.

## Шаг 4: полный прогон

Соберём атаку целиком и получим общий секрет:

```python
a = discrete_log(p, A, g)      # Полиг–Хеллман (sympy/Sage применяют сами)
print("pow(g, a, p) == A:", pow(g, a, p) == A)
b = random.randrange(2, p-1); B = pow(g, b, p)
print("shared:", pow(B, a, p) == pow(A, b, p))
```

```
pow(g, a, p) == A: True
shared: True
```

Общий секрет совпал. Заметьте: `discrete_log` вернул `a` не «точно», а по модулю порядка `g` — но этого достаточно, чтобы вычислить `g^(ab)`. В Sage тот же вызов `discrete_log(A, g)` автоматически выбирает Полига–Хеллмана для гладких порядков.

## Шаг 5: малые подгруппы

Если порядок `g` не является большим простым, а имеет малые множители, возможна атака **малой подгруппы**. Атакующий посылает серверу `A = g^k` малого порядка, получает общий секрет в этой маленькой подгруппе и извлекает остаток секрета сервера по модулю малого порядка. Повторяя для нескольких порядков, восстанавливают весь секрет — это, по сути, Полига–Хеллман на уровне протокола.

Защита: **проверять**, что присланный элемент лежит в подгруппе большого простого порядка, и использовать **safe prime** `p = 2q + 1` (где `q` простое) с `g` порядка `q`. Проверка генератора:

```python
q = (p - 1) // 2
assert pow(g, q, p) == 1      # g в подгруппе порядка q
assert pow(g, 2, p) != 1      # g не порядок 2
```

## Шаг 6: Logjam и MITM

**Logjam** (2015) — реальная атака: множество TLS/SSH-серверов использовали **общие 512-битные** DH-простые из экспортных наборов. Один раз выполнив предвычисление, атакующий быстро решает DLP для **любого** сервера с тем же `p`, что даёт пассивный перехват и расшифровку трафика. Проверить сервер можно так:

```bash
$ nmap --script ssl-dh-params -p 443 target
$ testssl.sh --vulnerable target
```

И отдельно: сам по себе DH **не аутентифицирует** стороны. Активный посредник может провести два независимых обмена — с Алисой и с Бобом — и читать всё. Поэтому DH комбинируют с подписью или сертификатом (как в TLS ECDHE-RSA). «Голый» DH в задаче без аутентификации — повод искать MITM-сценарий.

## Распознавание DH-задач

Смотрите на условие. Даны `p, g, A, B` и `p` маленькое — дискретный логарифм. `p` большое, но `p−1` раскладывается на малые простые — Полига–Хеллман. `g` подозрительно малого порядка, а сервер не проверяет подгруппу — small-subgroup. Параметры «экспортные» или общие между серверами — Logjam. Нет подписи или сертификата — MITM. А если вместо чисел даны точки `(x, y)` или имя кривой (`P-256`, `secp256k1`, `X25519`) — это ECDH, и атаки у него другие (invalid-curve, см. `crypto-ecc`).

## Что мы теперь знаем

- DH выводит общий секрет `g^(ab)` по открытому каналу; стойкость — на сложности DLP.
- **Маленькое `p`** (< 512 бит) → BSGS/Pollard's rho.
- **Гладкое `p−1`** → Полига–Хеллман; проверяйте `factorint(p-1)` первым делом.
- **Малый порядок `g`** без проверки подгруппы → small-subgroup атака.
- **Общие/экспортные простые** → Logjam.
- Без аутентификации DH уязвим к **MITM**.
- Безопасные параметры: safe prime, `g` порядка `q`, `p ≥ 2048` бит, либо ECDHE.
- Перед любой атакой: `factorint(p-1)` и проверка размера `p` — это две первые команды.
