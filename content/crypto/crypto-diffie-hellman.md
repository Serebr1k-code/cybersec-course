## Протокол Diffie-Hellman

Diffie-Hellman (DH) — протокол обмена ключами, позволяющий двум сторонам вывести **общий секрет** по незащищённому каналу. Параметры: простое число `p` и генератор `g` (элемент порядка, обычно делителя `p-1`).

1. Alice выбирает секрет `a`, отправляет `A = g^a mod p`.
2. Bob выбирает секрет `b`, отправляет `B = g^b mod p`.
3. Alice вычисляет `B^a = g^(ab)`, Bob — `A^b = g^(ab)`. Общий секрет `g^(ab)`.

Стойкость основана на сложности **задачи дискретного логарифмирования** (DLP): по `g` и `g^a mod p` найти `a`. Все атаки ниже эксплуатируют **плохие параметры** или **ошибки реализации**, а не слабость самой задачи при правильных параметрах.

## Атака 1: дискретный логарифм (малый p или слабые параметры)

Если `p` мал (несколько сотен бит и меньше), DLP решается общими методами: baby-step giant-step (BSGS, `O(√p)` памяти и времени), Pollard's rho (`O(√p)` времени, мало памяти), индексный метод (subexponential, для больших `p`).

```python
from sympy.ntheory.residue_ntheory import discrete_log
a = discrete_log(p, A, g)     # sympy решает DLP для умеренных p
```

Признак: `p` длиной 256 бит и меньше — считайте, что сломано.

## Атака 2: гладкое p−1 (Полиг–Хеллман)

Порядок группы равен `p-1`. Если `p-1` **гладкое** (разлагается на малые простые множители), применяется **алгоритм Полига–Хеллмана**: DLP разбивается на DLP в подгруппах малого порядка, решается в каждой (BSGS), и результат собирается по CRT.

```
p-1 = q1^e1 · q2^e2 · ... · qk^ek
```

Сложность — `O(Σ √qi · log p)`. Если максимальный `qi` мал, всё решается мгновенно.

```python
from sympy import factorint
print(factorint(p-1))   # все множители малы? -> Полиг-Хеллман
# sage: discrete_log(A, g) автоматически использует Полига-Хеллмана
```

**Признак:** `p-1` факторизуется на маленькие простые. Классика CTF — «safe prime не использован».

## Атака 3: малые подгруппы (small subgroup)

Если порядок `g` не является большим простым, а имеет малые множители, атакующий может подсунуть серверу `A = g^k` малого порядка, получить общий секрет в малой подгруппе и извлечь остаток секрета сервера по модулю малого порядка. Повторяя для нескольких малых порядков, восстанавливают весь секрет (это аналог Полига–Хеллмана на уровне протокола).

Защита — **проверка** что присланный элемент лежит в правильной подгруппе большого простого порядка, и использование safe prime (`p = 2q + 1`, где `q` простое) с `g` порядка `q`.

## Атака 4: Logjam

Logjam (2015) — реальная атака: множество TLS/SSH-серверов использовали **общие 512-битные DH-простые** из экспортных наборов. Один раз выполнив предвычисление (индексный метод, «number field sieve» с большим прекомпьютом), атакующий может **быстро** решать DLP для любого сервера, использующего то же `p`. Результат — пассивный MITM и расшифровка трафика.

```bash
# Проверка сервера на слабые DH-параметры
nmap --script ssl-dh-params -p 443 target
# или testssl.sh
testssl.sh --vulnerable target
```

Logjam показал: даже «формально 1024-битный» DH опасен, если `p` общее и предвычислено. Рекомендация — 2048+ бит, уникальные параметры или ECDHE.

## MITM и аутентификация

Сам по себе DH **не аутентифицирует** стороны: активный MITM может провести два независимых обмена (с Alice и с Bob) и читать всё. Именно поэтому DH комбинируют с подписью/сертификатом (как в TLS ECDHE-RSA) или PSK. «Голый» DH в задаче без аутентификации — повод искать MITM-сценарий.

## Практический пример: атака Полига–Хеллмана

```python
# p-1 гладкое: решаем DLP по частям
from sympy import factorint
from sympy.ntheory.residue_ntheory import discrete_log

p = ...      # из задачи
g = ...
A = ...      # g^a mod p

fac = factorint(p-1)
print(fac)   # например {2:1, 3:1, 5:1, ...} маленькие
# для каждого qi: решаем DLP в подгруппе порядка qi и собираем CRT
a = discrete_log(p, A, g)   # sympy сам применит Полига-Хеллмана
print(a.to_bytes((a.bit_length()+7)//8, "big"))
```

В Sage: `a = discrete_log(A, g)` — автоматически выбирает оптимальный метод (Полиг–Хеллман для гладких порядков).

## Безопасные параметры и их генерация

Правильный DH требует:

- `p` — «безопасное простое» (safe prime): `p = 2q + 1`, где `q` тоже простое. Тогда порядок группы `p-1 = 2q`, и подгруппа большого простого порядка `q` — единственная «опасная» подгруппа малого размера (порядка 2).
- `g` — генератор подгруппы порядка `q` (а не всей группы порядка `p-1`). Тогда малые подгруппы исключены.
- Размер `p` — не менее 2048 бит (для 112-битной стойкости) или переход на ECDHE.

Проверка генератора: `g^q mod p == 1` и `g != 1`, где `q = (p-1)/2`. Если это так, `g` лежит в подгруппе порядка `q`.

```python
q = (p - 1) // 2
assert pow(g, q, p) == 1      # g в подгруппе порядка q
assert pow(g, 2, p) != 1      # g не порядок 2
```

Если в задаче `g` имеет порядок, делящий `p-1` на много маленьких частей, — это сигнал к Полига–Хеллману или small-subgroup.

## ECDH в сравнении с классическим DH

ECDH — тот же протокол на группе точек эллиптической кривой. Плюсы: короткие ключи (256 бит ≈ 3072-битный DH), быстрее, нет проблем с выбором `p` (стандартные кривые). Минусы: сложнее валидация точек (invalid-curve), и ошибки реализации фатальны. В TLS 1.3 используется только ECDHE (эфемерный), что даёт forward secrecy.

С точки зрения атак: классический DH ломается через гладкое `p-1`/малые подгруппы/Logjam; ECDH — через invalid-curve/twist/nonce reuse (см. `crypto-ecc`). Признак ECDH: параметры выглядят как точки `(x, y)` или имя кривой (`P-256`, `secp256k1`, `X25519`).

## Распознавание DH-задач

| Что дано | Вероятная атака |
|---|---|
| `p`, `g`, `A`, `B`, маленькое `p` | дискретный лог (BSGS/rho) |
| `p-1` факторизуется на малые | Полиг–Хеллман |
| `g` малого порядка, сервер не проверяет | small subgroup |
| общие/экспортные 512-бит простые | Logjam |
| нет аутентификации | MITM |
| точки `(x,y)` и имя кривой | ECDH-атаки (invalid-curve) |

## Разобранный пример: полный разбор

```python
p = 0xffffffffffffffffc90fdaa22168c234c4c6628b80dc1cd1...  # из задачи
g = 2
A = int(input("A: "))     # публичный ключ сервера = g^a
B = int(input("B: "))     # наш публичный

# 1. Проверяем гладкость p-1
from sympy import factorint
print("p-1 =", factorint(p-1))
# Если все множители < 2^40 -> Полиг-Хеллман решает за секунды

# 2. Решаем DLP
from sympy.ntheory.residue_ntheory import discrete_log
a = discrete_log(p, A, g)
print("secret a =", a)
# 3. Общий секрет
S = pow(B, a, p)
print("shared =", S)
```

## Варианты DH: DHE, ECDHE, PSK, forward secrecy

- **Static DH:** долговременные ключи обеих сторон. Компрометация ключа раскрывает все прошлые сессии.
- **DHE (ephemeral):** для каждой сессии новый `a`, `b`. Даёт **forward secrecy** — компрометация долговременного ключа не раскрывает прошлый трафик.
- **ECDHE:** DHE на эллиптических кривых — быстрее и с короткими ключами; обязателен в TLS 1.3.
- **PSK (pre-shared key):** DH с предварительным общим секретом; аутентифицирует стороны без сертификатов (используется в IoT, WireGuard).

При аудите: если сервер использует static DH с общими параметрами — риск Logjam; если DHE с малым `p` — риск факторизации. TLS 1.3 разрешает только (EC)DHE с forward secrecy.

## Частые ошибки

- **Использовать малый `p`.** 256/512 бит ломается.
- **Не проверять `p-1` на гладкость.** Полиг–Хеллман — первая проверка.
- **Не проверять подгруппу.** Small-subgroup атака.
- **Общие параметры.** Logjam.
- **Считать DH аутентифицированным.** Без подписи — MITM.
- **Путать `g` порядка `p-1` и `g` порядка `q` (safe prime).** От этого зависит стойкость.

## Как не застрять

- **Факторизуйте `p-1`.** Гладкое → Полиг–Хеллман.
- **Проверьте размер `p`.** < 512 бит → BSGS/rho.
- **Проверьте порядок `g`.** Малые делители → small subgroup.
- **Ищите предвычисленные/общие простые.** Logjam-сценарий.
- **Проверьте аутентификацию.** Нет подписи → MITM.
- **В Sage `discrete_log` сам выберет метод** — используйте как быструю проверку.
- **Сверяйте параметры с известными.** Экспортные 512-битные простые — красный флаг.
- **Помните про forward secrecy.** Static DH без неё — риск компрометации истории.

## Где пригодится

- **CTF** — DH-задачи с слабыми параметрами, Полиг–Хеллман, малые подгруппы.
- **TLS/VPN-аудит** — Logjam, экспортные группы, выбор параметров.
- **Протоколы** — SSH, IPsec, Signal (X25519 — DH на эллиптических кривых).
- **Крипто-разработка** — выбор safe primes и проверка подгрупп.
- **Мост к ECC** — ECDH — тот же принцип на кривых.
