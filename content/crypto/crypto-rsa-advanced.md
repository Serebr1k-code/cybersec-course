## Вопрос, с которого всё начинается

Базовые атаки на RSA ты уже знаешь: малая экспонента, общий модуль, близкие простые, факторизация Полларда. А что делать, если `n` большое, `e` нормальное, простые далеко друг от друга — и всё равно ключ ломается? В таких задачах атакующему обычно известна **часть** секрета: несколько старших битов `p`, структура сообщения или связь между двумя сообщениями. Из этой части ключ восстанавливают не перебором, а математикой — решётками и полиномами.

## Наш пример

Возьмём конкретную утечку: два сообщения зашифрованы одним ключом с `e = 3`, и известно, что они **линейно связаны** — `m2 = m1 + b`. Вот реальный прогон:

```
n  = 100000000000000000050700000000000000004563
c1 = 10478859659713681601856823587628934661298
c2 = 73077989160402066817262616009418974430640
```

`n` — около 260 бит, `c1` и `c2` — шифротексты. Мы не знаем ни `p`, ни `q`, ни `m1`. Вопрос: можно ли достать `m1`?

## Шаг 1: превращаем шифротексты в полиномы

Напомню: `c = m^e mod n` означает, что число `m` — **корень** полинома `f(x) = x^e − c` по модулю `n`. Для `e = 3` это `f(x) = x^3 − c1`.

Для второго сообщения связь `m2 = m1 + b` превращает его шифротекст в полином от того же неизвестного `m1`:

```
g(x) = (x + b)^3 − c2
```

Оба полинома обнуляются при `x = m1`. Значит, `(x − m1)` делит и `f`, и `g`. А общий делитель двух полиномов — это их **наибольший общий делитель (gcd)**. Если gcd окажется линейным, его корень и есть `m1`.

Важно понять, почему это вообще возможно: мы не решаем дискретный логарифм и не факторизуем `n`. Мы пользуемся тем, что **два уравнения об одном неизвестном** всегда можно объединить — точно так же, как систему `x ≡ 1 (mod 5)` и `x ≡ 3 (mod 5)` мы объединяем в одно условие на `x`. Разница лишь в том, что здесь «уравнения» — полиномиальные, и роль общего решения играет gcd.

## Шаг 2: считаем gcd полиномов

Обычный `gcd` из математики работает над полем; здесь коэффициенты берутся по модулю `n`, а `n` составное. Но для нашей задачи хватает школьного алгоритма Евклида, если все ведущие коэффициенты обратимы по модулю `n`:

```python
def polygcd(a, b, n):
    while not iszero(b, n):
        r = polymod(a, b, n)     # остаток от деления полиномов
        a, b = b, r
    return trim(a, n)
```

Полиномы задаём списками коэффициентов от младшего к старшему: `f1 = [−c1, 0, 0, 1]`, а `f2` — раскрытая скобка `(x + b)^3`. Запускаем:

```
gcd degree = 1  coeffs = [1988097332717644780589007896083686153109, 99401240543661989069296379464446828269983]
recovered m1 = 9142616899009782263444882272305  match: True
message: secret_msg_01
```

GCD получился **линейным** (степень 1): это `g0 + g1·x`. Его корень `−g0/g1` и есть исходное сообщение — атакующий восстановил `m1`, не зная ключа. Так работает атака **Franklin–Reiter**.

## Шаг 3: а если связь нелинейная или сообщение структурировано?

Franklin–Reiter требует малого `e` и линейной связи. Более общий приём — теорема **Coppersmith**: если `f(x)` — полином степени `d`, и у него есть корень `x0`, меньший чем `n^(1/d)`, то этот корень можно найти за разумное время с помощью решётки. Идея — «вытянуть» маленький корень наружу, превратив сравнение по модулю в обычное равенство.

Продемонстрируем сам механизм — поиск малого `x`, удовлетворяющего `x ≡ a (mod N)`. Строим решётку из строк `(N, 0)` и `(a, 1)` и уменьшаем базис алгоритмом **LLL** (алгоритм Ленстры–Ленстры–Ловаса: он перестраивает базис решётки так, чтобы векторы стали короткими и почти ортогональными):

```
original basis : [[1000000000000037, 0], [999999999968700, 1]]
LLL-reduced    : [[-31337, 1], [1015937, 31911159300]]
small root x0 = 31337
```

Короткий вектор `(−31337, 1)` дал нам искомый корень. Именно так, только с большей решёткой, ищут корни полиномов в Coppersmith: если известны **старшие биты `p`**, строят `f(x) = p_high + x` и находят малые неизвестные биты; если у сообщения известен **префикс**, строят `f(x) = (m0 + x)^e − c`.

## Шаг 4: что даёт частичная утечка ключа

Разберём карту утечек — это и есть «продвинутый RSA»:

| Что известно атакующему | Что строим | Метод |
|---|---|---|
| префикс сообщения `m0` | `(m0+x)^e − c` | Coppersmith |
| старшие биты `p` | `p_high + x` | Coppersmith, `beta < 0.5` |
| линейная связь `m2=a·m1+b` | два полинома | Franklin–Reiter |
| разные padding у сообщений | система `(a_i·x+b_i)^e−c_i` | CRT + Coppersmith |
| младшие/старшие биты `d` | HNP-полином | решётка / Boneh–Durfee |

Обрати внимание: почти всё сводится к двум движкам — **поиску малого корня** (решётки, LLL/BKZ) и **gcd полиномов**. Понимая эти два движка, ты видишь все «продвинутые» атаки на RSA как одну семью.

## Шаг 5: границы применимости

Coppersmith сработает не всегда — у него есть жёсткие границы:

- корень должен быть **мал**: `|x0| < n^(1/d)` для полного модуля;
- если неизвестный множитель — не весь `n`, а только `p`, порог ниже: `x0 < n^(1/4)` при `beta ≈ 0.5`;
- при большом `e` атаки Franklin–Reiter и Coppersmith не работают;
- полином надо привести к **моническому** виду (старший коэффициент = 1), умножив на обратный по модулю.

Проверять границы нужно ДО запуска, иначе решётка просто вернёт пустой список корней.

Отдельно про `beta`. Это параметр, показывающий, какую долю `n` делит неизвестный множитель. Если атакующий ищет корень по модулю всего `n` (например, восстанавливает сообщение), то `beta = 1`. Если корень связан с делителем `n` (например, со старшими битами `p`), то `beta < 0.5`, и допустимый размер корня уменьшается примерно вдвое. Перепутать `beta` — самая частая причина, почему Coppersmith «не находит» корень, который на самом деле есть.

## Что мы теперь знаем

- Продвинутые атаки на RSA начинаются там, где атакующему известна **часть** секрета.
- Шифротекст — это корень полинома; связь между сообщениями становится системой полиномов.
- **gcd** двух полиномов даёт общий корень — это Franklin–Reiter.
- **LLL** находит маленькие корни по модулю — это ядро Coppersmith.
- Границы (`x < n^(1/d)`, `beta`) определяют, сработает ли атака.

## На что смотреть дальше

- **Franklin–Reiter** (отдельный урок) — разбор `e = 2` и без Sage.
- **Coppersmith вглубь** — построение решётки Howgrave–Graham для степени `d`.
- **Boneh–Durfee** — атака на малый `d` через ту же решётку.
- **Håstad broadcast** — CRT плюс извлечение корня при малом `e`.

В следующем уроке мы возьмём **решётки** как отдельный инструмент: построим их под конкретные задачи (knapsack, усечённый LCG) и разберём, когда LLL хватает, а когда нужен BKZ. А пока запомни главное: продвинутый RSA — это либо **gcd полиномов**, либо **малый корень, найденный решёткой**.
