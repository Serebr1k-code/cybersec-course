## Кодирование vs шифрование vs хэширование

Прежде чем распутывать цепочку, убедитесь, что понимаете разницу:

- **Кодирование** — обратимое отображение бинарных данных в текстовый алфавит. Ключ не нужен. Примеры: base64, hex, base32.
- **Шифрование** — обратимо только с ключом. AES, RSA, ChaCha20.
- **Хэширование** — необратимо, фиксированная длина. MD5, SHA-256, bcrypt.

Внешний слой почти всегда — кодирование (потому что бинарные данные нельзя удобно передать текстом). Значит, **первый шаг любой задачи — декодировать внешний слой**. И только потом вы увидите шифротекст или хэш.

## Base16 (hex)

Алфавит `0-9a-f`. 2 символа = 1 байт. Признаки: чётная длина, только hex-символы, часто префиксы `0x`, `\x`, `%`.

```bash
echo 48656c6c6f | xxd -r -p            # Hello
python3 -c "print(bytes.fromhex('48656c6c6f'))"
```

Особый случай — **hex-дампы** с адресами и ASCII-колонкой (`xxd`, `hexdump -C`). Их нужно «очистить» перед декодированием: убрать адреса, разделители, ASCII.

## Base32 / base32hex

Алфавит `A-Z2-7` (base32) или `0-9A-V` (base32hex). 8 символов = 5 байт. Выравнивание `=`. Признаки: заглавные, нет `0`, `1`, `8`, `9`, много `=`.

```python
import base64
base64.b32encode(b"Hello")     # b'JBSWY3DP'
base64.b32hexencode(b"Hello")  # b'91IMOR3F'
```

## Base64 / base64url / base64 custom

Стандартный алфавит `A-Za-z0-9+/`, URL-safe `A-Za-z0-9-_`. 4 символа = 3 байта. Выравнивание `=`, `==`.

**Кастомный алфавит** — частая CTF-уловка: разработчик меняет таблицу символов (например, использует `0-9A-Za-z` вместо стандартной). Признак: строка «похожа на base64», но декодируется в мусор. Решение — определить порядок символов (часто из кода задачи) и декодировать вручную.

```python
import base64

def decode_custom(s, alphabet):
    """Декодирование base64 с нестандартным алфавитом."""
    std = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"
    table = {c: std[i] for i, c in enumerate(alphabet)}
    # маппим кастомные символы в стандартные, затем декодируем
    mapped = "".join(table.get(c, c) for c in s)
    return base64.b64decode(mapped + "=" * (-len(mapped) % 4))

# пример: алфавит переставлен
alphabet = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz+/"
print(decode_custom("...", alphabet))
```

## Base85: b85, a85, z85, rfc1924

Четыре несовместимых варианта:

| Вариант | Признаки | Применение |
|---|---|---|
| **b85** (RFC 1924) | `0-9A-Za-z!#$%&()*+-;<=>?@^_`{`\|}~` | IPv6, Git |
| **a85** (Adobe ASCII85) | `<~ ... ~>`, символы `!`..`u` | PDF, PostScript |
| **z85** | алфавит ZeroMQ | ZeroMQ, CurveZMQ |
| **base85 (Python)** | `base64.b85encode` | — |

```python
import base64
base64.a85encode(b"Hello")   # b'87cURD]'
base64.b85encode(b"Hello")   # b'NM&qnZ!'
base64.a85decode(b'<~87cURD]~>')  # учитывает <~ ~>
```

## uuencode / xxencode / yenc

Старые форматы для передачи бинарников по 7-битным каналам (email, Usenet). Заголовок `begin <mode> <name>`, конец `end`. Строка начинается со символа-счётчика длины.

```python
import binascii
binascii.b2a_uu(b"Hello")     # b'&2&5L;&\\\n'
binascii.a2b_uu(b"&2&5L;&\\\n")  # b'Hello'
```

**yenc** — вариант с другим кодированием байтов (смещение +42, escape `=`). Встречается в Usenet.

## quoted-printable и MIME

**Quoted-printable** (email, MIME): непечатаемые байты → `=XX`, перенос строки `=\r\n`. Признак — много `=` в середине строк.

```python
import quopri
quopri.decodestring(b"Hello=20World=21")   # b'Hello World!'
```

**Base64 в MIME** (вложения email) — идёт после `Content-Transfer-Encoding: base64`.

## Base58 / base62 / base91 / base100

- **base58** — Bitcoin-адреса, Tor onion v2; алфавит без `0OIl`.
- **base62** — только `0-9A-Za-z`; URL-короткие ссылки.
- **base91** — плотнее base64, алфавит почти весь печатный ASCII.
- **base100** — эмодзи-кодирование (иногда в шутках/CTF).

```python
# pip install base58
import base58
base58.b58encode(b"Hello")   # b'8KLrpgwDMj'
```

## Цепочки: стратегия распутывания

1. **Определите внешний слой по алфавиту** (таблица выше).
2. **Декодируйте**, смотрите на результат.
3. **Если результат — снова печатный текст** в известном алфавите, повторяйте.
4. **Если результат — бинарный мусор**, возможно, дошли до шифротекста/хэша/сжатия (проверьте магические байты `1f 8b` gzip, `PK` zip, `\x89PNG`).

```python
import base64, codecs, re

def auto_decode(s, max_layers=10):
    for _ in range(max_layers):
        if re.fullmatch(r'[0-9a-fA-F]+', s) and len(s) % 2 == 0:
            s = bytes.fromhex(s).decode('latin1')
        elif re.fullmatch(r'[A-Z2-7]+=*', s):
            s = base64.b32decode(s + '=' * (-len(s) % 8)).decode('latin1')
        elif re.fullmatch(r'[A-Za-z0-9+/]+=*', s):
            s = base64.b64decode(s + '=' * (-len(s) % 4)).decode('latin1')
        else:
            break
    return s

print(auto_decode("4e4253575933504b4e525557593433544f4e5158454e4a5747354a544b4e525553534B4A4B4E35575335425A463435544D4E525547513354474E5A5648553D3D3D"))
```

## Практический пример: кастомный алфавит

Дана строка `QmFzZTY0IGlzIGVhc3k=` — это base64 → `Base64 is easy`. Но если строка «не декодируется», возможно, алфавит переставлен. Порядок восстановления: сравните частоты символов с ожидаемыми (для base64 ASCII-текста `=` в конце, распространённые символы — `A`, `B`, ...). Иногда алфавит лежит в коде сервера.

## Пишем универсальный декодер base-N

Иногда стандартные библиотеки не подходят (кастомный алфавит, base-N без выравнивания). Универсальный декодер работает так: сопоставляем каждому символу его индекс в алфавите, затем собираем биты и группируем в байты.

```python
def baseN_decode(s, alphabet):
    """Декодирование base-N (N = len(alphabet)) в байты."""
    n = len(alphabet)
    idx = {c: i for i, c in enumerate(alphabet)}
    # число = сумма digit * n^position
    num = 0
    for ch in s:
        num = num * n + idx[ch]
    # переводим число в байты
    length = (num.bit_length() + 7) // 8
    return num.to_bytes(length, "big")

# base58
b58 = "123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz"
print(baseN_decode("8KLrpgwDMj", b58))
# base62
b62 = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz"
print(baseN_decode("...", b62))
```

Для base64 этот подход нужно адаптировать: там нет «числа с ведущими нулями», а есть поток битов по 6, группируемый в байты. Общий приём: `bits = "".join(bin(idx[c])[2:].zfill(k) for c in s)`, затем режем по 8 бит.

## Скрытые данные в кодировках

Кодировки часто служат контейнером для стеганографии:

- **Base64 с «нулевыми» битами:** последние 2 бита каждого base64-символа иногда не влияют на декодированный байт — в них прячут сообщение.
- **Многослойная base64:** строка декодируется в другую base64-строку; слой может быть очень глубоким.
- **Base64 с нестандартным алфавитом** как обфускация.
- **Нулевые байты в hex** (`00`) как разделители скрытых сообщений.

## CyberChef: рецепты и автоматизация

CyberChef — стандартный инструмент для цепочек. Полезные операции: `From Base64`, `From Base32`, `From Hex`, `From Charcode`, `From Quoted Printable`, `ROT13`, `XOR`, `Gunzip`, `Detect File Type`. «Magic» подбирает цепочку, но проверяйте результат вручную — он ошибается. Рецепт можно сохранить в JSON и применять к файлам в CLI.

## Base64 без выравнивания и «грязные» строки

Реальные данные часто приходят «грязными»: с переносами строк (MIME разбивает base64 на 76-символовые строки), пробелами, отсутствующим padding. Прежде чем декодировать — очистите:

```python
import base64, re
s = "SGVs\nbG8s\nIHdv\ncmxk\nIQ"   # переносы каждые 4-5 символов
clean = re.sub(r'\s+', '', s)          # убрать все пробелы/переносы
clean += '=' * (-len(clean) % 4)       # добить padding
print(base64.b64decode(clean))          # b'Hello, world!'
```

Обратная ситуация — **лишние символы** в конце (иногда padding `=` больше, чем нужно). Попробуйте варианты: 0, 1, 2 `=`.

## Кодирование поверх сжатия

Частый паттерн: данные сжали (gzip/zlib), затем закодировали в base64. Признак — после декодирования base64 получаете бинарный мусор, начинающийся с `1f 8b` (gzip) или `78 9c`/`78 01`/`78 da` (zlib). Тогда:

```python
import base64, gzip, zlib
raw = base64.b64decode(s)
if raw[:2] == b'\x1f\x8b':
    print(gzip.decompress(raw))
else:
    print(zlib.decompress(raw))
```

## Кодировки в контексте: как отличить от шифра и хэша

- **Кодировка** — детерминирована, без ключа, предсказуемая длина (base64 = `ceil(n/3)*4`, base32 = `ceil(n/5)*8`).
- **Шифр** — бинарный или «случайный» вывод; в текст его оборачивают base64/hex. То есть base64 часто лишь внешняя обёртка шифротекста.
- **Хэш** — фиксированная длина (32/40/64 hex для MD5/SHA-1/SHA-256), не декодируется в осмысленное.
- **Сжатие** — магические байты `1f 8b`/`78 9c`; после декодирования base64 вы попадаете прямо на них.

Приём: декодируйте слой и оцените **энтропию** результата. Осмысленный текст → вероятно, есть ещё слой. Случайные байты → дошли до шифротекста или хэша.

## Частые ошибки

- **Путать base64 и base32.** Разные алфавиты и выравнивание.
- **Забывать padding.** Допишите `=` до кратности.
- **Не учитывать URL-safe.** `-`/`_` вместо `+`/`/`.
- **Считать, что «не декодируется» = не та кодировка.** Возможно, кастомный алфавит.
- **Игнорировать магические байты** после декодирования (сжатие/архив).
- **Портить hex-дампы** — очистите адреса/ASCII перед `fromhex`.

## Как не застрять

- **Составьте таблицу алфавитов** и сверяйтесь.
- **Автоматизируйте цикл** декодирования.
- **Проверяйте регистр** (base32 — заглавные).
- **Декодируйте в байты**, потом смотрите на них как на текст/бинарник.
- **Ищите кастомный алфавит в исходниках** задачи.
- **Помните: кодирование — не защита.**
