## Вопрос, с которого всё начинается

В прошлом уроке мы разобрали, чем кодирование отличается от шифрования: кодирование обратимо **без ключа**. Значит, в любой задаче внешний слой — почти всегда кодирование, и его надо просто распознать и снять. Вопрос новичка: «Мне дали длинную строку символов. Как за секунды понять, что это за кодирование — и что делать, если слоёв несколько?»

## Наш пример

В файле `challenge.txt` лежит одна строка:

```
4834734941414141414141432f30764c535579765473314c4e6b6a4a7a4573766a6b38734d6f35504b38327242514464423472674677414141413d3d
```

Больше ничего. Мы проведём её через весь урок и достанем флаг. А в конце тем же флагом покажем, как выглядят «соседние» кодирования — чтобы вы научились узнавать их по алфавиту.

## Шаг 1: первый слой — hex

Смотрим на строку: только символы `0-9a-f`, длина чётная. Это **base16** (hex): каждые два символа — один байт. Снимаем слой через `xxd` или Python:

```bash
$ python3 -c "print(bytes.fromhex('4834734941...').decode())"
H4sIAAAAAAAC/0vLSUyvTs1LNkjJzEsvjk8sMo5PK82rBQDdB4rgFwAAAA==
```

Получили строку, оканчивающуюся на `==`. Это уже другой алфавит — идём дальше.

## Шаг 2: второй слой — base64 и «грязные» строки

Результат начинается с `H4sI`, содержит `+` и `/` и заканчивается `==` — типичный **base64** (алфавит `A–Z a–z 0–9 + /`, выравнивание `=`). В Python декодируем `base64.b64decode`. Но реальные данные часто приходят «грязными»: с переносами строк (MIME режет base64 на куски по 76 символов) или без padding. Тогда сначала чистим:

```python
import base64, re
s = "ZmxhZ3tl\nbmMwZGlu\nZ3NfYXIz\nX2Z1bn0="   # переносы каждые 8 символов
clean = re.sub(r'\s+', '', s)
clean += '=' * (-len(clean) % 4)          # добить padding до кратности 4
print(base64.b64decode(clean))
```

```
b'flag{enc0dings_ar3_fun}'
```

Две вещи, которые ломают новичков: **забытый padding** (допишите `=` до кратности) и **URL-safe вариант** (там `-` и `_` вместо `+` и `/` — используйте `b64decode(..., altchars=b'-_')`).

## Шаг 3: третий слой — магические байты

Применим это к нашему примеру: декодируем base64 и посмотрим на первые два байта результата.

```python
import base64
raw = base64.b64decode("H4sIAAAAAAAC/0vLSUyvTs1LNkjJzEsvjk8sMo5PK82rBQDdB4rgFwAAAA==")
print(raw[:2].hex())
```

```
1f8b
```

`1f 8b` — это **магические байты** gzip. Магические байты — первые байты файла, по которым определяют его формат. Значит, следующий слой — не текст, а **сжатие**. Распаковываем:

```python
import gzip
print(gzip.decompress(raw).decode())
```

```
flag{enc0dings_ar3_fun}
```

Флаг получен. Запомните магические байты, которые чаще всего встречаются: `1f 8b` — gzip, `78 9c`/`78 01`/`78 da` — zlib, `50 4b` (`PK`) — zip, `89 50 4e 47` — PNG. Если после декодирования base64 вы видите такой префикс — это сжатие или архив, а не текст.

## Шаг 4: как распознавать другие алфавиты

Теперь — тот же флаг, но другими кодированиями. Сравните алфавиты, и вы научитесь узнавать их мгновенно.

| Кодирование | Как выглядит наш флаг | Признак |
|---|---|---|
| base64 | `ZmxhZ3tlbmMwZGluZ3NfYXIzX2Z1bn0=` | `A–Za–z0–9+/`, padding `=` |
| base32 | `MZWGCZ33MVXGGMDENFXGO427MFZDGX3GOVXH2===` | только `A–Z` и `2–7`, много `=` |
| ascii85 | `Ao(mgHY%))0P"m8B6.EgE\h'7F`)U` | в PDF/PostScript, часто обрамлён `<~ ~>` |
| base85 | `W^7?+du488Fl1?NXLDa+ax-6Mb#8q` | плотный печатный ASCII |
| quoted-printable | `flag{enc0dings_ar3_fun}` | `=XX` для спецсимволов, в email |
| uuencode | `79FQA9WME;F,P9&EN9W-?87(S7V9U;GT` | заголовок `begin <mode> <name>` |

Правила простые. **Base32** — заглавные буквы и цифры `2–7`, никаких `0`, `1`, `8`, `9`. **Ascii85** встречается в PDF и PostScript, обрамляется `<~ ... ~>`. **Quoted-printable** — это email: непечатаемые байты кодируются как `=XX`. **uuencode** — старый формат для передачи бинарников по 7-битным каналам, с заголовком `begin` и строкой-счётчиком в начале каждой строки.

## Шаг 5: кастомный алфавит base64

Самая частая CTF-уловка: строка «похожа на base64», но декодируется в мусор. Причина — разработчик **переставил таблицу символов**. Решение: сопоставить символы кастомного алфавита стандартным по позиции и только потом декодировать.

```python
import base64
def decode_custom(s, alphabet):
    std = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"
    table = {c: std[i] for i, c in enumerate(alphabet)}
    mapped = "".join(table.get(c, c) for c in s)
    return base64.b64decode(mapped + "=" * (-len(mapped) % 4))
```

Где взять кастомный алфавит? Часто он лежит прямо в коде задачи (`alphabet = "..."`). Если кода нет — восстановите порядок по смыслу: в конце строки почти всегда `=` (padding), а в ASCII-тексте часты определённые символы.

## Шаг 6: распутываем цепочку автоматически

Когда слоёв может быть много, снимать их вручную лень. Пишем цикл: на каждом шаге распознаём текущий алфавит, декодируем и смотрим, стал ли результат «чище». Скелет авто-декодера:

```python
import base64, re
def auto_decode(s, max_layers=10):
    for _ in range(max_layers):
        if re.fullmatch(r'[0-9a-fA-F]+', s) and len(s) % 2 == 0:
            s = bytes.fromhex(s).decode('latin1')
        elif re.fullmatch(r'[A-Z2-7]+=*', s):
            s = base64.b32decode(s + '=' * (-len(s) % 8)).decode('latin1')
        elif re.fullmatch(r'[A-Za-z0-9+/]+=*', s):
            s = base64.b64decode(s + '=' * (-len(s) % 4)).decode('latin1')
        else:
            break
    return s
```

Дальше смотрим на результат. Осмысленный текст в известном алфавите — крутим цикл ещё раз; бинарный мусор — проверяем магические байты (`1f 8b` gzip, `78 9c` zlib, `PK` zip). Ориентир — **энтропия**: гладкий текст → вероятно, есть ещё слой; равномерно случайные байты → дошли до шифротекста или хэша, и дальше нужен уже не декодер, а ключ.

Ещё пара алфавитов, которые стоит узнавать: **base58** (Bitcoin-адреса, без символов `0`, `O`, `I`, `l`) и **base62** (только `0-9A-Za-z`, короткие ссылки). Если строка состоит только из этих символов и «не похожа на base64» — попробуйте декодер base-N: сопоставьте каждому символу его индекс в алфавите и переведите получившееся число в байты.

И главное, что стоит держать в голове: **кодирование — это не защита**. Оно не скрывает данные, а лишь меняет их представление. Если в задаче единственное «шифрование» — base64, то задача решается в одну команду.

## Что мы теперь знаем

- **Кодирование** снимается без ключа; **шифр** — только с ключом; **хэш** — необратим.
- **Hex** — только `0-9a-f`, 2 символа = 1 байт.
- **Base64** — `A–Za–z0–9+/`, padding `=`; бывает URL-safe (`-_`) и «грязный» (переносы, нет padding).
- **Base32** — `A–Z` и `2–7`, много `=`.
- После декодирования смотрим на **магические байты**: `1f 8b` = gzip, `78 9c` = zlib, `PK` = zip.
- «Похоже на base64, но мусор» → **кастомный алфавит**: мапим символы и декодируем.

## Куда дальше

Мы научились снимать внешние слои и распознавать кодирования по алфавиту. Дальше — что делать, когда под кодированием лежит **настоящий шифр**: в уроке **crypto-xor-otp** мы возьмём base64-обёртку над XOR-шифротекстом и покажем, почему повторный ключ её ломает. А пока главное: **сначала определи алфавит, потом снимай слой — и смотри на магические байты.**

## Где пригодится

- **CTF crypto/misc:** почти каждая задача начинается с распознавания кодирования.
- **Forensics:** quoted-printable/uuencode в email, base64 в веб-артефактах.
- **Bug bounty / пентест:** обфускация токенов, конфигов, payload'ов.
- **Работа (SOC/IR):** декодирование подозрительных строк в логах и малвари.
- **Разработка:** корректный выбор кодирования для бинарных данных в текстовых протоколах.
