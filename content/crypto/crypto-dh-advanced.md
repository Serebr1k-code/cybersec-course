Diffie-Hellman стойкий ровно настолько, насколько «хороши» параметры. Если `p-1` гладкое — работает Pohlig-Hellman. Если сервер не проверяет присланную точку/остаток — малые подгруппы выдают секрет по частям. А если многие сервисы используют **одно и то же** простое (как в Logjam), то одна дорогая precomputation ломает их все. Эта глава — все три атаки и корректные параметры.

## Напоминание: DH

Классический DH над `F_p`:

- публичные: `p` (простое), `g` (генератор);
- Алиса: `a` → `A = g^a mod p`; Боб: `b` → `B = g^b mod p`;
- общий секрет: `B^a = A^b = g^{ab} mod p`.

Атакующий видит `A, B, g, p` и хочет `g^{ab}` — это требует решения CDH/DDH, сводимого к дискретному логарифму (DLP). Если DLP решается — ломается и DH.

## Pohlig-Hellman при гладком p-1

DLP в `F_p` живёт в группе порядка `p-1`. Если `p-1` гладкое (разлагается на малые простые), DLP сводится к подгруппам и собирается по CRT:

1. `p-1 = Π q_i^{e_i}` с малыми `q_i`.
2. Решаем DLP в каждой подгруппе порядка `q_i^{e_i}` (перебор/BSGS).
3. Собираем показатель по CRT.

Итог: DLP за `O(√(max q_i))` вместо `O(√p)`. «Безопасное простое» (safe prime) `p = 2q+1` с простым `q` устраняет эту атаку.

## Малые подгруппы (small-subgroup)

Если сервер не проверяет `A` (или `B`), атакующий посылает элемент **малого порядка** `m`. Тогда общий секрет лежит в подгруппе порядка `m`, и по ответу восстанавливается `a mod m`. Собирая остатки для нескольких `m`, восстанавливают `a` по CRT.

- В `F_p` элемент порядка `m` существует, если `m | p-1`.
- В ECDH — точки малого порядка (см. `crypto-invalid-curve`).
- Защита: проверка, что элемент лежит в подгруппе простого порядка (для DH — `A^q == 1`, `A != 1`).

## Logjam

Logjam (2015) — атака на DH с **общим 1024-битным простым**, используемым множеством серверов:

1. **Precomputation.** Для конкретного `p` один раз вычисляется таблица для DLP в подгруппе порядка `q` (сложность зависит от размера `q`).
2. **Online.** Для каждого соединения по таблице быстро восстанавливается сессионный ключ.

Дополнительно: **downgrade** до `DHE_EXPORT` (512-битное простое) делает атаку реальной за минуты. Выводы: используйте уникальные `p` ≥ 2048 бит, либо (лучше) ECDH/Curve25519.

## Invalid-curve для ECDH

Аналог малых подгрупп для эллиптических кривых: точка не проверяется, атакующий посылает точку на twist/другой кривой с гладким порядком → утечка `d` по частям. Подробно — в `crypto-invalid-curve`. В X25519 защищает clamping.

## Safe primes и выбор параметров

- **`p` — безопасное простое:** `p = 2q + 1`, `q` простое. Тогда `p-1` имеет большой простой множитель, и Pohlig-Hellman не работает.
- **`p` ≥ 2048 бит** (лучше 3072+), уникальное для сервиса.
- **`g` — генератор подгруппы простого порядка `q`** (или проверка `g^q == 1`).
- **Проверка присланных значений:** `1 < A < p-1` и `A^q == 1`.
- **Предпочтение ECDH/X25519** — нет проблем с гладкостью `p-1`, нет precomputation.

# small-subgroup оракул: восстановление a mod m
residues = []
for m, elem in small_order_elements:

    r = brute_log(recv(), elem, m)   # a mod m

## Разобранный пример: гладкое p-1

Дано: `p`, `g`, `A = g^a mod p`, и `p-1` гладко. Восстанавливаем `a`:

```python
from sage.all import GF, discrete_log
F = GF(p)
a = discrete_log(F(A), F(g))   # Sage применяет Pohlig-Hellman автоматически
print(a)
```

Если Sage не тянет — разложите `p-1`, решите по подгруппам вручную и соберите CRT. Для малых подгрупп (оракул) — соберите остатки от сервера.

## Распознавание в CTF и decision

1. Дано `p`, `g`, `A` и `p-1` гладко → Pohlig-Hellman (`discrete_log`).
2. Сервер принимает произвольный `A` без проверки → малые подгруппы + CRT.
3. Одно простое используется многими → Logjam (precomputation).
4. ECDH без валидации точки → invalid-curve (`crypto-invalid-curve`).
5. `p` безопасное и большое → DLP нереален, ищите другую уязвимость.
6. Реализация — X25519 → clamping защищает от small-subgroup.

## Частые ошибки и тупики

- **Забыть проверить гладкость `p-1`.** Без неё Pohlig-Hellman не работает.
- **Не проверить порядок `g`.** `g` может быть не генератором.
- **Путать DLP и CDH.** Атаки на DLP ломают DH; прямой CDH-алгоритм не нужен.
- **Игнорировать оракул.** Один запрос даёт `a mod m` — используйте все.
- **Считать 1024-битное `p` безопасным.** Logjam показывает обратное.
- **Неверная CRT-сборка.** Проверяйте, что `M > порядок`.

## Полный разбор: Logjam-подобная атака

Сценарий: сервис использует общее 512-битное простое `p` (например, из экспортного набора) и подгруппу порядка `q`, где `q` — 160-битное простое. Тогда:

1. **Offline.** Для этого `p` вычисляется таблица дискретных логарифмов в подгруппе порядка `q` (сложность ~`2^80` для 160-битного `q`, но для 512-битного `p` и меньшего `q` — быстрее).
2. **Online.** Для каждого сессионного `A = g^a` по таблице находится `a`, затем `g^{ab}`.

Если `q` мал (например, `p` гладкое), шаг 1 вообще не нужен — прямой Pohlig-Hellman. Практический вывод: одно и то же простое в тысячах соединений амортизирует стоимость precomputation почти до нуля. Защита — уникальные `p` ≥ 2048 бит или (лучше) ECDH с prime-order кривой.

```python
# проверка «гладкости» p-1 в задаче
from sympy import factorint
print(sorted(factorint(p - 1).keys()))   # если все малы -> Pohlig-Hellman
```

## Чек-лист: слабые параметры DH

- `p-1` гладкое → Pohlig-Hellman (`factorint(p-1)` показывает малые простые);
- сервер принимает произвольный `A` без проверки `A^q == 1` → малые подгруппы;
- `p` маленькое (512–1024 бит) или общее для многих → Logjam;
- `g` не генератор простого порядка → утечка;
- ECDH без валидации точки → invalid-curve;
- реализация на Curve25519 без clamping → twist.

Начните с `factorint(p-1)`: если все множители малы — задача решается `discrete_log` в Sage. Если нет — проверьте, есть ли оракул (принимает ли сервер точки малого порядка).

## Быстрые рецепты для CTF

- **`factorint(p-1)` гладкое** → `discrete_log` в Sage.
- **Сервер без проверки `A`** → малые подгруппы + CRT.
- **Общее слабое `p`** → Logjam (precomputation).
- **ECDH без валидации** → `crypto-invalid-curve`.
- **X25519** → clamping защищает.
