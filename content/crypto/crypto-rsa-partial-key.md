RSA падает не от факторизации `n`, а от **утечки части ключа**: нескольких старших бит `p`, значения `dp = d mod (p-1)`, куска `d`. Часто такие утечки даёт побочный канал (тайминг, кэш) или небрежная реализация. В CTF это задачи «дано `n`, `e` и, скажем, `dp`» или «известны старшие 200 бит `p`». Здесь — полный набор техник восстановления.

## Что такое partial key exposure

Утечка **части** секретного параметра RSA (не всего):

- старшие/младшие биты `p` или `q`;
- `dp = d mod (p-1)` или `dq`;
- часть бит `d`;
- комбинация нескольких частичных утечек.

Цель — восстановить полный ключ. Метод зависит от того, **какие** биты и **насколько много** известны.

## Известны старшие биты p

Если известно `p_high` (старшие биты `p`) и `n = p·q`, то `p` — малый корень полинома `f(x) = p_high + x` по модулю `n`... точнее, `f(x) ≡ 0 mod p`. Применяем **Coppersmith** (малые корни `mod` неизвестного делителя):

```python
# Sage: Coppersmith для восстановления p по старшим битам
n = ...
p_high = ...
k = ...            # сколько младших бит неизвестно (2^k)
R = 2^k
PR.<x> = PolynomialRing(Zmod(n))
f = p_high + x
roots = f.small_roots(X=R, beta=0.5)
p = p_high + int(roots[0])
```

Условие: известно примерно **половина** старших бит `p` (`p_high ≈ p / 2^k`, `2^k < n^{1/4}` — точнее, по границе Coppersmith `X < n^{β²/deg}`). Для 1024-битного `p` нужно ~512 известных старших бит.

## Известны младшие биты p

Если известны младшие биты `p mod 2^k`, старшие восстанавливаются **перебором** от младших к старшим:

```
p ≡ p0 (mod 2^k)
n ≡ 0 (mod p)  =>  перебираем p = p0 + t·2^k и проверяем n % p == 0
```

Число вариантов `≈ 2^{bits_unknown}`, но проверка `n % p` отсеивает быстро. Если известно больше половины младших бит — перебор реален.

```python
p0, k = ..., ...     # младшие биты
for t in range(1 << (p.bit_length() - k)):
    cand = p0 + (t << k)
    if n % cand == 0:
        print("p =", cand); break
```

## Утечка dp = d mod (p-1)

Очень частый случай. Известно `dp`, `e`, `n`. Тогда:

```
e·dp ≡ 1 (mod p-1)  =>  e·dp - 1 = k·(p-1)  для некоторого k < e
```

Перебираем `k ∈ [1, e-1]` (для `e=65537` это до 65536 итераций) и проверяем `(e·dp - 1) % k == 0`; тогда `p = (e·dp - 1)/k + 1` — кандидат; проверяем `n % p == 0`.

```python
for k in range(1, e):
    if (e * dp - 1) % k == 0:
        p = (e * dp - 1) // k + 1
        if n % p == 0:
            print("p =", p); break
```

Это упрощённая версия атаки Heninger-Shacham. При наличии `dp` и `dq` — факторизация гарантирована.

## Утечка битов d

Если известны старшие или младшие биты `d`:

- **Младшие биты `d`:** `d` связан с `p, q` через `e·d = 1 + k·φ(n)`; для малого `e` можно восстановить `d mod 2^k`, затем факторизовать.
- **Старшие биты `d`:** атака Boneh-Durfee/Frankel: `e·d_high` даёт приближение `k·(p+q)`, что позволяет восстановить `p, q` при достаточном числе бит.
- **Малый `d` (Wiener):** если `d < n^{0.25}`, работает цепная дробь (`crypto-rsa-wiener-bonedurfee`).

## Утечка через побочный канал

- **Timing (Kocher):** время модульного возведения утекает биты `d` (`crypto-timing`).
- **Power/cache:** утечка битов экспоненты.
- **Fault:** испорченная подпись даёт факторизацию (`crypto-rsa-faults`).
- **Шум/сеть:** иногда утекает `p mod 2^k` через размеры сообщений.

## Разобранный пример: dp утечка

Дано: `n`, `e=65537`, `dp`. Восстанавливаем `p`, затем `q` и `d`:

```python
for k in range(1, e):
    if (e * dp - 1) % k == 0:
        p = (e * dp - 1) // k + 1
        if n % p == 0:
            q = n // p
            d = pow(e, -1, (p-1)*(q-1))
            m = pow(c, d, n)
            print(bytes.fromhex(hex(m)[2:]))
            break
```

Проверка: `p*q == n`, `pow(pow(m, e, n), d, n) == m`.

## Частые ошибки и тупики

- **Мало известных старших бит для Coppersmith.** Нужно ~половина; иначе — не сработает.
- **Забыть про `k` в `e·dp - 1 = k(p-1)`.** Перебирайте `k` до `e`.
- **Путать `dp` и `d`.** `dp = d mod (p-1)`, не сам `d`.
- **Не проверить `n % p == 0`.** Кандидатов много; подтверждайте.
- **Младшие биты без перебора.** Их нельзя «достроить» Coppersmith'ом так же, как старшие.
- **Игнорировать малый `e`.** Для `e=3` перебор `k` тривиален.
- **Считать один бит достаточным.** Нужно много (сотни).

## Что дальше (decision)

1. Известны старшие биты `p` → Coppersmith `small_roots`.
2. Известны младшие биты `p` → перебор от младших.
3. Известно `dp`/`dq` → Heninger-Shacham (перебор `k`).
4. Известны биты `d` → Wiener/Boneh-Durfee/Frankel.
5. Утечка из side-channel → `crypto-timing`, `crypto-power`.
6. Ошибочная подпись → `crypto-rsa-faults`.

## Справочная таблица

| Утечка | Метод | Сколько нужно |
|--------|-------|---------------|
| старшие биты `p` | Coppersmith | ~половина `p` |
| младшие биты `p` | перебор | ~половина `p` |
| `dp`/`dq` | Heninger-Shacham | одно значение |
| старшие биты `d` | Boneh-Durfee/Frankel | ~половина `d` |
| малый `d` | Wiener (цепные дроби) | `d < n^{0.25}` |

## Полный разбор: Coppersmith по старшим битам p

Дано: `n` (1024 бита), `e`, `p_high` — старшие 600 бит `p` (младшие 424 неизвестны). Строим `f(x) = p_high + x`, где `x < 2^{424}`, и ищем малый корень по модулю неизвестного делителя `p` (известно, что `p ≈ n^{0.5}`, то есть `β = 0.5`):

```python
# Sage
n = ...
p_high = ...
X = 2**424
PR.<x> = PolynomialRing(Zmod(n))
f = p_high + x
roots = f.small_roots(X=X, beta=0.5)
assert roots, "увеличьте известную часть или проверьте X"
p = int(p_high + roots[0])
assert n % p == 0
q = n // p
```

Ключевой момент — граница: Coppersmith для делителя `p ≈ n^{β}` находит корни `x < n^{β²/deg}`. Для `β=0.5`, `deg=1` это `X < n^{0.25}`. Значит, для 1024-битного `n` можно восстановить `p`, если неизвестно не более ~256 младших бит (известно ~256 старших). Если известно меньше — нужен многомерный Coppersmith или другой подход.

## Быстрые рецепты для CTF

- **Старшие биты `p`** → Coppersmith `small_roots`.
- **Младшие биты `p`** → перебор от младших.
- **Дано `dp`/`dq`** → перебор `k` в `e·dp - 1 = k(p-1)`.
- **Биты `d`** → Wiener/Boneh-Durfee.
- **Side-channel** → `crypto-timing`, `crypto-power`.
