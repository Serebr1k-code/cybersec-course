Commitment — криптографический «запечатанный конверт»: вы фиксируете значение, не раскрывая его, и позже не можете его изменить. Из commitment-схем вырастают доказательства с нулевым разглашением (ZK), а сигма-протокол Schnorr + Fiat-Shamir — это уже почти готовая подпись (в том числе в EdDSA). В CTF это класс задач «сервер бросает challenge, я отвечаю», где ломается предсказуемость nonce или отсутствие привязки.

## Что такое commitment

Схема commitment состоит из двух фаз:

- **Commit:** вы фиксируете `m`, публикуя `c = Commit(m, r)`.
- **Reveal:** вы раскрываете `(m, r)`, и проверяющий убеждается, что `c` соответствует `m`.

Требуемые свойства:

- **Hiding** — по `c` нельзя узнать `m` (до раскрытия).
- **Binding** — нельзя раскрыть `c` как другое `m'` (после commit).

Компромисс: нельзя получить и идеальное hiding, и идеальное binding одновременно.

## Хэш-commitment

Простейшая схема: `c = H(r || m)`, где `r` — случайная соль. Hiding обеспечивается солью, binding — стойкостью хэша к коллизиям. Если `r` отсутствует, `m` из малого множества (например, «орёл/решка») подбирается перебором. Если хэш уязвим к length extension — commit можно «продлить» (см. `crypto-hmac`).

## Schnorr-протокол (proof of knowledge)

Доказательство знания дискретного логарифма `x` для `X = xG`:

1. **Commit:** доказывающий выбирает случайный `r`, отправляет `R = rG`.
2. **Challenge:** проверяющий бросает `c`.
3. **Response:** доказывающий отправляет `s = r + c·x mod n`.
4. **Verify:** проверяющий убеждается, что `sG == R + cX`.

Это «сигма-протокол»: 3 шага, zero-knowledge, special soundness. Знание `x` не раскрывается: `s` маскирован случайным `r`.

## Fiat-Shamir: превращение в подпись

Чтобы сделать интерактивный протокол неинтерактивным, `c` заменяют хэшем транскрипта: `c = H(R || X || m)`. Тогда `(R, s)` — это подпись (Schnorr/EdDSA). Критично: хэшировать **всё** (включая `R`, `X`, `m`), иначе возможна подделка.

## Pedersen commitment

`c = mG + rH`, где `H` — вторая точка с неизвестным дискретным логарифмом относительно `G`. Свойства:

- **Hiding:** `r` случаен.
- **Binding:** следует из трудности дискретного логарифма.
- **Гомоморфность:** `Commit(m1)+Commit(m2) = Commit(m1+m2)` — основа для range-proofs, MPC, Bulletproofs.

## Атаки

- **Слабый/предсказуемый nonce `r`.** Если `r` повторяется или утекает (например, из тайминга), из двух ответов `s` восстанавливается `x` (как в ECDSA, см. `crypto-ecdsa-nonce`).
- **Отсутствие привязки.** `c = H(m)` без соли — binding ломается, если `m` из малого множества (перебор).
- **Fiat-Shamir с неполным транскриптом.** Если `c = H(m)` без `R`/`X`, можно подобрать `R` под заранее выбранный `c` → подделка.
- **Weak Fiat-Shamir.** Хэширование только части данных; атака на «магические» значения.
- **Малые подгруппы.** Если `G` не проверяется, ответы могут «сворачиваться» — см. `crypto-invalid-curve`.
- **Replay/повтор challenge.** Если challenge фиксирован, ответ переиспользуется.

## Инструменты и код

```python
# Schnorr proof of knowledge (учебная реализация)
from hashlib import sha256
p = 0x...; g = 2; n = p - 1
x = 12345; X = pow(g, x, p)

r = int.from_bytes(sha256(b'seed').digest(), 'big') % n
R = pow(g, r, p)
c = int.from_bytes(sha256(f"{R}{X}".encode()).digest(), 'big') % n
s = (r + c * x) % n
assert pow(g, s, p) == (R * pow(X, c, p)) % p
```

## Разобранный пример: восстановление `x` из двух ответов

Дано: два доказательства с **одинаковым** `R` (повтор `r`), challenge `c1 ≠ c2`, ответы `s1, s2`.

```
s1 = r + c1·x
s2 = r + c2·x
=> s1 - s2 = (c1 - c2)·x  =>  x = (s1 - s2) / (c1 - c2) mod n
```

Это ровно атака «nonce reuse», как в ECDSA. Проверка: `xG == X`.

## Частые ошибки и тупики

- **Забыть соль в хэш-commitment.** Binding/hiding рушатся.
- **Хэшировать не весь транскрипт в Fiat-Shamir.** Подделка подписи.
- **Повтор `r`.** Восстановление секрета из двух ответов.
- **Не проверять `G` на малую подгруппу.** Invalid-curve.
- **Считать commitment шифрованием.** Это не конфиденциальность, а фиксация.
- **Путать hiding и binding.** Это разные свойства и разные гарантии.

## Что дальше (decision)

1. Задача «сервер бросает challenge» → ищите предсказуемый/повторный `r`.
2. Хэш-commitment без соли → перебор `m`.
3. Fiat-Shamir-подпись → проверьте полноту транскрипта.
4. Нужен range-proof/MPC → Pedersen + гомоморфность.
5. Группа не проверяется → `crypto-invalid-curve`.
6. Подпись на Schnorr/EdDSA → `crypto-edwards`, `crypto-ecdsa-nonce`.

## Полный разбор: атака на сервер с неполным Fiat-Shamir

Сервер реализует proof-of-knowledge и вычисляет challenge как `c = H(m)` — **без** `R` и `X`. Это классическая ошибка «weak Fiat-Shamir». Тогда атакующий выбирает произвольные `s` и `c`, вычисляет `R = sG - cX` и отправляет `(R, s)`; проверка `sG == R + cX` выполняется тождественно, а знания `x` не требуется вовсе.

```python
import random
n = curve_order
s = random.randrange(n)
c = random.randrange(n)     # сервер возьмёт c = H(m), подберём m с таким хэшем или атакуем иначе
R = s*G - c*X               # G, X — точки кривой
# пара (R, s) проходит проверку sG == R + cX без знания x
```

Если сервер вычисляет `c = H(R || X || m)`, подделка невозможна: изменение `R` меняет `c`. Отсюда правило: в Fiat-Shamir хэшируется **весь** транскрипт, включая commitment. Проверяйте это в любой задаче «докажи знание».

Дополнительный вектор — **повтор challenge**: если сервер не хранит выданные `c`, ответ на старый `c` можно переиспользовать в новом сеансе. И **отсутствие привязки `R` к сеансу** позволяет переставлять `R` между сессиями.

## Чек-лист: признаки ZK/commitment-задачи

- сервер присылает случайный **challenge** и ждёт ответ;
- протокол состоит из трёх шагов (commit → challenge → response);
- в условии «докажи знание», «proof of knowledge», «commitment», «Schnorr»;
- даны `(R, s)` или `(c, s)` и нужно «пройти проверку» без ключа;
- утечка/повтор `r` или предсказуемый challenge;
- Fiat-Shamir-подпись, где `c` зависит не от всего транскрипта.

Быстрая проверка: вычислите, что именно хэшируется в challenge. Если `R` не входит в хэш — это weak Fiat-Shamir и подделка тривиальна. Если `r` повторяется между сессиями — восстановление секрета как в ECDSA.

## Быстрые рецепты для CTF

- **Повтор `r`/`R`** → восстановите `x` вычитанием ответов.
- **Weak Fiat-Shamir** → подделайте `(R, s)` без ключа.
- **Хэш-commitment без соли** → переберите `m`.
- **Нужны range-proof** → Pedersen + гомоморфность.
- **Группа не проверяется** → `crypto-invalid-curve`.
