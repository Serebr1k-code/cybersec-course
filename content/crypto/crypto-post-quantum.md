## Вопрос, с которого всё начинается

Алгоритм Шора ломает RSA, DH и ECC (`crypto-shor-grover`). Но угроза «harvest now, decrypt later» реальна уже сегодня: перехваченный сейчас трафик расшифруют, когда появится достаточно мощный квантовый компьютер. Значит, асимметрию нужно менять **сейчас**. На что? На задачи, трудные и для классики, и для кванта. Главная из них — **LWE (Learning With Errors)**. В CTF «пост-квантовые» задачи — это почти всегда **ослабленные** инстансы LWE/Kyber, которые ломаются решёточными методами. Разберём такой инстанс.

## Наш пример

Возьмём ослабленную LWE-задачу: даны матрица `A` и вектор `b = A·s + e mod q`, где `s` — **малый** секрет, `e` — малый шум. Найти `s`. Ослабление — в том, что `s` бинарный (всего 2⁵ вариантов), поэтому его можно перебрать.

```python
import numpy as np
q, n, m = 97, 5, 12
A = np.random.randint(0, q, size=(m, n))
s = np.random.randint(0, 2, size=n)          # МАЛЫЙ (бинарный) секрет
e = np.random.randint(-1, 2, size=m)         # малый шум
b = (A @ s + e) % q
print("b =", b.tolist())
```

```
b = [36, 70, 8, 45, 93, 63, 81, 73, 84, 25, 56, 0]
```

Задача: по `A` и `b` восстановить `s`, не зная `e`.

## Шаг 1: почему LWE трудна

Без шума `b = A·s` — это обычная линейная алгебра: `s` находится за одно исключение Гаусса. **Шум** `e` всё ломает: уравнения «почти» верны, и точного решения нет. Именно «почти линейность + шум» делает LWE трудной и для классического, и для квантового компьютера. Стойкость определяется размерностью `n` и отношением `q/σ` (модуль к шуму).

**MLWE (Module-LWE)** — та же идея в кольце/модуле над полиномами, компактнее и быстрее; на ней построены Kyber и Dilithium. **SIS** (Short Integer Solution) — родственная задача, основа хэш-подписей. **NTRU** — кольцо усечённых полиномов, прямой предок Kyber.

## Шаг 2: ломаем ослабленный инстанс

Ключевая идея атаки: перебрать малые секреты и выбрать тот, у которого **невязка** `b - A·s` минимальна (центрируем по модулю, чтобы `-1` и `q-1` считались близкими).

```python
best, bestres = None, 10**9
for cand in range(2**n):
    sv = np.array([(cand >> i) & 1 for i in range(n)])
    r = (b - A @ sv) % q
    r = np.minimum(r, q - r)                 # невязка с учётом модуля
    res = int(np.sum(np.abs(r)))
    if res < bestres: bestres, best = res, sv
print("истинный секрет:", s.tolist())
print("восстановлен   :", best.tolist(), "  невязка:", bestres)
```

```
истинный секрет: [1, 0, 0, 0, 1]
восстановлен   : [1, 0, 0, 0, 1]   невязка: 6
```

Секрет восстановлен. На «боевых» Kyber-параметрах такой перебор невозможен (секрет и размерность огромны), поэтому там применяют решёточные методы — LLL/BKZ (`crypto-lattice-bkz`). В CTF параметры всегда ослабляют, и задача становится решаемой.

## Шаг 3: ослабление через повтор случайности

Второй классический вектор — повтор `r` между инкапсуляциями KEM. Если в двух обменах используется один и тот же `r`, то `u` совпадает, а `v` отличается только на `encode(m)`. XOR двух `v` даёт XOR сообщений — как **many-time pad** в потоковом шифре:

```python
m1, m2 = 0b10110, 0b01101
r = 777
print(bin((m1 ^ r) ^ (m2 ^ r)), bin(m1 ^ m2))
```

```
0b11011 0b11011
```

Утечка XOR сообщений видна сразу. Это ровно та же ошибка, что повтор nonce в ECDSA, только в PQ-обёртке.

## Шаг 4: что такое Kyber, Dilithium, SPHINCS+

Стандарты NIST, которые заменяют асимметрию:

- **ML-KEM (Kyber)** — схема инкапсуляции ключа (KEM). Параметры: `n=256`, `k ∈ {2,3,4}` (Kyber512/768/1024), `q=3329`. KeyGen: `t = A·s + e`; Encaps: `u = Aᵀ·r + e1`, `v = tᵀ·r + e2 + encode(m)`; Decaps: `m' = v - sᵀ·u` (шум сокращается), затем KDF → общий ключ.
- **ML-DSA (Dilithium)** — подпись на MLWE + Fiat-Shamir: commitment `w = A·y`, challenge `c = H(w, m)`, ответ `z = y + c·s` с rejection sampling. Атаки — при утечке `y` или слабом `H`.
- **FN-DSA (Falcon)** — подпись на NTRU-решётках через «быстрый Фурье»-сэмплинг; компактные подписи, но небрежный сэмплер ломается.
- **SLH-DSA (SPHINCS+)** — stateless хэш-подпись: стойкость опирается только на хэш-функцию (консервативная опция). Внутри — одноразовые подписи WOTS+ и деревья Меркла (`crypto-merkle`).

| Схема | Тип | Задача | Стандарт |
|-------|-----|--------|----------|
| ML-KEM (Kyber) | KEM | MLWE | FIPS 203 |
| ML-DSA (Dilithium) | подпись | MLWE | FIPS 204 |
| FN-DSA (Falcon) | подпись | NTRU | FIPS 206 |
| SLH-DSA (SPHINCS+) | подпись | хэш | FIPS 205 |

## Что мы теперь знаем

- PQ-криптография нужна **сейчас** из-за «harvest now, decrypt later».
- LWE: `b = A·s + e mod q` — «почти линейная» задача, трудная из-за шума.
- MLWE лежит в основе Kyber (KEM) и Dilithium (подпись).
- Ослабленный LWE (малые `n`, `q`, бинарный секрет) ломается перебором или LLL/BKZ.
- Повтор `r` в KEM даёт many-time pad — XOR сообщений.
- Симметрика выживает: AES-256/SHA-384 стойки (Гровер даёт лишь `2^{k/2}`).

## Почему LWE считают трудной

Learning With Errors формулируется просто: дана матрица `A` и вектор `b = A·s + e mod q`, где `e` — небольшой «шум». Задача — найти `s`. Без шума это обычная линейная алгебра и решается за полиномиальное время. Именно шум `e` превращает задачу в трудную: каждый выход «размыт» на небольшую ошибку, и линейные методы перестают работать напрямую.

Почему это важно: LWE **сводится** к решению трудных задач теории решёток (SVP/CVP в худшем случае), а для решёточных задач нет известного полиномиального алгоритма ни классического, ни квантового. Более того, есть редукция «худший случай = средний случай»: если LWE трудна в среднем, то она трудна и в худшем случае. Это редкое свойство — оно даёт гарантию стойкости, а не «мы не нашли атаку».

Шум `e` — сердце стойкости. Если взять его слишком маленьким, задача решается линейными методами или решёточными атаками; если слишком большим — ломается корректность расшифрования. Проектирование схемы — это баланс параметров `n`, `q` и распределения ошибок. Kyber (ML-KEM) — это вариант MLWE (модульное LWE), где кольцо `R_q` ускоряет операции и уменьшает ключи.

## Если не сработало

- **Ослабленный инстанс не ломается решёткой.** Возможно, параметры подобраны так, что шум слишком большой для LLL/BKZ; поднимайте размерность или берите больше выборок.
- **Не хватает выборок.** LWE требует примерно `n` уравнений (или больше) для однозначного решения; ищите, не даёт ли оракул новые пары.
- **Повтор случайности.** Если при генерации `s` или `e` переиспользован seed, две сессии дают линейную связь — это ломает даже сильные параметры.
- **Путаница с NTRU/решётками.** Kyber — модульный LWE; классические решёточные атаки (LLL) работают иначе и на реальных параметрах не проходят.
- **Инструмент не тот.** Для учебных атак на ослабленный LWE берите Sage или `fpylll`; для реального Kyber — liboqs только для проверки протокола, не для взлома.

## Частые вопросы

**Ломает ли Гровер LWE?** Нет, Гровер ускоряет перебор ключа симметрики; для LWE работает решёточный криптоанализ, а не Гровер.

**Почему Kyber — «ML-KEM»?** Это стандартизованное NIST имя: Module-Lattice Key Encapsulation Mechanism; Dilithium — ML-DSA (подпись).

**Когда это станет обязательным?** Уже сейчас: NIST стандартизовал ML-KEM/ML-DSA в 2024, и миграция рекомендована как гибрид (классика + PQC), чтобы не потерять стойкость ни до, ни после появления квантового компьютера.

## Куда дальше

Мы разобрали LWE и увидели, как ослабленные параметры и повтор случайности делают PQ-схемы ломаемыми. Дальше логично углубиться в **crypto-lattice** и **crypto-ntru** — математику решёток и кольцевые конструкции, на которых всё это стоит. А пока главное запомни: **PQ-схемы стойки на стандартных параметрах, но в CTF их ослабляют — и тогда работают перебор, LLL/BKZ и many-time pad.**

## Где пригодится

- **CTF (expert):** ослабленные LWE/Kyber/Dilithium, решёточные атаки.
- **Аудит:** оценка параметров PQ-схем, side-channel.
- **Работа (стратегия):** миграция на PQ, гибридные режимы.
- **Разработка:** интеграция liboqs, PQ-TLS.
- **Сертификации:** знание актуальных криптостандартов.
