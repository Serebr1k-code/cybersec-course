## Вопрос, с которого всё начинается

Хэш с `n`-битным выходом имеет `2^n` возможных дайджестов. Казалось бы, чтобы найти коллизию, нужно перебрать порядка `2^n` сообщений. Но это не так — и в этом главная контринтуитивная идея криптографии хэшей. Из-за **парадокса дней рождения** коллизия находится уже среди `~2^(n/2)` значений. Для 128-битного хэша это `2^64` — граница, которую современные кластеры проходят. Отсюда правило: для `k`-битной стойкости нужен выход `2k` бит.

## Наш пример: 32-битный хэш

`birthday.py` задаёт детерминированную 32-битную функцию

```
H(x) = ((x·2654435761) ⊕ (x >> 13)) mod 2^32
```

и ищет коллизию, генерируя случайные `x` и запоминая дайджесты. При 32-битном выходе ожидаемое число запросов — `~2^16 = 65536`. Прогоним:

```
$ python3 birthday.py
queries to find a collision: 62512 (~2^16 = 65536 expected)
H(505869112) == H(2097928481) == 317411471 : True
birthday bound ~2^(n/2) confirmed: True
flag: nto{b1rthd4y_c0ll1s10n_2_p0w_n_0v3r_2}
```

62 512 запросов — чуть меньше ожидаемых 65 536. Это и есть birthday-граница в действии: мы нашли коллизию не за `2^32`, а за `2^16`.

## Шаг 1: парадокс дней рождения

В классе из 23 человек вероятность совпадения дней рождения > 50%. Причина: пар не 23, а `23·22/2 = 253`, и каждая может совпасть. Аналогично, если мы сгенерировали `q` значений `n`-битного выхода, число **пар** ~`q²/2`. Когда `q²/2 ≈ 2^n`, появляется коллизия, то есть `q ≈ 2^(n/2)`. Отсюда — квадратичный выигрыш по сравнению с наивными `2^n`.

## Шаг 2: meet-in-the-middle и структура

Birthday-атаку часто называют meet-in-the-middle, потому что мы «идём с двух сторон»: генерируем значения и проверяем, не встречалось ли такое же раньше (или ищем пересечение двух списков). Есть две реализации:

- **Хранение в таблице**: генерируем `q` значений, пишем дайджест→вход в хэш-таблицу, ищем повтор. Память `O(q)`, время `O(q)`.
- **Rho-метод Флойда**: без памяти, «черепаха и заяц» по детерминированной цепочке `x → H(x)`, находят цикл за `O(q)` времени и `O(1)` памяти.

Наш `birthday.py` использует первый вариант — таблицу.

## Шаг 3: rho-метод без памяти

Rho-метод полезен, когда памяти мало. Определяем функцию перехода `g(x) = H(x)` и идём по цепочке `x0, g(x0), g(g(x0)), ...`. Цепочка конечна (выход `n` бит), значит, зацикливается — и вход в цикл даёт коллизию `H(a) = H(b)` с `a ≠ b`. «Черепаха и заяц» находят цикл за `O(2^(n/2))` шагов без хранения таблицы. Это стандарт для атак на усечённые хэши в CTF.

## Шаг 4: сколько бит достаточно

Практические следствия. Если выход хэша 64 бита, birthday-атака стоит `2^32` — минуты на одном компьютере. 80 бит → `2^40` — часы. 128 бит → `2^64` — годы на кластере. 160 бит (SHA-1) → `2^80` — считалось недостижимым, но структурные атаки (chosen-prefix) сломали SHA-1 дешевле. Отсюда современный стандарт: **не меньше 256 бит** для долгоживущих систем. И помните: это про **коллизии**; для preimage стойкость `2^n`, поэтому 128-битный выход всё ещё «ок» для многих задач.

## Шаг 5: birthday не только для хэшей

Парадокс дней рождения универсален. Он бьёт: усечённые MAC-и, «одноразовые» токены с коротким случайным полем, выбор nonce случайно из маленького пространства, генераторы сессионных ID. Любое место, где два случайных `n`-битных значения могут совпасть, требует `2^(n/2)` попыток, а не `2^n`. Это частая ошибка в реализациях: «мы используем 32-битный случайный токен, значит перебор `2^32`» — нет, коллизию найдём за `2^16`.

## Если не сработало

Если коллизия не находится быстро, проверьте: (1) не инъективна ли функция — для перестановки коллизий нет вообще; (2) достаточно ли широкий выход — если 64+ бит, `2^32` запросов могут не уложиться в бюджет; (3) правильно ли выбрано пространство входов. И не путайте: birthday-атака даёт **любую** коллизию, а не second-preimage для заданного сообщения — для второго нужно `2^n`.

## Что мы теперь знаем

- Birthday: коллизия находится среди `~2^(n/2)` значений.
- Причина — число пар растёт квадратично.
- Meet-in-the-middle хранит таблицу, rho-метод — нет.
- Для `k`-битной стойкости нужен выход `2k` бит.
- 32-битный выход ломается за `2^16`.
- Birthday бьёт любые короткие случайные поля, не только хэши.
