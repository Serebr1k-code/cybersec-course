ECDSA ломается не в математике кривой, а в **случайности nonce**. Если `k` повторён — ключ восстанавливается из двух подписей двумя вычитаниями. Если `k` лишь частично предсказуем (усечён, смещён, сгенерирован слабым PRNG) — ключ восстанавливается решёточными методами. Это одна из самых частых и самых «денежных» уязвимостей: именно так теряли биткоины (Sony PS3, многочисленные кошельки). Здесь — полный практический цикл.

## ECDSA: формула подписи

Дано: `d` — приватный ключ, `z` — хэш сообщения (как число), `n` — порядок базовой точки.

1. Выбрать случайный `k ∈ [1, n-1]`.
2. `R = k·G`; `r = x(R) mod n`.
3. `s = k^{-1}(z + r·d) mod n`.
4. Подпись — `(r, s)`.

Отсюда ключевое уравнение: `k ≡ s^{-1}(z + r·d) (mod n)`.

## Переиспользование nonce (k)

Если два сообщения подписаны одним `k` (одинаковый `r`):

```
s1 = k^{-1}(z1 + r·d)
s2 = k^{-1}(z2 + r·d)
```

Вычитаем: `s1 - s2 = k^{-1}(z1 - z2)`, откуда

```
k = (z1 - z2) · (s1 - s2)^{-1} mod n
d = (s1·k - z1) · r^{-1} mod n
```

Совпадение `r` у двух подписей — мгновенный красный флаг. Скрипт:

```python
n = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141  # secp256k1
def recover(z1, s1, z2, s2, r):
    k = (z1 - z2) * pow(s1 - s2, -1, n) % n
    d = (s1 * k - z1) * pow(r, -1, n) % n
    return d
```

## Смещённый/усечённый nonce (biased nonce)

Сложнее и интереснее: `k` не повторяется, но известны его **старшие биты** (например, `k < 2^l` или `k = k_high·2^l + k_low` с малым `k_low`). Это **hidden number problem (HNP)**: восстановление `d` из набора уравнений `k_i ≡ s_i^{-1}(z_i + r_i·d)`, где `k_i` «малы».

Переписываем: `d·r_i·s_i^{-1} - k_i·s_i^{-1} + z_i·s_i^{-1} ≡ 0`. Каждое уравнение даёт приближение к `d` с малой ошибкой `k_i`. Строим решётку и применяем LLL/BKZ.

## Решёточная атака (hidden number problem)

Стандартная конструкция (для `m` подписей, известны старшие биты `k_i`, т.е. `|k_i| < 2^l`):

```python
# Sage
n = ...            # порядок
t = [ (s_i^{-1} * r_i) % n for i in range(m) ]   # коэффициенты при d
u = [ (s_i^{-1} * z_i) % n for i in range(m) ]   # свободные члены
B = 2**l           # граница для k_i

M = Matrix(QQ, m + 2, m + 2)
for i in range(m):
    M[i, i] = n
    M[m, i] = t[i]
    M[m+1, i] = u[i]
M[m, m] = B / n
M[m+1, m+1] = B
Bred = M.LLL()
# среди коротких векторов ищем кандидата d
for row in Bred.rows():
    d_cand = abs(row[m]) * n / B
    if 0 < d_cand < n:
        print(d_cand)
```

Число нужных подписей растёт при уменьшении известной части `k`. Если известно лишь 1–2 бита — нужны десятки/сотни подписей; если известна половина — хватает нескольких.

## Разобранный пример: усечённый nonce

Сервер генерирует `k = random.getrandbits(64)` (то есть `k < 2^64`, старшие 192 бита нули). Собираем ~5 подписей и строим решётку с `B = 2^64`. LLL находит `d`. Проверка: `d·G == публичный ключ`.

Если nonce ещё уже (16 бит) — хватает 3–4 подписей. Если известны старшие биты частично (например, `k` из слабого PRNG) — та же техника с другим `B`.

## Варианты: EdDSA, Schnorr

- **EdDSA** детерминирован (`r = H(prefix||m)`) — повтор `k` невозможен при корректной реализации.
- **Schnorr** с внешним nonce — та же атака; с детерминированным — нет.
- **Nonce из слабого PRNG** (MT19937, LCG) — восстановите состояние PRNG (`crypto-python-random`, `crypto-lcg`) и предскажите `k` напрямую.
- **Fault в nonce** — если один бит `k` инвертирован, применима lattice/перебор.

## Частые ошибки и тупики

- **Не заметить одинаковый `r`.** Это прямой признак повтора `k`.
- **Путать `z` (хэш) и сообщение.** В уравнение входит числовой хэш, усечённый до длины `n`.
- **Неверная длина хэша.** `z` берётся как `int(H(m))`, часто усечённый по модулю `n`.
- **Мало подписей для biased-атаки.** Нужно больше, чем кажется.
- **Ошибки в построении решётки.** Масштабирование `B/n` критично.
- **Считать EdDSA уязвимым к повтору.** При корректной реализации — нет.
- **Игнорировать secp256k1 vs P-256.** Порядок `n` разный.

## Что дальше (decision)

1. Два одинаковых `r` → восстановите `k` и `d` вычитанием.
2. `k` усечён/смещён → HNP + LLL/BKZ.
3. `k` из слабого PRNG → восстановите PRNG (`crypto-python-random`).
4. Один бит `k` инвертирован → перебор/решётка.
5. EdDSA/детерминированный nonce → атака неприменима, ищите другое.
6. Нужны инструменты → `crypto-attacks`, Sage.

## Полный разбор: biased nonce с известными старшими битами

Пусть генератор `k` берёт 32 случайных бита и сдвигает влево, то есть `k = k_low + t·2^{l}` с `l = 224` (для 256-битного `n`) — старшие 224 бита «случайны», а младшие 32 неизвестны (или наоборот). В любом случае известна большая часть `k`, и остаётся HNP с малой ошибкой.

Практический рецепт:

1. Собрать `m ≈ 10–20` подписей с одинаковым «сдвигом» nonce.
2. Вычислить `t_i = r_i·s_i^{-1} mod n`, `u_i = z_i·s_i^{-1} mod n`.
3. Построить решётку размера `(m+2)×(m+2)` с `B = 2^{32}`.
4. `LLL` (или `BKZ-20`), найти вектор, дающий `d`.
5. Проверить `d·G == Q`.

Если известна лишь **половина** бит nonce — хватает 2–3 подписей; если известен 1 бит — нужны сотни. Готовые реализации — `crypto-attacks` (jvdsn), `ecdsa-nonce-recovery`. Для CTF часто дают «nonce < 2^64» или «nonce из `random.getrandbits(32)`» — оба случая закрываются этой схемой.

## Чек-лист: атака на nonce

- два сообщения с одинаковым `r` → мгновенное восстановление;
- в условии «nonce bias», «nonce < 2^k», «nonce из слабого PRNG»;
- много подписей под одним ключом;
- «k усечён», «старшие/младшие биты k известны»;
- `k` генерируется `random`/LCG/MT19937.

Начните с проверки повторов `r`. Если повторов нет — оцените, насколько «короткий» nonce (условие обычно даёт границу), и стройте HNP-решётку с `B = 2^l`. Для PRNG-генерируемого `k` — сначала восстановите PRNG.
