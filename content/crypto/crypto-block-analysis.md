## Зачем это нужно

Все уроки про AES до сих пор эксплуатировали **ошибки применения**: ECB без сцепления, CBC без MAC, CTR с reused nonce. Но существует и второй класс атак — **криптоанализ самого шифра**: попытки «заглянуть внутрь» алгоритма, используя его математическую структуру. Для полноценного AES такие атаки непрактичны (полный AES-128 держится десятилетиями), но:

- На CTF часто дают **редуцированные** шифры (AES на 2–4 раундах, DES на 6 раундах) или **самодельные** SPN-сети — их ломают именно дифференциальным/линейным криптоанализом.
- Понимание этих атак объясняет, **почему** S-box выбирают именно такими и почему важно число раундов.
- Это фундамент для понимания integral (Square) атак и более современных техник.

Модель угроз здесь — **known/chosen-plaintext**: атакующий может шифровать произвольные блоки и наблюдать шифротексты, но не знает ключ.

## Модель SPN-сети и S-box

Большинство современных блочных шифров (включая AES) построены как **SPN** (Substitution-Permutation Network). Раунд состоит из:

1. **Key addition** — XOR с подключом.
2. **Substitution** — нелинейная замена байтов через **S-box** (единственный источник нелинейности).
3. **Permutation** — линейное перемешивание (в AES — `ShiftRows` + `MixColumns`).

S-box — это таблица `8 бит → 8 бит` (256 значений). Его нелинейность — то, что мешает линейному криптоанализу. Атаки ищут «слабые места» S-box: пары входных разностей, которые переходят в конкретную выходную разность с высокой вероятностью.

Ключевое наблюдение: **для некоторых входных разностей `Δin` S-box даёт выходную разность `Δout` с вероятностью заметно выше случайной `1/256`.** Это «след», по которому прослеживается влияние ключа через несколько раундов.

## Дифференциальный криптоанализ (DC)

Идея Бихама и Шамира (1990, против DES): рассматривать не отдельные пары, а **разности** (XOR) между двумя открытыми текстами `P` и `P' = P ⊕ Δ`. Для случайного шифра выходная разность `Δout` распределена равномерно. Для реального шифра на некоторых `Δin` распределение смещено — и это утекает информацию о ключе.

**Дифференциальная характеристика** — цепочка разностей по раундам:

```
Δ0 → Δ1 → ... → Δr
```

с вероятностью `p = Π p_i`, где `p_i` — вероятность перехода разности через i-й раунд. Если `p` достаточно велика, то для пары текстов с входной разностью `Δ0` на выходе с вероятностью `p` получим предсказуемую разность — а значит, можем **перебором угадать часть последнего подключа**.

Для каждого S-box строят **DDT** (Difference Distribution Table): матрицу, где `DDT[Δin][Δout]` — число входов `x`, таких что `S(x) ⊕ S(x ⊕ Δin) = Δout`. Наибольшие значения (кроме `Δin=0`) — «слабые» дифференциалы.

```python
def build_ddt(sbox):
    n = 256
    ddt = [[0]*n for _ in range(n)]
    for x in range(n):
        for din in range(n):
            dout = sbox[x] ^ sbox[x ^ din]
            ddt[din][dout] += 1
    return ddt

# максимум вне нулевой разности — показатель дифференциальной стойкости
ddt = build_ddt(AES_SBOX)
worst = max(ddt[din][dout] for din in range(1,256) for dout in range(256))
print("worst differential probability:", worst/256)
# Для AES-SBOX максимум = 4, т.е. вероятность 4/256 = 1/64
```

У AES S-box максимальная дифференциальная вероятность — `4/256 = 1/64`. Это очень хорошо (низкий «шум» для атакующего). У слабого/самодельного S-box она может быть `1/4` — и тогда шифр ломается за 2–3 раунда.

## Линейный криптоанализ (LC)

Идея Мацуи (1993, против DES): искать **линейные приближения** — соотношения вида

```
a·P ⊕ b·C = c·K
```

(побитовые XOR-комбинации битов входа, выхода и ключа), которые выполняются с вероятностью `p ≠ 1/2`. Смещение `ε = |p − 1/2|` накапливается по раундам (лемма о накоплении Мацуи). Чем больше `|ε|`, тем меньше текстов нужно, чтобы отличить шифр от случайного и восстановить биты ключа.

Для S-box строят **LAT** (Linear Approximation Table): `LAT[a][b]` считает, сколько входов `x` удовлетворяют `parity(a & x) == parity(b & S(x))`. Отклонение от `128` (половина из 256) — это смещение.

```python
def build_lat(sbox):
    n = 256
    lat = [[0]*n for _ in range(n)]
    for a in range(n):
        for b in range(n):
            count = 0
            for x in range(n):
                if bin(a & x).count("1") % 2 == bin(b & sbox[x]).count("1") % 2:
                    count += 1
            lat[a][b] = count - 128     # смещение от 1/2
    return lat
```

Наибольшее `|LAT|` — линейная «дыра». Для AES S-box оно равно 16 (вероятность `1/2 ± 16/256`).

## Square / Integral attack (на AES-подобные)

Отдельная техника, специфичная для AES-структуры: берём **набор из 256 текстов**, отличающихся во всех байтах одного «активного» байта (то есть байт пробегает все 256 значений). После раундов свойство «каждый байт принимает каждое значение ровно один раз» (balanced) сохраняется для некоторых байтов. Атака на AES-4 (4 раунда) восстанавливает ключ за 2^32 операций, что демонстрирует: **число раундов критично**. Именно поэтому AES-128 — 10 раундов, а не 4.

## Практический пример: атака на игрушечный SPN

Дан 2-раундовый шифр с 4-битным S-box и перестановкой. Мы знаем `S` и `P` (структуру), не знаем подключи `k0, k1`.

```python
# Игрушечный SPN (упрощённо, 1 байт состояния)
S = [0xe,4,0xd,1,2,0xf,0xb,8,3,0xa,6,0xc,5,9,0,7]
def enc(pt, k0, k1):
    x = pt ^ k0
    x = S[x]
    x = x ^ k1
    return x

# 1. Строим DDT, находим лучший дифференциал S: din -> dout с p=?
#    Например S[0]^S[0^din] часто даёт dout.
# 2. Подбираем пары (P, P^din) с известным выходом.
# 3. Перебираем k1 (256 вариантов), для каждого "откатываем" S и
#    проверяем, что разность до последнего XOR совпадает с ожидаемой.
def attack(pairs, din, dout):
    for k1 in range(16):
        ok = 0
        for (p, c) in pairs:
            # c = S[p^k0]^k1 ; проверим разность S-выходов
            s_out = c ^ k1
            # разность до S = din, ожидаемая после S = dout
            # проверяем через обратный S
            x1 = invS(s_out)
            if (x1 ^ invS(s_out ^ dout)) == din:
                ok += 1
        if ok > len(pairs)*0.8:
            return k1
    return None
```

Идея та же, что для DES/AES: дифференциал с высокой вероятностью «просвечивает» подключ последнего раунда.

## DC против LC: что выбирать

Обе атаки — статистические: они собирают много пар/текстов и ищут отклонение от случайности. Разница в «языке», на котором описывается утечка.

| Аспект | Дифференциальный (DC) | Линейный (LC) |
|---|---|---|
| Что анализирует | разности входов/выходов (XOR) | линейные комбинации битов |
| Таблица S-box | DDT (Difference Distribution Table) | LAT (Linear Approximation Table) |
| Метрика | вероятность перехода `Δin→Δout` | смещение `ε = |p−1/2|` |
| Ключевая лемма | вероятности перемножаются по раундам | смещения накапливаются (лемма Мацуи) |
| Когда проще | малый размер блока, слабый S-box | наличие хорошего линейного приближения |
| Данные | `~1/p` пар выбранных текстов | `~1/ε²` известных текстов |

Практическое правило: если задача даёт **chosen-plaintext** (можно шифровать что угодно) — начинайте с DC. Если только **known-plaintext** (набор пар уже дан) — LC может оказаться удобнее, потому что ему достаточно известных текстов. На CTF чаще встречается DC: он проще кодируется и понятнее на игрушечных шифрах.

## Частые ошибки

- **Считать, что DC/LC ломают полный AES.** Нет: Wide Trail Strategy гарантирует, что для 4 раундов активных S-box становится минимум 25, а вероятность характеристики падает экспоненциально. Полный AES неуязвим.
- **Игнорировать число раундов.** Задача почти всегда «редуцированная» — сначала посчитайте раунды.
- **Путать DC и LC.** DC работает с разностями входов, LC — с линейными аппроксимациями; данные и таблицы разные.
- **Забывать про key schedule.** Подключи связаны; восстановив один, можно вывести соседние.
- **Недооценивать объём данных.** DC на `r` раундов требует порядка `1/p` пар текстов; при `p=1/64` и 4 раундах это может быть 2^24 пар.

## Как не застрять

- **Определите тип шифра.** SPN/Feistel, сколько раундов, размер блока и S-box.
- **Постройте DDT/LAT.** Это первые 20 строк кода и они сразу показывают «слабые» S-box.
- **Ищите характеристику с максимальной вероятностью** через раунды (умножение вероятностей).
- **Атакуйте последний раунд** перебором подключа, используя предсказанную разность.
- **Проверяйте на игрушечном примере**, прежде чем бить по боевому оракулу.
- **Если шифр полный (AES-10/12/14)** — это НЕ задача на DC/LC; ищите ошибку применения (ECB/CBC/CTR).
