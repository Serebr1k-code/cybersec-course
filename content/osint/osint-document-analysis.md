## Вопрос, с которого всё начинается

Тебе дали файл `invoice.pdf` и спросили: нет ли внутри чего-то скрытого. Новичок открывает его в просмотрщике и читает текст.

Но документ — это не картинка текста, а **контейнер**. PDF хранит объекты и потоки, DOCX и XLSX — это ZIP с XML. Внутри остаются метаданные, история правок, скрытые слои и вложения. Разберём это на одном PDF.

## Наш пример: файл invoice.pdf

У нас один объект — `invoice.pdf`. Введём термин: **поток** (stream) — сжатый блок данных внутри PDF, где лежит текст или изображение. Задача — заглянуть внутрь контейнера.

## Шаг 1: читаем метаданные

Начнём с самого простого — служебных полей:

```bash
exiftool invoice.pdf
```

```
Author    : J. Smith
Producer  : LibreOffice 7.6
Creator   : Writer
CreateDate: 2026:09:03 11:12:40
```

Поля `Author` и `Producer` сразу дают имя сотрудника и программу с версией. Разница между датой создания и датой изменения показывает, когда документ правили.

## Шаг 2: смотрим вложения

PDF умеет хранить внутри другие файлы — они называются **вложениями**:

```bash
pdfdetach -list invoice.pdf
```

```
2 embedded files
  1: notes.txt
  2: logo.png
```

Внутри лежит `notes.txt` — которого в самом документе не видно. Извлекаем:

```bash
pdfdetach -saveall invoice.pdf
cat notes.txt
```

```
Внутренний контакт: finance@example.com
```

Вот и утечка внутреннего адреса.

## Шаг 3: ищем «удалённый» текст

Частая ошибка редакторов — «замазать» секрет чёрным прямоугольником поверх. Текст при этом **остаётся** в потоке. Попробуем извлечь весь текст:

```bash
pdftotext -layout invoice.pdf - | grep -iE 'secret|confidential|password'
```

```
Account: 40817XXXX (confidential)
```

Строка, помеченная как конфиденциальная, извлекается обычным текстом. Если текст реально удалён, помогает распаковка структуры:

```bash
qpdf --qdf --object-streams=disable invoice.pdf unpacked.pdf
strings unpacked.pdf | grep -iE 'password|internal|@'
```

Флаг `--qdf` распаковывает сжатые потоки, после чего `strings` видит то, что было спрятано сжатием.

## Шаг 4: достаём изображения и их метаданные

Картинки внутри документа несут собственные метаданные:

```bash
pdfimages -all invoice.pdf img/
exiftool img/* | grep -iE 'gps|make|model|software'
```

```
GPS Position : 55 deg 45' 21.00" N, 37 deg 37' 02.00" E
Make         : Apple
```

Скан или скриншот, вставленный в документ, может выдать GPS съёмки и модель устройства автора.

## Шаг 5: ищем встроенные файлы через binwalk

Если документ «подозрительно большой», внутри может быть спрятан другой файл:

```bash
binwalk invoice.pdf
binwalk -e invoice.pdf
```

`binwalk` находит сигнатуры встроенных архивов, изображений и других документов, а ключ `-e` извлекает их. Так достают ZIP, спрятанный в теле PDF.

## Шаг 6: если это Office

Формат DOCX, XLSX и PPTX — это ZIP-архив с XML внутри:

```bash
unzip -l report.docx
```

```
docProps/core.xml    — автор, даты, заголовок
docProps/app.xml     — приложение и компания
word/document.xml    — основной текст
word/comments.xml    — комментарии
```

Читаем свойства:

```bash
unzip -p report.docx docProps/core.xml
```

```
<dc:creator>Ivan Petrov</dc:creator>
<cp:lastModifiedBy>hr-department</cp:lastModifiedBy>
```

А в таблицах Excel особенно ценны **скрытые листы**:

```bash
unzip -o budget.xlsx -d xlsx
grep -riE 'hidden|veryHidden' xlsx/xl/worksheets/*.xml
```

Скрытый лист не отображается, но данные в нём есть — часто это черновики с внутренними цифрами.

## Шаг 7: макросы в старых форматах

Старые `.doc` и `.xls` — это OLE-файлы, в которых могут быть макросы VBA. Их анализируют инструментами из набора **oletools**:

```bash
oleid suspicious.doc
olevba suspicious.doc
```

`olevba` извлекает код макроса, где часто видны URL, команды PowerShell и обфускация. Важно: недоверенный документ **не открывают** в полном Office — только анализируют извлечённое.

## Обезличивание: что всё равно утекает

Даже «обезличенные» документы часто содержат следы:

- **Автор и LastModifiedBy** в свойствах — реальные имена сотрудников.
- **Пути** (`/C/Users/<имя>/...`) — внутренняя структура и имя пользователя.
- **Company и Manager** в `docProps/app.xml`.
- **Стиль форматирования** — уникальный «отпечаток» редактора.
- **Метаданные картинок** внутри документа — GPS и устройство.

Практика: перед публикацией прогоняйте `exiftool -all=` и отдельно проверяйте `docProps/`.

## Типичные CTF-сценарии

В CTF документы — частый источник флага:

- **Флаг в метаданных**: `exiftool` → `Author`, `Comment`, `Producer`.
- **Флаг во вложении**: `pdfdetach -saveall` или `binwalk -e`.
- **Флаг в скрытом слое**: OCG в PDF или белый текст на белом фоне.
- **Флаг в «удалённом» тексте**: `qpdf --qdf` плюс `strings`.
- **Флаг в скрытом листе Excel**: распаковать и посмотреть `xl/worksheets`.

Алгоритм один: определить формат → `exiftool` → распаковать → `strings`/`grep` по ключевым словам (`flag`, `secret`, `key`).

## Что мы теперь знаем

- Документ — контейнер: PDF хранит объекты и потоки, Office — это ZIP.
- `exiftool` даёт автора, программу и таймлайн правок.
- `pdfdetach` достаёт вложения, `pdfimages` — картинки с их метаданными.
- «Замазанный» текст часто извлекается через `pdftotext` или `qpdf --qdf`.
- В Office скрытые листы и свойства выдают внутренние данные.
- Макросы в OLE-форматах разбирают через `olevba`.
- «Замазанный» чёрным прямоугольником текст обычно остаётся в потоке и извлекается.
- Вложения и скрытые листы — самый частый источник неожиданных данных.
- Недоверенный документ никогда не открывают в полном Office: только анализируют извлечённое.
- Даже «обезличенный» документ хранит автора, внутренние пути и стиль редактора.
- Разница дат создания и изменения сама по себе выдаёт таймлайн работы над документом.
- Скрытые листы Excel часто содержат черновики с внутренними цифрами.

## На что смотреть дальше

Разберись со **скрытыми слоями** PDF (OCG) — слой может быть выключен, но содержать текст, а также с белым текстом на белом фоне. Изучи метаданные картинок внутри документов отдельно: там своя геолокация и атрибуция. Для защиты — `exiftool -all=` и проверка `docProps/` перед публикацией.

## Куда дальше

Мы научились заглядывать внутрь документов. В следующем уроке — **заголовки email**: разберём письмо целиком, включая маршрут доставки, почтовый клиент и подписи почтовой защиты. А пока главное запомни: документ — это контейнер, а не просто текст на странице.

## Где пригодится

- **CTF (OSINT/Forensics):** найти флаг в метаданных или вложении.
- **Расследования:** восстановить удалённые правки и авторов.
- **Пентест:** извлечь внутренние имена и почты из корпоративных документов.
- **Работа:** анализ вложений в фишинге.

Помни главное: документ почти всегда «помнит» больше, чем видно на странице, — и метаданные, и вложения, и скрытые слои. Именно поэтому перед публикацией любого документа его прогоняют через `exiftool -all=` и проверяют `docProps/`.
