Социальные сети — самый богатый источник информации о людях и организациях. Люди добровольно публикуют место работы, должности, коллег, поездки, фото с геотегами и даже скриншоты внутренних систем. Задача разведчика — собрать эти данные, связать их между собой и построить граф «кто с кем и где». В этом уроке — практическая методика.

## Теория: что искать в соцсетях

Ключевые категории данных:

1. **Идентификация:** полное имя, ник, фото, дата рождения, город.
2. **Организационные связи:** место работы, должность, отдел, коллеги (для пентеста — самые ценные).
3. **Технологический стек:** в описаниях вакансий и постов («мы используем Kubernetes», «ищу админа 1С»).
4. **Локации:** чекины, геотеги, сторис, «домашний офис» в кадре.
5. **Временные паттерны:** когда человек онлайн, когда в отпуске (→ окно для атаки).
6. **Слабые места:** email в открытом виде, личные проекты, жалобы на работу.

### Платформы и их особенности

| Платформа | Что даёт | Нюансы |
|-----------|----------|--------|
| LinkedIn | Работодатель, должность, стек, связи | Часть полей видна без логина; Sales Navigator платный |
| VK | Люди, друзья, фото, города, рунет | Открытые стены, поиск по параметрам |
| X/Twitter | Мнения, контакты, техконтекст | Архивы через Nitter, поиск по датам |
| Instagram | Фото, геотеги, сторис | API закрыт; через поиск и зеркала |
| GitHub | Код, email, внутренние домены | API открыт, коммиты дают email |
| Telegram | Публичные каналы, комментарии | Поиск по username/номеру |
| Facebook | Личные данные, группы | Много приватности, но старые данные публичны |

## Практика: LinkedIn

LinkedIn — лучший источник корпоративных связей. Без логина видны имена и должности в превью.

Поисковые дорки:

```
site:linkedin.com/in "example company"
site:linkedin.com/in "DevOps" "Moscow"
site:linkedin.com/company example
```

Сбор сотрудников:

```bash
# через Google/Bing — постранично
for p in 0 10 20 30; do
  curl -s "https://www.bing.com/search?q=site:linkedin.com/in+%22example%22&first=$p" \
    | grep -oE 'linkedin\.com/in/[a-zA-Z0-9-]+' | sort -u
done
```

(В реальности лучше использовать `theHarvester -b linkedin` или платные API, чтобы не нарушать ToS.)

Что извлекать: имя → поиск в других соцсетях → email-паттерн компании (`first.last@company.com`).

## Практика: VK и X

VK имеет открытый поиск людей по параметрам (город, возраст, вуз, место работы):

```text
https://vk.com/search?c[section]=people&c[q]=Иван Петров&c[city]=1
```

Публичные стены и фото часто открыты. Через `vk.com/idXXXX` можно увидеть друзей, группы, интересы.

X/Twitter: используйте расширенный поиск:

```
from:username since:2023-01-01 until:2023-06-01
"password" from:username
near:Moscow within:15km
```

Архивы удалённых твитов — через `web.archive.org` и Nitter-зеркала.

## Практика: граф связей

Собранные связи удобно визуализировать. Простой формат — CSV/edges и Graphviz:

```bash
cat > people.dot <<'EOF'
digraph G {
  "Иван Петров" -> "example corp" [label="работает"];
  "Иван Петров" -> "Мария Сидорова" [label="коллега"];
  "Мария Сидорова" -> "example corp" [label="работает"];
  "Иван Петров" -> "ivan.petrov@example.com" [label="email"];
}
EOF
dot -Tpng people.dot -o people.png
```

Так вы видите, кто ключевая фигура (много связей), а кто изолирован.

## Разобранный пример: от компании к сотрудникам и email-паттерну

Дано: компания `Example LLC`.

Шаг 1 — LinkedIn-дорк:

```
site:linkedin.com/in "Example LLC"
```

Находим 8 сотрудников: CEO, CTO, DevOps, 3 разработчика, HR, бухгалтер.

Шаг 2 — определяем email-паттерн. Проверяем через публичные утечки/инструменты (в рамках закона) или через верификацию формата:

```text
Возможные паттерны:  first.last@ / firstlast@ / f.last@ / first@
```

Шаг 3 — ищем каждого в других сетях:

```
"Иван Петров" "Example"
site:github.com "Иван Петров"
```

GitHub даёт email из коммитов:

```bash
curl -s "https://api.github.com/search/users?q=example+location:moscow" | jq -r '.items[].login'
```

Шаг 4 — геолокация по фото. Смотрим сторис/посты с геотегами → офис, спортзал, дом. Из фото офиса читаем бейджи, экраны, названия систем (см. урок про геолокацию и метаданные).

Шаг 5 — временные окна. По активности определяем, когда команда в отпуске (летом) — потенциальное окно для атаки (в легальном пентесте это фиксируется в отчёте).

Шаг 6 — сводим в граф и таблицу с оценкой достоверности.

## Продвинутые приёмы

- **Search by email/phone:** вставьте email или телефон в поиск + соцсети; многие сервисы позволяют «найти по номеру».
- **Reverse image на аватары:** связывает аккаунты (см. урок про обратный поиск).
- **Facebook Graph (историческое):** старые данные часто остаются в кэше/архиве.
- **Instagram геотеги:** поиск по локации показывает посты всех, кто там был (в т.ч. сотрудников).
- **Telegram:** публичные каналы компании, комментарии сотрудников, поиск по username.
- **Скриншоты внутренних систем:** на фото «рабочего места» видны URL, названия Jira-проектов, чаты — это карта внутренней инфраструктуры.
- **Archive.org для удалённых постов:** `http://archive.org/wayback/available?url=...`.

## Частые ошибки

- **Скрейпинг против ToS.** LinkedIn агрессивно банит; используйте паузы/официальные API.
- **Вера одному источнику.** Профиль может быть фейковым или устаревшим.
- **Игнорирование «мелочей».** Фон фото, бейдж, кружка с логотипом — всё это данные.
- **Сбор ПДн без цели.** Нарушает закон; фиксируйте только необходимое.
- **Отсутствие структуры.** Без графа/таблицы связи теряются.
- **Забыть про временные метки.** Активность в нерабочее время тоже информация.

## Практика: инструменты автоматического сбора

Sherlock — быстрый поиск ника по 400+ платформам. Установка и базовый прогон:

```bash
pipx install sherlock-project
sherlock --print-found --timeout 5 ivan_petrov
```

Флаги: `--print-found` — выводить только найденное, `--timeout N` — таймаут на запрос, `--site SITE` — конкретный сайт, `-o file.txt` — сохранить результат, `--tor` и `--proxy` — анонимизация источника. На выходе — список URL, где ник занят; пустой результат по платформе означает, что ник там не зарегистрирован.

Maigret — расширенный аналог, умеет вытаскивать из профиля имя, аватар и биографию и строить HTML-отчёт:

```bash
pipx install maigret
maigret ivan_petrov --html -H report.html --timeout 10 -a
```

`-a` — проверять все сайты, `--html` — HTML-отчёт, `-H` — заголовок файла, `--json` — машинный вывод, `--print-not-found` — показывать и отрицательные результаты (полезно для доказательства полноты проверки).

socialscan проверяет занятость и username, и email сразу:

```bash
pipx install socialscan
socialscan ivan.petrov@example.com ivan_petrov
```

instaloader выгружает публичный профиль Instagram вместе с геотегами постов:

```bash
pipx install instaloader
instaloader --no-videos --geotags --post-metadata-txt "{date}: {caption}" profile ivanpetrov
```

`--geotags` сохраняет координаты постов в JSON, `--post-metadata-txt` задаёт шаблон метаданных, `--login` нужен для приватных профилей. Помните про ToS: массовая выгрузка может привести к бану аккаунта.

snscrape собирает посты X без API-ключа:

```bash
pipx install snscrape
snscrape --jsonl --max-results 200 twitter-search 'from:ivanpetrov since:2024-01-01'
```

## Практика: LinkedIn — дорки и обход ограничений

Расширенные операторы поиска для LinkedIn:

```
site:linkedin.com/in "at Example LLC"
site:linkedin.com/in "Example LLC" -intitle:jobs
site:linkedin.com/in ("DevOps" OR "SRE") "Москва"
site:linkedin.com/pub ivan-petrov
site:linkedin.com/company/example employees
```

Bing индексирует иначе и иногда отдаёт больше: `https://www.bing.com/search?q=site%3Alinkedin.com%2Fin+%22Example%22&first=1`. Удалённые профили часто остаются в Google Cache и в Wayback Machine — проверяйте `web.archive.org/web/*/linkedin.com/in/...`.

## Верификация и атрибуция аккаунтов

Совпадение ника — это гипотеза, а не доказательство. Уверенность набирается несколькими независимыми сигналами: кросс-ссылки (профиль A ссылается на B), совпадение аватара (обратный поиск изображения), совпадение email или телефона, корреляция по времени публикаций. Короткий ник вроде `ivan` даёт десятки ложных совпадений — всегда сверяйте контекст (город, место работы, аватар, круг общения). Оценивайте каждую связь как high/medium/low и не строите выводов на одном слабом признаке.

## Справочник: операторы и коды

| Задача | Оператор или подход |
|---|---|
| Профили сотрудников компании | `site:linkedin.com/in "Company"` |
| Посты за период | `from:user since:2024-01-01 until:2024-06-01` |
| Гео-поиск X | `near:Moscow within:15km` |
| Поиск VK по городу | `c[city]=1`, `c[section]=people` |
| Архив удалённого поста | `web.archive.org/web/*/URL` |
| Проверка занятости ника | sherlock / maigret / socialscan |
| Геотеги Instagram | `instaloader --geotags` |

## Что дальше / решение

Собранный граф связей — это вход для следующих шагов: email-паттерн ведёт к password spraying в рамках авторизации, список сотрудников — к целевому фишингу, технологический стек — к подбору CVE. Фиксируйте источник и дату каждой записи: устаревшие данные опасны тем, что вы принимаете бывшего сотрудника за действующего. Для CTF результатом обычно служит флаг, спрятанный в «забытом» профиле или в кросс-ссылке между аккаунтами.

## Разбор: OPSEC при работе с соцсетями

Разведка в соцсетях легко «засветить» наблюдателя, поэтому соблюдайте базовую гигиену. Не заходите на профили цели с личного аккаунта: LinkedIn показывает владельцу, кто смотрел профиль, а Facebook и VK фиксируют посещения. Используйте отдельные «sock puppet»-профили, заведённые на отдельные email и телефон, либо вообще не логиньтесь, а читайте публичные данные через Google Cache и Wayback Machine. Разделяйте браузерные профили для каждой персоны, чтобы куки и отпечаток не связывали ваши аккаунты между собой. Если нужен доступ к закрытому контенту, не пишите цели напрямую — это раскрывает интерес и может спровоцировать контрразведку. Фиксируйте время и источник каждого просмотра: при повторном обращении вы будете знать, что уже видели, и не станете лишний раз «светиться». Для CTF это менее критично, но привычка разделять личности полезна и там.

## Где пригодится

- **CTF (OSINT):** найти флаг/подсказку в соцпрофиле или связи.
- **Bug bounty:** определить сотрудников и email-паттерн для тестирования (в рамках scope).
- **Пентест:** подготовка целевого фишинга и понимание организационной структуры.
- **Расследования:** установление связей между людьми и организациями.
- **Blue team:** аудит того, что сотрудники публикуют о внутренней инфраструктуре.
