## Вопрос, с которого всё начинается

Тебе прислали видео: «вот доказательство, всё снято на телефон». Но видео можно смонтировать, перекодировать, замедлить и даже сгенерировать. Как понять, что с ним делали, и не подделано ли оно?

Задача: разобрать контейнер и потоки видео, найти следы монтажа и перекодирования, оценить признаки дипфейка.

## Наш пример: файл clip.mp4

Держим объект `clip.mp4`. Первый вопрос: **что это за файл и чем он создан?** Метаданные контейнера отвечают на это.

```bash
ffprobe -v error -show_format -show_streams clip.mp4
```

```text
[STREAM] codec_name=h264 codec_type=video width=1920 height=1080
[FORMAT] format_name=mov,mp4 duration=12.48 encoder=Lavf58.29.100
         creation_time=2024-03-11T09:14:22Z
```

Читаем: `codec_name=h264` — кодек, `encoder=Lavf58.29.100` — файл пересобран FFmpeg (Lavf — библиотека FFmpeg). Если видео «снято на телефон», но `encoder` указывает на FFmpeg, значит, его перекодировали или склеили. Это первая зацепка.

## Шаг 1: контейнер и кодеки

Видеофайл — это **контейнер** (MP4, MOV, MKV), внутри которого лежат потоки: видео, аудио, субтитры. Контейнер хранит метаданные: `encoder`, `creation_time`, `duration`. Поток описывает кодек, разрешение, частоту кадров.

```bash
ffprobe -v error -show_streams clip.mp4 | grep -E 'codec_name|width|height|r_frame_rate'
```

```text
codec_name=h264
width=1920
height=1080
r_frame_rate=30/1
```

Несоответствие между «заявленным» происхождением и этими данными — сигнал. Телефон обычно пишет в HEVC или H.264 с `encoder` производителя, а не с `Lavf`.

## Шаг 2: следы перекодирования

При перекодировании видео теряет качество характерным образом: меняются таблицы квантования, появляются артефакты блочности. Покадровый анализ (например, Error Level Analysis по кадрам) показывает, где кадры «свежее» остальных — это следы склейки.

```bash
# иллюстративно: извлечь кадры и сравнить
ffmpeg -i clip.mp4 -vf fps=1 frames/%03d.png
```

Если часть кадров резко отличается по артефактам сжатия, вероятна вставка. Дополнительный признак — несоответствие аудио и видео по частоте дискретизации: при монтаже дорожки часто перекодируют отдельно.

## Шаг 3: признаки дипфейка

Синтетическое видео выдаёт себя несколькими признаками. Первый — темпоральная нестабильность: мимика «плывёт» между кадрами, границы лица мерцают. Второй — артефакты смешивания на границе лица и фона. Третий — неестественное освещение и тени. Четвёртый — отсутствие естественного шума сенсора в областях лица.

```bash
# иллюстративно: покадровое различие
ffmpeg -i clip.mp4 -vf "tblend=all_mode=difference" diff.mp4
```

Разностный фильтр подчёркивает места, где кадры «дрожат» неестественно. В сочетании с покадровым просмотром это помогает заметить синтетику, которую не видно на глаз.

## Шаг 4: границы

Мы читаем метаданные и анализируем артефакты. Мы **не делаем вывод «подделка» только по одному признаку**: перекодирование часто делают легально (сжатие для отправки), а `encoder=FFmpeg` — нормален для конвертеров. Вывод строится на совокупности: метаданные, артефакты, контекст, C2PA.

## Полный прогон

```bash
# 1. метаданные
ffprobe -v error -show_format clip.mp4 | grep -E 'encoder|creation_time'
# → encoder=Lavf58.29.100, creation_time=2024-03-11T09:14:22Z
# 2. потоки
ffprobe -v error -show_streams clip.mp4 | grep codec_name
# → h264, aac
# 3. кадры
ffmpeg -i clip.mp4 -vf fps=1 frames/%03d.png
```

Непрерывно: файл → контейнер → кодеки → encoder → кадры → вывод о правках.

## Если не сработало

**Метаданные пусты.** Файл прошёл через соцсеть — опирайся на артефакты кадров.
**FFmpeg-энкодер у оригинала.** Некоторые телефоны и приложения используют FFmpeg — не делай поспешных выводов.
**Нет явных следов.** Отсутствие признаков монтажа не доказывает подлинность.

## Частые ошибки

**Ошибка: судить по одному полю.** `encoder=FFmpeg` сам по себе ничего не доказывает.
**Ошибка: игнорировать аудио.** Несоответствие дорожек — частый след монтажа.
**Ошибка: верить разрешению.** Его легко изменить перекодированием.
**Ошибка: забыть про контекст.** Источник и C2PA важны не меньше артефактов.

## Справочная таблица: что смотреть в видео

| Признак | Где | О чём говорит |
|---------|-----|---------------|
| `encoder` | контейнер | чем пересобрано |
| `creation_time` | контейнер | когда создано |
| `codec_name` | поток | кодек |
| артефакты кадров | кадры | следы склейки |
| темпоральная дрожь | кадры | возможный дипфейк |

## Разбор кейса: «телефонное» видео с FFmpeg

Дано: видео, заявленное как снятое на телефон. Шаг первый — `ffprobe` показывает `encoder=Lavf58.29.100`. Шаг второй — `creation_time` не совпадает с датой события. Шаг третий — покадровый анализ выявляет резкий скачок артефактов на 7-й секунде. Вывод: видео смонтировано и перекодировано, заявление о «прямой съёмке» недостоверно. Разведчик зафиксировал признаки и не стал делать категоричный вывод о полной подделке без дополнительных данных.

## Рабочий воркбук: полное расследование видео

**Этап 1. Контейнер.** Сними `format` и `streams`: кодеки, encoder, creation_time, разрешение.

**Этап 2. Кадры.** Извлеки кадры, прогони разностный фильтр, найди скачки артефактов.

**Этап 3. Аудио.** Сравни дорожки по частоте дискретизации и громкости; ищи разрывы.

**Этап 4. Дипфейк.** Проверь границы лица, освещение, темпоральную стабильность.

**Этап 5. Фиксация.** Сведи признаки в отчёт с указанием таймкодов и уверенности.

## Частые вопросы

**Всегда ли FFmpeg-энкодер = монтаж?** Нет. Многие приложения и сервисы используют FFmpeg легально.

**Что такое Error Level Analysis?** Метод, показывающий разницу в сжатии областей; помогает заметить правки.

**Можно ли точно доказать дипфейк?** Однозначно — редко; вывод строится на совокупности признаков.

**Зачем смотреть аудио?** Дорожки монтируют отдельно, и их рассинхрон выдаёт правку.

**Это законно?** Анализ присланного медиа — да; это стандартная верификация.

## Термины

**Контейнер** — формат-обёртка (MP4, MOV) с потоками и метаданными.

**Кодек** — алгоритм сжатия видео (H.264, HEVC).

**Перекодирование** — повторное сжатие, оставляющее артефакты.

**Дипфейк** — синтетическое видео с заменой лица/голоса.

**Темпоральная стабильность** — согласованность кадров во времени.

## Что мы теперь знаем

1. Видео — контейнер с потоками и метаданными.
2. `encoder` и `creation_time` выдают обработку.
3. Перекодирование оставляет артефакты кадров.
4. Дипфейк выдаёт темпоральная дрожь и границы лица.
5. Вывод строится на совокупности признаков.
