## Вопрос, с которого всё начинается

Обычные соцсети мы разобрали. Но есть мир, устроенный иначе: **Fediverse** — сеть независимых серверов, которые общаются между собой по открытому протоколу. Крупнейший её представитель — **Mastodon**. Здесь нет единой компании-владельца, а значит, данные доступны напрямую через API, без логина.

Вопрос урока: **как найти профиль по нику в федеративной сети и что из него можно вытащить?**

## Наш пример: ник `nasa` в федерации

Мы продолжаем с ником `nasa`. В обычном интернете он привёл нас на GitHub и Telegram. Проверим Mastodon — но сначала разберёмся, почему тут всё иначе.

## Шаг 1: что такое инстанс и федерация

В классической соцсети один сервер обслуживает всех. В Mastodon пользователей обслуживают **инстансы** — независимые серверы (`mastodon.social`, `mstdn.social`, `fosstodon.org`). Пользователь регистрируется на одном, но может читать и комментировать посты с других — потому что инстансы **федерируют** (синхронизируют контент между собой).

Отсюда важное следствие: **один и тот же ник может существовать на десятках инстансов**. Аккаунт обозначают как `user@instance` — это и есть его полный адрес, **acct**.

## Шаг 2: lookup — точная проверка адреса

Если мы знаем инстанс, профиль проверяют одним запросом к его API. Возьмём заведомо публичный аккаунт создателя Mastodon — `Gargron`:

```
$ curl -s "https://mastodon.social/api/v1/accounts/lookup?acct=Gargron" \
  | jq '{id,username,acct,display_name,statuses_count,followers_count,created_at}'
{
  "id": "1",
  "username": "Gargron",
  "acct": "Gargron",
  "display_name": "Eugen Rochko",
  "statuses_count": 82482,
  "followers_count": 383123,
  "created_at": "2016-03-16T00:00:00.000Z"
}
```

Это чистый структурированный ответ: имя, число постов, подписчиков, дата регистрации. `lookup` требует **точный** `acct` — то есть вы должны знать инстанс.

А теперь проверим наш ник `nasa` на том же инстансе:

```
$ curl -s "https://mastodon.social/api/v1/accounts/lookup?acct=nasa" \
  | jq '{id,username,acct,display_name,statuses_count}'
{
  "id": "77810",
  "username": "nasa",
  "acct": "nasa",
  "display_name": "NASA",
  "statuses_count": 1
}
```

Ник занят, имя «NASA» — но **один пост**. Это классический **сквоттер**: кто-то занял популярное имя и не ведёт аккаунт. Вывод: находка есть, но она ложная. Никогда не принимайте `display_name` за доказательство.

## Шаг 3: поиск по всей федерации

Раз один ник живёт на многих инстансах, нужен поиск, который их находит. У Mastodon есть **search** — он ищет аккаунты по всей федерации:

```
$ curl -s "https://mastodon.social/api/v2/search?q=nasa&type=accounts&limit=3" \
  | jq -r '.accounts[] | "\(.acct) — \(.display_name)"'
nasa@social.beachcom.org — NASA
NASA@mstdn.social — NASA
NASA@aspiechattr.me — NASA
```

Теперь видно настоящих кандидатов: полные адреса `acct` с указанием инстанса. Дальше каждый из них можно открыть и сравнить — аватары, ссылки, активность. Это ровно та корреляция, которую мы обсуждали в уроке про ники.

## Шаг 4: WebFinger — «кто такой этот адрес»

Есть ещё один открытый механизм — **WebFinger**. Это стандартный способ узнать, какой профиль стоит за адресом `user@instance`. Он отдаёт JSON со ссылками на профиль и на «машинное» представление аккаунта:

```
$ curl -s "https://mastodon.social/.well-known/webfinger?resource=acct:Gargron@mastodon.social" \
  | jq '.links[] | select(.rel=="self" or .rel=="http://webfinger.net/rel/profile-page") | {rel,type,href}'
{
  "rel": "http://webfinger.net/rel/profile-page",
  "type": "text/html",
  "href": "https://mastodon.social/@Gargron"
}
{
  "rel": "self",
  "type": "application/activity+json",
  "href": "https://mastodon.social/users/Gargron"
}
```

Ссылка `self` с типом `application/activity+json` ведёт на **ActivityPub**-представление профиля — это открытый формат, в котором отдаются посты, подписки и связи. Запросив её, вы получите данные без браузера:

```
$ curl -s -H "Accept: application/activity+json" https://mastodon.social/users/Gargron | jq '{preferredUsername,summary,url,followers,created}' 2>/dev/null || echo "(формат ActivityPub)"
```

## Шаг 5: миграции — история аккаунта

Люди переезжают между инстансами. Mastodon поддерживает **перенос аккаунта** и показывает в профиле поле `movedTo`. Если человек сменил инстанс, старая запись часто остаётся и указывает на новую. Это ценная зацепка: старый профиль может содержать старый ник, старую почту и связи, которых нет в новом.

## Шаг 6: мониторинг хэштегов

Федерация открыта не только для профилей: у каждого хэштега есть публичная лента, которая собирает посты со всех инстансов. Её тоже отдаёт API:

```
$ curl -s "https://mastodon.social/api/v1/timelines/tag/osint?limit=2" \
  | jq -r '.[] | "\(.account.acct): \(.content | gsub("<[^>]*>";""))"'
exilenova_plus@en.tg.anyfeed.cc: Good morning ...
analytics@social.vir.group: AirAttack | 8/10 ...
```

Выражение `gsub("<[^>]*>";"")` вырезает HTML-теги из текста поста, чтобы читать чистый текст. Так можно следить за обсуждением темы по всей федерации, а не на одном сервере.

Сводку по самому инстансу даёт эндпоинт `api/v1/instance`:

```
$ curl -s "https://mastodon.social/api/v1/instance" | jq '{uri,version,stats}'
{
  "uri": "mastodon.social",
  "version": "4.8.0-nightly.2026-10-06",
  "stats": { "user_count": 3429586, "status_count": 191480987, "domain_count": 124967 }
}
```

Здесь `domain_count` — сколько других инстансов видит этот сервер. Чем больше, тем шире его федерация и тем полезнее он как точка наблюдения.

## Полный прогон от начала до конца

1. Дано: ник `nasa`.
2. `lookup` на `mastodon.social` → аккаунт есть, но это сквоттер (1 пост).
3. `search` по федерации → три кандидата с полными адресами.
4. `WebFinger` для кандидата → ссылка на ActivityPub-представление.
5. Сравниваем аватары и активность → выбираем настоящий аккаунт.

## Если не сработало

- **`lookup` вернул 404.** Значит, на этом инстансе ника нет — не делайте вывод «аккаунта не существует вообще», попробуйте `search`.
- **`search` пуст.** У разных инстансов разный охват федерации: попробуйте другой инстанс или тематический (например, для ИТ — `fosstodon.org`).
- **Слишком много одноимённых.** Разделяйте по контексту: язык постов, ссылки в био, дата регистрации.

## Что мы теперь знаем

1. Fediverse — это сеть инстансов; аккаунт адресуется как `user@instance`.
2. `lookup` даёт точные данные, если известен инстанс; `search` ищет по всей федерации.
3. `display_name` легко подделать — сквоттеры занимают известные имена.
4. **WebFinger** и ActivityPub отдают машинные данные профиля без логина.
5. Хэштеги дают публичную ленту по всей федерации — готовый инструмент мониторинга.

## На что смотреть дальше

- **Проверяйте `movedTo`.** Переезд между инстансами оставляет след старого аккаунта.
- **Сравнивайте по содержимому, а не по имени.** Сквоттер с ником `nasa` и NASA — разные сущности.
- **Инстанс = сообщество.** Сам выбор сервера (региональный, тематический) говорит о человеке.
- **Помните про ToS.** Публичный API — это разведка; массовая выкачка постов может нарушать правила.

## Куда дальше

Мы научились работать с федеративной сетью через открытые API. Дальше возьмём **стриминговые платформы** (Twitch): там данные закрыты строже, и мы разберём, как обходить ограничения легальными способами. А пока главное запомни: в Fediverse данные открыты, но открытость не отменяет проверки — сквоттеры и подделки встречаются постоянно.

## Где пригодится

- **CTF (OSINT):** в метаданных профиля Mastodon спрятана ссылка к флагу.
- **Расследования:** найти профили в федерации и цепочки миграций.
- **Мониторинг сообществ:** отслеживать хэштеги и обсуждения.
- **Threat intelligence:** атрибуция аккаунтов по публичному ключу.
