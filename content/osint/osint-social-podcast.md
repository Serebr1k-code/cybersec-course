Подкасты и аудиоконтент — недооценённый пласт OSINT. Голос содержит биометрию и акцент, RSS-фиды раскрывают инфраструктуру и авторов, транскрипты индексируются поисковиками, а метаданные аудиофайлов иногда содержат имя устройства и геолокацию записи. В отличие от текста, аудио труднее модерировать, поэтому в подкастах люди говорят свободнее и раскрывают больше.

## Теория: экосистема подкастов

Ключевой факт: **подкасты распространяются через RSS**. Spotify и Apple — лишь каталоги, которые читают тот же RSS-фид. Это значит, что у любого подкаста есть публичный XML-фид с полным списком эпизодов, описаниями, ссылками и датами.

Компоненты:
- **RSS-фид** — «источник истины» (hosting: Anchor, Buzzsprout, Libsyn).
- **Каталоги** — Spotify, Apple Podcasts, Google Podcasts (архив), Podchaser.
- **Эпизоды** — MP3 с ID3-тегами.
- **Транскрипты** — сгенерированные (Whisper) или ручные.
- **Chapters/показания** — тайм-коды и темы.

## Поиск фида

Зная название подкаста, находим фид через каталоги:

```bash
# Apple: найти ID подкаста
curl -s "https://itunes.apple.com/search?term=target+podcast&entity=podcast" \
  | python3 -m json.tool | grep -E 'feedUrl|collectionName|artistName'
```

Вывод:

```json
{
  "collectionName": "Target Security Podcast",
  "artistName": "Ivan Petrov",
  "feedUrl": "https://anchor.fm/s/abc123/podcast/rss"
}
```

`feedUrl` — прямой RSS. `artistName` — часто реальное имя автора.

Скачиваем и разбираем фид:

```bash
curl -s "https://anchor.fm/s/abc123/podcast/rss" -o feed.xml
xmllint --format feed.xml | head -60
```

В фиде:
- `<itunes:author>` — автор;
- `<itunes:email>` — контактный email (!);
- `<link>` — сайт подкаста;
- `<enclosure url=...>` — прямые ссылки на MP3;
- `<pubDate>` — даты эпизодов.

## Метаданные аудио

Скачиваем эпизод и читаем теги:

```bash
curl -sO "https://anchor.fm/s/abc123/podcast/play/12345/https%3A%2F%2F.../episode.mp3"
ffprobe -v quiet -print_format json -show_format episode.mp3 | python3 -m json.tool
```

`ffprobe` показывает: кодеки, битрейт, длительность, а в `format.tags` — `artist`, `album`, `comment`, а иногда **`encoder`** (какой софт записывал) и `date`. `exiftool` для аудио:

```bash
exiftool episode.mp3
```

Иногда в тегах остаются: имя устройства записи, название проекта, путь.

## Транскрипция: превращаем голос в текст

Транскрипты делают аудио поисковым. Whisper (OpenAI) — стандарт:

```bash
pipx install openai-whisper
whisper episode.mp3 --model medium --language ru --output_format srt --output_dir out
```

Получаем `episode.srt` — субтитры с тайм-кодами. Теперь можно грепать:

```bash
grep -niE 'адрес|город|работаю|компани|email|@|github' out/episode.srt
```

Транскрипт раскрывает: места работы, города, имена коллег, ссылки, технические детали.

## Голосовая биометрия и акустика

- **Голос** — устойчивая характеристика (тембр, акцент, идиолект). Сравнение записей может подтвердить, что два подкаста ведёт один человек.
- **Фон** — звуки улицы, транспорт, часы, отголоски помещения дают подсказки о месте записи.
- **Оговорки** — «у нас сейчас 3 часа ночи» раскрывает часовой пояс.

Важно: голосовую биометрию используйте осторожно и этично — ошибки здесь дороги.

## Разобранный пример: от подкаста к автору

Дано: подкаст «Target Security».

Шаг 1 — фид через iTunes API:

```bash
curl -s "https://itunes.apple.com/search?term=target+security&entity=podcast" \
  | python3 -m json.tool | grep -E 'feedUrl|artistName|trackCount'
# "artistName": "Ivan Petrov", "feedUrl": "https://.../rss", "trackCount": 42
```

Шаг 2 — разбор фида:

```bash
curl -s "https://.../rss" | grep -oE '<itunes:email>[^<]+' 
# <itunes:email>ivan@example.com
```

Получили email автора — pivot в ветку email-разведки.

Шаг 3 — транскрипция одного эпизода и поиск упоминаний компании/города.

Шаг 4 — сравнение голоса с YouTube-каналом того же человека (атрибуция).

Итог: имя, email, компания, регион — всё из подкаста.

## Каталоги и поиск упоминаний

| Каталог | Что даёт |
|---------|----------|
| Apple Podcasts | фид, автор, рейтинги |
| Spotify | эпизоды, описания |
| Podchaser | гости, связи между подкастами |
| Listen Notes | поиск по транскриптам (!) |
| Podcast Addict | метаданные |

**Listen Notes** индексирует аудио и позволяет искать по произнесённому тексту — аналог «Google по подкастам». Это прямой способ найти, где человек упомянул нужное.

## Таблица: что извлекается из подкаста

| Артефакт | Источник | Ценность |
|----------|----------|----------|
| Автор | `<itunes:author>` | имя |

## Ошибки и подводные камни

- **Искать только в Spotify.** Настоящий фид — в RSS; Spotify может не отдавать всё.
- **Игнорировать ID3-теги.** Там бывают encoder, путь, имя устройства.
- **Считать транскрипт точным.** Whisper ошибается на именах и терминах — проверяйте.
- **Забывать про архив эпизодов.** Удалённые эпизоды могут остаться в кэше/архиве.
- **Переоценивать голос.** Акцент — подсказка, не доказательство.
- **Не соблюдать этику.** Транскрибирование частных разговоров без основания недопустимо.

## Что дальше / решение

Подкасты превращают голос в структурированные данные. Дальше: **новости и RSS** (`osint-social-news`) для медиамониторинга, **email-разведка** (`osint-email-enum`) по найденному адресу, **разрешение идентичностей** (`osint-identity-resolution`) для связывания. Итог: RSS + транскрипция делают аудио полноценным источником OSINT — с именами, контактами, местами и временем.

## Пакетная обработка и поиск по транскриптам

Когда эпизодов десятки, транскрипция вручную не масштабируется. Собираем пакетный пайплайн:

```bash
#!/usr/bin/env bash
# transcribe-all.sh — скачать и транскрибировать все эпизоды
mkdir -p audio text
# список MP3 из RSS
grep -oE 'https://[^"]+\.mp3' feed.xml | sort -u > eps.txt
i=0
while read -r url; do
  i=$((i+1))
  curl -sL "$url" -o "audio/ep$i.mp3"
  whisper "audio/ep$i.mp3" --model small --language ru \
    --output_format txt --output_dir text
done < eps.txt
```

Затем единый поиск по всем транскриптам:

```bash
grep -rniE 'адрес|город|компани|github|@[a-z0-9._-]+' text/ | head -30
```

Регулярка `@[a-z0-9._-]+` вылавливает упомянутые ники и email — готовые pivot-идентификаторы.

## Анализ гостей и сети контактов

Подкасты часто строятся на интервью. Список гостей — это **сеть контактов** ведущего:

```bash
# из описаний эпизодов извлекаем имена гостей
grep -oE '<itunes:summary>[^<]+' feed.xml | grep -oE 'гость[^.]*' | head
```

Каждый гость — узел графа. Связи «ведущий ↔ гость» показывают профессиональный круг. В расследованиях это помогает понять окружение и найти общих знакомых.

## Тайм-коды и главы

Современные подкасты публикуют chapters (тайм-коды). Они позволяют перескакивать к нужной теме:

```
00:00 Введение
05:12 Как мы строили инфраструктуру
22:40 Проблемы с безопасностью
```

Chapters в RSS (`<podcast:chapters>`) или в описании — это готовый навигатор по контенту. Для OSINT это экономит часы прослушивания: сразу к релевантному фрагменту.

## Аудио как объект форензики

Помимо содержания, аудио — объект форензики:
- **спектрограмма** (`sox`) выявляет скрытые сообщения и признаки клона;
- **метаданные** (ID3, encoder) раскрывают софт и устройство;
- **фон** даёт геолокацию и время;
- **шум** позволяет оценить, писали ли в студии или на улице.

Комбинация транскрипта и форензики делает подкаст полноценным источником.

## Платформы и их API

| Платформа | API/данные |
|-----------|-----------|
| Apple Podcasts | iTunes Search API (`feedUrl`) |
| Spotify | Web API (эпизоды, но фид в RSS) |
| Podcast Index | открытый каталог + API |
| Listen Notes | поиск по транскриптам |
| Podchaser | гости, связи |

Podcast Index API — свободная альтернатива:

```bash
curl -s "https://api.podcastindex.org/api/1.0/search/byterm?q=target&pretty" \
  -H "X-Auth-Key: $KEY" -H "X-Auth-Date: $TS" -H "Authorization: $HASH"
```

Позволяет найти фид, автора и историю эпизодов без привязки к Spotify.

## Аудио-стеганография и скрытые данные

Аудио — носитель скрытых данных:
- **спектрограмма** может содержать текст/изображение (`sox`, `Sonic Visualiser`);
- **LSB в WAV** — младшие биты;
- **ID3-комментарии** — скрытый текст;
- **мультитреки** — скрытый канал в неиспользуемой дорожке.

```bash
sox audio.wav -n spectrogram -o spec.png
exiftool audio.mp3 | grep -iE 'comment|lyrics'
strings audio.mp3 | grep -iE 'flag|ctf|http'
```

Для CTF это отдельный класс задач (см. также stego-раздел дерева).

## Гости как pivot-точка

Список гостей подкаста — готовый список «интересных людей». Каждого гостя проверяем стандартно: LinkedIn (должность), GitHub (код), Twitter (мнения). Связи «ведущий ↔ гость» формируют граф отрасли. В threat intelligence интервью с представителями компании-цели дают прямые цитаты о технологиях и планах — ценный контекст, недоступный из сухих отчётов.

## Монетизация и спонсоры

Спонсорские вставки в подкастах раскрывают деловые связи автора и его аудиторию. Регулярные спонсоры одного автора совпадают со спонсорами связанных проектов — сигнал сети. Рекламные промокоды (`promo=NAME`) иногда содержат уникальный идентификатор, по которому можно найти другие площадки автора (см. `osint-tracking-ids`).

## Где пригодится

- **CTF (OSINT):** в транскрипте подкаста спрятана фраза/флаг.
- **Расследования:** установить автора и его окружение через гостей/упоминания.
- **Медиамониторинг:** отслеживать, что организация говорит публично.
- **Атрибуция:** сопоставление голоса между разными медиа.
- **Threat intelligence:** интервью с участниками угрозы содержат детали TTP.
