## Вопрос, с которого всё начинается

Публичные компании обязаны раскрывать массу информации: структуру, риски, судебные дела, технологии, дочерние фирмы, руководство. Это значит, что **отчёты SEC** — по сути готовый отчёт о разведке, только написанный юристами.

Где там смотреть, чтобы найти технологии, дочерние компании и ключевых людей, а не утонуть в сотнях страниц? Разберём это на одной публичной компании.

## Наш пример: публичная компания Example Inc

Работаем с `Example Inc`, у которой есть тикер и, значит, набор форм в системе **EDGAR** — открытой базе всех filings (подач) SEC. Пройдём путь от идентификатора компании до карты «кто, где, на чём».

## Шаг 1: находим CIK

У каждой компании в EDGAR есть **CIK** (Central Index Key) — уникальный числовой идентификатор. Проще всего получить его из общего справочника компаний и тикеров.

```bash
curl -s -A "osint-research example@example.com" \
  "https://www.sec.gov/files/company_tickers.json" | jq '.[] | select(.ticker=="EXMP")'
```

```
{ "cik_str": 1234567, "ticker": "EXMP", "title": "Example Inc" }
```

Теперь `1234567` — ключ ко всем данным компании. Обратите внимание на `User-Agent`: SEC требует осмысленный заголовок с контактом, иначе блокирует запрос.

## Шаг 2: тянем список filings

По CIK API отдаёт список последних подач с типами форм.

```bash
curl -s -A "osint example@example.com" "https://data.sec.gov/submissions/CIK0001234567.json" \
  | jq -r '.filings.recent | [.form, .accessionNumber, .primaryDocument] | transpose[] | @tsv' | head
```

```
10-K     0001234567-23-000001  ex-10k.htm
8-K      0001234567-23-000042  ex-8k.htm
DEF 14A  0001234567-23-000050  proxy.htm
```

Разные формы несут разное: **10-K** — годовой отчёт, **10-Q** — квартальный, **8-K** — существенные события, **DEF 14A** (proxy) — состав руководства. Не читай только 10-K: свежее обычно в 8-K.

## Шаг 3: читаем 10-K — Risk Factors

10-K — это сотни страниц, но ценность сосредоточена в нескольких разделах. Самый полезный для разведки — **Item 1A Risk Factors** (факторы риска): там прямо перечислены облачные провайдеры, ключевые SaaS и зависимости.

```bash
curl -s -A "osint example@example.com" \
  "https://www.sec.gov/Archives/edgar/data/1234567/000123456723000001/ex-10k.htm" -o filing.htm
python3 - <<'PY'
import re
html = open("filing.htm", encoding="utf-8", errors="ignore").read()
text = re.sub(r"<[^>]+>", " ", html)
for kw in ["Risk Factors", "cloud", "data center", "subsidiary", "litigation"]:
    i = text.lower().find(kw.lower())
    print("==", kw, "==")
    print(text[i:i+200].strip() if i > 0 else "(not found)")
PY
```

Из этого фрагмента видно, какие облака и вендоров компания считает критичными — это карта технологического стека.

## Шаг 4: Exhibit 21 — дочерние компании

**Exhibit 21** в 10-K перечисляет дочерние компании и их юрисдикции. Это расширение поверхности: каждая дочерняя фирма — новые домены, бренды и люди.

```text
Exhibit 21 — Subsidiaries of Example Inc:
  Example Europe GmbH       (Germany)
  Example Labs Ltd          (United Kingdom)
  Example Cloud LLC         (United States, Delaware)
```

Три строки — три новых направления для OSINT: ищи домены, WHOIS и патентные портфели каждой дочерней структуры.

## Шаг 5: 8-K и proxy — свежие события и люди

Форма **8-K** сообщает о существенных событиях — смене руководства, инцидентах, сделках. Формулировка «material cybersecurity incident» плюс смена CISO в proxy — прямой сигнал о свежем инциденте.

```bash
curl -s -A "osint example@example.com" \
  "https://efts.sec.gov/LATEST/search-index?q=%22material%20cybersecurity%20incident%22&forms=8-K" | jq '.hits.total'
```

```
14
```

**DEF 14A (proxy)** даёт имена и биографии руководства — дальше их проверяют по другим реестрам и соцсетям.

## Шаг 6: собираем карту разведки

Данные из SEC складываются в целостную картину:

```text
Exhibit 21      → дочерние компании и страны → новые домены и бренды
Properties      → офисы и дата-центры → геолокация
Risk Factors    → стек и вендоры → технологии для фингерпринта
Proxy (14A)     → ключевые лица → OSINT по сотрудникам
8-K             → свежие события, включая инциденты
```

Так один публичный документ превращается в план: что искать, где и у кого.

## Сравнение filings по годам

Часть инсайтов видна только в динамике. Скачайте 10-K за два года и сравните разделы:

```bash
for y in 2023 2024; do
  curl -s -A "osint example@example.com" "https://www.sec.gov/Archives/edgar/data/1234567/$y/ex-10k.htm" -o "$y.htm"
  python3 -c "import re;print(re.sub(r'<[^>]+>',' ',open('$y.htm',encoding='utf-8',errors='ignore').read()))" > "$y.txt"
done
diff <(fold -w120 2023.txt) <(fold -w120 2024.txt) | grep -i '^[<>]' | head -40
```

Новые строки в «Risk Factors» часто указывают на свежие проблемы — нового вендора, регуляторное расследование, киберинцидент. А появившаяся в Exhibit 21 дочерняя компания в новой юрисдикции означает расширение поверхности.

## Не-США аналоги

Для компаний вне США работают свои реестры, но приёмы те же — дочерние, руководители, адреса, судебные дела:

- **Companies House (UK)** — бесплатный API `https://api.company-information.service.gov.uk/`.
- **SEDAR+ (Канада)**, **OpenCorporates** (агрегатор по странам).
- **ЕГРЮЛ/ЕГРИП (Россия)**, **Handelsregister (Германия)**, **ASIC (Австралия)**.

## Практические сценарии и ограничения

Вот как filings работают на практике:

- **Пентест scope:** «Risk Factors» перечисляет облака и SaaS — это кандидаты на поддомены и интеграции; Exhibit 21 расширяет scope на дочерние юрлица.
- **Due diligence:** сравнение 10-K за три года показывает, какие риски компания признала и как менялась структура.
- **Расследование:** 8-K с формулировкой «material cybersecurity incident» плюс смена CISO в proxy — прямой сигнал о свежем инциденте.
- **Конкурентная разведка:** S-1 конкурента раскрывает поставщиков и инфраструктуру.

Ограничения тоже важны: filings публикуются с задержкой, большие блоки текста повторяются год к году, а «Risk Factors» — это предупреждения для инвесторов, а не описание реальных инцидентов. Не принимай шаблонный текст за свежий факт.

## Как читать форму эффективно

Не пытайся прочитать 10-K целиком: это сотни страниц юридического текста. Открой оглавление, перейди сразу к нужным разделам — Business, Risk Factors, Properties, Legal Proceedings — и выпиши только факты: технологии, вендоров, адреса, дочерние фирмы, имена. Остальное — вода и стандартные формулировки, которые повторяются из года в год.

## Что мы теперь знаем

По-простому:

1. EDGAR — бесплатная база всех отчётов публичных компаний.
2. CIK — ключ компании; запросы требуют User-Agent.
3. 10-K даёт риски, технологии и дочерние компании.
4. 8-K и proxy — свежие события и состав руководства.
5. Exhibit 21 расширяет поверхность на дочерние фирмы.

## На что смотреть дальше

- **Не игнорируй User-Agent.** SEC блокирует запросы без него.
- **Не читай только 10-K.** Свежее лежит в 8-K и proxy.
- **Не пропускай Exhibit 21.** Дочерние компании — важная часть карты.
- **Не верь Risk Factors как фактам.** Это шаблонные предупреждения для инвесторов.
- **Помни про задержку.** 10-K выходит через 60–90 дней после закрытия года.

## EDGAR через JSON API без ключа

Помимо веб-интерфейса, у EDGAR есть **публичные JSON-эндпоинты**, которые не требуют ключа и отдают данные машиночитаемо. Это ускоряет разведку и позволяет строить скрипты. Первый — **справочник тикеров**: `https://www.sec.gov/files/company_tickers.json` сопоставляет тикер, название и CIK; по нему из названия компании получаешь её CIK одной строкой кода.

```bash
curl -s -A "research you@example.com" \
  https://www.sec.gov/files/company_tickers.json | \
  python3 -c "import sys,json; d=json.load(sys.stdin); \
  print([v for v in d.values() if 'Example' in v['title']])"
```

Второй — **лента отчётности по CIK**: `https://data.sec.gov/submissions/CIK##########.json` (CIK дополняется нулями до 10 цифр) отдаёт историю форм, даты, ссылки на документы. Третий — **XBRL-фреймы**: `https://data.sec.gov/api/xbrl/frames/us-gaap/Assets/USD/CY2024Q4I.json` возвращает финансовый показатель всех компаний за период — удобно для сравнения. Четвёртый — **full-text search** (`efts.sec.gov/LATEST/search-index?q=...`) ищет фразу по всем документам, что бесценно при поиске упоминаний конкретного вендора, продукта или технологии в отчётах.

Важно: SEC требует **User-Agent с контактом** и ограничивает частоту (10 запросов/сек). Указывай реальный адрес — иначе получишь 403.

## Что искать в отчётах с точки зрения атаки

Формы — это не только финансы, но и карта инфраструктуры. В **10-K** раздел «Risk Factors» и «Properties» называет используемые облака и дата-центры, критичных поставщиков, а иногда и конкретные регионы. **Exhibit 21** («Subsidiaries») перечисляет дочерние компании — каждая это потенциально отдельный домен, отдельная периметровая точка и отдельная зона доверия, то есть расширение поверхности атаки.

В **S-1** (IPO) обычно подробно расписаны технологический стек, зависимости от сторонних сервисов и кадровые риски — почти готовый профиль инфраструктуры. **8-K** сообщает о событиях в реальном времени: смена руководства, слияния, инциденты. **DEF 14A** (proxy) раскрывает состав совета, ключевых сотрудников и их биографии — основа для целевого фишинга и для понимания структуры принятия решений. **10-K Item 1C** (с 2023) прямо описывает процессы управления киберриском, что говорит о зрелости защиты.

Практический вывод: сложи из форм карту «люди — дочерние компании — вендоры — облака». Затем сопоставь её с внешним периметром: найденные дочерние компании и домены — кандидаты на поддомены и устаревшие активы, а упомянутые SaaS-провайдеры — на SSO-интеграции. Так юридический документ превращается в осмысленную разведку, а не в чтение ради чисел.

## Куда дальше

В следующем уроке мы возьмём **номер автомобиля** и научимся по нему устанавливать владельца, модель и историю. А пока запомни главное: filings — это структурированный и легальный источник, где одна форма 10-K плюс Exhibit 21 плюс proxy дают готовую карту «кто, где, на чём».

## Где пригодится

- **CTF (OSINT):** найти факт или компанию через filings.
- **Due diligence:** оценка структуры и рисков публичной компании.
- **Расследования:** доказательства из официальных отчётов.
- **Пентест:** карта технологий, вендоров и дочерних компаний для scope.
