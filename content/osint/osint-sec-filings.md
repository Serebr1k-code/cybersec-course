Публичные компании обязаны раскрывать массу информации: структуру, риски, судебные дела, технологии, дочерние компании, топ-менеджмент. Формы SEC (10-K, 10-Q, 8-K, S-1) — это, по сути, готовый отчёт о разведке. Для пентеста здесь видны технологические стеки и партнёры, для расследований — доказательства. В этом уроке — как искать, читать и автоматически извлекать данные из filings.

## Теория: ключевые формы SEC

- **10-K** — годовой отчёт: бизнес, риски, собственность, суды, дочерние.
- **10-Q** — квартальный отчёт (промежуточные финансы, обновления рисков).
- **8-K** — существенные события (смена руководства, инциденты, сделки).
- **S-1** — регистрация IPO: подробности бизнеса и технологий.
- **DEF 14A (proxy)** — вознаграждение и состав руководства.
- **13F** — holdings институциональных инвесторов.
- **Form D** — привлечение капитала частными компаниями.
- **SC 13G/D** — крупные пакеты акций (кто владеет >5%).

Всё бесплатно на **SEC EDGAR**. Для не-США — аналоги: Companies House (UK), национальные реестры, Sedar+ (Канада).

## Что извлекать из каждой формы

| Форма | Что даёт для OSINT |
|---|---|
| 10-K | технологии, вендоры, офисы/ЦОД, дочерние, суды |
| 10-Q | изменения с прошлого года, новые риски |
| 8-K | свежие события, смена CISO/CTO, утечки |
| S-1 | детали бизнеса до IPO, партнёры, поставщики |
| DEF 14A | имена и биографии руководства и директоров |
| 13F | институциональные инвесторы |
| Form D | частные компании, привлекающие капитал |
| Exhibit 21 | список дочерних компаний и юрисдикций |

## Инструменты и команды

EDGAR full-text search (EFTS) и company search:

```text
https://efts.sec.gov/LATEST/search-index?q=%22example%22
https://www.sec.gov/cgi-bin/browse-edgar?action=getcompany&company=example
```

API EDGAR (без ключа, но обязательно с User-Agent):

```bash
curl -s -A "osint-research example@example.com" \
  "https://data.sec.gov/submissions/CIK0001234567.json" | jq '.filings.recent.form[0:10]'
```

Полнотекстовый поиск по всем filings:

```bash
curl -s -A "osint-research example@example.com" \
  "https://efts.sec.gov/LATEST/search-index?q=%22kubernetes%22&forms=10-K"
```

Скачивание документа:

```bash
curl -s -A "osint-research example@example.com" \
  "https://www.sec.gov/Archives/edgar/data/1234567/000123456723000001/ex-10k.htm" -o filing.htm
```

Важно: SEC требует осмысленный `User-Agent` с контактом; иначе — блокировка и бан по IP.

## Разобранный пример: технологический стек и риски

Дано: публичная компания `Example Inc`.

Шаг 1 — находим CIK через EDGAR company search (или `https://www.sec.gov/files/company_tickers.json`).

Шаг 2 — тянем список последних filings:

```bash
curl -s -A "osint example@example.com" "https://data.sec.gov/submissions/CIK0001234567.json" \
  | jq -r '.filings.recent | [.form, .accessionNumber, .primaryDocument] | transpose[] | @tsv' | head
```

Вывод (фрагмент):

```
10-K  0001234567-23-000001  ex-10k.htm
8-K   0001234567-23-000042  ex-8k.htm
DEF 14A 0001234567-23-000050  proxy.htm
```

Шаг 3 — в 10-K читаем разделы: «Business», «Risk Factors», «Properties», «Legal Proceedings», «Subsidiaries».

Шаг 4 — из «Risk Factors» выписываем технологии и зависимости (облака, вендоры) — карта стека.

Шаг 5 — из «Subsidiaries» (Exhibit 21) — список дочерних компаний и юрисдикций.

Шаг 6 — ищем упоминания инцидентов в 8-K и судебных делах в «Legal Proceedings».

## Разделы 10-K, которые важнее всего для разведки

10-K — это сотни страниц, но ценность сосредоточена в нескольких разделах:

| Раздел | Что искать |
|---|---|
| Item 1 Business | продукты, рынки, ключевые клиенты, конкуренты |
| Item 1A Risk Factors | технологии, вендоры, зависимости, регуляторика |
| Item 2 Properties | офисы, дата-центры, склады (адреса!) |
| Item 3 Legal Proceedings | суды, иски, регуляторные разбирательства |
| Item 7 MD&A | финансовое состояние, планы |
| Exhibit 21 | список дочерних компаний и юрисдикций |
| Exhibit 10.x | значимые контракты (иногда с условиями) |

**Risk Factors** — золотая жила для оценки поверхности: там прямо перечислены облачные провайдеры, ключевые SaaS и зависимости, которые компания считает критичными.

## Автоматизация извлечения данных из filings

Ручное чтение 10-K не масштабируется. Извлекайте структуру и ищите ключевые слова:

```bash
curl -s -A "osint example@example.com" "https://www.sec.gov/Archives/edgar/data/1234567/000123456723000001/ex-10k.htm" -o filing.htm
python3 - <<'PY'
import re
html = open("filing.htm", encoding="utf-8", errors="ignore").read()
text = re.sub(r"<[^>]+>", " ", html)
for kw in ["Risk Factors", "cloud", "data center", "subsidiary", "litigation"]:
    idx = text.lower().find(kw.lower())
    print("==", kw, "==")
    print(text[idx:idx+300].strip()[:300] if idx > 0 else "(not found)")
PY
```

Полнотекстовый поиск EDGAR (EFTS) позволяет искать по **всем** filings сразу:

```bash
curl -s -A "osint example@example.com" \
  "https://efts.sec.gov/LATEST/search-index?q=%22Cloudflare%22&forms=10-K" | jq '.hits.total'
# 87
```

## От filings к карте инфраструктуры

Данные из SEC складываются в целостную картину:

1. **Exhibit 21** → список дочерних компаний и стран → расширение доменов и брендов для поиска.
2. **Properties** → физические локации → геолокация дата-центров и офисов.
3. **Risk Factors** → стек и вендоры → технологии для фингерпринта.
4. **Proxy (DEF 14A)** → ключевые лица → перекрёстный OSINT по сотрудникам.
5. **8-K** → свежие события (включая киберинциденты и смену CISO).

Так публичный документ превращается в план разведки: что искать, где и у кого.

## Не-США аналоги

- **Companies House (UK)** — бесплатный реестр, API `https://api.company-information.service.gov.uk/`.
- **SEDAR+ (Канада)**, **OpenCorporates** (агрегатор по странам).
- **ЕГРЮЛ/ЕГРИП (Россия)**, **Handelsregister (Германия)**, **INPI/RCS (Франция)**.
- **ASIC (Австралия)**, **CIPC (ЮАР)**.

Приёмы те же: дочерние, руководители, адреса, судебные дела.

## Продвинутые приёмы

- **Full-text search:** ищите названия технологий/вендоров по всем filings.
- **Exhibit 21:** список дочерних компаний — расширение поверхности.
- **Proxy (DEF 14A):** состав руководства и вознаграждение.
- **8-K:** свежие события, включая утечки и смену CISO.
- **Form D:** частные компании, привлекающие капитал, без IPO.
- **Сравнение по годам:** изменения в рисках/структуре между 10-K.
- **Связанные лица:** директора из proxy → перекрёстный поиск в других реестрах.
- **XBRL-данные**: `https://data.sec.gov/api/xbrl/companyconcept/...` — финансы машинно-читаемо.

## Частые ошибки

- **Игнорировать User-Agent.** SEC блокирует запросы без него.
- **Читать только 10-K.** 8-K и proxy содержат свежие/ключевые данные.
- **Пропускать Exhibit 21.** Дочерние компании — важная часть карты.
- **Верить «Risk Factors» как фактам.** Это шаблонные предупреждения.
- **Забыть про не-США аналоги.** Для других юрисдикций — свои реестры.
- **Нет извлечения данных.** Без парсинга большой filing тяжело читать.

## EDGAR без API: парсинг индексов

Если API недоступен, filings берутся напрямую из дерева `/Archives`. У каждой подачи есть индекс-файл, перечисляющий документы:

```bash
# index.json подачи — список всех файлов
curl -s -A "osint example@example.com" \
  "https://www.sec.gov/Archives/edgar/data/1234567/000123456723000001/index.json" \
  | jq -r '.directory.item[] | [.name, .size] | @tsv'
```

Вывод помогает быстро найти Exhibit 21 или нужный `.htm`, не качая весь пакет. Для исторических filings используйте quarterly index: `https://www.sec.gov/Archives/edgar/full-index/`.

## Практические сценарии

- **Bug bounty / пентест scope**: 10-K «Risk Factors» перечисляет облака и SaaS — это кандидаты на поддомены и интеграции; Exhibit 21 расширяет scope на дочерние юрлица.
- **Due diligence**: сравнение 10-K за 3 года показывает, какие риски компания признала (регуляторика, кибербезопасность) и как менялась структура.
- **Расследование**: 8-K с формулировкой «material cybersecurity incident» + смена CISO в proxy — прямой сигнал о свежем инциденте.
- **Конкурентная разведка**: S-1 конкурента раскрывает поставщиков, инфраструктуру и метрики.

## Сравнение filings по годам (diff)

Часть инсайтов видна только в динамике. Скачайте 10-K за два года и сравните ключевые разделы:

```bash
# нормализуем в текст и делаем diff по разделу Risk Factors
for y in 2023 2024; do
  curl -s -A "osint example@example.com" "https://www.sec.gov/Archives/edgar/data/1234567/$y/ex-10k.htm" -o "$y.htm"
  python3 -c "import re,sys;print(re.sub(r'<[^>]+>',' ',open('$y.htm',encoding='utf-8',errors='ignore').read()))" > "$y.txt"
done
diff <(fold -w120 2023.txt) <(fold -w120 2024.txt) | grep -i '^[<>]' | head -40
```

Новые строки в «Risk Factors» часто указывают на свежие проблемы (новый вендор, регуляторное расследование, киберинцидент), а исчезнувшие — на устранённые риски. Так же сравнивайте Exhibit 21: появившаяся дочерняя компания в новой юрисдикции = расширение поверхности.

## Ограничения и нюансы

- **Задержка**: filings публикуются с задержкой (10-K — до 60–90 дней после закрытия года), поэтому свежих данных там нет.
- **Шаблонность**: большие блоки текста повторяются год к году — не принимайте их за свежие факты.
- **Юридическая формулировка**: «Risk Factors» — это предупреждения для инвесторов, а не описание реальных инцидентов.
- **Англоязычность**: для не-США компаний данные фрагментированы по национальным реестрам.
- **Формат**: исторические filings бывают в `.txt`/`.htm` без разметки — нужен парсинг.

## Что дальше / решение

Filings — это структурированный, легальный и очень богатый источник. Дальше свяжите их с другими реестрами (Companies House, OpenCorporates), с WHOIS/DNS по найденным дочерним компаниям и с соцсетями по именам руководства. Итог: одна форма 10-K + Exhibit 21 + proxy дают готовую карту «кто, где, на чём» для планирования дальнейшей разведки.

## Где пригодится

- **CTF (OSINT):** найти факт/компанию через filings.
- **Due diligence:** оценка структуры и рисков публичной компании.
- **Расследования:** доказательства из официальных отчётов.
- **Пентест:** карта технологий, вендоров и дочерних компаний для scope.
