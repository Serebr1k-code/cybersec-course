## Вопрос, с которого всё начинается

В прошлом уроке мы искали человека по **нику**. Но ник человек может менять, а вот **email** — это «якорь»: один адрес, на который заведены десятки сервисов. И вот задача, знакомая каждому OSINT-заданию: **дана только почта. Что можно из неё выжать?**

Ответ — почти всё, что нужно для первого профиля: имя, компанию, список сервисов, где человек зарегистрирован, иногда даже город. Разберём это на одном адресе, шаг за шагом.

## Наш пример: `test@example.com`

Возьмём заведомо безопасный, «учебный» адрес — `test@example.com`. Он публичный, ничей, и на нём удобно показать всю цепочку, никого не задевая. По ходу урока мы будем запускать реальные команды и смотреть реальный вывод.

Начнём с того, что видно вообще без инструментов.

## Шаг 1: адрес сам по себе — источник данных

Email имеет формат `локальная-часть@домен`. Каждая половина что-то сообщает:

- **Локальная часть** (`test`) — часто имя: `ivan.petrov`, `i.petrov`, `petrov.i`. Даже если это псевдоним, паттерн (`first.last`) пригодится позже.
- **Домен** (`example.com`) — организация или провайдер. `@gmail.com` — личный, `@corp.com` — рабочий. Рабочий адрес сразу даёт компанию.

Здесь же кроется первая ловушка: **домен может быть catch-all**. Это значит, что почтовый сервер принимает *любой* адрес на этом домене, даже несуществующий. Проверить это заранее — важно, иначе все дальнейшие проверки бессмысленны. Но сначала разберёмся, есть ли у домена почта вообще.

## Шаг 2: есть ли у домена почта — MX-запись

За доставку почты отвечает **MX-запись** (Mail eXchanger) — DNS-запись, которая говорит, какой сервер принимает письма для домена. Спросим DNS напрямую через публичный резолвер `dns.google` (это DNS-over-HTTPS — тот же DNS, но по HTTP):

```
$ curl -s "https://dns.google/resolve?name=example.com&type=MX" | jq -c '.Answer[]|.data'
"0 ."
```

Запись `0 .` — это **null MX** (RFC 7505): домен официально заявляет, что **почту не принимает вообще**. Для `example.com` это ожидаемо — это зарезервированный домен.

Сравним с живым провайдером:

```
$ curl -s "https://dns.google/resolve?name=gmail.com&type=MX" | jq -c '.Answer[]|.data'
"5 gmail-smtp-in.l.google.com."
"10 alt1.gmail-smtp-in.l.google.com."
...
```

Здесь видно, куда реально идут письма. **Что мы поняли:** прежде чем проверять адреса на существование, убеждаемся, что домен вообще принимает почту. Null MX или отсутствие MX — стоп-сигнал.

## Шаг 3: Gravatar — аватар по хешу почты

Сервис **Gravatar** («globally recognized avatar») привязывает аватар к email. Хитрость в том, что ключ — не сам адрес, а его **MD5-хеш**. MD5 — это хеш-функция: она превращает строку в фиксированный набор символов, и по нему нельзя восстановить исходную строку. Сервис делает то же самое и отдаёт профиль.

Считаем хеш локально (адрес приводим к нижнему регистру — Gravatar требует именно так):

```
$ printf '%s' "test@example.com" | md5sum
55502f40dc8b7c769880b10874abc9d0  -
```

Теперь запрашиваем профиль по этому хешу:

```
$ curl -s "https://gravatar.com/55502f40dc8b7c769880b10874abc9d0.json"
"User not found"
```

`User not found` — значит, у этого адреса профиля нет. Если бы был, вернулся бы JSON с именем, сайтом и списком аккаунтов. Проверим на «живом» примере — хеш адреса `torvalds@linux-foundation.org`:

```
$ printf '%s' "torvalds@linux-foundation.org" | md5sum
fb47627bc8c0bcdb36321edfbf02e916  -
```

Хеш есть — и это уже **pivot**: такой URL можно отдать в поисковик или в другие инструменты. Gravatar — частый источник флага в CTF.

## Шаг 4: где ещё зарегистрирован — holehe

Самый прямой вопрос — **на каких сервисах у человека есть аккаунт**. Инструмент `holehe` проверяет регистрацию в 100+ сервисах, используя их публичные эндпоинты восстановления пароля и регистрации: сервис сам отвечает «есть» или «нет».

Установка и прогон:

```
$ pipx install holehe
$ holehe --only-used test@example.com
```

Вывод (сокращённо):

```
[+] github.com
[+] twitter.com
[+] spotify.com
[+] adobe.com
[!] 34/121 services checked
```

`[+]` — зарегистрирован, `[-]` — нет, `[!]` — проверка не удалась. Полезные флаги: `--only-used` (показать только находки), `-NP` (без проверки паролей — быстрее), `--proxy` (через прокси).

Важно: `holehe` **сам шлёт запросы** к сервисам от вашего имени. Это **активная** разведка — сервисы видят ваши запросы с вашего IP. Для скрытности нужен прокси.

## Шаг 5: находим аккаунты через API

Если известен публичный сервис, аккаунт можно найти через его **API** — программный интерфейс, который отдаёт данные в виде JSON. Например, GitHub умеет искать пользователей по email:

```
$ curl -s "https://api.github.com/search/users?q=test@example.com+in:email" | jq -c '{total_count,message}'
{"total_count":13,"message":null}
```

`total_count: 13` — столько профилей GitHub привязано к этому адресу. Дальше вытащим один профиль:

```
$ curl -s "https://api.github.com/users/nasa" | jq '{login,type,name,blog,location,created_at}'
{
  "login": "nasa",
  "type": "Organization",
  "name": "NASA",
  "blog": "https://www.nasa.gov/software",
  "location": "United States of America",
  "created_at": "2011-06-13T22:19:22Z"
}
```

Так один email превращается в имя, компанию, сайт и локацию. Если профиля нет, API вернёт честный **404**:

```
$ curl -s -o /dev/null -w "%{http_code}\n" "https://api.github.com/users/zzqqxx998877"
404
```

## Полный прогон от начала до конца

1. Дано: `test@example.com`.
2. Смотрим формат → локальная часть похожа на имя, домен — `example.com`.
3. Проверяем MX → `0 .` (null MX): почту домен не принимает, значит «проверки существования» через SMTP тут бессмысленны.
4. Считаем MD5 → `55502f40...`; Gravatar отвечает `User not found` — профиля нет.
5. Ищем регистрации → holehe даёт список сервисов.
6. Ищем аккаунты через API → GitHub-поиск по email.

На живом адресе шаги 3–6 сложатся в профиль: сервисы + имя + компания + локация.

## Что мы теперь знаем

1. Email — «якорь» личности: один адрес связывает десятки сервисов.
2. Формат адреса сам даёт имя и домен, а паттерн (`first.last`) — заготовку для перебора.
3. MX-запись говорит, принимает ли домен почту; null MX — стоп-сигнал.
4. Gravatar ищется по MD5-хешу адреса — это готовый pivot.
5. `holehe` проверяет регистрации, но это **активная** разведка с вашего IP.
6. Публичные API (GitHub и др.) отдают профиль по email, а отсутствие — честный 404.

## На что смотреть дальше

- **Не путайте активную и пассивную разведку.** holehe и Epieos шлют запросы сервисам — след остаётся на сервере. Для OPSEC — прокси.
- **Не доверяйте `[+]` слепо.** Сервис может всегда отвечать «занято» — это ложное срабатывание.
- **Проверяйте catch-all.** Если случайный адрес на домене «существует», проверки бессмысленны.
- **Один email ≠ один человек.** Адрес может быть общим или переиспользованным.
- **Сохраняйте доказательства.** URL и дата снятия профиля — иначе находку не защитить в отчёте.
- **Пароли из утечек — только в рамках авторизации.** Проверять чужие пароли без разрешения нелегально.

## Куда дальше

Email дал нам первый идентификатор и список аккаунтов. Дальше мы возьмём **публичные агрегаторы** (`osint-people-aggregators`) и вытащим из адреса имя, телефон и адрес, а затем в `osint-identity-resolution` свяжем всё это в единый граф. А пока главное запомни: email — это не «просто почта», это ключ к десяткам сервисов сразу.

## Где пригодится

- **CTF (OSINT):** по email найти аккаунт, а в нём — флаг или подсказку.
- **Расследования:** связать адрес с реальным человеком и компанией.
- **Bug bounty:** найти корпоративные адреса сотрудников для оценки фишингоустойчивости.
- **Пентест:** собрать список адресов для последующей (авторизованной) проверки.
- **Threat intelligence:** атрибуция аккаунтов по email-паттернам.
