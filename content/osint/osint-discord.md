Discord — дом для технических сообществ, геймеров, стартапов и, к сожалению, утечек. Публичные серверы индексируются, а API отдаёт метаданные без аутентификации. Здесь часто встречаются внутренние ссылки, токены (случайно), списки сотрудников. В этом уроке — методика вежливой разведки через публичный API.

## Теория: что доступно в Discord

- **Сервер (guild):** название, иконка, описание, регион, число участников.
- **Каналы:** список виден после вступления, но метаданные иногда утекают.
- **Инвайты:** `discord.gg/<code>` — точка входа; API отдаёт инфо о сервере по коду без логина.
- **Вебхуки:** URL вида `discord.com/api/webhooks/<id>/<token>`; если утёк — можно слать сообщения (уязвимость, не трогать без scope).
- **Профили:** username, тег, аватар, дата регистрации (ID → timestamp).
- **Боты:** публичные боты раскрывают статистику.

Публичный API endpoint для инвайта:

```text
GET https://discord.com/api/v10/invites/<code>?with_counts=true
```

## Инструменты и команды

Информация об инвайте (без логина):

```bash
curl -s "https://discord.com/api/v10/invites/discord-developers?with_counts=true" \
  | jq '{guild:.guild.name, members:.approximate_member_count, online:.approximate_presence_count}'
```

ID → дата регистрации (snowflake):

```python
# (id >> 22) + 1420070400000 = ms epoch
python3 -c "import datetime; print(datetime.datetime.utcfromtimestamp(((123456789012345678>>22)+1420070400000)/1000))"
```

Поиск серверов и инвайтов:

```text
site:discord.gg "example"
site:discord.com/invite "example"
site:disboard.org "example"
site:top.gg "example"
```

Каталоги: **disboard.org**, **disforge.com**, **top.gg**.

## Discord API: работа с эндпоинтами

Публичный API Discord (v10) отдаёт часть данных без токена. Основные полезные эндпоинты:

```text
GET /api/v10/invites/<code>?with_counts=true   # метаданные сервера по инвайту
GET /api/v10/users/<id>                         # профиль (нужен токен для деталей)
GET /api/v10/guilds/<id>/preview                # публичный предпросмотр сервера
GET /api/v10/guilds/<id>/widget.json            # виджет (если включён админом)
```

Виджет (`widget.json`) — недооценённый источник: если владелец включил виджет, он отдаёт **список каналов и онлайн-участников** без аутентификации:

```bash
curl -s "https://discord.com/api/v10/guilds/<guild_id>/widget.json" \
  | jq '{name, presence_count, channels: [.channels[].name]}'
```

Snowflake-ID кодирует время создания: `(id >> 22) + 1420070400000` — миллисекунды Unix. Это позволяет датировать сервер и аккаунт, даже не заходя внутрь.

## Разобранный пример: сообщество компании

Дано: `Example Corp`.

Шаг 1 — ищем инвайты через поисковики и каталоги:

```text
site:discord.gg "Example Corp"
site:disboard.org "Example Corp"
```

Шаг 2 — по коду инвайта получаем метаданные сервера:

```bash
curl -s "https://discord.com/api/v10/invites/abc123?with_counts=true" \
  | jq '{name:.guild.name, id:.guild.id, members:.approximate_member_count}'
```

Шаг 3 — по ID сервера вычисляем дату создания (snowflake).

Шаг 4 — вступаем в публичный сервер (если это допустимо) и читаем публичные каналы: `#announcements`, `#general`, ссылки на GitHub/сайт, имена модераторов (сотрудники).

Шаг 5 — ищем утёкшие вебхуки в публичном коде (GitHub, pastebin):

```text
site:github.com "discord.com/api/webhooks"
site:pastebin.com "discord.com/api/webhooks"
```

Шаг 6 — фиксируем: серверы, участники, возможные утечки. Вебхук **не** эксплуатируем без явного scope.

## Продвинутые приёмы

- **Snowflake-анализ:** дата создания аккаунта/сервера по ID.
- **Вебхуки в коде:** частая утечка в публичных репозиториях — фиксируется как находка.
- **Кросс-корреляция:** username из Discord → другие платформы.
- **Архивы:** удалённые сообщения могут быть в Wayback или в бот-логах.
- **Боты-аналитики:** показывают активность и «здоровье» сервера.
- **Роли:** названия ролей часто совпадают с отделами компании.

## OPSEC и правовые границы в Discord-разведке

Discord — приватная по своей природе платформа, и здесь особенно легко перейти черту:

- **Публичное ≠ открытое для сбора.** Вступая на сервер, вы принимаете ToS; массовый сбор участников нарушает правила.
- **Не пишите в чужие каналы** под разведывательной легендой без явного разрешения (red team scope).
- **Утёкший вебхук** — это уязвимость. Правильное действие: зафиксировать (URL, дата, контекст), сообщить владельцу, **не** отправлять сообщения.
- **Изолируйте личность:** отдельный аккаунт, отдельный браузерный профиль, отдельный IP, если задача чувствительна.
- **Фиксируйте доказательства**: скриншот + текст + ID + время; сервер может быть удалён в любой момент.

## Практический чек-лист Discord-разведки

```text
1. Найти инвайты: site:discord.gg / disboard / disforge
2. Получить метаданные: GET /invites/<code>?with_counts=true
3. Датировать: snowflake → timestamp
4. Проверить виджет: /guilds/<id>/widget.json
5. Вступить (если допустимо) и прочитать публичные каналы
6. Искать вебхуки: site:github.com "discord.com/api/webhooks"
7. Зафиксировать артефакты и оценку достоверности
```

## Инструменты и флаги

| Инструмент | Назначение |
|---|---|
| Discord API v10 | инвайты, виджет, метаданные |
| disboard.org / disforge.com | каталоги серверов |
| `site:discord.gg` | поиск инвайтов |
| snowflake-формула | датирование ID |
| GitHub/Pastebin-поиск | утёкшие вебхуки |
| Wayback | удалённые сообщения |

## Частые ошибки

- **Эксплуатировать утёкший вебхук.** Это атака, а не разведка; только фиксировать в рамках scope.
- **Спамить в чужие серверы.** Нарушение ToS и мгновенный бан.
- **Игнорировать API инвайта.** Он даёт метаданные без логина.
- **Путать ID с датой.** Нужна формула snowflake.
- **Верить каталогам.** Часть серверов мертва или переименована.
- **Забыть про роли.** Роли раскрывают оргструктуру.

## Что делать дальше / решение

- **Нужны серверы компании** → каталоги + `site:discord.gg`.
- **Нужны метаданные** → API инвайта + виджет + snowflake.
- **Нужны утечки** → поиск вебхуков/токенов в коде → фиксация (без эксплуатации).
- **Нужны связи** → usernames → кросс-корреляция по другим платформам.

## Поиск серверов через каталоги глубоко

Каталоги Discord индексируют тысячи серверов с описаниями и тегами. Приёмы:

- **Disboard**: поиск по ключевому слову + фильтр по тегам и языку; у каждого сервера виден инвайт и число участников.
- **Disforge / Discord.me**: альтернативные каталоги с иными наборами серверов.
- **top.gg**: серверы, связанные с ботами (часто технические сообщества).
- **`site:discord.gg "<keyword>"`**: поисковики индексируют инвайт-страницы с превью названия.

```bash
curl -s "https://disboard.org/search?keyword=example" | grep -oE 'discord\.gg/[A-Za-z0-9]+' | sort -u
```

Из каталогов берите инвайты и сразу прогоняйте через API инвайта — так вы получаете метаданные и отсекаете мёртвые серверы.

## Кросс-корреляция участников

Discord-username — сильный кросс-идентификатор, потому что люди переиспользуют ники:

- **Username → другие платформы**: проверьте тот же ник в GitHub, X, Reddit, Steam (см. `osint-username-enum`).
- **Аватар → reverse image**: связывает аккаунты с одинаковой картинкой.
- **Роли на сервере**: `#staff`, `#mod`, `#dev` указывают на сотрудников/ключевых участников.
- **Дата создания (snowflake)**: старые аккаунты — «старожилы» сообщества.

Строя таблицу `username, platform, url, confidence`, вы получаете граф, где Discord — один из узлов.

## Типичные находки (кейсы)

Что реально находят в Discord-разведке:

- **Утёкшие вебхуки** в публичных репозиториях — позволяют слать сообщения (фиксировать, не эксплуатировать).
- **Внутренние ссылки**: скриншоты дашбордов, URL staging-серверов в `#general`.
- **Списки сотрудников** в описаниях ролей или в канале `#team`.
- **Анонсы до релиза**: продуктовые планы раньше публичного запуска.
- **Публичные боты-токены**, случайно закоммиченные разработчиками.

Каждую находку фиксируйте с ID, временем и контекстом: сервер может исчезнуть, и без снимка доказательство потеряется.
