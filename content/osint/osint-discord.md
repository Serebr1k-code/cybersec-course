## Вопрос, с которого всё начинается

Компания `Example Corp` ведёт сообщество в Discord. Там обсуждают продукт, публикуют анонсы и иногда — по неосторожности — внутренние ссылки и токены. Как туда заглянуть, не нарушая правил?

Оказывается, многое видно **до вступления**: у Discord есть публичный API, который отдаёт метаданные сервера без аутентификации. В этом уроке мы разберём вежливую разведку Discord на одном сообществе — от поиска инвайта до кросс-корреляции участников.

## Наш пример: сообщество компании Example Corp

Работаем с одним объектом — сообществом компании `Example Corp`. Наша цель: найти сервер, узнать его метаданные, датировать его и проверить на утечки. Ничего не эксплуатируем — только публичные данные.

## Шаг 1: находим инвайт через каталоги

Вход в Discord — это **инвайт**, ссылка вида `discord.gg/<code>`. Публичные серверы индексируются каталогами и поисковиками.

```text
site:discord.gg "Example Corp"
site:disboard.org "Example Corp"
site:top.gg "Example Corp"
```

Каталоги (**disboard.org**, **disforge.com**, **top.gg**) хранят описания, теги и число участников. Из них удобно вытаскивать инвайты пачкой:

```bash
curl -s "https://disboard.org/search?keyword=example" | grep -oE 'discord\.gg/[A-Za-z0-9]+' | sort -u
```

```
discord.gg/examplecorp
discord.gg/ex-com
```

Осторожно: часть серверов мертва или переименована — каждый инвайт надо проверить.

## Шаг 2: метаданные сервера без логина

Ключевой эндпоинт Discord API отдаёт информацию о сервере прямо по коду инвайта, без токена:

```bash
curl -s "https://discord.com/api/v10/invites/examplecorp?with_counts=true" \
  | jq '{name: .guild.name, id: .guild.id, members: .approximate_member_count, online: .approximate_presence_count}'
```

```
{
  "name": "Example Corp Community",
  "id": "123456789012345678",
  "members": 4213,
  "online": 312
}
```

Мы получили имя сервера, его **ID** и размер сообщества — не заходя внутрь. `with_counts=true` добавляет количество участников и онлайн.

## Шаг 3: датируем сервер по snowflake

ID в Discord — это **snowflake**: число, в котором зашита дата создания. Первые 42 бита — миллисекунды с 1 января 2015 года. Значит, дату можно вычислить:

```python
# (id >> 22) + 1420070400000 = миллисекунды Unix
python3 -c "import datetime; print(datetime.datetime.utcfromtimestamp(((123456789012345678>>22)+1420070400000)/1000))"
```

```
2016-08-01 04:20:33
```

Так мы датируем и сервер, и любой аккаунт — даже не вступая. Старые серверы и аккаунты — «старожилы» сообщества, что полезно для атрибуции.

## Шаг 4: виджет раскрывает каналы

Если владелец сервера включил **виджет**, его эндпоинт отдаёт список каналов и онлайн-участников вообще без аутентификации:

```bash
curl -s "https://discord.com/api/v10/guilds/123456789012345678/widget.json" \
  | jq '{name, presence_count, channels: [.channels[].name]}'
```

```
{
  "name": "Example Corp Community",
  "presence_count": 312,
  "channels": ["announcements", "general", "support", "jobs"]
}
```

Каналы вроде `jobs` и `announcements` прямо указывают, где искать контакты и анонсы. Виджет — недооценённый источник, потому что о нём часто забывают.

## Шаг 5: ищем утёкшие вебхуки в коде

Discord-вебхук — это URL вида `discord.com/api/webhooks/<id>/<token>`, позволяющий отправлять сообщения в канал. Если он случайно попал в публичный код, это уязвимость.

```text
site:github.com "discord.com/api/webhooks"
site:pastebin.com "discord.com/api/webhooks"
```

Правильное действие с найденным вебхуком — **зафиксировать** (URL, дата, контекст) и сообщить владельцу. Отправлять сообщения нельзя: это уже атака, а не разведка. То же касается бот-токенов, случайно закоммиченных разработчиками.

## Шаг 6: кросс-корреляция и фиксация

Discord-username — сильный кросс-идентификатор, потому что люди переиспользуют ники. Один ник проверяем в GitHub, X, Reddit, Steam. Аватар — через обратный поиск изображения. Роли (`#staff`, `#mod`, `#dev`) указывают на сотрудников.

Строим таблицу и фиксируем артефакты:

```
username        platform   url                         confidence
ivan_dev        discord    discord.com/users/...        high
ivan_dev        github     github.com/ivan_dev          high (тот же ник)
examplecorp     server     discord.gg/examplecorp       confirmed
```

Сервер могут удалить в любой момент, поэтому снимок, ID и время обязательны — без них доказательство теряется.

## Поиск серверов через каталоги глубоко

Каталоги Discord индексируют тысячи серверов с описаниями и тегами, и это отдельный навык:

- **Disboard** — поиск по ключевому слову с фильтром по тегам и языку; у каждого сервера виден инвайт и число участников.
- **Disforge и Discord.me** — альтернативные каталоги с иными наборами серверов.
- **top.gg** — серверы, связанные с ботами, часто технические сообщества.
- **`site:discord.gg "<keyword>"`** — поисковики индексируют инвайт-страницы с превью названия.

Из каталогов бери инвайты и сразу прогоняй их через API инвайта — так ты получаешь метаданные и отсекаешь мёртвые серверы, не тратя время на вступление.

## Типичные находки в Discord-разведке

Что реально находят при разведке сообществ:

- **Утёкшие вебхуки** в публичных репозиториях — позволяют слать сообщения (фиксировать, не эксплуатировать).
- **Внутренние ссылки:** скриншоты дашбордов, URL staging-серверов в общем канале.
- **Списки сотрудников** в описаниях ролей или в канале команды.
- **Анонсы до релиза:** продуктовые планы раньше публичного запуска.
- **Бот-токены**, случайно закоммиченные разработчиками.

Каждую находку фиксируй с ID, временем и контекстом: сервер может исчезнуть, и без снимка доказательство потеряется.

## Кросс-корреляция участников

Discord-username — сильный кросс-идентификатор, потому что люди переиспользуют ники. Работает это так:

- **Username → другие платформы:** проверь тот же ник в GitHub, X, Reddit, Steam.
- **Аватар → обратный поиск:** связывает аккаунты с одинаковой картинкой.
- **Роли на сервере:** `#staff`, `#mod`, `#dev` указывают на сотрудников и ключевых участников.
- **Дата создания (snowflake):** старые аккаунты — «старожилы» сообщества.

Строя таблицу `username, platform, url, confidence`, ты получаешь граф, где Discord — лишь один из узлов. И как всегда: одно совпадение ника — кандидат, а не доказательство.

## OPSEC и правовые границы

Discord по своей природе приватнее Telegram, и здесь особенно легко перейти черту. Публичное не означает открытое для массового сбора: вступая на сервер, ты принимаешь ToS, а массовый сбор участников нарушает правила. Не пиши в чужие каналы под легендой без явного scope. Утёкший вебхук — это уязвимость: правильное действие — зафиксировать (URL, дата, контекст) и сообщить владельцу, а не отправлять сообщения. Для чувствительных задач изолируй личность: отдельный аккаунт, профиль и IP. И всегда фиксируй доказательства — сервер могут удалить в любой момент.

## Что мы теперь знаем

По-простому:

1. Инвайты Discord индексируются каталогами и поисковиками.
2. API инвайта отдаёт метаданные сервера без логина.
3. Snowflake-ID кодирует дату создания сервера и аккаунта.
4. Виджет раскрывает каналы и онлайн-участников.
5. Утёкший вебхук — уязвимость: фиксируем, не эксплуатируем.

## На что смотреть дальше

- **Не эксплуатируй вебхук.** Это атака, а не разведка; только фиксация в рамках scope.
- **Не спамь в чужие серверы.** Нарушение ToS и мгновенный бан.
- **Не путай ID с датой.** Нужна формула snowflake.
- **Не верь каталогам слепо.** Часть серверов мертва или переименована.
- **Изолируй личность.** Для чувствительных задач — отдельный аккаунт, профиль и IP.
