## Вопрос, с которого всё начинается

Ты хочешь узнать, какие сервисы наружу есть у организации `Acme`. Новичок запускает `nmap` по её диапазону — долго, шумно и сразу заметно.

**Shodan** — это поисковик не по сайтам, а по **баннерам сервисов**. Он уже просканировал интернет и сохранил ответы: HTTP-заголовки, сертификаты, баннеры баз данных. Умение строить запросы = умение мгновенно находить чужую инфраструктуру, не отправляя ни одного пакета на цель. Разберём это на одной задаче.

## Наш пример: серверы организации Acme

У нас один объект — организация `Acme`. Задача: найти все её серверы с открытым SSH и их версии. Введём термин: **баннер** — то, что сервис отвечает на подключение (например, `SSH-2.0-OpenSSH_8.9`).

## Шаг 1: учимся думать фильтрами

Запрос в Shodan — это фильтр по полям баннера. Ключевое правило синтаксиса: **пробел означает «И»**. То есть `org:Acme port:22` найдёт только то, что подходит под оба условия.

Наш первый запрос:

```
org:"Acme" port:22
```

Через API это выглядит так:

```bash
shodan search --fields ip_str,port,product,version 'org:"Acme" port:22' > acme_ssh.json
jq -r '.[] | "\(.ip_str)\t\(.product) \(.version)"' acme_ssh.json | sort -u
```

```
203.0.113.10	OpenSSH 8.9
203.0.113.15	OpenSSH 7.4
198.51.100.7	OpenSSH 9.3
```

Три сервера. Обрати внимание на `203.0.113.15` — OpenSSH 7.4 старый, и это уже повод для второго прохода по версиям.

## Шаг 2: собираем набор фильтров

Чтобы искать по разным признакам, нужен набор фильтров. Основные:

| Фильтр | Что ищет |
|---|---|
| `net:` | диапазон CIDR |
| `org:` | организация |
| `port:` | порт |
| `product:` | продукт (nginx, MongoDB) |
| `version:` | версия продукта |
| `http.title:` | заголовок страницы |
| `ssl.cert.subject.cn:` | имя в сертификате |
| `http.favicon.hash:` | хэш иконки |
| `vuln:` | известная уязвимость |

Логика запроса: `-` — исключение, `OR` — альтернатива, кавычки — точная фраза, скобки — приоритет. Например, `(http.title:"Grafana" OR http.title:"Kibana") country:DE`.

## Шаг 3: классические дорки

**Дорк** — это готовый запрос под типовую цель. Самые полезные:

```
port:27017 -authentication   # MongoDB без авторизации
port:6379 -authentication    # Redis без пароля
port:9200 http.title:"Kibana"
http.title:"Grafana"
http.title:"Jenkins"
http.title:"Index of /"
has_screenshot:true port:554
```

Фильтр `http.favicon.hash:` особенно ценен: одинаковая иконка означает одинаковую технологию, даже если заголовки подделаны. А `-authentication` — знак исключения: он оставляет только базы, у которых в баннере **нет** слова про аутентификацию, то есть открытые.

## Шаг 4: подключаем другие движки

У Shodan не полное покрытие. **Censys** сильнее в TLS и точных полях, **FOFA** — в азиатском сегменте и IoT, **ZoomEye** — в устройствах. Если в Shodan пусто, ищем в них:

```bash
curl -s https://search.censys.io/api/v2/hosts/search \
  -u "$CENSYS_ID:$CENSYS_SECRET" \
  --data-urlencode 'q=services.http.response.html_title: "Jenkins"' \
  -d per_page=50 | jq '.result.hits[].ip'
```

```
203.0.113.22
198.51.100.40
```

FOFA использует свои операторы `title=`, `cert=`, `icon_hash=`. Смысл один: один движок пропускает то, что видит другой.

## Шаг 5: читаем баннер, а не только IP

Найти IP мало — надо понять, что за сервис. Смотрим полный баннер хоста:

```bash
shodan host 203.0.113.15 | sed -n '1,20p'
```

```
203.0.113.15
Hostnames: ssh.acme.example
Ports: 22, 80
  22/tcp OpenSSH 7.4
  80/tcp nginx 1.18.0 (title: "Acme Intranet")
```

Поля баннера рассказывают историю: `hostnames` — обратные имена, `http.components` — технологии, `ssl.cert.expired` — просрочку сертификата. Умение читать эти поля отличает «нашёл IP» от «понял, что там за сервис». Здесь мы видим внутренний портал `Acme Intranet` на старом nginx.

## Шаг 6: конвейер анализа

Одиночные запросы не масштабируются. Строим конвейер:

1. **Собрать** — запрос по `org:` или `net:`.
2. **Нормализовать** — привести к таблице `IP, порт, продукт, версия`.
3. **Обогатить** — сопоставить версии с известными CVE.
4. **Верифицировать** — проверить критичное вручную, не доверяя кэшу.
5. **Отчёт** — список с пометкой, что подтверждено.

```bash
shodan search --fields ip_str,port --limit 1000 'org:"Acme"' \
  | awk '{print $1":"$2}' | sort -u > acme_ports.txt
cut -d: -f1 acme_ports.txt | sort -u | httpx -silent -title -tech-detect
```

Так пассивные данные Shodan превращаются в карту поверхности до единого пакета на цель.

## Шпаргалка по синтаксису

| Задача | Запрос |
|---|---|
| активы организации | `org:"Acme"` |
| диапазон | `net:203.0.113.0/24` |
| продукт и версия | `product:nginx version:1.18` |
| по TLS-имени | `ssl.cert.subject.cn:example.com` |
| по favicon | `http.favicon.hash:-305179312` |
| по уязвимости | `vuln:CVE-2021-44228` |
| только со скриншотом | `has_screenshot:true` |
| исключить | `... -http.title:"404"` |

## Этика, закон и границы

Shodan показывает только **публично доступное**, но это не значит, что всё можно трогать:

- Просмотр баннера в кэше — пассивно и безопасно.
- **Подключение** к найденному сервису (особенно к базе или панели) — уже активное действие и может быть нарушением.
- Не выгружайте и не публикуйте персональные данные из открытых баз.
- В bug bounty сверяйтесь с правилами: часть активов вне scope, даже если они «ваши» по баннеру.
- Фиксируйте время запроса: кэш быстро устаревает, и через неделю находка может не воспроизводиться.

## Что мы теперь знаем

- Shodan индексирует баннеры, а не сайты: запрос — это фильтр по полям баннера.
- Пробел в запросе означает «И», `-` — исключение, `OR` — альтернатива.
- Дорки по `http.title:`, `product:` и `favicon.hash:` находят панели и открытые сервисы.
- Censys, FOFA и ZoomEye дополняют покрытие Shodan.
- Найденное нужно верифицировать вручную: кэш устаревает.

## На что смотреть дальше

Разберись с фильтром `vuln:` и сопоставлением версий с CVE — помни, что баннер может врать. Изучи Shodan Monitor/Alert для мониторинга диапазона и Screenshots для визуального опознания панелей. Отдельно отработай этику: просмотр кэша пассивен, а подключение к найденному сервису — уже активное действие.

## Куда дальше

Мы освоили дорки и конвейер Shodan. В следующем уроке — **Censys, FOFA и ZoomEye**: сравним их синтаксис и покрытие и научимся комбинировать движки, чтобы не терять хосты. А пока главное запомни: Shodan — это фильтр по кэшу, а не живой сканер.

## Где пригодится

- **Bug bounty:** быстрый поиск активов организации, включая неочевидные порты.
- **Attack surface management:** инвентаризация внешних сервисов.
- **CTF (OSINT):** найти «спрятанный» сервис по подсказке.
- **Пентест:** приоритизация целей до активного сканирования.
