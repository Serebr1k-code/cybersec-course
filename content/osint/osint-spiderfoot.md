SpiderFoot — один из самых известных фреймворков автоматизированной OSINT-разведки. Он запускает десятки модулей против цели (домен, IP, имя, email, телефон, ASN) и строит граф связей: поддомены, сертификаты, утечки, соцсети, уязвимости. Вместо десятка ручных запросов вы получаете единый отчёт — идеально для этапа recon.

## Что такое SpiderFoot

SpiderFoot — это «оркестратор» OSINT: каждый **модуль** опрашивает один источник (Shodan, HaveIBeenPwned, crt.sh, VirusTotal, DNS, WHOIS, pastebin и т.д.) и производит **события** определённых типов (IP, домен, email, сертификат). Модули могут быть **активными** (сканирование портов) или **пассивными** (публичные API). Результаты связываются в граф, что позволяет увидеть неочевидные связи.

## Установка и запуск

```bash
# Docker (проще всего)
docker run -d -p 5001:5001 --name spiderfoot \
  -v $(pwd)/sf:/var/lib/spiderfoot spiderfoot/spiderfoot

# Или из исходников
git clone https://github.com/smicallef/spiderfoot
cd spiderfoot && pip install -r requirements.txt
python3 ./sf.py -l 127.0.0.1:5001     # веб-интерфейс
```

Веб-интерфейс на `http://127.0.0.1:5001` позволяет выбрать цель, модули и запустить скан.

## Модули и типы данных

Модули делятся по назначению: DNS, сертификаты, threat intel, соцсети, утечки, dark web, сканирование. Ключевые примеры: `sfp_crt`, `sfp_dnsresolve`, `sfp_shodan`, `sfp_haveibeenpwned`, `sfp_github`, `sfp_virustotal`, `sfp_spider`, `sfp_portscan_tcp`. Многие требуют API-ключи (Shodan, VirusTotal, HIBP) — их задают в настройках или через `-s`/config.

Типы событий (data types): `DOMAIN_NAME`, `IP_ADDRESS`, `INTERNET_NAME`, `EMAILADDR`, `NETBLOCK`, `CERTIFICATE_ISSUER`, `PASSWORD_COMPROMISED`, `VULNERABILITY_CVE_*` и др. Именно по ним строится граф.

## CLI и веб-интерфейс

```bash
# Список модулей
python3 sf.py -M
# Скан домена всеми пассивными модулями, вывод в CSV
python3 sf.py -s example.com -t DOMAIN_NAME -o csv -q
# Только определённые модули
python3 sf.py -s example.com -m sfp_crt,sfp_dnsresolve,sfp_whois -o json
# Веб-сервер
python3 sf.py -l 0.0.0.0:5001
```

Полезные флаги: `-s` цель, `-t` тип цели, `-m` модули, `-o` формат вывода (csv/json), `-q` тихий режим, `-r` рекурсивное сканирование связанных сущностей.

## Разобранный пример: скан домена

1. Запускаем пассивный скан:
   ```bash
   python3 sf.py -s target.com -t DOMAIN_NAME -o csv -q > scan.csv
   ```
2. Смотрим уникальные поддомены и IP:
   ```bash
   cut -d, -f3,4 scan.csv | grep -i "internet_name\|ip_address" | sort -u | head -40
   ```
3. Ищем утечки email:
   ```bash
   grep -i "email" scan.csv | head
   ```
4. Через веб-интерфейс открываем граф и смотрим, какие IP/домены связаны с целью.
5. Для углубления добавляем активные модули (`sfp_portscan_tcp`) — осторожно, это уже активное сканирование.
6. Экспортируем отчёт (CSV/JSON/HTML) для дальнейшего анализа.

## API и интеграция

SpiderFoot имеет REST API (в веб-режиме) для запуска сканов и получения результатов, что позволяет встроить его в пайплайн. Также есть **SpiderFoot HX** — коммерческая SaaS-версия с расширенными источниками. Для массовых задач запускайте несколько экземпляров (разные цели) или используйте `-r` для рекурсии по связям.

## Производительность и настройка

- **API-ключи** критичны: без них модули Shodan/HIBP/VirusTotal отключаются.
- **Rate limits** источников: слишком агрессивный скан получит бан.
- **Рекурсия `-r`** может «раздуть» скан на тысячи сущностей — контролируйте.
- **Ресурсы**: десятки модулей = заметная нагрузка; для больших целей — параллельные инстансы.
- **Конфиг** (`spiderfoot.cfg` / БД SQLite) хранит ключи и настройки.

## Подводные камни

- **Отсутствие ключей.** Половина модулей молча не работает — всегда проверяйте лог.
- **Активные модули против чужого периметра.** `portscan` — это уже атака; убедитесь в авторизации.
- **Ложные связи.** Общий IP/CDN может связать чужие домены.
- **Устаревшие модули.** Часть источников меняет API — обновляйте SpiderFoot.
- **Шум в отчёте.** Тысячи событий без приоритизации; фильтруйте по типам.
- **Юридические ограничения.** Пассивный сбор обычно ок; активный — только в рамках scope.

## Что дальше / решение

SpiderFoot — «широкий охват»; свяжите с `osint-maltego` (граф и трансформации), `osint-recon-ng` (модульный recon) и `osint-collection`. Дальше — ручная верификация находок (`osint-verification`). Для CTF/пентеста запустите SpiderFoot на домене и разберите граф.

## Сравнение с другими фреймворками

| Инструмент | Сильная сторона | Слабость |
|---|---|---|
| SpiderFoot | Много модулей, граф, веб-UI | Требует ключей, шумный |
| Maltego | Визуальный граф, трансформы | Много ручной работы, лицензии |
| recon-ng | Модульность, скрипты | CLI-only, устаревшие модули |
| theHarvester | Быстрый сбор email/доменов | Узкий охват |
| Amass | Глубокий DNS/поддомены | Только DNS/инфра |
| SpiderFoot HX | SaaS, расширенные данные | Платно |

SpiderFoot хорош как «первый широкий проход»; затем находки уточняются профильными инструментами (Amass для DNS, theHarvester для email, Maltego для графа).

## Написание собственного модуля

SpiderFoot расширяем: модуль — это Python-класс, наследующий `SpiderFootPlugin`, с методами `setup()`, `watchlist()`, `handleEvent()` и `producedEvents()`. Простейший модуль, который по домену запрашивает API и порождает IP-события:

```python
from spiderfoot import SpiderFootPlugin, SpiderFootEvent

class sfp_mymodule(SpiderFootPlugin):
    meta = {"name": "My Source", "summary": "Custom OSINT source"}
    opts = {"api_key": ""}
    def setup(self, sfc, userOpts=None):
        self.sf = sfc
    def watchedEvents(self):
        return ["DOMAIN_NAME"]
    def handleEvent(self, event):
        # ... запрос к API ...
        evt = SpiderFootEvent("IP_ADDRESS", "1.2.3.4", self.__name__, event)
        self.notifyListeners(evt)
```

Свой модуль позволяет добавить нишевый источник (локальный реестр, форум) в общий пайплайн.

## Лаборатория: скан и разбор

1. Запустите SpiderFoot в Docker и откройте веб-UI.
2. Добавьте цель (домен), выберите пассивные модули, запустите.
3. Дождитесь завершения, экспортируйте CSV/JSON.
4. Отфильтруйте события по типам: поддомены, IP, email, сертификаты.
5. Постройте граф и найдите кластеры (общие IP/сертификаты).
6. Повторите с активными модулями в авторизованной лабе (например, свой домен).
7. Сравните охват с ручным `amass`/`theHarvester` — оцените, что даёт автоматизация.

## Отчёты и визуализация

SpiderFoot умеет отдавать результат в CSV/JSON/HTML и строить интерактивный граф в веб-UI. На графе узлы — сущности, рёбра — связи («домен резолвится в IP», «email в утечке»). Это позволяет быстро находить «хабы»: общий IP у нескольких доменов, один сертификат на десятки поддоменов, повторяющийся email. Для больших сканов экспортируйте JSON и обрабатывайте внешним скриптом (networkx/pandas), выделяя кластеры. HTML-отчёт удобен для сдачи заказчику как приложение к recon-разделу.

## Кейс: от скана к находке

Реальный сценарий: пассивный скан домена выдаёт поддомен `staging.target.com` с устаревшим сертификатом. Дальше:

1. Поддомен резолвится в IP, который также обслуживает `old.target.com`.
2. Модуль утечек показывает email инженера в базе 2016 года.
3. Wayback хранит страницу `/admin` на staging с формой логина.
4. Через `osint-cert-transparency` находим ещё поддомены по тому же сертификату.

Так автоматический скан становится картой для ручного углубления. Ключ — не «получить отчёт», а **пройти по связям**: каждая сущность — новый вопрос.
