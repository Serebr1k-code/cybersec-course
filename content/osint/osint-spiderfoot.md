## Вопрос, с которого всё начинается

Ты собрал инструменты разведки и хочешь прогнать их по домену цели — но запускать по одному долго, а сводить результаты вручную ещё дольше. Есть ли инструмент, который сам опросит десятки источников и построит карту связей?

Да — **SpiderFoot**. Разберём его на одном скане от установки до разбора графа.

## Наш пример: скан домена target.com

Введём термины. SpiderFoot — это «оркестратор» OSINT: каждый его **модуль** опрашивает один источник (Shodan, HaveIBeenPwned, crt.sh, VirusTotal, DNS, WHOIS) и производит **события** определённых типов (IP, домен, email, сертификат). Результаты связываются в граф, что позволяет увидеть неочевидные связи.

## Шаг 1: устанавливаем и запускаем

Проще всего через Docker:

```bash
docker run -d -p 5001:5001 --name spiderfoot \
  -v $(pwd)/sf:/var/lib/spiderfoot spiderfoot/spiderfoot
```

Или из исходников:

```bash
git clone https://github.com/smicallef/spiderfoot
cd spiderfoot && pip install -r requirements.txt
python3 ./sf.py -l 127.0.0.1:5001
```

Веб-интерфейс на `http://127.0.0.1:5001` позволяет выбрать цель, модули и запустить скан.

## Шаг 2: разбираемся с модулями

Модули делятся по назначению: DNS, сертификаты, threat intel, соцсети, утечки, сканирование. Ключевые: `sfp_crt`, `sfp_dnsresolve`, `sfp_shodan`, `sfp_haveibeenpwned`, `sfp_github`, `sfp_virustotal`, `sfp_portscan_tcp`.

Модули бывают **пассивными** (публичные API) и **активными** (сканирование портов). Многие требуют API-ключей (Shodan, VirusTotal, HIBP) — их задают в настройках. Без ключей соответствующие модули **молча отключаются**, поэтому всегда проверяй лог.

## Шаг 3: понимаем типы событий

Каждый модуль порождает события типизированных данных:

| Тип события | Пример |
|---|---|
| `INTERNET_NAME` | поддомен |
| `IP_ADDRESS` | IP |
| `EMAILADDR` | email |
| `PASSWORD_COMPROMISED` | утечка |
| `VULNERABILITY_CVE_*` | CVE |

Именно по этим типам строится граф.

## Шаг 4: запускаем скан

Список модулей:

```bash
python3 sf.py -M
```

Пассивный скан домена с выводом в CSV:

```bash
python3 sf.py -s target.com -t DOMAIN_NAME -o csv -q > scan.csv
```

Только определённые модули:

```bash
python3 sf.py -s target.com -m sfp_crt,sfp_dnsresolve,sfp_whois -o json
```

Полезные флаги: `-s` цель, `-t` тип цели, `-m` модули, `-o` формат вывода, `-q` тихий режим, `-r` рекурсия по связанным сущностям.

## Шаг 5: разбираем результат

Смотрим уникальные поддомены и IP:

```bash
cut -d, -f3,4 scan.csv | grep -i "internet_name\|ip_address" | sort -u | head -40
```

Вывод (фрагмент):

```
INTERNET_NAME,staging.target.com
INTERNET_NAME,old.target.com
IP_ADDRESS,203.0.113.42
```

Ищем утечки email:

```bash
grep -i "email" scan.csv | head
```

## Шаг 6: читаем граф

Через веб-интерфейс открываем граф: узлы — сущности, рёбра — связи («домен резолвится в IP», «email в утечке»). Ищем **хабы**:

- общий IP у нескольких доменов;
- один сертификат на десятки поддоменов;
- повторяющийся email.

Для больших сканов экспортируй JSON и обрабатывай внешним скриптом (`networkx`/`pandas`), выделяя кластеры.

## Шаг 7: углубляемся по связям

Автоматический скан — не финал, а карта для ручного углубления. Пример:

1. Поддомен `staging.target.com` резолвится в IP, который также обслуживает `old.target.com`.
2. Модуль утечек показывает email инженера в базе 2016 года.
3. Wayback хранит страницу `/admin` на staging с формой логина.
4. Через CT-логи находим ещё поддомены по тому же сертификату.

Ключ — не «получить отчёт», а **пройти по связям**: каждая сущность — новый вопрос.

## Шаг 8: настраиваем производительность

- **API-ключи** критичны: без них Shodan/HIBP/VirusTotal отключаются.
- **Rate limits** источников: агрессивный скан получит бан.
- **Рекурсия `-r`** может раздуть скан на тысячи сущностей — контролируй.
- **Ресурсы**: десятки модулей = заметная нагрузка.
- **Конфиг** (`spiderfoot.cfg` и БД SQLite) хранит ключи и настройки.

## Шаг 9: пишем свой модуль

SpiderFoot расширяем: модуль — Python-класс, наследующий `SpiderFootPlugin`, с методами `setup()`, `watchedEvents()`, `handleEvent()`:

```python
from spiderfoot import SpiderFootPlugin, SpiderFootEvent

class sfp_mymodule(SpiderFootPlugin):
    meta = {"name": "My Source", "summary": "Custom OSINT source"}
    def watchedEvents(self):
        return ["DOMAIN_NAME"]
    def handleEvent(self, event):
        # ... запрос к API ...
        evt = SpiderFootEvent("IP_ADDRESS", "1.2.3.4", self.__name__, event)
        self.notifyListeners(evt)
```

Свой модуль позволяет добавить нишевый источник в общий пайплайн.

## Шаг 10: сравниваем с другими фреймворками

| Инструмент | Сильная сторона | Слабость |
|---|---|---|
| SpiderFoot | много модулей, граф, веб-UI | требует ключей, шумный |
| Maltego | визуальный граф, трансформы | ручная работа, лицензии |
| recon-ng | модульность, скрипты | CLI-only, часть модулей устарела |
| theHarvester | быстрый сбор email и доменов | узкий охват |
| Amass | глубокий DNS и поддомены | только DNS и инфра |

SpiderFoot хорош как «первый широкий проход»; затем находки уточняются профильными инструментами.

## Шаг 11: лаборатория

1. Запусти SpiderFoot в Docker и открой веб-UI.
2. Добавь цель-домен, выбери пассивные модули, запусти скан.
3. Дождись завершения, экспортируй CSV/JSON.
4. Отфильтруй события по типам: поддомены, IP, email, сертификаты.
5. Построй граф и найди кластеры (общие IP, сертификаты).
6. Сравни охват с ручным `amass` — оцени, что даёт автоматизация.

## Что мы теперь знаем

- SpiderFoot — оркестратор: модули опрашивают источники и порождают события.
- Без API-ключей часть модулей молча не работает.
- События типизированы (`INTERNET_NAME`, `IP_ADDRESS`, `EMAILADDR`).
- Результат — граф связей, где ищут «хабы».
- Автоматический скан — карта для ручного углубления, а не финал.

## Частые ошибки

- **Отсутствие ключей.** Половина модулей не работает — проверяй лог.
- **Активные модули против чужого периметра.** `portscan` — это уже атака.
- **Ложные связи.** Общий IP или CDN может связать чужие домены.
- **Шум в отчёте.** Тысячи событий без приоритизации; фильтруй по типам.
- **Юридические ограничения.** Активный сбор — только в рамках scope.

## На что смотреть дальше

SpiderFoot даёт «широкий охват», но находки нужно уточнять профильными инструментами: Amass для DNS, theHarvester для email, Maltego для графа. Дальше разберём **Maltego** — визуальный граф и трансформы. А пока главное запомни: SpiderFoot открывает карту, но осмысление — за тобой.

## Куда дальше

Мы разобрали SpiderFoot от установки до разбора графа. В следующем уроке — **Maltego**: визуальный инструмент с трансформами, идеальный для презентации связей. А пока главное запомни: автоматический скан — это карта, а не приговор.

## Где пригодится

- **Recon и пентест:** быстрый широкий охват цели.
- **Bug bounty:** автоматический сбор поддоменов и утечек.
- **OSINT:** построение графа связей.
- **CTF:** автоматизация поиска артефактов.
