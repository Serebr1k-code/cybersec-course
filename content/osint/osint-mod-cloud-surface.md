## Вопрос, с которого всё начинается

Организация переехала в облако. Снаружи остались «двери»: панель Kubernetes, API-документация, бакет с состоянием Terraform, метаданные SSO. Каждая из них по-своему рассказывает, как устроена инфраструктура — а иногда и отдаёт секреты.

Этот модуль — про облачно-нативную поверхность: то, что появилось поверх обычного сайта и почти всегда настроено «чтобы работало».

## Почему это ценно

Ошибки конфигурации облака — самый частый источник критичных утечек: открытый kubelet, публичный API без авторизации, state-файл с паролями, метаданные IdP с именами сертификатов. Для разведки это прямой путь к инфраструктуре.

## Что внутри модуля

1. **Kubernetes** — открытые дашборды, API и kubelet.
2. **API discovery** — Swagger/OpenAPI, GraphQL, поиск эндпоинтов.
3. **IaC / Terraform state** — где лежит состояние и почему оно опасно.
4. **IdP / SSO** — метаданные SAML, well-known, discovery.

## Наш сквозной пример

Поддомены и пути домена `example.com`: `k8s.example.com`, `/api-docs`, `example-tfstate.s3.amazonaws.com`, `/.well-known/saml-configuration`.

## Границы и этика

Мы фиксируем факт открытости и читаем метаданные. Не эксплуатируем найденное, не выкачиваем секреты дальше подтверждения. Найденный ключ — это красная строка для отчёта, а не для использования.

## Что мы теперь знаем

1. Облачно-нативные сервисы оставляют публичные «двери».
2. Их ошибки конфигурации — источник утечек.
3. State-файлы и метаданные часто содержат секреты.
4. Разведка фиксирует открытость, не эксплуатируя её.

## Куда дальше

Начни с Kubernetes: там мы по поддомену найдём открытую панель и прочитаем её метаданные. А пока запомни: облачная поверхность — это «двери», оставленные по недосмотру.

## Где пригодится

- **Пентест:** облачно-нативная атакуемая поверхность.
- **Bug bounty:** открытые k8s/API/бакеты в scope.
- **CTF (OSINT):** секреты в state и метаданных.
- **Blue team:** аудит публичной экспозиции облака.
