## Вопрос, с которого всё начинается

Тебе дали название компании — `Example LLC` — и просят понять, кому она на самом деле принадлежит. Новичок гуглит название и читает раздел «О нас» на сайте. Это ошибка: сайт — это маркетинг, а не факт.

**Бизнес-реестр** — это государственный или международный список зарегистрированных компаний. Там лежат объективные данные: кто директор, кто владелец, какой адрес. Разберём это на одной компании и увидим, как от названия дойти до реального бенефициара.

## Наш пример: компания Example LLC

У нас один объект — `Example LLC`, предположительно зарегистрированная в Великобритании. Введём два термина.

**Юрисдикция** — страна, чей реестр ведёт компанию (от неё зависят доступные данные). **Бенефициар** — реальный владелец, тот, кто получает выгоду, даже если формально компания записана на другого.

Работать будем через **Companies House** — британский реестр с бесплатным API.

## Шаг 1: находим компанию по названию

Первый шаг — получить уникальный номер компании. Названия повторяются, а номер — нет. **API** (application programming interface) — это программный доступ к сервису через HTTP-запросы.

```bash
curl -s "https://api.company-information.service.gov.uk/search/companies?q=Example" -u "$CH_KEY:" \
  | jq -r '.items[] | "\(.company_number) \(.title) [\(.company_status)]"'
```

```
09876543 Example LLC [active]
11223344 Example Solutions Ltd [dissolved]
```

У нас есть номер `09876543`. Обрати внимание: рядом компания-тёзка со статусом `dissolved` (ликвидирована). Именно поэтому дальше мы работаем **только по номеру**, а не по названию.

## Шаг 2: читаем профиль компании

Профиль отвечает на базовые вопросы: дата создания, статус, юридический адрес.

```bash
curl -s "https://api.company-information.service.gov.uk/company/09876543" -u "$CH_KEY:" \
  | jq '{name, status, date_of_creation, registered_office_address}'
```

```
{
  "name": "EXAMPLE LLC",
  "status": "active",
  "date_of_creation": "2019-03-14",
  "registered_office_address": {
    "address_line_1": "27 Old Gloucester Street",
    "locality": "London",
    "postal_code": "WC1N 3AX"
  }
}
```

Запомним адрес `27 Old Gloucester Street` — он нам ещё понадобится.

## Шаг 3: кто директора

**Директор** — человек, официально управляющий компанией. Смотрим список офицеров:

```bash
curl -s "https://api.company-information.service.gov.uk/company/09876543/officers" -u "$CH_KEY:" \
  | jq -r '.items[] | "\(.name) — \(.officer_role)"'
```

```
Ivan Petrov — director
Example Holdings Ltd — director
```

Интересно: один из директоров — не человек, а другая компания. Значит, структура многоуровневая, и надо смотреть владельцев.

## Шаг 4: реальные владельцы (PSC)

В британском реестре есть отдельный реестр **PSC** (persons with significant control) — «лица со значительным контролем». Это попытка государства раскрыть реальных бенефициаров.

```bash
curl -s "https://api.company-information.service.gov.uk/company/09876543/persons-with-significant-control" -u "$CH_KEY:" \
  | jq '.items[] | {name, natures_of_control}'
```

```
{
  "name": "Example Holdings Ltd",
  "natures_of_control": ["ownership-of-shares-75-to-100-percent"]
}
```

Полный контроль у холдинга `Example Holdings Ltd`. Теперь надо повторить шаги 2–4 уже для холдинга — и так до конца цепочки. Это **обход структуры владения**.

## Шаг 5: идём по цепочке владения

Обход удобно автоматизировать: берём номер, достаём PSC и офицеров, а если владелец — компания, идём глубже. Обязательно ограничиваем глубину, иначе цикл (A владеет B, B владеет A) зациклит программу.

```python
import os, requests
CH = (os.environ["CH_KEY"], "")

def psc(num):
    r = requests.get(f"https://api.company-information.service.gov.uk/company/{num}/persons-with-significant-control", auth=CH, timeout=20)
    return [i.get("name") for i in r.json().get("items", [])]

def walk(num, depth=0, seen=None):
    seen = seen or set()
    if num in seen or depth > 3:
        return
    seen.add(num)
    for name in psc(num):
        print("  " * depth + "-", name)
```

Правила гигиены: ключ хранить только в переменных окружения (не хардкодить), соблюдать лимит (у Companies House — 600 запросов за 5 минут), кэшировать ответы, чтобы не дёргать API повторно.

## Шаг 6: адрес выдаёт «сестринские» компании

Вернёмся к адресу `27 Old Gloucester Street`. Это известный адрес массовой регистрации: на нём зарегистрированы тысячи компаний. Проверим:

```bash
curl -s "https://api.company-information.service.gov.uk/search/companies?q=27+Old+Gloucester+Street" -u "$CH_KEY:" \
  | jq '.total_results'
```

```
15482
```

Пятнадцать тысяч компаний на одном адресе. Это **красный флаг**: реальный бизнес там не сидит — это либо сервис «регистрация под ключ», либо номинальная структура. Наш вывод меняется: `Example LLC` может быть «прокладкой».

## Шаг 7: проверяем офшоры и санкции

Структура владения часто уходит в офшоры. База **ICIJ Offshore Leaks** (Panama/Paradise/Pandora Papers) ищет по имени директора:

```
https://offshoreleaks.icij.org/search?q=Ivan+Petrov
```

Параллельно обязательный шаг due diligence — **санкционный скрининг** через **OpenSanctions**:

```bash
curl -s "https://api.opensanctions.org/search/default?q=Petrov" \
  -H "Authorization: ApiKey $OS_KEY" | jq '.results[] | {caption, schema, datasets}'
```

```
{"caption": "Ivan Petrov", "schema": "Person", "datasets": ["us_ofac_sdn"]}
```

Важно: совпадение имени — **не доказательство**. Тёзок много. Сверяйте дату рождения, гражданство и идентификаторы, а степень уверенности фиксируйте отдельно.

## Если в одном реестре пусто

Бывает, что в британском реестре цепочка обрывается на холдинге из другой страны. Тогда расширяем источники:

- **OpenCorporates** агрегирует 200+ юрисдикций и связывает компании в разных странах.
- **Национальные реестры** (Германия, Франция, Кипр) часто доступны только через локальные порталы.
- **GLEIF** отдаёт **LEI** — уникальный идентификатор юрлица, по которому компания находится в разных реестрах.
- **SEC/EDGAR** покрывает публичные компании США.

Практика: соберите минимум три независимых источника на каждую ключевую связь — тогда вывод устойчив к ошибке одного реестра.

## Что мы теперь знаем

- Компанию идентифицируют по **номеру регистрации**, а не по названию.
- Профиль даёт дату, статус и адрес; офицеры — директоров; PSC — реальных владельцев.
- Владение обходится рекурсивно, но с ограничением глубины от циклов.
- Массовый адрес регистрации — сильный красный флаг.
- Офшоры проверяются в ICIJ, санкции — в OpenSanctions, но совпадение имени требует подтверждения.

## На что смотреть дальше

Разберись с **LEI** (Legal Entity Identifier) в GLEIF — он связывает одно юрлицо в разных реестрах, что критично для трансграничных цепочек. Изучи визуализацию графа владения (Gephi, Neo4j): на схеме сразу видны циклы и кластеры общих директоров. Для пентеста это превращается в карту доменов и брендов группы.

## Разбор кейса: цепочка владения и «прокладки»

Ты нашёл компанию Example LLC. В реестре указан директор — но за ним стоит цепочка юрлиц. Разберём, как её читать.

Первый уровень — **директора (officers)**. Это люди, которые подписывают документы. Их имена — точка входа: тот же человек может быть директором ещё в десятке компаний, и реестр покажет их все. Второй уровень — **владельцы (PSC, persons with significant control)**. Это те, кто реально контролирует компанию, даже если не директор. В UK PSC-реестр обязателен, и он часто раскрывает конечного бенефициара. Третий уровень — **цепочка через холдинги**. Компания A владеет компанией B, та — компанией C. Каждое звено может быть зарегистрировано в другой юрисдикции (Кипр, BVI, Делавэр). Реестры не связаны между собой, поэтому цепочку собирают вручную: по названию холдинга ищут его регистрацию в другой стране.

## Разбор кейса: красные флаги на практике

Проверка идёт сверху вниз. Сначала находишь компанию по названию в OpenCorporates — он агрегирует десятки реестров. Затем открываешь первоисточник (Companies House, ЕГРЮЛ) — там данные свежее. Смотришь адрес: если по нему зарегистрированы сотни фирм, это номинальный адрес. Смотришь директора: если он «профессиональный» (директор в 200 компаниях), это фиктивный руководитель. Смотришь санкционные списки: OpenSanctions и OCCRP покажут совпадения. Вывод формулируется осторожно: «структура владения непрозрачна, конечный бенефициар не установлен». Это честнее, чем назвать конкретного человека владельцем на основании одного совпадения.

## Частые вопросы

**Всегда ли доступен PSC?** Нет, только там, где реестр это требует (например, UK). В офшорах владельцы могут не раскрываться.

**Что такое OCCRP?** Это журналистская сеть и база расследований по коррупции и офшорам. Полезный источник связей, но не официальный реестр.

**Как связать юрлицо с доменом?** По WHOIS, сертификату, адресу и упоминаниям в документах. Иногда название холдинга совпадает с названием домена — это подсказка, но не факт.

## Мини-практика: ищем массовый адрес

Возьми адрес регистрации найденной компании и проверь, сколько ещё фирм зарегистрировано по нему. В OpenCorporates вбей адрес в поиск — сервис покажет связанные компании. В UK аналог — Companies House: там есть поиск по адресу. Если по одному адресу зарегистрированы десятки или сотни фирм, это почти наверняка номинальный адрес (юридический сервис), а не реальный офис. Такой вывод меняет всю картину: «офис в центре Лондона» может оказаться просто ящиком в сервисе регистрации. Второй шаг — проверить, кто ещё из директоров связан с этими фирмами: один и тот же человек в 50 компаниях — признак массовой регистрации. Этот прогон учит не принимать реквизиты за реальность, а проверять их на «массовость».

## Как формулировать вывод

Реестры дают факты, но вывод всегда вероятностный. Пиши так: «Директор — И. Петров; он же директор ещё в 40 компаниях по тому же адресу; конечный бенефициар не установлен». Не утверждай владение без прямого подтверждения в PSC или документе. Разделяй три уровня: подтверждено реестром, вероятно по косвенным данным, возможно по совпадению имени. Заказчику нужна именно такая градация, иначе он примет догадку за факт и ошибётся в решении.

## Куда дальше

Мы распутали структуру владения одной компании. В следующем уроке — **DNS-разведка**: возьмём домен той же организации и соберём поддомены, записи и инфраструктуру пассивно и активно. А пока главное запомни: реестр — это первичный источник факта, а сайт компании — маркетинг.

## Где пригодится

- **CTF (OSINT):** распутать структуру компании из подсказок.
- **Due diligence:** проверка контрагента и владельцев.
- **Расследования:** выявление офшоров и номинальных структур.
- **Пентест:** карта организации и её подрядчиков для анализа scope.
