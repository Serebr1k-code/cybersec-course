Компания — это тоже «человек» со своими связями: директора, акционеры, дочерние структуры, адреса. Бизнес-реестры позволяют распутать структуру владения, найти общие адреса и людей, выявить офшоры. Для пентеста это карта поверхности организации и её подрядчиков; для расследований — доказательная база. В этом уроке — практические источники, работа с API, разобранные примеры и методика оценки красных флагов.

## Теория: что дают бизнес-реестры

- **Юрлицо:** название, номер, статус, дата регистрации, юрисдикция.
- **Директора и секретари:** люди, принимающие решения.
- **Акционеры/доли:** владельцы (иногда через номиналов).
- **Адрес:** общий офис → связи с другими компаниями.
- **Дочерние/материнские:** иерархия владения.
- **Филинги:** отчётность, изменения, ликвидации.

Красные флаги: массовый адрес, номинальные директора, частая смена владельцев, офшорные цепочки, «пропадающие» компании.

## Ключевые источники и что каждый умеет

- **OpenCorporates** — крупнейший агрегатор (веб-поиск бесплатный, API платный); связывает компании в разных юрисдикциях.
- **OCCRP Aleph** — графовый поиск по документам и реестрам, бесплатный для журналистов.
- **Companies House (UK)** — бесплатный полный доступ к filings и API, включая PSC.
- **SEC/EDGAR (US)** — публичные компании (см. osint-sec-filings).
- **ICIJ Offshore Leaks** — базы Panama/Paradise/Pandora Papers.
- **GLEIF** — идентификаторы юрлиц (LEI) и связи материнских/дочерних.
- **OpenSanctions** — санкционные и PEP-списки.

## Инструменты и команды

```bash
# Companies House API (нужен ключ) — поиск компании
curl -s "https://api.company-information.service.gov.uk/search/companies?q=example" -u "$CH_KEY:"

# PSC — реальные владельцы (UK)
curl -s "https://api.company-information.service.gov.uk/company/00000000/persons-with-significant-control" -u "$CH_KEY:" \
  | jq '.items[] | {name, natures_of_control}'

# OpenCorporates API: поиск компании
curl -s "https://api.opencorporates.com/v0.4/companies/search?q=example&api_token=$OC_KEY" \
  | jq '.results.companies[].company | {name, jurisdiction_code, company_number}'
```

## Разобранный пример: структура владения

Дано: компания `Example LLC`.

Шаг 1 — OpenCorporates: юрисдикция, номер, статус, директора.

Шаг 2 — Companies House (если UK): скачиваем filings, смотрим PSC (persons with significant control) — реальных владельцев.

Шаг 3 — Aleph: вводим название → граф связей с людьми, адресами и документами.

Шаг 4 — общий адрес: ищем все компании по адресу Example LLC → возможные «сестринские» структуры.

Шаг 5 — офшоры: ищем директоров в ICIJ Offshore Leaks.

Шаг 6 — сводим граф владения и помечаем красные флаги (номиналы, массовый адрес).

## Продвинутые приёмы

- **PSC-анализ (UK):** persons with significant control раскрывают реальных бенефициаров, включая трасты.
- **Общий адрес/телефон:** один адрес регистрации у десятков компаний = массовый регистратор/номинал.
- **Смена директоров:** даты изменений коррелируют с событиями (продажа, кризис, санкции).
- **LEI (GLEIF):** уникальный идентификатор связывает юрлица в разных реестрах.
- **API-автоматизация:** OpenCorporates/Companies House API для массового сбора.
- **Кросс-юрисдикция:** цепочки «страна A → B → офшор».
- **Санкции/PEP:** сверка с OpenSanctions/OFAC/EU.

## Работа с API: пошагово

```bash
# 1) поиск компании и получение номера
curl -s "https://api.company-information.service.gov.uk/search/companies?q=example" -u "$CH_KEY:" \
  | jq -r '.items[0] | .company_number'

# 2) профиль компании
curl -s "https://api.company-information.service.gov.uk/company/00000000" -u "$CH_KEY:" \
  | jq '{name, status, date_of_creation, registered_office_address}'

# 3) офицеры (директора)
curl -s "https://api.company-information.service.gov.uk/company/00000000/officers" -u "$CH_KEY:" \
  | jq -r '.items[] | "\(.name) — \(.officer_role)"'

# 4) PSC — реальные владельцы
curl -s "https://api.company-information.service.gov.uk/company/00000000/persons-with-significant-control" -u "$CH_KEY:" \
  | jq '.items[] | {name, natures_of_control}'
```

Вывод (пример):

```text
Ivan Petrov — director
Example Holdings Ltd — director
```

Правила: ключ — только в переменных окружения; пагинация через `start_index`; лимит Companies House — 600 запросов за 5 минут; кэшируйте ответы.

## Распознавание схем и красных флагов

| Признак | Что означает |
|---|---|
| Десятки компаний на одном адресе | массовый регистратор / номинал |
| Один директор в сотнях фирм | «профессиональный» директор |
| Частая смена владельцев | вывод активов, «прокладки» |
| Цепочка «страна → офшор» | сокрытие бенефициара |
| Регистрация и быстрая ликвидация | однодневка |
| Один регистратор/секретарь у множества фирм | общий «куратор» структуры |

Практика: соберите всех директоров компании, затем проверьте каждого в реестре — по количеству связанных фирм вы быстро отделите реальный бизнес от номинальной структуры.

## От структуры владения к поверхности атаки

Для пентеста/red team реестры дают:

1. **Список юрлиц** группы → связанные домены и бренды (расширение scope-анализа).
2. **Директоров и ключевых лиц** → перекрёстный OSINT (LinkedIn, соцсети).
3. **Адреса** → физическая инфраструктура и геоконтекст сотрудников.
4. **Партнёров и соучредителей** → цепочка поставщиков (supply chain).
5. **Смену руководства** → моменты нестабильности (часто = смена провайдеров/систем).

## Правовые и этические аспекты

- Часть реестров платные — не обходите ограничения и не нарушайте ToS.
- Персональные данные директоров обрабатывайте в рамках закона (GDPR/152-ФЗ).
- Санкционный скрининг — законное основание для проверки.
- Для отчёта фиксируйте источник каждой связи (ссылку на filing/запись).

## Частые ошибки

- **Путать тёзок.** Идентифицируйте по номеру регистрации/LEI.
- **Игнорировать номиналов.** Формальный директор может быть «подставным».
- **Верить устаревшим filings.** Данные обновляются с задержкой.
- **Забыть про офшоры.** Структура владения часто уходит в ICIJ-базы.
- **Нет графа.** Без визуализации связи теряются.
- **Хардкодить ключи.** Утечка через репозиторий; используйте env.

## Что дальше / решение

Собрав структуру владения, переходите к атрибуции: сопоставьте юрлица с доменами (WHOIS/CT), директоров — с соцпрофилями, адреса — с картами. Решение по каждой цепочке: «легитимная структура», «номинальная прокладка (повышенный интерес)» или «офшорное сокрытие (эскалировать в расследование)». Для пентеста вынесите список связанных брендов и домены-двойники в отдельную задачу scope-анализа.

## Практика: автоматический обход структуры владения

```python
import os, requests
CH = (os.environ["CH_KEY"], "")

def company(num):
    r = requests.get(f"https://api.company-information.service.gov.uk/company/{num}", auth=CH, timeout=20)
    return r.json() if r.ok else {}

def officers(num):
    r = requests.get(f"https://api.company-information.service.gov.uk/company/{num}/officers", auth=CH, timeout=20)
    return [o["name"] for o in r.json().get("items", [])]

def psc(num):
    r = requests.get(f"https://api.company-information.service.gov.uk/company/{num}/persons-with-significant-control", auth=CH, timeout=20)
    return [i.get("name") for i in r.json().get("items", [])]

def walk(num, depth=0, seen=None):
    seen = seen or set()
    if num in seen or depth > 3:
        return
    seen.add(num)
    c = company(num)
    print("  " * depth, c.get("company_name", num))
    for name in psc(num) + officers(num):
        print("  " * depth + "-", name)
```

Детали: Companies House отдаёт PSC как физлиц и юрлиц; рекурсию ограничивайте глубиной (защита от циклов); лимит — 600 запросов за 5 минут; кэшируйте ответы в SQLite.

## Санкционный скрининг и PEP

Проверка на санкции и статус PEP — обязательный шаг due diligence.

- **OpenSanctions** — агрегатор списков (OFAC, EU, UK, UN) и PEP; есть API и bulk-датасеты.
- **OFAC SDN** — список США; поиск по имени/паспорту/ИНН.
- **EU/UK sanctions** — консолидированные списки.
- **PEP-базы** — публичные должностные лица и их родственники.

```bash
# OpenSanctions API: поиск сущности
curl -s "https://api.opensanctions.org/search/default?q=Petrov" \
  -H "Authorization: ApiKey $OS_KEY" | jq '.results[] | {caption, schema, datasets}'
```

Совпадение имени — не доказательство: сверяйте дату рождения, гражданство, идентификаторы. Ложные срабатывания (тёзки) — норма; фиксируйте степень уверенности.

## Аналитика адресов и «массовых» регистраторов

- **Один адрес — десятки компаний**: типично для сервисов «регистрация под ключ» и номинальных структур.
- **Виртуальный офис**: адрес-коворкинг или юрадрес регистратора — не реальная деятельность.
- **Смена адреса**: переезд часто совпадает с кризисом или сменой владельцев.
- **Сопоставление адресов** компаний разных юрисдикций выявляет общий центр управления.

## Разница между реестром и «данными из интернета»

- Реестр — первичный источник (юридический факт), соцсеть — вторичный (может врать).
- Даты регистрации и filings объективны; «о компании» на сайте — маркетинг.
- Всегда сверяйте номер регистрации, а не название: тёзок много.
- Фиксируйте ссылку на запись в реестре — это доказательство.

## Расширенные источники и практика

- **OCCRP Aleph** принимает не только реестры, но и утёкшие документы — ищите по имени, адресу, номеру.
- **OpenCorporates** полезен для трансграничных цепочек: одна компания в нескольких юрисдикциях.
- **Национальные реестры** (Германия, Франция, Кипр) часто доступны только через локальные порталы.
- **Судовые и авиационные реестры** дополняют картину активов владельца.
- **Архивы веб-страниц** (Wayback) показывают, как менялся состав директоров на сайте компании.

Практика: соберите минимум три независимых источника на каждую ключевую связь — так вывод устойчив к ошибке одного реестра.

## Где пригодится

- **CTF (OSINT):** распутать структуру компании из подсказок.
