Новости и медиа — официальный, цитируемый пласт OSINT. Пресс-релизы раскрывают контракты, партнёров и руководство; локальные СМИ — адреса и происшествия; отраслевые издания — технологии и планы. В отличие от соцсетей, новости редактируются и проверяются, поэтому служат «первичным» источником для фактов. Задача OSINT здесь — **систематический мониторинг** упоминаний цели и извлечение сущностей.

## Теория: почему новости — ценный источник

- **Официальность.** Пресс-релизы публикуют компании сами — это их заявления о себе.
- **Даты и факты.** Назначения, сделки, инциденты фиксируются с датами.
- **Сущности.** Имена руководителей, партнёров, адреса, технологии.
- **Регионы.** Локальные СМИ знают адреса, происшествия, инфраструктуру.
- **Архивность.** Старые статьи доступны и раскрывают историю.

Новости хорошо сочетаются с реестрами (`osint-business-registry`) и SEC-отчётами (`osint-sec-filings`).

## RSS: базовый инструмент мониторинга

Почти каждое медиа отдаёт RSS. Подписка на фид = автоматический поток. Читаем фид:

```bash
curl -s "https://news.example.com/rss" | xmllint --format - | grep -E '<title>|<pubDate>|<link>' | head -20
```

Популярные ридеры: `Feedly`, `Inoreader`, `Miniflux`, `Newsboat` (CLI). Для автоматизации — `feedparser` в Python:

```python
import feedparser, datetime
d = feedparser.parse("https://news.example.com/rss")
for e in d.entries[:10]:
    print(e.published, "-", e.title, "-", e.link)
```

Мониторинг упоминаний: подписываемся на поиск по цели и сохраняем новые записи.

## Google News и поиск новостей

Google News поддерживает RSS-выходы по запросу:

```bash
# RSS по запросу "example.com"
curl -s "https://news.google.com/rss/search?q=example.com&hl=ru&gl=RU&ceid=RU:ru" \
  | xmllint --format - | grep -E '<title>|<pubDate>' | head -20
```

Меняя `q`, отслеживаем: имя компании, бренд, домен, имена руководителей. Также есть Bing News, Yandex.News, новостные агрегаторы.

## GDELT: глобальная база событий

GDELT (Global Database of Events, Language, and Tone) — огромная база новостей мира с API. Позволяет искать упоминания, строить таймлайны, анализировать тональность:

```bash
curl -s "https://api.gdeltproject.org/api/v2/doc/doc?query=example.com&mode=artlist&maxrecords=20&format=json" \
  | python3 -m json.tool | grep -E 'title|url|seendate' | head -30
```

Режимы: `artlist` (список статей), `timelinevol` (объём во времени), `tonechart` (тональность). Это готовый инструмент мониторинга на годы назад.

## Пресс-релизы и корпоративные медиа

Компании публикуют пресс-релизы на своих сайтах в разделах `/newsroom`, `/press`, `/media`. Проверяем:

```bash
for p in /newsroom /press /news /media /press-releases; do
  code=$(curl -s -o /dev/null -w '%{http_code}' "https://example.com$p")
  echo "$p -> $code"
done
```

Сторонние площадки: PRNewswire, BusinessWire, GlobeNewswire. В релизах — контракты, назначения, технологии, иногда контакты для прессы (email, телефон).

## Разобранный пример: мониторинг компании

Дано: `example.com`.

Шаг 1 — Google News RSS по домену:

```bash
curl -s "https://news.google.com/rss/search?q=example.com" | grep -oE '<title>[^<]+' | sed 's/<title>//' | head
# example.com partners with CloudCorp
# Example Inc raises Series B
# New CTO joins Example
```

Шаг 2 — из заголовков извлекаем сущности: партнёр `CloudCorp`, раунд B, новый CTO. Имена руководителей → поиск людей.

Шаг 3 — GDELT-таймлайн упоминаний за 5 лет — видим пики (инциденты, скандалы).

Шаг 4 — раздел `/newsroom` на сайте: находим пресс-контакты (email, телефон).

Итог: партнёры, руководство, события и контакты — всё из медиа.

## Извлечение сущностей

Из новостного текста вытаскиваем: **люди** (NER), **организации**, **места**, **даты**, **суммы**. Инструмент `spaCy`:

```python
import spacy
nlp = spacy.load("ru_core_news_lg")
doc = nlp(open("article.txt").read())
for ent in doc.ents:
    if ent.label_ in ("PER","ORG","LOC","DATE"):
        print(ent.label_, ent.text)
```

Это превращает статьи в структурированные данные для графа.

## Ошибки и подводные камни

- **Верить одному изданию.** Новости ошибаются и перепечатывают друг друга; нужен первичный источник.
- **Игнорировать дату.** Старая статья описывает прошлое состояние, не текущее.
- **Путать бренд и юрлицо.** «Example» может быть несколько компаний.
- **Забывать про язык/регион.** Локальные СМИ на местном языке содержат больше деталей.
- **Считать пресс-релиз объективным.** Это PR — маркетинг, не факт.
- **Не архивировать.** Ссылки «гниют»; сохраняйте в Wayback/archive.today.

## Что дальше / решение

Медиамониторинг даёт сущности и таймлайн. Дальше: **реестры** (`osint-business-registry`) для юридических деталей, **SEC** (`osint-sec-filings`) для финансов, **верификация** (`osint-verification`) для проверки утверждений. Итог: RSS + Google News + GDELT дают поток упоминаний, из которого вы извлекаете людей, организации и события — основу для графа цели.

## Автоматизированный мониторинг: пайплайн на Python

Ручной просмотр не масштабируется. Собираем пайплайн, который раз в полчаса читает список RSS, находит новые записи по ключевым словам и складывает их в SQLite с дедупликацией.

```python
#!/usr/bin/env python3
# news-monitor.py — мониторинг упоминаний по RSS
import feedparser, sqlite3, hashlib

FEEDS = [
    "https://news.google.com/rss/search?q=example.com",
    "https://example.com/newsroom/rss",
    "https://habr.com/ru/rss/all/all/",
]
KEYS = ["example", "пример", "cto", "утечка", "breach"]

db = sqlite3.connect("monitor.db")
db.execute("CREATE TABLE IF NOT EXISTS seen (id TEXT PRIMARY KEY, title TEXT, link TEXT, pub TEXT)")

def uid(link):
    return hashlib.sha256(link.encode()).hexdigest()[:16]

for url in FEEDS:
    d = feedparser.parse(url)
    for e in d.entries:
        text = (e.get("title", "") + " " + e.get("summary", "")).lower()
        if not any(k in text for k in KEYS):
            continue
        i = uid(e.link)
        if db.execute("SELECT 1 FROM seen WHERE id=?", (i,)).fetchone():
            continue
        db.execute("INSERT INTO seen VALUES (?,?,?,?)",
                   (i, e.title, e.link, e.get("published", "")))
        print("NEW:", e.get("published", ""), "-", e.title, "-", e.link)
db.commit()
```

Запуск по cron — каждые 30 минут:

```bash
crontab -e
*/30 * * * * /usr/bin/python3 /opt/osint/news-monitor.py >> /var/log/news.log 2>&1
```

Что даёт пайплайн: дедупликация по хэшу ссылки, фильтр по ключевым словам, история всех упоминаний. По таблице `seen` строится таймлайн упоминаний и видно пики активности вокруг цели.

## Google Alerts и другие каналы

Помимо RSS-фидов, упоминания приходят через:
- **Google Alerts** — email/RSS-уведомления о новых результатах; RSS-выход Alerts удобнее для автоматизации.
- **Yandex.News** — RSS по запросу для рунета.
- **Reddit/HN поиск** — упоминания в сообществах.
- **Telegram-каналы** — новости отрасли (см. `osint-telegram`).

Для сбора email-упоминаний компаний используйте комбинацию Alerts + feedparser из предыдущего раздела.

## Оценка достоверности новости

Не каждое упоминание — факт. Чек-лист:

| Признак | Вывод |
|---------|-------|
| Первоисточник = пресс-релиз компании | факт-заявление компании |
| Перепечатка без источника | низкая достоверность |
| Дата совпадает с событием | актуально |
| Несколько независимых изданий | вероятно, правда |
| Только одно издание + эмоции | требует проверки |

Всегда находите **первоисточник**: пресс-релиз, судебный документ, официальное заявление. Остальное — вторично.

## Архивация и «гниение» ссылок

Новостные ссылки со временем ломаются или меняют содержание. Сохраняйте важное:

```bash
curl -s "https://web.archive.org/save/https://news.example.com/article" | grep -i 'saved'
curl -s "http://archive.today/submit/?url=https://news.example.com/article"
```

Сохраняйте также локально (PDF/HTML), фиксируя дату — это доказательная база для отчёта.

## Анализ тональности и медиа-образа

Медиа-образ цели (позитив/негатив) измеряется тональностью:

```python
# простая тональность через словари
POS = {"успех","рост","партнёрство","инновация","прибыль"}
NEG = {"утечка","скандал","авария","иск","штраф","взлом"}
def tone(text):
    w = text.lower().split()
    return sum(x in POS for x in w) - sum(x in NEG for x in w)
for art in articles:
    print(tone(art), art[:60])
```

GDELT даёт тональность по API (`tonechart`), что позволяет отслеживать репутацию во времени. Негативные пики совпадают с инцидентами — полезно для threat intelligence.

## Сопоставление новостей с реестрами

Новости дают «зацепки», реестры — подтверждения:
- Новость «назначен новый CTO» → реестр/LinkedIn подтверждает.
- Новость «поглощение компании X» → бизнес-реестр показывает смену владельца.
- Новость «контракт с Y» → SEC-отчёт подтверждает.

```bash
# сопоставление имени из новости с бизнес-реестром
curl -s "https://api.opencorporates.com/v0.4/companies/search?q=Ivan+Petrov"
```

Комбинация медиа + реестр = верифицированный факт.

## Региональные и нишевые медиа

Крупные издания дают общую картину, но детали (адреса, происшествия, локальные контракты) — в региональных и отраслевых медиа. Ищите:
- **местные газеты** города, где базируется цель;
- **отраслевые издания** (для технологических компаний — профильные ресурсы);
- **корпоративные блоги** партнёров;
- **госзакупки** и тендерные порталы.

Часто именно локальная заметка раскрывает адрес офиса или имя руководителя филиала.

## Медиа-грамотность аналитика

Ключевой навык — отличать факт от мнения и заявления от доказательства. Читая новость, спрашивайте: кто источник, есть ли первоисточник, кому выгодна эта публикация, есть ли подтверждение из второго независимого издания. OSINT-аналитик относится к новости как к гипотезе, которую нужно проверить, а не как к установленному факту.

## Где пригодится

- **CTF (OSINT):** в новостной статье спрятано имя/ссылка к флагу.
- **Мониторинг:** отслеживать упоминания компании/персоны во времени.
- **Расследования:** собрать факты, руководство и партнёров из прессы.
- **Threat intelligence:** новости об инцидентах и атаках на отрасль.
- **Конкурентная разведка:** планы, контракты, технологии из релизов.
