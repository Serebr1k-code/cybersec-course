Dark web — это не «место, где всё незаконно», а набор сетей (Tor, I2P) со **скрытыми сервисами**. Для OSINT это источник утечек, форумов и данных, которых нет в открытом вебе. Главное здесь — **безопасность и законность**.

## Что такое Tor и .onion

- **Tor** — анонимизирующая сеть; трафик проходит через несколько узлов.
- **.onion** — адрес скрытого сервиса, доступный только через Tor.
- **Tor Browser** — браузер с изоляцией, HTTPS-Everywhere и anti-fingerprinting.

Ключевой принцип: **никогда** не выходите в Tor с рабочей машины и не смешивайте личности.

## Настройка безопасной среды

1. **Изолированная VM** (Whonix/Tails) — весь трафик через Tor, без утечек.
2. **Tor Browser** внутри VM.
3. Никаких личных аккаунтов, никаких логинов.
4. Выключенные JavaScript (по умолчанию «Safest») для опасных сайтов.
5. Отдельный блокнот для заметок, скриншоты — с осторожностью.

> Tails — «живая» система, не оставляющая следов на диске. Whonix — постоянная VM с жёсткой изоляцией.

## Каталоги и точки входа

- **Tor2web-шлюзы** — позволяют открыть `.onion` через обычный браузер (менее приватно).
- **Ahmia** (`ahmia.fi`) — поисковик по onion-сервисам.
- **DarkSearch / OnionLand** — поиск по скрытым сервисам.
- **Каталоги** (The Hidden Wiki и др.) — но осторожно: много скама и фишинга.

## Что искать

- **Утечки БД** — форумы и маркетплейсы данных.
- **Утёкшие креды** — дампы логинов.
- **Обсуждения** бренда/организации.
- **Рынки** — для понимания угроз (fraud, RaaS).

Поиск по домену/бренду:

```
example.com
"example" database
company leak
```

## Мониторинг и сбор

- **Ransomware-порталы** (leak sites) — часто в onion; мониторьте по названию организации.
- **Скрипты** через `torsocks`/`proxychains` для автоматизации (с паузами).
- **Захват доказательств**: скриншот + текст + адрес + время.

```bash
# Доступ к onion через torsocks (пример)
torsocks curl -s http://<onion-address>.onion/ | head
```

## Юридические и этические границы

| Действие | Статус |
|---|---|
| Просмотр публичных onion-страниц | Обычно легально |
| Покупка данных/услуг | Незаконно/аморально |
| Регистрация на криминальных форумах | Серая зона, риск |
| Скачивание утечек | Регулируется законом |
| Связь с продавцами | Не делайте без разрешения и легенды |

Для CTF/пентеста: **только пассивное наблюдение** и только с авторизацией. Никаких покупок и контактов.

## Разобранный пример

Задача: проверить, упоминается ли `example.com` на ransomware-портале.

1. Поднимаем Whonix VM, Tor Browser.
2. Через каталог находим leak site группы.
3. Ищем бренд в списке жертв.
4. Если найдено — фиксируем: дата, группа, заявленные данные.
5. В отчёте — только факт упоминания, без скачивания данных.

## Частые ошибки

- **Выходить в Tor с рабочей машины** (утечка реального IP).
- **Логиниться личными аккаунтами.**
- **Скачивать/запускать файлы** с onion-сайтов.
- **Покупать данные или услуги.**
- **Доверять каталогам без проверки** (фишинг на onion).
- **Забыть про OPSEC**: даже метаданные заметок могут раскрыть вас.

## Операционная безопасность в Tor

Даже внутри Tor легко «светиться»:

- **Не логиньтесь** своими аккаунтами ни на одном сервисе.
- **Отключите JavaScript** на «Safest» — JS-эксплойты деанонимизируют Tor-пользователей.
- **Не открывайте** скачанные файлы вне изолированной VM.
- **Не используйте** один и тот же ник/стиль письма между Tor и клирнетом.
- **Пишите заметки** в изолированной среде; метаданные редактора могут выдать вас.
- **Не меняйте размер окна** без надобности (fingerprinting), следуйте рекомендациям Tor Browser.

## Работа с onion-сервисами на практике

- **Каталоги**: Ahmia, DarkSearch, OnionLand, «Hidden Wiki» (осторожно — много фишинга).
- **Поиск по leak sites**: у ransomware-групп публичные порталы жертв; ищите бренд.
- **Мониторинг**: подписка на фиды (например, ransomware.live) даёт алерты без ручного обхода.
- **Захват доказательств**: скриншот + сохранённый HTML + onion-адрес + время; onion-сайты исчезают мгновенно.

```bash
# доступ к onion через прокси Tor (torsocks)
torsocks curl -s "http://<onion>.onion/" | head -50
```

## Юридические границы (повторение — критично)

| Действие | Допустимо? |
|---|---|
| Просмотр публичных onion-страниц | Обычно да |
| Регистрация на криминальных форумах | Нет без спец. авторизации |
| Покупка данных/услуг | Нет |
| Скачивание утечек | Регулируется законом; обычно нет |
| Контакт с продавцами | Нет |

Для пентеста/CTF — **только пассивное наблюдение** в авторизованном scope. Любое взаимодействие с криминальной инфраструктурой — риск и потенциальное нарушение закона.

## Анатомия onion-сервиса v3

Современный адрес `.onion` — это **56 символов base32** (в v3), кодирующих ed25519-публичный ключ. Из ключа выводится адрес, и сервис публикует **descriptor** (введение-точки, ключи) в распределённую хэш-таблицу (HSDir), построенную на консенсусе каталогов Tor.

```text
Адрес v3: <56 base32>.onion
   └─ ed25519 pubkey (32 байта) → SHA3-256 → base32
Descriptor: подписанные intro points; клиент расшифровывает их секретом,
            производным от адреса — поэтому сервер нельзя «перечислить» перебором.
```

Практическое следствие: **нельзя просканировать** все onion-адреса — они не перечислимы. Находить сервисы можно только через каталоги, ссылки и утечки.

## Безопасная среда: Whonix, Tails, изоляция

Не работайте с даркнетом с рабочей ОС. Варианты:

| Среда | Идея | Когда |
|-------|------|-------|
| Tails | amnesic-система с Tor по умолчанию, всё в RAM | разовый сеанс |
| Whonix | Gateway (Tor) + Workstation в отдельных VM | длительная работа |
| Qubes + Whonix | микро-изоляция по VM | высокий профиль риска |
| Tor Browser (hardened) | уровень «security slider: safest», без JS | быстрый просмотр |

```bash
# мосты для обхода блокировок Tor (obfs4 / snowflake / meek)
# в torrc:
#   UseBridges 1
#   ClientTransportPlugin obfs4 exec /usr/bin/obfs4proxy
#   Bridge obfs4 <ip>:<port> <fingerprint> cert=... iat-mode=0
sudo systemctl restart tor
torsocks curl -s https://check.torproject.org/api/ip   # проверить выходной узел
```

## Инструменты разведки по onion-пространству

- **Ahmia** (`ahmia.fi`) — поисковик по onion, индексирует и фильтрует контент.
- **OnionScan** — сканирует onion-сервис на утечки: misconfig, серверные баннеры, корреляция с clearnet.
- **torsocks** — проксирует любой TCP-инструмент (curl, nmap без syn) через Tor.
- **onionshare** — обмен файлами через временный onion.
- **dark.fail / tor.taxi** — проверенные зеркала популярных сервисов (борьба с фишингом).

```bash
# OnionScan: профилирование onion-сервиса
onionscan --verbose <address>.onion
# выход: HTTP-баннеры, заголовки, возможные clearnet-утечки (favicon, analytics)
```

OnionScan особенно ценен тем, что ищет **связь onion ↔ clearnet** по favicon, заголовкам, сертификатам — это деанонимизирующая зацепка.

## Мониторинг ransomware leak-sites

Современный даркнет-мониторинг — это прежде всего отслеживание площадок утечек вымогателей (Ransomware-as-a-Service). Что фиксируем:

- **Название группы** (LockBit, BlackCat/ALPHV, Cl0p…) и её TTP (см. MITRE ATT&CK).
- **Жертвы**: кто, отрасль, страна, дедлайн, объём данных.
- **IOC**: onion-адрес площадки, контактные Tox/email, кошельки для выкупа.
- **Утечки**: опубликованные архивы → проверка на домены организации.

```bash
# через Tor получаем onion-страницу площадки и парсим таблицу жертв
torsocks curl -s http://<leak-site>.onion/ | grep -oiE '[a-z0-9.-]+\.(com|org|ru)' | sort -u
```

Осторожно: контент площадок часто содержит вредоносные файлы; **не скачивайте** архивы, работайте по метаданным (имена файлов, размеры, даты).

## Работа с форумами и маркетами без покупок

Цель — наблюдение, не участие. Правила:

1. Только чтение; никаких регистраций на криминальных площадках.
2. Не скачивать образцы malware/дампы — используйте threat-intel-фиды.
3. Фиксировать: репутацию продавца, ассортимент, PGP-ключ, каналы связи.
4. Не платить выкуп и не вступать в контакт с вымогателями без юристов/правоохранителей.

Для данных об утечках используйте легальные агрегаторы: HIBP, DeHashed, LeakCheck — они дают API и не требуют захода в даркнет (см. osint-breach-data).

## Дополнительные угрозы и ловушки

- **Exit-node сниффинг** — выходной узел видит ваш clearnet-трафик; поэтому Whonix/Tails и HTTPS обязательны.
- **Correlation-атаки** — совпадение таймингов входа/выхода деанонимизирует; избегайте редких паттернов.
- **De-anonymization по подписи** — одинаковые посты в Tor и clearnet связывают псевдонимы (stylometry).
- **Malicious onion** — фишинг-зеркала маркетов; сверяйтесь с dark.fail и PGP-подписью.
- **Вредоносные вложения** — документы/архивы площадок; открывайте только в изолированной offline-VM.

## Итоговая таблица: что делать / чего не делать

| Делать | Не делать |
|--------|-----------|
| Tails/Whonix + Tor Browser safest | Заходить с рабочей ОС и личного IP |
| Читать, фиксировать метаданные | Регистрироваться и покупать |
