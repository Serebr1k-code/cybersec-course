People search engines (агрегаторы людей) — это сервисы, которые собирают из открытых и коммерческих источников персональные данные и позволяют искать человека по имени, телефону, email или адресу. Они выдают адрес проживания, возраст, родственников, историю телефонов, иногда судимости. Для OSINT это «быстрый старт» по человеку, но данные там устаревшие и требуют верификации. Data brokers (брокеры данных) — более широкая категория, включающая маркетинговые базы.

## Теория: откуда агрегаторы берут данные

Агрегаторы не «взламывают» — они легально собирают (data aggregation) из:
- **Публичных реестров:** записи о собственности, суды, регистрации избирателей, лицензии.
- **Телеком-данных:** привязка телефона к имени/адресу (через партнёров).
- **Маркетинговых списков:** лояльность, подписки, опросы.
- **Соцсетей:** профили, лайки, публичные посты.
- **Кредитных данных:** частично (в США — через FCRA-совместимые источники).

Результат — **профиль человека** с адресами, телефонами, родственниками и «ассоциированными лицами». Точность падает с возрастом данных: адрес может быть пятилетней давности.

## Основные агрегаторы

| Сервис | Регион | Особенности |
|--------|--------|-------------|
| Spokeo | США | адрес, соцсети, email; платный |
| Pipl | глобально | «люди за идентификаторами»; API |
| Whitepages | США | телефоны, адреса, reverse |
| TruePeopleSearch | США | бесплатный, свежие данные |
| FastPeopleSearch | США | бесплатный |
| BeenVerified | США | расширенные отчёты |
| PeekYou | США | соцсети + профили |
| 192.com | UK | реестры, избиратели |
| Yandex/поиск по людям | RU | соцсети, объявления |

Пример запроса по имени+городу:

```
TruePeopleSearch: "Ivan Petrov" "Seattle, WA"
Spokeo: ivan.petrov@example.com
```

## Pipl: поиск по идентификаторам

Pipl специализируется на поиске **по любому идентификатору**: email, телефон, username, соцсеть. Это «обратный» агрегатор: вы даёте цифровой след, получаете человека.

```bash
# API-запрос (требует ключа)
curl -s "https://api.pipl.com/search/?email=target@example.com&key=YOUR_KEY" \
  | python3 -m json.tool | head -40
```

Ответ содержит связанные записи: имена, соцсети, места работы. Для OSINT Pipl ценен именно связкой «идентификатор → личность».

## Reverse-поиск: телефон, адрес, email

Агрегаторы поддерживают обратный поиск:

```bash
# reverse phone (Whitepages, TruePeopleSearch)
# reverse address → жильцы (Whitepages, FastPeopleSearch)
# reverse email → профиль (Pipl, Epieos, HaveIBeenPwned)
```

Пример: адрес → список жильцов → родственники → новые телефоны. Это как строится «дерево» окружения человека (см. `osint-people-family`).

## Разобранный пример: полный профиль по email

Дано: `target@example.com`.

Шаг 1 — Pipl-подобный поиск по email (через публичные формы):

```
1. TruePeopleSearch → ввод email → имя и адрес
2. FastPeopleSearch → ввод email → телефоны
3. Epieos → Google/Outlook-аккаунты
```

Шаг 2 — полученное имя проверяем в Spokeo:

```
Spokeo "Ivan Petrov" → 3 записи:
  - Ivan A. Petrov, 38, Seattle WA, tel 206-xxx
  - Ivan Petrov, 41, Bellevue WA
  - I. Petrov, Renton WA
```

Шаг 3 — устраняем неоднозначность (однофамильцы) по совпадению email/телефона.

Шаг 4 — обогащаем: адрес → Google Maps (фото дома), телефон → соцсети, родственники → новое дерево.

Итог: имя, возраст, адрес, телефон, родственники. Дальше — верификация (см. `osint-identity-resolution`).

## Оценка достоверности

Агрегаторы ошибаются. Чек-лист:

| Признак | Вывод |
|---------|-------|
| Адрес совпадает в 2+ источниках | вероятно, актуален |
| Телефон активен (reverse) | вероятно, верен |
| Только один источник | требует верификации |
| Возраст не совпадает | ложное связывание |
| Родственник подтверждён реестром | сильная связь |

Правило: **два независимых агрегатора + первичный источник** (реестр, соцсеть) = подтверждено.

## Этические и юридические рамки

- **GDPR/152-ФЗ.** В ЕС и РФ обработка персданных граждан строго регулируется; использование агрегаторов по частным лицам без основания незаконно.
- **CTF/расследования.** В CTF данные вымышлены — этично. В реальных расследованиях — только в рамках закона и мандата.
- **Не деанонимизируйте частных лиц ради любопытства.** Это вред и потенциальное преследование.
- **Собирайте только необходимое.** Минимизация данных — принцип OSINT-этики.
- **Не публикуйте PII.** В отчётах используйте маскирование.

| Задача | Сервис |
|--------|--------|
| Имя → адрес (США) | TruePeopleSearch, FastPeopleSearch |

| UK-реестры | 192.com |
| Богатый отчёт | BeenVerified, Spokeo |

## Ошибки и подводные камни

- **Доверять одному источнику.** Агрегаторы перепродают друг другу устаревшие данные.
- **Путать однофамильцев.** `Ivan Petrov` — не редкость; нужен второй идентификатор.
- **Забывать про свежесть.** Адрес «на 2019» может быть неактуален.
- **Игнорировать закон.** Использование по частным лицам вне мандата — нарушение.
- **Платить за отчёт не проверив бесплатные.** TruePeopleSearch/FastPeopleSearch часто дают то же бесплатно.
- **Считать агрегатор «первичным источником».** Он вторичен; первичны реестры.

## Что дальше / решение

Агрегаторы дают «заготовку» профиля. Дальше: **разрешение идентичностей** (`osint-identity-resolution`) для связывания и верификации, **семья и окружение** (`osint-people-family`) для расширения дерева, **публичные реестры** (`osint-public-records`) как первичный источник. Итог: агрегаторы — быстрый вход, но истина всегда в первичных источниках; ваша задача — не «принять» данные, а перепроверить их.

## Автоматизация: сбор из нескольких агрегаторов

Ручной перебор десятков сайтов утомителен. Организуйте конвейер: один запрос → несколько источников → сводная таблица.

```python
#!/usr/bin/env python3
# people-lookup.py — сводка по имени (демонстрация пайплайна)
import requests, csv, sys

NAME = sys.argv[1]
results = []

# каждый источник — отдельная функция (публичные страницы/API)
def spokeo(name):
    # в реальности — API/скрейпинг с соблюдением ToS
    return {"source": "spokeo", "name": name, "city": "Seattle, WA", "age": 38}

def truepeoplesearch(name):
    return {"source": "truepeoplesearch", "name": name, "phone": "206-555-0100"}

for fn in (spokeo, truepeoplesearch):
    try:
        results.append(fn(NAME))
    except Exception as e:
        print("ERR", fn.__name__, e)

with open("people.csv", "w", newline="") as f:
    w = csv.DictWriter(f, fieldnames=["source", "name", "city", "age", "phone"])
    w.writeheader()
    for r in results:
        w.writerow({k: r.get(k, "") for k in w.fieldnames})
print("saved people.csv")
```

Дальше — дедупликация и сравнение полей: адрес, совпавший в двух источниках, повышает уверенность.

## Кросс-верификация адресов и телефонов

Данные агрегаторов проверяются перекрёстно:
- **Адрес** → OSM/Google Maps: существует ли дом, что там (жилой/бизнес).
- **Телефон** → reverse-поиск: имя, оператор, регион.
- **Email** → holehe/Gravatar (см. `osint-email-enum`).
- **Родственники** → публичные реестры, obituaries.

```bash
# пример: reverse phone через публичные сервисы (по одному запросу)
curl -s "https://api.example-reverse.com/?phone=+12065550100" | python3 -m json.tool
```

Три независимых подтверждения = высокий уровень уверенности.

## Ограничения по регионам

Агрегаторы сильно различаются по покрытию:
- **США/UK** — богатые данные (публичные реестры, избиратели).
- **ЕС** — ограничены GDPR (меньше данных, дороже).
- **РФ/СНГ** — данные в соцсетях, объявлениях, госреестрах; агрегаторы слабее.
- **Азия** — свои локальные сервисы.

Для региона вне покрытия переключайтесь на соцсети, объявления (Avito, OLX) и локальные реестры.

## Оптические и гуманитарные риски

- **Ошибка → вред невиновному.** Адрес может быть стар, человек — однофамильцем.
- **Data brokers продают данные без согласия.** Использование по частным лицам этически спорно.
- **Не «доксите».** Публикация PII (даже «открытых») может привести к преследованию.
- **Фиксируйте источник и дату.** В отчёте указывайте, откуда данные и на какую дату.

## Построение дерева окружения

Из агрегаторов извлекаются родственники и «ассоциированные лица». Строим дерево:

```python
# псевдокод: связи из агрегатора
family = {
    "Иван Петров": {"tel": "206-555-0100", "addr": "Seattle, WA"},
    "Мария Петрова": {"rel": "spouse", "addr": "Seattle, WA"},
    "Алексей Петров": {"rel": "relative", "addr": "Bellevue, WA"},
}
for name, info in family.items():
    print(f"{name}: {info}")
```

Совпадение адреса у нескольких «родственников» — подтверждение. Далее каждого проверяем в соцсетях (см. `osint-people-search`) и реестрах (см. `osint-public-records`).

## Публичные реестры как первичный источник

Агрегаторы вторичны. Первичные источники:
- **Записи о собственности** (county assessor) — адрес, владелец.
- **Суды** (PACER, местные) — дела, иски.
- **Регистрация избирателей** — адрес, партия.
- **Лицензии** — профессии.
- **Obituaries** — родственные связи (см. `osint-people-family`).

```bash
# пример: поиск в SEC EDGAR по имени
curl -s "https://efts.sec.gov/LATEST/search-index?q=%22Ivan%20Petrov%22" \
  -H 'User-Agent: osint research' | python3 -m json.tool | head
```

## Где пригодится

- **CTF (OSINT):** синтетический профиль в агрегаторе ведёт к флагу.
- **Расследования:** быстрый старт по человеку и его окружению.
- **Проверка контрагентов/KYC:** верификация лиц и адресов.
- **Bug bounty:** понимание цифрового следа сотрудников.
- **Фактчекинг:** сопоставление публичных данных о персоне.
