Открытые в интернет веб-камеры и IoT-устройства — отдельный, очень ценный класс OSINT-ресурсов. Кадр с публичной камеры даёт сразу три вещи: геолокацию (ориентиры, вывески, номера домов), хронолокацию (тени, освещение, погода, сезон) и верификацию события (что происходит в точке прямо сейчас). Дополнительно это индикатор гигиены инфраструктуры: десятки тысяч устройств смотрят наружу с заводскими паролями и без обновлений. В этом уроке — полный цикл: от поисковых запросов по базам баннеров до получения кадра, его анализа и превращения в координаты, с инструментами, флагами, разобранными примерами и этическими границами.

## Зачем камеры и IoT в разведке

- **Геолокация без выезда.** Камера на перекрёстке показывает вывески, дорожные знаки, архитектуру — этого достаточно для точной привязки.
- **Хронолокация.** Положение тени и уровень освещения позволяют оценить время суток и дату (см. урок про хронолокацию).
- **Верификация событий.** Журналисты и расследователи подтверждают факты (пожар, протест, погода) по живым потокам.
- **Инвентаризация.** Blue team ищет собственные устройства, случайно выставленные наружу.
- **Мониторинг.** Для критической инфраструктуры — проверка, что камера не отвалилась и не стала публичной.

## Анатомия открытого видеопотока

Камера отдаёт видео одним из нескольких способов:

- **MJPEG over HTTP** — последовательность JPEG-кадров, `Content-Type: multipart/x-mixed-replace; boundary=...`. Простейший случай: браузер открывает URL и видит поток.
- **RTSP** (порт 554) — потоковый протокол, путь (`/Streaming/Channels/101`, `/h264`, `/live`) зависит от вендора.
- **HLS** (`.m3u8`) — плейлист сегментов, часто используется облачными камерами.
- **RTMP** (порт 1935) — старый протокол, всё ещё встречается в дешёвых устройствах.
- **ONVIF** — SOAP-интерфейс управления (порты 80/8080), часто без аутентификации, отдаёт список профилей и URI потока.

Понимание протокола определяет инструмент: для RTSP — `ffmpeg`, для MJPEG — `curl`/`ffmpeg`, для ONVIF — `onvif-cli` или `python-onvif-zeep`.

## Поисковые системы и запросы

Главные базы — Shodan, Censys, FOFA, ZoomEye. Каждая индексирует баннеры и метаданные.

```bash
# Shodan: камеры со снимком, конкретная страна
shodan search --fields ip_str,port,product,location.country_name 'webcam country:RU has_screenshot:true'

# Shodan: устройства конкретного вендора
shodan search --fields ip_str,port 'product:"Hikvision IP Camera"'

# Censys: поиск по баннеру
curl -s "https://search.censys.io/api/v2/hosts/search?q=services.banner%3A%22IPCam%22&per_page=50" \
  -u "$CENSYS_ID:$CENSYS_SECRET" | jq '.result.hits[].ip'

# FOFA (ключ и email в env)
fofa search 'app="Hikvision-Webs" && country="RU"' -f ip,port,title
```

Google dorks дают дополнительный охват для веб-интерфейсов:

```
inurl:/view.shtml
intitle:"Live View / - AXIS"
inurl:ViewerFrame?Mode=
inurl:/cgi-bin/mjpg/video.cgi
intitle:"webcamXP"
"Server: IPCam"
```

## Инструменты и флаги

```bash
# получить кадр с RTSP (по TCP, чтобы избежать потерь)
ffmpeg -rtsp_transport tcp -i "rtsp://<ip>:554/Streaming/Channels/101" -frames:v 1 cam.jpg

# получить кадр с MJPEG-потока
ffmpeg -i "http://<ip>/video" -frames:v 1 cam.jpg

# проверить параметры потока (кодеки, разрешение) без скачивания
ffprobe -rtsp_transport tcp -v error -show_streams "rtsp://<ip>:554/stream"

# снять HTTP-заголовки камеры
curl -sI "http://<ip>/" | sed -n '1,15p'

# ONVIF: получить потоковые URI
onvif-cli devicemgmt http://<ip>/onvif/device_service GetStreamUri
```

Полезные флаги: `-rtsp_transport tcp` (надёжнее UDP), `-frames:v 1` (один кадр), `-t 5` (ограничить время), `-y` (перезапись файла), `-loglevel error` (тихий вывод). Для массовой проверки живых RTSP — `nmap` с NSE-скриптом `rtsp-url-brute`.

## Разобранный пример: от запроса до кадра

Дано: нужно подтвердить, что объект X находится в городе Y.

Шаг 1 — Shodan: `webcam country:RU has_screenshot:true` вокруг координат города. Выбираем кандидата `203.0.113.44:554`.

Шаг 2 — проверяем поток:

```bash
ffprobe -rtsp_transport tcp -v error -show_entries stream=codec_name,width,height \
  "rtsp://203.0.113.44:554/Streaming/Channels/101"
```

Вывод:

```text
codec_name=h264
width=1920
height=1080
```

Шаг 3 — снимаем кадр и читаем метаданные:

```bash
ffmpeg -rtsp_transport tcp -i "rtsp://203.0.113.44:554/Streaming/Channels/101" -frames:v 1 cam.jpg
exiftool cam.jpg | grep -iE 'date|software|model'
```

Вывод:

```text
File Modification Date/Time : 2026:10:11 14:22:03+03:00
```

Шаг 4 — на кадре читаем вывеску «Магазин "Радуга"», номер дома 12, перекрёсток. Сверяем с картами → координаты.

Шаг 5 — фиксируем: IP, порт, протокол, путь, координаты, время кадра, привязку (без публикации людей).

## Геолокация и хронолокация по кадру

1. Снимите кадр и метаданные (`exiftool cam.jpg`).
2. Найдите ориентиры: вывески, флаги, архитектуру, номера авто, логотипы сетей.
3. Сверьте с картами (Google/Yandex), панорамами, Street View.
4. Оцените тень и азимут солнца — это время суток и примерная дата.
5. Погода/облачность в кадре сужает регион и день.
6. Язык вывесок, номерные знаки, дорожная разметка — страна/регион.

Камеры на площадях, стройках, парковках особенно ценны: много привязок и движения.

## Вендоры, дефолты и признаки уязвимости

| Вендор | Признак в баннере | Дефолтные креды (только для аудита) |
|---|---|---|
| Hikvision | `/ISAPI/`, `Hikvision-Webs` | `admin:12345` |
| Dahua | `Dahua` в title | `admin:admin` |
| Axis | `AXIS` в title | `root:pass` |
| D-Link | `DCS-` | `admin:` (пусто) |
| Reolink | `Reolink` | `admin:` (пусто) |
| Foscam | `Foscam` | `admin:` (пусто) |

Признаки уязвимости: дефолтные учётки, открытый Telnet/SSH (23/22) с заводским паролем, известные CVE (Hikvision/Dahua RCE, path traversal), отсутствие HTTPS, открытая админ-консоль, ONVIF без аутентификации. Проверка дефолтов — **только** в авторизованном scope: публично доступное устройство не даёт права входа.

## Продвинутые приёмы и автоматизация

- **Массовая проверка.** `nmap -p554 --open -iL targets.txt` + `rtsp-url-brute` находит живые RTSP; для MJPEG — `ffuf` по путям (`/video`, `/mjpg/video.cgi`, `/axis-cgi/mjpg/video.cgi`).
- **Скриншоты интерфейсов.** Shodan/FOFA отдают кэшированный скриншот — быстрый способ оценить тип устройства без подключения.
- **Сравнение кадров.** `ffmpeg -i rtsp://... -vf fps=1/60 frame_%04d.jpg` вырезает кадр раз в минуту для анализа движения.
- **Привязка события.** Несколько камер одного района + погодный сервис позволяют надёжно привязать событие к дате и времени.
- **Облачные камеры.** Часть устройств пишет в облако вендора — это тоже поверхность (слабые токены, общие ссылки на клипы).

## Инвентаризация собственных устройств (blue team)

```bash
# найти свои камеры в Shodan по диапазону
shodan search 'product:"webcam" net:<your-cidr>'

# проверить, торчат ли наружу RTSP/HTTP-панели
nmap -p 80,554,8000,8080,8554 --open -iL your-ranges.txt -oX cam-scan.xml
```

Регулярная инвентаризация + закрытие портов + смена дефолтов = базовая гигиена IoT. Отдельно проверьте, не отдаёт ли камера снимки в облако третьей стороны и не остаётся ли пароль по умолчанию.

## Этика, право и scope

- Просмотр **публично доступной** камеры — серая зона; публикация кадров с людьми нарушает приватность.
- Вход по чужому/дефолтному паролю — несанкционированный доступ (уголовно наказуемо).
- Для отчётов используйте агрегированные данные и координаты, а не кадры с людьми.
- В bug bounty — только в scope и без вреда.
- Не публикуйте кадры, по которым можно установить местоположение частного лица.

## Частые ошибки

- **Публиковать кадры с людьми** — риск преследования и утечки приватности.
- **Пробовать дефолтные пароли без разрешения** — это уже атака, а не разведка.
- **Доверять метаданным камеры** — они часто пустые или подделаны.
- **Забыть про задержку/таймстамп** — камера может показывать архив, а не реальное время.
- **Путать открытый порт с доступом к видео** — порт отвечает, но поток под паролем.
- **Игнорировать масштаб** — одна камера даёт мало; сеть камер даёт маршруты и контекст.

## Что дальше / решение

Собрав кадр и координаты, двигайтесь дальше: (1) проверьте камеру в Censys/FOFA по вендору и версии прошивки; (2) поищите соседние устройства по тому же диапазону ASN; (3) при подтверждении события зафиксируйте цепочку доказательств (скриншот, хэш, время); (4) для blue team — внесите устройство в реестр и закройте лишние порты. Решение по каждой находке: «публичный ресурс — использовать для геолокации», «уязвимое устройство — эскалировать владельцу», «этически неприемлемо — не трогать».

## Практические сценарии и чек-лист

- **Геолокация объекта по вывеске.** Кадр камеры у магазина + Google Street View дают точку с погрешностью в десятки метров.
- **Хронолокация по тени.** Тень столба в кадре + дата → время суток; сезонные признаки (снег, листва, спецтехника) → месяц.
- **Верификация события.** Пожар или наводнение: несколько камер одного района подтверждают масштаб и время.
- **Инвентаризация IoT.** Организация находит свои камеры в Shodan/FOFA по ASN и закрывает лишние порты.
- **Проверка подлинности видео.** Сверка «горячего» видео с кадром камеры выявляет монтаж и подделку даты.

Порядок действий при находке: зафиксировать IP/порт/протокол → снять кадр → сохранить хэш и время → привязать к координатам → отметить уровень достоверности. Кадр без привязки бесполезен; кадр с привязкой и временем — доказательство.

## Ограничения метода

- Не все камеры доступны: часть за логином, часть за CDN/WAF.
- Качество и ракурс ограничивают чтение вывесок и номеров.
- Метаданные часто отсутствуют или подделаны — полагайтесь на визуальные признаки.
- Часовой пояс кадра неочевиден: используйте солнце, а не таймстамп.
- Юридический статус просмотра различается по странам.
