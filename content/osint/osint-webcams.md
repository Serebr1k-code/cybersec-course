## Вопрос, с которого всё начинается

Нужно подтвердить, что объект X действительно находится в городе Y. Карты дают общую картину, но не доказывают, что происходит прямо сейчас.

Открытая в интернет **веб-камера** даёт сразу три вещи: геолокацию (вывески, номера домов, ориентиры), хронолокацию (тени, освещение, погода) и верификацию события (что в точке прямо сейчас). Разберём полный цикл на одном устройстве.

## Наш пример: камера 203.0.113.44

У нас один объект — IP `203.0.113.44`. Введём термины. **RTSP** (Real Time Streaming Protocol) — протокол потокового видео, обычно на порту 554. **MJPEG** — поток из последовательных JPEG-кадров по обычному HTTP. **ONVIF** — стандартный интерфейс управления камерой.

## Шаг 1: находим камеры в базах

Сканеры интернета индексируют баннеры камер. Ищем устройства со снимком экрана в нужной стране:

```bash
shodan search --fields ip_str,port,product 'webcam country:RU has_screenshot:true'
```

```
203.0.113.44  554  Hikvision IP Camera
198.51.100.9  8080  Dahua
```

Фильтр `has_screenshot:true` оставляет только устройства, для которых Shodan снял скриншот веб-интерфейса — это быстрый способ оценить тип устройства, не подключаясь. Дополнительный охват дают Google-дорки по веб-интерфейсам камер:

```
inurl:/view.shtml
intitle:"Live View / - AXIS"
intitle:"webcamXP"
```

## Шаг 2: определяем протокол

Прежде чем тянуть видео, надо понять, как камера его отдаёт — от этого зависит инструмент:

| Протокол | Порт | Инструмент |
|---|---|---|
| MJPEG (HTTP) | 80/8080 | `ffmpeg -i http://ip/video` |
| RTSP | 554 | `ffmpeg -rtsp_transport tcp -i rtsp://...` |
| HLS | 80/443 | `ffmpeg -i http://ip/stream.m3u8` |
| ONVIF | 80/8080 | `onvif-cli` |

Проверим поток нашего кандидата, не скачивая видео целиком:

```bash
ffprobe -rtsp_transport tcp -v error -show_entries stream=codec_name,width,height \
  "rtsp://203.0.113.44:554/Streaming/Channels/101"
```

```
codec_name=h264
width=1920
height=1080
```

Флаг `-rtsp_transport tcp` заставляет работать по TCP, а не UDP — так надёжнее. Мы видим кодек H.264 и разрешение 1080p. Путь `/Streaming/Channels/101` — типичный для камер Hikvision.

## Шаг 3: снимаем кадр

Теперь забираем один кадр и читаем его метаданные:

```bash
ffmpeg -rtsp_transport tcp -i "rtsp://203.0.113.44:554/Streaming/Channels/101" -frames:v 1 cam.jpg
exiftool cam.jpg | grep -iE 'date|software|model'
```

```
File Modification Date/Time : 2026:10:11 14:22:03+03:00
```

Флаг `-frames:v 1` берёт ровно один кадр. **Метаданные** кадра (EXIF) — служебные поля файла: время, софт, модель. Здесь есть дата, но нет модели камеры — и это типично: метаданным камеры доверять нельзя, они часто пустые или подделаны.

## Шаг 4: геолокация по кадру

На кадре читаем вывеску, номер дома и перекрёсток. Дальше — стандартная воронка:

1. Находим ориентиры: вывески, флаги, архитектуру, логотипы сетей.
2. Сверяем с картами (Google, Яндекс) и панорамами Street View.
3. Определяем страну и регион по языку вывесок, номерам и дорожной разметке.

Например, вывеска «Магазин Радуга», дом 12 и характерный перекрёсток дают точку с погрешностью в десятки метров.

## Шаг 5: хронолокация по тени

Дата из метаданных может врать, а **тень** — нет. Направление тени показывает сторону света, длина — высоту солнца, то есть примерное время суток. Погода и сезонные признаки (снег, листва) сужают месяц. Так кадр превращается в «где и когда».

## Шаг 6: фиксируем доказательство

Кадр без привязки бесполезен; кадр с привязкой и временем — доказательство. Сохраняем IP, порт, протокол, путь, координаты и время, а также хэш файла:

```bash
sha256sum cam.jpg
```

```
3f9a1c...e7  cam.jpg
```

Хэш доказывает, что копия не изменена.

## Шаг 7: инвентаризация своих устройств (blue team)

Тот же инструментарий работает и в защиту. Организация ищет собственные камеры, случайно выставленные наружу:

```bash
shodan search 'product:"webcam" net:203.0.113.0/24'
nmap -p 80,554,8000,8080,8554 --open -iL your-ranges.txt -oX cam-scan.xml
```

Признаки уязвимости: дефолтные учётки, открытый Telnet с заводским паролем, отсутствие HTTPS, ONVIF без аутентификации. Регулярная инвентаризация, закрытие портов и смена дефолтов — базовая гигиена IoT.

Камеры на площадях, стройках и парковках особенно ценны: много привязок и движения. Несколько камер одного района дают маршруты и контекст, которых не даст один кадр.

## Вендоры и признаки устройства

Производителя камеры часто видно по баннеру или заголовку страницы:

| Вендор | Признак в баннере |
|---|---|
| Hikvision | `/ISAPI/`, `Hikvision-Webs` |
| Dahua | `Dahua` в заголовке |
| Axis | `AXIS` в заголовке |
| D-Link | `DCS-` |
| Reolink | `Reolink` |
| Foscam | `Foscam` |

Признаки уязвимости: дефолтные учётки, открытый Telnet с заводским паролем, отсутствие HTTPS, открытая админ-консоль, ONVIF без аутентификации. Проверка дефолтных паролей — **только** в авторизованном scope: публично доступное устройство не даёт права входа.

## Ограничения метода

- Не все камеры доступны: часть за логином, часть за CDN и WAF.
- Качество и ракурс ограничивают чтение вывесок и номеров.
- Метаданные часто отсутствуют или подделаны — полагайтесь на визуальные признаки.
- Часовой пояс кадра неочевиден: используйте солнце, а не таймстамп.
- Юридический статус просмотра различается по странам.

## Что мы теперь знаем

- Открытая камера даёт геолокацию, хронолокацию и верификацию события.
- Протокол потока определяет инструмент: RTSP и MJPEG тянутся через `ffmpeg`.
- Метаданным кадра доверять нельзя — полагайтесь на визуальные признаки и тень.
- Кадр становится доказательством только с привязкой, временем и хэшем.
- Тот же метод служит blue team для инвентаризации своих устройств.

## На что смотреть дальше

Разберись с **ONVIF** (`onvif-cli`), который часто отдаёт список профилей без аутентификации, и с массовой проверкой RTSP через `nmap` NSE-скрипт `rtsp-url-brute`. Изучи облачные камеры: часть устройств пишет в облако вендора, и это тоже поверхность — слабые токены и общие ссылки на клипы. И держи в голове этическую границу: просмотр публичного потока — серая зона, а вход по чужому паролю — преступление. Кадры с людьми в отчёт не включают: используйте только координаты и агрегированные данные.

## Куда дальше

Мы научились находить камеры и превращать кадр в координаты. В следующем уроке — **GitHub-разведка**: возьмём организацию и по её репозиториям соберём сотрудников, технологии и утёкшие секреты. А пока главное запомни: кадр без привязки бесполезен, а кадр с привязкой и временем — доказательство.

## Где пригодится

- **CTF:** геолокационные и verification-задачи.
- **Bug bounty:** отчёты об открытых IoT-устройствах в рамках scope.
- **Пентест:** инвентаризация физической и сетевой поверхности.
- **Blue team:** поиск и закрытие собственных открытых камер.
