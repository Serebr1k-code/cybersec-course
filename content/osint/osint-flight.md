Самолёты непрерывно передают телеметрию через ADS-B (Automatic Dependent Surveillance — Broadcast). Данные открыты и принимаются любительскими приёмниками по всему миру. Для OSINT это способ отследить конкретный борт, привязать его к владельцу и восстановить маршрут — вплоть до частной авиации. В уроке — как устроен ADS-B, как принять его своими силами, как работать с OpenSky API и реестрами бортов, и где проходят этические границы.

## ADS-B: что передаётся

- **ICAO 24-bit address (hex)** — уникальный идентификатор борта (например, `3c6444`).
- **Callsign** — рейс или регистрация.
- **Позиция, высота, скорость, курс.**
- **Squawk** — код транспондера (7700 — бедствие, 7600 — потеря связи, 7500 — захват).

Приём ведётся по **1090 МГц** (и 978 МГц UAT в США). Любительские приёмники (RTL-SDR + `dump1090`) питают публичные сети агрегаторов.

```bash
# собственный приём ADS-B (RTL-SDR)
rtl_fm -f 1090M -M adsb -s 2000000 - | dump1090 --net
# или напрямую через dump1090-rtl
dump1090 --net --interactive
```

## Сервисы трекинга и их отличия

| Сервис | Особенность |
|---|---|
| FlightRadar24 | удобный веб, история (платно) |
| ADSBexchange | **без фильтрации** частных бортов (в отличие от FR24) |
| FlightAware | расписания, история рейсов |
| OpenSky Network | бесплатный API, академические данные |
| Plane Finder | альтернативный агрегатор |
| JetPhotos/Airliners.net | фото бортов по регистрации |

Ключевое отличие: FR24 по запросу владельца скрывает часть бортов, ADSBexchange — нет. Для исследования частной авиации используйте ADSBexchange.

## OpenSky API: запросы и разбор

```bash
# состояние в зоне (bbox: lamin,lomin,lamax,lomax)
curl -s "https://opensky-network.org/api/states/all?lamin=55.5&lomin=37.0&lamax=56.0&lomax=37.9" \
  | jq '.states[] | {callsign: .[1], lon: .[5], lat: .[6], alt: .[7]}'

# история полётов конкретного борта (по hex) за интервал
curl -s "https://opensky-network.org/api/flights/aircraft?icao24=3c6444&begin=1700000000&end=1700086400" \
  | jq '.[] | {callsign, estDepartureAirport, estArrivalAirport}'
```

Вывод (пример):

```json
{"callsign":"AFL123","estDepartureAirport":"UUEE","estArrivalAirport":"ULLI"}
```

Лимиты: анонимно — ~100 запросов/сутки на endpoint; с аккаунтом больше. Интервал `begin`/`end` — unix-время, максимум 2 дня на запрос.

## От борта к владельцу: реестры

1. Возьмите **hex** или **регистрацию** (`RA-xxxxx`, `N-xxxxx`, `G-xxxx`).
2. Введите в **registry**: FAA N-registry (США), CAA G-INFO (UK), Росавиация (РФ), EASA.
3. Получите **тип, оператора, владельца**.
4. Сверьте с базой трекинга: где борт был (аэропорты, офисы, офшоры).
5. Для частной авиации маршрут часто выдаёт интересы владельца.

```bash
# FAA N-registry: поиск по регистрации
curl -s "https://registry.faa.gov/aircraftinquiry/Search/NNumberResult?nNumberTxt=N12345" \
  | grep -iE 'Name|Model'
```

## Разобранный пример: маршрут бизнес-джета

Задача: установить, куда летал частный бизнес-джет.

1. В ADSBexchange находите борт по регистрации.
2. Смотрите историю: аэропорты вылета/посадки за месяц.
3. По реестру определяете владельца (часто ООО или траст).
4. Сопоставляете аэропорты с офисами/активами владельца.
5. Фиксируете: регистрация, hex, маршруты, даты, владелец — с ссылками.

## Аналитика аномалий

- **Squawk 7700/7600/7500** — инциденты (авария/потеря связи/захват).
- **Отключение транспондера** — борт пропадает с карт (подозрительно).
- **Нестандартные маршруты** — облёт зон, необычные аэропорты.
- **Бизнес-джеты** — маршрут выдаёт деловые интересы владельца.
- **Военные (AE-hex)** — часто не видны; иногда отображаются частично.

## ACARS и смежные каналы

ACARS — текстовые сообщения борта, передаются по отдельному радиоканалу (VHF). Их можно принимать SDR-приёмником и декодировать (`acarsdec`). ACARS дополняет ADS-B: там бывают тексты о загрузке, технических проблемах и планах. См. также урок про радиоразведку.

## Этические и правовые границы

- Данные ADS-B публичны, но **массовое** отслеживание конкретного человека (PII) — чувствительная тема.
- Публикация домашнего аэродрома и графика частного лица может быть преследованием.
- В отчётах используйте только проверенные публичные источники и не разглашайте приватность.

## Частые ошибки

- **Путать callsign и регистрацию**: у рейсовых бортов callsign — номер рейса, у частных — регистрация.
- **Игнорировать фильтрацию FR24**: часть бортов скрыта; используйте ADSBexchange.
- **Забыть про задержку**: у некоторых сервисов позиция с задержкой 5–15 минут.
- **Считать отсутствие борта в воздухе доказательством**: он мог выключить транспондер или быть на земле.
- **Не проверять тип борта**: одинаковый callsign может использоваться разными бортами.

## Что дальше / решение

Определив борт и владельца, свяжите данные с другими источниками: реестры юрлиц (см. osint-business-registry), фото бортов, ACARS. Решение: «рейсовый борт — данные тривиальны», «частный борт — маршрут даёт связи владельца (анализировать)», «военный/скрытый — зафиксировать аномалию, не делать выводов». Всегда указывайте источник и дату наблюдения.

## Приём ADS-B своими силами

- **Оборудование:** RTL-SDR (~$30), антенна 1090 МГц (диполь/коллинеар), фильтр+LNA для слабых сигналов.
- **Софт:** `dump1090`/`readsb` декодирует ADS-B; `tar1090` даёт веб-карту.
- **Фидер:** локальный приёмник можно отдавать в ADSBexchange/FR24 — взамен вы получаете доступ к их данным.

```bash
# декодер с веб-картой
readsb --device-type rtlsdr --gain auto --net --write-json /run/readsb &
# классический dump1090
dump1090 --net --interactive --gain 40
# вытащить конкретный борт из локального JSON
curl -s "http://localhost:8080/data/aircraft.json" | jq '.aircraft[] | select(.hex=="3c6444")'
```

Покрытие зависит от высоты антенны и рельефа; типичный охват с балкона — 100–300 км по воздушным целям.

## Верификация борта: фото и ливрея

- **JetPhotos/Airliners.net/Planespotters** — фото по регистрации или hex; ливрея подтверждает оператора на дату.
- **Смена ливреи** — сигнал смены владельца или лизинга.
- **Серийный номер** — точная идентификация в реестрах и сервис-документах.
- **История регистраций** — борт мог менять регистрацию и владельца.

## Расчёт охвата и качества данных

| Фактор | Влияние |
|---|---|
| Высота антенны | прямо влияет на дальность |
| Рельеф | горы/застройка режут сигнал |
| Задержка сети | FR24/ADSBexchange отстают 5–15 мин |
| Плотность фидеров | в глухих районах пробелы |
| Отключение транспондера | борт исчезает из данных |

## Смежные радиоканалы

- **ACARS** — текстовые сообщения борта по VHF; приём через SDR + `acarsdec`.
- **VDL Mode 2** — более новый канал данных.
- **HFDL** — коротковолновый канал для дальних рейсов.
- **ADS-C** — спутниковая передача (не broadcast, требует доступа).

```bash
# декодирование ACARS
rtl_fm -f 131.550M -M am -s 12000 - | acarsdec -r 12000 -
```

## Открытые данные и API

- **OpenSky** — states/all, flights/aircraft, flights/arrival; лимиты анонимно ~100/сутки.
- **adsb.lol / adsb.fi** — бесплатные публичные фиды (JSON) без ключа.
- **ADSBexchange** — платный API для истории.
- **FAA** — реестр бортов (выгрузка по N-номеру).

```bash
# бесплатный публичный фид
curl -s "https://api.adsb.lol/v2/hex/3c6444" | jq '.ac[] | {flight, lat, lon, alt_baro}'
```

## Практический чек-лист анализа борта

1. Собрать hex/callsign из ADS-B.
2. Найти борт в ADSBexchange (не FR24 — фильтрация).
3. Поднять историю полётов (аэропорты, даты).
4. Определить владельца по реестру (FAA/CAA/Росавиация).
5. Проверить фото/ливрею и серийный номер.
6. Сопоставить маршруты с активами владельца.
7. Зафиксировать аномалии (squawk, пропадания).
8. Сохранить доказательства со ссылками и датами.

## История вопроса и приватность

ADS-B стал обязательным в значительной части воздушного пространства (Европа — с 2020, США — раньше). До него позиции определялись радарами, закрытыми для публики. Открытость ADS-B в сочетании с дешёвыми SDR породила экосистему публичного трекинга — и новые риски приватности: любой может построить маршрутный профиль борта и через реестры выйти на владельца.

## Как не ошибиться с идентификацией

- Один callsign могут использовать разные борта — сверяйте hex.
- Регистрация может быть переиспользована после снятия борта с учёта.
- Транспондер иногда настроен неверно (чужой hex) — кросс-проверка обязательна.
- «Пустой» callsign — норма для части военных и частных бортов.
- ADS-B не отдаёт тип борта напрямую — берите его из реестра.

## Сводка источников

| Источник | Данные | Ключ |
|---|---|---|
| OpenSky | states, flights | нет (лимит) |
| adsb.lol | live фид | нет |
| ADSBexchange | live + история | платный |
| FR24 | live + история | фильтрация |
| FAA/CAA/Росавиация | реестр борта | нет |
| JetPhotos | фото | нет |

## Дополнительные замечания и типичные кейсы

- **Рейсовые борта** дают мало: их маршруты и так публичны в расписаниях.
- **Чартеры и бизнес-джеты** — основная ценность: маршрут выдаёт встречи и активы.
- **Грузовые борта** помогают понять логистику компании.
- **Вертолёты** отслеживаются хуже: часть летает вне зон обязательного ADS-B.
- **Дроны** в большинстве не видны в ADS-B (Remote ID — отдельная система).

Для верификации события сопоставляйте трек борта с временем и местом события; расхождения — повод проверить подлинность.
