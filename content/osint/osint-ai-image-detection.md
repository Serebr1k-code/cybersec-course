## Вопрос, с которого всё начинается

Тебе прислали картинку: «вот как это выглядело». Но сегодня изображение легко сгенерировать: diffusion-модели и GAN создают фотореалистичные кадры за секунды. Как отличить сгенерированное от настоящего?

Задача: найти признаки генерации — в метаданных, в размере, в частотных артефактах — и оценить уверенность.

## Наш пример: файл gen.png

Держим объект `gen.png`. Первый вопрос: **что говорят метаданные?**

```bash
exiftool gen.png
```

```text
File Type : PNG
Software  : Stable Diffusion v1.5
Image Size: 512x512
```

Читаем: `Software: Stable Diffusion v1.5` — прямое указание на генератор, а `512x512` — типичный размер выхода моделей. Это простейший случай: генератор сам подписал файл. Но так бывает не всегда — метаданные легко удаляют.

## Шаг 1: метаданные и размер

Многие генераторы оставляют следы в метаданных: `Software`, `Comment`, `Parameters` (промпт), имя модели. Даже если их вычистили, остаётся косвенный признак — **размер**. Диффузионные модели по умолчанию дают 512×512, 768×768, 1024×1024. Нестандартные, но «ровные» размеры (не совпадающие с матрицами камер) — сигнал.

```bash
python3 -c "from PIL import Image;print(Image.open('gen.png').size)"
```

```text
(512, 512)
```

Сопоставление: у настоящей камеры размеры часто «неудобные» (например, 4032×3024), а у генератора — степени двойки.

## Шаг 2: частотные артефакты

Изображение можно разложить на частоты (преобразование Фурье). У настоящих фото есть естественный шум сенсора (PRNU) во всех частотах. У сгенерированных — характерные «регулярные» пики и провалы: GAN оставляют след апскейлинга, diffusion — характерный спектр.

```bash
# иллюстративно: спектр изображения
python3 -c "import numpy as np;from PIL import Image;f=np.fft.fft2(np.array(Image.open('gen.png').convert('L')));print(np.abs(f).mean())"
```

На спектре сгенерированных картинок часто видны регулярные структуры, которых не бывает у естественного шума. Это один из самых устойчивых признаков.

## Шаг 3: визуальные и семантические подсказки

Даже без частотного анализа генерацию выдают детали. Первое — руки и пальцы: классическая слабость моделей. Второе — текст: буквы «плывут» и не читаются. Третье — фон: повторяющиеся паттерны, странная геометрия. Четвёртое — освещение: тени не соответствуют источникам света. Пятое — украшения и мелкие объекты: они «слипаются».

```text
Признаки: руки, текст, фон, освещение, мелкие детали
```

Но осторожно: новые модели исправляют эти слабости, поэтому визуальные признаки — не приговор.

## Шаг 4: границы

Мы собираем признаки. Мы **не делаем вывод «сгенерировано» по одному признаку**: 512×512 может быть обрезанным фото, а странные руки — плохим качеством. Вывод строится на совокупности: метаданные, размер, частотный спектр, визуальные детали, контекст и C2PA.

Особенно важна честность в отчёте: указывай уверенность и метод. Ложное обвинение в генерации так же вредно, как пропуск подделки.

## Полный прогон

```bash
# 1. метаданные
exiftool gen.png | grep -E 'Software|Comment|Image Size'
# → Software: Stable Diffusion v1.5, Image Size: 512x512
# 2. размер
python3 -c "from PIL import Image;print(Image.open('gen.png').size)"
# → (512, 512)
# 3. спектр (иллюстративно)
python3 -c "import numpy as np;from PIL import Image;print(np.fft.fft2(np.array(Image.open('gen.png').convert('L'))).shape)"
```

Непрерывно: файл → метаданные → размер → спектр → визуальные детали → вывод.

## Если не сработало

**Метаданные пусты.** Соцсети вырезают их — переходи к спектру и визуальным признакам.
**Размер нестандартный.** Генератор мог изменить размер — это не оправдывает.
**Модель исправила слабости.** Новые генераторы реалистичны — нужна совокупность методов.

## Частые ошибки

**Ошибка: судить по рукам.** Новые модели рисуют руки правильно.
**Ошибка: игнорировать метаданные.** Поле `Software` — прямое доказательство.
**Ошибка: верить одному размеру.** Фото можно обрезать до 512×512.
**Ошибка: забывать про C2PA.** Многие генераторы помечают синтетику манифестом.

## Справочная таблица: признаки генерации

| Признак | Где | Надёжность |
|---------|-----|------------|
| `Software` = генератор | метаданные | высокая |
| размер 512/768/1024 | метаданные | средняя |
| частотный спектр | анализ | высокая |
| руки/текст/фон | визуально | средняя |
| C2PA-манифест | метаданные | высокая |

## Разбор кейса: «фото» с маркером генератора

Дано: изображение из соцсети, заявленное как снимок. Шаг первый — `exiftool` показывает `Software: Stable Diffusion v1.5`. Шаг второй — размер 512×512. Шаг третий — спектр содержит регулярные структуры. Вывод: изображение сгенерировано. Разведчик зафиксировал три независимых признака и указал высокую уверенность.

## Рабочий воркбук: полное расследование изображения

**Этап 1. Метаданные.** Прочитай `Software`, `Comment`, `Parameters`, размер.

**Этап 2. Размер.** Сопоставь с типовыми выходами моделей и матрицами камер.

**Этап 3. Спектр.** Построй частотное представление и ищи регулярные структуры.

**Этап 4. Визуально.** Проверь руки, текст, фон, освещение, мелкие детали.

**Этап 5. C2PA и контекст.** Проверь манифест происхождения и источник публикации.

## Частые вопросы

**Можно ли всегда определить генерацию?** Нет, новые модели реалистичны; вывод вероятностный.

**Что надёжнее всего?** Метаданные генератора и C2PA; затем частотный анализ.

**Почему размер важен?** Модели по умолчанию дают «ровные» размеры, нетипичные для камер.

**Помогает ли обратный поиск?** Да: если картинка найдена в базе генератора или впервые появилась онлайн — это зацепка.

**Это законно?** Анализ изображения — да; это верификация.

## Термины

**GAN** — генеративно-состязательная сеть.

**Diffusion** — класс моделей генерации изображений.

**PRNU** — шум сенсора, «отпечаток» камеры.

**Спектр (Фурье)** — частотное представление изображения.

**C2PA** — манифест происхождения, часто помечающий синтетику.

## Инструменты и практический воркфлоу

Метаданные смотрят не только `exiftool`, но и `exiv2`, а для PNG — читают чанки напрямую. Генераторы часто пишут промпт в текстовые чанки `tEXt`/`iTXt` с ключами `parameters`, `prompt`, `Comment`.

```bash
exiftool -G -a gen.png | grep -Ei 'software|comment|param|prompt|model'
# → [PNG-tEXt] Parameters: a photo of ..., Steps: 20, Sampler: Euler, Model: v1-5
```

Когда метаданные стёрли, применяют **Error Level Analysis (ELA)**: изображение пересохраняют в JPEG с известным качеством и строят карту разниц. У вставленных и сгенерированных областей уровень ошибки отличается от остального кадра.

```bash
convert gen.png -quality 90 /tmp/re.jpg
compare gen.png /tmp/re.jpg -compose src /tmp/ela.png
```

Частотный анализ (2D-FFT) показывает регулярные пики у GAN и характерный «сетчатый» спектр у diffusion-моделей, тогда как у камеры доминирует широкополосный шум сенсора (PRNU). Готовые классификаторы дают вероятность, но использовать их как единственное доказательство нельзя: высок процент ложных срабатываний на реальных фото, особенно после сжатия и ресайза.

## Почему детекторы ошибаются и как писать вывод

Главная проблема — **base rate**. Если детектор ошибается в 5% случаев, а настоящих снимков в потоке 99%, то большинство «срабатываний» окажутся ложными. Поэтому вывод «сгенерировано» по одному инструменту недопустим — нужно несколько независимых признаков.

Собирай доказательства по уровням. Жёсткие: метаданные с именем генератора, C2PA с `trainedAlgorithmicMedia`, невидимый водяной знак. Сильные: согласованный спектр и аномалии ELA. Слабые: визуальные огрехи (руки, текст, освещение), нестандартные размеры. Формулировка должна отражать силу: «прямое указание на Stable Diffusion в метаданных» — высокая уверенность; «спектр и ELA нетипичны для камеры» — средняя; «странные руки» — низкая.

Фиксируй метод и версии инструментов (`exiftool 12.7`, конкретный детектор, параметры ELA) — это делает вывод воспроизводимым. И держи в голове этику: ложное обвинение автора в генерации так же вредно, как пропуск подделки, поэтому в сомнительных случаях пиши «признаки неоднозначны», а не «подделка».

## Разбор частотного спектра вручную

Спектр читают глазами, а не «средним значением». Построй логарифмическую карту амплитуд и отцентрируй её (`fftshift`), чтобы нулевая частота оказалась в центре.

```bash
python3 - <<'PY'
import numpy as np
from PIL import Image
g = np.array(Image.open("gen.png").convert("L"), dtype=float)
F = np.fft.fftshift(np.fft.fft2(g))
mag = np.log1p(np.abs(F))
Image.fromarray((255*mag/mag.max()).astype("uint8")).save("spectrum.png")
PY
```

У естественного фото энергия убывает плавно от центра к краям — это розовый шум сенсора. У генератора видны аномалии: яркие кольца (след апскейлинга), симметричные «кресты» или решётка (артефакт свёрточных слоёв). Периодические структуры в спектре означают периодический паттерн в пикселях — их не бывает у оптического изображения.

Проверяй гипотезу количественно: построй радиальный профиль спектра (усреднение по кольцам) и сравни с профилем заведомо настоящего фото. Разница формы профиля — объективный сигнал, который можно приложить к отчёту.

## Разбор кейса: настоящее фото, ошибочно принятое за ИИ

Практика показывает: ложные срабатывания — норма. Дано фото `portrait.jpg` с размытым фоном. Детектор выдаёт «92% AI». Проверяем по слоям. Метаданные: `exiftool` показывает `Make: Canon`, `Model: EOS R6`, полный набор EXIF и GPS — генераторы такое не пишут. Размер 6000×4000 — матрица камеры, не выход модели. Спектр: плавный розовый шум без решётки. C2PA отсутствует. Визуально: размытый фон (боке) детектор принимает за «несфокусированную» генерацию.

Вывод: это настоящее фото, а срабатывание — ложное. Три независимых жёстких/сильных признака (EXIF камеры, размер, спектр) перевешивают один слабый (визуальный). Урок: детектор-классификатор — вспомогательный сигнал, а не приговор, и решение принимается по совокупности с приоритетом жёстких признаков.

## Что мы теперь знаем

1. Метаданные генератора — прямое доказательство.
2. Размер выдаёт типовые выходы моделей.
3. Частотный спектр показывает регулярные структуры.
4. Визуальные детали — вспомогательный признак.
5. Вывод строится на совокупности и указывает уверенность.
