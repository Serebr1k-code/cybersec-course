## Вопрос, с которого всё начинается

Тебе дали файл `photo.jpg` и спросили: кто его сделал, где и чем? Новичок открывает картинку и смотрит на неё глазами.

Но почти каждый файл несёт «невидимую» информацию о том, **кто, когда и чем** его создал. Это **метаданные** — служебные поля внутри файла. Разберём их на одном фото.

## Наш пример: файл photo.jpg

У нас один объект — `photo.jpg`. Задача: вытащить максимум фактов, не глядя на само изображение. Главный инструмент — **exiftool**, он понимает сотни форматов.

## Шаг 1: смотрим всё, что есть в файле

```bash
exiftool photo.jpg
```

```
Make          : Apple
Model         : iPhone 14 Pro
Software      : 17.4.1
DateTimeOriginal : 2026:07:14 18:22:41
GPSLatitude   : 55 deg 45' 21.00" N
GPSLongitude  : 37 deg 37' 02.00" E
Artist        : Ivan Petrov
```

Одной командой мы узнали модель телефона, версию системы, время съёмки, имя автора и координаты. Это уже полноценный факт.

## Шаг 2: читаем GPS

GPS — самое ценное поле: точные координаты съёмки. Смотрим в десятичном виде, удобном для карт:

```bash
exiftool -n -GPSLatitude -GPSLongitude -GPSAltitude photo.jpg
```

```
GPSLatitude  : 55.755833
GPSLongitude : 37.617222
GPSAltitude  : 156 m
```

Соберём ссылку на карту:

```bash
exiftool -GPSPosition -p '$GPSLatitude,$GPSLongitude' photo.jpg | \
  awk -F, '{print "https://www.google.com/maps?q="$1","$2}'
```

```
https://www.google.com/maps?q=55.755833,37.617222
```

## Шаг 3: связываем фото с камерой

Некоторые поля уникальны для устройства. **SerialNumber** камеры одинаков на всех снимках одного аппарата, а `ImageUniqueID` — идентификатор конкретного кадра:

```bash
exiftool -Make -Model -SerialNumber -LensModel -r ./photos | sort | uniq -c
```

```
      7 Make: Apple, Model: iPhone 14 Pro, SerialNumber: F1XXXXXX
```

Семь фото с одним серийником — все они сняты одним телефоном. Это основа атрибуции: одно устройство — один источник.

## Шаг 4: thumbnail может выдать «до»

В JPEG часто встроен **thumbnail** — маленькая копия для предпросмотра. Она может остаться от **предыдущей** версии изображения. Извлечём её:

```bash
exiftool -b -ThumbnailImage photo.jpg > thumb.jpg
```

Если фото редактировали, на эскизе иногда видно то, что потом убрали: лишнего человека, номер, документ на фоне.

## Шаг 5: ищем скрытое за пределами метаданных

Метаданные — не единственное «дно» файла. Данные могут быть дописаны после конца изображения или спрятаны в комментариях:

```bash
strings photo.jpg | grep -iE 'password|secret|flag'
binwalk photo.jpg
```

`binwalk` находит встроенные и добавленные файлы, а `strings` вытаскивает читаемые строки. Иногда так находится архив, склеенный с картинкой (**polyglot** — файл, валидный сразу как два формата).

## Шаг 6: если файл — документ

Тот же принцип работает для документов, только метаданные лежат в другом месте. **DOCX и XLSX — это ZIP-архивы** с XML внутри:

```bash
unzip -p report.docx docProps/core.xml
```

```
<dc:creator>Ivan Petrov</dc:creator>
<cp:lastModifiedBy>hr-department</cp:lastModifiedBy>
```

Здесь утекают реальные ФИО авторов, внутренние пути (`C:\Users\<user>\...`) и названия шаблонов компании. А для PDF есть свои инструменты:

```bash
pdfinfo report.pdf
pdfdetach -list report.pdf
```

## Шаг 7: чистим свои файлы

Помни: **ты тоже** оставляешь метаданные — в скриншотах, документах, фото с телефона. Перед публикацией их удаляют:

```bash
exiftool -all= -overwrite_original photo.jpg
mat2 --inplace document.pdf
```

Команда `exiftool -all=` сносит все теги, а `mat2` чистит глубже, включая скрытые структуры документов. Важно: удаление метаданных необратимо — делай копию.

## exiftool: полезные флаги

Базовый вывод — только начало. Важные флаги:

```bash
exiftool -a -u -g1 photo.jpg        # все теги, включая дубли и неизвестные, по группам
exiftool -json photo.jpg            # машиночитаемый вывод
exiftool -csv -r ./photos > meta.csv  # рекурсивно в таблицу
exiftool -if '$GPSLatitude' -r ./photos  # только файлы с GPS
```

Ключ `-a` показывает **все** теги (включая продублированные), `-u` — нестандартные, `-g1` группирует по семействам. Без них часть полей теряется.

## Скрытые данные и контейнеры

Метаданные — не единственное «дно» файла:

```bash
strings -n 8 photo.jpg | grep -iE 'password|secret|flag'
binwalk photo.jpg
pdfdetach -list report.pdf
```

`binwalk` находит встроенные и дописанные файлы, `strings` вытаскивает читаемые строки, а `pdfdetach` показывает вложения PDF. Так достают архивы, склеенные с картинкой, и вложенные документы.

## Продвинутые форматы

| Формат | Что искать |
|---|---|
| JPEG | EXIF, XMP, IPTC, комментарии, thumbnail |
| PNG | чанки `tEXt`/`iTXt` (иногда с паролями) |
| HEIC | Apple-метаданные, глубина, GPS |
| MP4/MOV | GPS-трек, устройство, время создания |
| MP3/FLAC | ID3-теги, комментарии, encoder |
| SVG | комментарии, скрипты, метаданные редактора |

```bash
pngcheck -v image.png
exiftool -PNG:all image.png
```

## Частые ошибки

- **Смотреть только EXIF картинки** — забыть про XMP, IPTC и встроенный thumbnail.
- **Путать `DateTime` и `DateTimeOriginal`** — второе время съёмки, первое — правки.
- **Считать отсутствие метаданных безопасностью** — их мог удалить загрузчик соцсети, но шум сенсора остаётся.
- **Забыть про OPSEC своих файлов** — ваши собственные документы выдают вас.
- **Не пробовать несколько инструментов** — exiftool показывает не всё, нужны ещё binwalk и strings.

## Что мы теперь знаем

- Метаданные отвечают на вопросы «кто, когда, чем» — это быстрый источник фактов.
- GPS даёт точные координаты, а SerialNumber связывает фото с одним устройством.
- Встроенный thumbnail может показать предыдущую версию изображения.
- Данные бывают и за пределами метаданных: `binwalk` и `strings` ищут скрытое.
- DOCX и XLSX — это ZIP; автор лежит в `docProps/core.xml`.
- Метаданные легко подделать, поэтому они не являются доказательством сами по себе.
- Разные форматы хранят метаданные по-разному: у Office это `docProps`, у PDF — поля `/Author` и `/Producer`.
- Один и тот же инструмент exiftool работает и на атаку, и на защиту: им же чистят свои файлы.

## На что смотреть дальше

Разберись с разницей между `DateTime` (время правки) и `DateTimeOriginal` (время съёмки) — путаница здесь встречается постоянно. Изучи форматы XMP и IPTC: они хранят больше, чем EXIF. И посмотри, как forensic-анализ по шуму сенсора (**PRNU**) связывает серию снимков даже после удаления всех тегов.

## Разбор кейса: thumbnail выдаёт правку

EXIF — не единственное место, где остаются следы. В JPEG часто хранится **встроенный thumbnail** — маленькая превьюшка, записанная камерой или редактором. И вот ключевая деталь: если фото отредактировали (обрезали, замазали), thumbnail может остаться от **исходного** кадра. Тогда в превью видно то, что автор хотел скрыть.

Разберём, как это найти. Сначала смотрим все метаданные: `exiftool photo.jpg`. Если есть `ThumbnailImage`, извлекаем его: `exiftool -b -ThumbnailImage photo.jpg > thumb.jpg`. Затем сравниваем с основным изображением. Расхождение — сигнал: правку делали после сохранения превью.

Второй приём — **сравнение размеров**. Основной файл 4000×3000, а превью — 160×120 от другого кадра. Если композиция превью не совпадает с основным, значит, был кроп. Иногда в превью видна часть, которую обрезали: край стола, лицо, вывеска. Третий приём — **поиск «хвостов»**. После JPEG-изображения может лежать второй файл: приклеенный архив, ещё одно фото, ZIP с данными. Их находят по сигнатурам (`FFD8` для JPEG, `PK` для ZIP) или инструментом `binwalk`. Итог: метаданные — это не только поля, но и «мусор» вокруг изображения. Новичок смотрит только на видимую картинку, а настоящие находки лежат рядом.

## Если не сработало

**Thumbnail отсутствует.** Многие редакторы его не пишут. Тогда ищи «хвосты» через binwalk и строки через `strings photo.jpg | grep -i http`.

**Данные очищены.** Сервис мог прогнать файл через «оптимизатор». Ищи оригинал в другом источнике.

**Несколько изображений в файле.** Форматы вроде HEIC или многослойный TIFF содержат несколько кадров. `exiftool -a` покажет все.

**Подозрение на подделку, но метаданные чистые.** Отсутствие следов не значит «оригинал». Суди по визуальным несоответствиям.

## Частые вопросы

**Чем EXIF отличается от IPTC и XMP?** Это разные наборы метаданных: EXIF — камера, IPTC — редакционные данные, XMP — расширяемые поля Adobe. Все три могут содержать информацию.

**Что такое binwalk?** Инструмент для поиска вложенных данных и сигнатур внутри файла. Полезен для «хвостов».

**Всегда ли thumbnail совпадает?** Нет, при обычном сохранении он пересчитывается. Расхождение — именно признак правки.

## Мини-практика: пакетная очистка

Если ты публикуешь файлы от лица организации, метаданные надо чистить пачкой. Для одной папки: `exiftool -all= -overwrite_original -r photos/`. Флаг `-all=` удаляет все метаданные, `-r` рекурсивно обходит подпапки. Проверь результат: `exiftool photo.jpg` должен показать пустой список. Отдельно проверь PDF и Office: там метаданные лежат в свойствах документа (автор, организация, история правок) и чистятся своими средствами. Заведи привычку: перед любой публикацией — прогон очистки и проверка. Это простейшая гигиена, которая закрывает целый класс утечек.

## Куда дальше

Мы научились вытаскивать факты из метаданных. В следующем уроке — **глубокий анализ EXIF**: разберём поля детальнее, включая компас, высоту и цепочки редактирования. А пока главное запомни: файл — это не только то, что видно на картинке.

## Где пригодится

- **CTF:** категории OSINT и Forensics — флаг часто в метаданных.
- **Bug bounty:** утёкшие документы выдают имена, пути и версии ПО.
- **Пентест:** реконструкция внутренней инфраструктуры по документам.
- **OPSEC:** очистка своих артефактов перед публикацией.
