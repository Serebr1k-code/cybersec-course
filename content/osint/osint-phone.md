Номер телефона — уникальный идентификатор человека, привязанный к мессенджерам, банкам и соцсетям. Правильно нормализованный номер превращается в **ключ** к целому профилю. В этом уроке — пошаговый маршрут от номера к личности и связям, с жёсткими этическими рамками.

## Нормализация номера

Первое — привести номер к формату **E.164**: `+<код страны><национальный номер>` без пробелов и дефисов.

```
+7 999 123-45-67  →  +79991234567
```

Инструмент — библиотека `phonenumbers` (Python):

```python
import phonenumbers
n = phonenumbers.parse("8 999 123-45-67", "RU")
print(phonenumbers.format_number(n, phonenumbers.PhoneNumberFormat.E164))
print(phonenumbers.is_valid_number(n))
print(phonenumbers.region_code_for_number(n))
```

Из номера сразу извлекается **код страны и оператор**. Если номер валиден и принадлежит диапазону — переходите к обогащению; если нет — вероятно, это виртуальный или «одноразовый» номер.

## Что даёт номер

| Источник | Что получаем |
|---|---|
| Оператор (по префиксу) | регион, оператор, тип (моб./стационар) |
| Мессенджеры (WhatsApp/Telegram/Signal) | аватар, имя, наличие аккаунта |
| Соцсети (VK, OK, Instagram) | привязка профиля, поиск по номеру |
| Truecaller-подобные сервисы | имя, метки спама (осторожно) |
| Утечки | привязка к email, ФИО, адресу |
| Google dorks | упоминания номера на сайтах/объявлениях |

## Шаг 1. Определить оператора и регион

- Онлайн-сервисы и библиотеки (numlookup, `phonenumbers`).
- Локальные базы префиксов (DEF-коды, диапазоны операторов).

Результат: `+7999...` → Москва/мобильный, оператор X.

## Шаг 2. Проверить мессенджеры

- **Telegram**: попробуйте найти по номеру (контакты) — покажет наличие аккаунта и username.
- **WhatsApp**: `wa.me/<номер>` откроет профиль, если номер зарегистрирован.
- **Signal**: аналогично через контакты.

Это пассивно-активные действия: они могут создать уведомление у владельца. Учитывайте OPSEC.

## Шаг 3. Поиск в соцсетях и на сайтах

- **VK/OK**: «восстановление пароля» / поиск по номеру показывает частично скрытый профиль (иногда).
- **Google dorks**:

```
"+79991234567"
"89991234567"
"79991234567" -site:operator.ru
```

Объявления (Avito, авто-форумы), резюме, доски — часто содержат номер и ФИО.

## Шаг 4. Утечки

Проверяйте номер по базам утечек (HIBP для email, DeHashed/IntelX для телефона — только поиск, легальность!). Часто номер связывает ФИО, email и адрес.

Связка: **номер → email → username → соцсети** (см. урок про корреляцию).

## Шаг 5. Обогащение

- Обратный поиск по номеру в **мессенджер-каталогах** и **спам-базах**.
- Поиск в **госреестрах** (для юрлиц номер телефона часто указан в ЕГРЮЛ).
- **Whois** доменов, где номер в контактах.

## Реестры и юридические лица

Номер телефона — частый «мостик» от человека к организации:

- **ЕГРЮЛ/ЕГРИП** — телефоны в карточке компании (RU).
- **OpenCorporates / Companies House** — для зарубежных юрлиц.
- **Госзакупки** — контакты поставщиков.
- **Сайт компании** — контакты отдела продаж часто совпадают с личными номерами сотрудников.

Совпадение номера из объявления и из реестра — сильный сигнал связи человека с фирмой.

## Операторы, диапазоны и перенос номера

Префикс даёт оператора, но номера **переносятся** (MNP). Поэтому:

- Первичный оператор определяется по диапазону (DEF-код).
- Текущий — может отличаться (перенос).
- Виртуальные номера (VoIP) и «одноразовые» сервисы искажают картину.
- Проверяйте HLR-lookup (легально — для бизнес-верификации), а не только префикс.

```python
import phonenumbers
from phonenumbers import carrier, geocoder
n = phonenumbers.parse("+79165551122")
print(carrier.name_for_number(n, "ru"), geocoder.description_for_number(n, "ru"))
```

## Поиск по объявлениям и доскам

Номер телефона часто публикуется в открытых объявлениях:

```text
"+79991234567"
"89991234567"
"79991234567" (avito OR auto OR продам)
```

Доски (Avito, авто-форумы, доски услуг), резюме (hh.ru), госзакупки — всё это даёт ФИО, город и связи. Комбинируйте с reverse image по фото объявления.

## Мошенничество и защита (blue team)

- **Спам-базы** (Truecaller, GetContact) показывают метки, но могут ошибаться.
- **Симплекс-подмена (spoofing)** номера — распространённый приём мошенников.
- **SIM-swap** — перехват номера через оператора (социальная инженерия).
- **Защита**: 2FA через приложение (не SMS), кодовые слова у оператора, мониторинг утечек.

## Разобранный пример

Дан номер `8 916 555-11-22`.

1. Нормализуем: `+79165551122` (Россия, мобильный, оператор по префиксу 916).
2. Telegram: номер зарегистрирован, username `@ivan_dev`.
3. Google: `"+79165551122"` → резюме на hh.ru с ФИО «Иван ...».
4. Утечка: связка с email `ivan.dev@...`.
5. Коррелируем email → GitHub → подтверждаем личность.

Из одного номера — целый профиль.

## Этические и юридические границы

- Поиск по **открытым** источникам допустим.
- Создание фейковых аккаунтов для доступа к данным человека — серая зона.
- Сбор и хранение персональных данных регулируются законом (GDPR, 152-ФЗ).
- Никогда не используйте номер для преследования, спама или мошенничества.

## Инструменты и флаги

| Инструмент | Что делает |
|---|---|
| `phonenumbers` (Python) | нормализация, валидация, оператор, регион |
| libphonenumber (CLI) | то же из терминала |
| `wa.me/<номер>` | проверка WhatsApp |
| HIBP / DeHashed / IntelX | утечки по номеру/email |

## Частые ошибки

- **Работать с ненормализованным номером** → ложные срабатывания.
- **Доверять Truecaller-меткам** без проверки (люди ошибаются).
- **Проверять мессенджеры, не думая об OPSEC** (владелец видит запрос).
- **Игнорировать виртуальные/одноразовые** номера.
- **Забыть про перенос номера** между операторами (префикс устаревает).
- **Не документировать источники** — вывод нельзя проверить.

## Что делать дальше / решение

- **Нужна личность** → нормализуйте → мессенджеры → dorks по номеру → резюме/объявления.
- **Нужна связь с организацией** → реестры юрлиц и госзакупки по номеру.
- **Нужны утечки** → HIBP/DeHashed, связать с email.
- **Нужна защита (blue team)** → SIM-swap, spoofing, 2FA без SMS.

## Каталоги мессенджеров и обратный поиск

Помимо прямой проверки, существуют агрегаторы, где номер уже связан с профилем:

- **Спам-базы** (Truecaller, GetContact, Sync.me) — показывают имя и метки, но данные вводят пользователи и часто устарели.
- **Каталоги Telegram-ботов** — проверка номера на регистрацию и username.
- **Поиск по объявлениям** — `dork` по номеру находит профиль продавца.

Ключевое правило: любой результат из агрегатора — **гипотеза**, а не факт. Подтверждайте вторым независимым источником (сайт компании, резюме, реестр).

## HLR, MNP и виртуальные номера

Оператор «по префиксу» — только первое приближение. Точная атрибуция требует:

- **HLR-lookup** — запрос к домашнему регистру оператора (доступен легально для бизнес-верификации): показывает текущую сеть, статус, роуминг.
- **MNP-база** — факт переноса номера к другому оператору; префикс при этом остаётся старым.
- **VoIP-диапазоны** — номера, выданные телефонии-провайдерам; за ними часто стоят колл-центры и боты.
- **Одноразовые сервисы** — номера для регистрации, которые уже «сгорели»; ими пользовались сотни людей.

Для CTF чаще всего достаточно префикса; для расследований — HLR/MNP обязательны, иначе легко приписать номер не тому оператору.

## Документирование и верификация

Каждый шаг фиксируйте в таблицу: **номер → источник → что найдено → дата → статус (подтверждено/гипотеза)**. Номер телефона — персональные данные, поэтому:

- храните минимум, необходимый для задачи;
- указывайте дату снятия (данные меняются);
- отделяйте факт от вывода;
- в отчёте — только публичные источники.

Полезные форматы для дорков (один номер — много написаний):

```text
"+79991234567"  "79991234567"  "89991234567"
"8 (999) 123-45-67"  "8-999-1234567"
```

Разные площадки хранят номер по-разному, поэтому перебирайте все варианты написания, иначе пропустите половину упоминаний.

## Международный контекст и форматы

При работе с зарубежными номерами важно учитывать различия:

- **Код страны** задаёт всё: `+1` (US/CA, NANP), `+44` (UK), `+49` (DE), `+380` (UA).
- **Формат записи** различается: в US — `(555) 123-4567`, в EU — национальные префиксы `0…`.
- **`phonenumbers`** корректно парсит номер только с указанием региона: `parse("020 7946 0000", "GB")`.
- **Переносимость** между операторами в ЕС закреплена правилами; в других регионах — по-разному.

```python
import phonenumbers
for raw, reg in [("020 7946 0000","GB"), ("(202) 555-0123","US")]:
    n = phonenumbers.parse(raw, reg)
    print(phonenumbers.format_number(n, phonenumbers.PhoneNumberFormat.INTERNATIONAL))
```

Неверный регион при парсинге → неверный E.164 → ложные срабатывания во всех последующих источниках.

## Что делать при отсутствии данных

Не всегда номер «раскрывается». Если после чек-листа пусто:

- **Виртуальный/одноразовый номер** — за ним нет личности; фиксируйте это как вывод.
- **Скрытый профиль** — номер есть, но аккаунты закрыты; попробуйте обогатить по email.
- **Не тот регион** — перепроверьте парсинг (частая причина ложных нулей).
- **Свежий номер** — ещё не попал в утечки и объявления; отложите и повторите позже.

Отрицательный результат тоже результат: «номер не привязан к публичным профилям на дату X» — валидный вывод для отчёта.
