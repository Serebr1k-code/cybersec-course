В потоке новостей и соцсетей большая часть контента — искажённая или фальшивая. Верификация — ключевой навык OSINT: не «найти», а «подтвердить». Это дисциплина из проверяемых шагов: происхождение, метаданные, гео/время, кросс-подтверждение и анализ мотивов.

В этом уроке — методика проверки утверждений и медиа, инструменты, разобранные кейсы и типичные ошибки.

## Теория: уровни верификации

- **Источник (provenance):** кто первым опубликовал, где оригинал, есть ли перепосты.
- **Содержание:** согласованность фактов, логики, деталей.
- **Метаданные:** EXIF, дата, устройство (легко подделываются — не доказательство).
- **Геолокация:** совпадает ли место с заявленным.
- **Хронолокация:** совпадает ли время.
- **Кросс-подтверждение:** ≥2 независимых источника.
- **Мотив:** кому выгодно, есть ли паттерн кампании.

Ключевой принцип: **факт** (что видно на медиа) и **вывод** (что это значит) — разные вещи. Их надо описывать отдельно, чтобы не выдать интерпретацию за доказательство.

## Шаг 1: происхождение (provenance)

Ищем **самое раннее** появление контента. Обратный поиск изображений (TinEye сортирует по дате), поиск видео по кадрам, поиск текста по цитатам.

```bash
# извлечь кадры из видео для поиска
ffmpeg -i video.mp4 -vf fps=1/5 frames/%04d.jpg
# затем каждый кадр — в обратный поиск
```

Если фото/видео старше заявленного события — это переиспользование. Если найдено в стоке — не оригинал.

## Шаг 2: метаданные

```bash
exiftool image.jpg
# Make, Model, DateTimeOriginal, GPS, Software
# проверить, редактировалось ли
exiftool -Software -ModifyDate image.jpg
# медиа-форензика
```

Но помните: метаданные тривиально подделываются и удаляются. Они — **подсказка**, а не доказательство. Отсутствие EXIF тоже информативно (соцсети вырезают его при загрузке).

## Шаг 3: геолокация и хронолокация

- **Геолокация:** сопоставить объекты на фото с картами/Street View. Ориентиры, вывески, архитектура, растительность.
- **Хронолокация:** тени, положение солнца, погода, сезон. По длине/направлению тени и известной дате можно вычислить время и широту (см. соответствующие уроки).

```bash
# проверить погоду на дату/место (исторические архивы)
# например, meteostat / wunderground history
```

Несоответствие погоды/тени заявленным дате и месту — сильный признак фейка.

## Шаг 4: кросс-подтверждение

Правило: **≥2 независимых источника**. «Независимых» — значит не перепечатки одного и того же. Если все ссылаются друг на друга — это один источник.

- Ищите первоисточник, а не агрегаторы.
- Проверяйте, не являются ли «разные» аккаунты одним sock puppet.
- Сверяйте официальные заявления, реестры, данные.

## Шаг 5: анализ мотива

- Кому выгодна публикация?
- Есть ли паттерн (одновременные публикации, одинаковые формулировки)?
- Совпадает ли с известными кампаниями дезинформации?
- Есть ли эмоциональный «крючок» (сенсация, страх, срочность)?

## Инструменты

| Инструмент | Назначение |
|---|---|
| InVID / WeVerify | разбор видео покадрово, обратный поиск, метаданные |
| Forensically | анализ изображений (ELA, клонирование, шум) |
| FotoForensics | error level analysis, детект манипуляций |
| TinEye | самое раннее появление изображения |
| Yandex/Google | обратный поиск, OCR |
| exiftool | метаданные |
| SunCalc | положение солнца по дате/месту (хронолокация) |
| Meteostat | историческая погода |

## Разобранный пример: проверка вирусного фото

Заявлено: «наводнение в городе X сегодня».

1. **Происхождение:** TinEye → фото найдено в публикации 2019 года. Уже подозрительно.
2. **Метаданные:** EXIF отсутствует (загружено через соцсеть) — не опора.
3. **Геолокация:** объекты на фото не совпадают с городом X (другая архитектура).
4. **Хронолокация:** тени не соответствуют сезону.
5. **Кросс-подтверждение:** ни один официальный источник не сообщает о наводнении.
6. **Вывод:** фото старое и из другого места — дезинформация.

## Разобранный пример: проверка видео

1. `ffmpeg` → кадры → обратный поиск: находим исходное видео на другом канале годом раньше.
2. InVID показывает метаданные и возможные монтажные склейки.
3. Аудио: анализ на монтаж (паузы, несоответствие звука).
4. Вывод: видео переиспользовано с другим комментарием.

## Edge cases и подводные камни

- **Соцсети вырезают EXIF** — не считайте отсутствие метаданных доказательством фейка.
- **Глубокие фейки (deepfake):** визуальные артефакты, несоответствие мимики/звука; отдельный набор инструментов.
- **Перепечатки** создают иллюзию «множества источников».
- **Датировка поста ≠ дата события** — платформа может показывать дату загрузки, а не съёмки.
- **Языковой сдвиг:** автоматический перевод искажает формулировки.
- **Контекст:** одно и то же медиа может быть правдой в одном контексте и фейком в другом.

## Что дальше / решение

Методика верификации — это последовательность шагов, а не один инструмент: происхождение → метаданные → гео/время → кросс-подтверждение → мотив. Практика: возьмите вирусное фото и проведите все шаги, документируя каждый вывод отдельно от факта. Цель — не «поверить/не поверить», а показать проверяемый путь к выводу.

## Reference-таблица: признаки манипуляции медиа

| Признак | Что проверять | Инструмент |
|---|---|---|
| Разные уровни сжатия | ELA-анализ | Forensically, FotoForensics |
| Клонирование участков | копипаст-детект | Forensically (clone detection) |
| Несогласованные тени | геометрия света | SunCalc + визуальный анализ |
| Монтажные склейки видео | покадровый анализ | InVID/WeVerify, ffmpeg |
| Несоответствие аудио | спектрограмма | Audacity, Sonic Visualiser |
| Подделка метаданных | несоответствие дат/устройств | exiftool |

## Reference-таблица: уровни уверенности

| Уровень | Что значит | Как формулировать |
|---|---|---|
| Подтверждено | ≥2 независимых источника + проверка | «подтверждено» |
| Вероятно | 1 сильный источник, согласуется | «вероятно» |
| Возможно | косвенные признаки | «возможно» |
| Не подтверждено | нет данных | «не подтверждено» |
| Опровергнуто | найдено противоречие | «опровергнуто» |

Язык отчёта должен отражать уровень уверенности — не смешивайте «возможно» и «подтверждено».

## Чек-лист верификации

1. Найти первоисточник и его дату (обратный поиск, TinEye).
2. Извлечь и оценить метаданные (`exiftool`) — как подсказку, не как факт.
3. Проверить геолокацию по объектам и картам.
4. Проверить хронолокацию (тени, погода, сезон).
5. Найти ≥2 независимых подтверждения.
6. Проанализировать мотив и паттерн распространения.
7. Отдельно описать факт и вывод; указать уровень уверенности.
8. Задокументировать каждый шаг со ссылкой на источник.

## Разобранный пример: дезинформационная кампания

Задача — понять, является ли всплеск однотипных сообщений организованной кампанией.

1. Собираем все публикации по теме за период (ключевые слова, хэштеги).
2. Строим временную шкалу: кто опубликовал первым, как распространялось.
3. Проверяем аккаунты: возраст, активность, подписчики, историю. Молодые аккаунты с одинаковым стилем — признак sock puppets.
4. Сравниваем формулировки: идентичные фразы в разных аккаунтах — признак координированной кампании (copy-paste).
5. Проверяем медиа: обратный поиск, метаданные, гео/время.
6. Анализируем мотив: кому выгодно, что продвигается, какие ссылки.
7. Вывод: набор индикаторов (синхронность, шаблонность, свежие аккаунты, непроверяемые медиа) указывает на организованную кампанию.

Такой разбор превращает «много постов в интернете» в проверяемую гипотезу о координированной активности.

## Связка с другими ветками

- Обратный поиск изображений → происхождение медиа.
- EXIF/метаданные → устройство, дата, возможный GPS.
- Геолокация и хронолокация → проверка места и времени.
- Соцсети и корреляция → связанные аккаунты и люди.
- Email-заголовки → проверка подлинности писем (SPF/DKIM/DMARC).

Верификация — это узел, который связывает все остальные ветки OSINT: каждая из них поставляет один проверяемый факт, а дисциплина верификации собирает их в обоснованный вывод. Без неё OSINT превращается в набор непроверенных скриншотов.

## Типовые сценарии дезинформации

Разберём частые приёмы, которые нужно распознавать:

- **Переиспользование старого фото** под новым событием → reverse image + дата оригинала.
- **Обрезка контекста** → ищите полный кадр/видео.
- **Подмена подписи** → сверяйте с первоисточником.
- **Сфабрикованный скриншот** → проверьте шрифты, выравнивание, метаданные, отсутствие оригинала.
- **Дублирование через ботов** → анализ аккаунтов-распространителей.
- **ИИ-генерация** → артефакты (лишние пальцы, текст-абракадабра, неестественные тени) + детекторы (с осторожностью).
- **Ложная атрибуция** → сравните с официальными заявлениями сторон.

Каждый приём ломается своим слоем проверки: provenance, метаданные, гео, хроно, кросс-подтверждение. Универсального детектора нет — есть дисциплина из независимых шагов.

## Работа с ИИ-контентом

Синтетические изображения и видео требуют особой осторожности:

- **Детекторы ИИ ненадёжны** — не делайте вывод только по ним.
- **Обратный поиск** часто бесполезен (фото «новое»), но иногда находит исходный промпт/шаблон.
- **Физика:** тени, отражения, перспектива часто «ломаются» в генерациях.
- **Текст:** мелкий текст и вывески — самое слабое место генераторов.
- **Метаданные:** часто отсутствуют или содержат следы генератора.

Вердикт «вероятно синтетика» ставится по совокупности физических несоответствий, а не по одному признаку.

## Работа с очевидцами и открытыми заявлениями

Не вся верификация — про медиа. Утверждения людей проверяются так же:

- **Сверьте с официальными источниками:** пресс-релизы, реестры, судебные документы.
- **Проверьте квалификацию спикера:** действительно ли он там, где заявляет.
- **Ищите противоречия:** заявление против более раннего заявления того же лица.
- **Контекст времени:** сказанное вчера может не относиться к сегодняшнему событию.
- **Независимость:** связан ли «очевидец» с одной из сторон конфликта.

Правило то же: минимум два независимых подтверждения, явная оценка уверенности и зафиксированный источник.

## Где пригодится

- **CTF (OSINT):** отличить подделку от подлинника в задаче.
- **Расследования:** проверка доказательств и выявление дезинформации.
- **Threat intel:** оценка достоверности источников и кампаний.
- **Работа:** фактчекинг, медиаграмотность, верификация контента в SOC/IR.
