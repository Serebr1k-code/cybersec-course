Фотофорензика отвечает на вопрос: **подлинное ли изображение?** Было ли оно отредактировано, вставлено ли что-то, пересохранено ли, снято ли на камеру или сгенерировано. В эпоху дезинформации это ключевой навык: одно фото может быть «доказательством» или подделкой. Этот урок — о технических методах: Error Level Analysis (ELA), анализ шума, JPEG-артефактов и клонирования, а также о метаданных.

## Теория: как изображение хранит следы редактирования

Формат JPEG устроен так, что **при каждом сохранении теряет данные** (lossy-сжатие). Это ключ к форензике:
- **Пересохранение** оставляет характерный уровень ошибок.
- **Вставка фрагмента** создаёт область с иным «уровнем ошибок», чем фон.
- **Клонирование** (copy-move) оставляет повторяющиеся блоки.
- **Шум сенсора** (PRNU) уникален для камеры; вставки его не имеют.

Форензика ищет **несоответствия**: области, отличающиеся по сжатию, шуму, освещению, перспективе, теням.

## Error Level Analysis (ELA)

ELA показывает разницу между исходным JPEG и его пересжатием. Однородные по сжатию области выглядят одинаково; вставки «вспыхивают».

Инструмент `fotoforensics.com` — онлайн. Локально через ImageMagick:

```bash
# ELA: пересжать в JPEG с известным качеством и вычесть
convert input.jpg -quality 90 temp.jpg
compare input.jpg temp.jpg -compose src ela.png
convert ela.png -auto-level ela_enhanced.png
```

Интерпретация:
- **равномерный фон** — изображение однородно (не редактировалось);
- **яркая область** — фрагмент с другим уровнем сжатия (возможная вставка);
- **контуры по краям объектов** — норма для JPEG;
- **шумная текстура** — сильное сжатие/скриншот.

ELA — не доказательство, а **указатель**: яркая область требует объяснения, а не автоматически означает подделку.

## Анализ шума

Шум сенсора различается по областям, если фото составное. Инструмент `Ghiro` и плагин `Forensically`. Проверка однородности шума:

```bash
# извлечь высокочастотный шум
convert input.jpg -colorspace Gray -statistic standard-deviation 3x3 -normalize noise.png
```

Неоднородность шума в разных областях → возможно составное изображение. Также смотрим **сенсорный шум** в тёмных и светлых участках: у вставки он не совпадает.

## JPEG-артефакты и квантование

JPEG разбивает изображение на блоки 8×8 и применяет квантование. Если изображение редактировали, **сетка блоков может смещаться** в области вставки. Инструмент `jpegio` и `jpegdimensions`:

```bash
jpegio -i input.jpg     # таблицы квантования, сетка блоков
```

Двойное сжатие (double compression) с разными таблицами — сильный признак редактирования и пересохранения.

## Клонирование (copy-move)

Область, скопированная из другого места того же фото, имеет **идентичный шум/текстуру**. Поиск дублей: `Forensically` (Clone Detection), `FotoForensics`, `ImageForensics`. Локально — через корреляцию блоков:

```bash
# пример: поиск повторяющихся областей (упрощённо, через autocorrelation)
python3 - <<'EOF'
from PIL import Image
import numpy as np
im = np.asarray(Image.open("input.jpg").convert("L"), dtype=float)
# корреляция блока с остальным изображением — псевдокод
print("используйте специализированный инструмент (Forensically Clone Detection)")
EOF
```

Клонирование выдают: повторяющиеся облака, одинаковые пятна, дублированные детали.

## Метаданные: первое, что смотрим

```bash
exiftool -a -u -g1 input.jpg
```

Полезное:
- **Software** — редактор (Photoshop, GIMP, Snapseed). Если «Photoshop» — фото обрабатывали.
- **ModifyDate / CreateDate** — когда правили.
- **GPS** — координаты (но легко подделать).
- **Camera Make/Model, Serial** — камера.
- **Thumbnail** — миниатюра иногда показывает **оригинал до обрезки**!

Извлечение встроенной миниатюры:

```bash
exiftool -b -ThumbnailImage input.jpg > thumb.jpg
```

Если миниатюра отличается от основного изображения — фото обрезали или отредактировали.

## Разобранный пример: подделка или нет?

Дано: фото «протеста» из соцсети.

Шаг 1 — метаданные:

```bash
exiftool -a -u -g1 protest.jpg | grep -iE 'software|modify|camera|gps'
# Software: Adobe Photoshop 24.0
# ModifyDate: 2026:10:05 12:30:00
```

Photoshop + поздняя дата правки → фото редактировали.

Шаг 2 — ELA:

```
Яркая однородная область в центре плаката → вставленный текст.
```

Шаг 3 — миниатюра:

```bash
exiftool -b -ThumbnailImage protest.jpg > thumb.jpg
compare thumb.jpg protest.jpg -compose src diff.png
```

Миниатюра не содержит плаката → текст добавлен после съёмки.

Шаг 4 — вывод: фото подлинное, но плакат — вставка. Как «доказательство» оно не годится.

## Таблица: метод → что находит

| Метод | Что выявляет |
|-------|--------------|
| EXIF | редактор, даты, камера, GPS |
| ELA | области с иным сжатием (вставки) |
| Шум | неоднородность (составные фото) |
| JPEG-блоки | двойное сжатие, смещение сетки |
| Клонирование | copy-move дубли |
| Миниатюра | оригинал до обрезки |
| Перспектива/тени | физическая нестыковка |

## Ошибки и подводные камни

- **Считать ELA доказательством.** Яркая область — гипотеза, а не приговор.
- **Забывать про соцсети.** Instagram/Telegram пересохраняют фото — метаданные и ELA «шумят».
- **Игнорировать скриншоты.** У скриншотов нет сенсорного шума и камеры.
- **Путать обрезку с подделкой.** Обрезка — не манипуляция содержания.
- **Доверять GPS.** Координаты подделываются тривиально.
- **Оценивать одно фото в вакууме.** Сравнивайте с другими кадрами серии.

## Что дальше / решение

Фотофорензика — техническая проверка подлинности. Дальше: **deepfake** (`osint-deepfake`) для синтетических медиа, **инструменты геолокации** (`osint-geo-tools`) для определения места, **верификация** (`osint-verification`) для оформления вывода. Итог: ELA + шум + JPEG + метаданные + миниатюра дают техническую картину; окончательный вывод всегда сочетает технику и контекст.

## Форензика через exiftool: полный разбор

`exiftool` — главный инструмент. Разбор по группам:

```bash
exiftool -a -u -g1 image.jpg
```

Группы и что в них важно:
- **EXIF** — камера, выдержка, ISO, GPS, дата.
- **XMP** — история редактирования (Lightroom, Photoshop), рейтинг, метки.
- **IPTC** — автор, копирайт, подпись.
- **MakerNotes** — проприетарные данные камеры (серийный номер!).
- **ICC_Profile** — цветовой профиль (признак редактора).
- **Composite** — вычисленные поля (например, `ImageSize`).

Удаление метаданных проверяется так:

```bash
exiftool -all= -o clean.jpg image.jpg    # стереть всё
exiftool clean.jpg | grep -iE 'software|camera|gps'   # пусто = вычищено
```

Наличие **серийного номера камеры** в MakerNotes связывает все фото, снятые на эту камеру, — мощный сигнал атрибуции.

## Обнаружение вставок через сравнение областей

Практический метод: разбить фото на области и сравнить их статистику шума/сжатия.

```bash
# нарезать на блоки
convert image.jpg -crop 4x4@ +repage tile_%02d.png
# оценить "шумность" каждого блока
for t in tile_*.png; do
  echo -n "$t "; convert "$t" -format "%[fx:standard_deviation]" info:; echo
done
```

Блоки с аномально низким/высоким отклонением — кандидаты на вставку. Сопоставьте с ELA-картой.

## Перспектива, тени и освещение

Технически сложный, но надёжный класс признаков:
- **Точки схода** (vanishing points) — линии перспективы должны сходиться; вставка ломает геометрию.
- **Направление теней** — от одного источника света тени параллельны; вставка даёт иное направление.
- **Освещение** — цвет и интенсивность света на объекте должны совпадать с фоном.

Инструменты: `Forensically` (perspective/lighting), ручная проверка в графическом редакторе.

## Формат-специфичные следы

| Формат | Особенности |
|--------|-------------|
| JPEG | блоки 8×8, квантование, double-compression |
| PNG | нет потерь; анализируется палитра, tEXt-чанки |
| HEIC/AVIF | современные, свои метаданные |
| GIF | палитра, кадры |
| RAW | оригинал сенсора, полные метаданные |

PNG-часто хранит текст в чанках `tEXt`/`iTXt` — проверяйте:

```bash
strings image.png | grep -iE 'comment|software|flag'
```

| Инструмент | Назначение |
|-----------|-----------|
| `exiftool` | метаданные всех форматов |
| `fotoforensics.com` | ELA онлайн |
| `Forensically` | ELA, шум, клоны, перспектива |

Комбинируйте: ELA показывает области, шум — составность, метаданные — историю. Ни один инструмент не даёт приговор в одиночку.

## Метаданные и приватность

Метаданные опасны для тех, кто публикует фото:
- **GPS** выдаёт дом;
- **серийный номер камеры** связывает фото;
- **имя автора** в IPTC/XMP раскрывает личность;
- **история редактирования** показывает правки.

```bash
# проверить, что утечёт из вашего фото
exiftool -a -u -g1 photo.jpg | grep -iE 'gps|author|creator|software|serial'
# очистить
exiftool -all= -overwrite_original photo.jpg
```

Для OSINT это двойной урок: уметь читать метаданные и уметь их прятать.

## Форензика как доказательство

Для отчёта/суда важна методология: фиксируйте хэш файла, последовательность действий, инструменты и версии. Хэш доказывает неизменность:

```bash
sha256sum evidence.jpg | tee evidence.sha256
```

Вывод формулируйте как «признаки редактирования (ELA-аномалия + редактор в EXIF)», а не «фото поддельное» — окончательный вердикт даёт эксперт с полным доступом к оригиналу.
