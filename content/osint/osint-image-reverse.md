Обратный поиск изображений отвечает на вопрос «**где это фото уже встречалось**». Это ключ к поиску источника, оригинального качества, связанных профилей и (вместе с геолокацией) места съёмки. В CTF и в расследованиях это один из самых быстрых способов деанонимизации и верификации.

В этом уроке — движки, подготовка картинки, разобранные сценарии, edge cases и связка с метаданными.

## Движки обратного поиска

| Движок | Сильная сторона |
|---|---|
| **Yandex Images** | Лучший для лиц, Восточной Европы, кропов |
| **Google Lens** | Точный подбор похожих, товары, текст (OCR) |
| **Bing Visual Search** | Хорош для товаров и локаций |
| **TinEye** | Старейший, точные совпадения, сортировка по дате |
| **Baidu** | Китайский сегмент |
| **PimEyes** | Поиск по лицу (осторожно с легальностью) |
| **Karma Decay** | Поиск постов на Reddit |
| **SauceNAO / IQDB** | Аниме/арт, поиск оригинала |

Загружать можно файл или URL. Ключевой приём — **кроп**: обрежьте лишнее, оставьте характерный объект (лицо, здание, вывеску).

## Подготовка изображения

1. **Определите, что искать**: лицо → Yandex/PimEyes; здание → Bing/Google; текст → Google Lens (OCR); арт → SauceNAO.
2. **Кроп**: уберите фон, оставьте характерный объект.
3. **Улучшите**: повысьте резкость/контраст, если фото размытое.
4. **Меняйте угол/масштаб**: иногда поиск работает только на конкретном кропе.
5. **Убирайте водяные знаки/подписи**, если они мешают (но помните: они сами — источник).
6. **Попробуйте разные форматы**: JPEG→PNG, поворот на 90°, зеркало.

```bash
# быстрая подготовка кропа
convert original.jpg -crop 400x400+120+80 +repage -resize 800x800 crop.jpg
# повышение резкости
convert blurry.jpg -sharpen 0x1 sharp.jpg
```

## Что можно найти

- **Оригинал в высоком разрешении** (у кропа есть источник).
- **Другие посты** того же фото → профили и контекст.
- **Дату первой публикации** (TinEye сортирует по времени) — помогает установить, кто оригинал.
- **Локацию**: похожие фото того же места → название.
- **Фейк**: если фото всплывает в несвязанных новостях — вероятно, сток/чужая картинка.
- **Товар**: Google Lens находит модель и магазины по фото.

## Работа с текстом и вывесками

- **Google Lens** распознаёт текст на изображении → переводите вывеску, ищите по названию.
- Язык надписей сужает страну (арабский, кириллица, тайский, деванагари...).
- Дорожные знаки, номера машин, форматы номеров — сильные гео-подсказки.
- Логотипы на форме/вывеске → компания → адрес филиала.

## Связка с метаданными

Перед публикацией фото часто **чистят**, но не всегда:

```bash
exiftool image.jpg | grep -iE 'gps|make|model|software|date|serial'
```

Если метаданные есть — GPS сразу даёт координаты. Если нет — переходите к визуальной геолокации (см. урок про геолокацию). Обратный поиск и EXIF дополняют друг друга: EXIF говорит «где снято», обратный поиск — «где опубликовано и кем».

## Разобранный пример: от фото к профилю

Задача — по одному фото человека найти его соцсети.

Шаг 1. Извлекаем EXIF:

```bash
exiftool photo.jpg
# Make: Apple, Model: iPhone 12, DateTimeOriginal: 2023:07:14 18:22:01
```

Шаг 2. Кропаем лицо и ищем в Yandex:

```bash
convert photo.jpg -crop 200x200+300+150 +repage face.jpg
```

Загружаем `face.jpg` в Yandex Images. Находим совпадения: 3 профиля ВКонтакте, 1 Instagram.

Шаг 3. Проверяем дату/место: метаданные говорят июль 2023, а фото на профиле опубликовано в августе — согласуется.

Шаг 4. Кросс-верификация: ищем ник из профиля в других сетях (см. урок про корреляцию соцсетей). Собираем связанные аккаунты.

## Разобранный пример: верификация новостного фото

Задача — проверить, действительно ли фото сделано на заявленном событии.

1. TinEye: ищем самое раннее появление. Если фото старше события — это переиспользование.
2. Проверяем погоду/тень (хронолокация) — согласуется ли с заявленной датой/местом.
3. Google Lens: находим ту же картинку в стоке (Getty/Shutterstock) — значит, не оригинал события.
4. Обратный поиск по характерным объектам (здание, вывеска) — устанавливаем реальное место.

Вывод: если фото найдено в стоке или датируется раньше события — это дезинформация.

## Edge cases и подводные камни

- **Кроп решает**: целое фото с фоном часто даёт шум; кроп объекта — точнее.
- **Движки не равны**: один не нашёл — другой найдёт. Пробуйте 3-4.
- **Приватность**: загрузка фото на сервисы оставляет след; для чувствительных задач — локальные инструменты или Tor.
- **Стоки**: много «совпадений» из стоков — не значит оригинал.
- **Ресайз/пересжатие** снижает совпадения — ищите несколько версий.
- **Юридические рамки**: PimEyes и распознавание лиц ограничены законом в ряде юрисдикций.

## Связка с другими ветками

- Геолокация по фото → определение места.
- EXIF → метаданные и время.
- Соцсети → корреляция аккаунтов.
- Фейс-корреляция → сопоставление разных фото одного человека.

## Что дальше / решение

Практика: возьмите любое стоковое фото и попробуйте найти его «источник» через TinEye; затем кропните объект и повторите в Yandex/Google. Обратный поиск — это навык перебора движков и кропов. Всегда комбинируйте его с EXIF и визуальной геолокацией: три инструмента вместе дают почти полную картину происхождения изображения.

## Разобранный пример: геолокация через обратный поиск

Задача — определить место по фото без EXIF.

1. Выделяем характерный объект (здание, памятник, вывеску) и кропаем.
2. Обратный поиск по объекту в Bing/Google — находим похожие фото с подписями.
3. Из подписей вытаскиваем название места → проверяем по картам.
4. Уточняем ракурс: сопоставляем тени/ориентиры с картой (см. урок про геолокацию).
5. Верифицируем: ищем независимое фото того же места с другого ракурса.

Так, фото вывески «Café Central» + архитектура → поиск → Вена, потом сверка с Street View по расположению зданий.

## Разобранный пример: деанон по аватарке

1. Аватарка из профиля → обратный поиск в Yandex.
2. Находим полноразмерную версию в другом профиле → это оригинал, возможно владелец.
3. По нику из второго профиля ищем в других сетях.
4. Сверяем аватарки (одно и то же лицо на разных платформах) — сильный сигнал.
5. Собираем связанные аккаунты и, при необходимости, подтверждаем по метаданным/геолокации.

## Чек-лист обратного поиска изображений

1. Извлечь EXIF (`exiftool`) — возможно, GPS уже есть.
2. Определить тип объекта: лицо / здание / товар / текст / арт.
3. Подготовить кроп и улучшение (`convert -crop`, `-sharpen`).
4. Прогнать 3-4 движка (Yandex, Google, Bing, TinEye).
5. Зафиксировать самое раннее появление (TinEye) — кто оригинал.
6. Проверить на сток (Getty/Shutterstock) — не переиспользование ли.
7. Кросс-верифицировать находки через другие ветки (соцсети, геолокация).
8. Помнить о приватности и легальности при работе с лицами.

## Инструменты для пакетной работы

Для десятков изображений пригодятся готовые утилиты: `img2dataset` (массовая загрузка), `imagehash` (перцептивные хэши), `ExifTool` (пакетный разбор метаданных). Пакетный EXIF-разбор:

```bash
exiftool -r -csv -GPS:all -Make -Model -DateTimeOriginal photos/ > meta.csv
```

Вывод (CSV) позволяет отсортировать фото по координатам и модели камеры, мгновенно выделив группу снимков одного устройства. Так вы находите «серии» — несколько фото, сделанных одним человеком.

## Составление панорамы из нескольких кадров

Один снимок часто не даёт точку, но серия — даёт. Приёмы:

- **Панорама:** если есть несколько фото места, сопоставьте перекрывающиеся детали (вывески, столбы, окна) — так строится 3D-связь.
- **Точка съёмки:** определите этаж и направление по линии горизонта и ракурсу зданий.
- **Сверка с панорамами:** Google Street View и Яндекс.Панорамы дают вид «с той же точки»; ищите совпадение 2–3 деталей.
- **Краудсорсинг:** Mapillary содержит пользовательские панорамы там, где нет официальных.

```bash
# извлечь гео-метаданные из серии и отсортировать по координатам
exiftool -csv -GPSLatitude -GPSLongitude -DateTimeOriginal series/ | sort -t, -k3
```

Совпадение координат нескольких фото подтверждает локацию куда надёжнее одного снимка — это ключ к деанону по «случайной» фотографии.

## Правовые аспекты обратного поиска

Обратный поиск публичных изображений сам по себе обычно законен, но результаты чувствительны:

- **Биометрия:** поиск по лицу (PimEyes) во многих юрисдикциях — обработка биометрических данных; нужны основание и правовое согласие.
- **Персональные данные:** связка «фото ↔ профиль ↔ человек» — это ПД; не публикуйте её без законной цели.
- **Авторские права:** скачанные фото могут быть защищены; используйте их только для анализа в рамках задания.
- **Документирование:** фиксируйте источник каждого совпадения (URL, дата) — это и доказательство, и защита от обвинений.

В CTF/пентесте границы задаёт задание: анализируйте, но не раскрывайте персональные связи третьим лицам.

## Где пригодится

- **CTF (OSINT):** задачи «найди место/владельца по фото».
- **Журналистика:** верификация снимков и первоисточника.
- **Bug bounty:** поиск аватара/фото сотрудника для атрибуции.
- **Правоохранительные/антифрод** (в рамках закона): поиск мошеннических фото.
