Распознавание лиц — самая чувствительная область OSINT. Технически это сопоставление изображений по лицевым признакам и поиск совпадений в открытых базах. Юридически и этически — зона повышенного риска: во многих юрисдикциях обработка биометрии без согласия незаконна. В уроке — что технически возможно, какие инструменты существуют, как устроены пороги и где проходят жёсткие границы.

## Что такое распознавание лиц в OSINT

- **Идентификация** — найти человека по фото в базе.
- **Верификация** — подтвердить, что два фото принадлежат одному человеку.
- **Корреляция** — связать лицо с аккаунтами и именами в открытых источниках.
- **Триаж** — отсеять заведомо непохожих кандидатов до ручной проверки.

Чаще всего в OSINT используют **верификацию** (два фото) и **reverse image** (поиск исходника), а не массовую идентификацию.

## Теория: детекция, эмбеддинг, сравнение

- **Детекция:** выделение лица на фото (bounding box, landmarks).
- **Эмбеддинг:** нейросеть превращает лицо в вектор (ArcFace, FaceNet, AdaFace).
- **Сравнение:** косинусное расстояние между векторами → «похожесть».
- **Порог:** высокий порог → мало ложных срабатываний, но пропуски; низкий — наоборот.
- **Reverse image:** поиск исходного/похожих изображений (см. osint-image-reverse).
- **Кросс-корреляция:** лицо → аккаунт → имя → другие сети.

Публичные «поисковики лиц» (PimEyes и подобные) существуют, но их использование регулируется законом и ToS. В РФ биометрия — специальная категория ПДн.

## Инструменты и команды

Безопасный минимум — reverse image по лицу/фото:

- Google Lens / Google Images «Search by image».
- Yandex Images (силён на лицах в RU-сегменте).
- Bing Visual Search, TinEye (точные совпадения).
- PimEyes (требует аккаунта; только в законном scope).

Локальная обработка (без загрузки в облако — приватнее):

```bash
pip install deepface
python3 - <<'PY'
from deepface import DeepFace
r = DeepFace.verify("a.jpg", "b.jpg", model_name="ArcFace")
print(r["verified"], round(r["distance"], 3))
PY
```

Вывод:

```text
True 0.312
```

Извлечение метаданных и кроп лица:

```bash
exiftool photo.jpg | grep -iE "gps|date|software"
# кроп по координатам (пример)
ffmpeg -i photo.jpg -vf "crop=200:200:300:120" face.jpg
```

## Reverse image по лицу

- **Yandex** — лучший на постсоветском пространстве; часто находит VK/OK-профили.
- **Google Lens** — силён на западных соцсетях.
- **TinEye** — точные совпадения и первое появление изображения.
- **Bing Visual Search** — дополнительный охват.

Приём: кроп только лица (без фона) улучшает точность reverse-поиска по лицу; полный кадр лучше ищет место съёмки.

## Разобранный пример: сопоставление аватаров

Дано: аватар из одного соцпрофиля и фото со встречи.

Шаг 1 — детекция и кроп лица на обоих изображениях.

Шаг 2 — reverse image по аватару (Yandex/Google Lens) → находим другие профили с тем же фото.

Шаг 3 — локальная проверка сходства двух фото:

```bash
python3 -c "from deepface import DeepFace; print(DeepFace.verify('avatar.jpg','meeting.jpg'))"
```

Шаг 4 — если `verified: true` и distance ниже порога — считаем сопоставление подтверждённым (с оговоркой о вероятности).

Шаг 5 — кросс-корреляция: имя из профиля → GitHub/LinkedIn → email-паттерн.

Шаг 6 — фиксируем доказательства и **явно** указываем уровень достоверности и юридические ограничения.

## Продвинутые приёмы

- **Landmark-анализ:** форма ушей, расстояние между глазами — устойчивы к возрасту.
- **Множественные ракурсы:** сверяйте несколько фото, а не одно.
- **Контекст важнее лица:** одежда, фон, время — снижают ошибки.
- **Локальные модели:** ArcFace/FaceNet офлайн — меньше утечек и приватнее.
- **Anti-recognition:** люди используют маски/фильтры — учитывайте искажения.
- **Документирование:** всегда сохраняйте цепочку доказательств.

## Правовые рамки по юрисдикциям

Биометрия — специальная категория данных практически везде:

- **GDPR (ЕС)**: биометрия для идентификации — особо защищённые данные; нужна явная основа.
- **152-ФЗ (РФ)**: биометрические ПДн обрабатываются отдельно, с повышенными требованиями.
- **BIPA (Иллинойс, США)**: строгие правила и судебные иски за обработку лиц без согласия.
- **AI Act (ЕС)**: ограничивает удалённую биометрическую идентификацию в реальном времени.

Практическое правило: **не применяйте** распознавание лиц к людям без согласия, если задача не в явном правовом scope. Для CTF/учебных задач используйте синтетические или собственные фото.

## Качество данных и пороги

Результат зависит от качества входных данных:

- **Разрешение**: лицо должно занимать достаточную площадь (обычно ≥ 100×100 px).
- **Ракурс**: фронтальные снимки точнее; профиль даёт больше ошибок.
- **Освещение/резкость**: размытие и шум ломают эмбеддинги.
- **Окклюзия**: маски, очки, руки снижают точность.
- **Возраст**: детские фото плохо сопоставляются со взрослыми.

Порог подбирайте под задачу: для «отсева» — выше (меньше ложных), для «кандидатов на проверку» — ниже. Всегда указывайте вероятность, а не бинарный вердикт.

## Синтетические и защитные техники

- **Anti-recognition**: маски, грим, специальные очки, фильтры.
- **Adversarial-патчи**: узоры, сбивающие детекторы (исследовательская область).
- **Диффприватность**: обучающие наборы без «запоминания» конкретных лиц.
- **Синтетические лица**: генерация (StyleGAN) для тестов без реальных людей.

Понимание защиты важно и для blue team: как снизить идентифицируемость сотрудников по публичным фото.

## Частые ошибки

- **Юридическая слепота.** Биометрия без согласия часто незаконна.
- **Доверять одному совпадению.** Ложные срабатывания — норма; нужны ≥2 признака.
- **Загружать чужие фото в облако.** Утечка и нарушение приватности.
- **Игнорировать качество.** Размытые фото дают мусорные эмбеддинги.
- **Путать похожесть с идентичностью.** Совпадение — вероятность, не доказательство.
- **Отсутствие документирования.** Без цепочки доказательств вывод ничего не стоит.

## Что дальше / решение

Сопоставив фото, переходите к корреляции: профиль → имя → email → другие сети (см. osint-people-search). Решение по кейсу: «совпадение ниже порога — отбросить», «кандидат — проверить вручную по ≥2 признакам», «подтверждено — использовать только в правовом scope с документированием». Никогда не делайте вывод об идентичности только по одному биометрическому совпадению.

## Сравнение моделей и метрик

- **ArcFace** — стандарт точности на бенчмарках (LFW, IJB-C); хорош для верификации.
- **FaceNet** — классическая триплетная модель, устойчива, но уступает ArcFace.
- **AdaFace** — лучше работает на изображениях низкого качества.
- **DeepFace** — обёртка, объединяющая несколько моделей; удобно для прототипов.

Метрика — **косинусное расстояние**. Типичный порог для ArcFace ~0.68: ниже — «вероятно один человек», выше — «разные». Порог зависит от модели и данных — калибруйте на своих парах.

## Калибровка порога

```python
from deepface import DeepFace
for pair in [("a1.jpg", "a2.jpg"), ("a1.jpg", "b1.jpg")]:
    r = DeepFace.verify(*pair, model_name="ArcFace")
    print(pair, r["verified"], round(r["distance"], 3))
```

Порог выбирайте по задаче: важнее не пропустить — снижайте (больше ложных); важнее точность — повышайте. Никогда не выдавайте бинарный вердикт без указания вероятности.

## Пример: от фото к аккаунту

1. Reverse image по аватару → список профилей с тем же фото.
2. Проверка сходства с эталонным фото (локально).
3. Из совпавших профилей извлекаем имя, ник, ссылки.
4. Кросс-поиск ника по другим платформам (sherlock/maigret).
5. По email/нику — утечки, GitHub, форумы.
6. Фиксация цепочки: фото → профиль → имя → контакты, с уровнем уверенности.

## Ограничения и риски

- **Демографические смещения** моделей: точность различается по группам.
- **Состаривание**: фото с разницей 10+ лет сопоставляются плохо.
- **Макияж/борода/очки**: существенно меняют эмбеддинг.
- **Сжатие/скриншоты**: JPEG-артефакты снижают качество.
- **Юридический риск**: обработка биометрии без основания наказуема.

## Blue-team: снижение идентифицируемости

- Не публикуйте фото сотрудников высокого разрешения.
- Ограничьте индексацию корпоративных фото.
- Используйте водяные знаки, чтобы отследить утечку корпоративных снимков.
- Обучайте сотрудников: лицо + контекст = деанонимизация.

## Практические сценарии применения

- **Верификация журналиста.** Подтвердить, что фото с мероприятия и профиль — один человек, используя ≥2 независимых признака.
- **CTF.** Сопоставить фото из задания с публичным аккаунтом, чтобы найти флаг.
- **Due diligence.** Проверить, не использует ли контрагент чужое лицо в документах.
- **Blue team.** Оценить, насколько сотрудники деанонимизируемы по публичным фото.

## Правовая памятка перед стартом

1. Есть ли законное основание обрабатывать биометрию?
2. Не нарушает ли загрузка фото в облако приватность третьих лиц?
3. Зафиксирована ли цепочка доказательств?
4. Указана ли вероятность, а не бинарный вердикт?
5. Ограничен ли вывод рамками scope?

Если хотя бы на один вопрос ответ «нет» — остановитесь.
