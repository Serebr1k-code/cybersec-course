## Вопрос, с которого всё начинается

Ты знаешь десяток инструментов разведки: subfinder, theHarvester, crt.sh, Shodan. Но когда целей много, а источников — десятки, ручной запуск не масштабируется. Каждый раз ты копируешь одни и те же команды и вручную сводишь результаты в таблицу.

Нужны **фреймворки**, которые автоматизируют запросы, объединяют результаты и строят графы связей. Разберём их и соберём единый конвейер.

## Наш пример: карта example.com за 30 минут

Введём термины. **Фреймворк разведки** — программа, которая запускает десятки источников против цели и складывает результаты в единую базу или граф. **Seed** — начальная сущность (домен, email, компания), с которой начинается сбор.

## Шаг 1: быстрый старт — theHarvester

Простейший инструмент: собирает email, поддомены, хосты и имена из публичных источников.

```bash
theHarvester -d example.com -b crtsh,virustotal,dnsdumpster -l 500 -f report.html
```

Флаги: `-d` домен, `-b` источники, `-l` лимит, `-f` вывод. Комбинация `crtsh` + `virustotal` + `dnsdumpster` даёт лучший охват поддоменов; поисковики — email и имена.

```bash
theHarvester -d example.com -b all | tee harvest.txt
grep -oE '[a-z0-9._%+-]+@[a-z0-9.-]+' harvest.txt | sort -u > emails.txt
```

## Шаг 2: структурированный сбор — recon-ng

**recon-ng** — модульный фреймворк с «рабочими пространствами». Логика: создаёшь workspace → добавляешь домен → запускаешь модули → результаты складываются в SQLite.

```bash
recon-ng
> marketplace install recon/domains-hosts/hackertarget
> db insert domains
domain (TEXT): example.com
> modules load recon/domains-hosts/hackertarget
> run
> show hosts
> modules load recon/hosts-ports/shodan_ip
> run
> show ports
```

Ключ в том, что модули «видят» результаты друг друга: домен → хосты → порты → контакты. API-ключи задаются через `keys add shodan_api <key>`.

## Шаг 3: комплексный скан — SpiderFoot

**SpiderFoot** — автоматический сканер по сотням модулей. Запускает цепочку: домен → поддомены → IP → порты → сервисы → утечки.

```bash
spiderfoot -s example.com -t DOMAIN_NAME -m all -o csv -q > sf.csv
# или веб-интерфейс:
spiderfoot -l 127.0.0.1:5001
```

Сильная сторона — **граф связей** и автоматическое обогащение. Минус — шум и много запросов (риск раскрытия).

## Шаг 4: визуализация — Maltego

**Maltego** — визуальный инструмент: сущности (домен, email, человек, IP) соединяются **трансформами** (запросами к внешним источникам). Отлично для презентации связей.

- Community Edition бесплатна (с лимитом трансформов).
- Строит граф вида `person → email → username → account`.
- Экспортирует в отчёт.

## Шаг 5: собираем единый конвейер

Свяжем инструменты в один скрипт:

```bash
#!/usr/bin/env bash
set -euo pipefail
DOM="$1"; OUT="recon_$DOM"; mkdir -p "$OUT"
subfinder -d "$DOM" -silent | sort -u > "$OUT/subs.txt"
theHarvester -d "$DOM" -b all 2>/dev/null | tee "$OUT/harvest.txt"
grep -oE '[a-z0-9._%+-]+@[a-z0-9.-]+' "$OUT/harvest.txt" | sort -u > "$OUT/emails.txt"
httpx -l "$OUT/subs.txt" -silent -o "$OUT/alive.txt"
printf 'subs=%s emails=%s alive=%s\n' \
  "$(wc -l <"$OUT/subs.txt")" "$(wc -l <"$OUT/emails.txt")" "$(wc -l <"$OUT/alive.txt")"
```

Логика конвейера: **вход (seed) → сбор → дедуп/нормализация → обогащение → визуализация → отчёт**.

## Шаг 6: нормализуем результаты

Автоматика даёт разнородные форматы. Приведём к единой схеме:

```bash
{ subfinder -d example.com -silent; assetfinder --subs-only example.com; \
  curl -s "https://crt.sh/?q=%25.example.com&output=json" | jq -r '.[].name_value'; } \
  | tr '[:upper:]' '[:lower:]' | sort -u > all_subs.txt
wc -l all_subs.txt
```

Ключ — **дедупликация** и **источник** каждого результата.

## Шаг 7: настраиваем мониторинг

Разовая разведка устаревает. Настрой регулярный прогон с диффом:

```bash
new=$(mktemp)
subfinder -d example.com -silent | sort -u > "$new"
comm -13 prev_subs.txt "$new" > newly_found.txt
mv "$new" prev_subs.txt
[ -s newly_found.txt ] && notify "новые поддомены: $(wc -l < newly_found.txt)"
```

Запуск через cron ловит новые активы сразу, а не через месяцы.

## Шаг 8: храним ключи правильно

Большинство модулей требуют API-ключей (Shodan, Censys, Hunter, VirusTotal, SecurityTrails). Храни их **вне репозитория** — в переменных окружения или менеджере секретов. Никогда не коммить в git: утёкший ключ — это и деньги, и доступ к твоим данным.

## Шаг 9: выбираем фреймворк

| Фреймворк | Сильная сторона | Слабость |
|---|---|---|
| theHarvester | быстрый старт, email и хосты | мало модулей |
| recon-ng | модульность, БД, workspace | часть модулей устарела |
| SpiderFoot | автоматизация, граф, сотни модулей | шум, ресурсоёмкость |
| Maltego | визуализация, трансформы | лицензии, ручной запуск |

Выбор прост: быстрая разведка → theHarvester; структурированный сбор → recon-ng; комплексный скан → SpiderFoot; презентация связей → Maltego.

## Шаг 10: помни про ограничения

- **Шум.** Автоматические запросы видны цели (DNS, сканы).
- **Ложные срабатывания.** Агрегированные данные требуют проверки.
- **Стоимость.** Платные API быстро расходуют бюджет.
- **Качество.** «Собрать всё» ≠ «понять»: автоматизация ускоряет, анализ — за тобой.

## Что мы теперь знаем

- Фреймворки автоматизируют запросы и строят графы связей.
- theHarvester — быстрый старт, recon-ng — структурированный сбор, SpiderFoot — комплексный скан, Maltego — визуализация.
- Конвейер: seed → сбор → нормализация → обогащение → отчёт.
- Дедупликация и источник обязательны для каждого результата.
- API-ключи хранят вне репозитория.

## Частые ошибки

- **Запускать всё «на максимум»** без ограничения → бан и шум.
- **Коммитить API-ключи** в репозиторий.
- **Верить автоматическим результатам** без проверки.
- **Игнорировать OPSEC** — все запросы идут с твоего IP.
- **Не логировать источник** каждого результата.

## На что смотреть дальше

Автоматизация ускоряет, но «собрать всё» не значит «понять»: анализ остаётся за тобой. Дальше разберём каждый фреймворк отдельно — начнём со **SpiderFoot**. А пока главное запомни: автоматика создаёт карту, а осмысленные выводы делает человек.

## Шаг 11: версионируем результаты и храним происхождение

Автоматика без истории бесполезна: через месяц никто не вспомнит, откуда взялся поддомен. Заведи для выходных данных отдельный git-репозиторий (или просто папку с датами) — так ты получишь дифф «что изменилось» и провенанс каждого факта.

```bash
$ mkdir -p recon_out && cd recon_out && git init -q
$ subfinder -d example.com -silent | sort -u > subs_$(date +%F).txt
$ git add -A && git commit -qm "recon $(date +%F)"
```

К каждому результату привязывай **источник**: `crtsh`, `virustotal`, `hackertarget`. В таблице это отдельная колонка. Без источника нельзя оценить достоверность — данные `crtsh` (логи сертификатов) надёжнее, чем «нашлось в поисковике».

Полезно хранить и «сырьё»: JSON-ответы API рядом с нормализованным списком. Тогда при вопросе «а точно ли этот хост существует» ты перепроверишь за секунду, а не перезапустишь весь конвейер.

## Справочник: где брать API-ключи

Большинство модулей работают без ключей на «бесплатном минимуме», но полнота приходит с ключами. Держи список того, что реально нужно:

| Источник | Ключ нужен? | Что даёт |
|---|---|---|
| crt.sh | нет | поддомены из CT-логов |
| Shodan | да | открытые порты и баннеры |
| Censys | да | сканы интернета, сертификаты |
| VirusTotal | да (бесплатный) | поддомены, репутация |
| SecurityTrails | да | исторические DNS |
| Hunter.io | да | email по домену |
| Have I Been Pwned | да | утечки по email |

Правило гигиены: ключи — только в переменных окружения (`export SHODAN_API_KEY=...`) или менеджере секретов, никогда в скрипте и никогда в git. Перед пушем прогоняй `gitleaks detect`, чтобы случайный ключ не уехал в публичный репозиторий.

## Если не сработало

- **Инструмент возвращает 403 / rate limit.** Снизь темп: добавь `--rate-limit`, задержку между запросами или отработай источники по очереди. 403 почти всегда означает «слишком часто», а не «нет данных».
- **Пустой результат при живом домене.** Проверь сам источник вручную (открой `crt.sh/?q=%25.example.com` в браузере). Если браузер показывает данные, а инструмент — нет, проблема в API-ключе или в парсинге.
- **Дубликаты и мусор.** Всегда прогоняй через `sort -u` и отбрасывай служебные имена (`*`, `_dmarc`, `localhost`). Иначе счётчики врут.
- **Конвейер «падает» на одном шаге.** Оберни шаги в `|| true`, чтобы одна упавшая утилита не убивала весь прогон (`set -e` без `|| true` останавливает скрипт на первом же сбое).

## Итоговая шпаргалка конвейера

```
seed (домен)
  └─ сбор      subfinder, theHarvester, crt.sh
  └─ нормализация  tr, sort -u, отброс служебных имён
  └─ обогащение  httpx (живость), nmap (порты), Shodan (баннеры)
  └─ хранение   git + колонка «источник»
  └─ мониторинг cron + comm -13 (дифф новых активов)
```

Держи этот скелет в голове — любой фреймворк (recon-ng, SpiderFoot, Maltego) реализует ровно эти пять стадий, просто прячет их за интерфейсом. Пятая стадия — мониторинг — отличает разовую разведку от непрерывной: активы появляются и исчезают, и только регулярный дифф ловит новое вовремя.

## Где пригодится

- **Bug bounty:** быстрый старт с широкой картой активов.
- **CTF (OSINT):** автоматизировать перебор источников.
- **Пентест:** собрать поверхность за минуты.
- **Работа:** масштабная разведка и построение графов связей.
