## Вопрос, с которого всё начинается

Ты нашёл домен `shop.example.com` и хочешь понять, какие ещё сайты принадлежат тому же владельцу. Новичок смотрит на дизайн и контакты — и получает лишь догадки.

Есть более надёжный след: **tracking-идентификатор**. Компания заводит один аккаунт аналитики и вставляет его номер на все свои сайты. Значит, этот номер — «отпечаток владельца», который переживает смену дизайна, хостинга и даже домена. Разберём это на двух «разных» сайтах.

## Наш пример: shop.example.com и blog-example.net

У нас два объекта, которые выглядят как разные компании. **Tracking-идентификатор** — уникальный номер, который сервис аналитики или рекламы выдаёт аккаунту. Примеры: Google Analytics (`UA-XXXXXXX-Y`, `G-XXXXXXXXXX`), Google Tag Manager (`GTM-XXXXXX`), AdSense (`pub-XXXX...`), Facebook Pixel, Yandex.Metrica.

Почему ID связывает домены? Потому что он привязан к **аккаунту**, а не к сайту. Один GA-аккаунт обслуживает все сайты компании, чтобы видеть сводную статистику.

## Шаг 1: ищем ID в исходнике страницы

ID живёт в коде страницы — в `gtag`, в `analytics.js`. Смотрим исходник первого домена:

```bash
curl -s https://shop.example.com | grep -oiE '(UA-[0-9]{4,}-[0-9]+|G-[A-Z0-9]{8,}|GTM-[A-Z0-9]{4,}|pub-[0-9]{10,})' | sort -u
```

```
G-8F2K9LQ3ZM
GTM-5XW2K9
UA-1234567-3
```

Три идентификатора. Регулярное выражение `grep -oiE` ищет строки по шаблонам разных сервисов: `G-` — GA4, `GTM-` — Tag Manager, `UA-` — старая Universal Analytics.

Теперь проверим второй домен — нет ли там того же:

```bash
curl -s https://blog-example.net | grep -oiE 'GTM-[A-Z0-9]{4,}'
```

```
GTM-5XW2K9
```

Совпадение `GTM-5XW2K9`. Один контейнер Tag Manager на двух доменах — сильное доказательство общего владельца.

## Шаг 2: pivot по ID

Теперь развернём находку: найдём **все** домены, где встречается этот ID. Ищем в сервисах, которые индексируют исходный код страниц:

```
publicwww.com/websites/"GTM-5XW2K9"
builtwith.com/analytics/G-8F2K9LQ3ZM
```

**PublicWWW** индексирует HTML и JS, поэтому находит ID прямо в исходниках. Результат — список «соседей» владельца. Дополнительно помогает Google-дорк по строке ID:

```
"GTM-5XW2K9" -site:example.com
```

## Шаг 3: не забываем про архивы

Иногда ID сняли с живого сайта, но он остался в старых снимках. Проверим через Wayback:

```bash
curl -s "http://web.archive.org/cdx/search/cdx?url=example.com&output=text&fl=timestamp,original" | head -3
```

```
20200115000000 http://example.com/
20220603000000 http://example.com/
```

Загружаем старый снимок и грепаем ID тем же шаблоном. Так находятся связи, которые уже не видны в живом коде.

## Шаг 4: региональная аналитика

В рунете Google Analytics может отсутствовать — там часто только Yandex.Metrica. Её ID ищется так:

```bash
curl -s https://example.ru | grep -oiE 'ym\([0-9]{6,}'
```

```
ym(12345678,
```

У Metrica есть публичный «Вебвизор» по ID: `metrika.yandex.ru/stat/?id=12345678`. Если владелец не закрыл доступ, можно увидеть чужую статистику — это отдельный мощный вектор.

## Шаг 5: пиксели соцсетей

Facebook Pixel, VK Pixel, TikTok Pixel содержат числовой ID и связывают домены с одним рекламным кабинетом:

```bash
curl -s https://example.com | grep -oiE "fbq\('init',\s*'[0-9]{10,}'"
```

```
fbq('init', '123456789012345')
```

Тот же пиксель на другом домене означает общего рекламодателя. В расследованиях это особенно ценно: рекламные кабинеты регистрируются на юридические лица.

## Шаг 6: автоматизируем сбор по списку доменов

По списку доменов соберём все ID и сгруппируем их — так автоматически находятся «кластеры» владельцев:

```bash
OUT=ids.tsv; : > "$OUT"
while read -r h; do
  ids=$(curl -sL -m 10 "https://$h" 2>/dev/null \
        | grep -oiE '(UA-[0-9]{4,}-[0-9]+|G-[A-Z0-9]{8,}|GTM-[A-Z0-9]{4,}|pub-[0-9]{10,})' \
        | sort -u | paste -sd, -)
  [ -n "$ids" ] && printf '%s\t%s\n' "$h" "$ids" >> "$OUT"
done < hosts.txt
```

Затем находим ID, встречающиеся на нескольких доменах, — это и есть связанные активы. Из одной строки `GTM-XXXX` разворачивается карта всех сайтов владельца.

## Типичные ошибки

- **Путать чужой ID с владельческим.** Некоторые ставят GA-код подрядчика или агентства — тогда ID связывает не владельцев, а исполнителей.
- **Считать совпадение одного ID доказательством.** Для атрибуции нужно 2+ совпадающих сигнала или ID плюс другой признак (общий сертификат, общий ASN).
- **Игнорировать дату.** ID мог быть снят годы назад: в архиве он есть, а в живом коде — уже нет.
- **Искать только в HTML.** Одностраничные приложения отдают код через JS-бандлы — грепайте и `*.js`.
- **Забывать про региональные системы.** В СНГ часто только Metrica и VK Pixel, а Google Analytics отсутствует вовсе.

## Где именно прячется ID

ID почти всегда виден в исходнике, но его расположение зависит от сервиса:

| Сервис | Паттерн ID | Где в коде |
|---|---|---|
| Universal Analytics | `UA-XXXXXXX-Y` | `analytics.js` |
| GA4 | `G-XXXXXXXXXX` | `gtag('config', ...)` |
| Tag Manager | `GTM-XXXXXX` | `gtm.js?id=` |
| AdSense | `pub-XXXXXXXXXXXX` | `adsbygoogle` |
| Facebook Pixel | 15–16 цифр | `fbq('init', ...)` |
| Yandex.Metrica | 8 цифр | `ym(XXXXXX, ...)` |
| Hotjar | 6–7 цифр | `hjid:` |

Помимо аналитики, домены связывают технические отпечатки: `ads.txt` (тот же `pub-` ID), favicon-хэш, общий ASN, общий сертификат. Комбинация двух-трёх отпечатков даёт уверенную атрибуцию владельца.

## Что мы теперь знаем

- Tracking-ID привязан к аккаунту и стоит на всех сайтах владельца.
- ID лежит в исходнике страницы и в JS-бандлах, а иногда остаётся в архивах.
- PublicWWW и BuiltWith ищут ID по коду чужих страниц — это pivot к «соседям».
- Региональные системы (Metrica) и пиксели соцсетей дают дополнительные связки.
- Для уверенной атрибуции нужно 2+ независимых сигнала, а не один ID.

## На что смотреть дальше

Разберись с **favicon-хэшингом**: отпечаток иконки связывает хосты так же, как tracking-ID связывает домены. Изучи, как комбинировать сигналы — общий ID, общий сертификат, общий ASN — в устойчивую атрибуцию. Для мобильных приложений тот же ID ищется в распакованном APK.

## Справочник: ID и что они выдают

Каждый сервис аналитики оставляет свой формат идентификатора. По нему узнаёшь владельца и связываешь сайты:

| Сервис | Формат ID | Что даёт |
|---|---|---|
| Google Analytics (Universal) | `UA-XXXXXX-Y` | один аккаунт — один владелец |
| Google Analytics 4 | `G-XXXXXXXXXX` | то же, новый формат |
| Google Tag Manager | `GTM-XXXXXX` | контейнер тегов, часто общий на все сайты |
| Yandex Metrica | `ym(XXXXXXXX)` | номер счётчика |
| Facebook Pixel | `fbq('init', 'NNNN')` | рекламный пиксель |
| Hotjar | `hjid:NNNNNN` | запись сессий |
| AdSense | `ca-pub-NNNN` | издательский аккаунт |

Один и тот же `UA`/`GTM` на разных доменах — сильный признак, что это один владелец.

## Защита: как не утекать через аналитику

Если ты на стороне защиты и не хочешь, чтобы сайты склеивались по ID:

- **Разные аккаунты** для разных проектов — не переиспользуй один `GTM`-контейнер.
- **Server-side tagging** (серверный GTM) — клиентский код больше не содержит полный ID.
- **Самохостинг аналитики** (Matomo, Plausible) — убирает сторонние пиксели вовсе.
- **Content Security Policy** с ограничением доменов — мешает чужим пикселям грузиться.
- **Проверяй исходник** перед публикацией: `grep -rE 'UA-|G-|GTM-|ca-pub-' dist/`.

## Если не сработало

- **ID нет в HTML.** Он может подгружаться из внешнего скрипта — ищи по JS-файлам, а не только по разметке.
- **ID спрятан в минифицированном коде.** Ищи по шаблону (`UA-\d+`, `G-[A-Z0-9]+`), а не по слову `analytics`.
- **Сайт за CDN.** Проверь архив (Wayback Machine) — там сохранились старые версии со старым ID.
- **Один сайт, много ID.** Возможно, разные страницы принадлежат разным владельцам — фиксируй, где какой ID найден.

## Мини-практика: связываем два сайта по GTM

Классический приём корреляции на конкретном примере:

1. **Ищем контейнер.** На `shop.example.com` в исходнике находим `GTM-XXXXXX`.
2. **Проверяем второй сайт.** На `blog-example.net` — тот же `GTM-XXXXXX`.
3. **Делаем вывод.** Одинаковый контейнер Google Tag Manager почти наверняка означает одного владельца: контейнеры редко переиспользуют между чужими проектами.
4. **Усиливаем.** Если совпадает ещё и `ca-pub` (AdSense) или ID Facebook Pixel — связь подтверждается вторым независимым признаком.
5. **Фиксируем.** Пара «домен A + домен B + общий GTM-ID» — доказанная связь для отчёта.

Правило то же, что и везде в OSINT: **один признак — гипотеза, два независимых — факт**.

## Шпаргалка: где искать ID

- `<script>` в исходнике страницы (GTM, GA).
- внешние JS-файлы, если в HTML пусто.
- архивы (Wayback) для старых версий.
- заголовки ответа и cookies (`_ga`, `_fbp`).
- несколько страниц сайта — ID может стоять не везде.
- минифицированный JS — ищи по шаблону (`UA-\d+`, `G-[A-Z0-9]+`), не по слову analytics.
- сравни два домена: общий GTM-ID = один владелец.

## Куда дальше

Мы связали два «разных» домена через общий tracking-ID. В следующем уроке — **TLS-фингерпринт**: возьмём сертификаты и параметры TLS и свяжем хосты по стеку и по общему выпуску сертификата. А пока главное запомни: ID — это отпечаток владельца, переживающий редизайн.

## Где пригодится

- **CTF (OSINT):** найти «второй» сайт цели по общему tracking ID.
- **Bug bounty:** расширить scope, обнаружив аффилированные домены.
- **Расследования:** связать сайты одного владельца.
- **Пентест:** выявить теневую инфраструктуру компании.
