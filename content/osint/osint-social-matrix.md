## Вопрос, с которого всё начинается

Ты видишь адрес вида `#osint-lab:matrix.example.org`. Это не email и не веб-ссылка — это Matrix-комната. Нужно понять: на каком сервере она живёт, кто её создал и что видно из публичного каталога.

Задача: разобрать Matrix-идентификатор и вытащить данные комнаты из публичного каталога.

## Наш пример: алиас комнаты

Держим файл `alias.txt`:

```bash
cat alias.txt
```

```text
#osint-lab:matrix.example.org
```

Первый вопрос: что здесь локальная часть, а что — сервер?

## Шаг 1: анатомия Matrix-адресов

Matrix различает три вида идентификаторов:
- **User ID** — `@user:server` (пользователь и его homeserver);
- **Room ID** — `!roomid:server` (внутренний ID комнаты);
- **Room alias** — `#alias:server` (человекочитаемый адрес комнаты).

Правая часть после `:` — **homeserver**, сервер, где живёт объект. Разбираем наш алиас:

```bash
python3 parse_matrix.py
```

```text
Тип: room alias
Локальная часть: osint-lab
Homeserver: matrix.example.org
```

## Шаг 2: федерация и публичный каталог

Matrix — федеративная сеть: серверы обмениваются сообщениями. У многих серверов включён **публичный каталог комнат** (`room directory`), который можно запросить без аккаунта. Это и есть точка входа для OSINT.

## Шаг 3: запрашиваем каталог

```bash
python3 room_directory.py
```

```text
Комната: #osint-lab:matrix.example.org
Название: OSINT Lab
Участников: 87
Создатель: @nordwind:matrix.example.org
nto{m4tr1x_r00m_d1r}
```

Мы получили название, число участников и **создателя** — User ID с тем же homeserver. Это связывает комнату с конкретным пользователем.

## Шаг 4: границы

Публичный каталог отдаёт метаданные комнаты, но не сообщения. История комнаты может быть публичной (если так настроено), но у большинства приватных комнат она закрыта. Как и с Signal: недоступное фиксируем как недоступное.

```bash
# иллюстративно: что даёт каталог и что нет
# даёт: название, участники, создатель
# не даёт: сообщения приватных комнат
```

## Полный прогон

```bash
cat alias.txt                 # алиас
python3 parse_matrix.py       # тип + homeserver
python3 room_directory.py     # метаданные комнаты
```

Непрерывно: алиас → homeserver → каталог → комната → создатель.

## Если не сработало

**Каталог выключен.** Публичный directory может быть отключён администратором.
**Комната приватная.** Метаданные могут быть скрыты, кроме самого факта существования.
**Федерация ограничена.** Сервер может не принимать запросы извне.

## Частые ошибки

**Ошибка: путать `@user` и `#room`.** Разные типы объектов.
**Ошибка: игнорировать homeserver.** Он говорит, где живут данные.
**Ошибка: считать каталог полным.** Многие комнаты в него не попадают.
**Ошибка: искать сообщения.** Для приватных комнат их нет в открытом доступе.

## Справочная таблица: Matrix-идентификаторы

| Идентификатор | Формат | Значение |
|---------------|--------|----------|
| User ID | `@user:server` | пользователь и homeserver |
| Room ID | `!id:server` | внутренний ID комнаты |
| Room alias | `#alias:server` | публичный адрес комнаты |
| Каталог | API directory | название, участники, создатель |

## Что мы теперь знаем

1. Matrix-адрес кодирует объект и homeserver.
2. Публичный каталог отдаёт метаданные комнат.
3. Создатель комнаты — User ID, это мостик к человеку.
4. Сообщения приватных комнат недоступны.
5. Федерация делает серверы взаимозависимыми.

## Разбор кейса: от алиаса к создателю

Проследим путь. На входе — `#osint-lab:matrix.example.org`. На выходе — создатель комнаты.

**Шаг первый.** Разбираем алиас: локальная часть `osint-lab`, homeserver `matrix.example.org`.

**Шаг второй.** Запрашиваем публичный каталог комнат у homeserver.

**Шаг третьий.** Получаем метаданные: название, число участников, создателя `@nordwind:matrix.example.org`.

**Шаг четвёртый.** Создатель — User ID на том же homeserver. Это мостик к человеку.

**Итог.** Мы связали публичную комнату с конкретным пользователем, не читая переписки.

## Рабочий воркбук: Matrix за пять шагов

1. **Классификация.** Определи тип: user, room id или alias.
2. **Homeserver.** Выдели сервер из правой части адреса.
3. **Каталог.** Запроси публичный directory этого сервера.
4. **Метаданные.** Выпиши название, участников, создателя.
5. **Атрибуция.** Свяжи создателя с другими площадками.

## Частые вопросы

**Можно ли прочитать историю комнаты?** Если она публичная — да; у приватных — нет.

**Что если каталог выключен?** Попробуй федеративный API или поиск по другим homeserver'ам.

**Чем Room ID отличается от alias?** Alias человекочитаем и может меняться; ID — внутренний и постоянный.

**Можно ли найти все комнаты пользователя?** Частично — через каталоги и упоминания; полного списка обычно нет.

**Почему это федеративная сеть?** Потому что серверы обмениваются данными и пользователи разных homeserver'ов видят друг друга.

## Термины

**Matrix** — федеративный протокол обмена сообщениями.

**Homeserver** — сервер, где живёт аккаунт или комната.

**User ID** — `@user:server`.

**Room alias** — `#alias:server`, публичный адрес комнаты.

**Room directory** — публичный каталог комнат сервера.

## Связь с другими уроками

Matrix завершает блок федеративных платформ (`osint-mod-social-federated`). Его приёмы — разбор адреса, опрос публичного каталога, атрибуция создателя — общие с **Nostr** и **Bluesky**. Дальше разведка уходит в реестры, записи и корпоративно-финансовую аналитику, где те же навыки атрибуции применяются к людям и компаниям.

## Практикум: карта комнат homeserver'а

Публичный каталог позволяет построить карту комнат сервера.

**Шаг первый.** Берём homeserver `matrix.example.org`.

**Шаг второй.** Запрашиваем directory: список публичных алиасов.

**Шаг третий.** Для каждой комнаты выписываем название, участников и создателя.

**Шаг четвёртый.** Группируем комнаты по создателю — получаем интересы и связи.

**Шаг пятый.** Ищем пересечения с другими площадками: те же ники, те же темы.

Так публичный каталог превращается в социальный граф. Ничего приватного мы не читаем — только метаданные, которые сервер сам публикует.

## Сценарии CTF и расследований

**CTF, базовая задача.** Дан алиас. Нужно назвать homeserver. Решение: разобрать правую часть.

**CTF, средняя задача.** Дана комната. Нужно найти создателя. Решение: запросить каталог.

**Расследование.** Нужно связать комнату с человеком. Решение: User ID создателя → другие площадки.

**Мониторинг.** Нужно отслеживать комнаты сервера. Решение: периодический запрос directory.

Matrix учит главному: даже в федеративной сети публичные метаданные дают много — если знать, где их спросить.

## Расширенный разбор: федерация как источник данных

Matrix устроен так, что данные распределены по серверам. Это одновременно и сложность, и возможность.

Сложность в том, что нет единой точки запроса. Комната живёт на конкретном homeserver, и его каталог — не полный список всех комнат мира. Чтобы найти больше, нужно опрашивать разные серверы и использовать федеративные API. Возможность в том, что каждый сервер публикует свои метаданные, и суммарно они дают богатую картину.

Начнём с каталога. Публичный room directory сервера отдаёт список алиасов с названиями и числом участников. Это первый слой. Второй слой — создатель: User ID, который связывает комнату с человеком. Третий слой — пересечения: если один пользователь создал несколько комнат, видно его интересы и сообщество.

Дальше — федеративные связи. Matrix-серверы обмениваются событиями. Это значит, что пользователь с одного сервера может быть виден на другом. Для разведки это даёт возможность находить аккаунты по активности в чужих комнатах, если она публична.

Про приватность. Matrix поддерживает шифрование и приватные комнаты. Публичный каталог показывает только то, что администратор решил опубликовать. Не пытайся обойти это — работай с открытыми метаданными.

Отдельно про идентификаторы. User ID, Room ID и alias — три разных типа. User ID указывает на аккаунт, Room ID — внутренний постоянный идентификатор комнаты, alias — человекочитаемый и может меняться. Для устойчивой ссылки на комнату используй Room ID, а для поиска — alias.

Наконец, про атрибуцию. Создатель комнаты — это User ID, за которым стоит человек или бот. Проверь, активен ли аккаунт, есть ли у него другие комнаты, совпадает ли ник с другими площадками. Так метаданные комнаты превращаются в узел социального графа.

## Итоговая шпаргалка

| Тип | Формат | Устойчивость |
|-----|--------|--------------|
| User ID | `@user:server` | высокая |
| Room ID | `!id:server` | постоянный |
| Alias | `#alias:server` | меняется |
| Каталог | API сервера | метаданные комнат |

Федерация означает много источников. Опрашивай несколько и объединяй — так картина становится полной.

## Практическое замечание о федеративном поиске

В Matrix нет единого поискового индекса всех комнат, поэтому разведка похожа на обход каталогов разных серверов. Начни с homeserver целевого объекта, затем проверь крупные публичные серверы. Для каждой найденной комнаты выпиши alias, Room ID, создателя и число участников. Собрав несколько серверов, ты увидишь пересечения: одни и те же пользователи, одинаковые темы, взаимные ссылки. Эти пересечения и есть твой граф. Не пытайся охватить всю федерацию сразу — двигайся от целевого сервера наружу, слой за слоем, фиксируя каждый шаг и его источник.

## Практическое замечание об отчётности

Результат Matrix-разведки удобно оформлять в виде таблицы: комната, сервер, создатель, число участников, источник и дата. Такая таблица сразу показывает, какие комнаты связаны общим создателем, а какие изолированы. Если по ходу работы ты обнаружил, что каталог сервера недоступен или комната приватна, внеси это в отдельную колонку «ограничения». Явное указание ограничений делает отчёт честным и позволяет коллеге продолжить работу с того места, где ты остановился, не повторяя уже пройденный путь.
