Ник (username) — один из самых связных идентификаторов: люди переиспользуют его на десятках сайтов. Задача — проверить, где ник **занят**, и отфильтровать ложные срабатывания. Это отправная точка большинства деанон-задач: от одного ника вы раскручиваете весь цифровой след.

## Как это работает

Большинство платформ отдают **разный ответ** для существующего и несуществующего профиля:

- **HTTP 200** для существующего, **404** для отсутствующего (GitHub, Reddit).
- **Редирект** на главную для отсутствующего.
- **Разный текст** страницы («пользователь не найден», «page not found»).
- **Разная длина ответа** (даже при одинаковом коде).

Инструменты просто отправляют запросы `https://site/<username>` и смотрят на признаки. Ключевой навык — не поверить «200», а понять, что за ним.

## Sherlock

Самый популярный инструмент:

```bash
pip install sherlock-project
sherlock username --timeout 10
# сохранить в файл
sherlock username -o results.txt
# только конкретные сайты
sherlock username --site GitHub --site Reddit --site Steam
# несколько ников сразу
sherlock alice bob charlie --timeout 15
# только существующие (без вывода)
sherlock username --print-found --timeout 10
```

Sherlock знает ~400 сайтов и выдаёт найденные профили. Учтите: **ложные срабатывания** бывают (сайт отдаёт 200 всегда).

## Maigret

Форк Sherlock с более богатыми отчётами и **анализом профилей** (извлекает имя, био, аватар, связи):

```bash
pip install maigret
maigret username
maigret username --html           # HTML-отчёт с аватарами
maigret username --json simple    # машинно-читаемый результат
maigret username --print-errors   # показать проблемы сети
maigret username --timeout 15 --top-sites 200
```

Maigret помечает «claimed» vs «unclaimed», строит граф связей и сохраняет аватары — удобно для деанона и сравнения.

## WhatsMyName и ручные списки

- **WhatsMyName** (`whatsmyname.app`) — веб-интерфейс + JSON-база сайтов и правил проверки (`wmn-data.json`), обновляется сообществом.
- **namechk.com**, **checkusernames.com** — быстрая онлайн-проверка.
- **usercheck.com** — проверка с эвристиками.

Ручной подход (когда инструмент не знает сайт):

```bash
USER=darkreader42
for u in "https://site1.com/$USER" "https://site2.com/u/$USER"; do
  code=$(curl -s -o /dev/null -w '%{http_code} %{size_download}' -A 'Mozilla/5.0' "$u")
  echo "$code  $u"
done
```

## Снижение ложных срабатываний

1. **Проверьте контрольный ник** — заведомо несуществующий (например `zzz_no_such_user_9931`). Если сайт и на него даёт 200 — правило для сайта бесполезно.
2. **Смотрите на содержимое**, а не только код: пустой профиль с нулём активности может быть placeholder.
3. **Сверяйте аватары**: одинаковое фото — сильный сигнал.
4. **Дата регистрации и активность**: заброшенный аккаунт тоже «существует».
5. **Учитывайте региональные/языковые сайты** — ник может быть занят только в вашем сегменте.

## Корреляция найденных аккаунтов

После сбора списка:

- Извлеките **аватары** (часто по `https://site/avatars/<hash>`) и сравните визуально/по хешу файла.
- Соберите **био и ссылки** — совпадения выдают человека (общий сайт, email, мессенджер).
- Постройте таблицу «сайт — URL — уверенность».
- Свяжите с email/телефоном (см. урок про поиск людей).

```bash
# сравнить аватары по хешу (одинаковый файл = один человек)
curl -s -o a1.jpg https://github.com/$USER.png
curl -s -o a2.jpg https://steamcommunity.com/.../$USER/avatar.jpg
md5sum a1.jpg a2.jpg
```

## Практический сценарий

```
sherlock darkreader42 --timeout 10 --print-found
```

Найдено: GitHub, Reddit, Steam, Telegram. Проверяем аватары — на GitHub и Steam одинаковое фото. Из GitHub достаём email в коммитах (`git log --format='%ae'`). Профиль сходится.

## Частые ошибки

- **Верить всем «найдено»** — обязательно проверяйте контрольным ником.
- **Не менять User-Agent** — часть сайтов отдаёт разное поведение ботам.
- **Игнорировать rate-limit** — сайты блокируют серию запросов; снижайте темп.
- **Забыть про приватность** — ваш перебор виден сайтам; для чувствительных задач используйте прокси.

# Sherlock: только найденные, с таймаутом

## Ложные срабатывания: методика

```bash
# контрольный ник — проверяем, что сайт вообще различает существование
curl -s -o /dev/null -w '%{http_code}\n' "https://site.com/zzz_no_such_user_9931"
curl -s -o /dev/null -w '%{http_code}\n' "https://site.com/$USER"
# одинаковые коды → сайт бесполезен для enum
```

Дополнительно: сравнивайте **размер ответа** (`-w '%{size_download}'`), текст «не найдено», редиректы.

## Корреляция аккаунтов

```bash
# сравнить аватары по хэшу
curl -s -o a1.jpg https://github.com/$USER.png
curl -s -o a2.jpg https://site.com/u/$USER/avatar
md5sum a1.jpg a2.jpg
```

Совпадение хэша → один человек. Плюс био, ссылки, общие друзья. Стройте таблицу «сайт — URL — уверенность».

## Флаги Sherlock и Maigret в деталях

Инструменты дают больше, чем простой прогон по списку сайтов.

```bash
# sherlock: только найденное, тайм-аут, CSV для отчёта
sherlock --print-found --timeout 10 --csv --output found.csv jsmith
# ограничить набор сайтов и категорий
sherlock --site GitHub --site Reddit jsmith
# через Tor (анонимно)
sherlock --tor --unique-tor jsmith
# прогнать сразу список ников
sherlock --print-found jsmith j.smith jsmith_dev

# maigret: больше сайтов, отчёты, теги, рекурсия по найденным
maigret jsmith --html --pdf --json simple
maigret jsmith --tags social,photo --timeout 15 --max-connections 30
maigret jsmith -a            # рекурсивно: искать новые ники в найденных профилях
```

`maigret -a` (recursive) — ключевая фича: он парсит найденные страницы и извлекает **другие** имена/ссылки, расширяя поиск автоматически.

## WhatsMyName и собственные списки сайтов

WhatsMyName (`whatsmyname.app`) — открытый JSON-список сайтов с шаблонами URL и признаком «есть/нет». Его можно расширять своими правилами:

```json
{
  "name": "InternalForum",
  "check_uri": "https://forum.example.com/u/{account}",
  "account_existence_code": "200",
  "account_existence_string": "profile",
  "account_missing_code": "404"
}
```

Правило хорошего детектора: **уникальный** признак существования (не общий текст шаблона), иначе получите ложные срабатывания. Проверяйте правила на заведомо существующем и заведомо отсутствующем нике.

## Снижение ложных срабатываний: методика

Почти все «находки» на сайтах с SPA/антиботом — ложные. Порядок фильтрации:

1. **Код ответа** — 200 сам по себе ничего не значит; ищите комбинацию кода + строки.
2. **Отрицательный контроль** — прогоните случайный ник (`zzq7x9`) по тем же сайтам; всё, что «нашли», — FP.
3. **Позитивный контроль** — прогоните заведомо существующий ник (например, публичную персону) и убедитесь, что детектор его ловит.
4. **Ручная проверка** — открыть найденный профиль и убедиться, что он не заглушка.
5. **Кросс-проверка** — сайт, где нет контента/аватара, считается неподтверждённым.

```bash
# отрицательный контроль
sherlock --print-found zzq7x9 > neg.txt
# позитивный контроль
sherlock --print-found someceleb > pos.txt
# вычитаем шум
comm -23 <(sherlock --print-found jsmith | sort) <(sort neg.txt)
```

## Корреляция аккаунтов: доказательство тождества

Совпадение ника — гипотеза, не доказательство. Усиливайте независимыми признаками:

| Признак | Как сравнивать |
|---------|----------------|
| Аватар | перцептивный хэш (imagehash), reverse image |
| Био/текст | сходство (stylometry, difflib) |
| Ссылки | один и тот же сайт/email в био |
| Время активности | совпадение таймзон и часов постов |
| Подписки/друзья | пересечение графов |

```python
import imagehash, requests
from PIL import Image
from io import BytesIO
h1 = imagehash.phash(Image.open(BytesIO(requests.get(a1).content)))
h2 = imagehash.phash(Image.open(BytesIO(requests.get(a2).content)))
print(h1 - h2)   # <10 при высоком сходстве
```

## Разобранный пример: от ника к личности

Дано: известен ник `jsmith`.

1. `maigret jsmith --html` → 30+ потенциальных профилей, отсеиваем FP отрицательным контролем.
2. Из подтверждённых (GitHub, Reddit) вытаскиваем аватар и био.
3. Reverse image аватара → та же фотография в LinkedIn (osint-image-reverse).
4. В GitHub-профиле — email в коммитах (`git log --format='%ae'`), паттерн корпоративной почты.
5. Кросс-корреляция по времени постов подтверждает одну таймзону.
6. Итог: граф «ник → имя → email → соцсети» с уровнями уверенности.

## Расширенные приёмы и ограничения

- **Ники-варианты**: `jsmith`, `j.smith`, `johnsmith`, `jsmith123`, `jsmith_dev` — генерируйте перестановки и деривативы.
- **Платформенные особенности**: Reddit скрывает существование, TikTok/Instagram отдают разное для приватных, Discord требует сервер.
- **Rate-limits**: массовый прогон ловит капчу/бан — `--timeout`, `--max-connections`, ротация прокси.
- **Юридически**: сбор публичных ников допустим, но агрегирование ПДн — см. osint-legal-ethics.
- **Не переоценивайте FP**: лучше 5 подтверждённых, чем 50 «найденных» заглушек.

## Где пригодится

- **CTF (OSINT):** деанон по нику из задания.
- **Bug bounty:** поиск профилей разработчиков и утечек.
- **Threat intel:** связывание аккаунтов атакующего.
- **HR/верификация:** проверка цифрового следа (в рамках закона).
