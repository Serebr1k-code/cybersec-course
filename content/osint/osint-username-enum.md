## Вопрос, с которого всё начинается

В прошлых уроках мы работали с доменами. Но у человека нет домена — у него есть **ник**: короткое имя, которое он повторяет на десятках сайтов. И вот вопрос, знакомый каждому OSINT-заданию: **на каких ещё платформах занят этот ник?**

Если человек один раз завёл `dark_wizard_88` на форуме, с большой вероятностью тот же ник живёт на GitHub, Reddit, Mastodon и в Telegram. Собрав эти аккаунты, вы получаете его цифровой след.

## Наш пример: ник `nasa`

Возьмём заведомо публичный, безопасный ник — `nasa`. Он реально занят в куче мест, и на нём удобно показать технику, не задевая частных лиц. Дальше мы прогоним его по нескольким платформам и разберём, как отличать настоящую находку от ложной.

## Шаг 1: одна платформа — через API

Самый надёжный способ проверить, занят ли ник, — не парсить HTML страницы, а спросить **API**: он отдаёт чистый ответ.

```
$ curl -s https://api.github.com/users/nasa | jq '{login,type,name,blog,location,public_repos,created_at}'
{
  "login": "nasa",
  "type": "Organization",
  "name": "NASA",
  "blog": "https://www.nasa.gov/software",
  "location": "United States of America",
  "public_repos": 632,
  "created_at": "2011-06-13T22:19:22Z"
}
```

Аккаунт есть: тип `Organization`, имя `NASA`, 632 публичных репозитория. Заодно мы получили **связи** — блог `nasa.gov`, локацию, дату регистрации. Так один ник даёт сразу несколько зацепок для других веток.

Если бы ника не было, GitHub вернул бы **404** — и это был бы честный ответ «не занят».

## Шаг 2: много платформ — массовая проверка

Проверять руками десятки сайтов долго. Поэтому ники гоняют **скриптом**, который по списку шаблонов URL делает запрос и смотрит код ответа. Вот маленький такой скрипт (его суть — в таблице «шаблон → код»):

```python
import urllib.request
nick = "nasa"
sites = {
  "GitHub":   "https://github.com/{u}",
  "GitLab":   "https://gitlab.com/{u}",
  "Reddit":   "https://www.reddit.com/user/{u}/about.json",
  "Mastodon": "https://mastodon.social/@{u}",
  "Telegram": "https://t.me/{u}",
}
for name, tpl in sites.items():
    url = tpl.format(u=nick)
    try:
        code = urllib.request.urlopen(urllib.request.Request(
            url, headers={"User-Agent": "Mozilla/5.0"}), timeout=10).status
    except urllib.error.HTTPError as e:
        code = e.code
    print(name, code, url)
```

Реальный вывод на нике `nasa`:

```
GitHub             200  https://github.com/nasa
GitLab             403  https://gitlab.com/nasa
Reddit             403  https://www.reddit.com/user/nasa/about.json
Mastodon(social)   200  https://mastodon.social/@nasa
Telegram           200  https://t.me/nasa
```

Читаем коды, и здесь — главная ловушка урока.

## Шаг 3: 200 ≠ «нашли», 403 ≠ «не нашли»

Код ответа **нельзя** трактовать в лоб:

- `200` — страница существует. Обычно значит «ник занят». Но у некоторых сайтов страница-заглушка «пользователь не найден» тоже отдаёт 200.
- `404` — почти всегда «ник свободен».
- `403` — **не** «не найден», а «доступ запрещён»: это антибот-защита (WAF) отбила скрипт. GitLab и Reddit выше вернули 403 именно поэтому, а не потому, что ника нет.

Именно из-за этого появляются **ложные срабатывания**. Готовые инструменты — `Sherlock` и `Maigret` — решают эту проблему двумя приёмами: (1) держат базу «какой признак на этом сайте означает „найден“», и (2) сравнивают ответ с эталонным «пустым» ответом. Всё, что похоже на заглушку, отбрасывается.

```
$ sherlock nasa --print-found
[*] Checking username nasa on:
[+] GitHub: https://www.github.com/nasa
[+] Mastodon: https://mastodon.social/@nasa
[+] Telegram: https://t.me/nasa
```

(вывод сокращён — реальный прогон добавляет ещё десятки площадок.)

## Шаг 4: подтверждение находки

Ник — это ещё не человек. Прежде чем считать, что `nasa` на Reddit и `nasa` на GitHub — один и тот же субъект, ищите **корреляции**: один и тот же аватар (сравните хэш файла картинки), одинаковые ссылки в описании профиля, совпадающие даты активности. Совпадение ника — гипотеза; совпадение ника **плюс** аватара **плюс** ссылки — уже версия.

Полезный приём: найти **уникальную** строку из профиля (имя, домен, строку из био) и прогнать её дорком в поисковике — так иногда вылезают связанные аккаунты, которые не поймал скрипт.

## Как устроена база признаков

Готовый инструмент — это, по сути, большой справочник, где для каждой площадки описаны три вещи: шаблон URL, способ проверки и признак «найден». Упрощённо это выглядит так:

```json
{
  "GitHub": {
    "url": "https://github.com/{username}",
    "checkType": "status_code",
    "found": 200
  },
  "Reddit": {
    "url": "https://www.reddit.com/user/{username}/about.json",
    "checkType": "message",
    "found": "reddit.com/user"
  }
}
```

Второй способ — `message` — надёжнее кода ответа: инструмент ищет в теле ответа строку-маркер (например, ссылку на профиль) и только тогда объявляет находку. Именно поэтому Maigret точнее «наивного» скрипта с одними статус-кодами: он не полагается на один лишь `200`.

## Полный прогон от начала до конца

1. Дано: ник `nasa`.
2. Спрашиваем API GitHub → аккаунт есть, это организация, есть блог и локация.
3. Прогоняем массовую проверку → ещё Mastodon и Telegram.
4. Видим 403 у GitLab/Reddit → помечаем как «непроверяемо скриптом», а не «нет».
5. Подтверждаем связь через уникальные строки профиля.

## Если не сработало

- **Ник занят, но чужой.** Проверьте, не переиспользован ли ник случайным человеком: сравнивайте аватары и стиль.
- **Всё отдаёт 403.** Снизьте темп запросов (пауза между ними) или возьмите API вместо HTML.
- **Ник занят только на одном сайте.** Это не провал: иногда «след» из одного аккаунта даёт уникальную строку, которая тянет остальные.
- **Скрипт сыпет «найдено» на всё подряд.** Проверьте его на заведомо свободном нике вроде `zzqqxx998877` — если он «находит» и его, признак подобран неверно.
- **Платформа не в списке инструмента.** Добавьте свою запись вручную: URL и признак обычно очевидны за минуту.

## Что мы теперь знаем

1. Ник проверяют по списку шаблонов URL, лучше — через API, а не HTML.
2. `200` не гарантирует «нашли», `403` не значит «нет» — нужен разбор ложных срабатываний.
3. Инструменты Sherlock/Maigret держат базу признаков для каждой площадки.
4. Находку подтверждают корреляцией (аватар, ссылки, уникальные строки).

## На что смотреть дальше

- **Не доверяйте одному совпадению ника.** Совпадение имени — самое слабое доказательство.
- **Сохраняйте доказательства.** Скриншот профиля с датой и URL — иначе находку не защитить в отчёте.
- **Уважайте границы.** Сбор публичных профилей — разведка; вход в чужой аккаунт — уже атака.
- **Помните про приватность.** Иногда ник ведёт на «закрытый» профиль — сам факт существования тоже информация.

## Разбор кейса: 403 значит занят

Проверка ника по платформам кажется простой, но коды ответов обманчивы. Разберём.

Первый шаг — прямая проверка на одной платформе через API или URL профиля. Второй шаг — массовая проверка (sherlock, maigret) по сотням платформ. Третий шаг — интерпретация. `200` — профиль есть. `404` — нет. `403` — часто значит, что профиль существует, но закрыт. Пустая страница или редирект — тоже сигнал. Четвёртый шаг — подтверждение. Найденный профиль проверь вручную: аватар, активность, совпадение с другими признаками.

## Мини-практика: подтверждение находки

Прогони ник по списку платформ. Для каждого «найденного» открой профиль и проверь, что он непустой и не заглушка. Запиши только подтверждённые. Отметь, на каких платформах профиль активен, а где пустой.

## Если что-то не вышло

**Все 404.** Ник не используется или платформа не в списке.

**Много 403.** Часть платформ блокирует анонимов. Проверяй вручную.

**Ложные 200.** Заглушка «пользователь не найден». Смотри содержимое.

**Совпадения ников.** Распространённые ники у многих. Подтверждай признаками.

## Частые вопросы

**Что такое sherlock?** Инструмент массовой проверки ников по платформам.

**Почему 403 важен?** Он часто означает «занят, но закрыт» — профиль существует.

**Как снизить ложные?** Проверять содержимое страницы, а не только код ответа.

## Вопросы и ответы

**Почему 403 не значит «не найден»?** Код 403 означает «доступ запрещён»: профиль, скорее всего, существует, но закрыт от анонимного просмотра. Считать его «не найденным» — распространённая ошибка, из-за которой теряются реальные находки.

**Как отличить настоящий профиль от заглушки?** Открой страницу и посмотри содержимое: аватар, описание, активность. Заглушка «пользователь не найден» часто отдаёт 200, но пустой шаблон, поэтому проверяй тело ответа, а не только код.

**Что делать с распространёнными никами?** Добавляй признаки: аватар, город, ссылки, тематику. Один ник без подтверждений — слабая связь; ник плюс два независимых признака — уже сильная гипотеза.

**Зачем нужны sherlock и maigret?** Они проверяют ник по сотням платформ автоматически и собирают кандидатов. Но результат — это список для ручной проверки, а не готовый вывод: инструменты дают ложные срабатывания.

**Как не нарушить ToS при массовой проверке?** Проверяй публичные страницы, не создавай массовых аккаунтов и не обходи капчу. Уважай лимиты платформ, иначе твой IP или аккаунт заблокируют, а работа встанет.

**Что делать с найденными профилями?** Зафиксируй URL, дату, признаки совпадения и уровень уверенности. Для отчёта важна проверяемость, а не количество ссылок: лучше пять подтверждённых, чем пятьдесят сомнительных.

## Куда дальше

Теперь у нас есть ник и список площадок. Дальше мы разберём каждую ветку социальных сетей отдельно: как устроены профили, что дают API и как из одного аккаунта вытащить связи и геолокацию. А пока главное запомни: ник — это гипотеза, а не доказательство, и настоящую находку делают корреляции.

## Где пригодится

- **CTF (OSINT):** деанон по нику из задания.
- **Bug bounty:** поиск профилей разработчиков и утечек.
- **Threat intel:** связывание аккаунтов атакующего.
- **HR/верификация:** проверка цифрового следа (в рамках закона).
