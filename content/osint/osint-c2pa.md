## Вопрос, с которого всё начинается

Тебе прислали фотографию «с места события». В эпоху генеративного ИИ главный вопрос уже не «что на фото», а «откуда оно и не сгенерировано ли». Есть стандарт, который пытается ответить на это криптографически, — **C2PA** (Coalition for Content Provenance and Authenticity), он же **Content Credentials**.

Задача: прочитать манифест C2PA и понять, кто создал файл, чем и какие правки вносил — и, главное, где предел этих гарантий.

## Наш пример: манифест файла

Держим объект `manifest.json` — выдержку из C2PA-манифеста, встроенного в файл `press-photo.jpg`. Первый вопрос: **что он утверждает о происхождении?**

```bash
python3 -c "import json;print(json.load(open('manifest.json')))"
```

```text
{'claim_generator': 'Adobe_Photoshop/25.0 c2pa-rs/0.25',
 'assertions': [{'label': 'c2pa.actions', 'data': {'actions': [
    {'action': 'c2pa.created'},
    {'action': 'c2pa.edited', 'digitalSourceType': 'trainedAlgorithmicMedia'}]}}],
 'signature': {'alg': 'ES256', 'issuer': 'Example Newsroom Signing CA'}}
```

Читаем: `claim_generator` — чем файл обрабатывался, `actions` — что с ним делали, `signature` — кто и чем подписал манифест. Здесь видно и создание (`c2pa.created`), и редактирование с пометкой `trainedAlgorithmicMedia` — то есть файл частично сгенерирован ИИ. Это ровно то, что C2PA и призван раскрывать.

## Шаг 1: что такое C2PA

C2PA — открытый стандарт, который встраивает в медиафайл подписанный «сертификат происхождения». Он описывает цепочку: кто создал контент, каким устройством или программой, какие правки вносились. Манифест хранится в контейнере (обычно JUMBF) и подписан сертификатом издателя. Ключевое слово — **подписан**: манифест можно проверить криптографически, и подделать его без ключа нельзя.

Стандарт поддерживают Adobe (Photoshop, Lightroom), производители камер (например, Leica), а также генераторы ИИ — они помечают синтетику. Поэтому C2PA стал основой «Content Credentials» — значка происхождения, который можно увидеть в интерфейсе.

## Шаг 2: как читать манифест

Манифест состоит из нескольких частей. `claim_generator` — инструмент, создавший или изменивший файл. `assertions` — утверждения: действия (`c2pa.actions`), авторство, источник. `signature` — алгоритм и сертификат подписи. `ingredients` — исходные файлы, из которых собран результат.

```bash
python3 -c "import json;d=json.load(open('manifest.json'));print([a['label'] for a in d['assertions']])"
```

```text
['c2pa.actions', 'stds.schema-org.CreativeWork']
```

Список утверждений сразу показывает, что нам сообщают: какие действия и кто автор. Для проверки важнее всего `actions` — там видно, был ли файл сгенерирован, отредактирован или только снят.

## Шаг 3: проверка подписи

Манифест имеет смысл только если подпись действительна. Инструмент `c2patool` (или библиотека c2pa) проверяет цепочку сертификатов и целостность:

```bash
# иллюстративно
c2patool press-photo.jpg
# → Validation: signature valid, issuer: Example Newsroom Signing CA
```

Если подпись не сходится, файл изменили после подписи — значит, манифесту верить нельзя. Если подписи нет вовсе, у файла просто нет Content Credentials; это **не** доказательство подделки.

## Шаг 4: границы доверия

Главная ловушка C2PA — ложное чувство определённости. Отсутствие манифеста ничего не доказывает: файл мог пройти через соцсеть, которая вырезала метаданные. Наличие подписи доказывает лишь то, что подписант заявил о происхождении; если подписант врёт или скомпрометирован, C2PA это не поймает. Поэтому C2PA — один из многих сигналов, а не приговор.

Мы читаем манифест и проверяем подпись. Мы **не делаем вывод «подделка» только потому, что манифеста нет**. Вывод строится на совокупности: C2PA, метаданные, визуальные артефакты, контекст публикации.

## Полный прогон

```bash
# 1. прочитать манифест
python3 -c "import json;print(json.load(open('manifest.json'))['claim_generator'])"
# → Adobe_Photoshop/25.0 c2pa-rs/0.25
# 2. действия
python3 -c "import json;print(json.load(open('manifest.json'))['assertions'][0]['data']['actions'])"
# → [{'action': 'c2pa.created'}, {'action': 'c2pa.edited', ...}]
# 3. подпись
python3 -c "import json;print(json.load(open('manifest.json'))['signature'])"
# → {'alg': 'ES256', 'issuer': 'Example Newsroom Signing CA'}
```

Непрерывно: файл → манифест → генератор → действия → подпись → вывод о происхождении.

## Если не сработало

**Манифеста нет.** Файл мог пройти через соцсеть — это не доказательство подделки.
**Подпись не сходится.** Файл изменили после подписи — манифесту верить нельзя.
**Только часть данных.** Некоторые редакторы сохраняют не весь манифест — читай то, что есть.

## Частые ошибки

**Ошибка: считать отсутствие C2PA подделкой.** Метаданные вырезаются постоянно.
**Ошибка: доверять манифесту без проверки подписи.** Без подписи это просто текст.
**Ошибка: игнорировать `actions`.** Именно там видно генерацию и правки.
**Ошибка: забывать про `ingredients`.** Исходные файлы раскрывают, из чего собран результат.

## Справочная таблица: поля манифеста

| Поле | Значение |
|------|----------|
| `claim_generator` | программа, создавшая/изменившая файл |
| `assertions` | утверждения: действия, авторство, источник |
| `c2pa.actions` | что делали с файлом |
| `ingredients` | исходные файлы |
| `signature` | алгоритм и сертификат подписи |

## Разбор кейса: сгенерированное фото в новостях

Дано: фото `press-photo.jpg` из новостной рассылки. Шаг первый — извлекаем манифест, `claim_generator` = Photoshop. Шаг второй — в `actions` видим `c2pa.edited` с `digitalSourceType: trainedAlgorithmicMedia`. Шаг третий — проверяем подпись: действительна, издатель — ньюзрум. Вывод: файл отредактирован и частично сгенерирован ИИ, о чём честно заявлено. Для редакции это основание перепроверить материал, а для разведчика — пример того, как C2PA раскрывает синтетику.

## Рабочий воркбук: полное расследование происхождения

**Этап 1. Извлечение.** Достань манифест C2PA из файла (c2patool, exiftool, python-библиотека).

**Этап 2. Генератор.** Посмотри `claim_generator`: камера, редактор или генератор ИИ.

**Этап 3. Действия.** Разбери `actions`: создание, редактирование, генерация. Отметь `digitalSourceType`.

**Этап 4. Подпись.** Проверь цепочку сертификатов. Недействительная подпись — красный флаг.

**Этап 5. Контекст.** Сопоставь с другими сигналами: метаданные, визуальные артефакты, источник публикации.

## Частые вопросы

**Что такое C2PA простыми словами?** Подписанный «паспорт» медиафайла, описывающий его происхождение и правки.

**Обязателен ли C2PA?** Нет, это добровольный стандарт. Его отсутствие нормально.

**Можно ли подделать манифест?** Подпись подделать без ключа нельзя, но можно подписать ложные утверждения.

**Где хранится манифест?** Обычно в контейнере JUMBF внутри файла.

**Это законно?** Читать и проверять метаданные — да; это стандартная верификация.

## Термины

**C2PA** — стандарт происхождения контента.

**Content Credentials** — пользовательское название манифестов C2PA.

**JUMBF** — контейнер, в котором хранится манифест.

**Assertion** — утверждение в манифесте (действие, авторство).

**trainedAlgorithmicMedia** — признак ИИ-генерации.

## Что мы теперь знаем

1. C2PA встраивает подписанный манифест происхождения.
2. `claim_generator` и `actions` рассказывают историю файла.
3. Подпись проверяется криптографически.
4. Отсутствие манифеста не доказывает подделку.
5. C2PA — один сигнал из многих.
