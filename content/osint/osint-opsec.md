OSINT — это про наблюдение за другими. Но наблюдение оставляет следы **на вас**: поисковики логируют запросы, сайты пишут IP, а в bug bounty «свой» профиль, замеченный в разведке цели, может обернуться баном или юридическими вопросами. OPSEC (Operational Security) — это дисциплина защиты собственной личности и данных в ходе разведки. В этом уроке — практические меры от базовых до продвинутых, модель угроз и разобранный пример.

## Модель угроз разведчика

Прежде чем что-то настраивать, определите, **от кого** вы защищаетесь:

- **От цели:** чтобы она не увидела, что её изучают (особенно перед пентестом).
- **От платформ:** чтобы поисковики/соцсети не связали ваш аккаунт с интересом к цели и не забанили.
- **От третьих лиц:** чтобы ваши находки (ПДн) не утекли и не скомпрометировали вас.
- **От деанонимизации:** чтобы по стилю, времени, ошибкам вас не связали с основной личностью.

Уровень мер пропорционален риску: для CTF достаточно гигиены, для расследований против сильного противника — изоляция и Tor.

### Атака на OPSEC: как вас деанонимизируют

- **Переиспользование аккаунта:** один и тот же email/ник в «личном» и «рабочем» контексте.
- **Утечки браузера:** cookies, localStorage, canvas-фингерпринт, WebRTC (реальный IP за VPN!).
- **Метаданные файлов:** ваш GPS/имя пользователя в отправленном файле.
- **Временные паттерны:** активность в одни часы, совпадающая с вашим часовым поясом.
- **Стилометрия:** одинаковые опечатки, обороты, форматирование.
- **Платёжные следы:** оплата сервисов личной картой.

## Базовый уровень (гигиена)

Подходит для CTF и большинства bug bounty:

1. **Отдельный браузер/профиль** для OSINT. Не смешивайте с личным.

```bash
firefox -P osint --no-remote
# или Chromium-профиль:
chromium --user-data-dir=$HOME/.config/osint-profile
```

2. **Отключите WebRTC** (утечка реального IP) — расширение `WebRTC Leak Prevent` или `media.peerconnection.enabled=false` в `about:config`.
3. **Блокировщики:** uBlock Origin, Privacy Badger. Уменьшают трекинг.
4. **Менеджер паролей** для уникальных паролей sock-аккаунтов (Bitwarden/KeePassXC).
5. **Отдельный email** для регистраций (не личный).

## Средний уровень (разделение личностей)

Для чувствительной разведки используйте **sock puppets** — легендированные аккаунты:

- **Устойчивая легенда:** имя, биография, интересы, история активности. Не «пустышка на один день».
- **Прогрев аккаунта:** подписки, лайки, репосты за недели до использования.
- **Отдельные контакты:** уникальный email (ProtonMail/Tutanota), уникальный телефон (виртуальный номер), отдельный браузер.
- **Уникальные аватары** (не стоковые, иначе свяжут с другими).
- **Не пересекайте легенды:** разные sock puppets не должны «дружить» друг с другом без причины.

Изоляция на уровне ОС — лучший вариант:

```bash
# отдельная ВМ (VirtualBox/QEMU) или контейнер на каждую личность
# всё внутри ВМ: браузер, аккаунты, файлы
```

## Продвинутый уровень (сетевая анонимность)

- **VPN + Tor.** VPN скрывает от провайдера, Tor — от сайта. Цепочка: `user → VPN → Tor → сайт`.

```bash
sudo apt install -y tor torbrowser-launcher
# для CLI-запросов через Tor SOCKS5:
curl --socks5-hostname 127.0.0.1:9050 -s https://check.torproject.org/api/ip
# {"IsTor":true,"IP":"185.x.x.x"}
```

- **Whonix/Tails** — ОС, маршрутизирующие весь трафик через Tor; Tails не оставляет следов на диске.
- **Прокси-цепочки** для массовых запросов (ротация IP), но помните: публичные прокси логируют.
- **Проверка утечек IP:** `ipleak.net`, `browserleaks.com`. Всегда проверяйте, что реальный IP не течёт (WebRTC, DNS).

```bash
# проверка, что DNS не течёт
dig +short TXT whoami.cloudflare @1.1.1.1
# и что curl идёт через Tor
curl --socks5-hostname 127.0.0.1:9050 -s https://api.ipify.org
```

## Защита собранных данных

- **Шифруйте находки:** VeraCrypt/`gocryptfs` для контейнера с ПДн.

```bash
gocryptfs -init ~/vault_cipher && gocryptfs ~/vault_cipher ~/vault
```

- **Не храните лишнее.** Удаляйте ПДн, как только цель достигнута (требование GDPR/152-ФЗ).
- **Метаданные исходящих файлов:** всегда чистите свои:

```bash
exiftool -all= -overwrite_original file.pdf
mat2 file.pdf      # анонимизация метаданных
```

- **Каналы связи:** для передачи находок — шифрованные (Signal, age/PGP).

## Разобранный пример: разведка без «палева»

Задача: изучить соцсети цели, не засветив основную личность.

Шаг 1 — изолированная среда:

```bash
firefox -P osint --no-remote   # отдельный профиль, без личных cookies
```

Шаг 2 — проверка утечек IP:

```text
Открой ipleak.net и browserleaks.com/webrtc
Убедись: IP = VPN/Tor, WebRTC не показывает реальный IP
```

Шаг 3 — sock puppet для платформ, требующих логина. Прогретый аккаунт с легендой.

Шаг 4 — вся активность через VPN/Tor (если цель чувствительна):

```bash
torsocks curl -s "https://target.example/profile" -o page.html
```

Шаг 5 — сохранение находок в зашифрованный контейнер, чистка метаданных при выгрузке.

Шаг 6 — после завершения: удалить лишние данные, зафиксировать только необходимое.

## Частые ошибки

- **Смешивать личности.** Один раз зашли в личный аккаунт из OSINT-браузера — и связь установлена.
- **Забыть про WebRTC.** VPN не спасает, если браузер отдаёт локальный/реальный IP через WebRTC.
- **Использовать стоковые аватары.** Их легко связать между sock puppets.
- **Свежий «пустой» аккаунт.** Мгновенно выглядит подозрительно; легенду надо прогреть.
- **Логин в личные сервисы через Tor.** Многие сервисы блокируют/флагают Tor-вход.
- **Хранить ПДн без шифрования.** Утечка = ваша юридическая ответственность.
- **Игнорировать стилометрию.** Стиль письма и опечатки выдают автора.

## Изоляция окружения: практические конфигурации

Надёжнее всего — изолировать не «профиль браузера», а всю среду:

- **Виртуальная машина** (VirtualBox/QEMU) на каждую личность. Снапшот до начала работы: после сессии откат — никаких следов.

```bash
# клонируем чистую ВМ под новую личность
VBoxManage clonevm osint-base --name osint-sock1 --register
VBoxManage snapshot osint-sock1 take clean
```

- **Отдельная виртуальная сеть** (NAT/host-only) — чтобы активность не пересекалась с основной машиной.
- **Whonix** — двух-ВМ схема: Gateway (весь трафик через Tor) + Workstation (рабочая среда). Приложение не знает своего реального IP.
- **Tails** — live-ОС, вся память стирается при выключении; persistent volume — зашифрованный.
- **Контейнеры (Docker)** — лёгкая изоляция для инструментов, но сеть всё равно надо маршрутизировать через Tor.

## Комплаенс, законность и этика

OPSEC — это ещё и юридическая гигиена:

- **Собирайте только публичное.** Доступ к закрытым ресурсам без разрешения — нарушение (CFAA и аналоги).
- **Минимизация данных.** Не храните ПДн дольше необходимого (GDPR, 152-ФЗ).
- **Не выдавайте себя за другого** в мошеннических целях — это уже не OSINT.
- **Согласие на пентест.** В рамках авторизованной работы цель знает о ней; в bug bounty — соблюдайте scope и правила программы.
- **Документируйте легальность** каждого действия — это защита и вас, и заказчика.

## Проверка собственного цифрового следа

Перед разведкой проверьте, что вы сами не «светитесь»:

- **Утечки:** `haveibeenpwned.com`, DeHashed по своим адресам.
- **Поиск себя:** `site:linkedin.com "Ваше Имя"`, поиск по уникальным никам.
- **Метаданные своих файлов:** `exiftool -a -G1 photo.jpg` — нет ли GPS/имени.
- **Утечки IP/фингерпринта:** browserleaks.com (WebRTC, canvas, DNS).
- **Историю:** проверьте старые аккаунты, которые могут связать личности.

## Быстрый чек-лист OPSEC

Перед сессией разведки пройдите список:

1. Определена модель угроз и выбран уровень мер.
2. Открыт **отдельный** профиль/ВМ, личные аккаунты не тронуты.
3. WebRTC отключён; ipleak.net показывает ожидаемый IP.
4. Для чувствительных целей трафик идёт через VPN/Tor; DNS не течёт.
5. Для платформ, требующих логина, готов прогретый sock puppet.
6. Находки пишутся в зашифрованный контейнер с провенансом.
7. Исходящие файлы очищены от метаданных.
8. После сессии — снапшот откачен, лишние ПДн удалены.

## Инструменты OPSEC: сводка

| Задача | Инструмент |
|---|---|
| Изоляция браузера | Firefox Multi-Account Containers, отдельный профиль |
| Блокировка утечек | uBlock Origin, WebRTC Leak Prevent |
| Анонимная сеть | Tor Browser, Whonix, Tails |
| Проверка утечек IP | ipleak.net, browserleaks.com |
| Виртуальные номера | сервисы виртуальных SIM/VoIP |
| Анонимная почта | ProtonMail, Tutanota |
| Шифрование данных | VeraCrypt, gocryptfs |
| Очистка метаданных | exiftool, mat2 |
| Менеджер паролей | Bitwarden, KeePassXC |

Держите инструменты **раздельно по личностям**: пароли, почта, номера и браузеры не должны пересекаться, иначе вся конструкция рушится об одну случайную связку.

## Что дальше / решение

OPSEC — это не пара инструментов, а **дисциплина**: разделение личностей, изоляция среды, проверка утечек и защита данных на каждом шаге. Дальше: практикуйте **создание sock puppets** (урок про sock puppets), **верификацию личности** и **защиту источников**. Итог: перед любой разведкой задайте модель угроз и уровень мер — «гигиена» для CTF и «изоляция + Tor» для расследований; одна утечка IP или один личный логин сводит на нет всю анонимность.

## Где пригодится

- **CTF (OSINT):** безопасный сбор данных без риска для реальных аккаунтов.
- **Bug bounty:** не засветить свой профиль перед программой и не получить бан.
- **Пентест:** скрыть активность разведки от цели перед авторизованной атакой.
- **Расследования:** защита источников и собственной личности.
- **Повседневная приватность:** понимание собственного цифрового следа.
