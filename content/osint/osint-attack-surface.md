## Вопрос, с которого всё начинается

Ты собрал кучу всего: 5 доменов, 312 поддоменов, 40 IP, 40 сотрудников, десятки аккаунтов. Всё это лежит в разных файлах и заметках. И теперь главный вопрос: что со всем этим делать? Как увидеть картину целиком и понять, куда смотреть в первую очередь?

Ответ — свести находки в единую **карту поверхности атаки**. Разберём, как это делается.

## Наш пример: карта для example.com

Введём термин. **Цифровой след** (digital footprint) — совокупность всех активов и данных, связанных с целью. **Карта поверхности атаки** — это граф: узлы (активы) и рёбра (связи между ними). Ключевая мысль: **рёбра важнее узлов**, потому что именно они показывают, как активы относятся к цели.

## Шаг 1: собираем активы по уровням

Все находки распределяются по уровням:

| Уровень | Примеры активов |
|---|---|
| Домены | example.com, дочерние, аффилированные |
| Поддомены | api., dev., admin., mail. |
| IP/ASN | диапазоны, облачные IP |
| Сервисы | порты, технологии, API |
| Данные | утечки, документы, метаданные |
| Люди | сотрудники, руководители, подрядчики |
| Аккаунты | GitHub, соцсети, репозитории |
| Облака | S3, Azure, GCS, CI/CD |

## Шаг 2: устанавливаем связи

Рёбра графа — это отношения между узлами:

| Связь | Как установлена |
|---|---|
| domain → subdomain | DNS |
| subdomain → IP | A/CNAME |
| IP → ASN | BGP |
| domain → domain | tracking ID, сертификат |
| person → account | email/username pivot |
| account → org | bio, коммиты |
| domain → technology | фингерпринт |

У каждого ребра есть **уверенность**: подтверждено / вероятно / возможно.

## Шаг 3: собираем всё в одну структуру

Минимальные поля узла: `id, type, value, source, confidence, first_seen, parent, notes`. Складываем в один CSV:

```
d1,domain,example.com,whois,confirmed,2026-10-01,,головной
s1,subdomain,api.example.com,crt.sh,confirmed,2026-10-01,d1,
i1,ip,203.0.113.42,dig,confirmed,2026-10-01,s1,
p1,person,Ivan Petrov,linkedin,likely,2026-10-02,,devops
a1,account,ipetrov-dev,github,likely,2026-10-02,p1,
t1,tracking,GTM-5XW2K9,html,confirmed,2026-10-01,d1,связывает 4 домена
```

Проверим целостность — нет ли «висячих» родителей:

```python
import csv
rows = list(csv.DictReader(open("assets.csv")))
ids = {r["id"] for r in rows}
for r in rows:
    if r["parent"] and r["parent"] not in ids:
        print("DANGLING PARENT:", r["id"], "->", r["parent"])
```

## Шаг 4: собираем данные по шагам

Для `example.com` проходим ветки:

```bash
# домены и поддомены
subfinder -d example.com -all -silent | sort -u > subs.txt
curl -s "https://crt.sh/?q=%25.example.com&output=json" | jq -r '.[].name_value' | sort -u >> subs.txt
# IP/ASN
for h in $(cat subs.txt); do dig +short "$h"; done | sort -u > ips.txt
# технологии
httpx -l subs.txt -tech-detect -sc -silent > live.txt
```

Найденный **tracking ID** (`GTM-5XW2K9`) связывает ещё 4 домена — это ребро `domain → domain`, которого не видно из DNS.

## Шаг 5: приоритизируем

Карта бесполезна без приоритетов:

| Критерий | Высокий приоритет |
|---|---|
| Доступность | из интернета |
| Критичность | auth, admin, api, CI/CD |
| Защищённость | dev/staging, устаревший стек |
| Данные | БД, бэкапы, секреты |
| Аномальность | «забытые» поддомены |

```bash
grep -iE 'dev|staging|admin|api|jenkins|gitlab|internal|old|backup' live.txt
```

## Шаг 6: переводим карту в план

Строим «дерево целей»: **цель → активы → слабые места → векторы**:

```
Цель: доступ к внутренней сети
├── Актив: dev.example.com (открыт)
│   ├── Слабость: PHP 5.6 (EOL)
│   └── Вектор: RCE через известную CVE
├── Актив: GitHub-орг (публичная)
│   ├── Слабость: секреты в истории коммитов
│   └── Вектор: утечка токена CI
└── Люди: DevOps-инженеры
    └── Вектор: фишинг (в рамках авторизации)
```

Такое дерево превращает карту в план действий.

## Шаг 7: визуализируем граф

Graphviz из списка рёбер:

```bash
cat > map.dot <<'EOF'
digraph G {
  rankdir=LR;
  "example.com" -> "api.example.com";
  "api.example.com" -> "203.0.113.42";
  "Ivan Petrov" -> "ipetrov-dev";
  "ipetrov-dev" -> "api.example.com" [label="commits"];
}
EOF
dot -Tsvg map.dot -o map.svg
```

Для больших графов — Gephi (сила-направленная раскладка) или Maltego.

## Шаг 8: экспортируем для разных потребителей

- **JSON/CSV** — для машинной обработки и импорта в инструменты.
- **GEXF/GraphML** — для Gephi и Maltego.
- **SVG/PNG** — для отчёта и презентации.
- **Markdown** — для текстового отчёта.

Единый формат (например, **STIX 2.1** для threat intel) позволяет обмениваться картой с другими командами.

## Шаг 9: обновляем карту

Карта — живой артефакт. Поверхность меняется, карта устаревает:

```bash
subfinder -d example.com -silent | sort -u > new.txt
diff old.txt new.txt   # появились новые поддомены? notify!
git add assets.csv && git commit -m "surface snapshot $(date +%F)"
```

История изменений показывает рост или сокращение поверхности и помогает вовремя заметить теневые активы.

## Что мы теперь знаем

- Карта поверхности атаки — граф узлов и рёбер; рёбра важнее узлов.
- Каждое ребро имеет уровень уверенности.
- Все находки сводятся в единую таблицу с provenance.
- Приоритизация по доступности, критичности, защищённости и аномальности.
- Карта обновляется регулярно и версионируется.

## Частые ошибки

- **Собирать без структуры.** Хаос находок не даёт картины.
- **Игнорировать уверенность связей.** Принять ложное ребро за факт.
- **Забывать про людей.** Человеческий фактор часто главный вектор.
- **Не приоритизировать.** Карта из 400 узлов без приоритетов бесполезна.
- **Путать владение с присутствием.** Актив на общем IP не значит «принадлежит цели».
- **Не обновлять карту.** Поверхность меняется; карта устаревает.

## На что смотреть дальше

Картирование — финальный, синтезирующий этап OSINT: все предыдущие ветки сходятся здесь. Дальше остаётся **отчётность** — оформление карты для заказчика, и **верификация** спорных связей. А пока главное запомни: единый граф активов с уровнями уверенности и приоритетами — это и есть цифровой след цели.

## Куда дальше

Мы свели разрозненные находки в единый связный граф. Дальше — **отчётность**: как оформить результат так, чтобы им воспользовались. А пока главное запомни: карта отвечает на три вопроса — что принадлежит цели, как это связано и куда смотреть первым.

## Где пригодится

- **Bug bounty:** карта in-scope активов для планомерного поиска.
- **Пентест:** определение периметра и приоритетов до атаки.
- **Threat intelligence:** понять внешнюю поверхность атаки организации.
- **Blue team/ASM:** управление собственной поверхностью атаки.
- **Red team:** выбор вектора первоначального доступа.
