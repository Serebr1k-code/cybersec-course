Картирование поверхности атаки (attack surface mapping) — финальный, синтезирующий этап OSINT. Все предыдущие ветки дали разрозненные находки: домены, IP, поддомены, люди, аккаунты, утечки, технологии. Задача этого этапа — **свести их в единую, связную карту** организации или человека и расставить приоритеты. Хорошая карта отвечает на вопросы: что принадлежит цели, как это связано, где слабые места и куда смотреть в первую очередь.

## Теория: что такое цифровой след

Цифровой след (digital footprint) — это совокупность всех активов и данных, связанных с целью. Уровни:

| Уровень | Примеры активов |
|---------|-----------------|
| Домены | example.com, дочерние, аффилированные |
| Поддомены | api., dev., admin., mail. |
| IP/ASN | диапазоны, облачные IP |
| Сервисы | порты, технологии, API |
| Данные | утечки, документы, метаданные |
| Люди | сотрудники, руководители, подрядчики |
| Аккаунты | GitHub, соцсети, репозитории |
| Облака | S3, Azure, GCS, CI/CD |

Карта — это **граф**: узлы (активы) и рёбра (связи). Рёбра важнее узлов: именно они показывают, как активы относятся к цели.

## Типы связей (рёбра графа)

| Связь | Как установлена |
|-------|-----------------|
| domain → subdomain | DNS |
| subdomain → IP | A/CNAME |
| IP → ASN | BGP |
| domain → domain | tracking ID, сертификат |
| person → account | email/username pivot |
| account → org | bio, коммиты |
| domain → technology | фингерпринт |
| asset → leak | утечка |

Каждое ребро имеет **уверенность** (см. `osint-identity-resolution`): подтверждено/вероятно/возможно.

## Сбор данных в одну структуру

Практика: все находки складываются в единую таблицу/граф. Минимальные поля узла:

```
id, type, value, source, confidence, first_seen, notes
```

Пример строк:

```
example.com,domain,example.com,whois,confirmed,2026-10-01,
api.example.com,subdomain,api.example.com,crt.sh,confirmed,2026-10-01,
93.184.216.34,ip,93.184.216.34,dig,confirmed,2026-10-01,
ivan@example.com,email,ivan@example.com,linkedin,likely,2026-10-02,
```

Из этой таблицы строится граф в Maltego или Graphviz.

## Инструменты картирования

| Инструмент | Роль |
|-----------|------|
| Maltego | граф активов и трансформы |
| SpiderFoot | автоматический сбор + граф |
| recon-ng | модульная разведка + БД |
| BloodHound (AD) | граф внутренней сети |
| Gephi / Graphviz | визуализация графа |
| `jq` + CSV | структурирование находок |
| Obsidian/Notion | база знаний с [[связями]] |

Maltego удобен для ручной работы: перетаскиваете узел, применяете трансформу, получаете новые узлы с рёбрами. SpiderFoot автоматизирует: собирает из десятков источников и рисует граф.

## Приоритизация

Карта бесполезна без приоритетов. Критерии:

| Критерий | Высокий приоритет |
|----------|-------------------|
| Доступность | из интернета |
| Критичность | auth, admin, api, CI/CD |
| Защищённость | dev/staging, устаревший стек |
| Данные | БД, бэкапы, секреты |
| Связи | ведёт к другим активам |
| Аномальность | «забытые» поддомены |

```bash
# фильтр приоритетных поддоменов
grep -iE 'dev|staging|admin|api|jenkins|gitlab|internal|old|backup' live.txt
```

## Разобранный пример: карта компании

Дано: `example.com`, программа bug bounty.

Шаг 1 — домены:

```bash
subfinder -d example.com -all -silent | sort -u > subs.txt
curl -s "https://crt.sh/?q=%25.example.com&output=json" | jq -r '.[].name_value' | sort -u >> subs.txt
```

Шаг 2 — «соседи» по tracking ID:

```
GTM-5XW2K9 → ещё 4 домена (example-shop.net, example-labs.io, ...)
```

Шаг 3 — IP/ASN:

```bash
for h in $(cat subs.txt); do dig +short "$h"; done | sort -u > ips.txt
# whois -h whois.radb.net -- '-i origin AS12345'
```

Шаг 4 — технологии:

```bash
httpx -l subs.txt -tech-detect -sc -silent > live.txt
```

Шаг 5 — люди:

```
LinkedIn: 40 сотрудников → 12 email-паттерн → GitHub-аккаунты → коммиты
```

Шаг 6 — сведение в граф (узлы: 5 доменов, 312 поддоменов, 40 IP, 40 человек, 12 аккаунтов; рёбра: DNS, tracking, ASN, employment).

Итог: карта из ~400 узлов и связей, приоритизированная по критериям. Дальше — проверка приоритетных активов.

## Форматы представления

- **Граф** (Maltego/Graphviz) — для связей.
- **Таблица/CSV** — для активов.
- **Дерево** — для структуры доменов.
- **Таймлайн** — для истории (Wayback, даты сертификатов).
- **Отчёт** — для заказчика (см. `osint-reporting`).

```bash
# Graphviz из рёбер
echo 'digraph G { "example.com" -> "api.example.com"; }' > g.dot
dot -Tpng g.dot -o map.png
```

## Ошибки и подводные камни

- **Собирать без структуры.** Хаос находок не даёт картины.
- **Игнорировать уверенность связей.** Принять ложное ребро за факт.
- **Забывать про людей.** Человеческий фактор — часто главный вектор.
- **Не приоритизировать.** Карта из 400 узлов без приоритетов бесполезна.
- **Путать владение с присутствием.** Актив на общем IP не значит «принадлежит цели».
- **Не обновлять карту.** Поверхность меняется; карта устаревает.

## Что дальше / решение

Картирование — финал OSINT-фазы. Дальше: **отчётность** (`osint-reporting`) для оформления, **верификация** (`osint-verification`) для проверки спорных связей, и переход к активной разведке/эксплуатации (в рамках авторизации). Итог: единый граф активов с уровнями уверенности и приоритетами — это и есть цифровой след цели, готовый к использованию.

## Практика: единая база находок

Структурируем всё в один CSV/JSON. Схема узла:

```
id,type,value,source,confidence,first_seen,parent,notes
```

Пример заполнения из разных веток:

```
d1,domain,example.com,whois,confirmed,2026-10-01,,головной
s1,subdomain,api.example.com,crt.sh,confirmed,2026-10-01,d1,
i1,ip,203.0.113.42,dig,confirmed,2026-10-01,s1,
p1,person,Ivan Petrov,linkedin,likely,2026-10-02,,devops
a1,account,ipetrov-dev,github,likely,2026-10-02,p1,
t1,tracking,GTM-5XW2K9,html,confirmed,2026-10-01,d1,связывает 4 домена
```

Скрипт проверки целостности графа:

```python
import csv
rows = list(csv.DictReader(open("assets.csv")))
ids = {r["id"] for r in rows}
for r in rows:
    if r["parent"] and r["parent"] not in ids:
        print("DANGLING PARENT:", r["id"], "->", r["parent"])
```

## Метрики поверхности атаки

Измеримые метрики для отчёта:
- **Количество активов** по типам (домены, поддомены, IP, сервисы).
- **Доля приоритетных** (dev/staging/admin).
- **Устаревшие технологии** (по фингерпринту).
- **Утечки** (секреты, PII).
- **Теневые активы** (не в инвентаре владельца).

Эти метрики позволяют сравнить организации и отследить динамику во времени.

## Интеграция с ASM-практиками

Attack Surface Management (ASM) — регулярный процесс: сканируй → картир→ отслеживай изменения → устраняй. OSINT-карта — вход ASM. Автоматизируйте:

```bash
# еженедельный снимок поддоменов + diff
subfinder -d example.com -silent | sort -u > new.txt
diff old.txt new.txt   # появились новые? notify!
```

Инструменты мониторинга: `notify`, `amass db`, `SecurityTrails API`.

## Карта для человека vs организации

Картирование различается по объекту:

**Организация:**
- домены и поддомены, облака, CI/CD;
- сотрудники и их аккаунты;
- утечки и документы;
- цепочки поставщиков.

**Человек:**
- аккаунты и ники;
- email/телефон;
- геолокация (дом, работа);
- круг общения;
- привычки/расписание.

Для организации карта — граф инфраструктуры; для человека — граф идентичностей. Инструменты общие, акценты разные.

## Приоритизация через «дерево целей»

Строим дерево: **цель → активы → слабые места → векторы**:

```
Цель: доступ к внутренней сети
├── Актив: dev.example.com (открыт)
│   ├── Слабость: PHP 5.6 (EOL)
│   └── Вектор: RCE через известную CVE
├── Актив: GitHub-орг (публичная)
│   ├── Слабость: секреты в истории коммитов
│   └── Вектор: утечка токена CI
└── Люди: DevOps-инженеры
    ├── Слабость: корпоративные email в LinkedIn
    └── Вектор: фишинг (в рамках авторизации)
```

Такое дерево переводит карту в план действий.

## Метрики и отчёт

Финальные артефакты:
- **Карта** (граф/таблица).
- **Список приоритетных активов.**
- **Метрики поверхности** (количество, доля приоритетных).
- **Рекомендации** по каждому активу.

## Экспорт и передача карты

Форматы для разных потребителей:
- **JSON/CSV** — для машинной обработки и импорта в другие инструменты.
- **GEXF/GraphML** — для Gephi/Maltego.
- **SVG/PNG** — для отчёта и презентации.
- **Markdown** — для текстового отчёта.

```bash
# экспорт узлов и рёбер в CSV для дальнейшей обработки
awk -F',' 'NR>1{print $1","$2","$3","$5}' assets.csv > nodes.csv
```

Единый формат (например, STIX 2.1 для threat intel) позволяет обмениваться картой с другими командами.

## Обновление и жизненный цикл карты

Карта — живой артефакт. Настройте регулярное обновление:
- **cron** с еженедельным сканом поддоменов;
- **diff** против предыдущего снимка;
- **уведомления** о новых активах (`notify`);
- **версионирование** карты (git).

```bash
git add assets.csv && git commit -m "surface snapshot $(date +%F)"
git diff HEAD~1 -- assets.csv   # что изменилось с прошлой недели
```

История изменений показывает рост/сокращение поверхности и помогает вовремя заметить тене-активы.

## Где пригодится

- **Bug bounty:** карта in-scope активов для планомерного поиска.
- **Пентест:** определение периметра и приоритетов до атаки.
- **Threat intelligence:** понять внешнюю поверхность атаки организации.
- **Blue team/ASM:** управление собственной поверхностью атаки.
- **Red team:** выбор вектора первоначального доступа.
