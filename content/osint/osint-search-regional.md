Google — не единственный и не всегда лучший поисковик. Для целей в России, Китае, Корее или Чехии **региональные системы** индексируют больше локального контента, лучше понимают язык и хранят данные, которых нет в западных индексах. Для OSINT это означает: если вы ищете человека, компанию или событие в конкретной стране, начинайте с её поисковика, а Google — дополнение, а не наоборот.

## Зачем региональные поисковики

Причины три. Первая — **покрытие**: Baidu индексирует китайские сайты, которые Google либо не индексирует, либо удаляет; Яндекс лучше видит российский сегмент. Вторая — **языковая морфология**: русский и китайский требуют иной обработки словоформ, и региональные движки делают это точнее. Третья — **локальные фичи**: Яндекс.Картинки, Wordstat, Baidu Baike (энциклопедия), Naver Blog/Café (огромные UGC-платформы). Игнорировать их — терять половину источников.

## Яндекс

Крупнейший русскоязычный поисковик. Возможности:

- **Операторы**: `site:`, `host:`, `url:`, `title:`, `mime:`, `date:`, `lang:`, кавычки для точной фразы.
- **Яндекс.Картинки** — поиск по изображению и «похожие».
- **Wordstat** (`wordstat.yandex.ru`) — статистика запросов, полезна для понимания терминологии.
- **Яндекс.Карты** — панорамы, организации, отзывы.
- **Поиск по блогам и соцсетям** (в т.ч. по VK/Telegram-контенту).

```
# Пример дорочного запроса
site:company.ru (filetype:pdf OR filetype:xlsx) ("конфиденциально" OR "для служебного пользования")
title:"отчёт" site:company.ru date:2023..
```

Яндекс строже к некоторым техникам, но часто находит то, что Google «потерял» в русском сегменте.

## Baidu

Китайский поисковик с уникальным индексом. Особенности:

- **Baidu Baike** — китайская «Википедия», часто с деталями о людях/компаниях.
- **Baidu Maps** — карты и панорамы Китая.
- **Baidu Tieba** — форумы; **Baidu Wenku** — документы (аналог Scribd).
- **Операторы**: `site:`, `intitle:`, `inurl:`, `filetype:`, `-` (исключение), кавычки. Синтаксис отличается от Google, многие операторы работают иначе.
- **Кодировка**: результаты в UTF-8, но URL часто с percent-encoding китайских символов.

Для целей в Китае Baidu обязателен: он видит Weibo, WeChat-контент (частично), китайские форумы.

## Naver

Корейский портал — не только поиск, но и **платформа**: Naver Blog, Naver Café, Naver News, Naver Map, Papago (перевод). Корейский контент почти не индексируется Google. Операторы: `site:`, `inurl:`, кавычки; есть отдельный поиск по блогам и кафе. Для OSINT по Корее — первый инструмент.

## Язык и кодировка

Ключ к региональному поиску — **правильные ключевые слова на языке страны**. Транслитерация почти бесполезна: ищите имя по-русски/по-китайски/по-корейски. Для китайского — упрощённые и традиционные формы, пиньинь; для корейского — хангыль и романизация; для русского — падежи (движок морфологичен, но точные фразы в кавычках работают иначе). Автоматизация: запросы URL-кодируются (`urllib.parse.quote`), а результаты парсятся с учётом языка.

```python
import urllib.parse
q = 'Иванов Иван site:vk.com'
print(urllib.parse.quote(q))  # %D0%98%D0%B2%D0%B0%D0%BD%D0%BE%D0%B2...
```

## Разобранный пример: поиск человека в русском сегменте

1. Начинаем с Яндекса: `"Иван Иванов" site:vk.com`.
2. Уточняем город: `"Иван Иванов" (Москва OR СПб)`.
3. Ищем упоминания в новостях: `"Иван Иванов" site:news.ru OR site:rbc.ru`.
4. Проверяем изображения через Яндекс.Картинки (поиск по лицу/похожим).
5. Дополняем Google для англоязычных упоминаний.
6. Для Китая/Кореи повторили бы с Baidu/Naver и локальным написанием имени.

## Подводные камни

- **Слепая транслитерация.** «Ivan Ivanov» в Baidu не сработает; нужно «伊万·伊万诺夫».
- **Разные операторы.** Синтаксис Google не всегда переносится.
- **Геоблокировки.** Часть сервисов недоступна без местного IP.
- **Кэш и устаревание.** Региональные индексы обновляются по-разному.
- **Цензура/удаление.** Контент может исчезнуть из одного движка, но остаться в другом/архиве.
- **Приватность запросов.** Логируйте/проксируйте запросы, если работаете под легендой.

## Автоматизация регионального поиска

Ручной поиск по пяти движкам быстро утомляет, поэтому его автоматизируют. Простейший путь — скрипт, который формирует запросы под каждый движок и сохраняет выдачу. Важно уважать `robots.txt` и лимиты: агрессивный скрапинг приведёт к блокировке и капче. Более надёжный путь — официальные/полуофициальные API: у Яндекса есть XML/JSON-поиск (Search API), у Bing — Azure Cognitive Search, у Brave — Search API. Для Baidu/Naver публичных API почти нет, поэтому используют headless-браузер (Playwright/Selenium) с человеческими задержками.

```python
# Скелет: запрос к нескольким движкам (псевдокод)
import requests, urllib.parse, time
queries = {
  "yandex":  "https://yandex.ru/search/?text={q}",
  "bing":    "https://www.bing.com/search?q={q}",
  "ddg":     "https://html.duckduckgo.com/html/?q={q}",
}
for name, tpl in queries.items():
    url = tpl.format(q=urllib.parse.quote('"Иван Иванов" vk.com'))
    r = requests.get(url, headers={"User-Agent": "Mozilla/5.0"})
    print(name, r.status_code, len(r.text))
    time.sleep(3)
```

При автоматизации обязательно меняйте язык (`Accept-Language`), учитывайте геолокацию (прокси в стране цели) и логируйте запросы — иначе легко «спалить» легенду.

## Региональные соцсети и мессенджеры

Поисковики — лишь вход. Основной контент лежит в **локальных платформах**: VK, Odnoklassniki, Telegram (RU); Weibo, WeChat, Zhihu, Douyin (CN); Naver Blog, KakaoStory (KR); Line (JP/TW). Их поиск отличается от западного:

- **VK** — расширенный поиск по людям (город, вуз, возраст), поиск по постам и сообществам.
- **Weibo** — микроблог, поиск по хэштегам и пользователям; иероглифы обязательны.
- **Zhihu** — Q&A-платформа (аналог Quora), ценный источник экспертизы.
- **Douyin/TikTok** — видео; геолокация и звук как идентификаторы.
- **KakaoStory/Naver Blog** — корейский UGC, почти невидимый для Google.

Для OSINT это означает: сначала определите, где цель «живёт», затем используйте локальный поиск этой платформы, а не универсальный.

## Лаборатория: кросс-языковой поиск

1. Возьмите вымышленное имя (или публичную фигуру) и составьте варианты: латиница, кириллица, иероглифы, хангыль.
2. Для каждого варианта прогоните запрос через соответствующий движок (Яндекс/Baidu/Naver).
3. Сравните выдачу: где больше релевантного, где — нет.
4. Добавьте оператор `site:` под локальные соцсети.
5. Сохраните результаты и составьте таблицу «движок → что нашлось».
6. Сделайте вывод, какие движки обязательны для вашей цели.

Упражнение показывает, что «правильный» поисковик зависит от географии цели.
