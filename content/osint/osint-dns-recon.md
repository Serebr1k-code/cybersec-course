## Вопрос, с которого всё начинается

Ты нашёл домен `example.com` и хочешь понять, что за ним стоит. Новичок сразу запускает сканер портов по `example.com` — и упирается в один-единственный IP, за которым ничего интересного.

Правильный порядок другой: сначала выяснить, **какие имена и адреса вообще существуют**. За одним доменом обычно прячется целая семья поддоменов — и вот они-то и есть настоящая поверхность. Разберём это на одном домене.

## Наш пример: домен example.com

У нас один объект — `example.com`. Введём два термина. **DNS** (Domain Name System) — «телефонная книга» интернета: она переводит имена в IP-адреса. **Запись** — это отдельная строка в этой книге определённого типа.

Начнём с типов записей, потому что каждая отвечает на свой вопрос:

| Запись | Что означает |
|---|---|
| `A` / `AAAA` | IPv4 / IPv6 адрес, куда указывает имя |
| `CNAME` | псевдоним — выдаёт облако, CDN или SaaS |
| `MX` | почтовые серверы домена |
| `TXT` | служебные строки: SPF, верификации сервисов |
| `NS` | серверы имён — DNS-провайдер |
| `PTR` | обратная запись: IP → имя |

## Шаг 1: читаем основные записи

Основной инструмент — `dig`. Запросим сразу несколько типов:

```bash
dig example.com A +short
dig example.com NS +short
dig example.com MX +short
```

```
93.184.216.34
a.iana-servers.net.
b.iana-servers.net.
0 .
```

Из этого уже видно: один A-адрес, NS у IANA, а MX `0 .` означает «почта не принимается». Флаг `+short` даёт только суть — это удобно для скриптов.

## Шаг 2: TXT — самая информативная запись

Записи `TXT` часто недооценивают, а именно там лежит карта сервисов компании:

```bash
dig example.com TXT +short
```

```
"v=spf1 -all"
"google-site-verification=abc123..."
```

Строка `v=spf1` — это **SPF**: список хостов, которым разрешено слать почту от имени домена. Здесь `-all` означает «всем остальным запрещено» — это строгая политика. А `google-site-verification` показывает, что домен подтверждён в Google — значит, у компании есть аккаунт в Google Workspace.

Отдельно смотрим почтовую защиту:

```bash
dig _dmarc.example.com TXT +short
dig google._domainkey.example.com TXT +short
```

```
"v=DMARC1; p=reject; rua=mailto:dmarc@example.com"
"v=DKIM1; k=rsa; p=MIIBIjANBg..."
```

**DMARC** — это политика обработки писем, проваливших проверку: `p=reject` (отклонять) — сильная настройка, а `p=none` (не блокировать) — слабая и часто означает «настроили, но не довели до ума». **DKIM** — подпись писем; публичный ключ лежит в записи `selector._domainkey`.

## Шаг 3: пассивный сбор поддоменов

Теперь главное — найти поддомены. Есть два способа: **пассивный** и **активный**. Пассивный не посылает запросов к целевому DNS вообще: мы читаем чужие логи и базы. Это безопасно и незаметно.

Самый богатый источник — **Certificate Transparency** (CT), публичный журнал всех выпущенных TLS-сертификатов. Сервис `crt.sh` отдаёт имена из сертификатов:

```bash
curl -s "https://crt.sh/?q=%25.example.com&output=json" \
  | python3 -c 'import sys,json;print("\n".join(sorted({n for e in json.load(sys.stdin) for n in e["name_value"].split(chr(10))})))'
```

```
api.example.com
dev.example.com
mail.example.com
staging.example.com
www.example.com
```

Символ `%25` — это закодированный `%`, а `%.example.com` означает «любое имя в домене». Получаем сразу пять поддоменов, не коснувшись цели. То же делает `subfinder`, собирая данные из десятков источников:

```bash
subfinder -d example.com -silent | sort -u > subs.txt
```

## Шаг 4: проверяем wildcard перед активным брутфорсом

Прежде чем перебирать имена словарём, проверим **wildcard** — ситуацию, когда «существуют» вообще все имена. Проверяется случайным именем:

```bash
dig +short "random-$RANDOM.example.com"
```


Пусто — wildcard выключен, брутфорс имеет смысл. Если бы случайное имя вернуло IP, это означало бы, что зона отвечает на всё подряд, и перебор утонул бы в ложных срабатываниях. Активный перебор (например, `dnsx -d example.com -w wordlist.txt`) уже заметен на цели, поэтому применяйте его только при наличии основания и с малой нагрузкой.

## Шаг 5: приоритизация результатов

Сырой список имён нужно превратить в приоритеты. Сначала сгруппируем по IP — много имён на один адрес означает общий сервер:

```bash
for h in $(cat subs.txt); do
  ip=$(dig +short "$h" A | head -1)
  [ -n "$ip" ] && echo "$ip $h"
done | sort | tee ip_names.txt
```

Потом вытащим имена, которые обычно ведут к самым слабым местам:

```bash
grep -iE 'admin|dev|staging|test|internal|jenkins|git|vpn|api|db|jira|grafana' subs.txt
```

```
dev.example.com
staging.example.com
api.example.com
```

`dev` и `staging` — типичные среды с ослабленной защитой. Именно они чаще всего становятся входной точкой.

## Шаг 6: реверс DNS и соседи по хостингу

Обратная запись `PTR` переводит IP в имя и помогает найти «соседей» по хостингу:

```bash
dig -x 93.184.216.34 +short
whois 93.184.216.34 | grep -iE 'netname|origin|country'
```

```
netname: EXAMPLE-NET
origin: AS15133
country: US
```

Поле `origin: AS15133` — это **ASN** (номер автономной системы), идентификатор сети организации. По ASN можно получить **весь** диапазон адресов компании — это следующий шаг разведки (см. урок про BGP), который находит хосты, вообще не попавшие в DNS.

## Шаг 7: мониторим изменения

DNS живой: записи меняются. Сохраняйте срез и сравнивайте его при следующем прогоне:

```bash
dig +short example.com A > snapshot_$(date +%F).txt
diff snapshot_2026-09-01.txt snapshot_2026-10-01.txt
```

Появление нового поддомена или TXT-верификации сигналит о развёртывании нового сервиса — повод повторить разведку.

## Что мы теперь знаем

- `A`, `MX`, `NS`, `TXT` — база; `TXT` даёт карту сервисов и почтовую защиту.
- SPF, DKIM и DMARC показывают, насколько домен защищён от подделки писем.
- Пассивный сбор (CT, `subfinder`) не касается цели и даёт лучший старт.
- Wildcard проверяют случайным именем до активного брутфорса.
- Имена `dev`, `staging`, `admin` — приоритетные цели; ASN расширяет охват за пределы DNS.

## На что смотреть дальше

Разберись с **трансфером зоны** (`dig axfr`): открытый AXFR отдаёт всю зону целиком, но это редкость. Изучи **висячие CNAME** — псевдонимы на удалённые сервисы, которые дают subdomain takeover. И свяжи домен с инфраструктурой через Certificate Transparency и ASN-префиксы.

## Куда дальше

Мы собрали имена и записи домена. В следующем уроке — **сканеры интернета** (Shodan, Censys, FOFA): возьмём найденные IP и посмотрим, что за сервисы на них открыты, не сканируя цель напрямую. А пока главное запомни: сначала пассивно выясни, какие имена существуют, — и только потом трогай цель.

## Где пригодится

- **CTF:** расшифровка записей, поиск поддомена с флагом.
- **Bug bounty:** полный охват scope — поддомены часто входят в программу.
- **Пентест:** поиск dev и staging-сред с ослабленной защитой.
- **Blue team:** инвентаризация собственной внешней поверхности.
