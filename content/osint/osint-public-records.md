Государственные реестры — золотой стандарт OSINT: это официальные, юридически значимые данные, которые сложно подделать. Собственность, судебные дела, лицензии, регистрационные записи раскрывают связи, адреса и активы. В этом уроке — что доступно публично и как это искать, с учётом различий юрисдикций.

## Теория: категории реестров

- **Коммерческие:** регистрация компаний, директора, доли (см. osint-business-registry).
- **Собственность:** земельные кадастры, недвижимость, автотранспорт.
- **Судебные:** иски, банкротства, уголовные и гражданские дела.
- **Лицензии и разрешения:** оружие, алкоголь, профессиональные лицензии.
- **Выборы и финансы:** декларации, доноры, лоббисты.
- **Регистрация граждан:** ЗАГС, домовые книги (в РФ ограничены).

Доступность сильно различается: в США/UK многие реестры открыты, в РФ часть платные/закрытые. Поэтому сначала определите **юрисдикцию** — от неё зависит весь дальнейший маршрут.

## Инструменты и команды

Международные агрегаторы:

- **OpenCorporates** — компании мира.
- **OCCRP Aleph** — расследовательская база (документы, реестры, утечки), графовый поиск.
- **ICIJ Offshore Leaks** — офшоры (Panama/Paradise/Pandora Papers).
- **Investigative Dashboard** — каталог реестров по странам.

Судебные:

```text
site:courtlistener.com "Petrov"                 # США (PACER-подобное)
site:caselaw.nationalarchives.gov.uk "Petrov"   # UK
site:bsr.bundesanzeiger.de "Petrov"             # DE
```

Собственность (примеры):

```text
# UK land registry — через gov.uk (Land Registry, за плату)
# US county assessor — site:<county>.gov "Petrov"
# Росреестр — публичная кадастровая карта (ограниченно)
```

Лицензии:

```text
site:gov.uk "Petrov" licence
"Petrov" "liquor license" OR "firearms licence"
site:apps2.sos.state.tx.us "Petrov"   # пример реестра лицензий штата
```

Публичные декларации и финансы:

```text
site:opensecrets.org "Petrov"
site:followthemoney.org "Petrov"
```

## Разобранный пример: проверка компании и директора

Дано: компания `Example LLC`, директор `Иван Петров`.

Шаг 1 — OpenCorporates:

```text
https://opencorporates.com/companies?q=Example+LLC
```

Получаем юрисдикцию, номер регистрации, дату, статус, директоров.

Шаг 2 — ищем директора в судебных реестрах юрисдикции:

```text
"Иван Петров" court OR lawsuit OR bankruptcy
```

Шаг 3 — проверяем собственность: земельный кадастр/assessor по адресу компании.

Шаг 4 — лицензии: есть ли лицензии, привязанные к компании/лицу.

Шаг 5 — офшоры: ищем имя и компании в ICIJ Offshore Leaks.

Шаг 6 — сводим: официальные записи = высокая достоверность; фиксируем источники и даты.

## Продвинутые приёмы

- **Aleph:** связывает сущности из разных документов — мощный графовый поиск.
- **Адрес как ключ:** один адрес → много компаний/людей (общий офис = связь).
- **Номер регистрации:** однозначно идентифицирует компанию.
- **Даты:** изменения директоров и статусов показывают события.
- **Кадастр:** связь «человек ↔ недвижимость» часто публична.
- **Кросс-юрисдикция:** офшорные цепочки раскрываются сопоставлением реестров.
- **Судебные документы:** часто содержат адреса, телефоны и контрагентов, которых нет больше нигде.

## Верификация и достоверность

- **Первичный источник** (госреестр) > агрегатор > форум.
- Фиксируйте **дату** записи — реестры меняются.
- **Перекрёстная проверка**: минимум два независимых источника.
- Оценивайте по Admiralty (источник × информация).
- Сохраняйте **скриншот + ссылку + дату** — реестр может стать платным.

## Частые ошибки

- **Игнорировать юрисдикцию.** Один и тот же реестр работает по-разному в странах.
- **Считать данные свежими.** Реестры обновляются с задержкой.
- **Путать компании-тёзки.** Идентифицируйте по номеру регистрации.
- **Выходить за закон.** Часть реестров платные/ограниченные; не обходите.
- **Вера одному источнику.** Перекрёстно проверяйте минимум по двум.
- **Забывать про даты.** Без временной привязки запись бесполезна.

## Реестры по регионам

Практические источники по юрисдикциям:

| Регион | Ресурсы |
|---|---|
| США | SEC EDGAR, PACER/CourtListener, county assessor, state registries |
| UK | Companies House, Land Registry, Gazette |
| ЕС | национальные торговые реестры, EUIPO |
| РФ/СНГ | ЕГРЮЛ/ЕГРИП, kad.arbitr (суды), Росреестр |
| Офшоры | ICIJ Offshore Leaks, OpenCorporates |

Разные страны — разная открытость. Для РФ многие реестры платные/ограниченные; для США/UK многое бесплатно.

## От записи к выводам

Реестры ценны **связями**, а не отдельными фактами:

```text
человек → компания (директор) → адрес → другие компании (тот же адрес)
компания → судебные дела → контрагенты → новые люди
человек → недвижимость (кадастр) → география и активы
```

Стройте граф и ищите «узлы»: один адрес, объединяющий десятки фирм, — это либо массовый регистратор, либо реальная связь.

## Верификация и цепочка доказательств

Официальные записи — сильнейшее доказательство, но:

- **Фиксируйте дату** обращения (реестр меняется).
- **Сохраняйте скриншот/PDF** страницы (может стать платной/недоступной).
- **Ссылайтесь на номер регистрации/дела** — однозначная идентификация.
- **Разделяйте** факт (запись) и интерпретацию (связь).
- **Учитывайте юрисдикцию** — законность доступа и публикации.

## Ключевые реестры и их API

Публичные реестры — золото для построения корпоративной карты: кто владеет, кто директор, какие дочерние, какие адреса.

| Реестр | Что даёт | Доступ |
|--------|----------|--------|
| Companies House (UK) | директора, адреса, отчёты | бесплатный API |
| OpenCorporates | компании 140+ юрисдикций | API (freemium) |
| SEC EDGAR (US) | 10-K/10-Q, инсайдеры, дочки | бесплатный full-text API |
| GLEIF | LEI, структура владения | бесплатный API |
| OCCRP Aleph | расследования, документы | веб/API |
| ЕГРЮЛ/ЕГРИП (РФ) | юрлица, ИП, директора | веб/выписки |

```bash
# Companies House: поиск компании
curl -s "https://api.company-information.service.gov.uk/search/companies?q=example" \
  -u "$CH_KEY:" | jq '.items[] | {title, company_number, address}'
# офицеры компании
curl -s "https://api.company-information.service.gov.uk/company/12345678/officers" \
  -u "$CH_KEY:" | jq '.items[] | {name, role, appointed_on}'
```

## SEC EDGAR: full-text и структура

```bash
# full-text поиск (с 2001 г.)
curl -s "https://efts.sec.gov/LATEST/search-index?q=%22Example%20Corp%22&dateRange=custom" -H "User-Agent: research" | jq
# реальный endpoint
curl -s "https://efts.sec.gov/LATEST/search-index?q=example" -H "User-Agent: osint research contact@example.com"
# submissions компании (по CIK)
curl -s "https://data.sec.gov/submissions/CIK0000320193.json" -H "User-Agent: osint research" | jq '.filings.recent.form'
# EX-21 (список дочерних) ищется в 10-K
```

**EX-21** в 10-K перечисляет дочерние компании — это карта холдинга. Инсайдерские сделки (Form 4) показывают руководителей и их доли.

## GLEIF и цепочки владения

GLEIF даёт Legal Entity Identifier и связи «родитель/дочерняя»:

```bash
# найти LEI по имени
curl -s "https://api.gleif.org/api/v1/lei-records?filter[entity.legalName]=Example%20Corp" | jq '.data[].attributes.entity.legalName'
# связи (ultimate parent)
curl -s "https://api.gleif.org/api/v1/lei-records/<lei>/ultimate-parent" | jq
```

Так строится **структура владения**: конечный бенефициар, цепочка холдингов, офшорные звенья.

## Разобранный пример: от компании к людям и адресам

Дано: `Example Corp`.

1. OpenCorporates → номер компании и юрисдикция.
2. Companies House `officers` → директора и даты назначения.
3. Один директор связан ещё с 5 компаниями (поиск по имени) → группа.
4. SEC EDGAR → 10-K → EX-21 (дочерние) и адреса.
5. GLEIF → ultimate parent (материнская структура).
6. Адрес регистрации → спутниковый снимок/карты → физическое расположение (osint-satellite).
7. Свод: граф «люди ↔ компании ↔ адреса» с датами.

## Продвинутые приёмы

- **Директор как хаб**: ищите человека по имени во всех реестрах — часто один человек связывает десятки фирм.
- **Даты**: смена директора/адреса в дату X коррелирует с событием (M&A, скандал).
- **Номера**: VAT/LEI/company number — уникальные ключи для кросс-проверки между реестрами.
- **Документы**: годовые отчёты содержат адреса офисов, банки, аудиторов, дочерние.
- **OCCRP Aleph**: полнотекстовый поиск по утёкшим документам (Панамские бумаги и др.).

## Верификация и цепочка доказательств

Реестры бывают устаревшими/ошибочными. Проверяйте:

1. **Свежесть** — дата последней записи.
2. **Совпадение ключей** — один и тот же номер компании/LEI в разных источниках.
3. **Первичный источник** — сам реестр, а не агрегатор.
4. **Корроборация** — подтверждение из независимого источника (пресс-релиз, домен, LinkedIn).

```bash
# сохранить доказательство с хэшем и датой
curl -s "<registry-url>" -o record.json
sha256sum record.json >> evidence.sha256
date -u +"%Y-%m-%dT%H:%M:%SZ" >> evidence.log
```

## Реестры по регионам

| Регион | Реестр | Особенность |
|--------|--------|-------------|
| UK | Companies House | бесплатный, полный API |
| US | SEC EDGAR / state SoS | EDGAR — ценные бумаги; SoS — регистрация |
| EU | BRIS / национальные | доступ по юрисдикциям |
| РФ | ЕГРЮЛ/ЕГРИП | выписки, есть API-провайдеры |
| Офшоры | ICIJ Offshore Leaks | утечки, не официальный реестр |
| Мир | OpenCorporates / GLEIF | агрегация, LEI |

## Частые ошибки

- **Доверять агрегатору без первичного источника** — OpenCorporates может отставать.
- **Путать юрисдикции** — одинаковая компания в UK и US — разные юрлица.
- **Игнорировать даты** — «директор» мог уйти год назад.
- **Забыть про офшоры** — реальный владелец часто скрыт за номиналом (ищите в утечках ICIJ).
- **Публиковать ПДн без нужды** — директора — публичные фигуры, но минимизируйте (osint-legal-ethics).

## Где пригодится

- **CTF (OSINT):** подтвердить факт через официальный реестр.
- **Расследования:** установление связей и активов по официальным данным.
- **Due diligence:** проверка компаний и контрагентов.
- **Blue team/финмониторинг:** выявление подставных структур.
