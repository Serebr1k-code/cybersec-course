Identity resolution (разрешение идентичностей) — это методологический «клей» всей people-OSINT: превращение разрозненных цифровых следов (email, ники, аккаунты, телефоны, фото) в **доказанную атрибуцию** — утверждение «все эти аккаунты принадлежат одному человеку». Главная опасность здесь — ложное связывание: склеить два разных человека в одного. Поэтому разрешение идентичностей — это дисциплина **доказательства**, а не угадывания.

## Теория: идентификатор, аккаунт, личность

Разведём три уровня:
- **Идентификатор** — строка, по которой находят (email, ник, телефон, фото).
- **Аккаунт** — запись в сервисе (GitHub-профиль, Telegram-канал).
- **Личность** — реальный человек (или организация).

Задача — установить соответствие «аккаунт ↔ личность». Один человек может иметь 10 аккаунтов; один аккаунт может использоваться несколькими людьми (общий). Связь доказывается **корреляцией сигналов**.

## Типы коррелирующих сигналов

Чем сильнее сигнал, тем выше уверенность:

| Сигнал | Сила | Пример |
|--------|------|--------|
| Прямое заявление | средняя | «мой github — @x» в профиле |
| Общий email | высокая | восстановление ведёт на тот же адрес |
| Общий телефон | высокая | 2FA/верификация |
| Перекрёстная ссылка | высокая | аккаунт A ссылается на B и наоборот |
| Общий аватар | средняя | хэш/перцептивный хэш фото |
| Общий стиль/опечатки | средняя | уникальные ошибки, идиолект |
| Общая активность | средняя | активность в одни часы |
| Общий контент | средняя | те же тексты/файлы |
| Общий tracking ID | высокая | GA/GTM на личных сайтах |
| Общий PGP-ключ | очень высокая | криптографическая связь |

Правило: **два и более независимых сигнала** → уверенная атрибуция. Один сильный (PGP, email) может быть достаточен.

## Техники корреляции

**1. Username pivot.** Один ник прогоняется по всем платформам (см. `osint-username-enum`):

```bash
sherlock targetuser
maigret targetuser --html
```

**2. Email pivot.** Email → аккаунты (holehe) → профили → новые идентификаторы.

**3. Reverse image.** Аватар → другие профили с тем же фото (см. `osint-image-reverse`).

**4. PGP-ключ.** Если человек использует PGP, ключ — криптографический якорь:

```bash
gpg --search-keys target@example.com
```

Один ключ на нескольких адресах = доказанная связь.

**5. Стилометрия.** Анализ уникальных оборотов, опечаток, форматирования.

**6. Временные корреляции.** Активность в одних часовых поясах, синхронные посты.

## Разобранный пример: связываем три аккаунта

Дано: три аккаунта — GitHub `ipetrov-dev`, Twitter `@ivan_p`, Telegram `@ipetrov`.

Шаг 1 — username pivot:

```bash
sherlock ipetrov-dev
# [+] github.com/ipetrov-dev
# [+] gitlab.com/ipetrov-dev
# [+] reddit.com/user/ipetrov-dev
```

Шаг 2 — общий email в профилях:

```bash
curl -s https://api.github.com/users/ipetrov-dev | grep -i email
# "email": "i.petrov@example.com"
```

В Twitter-био: `mail: i.petrov@example.com`. Совпадение email — **высокий сигнал**.

Шаг 3 — общий PGP на личном сайте:

```bash
gpg --search-keys i.petrov@example.com
# pub rsa4096 2018-06-01 [SC] ... "Ivan Petrov <i.petrov@example.com>"
```

Шаг 4 — Telegram-био ссылается на GitHub `ipetrov-dev`. Перекрёстная ссылка — **высокий сигнал**.

Итог: 4 независимых сигнала (username, email×2, PGP, перекрёстная ссылка) → атрибуция уверенная.

## Модель уверенности

Присваивайте уровень каждой связи:

| Уровень | Критерий | Формулировка |
|---------|----------|--------------|
| Подтверждено | ≥2 независимых сильных сигнала | «аккаунты принадлежат одному лицу» |
| Вероятно | 1 сильный ИЛИ 2 слабых | «вероятно, один человек» |
| Возможно | 1 слабый сигнал | «возможно, связано» |
| Отвергнуто | противоречие | «разные лица» |

Противорtile: разные часовые пояса в постах, несовпадающие фото, разные языки, конфликт биографий.

## Инструменты

| Инструмент | Назначение |
|-----------|-----------|
| `sherlock` / `maigret` | username → аккаунты |
| `holehe` | email → регистрации |
| `GHunt` | Google-аккаунт |
| Maltego | граф связей |
| `gpg --search-keys` | PGP-якорь |
| `exiftool` | метаданные фото |
| `h8mail` | email + утечки |

Maltego особенно удобен: узлы (email, ник, телефон) и трансформы строят визуальный граф связей.

## Ошибки и подводные камни

- **Склеивать по одному слабому сигналу.** Общий ник `admin` — не атрибуция.
- **Игнорировать противоречия.** Нашли конфликт — понизьте уверенность, не «списывайте» его.
- **Путать аккаунт и личность.** За аккаунтом может стоять команда.
- **Считать общий аватар доказательством.** Фото переиспользуют (мемы, сток).
- **Забывать про время.** Аккаунты могли быть проданы/переданы другому.
- **Не документировать сигналы.** Без записи «какой сигнал → какой вывод» атрибуция не проверяема.
- **Игнорировать этику.** Атрибуция может навредить невиновному при ошибке.

## Что дальше / решение

Разрешение идентичностей — финальный шаг people-OSINT. Дальше: **верификация** (`osint-verification`) для проверки выводов, **картирование поверхности атаки** (`osint-attack-surface`) для организации, и **отчётность** (`osint-reporting`) для документирования атрибуции с уровнями уверенности. Итог: соберите граф, присвойте каждой связи уровень уверенности, зафиксируйте сигналы — и вы получите атрибуцию, которую можно защитить, а не набор догадок.

## Практика: построение графа в Maltego

Maltego — основной инструмент разрешения идентичностей. Процесс:
1. Создаём сущность `Email` с адресом.
2. Применяем трансформу «Email to Person» / «Email to Accounts».
3. Из полученных аккаунтов — трансформы на связанные сущности.
4. Рёбра помечаем: подтверждено/вероятно.

Альтернатива — собственный граф в Python:

```python
import networkx as nx
G = nx.Graph()
G.add_node("i.petrov@example.com", type="email")
G.add_node("ipetrov-dev", type="account")
G.add_edge("i.petrov@example.com", "ipetrov-dev", signal="email_in_profile", conf=0.9)
G.add_node("Иван Петров", type="person")
G.add_edge("ipetrov-dev", "Иван Петров", signal="name_match", conf=0.7)
# визуализация
nx.write_gexf(G, "identities.gexf")
```

Файл `.gexf` открывается в Gephi для визуализации.

## Документирование атрибуции

Каждая связь фиксируется с сигналом и уверенностью:

| Узел A | Узел B | Сигнал | Уверенность |
|--------|--------|--------|-------------|
| email | GitHub | email в профиле | 0.9 |
| GitHub | Person | имя+компания | 0.7 |
| Telegram | GitHub | перекрёстная ссылка | 0.9 |

Такая таблица — основа защищаемого вывода. Без неё атрибуция = мнение.

## Обработка общих аккаунтов и организаций

Не всё сводится к «один человек — один аккаунт»:
- **Командные аккаунты** (`@company`, `info@`) — за ними несколько людей.
- **Боты и сервисные аккаунты** — не личность.
- **Общие устройства** — общий IP/устройство ≠ один человек.
- **Купленные аккаунты** — аккаунт сменил владельца.

Всегда уточняйте: атрибуция к **человеку** или к **организации**.

## Формулировки вывода

- **Подтверждено:** «Аккаунты X, Y, Z принадлежат одному лицу (сигналы: email, PGP, перекрёстные ссылки)».
- **Вероятно:** «Аккаунты, вероятно, связаны (общий аватар + стиль)».
- **Возможно:** «Возможная связь по совпадению ника; требует проверки».
- **Отвергнуто:** «Противоречия (разные часовые пояса, несовпадающие биографии) исключают связь».

Никогда не пишите «точно» без ≥2 сильных независимых сигналов.

## Стилометрия и поведенческие сигналы

Когда прямых сигналов нет, помогают косвенные:
- **Стиль письма:** уникальные обороты, опечатки, пунктуация.
- **Форматирование:** как человек расставляет пробелы, эмодзи.
- **Лексика:** профессиональный жаргон, диалект.
- **Время активности:** часовой пояс по постам.
- **Темы:** устойчивые интересы.

```python
# простая стилометрия: частотность слов
from collections import Counter
import re
def profile(text):
    words = re.findall(r'\w+', text.lower())
    return Counter(words).most_common(10)
a = profile(open("posts_a.txt").read())
b = profile(open("posts_b.txt").read())
print("A:", a[:5]); print("B:", b[:5])
```

Пересечение характерных слов — сигнал, но не доказательство.

## Работа с фото и аватарами

Аватар — частый связующий элемент:
- **Перцептивный хэш** (pHash) устойчив к сжатию: две копии фото дают близкий хэш.

```python
from PIL import Image
import imagehash
h1 = imagehash.phash(Image.open("av1.jpg"))
h2 = imagehash.phash(Image.open("av2.jpg"))
print("distance:", h1 - h2)   # малое расстояние → одно фото
```

- **EXIF** аватара может содержать имя устройства/автора.
- **Reverse image** находит другие профили с тем же фото (см. `osint-image-reverse`).

## Типичные ошибки атрибуции

- **Совпадение имени** `Иван Петров` — распространённое; нужен второй сигнал.
- **Общий город** — не связь.
- **Общий ник** `admin`/`dev` — не связь.
- **Совпадение аватара-мема** — не связь (мем используют многие).
- **Общий IP** — NAT/провайдер, не человек.

Правило: если сигнал может объясняться случайностью или массовым явлением — он слабый.

## Пример: связывание через общий домен

Если у человека личный сайт `ipetrov.dev`, домен — сильный якорь. WHOIS/CT раскрывают email регистранта, а сертификат — другие поддомены. Связка «аккаунт → личный домен → WHOIS email → PGP» даёт криптографически подтверждённую атрибуцию. Всегда проверяйте: домен зарегистрирован на того же человека или на приватный proxy (тогда сигнал слабее).

## Где пригодится

- **CTF (OSINT):** связать несколько аккаунтов, чтобы собрать флаг.
- **Расследования:** доказать, что аккаунты принадлежат одному лицу/группе.
- **Threat intelligence:** атрибуция аккаунтов угрозы (threat actor).
- **Bug bounty:** связать активы одного владельца.
- **Фактчекинг:** установить авторство контента.
