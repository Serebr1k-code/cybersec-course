Facebook — старейшая крупная соцсеть, поэтому здесь накоплен исторический слой данных: старые фото, группы, события, которые давно скрыты в других сетях. Приватность настроена строго, но публичные страницы, группы и кэш поисковиков дают многое. В этом уроке — методика сбора с акцентом на исторические и организационные данные.

## Теория: слои данных Facebook

- **Профили:** имя, фото, работа/учёба, город; приватность скрывает большую часть.
- **Страницы (Pages):** компании, бренды, публичны — посты, контакты, «О нас», отзывы.
- **Группы:** сообщества по интересам/отрасли; часто открытые, с обсуждениями стека.
- **События:** анонсы конференций/митапов → спикеры и их компании.
- **Мессенджер:** закрыт, но публичные ссылки `m.me` утекают в постах.
- **Исторический слой:** старые теги, чекины, «Друзья» видны в кэше поисковиков и Wayback.

Facebook Graph API сильно ограничен после 2018 года, поэтому основа — веб-поиск и архивы.

## Инструменты и команды

Поисковики — главный инструмент:

```text
site:facebook.com "Example Corp"
site:facebook.com/groups "example"
site:facebook.com/events "example"
site:facebook.com inurl:people "Иван Петров"
```

Публичная страница компании (без логина отдаёт базовое):

```bash
curl -s -A "Mozilla/5.0" "https://www.facebook.com/examplecorp/" | head
```

Wayback для исторических версий:

```bash
curl -s "http://archive.org/wayback/available?url=facebook.com/examplecorp" | jq
curl -s "http://web.archive.org/cdx/search/cdx?url=facebook.com/examplecorp&output=text&fl=timestamp,original&collapse=digest" | head
```

Инструменты корреляции:

- **WhoPostedWhat** (через API, ограничен) — поиск постов по дате.
- **intelx / sowsearch** — упоминания в открытых данных.
- **socialbearing / crowdtangle** (для страниц) — аналитика публичных постов.

## Facebook Ad Library и реклама

Ad Library (`facebook.com/ads/library`) — публичный каталог **всех** активных объявлений компании. Это недооценённый источник:

- Кто рекламируется и в каких странах.
- Тексты и креативы (иногда раскрывают продукты и планы).
- Даты запуска кампаний → периоды активности.
- Связанные страницы (у одного владельца часто несколько).

```text
facebook.com/ads/library/?q=Example%20Corp
```

Сопоставляя Ad Library с постами страницы, можно отделить официальные аккаунты от фейковых.

## Разобранный пример: сотрудники через группы и события

Дано: компания `Example Corp`.

Шаг 1 — официальная страница:

```text
site:facebook.com "Example Corp"
```

Смотрим «О нас»: адрес, сайт, телефон, часы работы.

Шаг 2 — события компании: конференции и митапы. Спикеры с должностями = сотрудники.

```text
site:facebook.com/events "Example Corp"
```

Шаг 3 — группы отрасли: сотрудники обсуждают внутренние проблемы, стек, вакансии. Поиск по ключевым словам:

```text
site:facebook.com/groups "Example Corp"
site:facebook.com/groups "Example Corp" (outage OR hiring OR vpn)
```

Шаг 4 — исторический слой через Wayback: старые версии страницы и профилей с открытыми данными (телефоны, email).

Шаг 5 — кросс-корреляция: имена из Facebook → LinkedIn/GitHub → email-паттерн.

Шаг 6 — граф связей (см. osint-social-media).

## Продвинутые приёмы

- **Чекины (Check-ins):** старые публичные чекины показывают места работы и встреч.
- **Фото-теги:** исторические теги связывают людей, даже если сейчас скрыты.
- **Комментарии к отзывам:** недовольные клиенты публикуют внутренние детали.
- **Номера телефонов:** `m.me` и старые посты «О нас» часто содержат прямой номер.
- **Реклама:** Facebook Ad Library (публичная) показывает активные объявления компании и их аудиторию.
- **Языковые группы:** локальные группы города дают геоконтекст сотрудников.
- **Отзывы (Reviews):** публичные жалобы содержат имена менеджеров и детали процессов.

## Graph API и его ограничения

Facebook Graph API после скандала с Cambridge Analytica сильно ограничен:

- Публичные данные о пользователях недоступны без явного согласия.
- Доступны в основном **страницы** и **публичные посты** владельцев.
- Для бизнес-задач — Marketing/Pages API с токеном.

Поэтому основная OSINT-работа идёт через **веб-поиск, архивы и группы**, а не через API. Не полагайтесь на Graph API как на основной инструмент.

## Группы и сообщества

Группы — самая богатая часть Facebook для OSINT:

- **Отраслевые группы**: обсуждение стека, вакансий, проблем.
- **Локальные группы города**: геоконтекст, упоминания компании.
- **Группы выпускников**: связи между людьми.
- **Buy/sell группы**: телефоны, адреса, имена.

```text
site:facebook.com/groups "example"
site:facebook.com/groups "example" (hiring OR outage OR vpn)
```

Собирайте имена участников и кросс-коррелируйте с LinkedIn/Instagram.

## Инструменты и исторический слой

- **Wayback Machine** — старые версии страниц/профилей (см. osint-wayback-archives).
- **intelx / sowsearch** — упоминания в открытых данных.
- **Facebook Ad Library** — публичная реклама компании.
- **CrowdTangle** (для исследователей) — аналитика публичных страниц.
- **Поисковики** — основной путь к публичным данным.

```bash
# снимки страницы в CDX-индексе Wayback
curl -s "http://web.archive.org/cdx/search/cdx?url=facebook.com/examplecorp&output=text&fl=timestamp,original&collapse=digest" | head
```

## Верификация и этические рамки

- **Однофамильцы:** подтверждайте личность минимум двумя независимыми признаками (фото + место работы + круг общения).
- **Скриншоты:** фиксируйте URL, дату и, если возможно, Wayback-ссылку — посты удаляются.
- **Только публичное:** не используйте чужие сессии и не запрашивайте доступ.
- **ПДн:** храните минимум, указывайте источник; GDPR/152-ФЗ никто не отменял.

## Что делать дальше / решение

- **Нужны сотрудники** → страница → события/спикеры → группы → кросс-корреляция.
- **Нужны контакты компании** → «О нас» + Ad Library + Wayback старых версий.
- **Нужен исторический контекст** → Wayback CDX по профилям и страницам.
- **Нужна атрибуция** → сравнить фото/имена с LinkedIn, GitHub, Instagram.

## Поиск людей и профилей

Встроенный Graph Search без логина недоступен, поэтому людей ищем через поисковики и косвенные следы. Рабочие операторы: `site:facebook.com inurl:people "<имя>"`, `site:facebook.com "<имя>" "<город>"`, `site:facebook.com "<email>"`. Связка `site:facebook.com "<номер телефона>"` часто находит профиль по контакту из объявления. Дополнительно подключайте Bing (у него есть `ip:` и `feed:`) и Yandex — он лучше индексирует VK и локальные посты. Внутри самого Facebook (при наличии аккаунта) работают фильтры «Люди», «Страницы», «Группы», «Места» и поиск по постам, но только для публичного контента. Если профиль закрыт, всё равно полезны превью: имя, аватар, число общих друзей и город — этого хватает для кросс-корреляции с LinkedIn.

## Верификация аккаунтов

Фейковые и заброшенные профили — норма, поэтому каждый аккаунт проверяется. Признаки «живого» официального представителя: верификационная галочка, ссылка на официальный сайт, давняя история постов, совпадение имени с реестром юрлица, наличие активных объявлений в Ad Library. Для персонального профиля — кросс-подтверждение минимум двумя независимыми признаками: фото (обратный поиск), место работы (LinkedIn), публикации (GitHub/СМИ). Всегда помечайте уровень уверенности и не стройте вывод на одном профиле.

## Частые ошибки

- Полагаться на Graph API — после 2018 он почти бесполезен.
- Скрейпинг с личного аккаунта — быстрый бан.
- Игнорировать исторический слой — а это главная ценность Facebook.
- Путать однофамильцев без второго независимого признака.
- Нарушать приватность и выходить за авторизованный scope.
- Забывать про Ad Library и отзывы — там контакты и детали процессов.

## Граф связей и кросс-платформенная корреляция

Отдельные профили бесполезны, пока не собраны в граф. Стройте узлы (люди, компании, события, места) и рёбра (дружба, тег, работа, совместное событие). Практический конвейер:

1. **Соберите людей** из событий, групп и тегов страницы.
2. **Для каждого** найдите кросс-ссылки: LinkedIn (работа), Instagram (фото), GitHub (код), VK (RU-контекст).
3. **Свяжите рёбрами**: общий работодатель, общий город, взаимные теги.
4. **Отметьте «хабы»** — людей с максимальным числом связей; обычно это HR, тимлиды или основатели.
5. **Визуализируйте** (Gephi, Maltego, даже ручная таблица) — граф выявляет скрытые связи.

```text
site:linkedin.com/in "Example Corp" "<имя из Facebook>"
site:instagram.com "<ник из Facebook>"
```

Кросс-подтверждение двумя платформами резко повышает уверенность атрибуции: совпадение фото + имени + места работы практически исключает однофамильца.

## Типичные CTF-задачи по Facebook

В CTF Facebook встречается реже LinkedIn, но задачи бывают такие: найти в старом посте упоминание флага; восстановить имя человека по аватарке и кросс-ссылке; определить место по геотегу чекина; связать фейковый аккаунт с настоящим через общие фото. Рецепт: `site:facebook.com "<подсказка>"` → открыть публичную страницу → Wayback-снимок (`web.archive.org/web/*/facebook.com/...`) → `grep -i flag` по тексту. Если страница закрыта — ищите её упоминания в Ad Library и в кэше поисковиков; иногда флаг лежит в описании страницы, которое видно без логина.

## Facebook для защиты бренда (blue team)

Компании стоит мониторить Facebook на предмет: фейковых страниц-двойников, публикации внутренних скриншотов, жалоб сотрудников с деталями инфраструктуры, утечек в группах. Практика: раз в неделю прогонять `site:facebook.com "<бренд>"` и Ad Library, сравнивать список официальных страниц с найденными. Найденные двойники — на репорт в Meta и в реестр фишинга. Отдельно отслеживайте посты с внутренними IP/доменами: они часто содержат скриншоты дашбордов, по которым восстанавливается стек.

## Где пригодится

- **CTF (OSINT):** историческая подсказка в старом посте или чекине.
- **Bug bounty:** контакты и структура компании для легитимного тестирования.
- **Расследования:** восстановление связей и событий из прошлого.
- **Blue team:** контроль того, что публикуется о компании в открытых группах.
