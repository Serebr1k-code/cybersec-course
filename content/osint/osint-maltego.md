## Вопрос, с которого всё начинается

Разведка быстро превращается в кашу из таблиц: где-то список поддоменов, где-то IP, где-то почты — и не видно, что с чем связано. Хочется увидеть картинку: вот домен, вот его поддомены, вот серверы, вот провайдер. Именно для этого придумали графовые среды вроде Maltego. Но чтобы ими пользоваться осознанно, надо понимать, что происходит «под капотом»: какие шаги превращают один узел в целую карту инфраструктуры.

Читателю уже знакомы CT-логи, DNS и идея графа связей. Здесь мы разберём, как из одного домена вырастает граф, и почему Maltego — это удобная обёртка над знакомыми нам шагами.

## Наш пример: цепочка «домен → инфраструктура»

Возьмём домен `example.com` и проследим типовую цепочку, которую Maltego запускает в один клик. На каждом шаге появляется новый тип узла, и мы будем собирать их в один граф.

Сначала — три слова, без которых урок не читается:

- **Сущность (entity)** — типизированный узел графа: `Domain`, `IPv4Address`, `EmailAddress`, `Person`, `AS`, `Netblock`.
- **Трансформ (transform)** — действие, которое берёт одну сущность и по внешнему источнику создаёт связанные. Например, `Domain → DNS Name`.
- **Граф** — то, что получается: узлы и связи между ними.

Maltego — это графическое Java-приложение, которое показывает граф и запускает трансформы мышкой. Мы же воспроизведём ту же цепочку консолью, чтобы увидеть, из чего она собрана.

## Шаг 1: сущность и первый трансформ

Начинаем с одной сущности — `Domain: example.com`. Первый трансформ — `To DNS Name`: он спрашивает у DNS и у CT-логов, какие имена существуют под этим доменом. Мы уже получали такой список ранее (сохранённый ответ CT-логов в `crtsh_example.json`):

```python
import json
subs = set()
for row in json.load(open("crtsh_example.json")):
    for name in row["name_value"].split("\n"):
        subs.add(name.strip().lower())
print(sorted(subs))
```

```
['api.example.com', 'dev.example.com', 'mail.example.com', 'staging.example.com', 'vpn.example.com', 'www.example.com']
```

Шесть имён. В терминах Maltego это шесть новых сущностей `DNSName`, выросших из одного `Domain`. Обратите внимание: трансформ не «выдумывает» данные — он ходит в конкретный источник (DNS, CT) и превращает ответ в узлы.

## Шаг 2: следующий трансформ — IP

На поддоменах запускаем `To IP Address` — резолвим имена в IP:

```python
import socket
for name in sorted(subs):
    try:
        for ip in socket.gethostbyname_ex(name)[2]:
            print(name, "->", ip)
    except socket.gaierror:
        print(name, "-> (не резолвится)")
```

```
api.example.com -> 198.18.0.18
dev.example.com -> 198.18.0.19
...
```

Появились сущности `IPv4Address`. Уже видно структуру: домен в центре, вокруг имена, за ними — адреса. Это и есть то, что Maltego рисует автоматически.

## Шаг 3: инфраструктура — AS и Netblock

На IP запускаются трансформы `To AS` и `To Netblock`. **AS (автономная система)** — это крупная сеть, управляемая одним провайдером и имеющая номер вида `AS12345`. **Netblock** — конкретный диапазон адресов внутри неё. Это отвечает на вопрос «чей это сервер»:

- `To AS` по IP → номер и владелец автономной системы;
- `To Netblock` → диапазон, которому принадлежит адрес.

Вместе они показывают провайдера: если это дешёвый «пуленепробиваемый» хостинг, это само по себе сигнал.

## Шаг 4: соседи по хостингу — Reverse DNS

Трансформ `Reverse DNS` (PTR-запись — обратное соответствие «IP → имя») возвращает все имена, привязанные к тому же IP. Это выявляет **соседей по хостингу** — чужие домены на том же сервере, которые могут быть связанными активами или точками перехода. Особенно ценны трансформы сертификатов: по одному сертификату из CT-логов вытаскиваются все имена, включая поддомены, которых нет в DNS-зоне.

## Шаг 5: собираем граф целиком

Теперь соберём всё в граф и сохраним в формате DOT (текстовый формат Graphviz — инструмента, который рендерит графы в картинки):

```python
import networkx as nx
G = nx.DiGraph()
for n in subs:
    G.add_edge("example.com", n)
print("nodes:", G.number_of_nodes(), "edges:", G.number_of_edges())
nx.drawing.nx_pydot.write_dot(G, "graph.dot")
```

```
nodes: 13 edges: 6
```

Тринадцать узлов (домен, шесть поддоменов, шесть IP) и шесть рёбер. Файл `graph.dot` начинается так:

```
strict digraph {
"www.example.com" [type=subdomain];
...
"example.com" -> "www.example.com";
"example.com" -> "api.example.com";
...
}
```

Читаем граф по-человечески: **кластеры** — инфраструктура одной организации, **изолированные узлы** — новые активы, которых мы раньше не видели, **узлы-хабы** (с максимумом связей) — ключевая инфраструктура. Именно хабы ищут в первую очередь: если один IP связан с дюжиной доменов, это общий сервер кампании.

В Maltego эти же узлы рисуются на полотне, а рёбра подписываются типом связи (`A`, `MX`, `CNAME`). Наш `graph.dot` можно открыть в Gephi или отрендерить в картинку — данные те же.

## Шаг 6: Community Edition и iTDS

Maltego поставляется в нескольких редакциях. **Community Edition (CE)** бесплатна, но урезана: ограничено число результатов на трансформ и недоступна часть серверных трансформов. Локальные (DNS-резолвинг, WHOIS, reverse DNS) работают без ключей, а «вкусные» источники (Shodan, VirusTotal) требуют API-ключа.

**iTDS (Transform Distribution Server)** — это сервер, который раздаёт трансформы команде. Свой трансформ — обычный HTTP-сервис: принимает сущность, возвращает список новых сущностей. Так оборачивают внутренние базы или кастомные API. Для масштабных задач Maltego сочетают с внешними скриптами: экспорт графа в GraphML и обработка в Python (networkx) — ровно то, что мы делали выше.

## Шаг 7: подводные камни

Главная ловушка графовых инструментов — **ложные связи**. Если два домена живут на одном CDN (Cloudflare, Akamai), трансформ «общий IP» соединит совершенно чужих клиентов. Поэтому перед выводом «это одна кампания» проверяют AS: если IP принадлежит крупному CDN, «соседи» ничего не значат.

Остальные грабли: CE урезана; серверные трансформы отправляют вашу цель третьим лицам (приватность); граф быстро зарастает шумом — фиксируйте гипотезы и отсекайте лишнее; активные трансформы, шлющие запросы к цели, применяйте только с авторизацией.

## Maltego и ручной OSINT

Стоит понимать, когда графовый инструмент уместен, а когда нет. Ручной подход (команды `dig`, `whois`, `curl` по одному источнику) даёт максимальную гибкость: вы лезете в нестандартные источники, которых нет среди трансформов. Maltego выигрывает в другом — в систематичности и наглядности: трансформы запускаются в один клик, а карта сохраняется и воспроизводится. На практике их сочетают: Maltego строит карту и показывает узлы-хабы, а ручной OSINT уточняет подозрительные связи. Если вам нужен разовый ответ на один вопрос — хватит консоли; если нужно регулярно обходить цель и видеть структуру — граф экономит часы.

## Что мы теперь знаем

- Граф собирается из типизированных сущностей (Domain, IPv4Address, AS) и связей.
- Трансформ — это шаг «взять сущность → спросить источник → создать новые сущности».
- Цепочка `Domain → DNS Name → IP → AS/Netblock → Reverse DNS` даёт карту инфраструктуры.
- Узлы-хабы показывают ключевую инфраструктуру; изолированные — новые активы.
- Ложные связи из-за CDN проверяются через AS.

## Куда дальше

В следующем уроке мы возьмём тот же сценарий «домен → отчёт», но соберём его в CLI-фреймворке recon-ng — там те же шаги превращаются в воспроизводимые скрипты и единую базу. А пока главное запомни: Maltego — это визуализация поверх знакомых трансформов, и качество графа зависит от того, насколько вы фильтруете ложные связи.

## Где пригодится

- **OSINT:** визуализация связей и инфраструктуры.
- **Пентест:** карта цели перед атакой.
- **Работа/SOC:** анализ связей инцидентов.
- **CTF:** графовый анализ для поиска ключевого узла.
