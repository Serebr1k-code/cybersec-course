Maltego — это среда для **визуального** OSINT-анализа. Вместо таблиц и логов вы строите граф из «сущностей» (домены, IP, люди, email, организации, телефоны) и «связей» между ними, а данные добываются через **трансформы** — плагины, которые по одной сущности находят другие. Это позволяет видеть структуру цели: как связаны домены, кто за ними стоит, где пересекаются инфраструктуры.

## Что такое Maltego

Maltego — Java-приложение (Community Edition бесплатна, с ограничениями) с графическим полотном. Основные понятия:

- **Entity** — типизированный узел: `Domain`, `IPv4Address`, `Person`, `EmailAddress`, `Company`, `PhoneNumber`, `AS`, `Netblock`, `Location` и др.
- **Transform** — действие, превращающее одну сущность в набор других (например, `Domain → DNS Name`, `Email → Breaches`).
- **Graph** — набор узлов и рёбер, который вы исследуете.
- **Machines** — цепочки трансформов, запускаемые «в один клик» для типового сценария.

## Трансформы

Трансформы бывают **локальными** (работают на вашей машине, бесплатны) и **серверными** (через iTDS — Maltego-сервер, часто платные/с API-ключами). Примеры бесплатных: DNS-резолвинг, WHOIS, поиск по crt.sh, Reverse DNS. Платные/серверные: Shodan, VirusTotal, HIBP, соцсети. Каждый трансформ «читает» входную сущность и создаёт выходные.

## Установка (Community Edition)

```bash
# Скачать с maltego.com, установить Java (JRE 11+)
# При первом запуске: Community Edition, регистрация бесплатная
# Публичные трансформы подключаются через "Transform Hub"
```

Community Edition ограничивает число результатов и часть серверных трансформов, но для базового recon хватает локальных + публичных.

## Разобранный пример: домен → инфраструктура

1. Создаём сущность `Domain: target.com`.
2. Запускаем трансформ `To DNS Name` — получаем поддомены.
3. На поддоменах — `To IP Address` — получаем IP.
4. На IP — `To Netblock` и `To AS` — выясняем провайдера и диапазон.
5. На IP — `Reverse DNS` — ищем соседей по хостингу (shared infra).
6. На домене — `To Email Address` (через whois/публичные источники) — находим контакты.
7. На email — трансформ утечек (если подключён HIBP) — ищем компрометации.
8. Сохраняем граф как отчёт; узлы-«хабы» показывают ключевую инфраструктуру.

## Полезные наборы трансформов

| Набор | Что даёт |
|---|---|
| DNS/WHOIS | Поддомены, IP, регистратор |
| crt.sh | Сертификаты и поддомены |
| Shodan | Открытые порты/баннеры |
| VirusTotal | Репутация, связи |
| HIBP | Утечки email |
| Social (Facebook/Twitter) | Связи людей |
| Netblock/AS | Инфраструктура |

Через **Transform Hub** наборы ставятся в один клик; часть требует API-ключей (Shodan, VirusTotal).

## iTDS и автоматизация

**iTDS (Maltego Transform Distribution Server)** позволяет раздавать собственные трансформы команде и запускать их с сервера. Свой трансформ — это HTTP-сервис, который принимает сущность и возвращает список сущностей (JSON/XML). Так можно обернуть внутренние базы или кастомные API. Для масштабных задач Maltego сочетают с внешними скриптами: экспорт графа в CSV/GraphML и обработка в Python (networkx).

Maltego силён там, где важна **структура связей**; SpiderFoot — где нужен автоматический охват.

## Подводные камни

- **Community Edition урезана.** Часть трансформов и лимиты недоступны.
- **API-ключи обязательны** для «вкусных» источников.
- **Ложные связи.** Общий CDN/хостинг может связать чужие домены — проверяйте.
- **Куча узлов без смысла.** Граф растёт быстро; фиксируйте гипотезы и отсекайте шум.
- **Юридические/этические рамки.** Пассивные трансформы ок; активные — по авторизации.
- **Приватность.** Серверные трансформы отправляют вашу цель третьим лицам.

## Трансформы в деталях: как работает DNS-цепочка

Разберём типовую цепочку подробно. Сущность `Domain` с именем `target.com` подаётся трансформу `To DNS Name`, который выполняет DNS-запросы (A, AAAA, MX, NS, TXT, CNAME) и создаёт дочерние сущности: `IPv4Address`, `MXRecord`, `NSRecord`, `DNSName`. Далее `To IP Address` берёт доменные имена и резолвит их в IP. Трансформ `To Netblock` по IP определяет принадлежащий диапазон (`Netblock`), а `To AS` — автономную систему и её владельца. Наконец, `Reverse DNS` по IP возвращает все PTR-записи, что выявляет **соседей по хостингу**: чужие домены на том же IP. Эта последовательность — сердце инфраструктурного recon: от одного домена вы приходите к провайдеру, диапазону и списку «соседей», которые могут быть связанными активами или точками pivot.

Особенно ценны трансформы сертификатов: по `crt.sh` из одного домена извлекаются все имена из выданных сертификатов, включая поддомены, которых нет в DNS-зоне. Комбинируя `Certificate → Domain` и `Domain → IP`, вы быстро строите карту, где видно, какие поддомены живут на одной инфраструктуре. Ложные срабатывания (CDN) отсекаются проверкой AS: если IP принадлежит Cloudflare/Akamai, «соседи» ничего не значат.

## Maltego против ручного OSINT

| Аспект | Ручной OSINT | Maltego |
|---|---|---|
| Скорость | Медленно, по одному запросу | Трансформы в один клик |
| Визуализация | Таблицы/заметки | Граф связей |
| Воспроизводимость | Зависит от дисциплины | Граф/машина сохраняются |
| Гибкость | Максимальная | Ограничена трансформами |
| Стоимость | Бесплатно | CE бесплатна, HX платно |

Ручной подход лучше для нестандартных источников; Maltego — для систематического обхода и наглядности. На практике их сочетают: Maltego даёт карту, ручной OSINT её уточняет.

## Лаборатория

1. Установите Maltego CE и войдите.
2. Создайте `Domain` для своего тестового домена.
3. Запустите Machine «Company Stalker» или вручную: DNS Name → IP → Netblock → AS → Reverse DNS.
4. Добавьте трансформ crt.sh и сравните список поддоменов с DNS.
5. Найдите «хаб» — узел с максимальным числом связей.
6. Экспортируйте граф (GraphML) и откройте в Gephi для анализа кластеров.
