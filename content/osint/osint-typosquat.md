## Вопрос, с которого всё начинается

Атакующие редко ломают домен — они покупают его почти-двойник: `g00gle.com`, `аpple.com` (с кириллической «а»), `paypal-secure.com`. Для разведчика такие домены — источник фишинговой инфраструктуры, для защитника — задача мониторинга бренда. Но как найти их системно, а не наугад?

Разберём тайпсквоттинг на одном бренде и научимся отличать безобидный паркинг от реальной угрозы.

## Наш пример: бренд example.com

Введём термин. **Тайпсквоттинг** (typosquatting) — регистрация домена, похожего на чужой, в расчёте на опечатку пользователя или визуальную подмену. Наша цель — бренд `example.com`; мы хотим найти его двойники и приоритизировать их по риску.

## Шаг 1: понимаем виды подмен

Двойники бывают разные:

1. **Опечатки** — замена, пропуск или перестановка символов: `exmaple.com`, `exmple.com`.
2. **Омоглифы** (IDN homograph) — похожие Unicode-символы: кириллические `а, е, о, р, с, х` вместо латинских.
3. **Битсквоттинг** — близкие символы: `rn` вместо `m`, `vv` вместо `w`.
4. **Добавление слов** — `example-login.com`, `secure-example.com`.
5. **Другие TLD** — `example.net`, `example.co`, `example.org`.
6. **Комбосквоттинг** — склейка брендов: `examplegoogle.com`.

Опасны те, у которых есть активная инфраструктура: A/MX-записи, свежий WHOIS, HTTPS-сертификат.

## Шаг 2: генерируем кандидатов через dnstwist

**dnstwist** — де-факто стандарт генерации lookalike-доменов:

```bash
dnstwist --registered example.com
```

Вывод (фрагмент):

```
example-login.com   A=203.0.113.10  MX=mx.example-login.com
examp1e.com         (паркинг)
example.co          A=198.51.100.5
exarnple.com        NXDOMAIN
```

Флаги: `--registered` (только живые), `--tld` (популярные TLD), `--format csv/json`, `--nameserver` (свой DNS). Аналог — `urlcrazy` из Kali.

## Шаг 3: проверяем инфраструктуру

Для каждого кандидата смотрим WHOIS и DNS:

```bash
whois example-login.com | grep -iE "creat|registrar|expir"
dig +short A example-login.com
dig +short MX example-login.com
```

Быстрая проверка пачки:

```bash
for d in example-login.com examp1e.com example.co; do
  printf '%-25s A=%s MX=%s\n' "$d" "$(dig +short A $d | tr '\n' ',')" "$(dig +short MX $d | tr '\n' ',')"
done
```

Наличие MX означает, что домен готов принимать почту — классический признак подготовки фишинга.

## Шаг 4: приоритизируем по риску

| Признак | Риск |
|---|---|
| Есть MX (принимает почту) | высокий |
| Свежая регистрация (< 6 мес) | высокий |
| HTTPS с сертификатом на бренд | высокий |
| Страница-клон логина | критический |
| Паркинг без A/MX | низкий |
| Домен занят легитимно | низкий |

Приоритет №1 — домены, **готовые к фишингу**: MX + свежий WHOIS + клон логина.

## Шаг 5: разбираем IDN и punycode

Для омоглифов важно смотреть **punycode** — ASCII-представление Unicode-домена (начинается с `xn--`), потому что браузер показывает «красивый» вид, а DNS работает с нормализованным:

```bash
python3 - <<'PY'
for d in ["аpple.com", "g00gle.com", "paypa1.com"]:
    print(d, "->", d.encode("idna").decode())
PY
```

Вывод:

```
аpple.com -> xn--pple-43d.com
g00gle.com -> g00gle.com
paypa1.com -> paypa1.com
```

В отчёте указывай **обе** формы: визуальную и punycode — иначе защитник не сможет занести домен в блок-лист.

## Шаг 6: подтверждаем угрозу скриншотом

Страницу-клон логина удобно зафиксировать через urlscan.io:

```bash
curl -s "https://urlscan.io/api/v1/scan/" -H "API-Key: $URLSCAN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example-login.com","visibility":"public"}'
```

Скриншот — доказательство, которое невозможно оспорить.

## Шаг 7: настраиваем мониторинг

Одноразовый прогон бесполезен — нужен регулярный:

```text
1. Регулярный прогон dnstwist (cron)
2. Алерты на новые домены (brand protection сервисы)
3. Подписка на CT-логи (crt.sh / certstream)
4. Проверка MX у новых доменов — сигнал готовящегося фишинга
```

**CT-логи** ловят новые домены сразу после выпуска TLS-сертификата — раньше, чем обновятся базы WHOIS:

```bash
certstream --json | jq -r 'select(.data.leaf_cert.all_domains[]? | test("example")) | .data.leaf_cert.all_domains[]' | head
```

## Шаг 8: держим рамки законности

Проверять чужие домены можно только лёгкими запросами:

- **Допустимо:** WHOIS, DNS (A/MX/TXT), HTTP HEAD, CT-логи, скриншот.
- **Недопустимо без разрешения:** полный порт-скан, брут поддоменов, эксплуатация найденных багов.

Чужие домены проверяй «снаружи», не создавая нагрузки.

## Шаг 9: распознаём кампанию

Отдельные двойники часто оказываются частью одной кампании. Признак — общие атрибуты:

1. `dnstwist --registered` даёт кандидатов.
2. Группируем по регистратору и дате — совпадение указывает на одну кампанию.
3. Проверяем MX: домены готовы принимать почту → фишинг.
4. CT-логи показывают общий wildcard-сертификат → общая инфраструктура.
5. urlscan.io даёт скриншоты клонов логина.

Вердикт по серии `example-login-*.com` с общим регистратором — организованная фишинг-кампания, эскалация.

## Шаг 10: сводим метрики для отчёта

| Метрика | Значение |
|---|---|
| Всего кандидатов | из dnstwist |
| Живых (A/MX) | сколько активно |
| С MX | готовы к фишингу |
| Со свежим WHOIS | < 6 мес |
| С клоном логина | критичные |

Эти числа превращают сырой список в приоритизированный отчёт с оценкой риска.

## Что мы теперь знаем

- Тайпсквоттинг — регистрация похожих доменов для фишинга или подмены.
- dnstwist генерирует кандидатов по всем техникам.
- Опасны домены с MX, свежим WHOIS и сертификатом на бренд.
- IDN-двойники различаются только в punycode-форме.
- Мониторинг = dnstwist по расписанию + CT-поток + алерты.

## Частые ошибки

- **Тестировать всё вручную.** Без dnstwist/urlcrazy пропустишь сотни вариантов.
- **Считать паркинг угрозой.** Пустой домен без инфраструктуры — низкий риск.
- **Игнорировать punycode.** Визуально одинаковые домены различаются в `xn--`-форме.
- **Сканировать чужие домены активно.** Проверяй лёгкими запросами.
- **Нет приоритизации.** Список из 500 доменов без классов риска бесполезен.

## На что смотреть дальше

Цель работы — не список, а **приоритизированные** находки с доказательствами: WHOIS, MX, сертификат, скриншот. Дальше разберём **BGP**: как из номера автономной системы получить все адреса оператора и понять маршрутизацию. А пока главное запомни: двойник опасен не самим фактом существования, а готовностью принимать почту и отдавать клон логина.

## Справочник: типы опечаток

Инструменты генерации опечаток (dnstwist) используют фиксированный набор мутаций. Знать их полезно, чтобы понимать вывод:

| Тип | Пример от `example` | Ловит кого |
|---|---|---|
| omission | `exmple.com` | быструю печать |
| insertion | `exxample.com` | дублирование клавиши |
| replacement | `exsmple.com` | соседнюю клавишу |
| transposition | `exmaple.com` | перестановку букв |
| homoglyph | `exаmple.com` (кир. `а`) | визуально неотличимо |
| TLD swap | `example.net`, `example.org` | смену зоны |
| subdomain swap | `example.com.evil.net` | чтение справа налево |
| punycode/IDN | `xn--exmple-...` | Unicode-подмену |

Каждый тип даёт десятки кандидатов; не проверять их вручную — задача для инструмента.

## Защита: как защититься от тайпсквоттинга

Обратная сторона — твоя собственная защита:

- **Зарегистрируй основные опечатки** заранее (defensive registration): частые замены и `.net`/`.org`-версии.
- **Включи DMARC `p=reject`** — даже если опечатку купят, спуфинг от твоего домена не пройдёт.
- **Мониторь новые регистрации**, похожие на твой бренд (сервисы brand monitoring, CT-логи).
- **Обучи сотрудников** смотреть на домен в адресной строке, а не на логотип.
- **Публикуй `security.txt`** — чтобы о находках сообщали тебе, а не злоумышленникам.

## Если не сработало

- **dnstwist не находит активных.** Запускай с проверкой DNS (`dnstwist --registered example.com`), иначе в списке будет мусор из свободных домен.
- **IDN-домен выглядит как обычный.** Всегда проверяй punycode-форму (`xn--`): именно она раскрывает подмену буквы.
- **Домен-кандидат без контента.** Отсутствие сайта не значит «безопасно»: домен мог быть куплен под будущий фишинг.
- **Слишком много кандидатов.** Приоритизируй по двум признакам: есть MX-запись (собираются слать письма) и есть логин-форма (собираются собирать пароли).

## Мини-практика: разбираем одну кампанию

Соберём историю от опечатки до вывода о кампании:

1. **Генерация.** `dnstwist` даёт список похожих доменов на бренд.
2. **Фильтр.** Оставляем только зарегистрированные (`--registered`) — остальное мусор.
3. **Инфраструктура.** У кандидатов смотрим MX (будут слать письма) и A (есть сайт).
4. **Клон.** Если на домене копия твоего логина — это фишинг.
5. **Связь.** Общий IP, сертификат или GTM-ID между несколькими опечатками говорит об **одной кампании**, а не о разрозненных регистрациях.
6. **Вывод.** «Пять доменов на одном хосте с MX и копией формы входа» — это уже сформулированная угроза для отчёта.

Так набор похожих доменов превращается в доказанную атаку.

## Шпаргалка: приоритизация кандидатов

- Есть MX → домен собираются использовать для почты (фишинг).
- Есть копия логин-формы → прямой фишинг.
- Есть валидный TLS-сертификат на бренд → серьёзная подготовка.
- Общий IP/GTM с другими опечатками → одна кампания.
- Ничего из этого → низкий приоритет, но не игнорируй.
- Проверяй `--registered` до анализа, иначе половина списка — свободные домены.
- Смотри MX отдельно от A: домен без сайта, но с MX, всё равно готовят под письма.

## Куда дальше

Мы научились находить и приоритизировать домены-двойники. В следующем уроке — **BGP**: как определить, какие адреса принадлежат оператору и как устроена маршрутизация. А пока главное запомни: двойник — это угроза только тогда, когда за ним стоит живая инфраструктура.

## Где пригодится

- **CTF (OSINT):** найти домен-двойник с фишинг-инфраструктурой или флагом.
- **Bug bounty:** сообщить о тайпсквот-домене, имитирующем бренд.
- **Blue team:** мониторинг бренда, раннее обнаружение фишинга.
- **Red team:** подготовка похожего домена для симуляции фишинга в рамках scope.
- **Юридически:** при явном фишинге уведомить регистратора и хостера домена.
