Атакующие часто не ломают домен, а покупают его почти-двойник: `g00gle.com`, `аpple.com` (кириллическая «а»), `paypal-secure.com`. Для разведчика такие домены — источник фишинговой инфраструктуры, а для защитника — задача мониторинга бренда. В уроке — как системно перечислять lookalike-домены, проверять их инфраструктуру и отличать безобидный паркинг от реальной угрозы.

## Что такое тайпсквоттинг и зачем его искать

- **Red team**: похожий домен для симуляции фишинга в рамках scope.
- **Blue team**: мониторинг бренда и раннее обнаружение фишинга.
- **Bug bounty**: репорт о домене-двойнике, имитирующем бренд.
- **CTF**: найти домен-двойник, где лежит фишинг-инфраструктура или флаг.

Цель работы — не «список из 500 доменов», а **приоритизированный** список с оценкой риска.

## Виды тайпсквоттинга

1. **Опечатки (typosquatting):** замена/пропуск/перестановка символов — `exmaple.com`, `exmple.com`.
2. **Омоглифы (IDN homograph):** похожие Unicode-символы — кириллические `а,е,о,р,с,х` вместо латинских.
3. **Битсквоттинг:** изменение одного бита или близкие символы — `rn` вместо `m`, `vv` вместо `w`.
4. **Добавление слов:** `example-login.com`, `secure-example.com`, `example-support.net`.
5. **Другие TLD:** `example.com` → `example.net`, `example.co`, `example.org`.
6. **Комбосквоттинг:** склейка брендов — `examplegoogle.com`.
7. **Поддомены-двойники:** `example.com.evil.net`.

Опасны те, что имеют активную инфраструктуру (A/MX-записи, свежий WHOIS, HTTPS-сертификат).

## Инструменты: dnstwist и urlcrazy

Генерация кандидатов через `dnstwist` — де-факто стандарт:

```bash
# все техники, только зарегистрированные домены
dnstwist --registered example.com

# перебор популярных TLD
dnstwist --tld example.com | head

# экспорт в CSV для дальнейшего анализа
dnstwist --format csv example.com > typos.csv
```

`urlcrazy` (Kali) даёт похожий результат:

```bash
urlcrazy -k nowww -f csv example.com
```

Флаги `dnstwist`: `--registered` (только живые), `--tld` (популярные TLD), `--format` (csv/json/list), `--nameserver` (кастомный DNS), `--threads` (параллелизм).

## Проверка инфраструктуры

Проверка WHOIS и даты регистрации (см. osint-whois-asn):

```bash
whois example-login.com | grep -iE "creat|registrar|expir"
```

Проверка сертификатов и DNS:

```bash
curl -s "https://crt.sh/?q=%25.example-login.com&output=json" | jq -r '.[].name_value' | sort -u
dig +short A example-login.com
dig +short MX example-login.com
```

Быстрая проверка пачки кандидатов:

```bash
for d in example-login.com examp1e.com example.co; do
  printf '%-25s A=%s MX=%s\n' "$d" "$(dig +short A $d | tr '\n' ',')" "$(dig +short MX $d | tr '\n' ',')"
done
```

## Разобранный пример: оценка домена-двойника

Дано: целевой бренд `example.com`.

Шаг 1 — генерация:

```bash
dnstwist --registered example.com --format csv | tee twist.csv
```

Шаг 2 — фильтр по «живости». Оставляем записи с A или MX:

```bash
awk -F, 'NR>1 && ($0 ~ /A|MX/)' twist.csv | head -30
```

Шаг 3 — приоритизация. Для каждого кандидата смотрим:

- дату регистрации (свежий домен = выше риск);
- наличие MX (готов принимать почту — классика фишинга);
- HTTPS-сертификат и содержимое страницы;
- регистратора и страну.

```bash
for d in example-login.com example.co examp1e.com; do
  echo "== $d =="
  whois $d | grep -iE "creation|registrar:" | head -2
  dig +short MX $d
  curl -sI "https://$d" | head -1
done
```

Шаг 4 — вердикт. `example-login.com` с MX, свежим WHOIS и страницей-клоном логина = высокая угроза. `examp1e.com` без A/MX и в паркинге = низкий приоритет.

Шаг 5 — фиксируем в отчёте: список доменов, класс риска, доказательства (WHOIS, MX, скриншот).

## Приоритизация и оценка риска

| Признак | Риск |
|---|---|
| Есть MX (принимает почту) | высокий |
| Свежая регистрация (< 6 мес) | высокий |
| HTTPS с сертификатом на бренд | высокий |
| Страница-клон логина | критический |
| Паркинг без A/MX | низкий |
| Домен занят легитимно (другая компания) | низкий |

Приоритет №1 — домены, **готовые к фишингу** (MX + свежий + клон).

## Мониторинг бренда

```text
1. Регулярный прогон dnstwist (cron)
2. Алерты на новые домены (brand protection сервисы)
3. Подписка на CT-логи (crt.sh / certstream) — ловит сразу после выпуска сертификата
4. Проверка MX у новых доменов — сигнал готовящегося фишинга
```

## IDN/омоглифы и punycode

- **IDN-нормализация:** `dnstwist` показывает punycode (`xn--...`), проверяйте его отдельно — браузер отображает «красивый» вид.
- **Визуально идентичные** домены различаются только в нормализованной форме: `аpple.com` (кириллица) = `xn--pple-43d.com`.
- **Регистратор-масса:** тысячи доменов у одного регистратора = кампания.

## Активные vs лёгкие проверки

- **Допустимо:** WHOIS, DNS (A/MX/TXT), HTTP HEAD, CT-логи, скриншот через urlscan.io.
- **Недопустимо без разрешения:** полный порт-скан, брут поддоменов, эксплуатация найденных багов.
- Чужие домены проверяйте «снаружи», не создавая нагрузки.

## Частые ошибки

- **Тестировать всё вручную.** Без `dnstwist`/`urlcrazy` вы пропустите сотни вариантов.
- **Считать паркинг угрозой.** Пустой домен без инфраструктуры — низкий риск.
- **Игнорировать punycode.** Визуально одинаковые домены различаются только в нормализованной форме.
- **Забывать про TLD.** `.co`, `.net`, `.ru` — популярные двойники.
- **Сканировать чужие домены активно.** Проверяйте лёгкими запросами.
- **Нет приоритизации.** Список из 500 доменов без классов риска бесполезен.

## Что дальше / решение

Собрав приоритизированный список, переходите к действию: для blue team — блокировка и алерт; для bug bounty — репорт с доказательствами; для red team — использование домена в рамках scope. Решение по каждому домену: «низкий риск — наблюдать», «высокий — блокировать/репортить», «критический (клон логина + MX) — немедленная эскалация». Всегда фиксируйте WHOIS, MX, сертификат и скриншот как доказательства.

## Генерация вариантов вручную

Если инструментов нет, варианты строятся по правилам:

- **Замена** символа: `example` → `examp1e`, `exampIe`.
- **Пропуск**: `exmple`, `eample`.
- **Перестановка**: `exmaple`.
- **Вставка**: `exaample`.
- **Замена TLD**: `.com → .co/.net/.org/.ru`.
- **Добавление слова**: `example-login`, `secure-example`, `example-support`.
- **Омоглифы**: кириллические `а,е,о,р,с,х,у` вместо латинских.

## Работа с IDN и homoglyph-таблицами

- Переводите домен в **punycode**: `python3 -c "print('аpple.com'.encode('idna'))"` → `b'xn--pple-43d.com'`.
- Обратно: `'xn--pple-43d.com'.encode().decode('idna')`.
- Кириллические двойники: `а→a`, `е→e`, `о→o`, `р→p`, `с→c`, `х→x`, `у→y`, `к→k`, `м→m`, `т→t`.
- В отчёте указывайте **обе** формы: красивую и punycode.

```bash
python3 - <<'PY'
for d in ["аpple.com", "g00gle.com", "paypa1.com"]:
    try:
        print(d, "->", d.encode("idna").decode())
    except Exception as e:
        print(d, "ERR", e)
PY
```

## Интеграция с CT-мониторингом

Сертификаты прозрачности (CT) ловят новые домены сразу после выпуска TLS-сертификата — раньше, чем обновятся базы WHOIS.

```bash
# поток новых сертификатов с фильтром по ключевому слову
certstream --json | jq -r 'select(.data.leaf_cert.all_domains[]? | test("example")) | .data.leaf_cert.all_domains[]' | head
```

Комбинируйте: `dnstwist` раз в сутки + CT-поток в реальном времени + проверка MX у новых доменов.

## Пример: кампания с массовым регистратором

Дано: серия доменов `example-login-*.com`.

1. `dnstwist --registered` даёт кандидатов.
2. Группируем по регистратору и дате — совпадение указывает на одну кампанию.
3. Проверяем MX: домены готовы принимать почту → фишинг.
4. CT-логи показывают общий wildcard-сертификат → общая инфраструктура.
5. urlscan.io даёт скриншоты клонов логина.
6. Вердикт: организованная фишинг-кампания → эскалация.

## Метрики для отчёта

| Метрика | Значение |
|---|---|
| Всего кандидатов | из dnstwist |
| Живых (A/MX) | сколько активно |
| С MX | готовы к фишингу |
| Со свежим WHOIS | < 6 мес |
| С клоном логина | критичные |

## Чек-лист оценки домена-двойника

1. Домен зарегистрирован? (`whois`)
2. Есть A-запись? (`dig +short A`)
3. Есть MX? (`dig +short MX`) — готов принимать почту.
4. Дата регистрации < 6 мес? (риск).
5. Есть TLS-сертификат? (`crt.sh`).
6. Открывается страница? (`curl -sI`).
7. Похожа на клон логина? (`urlscan.io`).
8. Общий регистратор/сертификат с другими? (кампания).

8 из 8 «да» — критический риск; 1–2 — низкий.

## Что делать с находками

- **Blue team:** внести в блок-лист, поднять алерт, уведомить пользователей.
- **Bug bounty:** репорт с WHOIS, MX, сертификатом и скриншотом.
- **Red team:** использовать домен в симуляции фишинга (в рамках scope).
- **Юридически:** при явном фишинге — уведомить регистратора и хостера.

## Автоматизация мониторинга

```bash
# ежедневный прогон + сохранение результата для диффа
0 6 * * * cd /opt/brand && dnstwist --registered example.com --format csv > $(date +\%F).csv
```

Дифф между днями выявляет новые домены — их проверяйте в первую очередь.

## Итоговая сводка

- **Генерация:** `dnstwist` (все техники) + `urlcrazy`.
- **Фильтр:** только живые (A/MX).
- **Приоритизация:** MX + свежий WHOIS + клон = критично.
- **Мониторинг:** cron + CT-поток + алерты.
- **Доказательства:** WHOIS, MX, сертификат, скриншот.
- **Действие:** блок/репорт/симуляция по роли.

Помните: цель — не список, а приоритизированные находки с оценкой риска и доказательствами.

## Отличие от поддомен-разведки

Тайпсквоттинг ищет **внешние** домены-двойники, а поддомен-энумерация — **внутренние** хосты целевого домена. Это разные задачи: первая про фишинг и бренд, вторая про поверхность атаки. Иногда они пересекаются: поддомен-двойник (`example.com.evil.net`) объединяет обе техники.
