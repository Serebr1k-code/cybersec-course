## Вопрос, с которого всё начинается

Тебе прилетел индикатор: домен `secure-login-bank.example`. Один индикатор бесполезен — надо понять, с чем он связан. Кто ещё его видел? К какой кампании он относится? Есть ли у него общий сертификат с другими доменами? Ответы живут в платформе обмена индикаторами, и самая распространённая из них — **MISP**.

Задача: прочитать событие MISP и вытащить из него связи.

## Наш пример: событие MISP

Держим объект `event.json` — выдержку события MISP. Первый вопрос: **что внутри?**

```bash
cat event.json
```

```text
{"Event": {"info": "Phishing wave targeting banks",
  "Attribute": [
    {"type": "ip-dst", "value": "203.0.113.7"},
    {"type": "domain", "value": "secure-login-bank.example"},
    {"type": "sha256", "value": "e3b0c442..."}],
  "Tag": ["tlp:amber", "misp-galaxy:threat-actor=APT-Example"]}}
```

Читаем: `info` — описание события, `Attribute` — сами индикаторы с типом, `Tag` — метки. Мы видим IP, домен и хеш — три разных типа индикаторов в одном событии.

## Шаг 1: что такое MISP

**MISP** (Malware Information Sharing Platform) — открытая платформа для обмена и хранения индикаторов. Единица хранения — **событие** (event): один инцидент или одна кампания, внутри — набор **атрибутов** (attribute), то есть значений с типом. Атрибуты связываются друг с другом: IP, домен и хеш в одном событии считаются относящимися к одному инциденту.

Тип атрибута важен: `ip-dst` — адрес назначения, `domain` — доменное имя, `sha256` — хеш файла. По типу инструменты понимают, как значение использовать.

## Шаг 2: атрибуты и их типы

```bash
python3 -c "import json;e=json.load(open('event.json'))['Event'];print([(a['type'],a['value']) for a in e['Attribute']])"
```

```text
[('ip-dst', '203.0.113.7'), ('domain', 'secure-login-bank.example'), ('sha256', 'e3b0c442...')]
```

Список сразу показывает «сюжет» события: фишинг с домена, раздающего малварь по хешу. Это уже не три разрозненных строки, а связная история.

## Шаг 3: теги, галактики и TLP

Тег `tlp:amber` — это **Traffic Light Protocol**: правило распространения. Amber означает «делиться только внутри сообщества и с партнёрами». Есть ещё `tlp:red` (только адресат), `tlp:green` (сообщество) и `tlp:clear` (публично).

Тег `misp-galaxy:threat-actor=APT-Example` — ссылка на **галактику**, то есть структурированный справочник. Галактика threat-actor описывает известные группы. Так MISP связывает сырой индикатор с атрибуцией.

## Шаг 4: корреляция

Главная сила MISP — **корреляция**: если один и тот же атрибут встречается в разных событиях, платформа связывает их автоматически. Домен из фишинга и домен из другой кампании с общим сертификатом окажутся в одном «кластере».

```bash
# в веб-интерфейсе MISP: Correlation graph по атрибуту domain
# → secure-login-bank.example связан с событием #4711 (crypto-phishing)
```

Именно корреляция превращает одиночные индикаторы в карту кампаний.

## Шаг 5: обмен — TAXII и фиды

MISP умеет публиковать события и подписываться на чужие. Обмен идёт либо напрямую между инстансами (MISP-to-MISP), либо через **фиды** — потоки индикаторов. Публичные фиды (например, от CERT) можно подключить и получать свежие события без ручного сбора.

## Полный прогон

```bash
# 1. прочитать событие
cat event.json
# 2. вытащить атрибуты
python3 -c "import json;print([a['value'] for a in json.load(open('event.json'))['Event']['Attribute']])"
# → ['203.0.113.7', 'secure-login-bank.example', 'e3b0c442...']
# 3. теги
python3 -c "import json;print(json.load(open('event.json'))['Event']['Tag'])"
# → ['tlp:amber', 'misp-galaxy:threat-actor=APT-Example']
```

Непрерывно: индикатор → событие → атрибуты → теги → корреляция → обмен.

## Если не сработало

**Инстанс закрыт.** Многие MISP доступны только по приглашению — работай со своими данными.
**Атрибут без типа.** Некоторые фиды отдают «сырой» текст — нормализуй тип сам.
**Слишком много событий.** Фильтруй по тегу или организации, иначе утонешь.

## Частые вопросы

**Чем MISP отличается от списка IOC?** Это база со связями и обменом, а не плоский список.
**Что такое TLP?** Правило, кому можно передавать индикатор.
**Обязателен ли MISP?** Нет; есть OpenCTI, TheHive и другие, но MISP — де-факто стандарт обмена.
**Можно ли доверять чужому событию?** Нет, у каждого фида своя репутация — учитывай её.

## Термины

**Event** — единица хранения (инцидент/кампания).

**Attribute** — значение индикатора с типом.

**Correlation** — автоматическая связь по общим атрибутам.

**Galaxy** — структурированный справочник (группы, инструменты).

**TLP** — правило распространения информации.

## Что мы теперь знаем

1. MISP хранит события с типизированными атрибутами.
2. Теги и галактики связывают индикатор с контекстом.
3. Корреляция объединяет разрозненные индикаторы.
4. Обмен идёт через фиды и MISP-to-MISP.
5. TLP задаёт границы распространения.

## Разбор кейса: фишинг по банкам

Дано: событие MISP с доменом `secure-login-bank.example`. Шаг первый — читаем `info`: «Phishing wave targeting banks». Шаг второй — разбираем атрибуты: IP назначения, домен и хеш малвари. Шаг третий — смотрим теги: `tlp:amber` запрещает публичную передачу, а галактика указывает на `APT-Example`. Шаг четвёртый — включаем корреляцию и видим, что тот же домен встречается в событии про крипто-фишинг. Вывод: перед нами не одиночный индикатор, а звено кампании, связанной с известной группой. Дальше аналитик подписывается на обновления события и ставит мониторинг новых атрибутов.

## Сравнение с другими платформами

| Платформа | Формат хранения | Обмен | Сильная сторона |
|-----------|-----------------|-------|-----------------|
| MISP | события + атрибуты | MISP-to-MISP, фиды | корреляция из коробки |
| OpenCTI | граф STIX | TAXII, коннекторы | граф знаний |
| TheHive | кейсы + наблюдаемые | Cortex | работа с инцидентом |
| Плоский список IOC | строки | файл | простота |

Из таблицы видно: MISP выигрывает там, где нужна автоматическая корреляция и обмен между командами, а плоский список хорош лишь для быстрого разового применения.

## Чек-лист работы с событием

1. Прочитать `info` и понять, о чём событие.
2. Проверить `tlp` — можно ли делиться дальше.
3. Разобрать атрибуты по типам.
4. Найти галактики и сверить атрибуцию.
5. Включить корреляцию и найти связанные события.
6. Отметить свежесть: старые атрибуты могли устареть.

## Типичные ошибки

**Ошибка: игнорировать TLP.** Передача `tlp:red` наружу — репутационный и юридический риск.
**Ошибка: считать корреляцию истиной.** Совпадение атрибута — гипотеза, а не доказательство.
**Ошибка: смешивать типы атрибутов.** `ip-dst` и `ip-src` означают разное.
**Ошибка: не проверять свежесть.** Индикатор недельной давности часто уже мёртв.

## Расширенный пример: атрибуты и теги через jq

```bash
# все доменные атрибуты события
jq -r '.Event.Attribute[] | select(.type=="domain") | .value' event.json
# → secure-login-bank.example
# список тегов
jq -r '.Event.Tag[]' event.json
# → tlp:amber
# → misp-galaxy:threat-actor=APT-Example
```

Так из события вытаскивается ровно то, что нужно для фида, — без ручного переписывания.

## Как устроен рабочий процесс вокруг MISP

Платформа редко используется в одиночку. Вокруг неё выстраивается цикл: сбор → нормализация → хранение → корреляция → обмен → обогащение → обратная связь. Сбор даёт сырые наблюдения: логи, отчёты, песочницы. Нормализация приводит их к типизированным атрибутам: адрес становится `ip-dst`, домен — `domain`, хеш — `sha256`. Хранение кладёт всё в события, чтобы не потерять контекст. Корреляция связывает события между собой. Обмен отправляет данные партнёрам по правилам TLP. Обогащение добавляет к атрибутам внешний контекст: репутацию, геолокацию, владельца. Обратная связь возвращает в платформу результаты расследований, и цикл замыкается. Аналитик, который понимает этот цикл, перестаёт быть «сборщиком строк» и становится частью системы обмена знаниями. Именно поэтому MISP — не просто база, а узел коллективной обороны: каждая команда, добавившая качественное событие, помогает всем остальным, а каждая команда, потребившая чужое, ускоряет свою реакцию. Качество события при этом важнее количества: одно хорошо размеченное событие с корректными типами и тегами полезнее сотни строк без контекста. Поэтому в зрелых командах есть правила: кто ставит TLP, как оформлять галактики, когда помечать атрибут как `to_ids` (годен ли он для автоматического обнаружения). `to_ids` — отдельное поле атрибута; если оно истинно, индикатор можно загружать в IDS/антивирус как сигнатуру. Если ложно, атрибут остаётся контекстом и в детекторы не попадает — например, потому что он слишком общий и даст ложные срабатывания.

## Разметка, которая экономит часы

Разметка — самая недооценённая часть работы. Атрибут без типа бесполезен для автоматизации; событие без тегов невозможно отфильтровать; индикатор без TLP нельзя безопасно передать. Хорошая разметка отвечает на четыре вопроса: что это (тип), к чему относится (событие), насколько чувствительно (TLP), годится ли для детектора (`to_ids`). Когда эти четыре ответа есть, платформа сама делает корреляцию, фильтрацию и обмен. Когда их нет, аналитик тратит часы на ручной разбор и всё равно ошибается. Поэтому правило простое: сначала разметка, потом публикация. Дешёвая минута разметки экономит час расследования у получателя.

## От индикатора к детекту

Финальная точка работы с MISP — превращение индикатора в правило обнаружения. Домен можно добавить в DNS-мониторинг, хеш — в антивирусную базу, IP — в firewall-лист. Но индикаторы быстро устаревают, поэтому в зрелых процессах их связывают с TTP: вместо «блокируй этот домен» правило звучит «отслеживай обращения к доменам с таким шаблоном сертификата». Именно переход от значений к поведению делает детект устойчивым к смене инфраструктуры противником.

## Куда дальше

Мы посмотрели, как индикаторы хранятся. Дальше возьмём **STIX/TAXII** — язык и транспорт, которыми эти данные перевозят между платформами. А пока главное: один индикатор — это ничто, связи — всё.

## Где пригодится

- **CTI:** ведение базы кампаний.
- **SOC:** обмен индикаторами с сообществом.
- **CTF (OSINT):** разбор событий и корреляция.
- **Расследования:** связь инцидентов.
