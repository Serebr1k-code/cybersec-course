## Вопрос, с которого всё начинается

Ты нашёл в Shodan пару серверов организации и решил, что картина полная. Но когда открыл ту же цель в Censys — обнаружил ещё три хоста, которых Shodan не видел.

Так и есть: **Shodan — не единственный сканер интернета**. Censys, FOFA и ZoomEye покрывают разные срезы и индексируют в разное время. Разберём это на одной задаче.

## Наш пример: инстансы Grafana у example.com

У нас один объект — организация `example.com`. Задача: найти **все** её инстансы Grafana. Введём термин: **fingerprint** (отпечаток) — устойчивый признак сервиса, по которому его узнают (заголовок, иконка, сертификат). Каждый движок умеет искать по своим полям.

## Шаг 1: Censys — точность полей

**Censys** силён в TLS-сертификатах и структурированных полях. У него своя грамматика: поля разделяются точками.

```
services.http.response.html_title: "Grafana"
services.tls.certificates.leaf_data.names: example.com
services.software.product: "nginx"
services.port: 9200
```

Запрос по `html_title` находит страницы Grafana, а `leaf_data.names` — хосты с сертификатом на наш домен. Операторы: `and`, `or`, `not`, скобки, диапазоны портов (`services.port: 8000-9000`).

Через API:

```bash
curl -s "https://search.censys.io/api/v2/hosts/search?q=services.http.response.html_title%3A%20%22Grafana%22&per_page=50" \
  -u "$CENSYS_ID:$CENSYS_SECRET" | jq '.result.hits[].ip'
```

```
203.0.113.22
198.51.100.40
```

## Шаг 2: FOFA — веб-отпечатки и favicon

**FOFA** фокусируется на веб-технологиях. Операторы проще: `domain=`, `title=`, `cert=`, `body=`, `icon_hash=`. Логика — `&&` (И) и `||` (ИЛИ).

```
title="Grafana" && cert="example.com"
port="2375" && country="RU"
```

Отдельная сила FOFA — **favicon-хэш**: отпечаток иконки сайта. Иконка часто одинакова на всех серверах одного продукта, даже если заголовки подделаны. Считается по алгоритму **mmh3**:

```bash
python3 - <<'PY'
import mmh3, requests
r = requests.get("https://example.com/favicon.ico")
print(mmh3.hash(r.content))
PY
```

```
-1234567890
```

Дальше в FOFA: `icon_hash="-1234567890"`. Так находят origin-серверы за Cloudflare: контент с той же иконкой отдаёт другой IP.

## Шаг 3: ZoomEye — азиатский сегмент и ICS

**ZoomEye** похож на Shodan синтаксисом и делит пространство на `host` и `web`. Он хорош по промышленным устройствам (ICS) и азиатскому сегменту:

```
site:example.com
app:"Apache httpd"
title:"dashboard"
device:"webcam"
```

У него есть **facets** — агрегаты: сколько серверов какой версии или приложения. Это удобно, когда нужно не «список IP», а статистика:

```bash
curl -s "https://api.zoomeye.org/host/search?query=port%3A22%20country%3A%22RU%22&facets=app,os" \
  -H "API-KEY: $ZOOMEYE_KEY" | jq '.facets'
```

## Шаг 4: объединяем движки

Ни один движок не даёт полной картины. Одна и та же задача решается в трёх:

```
# FOFA
title="Grafana" && cert="example.com"
# Censys
services.http.response.html_title: "Grafana" and services.tls.certificates.leaf_data.names: example.com
# ZoomEye
title:"Grafana" site:example.com
```

Результаты **объединяем, отсеиваем дубликаты** и проверяем версии: страница `/login` Grafana отдаёт версию. Так находятся устаревшие инстансы, которые и есть цель.

## Шаг 5: JARM — фингерпринт без баннера

Бывает, что сервис отдаёт только TLS-рукопожатие и ничего больше. Тогда работает **JARM** — активный фингерпринт: серверу шлют 10 специально собранных `ClientHello` и хэшируют ответы в 62-символьную строку.

```bash
pip install pyjarm
python3 -m pyjarm example.com
```

```
29d29d15d29d29d21c29d29d29d29d...
```

Один и тот же JARM у серверов C2-фреймворков (например, Cobalt Strike) позволяет найти **всю** инфраструктуру одного оператора. В Censys по нему ищут так: `services.tls.jarm.fingerprint: "29d29d..."`.

## Шаг 6: пайплайн «cert → поддомены → origin»

Самый продуктивный маршрут внешней разведки:

1. **Собрать имена** из Certificate Transparency (`crt.sh`).
2. **Обогатить** — прогнать имена по Censys и FOFA, собрать IP и порты.
3. **Найти origin** — сравнить favicon-хэш и JARM origin-IP с CDN-ответом.

```bash
curl -s "https://crt.sh/?q=%25.example.com&output=json" | jq -r '.[].name_value' | sort -u > names.txt
```

Дальше — по каждому имени запрос в FOFA. На выходе — реальные IP, включая те, что CDN маскирует за собой. Такой пайплайн повторяют регулярно: инфраструктура меняется, и новые имена появляются в CT-логах постоянно.

## Обогащаем найденные хосты

Список IP — это ещё не разведка. Каждый хост нужно обогатить:

1. **ASN и владелец** — по IP через whois.
2. **Домен** — по обратной DNS-записи.
3. **Технология и версия** — по баннеру и заголовкам.
4. **Уязвимость** — по версии, сопоставив её с CVE.
5. **Гео и хостинг** — страна, облако, CDN.

Так «список IP» превращается в приоритизированный список целей.

## Ограничения, лимиты и этика

Бесплатные тарифы быстро расходуются, поэтому планируйте запросы:

| Движок | Особенность | Лимит |
|---|---|---|
| Censys | точность TLS | небольшой месячный лимит |
| FOFA | favicon и азиатский сегмент | по тарифу |
| ZoomEye | ICS и азиатский сегмент | по тарифу |
| Shodan | широта охвата | 1 запрос в секунду |

Кэшируйте результаты локально, используйте `fields` для экономии квоты и соблюдайте rate-limit. Этическая граница та же, что и у Shodan: индексы содержат публично доступное, но активная проверка найденного сервиса — уже взаимодействие, требующее авторизации. Не логиньтесь в чужие панели и не эксплуатируйте найденное: фиксируйте находку и передавайте владельцу.

## Что мы теперь знаем

- Censys точен в TLS и структурированных полях, FOFA — в веб-отпечатках, ZoomEye — в Азии и ICS.
- Favicon-хэш (mmh3) связывает серверы одного продукта и находит origin за CDN.
- JARM — фингерпринт по TLS-рукопожатию, когда баннера нет.
- Один и тот же запрос нужно прогонять в 2–3 движках: у них разное покрытие.
- Отсутствие результата в одном движке — не доказательство отсутствия сервиса.

## На что смотреть дальше

Разберись с **SDK** движков (`pip install censys`) и **пагинацией** FOFA через `qbase64`, чтобы собирать объёмы без ручного curl. Помни, что FOFA принимает `qbase64` без url-safe-замены, поэтому для curl запрос кодируют через Python. Изучи, как обогащать найденные хосты по ASN, reverse DNS и версии ПО для поиска CVE. И держи в голове этику: пассивный просмотр кэша безопасен, а активная проверка сервиса — уже взаимодействие.

## Куда дальше

Мы научились комбинировать движки и находить origin через favicon и JARM. В следующем уроке — **веб-камеры и IoT**: возьмём конкретный класс устройств и соберём по ним дорки и фингерпринты. А пока главное запомни: полнота даётся не лучшим движком, а их объединением.

## Где пригодится

- **CTF:** поиск конкретного сервиса или панели по fingerprint.
- **Bug bounty:** расширение охвата и поиск origin за CDN.
- **Пентест:** инвентаризация внешней поверхности и устаревших сервисов.
- **Blue team:** поиск собственных случайно опубликованных сервисов.
