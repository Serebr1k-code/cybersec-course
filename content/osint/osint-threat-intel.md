## Вопрос, с которого всё начинается

Вы обогатили индикатор и получили вердикт «высокая уверенность, фишинг». Что дальше? Просто добавить домен в блок-лист — значит проиграть через день: атакующий сменит домен и продолжит. Настоящая разведка угроз (Threat Intelligence) отвечает на более глубокие вопросы: кто противник, какими инструментами он работает, через какую инфраструктуру и против кого. Здесь данные превращаются в решения.

Читателю уже знакомы индикаторы и обогащение. Здесь мы поднимаемся от одного индикатора к описанию кампании и к правилам детекта.

## Наш пример: инцидент с фишинговым вложением

Сотруднику пришло письмо с вложением; антивирус пометил файл, а из отчёта видно домен `secure-login.example`. Проведём это через конвейер аналитики угроз: определим уровень, отделим индикатор от поведения, привяжем к техникам, опишем кампанию и напишем правило детекта.

## Шаг 1: уровни разведки

Одна и та же находка смотрится по-разному на разных уровнях:

| Уровень | Для кого | Что даёт |
|---|---|---|
| Стратегический | руководство | риски, тренды, бюджет |
| Операционный | SOC/IR | кампании, техники, приоритеты |
| Тактический | аналитики | IOC: хэши, домены, IP |
| Технический | инструменты | сигнатуры, правила |

Список IP — это тактический уровень, а понимание кампании — операционный. В отчётах эти уровни не смешивают: руководителю не нужен хэш, а инженеру — тренды.

## Шаг 2: почему TTP ценнее индикатора

**TTP (Tactics, Techniques, Procedures)** — это «как» действует противник: его почерк. Индикатор же — конкретный хэш или IP, который легко сменить. Дэвид Бьянко описал это «пирамидой боли»: чем выше индикатор, тем дороже его сменить атакующему.

| Уровень | Индикатор | Боль для атакующего |
|---|---|---|
| Низ | хэш файла | тривиально (пересобрать) |
| ↓ | IP-адрес | легко (сменить VPS) |
| ↓ | домен | средне |
| ↓ | сетевой артефакт | ощутимо |
| Высок | инструмент (TTP) | дорого (переписать) |

Вывод: гоняйтесь за поведением, а не только за IOC, иначе детект устареет через сутки.

## Шаг 3: привязка к MITRE ATT&CK

**MITRE ATT&CK** — открытый каталог техник атак, каждая с номером. Он даёт общий язык для описания поведения. Разберём наше наблюдение — «фишинговое вложение с макросом»:

```
Наблюдение: фишинговый email с макросом
→ T1566.001 Spearphishing Attachment
→ T1204.002 User Execution: Malicious File
→ T1059.005 Command and Scripting: Visual Basic
```

Вместо расплывчатого «подозрительное письмо» мы получили три точные техники. Это устойчивее IOC: смена IP не меняет почерк.

## Шаг 4: Diamond Model — описываем кампанию

Чтобы описать кампанию целиком, используют **Diamond Model** — четыре вершины:

- **Adversary** — кто (группа, APT);
- **Capability** — чем (malware, эксплойт);
- **Infrastructure** — через что (C2-серверы, домены);
- **Victim** — против кого.

Заполнив модель, вы видите связи и пробелы: «есть инфраструктура и жертва, но неизвестен инструмент» — понятно, что копать дальше. Дополняет картину **Cyber Kill Chain** — семь этапов атаки (разведка → вооружение → доставка → эксплуатация → установка → C2 → действия): она показывает, где находку расположить на таймлайне и где прервать.

## Шаг 5: STIX — машиночитаемый обмен

Индикатор бесполезен, если его нельзя автоматически передать коллегам. **STIX 2.1** — стандартный язык описания угроз (объекты: Indicator, Malware, ThreatActor, AttackPattern и связи между ними). Наш домен в виде STIX-объекта выглядит так, и его можно разобрать через `jq`:

```
$ jq -r '"type=\(.type) pattern=\(.pattern) valid_from=\(.valid_from)"' stix.json
type=indicator pattern=[domain-name:value = 'secure-login.example'] valid_from=2026-01-01T00:00:00Z
```

Поле `pattern` формально описывает индикатор, `valid_from` — срок его действия. Транспорт для STIX называется **TAXII** (HTTPS + коллекции). Платформа **MISP** хранит события и автоматически связывает одинаковые индикаторы между событиями — так находятся общие кампании.

## Шаг 6: от индикатора к правилу детекта

Цель разведки — не список, а работающие правила. **Sigma** — вендор-независимый формат правил детекта, который конвертируется в запросы разных SIEM. Пример правила на именованный канал Cobalt Strike:

```yaml
title: Suspicious Cobalt Strike Named Pipe
logsource:
  product: windows
  category: pipe_created
detection:
  selection:
    PipeName|startswith: '\MSSE-'
  condition: selection
level: high
```

Проверим, что правило корректно разбирается:

```
$ python3 -c "import yaml;d=yaml.safe_load(open('rule.yml'));print('title:',d['title']);print('level:',d['level']);print('cond:',d['detection']['condition'])"
title: Suspicious Cobalt Strike Named Pipe
level: high
cond: selection
```

Цепочка «IOC → поведение → ATT&CK → Sigma → SIEM» превращает разрозненные индикаторы в алерты, которые сработают, даже когда атакующий сменит инфраструктуру.

## Шаг 7: обмен и оценка достоверности

Разведка — командная работа. Отраслевые центры обмена (ISAC) делятся угрозами внутри сектора, а MISP/OpenCTI связывают индикаторы с кампаниями и техниками. Но у обмена есть правила:

- **Уровень уверенности.** Каждый вывод маркируется (низкий/средний/высокий) и оценкой источника.
- **TLP** (Traffic Light Protocol) — маркировка распространения: `tlp:red` нельзя передавать дальше.
- **Срок годности.** У индикатора есть `valid_from`/`valid_until`.
- **Не путать атрибуцию и индикацию.** «Совпадает с APT28» ≠ «это APT28».

## Полный конвейер

Соберём шаги в одну линию — так выглядит типовой процесс от сырого индикатора до работающего алерта:

```
Сбор (фиды, MISP, honeypot, SOC)
  → Нормализация (STIX/CSV, дедупликация)
  → Обогащение (VirusTotal, passive DNS, Shodan, WHOIS)
  → Оценка (Admiralty: источник × достоверность)
  → Анализ (маппинг на ATT&CK, Diamond Model)
  → Публикация (MISP event, TAXII)
  → Детекция (Sigma/ATT&CK)
  → Обратная связь (что сработало, что пропущено)
```

Последний шаг не пропускайте: без обратной связи правила не уточняются, а ложные срабатывания копятся и убивают доверие к системе.

## Частые ошибки аналитика

- **Доверять одному источнику.** Верифицируйте через два-три независимых.
- **Гнаться за IOC** и игнорировать TTP — детект устареет за сутки.
- **Игнорировать TLP.** `tlp:red` нельзя передавать дальше.
- **Публиковать IOC без контекста** — бесполезно и опасно (ложные блокировки).
- **Забыть про срок годности.** У индикатора есть `valid_until`.
- **Путать атрибуцию и индикацию.** Совпадение с известной группой — не доказательство её авторства.

## Что мы теперь знаем

- Разведка угроз работает на четырёх уровнях: стратегический, операционный, тактический, технический.
- TTP устойчивее IOC: почерк дороже сменить, чем IP.
- MITRE ATT&CK даёт номера техник для точного описания поведения.
- Diamond Model описывает кампанию по четырём вершинам; Kill Chain — по этапам.
- STIX/TAXII/MISP — форматы обмена; Sigma превращает индикатор в правило детекта.

## Куда дальше

В следующем уроке мы спустимся от кампании к одному индикатору и разберём обогащение по шагам — как из одной строки вырастает карта инфраструктуры. А пока главное запомни: разведка угроз — это не список блокировок, а понимание противника и правил, которые его ловят.

## Где пригодится

- **SOC/IR:** обогащение инцидентов и построение детекций.
- **Threat intel:** публикация и обмен качественными данными.
- **CTF (OSINT):** структурировать разрозненные подсказки в кампанию.
- **Работа:** стратегические отчёты о рисках.
