X (бывший Twitter) — источник мнений, контактов и технического контекста: разработчики жалуются на инфраструктуру, компании анонсируют стек, люди публикуют скриншоты. Ключ к эффективности — операторы поиска и архивы (в т.ч. Nitter-зеркала, когда API закрыт). В этом уроке — практическая методика.

## Теория: операторы и структура

Поиск X понимает операторы:

| Оператор | Смысл | Пример |
|----------|-------|--------|
| `from:` | посты пользователя | `from:example` |
| `to:` | ответы пользователю | `to:example` |
| `since:`/`until:` | диапазон дат | `since:2023-01-01 until:2023-06-01` |
| `near:`/`within:` | геолокация | `near:Moscow within:15km` |
| `filter:media` | только медиа | `filter:images` |
| `filter:links` | только ссылки | `filter:links` |
| `"..."` | точная фраза | `"internal server"` |
| `-` | исключение | `example -filter:replies` |

Профиль даёт: bio, локацию, ссылку, дату регистрации, закреплённые посты, подписки/подписчиков.

## Инструменты и команды

Веб-поиск (в браузере) — самый надёжный путь. URL-форма:

```text
https://x.com/search?q=from%3Aexample%20since%3A2023-01-01&f=live
```

Nitter-зеркала (когда API/логин недоступны) — публичные инстансы:

```bash
# список инстансов: https://github.com/zedeus/nitter/wiki/Instances
curl -s "https://nitter.net/example" | grep -oE 'status/[0-9]+' | head
```

Архивы удалённых твитов:

```bash
# Wayback
curl -s "http://archive.org/wayback/available?url=twitter.com/example" | jq
# Google cache (если ещё жив) — через браузер
```

Мониторинг и экспорт:

- **twscrape / snscrape** — сбор постов без ключа API (периодически ломается):

```bash
pip install snscrape
snscrape --jsonl twitter-user example | jq -r '.content' | head
```

## Разобранный пример: технический контекст компании

Дано: аккаунт `@example`.

Шаг 1 — профиль и bio: ссылка на сайт, локация, дата регистрации.

Шаг 2 — технический стек из постов:

```text
from:example (kubernetes OR "1С" OR postgres OR "server down")
```

Находим жалобы на конкретные технологии и инциденты.

Шаг 3 — сотрудники через ответы и упоминания:

```text
to:example -filter:replies
```

Шаг 4 — геолокация офиса:

```text
near:Moscow within:5km from:example
```

Шаг 5 — удалённые посты через Wayback/Nitter: ищем старые версии профиля.

Шаг 6 — временные паттерны: когда аккаунт активен, когда молчит (отпуска, инциденты).

## Построение графа связей

X — это граф: кто на кого отвечает, кого цитирует, с кем взаимодействует. Это раскрывает структуру команды и сообщества:

- **Ответы (`to:`)** — кто общается с аккаунтом.
- **Упоминания** — взаимные связи между сотрудниками.
- **Списки (Lists)** — тематические подборки (часто «сотрудники компании»).
- **Ретвиты/цитаты** — распространение идей и внутренние шутки.
- **Общие подписки** — пересечение интересов.

```text
from:example -filter:replies        # собственные посты (не ответы)
to:example                          # входящие ответы
"@example" filter:links             # упоминания со ссылками
```

Собрав граф, вы видите ключевых «хабов» — людей, через которых идёт коммуникация.

## Временной анализ и активность

- **Таймзона**: часы активности аккаунта выдают рабочий часовой пояс.
- **График**: перерывы = отпуска/выходные; всплески = инциденты/анонсы.
- **Deleted tweets**: через Wayback/Nitter можно восстановить удалённое.
- **История bio**: смена должности/компании в bio фиксируется в архивах.
- **Закреплённые твиты**: актуальные приоритеты аккаунта.

```bash
# Wayback: снимки профиля по датам
curl -s "http://web.archive.org/cdx/search/cdx?url=twitter.com/example&output=text&fl=timestamp,original&collapse=digest" | head
```

## Медиа и изображения

Скриншоты в постах — богатейший источник:

- **Дашборды и ошибки**: внутренние URL, версии ПО, названия сервисов.
- **Метаданные**: если фото загружено «как есть», EXIF может содержать GPS/устройство (см. osint-metadata).
- **Reverse image**: связывает аватар/фото с другими аккаунтами (см. osint-image-reverse).
- **OCR**: читайте текст с картинок (Lens) — часто там тикеты, логи, конфиги.

## Продвинутые приёмы

- **Скриншоты внутренних систем:** в постах разработчиков часто видны URL, дашборды, ошибки — карта инфраструктуры.
- **Thread-анализ:** цепочки тредов раскрывают детали инцидентов.
- **List-мониторинг:** списки сотрудников позволяют отслеживать их без подписки.
- **Image reverse:** аватары связывают аккаунты (см. osint-image-reverse).
- **Deleted tweets:** Nitter + Wayback + архивы типа `threadreaderapp`.
- **API-эквиваленты:** официальный API (платный) для массового сбора в легальных задачах.

## Threat intel на X

X — канал быстрого распространения IOC и утечек. Практика: подписка на исследовательские аккаунты, поиск по хэшам/доменам из инцидента (`"<hash>" OR "<domain>"`), сбор ссылок на новые малвари через `filter:links`. Для мониторинга используйте Lists и уведомления, а не API (лимиты). Важно фильтровать шум: много репостов, мало первоисточников — ищите автора оригинального поста.

| Инструмент | Назначение |

## Частые ошибки

- **Игнорировать операторы.** Без `from:`/`since:` поиск тонет в шуме.
- **Полагаться только на один Nitter-инстанс.** Они падают и блокируются.
- **Забывать про даты.** Пост 2019 года о стеке может быть уже неактуален.
- **Верить удалённому = исчезло.** Архивы часто сохраняют контент.
- **Скрейпить агрессивно.** Бан и лимиты; соблюдайте темп.
- **Путать официальный и фанатский аккаунт.** Проверяйте верификацию и ссылки.

## Юридические рамки

Публичные посты — можно; массовый сбор и профилирование людей — с осторожностью. Не используйте данные для преследования, не выдавайте гипотезы за факты, фиксируйте источник и дату (посты удаляются). В расследованиях храните минимум ПДн и маскируйте лишнее в отчёте.

## Что делать дальше / решение

- **Нужен стек компании** → `from:` + технологии → скриншоты → фреймворки.
- **Нужны сотрудники** → `to:` + упоминания + Lists → кросс-корреляция.
- **Нужно удалённое** → Wayback/Nitter/threadreader.
- **Нужен мониторинг** → Lists + уведомления + регулярный поиск по IOC.

## Продвинутые комбинации операторов

Мощь X-поиска — в комбинациях. Полезные шаблоны:

- **Конкретный человек + период**: `from:user since:2024-01-01 until:2024-03-01 (кубер OR deploy OR outage)`.
- **Утечка ссылок на внутренние ресурсы**: `from:user filter:links (gitlab OR jenkins OR grafana)`.
- **Геолокация + медиа**: `near:"Example City" within:10km filter:images`.
- **Ответы от конкретного круга**: `to:user (from:colleague1 OR from:colleague2)`.
- **Поиск скриншотов**: `from:user filter:images (dashboard OR "500" OR "stack trace")`.
- **Исключение шума**: `"example.com" -filter:replies -filter:retweets`.

Комбинируя `from:`, `to:`, `filter:` и даты, вы из шумной ленты вырезаете точный срез: кто, когда и о чём говорил, — и получаете основу для графа и таймлайна.

## Работа с тредами и сообществами

Треды — это структурированные мини-отчёты. Для анализа:

- **Thread reader** (`threadreaderapp.com`) разворачивает цепочку в одну страницу.
- **Квотирование** (`quoted_tweet_id`) связывает реакцию с исходным постом.
- **Сообщества** (Communities) группируют людей по теме — фактически готовые «списки».
- **Списки (Lists)** — лучший способ мониторить группу людей без подписки на каждого.

```text
from:user "thread" "1/"          # начало треда
"@user" (kubernetes OR incident) # реакция сообщества
```

Так вы находите не только посты цели, но и круг её общения — контекст для атрибуции.

## Таймлайн активности аккаунта

Собрав посты с датами, стройте таймлайн:

```bash
snscrape --jsonl --since 2023-01-01 twitter-user example \
  | jq -r '[.date,.content]|@tsv' | sort > timeline.tsv
```

- **Часы публикаций** → часовой пояс (рабочее время).
- **Паузы** → отпуска, болезни, смена работы.
- **Всплески** → инциденты, релизы, утечки.
- **Смена тона/темы** → организационные изменения.

Таймлайн пересекается с другими источниками (объявления, коммиты) и даёт независимое подтверждение событий.

## Где пригодится

- **CTF (OSINT):** найти подсказку в старом твите или геолокации.
- **Threat intel:** мониторинг аккаунтов угроз, сбор IOC из постов.
- **Bug bounty:** понимание стека и контактов компании.
- **Blue team:** обнаружение утечек через соцсети сотрудников.
