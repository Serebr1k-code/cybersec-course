## Вопрос, с которого всё начинается

Ты хочешь понять, какие почтовые ящики есть у организации `example.com`. Новичок просто перебирает адреса наугад — и получает тысячи «успехов», которые ничего не значат.

**SMTP** — протокол отправки почты — умеет отвечать на вопросы о пользователях. Команды `VRFY`, `EXPN` и `RCPT TO` позволяют проверить, существует ли ящик. Разберём это на одном домене.

## Наш пример: домен example.com и сервер mail.example.com

У нас один объект — почтовый сервер `mail.example.com` для домена `example.com`. Задача: собрать валидные ящики. Начнём с изучения самого сервера.

## Шаг 1: знакомимся с сервером

Смотрим баннер и поддержку команд:

```bash
nc mail.example.com 25
```

```
220 mail.example.com ESMTP Postfix
```

Сервер — Postfix. Теперь проверим команду `VRFY` (verify) — «существует ли такой пользователь?»:

```
EHLO test
VRFY admin
```

```
252 2.0.0 Cannot VRFY user, but will accept message and attempt delivery
```

Ответ `252` означает «не могу подтвердить». На современных серверах (Postfix, Exchange) `VRFY` почти всегда закрыт, поэтому перебор через него не выйдет. Остаётся метод `RCPT`.

## Шаг 2: разбираемся в кодах ответов

Перебор опирается на реакцию сервера. Запомним ключевые коды:

| Код | Значение | Вывод |
|---|---|---|
| 250 | OK | ящик существует |
| 252 | cannot VRFY | сервер не подтверждает |
| 450 | временная ошибка | повторить позже |
| 550 | no such user | ящика нет |

Код `252` — не успех: он значит «не знаю», а не «существует». Это частая ошибка новичка.

## Шаг 3: собираем словарь

Перебор начинается со словаря. Сначала — типовые служебные адреса:

```bash
printf '%s\n' admin administrator root postmaster webmaster info support \
  sales billing noreply security abuse > users.txt
```

Затем — имена сотрудников. Их формат определяют по OSINT: из LinkedIn или утечек видно, что принято `i.ivanov@`, `ivanov@` или `ivan@`. Перебирать нужно **только** этот формат, иначе будет шум.

## Шаг 4: проверяем один адрес вручную

Прежде чем запускать перебор, проверим один адрес через `swaks` — он останавливается сразу после ответа на `RCPT`, не отправляя письмо:

```bash
swaks --to admin@example.com --from probe@example.com --server mail.example.com --quit-after RCPT
```

```
-> RCPT TO:<admin@example.com>
<- 250 2.1.5 Ok
```

Ответ `250` — ящик существует.

## Шаг 5: запускаем перебор

Инструмент **smtp-user-enum** автоматизирует проверку по словарю:

```bash
smtp-user-enum -M RCPT -U users.txt -D example.com -t mail.example.com -m 10 -w 2
```

```
250  admin@example.com
250  sales@example.com
550  hostmaster@example.com
```

Метод `RCPT` надёжнее `VRFY`. Флаг `-m 10` задаёт интервал между запросами (защита от блокировки), `-w 2` — таймаут, `-D` — домен для `RCPT`. Обрати внимание: перебор — активная и заметная операция, поэтому список и темп ограничивают.

## Шаг 6: проверяем catch-all

Самая коварная ловушка — **catch-all**: сервер принимает **любой** адрес домена. Тогда весь перебор — ложь. Проверяется случайным именем-приманкой:

```bash
swaks --to zzq7x9nonexist@example.com --from probe@example.com --server mail.example.com --quit-after RCPT
```

```
<- 550 5.1.1 <zzq7x9nonexist@example.com>: Recipient address rejected
```

Ответ `550` — catch-all выключен, значит результаты перебора достоверны. Если бы пришло `250`, перебор был бы бессмысленным.

## Шаг 7: учитываем защиту

Сервер может мешать перебору:

- **Tarpitting** — задержка после нескольких попыток: `smtp-user-enum` замедлится.
- **Greylisting** — временный ответ `450` на первый запрос, нужны повторы с паузами.
- **Rate-limit и Fail2ban** — блокировка IP: снижайте темп.
- **Единый ответ** на существующий и несуществующий ящик — enumeration невозможен в принципе.

## Шаг 8: зачем это нужно

Собранные валидные адреса — основа для дальнейших шагов:

- **Фишинг** — только в авторизованном scope.
- **Проверка утечек** — прогон каждого адреса по HIBP.
- **Вывод формата** — для остальных сотрудников.
- **Корреляция** с соцсетями и утечками.

Именно поэтому enumeration — заметная и юридически чувствительная операция: её проводят только при наличии задания.

## Шаг 9: альтернативные методы

`RCPT` — не единственный путь. Если `VRFY` открыт (бывает на старых и самописных серверах), перебор идёт через него и часто быстрее:

```bash
smtp-user-enum -M VRFY -U users.txt -t mail.example.com
```

`EXPN` (expand) раскрывает содержимое списка рассылки — иногда выдаёт сразу десятки адресов:

```
EXPN staff
250 <a.ivanov@example.com>
250 <b.petrov@example.com>
```

Ещё один источник — `nmap` со скриптом `smtp-enum-users`, который пробует несколько методов и сравнивает ответы:

```bash
nmap -p 25 --script smtp-enum-users --script-args smtp-enum-users.methods={VRFY,RCPT} mail.example.com
```

## Полный прогон от начала до конца

1. `nc mail.example.com 25` → баннер `Postfix`.
2. `VRFY admin` → `252`, метод закрыт, идём через `RCPT`.
3. Собираем словарь: служебные адреса плюс формат из LinkedIn.
4. `swaks --quit-after RCPT` на `admin@` → `250`, ящик есть.
5. Приманка `zzq7x9nonexist@` → `550`, catch-all выключен.
6. `smtp-user-enum -M RCPT -U users.txt -D example.com -t mail.example.com -m 10` → список валидных адресов.
7. Прогоняем список по HIBP и коррелируем с людьми.

## Что мы теперь знаем

- `VRFY` на современных серверах закрыт; работает метод `RCPT`.
- Код `252` — не подтверждение, а «не знаю»; `550` — ящика нет.
- Формат адресов определяют по OSINT и перебирают только его.
- `swaks --quit-after RCPT` проверяет адрес быстро и без отправки.
- Catch-all проверяют приманкой: `250` на случайный адрес делает перебор ложным.
- Перебор активен и заметен, поэтому его темп и объём ограничивают.

## На что смотреть дальше

Разберись с **открытым релеем**: если сервер принимает `RCPT TO` на внешний домен при чужом `MAIL FROM`, он может пересылать чужую почту. Проверяй `STARTTLS` — без обязательного шифрования учётные данные уходят открыто. И изучи, как собранные адреса проверяются по утечкам и коррелируются с людьми.

## Справочник: коды ответов SMTP

Весь перебор держится на кодах ответа сервера. Выучи ключевые:

| Код | Значение | Что делать |
|---|---|---|
| 220 | сервис готов | начинай сессию |
| 250 | OK, пользователь существует | записывай в найденные |
| 252 | не могу подтвердить, но принимаю | обычно тоже «есть» |
| 450 / 451 | временная ошибка | повтори позже |
| 550 | пользователь не найден | отбрасывай |
| 551 / 553 | адрес не принят | отбрасывай |
| 421 | слишком много соединений | снизь темп |

Главное различие: **550 vs 450**. 550 — «нет такого», 450 — «попробуй позже». Путаница между ними даёт ложные срабатывания, поэтому проверяй сервер на заведомо несуществующем адресе.

## Мини-практика: ручная проверка через openssl

Прежде чем запускать перебор, убедись вручную, что сервер вообще отдаёт разницу между существующим и несуществующим адресом:

```
$ openssl s_client -connect mail.example.com:25 -starttls smtp -quiet
EHLO probe.local
MAIL FROM:<test@probe.local>
RCPT TO:<postmaster@example.com>
RCPT TO:<nobody-zzz@example.com>
```

Если на первый `RCPT` придёт `250`, а на второй — `550`, сервер различает адреса и перебор имеет смысл. Если оба дают `250`, у сервера **catch-all** — он принимает всё, и перебор бесполезен.

## Если не сработало

- **Все ответы `250`.** Это catch-all. Ищи альтернативы: перебор через API, `VRFY` (если разрешён), проверку утечек.
- **Соединение рвётся после EHLO.** Сервер использует **greylisting** или блокирует по IP. Замедлись или смени источник.
- **Порт 25 закрыт.** Попробуй 587 (submission) и 465 (smtps); на них `STARTTLS`/TLS задаётся иначе.
- **`VRFY`/`EXPN` отключены (502).** Это норма для современных серверов — переходи к `RCPT TO`.
- **Много ложных «есть».** Сервер может отвечать `252` на всё. Проверь на явном мусоре и отбрось такие ответы.

## Справочник: команды SMTP

Сессия SMTP — это диалог командами. Минимальный набор для энумерации:

| Команда | Назначение |
|---|---|
| `EHLO <домен>` | поздороваться и узнать расширения |
| `HELO <домен>` | старая версия приветствия |
| `MAIL FROM:<адрес>` | задать отправителя |
| `RCPT TO:<адрес>` | проверить получателя (ядро энумерации) |
| `VRFY <имя>` | проверить имя пользователя (часто отключено) |
| `EXPN <список>` | раскрыть список рассылки |
| `STARTTLS` | перейти на шифрование |
| `NOOP` | проверить, жив ли канал |
| `QUIT` | закрыть сессию |

Ядро — `RCPT TO`: именно по коду ответа на него мы понимаем, существует ли ящик. `VRFY`/`EXPN` удобны, но современные серверы их запрещают (502), поэтому основной путь — `RCPT`.

## Шпаргалка: порядок действий

- Проверь `220` при подключении — сервер жив.
- `EHLO` покажет расширения и лимиты.
- Один `RCPT TO` на существующий и один на мусор — сравни коды.
- Разные коды → перебор имеет смысл; одинаковые → catch-all.
- `421`/`450` — притормози; `550` — ящика нет.

## Куда дальше

Мы научились подтверждать существование ящиков через SMTP. В следующем уроке — **авиационные данные**: разберём, как по открытым источникам отследить самолёт и связать его с владельцем. А пока главное запомни: проверяй catch-all до перебора — иначе «успех» ничего не значит.

## Где пригодится

- **CTF:** подтверждение существующего ящика для дальнейших шагов.
- **Bug bounty:** сбор валидных адресов в рамках программы.
- **Пентест:** подготовка списка учёток для фишинга и подбора.
- **Blue team:** проверка, не раскрывает ли ваш сервер пользователей.
