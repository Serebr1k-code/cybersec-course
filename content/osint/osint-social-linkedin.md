LinkedIn — самый структурированный источник по организациям: должности, отделы, связи, стек. Из профилей сотрудников выводится оргструктура, ключевые технические роли и корпоративный email-паттерн. Это фундамент для легитимного фишинга и оценки поверхности. В этом уроке — методика картирования с уважением к ToS.

## Теория: что даёт LinkedIn

- **Компания:** размер, отрасль, офисы, сайт, специализации.
- **Сотрудники:** имя, должность, отдел, стаж, навыки, сертификаты.
- **Стек:** навыки и описания вакансий раскрывают технологии (Kubernetes, 1С, SAP).
- **Связи:** коллеги, рекомендации, общие группы → граф организации.
- **Сигналы:** массовые увольнения, набор в ИБ → изменения приоритетов.

Даже без логина превью профилей видны в поисковиках. LinkedIn агрессивно банит скрейпинг, поэтому основная работа — через поиск и официальные/платные API.

## Инструменты и команды

Дорки через поисковик:

```text
site:linkedin.com/in "Example Corp"
site:linkedin.com/company example
site:linkedin.com/in "DevOps" "Example Corp"
site:linkedin.com/in "security" "Example Corp"
```

Постраничный сбор (осторожно, ToS):

```bash
for p in 0 10 20 30; do
  curl -s -A "Mozilla/5.0" "https://www.bing.com/search?q=site:linkedin.com/in+%22Example+Corp%22&first=$p" \
    | grep -oE 'linkedin\.com/in/[a-zA-Z0-9-]+' | sort -u
  sleep 3
done
```

Инструменты:

- **theHarvester** — сбор сотрудников и email:

```bash
theHarvester -d example.com -b linkedin -l 200
```

- **linkedin-api / Proxycurl** — платные/официальные способы.
- **Google X-Ray** — поиск профилей без захода в LinkedIn.

## X-Ray и Google-операторы

X-Ray — это поиск по LinkedIn через внешний поисковик, без авторизации и без риска бана:

```text
site:linkedin.com/in "Example Corp" (CTO OR CISO OR "Head of")
site:linkedin.com/in "Example Corp" (DevOps OR SRE OR "Platform Engineer")
site:linkedin.com/in "Example Corp" (security OR SOC OR blue team)
site:linkedin.com/company "Example Corp" -inurl:jobs
```

Комбинируйте с `before:`/`after:` для свежих профилей и с `-inurl:jobs` для отсечения вакансий. Сохраняйте найденные профили в таблицу: имя, роль, отдел, локация.

## Разобранный пример: от компании к оргструктуре

Дано: компания `Example Corp`.

Шаг 1 — страница компании: размер (200–500), отрасль, офисы.

Шаг 2 — X-Ray по ролям:

```text
site:linkedin.com/in "Example Corp" (CTO OR "Head of Security" OR DevOps OR SRE)
```

Собираем ключевые фигуры: CEO, CTO, CISO, DevOps, администраторы.

Шаг 3 — определяем стек из навыков и вакансий:

```text
site:linkedin.com/jobs "Example Corp" kubernetes
```

Шаг 4 — выводим email-паттерн (см. osint-spf-dkim для верификации): `first.last@`, `f.last@`, `first@`.

Шаг 5 — строим граф: подразделения → роли → имена → соцсети → email.

Шаг 6 — фиксируем «критичных» сотрудников (доступ к прод, ИБ) как приоритет для scope-анализа.

## Продвинутые приёмы

- **Навыки как инвентарь:** список технологий из навыков → потенциальные уязвимости (устаревший стек).
- **Рекомендации:** связи подтверждают реальное взаимодействие людей.
- **Активность:** комментарии и репосты показывают «живых» и влиятельных сотрудников.
- **Сертификаты:** сертификаты раскрывают используемые вендоры (AWS, Cisco, Microsoft).
- **Job postings:** вакансии = карта того, что строится и где боль.
- **Мобильность:** смена места работы у сотрудников — сигнал изменений.

## Дополнительные слои LinkedIn

- **Навыки (Skills)**: агрегируйте по всем сотрудникам → инвентарь технологий компании.
- **Сертификаты (Licenses)**: AWS/GCP/Cisco/Microsoft → используемые вендоры.
- **Рекомендации**: подтверждают рабочие связи (граф взаимодействий).
- **Группы**: отраслевые сообщества → обсуждения стека и боли.
- **Вакансии (Jobs)**: что строят сейчас, какие технологии, где узкие места.
- **Публикации/посты**: технические детали архитектуры, инциденты, дашборды.

```text
site:linkedin.com/posts "Example Corp" (kubernetes OR outage OR migration)
```

## Вывод email-паттерна и его верификация

Из имён сотрудников выводится корпоративный формат адреса:

- `first.last@example.com` — самый частый.
- `f.last@`, `first@`, `last@`, `flast@` — вариации.

Проверка паттерна (без отправки писем):

```bash
# SMTP VRFY/RCPT — только при разрешении (см. osint-smtp-enum)
smtp-user-enum -M RCPT -U candidates.txt -D example.com -t mail.example.com
```

Или косвенно: HIBP domain search, утечки, автоответчики. Точный паттерн превращает список имён в список **валидных адресов** — основу для легитимного фишинга/тестирования.

## От карты к приоритизации

Собранные данные превращаются в приоритеты:

1. **Ключевые технические лица** (CISO, DevOps, SRE) → целевые аккаунты для симуляций.
2. **Стек** → технологии для фингерпринта и поиска уязвимостей.
3. **Структура** → отделы и их системы.
4. **Email-паттерн** → список валидных адресов.
5. **Активность** → периоды изменений (релизы, миграции, инциденты).

## Инструменты и флаги

| Инструмент | Команда | Назначение |
|---|---|---|
| theHarvester | `theHarvester -d example.com -b linkedin -l 200` | сотрудники и email |
| Bing/Google | `site:linkedin.com/in "..."` | X-Ray профилей |
| Proxycurl / linkedin-api | REST | официальный сбор |
| HIBP domain | `hibp -d example.com` | email-паттерн |
| Wayback | `web.archive.org/web/*/linkedin.com/in/*` | старые профили |

## Частые ошибки

- **Скрейпинг в лоб.** LinkedIn банит по IP и аккаунту; используйте паузы/официальные API.
- **Доверять устаревшим профилям.** Люди не обновляют стаж и должности.
- **Путать компании-тёзки.** Проверяйте домен и локацию.
- **Игнорировать ToS.** Сбор ПДн — только в авторизованном scope и по делу.
- **Пропускать косвенные сигналы.** Увольнения и вакансии важнее должностей.
- **Нет структуры.** Без таблицы/графа данные бесполезны.

## Что делать дальше / решение

- **Нужны сотрудники** → X-Ray по ролям, собрать в таблицу, дедуплицировать.
- **Нужен стек** → навыки + вакансии, сопоставить с техниками фингерпринта.
- **Нужны email** → вывести паттерн, верифицировать через HIBP/SMTP (если разрешено).
- **Нужна структура** → сгруппировать по отделам и локациям, отметить критичные роли.

## Работа через официальные API и лимиты

LinkedIn официально отдаёт данные через **Marketing/Pages API** (токен приложения) и партнёрские API (Proxycurl, Phantombuster). Для OSINT это важно по двум причинам: официальный доступ не приводит к бану, а результаты стабильнее скрейпинга. Лимиты и правила:

- **Rate limit** на запросы — ставьте паузы и кэшируйте.
- **ToS**: массовый сбор персональных данных запрещён; работайте в рамках scope.
- **Превью без логина** видны в поисковиках — это самый безопасный вход.

```bash
# Proxycurl (пример, ключ в переменной)
curl -s "https://nubela.co/proxycurl/api/v2/linkedin?url=https://linkedin.com/in/..." \
  -H "Authorization: Bearer $PROXYCURL_KEY" | jq '.occupation, .experiences'
```

## Профилирование конкретных ролей

Разные роли дают разные зацепки:

- **CISO / Head of Security** — инструменты ИБ, стандарты (ISO, SOC2), вендоры.
- **DevOps / SRE** — облако (AWS/GCP), CI/CD, Kubernetes, мониторинг.
- **Backend / Data** — языки, БД, очереди, ML-стек.
- **Администраторы** — Active Directory, Windows-инфраструктура.
- **Менеджеры** — процессы, подрядчики, партнёры.

```text
site:linkedin.com/in "Example Corp" ("CISO" OR "SOC" OR "GRC")
site:linkedin.com/in "Example Corp" ("Terraform" OR "ArgoCD" OR "EKS")
```

## Юридические и этические рамки

LinkedIn — персональные данные. Границы: собирайте только публичное, храните минимум, указывайте источник и дату, не используйте данные для преследования или таргетированного спама. В bug bounty сверяйтесь с правилами программы: часто сбор сотрудников разрешён, а контакт с ними — только через оговорённый канал. В пентесте профилирование должно служить защите клиента, а не давлению на людей.

## Строим граф организации: практический пайплайн

Карта организации — это таблица + граф. Минимальный пайплайн:

1. **Компания** → `site:linkedin.com/company` → размер, отрасли, офисы.
2. **Люди** → X-Ray по ролям → имя, должность, локация, URL профиля.
3. **Стек** → навыки + вакансии → технологии и вендоры.
4. **Email** → вывод паттерна из имён → кандидаты.
5. **Связи** → рекомендации и общие группы → рёбра графа.

```text
# собрать роли одним проходом
site:linkedin.com/in "Example Corp" (CISO OR CTO OR "Head of" OR DevOps OR SRE OR "Data")
```

Результат оформляйте в CSV: `name, role, dept, location, profile, email_guess, confidence`. Отдельным столбцом — «критичность» (доступ к прод, ИБ, платежи). Так карта становится основой для приоритизации тестирования и планирования фишинговой симуляции.

## Как читать профиль: чек-лист полей

Публичное превью профиля отдаёт больше, чем кажется. Смотрите по порядку: **заголовок (headline)** — фактическая роль; **About** — стек и самопрезентация; **Experience** — работодатели и длительность (сигнал текучести); **Skills** — технологии; **Licenses** — вендоры; **Education** — выпускники-связи; **Recommendations** — подтверждённые контакты; **Activity** — что постит и комментирует; **Groups** — сообщества. Пропущенный About часто прячет самое полезное: там указывают «Python, AWS, Kafka», что сразу даёт стек для фингерпринта. Сохраняйте в таблицу только подтверждённое, а догадки (email-паттерн) помечайте как гипотезу.

## LinkedIn для защиты (blue team)

LinkedIn — двусторонний инструмент: атакующий картирует организацию, защитник использует ту же карту для тренировок и контроля. Что полезно обороняющейся стороне: инвентаризация публичных ролей и стека (что уже «утекло»), обучение сотрудников распознаванию X-Ray-разведки, минимизация чувствительных деталей в профилях (внутренние названия систем, точные версии). Рекомендация клиентам: убрать из публичных профилей упоминания внутренних инструментов и не публиковать архитектурные детали в постах — это снижает поверхность для целевого фишинга.

## Где пригодится
