Обратный поиск изображений — один из базовых инструментов OSINT: вы подаёте картинку и получаете страницы, где она встречается. Это помогает найти источник фото, оригинал (до кадрирования), связанные аккаунты и, иногда, точное место. Но разные движки находят разное, а «голый» поиск часто бесполезен — нужны правильные приёмы: кадрирование, отражение, улучшение. Это отдельный навык, а не одна кнопка.

## Как работает reverse image search

Движок извлекает из изображения признаки (перцептивные хэши, ключевые точки, цветовые гистограммы, текстовые совпадения) и ищет похожие в своём индексе. Разные движки используют разные признаки: **TinEye** — точные совпадения (в т.ч. кадрированные/изменённые), **Google** — семантически похожие, **Yandex** — лица и объекты, **PimEyes** — только лица. Понимание этого определяет, какой движок использовать.

## Основные движки

| Движок | Сильная сторона |
|---|---|
| Google Images | Широкий охват, «похожие» |
| Yandex Images | Лица, объекты, СНГ-контент |
| Bing Visual Search | Хорош по товарам/местам |
| TinEye | Точные и изменённые копии |
| PimEyes | Поиск по лицу |
| SauceNAO | Аниме/арт, pixiv/twitter |
| Karma Decay | Reddit-посты |

## Специализированные движки

- **PimEyes** — поиск по лицу; показывает, где лицо встречается в сети. Мощно, но этически чувствительно.
- **SauceNAO** — идентификация арта по базе pixiv/deviantart/twitter; полезно в CTF/аниме-задачах.
- **Search4Faces / Betaface** — альтернативы для лиц.
- **Google Lens** — распознаёт объекты, текст, товары.
- **Yandex «похожие»** — находит варианты изображения.

## Методы повышения результата

1. **Кадрирование (crop).** Убрать фон, оставить ключевой объект/лицо — движок точнее.
2. **Отражение (flip).** Некоторые копии зеркальные — ищите и отражённую версию.
3. **Улучшение (enhance).** Повысить контраст/резкость, убрать шум.
4. **Поиск по фрагменту.** Маленький фрагмент (логотип, вывеска) может дать точное место.
5. **Изменение размера.** Иногда апскейл помогает.
6. **Метаданные.** Перед поиском проверьте EXIF (`osint-exif-deep`).

## Разобранный пример

Дано: фото человека на фоне здания. Задача — найти источник и место.

1. Прогоняем через Google Images — получаем похожие, но не источник.
2. Кадрируем лицо → PimEyes/Yandex по лицу → находим соцсети.
3. Кадрируем вывеску/логотип → Google Lens → определяем компанию/город.
4. Прогоняем полное фото через TinEye → находим оригинал (большего размера) с датой.
5. По оригиналу читаем EXIF (если есть) → камера/время.
6. Комбинируем: лицо + место + дата → профиль и локация.
7. Верифицируем через `osint-verification`.

## Геолокация по фото

Комбинируйте признаки:

- **Текст/вывески** (язык, бренды, номера) → страна/город.
- **Архитектура/растительность** → регион/климат.
- **Номера домов/машин** → район.
- **Тени** (см. `osint-shadow-analysis`) → время/ориентация.
- **Спутниковые снимки** (см. `osint-satellite`) → точное место.
- **Обратный поиск** → другие фото того же места.

## Деанон и этика

Reverse image search может деанонимизировать человека по фото — это мощно и опасно. Правила: анализируйте публичные данные в законных целях (журналистика, расследование, authorized OSINT); не преследуйте; не публикуйте найденное без нужды. Помните: **сама возможность найти не означает право использовать**.

## Защита

- Удаляйте EXIF перед публикацией.
- Не публикуйте фото, по которым легко найти дом/работу.
- Используйте приватные профили и ограничение видимости.
- Для чувствительных фото — избегайте публикации вообще.
- Проверяйте, что попало в сеть (reverse search своих фото).

## Подводные камни

- **Кадрирование убивает точный поиск.** TinEye может не найти, а Google — найти «похожее».
- **Зеркальные копии.** Ищите и отражённые варианты.
- **Метаданные вычищены** соцсетями (но не всегда).
- **Ложные совпадения** (похожие люди/места).
- **PimEyes и приватность.** Использование по лицу требует особой осторожности.
- **Устаревание индекса.** Свежие фото могут ещё не проиндексироваться.

## Что дальше / решение

Обратный поиск — основа геолокации и деанона; свяжите с `osint-image-reverse`, `osint-geolocation`, `osint-exif-deep`, `osint-satellite`, `osint-verification`. Дальше — комбинирование признаков и верификация. Для CTF тренируйтесь находить место по фото через вывески и обратный поиск.

## Кейс: от фото к аккаунту

Разберём типовую цепочку деанона (в законных целях). Дано одно фото человека в кафе.

1. **Полное фото** → Google Images: находим несколько репостов, но не оригинал.
2. **Кадр с лицом** → Yandex/PimEyes: находим профиль в соцсети с похожим лицом.
3. **Кадр с вывеской/логотипом** → Google Lens: определяем сеть кафе и город.
4. **Полное фото** → TinEye: находим оригинал большего размера — вероятно, из поста с геометкой.
5. **Оригинал** → `exiftool`: читаем камеру/время (если EXIF сохранился).
6. **Комбинация** лицо+место+время → ищем аккаунты, активные в этом городе/времени.
7. **Верификация** через `osint-verification`: проверяем, что профиль действительно тот же человек.

Ключ — **итеративность**: результат одного поиска становится входом для следующего.

## Инструменты автоматизации

Ручной поиск по 6 движкам утомляет — его частично автоматизируют. Скрипты обращаются к API/эндпоинтам движков (где разрешено) и сводят результаты. Полезные обёртки и сервисы: **`google-reverse-image`** (неофициальные), **`SerpApi`** (платный, легальный доступ к Google Lens), **`Bing Visual Search API`**, **`TinEye API`** (коммерческий). Для батч-проверки больших коллекций фото используют конвейер: извлечь кропы → прогнать через API → собрать уникальные URL. Всегда соблюдайте ToS и лимиты: массовый скрапинг Google/PimEyes чреват блокировкой и юридическими рисками.

## Верификация результата поиска

Найденные совпадения — это гипотезы, а не факты. Проверяйте:

- **Точное совпадение vs похожее.** TinEye помечает точные; Google может показать «визуально похожее» (другой человек/место).
- **Дата оригинала.** Первое появление фото в сети — по TinEye (сортировка по дате).
- **Контекст.** Где фото опубликовано: оригинальный пост или репост/мем?
- **Метаданные.** Оригинал может сохранить EXIF, репост — нет.
- **Перекрёстная проверка.** Совпадение должно подтверждаться вторым независимым признаком (вывеска, событие, лицо).

Если фото — сток/референс (часто используется в мемах и фейках), это меняет вывод: возможно, человек на фото не связан с целью. Всегда отделяйте «источник изображения» от «личности».

## Кратко: рабочий порядок действий

Итоговый алгоритм: (1) проверьте EXIF; (2) полное фото — Google + TinEye; (3) кроп лица — Yandex/PimEyes; (4) кроп текста/логотипа — Google Lens; (5) flip + enhance при неудаче; (6) соберите оригинал и его дату; (7) комбинируйте с другими признаками; (8) верифицируйте. Такой порядок покрывает большинство задач.
