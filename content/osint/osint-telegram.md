## Вопрос, с которого всё начинается

Многие считают Telegram закрытым мессенджером: мол, ничего не видно без аккаунта. Это миф. Публичные каналы Telegram **индексируются** и доступны даже без логина — а значит, их можно собирать теми же инструментами, что и веб.

Разберём, что можно вытащить из Telegram и как это делать законно, на примере одной компании.

## Наш пример: компания Example Corp

Возьмём домен `example.com` и бренд `Example Corp`. Задача — найти официальные каналы компании, обсуждения сотрудников и упоминания утечек. Пойдём от публичного веб-превью к комментариям и графу каналов.

## Шаг 1: читаем публичный канал без аккаунта

У каждого публичного канала есть веб-превью по адресу `t.me/s/<username>`. Оно отдаёт последние посты в HTML — без всякого аккаунта. Это и есть главный «лаз».

```bash
curl -s "https://t.me/s/examplecorp" | sed 's/<[^>]*>//g' | grep -v '^$' | head -20
```

```
Example Corp — официальный канал
Обновление сервиса запланировано на пятницу.
Вакансия: backend-разработчик, резюме на hr@example.com
```

Мы получили и официальную информацию, и **контакт** (`hr@example.com`) — уже зацепка. Если постов на экране мало, историю листают параметром `?before=<id>`:

```bash
curl -s "https://t.me/s/examplecorp?before=1000" | grep -oE 'tgme_widget_message_text[^<]*'
```

## Шаг 2: находим канал через поисковые операторы

Если username неизвестен, канал ищут через поисковики — у Telegram есть индексируемые страницы `t.me`.

```text
site:t.me "Example Corp"
site:t.me/s/ example
"t.me/+" example
```

Последний запрос ищет **инвайт-ссылки** — приглашения в приватные группы. Их часто публикуют в открытых постах и на сайтах, и они ведут туда, куда обычным поиском не попасть.

## Шаг 3: комментарии дают сотрудников

Под постами канала часто открыта **связанная группа обсуждения**. Там сидят сотрудники и клиенты, и их usernames видны.

```bash
curl -s "https://t.me/s/examplecorp" | grep -oE 't\.me/[A-Za-z0-9_]+' | sort -u
```

```
t.me/ivan_dev
t.me/alex_smirnov
t.me/examplecorp_chat
```

Появились usernames. Дальше их прогоняют по другим платформам — GitHub, VK, форумам — как мы делали в уроке про разрешение идентичностей. Один username — это кандидат, а не доказательство.

## Шаг 4: ищем утечки по домену

Telegram — популярная площадка для публикации «сливов». Ищем упоминания домена компании в тематических каналах утечек.

```text
site:t.me/s/ "example.com" password
site:t.me/s/ "example.com" database
site:t.me/s/ "example" "leak" OR "слив" OR "dump"
```

Важно: анонимным «сливам» нельзя верить без проверки — среди них много фейков и приманок. Свежие дампы сверяют с независимыми источниками (см. урок про утечки). Посты удаляют через часы, поэтому сразу сохраняй `t.me/s/`-снимок и, при необходимости, ссылку на Wayback.

## Шаг 5: строим граф каналов

Каналы ссылаются друг на друга. Собрав все `t.me`-ссылки из постов, получаем граф: кто кого перепощивает.

```bash
curl -s "https://t.me/s/example_channel" \
  | grep -oE 't\.me/[A-Za-z0-9_]+' | sort | uniq -c | sort -rn | head
```

```
  12 t.me/example_news
   7 t.me/examplecorp
   3 t.me/example_jobs
```

Частые взаимные перепосты означают, что каналы связаны — часто их держит один оператор под разные темы. Это помогает атрибутировать источник утечки.

## Шаг 6: атрибуция аккаунта

Найденный username — ещё не личность. Строим атрибуцию на **пересечении независимых признаков**: дата создания аккаунта и история смены имён (бот `@SangMata_bot`), стиль и язык постов, ссылки на внешние профили с тем же ником, аватар.

```
username ivan_dev (Telegram)
  + тот же ник на GitHub
  + email из утечки
  → три независимых мостика → уверенная атрибуция
```

Одного совпадения ника недостаточно — и уровень уверенности указывается явно.

## Мониторинг каналов утечек

Каналы утечек публикуют дампы постоянно, поэтому для bug bounty и threat intel полезно держать «радар» по ключевым словам:

```text
site:t.me/s/ "example.com"
site:t.me/s/ "example.com" "2025"
site:t.me/s/ "example" "leak" OR "слив" OR "dump"
```

Заведи список каналов-источников и раз в несколько дней прогоняй по ним `grep` на домен компании, сохраняя совпадения с датой. Многие посты удаляют через часы, поэтому фиксируй `t.me/s/`-снимок и, если нужно, ссылку на Wayback.

## Библиотеки для сбора и ограничения

Для программного доступа есть два подхода. **Без аккаунта** — парсинг `t.me/s/` через `curl`, `requests` и BeautifulSoup: пассивно, но только последние посты. **С аккаунтом** — Telethon или pyrogram: полная история и участники, но это уже активность под твоим аккаунтом.

```python
import requests
from bs4 import BeautifulSoup
html = requests.get("https://t.me/s/example_channel").text
soup = BeautifulSoup(html, "html.parser")
for m in soup.select(".tgme_widget_message_text"):
    print(m.get_text(" ", strip=True)[:200])
```

Ограничения: rate-limit при частых запросах, изменчивая разметка, удаление старых постов. Держи темп низким, а если переходишь к Telethon — только с отдельного sock-puppet аккаунта.

## Связка Telegram с утечками и людьми

Telegram — мост между номером телефона и личностью. Вот типовой маршрут:

```text
номер → Telegram (наличие аккаунта, username)
username → другие соцсети
username → утечки → email → компания
канал утечек → домен компании → свежие дампы
```

Практически это выглядит так: находишь официальный канал компании → читаешь комментарии → вытаскиваешь usernames сотрудников → ищешь эти usernames в GitHub и утечках → получаешь email → продолжаешь OSINT. Каждый шаг опирается на предыдущий, а не висит сам по себе.

## Верификация и атрибуция аккаунтов

Найденный username — ещё не личность. Строя атрибуцию, опирайся на пересечение независимых признаков: дату создания и историю смены имён (бот `@SangMata_bot`), стиль и язык постов, ссылки на внешние профили с тем же ником, аватар через обратный поиск. Совпадение ника в Telegram и GitHub плюс одинаковый email из утечки — это уже три независимых мостика. Одного совпадения недостаточно, и уровень уверенности («высокая», «средняя», «низкая») указывается явно.

## Что мы теперь знаем

По-простому:

1. Публичные каналы Telegram читаются без аккаунта через `t.me/s/`.
2. `?before=<id>` листает историю постов назад.
3. Комментарии под постами дают usernames сотрудников.
4. Каналы утечек ищутся по домену, но требуют проверки.
5. Граф перепостов показывает связанные каналы одного оператора.

## На что смотреть дальше

- **Не считай Telegram закрытым.** Публичные каналы индексируются.
- **Не верь анонимным «сливам».** Много фейков и приманок.
- **Не забывай про боты.** Часть метаданных доступна только через них.
- **Не парсь со своего аккаунта.** Только отдельный sock-puppet — иначе деанон и бан.
- **Фиксируй дату снятия.** Посты удаляются, без метки доказательство теряет силу.

## Разбор кейса: канал как источник

Telegram — это и мессенджер, и медиаплатформа. Публичные каналы доступны без входа через веб-версию (`t.me/<channel>`), и это делает их ценным источником. Разберём.

Первый шаг — **найти канал**. По названию компании, домену или теме ищи в поиске Telegram и в Google по `site:t.me`. Публичные каналы индексируются. Второй шаг — **прочитать без аккаунта**. Веб-версия `t.me/s/<channel>` отдаёт ленту постов. Через неё можно собрать историю сообщений, даты, ссылки, медиа.

Третий шаг — **извлечь структуру**. В постах часто есть упоминания людей (`@username`), ссылки на документы, контакты. Чаты (группы) — отдельный источник: в них обсуждают рабочие вопросы, делятся файлами. Некоторые группы открыты для чтения.

Четвёртый шаг — **мониторинг**. Telegram-каналы часто первыми публикуют утечки, вакансии, новости. Подписка на ключевые слова через ботов позволяет отслеживать упоминания цели. Важно: боты и автоматизация должны соблюдать лимиты Telegram, иначе аккаунт заблокируют.

## Если не сработало

**Канал приватный.** Закрытые каналы недоступны без приглашения. Не пытайся обходить — это нарушение.

**Поиск пуст.** Используй внешние каталоги каналов (tgstat, telemetr) для поиска по темам.

**Веб-версия не отдаёт историю.** Некоторые каналы ограничивают глубину. Собирай постепенно.

**Много шума.** Каналы публикуют много нерелевантного. Фильтруй по ключевым словам.

## Частые вопросы

**Законно ли читать публичные каналы?** Да, это публичные данные. Но использование найденных персональных данных — отдельная граница.

**Что такое tgstat?** Аналитический сервис по Telegram-каналам: статистика, поиск, рейтинги. Полезен для картирования медиа.

**Как связать канал с организацией?** По ссылкам на сайт, упоминаниям сотрудников, реквизитам в постах.

## Мини-практика: собираем ленту

Возьми публичный канал по теме цели и собери посты за месяц через `t.me/s/<channel>`. Выпиши упоминания домена, имена, ссылки. Сложи в таблицу «дата, содержание, источник». Так ты получишь таймлайн событий, который может дополнить картину из других источников.

## Вопросы и ответы

**Как читать публичный канал без аккаунта?** Веб-версия `t.me/s/<channel>` отдаёт ленту постов с датами, ссылками и медиа. Это позволяет собрать историю канала, не входя в Telegram и не создавая аккаунт.

**Что искать в постах канала?** Упоминания домена, имена сотрудников, ссылки на документы, реквизиты и контакты. Часто канал публикует то, чего нет на сайте, — вакансии, анонсы, внутренние детали.

**Чем группы отличаются от каналов?** В каналах пишет только владелец, в группах общаются все участники. Открытые группы дают обсуждения, вопросы и ответы, из которых видно окружение и рабочие темы.

**Как найти канал по теме?** Через внешние каталоги (tgstat, telemetr) и поиск в Google по `site:t.me`. Встроенный поиск Telegram ограничен, поэтому каталоги дают более широкий охват.

**Как организовать мониторинг?** Подписка на ключевые слова через ботов и регулярный прогон поиска. Утечки и анонсы появляются в каналах раньше, чем в новостях, поэтому поток важнее разового сбора.

**Где этическая граница?** Публичные каналы — открытые данные, но персональные сведения из них требуют основания. Не обходи приватность закрытых чатов и не используй найденное во вред людям.
