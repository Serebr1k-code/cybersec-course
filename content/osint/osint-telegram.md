Telegram — крупнейший в русскоязычном пространстве источник открытых данных: каналы утечек, чаты компаний, комментарии, боты. В отличие от закрытых мессенджеров, публичные каналы и группы индексируются и доступны. В этом уроке — методика сбора с учётом специфики RU-контекста.

## Теория: структура и что искать

- **Публичные каналы:** вещание, часто тематические (утечки, вакансии, новости). Username `@channel`, веб-превью `t.me/s/<channel>`.
- **Публичные группы:** обсуждения; комментарии к постам каналов тоже видны.
- **Боты:** сервисы проверки (номер, username, утечки) — `@bot`.
- **Приватные чаты:** закрыты, но инвайт-ссылки (`t.me/+hash`) утекают в постах/поиске.
- **Профили:** username, bio, аватар; номер телефона скрыт, но иногда в bio.
- **История:** многие каналы имеют «предпросмотр» без логина через `t.me/s/`.

Ключевое: веб-версия `t.me/s/` даёт доступ к публичным каналам без аккаунта, а значит её можно парсить сетевыми инструментами.

## Инструменты и команды

Публичный предпросмотр канала (без логина):

```bash
curl -s "https://t.me/s/example_channel" | grep -oE 'message[^"]*' | head
# текст постов
curl -s "https://t.me/s/example_channel" | sed 's/<[^>]*>//g' | grep -v '^$' | head -50
```

Поиск каналов через поисковики:

```text
site:t.me "example"
site:t.me/s/ "example"
"t.me/+" example
```

Поиск по username/номеру — через ботов (в приложении):

- `@username_bot` / `@userinfobot` — информация о username/ID.
- `@tgstat` — статистика каналов.
- Сервисы: **tgstat.ru**, **telemetr.me** — аналитика публичных каналов.

Экспорт публичного канала:

```bash
curl -s "https://t.me/s/example_channel?before=1000" | grep -oE 'tgme_widget_message_text[^<]*'
```

Параметр `?before=<id>` отдаёт посты до указанного ID — так листают историю назад без API.

## Парсинг публичных каналов без аккаунта

Веб-превью `t.me/s/` отдаёт последние посты в HTML. Это позволяет собирать контент пассивно:

```bash
# текст постов (грубо, без учёта структуры)
curl -s "https://t.me/s/example_channel" \
  | sed 's/<[^>]*>//g' | sed '/^[[:space:]]*$/d' | head -80

# ссылки на другие каналы/сайты
curl -s "https://t.me/s/example_channel" | grep -oE 'https?://[^"< ]+' | sort -u | head
```

Для глубокого сбора используют **Telethon**/**pyrogram** с отдельным аккаунтом — но это уже заметная активность и требует осторожности и авторизации:

```python
from telethon.sync import TelegramClient
with TelegramClient('sess', api_id, api_hash) as c:
    for m in c.iter_messages('example_channel', limit=200):
        if m.message:
            print(m.id, m.date, m.message[:120])
```

## Боты-OSINT и каталоги

- **@userinfobot**, **@username_bot** — информация об ID/username.
- **@tgstat_bot**, **tgstat.ru**, **telemetr.me** — статистика каналов, охваты, динамика.
- **@SangMata_bot** — история смены имён пользователя (полезно для атрибуции).
- **@creationdatebot** — дата создания аккаунта.
- Каталоги: **telemetr**, **tgstat**, **tlgrm**.

Боты дают метаданные, которые не видны в веб-превью: даты, историю, связи.

## Разобранный пример: находим компанию и утечки

Дано: компания `Example Corp`.

Шаг 1 — ищем официальные каналы/чаты:

```text
site:t.me "Example Corp"
site:t.me/s/ example
```

Шаг 2 — проверяем публичный предпросмотр:

```bash
curl -s "https://t.me/s/examplecorp" | sed 's/<[^>]*>//g' | head -40
```

Шаг 3 — ищем утечки и упоминания компании в каналах утечек:

```text
site:t.me/s/ "example.com" password
site:t.me/s/ "example.com" database
```

Шаг 4 — комментарии к постам раскрывают сотрудников и их usernames.

Шаг 5 — по username сотрудника ищем в других сетях и в утечках (см. osint-breach-data, osint-username-enum).

Шаг 6 — фиксируем: официальные каналы, чаты сотрудников, найденные утечки.

## Продвинутые приёмы

- **t.me/s/ без логина:** основной лаз без аккаунта.
- **Инвайт-ссылки:** `t.me/+...` в постах и на сайтах → приватные группы.
- **Боты-OSINT:** проверка номера/username, поиск по утечкам (в рамках закона).
- **Архивы:** Wayback сохраняет старые посты каналов (`web.archive.org/web/*/t.me/s/*`).
- **Комментарии:** linked discussion group под постом часто открыт.
- **Связка с утечками:** номер телефона → Telegram → другие сервисы.
- **Ключевые слова в каталогах:** tgstat умеет искать по постам каналов (`tgstat.ru/search`), это быстрее ручного `site:`.

## Связка Telegram с утечками и людьми

Telegram — мост между номером телефона и личностью:

```
номер → Telegram (наличие аккаунта, username)
username → другие соцсети (см. osint-username-enum)
username → утечки → email → компания
канал утечек → домен компании → свежие дампы
```

Практический маршрут: находите официальный канал компании → комментарии → usernames сотрудников → поиск этих usernames в GitHub/утечках → email → дальнейший OSINT.

## Инструменты и флаги

| Инструмент | Что делает |
|---|---|
| `t.me/s/<channel>` | публичный веб-превью без логина |
| `?before=<id>` | пагинация истории постов |
| tgstat.ru | поиск по каналам и постам, статистика |
| telemetr.me | аналитика каналов, рейтинги |
| Telethon / pyrogram | программный сбор (активность!) |
| @userinfobot, @SangMata_bot | метаданные аккаунтов |

## Частые ошибки

- **Считать Telegram закрытым.** Публичные каналы индексируются.
- **Игнорировать t.me/s/.** Самый простой способ без аккаунта.
- **Верить анонимным «сливам».** Много фейков и приманок.
- **Нарушать закон.** Сбор ПДн и доступ к чужим чатам недопустимы.
- **Пропускать комментарии.** Там сотрудники и контакты.
- **Забыть про боты.** Часть проверок доступна только через ботов.
- **Использовать личный аккаунт для парсинга.** Риск бана и деанона — только отдельный sock puppet.

## Что делать дальше / решение

- **Нужен официальный канал** → `site:t.me` + tgstat по бренду.
- **Нужны утечки компании** → `site:t.me/s/ "<domain>"` + каналы утечек, сверить с HIBP (`osint-breach-data`).
- **Нужны сотрудники** → комментарии канала → usernames → `osint-username-enum`.
- **Нужен глубокий сбор** → Telethon с отдельного аккаунта, только в рамках scope.

## Граф каналов и перекрёстные ссылки

Каналы ссылаются друг на друга и на сайты. Собрав все `t.me`-ссылки из постов канала, вы строите граф: кто перепощивает кого, какие каналы образуют «семью» одного оператора. Регулярка для быстрого подсчёта:

```bash
curl -s "https://t.me/s/example_channel" \
  | grep -oE 't\.me/[A-Za-z0-9_]+' | sort | uniq -c | sort -rn | head
```

Частые взаимные перепосты = связанные аккаунты; один оператор часто держит сеть каналов под разные темы. Это помогает атрибутировать источник утечки.

## OPSEC и правовые границы

Читать публичные каналы — законно; вступать в приватные, покупать «сливы» и деанонимизировать людей — нет. Работайте с отдельного sock-puppet аккаунта без личных данных, не вступайте в группы от своего имени, фиксируйте только публичные артефакты. В отчёте указывайте источник и дату: посты удаляются, и без метки «снято тогда-то» доказательство теряет силу.

## Мониторинг каналов утечек

Каналы утечек публикуют дампы постоянно; для bug bounty и threat intel полезно держать «радар» по ключевым словам:

```
site:t.me/s/ "example.com"
site:t.me/s/ "example.com" "2025"
site:t.me/s/ "example" "leak" OR "слив" OR "dump"
```

Практика: заведите список каналов-источников, раз в несколько дней прогоняйте по ним `grep` на домен компании и сохраняйте совпадения с датой. Многие посты удаляют через часы, поэтому фиксируйте `t.me/s/`-снимок и, если нужно, ссылку на Wayback.

## Библиотеки для сбора и ограничения

Для программного доступа есть два подхода:

- **Без аккаунта** — парсинг `t.me/s/` через `curl`/`requests`/`BeautifulSoup`; пассивно, но только последние посты.
- **С аккаунтом** — Telethon/pyrogram: полная история, участники, но это активность под вашим аккаунтом.

```python
import requests
from bs4 import BeautifulSoup
html = requests.get("https://t.me/s/example_channel").text
soup = BeautifulSoup(html, "html.parser")
for m in soup.select(".tgme_widget_message_text"):
    print(m.get_text(" ", strip=True)[:200])
```

Ограничения: rate-limit при частых запросах, изменчивая разметка, удаление старых постов. Держите темп низким и используйте отдельный sock-puppet, если переходите к Telethon.

## Верификация и атрибуция аккаунтов

Найденный username — ещё не личность. Строя атрибуцию, опирайтесь на **пересечение независимых признаков**:

- **Дата создания и история имён** (`@SangMata_bot`, `@creationdatebot`).
- **Стиль и язык постов**, часовой пояс по времени публикаций.
- **Ссылки на внешние профили** (GitHub, VK, сайт) с тем же ником.
- **Аватар** → обратный поиск изображения (`osint-image-reverse`).
- **Перепосты и связи каналов** — кто ещё ссылается на этот аккаунт.

Совпадение ника в Telegram и GitHub, плюс одинаковый email из утечки — это уже три независимых мостика; одного совпадения недостаточно. Явно помечайте уровень уверенности: «высокая/средняя/низкая».

## Как читать аналитику tgstat/telemetr

Сервисы аналитики дают метаданные, которых нет в веб-превью:

- **Охват (ERR)** — сколько людей реально видят пост; по нему видно «живость» канала.
- **Динамика подписчиков** — резкий рост часто означает рекламу или вброс.
- **Дата создания и язык** — помогают атрибуции.
- **Похожие каналы** — граф перепостов, выявляющий одну «семью».

```text
tgstat.ru/search?q=example.com      # поиск по постам каналов
telemetr.me/channels/<username>     # статистика конкретного канала
```

Осторожно: метрики можно накрутить. Используйте их как ориентир, а не как факт.

## Типичные CTF-сценарии

В CTF Telegram обычно фигурирует так: в подсказке дан ник или номер — нужно найти канал/аккаунт и вытащить флаг из поста. Рецепт: `site:t.me "<ник>"` → `t.me/s/<channel>` → `grep -i flag` по тексту превью. Если канал закрыт, ищите упоминания в других каналах или Wayback-снимок `t.me/s/`. Флаг часто прячут в старом посте, поэтому листайте историю через `?before=<id>`, а не только первый экран.

## Где пригодится

- **CTF (OSINT):** найти флаг в публичном канале или связке username.
- **Threat intel:** мониторинг каналов утечек и угроз.
- **Bug bounty:** поиск утечек компании в открытых каналах.
- **Blue team:** раннее обнаружение публикации внутренних данных.
