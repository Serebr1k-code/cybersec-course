Instagram — визуальный источник: здесь люди показывают офисы, форму, бейджи, экраны и поездки. API закрыт, но публичные страницы, геотеги и веб-версия дают многое. В этом уроке — практическая методика сбора данных об организации и людях, с уважением к приватности и ToS.

## Теория: что и где лежит

- **Профиль:** username, имя, био, ссылка, аватар, счётчики, дата регистрации (косвенно).
- **Посты:** фото/видео, подпись, хэштеги, отметки людей, геотег.
- **Геотеги:** страница локации показывает посты всех, кто там отметился.
- **Сторис:** исчезают через 24 ч, но могут быть сохранены в Highlights или закэшированы.
- **Отметки:** `@username` в чужих постах связывает людей и места.
- **Reels и Tagged:** вкладка Tagged показывает упоминания без подписки.

Ключевое: даже приватный профиль виден через аватар, счётчики и упоминания; а публичные геотеги раскрывают офис и график.

## Инструменты и команды

Прямые публичные страницы (без логина видно ограниченно, но достаточно):

```bash
# публичный профиль через web (может требовать логина)
curl -s -A "Mozilla/5.0" "https://www.instagram.com/example_company/" | head
```

Специализированные OSINT-инструменты:

- **Osintgram** — сбор профиля, подписчиков, геолокаций (требует аккаунта).
- **instaloader** — скачивание публичных профилей и метаданных:

```bash
pip install instaloader
instaloader --no-videos --no-pictures example_company
# только метаданные профиля
instaloader --no-videos --no-pictures --metadata-only example_company
```

Поиск по геотегу (через веб-URL):

```text
https://www.instagram.com/explore/locations/<location_id>/
```

Поиск по хэштегу:

```text
https://www.instagram.com/explore/tags/examplecompany/
```

## Разобранный пример: офис по геотегу

Дано: компания `Example Corp`.

Шаг 1 — находим официальный профиль через поисковик:

```text
site:instagram.com "Example Corp"
```

Шаг 2 — открываем вкладку Tagged и Highlights: там сотрудники отмечают офис.

Шаг 3 — ищем геотег офиса. В посте с отметкой локации кликаем локацию → `explore/locations/<id>`. На странице — все посты с этой локации, включая других сотрудников.

Шаг 4 — по фото читаем детали: вывеска, номер этажа, экраны с внутренними URL, бейджи, форма. Это карта инфраструктуры (см. osint-geolocation).

Шаг 5 — строим граф: аккаунт → имя → другие соцсети → email-паттерн (см. osint-social-media).

Шаг 6 — проверяем, не остались ли метаданные в скачанных фото:

```bash
exiftool photo.jpg | grep -iE "gps|date|camera"
```

## Продвинутые приёмы

- **Сторис-архив:** Highlights хранят сторис бессрочно; `instaloader --highlights` их тянет.
- **Кросс-корреляция:** аватар через reverse image (см. osint-image-reverse) связывает аккаунты.
- **Временные окна:** сторис «из отпуска» показывают, когда офис пуст.
- **Комментарии:** под постами компании — жалобы клиентов и контакты сотрудников.
- **Партнёрские аккаунты:** подрядчики и партнёры в отметках расширяют поверхность.
- **Web archive:** удалённые посты иногда сохраняются в Wayback.

## Частые ошибки

- **Скрейпинг с основного аккаунта.** Instagram быстро банит; используйте изолированный аккаунт/инструмент.
- **Нарушение ToS и закона.** Сбор ПДн должен быть ограничен целью и авторизацией.
- **Вера в один пост.** Локация может быть указана неверно или быть «популярным» местом.
- **Игнорирование Highlights.** Там остаются исчезнувшие сторис.
- **Забыть про метаданные.** EXIF в исходных фото часто содержит GPS.
- **Путать приватный профиль с недоступным.** Аватар и отметки всё равно утекают.

## Хэштеги, локации и кросс-корреляция

Instagram — это сеть «по местам и темам». Систематизируйте:

- **Хэштеги компании**: `#examplecorp`, `#exampleoffice`, `#<город>офис`.
- **Локации**: страницы `explore/locations/<id>` показывают все посты с метки.
- **Отметки людей**: `@username` в постах связывают сотрудников.
- **Кросс-постинг**: тот же контент в TikTok/Twitter → другие аккаунты (см. osint-social-tiktok).
- **Аватары**: reverse image связывает профили (см. osint-image-reverse).

```text
site:instagram.com "examplecorp"
site:instagram.com/explore/tags/examplecorp
```

## Временной анализ и сторис

- **Highlights** — постоянный архив сторис (бесценен, т.к. сторис «живут» 24 ч).
- **Даты постов** — график активности, периоды отпусков, запуски.
- **Сторис «из офиса»** — показывают, когда и где работают люди.
- **Reels** — часто дублируют TikTok-контент, но с другой аудиторией.

```bash
# скачать Highlights (требуется авторизованный аккаунт)
instaloader --highlights --no-videos --no-pictures example_company
```

## Инструменты и ограничения

- **instaloader** — профили, посты, Highlights, метаданные.
- **Osintgram** — подписчики, геолокации, комментарии (нужен аккаунт).
- **Браузерный режим** — публичные профили частично видны без логина.
- **Wayback** — удалённые посты иногда сохраняются.

Ограничения: жёсткий rate-limit, баны за скрейпинг, скрытие данных при приватности. Всегда используйте изолированный аккаунт и паузы.

## instaloader: полный набор флагов

`instaloader` — самый стабильный способ вытянуть публичный профиль и метаданные без ручного скрейпинга. Ключевые флаги:

```bash
# авторизация (для приватных/ограниченных запросов; используйте одноразовый аккаунт)
instaloader --login=osint_burner --sessionfile=sess.insta example_company

# только метаданные, без медиа
instaloader --no-pictures --no-videos --metadata-only --sessionfile=sess.insta example_company

# посты с метаданными в отдельные txt-файлы
instaloader --post-metadata-txt="{shortcode}|{date_utc}|{caption}|{location}" \
            --storyitem-metadata-txt="{date_utc}|{caption}" \
            --sessionfile=sess.insta example_company

# скачать все Highlights (вечные сторис)
instaloader --highlights --sessionfile=sess.insta example_company

# комментарии к постам (кто и что писал)
instaloader --comments --sessionfile=sess.insta example_company

# все посты по геотегу (нужен location id)
instaloader --geotag=213385402 --sessionfile=sess.insta
```

Плейсхолдеры `{date_utc}`, `{caption}`, `{location}`, `{owner_username}`, `{shortcode}` позволяют сразу строить таблицу для анализа. `--fast-update` докачивает только новое — удобно для периодического мониторинга.

## Osintgram: интерактивный сбор

`Osintgram` (Datalux) даёт меню-команды по чужому публичному профилю:

```bash
git clone https://github.com/Datalux/Osintgram && cd Osintgram
pip install -r requirements.txt
python3 main.py example_company
# внутри REPL:
# > info            — общая инфа профиля
# > followers       — список подписчиков
# > followings      — кого читает
# > addrs           — все локации из постов
# > photos          — URL всех фото
# > comments        — комментарии
# > tagged          — где отмечают
# > stalking        — профиль по ID
# > wcommented      — кто комментировал
# > wtagged         — кто отмечал
```

Осторожно: инструмент шумит и легко ловит бан; гоняйте через прокси (`--proxy`) и на изолированном аккаунте.

## Поиск location id и геотег-страницы

Геотег-страница (`/explore/locations/<id>/`) собирает посты **всех** пользователей с этой локации. Найти id:

```text
# Google dork по названию локации
site:instagram.com/explore/locations "Example Corp HQ"
# или открыть любой пост с геотегом и скопировать id из URL
```

Далее `instaloader --geotag=<id>` тянет все посты. Это раскрывает не только официальный аккаунт, но и личные профили сотрудников, отмечающихся на работе, — часто вместе с графиком (кто когда на месте).

## Методика графа: от аккаунта к человеку

Строим граф по шагам и фиксируем в таблице:

| Узел | Атрибут | Источник |
|------|---------|----------|
| Аккаунт | username, id, имя | профиль |
| Человек | ФИО, должность | био, LinkedIn (osint-social-media) |
| Локация | офис, город | геотег, сторис |
| Email | паттерн `f.last@corp` | корпоративный домен |
| Другие сети | тот же аватар/ник | reverse image, username-enum |

Связки усиливают друг друга: аватар из Instagram → reverse image → тот же ник в Twitter; геотег офиса → адрес → спутниковый снимок (osint-satellite).

## Сторис, Highlights и временной анализ

Сторис живут 24 часа, но:

- **Highlights** сохраняются бессрочно и часто содержат «вечнозелёные» подборки (офис, команда, события).
- **Архивы**: удалённые посты иногда остаются в Wayback Machine или в кэше Google.
- **Временной анализ**: серия сторис «из командировки» показывает, когда ключевой сотрудник отсутствует; посты «в 2 часа ночи из офиса» — про режим работы.

```bash
# скачать highlights и разобрать даты
instaloader --highlights --storyitem-metadata-txt="{date_utc}|{caption}" --sessionfile=sess.insta example_company
```

## Анти-скрейпинг: лимиты и обход

Instagram агрессивно режет автоматизацию:

- **429 / checkpoint_required** — запросы слишком частые. Снижайте скорость: `--sleep`, `--max-connection-attempts`.
- **Login challenge** — новый аккаунт сразу ловит проверку; «прогревайте» аккаунт, заходите вручную с того же IP.
- **IP-бан** — используйте резидентные прокси, ротацию, один аккаунт на IP.
- **Приватность**: даже закрытый профиль отдаёт аватар, счётчики и упоминания в чужих постах.

```bash
instaloader --sessionfile=sess.insta --sleep --max-connection-attempts=2 --request-timeout=30 example_company
```

## Правовые и этические границы

- Сбор **публичных** данных допустим, но массовый сбор ПДн (подписчики, локации) подпадает под GDPR/152-ФЗ — нужна законная цель и минимизация.
- Не логиньтесь в чужой аккаунт и не используйте социальную инженерию для доступа.
- Не публикуйте персональные данные; в отчёте (osint-reporting) агрегируйте и обезличивайте там, где это возможно.
- Соблюдайте ToS платформы: нарушение — риск бана аккаунта и юридических претензий.

## Итоговый чек-лист по Instagram

1. Официальный профиль → `instaloader --metadata-only`.
2. Tagged/Highlights → сотрудники и офис.
3. Геотег офиса → все посты локации.
4. Reverse image аватара → другие сети.
5. EXIF скачанных фото → GPS/камера/дата.
6. Wayback → удалённые посты.
7. Свести всё в граф, обезличить, оформить по osint-reporting.

## Где пригодится

- **CTF (OSINT):** найти локацию/флаг по геотегу или аватару.
- **Bug bounty:** профилирование организации для социальной инженерии в рамках scope.
- **Расследования:** установление места и времени событий по фото.
- **Blue team:** аудит того, что сотрудники публикуют об офисах и системах.
