Большие языковые модели (LLM) изменили OSINT-работу: они быстро суммируют объёмные тексты, переводят, извлекают сущности, пишут скрипты и генерируют гипотезы. Но у них есть фундаментальное свойство — **галлюцинации**: модель уверенно выдумывает факты. Поэтому в OSINT LLM — это **ускоритель обработки**, а не источник истины. Этот урок о том, где AI реально помогает, где вредит и как строить пайплайны с проверкой.

## Теория: где LLM сильны, где нет

| Задача | LLM помогает? | Почему |
|--------|---------------|--------|
| Суммаризация текста | да | языковая задача |
| Перевод | да | языковая задача |
| Извлечение сущностей (NER) | да (с проверкой) | паттерны |
| Генерация кода/скриптов | да | код — язык |
| Кластеризация текстов | да | эмбеддинги |
| **Установление фактов** | **нет** | галлюцинации |
| **Точные цифры/даты** | **нет** | выдумывает |
| **Атрибуция личности** | **нет** | риск ложного связывания |

Правило: **LLM обрабатывает, но не подтверждает.** Любой факт из модели проверяется по первичному источнику.

## Применение 1: суммаризация и перевод

Собрали 50 новостных статей о цели — LLM сжимает их в дайджест:

```bash
# пример: пайплайн через API (псевдокод)
cat articles.txt | llm "Выдели факты о компании: партнёры, руководство, даты, технологии. Без домыслов."
```

Перевод локальных СМИ (китайских, арабских) открывает источники, недоступные без языка. Но: **проверяйте имена и цифры** — модель может «поправить» транслитерацию.

## Применение 2: NER и извлечение сущностей

LLM вытаскивает из текста людей, организации, места, даты:

```python
prompt = """Из текста извлеки JSON: {"people":[], "orgs":[], "locations":[], "dates":[]}.
Только то, что есть в тексте, ничего не выдумывай.
Текст: <статья>"""
```

Для продакшена лучше классический NER (`spaCy`, `Stanza`) — он не галлюцинирует, но LLM гибче на сложных текстах. Комбинация: LLM для черновика, spaCy для валидации.

## Применение 3: генерация кода и пайплайнов

LLM пишет скрипты разведки:

```python
# запрос: "Напиши на Python скрипт: читает subdomains.txt, для каждого делает
# HTTP HEAD, сохраняет сервер и код ответа в CSV, с таймаутом 5с и 20 потоками"
```

Это ускоряет рутину. Но код нужно **ревьюить**: модель может оставить SSRF, утечку ключей, небезопасный `eval`.

## Применение 4: эмбеддинги и кластеризация

Эмбеддинги (векторные представления текста) позволяют:
- группировать похожие аккаунты (стилометрия);
- находить дубликаты контента;
- искать семантически близкие упоминания (не по ключевым словам).

```python
from sentence_transformers import SentenceTransformer
m = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
vecs = m.encode(posts)
# косинусная близость → кластеры
```

Это ML-часть AI-assisted OSINT: без галлюцинаций, чистая математика.

## Применение 5: генерация гипотез

LLM хорош как «второй мозг»: предлагает векторы, о которых вы не подумали.

```
«Дано: фото, GPS, ник. Предложи 15 гипотез, где может быть флаг, и инструменты для каждой.»
```

Модель выдаёт чек-лист — вы его исполняете. Гипотезы валидируются, а не принимаются.

## Риски и ограничения

- **Галлюцинации.** Модель выдумывает URL, имена, CVE. Всегда проверяйте.
- **Устаревшие знания.** Дата обучения модели ≠ сегодня; свежие данные — из источников.
- **Утечка данных.** Не отправляйте в облачные LLM чувствительные PII/секреты; используйте локальные модели.
- **Предвзятость.** Модель может усиливать стереотипы при атрибуции.
- **Ложная уверенность.** Уверенный тон ≠ правильность.
- **Юридические риски.** Автодеанон через AI — те же правовые рамки.

## Разобранный пример: пайплайн обработки расследования

Дано: 200 новостных статей + 50 постов о цели.

Шаг 1 — извлечение сущностей (LLM + spaCy):

```bash
# LLM-черновик → валидация spaCy
python extract.py --input corpus/ --model llm --validate spacy
```

Шаг 2 — кластеризация эмбеддингами: находим 3 темы (продукт, руководство, инциденты).

Шаг 3 — суммаризация каждой темы.

Шаг 4 — **проверка** ключевых фактов по первичным источникам (реестры, SEC).

Шаг 5 — сборка графа: люди-организации-события.

Итог: AI сжал 250 документов до структурированного дайджеста, но каждый факт проверен вручную.

## Ошибки и подводные камни

- **Принимать вывод LLM за факт.** Главная ошибка. Всё проверяем.
- **Сливать PII в облако.** Используйте локальные модели для чувствительного.
- **Не ревьюить сгенерированный код.** Уязвимости и утечки ключей.
- **Доверять переводу имён.** Модель может исказить транслитерацию.
- **Игнорировать дату обучения.** Свежие события модель не знает.
- **Считать эмбеддинги истиной.** Это мера близости, не атрибуция.

## Что дальше / решение

AI ускоряет обработку, но не заменяет верификацию. Дальше: **картирование поверхности атаки** (`osint-attack-surface`) для сведения результатов, **верификация** (`osint-verification`) для проверки выводов, **отчётность** (`osint-reporting`). Итог: используйте LLM как черновик и ускоритель, а подтверждение оставляйте первичным источникам.

## Локальный LLM: приватный пайплайн

Для чувствительных данных используйте локальную модель. `Ollama` запускает модели без отправки в облако:

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.1:8b
ollama run llama3.1:8b "Суммаризируй текст и выдели сущности: <текст>"
```

API-запрос из скрипта:

```python
import requests
r = requests.post("http://localhost:11434/api/generate", json={
    "model": "llama3.1:8b",
    "prompt": "Извлеки людей, организации и места из текста: " + text,
    "stream": False,
})
print(r.json()["response"])
```

Плюсы: данные не уходят наружу; минусы: качество ниже топовых облачных моделей.

## Промптинг для OSINT: правила

Хороший промпт для разведки:
- **Роль:** «Ты — OSINT-аналитик».
- **Ограничение:** «Используй ТОЛЬКО текст ниже, не выдумывай».
- **Формат:** «Верни JSON со схемой ...».
- **Валидация:** «Если данных нет — верни null, не додумывай».

Пример:

```
Ты — OSINT-аналитик. Используй ТОЛЬКО предоставленный текст.
Извлеки сущности в JSON: {"people":[],"orgs":[],"locations":[],"dates":[],"urls":[]}.
Если чего-то нет — оставь пустым. Не выдумывай ничего.
Текст: <...>
```

Такой промпт резко снижает галлюцинации, но не устраняет их полностью.

## Валидация вывода: обязательный шаг

Каждый факт из LLM проверяется программно или по источнику:

```python
import json, requests
data = json.loads(llm_output)
for url in data["urls"]:
    r = requests.head(url, timeout=5, allow_redirects=True)
    print(url, r.status_code)   # 200 = существует, 404 = выдуман
```

Проверка URL на существование ловит большинство выдуманных ссылок. Имена/даты сверяйте с первичными источниками.

## RAG: ответы по вашим документам

Retrieval-Augmented Generation (RAG) — подключение LLM к вашей базе документов. Вместо «знаний модели» ответ строится по найденным фрагментам:

```
1. Индексируем документы (эмбеддинги в векторную БД: Chroma, Qdrant).
2. Запрос → ищем ближайшие фрагменты.
3. LLM отвечает, опираясь на эти фрагменты + цитаты.
```

Это снижает галлюцинации: модель цитирует ваши данные, а не «вспоминает». Для OSINT RAG идеален: вся база находок становится «умной».

## OCR и работа с изображениями

LLM с vision-возможностями распознаёт текст на изображениях (вывески, скриншоты, документы). Локально — Tesseract:

```bash
tesseract screenshot.png - -l rus+eng
# или через EasyOCR
python3 -c "import easyocr; print(easyocr.Reader(['ru','en']).readtext('img.png'))"
```

Комбинация OCR + LLM: OCR извлекает текст, LLM структурирует. Для геолокации OCR вывесок критичен.

## Мультимодальные модели для OSINT

Vision-LLM помогают:
- описать фото (объекты, вывески, марки авто);
- сравнить два изображения (одно ли место);
- перевести текст на фото;
- определить тип местности.

Но: модель может «додумать» детали. Используйте её как **второе мнение**, а не как факт.

## Оценка качества вывода

Метрики доверия к выводу LLM:
- **Проверяемость:** можно ли подтвердить факт источником?
- **Согласованность:** не противоречит ли другим данным?
- **Специфичность:** конкретика или общие слова?
- **Источник:** есть ли ссылка/цитата?

Вывод без источника — гипотеза. Требуйте цитаты (RAG) и проверяйте.

## Автоматизация пайплайна с LLM

Типовой пайплайн обработки расследования:

```python
# pipeline: сбор → NER → кластеризация → суммаризация → проверка
docs = load_corpus("corpus/")            # RSS/статьи/посты
ents = extract_entities(docs, model="llm")  # люди, орг, места
clusters = cluster_embeddings(docs)      # темы
summary = summarize(clusters, model="llm")
for fact in summary.facts:
    assert verify(fact, sources)          # обязательная проверка
save_graph(ents, "graph.json")
```

Ключевой элемент — `verify`: ни один факт не идёт в отчёт без подтверждения источником. Так LLM ускоряет рутину, не компрометируя достоверность.

## Где пригодится

- **CTF (OSINT):** быстрый разбор больших текстов/переводов под дедлайн.
- **Расследования:** обработка больших корпусов документов.
- **Threat intelligence:** кластеризация отчётов и извлечение IOC.
- **Автоматизация:** генерация скриптов разведки.
- **Медиамониторинг:** суммаризация потока новостей.
