Утечки и «сливы» часто появляются не в базах, а в **полуоткрытых** местах: Pastebin, Telegram-каналы, форумы, Discord. Там данные свежие, и именно поэтому мониторинг таких площадок — ключевой навык: организация узнаёт о сливе не через год из отчёта, а в день публикации. В уроке — как искать данные на пастбинах и в мессенджерах, как организовать мониторинг и сохранить доказательства.

## Почему пастбины и мессенджеры важны

- **Свежесть.** Слив появляется на пасте или в Telegram раньше, чем в агрегаторах утечек.
- **Полуоткрытость.** Часть контента доступна без аккаунта — низкий порог входа.
- **Разнообразие.** Конфиги, ключи, БД, переписки, списки целей — всё это живёт здесь.
- **Анонимность источника.** Публикация без регистрации усложняет атрибуцию.
- **Скорость удаления.** Пасты и сообщения исчезают — окно наблюдения узкое.

## Paste-сайты: типы и поиск

Сервисы вроде Pastebin, Ghostbin, Hastebin, Dpaste, ControlC, Rentry позволяют опубликовать текст без аккаунта. Их используют для:

- сливов БД и конфигов;
- ключей и токенов;
- списков целей и переписок;
- малвари и скриптов.

## Google dorks для пастов

```
site:pastebin.com "example.com"
site:pastebin.com "password"
site:pastebin.com "AKIA"
site:pastebin.com "BEGIN PRIVATE KEY"
site:rentry.co "example.com"
site:controlc.com "db_pass"
```

Dorks ищут по проиндексированным пастам, но не по свежим. Для свежих нужен поток (см. инструменты).

## Инструменты: PasteHunter, psbdmp, API

- **PasteHunter** — сканирует поток новых пастов по regex-правилам и присылает уведомления (Slack/Telegram).
- **psbdmp** (`psbdmp.ws`) — поиск по архиву дампов Pastebin.
- **Pastebin API** (`https://pastebin.com/api`) — программный доступ к своим пастам и trending.

```bash
# psbdmp: поиск по архиву
curl -s "https://psbdmp.ws/api/v3/search/example.com" | jq -r '.data[]?.id' | head

# Pastebin API: список trending (нужен dev-key)
curl -s -X POST https://pastebin.com/api/api_post.php \
  -d "api_dev_key=$PB_KEY&api_option=trends" | head
```

## Telegram: особенности и приёмы

Telegram — де-факто основная площадка сливов.

- Каналы и чаты индексируются частично; есть **веб-версия** `t.me/s/<channel>` (публичный предпросмотр последних сообщений без входа).
- Поиск по поисковикам и каталогам каналов (tgstat, telemetr).
- Встроенный поиск Telegram — по сообщениям, но ограничен.
- Боты-агрегаторы и API (`Telethon`, `pyrogram`) автоматизируют сбор.

```bash
# публичный предпросмотр канала без логина
curl -s "https://t.me/s/example_channel" | sed 's/<[^>]*>//g' | grep -v '^$' | head -40

# ссылки из постов
curl -s "https://t.me/s/example_channel" | grep -oE 'https?://[^"< ]+' | sort -u | head
```

- **Инвайт-ссылки** `t.me/+hash` ведут в приватные группы.
- **tgstat/telemetr** дают статистику и поиск по каналам.
- **Боты** (@userinfobot, @SangMata_bot) раскрывают метаданные аккаунтов.
- **Комментарии** к постам — контакты и usernames.

## Discord, форумы, IRC

- **Discord** — публичные серверы индексируются слабо; ищите через приглашения (`discord.gg/...`), dorks и каталоги (disboard).
- **Форумы** (XSS.is, Exploit, зеркала RaidForums) — обсуждения и сливы; доступ часто по регистрации/инвайту.
- **IRC** — старые каналы, всё ещё живые для части сообществ; логи публикуются на paste-сайтах.

## Организация мониторинга

1. Определите **ключевые слова**: домен, бренд, email-паттерны, имена, номера.
2. Настройте **правила** (regex) в PasteHunter или собственном скрипте.
3. Подключите **уведомления** (Telegram-бот, email, Slack).
4. Ведите **журнал** находок: дата, источник, что найдено, ссылка (сохраните копию).
5. Оценивайте достоверность по Admiralty (источник × информация).

## Автоматизация

```bash
# psbdmp: проверка ключевых слов в архиве паст
for kw in example.com "@example.ru"; do
  enc=$(python3 -c "import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1]))" "$kw")
  echo "== $kw"
  curl -s "https://psbdmp.ws/api/v3/search/$enc" | jq -r '.data[]?.id' | head
done
```

PasteHunter сканирует поток пастов по regex и шлёт уведомления. Для Telegram — боты-агрегаторы и подписка на каналы утечек.

## Сохранение доказательств

```bash
# сохранить текст и зафиксировать хэш + время
curl -s "https://pastebin.com/raw/<id>" -o paste.txt
sha256sum paste.txt | tee paste.sha256
date -u | tee collected_at.txt
```

Пасты и сообщения исчезают — без копии доказательство теряется. Дополнительно архивируйте в Wayback (`web.archive.org/save/<url>`).

## Разобранный пример

Задача: узнать, сливали ли данные `example.com`.

1. Google: `site:pastebin.com "example.com"` → паст с конфигом.
2. `site:t.me "example.com"` → Telegram-канал с упоминанием.
3. PasteHunter с правилом `example\.com` ловит новые пасты в реальном времени.
4. Сохраняем копии, фиксируем источники, оцениваем достоверность.
5. В отчёте — только подтверждённое, с ссылками и датами.

## Этика и правовые границы

- Доступ к публичным пастам легален; взлом закрытых каналов — нет.
- Не скачивайте и не запускайте содержимое пастов (малварь).
- Персональные данные из сливов обрабатывайте в рамках закона.
- Не публикуйте чужие данные; в отчёте — минимально необходимое.

## Частые ошибки

- **Не сохранять копию** — паст удалён, доказательство потеряно.
- **Скачивать и запускать содержимое пастов** — риск заражения.
- **Верить сливу без перекрёстной проверки** — много фейков и «накруток».
- **Нарушать правила площадки/закон** при доступе к закрытым каналам.
- **Игнорировать Telegram** — там публикуют первым, часто раньше баз утечек.
- **Мониторить вручную раз в год** — окно наблюдения слишком узкое.

## Что дальше / решение

Настроив мониторинг, свяжите находки с инфраструктурой: утёкшие ключи проверьте на валидность (в рамках scope), домены — на CT/WHOIS, креды — на вход без блокировок. Решение по находке: «шум/устаревшее», «утёкший ключ — эскалировать на ротацию», «БД с PII — инцидент». Всегда храните цепочку доказательств (скриншот, хэш, время, ссылка).

## Telegram: продвинутый сбор

- **Публичный предпросмотр** `t.me/s/<channel>` отдаёт последние сообщения без авторизации — базовый инструмент.
- **Telethon/pyrogram** позволяют подписаться на каналы и собирать историю (нужен аккаунт).
- **tgstat/telemetr** — каталоги с поиском по ключевым словам и статистикой.
- **Боты-индексаторы** ускоряют discovery новых каналов.
- **Инвайт-ссылки** `t.me/+hash` — вход в приватные группы; их часто постят на форумах.

```python
# Telethon: собрать историю канала
from telethon import TelegramClient
client = TelegramClient("sess", API_ID, API_HASH)
await client.start()
async for msg in client.iter_messages("channel", limit=500):
    if "example.com" in (msg.text or ""):
        print(msg.id, msg.date, msg.text[:120])
```

## Поисковые операторы и dorks

```
site:t.me "example.com"
site:t.me/s "база" "example"
site:pastebin.com "example.com" "password"
"example.com" telegram channel
```

Комбинируйте домен с маркерами утечек: `password`, `db_pass`, `AKIA`, `BEGIN PRIVATE KEY`, `token`.

## Пасты как источник креденшелов

- Пасты часто содержат **конфиги** с паролями БД и API-ключами.
- Ключи проверяйте на **валидность** только в рамках scope (например, свой сервис).
- Не запускайте скрипты из пастов — распространённый вектор заражения.
- Фиксируйте: URL, время, хэш содержимого.

## Мониторинг: архитектура

```text
[источники] -> [парсер/regex] -> [нормализация] -> [дедуп] -> [алерты]
 paste          PasteHunter       {type,value,     SQLite    Telegram
 telegram       свой скрипт        source,ts}                 email
 forums                                                       Slack
```

Правила regex под ключевые активы (домен, бренд, email-паттерн) плюс оценка по Admiralty.

## Сравнение источников утечек

| Источник | Свежесть | Доступ |
|---|---|---|
| Telegram | очень высокая | публичный/инвайт |
| Pastebin | высокая | публичный |
| Форумы | средняя | регистрация |
| Агрегаторы БД | низкая | платно/подписка |
| Wayback | архив | публичный |

Telegram обычно опережает агрегаторы на дни и недели.

## Проверка находок и триаж

- **Валидность ключей** — проверяйте только в рамках scope; иначе это уже использование чужих секретов.
- **Актуальность** — старый дамп может быть уже исправлен; сверяйте с датой паста.
- **Дубликаты** — один слив перепощивают десятки каналов; дедуплицируйте по хэшу.
- **Достоверность** — оценивайте по Admiralty: надёжность источника × достоверность данных.
- **Приоритет** — сначала активы с прямым доступом (ключи, креды), потом PII, потом «шум».

## Что делать после находки

1. Сохранить копию (текст + хэш + время + URL).
2. Оценить достоверность (Admiralty).
3. Связать с активами (домен, IP, аккаунт).
4. При подтверждении ключа — эскалация на ротацию.
5. Задокументировать в отчёте с доказательствами.

## Итоговая сводка

- **Источники:** Pastebin, Rentry, Telegram, Discord, форумы.
- **Поиск:** dorks + psbdmp + поток PasteHunter.
- **Telegram:** `t.me/s/<channel>`, tgstat, Telethon.
- **Мониторинг:** ключевые слова → regex → алерты → журнал.
- **Доказательства:** копия + sha256 + время + URL.
- **Триаж:** валидность, актуальность, достоверность, приоритет.

Главный принцип: сохраняй копию немедленно — пасты и сообщения исчезают.

## Отличие от баз утечек

Базы утечек (HIBP и агрегаторы) — это **исторические** дампы, обновляемые с задержкой. Пастбины и Telegram — **живой поток**, где свежий слив появляется первым. Оптимально использовать оба: поток для раннего обнаружения, базы для ретроспективной проверки.
