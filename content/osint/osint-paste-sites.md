## Вопрос, с которого всё начинается

Компания хочет узнавать о сливе своих данных **в день публикации**, а не через год из отчёта аудитора. Проблема в том, что свежие сливы почти никогда не появляются сразу в агрегаторах утечек — они сначала всплывают в «полуоткрытых» местах: на paste-сайтах, в Telegram-каналах, на форумах.

В прошлом уроке мы работали с историческими базами. Теперь разберём **живой поток** — и научимся не потерять доказательство, потому что пасты и сообщения исчезают очень быстро.

## Наш пример: следим за example.com

У нас один объект наблюдения — домен `example.com`. Задача: найти, что про него уже публиковали, и настроить обнаружение новых публикаций. Введём два термина.

**Паст** (paste) — это фрагмент текста, опубликованный на сервисе вроде Pastebin без регистрации: часто туда попадают конфиги, ключи, куски баз. **Слив** — публикация данных, которые не должны были стать публичными.

## Шаг 1: ищем в индексе пастов через dorks

Самый дешёвый старт — поиск по проиндексированным пастам. **Dork** — это поисковый запрос с операторами, который сужает выдачу. Например, оператор `site:` ограничивает поиск одним доменом:

```
site:pastebin.com "example.com"
site:pastebin.com "example.com" password
site:pastebin.com "AKIA"
site:pastebin.com "BEGIN PRIVATE KEY"
```

Маркеры вроде `AKIA` (префикс ключей AWS), `BEGIN PRIVATE KEY` (приватный ключ) и `password` находят пасты с секретами. Важная оговорка: dorks видят только то, что поисковик успел проиндексировать, — то есть обычно не самый свежий паст.

## Шаг 2: архив пастов через psbdmp

Чтобы искать по архиву, а не по индексу поисковика, используем **psbdmp** — сервис с API поиска по дампам Pastebin:

```bash
curl -s "https://psbdmp.ws/api/v3/search/example.com" | jq -r '.data[]?.id' | head
```

```
bXk2pQ1a
9fLm3TzR
```

Каждый `id` — это конкретный паст. Смотрим содержимое конкретного паста по «сырой» ссылке:

```bash
curl -s "https://psbdmp.ws/api/v3/dump/bXk2pQ1a" | jq -r '.data.text' | head
```

```
DB_HOST=db.internal.example.com
DB_USER=svc_backup
DB_PASS=Spring2023!
```

Вот это уже находка: конфиг с паролем к внутренней базе. Обрати внимание — мы **не запускаем** и **не используем** этот пароль, только фиксируем факт.

## Шаг 3: Telegram без авторизации

Telegram — де-факто главная площадка сливов. У него есть **публичный предпросмотр**: страница `t.me/s/<канал>` отдаёт последние сообщения канала без входа в аккаунт. Это и есть наш базовый инструмент.

```bash
curl -s "https://t.me/s/example_channel" | sed 's/<[^>]*>//g' | grep -v '^$' | head -20
```

```
Дамп базы example.com, 2.4 млн строк, актуален на март
Контакты для проверки: @example_seller
```

Дополнительно вытащим все ссылки из постов — часто там инвайты в приватные группы:

```bash
curl -s "https://t.me/s/example_channel" | grep -oE 'https?://[^"< ]+' | sort -u | head
```

```
https://t.me/+AbCdEf123
https://example-mirror.net/dump
```

Ссылка вида `t.me/+hash` — **инвайт** в приватную группу. Это граница: наблюдать публичный предпросмотр можно, а вступать в закрытые группы и выкачивать оттуда персональные данные — уже нарушение.

## Шаг 4: настраиваем живой поток

Ручной поиск ловит только прошлое. Для новых публикаций нужен **поток**. Инструмент **PasteHunter** постоянно читает ленту новых пастов и прогоняет каждый через регулярные выражения — **regex**, шаблоны поиска по тексту. Совпало — приходит уведомление в Telegram или Slack.

Правило для нашего домена выглядит так:

```
(?i)(example\.com|@example\.com)
```

Конструкция `(?i)` означает «без учёта регистра», а `\.` — экранированная точка (иначе она в regex означает «любой символ»). Как только на Pastebin появится паст с упоминанием домена, мы получим алерт.

## Шаг 5: сохраняем доказательство

Это самый недооценённый шаг. Паст может быть удалён через час — и без копии доказательство исчезает. Сохраняем текст, его хэш и время:

```bash
curl -s "https://pastebin.com/raw/bXk2pQ1a" -o paste.txt
sha256sum paste.txt | tee paste.sha256
date -u | tee collected_at.txt
```

```
3f9a1c...e7  paste.txt
Mon, 12 Oct 2026 09:14:02 +0000
```

Хэш (`sha256sum`) доказывает, что копия не изменена, а дата в UTC фиксирует момент сбора. Дополнительно архивируем страницу в **Wayback Machine**, чтобы осталась независимая копия:

```bash
curl -s "https://web.archive.org/save/https://pastebin.com/bXk2pQ1a" | head -1
```

## Шаг 6: триаж находки

Найденное надо рассортировать. Оцениваем по двум осям: **валидность** (работает ли ещё секрет) и **достоверность** (не фейк ли). Для оценки достоверности используют принцип **Admiralty**: надёжность источника × достоверность информации.

Приоритет такой: сначала активы с прямым доступом (ключи, пароли), потом персональные данные, потом «шум». Пароль `Spring2023!` из нашего паста — сезонный и старый, но проверить его на ротацию всё равно нужно. А вот утёкший ключ `AKIA...` — это эскалация на немедленную ротацию.

## Если в пастах и Telegram ничего нет

Не всё живёт на Pastebin и в Telegram. Если там пусто, расширяем площадки:

- **Discord.** Публичные серверы слабо индексируются, но приглашения вида `discord.gg/...` раскиданы по форумам и каталогам (disboard). Ищите по приглашениям и dorks.
- **Форумы.** Закрытые площадки с обсуждениями и сливами — доступ обычно по регистрации или инвайту. Смотрите заголовки и метаданные тем, не выкачивая данные.
- **IRC.** Старые каналы части сообществ живы до сих пор, а их логи нередко выкладывают обратно на паст-сайты.

Принцип один: сначала **наблюдать** и фиксировать факт публикации, и только потом — при наличии основания — работать с содержимым.

## Что мы теперь знаем

- Свежие сливы появляются на пастах и в Telegram раньше, чем в агрегаторах.
- Dorks находят проиндексированное, psbdmp — архив, PasteHunter — поток.
- `t.me/s/<канал>` даёт публичный предпросмотр без авторизации.
- Копию нужно сохранять немедленно: текст + `sha256` + время в UTC + URL.
- Находки сортируются по валидности и достоверности, приоритет — у прямых доступов.

## На что смотреть дальше

Разберись, как связать находку с инфраструктурой: утёкший домен — проверить через Certificate Transparency, утёкший ключ — на валидность в рамках scope. Изучи каталоги Telegram-каналов (tgstat, telemetr) и форумы: там инвайты и обсуждения. Дальше это перерастёт в полноценный threat intelligence.

## Разбор кейса: как работает триаж паста

Ты нашёл паст с упоминанием `example.com`. Первое желание — сразу сохранить и бежать дальше. Правильный порядок другой: сначала **триаж** — быстрая оценка, стоит ли вообще тратить время.

Шаг первый — определить тип паста. Это может быть лог ошибки, конфиг, дамп базы, кусок кода или просто болтовня. Тип определяет ценность: дамп базы — критично, лог — почти бесполезно. Шаг второй — оценить свежесть. Дата создания и дата последнего просмотра говорят, «живой» ли это слив или старый мусор. Шаг третий — проверить происхождение: подписан ли паст ником, есть ли ссылка на источник, похож ли стиль на реальную утечку.

Шаг четвёртый — извлечь артефакты. Из паста выписывают только конкретику: email, хеши, пути, имена хостов, ключи. Всё остальное — контекст. Шаг пятый — проверить артефакты на валидность: хеш пароля можно сравнить с известным форматом, домен — резолвнуть, email — проверить в HIBP.

| Признак | Реальная утечка | Мусор |
|---|---|---|
| Тип содержимого | структурированные данные | заметки, логи |
| Свежесть | недавняя дата | годы назад |
| Согласованность | поля сочетаются | даты и форматы спорят |
| Источник | подписан, обсуждается | анонимно, без контекста |

Ключевая мысль: паст — это не «находка», а сырьё. Находкой он становится только после триажа и проверки. Без этого ты утонешь в тысячах упоминаний и не найдёшь ничего полезного.

## Если не сработало

**Паст удалён.** Публичные сервисы хранят пасты по-разному; часть удаляется быстро. Ищи копию в архиве (Wayback), в зеркалах или в кэше поисковиков. Иногда упоминание сохранилось в обсуждении на форуме.

**Поиск по dork ничего не даёт.** Индексация пастов неполная. Попробуй специализированные агрегаторы (psbdmp, PasteLert), они индексируют больше.

**Много шума.** Ограничь поиск точной строкой в кавычках и добавь второе ключевое слово (например, имя продукта). Одиночный домен даёт тысячи ложных совпадений.

**Паст выглядит как приманка.** Мошенники выкладывают фейковые «утечки» для репутации. Проверь внутреннюю согласованность данных: несоответствие дат и форматов — признак выдумки.

## Частые вопросы

**Законно ли читать пасты?** Публичный паст — публичные данные. Но использовать найденные учётки — нет. Читай и фиксируй, не входи.

**Как настроить мониторинг?** Подписка на ключевые слова в агрегаторах плюс регулярный прогон dorks. Мониторинг важнее разового поиска: утечка может появиться в любой момент.

**Что делать с найденным ключом?** Сообщить владельцу и зафиксировать факт. Не проверять ключ «в бою» без авторизации.

## Правовые границы

Пасты часто содержат персональные данные и секреты. Даже чтение требует основания: задача, scope, легитимный интерес. Не публикуй найденное, не передавай третьим лицам, храни минимум и удаляй после отчёта.

## Куда дальше

Мы научились находить свежие сливы и фиксировать доказательства. В следующем уроке — **бизнес-реестры**: возьмём компанию и по открытым реестрам (OpenCorporates, OCCRP, Companies House) соберём её юрлицо, директоров и связи. А пока главное запомни: копию сохраняй немедленно — пасты исчезают.

## Где пригодится

- **Threat intelligence:** раннее обнаружение сливов бренда.
- **CTF (OSINT):** найти флаг в «слитом» пасте.
- **Пентест:** обнаружить утёкшие креды до активной фазы.
- **Работа:** мониторинг репутации и компрометации.
