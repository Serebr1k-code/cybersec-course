## Вопрос, с которого всё начинается

В LTE постоянный идентификатор абонента (IMSI) скрыт за временным GUTI, но при первой регистрации всё равно ходит по эфиру. В 5G эту проблему решили радикально: идентификатор шифруется. Разберём, как устроена архитектура 5G и действительно ли она закрывает старые угрозы.

## Наш пример: сигнализация 5G NR

Перед нами `nr-signal.log` — упрощённая запись регистрации в сети 5G. Смотрим начало:

```
$ head -6 nr-signal.log
UE -> gNB: RRCSetupRequest
UE -> AMF: Registration Request (5GMM) SUCI
AUSF -> UDM: UE Authentication
UE <- AMF: Authentication Request (5G-AKA)
UE -> AMF: Registration Accept
UE -> SMF: PDU Session Establishment
```

Новые имена: **gNB**, **AMF**, **AUSF**, **UDM**, **SMF**. Это не просто переименование LTE — изменилась сама архитектура.

## Шаг 1: gNB и service-based core

Базовая станция 5G называется **gNB** (next generation NodeB). Ядро — **5GC** — построено по принципу **service-based architecture** (SBA): функции оформлены как сервисы, общаются через API (HTTP/2, JSON), а не через жёсткие интерфейсы.

Основные функции ядра:

| Функция | Роль |
|---------|------|
| AMF | Access and Mobility Management — аналог MME |
| SMF | Session Management — управление сессиями |
| AUSF | Аутентификация |
| UDM | Управление абонентскими данными |
| UPF | Пользовательская плоскость (данные) |

Переход на веб-технологии (HTTP/2, REST) — важное изменение: у ядра появилась «обычная» сетевая поверхность, которую аудируют как API.

## Шаг 2: SUPI и SUCI — главное новшество

В 5G постоянный идентификатор абонента называется **SUPI** (Subscription Permanent Identifier). Чтобы он не ходил по эфиру открыто, вводится **SUCI** (Subscription Concealed Identifier):

- Телефон берёт SUPI (обычно IMSI).
- Применяет **открытый ключ домашней сети** (профиль защиты, ECIES).
- Получает SUCI — зашифрованный идентификатор.
- SUCI и уходит в эфир; расшифровать его может только домашняя сеть.

Именно это закрывает классический IMSI-catcher: перехватив SUCI, атакующий не получает IMSI.

## Шаг 3: аутентификация 5G-AKA

Аутентификация 5G-AKA развивает идею AKA из 3G/4G: взаимная проверка сети и абонента через RAND/AUTN, но с дополнительной защитой «домашней сети» (**home network public key**) и подтверждением от AUSF. Даже visiting-сеть (роуминг-партнёр) не может выдать себя за домашнюю — это защита от подделки в роуминге.

## Шаг 4: сетевые слайсы и их границы

5G умеет **network slicing** — делить одну физическую сеть на логически изолированные «слайсы» (например, для IoT, для критичной связи, для широкополосного доступа). Идея — изоляция. Но именно изоляция и становится объектом проверки: если слайсы настроены слабо, трафик одного может влиять на другой.

## Шаг 5: где остались поверхности

5G защищён лучше предшественников, но аудит всё равно находит точки:

1. **Даунгрейд** — телефон может уйти в 4G/3G/2G, если 5G недоступен.
2. **Реализации SUCI-профилей** — null-scheme (без шифрования) допускается и иногда используется.
3. **Service-based core** — ошибки в API-авторизации между функциями ядра.
4. **Роуминг** — доверие между операторами, непрозрачные границы.
5. **Виртуализация** — ядро часто разворачивают в облаке/контейнерах, добавляя классические веб-уязвимости.

Вывод: 5G закрыл конкретную дыру (открытый IMSI), но расширил поверхность за счёт веб-технологий в ядре.

## Шаг 6: что мы нашли в логе

В нашем файле, как и в предыдущих примерах, есть строка с полезной нагрузкой:

```
$ grep payload nr-signal.log
Registration Accept: payload=nto{5g_suc1_h1d35_5up1}
```

Флаг показывает суть урока: SUCI скрывает SUPI. Обрати внимание, что мы снова достали данные из служебной записи, а не «взломали шифр» — диагностические вставки в логах остаются источником утечек.

## Шаг 7: защита и аудит

- **Не откатываться на null-scheme SUCI** — всегда использовать профиль с шифрованием.
- **Сегментировать слайсы** и проверять их изоляцию.
- **Аудит API ядра** — аутентификация и авторизация между NF (network functions).
- **Отключение legacy** — убирает даунгрейд.
- **Мониторинг аномалий** — как и во всех поколениях.

## Что мы теперь знаем

1. Базовая станция 5G — **gNB**, ядро 5GC построено как сервисы (SBA).
2. **SUPI** — постоянный идентификатор, **SUCI** — его зашифрованная форма в эфире.
3. Аутентификация 5G-AKA защищает и от подделки в роуминге.
4. Network slicing даёт изоляцию, но её надо проверять.
5. Новые поверхности — API ядра и виртуализация; старые — даунгрейд.

## Куда дальше

Мы прошли всю сотовую цепочку от 2G до 5G. Но абонента представляет конкретное железо: смарт-карта и baseband-процессор. В следующем уроке разберём **SIM/eSIM**: файловую систему USIM, команды APDU и аутентификацию AKA на карте. А пока главное: **5G зашифровал идентификатор — но пока существует фолбэк, абонент остаётся достижимым.**
