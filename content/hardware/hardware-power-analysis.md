## Вопрос, с которого всё начинается

В прошлых уроках мы обходили защиту, внося сбои (glitching). Но есть и «тихая» атака: каждый такт процессор переключает миллионы транзисторов, и каждый переключатель потребляет ток. Потребление зависит от обрабатываемых данных — значит, по кривой тока можно «увидеть» биты ключа.

Вопрос урока: как из графика потребления извлечь секретный ключ AES?

## Наш пример: учебная цель с AES

Перед нами платформа **ChipWhisperer** с прошитым AES-ядром. Мы знаем открытые тексты, которые подаём на вход, и хотим восстановить ключ шифрования. Осциллограф подключён к цепи питания цели.

## Шаг 1: почему потребление зависит от данных

КМОП-логика потребляет энергию в основном при переключении (0→1 и 1→0). Если на шине меняется больше битов — потребление выше. Для криптоопераций (S-box в AES, умножение в RSA) число переключений коррелирует с данными и ключом.

Упрощённо: `потребление(t) ≈ Σ переключений(t)`. Записывая ток во времени, получаем сигнал, в котором «зашита» информация о внутренних значениях.

Две модели утечки:

- **Hamming weight** — потребление пропорционально числу единиц в значении;
- **Hamming distance** — потребление пропорционально числу изменившихся битов.

Выбор модели зависит от реализации.

## Шаг 2: три метода — SPA, DPA, CPA

| Метод | Идея | Нужно измерений | Устойчивость к шуму |
|-------|------|-----------------|---------------------|
| SPA (simple) | визуально по одной кривой | 1 | низкая |
| DPA (differential) | разность средних по гипотезам | много | средняя |
| CPA (correlation) | корреляция с гипотезами | много | хорошая |

**SPA** — вы смотрите на кривую и угадываете операции (например, «здесь квадрат, здесь умножение» в RSA). Работает на наивных реализациях.

**DPA** — группируете кривые по гипотезе о бите ключа и вычитаете средние; при верной гипотезе появляется пик.

**CPA** — считаете корреляцию Пирсона между потреблением и моделью для каждого кандидата байта ключа; максимум корреляции — правильный байт. Самый популярный метод.

## Шаг 3: захватываем кривые

Собираем N кривых (например, 5000) для случайных открытых текстов, синхронизируясь по началу шифрования:

```python
import numpy as np
from chipwhisperer.analyzer.attacks.cpa import CPA
from chipwhisperer.analyzer.attacks.models.aes import AES
# traces: (N, L) — N измерений длины L
# texts:  (N, 16) — открытые тексты
```

Кривая — массив точек потребления, снятых через равные интервалы. Дальше нужна **синхронизация**: без стабильного триггера кривые «разъезжаются», и корреляция размажется.

## Шаг 4: как устроена CPA на AES

1. Для каждого кандидата байта ключа `k` (0–255) и каждого открытого текста `p` вычисляем `Sbox(p ⊕ k)`.
2. По значению S-box строим модель потребления (Hamming weight).
3. Считаем корреляцию модели с кривой в точке, соответствующей выходу S-box.
4. Байт с максимальной корреляцией — правильный.

Ключевое: CPA «сканирует» все точки кривой и сам находит ту, где живёт утечка.

## Шаг 5: прогоняем атаку

```python
leak_model = AES(key_len=16, model=AES.KEY_HD)
attack = CPA(traces, texts, leak_model, 0)
best = attack.get_key_byte(0)   # байт 0
print(hex(best))
```

Результат:

```text
Byte 0: correlation peak 0.42 at sample 1830 -> 0x2b
Byte 1: correlation peak 0.39 at sample 1832 -> 0x7e
...
Recovered key: 2b7e151628aed2a6abf7158809cf4f3c
```

Пик корреляции на конкретной задержке выделяет правильный байт. Проверяем ключ, расшифровав известный шифротекст.

## Шаг 6: DPA «руками», чтобы понять суть

Покажем ядро без фреймворка — это проясняет механику. Гипотеза о бите ключа делит кривые на две группы, и мы смотрим, различаются ли средние:

```python
import numpy as np

def dpa_byte(traces, texts, byte=0):
    best = None
    for k in range(256):
        hw = np.array([bin(sbox[p[byte] ^ k]).count('1') for p in texts])
        group1 = traces[hw > hw.mean()]
        group0 = traces[hw <= hw.mean()]
        diff = group1.mean(0) - group0.mean(0)
        peak = np.max(np.abs(diff))
        if best is None or peak > best[0]:
            best = (peak, k, np.argmax(np.abs(diff)))
    return best

print(dpa_byte(traces, texts, 0))
# key byte 0 = 0x2b, peak=0.1837 at sample 1830
```

Для полного ключа повторяем по всем 16 байтам. CPA даёт более острый пик при меньшем числе кривых, поэтому на практике чаще используют именно его.

## Шаг 7: атаки на RSA/ECC

- **SPA на RSA** — по форме кривой видно возведение в квадрат и умножение; последовательность операций выдаёт биты приватного показателя.
- **CPA на RSA** — коррелируя потребление с гипотезами о промежуточных значениях, восстанавливают ключ.
- **ECC** — скалярное умножение (double-and-add) даёт различимый паттерн; по нему восстанавливают скаляр.
- **Differential fault + power** — комбинируя инъекцию ошибки и анализ, ломают даже защищённые реализации.

## Шаг 8: предобработка — половина успеха

Сырые кривые почти никогда не совпадают точка-в-точку: джиттер такта и случайные задержки сдвигают события. Если не выровнять кривые, корреляция «размажется».

Приёмы:
- **Стабильный триггер и внешний клок** — события на фиксированных позициях.
- **Cross-correlation alignment** — сдвиг каждой кривой к эталону по максимуму корреляции.
- **Усреднение и фильтрация** — против белого шума.
- **Heatmap** — визуальная проверка: стабильные операции выглядят как вертикальные полосы.

Практический совет: сначала добейтесь стабильного триггера и повторяемости, и только потом собирайте тысячи кривых.

## Шаг 9: как защищаются

- **Маскирование** — секрет разбивается на случайные доли; утечка каждой доли не коррелирует с секретом.
- **Скрытие (hiding)** — рандомизация операций, балансировка потребления, шум.
- **Constant-time** — устранение зависимостей от данных.
- **Ограничение числа операций** и **датчики** аномалий питания.

Маскирование дорого и уязвимо к атакам высокого порядка, но именно оно закрывает классическую CPA.

## Шаг 10: сколько нужно кривых и как понять, что ключ верный

Практический вопрос: сколько измерений достаточно? Теория говорит, что для CPA на AES корреляция правильного байта растёт как `1/√N` относительно шума, поэтому удвоение числа кривых повышает пик примерно в 1,4 раза. На учебном ChipWhisperer хватает 1000–5000 кривых; на реальном чипе с шумом и защитами — десятки тысяч, а при маскировании — миллионы (или атака второго порядка). Чтобы не гонять перебор вслепую, используют **метрику сходимости**: для каждого байта смотрят, как меняется пик корреляции с ростом N. Если для правильного кандидата пик стабильно отрывается от остальных 255 — ключ найден; если все кандидаты «слиплись», кривых мало или триггер плохой. Второй признак — проверка: расшифруйте известный шифротекст найденным ключом. Третий — позиции пиков: у правильных байтов они группируются в окрестности одного сэмпла (выход S-box), у шумовых — разбросаны.

## Шаг 11: почему это вообще работает

Фундамент атаки — физика КМОП-логики. Транзистор потребляет энергию в основном в момент переключения: пока состояние стабильно, ток мал; при смене 0→1 или 1→0 через ёмкости затворов протекает заряд. Значит, ток в данный такт пропорционален числу переключившихся битов, а число переключений зависит от обрабатываемых данных. Криптоалгоритм — это детерминированная функция от открытого текста и ключа, поэтому внутренние значения (например, выход S-box) предсказуемы для каждого кандидата ключа. CPA сопоставляет предсказание с измерением и находит кандидата, который «объясняет» сигнал. Никакой магии: это корреляция между моделью и физикой. Отсюда и все защиты — они либо разрывают связь данных с переключениями (маскирование, constant-time), либо прячут сигнал в шуме (скрытие), либо ограничивают число доступных измерений.

## Частые вопросы

**Нужен ли дорогой осциллограф?**
Для реальных чипов — да, нужен осциллограф с достаточной полосой и частотой дискретизации (десятки-сотни МГц), потому что утечка живёт на высоких частотах. Для обучения хватает ChipWhisperer, который совмещает захват и синхронизацию. Начинать всегда стоит с учебного стенда: там известен ключ, и вы видите, как атака работает, прежде чем тратить время на реальный чип.

**Что важнее — число кривых или качество захвата?**
Качество. Тысячи плохо синхронизированных кривых дадут размытый пик, тогда как сотни хорошо выровненных могут восстановить ключ. Поэтому сначала добиваются стабильного триггера, чистого питания и повторяемости, и только потом наращивают N. Хорошая проверка — heatmap: если операции видны как вертикальные полосы, сигнал стабилен.

**Почему у меня корреляция есть, а ключ неверный?**
Три частые причины: неверная модель утечки (Hamming weight вместо distance), не та точка на кривой (пик от другой операции), либо атака «нашла» корреляцию со вспомогательным значением, а не с ключом. Проверяйте по всем 16 байтам: если у половины пики совпадают с ожидаемым паттерном, а у другой половины — нет, вероятна ошибка в модели или выравнивании.

**Работает ли это на защищённых чипах?**
Классическая CPA — нет: маскирование и constant-time закрывают её. Но существуют атаки высокого порядка (снимают маскирование несколькими точками), профилированные атаки (обучение на копии чипа) и комбинации с fault injection. Это уже экспертный уровень: требует лаборатории, времени и часто нескольких тысяч долларов оборудования. Для пентеста важнее оценить, применяет ли производитель защиту, а не пытаться сломать её.

## Что мы теперь знаем

1. Потребление зависит от переключаемых битов, поэтому коррелирует с данными и ключом.
2. SPA — одна кривая визуально; DPA/CPA — статистика по тысячам.
3. CPA на AES: гипотеза по байту ключа, модель Hamming weight, корреляция.
4. Выравнивание кривых и стабильный триггер важнее выбора метода.
5. RSA/ECC атакуются по паттерну операций (square-and-multiply, double-and-add).
6. Защита: маскирование, скрытие, constant-time, датчики.

## На что смотреть дальше

- **Плохой триггер.** Без стабильной синхронизации кривые «разъезжаются».
- **Мало измерений.** CPA требует тысяч кривых; с сотней не выйдет.
- **Шум.** Неэкранированное питание и соседние компоненты портят сигнал.
- **Неверная модель.** Hamming weight против distance — ошибёшься, корреляция пропадёт.
- **Band-limit включён.** Фильтр «съедает» высокочастотные детали, где живёт утечка.

## Куда дальше

Power analysis — «входной билет» в side-channel: освоив CPA на учебном стенде, вы сможете атаковать реальные чипы. Дальше по дереву — электромагнитный анализ, который слушает чип без контакта. А пока главное: **данные и ключ «протекают» через потребление — и это не магия, а статистика.**

- **Исследования:** извлечение ключей из защищённых чипов.
