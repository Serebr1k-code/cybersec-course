SWD (Serial Wire Debug) — двухпроводная альтернатива JTAG для ARM: только SWCLK и SWDIO. Но за простотой скрывается CoreSight — целая подсистема трассировки и отладки: SWO/ITM (вывод printf без UART), ETM (поток выполненных инструкций), DWT (watchpoints), ROM table с описанием компонентов. Урок раскрывает эти возможности.

## Теория

**SWD** использует:
- SWCLK — такт,
- SWDIO — двунаправленные данные,
- опционально SWO (Serial Wire Output) — односторонний вывод трассировки,
- nRESET — сброс.

**CoreSight** — набор компонентов на кристалле:

| Компонент | Назначение |
|-----------|-----------|
| DAP (Debug Access Port) | доступ к шине памяти/регистрам |
| ITM (Instrumentation Trace Macrocell) | программный вывод трассировки (printf) |
| DWT (Data Watchpoint and Trace) | аппаратные watchpoints, счётчики |
| ETM (Embedded Trace Macrocell) | полный поток выполненных инструкций |
| ETB (Embedded Trace Buffer) | встроенный буфер трассировки |
| TPIU (Trace Port Interface Unit) | вывод трассировки наружу (SWO/параллельный) |
| ROM Table | карта компонентов CoreSight |

**SWO/ITM** позволяет устройству писать отладочные сообщения через один провод без UART — бесценно, когда UART занят или закрыт.

**ETM** даёт поток выполненных инструкций: можно реконструировать исполнение прошивки, включая переходы, без остановки ядра.

**Отладка без halt** — некоторые защиты блокируют остановку ядра; тогда используют неинтрузивную трассировку (ETM/SWO) или watchpoints.

## Инструменты и команды

- **OpenOCD** — SWD + SWO/ITM.
- **pyOCD** — Python-отладчик, удобен для скриптов и SWO.
- **J-Link / ST-Link / CMSIS-DAP** — железо.
- **Orbuculum / swo-tools** — декодирование ITM/SWO.
- **Tracealyzer** — анализ RTOS-трассировки.

```bash
# --- OpenOCD: SWD + SWO ---
openocd -f interface/cmsis-dap.cfg -f target/nrf52.cfg \
  -c "adapter speed 2000" \
  -c "tpiu config internal /tmp/swo.log uart off 64000000 2000000"
# в telnet 4444: itm port 0 on; resume

# --- pyOCD: чтение и трассировка ---
pyocd list
pyocd cmd -t nrf52840 --frequency 2M
# внутри: read32 0x20000000, halt, resume

# --- Декодирование SWO-потока ---
# В OpenOCD: trace ... ; затем разбор через orbtrace/Orbuculum
```

```text
# Проверка ROM Table (карта CoreSight) через OpenOCD:
> dap info 0
# Вывод перечисляет компоненты: ETM, ITM, DWT, TPIU...
```

## Разобранный пример: восстановление логики прошивки через ETM

**Дано:** ARM Cortex-M прошивка, UART закрыт, но SWD доступен. Нужно понять алгоритм проверки лицензии.

**Шаг 1 — подключение SWD.** Находим SWCLK/SWDIO (см. `hardware-jtag-deep`), подключаем CMSIS-DAP, `pyocd list` подтверждает чип.

**Шаг 2 — ROM table.** `dap info 0` показывает наличие ETM/ITM. Есть трассировка — отлично.

**Шаг 3 — SWO/ITM.** Включаем ITM-порт 0 и смотрим, пишет ли прошивка что-то через `ITM_SendChar`. Часто там debug-логи с этапами проверки лицензии.

```bash
openocd -f interface/cmsis-dap.cfg -f target/xxx.cfg \
  -c "tpiu config internal /tmp/swo.log uart off 64000000 2000000" \
  -c "itm port 0 on" -c "init" -c "reset run"
```

**Шаг 4 — ETM-трассировка.** Настраиваем ETM на захват потока инструкций в буфер, воспроизводим сценарий проверки лицензии (ввод неверного ключа), затем читаем трассировку и сопоставляем с адресами в дизассемблере.

**Шаг 5 — точки останова.** Ставим аппаратный breakpoint на функцию сравнения (`hb 0x08001234`), смотрим регистры в момент проверки. Так восстанавливаем алгоритм без дизассемблирования всей прошивки.

**Шаг 6 — вывод.** Полученный алгоритм либо воспроизводим (генерация валидного ключа), либо используем как доказательство уязвимости.

## Частые ошибки

- **SWD без nRESET.** Без линии сброса подключение нестабильно, особенно после `halt`. Подключайте nRESET.
- **Неверная скорость SWCLK.** Слишком быстро на длинных проводах = ошибки. Начните с 1 МГц.
- **SWO не декодируется.** Частота TPIU должна точно соответствовать системной; ошибка в множителе = мусор.
- **Ожидание ETM на всех чипах.** Дешёвые Cortex-M0 могут не иметь ETM. Проверяйте ROM table.
- **Забыли про защиту.** `halt` может блокироваться; используйте неинтрузивные методы.
- **Перезагрузка после halt.** Некоторые прошивки сбрасывают ключи в RAM при halt; анализируйте аккуратно.

## Теория: SWD и CoreSight

SWD (Serial Wire Debug) — двухпроводной интерфейс отладки ARM (SWCLK, SWDIO). CoreSight — набор компонентов трассировки: ETM (инструкции), ITM/SWO (printf-подобный вывод), DWT (watchpoints). Преимущество трассировки: можно наблюдать выполнение без остановки (non-halt), что важно для real-time и защищённых систем. ETM даёт поток исполненных инструкций, по которому восстанавливают логику прошивки, даже если код зашифрован в памяти.

## Инструменты и команды

```bash
# OpenOCD
openocd -f interface/cmsis-dap.cfg -f target/nrf52.cfg
# в telnet 4444
> reset halt
> flash read_bank 0 dump.bin 0 0x40000
> dump_image sram.bin 0x20000000 0x10000
# pyOCD
pyocd list
pyocd cmd -t nrf52840 --commands "reset halt"
# трассировка SWO
# JLink / CMSIS-DAP с SWO pin
```

`flash read_bank` читает флеш, `dump_image` — память. Для ETM нужен вывод TRACECLK/TRACEDATA и поддержка на стороне probe.

## Разобранный пример 2: восстановление логики через ETM

1. Подключаем SWD, `reset halt`, снимаем состояние.
2. Включаем ETM-трассировку и SWO.
3. Прогоняем сценарий (ввод данных).
4. Собираем поток инструкций и сопоставляем с адресами.
5. Восстанавливаем алгоритм (например, проверку пароля) без дизассемблирования всего бинарника.

## Обход debug-lock

Многие чипы блокируют SWD после прошивки (debug lock). Обходы: mass-erase через специальную последовательность, glitching в момент проверки lock, чтение через альтернативный интерфейс (JTAG, boot ROM). Иногда lock снимается через сам загрузчик.

## SWO/ITM: вывод без остановки

SWO (Serial Wire Output) передаёт данные ITM (Instrumentation Trace Macrocell) — аналог printf из прошивки. Если прошивка использует ITM, вы видите отладочные сообщения, не останавливая ядро. Настройка: probe с поддержкой SWO, частота SWO (обычно CPU/2 или /4), декодирование через `pyocd` или JLink.

```bash
pyocd commander -t nrf52840 --swo
# или
JLinkSWOViewerCL
```

## Практика

Подключитесь по SWD, включите SWO, прогоните сценарий и соберите вывод ITM. Сопоставьте сообщения с кодом. Затем попробуйте ETM-трассировку и восстановите поток инструкций. Это продвинутый уровень аппаратной отладки, позволяющий понять логику без полного дизассемблирования.

## Сводка по CoreSight

| Компонент | Назначение | Интерфейс |
|-----------|------------|-----------|
| SWD | отладка (halt/step) | SWCLK, SWDIO |
| SWO/ITM | printf без halt | SWO |
| ETM | поток инструкций | TRACECLK/DATA |
| DWT | watchpoints | через SWD |

Для реверса логики ETM ценнее всего: он даёт исполненный поток. Начните с SWD+SWO, затем переходите к ETM при необходимости.
