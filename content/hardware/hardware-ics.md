Промышленные системы управления (ICS/SCADA) управляют электростанциями, водоканалами, заводами и трубопроводами. Их особенность — приоритет **доступности** и **безопасности процесса** над конфиденциальностью: остановка производства или авария опаснее утечки данных. При этом протоколы (Modbus, DNP3, S7) создавались без аутентификации и шифрования, а сети часто плохо сегментированы. Этот урок — карта OT-ландшафта и векторов атак.

## Компоненты ICS/SCADA

- **PLC (Programmable Logic Controller)** — контроллер, исполняющий логику управления (лестничная логика).
- **RTU (Remote Terminal Unit)** — удалённый терминал для телеметрии.
- **HMI (Human-Machine Interface)** — операторская панель.
- **SCADA-сервер** — сбор данных и управление.
- **Historian** — архив измерений.
- **Инженерная станция** — программирование PLC (TIA Portal, Unity Pro).
- **Сеть OT** — промышленная сеть, отделённая от IT (или нет).

## Purdue-модель

Классическая сегментация описывается уровнями:

| Уровень | Название | Что там |
|---------|----------|---------|
| 0 | Process | датчики, приводы |
| 1 | Basic control | PLC, RTU |
| 2 | Supervisory | HMI, SCADA |
| 3 | Operations | historian, инжиниринг |
| 3.5 | DMZ | шлюзы, прокси |
| 4 | Enterprise | корпоративная IT |
| 5 | Internet | внешний мир |

Атака обычно идёт сверху вниз: из IT (уровень 4) в OT (уровни 0–2). DMZ (3.5) должна разделять домены, но часто этого нет.

## Протоколы OT

| Протокол | Порт | Особенности |
|----------|------|-------------|
| Modbus TCP | 502 | без аутентификации |
| Modbus RTU | serial | то же, по RS-485 |
| DNP3 | 20000 | «защищённый» режим редко включён |
| S7comm | 102 | Siemens, проприетарный |
| EtherNet/IP | 44818 | Rockwell |
| IEC 104 | 2404 | энергетика |
| OPC UA | 4840 | современный, с шифрованием |
| PROFINET | L2 | Siemens |

Большинство legacy-протоколов **не имеют аутентификации**: кто угодно в сети может читать и записывать значения.

## Векторы атак

- **Прямой доступ к PLC**: чтение/запись регистров через Modbus/DNP3.
- **Изменение логики**: перепрошивка PLC через инженерную станцию или сеть.
- **Спуфинг датчиков**: подмена значений, чтобы оператор принял неверное решение.
- **DoS на шину**: забить сеть, вызвать срабатывание защиты и останов.
- **Компрометация HMI**: через уязвимости Windows/веб-интерфейса.
- **Supply chain**: вредоносные обновления, скомпрометированные подрядчики.
- **Прыжок IT→OT**: через плохо сегментированные сети и общие учётки.

## Разобранный пример: обнаружение и чтение Modbus

```bash
# 1. Обнаружить Modbus-устройства
nmap -p 502 --script modbus-discover 10.0.0.0/24
# 2. Прочитать holding registers (pymodbus)
python3 -c "
from pymodbus.client import ModbusTcpClient
c = ModbusTcpClient('10.0.0.10', port=502)
r = c.read_holding_registers(0, 10)
print(r.registers)
"
# 3. Записать значение (ОСТОРОЖНО: может изменить процесс!)
python3 -c "
from pymodbus.client import ModbusTcpClient
c = ModbusTcpClient('10.0.0.10', port=502)
c.write_register(0, 1234)
"
```

Чтение безопасно, запись может повлиять на физический процесс — только в рамках согласованного теста.

## Правовые и этические аспекты

Атака на промышленные системы может привести к **аварии, травмам и смерти**. Работа с OT-сетями допускается только:

- в изолированной лаборатории/симуляторе (GRFICS, Conpot);
- в рамках согласованного пентеста с участием технологов и службы эксплуатации;
- с явным запретом на запись в реальные PLC без письменного разрешения.

Правило №1 в ICS-пентесте: **не сломать процесс**. Любые действия, влияющие на физику, согласуются и выполняются в окно обслуживания.

## Частые ошибки и подводные камни

- **Запись в регистр «на пробу»** — может открыть клапан или остановить насос.
- **Неверный адрес регистра**: чтение одного вместо другого даёт ложную картину.
- **Спутать unit ID**: несколько устройств за одним шлюзом.
- **Сканирование «в лоб»**: агрессивный скан может уронить legacy-PLC.
- **Игнорирование задержек**: OT-сети чувствительны к таймингам.

## Протоколы детальнее: DNP3, S7, OPC UA

Помимо Modbus, в OT распространены:

- **DNP3** (порт 20000) — телеметрия в энергетике и воде. Имеет «secure authentication» (SAv2/5), но он редко включён. Уязвимости: spoofing, несанкционированные команды, DoS на outstation.
- **S7comm** (порт 102) — Siemens. Позволяет читать/писать память PLC, запускать/останавливать CPU. Инструменты: `snap7`, `s7scan`.
- **OPC UA** (порт 4840) — современный стандарт с шифрованием и аутентификацией, но ошибки конфигурации (анонимный доступ, слабые сертификаты) сводят защиту на нет.
- **EtherNet/IP** (44818) — Rockwell; команды CIP.
- **IEC 60870-5-104** (2404) — энергетика.

```bash
# Обнаружение S7
nmap -p 102 --script s7-info 10.0.0.0/24
# OPC UA: проверка анонимного доступа
python3 -c "
from opcua import Client
c = Client('opc.tcp://10.0.0.10:4840'); c.connect()
print(c.get_root_node().get_children())
"
```

## Безопасность инженерных станций

Инженерные станции (TIA Portal, Unity Pro) — самый лакомый объект: они могут **перепрошивать PLC** и менять логику. Риски:

- Старые ОС (Windows XP/7) без патчей.
- Общие учётки/пароли на несколько станций.
- Отсутствие MFA и сегментации.
- Проекты (файлы логики) без защиты — их можно похитить и модифицировать.

Захват инженерной станции равносилен полному контролю над процессом. Защита: изоляция, отдельные учётки, контроль съёмных носителей, подпись проектов.

## Обнаружение и мониторинг OT

Пассивный мониторинг — ключевой метод в OT, потому что активное сканирование может уронить legacy-оборудование:

```bash
# Зеркалирование порта и анализ трафика
sudo tcpdump -i eth0 -n port 502 or port 102 or port 20000 -w ot.pcap
# Wireshark: dissectors для Modbus/S7/DNP3
```

Специализированные средства: **Nozomi**, **Claroty**, **Dragos**, **Zeek** с OT-скриптами. Задача — построить «базлайн» нормального трафика и ловить отклонения (новые команды записи, необычные адреса).

## Практический стенд

Для безопасного обучения используйте симуляторы:

- **GRFICS** — виртуальный завод (PLC + HMI + процесс).
- **Conpot** — honeypot, эмулирующий Modbus/S7.
- **OpenPLC** — программный PLC.
- **ScadaBR** — SCADA-платформа.

```bash
# Conpot: поднять honeypot
conpot --template default
# OpenPLC: залить лестничную логику и опрашивать по Modbus
```

Стенд позволяет отрабатывать чтение/запись, спуфинг и DoS без риска для реального процесса.

## Сегментация и DMZ

Правильная сегментация — основа защиты OT. Уровень **3.5 (DMZ)** должен отделять IT от OT: только через него идут данные (historian-реплика, jump-хост), и только в одну сторону там, где возможно.

```text
IT (4)  --[firewall]-->  DMZ (3.5)  --[firewall]-->  OT (0-3)
```

Частые ошибки: прямой доступ из корпоративной сети к PLC, общие учётки, RDP из IT в OT, отсутствие логирования. Для пентестера это первые точки входа: скомпрометировав IT, можно «провалиться» в OT через незащищённый мост. Проверяйте маршрутизацию, разрешённые порты и учётные записи между уровнями.

## Практические сценарии

- **Инвентаризация OT**: пассивно определить устройства и протоколы.
- **Проверка доступа**: есть ли неаутентифицированный доступ к PLC.
- **Анализ сегментации**: можно ли из IT дотянуться до OT.
- **Оценка конфигурации**: дефолтные пароли, открытые сервисы.
- **Демонстрация риска**: показать, что чтение регистров доступно без аутентификации.

Каждый шаг согласуется с эксплуатацией, чтобы не нарушить процесс.

## Соответствие стандартам и регуляции

OT-безопасность регулируется: **IEC 62443** (промышленная кибербезопасность), **NIST SP 800-82**, отраслевые требования (энергетика, вода). Они описывают зоны/кондуиты (сегментация), уровни защищённости (SL) и требования к компонентам. Для пентеста полезно знать эти рамки: находки формулируются в их терминах (нарушение зоны, недостаточный SL), что помогает в отчёте и защите результатов.
