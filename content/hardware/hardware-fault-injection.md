## Вопрос, с которого всё начинается

В прошлом уроке мы смотрели на side-channel — пассивное наблюдение за устройством. Но есть и активный метод: короткий **сбой** в питании или тактовом сигнале заставляет процессор пропустить инструкцию. Так обходят проверки пароля и даже secure boot.

Вопрос урока: как именно «сломать» вычисление в нужный момент и попасть в узкое окно успеха?

## Наш пример: микроконтроллер с 8-значным PIN

Перед нами устройство, которое требует 8-значный PIN и защищено readout protection — прошивку не сдампить. Но у нас есть **ChipWhisperer** (платформа для glitching). Наша цель — войти без верного PIN.

## Шаг 1: идея атаки

Процессор выполняет инструкции такт за тактом. Если на критический момент — например, на инструкцию сравнения `if (pin == correct)` — наложить сбой, решение получится «неправильным», обычно в пользу атакующего.

Типы инъекции:

| Тип | Как делается | Что ломает |
|-----|--------------|-----------|
| Voltage glitch (crowbar) | кратковременно просадить Vcc | пропуск инструкций |
| Clock glitch | «лишний»/короткий такт | сбой выборки/исполнения |
| EMFI | импульс катушкой рядом с чипом | пропуск без контакта |
| Optical (лазер) | лазер в кремний | точечный сбой (лаборатория) |

Ключевые параметры glitch: **width** (сколько держать сбой), **offset** (задержка от триггера), напряжение/форма. Обычно параметры подбирают «слепым» перебором с детекцией успеха.

## Шаг 2: что нужно подготовить

- **ChipWhisperer** (Husky/Nano) — glitch по питанию/такту и захват, синхронно.
- **Осциллограф** — контролировать форму glitch.
- **MOSFET-плата crowbar** — быстрый разряд Vcc.
- **Развязка по питанию** — обязательна: плохая фильтрация даёт неконтролируемые сбои.

```bash
$ pip install chipwhisperer
```

## Шаг 3: синхронизация — 80% успеха

Глитчер должен сработать **точно** в момент сравнения. Для этого нужен аппаратный триггер: сигнал UART, GPIO или начало ответа. Без точного триггера результат случайный.

## Шаг 4: развёртка параметров

Итерируем width и offset, на каждой комбинации подаём неверный PIN и смотрим ответ:

```python
import chipwhisperer as cw
scope = cw.scope()
scope.default_setup()
scope.glitch.clk_src = 'clkgen'
scope.glitch.output = 'glitch_only'
scope.glitch.trigger_src = 'ext_single'
target = cw.target(scope)
for width in range(1, 50):             # ширина импульса в тактах
    for offset in range(0, 1000, 10):  # задержка
        scope.glitch.width = width
        scope.glitch.offset = offset
        scope.io.glitch_hp = True
        scope.arm()
        target.write('check_pin 0000\n')
        ret = target.read(timeout=50)
        if ret and 'OK' in ret:        # детект успешного сбоя
            print('WIN', width, offset, ret)
```

На большинстве комбинаций — «DENIED». На одной — «OK» или переход к меню.

## Шаг 5: стабилизация

Успешная комбинация может быть «на грани». Повторяем её 100 раз и отбираем те, где успех >90%. Только стабильные параметры годятся для эксплуатации.

## Шаг 6: эксплуатируем

С успешной комбинацией заходим в защищённое меню. Иногда glitch используют, чтобы пропустить проверку readout protection и затем снять дамп памяти. Если voltage glitch не срабатывает — пробуем clock glitch: добавляем лишний короткий такт в момент выборки инструкции.

## Шаг 7: как от этого защищаются

- **Детекторы сбоев** — датчики напряжения/такта.
- **Двойные проверки** — результат подтверждается дважды.
- **Рандомизация таймингов** — сбивает точное попадание.
- **Redundant computation** — сравнение двух вычислений.
- **Физическая защита** кристалла (экран, датчики вскрытия).

## Шаг 8: если voltage glitch не срабатывает

Иногда питание просадить не удаётся — мешает развязка, защита или слишком быстрый чип. Тогда пробуют другие каналы:

| Метод | Параметр | Когда применять |
|-------|----------|-----------------|
| Voltage glitch | width/offset | обычные микроконтроллеры |
| Clock glitch | лишний такт | когда питание стабильно |
| EMFI | позиция зонда | запечатанные/залитые чипы |
| Optical (лазер) | точная позиция | защищённые кристаллы, лаборатория |

EMFI (электромагнитный импульс) хорош тем, что не требует электрического контакта: катушка подносится к чипу, и сбой возникает от наведённого поля. Optical-атака требует вскрытия кристалла и точного позиционирования лазера — это уровень серьёзной лаборатории.

Практический порядок: начинайте с voltage glitch (порог входа ниже всего), затем clock, и только потом переходите к EMFI/optical. В любом случае документируйте успешные параметры — воспроизводимость здесь ценится выше «одноразового везения».

## Шаг 9: что настраивать в ChipWhisperer

Помимо width и offset, важны ещё несколько параметров:

- **clk_src** — источник такта (`clkgen` для clock glitch, внешний для voltage).
- **trigger_src** — от чего стартовать (`ext_single` по внешнему триггеру).
- **repeat** — сколько раз повторить сбой подряд, чтобы повысить шанс.
- **glitch_hp/glitch_lp** — высокочастотный/низкочастотный выход глитчера.

Итерируйте по одному параметру за раз: сначала найдите грубое окно по offset, затем сужайте width, затем добавляйте repeat. Логируйте каждую успешную комбинацию — по ним строится воспроизводимая атака. Иногда помогает изменение полярности (glitch_hp против glitch_lp): одна полярность срабатывает, другая нет.

## Что мы теперь знаем

1. Fault injection накладывает сбой на критический такт, ломая проверку.
2. Типы: voltage (crowbar), clock, EMFI, optical.
3. Перебирают два параметра — width (ширина) и offset (задержка).
4. Точный аппаратный триггер критичен; без него сбой «промахивается».
5. Успешную комбинацию проверяют многократно на стабильность.
6. Защита: детекторы, двойные проверки, рандомизация таймингов.

## На что смотреть дальше

- **Слишком грубый glitch.** Убивает чип (brown-out/reset). Начинайте с минимальной ширины.
- **Нет стабильного триггера.** Результат случайный — синхронизация важнее всего.
- **Один прогон = вывод.** Успех может быть редким — собирайте статистику.
- **Нет детектора успеха.** Нужен надёжный признак «получилось» (UART-ответ, изменение поведения).
- **Питание без развязки.** Плохая фильтрация = неконтролируемые сбои.
- **Правовые рамки.** Fault injection на чужом оборудовании (банкоматы, счётчики) — преступление.

## Шаг 10: ведём таблицу sweep и статистику

Слепой перебор без учёта результатов превращается в лотерею. Поэтому каждую пробу фиксируем: параметры, ответ цели и признак успеха.

| width | offset | repeat | Ответ | Успех |
|-------|--------|--------|-------|-------|
| 5 | 200 | 1 | DENIED | · |
| 7 | 220 | 1 | DENIED | · |
| 7 | 240 | 2 | OK | ✓ |
| 9 | 240 | 1 | reset | ✗ |

`✓` — цель пустила без PIN, `✗` — сброс/повисание, `·` — без эффекта. Видно, что окно узкое: ширина 7 при задержке 240. Затем каждую успешную точку повторяют 100 раз и считают долю успеха — для эксплуатации годятся комбинации со стабильностью выше 90%. Нестабильные («на грани») тоже полезны: они очерчивают границу окна и подсказывают, куда двигаться.

Детектор успеха должен быть однозначным. «Устройство мигнуло LED» — плохой признак: мигание бывает и при сбое. Хороший — конкретный ответ по UART (`OK`, вход в меню) или появление ранее недоступной команды.

## Если не сработало

- **Цель сбрасывается на каждой пробе.** Импульс слишком широкий или просадка слишком глубокая — уменьшите width и амплитуду, начните с минимальных значений.
- **Успех «плавает» и не повторяется.** Синхронизация: замените программный таймер на аппаратный триггер и уменьшите jitter между стартом команды и glitch.
- **Чип перестал отвечать совсем.** Сбой «окирпичил» цель — работайте на копии, никогда на единственном образце.
- **Ни одна комбинация не даёт эффекта.** Проверьте развязку по питанию и полярность выхода (`glitch_hp` против `glitch_lp`); иногда нужен clock glitch вместо voltage.

## Законность и изоляция

Fault injection физически повреждает устройство и может вывести его из строя. Работайте только на своём оборудовании или в рамках явного письменного разрешения. Учебные платы ChipWhisperer для этого и существуют: они позволяют отработать все шаги без риска и без правовых последствий.

## Куда дальше

Fault injection даёт точечный сбой в нужном месте. Дальше по дереву нас ждут другие физические атаки — например, электромагнитный side-channel и Rowhammer, ломающий память программно. А пока главное: **любая проверка — это ветвление, а ветвление можно сбить.**

## Где пригодится

- **CTF:** Hardware-задачи с обходом PIN/secure boot и чтением защищённой памяти.
- **Аппаратная безопасность:** оценка стойкости микроконтроллеров, смарт-карт, TPM.
- **Red team:** физический доступ к устройствам, обход защит.
- **Работа:** сертификация по Common Criteria, аудит защищённых чипов.
- **Дальше по дереву:** `hardware-em-sidechannel`, `hardware-rowhammer`.
