Fault injection (инъекция сбоев) — мощнейший класс аппаратных атак: короткий сбой в питании или тактовом сигнале заставляет процессор пропустить инструкцию, сравнить неверно или «открыть» защиту. Именно так обходят secure boot, читают защищённую память и обходят проверки пароля. Это продвинутый урок, требующий понимания side-channel.

## Теория

Идея: процессор выполняет инструкции в такт. Если на критический момент (например, инструкцию сравнения `if (pin == correct)`) наложить сбой, можно получить «неправильное» решение — обычно в пользу атакующего.

Типы инъекции:

| Тип | Как делается | Что ломает |
|-----|--------------|-----------|
| Voltage glitch (crowbar) | кратковременно просадить Vcc через транзистор | пропуск инструкций, обход проверок |
| Clock glitch | «лишний»/короткий такт | сбой выборки/исполнения |
| EMFI (электромагнитная) | импульс катушкой рядом с чипом | пропуск инструкций без контакта |
| Optical (лазер) | лазер в кремний | точечный сбой (лабораторный уровень) |
| Body bias | подмена напряжения подложки | изменение порогов |
| Temperature | перегрев/переохлаждение | нестабильность |

Ключевые параметры glitch: **ширина импульса** (сколько держать сбой), **задержка** (когда именно), **напряжение/форма**. Обычно атакуют «слепым» перебором параметров с детекцией успеха.

Целевые защитные механизмы, которые ломают:
- проверка пароля/PIN в прошивке;
- secure boot (подпись образа);
- запрет чтения защищённой области флеш;
- crypto-операции (пропуск проверки подписи).

## Инструменты и команды

- **ChipWhisperer** (Husky/Nano/Pro) — эталон: glitch по питанию/клоку + захват, синхронно, с готовыми примерами.
- **PicoGlitcher / ChipWhisperer-Lite** — бюджетные варианты.
- **EFT/EMFI-инжекторы** — для бесконтактного сбоя.
- **Осциллограф** — контролировать форму glitch.
- **MOSFET-плата crowbar** — разряд Vcc через быстрый транзистор.

```bash
# Установка ChipWhisperer (Python)
pip install chipwhisperer

# Пример скрипта glitch по питанию (упрощённо)
python - <<'PY'
import chipwhisperer as cw
scope = cw.scope()
scope.default_setup()
scope.glitch.clk_src = 'clkgen'
scope.glitch.output = 'glitch_only'
scope.glitch.trigger_src = 'ext_single'
target = cw.target(scope)
for width in range(1, 50):          # ширина импульса в тактах
    for offset in range(0, 1000, 10):  # задержка
        scope.glitch.width = width
        scope.glitch.offset = offset
        scope.io.glitch_hp = True
        scope.arm()
        target.write('check_pin 0000\n')
        ret = target.read(timeout=50)
        if ret and 'OK' in ret:      # детект успешного сбоя
            print('WIN', width, offset, ret)
PY
```

## Разобранный пример: обход проверки PIN на микроконтроллере

**Дано:** устройство требует 8-значный PIN, прошивку дампить нельзя (readout protection). Есть ChipWhisperer.

**Шаг 1 — синхронизация.** Нужен триггер: момент, когда устройство начинает проверку PIN. Ищем точку в прошивке (или по UART-запросу) и вешаем триггер.

**Шаг 2 — определить цель сбоя.** Нам нужно пропустить ветку «PIN неверный». Значит, glitch ставим на инструкцию сравнения/ветвления.

**Шаг 3 — развёртка параметров.** Итерируем width (ширина) и offset (задержка). На каждой комбинации подаём неверный PIN и смотрим ответ.

```text
width=1..40, offset=0..1000 step 5
На большинстве — «DENIED». На одной комбинации — «OK» или переход к меню.
```

**Шаг 4 — стабилизация.** Успешная комбинация может быть «на грани» — повторяем 100 раз, отбираем комбинации с успехом >90%.

**Шаг 5 — эксплуатируем.** С успешной комбинацией заходим в защищённое меню / читаем память. Иногда glitch используют для пропуска проверки readout protection и последующего дампа.

**Шаг 6 — clock glitch вариант.** Если voltage glitch не срабатывает, пробуем clock glitch: добавляем лишний короткий такт в момент выборки инструкции.

## Частые ошибки

- **Слишком грубый glitch.** Убивает чип (brown-out/reset). Начинайте с минимальной ширины и постепенно увеличивайте.
- **Нет стабильного триггера.** Без точного момента сбоя результат случайный. Синхронизация — 80% успеха.
- **Один прогон = вывод.** Успех может быть редким. Собирайте статистику.
- **Нет детектора успеха.** Нужен надёжный признак «получилось» (UART-ответ, изменение поведения), иначе не отличите сбой от случайности.
- **Питание без развязки.** Плохая фильтрация = неконтролируемые сбои. Развязка по питанию обязательна.
- **Правовые рамки.** Fault injection на чужом оборудовании (банкоматы, счётчики, транспорт) — преступление. Только своё/авторизованное.

## Теория: как работает glitching

Fault injection создаёт кратковременный сбой в работе микроконтроллера, заставляя его пропустить проверку или выполнить неверную ветку. Основные виды: voltage glitching (кратковременное проседание питания), clock glitching (лишний/пропущенный такт), electromagnetic (EMFI, импульс рядом с чипом), optical (лазер). Успешный glitch может обойти проверку PIN, прочитать защищённую память или обойти secure boot. Ключ к успеху — точный тайминг: сбой должен попасть в конкретную инструкцию.

## Разобранный пример 2: подбор параметров

1. Цель: микроконтроллер с проверкой PIN.
2. Вводим неверный PIN, но glitch в момент сравнения.
3. Перебираем `offset` (задержку) с шагом, при фиксированном `width`.
4. При успехе устройство «принимает» неверный PIN.
5. Сужаем диапазон и находим стабильные параметры.
6. Повторяем для воспроизводимости.

## Защита

Детекторы сбоев (voltage/clock sensors), двойные проверки, рандомизация таймингов, redundant computation, физическая защита чипа.

## Тайминг и обратная связь

Успех glitch зависит от точности тайминга. Параметры: `width` (длительность импульса), `offset` (задержка от триггера), `ext_offset` (точная позиция). Подбор — перебор с обратной связью: успех виден по поведению цели (например, принят неверный PIN). Начните с широкого диапазона, затем сужайте. Используйте `repeat` для стабильности и логируйте каждый успешный набор.

## Практика

На учебной платформе (ChipWhisperer target) настройте voltage glitch и обойдите проверку пароля. Задокументируйте параметры успеха и проверьте воспроизводимость (несколько успешных запусков подряд). Затем обсудите защиту: детекторы сбоев и двойные проверки делают glitch существенно сложнее.
