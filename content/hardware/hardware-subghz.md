Суб-ГГц диапазон (315/433/868/915 МГц) — это брелоки шлагбаумов, гаражные ворота, пульты сигнализаций, датчики. Простые пульты передают фиксированный код — повтор и всё. Сложные используют rolling-коды (Keeloq), но и они уязвимы к RollJam. Урок — практическое введение.

## Теория

Типы кодирования:

| Тип | Пример | Защита |
|-----|--------|--------|
| Фиксированный код | дешёвые пульты, датчики | нет, replay работает |
| Rolling code (счётчик) | Keeloq, HCS301 | счётчик; replay в узком окне |
| Keeloq (крипто) | авто, ворота | блочный шифр, но ключи часто слабые |
| Challenge-response | современные авто | стойкие, требуют реверса |

**Rolling code**: при нажатии передаётся счётчик + криптограмма. Приёмник принимает счётчики из «окна» впереди последнего (чтобы не терять нажатия). Атака **RollJam** эксплуатирует это: глушим легитимный сигнал, записываем два кода (жертва нажимает дважды), затем жертва уходит, а мы воспроизводим один из записанных кодов — приёмник принимает его как «следующий».

Keeloq: 528-битный ключ, но многие реализации используют ключи, извлекаемые из прошивки; существуют атаки на слабые ключи и side-channel.

## Инструменты и команды

- **Flipper Zero** — Sub-GHz чтение/эмуляция, brute force простых кодов.
- **RTL-SDR / HackRF** — приём и анализ.
- **Yard Stick One / CC1101** — передача и replay.
- **Universal Radio Hacker (URH)** — анализ и реверс сигналов.
- **rfcat** — управление CC1111/CC1101.
- **GNU Radio** — обработка.

```bash
# --- RTL-SDR: приём сырых сэмплов 433 МГц ---
rtl_fm -f 433.92M -s 22050 -g 40 - | sox -t raw -r 22050 -e signed -b 16 -c 1 - out.wav
# или запись IQ
rtl_sdr -f 433920000 -s 2048000 capture.iq

# --- URH: анализ ---
urh                       # GUI: открыть capture.iq, авто-определить модуляцию

# --- rfcat: replay через CC1101 ---
rfcat -r
>>> d.setFreq(433920000)
>>> d.RFxmit(b'\xAA\xBB...')      # повтор сырого пакета
```

## Разобранный пример: атака на шлагбаум с фиксированным кодом

**Дано:** шлагбаум, пульт 433 МГц, есть Flipper Zero.

**Шаг 1 — приём.** Flipper: `Sub-GHz → Read`. Слушаем, нажимаем пульт, ловим сигнал. Flipper показывает частоту, модуляцию (AM/OOK), сырой код.

**Шаг 2 — сохранить.** `Save` — получаем файл `.sub` с параметрами и сырыми импульсами.

**Шаг 3 — replay.** `Sub-GHz → Read → Saved → [файл] → Send`. Пульт воспроизводит сигнал. Если код фиксированный — шлагбаум откроется.

**Шаг 4 — анализ rolling-кода.** Если replay не срабатывает, вероятно rolling-код. Смотрим, меняется ли код при каждом нажатии. Если да — нужна RollJam.

**Шаг 5 — RollJam.** Двухчастотная атака: одновременно глушим частоту приёма шлагбаума и записываем код жертвы. Жертва жмёт дважды (не сработало) → записали два кода. Затем воспроизводим первый из них, пока приёмник не «сдвинулся». Требует специального железа (два передатчика/приёмника) и координации.

**Шаг 6 — вывод.** Фиксированные коды — тривиально; rolling-коды требуют RollJam; современные авто — challenge-response, обычно не берутся.

## Частые ошибки

- **Нет внешней антенны.** RTL-SDR с комплектной антенной плохо ловит 433 МГц. Нужна антенна в резонанс (17 см штырь для 433).
- **Не та модуляция.** OOK/ASK vs FSK. Неправильный выбор = мусор.
- **Попытка replay rolling-кода вслепую.** Счётчик сдвинется, приёмник отклонит. Нужен RollJam.
- **Передача без разрешения.** Глушение и передача в чужих диапазонах регулируется законом. Только свой пульт/лаборатория.
- **Правовые рамки.** Открытие чужого шлагбаума/гаража — преступление.
- **Игнорирование помех.** 433 МГц зашумлён; повторите запись в тихом месте.

## Теория: sub-GHz и фиксированные коды

Устройства 315/433/868 МГц (шлагбаумы, брелоки, датчики) часто используют фиксированный код: нажатие передаёт один и тот же битовый шаблон. Перехват и повтор (replay) открывает доступ. Кодировки: PT2262, EV1527, CAME, Nice, Keeloq (rolling, сложнее).

## Инструменты

```bash
# HackRF / RTL-SDR + rtl_433
rtl_433 -f 433.92M -A
rtl_433 -f 433.92M -R 0   # все протоколы
# Flipper Zero
# Sub-GHz → Read (запись сигнала) → Replay
# Proxmark3 (для некоторых)
```

`rtl_433 -A` включает анализ, `-R` выбирает декодеры. Flipper Zero позволяет записать и воспроизвести сигнал в меню Sub-GHz.

## Разобранный пример 2: воспроизведение сигнала брелока

1. Сканируем частоту (`rtl_433 -f 433.92M -A`).
2. Фиксируем сигнал при нажатии брелока.
3. Анализируем: код фиксированный или rolling.
4. Если фиксированный — воспроизводим (Flipper Replay).
5. Проверяем на своём шлагбауме/тестовом приёмнике.

## Митигации

Rolling-коды (Keeloq), challenge-response, шифрование, ограничение дальности.

## Спектр, помехи и jamming

Sub-GHz-диапазоны: 315/433/868/915 МГц. Помехи (jamming) блокируют приёмник, но не дают доступа; для replay нужен перехват. Некоторые системы используют «code grabbing» — глушат оригинал и ретранслируют его код (для rolling-кодов сложнее). Наблюдение за спектром: `rtl_433 -f 433.92M -A` + визуализация в `inspectrum`/`URH`.

## Практика

1. Определите частоту вашего устройства (паспорт/этикетка).
2. Запишите сигнал брелока через Flipper/SDR.
3. Проанализируйте, фиксированный ли код.
4. Воспроизведите на своём приёмнике.
5. Сделайте вывод о защищённости и рекомендации (rolling-код, шифрование).

## Итог

Sub-GHz-устройства с фиксированным кодом уязвимы к replay; rolling-коды (Keeloq) и шифрование закрывают вектор. Инструменты — rtl_433, HackRF, Flipper Zero. Для защиты — rolling-коды и криптографическая аутентификация.

## Replay против rolling: как отличить

Ключевой вопрос при анализе sub-GHz-сигнала: меняется ли код при каждом нажатии. Запишите сигнал дважды и сравните:

```bash
rtl_433 -f 433.92M -A -F json | tee signals.json
# сравнить два нажатия
jq -r 'select(.model) | .code' signals.json
```

Если `code` одинаковый — фиксированный, replay работает. Если отличается — rolling (Keeloq/HCS), и простой replay не сработает. Для rolling-кодов нужен либо захват и мгновенная ретрансляция («code grabbing» с глушением), либо компромисс ключа шифрования. Практически большинство дешёвых шлагбаумов и брелоков используют фиксированные коды, поэтому replay остаётся рабочим вектором.

Инструментально: HackRF/RTL-SDR для приёма и анализа, Flipper Zero для записи/воспроизведения, `inspectrum`/URH для разбора модуляции. Важно соблюдать закон: тестируйте только своё оборудование или в рамках авторизованного пентеста. Для защитника рекомендация однозначна: переходить на rolling-коды и криптографическую аутентификацию, потому что фиксированный код не обеспечивает никакой защиты от перехвата.

## Быстрая проверка

```bash
rtl_433 -f 433.92M -A
rtl_433 -f 433.92M -R 0
# Flipper Zero: Sub-GHz → Read → Replay
```

Запишите сигнал дважды и сравните код. Одинаковый — фиксированный (replay работает); разный — rolling (нужен другой подход). Работайте только со своим оборудованием.
