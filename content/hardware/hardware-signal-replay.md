Replay-атака — это запись легитимного сигнала и его повтор. Звучит примитивно, но именно она открывает большинство дешёвых шлагбаумов, ворот, розеток, датчиков и пультов. Сложность не в самой атаке, а в понимании, **когда** она работает: если устройство использует фиксированный код, replay тривиален; если rolling code или challenge-response — нужны другие методы. Этот урок — про полный цикл «захват → анализ → воспроизведение → оценка применимости» и про то, как защищаться.

Мы разберём захват сигнала дешёвым SDR и Flipper, воспроизведение, задержку и code grabbing, а также границы применимости. Отдельный блок — защита: счётчики, nonce, таймстемпы и challenge-response.

## Когда replay работает

Replay применим, когда между переданным и принятым сигналом нет уникальной изменяющейся части, которую приёмник проверяет. Практические категории:

| Тип устройства | Кодирование | Replay |
|----------------|-------------|--------|
| Дешёвый пульт, розетка | фиксированный код (PT2262, EV1527) | работает |
| Датчик, брелок-«звонок» | фиксированный | работает |
| Шлагбаум с CAME/Nice | фиксированный/частичный | часто работает |
| Автосигнализация | rolling code (Keeloq) | нет (нужен RollJam) |
| Современное авто | challenge-response | нет |
| Wi-Fi/BLE-замок | крипто | нет |

Первый шаг любой оценки — определить, меняется ли код при каждом нажатии. Это делается записью двух-трёх нажатий и сравнением.

## Захват сигнала: SDR и Flipper

Для захвата нужен приёмник, покрывающий рабочую частоту (обычно 315/433/868/915 МГц). Варианты:

- **RTL-SDR** — дёшево, только приём, 24 МГц-2 ГГц. Хорош для анализа, но не для передачи.
- **HackRF One** — приём и передача (half-duplex), 1 МГц-6 ГГц. Универсальный.
- **Flipper Zero** — карманный, приём/передача Sub-GHz, меню Sub-GHz → Read/Send.
- **Yard Stick One / CC1101** — TX/RX Sub-GHz, управляется `rfcat`.
- **Proxmark3** — в основном RFID/NFC, но есть Sub-GHz-модули.

```bash
# --- RTL-SDR: приём сырых сэмплов 433.92 МГц ---
rtl_sdr -f 433920000 -s 2048000 -g 40 capture.iq

# --- rtl_433: декодирование известных протоколов «на лету» ---
rtl_433 -f 433.92M -A -F json | tee decode.json

# --- HackRF: приём с последующей передачей ---
hackrf_transfer -r capture.cs8 -f 433920000 -s 2000000 -a 1 -g 32
hackrf_transfer -t capture.cs8 -f 433920000 -s 2000000 -a 1 -x 40   # TX

# --- URH: анализ и ручное редактирование битов ---
urh capture.iq
```

## Разобранный пример: replay фиксированного кода

Дано: розетка 433 МГц с фиксированным кодом, RTL-SDR для анализа и HackRF для передачи.

**Шаг 1 — запись.** Слушаем канал и нажимаем пульт:

```bash
rtl_sdr -f 433920000 -s 2048000 -g 40 socket.iq
```

**Шаг 2 — декодирование.** Прогоняем через rtl_433:

```bash
rtl_433 -f 433.92M -A -r socket.iq
# OUTPUT:
# [433.92] model:  Prologue  id: 12345  code: 0xA1B2C3
# [433.92] model:  Prologue  id: 12345  code: 0xA1B2C3
```

Код одинаковый при повторных нажатиях → фиксированный.

**Шаг 3 — подготовка к передаче.** Записываем IQ-файл и передаём его через HackRF:

```bash
hackrf_transfer -t socket.iq -f 433920000 -s 2048000 -a 1 -x 40
```

**Шаг 4 — проверка.** Розетка срабатывает — replay успешен.

**Шаг 5 — вывод.** Устройство без защиты. Рекомендация — заменить на rolling code или криптографический протокол.

## Задержка, повторы и code grabbing

Replay не обязан быть точной копией. Возможны варианты:

- **Прямой replay** — передать записанный сигнал целиком.
- **Задержка (delayed replay)** — воспроизвести через время; иногда обходит проверки «свежести» с большим окном.
- **Повтор (repeat)** — многократно передать один и тот же код; для фиксированных кодов безвредно, для rolling — бесполезно.
- **Code grabbing** — активная атака: глушим оригинал, принимаем код жертвы и мгновенно ретранслируем его (или записываем и передаём позже). Для фиксированных кодов — работает; для rolling — только в узком окне.
- **Wormhole** — пересылка сигнала из точки A в точку B по сети (для систем, где важна физическая близость).

Важно: сам факт «повтора» не создаёт доступ. Приёмник решает, принять ли сигнал. Если есть счётчик/nonce — повтор отвергается.

## Защита: счётчики, nonce, таймстемпы, challenge-response

Как защищаются от replay:

1. **Счётчик (rolling code).** Каждый сигнал содержит инкрементируемое значение; приёмник принимает только значения из окна впереди. Повтор старого отвергается.
2. **Nonce.** Одноразовое число; приёмник отвергает уже виденные значения.
3. **Таймстемп.** Метка времени с узким окном (например, ±2 секунды). Задержанный replay отвергается. Требует синхронных часов.
4. **Challenge-response.** Приёмник шлёт случайный запрос, устройство отвечает криптограммой с секретом. Replay невозможен без знания ключа. Используется в современных авто и BLE-замках.
5. **Двусторонняя аутентификация.** Обе стороны проверяют друг друга (mutual auth), что закрывает подмену.
6. **MAC на кадре.** Криптографический код целостности связывает кадр с ключом и счётчиком.

Комбинация счётчика + MAC — практический минимум; challenge-response с AES — надёжный стандарт.

## Обход защиты: RollJam и ретрансляция

Против rolling code простой replay бессилен, но есть активные атаки:

- **RollJam** — глушим приёмник, записываем два кода жертвы, воспроизводим один из них. Эксплуатирует окно счётчика. Требует двух радио и физической близости.
- **Ретрансляция (relay)** — для систем с проверкой близости (например, NFC/BLE-замок) сигнал ретранслируется между двумя зондами, создавая иллюзию близости. Классика для автоключей (keyless entry).
- **Jamming** — глушение как DoS, но не доступ.
- **Fault injection** — сбой микроконтроллера в момент проверки, чтобы обойти сравнение.

Важно: эти атаки требуют специального железа и, как правило, физического присутствия. Правовые рамки — только лаборатория/разрешение.

## Инструменты и команды

```bash
# --- GNU Radio: визуальный анализ и генерация ---
gnuradio-companion
# блоки: RTL-SDR Source -> Low Pass Filter -> OOK Demod -> File Sink

# --- inspectrum: визуализация IQ ---
inspectrum capture.iq
# задать sample rate, выбрать область, посмотреть импульсы

# --- rfcat: ручная передача через CC1101 ---
rfcat -r
>>> d.setFreq(433920000)
>>> d.setMdmModulation(MOD_ASK_OOK)
>>> d.setMdmDRate(4800)
>>> d.RFxmit(b'\xAA\xAA\xAA\xD3\x91\x4C\x1F\x23\x00')

# --- flipper: меню ---
# Sub-GHz -> Read (захват) -> Save -> Send (replay)
# Sub-GHz -> Frequency Analyzer (поиск частоты)
```

Дополнительно: **URH** для автодетекта модуляции и редактирования битов, **Universal Radio Hacker** умеет генерировать сигнал из отредактированных битов — удобно для «подстройки» кода.

## Частые ошибки и подводные камни

- **Передача без правильной частоты/сэмплрейта.** HackRF должен использовать ту же частоту и полосу, что при захвате; иначе сигнал не декодируется.
- **RTL-SDR не передаёт.** Для TX нужен HackRF/Yard Stick/Flipper.
- **Попытка replay rolling-кода.** Сдвигает счётчик жертвы и не даёт доступа.
- **Игнорирование усиления (gain).** Слишком высокое усиление перегружает АЦП; слишком низкое — не декодируется.
- **Передача в чужих диапазонах без разрешения.** Регулируется законом.
- **Запись в шумном месте.** 433 МГц забит; повторите в тихой обстановке.
- **Нет внешней антенны.** Комплектная антенна RTL-SDR плохо ловит Sub-GHz; используйте резонансную (17 см для 433 МГц).

## Что дальше / решение

Дальнейшие шаги: (1) автоматизируйте захват и анализ — скрипт на rtl_433 + jq, который сам определяет «меняется ли код»; (2) отработайте RollJam на учебном стенде (два SDR); (3) исследуйте relay-атаки на BLE/NFC-замках; (4) для защиты — внедряйте challenge-response и проверяйте, что приёмник отвергает повторы (тест «replay должен провалиться»). В авторизованном пентесте результат — не «мы открыли дверь», а обоснованный вывод: какой тип кодирования, применим ли replay, какие митигации отсутствуют.

## Юридические и этические рамки replay

Replay-атака почти всегда выглядит как «взлом», и это не случайно: закон в большинстве юрисдикций трактует несанкционированное открытие чужого шлагбаума, ворот или автомобиля как правонарушение, а глушение радиосигнала — как отдельное нарушение правил использования радиочастот. Поэтому весь практический блок этого урока выполняется только на собственном оборудовании или в рамках подписанного договора пентеста с явно очерченной зоной. Перед любой передачей убедитесь, что вы не задеваете соседние устройства: Sub-GHz-диапазон общий, и нечаянная передача может помешать чужому датчику.

Технически работа делится на «безопасную» и «активную» части. Пассивный приём (запись IQ, декодирование `rtl_433`, анализ в URH) не излучает и почти всегда допустим. Активная передача (HackRF, rfcat, Flipper Send) и особенно глушение — излучают и требуют разрешения. Держите это разделение в отчёте: что вы наблюдали и что передавали. Для лабораторного стенда используйте экранированный бокс или хотя бы ослабляющие аттенюаторы, чтобы сигнал не уходил за пределы стола.

Ещё одна практическая тонкость — фиксация доказательств. Записывайте не только «сработало/не сработало», но и сырые IQ-файлы, дампы `rtl_433 -F json`, параметры захвата (частота, сэмплрейт, усиление) и версии инструментов. Без этого результат невоспроизводим и в отчёте выглядит голословно. Для защитника подготовьте короткую памятку: какие устройства в парке используют фиксированный код, какие — rolling, а какие — challenge-response, и что нужно заменить в первую очередь. Так пентест превращается в приоритизированный план миграции, а не в список «мы всё открыли».
