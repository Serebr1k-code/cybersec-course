## Вопрос, с которого всё начинается

У тебя есть умная розетка, которая включается с пульта на 433 МГц. Хочется понять, можно ли включить её, записав сигнал пульта и «повторив» его. Это классическая **replay-атака** — запись легитимного сигнала и его повтор. Звучит примитивно, но именно она открывает большинство дешёвых шлагбаумов, ворот, розеток и датчиков. Сложность не в самой атаке, а в понимании, **когда** она работает.

## Когда replay работает

Replay применим, когда в сигнале нет уникальной изменяющейся части, которую проверяет приёмник. Практические категории:

| Тип устройства | Кодирование | Replay |
|----------------|-------------|--------|
| Дешёвый пульт, розетка | фиксированный (PT2262, EV1527) | работает |
| Датчик, брелок-«звонок» | фиксированный | работает |
| Автосигнализация | rolling code (Keeloq) | нет (нужен RollJam) |
| Современное авто | challenge-response | нет |
| Wi-Fi/BLE-замок | крипто | нет |

Первый шаг любой оценки — определить, меняется ли код при каждом нажатии. Это делается записью двух-трёх нажатий и их сравнением.

## Наш пример: розетка 433 МГц

Дано: розетка с фиксированным кодом, RTL-SDR для анализа и HackRF для передачи. Задача — воспроизвести сигнал пульта.

## Шаг 1: захват сигнала

Для захвата нужен приёмник, покрывающий рабочую частоту (обычно 315/433/868/915 МГц). Варианты: **RTL-SDR** (только приём), **HackRF One** (приём и передача), **Flipper Zero** (карманный, приём/передача), **Yard Stick One / CC1101** (управляется `rfcat`).

```bash
rtl_sdr -f 433920000 -s 2048000 -g 40 socket.iq
```

## Шаг 2: декодируем

```bash
rtl_433 -f 433.92M -A -r socket.iq
# [433.92] model:  Prologue  id: 12345  code: 0xA1B2C3
# [433.92] model:  Prologue  id: 12345  code: 0xA1B2C3
```

Код одинаковый при повторных нажатиях → он **фиксированный**. Если бы код менялся от нажатия к нажатию, это был бы rolling code, и простой replay бы не прошёл.

## Шаг 3: воспроизводим

Записанный IQ-файл передаём через HackRF на той же частоте и с тем же sample rate:

```bash
hackrf_transfer -t socket.iq -f 433920000 -s 2048000 -a 1 -x 40
```

Розетка срабатывает — replay успешен. Устройство не имеет защиты; рекомендация — заменить его на rolling code или криптографический протокол.

## Варианты replay

Replay не обязан быть точной копией:

- **Прямой replay** — передать записанный сигнал целиком.
- **Задержка (delayed replay)** — воспроизвести через время; иногда обходит проверки «свежести» с большим окном.
- **Повтор (repeat)** — многократно передать один код; для фиксированных безвредно, для rolling бесполезно.
- **Code grabbing** — активная атака: глушим оригинал, принимаем код жертвы и мгновенно ретранслируем его (или записываем и передаём позже).
- **Wormhole** — пересылка сигнала из точки A в точку B по сети (для систем, где важна физическая близость).

Важно: сам факт «повтора» не создаёт доступ. Приёмник решает, принять ли сигнал. Если есть счётчик или nonce — повтор отвергается.

## Защита: счётчики, nonce, таймстемпы, challenge-response

1. **Счётчик (rolling code).** Каждый сигнал содержит инкрементируемое значение; приёмник принимает только значения из окна впереди. Повтор старого отвергается.
2. **Nonce.** Одноразовое число; приёмник отвергает уже виденные значения.
3. **Таймстемп.** Метка времени с узким окном (±2 секунды). Задержанный replay отвергается, но нужны синхронные часы.
4. **Challenge-response.** Приёмник шлёт случайный запрос, устройство отвечает криптограммой с секретом. Replay невозможен без знания ключа.
5. **Двусторонняя аутентификация (mutual auth).** Обе стороны проверяют друг друга — закрывает подмену.
6. **MAC на кадре.** Код целостности связывает кадр с ключом и счётчиком.

Комбинация счётчика и MAC — практический минимум; challenge-response с AES — надёжный стандарт.

## Обход защиты: RollJam и ретрансляция

Против rolling code простой replay бессилен, но есть активные атаки:

- **RollJam** — глушим приёмник, записываем два кода жертвы, воспроизводим один из них. Эксплуатирует окно счётчика; требует двух радио и физической близости.
- **Ретрансляция (relay)** — для систем с проверкой близости сигнал ретранслируется между двумя зондами, создавая иллюзию близости (классика для автоключей keyless entry).
- **Jamming** — глушение как DoS, но не доступ.
- **Fault injection** — сбой микроконтроллера в момент проверки, чтобы обойти сравнение.

Все они требуют специального железа и физического присутствия.

## Инструменты

```bash
inspectrum capture.iq     # визуализация IQ
gnuradio-companion        # RTL-SDR Source -> Low Pass Filter -> OOK Demod -> File Sink
rfcat -r
>>> d.setFreq(433920000); d.setMdmModulation(MOD_ASK_OOK); d.setMdmDRate(4800)
>>> d.RFxmit(b'\xAA\xAA\xAA\xD3\x91\x4C\x1F\x23\x00')
# Flipper Zero: Sub-GHz -> Read (захват) -> Save -> Send (replay)
```

**URH** умеет автодетект модуляции и генерацию сигнала из отредактированных битов — удобно для «подстройки» кода.

## Юридические рамки

Replay почти всегда выглядит как «взлом», и это не случайно: несанкционированное открытие чужого шлагбаума или автомобиля — правонарушение, а глушение радиочастот — отдельное нарушение. Пассивный приём (запись IQ, декодирование `rtl_433`, анализ в URH) почти всегда допустим; активная передача (HackRF, rfcat, Flipper Send) и особенно глушение — излучают и требуют разрешения. Держите это разделение в отчёте: что вы наблюдали и что передавали. Фиксируйте сырые IQ-файлы, дампы `rtl_433 -F json`, параметры захвата (частота, сэмплрейт, усиление) и версии инструментов — без этого результат невоспроизводим.

## Если не сработало

- **Передача без правильной частоты/сэмплрейта.** HackRF должен использовать ту же частоту и полосу, что при захвате.
- **RTL-SDR не передаёт.** Для TX нужен HackRF/Yard Stick/Flipper.
- **Попытка replay rolling-кода.** Сдвигает счётчик жертвы и не даёт доступа.
- **Игнорирование gain.** Слишком высокое усиление перегружает АЦП, слишком низкое — сигнал не декодируется.
- **Нет внешней антенны.** Комплектная антенна RTL-SDR плохо ловит Sub-GHz; нужна резонансная (~17 см для 433 МГц).

## Что мы теперь знаем

1. Replay работает только там, где код не меняется.
2. Определить тип кода можно, сравнив два нажатия.
3. Для передачи нужен TX-SDR (HackRF, Flipper, rfcat).
4. Защита строится на счётчиках, nonce, таймстемпах и challenge-response.
5. Активная передача и глушение регулируются законом.
