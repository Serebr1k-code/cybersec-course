## Зачем этот урок

Zigbee (IEEE 802.15.4, 2.4 ГГц) и Z-Wave (sub-GHz, ~868/908 МГц) — два стандарта умного дома. Оба шифруют трафик, но слабое место — **спаривание**: при джойне устройства ключ передаётся, и его можно перехватить. Этот урок — про сниффинг, извлечение ключей, атаки на спаривание и replay команд.

## Zigbee и IEEE 802.15.4: архитектура

Zigbee работает поверх IEEE 802.15.4 (2.4 ГГц, 16 каналов, 250 кбит/с). Сеть описывается **PAN ID** и каналом. Устройства: координатор (часто хаб), роутеры, end-devices. Стек Zigbee добавляет сетевой слой и APS, а безопасность — на уровне NWK (network key) и APS (link keys).

## Z-Wave: архитектура и частоты

Z-Wave — проприетарный протокол Silicon Labs на sub-GHz (868.42 МГц в EU, 908.42 МГц в US). Скорости 9.6/40/100 кбит/с. Сеть управляется контроллером (primary), устройства — узлы. Шифрование: S0 (устаревшее) и S2 (современное). Sub-GHz дальность выше, чем у Zigbee, но и перехват возможен.

## Транспорт и оборудование

| Протокол | Частота | Шифрование | Оборудование |
|----------|---------|------------|--------------|
| Zigbee | 2.4 ГГц (802.15.4) | AES-CCM*, network key | CC2531, nRF, ApiMote (KillerBee) |
| Z-Wave | 868/908 МГц | AES-128 (S2) | Z-Stick, Zniffer, RTL-SDR |

Для Zigbee нужен 802.15.4-трансивер (CC2531/nRF), для Z-Wave — Zniffer или sub-GHz-приёмник.

## Zigbee: сниффинг (KillerBee, CC2531)

```bash
zbid                       # список интерфейсов
zbstumbler                 # найти сети (PAN ID, канал)
zbdump -c <channel> -w zigbee.pcap   # запись трафика
```

CC2531 с прошивкой sniffer + `whsniff` отдаёт трафик в Wireshark. В Wireshark фильтр `wpan`. Важно попасть на рабочий канал — Zigbee использует 16 каналов, и устройства могут прыгать.

## Zigbee: ключи (network, link, TC link key)

Три уровня ключей: **network key** (шифрует весь трафик сети), **link keys** (между парами устройств), **TC link key** (между устройством и Trust Center при джойне). Дефолтный TC link key — `ZigBeeAlliance09` (16 байт: `5A 69 67 42 65 65 41 6C 6C 69 61 6E 63 65 30 39`). Если он дефолтный — перехват джойна даёт network key.

## Zigbee: извлечение ключа при джойне

Ключевой момент: при добавлении устройства Trust Center посылает ему **network key**, зашифрованный TC link key. Перехватив эту последовательность (`Transport Key` command) и зная TC link key (часто дефолтный), вы расшифровываете network key. Отсюда — полный доступ к трафику сети.

## Wireshark: расшифровка Zigbee

В Wireshark: Preferences → Protocols → ZigBee → Pre-configured keys → добавить network key. После этого весь трафик сети читается: команды управления, статусы, события. Это финальный шаг атаки на Zigbee.

## Z-Wave: S0 и его слабость

S0 использует AES-128, но с постоянным nonce при включении (`0xAA...`), что позволяет восстановить ключ из перехваченного обмена. S0 считается скомпрометированным и постепенно выводится из эксплуатации.

## Z-Wave: S2 и ECDH

S2 применяет ECDH (Curve25519) для обмена ключами и устойчив к перехвату джойна: подслушав обмен, вы не получите ключ. Остаются другие пути: извлечение ключа из прошивки/контроллера, компрометация облака производителя.

## Z-Wave: Zniffer и анализ

Zniffer (Silicon Labs) записывает Z-Wave-трафик и экспортирует в Wireshark. Для S0 — восстановление ключа из обмена; для S2 — анализ метаданных (команды, топология) без расшифровки содержимого.

## Атаки на спаривание

- **Replay джойна** — перехваченный обмен спаривания S0 воспроизводится.
- **Downgrade S2 → S0** — если контроллер поддерживает оба режима.
- **Извлечение link key** — из прошивки или сниффинга.
- **Джойн с дефолтным TC key** — если сеть не сменила ключ.

## Replay и инъекция команд

```bash
# Replay через Flipper/CC1101 для Z-Wave (sub-GHz)
# Zigbee replay: эмуляция устройства с украденным ключом
```

Имея network key (Zigbee) или восстановленный ключ S0 (Z-Wave), можно эмулировать устройство и слать команды (открыть замок, включить реле). Для sub-GHz-реплея используйте Flipper Zero или CC1101.

## Разобранный пример: перехват ключа Zigbee

1. Находим канал и PAN ID: `zbstumbler` (или сканер в Wireshark).
2. Записываем трафик: `zbdump -c 15 -w net.pcap`.
3. В Wireshark ищем `Transport Key` (join-последовательность).
4. Если TC link key дефолтный (`ZigBeeAlliance09`) — расшифровываем и извлекаем network key.
5. Вводим network key в Wireshark → читаем весь трафик, включая команды управления.

## Разобранный пример: replay Z-Wave S0

1. Zniffer записывает обмен между контроллером и устройством.
2. Находим включение/выключение и параметры nonce.
3. Восстанавливаем ключ S0 из известного постоянного nonce.
4. Формируем команду с этим ключом (через эмулятор/контроллер) и отправляем — устройство исполняет.

## Защита

- Использовать S2 в Z-Wave (отказ от S0).
- Сменять дефолтный TC link key в Zigbee (install code / out-of-band).
- Включать шифрование и аутентификацию на всех устройствах.
- Обновлять прошивки контроллеров и хабов.
- Мониторить аномальные джойны и replay.

## Правовые аспекты

Активные атаки (replay, инъекция, джойн) на чужие сети — противоправны. Все эксперименты — только на собственной сети или в рамках авторизованного пентеста.

## Частые ошибки

- **Сниффить не на том канале.** Zigbee прыгает по 16 каналам.
- **Забыть про ключ.** Без network key трафик — шифротекст.
- **Пропустить джойн.** Ключ передаётся именно при спаривании.
- **Считать S2 таким же слабым, как S0.** S2 использует ECDH.
- **Путать Zigbee и Wi-Fi.** Оба 2.4 ГГц, но разные PHY/MAC.

## Что дальше / решение

- Есть 802.15.4-сниффер → ищите джойн и дефолтный TC key.
- Z-Wave S0 → восстановите ключ из обмена.
- Z-Wave S2 → ищите другие пути (прошивка, облако).
- Смежные: `hardware-rf-protocols`, `hardware-bluetooth`, `hardware-subghz`.

## Z-Wave: топология и роли

Z-Wave — mesh-сеть: узлы ретранслируют трафик друг друга, что расширяет дальность, но и увеличивает поверхность перехвата. Роли: **primary controller** (управляет сетью), **secondary** (дублирует), **inclusion controller**. Home ID и Node ID идентифицируют сеть и узел. Перехват команд возможен на любом узле-ретрансляторе.

## Инструменты и снифферы

- **Zigbee**: CC2531/CC2652 (прошивки sniffer, Zigbee2MQTT), ApiMote + KillerBee, nRF52840 (802.15.4).
- **Z-Wave**: Silicon Labs Zniffer (UZB-7 + Zniffer firmware), Z-Stick, RTL-SDR для 908 МГц (частично).
- **Анализ**: Wireshark (диссекторы Zigbee/Z-Wave), `whsniff`.

## Zigbee: install code и out-of-band ключ

Современные Zigbee-сети (Zigbee 3.0) поддерживают **install code** — уникальный ключ устройства, передаваемый внеполосно (наклейка/QR). При джойне из install code выводится link key, и дефолтный TC key не используется. Если сеть настроена правильно, перехват джойна ключа не даёт — тогда путь лежит через прошивку или облако.

## Что даёт анализ трафика после расшифровки

С network key (Zigbee) или восстановленным ключом S0 (Z-Wave) вы видите команды управления в открытом виде: какие устройства включаются, какие состояния меняются, какие коды используются. Это позволяет не только реплеить команды, но и понять логику автоматизаций, найти скрытые функции и оценить влияние атаки.

## Итоговый чеклист Zigbee/Z-Wave

1. Определить протокол и частоту (2.4 ГГц vs sub-GHz).
2. Найти канал/PAN ID или Home ID.
3. Записать трафик сниффером (CC2531/Zniffer).
4. Найти момент джойна устройства.
5. Извлечь network key (дефолтный TC key) или восстановить S0.
6. Расшифровать в Wireshark, проанализировать команды.
7. Оценить возможность replay/инъекции.
