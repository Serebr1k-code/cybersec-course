## Вопрос, с которого всё начинается

В прошлом уроке для подбора пароля нужно было поймать WPA2-рукопожатие — а значит, дождаться подключения клиента и выкинуть его deauth-ом. Но что, если в сети **нет клиентов**? Точка доступа работает, но к ней никто не подключён. Ловить нечего. Можно ли получить материал для подбора пароля, общаясь только с точкой доступа? Оказывается, да — и это атака **PMKID**.

## Наш пример: точка без клиентов

Стенд: точка `nto-lab` (BSSID `00:11:22:33:44:55`, канал 6, WPA2-PSK). Клиентов нет. Адаптер в monitor-режиме. Нам нужно получить строку, по которой офлайн можно подобрать пароль.

## Что такое PMKID и откуда он берётся

Напомню, как WPA2 проверяет пароль. Из пароля и SSID выводится **PMK** (Pairwise Master Key) через функцию PBKDF2. Затем при подключении клиент и точка обмениваются **4-way handshake** и выводят сессионный ключ **PTK**. Именно handshake и служит материалом для офлайн-подбора: зная кадры handshake, можно перебирать пароли и проверять, сходится ли выведенный ключ.

В 2018 году исследователи обнаружили, что многие точки доступа в первом сообщении handshake отправляют **PMKID** — идентификатор, вычисленный как `HMAC-SHA1-128(PMK, "PMK Name" | AP_MAC | STA_MAC)`. Он нужен точке для **roaming** — быстрого перехода клиента между точками одной сети. Ключевое: PMKID зависит от PMK, а PMK — от пароля. Значит, получив PMKID, можно офлайн перебирать пароли: для каждого кандидата считаем PMK → PMKID и сравниваем.

Самое важное: **PMKID приходит в первом кадре RSN (EAPOL), который точка отправляет сразу**. Не нужен ни клиент, ни deauth, ни ожидание.

## Добываем PMKID: hcxdumptool

Инструмент **hcxdumptool** шлёт точке запрос ассоциации (Association Request) с RSN-элементом, провоцируя её отправить EAPOL с PMKID, и записывает результат в формате pcapng.

```
$ sudo hcxdumptool -i wlan0mon -o dump.pcapng --enable_status=1
start capturing (stop with ctrl+c)
INTERFACE:wlan0mon
...
[11:05:31] 00:11:22:33:44:55  nto-lab  PMKIDROGUE
[11:05:31] 00:11:22:33:44:55  nto-lab  EAPOL
```

Строка `PMKIDROGUE` означает, что мы получили PMKID, не имея клиента. Остановим захват (Ctrl+C). Теперь у нас `dump.pcapng`.

## Конвертируем в формат hashcat: hcxpcapngtool

Hashcat не ест pcapng напрямую. Инструмент **hcxpcapngtool** из набора hcxtools извлекает PMKID и/или handshake в текстовый формат `WPA*`.

```
$ hcxpcapngtool -o hash.22000 dump.pcapng
hcxpcapngtool 6.2.7 reading from dump.pcapng...
EAPOL pairs written to 22000 hash file (rc=0)...: 1
PMKID(s) written to 22000 hash file (rc=0): 1
$ cat hash.22000
WPA*01*4f3a1c...*001122334455*8c8590112233*6e746f2d6c6162***
```

Разберём строку формата `22000`:

- `WPA*01` — тип 01 означает **PMKID** (тип 02 — handshake).
- следующее поле — сам PMKID в hex.
- `001122334455` — MAC точки доступа.
- `8c8590112233` — MAC клиента (в PMKID-режиме тут может быть MAC из кадра).
- `6e746f2d6c6162` — SSID `nto-lab` в hex.
- пустые поля — для PMKID не нужны.

## Подбираем пароль: hashcat

Теперь офлайн. Режим hashcat для формата 22000 — `-m 22000`.

```
$ hashcat -m 22000 hash.22000 /usr/share/wordlists/rockyou.txt
hashcat (v6.2.6) starting
...
4f3a1c...:nto-lab:Sunshine2024
```

Если пароль в словаре — он найден. `-m 22000` объединяет старый PMKID-режим 16800 и handshake-режим 2500, поэтому один и тот же файл подходит для обоих типов.

Полезные флаги:

| Флаг | Смысл |
|---|---|
| `-m 22000` | формат WPA-PMKID/handshake |
| `-a 0` | атака по словарю |
| `-a 3` | брутфорс по маске |
| `-r rules/best64.rule` | правила (мутации слов) |
| `--potfile-path` | где хранить найденное |
| `--force` | игнорировать предупреждения (не рекомендуется) |

## PMKID или handshake — что выбрать

| Критерий | PMKID | Handshake |
|---|---|---|
| Нужен клиент | нет | да |
| Нужен deauth | нет | обычно да |
| Число кадров | 1 | 4 (EAPOL) |
| Поддержка точкой | не все AP | все |
| Скрытность | высокая | средняя/низкая |

PMKID быстрее и тише, но не все точки его отдают. Некоторые производители (особенно с обновлёнными прошивками) PMKID в первом EAPOL не кладут — тогда остаётся только классический handshake.

## Полный прогон от начала до конца

1. Включить монитор: `sudo airmon-ng start wlan0`.
2. Захватить PMKID: `sudo hcxdumptool -i wlan0mon -o dump.pcapng --enable_status=1`, подождать строку `PMKIDROGUE`, Ctrl+C.
3. Извлечь хеш: `hcxpcapngtool -o hash.22000 dump.pcapng`.
4. Убедиться, что в файле есть строка `WPA*01`.
5. Подобрать: `hashcat -m 22000 hash.22000 rockyou.txt`.
6. При необходимости прогнать правила: `hashcat -m 22000 hash.22000 rockyou.txt -r best64.rule`.

## Если не сработало

- **`PMKIDROGUE` не появляется.** Точка не отдаёт PMKID — переходи к захвату handshake с deauth (`hardware-wifi-deauth`).
- **`PMKID(s) written ...: 0`.** Файл пуст: либо не поймали, либо точка защищена PMF. Проверь, что адаптер действительно в monitor и на нужном канале.
- **hashcat не находит пароль.** Скорее всего, пароль вне словаря. Добавь правила или маску, но помни: офлайн-брутфорс ограничен только железом, не бойся больших списков — это разрешено и этично на своём стенде.
- **`No devices found` в hashcat.** Проверь драйвер GPU; для CPU-тестов добавь `--backend-ignore-cuda` или используй `-D 1`.

## Почему PMKID зависит от пароля: формула

Разберём формулу по частям, чтобы стало ясно, откуда берётся связь с паролем. Цепочка такая:

```
PMK  = PBKDF2-HMAC-SHA1(passphrase, ssid, 4096, 256)
PMKID = HMAC-SHA1-128(PMK, "PMK Name" | AP_MAC | STA_MAC)
```

Первая строка: **PMK** (256 бит) выводится из пароля и SSID функцией **PBKDF2** с 4096 итерациями и солью, равной SSID. Именно 4096 итераций делают офлайн-перебор «дорогим» — каждый кандидат требует заметного времени. Но он всё равно возможен: это не асимметричная криптография, а просто много хеширования.

Вторая строка: **PMKID** (128 бит) — это HMAC-SHA1 от PMK с константой `PMK Name` и двумя MAC-адресами. Значит, зная AP_MAC, STA_MAC и SSID (всё это открыто в эфире) и предполагая пароль, мы полностью воспроизводим вычисление и сравниваем результат с пойманным PMKID. Совпадение — пароль верный.

Именно поэтому PMKID годится для подбора: он — короткий «отпечаток» PMK, а PMK детерминированно зависит от пароля. В `hashcat -m 22000` эта цепочка реализована в GPU-ядре: на каждый кандидат словаря считается PBKDF2, затем HMAC и сравнение. Одна видеокарта делает миллионы таких проверок в секунду — потому PBKDF2 «всего» с 4096 итерациями не спасает слабый пароль.

## PMKID на практике: как убедиться, что он «настоящий»

Бывает, что `hcxdumptool` пишет в дамп нечто похожее, но не PMKID — например, EAPOL-кадры без нужного поля. Простой способ проверить качество:

```
$ hcxpcapngtool -o hash.22000 dump.pcapng 2>&1
Information: missing frames from 1 EAPOL handshake(s)!
EAPOL pairs written to 22000 hash file (rc=0)...: 0
PMKID(s) written to 22000 hash file (rc=0): 1
```

Если заполнена только строка `PMKID(s)`, а `EAPOL pairs` пусто — значит, handshake мы не поймали, но PMKID есть, и этого достаточно. Обратная ситуация (PMKID 0, EAPOL 1) тоже рабочая — это классический handshake. Оба случая hashcat обрабатывает одним режимом `-m 22000`.

Полезно помнить про **соль-итерации**: пароль `Sunshine2024` для SSID `nto-lab` даст совершенно другой PMK, чем для SSID `OtherNet`, даже если пароль тот же. Поэтому PMKID/хеш «привязан» к конкретной сети, и подбирать его для другой сети бессмысленно. В хеш-строке SSID хранится в hex-виде (`6e746f2d6c6162` = `nto-lab`) — hashcat сам подставляет его в PBKDF2.

## Что мы теперь знаем

- PMKID — значение, которое точка отдаёт в первом EAPOL и которое зависит от PMK, а значит, от пароля.
- PMKID можно получить **без клиента и без deauth** — только общаясь с точкой.
- `hcxdumptool` собирает PMKID, `hcxpcapngtool` конвертирует в `WPA*`-формат, `hashcat -m 22000` подбирает пароль.
- Формат 22000 единый для PMKID и handshake.
- Не все точки отдают PMKID; тогда возвращаемся к handshake.

## Частые грабли

- **Точка не отдаёт PMKID** → метод не работает, нужен клиент и рукопожатие.
- **Адаптер без injection** → ассоциационные кадры не уйдут, PMKID не придёт.
- **Забыл SSID при конвертации** → `hashcat` не стартует; добавь `-E` в `hcxpcapngtool`.
- **PMF включён** → client-less атака может не пройти; проверь защиту кадров заранее.
- **Пустой дамп** → проверь `hcxhashtool -i out.hc22000 --info=stdout`; если пусто — собирай заново.
- **Шум в эфире** → используй `--filterlist_ap`, чтобы не собирать чужие точки.

## Куда дальше

PMKID ломает WPA2-PSK, но против WPA3 он не работает: там другой механизм установления ключей. В следующем уроке `hardware-wifi-wpa3-sae` разберём SAE/Dragonfly и что утекло в атаках Dragonblood. А пока главное запомни: PMKID — это способ получить материал для подбора, не имея ни одного клиента.

## Где пригодится

- **Пентест:** быстрый захват материала для аудита стойкости пароля.
- **CTF:** задачи с `.pcapng`/`.22000` и hashcat.
- **Аудит:** проверка, отдают ли точки PMKID (маркер устаревшей прошивки).
- **Работа:** понимание roaming и RSN в корпоративных сетях.
- **Дальше по дереву:** `hardware-wifi-wpa3-sae`, `crypto-wifi-wpa`, `crypto-tool-hashcat`.
