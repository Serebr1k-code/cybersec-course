CAN (Controller Area Network) — шина, связывающая десятки электронных блоков (ECU) в автомобиле. Она не имеет аутентификации и адресации «кто есть кто»: любой участник может отправить кадр с любым ID. Это делает CAN-шину классическим объектом атак. Урок — практическое введение в автомобильную безопасность.

## Теория

CAN — дифференциальная двухпроводная шина (CAN-High, CAN-Low), скорость обычно 125/250/500 кбит/с. Кадр состоит из:

| Поле | Назначение |
|------|-----------|
| ID (11 или 29 бит) | идентификатор сообщения; младший ID = выше приоритет |
| DLC | длина данных (0–8 байт) |
| Data | до 8 байт полезной нагрузки |
| CRC | контрольная сумма |

Ключевые свойства:
- **Broadcast + arbitration** — все видят всё; приоритет по ID (низкий ID выигрывает арбитраж).
- **Нет аутентификации** — любой узел может подделать любой кадр.
- **Нет шифрования** — данные в открытом виде.
- **Один сбойный узел** может «залить» шину (bus-off).

Популярные ID и назначение (зависят от авто): ID `0x0C9` — обороты, `0x1A0` — двери, `0x0C5` — скорость, `0x0A0` — мультимедиа. Разбор сигналов (DBC) описывает, какие биты что значат.

**OBD-II** — обязательный диагностический порт (разъём J1962, часто под рулём), даёт доступ к CAN. Через него — диагностика, но часто и к «приводным» шинам.

## Инструменты и команды

- **CAN-адаптер**: USB2CAN, CANable, Macchina M2, PEAK PCAN.
- **Linux SocketCAN** — встроенный CAN-стек.
- **can-utils**: `candump`, `cansend`, `cangen`, `cansniffer`.
- **python-can** + `cantools` (работа с DBC).
- **Wireshark** — визуализация CAN (SocketCAN/PCAP).
- **SavvyCAN** — анализ и реверс сигналов.

```bash
# Поднять интерфейс (CANable = slcan)
sudo slcand -o -s8 -t hw -S 3000000 /dev/ttyACM0
sudo ip link set up slcan0
# или для CANable в candlelight-режиме
sudo ip link set can0 up type can bitrate 500000

# Слушать шину
candump can0
# Отправить кадр
cansend can0 0C9#0000000000000000
# Показывать только изменения (sniffer)
cansniffer can0
# Генерировать трафик (фаззинг)
cangen can0 -g 10 -I 0C9 -D i

# Записать в файл и открыть в Wireshark
candump -l can0        # candump-*.log
```

## Разобранный пример: открытие дверей и анализ сигналов

**Дано:** автомобиль, CAN-адаптер подключён к OBD-II. Нужно понять, какие кадры управляют замками (в рамках авторизованного теста на своём авто).

**Шаг 1 — поднять шину.** Определяем скорость (обычно 500 кбит/с для CAN, 125 для комфорт-шины). `ip link set can0 up type can bitrate 500000`.

**Шаг 2 — пассивное наблюдение.** `candump can0` — видим поток. `cansniffer can0` группирует по ID и показывает меняющиеся байты.

**Шаг 3 — корреляция.** Нажимаем «закрыть двери» на ключе и смотрим, какой ID и какой байт меняется синхронно. Так находим кадр замков.

**Шаг 4 — воспроизведение.** Отправляем найденный кадр: `cansend can0 1A0#0000000000000001`. Смотрим реакцию (в контролируемых условиях!).

**Шаг 5 — разбор DBC.** Загружаем DBC-файл в SavvyCAN/cantools, чтобы интерпретировать биты как физические величины (скорость, обороты, угол руля).

```python
import can, cantools
db = cantools.database.load_file('vehicle.dbc')
bus = can.interface.Bus('can0', bustype='socketcan')
for msg in bus:
    try:
        decoded = db.decode_message(msg.arbitration_id, msg.data)
        print(decoded)
    except Exception:
        pass
```

**Шаг 6 — поиск уязвимостей.** Проверяем: принимает ли шина команды без проверки состояния (двери на скорости), есть ли диагностические режимы, доступные без авторизации, можно ли отключить тормоза/руль подделкой кадра (демонстрация в симуляторе).

## Частые ошибки

- **Неверная скорость шины.** 500 кбит/с вместо 125 = мусор и ошибки шины. Определяйте скорость.
- **Отправка вслепую.** Случайный `cansend` может сломать состояние ECU. Сначала только слушайте.
- **Отсутствие терминатора.** CAN требует 120 Ом на концах; без них — ошибки.
- **Подключение к приводной шине напрямую.** Это опасно (тормоза, руль). Работайте на стенде/симуляторе.
- **Игнорирование bus-off.** Слишком активная отправка уводит узел в bus-off. Дозируйте.
- **Правовые рамки.** Вмешательство в чужой автомобиль — преступление. Только своё авто/стенд.

## CAN: кадры и арбитраж

CAN-кадр: ID (11 или 29 бит), DLC (длина), данные (до 8 байт), CRC. Арбитраж — по ID (меньший ID = выше приоритет). Нет аутентификации: любой узел может отправлять любые ID. Поэтому подделка кадра с нужным ID управляет устройством. Скорость: 125/250/500 кбит, 1 Мбит.

## Инструменты

```bash
ip link set can0 up type can bitrate 500000
candump can0                    # слушать шину
candump -l can0                 # логировать в файл
cansend can0 123#DEADBEEF       # отправить кадр
cangen can0 -g 10               # генерировать нагрузку
canplayer -I log.txt            # воспроизвести лог
# анализ: SavvyCAN, can-utils, Caring Caribou
```

## Разобранный пример 2: анализ и подделка

1. `candump can0` → наблюдаем поток кадров.
2. Находим кадры, меняющиеся при действиях (открытие двери).
3. Фиксируем ID и данные при открытии.
4. `cansend` тот же кадр → дверь открывается.
5. Проверяем на своём авто/стенде.

## Защита

- Gateway/сегментация шин (не всё на одной CAN).
- Message authentication (CAN-FD + SecOC).
- Мониторинг аномалий (IDS для CAN).
- Ограничение диагностического доступа.

## CAN-FD и SecOC

CAN-FD расширяет данные до 64 байт и повышает скорость, но не добавляет безопасности. SecOC (Secure Onboard Communication) добавляет MAC и свежесть (freshness) к кадрам — это защита от подделки и replay. Без SecOC любой узел может отправлять произвольные ID. При аудите определите: используется ли SecOC, есть ли gateway-сегментация, логируются ли аномалии. Для атакующего SecOC усложняет подделку, но ошибки в реализации (слабые ключи, отсутствие freshness) всё равно оставляют вектор. Проверьте также диагностические сервисы (UDS) — они часто обходят защиту шин.

## Итог

CAN не имеет аутентификации: подделка кадра управляет устройством. SecOC и gateway-сегментация — основные меры защиты. Начинайте с `candump`, находите кадры нужных действий и воспроизводите их на своём стенде. Помните о безопасности: не вмешивайтесь в системы чужих автомобилей.
