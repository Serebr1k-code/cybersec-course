Электромагнитный (EM) side-channel — бесконтактный аналог атаки по потреблению: катушка рядом с чипом ловит излучение, порождённое переключениями транзисторов. Эти утечки коррелируют с обрабатываемыми данными и ключом, что позволяет восстановить AES/RSA-ключ без вскрытия. Урок — продолжение `hardware-sidechannel`.

## Теория

Каждое переключение логического вентиля создаёт импульс тока и, следовательно, ЭМ-поле. Суммарная утечка зависит от:
- данных на шинах (значение байта),
- операции (S-box AES, умножение RSA),
- кода Хэмминга/веса Хэмминга значения.

Классы атак:

| Атака | Идея | Сложность |
|-------|------|-----------|
| SPA (Simple) | визуально различить операции по форме | низкая |
| DPA (Differential) | статистика по множеству трейсов, разделённых по гипотезе о бите ключа | средняя |
| CPA (Correlation) | корреляция Пирсона между утечкой и моделью Хэмминга | средняя |
| Template | обучаем профиль на известном ключе, атакуем неизвестный | высокая |
| MIA (Mutual Info) | взаимная информация вместо корреляции | высокая |

Модель утечки для AES: промежуточное значение = `Sbox[plaintext ^ key]`; для каждого байта ключа строится гипотеза, вычисляется вес Хэмминга, ищется максимум корреляции с трейсом. Правильная гипотеза даёт заметный пик.

## Инструменты и команды

- **ChipWhisperer** + EM-щуп (H-field/L-field probe) — захват ЭМ-трейсов.
- **Riscure Inspector / eShard esDynamic** — коммерческие платформы.
- **Python: numpy, scipy** — корреляционный анализ.
- **scared / lascar** — открытые библиотеки для side-channel анализа.

```bash
pip install chipwhisperer numpy scipy

# Захват трейсов: чип AES шифрует случайные plaintext под ключом
python - <<'PY'
import chipwhisperer as cw
import numpy as np
scope = cw.scope(); scope.default_setup()
target = cw.target(scope)
N = 5000
traces = np.zeros((N, scope.adc.samples))
texts  = []
for i in range(N):
    pt = np.random.bytes(16)
    texts.append(pt)
    scope.arm(); target.write(pt)
    traces[i] = scope.get_last_trace()
np.save('traces.npy', traces)
np.save('texts.npy', np.frombuffer(b''.join(texts), dtype=np.uint8).reshape(-1,16))
PY

# CPA-анализ первого байта ключа AES
python - <<'PY'
import numpy as np
from chipwhisperer.analyzer.attacks.models.AES128_8bit import AES128_8bit, SBox_output
traces = np.load('traces.npy'); texts = np.load('texts.npy')
model = AES128_8bit(SBox_output)
best = []
for kg in range(256):
    hw = np.array([bin(int(model.leak(texts[i,0], kg))).count('1') for i in range(len(texts))], dtype=float)
    hw -= hw.mean()
    tr = traces - traces.mean(axis=0)
    corr = (hw @ tr) / (np.linalg.norm(hw) * np.linalg.norm(tr, axis=0))
    best.append(np.max(np.abs(corr)))
print('K[0] =', int(np.argmax(best)))
PY
```

## Разобранный пример: восстановление AES-ключа смарт-карты

**Дано:** смарт-карта выполняет AES-128 с секретным ключом, есть EM-щуп и ChipWhisperer.

**Шаг 1 — навести щуп.** Подносим катушку над областью крипто-ядра (по даташиту или методом тыка). Оптимизируем позицию по амплитуде сигнала.

**Шаг 2 — синхронизация.** Триггер по началу команды шифрования (например, приёму APDU). Захватываем окно, где происходит AES-round.

**Шаг 3 — сбор трейсов.** 5–50 тыс. трейсов со случайными plaintext. Качество трейсов критично: шум убивает DPA.

**Шаг 4 — CPA.** Для каждого байта ключа строим модель `SBox[p ^ k]`, считаем корреляцию со всеми точками трейса. Правильная гипотеза даёт пик, выделяющийся над шумом.

**Шаг 5 — извлекаем байты.** Повторяем для 16 байт. Если пик нечёткий — увеличиваем число трейсов, улучшаем позиционирование щупа, применяем выравнивание (alignment) и фильтрацию.

**Шаг 6 — верификация.** Проверяем найденный ключ: расшифровываем известный ciphertext. Совпало — успех.

## Частые ошибки

- **Мало трейсов.** DPA/CPA требуют статистики: тысячи трейсов. 100 — мало.
- **Плохое позиционирование щупа.** Даже миллиметр в сторону = потеря сигнала. Пробуйте разные позиции.
- **Не выровнены трейсы.** Джиттер во времени размывает корреляцию. Применяйте alignment (например, по пику триггера).
- **Неверная модель утечки.** Для одной реализации лучше работает вес Хэмминга, для другой — значение. Пробуйте обе.
- **Игнорирование защиты.** Маскирование и рандомизация времени ломают простой CPA. Нужны higher-order атаки.
- **Правовые рамки.** Атака на чужие карты/устройства (банки, транспорт) — преступление.

## SPA против DPA

| Метод | Принцип | Что восстанавливает |
|-------|---------|---------------------|
| SPA (Simple) | визуальный анализ трасс | утечки по ветвлению/операциям |
| DPA (Differential) | статистика по многим трассам | ключ по корреляции |
| CPA (Correlation) | корреляция с моделью потребления | AES/DES ключ |
| Template | обучение на эталоне | ключ на похожих устройствах |

SPA смотрит на одну трассу (видны операции умножения/возведения), DPA/CPA усредняют тысячи трасс и коррелируют с гипотезами ключа.

## CPA детали

1. Соберите N трасс (обычно 5000-50000) с известными входными данными.
2. Для каждого байта ключа вычислите гипотетические промежуточные значения S-box.
3. Смоделируйте потребление (Hamming weight).
4. Вычислите корреляцию Пирсона между моделью и трассами.
5. Максимум корреляции → правильный байт ключа.

## Практика

Соберите трассы с учебной платформы (ChipWhisperer target), проведите CPA-атаку на AES и восстановите ключ. Оцените, сколько трасс нужно. Это классическая лабораторная по side-channel.

## Электромагнитные (EM) атаки

EM-атаки снимают эмиссии рядом с чипом без электрического контакта. Плюс: не нужно подключаться к питанию, можно атаковать запечатанные устройства. Минус: нужна точная позиция зонда и дорогое оборудование (Langer/EM-зонды). EMFI (Electromagnetic Fault Injection) — импульс создаёт сбой (fault), обходящий проверки. Применение: обход PIN, извлечение ключей, обход secure boot. Для пентеста EM-атаки требуют лабораторных условий; чаще начинают с power-analysis (ChipWhisperer), где порог входа ниже. В любом случае: сначала убедитесь, что уязвимость реальна (SPA), затем применяйте статистику (DPA/CPA).

## Итог

Side-channel (SPA/DPA/CPA) и EM-атаки восстанавливают секреты по физическим утечкам, а fault injection (glitching/EMFI) обходит проверки. Порог входа ниже у power-analysis (ChipWhisperer). Всегда начинайте с подтверждения утечки (SPA), затем применяйте статистику. Для защиты — маскирование, случайные задержки, сенсоры.
