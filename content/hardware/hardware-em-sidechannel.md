## Вопрос, с которого всё начинается

В прошлом уроке мы измеряли потребление чипа через шунт в цепи питания — для этого нужен электрический контакт. Но что если подключиться к питанию нельзя, а устройство залито компаундом? Тогда на помощь приходит **электромагнитный side-channel**: катушка рядом с чипом ловит излучение от переключений транзисторов.

Вопрос урока: как по излучению чипа восстановить ключ AES и чем это отличается от анализа потребления?

## Наш пример: смарт-карта с AES

Перед нами смарт-карта, выполняющая AES-128 с секретным ключом. Мы подаём ей команды шифрования и хотим узнать ключ. Есть EM-щуп и ChipWhisperer.

## Шаг 1: откуда берётся утечка

Каждое переключение логического вентиля создаёт импульс тока и, значит, электромагнитное поле. Суммарная утечка зависит от:

- данных на шинах (значение байта),
- операции (S-box в AES, умножение в RSA),
- веса Хэмминга значения (числа единичных бит).

Именно эта зависимость и позволяет восстановить ключ. Причём EM-канал часто «чище» power: катушка ловит активность конкретного блока, а не суммарный ток всего чипа.

## Шаг 2: классы атак

| Атака | Идея | Сложность |
|-------|------|-----------|
| SPA (Simple) | визуально различить операции по форме | низкая |
| DPA (Differential) | статистика по множеству трейсов, разделённых по гипотезе о бите ключа | средняя |
| CPA (Correlation) | корреляция Пирсона между утечкой и моделью | средняя |
| Template | профиль на известном ключе → атака на неизвестный | высокая |

Модель утечки для AES: промежуточное значение = `Sbox[plaintext ^ key]`. Для каждого байта ключа строится гипотеза, вычисляется вес Хэмминга и ищется максимум корреляции с трейсом. Правильная гипотеза даёт заметный пик.

## Шаг 3: наводим щуп

Подносим катушку над областью криптоядра (по даташиту или методом тыка). Оптимизируем позицию по амплитуде сигнала: даже миллиметр в сторону — потеря. Дальше настраиваем триггер по началу команды шифрования (например, приёму APDU).

## Шаг 4: собираем трейсы

Захватываем 5–50 тысяч трейсов со случайными открытыми текстами:

```python
import chipwhisperer as cw
import numpy as np
scope = cw.scope(); scope.default_setup()
target = cw.target(scope)
N = 5000
traces = np.zeros((N, scope.adc.samples))
texts = []
for i in range(N):
    pt = np.random.bytes(16)
    texts.append(pt)
    scope.arm(); target.write(pt)
    traces[i] = scope.get_last_trace()
np.save('traces.npy', traces)
```

Качество трейсов критично: шум убивает DPA.

## Шаг 5: CPA на первом байте

Для каждого кандидата байта ключа (0–255) строим модель `SBox[p ^ k]`, считаем корреляцию со всеми точками трейса:

```python
import numpy as np
from chipwhisperer.analyzer.attacks.models.AES128_8bit import AES128_8bit, SBox_output
traces = np.load('traces.npy'); texts = np.load('texts.npy')
model = AES128_8bit(SBox_output)
best = []
for kg in range(256):
    hw = np.array([bin(int(model.leak(texts[i,0], kg))).count('1') for i in range(len(texts))], dtype=float)
    hw -= hw.mean()
    tr = traces - traces.mean(axis=0)
    corr = (hw @ tr) / (np.linalg.norm(hw) * np.linalg.norm(tr, axis=0))
    best.append(np.max(np.abs(corr)))
print('K[0] =', int(np.argmax(best)))
```

Правильная гипотеза даёт пик, выделяющийся над шумом. Повторяем для всех 16 байт, затем проверяем ключ на расшифровке известного шифротекста.

## Шаг 6: если пик нечёткий

- Увеличиваем число трейсов.
- Улучшаем позиционирование щупа.
- Применяем **выравнивание** (alignment) — джиттер во времени размывает корреляцию.
- Пробуем другую модель утечки (вес Хэмминга против значения).

## Шаг 7: SPA, DPA и CPA — в чём разница

| Метод | Принцип | Что восстанавливает |
|-------|---------|---------------------|
| SPA | визуальный анализ одной трассы | утечки по ветвлению/операциям |
| DPA | статистика по многим трассам | ключ по корреляции |
| CPA | корреляция с моделью | ключ AES/DES |

SPA смотрит на одну трассу (видны операции умножения/возведения), DPA/CPA усредняют тысячи трасс и коррелируют с гипотезами ключа. Начинайте с SPA: если утечка вообще есть, она видна глазами.

## Шаг 8: EM против power и защита

EM выигрывает тем, что **бесконтактный и локальный**: маленькая катушка над конкретным блоком «слушает» именно его, обходя шум других блоков и иногда защиты от power-атак. Минус — нужен малошумящий усилитель и точное позиционирование (дороже).

Помните про **SNR**: снижение шума (экранирование, фильтры, усреднение) улучшает атаку быстрее любой хитрой математики.

**EMFI** (Electromagnetic Fault Injection) — обратная сторона: импульс поля создаёт **сбой** (fault), обходящий проверки. Применение: обход PIN, извлечение ключей, обход secure boot.

Защиты: **маскирование** (секрет разбивается на доли), рандомизация времени, балансировка потребления, датчики аномалий.

Практический совет: прежде чем вкладываться в дорогое EM-оборудование, подтвердите утечку на power-analysis (ChipWhisperer) — там порог входа ниже. И только когда цель запечатана и контакт к питанию невозможен, переходите к EM-щупу. Начинайте с SPA (визуально видно, есть ли утечка), затем применяйте статистику (DPA/CPA). Помните: EM-атака требует лабораторных условий и терпения — результат приходит не сразу.

## Что мы теперь знаем

1. EM-атака бесконтактна: катушка ловит излучение от переключений транзисторов.2. SPA — одна трасса; DPA/CPA — статистика по тысячам с гипотезами о ключе.
3. Модель для AES — вес Хэмминга выхода S-box.
4. Позиционирование щупа и выравнивание трейсов критичны.
5. EM локальнее power: можно «слушать» конкретный блок чипа.
6. EMFI — тот же принцип, но для внесения сбоев, а не для съёма утечки.

## На что смотреть дальше

- **Мало трейсов.** DPA/CPA требуют тысяч; 100 — мало.
- **Плохое позиционирование щупа.** Даже миллиметр в сторону = потеря сигнала.
- **Не выровнены трейсы.** Джиттер размывает корреляцию — применяйте alignment.
- **Неверная модель утечки.** Для одной реализации работает вес Хэмминга, для другой — значение; пробуйте обе.
- **Игнорирование защиты.** Маскирование ломает простой CPA — нужны higher-order атаки.
- **Правовые рамки.** Атака на чужие карты/устройства — преступление.

## Куда дальше

Мы прошли side-channel от потребления до излучения. Дальше по дереву нас ждут логический анализ шин и автомобильные протоколы. А пока главное: **секрет «протекает» не только через провода питания, но и через воздух вокруг чипа.**

## Где пригодится

- **CTF:** Hardware/Crypto-задачи с восстановлением ключа по утечке.
- **Аппаратная безопасность:** оценка стойкости смарт-карт, TPM, Secure Element.
- **Пентест:** анализ устройств с секретами в железе.
- **Работа:** сертификация Common Criteria / EMVCo, аудит крипточипов.
- **Дальше по дереву:** `hardware-fault-injection`, `hardware-crypto`.
