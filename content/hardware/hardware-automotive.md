Современный автомобиль — это десятки электронных блоков управления (ECU), соединённых шинами CAN, LIN, FlexRay и Ethernet. Безопасность в них проектировалась под надёжность, а не под защиту от атак: в CAN нет аутентификации, сообщения широковещательны, а критичные функции (тормоза, руль, двигатель) доступны по шине. Это делает автомобиль классическим объектом hardware-пентеста. Этот урок — обзор архитектуры и векторов атак.

## Архитектура автомобиля

Внутри машины несколько сетей:

- **CAN** (Controller Area Network) — основная шина для силового агрегата и кузова.
- **LIN** — дешёвая однопроводная шина для простых устройств (стеклоподъёмники, датчики).
- **FlexRay** — высокоскоростная шина для критичных систем (шасси, подвеска).
- **MOST** — мультимедиа.
- **Automotive Ethernet** — новые системы (ADAS, камеры).

Сети соединены **шлюзом (gateway)**, который фильтрует сообщения между доменами. Взлом одного ECU часто даёт доступ к другим через шлюз.

## CAN-шина

CAN — дифференциальная двухпроводная шина (CAN-H, CAN-L) со скоростями 125 кбит/с – 1 Мбит/с. Кадр содержит **ID** (приоритет) и до 8 байт данных. Аутентификации нет: любой узел может послать кадр с любым ID, а приоритет определяется ID (меньше = важнее). Это даёт две базовые атаки: **spoofing** (подделать чужой ID) и **DoS** (залить шину кадрами с высоким приоритетом, «заглушив» остальных).

```bash
# Захват CAN через can-utils
sudo ip link set can0 up type can bitrate 500000
candump can0
# Отправка кадра
cansend can0 123#DEADBEEF
```

## OBD-II: дверь к шине

**OBD-II** — стандартизированный диагностический разъём (обычно под рулём). Через него доступны CAN-шины автомобиля и диагностические сервисы. Именно поэтому OBD-II — самый удобный порт для подключения: любой адаптер ELM327 за 10 долларов даёт доступ к CAN.

```bash
# Чтение кодов ошибок (DTC) через ELM327 (пример через python-OBD)
python3 -c "
import obd
c = obd.OBD()
print(c.query(obd.commands.GET_DTC))
"
```

## ECU и диагностика UDS

**UDS (ISO 14229)** — протокол диагностики поверх CAN. Он поддерживает сервисы: чтение данных, запись, прошивка, сброс. Ключевой сервис — **Security Access**: перед критичными операциями ECU требует «разблокировки» (seed/key). Слабая реализация (предсказуемый ключ, утечка алгоритма) позволяет разблокировать ECU и перепрошить его.

```text
# Пример UDS-сессии
10 03          # переход в extended session
27 01          # запрос seed
27 02 <key>    # отправка ключа
2E <did> <data># запись данных
```

Разблокировка ECU открывает путь к изменению поведения автомобиля и установке модифицированных прошивок.

## Телематика и TCU

Современные машины подключены к интернету через **TCU (Telematics Control Unit)**. Это отдельный компьютер с сотовым модемом, GPS и доступом к CAN. Атаки на TCU — через сотовую сеть, Wi-Fi, Bluetooth и обновления «по воздуху» (OTA). Ошибки в TCU (слабые пароли, отладочные порты, небезопасные OTA) дают удалённый доступ к шине автомобиля.

## Keyless entry и иммобилайзеры

- **Relay attack** — ретрансляция сигнала ключа от машины к ключу в доме, чтобы открыть и завести.
- **Rolling code** — защита от replay; обходится **RollJam** (глушение + захват).
- **Иммобилайзер** — связь ключа и ECU; обход через разблокировку ECU или клонирование ключа.
- **CAN injection** — подключение к шине и имитация сообщений о наличии ключа.

Эти атаки требуют физического доступа к машине и часто — к ключу, но демонстрируют слабость беспроводной защиты.

## Разобранный пример: анализ CAN и поиск сообщений

```bash
# 1. Поднять интерфейс
sudo ip link set can0 up type can bitrate 500000
# 2. Записать трафик при нажатии кнопок
candump -L can0 > can.log &   # запись в лог
sleep 30
kill %1
# 3. Найти сообщения, меняющиеся при действии
grep '7E0' can.log | head     # диагностические ID
sort can.log | uniq -c | sort -rn | head   # частые ID
# 4. Воспроизвести конкретный кадр
cansend can0 2F0#0102030405060708
```

Сопоставляя действия (открыть дверь, включить фары) с изменениями в логе, находят «команды» и воспроизводят их.

## Правовые аспекты

Исследование автомобилей строго регулируется. Работать можно **только** со своим автомобилем или в рамках согласованного пентеста/CTF. Вмешательство в CAN-шину чужой машины, обход иммобилайзера, «ретрансляция» ключей — это уголовно наказуемые действия. Многие исследования публикуются только после согласования с производителем (responsible disclosure). Всегда фиксируйте scope и не выезжайте на дороги общего пользования с модифицированной шиной.

## Частые ошибки и подводные камни

- **Неверный bitrate**: CAN не «заведётся» — перебирайте 125/250/500 кбит/с.
- **Ошибки шины (Bus-Off)**: при конфликтах узел отключается.
- **Терминаторы 120 Ом**: без них сигнал искажается.
- **Запись без разметки**: логи большие, нужен фильтр по ID.
- **Шлюз блокирует диагностику**: некоторые операции требуют «диагностической» сессии.

## ADAS, Automotive Ethernet и новые шины

Современные автомобили добавляют **ADAS** (камеры, радары, лидары) и **Automotive Ethernet** (100BASE-T1/1000BASE-T1). Это меняет поверхность атаки:

- **Камеры и радары** — можно спуфить изображения/сигналы (классические демонстрации «невидимых» объектов).
- **Ethernet-домены** — те же уязвимости, что в IT (ARP spoofing, DoS), но с физическим доступом.
- **ADAS-ECU** — сложные процессоры, часто на Linux/QNX, с большим кодом.
- **Обновления OTA** — новый канал атаки (подмена сервера, слабая проверка подписи).

Изучение ADAS требует больше софтовых навыков (реверс, сети), но это направление растёт.

## Практический стенд (ICSim)

**ICSim (Instrument Cluster Simulator)** — открытый симулятор автомобиля для обучения CAN-атакам. Он эмулирует приборную панель и две CAN-шины.

```bash
# Сборка и запуск (упрощённо)
git clone https://github.com/zombieCraig/ICSim
cd ICSim && make
./icsim can0        # приборная панель
./controls can0     # «пульт» для управления (двери, свет, поворотники)
# Наблюдение за CAN
candump can0 | head
```

Стенд позволяет безопасно отрабатывать: перехват команд, спуфинг, DoS, реверс ID. Это лучший способ подготовиться к работе с реальным авто.

## Защита автомобильных систем

- **Сегментация** шин и шлюз с фильтрацией по ID.
- **IDS/IPS для CAN** — обнаружение аномальной частоты и неизвестных ID.
- **Secure gateway** между телематикой и CAN.
- **Подписанные OTA** и защищённая загрузка.
- **Аппаратная защита** диагностического порта.
- **Мониторинг keyless** (relay detection).

Для пентестера понимание защит помогает сформулировать рекомендации: где сегментация, где нужен шлюз, какие ID фильтровать.

## Инструменты и лаборатория

Минимальный набор для automotive-пентеста:

- **CAN-адаптер** (CANtact, USB2CAN, Macchina M2).
- **can-utils + SocketCAN** — базовый софт.
- **SavvyCAN** — GUI для анализа CAN.
- **ICSim** — симулятор для обучения.
- **SDR** (RTL-SDR/HackRF) — keyless и телеметрия.
- **OBD-II адаптер** — доступ к диагностике.

Лаборатория должна включать **изолированную шину** (не реальный автомобиль) для отработки спуфинга и DoS. Реальный автомобиль — только в согласованном тесте и без выезда на дороги.

## Карьера и направления

Автомобильная безопасность — быстро растущая область:

- **OEM-исследования**: тестирование машин и телематики.
- **Tier-1/Tier-2**: аудит компонентов (ECU, TCU, ADAS).
- **Standards/Regulation**: UN R155/R156, ISO 21434.
- **Bug bounty**: программы производителей.

Навыки: CAN, UDS, реверс прошивок, SDR, сети. Начните с ICSim и своего авто, затем — согласованные пентесты.

## Итог

Автомобиль — распределённая система без аутентификации на шинах. Понимая CAN, OBD-II, UDS и телематику, вы можете оценить поверхность атаки и продемонстрировать риски — от спуфинга кадров до доступа через TCU. Работайте в лаборатории и в рамках согласованного теста.
