## Вопрос, с которого всё начинается

Ты уже умеешь записать сигнал пульта в IQ-файл и даже разобрать его в inspectrum. Но `rtl_433` протокол не знает, а руками измерять каждый импульс долго. Хочется собрать **свой** обработчик: чтобы сигнал сам демодулировался и превращался в биты. Для этого и существует GNU Radio — конструктор конвейеров обработки сигналов.

## Что такое GNU Radio и flowgraph

**GNU Radio** — фреймворк цифровой обработки сигналов, на котором построено большинство продвинутых SDR-инструментов. Ты соединяешь **блоки** (источник, фильтр, демодулятор, сток) в **граф** — **flowgraph**, и GNU Radio выполняет его в реальном времени. **GNU Radio Companion (GRC)** — визуальный редактор таких графов.

Ключевые понятия:

- **Block** — элементарная операция (фильтр, демодулятор, источник, сток).
- **Flowgraph** — граф соединённых блоков.
- **Stream** — поток данных между блоками (complex/float/int/byte).
- **Source/Sink** — вход и выход (SDR-устройство, файл, звуковая карта).

Данные текут от источника к стоку; каждый блок обрабатывает поток и передаёт дальше.

## Наш пример: декодируем OOK-пульт

Возьмём наш неизвестный пульт с 433.92 МГц, который передаёт **OOK** (несущая включается и выключается). Задача — собрать граф, который превратит эфир в поток нулей и единиц, а затем декодирует биты.

## Шаг 1: запускаем GRC и собираем граф

```bash
gnuradio-companion   # запуск GRC
```

Сначала соберём простой FM-приёмник, чтобы понять механику: `RTL-SDR Source` → `Rational Resampler` → `WBFM Receive` → `Audio Sink`. Соединяем порты, задаём параметры (частота, sample rate), жмём «Run» (F6) — и слышим радио. Ключевые параметры блока: тип данных (`Complex`, `Float`), `samp_rate`, центральная частота, усиление.

## Шаг 2: понимаем типы данных

Самая частая причина «тишины» — несовпадение типов или sample rate. Сигнал с SDR приходит как `Complex`. Чтобы получить амплитуду, его прогоняют через `complex_to_mag` (модуль комплексного числа). Если блок ждёт `Float`, а получает `Complex` — граф не запустится. Переход между блоками с разной частотой дискретизации делается через `Rational Resampler`.

## Шаг 3: конвейер для OOK

Для OOK нужен не демодулятор FM, а цепочка «амплитуда → порог → биты»:

```
RTL-SDR Source (Complex) -> complex_to_mag (Float) -> threshold_ff (0/1) -> File Sink
```

`threshold_ff(0.05, 0.05)` — блок-порог: всё выше порога становится «1», ниже — «0». Порог надо подбирать под сигнал: слишком высокий — теряем слабые импульсы, слишком низкий — ловим шум. Полученный поток нулей и единиц пишется в файл и разбирается скриптом: измеряются длительности импульсов, определяется кодирование (PWM/PPM) и декодируются биты.

## Шаг 4: синхронизация для цифровых протоколов

Цифровой сигнал приходит «смазанным»: нет точного момента начала символа, частота приёмника чуть отличается от передатчика. Поэтому в конвейер добавляют два этапа синхронизации:

- **Clock recovery** (восстановление такта) — определяет моменты, когда считывать символы (`Clock Recovery MM`, `Symbol Sync`).
- **Frame sync** (синхронизация кадра) — находит начало пакета по корреляционной преамбуле (`Correlate Access Code`).

Типовой конвейер для FSK-протокола: `Quadrature Demod` → `Clock Recovery MM` → `Binary Slicer` → `Correlate Access Code` → `Packet Decoder`. Параметры (omega, gain mu, mu) подбираются под скорость символов; неверные значения дают «плавающие» биты. Иногда проще оцифровать сигнал в 0/1 и разобрать его в URH, где синхронизация настраивается интерактивно.

## Полезные блоки

| Блок | Назначение |
|------|-----------|
| RTL-SDR Source | источник с донгла |
| File Source/Sink | чтение/запись IQ |
| Frequency Xlating FIR Filter | перенос и фильтрация |
| Rational Resampler | пересэмплирование |
| Quadrature Demod | FM-демодуляция |
| Binary Slicer | оцифровка в 0/1 |
| Clock Recovery MM | восстановление такта |
| Correlate Access Code | поиск преамбулы |
| Constellation Decoder | демодуляция символов |
| Packet Decoder | сборка пакетов |

## Тот же граф на Python

Граф можно построить и кодом — удобно для автоматизации:

```python
from gnuradio import gr, blocks, analog, filter
import osmosdr

class OOK(gr.top_block):
    def __init__(self):
        gr.top_block.__init__(self, "OOK")
        self.src = osmosdr.source(args="rtl=0")
        self.src.set_sample_rate(1e6)
        self.src.set_center_freq(433.92e6)
        self.src.set_gain(40)
        self.mag = blocks.complex_to_mag(1)      # амплитуда
        self.thr = blocks.threshold_ff(0.05, 0.05)  # порог -> 0/1
        self.sink = blocks.file_sink(gr.sizeof_float, "/tmp/ook.bin", False)
        self.connect(self.src, self.mag, self.thr, self.sink)

OOK().run()
```

Так SDR-обработку встраивают в свои скрипты: параметризовать частоту и усиление через переменные GRC и менять их из командной строки.

## Производительность

GNU Radio чувствителен к нагрузке CPU. Если видишь `O` (overflow) в консоли — поток не успевает обрабатываться. Способы исправить: уменьшить `sample_rate` и полосу, использовать эффективные блоки (FIR вместо произвольной свёртки), писать IQ в файл и обрабатывать офлайн. Для долгих записей лучше писать IQ «как есть» и анализировать позже: так данные не теряются при перегрузке, и по одному файлу можно прогонять разные конвейеры.

## Экосистема расширений

GNU Radio расширяется через out-of-tree (OOT) модули: `gr-osmosdr` (драйверы SDR), `gr-satellites` (спутники), `gr-ieee802-11` (Wi-Fi), `gr-gsm` (GSM). Многие готовые декодеры собраны именно так — ставишь модуль и используешь блоки в GRC. Установка OOT-модуля обычно сводится к сборке из исходников:

```bash
git clone https://github.com/.../gr-xxx
cd gr-xxx && mkdir build && cd build
cmake .. && make -j8 && sudo make install && sudo ldconfig
```

Для пентеста особенно полезны `gr-gsm` (перехват GSM) и `gr-ieee802-11` (Wi-Fi PHY). Если нужного протокола нет, всегда можно собрать свой конвейер из блоков DSP — именно так появляются декодеры для экзотических датчиков и телеметрии.

## Если не сработало

- **Несовпадение sample rate.** Нужен ресемплер при переходе между блоками.
- **Overflow (`O`).** CPU не успевает — уменьшите полосу.
- **Нет сигнала.** Проверьте центр частоты, gain, антенну.
- **Типы данных.** `complex → float` через `complex_to_mag`/`complex_to_arg`.
- **Плавающий порог.** Для OOK порог подбирается под сигнал.

## Что мы теперь знаем

1. GNU Radio — конструктор конвейеров обработки; GRC — визуальный редактор.
2. Данные текут от источника к стоку через блоки, и типы должны совпадать.
3. OOK декодируется как «амплитуда → порог → биты».
4. Цифровые протоколы требуют восстановления такта и синхронизации кадра.
5. Overflow лечится снижением полосы или офлайн-обработкой.

## Куда дальше

Мы собрали свой конвейер обработки — теперь сигнал превращается в биты программно, а не руками. Дальше эти умения пригодятся при разборе конкретных протоколов: BLE и Zigbee (`hardware-bluetooth`, `hardware-zigbee-zwave`), а для воспроизведения сигнала понадобится TX-SDR (`hardware-subghz`). А пока главное запомни: GNU Radio — это граф «источник → обработка → сток», и типы данных в нём должны совпадать.

- **CTF:** Radio-задачи с нестандартными сигналами.
