Многие IoT-устройства управляются по радио: пульты ворот, датчики, умные замки, BLE-трекеры. Радиоканал — это «невидимый» интерфейс, который часто не защищён: команды передаются в открытом виде, а защита сводится к фиксированному коду, который можно просто повторить. Этот урок — введение в SDR и работу с sub-GHz и BLE.

## Теория

**SDR (Software Defined Radio)** — приёмопередатчик, где обработка сигнала идёт в софте. Позволяет слушать широкий диапазон и декодировать разные модуляции одним устройством. Вместо одной «жёсткой» микросхемы под конкретный стандарт вы получаете универсальный инструмент.

Ключевые параметры:

- **Частота** — 315/433/868/915 МГц (ISM sub-GHz), 2.4 ГГц (BLE, Wi-Fi, Zigbee).
- **Модуляция** — OOK/ASK (амплитудная, простейшая), FSK/GFSK (частотная), LoRa (CSS, chirp spread spectrum).
- **Ширина полосы, sample rate** — определяют, какой сигнал вы «видите» и с какой точностью.
- **Усиление (gain)** — приём слабых сигналов; слишком большое даёт перегруз и «мусор».

**Sub-GHz** — дешёвые пульты и датчики. Часто используют **фиксированный код** (dip-switch или прошитый ID) либо **кодовую посылку с rolling code** (KeeLoq). Фиксированный код тривиально воспроизводится (replay). Rolling code требует захвата и анализа (или атаки на реализацию).

**BLE (Bluetooth Low Energy)** — реклама (advertising) и соединения (GATT). Уязвимости: небезопасное сопряжение (Just Works), статичные пароли, отсутствие шифрования характеристик, чувствительные данные в advertising-пакетах.

**Replay-атака** — запись сигнала и его повтор. Работает, если код не меняется от нажатия к нажатию.

**Модуляции подробнее:**

| Модуляция | Применение | Особенность |
|-----------|-----------|-------------|
| OOK/ASK | пульты, датчики 433 МГц | «включён/выключен» несущая — проще всего ловить |
| FSK/GFSK | KeeLoq-пульты, шины | две частоты = 0/1 |
| LoRa (CSS) | дальняя связь, сенсоры | чирп — нужен LoRa-декодер |
| GMSK | BLE, Zigbee | частотная, узкая полоса |

## Инструменты и команды

- **RTL-SDR** — дешёвый приёмник (24–1700 МГц), только RX.
- **HackRF One / LimeSDR** — приём и передача (TX), широкий диапазон.
- **Flipper Zero** — sub-GHz, RFID/NFC, BLE в карманном формате.
- **Yard Stick One** — sub-GHz TX/RX.
- **GNU Radio / Universal Radio Hacker (URH)** — анализ и демодуляция.
- **rtl_433** — декодер множества датчиков на 433/868 МГц.
- **btlejack / bettercap** — BLE-исследование.
- **nRF Sniffer / Wireshark** — перехват BLE на уровне пакетов.

```bash
# Установка
sudo apt install rtl-sdr gnuradio gqrx-sdr
pip install urh
sudo apt install bettercap

# Просмотр спектра на 433 МГц (нужен rtl-sdr + gqrx)
gqrx   # выставить center freq 433.92M, смотреть водопад

# Декодирование датчиков на 433/868 МГц
rtl_433 -f 433920000 -F json

# Запись IQ-сигнала для анализа в URH
rtl_sdr -f 433920000 -s 1024000 -n 2048000 capture.iq
# затем открыть capture.iq в Universal Radio Hacker

# BLE: сканирование
sudo bettercap -iface hci0
# в консоли bettercap:
#   ble.recon on
#   ble.show
```

## Разобранный пример: replay пульта на 433 МГц

**Дано:** пульт от ворот, Flipper Zero (или HackRF + URH).

**Шаг 1 — определить частоту.** Смотрим маркировку на пульте (433/315/868 МГц) или сканируем спектр в gqrx, нажимая кнопку. Частый приём: начать с 433.92 МГц — это самый распространённый ISM-диапазон.

**Шаг 2 — запись сигнала.** На Flipper: `Sub-GHz → Read` → нажимаем кнопку пульта → сохраняем сигнал. Через SDR: записываем IQ и открываем в URH.

```bash
# HackRF: запись 2 секунд на 433.92 МГц
hackrf_transfer -r capture.iq -f 433920000 -s 2000000 -a 1 -g 40
```

**Шаг 3 — анализ в URH:**
```text
- Определяем модуляцию (обычно ASK/OOK)
- Autodetect parameters -> получаем битовую последовательность
- Если сигнал повторяется одинаково при каждом нажатии -> код фиксированный
```
В URH смотрим на «созвездие» и структуру пакета: преамбула, синхрослово, данные. Одинаковый payload при каждом нажатии = фиксированный код.

**Шаг 4 — воспроизведение (replay).** Flipper: `Sub-GHz → Read → сохранить → Send`. Ворота открываются. Подтверждена уязвимость «фиксированный код».

```bash
# HackRF: воспроизведение записанного IQ
hackrf_transfer -t capture.iq -f 433920000 -s 2000000 -a 1 -x 40
```

**Шаг 5 — если код rolling (меняется).** Каждое нажатие даёт новую посылку. Тогда:

- захватываем несколько нажатий, анализируем структуру (KeeLoq-шифр, счётчик),
- пробуем атаки на реализацию (счётчик, десинхронизация — «jam & replay»),
- или ищем другие векторы (уязвимость приёмника, небезопасная привязка).

**Шаг 6 — BLE-вариант.** Если устройство BLE:
```bash
# bettercap
ble.recon on
ble.show
# Подключаемся к интересующему устройству, перечисляем GATT-характеристики
ble.enum <MAC>
# Если характеристика записи без auth -> шлём команду
```
Отдельно проверяем advertising-пакеты: там бывают серийники, токены, состояние устройства без всякого сопряжения.

## Разобранный пример: декодирование датчика 433 МГц через rtl_433

```bash
rtl_433 -f 433920000 -R 0 -F json -M time:utc
# {"time":"...","model":"Generic-Remote","id":12345,"cmd":2,"channel":1}
```
Получив `id` и `cmd`, вы можете воспроизвести посылку совместимым TX (Flipper/HackRF) — датчик «поверит» команде. Это типовой CTF-сценарий и реальная проблема умных замков и ворот.

## Частые ошибки

- **Незаконная передача.** TX в неразрешённых диапазонах и на чужие устройства — нарушение закона. Тренируйтесь на своих устройствах и в экранированном боксе.
- **Неверная частота.** 433.92 МГц — самая частая, но бывает 315, 868, 915. Сканируйте спектр, а не угадывайте.
- **Слабый sample rate.** Слишком низкий rate обрезает сигнал; для OOK хватает 1 MS/s, для BLE нужно больше (2+ MS/s).
- **Попытка replay rolling-кода.** Симптом: ворота не открываются, потому что код уже «использован». Нужен анализ, а не слепое повторение.
- **Помехи.** Передача рядом с приёмником создаёт наводки. Разносите антенны, снижайте gain.
- **Игнорирование BLE advertising.** Данные могут утекать уже в рекламных пакетах, без подключения.
- **Перегруз приёмника.** Слишком высокий gain «забивает» эфир — сигнал выглядит как шум. Подбирайте gain вручную.

## Анализ модуляций и оборудование на практике

**Как отличить модуляции на глаз в URH/GNU Radio:**

| Признак | OOK/ASK | FSK/GFSK | LoRa |
|---------|---------|----------|------|
| Спектр | одна частота, вкл/выкл | две частоты | чирп (наклон) |
| Водопад | горизонтальные «штрихи» | чередование двух полос | диагональные линии |
| Автодетект URH | OOK | FSK | требует LoRa-декодера |

**Выбор оборудования под задачу:**

- **Только приём/разведка** → RTL-SDR ($30). Достаточно для датчиков 433/868 и анализа спектра.
- **Replay и TX** → Flipper Zero или HackRF. Flipper удобнее в поле, HackRF — шире диапазон и мощность.
- **Полноценный research** → HackRF/LimeSDR + GNU Radio + URH. Позволяет модулировать произвольные сигналы.
- **BLE** → nRF Sniffer (дешёвый, точный перехват) или btlejack.

**Практические советы по приёму:**

1. Начните с водопада: найдите «горячую» частоту, нажимая кнопку пульта.
2. Подберите gain так, чтобы сигнал был чётким, но не перегруженным.
3. Записывайте IQ, а не только демодулированные биты — так можно переиграть анализ.
4. Сохраняйте несколько нажатий: одинаковые посылки = фиксированный код, разные = rolling.

**Антенны и диапазон.** Штатная антенна RTL-SDR рассчитана на широкий диапазон и слаба. Для 433 МГц антенна ~17 см (λ/4) даёт заметно лучший приём. Для передачи мощность ограничена законом: 433 МГц в ISM допускает малую мощность, 868/915 — со своими ограничениями. Это не формальность: нарушение радиочастотного законодательства наказуемо.

## Что дальше / решение

- **Фиксированный код** → replay подтверждён, зафиксируйте impact (какие устройства, что открывает).
- **Rolling code** → зафиксируйте, что простой replay не работает, и переходите к анализу структуры или атакам на реализацию; не тратьте время на слепое повторение.
- **BLE без auth** → запишите GATT-характеристики, проверьте запись без сопряжения и утечки в advertising.
- **Ничего не декодируется** → поднимите sample rate, проверьте модуляцию, попробуйте `rtl_433 -A` (autodetect).
- **Радио не дало результата** → `record_vector attempted`, переходите к аппаратным интерфейсам (UART/JTAG/SPI).
