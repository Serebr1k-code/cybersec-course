**Mifare DESFire** — современная высокочастотная (13.56 МГц) карта NXP, пришедшая на смену сломанному Mifare Classic. Она использует настоящую криптографию (3DES, AES), поддерживает несколько приложений и файлов с раздельными ключами. Это стандарт де-факто для систем доступа, транспорта и микроплатежей. Взломать её «в лоб» нельзя, но реальные системы ломаются через слабую конфигурацию, утечки ключей и ошибки интеграции. Этот урок — про архитектуру и практическую работу.

## Архитектура DESFire

DESFire-карта содержит:

- **PICC** (сама карта) с master key.
- **Applications** — изолированные приложения (до 28 на EV1), каждое со своими ключами.
- **Files** — данные внутри приложения (standard, backup, value, cyclic, linear).
- **Keys** — до 14 ключей на приложение (EV1), типы: 3DES, AES, 2K3DES.

Аутентификация выполняется между приложением и картой по выбранному ключу; при успехе открывается доступ к файлам согласно правам.

## Аутентификация

DESFire поддерживает несколько схем:

- **Authenticate (legacy)** — 3DES/2K3DES challenge-response.
- **AuthenticateISO** — ISO 7816-4 аутентификация.
- **AuthenticateAES** — AES-128 challenge-response.

```text
# Пример AES-аутентификации (упрощённо)
# 1. Хост -> карта: команда AuthenticateAES с зашифрованным RndB
# 2. Карта -> хост: RndB (расшифрованный хостом), хост генерирует RndA
# 3. Хост -> карта: зашифрованные RndA||RndB'
# 4. Обе стороны имеют сессионный ключ
```

Ключевой момент: без знания ключа аутентификацию не пройти. Но **дефолтные ключи** (нули, известные наборы) встречаются на удивление часто.

## Proxmark3 и работа с DESFire

Proxmark3 — основной инструмент для HF-карт. Команды `hf mfdes`:

```bash
proxmark3 /dev/ttyACM0
> hf search                      # определить карту
# -> MIFARE DESFire EV1
> hf mfdes info                  # информация о карте
> hf mfdes enum                  # перечислить приложения
> hf mfdes getappnames
> hf mfdes auth --aid 000000 --key 00000000000000000000000000000000 --algo AES
# -> аутентификация дефолтным ключом
> hf mfdes lsapp --aid 000000    # список файлов приложения
> hf mfdes read --aid 000000 --fid 01   # чтение файла
```

Если ключ дефолтный, вы получаете полный доступ к приложению: чтение, запись, изменение ключей.

## Практические векторы атак

DESFire сама по себе криптографически стойкая, поэтому атакуют интеграцию:

- **Дефолтные/слабые ключи**: нули, простые паттерны, ключи из тестовых наборов.
- **Утечка ключей**: из прошивки ридера, бэкенда, конфигов (см. `hardware-firmware-extract`).
- **Неаутентифицированные данные**: некоторые файлы доступны без аутентификации (например, UID/публичные данные).
- **Replay/relay**: если система доверяет только UID (а не криптографии), карту можно эмулировать.
- **Downgrade**: попытка понизить версию/режим до слабого.
- **Side-channel/fault injection**: на физическом уровне (сложно, но известно).

## Разобранный пример: аудит системы доступа на DESFire

```bash
# 1. Определить карту
proxmark3
> hf search
# MIFARE DESFire EV1 4K
# 2. Перечислить приложения
> hf mfdes enum
# AID 000000 (master), AID 123456
# 3. Попробовать дефолтный ключ для AID 123456
> hf mfdes auth --aid 123456 --key 00000000000000000000000000000000 --algo AES
# Authentication successful!  <-- ключ дефолтный
# 4. Прочитать файлы
> hf mfdes lsapp --aid 123456
> hf mfdes read --aid 123456 --fid 01
# 5. Проверить права: можно ли писать/менять ключи
```

Найденный дефолтный ключ — критическая находка: он позволяет клонировать/перепрограммировать карты и заводить «свои».

## Частые ошибки и подводные камни

- **Неверный алгоритм**: AES-ключ против 3DES-команды не сработает.
- **Разный AID**: аутентификация к master ≠ к приложению.
- **Key version**: у ключей есть версия (0x00/0x01/...); несовпадение ломает auth.
- **Права файла**: аутентификация не гарантирует доступ к конкретному файлу.
- **Блокировка**: неверные ключи могут заблокировать приложение.
- **EV2 vs EV1**: новые карты имеют EV2 с расширениями; команды могут отличаться.

## ChangeKey и управление ключами

DESFire позволяет менять ключи командой **ChangeKey**. Это и защита, и риск: если атакующий разблокировался дефолтным ключом, он может **сменить ключи** и «захватить» карту, сделав её недоступной для легитимной системы.

```text
# ChangeKey (упрощённо)
# зашифрованный новый ключ отправляется карте
# после успеха старый ключ недействителен
```

В пентесте смена ключей — последнее средство (может сломать систему). Обычно достаточно прочитать данные и доказать доступ. Если ключи меняются, обязательно сохраните оригиналы для отката (если возможно).

## Value и cyclic файлы

DESFire поддерживает специальные типы файлов:

- **Value files** — счётчики с операциями increment/decrement/limited credit.
- **Cyclic files** — кольцевые записи (журналы).
- **Backup files** — с транзакционной целостностью.

Злоупотребление: если система использует value-файл как «баланс» (транспорт, кампус), некорректные права или отсутствие проверок позволяют манипулировать счётчиком. Проверяйте, какие операции разрешены без аутентификации.

## Защита систем на DESFire

- **Уникальные ключи** на карту/партию (не дефолтные).
- **Правильные права файлов**: чтение только после аутентификации.
- **Защита от смены ключей**: контроль ChangeKey.
- **Мониторинг**: обнаружение аномального доступа и смен ключей.
- **Хранение ключей** вне прошивки ридера (HSM/бэкенд).

DESFire — стойкая карта; почти все реальные компрометации — это ошибки конфигурации и утечки ключей из инфраструктуры.

## Команды DESFire: справочник

| Команда | Назначение |
|---------|-----------|
| 0x0A | Authenticate (legacy) |
| 0x1A | AuthenticateISO |
| 0xAA | AuthenticateAES |
| 0xCA | ChangeKey |
| 0x6A | GetKeyVersion |
| 0x54 | GetVersion |
| 0x6D | GetFreeMemory |
| 0x6E | GetFileSettings |
| 0x44 | ChangeFileSettings |
| 0xBD | ReadData |
| 0x3D | WriteData |
| 0x0C | CreateApplication |
| 0xCD | DeleteApplication |
| 0x64 | CreateFile |

Знание команд помогает понять, что именно проверяет система и какие операции доступны. Например, `GetFreeMemory` и `GetVersion` часто доступны без аутентификации и раскрывают тип карты.

## Интеграция в систему доступа

DESFire редко используется «в вакууме»: карта — часть системы (ридеры + бэкенд). Слабые места чаще в интеграции:

- **Ключи в ридерах**: если ридер хранит ключи в открытом виде, их достают из его прошивки.
- **Бэкенд**: база данных карт/ключей — цель для атаки.
- **Логика проверки**: некоторые системы проверяют только UID или неверно валидируют криптограммы.
- **Провижининг**: карты с дефолтными ключами при выдаче.

Поэтому пентест DESFire — это не только Proxmark, но и анализ ридеров, бэкенда и процесса выдачи карт.

## Сравнение с Mifare Classic

| Свойство | Mifare Classic | DESFire EV2 |
|----------|---------------|-------------|
| Крипто | Crypto1 (сломан) | AES/3DES |
| Клонирование | да | нет |
| Ключи | 6 байт, слабые | AES-128, версии |
| Файлы | 4-блочные сектора | типизированные файлы |
| Атака | autopwn | интеграция/утечки |

DESFire — правильный выбор для новых систем; Classic остаётся массовым, но уязвимым. Пентестеру важно уметь быстро определить тип карты (`hf search`) и выбрать стратегию: для Classic — autopwn, для DESFire — анализ интеграции и ключей.
