Прошивка — это целая ОС: ядро, BusyBox, библиотеки, веб-сервер, скрипты. Даже если производитель не публикует CVE, внутри часто лежат устаревшие компоненты с известными уязвимостями. Диффинг версий прошивок позволяет быстро находить изменения и новые баги. Урок — практическое продолжение `hardware-firmware-extract`.

## Теория

Идея: у вас есть две прошивки (старая и новая) или прошивка и публичная версия компонента. Сравнивая, можно:
- найти, что именно исправил вендор (значит, там была уязвимость);
- обнаружить устаревшие библиотеки (openssl, busybox, libc) с CVE;
- найти пароли/ключи, попавшие в сборку;
- выявить изменения в скриптах инициализации.

Что искать в распакованной прошивке:

| Артефакт | Где | Что даёт |
|----------|-----|----------|
| Версии библиотек | `/lib/*.so`, `/usr/lib` | сопоставление с CVE |
| BusyBox | `/bin/busybox` | известные CVE/версия |
| Веб-сервер | `/etc/init.d`, `/www` | конфиги, скрипты |
| Пароли/ключи | `/etc/shadow`, конфиги, бинарники | хардкод-креды |
| Init-скрипты | `/etc/init.d`, `/etc/rc.d` | запущенные сервисы |
| Строки | весь rootfs | URL, токены, IP |

## Инструменты и команды

- **binwalk** — распаковка.
- **firmware-mod-kit** — извлечение и пересборка.
- **firmware-analysis-toolkit (FAT)** — эмуляция.
- **cve-search / searchsploit** — сопоставление CVE.
- **diffoscope / binwalk -W** — сравнение.
- **trufflehog/grep** — поиск секретов.

```bash
# Распаковать две версии
binwalk -e firmware_v1.bin -C out_v1
binwalk -e firmware_v2.bin -C out_v2

# Сравнить файловые системы
diffoscope out_v1/_firmware.extracted/squashfs-root \
          out_v2/_firmware.extracted/squashfs-root | less

# Или быстро: список файлов + хэши
(cd out_v1/.../squashfs-root && find . -type f -exec md5sum {} \; | sort) > v1.txt
(cd out_v2/.../squashfs-root && find . -type f -exec md5sum {} \; | sort) > v2.txt
diff v1.txt v2.txt

# Определить версии компонентов
strings squashfs-root/usr/lib/libssl.so.1.1 | grep -i "OpenSSL"
squashfs-root/bin/busybox | head -1
readelf -p .comment squashfs-root/bin/busybox 2>/dev/null

# Поиск секретов
grep -rIn "password\|passwd\|secret\|api_key\|token" squashfs-root/etc 2>/dev/null
```

## Разобранный пример: поиск исправленной уязвимости

**Дано:** две версии прошивки роутера (v1.0 и v1.1), есть подозрение на исправленный баг.

**Шаг 1 — распаковка.** `binwalk -e` для обеих. Получаем два squashfs-root.

**Шаг 2 — сравнение хэшей.** Генерируем списки md5, `diff`. Видим, какие бинарники изменились.

**Шаг 3 — фокус на изменившихся.** Пусть изменился `usr/sbin/httpd`. Дизассемблируем обе версии в Ghidra, сравниваем функции. Находим добавленную проверку длины в обработчике URL — значит, в v1.0 был buffer overflow.

**Шаг 4 — версии библиотек.** Смотрим `libssl.so` — v1.0 использует OpenSSL 1.0.2 (много CVE), v1.1 — 1.1.1. Проверяем `searchsploit openssl 1.0.2`.

**Шаг 5 — секреты.** `grep` по конфигам находит хардкод-пароль администратора в v1.0 (удалён в v1.1). Это подтверждает, что баг был.

**Шаг 6 — репорт.** Формулируем: версия, компонент, CVE, PoC (для авторизованной программы). Проверяем актуальность: устройство может уже быть пропатчено.

## Частые ошибки

- **Сравнение без нормализации.** Разные пути/симлинки дают ложные различия. Сравнивайте осмысленно.
- **Игнорирование версии ядра.** CVE ядра — отдельная большая тема; смотрите `uname -r` из прошивки.
- **Слепое доверие версии.** Вендор может бэкпортировать патчи без смены версии. Проверяйте фактический код.
- **Слишком большой diff.** Начните с изменившихся бинарников и конфигов, не тоните в мелочах.
- **Забыть про U-Boot/загрузчик.** Уязвимости загрузчика тоже важны (secure boot).
- **Не проверить актуальность.** CVE мог быть исправлен; проверяйте версию устройства.

## Инструменты и команды

```bash
# распаковка
binwalk -Me firmware_v2.bin
binwalk --dd='.*' firmware_v2.bin
unblob firmware_v2.bin -o out/
# монтирование файловых систем
unsquashfs squashfs-root.sqsh
# сравнение версий
diff -r old_rootfs/ new_rootfs/ | tee diff.txt
# поиск исправленных строк
strings firmware_v1.bin > v1.txt && strings firmware_v2.bin > v2.txt
diff v1.txt v2.txt
# бинарный diff
radiff2 -c v1.bin v2.bin
```

Флаги `binwalk`: `-Me` — рекурсивная распаковка, `--dd` — извлечь по сигнатуре, `-A` — анализ архитектуры. `unblob` — современная альтернатива с лучшим покрытием форматов.

## Разобранный пример 2: поиск исправленного переполнения

1. Есть прошивки v1.0 и v1.1. Известно, что в v1.1 исправили уязвимость.
2. Распаковываем обе: `binwalk -Me`.
3. Ищем бинарные файлы, обрабатывающие сетевой ввод (`httpd`, `telnetd`).
4. Дизассемблируем обе версии в Ghidra и сравниваем функции обработки ввода.
5. В v1.0 находим `strcpy` без проверки длины; в v1.1 — `strncpy` с границей.
6. Это и есть исправленная уязвимость → строим PoC для v1.0.

## Таблица

| Сигнал в diff | Что означает |
|---------------|--------------|
| `strcpy` → `strncpy` | переполнение буфера |
| `system` появился/пропал | command injection |
| новая проверка пароля | слабая аутентификация |
| изменённый ключ/IV | фикс криптографии |
| новый endpoint | расширенная атака-поверхность |

## Практическое задание

Скачайте две версии прошивки любого роутера (или используйте учебные образы), распакуйте и сравните. Найдите хотя бы одну изменённую строку, объясняющую фикс. Оформите как version-diff-отчёт.

## Поиск ключей и секретов в прошивке

```bash
strings -n 8 firmware.bin | grep -iE 'password|secret|key|token|api'
grep -a -E 'BEGIN (RSA|EC) PRIVATE KEY' firmware.bin
binwalk -Me firmware.bin && grep -r -E 'AKIA[0-9A-Z]{16}' _firmware.bin.extracted/
# энтропия — найти зашифрованные/сжатые блоки
binwalk -E firmware.bin
```

Высокая энтропия указывает на шифрование/сжатие; низкая — на открытые данные (ключи, пароли). Hardcoded-ключи в прошивке — одна из самых частых находок в IoT.

## Таблица сигнатур

| Сигнатура | Что искать |
|-----------|------------|
| `strcpy`, `sprintf`, `gets` | переполнения |
| `system`, `popen`, `exec` | command injection |
| `admin:admin` | default-креды |
| `AWS` ключи | облачные креды |
| приватные ключи PEM | TLS/SSH |
| URL/C2 | коммуникация |

## Практическое задание

Скачайте прошивку учебного роутера, распакуйте и найдите хотя бы один hardcoded-секрет. Затем сравните две версии и определите, был ли секрет удалён или заменён. Оформите отчёт: версия, находка, доказательство.

## Итог

Version-diff прошивок — самый прямой путь к уязвимости: фикс указывает на баг. Сравнивайте распакованные образы, бинарники и строки; ищите `strcpy→strncpy`, новые проверки и удалённые секреты. Это тот же метод, что и в reversing, но применённый к встроенным системам.

## Быстрая проверка

```bash
binwalk -Me v1.bin && binwalk -Me v2.bin
diff -r v1.extracted/ v2.extracted/ | head
strings v1.bin > a.txt && strings v2.bin > b.txt && diff a.txt b.txt
```

Ищите в diff `strcpy`→`strncpy`, новые проверки и удалённые ключи. Один изменённый вызов часто указывает прямо на исправленную уязвимость.
