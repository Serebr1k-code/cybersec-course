## Вопрос, с которого всё начинается

Защитник поставил на рабочие станции политику: «разрешить только устройства с известными VID/PID». Ты подключаешь свой имплант — и он блокируется, потому что его VID не в списке. Можно ли стать **любым** устройством, которое хост точно пропустит? И как вообще устройство «решает», кем ему быть?

Ответ — в дескрипторах, и для работы с ними есть специальное железо.

## Наш пример: обход whitelist по классу

Наша цель — показать заказчику, что whitelist, построенный только на списке моделей, обходится. Мы возьмём плату-эмулятор, представимся разрешённым устройством и при этом добавим функцию, которой у оригинала нет. Разберём это шаг за шагом.

## Шаг 1: дескрипторы — это заявление о себе

Когда USB-устройство подключается, хост спрашивает его: «кто ты?» — и устройство отвечает **дескрипторами**. Это структуры данных с полями:

| Уровень | Поле | Что определяет |
|---------|------|----------------|
| Device | `bDeviceClass` | общий класс (или 0x00 = по интерфейсам) |
| Interface | `bInterfaceClass` | функционал интерфейса |
| Interface | `bInterfaceSubClass` | конкретный подтип |
| Interface | `bInterfaceProtocol` | протокол поверх класса |
| Endpoint | `bmAttributes` | тип передачи (bulk/int/isoc) |

Хост **верит** тому, что ему ответили. Значит, если мы умеем отвечать произвольно — мы можем назваться кем угодно. Именно это делает **Facedancer**.

## Шаг 2: аппаратная база

Facedancer — это софт плюс плата с USB-контроллером, работающим в device-режиме:

| Плата | Особенности |
|-------|-------------|
| GreatFET One | референсная плата проекта, USB host/device, GPIO |
| Luna (Great Scott Gadgets) | современная, high-speed, FPGA-ускорение |
| Raspberry Pi Pico | дешёвая альтернатива, device-режим |
| Facedancer21 (legacy) | на базе Teensy, историческая |
| FPGA-платы (Lattice ECP5) | для high-speed USB 2.0 и точных таймингов |
| USB Armory | полноценный Linux + USB device |

Для учебной задачи хватит GreatFET или Pico.

## Шаг 3: установка FaceDancer

Ставим библиотеку из репозитория проекта:

```bash
$ git clone https://github.com/greatscottgadgets/facedancer
$ cd facedancer
$ pip install -e .
$ python3 -c "import facedancer; print('ok')"
ok
```

Проверяем, что плата видна:

```
$ greatfet info
Found GreatFET One (serial ...)
```

## Шаг 4: эмуляция HID-клавиатуры

Простейший пример — представить плату клавиатурой. Логика: описать дескриптор HID и отправлять отчёты нажатий.

```python
from facedancer import *
from facedancer.devices.keyboard import USBKeyboardDevice

device = USBKeyboardDevice()
@device.standard_request_handler
def handle(req):
    return None

device.connect()
device.type_string("whoami")
```

`USBKeyboardDevice` — готовый класс, который при подключении сообщает хосту «я клавиатура» (класс 0x03, протокол Keyboard) и умеет печатать строки. С точки зрения хоста это неотличимо от обычной клавиатуры.

## Шаг 5: эмуляция сетевой карты

А вот и обход whitelist. Если политика разрешает «сетевые адаптеры известных моделей», мы представляемся именно ими — но заявляем интерфейс **CDC-Ethernet** (класс 0x02), а не HID. Хост загрузит сетевой драйвер и позволит устройству встать в сеть:

```python
from facedancer.devices.cdc import USBCDCDevice

device = USBCDCDevice()
device.connect()
# хост видит сетевую карту и поднимает интерфейс
```

Ключевой момент: мы **скопировали VID/PID** разрешённого устройства и заявили безобидный класс. Whitelist по модели пропустил нас, хотя реальная функция — сетевая.

## Шаг 6: диагностика эмуляции

Если хост не видит устройство, смотрим со стороны ядра:

```bash
$ sudo dmesg -w
[  512.11] usb 1-1: new full-speed USB device number 8 using xhci_hcd
[  512.20] usb 1-1: New USB device found, idVendor=1050, idProduct=0407
[  512.20] hid-generic 0003:1050:0407.0005: input,hidraw0: USB HID v1.11 Keyboard
```

Строка `USB HID v1.11 Keyboard` подтверждает: хост принял нашу эмуляцию за клавиатуру. Полезно также следить за событиями udev:

```bash
$ sudo udevadm monitor --property | head
KERNEL add /devices/.../usb1/1-1
```

## Шаг 7: смотрим на себя глазами хоста

Полезно проверить, что именно «увидел» хост. Смотрим дескрипторы на стороне хоста (не эмулятора):

```bash
$ lsusb -d 1050:0407 -v 2>/dev/null | head -20
idVendor           0x1050
idProduct          0x0407
bDeviceClass        0
bNumConfigurations  1
  Configuration Descriptor:
    bNumInterfaces    1
    Interface Descriptor:
      bInterfaceClass   3 Human Interface Device
      bInterfaceProtocol 1 Keyboard
```

Мы видим ровно то, что заявили: VID `1050` (Nintendo), класс `3` (HID), протокол `1` (Keyboard). Если бы мы заявили CDC-Ethernet, здесь стоял бы `bInterfaceClass 2 Communications`. Это и есть суть обхода: whitelist посмотрел на VID/PID и пропустил, а настоящий класс остаётся под нашим контролем.

Если отдельную плату покупать не хочется, ту же идею даёт **USB Raw Gadget** — модуль ядра, позволяющий писать device-side логику прямо в userspace на обычном одноплатнике с OTG-портом.

## Если не сработало

- **Хост не видит устройство.** Проверьте кабель (не все поддерживают данные) и что плата действительно в device-режиме, а не host.
- **Дескриптор отвергнут.** Ядро требует согласованных длин полей; смотрите `dmesg` на `device descriptor read/64, error -71`.
- **Windows кеширует устройства.** Совпадение VID/PID с уже известным может подтянуть старый драйвер — меняйте `iSerialNumber`, чтобы система приняла устройство за новое.

## На что смотреть дальше

- **Составные устройства.** Одна плата может заявить несколько интерфейсов: пока хост видит «накопитель», второе HID-устройство уже набирает команды.
- **Подделка серийного номера.** `iSerialNumber` кешируется хостом; его подмена помогает притвориться уже «знакомым» устройством.
- **Точные тайминги.** High-speed эмуляция требует FPGA-плат; на Pico возможны задержки, а full-speed (12 Мбит/с) для HID и CDC обычно хватает.
- **Фаззинг драйверов.** Отправляя нештатные дескрипторы (например, с битой длиной), ищут падения драйверов ядра — но только на изолированном стенде.

## Что мы теперь знаем

По-простому:

1. Устройство сообщает о себе **дескрипторами**, и хост им верит без перепроверки.
2. Facedancer — это плата в device-режиме плюс библиотека, описывающая дескрипторы и логику.
3. Заявив чужой VID/PID и безобидный класс, можно обойти whitelist по моделям.
4. Проверить результат удобно с хоста через `lsusb -v` и `dmesg`.
5. Составные устройства прячут опасную функцию за безобидной.
