## Вопрос, с которого всё начинается

На объекте стоит десяток дешёвых роутеров, раздающих Wi-Fi. Ломать шифрование не хочется — это шумно. Гораздо проще зайти в **сам роутер**: там веб-интерфейс, WPS, UPnP и прошивка с паролями провайдера. Как атакуют SOHO-устройство и что оно раскрывает?

## SOHO-роутер как цель

**SOHO** (Small Office/Home Office) — массовые потребительские роутеры. Их объединяет:

- слабый или дефолтный пароль администратора;
- включённый по умолчанию **WPS**;
- **UPnP** для проброса портов;
- прошивка на базе BusyBox + веб-сервер (обычно lighttpd/boa);
- почти всегда — **UART** на плате.

Каждый пункт — отдельный вектор. Начнём с самого простого.

## Шаг 1: дефолтные креды и вход в веб-UI

Производители часто оставляют заводские логины: `admin/admin`, `admin/password`, `root/root`. Проверяются они за секунды:

```
$ curl -s -u admin:admin http://192.168.1.1/ | grep -i 'welcome\|dashboard'
<title>Router Dashboard</title>
```

Если сработало — устройство наше. Если нет, помогает брутфорс веб-UI небольшим словарём (не мега-листом): `hydra -l admin -P common.txt 192.168.1.1 http-get /`. Важно: современные прошивки блокируют после нескольких попыток, поэтому сначала пробуют дефолты и словарь из модели устройства.

## Шаг 2: WPS и Pixie Dust

**WPS** (Wi-Fi Protected Setup) позволяет подключиться по 8-значному PIN вместо пароля. PIN проверяется по частям, что даёт утечку: атака **Pixie Dust** восстанавливает PIN и, что важнее, **PSK** за секунды, эксплуатируя слабый генератор случайных чисел в прошивке.

```
$ reaver -i wlan0 -b AA:BB:CC:00:11:22 -K 1 -vv
[+] WPS PIN: '12345670'
[+] WPA PSK: 'warehouse2024'
```

`-K 1` включает Pixie Dust. Если роутер уязвим, пароль от Wi-Fi извлекается без словаря — потому что берётся из предсказуемого RNG. Это один из самых практичных векторов против дешёвых точек.

## Шаг 3: UPnP и SSDP

**UPnP** — протокол автоматической настройки: устройства находят друг друга по **SSDP** (multicast на 239.255.255.250:1900) и управляют пробросом портов. Часто UPnP открыт наружу и позволяет любому в LAN добавить проброс на внутренний сервис.

```
$ nmap -sU -p 1900 --script upnp-info 192.168.1.1
1900/udp open  upnp
| upnp-info: 
|   Server: Linux/3.14 UPnP/1.0 MiniUPnPd/1.9
```

Через UPnP можно открыть порт на внутренний хост (например, SSH) — это превращает роутер в мост внутрь сети. Инструмент `miranda` умеет перечислять и добавлять маппинги.

## Шаг 4: CVE веб-интерфейсов

Веб-UI SOHO-роутеров исторически полон дыр: command injection в параметрах, path traversal в загрузке конфигов, авторизация по подделанному cookie. Классика — CVE вида «authenticated command injection» в `ping`/`traceroute` диагностике.

```
$ curl -s 'http://192.168.1.1/cgi-bin/diagnostic.cgi?ip=127.0.0.1;id' -b 'sid=valid'
uid=0(root) gid=0(root)
```

Символ `;` превращает диагностику в выполнение команд от root. Такие CVE ищут по баннерам прошивки (`grep` по версии) и по базе вендора. Для пентеста это часто быстрее, чем WPS.

## Шаг 5: UART на плате роутера

Если софт закрыт, роутер вскрывают. На плате почти всегда есть 4 площадки **UART** (TX/RX/GND/VCC). Подключаются USB-TTL адаптером и смотрят загрузку:

```
$ picocom -b 115200 /dev/ttyUSB0
Starting kernel ...
BusyBox v1.31.1 ...
# 
```

Скорость обычно 115200. Если загрузчик отдаёт shell — мы в системе роутера. Оттуда видно `/etc/shadow`, `nvram` с паролями, и можно снять прошивку. Часто UART защищён паролем загрузчика — тогда ищут обход (прерывание загрузки, кнопка reset, U-Boot env).

## Шаг 6: извлечение прошивки и ключей

Прошивку снимают с флеш-чипа (SPI) программатором или через `binwalk` из образа с сайта вендора. Внутри — файловая система (squashfs) и конфиги с ключами:

```
$ binwalk -e firmware.bin
$ grep -r 'password\|psk\|key' squashfs-root/etc/ 2>/dev/null | head
squashfs-root/etc/config/wireless: option key 'warehouse2024'
```

Пароль Wi-Fi, ключи провайдера (PPPoE), токены — всё лежит в открытом виде. Это и есть главная ценность роутера как цели.

## Частые грабли

- **Смена дефолтного пароля** → пробуй WPS и CVE, а не брутфорс.
- **WPS выключен** → Pixie Dust не пройдёт.
- **UART под паролем** → ищи обход или снимай флеш напрямую.
- **Прошивка зашифрована** → нужен ключ из загрузчика или дамп с работающего устройства.
- **Брутфорс веб-UI** → блокировка после N попыток; сначала дефолты.

## Полный прогон

1. `nmap -sV 192.168.1.1` — версия прошивки/веб-сервера.
2. Дефолтные креды → вход.
3. Если нет — WPS Pixie Dust → PSK.
4. UPnP → проброс внутреннего сервиса.
5. Если всё закрыто — вскрытие, UART, дамп флеша.
6. Из прошивки — ключи провайдера и Wi-Fi.

## Что мы теперь знаем

- SOHO-роутер — многослойная цель: веб-UI, WPS, UPnP, UART, флеш.
- Дефолтные креды и Pixie Dust дают доступ за секунды.
- UPnP превращает роутер в мост внутрь.
- CVE веб-UI часто дают root через command injection.
- Прошивка хранит ключи в открытом виде.

## Шаг 7: скрытые сервисы — Telnet, SSH, TR-069

Помимо веб-UI на роутере часто открыты другие сервисы. Сканирование изнутри LAN показывает неожиданное:

```
$ nmap -sV 192.168.1.1
PORT     STATE SERVICE   VERSION
23/tcp   open  telnet    BusyBox telnetd
80/tcp   open  http      lighttpd 1.4.45
7547/tcp open  tcpwrapped  TR-069 CWMP
```

`telnetd` от BusyBox с дефолтным паролем — прямой доступ к системе. А порт **7547** — это **TR-069 (CWMP)**, протокол удалённого управления от провайдера: исторически он был источником массовых компрометаций (CVE-2016-10372 в Deutsche Telekom). Если TR-069 открыт наружу без аутентификации, атакующий может менять конфигурацию роутера удалённо.

## Шаг 8: дефолтный WPS PIN и брутфорс

Даже без Pixie Dust WPS иногда ломается простым перебором, потому что PIN проверяется по частям: первые 4 цифры и последние 3 отдельно. Это сокращает пространство с 10⁸ до ~10⁴+10³ попыток.

```
$ reaver -i wlan0 -b AA:BB:CC:00:11:22 -vv -d 2
[+] Trying pin 12345670
[+] Pin cracked: 12345670
```

Многие прошивки блокируют после нескольких попыток, но некоторые — нет. Pixie Dust быстрее, потому что не перебирает вовсе, а вычисляет PIN из утечки RNG.

## Разбор реального кейса: захват офисной сети

В небольшом офисе стоял роутер с дефолтным `admin/admin`. Пентестер:

1. подключился к гостевому Wi-Fi (пароль был на доске);
2. вошёл в веб-UI роутера дефолтными кредами;
3. увидел в настройках **PPPoE-логин и пароль провайдера**, а также список MAC-адресов и резервные SSID;
4. через UPnP открыл порт на внутреннем сервере и получил к нему доступ.

Одна дефолтная пара `admin/admin` превратилась в доступ к внутренней инфраструктуре. В отчёте это описывают как «цепочку эскалации», а рекомендация одна: смена дефолтов и отключение UPnP/WPS.

## Что делать защитнику

- **Сменить** дефолтные пароли и логины администратора.
- **Отключить WPS** и UPnP там, где они не нужны.
- **Закрыть** Telnet/TR-069 от внешнего доступа, обновить прошивку.
- **Сегментировать** гостевую сеть от корпоративной.
- Вести **инвентарь** устройств и версий прошивок.

## Шаг 9: извлечение прошивки через веб-интерфейс

Не всегда нужно вскрывать устройство. Многие роутеры отдают резервную копию настроек — файл конфигурации, который можно скачать из веб-UI. Часто это архив с открытыми паролями:

```
$ curl -s -b 'sid=valid' http://192.168.1.1/cgi-bin/backup.cgi -o backup.tar.gz
$ tar xzf backup.tar.gz && grep -ri 'pass\\|key\\|psk' . | head
./etc/config/wireless: option key 'warehouse2024'
./etc/config/pppoe: option password 'isp_secret'
```

Тот же результат, что и с флеша, но без паяльника. Ещё один путь — **TFTP**: многие прошивки отдают/принимают образ по TFTP на 69/udp при зажатой кнопке. Это штатный механизм восстановления, которым пользуются и атакующие.

## Шаг 10: цепочка атаки на SOHO — сводим всё вместе

Практическая последовательность для пентеста:

1. **Разведка**: `nmap -sV` на шлюз, баннер веб-сервера и версия прошивки.
2. **Дефолты**: `admin/admin`, `root/root` и словарь по модели.
3. **WPS**: если включён — Pixie Dust за секунды.
4. **CVE**: сверка версии прошивки с базой, эксплуатация command injection.
5. **UPnP**: проброс порта на внутренний сервис.
6. **Физика**: если всё закрыто — UART/флеш и дамп.
7. **Извлечение**: пароли Wi-Fi, PPPoE, резервные SSID из конфига.

Каждый шаг даёт «мостик» дальше: дефолт → веб-UI → PPPoE-креды → провайдер; WPS → PSK → трафик LAN; UPnP → внутренний сервис. В отчёте цепочку показывают целиком — это демонстрирует реальный риск, а не набор разрозненных находок.

## Коротко: чего избегать

- **Не перегружай веб-UI брутфорсом** — устройство зависает и требует ручной перезагрузки; начинай с дефолтов.
- **Не трогай WPS на боевом устройстве без согласования** — перебор может заблокировать точку.
- **Не оставляй UPnP-маппинги** после теста — закрой их, иначе оставишь открытую дверь.
- **Не прошивай устройство заказчика** своей модифицированной прошивкой без письменного согласия.
- **Фиксируй версию прошивки** до и после — это доказательство для отчёта.
