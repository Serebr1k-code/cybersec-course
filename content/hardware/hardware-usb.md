USB (Universal Serial Bus) — универсальная шина, через которую к компьютеру подключается почти всё: клавиатуры, флешки, камеры, принтеры, сетевые адаптеры, отладочные платы. Она интересна и как **цель** (перехват данных, эксплуатация драйверов), и как **орудие** (эмуляция клавиатуры, BadUSB, DMA-атаки). Этот урок — точка входа в USB-ветку: устройство шины, классы устройств, векторы атак и инструменты анализа.

## Почему USB — цель и оружие

USB-порт есть на каждом компьютере, и он принимает **любое** устройство без подтверждения. Из этого следуют два класса атак:

- **Атаки на хост** — вредоносное USB-устройство эмулирует доверенную периферию: клавиатуру (вводит команды), сетевую карту (перенаправляет трафик), накопитель (автозапуск). Классика — BadUSB.
- **Атаки на устройство** — хост атакует подключённую периферию: перепрошивка, извлечение ключей, эксплуатация драйверов ядра.

Физический доступ + USB = очень высокий риск. В пентесте это стандартный вектор «оставленная зарядка/флешка», в CTF — задачи на анализ трафика или эмуляцию HID.

## Физика и топология

USB — это **хост-центричная** шина с иерархией хабов. Хост (контроллер) опрашивает устройства; устройство не может «заговорить» первым. Линии: VBUS (5 В), GND, D−, D+. Скорости: Low Speed (1.5 Мбит/с), Full Speed (12 Мбит/с), High Speed (480 Мбит/с), SuperSpeed (5/10/20 Гбит/с).

При подключении происходит **enumeration**: хост сбрасывает устройство, читает дескрипторы, выбирает конфигурацию. Именно дескрипторы сообщают хосту, кто перед ним — клавиатура, флешка или хаб. Подмена дескрипторов — основа BadUSB.

Ключевые понятия:

- **Endpoint** — логический канал (IN/OUT), по которому идут данные.
- **Configuration** — набор интерфейсов, выбираемый хостом.
- **Interface / Class** — функциональная роль (HID, MSC, CDC, Audio, Video).
- **Descriptor** — структура с метаданными (VID/PID, класс, строки).

## Классы устройств

| Класс | Код | Назначение | Атака |
|-------|-----|-----------|-------|
| HID | 0x03 | клавиатура, мышь | инъекция нажатий |
| MSC | 0x08 | накопитель | автозапуск, autorun |
| CDC | 0x02 | сетевая/COM | перенаправление трафика |
| Audio | 0x01 | звук | подслушивание микрофона |
| Video | 0x0E | камера | захват изображения |
| Hub | 0x09 | концентратор | подмена топологии |
| Vendor | 0xFF | проприетарный | произвольные драйверы |

Класс HID опасен тем, что операционная система доверяет «клавиатуре» полностью: она может набирать команды от имени пользователя, включая открытие терминала и запуск загрузки.

## Атаки на хост

1. **HID-инъекция (BadUSB / Rubber Ducky)** — устройство представляется клавиатурой и набирает заранее заготовленный скрипт (DuckyScript). Скорость ввода — тысячи символов в секунду, человек не успевает.
2. **USB-накопитель с LNK/автозапуском** — специально подготовленные файлы, эксплуатирующие Windows Explorer.
3. **DMA-атаки** — через Thunderbolt/PCIe или зловредное USB-устройство с DMA-возможностями читают память хоста (см. отдельные материалы по DMA).
4. **Juice jacking** — через «зарядную станцию» с данными перенаправляют ввод или воруют данные.
5. **Malicious cable** — кабель со встроенным чипом, выполняющий HID/сеть/сниффинг.

## Атаки на устройство

Обратное направление: хост-исследователь атакует периферию. Типичные цели:

- **Перепрошивка устройства** (клавиатура, мышь, флешка) — подмена firmware, добавление HID-функций.
- **Эксплуатация драйверов** — в ядре есть USB-драйверы с историей уязвимостей (OOB write при разборе дескрипторов).
- **Извлечение секретов** — из USB-токенов, аппаратных ключей, HSM-адаптеров.
- **Фаззинг** — эмуляция «кривого» устройства для поиска падений драйвера.

## Перехват и анализ USB-трафика

На Linux USB-трафик видно через `usbmon`:

```bash
sudo modprobe usbmon
ls /sys/kernel/debug/usb/usbmon/
# 0u 1u 2u ... (шины)
sudo cat /sys/kernel/debug/usb/usbmon/1u | head
# формат: URB-тег, timestamp, ... данные

# Запись и анализ в Wireshark
sudo dumpcap -i usbmon1 -w /tmp/usb.pcap
wireshark /tmp/usb.pcap
```

На Windows — **USBPcap** (интегрируется в Wireshark). На аппаратном уровне трафик снимают **USB-анализаторами** (Total Phase Beagle, Saleae с USB-декодером) или сниффером на базе **Facedancer/GreatFET**. Для эмуляции устройств и фаззинга используют **Facedancer** (Python + USB-железо): можно отвечать хосту произвольными дескрипторами.

```bash
# Facedancer: эмуляция клавиатуры
pip3 install facedancer
python3 -c "
from facedancer import *
# ...описание HID-дескриптора и отправка нажатий
"
```

## Разобранный пример: анализ трафика HID-клавиатуры

```bash
# 1. Находим шину, к которой подключена клавиатура
lsusb
# Bus 001 Device 004: ID 046d:c31c Logitech Keyboard

# 2. Включаем usbmon и пишем на нужную шину
sudo modprobe usbmon
sudo dumpcap -i usbmon1 -w hid.pcap -a duration:20
# (в это время набираем текст)

# 3. Анализируем в Wireshark: фильтр usb.transfer_type == 0x01 (interrupt)
#    Поле HID Data показывает коды клавиш (usage codes)
tshark -r hid.pcap -Y 'usbhid.data' -T fields -e usbhid.data | head
# 0000040000000000   <-- usage 0x04 = 'a'
```

Если это была BadUSB-инъекция, в трафике видна длинная последовательность нажатий с аномально малыми интервалами. По кодам клавиш восстанавливают набранную команду.

## Инструменты: шпаргалка

| Инструмент | Уровень | Назначение |
|-----------|---------|-----------|
| `lsusb` | хост | список устройств и дескрипторов |
| `usbmon` + Wireshark | хост | перехват USB-трафика |
| USBPcap | Windows | то же на Windows |
| Facedancer | железо | эмуляция устройств |
| GreatFET | железо | сниффинг/эмуляция |
| Beagle USB | железо | аппаратный анализатор |
| `usbhid-dump` | хост | дамп HID-отчётов |
| `wireshark` | ПО | декодирование протоколов |

## Частые ошибки и подводные камни

- **usbmon видит только свою шину**: сначала `lsusb`, потом выбрать `usbmonN`.
- **Запись без фильтра**: поток огромный, диски забиваются; используйте `-a duration` и фильтры Wireshark.
- **Права**: для usbmon и dumpcap нужен root или группы `wireshark`.
- **HID-коды ≠ ASCII**: в отчётах usage codes, а не символы; нужна таблица HID Usage ID.
- **Эмуляция требует железа**: Facedancer работает на определённых платах (Raspberry Pi Pico, GreatFET, MAX3421E).

## USB Power Delivery и альтернативные режимы

Современный USB — это не только данные. **USB Power Delivery (USB-PD)** договаривается о напряжении/токе до 100 Вт и выше, а режим **Alt Mode** позволяет передавать по тому же разъёму DisplayPort, HDMI, Thunderbolt. Для пентестера это важно по двум причинам. Во-первых, «зарядное устройство» может быть сложным активным устройством с собственным контроллером — именно на этом строятся атаки juice jacking и malicious cable. Во-вторых, Alt Mode (Thunderbolt/PCIe) открывает путь к DMA-атакам, если хост не включает IOMMU. Разъём USB-C симметричен и поддерживает ролевую модель (источник/приёмник), поэтому кабель может «перевернуть» роли и стать хостом. Понимание PD и Alt Mode помогает объяснить, почему «просто зарядка» иногда оказывается полноценным компьютером.

## Лабораторный стенд для USB-исследований

Чтобы безопасно экспериментировать, нужен изолированный стенд:

- **Отдельная тестовая машина** (или ВМ с пробросом USB-контроллера) — чтобы инъекция не задела рабочую систему.
- **Аппаратный USB-хаб с питанием** — не выводит порт хоста из строя при экспериментах.
- **USB data blocker** — для опытов с «зарядками».
- **Логический анализатор / USB-сниффер** — для разбора трафика.
- **Facedancer/GreatFET** — для эмуляции устройств.
- **Снимок ОС** — чтобы откатывать состояние после HID-инъекции.

Правило: HID-payload'ы и USB Killer-подобные устройства тестируйте **только** на своей изолированной лаборатории и только на железе, которое не жалко. В реальном пентесте применение разрушающих USB-атак требует отдельного письменного согласования в scope.

## Уровни анализа: от софта к железу

Полезно держать в голове три уровня, на которых исследуют USB:

1. **Софтовый** — `usbmon`/USBPcap и Wireshark. Дёшево, видно URB и данные, но только на стороне хоста.
2. **Эмуляционный** — Facedancer/GreatFET. Можно отвечать произвольно и фаззить, но нужна плата.
3. **Электрический** — аппаратный анализатор (Beagle, Saleae). Видно все пакеты, включая низкоуровневые, но дорого и требует навыка.

Начинать всегда со первого: часто уже там видно всё нужное. Эмуляция — когда нужно «стать» устройством. Аппаратный анализ — когда нужно увидеть то, что софт не отдаёт.
