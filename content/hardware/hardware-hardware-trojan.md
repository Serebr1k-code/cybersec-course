Аппаратный троян — это закладка, внедрённая в устройство на этапе производства, поставки или ремонта. В отличие от софтверных бэкдоров, обнаружить её сложно: она может не проявляться до определённого триггера. Урок — обзор угроз и методов защиты в цепочке поставок.

## Теория

Классы аппаратных закладок:

| Тип | Где внедряется | Пример |
|-----|----------------|--------|
| **Silicon trojan** | на этапе проектирования чипа | скрытая логика, срабатывающая по триггеру |
| **PCB implant** | при производстве/сборке платы | лишний компонент, перерезанная/добавленная дорожка |
| **Firmware implant** | в прошивку | бэкдор, подмена загрузчика |
| **Counterfeit IC** | подмена компонента | перемаркированный чип с дефектом/закладкой |
| **Interdiction** | перехват при доставке | вскрытие корпуса, врезка «жучка» |
| **Repair implant** | при сервисном обслуживании | подмена модуля |

Модель угрозы supply chain: каждый посредник (производитель, дистрибьютор, курьер, сервис) — потенциальная точка компрометации. Особенно критично для оборонки, телекома, критической инфраструктуры.

Триггеры троянов:
- **временной** (срабатывает через N часов),
- **по событию** (определённая команда/паттерн),
- **физический** (напряжение, температура),
- **по счётчику** (после N операций).

## Инструменты и методы обнаружения

- **Визуальный осмотр + микроскоп** — лишние компоненты, следы пайки.
- **Рентген (X-ray)** — внутренние слои, скрытые дорожки, лишние элементы.
- **CT-сканирование** — объёмная структура.
- **Сравнение с эталоном** — side-by-side осмотр плат из разных партий.
- **Тепловидение** — аномальный нагрев (работающая закладка).
- **Анализ энергопотребления** — отклонения в side-channel.
- **Дамп прошивки и diff** — сравнение с официальной версией.
- **X-ray fluorescence (XRF)** — состав материалов (контрафакт).

```bash
# Проверка прошивки на соответствие официальной
sha256sum extracted_firmware.bin
# Сравнить с хэшем с сайта вендора (если есть)
binwalk -e extracted_firmware.bin
diff -r vendor_rootfs device_rootfs     # искать лишние бинарники/скрипты

# Проверка подписи компонентов
openssl dgst -sha256 -verify pubkey.pem -signature fw.sig fw.bin
```

## Разобранный пример: аудит партии сетевых устройств

**Дано:** партия коммутаторов от нового поставщика. Нужно оценить риск закладок.

**Шаг 1 — документация.** Собираем официальные хэши прошивок и фотографии эталонной платы от вендора.

**Шаг 2 — вскрытие и визуальный осмотр.** Сравниваем платы партии с эталоном. Ищем:
- компоненты, которых нет на эталоне;
- следы ручной пайки (неравномерный припой, флюс);
- изменённую маркировку чипов.

**Шаг 3 — рентген.** X-ray показывает внутренние слои и скрытые элементы, которые не видны визуально.

**Шаг 4 — дамп прошивки.** Снимаем прошивку (`hardware-flash-dumping`), считаем sha256, сравниваем с официальной. Любое отличие — красный флаг.

**Шаг 5 — diff файловой системы.** Если хэш не совпал, распаковываем и ищем лишние скрипты/бинарники, изменения в init-скриптах, новые сетевые соединения.

**Шаг 6 — тепловидение под нагрузкой.** Запускаем устройство, смотрим тепловизором: аномально греющийся чип может быть активной закладкой (радиомодуль, дополнительный процессор).

**Шаг 7 — вывод.** Если найдено расхождение — эскалация, карантин партии, уведомление вендора/безопасности.

## Частые ошибки

- **Доверие «официальному» каналу.** Именно он и компрометируется. Проверяйте независимо.
- **Только визуальный осмотр.** Троян может быть внутри многослойной платы или в кремнии. Нужен X-ray.
- **Игнорирование прошивки.** Даже идеальная плата с заражённой прошивкой = бэкдор.
- **Нет эталона.** Без сравнения с доверенным образцом невозможно найти отличия.
- **Паранойя без модели угрозы.** Для домашнего роутера X-ray не нужен; для оборонного — обязателен.
- **Правовые и этические рамки.** Вскрытие чужого оборудования без разрешения — нарушение.

## Методы обнаружения

```bash
# сравнение с эталоном
diff <(strings suspect.bin) <(strings reference.bin)
# анализ прошивки
binwalk -Me suspect.bin
# рентген/оптический контроль — аппаратно
# тест на потребление и эмиссии
# логический анализ шин (SPI/JTAG)
# проверка подписей прошивки
```

## Разобранный пример 2: сравнение партий

1. Есть 10 одинаковых устройств; подозрение на закладку в одном.
2. Считываем прошивки со всех (SPI-дамп).
3. Считаем хеши: `sha256sum *.bin`.
4. Одна прошивка отличается → разбираем её.
5. Находим дополнительный сетевой callback или скрытый аккаунт.

## Таблица признаков

| Признак | Возможная закладка |
|---------|--------------------|
| лишний сетевой коннект | backdoor C2 |
| скрытый пользователь | доступ разработчика |
| изменённый хеш прошивки | модификация |
| лишний компонент на плате | аппаратный имплант |
| нестандартное потребление | активный модуль |

## Практическое задание

Сравните прошивки двух одинаковых устройств (или образцы с разными версиями). Найдите различия и классифицируйте их: багфикс, фича или потенциальная закладка. Оформите отчёт с доказательствами (хеши, дампы, строки).

## Виды имплантов

- **Аппаратный (chip-off)**: лишний компонент на плате, перехватывает шины.
- **Прошивочный (firmware)**: модифицированный bootloader/UEFI с backdoor.
- **FPGA/ASIC-закладка**: логика внутри микросхемы.
- **Ключевой логгер**: перехват ввода.
- **Комбинированный**: аппаратный триггер + программная нагрузка.

Обнаружение требует сравнения с эталоном (хеши прошивок, оптический контроль платы, рентген) и анализа поведения (сетевой трафик, эмиссии, потребление).

## Практическое задание

Сравните прошивки двух устройств одной модели из разных партий. Если хеши совпадают — закладки, скорее всего, нет (по крайней мере в прошивке). Если отличаются — распакуйте и сравните строки/модули. Оформите вывод: багфикс, фича или потенциальная закладка, с доказательствами.

## Инструменты проверки целостности

```bash
# хеши прошивок
sha256sum dump*.bin
# chipsec для платформы
chipsec_main -m common.bios_wp
# анализ эмиссий — спектроанализатор (аппаратно)
# оптический контроль платы под микроскопом
```

`chipsec_main -m common.bios_wp` проверяет защиту от записи BIOS. Комбинируйте программные (хеши, прошивка) и аппаратные (микроскоп, спектр) методы — закладка может быть незаметна в прошивке, но видна на плате.

## Практика: что делать при подозрении

1. Изолировать устройство, не включать (избежать активации закладки).
2. Снять прошивку (SPI/JTAG) и сравнить с эталоном.
3. Осмотреть плату (микроскоп, рентген) на лишние компоненты.
4. Проанализировать сетевой трафик при включении.
5. Проверить потребление и эмиссии.
6. Оформить отчёт с доказательствами и передать вендору.

Без эталона сравнение затруднено — поэтому храните «золотые образы» прошивок для критичных устройств.

## Итог

Аппаратные закладки — редкий, но самый опасный класс. Обнаружение строится на сравнении с эталоном: хеши прошивок, оптический контроль, анализ трафика и эмиссий. Храните эталонные образы и проверяйте партии перед развёртыванием.

## Быстрая проверка

```bash
sha256sum dump1.bin dump2.bin
diff <(strings dump1.bin) <(strings dump2.bin)
chipsec_main -m common.bios_wp
```

Совпадение хешей прошивок двух одинаковых устройств — сильный индикатор отсутствия закладки в прошивке. Различие требует разбора: багфикс, фича или имплант.

## Итог по закладкам

Обнаружение строится на сравнении с эталоном: хеши прошивок, оптический контроль платы, анализ трафика и эмиссий. Без «золотого образа» сравнение затруднено. Для критичных устройств храните эталонные прошивки и проверяйте партии перед развёртыванием.
