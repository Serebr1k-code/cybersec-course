SDR (Software Defined Radio) переносит обработку радио в софт: вы получаете поток чисел, описывающий эфир, и всё остальное делаете в компьютере. Понимание **IQ-сэмплов** и **модуляций** — ключ к тому, чтобы не просто «слушать», а декодировать цифровые протоколы пультов, датчиков и телеметрии. Этот урок — углубление после базового знакомства с SDR.

## IQ-сэмплы: что это

Радиосигнал — это комплексная величина. SDR выдаёт поток **комплексных отсчётов** (I — in-phase, Q — quadrature): каждый сэмпл — точка на комплексной плоскости. Из IQ можно восстановить амплитуду и фазу сигнала, а значит — любую модуляцию. Частота дискретизации (`sample rate`) определяет ширину полосы: 2.4 МГц у RTL-SDR означает, что видно полосу 2.4 МГц вокруг центральной частоты.

Ключевое правило Найквиста: чтобы «увидеть» сигнал шириной W, нужно `sample_rate >= W`. Если сигнал шире полосы захвата, он «расползётся» и не декодируется.

## Модуляции

| Модуляция | Принцип | Где встречается |
|-----------|---------|-----------------|
| AM/ASK/OOK | амплитуда | пульты 433 МГц, датчики |
| FM/FSK | частота | рации, телеметрия, BLE (GFSK) |
| PSK | фаза | Wi-Fi, Zigbee (OQPSK) |
| QAM | амплитуда+фаза | DVB, кабельное ТВ |
| OFDM | много несущих | Wi-Fi, DVB, LTE |

Простые устройства (пульты, погодные датчики) используют **OOK/ASK** или **FSK** — их проще всего декодировать. Сложные (Wi-Fi, Zigbee) требуют полноценных демодуляторов.

## Настройка приёмника

Три параметра определяют приём:

- **Center frequency** — центральная частота.
- **Sample rate** — полоса (и нагрузка на CPU/USB).
- **Gain** — усиление (слишком много → перегрузка и «зеркала»).

```bash
# rtl_sdr: записать IQ на 433.92 МГц, 2 МГц полоса, 10 секунд
rtl_sdr -f 433920000 -s 2000000 -g 40 -n 20000000 capture.iq
# rtl_fm: прослушать FM
rtl_fm -f 100000000 -M wbfm -s 200000 -r 48000 - | aplay -r 48000 -f S16_LE
# rtl_power: скан спектра
rtl_power -f 400M:500M:1M -i 1 -e 60 scan.csv
```

## Софт для просмотра спектра

- **gqrx** — популярный GUI-приёмник (RTL-SDR, HackRF, Airspy).
- **SDR#** — Windows, богатый набор плагинов.
- **SDRangel** — кроссплатформенный, мощный.
- **GQRX + GNU Radio** — связка для кастомной обработки.
- **inspectrum** — анализ записанных IQ-файлов.

```bash
gqrx   # выбрать устройство, выставить частоту/полосу, смотреть водопад
```

## Запись и воспроизведение IQ

Записанный IQ можно анализировать офлайн:

```bash
# Запись в файл (комплексные 8-битные сэмплы)
rtl_sdr -f 433920000 -s 1024000 capture.iq
# Воспроизведение из файла (для повторного анализа)
rtl_fm -f 433920000 -s 1024000 -r 48000 capture.iq | aplay -r 48000 -f S16_LE
# Просмотр в inspectrum
inspectrum -r 1024000 capture.iq
```

inspectrum показывает спектрограмму и позволяет «прицелиться» на сигнал, измерить длительность импульсов — это основа для ручного декодирования.

## Декодирование

Для распространённых протоколов есть готовые декодеры:

- **rtl_433** — погодные датчики, пульты, счётчики (множество протоколов).
- **multimon-ng** — POCSAG, FLEX, DTMF, Morse, AFSK.
- **dump1090** — ADS-B (авиация).
- **direwolf** — AX.25/APRS.
- **Universal Radio Hacker (URH)** — реверс и декодирование произвольных протоколов.

```bash
# Декодировать 433 МГц датчики/пульты
rtl_433 -f 433920000 -s 250000
# Пейджинг POCSAG
rtl_fm -f 153350000 -s 22050 - | multimon-ng -t raw -a POCSAG1200 -
```

## Разобранный пример: пульт 433 МГц

```bash
# 1. Найти частоту (скан спектра)
rtl_power -f 433M:434M:10k -i 1 -e 30 scan.csv
# (смотрим пики -> 433.92 МГц)
# 2. Записать IQ
rtl_sdr -f 433920000 -s 1024000 -g 40 -n 20000000 remote.iq
# 3. Проанализировать в inspectrum (найти импульсы)
inspectrum -r 1024000 remote.iq
# 4. Попробовать автодекодер
rtl_433 -r remote.iq
# 5. Если протокол неизвестен -> URH
#    URH: import -> autodetect parameters -> decode -> export
```

После декодирования видно битовую последовательность (ID пульта + код кнопки). Её можно воспроизвести (replay) через HackRF/Yard Stick One — см. `hardware-subghz`.

## Аппаратура

| Устройство | Диапазон | Особенности |
|-----------|----------|-------------|
| RTL-SDR | 24–1766 МГц | дешёвый, только приём |
| HackRF One | 1–6000 МГц | приём+передача, half-duplex |
| Airspy | 24–1800 МГц | высокое качество приёма |
| SDRplay | 1 кГц–2 ГГц | широкий диапазон |
| Yard Stick One | sub-GHz | передача (для replay) |
| Flipper Zero | sub-GHz/BLE | удобный, встроенный |

Для **replay** нужен передатчик (HackRF, YS1), для **сниффинга** достаточно RTL-SDR.

## Правовые аспекты

Приём — обычно законен, но **передача** в чужие диапазоны — нет. Регулируется лицензированием (в РФ — ГКРЧ/Роскомнадзор). В лаборатории передавайте в экранированном боксе или на малой мощности в разрешённых диапазонах. Пентест радиоканалов — только с письменным согласием владельца системы.

## Частые ошибки и подводные камни

- **Перегрузка (gain слишком высок)**: «зеркала» и мусор — снижайте усиление.
- **Sample rate > USB**: RTL-SDR на 3.2 МГц может терять сэмплы.
- **Не тот ppm-корректировка**: дешёвые донглы «плывут» по частоте; задайте `-p`.
- **Антенна не в диапазоне**: 433 МГц пульт не поймать на 1090 МГц антенну.
- **Запись 8-бит теряет динамику**: для слабых сигналов используйте 16-бит (Airspy/HackRF).

## Антенны и фронтенд

Даже лучший SDR бесполезен с плохой антенной. Базовые соображения:

- **Резонанс**: длина антенны подбирается под длину волны (для 433 МГц — четверть волны ≈ 17 см).
- **Тип**: диполь, штырь, логопериодическая, Yagi (направленная), дисхон.
- **Кабель и разъёмы**: потери в дешёвом коаксиале на высоких частотах заметны; используйте SMA-переходники с минимальными потерями.
- **Усилитель (LNA)**: помогает на слабых сигналах, но добавляет шум; ставить ближе к антенне.
- **Фильтр**: полосовой фильтр перед приёмником убирает мощные соседние сигналы (соты, FM-станции), которые «забивают» донгл.

Для пентеста sub-GHz часто достаточно простого штыря нужной длины. Для дальних целей — направленная антенна и LNA.

## Помехи, интермодуляция и фильтрация

Реальный эфир полон мощных сигналов. Дешёвый RTL-SDR без фильтров «слепнет» рядом с FM-вещанием или сотовыми вышками. Признаки проблем: шумовые «горбы», ложные пики, сигналы, которые «плывут». Решения:

- Включить/настроить встроенный **bias-tee** и внешний LNA.
- Добавить **FM-нотч** (фильтр-пробка на 88–108 МГц).
- Снизить усиление и использовать АРУ осторожно.
- Использовать SDR с лучшим динамическим диапазоном (Airspy, SDRplay).
- Для узкополосных сигналов — сузить полосу и применить FIR-фильтр в GNU Radio.

Понимание этих эффектов отличает «слышу шум» от «декодирую протокол».

## Частотные диапазоны: что где искать

Полезно держать в голове карту частот:

| Диапазон | Что там |
|----------|---------|
| 27 МГц | CB-рации |
| 88–108 МГц | FM-вещание |
| 118–137 МГц | авиация (AM) |
| 144–146 МГц | радиолюбители (2 м) |
| 315/433/868/915 МГц | пульты, датчики, IoT (ISM) |
| 1090 МГц | ADS-B (авиация) |
| 1575 МГц | GPS L1 |
| 2400 МГц | Wi-Fi, BLE, Zigbee |
| 2400–2500 МГц | дроны (видео/управление) |

Для hardware-пентеста чаще всего интересны **sub-GHz ISM** (пульты, датчики) и **2.4 ГГц** (BLE, Zigbee, Wi-Fi). Начните с обзора `rtl_power` по нужному диапазону, затем записывайте найденные сигналы и декодируйте.

## Итог

SDR превращает радио в данные. Поняв IQ-сэмплы, модуляции и инструменты (rtl_sdr, gqrx, inspectrum, rtl_433, URH), вы можете находить, записывать и декодировать беспроводные протоколы — от простых пультов до датчиков. Дальше — GNU Radio и replay для полного цикла.
