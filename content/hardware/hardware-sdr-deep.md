## Вопрос, с которого всё начинается

У тебя в руках неизвестный пульт, работающий где-то около 433 МГц, и записанный с эфира файл `capture.iq`. Автодекодер `rtl_433` его не понимает: протокол самодельный. Как разобрать сигнал с нуля — понять модуляцию, вытащить биты и собрать из них данные? Для этого нужно понимать, что такое IQ-сэмплы и модуляции. Этим и займёмся.

## Что такое IQ-сэмплы

Радиосигнал — величина комплексная. SDR выдаёт поток **комплексных отсчётов**: **I** (in-phase, синфазная) и **Q** (quadrature, квадратурная). Каждый сэмпл — точка на комплексной плоскости; из неё восстанавливаются амплитуда и фаза, а значит — любая модуляция.

**Частота дискретизации** (`sample rate`) задаёт ширину полосы: 2.4 МГц у RTL-SDR означает, что видно 2.4 МГц вокруг центральной частоты. Правило Найквиста: чтобы увидеть сигнал шириной W, нужно `sample_rate >= W`. Если сигнал шире полосы захвата, он «расползётся» и не декодируется.

## Модуляции

| Модуляция | Принцип | Где встречается |
|-----------|---------|-----------------|
| AM/ASK/OOK | амплитуда | пульты 433 МГц, датчики |
| FM/FSK | частота | рации, телеметрия, BLE (GFSK) |
| PSK | фаза | Wi-Fi, Zigbee (OQPSK) |
| QAM | амплитуда+фаза | DVB, кабельное ТВ |
| OFDM | много несущих | Wi-Fi, DVB, LTE |

Простые устройства (пульты, погодные датчики) используют **OOK/ASK** или **FSK** — их проще всего декодировать. Сложные (Wi-Fi, Zigbee) требуют полноценных демодуляторов.

## Наш пример: неизвестный пульт 433 МГц

Итак, у нас `capture.iq`, записанный на 433.92 МГц с частотой дискретизации 1.024 Мвыб/с. Проведём его от файла до битов.

## Шаг 1: настройка приёмника и запись

Три параметра определяют приём: **center frequency** (центр), **sample rate** (полоса) и **gain** (усиление; слишком много → перегрузка и «зеркала»). Записываем IQ:

```bash
rtl_sdr -f 433920000 -s 1024000 -g 40 -n 20000000 capture.iq
```

`-n 20000000` — 20 млн сэмплов, примерно 20 секунд эфира. Для быстрого обзора диапазона сначала полезен сканер спектра:

```bash
rtl_power -f 433M:434M:10k -i 1 -e 30 scan.csv
```

`scan.csv` покажет, на каких частотах есть устойчивые пики — там и живёт наш пульт.

## Шаг 2: смотрим сигнал глазами

Открываем запись в `inspectrum` — программе для анализа IQ-файлов:

```bash
inspectrum -r 1024000 capture.iq
```

inspectrum рисует **спектрограмму** (частота по вертикали, время по горизонтали, яркость = мощность). Нажимая кнопку пульта, видим периодические «пакеты». Увеличиваем масштаб: внутри пакета — серия импульсов. Так мы «прицеливаемся» и измеряем длительности.

## Шаг 3: определяем модуляцию

Если сигнал то появляется, то исчезает на одной частоте — это **OOK** (несущая включается/выключается). Если несущая «прыгает» между двумя частотами — это **FSK**. OOK виден в inspectrum как чередование ярких и пустых полос. От этого зависит, какой демодулятор собирать.

## Шаг 4: пробуем автодекодер

Прежде чем разбирать вручную, скормим запись готовым декодерам — они знают десятки протоколов:

```bash
rtl_433 -r capture.iq
```

Для распространённых устройств этого достаточно. Если протокол самодельный, `rtl_433` промолчит — тогда идём в **Universal Radio Hacker (URH)**: это GUI для реверса произвольных сигналов.

```
URH: import capture.iq -> autodetect parameters -> decode -> export
```

URH автоматически подбирает модуляцию и параметры, показывает демодулированный поток, из которого видно битовую последовательность (ID устройства + код кнопки). Её можно экспортировать и использовать для replay через HackRF/Yard Stick One (см. `hardware-subghz`).

## Декодирование известных протоколов

| Инструмент | Что декодирует |
|-----------|----------------|
| `rtl_433` | погодные датчики, пульты, счётчики |
| `multimon-ng` | POCSAG, FLEX, DTMF, Morse, AFSK |
| `dump1090` | ADS-B (авиация) |
| `direwolf` | AX.25/APRS |
| `URH` | произвольные протоколы |

```bash
# Пейджинг POCSAG
rtl_fm -f 153350000 -s 22050 - | multimon-ng -t raw -a POCSAG1200 -
```

## Аппаратура

| Устройство | Диапазон | Особенности |
|-----------|----------|-------------|
| RTL-SDR | 24–1766 МГц | дешёвый, только приём |
| HackRF One | 1–6000 МГц | приём+передача, half-duplex |
| Airspy | 24–1800 МГц | высокое качество приёма |
| SDRplay | 1 кГц–2 ГГц | широкий диапазон |
| Yard Stick One | sub-GHz | передача (для replay) |
| Flipper Zero | sub-GHz/BLE | удобный, встроенный |

Для **replay** нужен передатчик (HackRF, YS1), для **сниффинга** достаточно RTL-SDR.

## Антенны и фронтенд

Даже лучший SDR бесполезен с плохой антенной:

- **Резонанс.** Длина антенны подбирается под длину волны (для 433 МГц четверть волны ≈ 17 см).
- **Тип.** Диполь, штырь, логопериодическая, Yagi (направленная).
- **LNA.** Усилитель помогает на слабых сигналах, но добавляет шум — ставить ближе к антенне.
- **Фильтр.** Полосовой фильтр убирает мощные соседние сигналы (соты, FM-станции), которые «забивают» донгл.

## Помехи, интермодуляция и фильтрация

Реальный эфир полон мощных сигналов. Дешёвый RTL-SDR без фильтров «слепнет» рядом с FM-вещанием или сотовыми вышками. Признаки проблем: шумовые «горбы», ложные пики, «плывущие» сигналы. Решения: включить **bias-tee** и внешний LNA, добавить **FM-нотч** (фильтр-пробку на 88–108 МГц), снизить усиление, взять SDR с лучшим динамическим диапазоном (Airspy, SDRplay), сузить полосу и применить FIR-фильтр в GNU Radio.

## Частотные диапазоны: что где искать

| Диапазон | Что там |
|----------|---------|
| 88–108 МГц | FM-вещание |
| 118–137 МГц | авиация (AM) |
| 315/433/868/915 МГц | пульты, датчики, IoT (ISM) |
| 1090 МГц | ADS-B (авиация) |
| 1575 МГц | GPS L1 |
| 2400 МГц | Wi-Fi, BLE, Zigbee |
| 2400–2500 МГц | дроны (видео/управление) |

Для hardware-пентеста чаще интересны **sub-GHz ISM** и **2.4 ГГц**. Начните с обзора `rtl_power`, затем записывайте найденные сигналы и декодируйте.

## Правовые аспекты

Приём — обычно законен, но **передача** в чужие диапазоны — нет. Регулируется лицензированием. В лаборатории передавайте в экранированном боксе или на малой мощности. Пентест радиоканалов — только с письменным согласием владельца.

## Если не сработало

- **Перегрузка (gain слишком высок).** «Зеркала» и мусор — снижайте усиление.
- **Sample rate > USB.** RTL-SDR на 3.2 МГц может терять сэмплы.
- **Не та ppm-коррекция.** Дешёвые донглы «плывут» по частоте — задайте `-p`.
- **Антенна не в диапазоне.** Пульт 433 МГц не поймать на 1090 МГц антенну.
- **8-бит теряет динамику.** Для слабых сигналов берите 16-бит (Airspy/HackRF).

## Что мы теперь знаем

1. SDR отдаёт поток комплексных IQ-отсчётов, из которых восстанавливаются амплитуда и фаза.
2. Sample rate задаёт полосу; по Найквисту она должна быть не уже сигнала.
3. Простые устройства — OOK/ASK и FSK; их видно в inspectrum.
4. Известные протоколы декодируют `rtl_433`/`multimon-ng`, неизвестные — URH.
5. Антенна, gain и фильтрация определяют, увидишь ли ты сигнал вообще.

## Куда дальше

Мы разобрали сигнал до битов и знаем, как выбрать модуляцию. Дальше соберём из этих кубиков собственный обработчик — граф в GNU Radio, где приём, фильтрация и демодуляция соединяются в один поток (`hardware-gnuradio`). А пока главное запомни: IQ — это сырьё, а модуляция — ключ к его декодированию.
