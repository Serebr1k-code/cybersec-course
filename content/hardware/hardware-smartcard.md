Контактная смарт-карта (ISO 7816) — это мини-компьютер с файловой системой и командами. Банковские карты, SIM, паспорта, ID — всё это смарт-карты. Обмен идёт командами APDU, а карта хранит данные в файлах, доступ к которым защищён PIN-кодами и криптографией. Урок — практическое введение в их исследование.

## Теория

Карта имеет контакты (C1–C8): Vcc, RST, CLK, GND, Vpp, I/O (данные), и т.д. Обмен — полудуплексный, асинхронный (T=0/T=1).

**APDU** (Application Protocol Data Unit) — команда:

```
CLA INS P1 P2 Lc Data Le
```

| Поле | Значение |
|------|----------|
| CLA | класс команды (00 = стандарт, 80/00 = ISO) |
| INS | инструкция (A4 = SELECT, B0 = READ BINARY, 20 = VERIFY PIN) |
| P1/P2 | параметры |
| Lc | длина данных |
| Data | данные |
| Le | ожидаемая длина ответа |

Ответ: `Data SW1 SW2`, где `SW1SW2` — статус (9000 = успех, 6A82 = файл не найден, 6982 = условия не выполнены).

Типовые INS:
- `A4` SELECT — выбрать файл/приложение (по AID).
- `B0` READ BINARY — читать прозрачный файл.
- `B2` READ RECORD — читать запись.
- `20` VERIFY — проверить PIN.
- `88` INTERNAL AUTHENTICATE — аутентификация карты.
- `82` EXTERNAL AUTHENTICATE — аутентификация хоста.

Файловая система: MF (master) → DF (dedicated, приложения) → EF (elementary, данные). Доступ к EF регулируется условиями (ALW, PIN, ADM).

## Инструменты и команды

- **pyscard** — Python-обмен с картой.
- **pcsc-tools** (`pcsc_scan`) — определение карты.
- **GlobalPlatformPro** — работа с JavaCard.
- **OpenSC / opensc-tool** — стандартные операции.
- **Proxmark3** — контактный интерфейс (через adapter).
- **Осциллограф/логический анализатор** — перехват I/O.

```bash
# Определить карту
pcsc_scan
# Вывод: Card ATR: 3B 6F 00 FF ...

# opensc-tool
opensc-tool --list-readers
opensc-tool -r 0 --atr
opensc-tool -r 0 -s "00 A4 04 00 00"     # SELECT MF

# pyscard
python - <<'PY'
from smartcard.System import readers
r = readers()[0]
conn = r.createConnection()
conn.connect()
print('ATR:', conn.getATR())
# SELECT by AID (пример: Visa)
apdu = [0x00,0xA4,0x04,0x00,0x07,0xA0,0x00,0x00,0x00,0x03,0x10,0x10]
data, sw1, sw2 = conn.transmit(apdu)
print(f'SW={sw1:02X}{sw2:02X}')
PY
```

## Разобранный пример: чтение структуры SIM-карты

**Дано:** SIM-карта, ридер, pyscard. Нужно понять, какие данные читаются.

**Шаг 1 — ATR.** `pcsc_scan` показывает ATR — по нему определяют тип карты.

**Шаг 2 — SELECT MF.** Отправляем `00 A4 00 00 00` — выбираем мастер-файл. Ответ `9F xx` (размер ответа) или `9000`.

**Шаг 3 — SELECT DF GSM.** `00 A4 00 00 02 7F 20` — выбираем каталог GSM.

**Шаг 4 — SELECT EF ICCID.** `00 A4 00 00 02 2F E2` — выбираем файл ICCID.

**Шаг 5 — READ BINARY.** `00 B0 00 00 0A` — читаем 10 байт. Получаем ICCID (серийник SIM), возможно в BCD-кодировке.

**Шаг 6 — защищённые файлы.** Файлы с телефонной книгой/сообщениями защищены PIN. `VERIFY` (`00 20 00 01 08 <pin>`) с 3 попытками — при исчерпании карта блокируется. Не перебирайте PIN вслепую.

## Частые ошибки

- **Перебор PIN.** 3 неверных попытки = блокировка (PUK). Никогда не брутфорсите PIN на реальной карте.
- **Неверный ATR/протокол.** T=0 vs T=1 — разные тайминги. Библиотека обычно решает автоматически.
- **Нет Le в APDU.** Некоторые карты требуют явный Le; без него — ошибка 6700 (wrong length).
- **Игнорирование SW.** Всегда проверяйте `SW1SW2`; `9000` — успех, иначе причина отказа.
- **Питание карты.** Скачки напряжения могут «залочить» карту. Используйте штатный ридер.
- **Правовые рамки.** Чтение чужой SIM/банковской карты — преступление. Только своя/тестовая карта.

## APDU: структура и команды

Смарт-карта (ISO 7816) общается через APDU. Команда: `CLA INS P1 P2 Lc Data Le`. Ответ: `Data SW1 SW2`. Примеры:

| Команда | CLA INS | Назначение |
|---------|---------|------------|
| SELECT | 00 A4 | выбрать приложение/файл |
| READ BINARY | 00 B0 | читать данные |
| GET RESPONSE | 00 C0 | забрать ответ |
| VERIFY | 00 20 | проверка PIN |
| INTERNAL AUTH | 00 88 | аутентификация |

Статус `9000` — успех, `6A82` — файл не найден, `6982` — не удовлетворены условия безопасности.

## Разобранный пример 2: структура SIM

1. `pcsc_scan` находит SIM-ридер.
2. SELECT MF (master file) → `A0 A0 ...`.
3. Перебор файлов: `3F00` (MF), `7F20` (DF GSM), `6F07` (IMSI).
4. READ BINARY для чтения IMSI/ICCID (на своей SIM).
5. Вывод: какие данные доступны без PIN, какие защищены.

## Защита

- PIN/PUK, блокировка после неудачных попыток.
- Криптографические апплеты (JavaCard).
- Аттестация апплетов.
- Защита от side-channel (маскирование, случайные задержки).

## Почему смарт-карты сложнее клонировать

В отличие от 125 кГц-карт, смарт-карта выполняет код и хранит секреты в защищённой памяти. Клонирование требует либо извлечения ключей (side-channel, fault injection), либо атаки на реализацию апплета. Обычное чтение даёт лишь публичные данные. Именно поэтому банковские карты и SIM используют именно этот класс. Для пентеста это означает: работайте с моделью угроз — ищите не «клон», а уязвимость в апплете (неверная проверка PIN, логическая ошибка) или слабую криптографию.

## Практика: своя карта и логическая ошибка

Возьмите свою карту (банковскую или SIM, принадлежащую вам) и прочитайте APDU-обмен через pyscard. Обратите внимание, какие команды проходят без PIN, а какие возвращают `6982`. Часто уязвимость — не в криптографии, а в логике: проверка PIN реализована так, что при определённой последовательности команд флаг «аутентифицирован» остаётся установленным. Такие ошибки ищут фаззингом APDU и анализом апплета (если есть его код или можно дизассемблировать). Для JavaCard-апплетов используйте GlobalPlatformPro для инвентаризации и тестирования на своём экземпляре. Никогда не работайте с чужими картами — это прямое нарушение закона.
