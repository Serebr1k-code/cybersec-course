## Зачем этот урок

RTL-SDR — дешёвый USB-донгл (чип RTL2832U), превращающий компьютер в программно-определяемый приёмник 24–1766 МГц. С него начинается практическая радиоразведка: увидеть сигнал в спектре, записать его как IQ и декодировать. Этот урок — полный рабочий процесс от установки до перехвата датчика и пейджера.

## Что такое SDR и RTL-SDR

SDR (Software Defined Radio) — приёмник, где обработка сигнала делается в софте, а не аналоговой схемой. RTL-SDR — самый дешёвый вход: за копейки вы получаете приёмник, а вся демодуляция — в GNU Radio/GQRX. Ограничения: приём только (не передача), полоса до ~3.2 Мвыб/с, частоты примерно 24–1766 МГц.

## Установка и проверка донгла

```bash
sudo apt install rtl-sdr gqrx-sdr gnuradio rtl-433 multimon-ng
rtl_test -t              # проверка донгла (найдёт RTL2838)
rtl_sdr -h               # сырой IQ
```

`rtl_test -t` покажет диапазон и наличие E4000/R820T-тюнера. Если донгл не найден — проверьте udev-правила и занятость устройства другим процессом.

## Поиск сигнала: спектр и водопад

```bash
gqrx                     # выбрать устройство, диапазон, увидеть пики
```

В gqrx настройте центр частоты и полосу, gain — «auto» или вручную. Водопад покажет повторяющиеся пакеты (датчики передают периодически). Типичные цели: 433.92 МГц (EU), 315 МГц (US), 868 МГц (EU), 915 МГц (US).

## rtl_power: сканирование диапазона

```bash
rtl_power -f 433M:435M:12.5k -g 40 -i 1 -e 60 scan.csv
```

`rtl_power` строит карту мощности по диапазону: где есть устойчивый пик — там сигнал. Результат (`scan.csv`) визуализируют heatmap-утилитами. Это лучший способ быстро найти активные частоты в незнакомой местности.

## Запись IQ: параметры

```bash
rtl_sdr -f 433920000 -s 2400000 -g 40 -n 24000000 capture.iq
```

`-f` — центр частоты, `-s` — sample rate, `-g` — gain, `-n` — число отсчётов. IQ-файл — сырые I/Q-отсчёты (uint8, чередование I и Q). Пишите ≥5–10 секунд: пакеты короткие и периодические.

## inspectrum: анализ IQ

```bash
inspectrum capture.iq
```

В inspectrum видно водопад записанного файла; можно выделить пакет, измерить длительности символов, подобрать модуляцию и даже декодировать вручную. Параметры: sample rate, центр, число бит на символ.

## rtl_433: автодекод ISM

```bash
rtl_433 -f 433.92M -g 40           # автодекод всех протоколов
rtl_433 -f 433.92M -F json         # JSON для скриптов
rtl_433 -R help                    # список протоколов
rtl_433 -f 433.92M -S all          # сохранить дампы
```

Пример: `{"model":"Nexus-T","id":12345,"channel":1,"battery_ok":1,"temperature_C":21.5}`. Из таких сообщений строятся replay-атаки.

## multimon-ng: пейджеры и цифровые

```bash
rtl_fm -f 439.9875M -s 22050 - | multimon-ng -t raw -a POCSAG1200 -
```

`multimon-ng` декодирует POCSAG/FLEX (пейджинг), AFSK, DTMF. Это классика CTF: перехват пейджинговых сообщений.

## GNU Radio: построение потока

GNU Radio — конструктор потоков обработки. Простой приёмник: `RTL-SDR Source -> Filter -> Demod -> Sink`. Полезные блоки: `Frequency Xlating FIR Filter` (сдвиг/фильтр), `Quadrature Demod` (FM), `Rational Resampler` (передискретизация), `File Sink`/`File Source`.

## Модуляции: OOK/ASK, FSK, PSK

Пульты и датчики чаще всего используют **OOK/ASK** (включение/выключение несущей) или **FSK** (частотная манипуляция). OOK распознаётся как «всплески» в inspectrum. Понимание модуляции нужно для ручного декодирования, когда автодекодер не знает протокол.

## Разобранный пример: датчик температуры

1. Обзор: `gqrx` показывает пик на 433.92 МГц.
2. `rtl_433 -f 433.92M -g 40 -F json` → `{"temperature_C":21.5,...}`.
3. Запись IQ конкретного пакета: `rtl_sdr -f 433.92M -s 2.4M -n 5M packet.iq`.
4. `inspectrum` → модуляция OOK/ASK, длительности.
5. Replay через Flipper/CC1101 (см. `hardware-subghz`).

## Разобранный пример: перехват пейджера

1. Находим частоту пейджинга (`rtl_power` по 439–440 МГц).
2. `rtl_fm -f <FREQ> -s 22050 - | multimon-ng -t raw -a POCSAG1200 -`.
3. Читаем текст сообщений. В CTF флаг часто приходит в пейджинговом сообщении.

## Антенны и согласование

На 433 МГц нужна четвертьволновая антенна ~17 см; на 868 МГц — ~8 см. Без согласованной антенны сигнал почти не принимается. Для приёма слабых сигналов — направленная антенна и малошумящий усилитель (LNA). Не забывайте: приём безвреден, передача — регулируется законом.

## DC-пик, зеркала и артефакты

В центре спектра всегда есть **DC-пик** от донгла — он мешает слабым сигналам. Сдвиньте центр на 100–200 кГц, чтобы сигнал ушёл от пика. Зеркальные частоты и интермодуляция — типичные артефакты дешёвых донглов.

## Правовые аспекты

Приём общедоступного эфира в большинстве юрисдикций безобиден, но **декодирование и особенно передача/реплей** защищённых сигналов может нарушать закон (например, перехват чужих пейджинговых сообщений). Работайте только с собственными устройствами или в рамках авторизованного пентеста.

## Частые ошибки

- **Мало gain или плохая антенна.** Без антенны сигнала не видно.
- **Путать sample rate и центр.** Сигнал должен попадать в полосу `-s`.
- **Записывать слишком коротко.** Пишите ≥5–10 секунд.
- **Пробовать TCP-декодер.** `rtl_433` нужен прямой доступ к донглу.
- **Забыть про DC-пик.** Сдвиньте частоту.

## Что дальше / решение

- Быстро декодировать ISM → `rtl_433`.
- Произвольный сигнал → IQ + inspectrum + GNU Radio.
- Реплей → `hardware-subghz` (Flipper/CC1101).
- Смежные: `hardware-rf`, `hardware-subghz`, `hardware-rf-protocols`.

## Драйверы, udev и совместимость

На Linux конфликт с драйвером DVB-T мешает `rtl_sdr` — добавьте blacklist для `dvb_usb_rtl28xxu`:

```bash
echo 'blacklist dvb_usb_rtl28xxu' | sudo tee /etc/modprobe.d/blacklist-rtl.conf
sudo udevadm control --reload && sudo udevadm trigger
```

Проверьте права: без udev-правила донгл доступен только root. Создайте `/etc/udev/rules.d/20-rtlsdr.rules` с правилом для vendor `0bda`. На Windows ставьте драйвер через Zadig (WinUSB).

## LNA, bias-tee и фильтры

Для слабых сигналов: внешний **LNA** (малошумящий усилитель) у антенны, **bias-tee** для питания LNA по коаксиалу, полосовой **фильтр** для подавления сильных соседних станций (иначе перегрузка и интермодуляция). Донглы с R820T2 чувствительнее, чем старые E4000 на высоких частотах.

## Запись и обмен IQ

IQ-файлы большие: 2.4 Мвыб/с × 2 байта = ~4.8 МБ/с. Для обмена в CTF записывайте короткие окна и сжимайте (`gzip`). Формат `cu8` (uint8) — стандарт; конвертация в `cf32` (complex float) нужна некоторым SDR-программам. Метаданные (частота, sample rate) храните отдельно — без них IQ бесполезен.

## Итоговый чеклист рабочего процесса

1. Проверить донгл (`rtl_test -t`), настроить антенну.
2. Обзор диапазона (`gqrx`/`rtl_power`).
3. Найти пик, определить модуляцию.
4. Записать IQ (≥5–10 с).
5. Декодировать: `rtl_433`/`multimon-ng`, иначе inspectrum + GNU Radio.
6. Задокументировать частоту, sample rate, модуляцию.

## Частые частоты и протоколы ISM

| Частота | Регион | Устройства |
|---------|--------|-----------|
| 315 МГц | US | пульты, датчики |
| 433.92 МГц | EU/Asia | пульты, метео, TPMS |
| 868 МГц | EU | сигнализации, датчики |
| 915 МГц | US | IoT, счётчики |

Для каждой частоты `rtl_433` знает десятки протоколов. Если автодекод молчит — определите модуляцию в inspectrum и декодируйте вручную: измерьте длительность «единицы» и «нуля», соберите битовый поток, найдите синхрослово и CRC.
