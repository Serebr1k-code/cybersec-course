**OBD-II** — стандартизированный диагностический интерфейс, обязательный в автомобилях с 1996 года. Через 16-контактный разъём под рулём доступны диагностические сервисы и, что важнее для пентеста, **CAN-шины** автомобиля. Дешёвый адаптер ELM327 и ноутбук с `can-utils` дают полноценную площадку для анализа. Этот урок — практика: как подключиться, что читать и как воспроизводить кадры.

## Разъём и пины

Разъём OBD-II — трапеция с 16 контактами. Ключевые пины:

| Пин | Назначение |
|-----|-----------|
| 4 | GND (масса) |
| 5 | Signal ground |
| 6 | CAN-H (ISO 15765-4, 500 кбит/с) |
| 14 | CAN-L |
| 16 | +12 В (питание) |
| 7 | K-line (старые, ISO 9141) |
| 15 | L-line |

Современные машины используют CAN на пинах 6/14 (и иногда 3/11 для второй шины). Питание на 16 позволяет адаптеру работать от машины.

## Адаптеры

| Адаптер | Интерфейс | Особенности |
|---------|-----------|-------------|
| ELM327 | USB/Bluetooth | дешёвый, только диагностика |
| CANtact | USB | «сырой» CAN, открытый |
| USB2CAN | USB | промышленный |
| Macchina M2 | Arduino | программируемый |
| Raspberry Pi + MCP2515 | SPI | гибкий DIY |
| PEAK PCAN | USB | профессиональный |

Для пентеста нужен адаптер, дающий **сырой** доступ к CAN (CANtact, M2), а не только OBD-команды (ELM327). ELM327 удобен для быстрой диагностики, но ограничен.

## SocketCAN и can-utils

В Linux CAN-адаптер представляется сетевым интерфейсом (socketcan). Это элегантно: те же `ip`, `tcpdump`-подобные инструменты.

```bash
# Поднять интерфейс (для MCP2515 через SPI или USB-адаптера)
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up
ip -details link show can0

# Прослушать шину
candump can0
# (09:12:34.567890) can0 2F0#0102030405060708
# (09:12:34.568100) can0 3A0#0000

# Отправить кадр
cansend can0 123#DEADBEEF
# Генератор трафика
cangen can0 -g 10 -I 123 -L 8

# Логировать и анализировать
candump -L can0 > can.log      # в формате candump
candump can0 | grep 2F0
```

## Чтение DTC и PID

Диагностические данные читаются через сервисы OBD-II (Mode 01 — текущие данные, Mode 03 — коды ошибок). Через ELM327:

```bash
# python-OBD
python3 -c "
import obd
conn = obd.OBD()  # авто-определит порт и протокол
print('RPM:', conn.query(obd.commands.RPM).value)
print('SPEED:', conn.query(obd.commands.SPEED).value)
print('DTC:', conn.query(obd.commands.GET_DTC).value)
"
```

`PID` (Parameter ID) — стандартные идентификаторы данных: обороты, скорость, температура. Их можно читать и подделывать.

## Разобранный пример: анализ действий водителя

```bash
# 1. Подключить адаптер, поднять can0
sudo ip link set can0 up type can bitrate 500000
# 2. Записать трафик при нажатии кнопок на руле/дверях
candump -L can0 > drive.log &
DUMP_PID=$!
echo "Нажмите кнопки: открыть дверь, свет, стекло..."
sleep 60
kill $DUMP_PID
# 3. Найти изменяющиеся ID
awk '{print $3}' drive.log | sort | uniq -c | sort -rn | head -20
# 4. Взять подозрительный ID и посмотреть его кадры
grep '1A0' drive.log | head
# 5. Воспроизвести действие
cansend can0 1A0#0100000000000000
```

Сопоставляя момент нажатия с появлением/изменением кадров, определяют «команды». Это основа для спуфинга и автоматизации.

## Диагностические сервисы и UDS

Помимо базового OBD-II, производители используют **UDS** для расширенной диагностики: чтение/запись параметров, прошивка, разблокировка. UDS-запросы идут по тем же CAN-ID (обычно 0x7E0/0x7E8 для ECU двигателя). Последовательность `Security Access` (seed/key) защищает критичные операции.

```bash
# Пример UDS-обмена (через cansend, ID запроса 7E0, ответ 7E8)
cansend can0 7E0#02 10 03         # extended session
cansend can0 7E0#02 27 01         # request seed
candump can0 | grep 7E8           # ответ с seed
cansend can0 7E0#06 27 02 AA BB CC DD  # send key
```

Если алгоритм key слабый, его реверсируют из прошивки ECU (см. `hardware-firmware-extract`) и разблокируют блок.

## Атаки через OBD

- **DoS**: `cangen` с высоким приоритетом забивает шину.
- **Spoofing**: подделка кадров датчиков (скорость, обороты).
- **Replay**: воспроизведение записанных команд.
- **Разблокировка ECU**: через UDS Security Access → перепрошивка.
- **Считывание/запись EEPROM**: через диагностические сервисы.

## Частые ошибки и подводные камни

- **Неверный bitrate**: CAN не поднимется; перебирайте 125/250/500 кбит/с.
- **Терминаторы**: без 120 Ом на концах шины — ошибки и Bus-Off.
- **ELM327 «клоны»**: дешёвые адаптеры не поддерживают все протоколы и врут.
- **Запись без фильтра**: логи растут быстро; фильтруйте по ID.
- **Шлюз**: часть сообщений недоступна через OBD без диагностической сессии.
- **Запись в ECU необратима**: экспериментируйте на своём авто/симуляторе.

## Вторая CAN-шина и адресация

Многие автомобили имеют **несколько CAN-шин**: силовая (powertrain), кузовная (body/comfort), диагностическая. Разные шины доступны на разных пинах OBD-II (например, 6/14 и 3/11). Полезно понимать, что вы видите:

- **Powertrain CAN** (500 кбит/с) — двигатель, коробка; «жёсткие» сообщения.
- **Body/Comfort CAN** — двери, свет, стеклоподъёмники.
- **Diagnostic CAN** — диагностические запросы.

Если адаптер подключён только к одной шине, часть сообщений не видна. Для доступа к другой шине нужен мультипиновый адаптер или прямое подключение к нужным проводам.

## Автоматизация и скрипты

Для длительного анализа удобно писать скрипты:

```python
# Сбор и анализ CAN через python-can
import can, time, collections
bus = can.interface.Bus(channel='can0', bustype='socketcan')
seen = collections.Counter()
start = time.time()
while time.time() - start < 60:
    msg = bus.recv(timeout=1)
    if msg:
        seen[msg.arbitration_id] += 1
for cid, n in seen.most_common(20):
    print(hex(cid), n)
```

Дальше — сопоставление с действиями и поиск «команд». Для воспроизведения используйте `bus.send(can.Message(arbitration_id=0x1A0, data=..., is_extended_id=False))`.

## Правовые аспекты и безопасность

- Работать только со своим авто или в рамках согласованного пентеста.
- Не отправлять кадры в реальную шину без понимания последствий.
- Осторожно с диагностическими сервисами записи.
- На дорогах общего пользования — никаких экспериментов с шиной.

Безопасность: сегментация CAN, шлюзы с фильтрацией, IDS для CAN (например, на основе аномалий частоты), защита OBD-порта физически (замок/заглушка).

## Чтение и интерпретация данных

Помимо DTC, OBD-II даёт поток живых данных. Типовые PID и их смысл:

| PID | Данные |
|-----|--------|
| 0x0C | обороты двигателя |
| 0x0D | скорость |
| 0x05 | температура охлаждающей жидкости |
| 0x11 | положение дросселя |
| 0x2F | уровень топлива |
| 0x42 | напряжение модуля |

```bash
python3 -c "
import obd
c = obd.OBD()
for cmd in [obd.commands.RPM, obd.commands.SPEED, obd.commands.COOLANT_TEMP]:
    print(cmd.name, c.query(cmd).value)
"
```

Эти значения полезны для контекста: сопоставляя их с CAN-логами, вы понимаете, какие ID несут какую физическую величину.

## Безопасность OBD-порта

OBD-II — физическая дверь в шину автомобиля. Меры защиты:

- **Физическая блокировка** порта (замок, заглушка).
- **Аутентификация** диагностических операций (там, где поддерживается).
- **Мониторинг** аномальных диагностических сессий.
- **Сегментация**: OBD не должен давать доступ ко всем шинам.
- **Контроль** сервисных инструментов (кто и что подключал).

Для пентеста вывод: открытый OBD-порт — это полный доступ к CAN, поэтому его доступность в модели угроз надо учитывать.
