## Вопрос, с которого всё начинается

Есть карта-пропуск, которую нужно скопировать. Она выглядит обычной, но читается мгновенно — потому что это низкочастотная карта на 125 кГц. Такие карты (EM4100, HID Prox) не имеют криптографии: они просто повторяют свой ID.

Насколько просто их клонировать и почему? Разберём на практике.

## Наш пример: брелок EM4100

Перед нами офисный брелок — **EM4100** на 125 кГц. Есть **Proxmark3** и перезаписываемая болванка **T5577**. Задача: считать ID и записать его на болванку.

## Шаг 1: почему 125 кГц так просто

LF-карты передают статичный ID без аутентификации:

- **EM4100** — 40-битный ID, дешёвые брелоки и карты;
- **HID Prox** — форматы на 26/35/37 бит, распространён в офисах;
- **T5577** — перезаписываемая болванка, эмулирующая EM4100 и HID.

Ключевое: здесь нет **challenge-response** — механизма, где считыватель задаёт карте вопрос и проверяет ответ. Карта просто кричит свой номер, и считыватель его принимает. Отсюда — тривиальность клонирования.

| Карта | Частота | Криптография | Клонируется |
|-------|---------|--------------|-------------|
| EM4100 | 125 кГц | нет | да, тривиально |
| HID Prox | 125 кГц | нет | да |
| Mifare Classic | 13.56 МГц | Crypto1 (сломан) | да (autopwn) |
| Mifare DESFire | 13.56 МГц | AES | нет |

## Шаг 2: настраиваем антенну

Proxmark3 сначала нужно «настроить» — подстроить антенну под диапазон:

```
$ proxmark3 /dev/ttyACM0
> hw tune
```

`hw tune` проверяет и подстраивает антенну. Без этого шага чтение нестабильно: LF и HF используют разные антенны, и переключение между ними требует настройки.

## Шаг 3: читаем карту

Запускаем автоопределение:

```
> lf search
EM 410x ID 0F00A1B2C3
```

`lf search` перебирает все LF-протоколы и сообщает, что перед нами EM4100 с ID `0F00A1B2C3`. Если бы это был HID, вывод был бы `HID Prox TAG ID: ...`. Явное чтение конкретного типа тоже доступно: `lf em 410x_read` или `lf hid read`.

## Шаг 4: записываем на болванку

Теперь заливаем считанный ID на T5577-болванку:

```
> lf em 410x_write 0F00A1B2C3 1
```

`lf em 410x_write` записывает ID на перезаписываемую карту (последний аргумент — режим). Готово: болванка теперь отвечает тем же ID, что и оригинал. Если болванки нет, карту можно **эмулировать** прямо Proxmark3:

```
> lf em 410x sim 0F00A1B2C3
```

## Шаг 5: клонируем HID

С HID чуть сложнее: у этого формата есть **facility code** (код объекта) и **card number** (номер карты), а также разная длина (26/35/37 бит). Формат указывают флагом `-w`:

```
> lf hid clone --r 26 --id 2006ec1234
> lf hid sim -w H10301 --fc 118 --cn 1234
```

`--r 26` — формат H10301 на 26 бит, `--fc` и `--cn` — facility code и card number. Если перепутать формат, считыватель карту не примет.

## Шаг 6: проверяем клон

С Flipper Zero весь путь выглядит ещё проще: `125 kHz RFID → Read → Save → Write to T5577` или `Emulate`. На авторизованном пентесте клон проверяют на турникете: если проходит — уязвимость подтверждена. Иногда запись нужно повторить: у болванки могут быть «битые» блоки.

## Типы карт на 125 кГц

| Карта | Модуляция | Длина ID | Клонируется |
|-------|-----------|----------|-------------|
| EM4100/EM4102 | ASK/Manchester | 40 бит | да, тривиально |
| HID Prox (H10301) | FSK | 26 бит | да |
| HID Prox (Corporate 1000) | FSK | 35+ бит | сложнее |
| Indala | PSK | 32+ бит | зависит |
| T5577 (болванка) | перезаписываемая | любая | для клона |

Все они не имеют криптографии: карта просто передаёт ID. Считыватель не отличает оригинал от копии, потому что нечем — в протоколе нет ни секрета, ни проверки.

## Чем LF отличается от HF

| Параметр | 125 кГц (LF) | 13.56 МГц (HF) |
|----------|--------------|----------------|
| Протоколы | EM4100, HID Prox | Mifare Classic/Desfire, iClass |
| Криптография | нет | есть (Desfire), слабая (Classic) |
| Клонирование | тривиально | зависит от карты |
| Дальность | больше | меньше |

Вывод: LF-карты клонируются по определению. HF можно усилить криптографией, но Mifare Classic (Crypto1) взломан и тоже клонируется после извлечения ключей.

## Как защитить пропускную систему

1. Перейти на DESFire EV2/EV3 или SEOS.
2. Ввести PIN или биометрию как второй фактор.
3. Включить антипассбэк (запрет повторного входа без выхода).
4. Мониторить: одна карта в двух точках одновременно — сигнал клонирования.
5. Ротировать ключи и вести централизованный аудит.

Ни одна мера по отдельности не спасает от клона LF-карты — нужна комбинация криптографии, второго фактора и мониторинга.

## Команды Proxmark3 подробнее

Соберём вместе всё, что нужно для LF-работы:

```
proxmark3 /dev/ttyACM0
hw tune                     # настроить антенны
lf search                   # автоопределение карты
lf em 410x_read             # прочитать EM4100 -> ID
lf hid read                 # прочитать HID Prox
lf em 410x_write <ID> 1     # записать ID на T5577
lf em 410x_sim              # эмулировать EM4100
lf hid sim -w H10301 --fc 118 --cn 1234   # эмулировать HID
```

Флаги: `-w` задаёт формат, `--fc` — facility code, `--cn` — card number. `lf search` — самый быстрый старт: он перебирает все протоколы и сразу называет тип карты.

## Если не сработало

- **Путаница LF и HF.** 125 кГц и 13.56 МГц — разное оборудование и антенны.
- **Неверный формат HID.** Форматы 26/35/37 бит несовместимы — указывайте `--r`.
- **Забыли `hw tune`.** Без настройки антенны чтение нестабильно.
- **Не та болванка.** Для LF нужен T5577; для HF — другие метки.
- **Парольные биты.** У части T5577 есть защита от перезаписи — болванку придётся разблокировать.
- **Правовые рамки.** Клонирование пропусков — только авторизованно.

## Что мы теперь знаем

1. LF-карты (125 кГц) передают статический ID без криптографии.
2. `lf search` определяет карту, `lf em 410x_read` читает EM4100.
3. `lf em 410x_write` пишет ID на болванку T5577; можно и эмулировать.
4. HID требует указания формата (`--r`) и facility code.
5. Считыватель не отличает клон от оригинала, потому что в протоколе нет challenge-response — только повтор ID.

А пока запомни главное: LF-карты клонируются по определению, потому что передают статический ID без всякой проверки.
