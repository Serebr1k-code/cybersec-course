## Вопрос, с которого всё начинается

В прошлом уроке мы подключились к консоли роутера по UART и получили оболочку. Но оболочка — это уже запущенная система: часть данных она держит в памяти, часть — на диске, а некоторые секреты вообще доступны только root. Что, если забрать у устройства его «жёсткий диск» целиком и разбирать спокойно, офлайн, без риска что-то сломать?

Вот об этом урок: как снять копию микросхемы памяти.

## Наш пример: роутер с чипом памяти

Перед нами та же плата роутера. Рядом с большим чипом-процессором (его называют **SoC**, System-on-Chip) стоит маленькая восьминогaя микросхема с надписью `W25Q128`. Это **SPI-NOR флеш** — энергонезависимая память, в которой лежит вся прошивка: загрузчик, ядро и корневая файловая система со всеми паролями и ключами.

Наша цель: получить её полную копию — **дамп**. Дальше будем идти по шагам: понять, как чип устроен, подключиться к нему, снять копию, убедиться, что копия верная, и заглянуть внутрь.

## Шаг 1: как вообще читают такую память

Чип нельзя просто «открыть». С ним общаются по шине **SPI** (Serial Peripheral Interface) — это способ передавать данные по проводам, где один «ведущий» задаёт такт, а «ведомые» отвечают. У шины четыре линии:

| Линия | Что делает |
|-------|-----------|
| CLK (SCK) | тактовый сигнал — «стук метронома», под который идёт передача |
| MOSI (DI) | данные от ведущего к чипу |
| MISO (DO) | данные от чипа к ведущему |
| CS (SS) | «выбор чипа» — какая именно микросхема сейчас слушает |

Самый важный для нас факт: по команде `0x9F` чип отдаёт **JEDEC ID** — три байта, по которым можно точно определить модель и, главное, объём. Это первое, что мы спросим у чипа.

## Шаг 2: подключаемся программатором

Чтобы читать чип в обход процессора, берут **программатор** — маленькое устройство, которое само умеет говорить по SPI. Возьмём самый дешёвый, **CH341A**, и **SOIC8-клипсу**: это зажим, который цепляется прямо за ножки чипа, не требуя выпаивать его.

Плата при этом **обесточена** — это критично, и почему — разберём чуть ниже.

Управляет программатором утилита `flashrom`. Сначала просто спрашиваем, что за чип перед нами:

```
$ sudo flashrom -p ch341a_spi
flashrom v1.2 on Linux 6.5.0 (x86_64)
Found Winbond flash chip "W25Q128.V" (16384 kB, SPI) on ch341a_spi.
```

Мы узнали модель `W25Q128.V` и объём `16384 kB` — это 16 МБ. `-p ch341a_spi` — это указание «работай через программатор CH341A». Теперь мы знаем, сколько данных должно приехать.

## Шаг 3: снимаем дамп и проверяем его

Читаем чип в файл:

```
$ sudo flashrom -p ch341a_spi -r dump1.bin
Reading flash... done.
```

`-r dump1.bin` — «read», сохранить в файл. Казалось бы, готово. Но здесь прячется главная ловушка SPI.

Пока клипса висит на чипе, тот же чип подключён и к процессору SoC. Если на плате есть питание, SoC тоже обращается к памяти — и получается **два ведущих на одной шине**. Данные «плывут». Поэтому дамп снимают 2–3 раза и сравнивают контрольные суммы (**md5** — короткий отпечаток файла; совпали отпечатки — совпало и содержимое):

```
$ for i in 1 2 3; do sudo flashrom -p ch341a_spi -r dump$i.bin; done
$ md5sum dump1.bin dump2.bin dump3.bin
8f3a1c... dump1.bin
8f3a1c... dump2.bin
8f3a1c... dump3.bin
```

Все три отпечатка одинаковы — дамп **стабилен**, ему можно доверять. Если бы они разошлись, это означало бы конфликт с SoC: лечится полным обесточиванием платы, удержанием процессора в сбросе или выпаиванием чипа.

## Шаг 4: смотрим, что внутри

Теперь у нас 16 МБ сырых данных. Прошивка внутри разбита на разделы по фиксированным смещениям. Чтобы увидеть разметку, есть инструмент `binwalk` — он ищет в файле известные сигнатуры (заголовки загрузчиков, файловых систем) и показывает, где что начинается:

```
$ binwalk dump1.bin
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             U-Boot bootloader header
262144        0x40000         U-Boot environment
327680        0x50000         uImage header, Linux kernel
2097152       0x200000        Squashfs filesystem
12582912      0xC00000        JFFS2 filesystem
```

Читаем построчно: по смещению `0x0` — загрузчик **U-Boot**, дальше его переменные окружения (иногда там пароли), затем ядро Linux, а с `0x200000` начинается **Squashfs** — сжатая корневая файловая система. Именно она нам и нужна.

## Шаг 5: вырезаем корневую систему

Зная смещение (`0x200000` = 2097152) и размер, вырезаем только этот кусок утилитой `dd` (побайтовое копирование):

```
$ dd if=dump1.bin of=rootfs.squashfs bs=1 skip=$((0x200000)) count=$((0xA00000))
10485760 bytes copied
$ unsquashfs -d rootfs rootfs.squashfs
Parallel unsquashfs: Using 8 processors
created 1432 files, 289 directories
```

`unsquashfs` распаковала файловую систему в папку `rootfs`. Теперь можно искать секреты обычными текстовыми инструментами:

```
$ grep -r "root:" rootfs/etc/shadow
root:$1$xyz$...:0:0:root:/root:/bin/sh
```

Мы видим хеш пароля root — его можно попытаться вскрыть офлайн. Задача решена: без единого запроса по сети мы забрали всю прошивку и добрались до учётных данных.

## Что мы теперь знаем

По-простому:

1. SPI-NOR флеш хранит всю прошивку устройства; читают её программатором в обход SoC.
2. Модель и объём чипа узнают по JEDEC ID (`flashrom` без флагов).
3. Дамп снимают 2–3 раза и сверяют md5 — иначе «плавающие» данные.
4. Плата при чтении должна быть обесточена, иначе два ведущих на шине конфликтуют.
5. `binwalk` показывает разделы, `dd` + `unsquashfs` достают из них файловую систему.

## На что смотреть дальше

- **Дамп нестабилен (разные md5).** Обесточьте SoC, удерживайте его в reset или выпаяйте чип.
- **`No EEPROM/flash device found`.** Плохой контакт клипсы — переставьте её, проверьте ориентацию (ключ-точка у первого пина), протрите спиртом.
- **Чип не определяется автоматически.** Укажите модель вручную: `-c W25Q128.V`, но объём обязан совпадать.
- **Не пишите без бэкапа.** Команда `-w` затирает чип; без сохранённого оригинала устройство можно превратить в «кирпич».
- **Некоторые регионы защищены.** `flashrom` вернёт нули или ошибку — это не значит, что память пуста.

## Куда дальше

Теперь у нас на руках образ прошивки. В следующем уроке заглянем в самый его верх — в загрузчик U-Boot: он первым запускается на плате и часто хранит в своих переменных ключи к устройству. А пока запомни главное: SPI-флеш — это «диск» устройства, и снять его копию можно пятью долларами и парой команд.
