SPI-NOR флеш — это «жёсткий диск» большинства роутеров, камер и IoT-устройств. Здесь лежит загрузчик, ядро и корневая файловая система со всеми паролями и ключами. Умение снять корректный дамп SPI-флеша — ключевой навык: получив образ, вы работаете с устройством офлайн, без риска и без ограничений живой системы.

## Теория

**SPI (Serial Peripheral Interface)** — синхронная шина «ведущий-ведомые» с четырьмя линиями:

| Линия | Назначение |
|-------|-----------|
| **CLK / SCK** | такт |
| **MOSI / DI** | данные от ведущего (SoC) к ведомому (флеш) |
| **MISO / DO** | данные от флеша к ведущему |
| **CS / SS** | Chip Select — выбор чипа |

В отличие от I2C, SPI не имеет адресации: каждое устройство выбирается отдельной линией CS. Флеш обычно подключена к отдельному SPI-контроллеру SoC.

**SPI-NOR флеш** — типичные семейства: Winbond `W25Q*`, Macronix `MX25L*`, GigaDevice `GD25Q*`, Spansion/Infineon `S25FL*`. Ёмкость 1–32 МБ. Чипы отдают **JEDEC ID** (3 байта: производитель + тип + ёмкость) по команде `0x9F`, что позволяет точно определить модель.

**SPI-режимы (modes 0–3)** — комбинация полярности (CPOL) и фазы (CPHA) такта. Флеш обычно работает в mode 0 или mode 3; большинство инструментов перебирают автоматически.

**JEDEC ID** — ключ к успеху: определив чип, вы знаете его ёмкость и структуру секторов.

**Основные команды SPI-NOR:**

| Команда | Код | Назначение |
|---------|-----|-----------|
| JEDEC ID | `0x9F` | идентификация чипа |
| Read Data | `0x03` | чтение (низкая скорость) |
| Fast Read | `0x0B` | чтение (высокая скорость) |
| Write Enable | `0x06` | разрешить запись |
| Read Status | `0x05` | статус (в т.ч. WIP, защита) |
| Chip Erase | `0xC7` | стереть всё |
| Page Program | `0x02` | запись страницы |

## Инструменты и команды

- **CH341A** (программатор + SOIC8-клипса) — самый дешёвый путь, ~5 $.
- **flashrom** — чтение/запись SPI-флеша, поддерживает CH341A, Bus Pirate, Raspberry Pi.
- **Bus Pirate** — универсал, умеет SPI и определять JEDEC ID.
- **Raspberry Pi** — SPI на GPIO (MOSI=GPIO10, MISO=GPIO9, SCLK=GPIO11, CE0=GPIO8).
- **SOIC8-клипса** — чтение без выпаивания (но SoC может мешать).
- **PA1616/выпайка** — если клипса даёт нестабильный дамп.
- **binwalk / unsquashfs / jefferson** — разбор полученного дампа.

```bash
# flashrom с CH341A
sudo apt install flashrom
flashrom -p ch341a_spi          # определить чип (JEDEC ID)
# На Raspberry Pi (SPI включён через raspi-config)
flashrom -p linux_spi:dev=/dev/spidev0.0,spispeed=8000

# Пример вывода определения
# Found Winbond flash chip "W25Q128.V" (16384 kB, SPI) on ch341a_spi.

# Дамп (трижды для проверки стабильности)
sudo flashrom -p ch341a_spi -r dump1.bin
sudo flashrom -p ch341a_spi -r dump2.bin
sudo flashrom -p ch341a_spi -r dump3.bin
md5sum dump*.bin                # все три должны совпасть
```

## Определение чипа и подключение

1. **Найдите флеш.** Это 8-ногий (SOIC8) или 16-ногий чип рядом с SoC, часто с маркировкой `25Q...`. Читайте маркировку через лупу/макро.
2. **Найдите datasheet** по маркировке: он даёт распиновку (обычно 1=CS, 2=DO, 3=WP, 4=GND, 5=DI, 6=CLK, 7=HOLD, 8=VCC).
3. **Подключите клипсу** строго по распиновке, соблюдая ориентацию (ключ на корпусе — точка/фаска у 1-го пина).
4. **Определите чип** через `flashrom -p ch341a_spi`.
5. **Снимите дамп 2-3 раза** и сравните хэши — стабильный дамп совпадает.

## Разобранный пример: дамп роутера

**Дано:** роутер, флеш `W25Q128` (16 МБ), CH341A + SOIC8-клипса.

**Шаг 1 — подключение клипсы.** Ориентируем по ключу. Плата **обесточена** (важно!).

**Шаг 2 — определение:**
```bash
sudo flashrom -p ch341a_spi
# Found Winbond flash chip "W25Q128.V" (16384 kB, SPI) on ch341a_spi.
```

**Шаг 3 — дамп и верификация:**
```bash
for i in 1 2 3; do sudo flashrom -p ch341a_spi -r dump$i.bin; done
md5sum dump1.bin dump2.bin dump3.bin
```
Если хэши не совпадают — SoC подсаживает шину. Решения: выпаять чип, удерживать SoC в reset, либо использовать SPI-изоляцию (снять питание с SoC, оставив питание флеша).

**Шаг 4 — первичный анализ дампа:**
```bash
# Ищем сигнатуры файловых систем и загрузчиков
binwalk dump1.bin
# Типичный вывод:
# 0x00000000  U-Boot / uboot header
# 0x00040000  uImage / Linux kernel
# 0x00200000  Squashfs filesystem
# 0x00C00000  JFFS2 filesystem
```

**Шаг 5 — что дальше.** Дамп — это вход в `hardware-firmware-extract`: оттуда извлекаем squashfs, находим `/etc/shadow`, `/etc/config`, ключи, и получаем пароли/секреты.

**Шаг 6 — если нужен только раздел.** Работаем по смещениям:
```bash
# Вырезать rootfs (пример смещения и размера)
dd if=dump1.bin of=rootfs.squashfs bs=1 skip=$((0x200000)) count=$((0xA00000))
unsquashfs -d rootfs rootfs.squashfs
```

## Разобранный пример: нестабильный дамп и его лечение

**Симптом:** `md5sum` даёт три разных хэша.

**Причина:** SoC продолжает обращаться к флеш по шине, пока вы читаете клипсой. Два мастера на одной шине конфликтуют.

**Решения по возрастанию сложности:**

1. **Обесточить плату полностью** (если ещё не сделано) — часто достаточно.
2. **Удерживать SoC в reset** — замкнуть reset/держать кнопку сброса при чтении.
3. **Подать питание только на флеш** (3.3 В на Vcc чипа), не запитывая SoC — SoC «мёртв» и не мешает.
4. **Выпаять чип** — самый надёжный, но требует навыка пайки; читать в программаторе.

```bash
# Проверка стабильности после лечения
for i in 1 2 3; do sudo flashrom -p ch341a_spi -r v$i.bin; done
md5sum v1.bin v2.bin v3.bin   # должны совпасть
```

## Частые ошибки

- **Дамп нестабилен (разные хэши).** SoC конкурирует за шину. Отключите питание SoC, выпаяйте чип или используйте изоляцию. Никогда не анализируйте «плавающий» дамп.
- **Клипса плохо контачит.** Симптом: `No EEPROM/flash device found`. Переставьте клипсу, проверьте ориентацию, протрите контакты спиртом.
- **Питание платы включено при чтении.** Два мастера на шине = конфликт и повреждение данных. Всегда обесточивайте.
- **Неверный тип чипа.** Если flashrom не определяет, попробуйте `-c <модель>` вручную, но точная ёмкость обязательна.
- **Запись в флеш.** Не пишите ничего без необходимости и без бэкапа — можно превратить устройство в «кирпич».
- **Игнорирование OTP/защищённых регионов.** Некоторые регионы защищены; `flashrom` вернёт нули или ошибку — это не значит, что чип пуст.
- **Неверная ориентация клипсы.** Перепутанный 1-й пин = ошибка или повреждение. Ключ (точка) на корпусе — ориентир.

## Типовые раскладки дампа и что искать

Дамп SPI-NOR почти всегда структурирован по фиксированным смещениям:

| Смещение (тип.) | Содержимое |
|-----------------|-----------|
| 0x000000 | U-Boot / загрузчик, таблица векторов |
| 0x040000 | env U-Boot (переменные, иногда пароли) |
| 0x050000 | uImage/zImage ядра |
| 0x200000 | squashfs (rootfs) |
| конец | JFFS2/UBIFS (изменяемые данные, конфиг) |

```bash
# Быстрая разметка
binwalk dump1.bin
# Извлечь всё сразу
binwalk -e dump1.bin
# Найти строки-секреты прямо в дампе
strings -n 6 dump1.bin | grep -Ei "password|passwd|admin|key"
```

**Важно про верификацию.** Даже совпавшие хэши трёх дампов не гарантируют «правильность» содержимого, если SoC успел что-то изменить между чтениями. Для критичных случаев снимайте дамп при полностью обесточенном SoC и снимайте питание с SoC (оставляя питание флеш).

**Запись обратно.** Если вы модифицировали прошивку (например, добавили свой конфиг), `flashrom -p ch341a_spi -w mod.bin` вернёт её на место. Всегда храните оригинальный дамп: без него восстановление невозможно. Проверьте, что запись прошла (`-v` для верификации после записи).

**Работа с разделами.** Для точного вырезания раздела нужны смещение и размер из `binwalk -e` или из заголовков. `dd` с `bs=1` медленный; для больших разделов используйте `bs=4096` с `skip`/`count` в блоках или `dd if=... of=... skip=...` с `count` в блоках, пересчитав адреса.

## Что дальше / решение

- **Дамп стабилен** → `binwalk` и разбор разделов (`hardware-firmware-extract`).
- **Дамп нестабилен** → изоляция SoC или выпайка чипа.
- **Чип не определяется** → проверьте контакт/ориентацию, попробуйте `-c` вручную.
- **Нужен только rootfs** → `dd` по смещению + `unsquashfs`.
- **Данные зашифрованы** → переходите к `hardware-crypto` (поиск ключей).
- **Провал** → `record_vector attempted`, зафиксируйте симптом и переходите к UART/JTAG.
