## Вопрос, с которого всё начинается

Zigbee — второй после Z-Wave массовый протокол умного дома: лампы Hue, датчики, розетки. Он построен поверх 802.15.4 и использует шифрование AES-128. Казалось бы, безопасно. Но большинство публичных атак на Zigbee — это атаки на ключи и на то, как они передаются.

Вопрос урока: как устроен стек Zigbee и где взять ключ.

## Наш пример: перехваченный обмен Zigbee

У нас есть дамп Zigbee-сети с ключом, переданным открыто при подключении. Разберём кадры и найдём ключ.

## Шаг 1: стек 802.15.4 → Zigbee

Zigbee работает на радио 802.15.4 (2.4 ГГц, но бывает и sub-GHz). Физический и MAC-уровни — это 802.15.4, а поверх них Zigbee добавляет **NWK** (сеть) и **APS** (приложения).

Устройства делятся на роли: **coordinator** (координатор), **router** и **end device**. Маршрутизацию по mesh-сети ведёт NWK.

```text
$ grep -m2 'NWK' zigbee.log
NWK: src=0x1A2B dst=0x0000 broadcast=true
APS: cluster=0x0006 (OnOff) ep=1
```

## Шаг 2: типы ключей

В Zigbee есть два главных ключа:

- **Network key** — шифрует весь трафик сети. Один на всех.
- **TC link key** (Trust Center link key) — используется при подключении устройства к координатору (Trust Center).

Проблема: у многих устройств **TC link key по умолчанию** — известная всем строка `ZigBeeAlliance09`. Зная её, можно выдать себя за устройство и получить сетевой ключ.

```text
$ grep -n 'linkkey' zigbee.log
join: TC_link_key=5A6967426565416C6C69616E63653039  # ZigBeeAlliance09 (default)
transport-key: network_key=00112233445566778899AABBCCDDEEFF
```

## Шаг 3: извлечение ключа

Ключи можно добыть несколькими путями:

1. **Default TC link key** — как выше.
2. **Sniff на этапе join** — если ключ передаётся в момент подключения.
3. **OTA-дамп** — вытащить из прошивки устройства.
4. **Физический доступ** — прочитать flash.

С добытым сетевым ключом весь трафик расшифровывается.

## Шаг 4: расшифровка и инъекции

Зная network key и счётчик кадра, расшифровываем полезную нагрузку AES-CCM*:

```text
$ python3 -c "from cryptography.hazmat.primitives.ciphers.aead import AESCCM; k=bytes.fromhex('00112233445566778899AABBCCDDEEFF'); a=AESCCM(k); print(a.decrypt(bytes(13), open('ct.bin','rb').read(), None))"
b'...plaintext...'
```

Расшифровав, можно подделать команды (например, `OnOff`) и зашифровать их тем же ключом — устройство примет их как легитимные.

## Шаг 5: OTA и атаки

Zigbee поддерживает **OTA** (over-the-air) обновления. Атаки:

1. **OTA downgrade** — откатить устройство на уязвимую версию.
2. **Подмена образа** — если подпись не проверяется.
3. **Replay команд** — если счётчики не строгие.
4. **Отказ в обслуживании** — залить сеть кадрами.

Практика: нужен адаптер CC2531/CC2652 и инструменты `zigbee2mqtt`, `killerbee`, Wireshark с dissector.

## Стек и типы ключей

Zigbee строится поверх 802.15.4. Слои: PHY/MAC (802.15.4) → NWK (маршрутизация) → APS (транспорт) → ZCL (прикладные кластеры). Безопасность — на уровне NWK и APS. Ключи: **Network Key** (шифрует весь сетевой трафик, 16 байт), **Link Key** (парный ключ между устройствами), **TC Link Key** (ключ доверия для присоединения к сети). Классическая ошибка — **дефолтный TC Link Key** (ZigbeeAlliance09, известен публично), который позволяет присоединиться к сети и получить Network Key.

```text
Network Key : шифрует NWK-payload (все узлы знают)
TC Link Key : защищает обмен ключами при join (часто дефолтный!)
```

Понимание, какой ключ где используется, определяет атаку: с Network Key ты читаешь трафик, с TC Link Key — можешь вступить в сеть.

## Извлечение ключа и расшифровка

Способы получить Network Key: (1) **sniff join** — если сеть использует дефолтный TC Link Key, перехватываешь процедуру присоединения и восстанавливаешь Network Key; (2) **извлечь из устройства** — через UART/JTAG, дамп flash, или из прошивки; (3) **Zigbee Touchlink** — при слабой реализации. Инструменты: `killerbee` (API + `zb*` утилиты), `CC2531`/`nRF52840` как сниффер, `ZigDiggity`/`Attify Zigbee Framework` для автоматизации.

```bash
zbdump -f 15 -c 11 -w zigbee.pcap     # захват канала
zbgoodfind -f zigbee.pcap -k <key>   # проверка/поиск ключа
```

С Network Key весь трафик расшифровывается в Wireshark (задаёшь ключ в настройках Zigbee-диссектора).

## Инъекции, OTA и атаки

С ключом можно **инжектировать команды**: включить/выключить устройство, изменить уставки, подделать датчик. Если включён **OTA-апдейт** без проверки подписи — можно прошить устройство своей прошивкой (полный контроль). Атаки: replay команд (если нет счётчика), spoofing устройства, downgrade до insecure rejoin (в Zigbee 3.0 есть insecure rejoin, который иногда оставляют включённым).

Защита: уникальные TC Link Keys (install codes), включённый secure rejoin только, подпись OTA-образов, отключение insecure rejoin, мониторинг аномальных join. Для пентеста — сначала пассивный анализ и расшифровка, активные инъекции только на изолированном стенде.

## Разбор Zigbee-обмена и командный слой ZCL

Zigbee полезно понимать не только на уровне ключей, но и на уровне прикладных команд. ZCL (Zigbee Cluster Library) определяет кластеры: `0x0006` (On/Off), `0x0008` (Level Control), `0x0402` (Temperature Measurement). Команда состоит из frame control, sequence number, command id и payload.

```text
ZCL frame: FrameControl | SeqNum | CmdID | Payload
  cluster 0x0006, cmd 0x00 = Off, cmd 0x01 = On
```

Расшифровав трафик, ты видишь, кто чем управляет: хаб посылает `On/Off` лампе, датчик шлёт `Report Attributes` с температурой. Это даёт карту устройств и их ролей. Отдельно смотри `ZDO` (Zigbee Device Object) — там команды обнаружения, join, привязок (bindings), через которые устройства связаны напрямую.

## Sniff, join и восстановление ключа

Практический путь к ключу. Первый — **пассивный sniff join**: если сеть использует дефолтный TC Link Key (`ZigbeeAlliance09`), а устройство присоединяется, ты перехватываешь `Transport Key` и восстанавливаешь Network Key. Для этого надо быть в нужный момент на нужном канале (сеть может прыгать по каналам — используй несколько снифферов или `ZigDiggity` для автоматического следования).

```bash
zbstumbler                      # найти сеть (PAN ID, канал)
zbdump -f 15 -c 11 -w join.pcap # захват на канале сети
zbwireshark -f join.pcap        # разбор, задать TC Link Key
```

Второй путь — извлечение из устройства (flash/UART). Третий — Touchlink (при слабой реализации). Восстановленный ключ вводится в Wireshark (Preferences → Protocols → ZigBee → Network Key), после чего весь трафик читается.

## Инъекции, OTA и защита

С Network Key доступны активные действия. **Инъекция ZCL-команд**: включить/выключить устройство, изменить уровень, послать ложные показания датчика. **OTA**: если производитель не подписывает образы обновления, можно залить свою прошивку и получить полный контроль над устройством (например, превратить лампу в точку присутствия). **Replay**: команды без счётчика повторяются.

Защита: уникальные TC Link Keys через install codes (не дефолт), только secure rejoin, подпись OTA-образов, обновление прошивок устройств, сегментация Zigbee-сети. Для пентеста: сначала расшифровка и карта устройств, затем (на изолированном стенде) инъекции. В живой сети умного дома активные действия могут нарушить её работу, поэтому они допустимы только с явного разрешения.

## Карта сети и роли устройств

После расшифровки трафика строится карта Zigbee-сети. Coordinator (хаб) управляет сетью; routers ретранслируют; end devices спят и просыпаются по событию. По адресам (`NWK address`, `IEEE address`) ты сопоставляешь устройства. По кластерам ZCL — роли: лампы (`0x0006`), датчики температуры (`0x0402`), замки (`0x0101` Door Lock), термостаты (`0x0201`).

Это даёт понимание, чем можно управлять и что читать. Например, датчик присутствия (`0x0406`) раскрывает, дома ли люди; замок (`0x0101`) — критичное устройство, запись в которое физически открывает дверь. Такие устройства — приоритетные цели и в отчёте выделяются отдельно.

Отдельно смотри `bindings` — прямые связи устройств, которые работают без хаба. Через binding лампа может управляться кнопкой напрямую; компромисс одного устройства может дать управление другим.

## Типовые ошибки и итог

Типовые ошибки: считать Zigbee «безопасным по умолчанию» (дефолтный TC Link Key — правило, а не исключение); не проверять, включён ли insecure rejoin; игнорировать OTA-канал (часто без подписи); пытаться инжектировать команды в живую сеть без разрешения. Правильный порядок — пассивный анализ, определение ключей, расшифровка, карта устройств, оценка импакта, и только затем (на стенде) активные проверки.

## Быстрый чек-лист Zigbee

Порядок: найти сеть (`zbstumbler`) → захват (`zbdump`) → проверка дефолтного TC Link Key → восстановление Network Key → расшифровка → карта ZCL-устройств. Ключевые находки: дефолтный TC Link Key, insecure rejoin, OTA без подписи. Инструменты: `killerbee`, `nRF Sniffer`, Wireshark, `ZigDiggity`.

## Сводка: что важно запомнить про Zigbee

Главное про Zigbee: безопасность всей сети держится на двух ключах — TC Link Key (при присоединении) и Network Key (шифрование трафика). Если TC Link Key дефолтный (`ZigbeeAlliance09`), любой может присоединиться и получить Network Key, после чего весь трафик расшифровывается. Если Network Key слабый или утёк из устройства, трафик читается без присоединения. Поэтому первая задача аудита — определить, какие ключи используются и не дефолтные ли они.

Второе: активные функции. `insecure rejoin`, OTA без подписи, Touchlink со слабой реализацией — каждая из них расширяет поверхность. Проверь их наличие и включи в отчёт. Третье: карта устройств. Датчик присутствия и замок — критичные цели, лампа — нет; это определяет приоритет рекомендаций. Четвёртое: этика. Zigbee управляет домом; инъекция команд в живую сеть может нарушить её работу, поэтому активные проверки — только на изолированном стенде. Рекомендации — уникальные install codes, secure rejoin, подпись OTA, обновление прошивок.

## Что мы теперь знаем

- Zigbee = 802.15.4 + NWK + APS.
- Два ключа: network key (трафик) и TC link key (join).
- Дефолтный TC link key `ZigBeeAlliance09` — классическая слабость.
- Зная ключ, трафик расшифровывается и подделывается.
- OTA добавляет риск downgrade и подмены образа.
