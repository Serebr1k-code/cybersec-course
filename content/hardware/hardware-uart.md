UART — самый частый и самый «дешёвый» отладочный интерфейс на встраиваемых устройствах. Почти всегда производитель оставляет пятачки для отладки, и очень часто на них выходит полноценная консоль с shell, часто под root. Это первое, что нужно проверить на любой плате.

## Теория

**UART (Universal Asynchronous Receiver/Transmitter)** — асинхронный последовательный интерфейс. Асинхронный = нет отдельной линии тактирования, приёмник и передатчик заранее договариваются о скорости (бод-рейте). Минимум для связи — три линии:

| Линия | Направление | Назначение |
|-------|-------------|-----------|
| **TX** | устройство → хост | данные от платы |
| **RX** | хост → устройство | данные к плате |
| **GND** | общая | опорная земля |
| VCC | — | питание (обычно не подключаем) |

Уровни логики бывают **3.3 В** и **5 В**. Подача 5 В на 3.3-вольтовую линию RX платы убивает SoC, поэтому уровень проверяют мультиметром. USB-TTL адаптеры с переключателем 3.3/5 В (FT232RL) удобны, но дешёвые CP2102/CH340 обычно 3.3 В — для большинства современных плат это то, что нужно.

Скорость (бод-рейт) — часто 115200, но встречаются 9600, 38400, 57600, 230400 и экзотические 74880 (ESP8266). Формат кадра обычно `8N1`: 8 бит данных, без паритета, 1 стоп-бит.

**U-Boot** — загрузчик, который почти всегда ждёт пару секунд нажатия клавиши, чтобы прервать автозагрузку. Это «золотая дверь»: из его консоли можно читать/писать память, загружать образы по TFTP и часто получить root-shell.

## Инструменты и команды

- **USB-TTL адаптер** (CP2102, CH340, FT232RL) — физическое подключение.
- **Мультиметр** — найти GND/VCC и уровень логики.
- **Логический анализатор** (PulseView/Sigrok) — определить, какой пин TX, какой RX, и автоматически угадать бод-рейт.
- **Терминал:** `picocom`, `minicom`, `screen`, `screen /dev/ttyUSB0 115200`.
- **Скрипты:** `baudrate.py` из репозитория devttys0, `uart_analyzer`.

```bash
# Список портов
ls /dev/ttyUSB* /dev/ttyACM*

# Подключение (Ctrl-A Ctrl-X для выхода в picocom)
sudo picocom -b 115200 /dev/ttyUSB0

# Или screen
sudo screen /dev/ttyUSB0 115200

# Автоперебор бод-рейтов логическим анализатором (sigrok-cli)
sigrok-cli -d fx2lafw --channels D0 --config samplerate=1m --samples 5000000 -o dump.sr
# затем в PulseView: Decoders -> UART, подбор baudrate

# Автоматический подбор бод-рейта по пину RX (devttys0/baudrate.py)
python3 baudrate.py -p /dev/ttyUSB0
```

Логический анализатор подключается к предполагаемому TX платы (только к нему!) — так вы не создаёте конфликт, пока не убедились в назначении пинов.

## Поиск UART на плате

1. **Осмотр.** Ищем 3-4 пятачка/пина рядом с SoC, часто с маркировкой `J1`, `CON1`, `TX/RX`, `UART`. Иногда это распаянный гребень, иногда просто пустые площадки.
2. **GND.** Мультиметр в режиме прозвонки: пятачок, звонящийся с экраном или минусом питания — GND.
3. **VCC.** Мультиметр-вольтметр: при включённой плате один пятачок даст ~3.3 В — это VCC (не трогаем).
4. **TX/RX.** Остаются два. Анализатор на каждом: на TX при загрузке видна активность (данные), на RX — тишина. Если анализатора нет — подключаем USB-TTL с RX адаптера на предполагаемый TX, TX адаптера на RX, и смотрим вывод.
5. **Бод-рейт.** Начинаем с 115200, затем 57600, 38400, 9600. Мусор = неверная скорость или перепутаны линии.

## Разобранный пример: от пятачков до root shell

**Дано:** плата IP-камеры, пятачки `J2` (4 контакта), питание от 12 В.

**Шаг 1 — питание и земля.**
```bash
# Плата уже питается от родного БП. Мультиметром:
# - находим GND (звонится с экраном разъёма)
# - находим 3.3 В (VCC)
```

**Шаг 2 — подключение USB-TTL.**
```text
USB-TTL GND  ─── J2 GND
USB-TTL RX   ─── J2 TX   (данные от платы)
USB-TTL TX   ─── J2 RX   (данные к плате)
USB-TTL VCC  ─── не подключён
```

**Шаг 3 — терминал.**
```bash
sudo picocom -b 115200 /dev/ttyUSB0
# Перезагружаем плату и ловим вывод:
```
```text
U-Boot 2016.05 (Jul 12 2021 - 09:14:23 +0800)

DRAM:  128 MiB
...
Hit any key to stop autoboot:  3
```

**Шаг 4 — прерываем автозагрузку** (нажимаем любую клавишу) и получаем приглашение `hisilicon #`. Печатаем `help`.

**Шаг 5 — из U-Boot читаем окружение**, часто там лежат пароли и команды:
```text
hisilicon # printenv
bootargs=console=ttyAMA0,115200 root=/dev/mtdblock2 rootfstype=squashfs
...
```

**Шаг 6 — получить shell.** Если автозагрузку не остановить, дожидаемся логина в консоли. Многие устройства пускают по `root` без пароля или с паролем из дампа прошивки (см. `hardware-spi`). Если пускают — вы уже root.

**Шаг 7 — сливаем прошивку из U-Boot** (если shell нет, а U-Boot есть):
```text
hisilicon # tftpboot 0x80000000 192.168.1.100:fw.bin
# на хосте: python3 -m http.server 69 --bind 192.168.1.100 (TFTP-сервер)
```
Более прямой путь: из Linux-shell на устройстве выполнить `dd if=/dev/mtd0 of=/tmp/boot.bin` и вытащить файл по сети.

## Частые ошибки

- **Терминал показывает тишину.** Причины: перепутаны TX/RX, не тот бод-рейт, плата не грузится, или пятачок — не UART. Меняйте провода и скорости по одному.
- **Мусор при загрузке.** Почти всегда неверный бод-рейт. ESP8266 любит 74880 на старте.
- **Плата умирает после подключения.** Подали 5 В на 3.3 В линию или подключили VCC при работающем питании. Всегда измеряйте.
- **Консоль только для чтения.** Некоторые платы разводят только TX (лог), RX отсутствует — тогда shell не получить, остаётся только анализ лога.
- **Пароль в консоли неизвестен.** Ищите его в дампе прошивки (`hardware-spi`), в `printenv` U-Boot или в `/etc/shadow` после получения доступа.

## Взаимодействие с U-Boot

Если на UART видна консоль U-Boot, можно прервать загрузку (часто пробелом или клавишей) и получить командную строку загрузчика. Оттуда: `printenv` (переменные, включая пароли/адреса), `setenv`, `boot`, `md`/`mw` (чтение/запись памяти), `tftpboot` (загрузка по сети). Иногда можно изменить `bootargs` для получения root shell или обойти проверку пароля.

```bash
# подключение
picocom -b 115200 /dev/ttyUSB0
# прервать загрузку: нажать пробел при старте
U-Boot> printenv
U-Boot> setenv bootargs 'console=ttyS0,115200 init=/bin/sh'
U-Boot> boot
```

## Практика

Найдите UART на плате (прозвонка + логический анализатор), подключитесь USB-TTL адаптером, подберите baudrate. Дождитесь загрузки и, если есть консоль, попробуйте войти (часто root без пароля) или прервать U-Boot. Задокументируйте уровень доступа.

## Сводка по UART

| Задача | Команда/шаг |
|--------|-------------|
| подключение | picocom -b 115200 /dev/ttyUSB0 |
| поиск baud | перебор 9600/19200/38400/57600/115200 |
| декод | sigrok-cli -P uart:baudrate=... |
| U-Boot | прервать пробелом, printenv |
| shell | логин root / init=/bin/sh |

Сначала найдите пины (GND, VCC, TX), затем подберите baudrate и подключитесь. Консоль часто даёт root.

## Где пригодится

- **CTF:** Hardware-задачи, где нужно «подключиться к консоли» и вытащить флаг из shell или U-Boot.
- **Пентест IoT:** самый быстрый путь к root shell на роутерах, камерах, NAS.
- **Bug bounty:** hardware-программы, где важен физический доступ.
- **Работа:** reverse engineering загрузчиков, восстановление «кирпичей», отладка встраиваемых систем.
- **Дальше по дереву:** `hardware-spi` (дамп флеша после получения доступа), `hardware-jtag` (если UART закрыт).
