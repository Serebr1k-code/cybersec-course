Извлечь прошивку — половина дела. Вторая половина — найти в ней **секреты**: пароли и хэши, API-токены, приватные ключи, сертификаты, «сервисные» учётки, бэкдоры. Это самая результативная часть hardware-пентеста: часто достаточно `grep` по распакованному rootfs, чтобы получить доступ к устройству и его облаку. Этот урок — систематический подход к поиску секретов.

## Что искать

Чек-лист секретов в прошивке:

- **Учётные данные**: `/etc/passwd`, `/etc/shadow`, конфиги, базы sqlite.
- **Ключи и сертификаты**: `.pem`, `.key`, `.crt`, `id_rsa`, сертификаты обновлений.
- **API-токены**: облачные ключи (AWS/GCP/Azure), токены IoT-платформ.
- **Строки подключения**: пароли к БД, MQTT-брокерам, бэкенду.
- **Бэкдоры**: скрытые учётки, отладочные порты, «магические» строки.
- **Шифрование/обфускация**: XOR-ключи, константы алгоритмов.

## Статические секреты: строки

Начинайте с простого:

```bash
# Базовый поиск по распакованному rootfs
cd squashfs-root
grep -rIn -E 'password|passwd|secret|api[_-]?key|token|credential' . | head -50
strings -n 8 ./usr/sbin/* | grep -iE 'password|key|secret' | head

# Поиск конкретных форматов
grep -rIn -E 'AKIA[0-9A-Z]{16}' .            # AWS access key
grep -rIn -E 'AIza[0-9A-Za-z_-]{35}' .       # Google API key
grep -rIn -E 'xox[baprs]-' .                  # Slack token
grep -rIn -E '-----BEGIN [A-Z ]+-----' .      # ключи/сертификаты
grep -rIn -E '[a-zA-Z0-9._%+-]+@[a-zA-Z0-9.-]+' . | head  # email
```

Часто токены лежат в JS-файлах веб-интерфейса, в `.json`-конфигах и в бинарниках демонов.

## Учётные записи и хэши

```bash
# Учётные записи
cat etc/passwd
cat etc/shadow 2>/dev/null
# Конфиги с паролями
grep -rIn -E 'root:|admin:|user=' etc/ 2>/dev/null | head
# Базы данных
find . -name '*.db' -o -name '*.sqlite*' | while read f; do
  echo "== $f"; sqlite3 "$f" '.tables' 2>/dev/null
done
```

Найденные хэши (`$1$`, `$5$`, `$6$`) уходят в `hashcat`/`john` (офлайн). Иногда пароль лежит в открытом виде — тогда он сразу применим.

## Ключи и сертификаты

```bash
find . -type f \( -name '*.pem' -o -name '*.key' -o -name '*.crt' -o -name 'id_rsa*' \)
# Проверить тип ключа
openssl rsa -in key.pem -check -noout 2>/dev/null
openssl x509 -in cert.crt -text -noout 2>/dev/null | head
# Искать приватные ключи в бинарниках
grep -rl 'BEGIN RSA PRIVATE KEY' . 2>/dev/null
```

Приватный ключ подписи обновлений особенно ценен: он позволяет создавать «легитимные» прошивки, которые устройство примет.

## Токены и строки подключения

```bash
grep -rIn -E '(mqtt|amqp|redis|postgres|mysql)://' . | head
grep -rIn -E 'broker|endpoint|host.*=.*\.(com|net|io)' . | head
```

Строки подключения к облаку (MQTT-брокер, API-эндпоинт) с токеном дают доступ к флоту устройств — это часто критичнее, чем доступ к одному устройству.

## Обфускация и бинарные секреты

Если `grep` ничего не нашёл, секреты могут быть закодированы. Приёмы:

```bash
# Base64
grep -rIn -E '[A-Za-z0-9+/]{40,}={0,2}' . | head
# Hex-строки
grep -rIn -E '([0-9a-fA-F]{2}){16,}' . | head
# XOR-обфускация: искать повторяющиеся ключи, пробовать XOR
python3 - <<'EOF'
data = open('suspicious.bin','rb').read()
for k in range(1,256):
    dec = bytes(b ^ k for b in data[:64])
    if b'http' in dec or b'BEGIN' in dec:
        print('key', k, dec[:32])
EOF
```

Инструмент **binwalk** с энтропийным анализом и **radare2/Ghidra** помогают найти зашифрованные/сжатые блоки, где могут прятаться ключи.

## Разобранный пример: полный поиск секретов

```bash
# 1. Распаковать прошивку
binwalk -eM firmware.bin
cd _firmware.bin.extracted/squashfs-root
# 2. Учётки
cat etc/passwd etc/shadow 2>/dev/null
# 3. Токены облака
grep -rIn -E 'AKIA[0-9A-Z]{16}|AIza[0-9A-Za-z_-]{35}' .
# 4. Приватные ключи
find . -name '*.pem' -o -name 'id_rsa'
grep -rl 'BEGIN RSA PRIVATE KEY' .
# 5. Строки подключения
grep -rIn -E 'mqtt://|https://[^ ]+token' .
# 6. Базы
find . -name '*.db' -exec sqlite3 {} '.tables' \; 2>/dev/null
```

Даже одна найденная строка подключения с токеном может открыть облако производителя и тысячи устройств.

## Инструменты

| Инструмент | Назначение |
|-----------|-----------|
| `grep`/`rg` | текстовый поиск |
| `strings` | строки в бинарниках |
| `binwalk`/`unblob` | распаковка |
| `sqlite3` | чтение БД |
| `openssl` | ключи/сертификаты |
| `hashcat`/`john` | взлом хэшей |
| `trufflehog` | поиск секретов в репозиториях |

## Частые ошибки и подводные камни

- **Искать только «password»**: токены и ключи не содержат этого слова — расширяйте шаблоны.
- **Игнорировать бинарники**: секреты часто в демонах, а не в текстовых конфигах.
- **Пропустить JS**: в веб-интерфейсе могут быть ключи и эндпоинты.
- **Не проверить БД**: sqlite часто хранит токены/учётки.
- **Секреты в сжатых блоках**: сначала распакуйте всё (binwalk -eM).
- **Обфускация**: XOR/base64 — нужен доп. анализ.

## Поиск секретов в веб-интерфейсе

Веб-интерфейс устройства — частый источник утечек. Смотрите JS-файлы, API-эндпоинты и конфиги:

```bash
# JS с ключами/эндпоинтами
find www -name '*.js' | xargs grep -In -E 'token|key|api|endpoint' | head
# Скрытые эндпоинты
grep -rIn -oE '/api/[a-zA-Z0-9_/]+' www/ | sort -u | head
# Строки подключения в шаблонах
grep -rIn -E 'wss?://|https?://[^"]+' www/ | head
```

Часто в JS захардкожены API-ключи облачной платформы или пути к внутренним сервисам. Их можно использовать напрямую, минуя устройство.

## Анализ энтропии и зашифрованных блоков

Если секреты зашифрованы или упакованы, помогает энтропийный анализ:

```bash
# binwalk покажет энтропийный график; высокоэнтропийные регионы — сжатие/шифр
binwalk -E firmware.bin
# Поиск повторяющихся 16/32-байтовых блоков (возможные ключи)
python3 - <<'EOF'
from collections import Counter
data = open('blob.bin','rb').read()
blocks = [data[i:i+16] for i in range(0, len(data)-16, 16)]
for b, n in Counter(blocks).most_common(5):
    print(n, b.hex())
EOF
```

Высокая энтропия + повторяемость — признак крипто-ключей или зашифрованного раздела. Дальше — реверс алгоритма в Ghidra и восстановление ключа.

## Практический чек-лист поиска секретов

1. Распаковать всё (`binwalk -eM`, `unblob`).
2. Пройтись `grep`/`rg` по паттернам (пароли, ключи, токены).
3. Прочитать `/etc/passwd`, `/etc/shadow`, конфиги.
4. Найти ключи/сертификаты (`*.pem`, `id_rsa`).
5. Проверить JS и веб-эндпоинты.
6. Прочитать базы sqlite.
7. Проверить бинарные секреты (энтропия, hex, base64, XOR).
8. Сопоставить найденное с облаком/бэкендом.

Такой проход занимает десятки минут и часто даёт критичные находки — учётки, токены, ключи подписи.

## Секреты в облачных интеграциях

Современные IoT-устройства подключены к облаку, и в прошивке часто лежат учётные данные для него:

- **MQTT-брокер**: логин/пароль, иногда сертификаты.
- **REST API**: токены, ключи.
- **WebSocket**: URL + токен.
- **Device provisioning**: ключи регистрации устройства.

```bash
grep -rIn -E 'mqtts?://[^ ]+:[^ ]+@' .
grep -rIn -E '(api[_-]?key|auth[_-]?token|client[_-]?secret)' .
```

Компрометация облачных учёток — часто критичнее доступа к одному устройству: она даёт контроль над всем флотом. Если токен ведёт к API производителя, проверьте его права (часто — полный доступ).

## Ответственное обращение с секретами

Найденные секреты — это чувствительные данные. Обращайтесь с ними аккуратно:

- **Не публикуйте** ключи и токены (даже в отчёте — маскируйте).
- **Передавайте** по защищённому каналу, храните зашифрованно.
- **Не используйте** чужие ключи за пределами согласованного теста.
- **Сообщайте** вендору через responsible disclosure.
- **Фиксируйте** доказательства (скриншоты, хэши) без раскрытия значения.

В пентесте ценность — в доказательстве уязвимости, а не в самом секрете. Правильная работа с секретами — часть профессионализма.

## Секреты в логах и истории

Помимо конфигов, проверяйте логи и артефакты, которые производитель забыл удалить:

```bash
find . -name '*.log' -o -name '*.bak' -o -name '*~' | head
grep -rIn -E 'password=|Authorization: Bearer|token=' var/ 2>/dev/null | head
# История shell
cat root/.ash_history 2>/dev/null
cat home/*/.bash_history 2>/dev/null
```

В отладочных логах часто остаются пароли, токены и внутренние URL, которые убрали из конфигов, но не вычистили из образов.

## Коротко о главном

Секреты в прошивке ищут системно: распаковка, grep по паттернам, конфиги, ключи, базы, JS, бинарные блоки. Это самая результативная часть hardware-пентеста.
