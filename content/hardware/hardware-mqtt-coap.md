## Зачем этот урок

MQTT и CoAP — два протокола, на которых держится IoT. MQTT — pub/sub поверх TCP (1883/8883), CoAP — REST-подобный поверх UDP (5683/5684). Оба проектировались для лёгких устройств и оба часто лишены аутентификации. Здесь — практические атаки на оба, от анонимного доступа до инъекции команд.

## MQTT: модель pub/sub

MQTT — брокер и клиенты. Клиенты **публикуют** сообщения в **топики** (`home/kitchen/temp`) и **подписываются** на них (wildcards `+` — один уровень, `#` — все). Уровни QoS 0/1/2, retain (хранить последнее), will (сообщение при обрыве). Модель проста и потому распространена в умном доме и промышленности.

## MQTT: порты и транспорт

| Порт | Транспорт | Безопасность |
|------|-----------|--------------|
| 1883 | TCP | Обычно без TLS |
| 8883 | TCP | TLS |
| 8083/8084 | WebSocket | WS/WSS |

## MQTT: обнаружение

```bash
nmap -Pn -p 1883,8883,8083 --open <CIDR>
# Подписка на всё (если брокер без auth)
mosquitto_sub -h <host> -p 1883 -t '#' -v
```

Брокеры часто открыты в интернет без аутентификации — классика Shodan (`mqtt port:1883`).

## MQTT: анонимный доступ

Брокер без auth отдаёт все топики:

```bash
mosquitto_sub -h <host> -t '#' -v -d
mosquitto_pub -h <host> -t 'home/door/cmd' -m '{"open":true}'
```

Читайте всё, ищите управляющие топики, публикуйте команды. Часто в retained-сообщениях лежат токены к облаку.

## MQTT: ACL misconfig

Даже с auth ACL может разрешать подписку на `#`:

```bash
mosquitto_sub -h <host> -t '#' -v -u <user> -P <pass>
```

Проверяйте права: пользователь может не иметь publish, но иметь широкий subscribe. Обратно — publish в чужой топик.

## MQTT: retained и will

**Retained** — последнее сообщение топика хранится брокером и отдаётся новым подписчикам. Это утечка состояния и секретов:

```bash
mosquitto_sub -h <host> -t '#' -v | grep -iE 'pass|token|key|secret'
```

**Will** — сообщение, публикуемое при обрыве связи; злоумышленник может отслеживать состояние устройств.

## MQTT: $SYS и эксплуатация брокера

Топик `$SYS/#` раскрывает метрики брокера (клиенты, версия, uptime). Старые версии Mosquitto имели RCE. Проверяйте версию и известные CVE.

## CoAP: модель и методы

CoAP — HTTP-подобный протокол поверх UDP с методами GET/POST/PUT/DELETE и путями. Ресурсы: `/sensors/temp`, `/actuator/state`. Лёгкий, для constrained-устройств.

| Порт | Безопасность |
|------|--------------|
| 5683 | Обычно без DTLS |
| 5684 | DTLS |

## CoAP: обнаружение и каталог

```bash
nmap -sU -Pn -p 5683,5684 --open <CIDR>
coap-client -m get coap://<host>/.well-known/core
```

`.well-known/core` — встроенный каталог всех ресурсов устройства (аналог листинга). Это бесплатная карта поверхности.

## CoAP: открытая запись

PUT/POST без аутентификации меняет состояние устройства:

```bash
coap-client -m get coap://<host>/sensors/temp
coap-client -m put coap://<host>/actuator/state -e '{"on":true}'
```

## CoAP: amplification/DoS

CoAP по UDP с ответом больше запроса используется для amplification-атак. Для пентеста — учитывайте, что неосторожные запросы могут перегрузить устройство.

## Разобранный пример: MQTT без auth → управление домом

1. `mosquitto_sub -h <host> -t '#' -v` → видим `home/lock/state {"locked":true}`, `home/lock/cmd`, `home/camera/url`.
2. Публикуем команду: `mosquitto_pub -h <host> -t 'home/lock/cmd' -m '{"locked":false}'`.
3. Читаем retained — там токены к облаку.
4. Из токена — доступ к облачному API производителя (`hardware-iot-cloud`).

## Разобранный пример: CoAP-актуатор

1. `nmap -sU -p 5683` находит устройство.
2. `coap-client -m get coap://<host>/.well-known/core` → список ресурсов.
3. Находим `/actuator/relay` и пишем: `coap-client -m put coap://<host>/actuator/relay -e '1'`.
4. Реле срабатывает — подтверждение отсутствия авторизации.

## Инструменты

- **MQTT**: `mosquitto_sub`/`mosquitto_pub`, `mqtt-pwn`, MQTT Explorer.
- **CoAP**: `coap-client` (libcoap), `aiocoap`, `coap-thon`.
- **Общее**: Wireshark (диссекторы MQTT/CoAP), Shodan/Censys для поиска открытых брокеров.

## Защита

- Включить аутентификацию и TLS/DTLS.
- Настроить ACL по топикам (запретить `#`).
- Не хранить секреты в retained.
- Ограничить доступ к `.well-known/core` и write-методам CoAP.
- Обновлять брокеры (CVE Mosquitto).

## Частые ошибки

- **Путать 1883 и 8883.** На 8883 нужен TLS.
- **Забыть про `#` wildcard.** Без него не увидите все топики.
- **Игнорировать retained.** Это кэш значений, часто с секретами.
- **Не проверять `.well-known/core`.** Бесплатный каталог ресурсов.
- **Пробовать TCP для CoAP.** CoAP — UDP; `nmap -sU` обязателен.

## Что дальше / решение

- Открыт 1883 → подписка на `#`, публикация команд.
- Открыт 5683 → `.well-known/core`, затем чтение/запись.
- Нашли токены → облако производителя (`hardware-iot-cloud`).
- Смежные: `hardware-iot-network`, `hardware-iot-cloud`, `hardware-zigbee-zwave`.

## MQTT: мосты и WebSocket

Брокеры могут объединяться **мостами** (bridge) — тогда топики одной сети видны в другой. Мост с открытой конфигурацией расширяет периметр: через него вы попадаете в смежную сеть. WebSocket-порты (8083/8084) дают тот же pub/sub через браузерный транспорт и часто хуже защищены.

## MQTT 5.0: свойства и shared subscriptions

MQTT 5.0 добавил properties (reason codes, user properties), shared subscriptions (`$share/group/topic`) и flow control. Практическое следствие: некоторые ACL, написанные для 3.1.1, не учитывают новые конструкции и могут пропускать неожиданные подписки. Проверяйте поведение на конкретной версии брокера.

## CoAP: Observe и block-wise

CoAP поддерживает **Observe** — подписку на изменения ресурса (аналог MQTT subscribe). Это удобный канал мониторинга состояния устройства. **Block-wise transfer** позволяет читать/писать крупные ресурсы по блокам — учтите при перечислении содержимого.

## Инструменты и скрипты

```bash
# MQTT: подписка на всё и запись в файл
mosquitto_sub -h <host> -t '#' -v > mqtt.log &
# Публикация команды
mosquitto_pub -h <host> -t 'cmd/relay' -m 'ON'
# CoAP: чтение и запись
coap-client -m get  coap://<host>/.well-known/core
coap-client -m put  coap://<host>/actuator -e '1'
```

Для массового сканирования брокеров используйте Shodan/Censys (`port:1883`) и `nmap -sU -p 5683`.

## Промышленный контекст

MQTT широко применяется в IIoT (Sparkplug B для SCADA), CoAP — в constrained-сетях и умных счётчиках. Открытый брокер в промышленности означает доступ к телеметрии и, возможно, к управляющим командам. Всегда оценивайте влияние: команда на реле в цеху — это физический риск.

## Безопасное тестирование и OPSEC

Публикация команд в чужой брокер/устройство — это активное воздействие. В рамках пентеста фиксируйте границы: только чтение vs чтение+запись, какие устройства разрешено трогать. Для MQTT используйте отдельный client-id, чтобы не конфликтовать с реальными клиентами. Для CoAP — не шлите broadcast и не перегружайте constrained-устройства.

## Типичные находки по приоритету

| Находка | Риск | Действие |
|---------|------|----------|
| MQTT без auth | критический | чтение/запись топиков |
| MQTT ACL с `#` | высокий | подписка на всё |
| Retained с токенами | высокий | доступ к облаку |
| CoAP PUT без auth | высокий | изменение состояния |
| CoAP `.well-known/core` | средний | карта ресурсов |
| `$SYS/#` открыт | низкий | метрики брокера |

## Итоговый чеклист MQTT/CoAP

1. Просканировать 1883/8883/8083 и 5683/5684 (UDP!).
2. Проверить анонимный доступ и дефолтные креды.
3. Подписаться на `#`, собрать retained.
4. Найти управляющие топики, оценить publish.
5. Для CoAP — `.well-known/core`, затем GET/PUT ресурсов.
6. Извлечь секреты, идти в облако производителя (`hardware-iot-cloud`).
