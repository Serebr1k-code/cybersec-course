## Вопрос, с которого всё начинается

SPI-NOR кончается там, где нужно много памяти. Смартфоны, ТВ-приставки и «умные» колонки хранят систему на **eMMC** или **raw NAND** — носителях на порядок сложнее NOR. У них есть страницы, блоки, контроллер и таблица трансляции адресов. Если не понимать их устройство, дамп получится, но образ не смонтируется.

Этот урок — про то, как читать eMMC и raw NAND и собрать из дампа рабочий образ.

## Наш пример: Android-приставка с eMMC

Перед нами ТВ-приставка на eMMC в корпусе **BGA-153**. Задача — снять полный образ системы. Начнём с теории, потому что именно она определяет, что и как мы будем читать.

## Шаг 1: чем eMMC отличается от raw NAND

**eMMC** (embedded MultiMediaCard) — это микросхема, внутри которой NAND-память **плюс контроллер**. Контроллер сам занимается износом, коррекцией ошибок (**ECC**), бэд-блоками и трансляцией адресов. Снаружи eMMC выглядит как обычное блочное устройство: вы адресуете сектора, а не страницы.

**Raw NAND** — «голый» чип без контроллера. Всё это — страницы, блоки, ECC, бэд-блоки — должен делать хост. Именно поэтому raw NAND читать сложнее.

| Свойство | eMMC | Raw NAND |
|----------|------|----------|
| Контроллер | внутри чипа | в SoC |
| Адресация | сектора | страницы/блоки |
| ECC | аппаратный | программный |
| Bad blocks | скрыты | видны, надо пропускать |

## Шаг 2: читаем eMMC внутрисхемно

Первый, наименее инвазивный метод — **ISP** (in-system programming): припаиваемся к пятачкам на плате. Находим линии `CLK`, `CMD`, `DAT0`, `VCC`, `VCCQ`, `GND`. `DAT0` и `CLK` держим максимально короткими — на высокой частоте длинные провода портят сигнал.

Программатор (например, Easy JTAG Plus) выполняет инициализацию и определяет объём:

```
eMMC CID: 90014a...  (SanDisk)
eMMC size: 0x1C8000000 (7360 MiB)
Bus width: 8-bit, Speed: HS
```

`CID` — уникальный идентификатор чипа, `size` — объём. Видим 8-битную шину и высокую скорость. Дальше выбираем «Read full», ставим скорость пониже (1 МГц) и ждём.

Если есть Linux-доступ к системе, eMMC читается ещё проще — как блочное устройство:

```
$ sudo dd if=/dev/mmcblk0 of=emmc_full.bin bs=1M status=progress
```

`bs=1M` — читать блоками по мегабайту, `status=progress` — показывать ход.

## Шаг 3: сверяем и разбираем

Как и любой дамп, eMMC читают дважды и сравнивают хэши:

```
$ md5sum emmc_full.bin emmc_full2.bin
9f2a...  emmc_full.bin
9f2a...  emmc_full2.bin
```

Совпали — образ стабилен. Теперь разбираем его: `binwalk` находит таблицу разделов и файловые системы, а `mmls` показывает разметку:

```
$ binwalk emmc_full.bin | head
0        0x0        MBR
1048576  0x100000   ext4 filesystem
$ sudo mount -o loop,offset=$((1048576)) emmc_full.bin /mnt/part1
```

`offset` говорит ядру, с какого байта начинается раздел — так монтируется кусок внутри большого образа.

## Шаг 4: raw NAND и его капризы

Если перед нами raw NAND (маркировка вида `MT29F`), читать нужно через NAND-программатор или через контроллер SoC. Здесь появляются два ключевых понятия.

**OOB** (out-of-band) — область spare-байт в каждой странице, где лежат ECC-коды и метки бэд-блоков. **Bad-block management** — производитель помечает дефектные блоки (обычно в первом байте OOB), и при сборке образа их нужно пропускать, иначе логическая нумерация «съедет».

Параметры чипа берут из U-Boot:

```
$ nand info
Device 0: nand0, sector size 128 KiB
  Page size  2048 b
  OOB size   64 b
  Erase size 128 KiB
```

## Шаг 5: собираем образ из сырого дампа

Когда есть «сырое» чтение с OOB, его преобразуют в образ без служебных байт. Зная `page=2048` и `oob=64`, вырезаем только данные:

```
$ python3 - <<'PY'
data = open('raw_nand.bin','rb').read()
page, oob = 2048, 64
out = bytearray()
for off in range(0, len(data), page+oob):
    out += data[off:off+page]
open('clean_nand.bin','wb').write(out)
PY
$ binwalk clean_nand.bin | grep -E 'squashfs|ubifs|jffs2'
```

Скрипт идёт по файлу шагом «страница плюс OOB» и оставляет только байты данных. Бэд-блоки при этом пропускают, подменяя их данными из резервных блоков. Если ФС — UBIFS, её достают через `ubireader_extract_images` и `ubireader_extract_files`.

## Шаг 6: выбираем метод по лестнице инвазивности

Методы чтения выстраиваются от наименее к наиболее рискованному:

| Метод | Инвазивность | Когда применять |
|-------|--------------|-----------------|
| Chip-on (ISP) | минимальная | есть пятачки, чип исправен |
| eMMC-сокет | низкая | чип съёмный |
| JTAG/SWD-дамп | средняя | доступен отладочный интерфейс |
| Chip-off | высокая | ISP закрыт, устройство мертво |

Практическое правило: **всегда начинайте с наименее инвазивного** и повышайте только при доказанной невозможности предыдущего. Перегрев при chip-off уничтожает данные, которые можно было снять внутрисхемно.

## Если внутрисхемное чтение дало «мусор»

Иногда ISP-пятачки есть, но чтение возвращает бессмысленные данные. Разберём типичный случай: снимаем два дампа, оба идентичны, но `binwalk` не находит ни одной файловой системы, а энтропия ровная и высокая (около 7.99 бит на байт). Это признак **шифрования**, а не сжатия.

Дальше важно понять, **где именно** реализовано шифрование. Если inline-шифрование встроено в контроллер eMMC, то chip-off даст тот же шифротекст и не поможет. Если шифрует SoC, то chip-off **может** сработать — вы читаете чип в обход процессора. Ключ при этом часто лежит в e-fuse или в защищённой области SoC. Так что перед chip-off стоит построить модель угроз и решить, что дешевле: снять чип или искать ключ через side-channel.

## Глоссарий параметров raw NAND

Параметры NAND определяют, как собрать корректный образ. Держите их под рукой:

| Параметр | Смысл | Типичные значения |
|----------|-------|-------------------|
| Page size | размер страницы данных | 2048 / 4096 Б |
| OOB / spare | служебные байты на страницу | 64 / 128 / 224 Б |
| Pages per block | страниц в блоке | 64 / 128 / 256 |
| ECC bits | коррекция на страницу | 4–24 бит |
| Bad-block marker | где помечен дефектный блок | 1-й байт OOB |

Если ошибиться хотя бы в одном параметре, логическая нумерация страниц «съедет» и файловая система не смонтируется. Поэтому параметры берут из `nand info` или datasheet, а не угадывают.

## Если не сработало

- **Неверная ширина шины.** 8-bit вместо 4-bit даёт «мусор».
- **Длинные провода ISP.** На высокой частоте — ошибки чтения; сверяйте два дампа.
- **Игнорирование OOB.** Из него берут ECC и метки бэд-блоков — просто выкинуть нельзя.
- **Нет питания VCCQ.** Некоторым чипам нужно отдельное питание I/O; без него инициализация не проходит.
- **Перегрев феном.** BGA/eMMC легко перегреть — используйте нижний подогрев и флюс.

## Что мы теперь знаем

1. eMMC = NAND плюс контроллер; снаружи это блочное устройство.
2. Raw NAND требует учёта страниц, OOB и бэд-блоков.
3. ISP-чтение — самый безопасный метод; chip-off — крайняя мера.
4. Любой дамп сверяют дважды; «сырой» NAND пересобирают, убирая OOB.
5. `dd`, `mmls`, `binwalk`, `ubireader` превращают образ в файлы.
