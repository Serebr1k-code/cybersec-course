SPI-NOR заканчивается там, где нужно больше объёма: смартфоны, ТВ-приставки, автомобильные ГУ и «умные» колонки хранят систему на eMMC или raw NAND. Эти носители устроены сложнее: у них есть контроллер, страницы, блоки и таблица трансляции. Понимание их архитектуры — обязательное условие для того, чтобы снять корректный дамп и собрать из него монтируемый образ.

## Теория: eMMC против raw NAND

**eMMC (embedded MultiMediaCard)** — это микросхема, внутри которой находится собственно NAND-память **плюс контроллер**. Контроллер берёт на себя износ, коррекцию ошибок (ECC), bad-block management и трансляцию адресов. Снаружи eMMC выглядит как блочное устройство: вы адресуете сектора, а не страницы NAND.

**Raw NAND** — «голый» чип без контроллера. Хост сам управляет страницами, блоками, ECC и bad-block. Именно поэтому raw NAND читать сложнее: нужно знать параметры чипа (размер страницы, число байт OOB, количество блоков) и уметь собирать образ с учётом бэд-блоков.

| Свойство | eMMC | Raw NAND |
|----------|------|----------|
| Контроллер | внутри чипа | в SoC |
| Адресация | сектора (512/4096 Б) | страницы/блоки |
| ECC | аппаратный | программный (хостом) |
| Bad blocks | скрыты контроллером | видны, надо пропускать |
| Чтение | как блочное устройство | через NAND-контроллер |

## ONFI, страницы и блоки

Raw NAND описывает себя через **ONFI** (Open NAND Flash Interface) или параметры page. Ключевые параметры: размер страницы (обычно 2048 или 4096 Б), размер OOB/spare (64–256 Б), число страниц в блоке (64–256), число блоков. Эти параметры критичны: если ошибиться, образ получится «со сдвигом» и не смонтируется.

**OOB (out-of-band)** — область spare-байт в каждой странице. Там лежат ECC-коды и метки бэд-блоков. При чтении raw NAND через NAND-контроллер OOB обычно отбрасывается, но при чтении «сырым» способом его нужно либо исключать, либо обрабатывать.

**Bad-block management** — производитель помечает дефектные блоки (обычно в первом байте OOB). При сборке образа из «сырого» дампа бэд-блоки пропускают, чтобы логическая нумерация совпала с тем, что ожидает ФС.

## Инструменты и команды

- **Easy JTAG Plus / Easy JTAG Box** — самый популярный программатор eMMC/NAND с ISP-адаптером.
- **eMMC-адаптер BGA-153/169** — для чтения чипа вне платы.
- **CH341A** — только SPI-NOR, для eMMC не подходит напрямую.
- **`nanddump`**, **`flash_erase`**, **`ubi`-утилиты** — работа с NAND из-под Linux, если есть доступ к системе.
- **`dd`** — чтение eMMC как блочного устройства из Linux.
- **`binwalk`**, **`testdisk`**, **`mmls`** — разбор полученного образа и таблицы разделов.
- **`emmc-tools`**, **`mfgtools`** — вспомогательные утилиты.

```bash
# 1. Прямое чтение eMMC как блочного устройства (если есть Linux-доступ)
sudo dd if=/dev/mmcblk0 of=emmc_full.bin bs=1M status=progress
# 2. Обратное чтение через ISP: сначала определить геометрию
sudo fdisk -l emmc_full.bin
# 3. Разбор таблицы разделов и поиск ФС
mmls emmc_full.bin
binwalk emmc_full.bin
```

## Разобранный пример: дамп eMMC

Допустим, у нас есть Android-приставка с eMMC BGA-153. Порядок действий:

1. **Подключение ISP.** Находим на плате пятачки CLK, CMD, DAT0, VCC, VCCQ, GND. Припаиваем адаптер, оставляя DAT0 и CLK максимально короткими — на высокой частоте длинные провода портят сигнал.
2. **Инициализация.** Easy JTAG Plus выполняет eMMC init: читает CID/CSD и определяет размер. Вывод должен показать объём, например `14745600 sectors` (7.03 ГиБ).

```text
eMMC CID: 90014a...  (SanDisk)
eMMC size: 0x1C8000000 (7360 MiB)
Bus width: 8-bit, Speed: HS
```

3. **Чтение.** Выбираем «Read full», ставим скорость ниже (например, 1 МГц), запускаем и ждём. Результат — `emmc_full.bin` на весь объём.
4. **Сверка.** Снимаем дамп дважды и сравниваем хэши: `md5sum emmc_full.bin emmc_full2.bin`. Совпадение — обязательное условие.

```bash
md5sum emmc_full.bin emmc_full2.bin
# 9f2a...  emmc_full.bin
# 9f2a...  emmc_full2.bin
```

5. **Разбор.** `binwalk` находит таблицу разделов (GPT/MBR) и ФС (ext4, squashfs). Монтируем через offset.

```bash
binwalk emmc_full.bin | head
# 0      0x0        MBR
# 1048576 0x100000  ext4 filesystem
sudo mount -o loop,offset=$((1048576)) emmc_full.bin /mnt/part1
```

## Работа с raw NAND

Если перед вами raw NAND (например, маркировка `MT29F`), читать нужно через NAND-программатор или через контроллер SoC. Ключевые шаги:

- Определить параметры: `nand info` в U-Boot покажет page size, block size, number of blocks.
- Прочитать с ECC: программатор сам считает ECC и покажет ошибки. Если ECC-ошибок много — снижайте скорость или переходите на chip-off.
- Собрать образ: утилита программатора склеивает страницы, исключая OOB, и пропускает бэд-блоки.

```bash
# Пример из U-Boot: параметры NAND
nand info
# Device 0: nand0, sector size 128 KiB
#   Page size  2048 b
#   OOB size   64 b
#   Erase size 128 KiB
#   subpagesize 2048 b
#   options 0x4000
#   bbt options 0x00008000
```

Если ФС — UBIFS, потребуется `ubireader_extract_images` и `ubireader_extract_files`; для JFFS2 — `jefferson` или `mtd-utils`.

## Частые ошибки и подводные камни

- **Неверная ширина шины.** Если включить 8-bit вместо 4-bit, дамп будет «мусором».
- **Длинные провода ISP.** На высокой частоте появляются ошибки чтения; сверяйте два дампа.
- **Игнорирование OOB.** При «сыром» чтении raw NAND OOB нельзя просто выкинуть — из него берут ECC и метки бэд-блоков.
- **Чтение без питания VCCQ.** Некоторые чипы требуют отдельного питания I/O; без него инициализация не проходит.
- **Сборка образа без учёта бэд-блоков.** Логическая нумерация разойдётся, ФС не смонтируется.
- **Перегрев феном.** BGA/eMMC легко перегреть; используйте нижний подогрев и флюс.

## Что дальше / решение

Получив корректный образ, переходите к разбору разделов: `mmls`, `fls`, `binwalk`. Если внутри ext4/squashfs — монтируйте и ищите ключи, пароли, конфиги. Если raw NAND дал «сырой» образ — соберите его утилитами программатора или `nandsim`. Когда ФС зашифрована, образ бесполезен без ключа — смотрите урок `hardware-efuse-otp` и side-channel. Для дальнейшего углубления — chip-off (`hardware-chip-off-bga`), если внутрисхемное чтение блокируется.

## Сравнение методов чтения: ISP, chip-on и chip-off

Выбор метода — это компромисс между инвазивностью, временем и вероятностью успеха. Полезно держать в голове таблицу решений, потому что неправильный первый шаг часто закрывает остальные пути (например, перегрев при chip-off уничтожает данные, которые можно было снять внутрисхемно).

| Метод | Инвазивность | Когда применять | Ограничения |
|-------|--------------|-----------------|-------------|
| Chip-on (ISP) | минимальная | есть пятачки/адаптер, чип исправен | контроллер может блокировать чтение |
| Chip-on (eMMC-сокет) | низкая | чип съёмный (microSD-подобный BGA на переходнике) | нужен подходящий переходник |
| Chip-off | высокая | ISP закрыт, устройство мертво | риск перегрева и потери данных |
| JTAG/SWD-дамп | средняя | доступен отладочный интерфейс | часто закрыт e-fuse |

Практическое правило: **всегда начинайте с наименее инвазивного метода** и повышайте инвазивность только при доказанной невозможности предыдущего. Каждый шаг вверх по этой лестнице уменьшает шансы и повышает цену ошибки.

## Разбор реального кейса: eMMC с шифрованием на лету

Представьте Android-приставку: ISP-пятачки есть, но чтение возвращает «мусор» — контроллер SoC шифрует данные прозрачно. Что происходит и что делать:

1. **Диагностика.** Снимаем два дампа — оба идентичны, но `binwalk` не находит ни одной ФС, а энтропия ровная и высокая (~7.99 бит/байт). Это признак шифрования, а не сжатия.
2. **Проверка на chip-off.** Если шифрование реализовано в контроллере eMMC (inline encryption), то chip-off даст тот же шифротекст — метод бесполезен. Если шифрует SoC, то chip-off **может** помочь, потому что вы читаете чип в обход SoC.
3. **Проверка ключа.** Ключ шифрования часто лежит в e-fuse или в защищённой области SoC. Если он в e-fuse с `RD_DIS`, остаются физические атаки.
4. **Оценка.** Строим модель угроз: есть ли смысл в chip-off, или дешевле искать ключ через side-channel.

Этот кейс показывает, почему важно понимать, **где именно** реализовано шифрование: на уровне чипа памяти, на уровне SoC или на уровне файловой системы (fscrypt). От этого напрямую зависит выбор инструмента.

## Защита и детект

С точки зрения защищающейся стороны, чтение eMMC/NAND можно затруднить:

- включить inline-шифрование памяти и хранить ключ в e-fuse;
- залить ISP-точки компаундом и убрать тестовые площадки;
- использовать BGA-корпуса с плотным шагом, затрудняя пайку;
- включить защиту чтения и secure boot.

Детектировать chip-off на самом устройстве сложно (это физическое вмешательство), но следы остаются: смещённый припой, следы флюса, повреждённые соседние компоненты. При криминалистической экспертизе важно документировать эти признаки, а при защите — использовать датчики вскрытия и тампер-механизмы.

## Глоссарий параметров raw NAND

Параметры NAND определяют, как собрать корректный образ. Держите их под рукой:

| Параметр | Смысл | Типичные значения |
|----------|-------|-------------------|
| Page size | размер страницы данных | 2048 / 4096 Б |
| OOB / spare | служебные байты на страницу | 64 / 128 / 224 Б |
| Pages per block | страниц в блоке | 64 / 128 / 256 |
| Block size | объём стирания | 128 KiB / 256 KiB |
| ECC bits | коррекция на страницу | 4–24 бит |
| Bad-block marker | где помечен дефектный блок | 1-й байт OOB |

Если ошибиться хотя бы в одном параметре, логическая нумерация страниц «съедет», и файловая система не смонтируется. Поэтому параметры всегда берут из `nand info` (U-Boot) или из datasheet чипа, а не угадывают.

## Сборка образа из сырого дампа

Когда есть «сырое» чтение с OOB, его нужно преобразовать в образ без служебных байт:

```bash
# Убрать OOB (пример: page 2048 + oob 64)
python3 - <<'PY'
data = open('raw_nand.bin','rb').read()
page, oob = 2048, 64
out = bytearray()
for off in range(0, len(data), page+oob):
    out += data[off:off+page]
open('clean_nand.bin','wb').write(out)
PY
# Проверить, что ФС появилась
binwalk clean_nand.bin | grep -E 'squashfs|ubifs|jffs2'
```

Бэд-блоки при этом нужно пропускать: их страницы заменяются данными из резервных блоков, иначе образ будет «со сдвигом» и не смонтируется.
