## Вопрос, с которого всё начинается

Ты уже видишь эфир и каналы. Теперь задача конкретная: получить материал, по которому можно проверить пароль WPA2 **офлайн**, не сидя рядом с сетью. Что именно нужно поймать и почему это работает?

## Наш пример: точка `office` и клиент

В эфире — точка `office` и один клиент. Клиент подключается к сети, и в этот момент происходит **четырёхстороннее рукопожатие** (4-way handshake). Наша цель — поймать его кадры.

## Шаг 1: что такое четырёхстороннее рукопожатие

Пароль Wi-Fi (`passphrase`) не передаётся по воздуху. Из него и имени сети выводят **PMK** — Pairwise Master Key — медленной функцией PBKDF2:

```
PMK = PBKDF2(HMAC-SHA1, passphrase, SSID, 4096, 256)
```

При подключении точка и клиент доказывают друг другу, что знают PMK, не раскрывая его. Обмен состоит из четырёх EAPOL-Key кадров:

1. Точка → клиент: свой **ANonce** (случайное число).
2. Клиент → точка: свой **SNonce** и **MIC** (код целостности, посчитанный из PMK).
3. Точка → клиент: GTK и подтверждение.
4. Клиент → точка: ACK.

Для офлайн-проверки нам нужны ANonce, SNonce, MIC и пара MAC-адресов. Из них можно восстановить PTK и проверить любого кандидата пароля.

## Шаг 2: переводим адаптер и слушаем

```
$ iw dev wlan0 set type monitor
$ iw dev wlan0 set channel 6
$ airodump-ng -c 6 --bssid AA:BB:CC:00:11:22 -w office wlan0
```

`airodump-ng` пишет всё на канал 6 в файлы `office-01.cap`. Ждём, пока в столбце `STATION` появится клиент, а затем заставим его переподключиться.

## Шаг 3: деаутентификация, чтобы ускорить захват

Клиент переподключается нечасто, поэтому его мягко «выбивают» из сети deauth-кадром — тогда он заново проходит рукопожатие:

```
$ aireplay-ng --deauth 3 -a AA:BB:CC:00:11:22 -c 66:77:88:99:AA:BB wlan0
```

После этого в `office-01.cap` появляются EAPOL-кадры. Проверяем захват:

```
$ aircrack-ng office-01.cap
...
1 handshake(s) found!
```

Если бы рукопожатие было неполным, `aircrack-ng` написал бы `0 handshake(s) found`. Нам нужен полный EAPOL с MIC.

## Шаг 4: PMKID — захват без клиента

Деаутентификация шумная и её видно в логах. Есть тише способ: **PMKID**. Это значение точка вычисляет как

```
PMKID = HMAC-SHA1-128(PMK, "PMK Name" || AP-MAC || STA-MAC)
```

и отдаёт в первом EAPOL-кадре при ассоциации. `hcxdumptool` умеет запросить его напрямую у точки, **не дожидаясь клиента**:

```
$ hcxdumptool -i wlan0 -o pmkid.pcapng --enable_status=1
...
[14:02:11] AA:BB:CC:00:11:22 PMKID: 8a3f...c1
```

PMKID даёт материал для перебора так же, как рукопожатие, но требует лишь одной ассоциации с точкой и не тревожит клиентов.

## Шаг 5: конвертация в формат для hashcat

Соберём всё в `.hc22000` — единый формат hashcat для WPA:

```
$ hcxpcapngtool -o office.hc22000 office-01.cap pmkid.pcapng
$ wc -l office.hc22000
1 office.hc22000
```

Одна строка — один «целевой» объект. Теперь файл можно унести и ломать офлайн (следующий урок).

## Если не сработало

- **PMF включён** — deauth-кадры игнорируются, рукопожатие не перехватить так просто; переходим к PMKID или к WPA3-атакам.
- **Клиент редкий** — ждём дольше либо пробуем PMKID.
- **Адаптер не умеет injection** — `aireplay-ng` не отправит deauth; нужен совместимый чипсет.

## Что мы теперь знаем

- WPA2 проверяет пароль через четырёхстороннее рукопожатие, а не передаёт его.
- Для офлайн-взлома нужны EAPOL-кадры с MIC и nonce.
- Deauth ускоряет захват, PMKID ловит материал без клиента.
- `hcxpcapngtool` собирает всё в `.hc22000` для hashcat.

## Четырёхстороннее рукопожатие покадрово

В прошлом уроке мы видели обмен служебными кадрами. Теперь смотрим на момент, когда клиент уже ассоциировался и сеть его **пускает**. В WPA2-Personal доступ открывает не пароль напрямую, а **рукопожатие** — обмен четырьмя кадрами EAPOL-Key. Разберём их на реальном дампе:

```
$ tshark -r wpa.cap -Y 'eapol' -T fields \
    -e wlan.sa -e wlan.da -e eapol.type -e wlan_rsna_eapol.keydes.msgnr
AP_MAC    STA_MAC   3   1     # msg1: AP -> STA, ANonce
STA_MAC   AP_MAC    3   2     # msg2: STA -> AP, SNonce + MIC
AP_MAC    STA_MAC   3   3     # msg3: AP -> STA, GTK, install
STA_MAC   AP_MAC    3   4     # msg4: STA -> AP, ACK
```

Смысл кадров:

- **msg1 (ANonce)** — точка присылает случайное число `ANonce`.
- **msg2 (SNonce + MIC)** — клиент добавляет своё `SNonce` и **MIC** — подпись, посчитанную на ключе. Именно эта пара кадров (msg1+msg2) и есть «материал» для взлома: она даёт все входные данные для офлайн-перебора.
- **msg3/msg4** — точка раздаёт групповой ключ и подтверждает установку.

Из этих четырёх кадров атакующему нужны ровно **msg1 и msg2** — они содержат ANonce, SNonce и MIC. Дальше точка не нужна: пароль подбирается офлайн.

## Откуда берётся ключ: PBKDF2 и PMK

Чтобы понять, почему перебор возможен, посмотрим на вывод ключа. Из пароля и SSID считается **PMK** (Pairwise Master Key) через PBKDF2-HMAC-SHA1, 4096 итераций:

```
PMK  = PBKDF2(HMAC-SHA1, passphrase, SSID, 4096, 256 bit)
PTK  = PRF(PMK, "Pairwise key expansion", min(MAC)||max(MAC)||min(nonce)||max(nonce))
MIC  = HMAC-SHA1(PTK, EAPOL msg2)
```

Ключевая мысль: `MIC` зависит от пароля (через PMK) и от всего, что видно в дампе (MAC, nonce). Значит, зная дамп, можно для каждого кандидата-пароля посчитать свой MIC и сравнить с пойманным. Совпадение = угаданный пароль. Это и есть офлайн-атака — она не требует контакта с точкой.

## Как перехватить: активный и пассивный путь

Пассивно рукопожатие ловится только когда реальный клиент переподключается — а он может быть подключён неделями. Поэтому на практике атакующий **ускоряет** событие: шлёт **deauthentication**-кадр от имени точки, клиент отваливается и сразу переподключается, отдавая рукопожатие.

```
$ airodump-ng -c 6 --bssid aa:bb:cc:00:11:22 -w wpa wlan0
 CH  6 ][ Elapsed: 12 s ][ WPA handshake: aa:bb:cc:00:11:22

$ aireplay-ng --deauth 5 -a aa:bb:cc:00:11:22 -c 66:77:88:99:aa:bb wlan0
```

Строка `WPA handshake: aa:bb:cc:00:11:22` в `airodump-ng` означает, что обмен msg1+msg2 записан. Важно: **одного** deauth обычно достаточно; серия из сотен кадров — это уже DoS и лишний шум, который заметит WIDS. В отчёте фиксируй, что для захвата хватило пары кадров.

## Проверка годности захвата перед перебором

Прежде чем гонять `hashcat`, убедись, что в дампе есть именно msg1+msg2, а не «обрезанная» пара:

```
$ tshark -r wpa.cap -Y 'eapol' -T fields -e wlan_rsna_eapol.keydes.msgnr | sort | uniq -c
   1  1
   1  2
   1  3
   1  4
```

Если msg1 или msg2 отсутствует — перебор не сработает, и ты зря потратишь часы. Конвертация в формат hashcat и запуск:

```
$ hcxpcapngtool -o wpa.hc22000 wpa.cap
$ hashcat -m 22000 wpa.hc22000 rockyou.txt
```

`-m 22000` — это объединённый формат WPA-PMKID-PBKDF2. Если пароль в словаре есть, hashcat покажет `Status: Cracked` и сам пароль.

## Если не сработало

- **Клиентов нет** → пассивно рукопожатие не поймать; переходи к PMKID (следующий урок).
- **PMF включён** (WPA3-переходный режим) → deauth-кадры отбрасываются, придётся ждать естественного переподключения.
- **Только msg2 или только msg3** → дамп негоден, нужен новый захват.
- **5 ГГц и DFS** → следи за каналом: точка могла уйти на другой канал после radar-события.

## Что мы теперь знаем

- WPA2-доступ открывает четырёхстороннее рукопожатие EAPOL-Key.
- Для перебора нужны msg1 (ANonce) и msg2 (SNonce + MIC).
- MIC считается из пароля через PMK; поэтому перебор возможен офлайн.
- Deauth ускоряет захват, но одной пары кадров достаточно — серии не нужны.
- Перед перебором всегда проверяй полноту рукопожатия в tshark.

## Частые грабли при захвате

- **Deauth «на всякий случай» сотнями** → лишний шум и риск DoS. Одной пары кадров достаточно.
- **Захват на канале, отличном от целевого** → рукопожатия не будет; ставь `-c 6` явно.
- **msg1 без msg2** → перебор невозможен, жди переподключения клиента.
- **Deauth от неверного MAC** → в `aireplay-ng` адрес точки задаётся `-a`, клиента `-c`; перепутаешь — кадр уйдёт в никуда.
- **PMF включён** → deauth игнорируется; переходи к пассивному ожиданию.

## Тонкость: WPA3-переходный режим и PMF

Многие точки работают в **переходном режиме**: WPA2 для старых клиентов, WPA3 для новых, при этом включён **PMF** (Protected Management Frames) — защита management-кадров. В этом режиме поддельный deauth не сработает, потому что кадр не имеет корректной подписи. Это не «сломанная атака», а честная защита: в отчёте её фиксируют как положительную находку и переходят к другим векторам.

## Что важно не перепутать

Два кадра из четырёх — msg1 и msg2 — ключевые, но иногда аналитики путают их роли и гоняют бесполезный дамп. Запомни распределение:

| Кадр | Направление | Что несёт | Нужен для перебора |
|---|---|---|---|
| msg1 | AP → STA | ANonce | да |
| msg2 | STA → AP | SNonce + MIC | да |
| msg3 | AP → STA | GTK, установка | нет |
| msg4 | STA → AP | ACK | нет |

Если в дампе есть только msg3/msg4 — материал негоден: без msg2 нет MIC, а без MIC сравнивать нечего. Поэтому после каждого захвата первым делом проверяй наличие именно первой пары.

## Куда дальше

У нас есть `.hc22000` с валидным материалом. В следующем уроке мы запустим по нему `hashcat` с масками и правилами и посмотрим, сколько времени нужно на разные пароли. А пока главное запомни: сначала поймай полное рукопожатие или PMKID, и только потом ломай.

## Где пригодится

- Офлайн-аудит стойкости пароля WLAN по согласованию.
- CTF: `capture.pcap` с рукопожатием и словарь.
- Демонстрация риска слабого пароля в отчёте заказчику.
