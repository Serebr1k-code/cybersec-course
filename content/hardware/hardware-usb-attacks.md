Класс HID-инъекции — самый известный, но не единственный USB-вектор. Физический USB-порт открывает целый спектр атак: от «умных» кабелей со встроенным чипом до электрического уничтожения железа и прямого доступа к памяти через DMA. Этот урок — систематический обзор, чтобы вы понимали поверхность атаки целиком, а не только BadUSB.

## Таксономия USB-атак

Разделим атаки по цели и механизму:

| Класс | Механизм | Пример |
|-------|----------|--------|
| HID-инъекция | эмуляция клавиатуры | Rubber Ducky |
| Malicious cable | чип в кабеле | O.MG Cable |
| Накопитель | автозапуск/LNK | USB drop |
| DMA | прямой доступ к памяти | Thunderbolt, PCILeech |
| Juice jacking | данные через зарядку | публичные зарядки |
| USB Killer | электроразряд | уничтожение железа |
| Перехват | сниффинг шины | аппаратный анализатор |

## Malicious cable и O.MG

**O.MG Cable** — кабель, внешне неотличимый от обычного, со встроенным контроллером и Wi-Fi. Он может выполнять HID-инъекцию, эмулировать накопитель и даже принимать команды по беспроводной сети. Проблема в том, что такой кабель неотличим от обычного: ни по виду, ни (часто) по VID/PID.

Защита: не пользоваться чужими кабелями, использовать **USB data blocker** (физически разрывает D+/D−, оставляя только питание), контролировать кабели в критичных зонах.

## USB drop и autorun

Сценарий: злоумышленник «теряет» флешку в паркинге или у офиса. Любопытный сотрудник подключает её. Дальше работает либо HID-инъекция, либо специально подготовленные файлы:

- **Windows LNK** — иконка-ярлык с полезной нагрузкой; эксплуатирует доверие Explorer.
- **Autorun.inf** — срабатывает не всегда (в современных Windows отключён).
- **ZIP/архив с LNK** — обходит Mark-of-the-Web.
- **Файл с двойным расширением** — `report.pdf.exe`.

Мера защиты: отключить автозапуск, показывать расширения, использовать Device Control.

## Juice jacking

Публичные зарядные станции (аэропорты, кафе) могут передавать данные, а не только питание. Через такую станцию злоумышленник:

- выполняет HID-инъекцию («зарядка» = скрытая клавиатура);
- перенаправляет трафик (если устройство эмулирует сетевую карту);
- ворует данные через MTP.

Защита: **USB data blocker** или зарядка через собственный адаптер от розетки (не USB-порт). На телефоне — отключить передачу данных при зарядке.

## USB Killer

**USB Killer** — устройство, которое накапливает заряд от USB-порта и разряжает его обратно высоким напряжением. Результат — выгорание контроллера и цепей порта, часто материнской платы целиком. Это атака на **доступность**, а не на данные; в пентесте применяется редко, но как демонстрация риска — впечатляет.

Защита: аппаратные USB-фильтры (USB condom с защитой), изоляция портов.

## DMA-атаки

**Direct Memory Access** позволяет устройству читать/писать память в обход CPU. Исторически это Thunderbolt, ExpressCard, PCIe. Через DMA можно за секунды прочитать пароли, ключи шифрования и дамп памяти, включая обход блокировки экрана.

Инструменты: **PCILeech** + плата (FPGA-скважина, например Screamer), **Inception**, легитимные адаптеры с DMA. На современных ОС есть защиты: **IOMMU/VT-d**, **Kernel DMA Protection**, Thunderbolt security levels.

```bash
# PCILeech: чтение памяти цели через DMA-устройство
./pcileech dump -device FPGA -out memdump.raw
./pcileech search -device FPGA -string "password"
```

Ключевой момент: без физического доступа DMA-атака невозможна, но если порт Thunderbolt разрешает DMA — она тривиальна.

## Аппаратный перехват шины

Если нужно увидеть **всё**, что идёт по USB (включая трафик между устройством и хостом), используют аппаратный сниффер:

- **Total Phase Beagle USB 480/5000** — профессиональный анализатор.
- **Saleae** + декодер USB — бюджетнее.
- **GreatFET / Facedancer** — сниффинг и эмуляция.

Это дороже и сложнее софтового usbmon, но даёт видимость на уровне электрических пакетов, включая SOF/токены, что важно при реверсе протоколов.

## Разобранный пример: расследование USB-инцидента

```bash
# 1. Собрать список подключённых устройств
lsusb -t
# 2. Поймать трафик на шине, где было подозрительное устройство
sudo modprobe usbmon
sudo dumpcap -i usbmon2 -w incident.pcap -a duration:30
# 3. Найти HID-отчёты с аномально высокой частотой
tshark -r incident.pcap -Y 'usbhid.data' -T fields -e frame.time_epoch -e usbhid.data \
  | awk 'NR>1 {dt=$1-prev; if (dt<0.002) print dt, $2} {prev=$1}' | head
# Малые dt -> автоматическая инъекция
```

Дальше по кодам клавиш восстанавливают набранную команду и сопоставляют с логами ОС (Process Creation, PowerShell).

## Частые ошибки и подводные камни

- **Считать USB Killer безобидным** — он физически выводит железо из строя, применять только с разрешения.
- **DMA без IOMMU**: на новых системах DMA-атака может блокироваться — проверяйте уровень Thunderbolt Security.
- **Автозапуск в 2026 не работает по умолчанию**: расчёт на autorun.inf устарел.
- **Кабель-имплант неотличим**: не помогают антивирусы — только физические меры.
- **Права на usbmon**: без root не поймать трафик.

## Thunderbolt и PCIe: DMA подробнее

Thunderbolt по сути «выносит» PCIe наружу. Устройство, подключённое к порту Thunderbolt, получает доступ к шине PCIe и, если IOMMU выключен, может читать/писать физическую память. Уровни безопасности Thunderbolt (SL0–SL3) определяют, что разрешено без подтверждения: SL0 — всё, SL3 — только дисплеи. На Linux `boltctl` показывает домены и уровень; на Windows — Kernel DMA Protection в настройках.

```bash
boltctl list          # домены Thunderbolt и их security level
boltctl domains       # состояние IOMMU-защиты
dmesg | grep -i iommu # включён ли IOMMU
```

Практический вывод: на старых ноутбуках с SL0 и выключенным IOMMU DMA-атака занимает секунды и обходит блокировку экрана. На новых системах нужны либо 0-day, либо ошибки конфигурации.

## Беспроводные импланты

Помимо O.MG, существуют беспроводные платформы, объединяющие HID, Wi-Fi и иногда сотовую связь: **Wi-Fi Duck**, **P4wnP1 A.L.O.A.** (Raspberry Pi Zero), **Bash Bunny** (Hak5). Они позволяют удалённо управлять имплантом, менять payload'ы и даже организовывать «мост» между сетями. Bash Bunny умеет несколько режимов (HID + Ethernet + storage) одновременно и имеет payload switch — переключение сценариев физическим тумблером. Для защитника это значит, что «одно USB-устройство» может быть сразу клавиатурой, сетевой картой и накопителем.

## Форензика USB-подключений

После инцидента важно понять, **какие** USB-устройства подключались. Артефакты:

- **Windows**: `USBSTOR`, `setupapi.dev.log`, реестр `HKLM\SYSTEM\CurrentControlSet\Enum\USB`, `MountPoints2`.
- **Linux**: `dmesg`, `/var/log/syslog` (строки `usb 1-1: new full-speed USB device`), `journalctl -k`.
- **macOS**: `system_profiler SPUSBDataType`, unified log.

```bash
# Linux: история подключений USB
journalctl -k | grep -i 'new .*USB device' | tail -20
dmesg | grep -iE 'usb .*: New USB device found' | head
```

По VID/PID сопоставляют устройство с базой, по серийному номеру — конкретный экземпляр. Если у «флешки» VID/PID клавиатуры — это явный признак HID-импланта.

## USB-хабы и подмена топологии

USB-хаб — тоже устройство, и его можно эмулировать. Вредоносный хаб может:

- **незаметно вставлять** себя между хостом и легитимной периферией (MITM);
- **переключать** устройство между режимами по команде;
- **скрывать** реальное устройство за «безобидным» VID/PID хаба;
- **выдавать себя** за несколько устройств одновременно.

Композитные устройства (одно физическое — несколько интерфейсов) особенно удобны для имплантов: пока хост видит «накопитель», второе HID-устройство уже набирает команды. Защита на уровне политик должна учитывать топологию (какой порт, за каким хабом), а не только список VID/PID.

## Итог: что реально работает на практике

Из всего спектра USB-атак чаще всего срабатывают три: **HID-инъекция** (BadUSB), **USB drop** и **DMA** там, где порт Thunderbolt не защищён IOMMU. USB Killer и juice jacking — скорее демонстрации риска. Поэтому в отчётах по пентесту физического доступа в первую очередь описывают доступность открытых портов, отсутствие Device Control и возможность подключить имплант.
