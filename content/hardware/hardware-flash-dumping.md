## Вопрос, с которого всё начинается

В прошлом уроке мы сняли дамп SPI-флеша программатором. Но что делать, если памяти в устройстве много — гигабайты, как в приставке или смартфоне? Или если чип устроен сложнее, чем простая NOR?

Разные типы памяти читают по-разному, и в каждом есть свои ловушки. Этот урок — про полный дамп: как снять образ с SPI-NOR, eMMC и NAND и не получить при этом «битые» данные.

## Наш пример: роутер с SPI-NOR

Начнём с самого частого случая — роутер с чипом **25Q128** (16 МБ SPI-NOR), впаянным в плату. У нас есть программатор **CH341A** и **SOIC-8 клипса**. Цель — снять полный дамп, не выпаивая чип.

## Шаг 1: как устроены разные носители

Прежде чем читать, поймём, чем носители отличаются:

| Тип | Интерфейс | Особенности | Инструмент |
|-----|-----------|-------------|------------|
| SPI-NOR | SPI (SOIC-8) | простая, байтовый доступ | CH341A, flashrom |
| SPI-NAND | SPI | страничная, bad-блоки, ECC | программатор |
| eMMC | MMC (CLK/CMD/DAT) | блочная, гигабайты | eMMC-ридер, mmc-utils |
| raw NAND | параллельная шина | bad-блоки, ECC, OOB | NAND-программатор |

SPI-NOR — самая простая: к ней обращаются побайтово, как к обычной памяти. Именно с неё начинают.

## Шаг 2: подключаемся клипсой

По даташиту у SOIC-8 `25Q128` распиновка такая: `1=CS`, `2=DO(MISO)`, `3=WP`, `4=GND`, `5=DI(MOSI)`, `6=CLK`, `7=HOLD`, `8=Vcc`. Прикладываем клипсу, ориентируясь по метке-кружку у первого вывода. Ключевой момент — **питание**: на работающей плате процессор тоже держит линии, и возникает конфликт двух «хозяев» шины. Поэтому чаще всего дамп снимают, подав штатное питание платы (а не от программатора), либо удерживая процессор в сбросе.

## Шаг 3: первое чтение и верификация

Читаем чип:

```
$ flashrom -p ch341a_spi -r dump1.bin
Found Winbond flash chip "W25Q128.V" (16384 kB, SPI) on ch341a_spi.
Reading flash... done.
```

`-p ch341a_spi` — работать через CH341A, `-r dump1.bin` — сохранить в файл. Теперь главное правило дампа: **читать дважды и сравнивать**. Единичная ошибка чтения превращает образ в «битый»:

```
$ flashrom -p ch341a_spi -r dump2.bin
$ cmp dump1.bin dump2.bin && echo OK
OK
```

`cmp` побайтово сравнивает файлы. Если он молчит — дампы идентичны, можно доверять. Если различия есть — плохой контакт или помехи; переставьте клипсу, проверьте ориентацию.

## Шаг 4: разбираем дамп

Полученный образ анализируем `binwalk` — он ищет известные сигнатуры и показывает разметку:

```
$ binwalk -e dump1.bin
DECIMAL       HEXADECIMAL     DESCRIPTION
0             0x0             U-Boot bootloader header
327680        0x50000         uImage header, Linux kernel
2097152       0x200000        Squashfs filesystem
```

`-e` сразу извлекает найденные файловые системы. Дальше монтируем и ищем секреты:

```
$ unsquashfs -d rootfs _dump1.bin.extracted/*.squashfs
$ grep root: rootfs/etc/shadow
```

## Шаг 5: eMMC — если памяти гигабайты

Если устройство хранит систему на **eMMC**, подход другой. eMMC — это чип, внутри которого NAND-память **плюс контроллер**, который сам управляет износом, ECC и трансляцией адресов. Снаружи eMMC выглядит как блочное устройство: адресуются сектора, а не страницы.

Если у нас есть Linux-доступ к системе, читаем её как обычный диск:

```
$ sudo dd if=/dev/mmcblk0 of=emmc_full.bin bs=1M status=progress
$ mmls emmc_full.bin
```

`dd` копирует устройство целиком, `bs=1M` ускоряет чтение блоками по мегабайту, `mmls` показывает таблицу разделов. Если Linux-доступа нет, eMMC читают через ISP-адаптер (Easy JTAG Plus), припаиваясь к линиям `CLK/CMD/DAT0`.

## Шаг 6: raw NAND — самый капризный

**Raw NAND** — это «голый» чип без контроллера: хост сам управляет страницами, ECC и бэд-блоками. Здесь появляются два понятия. **OOB** (out-of-band) — служебная область spare-байт в каждой странице, где лежат ECC-коды и метки бэд-блоков. **Bad blocks** — дефектные блоки, которые помечены и при сборке образа пропускаются.

Из-за этого «сырой» дамп NAND нельзя просто смонтировать: сначала нужно убрать OOB и учесть бэд-блоки. Параметры берут из `nand info` в U-Boot:

```
$ nand info
Device 0: nand0, sector size 128 KiB
  Page size  2048 b
  OOB size   64 b
  Erase size 128 KiB
```

Зная `page=2048` и `oob=64`, можно собрать чистый образ:

```
$ nanddump -f nand.bin /dev/mtd0
$ ubireader_extract_images nand.bin
```

## Как от этого защищаются

Производители затрудняют дамп несколькими мерами: защитой чтения (read-protection, если чип её поддерживает), шифрованием прошивки с проверкой подписи, secure boot, а также физическими приёмами — заливкой платы компаундом и сокрытием тестовых площадок. Все они лишь повышают цену атаки: при физическом доступе ни одна из них не абсолютна, но вместе они делают быстрое копирование невозможным.

## Сводка по дампу

Чтобы не запутаться в носителях, держите под рукой таблицу «носитель → инструмент → команда»:

| Носитель | Инструмент | Команда |
|----------|-----------|---------|
| SPI-NOR | CH341A | `flashrom -p ch341a_spi -r d.bin` |
| raw NAND | nanddump | `nanddump -f n.bin /dev/mtd0` |
| eMMC | dd/mmc-utils | `dd if=/dev/mmcblk0 of=e.bin` |
| UBI-образ | ubireader | `ubireader_extract_images n.bin` |

Начинайте с SPI-NOR — это самый простой носитель. Для NAND всегда учитывайте bad-блоки и OOB, иначе образ будет «битым».

## Если не сработало

- **Одно чтение без сверки.** Всегда читайте минимум дважды — единичная ошибка даёт «битый» дамп.
- **Питание от программатора на плате.** Оно конфликтует со штатным; пробуйте оба варианта.
- **Игнорирование bad-блоков.** Прямой `dd` с raw NAND даст мусор в OOB и сдвиги.
- **Не тот размер чипа.** CH341A читает лишь то адресное пространство, которое «видит».
- **Перезапись без бэкапа.** Если планируете писать — сохраните оригинал минимум в двух местах.
- **Chip-off без навыка.** Выпаивание BGA легко заканчивается оторванными пятаками.

## Что мы теперь знаем

1. SPI-NOR читается побайтово и проще всего: CH341A плюс flashrom, никаких страниц и ECC.
2. Дамп всегда снимают дважды и сверяют, иначе рискуют получить «битые» данные, на которых невозможно построить достоверный анализ.
3. eMMC имеет встроенный контроллер и выглядит как блочное устройство.
4. Raw NAND требует учёта OOB и бэд-блоков — «сырой» образ без пересборки не смонтируется никогда.
5. `binwalk`, `dd`, `unsquashfs`, `ubireader` превращают дамп в файлы и секреты — но только если образ собран корректно.
